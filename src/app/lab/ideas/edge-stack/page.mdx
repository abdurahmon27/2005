**Status: shipped and in front of everything I run.**
[github.com/abdurahmon27/edge-stack](https://github.com/abdurahmon27/edge-stack)

## The mess it replaced

Every project arrives with its own opinion about the front door. One ships a
Caddy container, the next terminates TLS inside the app, a third wants nginx
with a hand-written vhost, and a fourth quietly grabs port 80. Put four of them
on one box and you get certificate renewals nobody owns, a reload that takes the
wrong thing down, and a `docker ps` you have to study before touching anything.

The rule I settled on is one line:

> **No app runs its own proxy or terminates its own TLS.** Apps expose
> containers on a docker network; one proxy fronts all of them.

## How it works

Declare the domain in `sites.yaml`, run `edgectl apply`, and the rest happens:

```yaml
- domain: app.example.com
  networks: [myapp_default]        # the docker network the app exposes
  routes:
    - path: /api/
      upstream: myapp-api:8080
      strip_prefix: true
    - path: /
      upstream: myapp-web:80
```

`edgectl` issues the Let's Encrypt certificate (HTTP-only vhost first so
validation passes, then the full HTTPS one), generates the nginx vhost, attaches
the proxy to the app's docker network, validates with `nginx -t`, and reloads —
zero downtime. `edgectl status` prints a live HTTP code per domain, and
`edgectl install-cron` keeps the disk from filling with junk.

Requirements: Docker and `python3`. No root.

## The details that took the longest

- **Generated, never hand-edited.** `edge/nginx/conf.d/*.conf` carries a warning
  saying so. The moment one file is edited by hand, the YAML stops being the
  truth and the whole idea collapses — the same rule that makes
  [spec-first delivery](/lab/spec-first) work, applied to a config directory.
- **`resolver 127.0.0.11 valid=10s`.** Docker's embedded DNS, re-resolved every
  ten seconds, so an app redeploy with a new container IP never strands the
  proxy pointing at an address that no longer exists. This is the single line
  that turns "works until the next deploy" into infrastructure.
- **Validate before reload.** `nginx -t` runs first, always. A proxy that
  reloads a broken config takes every site on the box down at once — the whole
  downside of sharing one front door.
- **Certificate ordering.** You cannot request a cert for a domain the proxy
  can't serve yet, so the HTTP vhost goes up first, validation passes, then
  HTTPS replaces it.

## Why it was worth building rather than installing

Caddy would have done most of this with less code, and I thought about it for a
while. What I wanted was the *inventory*: one file I can read in ten seconds
that says which domains exist on this machine, which containers they point at,
and on which network — plus a command that tells me if any of them is currently
returning something other than 200.

It is now the front door for [shoshshi](/lab/ideas/shoshshi) and
[oris](/lab/ideas/oris), and the reason adding a project to the box is a
paragraph of YAML instead of an afternoon.
