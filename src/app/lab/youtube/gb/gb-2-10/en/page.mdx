## What you will learn

The bozor receipt prints a product name into a column of 10 characters and cuts long names. But `oʻrik qoqi` ("dried apricots") lost its last letter,
and `paxta yogʻi` ("cottonseed oil") came out with a broken character at the end. Why does this happen, and how do you shorten an Uzbek name without breaking it?

**One idea:** a Go `string` is an immutable sequence of bytes, and the text in your code is UTF-8: each character takes 1–4 bytes
(`oʻrik` ("apricot") = 5 characters, 6 bytes). `len`, the index `s[i]` and slicing `s[a:b]` work on **bytes**. `for i, r := range s` reads the UTF-8 and gives, on every
step, one **rune** and the index of the byte where it starts. So it is safe to cut a string only at an index that `range` gave you.

By the end of the lesson you will:

- see why `len("oʻrik")` is 6 and print the bytes themselves with `% x`;
- walk over a string character by character (rune by rune) with `for i, r := range name`, and count runes with the `unicode/utf8` package;
- see in a real error how `name[:n]` cuts a character in the middle, and fix `short` so that it cuts at a rune boundary;
- write `shortLabel` (with `…`) and `checkName` (empty name, not UTF-8, longer than 20 runes) in the homework, until `go test` passes.

The three main new words of the lesson:

| Word | Plain meaning | English term |
|---|---|---|
| UTF-8 | the rule for writing a character's Unicode number in 1–4 bytes; a Go string consists of these bytes | UTF-8 |
| rune | the Unicode number (code point) of one character, type `int32`; it is not the same as a letter: `oʻ` is one letter but two runes | rune |
| rune boundary | the byte where one rune ends and the next begins; cutting a string is safe only here | rune boundary |

Helper ideas get one sentence where they first appear: **Unicode**, **code point**, **hexadecimal** (hex),
the `unicode/utf8` package, and the `Printf` verbs `%x`, `%c`, `%U`.

The receipt prints each product name into a column of 10 characters in square brackets. With three names the program gives this
(`_video/00-chek` — the first state from the video; we read its code in the last main section of the page):

```console
$ ./_video/run.sh 00-chek go run .

There are two bugs:

- `paxta yogʻi` ends with `�` (a diamond with a question mark) instead of `ʻ`. This is how the terminal draws an invalid byte.

Both bugs have one cause: the program measures text in **bytes**, while you see characters. First we look at what is inside a string,
then we fix the bug.

## What `len` counts

```

## Looking at the bytes themselves

`fmt.Printf` gets a new verb, `%x`: it prints a value in **hex**, that is, **hexadecimal** (the digits 0–9 and a–f; `a` = 10, `f` = 15).
For a string, `%x` writes every byte as two hex digits. A space between `%` and `x` also puts spaces between the bytes: `% x`.
The program (`_video/02-bayt/main.go`):

```go filename="_video/02-bayt/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "oʻrik"
	fmt.Println(len(name))
	fmt.Printf("% x\n", name)
}
```

The new line is line 8: `fmt.Printf("% x\n", name)`. `"% x\n"` is the template (GB-1.04), `% x` means print the bytes in hex separated by spaces, `\n` is the end of line. How many
hex pairs appear on screen?

<details>
<summary>Answer</summary>

Six: `len(name)` = 6 bytes, and each byte is one pair. The difference between 6 and 5 is the answer to the previous question: one character can take several bytes.

</details>

```console
$ ./_video/run.sh 02-bayt go run .
6
6f ca bb 72 69 6b
```

Six bytes. Which byte belongs to which character:

```text
byte index:     0    1  2    3    4    5
byte (hex):     6f   ca bb   72   69   6b
character:      o    ʻ       r    i    k
```

The first byte `6f` is the letter `o`. The next two bytes `ca bb` are **together** one character: the turned comma `ʻ` of `oʻ`. Then `r`, `i`
and `k`, one byte each.

Here is why. **Unicode** is a numbered list of the characters of the whole world. The number of a character is called its **code point** and is written
like `U+02BB` (a hex number after `U+`): `ʻ` is U+02BB (MODIFIER LETTER TURNED COMMA, [Unicode chart](https://www.unicode.org/charts/PDF/U02B0.pdf)).
**UTF-8** is the rule for writing this number as bytes: each code point takes from 1 to 4 bytes. The Latin letters a–z, digits and ordinary punctuation
(**ASCII**) take one byte. `ʻ` takes two. A Go source file is written in UTF-8
([Go spec: Source code representation](https://go.dev/ref/spec#Source_code_representation)), so text in quotes also sits in memory as these bytes.
A string is immutable: you cannot replace its bytes in place (you will see this error below, in "Common mistakes").

You can also look at how many bytes other characters take. The next program is not in the course folder: I ran it in a separate folder with the same `go.mod`.
`[]rune(s)[0]` is the first character of `s` (the section "Going deeper" below explains this notation), `%U` prints its code point:

```go
package main

import "fmt"

func main() {
	for _, s := range []string{"a", "ʻ", "…", "😀"} {
		fmt.Printf("%q: %d bayt, %U\n", s, len(s), []rune(s)[0])
	}
}
```

```console
$ go run .
"a": 1 bayt, U+0061
"ʻ": 2 bayt, U+02BB
"…": 3 bayt, U+2026
"😀": 4 bayt, U+1F600
```

(In the template, `bayt` is the Uzbek word for "byte": the output is shared by all languages of the page.) The rule ([RFC 3629](https://www.rfc-editor.org/rfc/rfc3629#section-3), section 3):

| Code point range | Bytes | Example |
|---|---|---|
| `U+0000`–`U+007F` (ASCII) | 1 | `a` |
| `U+0080`–`U+07FF` | 2 | `ʻ` (U+02BB) |
| `U+0800`–`U+FFFF` | 3 | `…` (U+2026) |
| `U+10000`–`U+10FFFF` | 4 | `😀` (U+1F600) |

## The index gives a byte too

The index in square brackets works on bytes too: `name[0]` is the first byte, `name[1]` is the second (indexes start at 0, GB-2.01).
The program (`_video/03-indeks/main.go`):

```go filename="_video/03-indeks/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "oʻrik"
	fmt.Println(name[0], name[1])
}
```

Line 7 prints `name[0]` and `name[1]` on one line (`Println` puts a space between arguments). Does the screen show letters or numbers?

<details>
<summary>Answer</summary>

**Numbers.** An index returns a value of type `byte` ([Go spec: Index expressions](https://go.dev/ref/spec#Index_expressions)); `byte` is the type from GB-2.07,
a number from 0 to 255. `Println` prints a number as a number.

</details>

```console
$ ./_video/run.sh 03-indeks go run .

```

These are the same bytes as in the previous step, only in decimal: `6f` = 6 × 16 + 15 = 111 (the byte of the letter `o`), `ca` = 12 × 16 + 10 = 202
(the first byte of the character `ʻ`). `name[1]` is not a character, it is **half** of a character.

Summary: `len`, `name[i]` and (we will see it below) `name[a:b]` work on bytes. To get characters you need a different way.

## `for range`: one step — one character

`range` over a slice gave the index and the element (GB-2.01). `range` over a **string** reads UTF-8: one character per step, that is,
one code point. `i` is the index of the byte where this character starts, `r` is the character itself. The program (`_video/04-range/main.go`):

```go filename="_video/04-range/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "oʻrik"
	for i, r := range name {
		fmt.Printf("%d %c\n", i, r)
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 7 | `for i, r := range name {` | walks over `name` character by character: on each step `i` is the byte index, `r` is the character (a rune) |
| 8 | `fmt.Printf("%d %c\n", i, r)` | `%d` prints `i` as a number, `%c` prints `r` as a **character** (`%c`: number → the character with that number) |

Which numbers does `i` take? `oʻrik` has 6 bytes.

**A)** `0 1 2 3 4` · **B)** `0 1 3 4 5` · **C)** `0 1 2 3 4 5`

<details>
<summary>Answer</summary>

**B: `0 1 3 4 5`.** `ʻ` takes two bytes (bytes 1 and 2), so the next character `r` starts at byte 3: `i` jumps from 1 to 3. If you chose **A**,
you thought `i` counts characters in a row from zero. If you chose **C**, you thought `range` takes a step for every byte: it takes a step for every **character**,
and there are five of them.
([Go spec: For statements with range clause](https://go.dev/ref/spec#For_range): the index is the index of the first byte of the character.)

</details>

```console
$ ./_video/run.sh 04-range go run .
0 o
1 ʻ
3 r
4 i
5 k
```

The steps in a table (`r` is a number: the code point of the character, `%c` turns it back into a character):

| Step | `i` | `r` | Bytes in this character | On screen |
|---|---|---|---|---|
| 1 | 0 | 111 | 1 (byte 0) | `0 o` |
| 2 | 1 | 699 | 2 (bytes 1 and 2) | `1 ʻ` |
| 3 | 3 | 114 | 1 (byte 3) | `3 r` |
| 4 | 4 | 105 | 1 (byte 4) | `4 i` |
| 5 | 5 | 107 | 1 (byte 5) | `5 k` |

The value of `r` is always the number of the character: for `o` it is 111, for `ʻ` it is 699 (that is U+02BB in hex).

## `rune`: the number of a character

The type of `r` is **rune**. It is another name for `int32` ([Go spec: Numeric types](https://go.dev/ref/spec#Numeric_types)), and it stores one code point.
A character in single quotes is a **rune literal**: its value is the number of the character. Double quotes (`"…"`) make a string,
single quotes (`'…'`) make a rune. The program (`_video/05-rune/main.go`):

```go filename="_video/05-rune/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var r rune
	r = 'ʻ'
	fmt.Printf("%d %c %U\n", r, r, r)
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `var r rune` | `r` is a variable of type rune, its starting value is 0 (GB-1.02) |
| 7 | `r = 'ʻ'` | puts the number of the character `ʻ` into `r` |
| 8 | `fmt.Printf("%d %c %U\n", r, r, r)` | prints one `r` in three ways: `%d` the number, `%c` the character, `%U` the Unicode notation (`U+` and hex) |

What do the three verbs print from one `r`?

```console
$ ./_video/run.sh 05-rune go run .
699 ʻ U+02BB
```

One number, three forms. The `02BB` after `U+` is the same 699, only in hex: the place of the character in Unicode.

The number of runes comes from the function `RuneCountInString` in the `unicode/utf8` package. `import` now has two packages. The last part of the import path
(`utf8`) is the package name: in code we call it by that name. The program (`_video/06-count/main.go`):

```go filename="_video/06-count/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	name := "oʻrik"
	fmt.Println(utf8.RuneCountInString(name))
}
```

| Line | Code | What it does |
|---|---|---|
| 3–6 | `import ( "fmt"  "unicode/utf8" )` | two packages, each on its own line; we call the second one as `utf8.` |
| 10 | `fmt.Println(utf8.RuneCountInString(name))` | prints the number of runes in `name` |

How many runes are in `oʻrik`?

```console
$ ./_video/run.sh 06-count go run .

```

Five runes, but six bytes.

### A rune is not a letter

A rune is a code point, not a letter. The Uzbek `oʻ` is one letter, but **two** runes: `o` and `ʻ`. If a cut falls between them, the remaining text
is still valid UTF-8, but `oʻ` turns into a plain `o`. The `go vet` warning from GB-1.04 ("string of one rune") is about the same thing: one code point.

An intermediate question. The ellipsis `…` is one character; the receipt puts it at the end of a shortened name (the homework needs exactly this one). What are its
`len` and its rune count? The program (`_video/07-quiz/main.go`):

**A)** `1 1` · **B)** `3 1` · **C)** `3 3`

**B: `3 1`.** A character outside ASCII takes at least two bytes, and the number of `…` (U+2026) is even bigger: it takes three bytes. It is still one character.
If you chose **A**, you thought `len` counts characters too. If you chose **C**, you thought the rune count equals the byte count.

</details>

## Fixing the receipt: cut at a rune boundary

Now the code of the first state (`_video/00-chek/main.go`):

```go filename="_video/00-chek/main.go" showLineNumbers
package main

import "fmt"

// short nomni chek ustuniga sigʻdiradi: limit'dan uzun boʻlsa kesadi.
func short(name string, limit int) string {
	if len(name) <= limit {
		return name
	}
	return name[:limit]
}

func main() {
	names := []string{"olma", "oʻrik qoqi", "paxta yogʻi"}
	for _, name := range names {
		fmt.Printf("[%-10s]\n", short(name, 10))
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `func short(name string, limit int) string {` | a function that cuts a name to `limit`; `limit` is the column width (GB-1.07) |
| 7–9 | `if len(name) <= limit { return name }` | if the name fits, returns it as it is. The condition is written with `len`, that is, in **bytes** |
| 10 | `return name[:limit]` | `name[:limit]` is the first `limit` **bytes** of the string. There is no number before `:`, so it starts at the beginning (GB-2.02: `os.Args[1:]` — to the end) |
| 14 | `names := []string{…}` | a slice with three names (GB-2.01) |
| 15 | `for _, name := range names {` | a loop over each name; `_` — the index is not needed |
| 16 | `fmt.Printf("[%-10s]\n", short(name, 10))` | `%-10s` writes the text into a 10-character column, left-aligned (GB-1.04); `[` and `]` are plain template characters |

Now in `main` we cut `oʻrik` to two bytes, store the result in `cut`, and print it with `%q` (quoted text, GB-1.04).
`utf8.ValidString` checks that the bytes are valid UTF-8: `true` or `false`. The program (`_video/08-kesish/main.go`):

```go filename="_video/08-kesish/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

// short nomni chek ustuniga sigʻdiradi: limit'dan uzun boʻlsa kesadi.
func short(name string, limit int) string {
	if len(name) <= limit {
		return name
	}
	return name[:limit]
}

func main() {
	cut := short("oʻrik", 2)
	fmt.Printf("%q\n", cut)
	fmt.Println(utf8.ValidString(cut))
}
```

What does `short("oʻrik", 2)` return?

**A)** `"oʻ"` and `true` · **B)** `"o"` and `true` · **C)** broken text and `false`

<details>
<summary>Answer</summary>

**C: broken text and `false`.** `name[:2]` is two **bytes**: `o` (`6f`) and only the first byte of `ʻ` (`ca`). If you chose **A**, you thought it takes two
**characters**. If you chose **B**, you thought half a character is thrown away: Go throws nothing away, it keeps the byte as it is.

</details>

```console
$ ./_video/run.sh 08-kesish go run .
"o\xca"
false
```

A string can hold any byte, even one that is not UTF-8. `%q` shows such a byte as `\x` and two hex digits: `\xca`.
`ValidString` is `false`. On the receipt the terminal drew this `ca` byte as `�`.

**The fix:** count runes, not bytes. First the part that only counts (this is not a separate file, it is a half-finished state of the function):

```go
func short(name string, limit int) string {
	n := 0
	for i := range name {
		// … i — shu rune boshlangan bayt
		n++
	}
	return name
}
```

`n` is how many runes we have passed so far. If `range` has one variable, only the index comes: the byte where each rune starts.
On each step `n++` raises the count by one. If the loop finishes, the name fit into `limit`: it is returned whole. For now the loop only
counts; the cutting comes in the next step.

Now the cut. When `n` reaches `limit`, `i` is exactly the start of the **next** rune. We cut here: `name[:i]`. For example, for `oʻrik` and `limit` 2,
`i` is 3, and `name[:3]` takes `o` and `ʻ` completely. The full program (`_video/09-tuzat/main.go`):

```go filename="_video/09-tuzat/main.go" showLineNumbers
package main

import "fmt"

// short nomni limit ta rune'gacha qisqartiradi va rune'ni hech qachon oʻrtasidan kesmaydi.
func short(name string, limit int) string {
	n := 0
	for i := range name {
		if n == limit {
			return name[:i]
		}
		n++
	}
	return name
}

func main() {
	names := []string{"olma", "oʻrik qoqi", "paxta yogʻi"}
	for _, name := range names {
		fmt.Printf("[%-10s]\n", short(name, 10))
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 7 | `n := 0` | how many runes have been passed |
| 8 | `for i := range name {` | one step per rune; `i` is the byte where the rune starts |
| 9–11 | `if n == limit { return name[:i] }` | `limit` runes have passed: `i` is the start of the next rune, we cut here |
| 12 | `n++` | raises the count for the next rune |
| 14 | `return name` | the loop ended, the name fit into `limit` runes: it is returned whole |

How do `oʻrik qoqi` and `paxta yogʻi` come out on the receipt?

**A)** both whole · **B)** `oʻrik qoqi` whole, `paxta yogʻ` (10 runes) · **C)** `oʻrik qoq` and `paxta yog`: both lose a letter

<details>
<summary>Answer</summary>

**B.** `oʻrik qoqi` is 10 runes (11 bytes) and now fits whole. `paxta yogʻi` is 11 runes: it is cut cleanly after the 10th rune, and `ʻ` stays intact.
If you chose **A**, you thought `paxta yogʻi` fits too: it has 11 runes and the column is 10. **C** is the bug of the old `short` that cut by bytes.

</details>

```console
$ ./_video/run.sh 09-tuzat go run .
[olma      ]
[oʻrik qoqi]
[paxta yogʻ]
```

`oʻrik qoqi` is printed in full, `paxta yogʻi` is cut cleanly after the 10th rune. The column is even because the width in `Printf` is also measured in runes
([fmt documentation](https://pkg.go.dev/fmt#hdr-Printing): "Width and precision are measured in units of Unicode code points, that is, runes").
In real work, the length limit of a product name or a user name is checked in runes, not in bytes.

## Going deeper (optional): `[]rune`, `string(number)` and two apostrophes

This section is the optional part at the end of the video. Everything above works without it.

**`[]rune` and `string(...)`.** There is another way to cut runes: `[]rune(s)` turns text into a slice of runes, and `string(runes)` builds
UTF-8 text from it again. The program (`_video/10-runes/main.go`):

```go filename="_video/10-runes/main.go" showLineNumbers
package main

import "fmt"

func main() {
	runes := []rune("paxta yogʻi")
	fmt.Println(len(runes), string(runes[:10]))
}
```

On line 6 the text is stored in `runes`: each rune is an `int32`, that is, it takes 4 bytes. Now `len(runes)` counts runes, and `runes[:10]` is the first 10
runes (the index must not go past `len`). What does `len` print?

```console
$ ./_video/run.sh 10-runes go run .
11 paxta yogʻ
```

This is the simple way, but the whole text is **copied into new memory**; `range` does not copy. This is why `short` is written with `range`.

**`string(number)` and the diamond.** In GB-1.04, `string(total)` (`total = 3_067_216`) printed `jami: �`. `string(integer)` takes the number as **one code point**.
The largest code point is U+10FFFF = 1_114_111; `total` is bigger, so Go replaced it with the replacement character `�`
([Go spec: Conversions to a string type](https://go.dev/ref/spec#Conversions_to_and_from_a_string_type)). This is why `go vet` warned: "conversion from int64 to
string yields a string of one rune".

**`ʻ` and the plain apostrophe.** Two names are almost the same: the first has `ʻ` (the turned comma, 2 bytes), the second has the keyboard apostrophe (`'`, 1 byte).
The program (`_video/11-apostrof/main.go`):

```go filename="_video/11-apostrof/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println("oʻrik" == "o'rik")
	fmt.Println(len("oʻrik"), len("o'rik"))
}
```

Are they equal?

```console
$ ./_video/run.sh 11-apostrof go run .
false
6 5
```

`==` compares bytes ([Go spec: Comparison operators](https://go.dev/ref/spec#Comparison_operators)), so the answer is `false`.
If a customer searches for `oʻrik` with the plain apostrophe, the market will not find it. That is why names are brought to one form right at the input (those programs come in later lessons).

## Common mistakes

**1. "`len` returns the number of characters."** The most common mistake. If you check a name length limit with `len`, a limit of 20 characters
turns into fewer characters for Uzbek names. The next program is not in the course folder: I ran it in a separate folder.

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	name := "oʻgʻil bola koʻylagi"
	fmt.Println(len(name), utf8.RuneCountInString(name))
	if len(name) > 20 {
		fmt.Println("rad etildi: nom uzun")
	}
}
```

```console
$ go run .
23 20
rad etildi: nom uzun
```

(`oʻgʻil bola koʻylagi` is "a boy's shirt"; `rad etildi: nom uzun` is "rejected: the name is long".) The name has 20 characters but 23 bytes (`oʻ`, `gʻ`, `oʻ` — three `ʻ`, each
+1 byte). The condition `len(name) > 20` rejected it. The fix: `utf8.RuneCountInString(name) > 20` (this is exactly what `checkName` in the homework does).

**2. Walking over characters with an index.** `for i := 0; i < len(name); i++` goes over bytes. This program is not in the course folder either:

```go
package main

import "fmt"

func main() {
	name := "oʻrik"
	for i := 0; i < len(name); i++ {
		fmt.Printf("%d %c\n", i, name[i])
	}
}
```

```console
$ go run .
0 o
1 Ê
2 »
3 r
4 i
5 k
```

There is no error, but on lines 1 and 2 `Ê` and `»` appear instead of `ʻ`: `name[1]` and `name[2]` are the bytes `ca` and `bb`, and `%c` prints each as a separate code point (202 and
187). The fix: `for i, r := range name`.

**3. Changing a string by index.** A string is immutable, so a byte cannot be replaced in place. The program (not in the course folder):

```go
package main

import "fmt"

func main() {
	name := "oʻrik"
	name[0] = 'O'
	fmt.Println(name)
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:7:2: cannot assign to name[0] (neither addressable nor a map index expression)
```

How to read it: file `main.go`, line 7, column 2; "cannot assign to name[0]" means you cannot store a value into `name[0]`. The fix: build a new string
(for example `"O" + name[1:]`: here the first letter takes 1 byte, so it works; in general, build the text from runes).

**4. Slicing with `name[:n]`.** This is a silent bug: neither the compiler nor `go vet` says anything, and the result is broken text. We saw it above, in the section
"Fixing the receipt: cut at a rune boundary" (`"o\xca"`, `ValidString` is `false`). The fix: cut at the index that `range` gave you, as `short` does.

func shortLabel(name string, width int) string {

const maxNameRunes = 20

func checkName(name string) error {
	if name == "" {
		return errors.New("nom boʻsh")
	}
	if !utf8.ValidString(name) {
		return errors.New("nom UTF-8 emas")
	}
	if n := utf8.RuneCountInString(name); n > maxNameRunes {
		return fmt.Errorf("nom %d belgi, eng koʻpi %d", n, maxNameRunes)
	}
	return nil
}
