## Nimani oʻrganasiz

bozorga har buyurtmaning jami koʻrsatilgan hisobot kerak. Jami alohida ustunda saqlanmaydi: buyurtma qatorlari boshqa jadvalda turadi. Qatorsiz buyurtmani yoʻqotmasdan jamini qanday hisoblaysiz?

**Bitta gʻoya:** bogʻliq jadvallarning qatorlarini juftlang, buyurtma boʻyicha guruhlang va har guruhning jamini hisoblang. Juftsiz buyurtmalarni saqlang va ulardagi yoʻq qiymat bilan alohida ishlang.

Dars oxirida siz:

- `orders` va `order_items`ni `REFERENCES` bilan bogʻlaysiz;
- `JOIN`, `LEFT JOIN`, `GROUP BY` va `SUM` bilan hisobot tuzasiz;
- `note = NULL` nega hech narsa topmasligini tushuntirasiz, `IS NULL` va `COALESCE`ni toʻgʻri ishlatasiz;
- ikkita SQL soʻrov yozib, `go test` bilan tekshirasiz.

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| `JOIN` / `LEFT JOIN` | jadval qatorlarini juftlash; chap turi juftsiz chap qatorni ham saqlaydi | join / left join |
| `GROUP BY` + `SUM` | guruhlar tuzib, har guruhdan bitta yigʻindi olish | grouping / aggregate |
| `NULL` | qiymat yoʻq yoki nomaʼlum; oddiy taqqoslash nomaʼlum natija berishi mumkin | NULL / three-valued logic |

Ikki yordamchi: **tashqi kalit** (`REFERENCES`, foreign key) havola qilingan qator mavjudligini talab qiladi. **COALESCE** qavsdagi qiymatlarning birinchi NULL boʻlmaganini qaytaradi.

Oldingi darsdagi `products` jadvalini tayyorlaymiz: `id`, `name`, `price`, `stock`, `active` va toʻrtta mahsulot. `exec db` baza servisida buyruq bajaradi. `psql -f` container yoʻlidagi SQL faylni oʻqiydi.

`CREATE TABLE` yaratilgan jadvalni tasdiqlaydi; `INSERT 0 4` toʻrtta qator yozilganini bildiradi. Mahsulotlar: `olma`, `non`, `choy` va `oʻrik`.

Buyurtmada izoh ixtiyoriy boʻlsin. Har buyurtma qatori mavjud buyurtma va mahsulotga bogʻlansin. Toʻliq `orders.sql`:

```sql filename="orders.sql" showLineNumbers
CREATE TABLE orders (
    id       bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer text   NOT NULL,
    note     text
);
CREATE TABLE order_items (
    id         bigint  GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    order_id   bigint  NOT NULL REFERENCES orders (id),
    product_id bigint  NOT NULL REFERENCES products (id),
    quantity   integer NOT NULL CHECK (quantity > 0),
    unit_price bigint  NOT NULL CHECK (unit_price > 0)
);
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `CREATE TABLE orders (` | buyurtma jadvali va uning ustunlar roʻyxatini boshlaydi |
| 2 | `id ... PRIMARY KEY` | baza beradigan `bigint` raqam; asosiy kalit bitta qatorni aniqlaydi |
| 3 | `customer text NOT NULL,` | majburiy mijoz ismi; vergul ustunlarni ajratadi |
| 4 | `note text` | ixtiyoriy izoh: `NOT NULL` talabi yoʻq |
| 5 | `);` | ustunlar roʻyxatini yopib, buyruqni tugatadi |
| 6 | `CREATE TABLE order_items (` | buyurtma qatorlari jadvalini boshlaydi |
| 7 | `id ... PRIMARY KEY,` | har buyurtma qatori uchun baza beradigan raqam |
| 8 | `order_id ... REFERENCES orders (id),` | majburiy buyurtma raqami; havola qilingan buyurtma mavjud boʻlishi shart |
| 9 | `product_id ... REFERENCES products (id),` | majburiy mahsulot raqami; havola qilingan mahsulot mavjud boʻlishi shart |
| 10 | `quantity ... CHECK (quantity > 0),` | majburiy, musbat butun dona soni |
| 11 | `unit_price ... CHECK (unit_price > 0)` | xarid paytidagi bir donaning majburiy, musbat narxi, tiyinda |
| 12 | `);` | ikkinchi jadval taʼrifini tugatadi |

`unit_price` — xarid paytidagi narx nusxasi. `products.price` keyin oʻzgarsa, eski buyurtma jami oʻzgarmasligi kerak. Tashqi kalit mavjudlikni tekshiradi, narxni koʻchirmaydi.

## JOIN: har juftdan bitta natija qatori

Har buyurtma qatoriga mijoz kerak. Yangi `sorov.sql` fayliga quyidagi toʻliq soʻrovni yozing. Keyingi har soʻrovda shu fayl mazmunini almashtiring; soʻrovlarni oxiriga qoʻshmang.

```sql
SELECT orders.customer, order_items.quantity
FROM orders
JOIN order_items ON order_items.order_id = orders.id;
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `SELECT orders.customer, order_items.quantity` | ikkita ustunni tanlaydi; `jadval.ustun` qaysi jadvaldan olinishini aniqlaydi |
| 2 | `FROM orders` | buyurtmalar jadvalidan boshlaydi |
| 3 | `JOIN order_items ON ...` | `order_items.order_id = orders.id` boʻlgan qatorlarni juftlaydi; `ON` moslik sharti |

Bitta buyurtmaga bir nechta buyurtma qatori mos kelishi mumkin. Tanlangan ustunlarni chiqarishdan oldingi juftlash holati:

| Buyurtma | Mos qatorlarning donalari | JOIN natija qatorlari |
|---|---|---|
| 1, Dilnoza | 2, 3 | 2 |
| 2, Jasur | 1, 1 | 2 |
| 3, Malika | mos qator yoʻq | 0 |

**Bashorat:** bu JOIN nechta qator qaytaradi?
**A)** 3 buyurtma · **B)** 4 juft · **C)** Malika bilan 5 qator

<details>
<summary>Javob</summary>

**B: 4.** `JOIN` — `INNER JOIN`: faqat mos juftlar qoladi. A juftlar oʻrniga buyurtmalarni sanaydi. C uchun juftsiz buyurtma ham saqlanishi kerak.

</details>

```console
$ docker compose exec db psql -f /lab/sorov.sql
 customer | quantity 
----------+----------
 Dilnoza  |        2
 Dilnoza  |        3
 Jasur    |        1
 Jasur    |        1
(4 rows)
```

Malika yoʻq. Bu boshlangʻich soʻrovda `ORDER BY` yoʻq: koʻrsatilgan tartib shu safar chiqdi, ammo kafolatlanmagan. Keyingi hisobot soʻrovlari tartibni aniq belgilaydi.

## GROUP BY va SUM: har buyurtmaga bitta jami

Har qator uchun dona sonini xarid paytidagi narxga koʻpaytiramiz. Bu yerda `*` — koʻpaytirish; `SELECT *`da esa barcha ustunlarni tanlagan edi. **SUM** — agregat: kirish qiymatlarini bitta qiymatga yigʻadi. `AS jami` natija ustunini `jami` deb nomlaydi.

Avval `sorov.sql`ni quyidagi yetishmayotgan qismli urinishga almashtiring:

```sql
SELECT orders.id, orders.customer,
       SUM(order_items.quantity * order_items.unit_price) AS jami
FROM orders
JOIN order_items ON order_items.order_id = orders.id;
```

**Bashorat:** agregat bilan alohida buyurtma ustunlarini guruhlamasdan birga chiqarish mumkinmi?
**A)** ha, har buyurtmaga jami · **B)** ha, hammasiga bitta jami · **C)** GROUP BY xatosi

<details>
<summary>Javob</summary>

**C.** Soʻrov qaysi qatorlar bitta jamiga kirishini aytmadi. A guruhlash avtomatik boʻladi deb oʻylaydi. B umumiy yigʻindi yonida qaysi `orders.id` chiqishini belgilamaydi.

</details>

```console
$ docker compose exec db psql -f /lab/sorov.sql
psql:/lab/sorov.sql:4: ERROR:  column "orders.id" must appear in the GROUP BY clause or be used in an aggregate function
LINE 1: SELECT orders.id, orders.customer,
               ^
```

`psql:/lab/sorov.sql:4` faylni va buyruq tugagan qatorni koʻrsatadi. `LINE 1` va `^` xato ifodasini koʻrsatadi. `Must appear in the GROUP BY clause or be used in an aggregate function` talabi `orders.id`ga tegishli. Yaʼni ustun GROUP BY qismida yoki agregat ichida boʻlishi kerak.

`GROUP BY orders.id` bir xil buyurtma raqamlarini guruhlaydi. `ORDER BY orders.id` natijani raqam oʻsishi boʻyicha tartiblaydi:

```sql
SELECT orders.id, orders.customer,
       SUM(order_items.quantity * order_items.unit_price) AS jami
FROM orders
JOIN order_items ON order_items.order_id = orders.id
GROUP BY orders.id
ORDER BY orders.id;
```

1–4-qatorlar buyurtma ustunlarini tanlaydi, yigʻindini hisoblaydi va jadvallarni bogʻlaydi. 5-qator guruhlaydi, 6-qator tartiblaydi va buyruqni tugatadi. `SUM(...)` qavsdagi ifodani har kirish qatorida hisoblab, guruh ichida yigʻadi.

| Guruh | Qator summalari, tiyinda | SUM |
|---|---|---|
| 1-buyurtma | `2 × 1200000 + 3 × 400000` | 3600000 |
| 2-buyurtma | `1 × 3500000 + 1 × 1200000` | 4700000 |

Nega `orders.customer` GROUP BY ichida yoʻq? `orders.id` jadvalning asosiy kaliti: har raqamga aynan bitta mijoz toʻgʻri keladi. PostgreSQL shu bogʻliqlikni taniydi. Bu istalgan guruhlanmagan ustunni tanlashga ruxsat emas.

**Bashorat:** nechta natija qatori qoladi?
**A)** 3 · **B)** 2 · **C)** 4

<details>
<summary>Javob</summary>

**B: 2.** Toʻrtta juftlangan qator ikki guruh boʻladi. A JOIN chiqarib yuborgan Malikani ham sanaydi. C guruhlashdan oldingi qatorlarni sanaydi.

</details>

```console
$ docker compose exec db psql -f /lab/sorov.sql
 id | customer |  jami   
----+----------+---------
  1 | Dilnoza  | 3600000
  2 | Jasur    | 4700000
(2 rows)
```

Summalar 3 600 000 va 4 700 000 tiyin. `SUM(bigint)` hatto bu butun summalar uchun PostgreSQL'ning aniq sonli `numeric` turini qaytaradi. Uni Go'ga oʻqish [GB-5.05 · Go → Postgres: pgx](/lab/youtube/gb/gb-5-05)da oʻrganiladi.

## LEFT JOIN va NULL: yoʻqolgan buyurtmani saqlash

Hisobotga har buyurtma kerak. **LEFT JOIN** chap jadvalning barcha qatorini saqlaydi; bizda bu `orders`. Mos juft topilmasa, oʻng jadval ustunlariga NULL beradi. `order_items` jadvaliga yangi qator yozmaydi.

`sorov.sql`ni almashtiring:

```sql
SELECT orders.customer, order_items.quantity
FROM orders
LEFT JOIN order_items ON order_items.order_id = orders.id;
```

Faqat 3-qator oʻzgardi: `LEFT` endi juftsiz buyurtmani saqlaydi. Toʻrtta mos juft va donasi NULL boʻlgan Malika qatorini kuting:

```console
$ docker compose exec db psql -f /lab/sorov.sql
 customer | quantity 
----------+----------
 Dilnoza  |        2
 Dilnoza  |        3
 Jasur    |        1
 Jasur    |        1
 Malika   |         
(5 rows)
```

**NULL** — qiymat yoʻq yoki nomaʼlum. U nol ham, `''` ham emas. NULL bilan oddiy `=` va `<>` taqqoslashlari nomaʼlum natija, NULL beradi. Bu **uch qiymatli mantiq**: rost, yolgʻon, nomaʼlum. `WHERE` faqat rostni qoldiradi.

| `note` | `note = NULL` | WHERE qoldiradimi? | `note IS NULL` |
|---|---|---|---|
| `NULL` | nomaʼlum (`NULL`) | yoʻq | rost |
| `'ertalab yetkazing'` | nomaʼlum (`NULL`) | yoʻq | yolgʻon |
| `''` | nomaʼlum (`NULL`) | yoʻq | yolgʻon |

Boʻsh matn qatori qoidani koʻrsatadi; u seed ichidagi qoʻshimcha qator emas.

**Bashorat:** ikkita buyurtmaning izohi NULL. `WHERE note = NULL` nechta qator qaytaradi?
**A)** 2 · **B)** 0 · **C)** sintaksis xatosi

<details>
<summary>Javob</summary>

**B: 0.** Shart har qatorda nomaʼlum, hech qachon rost emas. A NULL'ni oddiy taqqoslanadigan qiymat deb hisoblaydi. C notoʻgʻri: soʻrov toʻgʻri, ammo jimgina hech narsa qaytarmaydi.

</details>

```console
$ docker compose exec db psql -c 'SELECT id, customer FROM orders WHERE note = NULL'
 id | customer 
----+----------
(0 rows)
```

Qiymat yoʻqligini **IS NULL** bilan tekshiring. U doim rost yoki yolgʻon qaytaradi; `IS NOT NULL` teskarisini soʻraydi. Dilnoza va Malika chiqishini kuting:

```console
$ docker compose exec db psql -c 'SELECT id, customer FROM orders WHERE note IS NULL'
 id | customer 
----+----------
  1 | Dilnoza
  3 | Malika
(2 rows)
```

Bu ikki namoyish filtrida `ORDER BY` yoʻq; koʻrsatilgan qatorlar tartibi kafolatlanmagan. Uy vazifasidagi soʻrov uni qoʻshadi.

## COALESCE: yoʻq jami oʻrniga nol

Endi guruhlangan hisobotda barcha buyurtmani saqlaymiz. Oldingi guruhlash soʻrovida faqat `JOIN`ni `LEFT JOIN`ga almashtiring:

```sql
SELECT orders.id, orders.customer,
       SUM(order_items.quantity * order_items.unit_price) AS jami
FROM orders
LEFT JOIN order_items ON order_items.order_id = orders.id
GROUP BY orders.id
ORDER BY orders.id;
```

`SUM` NULL qiymatlarni oʻtkazib yuboradi. Malikaning guruhida bitta natija qatori bor, uning donasi va narxi NULL. Koʻpaytirish ham NULL beradi; qoʻshiladigan NULL boʻlmagan summa yoʻq.

**Oraliq savol:** Malikaning SUM natijasi nima?
**A)** 0 · **B)** NULL · **C)** xato

<details>
<summary>Javob</summary>

**B: NULL.** NULL boʻlmagan kirish qiymati qolmasa, SUM NULL qaytaradi. A agregat avtomatik nol beradi deb oʻylaydi; C qiymat yoʻqligini SQL xatosi deb hisoblaydi.

</details>

```console
$ docker compose exec db psql -f /lab/sorov.sql
 id | customer |  jami   
----+----------+---------
  1 | Dilnoza  | 3600000
  2 | Jasur    | 4700000
  3 | Malika   |        
(3 rows)
```

Boʻsh jami — NULL. Hisobotda nol chiqishi uchun 2-qatorni `COALESCE(SUM(...), 0) AS jami`ga almashtiring. Toʻliq soʻrov:

```sql
SELECT orders.id, orders.customer,
       COALESCE(SUM(order_items.quantity * order_items.unit_price), 0) AS jami
FROM orders
LEFT JOIN order_items ON order_items.order_id = orders.id
GROUP BY orders.id
ORDER BY orders.id;
```

**COALESCE** vergul bilan ajratilgan qiymatlarni tartibda koʻrib, birinchi NULL boʻlmaganini qaytaradi. Ichki qavsda SUM ifodasi; tashqi qavsda SUM natijasi va zaxira nol bor. Boshqa qatorlar oʻzgarmadi.

| Buyurtma | Mos qatorlar | SUM | COALESCE(SUM, 0) |
|---|---|---|---|
| 1 | 2 | 3600000 | 3600000 |
| 2 | 2 | 4700000 | 4700000 |
| 3 | 0 | `NULL` | 0 |

Uchta buyurtma va 3600000, 4700000, 0 jamilarini kuting:

```console
$ docker compose exec db psql -f /lab/sorov.sql
 id | customer |  jami   
----+----------+---------
  1 | Dilnoza  | 3600000
  2 | Jasur    | 4700000
  3 | Malika   |       0
(3 rows)
```

`LEFT JOIN` buyurtmani saqlaydi; `COALESCE` uning yoʻq jamini almashtiradi. Ikkalasi ham kerak: COALESCE INNER JOIN chiqarib yuborgan qatorni qaytara olmaydi.

## Chuqurroq (ixtiyoriy): NULL bilan teng emas

`<>` — «teng emas», ammo NULL izohni matnga taqqoslash yana nomaʼlum beradi. `'ertalab yetkazing'`dan farqli izohlarni soʻrasak, nechta qator qoladi? Hech qaysisi: Jasurning sharti yolgʻon, qolgan ikkitasi nomaʼlum.

```console
$ docker compose exec db psql -c "SELECT id, customer FROM orders WHERE note <> 'ertalab yetkazing'"
 id | customer 
----+----------
(0 rows)
```

**IS DISTINCT FROM** NULL'ni taqqoslanadigan yoʻq qiymat sifatida koʻradi. NULL va shu matn farqli, shuning uchun Dilnoza va Malika qoladi. Ikkita NULL farqli emas deb hisoblanadi.

```console
$ docker compose exec db psql -c "SELECT id, customer FROM orders WHERE note IS DISTINCT FROM 'ertalab yetkazing'"
 id | customer 
----+----------
  1 | Dilnoza
  3 | Malika
(2 rows)
```

Bu filtrlarda ham `ORDER BY` yoʻq. Ish qoidasi oddiy teng emasni emas, «yoʻq qiymatni ham qoʻshib, farqli»ni talab qilsa, shu shartni ishlating.

## Koʻp uchraydigan xatolar

1. **`WHERE note = NULL`.** SQL toʻgʻri, natija boʻsh. «LEFT JOIN va NULL» boʻlimida xato soʻrov va haqiqiy natija bor. `WHERE note IS NULL` yozing; `''` alohida qiymat.
2. **SUM oʻzi guruhlaydi deb kutish.** «GROUP BY va SUM»dagi toʻrt qatorli soʻrov haqiqiy `must appear in the GROUP BY clause` xatosini beradi. `GROUP BY orders.id` qoʻshing; aniq tartib uchun `ORDER BY`ni saqlang.
3. **Barcha buyurtmalar hisobotida INNER JOIN.** Soʻrov ishlaydi, ammo Malikani tushirib qoldiradi. LEFT JOIN va jami uchun COALESCE yozing; faqat NULL'ni almashtirish qatorni qaytarmaydi.
4. **LEFT JOIN'dan keyin oʻng jadvalni filtrlash.** `WHERE order_items.quantity > 0` NULL qoʻshilgan qatorni yana chiqarib yuboradi. Har chap qator saqlanishi kerak boʻlsa, qator cheklovini `ON`ga qoʻying yoki yozmang.
5. **NULL yigʻindini DESC bilan saralash.** PostgreSQL odatda kamayish tartibida NULL'ni birinchi qoʻyadi. Vazifaga sonli nol kerak: tartiblashdan oldin COALESCE qoʻllang.

Tashqi kalit havola qiluvchi ustunga avtomatik indeks ham yaratmaydi. Indeks tanlash va bogʻlanishni tekshirish alohida ishlar.

</details>

SELECT products.name,
       COALESCE(SUM(order_items.quantity), 0) AS sotilgan
