## Nimani oʻrganasiz

bozor katalogiga bir vaqtda yuzlab soʻrov kelishi mumkin. Server, route'lar, JSON yordamchilari va store bitta katalog bilan qanday xavfsiz ishlaydi? Har xato qayerda HTTP javobiga aylanishi kerak?

**Bitta gʻoya:** soʻrov bitta yoʻldan oʻtadi: server → mux → handler → qulfli store → javob. Qulf murojaatni faqat ushlangan paytda himoya qiladi. Store nusxa qaytarsin: shunda JSON yozish qulf ochilgach umumiy maʼlumotni oʻqimaydi.

Dars oxirida siz:

- 3-modul katalogi ustida `cmd/api`ni yigʻasiz;
- store xatosini HTTP statusga bitta joyda aylantirasiz;
- route'larni haqiqiy mux orqali tekshirib, oddiy test sezmagan poygani topasiz;
- `DELETE /products/{id}`ni oʻz testingiz bilan qoʻshasiz.

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| API qismlarini ulash | server, mux va handler'larga bitta katalog beriladi | API wiring |
| store xatosini statusga aylantirish | bitta funksiya store xatosi uchun HTTP statusni tanlaydi | store error mapping |
| qiymat nusxasi | handler katalog ichidagi koʻrsatkichni emas, oʻz `Product` qiymatini oladi | value copy |

**CRUD** — yaratish, oʻqish, oʻzgartirish va oʻchirish. Bu yerda buyurtma qoldiqni oʻzgartiradi; oʻchirish esa vazifa. Ikki yordamchi status: **500 Internal Server Error** — serverdagi kutilmagan xato, **204 No Content** — muvaffaqiyatli, ammo body'siz javob.

## Bitta katalog, bitta soʻrov yoʻli

Kod — 3-modul CLI'si va yangi HTTP kirish nuqtasi:

| Fayl | Vazifasi |
|---|---|
| `cmd/bozor/` | oldingi CLI |
| `cmd/api/main.go` | katalogni yuklash va serverni boshlash |
| `cmd/api/handlers.go` | `api`, route'lar, handler'lar, ID oʻqish va xatoni statusga aylantirish |
| `cmd/api/json.go` | GB-4.06'dan JSON yordamchilari |
| `cmd/api/api_test.go` | route, qoldiq, server va parallel testlar |
| `internal/store/store.go` | mahsulotlar va qoldiq qoidalari, endi mutex bilan |
| `internal/store/file.go` | GB-3.06'dan `Load` va atomar `Save` |
| `internal/store/restock_test.go` | oldingi qoldiq toʻldirish vazifasining testlari |
| `cmd/api/tekshiruv_test.go`, `internal/store/tekshiruv_test.go` | yangi vazifa tekshiruvlari |

| Bosqich | Kirish → amal → natija |
|---|---|
| `http.Server` | ulanish → soʻrov header'larini 5 soniyada oʻqish → mux |
| `ServeMux` | metod va yoʻl → pattern tanlash → handler |
| handler | yoʻl yoki body → oʻqish va tekshirish → store chaqiruvi |
| store | `mu`ni olish → katalogni oʻqish yoki oʻzgartirish → natijani nusxalash → `mu`ni ochish |
| javob | muvaffaqiyat → `writeJSON`; store xatosi → `writeStoreError` |

Avval `handlers.go`dagi ulash boʻlagi:

```go
type api struct {
	st *store.Store
}

func newMux(st *store.Store) *http.ServeMux {
	a := &api{st: st}
	mux := http.NewServeMux()
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /products", a.listProducts)
	mux.HandleFunc("GET /products/{id}", a.getProduct)
	mux.HandleFunc("POST /products", a.createProduct)
	mux.HandleFunc("POST /orders", a.createOrder)
	// VAZIFA (TASK.md, 2-qadam): DELETE /products/{id} → a.deleteProduct
	return mux
}
```

| Kod | Nima qiladi |
|---|---|
| `type api struct`, `st *store.Store` | handler'lar ishlatadigan bogʻliqliklar; `st` yagona katalogga qaraydi |
| `newMux(st *store.Store) *http.ServeMux` | shu katalogni oladi va mux qaytaradi |
| `a := &api{st: st}` | `api` yasaydi; `st` maydoniga `st` argumentini beradi |
| `http.NewServeMux()` | alohida route jadvali yasaydi |
| beshta `HandleFunc` chaqiruvi | holat, roʻyxat, bitta mahsulot, mahsulot yaratish va buyurtmani roʻyxatdan oʻtkazadi |
| `a.listProducts` | **metod qiymati** (method value): `a`ga bogʻlangan funksiya; qavs yoʻq, roʻyxatdan oʻtkazish uni chaqirmaydi |
| vazifa izohi, `return mux` | yetishmayotgan oʻchirish route'ini belgilaydi va sozlangan mux'ni qaytaradi |

Global katalog yoʻq. Har test `newMux`ga oʻz store'ini beradi: bir testning buyurtmasi boshqasining boshlangʻich qoldigʻini oʻzgartirmaydi. `healthHandler`ga katalog kerak emas; u oddiy matnda `ok` qaytaradi.

Toʻliq `main.go`:

```go filename="cmd/api/main.go" showLineNumbers
// api — bozor katalog API'si (GB-4.08, 4-modul nazorat nuqtasi): GB-3.06'dagi internal/store
// katalogi HTTP orqali. Katalog ishga tushishda bozor.json'dan oʻqiladi (CLI yozgan fayl) va keyin
// xotirada turadi: API'dagi oʻzgarishlar faylga yozilmaydi, server toʻxtasa yoʻqoladi.
// Saqlash Postgres'ga 5-modulda koʻchadi (GB-5.01: nega baza kerak).
//
//	go run ./cmd/api        → bozor API: http://localhost:8765
package main

import (
	"fmt"
	"net/http"
	"os"
	"time"

	"github.com/abdurahmon27/bozor/internal/store"
)

const dataFile = "bozor.json"

// newServer — bozor API serveri (GB-4.04): route'lar newMux'da (GB-4.05), sarlavhalar uchun vaqt chegarasi.
func newServer(addr string, st *store.Store) *http.Server {
	return &http.Server{
		Addr:              addr,
		Handler:           newMux(st),
		ReadHeaderTimeout: 5 * time.Second, // soʻrov sarlavhalari 5 s'da kelmasa, ulanish yopiladi
	}
}

func main() {
	st, err := store.Load(dataFile)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	srv := newServer(":8765", st)
	fmt.Println("bozor API: http://localhost:8765")
	err = srv.ListenAndServe()
	fmt.Fprintln(os.Stderr, "xato:", err)
	os.Exit(1)
}
```

| Qatorlar | Nima qiladi |
|---|---|
| 1–6 | izohlar xotiradagi API va uni boshlash buyrugʻini tushuntiradi |
| 7–16 | `package main`; chiqish, HTTP, jarayon, vaqt paketlari va `internal/store` import'i |
| 18 | `dataFile` — nisbiy `bozor.json` fayl nomi |
| 20–27 | `newServer`: manzil argumentdan, `Handler: newMux(st)`, header oʻqish chegarasi `5 * time.Second` |
| 29–34 | `main` `store.Load`ni chaqiradi; xato `os.Stderr`ga yoziladi, chiqish kodi 1 |
| 35–36 | `:8765`da server yasaydi va manzilini yozadi |
| 37–40 | `ListenAndServe` soʻrov kutadi; qaytganda uning `nil` boʻlmagan xatosi yoziladi va dastur tugaydi |

`bozor.json` faqat ish boshlanishida oʻqiladi. API oʻzgarishlari xotirada qoladi, jarayon toʻxtasa yoʻqoladi. Har soʻrovda `Save` chaqirilmaydi. Doimiy saqlash 5-modulda keladi.

## Route'larni ishga tushirib, javobni oʻqing

Mahalliy `8765` porti boʻshligini tekshirdim, API'ni ishga tushirdim va soʻrovlardan keyin toʻxtatdim. Birinchi terminalda dars ildizidan boshlang:

```console
$ go run ./cmd/api
bozor API: http://localhost:8765
```

`go run ./cmd/api` paketni qurib, ishga tushiradi. Uni ishlab turgan holda qoldiring; `curl` uchun ikkinchi terminaldan foydalaning. `-s` jarayon koʻrsatkichini yashiradi; `-i` javob header'larini qoʻshadi; `-d` body beradi va POST tanlaydi; `-X DELETE` DELETE'ni ochiq tanlaydi. Header chiqishlarida `…` oʻrnida `Date`, `Content-Length` va bor joyida `X-Content-Type-Options` tushirilgan.

Katalog ID'lari GB-3.06'dan: `olma` 1, `non` 2, `choy` 3, `oʻrik` 4. Kichik laboratoriyalarda ID'lar boshqacha edi. Oʻrikni oʻqing:

```console
$ curl -s localhost:8765/products/4
{"id":4,"name":"oʻrik","price":3500000,"stock":2}
```

`price` tiyinda: `3500000` — 35 000 soʻm; `stock` — 2 dona.

Bashorat qiling: buyurtma 4-mahsulotdan 5 dona soʻraydi. Miqdor tekshiruvi 1–100 donaga ruxsat beradi, ammo qoldiq 2. Status qaysi?

**A)** 422 · **B)** 409 · **C)** 201

<details>
<summary>Javob</summary>

**B: 409 Conflict.** Besh — ruxsat etilgan miqdor, lekin soʻrov hozirgi qoldiqqa zid. **A** nol kabi notoʻgʻri miqdorga tegishli; **C** mahsulot yetmay turib muvaffaqiyat degan boʻlardi. Bu API tanlagan status kelishuvi.

</details>

```console
$ curl -s -i localhost:8765/orders -d '{"product_id":4,"quantity":5}'

Content-Type: application/json
…

{"error":{"code":"insufficient_stock","message":"oʻrik: qoldiq 2, soʻralgan 5"}}
```

`insufficient_stock` — oʻzgarmas xato kodi, `message` esa qoldiq 2, soʻralgan 5 ekanini aytadi. `-H Content-Type` berilmagan: bu server soʻrovning format header'ini tekshirmaydi, body'ni JSON deb oʻqiydi. GB-4.01'dagi namuna server tekshirgan edi; u boshqa kelishuv edi.

**A)** `7000000`, qoldiq 0 · **B)** `70000`, qoldiq 0 · **C)** xato, qoldiq 2

**A.** `3500000 × 2 = 7000000` tiyin, yaʼni 70 000 soʻm. Buyurtma ikkala donani oladi. **B** tiyin bilan soʻmni aralashtiradi; **C** mavjud miqdorning hammasini sotib olish mumkinligini unutadi.

## Handler yoʻli bir xil, store xatosi bitta joyda

`handlers.go`dan oʻzgartirmay olingan `getProduct` va ID yordamchisi:

```go
func (a *api) getProduct(w http.ResponseWriter, r *http.Request) {
	id, ok := pathID(w, r)
	if !ok {
		return
	}
	p, err := a.st.Get(id)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	writeJSON(w, http.StatusOK, p)
}

func pathID(w http.ResponseWriter, r *http.Request) (int64, bool) {
	id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)
	if err != nil {
		writeError(w, http.StatusBadRequest, apiError{Code: "bad_id", Message: "id butun son boʻlishi kerak"})
		return 0, false
	}
	return id, true
}
```

| Har funksiyadagi qatorlar | Maʼnosi |
|---|---|
| `getProduct` 1–5 | `a *api` — receiver; `w` javob yozadi, `r` — soʻrov; `pathID` xatoni oʻzi yozib, `false` qaytaradi |
| `getProduct` 6–10 | shu API'ning `a.st.Get(id)` metodini chaqiradi; xato boʻlsa bitta joyda statusga aylantirib, `return` bilan toʻxtaydi |
| `getProduct` 11–12 | mahsulotni 200 bilan yozadi |
| `pathID` 1–2 | `r.PathValue("id")` bilan wildcard'ni oʻqiydi; `ParseInt` oʻnlik matnni 64 bitli songa aylantiradi |
| `pathID` 3–8 | oʻqish xatosida `400 bad_id` yozib, `0, false` qaytaradi; aks holda ID va `true` |

Ikki POST handler ham shu yoʻldan yuradi. Quyida toʻliq funksiya tanalari; ular shu fayldagi kirish turlari va tekshiruv funksiyalaridan foydalanadi:

```go
func (a *api) createProduct(w http.ResponseWriter, r *http.Request) {
	var in productInput
	if !decodeJSON(w, r, &in) {
		return
	}
	if f := validate(in); len(f) > 0 {
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: "qiymatlar notoʻgʻri", Fields: f})
		return
	}
	p, err := a.st.Add(in.Name, in.Price, in.Stock)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	w.Header().Set("Location", fmt.Sprintf("/products/%d", p.ID)) // yangi resursning manzili (RFC 9110 §15.3.2)
	writeJSON(w, http.StatusCreated, p)
}

func (a *api) createOrder(w http.ResponseWriter, r *http.Request) {
	var in orderInput
	if !decodeJSON(w, r, &in) {
		return
	}
	if f := validateOrder(in); len(f) > 0 {
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: "qiymatlar notoʻgʻri", Fields: f})
		return
	}
	p, err := a.st.Sell(in.ProductID, in.Quantity)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	// Narx ≤ maxPrice (store), dona ≤ 100 (validateOrder): koʻpaytma int64'ga sigʻadi.
	writeJSON(w, http.StatusCreated, orderResponse{ProductID: p.ID, Quantity: in.Quantity, Total: p.Price * int64(in.Quantity)})
}
```

`productInput` maydonlari: `Name string`, `Price int64`, `Stock int`; `orderInput`da `ProductID int64`, `Quantity int`. JSON tag'lari soʻrov kalitlariga mos. `orderResponse` ichida `ProductID`, `Quantity`, `Total` bor; `Order` nomi keyingi domen turi uchun saqlanadi.

| Kod | Nima qiladi |
|---|---|
| `var in …`, `decodeJSON(w, r, &in)` | kirish qiymatini yaratib, manzili orqali oʻqiydi; xatoda yordamchi javob yozadi, shuning uchun qaytiladi |

[`json.go`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-4-08-katalog-api/cmd/api/json.go) yordamchilari GB-4.06'dan: body eng koʻpi 1024 bayt, ortiqcha kalit rad etiladi, JSON qiymat bitta boʻlishi kerak. Yangi **store xatosini statusga aylantirish** bitta funksiyada:

```go
func writeStoreError(w http.ResponseWriter, err error) {
	var se *store.StockError
	switch {
	case errors.Is(err, store.ErrNotFound):
		writeError(w, http.StatusNotFound, apiError{Code: "not_found", Message: err.Error()})
	case errors.As(err, &se):
		writeError(w, http.StatusConflict, apiError{Code: "insufficient_stock", Message: err.Error()})
	case errors.Is(err, store.ErrBadQuantity), errors.Is(err, store.ErrBadProduct):
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: err.Error()})
	default:
		log.Printf("ichki xato: %v", err) // tafsilot server logiga (slog: GB-8.02), mijozga emas
		writeError(w, http.StatusInternalServerError, apiError{Code: "internal", Message: "ichki xato"})
	}
}
```

| Tarmoq | Status va kod | Sabab |
|---|---|---|
| `errors.Is(err, store.ErrNotFound)` | 404 `not_found` | shu ID'li mahsulot yoʻq; oʻralgan xatoda ham topiladi |
| `errors.As(err, &se)` | 409 `insufficient_stock` | oʻram ichidan `*StockError`ni topadi; `se` — nishon koʻrsatkich |
| vergulli `case`dagi ikki xatodan biri | 422 `validation_failed` | miqdor yoki mahsulot store qoidasiga zid |
| `default` | 500 `internal` | kutilmagan xato; mijozga faqat `ichki xato` |

`switch`dan keyin ifoda yoʻq: har `case` — shart. Vergul bilan yozilgan ikki shartdan bittasi mos kelsa yetadi. `log.Printf("ichki xato: %v", err)` asl xatoni server logiga yozadi; `%v` uning qiymatini formatlaydi. Javobga ichki fayl yoʻli chiqmaydi. `slog` bilan tuzilgan log [GB-8.02](/lab/youtube/gb#gb-8-02)da keladi.

## Nusxa qulf ostida, yield esa qulfdan keyin

Store yana GB-3.06'dagi tartibli `[]Product`dan foydalanadi. GB-4.07'dagi `map` kichik parallel laboratoriya uchun edi. Store'ga `mu sync.Mutex` qoʻshiladi; `Add`, `Sell`, `Restock`, `Get` boshida `Lock` va `defer Unlock` bor. Hamma receiver `*Store`ligicha qoladi: mutex nusxalanmaydi.

`All` kirishdagi deadlock'ni hal qiladi:

```go
func (s *Store) All() iter.Seq[Product] {
	return func(yield func(Product) bool) {
		s.mu.Lock()
		products := slices.Clone(s.products)
		s.mu.Unlock()
		for _, p := range products {
			if !yield(p) {
				return
			}
		}
	}
}
```

| Qator | Nima qiladi |
|---|---|
| 1–2 | `iter.Seq[Product]` qaytaradi: iterator funksiyasi `yield`ni oladi |
| 3–5 | qulfni oladi, mahsulotlar slice'ini mahalliy `products`ga nusxalaydi, qulfni darhol ochadi |
| 6 | shu nusxa ustida aylanadi |
| 7–10 | har nusxa mahsulotni `yield`ga beradi; `false`, jumladan chaqiruvchining `break`ida, toʻxtaydi |
| 11–12 | iterator funksiyasi va metod tugaydi |

| Payt | Umumiy katalog | Iterator | Qulf |
|---|---|---|---|
| nusxalash | `slices.Clone` oʻqiydi | oʻz slice'ini yasaydi | ushlangan |
| `yield(p)` | boshqa soʻrov oʻzgartirishi mumkin | faqat oʻz nusxasini oʻqiydi | ochiq |
| sikl tanasi `Sell`ni chaqiradi | qoldiq xavfsiz oʻzgaradi | oldingi nusxasi oʻzgarmaydi | `Sell` uni ololadi |

Bu yerda `defer Unlock` qulfni iterator tugaguncha, har bir `yield` davomida ham ushlab turardi. Ochiq `Unlock` ataylab qoʻyilgan. Endi `All` oldingi jonli koʻrinish oʻrniga aylanish boshlanganda olingan nusxani beradi.

Roʻyxat handler'i shu iteratorni yigʻadi:

```go
func (a *api) listProducts(w http.ResponseWriter, r *http.Request) {
	products := slices.Collect(a.st.All())
	if products == nil {
		products = []store.Product{} // boʻsh katalog JSON'da null emas, [] boʻlsin (GB-3.06)
	}
	writeJSON(w, http.StatusOK, products)
}
```

`slices.Collect` qiymatlarni slice'ga yigʻadi. Boʻsh iterator `nil` beradi; u JSON'da `null` boʻlardi. 3–5-qatorlar uni `[]store.Product{}` — boʻsh, ammo `nil` boʻlmagan slice bilan almashtiradi: javob `[]`. Oxirgi chaqiruv 200 va shu slice'ni yuboradi.

```go
func TestParallel(t *testing.T) {
	st := testStore(t)
	h := newMux(st)
	var wg sync.WaitGroup
	for range 30 {
		wg.Go(func() { send(h, "POST", "/orders", `{"product_id":1,"quantity":1}`) })
		wg.Go(func() { send(h, "GET", "/products/1", "") })
```

Xabar race rejimiga C bilan ishlash kerakligini aytadi. Linux'da cgo'ni yoqing **va** `gcc` kabi C kompilyator boʻlsin; faqat `CGO_ENABLED=1` uni oʻrnatmaydi. Barcha race buyruqlarini berilgan Docker skripti bilan qayta ishlatdim. Kerakli kompilyator bor mashinada bevosita `go test -race ./...` ishlaydi. Docker GB-5.02'da tushuntiriladi.

**3. `yield` davomida qulfni tutish yoki qulfli `Delete` ichida `Get` chaqirish.** Ikkalasi ham oʻsha mutex'ni ikki marta kutishi mumkin. `All`dagi nusxa usulidan foydalaning; `Delete` ichida qulfni bir marta olib, bevosita `s.products`dan qidiring.

**4. `writeJSON(w, 204, nil)` ishlatish.** U `null` yozishga urinadi. Haqiqiy server 204'ga body yozishni rad etadi; recorder esa uni yozib, boʻsh body testini yiqitishi mumkin. Faqat `w.WriteHeader(http.StatusNoContent)` ishlating.

**5. Dars ildizidan tashqarida boshlash.** `bozor.json` — nisbiy yoʻl. `Load`da yoʻq fayl boʻsh katalog degani; boshlash xatosi emas. Shu fayl bor papkadan ishlating. 8765 porti band boʻlsa, yangi serverdan oldin oʻzingizning oldingi serveringizni toʻxtating.

## Oʻzingizni tekshiring

**1.** Nega `Get` nusxa qaytarishi kerak?

</details>

**2.** Store xatosi qayerda statusga aylanadi? Kutilmagan xato nima boʻladi?

<details>
<summary>Javob</summary>

</details>

**3.** [GB-4.05](/lab/youtube/gb/gb-4-05)dan: yangi soʻrovda handler mux'siz chaqirilsa, `r.PathValue("id")` nima qaytaradi?

<details>
<summary>Javob</summary>

Boʻsh matn: mux wildcard'ni toʻldirmagan. Shu sababli testlar `newMux(st)` orqali yuboriladi; route tanlanishi ham tekshiriladi.

</details>

**4.** Bashorat qiling: `All` `mu` ostida nusxalaydi, qulfni ochadi, keyin sikl tanasi `Sell`ni chaqiradi. **A)** deadlock · **B)** tugay oladi · **C)** `Sell` iterator nusxasini oʻzgartiradi.

```go
func (s *Store) Delete(id int64) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	i := slices.IndexFunc(s.products, func(p Product) bool { return p.ID == id })
	if i < 0 {
		return fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
	}
	s.products = slices.Delete(s.products, i, i+1)
	return nil
}

func (a *api) deleteProduct(w http.ResponseWriter, r *http.Request) {
	id, ok := pathID(w, r)
	if !ok {
		return
	}
	if err := a.st.Delete(id); err != nil {
		writeStoreError(w, err)
		return
	}
	w.WriteHeader(http.StatusNoContent)
}
```

`Delete` mutex'ni bir marta oladi. `IndexFunc` ID boʻyicha qidiradi; manfiy indeksda oʻralgan xato qaytadi. `slices.Delete` bitta elementni oʻchiradi; qaytgan slice `s.products` oʻrniga yoziladi. `defer` ikkala `return`da ham qulfni ochadi. `deleteProduct` bir marta oʻqiydi, bir marta oʻchiradi, keyin statusga aylantirilgan xato yoki body'siz 204 yozadi.

`newMux` ichiga qoʻshiladigan route qatori:

```go
mux.HandleFunc("DELETE /products/{id}", a.deleteProduct)
```

Namuna test:

```go
func TestDeleteProduct(t *testing.T) {
	tests := []struct {
		name   string
		path   string
		status int
	}{
		{"bor", "/products/3", 204},
		{"yoq", "/products/99", 404},
		{"xato_id", "/products/abc", 400},
	}
	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			h := newMux(testStore(t))
			if rec := send(h, "DELETE", tc.path, ""); rec.Code != tc.status {
				t.Errorf("DELETE %s: status %d, kutilgan %d: %s", tc.path, rec.Code, tc.status, rec.Body)
			}
		})
	}
	// oʻchirilgan mahsulot GET'da ham yoʻq
	h := newMux(testStore(t))
	send(h, "DELETE", "/products/3", "")
	if rec := send(h, "GET", "/products/3", ""); rec.Code != 404 {
		t.Errorf("DELETE'dan keyin GET /products/3: status %d, kutilgan 404", rec.Code)
	}
}
```
