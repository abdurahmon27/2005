## Что вы узнаете

К каталогу bozor могут одновременно прийти сотни запросов. Как сервер, маршруты, JSON-функции и хранилище безопасно работают с одним каталогом? Где каждая ошибка должна превращаться в HTTP-ответ?

**Одна идея:** запрос проходит один путь: сервер → mux → обработчик → хранилище под блокировкой → ответ. Блокировка защищает обращения, пока удерживается. Возвращайте из хранилища копии, чтобы JSON-кодирование не читало общие данные после снятия блокировки.

К концу урока вы:

- соберёте `cmd/api` поверх каталога из модуля 3;
- будете сопоставлять ошибки хранилища со статусами HTTP в одном месте;
- проверите маршруты через настоящий mux и найдёте гонку, которую пропускают обычные тесты;
- добавите `DELETE /products/{id}` со своим тестом.

| Слово | Простой смысл | Английский термин |
|---|---|---|
| соединение частей API | серверу, mux и обработчикам передают один каталог | API wiring |
| сопоставление ошибок хранилища | одна функция выбирает статус HTTP для ошибки хранилища | store error mapping |
| копия значения | обработчик получает собственный `Product`, а не указатель внутрь каталога | value copy |

**CRUD** — создание, чтение, изменение и удаление. Здесь заказ изменяет остаток; удаление станет вашим заданием. Два вспомогательных статуса: **500 Internal Server Error** — непредвиденная ошибка сервера, **204 No Content** — успех без тела ответа.

## Один каталог, один путь запроса

Код — CLI из модуля 3 и новая точка входа по HTTP:

| Файл | Задача |
|---|---|
| `cmd/bozor/` | существующий CLI |
| `cmd/api/main.go` | загрузить каталог и запустить сервер |
| `cmd/api/handlers.go` | `api`, маршруты, обработчики, чтение ID и сопоставление ошибок |
| `cmd/api/json.go` | JSON-функции из GB-4.06 |
| `cmd/api/api_test.go` | тесты маршрутов, остатка, сервера и параллельных обращений |
| `internal/store/store.go` | товары и правила остатков, теперь под мьютексом |
| `internal/store/file.go` | `Load` и атомарный `Save` из GB-3.06 |
| `internal/store/restock_test.go` | тесты прежнего задания на пополнение остатка |
| `cmd/api/tekshiruv_test.go`, `internal/store/tekshiruv_test.go` | проверки нового задания |

| Этап | Вход → действие → результат |
|---|---|
| `http.Server` | соединение → прочитать заголовки запроса за 5 секунд → mux |
| `ServeMux` | метод и путь → выбрать паттерн → обработчик |
| обработчик | путь или тело → прочитать и проверить → вызов хранилища |
| хранилище | захватить `mu` → прочитать или изменить каталог → скопировать результат → освободить `mu` |
| ответ | успех → `writeJSON`; ошибка хранилища → `writeStoreError` |

Сначала фрагмент соединения частей из `handlers.go`:

```go
type api struct {
	st *store.Store
}

func newMux(st *store.Store) *http.ServeMux {
	a := &api{st: st}
	mux := http.NewServeMux()
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /products", a.listProducts)
	mux.HandleFunc("GET /products/{id}", a.getProduct)
	mux.HandleFunc("POST /products", a.createProduct)
	mux.HandleFunc("POST /orders", a.createOrder)
	// VAZIFA (TASK.md, 2-qadam): DELETE /products/{id} → a.deleteProduct
	return mux
}
```

| Код | Что делает |
|---|---|
| `type api struct`, `st *store.Store` | зависимости обработчиков; `st` указывает на единственный каталог |
| `newMux(st *store.Store) *http.ServeMux` | принимает этот каталог и возвращает mux |
| `a := &api{st: st}` | создаёт `api`; полю `st` присваивается аргумент `st` |
| `http.NewServeMux()` | создаёт отдельную таблицу маршрутов |
| пять вызовов `HandleFunc` | регистрируют проверку состояния, список, один товар, создание товара и заказ |
| `a.listProducts` | **значение метода** (method value): функция, связанная с `a`; скобок нет, регистрация её не вызывает |
| комментарий задания, `return mux` | отмечает отсутствующий маршрут удаления, затем возвращает настроенный mux |

Глобального каталога нет. Каждый тест передаёт в `newMux` своё хранилище, поэтому заказ в одном тесте не меняет начальный остаток другого. `healthHandler` каталог не нужен: он возвращает обычный текст `ok`.

Полный `main.go`:

```go filename="cmd/api/main.go" showLineNumbers
// api — bozor katalog API'si (GB-4.08, 4-modul nazorat nuqtasi): GB-3.06'dagi internal/store
// katalogi HTTP orqali. Katalog ishga tushishda bozor.json'dan oʻqiladi (CLI yozgan fayl) va keyin
// xotirada turadi: API'dagi oʻzgarishlar faylga yozilmaydi, server toʻxtasa yoʻqoladi.
// Saqlash Postgres'ga 5-modulda koʻchadi (GB-5.01: nega baza kerak).
//
//	go run ./cmd/api        → bozor API: http://localhost:8765
package main

import (
	"fmt"
	"net/http"
	"os"
	"time"

	"github.com/abdurahmon27/bozor/internal/store"
)

const dataFile = "bozor.json"

// newServer — bozor API serveri (GB-4.04): route'lar newMux'da (GB-4.05), sarlavhalar uchun vaqt chegarasi.
func newServer(addr string, st *store.Store) *http.Server {
	return &http.Server{
		Addr:              addr,
		Handler:           newMux(st),
		ReadHeaderTimeout: 5 * time.Second, // soʻrov sarlavhalari 5 s'da kelmasa, ulanish yopiladi
	}
}

func main() {
	st, err := store.Load(dataFile)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	srv := newServer(":8765", st)
	fmt.Println("bozor API: http://localhost:8765")
	err = srv.ListenAndServe()
	fmt.Fprintln(os.Stderr, "xato:", err)
	os.Exit(1)
}
```

| Строки | Что делают |
|---|---|
| 1–6 | комментарии описывают API в памяти и команду запуска |
| 7–16 | `package main`; импорты пакетов вывода, HTTP, процесса, времени и `internal/store` |
| 18 | `dataFile` задаёт относительное имя файла `bozor.json` |
| 20–27 | `newServer`: адрес из аргумента, `Handler: newMux(st)`, предел чтения заголовков `5 * time.Second` |
| 29–34 | `main` вызывает `store.Load`; ошибка загрузки выводится в `os.Stderr`, код выхода 1 |
| 35–36 | создать сервер на `:8765` и вывести его адрес |
| 37–40 | `ListenAndServe` ждёт запросы; при возврате вывести его ненулевую ошибку; программа завершается |

`bozor.json` читается только при старте. Изменения API остаются в памяти и исчезают при остановке процесса. `Save` на каждый запрос не вызывается. Постоянное хранение появится в модуле 5.

Предскажите: заказ запрашивает 5 штук товара 4. Валидация количества разрешает 1–100, но остаток равен 2. Какой статус?

**A)** 422 · **B)** 409 · **C)** 201

<details>
<summary>Ответ</summary>

**B: 409 Conflict.** Пять — допустимое количество, но запрос противоречит текущему остатку. **A** относится к недопустимому количеству, например нулю; **C** означал бы успех без достаточного остатка. Это выбранный контракт статусов нашего API.

</details>

```console
$ curl -s -i localhost:8765/orders -d '{"product_id":4,"quantity":5}'
HTTP/1.1 409 Conflict
Content-Type: application/json
…

{"error":{"code":"insufficient_stock","message":"oʻrik: qoldiq 2, soʻralgan 5"}}
```

`insufficient_stock` — стабильный код ошибки; узбекское сообщение означает «абрикос: остаток 2, запрошено 5». Опции `-H Content-Type` нет: этот сервер не проверяет тип содержимого запроса и читает тело как JSON. Демонстрационный сервер из GB-4.01 проверял его; там был другой контракт.

## Один путь обработчика, одно место для ошибок хранилища

`getProduct` и его функция чтения ID, фрагменты без изменений из `handlers.go`:

```go
func (a *api) getProduct(w http.ResponseWriter, r *http.Request) {
	id, ok := pathID(w, r)
	if !ok {
		return
	}
	p, err := a.st.Get(id)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	writeJSON(w, http.StatusOK, p)
}

func pathID(w http.ResponseWriter, r *http.Request) (int64, bool) {
	id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)
	if err != nil {
		writeError(w, http.StatusBadRequest, apiError{Code: "bad_id", Message: "id butun son boʻlishi kerak"})
		return 0, false
	}
	return id, true
}
```

| Строки внутри каждой функции | Значение |
|---|---|
| `getProduct` 1–5 | `a *api` — receiver; `w` пишет ответ, `r` — запрос; при ошибке `pathID` сам пишет ответ и возвращает `false` |
| `getProduct` 6–10 | вызвать `a.st.Get(id)` этого API; при ошибке сопоставить её со статусом и выйти через `return` |
| `getProduct` 11–12 | закодировать товар со статусом 200 |
| `pathID` 1–2 | прочитать wildcard через `r.PathValue("id")`; `ParseInt` разбирает десятичное число в 64 бита |
| `pathID` 3–8 | при ошибке разбора написать `400 bad_id`, вернуть `0, false`; иначе вернуть ID и `true` |

Оба POST-обработчика идут тем же путём. Здесь их полные тела функций; типы входных данных и функции валидации уже есть в этом файле:

```go
func (a *api) createProduct(w http.ResponseWriter, r *http.Request) {
	var in productInput
	if !decodeJSON(w, r, &in) {
		return
	}
	if f := validate(in); len(f) > 0 {
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: "qiymatlar notoʻgʻri", Fields: f})
		return
	}
	p, err := a.st.Add(in.Name, in.Price, in.Stock)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	w.Header().Set("Location", fmt.Sprintf("/products/%d", p.ID)) // yangi resursning manzili (RFC 9110 §15.3.2)
	writeJSON(w, http.StatusCreated, p)
}

func (a *api) createOrder(w http.ResponseWriter, r *http.Request) {
	var in orderInput
	if !decodeJSON(w, r, &in) {
		return
	}
	if f := validateOrder(in); len(f) > 0 {
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: "qiymatlar notoʻgʻri", Fields: f})
		return
	}
	p, err := a.st.Sell(in.ProductID, in.Quantity)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	// Narx ≤ maxPrice (store), dona ≤ 100 (validateOrder): koʻpaytma int64'ga sigʻadi.
	writeJSON(w, http.StatusCreated, orderResponse{ProductID: p.ID, Quantity: in.Quantity, Total: p.Price * int64(in.Quantity)})
}
```

У `productInput` поля `Name string`, `Price int64`, `Stock int`; у `orderInput` — `ProductID int64`, `Quantity int`. Их JSON-теги соответствуют ключам запроса. `orderResponse` содержит `ProductID`, `Quantity`, `Total`: имя `Order` оставлено для будущего доменного типа.

| Код | Что делает |
|---|---|
| `var in …`, `decodeJSON(w, r, &in)` | создать входное значение и прочитать данные по его адресу; при ошибке функция сама пишет ответ, поэтому выйти |
| `validate` / `validateOrder`, `len(f) > 0` | собрать ошибки полей; непустая map → 422 с `fields` |
| `a.st.Add` / `a.st.Sell` | изменить общий каталог под его блокировкой; ошибка хранилища → `writeStoreError`, затем `return` |
| `w.Header().Set("Location", fmt.Sprintf(…))` | задать адрес нового товара до отправки статуса |
| `writeJSON(…, http.StatusCreated, …)` | 201 и созданный товар либо результат заказа |
| `p.Price * int64(in.Quantity)` | привести количество к `int64` и умножить тийины, а не сумы |

Функции в [`json.go`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-4-08-katalog-api/cmd/api/json.go) — код из GB-4.06: тело не более 1024 байт, неизвестные поля запрещены, JSON-значение должно быть одно. Ошибки чтения дают 400, превышение размера 413, неверные значения 422. `writeJSON` задаёт `Content-Type`, пишет статус, затем кодирует тело. `writeError` помещает `apiError{Code, Message, Fields}` внутрь `error`; отсутствующее `fields` опускается.

Новое **сопоставление ошибок хранилища** со статусами находится в одной функции:

```go
func writeStoreError(w http.ResponseWriter, err error) {
	var se *store.StockError
	switch {
	case errors.Is(err, store.ErrNotFound):
		writeError(w, http.StatusNotFound, apiError{Code: "not_found", Message: err.Error()})
	case errors.As(err, &se):
		writeError(w, http.StatusConflict, apiError{Code: "insufficient_stock", Message: err.Error()})
	case errors.Is(err, store.ErrBadQuantity), errors.Is(err, store.ErrBadProduct):
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: err.Error()})
	default:
		log.Printf("ichki xato: %v", err) // tafsilot server logiga (slog: GB-8.02), mijozga emas
		writeError(w, http.StatusInternalServerError, apiError{Code: "internal", Message: "ichki xato"})
	}
}
```

| Ветка | Статус и код | Причина |
|---|---|---|
| `errors.Is(err, store.ErrNotFound)` | 404 `not_found` | товара с этим ID нет; работает и для обёрнутой ошибки |
| `errors.As(err, &se)` | 409 `insufficient_stock` | найти `*StockError` через обёртки; `se` — целевой указатель |
| любая из двух ошибок в `case` через запятую | 422 `validation_failed` | количество или товар нарушает правило хранилища |
| `default` | 500 `internal` | непредвиденный сбой; клиенту только `ichki xato` («внутренняя ошибка») |

У `switch` нет выражения: каждый `case` содержит условие. Два условия через запятую означают, что достаточно любого из них. `log.Printf("ichki xato: %v", err)` пишет настоящую ошибку в журнал сервера; `%v` форматирует её значение. Внутренний путь файла в ответ не попадает. Структурированные журналы с `slog` будут в [GB-8.02](/lab/youtube/gb#gb-8-02).

## Копировать под блокировкой, вызывать yield после её снятия

Хранилище возвращается к упорядоченному `[]Product` из GB-3.06. `map` из GB-4.07 был небольшой лабораторией параллельных обращений. В хранилище добавляется `mu sync.Mutex`; `Add`, `Sell`, `Restock` и `Get` начинаются с `Lock` и `defer Unlock`. Все receiver остаются `*Store`, поэтому мьютекс не копируется.

`All` устраняет deadlock из первого вопроса:

```go
func (s *Store) All() iter.Seq[Product] {
	return func(yield func(Product) bool) {
		s.mu.Lock()
		products := slices.Clone(s.products)
		s.mu.Unlock()
		for _, p := range products {
			if !yield(p) {
				return
			}
		}
	}
}
```

| Строка | Что делает |
|---|---|
| 1–2 | вернуть `iter.Seq[Product]`: функция итератора принимает `yield` |
| 3–5 | захватить блокировку, скопировать слайс товаров в локальный `products`, сразу освободить блокировку |
| 6 | обойти эту копию |
| 7–10 | передать каждый скопированный товар в `yield`; при `false` остановиться, в том числе после `break` вызывающей стороны |
| 11–12 | завершить функцию итератора и метод |

| Момент | Общий каталог | Итератор | Блокировка |
|---|---|---|---|
| копирование | читается `slices.Clone` | создаёт собственный слайс | удерживается |
| `yield(p)` | другой запрос может его изменить | читает только свою копию | снята |
| тело цикла вызывает `Sell` | остаток безопасно меняется | прежняя копия остаётся такой же | `Sell` может её захватить |

`defer Unlock` здесь держал бы блокировку до завершения итератора, включая все вызовы `yield`. Явный `Unlock` поставлен намеренно. Теперь `All` даёт копию на момент начала обхода вместо прежнего живого представления.

Обработчик списка собирает этот итератор:

```go
func (a *api) listProducts(w http.ResponseWriter, r *http.Request) {
	products := slices.Collect(a.st.All())
	if products == nil {
		products = []store.Product{} // boʻsh katalog JSON'da null emas, [] boʻlsin (GB-3.06)
	}
	writeJSON(w, http.StatusOK, products)
}
```

`slices.Collect` собирает значения в слайс. Пустой итератор даёт `nil`, который закодировался бы как `null`; строки 3–5 заменяют его на `[]store.Product{}`, пустой ненулевой слайс, поэтому ответ — `[]`. Последний вызов отправляет 200 и этот слайс.

## Проверяйте маршруты через настоящий mux

`send` использует настоящую таблицу маршрутов, не открывая порт:

```go
func send(h http.Handler, method, path, body string) *httptest.ResponseRecorder {
	req := httptest.NewRequest(method, path, strings.NewReader(body))
	rec := httptest.NewRecorder()
	h.ServeHTTP(rec, req)
	return rec
}
```

Строка 2 создаёт запрос; `strings.NewReader(body)` задаёт его тело. Строка 3 создаёт recorder. Строка 4 вызывает `ServeHTTP` обработчика; строка 5 возвращает записанные статус и тело. В отличие от функции из GB-4.06, теперь она возвращает recorder, а не печатает его.

## Даже Get с блокировкой может выпустить указатель

Прежний вариант в `_video/01-pointer/internal/store/store.go` возвращал указатель, найденный внутри слайса:

```go
func (s *Store) Get(id int64) (*Product, error) {
	s.mu.Lock()
	defer s.mu.Unlock()
	p := s.find(id)
	if p == nil {
		return nil, fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
	}
	return p, nil
}
```

Строка 1 возвращает `*Product`. Строки 2–3 захватывают блокировку и откладывают её снятие. Строка 4 находит `&s.products[i]`; строки 5–7 возвращают обёрнутую ошибку для отсутствующего товара. Строка 8 возвращает тот же указатель. Отложенный `Unlock` срабатывает при возврате из `Get`.

Обычные тесты на этом варианте тоже проходят:


Параллельный тест использует один mux и одно хранилище для всех запросов:

```go
func TestParallel(t *testing.T) {
	st := testStore(t)
	h := newMux(st)
	var wg sync.WaitGroup
	for range 30 {
		wg.Go(func() { send(h, "POST", "/orders", `{"product_id":1,"quantity":1}`) })
		wg.Go(func() { send(h, "GET", "/products/1", "") })
	}
	wg.Wait()
	if p, _ := st.Get(1); p.Stock != 10 {
		t.Errorf("30 ta buyurtmadan keyin olma qoldigʻi %d, kutilgan 10", p.Stock)
	}
}
```

В `st` изначально 40 яблок. `h` — его mux. `wg.Go` запускает функцию в горутине; `wg.Wait` ждёт их завершения. Каждая из 30 итераций запускает один заказ и одно чтение, поэтому ожидаемый остаток — `40 − 30 = 10`. Финальный `if` проверяет его, игнорируя ошибку через `_`, поскольку товар заведомо существует. Полное объяснение `sync.WaitGroup` будет в [GB-7.01](/lab/youtube/gb#gb-7-01).

Шестнадцатеричный адрес должен совпадать у обоих обращений. Адреса, номера горутин и смещения внутри функций (`+0x…`) меняются от запуска к запуску. В видео сначала шёл `Read at`, затем `Previous write`; у меня порядок обратный. Ошибка та же.

| Шаг | Запрос A: GET | Запрос B: заказ | Память |
|---|---|---|---|
| 1 | `Get` возвращает указатель `p`, затем снимает блокировку | | `p` указывает внутрь каталога, остаток 40 |
| 2 | JSON читает через `p` без блокировки | `Sell` пишет остаток 39 под блокировкой | оба обращаются к одной ячейке |
| 3 | race detector находит чтение/запись | изменения остатка по-прежнему последовательны | нет синхронизации, упорядочивающей JSON-чтение и запись |

Для отчёта обращениям необязательно физически совпасть по времени. Детектор проверяет синхронизацию между обращениями, выполненными в этом запуске. Он не найдёт гонку в ветке, которую тесты вообще не выполнили.

Исправьте `Get`: скопируйте значение, **пока блокировка ещё удерживается**:

```go
func (s *Store) Get(id int64) (Product, error) {
	s.mu.Lock()
	defer s.mu.Unlock()
	p := s.find(id)
	if p == nil {
		return Product{}, fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
	}
	return *p, nil
}
```

Теперь возвращаемый тип — `Product`. При ошибке возвращается `Product{}`, нулевое значение, вместе с ошибкой. При успехе `*p` читает значение по указателю и копирует его в результат **до** выполнения отложенного `Unlock`.

| После возврата из `Get` | Каталог | `p` обработчика |
|---|---|---|
| сначала | остаток яблок 40 | независимая копия, остаток 40 |
| другой заказ | остаток 39 | всё ещё 40 |
| JSON-кодирование | читать каталог не нужно | читает свою копию |

Такой копии достаточно: `Product` содержит целые числа и строку. Если позже появится изменяемая map или слайс, одна копия структуры всё ещё будет разделять их внутренние данные.

Предскажите исправленный вариант: **A)** три строки `ok` · **B)** та же гонка · **C)** deadlock.

<details>
<summary>Ответ</summary>

**A.** `Get` копирует под блокировкой; `All` тоже копирует под блокировкой, но вызывает `yield` после её снятия. Для **B** нужно ещё одно несинхронизированное обращение к общим данным; для **C** — ожидание уже захваченной в этой цепочке вызовов блокировки.

</details>

## Глубже (необязательно): правила остаются в хранилище

Обработчик валидирует входные данные ради понятных сообщений по полям. Хранилище проверяет снова, потому что им пользуются также CLI и загружаемый файл. `maxPrice` — 1 000 000 000 тийинов, или 10 миллионов сумов; `maxStock` — 1 000 000 штук. `Restock` проверяет и итоговый остаток. Цена из API не должна обходить прежний верхний предел CLI. При количестве в заказе не более 100 сумма не превышает `10¹¹` тийинов и помещается в `int64`.

`Save` также копирует слайс под блокировкой, затем пишет файл без неё. Этот API не вызывает его на каждый запрос; параллельные процессы и постоянное хранение — тема следующего модуля. `ReadHeaderTimeout` ограничивает только чтение заголовков, а не весь запрос. Другие ограничения времени и остановка сервера будут в [GB-8.03](/lab/youtube/gb#gb-8-03).

`Add` по-прежнему выбирает наибольший текущий ID плюс один. Поэтому после удаления наибольшего ID он может использоваться снова. Ограничение этого учебного хранилища описано в README; не считайте его ID постоянными идентификаторами ресурсов.

## Частые ошибки

**1. «В Get есть Lock, значит результат защищён».** Неверный `Get` и настоящий отчёт race приведены выше. Указатель остаётся связан с общими данными после снятия блокировки. Возвращайте копию `Product`, полученную под блокировкой; запускайте тесты маршрутов и параллельных обращений с `-race`.

**2. Режим race не запускается.** На этой машине с `CGO_ENABLED=0`:

```console
$ go test -race ./cmd/api
go: -race requires cgo; enable cgo by setting CGO_ENABLED=1
```

Сообщение говорит, что режиму race нужна интеграция с C. В Linux включите cgo **и** обеспечьте C-компилятор, например `gcc`; одно `CGO_ENABLED=1` его не установит. Я повторил все команды race через приложенный Docker-скрипт. На машине с нужным компилятором запускайте `go test -race ./...` напрямую. Docker разбирается в GB-5.02.

**3. Удерживать блокировку во время `yield` или вызывать `Get` внутри заблокированного `Delete`.** В обоих случаях можно дважды ждать один мьютекс. Используйте копирование из `All`; внутри `Delete` ищите непосредственно в `s.products`, захватив блокировку один раз.

**4. Использовать `writeJSON(w, 204, nil)`.** Он пытается закодировать `null`. Настоящий сервер отклоняет тело для 204; recorder может его записать и провалить проверку пустого тела. Нужен только `w.WriteHeader(http.StatusNoContent)`.

**5. Запускать вне корня урока.** `bozor.json` — относительный путь. Для `Load` отсутствие файла означает пустой каталог, а не ошибку старта. Запускайте из папки с этим файлом. Если порт 8765 занят, остановите свой прежний сервер перед запуском нового.

## Проверьте себя

**1.** Почему `Get` должен возвращать копию?

<details>
<summary>Ответ</summary>

Указатель внутрь хранилища живёт дольше блокировки. После её снятия JSON читает через него, пока `Sell` может изменить то же значение. Копирование под блокировкой отделяет чтение обработчика от общего каталога.

</details>

**2.** Где ошибка хранилища становится статусом? Что происходит с непредвиденной ошибкой?

<details>
<summary>Ответ</summary>

В `writeStoreError`: 404, 409, 422, иначе 500. Подробности непредвиденной ошибки идут в журнал; клиент получает `internal` и общее сообщение, а не внутренний текст.

</details>

**3.** Из [GB-4.05](/lab/youtube/gb/gb-4-05/ru): вызовите обработчик напрямую с новым запросом без mux. Что вернёт `r.PathValue("id")`?

<details>
<summary>Ответ</summary>

Пустую строку: mux не заполнил wildcard. Поэтому тесты отправляют запрос через `newMux(st)`, проверяя также выбор маршрута.

</details>

**4.** Предскажите: `All` копирует под `mu`, снимает блокировку, затем тело цикла вызывает `Sell`. **A)** deadlock · **B)** может завершиться · **C)** `Sell` изменит копию итератора.

<details>
<summary>Ответ</summary>

**B.** `Sell` может захватить освобождённую блокировку и изменить каталог. **A** описывает прежний вариант с `yield` под блокировкой; **C** смешивает скопированный слайс с общим каталогом.

</details>

Образец — [`solution/`](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/gb-4-08-katalog-api/solution). Два изменённых метода:

```go
func (s *Store) Delete(id int64) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	i := slices.IndexFunc(s.products, func(p Product) bool { return p.ID == id })
	if i < 0 {
		return fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
	}
	s.products = slices.Delete(s.products, i, i+1)
	return nil
}

func (a *api) deleteProduct(w http.ResponseWriter, r *http.Request) {
	id, ok := pathID(w, r)
	if !ok {
		return
	}
	if err := a.st.Delete(id); err != nil {
		writeStoreError(w, err)
		return
	}
	w.WriteHeader(http.StatusNoContent)
}
```

`Delete` захватывает мьютекс один раз. `IndexFunc` ищет по ID; отрицательный индекс возвращает обёрнутую ошибку. `slices.Delete` удаляет один элемент, возвращённый слайс заменяет `s.products`. `defer` снимает блокировку при обоих возвратах. `deleteProduct` один раз разбирает ID, один раз удаляет, затем пишет либо сопоставленную ошибку, либо 204 без тела.

Дополнительная строка маршрута внутри `newMux`:

```go
mux.HandleFunc("DELETE /products/{id}", a.deleteProduct)
```

Образец теста:

```go
func TestDeleteProduct(t *testing.T) {
	tests := []struct {
		name   string
		path   string
		status int
	}{
		{"bor", "/products/3", 204},
		{"yoq", "/products/99", 404},
		{"xato_id", "/products/abc", 400},
	}
	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			h := newMux(testStore(t))
			if rec := send(h, "DELETE", tc.path, ""); rec.Code != tc.status {
				t.Errorf("DELETE %s: status %d, kutilgan %d: %s", tc.path, rec.Code, tc.status, rec.Body)
			}
		})
	}
	// oʻchirilgan mahsulot GET'da ham yoʻq
	h := newMux(testStore(t))
	send(h, "DELETE", "/products/3", "")
	if rec := send(h, "GET", "/products/3", ""); rec.Code != 404 {
		t.Errorf("DELETE'dan keyin GET /products/3: status %d, kutilgan 404", rec.Code)
	}
}
```

Три строки получают свежие хранилища. Финальная последовательность использует один mux для DELETE и следующего GET, доказывая фактическое удаление товара. `bor`, `yoq`, `xato_id` означают «существует», «отсутствует», «неверный ID».
