## What you will learn

Hundreds of requests can reach the bozor catalog together. How do the server, routes, JSON helpers and store share one catalog safely? Where should each error become an HTTP response?

**The one idea:** a request follows one path: server → mux → handler → locked store → response. The lock protects access while it is held. Return copies from the store so JSON encoding does not read shared data after the lock is released.

By the end you will:

- assemble `cmd/api` on top of the catalog from Module 3;
- map store errors to HTTP statuses in one place;
- test routes through the real mux and find a race that ordinary tests miss;
- add `DELETE /products/{id}` with your own test.

| Word | Plain meaning | English term |
|---|---|---|
| API wiring | one catalog passed to server, mux and handlers | API wiring |
| store error mapping | one function chooses the HTTP status for a store error | store error mapping |
| value copy | the handler receives its own `Product`, not a pointer into the catalog | value copy |

**CRUD** means create, read, update and delete. Here orders update stock; the delete operation is your task. Two helper statuses: **500 Internal Server Error** for an unexpected server failure, and **204 No Content** for success with no response body.

| Stage | Input → action → result |
|---|---|
| `http.Server` | connection → read request headers within 5 seconds → mux |
| `ServeMux` | method and path → choose a pattern → handler |
| handler | path or body → parse and validate → store call |
| store | take `mu` → read or change catalog → copy result → release `mu` |
| response | success → `writeJSON`; store error → `writeStoreError` |

First the wiring fragment from `handlers.go`:

```go
type api struct {
	st *store.Store
}

func newMux(st *store.Store) *http.ServeMux {
	a := &api{st: st}
	mux := http.NewServeMux()
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /products", a.listProducts)
	mux.HandleFunc("GET /products/{id}", a.getProduct)
	mux.HandleFunc("POST /products", a.createProduct)
	mux.HandleFunc("POST /orders", a.createOrder)
	// VAZIFA (TASK.md, 2-qadam): DELETE /products/{id} → a.deleteProduct
	return mux
}
```

| Code | What it does |
|---|---|
| `type api struct`, `st *store.Store` | names the handler dependencies; `st` points to the single catalog |
| `newMux(st *store.Store) *http.ServeMux` | receives that catalog as a parameter and returns a mux |
| `a := &api{st: st}` | creates `api`; the field `st` gets the argument `st` |
| `http.NewServeMux()` | creates an independent route table |
| five `HandleFunc` calls | register health, list, single product, create product and create order |
| `a.listProducts` | a **method value**: a function bound to `a`; no parentheses, so registration does not call it |
| task comment, `return mux` | marks the missing delete route, then returns the configured mux |

There is no global catalog. Each test can pass its own store to `newMux`, so one test's order does not change another test's starting stock. `healthHandler` needs no catalog and returns plain text `ok`.

The complete `main.go`:

```go filename="cmd/api/main.go" showLineNumbers

// katalogi HTTP orqali. Katalog ishga tushishda bozor.json'dan oʻqiladi (CLI yozgan fayl) va keyin
// xotirada turadi: API'dagi oʻzgarishlar faylga yozilmaydi, server toʻxtasa yoʻqoladi.
// Saqlash Postgres'ga 5-modulda koʻchadi (GB-5.01: nega baza kerak).
//
//	go run ./cmd/api        → bozor API: http://localhost:8765
package main

import (
	"fmt"
	"net/http"
	"os"
	"time"

	"github.com/abdurahmon27/bozor/internal/store"
)

const dataFile = "bozor.json"

// newServer — bozor API serveri (GB-4.04): route'lar newMux'da (GB-4.05), sarlavhalar uchun vaqt chegarasi.
func newServer(addr string, st *store.Store) *http.Server {
	return &http.Server{
		Addr:              addr,
		Handler:           newMux(st),
		ReadHeaderTimeout: 5 * time.Second, // soʻrov sarlavhalari 5 s'da kelmasa, ulanish yopiladi
	}
}

func main() {
	st, err := store.Load(dataFile)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	srv := newServer(":8765", st)
	fmt.Println("bozor API: http://localhost:8765")
	err = srv.ListenAndServe()
	fmt.Fprintln(os.Stderr, "xato:", err)
	os.Exit(1)
}
```

| Lines | What they do |
|---|---|
| 1–6 | comments describe the in-memory API and its run command |
| 7–16 | `package main`; import output, HTTP, process and time packages plus `internal/store` |
| 18 | `dataFile` names the relative file `bozor.json` |
| 20–27 | `newServer`: address from its argument, `Handler: newMux(st)`, header read limit `5 * time.Second` |
| 29–34 | `main` calls `store.Load`; loading errors go to `os.Stderr`, then exit code 1 |
| 35–36 | construct the server on `:8765` and print its address |
| 37–40 | `ListenAndServe` waits for requests; when it returns, print its non-nil error; the program exits |

Only startup reads `bozor.json`. API changes stay in memory and disappear when the process stops. It does not call `Save` per request. Persistent storage follows in Module 5.

## One handler path, one place for store errors

`getProduct` and its ID helper, verbatim fragments from `handlers.go`:

```go
func (a *api) getProduct(w http.ResponseWriter, r *http.Request) {
	id, ok := pathID(w, r)
	if !ok {
		return
	}
	p, err := a.st.Get(id)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	writeJSON(w, http.StatusOK, p)
}

func pathID(w http.ResponseWriter, r *http.Request) (int64, bool) {
	id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)
	if err != nil {
		writeError(w, http.StatusBadRequest, apiError{Code: "bad_id", Message: "id butun son boʻlishi kerak"})
		return 0, false
	}
	return id, true
}
```

| Lines in each function | Meaning |
|---|---|
| `getProduct` 1–5 | `a *api` is the receiver; `w` writes the response, `r` is the request; `pathID` writes an error itself and returns `false` on failure |
| `getProduct` 6–10 | call this API's `a.st.Get(id)`; on error, map it once and stop with `return` |
| `getProduct` 11–12 | encode the product with status 200 |
| `pathID` 1–2 | read the wildcard using `r.PathValue("id")`; `ParseInt` parses base 10 into 64 bits |
| `pathID` 3–8 | on parse failure write `400 bad_id`, return `0, false`; otherwise return the ID and `true` |

The two POST handlers use the same path. These are their complete function bodies, using the input types and validation functions already present in this file:

```go
func (a *api) createProduct(w http.ResponseWriter, r *http.Request) {
	var in productInput
	if !decodeJSON(w, r, &in) {
		return
	}
	if f := validate(in); len(f) > 0 {
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: "qiymatlar notoʻgʻri", Fields: f})
		return
	}
	p, err := a.st.Add(in.Name, in.Price, in.Stock)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	w.Header().Set("Location", fmt.Sprintf("/products/%d", p.ID)) // yangi resursning manzili (RFC 9110 §15.3.2)
	writeJSON(w, http.StatusCreated, p)
}

func (a *api) createOrder(w http.ResponseWriter, r *http.Request) {
	var in orderInput
	if !decodeJSON(w, r, &in) {
		return
	}
	if f := validateOrder(in); len(f) > 0 {
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: "qiymatlar notoʻgʻri", Fields: f})
		return
	}
	p, err := a.st.Sell(in.ProductID, in.Quantity)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	// Narx ≤ maxPrice (store), dona ≤ 100 (validateOrder): koʻpaytma int64'ga sigʻadi.
	writeJSON(w, http.StatusCreated, orderResponse{ProductID: p.ID, Quantity: in.Quantity, Total: p.Price * int64(in.Quantity)})
}
```

`productInput` has `Name string`, `Price int64`, `Stock int`; `orderInput` has `ProductID int64`, `Quantity int`. Their JSON tags match the request keys. `orderResponse` contains `ProductID`, `Quantity`, `Total`: the name `Order` is reserved for the domain type later.

| Code | What it does |
|---|---|
| `var in …`, `decodeJSON(w, r, &in)` | allocate input and decode through its address; on failure the helper writes the response, so return |
| `validate` / `validateOrder`, `len(f) > 0` | collect field errors; nonempty map → 422 with `fields` |
| `a.st.Add` / `a.st.Sell` | change the shared catalog under its lock; store errors → `writeStoreError`, then return |
| `w.Header().Set("Location", fmt.Sprintf(…))` | set the new product's address before the status is sent |
| `writeJSON(…, http.StatusCreated, …)` | 201 and the created product or order result |
| `p.Price * int64(in.Quantity)` | convert quantity to `int64` and multiply tiyin, not soʻm |

The helpers in [`json.go`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-4-08-katalog-api/cmd/api/json.go) are the GB-4.06 code: maximum body 1024 bytes, unknown fields rejected, exactly one JSON value. Decode errors become 400, excess size 413, invalid values 422. `writeJSON` sets `Content-Type`, writes the status, then encodes the body. `writeError` wraps `apiError{Code, Message, Fields}` inside `error`; absent `fields` is omitted.

The new **store error mapping** lives in one function:

```go
func writeStoreError(w http.ResponseWriter, err error) {
	var se *store.StockError
	switch {
	case errors.Is(err, store.ErrNotFound):
		writeError(w, http.StatusNotFound, apiError{Code: "not_found", Message: err.Error()})
	case errors.As(err, &se):
		writeError(w, http.StatusConflict, apiError{Code: "insufficient_stock", Message: err.Error()})
	case errors.Is(err, store.ErrBadQuantity), errors.Is(err, store.ErrBadProduct):
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: err.Error()})
	default:
		log.Printf("ichki xato: %v", err) // tafsilot server logiga (slog: GB-8.02), mijozga emas
		writeError(w, http.StatusInternalServerError, apiError{Code: "internal", Message: "ichki xato"})
	}
}
```

| Branch | Status and code | Why |
|---|---|---|
| `errors.Is(err, store.ErrNotFound)` | 404 `not_found` | no product with that ID, including a wrapped error |
| `errors.As(err, &se)` | 409 `insufficient_stock` | find `*StockError` through wrapping; `se` is the target pointer |
| either error in the comma-separated `case` | 422 `validation_failed` | quantity or product violates a store rule |
| `default` | 500 `internal` | unexpected failure; the client gets only `ichki xato` ("internal error") |

`switch` has no expression: each `case` is a condition. The two conditions separated by a comma mean either one may match. `log.Printf("ichki xato: %v", err)` writes the actual error to the server log; `%v` formats its value. It does not expose an internal file path in the response. Structured logging with `slog` follows in [GB-8.02](/lab/youtube/gb#gb-8-02).

## Copy under the lock; call yield after unlocking

The store returns to the ordered `[]Product` from GB-3.06. GB-4.07's `map` was a smaller concurrency lab. The store adds `mu sync.Mutex`; `Add`, `Sell`, `Restock` and `Get` begin with `Lock` and `defer Unlock`. All receivers remain `*Store`, so the mutex is not copied.

`All` solves the opening deadlock:

```go
func (s *Store) All() iter.Seq[Product] {
	return func(yield func(Product) bool) {
		s.mu.Lock()
		products := slices.Clone(s.products)
		s.mu.Unlock()
		for _, p := range products {
			if !yield(p) {
				return
			}
		}
	}
}
```

| Line | What it does |
|---|---|
| 1–2 | return an `iter.Seq[Product]`: the iterator function receives `yield` |
| 3–5 | lock, clone the product slice into local `products`, unlock immediately |
| 6 | loop over that copy |
| 7–10 | give each copied product to `yield`; stop if it returns `false`, including a caller's `break` |
| 11–12 | end the iterator function and method |

| Moment | Shared catalog | Iterator | Lock |
|---|---|---|---|
| copy | read by `slices.Clone` | builds its own slice | held |
| `yield(p)` | another request may change it | reads only its copy | released |
| loop body calls `Sell` | stock changes safely | its earlier copy stays the same | `Sell` can take it |

`defer Unlock` here would keep the lock until the iterator finishes, including every `yield` call. The explicit `Unlock` is deliberate. This `All` now gives a copy captured when iteration starts, rather than the earlier live view.

The list handler collects that iterator:

```go
func (a *api) listProducts(w http.ResponseWriter, r *http.Request) {
	products := slices.Collect(a.st.All())
	if products == nil {
		products = []store.Product{} // boʻsh katalog JSON'da null emas, [] boʻlsin (GB-3.06)
	}
	writeJSON(w, http.StatusOK, products)
}
```

`slices.Collect` gathers the values into a slice. An empty iterator gives `nil`, which would encode as `null`; lines 3–5 replace it with `[]store.Product{}`, an empty non-nil slice, so the response is `[]`. The final call sends 200 and that slice.

## Test routes through the real mux

`send` runs the real routing table without opening a port:

```go
func send(h http.Handler, method, path, body string) *httptest.ResponseRecorder {
	req := httptest.NewRequest(method, path, strings.NewReader(body))
	rec := httptest.NewRecorder()
	h.ServeHTTP(rec, req)
	return rec
}
```

Line 2 makes a request, with `strings.NewReader(body)` supplying its body. Line 3 makes a recorder. Line 4 calls the handler's `ServeHTTP`; line 5 returns the recorded status and body. Unlike the GB-4.06 helper, it returns the recorder instead of printing it.

## A locked Get can still leak a pointer

The earlier version in `_video/01-pointer/internal/store/store.go` returned the pointer found inside the slice:

```go
func (s *Store) Get(id int64) (*Product, error) {
	s.mu.Lock()
	defer s.mu.Unlock()
	p := s.find(id)
	if p == nil {
		return nil, fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
	}
	return p, nil
}
```

Line 1 returns `*Product`. Lines 2–3 lock and arrange unlocking. Line 4 finds `&s.products[i]`; lines 5–7 return a wrapped missing-product error. Line 8 returns that same pointer. The deferred unlock runs as `Get` returns.

Ordinary tests on this version still pass:

The parallel test uses the same mux and store for all requests:

```go
func TestParallel(t *testing.T) {
	st := testStore(t)
	h := newMux(st)
	var wg sync.WaitGroup
	for range 30 {
		wg.Go(func() { send(h, "POST", "/orders", `{"product_id":1,"quantity":1}`) })
		wg.Go(func() { send(h, "GET", "/products/1", "") })
	}
	wg.Wait()
	if p, _ := st.Get(1); p.Stock != 10 {
		t.Errorf("30 ta buyurtmadan keyin olma qoldigʻi %d, kutilgan 10", p.Stock)
	}
}
```

`st` starts with 40 apples. `h` is its mux. `wg.Go` starts a function in a goroutine; `wg.Wait` waits for those functions. Each of 30 iterations starts one order and one read, so the expected stock is `40 − 30 = 10`. The final `if` checks it, ignoring the error with `_` because the product is known to exist. The full `sync.WaitGroup` explanation is in [GB-7.01](/lab/youtube/gb/gb-7-01/en).

With pointer-returning `Get`, predict `go test -race`:

**A)** `ok`, since writes are locked · **B)** `WARNING: DATA RACE` · **C)** failure because stock is not 10

<details>
<summary>Answer</summary>

**B.** Stock updates are locked, so the final quantity can be correct. But after `Get` unlocks, JSON encoding still reads the shared `Product` through its pointer. **A** checks only the writers; **C** assumes a lost update, which the writer's lock prevents here.

</details>

| `Write at … goroutine 29` | `Sell`, line 160, writes stock through the order handler |
| `Previous read at … goroutine 86` | the same address was read by another goroutine |

| `(chiqish kodi: 1)` | the wrapped test command failed |

| Step | Request A: GET | Request B: order | Memory |
|---|---|---|---|
| 1 | `Get` returns pointer `p`, then unlocks | | `p` points into the catalog, stock 40 |
| 2 | JSON reads through `p` without the lock | `Sell` writes stock 39 under the lock | both access the same cell |
| 3 | race detector reports read/write | stock updates remain serialized | no synchronization orders the JSON read and write |

The accesses need not physically overlap for the detector to report them. It checks synchronization between the accesses executed in this run. It cannot find a race on a path the tests never run.

Fix `Get` by copying the value **while the lock is still held**:

```go
func (s *Store) Get(id int64) (Product, error) {
	s.mu.Lock()
	defer s.mu.Unlock()
	p := s.find(id)
	if p == nil {
		return Product{}, fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
	}
	return *p, nil
}
```

The return type is now `Product`. On failure return `Product{}`, the zero value, with the error. On success `*p` reads the pointed-to value and copies it into the return value **before** deferred `Unlock` runs.

| After `Get` returns | Catalog | Handler's `p` |
|---|---|---|
| initially | apple stock 40 | independent copy, stock 40 |
| another order | stock 39 | still 40 |
| JSON encoding | no read of catalog needed | reads its own copy |

This copy is sufficient because `Product` contains integers and a string. If a future product contains a mutable map or slice, a struct copy alone would still share its underlying data.

Predict the fixed version: **A)** three `ok` lines · **B)** the same race · **C)** a deadlock.

<details>
<summary>Answer</summary>

**A.** `Get` copies under the lock; `All` clones under the lock and calls `yield` after unlocking. **B** would need another unsynchronized shared access; **C** would require waiting for a lock already held in this call chain.

</details>

## Going deeper (optional): keep the rules in the store

The handler validates input to return useful field messages. The store validates again because the CLI and loaded file also use it. `maxPrice` is 1,000,000,000 tiyin (10 million soʻm), `maxStock` is 1,000,000 pieces; `Restock` checks the resulting stock too. An API price must not bypass the CLI's old upper bound. With order quantity at most 100, the total is at most `10¹¹` tiyin and fits `int64`.

`Save` also takes its slice copy under the lock, then writes the file without holding it. This API does not use it per request; concurrent processes and persistent storage are the next module's problem. `ReadHeaderTimeout` limits only header reading, not the entire request. Further server timeouts and shutdown are covered in [GB-8.03](/lab/youtube/gb#gb-8-03).

`Add` still chooses the largest current ID plus one. Deleting the largest ID can therefore allow reuse. This teaching store's limitation is documented in the README; do not treat its IDs as permanent resource identities.

## Common mistakes

**1. "Get has Lock, so its result stays protected."** The broken `Get` and real race report are above. A pointer still refers to shared data after the method unlocks. Return a `Product` copy obtained under the lock; run both route and parallel tests with `-race`.

**2. Race mode does not start.** With this machine's `CGO_ENABLED=0`:

```console
$ go test -race ./cmd/api
go: -race requires cgo; enable cgo by setting CGO_ENABLED=1
```

The message says race mode requires C integration. On Linux enable cgo **and** have a C compiler such as `gcc`; setting `CGO_ENABLED=1` alone does not install it. I reran all race commands with the supplied Docker script. On a machine with the required compiler, run `go test -race ./...` directly. Docker is explained in GB-5.02.

**3. Hold the lock across `yield`, or call `Get` inside locked `Delete`.** Both can wait for the same mutex twice. Use the `All` copy pattern; inside `Delete`, search `s.products` directly while holding the lock once.

**4. Use `writeJSON(w, 204, nil)`.** It tries to encode `null`. A real server rejects a body for 204; a recorder can record it and fail the empty-body check. Use only `w.WriteHeader(http.StatusNoContent)`.

**5. Start outside the lesson root.** `bozor.json` is a relative path. A missing file means an empty catalog in `Load`, not a startup error. Run from the folder containing this file. If port 8765 is busy, stop your earlier server before starting another.
