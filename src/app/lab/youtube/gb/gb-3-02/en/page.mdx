## What you will learn

bozor can read the catalog from the file `katalog.txt`, but it writes nothing. Sold stock and new products disappear as soon as the program ends.
Today we write the catalog to the file `bozor.json` and read it back on the next run. On the way you will meet one dangerous case: `json.Marshal`
returns `{}` with no error at all. Where did the catalog go?

**One idea:** `encoding/json` turns a struct into JSON text using its **exported fields**. The key of each field is the name in the tag
(`` `json:"name"` ``); if there is no tag, it is the field's own name. The `json` package does not see a lowercase field and silently skips it; `omitempty` skips an "empty" value
(`""`, `0`, `false`, `nil`). The way back is `json.Unmarshal(data, &v)`: it writes the result into our variable **through its address**, skips an unknown key,
leaves a missing key at its zero value, and returns an error on broken text or a type that does not match. The file is just those same bytes.

By the end of the lesson you will:

- add json tags and `omitempty` to `Product` and write the catalog to `bozor.json` with `json.MarshalIndent` and `os.WriteFile`;
- load the catalog back with `os.ReadFile` and `json.Unmarshal(data, &products)`;
- read the errors: a lowercase field, an extra space in a tag, `Unmarshal` without `&`, a broken file — and know which of them `go vet` finds in advance;
- in `TASK.md`, add tags to `Order` and `OrderItem` and change `loadProducts`: "no file — empty catalog" and "broken file — error with the path".

Three core new words today:

| Word | Plain meaning | English term |
|---|---|---|
| `json.Marshal` | turns a struct into JSON bytes | marshal |
| struct tag | text after a field: the JSON key name and rules | struct tag |
| `json.Unmarshal` | writes JSON text into a struct (through the variable's address) | unmarshal |

Helpers: `os.WriteFile` and `os.ReadFile` (write and read a whole file), `json.NewEncoder` and `json.NewDecoder` (write to a stream and read from a stream).

## What JSON is

When a program ends, its memory is cleared, so we write the catalog to a file as **text**. We need a text format: both `bozor.json` and the HTTP requests in GB-4
carry data mostly in it. It is called **JSON**. The rules are short ([RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)):

- an **object** — curly braces `{ … }`; inside, `key: value` pairs separated by commas;
- a **key** — always text in double quotes (`"name"`);
- a **value** — text (`"olma"`), a number (`40`), `true` or `false`, a nested object, or a list;
- a **list** — square brackets `[ … ]`, with values inside;
- `null` — means "there is no value".

Two separate examples: the first is an object, the second is a list:

```text
{"name": "olma", "stock": 40, "active": true}
["olma", "oʻrik"]
```

| Example | What it is |
|---|---|
| `{"name": "olma", …}` | an object: keys `name`, `stock`, `active` |
| `"olma"` | a text value, in quotes |
| `40` | a number value, no quotes |
| `true` | a boolean value |
| `["olma", "oʻrik"]` | a list of two texts |

Today there are three things: `json.Marshal` (struct to JSON bytes), struct tags (the key name next to the field), `json.Unmarshal` (JSON to struct, and its errors).

## json.Marshal: from a struct to JSON bytes

`encoding/json` is a package of the standard library; in code its name is `json` (as in the line `package json` at the top). We look at its signature with `go doc`
(the first 4 lines of the output; `| head -4` cuts the output to 4 lines):

```console
$ go doc encoding/json.Marshal | head -4
package json // import "encoding/json"

func Marshal(v any) ([]byte, error)
    Marshal returns the JSON encoding of v.
```

`Marshal` takes any value (`any`) and returns its JSON form as a **byte slice** (`[]byte`); the second result is an `error`.
The smallest program (`_video/01-marshal/main.go`). The names in the code are Uzbek: `olma` ("apple"), `tiyin` ("tiyin", one hundredth of a som):

```go filename="_video/01-marshal/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
	"os"
)

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	p := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	data, err := json.Marshal(p)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println(string(data))
}
```

| Line | Code | What it does |
|---|---|---|
| 3–7 | `import ( … )` | three packages: `encoding/json` (today's), `fmt`, `os` |
| 10–15 | `type Product struct { … }` | the type from GB-2.03: `ID`, `Name`, `Price` (in tiyin), `Stock` |
| 18 | `p := Product{ID: 1, Name: "olma", …}` | `p` — one product (`olma`, price 1 200 000 tiyin, stock 40) |
| 19 | `data, err := json.Marshal(p)` | turns `p` into JSON: `data` — bytes (`[]byte`), `err` — an error or `nil` |
| 20–23 | `if err != nil { … }` | on an error, as in GB-3.01, prints to `os.Stderr` and calls `os.Exit(1)` |
| 24 | `fmt.Println(string(data))` | `string(data)` turns bytes into text, `Println` prints it |

### A lowercase field: `{}` with no error

In files, keys are usually written in lowercase. The first idea: name the fields themselves in lowercase (`_video/02-kichik/main.go`; everything else as before,
the literal in `main` also uses the new names):

```go
type Product struct {
	id    int64
	name  string
	price int64 // tiyin
	stock int
}
```

What will happen now: lowercase keys, an empty object, or a compile error?

**A)** `{"id":1,"name":"olma",…}` · **B)** `{}` · **C)** a compile error

<details>
<summary>Answer</summary>

**B: `{}`, with no error.** `go vet` says nothing either. If you chose **A**, you thought `json` reads lowercase fields too.
If you chose **C**, you thought such code is wrong; in fact it is valid Go.

```console
$ ./_video/run.sh 02-kichik go run .
{}
$ ./_video/run.sh 02-kichik go vet .
```

`go vet .` printed nothing: that is how it says "I found nothing".

</details>

The reason is the rule from GB-2.06: a lowercase name is visible only inside its own package. `id`, `name`, `price`, `stock` are fields of the `main` package, and `encoding/json` is another package.
It does **not see** them and silently skips them. The compiler agrees (the code is valid), `go vet` agrees — **the data disappears with no error**. That is why this is the most common JSON mistake.

| Field | Exported? | What `json` does |
|---|---|---|
| `ID`, `Name`, `Price`, `Stock` | yes (capital letter) | writes to JSON |
| `id`, `name`, `price`, `stock` | no (lowercase) | skips, says nothing |

## A struct tag: saying the key name next to the field

The solution: the field stays with a capital letter (it is exported), and the name in JSON is given in a **struct tag**. A tag is text after the field's type, inside **backticks**
(`` ` ``, the reverse quote) (`_video/03-tag/main.go`; only the struct changed):

```go
type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
}
```

We take the tag apart:

| Part | Meaning |
|---|---|
| `ID int64` | an ordinary field: name, then type |
| `` `json:"id"` `` | the tag: written after the type |
| `` ` `` … `` ` `` | text inside backticks is a **raw string literal**: a `"` inside is an ordinary character, no need to escape it (`\"`) |
| `json:"id"` | the form `key:"value"`: the key `json`, a colon, then in quotes the name in JSON |

`encoding/json` reads the tag while the program is **running**, through the `reflect` package: `reflect` is a standard package that shows a program the structure of types (field names, their tags).
That is why the compiler does not check the text inside a tag: for it, it is an ordinary string.

### The form is strict: no space after the colon

In `_video/03b-probel/main.go` one line is different: `Name  string `` `json: "name"` `` (a space after the colon). The compiler accepts it. We run it,
then check with `go vet`:

```console
$ ./_video/run.sh 03b-probel go run .
{"id":1,"Name":"olma","price":1200000,"stock":40}
$ ./_video/run.sh 03b-probel go vet .
main.go:12:2: struct field tag `json: "name"` not compatible with reflect.StructTag.Get: bad syntax for struct tag value
```

`json` does **not recognize** this tag and silently uses the field name: the key is `"Name"` again. There is no error. But `go vet` finds it:

| Part | Meaning |
|---|---|
| `main.go:12:2` | file, line 12, column 2: this is the `Name` field's line |
| `struct field tag` | a struct tag |
| `` `json: "name"` `` | the tag vet showed |
| `not compatible with reflect.StructTag.Get` | `reflect.StructTag.Get`, which reads the tag, does not accept this form |
| `bad syntax for struct tag value` | the way the tag value is written is wrong |

We remove the space (`03-tag`) and run again:

```console
$ ./_video/run.sh 03-tag go run .
{"id":1,"name":"olma","price":1200000,"stock":40}
```

The keys are now lowercase, and the names in Go did not change: the code says `p.Name`, and the JSON says `name`.

## omitempty: not writing an empty field

A new field: `Note` — a note on the product. Most products have no note; an empty `"note":""` in every one is just noise. In the tag, after the name, we write a comma and `omitempty`:
if the field is **empty**, the key is not written. For text, "empty" means an empty string `""`. The catalog now has two products: olma has no note, oʻrik ("apricot") has one
(from `_video/04-omit/main.go`):

```go
	Note  string `json:"note,omitempty"`
}

	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "oʻrik", Price: 3_500_000, Stock: 5, Note: "quritilgan"},
	}
```

The first line is the last field of `Product` and the closing `}`; the rest is the catalog in `main`: `[]Product` is a slice of `Product` (GB-2.01, GB-2.03). `quritilgan` means "dried".

To print both, we use `json.NewEncoder` (the rest of `main`):

```go
	enc := json.NewEncoder(os.Stdout)
	for _, p := range products {
		if err := enc.Encode(p); err != nil {
			fmt.Fprintln(os.Stderr, "xato:", err)
			os.Exit(1)
		}
	}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `enc := json.NewEncoder(os.Stdout)` | `NewEncoder` takes an `io.Writer` (GB-2.07); here `os.Stdout`. The result `enc` is an **Encoder** that writes to that stream |
| 2 | `for _, p := range products {` | a loop over each product `p` (GB-1.06) |
| 3 | `if err := enc.Encode(p); err != nil {` | `Encode` turns `p` into JSON, writes it to the stream **at once** and adds a newline; the error is in the short form of `if` (GB-1.05) |
| 4–5 | `fmt.Fprintln(os.Stderr, …)`, `os.Exit(1)` | on an error, exit |

`Marshal` **returns** the bytes, `Encode` **writes** them to a stream: the same job in a different form. How does the word oʻrik come out: as it is, or through a special code?

```console
$ ./_video/run.sh 04-omit go run .
{"id":1,"name":"olma","price":1200000,"stock":40}
{"id":2,"name":"oʻrik","price":3500000,"stock":5,"note":"quritilgan"}
```

As it is: JSON text is UTF-8 ([RFC 8259 §8.1](https://www.rfc-editor.org/rfc/rfc8259#section-8.1)), and the tutuq belgisi (glottal-stop sign) `ʻ` takes two bytes, as in GB-2.10. The olma line has no `note`, oʻrik has one.

### A question: what if we put omitempty on a number?

We add `omitempty` to the `Stock` tag too (`"stock,omitempty"`) and set oʻrik's stock to zero (`Stock: 0`). How is `stock` written in the oʻrik line?

**A)** `"stock":0` · **B)** there is no `stock` key at all · **C)** `"stock":null`

<details>
<summary>Answer</summary>

**B: there is no `stock` key.** For `omitempty`, **zero is empty too**. The list from the documentation: `false`, `0`, a nil pointer, a nil interface value, and an array, slice, map or string of length zero.
If you chose **A**, you thought `omitempty` affects only text. **C** — `null` is written only for a nil pointer or a nil slice, not for a zero number.

```console
$ ./_video/run.sh 05-quiz go run .
{"id":1,"name":"olma","price":1200000,"stock":40}
{"id":2,"name":"oʻrik","price":3500000,"note":"quritilgan"}
```

</details>

Why this is bad: a program that reads the file later **cannot tell zero from "unknown"**: in both cases there is no key. **The rule: `omitempty` is for text and lists, not for numbers.**

| Field type | "Empty" for `omitempty` |
|---|---|
| `string` | `""` |
| `int`, `int64` and other numbers | `0` |
| `bool` | `false` |
| pointer, interface | `nil` |
| slice, map | length 0 (both nil and empty) |

### How Marshal decides for each field

All the rules, along one path:

| Step | Question | If the answer is |
|---|---|---|
| 1 | is the field exported (capital letter)? | no → **skip** |
| 2 | what is the key? | the name in the tag; if there is no tag — the field name |
| 3 | is there `omitempty` and is the field empty? | yes → **skip** |
| 4 | otherwise | write the value (number, text, list, nested object) with the key |

## Writing to a file: saveProducts

Now we write the catalog to a file. The full program (`_video/06-save/main.go`); `run` has the shape from GB-3.01:

```go filename="_video/06-save/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
	"os"
)

// Product — katalogdagi bitta mahsulot. Tag'lar — bozor.json'dagi kalit nomlari.
type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
	Note  string `json:"note,omitempty"`
}

// saveProducts katalogni path fayliga JSON qilib yozadi.
func saveProducts(path string, products []Product) error {
	data, err := json.MarshalIndent(products, "", "  ")
	if err != nil {
		return err
	}
	return os.WriteFile(path, data, 0o644)
}

// run katalogni bozor.json'ga saqlaydi (GB-3.01'dagi shakl).
func run() error {
	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "oʻrik", Price: 3_500_000, Stock: 5, Note: "quritilgan"},
	}
	if err := saveProducts("bozor.json", products); err != nil {
		return err
	}
	fmt.Println("saqlandi:", len(products), "ta mahsulot")
	return nil
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 19 | `func saveProducts(path string, products []Product) error` | `path` is the file path, `products` is the catalog; returns only an `error` |
| 20 | `json.MarshalIndent(products, "", "  ")` | like `Marshal`, but splits the JSON into lines: the **prefix** at the start of each line is empty (`""`), the **indent** is two spaces (`"  "`) |
| 21–23 | `if err != nil { return err }` | if marshal returned an error, the function returns it |
| 24 | `return os.WriteFile(path, data, 0o644)` | writes `data` to the file `path`; creates the file if it does not exist, and if it does, **empties it** and writes again; the result is an `error` |
| 28–38 | `run` | builds the catalog, calls `saveProducts("bozor.json", …)` and prints how many products were saved (`saqlandi` — "saved", `ta mahsulot` — "products") |

`0o644` — a number with the prefix `0o` is **octal** (since Go 1.13). Read it as three digits: owner, group, others.

| Digit | Who | Permission |
|---|---|---|
| 6 | owner | `rw-`: reads and writes |
| 4 | group | `r--`: only reads |
| 4 | others | `r--`: only reads |

In `ls -l` it is `-rw-r--r--`. A warning: `os.WriteFile` is **not atomic**. If the write is cut off in the middle (the disk fills up, the process is killed), the file stays half-written; the documentation says so openly.
That is enough for this lesson; safe saving (write a temporary file, then swap it in) is outside this lesson.

```console
$ ./_video/run.sh 06-save go run .
saqlandi: 2 ta mahsulot
$ ./_video/run.sh 06-save sh -c 'go run . >/dev/null && stat -c "%A %s" bozor.json'
-rw-r--r-- 189
```

The second command shows the file's permissions and size: `-rw-r--r--`, 189 bytes (on a system with umask 022; another umask may narrow the permissions). The written [`bozor.json`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-3-02-json-saqlash/bozor.json):

```text
[
  {
    "id": 1,
    "name": "olma",
    "price": 1200000,
    "stock": 40
  },
  {
    "id": 2,
    "name": "oʻrik",
    "price": 3500000,
    "stock": 5,
    "note": "quritilgan"
  }
]
```

The outer square brackets are a list, because we wrote a slice. Each product is a separate object, each key is on its own line. oʻrik has `note`, olma does not. This is an ordinary text file:
you can compare it with diff in git and fix it by hand (we do that below).

## Reading the file: loadProducts and why &products

Now we read the file back (`_video/07-load/main.go`, lines 28–38):

```go
// loadProducts path faylidagi JSON katalogni oʻqiydi.
func loadProducts(path string) ([]Product, error) {
	data, err := os.ReadFile(path)
	if err != nil {
		return nil, err
	}
	var products []Product
	if err := json.Unmarshal(data, &products); err != nil {
		return nil, err
	}
	return products, nil
}
```

| Line | Code | What it does |
|---|---|---|
| 28 | `func loadProducts(path string) ([]Product, error)` | takes a file path, returns the catalog and an `error` |
| 29–32 | `data, err := os.ReadFile(path)` and the check | `ReadFile` reads the **whole** content of the file into a `[]byte`; on an error — a `nil` catalog and that error |
| 33 | `var products []Product` | an empty variable: for now a `nil` slice (GB-2.01) |
| 34 | `json.Unmarshal(data, &products)` | writes the JSON bytes into `products`; the signature is `Unmarshal(data []byte, v any) error` |
| 35 | `return nil, err` | if the JSON is broken — an error instead of a catalog |
| 37 | `return products, nil` | all is well: the filled catalog |

Why `&products`? The second parameter of `Unmarshal` is `any`: it writes the result **into this argument**. A function can write to the caller's variable only through its **address** (GB-2.04).

| Moment | The variable `products` | What `Unmarshal` sees |
|---|---|---|
| after line 33 | `nil` (nothing in it) | — |
| the call with `&products` | `nil` | the variable's **address**: there is somewhere to write |
| `Unmarshal` finished | `[{1 olma …} {2 oʻrik …}]` | — |

What if we forget `&`: `json.Unmarshal(data, products)`?

**A)** a compile error · **B)** the program runs, `Unmarshal` returns an error · **C)** no error, but the catalog is empty

<details>
<summary>Answer</summary>

**B.** The parameter of `Unmarshal` is `any`, so the compiler is silent: anything passes into `any` (**A** is wrong). That there is nowhere to write is checked by `Unmarshal` itself, and it is **not silent**:
`non-pointer` — "not a pointer". The result is an error, so **C** (a quietly empty catalog) is wrong too. And `go vet` finds it before the program runs.

```console
$ ./_video/run.sh 08-pointer go run .
xato: json: Unmarshal(non-pointer []main.Product)
exit status 1
$ ./_video/run.sh 08-pointer go vet .
main.go:34:26: call of Unmarshal passes non-pointer as second argument
```

`34:26` — line 34 (the `Unmarshal` line), column 26: the second argument; vet says it is "not a pointer".

</details>

That is why you run `go vet` before a commit: it gets a detailed look in GB-3.03. Once `&` is back in place (`07-load`), `run` calls `loadProducts("bozor.json")` and prints each product
(the loop in `run`: `fmt.Printf("%d %s: %d dona\n", p.ID, p.Name, p.Stock)`; `dona` means "pieces"):

```console
$ ./_video/run.sh 07-load go run .

2 oʻrik: 5 dona
```

The two products from the file came back: the path `Marshal` → file → `Unmarshal` is closed.

## Error paths: a broken file, no file and the Unmarshal rules

### When the price becomes text

We edit the file by hand (`_video/09-buzuq/bozor.json`): we put olma's price in quotes, so it is now not a number but **text**:

```text
  {
    "id": 1,
    "name": "olma",
    "price": "1200000",
    "stock": 40
  },
```

What does `Unmarshal` do now? `Price` is an `int64`, but the value in the file is text.

```console
$ ./_video/run.sh 09-buzuq go run .
xato: json: cannot unmarshal string into Go struct field .0.price of type int64
exit status 1
```

Read the message: "a `string` cannot be written into an `int64` field". `.0.price` is the `price` key in the zeroth element of the list (this is how the field name looks in the Go 1.27 message; `.0` is the element number).
The message has **no file name**: you will add it in the task. One more detail: on such an error `Unmarshal` still fills the other fields; that is why `loadProducts` returns `nil` on an error, not a half-filled catalog.

### The Unmarshal rules

The video states these rules as a list. I checked them in a separate small program (it is not in the course folder: `rules/main.go`, `go run main.go`). The full code:

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
	Note  string `json:"note,omitempty"`
}

func main() {
	var a Product
	err := json.Unmarshal([]byte(`{"id":1,"name":"olma","rang":"qizil"}`), &a)
	fmt.Printf("1: %+v err=%v\n", a, err)

	var b Product
	err = json.Unmarshal([]byte(`{"ID":3,"NAME":"non"}`), &b)
	fmt.Printf("2: %+v err=%v\n", b, err)

	var c Product
	err = json.Unmarshal([]byte(`{"id":1 "name":"olma"}`), &c)
	fmt.Printf("3: %+v err=%v\n", c, err)

	var d []Product
	err = json.Unmarshal([]byte(`[{"id":1,"name":"olma","price":"1200000","stock":40}]`), &d)
	fmt.Printf("4: %+v err=%v\n", d, err)

	out, err := json.Marshal(Product{ID: 2, Name: "non", Price: 400_000})
	fmt.Println("5:", string(out), err)
}
```

`[]byte(`…`)` turns text into bytes (the reverse of `string(data)`); the backtick is a raw string again. `%+v` prints a struct with its field names. Names in the code: `rang` — "colour", `qizil` — "red", `non` — "bread".

```console
$ go run main.go
1: {ID:1 Name:olma Price:0 Stock:0 Note:} err=<nil>
2: {ID:3 Name:non Price:0 Stock:0 Note:} err=<nil>
3: {ID:0 Name: Price:0 Stock:0 Note:} err=invalid character '"' after object key:value pair
4: [{ID:1 Name:olma Price:0 Stock:40 Note:}] err=json: cannot unmarshal string into Go struct field .0.price of type int64
5: {"id":2,"name":"non","price":400000,"stock":0} <nil>
```

| Line | What it shows |
|---|---|
| 1 | an **unknown key** (`rang`) was skipped silently; **missing keys** (`price`, `stock`) left the fields at zero; no error |
| 2 | upper and lower case in a key name **do not matter**: `"ID"` and `"NAME"` landed in the `id` and `name` fields |
| 3 | broken JSON (no comma after a key-value pair): an error, the catalog is empty |
| 4 | the type did not match: an error **and** `Stock: 40` was still filled (that is why `loadProducts` returns `nil` on an error) |
| 5 | `Note` is empty — no key (`omitempty`); `Stock` is zero, but there is no `omitempty` — `"stock":0` was written |

Three rules: an unknown key is skipped, a missing key leaves the field at zero, letter case in a key name does not matter. An error comes in two cases: broken JSON and a type that does not match.

### The file does not exist yet

When bozor runs for the first time, `bozor.json` does not exist yet. What error do you expect? We delete the file with `rm` (removes a file) and run `go run .`.
The command deletes the copy in the temporary `bozor/` folder; the `bozor.json` in your course folder stays in place:

## Decoder: reading the file as a stream

The reading partner of `Encoder` is `Decoder`. This is another variant of `loadProducts` (`_video/11-decoder/main.go`, the changed part of the function):

```go
	f, err := os.Open(path)
	if err != nil {
		return nil, err
	}
	defer f.Close()
	var products []Product
	if err := json.NewDecoder(f).Decode(&products); err != nil {
		return nil, err
	}
```

| Line | Code | What it does |
|---|---|---|
| 1–4 | `f, err := os.Open(path)` and the check | opens the file, as in GB-3.01; on an error it returns |
| 5 | `defer f.Close()` | **after** the `err` check (GB-2.09): on an error `f` is `nil`, there is nothing to close |
| 7 | `json.NewDecoder(f).Decode(&products)` | `NewDecoder` takes an `io.Reader`: `f` (`*os.File`) fits; the `Decode` method of the returned `Decoder` reads JSON from the stream and writes it into `&products` |

`Decode` also takes an address — `&` is needed again. The result is the same as before (`./_video/run.sh 11-decoder go run .` gives the same two lines as `07-load`). You will need `Decoder` in GB-4:
a server reads the JSON of an HTTP request this way, through an `io.Reader`. For this lesson `ReadFile` + `Unmarshal` is enough.

## Going deeper (optional): encoding/json/v2

Go 1.27 added `encoding/json/v2`; and `encoding/json` now runs on top of it, with the same behavior ([Go 1.27 release notes](https://go.dev/doc/go1.27)).
In the import we give v2 the name `jsonv2`, because both packages are named `json`. The full program (`_video/12-v2/main.go`): in the variable `in` the key `name` appears **twice**:

```go filename="_video/12-v2/main.go" showLineNumbers
package main

import (
	"encoding/json"
	jsonv2 "encoding/json/v2"
	"fmt"
)

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
}

func main() {
	in := []byte(`{"id":1,"name":"olma","name":"non"}`)
	var p Product
	err := json.Unmarshal(in, &p)
	fmt.Println("v1:", err, p.Name)
	err = jsonv2.Unmarshal(in, &p)
	fmt.Println("v2:", err)
}
```

| Line | Code | What it does |
|---|---|---|
| 5 | `jsonv2 "encoding/json/v2"` | imports the v2 package under the name `jsonv2` |
| 18 | `in := []byte(`…`)` | turns the JSON text into bytes; `name` twice |
| 20–21 | `json.Unmarshal(in, &p)` | v1: prints the error and `p.Name` |
| 22–23 | `jsonv2.Unmarshal(in, &p)` | v2: prints only the error |

```console
$ ./_video/run.sh 12-v2 go run .
v1: <nil> non
v2: jsontext: duplicate object member name "name"
```

v1 took the **last** value with no error: `non`, error `nil`. v2 refused: `jsontext` (the text package of v2) says "duplicate" — a repeated key.

v2 differs in three more places. I ran them side by side, `v1` and `v2` (a program that is not in the course folder; the code is short, it is here):

```go
package main

import (
	"encoding/json"
	jsonv2 "encoding/json/v2"
	"fmt"
)

type P struct {
	ID    int64 `json:"id"`
	Stock int   `json:"stock,omitempty"`
}

type L struct {
	id int64
}

func main() {
	b, err := json.Marshal(P{ID: 2})
	fmt.Println("v1:", string(b), err)
	b, err = jsonv2.Marshal(P{ID: 2})
	fmt.Println("v2:", string(b), err)

	b, err = json.Marshal(L{id: 1})
	fmt.Println("v1:", string(b), err)
	b, err = jsonv2.Marshal(L{id: 1})
	fmt.Println("v2:", string(b), err)

	var p P
	err = json.Unmarshal([]byte(`{"ID":3}`), &p)
	fmt.Println("v1:", p.ID, err)
	p = P{}
	err = jsonv2.Unmarshal([]byte(`{"ID":3}`), &p)
	fmt.Println("v2:", p.ID, err)
}
```

```console
$ go run main.go
v1: {"id":2} <nil>
v2: {"id":2,"stock":0} <nil>
v1: {} <nil>
v2:  json: cannot marshal from Go main.L: Go struct has no exported fields
v1: 3 <nil>
v2: 0 <nil>
```

| Case | v1 (`encoding/json`) | v2 (`encoding/json/v2`) |
|---|---|---|
| `omitempty` and `Stock: 0` | no `stock` | `"stock":0` stays: v2 skips only empty **JSON** values |
| a struct with no exported fields | a silent `{}` | an error: `Go struct has no exported fields` |
| key `"ID"`, tag `"id"` | `ID` is filled (letter case does not matter) | not filled (letter case matters) |

`go doc encoding/json` recommends v2 for new code; the v1 API stays supported, and moving is not required. The course continues with `encoding/json`, which is widespread in working code.

## Common mistakes

All of them have appeared on this page; here they are short, with the fix.

**1. "A lowercase field is written too, or at least gives an error."** No: `Marshal` silently returns `{}` (see the section above, "A lowercase field: `{}` with no error").
Both `go run` and `go vet` are silent. The fix: the field with a capital letter, the name in JSON in the tag: `` ID int64 `json:"id"` ``.

**2. A space after the colon in a tag.** `` `json: "name"` `` — `json` does not recognize it and uses the field name (`"Name"`); the compiler is silent, `go vet` finds it:

```console
$ ./_video/run.sh 03b-probel go vet .
main.go:12:2: struct field tag `json: "name"` not compatible with reflect.StructTag.Get: bad syntax for struct tag value
```

Line 12, column 2 is that field; `bad syntax for struct tag value` — the tag is written wrongly. The fix: no space, `` `json:"name"` ``.

**3. `Unmarshal` without `&`.** The compiler is silent, the program stops with an error:

```console
$ ./_video/run.sh 08-pointer go run .
xato: json: Unmarshal(non-pointer []main.Product)
exit status 1
```

`non-pointer` — the second argument is not an address. The fix: `json.Unmarshal(data, &products)`. `go vet .` finds it in advance (`call of Unmarshal passes non-pointer as second argument`).

**4. `omitempty` on a number.** With `Stock: 0` the `stock` key disappears, and the program that reads the file cannot tell zero from unknown (see the section above, "A question: what if we put omitempty on a number?"). The fix: keep the tag `` `json:"stock"` `` on a number.

**5. Returning the error of a broken file without the file name.** `json: cannot unmarshal string into Go struct field .0.price of type int64` does not say which file it is. The fix: wrap the error with the path through `%w` (the task, step 2(b)).

```go
func loadProducts(path string) ([]Product, error) {
	data, err := os.ReadFile(path)
	if errors.Is(err, os.ErrNotExist) {
		return nil, nil
	}
	if err != nil {
		return nil, err
	}
	var products []Product
	if err := json.Unmarshal(data, &products); err != nil {
		return nil, fmt.Errorf("%s: %w", path, err)
	}
	return products, nil
}
```

(a) `errors.Is(err, os.ErrNotExist)` recognizes the "no such file" error; this check must stand **before** `if err != nil`, otherwise "no such file" is returned as an ordinary error too.
If the file does not exist — `nil, nil`: an empty catalog and no error. (b) `fmt.Errorf("%s: %w", path, err)` adds the path to the error text, and `%w` keeps the original JSON error in the chain (GB-2.08);
