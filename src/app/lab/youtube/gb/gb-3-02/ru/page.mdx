## Что вы узнаете

bozor умеет читать каталог из файла `katalog.txt`, но ничего не записывает. Проданные остатки и новые товары исчезают, как только программа завершается.
Сегодня мы записываем каталог в файл `bozor.json` и читаем его обратно при следующем запуске. По пути встретится один опасный случай: `json.Marshal`
без всякой ошибки возвращает `{}`. Куда делся каталог?

**Одна идея:** `encoding/json` превращает структуру в текст JSON по её **экспортируемым полям**. Ключ каждого поля — имя из тега
(`` `json:"name"` ``), а если тега нет — имя самого поля. Поле с маленькой буквы пакет `json` не видит и молча пропускает; `omitempty` пропускает «пустое» значение
(`""`, `0`, `false`, `nil`). Обратный путь — `json.Unmarshal(data, &v)`: результат он записывает в нашу переменную **по адресу**, неизвестный ключ пропускает,
отсутствующий ключ оставляет нулевым, а на битом тексте или несовпадающем типе возвращает ошибку. Файл — это те же самые байты.

К концу урока вы:

- ставите json-теги и `omitempty` в `Product` и записываете каталог в `bozor.json` через `json.MarshalIndent` и `os.WriteFile`;
- загружаете каталог обратно через `os.ReadFile` и `json.Unmarshal(data, &products)`;
- читаете ошибки: поле с маленькой буквы, лишний пробел в теге, `Unmarshal` без `&`, битый файл — и знаете, какую из них `go vet` находит заранее;
- в `TASK.md` ставите теги в `Order` и `OrderItem` и переделываете `loadProducts`: «файла нет — пустой каталог» и «битый файл — ошибка с путём».

Три основных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| `json.Marshal` | превращает структуру в байты JSON | marshal |
| тег структуры | текст после поля: имя JSON-ключа и правила | struct tag |
| `json.Unmarshal` | записывает текст JSON в структуру (по адресу переменной) | unmarshal |

Вспомогательные: `os.WriteFile` и `os.ReadFile` (записать и прочитать файл целиком), `json.NewEncoder` и `json.NewDecoder` (запись в поток и чтение из потока).

## Что такое JSON

Когда программа завершается, память очищается, поэтому каталог мы записываем в файл в виде **текста**. Нам нужен текстовый формат: и `bozor.json`, и HTTP-запросы в GB-4
переносят данные в основном в нём. Он называется **JSON**. Правила короткие ([RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)):

- **объект** — фигурные скобки `{ … }`; внутри пары `ключ: значение`, разделённые запятыми;
- **ключ** — всегда текст в двойных кавычках (`"name"`);
- **значение** — текст (`"olma"`), число (`40`), `true` или `false`, вложенный объект или список;
- **список** — квадратные скобки `[ … ]`, внутри значения;
- `null` — означает «значения нет».

Два отдельных примера: первый — объект, второй — список:

```text
{"name": "olma", "stock": 40, "active": true}
["olma", "oʻrik"]
```

| Пример | Что это |
|---|---|
| `{"name": "olma", …}` | объект: ключи `name`, `stock`, `active` |
| `"olma"` | текстовое значение, в кавычках |
| `40` | числовое значение, без кавычек |
| `true` | логическое значение |
| `["olma", "oʻrik"]` | список из двух текстов |

Сегодня три вещи: `json.Marshal` (из структуры — байты JSON), теги структур (имя ключа рядом с полем), `json.Unmarshal` (из JSON — структура, и его ошибки).

## json.Marshal: из структуры в байты JSON

`encoding/json` — пакет стандартной библиотеки; в коде его имя `json` (как в строке `package json` в начале). Сигнатуру посмотрим через `go doc`
(первые 4 строки вывода; `| head -4` обрезает вывод до 4 строк):

```console
$ go doc encoding/json.Marshal | head -4
package json // import "encoding/json"

func Marshal(v any) ([]byte, error)
    Marshal returns the JSON encoding of v.
```

`Marshal` принимает любое значение (`any`) и возвращает его JSON-представление в виде **слайса байтов** (`[]byte`); второй результат — `error`.
Самая маленькая программа (`_video/01-marshal/main.go`). Имена в коде узбекские: `olma` («яблоко»), `tiyin` («тиын», сотая часть сума):

```go filename="_video/01-marshal/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
	"os"
)

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	p := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	data, err := json.Marshal(p)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println(string(data))
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–7 | `import ( … )` | три пакета: `encoding/json` (сегодняшний), `fmt`, `os` |
| 10–15 | `type Product struct { … }` | тип из GB-2.03: `ID`, `Name`, `Price` (в тиынах), `Stock` |
| 18 | `p := Product{ID: 1, Name: "olma", …}` | `p` — один товар (`olma`, цена 1 200 000 тиын, остаток 40) |
| 19 | `data, err := json.Marshal(p)` | превращает `p` в JSON: `data` — байты (`[]byte`), `err` — ошибка или `nil` |
| 20–23 | `if err != nil { … }` | при ошибке, как в GB-3.01, печатает в `os.Stderr` и вызывает `os.Exit(1)` |
| 24 | `fmt.Println(string(data))` | `string(data)` превращает байты в текст, `Println` его печатает |

Что появится на экране? Как будут записаны ключи?

**A)** с маленькой буквы: `{"id":1,"name":"olma",…}` · **B)** точно как имена полей: `{"ID":1,"Name":"olma",…}` · **C)** без ключей, только значения: `{1,"olma",1200000,40}`

<details>
<summary>Ответ</summary>

**B.** Если тега нет, ключ — имя поля в Go, с заглавной буквой. Если вы выбрали **A**, вы решили, что `json` сам делает имена маленькими: нет,
ключ с маленькой буквы вы задаёте **сами** тегом, который мы разберём сегодня. **C** — в JSON значение всегда идёт с ключом (`{1,"olma",…}` даже не JSON).

```console
$ ./_video/run.sh 01-marshal go run .
{"ID":1,"Name":"olma","Price":1200000,"Stock":40}
```

</details>

Прочитайте результат: числа без кавычек (`1200000`), текст в кавычках (`"olma"`), цена в тиынах. Порядок — это порядок полей в структуре.

| Поле `Product` | Значение | Пара в JSON |
|---|---|---|
| `ID` | `1` | `"ID":1` |
| `Name` | `"olma"` | `"Name":"olma"` |
| `Price` | `1_200_000` | `"Price":1200000` |
| `Stock` | `40` | `"Stock":40` |

### Поле с маленькой буквы: `{}` без ошибки

В файлах ключи обычно пишут с маленькой буквы. Первая мысль: назвать сами поля с маленькой буквы (`_video/02-kichik/main.go`; остальное как раньше,
литерал в `main` тоже с новыми именами):

```go
type Product struct {
	id    int64
	name  string
	price int64 // tiyin
	stock int
}
```

Что теперь будет: ключи с маленькой буквы, пустой объект или ошибка компиляции?

**A)** `{"id":1,"name":"olma",…}` · **B)** `{}` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `{}`, без ошибки.** `go vet` тоже молчит. Если вы выбрали **A**, вы решили, что `json` читает и поля с маленькой буквы.
Если выбрали **C**, вы решили, что такой код неверен; на деле это корректный код Go.

```console
$ ./_video/run.sh 02-kichik go run .
{}
$ ./_video/run.sh 02-kichik go vet .
```

`go vet .` ничего не напечатал: так он говорит «я ничего не нашёл».

</details>

Причина — правило из GB-2.06: имя с маленькой буквы видно только в своём пакете. `id`, `name`, `price`, `stock` — поля пакета `main`, а `encoding/json` — другой пакет.
Он их **не видит** и молча пропускает. Компилятор согласен (код верный), `go vet` согласен — **данные пропадают без ошибки**. Поэтому это самая частая ошибка с JSON.

| Поле | Экспортируется? | Что делает `json` |
|---|---|---|
| `ID`, `Name`, `Price`, `Stock` | да (заглавная) | записывает в JSON |
| `id`, `name`, `price`, `stock` | нет (маленькая) | пропускает, ничего не сообщая |

## Тег структуры: имя ключа рядом с полем

Решение: поле остаётся с заглавной буквы (экспортируется), а имя в JSON задаётся **тегом структуры**. Тег — текст после типа поля, внутри **backtick**
(`` ` ``, обратная кавычка) (`_video/03-tag/main.go`; изменилась только структура):

```go
type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
}
```

Разберём тег по частям:

| Часть | Смысл |
|---|---|
| `ID int64` | обычное поле: имя, потом тип |
| `` `json:"id"` `` | тег: пишется после типа |
| `` ` `` … `` ` `` | текст внутри backtick — **raw string literal** (сырая строка): `"` внутри — обычный символ, экранировать (`\"`) не нужно |
| `json:"id"` | форма `ключ:"значение"`: ключ `json`, двоеточие, в кавычках имя в JSON |

`encoding/json` читает тег, когда программа **работает**, через пакет `reflect`: `reflect` — стандартный пакет, который показывает программе строение типов (имена полей, их теги).
Поэтому компилятор не проверяет текст внутри тега: для него это обычная строка.

### Форма строгая: после двоеточия пробела быть не должно

В `_video/03b-probel/main.go` одна строка другая: `Name  string `` `json: "name"` `` (пробел после двоеточия). Компилятор её принимает. Запустим,
потом проверим через `go vet`:

```console
$ ./_video/run.sh 03b-probel go run .
{"id":1,"Name":"olma","price":1200000,"stock":40}
$ ./_video/run.sh 03b-probel go vet .
main.go:12:2: struct field tag `json: "name"` not compatible with reflect.StructTag.Get: bad syntax for struct tag value
```

`json` этот тег **не распознаёт** и молча берёт имя поля: ключ снова `"Name"`. Ошибки нет. А `go vet` находит:

| Часть | Смысл |
|---|---|
| `main.go:12:2` | файл, строка 12, столбец 2: это строка поля `Name` |
| `struct field tag` | тег структуры |
| `` `json: "name"` `` | тег, который показал vet |
| `not compatible with reflect.StructTag.Get` | `reflect.StructTag.Get`, который читает тег, эту форму не принимает |
| `bad syntax for struct tag value` | неверная запись значения тега |

Уберём пробел (`03-tag`) и запустим снова:

```console
$ ./_video/run.sh 03-tag go run .
{"id":1,"name":"olma","price":1200000,"stock":40}
```

Ключи теперь с маленькой буквы, а имена в Go не изменились: код говорит `p.Name`, а JSON — `name`.

## omitempty: не записывать пустое поле

Новое поле: `Note` — примечание к товару. У большинства товаров примечания нет; пустой `"note":""` в каждом — просто шум. В теге после имени пишем запятую и `omitempty`:
если поле **пустое**, ключ не записывается. Для текста «пустое» — это пустая строка `""`. Теперь в каталоге два товара: у olma примечания нет, у oʻrik («абрикос») есть
(из `_video/04-omit/main.go`):

```go
	Note  string `json:"note,omitempty"`
}

	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "oʻrik", Price: 3_500_000, Stock: 5, Note: "quritilgan"},
	}
```

Первая строка — последнее поле `Product` и закрывающая `}`; остальное — каталог в `main`: `[]Product` — слайс из `Product` (GB-2.01, GB-2.03). `quritilgan` — «сушёный».

Чтобы вывести оба товара, берём `json.NewEncoder` (остальная часть `main`):

```go
	enc := json.NewEncoder(os.Stdout)
	for _, p := range products {
		if err := enc.Encode(p); err != nil {
			fmt.Fprintln(os.Stderr, "xato:", err)
			os.Exit(1)
		}
	}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `enc := json.NewEncoder(os.Stdout)` | `NewEncoder` принимает `io.Writer` (GB-2.07); здесь `os.Stdout`. Результат `enc` — **Encoder**, пишущий в этот поток |
| 2 | `for _, p := range products {` | цикл по товарам `p` (GB-1.06) |
| 3 | `if err := enc.Encode(p); err != nil {` | `Encode` превращает `p` в JSON, **сразу** пишет в поток и добавляет перевод строки; ошибка — в короткой форме `if` (GB-1.05) |
| 4–5 | `fmt.Fprintln(os.Stderr, …)`, `os.Exit(1)` | при ошибке — выход |

`Marshal` байты **возвращает**, а `Encode` **записывает** в поток: это одна работа в разной форме. Как выведется слово oʻrik: как есть или через специальный код?

```console
$ ./_video/run.sh 04-omit go run .
{"id":1,"name":"olma","price":1200000,"stock":40}
{"id":2,"name":"oʻrik","price":3500000,"stock":5,"note":"quritilgan"}
```

Как есть: текст JSON — это UTF-8 ([RFC 8259 §8.1](https://www.rfc-editor.org/rfc/rfc8259#section-8.1)), знак тутук `ʻ` занимает два байта, как в GB-2.10. В строке olma нет `note`, у oʻrik он есть.

### Вопрос: а если поставить omitempty на число?

Добавим `omitempty` и в тег `Stock` (`"stock,omitempty"`) и обнулим остаток oʻrik (`Stock: 0`). Как в строке oʻrik запишется `stock`?

**A)** `"stock":0` · **B)** ключа `stock` нет вообще · **C)** `"stock":null`

<details>
<summary>Ответ</summary>

**B: ключа `stock` нет.** Для `omitempty` **ноль тоже пустой**. Список из документации: `false`, `0`, nil-указатель, nil-значение интерфейса и массив, слайс, map или строка нулевой длины.
Если вы выбрали **A**, вы решили, что `omitempty` касается только текста. **C** — `null` выводится только для nil-указателя или nil-слайса, а не для нулевого числа.

```console
$ ./_video/run.sh 05-quiz go run .
{"id":1,"name":"olma","price":1200000,"stock":40}
{"id":2,"name":"oʻrik","price":3500000,"note":"quritilgan"}
```

</details>

Чем это плохо: программа, которая потом читает файл, **не отличит ноль от «неизвестно»**: в обоих случаях ключа нет. **Правило: `omitempty` — для текста и списков, не для чисел.**

| Тип поля | «Пустое» для `omitempty` |
|---|---|
| `string` | `""` |
| `int`, `int64` и другие числа | `0` |
| `bool` | `false` |
| указатель, интерфейс | `nil` |
| слайс, map | длина 0 (и nil, и пустой) |

### Как Marshal решает для каждого поля

Все правила — по одному пути:

| Шаг | Вопрос | Если ответ |
|---|---|---|
| 1 | поле экспортируется (заглавная буква)? | нет → **пропустить** |
| 2 | какой ключ? | имя из тега; если тега нет — имя поля |
| 3 | есть `omitempty` и поле пустое? | да → **пропустить** |
| 4 | иначе | записать значение (число, текст, список, вложенный объект) с ключом |

## Запись в файл: saveProducts

Теперь записываем каталог в файл. Полная программа (`_video/06-save/main.go`); `run` — форма из GB-3.01:

```go filename="_video/06-save/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
	"os"
)

// Product — katalogdagi bitta mahsulot. Tag'lar — bozor.json'dagi kalit nomlari.
type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
	Note  string `json:"note,omitempty"`
}

// saveProducts katalogni path fayliga JSON qilib yozadi.
func saveProducts(path string, products []Product) error {
	data, err := json.MarshalIndent(products, "", "  ")
	if err != nil {
		return err
	}
	return os.WriteFile(path, data, 0o644)
}

// run katalogni bozor.json'ga saqlaydi (GB-3.01'dagi shakl).
func run() error {
	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "oʻrik", Price: 3_500_000, Stock: 5, Note: "quritilgan"},
	}
	if err := saveProducts("bozor.json", products); err != nil {
		return err
	}
	fmt.Println("saqlandi:", len(products), "ta mahsulot")
	return nil
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 19 | `func saveProducts(path string, products []Product) error` | `path` — путь к файлу, `products` — каталог; возвращает только `error` |
| 20 | `json.MarshalIndent(products, "", "  ")` | как `Marshal`, но разбивает JSON на строки: **префикс** в начале каждой строки пустой (`""`), **отступ** — два пробела (`"  "`) |
| 21–23 | `if err != nil { return err }` | если marshal дал ошибку, функция возвращает её |
| 24 | `return os.WriteFile(path, data, 0o644)` | записывает `data` в файл `path`; если файла нет — создаёт, если есть — **очищает** и пишет заново; результат — `error` |
| 28–38 | `run` | собирает каталог, вызывает `saveProducts("bozor.json", …)` и печатает, сколько товаров сохранено (`saqlandi` — «сохранено», `ta mahsulot` — «товара(ов)») |

`0o644` — число с префиксом `0o` записано в **восьмеричной** системе (с Go 1.13). Читайте его как три цифры: владелец, группа, остальные.

| Цифра | Кто | Права |
|---|---|---|
| 6 | владелец | `rw-`: читает и пишет |
| 4 | группа | `r--`: только читает |
| 4 | остальные | `r--`: только читает |

В `ls -l` это `-rw-r--r--`. Предупреждение: `os.WriteFile` **не атомарна**. Если запись оборвётся посередине (диск заполнился, процесс убили), файл останется недописанным; документация говорит об этом прямо.
Для этого урока достаточно; надёжное сохранение (записать временный файл, потом заменить) выходит за рамки урока.

```console
$ ./_video/run.sh 06-save go run .
saqlandi: 2 ta mahsulot
$ ./_video/run.sh 06-save sh -c 'go run . >/dev/null && stat -c "%A %s" bozor.json'
-rw-r--r-- 189
```

Вторая команда показывает права и размер файла: `-rw-r--r--`, 189 байт (в системе с umask 022; другой umask может сузить права). Записанный [`bozor.json`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-3-02-json-saqlash/bozor.json):

```text
[
  {
    "id": 1,
    "name": "olma",
    "price": 1200000,
    "stock": 40
  },
  {
    "id": 2,
    "name": "oʻrik",
    "price": 3500000,
    "stock": 5,
    "note": "quritilgan"
  }
]
```

Внешние квадратные скобки — список, потому что мы записали слайс. Каждый товар — отдельный объект, каждый ключ на своей строке. У oʻrik есть `note`, у olma нет. Это обычный текстовый файл:
его можно сравнивать через diff в git и править руками (ниже мы так и сделаем).

## Чтение файла: loadProducts и зачем &products

Теперь читаем файл обратно (`_video/07-load/main.go`, строки 28–38):

```go
// loadProducts path faylidagi JSON katalogni oʻqiydi.
func loadProducts(path string) ([]Product, error) {
	data, err := os.ReadFile(path)
	if err != nil {
		return nil, err
	}
	var products []Product
	if err := json.Unmarshal(data, &products); err != nil {
		return nil, err
	}
	return products, nil
}
```

| Строка | Код | Что делает |
|---|---|---|
| 28 | `func loadProducts(path string) ([]Product, error)` | принимает путь к файлу, возвращает каталог и `error` |
| 29–32 | `data, err := os.ReadFile(path)` и проверка | `ReadFile` читает **всё** содержимое файла в `[]byte`; при ошибке — `nil` вместо каталога и эта ошибка |
| 33 | `var products []Product` | пустая переменная: пока `nil`-слайс (GB-2.01) |
| 34 | `json.Unmarshal(data, &products)` | записывает байты JSON в `products`; сигнатура `Unmarshal(data []byte, v any) error` |
| 35 | `return nil, err` | если JSON битый — вместо каталога ошибка |
| 37 | `return products, nil` | всё хорошо: заполненный каталог |

Зачем `&products`? Второй параметр `Unmarshal` — `any`: результат он записывает **в этот аргумент**. Функция может записать в переменную вызывающего только по её **адресу** (GB-2.04).

| Момент | Переменная `products` | Что видит `Unmarshal` |
|---|---|---|
| после строки 33 | `nil` (ничего нет) | — |
| вызов с `&products` | `nil` | **адрес** переменной: есть куда записать |
| `Unmarshal` завершился | `[{1 olma …} {2 oʻrik …}]` | — |

А если забыть `&`: `json.Unmarshal(data, products)`?

**A)** ошибка компиляции · **B)** программа работает, `Unmarshal` возвращает ошибку · **C)** без ошибки, но каталог пуст

<details>
<summary>Ответ</summary>

**B.** Параметр `Unmarshal` — `any`, поэтому компилятор молчит: в `any` проходит что угодно (**A** неверно). Что записать некуда, проверяет сам `Unmarshal`, и он **не молчит**:
`non-pointer` — «не указатель». Результат — ошибка, поэтому **C** (тихо пустой каталог) тоже неверно. А `go vet` находит это до запуска программы.

```console
$ ./_video/run.sh 08-pointer go run .
xato: json: Unmarshal(non-pointer []main.Product)
exit status 1
$ ./_video/run.sh 08-pointer go vet .
main.go:34:26: call of Unmarshal passes non-pointer as second argument
```

`34:26` — строка 34 (строка `Unmarshal`), столбец 26: второй аргумент; vet говорит, что это «не указатель».

</details>

Поэтому перед коммитом запускайте `go vet`: подробно он разобран в GB-3.03. Когда `&` вернулся на место (`07-load`), `run` вызывает `loadProducts("bozor.json")` и печатает каждый товар
(цикл в `run`: `fmt.Printf("%d %s: %d dona\n", p.ID, p.Name, p.Stock)`; `dona` — «штук»):

```console
$ ./_video/run.sh 07-load go run .
1 olma: 40 dona
2 oʻrik: 5 dona
```

Два товара из файла вернулись: путь `Marshal` → файл → `Unmarshal` замкнулся.

## Пути ошибок: битый файл, нет файла и правила Unmarshal

### Если цена стала текстом

Правим файл руками (`_video/09-buzuq/bozor.json`): цену olma берём в кавычки, теперь это не число, а **текст**:

```text
  {
    "id": 1,
    "name": "olma",
    "price": "1200000",
    "stock": 40
  },
```

Что теперь сделает `Unmarshal`? `Price` — `int64`, а значение в файле — текст.

```console
$ ./_video/run.sh 09-buzuq go run .
xato: json: cannot unmarshal string into Go struct field .0.price of type int64
exit status 1
```

Прочитайте сообщение: «`string` в поле `int64` записать нельзя». `.0.price` — ключ `price` в нулевом элементе списка (так имя поля выглядит в сообщении Go 1.27; `.0` — номер элемента).
В сообщении **нет имени файла**: его вы добавите в задании. И ещё деталь: при такой ошибке `Unmarshal` всё равно заполняет остальные поля; поэтому `loadProducts` при ошибке возвращает `nil`, а не неполный каталог.

### Правила Unmarshal

В видео эти правила названы списком. Я проверил их в отдельной маленькой программе (её нет в папке курса: `rules/main.go`, `go run main.go`). Полный код:

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
	Note  string `json:"note,omitempty"`
}

func main() {
	var a Product
	err := json.Unmarshal([]byte(`{"id":1,"name":"olma","rang":"qizil"}`), &a)
	fmt.Printf("1: %+v err=%v\n", a, err)

	var b Product
	err = json.Unmarshal([]byte(`{"ID":3,"NAME":"non"}`), &b)
	fmt.Printf("2: %+v err=%v\n", b, err)

	var c Product
	err = json.Unmarshal([]byte(`{"id":1 "name":"olma"}`), &c)
	fmt.Printf("3: %+v err=%v\n", c, err)

	var d []Product
	err = json.Unmarshal([]byte(`[{"id":1,"name":"olma","price":"1200000","stock":40}]`), &d)
	fmt.Printf("4: %+v err=%v\n", d, err)

	out, err := json.Marshal(Product{ID: 2, Name: "non", Price: 400_000})
	fmt.Println("5:", string(out), err)
}
```

`[]byte(`…`)` превращает текст в байты (обратное к `string(data)`); backtick — снова сырая строка. `%+v` печатает структуру с именами полей. Имена в коде: `rang` — «цвет», `qizil` — «красный», `non` — «хлеб».

```console
$ go run main.go
1: {ID:1 Name:olma Price:0 Stock:0 Note:} err=<nil>
2: {ID:3 Name:non Price:0 Stock:0 Note:} err=<nil>
3: {ID:0 Name: Price:0 Stock:0 Note:} err=invalid character '"' after object key:value pair
4: [{ID:1 Name:olma Price:0 Stock:40 Note:}] err=json: cannot unmarshal string into Go struct field .0.price of type int64
5: {"id":2,"name":"non","price":400000,"stock":0} <nil>
```

| Строка | Что показывает |
|---|---|
| 1 | **неизвестный ключ** (`rang`) тихо пропущен; **отсутствующие ключи** (`price`, `stock`) оставили поля нулевыми; ошибки нет |
| 2 | регистр букв в имени ключа **не различается**: `"ID"` и `"NAME"` попали в поля `id` и `name` |
| 3 | битый JSON (нет запятой после пары ключ-значение): ошибка, каталог пуст |
| 4 | тип не совпал: ошибка **и** `Stock: 40` всё равно заполнено (поэтому `loadProducts` при ошибке возвращает `nil`) |
| 5 | `Note` пусто — ключа нет (`omitempty`); `Stock` равен нулю, но без `omitempty` — записано `"stock":0` |

Три правила: неизвестный ключ пропускается, отсутствующий ключ оставляет поле нулевым, регистр в имени ключа не различается. Ошибка — в двух случаях: битый JSON и несовпавший тип.

### Файла ещё нет

Когда bozor запускается впервые, `bozor.json` ещё нет. Какую ошибку вы ждёте? Удалим файл через `rm` (удаляет файл) и выполним `go run .`.
Команда удаляет копию во временной папке `bozor/`; `bozor.json` в вашей папке курса остаётся на месте:

```console
$ ./_video/run.sh final sh -c 'rm bozor.json && go run .'
xato: open bozor.json: no such file or directory
exit status 1
```

Это ошибка `os.ReadFile`: `open` — при открытии, файла нет (`no such file or directory`). `main` счёл это ошибкой и остановился, хотя на деле это **пустой каталог**. Такую ошибку
можно распознать через `errors.Is(err, os.ErrNotExist)` (`errors.Is` — GB-2.08): это тоже в задании.

## Decoder: читаем файл как поток

Пара `Encoder`, которая читает, — `Decoder`. Это другой вариант `loadProducts` (`_video/11-decoder/main.go`, изменённая часть функции):

```go
	f, err := os.Open(path)
	if err != nil {
		return nil, err
	}
	defer f.Close()
	var products []Product
	if err := json.NewDecoder(f).Decode(&products); err != nil {
		return nil, err
	}
```

| Строка | Код | Что делает |
|---|---|---|
| 1–4 | `f, err := os.Open(path)` и проверка | открывает файл, как в GB-3.01; при ошибке возвращается |
| 5 | `defer f.Close()` | **после** проверки `err` (GB-2.09): при ошибке `f` равен `nil`, закрывать нечего |
| 7 | `json.NewDecoder(f).Decode(&products)` | `NewDecoder` принимает `io.Reader`: `f` (`*os.File`) подходит; метод `Decode` полученного `Decoder` читает JSON из потока и записывает в `&products` |

`Decode` тоже принимает адрес — `&` снова нужен. Результат тот же, что раньше (`./_video/run.sh 11-decoder go run .` — те же две строки, что в `07-load`). `Decoder` пригодится в GB-4:
сервер так читает JSON из HTTP-запроса через `io.Reader`. Для этого урока хватает `ReadFile` + `Unmarshal`.

## Глубже (необязательно): encoding/json/v2

В Go 1.27 добавлен `encoding/json/v2`; а `encoding/json` теперь работает поверх него, и поведение прежнее ([Go 1.27 release notes](https://go.dev/doc/go1.27)).
В импорте даём v2 имя `jsonv2`, потому что у обоих пакетов имя `json`. Полная программа (`_video/12-v2/main.go`): в переменной `in` ключ `name` встречается **дважды**:

```go filename="_video/12-v2/main.go" showLineNumbers
package main

import (
	"encoding/json"
	jsonv2 "encoding/json/v2"
	"fmt"
)

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
}

func main() {
	in := []byte(`{"id":1,"name":"olma","name":"non"}`)
	var p Product
	err := json.Unmarshal(in, &p)
	fmt.Println("v1:", err, p.Name)
	err = jsonv2.Unmarshal(in, &p)
	fmt.Println("v2:", err)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `jsonv2 "encoding/json/v2"` | импортирует пакет v2 под именем `jsonv2` |
| 18 | `in := []byte(`…`)` | превращает текст JSON в байты; `name` дважды |
| 20–21 | `json.Unmarshal(in, &p)` | v1: печатает ошибку и `p.Name` |
| 22–23 | `jsonv2.Unmarshal(in, &p)` | v2: печатает только ошибку |

```console
$ ./_video/run.sh 12-v2 go run .
v1: <nil> non
v2: jsontext: duplicate object member name "name"
```

v1 без ошибки взял **последнее** значение: `non`, ошибка `nil`. v2 отказал: `jsontext` (текстовый пакет v2) говорит «duplicate» — дубликат ключа.

v2 отличается ещё в трёх местах. Я запустил их рядом, `v1` и `v2` (программы нет в папке курса; код короткий, он здесь):

```go
package main

import (
	"encoding/json"
	jsonv2 "encoding/json/v2"
	"fmt"
)

type P struct {
	ID    int64 `json:"id"`
	Stock int   `json:"stock,omitempty"`
}

type L struct {
	id int64
}

func main() {
	b, err := json.Marshal(P{ID: 2})
	fmt.Println("v1:", string(b), err)
	b, err = jsonv2.Marshal(P{ID: 2})
	fmt.Println("v2:", string(b), err)

	b, err = json.Marshal(L{id: 1})
	fmt.Println("v1:", string(b), err)
	b, err = jsonv2.Marshal(L{id: 1})
	fmt.Println("v2:", string(b), err)

	var p P
	err = json.Unmarshal([]byte(`{"ID":3}`), &p)
	fmt.Println("v1:", p.ID, err)
	p = P{}
	err = jsonv2.Unmarshal([]byte(`{"ID":3}`), &p)
	fmt.Println("v2:", p.ID, err)
}
```

```console
$ go run main.go
v1: {"id":2} <nil>
v2: {"id":2,"stock":0} <nil>
v1: {} <nil>
v2:  json: cannot marshal from Go main.L: Go struct has no exported fields
v1: 3 <nil>
v2: 0 <nil>
```

| Случай | v1 (`encoding/json`) | v2 (`encoding/json/v2`) |
|---|---|---|
| `omitempty` и `Stock: 0` | `stock` нет | `"stock":0` остаётся: v2 пропускает только пустые **JSON**-значения |
| структура без экспортируемых полей | тихое `{}` | ошибка: `Go struct has no exported fields` |
| ключ `"ID"`, тег `"id"` | `ID` заполнен (регистр не различается) | не заполнен (регистр различается) |

`go doc encoding/json` рекомендует v2 для нового кода; API v1 поддерживается, переходить не обязательно. Курс продолжает с `encoding/json`, который широко распространён в рабочем коде.

## Частые ошибки

Все они уже встречались на этой странице; здесь — коротко, с исправлением.

**1. «Поле с маленькой буквы тоже запишется или хотя бы даст ошибку».** Нет: `Marshal` тихо возвращает `{}` (см. раздел выше «Поле с маленькой буквы: `{}` без ошибки»).
И `go run`, и `go vet` молчат. Исправление: поле с заглавной буквы, имя в JSON — в теге: `` ID int64 `json:"id"` ``.

**2. Пробел после двоеточия в теге.** `` `json: "name"` `` — `json` не распознаёт его и берёт имя поля (`"Name"`); компилятор молчит, `go vet` находит:

```console
$ ./_video/run.sh 03b-probel go vet .
main.go:12:2: struct field tag `json: "name"` not compatible with reflect.StructTag.Get: bad syntax for struct tag value
```

Строка 12, столбец 2 — это поле; `bad syntax for struct tag value` — запись тега неверна. Исправление: без пробела, `` `json:"name"` ``.

**3. `Unmarshal` без `&`.** Компилятор молчит, программа останавливается с ошибкой:

```console
$ ./_video/run.sh 08-pointer go run .
xato: json: Unmarshal(non-pointer []main.Product)
exit status 1
```

`non-pointer` — второй аргумент не адрес. Исправление: `json.Unmarshal(data, &products)`. Заранее находит `go vet .` (`call of Unmarshal passes non-pointer as second argument`).

**4. `omitempty` на числе.** При `Stock: 0` ключ `stock` пропадает, и читающая программа не отличит ноль от неизвестного (см. раздел выше «Вопрос: а если поставить omitempty на число?»). Исправление: у числа оставьте тег `` `json:"stock"` ``.

**5. Вернуть ошибку битого файла без имени файла.** `json: cannot unmarshal string into Go struct field .0.price of type int64` не говорит, какой это файл. Исправление: оберните ошибку путём через `%w` (задание, шаг 2(b)).

## Проверьте себя

1. Что делает `json.Marshal` с полем с маленькой буквы и почему?

<details>
<summary>Ответ</summary>

Молча пропускает. Имя с маленькой буквы видно только в своём пакете, а `encoding/json` — другой пакет: такое поле он не видит. Ни ошибки, ни предупреждения `go vet`.

</details>

2. `json.Unmarshal(data, &products)`: зачем `&`?

<details>
<summary>Ответ</summary>

`Unmarshal` записывает результат в переменную `products` вызывающего; функция может записать в переменную только по её адресу (GB-2.04). Без `&` он вернёт ошибку `non-pointer`.

</details>

3. (Из GB-2.09.) В варианте `loadProducts` с `Decoder` почему `defer f.Close()` стоит после проверки `err` от `os.Open`?

<details>
<summary>Ответ</summary>

Если `os.Open` вернул ошибку, `f` равен `nil` и закрывать нечего. Сначала проверка, потом `defer`.

</details>

4. Предскажите результат: `json.Marshal(Product{ID: 2, Name: "non", Price: 400_000})`, где `Product` — с полем `Note` и всеми тегами (итоговый вариант). У `Stock` нет `omitempty`.

<details>
<summary>Ответ</summary>

`{"id":2,"name":"non","price":400000,"stock":0}`. `Note` пусто и есть `omitempty` — ключа нет. `Stock` равен нулю, но без `omitempty` — записывается `"stock":0`.
Это строка 5 программы «Правила Unmarshal» выше (я её запускал).
**Неверный вариант:** если вы написали, что `stock` нет, вы решили, что `omitempty` стоит и на `Stock`.

</details>

5. Почему `omitempty` не ставят на числа?

<details>
<summary>Ответ</summary>

Для `omitempty` ноль тоже «пустой»: при `Stock: 0` ключ `stock` пропадает. Программа, прочитавшая файл, не отличит «остаток ноль» от «остаток неизвестен».

</details>

6. Что напечатает `go run`, если тег записан как `` `json: "name"` `` (пробел после двоеточия), и какой инструмент это находит?

<details>
<summary>Ответ</summary>

`go run` молча запишет ключ `"Name"` (имя поля), ошибки нет. Находит это `go vet` (`bad syntax for struct tag value`).

</details>

<summary>Ответы: шаг 1 (теги) и шаг 2 (loadProducts)</summary>

**Шаг 1.** Тег на каждое поле, в `Status` без `omitempty`:

```go
type OrderItem struct {
	ProductID int64 `json:"product_id"`
	Price     int64 `json:"price"` // tiyin, buyurtma paytidagi narx
	Quantity  int   `json:"quantity"`
}

type Order struct {
	ID     int64       `json:"id"`
	Items  []OrderItem `json:"items"`
	Status OrderStatus `json:"status"`
}
```

Если поставить `omitempty` на `status`, `StatusNew` (0) не запишется: это тот же вопрос про `stock`, что был в уроке.

**Шаг 2.** `loadProducts`:

```go
func loadProducts(path string) ([]Product, error) {
	data, err := os.ReadFile(path)
	if errors.Is(err, os.ErrNotExist) {
		return nil, nil
	}
	if err != nil {
		return nil, err
	}
	var products []Product
	if err := json.Unmarshal(data, &products); err != nil {
		return nil, fmt.Errorf("%s: %w", path, err)
	}
	return products, nil
}
```

(a) `errors.Is(err, os.ErrNotExist)` распознаёт ошибку «файла нет»; эта проверка обязана стоять **до** `if err != nil`, иначе «файла нет» тоже вернётся как обычная ошибка.
Если файла нет — `nil, nil`: пустой каталог и нет ошибки. (b) `fmt.Errorf("%s: %w", path, err)` добавляет путь в текст ошибки, а `%w` сохраняет исходную ошибку JSON в цепочке (GB-2.08);
если написать `%v`, цепочка рвётся, и тест скажет «исходной ошибки JSON нет». Проверка (мой запуск):

```console

```

</details>
