## Nimani oʻrganasiz

SQL'da ustun nomi xato. `go build` va `go vet` oʻtdi. Nega dastur faqat bazaga soʻrov yuborganda yiqiladi?

**Bitta gʻoya:** SQL'ni siz yozasiz; **sqlc** sxema va soʻrovlarni oʻqib, tekshirilgan soʻrovlar uchun oddiy Go kodini yaratadi.
Shu sozlamada bazaga ulanmaydi. Yoʻq ustun xatosi `sqlc generate` paytida chiqadi; bajarilishdagi xatolarni baribir tekshirasiz.

Darsdan keyin siz:

- `query.sql` izohlari va `sqlc.yaml` sozlamasini yozasiz;
- `db/` ichidagi turlar, `QueryRow`, `Scan` va qatorlar siklini oʻqiysiz;
- `Store.Get`, `ListActive` va `PlaceOrder`ni yaratilgan metodlar orqali ishlatasiz;
- eski `db/`, unutilgan generate va hisoblangan tur xatolarini farqlaysiz.

```go filename="_video/stages/01-store-qolda.go" showLineNumbers
package main

import (
	"context"
	"errors"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

// Videoning boshidagi holat: GB-5.05'dagi qoʻlda yozilgan Get, ustun nomida xato bilan (stock → qoldiq).
type Product struct {
	ID    int64
	Name  string
	Price int64
	Stock int
}

var ErrNotFound = errors.New("mahsulot topilmadi")

type Store struct {
	pool *pgxpool.Pool
}

func (s *Store) Get(ctx context.Context, id int64) (Product, error) {
	var p Product
	err := s.pool.QueryRow(ctx,
		"SELECT id, name, price, qoldiq FROM products WHERE id = $1", id).
		Scan(&p.ID, &p.Name, &p.Price, &p.Stock)
	if errors.Is(err, pgx.ErrNoRows) {
		return Product{}, ErrNotFound
	}
	return p, err
}
```

```go filename="_video/stages/01-main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"os"
	"time"

	"github.com/jackc/pgx/v5/pgxpool"
)

func main() {
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
	if err != nil {
		fmt.Fprintln(os.Stderr, "pool:", err)
		os.Exit(1)
	}
	defer pool.Close()

	store := &Store{pool: pool}
	qctx, cancel := context.WithTimeout(ctx, 5*time.Second)
	defer cancel()

	p, err := store.Get(qctx, 1)
	fmt.Println(p, err)
}
```

## query.sql va sqlc.yaml

Har soʻrov uchun bir xil `QueryRow` va `Scan`ni yozishni asbobga beramiz. `sqlc generate` shu takroriy Go kodini yaratadi.
Avval asbobni oʻrnating. `cmd/sqlc` — buyruq paketi, `@v1.31.1` — tanlangan versiya.
Go bin papkasi `PATH`da boʻlishi kerak, GB-3.03 dagidek:

```console
$ go install github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1
$ sqlc version
v1.31.1
```

Oʻrnatish bizda hech narsa chiqarmadi. Videoning tadqiqotida sovuq oʻrnatish taxminan toʻrt daqiqa, qayta oʻrnatishimiz kesh bilan uch soniya oldi.
Bular tezlik taqqoslash uchun teng sharoit emas. C kompilyatori kerak boʻlmadi: `CGO_ENABLED=0` bilan sqlc parser'ning WebAssembly variantini ishlatadi.
Bu oldindan yigʻilgan parser kodi; PostgreSQL serverini ishga tushirmaydi.

Hozircha `query.sql`ga faqat ikkita soʻrov qoʻyamiz (`_video/stages/02-query.sql`):

```sql filename="_video/stages/02-query.sql" showLineNumbers
-- name: GetProduct :one
SELECT id, name, price, stock FROM products
WHERE id = $1;

-- name: ListActiveProducts :many
SELECT id, name, price, stock FROM products
WHERE active
ORDER BY id;
```

```bash
cp _video/stages/02-query.sql query.sql
```

`--` SQL izohini boshlaydi. **Soʻrov annotatsiyasi** `name:` orqali Go metodiga nom beradi; `:one` bitta qiymat va xato qaytaradi.
`GetProduct` `id = $1` boʻyicha qidiradi. `$1` qiymati alohida argument sifatida keladi.
`:many` slice va xato qaytaradi. `ListActiveProducts` faqat faol qatorlarni ID tartibida oladi.
Qator qaytarmaydigan buyruq uchun `:exec` faqat xato qaytaradi; transaction qismida ishlatamiz.

`sqlc.yaml`ning toʻliq matni:

```yaml filename="sqlc.yaml" showLineNumbers
version: "2"
sql:
  - engine: postgresql
    schema: migrations
    queries: query.sql
    gen:
      go:
        package: db
        out: db
        sql_package: pgx/v5
```

| Qator | Maʼnosi |
|---|---|
| 1 | `version: "2"` — sqlc versiyasi emas, sozlama formati; qoʻshtirnoq uni matn qiladi. |
| 2–3 | `sql` — roʻyxat; `-` bitta element; `engine` SQL sintaksisini Postgres deb tanlaydi. |
| 4 | `schema` jadvallar tuzilmasini `migrations/`dan oladi; goose `Down` qismini tashlaydi. |
| 5 | `queries` — soʻrovlar manbasi. |
| 6–7 | `gen.go` Go kodi yaratilishini belgilaydi. |
| 8 | `package` — hosil boʻladigan paket nomi. |
| 9 | `out` — fayllar yoziladigan papka. |
| 10 | `sql_package: pgx/v5` pgx v5 API'sini tanlaydi. |

Fayllar nom boʻyicha oʻqiladi; `00001_…` tartibi shu sabab muhim. sqlc migratsiyalarni bazaga qoʻllamaydi: bu goose'ning ishi.

| Oldin | Amal | Keyin |
|---|---|---|
| `migrations/` + `query.sql` | `sqlc generate` | `db/*.go` yaratiladi |
| Go dasturi + `db/*.go` | `go run .` | SQL pgx orqali Postgres'ga yuboriladi |

Muvaffaqiyatli generate nima chiqaradi? **A)** hech narsa · **B)** fayllar roʻyxati · **C)** `OK` va soʻrovlar soni.

## db.go va query.sql.go: oddiy Go

```go filename="db/db.go" showLineNumbers
// Code generated by sqlc. DO NOT EDIT.
// versions:
//   sqlc v1.31.1

package db

import (
	"context"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgconn"
)

type DBTX interface {
	Exec(context.Context, string, ...interface{}) (pgconn.CommandTag, error)
	Query(context.Context, string, ...interface{}) (pgx.Rows, error)
	QueryRow(context.Context, string, ...interface{}) pgx.Row
}

func New(db DBTX) *Queries {
	return &Queries{db: db}
}

type Queries struct {
	db DBTX
}

func (q *Queries) WithTx(tx pgx.Tx) *Queries {
	return &Queries{
		db: tx,
	}
}
```

1–3 fayl belgisi; 5 paket; 7–12 importlar. 14–18 `DBTX` interface'i uch metod talab qiladi.
`Exec` `pgconn.CommandTag` va xato; `Query` `pgx.Rows` va xato; `QueryRow` `pgx.Row` qaytaradi.
Parametr nomlari interface'da shart emas. `...interface{}` — `...any`: istalgan sondagi argument.
20–22 `New` berilgan DBTX'ni yangi `Queries`ga joylaydi; `&` uning manzilini qaytaradi. 24–26 `Queries.db` shu DBTX'ni saqlaydi.
28–32 `WithTx` yangi `Queries` yaratib, uning `db` maydoniga `tx`ni qoʻyadi.
Pool ham, `pgx.Tx` ham uch metodga ega; ikkalasi ham shu interface'ni qanoatlantiradi.

Endi `db/query.sql.go`dan ikkita toʻliq parcha. Bular butun fayl emas:

```go
const getProduct = `-- name: GetProduct :one
SELECT id, name, price, stock FROM products
WHERE id = $1
`

type GetProductRow struct {
	ID    int64
	Name  string
	Price int64
	Stock int32
}

func (q *Queries) GetProduct(ctx context.Context, id int64) (GetProductRow, error) {
	row := q.db.QueryRow(ctx, getProduct, id)
	var i GetProductRow
	err := row.Scan(
		&i.ID,
		&i.Name,
		&i.Price,
		&i.Stock,
	)
	return i, err
}
```

```go
const listActiveProducts = `-- name: ListActiveProducts :many
SELECT id, name, price, stock FROM products
WHERE active
ORDER BY id
`

type ListActiveProductsRow struct {
	ID    int64
	Name  string
	Price int64
	Stock int32
}

func (q *Queries) ListActiveProducts(ctx context.Context) ([]ListActiveProductsRow, error) {
	rows, err := q.db.Query(ctx, listActiveProducts)
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	var items []ListActiveProductsRow
	for rows.Next() {
		var i ListActiveProductsRow
		if err := rows.Scan(
			&i.ID,
			&i.Name,
			&i.Price,
			&i.Stock,
		); err != nil {
			return nil, err
		}
		items = append(items, i)
	}
	if err := rows.Err(); err != nil {
		return nil, err
	}
	return items, nil
}
```

`GetProduct` parchasida 1–4 `const` va backtick ichidagi raw string: SQL nuqta-vergulsiz saqlanadi.
6–11 `GetProductRow`: tanlangan toʻrtta ustun. `active` tanlanmagani uchun bu `db.Product` emas.
13 metod imzosi: `id int64` turi `WHERE id = $1`dan kelgan. 14 `QueryRow`; 15 natija uchun `i` oʻzgaruvchisi.
16–21 `Scan` manzillarni SELECT tartibida oladi; koʻp qatorli argumentlar oxirida vergul bor. 22 natija va xato, 23 yopuvchi qavs.

`ListActiveProducts` parchasida 1–5 soʻrov, 7–12 natija struct'i, 14 metod imzosi.
15–18 `Query` va xato tekshiruvi; 19 `defer rows.Close`; 20 `var items` dastlab `nil`.
21–32 sikl: yangi `i`, toʻrtta `Scan` manzili, xatoda qaytish, `append`.
33–35 oxirgi `rows.Err()` tekshiruvi; 36–37 natijani qaytarish va yopish.
Qator boʻlmasa, sikl ishlamaydi va `items` `nil` qoladi. Yaratilgan kod ham oddiy pgx: xatolar yoʻqolmaydi.

```go filename="_video/stages/02-store-get.go" showLineNumbers
// Product — products jadvalidagi bitta qator (narx tiyinda, GB-1.03).
type Product struct {
	ID    int64
	Name  string
	Price int64
	Stock int
}

// ErrNotFound — jadvalda bunday mahsulot yoʻq (GB-2.08: chaqiruvchi errors.Is bilan tekshiradi).
var ErrNotFound = errors.New("mahsulot topilmadi")

// Store — bozor jadvallariga Go'dan kirish. pool — transaction ochish uchun (Begin),
// q — sqlc query.sql'dan generatsiya qilgan soʻrovlar (db papkasi).
type Store struct {
	pool *pgxpool.Pool
	q    *db.Queries
}

// NewStore pool ustida Store yaratadi: db.New pool'ni sqlc soʻrovlariga ulaydi.
func NewStore(pool *pgxpool.Pool) *Store {
	return &Store{pool: pool, q: db.New(pool)}
}

// Get id boʻyicha bitta mahsulotni oʻqiydi; yoʻq boʻlsa ErrNotFound.
func (s *Store) Get(ctx context.Context, id int64) (Product, error) {
	r, err := s.q.GetProduct(ctx, id)
	if errors.Is(err, pgx.ErrNoRows) {
		return Product{}, ErrNotFound
	}
	if err != nil {
		return Product{}, err
	}
	return Product{ID: r.ID, Name: r.Name, Price: r.Price, Stock: int(r.Stock)}, nil
}

// ListActive faol mahsulotlarni id tartibida oʻqiydi. Mahsulot yoʻq boʻlsa boʻsh (nil emas) slice qaytaradi.
func (s *Store) ListActive(ctx context.Context) ([]Product, error) {
	rows, err := s.q.ListActiveProducts(ctx)
	if err != nil {
		return nil, err
	}
	out := make([]Product, 0, len(rows))
	for _, r := range rows {
		out = append(out, Product{ID: r.ID, Name: r.Name, Price: r.Price, Stock: int(r.Stock)})
	}
	return out, nil
}
```

```go
// ErrNotEnoughStock — omborda yetarli qoldiq yoʻq: baza CHECK (stock >= 0) bilan rad etdi (GB-5.07).
var ErrNotEnoughStock = errors.New("qoldiq yetarli emas")

// ErrInvalidQuantity — miqdor noldan katta boʻlishi va integer ustuniga (int32) sigʻishi kerak.
var ErrInvalidQuantity = errors.New("miqdor notoʻgʻri: 1 dan 2147483647 gacha boʻlishi kerak")

// OrderItem — buyurtmadagi bitta qator: qaysi mahsulot va nechta.
type OrderItem struct {
```

```go
func (s *Store) PlaceOrder(ctx context.Context, customer string, items []OrderItem) (int64, error) {
	for _, it := range items {
		if it.Quantity <= 0 || it.Quantity > math.MaxInt32 {
			return 0, ErrInvalidQuantity
		}
	}
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return 0, err
	}
	defer tx.Rollback(ctx)
	qtx := s.q.WithTx(tx)

	orderID, err := qtx.CreateOrder(ctx, customer)
	if err != nil {
		return 0, err
	}
	for _, it := range items {
		var price int64
		price, err = qtx.DecrementStock(ctx, db.DecrementStockParams{
			Quantity: int32(it.Quantity),
			ID:       it.ProductID,
		})
		if errors.Is(err, pgx.ErrNoRows) {
			return 0, ErrNotFound
		}
		var pgErr *pgconn.PgError
		if errors.As(err, &pgErr) && pgErr.Code == "23514" { // 23514 = check_violation: CHECK (stock >= 0) buzildi
			return 0, ErrNotEnoughStock
		}
		if err != nil {
			return 0, err
		}
		err = qtx.AddOrderItem(ctx, db.AddOrderItemParams{
			OrderID:   orderID,
			ProductID: it.ProductID,
			Quantity:  int32(it.Quantity),
			UnitPrice: price,
		})
		if err != nil {
			return 0, err
		}
	}
	if err := tx.Commit(ctx); err != nil {
		return 0, err
	}
	return orderID, nil
}
```

## Chuqurroq (ixtiyoriy): db/ va SQL doim birga

`db/` odatda git'ga commit qilinadi. Dastur qurilishi uchun sqlc oʻrnatilgan boʻlishi shart emas; Go fayllar yetadi.
`sqlc diff` qayta yaratilishi kerak boʻlgan fayllarni mavjud fayllar bilan solishtiradi.
Toza boshlangʻich nusxada:

```console
$ sqlc diff
```

Chiqish yoʻq, exit `0`. SQL'ga yangi soʻrov qoʻshib, generate qilmaganimizda diff koʻrsatdi va exit `1` qaytdi.
Farq matni fayl tarkibiga bogʻliq; bu yerda takrorlanmadi. Avtomatik tekshiruvga shu qoida qoʻshilishi GB-8.05 da ochiladi.

Hisoblangan ustunlarning turi esa sqlc taxmini. Uch variantni alohida nusxada qayta generatsiya qildik:

| OrderTotal ifodasi | sqlc v1.31.1 natijasi | Chegara |
|---|---|---|
| `COALESCE(SUM(quantity * unit_price), 0)` | `interface{}` | `int64` kutgan Go metodiga mos emas |
| `SUM(quantity * unit_price) AS total` | `int64` | qator boʻlmasa Postgres `NULL` beradi |
| `COALESCE(SUM(quantity * unit_price), 0)::bigint AS total` | `int64` | boʻsh natija `0`, tur SQL'da aniq |

Postgres `SUM(bigint)` uchun `numeric` beradi. `COALESCE` birinchi `NULL` boʻlmagan qiymatni tanlaydi.
`::bigint` SQL tur oʻzgartirishi; `AS total` natija ustunining nomi. sqlc imzosini oʻqish va haqiqiy bazada test qilish baribir kerak.
Bu sahifadagi sozlama bazasiz tekshiradi; sqlc boshqa sozlamalarda baza bilan tahlil qilishni ham qoʻllaydi.

**5.** `WithTx`dan keyin `s.q.db` oʻzgardimi? Commitni kim qiladi?

<details>
<summary>Javob</summary>

Yoʻq. Yangi `qtx.db = tx`; eski `s.q.db = pool`. Commitni `Store` chaqiradi.

</details>


<details>
<summary>Javob</summary>

`ByName` `Get` kabi `ErrNoRows`ni aylantiradi va `Row → Product` qiladi.
`Cheapest` faol mahsulotlarni `ORDER BY price, id LIMIT $1` bilan oladi. `LIMIT` parametri sqlc'da `int32`.
`n < 0` yoki `n > math.MaxInt32` boʻlsa avval xato qaytaring; manfiy `LIMIT` Postgres'da mumkin emas.
Natijani `make([]Product, 0, len(rows))`ga yigʻing. `Stock: int(r.Stock)`ni unutmang.
`OrderTotal` uchun quyidagi soʻrov, keyin `return s.q.OrderTotal(ctx, orderID)` yetadi:

```sql
-- name: OrderTotal :one
SELECT COALESCE(SUM(quantity * unit_price), 0)::bigint AS total
FROM order_items
WHERE order_id = $1;
```

🟡 `UPDATE products SET stock = stock + @quantity WHERE id = @id`ga `AddStock :execrows` annotatsiyasini bering.
`qtx.AddStock` xatosini tekshiring, son `0` boʻlsa `ErrNotFound`; aks holda oxirida commit.
`go test -run Restock -v` ikkala tekshiruvni ham bajaradi. Starter'da faqat ixtiyoriy koʻchirish tekshiruvi SKIP, `Restock` xatti-harakati tekshiriladi.

</details>

Ish tugagach nusxangizda `docker compose down -v`: konteyner va shu laboratoriyaning volume'ini oʻchiradi.
