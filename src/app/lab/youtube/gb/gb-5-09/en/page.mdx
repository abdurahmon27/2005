## What you will learn

A column name in SQL is wrong. `go build` and `go vet` passed. Why does the program fail only when it queries the database?

**One idea:** you write SQL; **sqlc** reads the schema and queries, then creates ordinary Go code for the checked queries.
With this configuration it does not connect to the database. An unknown column produces an error during `sqlc generate`; runtime errors still need handling.

After this lesson you will:

- write the annotations in `query.sql` and the `sqlc.yaml` configuration;
- read the types, `QueryRow`, `Scan`, and row loop in `db/`;
- move `Store.Get`, `ListActive`, and `PlaceOrder` to generated methods;
- distinguish stale `db/` files, forgotten generation, and expression type errors.

| Term | Plain meaning | English term |
|---|---|---|
| query annotation | the Go method name and result shape in an SQL comment | query annotation |
| generated code | Go files sqlc writes from SQL and the schema | generated code |
| generation-time error | an error found while checking SQL before the program runs | generation-time error |

```go filename="_video/stages/01-store-qolda.go" showLineNumbers
package main

import (
	"context"
	"errors"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

// Videoning boshidagi holat: GB-5.05'dagi qoʻlda yozilgan Get, ustun nomida xato bilan (stock → qoldiq).
type Product struct {
	ID    int64
	Name  string
	Price int64
	Stock int
}

var ErrNotFound = errors.New("mahsulot topilmadi")

type Store struct {
	pool *pgxpool.Pool
}

func (s *Store) Get(ctx context.Context, id int64) (Product, error) {
	var p Product
	err := s.pool.QueryRow(ctx,
		"SELECT id, name, price, qoldiq FROM products WHERE id = $1", id).
		Scan(&p.ID, &p.Name, &p.Price, &p.Stock)
	if errors.Is(err, pgx.ErrNoRows) {
		return Product{}, ErrNotFound
	}
	return p, err
}
```

Which command finds the error? **A)** `go build` · **B)** `go vet .` · **C)** `go run .`.

<details>
<summary>Answer</summary>

**C.** SQL is an ordinary string to the Go compiler. `go vet` does not know this table either. A and B assume SQL schema validation.

</details>

```console
$ go build
$ go vet .
$ go run .
{0  0 0} ERROR: column "qoldiq" does not exist (SQLSTATE 42703)
```

The first two commands printed nothing and exited with `0`. `column … does not exist` means the named column is absent.
`42703` is the Postgres `undefined_column` code. `Scan` wrote no values, so the empty `Product` was printed.
The program only prints the error, so `go run` also exited with `0`: a successful exit does not guarantee a successful query.
Fix: replace `qoldiq` with `stock` in SQL.

## query.sql and sqlc.yaml

We can let a tool write the repeated `QueryRow` and `Scan` for each query. `sqlc generate` creates this repeated Go code.
Install the tool first. `cmd/sqlc` is the command package; `@v1.31.1` selects its version.
The Go bin folder must be in `PATH`, as in GB-3.03:

```console
$ go install github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1
$ sqlc version
v1.31.1
```

Installation printed nothing here. The video research records about four minutes for a cold install; our cached reinstall took three seconds.
Those conditions do not support a speed comparison. No C compiler was needed: with `CGO_ENABLED=0`, sqlc uses the WebAssembly parser variant.
This is precompiled parser code; it does not start a PostgreSQL server.

For now, put only two queries in `query.sql` (`_video/stages/02-query.sql`):

```sql filename="_video/stages/02-query.sql" showLineNumbers
-- name: GetProduct :one
SELECT id, name, price, stock FROM products
WHERE id = $1;

-- name: ListActiveProducts :many
SELECT id, name, price, stock FROM products
WHERE active
ORDER BY id;
```

```bash
cp _video/stages/02-query.sql query.sql
```

`--` starts an SQL comment. A **query annotation** uses `name:` to name the Go method; `:one` returns one value and an error.
`GetProduct` searches by `id = $1`. The value of `$1` arrives as a separate argument.
`:many` returns a slice and an error. `ListActiveProducts` fetches active rows ordered by ID.
For commands returning no rows, `:exec` returns only an error; we will use it in the transaction.

The complete `sqlc.yaml`:

```yaml filename="sqlc.yaml" showLineNumbers
version: "2"
sql:
  - engine: postgresql
    schema: migrations
    queries: query.sql
    gen:
      go:
        package: db
        out: db
        sql_package: pgx/v5
```

| Line | Meaning |
|---|---|
| 1 | `version: "2"` is the configuration format, not the sqlc version; quotes make it a string. |
| 2–3 | `sql` is a list; `-` introduces one element; `engine` selects Postgres syntax. |
| 4 | `schema` reads table definitions from `migrations/`, skipping goose `Down` sections. |
| 5 | `queries` is the query source. |
| 6–7 | `gen.go` selects Go code generation. |
| 8 | `package` names the generated package. |
| 9 | `out` is the output folder. |
| 10 | `sql_package: pgx/v5` selects the pgx v5 API. |

Files are read by name; this is why the `00001_…` ordering matters. sqlc does not apply migrations to the database: goose does.

| Before | Action | After |
|---|---|---|
| `migrations/` + `query.sql` | `sqlc generate` | `db/*.go` created |
| Go program + `db/*.go` | `go run .` | SQL sent through pgx to Postgres |

## db.go and query.sql.go: ordinary Go

```go filename="db/db.go" showLineNumbers
// Code generated by sqlc. DO NOT EDIT.
// versions:
//   sqlc v1.31.1

package db

import (
	"context"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgconn"
)

type DBTX interface {
	Exec(context.Context, string, ...interface{}) (pgconn.CommandTag, error)
	Query(context.Context, string, ...interface{}) (pgx.Rows, error)
	QueryRow(context.Context, string, ...interface{}) pgx.Row
}

func New(db DBTX) *Queries {
	return &Queries{db: db}
}

type Queries struct {
	db DBTX
}

func (q *Queries) WithTx(tx pgx.Tx) *Queries {
	return &Queries{
		db: tx,
	}
}
```

1–3 mark the file; 5 declares the package; 7–12 are imports. 14–18 define the three methods required by `DBTX`.
`Exec` returns `pgconn.CommandTag` and an error; `Query` returns `pgx.Rows` and an error; `QueryRow` returns `pgx.Row`.
Interface parameters need no names. `...interface{}` means `...any`: any number of arguments.
20–22 put the supplied DBTX into a new `Queries`; `&` returns its address. 24–26 store that DBTX in `Queries.db`.
28–32 create a new `Queries` with `tx` in its `db` field.
Both the pool and `pgx.Tx` have those three methods, so both satisfy this interface.

Now two complete fragments from `db/query.sql.go`. These are not the whole file:

```go
const getProduct = `-- name: GetProduct :one
SELECT id, name, price, stock FROM products
WHERE id = $1
`

type GetProductRow struct {
	ID    int64
	Name  string
	Price int64
	Stock int32
}

func (q *Queries) GetProduct(ctx context.Context, id int64) (GetProductRow, error) {
	row := q.db.QueryRow(ctx, getProduct, id)
	var i GetProductRow
	err := row.Scan(
		&i.ID,
		&i.Name,
		&i.Price,
		&i.Stock,
	)
	return i, err
}
```

```go
const listActiveProducts = `-- name: ListActiveProducts :many
SELECT id, name, price, stock FROM products
WHERE active
ORDER BY id
`

type ListActiveProductsRow struct {
	ID    int64
	Name  string
	Price int64
	Stock int32
}

func (q *Queries) ListActiveProducts(ctx context.Context) ([]ListActiveProductsRow, error) {
	rows, err := q.db.Query(ctx, listActiveProducts)
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	var items []ListActiveProductsRow
	for rows.Next() {
		var i ListActiveProductsRow
		if err := rows.Scan(
			&i.ID,
			&i.Name,
			&i.Price,
			&i.Stock,
		); err != nil {
			return nil, err
		}
		items = append(items, i)
	}
	if err := rows.Err(); err != nil {
		return nil, err
	}
	return items, nil
}
```

In the `GetProduct` fragment, 1–4 are a `const` and a backtick raw string: SQL is stored without the semicolon.
6–11 define `GetProductRow` for the four selected columns. Because `active` is omitted, this is not `db.Product`.
13 is the method signature: `id int64` comes from `WHERE id = $1`. 14 calls `QueryRow`; 15 declares result variable `i`.
16–21 scan addresses in SELECT order; multiline arguments have trailing commas. 22 returns the result and error; 23 closes the method.

In the `ListActiveProducts` fragment: 1–5 query, 7–12 result struct, 14 signature.
15–18 call `Query` and check its error; 19 defers `rows.Close`; 20 declares initially `nil` `items`.
21–32 loop: new `i`, four `Scan` addresses, error return, and `append`.
33–35 check `rows.Err()` at the end; 36–37 return the result and close.
With no rows, the loop never runs and `items` stays `nil`. Generated code is ordinary pgx: errors still exist.

```go filename="_video/stages/02-store-get.go" showLineNumbers
// Video bosqichi: Get va ListActive sqlc orqali (query.sql: 02-query.sql).
package main

import (
	"context"
	"errors"

	"github.com/abdurahmon27/bozor/db"
	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

// Product — products jadvalidagi bitta qator (narx tiyinda, GB-1.03).
type Product struct {
	ID    int64
	Name  string
	Price int64
	Stock int
}

// ErrNotFound — jadvalda bunday mahsulot yoʻq (GB-2.08: chaqiruvchi errors.Is bilan tekshiradi).
var ErrNotFound = errors.New("mahsulot topilmadi")

// Store — bozor jadvallariga Go'dan kirish. pool — transaction ochish uchun (Begin),
// q — sqlc query.sql'dan generatsiya qilgan soʻrovlar (db papkasi).
type Store struct {
	pool *pgxpool.Pool
	q    *db.Queries
}

// NewStore pool ustida Store yaratadi: db.New pool'ni sqlc soʻrovlariga ulaydi.
func NewStore(pool *pgxpool.Pool) *Store {
	return &Store{pool: pool, q: db.New(pool)}
}

// Get id boʻyicha bitta mahsulotni oʻqiydi; yoʻq boʻlsa ErrNotFound.
func (s *Store) Get(ctx context.Context, id int64) (Product, error) {
	r, err := s.q.GetProduct(ctx, id)
	if errors.Is(err, pgx.ErrNoRows) {
		return Product{}, ErrNotFound
	}
	if err != nil {
		return Product{}, err
	}
	return Product{ID: r.ID, Name: r.Name, Price: r.Price, Stock: int(r.Stock)}, nil
}

// ListActive faol mahsulotlarni id tartibida oʻqiydi. Mahsulot yoʻq boʻlsa boʻsh (nil emas) slice qaytaradi.
func (s *Store) ListActive(ctx context.Context) ([]Product, error) {
	rows, err := s.q.ListActiveProducts(ctx)
	if err != nil {
		return nil, err
	}
	out := make([]Product, 0, len(rows))
	for _, r := range rows {
		out = append(out, Product{ID: r.ID, Name: r.Name, Price: r.Price, Stock: int(r.Stock)})
	}
	return out, nil
}
```

## Parameter names and WithTx

The transaction retains the previous three SQL queries. The initial version (`_video/stages/03-query-dollar.sql`) is:

`CreateOrder` has `RETURNING id`, hence `:one`; `DecrementStock` returns price, so it also uses `:one`.

With this configuration sqlc creates a `Params` struct for multiple parameters. It infers names from columns.
What field name represents `$1` in `stock = stock - $1`? **A)** `Quantity` · **B)** `Stock` · **C)** `Column1`.

<details>

**B.** Regeneration produced `Stock int32`, `ID int64`. A is our intended meaning but is unwritten; C is not the observed result here.

// ErrNotEnoughStock — omborda yetarli qoldiq yoʻq: baza CHECK (stock >= 0) bilan rad etdi (GB-5.07).
var ErrNotEnoughStock = errors.New("qoldiq yetarli emas")

// ErrInvalidQuantity — miqdor noldan katta boʻlishi va integer ustuniga (int32) sigʻishi kerak.
var ErrInvalidQuantity = errors.New("miqdor notoʻgʻri: 1 dan 2147483647 gacha boʻlishi kerak")

// OrderItem — buyurtmadagi bitta qator: qaysi mahsulot va nechta.
type OrderItem struct {

```go
func (s *Store) PlaceOrder(ctx context.Context, customer string, items []OrderItem) (int64, error) {
	for _, it := range items {
		if it.Quantity <= 0 || it.Quantity > math.MaxInt32 {
			return 0, ErrInvalidQuantity
		}
	}
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return 0, err
	}
	defer tx.Rollback(ctx)
	qtx := s.q.WithTx(tx)

	orderID, err := qtx.CreateOrder(ctx, customer)
	if err != nil {
		return 0, err
	}
	for _, it := range items {
		var price int64
		price, err = qtx.DecrementStock(ctx, db.DecrementStockParams{
			Quantity: int32(it.Quantity),
			ID:       it.ProductID,
		})
		if errors.Is(err, pgx.ErrNoRows) {
			return 0, ErrNotFound
		}
		var pgErr *pgconn.PgError
		if errors.As(err, &pgErr) && pgErr.Code == "23514" { // 23514 = check_violation: CHECK (stock >= 0) buzildi
			return 0, ErrNotEnoughStock
		}
		if err != nil {
			return 0, err
		}
		err = qtx.AddOrderItem(ctx, db.AddOrderItemParams{
			OrderID:   orderID,
			ProductID: it.ProductID,
			Quantity:  int32(it.Quantity),
			UnitPrice: price,
		})
		if err != nil {
			return 0, err
		}
	}
	if err := tx.Commit(ctx); err != nil {
		return 0, err
	}
	return orderID, nil
}
```

Declarations: two error values; `OrderItem` holds a product ID and quantity. `math.MaxInt32` is `2147483647`.
The `store.go` imports add `math` and `github.com/jackc/pgx/v5/pgconn`.

| Method lines | Change and purpose |
|---|---|
| 1–6 | Quantity must be positive and fit `int32`; otherwise return an error before opening a transaction. `\|\|` means “or”. |
| 7–11 | `Begin`, error check, `defer Rollback`: the GB-5.07 rule. |
| 12 | `qtx := s.q.WithTx(tx)` makes a new `Queries` whose executor is `tx`. |
| 14–17 | `CreateOrder` returns the ID; return on error. |
| 18–23 | `range items`, declare `price`; pass checked `int32` quantity and product ID in `DecrementStockParams`. |
| 24–26 | Map `ErrNoRows` to `ErrNotFound`. |
| 27–30 | `errors.As` extracts `*pgconn.PgError`; `23514` (`check_violation`) means the stock CHECK failed. |
| 31–33 | Return another error. |
| 34–42 | Write order ID, product, quantity, and current price through `AddOrderItemParams`; check the error. |
| 43–48 | Close the loop, check the `Commit` error, return the ID and `nil`. |

`price, err =` assigns to the existing `err`, avoiding an inner shadow variable.
`WithTx` neither begins nor commits the transaction; those operations remain in `Store`.

| State | `s.q.db` | `qtx.db` | Database |
|---|---|---|---|
| before `Begin` | pool | absent | no transaction |
| after `WithTx(tx)` | pool | tx | open transaction |
| `qtx.CreateOrder` and the others | pool | tx | uncommitted changes |
| after `Commit` | pool | finished tx | changes committed |

Calling `s.q` inside the transaction can send a query through the pool on another connection. All three operations must use `qtx`.

`db/` is commonly committed to git. Building the program does not require sqlc to be installed; the Go files suffice.

Computed column types are sqlc's inference. We regenerated three variants in a separate copy:

| OrderTotal expression | sqlc v1.31.1 result | Limitation |
|---|---|---|
| `COALESCE(SUM(quantity * unit_price), 0)` | `interface{}` | incompatible with a Go method expecting `int64` |
| `SUM(quantity * unit_price) AS total` | `int64` | Postgres returns `NULL` with no input rows |
| `COALESCE(SUM(quantity * unit_price), 0)::bigint AS total` | `int64` | empty input gives `0`, SQL type is explicit |

Postgres returns `numeric` for `SUM(bigint)`. `COALESCE` selects the first non-`NULL` value.
`::bigint` converts the SQL type; `AS total` names the result column. You still need to read sqlc's signature and test with a real database.

## Common mistakes

**1. “Build passed, so the new SQL is valid.”** The `qoldiq` experiment above kept the old `db/` files.
Fix: correct the column, check generation's exit status, then run `sqlc diff`. The compiler catches forgotten generation when a new method is used.

**2. Editing `db/*.go` manually.** The next generation overwrites the change. Fix SQL or `sqlc.yaml`, then regenerate.

**3. Using the pool instead of the transaction.** `s.q` is bound to the pool. After `qtx := s.q.WithTx(tx)`, send all three queries through `qtx`.

**4. Not checking the SUM type.** In a solution copy, we removed `::bigint` from `OrderTotal`.
The new method returned `interface{}`, but `store.go` expected `int64`. Actual result:

```sql
-- name: OrderTotal :one
SELECT COALESCE(SUM(quantity * unit_price), 0) AS total
FROM order_items
WHERE order_id = $1;
```

```console
$ go vet .
# github.com/abdurahmon27/bozor
# [github.com/abdurahmon27/bozor]
vet: ./store.go:158:9: cannot use 1st function result (value of type interface{}) as int64 value in return statement: need type assertion
```

`store.go:158:9` locates the error in the solution file. `cannot use … as int64` means the result is incompatible with `int64`.
Here `go vet` did not understand SQL; it found a Go type error after generation.
Fix: `COALESCE(…)::bigint AS total`, then regenerate.

Removing `COALESCE` entirely is no solution either. This broken variant generated `int64`:

```sql
-- name: OrderTotal :one
SELECT SUM(quantity * unit_price) AS total
FROM order_items
WHERE order_id = $1;
```

```console
$ go test -run TestOrderTotal .
--- FAIL: TestOrderTotal (0.05s)
    store_test.go:262: OrderTotal(3): can't scan into dest[0] (col: total): cannot scan NULL into *int64
FAIL
FAIL	github.com/abdurahmon27/bozor	0.055s
FAIL
```

`store_test.go:262` is the assertion line. `cannot scan NULL into *int64` means `NULL` cannot be written into an `int64` destination.
Order `3` has no items. Fix: zero through `COALESCE`, an explicit type through `::bigint`.

**5. Converting quantity to `int32` without checking.** `int32(it.Quantity)` truncates an oversized number. Check `1 … math.MaxInt32` first.
**6. Always expecting an empty slice from `:many`.** This configuration may return `nil`. Use `make([]Product, 0, len(rows))` in the domain method.
Alternatively set `emit_empty_slices: true` under `gen.go`; regeneration creates `items := []T{}`.
