## Что вы узнаете

Функция `afterOrder` из проекта bozor должна только **показать**, сколько товара останется после заказа. Запустим её
(как запускать шаги, описано в следующем разделе):

```console
$ ./_video/run.sh 00-bug go run .
ombor oldin: [40 12 7]
koʻrish:     [38 11 7]
ombor keyin: [38 11 7]
```

Первая строка (`ombor oldin`, «склад до») — склад: яблоки 40, хлеб 12, чай 7. Вторая (`koʻrish`, «просмотр») — остаток,
который посчитала функция: вычтены 2 яблока и 1 хлеб. Третья строка (`ombor keyin`, «склад после») — настоящий склад, и он тоже стал `[38 11 7]`. Склад уменьшился, хотя заказ никто не
подтверждал. Функции никто не говорил менять склад. Почему она его изменила и как это исправить?

**Одна идея:** слайс — это **заголовок** из трёх полей (`ptr` — адрес массива, `len`, `cap`) и **массив** за ним.
`before := stock` и передача в функцию копируют только заголовок, массив остаётся один. `append` пишет в тот же массив,
если в нём есть место, а если места нет — создаёт новый массив и возвращает новый заголовок.

К концу урока вы:

- нарисуете устройство слайса в памяти: заголовок и его массив;
- скажете, что именно копируют `before := stock` и параметр функции, а что не копируют;
- будете знать, когда `append` пишет в тот же массив, когда создаёт новый и почему результат нужно обязательно
  записывать;
- исправите функцию, которая портит данные вызывающего кода, с помощью `make` и найдёте такую же ошибку сами
  (`discounted`, задание).

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| слайс | список элементов одного типа. В памяти он состоит из двух частей: заголовка (`ptr`, `len`, `cap`) и массива, где лежат элементы | slice, slice header, array |
| `append` | добавляет в слайс элемент и **возвращает новый заголовок**. Если в массиве есть место, пишет в тот же массив, если нет — создаёт новый | `append` |
| общий массив (алиасинг) | два слайса (или параметр и аргумент) смотрят на один массив: один записал — другой видит изменение | aliasing |

Две вспомогательные вещи: **`make([]int, n)`** — создаёт новый массив и возвращает слайс на него (в разделе об
исправлении); **`%p`** — шаблон `Printf`, который выводит адрес массива, на который смотрит слайс.

## Из чего состоит слайс: заголовок и массив

На складе bozor у каждого товара есть остаток: яблоки, хлеб, чай. Чтобы хранить эти три числа в одной переменной, в Go
есть **слайс**. Самая маленькая программа:

```go filename="_video/01-slice/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := []int{40, 12, 7} // olma, non, choy
	fmt.Println(stock, len(stock), cap(stock))
	fmt.Println(stock[0], stock[2])
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `package main` | файл в пакете `main`: `go run .` запускает именно его (GB-1.01) |
| 3 | `import "fmt"` | подключает пакет `fmt`, откуда `Println` и `Printf` (GB-1.01) |
| 5 | `func main() {` | программа начинается с этой функции (GB-1.01) |
| 6 | `stock := []int{40, 12, 7}` | переменная `stock`. `[]int` — тип: «слайс `int`». В фигурных скобках `40, 12, 7` — начальные элементы через запятую. Такая запись называется **литералом слайса**. Комментарий после `//`: яблоки, хлеб, чай |
| 7 | `fmt.Println(stock, len(stock), cap(stock))` | выводит `stock`, `len(stock)` (число элементов) и `cap(stock)` (**ёмкость**: сколько мест в массиве за слайсом) |
| 8 | `fmt.Println(stock[0], stock[2])` | индекс начинается с 0: `stock[0]` — яблоки, `stock[2]` — чай |

Вывод:

```console
$ ./_video/run.sh 01-slice go run .
[40 12 7] 3 3
40 7
```

`Println` печатает слайс в квадратных скобках, элементы через пробел. Затем `len` — 3 и `cap` — 3. Во второй строке
`40` и `7` — нулевой и второй элементы.

Почему `len` и `cap` — два числа? Это показывает картинка памяти. Переменная `stock` хранит не сам слайс, а его
**заголовок** (slice header). В заголовке три поля:

- `ptr` — адрес (address) в памяти, где лежит нулевой элемент. `ptr` — сокращение от pointer; указатели мы разберём в
  [GB-2.04](/lab/youtube/gb/gb-2-04/ru), пока достаточно понимать это как «адрес»;
- `len` — длина: сколько элементов в слайсе сейчас;
- `cap` — ёмкость: сколько мест от начала слайса до конца массива.

Сами элементы лежат не в заголовке, а в **массиве** за ним. Массив — это места, расположенные в памяти подряд, и их
число жёстко задано. Его тип — `[3]int`: длина входит в тип и не меняется ([Go spec: Array types](https://go.dev/ref/spec#Array_types)).

```text
stock ─► ┌─────┬─────┬─────┐
         │ ptr │ len │ cap │     заголовок (slice header)
         │  ●  │  3  │  3  │
         └──┬──┴─────┴─────┘
            │
            ▼
         ┌─────┬─────┬─────┐
         │ 40  │ 12  │  7  │     массив [3]int
         └─────┴─────┴─────┘
 индекс     0     1     2
```

Литерал `[]int{40, 12, 7}` сам создаёт массив, поэтому и `len`, и `cap` равны 3: в массиве ровно три места
([Go spec: Composite literals](https://go.dev/ref/spec#Composite_literals)). `cap` может быть больше `len`, если в
массиве остались свободные места. Это мы увидим в разделе об `append`.

## `before := stock`: копия берёт только заголовок

Пусть программе нужно запомнить состояние до изменения: отдадим переменной `before` значение `stock`, а затем запишем 38
в `stock[0]`.

```go filename="_video/02-nusxa/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := []int{40, 12, 7}
	before := stock
	stock[0] = 38
	fmt.Println(before[0])
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `stock := []int{40, 12, 7}` | заголовок и массив (как в прошлом разделе) |
| 7 | `before := stock` | новая переменная `before`; ей присваивается значение `stock` |
| 8 | `stock[0] = 38` | записывает 38 в нулевой элемент `stock` (`=` — заменить значение существующей, GB-1.02) |
| 9 | `fmt.Println(before[0])` | выводит нулевой элемент `before` |

Что выведет `before[0]`?

**A)** `40` · **B)** `38` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: 38.** `before := stock` копирует **только заголовок**: три поля (`ptr`, `len`, `cap`) переходят в новую переменную,
а копия `ptr` указывает на тот же массив. `stock[0] = 38` пишет в массив, и `before` видит тот же массив. Если вы выбрали
**A**, вы решили, что `before` получил полную копию слайса: массив не копировался. **C** — код правильный, компилятор
тут ничего не отвергает.

</details>

```console
$ ./_video/run.sh 02-nusxa go run .
38
```

Состояние по строкам (массив A — единственный массив, на который смотрят оба заголовка):

| Строка | заголовок `stock` | заголовок `before` | массив A | На экране |
|---|---|---|---|---|
| 6 | (ptr→A, 3, 3) | — | `40 12 7` | |
| 7 | (ptr→A, 3, 3) | (ptr→A, 3, 3) копия | `40 12 7` | |
| 8 | (ptr→A, 3, 3) | (ptr→A, 3, 3) | `38 12 7` | |
| 9 | (ptr→A, 3, 3) | (ptr→A, 3, 3) | `38 12 7` | `38` |

Итог: `before` не сохранил прежнее состояние. Зато передать слайс другой переменной дёшево: каким бы большим ни был массив,
копируются только три поля.

## `append`: есть место — тот же массив, нет места — новый

Добавим на склад новый товар: абрикос, остаток 25. Функция, которая добавляет элемент в слайс, — **`append`**.

```go filename="_video/03-append/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := []int{40, 12, 7}
	fmt.Printf("%d %d %p\n", len(stock), cap(stock), stock)
	stock = append(stock, 25) // oʻrik
	fmt.Printf("%d %d %p\n", len(stock), cap(stock), stock)
	stock = append(stock, 3) // anor
	fmt.Printf("%d %d %p\n", len(stock), cap(stock), stock)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 7 | `fmt.Printf("%d %d %p\n", len(stock), cap(stock), stock)` | выводит `len`, `cap` и адрес. `%d` — целое число (GB-1.04); `%p` — адрес **массива**, на который смотрит слайс, в 16-ричной записи с `0x`; `\n` — перевод строки |
| 8 | `stock = append(stock, 25) // oʻrik` | `append` берёт слайс и новый элемент и **возвращает новый заголовок**. Мы снова записываем его в `stock` |
| 9 | `fmt.Printf(…)` | выводит состояние после `append` |
| 10 | `stock = append(stock, 3) // anor` | ещё один элемент: гранат, остаток 3 |
| 11 | `fmt.Printf(…)` | выводит ещё раз |

Как работает `append` ([Go spec: Appending to and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)):

1. Если в массиве есть место для нового элемента, то есть `len < cap`, элемент записывается **в тот же массив**.
2. Если места не хватает, `append` выделяет в памяти **новый массив** с запасом, копирует старые элементы и возвращает
   заголовок, который смотрит на него.
3. У небольших слайсов runtime обычно делает новый массив вдвое больше. Это не гарантия: спецификация говорит только
   «достаточно большой».

Выведется три строки; в начале и `len`, и `cap` равны 3. В каких строках `%p` совпадёт?

**A)** 1 и 2 · **B)** 2 и 3 · **C)** во всех трёх

<details>
<summary>Ответ</summary>

**B: во второй и третьей.** При первом `append` места не было (`len` 3 = `cap` 3): создан новый массив, адрес изменился,
ёмкость стала 6. При втором `append` место есть: элемент записан в тот же массив, только `len` стал 5. Если вы выбрали
**A**, вы решили, что `append` всегда сохраняет прежний массив: при нехватке места не сохраняет. **C** означало бы, что
`append` никогда не меняет массив.

</details>

```console
$ ./_video/run.sh 03-append go run .
3 3 0x6f8787a8000
4 6 0x6f878800000
5 6 0x6f878800000
```

Адрес — 16-ричное число, начинающееся с `0x`, и при каждом запуске оно другое. Читать его не нужно: мы просто сравниваем
строки между собой. Та же программа во второй раз:

```console
$ ./_video/run.sh 03-append go run .
3 3 0xb2fe8d20120
4 6 0xb2fe8e00000
5 6 0xb2fe8e00000
```

Адреса другие, а структура та же: строка 1 ≠ строка 2, строка 2 = строка 3. (В видео вышло `0x103325296000`,
`0x10332529e000`, `0x10332529e000`; эти три числа взяты из видео, я их заново не запускал.)

| Строка | `len` | `cap` | Массив, на который смотрит слайс |
|---|---|---|---|
| 7 | 3 | 3 | массив A: `40 12 7` |
| 9 (`append(…, 25)`) | 4 | 6 | **новый** массив B: `40 12 7 25 _ _` (последние два места свободны) |
| 11 (`append(…, 3)`) | 5 | 6 | тот же массив B: `40 12 7 25 3 _` |

Теперь соединим оба случая: `before` снова копия `stock`, но между ними стоит `append`.

```go filename="_video/04-append-nusxa/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := []int{40, 12, 7}
	before := stock
	stock = append(stock, 25)
	stock[0] = 38
	fmt.Println(before[0], stock[0])
}
```

В прошлом примере `before` увидел 38. Что на этот раз выведет `fmt.Println(before[0], stock[0])`?

**A)** `40 38` · **B)** `38 38` · **C)** `40 40`

<details>
<summary>Ответ</summary>

**A: `40 38`.** В момент `append` значение `cap` было 3, и места не было. Создан новый массив на шесть мест, три старых
элемента скопированы, 25 записано четвёртым. `stock` теперь смотрит на новый массив, а `before` остался на старом.
`stock[0] = 38` попадает в новый массив, `before` его не видит. Если вы выбрали **B**, вы решили, что массив общий, как в
прошлом примере: на этот раз `append` его разделил. В **C** не учтено, что `stock[0]` стал 38.

</details>

```console
$ ./_video/run.sh 04-append-nusxa go run .
40 38
```

| Строка | `stock` | `before` | Массивы | На экране |
|---|---|---|---|---|
| 6 | (ptr→A, 3, 3) | — | A: `40 12 7` | |
| 7 | (ptr→A, 3, 3) | (ptr→A, 3, 3) | A: `40 12 7` | |
| 8 (`append`) | (ptr→**B**, 4, 6) | (ptr→A, 3, 3) | A: `40 12 7`; B: `40 12 7 25 _ _` | |
| 9 (`stock[0] = 38`) | (ptr→B, 4, 6) | (ptr→A, 3, 3) | A: `40 12 7`; B: `38 12 7 25 _ _` | |
| 10 | | | | `40 38` |

Код выглядит одинаково, но в зависимости от `cap` массив то общий, то раздельный. Поэтому после `append` нельзя
полагаться на старый слайс.

## Результат `append` нужно записывать

`append` возвращает новый заголовок и не меняет старый. Поэтому самая частая ошибка — вызвать `append` и никуда не
записать результат. В строке 7 `append` стоит один, без `stock =`:

```go filename="_video/05-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := []int{40, 12, 7}
	append(stock, 25)
	fmt.Println(stock)
}
```

```console
$ ./_video/run.sh 05-xato go build
# github.com/abdurahmon27/bozor
./main.go:7:2: append(stock, 25) (value of type []int) is not used
```

Читаем сообщение:

|---|---|

## Ошибка bozor: параметр функции тоже копия заголовка

Теперь вернёмся к ошибке из начала урока. Когда в функцию передают слайс, копируется заголовок, как в `before := stock`.

```go filename="_video/00-bug/main.go" showLineNumbers
package main

import "fmt"

// afterOrder buyurtmadan keyingi qoldiqni hisoblaydi.
func afterOrder(stock []int, sold []int) []int {
	for i := range stock {
		stock[i] = stock[i] - sold[i]
	}
	return stock
}

func main() {
	stock := []int{40, 12, 7} // olma, non, choy
	sold := []int{2, 1, 0}    // savatda
	fmt.Println("ombor oldin:", stock)
	left := afterOrder(stock, sold)
	fmt.Println("koʻrish:    ", left)
	fmt.Println("ombor keyin:", stock)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `// afterOrder …` | комментарий: функция считает остаток после заказа |
| 6 | `func afterOrder(stock []int, sold []int) []int {` | два параметра, оба слайсы: `stock` (склад) и `sold` (количество в корзине по каждому товару). Результат тоже слайс |
| 7 | `for i := range stock {` | `range` по слайсу с одной переменной даёт только индекс: 0, 1, 2 |
| 8 | `stock[i] = stock[i] - sold[i]` | на каждом шаге из `stock[i]` вычитается `sold[i]`, и результат снова записывается в `stock[i]` |
| 10 | `return stock` | в конце возвращается `stock` |
| 14–15 | `stock := …`, `sold := []int{2, 1, 0}` | в `main` склад и корзина: 2 яблока, 1 хлеб, 0 чая |
| 17 | `left := afterOrder(stock, sold)` | результат попадает в `left` |
| 16, 18, 19 | `fmt.Println(…)` | до функции, результат и после функции: три строки из начала урока |

(Параметр `stock` в функции и `stock` в `main` — две разные переменные, имя совпало случайно.)

Вывод тот же, что в начале урока: `[40 12 7]`, `[38 11 7]`, `[38 11 7]`. Почему так:

| Момент | `stock` в `main` | `stock` в `afterOrder` | массив A | `left` |
|---|---|---|---|---|
| 17: вызов | (ptr→A, 3, 3) | (ptr→A, 3, 3) — копия | `40 12 7` | |
| 7–9: цикл | (ptr→A, 3, 3) | (ptr→A, 3, 3) | `38 11 7` | |
| 10: `return stock` | (ptr→A, 3, 3) | | `38 11 7` | (ptr→A, 3, 3) — возвращённый заголовок |
| 19 | (ptr→A, 3, 3) | | `38 11 7` | (ptr→A, 3, 3) |

При вызове параметр — такая же копия заголовка, как `before := stock`. Запись в `stock[i]` внутри функции попадает в
исходный массив. Возвращённый заголовок тоже смотрит на этот массив: `left` и `stock` — одни и те же данные. Одна область
памяти и два имени — это называется **алиасингом** (aliasing). `sold` в таблице нет: его только читают. Функция хотела
«только посчитать», но изменила склад в `main`, который её вызвал.

## Исправление: отдельный массив для результата через `make`

Для результата нужен отдельный массив. Его создаёт **`make`**:

```go filename="_video/06-tuzat/main.go" showLineNumbers
package main

import "fmt"

// afterOrder buyurtmadan keyingi qoldiqni hisoblaydi; stock oʻzgarmaydi.
func afterOrder(stock []int, sold []int) []int {
	left := make([]int, len(stock))
	for i := range stock {
		left[i] = stock[i] - sold[i]
	}
	return left
}

func main() {
	stock := []int{40, 12, 7} // olma, non, choy
	sold := []int{2, 1, 0}    // savatda
	fmt.Println("ombor oldin:", stock)
	left := afterOrder(stock, sold)
	fmt.Println("koʻrish:    ", left)
	fmt.Println("ombor keyin:", stock)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `// afterOrder …; stock oʻzgarmaydi.` | комментарий тоже даёт это обещание |
| 7 | `left := make([]int, len(stock))` | `make` выделяет новый массив, заполняет его нулями и возвращает слайс на него. Длина — `len(stock)`, то есть 3 |
| 9 | `left[i] = stock[i] - sold[i]` | цикл теперь пишет только в `left`, а `stock` только читает |
| 11 | `return left` | в конце возвращается `left` |

`make([]int, длина, ёмкость)`: третий аргумент необязателен, и он становится `cap`. Если его не указать, `cap` равен `len`.

| Строка | `stock` | `left` | Массивы |
|---|---|---|---|
| 7 | (ptr→A, 3, 3) | (ptr→B, 3, 3) | A: `40 12 7`; B: `0 0 0` (новый) |
| 8–10: цикл | (ptr→A, 3, 3) | (ptr→B, 3, 3) | A: `40 12 7`; B: `38 11 7` |

Строка `koʻrish` осталась прежней (`[38 11 7]`), а склад остался `[40 12 7]`. Файл `stock_test.go` в папке проверяет именно эти два
условия:

```go filename="stock_test.go" showLineNumbers
package main

import (
	"slices"
	"testing"
)

func TestAfterOrder(t *testing.T) {
	stock := []int{40, 12, 7}
	sold := []int{2, 1, 0}
	left := afterOrder(stock, sold)
	// slices.Equal ikki slice'ning uzunligi va elementlari bir xilligini tekshiradi
	// (slice'larni == bilan solishtirib boʻlmaydi: kompilyator buni rad etadi).
```

Промежуточный вопрос. `s := make([]int, 0, 4)`, затем один `append(s, 1)`. Чему равны `len(s)` и `cap(s)`?

```go filename="_video/08-make/main.go" showLineNumbers
package main

import "fmt"

func main() {
	s := make([]int, 0, 4)
	s = append(s, 1)
	fmt.Println(len(s), cap(s))
}
```

**A)** `1 4` · **B)** `5 8` · **C)** `1 1`

<details>
<summary>Ответ</summary>

**A: `1 4`.** `make([]int, 0, 4)` даёт слайс с длиной 0 и ёмкостью 4. `append` записал элемент в свободное место, новый
массив не понадобился: `len` стал 1, `cap` остался 4. Если вы выбрали **B**, вы решили, что `append` всегда сразу удваивает
ёмкость: так бывает только при нехватке места. В **C** не учтён третий аргумент `make`.

</details>

```console
$ ./_video/run.sh 08-make go run .

```

Если число элементов известно заранее, на работе пишут так: `make([]int, 0, n)` и `append`. Каждый `append` не копирует
данные в новый массив.

## Глубже (необязательно): два `append` из одного заголовка

`append` при наличии места тоже может стать ловушкой. Здесь у `stock` `len` равен 4, `cap` равен 6. Сделаем из него два
`append`: в `a` добавим 3, в `b` добавим 9.

```go filename="_video/07-ikki-append/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := []int{40, 12, 7}
	stock = append(stock, 25) // len 4, cap 6
	a := append(stock, 3)
	b := append(stock, 9)
	fmt.Println(a[4], b[4])
}
```

`a[4]` и `b[4]` — пятые элементы. Что выведется?

**A)** `3 9` · **B)** `9 9` · **C)** `3 3`

<details>
<summary>Ответ</summary>

**B: `9 9`.** В обоих `append` есть место (`len` 4 &lt; `cap` 6), поэтому ни один не создал новый массив, и оба записали в
четвёртый индекс одного и того же массива. `b` записал поверх `a`. Если вы выбрали **A**, вы решили, что каждый `append`
сохраняет свой результат. В **C** последняя запись — 9, а не 3.

</details>

```console
$ ./_video/run.sh 07-ikki-append go run .
9 9
```

| Строка | `stock` | `a` | `b` | Массив B |
|---|---|---|---|---|
| 7 | (ptr→B, 4, 6) | | | `40 12 7 25 _ _` |
| 8 (`a := append(stock, 3)`) | (ptr→B, 4, 6) | (ptr→B, 5, 6) | | `40 12 7 25 3 _` |
| 9 (`b := append(stock, 9)`) | (ptr→B, 4, 6) | (ptr→B, 5, 6) | (ptr→B, 5, 6) | `40 12 7 25 9 _` |

Если из одного слайса вы делаете несколько результатов, стройте каждый в отдельном массиве через `make`.

## Частые ошибки

**1. «`before := stock` сохраняет прежнее состояние».** Ошибки нет, но результат неверный: `before` не копирует массив
(`38`, см. раздел «`before := stock`» выше). Исправление: сделать отдельный массив через `make` и скопировать элементы
циклом, как в `afterOrder`.

**2. Не записать результат `append`.** Если `append` стоит отдельной строкой, компилятор поймает ошибку (`is not used`
выше). Но есть и тихий вариант: функция делает `append` к параметру и не возвращает новый заголовок. Этого кода нет в
папке, я запустил его отдельно (полный код здесь):

```go showLineNumbers
package main

import "fmt"

// addPlumLost parametr orqali qoʻshmoqchi: yangi sarlavha faqat s ichida qoladi.
func addPlumLost(s []int) {
	s = append(s, 25)
}

// addPlum yangi sarlavhani qaytaradi.
func addPlum(s []int) []int {
	return append(s, 25)
}

func main() {
	stock := []int{40, 12, 7}
	addPlumLost(stock)
	fmt.Println(stock, len(stock))
	stock = addPlum(stock)
	fmt.Println(stock, len(stock))
}
```

```console
$ go run .
[40 12 7] 3
[40 12 7 25] 4
```

`s = append(s, 25)` внутри `addPlumLost(stock)` записал новый заголовок только в параметр `s`. `s` — копия заголовка
`stock`, поэтому `stock` в `main` не изменился: `[40 12 7]`, `len` 3. Ни ошибки, ни предупреждения. Исправление: функция
возвращает новый заголовок, а вызывающий код записывает его: `stock = addPlum(stock)`.

**3. Функция пишет во входной слайс.** Главная ошибка урока (функция `afterOrder` из bozor, см. раздел «Ошибка bozor»
выше): ошибки нет, склад молча меняется. Исправление: отдельный массив для результата через `make`.

**4. Индекс больше `len`, а не `cap`.** `cap` — это места в массиве, а не элементы: индекс допустим только до `len`. Этого
кода тоже нет в папке, я запустил его отдельно:

```go showLineNumbers
package main

import "fmt"

func main() {
	s := make([]int, 0, 4)
	fmt.Println(len(s), cap(s))
	s[0] = 1
	fmt.Println(s)
}
```

```console
$ go run .
0 4
panic: runtime error: index out of range [0] with length 0

goroutine 1 [running]:
main.main()
	…/bozor/main.go:8 +0x8a
exit status 2
```

Первая строка `0 4`: в `make([]int, 0, 4)` в массиве 4 места, но `len` равен 0. Поэтому `s[0] = 1` в строке 8 вызывает
panic (`index out of range` из GB-1.07): `index out of range [0] with length 0` — «индекс 0 вне границ, длина 0».
`…` в `…/bozor/main.go:8` — временная папка, её имя каждый раз другое; `exit status 2` — код выхода программы, упавшей с
panic, его пишет `go run`. Исправление: пишите в свободное место через `append` (`s = append(s, 1)`) или сделайте длину 4
через `make([]int, 4)`.

## Проверьте себя

**1.** Какие три поля в заголовке слайса и что означает каждое?

<details>
<summary>Ответ</summary>

`ptr` — адрес массива, где лежит нулевой элемент, `len` — сколько элементов в слайсе, `cap` — сколько мест от начала
слайса до конца массива. Сами элементы лежат не в заголовке, а в массиве за ним.

</details>

**2.** Когда `append` создаёт новый массив?

<details>
<summary>Ответ</summary>

Когда места не хватает: для одного элемента — когда `len` равен `cap`. Если место есть, элемент записывается в тот же
массив, растёт только `len`. В любом случае результат нужно записывать: `stock = append(stock, 25)`.

</details>

**3.** Из GB-1.06: какие значения принимает `i` в цикле `for i := range 3`?

<details>
<summary>Ответ</summary>

0, 1 и 2: `range` по целому числу считает от 0 до число−1, само число не входит.

</details>

**4.** Что выведет эта программа? (Этого кода нет в папке, я запустил его отдельно.)

```go showLineNumbers
package main

import "fmt"

func main() {
	s := make([]int, 2, 5)
	t := append(s, 7)
	u := append(s, 8)
	fmt.Println(t[2], u[2], len(s))
}
```

**A)** `7 8 2` · **B)** `8 8 2` · **C)** `8 8 4`

<details>
<summary>Ответ</summary>

**B: `8 8 2`.** У `s` `len` равен 2, `cap` равен 5: в обоих `append` есть место, оба записали во второй индекс массива,
8 затёрло 7. Сам `s` не изменился: `len(s)` равен 2. В **A** предполагалось, что оба `append` пишут в отдельные массивы.
В **C** предполагалось, что `append` увеличивает `len` у `s`: он возвращает новый заголовок, а `s` остаётся на месте.

```console
$ go run .
8 8 2
```

</details>

**5.** `afterOrder(stock, sold)` мог изменить `stock` на складе. Почему с параметром типа `int` так не бывает?

<details>
<summary>Ответ</summary>

В параметр всегда передаётся копия. У `int` копия — само значение: если функция его изменит, переменная вызывающего кода
не изменится. У слайса копия — заголовок; его поле `ptr` смотрит на массив вызывающего кода, поэтому запись в массив
видна и там.

</details>

len(prices))` — отдельный массив для результата; цикл пишет в `sale[i]` и только читает `prices[i]`; `return sale`.
Остальное — комментарий. Итоговый вид функции:

```go
func discounted(prices []int64, percent int64) []int64 {
	sale := make([]int64, len(prices))
	for i := range prices {
		sale[i] = prices[i] - prices[i]*percent/100
	}
	return sale
}
```
