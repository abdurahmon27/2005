## What you will learn

Port `8765` is occupied on the server running the bozor API. Why should choosing another port require rebuilding the code?
Who sees the Postgres password if it reaches the startup log?

**The one idea:** configuration enters the process from outside and is checked in one place at startup.
An invalid port or missing database address makes the API return the problems together, before connecting or opening its HTTP port.
Only values approved for disclosure belong in logs and git.

After this lesson you will:

- implement `flag > environment > default` precedence and distinguish missing from empty values;
- put validation before external resources using `loadConfig` and `run`;
- reproduce a password leak through `%+v` and define an explicit log view;
- keep `.env` outside git and add `HOST` until the tests pass.

| Term | Plain meaning | English term |
|---|---|---|
| configuration | a port, database address and other inputs that change between deployments | configuration |
| startup validation | checking values before the service starts work | startup validation |
| secret | a password or key that must not be disclosed; marked `secret` in the code | secret |

## Configuration outside the code

**Deploy in Twelve-Factor** means a running instance of the application in a particular environment: local, test or production, where real users work.
This definition comes from the [Codebase section](https://12factor.net/codebase).
[Twelve-Factor](https://12factor.net/config) defines configuration as values that change between deployments.
Changing the port does not change the code. The same binary works after changing the password.

The database password enters through an environment variable. A **flag** is a named command-line parameter, such as `-port 8781`.
The flags in this lesson are a convenience; Twelve-Factor recommends storing configuration in the environment.

| Input | Flag | Default | Validation |
|---|---|---|---|
| `PORT` | `-port` | `8765` | integer from 1 to 65535 |
| `DATABASE_URL` | none | none | nonempty; pgx checks format and connectivity later |

This API deliberately rejects port 0. That is an application rule, not a general rule about all TCP ports.
The secret is the password in the database connection string. These bozor sessions have no extra signature key; we do not invent one.
Publishing the source code must not disclose real credentials.

## Environment, flags and precedence

`cmd/api/config.go` has two fields. Lowercase names keep them inside the `main` package; they do not hide them from logs.
These are fragments of that file. The full file appears after we fix secret disclosure.

```go
type config struct {
	port        int
	databaseURL string // secret: ichida parol bor
}

func envOr(key, def string) string {
	if v, ok := os.LookupEnv(key); ok {
		return v
	}
	return def
}
```

`key` is the environment name; `def` is the default. `LookupEnv` returns the value and a presence boolean, `ok`.
The `:=` inside `if` receives both results; `; ok` checks presence. `Getenv` cannot distinguish these cases.

| `PORT` state | `v` | `ok` | `envOr("PORT", "8765")` |
|---|---|---|---|
| absent | `""` | `false` | `"8765"` |
| `PORT=` | `""` | `true` | `""` |
| `PORT=9090` | `"9090"` | `true` | `"9090"` |

```go
func loadConfig(args []string) (config, error) {
	fs := flag.NewFlagSet("api", flag.ContinueOnError)
	port := fs.String("port", envOr("PORT", "8765"), "HTTP port (muhitda: PORT)")
	if err := fs.Parse(args); err != nil {
		return config{}, err
	}
```

`args []string` holds arguments without the program name. `NewFlagSet` creates a separate set named `api` on each call.
With `ContinueOnError`, `Parse` returns an error instead of terminating the process. This makes the function callable from tests.
`fs.String` takes a name, default value and help text. It returns `*string`, a pointer to a string.
It initially holds the environment value or default. `Parse` replaces it with the supplied `-port` value.
`config{}` is an empty struct returned alongside an error. Do not use it as successful configuration.

| Step | `PORT=9090`, argument `-port 8781` | Only `PORT=9090` | Neither |
|---|---|---|---|
| `*port` after `fs.String` | `"9090"` | `"9090"` | `"8765"` |
| `*port` after `fs.Parse` | `"8781"` | `"9090"` | `"8765"` |

No flag is registered for `DATABASE_URL`: secrets must stay out of the command line.

## Validate before opening resources

```go
	var errs []error
	n, err := strconv.Atoi(*port)
	if err != nil || n < 1 || n > 65535 {
		errs = append(errs, fmt.Errorf("port %q: 1–65535 oraligʻidagi butun son kerak", *port))
	}
	db := os.Getenv("DATABASE_URL")
	if db == "" {
		errs = append(errs, errors.New("DATABASE_URL qoʻyilmagan: .env.example'ga qarang"))
	}
	if len(errs) > 0 {
		return config{}, errors.Join(errs...)
	}
	return config{port: n, databaseURL: db}, nil
}
```

`errs` is an error slice. `Atoi(*port)` converts the string behind the pointer to an integer.
`||` adds an error if any condition holds. The result of `append` is assigned back to `errs`.
`%q` adds quotes: even an empty port appears as `""`. The database error includes the name, without its value.
If `len(errs)` is positive, `errs...` passes the elements to `Join` as separate arguments.
`Join` returns one error value and separates messages with newlines. With no problems, a `config` with named fields and `nil` are returned.

```go filename="cmd/api/main.go" showLineNumbers
// api — bozor API'si (GB-6.08'dagi himoyalangan bozor), endi sozlamasi tashqaridan (GB-8.01, config.go):
// port flag yoki muhitdan, DATABASE_URL faqat muhitdan; notoʻgʻri sozlamada server aniq xato bilan toʻxtaydi.
//
//	docker compose up -d --wait
//	goose up                     (GOOSE_DRIVER, GOOSE_DBSTRING, GOOSE_MIGRATION_DIR: GB-5.06)
//	docker compose exec db psql -f /lab/seed.sql
//	cp .env.example .env         (bir marta; .env gitga tushmaydi)
//	set -a; . ./.env; set +a     (.env'dagi qatorlarni muhitga eksport qiladi)
//	go build ./cmd/api && ./api  → config: port=8765 db=localhost:5581/bozor
//	./api -h                     → flag'lar roʻyxati
package main

import (
	"context"
	"errors"
	"flag"
	"fmt"
	"net/http"
	"os"
	"time"

	"github.com/abdurahmon27/bozor/internal/store"
	"github.com/jackc/pgx/v5/pgxpool"
)

// newServer — bozor API serveri (GB-4.04). Handler — newHandler: middleware zanjiri, ichida newMux (GB-6.01).
func newServer(addr string, st *store.Store) *http.Server {
	return &http.Server{
		Addr:              addr,
		Handler:           newHandler(st),
		ReadHeaderTimeout: 5 * time.Second,
	}
}

func main() {
	err := run(os.Args[1:])
	if errors.Is(err, flag.ErrHelp) {
		return // -h: flag yordam matnini chiqardi, bu xato emas
	}
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}

// run — dasturning hammasi shu yerda (GB-5.10): xato qaytaradi, defer'lar ishlaydi, chiqish kodini main hal qiladi.
func run(args []string) error {
	cfg, err := loadConfig(args)
	if err != nil {
		return err
	}
	fmt.Printf("config: %+v\n", cfg) // String() chaqiriladi: parol chiqmaydi
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	pool, err := pgxpool.New(ctx, cfg.databaseURL)
	if err != nil {
		return err
	}
	defer pool.Close()
	if err := pool.Ping(ctx); err != nil { // baza ishlamasa server ishga tushmaydi
		return err
	}
	srv := newServer(cfg.addr(), store.New(pool))
	fmt.Printf("bozor API: http://localhost:%d\n", cfg.port)
	return srv.ListenAndServe()
}
```

| Line | What it does |
|---|---|
| 1–10 | startup comments; not executed |
| 11 | executable `main` package |
| 13–24 | context, errors, flags, formatting, HTTP, environment, time, store and pgx pool packages |
| 26–33 | `newServer`: address, handler and a 5-second header-reading limit; `&` returns a server pointer |
| 35–39 | `os.Args[1:]` removes the program name; `ErrHelp` exits successfully |
| 40–44 | writes other errors to stderr and calls `os.Exit(1)` |
| 46–51 | `run` loads configuration; on error, returns before external resources |
| 52 | prints the configuration's log view |
| 53–54 | a 5-second database context; `defer cancel()` runs on return |
| 55–62 | creates the pool, schedules its closure and checks connectivity with `Ping` |
| 63–65 | creates the HTTP server, prints its address and listens; returns its error |

`loadConfig` checks only the port and a nonempty `DATABASE_URL`. It does not validate URI syntax or database availability.
`pgxpool.New` and `Ping` are the next stage; both also run before HTTP listening.
An invalid flag makes `Parse` return immediately: subsequent validation errors are not collected in that case.

| State | `loadConfig` | Postgres | HTTP port |
|---|---|---|---|
| invalid port or missing DB | error, `run` returns | not opened | not opened |
| DB text present, connection invalid | returns configuration | creation or `Ping` fails | not opened |
| everything valid | returns configuration | `Ping` succeeds | opened by `ListenAndServe` |

## Keep secrets out of git

`.env.example` holds only names and a template. `PAROL` ("password") is not a real credential.
This template matches the course file:

```text
# Nusxa oling: cp .env.example .env — haqiqiy qiymatlar faqat .env'da (u gitga tushmaydi).
PORT=8765
DATABASE_URL='postgres://bozor:PAROL@localhost:5581/bozor'
```

In the URI, `bozor` is the user, `PAROL` the password, `localhost:5581` the host and port, and `/bozor` the database.
Single quotes prevent shell interpretation; special characters inside the URI may still need percent-encoding.
A single quote in the password itself cannot be inserted unchanged into this quoted form.

Bash executes the file as code instead of reading it as data. Source only a trusted `.env`.
The git rules already exist. Which file is ignored: `.env` or `.env.example`?

**A)** both · **B)** only `.env` · **C)** neither

<details>
<summary>Answer</summary>

**B.** The `.env` rule does not match `.env.example`. `/api` ignores only the root binary; `api` would also match `cmd/api`.

</details>

```console
$ cat .gitignore
.env
/api
$ git check-ignore -v .env
.gitignore:1:.env	.env
$ git check-ignore -v .env.example ; echo "kod: $?"
kod: 1
$ cp .env.example .env
```

The `-v` result contains the rule file, line, pattern, then a Tab and the checked path. Here `kod: 1` means no ignore rule matched.
`cp` printed nothing. In the copy, replace `PAROL` with `bozor-lab` in your editor; keep the quotes.
**This is a deliberately public lab password**, also used by `compose.yaml`. Never put a real password on the page or in git.

`set -a` exports subsequent values; `.` executes the file in the current shell; `set +a` disables automatic export.
Go does not read `.env` automatically. Only `echo` printed output below:

```console
$ set -a; . ./.env; set +a
$ echo $PORT
8765
```

`.gitignore` helps only with untracked files. A previously committed secret remains in history.
Immediately revoke or replace an exposed password or key. Ignoring the file does not repair that exposure.
On the server, Docker or systemd supplies the environment; GB-8.04 and GB-8.06 cover them.

`net/url` provides `Parse` to split an address; `Host` holds host and port, and `Path` holds the database path.

Here is the complete corrected course `config.go`:

```go filename="cmd/api/config.go" showLineNumbers
package main

// Sozlama (GB-8.01). Kod hamma muhitda bir xil; muhitga qarab oʻzgaradigan narsa (port, baza manzili, kalitlar)
// tashqaridan keladi: muhit oʻzgaruvchilari va flag'lardan (Twelve-Factor App, III. Config).
// Ustunlik: flag > muhit oʻzgaruvchisi > standart qiymat. Hammasi ishga tushishda BIR MARTA tekshiriladi:
// biror qiymat notoʻgʻri boʻlsa server hech narsa ochmaydi, hamma xatolarni sanab, 1 kodi bilan chiqadi.
//
//	PORT          -port   HTTP port, 1–65535 (standart 8765)
//	DATABASE_URL  —       Postgres manzili. SECRET: ichida parol bor. Faqat muhitdan, flag emas:
//	                      buyruq qatori (ps, /proc/PID/cmdline) shu kompyuterdagi hamma foydalanuvchiga koʻrinadi.
//
// Qiymatlar: .env.example (gitda) → nusxasi .env (gitda emas, .gitignore).

import (
	"errors"
	"flag"
	"fmt"
	"net/url"
	"os"
	"strconv"
)

// config — serverning ishga tushish sozlamalari.
type config struct {
	port        int
	databaseURL string // secret: ichida parol bor
}

// envOr — key qoʻyilgan boʻlsa uning qiymati (boʻsh boʻlsa ham), qoʻyilmagan boʻlsa def.
// «PORT=» (boʻsh) — xato sozlama: u standart qiymatga jim almashmaydi, tekshiruvda ushlanadi.
func envOr(key, def string) string {
	if v, ok := os.LookupEnv(key); ok {
		return v
	}
	return def
}

// loadConfig — args (os.Args[1:]) va muhitdan config. Hamma xato bitta error'da (errors.Join), har biri alohida qatorda.
// flag.ContinueOnError: notoʻgʻri flag'da Parse dasturni toʻxtatmaydi, xato qaytaradi (testlar uchun ham).
func loadConfig(args []string) (config, error) {
	fs := flag.NewFlagSet("api", flag.ContinueOnError)
	port := fs.String("port", envOr("PORT", "8765"), "HTTP port (muhitda: PORT)")
	if err := fs.Parse(args); err != nil {
		return config{}, err
	}

	var errs []error
	n, err := strconv.Atoi(*port)
	if err != nil || n < 1 || n > 65535 {
		errs = append(errs, fmt.Errorf("port %q: 1–65535 oraligʻidagi butun son kerak", *port))
	}
	db := os.Getenv("DATABASE_URL")
	if db == "" {
		errs = append(errs, errors.New("DATABASE_URL qoʻyilmagan: .env.example'ga qarang"))
	}
	if len(errs) > 0 {
		return config{}, errors.Join(errs...)
	}
	return config{port: n, databaseURL: db}, nil
}

// addr — http.Server'ning Addr maydoni: ":8765" — shu portda, kompyuterning hamma tarmoq manzillarida.
func (c config) addr() string {
	return fmt.Sprintf(":%d", c.port)
}

// String — config'ning log'dagi koʻrinishi. fmt'ning %v, %+v va %s'i shu metodni chaqiradi (GB-2.07).
// Bazadan faqat host va baza nomi: foydalanuvchi, parol va ?parametrlar chiqmaydi (OWASP Logging Cheat Sheet:
// «Database connection strings» log'ga toʻgʻridan-toʻgʻri yozilmaydi). %#v String'ni chaqirmaydi: config'ni %#v bilan yozmang.
func (c config) String() string {
	db := "[yashirin]"
	if u, err := url.Parse(c.databaseURL); err == nil && u.Host != "" {
		db = u.Host + u.Path
	}
	return fmt.Sprintf("port=%d db=%s", c.port, db)
}
```

<summary>Answer</summary>

**B.** `fmt` calls `String()` on the directly supplied `config`. Output changes even though `Printf` is unchanged.

</details>

```console
$ go build ./cmd/api && ./api -port 8781
```

This result was also rerun. `%v`, `%+v` and `%s` use `String()` on a directly supplied `config` value.
**Limit:** `%#v` bypasses this method. An invalid `%d` or config nested in another struct's lowercase field can also expose raw data.
Do not send entire structs to logs using arbitrary formats. This method controls only the demonstrated output path.
The next lesson shows `LogValue` for `slog`.

Your system must also permit disclosure of the selected `Host` and `Path`.
The error constructed by `loadConfig` omits the secret value; that is not a guarantee about every library error.
Check those paths separately before logging a raw connection string or an unreviewed external error in production.

## Going deeper (optional): command lines are visible too

There is a reason we did not add a `DATABASE_URL` flag. On Linux, command lines are usually visible to other users.
The video uses `ps -o args= -C api` and `pid=$(pgrep -x api)`.
`-o args=` prints arguments without a header; `-C api` selects all processes with that name; `pgrep -x` matches the full name.
Another lab with the same process name was running during our check. We therefore selected only our process's PID.
PID means process ID. Here is the real second-terminal output while the server ran the preceding command:

```console
$ ps -o args= -p 1036694
./api -port 8781
$ stat -c '%A %n' /proc/1036694/cmdline /proc/1036694/environ
-r--r--r-- /proc/1036694/cmdline
-r-------- /proc/1036694/environ
```

`-p` selects one PID; in the `stat -c` template, `%A` means permissions and `%n` means filename.
The video PID is `990337`; ours is shown above. PIDs change between runs.
Here, `cmdline` permissions were `-r--r--r--`, while `environ` permissions were `-r--------`.
That does not make the environment absolute secret protection: access also depends on procfs mount settings, process state and ptrace checks.
The [Linux documentation](https://man7.org/linux/man-pages/man5/proc_pid_environ.5.html) specifies a ptrace access check for `environ`.

[OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html) notes that environment values can reach logs and memory dumps.
Larger systems use a secret manager, a separate service for managing secrets.
Do not print the process's entire environment. After checking, stop the server with `Ctrl+C` and remove the lab database and its volume:

## Common mistakes

1. **"Lowercase hides the password."** The broken code is the earlier `fmt.Printf("config: %+v\n", cfg)` at the stage without `String()`.
   Its real output disclosed the password. Select approved values; JSON's field rules do not apply to `fmt`.
2. **Replacing an empty `PORT` with the default.** The earlier `PORT=` run produced `port ""` and exit code 1.
   Use the default only when `LookupEnv` returns `ok == false`. Do not silently hide invalid input.
3. **An undefined flag.** The starter does not yet have `-host`. The homework test below really reports `flag provided but not defined: -host`.
   It means the supplied flag has not been registered. Add `fs.String("host", …)` before `Parse`.
4. **Trying to repair an old commit with `.gitignore`.** The rule does not affect a tracked file.
   Immediately revoke or replace exposed credentials, then clean the repository and history using the appropriate process.
5. **Assuming `loadConfig` validates everything.** pgx validates the database URI later; this code does not reject positional arguments.
   `flag.Parse` stops at the first ordinary argument. Check `fs.NArg()` if extra arguments must be rejected.
