## What you will learn

Right now bozor takes the name, price and quantity from inside `main.go`: `name = "choy"`, `price = 1_999 * tiyinPerSom`.
For a new product you have to change the code and build again. Today bozor takes them from the terminal:
`./bozor add olma 12000` (*olma* is "apple"). And if someone types `12k` instead of a price? The program must notice and
reject the input with a clear message.

**One idea:** in Go, failure is also an ordinary return value. A function returns a `(value, error)` pair; when there is
no error, `err` is `nil`. The calling code checks `if err != nil` before it touches the value: when there is an error,
the value may be meaningless (`Atoi` returns `9223372036854775807` when the number is out of range).

By the end of the lesson you will:

- read the command-line words with `os.Args` and check its length *before* you index it;
- turn text into a number with `strconv.Atoi` and read the returned `error`;
- write `func parsePrice(s string) (int64, error)`: a parameter, two results, `return`, your own error with `fmt.Errorf`;
- reject bad input with a message on the standard error stream and exit code 1, and see the code with `echo $?`.

Today's three core new words:

| Word | Plain meaning | English term |
|---|---|---|
| `os.Args` | the list of words typed in the terminal when the program starts; `os.Args[0]` is the program itself, the index starts at 0; `len(os.Args)` is how many words | command-line arguments |
| `(value, error)` and `if err != nil` | a function returns an error together with its result; `nil` means "no error"; `err` is checked before the value | error value, `nil` |
| `func`: parameter, results, `return` | `func name(parameter type) (results) { … }`; `return` ends the function and gives the values back to the calling code | function, parameter, result, `return` |

Two helper words: **exit code** — the number a program leaves to the operating system when it ends: `0` is success,
anything else is an error; `os.Exit(1)` stops the program at once with code 1. **Standard error stream** (*standard
error*, `os.Stderr`) — a separate output for messages; `fmt.Fprintln(os.Stderr, …)` writes there.

## `os.Args`: the terminal's words reach the program

First, in place of `main.go`, we write a small temporary test program; the bozor receipt code comes back later. Now we need
two packages, so after `import` we open a parenthesis and write each package on its own line. This is the usual way to
import several packages ([Go spec: Import declarations](https://go.dev/ref/spec#Import_declarations)).

```go filename="_video/01-args/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
)

func main() {
	fmt.Println(len(os.Args), os.Args)
}
```

| Line | Code | What it does |
|---|---|---|
| 3–6 | `import (` … `)` | grouped import: several packages in parentheses, each on its own line |
| 4 | `"fmt"` | the package that prints to the screen (GB-1.01) |
| 5 | `"os"` | the standard package that works with the operating system (GB-1.01) |
| 9 | `os.Args` | **command-line arguments**: the list of words typed in the terminal when the program starts, beginning with the program name |
| 9 | `len(os.Args)` | `len(…)` returns the number of elements in the list |
| 9 | `fmt.Println(len(os.Args), os.Args)` | prints the number first, then the list itself |

We run the program with three words: `add`, `olma` and `12000`.

```console
$ ./_video/run.sh 01-args add olma 12000
4 [./bozor add olma 12000]
(chiqish kodi: 0)
```

First `4` was printed: the list has four elements. Then `Println` printed the list in square brackets, with the elements
separated by spaces. The first element is the program itself, exactly as it was typed in the terminal: `./bozor`.
pkg.go.dev says the same: «Args hold the command-line arguments, starting with the program name»
([os.Args](https://pkg.go.dev/os#pkg-variables)).

Where do these words come from? The **shell** in the terminal — the program that reads your command — splits the line
into words at the spaces, except for text inside quotes. The operating system gives these words to the program, and they
end up in `os.Args`. You reach each element by its position: `os.Args[3]`. The number in square brackets is the
**index**, and counting starts at zero:

| Element | Value | What it is |
|---|---|---|
| `os.Args[0]` | `"./bozor"` | the program name |
| `os.Args[1]` | `"add"` | the command |
| `os.Args[2]` | `"olma"` | the product name |
| `os.Args[3]` | `"12000"` | the price — but as **text**, not a number |

`len(os.Args)` = 4, so the valid indexes are 0, 1, 2 and 3. The rule in the specification: an index `x` is in range if
`0 <= x < len(a)` ([Go spec: Index expressions](https://go.dev/ref/spec#Index_expressions)). Most important: all four
elements are text (`string`), `12000` too. The type of `os.Args` is `[]string`, a list of strings (a **slice**); we open
up slices in [GB-2.01](/lab/youtube/gb#gb-2-01), today the index and `len` are enough.

<summary>Answer</summary>

**C: the program does not build.** `price` is a `string`, and `1` is an integer whose type is not chosen yet (the
*untyped* constant from GB-1.03). `+` adds only values of the same type (GB-1.04). If you chose **A**, you thought Go
turns text into a number by itself: it does not. **B** assumes that `+` joins texts (string concatenation): that works only when both sides are
`string`, and `1` is not text.

</details>

```console
$ ./_video/run.sh 02-plus-xato add olma 12000
# github.com/abdurahmon27/bozor
./main.go:10:14: invalid operation: price + 1 (mismatched types string and untyped int)
```

The first line says which module has the error (GB-1.04). The second one: `main.go`, **line 10, column 14** (`price`
starts at that column). `invalid operation: price + 1` means "an operation that is not allowed"; `mismatched types string
and untyped int` means "the types do not match: `string` and an `int` with no chosen type". The program did not build, so
it did not run either: the script never reached the `(chiqish kodi …)` line. In short: a price from the terminal must be
turned into a number before you calculate with it.

## `strconv.Atoi`: a number from text, and an `error`

For this the standard library has the `strconv` package. The name comes from *string conversion*. `strconv.Atoi` is a
function in it: it makes an integer (`int`) from text. Its full declaration on pkg.go.dev is
`func Atoi(s string) (int, error)` ([strconv.Atoi](https://pkg.go.dev/strconv#Atoi)). The two types in the last
parentheses mean that `Atoi` **returns two values**: the number and an error.

```go filename="_video/03-atoi/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"strconv"
)

func main() {
	price, err := strconv.Atoi(os.Args[3])
	fmt.Println(price, err)
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `"strconv"` | the standard package that converts text to numbers and other types |
| 10 | `strconv.Atoi(os.Args[3])` | tries to turn the text `"12000"` into an `int` |
| 10 | `price, err :=` | two names separated by a comma on the left, one per result: `price` for the number, `err` for the error. `:=` declares both at once (GB-1.02) |
| 11 | `fmt.Println(price, err)` | prints both values separated by a space |

With `12000`, two name tags appear in memory:

| Name tag | Type | Value |
|---|---|---|
| `price` | `int` | `12000` |
| `err` | `error` | `nil` — no error |

**`error`** is Go's type for errors, a predeclared type ([Go spec: Errors](https://go.dev/ref/spec#Errors)). **`nil`** is
its empty value, meaning "no error". `Println` prints a `nil` error in angle brackets: `<nil>`. Now we try two inputs —
`12000` and `12k`:

```console
$ ./_video/run.sh 03-atoi add olma 12000
12000 <nil>
(chiqish kodi: 0)
$ ./_video/run.sh 03-atoi add olma 12k
0 strconv.Atoi: parsing "12k": invalid syntax
(chiqish kodi: 0)
```

With `12k`, `price` is `0` and `err` is the error text. Read it piece by piece: `strconv.Atoi` — which function;
`parsing "12k"` — which text it was reading (in quotes); `invalid syntax` — the reason: "the text is not written
correctly", it is not a number ([strconv.NumError](https://pkg.go.dev/strconv#NumError)). Notice: the program did not
stop, the exit code is `0`. The error came back as an ordinary value, just like `price`. Checking it is the job of the
calling code.

## `Atoi` checks only the spelling

Now we pass `-5` as the price. What is printed?

**A)** `-5 <nil>` · **B)** `0` and `invalid syntax` · **C)** `0` and a "negative price" error

<details>
<summary>Answer</summary>

**A: `-5 <nil>`.** `Atoi` checks only how the number is written, and `-5` is a correctly written number: «The string may
begin with a leading sign» ([strconv.ParseInt](https://pkg.go.dev/strconv#ParseInt); `Atoi` is short for
`ParseInt(s, 10, 0)`). If you chose **B**, you thought the minus sign is not allowed. **C** assumes `Atoi` knows something
about prices: that a price must be positive is our rule, and we write it ourselves.

</details>

```console
$ ./_video/run.sh 03-atoi add olma -5
-5 <nil>
(chiqish kodi: 0)
```

One more case: twenty nines. On this computer `int` is 64 bits, and such a number does not fit.

```console
$ ./_video/run.sh 03-atoi add olma 99999999999999999999
9223372036854775807 strconv.Atoi: parsing "99999999999999999999": value out of range
(chiqish kodi: 0)
```

`price` is not `0`! `9223372036854775807` is about 9.2 quintillion, the largest value of a 64-bit `int`. And `err` is
`value out of range`. The documentation says: when the value is out of range, `err.Err = ErrRange` and the returned value
is the largest number of that type ([strconv.ParseInt](https://pkg.go.dev/strconv#ParseInt)). The rule follows from this:

> If `err` is not `nil`, do not trust the first value: check `err` first.

| Input | `price` | `err` | Can you trust `price`? |
|---|---|---|---|
| `12000` | `12000` | `<nil>` | yes |
| `12k` | `0` | `invalid syntax` | no: `0` is not a real price |
| `-5` | `-5` | `<nil>` | the spelling is correct, but we check the price rule ourselves |
| twenty `9`s | `9223372036854775807` | `value out of range` | no: this is the limit value, not what the user typed |

## `if err != nil`, the error stream and the exit code

The check is written like this:

```go filename="_video/04-iferr/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"strconv"
)

func main() {
	price, err := strconv.Atoi(os.Args[3])
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println("narx:", price)
}
```

| Line | Code | What it does |
|---|---|---|
| 11 | `if err != nil {` | `!=` means "not equal" (GB-1.05): if there is an error, the lines inside `{ }` run |
| 12 | `fmt.Fprintln(os.Stderr, "xato:", err)` | `Fprintln` is like `Println`, but its first argument says **where** to write; `os.Stderr` is the standard error stream; `xato` is "error" |
| 13 | `os.Exit(1)` | stops the program at once and returns exit code `1` to the operating system |
| 15 | `fmt.Println("narx:", price)` | reached only when `err == nil`: then the `if` body was skipped (`narx` is "price") |

Two new ideas:

- **Standard error stream** (*standard error*, `stderr`). A program has two separate outputs: **standard output**
  (`os.Stdout`; `fmt.Println` writes there) for the normal result, and the standard error stream for messages. The
  terminal shows both. But when a script writes the result to a file, the error message does not get mixed into the
  file; it stays on the screen. We will see this with bozor below.
- **Exit code**. The number a program leaves to the operating system when it ends. «Conventionally, code zero indicates
  success, non-zero an error» ([os.Exit](https://pkg.go.dev/os#Exit)). In the terminal, `echo $?` prints the exit code of
  the last command ([bash: Special Parameters](https://www.gnu.org/software/bash/manual/bash.html#Special-Parameters)).
  Scripts and CI — a server that checks code automatically — look exactly at this number.

With `12k` and `12000`:

```console
$ ./_video/run.sh 04-iferr add olma 12k
xato: strconv.Atoi: parsing "12k": invalid syntax
(chiqish kodi: 1)
$ ./_video/run.sh 04-iferr add olma 12000
narx: 12000
(chiqish kodi: 0)
```

With `12k`, only the error line is printed now, and the exit code is `1`. In the video, `echo $?` is typed at this point
and prints `1` too; the script's `(chiqish kodi: 1)` line shows exactly that number. With `12000` the `if` body is skipped,
the last line prints the price, and the code is `0`. In short: the value and the `error` come back together, and `err` is
checked before the value is touched.

## `func parsePrice`: the price rule in one place

The price rule grows: it must be a number, it must be positive, it must be converted to tiyin. We move it into a separate
**function**: `main` stays short, and in the next lesson we can test the function on its own. Its first line is the
function's declaration, or its **signature**:

```go
func parsePrice(s string) (int64, error) {
```

| Part | What it is |
|---|---|
| `func` | a function is being declared (`func main` from GB-1.01 works the same way) |
| `parsePrice` | the function's name: "parse the price" |
| `(s string)` | the **parameter**: first the name `s`, then the type `string`. The value given at the call — the **argument** — goes into this name |
| `(int64, error)` | the **results**: two return values — the price in tiyin (`int64`, GB-1.03) and an error |
| `{` | the function body begins |

The Go convention: `error` is always the last result. `strconv.Atoi` does the same: `(int, error)`. The body:

```go
func parsePrice(s string) (int64, error) {
	som, err := strconv.Atoi(s)
	if err != nil {
		return 0, err
	}
	return int64(som) * tiyinPerSom, nil
}
```

| Line | Code | What it does |
|---|---|---|
| 2 | `som, err := strconv.Atoi(s)` | turns `s` into a number; the result goes into `som` ("som", the currency), the error into `err` |
| 3–5 | `if err != nil { return 0, err }` | on error: `0` and that same `err` are returned |
| 6 | `return int64(som) * tiyinPerSom, nil` | with no error: convert `som` to `int64` and multiply by `tiyinPerSom` (100); `nil` in the error's place |

**`return`** stopped `main` in GB-1.05. Here it ends the function and gives the values back to the **caller**, the code
that called the function ([Go spec: Return statements](https://go.dev/ref/spec#Return_statements)). After `return`, the
number and order of the results must match the signature: first `int64`, then `error`.

Let us follow the call `parsePrice("12000")` in memory:

| Step | Line | `s` (`string`) | `som` (`int`) | `err` (`error`) | What happens |
|---|---|---|---|---|---|
| call | 1 | `"12000"` | | | `s` gets a **copy** of the argument |
| `Atoi` | 2 | `"12000"` | `12000` | `nil` | the text became a number |
| `if` | 3 | | | | `err != nil` is `false`: the `if` body is skipped |
| `return` | 6 | | | | `1200000, nil` is returned: 12,000 som = 1,200,000 tiyin |

`s`, `som` and `err` exist only inside this call: when the function ends, they are gone. The specification: the arguments
of the call are passed to the function and assigned to the matching parameters
([Go spec: Calls](https://go.dev/ref/spec#Calls)).

**The second rule: the price is positive.** We saw that `Atoi` accepts `-5` without an error, and `0` passes the same way.
But a price must be positive. If `som` is less than or equal to zero, we make the error ourselves:

```go
	if som <= 0 {
		return 0, fmt.Errorf("narx musbat boʻlishi kerak, keldi %d", som)
	}
```

("the price must be positive, got %d".) **`fmt.Errorf`** fills in the template like `fmt.Sprintf` from GB-1.04 (`som` is
put in place of `%d`), but it returns the result as an `error`, not a `string` ([fmt.Errorf](https://pkg.go.dev/fmt#Errorf)).
These three functions work with the same template; the difference is the result:

| Function | What it does with the result |
|---|---|
| `fmt.Printf` | writes it to the screen |
| `fmt.Sprintf` | returns a `string` |
| `fmt.Errorf` | returns an `error` |

## Putting it all into bozor

Now we bring the receipt code back. The beginning is bozor from the end of GB-1.06: the startup lines, `name`, `price` and
`active` declared with `var`, the zero-value line. What changed: instead of `name = "choy"` we now have
`name = os.Args[2]`, and the price text is passed to `parsePrice`. This state — bozor before the length check was added —
is in the file `_video/05-panic/main.go` (you will see why it has this name in the next section):

```go filename="_video/05-panic/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"strconv"
)

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)
const maxFree = 2          // bitta buyurtmada koʻpi bilan shuncha dona bepul

// parsePrice soʻmdagi narx matnini tiyinga oʻgiradi.
func parsePrice(s string) (int64, error) {
	som, err := strconv.Atoi(s)
	if err != nil {
		return 0, err
	}
	if som <= 0 {
		return 0, fmt.Errorf("narx musbat boʻlishi kerak, keldi %d", som)
	}
	return int64(som) * tiyinPerSom, nil
}

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = os.Args[2]
	price, err := parsePrice(os.Args[3]) // tiyinda
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 7
	if name == "" {
		fmt.Println("xato: mahsulot nomi boʻsh")
		return
	}
	if !active {
		fmt.Printf("xato: %s sotuvda emas\n", name)
		return
	}
	if price > 10_000_000*tiyinPerSom { // price <= 0 endi parsePrice ichida
		fmt.Printf("xato: narx notoʻgʻri: %d tiyin\n", price)
		return
	}
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)

	var subtotal int64
	free := 0
	for i := 1; i <= sold; i++ {
		if i%3 == 0 && free < maxFree {
			free++
			continue // aksiya: har uchinchi dona bepul
		}
		subtotal += price
	}
```

## The trap: indexing without checking the length

Now the classic mistake. The file above has no length check. We forget the price and type only `add olma`:

```console
$ ./_video/run.sh 05-panic add olma
bozor ishga tushdi
versiya: 0.1.0
 0 false
panic: runtime error: index out of range [3] with length 3

goroutine 1 [running]:
main.main()
	/tmp/tmp.0oNT412J6V/bozor/main.go:36 +0x953
(chiqish kodi: 2)
```

After the startup lines the program crashed with a **panic**. A panic is an emergency state that stops a Go program at
once; we open it up in [GB-2.09](/lab/youtube/gb#gb-2-09). Let us read the message:

| Line | Meaning |
|---|---|
| `panic: runtime error:` | the error happened while the program was running (*runtime*) |
| `index out of range [3] with length 3` | "index 3 is out of range, the length is 3": `os.Args` has three elements (`./bozor`, `add`, `olma`), positions 0, 1 and 2; there is no position 3 |
| `goroutine 1 [running]:` and `main.main()` | where it stopped: the `main` function of package `main` (we explain the word *goroutine* in GB-7.01) |
| `…/bozor/main.go:36 +0x953` | `main.go`, **line 36** — the `price` line with `os.Args[3]`. The `/tmp/tmp.…` at the start is the script's temporary folder; its name is different every time |
| `(chiqish kodi: 2)` | a Go program that crashed with a panic exits with code 2 |

`os.Args[2]` on line 35 worked fine: `olma` is there. But `os.Args[3]` on line 36 refers to a position that does not
exist: by the specification, if an index is out of range at run time, a *run-time panic* occurs
([Go spec: Run-time panics](https://go.dev/ref/spec#Run_time_panics)). The compiler cannot know this in advance: the
number of words is known only when the program starts.

**The fix: check the length before the index.** If there are not four elements, or the first word is not `add`, we print
the usage line (`foydalanish` is "usage", `NOM NARX` is "NAME PRICE") and exit with 1. The folder's `main.go` is the file
above plus these four lines:

```console
$ diff _video/05-panic/main.go main.go

> 		fmt.Fprintln(os.Stderr, "foydalanish: bozor add NOM NARX")
> 		os.Exit(1)
> 	}
```

`34a35,38` means "new lines 35–38 after line 34". `||` means "or" (GB-1.05), and it is evaluated from left to right: if the
left side is `true`, the right side is not evaluated at all
([Go spec: Logical operators](https://go.dev/ref/spec#Logical_operators)). So reading `os.Args[1]` is safe even when there
are too few elements: `len(os.Args) != 4` is already `true`.

| Command | `len(os.Args)` | `len(os.Args) != 4` | `os.Args[1] != "add"` | Result |
|---|---|---|---|---|
| `./bozor` | 1 | `true` | not evaluated | usage line |
| `./bozor add olma` | 3 | `true` | not evaluated | usage line |
| `./bozor sell olma 12000` | 4 | `false` | `true` | usage line |
| `./bozor add olma 12000` | 4 | `false` | `false` | receipt |

## Common mistakes

**1. Trusting the value when there is an error (no error is shown).** The most common wrong belief: "if `Atoi` fails, the
value is `0`, so you can use it". We saw above: when the number is out of range, `Atoi` returns `9223372036854775807`, and
for `12k` it returns `0`, which is not a real price. In both cases the program does not stop, and the receipt would use a
wrong price. The fix: always `if err != nil` before the value (see the table in the section "`Atoi` checks only the
spelling").

**2. Getting `err` and not checking it.** An example that is not in the folder: `err` is received but never used.

```go
package main

import (
	"fmt"
	"os"
	"strconv"
)

func main() {
	price, err := strconv.Atoi(os.Args[3])
	fmt.Println("narx:", price)
}
```

```console
$ go build
# github.com/abdurahmon27/bozor
./main.go:10:9: declared and not used: err
```

`main.go`, line 10, column 9 — `err`. `declared and not used: err` means "`err` is declared but not used". Go rejects an
unused variable inside a function ([Go spec: Variable declarations](https://go.dev/ref/spec#Variable_declarations)), so you
cannot just "forget" an error: the code does not compile. The fix: `if err != nil { … }` before `price`.

**3. `:=` when no new name is left on the left side.** This happens if, in the task, you keep the `sold := 7` line and add
`sold, err := …` below it. An example that is not in the folder:

```go
package main

import (
	"fmt"
	"os"
	"strconv"
)

func main() {
	price, err := strconv.Atoi(os.Args[3])
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	sold := 7
	sold, err := strconv.Atoi(os.Args[4])
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println(price, sold)
}
```

```console
$ go build
# github.com/abdurahmon27/bozor
./main.go:16:12: no new variables on left side of :=
```

Line 16, column 12 — the `:=`. `no new variables on left side of :=` means exactly that: `sold` was declared on line 15,
`err` on line 10. `:=` needs at least one new name on the left. The fix: delete the `sold := 7` line; then `sold` is a new
name and `sold, err := …` works (`err` simply gets a new value).

**4. `os.Args[3]` without checking the length.** `panic: runtime error: index out of range [3] with length 3` and exit
code 2. See the trap section above. The fix: before the index, `if len(os.Args) != 4 || … { … os.Exit(1) }`.

**5. Calculating with text from the terminal.** `os.Args[3] + 1` gives `mismatched types string and untyped int` (the
section "Everything from the terminal is text"). The fix: first `strconv.Atoi`, then the `err` check, then the
calculation.

```go
// parseSold sotilgan dona sonini matndan oʻgiradi: kamida 1 dona.
func parseSold(s string) (int, error) {
	n, err := strconv.Atoi(s)
	if err != nil {
		return 0, err
	}
	if n < 1 {
		return 0, fmt.Errorf("miqdor kamida 1 boʻlishi kerak, keldi %d", n)
	}
	return n, nil
}
```

The length check now expects 5 words (`./bozor`, `add`, name, price, quantity), and in place of `sold := 7` there is the
`parseSold` call and the usual `if err != nil`. The old `if sold <= 0 { … }` block in `main` is deleted: this rule now
lives in `parseSold`. The difference in the folder (`<` is the starting `main.go`, `>` is the answer):
