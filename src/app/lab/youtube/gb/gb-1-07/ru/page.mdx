## Что вы узнаете

Сейчас bozor берёт название, цену и количество из `main.go`: `name = "choy"`, `price = 1_999 * tiyinPerSom`. Для нового
товара нужно менять код и заново делать build. Сегодня bozor получит их из терминала: `./bozor add olma 12000` (*olma* —
«яблоко»). А если вместо цены кто-то напишет `12k`? Программа должна это заметить и отклонить ввод с понятным сообщением.

**Одна идея:** в Go неудача — тоже обычное возвращаемое значение. Функция возвращает пару `(значение, error)`; если ошибки
нет, `err` равен `nil`. Вызывающий код проверяет `if err != nil` до того, как трогать значение: при ошибке значение может
не иметь смысла (`Atoi` при выходе за границу возвращает `9223372036854775807`).

В конце урока вы:

- прочитаете слова командной строки через `os.Args` и проверите её длину *до* обращения по индексу;
- превратите текст в число через `strconv.Atoi` и прочитаете возвращённую `error`;
- напишете `func parsePrice(s string) (int64, error)`: параметр, два результата, `return`, своя ошибка через `fmt.Errorf`;
- отклоните неверный ввод сообщением в стандартный поток ошибок и кодом выхода 1, а код увидите через `echo $?`.

Три главных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| `os.Args` | список слов, набранных в терминале при запуске программы; `os.Args[0]` — сама программа, индекс с 0; `len(os.Args)` — сколько слов | command-line arguments |
| `(значение, error)` и `if err != nil` | функция возвращает вместе с результатом и ошибку; `nil` — «ошибки нет»; `err` проверяется до значения | error value, `nil` |
| `func`: параметр, результаты, `return` | `func имя(параметр тип) (результаты) { … }`; `return` завершает функцию и возвращает значения вызвавшему коду | function, parameter, result, `return` |

Два вспомогательных слова: **код выхода** (*exit code*) — число, которое программа оставляет операционной системе при
завершении: `0` — успех, всё остальное — ошибка; `os.Exit(1)` сразу останавливает программу с кодом 1. **Стандартный поток
ошибок** (*standard error*, `os.Stderr`) — отдельный вывод для сообщений; `fmt.Fprintln(os.Stderr, …)` пишет туда.

Сначала один вопрос по прошлому уроку. Какое число этот цикл выведет на экран?

```go
total := 0
for i := 1; i <= 4; i++ {
	if i == 3 {
		continue
	}
	total += i
}
fmt.Println(total)
```

**A)** 10 · **B)** 7 · **C)** 3

<details>
<summary>Ответ</summary>

**B: 7.** При `i` = 1, 2 и 4 значение прибавляется к `total`. При `i` = 3 `continue` пропускает остаток тела, и цикл
переходит к `i++`:

| `i` | `i == 3` | `total` |
|---|---|---|
| 1 | `false` | 1 |
| 2 | `false` | 3 |
| 3 | `true` → `continue` | 3 |
| 4 | `false` | 7 |

**A** (10) — ответ без учёта `continue`: 1 + 2 + 3 + 4. **C** (3) — вы приняли `continue` за `break`: если бы цикл
закончился на 3, сложились бы только 1 + 2.

</details>

## `os.Args`: слова из терминала попадают в программу

Сначала на месте `main.go` временно пишем маленькую пробную программу; код чека bozor вернётся позже. Теперь нужны два
пакета, поэтому после `import` открываем скобку и пишем каждый пакет на отдельной строке. Это обычный способ подключить
несколько пакетов ([Go spec: Import declarations](https://go.dev/ref/spec#Import_declarations)).

```go filename="_video/01-args/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
)

func main() {
	fmt.Println(len(os.Args), os.Args)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–6 | `import (` … `)` | групповой импорт: несколько пакетов в скобках, каждый на своей строке |
| 4 | `"fmt"` | пакет вывода на экран (GB-1.01) |
| 5 | `"os"` | стандартный пакет для работы с операционной системой (GB-1.01) |
| 9 | `os.Args` | **аргументы командной строки** (*command-line arguments*): список слов, набранных в терминале при запуске программы, начиная с имени программы |
| 9 | `len(os.Args)` | `len(…)` возвращает число элементов в списке |
| 9 | `fmt.Println(len(os.Args), os.Args)` | выводит сначала число, потом сам список |

Запускаем программу с тремя словами: `add`, `olma` и `12000`.

```console
$ ./_video/run.sh 01-args add olma 12000
4 [./bozor add olma 12000]
(chiqish kodi: 0)
```

Сначала вывелось `4`: в списке четыре элемента. Потом `Println` вывел список в квадратных скобках, разделив элементы
пробелами. Первый элемент — сама программа, так, как она была набрана в терминале: `./bozor`. pkg.go.dev говорит то же
самое: «Args hold the command-line arguments, starting with the program name»
([os.Args](https://pkg.go.dev/os#pkg-variables)).

Откуда берутся эти слова? **Shell** в терминале — программа, которая читает команду, — делит строку на слова по пробелам;
исключение — то, что стоит в кавычках. Операционная система передаёт эти слова программе, и они попадают в `os.Args`.
К каждому элементу обращаются по его месту: `os.Args[3]`. Число в квадратных скобках — **индекс** (*index*), счёт
начинается с нуля:

| Элемент | Значение | Что это |
|---|---|---|
| `os.Args[0]` | `"./bozor"` | имя программы |
| `os.Args[1]` | `"add"` | команда |
| `os.Args[2]` | `"olma"` | название товара |
| `os.Args[3]` | `"12000"` | цена — но **текст**, а не число |

`len(os.Args)` = 4, значит допустимые индексы — 0, 1, 2 и 3. Правило спецификации: индекс `x` допустим, если
`0 <= x < len(a)` ([Go spec: Index expressions](https://go.dev/ref/spec#Index_expressions)). Самое важное: все четыре
элемента — текст (`string`), и `12000` тоже. Тип `os.Args` — `[]string`, то есть список строк (**слайс**, *slice*);
устройство слайса разберём в [GB-2.01](/lab/youtube/gb#gb-2-01), сегодня хватит индекса и `len`.

## Всё, что приходит из терминала, — текст

Проверим. Переменная `price` получает `os.Args[3]`, а следующая строка прибавляет к ней единицу и выводит результат.
Команда та же: `add olma 12000`.

```go filename="_video/02-plus-xato/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
)

func main() {
	price := os.Args[3]
	fmt.Println(price + 1)
}
```

Что выведется?

**A)** `12001` · **B)** тексты склеятся: `120001` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**C: программа не собирается.** `price` — `string`, а `1` — целое число, тип которого ещё не выбран (*untyped*
константа из GB-1.03). `+` складывает только значения одного типа (GB-1.04). Если вы выбрали **A**, вы думали, что Go сам
превращает текст в число: не превращает. В **B** предполагается, что `+` склеивает тексты: так бывает, только когда обе
стороны — `string`, а `1` — не текст.

</details>

```console
$ ./_video/run.sh 02-plus-xato add olma 12000
# github.com/abdurahmon27/bozor
./main.go:10:14: invalid operation: price + 1 (mismatched types string and untyped int)
```

Первая строка — в каком модуле ошибка (GB-1.04). Вторая: `main.go`, **строка 10, столбец 14** (с этого столбца начинается
`price`). `invalid operation: price + 1` — «недопустимая операция»; `mismatched types string and untyped int` — «типы не
совпадают: `string` и `int` без выбранного типа». Программа не собралась, поэтому и не запустилась: скрипт не дошёл до
строки `(chiqish kodi …)`. Коротко: цену из терминала нужно превратить в число до того, как с ней считать.

## `strconv.Atoi`: число из текста и `error`

Для этого в стандартной библиотеке есть пакет `strconv`. Имя — от *string conversion*, то есть «преобразование текста».
`strconv.Atoi` — функция из него: делает из текста целое число (`int`). Её полное объявление на pkg.go.dev:
`func Atoi(s string) (int, error)` ([strconv.Atoi](https://pkg.go.dev/strconv#Atoi)). Два типа в последних скобках
означают, что `Atoi` **возвращает два значения**: число и ошибку.

```go filename="_video/03-atoi/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"strconv"
)

func main() {
	price, err := strconv.Atoi(os.Args[3])
	fmt.Println(price, err)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `"strconv"` | стандартный пакет, который преобразует текст в числа и другие типы |
| 10 | `strconv.Atoi(os.Args[3])` | пытается превратить текст `"12000"` в `int` |
| 10 | `price, err :=` | для двух результатов слева два имени через запятую: `price` — число, `err` — ошибка. `:=` объявляет обе сразу (GB-1.02) |
| 11 | `fmt.Println(price, err)` | выводит оба значения через пробел |

С `12000` в памяти появляются два ярлыка:

| Ярлык | Тип | Значение |
|---|---|---|
| `price` | `int` | `12000` |
| `err` | `error` | `nil` — ошибки нет |

**`error`** — тип ошибки в Go, заранее объявленный тип ([Go spec: Errors](https://go.dev/ref/spec#Errors)).
**`nil`** — его пустое значение, то есть «ошибки нет». `Println` выводит ошибку `nil` в угловых скобках: `<nil>`.
Теперь попробуем два ввода — `12000` и `12k`:

```console
$ ./_video/run.sh 03-atoi add olma 12000
12000 <nil>
(chiqish kodi: 0)
$ ./_video/run.sh 03-atoi add olma 12k
0 strconv.Atoi: parsing "12k": invalid syntax
(chiqish kodi: 0)
```

С `12k` `price` равен `0`, а `err` — текст ошибки. Разберём его по частям: `strconv.Atoi` — какая функция; `parsing "12k"`
— какой текст она читала (в кавычках); `invalid syntax` — причина: «неверная запись», это не запись числа
([strconv.NumError](https://pkg.go.dev/strconv#NumError)). Обратите внимание: программа не остановилась, код выхода `0`.
Ошибка вернулась таким же обычным значением, как `price`. Проверить её — задача вызывающего кода.

## `Atoi` проверяет только запись

Теперь вместо цены передадим `-5`. Что выведется?

**A)** `-5 <nil>` · **B)** `0` и `invalid syntax` · **C)** `0` и ошибка «цена отрицательная»

<details>
<summary>Ответ</summary>

**A: `-5 <nil>`.** `Atoi` проверяет только запись, а `-5` — правильная запись числа: «The string may begin with a leading
sign» ([strconv.ParseInt](https://pkg.go.dev/strconv#ParseInt); `Atoi` — краткая форма `ParseInt(s, 10, 0)`). Если вы
выбрали **B**, вы думали, что знак минус запрещён. В **C** предполагается, что `Atoi` что-то знает о цене: то, что цена
должна быть положительной, — наше правило, его мы напишем сами.

</details>

```console
$ ./_video/run.sh 03-atoi add olma -5
-5 <nil>
(chiqish kodi: 0)
```

Ещё один случай: двадцать девяток. На этом компьютере `int` 64-битный, такое число в него не помещается.

```console
$ ./_video/run.sh 03-atoi add olma 99999999999999999999
9223372036854775807 strconv.Atoi: parsing "99999999999999999999": value out of range
(chiqish kodi: 0)
```

`price` — не `0`! `9223372036854775807` — примерно 9,2 квинтиллиона, наибольшее значение 64-битного `int`. А `err` —
`value out of range`: «значение вне допустимого диапазона». Так написано в документации: при выходе за границу
`err.Err = ErrRange`, а возвращаемое значение — наибольшее число этого типа
([strconv.ParseInt](https://pkg.go.dev/strconv#ParseInt)). Отсюда правило:

> Если `err` не `nil`, не доверяйте первому значению: сначала проверьте `err`.

| Ввод | `price` | `err` | Можно ли доверять `price` |
|---|---|---|---|
| `12000` | `12000` | `<nil>` | да |
| `12k` | `0` | `invalid syntax` | нет: `0` — не настоящая цена |
| `-5` | `-5` | `<nil>` | запись верная, но правило цены проверяем сами |
| двадцать `9` | `9223372036854775807` | `value out of range` | нет: это граничное число, а не то, что ввёл пользователь |

## `if err != nil`, поток ошибок и код выхода

Проверка пишется так:

```go filename="_video/04-iferr/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"strconv"
)

func main() {
	price, err := strconv.Atoi(os.Args[3])
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println("narx:", price)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 11 | `if err != nil {` | `!=` — «не равно» (GB-1.05): если ошибка есть, выполняются строки внутри `{ }` |
| 12 | `fmt.Fprintln(os.Stderr, "xato:", err)` | `Fprintln` — как `Println`, только первым аргументом получает, **куда** писать; `os.Stderr` — стандартный поток ошибок; `xato` — «ошибка» |
| 13 | `os.Exit(1)` | сразу останавливает программу и возвращает операционной системе код выхода `1` |
| 15 | `fmt.Println("narx:", price)` | выполняется, только когда `err == nil`: тогда тело `if` пропущено (`narx` — «цена») |

Два новых понятия:

- **Стандартный поток ошибок** (*standard error*, `stderr`). У программы два отдельных вывода: **стандартный вывод**
  (*standard output*, `os.Stdout`; туда пишет `fmt.Println`) для обычного результата и стандартный поток ошибок для
  сообщений. Терминал показывает оба. Но если скрипт записывает результат в файл, сообщение об ошибке не смешивается с
  файлом и остаётся на экране. Ниже увидим это на bozor.
- **Код выхода** (*exit code*). Число, которое программа оставляет операционной системе при завершении. «Conventionally,
  code zero indicates success, non-zero an error» ([os.Exit](https://pkg.go.dev/os#Exit)). В терминале `echo $?` выводит
  код выхода последней команды ([bash: Special Parameters](https://www.gnu.org/software/bash/manual/bash.html#Special-Parameters)).
  Скрипты и CI — сервер, который автоматически проверяет код, — смотрят именно на это число.

С `12k` и `12000`:

```console
$ ./_video/run.sh 04-iferr add olma 12k
```

## `func parsePrice`: правило цены в одном месте

Правило цены растёт: это должно быть число, положительное, переведённое в тийины. Выносим его в отдельную **функцию**
(*function*): `main` остаётся коротким, а в следующем уроке функцию можно будет протестировать отдельно. Первая строка —
объявление функции, или её **сигнатура** (*signature*):

```go
func parsePrice(s string) (int64, error) {
```

| Часть | Что это |
|---|---|
| `func` | объявляется функция (`func main` из GB-1.01 устроен так же) |
| `parsePrice` | имя функции: «прочитать цену» |
| `(s string)` | **параметр** (*parameter*): сначала имя `s`, потом тип `string`. Значение, переданное при вызове, — **аргумент** — попадает в это имя |
| `(int64, error)` | **результаты** (*results*): два возвращаемых значения — цена в тийинах (`int64`, GB-1.03) и ошибка |
| `{` | начинается тело функции |

В Go принято: `error` всегда последний результат. У `strconv.Atoi` так же: `(int, error)`. Тело:

```go
func parsePrice(s string) (int64, error) {
	som, err := strconv.Atoi(s)
	if err != nil {
		return 0, err
	}
	return int64(som) * tiyinPerSom, nil
}
```

| Строка | Код | Что делает |
|---|---|---|
| 2 | `som, err := strconv.Atoi(s)` | превращает `s` в число; результат — в `som` («сум»), ошибка — в `err` |
| 3–5 | `if err != nil { return 0, err }` | при ошибке возвращаются `0` и та же `err` |
| 6 | `return int64(som) * tiyinPerSom, nil` | без ошибки: переводим `som` в `int64` и умножаем на `tiyinPerSom` (100); на месте ошибки `nil` |

**`return`** в GB-1.05 останавливал `main`. Здесь он завершает функцию и возвращает значения **вызывающему коду**
(*caller*), то есть коду, который вызвал функцию ([Go spec: Return statements](https://go.dev/ref/spec#Return_statements)).
После `return` число и порядок результатов должны совпадать с сигнатурой: сначала `int64`, потом `error`.

Проследим в памяти вызов `parsePrice("12000")`:

| Шаг | Строка | `s` (`string`) | `som` (`int`) | `err` (`error`) | Что происходит |
|---|---|---|---|---|---|
| вызов | 1 | `"12000"` | | | `s` получает **копию** аргумента |
| `Atoi` | 2 | `"12000"` | `12000` | `nil` | текст стал числом |
| `if` | 3 | | | | `err != nil` — `false`: тело `if` пропускается |
| `return` | 6 | | | | возвращается `1200000, nil`: 12 000 сумов = 1 200 000 тийинов |

`s`, `som` и `err` существуют только внутри этого вызова: как только функция завершается, они исчезают. Спецификация:
аргументы вызова передаются функции и присваиваются соответствующим параметрам
([Go spec: Calls](https://go.dev/ref/spec#Calls)).

**Второе правило: цена положительная.** Мы видели, что `Atoi` принимает `-5` без ошибки, `0` проходит точно так же. Но
цена должна быть положительной. Если `som` меньше или равен нулю, создаём ошибку сами:

```go
	if som <= 0 {
		return 0, fmt.Errorf("narx musbat boʻlishi kerak, keldi %d", som)
	}
```

(«цена должна быть положительной, пришло %d».) **`fmt.Errorf`** заполняет шаблон, как `fmt.Sprintf` из GB-1.04 (вместо
`%d` подставляется `som`), только возвращает результат не как `string`, а как `error`
([fmt.Errorf](https://pkg.go.dev/fmt#Errorf)). Эти три функции работают с одним и тем же шаблоном, разница в результате:

| Функция | Что делает с результатом |
|---|---|
| `fmt.Printf` | пишет на экран |
| `fmt.Sprintf` | возвращает `string` |
| `fmt.Errorf` | возвращает `error` |

Полная `parsePrice` стоит в строках 14–24 следующего файла.

## Собираем всё в bozor

Возвращаем код чека. Начало — bozor из конца GB-1.06: стартовые строки, объявленные через `var` `name`, `price` и

```go filename="_video/05-panic/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"strconv"
)

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)
const maxFree = 2          // bitta buyurtmada koʻpi bilan shuncha dona bepul

// parsePrice soʻmdagi narx matnini tiyinga oʻgiradi.
func parsePrice(s string) (int64, error) {
	som, err := strconv.Atoi(s)
	if err != nil {
		return 0, err
	}
	if som <= 0 {
		return 0, fmt.Errorf("narx musbat boʻlishi kerak, keldi %d", som)
	}
	return int64(som) * tiyinPerSom, nil
}

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = os.Args[2]
	price, err := parsePrice(os.Args[3]) // tiyinda
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 7
	if name == "" {
		fmt.Println("xato: mahsulot nomi boʻsh")
		return
	}
	if !active {
		fmt.Printf("xato: %s sotuvda emas\n", name)
		return
	}
	if price > 10_000_000*tiyinPerSom { // price <= 0 endi parsePrice ichida
		fmt.Printf("xato: narx notoʻgʻri: %d tiyin\n", price)
		return
	}
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)

	var subtotal int64
	free := 0
	for i := 1; i <= sold; i++ {
		if i%3 == 0 && free < maxFree {
			free++
			continue // aksiya: har uchinchi dona bepul
		}
		subtotal += price
	}
	vat := subtotal * vatPercent / 100

	var delivery int64 // tiyinda
	switch {
	case subtotal >= 500_000*tiyinPerSom:
		delivery = 0
	case subtotal >= 100_000*tiyinPerSom:
		delivery = 10_000 * tiyinPerSom
	default:
		delivery = deliverySom * tiyinPerSom
	}
	total := subtotal + vat + delivery

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", delivery/tiyinPerSom, delivery%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
	if free > 0 {
		fmt.Printf("aksiya: %d dona bepul\n", free)
	}
}
```

только при `base` 0, а `Atoi` работает в десятичной системе: [strconv.ParseInt](https://pkg.go.dev/strconv#ParseInt)).
Если вы выбрали **A**, вы думали, что `Atoi` читает по правилам кода Go. **C** — компилятор вообще не видит текст,
введённый пользователем: программа уже собрана.

</details>

## Ловушка: индекс без проверки длины

Теперь классическая ошибка. В файле выше проверки длины нет. Забываем цену и пишем только `add olma`:

```console
$ ./_video/run.sh 05-panic add olma
bozor ishga tushdi
versiya: 0.1.0
 0 false
panic: runtime error: index out of range [3] with length 3

goroutine 1 [running]:
main.main()
	/tmp/tmp.0oNT412J6V/bozor/main.go:36 +0x953
(chiqish kodi: 2)
```

После стартовых строк программа упала с **panic**. Panic — аварийная ситуация, которая сразу останавливает программу на Go;
её разберём в [GB-2.09](/lab/youtube/gb#gb-2-09). Читаем сообщение:

| Строка | Смысл |
|---|---|
| `panic: runtime error:` | ошибка произошла во время работы программы (*runtime*) |
| `index out of range [3] with length 3` | «индекс 3 вне диапазона, длина 3»: в `os.Args` три элемента (`./bozor`, `add`, `olma`), места 0, 1 и 2; места 3 нет |
| `goroutine 1 [running]:` и `main.main()` | где остановилась: функция `main` пакета `main` (слово *goroutine* разберём в GB-7.01) |
| `…/bozor/main.go:36 +0x953` | `main.go`, **строка 36** — строка `price`, где стоит `os.Args[3]`. `/tmp/tmp.…` в начале — временная папка скрипта, её имя каждый раз другое |
| `(chiqish kodi: 2)` | программа на Go, упавшая с panic, завершается с кодом 2 |

`os.Args[2]` в строке 35 сработал без проблем: `olma` есть. А `os.Args[3]` в строке 36 — обращение к несуществующему месту:
по спецификации, если индекс во время выполнения выходит за границы, происходит *run-time panic*
([Go spec: Run-time panics](https://go.dev/ref/spec#Run_time_panics)). Компилятор не может знать этого заранее: число слов
известно только при запуске.

**Исправление: проверяем длину до индекса.** Если элементов не четыре или первое слово не `add`, выводим строку
использования (`foydalanish` — «использование», `NOM NARX` — «НАЗВАНИЕ ЦЕНА») и выходим с кодом 1. `main.go` в папке — файл
выше плюс эти четыре строки:

```console
$ diff _video/05-panic/main.go main.go
34a35,38
> 	if len(os.Args) != 4 || os.Args[1] != "add" {
> 		fmt.Fprintln(os.Stderr, "foydalanish: bozor add NOM NARX")
> 		os.Exit(1)
> 	}
```

`34a35,38` — «после строки 34 новые строки 35–38». `||` — «или» (GB-1.05), и он вычисляется слева направо: если левая
часть `true`, правая не вычисляется вовсе ([Go spec: Logical operators](https://go.dev/ref/spec#Logical_operators)).
Поэтому обращение к `os.Args[1]` безопасно, даже когда элементов мало: `len(os.Args) != 4` уже `true`.

| Команда | `len(os.Args)` | `len(os.Args) != 4` | `os.Args[1] != "add"` | Результат |
|---|---|---|---|---|
| `./bozor` | 1 | `true` | не вычисляется | строка использования |
| `./bozor add olma` | 3 | `true` | не вычисляется | строка использования |
| `./bozor sell olma 12000` | 4 | `false` | `true` | строка использования |
| `./bozor add olma 12000` | 4 | `false` | `false` | чек |

Теперь та же команда даёт не panic, а строку использования:

(`>` — команда shell: направляет стандартный вывод программы в файл; `cat` выводит файл на экран; `natija` — «результат»):


результат bozor в файл, не смешивает ошибки с результатом, а `echo $?` говорит, что работа завершилась неудачей.

Если в названии есть пробел, пишите его в кавычках: shell сделает из него одно слово, и `os.Args[2]` = `oʻrik qoqi`

## Частые ошибки

**1. Доверять значению при ошибке (ошибки не видно).** Самое частое неверное представление: «если `Atoi` не справилась,
значение будет `0`, его можно использовать». Выше мы видели: при выходе за границу `Atoi` возвращает
`9223372036854775807`, а для `12k` — `0`, которое не является настоящей ценой. В обоих случаях программа не
останавливается, а чек вышел бы с неверной ценой. Исправление: всегда `if err != nil` до значения (см. таблицу в разделе
«`Atoi` проверяет только запись»).

**2. Получить `err` и не проверить.** Пример, которого нет в папке: `err` получена, но нигде не используется.

```go
package main

import (
	"fmt"
	"os"
	"strconv"
)

func main() {
	price, err := strconv.Atoi(os.Args[3])
	fmt.Println("narx:", price)
}
```

```console
$ go build
# github.com/abdurahmon27/bozor
./main.go:10:9: declared and not used: err
```

`main.go`, строка 10, столбец 9 — `err`. `declared and not used: err` — «`err` объявлена, но не используется». Go отклоняет
неиспользуемую переменную внутри функции ([Go spec: Variable declarations](https://go.dev/ref/spec#Variable_declarations)),
поэтому «забыть» ошибку не получится: код не скомпилируется. Исправление: `if err != nil { … }` до `price`.

**3. `:=`, когда слева не осталось новых имён.** Так будет, если в задании оставить строку `sold := 7` и добавить под ней
`sold, err := …`. Пример, которого нет в папке:

```go
package main

import (
	"fmt"
	"os"
	"strconv"
)

func main() {
	price, err := strconv.Atoi(os.Args[3])
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	sold := 7
	sold, err := strconv.Atoi(os.Args[4])
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println(price, sold)
}
```

```console
$ go build
# github.com/abdurahmon27/bozor
./main.go:16:12: no new variables on left side of :=
```

Строка 16, столбец 12 — `:=`. `no new variables on left side of :=` — «слева от `:=` нет новых переменных»: `sold` объявлена
в строке 15, `err` — в строке 10. Для `:=` слева нужно хотя бы одно новое имя. Исправление: удалите строку `sold := 7`;
тогда `sold` станет новым именем, и `sold, err := …` заработает (`err` просто получит новое значение).

**4. `os.Args[3]` без проверки длины.** `panic: runtime error: index out of range [3] with length 3` и код выхода 2.
См. раздел о ловушке выше. Исправление: перед индексом `if len(os.Args) != 4 || … { … os.Exit(1) }`.

**5. Считать с текстом из терминала.** `os.Args[3] + 1` — `mismatched types string and untyped int` (раздел «Всё, что
приходит из терминала, — текст»). Исправление: сначала `strconv.Atoi`, затем проверка `err`, затем расчёт.
