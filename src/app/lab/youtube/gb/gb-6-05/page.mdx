## Nimani oʻrganasiz

GB-6.04 da bozor har himoyalangan soʻrovda session yozuvini qidiradi. Keng tarqalgan muqobili — JWT: bazaga murojaat qilmasdan tekshiriladigan token. Qaysi biri toʻgʻri? Bugun ikkalasini bir xil soʻrovlarda sinab koʻramiz.

**Bitta gʻoya:** JWT — nuqta bilan ulangan uch qism, `header.payload.imzo`. Imzo — birinchi ikki qismning kalitli HMAC-SHA256 hisobi. Server uni qayta hisoblab tekshiradi, shuning uchun hech narsa saqlamaydi. Aynan shu sababli logout oʻchiradigan yozuv ham yoʻq: oʻgʻirlangan JWT `exp` muddatigacha ishlaydi, session esa yozuv oʻchgan zahoti oʻladi. JWTni bekor qilish (denylist yoki refresh token) yana server holatini qaytaradi.

Dars oxirida siz:

- JWTni kutubxonasiz yasab, payloadni kalitsiz oʻqiysiz;
- `golang-jwt/jwt/v5` bilan toʻrt qoida asosida tekshirasiz va qoidasiz `Parse` nimani oʻtkazishini koʻrasiz;
- logoutdan keyin eski cookie `401`, oʻsha JWT esa `200` ekanini oʻz ekraningizda koʻrasiz;
- bekor qilishning narxini aytib, bozor uchun tanlovni asoslaysiz va `jti` denylistni `go test` oʻtguncha yozasiz.

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| JWT | nuqta bilan ulangan uch qism: header, payload, imzo | JSON Web Token |
| imzo | birinchi ikki qismning kalit bilan hisoblangan HMAC natijasi | signature |
| tokenni bekor qilish | token muddatidan oldin rad etilishi uchun serverda belgi saqlash | token revocation |

Ikki yordamchi: **base64url** — baytlarni harf, raqam, `-` va `_`dan iborat matnga aylantirish; **HMAC** — kalit bilan hisoblanadigan hash, kalitsiz uni hisoblab boʻlmaydi. Ikkalasi quyida kodda koʻrinadi. **Claim** — payloaddagi maydon: token kim va nima haqida ekanini aytadi.

## JWT ichida nima bor

**JWT** (JSON Web Token, [RFC 7519](https://www.rfc-editor.org/rfc/rfc7519)) — nuqta bilan ulangan uch qism. Har qism base64url matni.

```text
header . payload . imzo
```

| Qism | Ichida | Vazifasi |
|---|---|---|
| header | `{"alg":"HS256","typ":"JWT"}` | `alg` — imzo algoritmi (`HS256` — HMAC va SHA-256), `typ` — token turi |
| payload | claim'lar | token kim va nima haqida |
| imzo | HMAC natijasi | birinchi ikki qismni kalit bilan bogʻlaydi |

Bu darsdagi payloadda toʻrt claim bor:

| Claim | Inglizcha | Maʼnosi | Bozorda |
|---|---|---|---|
| `sub` | subject | token kim haqida | foydalanuvchi ID: `1` |
| `iss` | issuer | kim bergan | `bozor` |
| `aud` | audience | kim uchun | `bozor-api` |
| `exp` | expiration time | shu vaqtdan boshlab token qabul qilinmaydi | hozir + 15 daqiqa |

`exp` Unix vaqtda yoziladi: 1970-01-01 00:00:00 UTC dan beri oʻtgan soniyalar soni ([RFC 7519 §2, NumericDate](https://www.rfc-editor.org/rfc/rfc7519#section-2)). Kutubxona tokenga yana ikki claim qoʻshadi: `iat` (issued at, berilgan vaqt) va `jti` (JWT ID, tokenning noyob ID'si).

RFC 7519 JWTni ikki shaklda tasvirlaydi: imzolangani (JWS, uch qism) va shifrlangani (JWE, [besh qism](https://www.rfc-editor.org/rfc/rfc7516#section-3.1)). Bu dars faqat imzolangan JWT haqida; bozor shuni beradi.

## JWTni qoʻlda yasaymiz

Avval kutubxonasiz yasaymiz: har bayt koʻrinsin. `cmd/qolda/main.go` tokenni yasab, uch qismini alohida qatorda chiqaradi.

```go filename="cmd/qolda/main.go" showLineNumbers
// qolda — HS256 imzoli JWT'ni kutubxonasiz yasaydi va uch qismini alohida qatorda chiqaradi (GB-6.05).
// Token: header.payload.imzo — uchala qism nuqta bilan ulanadi. Kalit har ishga tushishda yangi.
//
//	go run ./cmd/qolda
package main

import (
	"fmt"
	"strings"
	"time"

	"github.com/abdurahmon27/bozor/internal/token"
)

func main() {
	key := token.NewKey()
	exp := time.Now().Add(15 * time.Minute).Unix() // Unix vaqt: 1970-01-01 UTC'dan beri soniyalar (RFC 7519 §2: NumericDate)
	header := `{"alg":"HS256","typ":"JWT"}`
	payload := fmt.Sprintf(`{"sub":"1","iss":"bozor","aud":"bozor-api","exp":%d}`, exp)
	t := token.SignHS256(header, payload, key)

	parts := strings.Split(t, ".")
	fmt.Println("header: ", parts[0])
	fmt.Println("payload:", parts[1])
	fmt.Println("imzo:   ", parts[2])
}
```

|---|---|---|

| 5–13 | `package main`, `import` | bu ishga tushiriladigan dastur; kerakli paketlar: `fmt`, `strings`, `time` va bizning `internal/token` |

| 17 | `exp := time.Now().Add(15 * time.Minute).Unix()` | `Now()` hozirgi lahza, `Add` unga 15 daqiqa qoʻshadi, `Unix()` lahzani Unix vaqt soniyalariga aylantiradi |
| 18 | ``header := `\{"alg":"HS256","typ":"JWT"\}` `` | backtick ichidagi matn — tayyor JSON (GB-3.02); ichidagi qoʻshtirnoqni `\` bilan yozish shart emas |
| 19 | `payload := fmt.Sprintf(…, exp)` | `Sprintf` `%d` oʻrniga `exp` sonini qoʻyib matn yasaydi (GB-1.04) |

Endi `SignHS256` ichida. U `internal/token/qolda.go` faylida. Avval yordamchi `b64`: baytlarni base64url matniga aylantiradi.

```go filename="internal/token/qolda.go" showLineNumbers
// Package token — bozor'ning JWT'lari (GB-6.05).
//
// qolda.go: HS256 imzoli JWT'ni kutubxonasiz, qoʻlda yasash — har bayti koʻrinsin deb (RFC 7519, RFC 7515).
// token.go: ishdagi yoʻl — golang-jwt/jwt/v5 bilan yasash va qatʼiy tekshirish (RFC 8725).
package token

import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/base64"
)

// b64 — base64url, "="siz (RFC 7515 §2: Base64url Encoding, padding yoʻq).
// Alifbo: A–Z a–z 0–9 - _ ; oddiy base64'dagi + va / oʻrniga - va _, shuning uchun URL va sarlavhada xavfsiz.
func b64(b []byte) string {
	return base64.RawURLEncoding.EncodeToString(b)
}

// SignHS256 — JWT'ni qoʻlda yasaydi: base64url(header) . base64url(payload) . base64url(imzo).
// Imzo — nuqtagacha boʻlgan matnning HMAC-SHA256'i, kalit bilan (RFC 7518 §3.2).
// header va payload — tayyor JSON matnlar; ular shifrlanmaydi, faqat imzolanadi.
func SignHS256(header, payload string, key []byte) string {
	input := b64([]byte(header)) + "." + b64([]byte(payload))
	mac := hmac.New(sha256.New, key)
	mac.Write([]byte(input))
	return input + "." + b64(mac.Sum(nil))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 5 | `package token` | `internal/token` papkasi shu nomli paket (GB-2.06) |
| 7–11 | `import` | `crypto/hmac` va `crypto/sha256` — imzo uchun; `encoding/base64` — matn uchun |
| 15–17 | `func b64(b []byte) string` | baytlarni oladi, matn qaytaradi. `RawURLEncoding` — URL alifbosi (`A–Z a–z 0–9 - _`), oxirida `=` yoʻq; shuning uchun token URLda ham, sarlavhada ham buzilmaydi. `EncodeToString` natijani `string` qilib beradi |
| 22 | `func SignHS256(header, payload string, key []byte) string` | ikki matn va kalit baytlari kiradi, token matni chiqadi |
| 23 | `input := b64([]byte(header)) + "." + b64([]byte(payload))` | `[]byte(…)` matnni baytlarga aylantiradi (GB-2.07); `b64` kodlaydi; `+` nuqta bilan ulaydi. Bu imzolanadigan matn |
| 24 | `mac := hmac.New(sha256.New, key)` | kalitli hash hisoblagichi. `sha256.New` qavssiz: funksiyaning oʻzi beriladi, `hmac` uni kerak boʻlganda chaqiradi |
| 25 | `mac.Write([]byte(input))` | imzolanadigan matnni hisoblagichga beradi |
| 26 | `return input + "." + b64(mac.Sum(nil))` | `Sum(nil)` natijani — 32 bayt — yangi slice'da qaytaradi. `b64` uni matn qiladi: bu uchinchi qism |

Token shunday hisoblanadi:

| Qadam | Nima | Qiymat |
|---|---|---|
| 1 | `b64(header)` | `eyJhbGci…` |
| 2 | `b64(payload)` | payload JSON matnining base64url koʻrinishi |
| 3 | `input` | 1 + `.` + 2 |
| 4 | `HMAC-SHA256(kalit, input)` | 32 bayt |
| 5 | `b64(32 bayt)` | 43 belgi: bu imzo |
| 6 | token | `input` + `.` + imzo |

Ishga tushiramiz:

```console
$ go run ./cmd/qolda
header:  eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
payload: eyJzdWIiOiIxIiwiaXNzIjoiYm96b3IiLCJhdWQiOiJib3pvci1hcGkiLCJleHAiOjE3OTU4NTg0OTh9
imzo:    C1q-jEJddLMip5WA-QKKdF8byGpmxhY4SR4JpBQ51TY
```

Uch qator: ekranda `header`, `payload` va `imzo` alohida, tokenda esa nuqta bilan ulangan. Imzo 43 belgi: 32 baytning base64url koʻrinishi. Sizda `payload` va `imzo` boshqacha: `exp` va kalit boshqa.

Odatda JWT `eyJ` bilan boshlanadi. Sabab: header JSON matni `{"alg"…` bilan boshlanadi. Uning base64url koʻrinishi — `eyJhbGci…`. `eyJ` — `{"` va keyingi harfning boshi. Header `{` dan keyin boʻsh joy bilan yozilsa, boshlanish boshqa boʻladi. Bu `basenc` bilan koʻrinadi; `basenc` — GNU coreutils buyrugʻi, `--base64url` bilan kodlaydi. `printf` matnni yangi qatorsiz chiqaradi:

```console
$ printf '{"alg"' | basenc --base64url
eyJhbGci
$ printf '{ "alg"' | basenc --base64url
eyAiYWxnIg==
```

`basenc` oxiriga `=` toʻldiruvchisini qoʻygan (`==`). JWT uni olib tashlaydi: `RawURLEncoding` aynan shuni qiladi. `basenc` yangi qator chiqarmaydi, shuning uchun terminalda keyingi buyruq qatori oʻsha satrda boshlanishi mumkin.

## Payload shifrlanmagan

Kalitni bilmagan odam payload qatorini oʻqiy oladimi? **A)** yoʻq: u shifrlangan · **B)** ha: bu faqat base64url · **C)** faqat imzo ham boʻlsa.

<details>
<summary>Javob</summary>

**B.** Base64url kodlash — shifrlash emas: kalitsiz qaytariladi. **A** deb oʻylagan boʻlsangiz, kodlashni shifrlash bilan adashtirgansiz. **C** da imzo payloadni yashirmaydi; u faqat oʻzgarmaganini tekshirishga yordam beradi.

</details>

`echo` qatorni chiqaradi, `|` uni keyingi buyruqqa beradi, `basenc --base64url -d` esa `-d` bilan qaytaradi (decode):

```console
$ echo eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9 | basenc --base64url -d
{"alg":"HS256","typ":"JWT"}
$ echo eyJzdWIiOiIxIiwiaXNzIjoiYm96b3IiLCJhdWQiOiJib3pvci1hcGkiLCJleHAiOjE3OTU4NTg0OTh9 | basenc --base64url -d
{"sub":"1","iss":"bozor","aud":"bozor-api","exp":1795858498}
```

Kalit kerak boʻlmadi: claim'lar ochiq matn. Shuning uchun JWTga sir — parol, shaxsiy maʼlumot — yozilmaydi. Imzo faqat shuni kafolatlaydi: matnni kalitni biladigan kimdir yozgan va u oʻzgarmagan. OWASP: HS256 imzosi tokenni umumiy sirni bilgan kimdir yasaganini isbotlaydi, xolos ([OWASP JWT Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/JSON_Web_Token_Cheat_Sheet.html)).

## Server imzoni qayta hisoblaydi

Tekshiruvda server `SignHS256`dagi hisobni qaytadan qiladi:

```text
token  =  header . payload . imzo
          \_______  _______/    |
                  \/            |
     HMAC-SHA256(server kaliti)  |
                  |              |
          hisoblangan imzo  ==  tokendagi imzo ?
                  |
     ha   → payloadga ishonadi, bazaga borilmaydi
     yoʻq → token rad etiladi
```

Bitta harf oʻzgarsa, HMAC butunlay boshqa chiqadi. Server hech narsa qidirmaydi: yetarli narsa tokenning oʻzida va serverdagi kalitda. Kutubxona solishtirishni `hmac.Equal` bilan, doimiy vaqtda qiladi ([golang-jwt/jwt v5.3.1 manba kodi](https://github.com/golang-jwt/jwt/blob/v5.3.1/hmac.go)).

## Kutubxona va toʻrt qoida

Ishda tekshiruvni qoʻlda yozmaysiz. [RFC 8725](https://www.rfc-editor.org/rfc/rfc8725) — JWT boʻyicha eng yaxshi amaliyotlar — odatiy xatolarni sanaydi: headerdagi `alg`ga ishonish, `iss` va `aud`ni tekshirmaslik. Biz [golang-jwt/jwt](https://github.com/golang-jwt/jwt/releases), beshinchi versiyani olamiz: u faol yuritiladi. `go get` GB-2.06 dagidek, versiya aniq yoziladi:

```console
$ go get github.com/golang-jwt/jwt/v5@v5.3.1
go: added github.com/golang-jwt/jwt/v5 v5.3.1
```

Bu chiqish yangi boʻsh modulda olingan. Dars papkasida satr tayyor, shuning uchun takroriy `go get` hech narsa chiqarmaydi. Satr `go.mod`da:

```console
$ grep jwt go.mod

```

Tekshiruv `internal/token/token.go` dagi `Parse` funksiyasida:

```go
func Parse(s string, key []byte) (Claims, error) {
	rc := &jwt.RegisteredClaims{}
	_, err := jwt.ParseWithClaims(s, rc, func(*jwt.Token) (any, error) {
		return key, nil
	},
		jwt.WithValidMethods([]string{"HS256"}),
		jwt.WithIssuer(Issuer),
		jwt.WithAudience(Audience),
		jwt.WithExpirationRequired(),
	)
	if err != nil {
		return Claims{}, err
	}
	id, err := strconv.ParseInt(rc.Subject, 10, 64)
	if err != nil {
		return Claims{}, fmt.Errorf("token: sub son emas: %w", err)
	}
	c := Claims{UserID: id, JTI: rc.ID}
	if rc.ExpiresAt != nil { // WithExpirationRequired bilan doim bor; nil'ga baribir tayanmaymiz
		c.Expires = rc.ExpiresAt.Time
	}
	return c, nil
}
```

| Qator | Nima qiladi |
|---|---|

| 2 | `jwt.RegisteredClaims` — kutubxonadagi struct: standart claim'lar (`sub`, `iss`, `aud`, `exp`…) uchun maydonlari bor. `&…{}` uning manzilini beradi (GB-2.04) |
| 3–5 | `jwt.ParseWithClaims` tokenni boʻlaklaydi, payloadni `rc`ga oʻqiydi va imzoni tekshiradi. Uchinchi argument — nomsiz funksiya: kutubxona undan kalitni soʻraydi, biz oʻsha `key`ni beramiz (GB-2.09). Uning parametri `*jwt.Token` kerak emas, shuning uchun nomsiz. `any` — har qanday tur (GB-2.07) |
| 6–9 | toʻrt qoida: har biri `With` bilan boshlanadigan option. Quyida jadval |

```go
type Claims struct {
```

| Option | Nimani rad etadi | Nega kerak |
|---|---|---|
| `WithValidMethods([]string{"HS256"})` | headerda boshqa `alg`: `none`, `HS512`… | algoritmni token emas, server tanlaydi ([RFC 8725 §3.1](https://www.rfc-editor.org/rfc/rfc8725#section-3.1)) |
| `WithIssuer(Issuer)` | `iss` `bozor` emas | token beruvchini tekshirish ([§3.8](https://www.rfc-editor.org/rfc/rfc8725#section-3.8)); `Issuer` — paketdagi konstanta |
| `WithAudience(Audience)` | `aud`da `bozor-api` yoʻq | boshqa xizmat uchun berilgan token bu API'ga yaramasin ([§3.9](https://www.rfc-editor.org/rfc/rfc8725#section-3.9)) |
| `WithExpirationRequired()` | `exp` yoʻq | `exp`siz token hech qachon oʻlmaydi; kutubxonada `exp` standart boʻyicha ixtiyoriy |

`exp` bor boʻlsa, kutubxona uni doim tekshiradi: [RFC 7519 §4.1.4](https://www.rfc-editor.org/rfc/rfc7519#section-4.1.4) boʻyicha shu vaqtdan keyin token qabul qilinmaydi. `exp`ni **talab qilish** — bizning qoidamiz.

`cmd/tekshir` qoʻlda yasalgan tokenni `Parse`dan oʻtkazadi, keyin yetti holatni sinaydi. Holatlar roʻyxati:

```go
	cases := []struct{ name, tok string }{
		{"qoʻlda yasalgan", good},
		// payload'da sub 1 → 2, imzo eski: header va imzo oʻsha, faqat oʻrtadagi qism yangi.
		{"sub 1 → 2, imzo eski", parts[0] + "." + b64([]byte(claims("2", "bozor-api", exp))) + "." + parts[2]},
		// alg "none": imzo boʻsh (RFC 7519 §6: unsecured JWT).
		{"alg none, imzo yoʻq", b64([]byte(`{"alg":"none","typ":"JWT"}`)) + "." + parts[1] + "."},
		{"exp yoʻq", token.SignHS256(hs256, claims("1", "bozor-api", 0), key)},
		{"aud boshqa xizmat", token.SignHS256(hs256, claims("1", "hisobot-api", exp), key)},
		{"muddati oʻtgan", token.SignHS256(hs256, claims("1", "bozor-api", time.Now().Add(-time.Minute).Unix()), key)},
		// alg HS512, imzo shu kalit bilan TOʻGʻRI hisoblangan: algoritmni token emas, server tanlaydi.
		{"alg HS512, imzo toʻgʻri", signHS512(claims("1", "bozor-api", exp), key)},
	}
```

Har holat — nom va token matni. Birinchisi — butun token. Ikkinchisi — nusxa: `parts[0]` va `parts[2]` (header va imzo) eski, oʻrtadagi payload yangi: `sub` bir oʻrniga ikki. `alg none` tokenida imzo boʻsh ([RFC 7519 §6](https://www.rfc-editor.org/rfc/rfc7519#section-6): imzosiz JWT). Oxirgisi `HS512` bilan imzolangan, imzo shu kalit bilan toʻgʻri hisoblangan.

Ikki savol, keyin ishga tushiramiz.

**Bashorat 1:** nusxada `sub` 1 oʻrniga 2, header va imzo eski. `Parse`? **A)** `ok, sub=2` · **B)** rad: imzo notoʻgʻri · **C)** rad: payload ochilmaydi.

## Server: ikki yoʻlli authenticate

GB-6.04 dagi `requireUser` endi `authenticate`ni chaqiradi. Unda ikki yoʻl: `Authorization: Bearer <token>` sarlavhasi bor boʻlsa — JWT, aks holda cookie.

```go
func (a *api) authenticate(r *http.Request) (store.User, error) {
	if s, ok := bearer(r); ok {
		c, err := token.Parse(s, a.jwtKey)
		if err != nil {
			return store.User{}, fmt.Errorf("%w: %w", errBadToken, err)
		}
		// VAZIFA (TASK.md, 3-qadam): c.JTI denylist'da boʻlsa (a.st.TokenRevoked) — errBadToken.
		return store.User{ID: c.UserID}, nil
	}
	// aks holda: session cookie'si (GB-6.04)
	cookie, err := r.Cookie(sessionCookie)
	if err != nil {
		return store.User{}, err // http.ErrNoCookie → 401
	}
	return a.st.UserBySession(r.Context(), hashToken(cookie.Value))
}
```

| Qator | Nima qiladi |
|---|---|
| 1 | `authenticate` soʻrovni oladi, `store.User` yoki xato qaytaradi |
| 2 | `bearer(r)` `Authorization` sarlavhasidan `Bearer` soʻzidan keyingi tokenni ajratadi. Token bor boʻlsa `ok` — `true` (GB-2.02 dagi comma-ok shakli) |
| 3–6 | `token.Parse` serverning kaliti `a.jwtKey` bilan tekshiradi. Xato boʻlsa, uni `errBadToken` bilan oʻraymiz (`%w` ikki marta, GB-6.02); `problemFor` buni `401`ga aylantiradi |
| 7 | izoh: vazifada denylist tekshiruvi shu yerga qoʻshiladi |
| 8 | foydalanuvchining ID'si tokendagi `sub`dan olinadi. **Storega murojaat yoʻq** |
| 10–15 | Bearer boʻlmasa, GB-6.04 dagi yoʻl: `r.Cookie` cookie'ni oladi (yoʻq boʻlsa xato, `401`), `hashToken` uni hashlaydi, `UserBySession` store'dan qidiradi |

**Bearer** — tokenga ega boʻlgan istalgan tomon undan foydalana oladigan token ([RFC 6750 §1.2](https://www.rfc-editor.org/rfc/rfc6750#section-1.2)). Sarlavha shakli: `Authorization: Bearer <token>`. `bearer` funksiyasi shu sarlavhani ajratadi:

```go
func bearer(r *http.Request) (string, bool) {
	scheme, rest, ok := strings.Cut(r.Header.Get("Authorization"), " ")
	if !ok || !strings.EqualFold(scheme, "Bearer") {
		return "", false
	}
	t := strings.TrimLeft(rest, " ")
	return t, t != ""
}
```

`strings.Cut` matnni birinchi boʻsh joyda ikkiga boʻladi: sxema nomi va qolgani. `EqualFold` sxema nomini katta-kichik harfga qaramay solishtiradi ([RFC 9110 §11.1](https://www.rfc-editor.org/rfc/rfc9110#section-11.1)). `TrimLeft` token oldidagi ortiqcha boʻsh joylarni olib tashlaydi.

## Bir xil soʻrovlar: login, /me, logout

Birinchi terminalda serverni ishga tushiramiz. U terminalni band qiladi: soʻrovlarni ikkinchisidan yuboramiz.

```console
$ go run ./cmd/api
bozor API: http://localhost:8765
```

Ikkinchi terminalda ham dars papkasini oching. Videoda login maʼlumotlari buyruqda yoziladi. Bu sahifada ular koʻrinmasin deb, README dagi birinchi sinov foydalanuvchisining manzili va parolini oʻzgaruvchilarga kiriting. `read -r` matnni oladi, `-s` parolni ekranga chiqarmaydi, `jq -n --arg` JSON yasaydi. Buyruqlar natija chiqarmaydi:

```bash
read -r LAB_EMAIL
read -r -s LAB_PASSWORD
jq -n --arg email "$LAB_EMAIL" --arg password "$LAB_PASSWORD" '{email:$email,password:$password}' > cred.json
```

Login. `-s` progressni yashiradi, `-c jar.txt` cookie'ni `jar.txt` fayliga yozadi, `-H` media turini qoʻyadi, `--data-binary @cred.json` faylni body qilib yuboradi. Javobni `login.json`ga yozamiz. `jq -c keys` maydon nomlarini koʻrsatadi: javob bodysida endi `token` ham bor — bu JWT:

```console
$ curl -s -c jar.txt localhost:8765/login -H "Content-Type: application/json" --data-binary @cred.json > login.json
$ jq -c keys login.json
["email","id","token"]
```

`jq -r .token` tokenni qoʻshtirnoqsiz oladi; `$(…)` natijani `T` degan shell oʻzgaruvchisiga yozadi. `cut -c1-36` birinchi 36 belgini koʻrsatadi — bu tokenning header qismi, bu serverning har tokenida bir xil:

```console
$ T=$(jq -r .token login.json)
$ echo "$T" | cut -c1-36
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
```

Payloadni ochamiz. `cut -d. -f2` tokenni nuqta boʻyicha boʻlib, ikkinchi qismni oladi:

```console
$ echo "$T" | cut -d. -f2 | basenc --base64url -d
{"iss":"bozor","sub":"1","aud":["bozor-api"],"exp":1795858747,"iat":1795857847,"jti":"QRMH66VP3WITY52K3JFBCJSPGV"}
```

Toʻrt claim bor edi; ikki yangisi kutubxonadan: `iat` (berilgan vaqt) va `jti` (tokenning noyob ID'si). `aud` roʻyxat koʻrinishida: JWTda `aud` bitta matn ham, matnlar roʻyxati ham boʻlishi mumkin ([RFC 7519 §4.1.3](https://www.rfc-editor.org/rfc/rfc7519#section-4.1.3)). `exp − iat` = 900 soniya = 15 daqiqa.

Endi `/me`ni ikkala yoʻl bilan chaqiramiz. `-b jar.txt` cookie'ni yuboradi; `-H "Authorization: Bearer $T"` JWTni yuboradi:

```console
$ curl -s -b jar.txt localhost:8765/me | jq -c keys
["email","id"]
$ curl -s -H "Authorization: Bearer $T" localhost:8765/me
{"id":1}
```

Cookie yoʻli foydalanuvchini storedan oladi: `id` va `email`. JWT yoʻli faqat tokendagini biladi: `id`. Email kerak boʻlsa, bazadan oʻqiysiz: payloadni hamma oʻqiy oladi.

Endi oʻgʻirlanishni modellashtiramiz. Cookie faylini `eski.txt`ga nusxalaymiz: bu «oʻgʻirlangan» nusxa. Keyin logout qilamiz. Logout har credential'ni alohida bekor qiladi, shuning uchun cookie'ni ham, oʻsha `$T`ni ham yuboramiz. `-i` javob sarlavhalarini ham koʻrsatadi, `-X POST` metodni qoʻyadi:

```console
$ cp jar.txt eski.txt
$ curl -s -i -X POST -b jar.txt -c jar.txt -H "Authorization: Bearer $T" localhost:8765/logout

Set-Cookie: session=; Path=/; Max-Age=0; HttpOnly; Secure; SameSite=Lax
X-Request-Id: LBKKRHY6FBOB7S2XRM7BIP6KRV
Date: Sat, 28 Nov 2026 09:24:07 GMT
```

`204 No Content` — muvaffaqiyat, body yoʻq. `Set-Cookie: session=; … Max-Age=0` brauzerga cookie'ni oʻchirishni aytadi, GB-6.04 dagidek. `HttpOnly; Secure; SameSite=Lax` atributlarini GB-6.07 da koʻramiz.

## Nega JWT logoutdan keyin ishlayveradi

| | session | JWT |
|---|---|---|
| serverda nima bor | token hashi → foydalanuvchi, muddat | faqat kalit |
| logout nima qiladi | qatorni oʻchiradi | oʻchiradigan yozuv yoʻq |
| keyingi soʻrov | qidiruv: qator yoʻq → `401` | imzo toʻgʻri, `exp` oʻtmagan → `200` |

Isbot tokenning oʻzida: imzo toʻgʻri va `exp` oʻtmagan ekan, u yaroqli. Server uni «unutishi» uchun unda biror narsa saqlangan boʻlishi kerak edi. Oʻgʻirlangan token bilan hujumchi uni `exp`gacha ishlatadi.

## Bekor qilishning narxi

Tuzatishning ikki odatiy yoʻli bor. Ularning har biri serverga holat qaytaradi.

1. **Denylist** — bekor qilingan `jti`lar roʻyxati. Uni har soʻrovda tekshirish kerak, yaʼni yana qidiruv. OWASP shunday yozadi: denylist boʻlsa, foydalanuvchi session'lari endi toʻliq **stateless** (serverda holat saqlanmaydigan) boʻlmaydi, shuning uchun oddiy session tizimini koʻrib chiqish mumkin ([OWASP JWT Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/JSON_Web_Token_Cheat_Sheet.html)).
2. **Qisqa `exp` + refresh token.** Access token bir necha daqiqa yashaydi, yangisi **refresh token** bilan olinadi. Refresh token serverda saqlanadi va bekor qilinadi, yaʼni yana session.
3. **Kalitni almashtirish** — bazasiz yoʻl, lekin u hammaning tokenini oʻldiradi.

**Oʻlcham.** JWT har soʻrov bilan ketadi va har claim bilan oʻsadi. `printf %s` tokenni yangi qatorsiz chiqaradi, `wc -c` baytni sanaydi. Cookie qiymatini `jar.txt` formatidan olamiz: cookie fayli — tab bilan ajratilgan ustunlar, yettinchisi qiymat (`cut -f7`), `tr -d` yangi qatorni olib tashlaydi:

```console
$ printf %s "$T" | wc -c
233
$ grep session eski.txt | cut -f7 | tr -d '\n' | wc -c
43
```

JWT — 233 belgi, session tokeni — 43. Bu laboratoriya qiymati: har bir qoʻshilgan claim tokenni kattalashtiradi.

## Bozor uchun tanlov

- **bozor: session.** Bitta API va bitta Postgres: soʻrovlar baribir bazaga boradi, session qidiruvi esa primary key boʻyicha bitta `SELECT` (GB-6.04). Odatda u arzon; bu darsda oʻlchanmagan. Logout va bloklash darhol ishlashi kerak.
- **JWT xizmatlar orasida oʻrinli:** bir xizmat boshqasiga qisqa umrli token beradi, tokenni qabul qiladigan xizmat bazaga ulanmaydi.

Bu bozorning shartlari uchun tanlov, umumiy qoida emas. Shart oʻzgarsa, tanlov ham oʻzgaradi: asosiy narsa — ikkala yoʻlning narxini bilish. Ishda ertaga: JWT koʻrsangiz, toʻrt qoidani va logout nima qilishini tekshiring.

## Chuqurroq (ixtiyoriy): har credential alohida, alg confusion va 401 sarlavhasi

**Logout har credential'ni alohida bekor qiladi.** `POST /login` ikkalasini beradi, shuning uchun videoda logoutga cookie ham, `$T` ham yuborildi. Faqat cookie bilan logout JWTga tegmaydi; `/logout-all` ham faqat session qatorlarini oʻchiradi. Ikkisini testlar tekshiradi:

```console
$ go test -count=1 -run "TestLogoutHarBiriAlohida|TestUsersVaLogoutAll" -v ./cmd/api
=== RUN   TestUsersVaLogoutAll
--- PASS: TestUsersVaLogoutAll (0.16s)
=== RUN   TestLogoutHarBiriAlohida
--- PASS: TestLogoutHarBiriAlohida (0.03s)
PASS
ok  	github.com/abdurahmon27/bozor/cmd/api	0.290s
```

JWTlarni «hamma qurilmadan» oʻldirish uchun foydalanuvchi boʻyicha yozuv kerak («shu vaqtdan oldin berilgan tokenlar yaroqsiz»): yana server holati.

**Yaroqsiz Bearer.** Token yaroqsiz boʻlsa, javob `401` va `WWW-Authenticate: Bearer error="invalid_token"` sarlavhasi ([RFC 6750 §3](https://www.rfc-editor.org/rfc/rfc6750#section-3)). Bearer bor-u yaroqsiz boʻlsa, `authenticate` cookie'ga oʻtmaydi: mijoz usulni tanlagan.

```console
$ curl -s -i -H "Authorization: Bearer salom" localhost:8765/me
HTTP/1.1 401 Unauthorized
Content-Type: application/problem+json
Www-Authenticate: Bearer error="invalid_token"
X-Request-Id: PNKR2JIJZAWHYTB6O5ZWTW5WMX
Date: Sat, 28 Nov 2026 09:24:07 GMT
Content-Length: 131

{"type":"about:blank","title":"Unauthorized","status":401,"detail":"avval login qiling","request_id":"PNKR2JIJZAWHYTB6O5ZWTW5WMX"}
```

`X-Request-Id` sarlavhasi GB-6.01 dagi; `Content-Type: application/problem+json` GB-6.02 dagi. Sababi — `token is malformed` — faqat logda:

```text
2026/11/28 14:24:07 PNKR2JIJZAWHYTB6O5ZWTW5WMX xato 401: "JWT yaroqsiz: token is malformed: token contains an invalid number of segments"
2026/11/28 14:24:07 PNKR2JIJZAWHYTB6O5ZWTW5WMX GET "/me" 401 340.984µs
```

**Alg confusion** (bu yerda qayta bajarilmagan, [RFC 8725 §2.1](https://www.rfc-editor.org/rfc/rfc8725#section-2.1) iqtibosi). Ochiq kalitli imzo (masalan `RS256`) ishlatadigan tizimda hujumchi headerdagi `alg`ni `HS256`ga almashtiradi va hammaga maʼlum ochiq kalitni HMAC siri sifatida ishlatadi. Himoya — ruxsat etilgan algoritmlarni server belgilashi, yaʼni `WithValidMethods`. Bizning bitta HMAC kalitli tizimda bu hujum yoʻq; shu sababli bu yerda faqat qoida sifatida eslatildi.

## Koʻp uchraydigan xatolar

**1. Qoidasiz `Parse`.** Xato xabari yoʻq: token oʻtib ketadi. `exp`siz token abadiy yashaydi, boshqa xizmat uchun berilgan token qabul qilinadi, algoritm token tanlaganicha qoladi. Toʻliq tahlil — yuqoridagi «Klassik xato: qoidasiz Parse» boʻlimida. Tuzatish: toʻrt option.

**2. JWTga sir yozish.** Payloadni kalitsiz `basenc` bilan oʻqidik (yuqoridagi «Payload shifrlanmagan» boʻlimi). Parol yoki shaxsiy maʼlumotni claimga qoʻymang. Email kerak boʻlsa, `sub` bilan bazadan oʻqing; shuning uchun JWT yoʻlida `/me` faqat `id` qaytardi.

**3. «Logout JWTni ham oʻldiradi» deb oʻylash.** Logout session qatorini oʻchiradi; JWT uchun oʻchiradigan narsa yoʻq («Bir xil soʻrovlar» boʻlimi: eski cookie `401`, JWT `200`). Tuzatish: denylist (vazifa) yoki qisqa `exp`ga qanoat qilish.

<details>

Birinchi parcha storeʼga, ikkinchisi `logout`ga, uchinchisi `authenticate`da `Parse`dan keyin qoʻyiladi. Ixtiyoriy `PurgeRevoked` roʻyxatni aylanib, `exp`i `now`dan oldin boʻlganlarni oʻchiradi:

```go
func (s *Store) PurgeRevoked(ctx context.Context, now time.Time) (int, error) {
	s.mu.Lock()
	defer s.mu.Unlock()
	n := 0
	for jti, exp := range s.revoked {
		if exp.Before(now) {
			delete(s.revoked, jti)
			n++
		}
	}
	return n, nil
}
```

Qolgan izoh: `revoked` map'i `jti` → `exp`: `exp`dan keyin token baribir rad etiladi, shuning uchun yozuvni tozalash mumkin (ixtiyoriy qism). `Parse` xato bersa, `logout` bekor qilmaydi: yaroqsiz token kira olmaydi. Tartib: avval JWT, keyin session. Denylistga yozib boʻlmasa, session joyida qoladi va logoutni takrorlash mumkin.
