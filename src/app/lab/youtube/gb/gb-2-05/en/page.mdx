## What you will learn

In GB-2.03 the function `orderTotal` computed the order total. Now we need to add lines to an order and mark it as paid. These
actions **change** the order, and the change must not be lost. Where do you write them, and why does one method written almost like
another change the order while the second does not, with the compiler silent in both cases?

**The one idea:** a method is a function with a receiver written before its name. The receiver is copied like an ordinary
parameter: a value receiver (`o Order`) gets a copy of the value, and a write to it is lost when the method returns; a pointer
receiver (`o *Order`) gets the address and writes to the original value. If you write `order.Pay()` on a plain variable, Go
inserts `&order` for you.

By the end you will:

- write the methods `Total`, `Pay` and `AddItem` on the `Order` type and call them as `order.Total()`;
- see in a memory picture that a value receiver gets a copy and a pointer receiver gets an address;
- find a lost change in a value receiver from the result (the compiler and `go vet` are silent) and fix it with one character;
- choose the receiver type by a rule;
- write a `String()` method on the `OrderStatus` type (based on int) and see `fmt` print the status by name.

Today's three core new words:

| Word | Plain meaning | English term |
|---|---|---|
| method | a function bound to a type; declared as `func (o Order) Total() int64 { … }`, called as `order.Total()` | method |
| receiver | the value the method works on; written in parentheses between `func` and the method name. `o Order` is a copy (**value receiver**), `o *Order` is an address (**pointer receiver**) | receiver |
| choosing a receiver | changes the value or the struct is large — pointer; one type — one kind of receiver; small unchanging value — value | choosing a receiver |

Two helper ideas: the `String()` method (`fmt` prints the status name instead of the number) and the "compiler and `go vet` are silent"
kind of bug (`go vet` is Go's standard checker; it looks for suspicious places in the code of the current folder).

## Method: a function bound to a type

In GB-2.03 a function computed the total: `func orderTotal(o Order) int64`. The actions on an order — total, pay, add a line — belong to
`Order`. They can be bound to the `Order` type: such a function is called a **method**. The first method is `Total`
(`orderTotal` itself, only declared differently). The full program (`_video/01-total/main.go`):

```go filename="_video/01-total/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// OrderItem — buyurtmadagi bitta qator.
type OrderItem struct {
	ProductID int64
	Price     int64 // tiyin, buyurtma paytidagi narx
	Quantity  int
}

// Order — bitta buyurtma.
type Order struct {
	ID     int64
	Items  []OrderItem
	Status OrderStatus
}

// OrderStatus — buyurtma holati.
type OrderStatus int

const (
	StatusNew OrderStatus = iota
	StatusPaid
	StatusShipped
	StatusCancelled
)

// Total buyurtma summasini tiyinda qaytaradi.
func (o Order) Total() int64 {
	var total int64
	for _, it := range o.Items {
		total += it.Price * int64(it.Quantity)
	}
	return total
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	order := Order{
		ID: 1,
		Items: []OrderItem{
			{ProductID: olma.ID, Price: olma.Price, Quantity: 3},
		},
	}
	fmt.Println(order.Total())
}
```

Lines 1–35 are the types from GB-2.03 (`Product`, `OrderItem`, `Order`, `OrderStatus` and the statuses); they did not change. The new lines:

| Line | Code | What it does |
|---|---|---|
| 38 | `func (o Order) Total() int64 {` | after `func`, in parentheses, `o Order` is the **receiver**: the value the method works on. Then the method name `Total`, empty parentheses (no parameters) and the result type `int64`. The method name is capitalized too: we explain why in [GB-2.06](/lab/youtube/gb/gb-2-06/en) |
| 39 | `var total int64` | `total` starts at zero (zero value) |
| 40 | `for _, it := range o.Items {` | the receiver is used in the body like an ordinary parameter: `o.Items` is the order's lines; `it` is one line |
| 41 | `total += it.Price * int64(it.Quantity)` | for each line the price is multiplied by the quantity and added to `total`. Here `*` is multiplication |
| 43 | `return total` | returns the accumulated total |
| 54 | `fmt.Println(order.Total())` | the method is called as `order.Total()`, with empty parentheses |

In the call, `order` before the dot goes into the receiver `o`. In a function the value stood in parentheses (`orderTotal(order)`);
in a method it stands before the dot (`order.Total()`). What is printed?

**A)** `3600000` · **B)** `1200000` · **C)** compile error

<details>
<summary>Answer</summary>

**A: `3600000`.** The order has one line: price 1 200 000 tiyin, 3 pieces. The loop runs once: `0 + 1 200 000 × 3 = 3 600 000`.
If you chose **B**, you ignored the quantity. **C** — `Total` is declared on this type, so `order.Total()` is a valid call.

```console
$ ./_video/run.sh 01-total go run .
3600000
```

3 600 000 tiyin is 36 000 som.

</details>

The method worked like a function, only bound to the `Order` type: the order's actions are now in one place, found after `order.`.

## Value receiver: Pay changes a copy

Now a method that changes the order: `Pay`, the payment. `_video/02-pay-value/main.go` has the same types and statuses; the new part:

```go
// Pay buyurtmani toʻlangan deb belgilaydi.
func (o Order) Pay() {
	o.Status = StatusPaid
}

func main() {
	var order Order
	order.Pay()
	fmt.Println(order.Status)
}
```

| Code | What it does |
|---|---|
| `func (o Order) Pay() {` | the receiver is `o Order` again. There is no result type, so `{` follows the parentheses directly |
| `o.Status = StatusPaid` | writes `StatusPaid` into the status; its value is 1 (`iota`, GB-2.03) |
| `var order Order` | an empty order: `ID` 0, `Items` `nil`, `Status` 0 (zero value) |
| `order.Pay()` | we pay the order |
| `fmt.Println(order.Status)` | prints the status **number** (not the name: there is no `String` method yet) |

What is printed?

**A)** `1` · **B)** `0` · **C)** compile error

<details>
<summary>Answer</summary>

**B: `0`.** The compiler gave no error, the program ran, but the status did not change. The reason is in the memory picture below. If you chose **A**,
you thought `order.Pay()` changes `order`: that is true for a pointer receiver, not here. **C** — the code is well formed, and the compiler
accepts both forms.

```console
$ ./_video/run.sh 02-pay-value go run .
0
```

</details>

In memory, step by step:

| Step | Code | `order` | `o` | Screen |
|---|---|---|---|---|
| 1 | `var order Order` | `ID 0 · Items nil · Status 0` | — | |
| 2 | `order.Pay()` called: the receiver `o` is created as a new variable | `ID 0 · Items nil · Status 0` | a **full copy** of `order`: `ID 0 · Items nil · Status 0` | |
| 3 | `o.Status = StatusPaid` | `Status 0` | `Status 1` | |
| 4 | `Pay` finished: `o` disappears | `Status 0` | — | |
| 5 | `fmt.Println(order.Status)` | `Status 0` | — | `0` |

The receiver works like an ordinary parameter: like `p` in `sell`, `o` receives a copy of `order`. `Pay` wrote `1` into the copy, the copy
disappeared when the method ended, and `order` still holds `0`. A **value receiver** is a receiver of the form `o Order`: it gets a copy of
the value, and a write to the copy is lost together with the method.

## Pointer receiver: Pay changes the original value

The fix is one character: the receiver type `*Order`. `_video/03-pay-pointer/main.go`:

```go
// Pay buyurtmani toʻlangan deb belgilaydi.
func (o *Order) Pay() {
	o.Status = StatusPaid
}

func main() {
	var order Order
	order.Pay()
	fmt.Println(order.Status)
}
```

Only the line `func (o *Order) Pay()` changed. `*Order` is the type of the address of an `Order` (GB-2.04). Such a receiver is a **pointer receiver**:
the method gets not a copy of `order` but its **address**. `main` did not change: `order` is still a plain variable, not a pointer, and the
call is still `order.Pay()`, without `&`. Does this code compile, and if so what does it print?

**A)** `1` · **B)** `0` · **C)** compile error: `&order` is needed

<details>
<summary>Answer</summary>

**A: `1`.** The code compiles and the status changed: Go itself turns `order.Pay()` into `(&order).Pay()`. **B** is the result of the previous
version (value receiver): a pointer receiver gets an address, not a copy. **C** — in GB-2.04 you passed the address to a function yourself
(`sell(&olma, 3)`), but for a method on a variable Go does it for you.

```console
$ ./_video/run.sh 03-pay-pointer go run .
1
```

</details>

In memory:

| Step | Code | `order` | `o` | Screen |
|---|---|---|---|---|
| 1 | `var order Order` | `ID 0 · Items nil · Status 0` | — | |
| 2 | `order.Pay()`: Go calls it as `(&order).Pay()` | `ID 0 · Items nil · Status 0` | — | |
| 3 | the receiver `o` is the **address** of `order` (no copy) | `ID 0 · Items nil · Status 0` | `&order` ↦ `order` | |
| 4 | `o.Status = StatusPaid`: through the address the write goes into `order` itself (as in GB-2.04) | `Status 1` | `&order` ↦ `order` | |
| 5 | `fmt.Println(order.Status)` | `Status 1` | — | `1` |

```text
order ──► ┌───────────────────────────────┐
          │ ID 0 · Items nil · Status 1   │
          └───────────────────────────────┘
               ▲
   o ──────────┘   (o is an address; o.Status = … writes to this value)
```

`order.Pay()` is a short form, and Go makes it `(&order).Pay()`. The rule works because `order` is a plain variable, so its address can be taken
([Go spec: Calls](https://go.dev/ref/spec#Calls): if `x` is such a variable, `x.m()` is shorthand for `(&x).m()`).
If you write the call in full, the result is the same:

```go
var order Order
(&order).Pay()
fmt.Println(order.Status)
```

```console
$ go run .
1
```

(This program is not in the course folder: it is a full copy of `_video/03-pay-pointer/main.go`, with the line `order.Pay()` replaced by `(&order).Pay()`.)

## AddItem: store the result of append through the pointer

The main method is `AddItem`, adding a line to the order. It changes `Items`, so the receiver is a pointer. `_video/04-additem/main.go`
(lines 1–35 are the earlier types; I do not show them again):

```go filename="_video/04-additem/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// OrderItem — buyurtmadagi bitta qator.
type OrderItem struct {
	ProductID int64
	Price     int64 // tiyin, buyurtma paytidagi narx
	Quantity  int
}

// Order — bitta buyurtma.
type Order struct {
	ID     int64
	Items  []OrderItem
	Status OrderStatus
}

// OrderStatus — buyurtma holati.
type OrderStatus int

const (
	StatusNew OrderStatus = iota
	StatusPaid
	StatusShipped
	StatusCancelled
)

// AddItem buyurtmaga qator qoʻshadi; narx mahsulotdan nusxalanadi.
func (o *Order) AddItem(p Product, quantity int) {
	item := OrderItem{ProductID: p.ID, Price: p.Price, Quantity: quantity}
	o.Items = append(o.Items, item)
}

// Total buyurtma summasini tiyinda qaytaradi.
func (o Order) Total() int64 {
	var total int64
	for _, it := range o.Items {
		total += it.Price * int64(it.Quantity)
	}
	return total
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	non := Product{ID: 2, Name: "non", Price: 400_000, Stock: 100}
	var order Order
	order.AddItem(olma, 3)
	order.AddItem(non, 2)
	fmt.Println(len(order.Items), order.Total())
}
```

`Total` did not change. The new lines:

| Line | Code | What it does |
|---|---|---|
| 38 | `func (o *Order) AddItem(p Product, quantity int) {` | a pointer receiver: `Items` changes. After the receiver come ordinary parameters: the product `p` (type `Product`) and the count `quantity` |
| 39 | `item := OrderItem{…}` | the ID and price are taken from `p`: the price is stored in the line as it was at order time (GB-2.03) |
| 40 | `o.Items = append(o.Items, item)` | `append` returns a new slice header ([GB-2.01](/lab/youtube/gb/gb-2-01/en)); the result is stored in `o.Items`. The receiver is a pointer, so this is `order` itself |
| 54 | `non := Product{…}` | the second product: bread (`non`), price 400 000 tiyin |
| 56–57 | `order.AddItem(olma, 3)`, `order.AddItem(non, 2)` | adds apples (3 pieces) and bread (2 pieces) |
| 58 | `fmt.Println(len(order.Items), order.Total())` | the number of lines and the total |

Predict: what are the number of lines and the total?

**A)** `2 4400000` · **B)** `0 0` · **C)** `2 3600000`

<details>
<summary>Answer</summary>

**A: `2 4400000`.** Two lines: apples `1 200 000 × 3 = 3 600 000` and bread `400 000 × 2 = 800 000`; together `4 400 000` tiyin (44 000 som).
**B** is what you would get without a pointer receiver; we see it below in "Common mistakes". **C** — you left out the bread.

```console
$ ./_video/run.sh 04-additem go run .

```

</details>

The receiver of `Total` is still a value: it only reads, so the copy does not get in its way.

## The rule for choosing a receiver

There are two kinds of receiver. Which one do you write? Four rules ([Go FAQ](https://go.dev/doc/faq#methods_on_values_or_pointers) and
[Go Code Review Comments: Receiver Type](https://go.dev/wiki/CodeReviewComments#receiver-type)):

| # | Rule | Example |
|---|---|---|
| 1 | The method changes the value — **pointer receiver** | `Pay`, `AddItem` |
| 2 | The struct is large (for example, dozens of fields) — also a pointer: copying the whole struct on every call is expensive | — |
| 3 | All methods of one type get the same kind of receiver | `Order`: `Pay`, `AddItem` are pointer, so `Total` is pointer too |
| 4 | A small, unchanging value — **value receiver** | `OrderStatus` |

On `Order`, `Pay` and `AddItem` get a pointer receiver, and by the third rule so does `Total`. Its body does not change: through the pointer
`o.Items` is read the same way. The headers of all three methods:

```go
func (o *Order) Total() int64 { … }
func (o *Order) Pay() { … }
func (o *Order) AddItem(p Product, quantity int) { … }
```

(`{ … }` — the body is shortened on the page; the full text is in `main.go`.) A question. We want to write three methods on `Product`: `InStock` says
whether stock remains, `Sell` subtracts the sold count from `Stock`, `PriceSom` returns the price in som. Which of them get a pointer receiver?

**A)** only `Sell` · **B)** `Sell` and `InStock` · **C)** all three

<details>
<summary>Answer</summary>

**C: all three.** `Sell` changes `Stock`, so it needs a pointer receiver (rule 1). `InStock` and `PriceSom` only read, but by rule 3 all
methods of one type get the same kind of receiver. If you chose **A**, you applied only rule 1; **B** — you split off some of the reading
methods, while the rule keeps them all together.

</details>

`OrderStatus`, on the other hand, is small (a single `int`) and does not change, so a value receiver is enough: in the next section.

## String: print the status by name

A method is written not only on a struct but on any type you declared ([Go spec: Method declarations](https://go.dev/ref/spec#Method_declarations)).
`OrderStatus` was declared in GB-2.03 based on `int`. Let us give it a `String` method:

```go
// String holatning nomini qaytaradi; fmt uni oʻzi chaqiradi.
func (s OrderStatus) String() string {
	switch s {
	case StatusNew:
		return "yangi"
	case StatusPaid:
		return "toʻlangan"
	case StatusShipped:
		return "joʻnatilgan"
	case StatusCancelled:
		return "bekor qilingan"
	}
	return "nomaʼlum"
}
```

| Code | What it does |
|---|---|
| `func (s OrderStatus) String() string {` | the receiver `s` of type `OrderStatus` is a value receiver (a small, unchanging value). The result type is `string` |
| `switch s {` | a branch is chosen by the value of `s` (GB-1.05) |
| `case StatusNew:` + `return "yangi"` | if the status is `StatusNew`, returns its name ("new"). The other three statuses are written the same way |
| `return "nomaʼlum"` | when a number that is not in the list arrives (for example `OrderStatus(9)`): "unknown" |

`fmt` checks whether the value has a method named exactly `String` that returns a `string`, and if so it calls it instead of printing the number
([pkg.go.dev/fmt](https://pkg.go.dev/fmt)). How exactly `fmt` checks this we open in [GB-2.07](/lab/youtube/gb#gb-2-07), the interface lesson.
The final `main`:

```go
var order Order
order.AddItem(olma, 3)
order.AddItem(non, 2)
order.Pay()
fmt.Println(len(order.Items), order.Total(), order.Status)
```

There is one new line, `order.Pay()`. How is the last value, the status, printed?

**A)** `2 4400000 1` · **B)** `2 4400000 toʻlangan` · **C)** `2 4400000 StatusPaid`

<details>
<summary>Answer</summary>

**B: `2 4400000 toʻlangan`.** `Println` found the `String` method on `Status` and wrote the name ("paid") instead of the number. **A** is what you would
get without `String` (in the earlier sections you saw `0` and `1` this way). **C** — `fmt` does not know how the constant is named in the code;
it prints only the text that `String` returned.

`main.go` in the folder is this final code:

```console
$ go run .
2 4400000 toʻlangan
```

</details>

Now the order's actions are methods of `Order`: `AddItem` and `Pay` change it, `Total` reads it, and the status prints by name.

## Common mistakes

**1. Thinking "a method changes the variable".** The method is called after `order.`, so it feels like it changes `order`. In fact the change
depends on the receiver type: `func (o Order) Pay()` writes into a copy. You saw this above (in the section "Value receiver: Pay changes a copy"
it printed `0`); the fix is `*Order`.

**2. A missing asterisk in `AddItem`.** The most common variant: less obvious than `Pay`, because adding a line is written with `append`.
In `_video/05-xato/main.go` the receiver of `AddItem` is `o Order`, the rest of the code is the same. Only the header line differs:

```go
func (o Order) AddItem(p Product, quantity int) {
	item := OrderItem{ProductID: p.ID, Price: p.Price, Quantity: quantity}
	o.Items = append(o.Items, item)
}
```

`main` is as before: apples 3, bread 2, then `fmt.Println(len(order.Items), order.Total())`. Will the compiler catch this? What is printed?

```console
$ ./_video/run.sh 05-xato go run .
0 0
```

How to read it: there is no error message, the program ran, but both `len(order.Items)` and `Total()` are zero. Every call added a line to its own
copy and lost it together with the copy: in the copy the `Items` header is a copy too, and `append` wrote the new header only into it. `go vet` is silent too:

```console
$ ./_video/run.sh 05-xato go vet .
```

`go vet` printed nothing (when it finds no suspicious place it stays silent): the code is valid by Go's rules, and a logic error is not something it sees.
Neither the compiler nor `go vet` sees this bug; the result or a test catches it. The fix is the asterisk in the receiver: `func (o *Order) AddItem(…)`.
At work, this is the question asked in code review: does the method change the value — is its receiver a pointer?

**3. Forgetting that `it` in a loop is a copy.** The same rule works inside `for _, it := range`: `it` is a copy of the line, and writing to it does not touch
`Items` (this mistake shows up in the homework too). The full program (not in the course folder):

```go
package main

import "fmt"

// OrderItem — buyurtmadagi bitta qator.
type OrderItem struct {
	ProductID int64
	Quantity  int
}

func main() {
	items := []OrderItem{{ProductID: 1, Quantity: 3}, {ProductID: 2, Quantity: 2}}
	for _, it := range items {
		it.Quantity += 1
	}
	fmt.Println(items[0].Quantity)
}
```

```console
$ go run .
3
```

The result is `3`, not `4`. Here too the compiler and `go vet` are silent. The fix is to write to the line by index: `items[i].Quantity += 1` (`for i := range items`).

## Check yourself

**1.** If a method with a value receiver writes to a field, does the variable that called it change?

<details>
<summary>Answer</summary>

No. A value receiver gets a copy of the value, the method writes into the copy, and the copy disappears with the method (the version of `Pay` that printed `0`).

</details>

**2.** `Pay` has a pointer receiver and `order` is a plain variable (`var order Order`). Do you have to write `&order` to call `order.Pay()`?

<details>
<summary>Answer</summary>

No. Because `order` is a variable, Go itself turns `order.Pay()` into `(&order).Pay()`.

</details>

**3.** (GB-2.02) When you loop over a `map` with `range`, is the order of the keys guaranteed?

<details>
<summary>Answer</summary>

No. The order is not guaranteed; it can differ even between two loops in the same program
([Go spec: For statements with range clause](https://go.dev/ref/spec#For_range)).

</details>

**4.** What does this program print? (`OrderStatus` as in GB-2.03, with the `String` method above.)

```go
fmt.Println(StatusShipped, OrderStatus(9), int(StatusPaid))
```

<details>
<summary>Answer</summary>

`joʻnatilgan nomaʼlum 1`. For `StatusShipped`, `String` runs → `joʻnatilgan` ("shipped"); `OrderStatus(9)` is a number not in the list,

The full program (not in the course folder) consists of the types and `String`:

```go
	StatusNew OrderStatus = iota
	StatusPaid
	StatusShipped
	StatusCancelled

func (s OrderStatus) String() string {
	switch s {
	case StatusNew:
		return "yangi"
	case StatusPaid:
		return "toʻlangan"
	case StatusShipped:
		return "joʻnatilgan"
	case StatusCancelled:
		return "bekor qilingan"
	}
	return "nomaʼlum"
}

func main() {
	fmt.Println(StatusShipped, OrderStatus(9), int(StatusPaid))
}
```

**Step 1.** `for _, it := range o.Items { it.Quantity += quantity }` does not work: `it` is a copy of the line (mistake 3 above). Write by index.
`for i := range o.Items` gives only the index: `i` = 0, 1, 2 …. When the line is found, add and `return`: a bare `return` in a method with no result
leaves the method right there, and does not reach the `append` below:

```go
func (o *Order) AddItem(p Product, quantity int) {
	for i := range o.Items {
		if o.Items[i].ProductID == p.ID {
			o.Items[i].Quantity += quantity
			return
		}
	}
	item := OrderItem{ProductID: p.ID, Price: p.Price, Quantity: quantity}
	o.Items = append(o.Items, item)
}
```

```go
func (o *Order) Cancel() error {
```
