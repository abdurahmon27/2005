## Что вы узнаете

В GB-2.03 сумму заказа считала функция `orderTotal`. Теперь нужно добавлять в заказ строки и помечать его оплаченным. Эти действия
**изменяют** заказ, и изменение не должно пропасть. Куда их записать — и почему один метод, написанный почти так же, как другой,
изменяет заказ, а второй нет, хотя компилятор молчит в обоих случаях?

**Главная идея:** метод — это функция, перед именем которой записан receiver. Receiver копируется как обычный параметр: value receiver
(`o Order`) получает копию значения, и запись в неё пропадает вместе с методом; pointer receiver (`o *Order`) получает адрес и
записывает в исходное значение. Если вы пишете `order.Pay()` для обычной переменной, Go сам подставляет `&order`.

К концу урока вы:

- напишете для типа `Order` методы `Total`, `Pay` и `AddItem` и вызовете их как `order.Total()`;
- увидите на схеме памяти, что value receiver получает копию, а pointer receiver — адрес;
- найдёте по результату потерянное изменение в value receiver (компилятор и `go vet` молчат) и исправите его одним символом;
- выберете тип receiver по правилу;
- напишете метод `String()` для типа `OrderStatus` на основе int и увидите, что `fmt` печатает статус по имени.

Три основных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| метод | функция, привязанная к типу; объявляется как `func (o Order) Total() int64 { … }`, вызывается как `order.Total()` | method |
| receiver | значение, с которым работает метод; пишется в скобках между `func` и именем метода. `o Order` — копия (**value receiver**), `o *Order` — адрес (**pointer receiver**) | receiver |
| правило выбора receiver | изменяет значение или структура большая — pointer; один тип — один вид receiver; маленькое неизменяемое значение — value | choosing a receiver |

Два вспомогательных понятия: метод `String()` (`fmt` печатает имя статуса вместо числа) и ошибка вида «компилятор и `go vet` молчат»
(`go vet` — стандартный анализатор кода Go, он ищет подозрительные места в коде текущей папки).

## Метод: функция, привязанная к типу

В GB-2.03 сумму считала функция: `func orderTotal(o Order) int64`. Действия с заказом — сумма, оплата, добавление строки — относятся
к `Order`. Их можно привязать к типу `Order`: такая функция называется **методом** (*method*). Первый метод — `Total`
(та же `orderTotal`, только объявленная иначе). Полный текст программы (`_video/01-total/main.go`):

```go filename="_video/01-total/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// OrderItem — buyurtmadagi bitta qator.
type OrderItem struct {
	ProductID int64
	Price     int64 // tiyin, buyurtma paytidagi narx
	Quantity  int
}

// Order — bitta buyurtma.
type Order struct {
	ID     int64
	Items  []OrderItem
	Status OrderStatus
}

// OrderStatus — buyurtma holati.
type OrderStatus int

const (
	StatusNew OrderStatus = iota
	StatusPaid
	StatusShipped
	StatusCancelled
)

// Total buyurtma summasini tiyinda qaytaradi.
func (o Order) Total() int64 {
	var total int64
	for _, it := range o.Items {
		total += it.Price * int64(it.Quantity)
	}
	return total
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	order := Order{
		ID: 1,
		Items: []OrderItem{
			{ProductID: olma.ID, Price: olma.Price, Quantity: 3},
		},
	}
	fmt.Println(order.Total())
}
```

Строки 1–35 — типы из GB-2.03 (`Product`, `OrderItem`, `Order`, `OrderStatus` и статусы), они не изменились. Новые строки:

| Строка | Код | Что делает |
|---|---|---|
| 38 | `func (o Order) Total() int64 {` | после `func` в скобках `o Order` — **receiver** (*receiver*): значение, с которым работает метод. Затем имя метода `Total`, пустые скобки (параметров нет) и тип результата `int64`. Имя метода тоже с заглавной буквы: почему, объясним в [GB-2.06](/lab/youtube/gb/gb-2-06/ru) |
| 39 | `var total int64` | `total` начинается с нуля (zero value) |
| 40 | `for _, it := range o.Items {` | receiver в теле используется как обычный параметр: `o.Items` — строки заказа; `it` — одна строка |
| 41 | `total += it.Price * int64(it.Quantity)` | для каждой строки цена умножается на количество и прибавляется к `total`. Здесь `*` — умножение |
| 43 | `return total` | возвращает накопленную сумму |
| 54 | `fmt.Println(order.Total())` | метод вызывается как `order.Total()`, с пустыми скобками |

При вызове `order` перед точкой попадает в receiver `o`. В функции значение стояло в скобках (`orderTotal(order)`),
в методе оно стоит перед точкой (`order.Total()`). Что будет напечатано?

**A)** `3600000` · **B)** `1200000` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**A: `3600000`.** В заказе одна строка: цена 1 200 000 тиын, 3 штуки. Цикл выполняется один раз: `0 + 1 200 000 × 3 = 3 600 000`.
Если вы выбрали **B**, вы не учли количество. **C** — `Total` объявлен для этого типа, `order.Total()` — правильный вызов.

```console
$ ./_video/run.sh 01-total go run .
3600000
```

3 600 000 тиын — это 36 000 сумов.

</details>

Метод работал как функция, только привязанная к типу `Order`: действия с заказом теперь собраны в одном месте, их ищут после `order.`.

## Value receiver: Pay изменяет копию

Теперь метод, изменяющий заказ, — `Pay`, оплата. `_video/02-pay-value/main.go` с теми же типами и статусами; новая часть:

```go
// Pay buyurtmani toʻlangan deb belgilaydi.
func (o Order) Pay() {
	o.Status = StatusPaid
}

func main() {
	var order Order
	order.Pay()
	fmt.Println(order.Status)
}
```

| Код | Что делает |
|---|---|
| `func (o Order) Pay() {` | receiver снова `o Order`. Типа результата нет, поэтому сразу после скобок идёт `{` |
| `o.Status = StatusPaid` | в статус записывается `StatusPaid`; его значение 1 (`iota`, GB-2.03) |
| `var order Order` | пустой заказ: `ID` 0, `Items` `nil`, `Status` 0 (zero value) |
| `order.Pay()` | оплачиваем заказ |
| `fmt.Println(order.Status)` | печатает **число** статуса (не имя: метода `String` пока нет) |

Что будет напечатано?

**A)** `1` · **B)** `0` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `0`.** Компилятор не выдал ошибку, программа отработала, но статус не изменился. Причина — на схеме памяти ниже. Если вы выбрали **A**,
вы решили, что `order.Pay()` изменяет `order`: для pointer receiver это верно, здесь нет. **C** — код составлен правильно,
компилятор принимает обе записи.

```console
$ ./_video/run.sh 02-pay-value go run .
0
```

</details>

В памяти, шаг за шагом:

| Шаг | Код | `order` | `o` | Экран |
|---|---|---|---|---|
| 1 | `var order Order` | `ID 0 · Items nil · Status 0` | — | |
| 2 | вызвана `order.Pay()`: receiver `o` создаётся как новая переменная | `ID 0 · Items nil · Status 0` | **полная копия** `order`: `ID 0 · Items nil · Status 0` | |
| 3 | `o.Status = StatusPaid` | `Status 0` | `Status 1` | |
| 4 | `Pay` завершилась: `o` исчезает | `Status 0` | — | |
| 5 | `fmt.Println(order.Status)` | `Status 0` | — | `0` |

Receiver работает как обычный параметр: как `p` в `sell`, в `o` попадает копия `order`. `Pay` записала в копию `1`, после выхода
из метода копия исчезла, а в `order` осталось `0`. **Value receiver** (*value receiver*) — receiver вида `o Order`: он получает копию
значения, и запись в копию пропадает вместе с методом.

## Pointer receiver: Pay изменяет исходное значение

Исправление — один символ: тип receiver `*Order`. `_video/03-pay-pointer/main.go`:

```go
// Pay buyurtmani toʻlangan deb belgilaydi.
func (o *Order) Pay() {
	o.Status = StatusPaid
}

func main() {
	var order Order
	order.Pay()
	fmt.Println(order.Status)
}
```

Изменилась только строка `func (o *Order) Pay()`. `*Order` — тип адреса `Order` (GB-2.04). Такой receiver называется **pointer receiver**
(*pointer receiver*): метод получает не копию `order`, а его **адрес**. `main` не изменился: `order` по-прежнему обычная переменная,
не указатель, и вызов по-прежнему `order.Pay()`, без `&`. Скомпилируется ли этот код и что он напечатает?

**A)** `1` · **B)** `0` · **C)** ошибка компиляции: нужен `&order`

<details>
<summary>Ответ</summary>

**A: `1`.** Код компилируется, и статус изменился: Go сам превращает `order.Pay()` в `(&order).Pay()`. **B** — это результат предыдущего
варианта (value receiver): pointer receiver получает не копию, а адрес. **C** — в GB-2.04 адрес в функцию вы передавали сами
(`sell(&olma, 3)`), а для метода, если это переменная, Go делает это сам.

```console
$ ./_video/run.sh 03-pay-pointer go run .
1
```

</details>

В памяти:

| Шаг | Код | `order` | `o` | Экран |
|---|---|---|---|---|
| 1 | `var order Order` | `ID 0 · Items nil · Status 0` | — | |
| 2 | `order.Pay()`: Go вызывает её как `(&order).Pay()` | `ID 0 · Items nil · Status 0` | — | |
| 3 | receiver `o` — **адрес** `order` (копии нет) | `ID 0 · Items nil · Status 0` | `&order` ↦ `order` | |
| 4 | `o.Status = StatusPaid`: по адресу запись идёт в сам `order` (как в GB-2.04) | `Status 1` | `&order` ↦ `order` | |
| 5 | `fmt.Println(order.Status)` | `Status 1` | — | `1` |

```text
order ──► ┌───────────────────────────────┐
          │ ID 0 · Items nil · Status 1   │
          └───────────────────────────────┘
               ▲
   o ──────────┘   (o — адрес; o.Status = … пишет в это значение)
```

`order.Pay()` — сокращённая запись, Go делает из неё `(&order).Pay()`. Это правило работает потому, что `order` — обычная переменная,
и можно взять её адрес ([Go spec: Calls](https://go.dev/ref/spec#Calls): если `x` — такая переменная, `x.m()` — сокращение для `(&x).m()`).
Если записать вызов полностью, результат тот же:

```go
var order Order
(&order).Pay()
fmt.Println(order.Status)
```

```console
$ go run .
1
```

(Этой программы в папке курса нет: это полная копия `_video/03-pay-pointer/main.go`, только строка `order.Pay()` заменена на `(&order).Pay()`.)

## AddItem: сохранить результат append через указатель

Главный метод — `AddItem`, добавление строки в заказ. Он изменяет `Items`, значит receiver — указатель. `_video/04-additem/main.go`
(строки 1–35 — прежние типы, их не показываю):

```go filename="_video/04-additem/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// OrderItem — buyurtmadagi bitta qator.
type OrderItem struct {
	ProductID int64
	Price     int64 // tiyin, buyurtma paytidagi narx
	Quantity  int
}

// Order — bitta buyurtma.
type Order struct {
	ID     int64
	Items  []OrderItem
	Status OrderStatus
}

// OrderStatus — buyurtma holati.
type OrderStatus int

const (
	StatusNew OrderStatus = iota
	StatusPaid
	StatusShipped
	StatusCancelled
)

// AddItem buyurtmaga qator qoʻshadi; narx mahsulotdan nusxalanadi.
func (o *Order) AddItem(p Product, quantity int) {
	item := OrderItem{ProductID: p.ID, Price: p.Price, Quantity: quantity}
	o.Items = append(o.Items, item)
}

// Total buyurtma summasini tiyinda qaytaradi.
func (o Order) Total() int64 {
	var total int64
	for _, it := range o.Items {
		total += it.Price * int64(it.Quantity)
	}
	return total
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	non := Product{ID: 2, Name: "non", Price: 400_000, Stock: 100}
	var order Order
	order.AddItem(olma, 3)
	order.AddItem(non, 2)
	fmt.Println(len(order.Items), order.Total())
}
```

`Total` не изменился. Новые строки:

| Строка | Код | Что делает |
|---|---|---|
| 38 | `func (o *Order) AddItem(p Product, quantity int) {` | pointer receiver: `Items` изменяется. После receiver идут обычные параметры: товар `p` (тип `Product`) и количество `quantity` |
| 39 | `item := OrderItem{…}` | из `p` берутся ID и цена: цена сохраняется в строке такой, какой была в момент заказа (GB-2.03) |
| 40 | `o.Items = append(o.Items, item)` | `append` возвращает новый заголовок слайса ([GB-2.01](/lab/youtube/gb/gb-2-01/ru)); результат сохраняется в `o.Items`. Receiver — указатель, поэтому это сам `order` |
| 54 | `non := Product{…}` | второй товар: хлеб (`non`), цена 400 000 тиын |
| 56–57 | `order.AddItem(olma, 3)`, `order.AddItem(non, 2)` | добавляются яблоки (3 штуки) и хлеб (2 штуки) |
| 58 | `fmt.Println(len(order.Items), order.Total())` | число строк и сумма |

Предскажите: чему равны число строк и сумма?

**A)** `2 4400000` · **B)** `0 0` · **C)** `2 3600000`

<details>
<summary>Ответ</summary>

**A: `2 4400000`.** Две строки: яблоки `1 200 000 × 3 = 3 600 000` и хлеб `400 000 × 2 = 800 000`; вместе `4 400 000` тиын (44 000 сумов).
**B** получилось бы без pointer receiver — это мы увидим ниже, в «Частых ошибках». **C** — вы не учли хлеб.

```console
$ ./_video/run.sh 04-additem go run .
2 4400000
```

</details>

Receiver у `Total` пока value: он только читает, поэтому копия ему не мешает.

## Правило выбора receiver

Receiver бывает двух видов. Какой писать? Четыре правила ([Go FAQ](https://go.dev/doc/faq#methods_on_values_or_pointers) и
[Go Code Review Comments: Receiver Type](https://go.dev/wiki/CodeReviewComments#receiver-type)):

| # | Правило | Пример |
|---|---|---|
| 1 | Метод изменяет значение — **pointer receiver** | `Pay`, `AddItem` |
| 2 | Структура большая (например, десятки полей) — тоже pointer: копировать всю структуру при каждом вызове дорого | — |
| 3 | Все методы одного типа получают receiver одного вида | `Order`: `Pay`, `AddItem` — pointer, значит и `Total` тоже pointer |
| 4 | Маленькое неизменяемое значение — **value receiver** | `OrderStatus` |

У `Order` методы `Pay` и `AddItem` получают pointer receiver, а по третьему правилу и `Total`. Его тело не меняется: через указатель
`o.Items` читается так же. Заголовки всех трёх методов:

```go
func (o *Order) Total() int64 { … }
func (o *Order) Pay() { … }
func (o *Order) AddItem(p Product, quantity int) { … }
```

(`{ … }` — на странице тело сокращено; полный текст в `main.go`.) Вопрос. Мы хотим написать для `Product` три метода: `InStock` — говорит,
есть ли остаток, `Sell` — вычитает проданное количество из `Stock`, `PriceSom` — возвращает цену в сумах. Какие получат pointer receiver?

**A)** только `Sell` · **B)** `Sell` и `InStock` · **C)** все три

<details>
<summary>Ответ</summary>

**C: все три.** `Sell` изменяет `Stock`, поэтому ему нужен pointer receiver (первое правило). `InStock` и `PriceSom` только читают, но по третьему
правилу все методы одного типа получают receiver одного вида. Если вы выбрали **A**, вы применили только первое правило;
**B** — вы отделили часть читающих методов, а правило оставляет их все вместе.

</details>

А `OrderStatus` маленький (один `int`) и не меняется, поэтому ему хватает value receiver: в следующем разделе.

## String: печатаем статус по имени

Метод пишется не только для структуры, а для любого объявленного вами типа ([Go spec: Method declarations](https://go.dev/ref/spec#Method_declarations)).
`OrderStatus` в GB-2.03 объявлен на основе `int`. Дадим ему метод `String`:

```go
// String holatning nomini qaytaradi; fmt uni oʻzi chaqiradi.
func (s OrderStatus) String() string {
	switch s {
	case StatusNew:
		return "yangi"
	case StatusPaid:
		return "toʻlangan"
	case StatusShipped:
		return "joʻnatilgan"
	case StatusCancelled:
		return "bekor qilingan"
	}
	return "nomaʼlum"
}
```

| Код | Что делает |
|---|---|
| `func (s OrderStatus) String() string {` | receiver `s` типа `OrderStatus` — value receiver (маленькое неизменяемое значение). Тип результата `string` |
| `switch s {` | ветка выбирается по значению `s` (GB-1.05) |
| `case StatusNew:` + `return "yangi"` | если статус `StatusNew`, возвращается его имя («новый»). Остальные три статуса записываются так же |
| `return "nomaʼlum"` | если пришло число, которого нет в списке (например, `OrderStatus(9)`): «неизвестный» |

`fmt` проверяет, есть ли у значения метод именно с именем `String`, возвращающий `string`, и если есть, вызывает его вместо печати числа
([pkg.go.dev/fmt](https://pkg.go.dev/fmt)). Как именно `fmt` это проверяет, мы раскроем в [GB-2.07](/lab/youtube/gb/gb-2-07/ru), в уроке про interface.
Итоговый `main`:

```go
var order Order
order.AddItem(olma, 3)
order.AddItem(non, 2)
order.Pay()
fmt.Println(len(order.Items), order.Total(), order.Status)
```

Новая строка одна — `order.Pay()`. Как напечатается последнее значение, статус?

**A)** `2 4400000 1` · **B)** `2 4400000 toʻlangan` · **C)** `2 4400000 StatusPaid`

<details>
<summary>Ответ</summary>

**B: `2 4400000 toʻlangan`.** `Println` нашла у `Status` метод `String` и вместо числа напечатала имя («оплачен»). **A** получилось бы без `String`
(в предыдущих разделах вы так видели `0` и `1`). **C** — `fmt` не знает, как константа названа в коде, он печатает только текст, который вернул `String`.

`main.go` в папке — это и есть итоговый код:

```console
$ go run .
2 4400000 toʻlangan
```

</details>

Теперь действия с заказом — методы `Order`: `AddItem` и `Pay` изменяют, `Total` читает, а статус печатается по имени.

## Частые ошибки

**1. Думать, что «метод изменяет переменную».** Метод вызывается после `order.`, и кажется, что он меняет `order`. На деле изменение зависит от типа
receiver: `func (o Order) Pay()` записывает в копию. Вы это уже видели выше (в разделе «Value receiver: Pay изменяет копию» напечаталось
`0`); исправление — `*Order`.

**2. В `AddItem` забыта звёздочка.** Самый частый вариант: не такой очевидный, как `Pay`, добавление строки написано через `append`.
В `_video/05-xato/main.go` receiver у `AddItem` — `o Order`, остальной код тот же. Отличается только строка заголовка:

```go
func (o Order) AddItem(p Product, quantity int) {
	item := OrderItem{ProductID: p.ID, Price: p.Price, Quantity: quantity}
	o.Items = append(o.Items, item)
}
```

`main` прежний: яблоки 3, хлеб 2, затем `fmt.Println(len(order.Items), order.Total())`. Заметит ли это компилятор? Что будет напечатано?

```console
$ ./_video/run.sh 05-xato go run .
0 0
```

Как читать: сообщения об ошибке нет, программа отработала, но и `len(order.Items)`, и `Total()` равны нулю. Каждый вызов добавил строку в свою
копию и потерял её вместе с копией: в копии заголовок `Items` тоже копия, `append` записал новый заголовок только в неё. `go vet` тоже молчит:

```console
$ ./_video/run.sh 05-xato go vet .
```

`go vet` ничего не напечатал (если подозрительного места нет, он молчит): код корректен по правилам Go, а логическую ошибку он не видит.
Эту ошибку не видят ни компилятор, ни `go vet`; её ловит результат или тест. Исправление — звёздочка в receiver: `func (o *Order) AddItem(…)`.
В работе на code review задают именно этот вопрос: метод изменяет значение — receiver указатель?

**3. Забыть, что `it` в цикле — копия.** То же правило действует в `for _, it := range`: `it` — копия строки, запись в неё не затрагивает
`Items` (эта ошибка встретится и в задании). Полная программа (в папке курса её нет):

```go
package main

import "fmt"

// OrderItem — buyurtmadagi bitta qator.
type OrderItem struct {
	ProductID int64
	Quantity  int
}

func main() {
	items := []OrderItem{{ProductID: 1, Quantity: 3}, {ProductID: 2, Quantity: 2}}
	for _, it := range items {
		it.Quantity += 1
	}
	fmt.Println(items[0].Quantity)
}
```

```console
$ go run .
3
```

Результат `3`, а не `4`. Здесь компилятор и `go vet` тоже молчат. Исправление — записывать в строку по индексу: `items[i].Quantity += 1` (`for i := range items`).

## Проверьте себя

**1.** Если метод с value receiver записывает в поле, изменится ли переменная, которая его вызвала?

<details>
<summary>Ответ</summary>

Нет. Value receiver получает копию значения, метод пишет в копию, и копия исчезает вместе с методом (вариант `Pay`, который напечатал `0`).

</details>

**2.** У `Pay` pointer receiver, а `order` — обычная переменная (`var order Order`). Нужно ли писать `&order`, чтобы вызвать `order.Pay()`?

<details>
<summary>Ответ</summary>

Нет. Раз `order` — переменная, Go сам превращает `order.Pay()` в `(&order).Pay()`.

</details>

**3.** (GB-2.02) Гарантирован ли порядок ключей при обходе `map` через `range`?

<details>
<summary>Ответ</summary>

Нет. Порядок не гарантирован, он может отличаться даже между двумя обходами в одной программе
([Go spec: For statements with range clause](https://go.dev/ref/spec#For_range)).

</details>

**4.** Что напечатает программа? (`OrderStatus` как в GB-2.03, с методом `String` выше.)

```go
fmt.Println(StatusShipped, OrderStatus(9), int(StatusPaid))
```

<details>
<summary>Ответ</summary>

`joʻnatilgan nomaʼlum 1`. У `StatusShipped` срабатывает `String` → `joʻnatilgan` («отправлен»); `OrderStatus(9)` — число, которого нет в списке,
`String` возвращает `nomaʼlum` («неизвестный»); `int(StatusPaid)` преобразован в обычный `int`, у него `String` нет, поэтому печатается число: `1`.
Полная программа (в папке курса её нет) состоит из типов и `String`:

```go
package main

import "fmt"

// OrderStatus — buyurtma holati.
type OrderStatus int

const (
	StatusNew OrderStatus = iota
	StatusPaid
	StatusShipped
	StatusCancelled
)

// String holatning nomini qaytaradi; fmt uni oʻzi chaqiradi.
func (s OrderStatus) String() string {
	switch s {
	case StatusNew:
		return "yangi"
	case StatusPaid:
		return "toʻlangan"
	case StatusShipped:
		return "joʻnatilgan"
	case StatusCancelled:
		return "bekor qilingan"
	}
	return "nomaʼlum"
}

func main() {
	fmt.Println(StatusShipped, OrderStatus(9), int(StatusPaid))
}
```

```console
$ go run .
joʻnatilgan nomaʼlum 1
```

</details>

`for i := range o.Items` даёт только индекс: `i` = 0, 1, 2 …. Когда строка найдена, прибавляем и пишем `return`: одинокий `return` в методе без результата
выходит из метода прямо здесь, до `append` внизу он не доходит:

func (o *Order) AddItem(p Product, quantity int) {
	for i := range o.Items {
		if o.Items[i].ProductID == p.ID {

func (o *Order) Cancel() error {
	if o.Status != StatusNew && o.Status != StatusPaid {

	o.Status = StatusCancelled

}
