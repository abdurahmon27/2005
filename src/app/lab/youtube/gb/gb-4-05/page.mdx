## Nimani oʻrganasiz

bozor katalogida har mahsulotning ID raqami bor, mijoz esa uni yoʻlda soʻraydi: `/products/1`, `/products/3`. Har ID uchun alohida pattern yozib boʻlmaydi.
Savol: bitta qoida hamma ID'ni qanday oladi? Yoʻq mahsulotga `404`ni, notoʻgʻri metodga `405`ni kim beradi: mux'mi yoki bizning handler'imizmi?

**Bitta gʻoya:** `ServeMux` har soʻrov uchun avval **metodi ham, yoʻli ham** mos pattern'ni qidiradi. Topsa, `{id}` kabi qiymatni soʻrovga yozib (`r.PathValue("id")`, matn) handler'ni chaqiradi.
Topmasa: yoʻli mos pattern bor boʻlsa, mux'ning oʻzi `405` + `Allow`, umuman yoʻq boʻlsa, mux'ning oʻzi `404 page not found` yozadi.
Shuning uchun handler'ga faqat oʻzi biladigan xatolar qoladi: `ParseInt` → `400`, `findProduct` → bizning `404`. Handler mux'siz chaqirilsa, `PathValue` boʻsh.
Metodsiz `"/"` pattern'i esa hamma yoʻl va metodga mos kelib, `404` bilan `405`ni yutib yuboradi; `"GET /{$}"` uni cheklaydi.

Dars oxirida siz:

- pattern'ga metod yozib (`"GET /products/{id}"`), `curl` bilan `200`, oʻzingizning `404`/`400`ingizni va mux'ning `404`/`405`ini bir-biridan ajratasiz;
- yoʻldagi qismni `r.PathValue("id")` bilan oʻqib, `strconv.ParseInt` bilan songa aylantirasiz va `findProduct` bilan mahsulotni topasiz;
- route'larni `newMux()` funksiyasiga yigʻib, `newMux().ServeHTTP(rec, req)` bilan serversiz test qilasiz;
- `"/"` pattern'i nega xato yoʻlga ham, notoʻgʻri metodga ham `200` berishini tushuntirib, `"GET /{$}"` bilan tuzatasiz;
- `TASK.md`da `GET /products/{id}/stock` route'ini oʻzingiz yozasiz, `go test .` oʻtguncha.

Bugungi uchta asosiy yangi tushuncha:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| pattern = `METOD yoʻl` | `mux.HandleFunc`ning birinchi argumenti: qaysi metod va qaysi yoʻlga mos kelishi. Mos kelmasa javobni mux yozadi: `404` yoki `405` + `Allow` | pattern (method + path) |
| `{id}` + `r.PathValue("id")` | yoʻlning bitta segmentiga mos keladigan oʻzgaruvchi qism; uning qiymatini mux soʻrovga yozadi, handler matn sifatida oʻqiydi | wildcard, `PathValue` |
| `"/"` va `"GET /{$}"` | `"/"` — hamma yoʻlga (va, metodsiz boʻlsa, hamma metodga) mos pattern; `{$}` — «yoʻl shu yerda tugaydi» | catch-all pattern, `{$}` |

Yordamchi nomlar: `http.Error(w, xabar, kod)` va `newMux()`. Boshqa yangi nomlarga yoʻlda bitta jumla beraman.

## Pattern'ga metod yoziladi

GB-4.03'da `catalogHandler` metodni oʻzi tekshirardi:

```go
func catalogHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodGet {
		w.Header().Set("Allow", http.MethodGet)
		w.WriteHeader(http.StatusMethodNotAllowed)
		return
	}
	// … catalog'ni JSON qilib yozish (GB-4.03)
}
```

Beshta qator faqat bitta narsa uchun: `GET` boʻlmasa, `405` + `Allow` yozib chiqib ketish. Har handler'da shuni takrorlash kerak. Go 1.22'dan beri ([Go 1.22 release notes](https://go.dev/doc/go1.22#enhanced_routing_patterns)) bu tekshiruvni pattern oʻzi qiladi: pattern oldiga metod yoziladi.

```text
METOD  YOʻL
GET    /products
HEAD   /products   (GET pattern'i oladi)
```

Qoida: metod, boʻshliq, keyin yoʻl. `GET /products` — «`GET` soʻrovi **va** aynan shu yoʻl». Metod yozilmagan pattern (`/products`) hamma metodni oladi.
`GET` pattern'i `HEAD` soʻrovini ham oladi: `HEAD` `GET` bilan bir xil javobni soʻraydi, lekin body'siz ([RFC 9110, HEAD](https://www.rfc-editor.org/rfc/rfc9110#name-head)).

`newServer`dagi ikki qator shunday oʻzgaradi: birinchi argumentga metod qoʻshiladi, ikkinchi argument — handler — oʻsha:

```go
func newServer(addr string) *http.Server {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /products", catalogHandler)
```

Endi `catalogHandler`dan `r.Method` tekshiruvini oʻchiramiz: `GET` yoki `HEAD` boʻlmagan soʻrov handler'ga yetib kelmaydi.

```go
func catalogHandler(w http.ResponseWriter, r *http.Request) {
	products := catalog
	if products == nil {
		products = []Product{}
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(products)
}
```

Qolgani GB-4.03 vazifasining oʻzi: `catalog` boʻsh boʻlsa ham JSON `[]` chiqsin (`null` emas), `Content-Type`, keyin `Encode`. Toʻliq fayl keyinroq, «Papkadagi toʻliq kod» boʻlimida.

Birinchi terminalda serverni ishga tushiramiz, GB-4.04'dagidek: `go run .`. Dastur banner yozadi va soʻrov kutadi; buyruq qaytmaydi, shuning uchun bu terminalni ochiq qoldiring.

```console
$ go run .
bozor API: http://localhost:8765
```

(Bu blokni Ctrl+C bilan toʻxtatib oldim; toʻxtatganda Go `signal: interrupt` yozadi, [GB-4.02](/lab/youtube/gb/gb-4-02).)

Ikkinchi terminalda `curl -i`: status qatori va sarlavhalar ham chiqadi ([GB-4.04](/lab/youtube/gb/gb-4-04)). Yangi bayroq `-X` soʻrov metodini beradi. Bu yoʻlga faqat `GET` pattern'i bor, biz esa `POST` yuboramiz:

```bash
curl -i -X POST http://localhost:8765/products
```

**Bashorat.** `POST /products`: status va `Allow` qanday?

**A)** `405` va `Allow: GET` · **B)** `405` va `Allow: GET, HEAD` · **C)** `404` va `Allow` yoʻq

<details>
<summary>Javob</summary>

**B.** Yoʻl mos, metod mos emas: mux `405 Method Not Allowed` yozadi va `Allow`ga shu yoʻl qabul qiladigan metodlarni qoʻyadi. `GET` pattern'i `HEAD`ni ham oladi, shuning uchun `GET, HEAD`.
**A** ni tanlagan boʻlsangiz, GB-4.03'dagi qoʻlda yozilgan `Allow: GET`ni esladingiz: u yerda `HEAD`ni biz qoʻshmagan edik. **C** — yoʻl mavjud, shuning uchun `404` emas.

</details>

```console
$ curl -i -X POST http://localhost:8765/products
HTTP/1.1 405 Method Not Allowed

Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 12:02:14 GMT
Content-Length: 19

Method Not Allowed
```

Qatorma-qator:

| Qator | Nima |
|---|---|
| `HTTP/1.1 405 Method Not Allowed` | status qatori ([GB-4.01](/lab/youtube/gb/gb-4-01)): `405` — yoʻl bor, metod notoʻgʻri |
| `Allow: GET, HEAD` | bu yoʻl qabul qiladigan metodlar; `405`da bu sarlavha majburiy ([RFC 9110, 405](https://www.rfc-editor.org/rfc/rfc9110#name-405-method-not-allowed)) |
| `Content-Type`, `X-Content-Type-Options` | oddiy matn, UTF-8'da; `nosniff` brauzerga turini taxmin qilmaslikni aytadi |
| `Date`, `Content-Length: 19` | vaqt va body hajmi: `Method Not Allowed` + oxirgi yangi qator = 19 bayt |
| `Method Not Allowed` | body |

Bu javobni **handler emas, mux yozdi**: `catalogHandler` chaqirilmadi.

```console
Date: Fri, 27 Nov 2026 12:02:14 GMT
Content-Length: 19

404 page not found
```

### Mux qoidasi

Endi mux qanday qaror qilishini bir joyga yigʻamiz:

```text
soʻrov: METOD + YOʻL
   │
   ├─ metodi ham, yoʻli ham mos pattern bor ──► handler(w, r) chaqiriladi
   │
   ├─ faqat yoʻli mos pattern bor ────────────► mux oʻzi: 405 + Allow
   │
   └─ yoʻli ham mos emas ─────────────────────► mux oʻzi: 404 page not found
```

Uchala natijadan faqat birinchisida bizning kod ishlaydi. Qolgan ikkitasini mux yozadi: handler'da `405` ham, «yoʻl topilmadi» ham yoʻq.

## `{id}`: yoʻldagi oʻzgaruvchi qism

Endi bitta mahsulot. Pattern'da yoʻlning oʻzgaruvchi qismi jingalak qavsga olinadi: `{id}` — **wildcard**. U **bitta segmentni** oladi: ikki slesh orasidagi bitta qismni.

```text
GET /products/{id}
/products/3          id = "3"
/products/abc        id = "abc"
/products/3/stock    mos emas
```

| Yoʻl | Natija | Sababi |
|---|---|---|
| `/products/3` | `id = "3"` | `3` — bitta segment |
| `/products/abc` | `id = "abc"` | pattern son ekanini **tekshirmaydi**: har qanday matn mos |
| `/products/3/stock` | mos emas | `3/stock` — ikki segment, `{id}` bittasini oladi |

Muhim: `id` har doim **matn** (`string`). Songa aylantirish bizning ishimiz.

`productHandler`ni qaytadan yozamiz: GB-4.04'da u har doim olmani berardi.

```go
func productHandler(w http.ResponseWriter, r *http.Request) {
	id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)
	if err != nil {
		http.Error(w, "id butun son boʻlishi kerak", http.StatusBadRequest)
		return
	}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `func productHandler(w http.ResponseWriter, r *http.Request) {` | GB-4.03'dagi handler imzosi |
| 2 | `r.PathValue("id")` | mux yoʻldan topgan qiymatni **matn** qilib qaytaradi. Qavs ichidagi nom pattern'dagi `{id}` bilan bir xil boʻlishi shart |
| 2 | `strconv.ParseInt(…, 10, 64)` | matnni songa aylantiradi ([GB-3.06](/lab/youtube/gb/gb-3-06)): `10` — oʻnlik sanoq, `64` — `int64`. Ikki qiymat qaytadi: son va xato (`id`, `err`) |
| 3 | `if err != nil {` | xato boʻlsa (`abc` son emas), blokka kiramiz |
| 4 | `http.Error(w, "id butun son boʻlishi kerak", http.StatusBadRequest)` | javobni yozadi: `Content-Type` oddiy matn, keyin status `400`, keyin xabar. Tartib GB-4.03'dagidek: sarlavha → status → body |
| 5 | `return` | handler'dan chiqish. `http.Error` handler'ni **toʻxtatmaydi**: `return` boʻlmasa, kod pastga davom etadi (pastda «Koʻp uchraydigan xatolar»da koʻrasiz) |

`StatusBadRequest` — `400`: soʻrovning oʻzi xato. Davomi: son bor, endi mahsulotni topamiz. `findProduct` — GB-2.04'dagi funksiyaning oʻzi:

```go
func findProduct(products []Product, id int64) *Product {
	for i := range products {
		if products[i].ID == id {
			return &products[i]
		}
	}
	return nil
}
```

Topilsa — slice ichidagi mahsulotga koʻrsatkich (`&products[i]`), topilmasa — `nil`. Handler'ning davomi:

```go
	p := findProduct(catalog, id)
	if p == nil {
		http.Error(w, "mahsulot topilmadi", http.StatusNotFound)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(p)
}
```

`p` — `*Product`. `nil` boʻlsa: `StatusNotFound` (`404`), xabar `mahsulot topilmadi`, `return`. Topilsa: GB-4.03'dagidek `Content-Type`, keyin `Encode`.

Oxirgi qadam: route. `"/products/1"` oʻrniga:

```go
	mux := http.NewServeMux()
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /products", catalogHandler)
	mux.HandleFunc("GET /products/{id}", productHandler)
```

**Route** = pattern va uning handler'i. Serverni qayta ishga tushiramiz (birinchi terminalda `go run .`) va ikkinchi terminaldan uch soʻrov yuboramiz.

```console
$ curl -i http://localhost:8765/products/3
HTTP/1.1 200 OK
Content-Type: application/json
Date: Fri, 27 Nov 2026 12:02:14 GMT
Content-Length: 51

{"id":3,"name":"oʻrik","price":3500000,"stock":5}
```

`200`, body'da oʻrik; narxi tiyinda ([GB-1.03](/lab/youtube/gb/gb-1-03)). `PathValue` `"3"` matnini berdi, `ParseInt` songa aylantirdi, `findProduct` oʻrikni topdi.

```console
$ curl -i http://localhost:8765/products/99
HTTP/1.1 404 Not Found
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 12:02:14 GMT
Content-Length: 19

mahsulot topilmadi
```

`99` yoʻq: yana `404`, lekin body boshqa: `mahsulot topilmadi`. Bu **bizning** `404`imiz: yoʻl mos keldi, handler ishladi.

```console
$ curl -i http://localhost:8765/products/abc
HTTP/1.1 400 Bad Request
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 12:02:14 GMT
Content-Length: 29

id butun son boʻlishi kerak
```

`abc` pattern'ga mos, lekin `ParseInt` uni oʻqiy olmaydi: `400 Bad Request`. (`Content-Length: 29`: `ʻ` belgisi ikki bayt, [GB-2.10](/lab/youtube/gb/gb-2-10).)

Demak, `404` ikki xil. Bu darsning asosiy ajratmasi:

| Soʻrov | Status | Kim yozdi | Body |
|---|---|---|---|
| `GET /narsalar` | `404` | mux: yoʻl yoʻq | `404 page not found` |
| `GET /products/99` | `404` | handler (bizning kod): yoʻl bor, mahsulot yoʻq | `mahsulot topilmadi` |
| `GET /products/abc` | `400` | handler: id son emas | `id butun son boʻlishi kerak` |
| `POST /products` | `405` | mux: yoʻl bor, metod yoʻq | `Method Not Allowed` + `Allow: GET, HEAD` |

`{id}` faqat **bitta** segment oladi. Shuning uchun slesh bilan tugagan yoʻl ham, uch segmentli yoʻl ham mux'ning `404`ini oladi:

```console
$ curl -i http://localhost:8765/products/3/
HTTP/1.1 404 Not Found
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 12:02:14 GMT
Content-Length: 19

404 page not found
$ curl -i http://localhost:8765/products/3/stock
HTTP/1.1 404 Not Found
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 12:02:14 GMT
Content-Length: 19

404 page not found
```

(`/products/3/stock` — vazifada yoziladigan route; hozircha uni hech kim qabul qilmaydi. `/products/3/` videoda emas, papkadagi README'da: men uni ham qayta ishga tushirdim.)

`GET` pattern'i `HEAD`ni ham oladi. `curl -I` — `HEAD` yuboradi va faqat sarlavhalarni koʻrsatadi:

```console
$ curl -I http://localhost:8765/products/3
HTTP/1.1 200 OK
Content-Type: application/json
Date: Fri, 27 Nov 2026 12:02:14 GMT
Content-Length: 51

```

Sarlavhalar `GET` javobiniki bilan bir xil (`Content-Length: 51` ham), body yoʻq. Bu buyruq videoda yoʻq; men uni oʻzim ishga tushirdim ([curl man page](https://curl.se/docs/manpage.html): `-I`).

## Testda `PathValue` boʻsh

Endi testga, GB-4.03'dagi shaklda: soʻrov `/products/3`, recorder, va `productHandler`ni toʻgʻridan-toʻgʻri chaqiramiz. Status `200` kutiladi.

```go filename="_video/02-test-direct/handler_test.go" showLineNumbers
package main

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestProduct(t *testing.T) {
	req := httptest.NewRequest(http.MethodGet, "/products/3", nil)
	rec := httptest.NewRecorder()
	productHandler(rec, req)
	if rec.Code != http.StatusOK {
		t.Errorf("status %d, kutilgan %d: %s", rec.Code, http.StatusOK, rec.Body.String())
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10 | `httptest.NewRequest(http.MethodGet, "/products/3", nil)` | `GET /products/3` soʻrovini yasaydi (GB-4.03) |
| 11 | `httptest.NewRecorder()` | javobni ushlaydigan `w` |
| 12 | `productHandler(rec, req)` | handler'ni oddiy funksiya kabi chaqiramiz |
| 13–15 | `if rec.Code != http.StatusOK { t.Errorf(…) }` | status `200` boʻlmasa, testni yiqitadi va statusni hamda body'ni yozadi (`%d` — son, `%s` — matn) |

## `"/"` pattern'i hamma narsani yutadi

Endi bosh sahifa. `homeHandler` `/` yoʻliga API nomini yozadi:

```go

	fmt.Fprintln(w, "bozor API")

// newMux ichida:
	mux.HandleFunc("/", homeHandler)
```

Koʻp misollarda bosh sahifaning pattern'i shunday: faqat `/`, metodsiz. Serverni qayta ishga tushiramiz. Mijoz yoʻlda xato qildi: `products` oʻrniga `produkts`. Bunday yoʻl jadvalda yoʻq.

## Koʻp uchraydigan xatolar

### 1. «`{id}` son ekanini tekshiradi» deb oʻylash

`{id}` har qanday bitta segmentni oladi: `/products/abc` ham mos (yuqorida koʻrdik). Tekshiruv — handler'da: `ParseInt` → `400`. Pattern'ga ishonib, `PathValue`ni tekshirmasdan ishlatsangiz, `abc` handler'ning ichida kutilmagan holat boʻladi.
`ParseInt` yana: `+3` va `03`ni ham `3` deb oʻqiydi (bitta mahsulotga bir nechta URL), `int64`ga sigʻmaydigan katta son `400` oladi (README'dagi izoh; men bu ikkitasini qayta ishga tushirmadim). Ishlab turgan API'da `id < 1`ni ham rad etish mumkin; bu darsda soddalik uchun yoʻq.

### 2. `"/"` — hamma narsani yutadigan pattern

Darsning oʻrtasida koʻrdingiz: `mux.HandleFunc("/", homeHandler)` — xato yoʻlga ham, notoʻgʻri metodga ham `200`. Bu **jim** xato: hech qanday error yoʻq, javob notoʻgʻri. Tuzatish — `"GET /{$}"` (yuqoridagi «`"/"` pattern'i hamma narsani yutadi» boʻlimi).

### 3. `http.Error`dan keyin `return` yozmaslik

`http.Error` javobni yozadi, lekin handler'ni toʻxtatmaydi. `return`ni oʻchirib koʻramiz (bu `productHandler`ning 400 blokida, `return` qatorini olib tashlang; men buni papka nusxasida qildim, kurs papkasida bu oʻzgarish yoʻq):

```go

	if err != nil {
		http.Error(w, "id butun son boʻlishi kerak", http.StatusBadRequest)
	}
	p := findProduct(catalog, id)
	if p == nil {
		http.Error(w, "mahsulot topilmadi", http.StatusNotFound)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(p)
}
```


Statusda `400`, lekin body'da **ikkita** xabar. Sababi: `ParseInt` xatosida `id` — `0`; `return` yoʻq, kod davom etdi, `findProduct(catalog, 0)` `nil` qaytardi va `http.Error` ikkinchi marta chaqirildi. Birinchi javob allaqachon ketgan edi, shuning uchun ikkinchisining `404` statusi eʼtiborga olinmadi, faqat matni qoʻshildi. Server ishlayotgan terminal buni log'ga yozadi:

```text
2026/11/27 17:03:01 http: superfluous response.WriteHeader call from main.productHandler (main.go:67)
```

(Bu server log'idan satr; vaqt mahalliy soat boʻyicha. `superfluous response.WriteHeader call` — «ortiqcha `WriteHeader` chaqiruvi»: status ikkinchi marta yozilmoqchi boʻldi, `main.go:67` — oʻsha chaqiruv.) Tuzatish: `http.Error`dan keyin har doim `return`. Papkadagi `tekshiruv_test.go` ham body'ni aynan solishtirib, buni ushlaydi.

### 4. `PathValue` nomi pattern'dagi nomga mos emas

Pattern'da `{id}`, handler'da `r.PathValue("product")` — qavs ichidagi nom bir xil boʻlishi shart. Men papka nusxasida shu bir qatorni almashtirdim: `r.PathValue("id")` oʻrniga `r.PathValue("product")`.

```console
$ curl -i http://localhost:8765/products/3
HTTP/1.1 400 Bad Request
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 12:03:02 GMT
Content-Length: 29

id butun son boʻlishi kerak
```

Yoʻlda `3` bor, javob esa `400`. Kompilyator ham, mux ham xato demaydi: `PathValue("product")` shunchaki boʻsh matn qaytaradi, xuddi mux'siz testdagidek. Belgi: «toʻgʻri id'ga `400`». Tekshiring: `{…}` ichidagi nom va `PathValue("…")` bir xilmi.

### 5. Oxirida slesh va `{id}`

`/products/3/` — mux'ning `404`i: `{id}` faqat bitta segment, slesh yangi (boʻsh) segment boshlaydi (yuqoridagi `curl` natijasi). Mijozga `/products/3` yozishni ayting; `{id}` ni sleshli qilib «tuzatmang».

## Oʻzingizni tekshiring

**1.** Faqat `GET /products/{id}` pattern'i bor. `POST /products/3` kelsa, status va sarlavha qanday? Kim yozadi?

<details>
<summary>Javob</summary>

`405 Method Not Allowed` va `Allow: GET, HEAD`. Javobni mux yozadi: yoʻli mos pattern bor, metodi mos emas. Handler chaqirilmaydi.

</details>

**2.** `productHandler(rec, req)`ni testda toʻgʻridan-toʻgʻri chaqirdingiz. `PathValue("id")` nega boʻsh?

<details>
<summary>Javob</summary>

`PathValue`ni pattern'ni tanlagan **mux** toʻldiradi: u `id = "3"`ni soʻrovga yozib, keyin handler'ni chaqiradi. Toʻgʻridan-toʻgʻri chaqiruvda mux yoʻq, soʻrovda `id` yoʻq, shuning uchun `""`. Tuzatish: testni `newMux().ServeHTTP(rec, req)` orqali oʻtkazish.

</details>

**3.** [GB-4.02](/lab/youtube/gb/gb-4-02)dan: `http.DefaultClient`ning `Timeout`i qancha? Bu hozirgi dars bilan nima aloqasi bor: `curl` va client farqlimi?

<details>
<summary>Javob</summary>

`0`: cheklov yoʻq, shuning uchun ishda `Timeout`ni oʻzimiz beramiz. Tekshirish uchun men kursning papkasidan tashqarida kichik dastur yozdim (kursda yoʻq; `fmt.Println(http.DefaultClient.Timeout)`):

```go
package main

import (
	"fmt"
	"net/http"
)

func main() {
	fmt.Println(http.DefaultClient.Timeout)
}
```

```console
$ go run .
0s
```

`0s` — nol davomiylik, ya'ni muddat qoʻyilmagan. Bu darsning serveri bilan aloqasi shu: server tomonda `ReadHeaderTimeout` ([GB-4.04](/lab/youtube/gb/gb-4-04)), client tomonda `Timeout` — ikkalasini ham oʻzimiz beramiz.

</details>

**4.** Bashorat: faqat shu route'lar bor: `GET /{$}`, `GET /health`, `GET /products`, `GET /products/{id}`. `curl -i http://localhost:8765/products/1/stock` nima qaytaradi?

<details>
<summary>Javob</summary>

`404 page not found`, mux'dan: `{id}` bitta segment oladi, `/products/1/stock` esa uch segmentli, hech bir pattern'ga mos emas. Men buni vazifa yechilmagan `main.go` bilan qayta ishga tushirdim:

```console
$ curl -i http://localhost:8765/products/1/stock
HTTP/1.1 404 Not Found
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 12:02:16 GMT
Content-Length: 19

404 page not found
```

Vazifaning birinchi qadami aynan shu `404`ni yoʻq qiladi.

</details>

**5.** `"/"` pattern'i bor, `GET /products/3` ham bor. `GET /products/3` qaysi handler'ga boradi va nega?

<details>
<summary>Javob</summary>

`productHandler`ga. Ikkala pattern mos, lekin `GET /products/{id}` aniqroq: uning har soʻrovini `"/"` ham oladi, aksi emas. Aniqrogʻi yutadi; tartib ahamiyatsiz (yuqoridagi `curl`da `/products/3` — JSON).

</details>

Ombor xodimiga butun mahsulot emas, faqat qoldiq (`Stock`) kerak: `GET /products/{id}/stock`. `main.go`dagi `stockHandler` hozir boʻsh, `newMux`da route yoʻq, shuning uchun yuqorida koʻrdingiz: mux oʻzi `404 page not found` beradi.

- 🟢 **1-qadam, route.** `newMux`ga `GET /products/{id}/stock` pattern'ini `stockHandler` bilan qoʻshing (`VAZIFA` izohi turgan joyga).
- 🟡 **2-qadam, handler.** `stockHandler` id'ni yoʻldan oʻqisin (`productHandler`dagidek): son boʻlmasa `http.Error(w, "id butun son boʻlishi kerak", http.StatusBadRequest)` va `return`; `findProduct` `nil` qaytarsa `http.Error(w, "mahsulot topilmadi", http.StatusNotFound)` va `return`; topilsa qoldiqni bitta qator matn qilib yozing: `fmt.Fprintln(w, p.Stock)` (olma uchun `40`).

```go
func stockHandler(w http.ResponseWriter, r *http.Request) {
	id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)
	if err != nil {
		http.Error(w, "id butun son boʻlishi kerak", http.StatusBadRequest)
		return
	}
	p := findProduct(catalog, id)
	if p == nil {
		http.Error(w, "mahsulot topilmadi", http.StatusNotFound)
		return
	}
	fmt.Fprintln(w, p.Stock)
}
```

```go
	mux.HandleFunc("GET /products/{id}", productHandler)
	mux.HandleFunc("GET /products/{id}/stock", stockHandler)
```
