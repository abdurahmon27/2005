## Что вы узнаете

`GET /stock` запрашивает остаток абрикосов у поставщика. Ответ приходит за 3 секунды, а клиент уходит через 1 секунду. Зачем handler ждёт ещё 2 секунды?

**Одна идея:** у ожидающей горутины должен быть второй путь выхода. `select` ждёт результат или сигнал отмены; контекст передаёт этот сигнал между вызовами.

После урока вы:

- зададите таймаут через `select` и `time.After`;
- напишете `checkStock(ctx, id)`, учитывающую `ctx.Done()` и `ctx.Err()`;
- завершите ожидание handler через `r.Context()`, когда клиент уйдёт;
- выполните задания `sumStock` и `/report` с ограниченным сроком до прохождения тестов.

| Слово | Простой смысл | Английский термин |
|---|---|---|
| `select` | выполнение одной готовой операции из нескольких операций с каналами | select statement |
| отмена контекста | закрытие `Done` сообщает ожидающему коду, что пора остановиться | context cancellation |
| контекст запроса | срок, отмена и значения HTTP-запроса | request context |

Вспомогательное понятие **утечка горутины** — ненужная горутина, которая навсегда осталась в ожидании. `curl --max-time` ограничивает время ожидания клиента.

## Поставщик и обычное ожидание

`supplier` имитирует поставщика: в карте `stocks` ID → количество. ID 1 — `olma` (яблоко), 40; ID 2 — `non` (хлеб), 120; ID 3 — `oʻrik` (абрикос), 5. `supplierDelay` — 3 секунды.

```go filename="_video/01-kutish/supplier.go" showLineNumbers
package main

import "time"

// stocks: yetkazib beruvchidagi qoldiqlar (ID → dona): olma 1, non 2, oʻrik 3.
var stocks = map[int64]int{1: 40, 2: 120, 3: 5}

// supplierDelay: yetkazib beruvchi shuncha vaqtda javob beradi.
var supplierDelay = 3 * time.Second

// supplier qoldiqni yetkazib beruvchidan soʻraydi: javob supplierDelay'dan keyin channel'ga keladi.
func supplier(id int64) chan int {
	ch := make(chan int, 1)
	go func() {
		time.Sleep(supplierDelay)
		ch <- stocks[id]
	}()
	return ch
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1–3 | `package main`, `import "time"` | исполняемый пакет и пакет времени |
| 5–6 | `stocks` | комментарий и значение `map[int64]int`: ID → количество |
| 8–9 | `supplierDelay` | комментарий и `3 * time.Second`: 3 секунды |
| 11–12 | `supplier(id int64) chan int` | комментарий и сигнатура: принимает ID, возвращает канал `int` |
| 13 | `make(chan int, 1)` | создаёт буфер для одного значения |
| 14 | `go func() {` | запускает новую горутину |
| 15 | `time.Sleep(...)` | ожидает в этой горутине |
| 16 | `ch <- stocks[id]` | отправляет остаток в канал |
| 17 | `}()` | вызывает анонимную функцию |
| 18–19 | `return ch`, `}` | возвращает канал, не дожидаясь результата, закрывает функцию |

Зачем буферу одно место, измерим в необязательном разделе. Сначала `main`:


| Строка | Что делает |

| 11–12 | `fmt.Println` выводит остаток и прошедшее время; `Round(time.Second)` округляет до секунды; `main` заканчивается |

## select: два ожидания, один выбор

Если ответа нет, обычный приём остаётся ждать. **`select`** следит за несколькими операциями с каналами. Каждый `case` внутри `{}` задаёт отправку или приём; после `:` идёт тело этой ветки.

`time.After(time.Second)` возвращает канал. После истечения интервала в него отправляется текущее время. Само значение времени не нужно: слева от `case <-time.After(...)` нет переменной.

```go filename="_video/02-select/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	start := time.Now()
	select {
	case n := <-supplier(3):
		fmt.Println("qoldiq:", n)
	case <-time.After(time.Second):
		fmt.Println("supplier javob bermadi")
	}
	fmt.Println(time.Since(start).Round(time.Second))
}
```

Новые строки: 10 — `select`; 11–12 — готовый остаток принимается в `n` и выводится; 13–14 — если готов таймер, выводится сообщение. 15 закрывает `select`, 16 выводит общее время.

| Время | Канал supplier | Канал After | main |
|---|---|---|---|
| 0 s | пуст | таймер ожидает | `select` ожидает |
| ≈1 s | ещё пуст | приём готов | только второй `case`, затем выход |
| ≈3 s | supplier может отправить значение | выбор завершён | эта CLI уже завершилась |

Правило Go: если в момент выбора готовы несколько операций, одна выбирается равновероятно псевдослучайным образом. Верхний `case` не имеет приоритета. Без `default`, когда ни одна операция не готова, `select` ждёт.

Что будет выведено? **A)** остаток, `3s` · **B)** ответа нет, `1s` · **C)** ответа нет, `3s`.

<details>
<summary>Ответ</summary>

**B.** В этом эксперименте таймер стал готов раньше. A: вы не учли второй путь выхода из ожидания. C: `main` не ждёт завершения спящей горутины supplier, GB-7.01.

</details>

```console
$ cp _video/02-select/*.go .
$ go run .
supplier javob bermadi
1s
```

## context: передаём срок в вызов

Здесь `After` обслуживал один `select`. Если handler вызывает функции остатка, базы и оплаты, им нужен общий сигнал отмены.

**Отмена контекста** передаёт этот сигнал. `checkStock` принимает первым параметром `ctx context.Context`. Второй `case` ждёт `ctx.Done()`. В этот канал не отправляются значения; при отмене он закрывается. Приём из закрытого канала не ждёт.

`WithTimeout` знаком из GB-5.05: следующий `main` задаёт срок context в одну секунду.

```go filename="_video/03-timeout/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"time"
)

func checkStock(ctx context.Context, id int64) (int, error) {
	select {
	case n := <-supplier(id):
		return n, nil
	case <-ctx.Done():
		return 0, ctx.Err()
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), time.Second)
	defer cancel()
	start := time.Now()
	n, err := checkStock(ctx, 3)
	fmt.Println(n, err, time.Since(start).Round(time.Second))
}
```

| Строка | Что делает |
|---|---|
| 4 | импортирует пакет `context` |
| 9 | `checkStock(ctx, id)` возвращает остаток и ошибку |
| 10–12 | если выбран ответ supplier, `n, nil`: результат есть, ошибки нет |
| 13–14 | если `Done` закрыт, `0, ctx.Err()`: вместо результата ноль, причина отдельно |
| 15–16 | закрывает `select` и функцию |
| 19 | получает из `Background()` контекст со сроком и функцию `cancel` |
| 20 | при возврате из `main` вызов `cancel()` освобождает ресурсы |
| 21–24 | сохраняет время, передаёт `ctx`, выводит результат, ошибку и время |

Supplier ждёт 3 секунды, context — 1 секунду. **A)** `5 <nil> 3s` · **B)** `0 context deadline exceeded 1s` · **C)** `0 context canceled 1s`?

<details>
<summary>Ответ</summary>

**B.** Срок истёк: `context deadline exceeded` означает «срок контекста превышен». A: ожидание трёхсекундного результата ещё не завершилось. C: в этот раз сигнал пришёл не от ручного `cancel()`.

</details>

```console
$ cp _video/03-timeout/*.go .
$ go run .
0 context deadline exceeded 1s
```

| Состояние context | Done | Err |
|---|---|---|
| ещё активен | открыт | `nil` |
| срок истёк | закрыт | `context.DeadlineExceeded` |
| отменён по другой причине | закрыт | `context.Canceled` |

`context.Background()` никогда не отменяется; его `Done()` возвращает `nil`. Приём из `nil`-канала не становится готовым. Поэтому в `checkStock` с `Background()` второй путь не срабатывает.

`Err()` возвращает значение ошибки; `fmt.Println` выводит её текст. Не сравнивайте текст: используйте `errors.Is(err, context.DeadlineExceeded)` или `errors.Is(err, context.Canceled)`.

## WithCancel: не ждём истечения срока

`WithCancel` не устанавливает собственного срока. Его контекст отменяется при вызове `cancel()` или отмене родительского контекста. Здесь родитель — `Background()`, поэтому сигнал подаём сами.

```go filename="_video/04-cancel/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"time"
)

func checkStock(ctx context.Context, id int64) (int, error) {
	select {
	case n := <-supplier(id):
		return n, nil
	case <-ctx.Done():
		return 0, ctx.Err()
	}
}

func main() {
	start := time.Now()
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()
	go func() {
		time.Sleep(time.Second)
		cancel()
	}()
	n, err := checkStock(ctx, 3)
	fmt.Println(n, err, time.Since(start).Round(time.Second))
}
```

Новые строки: 20 получает context и `cancel`; 21 сохраняет `defer cancel()`. Горутина в строках 22–25 спит секунду и вызывает `cancel()`. Строка 26 передаёт `ctx` той же `checkStock`.

Что будет выведено? **A)** `0 context canceled 1s` · **B)** `0 context deadline exceeded 1s` · **C)** `5 <nil> 3s`?

<details>
<summary>Ответ</summary>

**A.** `context canceled` — «контекст отменён». B: срок не задан. C: `Done` закрывается до появления результата. Повторные вызовы `cancel()` ничего не делают, поэтому `defer cancel()` остаётся.

</details>

```console
$ cp _video/04-cancel/*.go .
$ go run .
0 context canceled 1s
```

`cancel()` можно вызывать из нескольких горутин. Он не ждёт завершения работ: он подаёт сигнал остановки. Сама работа должна следить за сигналом.

Три правила: `ctx` — первый параметр; не храните контекст внутри struct. Создавшая контекст функция должна использовать `cancel`; здесь удобен `defer cancel()`. Отмена родителя отменяет и производные контексты.

**Десять горутин ждут один `ctx.Done()`. Один `cancel()`: сколько из них могут выйти? A)** одна · **B)** все десять · **C)** ни одной.

<details>
<summary>Ответ</summary>

**B.** Канал закрыт: приём готов для каждой горутины. Одно отправленное значение получил бы только один получатель. Закрытие сигнализирует всем; одновременное выполнение этих горутин не гарантируется.

</details>

## HTTP: потерянный сигнал с Background

`GET /stock` — сокращённый route этой лаборатории. В полном каталоге его назначение соответствует `GET /products/{id}/stock`, GB-4.05.

Следующая первая попытка ошибочна: handler передаёт `Background()` вместо `r.Context()`. Связь с контекстом запроса теряется.

```go filename="_video/05-background/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"time"
)

func checkStock(ctx context.Context, id int64) (int, error) {
	select {
	case n := <-supplier(id):
		return n, nil
	case <-ctx.Done():
		return 0, ctx.Err()
	}
}

func stockHandler(w http.ResponseWriter, r *http.Request) {
	start := time.Now()
	n, err := checkStock(context.Background(), 3)
	if err != nil {
		fmt.Println("toʻxtadi:", err, time.Since(start).Round(time.Second))
		return
	}
	fmt.Println("javob yozildi", time.Since(start).Round(time.Second))
	fmt.Fprintln(w, "qoldiq:", n)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /stock", stockHandler)
	log.Fatal(http.ListenAndServe("localhost:8093", mux))
}
```

Новые строки: 6–7 импортируют `log` и `net/http`. 20–29 — handler `stockHandler(w http.ResponseWriter, r *http.Request)` с объектом записи ответа и указателем на запрос. 21 сохраняет время; 22 ждёт остаток с `Background()`.

23–26: при ошибке в терминал сервера пишутся `toʻxtadi:` («остановлено») и причина, затем handler возвращается. 27 — лог `javob yozildi` («ответ записан»). 28 — `fmt.Fprintln(w, ...)` пытается записать ответ клиенту. Этот лог не подтверждает получение ответа клиентом.

31–35: `main`, новый mux, регистрация `GET /stock`; `ListenAndServe` слушает порт, при ошибке `log.Fatal` выводит её и завершает процесс.

Сервер использует `localhost:8093`. Перед экспериментом я проверил, что порт свободен. Если он занят, замените порт в обеих копиях серверных файлов и в адресе curl на один свободный номер.

`go build; ./bozor &`: `;` выполняет команды последовательно, `&` оставляет в фоне только binary. `kill %1` останавливает первую фоновую работу этого терминала. Используйте отдельный терминал Bash без других фоновых работ.

`curl -sS --max-time 1`: `-s` скрывает лишний вывод; `-S` показывает ошибку; `--max-time 1` ограничивает передачу одной секундой.

Клиент уходит через 1 секунду. Что в логе сервера? **A)** `toʻxtadi: ... 1s` · **B)** `javob yozildi 3s` · **C)** ничего.

<details>
<summary>Ответ</summary>

**B.** Канал `Done()` у `Background()` равен `nil`; уход клиента его не отменяет. A: контексты не связаны. C: сервер продолжает работу и пишет лог после ответа supplier.

</details>

```console
$ cp _video/05-background/*.go .
$ go build; ./bozor &
$ curl -sS --max-time 1 localhost:8093/stock
curl: (28) Operation timed out after 1000 milliseconds with 0 bytes received
javob yozildi 3s
```

`go build` ничего не вывел. Отправьте curl после начала прослушивания порта. `(28)` — ошибка таймаута curl; 1000 миллисекунд — 1 секунда; получено 0 байт ответа. Последняя строка принадлежит серверу, а не curl, и появляется ещё через 2 секунды.

Вывод получен повторным запуском. Номер фоновой работы и номер процесса оболочки опущены. Два процесса пишут в один терминал; строки могут перемешаться, вместо 1000 может быть 1001.

## r.Context: ожидание связано с запросом

Исправление — один аргумент: `checkStock(r.Context(), 3)`. Контекст запроса переносил значения в GB-6.04; теперь используем его отмену.

Сервер `net/http` отменяет контекст входящего запроса при закрытии клиентского соединения, отмене HTTP/2-запроса или возврате из `ServeHTTP`.

```go filename="_video/06-handler/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"time"
)

func checkStock(ctx context.Context, id int64) (int, error) {
	select {
	case n := <-supplier(id):
		return n, nil
	case <-ctx.Done():
		return 0, ctx.Err()
	}
}

func stockHandler(w http.ResponseWriter, r *http.Request) {
	start := time.Now()
	n, err := checkStock(r.Context(), 3)
	if err != nil {
		fmt.Println("toʻxtadi:", err, time.Since(start).Round(time.Second))
		return
	}
	fmt.Println("javob yozildi", time.Since(start).Round(time.Second))
	fmt.Fprintln(w, "qoldiq:", n)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /stock", stockHandler)
	log.Fatal(http.ListenAndServe("localhost:8093", mux))
}
```

| Этап | Контекст запроса | Handler | Горутина supplier |
|---|---|---|---|
| 0 s | активен | ждёт | спит |
| ≈1 s: curl ушёл | отменён, `Done` закрыт | вернулся с `ctx.Err()` | ещё спит |
| ≈3 s | отменён | завершён | отправляет в буфер и завершается, если сервер жив |

**Завершилось только ожидание handler.** `supplier` не принимает `ctx`; контекст не прерывает `time.Sleep`. Настоящий вызов базы или HTTP должен сам принимать контекст.

Handler может задать и собственный срок. Следующий фрагмент вставляется в handler задания:

```go
ctx, cancel := context.WithTimeout(r.Context(), 2*time.Second)
defer cancel()
```

Родитель — `r.Context()`. Дочерний контекст завершится через 2 секунды или при отмене родителя; причиной станет более раннее событие. `defer cancel()` освобождает ресурсы и при раннем возврате handler.

| Событие | Родитель: r.Context() | Потомок: WithTimeout |
|---|---|---|
| клиент ушёл через 1 s | отменён | отменён, `context.Canceled` |
| клиент ждёт, прошло 2 s | может оставаться активным | срок истёк, `context.DeadlineExceeded` |
| handler вернулся | сервер отменяет | также вызывается `defer cancel()` |

Повторное измерение: в видео обычный приём — 3s, таймаут — 1s; handler с `Background` — 3s, с `r.Context` — 1s. На этой машине также получились 3s/1s и 3s/1s. Ожидание сократилось примерно втрое: убраны 2 секунды ненужного ожидания handler. Вычисление не стало быстрее; изменилось время выхода. Из-за `Round` и нагрузки точное время меняется.

## Глубже (необязательно): буфер и утечка горутины

Сервер не завершается как CLI. После возврата handler поставщик может оставаться живым. Что будет, если убрать буфер канала результата? `07-leak` измеряет это отдельным процессом.

```go filename="_video/07-leak/supplier.go" showLineNumbers
package main

import "time"

// stocks: yetkazib beruvchidagi qoldiqlar (ID → dona): olma 1, non 2, oʻrik 3.
var stocks = map[int64]int{1: 40, 2: 120, 3: 5}

// supplierDelay: yetkazib beruvchi shuncha vaqtda javob beradi.
var supplierDelay = 3 * time.Second

// supplier qoldiqni yetkazib beruvchidan soʻraydi: javob supplierDelay'dan keyin channel'ga keladi.
func supplier(id int64) chan int {
	ch := make(chan int)
	go func() {
		time.Sleep(supplierDelay)
		ch <- stocks[id]
	}()
	return ch
}
```

Строка 13 теперь содержит `make(chan int)`: отправка ждёт получателя. Остальной код тот же.

```go filename="_video/07-leak/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"runtime"
	"time"
)

func checkStock(ctx context.Context, id int64) (int, error) {
	select {
	case n := <-supplier(id):
		return n, nil
	case <-ctx.Done():
		return 0, ctx.Err()
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), time.Second)
	defer cancel()
	_, err := checkStock(ctx, 3)
	time.Sleep(4 * time.Second)
	fmt.Println(err, "goroutine'lar:", runtime.NumGoroutine())
}
```

Строка 6 импортирует `runtime`. 20–21 создают ctx на секунду и `defer cancel()`. 22 отбрасывает результат через `_`, сохраняя ошибку. 23 ждёт ещё 4 секунды. 24 выводит число живых горутин через `runtime.NumGoroutine()`.

<summary>Ответ</summary>

**B.** `main` и supplier, застрявший на `ch <- stocks[id]`. Получатель уже вернулся. A: буфера нет; C: подсчёт выполняет `main`.

| Канал | Отправка после таймаута | Число на 5 s |
|---|---|---|
| `make(chan int)` | ждёт без получателя | 2 |
| `make(chan int, 1)` | одно значение помещается, supplier завершается | 1 |

Это исправление для supplier, который отправляет ровно один результат. Для бесконечного отправителя одного места недостаточно; сама отправка тоже должна иметь путь остановки через `ctx.Done()`.

В модели памяти Go отправка синхронизирована перед завершением соответствующего приёма. Закрытие канала синхронизировано перед приёмом, завершившимся из-за закрытия. Здесь результат передаётся через канал, а отмена — через закрытие `Done`.

## Частые ошибки

**1. `Background()` внутри handler.** Ошибочный код выше вывел `javob yozildi 3s` уже после ухода клиента. Исправление: передавайте `r.Context()` вниз; внутри `sumStock` тоже не создавайте новый фоновой контекст.

**2. Убрать буфер канала результата.** Число `2` в необязательном разделе показало supplier, оставшийся на отправке. В этом примере с одним результатом исправление — `make(chan int, 1)`.

**3. Отбросить `cancel`.** Следующей полной небольшой программы нет в папке курса. Я проверил её отдельно как `lostcancel.go`:

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, _ := context.WithTimeout(context.Background(), time.Second)
	fmt.Println(ctx.Err())
}
```

1–7 — пакет и импорты; 9–12 — `main`. Строка 10 отбрасывает `cancel` через `_`; 11 выводит `ctx.Err()`. Что скажет `go vet`? **A)** проблем нет · **B)** нужно вызвать cancel · **C)** неверный тип ctx.

<details>
<summary>Ответ</summary>

**B.** `_` позволяет пройти компиляцию, но обязанность освободить ресурсы остаётся. C: тип корректен.

</details>

```console
$ go vet lostcancel.go
lostcancel.go:10:7: the cancel function returned by context.WithTimeout should be called, not discarded, to avoid a context leak
```

`lostcancel.go:10:7` — файл, строка 10, столбец 7. Смысл сообщения: «вызовите cancel, возвращённую WithTimeout, а не отбрасывайте её, чтобы не оставлять ресурсы контекста». Исправление: замените `_` на `cancel`, следующей строкой добавьте `defer cancel()`.

**4. Считать, что `cancel()` принудительно завершает любую работу.** Supplier не принимает контекст и продолжает спать. Даже код, получивший контекст, должен проверять сигнал или вызывать API с его поддержкой.

**5. Считать, что cancel всегда важнее результата.** Если оба `case` готовы, `select` выбирает случайно. Даже с заранее отменённым ctx вызов `supplier(id)` вычисляется до выбора и запускает горутину. Это упрощение лаборатории: передавайте ctx настоящему внешнему вызову.

**6. Управлять `go run . &` через `kill %1`.** Процесс сборки может остановиться, а дочерний сервер остаться. Как выше, соберите binary, запустите `./bozor &` и остановите именно эту работу.

```go filename="solution/main.go" showLineNumbers
// bozor: yetkazib beruvchidan qoldiq soʻrash, select va context bilan vaqtida toʻxtatish (GB-7.03).
// Javob (solution): sumStock va reportHandler yozilgan.
package main

import (
	"context"
	"errors"
	"fmt"
	"log"
	"net/http"
	"time"
)

// checkStock yetkazib beruvchining javobini yoki ctx bekor qilinishini kutadi: qaysi biri oldin boʻlsa.
func checkStock(ctx context.Context, id int64) (int, error) {
	select {
	case n := <-supplier(id):
		return n, nil
	case <-ctx.Done():
		return 0, ctx.Err()
	}
}

// GET /stock: oʻrikning (ID 3) qoldigʻi. Mijoz ketsa, r.Context() bekor qilinadi va ish toʻxtaydi.
func stockHandler(w http.ResponseWriter, r *http.Request) {
	start := time.Now()
	n, err := checkStock(r.Context(), 3)
	if err != nil {
		fmt.Println("toʻxtadi:", err, time.Since(start).Round(time.Second))
		return
	}
	fmt.Println("javob yozildi", time.Since(start).Round(time.Second))
	fmt.Fprintln(w, "qoldiq:", n)
}

// reportIDs: hisobotdagi mahsulotlar; reportTimeout: GET /report shuncha vaqtdan koʻp kutmaydi.
var (
	reportIDs     = []int64{1, 2, 3}
	reportTimeout = 5 * time.Second
)

// sumStock ids'dagi har mahsulot qoldigʻini checkStock bilan ketma-ket soʻrab, yigʻindisini qaytaradi.
// ctx bekor qilinsa yoki muddati tugasa, darhol 0 va ctx'ning xatosini qaytaradi.
func sumStock(ctx context.Context, ids []int64) (int, error) {
	total := 0
	for _, id := range ids {
		n, err := checkStock(ctx, id)
		if err != nil {
			return 0, err
		}
		total += n
	}
	return total, nil
}

// GET /report: reportIDs qoldiqlarining yigʻindisi, "jami: N".
func reportHandler(w http.ResponseWriter, r *http.Request) {
	ctx, cancel := context.WithTimeout(r.Context(), reportTimeout)
	defer cancel()
	total, err := sumStock(ctx, reportIDs)
	if errors.Is(err, context.DeadlineExceeded) {
		http.Error(w, "yetkazib beruvchi javob bermadi", http.StatusGatewayTimeout)
		return
	}
	if err != nil {
		return // mijoz ketdi (context.Canceled): javob yozishning ma'nosi yoʻq
	}
	fmt.Fprintln(w, "jami:", total)
}

func newMux() *http.ServeMux {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /stock", stockHandler)
	mux.HandleFunc("GET /report", reportHandler)
	return mux
}

func main() {
	log.Fatal(http.ListenAndServe("localhost:8093", newMux()))
}
```

44–54: `total` начинается с нуля; `for _, id := range ids` отбрасывает индекс, каждому ID передаётся тот же ctx. При ошибке возвращается `0, err`, а не частичная сумма; в конце — `total, nil`.

57–69: из запроса получается дочерний ctx со сроком, cancel откладывается. `DeadlineExceeded` отдельно преобразуется в 504; при других ошибках ответ не записывается. При успехе записывается сумма. 14–34 — прежние `checkStock` и `stockHandler`. В 36–40 `reportIDs` — `[]int64{1, 2, 3}`, `reportTimeout` — 5 секунд. В 71–80 `newMux()` возвращает mux с двумя route; `main` запускает сервер. 1–12 — комментарии, пакет и знакомые импорты.

Пройдут ли тесты решения? **A)** да · **B)** все запросы получат 504 · **C)** после ухода клиента всё равно ждём 9 секунд.

Обе команды ничего не вывели. `gofmt -l` перечисляет неотформатированные файлы; `go vet ./...` проверяет пакеты и вложенные пакеты. Go пропускает `_video`; его этапы запускались выше отдельно.

</details>

Дополнительно, без проверки: запросите `/report` у сервера решения. Три товара последовательно требуют 3 × 3 = 9 секунд, а `reportTimeout` — 5 секунд. Поэтому ожидается 504. Эти 9 секунд — арифметический расчёт; отдельное измерение curl для этой страницы не выполнялось.
