## What you will learn

Users are joining bozor with an email and a password. If a copy of the `users` table leaks one day, how quickly will an attacker find the passwords?

**One idea:** a password goes into the database as a string you can check but cannot reverse, and every guess against it is expensive. Argon2id fills 19 MiB of memory on every computation and makes two passes over it. Each user gets a new random salt. The result is one string that holds everything needed to verify. The attacker can only guess too, and each guess costs them a lot.

By the end of this lesson you will:

- measure an offline attack on a leaked table on your own machine: against a fast hash and against argon2id;
- write `Hash` and `Verify` in the `internal/password` package: random salt, argon2id, one string;
- see `Verify` read the salt and parameters from the stored string and compare the keys in constant time;
- add `POST /users` (registration) to bozor: the database receives only the argon2id string.

| Word | Plain meaning | English term |
|---|---|---|
| offline attack | the attacker opens a copy of the table on their own computer and tests password guesses; the server notices nothing | offline attack |
| argon2id and salt | a password hash that makes every computation deliberately expensive; salt is new random bytes for each user | argon2id, salt |
| constant-time comparison | comparing two byte strings so that the time does not depend on how many bytes match | constant-time comparison |

The other terms (OWASP, PHC string, `fmt.Sscanf`) get one sentence where they first appear.

## The leaked table: plain password and fast hash

The `sizdi/` folder (Uzbek for "leaked") holds one `users` table in three forms. The emails and passwords are made up; the `.test` domain is reserved for testing only ([RFC 2606](https://www.rfc-editor.org/rfc/rfc2606#section-2)). The first form: the password itself.

```console
$ cat sizdi/ochiq.txt
dilnoza@bozor.test choy2024
jasur@bozor.test choy2024
malika@bozor.test tarvuz-osmon-qalam-ariq-27
```

`cat` prints the file to the terminal. Each line has the email and the password itself: the attacker has nothing left to do.

The second form: the password is hashed with sha256. A **hash** is a function that computes a fixed-length byte string from text. SHA-256 is one-way: you cannot compute the password back from the result. Storing passwords with sha256 does happen in practice, and OWASP warns against it. **OWASP** is an open project about web security; its Password Storage Cheat Sheet collects the rules for storing passwords.

```console
$ cat sizdi/sha256.txt
dilnoza@bozor.test 385426486641a520e865c4e6b24d379c8f8afa1eb5de2f932ba90f0622f06289
jasur@bozor.test 385426486641a520e865c4e6b24d379c8f8afa1eb5de2f932ba90f0622f06289
malika@bozor.test f8fe182b2bef6749451694c3042b04e5cd5f5aa6aeecbfb0c2744dfbac6549a5
```

Each line has a 64-character hex string: 32 bytes, two hex characters per byte ([GB-2.10](/lab/youtube/gb/gb-2-10/en)). Compare two lines:

| User | Hash | What we see |
|---|---|---|
| dilnoza | `38542648…f06289` | — |
| jasur | `38542648…f06289` | the same as dilnoza: so the password is the same |
| malika | `f8fe182b…6549a5` | different: a different password |

Looking at the table, the attacker learns that two people share a password. Find one password and both open. The reason: no **salt** was added to the password. A salt is new random bytes for each user; it is added to the password before hashing. Without a salt, the same password always gives the same hash.

## Offline attack: millions of guesses per second against sha256

The attacker does not reverse the hash. They **guess**: they take each candidate from a list of popular passwords, hash it the same way and compare it with the hash from the table.

```text
candidate ("olma")  →  sha256(candidate)  →  same as the hash in the table?
                                               ├─ yes: password found
                                               └─ no:  next candidate
```

This is an **offline attack**: the copy of the table sits on the attacker's computer and the server knows nothing about it. Only the attacker's computer limits the speed.

The `cmd/taxmin` program in the folder (`taxmin` means "guess") measures exactly this. `nomzodlar.txt` ("candidates") has 1000 made-up candidates (not a real leaked list). For a sha256 line the program computes sha256; for an argon2id line it calls bozor's own `password.Verify`, which we meet later. The program's code is in the folder as `cmd/taxmin/main.go`; read it after the lesson.

Guess: how many candidates per second does one processor core check with sha256?

**A)** ~100,000 · **B)** ~1,000,000 · **C)** ~10,000,000

<details>
<summary>Answer</summary>

**C.** The measurement in the video: 8,229,029 guesses per second, so one hash takes ≈ 0.12 microseconds (1,000,000 ÷ 8,229,029). If you chose A or B, you estimated a hash in milliseconds: sha256 is fast on purpose, and computing over 32 bytes is very cheap.

</details>

Run the program against the sha256 table. Dilnoza's and Jasur's password is `choy2024`; Malika's is a long phrase:

## argon2id: a hash where every computation is expensive

For a password, every hash computation must be expensive on purpose. **Argon2id** fills a given amount of memory, for example 19 mebibytes, and makes several passes over it. The output is a 32-byte key. (A **kibibyte** KiB is 1024 bytes, a **mebibyte** MiB is 1024 KiB.) Argon2 won the Password Hashing Competition in 2015; OWASP recommends argon2id first for storing passwords.

```text
password + salt  →  19 MiB of memory is filled  →  several passes over the memory  →  32-byte key (this goes to the database)
```

Argon2id is tuned with three parameters:

| Parameter | Meaning | Ours |
|---|---|---|
| `m` | memory, in kibibytes | 19456 (19 MiB) |
| `t` | number of passes over the memory | 2 |
| `p` | number of parallel lanes | 1 |

The OWASP table gives five minimum settings. They give the same level of defense: less memory means more passes.

| `m` | `t` | `p` |
|---|---|---|
| 47104 (46 MiB) | 1 | 1 |
| **19456 (19 MiB)** | **2** | **1** |
| 12288 (12 MiB) | 3 | 1 |
| 9216 (9 MiB) | 4 | 1 |
| 7168 (7 MiB) | 5 | 1 |

We take the second row. These are **minimum** values: OWASP advises tuning them by measuring on the production server.

The salt is new random bytes for each user. It is not a secret: its job is to stop the attacker from sharing work between users.

Argon2 is not in the standard library: it is in the Go team's `golang.org/x/crypto` module ([GB-2.06](/lab/youtube/gb/gb-2-06/en)). In an empty project you add the module with `go get`:

```console
$ go get golang.org/x/crypto/argon2
go: downloading golang.org/x/crypto v0.59.0
go: downloading golang.org/x/sys v0.50.0
go: added golang.org/x/crypto v0.59.0
go: added golang.org/x/sys v0.50.0
```

`go get` downloads the module and records it in `go.mod`. The second module, `golang.org/x/sys`, is needed by `x/crypto`: it depends on it. In the lesson folder this is already done (`go.mod`, `go.sum`), so you do not have to run the command. The output above was taken in a copy of the GB-6.02 solution with an empty module cache, which is why the `downloading` lines appear.

## Hash: salt, argon2id and one string

A new package, `internal/password`. At the top of the file the parameters sit in a `const` block:

```go
const (
	memory  = 19 * 1024 // m: xotira, KiB
	passes  = 2         // t: xotira ustidan necha marta oʻtiladi
	threads = 1         // p: parallel yoʻlaklar soni
	keyLen  = 32        // hosil boʻladigan kalit, bayt
	saltLen = 16        // salt, bayt
)
```

| Line | Code | What it does |
|---|---|---|
| 1 | `const (` | start of the constant block ([GB-2.03](/lab/youtube/gb/gb-2-03/en)) |
| 2 | `memory  = 19 * 1024` | `m`: 19 times 1024 = 19456 KiB = 19 MiB. `*` is multiplication, `//` starts a comment |
| 3 | `passes  = 2` | `t`: how many passes over the memory |
| 4 | `threads = 1` | `p`: number of parallel lanes |
| 5 | `keyLen  = 32` | length of the resulting key, in bytes |
| 6 | `saltLen = 16` | salt length, in bytes |

Now the start of the `Hash` function:

```go
func Hash(pw string) string {
	salt := make([]byte, saltLen)
	rand.Read(salt) // Go 1.24'dan beri xato qaytarmaydi
	key := argon2.IDKey([]byte(pw), salt, passes, memory, threads, keyLen)
```

| Line | Code | What it does |
|---|---|---|
| 1 | `func Hash(pw string) string {` | `pw` is the password; the function returns a string ([GB-1.07](/lab/youtube/gb/gb-1-07/en)) |
| 2 | `salt := make([]byte, saltLen)` | creates a 16-byte slice ([GB-2.01](/lab/youtube/gb/gb-2-01/en)) |
| 3 | `rand.Read(salt)` | the `crypto/rand` package ([GB-6.01](/lab/youtube/gb/gb-6-01/en)) fills the slice with **cryptographically** random bytes, that is, bytes that cannot be predicted. Since Go 1.24, `Read` does not return an error |
| 4 | `key := argon2.IDKey(…)` | creates a 32-byte `key` from the password bytes, the salt, `passes`, `memory`, `threads` and the key length |

What is left is putting the result into a string. The complete `Hash`:

```go
var b64 = base64.RawStdEncoding

// Hash parolni argon2id bilan hash qiladi va bazaga yoziladigan satrni qaytaradi:
//
//	$argon2id$v=19$m=19456,t=2,p=1$<salt>$<kalit>
//
// Har chaqiruvda yangi tasodifiy salt: bir xil parol ham har safar boshqa satr beradi.
func Hash(pw string) string {
	salt := make([]byte, saltLen)
	rand.Read(salt) // Go 1.24'dan beri xato qaytarmaydi
	key := argon2.IDKey([]byte(pw), salt, passes, memory, threads, keyLen)
	return fmt.Sprintf("$argon2id$v=%d$m=%d,t=%d,p=%d$%s$%s", argon2.Version,
		memory, passes, threads, b64.EncodeToString(salt), b64.EncodeToString(key))
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `var b64 = base64.RawStdEncoding` | a way to write bytes as text (explained below); used in two places: when writing and when reading |
| 3–7 | comment | the shape of the string: `$argon2id$v=19$m=…,t=…,p=…$salt$key` |
| 12 | `return fmt.Sprintf(…)` | [GB-1.04](/lab/youtube/gb/gb-1-04/en): the values replace `%d` and `%s` in the template |
| 12–13 | `argon2.Version`, `memory, passes, threads` | the version (19), then `m`, `t`, `p` |
| 13 | `b64.EncodeToString(salt)`, `b64.EncodeToString(key)` | writes the salt and key bytes as text |

**Base64** turns every 3 bytes into 4 characters. A 16-byte salt becomes 22 characters, a 32-byte key becomes 43. `RawStdEncoding` does not add the `=` padding at the end; `StdEncoding` does. The difference matters below, in "Common mistakes".

The result is a **PHC string**: a format agreed in the Password Hashing Competition, with parts separated by `$`. Let us split one string:

```text
$argon2id$v=19$m=19456,t=2,p=1$fd+QrkyR3ap9uAJkzw4Ocw$1tRXqM9ibZAPh1bCRLKEoQtHxfvyHk/HuicsoJA/CsQ
```

| Part | Value | Meaning |
|---|---|---|
| 0 | (empty) | the string starts with `$`, so the first part is empty |
| 1 | `argon2id` | the algorithm |
| 2 | `v=19` | the version (`argon2.Version` = 0x13 = 19) |
| 3 | `m=19456,t=2,p=1` | the parameters |
| 4 | `fd+QrkyR3ap9uAJkzw4Ocw` | the salt, 22 characters |
| 5 | `1tRXqM9ibZAPh1bCRLKEoQtHxfvyHk/HuicsoJA/CsQ` | the key, 43 characters |

This string has everything needed to verify: the algorithm, the parameters and the salt. That is why the database stores only this string.

First, predict. `sizdi/argon2id.txt` was made by this very `Hash`. Dilnoza and Jasur have the same password (`choy2024`). Which part of the two lines is the same?

**A)** no part · **B)** the salt · **C)** the start: algorithm and parameters

<details>
<summary>Answer</summary>

**C.** `$argon2id$v=19$m=19456,t=2,p=1$` is built from constants, so it is the same on every line. B is wrong: the salt is new and random on every call. A is wrong too: the start is the same. The key is computed together with the salt, so it is completely different.

</details>

```console
$ cat sizdi/argon2id.txt
dilnoza@bozor.test $argon2id$v=19$m=19456,t=2,p=1$fd+QrkyR3ap9uAJkzw4Ocw$1tRXqM9ibZAPh1bCRLKEoQtHxfvyHk/HuicsoJA/CsQ
jasur@bozor.test $argon2id$v=19$m=19456,t=2,p=1$rUPhzHtvN8st9ZvrLtD39A$QDmgSweLTZ3B4crIK4E1dj13e/GF9VEcFyNE49sErHY
malika@bozor.test $argon2id$v=19$m=19456,t=2,p=1$GX6RH2ZGTsRb4K5+L5A5Ew$nsERR+E5HtqLtBfmTmTOsYGRpK9blc8HIdMX/k2/SRY
```

The start is the same: algorithm, version, parameters. The salt differs, and the key is completely different too. Now you cannot tell equal passwords from the table.

## Verify: parameters from the string, comparison in constant time

At login, that is, when the user signs in, the server hashes the password again with the salt **from the stored string** and compares the result with the stored key.

```go
var ErrBadHash = errors.New("hash satri notoʻgʻri")

// Verify parol saqlangan satrga mos kelishini tekshiradi. Parametrlar va salt satrdan olinadi,
// kalit qaytadan hisoblanadi va saqlangani bilan doimiy vaqtda solishtiriladi.
// Parol notoʻgʻri boʻlsa — false, nil; satrning oʻzi buzuq boʻlsa — xato (ErrBadHash).
func Verify(pw, encoded string) (bool, error) {
	p, err := decode(encoded)
	if err != nil {
		return false, err
	}
	key := argon2.IDKey([]byte(pw), p.salt, p.passes, p.memory, p.threads, uint32(len(p.key)))
	return subtle.ConstantTimeCompare(key, p.key) == 1, nil
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `var ErrBadHash = errors.New(…)` | a sentinel error for a malformed string ([GB-2.08](/lab/youtube/gb/gb-2-08/en)) |
| 3 | `func Verify(pw, encoded string) (bool, error)` | `pw` and `encoded` are both `string`: the type is written once. The results: did it match, and an error |
| 4 | `p, err := decode(encoded)` | gets `params` from the string; `decode` is below |
| 5–7 | `if err != nil { return false, err }` | if the string is malformed, `false` and the error |
| 8 | `key := argon2.IDKey(…)` | computes the key again with the salt and parameters **from the string**. `len` returns an `int`, but `IDKey` expects a non-negative `uint32`, so `uint32(len(p.key))` |
| 9 | `subtle.ConstantTimeCompare(key, p.key) == 1` | returns `1` when the keys are equal, and `== 1` gives `true` |

The result of `decode` is a `params` struct:

```go
type params struct {
	memory, passes uint32
	threads        uint8
	salt, key      []byte
}
```

| Line | Code | What it does |
|---|---|---|
| 2 | `memory, passes uint32` | two numbers; fields of the same type go on one line, separated by a comma |
| 3 | `threads uint8` | one byte: this is the type `IDKey` expects |
| 4 | `salt, key []byte` | the salt and key bytes |

`decode` splits the string into parts:

```go
func decode(encoded string) (params, error) {
	var p params
	parts := strings.Split(encoded, "$")
	if len(parts) != 6 || parts[1] != "argon2id" || parts[2] != "v=19" {
		return p, ErrBadHash
	}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `func decode(encoded string) (params, error)` | takes the string, returns `params` and an error |
| 2 | `var p params` | `p` is a variable of this type, its fields at their zero values |
| 3 | `strings.Split(encoded, "$")` | splits the string on `$` into 6 parts; the first is empty. The result is `parts` |
| 4–6 | `if len(parts) != 6 \|\| …` | if the number of parts, the algorithm or the version is different, `ErrBadHash` is returned |

Next: the parameters, the salt and the key.

```go
	_, err := fmt.Sscanf(parts[3], "m=%d,t=%d,p=%d", &p.memory, &p.passes, &p.threads)
	if err != nil || p.passes < 1 || p.threads < 1 {
		return p, fmt.Errorf("%w: parametrlar %q", ErrBadHash, parts[3])
	}
	if p.salt, err = b64.DecodeString(parts[4]); err != nil {
		return p, fmt.Errorf("%w: salt: %w", ErrBadHash, err)
	}
	if p.key, err = b64.DecodeString(parts[5]); err != nil {
		return p, fmt.Errorf("%w: kalit: %w", ErrBadHash, err)
	}
	if len(p.key) < 16 { // boʻsh kalit har qanday parolga «mos» kelardi
		return p, fmt.Errorf("%w: kalit %d bayt", ErrBadHash, len(p.key))
	}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `fmt.Sscanf(parts[3], "m=%d,t=%d,p=%d", …)` | the reverse of `Sprintf`: reads by a template and writes the numbers into the fields through pointers (`&p.memory`, [GB-2.04](/lab/youtube/gb/gb-2-04/en)). `_` is the number of fields read, which we do not need |
| 2–4 | `if err != nil \|\| p.passes < 1 \|\| p.threads < 1` | if `t` or `p` is zero, `IDKey` would panic; we wrap that in `ErrBadHash` (`%w`) |
| 5–7 | `b64.DecodeString(parts[4])` | turns the salt text back into bytes; on error `ErrBadHash` wraps it |
| 8–10 | `b64.DecodeString(parts[5])` | the same for the key |
| 11–13 | `if len(p.key) < 16` | a short key is also an error. `Verify` takes the key length from the stored key (`uint32(len(p.key))`): with an empty key, `IDKey` would also compute an empty key, the two empty strings would be equal, and any password would "match" |

At the end `p` and `nil` are returned. There is one more check that the video does not show; it is in "Going deeper". `NeedsRehash` still always returns `false`: you write it in the homework.

```go filename="internal/password/password.go" showLineNumbers
// Package password — parollarni argon2id bilan saqlash va tekshirish (GB-6.03).
//
// Bazaga parolning oʻzi ham, tez hash'i (sha256) ham yozilmaydi: faqat Hash qaytargan satr.
// Satrda hamma narsa bor: algoritm, versiya, parametrlar, salt va hosil boʻlgan kalit —
// shuning uchun Verify parametrlarni satrdan oʻqiydi va parametrlar keyin oʻzgarsa ham eski satrlar tekshiriladi.
package password

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/base64"
	"errors"
	"fmt"
	"strings"

	"golang.org/x/crypto/argon2"
)

// argon2id parametrlari — OWASP Password Storage Cheat Sheet'ning minimal sozlamasi:
// m=19456 KiB (19 MiB), t=2, p=1. Bitta Hash shu kompyuterda ≈ 20 ms va 19 MiB xotira oladi.
const (
	memory  = 19 * 1024 // m: xotira, KiB
	passes  = 2         // t: xotira ustidan necha marta oʻtiladi
	threads = 1         // p: parallel yoʻlaklar soni
	keyLen  = 32        // hosil boʻladigan kalit, bayt
	saltLen = 16        // salt, bayt
)

// b64 — PHC satr formatidagi base64: standart alifbo, oxirida «=» toʻldiruvchisiz.
var b64 = base64.RawStdEncoding

// Hash parolni argon2id bilan hash qiladi va bazaga yoziladigan satrni qaytaradi:
//
//	$argon2id$v=19$m=19456,t=2,p=1$<salt>$<kalit>
//
// Har chaqiruvda yangi tasodifiy salt: bir xil parol ham har safar boshqa satr beradi.
func Hash(pw string) string {
	salt := make([]byte, saltLen)
	rand.Read(salt) // Go 1.24'dan beri xato qaytarmaydi
	key := argon2.IDKey([]byte(pw), salt, passes, memory, threads, keyLen)
	return fmt.Sprintf("$argon2id$v=%d$m=%d,t=%d,p=%d$%s$%s", argon2.Version,
		memory, passes, threads, b64.EncodeToString(salt), b64.EncodeToString(key))
}

// ErrBadHash — saqlangan satr argon2id formatida emas (buzilgan yoki boshqa algoritm).
var ErrBadHash = errors.New("hash satri notoʻgʻri")

// Verify parol saqlangan satrga mos kelishini tekshiradi. Parametrlar va salt satrdan olinadi,
// kalit qaytadan hisoblanadi va saqlangani bilan doimiy vaqtda solishtiriladi.
// Parol notoʻgʻri boʻlsa — false, nil; satrning oʻzi buzuq boʻlsa — xato (ErrBadHash).
func Verify(pw, encoded string) (bool, error) {
	p, err := decode(encoded)
	if err != nil {
		return false, err
	}
	key := argon2.IDKey([]byte(pw), p.salt, p.passes, p.memory, p.threads, uint32(len(p.key)))
	return subtle.ConstantTimeCompare(key, p.key) == 1, nil
}

// NeedsRehash — saqlangan satr hozirgi parametrlardan boshqasi bilan yasalganmi.
// Login paytida parol toʻgʻri chiqsa va bu true boʻlsa, parolni qaytadan Hash qilib saqlash kerak.
func NeedsRehash(encoded string) (bool, error) {

	// kalit uzunligi hozirgi konstantalardan farq qilsa true qaytaring.
	return false, nil
}

// Satrdan oʻqiladigan parametrlarning yuqori chegarasi (OWASP jadvalining eng katta qatoridan ancha yuqori).
const (
	maxMemory = 256 * 1024 // KiB: 256 MiB
	maxPasses = 16
)

// params — satrdan oʻqilgan qismlar.
type params struct {
	memory, passes uint32
	threads        uint8
	salt, key      []byte
}

// decode satrni «$» boʻyicha olti qismga ajratadi: "", "argon2id", "v=19", "m=…,t=…,p=…", salt, kalit.
func decode(encoded string) (params, error) {
	var p params
	parts := strings.Split(encoded, "$")
	if len(parts) != 6 || parts[1] != "argon2id" || parts[2] != "v=19" {
		return p, ErrBadHash
	}
	_, err := fmt.Sscanf(parts[3], "m=%d,t=%d,p=%d", &p.memory, &p.passes, &p.threads)
	if err != nil || p.passes < 1 || p.threads < 1 {
		return p, fmt.Errorf("%w: parametrlar %q", ErrBadHash, parts[3])
	}
	if p.salt, err = b64.DecodeString(parts[4]); err != nil {
		return p, fmt.Errorf("%w: salt: %w", ErrBadHash, err)
	}
	if p.key, err = b64.DecodeString(parts[5]); err != nil {
		return p, fmt.Errorf("%w: kalit: %w", ErrBadHash, err)
	}
	if len(p.key) < 16 { // boʻsh kalit har qanday parolga «mos» kelardi
		return p, fmt.Errorf("%w: kalit %d bayt", ErrBadHash, len(p.key))
	}
	// Parametrlar qatorida ortiqcha belgi yoʻq ("p=1abc") va qiymatlar chegarada: buzilgan satrdagi
	// m=4294967295 jarayonni «out of memory» bilan oʻldirardi (buni recover ham ushlay olmaydi).
	if fmt.Sprintf("m=%d,t=%d,p=%d", p.memory, p.passes, p.threads) != parts[3] ||
		p.memory > maxMemory || p.passes > maxPasses {
		return p, fmt.Errorf("%w: parametrlar %q", ErrBadHash, parts[3])
	}
	return p, nil
}
```

### Why constant time

An ordinary comparison stops at the first byte that differs. The response time reveals how many bytes matched. `subtle.ConstantTimeCompare` looks at every byte: the time does not depend on the content ([crypto/subtle](https://pkg.go.dev/crypto/subtle#ConstantTimeCompare)).

| Comparison | When it stops | What the time reveals |
|---|---|---|
| ordinary | at the first differing byte | how many bytes matched |
| `ConstantTimeCompare` | after looking at all bytes | not the content (only the length) |

In `Verify` this is an extra precaution: the key is computed from the attacker's own password. Where a secret is compared directly, it is required: that place is the session tokens of the next lesson ([GB-6.04](/lab/youtube/gb/gb-6-04/en)).

## The same attack on argon2id strings

Now the attacker has the `argon2id.txt` file. For each candidate they call our `Verify`. Will `choy2024` be found?

**A)** no: it cannot be broken · **B)** yes, but much slower · **C)** yes, as fast as sha256

<details>
<summary>Answer</summary>

**B.** Argon2id does not make a password unbreakable: if the candidate is in the list it is found, because `Verify` answers `true` for the right password and that is exactly what the attacker waits for (A is wrong). Argon2id makes every guess expensive, so C is wrong too.

</details>

The absolute speed depends on the computer and how busy it is: mine was busy, so argon2id is slower. Two things do not change: every guess takes 19.0 MiB, and the gap is more than a hundred thousand times. Here is that gap (the video's measurement, on a logarithmic axis; each block is one power of ten, approximate):

```text
guesses per second, one core (log10 axis)
sha256    ███████  8,229,029
argon2id  ██       51
```

One billion candidates on one core, **for one user**:

| | Video's measurement | My run |
|---|---|---|
| sha256 | 1,000,000,000 ÷ 8,229,029 ≈ 122 s ≈ 2 minutes | ≈ 137 s (output above: 7,279,728/s) |
| argon2id | 1,000,000,000 ÷ 51 ≈ 19.6 million s ≈ 227 days | ≈ 445 days (output above: 26/s) |

Every salt is different, so three users mean three times the work: each is computed separately.

**Why the memory cost matters.** The attacker guesses on a graphics card, on thousands of cores at once. Sha256 needs no memory, so all the cores work. Each argon2id guess takes 19 MiB: a card with 24 GiB of memory holds no more than 24,576 ÷ 19 ≈ 1293 guesses at once. This is arithmetic, not a benchmark: the card's memory is needed for other things too, so the real number is lower. [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106#section-1) calls argon2 a *memory-hard* function, built for this: to raise the cost of password guessing on special hardware (GPU, ASIC).

One more thing: `choy2024` was found anyway. Argon2id only slowed it down: the guess rate fell about 160,000 times (the video's measurement), but it did not protect the password. That is why a password length rule is needed too. It is in the next section.

## Registration: POST /users

Registration goes in order: read the request, validate, hash the password, store, respond **without** the hash. Users are in memory for now, in `store.Users`; in Postgres the same string will go into the `password_hash` column of the `users` table, and the code will not change.

The request body:

```go
type userInput struct {
	Email    string `json:"email"`
	Password string `json:"password"`
}
```

`in` is the body that was read (in the next code). The length rule:

```go
const (
	minPassword = 15
	maxPassword = 64
)
```

By OWASP and the US standards institute NIST (SP 800-63B): without a second factor a password is at least 15 characters. The upper limit must be **at least** 64; bozor takes exactly 64. There are no composition rules ("one capital letter…"): NIST does not recommend them.

```go
func validateUser(in userInput) fieldErrors {
	f := fieldErrors{}
	if !strings.Contains(in.Email, "@") {
		f["email"] = "email manzil boʻlsin"
	}
	if n := utf8.RuneCountInString(in.Password); n < minPassword || n > maxPassword {
		f["password"] = fmt.Sprintf("%d–%d belgi boʻlsin", minPassword, maxPassword)
	}
	return f
}
```

| 1 | `func validateUser(in userInput) fieldErrors` | `in` is the body that was read; the result is the field errors ([GB-6.02](/lab/youtube/gb/gb-6-02/en)) |
| 2 | `f := fieldErrors{}` | an empty `f`: field name → message |

## Going deeper (optional): checks the video does not show, and production notes

**A malformed string must not kill the server.** At the end of `decode` there is a check that is not in the video. Here are the relevant parts:

```go
// Satrdan oʻqiladigan parametrlarning yuqori chegarasi (OWASP jadvalining eng katta qatoridan ancha yuqori).
const (
	maxMemory = 256 * 1024 // KiB: 256 MiB
	maxPasses = 16
)
```

```go
	// Parametrlar qatorida ortiqcha belgi yoʻq ("p=1abc") va qiymatlar chegarada: buzilgan satrdagi
	// m=4294967295 jarayonni «out of memory» bilan oʻldirardi (buni recover ham ushlay olmaydi).
	if fmt.Sprintf("m=%d,t=%d,p=%d", p.memory, p.passes, p.threads) != parts[3] ||
		p.memory > maxMemory || p.passes > maxPasses {
		return p, fmt.Errorf("%w: parametrlar %q", ErrBadHash, parts[3])
	}
	return p, nil
```

The first reason: `m=4294967295` in a string kills the process with `fatal error: out of memory`, and `recover` cannot catch it. That is why `m` is at most 256 MiB and `t` at most 16. The second reason: `Sscanf` accepts extra characters such as `p=1abc`; rebuilding the text with `Sprintf` and comparing rejects them. `TestVerifyBadHash` in `internal/password/password_test.go` checks this (`m juda katta`, `t juda katta`, `ortiqcha belgi`).

**In production** (notes from the [README](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/gb-6-03-parollar#readme)):

- Measure the parameters on your own server: the OWASP table gives minimums; one `Hash` here takes ≈ 20–45 ms, depending on load.
- The Unicode form of a password is not normalized (NFC/NFKC): two forms that look the same give different hashes. bozor does not do this yet.
- The 409 response tells who is registered. The full fix is a confirmation message sent by email; bozor makes do with a plain 409 for now.
- Every `POST /users` takes ~20 ms of CPU and 19 MiB of memory: registration and login need a rate limit ([GB-6.07](/lab/youtube/gb/gb-6-07/en)).
- The password itself must never be written to the log. A JSON syntax error from `decodeJSON` can quote one character of the body, so a malformed character in the password field can reach the log.

## Common mistakes

**1. "A hash is one-way, so the password is safe."** No. A one-way function does not recover the password from the result, but the attacker does not recover it, they guess: above, sha256 gave 8 million guesses per second, and `choy2024` was found in microseconds. The rule: for a password use not a fast hash but argon2id, a new salt for every user and a length rule (the "Offline attack" section above).

**2. `RawStdEncoding` when writing, `StdEncoding` when reading.** `Hash` writes the salt without `=`, and `decode` reads it with `StdEncoding`:

```go
	if p.salt, err = base64.StdEncoding.DecodeString(parts[4]); err != nil {
		return p, fmt.Errorf("%w: salt: %w", ErrBadHash, err)
	}
```

Guess: what does `Verify` return with the right password in this copy?

**A)** `true`, `nil` · **B)** `false`, `nil` · **C)** `false` and `ErrBadHash`

<details>
<summary>Answer</summary>

**C.** The salt text is not valid for `StdEncoding`: it expects the `=` padding, `decode` returns an error wrapped in `ErrBadHash`, and `Verify` gives `false` and that error. Even the right password does not pass.

</details>

How to read it: `--- FAIL: TestVerify` is the test; `password_test.go:39` is the file and line; then the message (`toʻgʻri parol` means "correct password"). `hash satri notoʻgʻri: salt: illegal base64 data at input byte 20` is the text of `ErrBadHash` ("the hash string is wrong"), then `: salt: ` and the base64 error (`illegal base64 data at input byte 20`). `kutilgan true, nil` says what the test expected. Other tests failed too because they also call `decode`; in the video the extra lines are shortened to `…`.

The cause: a 16-byte salt is 22 characters. `StdEncoding` reads blocks of 4 characters: 20 characters are 5 full blocks, and the remaining 2 characters are not a full block, they need `==`. The fix: one `b64` (`RawStdEncoding`) for both writing and reading, as in the lesson code.

**3. `Verify` takes the parameters from the constants.** This mistake is silent: after the constants change, `IDKey` computes the key with the stored salt under different parameters, and no existing user can sign in (`false`). The rule: the parameters come from the string (the mid-lesson question above). A new `Hash` builds its string from the constants; changing them does not touch old strings. `TestVazifaOldStillVerifies` checks this.

## Check yourself

**1.** Why is sha256 not suitable for storing passwords?

<details>
<summary>Answer</summary>

It is too fast: millions of guesses per second on one core (8,229,029 on this machine) with almost no memory. Without a salt, the same password gives the same hash.

</details>

**2.** How does a salt get in the attacker's way?

<details>
<summary>Answer</summary>

The same password gives a different string for each user, so you cannot tell equal passwords from the table. Each user is guessed separately: work done on one candidate does not help with another user.

</details>

**3.** ([GB-5.10](/lab/youtube/gb/gb-5-10/en)) Why does each integration test run in its own schema?

<details>
<summary>Answer</summary>

`go test` runs packages in parallel. In a shared schema, tests break each other's tables; a separate schema makes each test independent.

</details>

**4.** What does `Verify("x", "$argon2id$v=19$m=19456,t=0,p=1$" + salt + "$" + key)` return (the salt and key are valid base64 of enough length)?

<details>
<summary>Answer</summary>

`false` and an error wrapped in `ErrBadHash`. `decode` rejects `t < 1` before `IDKey`, because `IDKey` panics when `t` or `p` is zero. This case is in `TestVerifyBadHash` under the name `t=0`.

</details>

```go
const (
	memory  = 46 * 1024 // m: xotira, KiB
	passes  = 1         // t: xotira ustidan necha marta oʻtiladi
	threads = 1         // p: parallel yoʻlaklar soni
	keyLen  = 32        // hosil boʻladigan kalit, bayt
	saltLen = 16        // salt, bayt
)
```

```go
func NeedsRehash(encoded string) (bool, error) {
	p, err := decode(encoded)
	if err != nil {
		return false, err
	}
	return p.memory != memory || p.passes != passes || p.threads != threads || len(p.key) != keyLen, nil
}
```

`decode` reads the string and, on an error, returns it unchanged: it wraps `ErrBadHash`, so `errors.Is(err, ErrBadHash)` works. Then one expression with `||` checks four differences: `p.memory != memory`, `p.passes != passes`, `p.threads != threads`, `len(p.key) != keyLen`. If all the inequalities are false, the string was made with the current parameters and `NeedsRehash` returns `false`. In the old string, `m=19456` and `t=2` do not match the constants, so the result is `true`. `Verify` does not change: it reads the parameters from the string, so the old string still passes.
