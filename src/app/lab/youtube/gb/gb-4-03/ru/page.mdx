## Что вы узнаете

Каталог bozor отдаётся по HTTP. Если после каждой правки запускать сервер и проверять вручную через `curl`, проверка получается медленной и не повторяется.
Вопрос: как проверить код, который формирует ответ, без запуска сервера, одним `go test`?

**Главная идея:** обработчик (handler) — обычная функция с сигнатурой `func(w http.ResponseWriter, r *http.Request)`. Сервер читает текст запроса в структуру `*http.Request`, вызывает эту функцию
и делает из того, что записано в `w`, текст ответа. Поэтому обработчик можно вызвать и без сервера: `httptest.NewRequest` создаёт запрос, а `httptest.NewRecorder` — `w`, который сохраняет записанное.
Порядок ответа: заголовки → статус → тело. Если `WriteHeader` не вызван, первый `Write` ставит статус `200`; `Header().Set` и `WriteHeader` после `Write` ни на что не влияют.

К концу урока вы:

- прочитаете сигнатуру `func(w http.ResponseWriter, r *http.Request)` и объясните, что такое `w` и `r`;
- вызовете обработчик без сервера, порта и `curl` — через `httptest.NewRequest` и `httptest.NewRecorder` — и проверите статус, заголовок и JSON-тело;
- объясните порядок ответа (заголовки → статус → тело) и почему без `WriteHeader` статус равен `200`;
- напишете обработчик `catalogHandler` и добьётесь, чтобы `go test .` проходил.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| обработчик (handler) | функция, которую сервер вызывает на каждый запрос: получает запрос, пишет ответ в `w` | handler |
| `httptest.NewRequest` и `httptest.NewRecorder` | свой запрос на входе и своё место для ответа: вызов без сервера | httptest request, recorder |
| порядок ответа | заголовки, потом статус, потом тело; после первого `Write` предыдущее уже не изменить | response order |

Вспомогательные слова: `json.NewEncoder(w).Encode(v)` (записывает значение в `w` как JSON) и `http.HandlerFunc` с `httptest.NewServer` (последний, необязательный раздел).
Каждое другое новое имя я поясняю одной фразой по ходу дела.

## Что сервер делает с одним запросом

Текст запроса такой же, как в [GB-4.01](/lab/youtube/gb/gb-4-01/ru): первая строка `GET /products/1 HTTP/1.1`, затем заголовки и тело. На каждый запрос сервер делает три вещи:

| Шаг | Что происходит |
|---|---|
| 1 | сервер читает пришедший по сети текст запроса в структуру Go — `http.Request` |
| 2 | сервер вызывает **нашу функцию**: передаёт ей запрос и место, куда писать ответ |
| 3 | то, что функция записала, становится текстом ответа |

```text
текст запроса                   сервер                         наш код
GET /products/1 HTTP/1.1  ──►   1. читает текст в
Host: …                            http.Request
                                2. вызывает handler(w, r) ──►  func(w, r) { … пишет в w }
текст ответа              ◄──   3. то, что записано в w,
HTTP/1.1 200 OK …                  отправляет как ответ
```

Сегодня нас интересует только функция посередине. Эта функция называется **обработчик** (handler).

## Сигнатура обработчика: w и r

Вот самый маленький обработчик. Пока мы его только читаем, не запускаем:

```go
func healthHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "ok")
}
```

Первая строка функции — её **сигнатура** (signature): имя, параметры и тип результата.

| Часть | Смысл |
|---|---|
| `func` | объявление функции ([GB-1.07](/lab/youtube/gb/gb-1-07/ru)) |
| `healthHandler` | имя функции. Имя выбрали мы: обработчик, проверяющий, что сервер жив |
| `w http.ResponseWriter` | первый параметр: имя `w`, тип `http.ResponseWriter`. Ответ записывается в него |
| `r *http.Request` | второй параметр: имя `r`, тип `*http.Request`. Пришедший запрос. Звёздочка — указатель на структуру ([GB-2.04](/lab/youtube/gb/gb-2-04/ru)): запрос не копируется |
| (типа результата нет) | функция ничего не возвращает. Ответ не возвращают: его записывают в `w` |

`http` — имя пакета `net/http`; `ResponseWriter` и `Request` — типы из этого пакета. Сервер ждёт обработчик именно с такой сигнатурой: имена `w` и `r` — привычка, а тип и порядок — правило.

## ResponseWriter: куда пишется ответ

Тип `w` — `http.ResponseWriter` — это **интерфейс** (interface), как в [GB-2.07](/lab/youtube/gb/gb-2-07/ru). В пакете `net/http` он объявлен так (комментарии убраны):

```go
type ResponseWriter interface {
	Header() Header
	Write([]byte) (int, error)
	WriteHeader(statusCode int)
}
```

Три метода:

| Метод | Что делает |
|---|---|
| `Header()` | возвращает таблицу заголовков ответа; её тип тоже `Header`. Заголовки кладём в эту таблицу |
| `Write([]byte)` | записывает байты в тело ответа |
| `WriteHeader(statusCode int)` | задаёт код статуса |

У `ResponseWriter` есть метод `Write`, значит он ещё и `io.Writer`. Поэтому работает `fmt.Fprintln(w, "ok")`: он записывает в `w` строку `ok` и перевод строки.
Это всё тело `healthHandler`.

Важное правило: **если `WriteHeader` не вызван, первый `Write` ставит статус `200`** ([документация ResponseWriter](https://pkg.go.dev/net/http#ResponseWriter)).
`healthHandler` статус не задаёт, значит ответ будет с `200`. Скоро проверим.

## httptest.NewRequest: создаём запрос сами

Функция готова. Но кто даст ей `w` и `r`? Обычно сервер: его мы напишем в уроке [GB-4.04 · Первый сервер, строка за строкой](/lab/youtube/gb/gb-4-04/ru).
Но обработчик — обычная функция, мы тоже можем её вызвать. Для этого нужны только `w` и `r`. Их создаёт пакет `net/http/httptest`.

Сначала запрос. Эта программа создаёт `r` и заглядывает внутрь:

```go filename="_video/01-request/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	req := httptest.NewRequest(http.MethodGet, "/products/1", nil)
	fmt.Println(req.Method, req.URL.Path, req.Proto)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 10 | `req := httptest.NewRequest(http.MethodGet, "/products/1", nil)` | создаёт запрос и возвращает `*http.Request`; результат в `req`. Первый аргумент — метод: `http.MethodGet` — это строка `"GET"`. Второй — путь, из строки запроса в [GB-4.01](/lab/youtube/gb/gb-4-01/ru). Третий — тело: `nil`, то есть его нет |
| 11 | `fmt.Println(req.Method, req.URL.Path, req.Proto)` | заглядывает в запрос: `Method` — метод, `URL.Path` — путь, `Proto` — версия протокола |

Предскажите: что выведет `go run .`?

**A)** `GET /products/1 HTTP/1.1` · **B)** `GET /products/1` · **C)** `/products/1 GET`

<details>
<summary>Ответ</summary>

**A.** `Println` печатает аргументы через один пробел: метод, путь, версия. В **B** вы забыли версию (`Proto`) — третий аргумент тоже есть.
В **C** вы поменяли порядок: `Println` пишет аргументы в том порядке, в каком их передали, а здесь `Method` первый.

</details>

```console
$ ./_video/run.sh 01-request go run .
GET /products/1 HTTP/1.1
(chiqish kodi: 0)
```

Это ровно строка запроса из `curl -v`. `http.Request` — представление этого текста в Go.

## httptest.NewRecorder: вызываем обработчик как функцию

Теперь место для ответа. `httptest.NewRecorder()` — тоже `ResponseWriter`: он никуда ничего не отправляет, а сохраняет записанное. Сохранённое читаем через `rec.Code` (статус) и `rec.Body` (тело).
Вся программа:

```go filename="_video/02-recorder/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func healthHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "ok")
}

func main() {
	req := httptest.NewRequest(http.MethodGet, "/health", nil)
	rec := httptest.NewRecorder()
	healthHandler(rec, req)
	fmt.Printf("%d %q\n", rec.Code, rec.Body.String())
}
```

| Строка | Код | Что делает |
|---|---|---|
| 9–11 | `func healthHandler(…) { fmt.Fprintln(w, "ok") }` | обработчик из предыдущего раздела |
| 14 | `req := httptest.NewRequest(http.MethodGet, "/health", nil)` | запрос; путь теперь `/health` |
| 15 | `rec := httptest.NewRecorder()` | `ResponseWriter`, который сохраняет записанное |
| 16 | `healthHandler(rec, req)` | весь фокус здесь: вызываем обработчик как обычную функцию. Вместо `w` передаём `rec`, вместо `r` — `req` |
| 17 | `fmt.Printf("%d %q\n", rec.Code, rec.Body.String())` | `rec.Code` — статус, `rec.Body.String()` — записанное тело как строка. `%d` — число, `%q` — строка в кавычках, со скрытыми символами |

Обработчик статус не задавал. Чему будет равен `rec.Code`?

**A)** `0` · **B)** `200` · **C)** `500`

<details>
<summary>Ответ</summary>

**B: `200`.** Правило выше: если `WriteHeader` не вызван, первый `Write` ставит статус `200`. Если вы выбрали **A**, вы решили, что «не заданный статус = ноль»;
**C** — там, где ошибки нет, `500` не появится.

</details>

```console
$ ./_video/run.sh 02-recorder go run .
200 "ok\n"
(chiqish kodi: 0)
```

`200` — статус. Тело — `ok` и перевод строки: его добавил `Fprintln`; `%q` показал его как `\n`.

На настоящем сервере первый `Write` отправляет `200`; а recorder начинает со `200` — результат тот же. Не понадобились ни сервер, ни порт, ни `curl`: это обычный вызов функции.

## Первый тест: TestHealth

Превратим этот вызов в тест. Файл `handler_test.go` — в форме из [GB-1.08](/lab/youtube/gb/gb-1-08/ru), в одном пакете с `healthHandler` (`package main`):

```go filename="_video/03-test/handler_test.go" showLineNumbers
package main

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestHealth(t *testing.T) {
	req := httptest.NewRequest(http.MethodGet, "/health", nil)
	rec := httptest.NewRecorder()
	healthHandler(rec, req)
	if rec.Code != http.StatusOK {
		t.Errorf("status %d, kutilgan %d", rec.Code, http.StatusOK)
	}
	if got := rec.Body.String(); got != "ok\n" {
		t.Errorf("body %q, kutilgan %q", got, "ok\n")
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 9 | `func TestHealth(t *testing.T) {` | тестовая функция ([GB-1.08](/lab/youtube/gb/gb-1-08/ru)) |
| 10–12 | `req`, `rec`, `healthHandler(rec, req)` | три строки из предыдущего раздела: запрос, recorder, вызов |
| 13–15 | `if rec.Code != http.StatusOK { t.Errorf(…) }` | статус `200`? `http.StatusOK` — имя числа `200`. Если нет, тест пишет сообщение об ошибке |
| 16–18 | `if got := rec.Body.String(); got != "ok\n" { t.Errorf(…) }` | тело ровно `ok` и перевод строки? `Fprintln` добавляет перевод строки, поэтому ожидаемое значение — не `"ok"`, а `"ok\n"` |

Пройдёт ли тест? Оба условия выполнены, значит пройдёт:

```console
$ ./_video/run.sh 03-test go test -v
=== RUN   TestHealth
--- PASS: TestHealth (0.00s)
PASS
ok  	github.com/abdurahmon27/bozor	0.002s
(chiqish kodi: 0)
```

`PASS` и `ok`: тест прошёл. Ни сервера, ни порта, ни `curl`. Время — тысячные доли секунды: в видео было `0.002s`, выше — мой запуск. Это число зависит от загрузки машины
(в каждом запуске может выйти `0.002s` или `0.003s`); важен порядок величины: миллисекунды, потому что ничего не запускается и сети нет.

## Обработчик с данными: productHandler

`healthHandler` только говорит `ok`. Теперь обработчик, который отдаёт товар. Весь файл (`Product` — структура из [GB-3.02](/lab/youtube/gb/gb-3-02/ru), цена в тийинах):

```go filename="_video/04-product/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
)

// Product — katalogdagi bitta mahsulot (GB-3.02).
type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
}

var olma = Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}

// healthHandler — server tirikligini tekshirish: har soʻrovga «ok».
func healthHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "ok")
}

// productHandler — GET'ga olma mahsulotini JSON qilib beradi, boshqa metodga 405.
func productHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodGet {
		w.Header().Set("Allow", http.MethodGet)
		w.WriteHeader(http.StatusMethodNotAllowed)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(olma) // Encode xatosi: log'ga yozish GB-8.02'da
}

// main serverni ishga tushirmaydi (u GB-4.04'da): handler'ni oddiy funksiya kabi chaqirib, javobni chiqaradi.
func main() {
	req := httptest.NewRequest(http.MethodGet, "/products/1", nil)
	rec := httptest.NewRecorder()
	productHandler(rec, req)
	fmt.Printf("%d %s", rec.Code, rec.Body.String())
}
```

**Товар (строка 18).** `var olma = Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}` — значение `Product`, которое отдаёт обработчик (`olma` — «яблоко»). Цена в тийинах: `1_200_000` тийинов ([GB-1.03](/lab/youtube/gb/gb-1-03/ru)).

**Заголовок (строка 32).** `w.Header().Set("Content-Type", "application/json")`: `w.Header()` возвращает таблицу заголовков, `Set` кладёт в неё значение. `application/json` сообщает, что тело — JSON
([GB-4.01](/lab/youtube/gb/gb-4-01/ru)). Заголовок ставим **до** тела; почему — в разделе «Порядок ответа».

**Тело (строка 33).** `json.NewEncoder(w).Encode(olma)`: в `NewEncoder` передаём `w` — это обратное к `Decode`, он пишет JSON в любой `io.Writer`. `Encode` записывает в `w` значение `olma` (объявленный в этом файле `Product`).
Ошибку `Encode` пока не проверяем: запись в лог — в [GB-8.02](/lab/youtube/gb#gb-8-02).

**Метод (строки 27–31).** Обработчик может читать и из `r`: `r.Method` — первое слово строки запроса. Если это не `GET`, ответ — `405` (Method Not Allowed): заголовок `Allow` сообщает, какой метод разрешён
(`http.MethodGet`); [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#name-405-method-not-allowed) — стандарт HTTP — делает его обязательным в ответе `405`. `WriteHeader(http.StatusMethodNotAllowed)` задаёт статус: `405`.
`return` завершает функцию на этом месте, поэтому тело не пишется. В [GB-4.05](/lab/youtube/gb#gb-4-05) `ServeMux` сам проверит метод; здесь мы написали проверку вручную, чтобы показать чтение из `r`.

**main (строки 37–42).** Вызывает обработчик по адресу `/products/1` методом `GET` и печатает статус и тело. `%s` — строка; `Encode` добавляет в конец перевод строки, поэтому `\n` в `Printf` не нужен.

## Порядок ответа: заголовки, статус, тело

В обработчике порядок важен. Три шага, именно в такой последовательности:

| Шаг | Вызов | Что происходит |
|---|---|---|
| 1 | `w.Header().Set(…)` | заголовки собираются в таблице; ничего ещё не отправлено |
| 2 | `w.WriteHeader(…)` | задаётся статус (если не вызван — `200`) |
| 3 | `w.Write(…)` или `Encode` | пишется тело |

При первом вызове `Write` заголовки и статус **отправляются**. Последующие `Header().Set` и `WriteHeader` ничего не меняют:
отправленное не вернуть ([документация ResponseWriter](https://pkg.go.dev/net/http#ResponseWriter)).

```text
Header().Set(…)  ─►  WriteHeader(…)  ─►  Write(…) / Encode(…)  ─►  отправлено
  заголовки           статус               тело                     при первом Write

                                                   последующие Set / WriteHeader: без эффекта
```

Поэтому в `productHandler` `Content-Type` ставится до `Encode`, а `Allow` — до `WriteHeader`. Что бывает при нарушении порядка — в разделе «Частые ошибки».

## Глубже (необязательно): http.Handler, HandlerFunc и NewServer

Тестовый файл из [GB-4.02](/lab/youtube/gb/gb-4-02/ru) использовал `http.HandlerFunc` и `httptest.NewServer`. Теперь вы можете его прочитать.

Сервер ждёт обработчик типа `http.Handler`. Это **интерфейс с одним методом**: `ServeHTTP(ResponseWriter, *Request)`. У нашей функции такого метода нет.
`http.HandlerFunc` — **тип функции**: `type HandlerFunc func(ResponseWriter, *Request)`. У него есть метод `ServeHTTP`, и он вызывает функцию внутри. Значит `http.HandlerFunc(f)` — способ
превратить обычную функцию в `Handler` ([документация HandlerFunc](https://pkg.go.dev/net/http#HandlerFunc)).

`httptest.NewServer` открывает на этом компьютере на свободном порту **настоящий** сервер. Вся программа:

```go filename="_video/07-server/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "ok")
	}))
	defer srv.Close()
	resp, err := http.Get(srv.URL)
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	defer resp.Body.Close()
	fmt.Println(resp.Status)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 10–12 | `srv := httptest.NewServer(http.HandlerFunc(func(w …, r …) { … }))` | литерал функции — с `w` и `r`, форма нашего обработчика; `HandlerFunc` делает из него `Handler`; `NewServer` открывает сервер. Скобки закрываются по очереди: функция, `HandlerFunc`, `NewServer` |
| 13 | `defer srv.Close()` | как в [GB-2.09](/lab/youtube/gb/gb-2-09/ru): `srv.Close()` вызовется при завершении функции |
| 14–19 | `resp, err := http.Get(srv.URL)` и проверка ошибки | `srv.URL` — адрес сервера; клиент отправляет ему настоящий запрос ([GB-4.02](/lab/youtube/gb/gb-4-02/ru)) |
| 20 | `fmt.Println(resp.Status)` | печатает строку статуса ответа |

Что выведет программа? `A)` `200 OK` · `B)` `ok` · `C)` ошибка.

<details>
<summary>Ответ</summary>

**A.** `resp.Status` — код статуса и пояснение: `200 OK`. Тело (`ok`) в этой строке не печатается. `ok` (B) — это тело, записанное обработчиком, а ошибки (C) нет: сервер открылся и ответил.

</details>

```console
$ ./_video/run.sh 07-server go run .
200 OK
(chiqish kodi: 0)
```

Клиент отправил настоящий запрос, наш обработчик ответил. Что когда использовать:

| Что проверяем | Что нужно | Почему |
|---|---|---|
| сам обработчик | `httptest.NewRecorder` | быстро, порт не нужен |
| клиентский код (например, из [GB-4.02](/lab/youtube/gb/gb-4-02/ru)) | `httptest.NewServer` | клиент говорит с настоящим сервером |

Тестовый сервер находится на этом же компьютере, поэтому хватает обычного `http.Get`; для обращения к внешнему серверу нужен таймаут (`Timeout`) ([GB-4.02](/lab/youtube/gb/gb-4-02/ru)).

## Частые ошибки

**1. Сначала тело, потом статус.** Самая частая ошибка. Вот `notFoundHandler`: `Fprintln` пишет тело, а потом через `WriteHeader` мы задаём `404`.
