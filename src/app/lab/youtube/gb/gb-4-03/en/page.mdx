## What you will learn

The bozor catalog is served over HTTP. If you start the server and check by hand with `curl` after every change, the check is slow and it never repeats.
The question: how can you test the code that builds the response with one `go test`, without starting a server?

**The one idea:** a handler is a plain function with the signature `func(w http.ResponseWriter, r *http.Request)`. The server reads the request text into a `*http.Request` struct, calls this function,
and turns whatever was written to `w` into the response text. So you can call a handler without a server: `httptest.NewRequest` builds the request, and `httptest.NewRecorder` builds a `w` that keeps what is written to it.
The order of a response: headers → status → body. If `WriteHeader` is not called, the first `Write` sets the status to `200`; `Header().Set` and `WriteHeader` after a `Write` have no effect.

By the end of the lesson you will:

- read the signature `func(w http.ResponseWriter, r *http.Request)` and say what `w` and `r` are;
- call a handler without a server, a port or `curl`, using `httptest.NewRequest` and `httptest.NewRecorder`, and check the status, a header and the JSON body;
- explain the order of a response (headers → status → body) and why the status is `200` when `WriteHeader` is missing;
- write the `catalogHandler` handler and make `go test .` pass.

The three main new words of the lesson:

| Word | Plain meaning | In English |
|---|---|---|
| handler | a function the server calls on every request: it receives the request and writes the response to `w` | handler |
| `httptest.NewRequest` and `httptest.NewRecorder` | making the incoming request and the place for the response ourselves: calling without a server | httptest request, recorder |
| response order | headers, then status, then body; after the first `Write` the earlier parts cannot change | response order |

Helper words: `json.NewEncoder(w).Encode(v)` (writes a value to `w` as JSON) and `http.HandlerFunc` with `httptest.NewServer` (the last, optional section).
Every other new name gets one sentence where it first appears.

## What the server does with one request

The request text is the same as in [GB-4.01](/lab/youtube/gb/gb-4-01/en): the first line `GET /products/1 HTTP/1.1`, then headers and a body. For every request the server does three things:

| Step | What happens |
|---|---|
| 1 | the server reads the request text that arrived over the network into a Go struct, `http.Request` |
| 2 | the server calls **our function**: it passes the request and a place to write the response |
| 3 | whatever the function wrote becomes the response text |

```text
request text                    server                         our code
GET /products/1 HTTP/1.1  ──►   1. reads the text into
Host: …                            http.Request
                                2. calls handler(w, r) ──────►  func(w, r) { … writes to w }
response text             ◄──   3. sends what was written
HTTP/1.1 200 OK …                  to w as the response
```

Today we work only on the function in the middle. This function is called a **handler**.

## The handler signature: w and r

Here is the smallest handler. For now we only read it, we do not run it:

```go
func healthHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "ok")
}
```

The first line of a function is its **signature**: the name, the parameters and the result type.

| Part | Meaning |
|---|---|
| `func` | a function declaration ([GB-1.07](/lab/youtube/gb/gb-1-07/en)) |
| `healthHandler` | the function name. We chose it: a handler that checks the server is alive |
| `w http.ResponseWriter` | the first parameter: named `w`, of type `http.ResponseWriter`. The response is written to it |
| `r *http.Request` | the second parameter: named `r`, of type `*http.Request`. The incoming request. The star is a pointer to a struct ([GB-2.04](/lab/youtube/gb/gb-2-04/en)): the request is not copied |
| (no result type) | the function returns nothing. A response is not returned: it is written to `w` |

`http` is the name of the `net/http` package; `ResponseWriter` and `Request` are types from that package. The server expects a handler with exactly this signature: the names `w` and `r` are a habit, the types and their order are the rule.

## ResponseWriter: where the response is written

The type of `w`, `http.ResponseWriter`, is an **interface**, as in [GB-2.07](/lab/youtube/gb/gb-2-07/en). In the `net/http` package it is declared like this (comments removed):

```go
type ResponseWriter interface {
	Header() Header
	Write([]byte) (int, error)
	WriteHeader(statusCode int)
}
```

Three methods:

| Method | What it does |
|---|---|
| `Header()` | returns the table of response headers; its type is also called `Header`. We put headers into this table |
| `Write([]byte)` | writes bytes to the response body |
| `WriteHeader(statusCode int)` | sets the status code |

`ResponseWriter` has a `Write` method, so it is an `io.Writer` too. That is why `fmt.Fprintln(w, "ok")` works: it writes `ok` and a newline to `w`.
That is the whole body of `healthHandler`.

An important rule: **if `WriteHeader` is not called, the first `Write` sets the status to `200`** ([the ResponseWriter docs](https://pkg.go.dev/net/http#ResponseWriter)).
`healthHandler` never sets a status, so its response will have `200`. We will see it in a moment.

## httptest.NewRequest: building the request ourselves

The function is ready. But who gives it `w` and `r`? Normally the server: we write it in [GB-4.04 · The first server, line by line](/lab/youtube/gb/gb-4-04/en).
But a handler is a plain function, so we can call it too. All it needs is `w` and `r`. The `net/http/httptest` package builds them for us.

The request first. This program builds `r` and looks inside it:

```go filename="_video/01-request/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	req := httptest.NewRequest(http.MethodGet, "/products/1", nil)
	fmt.Println(req.Method, req.URL.Path, req.Proto)
}
```

| Line | Code | What it does |
|---|---|---|
| 10 | `req := httptest.NewRequest(http.MethodGet, "/products/1", nil)` | builds a request and returns a `*http.Request`; the result is in `req`. The first argument is the method: `http.MethodGet` is the text `"GET"`. The second is the path, from the request line in [GB-4.01](/lab/youtube/gb/gb-4-01/en). The third is the body: `nil`, meaning none |
| 11 | `fmt.Println(req.Method, req.URL.Path, req.Proto)` | looks inside the request: `Method` is the method, `URL.Path` the path, `Proto` the protocol version |

## httptest.NewRecorder: calling the handler like a function

Now the place for the response. `httptest.NewRecorder()` is also a `ResponseWriter`: it sends nothing anywhere and keeps what was written. We read what it kept through `rec.Code` (the status) and `rec.Body` (the body).
The whole program:

```go filename="_video/02-recorder/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func healthHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "ok")
}

func main() {
	req := httptest.NewRequest(http.MethodGet, "/health", nil)
	rec := httptest.NewRecorder()
	healthHandler(rec, req)
	fmt.Printf("%d %q\n", rec.Code, rec.Body.String())
}
```

| Line | Code | What it does |
|---|---|---|
| 9–11 | `func healthHandler(…) { fmt.Fprintln(w, "ok") }` | the handler from the previous section |
| 14 | `req := httptest.NewRequest(http.MethodGet, "/health", nil)` | the request; the path is now `/health` |
| 15 | `rec := httptest.NewRecorder()` | a `ResponseWriter` that keeps what is written |
| 16 | `healthHandler(rec, req)` | the whole trick is here: we call the handler like a plain function. We pass `rec` instead of `w` and `req` instead of `r` |
| 17 | `fmt.Printf("%d %q\n", rec.Code, rec.Body.String())` | `rec.Code` is the status, `rec.Body.String()` is the body that was written, as text. `%d` is a number, `%q` is text in quotes with hidden characters shown |

The handler never set a status. What is `rec.Code`?

**A)** `0` · **B)** `200` · **C)** `500`

<details>
<summary>Answer</summary>

**B: `200`.** The rule above: if `WriteHeader` is not called, the first `Write` sets the status to `200`. If you chose **A**, you assumed "an unset status is zero";
**C**: where nothing went wrong, `500` does not appear.

</details>

```console
$ ./_video/run.sh 02-recorder go run .
200 "ok\n"
(chiqish kodi: 0)
```

`200` is the status. The body is `ok` and a newline: `Fprintln` added it; `%q` showed it as `\n`.

On a real server the first `Write` sends `200`; and the recorder starts at `200`, so the result is the same. We needed no server, no port and no `curl`: this is a plain function call.

## A handler that returns data: productHandler

`healthHandler` only says `ok`. Now a handler that returns a product. The whole file (`Product` is the struct from [GB-3.02](/lab/youtube/gb/gb-3-02/en), the price is in tiyin):

```go filename="_video/04-product/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
)

// Product — katalogdagi bitta mahsulot (GB-3.02).
type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
}

var olma = Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}

// healthHandler — server tirikligini tekshirish: har soʻrovga «ok».
func healthHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "ok")
}

// productHandler — GET'ga olma mahsulotini JSON qilib beradi, boshqa metodga 405.
func productHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodGet {
		w.Header().Set("Allow", http.MethodGet)
		w.WriteHeader(http.StatusMethodNotAllowed)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(olma) // Encode xatosi: log'ga yozish GB-8.02'da
}

// main serverni ishga tushirmaydi (u GB-4.04'da): handler'ni oddiy funksiya kabi chaqirib, javobni chiqaradi.
func main() {
	req := httptest.NewRequest(http.MethodGet, "/products/1", nil)
	rec := httptest.NewRecorder()
	productHandler(rec, req)
	fmt.Printf("%d %s", rec.Code, rec.Body.String())
}
```

**The product (line 18).** `var olma = Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}` is the `Product` value the handler returns (`olma` means "apple"). The price is in tiyin: `1_200_000` tiyin ([GB-1.03](/lab/youtube/gb/gb-1-03/en)).

**The header (line 32).** `w.Header().Set("Content-Type", "application/json")`: `w.Header()` returns the header table, `Set` puts a value into it. `application/json` says the body is JSON
([GB-4.01](/lab/youtube/gb/gb-4-01/en)). We set the header **before** the body; the reason is in the section "Response order".

**The body (line 33).** `json.NewEncoder(w).Encode(olma)`: we give `NewEncoder` the `w`. It is the reverse of `Decode`: it writes JSON to any `io.Writer`. `Encode` writes `olma` (the `Product` declared in this file) to `w`.
We do not check the `Encode` error yet: writing it to a log comes in [GB-8.02](/lab/youtube/gb#gb-8-02).

**The method (lines 27–31).** A handler can read from `r` too: `r.Method` is the first word of the request line. If it is not `GET`, the response is `405` (Method Not Allowed): the `Allow` header says which method is allowed
(`http.MethodGet`); [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#name-405-method-not-allowed), the HTTP standard, makes it mandatory in a `405` response. `WriteHeader(http.StatusMethodNotAllowed)` sets the status: `405`.
`return` ends the function right there, so no body is written. In [GB-4.05](/lab/youtube/gb#gb-4-05) `ServeMux` checks the method itself; here we wrote it by hand to show reading from `r`.

**main (lines 37–42).** It calls the handler for `/products/1` with `GET` and prints the status and the body. `%s` is text; `Encode` adds a newline at the end, so `Printf` needs no `\n`.

Predict: what does `go run .` print?

<details>
<summary>Answer</summary>

**B.** The keys come from the `json` tags on `Product`, in lowercase ([GB-3.02](/lab/youtube/gb/gb-3-02/en)); the price is stored in tiyin: `1200000`. In **A** you forgot the tags (the keys would be capitalised) and converted the price
to som: `Encode` converts nothing. **C**: `Encode` writes the whole struct, not just `Name`.

</details>

```go
func TestProduct(t *testing.T) {
	rec := httptest.NewRecorder()
	productHandler(rec, httptest.NewRequest(http.MethodGet, "/products/1", nil))
	var got Product
	if err := json.NewDecoder(rec.Body).Decode(&got); err != nil {
		t.Fatalf("body JSON emas: %v", err)
	}
	if got != olma {
		t.Errorf("mahsulot %v, kutilgan %v", got, olma)

}
```

| Line | Code | What it does |
|---|---|---|
| 1–2 | `rec := …; productHandler(rec, httptest.NewRequest(…))` | the recorder and the call; the request is built right in the argument with `NewRequest` |
| 3 | `var got Product` | an empty variable for the product we read back |
| 4–6 | `if err := json.NewDecoder(rec.Body).Decode(&got); err != nil { t.Fatalf(…) }` | the `Decode` from [GB-4.02](/lab/youtube/gb/gb-4-02/en), only the source is `rec.Body`. If the body is not JSON, `t.Fatalf` stops the test here |
| 7–9 | `if got != olma { t.Errorf(…) }` | we compare the structs `got` and `olma` with one `!=`: Go compares structs field by field |

`TestProductMetod` checks the `405` path (`Metod` means "method"):

```go
func TestProductMetod(t *testing.T) {
	rec := httptest.NewRecorder()
	productHandler(rec, httptest.NewRequest(http.MethodPost, "/products/1", nil))
	if rec.Code != http.StatusMethodNotAllowed {
		t.Errorf("status %d, kutilgan %d", rec.Code, http.StatusMethodNotAllowed)
	}
	if got := rec.Result().Header.Get("Allow"); got != "GET" {
		t.Errorf("Allow %q, kutilgan %q", got, "GET")
	}
}
```

The request is `POST`; we expect status `405` and `Allow: GET`. The header is read from `rec.Result().Header`. `Result()` builds an ordinary `*http.Response` from what the recorder kept (the same type as `resp` in [GB-4.02](/lab/youtube/gb/gb-4-02/en));
its headers are a snapshot taken at the first `Write` or `WriteHeader`. `rec.Header()` is a live table: a header the handler set after `Write` would show up in it, although the client never receives it
([the httptest docs](https://pkg.go.dev/net/http/httptest#ResponseRecorder.Result)).

## Response order: headers, status, body

In a handler the order matters. Three steps, in this sequence:

| Step | Call | What happens |
|---|---|---|
| 1 | `w.Header().Set(…)` | headers are collected in the table; nothing has been sent yet |
| 2 | `w.WriteHeader(…)` | the status is set (if not called: `200`) |
| 3 | `w.Write(…)` or `Encode` | the body is written |

On the first `Write` the headers and the status are **sent**. Any later `Header().Set` or `WriteHeader` changes nothing:
what has been sent cannot be taken back ([the ResponseWriter docs](https://pkg.go.dev/net/http#ResponseWriter)).

```text
Header().Set(…)  ─►  WriteHeader(…)  ─►  Write(…) / Encode(…)  ─►  sent
  headers             status               body                     at the first Write

                                                   later Set / WriteHeader: no effect
```

That is why in `productHandler` `Content-Type` is set before `Encode`, and `Allow` before `WriteHeader`. What happens when the order is broken is in the section "Common mistakes".

## Going deeper (optional): http.Handler, HandlerFunc and NewServer

The test file in [GB-4.02](/lab/youtube/gb/gb-4-02/en) used `http.HandlerFunc` and `httptest.NewServer`. Now you can read it.

The server expects a handler of type `http.Handler`. It is an **interface with one method**: `ServeHTTP(ResponseWriter, *Request)`. Our function has no such method.
`http.HandlerFunc` is a **function type**: `type HandlerFunc func(ResponseWriter, *Request)`. It has a `ServeHTTP` method, and that method calls the function inside it. So `http.HandlerFunc(f)` turns
a plain function into a `Handler` ([the HandlerFunc docs](https://pkg.go.dev/net/http#HandlerFunc)).

`httptest.NewServer` opens a **real** server on a free port on this computer. The whole program:

```go filename="_video/07-server/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "ok")
	}))
	defer srv.Close()
	resp, err := http.Get(srv.URL)
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	defer resp.Body.Close()
	fmt.Println(resp.Status)
}
```

| Line | Code | What it does |
|---|---|---|
| 10–12 | `srv := httptest.NewServer(http.HandlerFunc(func(w …, r …) { … }))` | a function literal with `w` and `r`, the shape of our handler; `HandlerFunc` makes it a `Handler`; `NewServer` opens the server. The parentheses close in order: the function, `HandlerFunc`, `NewServer` |
| 13 | `defer srv.Close()` | as in [GB-2.09](/lab/youtube/gb/gb-2-09/en): `srv.Close()` runs when the function ends |
| 14–19 | `resp, err := http.Get(srv.URL)` and the error check | `srv.URL` is the server's address; the client sends it a real request ([GB-4.02](/lab/youtube/gb/gb-4-02/en)) |
| 20 | `fmt.Println(resp.Status)` | prints the status line of the response |

What does it print? `A)` `200 OK` · `B)` `ok` · `C)` an error.

<details>
<summary>Answer</summary>

**A.** `resp.Status` is the status code and its reason text: `200 OK`. The body (`ok`) is not printed by this line. `ok` (B) is the body the handler wrote, and there is no error (C): the server started and answered.

</details>

## Common mistakes

**1. The body first, the status after.** The most common mistake. Here is `notFoundHandler`: `Fprintln` writes the body, and then we set `404` with `WriteHeader`.

```go filename="_video/05-tartib/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
)

func notFoundHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "topilmadi")
	w.WriteHeader(http.StatusNotFound)
}

func main() {}
```

Its test (`TestNotFound`) runs with `go test` and expects status `404`:

```go filename="_video/05-tartib/handler_test.go" showLineNumbers
package main

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestNotFound(t *testing.T) {
	rec := httptest.NewRecorder()
	notFoundHandler(rec, httptest.NewRequest(http.MethodGet, "/yoq", nil))
	if rec.Code != http.StatusNotFound {
		t.Errorf("status %d, kutilgan %d", rec.Code, http.StatusNotFound)
	}
}
```

What is `rec.Code`?

**A)** `404` · **B)** `200` · **C)** `panic`

<details>
<summary>Answer</summary>

**B: `200`.** `Fprintln` had already sent `200` at the first `Write`; the later `WriteHeader(404)` changes nothing. If you chose **A**, you thought the last call wins:
in fact the first one does. **C**: this mistake does not stop the program, it is silently ignored.

</details>

```console

FAIL
exit status 1
```

How to read it: `--- FAIL: TestNotFound` is the failed test; `handler_test.go:13` means the error is on line 13 of the test file (`t.Errorf`); `status 200, kutilgan 404` shows the status the handler gave on the left and the one the test expected on the right
(`kutilgan` means "expected"). `exit status 1` means the test binary ended with an error, the last `FAIL` means the package failed ([GB-1.08](/lab/youtube/gb/gb-1-08/en)). The test caught the mistake.

The fix: `WriteHeader` first, then the body ([`_video/06-tartib-fix/main.go`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-4-03-handler-httptest/_video/06-tartib-fix/main.go)):

```go
func notFoundHandler(w http.ResponseWriter, r *http.Request) {
	w.WriteHeader(http.StatusNotFound)
	fmt.Fprintln(w, "topilmadi")
}
```

Will the test pass? Yes, the status is `404`:

**On a real server this mistake goes by silently.** Without a test nothing fails: the client gets `200` and the server only writes a line to its log. To show it, I ran this handler through `httptest.NewServer`.
This example is not in the course folder: I created it in a separate folder (with the course's `go.mod`); here is the whole code:

```go

	"fmt"
	"net/http"
	"net/http/httptest"

	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "topilmadi")
		w.WriteHeader(http.StatusNotFound)
	}))
	defer srv.Close()
	resp, err := http.Get(srv.URL)
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	defer resp.Body.Close()
```


The first line is the server's log (`log` starts a line with the time; the time differs every run): `superfluous response.WriteHeader call` means a redundant call; `main.go:12` is the line where `WriteHeader` stands.
The second line is what the client saw: `200 OK`, not `404`.

**2. Thinking you need a server to test a handler.** A handler is a plain function: `httptest.NewRecorder` is enough, no port is opened, and the test runs in milliseconds. `httptest.NewServer` is needed only
to test client code (the last section).

```go
func catalogHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodGet {
		w.Header().Set("Allow", http.MethodGet)
		w.WriteHeader(http.StatusMethodNotAllowed)
		return
	}
	products := catalog
	if products == nil {
		products = []Product{} // nil slice JSON'da null boʻlardi
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(products) // Encode xatosi: log'ga yozish GB-8.02'da
}
```

| Line | Code | What it does |

| 7 | `products := catalog` | takes `catalog` under a new name |
| 8–10 | `if products == nil { products = []Product{} }` | step 3: instead of a `nil` slice, an empty slice that is not `nil`: it is `[]` in JSON |
| 11 | `w.Header().Set("Content-Type", "application/json")` | step 1: the header before the body |
