## Nimani oʻrganasiz

Bozor backend'ini serverga chiqarganda u yerga nimani koʻchirasiz: kodnimi, Go'ning oʻzinimi yoki boshqa narsanimi?
Bu sahifada boʻsh papkadan boshlab, shu savolga terminalning oʻzida javob topamiz.

**Bozor** — kurs davomida oʻsadigan backend, yaʼni serverda ishlaydigan dastur: mahsulot, qoldiq va buyurtmalarni
boshqaradigan kichik marketplace. Bugun u bitta qator chiqaradi. Kurs oxirida u serverda ishlaydigan API boʻladi.

**Bitta gʻoya:** manba matn (`main.go` va `go.mod`) `go build` orqali bitta faylga aylanadi. Uni operatsion tizim
toʻgʻridan-toʻgʻri ishga tushiradi: unga Go ham, `main.go` ham kerak emas. Lekin u oxirgi `go build` paytidagi koddan
yasalgan.

Dars oxirida siz:

- boʻsh papkada `go mod init` bilan modul yaratasiz va `go.mod`'ning ikki qatorini tushuntirasiz;
- `main.go`'ning har bir qatori va belgisini oʻqiysiz: `package main`, `import "fmt"`, `func main() { … }`,
  `fmt.Println(…)`;
- `go run .` va `go build` farqini bilasiz va eskirgan binary tuzogʻiga tushmaysiz;
- kompilyator xatosini `fayl:qator:ustun` boʻyicha topasiz va `go fmt ./...` bilan kodni standart formatga keltirasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| modul | bitta nom ostida birga versiyalanadigan kod; nomi va Go versiyasi `go.mod` faylida | module |
| kirish nuqtasi | dastur boshlanadigan joy: `main` paketidagi `main` funksiyasi | entry point (`package main` + `func main`) |
| binary | `go build` yasagan bajariladigan fayl: mashina kodi, ichida Go runtime ham bor | binary (executable) |

Ikki yordamchi buyruq ham bor: `go run .` (kompilyatsiya qilib darhol ishga tushiradi) va `go fmt ./...` (kodni
standart formatga keltiradi).

## `go version`: qaysi Go oʻrnatilgan

Burchak belgisi (`$`) — terminal buyruq kutayotgani. Undan keyin `go version` yozamiz: u oʻrnatilgan Go'ni aytadi.

```console
$ go version
go version go1.26.8 linux/amd64
```

| Qism | Maʼnosi |
|---|---|
| `go1.26` | asosiy reliz (major release): Go 1.26 |
| `.8` | sakkizinchi tuzatish relizi (minor release): xatolar tuzatilgan, til oʻzgarmagan |
| `linux` | shu kompyuterning operatsion tizimi |
| `amd64` | protsessor arxitekturasi: 64 bitli Intel yoki AMD |

Sizda yangiroq versiya boʻlishi mumkin (kurs README'siga koʻra, 2026-yil noyabrida eng yangisi `go1.27.4`). Darsdagi
hamma narsa bir xil ishlaydi. `linux/amd64` jufti bugun yana bir marta kerak boʻladi: binary qayerda ishlashini u
belgilaydi.

## Modul: `go mod init` va `go.mod`

Loyihaga nom va Go versiyasi kerak. Go'da loyiha **modul** (module) boʻladi: bitta nom ostida birga versiyalanadigan
kod.

Avval boʻsh `bozor` papkasini yaratib, unga kiramiz. `mkdir` papka yaratadi, `cd` unga kiradi. Ikki ampersand (`&&`)
ikkinchi buyruqni faqat birinchisi muvaffaqiyatli boʻlsa bajaradi.

```console
$ mkdir bozor && cd bozor
$ go mod init github.com/abdurahmon27/bozor
go: creating new go.mod: module github.com/abdurahmon27/bozor
```

`mkdir … && cd …` hech narsa chiqarmadi. `go mod init` yangi modul boshlaydi. Oxiridagi matn — **modul yoʻli**
(module path), yaʼni modulning toʻliq nomi. Odatda bu kod turadigan manzil: `github.com`, foydalanuvchi nomi va
loyiha nomi. `abdurahmon27` oʻrniga oʻz GitHub nomingizni yozing; manzil hozircha mavjud boʻlmasa ham boʻladi.

Go bitta qator yozdi: «yangi go.mod yaratilmoqda: modul github.com/abdurahmon27/bozor». Videoda bu uzun yoʻl
ekranda `…/bozor` deb qisqartirilgan; bu yerda u toʻliq.

Fayl ichini koʻramiz (`cat` faylni terminalga chiqaradi):

```console
$ cat go.mod
module github.com/abdurahmon27/bozor

go 1.26.8
```

| Qator | Yozuv | Nima qiladi |
|---|---|---|
| 1 | `module github.com/abdurahmon27/bozor` | modul yoʻli: boshqa kod bu modulga shu nom bilan murojaat qiladi |
| 2 | (boʻsh) | ikki yozuvni ajratadi |
| 3 | `go 1.26.8` | `go` qatori: bu modulga kerakli eng past Go versiyasi (Go 1.21'dan beri shunday) |

Faylda ikki yozuv bor. Har birining birinchi soʻzi (`module`, `go`) — **direktiva** (directive): qator nima haqida
ekanini aytadi. `go mod init` `go` qatoriga oʻrnatilgan versiyani yozadi, sizda boshqa raqam boʻlishi mumkin.

Bir aniqlik. Go 1.26 reliz eslatmalarida `go mod init` `go 1.25.0` yozadi deyilgan. Bu faqat go1.26.0 uchun toʻgʻri:
go1.26.1'dan boshlab u yana oʻrnatilgan versiyani yozadi (manba: `cmd/go/internal/modload/init.go`). Shuning uchun
bizda `go 1.26.8`.

Kurs papkasidagi `go.mod` `go 1.26.8` talab qiladi. Sizdagi Go eskiroq boʻlsa, README'ga koʻra ikki holat bor
(bu yerda qayta ishga tushirilmagan, eski Go kerak): odatiy sozlamada (`GOTOOLCHAIN=auto`) Go kerakli versiyani oʻzi
yuklab oladi; Debian/Ubuntu paketidagi Go'da (`GOTOOLCHAIN=local`) `go.mod requires go >= 1.26.8` xatosi chiqadi.
Yechim: Go'ni yangilang yoki oʻz papkangizda `go mod init` qiling.

## `main.go` qatorma-qator

Endi shu papkada `main.go` faylini yaratamiz. Mana butun dastur, 7 qator:

```go filename="main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println("bozor ishga tushdi")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `package main` | fayl `main` paketiga tegishli: kompilyator undan ishga tushadigan dastur yasaydi |
| 2 | (boʻsh) | ajratuvchi; uni `go fmt` qoʻyadi (pastda) |
| 3 | `import "fmt"` | standart kutubxonadagi `fmt` paketini shu faylga ulaydi |
| 4 | (boʻsh) | ajratuvchi |
| 5 | `func main() {` | `main` funksiyasini eʼlon qiladi va tanasini ochadi: dastur shu yerdan boshlanadi |
| 6 | `fmt.Println("bozor ishga tushdi")` | `fmt` paketidagi `Println` ni chaqiradi: matnni terminalga yozadi |
| 7 | `}` | funksiya tanasi tugadi; `main` tugasa, dastur ham tugaydi |

Endi har bir qatorni batafsil.

### 1-qator: `package main`

Har bir Go fayli `package` soʻzi bilan boshlanadi va qaysi **paket** (package) ga tegishli ekanini aytadi. Paket —
bitta papkadagi, birga kompilyatsiya qilinadigan `.go` fayllar. `main` nomi alohida: kompilyator `main` paketidan
ishga tushadigan dastur yasaydi. Boshqa nomli paket esa kutubxona boʻladi: uni boshqa paketlar ishlatadi, oʻzi ishga
tushmaydi.

### 3-qator: `import "fmt"`

`import` boshqa paketni shu faylga ulaydi. `fmt` — **standart kutubxona** (standard library) dagi paket, nomi
«format» soʻzidan: matnni formatlab chiqaradi. Standart kutubxona Go bilan birga keladi, uni yuklab olish va internet
kerak emas.

Paket yoʻli qoʻshtirnoq ichida yoziladi: qoʻshtirnoq matn qiymatini, yaʼni **string** ni chegaralaydi. `"fmt"` —
`fmt` degan uch harfli string, paketning yoʻli.

### 5- va 7-qator: `func main() { … }`

- `func` funksiya eʼlon qiladi, `main` — uning nomi.
- Boʻsh qavslar `()` funksiya hech qanday qiymat qabul qilmasligini bildiradi.
- Jingalak qavslar `{` va `}` funksiya tanasining boshi va oxirini belgilaydi. Ochuvchi `{` shu qatorda turishi shart; keyingi
  qatorga tushirsangiz, kompilyator xato beradi («Koʻp uchraydigan xatolar» boʻlimida haqiqiy xabar).

`main` paketidagi `main` funksiyasi — dasturning **kirish nuqtasi** (entry point). Go uni oʻzi chaqiradi. Tanadagi
qatorlar tepadan pastga bajariladi. Funksiya tugasa, dastur ham tugaydi.

### 6-qator: `fmt.Println("bozor ishga tushdi")`

Bu qator dasturning butun ishi.

- `fmt.Println`: nuqta `fmt` paketi ichidagi nomga murojaat qiladi. `fmt.Println` = «`fmt` paketidagi `Println`».
- `( … )`: qavslar funksiyani **chaqiradi**. Ichidagi qiymat — **argument** (argument); bu yerda bitta string.
- `Println` argumentini **standart chiqish** (standard output) ga, yaʼni terminalga yozadi va oxiriga yangi qator
  belgisini qoʻshadi. Nomi «print line» dan.
- Katta `P` harfi nom paketdan tashqarida koʻrinishini bildiradi. Bu qoidani kursning paketlar darsida
  ([GB-2.06](/lab/youtube/gb#gb-2-06)) ochamiz. Hozir bilishingiz kerak boʻlgani: `fmt.println` deb kichik harf bilan yozib
  boʻlmaydi.
- Qator boshidagi surilish bitta Tab belgisi. Uni qoʻlda toʻgʻrilash shart emas: `go fmt` qoʻyadi.

### Dastur ishlaganda nima boʻladi

| Qadam | Nima boʻladi | Ekranda |
|---|---|---|
| 1 | operatsion tizim dasturni ishga tushiradi, Go runtime tayyorlanadi | — |
| 2 | Go `main` paketidagi `main` funksiyasini chaqiradi (5-qator) | — |
| 3 | 6-qator: `Println` `bozor ishga tushdi` va yangi qator belgisini standart chiqishga yozadi | `bozor ishga tushdi` |
| 4 | 7-qator: `main` tugadi, dastur tugaydi | — |

## `go run .`: kompilyatsiya va darhol ishga tushirish

Dasturni ishga tushiramiz: `go run .` deb yozamiz. Nuqta (`.`) — joriy papkadagi paket. Bu buyruq paketni
kompilyatsiya qiladi va natijani darhol ishga tushiradi.

Buyruqdan keyin papkada nechta fayl boʻladi?

**A)** 2: `go.mod`, `main.go` · **B)** 3: kompilyatsiya qilingan `bozor` fayli ham qoʻshiladi · **C)** 3: `main`
degan fayl paydo boʻladi

<details>
<summary>Javob</summary>

**A: ikkita.** `go run` kompilyatsiya natijasini loyiha papkasiga emas, Go'ning **build cache** papkasiga yozadi va
oʻsha yerdan ishga tushiradi (Go 1.24'dan beri natija u yerda saqlanib qoladi). Linux'da bu papka
`~/.cache/go-build`; sizdagisini `go env GOCACHE` aytadi. «B» ni tanlagan boʻlsangiz, `go run` ni `go build` bilan
adashtirgansiz: faylni papkaga `go build` yozadi (keyingi boʻlim). «C» da ham xuddi shu xato, ustiga nom ham notoʻgʻri.

</details>

```console
$ go run .
bozor ishga tushdi
$ ls
go.mod  main.go
```

Ekranda dastur yozgan qator, qoʻshtirnoqsiz: qoʻshtirnoq faqat koddagi matn chegarasi edi. `ls` papkada faqat
`go.mod` va `main.go` ni koʻrsatdi.

`go run` ga paketni doim aytasiz, bu yerda nuqta bilan. `go run main.go` ham ishlaydi, lekin faqat shu bitta faylni
oladi: paketda fayllar koʻpaysa, `go run .` kerak.

## `go build`: bitta bajariladigan fayl

`go run` har safar qayta kompilyatsiya qiladi va natijani papkaga qoldirmaydi. `go build` esa natijani papkaga fayl
qilib yozadi. Unga paket aytilmasa, joriy papkadagi paketni quradi.

```console
$ go build
$ ls
bozor  go.mod  main.go
```

Muvaffaqiyatli `go build` jim ishlaydi: hech narsa chiqarmadi. `ls` endi uchta fayl koʻrsatadi. Yangi fayl —
**binary**, `bozor` deb ataldi. Nomi papkadan emas, modul yoʻlining oxirgi qismidan olinadi
(`github.com/abdurahmon27/bozor` → `bozor`). Windows'da u `bozor.exe` boʻladi.

Faylni batafsil koʻramiz va ishga tushiramiz:

```console
$ ls -lh bozor
-rwxr-xr-x 1 haywan users 2.3M Nov 27 00:07 bozor
$ ./bozor
bozor ishga tushdi
```

`ls -l` batafsil roʻyxat beradi, `h` hajmni oʻqishga qulay birlikda yozadi:

| Ustun | Qiymat | Maʼnosi |
|---|---|---|
| ruxsatlar | `-rwxr-xr-x` | birinchi `-` = oddiy fayl; `x` harflari faylni ishga tushirish mumkinligini bildiradi |
| havolalar soni | `1` | faylning nechta nomi bor |
| egasi | `haywan` | faylni yaratgan foydalanuvchi |
| guruhi | `users` | egasining guruhi |
| hajmi | `2.3M` | 2,3 MiB (aniq: 2 410 014 bayt) |
| vaqt | `Nov 27 00:07` | oxirgi oʻzgarish vaqti |
| nomi | `bozor` | fayl nomi |

Videodagi qator `Nov 26 23:27` vaqtini koʻrsatadi; qolgan ustunlar bir xil. Sizda egasi, guruhi va vaqt boshqacha
boʻladi. Aniq bayt soni ham bir necha baytga farq qilishi mumkin (videoni yozgandagi qurilishda 2 410 070 bayt),
`2.3M` esa oʻzgarmaydi.

`./bozor` uni joriy papkadan ishga tushirdi: xuddi oʻsha qator. Hajmi nega 2,3 MiB ekanini keyingi boʻlimda koʻramiz.

## Go'siz muhitda: `env -i`

Endi `bozor` faylini boshqa papkaga koʻchirib, PATH'siz boʻsh muhitda ishga tushiramiz. Yonida `main.go` yoʻq,
terminal Go'ni topa olmaydi. Nima boʻladi?

**A)** `bozor ishga tushdi` chiqadi · **B)** xato: go topilmadi · **C)** xato: main.go yoʻq

<details>
<summary>Javob</summary>

**A: dastur ishlaydi.** `bozor` — tayyor mashina kodi, uni ishga tushirish uchun Go ham, `main.go` ham kerak emas.
«B» ni tanlagan boʻlsangiz, Go dasturi ishlashi uchun Go oʻrnatilgan boʻlishi kerak deb oʻylagansiz: Go faqat
**qurish** uchun kerak. «C» ni tanlagan boʻlsangiz, binary har safar `main.go` ni oʻqiydi deb oʻylagansiz: u matnni
oʻqimaydi, matn qurilish paytida mashina kodiga aylangan.

</details>

```console
$ env -i go version
env: ‘go’: No such file or directory
$ cp bozor /tmp/ && env -i /tmp/bozor
bozor ishga tushdi
```

`env -i` undan keyingi buyruqni boʻsh muhitda, PATH'siz ishga tushiradi. Birinchi buyruqda `env` `go` ni topmadi:
«bunday fayl yoki papka yoʻq» (chiqish kodi 127). Ikkinchisida `cp` faylni `/tmp` papkasiga koʻchirdi, `env` esa uni
oʻsha yerda ishga tushirdi: yonida `main.go` yoʻq, PATH yoʻq, `bozor` baribir ishladi.

Bir istisno (README'dan): PATH boʻlmasa, `env` `/bin` va `/usr/bin` ni qidiradi. Go `apt install golang-go` bilan
`/usr/bin` ga oʻrnatilgan boʻlsa, `env -i go version` ishlaydi. Bu `bozor` ning Go'ga muhtoj emasligini
oʻzgartirmaydi.

### Nega ishladi: `go build` ichida nima bor

`go build` bizning kodimizni, `fmt` paketini va Go **runtime** ni bitta faylga yigʻadi. Runtime — har bir Go
dasturiga qoʻshiladigan, xotira va dastur ishini boshqaradigan kod.

```text
main.go + go.mod       bizning matn
      │
      ▼
   go build            kompilyatsiya + yigʻish
      │
      ▼
    bozor              bizning kod + fmt + runtime
      │                mashina kodi: Go ham, main.go ham kerak emas
      ▼
  linux/amd64          shu tizim uni toʻgʻridan-toʻgʻri ishga tushiradi
```

Faylning katta qismi runtime. Buni oʻlchab koʻramiz: ichi boʻsh `func main() {}` dasturini quramiz. Bu misol kurs
papkasida yoʻq; uning toʻliq kodi:

```go
package main

func main() {}
```

```console
$ mkdir bosh && cd bosh
$ go mod init github.com/abdurahmon27/bosh
go: creating new go.mod: module github.com/abdurahmon27/bosh
$ go build
$ stat -c %s bosh
1830036
```

`stat -c %s` faylning hajmini baytda chiqaradi. Hech narsa qilmaydigan dastur — 1 830 036 bayt, `bozor` esa
2 410 014 bayt: `bozor` ning 76 % i `fmt` ulanmasdan oldin ham bor edi (runtime va dastur ishga tushishi uchun kod).
Kurs tadqiqotida xuddi shu Go'da 1 830 044 va 2 410 070 bayt chiqqan: nisbat yana 76 %.

Fayl tizimdagi boshqa kutubxonalarga ham bogʻlanmagan. `ldd` dastur qaysi tizim kutubxonalarini talab qilishini
koʻrsatadi:

```console
$ ldd ./bozor
	not a dynamic executable
```

«dinamik bajariladigan fayl emas»: `bozor` hech qanday tizim kutubxonasini yuklamaydi. Shuning uchun serverga shu
bitta fayl koʻchiriladi. Bitta shart bor: server ham `linux/amd64` boʻlishi kerak. Boshqa tizim uchun qurishni kursning
serverga chiqarish boʻlimida koʻramiz.

## Eskirgan binary

Endi 6-qatordagi matnni `bozor yangilandi` deb oʻzgartiramiz va faylni saqlaymiz:

```go
package main

import "fmt"

func main() {
	fmt.Println("bozor yangilandi")
}
```

```console
$ go run .
bozor yangilandi
```

`go run .` yangi matnni chiqardi: u har safar hozirgi koddan kompilyatsiya qiladi. `go build` ni esa qilmadik.

Endi `./bozor` nima yozadi?

**A)** `bozor yangilandi` · **B)** `bozor ishga tushdi` · **C)** xato: fayl eskirgan

<details>
<summary>Javob</summary>

**B: eski matn.** `go run` natijani papkaga yozmaydi. `bozor` fayli esa oxirgi `go build` paytidagi koddan yasalgan.
«A» ni tanlagan boʻlsangiz, `go run` `bozor` faylini ham yangilaydi deb oʻylagansiz. «C» ni tanlagan boʻlsangiz,
binary `main.go` oʻzgarganini biladi deb oʻylagansiz: u `main.go` ni umuman koʻrmaydi, hech kim ogohlantirmaydi.

</details>

```console
$ ./bozor
bozor ishga tushdi
$ go build && ./bozor
bozor yangilandi
```

| Qadam | `main.go` dagi matn | `bozor` fayli ichidagi matn | Ekranda |
|---|---|---|---|
| birinchi `go build` | `bozor ishga tushdi` | `bozor ishga tushdi` | — |
| matn oʻzgardi, `go run .` | `bozor yangilandi` | `bozor ishga tushdi` | `bozor yangilandi` |
| `./bozor` | `bozor yangilandi` | `bozor ishga tushdi` | `bozor ishga tushdi` |
| `go build && ./bozor` | `bozor yangilandi` | `bozor yangilandi` | `bozor yangilandi` |

Yangilash uchun qayta `go build` kerak. Serverda eski fayl qolib ketishi — haqiqiy xato. Shuning uchun dasturlar
odatda ishga tushganda oʻz versiyasini yozadi: uy vazifasida buni bozorga qoʻshasiz.

Keyingi boʻlimdan oldin matnni asl holiga (`bozor ishga tushdi`) qaytaring.

## Kompilyator xatosini oʻqish: `fayl:qator:ustun`

Endi kompilyator xabarlarini oʻqishni mashq qilamiz. Har bir xatoni `main.go` da vaqtincha qiling, keyin qaytaring.

### Yopilmagan qoʻshtirnoq

6-qatordagi yopuvchi qoʻshtirnoqni oʻchiramiz:

```go
package main

import "fmt"

func main() {
	fmt.Println("bozor ishga tushdi)
}
```

Qoʻshtirnoqda bitta belgi yetishmaydi. `go run .` nima deydi?

**A)** dastur ishlaydi, qator oxirigacha matn deb oladi · **B)** bitta xato: matn yopilmagan · **C)** ikkita xato:
matn ham, qavs ham

<details>
<summary>Javob</summary>

**C: ikki qator xato.** Birinchisi — matn yopilmagan. Matn qatorning oxirigacha choʻzilib, yopuvchi `)` ni ham yutib
yubordi, shuning uchun kompilyator qavs ham yopilmaganini koʻradi. «A» ni tanlagan boʻlsangiz: Go'da oddiy
qoʻshtirnoqli matn bitta qatordan oshmaydi. «B» da ikkinchi xato hisobga olinmagan, u birinchisining oqibati.

</details>

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:6:34: newline in string
./main.go:6:34: syntax error: unexpected newline in argument list; possibly missing comma or )
```

Birinchi qator `# github.com/abdurahmon27/bozor` — qaysi paket kompilyatsiya qilinayotgani (videoda bu qator
yashirilgan). Keyingi ikki qatorning har biri `fayl:qator:ustun` bilan boshlanadi:

| Qism | Qiymat | Maʼnosi |
|---|---|---|
| fayl | `./main.go` | joriy papkadagi `main.go` |
| qator | `6` | 6-qator |
| ustun | `34` | qatordagi 34-bayt, 1 dan sanaladi |

**Ustun** (column) — qatordagi bayt tartibi. Bu qatorda har bir belgi, Tab ham, bitta bayt:

| Boʻlak | Bayt | Jami |
|---|---|---|
| Tab | 1 | 1 |
| `fmt.Println(` | 12 | 13 |
| `"` | 1 | 14 |
| `bozor ishga tushdi)` | 19 | 33 |
| qator oxiri (yangi qator belgisi) | — | **34** |

34-bayt — qator oxiri: kompilyator ochiq matn ichida yangi qator belgisini koʻrdi.

- `newline in string` — «matn ichida yangi qator»: matn yopilmasdan qator tugadi.
- `syntax error: unexpected newline in argument list; possibly missing comma or )` — **yozilish xatosi** (syntax
  error): «argumentlar roʻyxatida kutilmagan yangi qator; vergul yoki `)` yetishmasa kerak». Bu birinchisining oqibati.

Qoida: **birinchi xatoni tuzating**. Koʻpincha qolganlari oʻzi yoʻqoladi. Bu yerda yopuvchi `"` ni qaytarish ikkala
xabarni ham yoʻqotadi.

### Ishlatilmagan import

Qoʻshtirnoqni qaytardik. Endi 4-qatorga `import "os"` qoʻshamiz. `os` — operatsion tizim bilan ishlaydigan standart
paket, lekin biz undan hech narsa chaqirmaymiz:

```go
package main

import "fmt"
import "os"

func main() {
	fmt.Println("bozor ishga tushdi")
}
```

`go run .` nima qiladi?

**A)** dastur ishlaydi va hech narsa demaydi · **B)** dastur ishlaydi, lekin ogohlantirish chiqadi · **C)** dastur
umuman kompilyatsiya qilinmaydi

<details>
<summary>Javob</summary>

**C.** Go'da ishlatilmagan import ogohlantirish emas, xato: dastur qurilmaydi, `bozor ishga tushdi` ham chiqmaydi.
«B» ni tanlagan boʻlsangiz, ogohlantirish beradigan kompilyatorni kutgansiz: Go kompilyatorida ogohlantirish yoʻq,
faqat xato bor.

</details>

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:4:8: "os" imported and not used
```

Manzil: 4-qator, 8-ustun. `import ` (boʻshliq bilan) 7 bayt, 8-bayt — qoʻshtirnoqli `"os"` boshlangan joy.
`imported and not used` — «import qilingan, lekin ishlatilmagan». Tuzatish: shu qatorni oʻchirish.

Go'ning rasmiy FAQ sahifasi sababini aytadi: keraksiz import kompilyatsiyani sekinlashtiradi, kod oʻsgan sari bu
sezilarli boʻladi. Shuning uchun Go uni xato deb hisoblaydi.

Ikki eslatma (README'dan). Odatda importlar bitta guruhga yoziladi: `import (` … `"fmt"` … `"os"` … `)`; bu shaklni
keyingi darslarda koʻramiz. VS Code'ning Go kengaytmasi faylni saqlashda ishlatilmagan importni oʻzi oʻchiradi:
bu xatoni koʻrish uchun faylni «Save without Formatting» bilan saqlang.

## `go fmt ./...`: bitta standart format

Oxirgi asbob. `main.go` ni tartibsiz yozib saqladik:

```go
package main
import "fmt"
func main(){
fmt.Println("bozor ishga tushdi")
}
```

Bu kod ishlaydi, lekin boʻsh qatorlar yoʻq, surilish yoʻq, `)` va `{` orasida boʻshliq yoʻq. Go'da kod qanday
koʻrinishi bitta standart bilan belgilangan. Uni **gofmt** degan dastur qoʻyadi, `go fmt` esa uni paketlar ustida
ishga tushiradi.

```console
$ go fmt ./...
main.go
$ go fmt ./...
```

`./...` — joriy papka va uning ichidagi hamma papkalardagi paketlar. `go fmt` har bir faylni gofmt formatiga
keltiradi va oʻzgartirgan fayllar nomini yozadi: birinchi marta `main.go`. Ikkinchi marta hech narsa chiqarmadi:
oʻzgartiradigan narsa qolmadi.

Fayl yana 7 qatorga qaytdi:

```go filename="main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println("bozor ishga tushdi")
}
```

2- va 4-qatorda boʻsh qatorlar, 6-qatorda bitta Tab bilan surilish, 5-qatorda `main() {` orasida boʻshliq. Hamma Go
kodi bir xil koʻrinadi, shuning uchun kod koʻrib chiqishda (code review) formatni emas, mazmunni muhokama qilasiz.
Koʻp muharrirlar faylni saqlashda gofmt'ni oʻzi chaqiradi.

## Chuqurroq (ixtiyoriy): ustun — bayt, belgi emas

Xato xabaridagi ustun baytlarda sanaladi. Yuqoridagi qatorda har bir belgi bitta bayt edi, shuning uchun farq
koʻrinmadi. Oʻzbekcha harf bilan farq koʻrinadi: `ʻ` (U+02BB) UTF-8'da ikki bayt. Bu misol kurs papkasida yoʻq;
6-qatorda yopilmagan `"oʻrik` matni:

```go
package main

import "fmt"

func main() {
	fmt.Println("oʻrik)
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:6:22: newline in string
./main.go:6:22: syntax error: unexpected newline in argument list; possibly missing comma or )
```

6-qatorda 20 ta belgi, lekin 21 bayt (`ʻ` ikki bayt). Kompilyator 22-ustunni koʻrsatdi: qator oxiri 22-baytda.
Belgilar boʻyicha sanaganda 21 chiqardi. Oʻzbekcha matnli qatorlarda ustun raqami belgilar sonidan katta boʻlishi
mumkin: xato baribir koʻrsatilgan joyda, faqat sanoq baytlarda.

## Koʻp uchraydigan xatolar

### 1. «`go run .` binary'ni ham yangilaydi»

Bu mavzudagi eng koʻp uchraydigan notoʻgʻri tasavvur. `go run .` natijani build cache'ga yozadi, papkadagi `bozor`
faylini oʻzgartirmaydi. Xato xabari yoʻq: eski fayl jim ishlayveradi va eski natija beradi. Haqiqiy natija
«Eskirgan binary» boʻlimida. Tuzatish: koʻchirishdan yoki ishga tushirishdan oldin qayta `go build`, va dastur
ishga tushganda versiyasini yozsin (uy vazifasi).

### 2. Ochuvchi `{` keyingi qatorda

```go
package main

import "fmt"

func main()
{
	fmt.Println("bozor ishga tushdi")
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:6:1: syntax error: unexpected semicolon or newline before {
```

Oʻqish: `main.go`, 6-qator, 1-ustun — yolgʻiz turgan `{`. Xabar: «`{` dan oldin kutilmagan nuqtali vergul yoki yangi
qator». Go kompilyatori `)` bilan tugagan qator oxiriga koʻrinmas nuqtali vergul qoʻyadi, shuning uchun
`func main()` qatori oʻsha yerda tugab qoladi. Tuzatish: `{` ni `func main()` bilan bir qatorga qaytaring
(`go fmt` buni tuzatmaydi: u ham xuddi shu xatoni beradi va faylni oʻzgartirmaydi).

### 3. `fmt.println` kichik harf bilan

```go
package main

import "fmt"

func main() {
	fmt.println("bozor ishga tushdi")
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:6:6: undefined: fmt.println (but have Println)
```

Oʻqish: 6-qator, 6-ustun — `println` boshlangan joy (Tab, `fmt.` = 5 bayt). `undefined: fmt.println (but have
Println)` — «`fmt.println` aniqlanmagan (lekin `Println` bor)». Kichik harfli nom paketdan tashqarida koʻrinmaydi;
qoidasi [GB-2.06](/lab/youtube/gb#gb-2-06)'da. Tuzatish: `Println`.

### 4. `go run` paketsiz

```console
$ go run
go: no go files listed
```

«hech qanday go fayli koʻrsatilmagan». `go build` dan farqli, `go run` joriy papkani oʻzi olmaydi. Tuzatish:
`go run .`.

### 5. Bir nechta xatoni oxiridan tuzatish

Yopilmagan qoʻshtirnoq ikki qator xato berdi, ikkinchisi «vergul yoki `)` yetishmaydi» dedi. Ikkinchisiga ishonib `)`
qoʻshsangiz, hech narsa tuzalmaydi: sabab birinchi qatorda. Har doim birinchi xabardan boshlang
(«Kompilyator xatosini oʻqish» boʻlimi).
