## Nimani oʻrganasiz

bozor kompilyatsiya boʻladi, testlari oʻtadi va ishlaydi. Lekin buyurtmada olmadan 50 dona soʻralgan, omborda esa 40 ta boʻlsa ham, dastur "buyurtma qabul qilindi" deydi.
Katalogning JSON'ida esa narx yoʻq. Kompilyator ham, test ham jim. Bu xatolarni kim topadi?

**Bitta gʻoya:** kompilyator faqat til qoidalarini tekshiradi. Kompilyatsiya boʻladigan, lekin notoʻgʻri kodni **statik tahlil** (static analysis) asboblari kodni ishga tushirmasdan oʻqib topadi.
Har asbob boshqa qatlamni koʻradi: `go vet` Go bilan keladi, `staticcheck` koʻproq tekshiruv beradi, `govulncheck` bogʻliqliklardagi maʼlum zaifliklarni qidiradi
va faqat kodingiz zaif funksiyani *chaqirsa* "affected" deydi. Uchalasi `&&` bilan commit'dan oldingi bitta qatorga yigʻiladi.

Dars oxirida siz:

- `go vet ./...` bilan takrorlangan JSON tag'ini topib tuzatasiz va `go test` uni nega koʻrmaganini tushuntirasiz;
- `staticcheck`ni aniq versiyada oʻrnatib, tekshirilmay ustiga yozilgan `err`ni (`SA4006`) topasiz va qisqa `if` bilan tuzatasiz;
- `govulncheck` natijasini uch darajada (modul, paket, funksiya) oʻqiysiz, `golang.org/x/text v0.3.7`dagi GO-2022-1059'ni trace bilan topasiz va `go get` bilan yopasiz;
- `TASK.md`da jamoadoshning `Rename` PR'ida shu uch asbob topgan uch muammoni tuzatasiz, `go test ./...` oʻtguncha.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| `go vet` | Go bilan birga keladigan tekshiruvchi: kodni ishga tushirmasdan shubhali joylarni topadi | go vet |
| `staticcheck` | alohida oʻrnatiladigan tekshiruvchi: yuzdan ortiq tekshiruv, koʻpi `go vet`da yoʻq | staticcheck |
| `govulncheck` | `go.mod`dagi versiyalarni Go zaifliklar bazasi bilan solishtiradi va kodingiz zaif funksiyani chaqirishini tekshiradi | govulncheck |

**Zaiflik** (vulnerability) — bogʻliqlik kodidagi, tashqaridan ishlatib boʻladigan xavfsizlik xatosi. Yordamchi tushunchalar: `go install paket@versiya` (asbobni oʻrnatish) va `&&` zanjiri (GB-1.01'da koʻrgansiz).

**A)** `{"name":"olma","sold":3}` · **B)** `{"name":"olma"}` · **C)** kompilyatsiya xatosi

<summary>Javob</summary>

## Muammo: kompilyatsiya boʻladi, test oʻtadi, dastur notoʻgʻri

Videoning boshlanishi — `_video/00-boshlash` qadami. Uning `cmd/bozor/main.go` fayli:

```go filename="_video/00-boshlash/cmd/bozor/main.go" showLineNumbers
// bozor dasturi: katalogni chiqaradi, buyurtmani sotadi va katalogni JSON'da yozadi.
package main

import (
	"encoding/json"
	"fmt"
	"os"

	"github.com/abdurahmon27/bozor/internal/store"
	"golang.org/x/text/language"
	"golang.org/x/text/message"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	printer := message.NewPrinter(language.Uzbek)
	for _, p := range st.List() {
		printer.Printf("%d. %s: %d soʻm\n", p.ID, p.Name, p.Price/tiyinPerSom)
	}

	err := st.Sell(1, 50)
	err = st.Sell(2, 3)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println("buyurtma qabul qilindi")

	if err := json.NewEncoder(os.Stdout).Encode(st.List()); err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}
```

Bu fayldagi hamma narsani oldingi darslardan bilasiz. Qisqacha eslatma:

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1–2 | izoh, `package main` | dastur paketi (GB-1.01) |
| 4–12 | `import (…)` | standart kutubxona (`encoding/json`, `fmt`, `os`), bozorning `internal/store` paketi va tashqi modul `golang.org/x/text` (GB-2.06) |
| 14 | `const tiyinPerSom = 100` | 1 soʻm = 100 tiyin; narx tiyinda saqlanadi (GB-1.03) |
| 17–19 | `var st store.Store`, ikkita `st.Add` | boʻsh katalog va ikki mahsulot: olmadan 40, nondan 100 dona |
| 21–24 | `printer`, `for … range` | katalogni soʻmda chiqaradi: narx tiyinda, `tiyinPerSom`ga boʻlinadi (GB-2.06) |
| 26–27 | `err := st.Sell(1, 50)`, `err = st.Sell(2, 3)` | olmadan 50 dona, keyin nondan 3 dona sotadi; `Sell` `error` qaytaradi va natija `err`ga yoziladi (GB-2.08) |
| 28–31 | `if err != nil { … os.Exit(1) }` | xato boʻlsa stderr'ga yozib, 1 kodi bilan chiqadi (GB-1.07) |
| 32 | `fmt.Println(…)` | "buyurtma qabul qilindi" |
| 34–37 | `json.NewEncoder(os.Stdout).Encode(st.List())` | katalogni JSON qilib stdout'ga yozadi (GB-3.02) |

Ishga tushiramiz:

```console
$ go run ./cmd/bozor
1. olma: 12 000 soʻm
2. non: 4 000 soʻm
buyurtma qabul qilindi
[{"id":1,"name":"olma","stock":40},{"id":2,"name":"non","stock":97}]
```

## Uch asbob, uch qatlam

Kompilyator (`go build`) til qoidalarini tekshiradi: imlo, turlar, ishlatilmagan import. Yuqoridagi ikki xato til qoidasini buzmaydi, shuning uchun kompilyator jim.
**Statik tahlil** asboblari kodni ishga tushirmasdan oʻqiydi va "bu qoidaga zid emas, lekin shubhali" deydi. Bugun uchta asbob bor, har biri boshqa narsani koʻradi:

| Asbob | Qayerdan | Nimani koʻradi | Bugungi topilma |
|---|---|---|---|
| `go vet` | Go bilan birga keladi | shubhali konstruksiyalar (35 ta tekshiruv) | takrorlangan JSON tag'i |
| `staticcheck` | alohida oʻrnatiladi | yuzdan ortiq tekshiruv, koʻpi `go vet`da yoʻq | tekshirilmay ustiga yozilgan `err` |
| `govulncheck` | alohida oʻrnatiladi | bogʻliqliklardagi maʼlum zaifliklar | eski `golang.org/x/text` |

Kod commit'ga yetguncha shu yoʻldan oʻtadi:

```text
kod ─┬─ go build ......... til qoidalari
     └─ statik tahlil .... kodni ishga tushirmasdan oʻqiydi
            ├─ go vet ........... Go bilan keladi
            ├─ staticcheck ...... koʻproq tekshiruv
            └─ govulncheck ...... maʼlum zaifliklar
                     │
                  commit  (bitta qator)
```

`go vet` ning hujjati uni shunday taʼriflaydi: "examines Go source code and reports suspicious constructs" — Go manbasini oʻqib, shubhali konstruksiyalar haqida xabar beradi ([pkg.go.dev/cmd/vet](https://pkg.go.dev/cmd/vet)).

## go vet: test oʻtdi, vet topdi

Avval testlar. `./...` — "shu papka va uning ichidagi hamma paketlar" (GB-1.01):

```console
$ go test ./...
?   	github.com/abdurahmon27/bozor/cmd/bozor	[no test files]
ok  	github.com/abdurahmon27/bozor/internal/store	0.002s
```

`cmd/bozor`da test fayli yoʻq, `store` paketining testi oʻtdi. Videoda `0.003s`, mening ishga tushirishimda `0.002s`: test vaqti har safar oʻzgaradi, muhimi `ok`.
GB-1.04'dan bilasiz: `go test` vet tekshiruvlarini ham oʻzi ishga tushiradi. Endi `go vet ./...` — hamma paketlarda. Nima chiqadi?

**A)** hech narsa: `go test` vet'ni ishlatgan · **B)** xato `store.go`da · **C)** xato `main.go`da

<details>
<summary>Javob</summary>

**B.** Xato `store.go`da, `main.go`da emas. **A** ni tanlagan boʻlsangiz, `go test` vet'ning hamma tekshiruvini ishlatadi deb oʻylagansiz: pastda koʻramiz, u faqat 11 tasini ishlatadi. **C** — `main.go`da JSON tag'i yoʻq.

</details>

```console
$ go vet ./...
internal/store/store.go:16:2: struct field OldPrice repeats json tag "price" also at store.go:15
```

Xabarni oʻqiymiz:

- `internal/store/store.go:16:2` — fayl, qator va ustun (GB-1.01'dagi `fayl:qator:ustun`);
- `struct field OldPrice repeats json tag "price"` — "`OldPrice` maydoni `price` JSON tag'ini takrorlaydi";
- `also at store.go:15` — "xuddi shu tag shu faylning 15-qatorida ham bor".

Kod kompilyatsiya boʻldi, test oʻtdi; xatoni faqat vet koʻrdi. `store.go`ning 12–18-qatorlari:

```go
type Product struct {
	ID       int64  `json:"id"`
	Name     string `json:"name"`
	Price    int64  `json:"price"` // tiyin
	OldPrice int64  `json:"price"` // chegirmagacha narx, tiyin
	Stock    int    `json:"stock"`
}
```

Jamoadosh chegirmagacha boʻlgan narx uchun `OldPrice` maydonini qoʻshgan (15-qator `Price`, 16-qator `OldPrice`). U `Price` qatorini nusxalagan va tag'ni oʻzgartirmagan.

### Nega `go test` topmadi

`go test` vet'ning hamma tekshiruvini emas, faqat **eng ishonchli 11 tasini** ishga tushiradi: ular deyarli hech qachon bekorga ogohlantirmaydi. `go help test` ularni sanaydi:

```console
$ go help test | grep -A2 'high-confidence'
binary. Only a high-confidence subset of the default go vet checks are
used. That subset is: atomic, bools, buildtag, directive, errorsas,
ifaceassert, nilfunc, printf, stdversion, stringintconv, and tests.
```

`printf` (GB-1.04) shu roʻyxatda. Tag'larni tekshiradigan `structtag` esa yoʻq. `go vet ./...` esa sukut boʻyicha hammasini ishlatadi; `go tool vet help` ularni sanaydi:

```console
$ go tool vet help | grep -c '^    [a-z]'
35
```

| Buyruq | Nechta tekshiruv | `printf` | `structtag` |
|---|---|---|---|
| `go test ./...` | 11 | bor | yoʻq |
| `go vet ./...` | 35 | bor | bor |

Oldingi darsda `structtag` tag'dagi probelni shunday topgan edi ([GB-3.02](/lab/youtube/gb/gb-3-02)). Bugun u yana bir xatoni topdi.

## Takrorlangan tag: JSON ikkala maydonni jim tashlaydi

Ikki maydonda **bir xil** JSON nomi boʻlsa, `encoding/json` ikkalasini ham tashlab yuboradi va xato bermaydi ([pkg.go.dev/encoding/json#Marshal](https://pkg.go.dev/encoding/json#Marshal):
"all fields are ignored; no error occurs"). Videoda katalogning JSON'ida `price` yoʻqligi shundan. `Unmarshal` ham narxni olmaydi: narx jim yoʻqoladi.
Buni kichik dasturda tekshirdim. Bu fayl kurs papkasida yoʻq; toʻliq kodi shu yerda (alohida papkada `go mod init example.com/takror` dan keyin `go run .`):

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Product struct {
	ID       int64 `json:"id"`
	Price    int64 `json:"price"`
	OldPrice int64 `json:"price"`
}

func main() {
	p := Product{ID: 1, Price: 1_200_000, OldPrice: 1_500_000}
	data, err := json.Marshal(p)
	fmt.Println(string(data), err)

	var q Product
	err = json.Unmarshal([]byte(`{"id":1,"price":5}`), &q)
	fmt.Println(q, err)
}
```

```console
$ go run .
{"id":1} <nil>
{1 0 0} <nil>
$ go vet ./...
main.go:11:2: struct field OldPrice repeats json tag "price" also at main.go:10
```

| Amal | Natija | Nega |
|---|---|---|
| `json.Marshal(p)` | `{"id":1}` | `Price` ham, `OldPrice` ham tashlandi; `err` — `nil` |
| `json.Unmarshal(…"price":5…)` | `{1 0 0}` | `price` kaliti hech bir maydonga yozilmadi; `err` — `nil` |
| `go vet ./...` | `struct field OldPrice repeats json tag "price"` | vet qatorni koʻrsatadi |

Tuzatish: `OldPrice`ga oʻz kaliti, `old_price`. `omitempty` qoʻshmaymiz: [GB-3.02](/lab/youtube/gb/gb-3-02) qoidasi — songa `omitempty` qoʻyilmaydi, aks holda nol qiymat bilan yoʻq kalitni ajratib boʻlmaydi.

```go
type Product struct {
	ID       int64  `json:"id"`
	Name     string `json:"name"`
	Price    int64  `json:"price"`     // tiyin
	OldPrice int64  `json:"old_price"` // chegirmagacha narx, tiyin
	Stock    int    `json:"stock"`
}
```

`&&` — "oldingi buyruq muvaffaqiyatli tugasagina keyingisini ishga tushir" (GB-1.01). `go vet` jim boʻlsa, `go run` ishlaydi:

```console
$ go vet ./... && go run ./cmd/bozor
1. olma: 12 000 soʻm
2. non: 4 000 soʻm
buyurtma qabul qilindi
[{"id":1,"name":"olma","price":1200000,"old_price":0,"stock":40},{"id":2,"name":"non","price":400000,"old_price":0,"stock":97}]
```

`go vet` jim boʻldi, shuning uchun `go run` ham ishladi. JSON'da narx qaytdi, `old_price` esa nol: chegirma yoʻq.

## staticcheck: oʻrnatish

Videodagi ikkinchi xato — buyurtma — hali joyida, vet esa jim. Uni topish uchun `staticcheck` kerak. U Go'da keng tarqalgan statik tahlil asbobi, uni mustaqil loyiha yuritadi
([staticcheck.dev](https://staticcheck.dev/docs/)). Yuzdan ortiq tekshiruvi bor: bir qismi vet'nikiga oʻxshaydi, koʻpi vet'da yoʻq. Tekshiruvlarning nomi harf va raqam:
Qavs ichidagi nom (masalan `SA4006`) — guruh (`SA`) va raqam (`4006`).

Asbob Go bilan kelmaydi, uni `go install` bilan oʻrnatamiz. Qatorning qismlari:

| Qism | Nima |
|---|---|
| `go install` | modulni yuklaydi, undagi buyruqni build qiladi va binary faylni Go'ning `bin` papkasiga qoʻyadi |
| `honnef.co/go/tools/cmd/staticcheck` | `honnef.co/go/tools` — modul; `cmd/staticcheck` — undagi buyruq papkasi (GB-2.06) |
| `@2026.2.2` | kuchukcha belgisidan keyin versiya: aniq versiya yozsak, jamoadagi har kim bir xil tekshiruvlarni oladi |

```console
$ go install honnef.co/go/tools/cmd/staticcheck@2026.2.2
go: downloading honnef.co/go/tools v0.8.2
go: downloading golang.org/x/tools v0.51.0
go: downloading golang.org/x/exp/typeparams v0.0.0-20231108232855-2478ac86f678
go: downloading github.com/BurntSushi/toml v1.4.1-0.20240526193622-a339e1f7089c
go: downloading golang.org/x/exp v0.0.0-20231110203233-9a3e6036ecaa
go: downloading golang.org/x/sync v0.23.0
go: downloading golang.org/x/mod v0.41.0
```

Bu yuqorida — toza modul keshi bilan olingan toʻliq chiqish (mening ishga tushirishim: kesh boʻsh edi). Videoda faqat birinchi qator koʻrinadi, qolganlari `…` bilan yashirilgan.
Kesh toʻla boʻlsa, `go install` hech narsa chiqarmaydi. Birinchi marta Go versiyasini ham yuklasa, yana bitta `go: downloading go1.27.4` qatori chiqishi mumkin.
staticcheck relizi yil bilan nomlanadi (`2026.2.2`); modul versiyasi `v0.8.2` — bu bitta reliz (`staticcheck -version` ikkalasini koʻrsatadi). `go install` bozor'ning `go.mod`'iga tegmaydi.

Endi ishga tushiramiz. Koʻp uchraydigan xato:

```console
$ staticcheck ./...
bash: staticcheck: command not found
```

Shell `staticcheck`ni topmadi: binary oʻrnatilgan, lekin Go'ning `bin` papkasi **PATH**da yoʻq (PATH — shell buyruqni qidiradigan papkalar roʻyxati). Tuzatish:

```console
$ export PATH="$PATH:$(go env GOPATH)/bin"
```

Buyruq hech narsa chiqarmaydi. `go env GOPATH` Go'ning uy papkasini chiqaradi (odatda `~/go`), `go install` binary'larni uning `bin` papkasiga qoʻyadi. `$( … )` ichidagi buyruq natijasini qatorga qoʻyadi,
`export` esa shu qatorni PATH oxiriga yozadi. Bu faqat shu terminal uchun. Doimiy qilish uchun xuddi shu qatorni `~/.bashrc` oxiriga qoʻshamiz (zsh'da `~/.zshrc`):

```console
$ echo 'export PATH="$PATH:$(go env GOPATH)/bin"' >> ~/.bashrc
```

Bu ham hech narsa chiqarmaydi. Bittalik qoʻshtirnoq ichida `$` hozir ochilmaydi: faylga qator oʻzicha yoziladi. `>>` — qatorni faylning oxiriga qoʻshadi.

## staticcheck: yoʻqolgan xato

Buyurtma kodi (`cmd/bozor/main.go`, 26–32-qatorlar):

```go
	err := st.Sell(1, 50)
	err = st.Sell(2, 3)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println("buyurtma qabul qilindi")
```

Birinchi `Sell` olmadan 50 dona sotadi va xatoni `err`ga yozadi. Ikkinchi `Sell` nondan 3 dona sotadi, natija yana `err`ga. Keyin `if err != nil`. `staticcheck ./...` qaysi qatorni koʻrsatadi?

**A)** 26: `err := st.Sell(1, 50)` · **B)** 27: `err = st.Sell(2, 3)` · **C)** hech qaysi: `err` tekshirilgan

<details>
<summary>Javob</summary>

**A.** 26-qatordagi qiymat 27-qatorda oʻqilmasdan ustiga yoziladi. **B** ni tanlagan boʻlsangiz: 27-qatordagi qiymatni `if` oʻqiydi, shuning uchun u muammo emas. **C** — `err` tekshirilgan, ammo faqat *oxirgi* qiymati; birinchisi yoʻqolgan.

</details>

Avval `00-boshlash` qadamida (ikkala xato ham shu yerda) ishga tushiramiz:

```console
$ staticcheck ./...
cmd/bozor/main.go:26:2: this value of err is never used (SA4006)
```

`cmd/bozor/main.go:26:2` — 26-qator, 2-ustun: "`err`ning shu qiymati hech qachon ishlatilmaydi". Qavs ichida tekshiruvning nomi, `SA4006`. Nega:

| Qator | Kod | `err`da nima turibdi |
|---|---|---|
| 26 | `err := st.Sell(1, 50)` | olma xatosi (qoldiq 40, soʻralgan 50) |
| 27 | `err = st.Sell(2, 3)` | nonning natijasi `nil`; olma xatosi yoʻqoldi |
| 28 | `if err != nil {` | `err` — `nil`: `if` ichiga kirilmaydi |

Natijada olma xatosini hech kim tekshirmadi va dastur "buyurtma qabul qilindi" dedi. Bu boshidagi birinchi xato: buyurtma qabul qilindi. Vet buni koʻrmadi, chunki `go vet` va `staticcheck` turli tekshiruvlarni ishlatadi:
vet jim edi (yuqoridagi `go vet ./... && go run ./cmd/bozor` qatoriga qarang), `staticcheck` esa topdi. Aksincha ham shunday: yuqoridagi chiqishda `staticcheck` takrorlangan tag'ni topmadi — uni vet topgan edi. Asboblar bir-birini toʻldiradi.

Tekshiruv nomini bilsangiz, `staticcheck -explain` uning hujjatini terminalda koʻrsatadi:

```console
$ staticcheck -explain SA4006
A value assigned to a variable is never read before being overwritten. Forgotten error check or dead code?

Available since
    2017.1

Online documentation
    https://staticcheck.dev/docs/checks#SA4006
```

Birinchi qator: "oʻzgaruvchiga yozilgan qiymat ustiga yozilishidan oldin oʻqilmadi: xato tekshiruvi unutilgan yoki kod keraksiz". Pastda — hujjat sahifasining manzili. Videoda "Available since 2017.1" qismi yashirilgan.

**Tuzatish — qisqa `if`** ([GB-1.05](/lab/youtube/gb/gb-1-05)): `err` faqat shu `if` ichida yashaydi va oʻsha zahoti tekshiriladi. Ikkinchi `Sell` oʻzining `err`ini oladi: endi birini ikkinchisining ustiga yozib boʻlmaydi.

```go

		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	if err := st.Sell(2, 3); err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
```

```console
$ staticcheck ./... && go run ./cmd/bozor

2. non: 4 000 soʻm
xato: olma: qoldiq 40, soʻralgan 50
exit status 1
```

`staticcheck` jim; dastur esa toʻgʻrisini aytadi: olma qoldigʻi 40, soʻralgan 50. `exit status 1` — `os.Exit(1)` bergan chiqish kodi; `go run` uni shunday yozadi (GB-1.07).

## Koʻp uchraydigan xatolar

**1. "Kompilyatsiya boʻldi va test oʻtdi, demak kod toʻgʻri."** Bu dars shu eʼtiqodga qarshi. `go build` til qoidalarini tekshiradi, `go test` faqat yozilgan tekshiruvlarni va vet'ning 11 tasini ishlatadi.

**2. `bash: staticcheck: command not found`.** Buyruq yuqorida koʻrsatilgan. Oʻqish: shell `staticcheck` degan buyruqni PATH papkalaridan topmadi. Sabab: `go install` binary'ni `$(go env GOPATH)/bin` ga qoʻydi, u PATH'da emas.
Tuzatish: `export PATH="$PATH:$(go env GOPATH)/bin"`, doimiy boʻlishi uchun `~/.bashrc`ga ham yozing.

**3. Asbobni papkadan tashqarida oʻrnatish.** Go eskiroq boʻlsa, asbob eski Go bilan quriladi va yangi standart kutubxonani oʻqiy olmaydi: `unknown field rfd in struct literal of type splicePipe (compile)`.
Oʻqish: xato `internal/poll` — Go'ning oʻz kodida, sizniki emas. Tuzatish: `go install` ni lesson papkasi ichida qayta ishga tushiring; Go'ni yangilaganingizdan keyin ham asboblarni qayta oʻrnating.

**4. `doesn't appear to call` ni "hammasi joyida" deb oʻqish.** Chiqish kodi 0 va "affected by 0", lekin paket va modul darajasida zaiflik bor edi (GO-2022-1059, GO-2026-6629, GO-2026-5970). Bugun chaqirilmagan funksiyani ertaga yangi kod chaqirishi mumkin.
Tuzatish: baribir `go get golang.org/x/text@latest`.

## Oʻzingizni tekshiring

1. Takrorlangan JSON tag'ini qaysi buyruq topadi va nega `go test` topmadi?

<details>
<summary>Javob</summary>

`go vet ./...` (tekshiruv `structtag`). `go test` vet'ning faqat 11 ta ishonchli tekshiruvini ishlatadi, `structtag` ular orasida yoʻq; `go vet ./...` esa hamma 35 tasini ishlatadi.

</details>

2. `govulncheck` "zaiflik bor, lekin kodingiz uni chaqirmaydi" desa (`doesn't appear to call`), chiqish kodi qanday? Modulni yangilash kerakmi?

<details>
<summary>Javob</summary>

Chiqish kodi 0 (kod chaqirsa — 3). Baribir yangilang: bugun chaqirilmagan zaif funksiyani ertaga yangi kod chaqirishi mumkin, paket va modul darajasidagi zaifliklar ham yopiladi.

</details>

3. [GB-2.10](/lab/youtube/gb/gb-2-10)'dan: `len("oʻrik")` nechaga teng?

<details>
<summary>Javob</summary>

6. `ʻ` belgisi UTF-8'da 2 bayt oladi, qolgan 4 harf — 1 baytdan: 1 + 2 + 1 + 1 + 1 = 6.

</details>

4. Yuqoridagi `takror` dasturida `json.Marshal(p)` nima yozadi (`p` — `ID: 1`, `Price: 1_200_000`, `OldPrice: 1_500_000`)?

<details>
<summary>Javob</summary>

`{"id":1}`. `Price` ham, `OldPrice` ham tashlanadi, `err` — `nil`. Bu natija shu sahifadagi `takror` dasturining birinchi qatori (men ishga tushirdim).
Agar `{"id":1,"price":1200000}` deb yozgan boʻlsangiz, ikki maydondan biri "gʻolib" boʻladi deb oʻylagansiz; `encoding/json` ikkalasini ham tashlaydi.

</details>

5. `go vet ./... && staticcheck ./... && govulncheck ./... && go test ./...` qatorida `staticcheck` xato topsa, `govulncheck` ishga tushadimi?

<details>
<summary>Javob</summary>

Yoʻq. `staticcheck` noldan farqli kod bilan chiqadi, `&&` zanjirni toʻxtatadi: `govulncheck` va `go test` ishga tushmaydi.

</details>

## Uy vazifasi

Vazifa kurs papkasidagi [`TASK.md`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-3-03-jamoa-asboblari/TASK.md) faylida;
papka: [lessons/gb-3-03-jamoa-asboblari](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/gb-3-03-jamoa-asboblari).
Jamoadoshingiz `Rename(id int64, name string) error` metodi bilan PR yubordi: u mahsulot nomini almashtiradi, nom chetidagi boʻsh joylarni olib tashlaydi, boʻsh nom boʻlsa `error` qaytaradi.
PR eski branch'dan kelgani uchun `go.mod`da `golang.org/x/text` yana `v0.3.7`. Kod kompilyatsiya boʻladi va eski test oʻtadi. Fayl `internal/store/rename.go`:

```go filename="internal/store/rename.go" showLineNumbers
package store

// Bu fayl — jamoadoshingizning PR'i (TASK.md). U kompilyatsiya boʻladi va eski test oʻtadi,
// lekin go vet va staticcheck unda xato topadi.

import (
	"errors"
	"fmt"
	"strings"
)

// Rename id'li mahsulotning nomini almashtiradi.
// Nom chetidagi boʻsh joylarsiz saqlanadi; boʻsh nom — xato.
func (s *Store) Rename(id int64, name string) error {
	strings.TrimSpace(name)
	if name == "" {
		return errors.New("nom boʻsh boʻlmasin")
	}
	for i := range s.products {
		p := &s.products[i]
		if p.ID == id {
			p.Name = p.Name
			return nil
		}
	}
	return fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
}
```

Daraja belgilari (🟢🟡🟠) kurs papkasida yoʻq: men qoʻydim. Papkaning ildizida uch qadam; test fayllarini (`tekshiruv_test.go`) oʻzgartirmang:

- 🟢 **1-qadam, `go vet ./...`.** Bitta xabar chiqadi. Uni oʻqing va `rename.go`dagi qatorni tuzating.
- 🟡 **2-qadam, `staticcheck ./...`.** Vet koʻrsatgan qatorni u ham koʻrsatadi, lekin yana bitta xato topadi, uni vet koʻrmaydi. Ikkalasini tuzating.
- 🟠 **3-qadam, `govulncheck ./...`.** Qaysi zaiflik, qaysi qator uni chaqiradi? Modulni yangilang.

Uchala buyruq jim boʻlsin (`govulncheck` faqat `No vulnerabilities found.` desin), keyin `go test ./...` `ok` boʻlguncha ishlang. Boshlangʻich kodda test shunday yiqiladi (mening ishga tushirishim):

(`diff -ru internal solution/internal`, `diff go.mod solution/go.mod`).

<summary>Javoblar: 1-, 2- va 3-qadam</summary>

**1-qadam.** Vet `rename.go:22:4`da `self-assignment of p.Name`: `p.Name = p.Name` oʻz-oʻziga yozadi, nom almashmaydi. Tuzatish: `p.Name = name`.

**2-qadam.** `staticcheck` shu qatorni (`SA4018`) va yana bittasini koʻrsatadi: `rename.go:15:2` `TrimSpace doesn't have side effects and its return value is ignored (SA4017)`.
`strings.TrimSpace(name)` yangi qator qaytaradi va `name`ni oʻzgartirmaydi; natija tashlab yuborilgan. Tuzatish: `name = strings.TrimSpace(name)`. Vet bu qatorni koʻrmaydi: SA4017 vet'da yoʻq.

**3-qadam.** `govulncheck ./...` yuqoridagi `GO-2022-1059` natijasini beradi (`main` `language.MatchStrings`ni 26-qatorda chaqiradi), chiqish kodi 3. Tuzatish: `go get golang.org/x/text@latest` (`v0.44.0`).
Test kamida `v0.41.0` talab qiladi: 2026-11-27 holatida `x/text` boʻyicha `govulncheck` hech narsa topmaydigan eng past versiya shu; `v0.3.8` GO-2022-1059'ni yopadi, lekin ikki modul darajasidagi zaiflik qoladi.
