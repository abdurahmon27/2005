## Nimani oʻrganasiz

bozor importeri katalog qoldiqlarini yangilaydi. U har kecha 1000 mahsulot qoldigʻini yetkazib beruvchidan soʻraydi. Ketma-ket ishlash taxminan 20 soniya oladi. Har mahsulotga goroutine ochsak, tajribadagi yetkazib beruvchi 990 soʻrovni rad etadi. Qanday qilib importni tezlatib, soʻrovlar sonini chegaralaymiz?

**Bitta gʻoya:** bir vaqtda ishlaydigan soʻrovlar sonini kirish hajmi belgilamasin. Oʻzingiz tanlagan chegara va bekor qilish signali importni boshqaradi.

Darsdan keyin siz:

- cheksiz goroutine ochishning oqibatini soʻrov, goroutine va xotira oʻlchovlarida tekshirasiz;
- bitta kanal ustida oʻnta worker yozasiz;
- `errgroup` bilan limit va birinchi xatoni qaytarishni birlashtirasiz;
- guruh contextini ishlatib, xatodan keyingi ishlarni bekor qilasiz va `Wait`dan keyingi context xatosini tuzatasiz.

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| worker pool | bitta kanaldan ish oladigan doimiy goroutine guruhi | worker pool |
| `errgroup.Group` | funksiyalar tugashini kutadi, birinchi xatoni qaytaradi | errgroup |
| `errgroup.WithContext` | xatoda yoki `Wait` qaytganda guruh contextini bekor qiladi | WithContext |

**Chegaralangan parallellik** — bir vaqtda koʻpi bilan N ta ish. Bu yerda “bir vaqtda” soʻrovlarning kutish vaqti ustma-ust kelishini ham bildiradi. `SetLimit` shu chegarani qoʻyadi. Yordamchi yozuv `errs...` slice elementlarini alohida argumentlarga yoyadi. `golang.org/x/sync` — standart kutubxonadan tashqaridagi Go moduli.

## Ketma-ket import: oʻlchov uchun asos

Bu safar yetkazib beruvchi soxta va tarmoqsiz: `supplier.go`. `checkStock(ctx, id)` bitta qoldiqni qaytaradi. ID 1 — olma, 40; ID 2 — non, 120; ID 3 — oʻrik, 5. Qolgan mavjud ID uchun qoldiq `id % 50`. Faqat 1…1000 ID mavjud.

Har soʻrov taxminan 20 ms kutadi. Bir vaqtda 10 tadan ortiq soʻrov kirsa, ortigʻi `ErrTooMany` oladi: `429 too many requests`. Bu laboratoriyaning bir vaqtdagi ishlar chegarasi; vaqt birligidagi rate limit bilan aynan bir narsa emas. Haqiqiy HTTP javobi yuborilmaydi. `catalogIDs(n)` 1…n ID slice'ini yasaydi; `saveStocks` faqat contextni tekshiradi. Postgres'ga yozish GB-7.07 da keladi.

```go filename="_video/01-ketma/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"time"
)

func importStocks(ctx context.Context, ids []int64) ([]int, error) {
	stocks := make([]int, len(ids))
	for i, id := range ids {
		n, err := checkStock(ctx, id)
		if err != nil {
			return nil, fmt.Errorf("mahsulot %d: %w", id, err)
		}
		stocks[i] = n
	}
	return stocks, nil
}

func main() {
	start := time.Now()
	stocks, err := importStocks(context.Background(), catalogIDs(1000))
	report(stocks, err, start)
}
```

## Har ID uchun goroutine: chegara yoʻq

```go filename="_video/02-cheksiz/main.go" showLineNumbers
package main

import (
	"context"
	"errors"
	"sync"
	"time"
)

func importStocks(ctx context.Context, ids []int64) ([]int, error) {
	stocks := make([]int, len(ids))
	errs := make([]error, len(ids))
	var wg sync.WaitGroup
	for i, id := range ids {
		wg.Go(func() {
			stocks[i], errs[i] = checkStock(ctx, id)
		})
	}
	wg.Wait()
```

## Bitta jobs kanali, oʻnta worker

Har ID uchun yangi goroutine oʻrniga **worker pool** tuzamiz. `main` ish indeksini yuboradi; oʻnta doimiy goroutine ularni oladi.

| Holat | main / jobs | Worker va soʻrovlar |
|---|---|---|
| boshlanish | buffersiz `jobs`, ish yoʻq | 10 worker qabul qilishni kutadi |
| 10 ta band | keyingi `jobs <- i` kutadi | koʻpi bilan 10 soʻrov |
| bittasi tugadi | indeks oʻsha workerga oʻtadi | u keyingi soʻrovni boshlaydi |
| yuborish tugadi | `close(jobs)`, keyin `wg.Wait()` | range tugaydi, hammasi kutiladi |

```go filename="_video/04-worker/main.go" showLineNumbers
package main

import (
	"context"
	"errors"
	"sync"
	"time"
)

const workers = 10

func importStocks(ctx context.Context, ids []int64) ([]int, error) {
	stocks := make([]int, len(ids))
	errs := make([]error, len(ids))
	jobs := make(chan int)
	var wg sync.WaitGroup
	for range workers {
		wg.Go(func() {
			for i := range jobs {
				stocks[i], errs[i] = checkStock(ctx, ids[i])
			}
		})
	}
	for i := range ids {
		jobs <- i
	}
	close(jobs)
	wg.Wait()
	return stocks, errors.Join(errs...)
}

func main() {
	start := time.Now()
	stocks, err := importStocks(context.Background(), catalogIDs(1000))
	report(stocks, err, start)
}
```

10-qator `workers = 10` chegarasi. 15-qator buffersiz `chan int` yaratadi: kanalga ID emas, indeks yuboriladi. 17–23 oʻnta `wg.Go` boshlaydi. 19–21-qatorlar kanal yopilguncha indeks olib, faqat oʻsha natija joyiga yozadi.

24–26 har indeksni `jobs <- i` bilan yuboradi. Boʻsh worker boʻlmasa, yuboruvchi kutadi. 27-qator kanalni yopadi; `for i := range jobs` tugaydi. 28-qator barcha workerlarni kutadi. 29-qator xatolarni yigʻadi.

## errgroup: limit va birinchi xato

Qoʻlda kanal, worker sikli va xatolar slice'ini boshqardik. **errgroup** funksiyalar tugashini kutish va xato qaytarishni birlashtiradi. Bu `golang.org/x/sync` modulidagi paket.

Bogʻliqlik dars papkasida allaqachon bor. Quyidagi buyruq oʻsha bogʻliqligi hali yoʻq alohida vaqtinchalik modulda qayta bajarildi:

```console
$ go get golang.org/x/sync/errgroup
go: added golang.org/x/sync v0.25.0
```

`go: added` — modul `go.mod`ga qoʻshildi; `go.sum` tekshiruv summalarini saqlaydi. Videoda qoʻshimcha `go: downloading` qatori bor edi; hozir modul keshda, yuklash qatori chiqmadi.

```go filename="_video/05-errgroup/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"time"

	"golang.org/x/sync/errgroup"
)

const workers = 10

func importStocks(ctx context.Context, ids []int64) ([]int, error) {
	stocks := make([]int, len(ids))
	var g errgroup.Group
	g.SetLimit(workers)
	for i, id := range ids {
		g.Go(func() error {
			n, err := checkStock(ctx, id)
			if err != nil {
				return fmt.Errorf("mahsulot %d: %w", id, err)
			}
			stocks[i] = n
			return nil
		})
	}
	if err := g.Wait(); err != nil {
		return nil, err
	}
	return stocks, nil
}

func main() {
	start := time.Now()
	stocks, err := importStocks(context.Background(), catalogIDs(1000))
	report(stocks, err, start)
}
```

8-qator paketni import qiladi. 15-qator nol qiymatli `Group`; u tayyor, lekin oʻzi limit ham, xatoda bekor qilish ham bermaydi. 16-qator `SetLimit(workers)` bilan faol ishlar sonini chegaralaydi.

18-qator `g.Go`ga `func() error` beradi. Limit band boʻlsa, aynan `g.Go` chaqiruvchisi kutadi. Bu oʻnta doimiy worker emas: har ish uchun goroutine boshlanadi, faol ishlar soni cheklanadi. 19–25 avvalgidek qoldiqni oladi, ID bilan xatoni oʻraydi yoki `stocks[i]`ga yozib `nil` qaytaradi.

27–29-qatorlar barcha boshlangan funksiyalar tugashini kutadi va birinchi nil boʻlmagan xatoni qaytaradi. “Birinchi” ID tartibidagi birinchi emas; birinchi qayd etilgan xato. 30-qator faqat xatosiz natijani qaytaradi.

| Holat | `g.Go` chaqiruvchisi | Natija |
|---|---|---|
| 0 faol | birinchi ishni boshlaydi | 1 faol |
| 10 faol | 11-ishni qoʻshishda kutadi | chegara saqlanadi |
| bittasi tugadi | joy ochilib, keyingisi boshlanadi | koʻpi bilan 10 faol |
| sikl tugadi | `g.Wait()` | hammasi tugaydi, birinchi xato yoki `nil` |

**Bashorat:** xatosiz 1000 ID bilan nima oʻzgaradi? **A)** yana 990 rad · **B)** taxminan 2 s, koʻpi bilan 10 faol · **C)** faqat 10 ta natija.

</details>

```go filename="_video/07-withctx/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"time"

	"golang.org/x/sync/errgroup"
)

const workers = 10

func importStocks(ctx context.Context, ids []int64) ([]int, error) {
	stocks := make([]int, len(ids))
	g, ctx := errgroup.WithContext(ctx)
	g.SetLimit(workers)
	for i, id := range ids {
		g.Go(func() error {
			n, err := checkStock(ctx, id)
			if err != nil {
				return fmt.Errorf("mahsulot %d: %w", id, err)
			}
			stocks[i] = n
			return nil
		})
	}
	if err := g.Wait(); err != nil {
		return nil, err
	}
	return stocks, nil
}

func main() {
	start := time.Now()
	ids := catalogIDs(1000)
	ids[499] = 9999
	stocks, err := importStocks(context.Background(), ids)
	report(stocks, err, start)
}
```

15-qator `g, ctx := errgroup.WithContext(ctx)`. Bu funksiya tanasida `ctx` parametr bilan bir xil blokda. `:=` faqat `g`ni yaratadi; mavjud `ctx`ga yangi context qiymatini yozadi. 19-qator endi guruh contextini beradi. Birinchi nil boʻlmagan xato shu contextni bekor qiladi.

Yetkazib beruvchi bunga ikki joyda javob beradi: chaqiruv boshida `ctx.Err()`ni tekshiradi; kutayotganda `select` orqali `ctx.Done()`ni ham kuzatadi. Bekor qilish goroutine'ni majburan oʻldirmaydi. Ikkala `select` tarmogʻi tayyor boʻlsa, bekor qilish tarmogʻi doim tanlanishi kafolatlanmaydi.

## Wait tugagach qaysi context?

Endi xato ID yoʻq. Importdan keyin qoldiqlarni `saveStocks` bilan saqlaymiz. `g, ctx :=` parametrdagi contextni almashtirgan. `_video/08-wait-ctx/main.go`da qoʻshilgan qism:

```go

		return nil, err
```

```go filename="_video/09-gctx/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"time"

	"golang.org/x/sync/errgroup"
)

const workers = 10

func importStocks(ctx context.Context, ids []int64) ([]int, error) {
	stocks := make([]int, len(ids))
	g, gctx := errgroup.WithContext(ctx)
	g.SetLimit(workers)
	for i, id := range ids {
		g.Go(func() error {
			n, err := checkStock(gctx, id)
			if err != nil {
				return fmt.Errorf("mahsulot %d: %w", id, err)
			}
			stocks[i] = n
			return nil
		})
	}
	if err := g.Wait(); err != nil {
		return nil, err
	}
	if err := saveStocks(ctx, stocks); err != nil {
		return nil, err
	}
	return stocks, nil
}

func main() {
	start := time.Now()
	stocks, err := importStocks(context.Background(), catalogIDs(1000))
	report(stocks, err, start)
}
```

15-qator endi yangi `g` va `gctx` yaratadi, parametr `ctx`ni saqlaydi. 19-qator `checkStock(gctx, id)`; 30–32-qatorlar `saveStocks(ctx, stocks)`. Tashqi contextning oʻz muddati yoki bekor qilinishi hali amal qiladi.

## Chuqurroq (ixtiyoriy): limit ichidagi kanal

v0.25.0 manbasida `SetLimit(n)` sigʻimi n boʻlgan buferli kanal yaratadi. `g.Go` joy olish uchun yuboradi; funksiya tugaganda qabul qilish joyni boʻshatadi. Bu detal versiyaga tegishli, API vaʼdasi esa faol ishlar chegarasidir.

`SetLimit(0)` yangi goroutine qoʻshilishiga yoʻl bermaydi. Limit oʻzgarmasa, keyingi `g.Go` kutishda qoladi. Barcha goroutine oldinga siljiy olmasa, runtime deadlock bilan toʻxtatishi mumkin. Serverda boshqa ish yoki taymerlar bor boʻlsa, bitta osilgan chaqiruv uchun bunday xabar kafolatlanmaydi. Manfiy limit cheklovni olib tashlaydi. Faol ishlar bor paytda limitni oʻzgartirmang.

`errgroup` panicni ushlamaydi. Ushlanmagan panic butun dasturni toʻxtatadi; `Wait` uni oddiy `error`ga aylantirmaydi.

## Koʻp uchraydigan xatolar

1. **Oddiy Group xatoda hammasini toʻxtatadi deb oʻylash.** Yuqoridagi 06-bosqichda 1000 soʻrov ketdi. Tuzatish — `WithContext`, ishlar ichida uning contexti va signalni tekshiradigan funksiya.
2. **`Wait`dan keyin guruh contextini ishlatish.** 08-bosqichdagi `saveStocks(ctx, stocks)` haqiqiy `saqlash: context canceled` xatosini berdi. 09-bosqichda `gctx` alohida, saqlashga tashqi `ctx` berilgan.
3. **Hamma goroutine bitta slice'ga `append` qilishi.** Indekslar alohida boʻlishi qoidasini buzadi. Natija uzunligini oldindan ajrating, har ish faqat `stocks[i]`ga yozsin; oʻqishdan oldin `Wait`.
4. **Limitni tekshirmaslik.** Nol bilan yangi ish boshlanmaydi; manfiy son chegarani olib tashlaydi. Vazifada `limit < 1` boʻlsa, `SetLimit`gacha `errBadLimit` qaytaring.
5. **0 chiqish kodini muvaffaqiyatli import deb oʻqish.** Bu laboratoriyaning `main` funksiyasi xatoni chiqaradi, `os.Exit(1)` chaqirmaydi. Natija qatoridagi `xato`ni ham oʻqing.

```go
func fetchPrices(ctx context.Context, ids []int64, limit int) ([]int64, error) {
	if limit < 1 {
		return nil, errBadLimit
	}
	prices := make([]int64, len(ids))
	g, gctx := errgroup.WithContext(ctx)
	g.SetLimit(limit)
	for i, id := range ids {
		g.Go(func() error {
			p, err := checkPrice(gctx, id)

	if err := g.Wait(); err != nil {
		return nil, err
	}
	return prices, nil
}
```
