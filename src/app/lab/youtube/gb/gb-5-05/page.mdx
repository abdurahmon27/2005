## Ulanish: manzil va pool

Postgres mijozi SQL yuboradigan dastur: oldin `psql`, endi Go. `pgx` protokolni bajaradi; `pgxpool` ulanishlarni qayta ishlatadi. Har ulanish Postgres jarayoniga tegishli. Har HTTP soʻrov uchun yangi pool yaratmang.

| Bosqich | Pool | Postgres |
|---|---|---|
| soʻrovdan oldin | boʻsh ulanish bor | SQL kutmoqda |
| `QueryRow` / `Query` | ulanish olindi | SQL bajarilmoqda |
| natija yopildi | ulanish qaytdi | keyingi buyruqni kutmoqda |

Quyidagi buyruqlar shu nusxa ichida bajariladi. `export` dasturlar koʻradigan **muhit oʻzgaruvchisi**ni beradi. `CGO_ENABLED=0` C integratsiyasini oʻchiradi, `GOTOOLCHAIN` Go versiyasini tanlaydi. `up -d --wait` bazani fonda ishga tushirib, tayyor boʻlishini kutadi. `5475` band boʻlsa, nusxadagi `ports` va URL portini bir xil boʻsh raqamga almashtiring.

```bash
export CGO_ENABLED=0
export GOTOOLCHAIN=go1.27.4
docker compose up -d --wait
```

`exec db psql` — `db` servisida SQL mijozi. Har `-f` konteynerdagi `/lab/` ostidan bitta faylni oʻqiydi. Yangi bazaga toʻrtta fayl qoʻllanadi:


Bu laboratoriya uchun sunʼiy ulanish URL'i. `postgres` — protokol; `bozor:bozor-lab` — foydalanuvchi va laboratoriya paroli. `localhost:5475` — kompyuterdagi manzil va port, oxirgi `bozor` — baza. `os.Getenv("DATABASE_URL")` shu satrni oʻqiydi.

## Bitta qator: QueryRow va Scan

`Product` — bitta mahsulot yozuvi. `ID`, `Price`: `bigint` → `int64`; `Name`: `text` → `string`; `Stock`: `integer` → `int`. Narx tiyinda. `active` tanlanmaydi. `Store` pool manzilini saqlaydi; `*pgxpool.Pool` — pointer turi.

```go filename="_video/stages/02-store.go" showLineNumbers
package main

import (
	"context"

	"github.com/jackc/pgx/v5/pgxpool"
)

type Product struct {
	ID    int64
	Name  string
	Price int64
	Stock int
}

type Store struct {
	pool *pgxpool.Pool
}

func (s *Store) Get(ctx context.Context, id int64) (Product, error) {
	var p Product
	err := s.pool.QueryRow(ctx,
		"SELECT id, name, price, stock FROM products WHERE id = $1", id).
		Scan(&p.ID, &p.Name, &p.Price, &p.Stock)
	return p, err
}
```

| Qatorlar | Nima qiladi |
|---|---|
| 1–7 | paket va kerakli importlar |
| 9–14 | `Product` nomli struct, toʻrtta maydon |
| 16–18 | `Store` ichidagi `pool` maydoni |
| 20 | `s *Store` receiver; `ctx`, `id` kiradi; `Product`, `error` chiqadi |
| 21 | natija uchun nol qiymatli `p` |
| 22–24 | `QueryRow` bitta qator kutadi; `Scan` ustunlarni manzillarga yozadi |
| 25–26 | mahsulot va xatoni chaqiruvchiga qaytaradi |

`$1` — birinchi parametr oʻrni; keyingi `id` argumenti uning qiymati. Qiymat SQL matniga qoʻshilmaydi. Shu ajratish SQL injection'ni, yaʼni kiruvchi matn SQL tuzilishini oʻzgartirishini, toʻxtatadi. Foydalanuvchi qiymati uchun `fmt.Sprintf` ishlatmang. `&p.ID` — maydon manzili; `Scan` tartibi `SELECT` tartibi bilan bir xil. Qator oxiridagi nuqta metod chaqiruvini keyingi qatorda davom ettiradi.

| Holat | `p.ID` | `p.Name` | `p.Price` | `p.Stock` |
|---|---|---|---|---|
| `var p Product` | 0 | `""` | 0 | 0 |
| `Scan`dan keyin | 1 | `"olma"` | 1200000 | 40 |

```go filename="_video/stages/03-main-get1.go" showLineNumbers

	"context"
	"fmt"
	"os"
```

## Koʻp qator: Query, Next, Close va Err

`ListActive` faol mahsulotlarni `id` tartibida qaytaradi. `Query` natijasi — `Rows`, yaʼni ketma-ket oʻqiladigan qatorlar. Quyida metodning asosiy qismi:

```go
	rows, err := s.pool.Query(ctx,
		"SELECT id, name, price, stock FROM products WHERE active ORDER BY id")
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	out := []Product{}
	for rows.Next() {
		var p Product
		if err := rows.Scan(&p.ID, &p.Name, &p.Price, &p.Stock); err != nil {
			return nil, err
		}
		out = append(out, p)
	}
	return out, rows.Err()
```

1–5: soʻrov va uning xatosi; `WHERE active` rost qatorlarni tanlaydi. 6: `defer rows.Close()` erta qaytishda ham natijani yopadi. 7: `out := []Product{}` — boʻsh, `nil` boʻlmagan slice. 8: `Next()` navbatdagi qatorga oʻtadi. 9–12: har qatorni alohida `p`ga oʻqiydi, xatoda qaytadi. 13: `append` natijaga mahsulot qoʻshadi. 15: slice va `rows.Err()` qaytadi.

| Amal | Joriy qator | `out` | Ulanish |
|---|---|---|---|
| `Query` | hali yoʻq | `[]` | band |
| `Next` → `Scan` | olma | `[olma]` | band |
| keyingi uch qator | non, choy, oʻrik | `[olma non choy oʻrik]` | band |
| `Next` → false | tugadi | oʻzgarmaydi | qaytdi |

`non` — non, `choy` — choy, `oʻrik` — oʻrik nomlari. `Next() == false` oddiy tugash yoki oʻqish xatosi boʻlishi mumkin. `rows.Err()` shu farqni beradi. `Next` oxirigacha oʻqilganda avtomatik yopadi; `defer Close` erta chiqishni ham qoplaydi. Natijani yopish ulanishni pool'ga qaytaradi.

## Buyurtma jami: SUM, NULL va COALESCE

GB-5.04'dagi SQL endi Go'dan chaqiriladi. `quantity * unit_price` — miqdor karra birlik narxi. `SUM(bigint)` natijasi `numeric`: aniq oʻnli son. pgx butun va `int64`ga sigʻadigan qiymatni oʻqiydi; kasr yoki sigʻmaydigan qiymat xato beradi.

```go
func (s *Store) OrderTotal(ctx context.Context, orderID int64) (int64, error) {
	var total int64
	err := s.pool.QueryRow(ctx,
		"SELECT SUM(quantity*unit_price) FROM order_items WHERE order_id = $1", orderID).
		Scan(&total)
	return total, err
}
```

`orderID` — buyurtma raqami, `total` — jami. 2-qator uni nol qiladi; 3–5 soʻrov javobini manziliga yozadi; 6 son va xatoni qaytaradi. Agregat `GROUP BY`siz bitta natija qatori beradi. Kirish qatori yoʻq boʻlsa, uning qiymati `NULL`.

Buyurtma 99 yoʻq. `SUM` nima beradi? **A)** 0 · **B)** `NULL` · **C)** `pgx.ErrNoRows`.

<details>
<summary>Javob</summary>

**B.** Natijada qator bor, lekin qiymat `NULL`. `int64` yoʻqlikni saqlay olmaydi. 1-buyurtma: `2*1200000 + 3*400000 = 3600000`. Nol va “qator yoʻq” javoblari ikki xil tushunchani aralashtiradi.

</details>

Bosqichdagi `main` avval `Get`, keyin roʻyxat, keyin ikkita `OrderTotal` natijasini chiqaradi. Toʻliq `main.go` keyingi boʻlimda. Bu safar xatoli `SUM` versiyasini oʻrnating:

`<nil>` — xato yoʻq. `dest[0]` — birinchi qabul qiluvchi, `col: sum` — SQL ustuni. `cannot scan NULL into *int64` — `NULL`ni `int64` manziliga yozib boʻlmaydi. Bosilgan `0` — boshlangʻich qiymat; xato borligi uchun uni hisoblangan jami deb olmang.

`COALESCE` birinchi `NULL` boʻlmagan qiymatni oladi: yigʻindi yoʻq boʻlsa 0. Bu laboratoriyaning qoidasi: 99 uchun ham jami 0. Buyurtma mavjudligini tekshirish alohida talab boʻlsa, uni alohida soʻrov bilan tekshiring.

## Muddat: context.WithTimeout

`context.Background()` muddatsiz. `WithTimeout` undan yangi `qctx` va resurslarni boʻshatadigan `cancel` funksiyasini oladi. Quyidagi toʻliq video bosqichi sekin soʻrovni ataylab yaratadi:

```go filename="_video/stages/06-main-slow.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"os"
	"time"

	"github.com/jackc/pgx/v5/pgxpool"
)

func main() {
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
	if err != nil {
		fmt.Fprintln(os.Stderr, "pool:", err)
		os.Exit(1)
	}
	defer pool.Close()

	qctx, cancel := context.WithTimeout(ctx, 2*time.Second)
	defer cancel()
	start := time.Now()
	_, err = pool.Exec(qctx, "SELECT pg_sleep(5)")
	fmt.Println("xato:", err, time.Since(start).Round(time.Second))
}
```

Yangi 21–25-qatorlar: `2*time.Second` — ikki soniya; `defer cancel()` resurslarni boʻshatadi. `time.Now()` boshlanish vaqtini saqlaydi. `Exec`da javob qatorlari oʻqilmaydi; `_` buyruq natijasini tashlaydi, `err` saqlanadi. `pg_sleep(5)` bazada besh soniya kutadi. `time.Since(start)` oʻtgan vaqt, `Round(time.Second)` soniyaga yaxlitlaydi.

Nima chiqadi? **A)** 5 soniya, xatosiz · **B)** taxminan 2 soniya, muddat xatosi · **C)** darhol 0.

<details>
<summary>Javob</summary>

**B.** `qctx`ning muddati besh soniyalik soʻrovdan oldin tugaydi. `cancel()`ni faqat muddat tugashiga ishonib tashlab ketmang.

</details>

```console
$ cp _video/stages/06-main-slow.go main.go
$ go run .
xato: timeout: context deadline exceeded 2s
```

`timeout: context deadline exceeded` — context muddati tugadi. Videoda ham, bu qayta yugurishda ham yaxlitlangan vaqt 2s: 5s kutishning taxminan 40 foizi. Yuk va rejalashtirish aniq vaqtni oʻzgartiradi. Muhimi, baza uyqusi emas, context kutishni chegaraladi; yigʻish vaqti bu oʻlchovga kirmaydi.

| Vaqt | `qctx` | Go kutishi |
|---|---|---|
| 0s | faol | soʻrovda |
| taxminan 2s | muddati tugadi | xato qaytadi |
| undan keyin | tugagan | shu context bilan keyingi soʻrov ham xato |

## Yakuniy fayllar va ishga tushirish

Bu — kursdagi toʻliq `store.go`: yuqoridagi metodlar, `COALESCE` tuzatishi va vazifadagi ikkita yozilmagan metod. Yangi qismlar oxirida: `ByName` va `Cheapest` hozir ataylab xato qaytaradi.

```go filename="store.go" showLineNumbers
package main

import (
	"context"
	"errors"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

// Product — products jadvalidagi bitta qator (narx tiyinda, GB-1.03).
type Product struct {
	ID    int64
	Name  string
	Price int64
	Stock int
}

// ErrNotFound — jadvalda bunday mahsulot yoʻq (GB-2.08: chaqiruvchi errors.Is bilan tekshiradi).
var ErrNotFound = errors.New("mahsulot topilmadi")

// Store — products jadvaliga Go'dan kirish. pool bir vaqtda koʻp goroutine'dan ishlatilishi mumkin.
type Store struct {
	pool *pgxpool.Pool
}

// Get id boʻyicha bitta mahsulotni oʻqiydi; yoʻq boʻlsa ErrNotFound.
func (s *Store) Get(ctx context.Context, id int64) (Product, error) {
	var p Product
	err := s.pool.QueryRow(ctx,
		"SELECT id, name, price, stock FROM products WHERE id = $1", id).
		Scan(&p.ID, &p.Name, &p.Price, &p.Stock)
	if errors.Is(err, pgx.ErrNoRows) {
		return Product{}, ErrNotFound
	}
	return p, err
}

// ListActive faol mahsulotlarni id tartibida oʻqiydi.
func (s *Store) ListActive(ctx context.Context) ([]Product, error) {
	rows, err := s.pool.Query(ctx,
		"SELECT id, name, price, stock FROM products WHERE active ORDER BY id")
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	out := []Product{}
	for rows.Next() {
		var p Product
		if err := rows.Scan(&p.ID, &p.Name, &p.Price, &p.Stock); err != nil {
			return nil, err
		}
		out = append(out, p)
	}
	return out, rows.Err()
}

// OrderTotal bitta buyurtmaning jami summasini (tiyinda) hisoblaydi. Buyurtma yoʻq boʻlsa SUM NULL beradi: COALESCE uni nolga aylantiradi.
func (s *Store) OrderTotal(ctx context.Context, orderID int64) (int64, error) {
	var total int64
	err := s.pool.QueryRow(ctx,
		"SELECT COALESCE(SUM(quantity*unit_price), 0) FROM order_items WHERE order_id = $1", orderID).
		Scan(&total)
	return total, err
}
```

## Chuqurroq (ixtiyoriy): bazadagi soʻrov bekor boʻldimi?

pgx v5.13.0 bu xato yoʻlida ulanishni yopayotib asinxron `CancelRequest` ham yuboradi. Alohida 30s uyqu tajribasida qaytish 2.001s boʻldi. Darhol, 0.5s va 1s keyin kuzatuv ulanishi 0 faol uyqu soʻrovini koʻrdi. Bu — oʻz qayta tekshiruvimiz. Bekor qilish kafolat emas: “odatda” soʻzi zarur; xato qaytgan payt SQL darhol toʻxtadi deb hisoblamang.

Probe kodi kurs papkasiga kirmaydi; bu qoʻshimcha oʻlchovning toʻliq dasturi quyida. `observer` kuzatadi, `victim` sekin soʻrovni bajaradi. `application_name` uni ajratadi. `pg_stat_activity`dagi `active` qatorlarni `count(*)` sanaydi; `time.Sleep` kuzatish oraligʻini beradi.

Quyidagi qoʻshimcha dastur kurs papkasida yoʻq. Uni ishchi nusxada `probe/main.go` sifatida saqlang. `mkdir -p probe` shu papkani tayyorlaydi:

```bash
mkdir -p probe
```

```go
package main

import (
	"context"
	"fmt"
	"os"
	"time"

	"github.com/jackc/pgx/v5/pgxpool"
)

func main() {
	ctx := context.Background()
	observer, err := pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
	if err != nil {
		panic(err)
	}
	defer observer.Close()
	var kind string
	err = observer.QueryRow(ctx, "SELECT pg_typeof(SUM(quantity*unit_price))::text FROM order_items WHERE order_id=1").Scan(&kind)
	fmt.Println("SUM type:", kind, err)
	for _, sql := range []string{"SELECT 1.5::numeric", "SELECT 9223372036854775808::numeric"} {
		var n int64
		err := observer.QueryRow(ctx, sql).Scan(&n)
		fmt.Println(sql, n, err)
	}
	victim, err := pgxpool.New(ctx, os.Getenv("DATABASE_URL")+"?application_name=gb505_timeout_probe")
	if err != nil {
		panic(err)
	}
	defer victim.Close()
	qctx, cancel := context.WithTimeout(ctx, 2*time.Second)
	defer cancel()
	start := time.Now()
	_, err = victim.Exec(qctx, "SELECT pg_sleep(30)")
	fmt.Printf("timeout elapsed=%.3fs err=%v\n", time.Since(start).Seconds(), err)
	for _, wait := range []time.Duration{0, 500 * time.Millisecond, 500 * time.Millisecond} {
		time.Sleep(wait)
		var n int
		err := observer.QueryRow(ctx, "SELECT count(*) FROM pg_stat_activity WHERE application_name='gb505_timeout_probe' AND state='active' AND query LIKE '%pg_sleep%'").Scan(&n)
		fmt.Println("active sleepers:", n, err)
	}
	fmt.Println("default MaxConns:", observer.Config().MaxConns)
}
```

`pg_typeof(... )::text` SQL turini matn qilib oʻqiydi. Ikkita qoʻshimcha SQL `numeric`ning kasr va diapazon xatolarini tekshiradi. `%v` xatoni, `%.3f` soniyani uch kasr bilan chiqaradi. `pool.Config().MaxConns` shu mashinada 12 boʻldi. Standart chegara — 4 va `runtime.NumCPU()`ning kattasi; bu tavsiya etilgan sozlama degani emas.

`numeric <nil>` — SQL turi va xatosiz javob. `cannot convert … to integer` — kasr butun songa oʻqilmadi. `out of range for int64` — butun son ham diapazonga sigʻmadi. `active sleepers: 0` — kuzatuv paytida shu dasturga tegishli faol uyqu yoʻq. ## Koʻp uchraydigan xatolar

**1. `rows.Close`ni unutib, qatorlarni yarmida tashlash.** Bu darsning asosiy xatosi. Quyidagi toʻliq dastur birinchi nomdan keyin qaytadi. `firstName` — birinchi mahsulot nomini oʻqish:

```go filename="_video/leak/main.go" showLineNumbers
package main

import (
	"context"
	"fmt"
	"os"
	"time"

	"github.com/jackc/pgx/v5/pgxpool"
)

// firstName: birinchi mahsulotning nomi
func firstName(ctx context.Context, pool *pgxpool.Pool) (string, error) {
	rows, err := pool.Query(ctx, "SELECT name FROM products ORDER BY id")
	if err != nil {
		return "", err
	}
	if !rows.Next() {
		return "", rows.Err()
	}
	var name string
	err = rows.Scan(&name)
	return name, err
}

func main() {
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
	if err != nil {
		fmt.Fprintln(os.Stderr, "pool:", err)
		os.Exit(1)
	}
	qctx, cancel := context.WithTimeout(ctx, 2*time.Second)
	defer cancel()
	for i := 1; i <= 2; i++ {
		start := time.Now()
		name, err := firstName(qctx, pool)
		fmt.Println(i, name, err, time.Since(start).Round(time.Second))
	}
}
```

Yangi qatorlar: `firstName`dagi `!rows.Next()` — keyingi qator yoʻq; shunda `rows.Err()` qaytadi. `err = rows.Scan(&name)` yangi oʻzgaruvchi yaratmaydi, borini oʻzgartiradi. `main`dagi `for` ikki marta chaqiradi va har chaqiruv vaqtini chiqaradi. Bu buzilgan tajribada `pool.Close()` yoʻq: u qaytmagan ulanishni kutardi. Tuzatishdan keyin pool'ni ham yoping.

Pool'da faqat bitta ulanish boʻlsin. Ikkinchi chaqiruv nima qiladi? **A)** tez tugaydi · **B)** boʻsh ulanishni kutadi, muddatda xato · **C)** yangi ulanish ochadi.

<details>
<summary>Javob</summary>

**B.** Birinchi `Rows` hali ochiq va yagona ulanishni ushlab turibdi. `pool_max_conns=1` ikkinchi ulanishni taqiqlaydi. Soʻrov bu safar SQL bajarilishini emas, ulanishni kutdi.

</details>

URL'dagi `?pool_max_conns=1` pool chegarasi. Bir tirnoq shell'ning `?` belgisini talqin qilishini toʻxtatadi. `mkdir -p` ishchi `leak` papkasini tayyorlaydi:

```console
$ mkdir -p leak
$ cp _video/leak/main.go leak/main.go
$ export DATABASE_URL='postgres://bozor:bozor-lab@localhost:5475/bozor?pool_max_conns=1'
$ go run ./leak
1 olma <nil> 0s
2  context deadline exceeded 2s
```

Ikkinchi satrda boʻsh nom sabab ikki boʻshliq bor. `context deadline exceeded` — muddat tugadi. Videoda ham, qayta tekshiruvda ham 0s/2s; 0s soniyaga yaxlitlangan, mutlaq nol emas. Muddat boʻlmasa, chaqiruv kutishda qoladi.

Tuzatish — `Query` xatosi tekshirilgandan keyin bitta qator:

```go
defer rows.Close()
```

Tuzatishdan keyin ikkinchi chaqiruv? **A)** `olma`, xatosiz · **B)** 2s muddat xatosi · **C)** panic.

<details>
<summary>Javob</summary>

**A.** Birinchi funksiya qaytishida `defer` natijani yopib, yagona ulanishni qaytardi.

</details>

```console

$ go run ./leak
```

| Holat | Birinchi chaqiruvdan keyin | Ikkinchi chaqiruv |
|---|---|---|
| `Close` yoʻq | ulanish band | kutadi, 2s xato |
| `defer Close` bor | ulanish boʻsh | olma, 0s |

**2. `Next` false boʻlsa, har doim muvaffaqiyat deb olish.** Yuqoridagi `ListActive`dagi `rows.Err()`ni qaytaring: tarmoq yoki muddat xatosi yoʻqolmasin.

**3. `NULL`dan keyingi 0'ni jami deb olish.** “Buyurtma jami” boʻlimidagi haqiqiy `Scan` xatosini tekshiring. Nol qoidasini SQL'da `COALESCE` bilan belgilang.

**4. `$1` oʻrniga matn qoʻshish.** `name` va `n`ni SQL'dan keyingi argument sifatida bering. Parametr qiymat oʻrnini egallaydi, jadval yoki ustun nomini emas.

**5. Tugagan `qctx`ni qayta ishlatish.** Muddat barcha chaqiruvlar uchun bir xil tugash vaqti. Keyingi mustaqil operatsiya uchun yangi context oling.
