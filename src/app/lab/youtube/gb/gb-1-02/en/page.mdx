## What you will learn

We add the first product to bozor: apples (`olma`), 12,000 soʻm per kilogram, 40 packs in stock. If text ends up in
the code by accident where the price should be, who catches that mistake before the program even runs?

**One idea:** a variable is a place in memory with a name and one type. If it is declared without a value, it holds
the zero value of that type. `=` writes a new value into it, but its type does not change after the declaration,
and the compiler checks this at build time.

By the end of this lesson you will:

- declare a variable with `var` and with the short form `:=`, and know when to choose which;
- choose one of the four basic types: `int`, `float64`, `string`, `bool`;
- say in advance what a variable without a value holds (the zero value);
- read three real compiler messages by `file:line:column` and fix the mistake.

The three core new words of this lesson:

| Word | Plain meaning | Term |
|---|---|---|
| variable declaration | open a place in memory with a name and a type: `var name string` or `stock := 40` | variable declaration |
| type | what kind of value it is: a whole number, a fractional number, text, or `true`/`false` | type (`int`, `float64`, `string`, `bool`) |
| zero value | the starting value of a variable that was given no value: `""`, `0`, `false` | zero value |

There are also two helper terms: **assignment** — writing a new value into an existing variable with one `=`; and
three compiler messages about types: `invalid operation … mismatched types`, `no new variables on left side of :=`
and `cannot use … as int value in assignment`. Each one gets its own section below.

## `var`: declaring with a name and a type

The program has to remember the product's name. For that you declare a **variable**: a place with a name is set
aside in memory, and only a value of one type is written into it. The Go specification defines it the same way: a
variable is a storage location for holding a value, and its type determines which values are allowed.

On line 9 of `main.go` we write:

```go
	var name string
```

Read the line from left to right: *a variable named `name`, of type `string`.*

| Part | What it is |
|---|---|
| `var` | a keyword: "I am declaring a variable". It comes from the word *variable* |
| `name` | the name we chose. We use it later to read and change the value |
| `string` | the type: text |

We choose English names; the bozor code keeps the same names in later lessons. Two more declarations:

```go
	var name string
	var price int
	var active bool
```

- `price` — the price of one kilogram, type `int`: a **whole number**. For now we keep the price in whole soʻm. The
  right choice for money is the topic of the next lesson ([GB-1.03](/lab/youtube/gb/gb-1-03/en)).
- `active` — whether the product is on sale. Its type is `bool`, and its value is only `true` (yes) or `false` (no).

Now we print all three. You can pass several values to `fmt.Println` inside the parentheses, separated by commas.
It writes them all on one line, puts one space between them, and moves to a new line at the end. The documentation
says the same: "Spaces are always added between operands and a newline is appended."

```go
	fmt.Println(name, price, active)
```

Note: we have not given a value to any variable yet. At this point the file looks like this (the first 12 lines of

## Zero value: when no value is given

This is a rule of Go, and its name is **zero value**. If a variable is declared without a value, Go fills its memory
with the zero value of its type. So in Go every variable always has a definite starting value.

| Type | Zero value | What `fmt.Println` shows |
|---|---|---|
| `string` | `""` (empty text) | nothing |
| `int` | `0` | `0` |
| `float64` | `0` | `0` |
| `bool` | `false` | `false` |

Memory after the three lines:

| Line | Code | `name` (`string`) | `price` (`int`) | `active` (`bool`) |
|---|---|---|---|---|
| 9 | `var name string` | `""` | — | — |
| 10 | `var price int` | `""` | `0` | — |
| 11 | `var active bool` | `""` | `0` | `false` |

"—" means the variable is not declared yet.

**This is common in a backend.** Later, bozor reads products from a JSON file. If the file has no price, there is
no error: `price` stays at its zero value, `0`. Zero is not an error for the compiler, but it is not a valid price.
That is why such a value is checked separately: this happens in [GB-1.05](/lab/youtube/gb/gb-1-05/en), with `if`.

## Assignment: one `=`

Now we fill in the record. A single equals sign is **assignment**. Go writes the value on the right into the memory
of the variable on the left, and the old value is gone. Lines 14–16 of `main.go`:

```go
	name = "olma"
	price = 12000
	active = true
```

| Line | Code | `name` | `price` | `active` |
|---|---|---|---|---|
| after 11 | (zero value) | `""` | `0` | `false` |
| 14 | `name = "olma"` | `"olma"` | `0` | `false` |
| 15 | `price = 12000` | `"olma"` | `12000` | `false` |
| 16 | `active = true` | `"olma"` | `12000` | `true` |

`name` gets `olma` in quotes, `price` gets the whole number 12,000, and `active` gets `true`. A single `=` does not
create a new variable; it only writes into an existing one. You will need this rule in the section "Mid-lesson
question".

## `:=`: the short declaration

If the value is already known when you declare the variable, you give it right away. `stock` holds how many packs
are in stock. You can write it in three ways:

```go
var stock int = 40
var stock = 40
stock := 40
```

| Form | What is written | Where the type comes from |
|---|---|---|
| `var stock int = 40` | `var`, name, type, value | written: `int` |
| `var stock = 40` | no type written | from the value: `40` is a whole number, so Go decides the type is `int` |
| `stock := 40` | the shortest form, "colon equals" | from the value: `int` |

The third is a **short variable declaration**: declaration and assignment in one step, with the type taken from the
value. All three lines give the same result: `stock` of type `int` with the value `40`. A whole number gives the type
`int`; a number with a dot (`1.5`) gives `float64`. The specification calls this the *default type* of a number
written without quotes.

The rules of `:=`:

- **One name, one declaration.** You cannot declare the same name twice in one place, so the code contains only one
  of the three forms.
- **`:=` works only inside a function.** `main` is a function too. Outside a function, a variable is declared only
  with `var`.
- **The usual choice:** if you have a value, use `:=`; if the variable should start at its zero value, use `var`.
  Google's Go Style Guide recommends the same.

We add two short declarations to `main.go` (lines 17–18):

```go
	stock := 40
	weight := 1.5
```

`stock` is 40, type `int`. `weight` is the weight of one pack, 1.5 kilograms. A number with a dot is a
**floating-point number**, and Go gives it the type `float64`. The `64` at the end: this value takes 64 bits; sizes
come in the next lesson.

| Line | Code | `stock` (`int`) | `weight` (`float64`) |
|---|---|---|---|
| 17 | `stock := 40` | `40` | — |
| 18 | `weight := 1.5` | `40` | `1.5` |

All four basic types of today are now in the file: `string`, `int`, `bool`, `float64`.

## A type error: `int` and `float64`

Now we compute the price of one pack: 12,000 per kilo, a pack of 1.5 kilos. We add this as line 20 (after line 19,
before the closing `}`). `*` is multiplication:

```go
	fmt.Println(name, price, active, stock, weight)
	fmt.Println(price * weight)
}
```

`price` is `int`, `weight` is `float64`. What happens?

**A)** `18000` · **B)** `12000` · **C)** a compile error

<details>
<summary>Answer</summary>

**C: a compile error.**

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:20:14: invalid operation: price * weight (mismatched types int and float64)
```

We read the message as in the previous lesson: `main.go`, line 20, column 14, where `price` starts (the Tab is
column 1, `fmt.Println(` takes columns 2–13). *invalid operation*: the operation is not allowed. The reason is in
the parentheses: *mismatched types int and float64*, the types do not match.

- If you chose **A**, you thought Go would turn `price` into a floating-point number by itself.
- If you chose **B**, you thought `1.5` would be cut down to a whole number (`1`).

Go does neither.

</details>

**Why it is an error.** In Go, in an operation on two variables, both must have the same type. Numbers written
without quotes (for example `price * 2`) are an exception; we look at them in the next lesson. The compiler does
not turn an `int` into a `float64` by itself. The official Go FAQ gives the reason: the convenience of automatic
conversion between numeric types is outweighed by the confusion it causes. Changing a type explicitly is called a
**conversion**; we write one in [GB-1.03](/lab/youtube/gb/gb-1-03/en). In short, Go does not mix types silently. So we delete
this line for now.

## Mid-lesson question: `stock := stock - 1`

One pack was sold, and someone wrote this as line 20 (`-` is subtraction):

```go
	fmt.Println(name, price, active, stock, weight)
	stock := stock - 1
}
```

But `stock` was already declared on line 17 as `stock := 40`. What does this line do?

**A)** `stock` is now 39 · **B)** a compile error · **C)** a second `stock`: 39, the first one 40

<details>
<summary>Answer</summary>

**B: a compile error.**

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:20:8: no new variables on left side of :=
```

The message points to line 20, column 8, where `:=` stands (the Tab is column 1, `stock` is 2–6, the space is 7).
*no new variables on left side of :=*: there is no new variable to the left of `:=`. `:=` declares, and `stock` is
already declared.

- If you chose **A**, you thought `:=` writes into an existing variable: that is the job of `=`.
- If you chose **C**, you thought one name can be declared twice in one place. That is not allowed either.

If there are several names on the left, it is enough for at least one of them to be new. You will need this rule in
[GB-1.07](/lab/youtube/gb/gb-1-07/en).

</details>

**The fix.** You write into an existing variable with a single `=`:

```go
	stock = stock - 1
```

Go first computes the right side, then writes the result into the variable on the left:

| Step | What happens | `stock` |
|---|---|---|
| after line 17 | `stock := 40` | `40` |
| line 20, step 1 | the right side is computed: `stock - 1` = 40 − 1 = 39 | `40` |
| line 20, step 2 | 39 is written into the memory of `stock` | `39` |

The fixed line builds. The output does not change, because `stock` is not printed after line 20:

```console
$ go run .
bozor ishga tushdi
versiya: 0.1.0
 0 false
olma 12000 true 40 1.5
```

We keep this line for the task and delete it for now.

## Text instead of a number: `price = "12000"`

Now the situation from the start of the lesson: text instead of a price. The value was copied from somewhere with
its quotes, and line 15 is now:

```go
	price = "12000"
```

It looks like a number, but the quotes make it text. And `price` was declared as `int` on line 10. Who catches this
mistake?

**A)** the customer, while the program runs · **B)** the compiler, at build time · **C)** nobody: Go turns the text
into a number

<details>
<summary>Answer</summary>

**B: the compiler, at build time.**

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:15:10: cannot use "12000" (untyped string constant) as int value in assignment
```

The message points to line 15, column 10, where the opening quote is. *cannot use "12000"*: this value cannot be
used; *as int value in assignment*: as an `int` value in an assignment. *untyped string constant* in the parentheses
is the compiler's name for text in quotes; we cover constants in [GB-1.03](/lab/youtube/gb/gb-1-03/en). The main point: the type
of `price` was `int` at its declaration, and it does not change.

- If you chose **A**, you thought the type is checked while the program runs. In Go the compiler checks the type,
  before the program starts.
- If you chose **C**, you thought Go turns text into a number by itself. Go does not do that, just as with
  `int * float64`.

</details>

**The fix:** remove the quotes, so line 15 is `price = 12000` again. This mistake reached nobody, because the
compiler stopped and no executable file was built at all. But the compiler does not see text that a user types into
the running program; we check that in [GB-1.07](/lab/youtube/gb/gb-1-07/en).

In short, a variable's type is set once at its declaration, and the compiler compares every value with that type.

## Common mistakes

**1. Writing to an existing variable with `:=`.** The most common one, and the task has exactly this trap. If you
start the task like this (after line 20):

```go
	sold := 3
	stock := stock - sold
	fmt.Println(name, stock)
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:22:8: no new variables on left side of :=
```

Line 22, column 8: `stock` was declared on line 17, and `:=` needs a new name (section "Mid-lesson question").
**Fix:** `stock = stock - sold`.

**2. Declaring and not using.** If you write `sold := 3` and never use it:

```go
	fmt.Println(name, price, active, stock, weight)

	sold := 3
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:21:2: declared and not used: sold
```

*declared and not used: sold*: `sold` was declared but never used. This is not a warning but an error: the program
does not build. **Fix:** use the variable or delete the declaration.

**3. `:=` outside a function.** If you write `stock := 40` before `func main()`, at the file level:

```go
package main

import "fmt"

stock := 40

func main() {
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:5:1: syntax error: non-declaration statement outside function body
```

*syntax error: non-declaration statement outside function body*: a statement that is not a declaration stands
outside a function body. `:=` does not work outside a function. **Fix:** `var stock = 40`, or move the declaration
into `main`. (This example is not in the video; we ran it separately.)

**4. Mixing types, and a number in quotes.** `price * weight` (`int` and `float64`) and `price = "12000"` are both
compile errors. The full walk-through is in the sections "A type error" and "Text instead of a number".

**5. A silent bug: reducing the stock too early.** If you write the new lines of the task *before* line 19, the
program builds and gives no error, but line 4 changes: `olma 12000 true 37 1.5`. `go test` catches it:

```console
$ go test
--- FAIL: TestQatorlar (0.00s)
    main_test.go:64: 4-qator «olma 12000 true 40 1.5» boʻlishi kerak, hozir «olma 12000 true 37 1.5»
FAIL
exit status 1
FAIL	github.com/abdurahmon27/bozor	0.002s
```

(The test message is in Uzbek: "line 4 must be «…», now it is «…»".) **Fix:** write the new lines **after** the
existing `fmt.Println(name, price, active, stock, weight)` line. (The time in the last column is a little different
on every run.)

The test checks three things: the five output lines, a `sold := …` declaration, and that the new value of `stock` is
computed from `sold` with `=`. It also checks that the file is formatted by `go fmt`.

<summary>Answer</summary>

```go filename="solution/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int
	var active bool
	fmt.Println(name, price, active)

	name = "olma"
	price = 12000
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 3
	stock = stock - sold
	fmt.Println(name, stock)
}
```

| Line | Code | What it does |
|---|---|---|
| 21 | `sold := 3` | a new variable, short declaration, type `int` |
| 22 | `stock = stock - sold` | writes into the existing `stock`: first `40 - 3` = `37`, then `37` is written. Not `:=` |
| 23 | `fmt.Println(name, stock)` | `olma 37`; `sold` counts as used as well (on line 22) |

All three lines come after line 19, so line 4 keeps `40`. There is also the form `stock -= sold`: it is the short
form of `stock = stock - sold`, and the test accepts it too.
