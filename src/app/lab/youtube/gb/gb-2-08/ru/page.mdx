## Что вы узнаете

Метод `Sell` пакета `store` в bozor возвращает ошибки двух видов. Первая: товара с ID 9 нет в каталоге. Вторая: остатка яблок не хватает.
`main` выводит обе:

```console
$ ./_video/run.sh 00-matn go run ./cmd/bozor
mahsulot 9 topilmadi
olma: qoldiq 40, soʻralgan 41
```

Для `main` это просто два текста. Позже bozor станет сервером, и на эти две ошибки придётся отвечать по-разному. Решать по тексту можно,
но текст однажды изменится, а код сломается молча. Как вызывающий код узнаёт, **какая** это ошибка, не глядя на текст?

**Одна идея:** `error` — это интерфейс с одним методом `Error() string`. Sentinel-ошибка, созданная через `errors.New`, — одно конкретное значение,
и `==` считает её равной только ей самой. `%w` оборачивает ошибку и хранит исходную внутри нового слоя, поэтому `==` начинает давать `false`;
а `errors.Is` (по значению) и `errors.As` (по типу) проходят по слоям через `Unwrap` до конца.

К концу урока вы:

- объявите sentinel-ошибку `ErrNotFound`, добавите контекст через `fmt.Errorf("mahsulot %d: %w", …)` и найдёте её через `errors.Is`;
- объясните, почему при `%v` вместо `%w` цепочка рвётся и почему `==` и `err.(*T)` не работают на обёрнутой ошибке;
- напишете свой тип ошибки с полями (`*StockError`) и достанете из него остаток через `errors.As` и `errors.AsType`;
- соберёте несколько ошибок в одну через `errors.Join` (необязательный раздел).

Три главных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| sentinel-ошибка | значение ошибки, созданное один раз на уровне пакета; вызывающий код сравнивает с этим конкретным значением | sentinel error |
| обёртывание и цепочка | `%w` добавляет к ошибке контекст и хранит исходную ошибку внутри; обёрнутые ошибки образуют цепочку | wrapping, error chain |
| typed error | собственный тип с полями и методом `Error()`; вызывающий код находит его по типу и читает поля | typed error |

Два вспомогательных: `%T` (печатает конкретный тип значения) и `errors.Join` (собирает несколько ошибок в одну, раздел «Глубже»).

## Проблема: две ошибки, один текст

Первая программа — начало урока (`_video/00-matn`): `Sell` создаёт ошибки через `fmt.Errorf`, `main` их выводит.

```go filename="_video/00-matn/cmd/bozor/main.go" showLineNumbers
// bozor dasturi: mahsulot sotadi va xatoni turiga qarab tushuntiradi.
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	err := st.Sell(9, 1)
	fmt.Println(err)
	err = st.Sell(1, 41)
	fmt.Println(err)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `// bozor dasturi: …` | комментарий |
| 2 | `package main` | это пакет программы (GB-1.01) |
| 4–8 | `import ( … )` | `fmt` и наш пакет `store` (GB-2.06) |
| 10 | `func main() {` | отсюда начинается программа |
| 11 | `var st store.Store` | пустой каталог |
| 12–13 | `st.Add(…)` | добавляет в каталог яблоки `olma` (40 штук) и хлеб `non` (100 штук) |
| 15 | `err := st.Sell(9, 1)` | пытается продать 1 штуку товара с ID 9; в каталоге нет 9 |
| 16 | `fmt.Println(err)` | выводит текст ошибки |
| 17–18 | `err = st.Sell(1, 41)`, `fmt.Println(err)` | просит 41 яблоко при остатке 40; в ту же переменную `err` записывается новый результат |

Строки `Sell`, возвращающие две ошибки (из решения GB-2.06; пока обе через `fmt.Errorf`):

```go
	// … qoldiq yetmasa:
	return fmt.Errorf("%s: qoldiq %d, soʻralgan %d", p.Name, p.Stock, quantity)
	// … sikl tugadi, mahsulot topilmasa:
	return fmt.Errorf("mahsulot %d topilmadi", id)
```

(Слова в коде: `qoldiq` — «остаток», `soʻralgan` — «запрошено», `mahsulot … topilmadi` — «товар … не найден».)

У обоих значений тип одинаков — `error`, разница только в тексте. Если вызывающий код ищет по тексту, он привязывается к тексту. Ниже мы
дадим вызывающему коду не текст, а **значение** или **тип**.

## error — интерфейс с одним методом

Сначала сам `error`. `go doc builtin.error` — документация пакета `builtin`: он описывает заранее объявленные в Go имена
(`error`, `int`, `string`). Они видны в каждом пакете, хотя начинаются со строчной буквы.

```console
$ go doc builtin.error
package builtin // import "builtin"

type error interface {
	Error() string
}
    The error built-in interface type is the conventional interface for
    representing an error condition, with the nil value representing no error.
```

`error` — интерфейс с одним методом: `Error`, без параметров, возвращает `string`. **Любой** тип с методом `Error() string`
реализует `error` (GB-2.07: слово `implements` не пишется). Когда `fmt.Println` выводит ошибку, он вызывает этот метод
([документация fmt](https://pkg.go.dev/fmt): «If an operand implements the error interface, the Error method will be invoked»).

Простейшую ошибку создаёт `errors.New`. Вот собственный исходный код Go (пакет `errors`, строки 64–75):

```console
$ sed -n 64,75p $(go env GOROOT)/src/errors/errors.go
func New(text string) error {
	return &errorString{text}
}

// errorString is a trivial implementation of error.
type errorString struct {
	s string
}

func (e *errorString) Error() string {
	return e.s
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `func New(text string) error {` | принимает текст `text`, возвращает интерфейс `error` |
| 2 | `return &errorString{text}` | `&` и `{…}` создают новую структуру `errorString` и возвращают её **адрес** (GB-2.04). Поле в структуре одно, поэтому значение записано без имени поля, по порядку |
| 6–8 | `type errorString struct { s string }` | имя типа со строчной буквы: вне пакета `errors` оно не видно (GB-2.06). Текст лежит в поле `s` |
| 10–12 | `func (e *errorString) Error() string { return e.s }` | у `*errorString` есть метод `Error`, он возвращает текст из `s`: поэтому `*errorString` — это `error` |

Значит, внутри значения, которое вернул `errors.New("…")`, лежат **тип** `*errors.errorString` и **значение** — адрес новой структуры.
Та же конструкция, что у `w io.Writer` в вопросе выше.

## Sentinel-ошибка и ==

Вызывающему коду нужно одно конкретное значение ошибки, с которым можно сравнивать. В `store.go` добавим импорт `errors` и объявим переменную
`ErrNotFound` **вне** функций, на уровне пакета; если `Sell` не находит товар, он возвращает именно её:

```go
// ErrNotFound — katalogda bunday ID'li mahsulot yoʻq.
var ErrNotFound = errors.New("mahsulot topilmadi")

func (s *Store) Sell(id int64, quantity int) error {
	// … mahsulotni qidiradi, topsa sotadi va nil qaytaradi
	return ErrNotFound
}
```

| Строка | Код | Что делает |
|---|---|---|
| 2 | `var ErrNotFound = errors.New(…)` | переменная уровня пакета: вне функции. Она создаётся при запуске программы, до `main`, **один раз** ([Go spec: Package initialization](https://go.dev/ref/spec#Package_initialization)) |
| 2 | `ErrNotFound` | заглавная буква: её видит и `main` (GB-2.06). Начинать имя с `Err` — обычай Go |
| 4 | `func (s *Store) Sell(id int64, quantity int) error {` | как в GB-2.06: `id` — номер товара, `quantity` — количество штук |
| 6 | `return ErrNotFound` | если товар не найден, возвращается именно это значение |

(Слова в комментариях: `katalogda bunday ID'li mahsulot yoʻq` — «в каталоге нет товара с таким ID»; `mahsulotni qidiradi, topsa sotadi va nil qaytaradi` —
«ищет товар, находит — продаёт и возвращает nil».) Такая ошибка называется **sentinel error** (sentinel-ошибка): в стандартной библиотеке так устроен `io.EOF`.
В `main` сравним `err` с `store.ErrNotFound` через `==`:

```go
	err := st.Sell(9, 1)
	if err == store.ErrNotFound {
		fmt.Println("bunday mahsulot yoʻq")
	} else if err != nil {
		fmt.Println("xato:", err)
	}
```

(`bunday mahsulot yoʻq` — «такого товара нет», `xato` — «ошибка».) Два значения интерфейса равны, если равны и их **типы**, и **значения** ([Go spec: Comparison operators](https://go.dev/ref/spec#Comparison_operators)).
Если равны — пользователю понятное сообщение. Иначе, если ошибка есть (`err != nil`), печатается сама ошибка, чтобы другая ошибка не пропала.

```console
$ ./_video/run.sh 01-sentinel go run ./cmd/bozor
bunday mahsulot yoʻq
```

Теперь добавим в `main` импорт `errors` и две строки: `other` — новая ошибка, созданная через `errors.New`, её текст в точности совпадает с текстом
`ErrNotFound`. Затем выведем `other == store.ErrNotFound`:

```go
	other := errors.New("mahsulot topilmadi")
	fmt.Println(other == store.ErrNotFound)
```

Что выведет вторая строка?

**A)** `true`: текст одинаковый · **B)** `false` · **C)** ошибка компиляции: интерфейсы нельзя сравнивать

<details>
<summary>Ответ</summary>

**B: `false`.** Интерфейсы сравнивать можно: ошибки компиляции нет (**C** неверно). Сравнение смотрит не на текст, а на тип и значение.
`errors.New` при каждом вызове создаёт **новую** структуру и возвращает её адрес. Тип у обоих значений один (`*errors.errorString`),
но адреса разные. Если вы выбрали **A**, вы решили, что сравнение смотрит на текст. Это же говорит комментарий в документации `errors.New`:
«Each call to New returns a distinct error value even if the text is identical».

</details>

```console
$ ./_video/run.sh 02-yangi go run ./cmd/bozor
bunday mahsulot yoʻq
false
```

Первая строка — ошибка, которую вернул `Sell`, равна sentinel. Вторая — `false`. В памяти:

| значение | тип внутри | значение внутри (адрес) | `== store.ErrNotFound` |
|---|---|---|---|
| `store.ErrNotFound` | `*errors.errorString` | A | — |
| `err`, который вернул `Sell` | `*errors.errorString` | A | `true` (одно и то же значение) |
| `other` | `*errors.errorString` | B | `false` (тип тот же, адрес другой) |

Поэтому sentinel объявляют **один раз**, и все пользуются этой одной переменной.

## Обёртывание через %w

Проблема: сообщение говорит «товар не найден», но **какой** ID? Добавим ID. `fmt.Errorf` (GB-1.07) заполняет шаблон, как `Sprintf`, и возвращает результат как `error`.
Новое здесь — `%w`:

```go
func (s *Store) Sell(id int64, quantity int) error {
	// … mahsulotni qidiradi, topsa sotadi va nil qaytaradi
	return fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3 | `fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)` | `%d` подставляет `id` числом. `%w` в тексте подставляет текст ошибки, как `%v`, но результат **хранит исходную ошибку внутри** |
 
Это называется **обёртыванием** (по-английски **wrapping**): исходная ошибка лежит внутри новой, а в текст добавлена подробность. `main` не изменился,
он по-прежнему сравнивает через `==`. Что выведется при вызове `Sell(9, 1)`?

**A)** `bunday mahsulot yoʻq` · **B)** `xato: mahsulot 9: mahsulot topilmadi` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B.** Сработала ветка `else`: в тексте теперь есть ID, но `==` стало ложным. Почему — увидим на следующем шаге по типу внутри ошибки.
Если вы выбрали **A**, вы решили, что изменился текст, а ошибка осталась той же. **C** — код корректен, компилятор ошибок не находит.

</details>

```console
$ ./_video/run.sh 03-wrap go run ./cmd/bozor
xato: mahsulot 9: mahsulot topilmadi
```

Чтобы увидеть причину, добавим в конец `main` две строки. `%T` в `fmt.Printf` печатает конкретный тип значения; если это интерфейс —
тип внутри него. Первая строка для `err`, вторая для `ErrNotFound`:

```go
	fmt.Printf("%T\n", err)
	fmt.Printf("%T\n", store.ErrNotFound)
```

```console
$ ./_video/run.sh 04-tur go run ./cmd/bozor
xato: mahsulot 9: mahsulot topilmadi
*fmt.wrapError
*errors.errorString
```

Тип `err` — `*fmt.wrapError`, тип `ErrNotFound` — `*errors.errorString`. Если типы внутри интерфейсов разные, `==` всегда
`false`. `wrapError` — собственный тип пакета `fmt`; его исходный код:

```console
$ sed -n 70,81p $(go env GOROOT)/src/fmt/errors.go
type wrapError struct {
	msg string
	err error
}

func (e *wrapError) Error() string {
	return e.msg
}

func (e *wrapError) Unwrap() error {
	return e.err
}
```

`wrapError` хранит две вещи: готовый текст (`msg`) и исходную ошибку внутри (`err`). Метод `Unwrap` возвращает эту внутреннюю ошибку.
Каждый `%w` добавляет новый слой, слои образуют **цепочку** (error chain):

```text
err ──► *fmt.wrapError            msg: "mahsulot 9: mahsulot topilmadi"
            │ Unwrap()            err: ─────────────┐
            ▼                                       │
        *errors.errorString  ◄──────────────────────┘
        (store.ErrNotFound)
```

`errors.Is(err, target)` сравнивает ошибку с `target`; если не равна, спускается на один слой вниз через `Unwrap` и так идёт,
пока цепочка не кончится. В нашей цепочке:

| Шаг | Проверяемый слой | Тип | `== store.ErrNotFound`? |
|---|---|---|---|
| 1 | `err` | `*fmt.wrapError` | нет (тип другой) → `Unwrap` |
| 2 | ошибка внутри | `*errors.errorString` | да, адрес A → `true` |

В `main` вместо `==` пишем `errors.Is`: первый аргумент — проверяемая ошибка, второй — искомый sentinel. В `main` должен быть импорт `errors`:

```go
	err := st.Sell(9, 1)
	if errors.Is(err, store.ErrNotFound) {
		fmt.Println("bunday mahsulot yoʻq")
	} else if err != nil {
		fmt.Println("xato:", err)
	}
```

```console
$ ./_video/run.sh 05-is go run ./cmd/bozor
bunday mahsulot yoʻq
```

Ошибка обёрнута, но найдена. Вопрос: добавим в `main` ещё одну строку — в `errors.Is` вместо sentinel передаём **новую** ошибку с тем же текстом:

```go
	fmt.Println(errors.Is(err, errors.New("mahsulot topilmadi")))
```

`%w` в `Sell` стоит правильно. Что выведется?

**A)** `true`: текст одинаковый · **B)** `false` · **C)** `true`: ошибка обёрнута через `%w`

<details>
<summary>Ответ</summary>

**B: `false`.** `errors.Is` сравнивает каждый слой цепочки через `==`, а не текст. `errors.New` создал новое значение, его адрес
не равен адресу `ErrNotFound`. **A** — текст одинаковый, но `Is` на текст не смотрит. **C** — обёртывание строит цепочку, но чтобы найти ошибку, всё равно нужно
**то самое** значение. Поэтому в `Is` всегда передают сам объявленный sentinel.

</details>

```console
$ ./_video/run.sh 07-quiz go run ./cmd/bozor
bunday mahsulot yoʻq
false
```

Первая строка — результат прежнего `if`, вторая — новой строки.

## Свой тип ошибки: StockError

Теперь остаток. Пользователю хочется сказать «осталось только 40 штук», но число 40 живёт только в тексте, а искать число в тексте хрупко.
Решение: свой тип ошибки, где число лежит в **поле**. В `store.go` — структура `StockError`: название товара `Name`, остаток на складе `Stock`
и запрошенное число `Want`. У неё метод `Error`: `Sprintf` собирает текст с первого экрана.

```go
// StockError — omborda soʻralgancha mahsulot yoʻq.
type StockError struct {
	Name  string
	Stock int // omborda bor
	Want  int // soʻralgan
}

func (e *StockError) Error() string {
	return fmt.Sprintf("%s: qoldiq %d, soʻralgan %d", e.Name, e.Stock, e.Want)
}
```

(Комментарии: `omborda soʻralgancha mahsulot yoʻq` — «на складе нет столько товара, сколько запрошено»; `omborda bor` — «есть на складе»; `soʻralgan` — «запрошено».)

| Строка | Код | Что делает |
|---|---|---|
| 2–6 | `type StockError struct { … }` | три поля: `Name` (название товара), `Stock` (сколько есть на складе), `Want` (сколько запрошено) |
| 8 | `func (e *StockError) Error() string {` | метод `Error`, receiver `e`. Receiver — **указатель**: тогда `error` становится только `*StockError` (GB-2.07: методы с pointer receiver принадлежат `*T`), и тип, который ищет вызывающий код, один |
| 9 | `return fmt.Sprintf(…)` | собирает текст из полей: «olma: qoldiq 40, soʻralgan 41» |

Такая ошибка — **typed error**: у неё свой тип и поля. Теперь в `Sell` `%w` вернулся на место (`ErrNotFound` снова оборачивается через `%w`). Если остатка не хватает, `Sell` раньше создавал
ошибку через `fmt.Errorf`; вместо этого возвращаем `&StockError{…}`. Здесь `p` — указатель на найденный товар (часть с поиском сокращена):

```go
	// … p — topilgan mahsulot (*Product)
	if p.Stock < quantity {
		return &StockError{Name: p.Name, Stock: p.Stock, Want: quantity}
	}
```

(`topilgan mahsulot` — «найденный товар».) `&StockError{…}` — новая структура с заполненными полями и её **адрес**. Текст тот же, а числа теперь лежат в полях.

## errors.As: поиск по типу

В `main` просим 41 яблоко. Если ошибка есть, оборачиваем её слоем «buyurtma 7» («заказ 7»), как будто вызов сделан внутри заказа.
Сначала выводим `err`, затем type assertion из GB-2.07 — только `T` на этот раз конкретный тип: есть ли внутри `err` значение `*store.StockError`?
Результат попадает в `ok`, значение отбрасывается через `_`:

```go
	err = st.Sell(1, 41)
	if err != nil {
		err = fmt.Errorf("buyurtma 7: %w", err)
	}
	fmt.Println(err)
	_, ok := err.(*store.StockError)
	fmt.Println(ok)
```

Чему будет равно `ok`?

**A)** `true`: внутри есть `*StockError` · **B)** `false` · **C)** `panic`

<details>
<summary>Ответ</summary>

**B: `false`.** Текст собрался слой за слоем: «buyurtma 7: » и текст `Sell`. Type assertion смотрит только на **самый внешний** слой, а там
`*fmt.wrapError`. Как и `==`, на обёрнутой ошибке он не работает. **A** — ошибка внутри есть, но assertion внутрь не заглядывает. **C** — форма с comma ok
(`_, ok :=`) никогда не паникует.

</details>

```console
$ ./_video/run.sh 08-assert go run ./cmd/bozor
bunday mahsulot yoʻq
buyurtma 7: olma: qoldiq 40, soʻralgan 41
false
```

Третья строка — `false`. Вместо строк с assertion — `errors.As`:

```go
	var se *store.StockError
	if errors.As(err, &se) {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
	} else if err != nil {
		fmt.Println("xato:", err)
	}
```

(`faqat %d dona qoldi` — «осталось только %d штук».)

| Строка | Код | Что делает |
|---|---|---|
| 1 | `var se *store.StockError` | переменная типа `*store.StockError`; пока `nil` |
| 2 | `errors.As(err, &se)` | идёт по цепочке, как `Is`, но ищет не **значение**, а **тип**. Какой тип — узнаёт из типа `se`. Найдя, записывает найденную ошибку в `se` и возвращает `true` |
| 2 | `&se` | `se` само указатель, а `&se` — **адрес этой переменной**: `As` может записать в неё только через адрес (GB-2.04) |
| 3 | `se.Name`, `se.Stock` | поля найденной ошибки |

`As` в цепочке:

| Шаг | Слой | Тип подходит к `*store.StockError`? |
|---|---|---|
| 1 | `err` | `*fmt.wrapError`: нет → `Unwrap` |
| 2 | ошибка внутри | `*store.StockError`: да → `se` = эта ошибка, результат `true` |

Полная программа — шаг `09-as` из видео (`main` в папке — это она же плюс функция `message`, которая нужна для задания):

```go filename="_video/09-as/cmd/bozor/main.go" showLineNumbers
// bozor dasturi: mahsulot sotadi va xatoni turiga qarab tushuntiradi.
package main

import (
	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	err := st.Sell(9, 1)
	if errors.Is(err, store.ErrNotFound) {
		fmt.Println("bunday mahsulot yoʻq")
	} else if err != nil {
		fmt.Println("xato:", err)
	}

	err = st.Sell(1, 41)
	if err != nil {
		err = fmt.Errorf("buyurtma 7: %w", err)
	}
	var se *store.StockError
	if errors.As(err, &se) {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
	} else if err != nil {
		fmt.Println("xato:", err)
	}
}
```

Новые строки: 23–26 — оборачивание ошибки `Sell(1, 41)`; 27–32 — `errors.As`. `errors.Is` в строках 16–21 — код из прошлого шага `05-is`.

В работе сервер выбирает ответ на каждую ошибку именно этими двумя функциями
([GB-4.06 · JSON на входе и выходе: лимит, валидация и ответ с ошибкой](/lab/youtube/gb#gb-4-06) и [GB-6.02 · Единые ошибки API: безопасно для клиента, полно в логе](/lab/youtube/gb#gb-6-02)).

Начиная с Go 1.26 для той же задачи есть `errors.AsType`. Он похож на comma ok у type assertion, но идёт по цепочке:
в коротком выражении `if` возвращаются `se` и `ok`, `var` и `&` не нужны.

```go
	if se, ok := errors.AsType[*store.StockError](err); ok {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
```

В квадратных скобках передаётся искомый тип: это **параметр типа**, его мы разберём в [GB-3.04 · Generics: когда параметр типа полезен](/lab/youtube/gb#gb-3-04).
Документация в большинстве случаев рекомендует `AsType` («For most uses, prefer AsType»). А `As` есть с Go 1.13,
поэтому в рабочем коде он встречается часто. Результат тот же (шаг `10-astype`):

## Глубже (необязательно): errors.Join

В заказе три строки, и мы хотим вернуть ошибки всех трёх сразу. `errors.Join` собирает ошибки в одну `error` и отбрасывает `nil`. Заменим `main`
коротким примером (`_video/11-join`):

```go filename="_video/11-join/cmd/bozor/main.go" showLineNumbers

package main

	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	err := errors.Join(st.Sell(9, 1), st.Sell(1, 41), st.Sell(2, 3))
	fmt.Println(err)
	fmt.Println(errors.Is(err, store.ErrNotFound))
}
```

| Строка | Код | Что делает |
|---|---|---|
| 16 | `err := errors.Join(st.Sell(9, 1), st.Sell(1, 41), st.Sell(2, 3))` | выполняет три продажи подряд, результаты собирает в одну ошибку. Третья продажа успешна (хлеб, 100 штук): возвращает `nil`, `Join` её отбрасывает |
| 17 | `fmt.Println(err)` | текст собранной ошибки |
| 18 | `errors.Is(err, store.ErrNotFound)` | проверяет каждую ошибку внутри `Join` |

Сколько строк выведет первый `Println`?

**A)** 3 · **B)** 2 · **C)** 1

<details>
<summary>Ответ</summary>

**B: 2.** `Join` соединяет тексты ошибок символом новой строки, а `nil` не входит: третья продажа ошибки не вернула. Если вы выбрали **A**, вы посчитали и `nil` за ошибку.
**C** — `Join` складывает тексты, а не выбирает первый.

</details>

## Частые ошибки

**1. «Текст одинаковый, значит, и ошибка та же».** Это самое распространённое заблуждение. Sentinel — не текст, а **одно значение**:
второй раз написанный `errors.New("mahsulot topilmadi")` создаёт новую, другую ошибку. В разделе «Sentinel-ошибка и ==» выше `other == store.ErrNotFound`
дало `false`, а в вопросе раздела «Обёртывание через %w» `errors.Is` не нашла новую ошибку. Исправление: объявите sentinel на уровне пакета **один раз** и везде используйте его.

**2. `%v` вместо `%w`.** Тихая ошибка: программа работает, результат неверный. В `Sell` заменена одна буква (`_video/06-v`):

```go
	return fmt.Errorf("mahsulot %d: %v", id, ErrNotFound)
```

`main` тот же, с `errors.Is`:

```console
$ ./_video/run.sh 06-v go run ./cmd/bozor
xato: mahsulot 9: mahsulot topilmadi
```

Снова ветка `else`, а текст буква в букву как раньше. `%v` берёт только **текст** ошибки, исходной ошибки в результате нет — цепочка рвётся, `errors.Is` ничего
не находит. `go vet` тоже этого не видит:

```console
$ ./_video/run.sh 06-v go vet ./...
```

`go vet` ничего не вывел (скрипт добавляет только собственную строку `(chiqish kodi: 0)`, она, как сказано выше, не приведена). Правило: ошибку, которую должен проверять
вызывающий код, оборачивайте через `%w`. Если внутреннюю подробность нужно скрыть намеренно — `%v`: обёрнутая ошибка становится частью вашего API
([Go blog: Whether to Wrap](https://go.dev/blog/go1.13-errors#whether-to-wrap)).

**3. `errors.As(err, se)`: нет `&`.** Этой программы нет в папке курса: я запускал её в отдельной папке с тем же `go.mod` и `internal/store`.
`cmd/bozor/main.go`:

```go
package main

import (
	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)

	err := st.Sell(1, 41)
	var se *store.StockError
	if errors.As(err, se) {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
	}
}
```

Компилятор молчит, а `go vet` ловит:

```console
$ go vet ./...
cmd/bozor/main.go:16:5: second argument to errors.As must be a non-nil pointer to either a type that implements error, or to any interface type
```

`cmd/bozor/main.go:16:5` — файл, строка 16, столбец 5: вызов `errors.As`. Сообщение: «второй аргумент `errors.As` должен быть **не-nil указателем**». Если запустить без vet:

```console
$ go run ./cmd/bozor
panic: errors: target must be a non-nil pointer

goroutine 1 [running]:
…
exit status 2
```

(Stack trace содержит пути этой машины, поэтому он обрезан.) `As` должна **записать** найденную ошибку в `se`, а `se` — это `nil`-указатель; для записи нужен адрес.
Исправление: `errors.As(err, &se)`.

**4. `var se store.StockError`: нет звёздочки.** Снова программа, которой нет в папке курса (тот же `go.mod` и `internal/store`):

```go
package main

	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)

	err := st.Sell(1, 41)
	var se store.StockError
	if errors.As(err, &se) {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
	}
}
```

```console
$ go vet ./...
cmd/bozor/main.go:16:5: second argument to errors.As must be a non-nil pointer to either a type that implements error, or to any interface type
```

Сообщение то же, причина другая: `&se` — указатель не на `*store.StockError`, а на `store.StockError`. Метод `Error` объявлен с pointer receiver, поэтому
`store.StockError` (без звёздочки) **не** `error`. Если запустить:

```console
$ go run ./cmd/bozor
panic: errors: *target must be interface or implement error

goroutine 1 [running]:
…
exit status 2
```

Исправление: `var se *store.StockError`. Правило: переменная для `errors.As` должна иметь тип, у которого есть метод `Error` (у нас `*store.StockError`).

## Проверьте себя

**1.** В `Errorf` `%v` и `%w` дают один и тот же текст. В чём разница?

<details>
<summary>Ответ</summary>

`%w` сохраняет исходную ошибку внутри результата (`*fmt.wrapError` + `Unwrap`), поэтому `errors.Is` и `errors.As` находят её в цепочке. `%v` берёт только текст:
цепочка рвётся, `errors.Is` и `errors.As` ничего не находят.

</details>

**2.** Почему в `errors.As(err, &se)` передают `&se`, а не `se`?

<details>
<summary>Ответ</summary>

`As` **записывает** найденную ошибку в `se`. Функция может записать в переменную вызывающего только через её адрес (GB-2.04), поэтому `&se`. `se` само
указатель (`*store.StockError`), а `&se` — адрес этой переменной. Если передать `se`, `As` паникует.

</details>

**3.** Из GB-2.05: в структуре `Order` есть поле `Status`, метод `Pay` с **value receiver**:

```go
func (o Order) Pay() {
	o.Status = Paid
}
```

Изменится ли `Status` у `order` после `order.Pay()`?

<details>
<summary>Ответ</summary>

Нет. Value receiver получает **копию** `order`, `Status` меняется в копии и исчезает вместе с ней. Чтобы изменить, receiver должен быть указателем: `(o *Order) Pay()`.

</details>

**4.** Предскажите вывод. Программы нет в папке курса (запущена в отдельной папке с тем же `go.mod` и `internal/store`):

```go
package main

import (
	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	e1 := fmt.Errorf("katalog: %w", store.ErrNotFound)
	e2 := fmt.Errorf("buyurtma 7: %w", e1)
	fmt.Println(e2)
	fmt.Println(errors.Is(e2, store.ErrNotFound))
	fmt.Println(e2 == e1)
	fmt.Println(errors.Is(e2, e1))
}
```

Что выведется?

<details>
<summary>Ответ</summary>

```console
$ go run ./cmd/bozor
buyurtma 7: katalog: mahsulot topilmadi
true
false
true
```

Текст собирается слой за слоем (строка 1). Цепочка из трёх слоёв: `e2` → `e1` → `ErrNotFound`; `errors.Is` дважды делает `Unwrap` и находит sentinel (строка 2).
`e2 == e1` — типы одинаковые (`*fmt.wrapError`), а адреса разные: `false` (строка 3). `errors.Is(e2, e1)` — `e1` лежит в самой цепочке, на втором слое: `true` (строка 4).

</details>

  `xato: …`. Нужно: `store.ErrNotFound` → `bunday mahsulot yoʻq`; `store.ErrBadQuantity` → `dona soni notoʻgʻri`; `*store.StockError` →
  `olma: faqat 40 dona qoldi` (название и остаток из полей); любая другая ошибка → `xato: ` + `err.Error()`. Ошибка может лежать на любом слое цепочки.

Значки уровня (🟢🟡) в папке курса отсутствуют: их поставил я. `main`, `StockError` и `ErrNotFound` не меняйте. Подсказки есть в `TASK.md`: текст `ErrBadQuantity` —
`dona soni musbat boʻlishi kerak`, в шаблоне `%w` подставляет текст ошибки, а число — `%d`. В `message` порядок такой: сначала два sentinel (`errors.Is`), затем тип
(`errors.As`), в конце всё остальное; `==` не работает, потому что ошибка обёрнута.

```go filename="solution/internal/store/store.go" showLineNumbers
// Package store bozor katalogini xotirada saqlaydi.
// U internal/ ichida: uni faqat bozor modulining oʻz kodi import qila oladi.
package store

import (
	"errors"
	"fmt"
	"slices"
)

// ErrNotFound — katalogda bunday ID'li mahsulot yoʻq.
var ErrNotFound = errors.New("mahsulot topilmadi")

// ErrBadQuantity — soʻralgan dona soni musbat emas.
var ErrBadQuantity = errors.New("dona soni musbat boʻlishi kerak")

// StockError — omborda soʻralgancha mahsulot yoʻq.
type StockError struct {
	Name  string
	Stock int // omborda bor
	Want  int // soʻralgan
}

func (e *StockError) Error() string {
	return fmt.Sprintf("%s: qoldiq %d, soʻralgan %d", e.Name, e.Stock, e.Want)
}

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// Store — xotiradagi katalog. Nol qiymati tayyor: var st store.Store.
type Store struct {
	products []Product
}

// Add katalogga mahsulot qoʻshadi va unga ID beradi (1, 2, 3 …).
func (s *Store) Add(name string, price int64, stock int) Product {
	p := Product{ID: int64(len(s.products)) + 1, Name: name, Price: price, Stock: stock}
	s.products = append(s.products, p)
	return p
}

// List katalogdagi mahsulotlarning nusxasini qaytaradi.
func (s *Store) List() []Product {
	return slices.Clone(s.products)
}

// Sell id'li mahsulotdan quantity dona sotadi va qoldiqni kamaytiradi.
// Xato boʻlsa qoldiq oʻzgarmaydi. Chaqiruvchi xatoni tekshira oladi:
// errors.Is(err, ErrNotFound) — mahsulot yoʻq,
// errors.As(err, &se) (se *StockError) — qoldiq yetmaydi,
// errors.Is(err, ErrBadQuantity) — dona soni musbat emas.
func (s *Store) Sell(id int64, quantity int) error {
	if quantity <= 0 {
		return fmt.Errorf("%w, hozir %d", ErrBadQuantity, quantity)
	}
	for i := range s.products {
		p := &s.products[i]
		if p.ID == id {
			if p.Stock < quantity {
				return &StockError{Name: p.Name, Stock: p.Stock, Want: quantity}
			}
			p.Stock -= quantity
			return nil
		}
	}
	return fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
}
```

и [`solution/cmd/bozor/main.go`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-2-08-xatolar/solution/cmd/bozor/main.go):

```go filename="solution/cmd/bozor/main.go" showLineNumbers
// bozor dasturi: mahsulot sotadi va xatoni turiga qarab tushuntiradi.
package main

import (
	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	err := st.Sell(9, 1)
	if errors.Is(err, store.ErrNotFound) {
		fmt.Println("bunday mahsulot yoʻq")
	} else if err != nil {
		fmt.Println("xato:", err)
	}

	err = st.Sell(1, 41)
	if err != nil {
		err = fmt.Errorf("buyurtma 7: %w", err)
	}
	var se *store.StockError
	if errors.As(err, &se) {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
	} else if err != nil {
		fmt.Println("xato:", err)
	}
}

// message xatoni (err nil emas) foydalanuvchiga koʻrsatiladigan matnga aylantiradi.
// Xatoni matnga aylantirish bitta joyda: keyinroq server ham shunday funksiyadan foydalanadi.
// errors.Is va errors.As butun zanjirni tekshiradi, shuning uchun qoʻshimcha
// oʻralgan xatolar («buyurtma 7: …») ham taniladi.
func message(err error) string {
	if errors.Is(err, store.ErrNotFound) {
		return "bunday mahsulot yoʻq"
	}
	if errors.Is(err, store.ErrBadQuantity) {
		return "dona soni notoʻgʻri"
	}
	var se *store.StockError
	if errors.As(err, &se) {
		return fmt.Sprintf("%s: faqat %d dona qoldi", se.Name, se.Stock)
	}
	return "xato: " + err.Error()
}
```

- `Sell`, шаг 1: `fmt.Errorf("%w, hozir %d", ErrBadQuantity, quantity)` — `%w` оборачивает и сохраняет sentinel, `%d` подставляет запрошенное число в текст.
  Теперь `errors.Is(err, ErrBadQuantity)` — `true`, а текст прежний: `dona soni musbat boʻlishi kerak, hozir 0`.
- `message`, шаг 2: порядок не важен, но всё делается через `errors.Is`/`errors.As`, а не `==`. Тест оборачивает ошибки ещё одним слоем («buyurtma 7: …»);
  `Is` и `As` проверяют всю цепочку, поэтому такие ошибки тоже распознаются. Последний `return` — прежнее поведение `xato: …`.
