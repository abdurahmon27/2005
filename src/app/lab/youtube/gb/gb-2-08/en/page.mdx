## What you will learn

The `Sell` method of the `store` package in bozor returns two kinds of error. The first: the product with ID 9 is not in the catalog.
The second: there is not enough stock of apples. `main` prints both:

```console
$ ./_video/run.sh 00-matn go run ./cmd/bozor
mahsulot 9 topilmadi
olma: qoldiq 40, soʻralgan 41
```

For `main` these are just two strings. Later bozor becomes a server, and these two errors will need two different answers. You can decide by reading the text,
but one day the text changes and the code breaks silently. How does the caller know **which** error it got without looking at the text?

**One idea:** `error` is an interface with one method, `Error() string`. A sentinel error made by `errors.New` is one exact value,
and `==` says it equals only itself. `%w` wraps an error and keeps the original inside a new layer, so `==` becomes false;
`errors.Is` (by value) and `errors.As` (by type) walk the layers with `Unwrap` to the end.

By the end of the lesson you will:

- declare the sentinel error `ErrNotFound`, add context with `fmt.Errorf("mahsulot %d: %w", …)` and find it with `errors.Is`;
- explain why `%v` instead of `%w` breaks the chain, and why `==` and `err.(*T)` do not work on a wrapped error;
- write your own error type with fields (`*StockError`) and get the stock number from it with `errors.As` and `errors.AsType`;
- combine several errors into one with `errors.Join` (an optional section).

The three core new words today:

| Word | Plain meaning | English |
|---|---|---|
| sentinel error | an error value created once at package level; the caller compares against that exact value | sentinel error |
| wrapping and chain | `%w` adds context to an error and keeps the original error inside; wrapped errors form a chain | wrapping, error chain |
| typed error | your own type with fields and an `Error()` method; the caller finds it by type and reads its fields | typed error |

Two helpers: `%T` (prints the concrete type of a value) and `errors.Join` (combines several errors into one, in the "Going deeper" section).

## error is an interface with one method

First, `error` itself. `go doc builtin.error` is the documentation of the `builtin` package: it describes the names that Go declares in advance
(`error`, `int`, `string`). They are visible in every package even though they start with a lower-case letter.

```console
$ go doc builtin.error
package builtin // import "builtin"

type error interface {
	Error() string
}
    The error built-in interface type is the conventional interface for
    representing an error condition, with the nil value representing no error.
```

`error` is an interface with one method: `Error`, no parameters, returns `string`. **Any** type with the method `Error() string`
implements `error` (GB-2.07: you never write `implements`). When `fmt.Println` prints an error, it calls this method
([fmt documentation](https://pkg.go.dev/fmt): "If an operand implements the error interface, the Error method will be invoked").

The simplest error is made by `errors.New`. Here is Go's own source (package `errors`, lines 64–75):

```console
$ sed -n 64,75p $(go env GOROOT)/src/errors/errors.go
func New(text string) error {
	return &errorString{text}
}

// errorString is a trivial implementation of error.
type errorString struct {
	s string
}

func (e *errorString) Error() string {
	return e.s
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `func New(text string) error {` | takes the text `text`, returns the `error` interface |
| 2 | `return &errorString{text}` | `&` and `{…}` create a new `errorString` struct and return its **address** (GB-2.04). The struct has one field, so the value is written without the field name, by position |
| 6–8 | `type errorString struct { s string }` | the type name is lower-case: it is not visible outside the `errors` package (GB-2.06). The text is in the field `s` |
| 10–12 | `func (e *errorString) Error() string { return e.s }` | `*errorString` has an `Error` method that returns the text in `s`: so `*errorString` is an `error` |

So the value that `errors.New("…")` returned holds the **type** `*errors.errorString` and the **value**: the address of a new struct.
It is the same structure as `w io.Writer` in the question above.

## The sentinel error and ==

The caller needs one exact error value to compare with. In `store.go` we add the `errors` import and declare the variable
`ErrNotFound` **outside** any function, at package level; when `Sell` does not find the product, it returns exactly this value:

```go
// ErrNotFound — katalogda bunday ID'li mahsulot yoʻq.
var ErrNotFound = errors.New("mahsulot topilmadi")

func (s *Store) Sell(id int64, quantity int) error {
	// … mahsulotni qidiradi, topsa sotadi va nil qaytaradi
	return ErrNotFound
}
```

| Line | Code | What it does |
|---|---|---|
| 2 | `var ErrNotFound = errors.New(…)` | a package-level variable: outside a function. It is created when the program starts, before `main`, **once** ([Go spec: Package initialization](https://go.dev/ref/spec#Package_initialization)) |
| 2 | `ErrNotFound` | capital letter: `main` sees it too (GB-2.06). Starting the name with `Err` is the Go convention |
| 4 | `func (s *Store) Sell(id int64, quantity int) error {` | as in GB-2.06: `id` is the product number, `quantity` is the number of pieces |
| 6 | `return ErrNotFound` | if the product is not found, exactly this value is returned |

(Words in the comments: `katalogda bunday ID'li mahsulot yoʻq` — "there is no product with this ID in the catalog"; `mahsulotni qidiradi, topsa sotadi va nil qaytaradi` —
"looks for the product, sells it if found and returns nil".) Such an error is called a **sentinel error**: `io.EOF` in the standard library is one.
In `main` we compare `err` with `store.ErrNotFound` using `==`:

```go
	err := st.Sell(9, 1)
	if err == store.ErrNotFound {
		fmt.Println("bunday mahsulot yoʻq")
	} else if err != nil {
		fmt.Println("xato:", err)
	}
```

(`bunday mahsulot yoʻq` — "there is no such product", `xato` — "error".) Two interface values are equal if both their **types** and their **values** are equal ([Go spec: Comparison operators](https://go.dev/ref/spec#Comparison_operators)).
If they are equal, the user gets a clear message. Otherwise, if there is an error (`err != nil`), the error itself is printed, so no other error is lost.

```console
$ ./_video/run.sh 01-sentinel go run ./cmd/bozor
bunday mahsulot yoʻq
```

Now we add the `errors` import to `main` and two lines: `other` is a new error made with `errors.New`, and its text is exactly the same as the text of
`ErrNotFound`. Then we print `other == store.ErrNotFound`:

```go
	other := errors.New("mahsulot topilmadi")
	fmt.Println(other == store.ErrNotFound)
```

What does the second line print?

**A)** `true`: the text is the same · **B)** `false` · **C)** a compile error: interfaces cannot be compared

<details>
<summary>Answer</summary>

**B: `false`.** Interfaces can be compared: there is no compile error (**C** is wrong). The comparison looks at type and value, not at text.
`errors.New` creates a **new** struct on every call and returns its address. Both values have the same type (`*errors.errorString`),
but the addresses differ. If you chose **A**, you thought the comparison looks at the text. The doc comment of `errors.New` says the same:
"Each call to New returns a distinct error value even if the text is identical".

</details>

```console
$ ./_video/run.sh 02-yangi go run ./cmd/bozor
bunday mahsulot yoʻq
false
```

The first line: the error that `Sell` returned equals the sentinel. The second line: `false`. In memory:

| value | type inside | value inside (address) | `== store.ErrNotFound` |
|---|---|---|---|
| `store.ErrNotFound` | `*errors.errorString` | A | — |
| the `err` that `Sell` returned | `*errors.errorString` | A | `true` (the same value) |
| `other` | `*errors.errorString` | B | `false` (same type, different address) |

That is why a sentinel is declared **once** and everybody uses that one variable.

## Wrapping with %w

The problem: the message says "product not found", but **which** ID? We add the ID. `fmt.Errorf` (GB-1.07) fills a template like `Sprintf` and returns the result as an `error`.
The new thing is `%w`:

```go
func (s *Store) Sell(id int64, quantity int) error {
	// … mahsulotni qidiradi, topsa sotadi va nil qaytaradi
	return fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
}
```

| Line | Code | What it does |
|---|---|---|
| 3 | `fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)` | `%d` puts `id` in as a number. In the text `%w` puts the text of the error like `%v`, but the result **keeps the original error inside** |
 
This is called **wrapping**: the original error is inside the new one, and the text has more detail. `main` did not change,
it still compares with `==`. What is printed when `Sell(9, 1)` is called?

**A)** `bunday mahsulot yoʻq` · **B)** `xato: mahsulot 9: mahsulot topilmadi` · **C)** a compile error

<details>
<summary>Answer</summary>

**B.** The `else` branch ran: the text now has the ID, but `==` became false. Why — we see in the next step from the type inside the error.
If you chose **A**, you thought only the text changed and the error stayed the same. **C** — the code is correct, the compiler finds no error.

</details>

```console
$ ./_video/run.sh 03-wrap go run ./cmd/bozor
xato: mahsulot 9: mahsulot topilmadi
```

To see the reason, we add two lines at the end of `main`. `%T` in `fmt.Printf` prints the concrete type of a value; if it is an interface,
the type inside it. The first line is for `err`, the second for `ErrNotFound`:

```go
	fmt.Printf("%T\n", err)
	fmt.Printf("%T\n", store.ErrNotFound)
```

```console
$ ./_video/run.sh 04-tur go run ./cmd/bozor
xato: mahsulot 9: mahsulot topilmadi
*fmt.wrapError
*errors.errorString
```

The type of `err` is `*fmt.wrapError`, the type of `ErrNotFound` is `*errors.errorString`. If the types inside the interfaces differ, `==` is always
`false`. `wrapError` is a type of the `fmt` package itself; its source:

```console
$ sed -n 70,81p $(go env GOROOT)/src/fmt/errors.go
type wrapError struct {
	msg string
	err error
}

func (e *wrapError) Error() string {
	return e.msg
}

func (e *wrapError) Unwrap() error {
	return e.err
}
```

`wrapError` keeps two things: the ready text (`msg`) and the original error inside (`err`). The `Unwrap` method returns this inner error.
Each `%w` adds a new layer, and the layers form a **chain** (error chain):

```text
err ──► *fmt.wrapError            msg: "mahsulot 9: mahsulot topilmadi"
            │ Unwrap()            err: ─────────────┐
            ▼                                       │
        *errors.errorString  ◄──────────────────────┘
        (store.ErrNotFound)
```

`errors.Is(err, target)` compares the error with `target`; if they are not equal, it goes one layer down with `Unwrap` and continues
until the chain ends. In our chain:

| Step | Layer checked | Type | `== store.ErrNotFound`? |
|---|---|---|---|
| 1 | `err` | `*fmt.wrapError` | no (different type) → `Unwrap` |
| 2 | the error inside | `*errors.errorString` | yes, address A → `true` |

In `main` we write `errors.Is` instead of `==`: the first argument is the error to check, the second is the sentinel we look for. `main` must import `errors`:

```go
	err := st.Sell(9, 1)
	if errors.Is(err, store.ErrNotFound) {
		fmt.Println("bunday mahsulot yoʻq")
	} else if err != nil {
		fmt.Println("xato:", err)
	}
```

```console
$ ./_video/run.sh 05-is go run ./cmd/bozor
bunday mahsulot yoʻq
```

The error is wrapped, but it was found. A question: we add one more line to `main` — we give `errors.Is` a **new** error with the same text instead of the sentinel:

```go
	fmt.Println(errors.Is(err, errors.New("mahsulot topilmadi")))
```

`%w` in `Sell` is correct. What is printed?

**A)** `true`: the text is the same · **B)** `false` · **C)** `true`: the error is wrapped with `%w`

<details>
<summary>Answer</summary>

**B: `false`.** `errors.Is` compares each layer of the chain with `==`, not the text. `errors.New` made a new value, its address
is not equal to the address of `ErrNotFound`. **A** — the text is the same, but `Is` does not look at text. **C** — wrapping builds the chain, but to find an error you still need
**that very** value. That is why `Is` always gets the declared sentinel itself.

</details>

```console
$ ./_video/run.sh 07-quiz go run ./cmd/bozor
bunday mahsulot yoʻq
false
```

The first line is the result of the earlier `if`, the second is from the new line.

## Our own error type: StockError

Now the stock. We want to tell the user "only 40 pieces left", but the number 40 lives only in the text, and searching a text for a number is fragile.
The solution: our own error type where the number sits in a **field**. In `store.go`, a `StockError` struct: the product name `Name`, the stock in the warehouse `Stock`
and the requested number `Want`. It gets an `Error` method: `Sprintf` builds the text from the first screen.

```go
// StockError — omborda soʻralgancha mahsulot yoʻq.
type StockError struct {
	Name  string
	Stock int // omborda bor
	Want  int // soʻralgan
}

func (e *StockError) Error() string {
	return fmt.Sprintf("%s: qoldiq %d, soʻralgan %d", e.Name, e.Stock, e.Want)
}
```

(Comments: `omborda soʻralgancha mahsulot yoʻq` — "the warehouse does not have as much product as requested"; `omborda bor` — "in the warehouse"; `soʻralgan` — "requested".)

| Line | Code | What it does |
|---|---|---|
| 2–6 | `type StockError struct { … }` | three fields: `Name` (product name), `Stock` (how many are in the warehouse), `Want` (how many were requested) |
| 8 | `func (e *StockError) Error() string {` | the `Error` method, receiver `e`. The receiver is a **pointer**: then only `*StockError` is an `error` (GB-2.07: methods with a pointer receiver belong to `*T`), and the type the caller looks for is just one |
| 9 | `return fmt.Sprintf(…)` | builds the text from the fields: "olma: qoldiq 40, soʻralgan 41" |

Such an error is a **typed error**: it has its own type and fields. Now `%w` is back in `Sell` (`ErrNotFound` is wrapped with `%w` again). When the stock is not enough, `Sell` used to build
the error with `fmt.Errorf`; instead we return `&StockError{…}`. Here `p` is a pointer to the found product (the search part is shortened):

```go
	// … p — topilgan mahsulot (*Product)
	if p.Stock < quantity {
		return &StockError{Name: p.Name, Stock: p.Stock, Want: quantity}
	}
```

(`topilgan mahsulot` — "the found product".) `&StockError{…}` is a new struct with filled fields and its **address**. The text is the same, and the numbers now sit in the fields.

## errors.As: search by type

In `main` we ask for 41 apples. If there is an error, we wrap it with the layer "buyurtma 7" ("order 7"), as if the call were made inside an order.
First we print `err`, then the type assertion from GB-2.07 — only `T` is now a concrete type: is there a `*store.StockError` inside `err`?
The result goes to `ok`, the value is thrown away with `_`:

```go
	err = st.Sell(1, 41)
	if err != nil {
		err = fmt.Errorf("buyurtma 7: %w", err)
	}
	fmt.Println(err)
	_, ok := err.(*store.StockError)
	fmt.Println(ok)
```

What will `ok` be?

**A)** `true`: there is a `*StockError` inside · **B)** `false` · **C)** `panic`

<details>
<summary>Answer</summary>

**B: `false`.** The text was built layer by layer: "buyurtma 7: " and the text of `Sell`. A type assertion looks only at the **outermost** layer, and there it finds
`*fmt.wrapError`. Like `==`, it does not work on a wrapped error. **A** — the error is inside, but the assertion does not look inside. **C** — the comma-ok form
(`_, ok :=`) never panics.

</details>

```console
$ ./_video/run.sh 08-assert go run ./cmd/bozor
bunday mahsulot yoʻq
buyurtma 7: olma: qoldiq 40, soʻralgan 41
false
```

The third line is `false`. Instead of the assertion lines we use `errors.As`:

```go
	var se *store.StockError
	if errors.As(err, &se) {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
	} else if err != nil {
		fmt.Println("xato:", err)
	}
```

(`faqat %d dona qoldi` — "only %d pieces left".)

| Line | Code | What it does |
|---|---|---|
| 1 | `var se *store.StockError` | a variable of type `*store.StockError`; `nil` for now |
| 2 | `errors.As(err, &se)` | walks the chain like `Is`, but searches for a **type**, not a **value**. Which type — it learns from the type of `se`. When it finds one, it writes the found error into `se` and returns `true` |
| 2 | `&se` | `se` is itself a pointer, and `&se` is the **address of this variable**: `As` can write into it only through the address (GB-2.04) |
| 3 | `se.Name`, `se.Stock` | the fields of the found error |

`As` on the chain:

| Step | Layer | Does the type match `*store.StockError`? |
|---|---|---|
| 1 | `err` | `*fmt.wrapError`: no → `Unwrap` |
| 2 | the error inside | `*store.StockError`: yes → `se` = this error, result `true` |

The full program is the `09-as` step of the video (the `main` in the folder is this one plus the `message` function, which belongs to the task):

```go filename="_video/09-as/cmd/bozor/main.go" showLineNumbers
// bozor dasturi: mahsulot sotadi va xatoni turiga qarab tushuntiradi.
package main

import (
	"errors"
	"fmt"
```

## Going deeper (optional): errors.Join

An order has three lines and we want to return the errors of all three at once. `errors.Join` combines errors into one `error` and drops the `nil` values. We replace `main`
with a short example (`_video/11-join`):

```go filename="_video/11-join/cmd/bozor/main.go" showLineNumbers
// bozor dasturi: mahsulot sotadi va xatoni turiga qarab tushuntiradi.
package main

import (
	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	err := errors.Join(st.Sell(9, 1), st.Sell(1, 41), st.Sell(2, 3))
	fmt.Println(err)
	fmt.Println(errors.Is(err, store.ErrNotFound))
}
```

| Line | Code | What it does |
|---|---|---|
| 16 | `err := errors.Join(st.Sell(9, 1), st.Sell(1, 41), st.Sell(2, 3))` | runs three sales one after another and combines the results into one error. The third sale succeeds (bread, 100 pieces): it returns `nil`, and `Join` drops it |
| 17 | `fmt.Println(err)` | the text of the combined error |
| 18 | `errors.Is(err, store.ErrNotFound)` | checks every error inside `Join` |

How many lines does the first `Println` print?

**A)** 3 · **B)** 2 · **C)** 1

<details>
<summary>Answer</summary>

**B: 2.** `Join` joins the texts of the errors with a newline, and `nil` is not there: the third sale returned no error. If you chose **A**, you counted `nil` as an error too.
**C** — `Join` adds the texts together, it does not pick the first one.

</details>

```console
$ ./_video/run.sh 11-join go run ./cmd/bozor
mahsulot 9: mahsulot topilmadi
olma: qoldiq 40, soʻralgan 41
true
```

Two errors on separate lines, the third is missing. `errors.Is` checks every error inside `Join` (and so does `errors.As`), so the second `Println` is `true`.
`Join` exists since Go 1.20.

## Common mistakes

**1. "The text is the same, so the error is the same."** This is the most common wrong idea. A sentinel is not a text, it is **one value**:
writing `errors.New("mahsulot topilmadi")` a second time creates a new, different error. In the section "The sentinel error and ==" above, `other == store.ErrNotFound`
gave `false`, and in the question of the section "Wrapping with %w", `errors.Is` did not find the new error. The fix: declare the sentinel at package level **once** and use it everywhere.

**2. `%v` instead of `%w`.** A silent bug: the program runs, the result is wrong. One letter was changed in `Sell` (`_video/06-v`):

```go
	return fmt.Errorf("mahsulot %d: %v", id, ErrNotFound)
```

`main` is the same, with `errors.Is`:

```console
$ ./_video/run.sh 06-v go run ./cmd/bozor
xato: mahsulot 9: mahsulot topilmadi
```

Again the `else` branch, and the text is letter for letter as before. `%v` takes only the **text** of the error, the original error is not in the result — the chain breaks, and `errors.Is` finds
nothing. `go vet` does not see it either:

```console
$ ./_video/run.sh 06-v go vet ./...
```

`go vet` printed nothing (the script adds only its own line `(chiqish kodi: 0)`, which, as said above, is left out). The rule: wrap with `%w` the error that the caller has to check.
If you want to hide an internal detail on purpose, use `%v`: a wrapped error becomes part of your API
([Go blog: Whether to Wrap](https://go.dev/blog/go1.13-errors#whether-to-wrap)).

**3. `errors.As(err, se)`: no `&`.** This program is not in the course folder: I ran it in a separate folder with the same `go.mod` and `internal/store`.
`cmd/bozor/main.go`:

```go
package main

import (
	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)

	err := st.Sell(1, 41)
	var se *store.StockError
	if errors.As(err, se) {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
	}
}
```

The compiler is silent, and `go vet` catches it:

```console
$ go vet ./...
cmd/bozor/main.go:16:5: second argument to errors.As must be a non-nil pointer to either a type that implements error, or to any interface type
```

`cmd/bozor/main.go:16:5` is the file, line 16, column 5: the call of `errors.As`. The message: "the second argument of `errors.As` must be a **non-nil pointer**". Without vet, running it gives:

```console
$ go run ./cmd/bozor
panic: errors: target must be a non-nil pointer

goroutine 1 [running]:
…
exit status 2
```

(The stack trace contains paths of this machine, so it is cut.) `As` has to **write** the found error into `se`, and `se` is a `nil` pointer; writing needs an address.
The fix: `errors.As(err, &se)`.

**4. `var se store.StockError`: no star.** Again a program that is not in the course folder (the same `go.mod` and `internal/store`):

```go
package main

import (
	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)

	err := st.Sell(1, 41)
	var se store.StockError
	if errors.As(err, &se) {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
	}
}
```

```console
$ go vet ./...
cmd/bozor/main.go:16:5: second argument to errors.As must be a non-nil pointer to either a type that implements error, or to any interface type
```

The message is the same as before, the reason is different: `&se` is a pointer not to `*store.StockError` but to `store.StockError`. The `Error` method has a pointer receiver, so
`store.StockError` (without the star) is **not** an `error`. Running it gives:

```console
$ go run ./cmd/bozor
panic: errors: *target must be interface or implement error

goroutine 1 [running]:
…
exit status 2
```

The fix: `var se *store.StockError`. The rule: the variable for `errors.As` must have a type that has the `Error` method (for us `*store.StockError`).

## Check yourself

**1.** In `Errorf`, `%v` and `%w` give the same text. What is the difference?

<details>
<summary>Answer</summary>

`%w` keeps the original error inside the result (`*fmt.wrapError` + `Unwrap`), so `errors.Is` and `errors.As` find it in the chain. `%v` takes only the text:
the chain breaks, and `errors.Is` and `errors.As` find nothing.

</details>

**2.** Why do we pass `&se` and not `se` to `errors.As(err, &se)`?

<details>
<summary>Answer</summary>

`As` **writes** the found error into `se`. A function can write into the caller's variable only through its address (GB-2.04), so `&se`. `se` is itself
a pointer (`*store.StockError`), and `&se` is the address of this variable. If you pass `se`, `As` panics.

</details>

**3.** From GB-2.05: the `Order` struct has a `Status` field, and the `Pay` method has a **value receiver**:

```go
func (o Order) Pay() {
	o.Status = Paid
}
```

Does the `Status` of `order` change after `order.Pay()`?

<details>
<summary>Answer</summary>

No. A value receiver gets a **copy** of `order`, `Status` changes in the copy and disappears with it. To change it, the receiver must be a pointer: `(o *Order) Pay()`.

</details>

**4.** Predict the output. The program is not in the course folder (it was run in a separate folder with the same `go.mod` and `internal/store`):

```go
package main

import (
	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	e1 := fmt.Errorf("katalog: %w", store.ErrNotFound)
	e2 := fmt.Errorf("buyurtma 7: %w", e1)
	fmt.Println(e2)
	fmt.Println(errors.Is(e2, store.ErrNotFound))
	fmt.Println(e2 == e1)
	fmt.Println(errors.Is(e2, e1))
}
```

What is printed?

<details>
<summary>Answer</summary>

```console
$ go run ./cmd/bozor
buyurtma 7: katalog: mahsulot topilmadi
true
false
true
```

The text is built layer by layer (line 1). The chain has three layers: `e2` → `e1` → `ErrNotFound`; `errors.Is` calls `Unwrap` twice and finds the sentinel (line 2).
`e2 == e1` — the types are the same (`*fmt.wrapError`), but the addresses differ: `false` (line 3). `errors.Is(e2, e1)` — `e1` is in the chain itself, on the second layer: `true` (line 4).

</details>

```go filename="solution/internal/store/store.go" showLineNumbers
// Package store bozor katalogini xotirada saqlaydi.
// U internal/ ichida: uni faqat bozor modulining oʻz kodi import qila oladi.
package store

import (
	"errors"
	"fmt"
	"slices"
)

// ErrNotFound — katalogda bunday ID'li mahsulot yoʻq.
var ErrNotFound = errors.New("mahsulot topilmadi")

// ErrBadQuantity — soʻralgan dona soni musbat emas.
var ErrBadQuantity = errors.New("dona soni musbat boʻlishi kerak")

// StockError — omborda soʻralgancha mahsulot yoʻq.
type StockError struct {
	Name  string
	Stock int // omborda bor
	Want  int // soʻralgan
}

func (e *StockError) Error() string {
	return fmt.Sprintf("%s: qoldiq %d, soʻralgan %d", e.Name, e.Stock, e.Want)
}

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// Store — xotiradagi katalog. Nol qiymati tayyor: var st store.Store.
type Store struct {
	products []Product
}

// Add katalogga mahsulot qoʻshadi va unga ID beradi (1, 2, 3 …).
func (s *Store) Add(name string, price int64, stock int) Product {
	p := Product{ID: int64(len(s.products)) + 1, Name: name, Price: price, Stock: stock}
	s.products = append(s.products, p)
	return p
}

// List katalogdagi mahsulotlarning nusxasini qaytaradi.
func (s *Store) List() []Product {
	return slices.Clone(s.products)
}

// Sell id'li mahsulotdan quantity dona sotadi va qoldiqni kamaytiradi.
// Xato boʻlsa qoldiq oʻzgarmaydi. Chaqiruvchi xatoni tekshira oladi:
// errors.Is(err, ErrNotFound) — mahsulot yoʻq,
// errors.As(err, &se) (se *StockError) — qoldiq yetmaydi,
// errors.Is(err, ErrBadQuantity) — dona soni musbat emas.
func (s *Store) Sell(id int64, quantity int) error {
	if quantity <= 0 {
		return fmt.Errorf("%w, hozir %d", ErrBadQuantity, quantity)
	}
	for i := range s.products {
		p := &s.products[i]
		if p.ID == id {
			if p.Stock < quantity {
				return &StockError{Name: p.Name, Stock: p.Stock, Want: quantity}
			}
			p.Stock -= quantity
			return nil
		}
	}
	return fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
}
```

and [`solution/cmd/bozor/main.go`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-2-08-xatolar/solution/cmd/bozor/main.go):

```go filename="solution/cmd/bozor/main.go" showLineNumbers
package main

import (
	"errors"
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	err := st.Sell(9, 1)
	if errors.Is(err, store.ErrNotFound) {
		fmt.Println("bunday mahsulot yoʻq")
	} else if err != nil {
		fmt.Println("xato:", err)
	}

	err = st.Sell(1, 41)
	if err != nil {
		err = fmt.Errorf("buyurtma 7: %w", err)
	}
	var se *store.StockError
	if errors.As(err, &se) {
		fmt.Printf("%s: faqat %d dona qoldi\n", se.Name, se.Stock)
	} else if err != nil {
		fmt.Println("xato:", err)
	}

// message xatoni (err nil emas) foydalanuvchiga koʻrsatiladigan matnga aylantiradi.
// Xatoni matnga aylantirish bitta joyda: keyinroq server ham shunday funksiyadan foydalanadi.
// errors.Is va errors.As butun zanjirni tekshiradi, shuning uchun qoʻshimcha
// oʻralgan xatolar («buyurtma 7: …») ham taniladi.
func message(err error) string {
	if errors.Is(err, store.ErrNotFound) {
		return "bunday mahsulot yoʻq"
	}
	if errors.Is(err, store.ErrBadQuantity) {
		return "dona soni notoʻgʻri"
	}
	var se *store.StockError
	if errors.As(err, &se) {
		return fmt.Sprintf("%s: faqat %d dona qoldi", se.Name, se.Stock)
	}
	return "xato: " + err.Error()
}
```

  Now `errors.Is(err, ErrBadQuantity)` is `true`, and the text is as before: `dona soni musbat boʻlishi kerak, hozir 0`.
- `message`, step 2: the order does not matter, but everything is done with `errors.Is`/`errors.As`, not `==`. The test wraps errors with one more layer ("buyurtma 7: …");
  `Is` and `As` check the whole chain, so those are recognised too. The last `return` is the old `xato: …` behaviour.
