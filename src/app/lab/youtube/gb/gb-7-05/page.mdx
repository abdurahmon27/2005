## Nimani oʻrganasiz

bozorda buyurtmalar qoldiqni kamaytiradi, importer esa uni toʻldiradi. Bitta map'ni himoyalash uchun mutex ishlatamizmi yoki barcha oʻzgarishni bitta goroutine'ga topshiramizmi?

**Bitta gʻoya:** holatga har murojaatni bitta qulf ostida bajaring yoki holatga faqat bitta goroutine tegsin. Ikkalasi ham toʻgʻri; tanlovni kodning soddaligi va aynan sizning yukingizdagi oʻlchov asoslasin.

Darsdan keyin siz:

- bir xil `Sell` amalini mutex va soʻrov–javob kanallari bilan yozasiz;
- `-race` natijasini tushuntirib, ikki usulning xarajatini oʻlchaysiz;
- `atomic.Int64` bilan sanaysiz va ikki atomik amal nega bir butun qadam emasligini koʻrsatasiz;
- `OwnedStore.Stock`ni qulfsiz yozib, vazifa testlarini oʻtkazasiz.

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| egasi goroutine | holatga faqat oʻzi tegadi; boshqalar unga soʻrov yuboradi | owner goroutine |
| oʻtkazuvchanlikning teskarisi | jami vaqt / tugagan amallar soni; bu yerda oʻlchaydigan sonimiz | inverse throughput |
| atomik amal | boshqa goroutine'larga bitta boʻlinmas amal sifatida koʻrinadigan oʻqish yoki oʻzgartirish | atomic operation |

Yordamchi: **race condition** — natijaning goroutine'lar bajarilish tartibiga notoʻgʻri bogʻlanishi. U har doim data race degani emas. `ns` — nanosekund; `µs` — mikrosekund, 1000 ns.

## Tekshirish va kamaytirish bir qulf ostida

GB-4.07'dagi doʻkonni soddalashtiramiz: `stock` — mahsulot ID'sidan dona soniga `map[int64]int`. `Sell(id, n)` yetarli qoldiq boʻlsa `n` dona sotadi. Bu laboratoriyada `n > 0` deb olamiz; kirishni tekshirish bu metodlarga qoʻshilmagan.

`LockedStore` qulfli doʻkon. Uning `Sell` metodi, toʻliq fayldan parcha:

```go
func (s *LockedStore) Sell(id int64, n int) bool {
	s.mu.Lock()
	defer s.mu.Unlock()
	if s.stock[id] < n {
		return false
	}
	s.stock[id] -= n
	return true
}
```

| Qator | Nima qiladi |
|---|---|
| 1 | `s *LockedStore` — asl doʻkon bilan ishlaydigan koʻrsatkichli receiver; `id`, `n` parametrlar; natija `bool` |
| 2 | `s.mu.Lock()` shu qulf boʻshaguncha kutadi, keyin uni oladi |
| 3 | `defer` metoddan har qanday qaytishda `Unlock` bajarilishini taʼminlaydi |
| 4–6 | `stock[id] < n` boʻlsa, `false` qaytadi; qoldiq oʻzgarmaydi |
| 7 | `-=` shu map qiymatini `n`ga kamaytiradi |
| 8–9 | `true` qaytaradi va metod tugaydi; kechiktirilgan `Unlock` ishlaydi |

Bir dona qolgan holat:

| Qadam | A | B | `stock[1]` |
|---|---|---|---|
| Boshlanish | qulfni oladi | `Lock`da kutadi | 1 |
| A sotadi | 1 yetadi, 0 yozadi | kutadi | 0 |
| A qulfni boʻshatadi | `true` qaytaradi | qulfni oladi | 0 |
| B tekshiradi | tugagan | 0 yetmaydi, `false` | 0 |

Faqat kamaytirishni qulflash yetmaydi: tekshirish ham shu qulf ostida boʻlsin. Oʻqiydigan boshqa metodlar ham ayni qulfdan foydalanishi kerak.

## Map'ga faqat egasi goroutine tegadi

Endi map'ga bitta goroutine tegadi. Boshqalar unga kanal orqali mahsulot ID'si, dona soni va javob kanalini yuboradi. Egasi soʻrovlarni birma-bir bajaradi.

| Bosqich | `Sell` chaqiruvchisi | Egasi `loop` |
|---|---|---|
| Soʻrovdan oldin | `reply` kanalini yaratadi | `sells`dan kutadi |
| Soʻrov | `{id, n, reply}` yuboradi | soʻrovni `r`ga oladi |
| Ish | javobni kutadi | tekshiradi va kamaytiradi |
| Javob | `bool` oladi | `r.reply`ga natija yuboradi |

`OwnedStore` — egasi goroutine ishlatadigan doʻkon. Unda map maydoni yoʻq. `NewOwnedStore` map'ni `loop`ga topshiradi; chaqiruvchi undan keyin shu map'ga tegmasligi kerak. Go bu egalik qoidasini tur tizimida majburlamaydi.

Bosqichning toʻliq `store.go` fayli, yuqoridagi mutex varianti bilan birga:

```go filename="_video/01-ikki/store.go" showLineNumbers
// bozor: bitta umumiy holat — mahsulot qoldigʻi (ID → dona) — ikki usulda himoyalangan (GB-7.05).
// LockedStore: map + sync.Mutex (GB-4.07). OwnedStore: map'ning yagona egasi boʻlgan goroutine, qolganlar
// unga channel orqali soʻrov yuboradi. Ikkalasida Sell bir xil ishlaydi.
package main

import "sync"

// LockedStore — qoldiq map'i va uni himoyalaydigan qulf. stock'ga har murojaat mu ostida.
type LockedStore struct {
	mu    sync.Mutex
	stock map[int64]int
}

// Sell id'li mahsulotdan n dona sotadi; qoldiq yetmasa false.
func (s *LockedStore) Sell(id int64, n int) bool {
	s.mu.Lock()
	defer s.mu.Unlock()
	if s.stock[id] < n {
		return false
	}
	s.stock[id] -= n
	return true
}

// sellReq — egasiga yuboriladigan sotish soʻrovi: qaysi mahsulot, necha dona va javob qaytadigan channel.
type sellReq struct {
	id    int64
	n     int
	reply chan bool
}

// OwnedStore — qoldiq map'iga faqat loop goroutine'i tegadi; Sell unga soʻrov yuboradi va javobni kutadi.
type OwnedStore struct {
	sells chan sellReq
}

// NewOwnedStore loop'ni yangi goroutine'da boshlaydi va stock map'ini unga topshiradi:
// bundan keyin chaqiruvchi bu map'ga tegmasligi kerak.
func NewOwnedStore(stock map[int64]int) *OwnedStore {
	s := &OwnedStore{sells: make(chan sellReq)}
	go s.loop(stock)
	return s
}

// loop — stock'ning yagona egasi. Soʻrovlarni birma-bir bajaradi; sells yopilganda tugaydi.
func (s *OwnedStore) loop(stock map[int64]int) {
	for r := range s.sells {
		ok := stock[r.id] >= r.n
		if ok {
			stock[r.id] -= r.n
		}
		r.reply <- ok
	}
}

// Sell id'li mahsulotdan n dona sotadi; qoldiq yetmasa false.
func (s *OwnedStore) Sell(id int64, n int) bool {
	reply := make(chan bool)
	s.sells <- sellReq{id, n, reply}
	return <-reply
}

// Close loop goroutine'ini toʻxtatadi. Close'dan keyin Sell chaqirilmaydi; Close ikkinchi marta chaqirilsa,
// yopiq channel'ni qayta yopish panic beradi (GB-7.02).
func (s *OwnedStore) Close() { close(s.sells) }
```

| Qator | Nima qiladi |
|---|---|
| 1–6 | `//` izohlar; `package main` bajariladigan paket; `sync` qulf uchun import qilinadi |
| 8–12 | `LockedStore`: `mu` qulf, `stock` ID → dona; `{}` maydonlar roʻyxatini chegaralaydi |
| 14–23 | yuqorida tushuntirilgan qulfli `Sell` |
| 25–30 | `sellReq` sotish soʻrovi: `id int64`, `n int`, `reply chan bool` |
| 32–35 | `sells chan sellReq` faqat `sellReq` qiymatlarini tashiydi |
| 37–40 | konstruktor `*OwnedStore` qaytaradi; `&` struct manzilini oladi; `make` bufer yoʻq kanal yaratadi |
| 41–43 | `go s.loop(stock)` yangi goroutine boshlaydi; `return s` doʻkon koʻrsatkichini qaytaradi |
| 45–47 | `loop` map'ni parametr sifatida oladi; `for r := range` yopilguncha soʻrov qabul qiladi |
| 48 | `ok` — ayni sotuvga qoldiq yetadimi; `>=` tenglikni ham qabul qiladi |
| 49–51 | `ok` rost boʻlsagina `stock[r.id]`dan `r.n` ayiriladi |
| 52–54 | `<-` bilan natija javob kanaliga yuboriladi; sikl va metod qavslari yopiladi |
| 56–58 | `Sell` har chaqiruv uchun alohida `reply` yaratadi |
| 59 | `sellReq{id, n, reply}` qiymatlari maydon eʼlonidagi tartibda; soʻrov `sells`ga yuboriladi |
| 60–61 | `return <-reply` javobni kutadi va uni qaytaradi |
| 63–65 | `Close` `sells`ni yopadi; `range` tugaydi va `loop` qaytadi |

Bufer yoʻq yuborish qabul qiluvchi bilan uchrashishni kutadi. `Sell` soʻrov yuborgach javobni albatta oladi, shuning uchun egasi javob yuborishda qolib ketmaydi. Bu API bekor qilinadigan chaqiruvlarni hozircha qoʻllamaydi.

`Close`ni barcha `Sell` tugagach, bir marta chaqiring. U loop tugashini kutmaydi: yopilish loop'ga chiqish imkonini beradi. Keyin yana `Sell` yoki `Stock` chaqirmang.

## Bir xil yukni tayyorlaymiz

Ikkala doʻkonda ham ID 1 uchun 800 000 dona bor. `measure` sakkiz goroutine'dan jami 800 000 chaqiruv bajaradi:

```go filename="_video/01-ikki/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

// measure op'ni sakkiz goroutine'dan jami 800 000 marta chaqiradi va bitta chaqiruvga ketgan oʻrtacha vaqtni chiqaradi.
func measure(name string, op func()) {
	start := time.Now()
	var wg sync.WaitGroup
	for range 8 {
		wg.Go(func() {
			for range 100_000 {
				op()
			}
		})
	}
	wg.Wait()
	fmt.Println(name, time.Since(start)/800_000)
}

func main() {
	locked := &LockedStore{stock: map[int64]int{1: 800_000}}
	measure("mutex", func() { locked.Sell(1, 1) })
	owned := NewOwnedStore(map[int64]int{1: 800_000})
	measure("egasi", func() { owned.Sell(1, 1) })
	owned.Close()
}
```

| Qator | Nima qiladi |
|---|---|
| 1–7 | `main` paketi; chiqarish uchun `fmt`, kutish uchun `sync`, vaqt uchun `time` |
| 9–10 | `measure(name string, op func())`: nom va parametrsiz, natijasiz funksiyani oladi |
| 11–12 | `start` boshlanish vaqtini oladi; `wg` ishlar tugashini sanaydi |
| 13–14 | `for range 8` sakkiz marta aylanadi; `wg.Go` har safar yangi goroutine boshlaydi |
| 15–19 | har goroutine `op()`ni 100 000 marta chaqiradi; `})` nomsiz funksiya va `Go` chaqiruvini tugatadi |
| 20 | `wg.Wait()` sakkiz ish tugashini kutadi |
| 21–22 | jami oʻtgan vaqtni 800 000 ga boʻlib, `name` bilan chiqaradi; `measure` tugaydi |
| 24–26 | `locked` map va nol qiymatli mutex bilan yaratiladi; nomsiz funksiya `Sell(1, 1)`ni chaqiradi |
| 27–30 | `owned` boshqa map oladi; ayni sotuv oʻlchanadi; keyin kanal yopiladi va `main` tugaydi |

`egasi` natijadagi owner varianti nomi. Bu son bitta chaqiruvning kechikishi emas: sakkiz goroutine birga ishlaydi. U **oʻtkazuvchanlikning teskarisi** — jami vaqt / amallar soni.

## Qulfsiz kodda nega data race yoʻq?

`OwnedStore`da mutex yoʻq. `-race` nima chiqaradi? **A)** `WARNING: DATA RACE` · **B)** faqat oʻlchovlar · **C)** `fatal error: concurrent map`.

<details>
<summary>Javob</summary>

**B.** Map'ga faqat `loop` tegadi. A yoki C variantini tanlasangiz, koʻp chaqiruvchi bilan map'ga koʻp murojaatchini tenglashtirgansiz. Chaqiruvchilar faqat kanallar bilan ishlaydi.

</details>

Qayta olingan Docker natijasi:

```console
$ ./_video/race.sh 01-ikki go run -race .
mutex 519ns
egasi 1.252µs
(chiqish kodi: 0)
```

Videoda `mutex 784ns`, `egasi 1.634µs` yozilgan. Bu yozib olingan sonlar; yuqorida yangi natija. `-race` qoʻshimcha tekshiruv kiritib, vaqtni oʻzgartiradi. Tezlikni keyingi oddiy ishga tushirishdan olamiz.

**Data race** uchun ayni xotira joyiga sinxronlashsiz toʻqnashuvchi murojaatlar kerak; kamida bittasi yozish boʻladi. Bu map'ga bitta goroutine tegishi asosiy himoya.

[Go xotira modeli](https://go.dev/ref/mem#chan) soʻrov–javob tartibini ham kafolatlaydi: yuborish mos qabul tugashidan oldin sinxronlanadi. Demak yuborishdan oldingi yozuvlar qabuldan keyingi kodga koʻrinadi.

Map `go s.loop(stock)`dan oldin yaratilgan. [Goroutine boshlanishi](https://go.dev/ref/mem#go) qoidasi boshlanishdan oldingi shu yozuvlarning ham koʻrinishini taʼminlaydi.

| Oldin | Sinxronlash | Keyin |
|---|---|---|
| chaqiruvchi soʻrov maydonlarini yozadi | `sells` yuborish → mos qabul tugashi | `loop` maydonlarni oʻqiydi |
| `loop` qoldiqni yangilaydi | `reply` yuborish → mos qabul tugashi | `Sell` natijani oladi |
| mutex ostidagi yangilash | shu mutex'ning `Unlock`i → keyingi `Lock` qaytishi | keyingi qulfli murojaat yangilangan holatni koʻradi |

`-race` jimligi barcha bajarilishlar uchun isbot emas. Bu yerda asos — egalik qoidasi va sinxronlash; ishga tushirish ularni amalda tekshiradi.

## Bitta sanagich uchun atomic

Sotuvlar sonini oshirishga bitta son kerak. `atomic.Int64` shu son ustidagi **atomik amal**larni beradi. Nol qiymati tayyor; birinchi ishlatishdan keyin nusxalamang. `Add(1)` boʻlinmas qoʻshadi, `Load()` oʻqiydi, `Store(v)` yangi qiymat yozadi.

Keyingi bosqichning toʻliq `main.go`si; `store.go` oʻzgarmaydi:

```go filename="_video/02-atomic/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

// measure op'ni sakkiz goroutine'dan jami 800 000 marta chaqiradi va bitta chaqiruvga ketgan oʻrtacha vaqtni chiqaradi.
func measure(name string, op func()) {
	start := time.Now()
	var wg sync.WaitGroup
	for range 8 {
		wg.Go(func() {
			for range 100_000 {
				op()
			}
		})
	}
	wg.Wait()
	fmt.Println(name, time.Since(start)/800_000)
}

// sold — sanagich: sakkiz goroutine bir vaqtda oshiradi, qulfsiz.
var sold atomic.Int64

func main() {
	locked := &LockedStore{stock: map[int64]int{1: 800_000}}
	measure("mutex", func() { locked.Sell(1, 1) })
	owned := NewOwnedStore(map[int64]int{1: 800_000})
	measure("egasi", func() { owned.Sell(1, 1) })
	owned.Close()
	measure("atomic", func() { sold.Add(1) })
	fmt.Println("sotildi:", sold.Load())
}
```

Yangi qatorlar: 6 — `sync/atomic` importi; 25–26 — `sold` sanagichi; 34 — `Add(1)`ni oʻlchash; 35 — `Load()` natijasini chiqarish. Qolgan `measure` va ikkala `Sell` oʻzgarmagan. `sotildi` — sanalgan sotuvlar yozuvi.

Oxirida nima chiqadi? **A)** doim 800 000 · **B)** yoʻqolgan qoʻshishlar sabab kamroq · **C)** data race ogohlantirishi.

<summary>Javob</summary>

## Ikki atomik amal bitta sotuv emas

Qoldiq uchun «avval oʻqi, keyin kamaytir» yozamiz. Bu ataylab xato dastur:

```go filename="_video/03-atomic-xato/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

// measure op'ni sakkiz goroutine'dan jami 800 000 marta chaqiradi va bitta chaqiruvga ketgan oʻrtacha vaqtni chiqaradi.
func measure(name string, op func()) {
	start := time.Now()
	var wg sync.WaitGroup
	for range 8 {
		wg.Go(func() {
			for range 100_000 {
				op()
			}
		})
	}
	wg.Wait()
	fmt.Println(name, time.Since(start)/800_000)
}

// stock — oʻrik qoldigʻi, 100 000 dona. Xato: tekshirish va kamaytirish — ikki alohida atomik amal.
var stock atomic.Int64

func main() {
	stock.Store(100_000)
	measure("atomic", func() {
		if stock.Load() > 0 {
			stock.Add(-1)
		}
	})
	fmt.Println("qoldiq:", stock.Load())
}
```

`measure` avvalgidek. 26-qatorda `stock` endi atomik son; 29 da `Store` 100 000 dona yozadi. 31 da `Load` musbatligini tekshiramiz, 32 da `Add(-1)` kamaytiradi. 35-qator `qoldiq`ni chiqaradi.

800 000 urinishdan keyin nima boʻladi? **A)** doim 0 · **B)** manfiy ham chiqishi mumkin · **C)** `-race` albatta data race topadi.

<details>
<summary>Javob</summary>

**B.** `Load` bilan `Add` orasida boshqa goroutine sotishi mumkin. A butun `if`ni bitta atomik amal deb oladi. C mantiq xatosi bilan data race'ni aralashtiradi.

</details>

## Bozor uchun tanlov

[Go wiki](https://go.dev/wiki/MutexOrChannel) eng aniq ifodalangan yoki eng sodda yechimni tanlashni tavsiya qiladi. Qulf qoidalari murakkablashsa, egasi goroutine ularni soddalashtirishi mumkin.

| Vaziyat | Odatdagi tanlov | Sabab |
|---|---|---|
| qoldiq map'i, qisqa oʻqish–yozish | mutex | umumiy holatni himoyalash oson; GB-4.08 katalogi kabi |
| narx roʻyxatlarini bosqichlarga uzatish | kanal | maʼlumot egaligi uzatiladi; GB-7.02 oqimi kabi |
| ish taqsimlash yoki keyin tayyor natija | kanal | bajariladigan ish va natijani uzatish |
| soʻrovlar soni | atomic | bitta mustaqil sonning bitta amali |
| holat va ketma-ket ish, masalan faylga yozish | egasi goroutine | holat va ish bitta bajarilish tartibida |

Kesh — xotirada saqlangan natijalar — ham mutex uchun odatiy holat. Kerakli qoida va oʻlchovsiz kanallarni koʻpaytirish kodni murakkablashtirishi mumkin.

«Xotirani boʻlishib muloqot qilmang, muloqot qilib xotirani boʻlishing» qoidasini egalik bilan oʻqing. Kanal orqali map yuborishning oʻzi eski murojaatlarni taqiqlamaydi. Kod ulardan voz kechishi kerak. [Effective Go](https://go.dev/doc/effective_go#sharing) bu yondashuvni haddan oshirish mumkinligini ham aytadi; sanagichga mutex yetishi mumkin.

## Chuqurroq (ixtiyoriy): bitta sonni CompareAndSwap bilan sotish

**Compare-and-swap**: qiymat hali `old` boʻlsa `old-1` yozish. `CompareAndSwap` bularni bitta atomik amal qilib, muvaffaqiyatni `bool` bilan qaytaradi. Boshqa goroutine qiymatni oʻzgartirsa, qaytadan oʻqiymiz.

```go filename="_video/04-cas/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

// measure op'ni sakkiz goroutine'dan jami 800 000 marta chaqiradi va bitta chaqiruvga ketgan oʻrtacha vaqtni chiqaradi.
func measure(name string, op func()) {
	start := time.Now()
	var wg sync.WaitGroup
	for range 8 {
		wg.Go(func() {
			for range 100_000 {
				op()
			}
		})
	}
	wg.Wait()
	fmt.Println(name, time.Since(start)/800_000)
}

var stock atomic.Int64

// sellOne: CompareAndSwap — qiymat hali biz oʻqigan old boʻlsa, old-1 yozadi; boshqa goroutine
// oraliqda oʻzgartirgan boʻlsa, false qaytaradi va biz qaytadan oʻqiymiz.
func sellOne() bool {
	for {
		old := stock.Load()
		if old <= 0 {
			return false
		}
		if stock.CompareAndSwap(old, old-1) {
			return true
		}
	}
}

func main() {
	stock.Store(100_000)
	measure("cas", func() { sellOne() })
	fmt.Println("qoldiq:", stock.Load())
}
```

1–23-qatorlar avvalgi importlar va `measure`; 25 — `stock`. 29–31 — `sellOne` cheksiz siklda qoldiqni oladi. 32–34 — qoldiq tugasa `false`. 35–36 — hali oʻzgarmagan qiymatni kamaytirib `true` qaytaradi. CAS muvaffaqiyatsiz boʻlsa, 38 dan yangi aylanish boshlanadi. 41–45 — boshlangʻich qoldiq, 800 000 urinish va yakuniy chiqarish.

Natija? **A)** har doim 0 · **B)** manfiy boʻlishi mumkin · **C)** faqat `-race` toʻgʻrilaydi.

<details>
<summary>Javob</summary>

**A.** Oxirgi dona uchun faqat bitta CAS muvaffaqiyatli boʻladi. Boshqasi yangilangan 0 ni oʻqib rad etadi. `-race` kodni tuzatmaydi.

</details>

Uni barcha chaqiruvlari sotadigan `Sell` bilan teng ish deb solishtirmang. Qoldiq va buyurtmalar roʻyxatini birga oʻzgartirish uchun bu bitta CAS yetmaydi.

Bitta va sakkiz goroutine taʼsirini ajratadigan qoʻshimcha tajriba:

```go filename="_video/06-bitta/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

// measure — 01-ikki'dagidek, lekin goroutine'lar soni g: 800 000 chaqiruv g ta goroutine'ga boʻlinadi.
// Natija: jami vaqt / 800 000, ya'ni bitta chaqiruvga toʻgʻri keladigan vaqt (g = 1 da bu bitta chaqiruvning oʻzi).
func measure(name string, g int, op func()) {
	start := time.Now()
	var wg sync.WaitGroup
	for range g {
		wg.Go(func() {
			for range 800_000 / g {
				op()
			}
		})
	}
	wg.Wait()
	fmt.Println(name, g, time.Since(start)/800_000)
}

func main() {
	for _, g := range []int{1, 8} {
		locked := &LockedStore{stock: map[int64]int{1: 800_000}}
		measure("mutex", g, func() { locked.Sell(1, 1) })
		owned := NewOwnedStore(map[int64]int{1: 800_000})
		measure("egasi", g, func() { owned.Sell(1, 1) })
		owned.Close()
	}
}
```

Oʻzgargan qatorlar: 11 — `g` parametri; 14–16 — `g` ishga 800 000 chaqiruvni boʻlish. 22 — `g`ni ham chiqarish. 26 — `[]int{1, 8}` qiymatlari ustida aylanish; `_` indeksni tashlaydi. 27–31 har `g` uchun doʻkonlar yaratib, oʻlchab, yopadi.

Bitta chaqiruvchida egasi variantining uzatish xarajati yoʻqoladimi? **A)** ha · **B)** yoʻq · **C)** kanal kerak boʻlmaydi.

<details>
<summary>Javob</summary>

**B.** Bir chaqiruvchida ham egasi alohida goroutine. Shu sababli kanal orqali soʻrov va javob uzatish xarajati qoladi.

</details>

## Koʻp uchraydigan xatolar

**1. «Har metod atomik, demak sotuv ham atomik».** Xato dastur va haqiqiy manfiy natija yuqorida. `-race`ning jimligi sotuv qoidasini tekshirmaydi. Tuzatish: umumiy qulf, egasi yoki bitta songa CAS.

**2. Map'ni topshirgandan keyin yana oʻqish.** `OwnedStore` turi map'ni yashiradi, lekin chaqiruvchidagi eski map nomi qolishi mumkin. Bu bosqich `store.go`ning yuqoridagi ayni nusxasi bilan ishlaydi:

```go filename="_video/05-topshirilgan/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
)

// Xato: map loop'ga topshirilgandan keyin main uni oʻzi oʻqiydi. Endi map'ga ikki goroutine tegadi.
func main() {
	stock := map[int64]int{1: 1000}
	owned := NewOwnedStore(stock)
	var wg sync.WaitGroup
	for range 4 {
		wg.Go(func() {
			for range 100 {
				owned.Sell(1, 1)
			}
		})
	}
	fmt.Println("qoldiq:", stock[1]) // topshirilgan map'ga tegdik
	wg.Wait()
	owned.Close()
}
```

9–11-qatorlarda `stock` egasiga beriladi. 12–19 da `wg` toʻrtta sotuvchini boshlaydi, har biri 100 marta sotadi. 20 da `main` map'ni sinxronlashsiz oʻqiydi; 21–23 esa sotuvlarni kutib, doʻkonni yopadi. `qoldiq` yozuvi kafolatlangan qiymat emas.

`-race` nima deydi? **A)** map berilgani uchun hammasi xavfsiz · **B)** toʻqnashuvchi oʻqish va yozishni topsa ogohlantiradi · **C)** har doim oddiy `0` chiqaradi.

<details>
<summary>Javob</summary>

**B.** Asosiy goroutine map'ni oʻqiydi, `loop` esa unga yozadi. Kanal chaqiruvchidagi eski map'ni oʻqib boʻlmaydigan qilib qoʻymaydi.

</details>

Buyruqning `2>&1` qismi xatolar oqimini ham uzatadi; `|` uni `sed`ga beradi. `sed -n` faqat ogohlantirish, topilgan xatolar soni va chiqish holati qatorlarini chiqaradi. Hisobotning manzil va stek qatorlari shu filtr bilan olib tashlangan:

```console
$ ./_video/race.sh 05-topshirilgan go run -race . 2>&1 | sed -n '/^WARNING: DATA RACE$/p; /^Found .*data race/p; /^exit status /p; /^(chiqish kodi:/p'
WARNING: DATA RACE
WARNING: DATA RACE
Found 2 data race(s)
exit status 66
(chiqish kodi: 1)
```

`WARNING: DATA RACE` — data race ogohlantirishi; `Found 2 data race(s)` — shu ishga tushirishda ikkita toʻqnashuv topildi. `exit status 66` tekshiruv xato topib tugaganini bildiradi. Skript buni chiqish kodi 1 deb koʻrsatadi. Tuzatish: eski map'ga tegmang; qoldiqni egasidan `Stock` bilan soʻrang.

**3. Yopilgan kanalni oddiy qabul qilish.** Vazifadagi `select`da yopilgan `sells` doim tayyor boʻladi. `r, ok := <-s.sells` va `if !ok { return }` kerak; aks holda loop aylanishda yoki nol `reply`ga yuborishda qolishi mumkin.

**4. Yaratilmagan kanal.** Yangi `stocks` maydoni `make` qilinmasa, u `nil`. Unga yuborish abadiy kutadi. Konstruktor kanalni yaratsin, loop uni qabul qilsin.

**5. Tugash va nusxalash.** `Close`ni ikki marta chaqirish panic beradi; undan keyin sotish ham yaroqsiz. Yechimdagi `Stock` ham egasi tugagach kutib qoladi. Avval chaqiruvchilarni tugating; ishlatilgan mutex yoki `atomic.Int64`ni nusxalamang.

## Oʻzingizni tekshiring

**1.** Qulfsiz egasi variantida nega data race yoʻq?

<details>
<summary>Javob</summary>

Map'ga faqat `loop` tegadi. Soʻrov va javob kanallari yozuvlarning koʻrinishini sinxronlaydi. Chaqiruvchi topshirilgan map'ga tegmasligi kerak.

</details>

**2.** Ikkita goroutine `Load()`dan 1 oldi. Har biri `Add(-1)` qilsa, nima qoladi? **A)** 0 · **B)** −1 · **C)** data race xatosi.

<details>
<summary>Javob</summary>

**B: −1.** Ikki boʻlinmas amal ketma-ket kamaytiradi. Ikkala tekshirish ham oldin oʻtib boʻlgan. Bu data race'siz race condition.

</details>

**3.** GB-7.02: buferi boʻsh, yopilgan `chan int`dan `n, ok := <-ch` nima beradi?

<details>
<summary>Javob</summary>

Darhol `n == 0`, `ok == false`. Vazifada shu `ok` loop'ning tugashini taʼminlaydi.

</details>

**4.** 800 000 amal 0.4 soniyada tugadi. Har chaqiruv 500 ns kutdimi?

<details>
<summary>Javob</summary>

Yoʻq. 0.4 / 800 000 = 500 ns/amal — jami oʻtkazuvchanlikning teskarisi. Bir vaqtda ishlayotgan chaqiruvning shaxsiy kutish vaqti boshqa.

</details>
