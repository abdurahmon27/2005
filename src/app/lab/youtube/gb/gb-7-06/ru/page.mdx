## Что вы узнаете

Bozor одновременно запрашивает цену яблок у трёх поставщиков. Первый ответ получен, тест проходит, но каждый вызов оставляет две горутины. Как это обнаружить?

**Одна идея:** проверки результата недостаточно; проверяйте и завершение запущенных горутин. `testing/synctest` управляет ожиданием и искусственным временем в изолированной тестовой среде.

После урока вы сможете:

- подсчитать утечку горутин и найти строку ожидания по профилю;
- поймать через `synctest.Test` ошибку, которую пропускает обычный тест;
- отменить медленную работу через контекст;
- точно проверить срок 50 мс и обнаружить забытый `Close`.

| Слово | Простой смысл | Английский термин |
|---|---|---|
| утечка горутины | горутина ждёт вечно, хотя уже должна завершиться | goroutine leak |
| пузырь | изолированная среда для теста и запущенных им горутин | bubble |
| искусственные часы | часы переходят к концу ожидания без ожидания в реальном времени | fake clock |

## Один ответ, две оставшиеся горутины

Начнём с ошибочного снимка. `prices` сопоставляет ID с ценой в тийинах; `supplierDelays` хранит время ответа трёх поставщиков.
`quote` имитирует ожидание вместо настоящей сети.

```go filename="_video/01-leak/price.go" showLineNumbers
package main

import "time"

// prices: yetkazib beruvchilar aytadigan narx, tiyinda (ID → tiyin): olma 1, non 2, oʻrik 3.
var prices = map[int64]int64{1: 1_200_000, 2: 500_000, 3: 3_000_000}

// supplierDelays: uch yetkazib beruvchining (chorsu, oloy, siyob) javob vaqti.
var supplierDelays = []time.Duration{
	100 * time.Millisecond,
	200 * time.Millisecond,
	300 * time.Millisecond,
}

func quote(delay time.Duration, id int64) int64 {
	time.Sleep(delay)
	return prices[id]
}

func fastestPrice(id int64) int64 {
	ch := make(chan int64)
	for _, d := range supplierDelays {
		go func() {
			ch <- quote(d, id)
		}()
	}
	return <-ch
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1, 3 | `package main`, `import "time"` | исполняемый пакет и пакет времени |
| 5–6 | `prices` | комментарий и `map[int64]int64`; ID 1 стоит 1 200 000 тийинов, то есть 12 000 сумов |
| 8–13 | `supplierDelays` | комментарий и слайс `[]time.Duration`; `*` — умножение, последняя запятая нужна в многострочном литерале |
| 15–18 | `quote` | принимает `delay` и `id`, спит, возвращает значение map |
| 20–21 | `fastestPrice`, `make(chan int64)` | функция и небуферизованный канал результата |
| 22 | `for _, d := range` | отбрасывает индекс через `_`; в каждой итерации новая `d` |
| 23 | `go func() {` | запускает анонимную функцию в отдельной горутине |
| 24 | `ch <- quote(d, id)` | сначала вычисляет цену, затем пытается отправить |
| 25–26 | `}()`, `}` | вызывает анонимную функцию и закрывает цикл |
| 27–28 | `return <-ch`, `}` | получает одну цену и возвращается из функции |

Пустые строки разделяют код; строки с `//` — комментарии. `{}` задают границы блока; `:=` объявляет новую переменную.

```go filename="_video/01-leak/main.go" showLineNumbers
package main

import (
	"fmt"
	"runtime"
	"time"
)

func main() {
	for range 3 {
		for range 100 {
			fastestPrice(1)
		}
		time.Sleep(time.Second)
		fmt.Println("goroutine'lar:", runtime.NumGoroutine())
	}
}
```

`main.go`: строка 1 — пакет; 3–7 — импорты; 9 — функция; 10 — внешний цикл; 11–13 — сто вызовов; 14 — ожидание секунды.
Строка 15 печатает число всех живых горутин через `fmt.Println`; 16–17 закрывают блоки.
`for range 3` — три итерации без переменной-счётчика.

**Предскажите:** сколько горутин останется после 300 вызовов? **A)** 1 · **B)** 301 · **C)** 601.

<details>
<summary>Ответ</summary>

**C: 1 + 300 × 2 = 601.** 1 — это `main`. Каждый вызов запускает три горутины, но получает только один ответ.
A предполагает завершение всей работы; B учитывает лишь одну оставшуюся горутину на вызов.

</details>

```console
$ ./_video/run.sh 01-leak go run .

goroutine'lar: 401
goroutine'lar: 601
(chiqish kodi: 0)
```

| Время | Первый поставщик | Второй | Третий | Получатель |
|---|---|---|---|---|
| 0 мс | ждёт | ждёт | ждёт | `<-ch` |
| 100 мс | отправляет, завершается | ждёт | ждёт | получает цену и возвращается |
| 200 мс | завершился | застрял на отправке | ждёт | отсутствует |
| 300 мс | завершился | застрял на отправке | застрял на отправке | отсутствует |

Это **утечка горутины**: у двух оставшихся отправителей больше не будет получателя.
Ресурсы ожидающей горутины не освобождаются автоматически; она должна завершиться.

## Профиль: на какой строке ожидание?

Счётчик показывает рост. **Профиль** показывает стеки горутин — последовательности вызовов функций.
Следующий снимок добавляет один вызов в конце `main`:

```go filename="_video/02-profil/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"runtime"
	"runtime/pprof"
	"time"
)

func main() {
	for range 3 {
		for range 100 {
			fastestPrice(1)
		}
		time.Sleep(time.Second)
		fmt.Println("goroutine'lar:", runtime.NumGoroutine())
	}
	pprof.Lookup("goroutine").WriteTo(os.Stdout, 1)
}
```

Новая строка 5 импортирует `os`, строка 7 — `runtime/pprof`. Строка 19 выбирает профиль через `Lookup("goroutine")`.
`WriteTo(os.Stdout, 1)` пишет его в стандартный вывод; `1` выбирает текст с группировкой одинаковых стеков.

**Предскажите:** сколько всего горутин в профиле? **A)** 600 · **B)** 601 · **C)** 3.

<details>
<summary>Ответ</summary>

**B.** Обычный профиль `goroutine` включает работающую `main` наряду с утечками. 600 — только ожидающие отправители.

</details>

## Обычный тест не проверяет утечки

```go filename="_video/03-test/price_test.go" showLineNumbers
package main

import "testing"

func TestFastestPrice(t *testing.T) {
	got := fastestPrice(1)
	if got != 1_200_000 {
		t.Errorf("fastestPrice(1) = %d; kutilgan 1200000", got)
	}
}
```

Строка 1 — пакет; 3 — пакет тестирования; 5 — функция теста; 6 — результат `got`; 7 — сравнение с ожидаемой ценой.
Строка 8 помечает тест как неуспешный через `t.Errorf`; `%d` печатает целое число; 9–10 закрывают блоки.

**Предскажите:** результат и время? **A)** PASS, примерно 0.10 с · **B)** PASS, примерно 0.30 с · **C)** FAIL, утечка.

<summary>Ответ</summary>

**A.** Тест ждёт только первую цену. Остальные горутины не проверяются; при завершении процесса теста они тоже исчезают.

## synctest: тест вернулся, работа осталась

`testing/synctest` доступен без экспериментального флага начиная с Go 1.25. Он выполняет тест внутри **пузыря**.
Это изолированная тестовая среда: запущенные внутри горутины тоже ей принадлежат. `synctest.Test` ждёт завершения их всех.

**Устойчивая блокировка** (*durably blocked*) — ожидание, которое может закончить только работа внутри того же пузыря.
К ней относятся ожидание на созданном в пузыре канале и `time.Sleep`.
Когда так ждут все горутины, часы переходят к следующему пробуждению. Начальное время: `2000-01-01 00:00:00 UTC`.
После завершения корневой функции пузыря часы останавливаются. Если пробуждение невозможно, а ожидание осталось, возникает deadlock.

```go filename="_video/04-synctest/price_test.go" showLineNumbers
package main

import (
	"testing"
	"testing/synctest"
)

func TestFastestPrice(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		got := fastestPrice(1)
		if got != 1_200_000 {
			t.Errorf("fastestPrice(1) = %d; kutilgan 1200000", got)
		}
	})
}
```

Новая строка 5 импортирует пакет; строка 9 передаёт внешний `t` и анонимную функцию со своим параметром `t`.
Строки 10–13 сохраняют прежнюю проверку; 14–15 закрывают пузырь и тест.

**Предскажите:** **A)** PASS · **B)** FAIL: deadlock · **C)** ждёт 300 мс и проходит.

<details>
<summary>Ответ</summary>

**B.** Цена приходит на 100 мс искусственного времени. Функция теста возвращается, часы останавливаются; две горутины ещё спят.
A учитывает только цену. C предполагает, что часы продолжают идти после выхода из функции теста.

</details>

## Остановка оставшейся работы через context

Итоговый `price.go` из папки урока:

```go filename="price.go" showLineNumbers
// bozor: bitta mahsulot narxini uch yetkazib beruvchidan birdan soʻrab, eng tez javobni olish (GB-7.06).
// Videoning oxiridagi holat: goroutine'lar fastestPrice bilan birga tugaydi (ctx + cancel), leak yoʻq.
package main

import (
	"context"
	"time"
)

// prices: yetkazib beruvchilar aytadigan narx, tiyinda (ID → tiyin): olma 1, non 2, oʻrik 3.
var prices = map[int64]int64{1: 1_200_000, 2: 500_000, 3: 3_000_000}

// supplierDelays: uch yetkazib beruvchining (chorsu, oloy, siyob) javob vaqti.
var supplierDelays = []time.Duration{
	100 * time.Millisecond,
	200 * time.Millisecond,
	300 * time.Millisecond,
}

// quote bitta yetkazib beruvchidan narx soʻrashni taqlid qiladi: delay oʻtguncha yoki ctx bekor qilinguncha kutadi.
func quote(ctx context.Context, delay time.Duration, id int64) (int64, error) {
	select {
	case <-time.After(delay):
		return prices[id], nil
	case <-ctx.Done():
		return 0, ctx.Err()
	}
}

// fastestPrice hamma yetkazib beruvchidan birdan soʻraydi va birinchi kelgan javobni qaytaradi.
// Qaytishdan oldin cancel() qolgan soʻrovlarni toʻxtatadi: oʻzi boshlagan goroutine'lar uning bilan tugaydi.
func fastestPrice(ctx context.Context, id int64) (int64, error) {
	ctx, cancel := context.WithCancel(ctx)
	defer cancel()
	ch := make(chan int64, len(supplierDelays))
	for _, d := range supplierDelays {
		go func() {
			p, err := quote(ctx, d, id)
			if err == nil {
				ch <- p
			}
		}()
	}
	select {
	case p := <-ch:
		return p, nil
	case <-ctx.Done():
		return 0, ctx.Err()
	}
}
```

Изменённые строки:

| Строка | Что делает |
|---|---|
| 5–8 | импортирует `context` и `time` |
| 21 | `quote` принимает контекст и возвращает `(int64, error)` |
| 22–28 | `select`: цена и `nil`, если время прошло; 0 и `ctx.Err()`, если `Done` закрыт |
| 32–34 | `WithCancel` создаёт дочерний контекст; `ctx` переприсваивает параметр в этом блоке, `cancel` — новый; `defer` сигнализирует при возврате |
| 35 | сохраняет буфер на три места |
| 36–43 | каждая горутина запрашивает с дочерним контекстом; `p` — цена, `err` — ошибка; отправка только при `err == nil` |
| 44–50 | ждёт первую цену или отмену вызывающей стороны |

Строки 1–2, 10, 13, 20 и 30–31 — комментарии. Не читайте «birga tugaydi» («завершаются вместе») как гарантию ожидания завершения.
[`CancelFunc`](https://pkg.go.dev/context#CancelFunc) только сигнализирует; завершения работы он не ждёт.
Здесь оставшиеся горутины видят сигнал и выходят; их завершения ждёт `synctest.Test`.
Если вызывающая функция обязана дождаться их перед возвратом, нужна группа ожидания, как в [GB-7.01](/lab/youtube/gb/gb-7-01/ru).
Буфер тоже остаётся полезен: если время и отмена готовы одновременно, отправка успешной цены не застрянет.

| Этап | Результат |
|---|---|
| первая цена | `fastestPrice` начинает возвращаться |
| `defer cancel()` | закрывается канал `Done` дочернего контекста |
| оставшиеся вызовы `quote` | видят отмену, возвращают ошибки, не отправляют |
| `synctest.Test` | ждёт завершения всех горутин |

## Забытый Close: другое ожидание, та же ошибка

`store.go` — сокращённый `OwnedStore` из прошлого урока. К map обращается только горутина-владелец.

```go filename="store.go" showLineNumbers
package main

// OwnedStore — GB-7.05'dagi qoldiq doʻkoni (qisqartirilgan): stock map'iga faqat loop goroutine'i tegadi,
// Sell unga channel orqali soʻrov yuboradi. loop sells yopilganda (Close) tugaydi.
type OwnedStore struct {
	sells chan sellReq
}

// sellReq — egasiga yuboriladigan sotish soʻrovi: qaysi mahsulot, necha dona va javob qaytadigan channel.
type sellReq struct {
	id    int64
	n     int
	reply chan bool
}

// NewOwnedStore loop'ni yangi goroutine'da boshlaydi va stock map'ini unga topshiradi.
func NewOwnedStore(stock map[int64]int) *OwnedStore {
	s := &OwnedStore{sells: make(chan sellReq)}
	go s.loop(stock)
	return s
}

func (s *OwnedStore) loop(stock map[int64]int) {
	for r := range s.sells {
		ok := stock[r.id] >= r.n
		if ok {
			stock[r.id] -= r.n
		}
		r.reply <- ok
	}
}

// Sell id'li mahsulotdan n dona sotadi; qoldiq yetmasa false.
func (s *OwnedStore) Sell(id int64, n int) bool {
	reply := make(chan bool)
	s.sells <- sellReq{id, n, reply}
	return <-reply
}

// Close loop goroutine'ini toʻxtatadi. Close'dan keyin Sell chaqirilmaydi.
func (s *OwnedStore) Close() { close(s.sells) }
```

Строки 5–7 хранят канал запросов; 10–14 — `id` запроса, количество `n` и канал ответа `reply`.

34–38 заставляют `Sell` отправить запрос и получить ответ. Строка 41 закрывает канал запросов в `Close`.
`>=` сравнивает доступность; `-=` уменьшает; `&` берёт адрес; `*OwnedStore` — указательный получатель метода.

## Глубже (необязательно): goroutineleak и границы synctest

В Go 1.27 профиль `goroutineleak` вышел из эксперимента; `GOEXPERIMENT=goroutineleakprofile` не нужен, старая настройка удалена.
GC — сборка мусора: освобождение неиспользуемой памяти.
Профиль доступен в обычной сборке, но это не означает автоматического поиска утечек при каждом GC.
В исходниках Go 1.27.4 `writeGoroutineLeak` сначала вызывает `runtime_goroutineLeakGC()`, затем записывает профиль.
Значит, запрос профиля запускает цикл GC с поиском утечек.

Утечки через примитивы, достижимые из глобальных переменных или работающих горутин, могут остаться незамеченными.
`WriteTo(..., 2)` печатает все стеки, отмечая утечки как `(leaked)`; это не список только утечек.

Искусственные часы в `synctest` не определяют весь порядок выполнения. При нескольких готовых ветках `select` не полагайтесь на их порядок.

## Частые ошибки

1. **«PASS — значит утечек нет».** Обычный тест проверил только цену. Сравните два снимка в разделах об обычном тесте и synctest; добавьте тест в пузыре.
2. **«Буфер завершает всю работу».** Реальный deadlock выше показал оставшиеся сны. Пусть `quote` следит за отменой, а вызывающая сторона вызывает `cancel`.
3. **«cancel ждёт».** Он сигнализирует. Для строгого завершения добавьте ожидание; в тесте `synctest.Test` ждёт все внутренние горутины.
4. **Забытый `Close`.** Ошибочный тест выше упал на получении в `store.go:24`. Исправление: `defer s.Close()`.
5. **`took == 50*time.Millisecond` на настоящих часах.** Нагрузка среды задерживает выполнение. Оставьте точное равенство для искусственного времени внутри пузыря.
6. **«`synctest.Wait()` означает завершение всей работы».** Он ждёт выхода остальных или их устойчивой блокировки. Заблокированная утечка может остаться.
7. **Запуск `-race` без cgo.** Используйте среду с компилятором C или Docker-скрипт выше. Проверка гонок не заменяет проверку утечек.

## Проверьте себя

**1.** Почему synctest может упасть, хотя все проверки цены прошли?

<details>
<summary>Ответ</summary>

Работа в пузыре может попасть в deadlock. Здесь его корневая функция завершается, часы останавливаются, остаются две устойчиво заблокированные горутины.

</details>

**2.** Почему буфера на три места недостаточно?

<details>
<summary>Ответ</summary>

Отправка могла бы закончиться позже, но горутины ещё спят. После выхода корневой функции пузыря часы не разбудят их; нужна отмена через контекст.

</details>

**3.** Других горутин в пузыре нет. Что даст `start := time.Now(); time.Sleep(time.Hour); time.Since(start)`?
**A)** примерно 0 · **B)** ровно 1 час · **C)** deadlock.

<details>
<summary>Ответ</summary>

**B.** Искусственная длительность — час, а реальное выполнение очень короткое. Это проверенный выше случай `TestHour`.

</details>

**4.** Из GB-7.03: что отправляет `ctx.Done()` и когда он закрывается?

<details>
<summary>Ответ</summary>

Это `<-chan struct{}`: значение не отправляется, сигналом служит закрытие. Он закрывается при отмене контекста или истечении его срока.
У `Background` `Done()` равен nil; сам он не закроется.

</details>

**5.** Что гарантирует наличие `goroutineleak` в Go 1.27?

<details>
<summary>Ответ</summary>

Можно запросить профиль без экспериментального флага. Это не означает обнаружения всех утечек или автоматического поиска при каждом GC.
Запрос профиля запускает специальный GC; достижимость может скрыть часть утечек.

</details>

package main

import (
	"context"
	"errors"
	"time"
)

// priceOffer — bitta yetkazib beruvchining olma uchun taklifi: qancha vaqtda javob beradi va qancha narx aytadi (tiyin).
type priceOffer struct {
	delay time.Duration
	price int64
}

// priceOffers: uch yetkazib beruvchi. Uchinchisi eng arzon, lekin juda sekin.
var priceOffers = []priceOffer{
	{100 * time.Millisecond, 1_250_000},
	{200 * time.Millisecond, 1_150_000},
	{3 * time.Second, 1_100_000},
}

// quoteTimeout: cheapestPrice takliflarni shuncha vaqtdan koʻp kutmaydi.
const quoteTimeout = time.Second

// errNoOffer: quoteTimeout ichida hech bir yetkazib beruvchi javob bermadi.
var errNoOffer = errors.New("hech bir yetkazib beruvchi vaqtida javob bermadi")

// askOffer bitta yetkazib beruvchidan taklif soʻraydi: o.delay oʻtguncha yoki ctx bekor qilinguncha kutadi.
func askOffer(ctx context.Context, o priceOffer) (int64, error) {
	select {
	case <-time.After(o.delay):
		return o.price, nil
	case <-ctx.Done():
		return 0, ctx.Err()
	}
}

// cheapestPrice hamma yetkazib beruvchidan birdan soʻraydi, quoteTimeout ichida kelgan takliflarning eng arzonini
// qaytaradi va qaytganda oʻzi boshlagan birorta goroutine'ni ham ortda qoldirmaydi.
func cheapestPrice(ctx context.Context) (int64, error) {
	tctx, cancel := context.WithTimeout(ctx, quoteTimeout)
	defer cancel()
	ch := make(chan int64, len(priceOffers))
	for _, o := range priceOffers {
		go func() {
			p, err := askOffer(tctx, o)
			if err == nil {
				ch <- p
			}
		}()
	}
	var best int64
	found := false
	take := func(p int64) {
		if !found || p < best {
			best, found = p, true
		}
	}
	for range priceOffers {
		select {
		case p := <-ch:
			take(p)
		case <-tctx.Done():
			if err := ctx.Err(); err != nil {
				return 0, err // chaqiruvchi bekor qildi yoki uning muddati tugadi
			}
			for len(ch) > 0 { // muddat bilan bir paytda kelib, buffer'da turgan javoblar
				take(<-ch)
			}
			if !found {
				return 0, errNoOffer
			}
			return best, nil
		}
	}
	return best, nil
}

59–62 собирают каждый ожидаемый ответ. 63–66 отличают ошибку родительского контекста от собственного срока операции.
67–69 забирают также ответы, уже лежащие в буфере. Это не добавляет гарантированного порядка для всех одновременных событий.
70–76 возвращают ошибку отсутствия предложений либо минимальную цену. Остальные строки — знакомые блоки и готовые помощники.
