## What you will learn

A customer ordered one apple and one pomegranate from bozor. The pomegranate is not in the catalog. The program did not report an error:

```console
$ ./_video/run.sh 00-hook go run . olma anor
anor  1 dona
olma  1 dona
jami: 12000 soʻm
```

The pomegranate went onto the receipt, and the total is only the price of the apple. Why did the program accept a product that does
not exist, and how do you reject it?

**One idea:** a map is a table that finds a value by key. A missing key is not an error: the map returns the zero value of the value
type, so only comma-ok tells "missing" from "zero". `range` over a map starts at a random place every time: if you need an order,
you sort the keys yourself.

By the end of the lesson you will:

- write the type `map[string]int64`, fill it with a map literal, and read, write and delete values by key;
- reject a product that is not in the catalog with `price, ok := prices[name]`;
- count the items of an order with `count[name]++`;
- print the receipt in the same order every time by sorting the keys, and see why writing to a map declared with `var` causes a panic.

Today's three core new words:

| Word | Plain meaning | English term |
|---|---|---|
| map | a table that finds a value by key (a name): `map[string]int64` is name → price | map |
| comma-ok | `price, ok := prices[name]`: the second variable `ok` tells whether the key is in the map (`true` / `false`) | comma-ok |
| order of `range` over a map | the order in which `range` hands out the keys is not specified and can change from run to run | map iteration order |

Two helper ideas: **`make`** for creating an empty map, and the nil map; and the fact that a map value is not the table itself but its
address (passing a map to a function does not copy the table).

## The problem: finding by name in a list

If the prices are in a slice, to find the price of the apple you walk the list from the start and compare every name with "olma".
With 50 000 products, one query can take up to 50 000 comparisons. This is arithmetic, not a measurement: the longer the list, the longer the search.

## Map: a value by key

A **map** solves this differently. It passes the key through a **hash function**: the function makes a number out of text. The number
points to a place in the table, and the map compares only the keys at that place and returns the value. That is why lookup time on
average does not depend on the number of products ([Go blog: Go maps in action](https://go.dev/blog/maps)). The internal table is
called a **hash table**.

```text
key "olma"  →  hash (text → number)  →  place in the table  →  value 1200000 (price of an apple, in tiyin)
```

An important consequence: the hash chooses the place, so the keys in the table stand neither in insertion order nor in alphabetical order.
You will need this again in the section "Range over a map and its order".

### Type and literal

The first program (`_video/01-map/main.go`):

```go filename="_video/01-map/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	prices := map[string]int64{
		"olma": 12_000 * tiyinPerSom,
		"non":  4_000 * tiyinPerSom,
	}
	fmt.Println(prices["olma"])
	prices["choy"] = 25_000 * tiyinPerSom
	fmt.Println(len(prices))
	fmt.Println(prices["anor"])

```

Lines 1–7 are familiar (`package`, `import`, `const`, `func main`). The new lines:

| Line | Code | What it does |
|---|---|---|
| 8 | `prices := map[string]int64{` | creates the variable `prices`. `map[string]int64` is the type: inside the square brackets the **key type** (`string`, the product name), after them the **value type** (`int64`, the price in tiyin). The curly brace opens a map literal: a map whose values are written in the code |
| 9–10 | `"olma": 12_000 * tiyinPerSom,` | a literal row: key, colon, value, a comma at the end (like the `tests` list in GB-1.08) |
| 11 | `}` | closes the literal: the map has two keys |
| 12 | `fmt.Println(prices["olma"])` | a key in square brackets: **reading** by key |
| 13 | `prices["choy"] = 25_000 * tiyinPerSom` | **writing**: if the key is missing it is added, if it exists its value is replaced |
| 14 | `fmt.Println(len(prices))` | `len` gives the number of keys in the map |
| 15 | `fmt.Println(prices["anor"])` | reads `anor`, which is not in the catalog |

The key type must be comparable with `==` ([Go spec: Map types](https://go.dev/ref/spec#Map_types)). `string` is such a type.

## Comma-ok: a missing key and a zero price

A price of `0` is possible too (a free product), and a missing product also gives `0`. To tell them apart, indexing has a second form.
The second program (`_video/02-ok/main.go`) takes one name from the command line:

```go filename="_video/02-ok/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	prices := map[string]int64{
		"olma": 12_000 * tiyinPerSom,
		"non":  4_000 * tiyinPerSom,
	}
	if len(os.Args) != 2 {
		fmt.Fprintln(os.Stderr, "foydalanish: bozor NOM")
		os.Exit(1)
	}
	name := os.Args[1]
	price, ok := prices[name]
	if !ok {
		fmt.Fprintln(os.Stderr, "xato:", name, "katalogda yoʻq")
		os.Exit(1)
	}
	fmt.Println(name, price/tiyinPerSom, "soʻm")
}
```

| Line | Code | What it does |
|---|---|---|
| 15–18 | `if len(os.Args) != 2 { … }` | checks the number of words, as in GB-1.07: if there is no program name plus exactly one product name, it writes a usage message to stderr and exits with code 1 |
| 19 | `name := os.Args[1]` | `name` is the first word of the command line (`os.Args[0]` is the program name) |
| 20 | `price, ok := prices[name]` | two variables on the left: `price` is the value, `ok` is a `bool`: `true` if the key is in the map, `false` if not. When `false`, `price` is the zero value, that is `0` |
| 21–24 | `if !ok { … }` | `!ok`, that is "not ok": writes the error to stderr and exits with code 1 (GB-1.07) |
| 25 | `fmt.Println(name, price/tiyinPerSom, "soʻm")` | divides the price from tiyin to soʻm and prints it |

The form `v, ok := m[k]` is called **comma-ok**: it is very common in Go code. Three cases:

| Case | `price` | `ok` |
|---|---|---|
| key exists, price 1 200 000 | `1200000` | `true` |
| key exists, price `0` | `0` | `true` |
| key missing | `0` | `false` |

```console
$ ./_video/run.sh 02-ok go run . olma
olma 12000 soʻm
$ ./_video/run.sh 02-ok go run . anor
xato: anor katalogda yoʻq
exit status 1
$ ./_video/run.sh 02-ok go run .
foydalanish: bozor NOM
exit status 1
```

The line `exit status 1` is written not by the program but by `go run`: it reports that the program ended with code 1 (GB-1.07). Now
"zero soʻm" and "no such product" are two different cases.

## Zero value and delete

The third program (`_video/03-delete/main.go`) compares a key with a zero value and a deleted key:

```go filename="_video/03-delete/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	prices := map[string]int64{
		"olma": 12_000 * tiyinPerSom,
		"non":  4_000 * tiyinPerSom,
	}
	prices["olma"] = 0
	_, ok := prices["olma"]
	fmt.Println(len(prices), ok)
	delete(prices, "non")
	_, ok = prices["non"]
	fmt.Println(len(prices), ok)
}
```

| Line | Code | What it does |
|---|---|---|
| 12 | `prices["olma"] = 0` | writes zero for the apple: the key stays in place, only its value is replaced |
| 13 | `_, ok := prices["olma"]` | checks with comma-ok; the value is not needed, `_` discards it |
| 14 | `fmt.Println(len(prices), ok)` | prints the number of keys and `ok` |
| 15 | `delete(prices, "non")` | `delete` is a built-in Go function: the first argument is the map, the second is the key to remove |
| 16 | `_, ok = prices["non"]` | `ok` already exists, so this is `=`, not `:=` |
| 17 | `fmt.Println(len(prices), ok)` | the number of keys and `ok` again |

The program prints two lines, each with `len` first, then `ok`. Which option is right?

**A)** `2 true`, then `1 false` · **B)** `2 false`, then `1 false` · **C)** `1 false`, then another `1 false`

<details>
<summary>Answer</summary>

**A.** The apple with a zero value is in the map: `len` is 2, `ok` is `true`. After `delete(prices, "non")` one key is left, and for
`non` `ok` is `false`. If you chose **B**, you took a zero price for "missing": a key with the value `0` stays in the map. **C**:
`prices["olma"] = 0` does not delete the key, it only replaces its value.

</details>

```console
$ ./_video/run.sh 03-delete go run .
2 true
1 false
```

| Line | `prices` (key → value) | `len` | `ok` |
|---|---|---|---|
| after 12 | `olma → 0`, `non → 4000·100` | 2 | |
| 13–14 | unchanged | 2 | `true` (`olma` exists) |
| after 15 | `olma → 0` | 1 | |
| 16–17 | unchanged | 1 | `false` (`non` is missing) |

Deleting a missing key with `delete` is not an error, it does nothing: the spec says so explicitly (*"If the map m is nil or the element
m[k] does not exist, delete is a no-op"*, [Go spec: Deletion of map elements](https://go.dev/ref/spec#Deletion_of_map_elements)).
I did not run this sentence separately, I quoted it from the spec.

## An empty map with make, and counting

To count the items of an order you need an empty map. `make` creates it. In GB-2.01 `make` allocated an array for a slice, for a map it
allocates an empty table ([Go spec: Making slices, maps and channels](https://go.dev/ref/spec#Making_slices_maps_and_channels)).
The complete program (this file is not in the course folder: I ran it separately in a scratch folder):

```go
package main

import "fmt"

func main() {
	order := []string{"olma", "non", "olma"}
	count := make(map[string]int)
	for _, name := range order {
		count[name]++
	}
	fmt.Println(count["olma"], count["anor"])
}
```

```console
$ go run .
2 0
```

`count[name]++` uses the rule "a missing key gives zero": the value of a missing key is `0`, we add 1 and write it back. The steps of the loop:

| Loop step | `name` | table `count` |
|---|---|---|
| after `make` | | empty |
| 1 | `olma` | `olma 1` (it was missing: `0 + 1`) |
| 2 | `non` | `olma 1`, `non 1` |
| 3 | `olma` | `olma 2`, `non 1` (`1 + 1`) |

At the end `count["olma"]` is 2 and the missing `count["anor"]` is 0. In the picture the variable `count` holds not the table itself but
its address in memory, like `ptr` in a slice header (GB-2.01). There is no name "table" in the code: it is the hash table created by the runtime.

```text
count (map[string]int)          hash table (created by the runtime)
┌──────────────┐                ┌─────────┬───┐
│   address ───┼──────────────► │ olma    │ 2 │
└──────────────┘                │ non     │ 1 │
                                └─────────┴───┘
```

## Range over a map and its order

Now the names come from the command line. The fourth program (`_video/04-tartib/main.go`):

```go filename="_video/04-tartib/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
)

func main() {
	order := os.Args[1:]
	count := make(map[string]int)
	for _, name := range order {
		count[name]++
	}

```

| Line | Code | What it does |
|---|---|---|
| 9 | `order := os.Args[1:]` | `1:` in square brackets means from index 1 to the end: all words after the program name ([Go spec: Slice expressions](https://go.dev/ref/spec#Slice_expressions)) |
| 10–13 | `count := make(…)` and the loop | the same counting as in the previous section |
| 14 | `for name, n := range count {` | `range` over a map gives two variables: `name` is the key, `n` is the value |
| 15 | `fmt.Println(name, n)` | prints each pair |

The command `go run . olma non olma choy` is run several times. In what order will the lines appear?

*"you should not rely on it"*; [Go 1 release notes](https://go.dev/doc/go1#iteration)). The risk: a test that depends on the order
usually passes and one day fails. Here about one run in four gives another order.

## If you need an order: sort the keys

If you need an order, you build it yourself: collect the keys into a slice, sort the slice and walk over it. The fifth program
(`_video/05-sort/main.go`):

```go filename="_video/05-sort/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"slices"
)

func main() {
	order := os.Args[1:]
	count := make(map[string]int)
	for _, name := range order {
		count[name]++
	}
	var names []string
	for name := range count {
		names = append(names, name)
	}
	slices.Sort(names)
	for _, name := range names {
		fmt.Printf("%-5s %d dona\n", name, count[name])
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `"slices"` | a new package: `slices` from the standard library (it ships with Go) |
| 15 | `var names []string` | `names` is a slice of `string`; declared with `var`, length 0, `append` can add to it |
| 16–18 | `for name := range count { … }` | with one variable in `range`, only the keys arrive; `append` adds them to `names` |
| 19 | `slices.Sort(names)` | sorts the list in place, in ascending order |
| 20–22 | `for _, name := range names { … }` | printing now goes over `names`, and the number comes from `count[name]` |
| 21 | `fmt.Printf("%-5s %d dona\n", name, count[name])` | `%-5s` writes the name into a 5-character column, aligned to the left |

```console
$ ./_video/run.sh 05-sort go run . olma non olma choy
choy  1 dona
non   1 dona
olma  2 dona
$ ./_video/run.sh 05-sort go run . olma non olma choy
choy  1 dona
non   1 dona
olma  2 dona
```

The two runs are identical: `choy`, `non`, `olma`. This is what you do wherever a receipt or a test expects a stable text.

`slices.Sort` compares strings **byte by byte** ([pkg.go.dev/slices#Sort](https://pkg.go.dev/slices#Sort)). Latin letters come in
alphabetical order, but the `ʻ` (U+02BB) in `oʻ` and `gʻ` does not follow that rule. See it in a small program
(it is not in the course folder, I ran it):

```go
package main

import (
	"fmt"
	"slices"
)

func main() {
	names := []string{"pista", "oʻrik", "olma", "anor"}
	slices.Sort(names)
	fmt.Println(names)
}
```

```console
$ go run .
[anor olma oʻrik pista]
```

`oʻrik` landed between `olma` and `pista`: the comparison sees the letter `o` followed by another character, not the separate letter
`oʻ` of the Uzbek alphabet. Uzbek text and bytes are covered in GB-2.10. One more limit: `%-5s` does not cut a name longer than 5
characters, the column shifts; for a real table you will later need `text/tabwriter` (mentioned in the course README).

```go filename="main.go" showLineNumbers
		if !ok {
			fmt.Fprintln(os.Stderr, "xato:", name, "katalogda yoʻq")
			os.Exit(1)
		}
		count[name]++
		total += price
	}
	var names []string
	for name := range count {
		names = append(names, name)
	}
	slices.Sort(names)
	for _, name := range names {
		fmt.Printf("%-5s %d dona\n", name, count[name])
	}
	fmt.Printf("jami: %d soʻm\n", total/tiyinPerSom)
}
```

|---|---|---|
| 11–14 | `func reserve(stock map[string]int, order []string) error { … }` | the function takes the stock map `stock` and the order `order`, and returns `error`. For now it is empty (`return nil`): you fill it in the task |
| 17–21 | `prices := map[string]int64{ … }` | the catalog: name → price in tiyin, with `choy` too |

| 25–33 | the loop | each name is first looked up in `prices` with comma-ok; if it is missing, the program stops (28–29). If it exists, it is counted in `count` (31) and its price is added to `total` (32) |
| 34–41 | sorting and the receipt | the code from the previous section |
| 42 | `fmt.Printf("jami: %d soʻm\n", total/tiyinPerSom)` | prints the total in soʻm |

## A map passed to a function

The function `restock` adds 10 to the apples through its parameter `s`. In `main`, `stock` had 40 apples. How many are there after the call?
The complete program (it is not in the course folder, I ran it):

```go
package main

import "fmt"

func restock(s map[string]int) {
	s["olma"] += 10
}

func main() {
	stock := map[string]int{"olma": 40}
	restock(stock)
	fmt.Println(stock["olma"])
}
```

**A)** `40` · **B)** `50` · **C)** compile error

<details>
<summary>Answer</summary>

**B: `50`.** Go copies the argument, but a map value is not the table itself, it is its address. In `restock(stock)` the parameter `s` is
a copy of that address, so `s` looks at the same table. If you chose **A**, you thought the function copies the whole table: only the
address is copied. **C**: the code is correct, a map can be passed as a parameter.

</details>

```console
$ go run .
50
```

| Line | `stock` | `s` | table |
|---|---|---|---|
| `stock := map[string]int{"olma": 40}` | address → table | | `olma 40` |
| `restock(stock)` is called | address → table | copy of the address → the **same** table | `olma 40` |
| `s["olma"] += 10` | address → table | address → table | `olma 50` |
| `fmt.Println(stock["olma"])` | | | prints `50` |

A map is a "reference type": the words of the Go blog are *"Map types are reference types"* ([Go maps in action](https://go.dev/blog/maps)).
This matters for the task: `reserve` receives the address of the `stock` table, so for the stock to stay unchanged on an error you must check
everything first and subtract afterwards.

## Going deeper (optional): why exactly three orders and why 75 %

This section is a runtime detail: do not rely on it, it does not matter for your code. In a small map (up to eight keys), since Go 1.24
the keys sit in one group of 8 places in insertion order (if there were no deletions; [Go 1.24 release notes](https://go.dev/doc/go1.24#runtime)).
`range` chooses the starting place at random out of 8 (in the runtime source it is `it.entryOffset = rand()`; I found it in the
`go1.27.4` source, `src/internal/runtime/maps/table.go`, line 757). We have 3 keys and 5 empty places:

| Starting place | 0 | 1 | 2 | 3–7 (empty) |
|---|---|---|---|---|
| Order that comes out | `olma non choy` | `non choy olma` | `choy olma non` | `olma non choy` |

6 of the 8 places give an order that starts with `olma`: 6/8 = 75 %. The other two places give 12.5 % each. This matches our measurement
(about 75 %, 12.5 %, 12.5 %). Only 3 orders appear, not 6: the order starts at a random place, but the keys are not shuffled.

## Common mistakes

### 1. Expecting an error for a missing key

The most common mistake is to write `price := prices[name]` and expect an error when `name` is missing. There is no error:
`price` is `0`. The receipt at the start of the lesson came from this: in `_video/00-hook/main.go` the loop line was `price := prices[name]`, and the pomegranate
was sold for 0 soʻm (the output is in the section "What you will learn"). The fix is comma-ok and `if !ok` (the section "Comma-ok: a missing
key and a zero price" above).

### 2. Writing to a map declared with `var`

`var stock map[string]int`: you know from GB-1.02 that a variable declared without a value holds the zero value. For a map that is `nil`:
there is no table at all. `_video/06-nil/main.go`:

```go filename="_video/06-nil/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var stock map[string]int
	fmt.Println(stock["olma"], len(stock))
	stock["olma"] = 40
	fmt.Println(stock["olma"])
}
```

What does the program print?

**A)** `0 0`, then a panic · **B)** `0 0` and `40` · **C)** compile error

<details>
<summary>Answer</summary>

**A.** Reading from a nil map gives `0`, like an empty map, and `len` is `0` too (line 7). Writing needs a table: on line 8 the runtime
panics. If you chose **B**, you thought a write creates the table by itself: it does not. **C**: the code compiles, the error appears while running.

</details>

```console
$ ./_video/run.sh 06-nil go run .
0 0
panic: assignment to entry in nil map

goroutine 1 [running]:
main.main()
	/tmp/…/bozor/main.go:8 +0xa7
exit status 2
```

(I shortened the path of the temporary folder to `/tmp/…`; the rest is as printed.) How to read it:

- `0 0`: line 7 ran; reading from a nil map and `len` do not fail;
- `panic: assignment to entry in nil map`: "writing to a nil map"; the spec says: *"A nil map is equivalent to an empty map
  except that no elements may be added"* ([Go spec: Map types](https://go.dev/ref/spec#Map_types));
- `main.go:8` is the line with the write, and `goroutine 1 [running]:` and `main.main()` are the chain of calls at the moment of the panic;
- `exit status 2`: the exit code after a panic is 2 (not 1 like an ordinary error, GB-1.07).

The fix: create the map with `make` or a literal (`_video/07-nil-tuzat/main.go`, one line changed):

```go filename="_video/07-nil-tuzat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := make(map[string]int)
	fmt.Println(stock["olma"], len(stock))
	stock["olma"] = 40
	fmt.Println(stock["olma"])
}
```

```console
$ ./_video/run.sh 07-nil-tuzat go run .
0 0
40
```

The rule: a map declared with `var` is good only for reading.

### 3. Relying on the order

A receipt or a test that depends on the `range` order will fail one day. What happens and how to fix it is in the sections
"Range over a map and its order" and "If you need an order: sort the keys": collect the keys, sort them and walk over the slice.

## Check yourself

1. What does a missing key return, and how do you tell it from a real zero?

<details>
<summary>Answer</summary>

The zero value of the value type (`0` for `int64`). Comma-ok tells them apart: `price, ok := prices[name]`; if the key is missing,
`ok` is `false`, and for a zero price it is `true`.

</details>

2. What do you do to print the receipt in the same order every time?

<details>
<summary>Answer</summary>

Collect the keys into a slice (`names = append(names, name)`), sort it with `slices.Sort(names)` and `range` over the slice, not over the map.
The `range` order over a map is not guaranteed.

</details>

3. From GB-1.07: what is in element zero of `os.Args`? So at which index does the order start?

<details>
<summary>Answer</summary>

The program name. So the order starts at index 1: `os.Args[1:]`.

</details>

```go filename="solution/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"slices"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

// reserve buyurtmadagi mahsulotlarni ombordan ayiradi. Biror mahsulot katalogda
// yoʻq boʻlsa yoki yetmasa, xato qaytaradi va omborni oʻzgartirmaydi.
func reserve(stock map[string]int, order []string) error {
	need := make(map[string]int)
	for _, name := range order {
		need[name]++
	}
	// avval hammasini tekshiramiz: shu yerda ombor hali oʻzgarmagan
	for _, name := range order {
		have, ok := stock[name]
		if !ok {
			return fmt.Errorf("%s omborda yoʻq", name)
		}
		if have < need[name] {
			return fmt.Errorf("%s: omborda %d dona, buyurtmada %d", name, have, need[name])
		}
	}
	// keyin ayiramiz: stock chaqiruvchining jadvali, oʻzgarish unga ham koʻrinadi
	for name, n := range need {
		stock[name] -= n
	}
	return nil
}

func main() {
	prices := map[string]int64{
		"olma": 12_000 * tiyinPerSom,
		"non":  4_000 * tiyinPerSom,
		"choy": 25_000 * tiyinPerSom,
	}
	order := os.Args[1:]
	count := make(map[string]int)
	var total int64
	for _, name := range order {
		price, ok := prices[name]
		if !ok {
			fmt.Fprintln(os.Stderr, "xato:", name, "katalogda yoʻq")
			os.Exit(1)
		}
		count[name]++
		total += price
	}
	var names []string
	for name := range count {
		names = append(names, name)
	}
	slices.Sort(names)
	for _, name := range names {
		fmt.Printf("%-5s %d dona\n", name, count[name])
	}
	fmt.Printf("jami: %d soʻm\n", total/tiyinPerSom)
}
```

The idea: `reserve` works in two stages. First it checks everything, then it subtracts. The reason is the previous section: `stock` is the
caller's table, and `stock[name] -= n` is visible to the caller at once. If checking and subtracting were mixed, an error on the second
product would find the first one already subtracted.

- lines 14–17: `need` is a new map made with `make`; `need[name]++` counts the items of the order (`olma non olma` → `olma 2`, `non 1`);
- lines 18–27: a loop over the order; each name is checked with `have, ok := stock[name]`. `!ok` is `omborda yoʻq`, `have < need[name]` is not enough. Nothing
  is written, so when we return with an error, the stock is unchanged;
- lines 28–32: no errors, so `stock[name] -= n` (`x -= n` means `x = x - n`) subtracts. The order does not matter here, so `range` over a map is enough.
