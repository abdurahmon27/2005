## Что вы узнаете

Покупатель заказал в bozor одно яблоко и один гранат. Граната в каталоге нет. Программа не выдала ошибку:

```console
$ ./_video/run.sh 00-hook go run . olma anor
anor  1 dona
olma  1 dona
jami: 12000 soʻm
```

Гранат попал в чек, а итог — это только цена яблока. Почему программа приняла несуществующий товар без ошибки и как его
отклонить?

**Одна идея:** map — таблица, которая находит значение по ключу. Отсутствующий ключ не ошибка: map возвращает нулевое значение
(zero value) типа значения, поэтому «нет» и «ноль» отличает только comma-ok. `range` по map каждый раз начинает с случайного
места: если нужен порядок, ключи сортируете вы сами.

К концу урока вы:

- напишете тип `map[string]int64`, заполните его map-литералом и будете читать, записывать и удалять значения по ключу;
- отклоните товар, которого нет в каталоге, через `price, ok := prices[name]`;
- посчитаете штуки в заказе через `count[name]++`;
- напечатаете чек в одном и том же порядке, отсортировав ключи, и поймёте, почему запись в map, объявленный через `var`,
  вызывает panic.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| map | таблица, которая находит значение по ключу (названию): `map[string]int64` — название → цена | map |
| comma-ok | `price, ok := prices[name]`: вторая переменная `ok` говорит, есть ли ключ в map (`true` / `false`) | comma-ok |
| порядок `range` по map | в каком порядке `range` выдаст ключи, не определено и может меняться от запуска к запуску | map iteration order |

Два вспомогательных понятия: **`make`** для создания пустого map и nil map; а также то, что значение map — это не сама таблица,
а её адрес (при передаче в функцию таблица не копируется).

## Проблема: поиск по названию в списке

Если цены лежат в слайсе, то чтобы найти цену яблока, вы идёте по списку с начала и сравниваете каждое название с «olma». На
50 000 товаров один запрос может дойти до 50 000 сравнений. Это арифметика, а не измерение: чем длиннее список, тем дольше поиск.

## Map: значение по ключу

**Map** решает эту задачу иначе. Он пропускает ключ через **хеш-функцию**: функция делает из текста число. Число указывает
место в таблице, и map сравнивает только ключи в этом месте и возвращает значение. Поэтому время поиска в среднем не зависит от
числа товаров ([Go blog: Go maps in action](https://go.dev/blog/maps)). Внутренняя таблица называется **хеш-таблицей** (hash table).

```text
ключ "olma"  →  хеш (текст → число)  →  место в таблице  →  значение 1200000 (цена яблока, в тиынах)
```

Важное следствие: место выбирает хеш, поэтому ключи в таблице стоят не в порядке добавления и не в алфавитном порядке. Это
понадобится снова в разделе «Порядок `range` по map».

### Тип и литерал

Первая программа (`_video/01-map/main.go`):

```go filename="_video/01-map/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	prices := map[string]int64{
		"olma": 12_000 * tiyinPerSom,
		"non":  4_000 * tiyinPerSom,
	}
	fmt.Println(prices["olma"])
	prices["choy"] = 25_000 * tiyinPerSom
	fmt.Println(len(prices))
	fmt.Println(prices["anor"])
}
```

Строки 1–7 вам знакомы (`package`, `import`, `const`, `func main`). Новые строки:

| Строка | Код | Что делает |
|---|---|---|
| 8 | `prices := map[string]int64{` | создаёт переменную `prices`. `map[string]int64` — тип: в квадратных скобках **тип ключа** (`string`, название товара), после них **тип значения** (`int64`, цена в тиынах). Фигурная скобка открывает map-литерал: map, значения которого записаны прямо в коде |
| 9–10 | `"olma": 12_000 * tiyinPerSom,` | строка литерала: ключ, двоеточие, значение, в конце запятая (как в списке `tests` из GB-1.08) |
| 11 | `}` | закрывает литерал: в map два ключа |
| 12 | `fmt.Println(prices["olma"])` | ключ в квадратных скобках: **чтение** по ключу |
| 13 | `prices["choy"] = 25_000 * tiyinPerSom` | **запись**: если ключа нет, он добавляется, если есть, его значение заменяется |
| 14 | `fmt.Println(len(prices))` | `len` даёт число ключей в map |
| 15 | `fmt.Println(prices["anor"])` | читает `anor`, которого нет в каталоге |

Тип ключа должен сравниваться через `==` ([Go spec: Map types](https://go.dev/ref/spec#Map_types)). `string` — такой тип.

Что напечатает последняя строка? `anor` в map нет.

**A)** `0` · **B)** `panic` (программа аварийно останавливается во время работы) · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**A: `0`.** Для отсутствующего ключа map не выдаёт ошибку: он возвращает нулевое значение (zero value) типа значения. Для `int64`
это `0` ([Go spec: Index expressions](https://go.dev/ref/spec#Index_expressions)). Если вы выбрали **B**, вы вспомнили panic из-за
индекса за границей слайса (GB-1.07): у map такого panic нет. **C** — код верный, компилятор не проверяет, есть ли ключ.

</details>

Первая строка — цена яблока в тиынах (12 000 сумов × 100). Вторая — число ключей после добавления `choy`. Третья — `0` для
отсутствующего `anor`. Именно так гранат в начале урока достался бесплатно.

## Comma-ok: отсутствующий ключ и нулевая цена

Цена `0` тоже бывает (бесплатный товар), и отсутствующий товар тоже даёт `0`. Чтобы их различить, у индексации есть вторая
форма. Вторая программа (`_video/02-ok/main.go`) берёт одно название из командной строки:

```go filename="_video/02-ok/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	prices := map[string]int64{
		"olma": 12_000 * tiyinPerSom,
		"non":  4_000 * tiyinPerSom,
	}
	if len(os.Args) != 2 {
		fmt.Fprintln(os.Stderr, "foydalanish: bozor NOM")
		os.Exit(1)
	}
	name := os.Args[1]
	price, ok := prices[name]
	if !ok {
		fmt.Fprintln(os.Stderr, "xato:", name, "katalogda yoʻq")
		os.Exit(1)
	}
	fmt.Println(name, price/tiyinPerSom, "soʻm")
}
```

| Строка | Код | Что делает |
|---|---|---|
| 15–18 | `if len(os.Args) != 2 { … }` | проверяет число слов, как в GB-1.07: если нет имени программы и одного названия товара, пишет подсказку в stderr и выходит с кодом 1 |
| 19 | `name := os.Args[1]` | `name` — первое слово командной строки (`os.Args[0]` — имя программы) |
| 20 | `price, ok := prices[name]` | слева две переменные: `price` — значение, `ok` — `bool`: `true`, если ключ есть в map, и `false`, если нет. При `false` `price` — zero value, то есть `0` |
| 21–24 | `if !ok { … }` | `!ok`, то есть «ok ложно»: пишет ошибку в stderr и выходит с кодом 1 (GB-1.07) |
| 25 | `fmt.Println(name, price/tiyinPerSom, "soʻm")` | делит цену из тиынов на сумы и печатает |

Форма `v, ok := m[k]` называется **comma-ok**: в коде на Go она встречается очень часто. Три случая:

| Случай | `price` | `ok` |
|---|---|---|
| ключ есть, цена 1 200 000 | `1200000` | `true` |
| ключ есть, цена `0` | `0` | `true` |
| ключа нет | `0` | `false` |

```console
$ ./_video/run.sh 02-ok go run . olma
olma 12000 soʻm
$ ./_video/run.sh 02-ok go run . anor
xato: anor katalogda yoʻq
exit status 1
$ ./_video/run.sh 02-ok go run .
foydalanish: bozor NOM
exit status 1
```

Строку `exit status 1` пишет не сама программа, а `go run`: так он сообщает, что программа завершилась с кодом 1 (GB-1.07). Теперь
«ноль сумов» и «товара нет» — два разных случая.

## Нулевое значение и delete

Третья программа (`_video/03-delete/main.go`) сравнивает ключ с нулевым значением и удалённый ключ:

```go filename="_video/03-delete/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	prices := map[string]int64{
		"olma": 12_000 * tiyinPerSom,
		"non":  4_000 * tiyinPerSom,
	}
	prices["olma"] = 0
	_, ok := prices["olma"]
	fmt.Println(len(prices), ok)
	delete(prices, "non")
	_, ok = prices["non"]
	fmt.Println(len(prices), ok)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 12 | `prices["olma"] = 0` | записывает яблоку ноль: ключ остаётся на месте, меняется только значение |
| 13 | `_, ok := prices["olma"]` | проверяет через comma-ok; значение не нужно, `_` его отбрасывает |
| 14 | `fmt.Println(len(prices), ok)` | печатает число ключей и `ok` |
| 15 | `delete(prices, "non")` | `delete` — встроенная функция Go: первый аргумент — map, второй — удаляемый ключ |
| 16 | `_, ok = prices["non"]` | `ok` уже есть, поэтому здесь `=`, а не `:=` |
| 17 | `fmt.Println(len(prices), ok)` | снова число ключей и `ok` |

Программа печатает две строки, в каждой сначала `len`, потом `ok`. Какой вариант верный?

**A)** `2 true`, затем `1 false` · **B)** `2 false`, затем `1 false` · **C)** `1 false`, затем ещё `1 false`

<details>
<summary>Ответ</summary>

**A.** Яблоко с нулевым значением в map есть: `len` равен 2, `ok` — `true`. После `delete(prices, "non")` остался один ключ, а для
`non` `ok` — `false`. Если вы выбрали **B**, вы приняли нулевую цену за «нет»: ключ с значением `0` остаётся в map. **C** —
`prices["olma"] = 0` не удаляет ключ, а лишь заменяет значение.

</details>

```console
$ ./_video/run.sh 03-delete go run .
2 true
1 false
```

| Строка | `prices` (ключ → значение) | `len` | `ok` |
|---|---|---|---|
| после 12 | `olma → 0`, `non → 4000·100` | 2 | |
| 13–14 | не изменился | 2 | `true` (`olma` есть) |
| после 15 | `olma → 0` | 1 | |
| 16–17 | не изменился | 1 | `false` (`non` нет) |

Удаление отсутствующего ключа через `delete` не ошибка, а пустая операция: спецификация говорит об этом прямо (*«If the map m is
nil or the element m[k] does not exist, delete is a no-op»*, [Go spec: Deletion of map elements](https://go.dev/ref/spec#Deletion_of_map_elements)).
Эту фразу я отдельно не запускал, а процитировал из спецификации.

## Пустой map через make и подсчёт

Чтобы посчитать штуки в заказе, нужен пустой map. Его создаёт `make`. В GB-2.01 `make` выделял массив для слайса, для map он
выделяет пустую таблицу ([Go spec: Making slices, maps and channels](https://go.dev/ref/spec#Making_slices_maps_and_channels)).
Полная программа (этого файла нет в папке курса: я запускал её в отдельной папке):

```go
package main

import "fmt"

func main() {
	order := []string{"olma", "non", "olma"}
	count := make(map[string]int)
	for _, name := range order {
		count[name]++
	}
	fmt.Println(count["olma"], count["anor"])
}
```

```console
$ go run .
2 0
```

`count[name]++` использует правило «отсутствующий ключ даёт ноль»: значение отсутствующего ключа `0`, к нему прибавляем 1 и
записываем. Шаги цикла:

| Шаг цикла | `name` | таблица `count` |
|---|---|---|
| после `make` | | пусто |
| 1 | `olma` | `olma 1` (не было: `0 + 1`) |
| 2 | `non` | `olma 1`, `non 1` |
| 3 | `olma` | `olma 2`, `non 1` (`1 + 1`) |

В конце `count["olma"]` равно 2, а отсутствующий `count["anor"]` — 0. На рисунке в переменной `count` лежит не сама таблица, а её
адрес в памяти, как `ptr` в заголовке слайса (GB-2.01). Названия «таблица» в коде нет: это хеш-таблица, созданная runtime.

```text
count (map[string]int)          хеш-таблица (создана runtime)
┌──────────────┐                ┌─────────┬───┐
│   адрес   ───┼──────────────► │ olma    │ 2 │
└──────────────┘                │ non     │ 1 │
                                └─────────┴───┘
```

## `range` по map и его порядок

Теперь названия приходят из командной строки. Четвёртая программа (`_video/04-tartib/main.go`):

```go filename="_video/04-tartib/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
)

func main() {
	order := os.Args[1:]
	count := make(map[string]int)
	for _, name := range order {
		count[name]++
	}
	for name, n := range count {
		fmt.Println(name, n)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 9 | `order := os.Args[1:]` | `1:` в квадратных скобках — с первого индекса до конца: все слова после имени программы ([Go spec: Slice expressions](https://go.dev/ref/spec#Slice_expressions)) |
| 10–13 | `count := make(…)` и цикл | тот же подсчёт, что в предыдущем разделе |
| 14 | `for name, n := range count {` | `range` по map выдаёт две переменные: `name` — ключ, `n` — значение |
| 15 | `fmt.Println(name, n)` | печатает каждую пару |

два остальных порядка — примерно по одному случаю из восьми. Моё 1-е измерение — блок выше; во втором я ещё раз запустил

Причина в спецификации: *«The iteration order over maps is not specified and is not guaranteed to be the same from one iteration
to the next»* ([Go spec: For statements with range clause](https://go.dev/ref/spec#For_range)). Runtime в начале каждого `range`
выбирает случайное место старта, и сделано это намеренно, чтобы программисты не рассчитывали на порядок ([Go blog](https://go.dev/blog/maps):
*«you should not rely on it»*; [Go 1 release notes](https://go.dev/doc/go1#iteration)). Риск: тест, зависящий от порядка, чаще
всего проходит и однажды падает. Здесь примерно каждый четвёртый запуск даёт другой порядок.

## Нужен порядок: сортируем ключи

Если нужен порядок, вы строите его сами: собираете ключи в слайс, сортируете слайс и идёте по нему. Пятая программа
(`_video/05-sort/main.go`):

```go filename="_video/05-sort/main.go" showLineNumbers
package main

import (
	"fmt"
	"os"
	"slices"
)

func main() {
	order := os.Args[1:]
	count := make(map[string]int)
	for _, name := range order {
		count[name]++
	}
	var names []string
	for name := range count {
		names = append(names, name)
	}
	slices.Sort(names)
	for _, name := range names {
		fmt.Printf("%-5s %d dona\n", name, count[name])
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `"slices"` | новый пакет: `slices` из стандартной библиотеки (поставляется вместе с Go) |
| 15 | `var names []string` | `names` — слайс из `string`; объявлен через `var`, длина 0, `append` может в него добавлять |
| 16–18 | `for name := range count { … }` | если в `range` одна переменная, приходят только ключи; `append` добавляет их в `names` |
| 19 | `slices.Sort(names)` | сортирует список на месте, по возрастанию |
| 20–22 | `for _, name := range names { … }` | печать теперь идёт по `names`, а число берётся из `count[name]` |
| 21 | `fmt.Printf("%-5s %d dona\n", name, count[name])` | `%-5s` пишет название в колонку шириной 5 символов, выравнивая влево |

```console
$ ./_video/run.sh 05-sort go run . olma non olma choy
choy  1 dona
non   1 dona
olma  2 dona
$ ./_video/run.sh 05-sort go run . olma non olma choy
choy  1 dona
non   1 dona
olma  2 dona
```

Два запуска одинаковы: `choy`, `non`, `olma`. Так делают везде, где чек или тест ждёт устойчивый текст.

`slices.Sort` сравнивает строки **по байтам** ([pkg.go.dev/slices#Sort](https://pkg.go.dev/slices#Sort)). Латинские буквы идут в
алфавитном порядке, но `ʻ` (U+02BB) в `oʻ` и `gʻ` под это правило не подпадает. Посмотрите на маленькой программе
(в папке курса её нет, я её запускал):

```go
package main

import (
	"fmt"
	"slices"
)

func main() {
	names := []string{"pista", "oʻrik", "olma", "anor"}
	slices.Sort(names)
	fmt.Println(names)
}
```

```console
$ go run .
[anor olma oʻrik pista]
```

`oʻrik` оказался между `olma` и `pista`: сравнение видит в нём букву `o` и следующий знак, а не отдельную букву `oʻ` узбекского
алфавита. Узбекский текст и байты разбираются в GB-2.10. Ещё одно ограничение: `%-5s` не обрезает название длиннее 5
символов, колонка сдвигается; для настоящей таблицы позже понадобится `text/tabwriter` (упомянут в README курса).

## Map в функции

Функция `restock` через параметр `s` прибавляет к яблокам 10. В `stock` в `main` яблок было 40. Сколько их после вызова?
Полная программа (в папке курса её нет, я её запускал):

```go
package main

import "fmt"

func restock(s map[string]int) {
	s["olma"] += 10
}

func main() {
	stock := map[string]int{"olma": 40}
	restock(stock)
	fmt.Println(stock["olma"])
}
```

**A)** `40` · **B)** `50` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `50`.** Go копирует аргумент, но значение map — это не сама таблица, а её адрес. В `restock(stock)` параметр `s` — копия этого
адреса, поэтому `s` смотрит на ту же таблицу. Если вы выбрали **A**, вы решили, что функция копирует всю таблицу: копируется
только адрес. **C** — код верный: map спокойно передаётся как параметр.

</details>

```console
$ go run .
50
```

| Строка | `stock` | `s` | таблица |
|---|---|---|---|
| `stock := map[string]int{"olma": 40}` | адрес → таблица | | `olma 40` |
| вызван `restock(stock)` | адрес → таблица | копия адреса → **та же** таблица | `olma 40` |
| `s["olma"] += 10` | адрес → таблица | адрес → таблица | `olma 50` |
| `fmt.Println(stock["olma"])` | | | печатается `50` |

Map — «reference type», то есть значение-ссылка на таблицу: слова Go blog — *«Map types are reference types»* ([Go maps in action](https://go.dev/blog/maps)). Для задания
это важно: в `reserve` приходит адрес таблицы `stock`, поэтому, чтобы при ошибке склад не изменился, сначала нужно проверить
всё, а потом списывать.

## Глубже (необязательно): почему именно три порядка и почему 75 %

Этот раздел — деталь runtime: не опирайтесь на неё, для кода она не важна. В маленьком map (до восьми ключей) ключи с Go 1.24
лежат в одной группе из 8 мест в порядке добавления (если не было удалений; [Go 1.24 release notes](https://go.dev/doc/go1.24#runtime)).
`range` выбирает место старта случайно из 8 (в исходниках runtime это `it.entryOffset = rand()`; я нашёл его в исходниках
`go1.27.4`, `src/internal/runtime/maps/table.go`, строка 757). У нас 3 ключа и 5 пустых мест:

| Место старта | 0 | 1 | 2 | 3–7 (пустые) |
|---|---|---|---|---|
| Выпадающий порядок | `olma non choy` | `non choy olma` | `choy olma non` | `olma non choy` |

6 из 8 мест дают порядок, начинающийся с `olma`: 6/8 = 75 %. Остальные два места дают по 12,5 %. Это совпадает с нашим измерением
(около 75 %, 12,5 %, 12,5 %). Выпадают только 3 порядка, а не 6: порядок начинается случайно, но ключи не перемешиваются.

## Частые ошибки

### 1. Ждать ошибку для отсутствующего ключа

Самая частая ошибка — написать `price := prices[name]` и ждать, что для отсутствующего `name` будет ошибка. Ошибки не будет:
`price` равна `0`. Чек в начале урока получился именно так: в `_video/00-hook/main.go` строка цикла была `price := prices[name]`, и гранат
ушёл за 0 сумов (результат — в разделе «Что вы узнаете»). Исправление — comma-ok и `if !ok` (раздел «Comma-ok: отсутствующий
ключ и нулевая цена» выше).

### 2. Запись в map, объявленный через `var`

`var stock map[string]int` — вы знаете из GB-1.02: объявленная без значения переменная получает zero value. Для map это `nil`:
таблицы нет вообще. `_video/06-nil/main.go`:

```go filename="_video/06-nil/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var stock map[string]int
	fmt.Println(stock["olma"], len(stock))
	stock["olma"] = 40
	fmt.Println(stock["olma"])
}
```

Что напечатает программа?

**A)** `0 0`, затем panic · **B)** `0 0` и `40` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**A.** Чтение из nil map даёт `0`, как из пустого map, и `len` тоже `0` (строка 7). Для записи нужна таблица: в строке 8 runtime
выдаёт panic. Если вы выбрали **B**, вы решили, что запись сама создаст таблицу: не создаст. **C** — код компилируется, ошибка
возникает во время работы.

</details>

```console
$ ./_video/run.sh 06-nil go run .
0 0
panic: assignment to entry in nil map

goroutine 1 [running]:
main.main()
	/tmp/…/bozor/main.go:8 +0xa7
exit status 2
```

(Путь к временной папке я сократил до `/tmp/…`; остальное выведено как есть.) Порядок чтения:

- `0 0` — отработала строка 7: чтение из nil map и `len` не дают ошибки;
- `panic: assignment to entry in nil map` — «запись в nil map»; спецификация говорит так: *«A nil map is equivalent to an empty map
  except that no elements may be added»* ([Go spec: Map types](https://go.dev/ref/spec#Map_types));
- `main.go:8` — строка с записью, а `goroutine 1 [running]:` и `main.main()` — цепочка вызовов в момент panic;
- `exit status 2` — код выхода после panic равен 2 (не 1, как у обычной ошибки, GB-1.07).

Исправление: создайте map через `make` или литерал (`_video/07-nil-tuzat/main.go`, изменена одна строка):

```go filename="_video/07-nil-tuzat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := make(map[string]int)
	fmt.Println(stock["olma"], len(stock))
	stock["olma"] = 40
	fmt.Println(stock["olma"])
}
```

```console
$ ./_video/run.sh 07-nil-tuzat go run .
0 0
40
```

Правило: map, объявленный через `var`, годится только для чтения.

### 3. Полагаться на порядок

Чек или тест, зависящий от порядка `range`, в один из дней упадёт. Что происходит и как это исправить, описано в разделах
«`range` по map и его порядок» и «Нужен порядок: сортируем ключи»: соберите ключи, отсортируйте и идите по слайсу.

## Проверьте себя

1. Что возвращает отсутствующий ключ и как отличить его от настоящего нуля?

<details>
<summary>Ответ</summary>

Нулевое значение (zero value) типа значения (`0` для `int64`). Отличает comma-ok: `price, ok := prices[name]`; если ключа нет,
`ok` равно `false`, а при нулевой цене — `true`.

</details>

2. Что нужно сделать, чтобы чек каждый раз печатался в одном порядке?

<details>
<summary>Ответ</summary>

Собрать ключи в слайс (`names = append(names, name)`), отсортировать через `slices.Sort(names)` и выполнять `range` не по map, а по
слайсу. Порядок `range` по map не гарантирован.

</details>

3. Из GB-1.07: что лежит в нулевом элементе `os.Args`? Поэтому с какого индекса начинается заказ?

<details>
<summary>Ответ</summary>

Имя программы. Поэтому заказ начинается с первого индекса: `os.Args[1:]`.

</details>

4. Предскажите. Что напечатает программа?

```go

count["non"]++
count["non"]++
_, ok := count["olma"]
fmt.Println(count["non"], len(count), ok)
```

<details>
<summary>Ответ</summary>

`2 1 false`. `count["non"]++` для отсутствующего ключа записывает `0 + 1`, затем `1 + 1`: значение 2. `olma` не записывали, поэтому в map
один ключ (`non`), а `ok` равно `false`. Полную программу (`package main`, `import "fmt"`, `func main`) я запускал: `2 1 false`.

</details>

```go filename="solution/main.go" showLineNumbers
func reserve(stock map[string]int, order []string) error {
	need := make(map[string]int)
	for _, name := range order {
		need[name]++
	}
	// avval hammasini tekshiramiz: shu yerda ombor hali oʻzgarmagan
	for _, name := range order {
		have, ok := stock[name]
		if !ok {
			return fmt.Errorf("%s omborda yoʻq", name)
		}
		if have < need[name] {
			return fmt.Errorf("%s: omborda %d dona, buyurtmada %d", name, have, need[name])
		}
	}
	// keyin ayiramiz: stock chaqiruvchining jadvali, oʻzgarish unga ham koʻrinadi
	for name, n := range need {
		stock[name] -= n
	}
	return nil
}

func main() {
	prices := map[string]int64{
		"olma": 12_000 * tiyinPerSom,
		"non":  4_000 * tiyinPerSom,
		"choy": 25_000 * tiyinPerSom,
	}
	order := os.Args[1:]
	count := make(map[string]int)
	var total int64
	for _, name := range order {
		price, ok := prices[name]
		if !ok {
			fmt.Fprintln(os.Stderr, "xato:", name, "katalogda yoʻq")
			os.Exit(1)
		}
		count[name]++
		total += price
	}
	var names []string
	for name := range count {
		names = append(names, name)
	}
	slices.Sort(names)
	for _, name := range names {
		fmt.Printf("%-5s %d dona\n", name, count[name])
	}
	fmt.Printf("jami: %d soʻm\n", total/tiyinPerSom)
}
```

Идея: `reserve` работает в два этапа. Сначала проверяет всё, потом списывает. Причина — предыдущий раздел: `stock` — таблица
вызывающего, и `stock[name] -= n` сразу виден ему. Если проверку и списание смешать, то при ошибке на втором товаре первый
уже был бы списан.

- строки 14–17: `need` — новый map через `make`; `need[name]++` считает штуки в заказе (`olma non olma` → `olma 2`, `non 1`);
- строки 18–27: цикл по заказу, каждое название проверяется через `have, ok := stock[name]`. `!ok` — `omborda yoʻq`, `have < need[name]` — не хватает. Ничего не
  записывается, поэтому при возврате с ошибкой склад не изменён;
- строки 28–32: ошибок нет, и `stock[name] -= n` (`x -= n` — это `x = x - n`) списывает. Здесь порядок не важен, поэтому хватает `range` по map.
