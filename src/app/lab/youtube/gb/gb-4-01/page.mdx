## Nimani oʻrganasiz

bozor katalogi endi serverda. Telefon ilovasi 99 raqamli mahsulotni soʻradi va javob oʻrniga xato oldi. Xatoning sababi ilova bilan server almashgan ikki matnda
yozilgan. Bugun biz shu ikki matnni oʻqiymiz.

**Bitta gʻoya:** HTTP almashinuvi — ikki matn. Mijoz soʻrov matnini yuboradi, server javob matnini qaytaradi. Ikkalasi bir xil shaklda: birinchi qator, `nom: qiymat`
koʻrinishidagi header'lar, boʻsh qator, body. Soʻrovning birinchi qatori `method yoʻl versiya`, javobniki `versiya status-kodi sabab`. Status kodining birinchi raqami sinfni
aytadi: `2xx` — muvaffaqiyat, `4xx` — xato soʻrovda, `5xx` — xato serverda. `Content-Type` body qaysi formatda ekanini, `Content-Length` uning uzunligini **baytlarda** aytadi.

Dars oxirida siz:

- `curl -v` chiqishida soʻrovning method, yoʻl va header'larini, javobning status kodi, header'lari va body'sini ajratib oʻqiysiz;
- bir xil soʻrovni `printf` va `nc` bilan qoʻlda yozib yuborasiz: curl ham aynan shu matnni yuboradi;
- `Content-Length` nega belgilarni emas, baytlarni sanashini va `-H` unutilganda server nega `415` qaytarishini tushuntirasiz;
- Go'da soʻrov qatorini ajratadigan `parseRequestLine` va status sinfini aytadigan `statusClass` funksiyalarini yozib, `go test` ni oʻtkazasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| soʻrov va javob (HTTP almashinuvi) | mijoz yuboradigan matn va server qaytaradigan matn | HTTP exchange (request, response) |
| status kodi | javobning birinchi qatoridagi uch xonali son: javob qanday tugadi | status code |
| header | `nom: qiymat` koʻrinishidagi qoʻshimcha qator: body'ni qanday oʻqishni aytadi | header |

Yordamchi soʻzlar: **mijoz** va **server**, **body** (xabarning asosiy qismi), `curl` (terminal'dan soʻrov yuboradigan dastur), `printf` bilan `nc` (soʻrovni qoʻlda yuborish).

## Mijoz, server va manzil

Katalog serveri — soʻrovlarni qabul qilib, javob qaytaradigan dastur. U shu kompyuterda ishlayapti. Soʻrov yuboradigan tomon (masalan, telefon ilovasi) **mijoz** (client) deyiladi.
Ularning gaplashish qoidalari — **HTTP protokoli**: soʻrov va javob qanday yozilishini shu qoidalar belgilaydi.

Serverning manzili bitta qator: `http://localhost:8765/products/1`.

| Qism | Maʼnosi |
|---|---|
| `http://` | protokol: mijoz va server HTTP qoidalari bilan gaplashadi |
| `localhost` | shu kompyuterning oʻzi |
| `:8765` | **port**: kompyuterdagi bitta dasturning tarmoq raqami; server shu raqamni tinglaydi |
| `/products/1` | **yoʻl** (path): qaysi narsa kerak — 1 raqamli mahsulot (`products` — "mahsulotlar") |

## Birinchi soʻrov: curl -v

Unga `curl` bilan soʻrov yuboramiz. `curl` — terminal'dan HTTP soʻrov yuboradigan mijoz dasturi. `-v` bayrogʻi (verbose, "batafsil") yuborilgan va olingan qatorlarni ham koʻrsatadi.
Shu terminalda, serverga qarshi (men uni oʻzim ishga tushirib, ishlatib boʻldim va toʻxtatdim):

```console
$ curl -v http://localhost:8765/products/1
* Host localhost:8765 was resolved.
* IPv6: ::1
* IPv4: 127.0.0.1
*   Trying [::1]:8765...
* connect to ::1 port 8765 from ::1 port 45334 failed: Connection refused
*   Trying 127.0.0.1:8765...
* Established connection to localhost (127.0.0.1 port 8765) from 127.0.0.1 port 41116 
* using HTTP/1.x
> GET /products/1 HTTP/1.1
> Host: localhost:8765
> User-Agent: curl/8.22.0
> Accept: */*
> 
* Request completely sent off
< HTTP/1.1 200 OK
< Content-Type: application/json
< Date: Fri, 27 Nov 2026 07:22:46 GMT
< Content-Length: 49
< 
* Connection #0 to host localhost:8765 left intact
{"id":1,"name":"olma","price":1200000,"stock":40}
```

Chiqishda uch xil qator bor:

| Qator boshi | Nima |
|---|---|
| `*` | ulanish haqida maʼlumot (manzil topildi, ulanish ochildi): HTTP matnining oʻzi emas |
| `>` | curl **yuborgan soʻrov**ning qatori |
| `<` | serverning **javobi**ning qatori; oxirida belgisiz qator — body, mahsulotning oʻzi |

Bu yerda server faqat IPv4 manzilini (`127.0.0.1`) tinglaydi: curl avval `::1` (IPv6) ga urinib, rad etilganini koʻrdi va `127.0.0.1` ga oʻtdi. `*` qatorlar mashinaga bogʻliq, shuning uchun
bundan keyin ularni (va curl'ning `[N bytes data]` qatorlarini) olib tashlayman; videoda ham ular yashirilgan. Qolgani — oʻzgartirilmagan. `Date` qiymati har safar boshqacha boʻladi:
videoda `06:37:46`, mening yurishimda `07:22:46` GMT edi. Hamma qadam bir soniyada ishlagani uchun ketma-ket buyruqlarda `Date` bir xil koʻrinadi.

## Soʻrov matni qatorma-qator

Faqat `>` qatorlari soʻrovning oʻzi:

```http
GET /products/1 HTTP/1.1
Host: localhost:8765
User-Agent: curl/8.22.0
Accept: */*

```

Birinchi qator — **soʻrov qatori**. U uch qismdan iborat, qismlar bitta boʻshliq bilan ajratilgan:

| Qism | Qiymat | Maʼnosi |
|---|---|---|
| **method** | `GET` | nima qilish kerak: bu yerda "olish" |
| yoʻl | `/products/1` | qaysi narsa kerak |
| protokol versiyasi | `HTTP/1.1` | HTTP, bir nuqta bir |

Undan keyingilar — **header**'lar: har biri nom, ikki nuqta, qiymat.

| Qator | Maʼnosi |
|---|---|
| `Host: localhost:8765` | soʻrov qaysi serverga ketayotgani |
| `User-Agent: curl/8.22.0` | soʻrovni kim yuborgani: curl va uning versiyasi |
| `Accept: */*` | qanday javob turini qabul qilishi: yulduzcha, slesh, yulduzcha — har qanday |

Oxirida **boʻsh qator** turadi: u "header'lar tugadi" degani. Bu soʻrovda body yoʻq, shuning uchun boʻsh qatordan keyin hech narsa yoʻq.

## Javob matni qatorma-qator

Endi javob — `<` qatorlari va ularning ostidagi mahsulot:

```http
HTTP/1.1 200 OK
Content-Type: application/json
Date: Fri, 27 Nov 2026 07:22:46 GMT
Content-Length: 49

{"id":1,"name":"olma","price":1200000,"stock":40}
```

Birinchi qator — **status qatori**. U ham uch qismdan iborat:

| Qism | Qiymat | Maʼnosi |
|---|---|---|
| protokol versiyasi | `HTTP/1.1` | HTTP, bir nuqta bir |
| **status kodi** | `200` | uch xonali son: javob qanday tugadi |
| sabab matni | `OK` | odam uchun izoh; dastur kodga qaraydi, matnni eʼtiborsiz qoldiradi |

Header'lar soʻrovdagi kabi: nom, ikki nuqta, qiymat.

| Qator | Maʼnosi |
|---|---|
| `Content-Type: application/json` | body qaysi formatda: `application/json` — JSON |
| `Date: …` | server javobni qachon yasagani, Grinvich vaqti (GMT) bilan |
| `Content-Length: 49` | body necha **bayt**: 49 |

Keyin boʻsh qator: header'lar tugadi, body boshlanadi. Body — mahsulotning oʻzi: `{"id":1,"name":"olma","price":1200000,"stock":40}`. `price` qoʻshtirnoqsiz son:
oldingi savolning javobi shu yerda koʻrinyapti.

## Ikki matn, bitta shakl

Soʻrov ham, javob ham bir xil shaklda:

| Qism | Soʻrovda | Javobda |
|---|---|---|
| birinchi qator | `GET /products/1 HTTP/1.1` (method, yoʻl, versiya) | `HTTP/1.1 200 OK` (versiya, status kodi, sabab) |
| header'lar | `Host: …`, `User-Agent: …`, `Accept: …` | `Content-Type: …`, `Date: …`, `Content-Length: …` |
| boʻsh qator | header'lar tugadi | header'lar tugadi |
| body | bu soʻrovda yoʻq | `{"id":1,…}` |

Faqat birinchi qator farq qiladi: soʻrovda method va yoʻl, javobda status kodi. Qabul qiluvchi shu shaklga tayanadi: boʻsh qatorgacha header'larni oʻqiydi, keyin
`Content-Length`da yozilgan bayt sonicha body oʻqiydi. Body boʻlmasligi ham mumkin.

## Qoʻlda yozamiz: printf va nc

curl bu matnni yuboradi, xolos. Buni qoʻlda tekshiramiz, bitta buyruq bilan. U uch qismdan iborat:

1. `printf` — terminal buyrugʻi: berilgan matnni chiqaradi. Matn ichidagi `\r\n` — qator oxiri: HTTP'da har qator shu ikki bayt (CR va LF) bilan tugaydi.
2. `|` (tik chiziq) — chap buyruqning chiqishini oʻngdagi buyruqqa beradi.
3. `nc` (netcat) — koʻrsatilgan host va portga ulanadi, olgan matnini yuboradi va javobni chiqaradi.

```console
$ printf 'GET /products/1 HTTP/1.1\r\nHost: localhost:8765\r\nConnection: close\r\n\r\n' | nc localhost 8765
HTTP/1.1 200 OK
Content-Type: application/json
Date: Fri, 27 Nov 2026 07:22:38 GMT
Content-Length: 49
Connection: close

{"id":1,"name":"olma","price":1200000,"stock":40}
```

Bitta tirnoq ichidagi matn buyruqqa bitta argument boʻlib boradi. Unda uchta qator va oxirida boʻsh qator bor: soʻrov qatori, `Host` va `Connection: close`
(javobdan keyin ulanishni yoping). Natija — curl koʻrsatgan javobning oʻzi, faqat serverning `Connection: close` qatori qoʻshilgan. curl yoʻq, faqat matn.

`Connection: close` nega kerak? Busiz server ulanishni ochiq qoldiradi va `nc` javobdan keyin ham kutib turadi. Men buni tekshirdim: `timeout 3` bilan (3 soniyadan keyin dasturni toʻxtatadi)
javob chiqadi, keyin buyruq 124 chiqish kodi bilan toʻxtatiladi. Bu buyruq kurs papkasida yoʻq, men oʻzim ishga tushirdim:

```console
$ printf 'GET /products/1 HTTP/1.1\r\nHost: localhost:8765\r\n\r\n' | timeout 3 nc localhost 8765; echo " chiqish kodi: $?"
HTTP/1.1 200 OK
Content-Type: application/json
Date: Fri, 27 Nov 2026 07:23:58 GMT
Content-Length: 49

{"id":1,"name":"olma","price":1200000,"stock":40} chiqish kodi: 124
```

`nc` dasturlari har xil: bu yerda OpenBSD netcat, GNU variantida bayroqlar boshqacha boʻlishi mumkin.

## Status kodi: xato kimning tomonida

**Status kodi** — javobning birinchi qatoridagi uch xonali son. Uning birinchi raqami **sinf**ni aytadi:

| Sinf | Maʼnosi | Misollar |
|---|---|---|
| `2xx` | muvaffaqiyat | `200 OK` — soʻralgan narsa qaytdi; `201 Created` — yangi narsa yaratildi |
| `4xx` | xato **soʻrovda** | `400 Bad Request` — soʻrov notoʻgʻri tuzilgan (masalan, JSON buzuq); `404 Not Found` — server bunday narsani topmadi |
| `5xx` | xato **serverda** | `500 Internal Server Error` |

`1xx` va `3xx` sinflari ham bor; ularni vazifada koʻrasiz.

Bashorat. Ilova 99 raqamli mahsulotni soʻradi, bozor'da esa faqat ikkita mahsulot bor. Soʻrov toʻgʻri tuzilgan. Javobning birinchi qatorida nima boʻladi?

**A)** `HTTP/1.1 200 OK`, body boʻsh · **B)** `HTTP/1.1 404 Not Found` · **C)** `HTTP/1.1 400 Bad Request`

<details>
<summary>Javob</summary>

**B: `404 Not Found`.** Soʻrov toʻgʻri tuzilgan, shuning uchun `400` emas: shunchaki bunday mahsulot yoʻq. **C** ni tanlagan boʻlsangiz, "yoʻq narsani soʻradi" ni "soʻrov buzuq" deb oʻyladingiz;
`400` soʻrovning oʻzi notoʻgʻri boʻlganda keladi. **A** ni tanlagan boʻlsangiz, "muvaffaqiyat" sinfini xatoga aralashtirdingiz: yoʻq narsa uchun `2xx` bermaymiz.

</details>

Mana oʻsha soʻrov: oxirida 99.

```console
$ curl -v http://localhost:8765/products/99
> GET /products/99 HTTP/1.1
> Host: localhost:8765
> User-Agent: curl/8.22.0
> Accept: */*
> 
< HTTP/1.1 404 Not Found
< Content-Type: application/json
< Date: Fri, 27 Nov 2026 07:22:38 GMT
< Content-Length: 30
< 
{"error":"mahsulot topilmadi"}
```

Body ham JSON: `error` kaliti ostida xato matni (`"mahsulot topilmadi"`), ilova uni shu yerdan oladi. Hookdagi xato ham shu edi. Ilovangiz ishda shunday ishlaydi:
avval status kodiga qaraydi, keyin body'ni oʻqiydi. Status kodi muvaffaqiyat boʻlsa, body — kerakli maʼlumot. Xato boʻlsa, body — xato matni.

Qisqa savol. Ilova javobning birinchi qatorida `503` koʻrdi. Xato kimning tomonida?

**A)** soʻrovda: mijoz xato qilgan · **B)** serverda · **C)** aytib boʻlmaydi

<details>
<summary>Javob</summary>

**B: serverda.** `5xx` kod aytadi: server xatoga yoʻl qoʻydi yoki soʻrovni bajara olmadi (`503` — "Service Unavailable", xizmat hozir javob bera olmaydi). Birinchi raqam xato kimning tomonida
ekanini koʻrsatadi, aniq kod esa nima boʻlganini. **A** — bu `4xx` sinfi; **C** — aytib boʻladi, aynan shu uchun sinf bor.

</details>

Serverda boshqa javob ham bor. Katalog `GET /products/{id}` va `POST /products` ni biladi, xolos. Boshqa method bilan soʻrasak, server `405` qaytaradi. Bu videoda yoʻq,
kurs README'sida bor; men ham ishga tushirdim (`-X` — method nomini oʻzingiz aytasiz):

```console
$ curl -v -X DELETE http://localhost:8765/products/1
> DELETE /products/1 HTTP/1.1
> Host: localhost:8765
> User-Agent: curl/8.22.0
> Accept: */*
> 
< HTTP/1.1 405 Method Not Allowed
< Allow: GET, HEAD
< Content-Type: text/plain; charset=utf-8
< X-Content-Type-Options: nosniff
< Date: Fri, 27 Nov 2026 07:24:01 GMT
< Content-Length: 19
< 
Method Not Allowed
```

`405` ham `4xx` sinfida: xato soʻrovda (yoʻl bor, lekin bu method bilan emas). `Allow` header'i qaysi method'lar mumkinligini aytadi.

## Body yuboramiz: POST va Content-Length

Endi body soʻrovning oʻzida. Yangi mahsulot qoʻshish uchun method — `POST`: u serverga body beradi, server undan yangi mahsulot yaratadi. Bu body — mahsulotning JSON'i.
Body qanday formatda va necha bayt ekanini ikki header aytadi: `Content-Type` va `Content-Length`.

Mana body:

```json
{"name":"oʻrik","price":3500000,"stock":5}
```

Bu 42 belgi: `oʻrik` soʻzidagi `oʻ` harfining vergulsimon belgisi (`ʻ`) ham bitta belgi. Bashorat. Soʻrov header'ida `Content-Length` bor: u body'ning uzunligi, **baytlarda**.
Body 42 belgi. `Content-Length` nechta boʻladi?

**A)** 42 · **B)** 43 · **C)** 44

<details>
<summary>Javob</summary>

**B: 43.** `Content-Length` belgilarni emas, baytlarni sanaydi, `ʻ` esa UTF-8'da ikki bayt ([GB-2.10](/lab/youtube/gb/gb-2-10)). **A** ni tanlagan boʻlsangiz, belgi bilan baytni bir xil deb oʻyladingiz;
**C** — faqat bitta belgi ikki bayt, hammasi emas. Tekshiramiz (bu buyruq kurs papkasida yoʻq; `wc -m` UTF-8 locale'da belgilarni, `wc -c` baytlarni sanaydi):

```console
$ printf '{"name":"oʻrik","price":3500000,"stock":5}' | wc -m -c
     42      43
```

</details>

Mana soʻrov. `-d` body'ni beradi, `-H` header qoʻshadi: body JSON ekanini `Content-Type` aytadi. Qoʻsh tirnoq ham bitta argumentni oʻraydi. Server `201 Created` qaytardi:

```console
$ curl -v -d '{"name":"oʻrik","price":3500000,"stock":5}' -H "Content-Type: application/json" http://localhost:8765/products
> POST /products HTTP/1.1
> Host: localhost:8765
> User-Agent: curl/8.22.0
> Accept: */*
> Content-Type: application/json
> Content-Length: 43
> 
< HTTP/1.1 201 Created
< Content-Type: application/json
< Location: /products/3
< Date: Fri, 27 Nov 2026 07:22:38 GMT
< Content-Length: 50
< 
{"id":3,"name":"oʻrik","price":3500000,"stock":5}
```

Soʻrovda: birinchi qator endi `POST /products HTTP/1.1`, ikki yangi header (`Content-Type`, `Content-Length: 43`), boʻsh qatordan keyin esa body (curl uni `>` belgisi bilan chiqarmaydi).
Javobda: `201 Created` — yangi mahsulot yaratildi. `Location` header'i yangi mahsulotning yoʻlini aytadi: `/products/3`. Body'da mahsulot endi `id` bilan: uni server oʻzi berdi.
Javobning `Content-Length: 50`: `oʻ` shu yerda ham bor, 49 belgi va 50 bayt. Videoda `id` 3, chunki serverda ikkita mahsulot bor edi.

## Klassik xato: Content-Type unutildi

Bashorat. Xuddi shu `POST` soʻrovni `-H`siz yuboramiz: header yoʻq, body xuddi shu JSON. Server nima qaytaradi?

**A)** `201 Created` · **B)** `4xx`: xato soʻrovda · **C)** `5xx`: xato serverda

<details>
<summary>Javob</summary>

**B: `4xx`.** Body toʻgʻri edi, header notoʻgʻri: server qaysi format kelganini bilmaydi. **A** ni tanlagan boʻlsangiz, serverga sezgir deb oʻyladingiz — u `Content-Type` ga qaraydi.
**C** — server oʻz ishida xato qilmadi, soʻrov xato edi.

</details>

qoʻllab-quvvatlanmaydi. `4xx` bilan boshlanadi, demak xato soʻrovda: body toʻgʻri edi, header notoʻgʻri. Javob body'sida server sababni yozgan.

Tuzatish — `-H` bilan `Content-Type: application/json`. Endi server `201` qaytaradi. Server oldingi muvaffaqiyatli `POST` ni eslab qolgan, shuning uchun bu safar `id` 4 va `Location: /products/4`:

## Koʻp uchraydigan xatolar

**1. "Javob keldi, demak hammasi yaxshi."** Xato `4xx` yoki `5xx` boʻlsa ham, server toʻgʻri HTTP javobi yuboradi: ulanish ishladi, matn keldi. curl uchun bu muvaffaqiyat:
u `404` da ham chiqish kodi 0 bilan tugaydi. Faqat `-f` (`--fail`) bayrogʻi bilan curl status kodi xato boʻlsa, chiqish kodi 22 qaytaradi. Men ikkalasini ham ishga tushirdim:

```console
$ curl -s http://localhost:8765/products/99; echo " chiqish kodi: $?"
{"error":"mahsulot topilmadi"} chiqish kodi: 0
$ curl -sf http://localhost:8765/products/99; echo "chiqish kodi: $?"
chiqish kodi: 22
```

(`-s` — jim rejim: curl oʻzining oraliq yozuvlarini chiqarmaydi.) Xulosa: status kodiga qarang, chiqish kodiga yoki "javob keldimi" ga emas.

**2. `-H "Content-Type: application/json"` ni unutish.** Natija `415 Unsupported Media Type`; oʻqilishi va tuzatilishi yuqorida, "Klassik xato: Content-Type unutildi" boʻlimida.

**3. `Content-Length` ni belgilar soni deb oʻylash.** `oʻrik` mahsulotida 42 belgi, lekin `Content-Length: 43`: javobi — yuqorida, "Body yuboramiz: POST va Content-Length" boʻlimida.

**4. `printf | nc` da `Connection: close` ni unutish.** `nc` javobdan keyin ham kutib turadi; yuqoridagi `timeout 3` misolida chiqish kodi 124.

**5. Go'da qator oxiridagi `\r\n` ni unutish.** HTTP qatori `\r\n` bilan tugaydi. `strings.Split` ularni olib tashlamaydi, shuning uchun `Proto` `"HTTP/1.1\r\n"` boʻlib qoladi. Mana
`parseRequestLine`ning xato varianti: `solution/main.go` dagi funksiyadan bitta qator — `line = strings.TrimRight(line, "\r\n")` — olib tashlangan; faylning qolgani (`Request`, `statusClass`, `main`) oʻsha fayl. Bu papka kurs repozitoriysida yoʻq,
men uni alohida yaratdim (`go.mod` va `tekshiruv_test.go` — kursdagi bilan bir xil):

```go
func parseRequestLine(line string) (Request, error) {
	parts := strings.Split(line, " ")
	if len(parts) != 3 {
		return Request{}, fmt.Errorf("soʻrov qatori uch qismdan iborat boʻlishi kerak, hozir %d: %q", len(parts), line)
	}
	method, path, proto := parts[0], parts[1], parts[2]
	if method == "" {
		return Request{}, errors.New("method boʻsh")
	}
	if !strings.HasPrefix(path, "/") {
		return Request{}, fmt.Errorf("yoʻl / bilan boshlanishi kerak: %q", path)
	}
	if !strings.HasPrefix(proto, "HTTP/") {
		return Request{}, fmt.Errorf("versiya HTTP/ bilan boshlanishi kerak: %q", proto)
	}
	return Request{Method: method, Path: path, Proto: proto}, nil
}
```

package main

import (
	"errors"
	"fmt"
	"strings"
)

// Request — HTTP soʻrovning birinchi qatoridan olingan uch qism (curl -v'dagi "> GET /products/1 HTTP/1.1").
type Request struct {
	Method string // "GET"
	Path   string // "/products/1"
	Proto  string // "HTTP/1.1"
}

// parseRequestLine "GET /products/1 HTTP/1.1" kabi qatorni qismlarga ajratadi (TASK.md, 1-qadam).
func parseRequestLine(line string) (Request, error) {
	line = strings.TrimRight(line, "\r\n") // HTTP qatori \r\n bilan tugaydi
	parts := strings.Split(line, " ")
	if len(parts) != 3 {
		return Request{}, fmt.Errorf("soʻrov qatori uch qismdan iborat boʻlishi kerak, hozir %d: %q", len(parts), line)
	}
	method, path, proto := parts[0], parts[1], parts[2]
	if method == "" {
		return Request{}, errors.New("method boʻsh")
	}
	if !strings.HasPrefix(path, "/") {
		return Request{}, fmt.Errorf("yoʻl / bilan boshlanishi kerak: %q", path)
	}
	if !strings.HasPrefix(proto, "HTTP/") {
		return Request{}, fmt.Errorf("versiya HTTP/ bilan boshlanishi kerak: %q", proto)
	}
	return Request{Method: method, Path: path, Proto: proto}, nil
}

// statusClass status kodi qaysi sinfga kirishini aytadi (TASK.md, 2-qadam).
func statusClass(code int) string {
	switch {
	case code >= 100 && code < 200:
		return "axborot"
	case code >= 200 && code < 300:
		return "muvaffaqiyat"
	case code >= 300 && code < 400:
		return "yoʻnaltirish"
	case code >= 400 && code < 500:
		return "mijoz xatosi"
	case code >= 500 && code < 600:
		return "server xatosi"
	}
	return "nomaʼlum"
}

func main() {
	req, err := parseRequestLine("GET /products/1 HTTP/1.1")
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	fmt.Println(req.Method, req.Path, req.Proto)
	fmt.Println(404, statusClass(404))
}
