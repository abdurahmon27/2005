## Nimani oʻrganasiz

bozor handler'lari GB-4.03'da testdan oʻtdi. Lekin `curl http://localhost:8765/health` hozir `Failed to connect` beradi: 8765-portda hech kim tinglamayapti.
Savol: handler'larni portga qanday ulaymiz va ulangan dastur nega tugamaydi?

**Bitta gʻoya:** server — ikki qism. `ServeMux` — yoʻl → handler jadvali: `mux.HandleFunc(pattern, handler)` jadvalga bitta yozuv qoʻshadi,
handler qavssiz beriladi (funksiyaning oʻzi, chaqiruvi emas). Oxiri sleshsiz pattern faqat aynan shu yoʻlga mos; mos pattern boʻlmasa `ServeMux` oʻzi `404 page not found` yozadi.
`ListenAndServe(addr, handler)` — portni ochadi, ulanishlarni kutadi va har soʻrovda `mux.ServeHTTP(w, r)`ni chaqiradi. Server ishlab turganda bu sikl tugamaydi:
funksiya **faqat server toʻxtaganda** qaytadi va qaytgan qiymat doim xato. `http.ListenAndServe` — `&http.Server{Addr, Handler}` yasab, uning `ListenAndServe` metodini chaqiradigan qisqa yoʻl.

Dars oxirida siz:

- `http.NewServeMux` va `mux.HandleFunc` bilan yoʻl → handler jadvalini yasab, har qatorini tushuntirasiz;
- `http.ListenAndServe(":8765", mux)` portni ochishini, nega qaytmasligini va qaytsa nega doim xato ekanini aytasiz;
- ishlab turgan serverni ikkinchi terminaldan `curl` bilan tekshirib, `Ctrl+C` bilan toʻxtatasiz va `bind: address already in use` xatosini oʻqiysiz;
- `newServer(addr) *http.Server` funksiyasini oʻzingiz yozib, `go test .` ni oʻtkazasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| `ServeMux` | soʻrov yoʻliga qarab handler tanlaydigan jadval: yoʻl → handler | ServeMux (multiplexer) |
| `ListenAndServe` | portni ochadigan, ulanishlarni kutadigan va handler'ni chaqiradigan funksiya; server ishlab turganda qaytmaydi | ListenAndServe |
| server tashqaridan | ishlab turgan server — alohida jarayon: uni ikkinchi terminaldagi `curl` tekshiradi, `Ctrl+C` toʻxtatadi; port band boʻlsa xato chiqadi | port, `address already in use` |

Yordamchi soʻzlar: `http.HandleFunc` bilan `nil` (umumiy `DefaultServeMux`) va `http.Server` struct'i bilan `ReadHeaderTimeout`. Boshqa yangi nomlarning hammasiga yoʻlda bitta jumla beraman.

## Muammo: portda hech kim tinglamayapti

Hozirgi holatni oʻz koʻzingiz bilan koʻring. Hech qanday server ishlamayapti; `curl` bilan `/health`ga soʻrov yuboramiz:

```console
$ curl http://localhost:8765/health
curl: (7) Failed to connect to localhost:8765 after 0 ms: Could not connect to server
```

Xabarni oʻqiymiz:

| Qism | Maʼnosi |
|---|---|
| `curl: (7)` | `curl`ning oʻz xabari; `7` — `curl`ning «ulana olmadim» xato kodi (chiqish kodi ham `7`) |
| `Failed to connect` | ulanib boʻlmadi |
| `to localhost:8765` | `localhost` — shu kompyuter, `8765` — **port**: dastur manzilining raqami ([GB-4.02](/lab/youtube/gb/gb-4-02)) |
| `after 0 ms` | 0 millisekunddan keyin: javob kutilmadi, ulanish darrov rad etildi |
| `Could not connect to server` | serverga ulanib boʻlmadi |

(Videoda bu qatorning oʻrtasi `…` bilan yashirilgan; bu yerda toʻliq.) Ikkala qism ham bir narsani aytadi: bu portda hech qanday dastur ulanish kutmayapti.

Handler'lar bor, lekin ularni hech kim chaqirmaydi. Server yasash uchun ikki ish kerak:

1. soʻrov yoʻliga qarab qaysi handler chaqirilishini aytadigan jadval;
2. portni ochib, ulanishlarni kutadigan va soʻrov kelganda shu jadvalga murojaat qiladigan dastur.

Birinchisi `ServeMux`, ikkinchisi `ListenAndServe`. Avval bitta soʻrov serverda qanday oʻtishini koʻramiz.

|---|---|
| 1 | portga ulanish keladi (`:8765`) |
| 2 | server soʻrov matnini oʻqiydi: birinchi qator `GET /health HTTP/1.1` ([GB-4.01](/lab/youtube/gb/gb-4-01)) |

## ServeMux: yoʻl → handler jadvali

`main`ning birinchi qatori — `func main() {` ([GB-1.01](/lab/youtube/gb/gb-1-01)). Undan keyingi birinchi qator:

```go
	mux := http.NewServeMux()
```

| Qism | Maʼnosi |
|---|---|
| `http` | `net/http` paketining nomi |
| `NewServeMux()` | shu paketdagi funksiya: yangi, **boʻsh** `ServeMux` yasaydi |
| `:=` | yangi oʻzgaruvchi yaratadi va natijani unga beradi ([GB-1.02](/lab/youtube/gb/gb-1-02)) |
| `mux` | oʻzgaruvchining nomi: nomni biz tanladik |

**`ServeMux`** nomi *multiplexer* soʻzidan: bitta kirishdagi koʻp soʻrovni yoʻliga qarab turli handler'larga taqsimlaydi. Amalda bu jadval: har yozuvda yoʻl va handler. Hozir u boʻsh.

Ikkinchi qator jadvalga birinchi yozuvni qoʻshadi:

```go
	mux.HandleFunc("/health", healthHandler)
```

| Qism | Maʼnosi |
|---|---|
| `mux.HandleFunc(...)` | `mux`ning metodi: jadvalga bitta yozuv qoʻshadi |
| `"/health"` | birinchi argument — **pattern**: qaysi yoʻlga mos kelishi |
| `healthHandler` | ikkinchi argument — shu yoʻl kelganda chaqiriladigan handler |

E'tibor bering: `healthHandler` **qavssiz**. `healthHandler(w, r)` yozsak, funksiya shu zahoti chaqirilardi. Biz esa funksiyani hozir chaqirmaymiz: uning **oʻzini** `mux`'ga beramiz.
`mux` uni keyin, `/health` soʻrovi kelgan har safar, oʻsha soʻrovning `w` va `r`i bilan chaqiradi. Qavs yozilsa nima boʻlishini «Koʻp uchraydigan xatolar» boʻlimida koʻrasiz.

Uchinchi qator — ikkinchi yozuv:

```go
	mux.HandleFunc("/products", catalogHandler)
```

Endi jadvalda ikki yozuv bor. Bu hali server emas: port ochilmadi, hech narsa tinglamayapti.

| Pattern | Handler |
|---|---|
| `"/health"` | `healthHandler` |
| `"/products"` | `catalogHandler` |
| boshqa yoʻl | ? |

Jadvalda yoʻq yoʻl kelsa nima boʻlishini bir ozdan keyin sinab koʻramiz.

## ListenAndServe: portni ochish va kutish

Keyingi qator manzilni ekranga chiqaradi:

```go
	fmt.Println("bozor API: http://localhost:8765")
```

`fmt.Println` ([GB-1.01](/lab/youtube/gb/gb-1-01)) matnni chiqaradi; `http://localhost:8765` — serverga `curl` yuboradigan manzil. Undan keyingi qator — dastur yuragi:

```go
	err := http.ListenAndServe(":8765", mux)
```

`ListenAndServe` — *Listen and Serve*: «tingla va xizmat qil». Ikkita argument oladi:

| Argument | Maʼnosi |
|---|---|
| `":8765"` | **manzil**: ikki nuqta va port raqami. Host yozilmagan |
| `mux` | **handler**: har soʻrovni kim hal qilishi |

**Manzil.** Host yozilmasa, server shu kompyuterning **hamma** tarmoq manzillarida tinglaydi; `localhost` ham shular ichida. Demak bir tarmoqdagi boshqa kompyuterlar ham ulana oladi.
Faqat shu kompyuter ulanishi kerak boʻlsa, `"localhost:8765"` yoziladi. (`ss -ltn` bu holatni `*:8765` deb koʻrsatadi: yulduzcha — «hamma manzil».)

**Handler.** `ListenAndServe`ning ikkinchi argumenti turi `http.Handler`: ichida `ServeHTTP` metodi boʻlgan har qanday qiymat ([GB-4.03](/lab/youtube/gb/gb-4-03)).
`ServeMux`da `ServeHTTP` metodi bor, demak u ham `http.Handler`. Server har soʻrovda `mux.ServeHTTP(w, r)`ni chaqiradi, `mux` esa yoʻlga qarab bizning handler'ni.

**Natija.** `ListenAndServe` bitta qiymat qaytaradi — `error`. Biz uni `err`ga yozamiz. Keyingi ikki qator ([GB-1.07](/lab/youtube/gb/gb-1-07)dagidek):

```go
	fmt.Fprintln(os.Stderr, "xato:", err)
	os.Exit(1)
```

Birinchisi xatoni stderr'ga yozadi, ikkinchisi dasturni `1` kodi bilan tugatadi. Bu ikki qator faqat `ListenAndServe` qaytganda ishlaydi, yaʼni qachon — buni birozdan keyin koʻramiz.

Mana butun dastur (`~/bozor-04/main.go`):

```go filename="_video/02-server/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
	"os"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/health", healthHandler)
	mux.HandleFunc("/products", catalogHandler)

	fmt.Println("bozor API: http://localhost:8765")
	err := http.ListenAndServe(":8765", mux)
	fmt.Fprintln(os.Stderr, "xato:", err)
	os.Exit(1)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `package main` | bu fayl `main` paketida ([GB-1.01](/lab/youtube/gb/gb-1-01)). Bir papkadagi hamma `.go` fayl shu paketda: `handlers.go`dagi `healthHandler` shu yerda koʻrinadi |
| 3–7 | `import (…)` | `fmt` (chiqarish), `net/http` (server), `os` (`Stderr`, `Exit`) |
| 9 | `func main() {` | dastur shu yerdan boshlanadi |
| 10 | `mux := http.NewServeMux()` | boʻsh yoʻllar jadvali |
| 11 | `mux.HandleFunc("/health", healthHandler)` | jadvalga yozuv: `/health` → `healthHandler` |
| 12 | `mux.HandleFunc("/products", catalogHandler)` | jadvalga yozuv: `/products` → `catalogHandler` |
| 14 | `fmt.Println(…)` | manzilni ekranga chiqaradi |
| 15 | `err := http.ListenAndServe(":8765", mux)` | portni ochadi, soʻrovlarga xizmat qiladi; qaytsa — xatoni `err`ga beradi |
| 16 | `fmt.Fprintln(os.Stderr, "xato:", err)` | xatoni stderr'ga yozadi |
| 17 | `os.Exit(1)` | dasturni `1` kodi bilan tugatadi |

### Bashorat: `go run .` nima qiladi?

<details>

**A** ni tanlagan boʻlsangiz, `ListenAndServe`ni oddiy funksiya deb oʻyladingiz: u chaqiriladi, ishini qiladi, qaytadi. Bu funksiya esa server ishlab turganda qaytmaydi. **C** ni tanlasangiz, port band deb oʻyladingiz; port boʻsh boʻlsa xato chiqmaydi (band port — oxirgi boʻlimlarda).

</details>

```console
$ go run .
bozor API: http://localhost:8765
```

Manzil chiqdi, lekin buyruq satri (`$`) qaytmadi: dastur `ListenAndServe` ichida soʻrov kutyapti. Mana nima boʻlayotgani:

| Qadam | `ListenAndServe` ichida |
|---|---|
| 1 | port ochiladi (`:8765`) |
| 2 | ulanish kutadi: tinglaydi |
| 3 | ulanish kelsa, xizmat qiladi: `mux.ServeHTTP(w, r)` |
| 4 | yana kutadi: 2-qadamga qaytadi |
| — | sikl tugamaydi: funksiya shu yerdan chiqmaydi |

Funksiya **faqat server toʻxtaganda** qaytadi: port ochilmasa (masalan, band boʻlsa) yoki dastur serverni oʻzi toʻxtatsa (bu [GB-8.03](/lab/youtube/gb#gb-8-03)da). Qaytgan qiymat **doim xato**: Go hujjati shunday deydi
(*«ListenAndServe always returns a non-nil error»*). Shuning uchun 16–17-qatorlar faqat server ishlamay qolganda ishlaydi. Har ulanish alohida xizmat qilinadi; bir vaqtda kelgan soʻrovlar — [GB-4.07](/lab/youtube/gb#gb-4-07)da.

## Serverni ikkinchi terminaldan tekshiramiz

Birinchi terminal band, shuning uchun ikkinchisini ochamiz. Bu terminalda boshdagi `curl`ni yuboramiz:

```console
$ curl http://localhost:8765/health
ok
```

`-v` siz `curl` faqat body'ni chiqaradi: `ok` — `healthHandler` javob berdi. Endi katalog:

```console
$ curl http://localhost:8765/products
[{"id":1,"name":"olma","price":1200000,"stock":40},{"id":2,"name":"non","price":400000,"stock":120},{"id":3,"name":"oʻrik","price":3500000,"stock":5}]
```

Uchta mahsulot, JSON massiv ([GB-3.02](/lab/youtube/gb/gb-3-02); narx tiyinda). Bu `catalogHandler`ning javobi.

Eslab qoling: manzilni chiqargan qator serverning ishlayotganini isbotlamaydi — u `ListenAndServe`dan **oldin** chiqadi. Server ishlayotganini `curl`ning javobi isbotlaydi.
(Server har soʻrovni birinchi terminalga yozmaydi: u yerda hech narsa chiqmaydi. Log — [GB-8.02](/lab/youtube/gb#gb-8-02)da.)

Port haqiqatan ochiqmi, deb operatsion tizimdan ham soʻrash mumkin. Bu buyruq videoda yoʻq: `ss` ochiq ulanishlarni koʻrsatadi (`-l` — tinglayotganlar, `-t` — TCP, `-n` — raqamlar bilan), `grep 8765` faqat shu portli qatorni qoldiradi:

```console
$ ss -ltn | grep 8765
LISTEN 0      4096               *:8765             *:*
```

`LISTEN` — port tinglanyapti, `*:8765` — hamma manzillarda, 8765-portda.

### Bashorat: jadvalda yoʻq yoʻl

Jadvalda `/health` va `/products` bor. `curl http://localhost:8765/products/1` nima qaytaradi?

**A)** butun katalog: `/products` mos keladi · **B)** `404 page not found` · **C)** `405 Method Not Allowed`

<details>
<summary>Javob</summary>

**B.** `"/products"` patterni oxiri sleshsiz: u faqat aynan `/products` yoʻlga mos, `/products/1`ga emas. Mos pattern topilmasa `ServeMux` oʻzi `404` javobini yozadi.
**A** ni tanlagan boʻlsangiz, pattern «shu bilan boshlanadigan hamma yoʻl» deb oʻyladingiz; bunday qoida faqat oxiri sleshli patternda (pastda). **C**: `405` — yoʻl topilib, metod notoʻgʻri boʻlganda chiqadi; bu yerda yoʻlning oʻzi topilmadi.

</details>

`-i` `curl`ga javobning status qatori va header'larini ham chiqarishni aytadi:

```console
$ curl -i http://localhost:8765/products/1
HTTP/1.1 404 Not Found
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 11:23:51 GMT
Content-Length: 19

404 page not found
```

(`Date` sizda boshqa boʻladi. Videoda header qatorlari `…` bilan yashirilgan.)

| Qator | Maʼnosi |
|---|---|
| `HTTP/1.1 404 Not Found` | status qatori ([GB-4.01](/lab/youtube/gb/gb-4-01)): kod `404`, sababi `Not Found` |
| `Content-Type: text/plain; charset=utf-8` | body — oddiy matn |
| `X-Content-Type-Options: nosniff` | `ServeMux` xato javobiga qoʻshadigan xavfsizlik header'i; bu darsda unga tegmaymiz |
| `Date: …` | javob vaqti |
| `Content-Length: 19` | body uzunligi baytlarda: `404 page not found` 18 belgi + qator oxiri = 19 bayt |
| (boʻsh qator) | header'lar tugadi, body boshlanadi |
| `404 page not found` | body: `ServeMux`ning oʻz xabari |

Bu javobni bizning handler'lardan hech biri yozmadi: mos pattern topilmagach, `ServeMux`ning oʻzi yozdi.

### Pattern qoidasi

| Pattern | Qaysi yoʻllarga mos |
|---|---|
| `"/products"` (oxirida slesh yoʻq) | faqat aynan `/products` |
| `"/products/"` (oxirida slesh bor) | shu bilan boshlanadigan hamma yoʻl: `/products/1`, `/products/abc/def` … |
| metod yozilmagan (hamma patternimiz shunday) | har qanday metod |

Oxirgi qatorning isboti: `POST` ham `catalogHandler`ga keladi, u esa faqat `GET`ni qabul qiladi:

```console
$ curl -i -X POST http://localhost:8765/products
HTTP/1.1 405 Method Not Allowed
Allow: GET
Date: Fri, 27 Nov 2026 11:23:51 GMT
Content-Length: 0

```

`-X POST` metodni `POST` qiladi. `405` va `Allow: GET` ni `catalogHandler` yozdi ([GB-4.03](/lab/youtube/gb/gb-4-03)); yoʻl topildi, metod mos kelmadi. Oxiridagi boʻsh qator — boʻsh body.
Metodni patternning oʻziga yozish va bitta pattern bilan hamma ID'ni olish (`/products/{id}`) — [GB-4.05](/lab/youtube/gb#gb-4-05)da.

Oxiri sleshli patternni ham sinab koʻramiz. Bu dasturning **butun** `main.go`'si; `handlers.go` oldingisi. U kurs papkasida yoʻq: men uni alohida yozib ishga tushirdim (qoralama papkasi: `scratchpad/gb404/extra2`):

```go
package main

import (
	"fmt"
	"net/http"
	"os"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/products/", catalogHandler)

	fmt.Println("bozor API: http://localhost:8765")
	err := http.ListenAndServe(":8765", mux)
	fmt.Fprintln(os.Stderr, "xato:", err)
	os.Exit(1)
}
```

Jadvalda bitta yozuv: `"/products/"` → `catalogHandler`. Soʻrovlar:

```console
$ curl -i http://localhost:8765/products/1
HTTP/1.1 200 OK
Content-Type: application/json
Date: Fri, 27 Nov 2026 11:25:41 GMT
Content-Length: 152

[{"id":1,"name":"olma","price":1200000,"stock":40},{"id":2,"name":"non","price":400000,"stock":120},{"id":3,"name":"oʻrik","price":3500000,"stock":5}]
```

`/products/1` — `/products/` bilan boshlanadi, shuning uchun `catalogHandler` javob berdi (u yoʻlga qaramaydi, shuning uchun hammasini beradi). `/products/a/b` ham xuddi shunday `200` oldi. `/products`ning oʻzi esa:

```console
$ curl -i http://localhost:8765/products
HTTP/1.1 307 Temporary Redirect
Content-Type: text/html; charset=utf-8
Location: /products/
Date: Fri, 27 Nov 2026 11:25:41 GMT
Content-Length: 46
```

`ServeMux` oxiri sleshli pattern bor, sleshsiz yoʻl kelsa, mijozni `Location: /products/`ga yoʻnaltiradi (hujjatda shunday). Bu darsda asosiy narsa: sleshsiz pattern bitta yoʻl, sleshli — butun «novda».
Videodagi serverda pattern oxiri sleshsiz va `/products/1` uchun hech narsa yoʻq, shuning uchun `404`. GB-4.01'dagi tayyor serverda bu yoʻl bor edi, bizda yoʻq.

## DefaultServeMux: nega koʻp misollarda `mux` yoʻq

Koʻp misollarda `mux` yoʻq. `http.HandleFunc` toʻgʻridan-toʻgʻri chaqiriladi, `ListenAndServe`ga esa handler oʻrniga `nil` beriladi. Mana shunday dastur (qolgan fayl oldingidek):

```go filename="_video/05-default/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
	"os"
)

// Koʻp misollardagi shakl: http.HandleFunc va nil — DefaultServeMux (umumiy, global mux).
func main() {
	http.HandleFunc("/health", healthHandler)

	fmt.Println("bozor API: http://localhost:8765")
	err := http.ListenAndServe(":8765", nil)
	fmt.Fprintln(os.Stderr, "xato:", err)
	os.Exit(1)
}
```

Bu kod ishlaydi (men ishga tushirdim):

```console
$ curl http://localhost:8765/health
ok
$ curl http://localhost:8765/products
404 page not found
```

`/products` `404` berdi, chunki bu variantda uni roʻyxatga olmadik. Lekin `http.HandleFunc` yoʻlni **qayerga** yozdi?
`http.HandleFunc` yoʻlni **`DefaultServeMux`**ga yozadi: `net/http` paketining ichidagi bitta umumiy `ServeMux`. `ListenAndServe`ning ikkinchi argumenti `nil` boʻlsa, server shu `DefaultServeMux`ni ishlatadi.

U umumiy: dasturga qoʻshilgan **istalgan paket** unga oʻz yoʻlini yozishi mumkin. Masalan, profiler paketi `net/http/pprof` oʻzi `/debug/pprof/…` yoʻllarini qoʻshadi:
ular dastur xotirasi va buyruq qatorini koʻrsatadi (manba: [pkg.go.dev/net/http/pprof](https://pkg.go.dev/net/http/pprof); buni men ishga tushirib koʻrmadim, hujjatdan keltirdim).
Oʻz `mux`'imizda esa faqat biz yozgan yoʻllar bor. Shuning uchun ishda oʻz `ServeMux`'ni yasaymiz.

## http.Server: ListenAndServe ichida nima bor

Endi `ListenAndServe`ning oʻz kodiga qaraymiz: `net/http` manbasi, `go1.27.4`, `src/net/http/server.go` (izohlar tushirilgan). Bu paketning oʻz kodi, shuning uchun `Server` va `Handler` oldida `http.` yoʻq:

```go
func ListenAndServe(addr string, handler Handler) error {
	server := &Server{Addr: addr, Handler: handler}
	return server.ListenAndServe()
}
```

| Qator | Maʼnosi |
|---|---|
| 1 | funksiya manzil va handler oladi, `error` qaytaradi: bizning chaqiruvimiz |
| 2 | `Server` struct'ini yasaydi: `Addr` (manzil) va `Handler` maydonlari bilan; `&` — unga koʻrsatkich ([GB-2.04](/lab/youtube/gb/gb-2-04)), `Server{…}` — struct yozuvi ([GB-2.03](/lab/youtube/gb/gb-2-03)). Natija `server` oʻzgaruvchisida |
| 3 | `Server`ning `ListenAndServe` **metodini** chaqiradi va uning natijasini qaytaradi |

Demak biz ishlatgan funksiya — qisqa yoʻl. Ishda server odatda shu shaklda yoziladi, chunki struct'ga yana sozlamalar qoʻshiladi:

```go
	srv := &http.Server{
		Addr:    ":8765",
		Handler: mux,
	}
	fmt.Println("bozor API: http://localhost:8765")
	err := srv.ListenAndServe()
```

`srv` — `Server`ga koʻrsatkich; `srv.ListenAndServe()` xuddi oʻsha ishni qiladi: portni ochadi va ulanish kutadi. Endi struct'ga uchinchi maydon qoʻshamiz:

```go filename="_video/06-http-server/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
	"os"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/health", healthHandler)
	mux.HandleFunc("/products", catalogHandler)

	srv := &http.Server{
		Addr:              ":8765",
		Handler:           mux,
		ReadHeaderTimeout: 5 * time.Second,
	}
	fmt.Println("bozor API: http://localhost:8765")
	err := srv.ListenAndServe()
	fmt.Fprintln(os.Stderr, "xato:", err)
	os.Exit(1)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7 | `"time"` | `time` paketi: `time.Second` shu yerdan ([GB-4.02](/lab/youtube/gb/gb-4-02)) |
| 15 | `srv := &http.Server{` | `http.Server` struct'ini yasab, koʻrsatkichini `srv`ga beradi |
| 16 | `Addr: ":8765",` | manzil: `ListenAndServe(":8765", …)`dagi birinchi argument |
| 17 | `Handler: mux,` | handler: ikkinchi argument |
| 18 | `ReadHeaderTimeout: 5 * time.Second,` | mijoz soʻrov header'larini qancha vaqtda yuborib boʻlishi kerak: 5 soniya |
| 19 | `}` | struct yozuvi tugadi (koʻp qatorli yozuvda har maydondan keyin vergul) |
| 21 | `err := srv.ListenAndServe()` | `http.ListenAndServe`dagi ish: port, kutish, xato |

`ReadHeaderTimeout` nolga teng boʻlsa (va `ReadTimeout` ham berilmagan boʻlsa), server header'larni **cheksiz** kutadi — [GB-4.02](/lab/youtube/gb/gb-4-02)dagi client `Timeout`i nol boʻlgandek.
`5 * time.Second` — besh soniya: sarlavha kelmasa, server ulanishni yopadi. Bu ish qiladimi? Hech narsa yubormaydigan ulanishni sinab koʻramiz.

### Oʻlchov: jim ulanish

Hech narsa yubormaydigan TCP ulanish. Bu buyruq videoda koʻrsatilmaydi (faqat natijasi aytiladi), kurs README'sida bor; birinchi terminalda server ishlab turganda ikkinchisida ishga tushiriladi:

```console
$ bash -c 'exec 3<>/dev/tcp/127.0.0.1/8765; s=$SECONDS; timeout 12 cat <&3; echo "kod $? · $((SECONDS-s)) s"'
```

| Qism | Maʼnosi |
|---|---|
| `exec 3<>/dev/tcp/127.0.0.1/8765` | 8765-portga TCP ulanish ochadi (`3` — fayl raqami); hech narsa yubormaydi |
| `s=$SECONDS` | boshlangan vaqtni eslab qoladi |
| `timeout 12 cat <&3` | serverdan kelgan baytlarni oʻqiydi, lekin 12 soniyadan oshsa uzadi |
| `echo "kod $? · …"` | `cat`ning chiqish kodi va oʻtgan soniyalar |

`kod 0` — `cat` oʻzi tugadi, yaʼni server ulanishni yopdi; `kod 124` — `timeout` 12 soniyadan keyin uzdi, yaʼni ulanish hali ochiq edi.
`06-http-server` (`ReadHeaderTimeout: 5 * time.Second`) bilan ishlab turgan server:

```console
$ bash -c 'exec 3<>/dev/tcp/127.0.0.1/8765; s=$SECONDS; timeout 12 cat <&3; echo "kod $? · $((SECONDS-s)) s"'
kod 0 · 5 s
```

`02-server` (muddat yoʻq) bilan:

```console
$ bash -c 'exec 3<>/dev/tcp/127.0.0.1/8765; s=$SECONDS; timeout 12 cat <&3; echo "kod $? · $((SECONDS-s)) s"'
kod 124 · 12 s
```

Videoda ikki raqam aytiladi: 5 soniya va 12 soniya. Mening mashinamda ham xuddi shu: **5 s** va **12 s**. Bu raqamlar mashina tezligiga bogʻliq emas; muhimi — nisbat: server 5 soniyada oʻzi yopdi, muddatsiz esa ulanish biz kutganchalik ochiq qoldi.
(12 soniya — serverning xususiyati emas, mening `timeout 12`im: «12 soniyada ham yopilmadi» degani.) Har ochiq ulanish server resursini band qiladi, shuning uchun muddat kerak.

Ikki cheklov. Birinchidan, bu muddat faqat soʻrov header'larini oʻqishni cheklaydi. Bitta soʻrov yuborib, keyin jim turgan ulanishni emas: keyingi soʻrovni kutish `IdleTimeout` (u ham 0 boʻlsa — `ReadTimeout`) bilan cheklanadi, ikkalasi nol boʻlsa — cheksiz.
Bu holatni men oʻlchamadim; manba — kurs README'si va `server.go` ([pkg.go.dev: Server](https://pkg.go.dev/net/http#Server)). Ikkinchidan, qolgan muddatlar va serverni toʻgʻri toʻxtatish — [GB-8.03](/lab/youtube/gb#gb-8-03)da.

## Koʻp uchraydigan xatolar

### 1. `ListenAndServe` xatosini tashlab yuborish

Eng koʻp uchraydigan xato: `ListenAndServe`ning natijasi tekshirilmaydi, qaytgan xato tashlab yuboriladi. Birinchi terminalda toʻgʻri server (`02-server`) yana ishlab turibdi. Ikkinchi terminalda esa — buzilgan nusxa.
Bu nusxa alohida papkada: `err` qatorlari yoʻq, `os` importi ham olib tashlangan (nega — pastda):

```go filename="_video/03-xato-yoq/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/health", healthHandler)
	mux.HandleFunc("/products", catalogHandler)

	fmt.Println("bozor API: http://localhost:8765")
	http.ListenAndServe(":8765", mux) // XATO: qaytgan error tashlab yuborildi
}
```

Port hozir band: unda birinchi terminaldagi server. Ikkinchi terminalda buzilgan nusxani `go run .` qilsak, nima boʻladi?

**A)** ikkinchi server ham ishlaydi · **B)** dastur jim tugaydi, xabar yoʻq · **C)** `panic`

<details>
<summary>Javob</summary>

**B.** Bitta manzil va portni bir vaqtda faqat bitta dastur tinglay oladi; ikkinchi `ListenAndServe` ishga tusha olmaydi va xato qaytaradi. Lekin xato tashlab yuborilgan, `main` esa tugadi.
**A** boʻlmaydi: port band. **C** ham yoʻq: xato `panic` emas, oddiy qaytgan qiymat; uni tekshirmasak, hech narsa sodir boʻlmaydi.

</details>

```console
$ go run .
bozor API: http://localhost:8765
$ echo $?
0
```

Dastur darhol tugadi. Manzil qatori `ListenAndServe`dan oldin chiqadi, shuning uchun u hech narsani isbotlamaydi. `echo $?` ([GB-1.07](/lab/youtube/gb/gb-1-07)) oxirgi buyruqning chiqish kodini koʻrsatadi: `0` — muvaffaqiyat.
Server ishlamayapti, lekin hech narsa buni aytmaydi. Ishda bu: dastur xatosiz tugagandek koʻrinadi, soʻrovlar esa hech qayoqqa kelmaydi.

Toʻgʻri nusxa (xato tekshiriladi, `02-server` bilan bir xil) shu holatda shunday javob beradi:

```console
$ go run .
bozor API: http://localhost:8765
xato: listen tcp :8765: bind: address already in use
exit status 1
```

Qatorni qismlarga boʻlib oʻqiymiz:

| Qism | Maʼnosi |
|---|---|
| `xato:` | bizning `fmt.Fprintln(os.Stderr, "xato:", err)` qatorimizning boshi |
| `listen tcp :8765` | TCP portini ochish urinishi; TCP — HTTP ishlaydigan ulanish protokoli, `:8765` — bizning manzil |
| `bind` | portni dasturga biriktiradigan operatsion tizim chaqiruvi ([bind(2)](https://man7.org/linux/man-pages/man2/bind.2.html)) |
| `address already in use` | manzil band |
| `exit status 1` | `go run`ning xabari: dastur `os.Exit(1)` bilan tugadi |

Portni kim egallaganini koʻrish (videoda yoʻq):

```console
$ ss -ltnp 'sport = :8765'
State  Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
LISTEN 0      4096               *:8765            *:*    users:(("bozor",pid=1037182,fd=3))
```

`users:(("bozor",pid=…))` — portni `bozor` dasturi egallagan (`pid` — jarayon raqami, sizda boshqa). Qoida: `ListenAndServe` qaytdimi, demak server ishlamayapti.
Xatoni doim chiqaring va noldan farqli kod bilan chiqing. Port band boʻlsa, eski serverni toʻxtating yoki boshqa port bering. Ishda dastur serverda ishga tushmay qolsa, birinchi qaraladigan qator — shu.

`mux.HandleFunc("/health", healthHandler())` — qavs bilan yozilsa, funksiya jadvalga berilmaydi, balki shu qatorda chaqiriladi. Men buni sinadim (qoralama papkasi: `scratchpad/gb404/extra3`; `main.go` toʻliq):

## Oʻzingizni tekshiring

**1.** `ListenAndServe` qachon qaytadi?

<details>
<summary>Javob</summary>

Faqat server toʻxtaganda: port ochilmasa yoki dastur serverni toʻxtatsa. Qaytgan qiymat doim xato.

</details>

**2.** Jadvalda faqat `"/products"` bor. `/products/1` nima oladi?

<details>
<summary>Javob</summary>

`404 page not found`: oxiri sleshsiz pattern faqat aynan shu yoʻlni oladi.

</details>

**3.** [GB-4.01](/lab/youtube/gb/gb-4-01)dan: `Content-Length` belgilarni sanaydimi yoki baytlarni? `/products` javobi uchun tekshiring.

<details>
<summary>Javob</summary>

Baytlarni. `oʻrik` — besh belgi, lekin olti bayt: `ʻ` (vergulsimon belgi, U+02BB) ikki bayt ([GB-2.10](/lab/youtube/gb/gb-2-10)). Server ishlab turganda men buni oʻlchadim; bu buyruqlar kurs papkasida yoʻq:

```console
$ curl -s http://localhost:8765/products | wc -c
152
$ curl -s http://localhost:8765/products | LC_ALL=C.UTF-8 wc -m
151
```

`wc -c` baytlarni, `wc -m` belgilarni sanaydi (`-s` — `curl`ning jimlik rejimi). 152 bayt, 151 belgi: farq — `ʻ`ning ikkinchi bayti. `Content-Length: 152` ham shuni aytadi (yuqoridagi `/products/1` javobiga qarang).

</details>

**4.** Bashorat: jadvalda `"/health"` bor, `curl -i http://localhost:8765/health/` (oxirida slesh!) birinchi qatorda nima beradi?

<details>
<summary>Javob</summary>

`HTTP/1.1 404 Not Found`. `"/health"` oxiri sleshsiz: u faqat `/health`ga mos, `/health/`ga emas. Men ishga tushirdim:

```console
$ curl -i http://localhost:8765/health/ | head -1
HTTP/1.1 404 Not Found
```

(`| head -1` javobning birinchi qatorinigina qoldiradi.) Butun javob esa `/products/1`dagidek: `404 page not found` body bilan.

</details>

**5.** `":8765"` manziliga boshqa kompyuter ulana oladimi? Faqat shu kompyuter ulanishi uchun nima yoziladi?

<details>
<summary>Javob</summary>

Ha: host yozilmagan, server hamma manzillarda tinglaydi, bir tarmoqdagi boshqa kompyuter ham ulana oladi. Faqat shu kompyuter uchun `"localhost:8765"`. Konteynerda esa aynan hamma manzillar kerak (GB-8 moduli).

</details>

- 🟢 **1-qadam, yoʻllar jadvali.** Yangi `ServeMux` yasang va unga uchta yozuv qoʻshing: `/health` → `healthHandler`, `/products` → `catalogHandler`, `/products/1` → `productHandler` (olma). `/products/2` `404` boʻlib qolsin: faqat aynan `/products/1`.
- 🟡 **2-qadam, server.** `*http.Server` qaytaring: `Addr` — funksiyaga kelgan `addr`, `Handler` — sizning `mux`ingiz, `ReadHeaderTimeout` — 5 soniya. Fayl boshidagi `import (…)`ga `"time"`ni qoʻshing.

Maslahatlar:

- 1-qadam: yuqoridagi «ServeMux» boʻlimi. Handler'ni qavssiz bering: funksiyani chaqirmaymiz, uning oʻzini beramiz.
- `/products/1`ni oxiri sleshli (`/products/`) yozsangiz, u `/products/` bilan boshlanadigan hamma yoʻlni oladi va `/products/2` ham olma qaytaradi: test buni ushlaydi.
- 2-qadam: yuqoridagi `http.Server` struct yozuvi. Faqat `5` yozilsa, bu 5 soniya emas, 5 nanosoniya: `time.Duration` nanosoniyalarda sanaydi. Test buni ham ushlaydi.

<summary>Javob: solution/main.go dagi newServer</summary>

Avval oʻzingiz urinib koʻring. Javob — kurs repozitoriysidagi [`solution/main.go`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-4-04-birinchi-server/solution/main.go); `newServer`:

```go
func newServer(addr string) *http.Server {
	mux := http.NewServeMux()
	mux.HandleFunc("/health", healthHandler)
	mux.HandleFunc("/products", catalogHandler)
	mux.HandleFunc("/products/1", productHandler) // {id} bilan hamma ID uchun bitta pattern: GB-4.05

	return &http.Server{
		Addr:              addr,
		Handler:           mux,
		ReadHeaderTimeout: 5 * time.Second, // soʻrov sarlavhalari 5 s'da kelmasa, ulanish yopiladi
	}
}
```

Qatorma-qator:

| Qator | Kod | Nima qiladi |
|---|---|---|
| 2 | `mux := http.NewServeMux()` | boʻsh yoʻllar jadvali |
| 3–5 | `mux.HandleFunc(…)` | uch yozuv: `/health`, `/products`, `/products/1`; handler'lar qavssiz. `/products/1` oxiri sleshsiz: `/products/2` — `404` |
| 7 | `return &http.Server{` | `Server` struct'ini yasab, koʻrsatkichini qaytaradi |
| 8 | `Addr: addr,` | manzil — funksiyaga kelgan parametr (`main` `":8765"` beradi, test `"127.0.0.1:0"`) |
| 9 | `Handler: mux,` | `mux` — handler |
| 10 | `ReadHeaderTimeout: 5 * time.Second,` | 5 soniya; `5 * time.Second` — `Duration` |
