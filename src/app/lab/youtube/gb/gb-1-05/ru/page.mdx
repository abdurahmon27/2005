## Что вы узнаете

Если в bozor вместо количества придёт −3, программа молча отработает: чая на складе станет не 40, а 43, а НДС в чеке
выйдет как `-719.-64`. Компилятор ничего не скажет, потому что −3 — правильный `int`. Какое значение имеет смысл, он
не знает. Как остановить неверный заказ до того, как напечатан чек и уменьшен склад?

**Одна идея:** сравнение даёт значение `true` или `false`. `if` и `switch` по этому значению выбирают один блок, а
после блока программа продолжается: чтобы остановить неверный заказ, нужен `return`.

К концу урока вы:

- сравниваете два значения через `==`, `!=`, `<`, `<=`, `>`, `>=` и соединяете условия через `&&`, `||`, `!`;
- пишете `if`, `else if`, `else` и при ошибке выходите из `main` через `return`;
- пишете `if` с коротким объявлением (`if left := …; left < 0`) и читаете ошибку `undefined: left`;
- выбираете через `switch` одно из нескольких условий: цену доставки по сумме заказа.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| сравнение и логическая операция | сравнение двух значений (`sold > 0`) даёт `bool`: `true` или `false`; `&&` (и), `\|\|` (или), `!` (не) соединяют несколько условий | comparison, logical operators |
| `if` / `else` | если условие `true`, выполняется блок внутри `{ }`, если `false` — пропускается; `else` — когда условие `false` | if statement |
| `switch` | выполняет первый подходящий `case` из нескольких и на этом заканчивается; если не подошёл ни один — `default` | switch statement |

Два вспомогательных слова: **`return`** завершает функцию в этом месте (в этом уроке `main`, а значит, программу); и
**область видимости** (по-английски **scope**) — часть кода, где видно имя.

## Исходное состояние: отрицательное количество

Это bozor из прошлого урока, вместе с заданием. Изменена только строка 25: `sold` теперь −3:

```go filename="_video/01-manfiy/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := -3
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100
	total := subtotal + vat + deliverySom*tiyinPerSom

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5–7 | `const …` | GB-1.03: 1 сум = 100 тийинов, НДС 12 %, доставка 15 000 сумов |
| 10–23 | `fmt.Println(…)`, `var …`, `:=` | GB-1.01–1.02: строки запуска и версии, нулевые значения, товар и склад. Сегодня их не трогаем |
| 25 | `sold := -3` | продано штук: **−3**. Единственное изменение |
| 26 | `stock = stock - sold` | склад должен был уменьшиться: 40 − (−3) = 43, склад вырос |
| 29–31 | `subtotal`, `vat`, `total` | расчёт из GB-1.03, в тийинах: 199 900 × (−3) = −599 700; НДС −71 964 |
| 33–37 | `fmt.Sprintf`, `fmt.Printf` | чек из GB-1.04: `%9d` сумы, `.`, `%02d` тийины |

choy 43
choy, -3 dona      -5997.00

Компилятор молчит: −3 — правильный `int`. Склад 43, суммы отрицательные. Посмотрите на `-719.-64` в строке НДС (`QQS`).
НДС в тийинах равен −71 964. `-71964 / 100` = −719, `-71964 % 100` = −64: в Go остаток берёт знак делимого
(спецификация Go, Integer operators). Поэтому минус появился и после точки. Формат чека `%9d.%02d` верен только для
нулевых и положительных сумм. Значит, отрицательная сумма не должна доходить до чека.

Для этого нужны три вещи:

1. **сравнение**: сравнить два значения, результат — `true` или `false` (`sold > 0`);
2. **`if`**: выполнить или пропустить код по условию и остановиться через `return`;
3. **`switch`**: выбрать одно из нескольких условий (цену доставки).

Правила для названия, продажи и цены вы напишете сами в домашнем задании.

## Сравнение: результат — `bool`

Решение начинается со сравнения:

```go filename="_video/02-bool/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := -3
	ok := sold > 0
	fmt.Println(ok)
}
```

В строке 7 `>` — знак «больше»: больше ли `sold` нуля? Результат — не число, а тип **`bool`** из GB-1.02: `true` или
`false`. −3 не больше нуля, поэтому в новую переменную `ok` записывается `false`. `:=` берёт тип из значения, значит,
`ok` — это `bool`. В памяти, строка за строкой:

| Строка | Код | `sold` (`int`) | `ok` (`bool`) | На экране |
|---|---|---|---|---|
| 6 | `sold := -3` | −3 | — | |
| 7 | `ok := sold > 0` | −3 | `false` (−3 > 0 ?) | |
| 8 | `fmt.Println(ok)` | −3 | `false` | `false` |

```console
$ ./_video/run.sh 02-bool
false
```

В Go шесть операторов **сравнения** (comparison operators). Результат каждого — `bool`:

| Оператор | Смысл | Пример, `sold` = 7 | Результат |
|---|---|---|---|
| `==` | равно | `sold == 7` | `true` |
| `!=` | не равно | `sold != 7` | `false` |
| `<` | меньше | `sold < 7` | `false` |
| `<=` | меньше или равно | `sold <= 7` | `true` |
| `>` | больше | `sold > 0` | `true` |
| `>=` | больше или равно | `sold >= 10` | `false` |

Осторожно: **одиночный** `=` — не сравнение, а присваивание (GB-1.02). Равенство проверяют **два** знака равенства,
`==`. Строки (`string`) тоже можно сравнивать через `==`: `name == "choy"` даёт `true`, если `name` ровно `"choy"`
(«чай»).

**Типы обеих сторон должны совпадать.** `sold` — `int`, `price` — `int64`. Если написать `sold > price`, компилятор
выдаст ошибку `mismatched types` из GB-1.03 (полный пример — в разделе «Частые ошибки»). А `sold > 0` работает: `0` —
нетипизированная константа, она сама принимает тип `sold`, то есть `int`.

### Логические операции: `&&`, `||`, `!`

Часто одного условия мало: количество должно быть положительным **и** не больше остатка на складе. Для этого есть
**логические операции** (logical operators):

```go filename="_video/03-mantiq/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := 7
	stock := 40
	ok := sold > 0 && sold <= stock
	bad := sold <= 0 || sold > stock
	fmt.Println(ok, bad, !ok)
}
```

- `&&` (два амперсанда) — логическое **и**: результат `true`, только если обе стороны `true`.
- `||` (две вертикальные черты) — логическое **или**: достаточно одной стороны `true`.
- `!` (восклицательный знак) — **отрицание**: превращает `true` в `false`, а `false` в `true`.

| `a` | `b` | `a && b` | `a \|\| b` |
|---|---|---|---|
| `true` | `true` | `true` | `true` |
| `true` | `false` | `false` | `true` |
| `false` | `true` | `false` | `true` |
| `false` | `false` | `false` | `false` |

В строке 8 нет скобок. Они и не нужны: сравнения (`>`, `<=`) вычисляются раньше `&&` и `||` (спецификация Go,
Operator precedence). Поэтому `sold > 0 && sold <= stock` = `(sold > 0) && (sold <= stock)`.

`sold` равно 7, `stock` — 40. Что будет на экране?

**A)** `true false false` · **B)** `true true false` · **C)** `true false true`

<details>
<summary>Ответ</summary>

**A: `true false false`.** `ok`: 7 > 0 → `true`, 7 &lt;= 40 → `true`, `true && true` → `true`. `bad` спрашивает обратное
обоим условиям: 7 &lt;= 0 → `false`, 7 > 40 → `false`, `false || false` → `false`. `!ok` → `false`. Если вы выбрали
**B**, вы прочитали `||` не как «хотя бы одно»: здесь обе стороны `false`. В **C** забыт `!`: `!ok` — это
противоположность `ok`.

</details>

| Строка | Код | Вычисление | Результат |
|---|---|---|---|
| 8 | `ok := sold > 0 && sold <= stock` | `true && true` | `ok` = `true` |
| 9 | `bad := sold <= 0 \|\| sold > stock` | `false \|\| false` | `bad` = `false` |
| 10 | `fmt.Println(ok, bad, !ok)` | `!true` | на экране `true false false` |

## `if`: если условие `true`, блок выполняется

Первое правило: количество — не меньше 1 штуки. Оно стоит после строки, где объявлен `sold`, и до списания со склада:

```go filename="_video/04-if/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := -3
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
	}
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100
	total := subtotal + vat + deliverySom*tiyinPerSom

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 26 | `if sold <= 0 {` | ключевое слово `if`, затем условие `sold <= 0`, без скобок; в конце открывающая фигурная скобка |
| 27 | `fmt.Println("xato: …")` | строка внутри блока: выполняется, только если условие `true` («xato» — «ошибка») |
| 28 | `}` | блок закончился |

Правила **`if`** (спецификация Go, If statements):

- условие может быть только `bool`. Если написать `if sold {`, компилятор откажет: `sold` — число, а не `bool`;
- если условие `true`, выполняется **блок** внутри `{ }`; если `false`, Go его пропускает;
- фигурные скобки нужны всегда, даже если в блоке одна строка. Открывающая `{` стоит на той же строке, как в
  `func main() {`;
- круглые скобки вокруг условия не нужны. `if (sold > 0) {` тоже скомпилируется, но `gofmt` уберёт скобки, поэтому в
  коде на Go их не пишут.

`sold` равно −3, условие `true`, блок выполняется. Что выведет `go run .`?

**A)** только строку ошибки · **B)** строку ошибки, а затем чек · **C)** ошибку компиляции

<details>
<summary>Ответ</summary>

**B.** Выводится строка ошибки, а потом всё равно склад 43 и отрицательный чек. `if` управляет только своим блоком:
после закрывающей `}` программа продолжается со следующей строки. Если вы выбрали **A**, вы думали, что вывод ошибки
останавливает программу: не останавливает. Код написан правильно, поэтому и не **C**.

</details>

## `return`: остановиться здесь

Чтобы остановиться, добавим в блок **`return`**. Файл такой же, как `04-if`, добавлена только строка 28. Его строки
25–31:

```go
	sold := -3
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)
```

`return` завершает функцию в этом месте: строки после него не выполняются. Это `main`, а когда заканчивается `main`,
заканчивается и программа (GB-1.01). `return`, который возвращает значение, увидим в [GB-1.07](/lab/youtube/gb/gb-1-07/ru).
Полный файл: `_video/05-return/main.go`.

```console
$ ./_video/run.sh 05-return
bozor ishga tushdi
versiya: 0.1.0
 0 false
choy 199900 true 40 1.5
xato: miqdor kamida 1 dona boʻlishi kerak
```

Теперь после строки ошибки нет ни строки склада, ни чека. Эта форма очень часто встречается в коде на Go: проверить
неверный случай в начале и сразу выйти (по-английски *guard clause*, *early return*). Основной расчёт не уходит в
лишние скобки, а остаётся у левого края. Go Code Review Comments называет это «Indent Error Flow». Effective Go пишет
то же самое: если ошибочный случай заканчивается `return`, лишний `else` не пишут. Так не пишут:

```go
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
	} else {
		stock = stock - sold
		// … butun hisob va chek shu qavslar ichida, bir pogʻona oʻngda
	}
```

Пока есть одно упрощение. Сообщение об ошибке пишется туда же, куда и чек, — в стандартный вывод (stdout). А программа
завершается с кодом выхода 0, то есть «успешно»: операционная система не знает, что была ошибка. Запись ошибки в
отдельный поток (stderr) и сообщение о неудаче (`os.Exit(1)`) — в [GB-1.07](/lab/youtube/gb/gb-1-07/ru).

## Одиночный `=` в условии

Теперь ошибка, которая часто встречается в условиях. Хотели проверить нулевое количество и вместо `==` написали один
`=`. Файл такой же, как `05-return`, отличаются только строки 25–26:

```go
	sold := 0
	if sold = 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
```

На вид это проверка, но одиночный `=` — присваивание. В этом файле намеренная синтаксическая ошибка, поэтому в папке он
лежит под именем `_video/06-teng-xato/main.go.txt`: как файл `.go` он помешал бы `gofmt` и `go vet` прочитать всю
папку. `run.sh` копирует его как `main.go`:

```console
$ ./_video/run.sh 06-teng-xato
# github.com/abdurahmon27/bozor
./main.go:26:10: syntax error: cannot use assignment sold = 0 as value
```

Читаем сообщение:

- `./main.go:26:10` — строка 26, столбец 10: знак `=` (Tab — один столбец, `if` — столбцы 2–3, `sold` — 5–8, `=` — 10);
- `syntax error` — синтаксическая ошибка: компилятор не смог прочитать код;
- `cannot use assignment sold = 0 as value` — «присваивание `sold = 0` нельзя использовать как значение».

В Go присваивание не даёт результата, это отдельная инструкция (спецификация Go, Assignment statements). А условие
ждёт значение `bool`. Поэтому ошибка ловится до запуска программы. Исправление: `==`, а в нашем правиле — `<=` (отказ
и для нуля, и для отрицательных).

## `if` с коротким объявлением: правило склада

Второе правило: нельзя продать больше, чем есть на складе. На этот раз заказ — 50 штук (строка 25), а на складе 40:

```go filename="_video/07-ombor/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 50
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100
	total := subtotal + vat + deliverySom*tiyinPerSom

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

`if` в строке 30 другой: перед условием стоит **короткое объявление**.

| Часть | Код | Что делает |
|---|---|---|
| объявление | `left := stock - sold` | сколько штук останется на складе после продажи; `left` («остаток») — новая переменная |
| разделитель | `;` | точка с запятой отделяет объявление от условия |
| условие | `left < 0` | если остаток отрицательный, на складе не хватает |
| строка 31 | `fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)` | `-left` — минус `left`: делает число недостающих штук положительным («ошибка: на складе не хватает … шт.») |
| строка 32 | `return` | ни чека, ни списания со склада |

Go сначала выполняет объявление, потом проверяет условие (спецификация Go: «The expression may be preceded by a simple
statement, which executes before the expression is evaluated»):

| Шаг | Что происходит | `left` | Результат |
|---|---|---|---|
| 1 | `left := stock - sold` → 40 − 50 | −10 | |
| 2 | `left < 0` → −10 &lt; 0 | −10 | `true`: блок выполняется |
| 3 | `-left` → −(−10) | −10 | на экране `xato: omborda 10 dona yetmaydi` |
| 4 | `return` | | `main` заканчивается |

Если `stock` равно 40 и `sold` равно 40, `left` будет 0: 0 &lt; 0 — `false`, заказ проходит. Весь чай со склада продать
можно.

```console
$ ./_video/run.sh 07-ombor
bozor ishga tushdi
versiya: 0.1.0
 0 false
choy 199900 true 40 1.5
xato: omborda 10 dona yetmaydi
```

### Где виден `left`

Теперь выведем `left` на строке после закрывающей `}` у `if` (`08-scope`, добавлена строка 34):

```go
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	fmt.Println(left)
```

`stock` равно 40, `sold` — 50. Что произойдёт?

**A)** выведется `-10` · **B)** выведется `0` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**C.** Ошибка компиляции: `undefined: left`, то есть «`left` не определён». Переменная из короткого объявления видна
только внутри этого `if`, после закрывающей `}` такого имени нет. Если вы выбрали **A**, вы думали, что `left`
относится к `main`. **B** — предположение, что `left` остаётся с нулевым значением: имени нет вообще, о значении и
речи нет.

</details>

```console
$ ./_video/run.sh 08-scope
# github.com/abdurahmon27/bozor
./main.go:34:14: undefined: left
```

`./main.go:34:14` — строка 34, столбец 14: `left` внутри `fmt.Println(`. Место, где видно имя, называется **областью
видимости**, по-английски **scope**. Спецификация Go (Blocks): «Each if, for, and switch statement is considered to be
in its own implicit block» — каждый `if`, `for` и `switch` находится в собственном неявном блоке:

```text
func main() {                          ← блок main: name, price, stock, sold …
    if left := stock - sold; left < 0 {   ← начинается блок if: здесь появляется left
        … -left …                      ← left виден
    }                                  ← блок if закончился: left нет
    fmt.Println(left)                  ← undefined: left
}
```

`left` виден в условии и блоке `if` (и в блоках `else`, привязанных к этому `if`). Так вспомогательное имя живёт
только там, где оно нужно, и его нельзя по ошибке использовать в коде ниже.

## `else if` и `else`: цена доставки

Теперь цена доставки. Заказ: урюк (`oʻrik`), по 25 000 сумов, 24 штуки. Правило:

| Сумма товара | Доставка |
|---|---|
| 500 000 сумов и больше | 0 (бесплатно) |
| 100 000 сумов и больше | 10 000 сумов |
| всё остальное | 15 000 сумов (`deliverySom`) |

```go filename="_video/09-elseif/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "oʻrik"
	price = 25_000 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 24
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100

	var delivery int64 // tiyinda
	if subtotal >= 500_000*tiyinPerSom {
		delivery = 0
	} else if subtotal >= 100_000*tiyinPerSom {
		delivery = 10_000 * tiyinPerSom
	} else {
		delivery = deliverySom * tiyinPerSom
	}
	total := subtotal + vat + delivery

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", delivery/tiyinPerSom, delivery%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 18–19, 25 | `name = "oʻrik"`, `price = 25_000 * tiyinPerSom`, `sold := 24` | новый заказ: 25 000 × 24 = 600 000 сумов |
| 40 | `var delivery int64 // tiyinda` | объявление без значения: пока нулевое значение 0 (GB-1.02). Значение даст один из трёх путей ниже |
| 41–42 | `if subtotal >= 500_000*tiyinPerSom {` | сумма в тийинах, поэтому граница в сумах умножена на `tiyinPerSom`; с 500 000 сумов бесплатно |
| 43–44 | `} else if subtotal >= 100_000*tiyinPerSom {` | **`else if`**: если условие выше `false`, ещё одно условие; с 100 000 сумов — 10 000 сумов |
| 45–47 | `} else {` | **`else`**: если все условия выше `false`; 15 000 сумов |
| 48 | `total := subtotal + vat + delivery` | итог теперь берётся из `delivery` |
| 53 | `"yetkazish", delivery/tiyinPerSom, delivery%tiyinPerSom` | строка доставки в чеке (`yetkazish`) тоже |

Условия проверяются сверху вниз. Выполняется блок первого условия, которое `true`, остальные не проверяются. `else` и
`else if` стоят на одной строке с закрывающей `}`: если после `}` начать новую строку, будет ошибка компиляции
(«Частые ошибки», пункт 4).

В этом заказе сумма товара — 600 000 сумов (60 000 000 тийинов):

| Условие | Значение | Что происходит |
|---|---|---|
| `subtotal >= 500_000*tiyinPerSom` | `true` | `delivery = 0` |
| `subtotal >= 100_000*tiyinPerSom` | не проверяется | — |
| `else` | — | — |

## `switch`: первый `true` case

Ту же цепочку `if`, `else if`, `else` удобнее читать как **`switch`**. Effective Go говорит то же: «it's idiomatic to
write an if-else-if-else chain as a switch». Файл такой же, как `09-elseif`, отличаются только строки 41–48. Его
строки 40–49:

```go
	var delivery int64 // tiyinda
	switch {
	case subtotal >= 500_000*tiyinPerSom:
		delivery = 0
	case subtotal >= 100_000*tiyinPerSom:
		delivery = 10_000 * tiyinPerSom
	default:
		delivery = deliverySom * tiyinPerSom
	}
	total := subtotal + vat + delivery
```

| Строка | Код | Что делает |
|---|---|---|
| 41 | `switch {` | после `switch` ничего нет: это **switch без выражения**, каждый `case` принимает условие `bool` |
| 42–43 | `case subtotal >= 500_000*tiyinPerSom:` | слово `case`, условие, двоеточие; ниже — строки этого `case` |
| 44–45 | `case subtotal >= 100_000*tiyinPerSom:` | следующий `case` по тому же шаблону |
| 46–47 | `default:` | выполняется, когда ни один `case` не `true` |
| 48 | `}` | `switch` закончился |

Спецификация Go: `switch` без выражения — то же, что `switch true`. То есть Go ищет первый `case`, который `true`.
Полный файл: `_video/10-switch/main.go`.

Сумма 600 000 сумов, значит, и первый `case`, и второй — `true`. Сколько будет стоить доставка?

**A)** 0 сумов · **B)** 10 000 сумов · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**A: 0 сумов.** Go сверху вниз выполнил первый `true` `case`, и на этом `switch` закончился. Следующие `case` даже не
проверяются. Если вы выбрали **B**, вы думали, что выполняются все `true` case и побеждает последний. Не **C**: два
`case` могут быть `true` одновременно, Go этого не запрещает.

</details>

Каждый `case` заканчивается в конце своих строк и не переходит в следующий `case`. Если всё же нужно перейти в
следующий, есть ключевое слово `fallthrough`, оно используется редко. А порядок важен: большая граница стоит сверху.
В обратном порядке заказ на 600 000 сумов попадёт в `case` для 100 000 («Частые ошибки», пункт 6).

### `switch` по значению

После `switch` можно написать и значение. Тогда каждый `case` сравнивается с этим значением через `==`:

```go filename="_video/11-qiymat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "oʻrik"
	switch name {
	case "olma", "oʻrik":
		fmt.Println("meva")
	case "non":
		fmt.Println("non mahsuloti")
	default:
		fmt.Println("boshqa")
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 7 | `switch name {` | `name` сравнивается с каждым значением `case` через `==` |
| 8–9 | `case "olma", "oʻrik":` | в одном `case` несколько значений через запятую: `"olma"` («яблоко») **или** `"oʻrik"` («урюк»); выводит `meva` («фрукт») |
| 10–11 | `case "non":` | если `name` — `"non"` («хлеб»); выводит `non mahsuloti` («хлебобулочное изделие») |
| 12–13 | `default:` | любое другое название; выводит `boshqa` («другое») |

`name` — `"oʻrik"`, поэтому подходит `case` в строке 8:

## Частые ошибки

### 1. Думать, что после блока `if` программа останавливается

Самая частая ошибка. Вывод сообщения не останавливает программу: после блока `if` она продолжается. Компилятор молчит,
а результат неверный: после строки ошибки склад всё равно меняется и печатается отрицательный чек (вывод `04-if` в
разделе «`if`: если условие `true`, блок выполняется»). **Исправление:** `return` в конце блока.

### 2. Одиночный `=` в условии

`if sold = 0 {` — присваивание, а не сравнение. Результат: `syntax error: cannot use assignment sold = 0 as value`
(раздел «Одиночный `=` в условии»). **Исправление:** `==` или, в зависимости от правила, `<=`.

### 3. Условие — не `bool`

В условие пишут само число. Примера нет в папке:

```go
package main

import "fmt"

func main() {
	sold := 7
	if sold {
		fmt.Println("sotildi")
	}
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:7:5: non-boolean condition in if statement
```

«Строка 7, столбец 5: условие не типа `bool` в инструкции `if`». `sold` — `int`, а `if` принимает только
`true`/`false`. Go сам не превращает число в `bool`. **Исправление:** напишите вопрос явно: `if sold > 0 {`.

### 4. `else` на новой строке

Примера нет в папке:

```go
package main

import "fmt"

func main() {
	sold := 7
	if sold <= 0 {
		fmt.Println("xato")
	}
	else {
		fmt.Println("ok")
	}
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:10:2: syntax error: unexpected keyword else, expected }
```

«Строка 10: неожиданное ключевое слово `else`, ожидалась `}`». В конце строки после `}` Go сам ставит точку с запятой
(спецификация Go, Semicolons). Тогда `if` заканчивается на строке 9, а `else` на строке 10 ни к чему не привязан.
**Исправление:** `} else {` на одной строке.

### 5. Сравнение значений разных типов

Примера нет в папке: `sold` — `int`, `price` — `int64`:

```go
package main

import "fmt"

func main() {
	var price int64 = 199_900
	sold := 7
	if sold > price {
		fmt.Println("?")
	}
	fmt.Println(sold > 0)
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:8:12: invalid operation: sold > price (mismatched types int and int64)
```

«Недопустимая операция: `sold > price`, типы не совпадают: `int` и `int64`» — то же сообщение, что в GB-1.03. А
`sold > 0` в строке 11 ошибки не даёт: `0` — нетипизированная константа. **Исправление:** приведите к одному типу,
например `int64(sold) > price`.

### 6. Маленькая граница сверху в `switch`

Компилятор молчит, результат неверный. Примера нет в папке, `case` стоят в обратном порядке:

```go
package main

import "fmt"

const tiyinPerSom = 100

func main() {
	var subtotal int64 = 600_000 * tiyinPerSom
	var delivery int64
	switch {
	case subtotal >= 100_000*tiyinPerSom:
		delivery = 10_000 * tiyinPerSom
	case subtotal >= 500_000*tiyinPerSom:
		delivery = 0
	}
	fmt.Println(delivery / tiyinPerSom)
}
```

```console
$ go run .
10000
```

Заказ на 600 000 сумов должен был получить бесплатную доставку, а получил 10 000 сумов. Первый `case` уже `true`,
поэтому второй никогда не проверяется. **Исправление:** самая строгая (самая большая) граница сверху, как в
`10-switch`.

## Проверьте себя

**1.** Продолжается ли код после блока `if`? Что нужно, чтобы остановить неверный заказ?

<details>
<summary>Ответ</summary>

Да, продолжается: `if` управляет только своим блоком. Чтобы остановиться, нужен `return` внутри блока. `return` в
`main` завершает `main`, а значит, и программу.

</details>

**2.** Если в `switch` два `case` равны `true`, какой выполнится?

<details>
<summary>Ответ</summary>

Только первый сверху. `switch` выполняет первый `true` `case` и на этом заканчивается; следующие не проверяются (если
не написан `fallthrough`).

</details>

**3.** Из GB-1.02: если объявить `var price int64` и не дать значения, чему равен `price`?

<details>
<summary>Ответ</summary>

`0` — нулевое значение `int64`. Значит, товар без цены может уйти за 0 сумов. Отказывать в этом случае — домашнее
задание.

</details>

**5.** Что выведет эта программа (её нет в папке)? На складе 40, заказ тоже 40.

```go
package main

import "fmt"

func main() {
	stock := 40
	sold := 40
	if left := stock - sold; left < 0 {
		fmt.Println("yetmaydi")
	} else {
		fmt.Println("qoladi:", left)
	}
}
```

**A)** `yetmaydi` («не хватает») · **B)** `qoladi: 0` («остаётся: 0») · **C)** `undefined: left`

<details>
<summary>Ответ</summary>

**B: `qoladi: 0`.** `left` = 40 − 40 = 0, `0 < 0` — `false`, поэтому выполняется `else`. Не **C**: `left` из
короткого объявления виден и в блоке `else`, привязанном к `if`; он исчезает только после того, как закончится весь
`if`-`else`.

```console
$ go run .
qoladi: 0
```

</details>

```go filename="solution/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 7
	if name == "" {
		fmt.Println("xato: mahsulot nomi boʻsh")
		return
	}
	if !active {
		fmt.Printf("xato: %s sotuvda emas\n", name)
		return
	}
	if price <= 0 || price > 10_000_000*tiyinPerSom {
		fmt.Printf("xato: narx notoʻgʻri: %d tiyin\n", price)
		return
	}
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100

	var delivery int64 // tiyinda
	switch {
	case subtotal >= 500_000*tiyinPerSom:
		delivery = 0
	case subtotal >= 100_000*tiyinPerSom:
		delivery = 10_000 * tiyinPerSom
	default:
		delivery = deliverySom * tiyinPerSom
	}
	total := subtotal + vat + delivery

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", delivery/tiyinPerSom, delivery%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 26–29 | `if name == "" {` | равно ли название пустой строке: `""` — нулевое значение `string` |
| 30–33 | `if !active {` | если `active` равно `false`, `!active` равно `true`; на место `%s` — название |
| 34–37 | `if price <= 0 \|\| price > 10_000_000*tiyinPerSom {` | достаточно одного из двух условий; `>` (не `>=`), поэтому ровно 10 000 000 сумов проходит; 1 тийин не `<= 0`, он тоже проходит |
| 38–45 | `if sold <= 0`, `if left := …` | два правила из видео, на своих местах |

Правила идут одно за другим, и каждое заканчивается `return`. Поэтому выводится сообщение первого нарушенного правила,
а остальные не проверяются: порядок — это просто порядок в коде.

Необязательный путь через `switch` (я проверил его тем же `go test`; в `solution/` его нет), вместо строк 26–37:

```go
	switch {
	case name == "":
		fmt.Println("xato: mahsulot nomi boʻsh")
		return
	case !active:
		fmt.Printf("xato: %s sotuvda emas\n", name)
		return
	case price <= 0 || price > 10_000_000*tiyinPerSom:
		fmt.Printf("xato: narx notoʻgʻri: %d tiyin\n", price)
		return
	}
```

Здесь нет `default`: если все правила соблюдены, `switch` ничего не делает, и программа продолжается со следующей
строки.
