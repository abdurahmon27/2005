## What you will learn

If bozor gets −3 instead of a quantity, the program runs without a word: the tea in stock grows from 40 to 43, and
the VAT on the receipt comes out as `-719.-64`. The compiler says nothing, because −3 is a valid `int`. It does not
know which value makes sense. How do you stop a wrong order before the receipt is printed and before stock is reduced?

**One idea:** a comparison gives the value `true` or `false`. `if` and `switch` pick one block by that value, and
after the block the program goes on: to stop a wrong order you need `return`.

By the end of the lesson you will:

- compare two values with `==`, `!=`, `<`, `<=`, `>`, `>=` and join conditions with `&&`, `||`, `!`;
- write `if`, `else if`, `else` and leave `main` with `return` when something is wrong;
- write an `if` with a short declaration (`if left := …; left < 0`) and read the `undefined: left` error;
- use `switch` to pick one of several conditions: the delivery price by the order amount.

Today's three core new words:

| Word | Plain meaning | Term |
|---|---|---|
| comparison and logical operator | comparing two values (`sold > 0`) gives a `bool`: `true` or `false`; `&&` (and), `\|\|` (or), `!` (not) join several conditions | comparison, logical operators |
| `if` / `else` | if the condition is `true`, the block inside `{ }` runs; if `false`, it is skipped; `else` runs when the condition is `false` | if statement |
| `switch` | runs the first matching `case` out of several and ends there; if none matches, `default` | switch statement |

Two helper words: **`return`** ends the function at that point (in this lesson `main`, so the program); and
**scope**, the part of the code where a name is visible.

## Where we start: a negative quantity

This is bozor from the last lesson, with its task done. Only line 25 changed: `sold` is now −3:

```go filename="_video/01-manfiy/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := -3
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100
	total := subtotal + vat + deliverySom*tiyinPerSom

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| 10–23 | `fmt.Println(…)`, `var …`, `:=` | GB-1.01–1.02: the startup and version lines, zero values, the product and stock. We don't touch them today |

The compiler is silent: −3 is a valid `int`. Stock is 43, the amounts are negative. Look at `-719.-64` on the VAT
line. The VAT in tiyin is −71 964. `-71964 / 100` = −719, `-71964 % 100` = −64: in Go the remainder takes the sign of
the dividend (Go specification, Integer operators). That is why there is a minus after the dot too. The receipt format
`%9d.%02d` is only right for zero and positive amounts. So a negative amount must never reach the receipt.

For that we need three things:

1. **comparison**: comparing two values, with the result `true` or `false` (`sold > 0`);
2. **`if`**: running or skipping code by a condition, and stopping with `return`;
3. **`switch`**: picking one of several conditions (the delivery price).

## Comparison: the result is a `bool`

A decision starts with a comparison:

```go filename="_video/02-bool/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := -3
	ok := sold > 0
	fmt.Println(ok)
}
```

On line 7, `>` is the "greater than" sign: is `sold` greater than zero? The result is not a number but the
**`bool`** type from GB-1.02: `true` or `false`. −3 is not greater than zero, so the new variable `ok` gets `false`.
`:=` takes the type from the value, so `ok` is a `bool`. In memory, line by line:

| Line | Code | `sold` (`int`) | `ok` (`bool`) | Screen |
|---|---|---|---|---|
| 6 | `sold := -3` | −3 | — | |
| 7 | `ok := sold > 0` | −3 | `false` (−3 > 0 ?) | |
| 8 | `fmt.Println(ok)` | −3 | `false` | `false` |

```console
$ ./_video/run.sh 02-bool
false
```

Go has six **comparison** operators. Each one gives a `bool`:

| Operator | Meaning | Example, `sold` = 7 | Result |
|---|---|---|---|
| `==` | equal | `sold == 7` | `true` |
| `!=` | not equal | `sold != 7` | `false` |
| `<` | less | `sold < 7` | `false` |
| `<=` | less or equal | `sold <= 7` | `true` |
| `>` | greater | `sold > 0` | `true` |
| `>=` | greater or equal | `sold >= 10` | `false` |

Careful: a **single** `=` is not a comparison, it is assignment (GB-1.02). Equality is checked with **two** equal
signs, `==`. You can compare `string` values with `==` too: `name == "choy"` is `true` when `name` is exactly
`"choy"` ("tea").

**Both sides must have matching types.** `sold` is an `int`, `price` is an `int64`. If you write `sold > price`, the
compiler gives the `mismatched types` error from GB-1.03 (the full example is in "Common mistakes"). `sold > 0`
works: `0` is an untyped constant, and it takes the type of `sold`, `int`, by itself.

### Logical operators: `&&`, `||`, `!`

Often one condition is not enough: the quantity must be positive **and** not more than the stock. For this there are
**logical operators**:

```go filename="_video/03-mantiq/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := 7
	stock := 40
	ok := sold > 0 && sold <= stock
	bad := sold <= 0 || sold > stock
	fmt.Println(ok, bad, !ok)
}
```

- `&&` (two ampersands) is logical **and**: the result is `true` only if both sides are `true`.
- `||` (two vertical bars) is logical **or**: one `true` side is enough.
- `!` (exclamation mark) is **not**: it turns `true` into `false` and `false` into `true`.

| `a` | `b` | `a && b` | `a \|\| b` |
|---|---|---|---|
| `true` | `true` | `true` | `true` |
| `true` | `false` | `false` | `true` |
| `false` | `true` | `false` | `true` |
| `false` | `false` | `false` | `false` |

Line 8 has no parentheses. It doesn't need them: comparisons (`>`, `<=`) are evaluated before `&&` and `||` (Go
specification, Operator precedence). So `sold > 0 && sold <= stock` = `(sold > 0) && (sold <= stock)`.

`sold` is 7, `stock` is 40. What does it print?

**A)** `true false false` · **B)** `true true false` · **C)** `true false true`

<details>
<summary>Answer</summary>

**A: `true false false`.** `ok`: 7 > 0 → `true`, 7 &lt;= 40 → `true`, `true && true` → `true`. `bad` asks the opposite
of both conditions: 7 &lt;= 0 → `false`, 7 > 40 → `false`, `false || false` → `false`. `!ok` → `false`. If you chose
**B**, you read `||` as something other than "at least one": here both sides are `false`. In **C** the `!` was
forgotten: `!ok` is the opposite of `ok`.

</details>

| Line | Code | Evaluation | Result |
|---|---|---|---|
| 8 | `ok := sold > 0 && sold <= stock` | `true && true` | `ok` = `true` |
| 9 | `bad := sold <= 0 \|\| sold > stock` | `false \|\| false` | `bad` = `false` |
| 10 | `fmt.Println(ok, bad, !ok)` | `!true` | screen: `true false false` |

## `if`: when the condition is `true`, the block runs

The first rule: the quantity is at least 1 unit. It goes after the line that declares `sold` and before stock is
reduced:

```go filename="_video/04-if/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := -3
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
	}
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100
	total := subtotal + vat + deliverySom*tiyinPerSom

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Line | Code | What it does |
|---|---|---|
| 26 | `if sold <= 0 {` | the `if` keyword, then the condition `sold <= 0`, without parentheses; an opening curly brace at the end |
| 27 | `fmt.Println("xato: …")` | the line inside the block: it runs only if the condition is `true` ("xato" means "error") |
| 28 | `}` | the block ends |

The rules of **`if`** (Go specification, If statements):

- the condition must be a `bool`. If you write `if sold {`, the compiler rejects it: `sold` is a number, not a `bool`;
- if the condition is `true`, the **block** inside `{ }` runs; if `false`, Go skips it;
- the curly braces are always required, even for a one-line block. The opening `{` stays on the same line, as in
  `func main() {`;
- parentheses around the condition are not needed. `if (sold > 0) {` compiles too, but `gofmt` removes them, so Go
  code is written without them.

`sold` is −3, the condition is `true`, the block runs. What does `go run .` print?

**A)** only the error line · **B)** the error line, then the receipt · **C)** a compile error

<details>
<summary>Answer</summary>

**B.** The error line is printed, and then the stock line (43) and the negative receipt anyway. `if` controls only its
own block: after the closing `}` the program continues with the next line. If you chose **A**, you thought printing an
error stops the program: it does not. The code is correct, so it is not **C** either.

</details>

## `return`: stop right here

To stop, we add **`return`** inside the block. The file is the same as `04-if`, only line 28 is added. Its lines
25–31:

```go
	sold := -3
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)
```

`return` ends the function at this point: the lines after it don't run. This is `main`, and when `main` ends, the
program ends (GB-1.01). A `return` that gives back a value comes in [GB-1.07](/lab/youtube/gb#gb-1-07). The full file:
`_video/05-return/main.go`.

```console
$ ./_video/run.sh 05-return
bozor ishga tushdi
versiya: 0.1.0
 0 false
choy 199900 true 40 1.5
xato: miqdor kamida 1 dona boʻlishi kerak
```

Now there is no stock line and no receipt after the error line. This shape is very common in Go code: check the wrong
case at the start and leave at once (a *guard clause*, *early return*). The main calculation is not pushed into extra
braces, it stays at the left edge. Go Code Review Comments calls this "Indent Error Flow". Effective Go says the same:
when the error case ends with `return`, the unnecessary `else` is omitted. This is how it is not written:

```go
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
	} else {
		stock = stock - sold
		// … butun hisob va chek shu qavslar ichida, bir pogʻona oʻngda
	}
```

There is one simplification for now. The error message goes to the same place as the receipt, standard output
(stdout). And the program ends with exit code 0, which means "success": the operating system does not know there was
an error. Writing the error to a separate stream (stderr) and reporting failure (`os.Exit(1)`) comes in
[GB-1.07](/lab/youtube/gb#gb-1-07).

## A single `=` in a condition

Now a mistake that is common in conditions. Someone wanted to check for a zero quantity and wrote a single `=` instead
of `==`. The file is the same as `05-return`, only lines 25–26 differ:

```go
	sold := 0
	if sold = 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
```

It looks like a check, but a single `=` is assignment. This file has a deliberate syntax error, so it is stored in the
folder as `_video/06-teng-xato/main.go.txt`: as a `.go` file it would stop `gofmt` and `go vet` from reading the whole
folder. `run.sh` copies it as `main.go`:

```console
$ ./_video/run.sh 06-teng-xato
# github.com/abdurahmon27/bozor
./main.go:26:10: syntax error: cannot use assignment sold = 0 as value
```

Reading the message:

- `./main.go:26:10`: line 26, column 10, the `=` sign (a Tab is one column, `if` is columns 2–3, `sold` 5–8, `=`
  column 10);
- `syntax error`: the compiler could not read the code;
- `cannot use assignment sold = 0 as value`: "the assignment `sold = 0` cannot be used as a value".

In Go an assignment gives no result, it is a separate statement (Go specification, Assignment statements). A condition
expects a `bool` value. That is why the mistake is caught before the program runs. The fix: `==`, and in our rule
`<=` (zero and negative are both rejected).

## `if` with a short declaration: the stock rule

The second rule: you can't sell more than is in stock. This time the order is 50 units (line 25), and the stock is 40:

```go filename="_video/07-ombor/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 50
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100
	total := subtotal + vat + deliverySom*tiyinPerSom

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

The `if` on line 30 is different: a **short declaration** comes before the condition.

| Part | Code | What it does |
|---|---|---|
| declaration | `left := stock - sold` | the units left in stock after the sale; `left` is a new variable |
| separator | `;` | the semicolon separates the declaration from the condition |
| condition | `left < 0` | if what is left is negative, the stock is short |
| line 31 | `fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)` | `-left` is minus `left`: it makes the number of missing units positive ("error: … units short in stock") |
| line 32 | `return` | no receipt and no stock change |

Go runs the declaration first, then checks the condition (Go specification: "The expression may be preceded by a
simple statement, which executes before the expression is evaluated"):

| Step | What happens | `left` | Result |
|---|---|---|---|
| 1 | `left := stock - sold` → 40 − 50 | −10 | |
| 2 | `left < 0` → −10 &lt; 0 | −10 | `true`: the block runs |
| 3 | `-left` → −(−10) | −10 | screen: `xato: omborda 10 dona yetmaydi` |
| 4 | `return` | | `main` ends |

If `stock` is 40 and `sold` is 40, `left` is 0: 0 &lt; 0 is `false`, and the order goes through. You can sell all the
tea in stock.

```go
	if left := stock - sold; left < 0 {
```

<summary>Answer</summary>

**C.** A compile error: `undefined: left`, that is, "`left` is not defined". A variable from the short declaration is
visible only inside this `if`; after the closing `}` the name does not exist. If you chose **A**, you thought `left`

to talk about.

</details>


`./main.go:34:14`: line 34, column 14, the `left` inside `fmt.Println(`. The place where a name is visible is called
its **scope**. The Go specification (Blocks): "Each if, for, and switch statement is considered to be in its own
implicit block":

```text
func main() {                          ← main's block: name, price, stock, sold …
    if left := stock - sold; left < 0 {   ← the if block starts: left appears here
        … -left …                      ← left is visible
    }                                  ← the if block ended: no left
    fmt.Println(left)                  ← undefined: left
}
```

`left` is visible in the condition and the block of the `if` (and in the `else` blocks attached to that `if`). This
way a helper name exists only where it is needed and can't be used by mistake in the code below.

## `else if` and `else`: the delivery price

Now the delivery price. The order: apricots (`oʻrik`), 25 000 som each, 24 units. The rule:

| Product amount | Delivery |
|---|---|
| 500 000 som or more | 0 (free) |
| 100 000 som or more | 10 000 som |
| anything else | 15 000 som (`deliverySom`) |

```go filename="_video/09-elseif/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "oʻrik"
	price = 25_000 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 24
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100

	var delivery int64 // tiyinda
	if subtotal >= 500_000*tiyinPerSom {
		delivery = 0
	} else if subtotal >= 100_000*tiyinPerSom {
		delivery = 10_000 * tiyinPerSom
	} else {
		delivery = deliverySom * tiyinPerSom
	}
	total := subtotal + vat + delivery

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", delivery/tiyinPerSom, delivery%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Line | Code | What it does |
|---|---|---|
| 18–19, 25 | `name = "oʻrik"`, `price = 25_000 * tiyinPerSom`, `sold := 24` | a new order: 25 000 × 24 = 600 000 som |
| 40 | `var delivery int64 // tiyinda` | declared without a value: for now the zero value 0 (GB-1.02). One of the three paths below gives it a value |
| 41–42 | `if subtotal >= 500_000*tiyinPerSom {` | the amount is in tiyin, so the som limit is multiplied by `tiyinPerSom`; free from 500 000 som |
| 43–44 | `} else if subtotal >= 100_000*tiyinPerSom {` | **`else if`**: if the condition above is `false`, one more condition; 10 000 som from 100 000 som |
| 45–47 | `} else {` | **`else`**: if all conditions above are `false`; 15 000 som |
| 48 | `total := subtotal + vat + delivery` | the total now uses `delivery` |
| 53 | `"yetkazish", delivery/tiyinPerSom, delivery%tiyinPerSom` | so does the delivery line on the receipt (`yetkazish`) |

The conditions are checked from top to bottom. The block of the first `true` condition runs, the rest are not checked.
`else` and `else if` stay on the same line as the closing `}`: if you start a new line after `}`, you get a compile
error ("Common mistakes", item 4).

In this order the product amount is 600 000 som (60 000 000 tiyin):

| Condition | Value | What happens |
|---|---|---|
| `subtotal >= 500_000*tiyinPerSom` | `true` | `delivery = 0` |
| `subtotal >= 100_000*tiyinPerSom` | not checked | — |
| `else` | — | — |

## `switch`: the first `true` case

The same `if`, `else if`, `else` chain is easier to read as a **`switch`**. Effective Go says so too: "it's idiomatic
to write an if-else-if-else chain as a switch". The file is the same as `09-elseif`, only lines 41–48 differ. Its
lines 40–49:

```go
	var delivery int64 // tiyinda
	switch {
	case subtotal >= 500_000*tiyinPerSom:
		delivery = 0
	case subtotal >= 100_000*tiyinPerSom:
		delivery = 10_000 * tiyinPerSom
	default:
		delivery = deliverySom * tiyinPerSom
	}
	total := subtotal + vat + delivery
```

| Line | Code | What it does |
|---|---|---|
| 41 | `switch {` | nothing after `switch`: this is a **switch with no expression**, and each `case` takes a `bool` condition |
| 42–43 | `case subtotal >= 500_000*tiyinPerSom:` | the word `case`, a condition, a colon; below it, the lines of this `case` |
| 44–45 | `case subtotal >= 100_000*tiyinPerSom:` | the next `case`, same pattern |
| 46–47 | `default:` | runs when no `case` is `true` |
| 48 | `}` | the `switch` ends |

The Go specification: a `switch` with no expression is the same as `switch true`. So Go looks for the first `case`
that is `true`. The full file: `_video/10-switch/main.go`.

The amount is 600 000 som, so both the first and the second `case` are `true`. What is the delivery price?

**A)** 0 som · **B)** 10 000 som · **C)** a compile error

<details>
<summary>Answer</summary>

**A: 0 som.** Going from top to bottom, Go ran the first `true` `case`, and the `switch` ended there. The cases after
it are not even checked. If you chose **B**, you thought every `true` case runs and the last one wins. Not **C**: two
cases may be `true` at the same time, Go does not forbid it.

</details>

Each `case` ends at the end of its own lines and does not continue into the next `case`. If you do need to continue
into the next one, there is a keyword `fallthrough`; it is rarely used. The order matters: the bigger limit goes on
top. In the reverse order a 600 000 som order falls into the 100 000 `case` ("Common mistakes", item 6).

## Common mistakes

### 1. Thinking the program stops after the `if` block

The most common mistake. Printing a message does not stop the program: after the `if` block the program goes on. The
compiler is silent, but the result is wrong: after the error line the stock still changes and a negative receipt is
printed (the `04-if` output in the section "`if`: when the condition is `true`, the block runs"). **Fix:** `return` at
the end of the block.

### 2. A single `=` in a condition

`if sold = 0 {` is assignment, not comparison. The result: `syntax error: cannot use assignment sold = 0 as value`
(the section "A single `=` in a condition"). **Fix:** `==`, or `<=`, depending on the rule.

### 3. The condition is not a `bool`

Writing the number itself as the condition. An example that is not in the folder:

```go
package main

import "fmt"

func main() {
	sold := 7
	if sold {
		fmt.Println("sotildi")
	}
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:7:5: non-boolean condition in if statement
```

"Line 7, column 5: a non-`bool` condition in an `if` statement". `sold` is an `int`, and `if` accepts only
`true`/`false`. Go does not turn a number into a `bool` by itself. **Fix:** write the question explicitly:
`if sold > 0 {`.

### 4. `else` on a new line

An example that is not in the folder:

```go
package main

import "fmt"

func main() {
	sold := 7
	if sold <= 0 {
		fmt.Println("xato")
	}
	else {
		fmt.Println("ok")
	}
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:10:2: syntax error: unexpected keyword else, expected }
```

"Line 10: unexpected keyword `else`, `}` was expected". At the end of a line, after `}`, Go inserts a semicolon by
itself (Go specification, Semicolons). So the `if` ends on line 9, and the `else` on line 10 is attached to nothing.
**Fix:** `} else {` on one line.

### 5. Comparing values of different types

An example that is not in the folder: `sold` is an `int`, `price` is an `int64`:

```go
package main

import "fmt"

func main() {
	var price int64 = 199_900
	sold := 7
	if sold > price {
		fmt.Println("?")
	}
	fmt.Println(sold > 0)
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:8:12: invalid operation: sold > price (mismatched types int and int64)
```

"Invalid operation: `sold > price`, mismatched types `int` and `int64`": the same message as in GB-1.03.
`sold > 0` on line 11 gives no error: `0` is an untyped constant. **Fix:** bring both sides to one type, for example
`int64(sold) > price`.

### 6. A small limit on top in a `switch`

The compiler is silent, the result is wrong. An example that is not in the folder, with the cases in reverse order:

```go
package main

import "fmt"

const tiyinPerSom = 100

func main() {
	var subtotal int64 = 600_000 * tiyinPerSom
	var delivery int64
	switch {
	case subtotal >= 100_000*tiyinPerSom:
		delivery = 10_000 * tiyinPerSom
	case subtotal >= 500_000*tiyinPerSom:
		delivery = 0
	}
	fmt.Println(delivery / tiyinPerSom)
}
```

```console
$ go run .
10000
```

A 600 000 som order should have free delivery, but it got 10 000 som. The first `case` is already `true`, so the
second one is never checked. **Fix:** the strictest (largest) limit on top, as in `10-switch`.

```go filename="solution/main.go" showLineNumbers
	case subtotal >= 500_000*tiyinPerSom:
		delivery = 0
	case subtotal >= 100_000*tiyinPerSom:
		delivery = 10_000 * tiyinPerSom
	default:
		delivery = deliverySom * tiyinPerSom
	}
	total := subtotal + vat + delivery

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", delivery/tiyinPerSom, delivery%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Line | Code | What it does |
|---|---|---|
| 26–29 | `if name == "" {` | is the name equal to the empty string: `""` is the zero value of `string` |
| 30–33 | `if !active {` | if `active` is `false`, `!active` is `true`; the name goes in place of `%s` |
| 34–37 | `if price <= 0 \|\| price > 10_000_000*tiyinPerSom {` | one of the two conditions is enough; `>` (not `>=`), so exactly 10 000 000 som passes; 1 tiyin is not `<= 0`, so it passes too |
| 38–45 | `if sold <= 0`, `if left := …` | the two rules from the video, in place |

The rules come one after another, and each one ends with `return`. So the message of the first broken rule is printed
and the rest are not checked: the order is simply the order in the code.

The optional `switch` way (I checked it with the same `go test`; it is not in `solution/`), in place of lines 26–37:

```go
	switch {
	case name == "":
		fmt.Println("xato: mahsulot nomi boʻsh")
		return
	case !active:
		fmt.Printf("xato: %s sotuvda emas\n", name)
		return
	case price <= 0 || price > 10_000_000*tiyinPerSom:
		fmt.Printf("xato: narx notoʻgʻri: %d tiyin\n", price)
		return
	}
```

There is no `default` here: if every rule holds, the `switch` does nothing and the program continues with the next
line.
