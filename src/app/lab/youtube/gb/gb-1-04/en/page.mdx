## What you will learn

In the last lesson bozor computed the order total exactly, down to the tiyin. But it prints the receipt with
`fmt.Println`: the numbers sit in a different place on every line, and som and tiyin come as separate words. You
can't hand a customer a receipt like that. How do you print an amount as `13993.00`, with all amounts in one
column?

**One idea:** `fmt.Printf` reads the template from left to right. It prints plain text as it is, and in place of
each `%` verb it puts the next argument in the form and width that verb asks for. `fmt.Sprintf` builds the same
text but does not print it: it returns it as a `string` value.

By the end of the lesson you will:

- join two `string` values with `+` and read from the message why `string + int64` does not compile;
- write a `fmt.Printf` template with the verbs `%s`, `%d`, `%v`, `%q` and `\n`;
- use width (`%9d`, `%-14s`) and `0` (`%02d`) to print an amount in a column: som, a dot, and two-digit tiyin;
- recognize two common mistakes (`string(total)` and a wrong verb) by their output and by the `go vet` message.

Today's three core new words:

| Word | Plain meaning | Term |
|---|---|---|
| joining strings | `+` between two `string` values: puts them side by side and makes a new `string`; both sides must have the same type | string concatenation |
| template and verb | the first argument of `Printf` is the template; a `%` plus a letter inside it (`%s`, `%d`) is a verb that says how to write the next argument | format string, verb |
| width | a number between `%` and the letter: the value takes at least that many characters (`%9d`); `-` aligns left, `0` fills the empty space with zeros | width (flags `-`, `0`) |

Two helper words: **`fmt.Sprintf`** takes the same template as `Printf` but returns the result as a `string`
instead of printing it; and **`\n`** is the newline character in a template.

## Joining text: `string` and `+`

`string` is Go's text type, written in double quotes. `+` between two `string` values joins them side by side and
makes a **new** `string`. This is called **concatenation** (joining strings).

```go
name := "choy"
label := "mahsulot: " + name
fmt.Println(label)
```

The new variable `label` gets the texts `"mahsulot: "` ("product: ") and `"choy"`. The space after the colon is
part of the text too: without it you would get `mahsulot:choy`. In memory, line by line:

| Line | Code | `name` | `label` | On screen |
|---|---|---|---|---|
| 1 | `name := "choy"` | `"choy"` | — | |
| 2 | `label := "mahsulot: " + name` | `"choy"` | `"mahsulot: choy"` | |
| 3 | `fmt.Println(label)` | `"choy"` | `"mahsulot: choy"` | `mahsulot: choy` |

`+` does not change `name`: it is still `"choy"`. The result is a separate value, and it is stored in `label`.

Now let's try to join an amount to the text. `total` is an `int64`, in tiyin; `label` is `"jami: "`:

```go filename="_video/03-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var total int64 = 3_067_216 // tiyinda
	label := "jami: "
	fmt.Println(label + total)
}
```

```console
$ ./_video/run.sh 03-xato
# github.com/abdurahmon27/bozor
./main.go:8:14: invalid operation: label + total (mismatched types string and int64)
```

Reading the message:

- `# github.com/abdurahmon27/bozor` is the module path from GB-1.01: the error is in this module's code.
- `./main.go:8:14` means `main.go`, line 8, column 14 (a Tab counts as one column, `label` starts at column 14).
- `invalid operation: label + total`: the operation `label + total` is not allowed.
- `(mismatched types string and int64)`: the types `string` and `int64` don't match.

The rule: both sides of `+` must have the same type. Go does not turn a number into text by itself. The `int64`
and `int` error in GB-1.03 came from the same rule. An untyped numeric constant adapts to another numeric type, but
it does not become text. Putting a number inside text is a formatting job, and `fmt.Printf` in the next section
does it.

## `fmt.Printf`: template and verbs

`Printf` from the `fmt` package takes a **template** (format string) as its first argument. A `%` plus a letter in
the template is called a **verb**. The remaining arguments go in place of the verbs, in order.

```go filename="_video/04-printf/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "choy"
	var price int64 = 199_900 // tiyinda
	fmt.Printf("%s: %d tiyin\n", name, price)
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `name := "choy"` | the product name, a `string` |
| 7 | `var price int64 = 199_900` | the price in tiyin (1,999 som) |
| 8 | `fmt.Printf("%s: %d tiyin\n", name, price)` | the template `"%s: %d tiyin\n"`, then two arguments |

Inside the template:

- `%s` puts the next `string` argument as it is;
- `%d` writes an integer in decimal digits;
- `\n` is a backslash and `n`: the newline character. Inside double quotes Go stores it as **one** character, not
  two.

`Printf` reads the template from left to right. It prints plain text as it is. At the first verb it takes the first
argument, at the second verb the second one:

| Template part | What happens | On screen |
|---|---|---|
| `%s` | the 1st argument `name` goes here | `choy` |
| `: ` | plain text | `: ` |
| `%d` | the 2nd argument `price` goes here | `199900` |
| ` tiyin` | plain text | ` tiyin` |
| `\n` | newline character | the line ends |

```console
$ ./_video/run.sh 04-printf
choy: 199900 tiyin
```

`%d` writes the digits without underscores: `199_900` was only for reading the code (GB-1.03).

### Without `\n`

Now we remove `\n` and call `Printf` twice; the second call gets `"non"` ("bread") and 400,000 tiyin:

```go filename="_video/05-qator/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "choy"
	var price int64 = 199_900 // tiyinda
	fmt.Printf("%s: %d tiyin", name, price)
	fmt.Printf("%s: %d tiyin", "non", 400_000)
}
```

Think before you run it: where does the second product appear?

**A)** on the next line · **B)** on the same line as the first · **C)** nowhere, a compile error

<details>
<summary>Answer</summary>

**B.** Both are glued into one line: `non` comes right after the word `tiyin`. `Printf` does not end the line by
itself; it prints only what the template says. If you chose **A**, you thought `Printf` works like `Println`:
`Println` adds the line end itself, `Printf` does not. The code is valid, so it is not **C** either.

</details>

```console
$ ./_video/run.sh 05-qator
choy: 199900 tiyinnon: 400000 tiyin
```

You add the line end yourself, with `\n`. Here the program's output itself does not end with `\n`, so the terminal's
line that waits for the next command appears on the same line, right after it.

### Two more verbs: `%v` and `%q`

`%v` prints any value in its default form: a number, a `string`, `true` or `false`. It is handy when the type
doesn't matter (*value*). `%q` prints text inside double quotes (*quoted*).

```go filename="_video/06-feyllar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	input := " choy "
	sold := 7
	active := true
	fmt.Printf("%v dona, sotuvda: %v\n", sold, active)
	fmt.Printf("%s\n", input)
	fmt.Printf("%q\n", input)
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `input := " choy "` | text a user typed: `choy` with one space before and one after |
| 7 | `sold := 7` | number of pieces sold |
| 8 | `active := true` | a `bool`: is the product on sale |
| 9 | `fmt.Printf("%v dona, sotuvda: %v\n", sold, active)` | both values with `%v` (`sotuvda` is "on sale") |
| 10 | `fmt.Printf("%s\n", input)` | `input` with `%s` |
| 11 | `fmt.Printf("%q\n", input)` | `input` with `%q` |

Think: are the spaces visible in the line printed with `%s`?

<details>
<summary>Answer</summary>

The leading space is visible (the line starts indented), but the trailing one is not: on screen a space looks the
same as nothing. `%q` adds quotes, so both spaces show.

</details>

```console
$ ./_video/run.sh 06-feyllar
7 dona, sotuvda: true
 choy 
" choy "
```

On line 1 both the number and `true` came out with `%v`. Line 2 ends with a space, but you can't see it. On line 3
the quotes reveal both spaces. The lines a server writes about its own work are called a **log**. If you write user
text to the log with `%q`, an extra space is visible at once.

In short:

| Verb | For | Example | Output |
|---|---|---|---|
| `%s` | `string` | `"choy"` | `choy` |
| `%d` | integer, decimal | `199_900` | `199900` |
| `%v` | any value, default form | `7`, `true` | `7`, `true` |
| `%q` | text in double quotes | `" choy "` | `" choy "` |

## Tiyin: the `%d.%d` bug and `%02d`

Now we print the VAT in som, with a dot and tiyin. With 8 pieces of tea, the VAT in tiyin is `191_904`:
1,999 × 100 × 8 = 1,599,200 tiyin, and 12 % of that is 191,904.

```go filename="_video/07-pul/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100

func main() {
	var vat int64 = 191_904 // choy, 8 dona: QQS tiyinda
	fmt.Printf("QQS: %d.%d soʻm\n", vat/tiyinPerSom, vat%tiyinPerSom)
}
```

`vat/tiyinPerSom` is the som part (integer division drops the fraction: `1919`). `vat%tiyinPerSom` is the tiyin
part, the remainder: `4`. Careful: `%` **in the code** is the remainder operator (GB-1.03), while `%` **in the
template** starts a verb. The two have nothing to do with each other.

`vat` is 191,904 tiyin. What appears on screen?

**A)** `QQS: 1919.04 soʻm` · **B)** `QQS: 1919.4 soʻm` · **C)** `QQS: 1919.40 soʻm`

<details>
<summary>Answer</summary>

**B: `QQS: 1919.4 soʻm`.** The remainder is `4`, and `%d` writes it as one digit. If you chose **A**, you thought
`%d` keeps room for two digits: it doesn't, a number is written at its own length. For **C**, Go would have to
know that the digit after the dot is money; it only puts two separate integers side by side with a dot.

</details>

```console
$ ./_video/run.sh 07-pul
QQS: 1919.4 soʻm
```

The customer reads this as 40 tiyin, but it is really 4 tiyin. This is a real bug on the receipt, and both the
compiler and the program stay silent.

**The fix:** the second verb becomes `%02d`. The `2` between `%` and `d` is the **width**: the result takes at
least 2 characters. The `0` before it is a flag: it fills the empty space with zeros instead of spaces.

```go filename="_video/08-pul-tuzat/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100

func main() {
	var vat int64 = 191_904 // choy, 8 dona: QQS tiyinda
	fmt.Printf("QQS: %d.%02d soʻm\n", vat/tiyinPerSom, vat%tiyinPerSom)
}
```

```console
$ ./_video/run.sh 08-pul-tuzat
QQS: 1919.04 soʻm
```

After the dot: `04`, that is, 4 tiyin. The remainder is from `0` to `99`; `%02d` writes each one as exactly two
digits: `00`, `04`, `16`, `99`.

## Width: a column with `%9d` and `%-14s`

Width works with any verb. The number between `%` and the letter is the width, and the result takes at least that
many characters:

- `%9d` pushes the number to the **right** edge of a 9-character column and fills the left with spaces;
- `%-14s`: the `-` flag aligns left; it puts the name at the left edge of a 14-character field and fills the right.

Only the som part for now:

```go filename="_video/09-jadval/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Printf("%-14s %9d\n", "QQS", 1679)
	fmt.Printf("%-14s %9d\n", "yetkazish", 15000)
	fmt.Printf("%-14s %9d\n", "jami", 30672)
}
```

Let's check before we run it. The template has two pairs of square brackets (plain text here), with `%-6s` and
`%4d` inside; the arguments are `"QQS"` and `7`:

```go
fmt.Printf("[%-6s][%4d]", "QQS", 7)
```

What is printed?

**A)** `[QQS   ][   7]` · **B)** `[   QQS][7   ]` · **C)** `[QQS][7]`

<details>
<summary>Answer</summary>

**A.** `QQS` sits on the left of a 6-character field (3 spaces on its right), `7` on the right of a 4-character
field (3 spaces on its left). If you chose **B**, you read `-` the other way round: `-` aligns left, and without
`-` a number goes right. **C** is the result with no width.

This example is not in the folder; I ran it myself (with `\n` added at the end so the terminal output is tidy):

```go
package main

import "fmt"

func main() {
	fmt.Printf("[%-6s][%4d]\n", "QQS", 7)
}
```

```console
$ go run .
[QQS   ][   7]
```

</details>

Each cell is one character:

```text
%-6s  "QQS"  ->  [Q][Q][S][ ][ ][ ]   left, spaces on the right
%4d   7      ->  [ ][ ][ ][7]         right, spaces on the left
%02d  4      ->  [0][4]               width 2, empty space as 0
```

Now the three lines from the folder (`yetkazish` is "delivery"):

```console
$ ./_video/run.sh 09-jadval
QQS                 1679
yetkazish          15000
jami               30672
```

The names have different lengths (`QQS` 3, `yetkazish` 9 characters), but the right edges of the numbers line up.

Width is a minimum, not a limit. If the text is longer than the width, it is not cut: the column shifts. This
example is not in the folder either: `"yetkazib berish"` is 15 characters, one more than `%-14s`.

```go
package main

import "fmt"

func main() {
	fmt.Printf("%-14s %9d\n", "QQS", 1679)
	fmt.Printf("%-14s %9d\n", "yetkazib berish", 15000)
	fmt.Printf("%-14s %9d\n", "jami", 30672)
}
```

```console
$ go run .
QQS                 1679
yetkazib berish     15000
jami               30672
```

The number on line 2 moved one character to the right. That is why you choose the width from the longest name.

In short: the number is the width, `-` aligns left, `0` fills the empty space with zeros.

## `fmt.Sprintf`: the result comes back as a `string`

On the product line the left column needs two values: the name and the count (`choy, 7 dona`). Width applies to one
argument, so first we combine them into one text. **`fmt.Sprintf`** does that: the template is exactly like
`Printf`'s, but the result is not printed; it is **returned** as a `string`.

```go filename="_video/10-sprintf/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "choy"
	sold := 7
	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Println(item)
}
```

Where `fmt.Sprintf(…)` is written, this text is produced, and `:=` gives it to a new variable `item`:

| Line | Code | `name` | `sold` | `item` | On screen |
|---|---|---|---|---|---|
| 6 | `name := "choy"` | `"choy"` | | | |
| 7 | `sold := 7` | `"choy"` | `7` | | |
| 8 | `item := fmt.Sprintf("%s, %d dona", name, sold)` | `"choy"` | `7` | `"choy, 7 dona"` | nothing yet |
| 9 | `fmt.Println(item)` | `"choy"` | `7` | `"choy, 7 dona"` | `choy, 7 dona` |

```console
$ ./_video/run.sh 10-sprintf
choy, 7 dona
```

After line 8 nothing is on screen yet. The `Println` on line 9 prints the text.

## The final receipt

Now we put it all into bozor. The top part and the calculation (lines 1–31) did not change; the three `Println`
calls at the end were replaced:

```go filename="main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 7
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100
	total := subtotal + vat + deliverySom*tiyinPerSom

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Line | Code | What it does |
|---|---|---|
| 33 | `item := fmt.Sprintf("%s, %d dona", name, sold)` | one text for the left column: `"choy, 7 dona"` |
| 34 | `fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)` | product line: 1,399,300 tiyin → `13993` and `00` |
| 35 | `… "QQS", vat/tiyinPerSom, vat%tiyinPerSom)` | VAT line: 167,916 tiyin → `1679` and `16` |
| 36 | `… "jami", total/tiyinPerSom, total%tiyinPerSom)` | total line: 3,067,216 tiyin → `30672` and `16` |

All three lines use one template: `"%-14s %9d.%02d\n"`. The name left-aligned in 14, a space, the som part
right-aligned with `%9d`, a dot, the tiyin with `%02d`. The amount takes 9 + 1 + 2 = 12 characters, the whole line
14 + 1 + 12 = 27.

```console
$ go run .
bozor ishga tushdi
versiya: 0.1.0
 0 false
choy 199900 true 40 1.5
choy 33
choy, 7 dona       13993.00
QQS                 1679.16
jami               30672.16
```

The receipt promised at the start: three lines, amounts in one column, tiyin always two digits. Count the
characters:

```text
         1         2
123456789012345678901234567
choy, 7 dona       13993.00
QQS                 1679.16
jami               30672.16
```

| Characters | Template part | On line 1 |
|---|---|---|
| 1–14 | `%-14s` ← `item` | `choy, 7 dona` and 2 spaces |
| 15 | space | |
| 16–24 | `%9d` ← som | 4 spaces and `13993` |
| 25 | `.` | `.` |
| 26–27 | `%02d` ← tiyin | `00` |

One limit (from the course folder's README): `%d.%02d` is right only for amounts that are not negative. For a
negative amount both the integer division and the remainder are negative. This example is not in the folder:

```go
package main

import "fmt"

const tiyinPerSom = 100

func main() {
	var refund int64 = -5 // tiyinda
	fmt.Printf("%d.%02d\n", refund/tiyinPerSom, refund%tiyinPerSom)
}
```

```console
$ go run .
0.-5
```

In bozor an amount is never negative: in [GB-1.05](/lab/youtube/gb#gb-1-05) we reject a wrong price and quantity with `if`.

## Common mistakes

### 1. `string(total)` gives one character, not digits

In the last lesson we saw a conversion: `int64(sold)`. Someone uses the same form to turn the amount into text and
joins it to `"jami: "` with `+`:

```go filename="_video/11-string-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var total int64 = 3_067_216 // tiyinda
	fmt.Println("jami: " + string(total))
}
```

What happens if we compile and run it?

**A)** it prints `jami: 3067216` · **B)** a compile error · **C)** one character instead of the number

<details>
<summary>Answer</summary>

**C.** The code compiles, and one character comes out instead of the number. When you write `string(number)`, Go
takes the number as the code of a character. **A** is what you'd expect, but `string(…)` does not write digits.
Not **B**: both sides are `string`, so `+` works.

</details>

```console
$ ./_video/run.sh 11-string-xato
jami: �
```

The largest character code in Unicode is 1,114,111 (U+10FFFF), and 3,067,216 is bigger. No character has that
code, so Go put the replacement character: a diamond with a question mark inside (U+FFFD). The program ran without
an error, and the amount on the receipt is broken.

**`go vet`** finds a spot like this. `go vet` is a code checker that comes with Go: it finds suspicious code
without running it (in full in [GB-3.03](/lab/youtube/gb#gb-3-03)).

```console
$ ./_video/run.sh 11-string-xato vet
main.go:7:25: conversion from int64 to string yields a string of one rune, not a string of digits
```

The message is about line 7, column 25: converting an `int64` to a `string` gives a string of one rune, not a
string of digits. A **rune** is the code of one character; we open it in [GB-2.10](/lab/youtube/gb#gb-2-10). The `go vet`
message has no `./`, only `main.go`.

**The fix:** `fmt.Sprintf("%d", total)`, or `fmt.Printf("jami: %d\n", total)` directly.

### 2. The verb doesn't match the argument: `%!d(string=choy)`

The template has `%d`, so it expects an integer, but the argument is `name`, a `string`:

```go filename="_video/12-feyl-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "choy"
	fmt.Printf("%d\n", name)
}
```

The compiler stopped the type mismatch with `+`. What about this time?

**A)** a compile error · **B)** it runs and prints `choy` · **C)** it runs, but prints an error marker

<details>
<summary>Answer</summary>

**C.** The program runs, but prints an error marker instead of the result. `Printf` accepts arguments of any type
and reads the template while the program runs. The compiler does not compare the argument types with the
template, so not **A**. `%d` can't write a `string`, so not **B** either.

</details>

```console
$ ./_video/run.sh 12-feyl-xato
%!d(string=choy)
```

How to read it: `%`, an exclamation mark, the verb `d`, and in parentheses the argument's real type and value. If
you see `%!` in a log, a verb and its argument don't match.

`go vet` finds this one too:

```console
$ ./_video/run.sh 12-feyl-xato vet
main.go:7:14: fmt.Printf format %d has arg name of wrong type string
```

"`fmt.Printf` on line 7: the verb `%d` got the argument `name`, whose type is wrong: `string`."

`go test` runs these two vet checks (printf and stringintconv) itself, before the tests. If vet finds something,
the tests don't run. I checked this on a copy of the folder (it is not in the folder): on line 35 of `main.go` I
passed the text `"1679"` instead of the VAT amount:

```go
fmt.Printf("%-14s %9d.%02d\n", "QQS", "1679", vat%tiyinPerSom)
```

```console
$ go test
# github.com/abdurahmon27/bozor
# [github.com/abdurahmon27/bozor]
./main.go:35:20: fmt.Printf format %9d has arg "1679" of wrong type string
FAIL	github.com/abdurahmon27/bozor [build failed]
```

`[build failed]`: the tests did not run at all. So in the task a mistake like this does not pass the test.

### 3. Other mistakes from the video

- **`"jami: " + total`**: `mismatched types string and int64`. `fmt.Sprintf`/`fmt.Printf` turns a number into
  text (section "Joining text").
- **Forgotten `\n`**: two `Printf` calls stick together on one line, with no error. Put `\n` at the end of the
  template (section "Without `\n`").
- **`%d.%d` for tiyin**: 4 tiyin comes out as `.4` and reads as 40 tiyin, with no error. Use `%02d` for tiyin
  (section "Tiyin").

## Check yourself

**1.** Why doesn't `label + total` (`string` and `int64`) compile, and what is the right way?

<details>
<summary>Answer</summary>

Both sides of `+` must have the same type, and Go does not turn a number into text by itself:
`invalid operation: label + total (mismatched types string and int64)`. The right way is to format the number, for
example `fmt.Sprintf("%d", total)` or directly `fmt.Printf("jami: %d\n", total)`. Not `string(total)` (mistake 1).

</details>

**2.** The amount has 4 tiyin. How does the tiyin part come out with `%d.%d`, and what fixes it?

<details>
<summary>Answer</summary>

One `4` after the dot: `1919.4`. The fix is `%02d`: width 2, empty space as zero, giving `1919.04`.

</details>

**3.** Predict the output (`|` is plain text here):

```go
package main

import "fmt"

func main() {
	fmt.Printf("%-5s|%3d|%03d\n", "non", 4, 4)
	fmt.Printf("%q\n", "choy")
}
```

<details>
<summary>Answer</summary>

`%-5s` gives `non` and 2 spaces; `%3d` gives 2 spaces and `4`; `%03d` gives `004`. `%q` prints the text in quotes.

```console
$ go run .
non  |  4|004
"choy"
```

</details>

**4.** What is on screen after the line `item := fmt.Sprintf("%s, %d dona", name, sold)`?

<details>
<summary>Answer</summary>

Nothing. `Sprintf` does not print the result; it returns it as a `string`, which is stored in `item`. The next
`Println` or `Printf` prints it.

</details>

**5.** From GB-1.01: what is the difference between `go run .` and `go build`?

<details>
<summary>Answer</summary>

`go run .` builds a temporary executable and runs it right away; nothing stays in the folder. `go build` leaves an
executable named `bozor` in the folder, and you run it with `./bozor`.

</details>

- 🟢 **Easy · a delivery line on the receipt.** The receipt has no delivery line, but `jami` includes delivery:

  and the total, **with the same template**. Don't touch the lines above. The last four lines must be:

```text
choy, 7 dona       13993.00
QQS                 1679.16
yetkazish          15000.00
```

Hints (from `TASK.md`):

1. `deliverySom` is in som, the other amounts are in tiyin. The som part is `deliverySom` itself, the tiyin part
   is `0`. Or first convert it to tiyin (`deliverySom * tiyinPerSom`), then split it in two with `/` and `%` like
   the other lines.
2. The rule from GB-1.03: mixing `int64` and `int` gives `mismatched types`. If you need a new variable, write its
   type explicitly: `var … int64 = …`.
3. Copy the template from the other lines: `"%-14s %9d.%02d\n"`. Don't pass the amount as ready-made text
   (`"15000.00"`) or as a hand-typed number (`15000`): the second test checks this.

The check is `go test` in the folder. It runs the file `main_test.go`; don't change this file, we open it in

`main_test.go:62` means the message comes from line 62 of the test file. It says: "the receipt must have 4 lines,
now it has 3: there is no «yetkazish» line between QQS and jami", then `kerak:` ("expected") and `hozir:` ("now").
If the line count is right but a line's text differs, the message looks like `kerak: "…"` and `hozir: "…"`: the
quotes come from `%q` and show the spaces. The second test (`TestSummaHisoblanadi`) checks that `main.go` has no
hand-typed number `15000` or `1500000` and no text containing `15000`: the amount must be computed from
`deliverySom`.

<details>
<summary>Answer</summary>

```go filename="solution/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 7
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100
	total := subtotal + vat + deliverySom*tiyinPerSom

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Line | Code | What it does |
|---|---|---|
| 36 | `fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)` | the som part is `deliverySom` (15,000), the tiyin part `0`; `%02d` makes it `00` |

`deliverySom` is an untyped constant (GB-1.03), so `%9d` takes it like any integer. The second way is right too:
`var delivery int64 = deliverySom * tiyinPerSom`, then `delivery/tiyinPerSom` and `delivery%tiyinPerSom`, like the
other lines.
