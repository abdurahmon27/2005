## Что вы узнаете

В прошлом уроке bozor посчитал сумму заказа точно, до тийина. Но чек он выводит через `fmt.Println`: числа в каждой
строке стоят в разных местах, сумы и тийины идут отдельными словами. Такой чек клиенту не отдашь. Как вывести сумму
в виде `13993.00`, а все суммы — одним столбцом?

**Одна идея:** `fmt.Printf` читает шаблон слева направо. Обычный текст он выводит как есть, а вместо каждого
глагола `%` подставляет следующий аргумент в том виде и той ширине, которые задал глагол. `fmt.Sprintf` делает тот
же текст, но не выводит его на экран, а возвращает как значение `string`.

К концу урока вы:

- склеиваете две строки `string` через `+` и по сообщению понимаете, почему `string + int64` не компилируется;
- пишете шаблон `fmt.Printf` с глаголами `%s`, `%d`, `%v`, `%q` и `\n`;
- с помощью ширины (`%9d`, `%-14s`) и `0` (`%02d`) выводите сумму в столбец: сумы, точка и тийины из двух цифр;
- узнаёте две частые ошибки (`string(total)` и неверный глагол) по их выводу и по сообщению `go vet`.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| склеивание строк | `+` между двумя `string`: ставит их рядом и создаёт новую `string`; обе стороны обязаны быть одного типа | string concatenation |
| шаблон и глагол | первый аргумент `Printf` — шаблон; пара `%` и буква в нём (`%s`, `%d`) — глагол, он говорит, как записать следующий аргумент | format string, verb |
| ширина | число между `%` и буквой: значение занимает не меньше стольких символов (`%9d`); `-` выравнивает влево, `0` заполняет пустое место нулями | width (flags `-`, `0`) |

Два вспомогательных слова: **`fmt.Sprintf`** — берёт шаблон как у `Printf`, но не выводит результат на экран, а
возвращает его как `string`; и **`\n`** — символ новой строки в шаблоне.

## Исходное состояние: чек через `Println`

Это решение прошлого урока вместе с заданием. Сегодня меняются только последние три строки, то есть чек:

```go filename="_video/01-println/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 7
	stock = stock - sold
	fmt.Println(name, stock)

	subtotal := price * int64(sold)
	vat := subtotal * vatPercent / 100
	total := subtotal + vat + deliverySom*tiyinPerSom
	fmt.Println(name, sold, "dona")
	fmt.Println("QQS:", vat/tiyinPerSom, "soʻm", vat%tiyinPerSom, "tiyin")
	fmt.Println("jami:", total/tiyinPerSom, "soʻm", total%tiyinPerSom, "tiyin")
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5–7 | `const …` | `tiyinPerSom` (1 сум = 100 тийинов), `vatPercent` (НДС 12 %), `deliverySom` (доставка, 15 000 сумов) |
| 10–27 | `fmt.Println(…)`, `var …`, `:=` | строки из GB-1.01–1.03: запуск, версия, zero value, товар, склад. Сегодня их не трогаем |
| 29 | `subtotal := price * int64(sold)` | сумма за товар в тийинах: 199 900 × 7 = 1 399 300 |
| 30 | `vat := subtotal * vatPercent / 100` | НДС в тийинах: 167 916 |
| 31 | `total := subtotal + vat + deliverySom*tiyinPerSom` | итог в тийинах; `deliverySom` в сумах, поэтому умножается на 100: 3 067 216 |
| 32–34 | `fmt.Println(…)` | чек. `Println` ставит значения, переданные через запятую, подряд через один пробел и завершает строку |

Запускаем:

длиной, места под столбец не выделено: `1679` и `30672` стоят в разных местах. К концу урока `go run .` не изменит

Слева название, справа сумма в сумах, после точки тийины из двух цифр, все суммы в одном столбце. Для этого нужны
три вещи: склеивание текста через `+`, шаблон `fmt.Printf` и его глаголы, начинающиеся с `%`, и ширина, то есть
сколько места занимает значение. Строку доставки в задании вы добавите сами.

## Склеивание текста: `string` и `+`

`string` — тип текста в Go, пишется в кавычках. `+` между двумя `string` склеивает их рядом и создаёт **новую**
`string`. Это называется **concatenation** (склеивание строк).

```go
name := "choy"
label := "mahsulot: " + name
fmt.Println(label)
```

Новая переменная `label` («подпись») получает тексты `"mahsulot: "` («товар: ») и `"choy"` («чай»). Пробел после
двоеточия тоже часть текста: без него вышло бы `mahsulot:choy`. В памяти по строкам:

| Строка | Код | `name` | `label` | На экране |
|---|---|---|---|---|
| 1 | `name := "choy"` | `"choy"` | — | |
| 2 | `label := "mahsulot: " + name` | `"choy"` | `"mahsulot: choy"` | |
| 3 | `fmt.Println(label)` | `"choy"` | `"mahsulot: choy"` | `mahsulot: choy` |

`+` не меняет `name`: там всё то же `"choy"`. Результат — отдельное значение, оно записывается в `label`.

Теперь попробуем приклеить к тексту сумму. `total` — `int64`, в тийинах; `label` — `"jami: "`:

```go filename="_video/03-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var total int64 = 3_067_216 // tiyinda
	label := "jami: "
	fmt.Println(label + total)
}
```

```console
$ ./_video/run.sh 03-xato
# github.com/abdurahmon27/bozor
./main.go:8:14: invalid operation: label + total (mismatched types string and int64)
```

Читаем сообщение:

- `# github.com/abdurahmon27/bozor` — путь модуля из GB-1.01: ошибка в коде этого модуля.
- `./main.go:8:14` — `main.go`, строка 8, столбец 14 (Tab — один столбец, `label` начинается в столбце 14).
- `invalid operation: label + total` — «недопустимая операция: `label + total`».
- `(mismatched types string and int64)` — «типы не совпадают: `string` и `int64`».

Правило: обе стороны `+` должны быть одного типа. Go сам не превращает число в текст. Ошибка с `int64` и `int` из
GB-1.03 следовала из того же правила. Нетипизированная числовая константа подстраивается под другой числовой тип, но
в текст не превращается. Вставить число в текст — задача форматирования, её решает `fmt.Printf` из следующего
раздела.

## `fmt.Printf`: шаблон и глаголы

`Printf` из пакета `fmt` принимает первым аргументом **шаблон** (format string). Пара `%` и буква в шаблоне
называется **глаголом** (по-английски **verb**). Остальные аргументы по порядку подставляются вместо глаголов.

```go filename="_video/04-printf/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "choy"
	var price int64 = 199_900 // tiyinda
	fmt.Printf("%s: %d tiyin\n", name, price)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `name := "choy"` | название товара, `string` |
| 7 | `var price int64 = 199_900` | цена в тийинах (1 999 сумов) |
| 8 | `fmt.Printf("%s: %d tiyin\n", name, price)` | шаблон `"%s: %d tiyin\n"`, затем два аргумента |

Внутри шаблона:

- `%s` — подставляет следующий аргумент-`string` как есть;
- `%d` — пишет целое число десятичными цифрами (по-английски *decimal*);
- `\n` — обратная косая черта и `n`: символ новой строки. Go хранит его в кавычках не как два символа, а как
  **один**.

`Printf` читает шаблон слева направо. Обычный текст выводит как есть. Дойдя до первого глагола, берёт первый
аргумент, до второго — второй:

| Часть шаблона | Что происходит | На экран |
|---|---|---|
| `%s` | подставляется 1-й аргумент `name` | `choy` |
| `: ` | обычный текст | `: ` |
| `%d` | подставляется 2-й аргумент `price` | `199900` |
| ` tiyin` | обычный текст | ` tiyin` |
| `\n` | символ новой строки | строка заканчивается |

```console
$ ./_video/run.sh 04-printf
choy: 199900 tiyin
```

`%d` пишет цифры без подчёркиваний: `199_900` было только для чтения кода (GB-1.03).

### Если нет `\n`

Теперь уберём `\n` и вызовем `Printf` дважды, во втором вызове `"non"` («хлеб») и 400 000 тийинов:

```go filename="_video/05-qator/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "choy"
	var price int64 = 199_900 // tiyinda
	fmt.Printf("%s: %d tiyin", name, price)
	fmt.Printf("%s: %d tiyin", "non", 400_000)
}
```

Подумайте до запуска: где появится второй товар?

**A)** на следующей строке · **B)** на одной строке с первым · **C)** нигде, ошибка компиляции

<details>
<summary>Ответ</summary>

**B.** Оба склеиваются в одну строку: сразу после слова `tiyin` идёт `non`. `Printf` сам строку не завершает, он
выводит только то, что написано в шаблоне. Если вы выбрали **A**, вы считали `Printf` похожим на `Println`:
`Println` ставит конец строки сам, `Printf` — нет. Код корректен, поэтому и не **C**.

</details>

```console
$ ./_video/run.sh 05-qator
choy: 199900 tiyinnon: 400000 tiyin
```

Конец строки ставите вы, через `\n`. Здесь и сама программа не заканчивается на `\n`: строка терминала, ждущая
следующую команду, появится в продолжение этой строки.

### Ещё два глагола: `%v` и `%q`

`%v` выводит любое значение в его стандартном виде: число, `string`, `true` или `false`. Удобно, когда тип не важен
(по-английски *value*). `%q` выводит текст в кавычках (по-английски *quoted*).

```go filename="_video/06-feyllar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	input := " choy "
	sold := 7
	active := true
	fmt.Printf("%v dona, sotuvda: %v\n", sold, active)
	fmt.Printf("%s\n", input)
	fmt.Printf("%q\n", input)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `input := " choy "` | текст, введённый пользователем: `choy` с пробелом спереди и сзади |
| 7 | `sold := 7` | сколько штук продано |
| 8 | `active := true` | `bool`: товар в продаже или нет |
| 9 | `fmt.Printf("%v dona, sotuvda: %v\n", sold, active)` | оба значения через `%v` (`sotuvda` — «в продаже») |
| 10 | `fmt.Printf("%s\n", input)` | `input` через `%s` |
| 11 | `fmt.Printf("%q\n", input)` | `input` через `%q` |

Подумайте: видны ли пробелы в строке, выведенной через `%s`?

<details>
<summary>Ответ</summary>

Передний пробел виден (строка начинается с отступа), а последний — нет: на экране пробел ничем не отличается от
пустоты. `%q` ставит кавычки, поэтому видны оба пробела.

</details>

```console
$ ./_video/run.sh 06-feyllar
7 dona, sotuvda: true
 choy 
" choy "
```

В 1-й строке и число, и `true` вышли через `%v`. В конце 2-й строки есть пробел, но его не видно. В 3-й строке
кавычки показывают оба пробела. Строки, которые сервер пишет о своей работе, называются **логом** (log). Если
писать пользовательский текст в лог через `%q`, лишний пробел сразу заметен.

Итого:

| Глагол | Для чего | Пример | Вывод |
|---|---|---|---|
| `%s` | `string` | `"choy"` | `choy` |
| `%d` | целое число, десятичное | `199_900` | `199900` |
| `%v` | любое значение, стандартный вид | `7`, `true` | `7`, `true` |
| `%q` | текст в кавычках | `" choy "` | `" choy "` |

## Тийины: ошибка `%d.%d` и `%02d`

Теперь выведем НДС в сумах, с точкой и тийинами. Когда чая 8 штук, НДС в тийинах равен `191_904`:
1 999 × 100 × 8 = 1 599 200 тийинов, 12 % от этого — 191 904.

```go filename="_video/07-pul/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100

func main() {
	var vat int64 = 191_904 // choy, 8 dona: QQS tiyinda
	fmt.Printf("QQS: %d.%d soʻm\n", vat/tiyinPerSom, vat%tiyinPerSom)
}
```

`vat/tiyinPerSom` — часть в сумах (целочисленное деление отбрасывает дробь: `1919`). `vat%tiyinPerSom` — часть в
тийинах, остаток: `4`. Осторожно: `%` **в коде** — операция остатка (GB-1.03), а `%` **в шаблоне** — начало
глагола. Друг с другом они никак не связаны.

`vat` — 191 904 тийина. Что появится на экране?

**A)** `QQS: 1919.04 soʻm` · **B)** `QQS: 1919.4 soʻm` · **C)** `QQS: 1919.40 soʻm`

<details>
<summary>Ответ</summary>

**B: `QQS: 1919.4 soʻm`.** Остаток `4`, `%d` пишет его одной цифрой. Если вы выбрали **A**, вы думали, что `%d`
выделяет место под две цифры: не выделяет, число пишется своей длиной. Для **C** Go должен был бы знать, что цифра
после точки — деньги; он лишь ставит рядом два отдельных целых числа через точку.

</details>

```console
$ ./_video/run.sh 07-pul
QQS: 1919.4 soʻm
```

Клиент прочитает это как 40 тийинов, а на самом деле 4 тийина. Это настоящая ошибка в чеке, а компилятор и
программа молчат.

**Исправление:** второй глагол — `%02d`. `2` между `%` и `d` — это **ширина** (width): результат занимает не
меньше 2 символов. `0` перед ней — флаг (flag): заполняет пустое место не пробелом, а нулём.

```go filename="_video/08-pul-tuzat/main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100

func main() {
```

## Ширина: столбец через `%9d` и `%-14s`

Ширина работает с любым глаголом. Число между `%` и буквой — ширина, результат занимает не меньше стольких символов:

- `%9d` — сдвигает число к **правому** краю столбца из 9 символов, слева заполняет пробелами;
- `%-14s` — флаг `-` выравнивает влево: ставит название к левому краю места из 14 символов, справа заполняет.

Пока только часть в сумах:

```go filename="_video/09-jadval/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Printf("%-14s %9d\n", "QQS", 1679)
	fmt.Printf("%-14s %9d\n", "yetkazish", 15000)
	fmt.Printf("%-14s %9d\n", "jami", 30672)
}
```

Проверим до запуска. В шаблоне две пары квадратных скобок (здесь это обычный текст), внутри `%-6s` и `%4d`,
аргументы `"QQS"` и `7`:

```go
fmt.Printf("[%-6s][%4d]", "QQS", 7)
```

Что выйдет?

**A)** `[QQS   ][   7]` · **B)** `[   QQS][7   ]` · **C)** `[QQS][7]`

<details>
<summary>Ответ</summary>

**A.** `QQS` слева в месте из 6 символов (справа 3 пробела), `7` справа в месте из 4 символов (слева 3 пробела).
Если вы выбрали **B**, вы поняли `-` наоборот: `-` выравнивает влево, без `-` число сдвигается вправо. **C** —
результат без ширины.

Этого примера в папке нет; я запустил его сам (добавил в конец `\n`, чтобы в терминале вывод был аккуратным):

```go
package main

import "fmt"

func main() {
	fmt.Printf("[%-6s][%4d]\n", "QQS", 7)
}
```

```console
$ go run .
[QQS   ][   7]
```

</details>

Каждая ячейка — один символ:

```text
%-6s  "QQS"  ->  [Q][Q][S][ ][ ][ ]   влево, справа пробелы
%4d   7      ->  [ ][ ][ ][7]         вправо, слева пробелы
%02d  4      ->  [0][4]               ширина 2, пустое место нулём
```

Теперь три строки из папки (`yetkazish` — «доставка»):

```console
$ ./_video/run.sh 09-jadval
QQS                 1679
yetkazish          15000
jami               30672
```

Названия разной длины (`QQS` — 3, `yetkazish` — 9 символов), но правые края чисел на одной линии.

Ширина — это минимум, а не предел. Если текст длиннее ширины, он не обрезается, столбец сдвигается. Этого примера
тоже нет в папке: `"yetkazib berish"` — 15 символов, на один длиннее `%-14s`.

```go
package main

import "fmt"

func main() {
	fmt.Printf("%-14s %9d\n", "QQS", 1679)
	fmt.Printf("%-14s %9d\n", "yetkazib berish", 15000)
	fmt.Printf("%-14s %9d\n", "jami", 30672)
}
```

```console
$ go run .
QQS                 1679
yetkazib berish     15000
jami               30672
```

Число во 2-й строке сдвинулось на один символ вправо. Поэтому ширину выбирают по самому длинному названию.

Итого: число — ширина, `-` выравнивает влево, `0` заполняет пустое место нулями.

## `fmt.Sprintf`: результат возвращается как `string`

В строке товара в левом столбце нужны два значения: название и количество (`choy, 7 dona`). Ширина применяется к
одному аргументу, поэтому сначала соберём их в один текст. Это делает **`fmt.Sprintf`**: шаблон точно как у
`Printf`, но результат не выводится на экран, а **возвращается** как `string`.

```go filename="_video/10-sprintf/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "choy"
	sold := 7
	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Println(item)
}
```

Там, где написан `fmt.Sprintf(…)`, получается этот текст, а `:=` отдаёт его новой переменной `item` («позиция»):

| Строка | Код | `name` | `sold` | `item` | На экране |
|---|---|---|---|---|---|
| 6 | `name := "choy"` | `"choy"` | | | |
| 7 | `sold := 7` | `"choy"` | `7` | | |
| 8 | `item := fmt.Sprintf("%s, %d dona", name, sold)` | `"choy"` | `7` | `"choy, 7 dona"` | пока ничего |
| 9 | `fmt.Println(item)` | `"choy"` | `7` | `"choy, 7 dona"` | `choy, 7 dona` |

```console
$ ./_video/run.sh 10-sprintf
choy, 7 dona
```

После 8-й строки на экране ещё ничего нет. Текст выводит `Println` в 9-й строке.

## Итоговый чек

Собираем всё в bozor. Верхняя часть и расчёт (строки 1–31) не изменились, три `Println` в конце заменены:

```go filename="main.go" showLineNumbers

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
```

| 34 | `fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)` | строка товара: 1 399 300 тийинов → `13993` и `00` |

## Частые ошибки

### 1. `string(total)` даёт не цифры, а один символ

В прошлом уроке мы видели преобразование (conversion): `int64(sold)`. Кто-то тем же способом превращает сумму в
текст и приклеивает её через `+` к `"jami: "`:

```go filename="_video/11-string-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var total int64 = 3_067_216 // tiyinda
	fmt.Println("jami: " + string(total))
}
```

Что будет, если скомпилировать и запустить?

**A)** выведется `jami: 3067216` · **B)** ошибка компиляции · **C)** вместо числа один символ

<details>
<summary>Ответ</summary>

**C.** Код компилируется, и вместо числа выводится один символ. Когда пишут `string(число)`, Go считает число кодом
символа. **A** — ожидаемый результат, но `string(…)` цифры не пишет. Не **B**: обе стороны — `string`, поэтому `+`
работает.

</details>

```console
$ ./_video/run.sh 11-string-xato
jami: �
```

Самый большой код символа в Unicode — 1 114 111 (U+10FFFF), а 3 067 216 больше. Символа с таким кодом нет, поэтому
Go поставил символ замены: ромб с вопросительным знаком внутри (U+FFFD). Программа отработала без ошибок, а сумма в
чеке испорчена.

Такое место находит **`go vet`**. `go vet` — анализатор кода, который поставляется вместе с Go: он находит
подозрительные места, не запуская код (подробно в [GB-3.03](/lab/youtube/gb#gb-3-03)).

```console
$ ./_video/run.sh 11-string-xato vet
main.go:7:25: conversion from int64 to string yields a string of one rune, not a string of digits
```

Сообщение о строке 7, столбце 25: «преобразование из `int64` в `string` даёт не строку цифр, а строку из одной
руны». **rune** (руна) — код одного символа; её разберём в [GB-2.10](/lab/youtube/gb#gb-2-10). В сообщении `go vet` нет
`./`, только `main.go`.

**Исправление:** `fmt.Sprintf("%d", total)` или сразу `fmt.Printf("jami: %d\n", total)`.

### 2. Глагол не подходит к аргументу: `%!d(string=choy)`

В шаблоне `%d`, то есть ожидается целое число, а аргумент — `name`, то есть `string`:

```go filename="_video/12-feyl-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	name := "choy"
	fmt.Printf("%d\n", name)
}
```

Ошибку типов с `+` компилятор остановил. А в этот раз?

**A)** ошибка компиляции · **B)** работает и выводит `choy` · **C)** работает, но выводит пометку об ошибке

<details>
<summary>Ответ</summary>

**C.** Программа работает, но вместо результата выводит пометку об ошибке. `Printf` принимает аргументы любого
типа, а шаблон читает во время работы программы. Компилятор не сверяет типы аргументов с шаблоном, поэтому не
**A**. `%d` не умеет записывать `string`, поэтому и не **B**.

</details>

```console
$ ./_video/run.sh 12-feyl-xato
%!d(string=choy)
```

Как читать: `%`, восклицательный знак, глагол `d`, в скобках исходный тип аргумента и значение. Увидели в логе
`%!` — глагол и аргумент не совпадают.

`go vet` находит и это:

```console
$ ./_video/run.sh 12-feyl-xato vet
main.go:7:14: fmt.Printf format %d has arg name of wrong type string
```

«`fmt.Printf` в строке 7: глаголу `%d` передан аргумент `name`, его тип неверный — `string`».

`go test` сам запускает эти две проверки vet (printf и stringintconv) перед тестами. Если vet что-то нашёл, тесты
не запускаются. Я проверил это на копии папки (в папке такого нет): в строке 35 `main.go` вместо суммы НДС передал
текст `"1679"`:

```go
fmt.Printf("%-14s %9d.%02d\n", "QQS", "1679", vat%tiyinPerSom)
```

```console
$ go test
# github.com/abdurahmon27/bozor
# [github.com/abdurahmon27/bozor]
./main.go:35:20: fmt.Printf format %9d has arg "1679" of wrong type string
FAIL	github.com/abdurahmon27/bozor [build failed]
```

`[build failed]` — «сборка не удалась»: тесты вообще не запускались. Поэтому в задании такая ошибка тест не
пройдёт.

### 3. Другие ошибки из видео

- **`"jami: " + total`** — `mismatched types string and int64`. Число в текст превращает `fmt.Sprintf`/`fmt.Printf`
  (раздел «Склеивание текста»).
- **Забыт `\n`** — два `Printf` склеиваются в одну строку, ошибки нет. Ставьте `\n` в конце шаблона (раздел
  «Если нет `\n`»).
- **`%d.%d` для тийинов** — 4 тийина выходят как `.4` и читаются как 40 тийинов, ошибки нет. Для тийинов —
  `%02d` (раздел «Тийины»).

```go filename="solution/main.go" showLineNumbers
	total := subtotal + vat + deliverySom*tiyinPerSom

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 36 | `fmt.Printf("%-14s %9d.%02d\n", "yetkazish", deliverySom, 0)` | часть в сумах — `deliverySom` (15 000), тийины — `0`, `%02d` превращает его в `00` |

`deliverySom` — нетипизированная константа (GB-1.03), поэтому `%9d` принимает её как обычное целое число. Второй
путь тоже верен: `var delivery int64 = deliverySom * tiyinPerSom` и `delivery/tiyinPerSom`,
`delivery%tiyinPerSom`, как в остальных строках.
