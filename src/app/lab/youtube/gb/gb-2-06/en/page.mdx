## What you will learn

The code of bozor ("market") is still in one file, `main.go`: a catalog called `st`, its `Add` method and the `products` slice inside
it. `main` writes straight into that slice and drops the stock of apples (`olma`) to minus five. The compiler says nothing:

```go
func main() {
	var st Store
	st.Add("olma", 1_200_000, 40)
	st.products[0].Stock = -5
	fmt.Println(st.products[0].Stock)
}
```

```console
$ ./_video/run.sh 00-birfayl go run .
-5
```

The catalog's rule ("stock is never negative") must be written in the methods of `Store`. But `products` is open to everyone, so any
line of code can go around the rule. If we split the code into packages, the compiler closes that path itself. How, and which hole
is left?

**One idea:** a package in Go is the files of one folder, and an import path is the module name plus the folder. Only names that
start with a capital letter cross the package boundary, and the `internal/` folder limits who may import a package to the module
itself. This boundary makes the rule impossible to bypass.

By the end of the lesson you will:

- split one `main.go` into the packages `cmd/bozor` (the program) and `internal/store` (the catalog) and run it with `go run ./cmd/bozor`;
- read the `unexported` error and refer to a name in another package with a capital letter;
- add an external module with `go mod tidy` and know what `go.sum` checks;
- read the `internal/` error and say who this folder allows to import.

Three core new words today:

| Word | Plain meaning | English term |
|---|---|---|
| package | the set of Go files in one folder; every file starts with a `package` line, and all files of a folder write the same name in it | package |
| exported name | a name that starts with a capital letter: other packages can see it. A lowercase name is visible only in its own package | exported / unexported |
| `internal/` folder | a package inside it can be imported only by code under the parent folder of `internal` | internal directory |

Two helper ideas: the **import path** (the full name of a package) and an **external module** with the `go.sum` file.

## The problem: the catalog's rule is not in one place

The program from the start of the lesson (`_video/00-birfayl/main.go`): the bozor catalog and `main`, all in one file.

```go filename="_video/00-birfayl/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// Store — xotiradagi katalog.
type Store struct {
	products []Product
}

// Add katalogga mahsulot qoʻshadi va unga ID beradi.
func (s *Store) Add(name string, price int64, stock int) Product {
	p := Product{ID: int64(len(s.products)) + 1, Name: name, Price: price, Stock: stock}
	s.products = append(s.products, p)
	return p
}

// List katalogdagi mahsulotlarni qaytaradi.
func (s *Store) List() []Product {
	return s.products
}

func main() {
	var st Store
	st.Add("olma", 1_200_000, 40)
	st.products[0].Stock = -5
	fmt.Println(st.products[0].Stock)
}
```

Lines 5–11 are the `Product` type from GB-2.03. The new lines:

| Line | Code | What it does |
|---|---|---|
| 14–16 | `type Store struct { products []Product }` | `Store` is the catalog type. It has one field: `products`, a slice of `Product` |
| 19 | `func (s *Store) Add(name string, price int64, stock int) Product {` | `Add` is a method of `Store`. The receiver is a pointer: `*Store`, because the method changes the catalog (GB-2.05). The result is the added `Product` |
| 20 | `p := Product{ID: int64(len(s.products)) + 1, …}` | the `ID` of the new product is the slice length plus one: 1, 2, 3. The other fields come from the parameters |
| 21 | `s.products = append(s.products, p)` | adds the product to the slice; the result of `append` must be stored back into `s.products` (GB-2.01) |
| 22 | `return p` | returns a **copy** of the added product |
| 26–28 | `func (s *Store) List() []Product { return s.products }` | a new method: returns the products of the catalog |
| 31 | `var st Store` | an empty catalog: `products` is a nil slice. `append` works on a nil slice too, so `Add` works at once |
| 32 | `st.Add("olma", 1_200_000, 40)` | apples (price 1,200,000 tiyin, stock 40) are the first product in the catalog, `ID` 1 |
| 33 | `st.products[0].Stock = -5` | `main` writes directly into the catalog's inner slice: the stock of the first product becomes −5 |
| 34 | `fmt.Println(st.products[0].Stock)` | prints that stock |

The compiler says nothing: in one file `main` and `Store` see each other's names. However you write the stock rule into `Add` and
the later methods, line 33 goes around it.

| Step | `st.products[0].Stock` | On screen |
|---|---|---|
| `st.Add("olma", …, 40)` (line 32) | 40 | |
| `st.products[0].Stock = -5` (line 33) | **−5** | |
| `fmt.Println(…)` (line 34) | −5 | `-5` |

## Package: the files of one folder

A **package** in Go is the Go files of one folder. The first line of code in every file is `package` and the package name; all files
of one folder write the same name. This rule is in the Go specification: the files that share the same package name form the
implementation of that package ([Go spec: Package clause](https://go.dev/ref/spec#Package_clause)).

There are two kinds of package:

- `package main` — a program you can run. `go run` and `go build` run it (GB-1.01).
- any other name (`store`, `fmt`) — a package that other code imports. `fmt` is such a package too: its files are in the `fmt` folder
  of Go's own library.

We split bozor like this:

```text
bozor/
├── go.mod
├── cmd/
│   └── bozor/
│       └── main.go        package main
└── internal/
    └── store/
        └── store.go       package store
```

- `cmd/bozor/main.go` — the program (`package main`). In `cmd/` every program has its own folder; in module 4 of the course a second
  program appears next to bozor.
- `internal/store/store.go` — the catalog, package name `store`. We explain the word `internal` at the end of the lesson.
- `go.mod` — in the root, with the module name (GB-1.01).

We create the folders. Right now the current folder holds `go.mod` and `main.go`:

```console
$ mkdir -p cmd/bozor internal/store
$ mv main.go cmd/bozor/
```

Both commands print nothing. `mkdir -p` creates both paths at once: `-p` also creates the intermediate folders (`cmd`, `internal`) and
gives no error if a folder already exists. `mv main.go cmd/bozor/` moves `main.go` into `cmd/bozor`. Then we move `Product`, `Store` and
their methods into a new file, `store.go`.

`internal/store/store.go`:

```go filename="_video/01-paket/internal/store/store.go" showLineNumbers
package store

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// Store — xotiradagi katalog.
type Store struct {
	products []Product
}

// Add katalogga mahsulot qoʻshadi va unga ID beradi.
func (s *Store) Add(name string, price int64, stock int) Product {
	p := Product{ID: int64(len(s.products)) + 1, Name: name, Price: price, Stock: stock}
	s.products = append(s.products, p)
	return p
}

// List katalogdagi mahsulotlarni qaytaradi.
func (s *Store) List() []Product {

}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `package store` | the file belongs to the `store` package. The package name equals the folder name: the compiler does not require this, but in Go it is the custom ([Effective Go: Package names](https://go.dev/doc/effective_go#package-names)) |
| 3–9, 12–14, 17–21 | `Product`, `Store`, `Add` | the bodies are the same as in 00-birfayl, unchanged |
| 24–26 | `func (s *Store) List() []Product` | `List` is not new: it was in 00-birfayl too. It returns the products of the catalog |

Now `cmd/bozor/main.go`. A second line is added to its `import`:

```go filename="_video/01-paket/cmd/bozor/main.go" showLineNumbers
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	}

```

| Line | Code | What it does |
|---|---|---|
| 3–7 | `import ( … )` | imports two packages (GB-1.07). The standard package (`fmt`) is in its own group, ours in another: the blank line between them is for that |
| 6 | `"github.com/abdurahmon27/bozor/internal/store"` | the **import path** of the `store` package |
| 10 | `var st store.Store` | a name from another package is reached with the package name and a dot: `store.Store`, like `fmt.Println`. `st` is an empty catalog |
| 11–12 | `st.Add(…)` | add two products: apples (ID 1) and bread (`non`, ID 2) |
| 13–15 | `for _, p := range st.List() { … }` | loops over the products `List` returned (GB-1.06) and prints the `ID`, `Name` and `Price` of each |

An **import path** has two parts: the module name from `go.mod`, then the folder inside the module. We wrote the module name in the
first lesson with `go mod init`:

```console
$ cat go.mod
module github.com/abdurahmon27/bozor

go 1.27
```

| Part | Value | Where from |
|---|---|---|
| module name | `github.com/abdurahmon27/bozor` | the `module` line of `go.mod` |
| folder inside the module | `internal/store` | the file tree |
| import path | `github.com/abdurahmon27/bozor/internal/store` | the two are joined with `/` ([Go Modules Reference](https://go.dev/ref/mod#modules-overview)) |

## Capital letter: what is visible outside the package

Now the line from the start of the lesson. `main` writes minus five straight into the stock of apples. In one file this worked; now
`products` is in another package (`_video/02-eksport/cmd/bozor/main.go`):

```go filename="_video/02-eksport/cmd/bozor/main.go" showLineNumbers
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)
	st.products[0].Stock = -5
	for _, p := range st.List() {
		fmt.Println(p.ID, p.Name, p.Price)
	}
}
```

What does `go run ./cmd/bozor` do?

**A)** runs, the stock is −5 · **B)** compile error · **C)** the program runs and crashes with a panic

<details>
<summary>Answer</summary>

**B.** If you chose **A**, you relied on the result from the single file: there `main` and `Store` were in the same package. **C** — a
panic happens while the program is **running**, and this is caught by compilation: the program does not start at all.

</details>

```console
$ ./_video/run.sh 02-eksport go run ./cmd/bozor
# github.com/abdurahmon27/bozor/cmd/bozor
cmd/bozor/main.go:13:5: st.products undefined (cannot refer to unexported field products)
```

We read the message line by line:

- `# github.com/abdurahmon27/bozor/cmd/bozor` — which package was being compiled when the error appeared: `cmd/bozor`.
- `cmd/bozor/main.go:13:5` — file, line, column (GB-1.01): line 13, column 5, that is, the start of the word `products`.
- `st.products undefined` — "`st.products` is not defined": the compiler does not see the name `products` on `st`.
- `(cannot refer to unexported field products)` — the reason: "you cannot refer to an unexported field". `products` is in another
  package and it is unexported.

Go has one rule. If a name starts with a **capital letter**, it is **exported**: other packages can see it. If it starts with a
lowercase letter, it is visible only in its own package — in all files of that folder. More precisely, the first character must be a
Unicode upper-case letter ([Go spec: Exported identifiers](https://go.dev/ref/spec#Exported_identifiers)).

The rule works the same for package-level types, functions, constants and variables, and also for fields and methods:

| Name | First letter | To another package |
|---|---|---|
| `Store`, `Product`, `Add`, `List` | capital | visible |
| `Product.Stock`, `Product.Name` | capital | visible |
| `fmt.Println` | capital `P` | visible: that is why the `P` in the first lesson is capital |
| `products` | lowercase | only inside the `store` package |

In the picture: `main` sees only the capital-letter names of `store`.

```text
 cmd/bozor (package main)          internal/store (package store)
┌──────────────────────┐          ┌───────────────────────────────┐
│ st.Add(…)            │ ───────► │ Store, Product, Add, List     │ exported
│ st.List()            │ ───────► │                               │
│ st.products     ✗    │ ─ ─ ╳    │ products                      │ only inside store
└──────────────────────┘          └───────────────────────────────┘
```

Now the catalog changes only through the methods of `store`: the stock rule is written in one place — inside `store`. This is exactly
what a package boundary is for in real work.

A question. In `main`, `p := st.Add("choy", 3_000_000, 10)` was written ("choy" means "tea"). There are two lines: `st.products = nil` and `p.Stock = 0`. Which


**A)** `st.products = nil` · **B)** `p.Stock = 0` · **C)** both are errors

<details>
<summary>Answer</summary>

**B.** `Stock` has a capital letter: it is an exported field. `products` has a lowercase letter: it is closed.

```console
$ go run ./cmd/bozor

cmd/bozor/main.go:10:5: st.products undefined (cannot refer to unexported field products)
```

The error is only for line 10. If I delete line 10, the program builds and runs (it prints nothing). But `p.Stock = 0` does **not**
change the catalog: `Add` returned a copy of the product, and we saw the struct copy in GB-2.03. If you chose **A**, you forgot that `st.products`
is closed; if you chose **C**, you thought `p.Stock` is closed too.

</details>

### The hole in the boundary

But our boundary still has one hole. `List` returns the inner slice. `main` writes minus five into the first element of the result, then
calls `List` again and prints the stock of apples. `products` is not written here (`_video/06-teshik/cmd/bozor/main.go`):

```go filename="_video/06-teshik/cmd/bozor/main.go" showLineNumbers
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)
	st.List()[0].Stock = -5
	fmt.Println(st.List()[0].Stock)
}
```

What is printed?

**A)** `40` · **B)** `-5` · **C)** compile error

<details>
<summary>Answer</summary>

**B: `-5`.** If you chose **C**, you thought line 13 writes to `products`: it is not there, there is the result of `List()`, and the compiler
only checks whether a name is exported. If you chose **A**, you thought `List` returns a copy.

</details>

```console
$ ./_video/run.sh 06-teshik go run ./cmd/bozor
-5
```

The compiler is silent because the write went not to `products` but to the result of `List`. You know from GB-2.01: when a slice is returned,
only its header (the length and the pointer to the array) is copied, and the array itself is shared. `List` handed the inner array of `store` to the outside.

| Step | array inside `store`, apples | slice from `List()`, apples |
|---|---|---|
| `st.Add("olma", …, 40)` | 40 | |
| `st.List()` | 40 | **points to the same array**: 40 |
| `st.List()[0].Stock = -5` | **−5** | −5 |
| `st.List()[0].Stock` (second call) | −5 | −5, on screen `-5` |

You close this hole in the homework by making `List` return a copy (below, "Homework").

## External module: the price in som, with digit groups

Now we print prices in som with digit groups: "12 000", with a space in the middle. `fmt` does not group digits. The `golang.org/x/text`
module of the Go team does it: it is outside the standard library, but part of the Go project
([Go wiki: X-Repositories](https://go.dev/wiki/X-Repositories), [x/text](https://pkg.go.dev/golang.org/x/text)). We take two packages from it:
`language` gives a language tag, `message` creates a printer adapted to a language. `_video/04-modul/cmd/bozor/main.go`:

```go filename="_video/04-modul/cmd/bozor/main.go" showLineNumbers
package main

import (
	"github.com/abdurahmon27/bozor/internal/store"
	"golang.org/x/text/language"
	"golang.org/x/text/message"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	printer := message.NewPrinter(language.Uzbek)
	for _, p := range st.List() {
		printer.Printf("%d. %s: %d soʻm\n", p.ID, p.Name, p.Price/tiyinPerSom)
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 3–7 | `import ( … )` | `fmt` is removed: it is no longer used. `golang.org/x/text/language` and `…/message` are two external packages |
| 9 | `const tiyinPerSom = 100` | 1 som = 100 tiyin (GB-1.03) |
| 16 | `printer := message.NewPrinter(language.Uzbek)` | `language.Uzbek` is the tag of the Uzbek language; `message.NewPrinter` returns a printer that prints by the rules of that language. We put it in the variable `printer` |

## internal/: who can import a package

Inside the `x/text` module there is a package `internal/number`; `message` formats numbers through it. Let us import it directly
(`_video/05-internal/cmd/bozor/main.go`):

```go filename="_video/05-internal/cmd/bozor/main.go" showLineNumbers
package main

import (
	"github.com/abdurahmon27/bozor/internal/store"
	"golang.org/x/text/internal/number"
	"golang.org/x/text/language"
	"golang.org/x/text/message"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	printer := message.NewPrinter(language.Uzbek)
	for _, p := range st.List() {
		printer.Printf("%d. %s: %d soʻm\n", p.ID, p.Name, p.Price/tiyinPerSom)
	}
}
```

The package exists, the module is downloaded; the only new line is line 5 (`number`). Does it compile? What does `go run ./cmd/bozor` say?

**A)** it works · **B)** error: use of an internal package is not allowed · **C)** error: `number` is not used

<details>
<summary>Answer</summary>

**B.** If you chose **A**, you thought an existing package can be imported. **C** — you know from GB-1.01 that an unused import is an error; but here
the check never gets as far as that message (the reason is below).

</details>

```console
$ ./_video/run.sh 05-internal go run ./cmd/bozor
package github.com/abdurahmon27/bozor/cmd/bozor
	cmd/bozor/main.go:5:2: use of internal package golang.org/x/text/internal/number not allowed
```

The first line says in which package the error is. The second: `use of internal package … not allowed`; `main.go:5:2` is the import line of
`number`. There is no message about an unused import: Go first checks all the imports, and compiles after that. The error appeared at
this first stage and never reached compilation.

The rule: a package whose path has an `internal` folder can be imported only by code inside the **parent folder** of `internal`
([go command: Internal Directories](https://pkg.go.dev/cmd/go#hdr-Internal_Directories)).

| Package | Who can import it |
|---|---|
| `golang.org/x/text/internal/number` | only packages inside `golang.org/x/text/…`, for example `message` |
| `github.com/abdurahmon27/bozor/internal/store` | only code inside `github.com/abdurahmon27/bozor/…`: `cmd/bozor` |
| both | another module — no: `use of internal package … not allowed` |

That is why the authors can change the inside of `internal` at any time: other modules cannot depend on it, so a change does not
break them. Our `store` is the same: nobody except the bozor module can import it.

## Common mistakes

**1. A lowercase name is not "hidden".** It cannot be seen from another package, but it is open to **all** files of the same folder. And the package name
does not have to equal the folder name: it is only a custom (see the `store.go` table above).

**2. `add` instead of `Add`.** In Go `Add` and `add` are two different names. The second call in `main` is written with a lowercase `a`
(`_video/03-kichik-harf/cmd/bozor/main.go`, line 12: `st.add("non", 400_000, 100)`):

```console
$ ./_video/run.sh 03-kichik-harf go run ./cmd/bozor
# github.com/abdurahmon27/bozor/cmd/bozor
cmd/bozor/main.go:12:5: st.add undefined (type store.Store has no field or method add, but does have method Add)
```

The compiler again says `undefined`, but at the end it gives a hint: `Store` has no lowercase `add` (`has no field or method add`), but it has a method
with a capital letter, `Add` (`but does have method Add`). The fix: a capital letter in the call, `st.Add(…)`.

**3. Calling your own lowercase function from outside.** Then the message has no hint, only `undefined`. An example (it is not in the
course folder; I ran it in a separate folder, `go.mod` is the same `module github.com/abdurahmon27/bozor` and `go 1.27`).
`internal/store/store.go`:

```go
package store

func newID() int64 {
	return 1
}
```

`cmd/bozor/main.go`:

```go
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	fmt.Println(store.newID())
}
```

```console
$ go run ./cmd/bozor
# github.com/abdurahmon27/bozor/cmd/bozor
cmd/bozor/main.go:10:20: undefined: store.newID
```

`undefined: store.newID` — "`store.newID` is not defined". Column 20 is the start of the word `newID`. The fix: give the function a capital letter
(`NewID`) and it becomes exported. Do this only if it must be called from another package; otherwise keep it lowercase.

**4. `go run .` in the root.** After the program moved to `cmd/bozor`, the root has no Go files: `no Go files in …`. The command is
`go run ./cmd/bozor` (the "Package" section above).

**5. `List` returns the inner slice.** This is a silent bug: the program runs, the result is wrong. We saw it above in the section
"The hole in the boundary"; the fix is to make `List` return a copy (the homework).

**6. Not adding `go.sum` to git.** After adding an external module, commit `go.sum` together with `go.mod`: otherwise the hash check does not
work on another computer. This rule comes from the documentation of the `go.sum` file ([Go Modules Reference](https://go.dev/ref/mod#go-sum-files));
I did not run this situation on the page.

```go filename="solution/internal/store/store.go" showLineNumbers
// Package store bozor katalogini xotirada saqlaydi.
// U internal/ ichida: uni faqat bozor modulining oʻz kodi import qila oladi.
package store

import (
	"fmt"
	"slices"
)

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// Store — xotiradagi katalog. Nol qiymati tayyor: var st store.Store.
// products kichik harf bilan: paketdan tashqaridagi kod unga yoza olmaydi.
type Store struct {
	products []Product
}

// Add katalogga mahsulot qoʻshadi va unga ID beradi (1, 2, 3 …).
func (s *Store) Add(name string, price int64, stock int) Product {
	p := Product{ID: int64(len(s.products)) + 1, Name: name, Price: price, Stock: stock}
	s.products = append(s.products, p)
	return p
}

// List katalogdagi mahsulotlarning nusxasini qaytaradi: natijaga yozish
// katalogni oʻzgartirmaydi.
func (s *Store) List() []Product {
	return slices.Clone(s.products)
}

// Sell id'li mahsulotdan quantity dona sotadi va qoldiqni kamaytiradi.
// quantity musbat boʻlishi, mahsulot katalogda boʻlishi va qoldiq yetishi kerak;
// aks holda error qaytadi va qoldiq oʻzgarmaydi.
func (s *Store) Sell(id int64, quantity int) error {
	if quantity <= 0 {
		return fmt.Errorf("dona soni musbat boʻlishi kerak, hozir %d", quantity)
	}
	for i := range s.products {
		if s.products[i].ID == id {
			if s.products[i].Stock < quantity {
				return fmt.Errorf("%s: qoldiq %d, soʻralgan %d", s.products[i].Name, s.products[i].Stock, quantity)
			}
			s.products[i].Stock -= quantity
			return nil
		}
	}
	return fmt.Errorf("mahsulot %d topilmadi", id)
}
```

- `Sell`: first `quantity <= 0` is checked. Then `for i := range s.products` searches by index, and `s.products[i]` is the catalog element **itself**,
  not a copy; so `s.products[i].Stock -= quantity` changes the catalog. If the stock is not enough, an `error` is returned **before** the decrease: on an error
  the stock does not change. If the loop ends and the product was not found — the last `error`.
- `List`: `slices.Clone` returns a copy with a new array, and `st.List()[0].Stock = -5` now writes into the copy.
