## Что вы узнаете

Код bozor («рынок») пока лежит в одном файле `main.go`: переменная `st` — каталог, его метод `Add` и срез `products` внутри. `main`
пишет прямо в этот срез и опускает остаток яблок (`olma`) до минус пяти. Компилятор молчит:

```go
func main() {
	var st Store
	st.Add("olma", 1_200_000, 40)
	st.products[0].Stock = -5
	fmt.Println(st.products[0].Stock)
}
```

```console
$ ./_video/run.sh 00-birfayl go run .
-5
```

Правило каталога («остаток не бывает отрицательным») должно быть записано в методах `Store`. Но `products` открыт для всех,
поэтому любая строка кода обходит правило. Если разделить код на пакеты, компилятор сам закроет этот путь. Как именно, и какая
дыра останется?

**Одна идея:** пакет в Go — это файлы одной папки, а путь импорта — это имя модуля плюс папка. Через границу пакета проходят
только имена с заглавной буквы, а папка `internal/` ограничивает круг тех, кто может импортировать пакет, самим модулем. Эта
граница делает правило необходимым для всех.

К концу урока вы:

- разделите один `main.go` на пакеты `cmd/bozor` (программа) и `internal/store` (каталог) и запустите их через `go run ./cmd/bozor`;
- прочитаете ошибку `unexported` и обратитесь к имени из другого пакета с заглавной буквы;
- добавите внешний модуль через `go mod tidy` и будете знать, что проверяет `go.sum`;
- прочитаете ошибку `internal/` и скажете, кому эта папка разрешает импорт.

Три основных новых слова сегодня:

| Слово | Простое значение | По-английски |
|---|---|---|
| пакет | набор Go-файлов одной папки; каждый файл начинается со строки `package`, и во всех файлах одной папки в ней написано одно и то же имя | package |
| экспортируемое имя | имя с заглавной буквы: оно видно другим пакетам. Имя со строчной буквы видно только в своём пакете | exported / unexported |
| папка `internal/` | пакет внутри неё могут импортировать только те, кто лежит под родительской папкой `internal` | internal directory |

Два вспомогательных понятия: **путь импорта** (полное имя пакета) и **внешний модуль** вместе с файлом `go.sum`.

## Проблема: правило каталога записано не в одном месте

Программа из начала урока (`_video/00-birfayl/main.go`): каталог bozor и `main` — всё в одном файле.

```go filename="_video/00-birfayl/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// Store — xotiradagi katalog.
type Store struct {
	products []Product
}

// Add katalogga mahsulot qoʻshadi va unga ID beradi.
func (s *Store) Add(name string, price int64, stock int) Product {
	p := Product{ID: int64(len(s.products)) + 1, Name: name, Price: price, Stock: stock}
	s.products = append(s.products, p)
	return p
}

// List katalogdagi mahsulotlarni qaytaradi.
func (s *Store) List() []Product {
	return s.products
}

func main() {
	var st Store
	st.Add("olma", 1_200_000, 40)
	st.products[0].Stock = -5
	fmt.Println(st.products[0].Stock)
}
```

Строки 5–11 — тип `Product` из GB-2.03. Новые строки:

| Строка | Код | Что делает |
|---|---|---|
| 14–16 | `type Store struct { products []Product }` | `Store` — тип каталога. У него одно поле: `products`, срез `Product` |
| 19 | `func (s *Store) Add(name string, price int64, stock int) Product {` | `Add` — метод `Store`. Receiver — указатель: `*Store`, потому что метод меняет каталог (GB-2.05). Результат — добавленный `Product` |
| 20 | `p := Product{ID: int64(len(s.products)) + 1, …}` | `ID` нового товара — длина среза плюс один: 1, 2, 3. Остальные поля — из параметров |
| 21 | `s.products = append(s.products, p)` | добавляет товар в срез; результат `append` нужно снова записать в `s.products` (GB-2.01) |
| 22 | `return p` | возвращает **копию** добавленного товара |
| 26–28 | `func (s *Store) List() []Product { return s.products }` | новый метод: возвращает товары каталога |
| 31 | `var st Store` | пустой каталог: `products` — nil-срез. `append` работает и с nil-срезом, поэтому `Add` работает сразу |
| 32 | `st.Add("olma", 1_200_000, 40)` | яблоки (цена 1 200 000 тийинов, остаток 40) — первый товар каталога, `ID` 1 |
| 33 | `st.products[0].Stock = -5` | `main` пишет прямо во внутренний срез каталога: остаток первого товара −5 |
| 34 | `fmt.Println(st.products[0].Stock)` | выводит этот остаток |

Компилятор молчит: в одном файле `main` и `Store` видят все имена друг друга. Сколько бы вы ни записали правило остатка в `Add` и
следующие методы, строка 33 их обходит.

| Шаг | `st.products[0].Stock` | На экране |
|---|---|---|
| `st.Add("olma", …, 40)` (строка 32) | 40 | |
| `st.products[0].Stock = -5` (строка 33) | **−5** | |
| `fmt.Println(…)` (строка 34) | −5 | `-5` |

## Пакет: файлы одной папки

**Пакет** (package) в Go — это Go-файлы одной папки. Первая строка кода каждого файла — `package` и имя пакета; все файлы одной
папки пишут одно и то же имя. Это правило есть в спецификации Go: файлы с одним и тем же именем пакета образуют реализацию этого пакета
([Go spec: Package clause](https://go.dev/ref/spec#Package_clause)).

Есть два вида пакетов:

- `package main` — запускаемая программа. Её запускают `go run` и `go build` (GB-1.01).
- любое другое имя (`store`, `fmt`) — пакет, который импортирует другой код. `fmt` — тоже такой пакет: его файлы лежат в папке `fmt`
  стандартной библиотеки Go.

Делим bozor так:

```text
bozor/
├── go.mod
├── cmd/
│   └── bozor/
│       └── main.go        package main
└── internal/
    └── store/
        └── store.go       package store
```

- `cmd/bozor/main.go` — программа (`package main`). В `cmd/` каждая программа лежит в своей папке; в 4-м модуле курса рядом с
  bozor появится вторая программа.
- `internal/store/store.go` — каталог, имя пакета `store`. Что значит слово `internal`, объясним в конце урока.
- `go.mod` — в корне, с именем модуля (GB-1.01).

Создаём папки. Сейчас в текущей папке лежат `go.mod` и `main.go`:

```console
$ mkdir -p cmd/bozor internal/store
$ mv main.go cmd/bozor/
```

Обе команды ничего не печатают. `mkdir -p` создаёт оба пути сразу: `-p` создаёт и промежуточные папки (`cmd`, `internal`) и не
выдаёт ошибку, если папка уже есть. `mv main.go cmd/bozor/` переносит `main.go` в `cmd/bozor`. Затем переносим `Product`, `Store` и их
методы в новый файл `store.go`.

`internal/store/store.go`:

```go filename="_video/01-paket/internal/store/store.go" showLineNumbers
package store

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// Store — xotiradagi katalog.
type Store struct {
	products []Product
}

// Add katalogga mahsulot qoʻshadi va unga ID beradi.
func (s *Store) Add(name string, price int64, stock int) Product {
	p := Product{ID: int64(len(s.products)) + 1, Name: name, Price: price, Stock: stock}
	s.products = append(s.products, p)
	return p
}

// List katalogdagi mahsulotlarni qaytaradi.
func (s *Store) List() []Product {
	return s.products
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `package store` | файл входит в пакет `store`. Имя пакета совпадает с именем папки: компилятор этого не требует, но в Go так принято ([Effective Go: Package names](https://go.dev/doc/effective_go#package-names)) |
| 3–9, 12–14, 17–21 | `Product`, `Store`, `Add` | тела такие же, как в 00-birfayl, не изменились |
| 24–26 | `func (s *Store) List() []Product` | `List` не новый: он был и в 00-birfayl. Он возвращает товары каталога |

Теперь `cmd/bozor/main.go`. В его `import` добавляется вторая строка:

```go filename="_video/01-paket/cmd/bozor/main.go" showLineNumbers
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)
	for _, p := range st.List() {
		fmt.Println(p.ID, p.Name, p.Price)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–7 | `import ( … )` | импортирует два пакета (GB-1.07). Стандартный пакет (`fmt`) — в отдельной группе, наш — в другой: пустая строка между ними для этого |
| 6 | `"github.com/abdurahmon27/bozor/internal/store"` | **путь импорта** пакета `store` |
| 10 | `var st store.Store` | к имени из другого пакета обращаются через имя пакета и точку: `store.Store`, как `fmt.Println`. `st` — пустой каталог |
| 11–12 | `st.Add(…)` | добавляют два товара: яблоки (ID 1) и хлеб (`non`, ID 2) |
| 13–15 | `for _, p := range st.List() { … }` | перебирает товары, которые вернул `List` (GB-1.06), и печатает `ID`, `Name`, `Price` каждого |

**Путь импорта** состоит из двух частей: имя модуля из `go.mod` и папка внутри модуля. Имя модуля мы записали в первом уроке через
`go mod init`:

```console

```

| Часть | Значение | Откуда |
|---|---|---|
| имя модуля | `github.com/abdurahmon27/bozor` | строка `module` в `go.mod` |
| папка внутри модуля | `internal/store` | дерево файлов |
| путь импорта | `github.com/abdurahmon27/bozor/internal/store` | обе части соединяются через `/` ([Go Modules Reference](https://go.dev/ref/mod#modules-overview)) |

## Заглавная буква: что видно за пределами пакета

Теперь строка из начала урока. `main` пишет в остаток яблок прямо минус пять. В одном файле это работало; теперь `products` лежит
в другом пакете (`_video/02-eksport/cmd/bozor/main.go`):

```go filename="_video/02-eksport/cmd/bozor/main.go" showLineNumbers
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)
	st.products[0].Stock = -5
	for _, p := range st.List() {
		fmt.Println(p.ID, p.Name, p.Price)
	}
}
```

Что сделает `go run ./cmd/bozor`?

**A)** запустится, остаток −5 · **B)** ошибка компиляции · **C)** программа запустится и упадёт с panic

<details>
<summary>Ответ</summary>

**B.** Если вы выбрали **A**, вы опирались на результат из одного файла: там `main` и `Store` были в одном пакете. **C** — panic
возникает, когда программа **работает**, а это находит компиляция: программа вообще не запустится.

</details>

```console
$ ./_video/run.sh 02-eksport go run ./cmd/bozor
# github.com/abdurahmon27/bozor/cmd/bozor
cmd/bozor/main.go:13:5: st.products undefined (cannot refer to unexported field products)
```

Читаем сообщение строка за строкой:

- `# github.com/abdurahmon27/bozor/cmd/bozor` — при компиляции какого пакета возникла ошибка: `cmd/bozor`.
- `cmd/bozor/main.go:13:5` — файл, строка, столбец (GB-1.01): строка 13, столбец 5, то есть начало слова `products`.
- `st.products undefined` — «`st.products` не определено»: компилятор не видит имени `products` у `st`.
- `(cannot refer to unexported field products)` — причина: «нельзя обратиться к неэкспортируемому (**unexported**) полю». `products` лежит
  в другом пакете и не экспортируется.

Правило Go одно. Если имя начинается с **заглавной буквы**, оно **экспортируется** (**exported**): видно другим пакетам. Если со
строчной — видно только в своём пакете, во всех файлах этой папки. Точнее, первый символ должен быть заглавной буквой Unicode
([Go spec: Exported identifiers](https://go.dev/ref/spec#Exported_identifiers)).

Правило одинаково действует для типов, функций, констант и переменных уровня пакета, а также для полей и методов:

| Имя | Первая буква | Другому пакету |
|---|---|---|
| `Store`, `Product`, `Add`, `List` | заглавная | видно |
| `Product.Stock`, `Product.Name` | заглавная | видно |
| `fmt.Println` | заглавная `P` | видно: поэтому в первом уроке `P` заглавная |
| `products` | строчная | только внутри пакета `store` |

На рисунке: `main` видит только имена `store` с заглавной буквы.

```text
 cmd/bozor (package main)          internal/store (package store)
┌──────────────────────┐          ┌───────────────────────────────┐
│ st.Add(…)            │ ───────► │ Store, Product, Add, List     │ экспортируется
│ st.List()            │ ───────► │                               │
│ st.products     ✗    │ ─ ─ ╳    │ products                      │ только внутри store
└──────────────────────┘          └───────────────────────────────┘
```

Теперь каталог меняется только через методы `store`: правило остатка записано в одном месте — внутри `store`. Именно для этого на
практике нужна граница пакета.

Вопрос. В `main` написали `p := st.Add("choy", 3_000_000, 10)` («choy» — «чай»). Есть две строки: `st.products = nil` и `p.Stock = 0`. Какая
из них компилируется без ошибки? Программа (её нет в папке курса; я запускал её в отдельной папке):

```go

	p.Stock = 0

```

**A)** `st.products = nil` · **B)** `p.Stock = 0` · **C)** обе с ошибкой

<details>
<summary>Ответ</summary>

**B.** `Stock` с заглавной буквы: это экспортируемое поле. `products` со строчной: закрыто.

**не меняет**: `Add` вернул копию товара, копию структуры мы разбирали в GB-2.03. Если вы выбрали **A**, вы забыли, что `st.products`

### Дыра в границе

Но в нашей границе осталась одна дыра. `List` возвращает внутренний срез. `main` записывает минус пять в первый элемент результата, затем
снова вызывает `List` и печатает остаток яблок. `products` здесь не написан (`_video/06-teshik/cmd/bozor/main.go`):

```go filename="_video/06-teshik/cmd/bozor/main.go" showLineNumbers

	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"

	st.Add("non", 400_000, 100)
	st.List()[0].Stock = -5
	fmt.Println(st.List()[0].Stock)

```

Что выведется?

**A)** `40` · **B)** `-5` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `-5`.** Если вы выбрали **C**, вы решили, что строка 13 пишет в `products`: его здесь нет, есть результат `List()`, а компилятор
проверяет только то, открыто ли имя. Если выбрали **A**, вы решили, что `List` возвращает копию.

</details>


Компилятор молчит, потому что запись пошла не в `products`, а в результат `List`. Из GB-2.01 вы знаете: при возврате среза копируется
только заголовок (длина и указатель на массив), а сам массив общий. `List` отдал наружу внутренний массив `store`.

| Шаг | массив внутри `store`, яблоки | срез от `List()`, яблоки |
|---|---|---|
| `st.Add("olma", …, 40)` | 40 | |
| `st.List()` | 40 | **указывает на тот же массив**: 40 |
| `st.List()[0].Stock = -5` | **−5** | −5 |
| `st.List()[0].Stock` (повторный вызов) | −5 | −5, на экране `-5` |

Эту дыру вы закроете в задании, заставив `List` вернуть копию (ниже, «Домашнее задание»).

## Внешний модуль: цена в сумах, с разделением разрядов

Теперь выведем цены в сумах, с разделением разрядов: «12 000», с пробелом посередине. `fmt` не разделяет разряды. Это делает модуль
`golang.org/x/text` команды Go: он вне стандартной библиотеки, но входит в проект Go
([Go wiki: X-Repositories](https://go.dev/wiki/X-Repositories), [x/text](https://pkg.go.dev/golang.org/x/text)). Берём из него два пакета:
`language` даёт языковой тег, `message` создаёт принтер, настроенный на язык. `_video/04-modul/cmd/bozor/main.go`:

```go filename="_video/04-modul/cmd/bozor/main.go" showLineNumbers
package main

import (
	"github.com/abdurahmon27/bozor/internal/store"
	"golang.org/x/text/language"
	"golang.org/x/text/message"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

	printer := message.NewPrinter(language.Uzbek)
	for _, p := range st.List() {
		printer.Printf("%d. %s: %d soʻm\n", p.ID, p.Name, p.Price/tiyinPerSom)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–7 | `import ( … )` | `fmt` убран: он больше не используется. `golang.org/x/text/language` и `…/message` — два внешних пакета |
| 9 | `const tiyinPerSom = 100` | 1 сум = 100 тийинов (GB-1.03) |
| 16 | `printer := message.NewPrinter(language.Uzbek)` | `language.Uzbek` — тег узбекского языка; `message.NewPrinter` возвращает принтер, который выводит по правилам этого языка. Кладём его в переменную `printer` |
| 18 | `printer.Printf("%d. %s: %d soʻm\n", …)` | формат-строка как у `fmt.Printf` (GB-1.04), но числа разделяются по правилам языка |
| 18 | `p.Price/tiyinPerSom` | цена в тийинах; разделив на `tiyinPerSom`, получаем сумы |

Модуль ещё не загружен. Что скажет `go run ./cmd/bozor`?

<details>
<summary>Ответ</summary>

**B.** Если вы выбрали **A**, вы решили, что Go сам найдёт и скачает пакет: `go run` не добавляет в `go.mod` модуль, которого там нет.

</details>

## internal/: кто может импортировать пакет

Внутри модуля `x/text` есть пакет `internal/number`; `message` форматирует числа через него. Попробуем импортировать его напрямую
(`_video/05-internal/cmd/bozor/main.go`):

```go filename="_video/05-internal/cmd/bozor/main.go" showLineNumbers

	"github.com/abdurahmon27/bozor/internal/store"

	"golang.org/x/text/language"
	"golang.org/x/text/message"

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 100)

		printer.Printf("%d. %s: %d soʻm\n", p.ID, p.Name, p.Price/tiyinPerSom)
	}
}
```

Пакет существует, модуль загружен; новая строка — только строка 5 (`number`). Скомпилируется ли? Что скажет `go run ./cmd/bozor`?

**A)** работает · **B)** ошибка: использовать internal-пакет нельзя · **C)** ошибка: `number` не используется

<details>
<summary>Ответ</summary>

**B.** Если вы выбрали **A**, вы решили, что существующий пакет можно импортировать. **C** — из GB-1.01 вы знаете, что неиспользуемый
импорт — ошибка; но здесь до этого сообщения дело не доходит (причина ниже).

</details>

```console
$ ./_video/run.sh 05-internal go run ./cmd/bozor
package github.com/abdurahmon27/bozor/cmd/bozor
	cmd/bozor/main.go:5:2: use of internal package golang.org/x/text/internal/number not allowed
```

Первая строка говорит, в каком пакете ошибка. Вторая: `use of internal package … not allowed` — «использование internal-пакета … не
разрешено»; `main.go:5:2` — строка импорта `number`. Сообщения о неиспользуемом импорте нет: Go сначала проверяет все импорты, и лишь
потом компилирует. Ошибка возникла на этом первом этапе и до компиляции не дошла.

Правило: пакет, в чьём пути есть папка `internal`, могут импортировать только те, кто лежит внутри **родительской папки** `internal`
([команда go: Internal Directories](https://pkg.go.dev/cmd/go#hdr-Internal_Directories)).

| Пакет | Кто может импортировать |
|---|---|
| `golang.org/x/text/internal/number` | только пакеты внутри `golang.org/x/text/…`, например `message` |
| `github.com/abdurahmon27/bozor/internal/store` | только код внутри `github.com/abdurahmon27/bozor/…`: `cmd/bozor` |
| оба | другой модуль — нет: `use of internal package … not allowed` |

Поэтому авторы могут менять содержимое `internal` когда угодно: другие модули не могут к нему привязаться, значит изменение их не
сломает. Наш `store` устроен так же: кроме модуля bozor, его не импортирует никто.

## Частые ошибки

**1. Имя со строчной буквы не «скрыто».** Его не видно из другого пакета, но оно открыто для **всех** файлов этой же папки. И имя пакета
не обязано совпадать с именем папки: это только обычай (см. таблицу про `store.go` выше).

**2. `add` вместо `Add`.** В Go `Add` и `add` — два разных имени. Второй вызов в `main` написан со строчной `a`
(`_video/03-kichik-harf/cmd/bozor/main.go`, строка 12: `st.add("non", 400_000, 100)`):

```console
$ ./_video/run.sh 03-kichik-harf go run ./cmd/bozor
# github.com/abdurahmon27/bozor/cmd/bozor
cmd/bozor/main.go:12:5: st.add undefined (type store.Store has no field or method add, but does have method Add)
```

Компилятор снова говорит `undefined`, но в конце даёт подсказку: у `Store` нет строчного `add` (`has no field or method add`), зато есть метод
с заглавной буквой `Add` (`but does have method Add`). Исправление: заглавная буква в вызове, `st.Add(…)`.

**3. Вызов снаружи своей функции, написанной со строчной буквы.** Тогда сообщение без подсказки, только `undefined`. Пример (его нет в
папке курса; я запускал его в отдельной папке, `go.mod` — тот же `module github.com/abdurahmon27/bozor` и `go 1.27`).
`internal/store/store.go`:

```go
package store

func newID() int64 {
	return 1
}
```

`cmd/bozor/main.go`:

```go
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	fmt.Println(store.newID())
}
```

```console
$ go run ./cmd/bozor
# github.com/abdurahmon27/bozor/cmd/bozor
cmd/bozor/main.go:10:20: undefined: store.newID
```

`undefined: store.newID` — «`store.newID` не определено». Столбец 20 — начало слова `newID`. Исправление: дайте функции заглавную
букву (`NewID`), и она станет экспортируемой. Делайте так, только если её нужно вызывать из другого пакета; иначе оставьте строчную.

**4. `go run .` в корне.** Когда программа переехала в `cmd/bozor`, в корне нет Go-файлов: `no Go files in …`. Команда —
`go run ./cmd/bozor` (раздел «Пакет» выше).

**5. `List` возвращает внутренний срез.** Это тихая ошибка: программа работает, результат неверный. Мы разобрали её выше в разделе
«Дыра в границе»; исправление — пусть `List` возвращает копию (задание).

**6. Не добавить `go.sum` в git.** После добавления внешнего модуля коммитьте `go.sum` вместе с `go.mod`: иначе на другом компьютере
проверка хешей не сработает. Это правило взято из документации о файле `go.sum` ([Go Modules Reference](https://go.dev/ref/mod#go-sum-files));
эту ситуацию я на странице не запускал.

**B: `0 10`.** `p` — копия, которую вернул `Add`; запись в неё каталога не касается, остаток чая в каталоге остаётся 10. `Stock` экспортируется,
поэтому не **C**. Если вы выбрали **A**, вы решили, что `p` и товар в каталоге — одно значение.

```console
$ go run ./cmd/bozor
0 10
```

</details>

## Домашнее задание

Задание лежит в файле [`TASK.md`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-2-06-paketlar/TASK.md) папки курса;
папка: [lessons/gb-2-06-paketlar](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/gb-2-06-paketlar). Две задачи, обе в
`internal/store/store.go`:

- 🟡 **`Sell(id int64, quantity int) error`.** Сейчас он ничего не делает и всегда возвращает `nil`. Запишите правило: если `quantity`
  не положительно (0 или отрицательно), если товара с таким `id` нет в каталоге или остаток меньше `quantity` — `error`; иначе `Stock`
  этого товара уменьшается на `quantity` и возвращается `nil`. При ошибке ни один остаток не должен меняться. Например, хлеб
  (ID 2, остаток 100): `Sell(2, 3)` → `nil`, остаток 97; яблоки (ID 1, остаток 40): `Sell(1, 41)` → `error`, остаток 40.
- 🟢 **`List() []Product`.** Сейчас он возвращает сам `s.products`: это дыра, которую вы видели выше. Пусть `List` возвращает **копию**:
  запись в результат не должна влиять на каталог.

Не меняйте `Product`, поля `Store` и `Add`. Значки уровня (🟢🟡) в папке курса отсутствуют: их поставил я. Подсказки есть в `TASK.md`:
ищите товар по индексу (`for i := range s.products`): в `for _, p := range s.products` переменная `p` — копия элемента, и
`p.Stock -= quantity` каталог не изменит. Для ошибки — `fmt.Errorf` (GB-1.07). Для копии — `slices.Clone(s.products)` или `make` с `copy`.

<summary>Ответ и объяснение</summary>

Ответ — [`solution/internal/store/store.go`](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-2-06-paketlar/solution/internal/store/store.go):

```go filename="solution/internal/store/store.go" showLineNumbers
// Package store bozor katalogini xotirada saqlaydi.
// U internal/ ichida: uni faqat bozor modulining oʻz kodi import qila oladi.
package store

import (
	"fmt"
	"slices"
)

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// Store — xotiradagi katalog. Nol qiymati tayyor: var st store.Store.
// products kichik harf bilan: paketdan tashqaridagi kod unga yoza olmaydi.
type Store struct {
	products []Product
}

// Add katalogga mahsulot qoʻshadi va unga ID beradi (1, 2, 3 …).
func (s *Store) Add(name string, price int64, stock int) Product {
	p := Product{ID: int64(len(s.products)) + 1, Name: name, Price: price, Stock: stock}
	s.products = append(s.products, p)
	return p
}

// List katalogdagi mahsulotlarning nusxasini qaytaradi: natijaga yozish
// katalogni oʻzgartirmaydi.
func (s *Store) List() []Product {
	return slices.Clone(s.products)
}

// Sell id'li mahsulotdan quantity dona sotadi va qoldiqni kamaytiradi.
// quantity musbat boʻlishi, mahsulot katalogda boʻlishi va qoldiq yetishi kerak;
// aks holda error qaytadi va qoldiq oʻzgarmaydi.
func (s *Store) Sell(id int64, quantity int) error {
	if quantity <= 0 {
		return fmt.Errorf("dona soni musbat boʻlishi kerak, hozir %d", quantity)
	}
	for i := range s.products {
		if s.products[i].ID == id {
			if s.products[i].Stock < quantity {
				return fmt.Errorf("%s: qoldiq %d, soʻralgan %d", s.products[i].Name, s.products[i].Stock, quantity)
			}
			s.products[i].Stock -= quantity
			return nil
		}
	}
	return fmt.Errorf("mahsulot %d topilmadi", id)
}
```

- `Sell`: сначала проверяется `quantity <= 0`. Затем `for i := range s.products` ищет по индексу, а `s.products[i]` — **сам** элемент каталога,
  не копия; поэтому `s.products[i].Stock -= quantity` меняет каталог. Если остатка не хватает, `error` возвращается **до** уменьшения: при ошибке
  остаток не меняется. Если цикл закончился и товар не найден — последний `error`.
- `List`: `slices.Clone` возвращает копию с новым массивом, и `st.List()[0].Stock = -5` теперь пишет в копию.
