## What you will learn

The `printReport` function prints the bozor catalog report to the screen with `Printf`. Now the same report is needed in a file,
and in a test as text in memory. How do you avoid writing three functions for the screen, the file and the test?

**The one idea:** an interface is a type made of a list of methods. Any type that has all the methods of the list implements the interface
**without any declaration**: the compiler compares the methods itself. An interface value holds a concrete type and a value of that type,
and the call `w.Write(p)` goes to the `Write` method of exactly that concrete type. This is why one `writeReport(w io.Writer, …)` can write to
the screen, to a file and to a buffer in memory.

By the end of the lesson you will:

- read the signatures of `io.Writer` and `fmt.Stringer` from the standard library with `go doc`;
- write the report with one function, `writeReport(w io.Writer, …)`, to `os.Stdout`, to a file opened by `os.Create`, and to your own `*byteCounter`;
- read the error "method Write has pointer receiver" and fix it with `&c`;
- write `String()` for `Product`, see how `fmt` finds it, and test `writeReport` without a file using `strings.Builder`.

Today's three core new words:

| Word | Plain meaning | English term |
|---|---|---|
| interface | a type made of a list of methods: name, parameters and results are written, there is no body; no fields | interface |
| implementing an interface | if the methods of a type include every method of the list, the type implements the interface; you declare this nowhere | implementing an interface (implicitly) |
| small interface | an interface with one or two methods (`io.Writer`, `fmt.Stringer`); the smaller it is, the more types implement it | small interface |

Two helper ideas: `go doc` (a command that shows standard library documentation in the terminal) and type assertion with `any` (in the last
part, inside `fmt`). `os.Create`, `Close`, `fmt.Fprintf` and `strings.Builder` are not new concepts: each one is named in one sentence.

## The problem: one report, three places

The report function prints one line for each product in the catalog (this code is the starting point of the video, it is not in the course folder):

```go
func printReport(products []Product) {
	for _, p := range products {
		fmt.Printf("%-6s %6d soʻm %4d dona\n", p.Name, p.Price/tiyinPerSom, p.Stock)
	}
}
```

The line template is from GB-1.04: `%-6s` is the name, left-aligned, width 6; `%6d` is the price in som (`p.Price/tiyinPerSom`, GB-1.03), width 6; `%4d` is the stock,
width 4; `\n` is the end of the line. `printReport` sends the result only to the screen: `Printf` always writes to the screen.

Now the report is needed in two more places: in a file, and as text in memory in a test. If you copy the function and replace `Printf`, one loop lives in three places:
when you change the format, you change all three. Ask a different question: what do the screen, a file and text in memory have in common? Bytes are written to each of
them. So "where to write" must become a parameter of the function.

## Reading a signature with go doc

In lesson 7 we wrote the error to the standard error stream with `fmt.Fprintln(os.Stderr, …)`: the first argument says where to write. What is the type of this
argument? The answer is in the standard library documentation. The `go doc` command shows this documentation in the terminal: `go doc fmt.Fprintln` is about
`Fprintln` in package `fmt`:

```console
$ go doc fmt.Fprintln
package fmt // import "fmt"

func Fprintln(w io.Writer, a ...any) (n int, err error)
    Fprintln formats using the default formats for its operands and writes to w.
    Spaces are always added between operands and a newline is appended.
    It returns the number of bytes written and any write error encountered.
```

The video keeps only the signature line from the documentation; here is the full output of `go doc`. The first line is the package name and its import path
(a comment after `//`). The signature line:

| Part | Meaning |
|---|---|
| `w io.Writer` | the first parameter: the name is `w`, the type is `Writer` from package `io`. The next command opens `Writer` |
| `a ...any` | the second parameter `a`: any number of values of any type (we open `any` in this lesson) |
| `(n int, err error)` | two results, and they even have names: `n` is the number of bytes written, `err` is the error. The names are for the documentation |

The last sentence of the documentation says the same: the function returns the number of bytes written and the write error.

## Interface: a type made of a list of methods

Now `io.Writer` itself:

```console
$ go doc io.Writer
package io // import "io"

type Writer interface {
	Write(p []byte) (n int, err error)
}
    Writer is the interface that wraps the basic Write method.

    Write writes len(p) bytes from p to the underlying data stream. It returns
    the number of bytes written from p (0 <= n <= len(p)) and any error
    encountered that caused the write to stop early. Write must return a non-nil
    error if it returns n < len(p). Write must not modify the slice data,
    even temporarily.

    Implementations must not retain p.

var Discard Writer = discard{}
func MultiWriter(writers ...Writer) Writer
```

The first line: `type Writer interface`. An **interface** is also a type, but it has no fields, only a **list of methods**: for each method a name, parameters
and results, **with no body**. `Writer` has one method, `Write`. It takes a slice of bytes `p` (`[]byte`, GB-2.01). A `byte` is a number from 0 to 255; text in memory is
a sequence of such bytes. The results are the same as in `Fprintln`: the number of bytes written `n` and the error `err`.

The documentation text gives the contract of this method: `Write` must write all `len(p)` bytes of `p`; if it cannot, it returns `n < len(p)` and a non-`nil` error;
it does not modify `p` and does not keep it. When we write our own `Write`, we will follow this rule. The last two lines (`Discard`, `MultiWriter`) are other names
in package `io`: we do not need them today.

## A type implements an interface without a declaration

Who has such a method? The `File` type in package `os` represents an open file:

```console
$ go doc os.File.Write
package os // import "os"

func (f *File) Write(b []byte) (n int, err error)
    Write writes len(b) bytes from b to the File. It returns the number of
    bytes written and an error, if any. Write returns a non-nil error when n !=
    len(b).
```

The receiver is `(f *File)`: there is an asterisk, so it is a pointer receiver (GB-2.05). The parameter name is different, `b` instead of `p`, but the name does not matter:
the types are the same.

| `io.Writer` requires | `*os.File` has | Match? |
|---|---|---|
| `Write(p []byte) (n int, err error)` | `Write(b []byte) (n int, err error)` | yes: the names differ, the types are the same |

**The rule:** if the methods of a type include every method in the interface's list, the type **implements** the interface. You declare this nowhere: there is no `implements`
keyword, the compiler compares the methods itself
([Go spec: Implementing an interface](https://go.dev/ref/spec#Implementing_an_interface)).

`os.Stdout` and `os.Stderr` are variables of type `*os.File`. That is why `fmt.Fprintln(os.Stderr, …)` from GB-1.07 worked: the first parameter is `io.Writer`, and
`*os.File` has such a `Write`.

## writeReport: writing to the screen

The report function is `writeReport`. The full text of the program (`_video/01-stdout/main.go`):

```go filename="_video/01-stdout/main.go" showLineNumbers
package main

import (
	"fmt"
	"io"
	"os"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// writeReport katalog hisobotini w'ga yozadi.
func writeReport(w io.Writer, products []Product) error {
	for _, p := range products {
		_, err := fmt.Fprintf(w, "%-6s %6d soʻm %4d dona\n", p.Name, p.Price/tiyinPerSom, p.Stock)
		if err != nil {
			return err
		}
	}
	return nil
}

func main() {
	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
		{ID: 3, Name: "oʻrik", Price: 3_500_000, Stock: 5},
	}

	err := writeReport(os.Stdout, products)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}
```

The Uzbek words in the code: `olma` is "apple", `non` is "bread", `oʻrik` is "apricot", `soʻm` is the Uzbek currency, `dona` is "pieces", `xato` is "error", `tiyin` is one hundredth of a som.

| Line | Code | What it does |
|---|---|---|
| 3–7 | `import ( … )` | packages `fmt`, `io` (it has `io.Writer`) and `os` (it has `os.Stdout`) |
| 9–17 | `tiyinPerSom`, `Product` | as in GB-1.03 and GB-2.03 |
| 20 | `func writeReport(w io.Writer, products []Product) error` | parameters: `w` has type `io.Writer`, that is "where to write"; `products` is the slice of products. The result is `error` |
| 21 | `for _, p := range products {` | the same loop as in `printReport`: `p` is the current product (`_` is the index, not needed) |
| 22 | `_, err := fmt.Fprintf(w, …)` | the same template as `Printf`, but the first argument is where to write. `Fprintf` also returns two results: we do not need the byte count, so we drop it with `_`; we keep `err` |
| 23–25 | `if err != nil { return err }` | if writing fails (for example the disk is full), we return the error to the caller |
| 27 | `return nil` | everything was written: no error |
| 31–35 | `products := []Product{ … }` | three products in `main`: `olma`, `non` and `oʻrik` (the price is in tiyin, `1_200_000` is from GB-1.03) |
| 37 | `err := writeReport(os.Stdout, products)` | we pass `os.Stdout` as `w`: the caller chooses where to write |
| 38–41 | `if err != nil { … }` | on error we write it to stderr and exit with code 1, as in GB-1.07 |

Inside `writeReport` you cannot see where the writing goes:

```text
main ──► writeReport(w, products) ──► Fprintf(w, …) ──► w.Write(bytes) ──► terminal
                  w = os.Stdout
```

```console
$ ./_video/run.sh 01-stdout go run .

non      4000 soʻm  100 dona
oʻrik   35000 soʻm    5 dona
```

Three lines, the columns are aligned (`%-6s`, `%6d`, `%4d`). So far the result is the same as with `Printf`.

## Our own Writer: byteCounter

Now we write an `io.Writer` ourselves: `byteCounter` counts the bytes written (from `_video/03-counter/main.go`):

```go
// byteCounter oʻziga yozilgan baytlarni sanaydi.
type byteCounter struct {
	n int
}

// Write p'dagi baytlar sonini n'ga qoʻshadi.
func (c *byteCounter) Write(p []byte) (int, error) {
	c.n += len(p)
	return len(p), nil
}
```

| Code | What it does |
|---|---|
| `type byteCounter struct { n int }` | a struct with one field: `n` is how many bytes have been written so far |
| `func (c *byteCounter) Write(p []byte) (int, error)` | the `Write` method. The receiver `c` is a pointer receiver, because `n` changes (GB-2.05). The signature is the same as in `io.Writer`: the parameter `p` is a slice of bytes, the results are `int` and `error` |
| `c.n += len(p)` | `len(p)` is how many bytes arrived (GB-2.01): we add it to `n` |
| `return len(p), nil` | we return "everything was written": `n == len(p)` and no error, the `io.Writer` contract |

Notice: the words `io.Writer` do not appear in this code. In `main`, after the file is closed:

```go
	var c byteCounter
	err = writeReport(&c, products)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println("hisobot:", c.n, "bayt")
```

`var c byteCounter` is an empty counter, `c.n` is zero (zero value, GB-1.02). We pass `&c` to `writeReport` (`&` is from GB-2.04: the address of `c`), because `Write`
belongs to `*byteCounter`. Then we print `n`. Does it compile?

**A)** yes, the number of bytes is printed · **B)** no: `byteCounter` did not declare that it implements `io.Writer` · **C)** yes, but `0`: `Write` writes to a copy

<details>
<summary>Answer</summary>

**A: the number of bytes is printed.** If you chose **B**, you thought a declaration is needed: the compiler saw `Write` on `*byteCounter`, and that is enough. **C**: `Write` has a pointer
receiver, so it writes to `c` itself, not to a copy (GB-2.05).

```console
$ ./_video/run.sh 03-counter sh -c 'go run . ; wc -c hisobot.txt ; wc -m hisobot.txt'
hisobot: 91 bayt
91 hisobot.txt
87 hisobot.txt
```

`wc -c` counts the bytes in the file: `hisobot.txt` also has 91 bytes, the same as the counter. `wc -m` counts characters (in a UTF-8 locale): 87. A byte is not a character:
the sign `ʻ` in `soʻm` takes two bytes in UTF-8 (`soʻm` is in three lines and `oʻrik` in one: 4 signs `ʻ`, 87 + 4 = 91). We open this in
[GB-2.10 · UTF-8: bayt, rune va oʻzbekcha matn](/lab/youtube/gb/gb-2-10/en).

</details>

## What is inside an interface value

`w io.Writer` in `writeReport` is an **interface value**. It has two parts: the **concrete type** inside and the **value** of that type. `Fprintf` calls `w.Write(…)`, and Go runs the
`Write` method of the type that is inside `w`
([Go blog: The Laws of Reflection](https://go.dev/blog/laws-of-reflection): an interface variable stores a pair of a value and its type).

| Call | Type inside `w` | Value inside `w` | What `w.Write(p)` does |
|---|---|---|---|
| `writeReport(os.Stdout, …)` | `*os.File` | `os.Stdout` | writes the bytes to the terminal |
| `writeReport(f, …)` | `*os.File` | `f` (`hisobot.txt`) | writes the bytes to the file |
| `writeReport(&c, …)` | `*byteCounter` | `&c` (the address of `c`) | `c.n += len(p)` |

`writeReport` does not have to know which type arrived: it relies only on `Write` being there.

## Pointer receiver and interface: why &c is needed

The most common mistake: `&` was forgotten and `c` itself was passed to `writeReport` (`_video/04-xato/main.go`, line 65):

```go
	var c byteCounter
	err = writeReport(c, products)
```

If we called the method directly, `c.Write(…)`, Go would add `&` itself (GB-2.05). What about here?

```console
$ ./_video/run.sh 04-xato go run .
# github.com/abdurahmon27/bozor
./main.go:65:20: cannot use c (variable of struct type byteCounter) as io.Writer value in argument to writeReport: byteCounter does not implement io.Writer (method Write has pointer receiver)
```

How to read the error:

| Part | Meaning |
|---|---|
| `./main.go:65:20` | file, line, column: the place where `c` is written |
| `cannot use c (variable of struct type byteCounter)` | `c`, a variable of struct type `byteCounter`, cannot be used |
| `as io.Writer value in argument to writeReport` | as an `io.Writer` value in the argument to `writeReport` |
| `byteCounter does not implement io.Writer` | `byteCounter` does not implement `io.Writer` |
| `(method Write has pointer receiver)` | the reason: `Write` has a pointer receiver, that is, it belongs to `*byteCounter`; the `byteCounter` value itself has no `Write` |

In a method call Go adds `&` itself; when passing to an interface it does not. The fix: `writeReport(&c, products)`.

A question. There is another type, `logWriter`, and its `Write` method has a **value** receiver. Which call compiles: with `l` or with `&l`?

**A)** only `l` · **B)** only `&l` · **C)** both

<details>
<summary>Answer</summary>

**C: both.** A method with a value receiver exists on the value and on the pointer: Go takes the copy through the pointer. The reverse does not work: a method with a pointer receiver exists
only on the pointer. If you chose **A**, you thought a pointer cannot be passed; **B**: you generalized the previous error, but it applies only to a pointer receiver. The full program
(it is not in the course folder):

```go
package main

import (
	"fmt"
	"io"
)

// logWriter — Write metodi value receiver'li tur.
type logWriter struct{}

func (l logWriter) Write(p []byte) (int, error) {
	fmt.Println("yozildi:", len(p), "bayt")
	return len(p), nil
}

func hello(w io.Writer) {
	fmt.Fprintln(w, "salom")
}

func main() {
	var l logWriter
	hello(l)
	hello(&l)
}
```

```console
$ go run .
yozildi: 6 bayt
yozildi: 6 bayt
```

Both calls worked (`salom\n` is 6 bytes). The rule as a table ([Go spec: Method sets](https://go.dev/ref/spec#Method_sets)):

| Receiver of the method | It is on a `T` value | It is on `*T` |
|---|---|---|
| `(l T)` — value | yes | yes |
| `(l *T)` — pointer | no | yes |

This is why `byteCounter` needed `&`.

</details>

## fmt.Stringer: a small interface

Besides `writeReport`, there is one more small interface. We add a direct print of the products at the end of `main`: `fmt.Println(products)`. `fmt` prints each struct as a
sequence of fields in curly braces; the price is in tiyin, which is hard to read:

```console
$ ./_video/run.sh 05-oldin go run .
hisobot: 91 bayt
[{1 olma 1200000 40} {2 non 400000 100} {3 oʻrik 3500000 5}]
```

Package `fmt` has an interface with one method:

```console
$ go doc fmt.Stringer
package fmt // import "fmt"

type Stringer interface {
	String() string
}
    Stringer is implemented by any value that has a String method, which defines
    the “native” format for that value. The String method is used to print
    values passed as an operand to any format that accepts a string or to an
    unformatted printer such as Print.
```

The method is `String`, with no parameters, and it returns a `string`. In GB-2.05 we wrote exactly such a method for `OrderStatus`, and `fmt` printed the status by name:
`OrderStatus` implemented `Stringer` without a declaration. Now we write `String` for `Product` (from `main.go`):

```go
// String mahsulotni «olma (12000 soʻm)» koʻrinishida qaytaradi.
func (p Product) String() string {
	return fmt.Sprintf("%s (%d soʻm)", p.Name, p.Price/tiyinPerSom)
}
```

The receiver is a value receiver `(p Product)`: the method only reads, and `Product` is small. `Sprintf` is from GB-1.04: a template like `Printf`, but it does not print to the screen, it returns the text;
here it is the name and the price in som in parentheses. `main` does not change: the same `fmt.Println(products)`. What is printed now?

**A)** unchanged: `String` does not work on the elements of a slice · **B)** the name and price of each product · **C)** compile error

<details>
<summary>Answer</summary>

**B.** `fmt` went through the slice, found `String` on each element and called it. If you chose **A**, you thought `fmt` looks only at the outer value; **C**: `Product` does not declare that it
implements `Stringer`, and the compiler does not need that.

```console
$ ./_video/run.sh final go run .
hisobot: 91 bayt
[olma (12000 soʻm) non (4000 soʻm) oʻrik (35000 soʻm)]
```

(`final` is the `main.go` in the folder.)

</details>

## How fmt finds String

The parameters of `Println` have type `any`. `any` is an **interface with no methods**: the list is empty, so any value fits. Inside, `fmt` asks each value, here `arg`, a question:
"are you a `fmt.Stringer`?". This question is a **type assertion**. The simplified form (this is not the real code):

```go
// arg — Println'ga berilgan qiymat, turi any
s, ok := arg.(fmt.Stringer)
if ok {
	// … s.String() natijasini yozadi
}
```

| Code | What it does |
|---|---|
| `arg.(fmt.Stringer)` | type assertion `x.(T)`: does the type inside `arg` implement `fmt.Stringer`? |
| `s, ok := …` | the comma-ok form from GB-2.02: `ok` is `true` or `false`; if `true`, `s` is the value as a `fmt.Stringer` |
| `if ok { … }` | if `ok` is `true`, `s.String()` is called and its result is written |

The real `fmt` checks several interfaces (`error`, `Stringer`, …) in one `switch`: in the Go 1.27.4 source, file `src/fmt/print.go`, function `handleMethods`, `case Stringer` comes
after `case error`. The mechanism is the same as in the code on screen: it asks whether the type inside the value implements the method. We run it ourselves (a program that is not in the course folder):

```go
package main

import "fmt"

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// String mahsulotni «olma (12000 soʻm)» koʻrinishida qaytaradi.
func (p Product) String() string {
	return fmt.Sprintf("%s (%d soʻm)", p.Name, p.Price/tiyinPerSom)
}

// describe arg fmt.Stringer'ni bajaradimi, shuni soʻraydi.
func describe(arg any) {
	s, ok := arg.(fmt.Stringer)
	if ok {
		fmt.Println("Stringer:", s.String())
	} else {
		fmt.Println("Stringer emas")
	}
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	describe(olma)
	describe(42)
	describe("non")
}
```

```console
$ go run .
Stringer: olma (12000 soʻm)
Stringer emas
Stringer emas
```

(`Stringer emas` means "not a Stringer".) For `describe(olma)`, `Product` has `String`, so `ok` is `true`. `42` (`int`) and `"non"` (`string`) have no `String`, so `ok` is `false`. The same query works
inside `fmt`.

## A small interface and a test without a file

`io.Writer` and `fmt.Stringer` each have one method. The smaller an interface is, the more types implement it:

| Interface | Types that implement it |
|---|---|
| `io.Writer` | `*os.File` (an open file and `os.Stdout`), `*byteCounter`, `*strings.Builder` (a text buffer in memory) |
| `fmt.Stringer` | `Product`, `OrderStatus` |

The type that writes an HTTP response also implements `io.Writer`: we see this in [GB-4.03 · Handler — oddiy funksiya: httptest bilan tekshiramiz](/lab/youtube/gb/gb-4-03/en).
So the rule is: **in a function parameter, ask only for the methods the function needs**. `writeReport` needs not a file but `Write` (a Go proverb: "the bigger the interface, the weaker the
abstraction", [Go Proverbs](https://go-proverbs.github.io/)).

At work the use of this rule shows in tests. `TestHisobot` in the folder's `tekshiruv_test.go` tests `writeReport` without a file (the function is copied from the file as it is;
`testProducts` is a helper in the same file that returns three products):

```go
func TestHisobot(t *testing.T) {
	products := testProducts()
	want := "olma    12000 soʻm   40 dona\n" +
		"non      4000 soʻm  100 dona\n" +
		"oʻrik   35000 soʻm    5 dona\n"

	var sb strings.Builder
	err := writeReport(&sb, products)
	if err != nil {
		t.Fatalf("writeReport xato qaytardi: %v", err)
	}
	got := sb.String()
	if got != want {
		t.Errorf("hisobot:\n%s\nkutilgan:\n%s", got, want)
	}
	if got := fmt.Sprint(testProducts()[0]); got != "olma (12000 soʻm)" {
		t.Errorf("fmt.Sprint(olma) = %q; kutilgan %q", got, "olma (12000 soʻm)")
	}
}
```

| Code | What it does |
|---|---|
| `want := "…" + "…" + "…"` | the expected text: three lines joined with `+` |
| `var sb strings.Builder` | `sb` is an empty text buffer; the type `*strings.Builder` has `Write` |
| `writeReport(&sb, products)` | the report is written to this buffer (`&sb`: `Write` has a pointer receiver) |
| `got := sb.String()` | `String` returns the collected text |
| `if got != want { … }` | the text is compared with the expected text; if they differ, `t.Errorf` (GB-1.08) |
| `fmt.Sprint(testProducts()[0])` | `Sprint` turns a value into text like `Println`, but returns the text; it checks that `Product.String` works |

No file, no disk. The flag `-run` selects a test by name, the flag `-v` shows each test:

```console
$ go test -run TestHisobot -v
=== RUN   TestHisobot
--- PASS: TestHisobot (0.00s)
PASS
ok  	github.com/abdurahmon27/bozor	0.002s
```

(The time `0.002s` is different each time.)

## Common mistakes

**1. A type with a pointer receiver, without `&`.** The most common one was shown above: `writeReport(c, products)` (the section "Pointer receiver and interface: why &c is needed"). The same error
appears with standard library types. The `Write` method of `strings.Builder` also has a pointer receiver (a full program, not in the course folder):

```go
package main

import (
	"fmt"
	"io"
	"strings"
)

func hello(w io.Writer) {
	fmt.Fprintln(w, "salom")
}

func main() {
	var sb strings.Builder
	hello(sb)
	fmt.Print(sb.String())
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:15:8: cannot use sb (variable of struct type strings.Builder) as io.Writer value in argument to hello: strings.Builder does not implement io.Writer (method Write has pointer receiver)
```

It reads the same way: `cannot use sb … as io.Writer`, and the reason is in parentheses: `method Write has pointer receiver`. The fix: `hello(&sb)`.

**2. `String` with a pointer receiver: `fmt` does not call it (a silent bug).** If you write `String` as `func (p *Product) String() string`, the code compiles, there is no error, but `fmt` prints the product
with its fields. A full program (not in the course folder; the body of `String` is as in the lesson):

```go
package main

import "fmt"

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// String bu yerda pointer receiver'li: bu xato.
func (p *Product) String() string {
	return fmt.Sprintf("%s (%d soʻm)", p.Name, p.Price/tiyinPerSom)
}

func main() {
	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	fmt.Println(products)
	fmt.Println(products[0])
	fmt.Println(&products[0])
}
```

```console
$ go run .
[{1 olma 1200000 40} {2 non 400000 100}]
{1 olma 1200000 40}
olma (12000 soʻm)
```

The reason is the method set: the elements of the slice are `Product` values, and the type `Product` has no `String` (it is only on `*Product`). `fmt` looks at the type inside the interface:
`Product` is not a `Stringer`, `*Product` is a `Stringer`. Neither the compiler nor `go vet` reports it. The fix: for a small type that does not change, write `String` with a value
receiver (`func (p Product) String() string`): it is on `Product` and on `*Product`.

**3. A parameter type that is concrete without need.** If you write `writeReport(f *os.File, …)`, the function can write only to a file. A full program (not in the course folder):

```go
package main

import (
	"fmt"
	"os"
	"strings"
)

// hello faqat *os.File qabul qiladi.
func hello(f *os.File) {
	fmt.Fprintln(f, "salom")
}

func main() {
	var sb strings.Builder
	hello(os.Stdout)
	hello(&sb)
	fmt.Print(sb.String())
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:17:8: cannot use &sb (value of type *strings.Builder) as *os.File value in argument to hello
```

`hello(os.Stdout)` works, `hello(&sb)` does not: `*strings.Builder` is not `*os.File`. The function needed only `Write`: make the parameter type `io.Writer`, and the test, `byteCounter` and the file
all fit.

## Check yourself

**1.** What must a type have to implement `io.Writer`? Where do you declare it?

<details>
<summary>Answer</summary>

It must have a method with exactly this signature: `Write(p []byte) (n int, err error)` (the names of parameters and results do not matter, the types must be the same).
You declare it nowhere: the compiler compares the methods itself.

</details>

**2.** If `Write` has a pointer receiver (`func (c *byteCounter) Write…`), do you pass `c` or `&c` to `writeReport`?

<details>
<summary>Answer</summary>

`&c`. `Write` is in the method set of `*byteCounter` and not in the method set of `byteCounter`; if you pass `c`, the compiler says
`method Write has pointer receiver`.

</details>

**3.** (GB-2.04) A function takes a copy of a `Product` and decreases `Stock`. Does the product change in the caller?

<details>
<summary>Answer</summary>

No. The function changes the copy, the original `Product` stays the same. To change it, you pass a `*Product`.

</details>

- 🟢 **Step 1: `writeLowStock` writes everything to `w`.** It writes one line for each product whose stock (`Stock`) is below `limit`, for example
  `oʻrik (35000 soʻm) — 5 dona qoldi`. Now it writes the lines not to `w` but straight to the screen. Make all lines go to `w`; if writing returns an error,
  `writeLowStock` returns that error at once, otherwise `nil`.
- 🟡 **Step 2: `lineCounter` is an `io.Writer`.** A type like `byteCounter`, but it counts **lines**, not bytes. Write its `Write` method: on each call the number of
  line ends (`'\n'`) in `p` is added to `lines`, and the result is `len(p)` and `nil`. After the report of three products is written, `lines` is 3.

Do not change `writeReport`, `Product` or `String`. In the starting state `go test` fails like this (the real output; the time differs each run; the top two lines are the starting
`writeLowStock` writing to the screen from inside the test):

<details>
<summary>The answer explained (try it yourself first)</summary>

**Step 1.** `fmt.Printf(…)` always writes to the screen; to write to `w` you need `fmt.Fprintf(w, …)`. `Fprintf` returns two results: we do not need the byte count (`_`), we check the error
and return it. `%v` in the template prints a `Product` through its `String` method (the `Stringer` of this lesson):

```go
func writeLowStock(w io.Writer, products []Product, limit int) error {
	for _, p := range products {
		if p.Stock < limit {
			_, err := fmt.Fprintf(w, "%v — %d dona qoldi\n", p, p.Stock)
			if err != nil {
				return err
			}
		}
	}
	return nil
}
```

**Step 2.** `bytes.Count(p, []byte("\n"))` returns how many times the byte `'\n'` is in `p` (`[]byte("\n")` turns the text into a slice of bytes; add `"bytes"` to
`import`). `Write` changes `lines`, so the receiver is a pointer (GB-2.05); `n == len(p)` and `nil` are the `io.Writer` contract:

```go
// lineCounter oʻziga yozilgan qatorlarni sanaydi.
type lineCounter struct {
	lines int
}

// Write p'dagi qator oxirlarini ('\n') sanab, lines'ga qoʻshadi.
func (c *lineCounter) Write(p []byte) (int, error) {
	c.lines += bytes.Count(p, []byte("\n"))
	return len(p), nil
}
```
