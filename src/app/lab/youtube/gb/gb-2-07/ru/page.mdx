## Что вы узнаете

Отчёт по каталогу bozor функция `printReport` выводит на экран через `Printf`. Теперь тот же отчёт нужен в файле, а в тесте — в тексте
в памяти. Как обойтись без трёх функций для экрана, файла и теста?

**Одна идея:** интерфейс — тип, который состоит из списка методов. Любой тип, у которого есть все методы списка, реализует интерфейс
**без объявления**: компилятор сам сопоставляет методы. Внутри значения интерфейса лежат конкретный тип и значение этого типа, а вызов
`w.Write(p)` идёт в метод `Write` именно этого конкретного типа. Поэтому одна `writeReport(w io.Writer, …)` пишет на экран, в файл и в буфер
в памяти.

К концу урока вы:

- прочитаете через `go doc` сигнатуры `io.Writer` и `fmt.Stringer` из стандартной библиотеки;
- запишете отчёт одной функцией `writeReport(w io.Writer, …)` в `os.Stdout`, в файл, открытый `os.Create`, и в написанный вами `*byteCounter`;
- прочитаете ошибку «method Write has pointer receiver» и исправите её через `&c`;
- напишете `String()` для `Product`, увидите, как `fmt` его находит, и проверите `writeReport` без файла через `strings.Builder`.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| интерфейс | тип из списка методов: записаны имя, параметры и результаты, тела нет; полей нет | interface |
| реализовать интерфейс | если методы типа включают все методы списка, тип реализует интерфейс; нигде это не объявляется | implementing an interface (implicitly) |
| маленький интерфейс | интерфейс из одного-двух методов (`io.Writer`, `fmt.Stringer`); чем он меньше, тем больше типов его реализует | small interface |

Два вспомогательных понятия: `go doc` (команда, которая показывает документацию стандартной библиотеки в терминале) и type assertion
с `any` (в последней части, внутри `fmt`). `os.Create`, `Close`, `fmt.Fprintf` и `strings.Builder` — не новые понятия: каждое названо одной
фразой.

## Проблема: один отчёт, три места

Функция отчёта выводит по одной строке на каждый товар каталога (это код из начала видео, его нет в папке курса):

```go
func printReport(products []Product) {
	for _, p := range products {
		fmt.Printf("%-6s %6d soʻm %4d dona\n", p.Name, p.Price/tiyinPerSom, p.Stock)
	}
}
```

Шаблон строки — из GB-1.04: `%-6s` — название, выравнивание по левому краю, ширина 6; `%6d` — цена в сумах (`p.Price/tiyinPerSom`, GB-1.03), ширина 6; `%4d` —
остаток, ширина 4; `\n` — конец строки. `printReport` выводит результат только на экран: `Printf` всегда пишет на экран.

Теперь отчёт нужен ещё в двух местах: в файле и в тексте в памяти (в тесте). Если скопировать функцию и заменить `Printf`, один цикл будет жить
в трёх местах: меняя формат, вы поменяете все три. Вопрос ставится иначе: что общего у экрана, файла и текста в памяти? В каждое из них
записываются байты. Значит, «куда писать» нужно передать в функцию параметром.

## Читаем сигнатуру через go doc

В седьмом уроке мы писали ошибку в стандартный поток ошибок через `fmt.Fprintln(os.Stderr, …)`: первый аргумент говорит, куда писать. Какого он типа?
Ответ — в документации стандартной библиотеки. Команда `go doc` показывает эту документацию в терминале: `go doc fmt.Fprintln` — про `Fprintln`
из пакета `fmt`:

```console
$ go doc fmt.Fprintln
package fmt // import "fmt"

func Fprintln(w io.Writer, a ...any) (n int, err error)
    Fprintln formats using the default formats for its operands and writes to w.
    Spaces are always added between operands and a newline is appended.
    It returns the number of bytes written and any write error encountered.
```

В видео из документации оставлена только строка сигнатуры; здесь — полный вывод `go doc`. Первая строка — имя пакета и его путь импорта (после `//`
комментарий). Строка сигнатуры:

| Часть | Смысл |
|---|---|
| `w io.Writer` | первый параметр: имя `w`, тип `Writer` из пакета `io`. `Writer` откроет следующая команда |
| `a ...any` | второй параметр `a`: любое количество значений любого типа (`any` мы разберём в этом уроке) |
| `(n int, err error)` | два результата, им даже даны имена: `n` — число записанных байт, `err` — ошибка. Имена нужны для документации |

Последнее предложение документации говорит то же: функция возвращает число записанных байт и ошибку записи.

## Интерфейс: тип из списка методов

Теперь сам `io.Writer`:

```console
$ go doc io.Writer
package io // import "io"

type Writer interface {
	Write(p []byte) (n int, err error)
}
    Writer is the interface that wraps the basic Write method.

    Write writes len(p) bytes from p to the underlying data stream. It returns
    the number of bytes written from p (0 <= n <= len(p)) and any error
    encountered that caused the write to stop early. Write must return a non-nil
    error if it returns n < len(p). Write must not modify the slice data,
    even temporarily.

    Implementations must not retain p.

var Discard Writer = discard{}
func MultiWriter(writers ...Writer) Writer
```

Первая строка: `type Writer interface`. **Интерфейс** (*interface*) — тоже тип, но полей в нём нет, только **список методов**: у каждого метода имя, параметры
и результаты, **без тела**. В `Writer` один метод — `Write`. Он принимает слайс байт `p` (`[]byte`, GB-2.01). `byte` — число от 0 до 255; текст в памяти
— это последовательность таких байт. Результаты те же, что у `Fprintln`: число записанных байт `n` и ошибка `err`.

Текст документации задаёт контракт метода: `Write` должен записать все `len(p)` байт из `p`; если не смог, он возвращает `n < len(p)` и ошибку, не равную
`nil`; `p` он не изменяет и не запоминает. Когда мы напишем свой `Write`, мы выполним это условие. Последние две строки (`Discard`, `MultiWriter`) — другие
имена пакета `io`: сегодня они не нужны.

## Тип реализует интерфейс без объявления

У кого есть такой метод? Тип `File` из пакета `os` представляет открытый файл:

```console
$ go doc os.File.Write
package os // import "os"

func (f *File) Write(b []byte) (n int, err error)
    Write writes len(b) bytes from b to the File. It returns the number of
    bytes written and an error, if any. Write returns a non-nil error when n !=
    len(b).
```

Receiver — `(f *File)`: есть звёздочка, значит это pointer receiver (GB-2.05). Имя параметра другое — `b`, а не `p` — но имя не важно: типы одинаковые.

| `io.Writer` требует | У `*os.File` есть | Подходит? |
|---|---|---|
| `Write(p []byte) (n int, err error)` | `Write(b []byte) (n int, err error)` | да: имена разные, типы одинаковые |

**Правило:** если методы типа включают все методы из списка интерфейса, этот тип **реализует** интерфейс (*implements*). Нигде это не объявляется:
слова `implements` нет, компилятор сам сопоставляет методы
([Go spec: Implementing an interface](https://go.dev/ref/spec#Implementing_an_interface)).

`os.Stdout` и `os.Stderr` — переменные типа `*os.File`. Поэтому в GB-1.07 `fmt.Fprintln(os.Stderr, …)` и работал: первый параметр — `io.Writer`, а
у `*os.File` есть такой `Write`.

## writeReport: пишем на экран

Функция отчёта — `writeReport`. Полный текст программы (`_video/01-stdout/main.go`):

```go filename="_video/01-stdout/main.go" showLineNumbers
package main

import (
	"fmt"
	"io"
	"os"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// writeReport katalog hisobotini w'ga yozadi.
func writeReport(w io.Writer, products []Product) error {
	for _, p := range products {
		_, err := fmt.Fprintf(w, "%-6s %6d soʻm %4d dona\n", p.Name, p.Price/tiyinPerSom, p.Stock)
		if err != nil {
			return err
		}
	}
	return nil
}

func main() {
	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
		{ID: 3, Name: "oʻrik", Price: 3_500_000, Stock: 5},
	}

	err := writeReport(os.Stdout, products)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}
```

Узбекские слова в коде: `olma` — «яблоко», `non` — «хлеб», `oʻrik` — «абрикос», `soʻm` — узбекский сум, `dona` — «штук», `xato` — «ошибка», `tiyin` — одна сотая сума.

| Строка | Код | Что делает |
|---|---|---|
| 3–7 | `import ( … )` | пакеты `fmt`, `io` (в нём `io.Writer`) и `os` (в нём `os.Stdout`) |
| 9–17 | `tiyinPerSom`, `Product` | как в GB-1.03 и GB-2.03 |
| 20 | `func writeReport(w io.Writer, products []Product) error` | параметры: `w` — тип `io.Writer`, то есть «куда писать»; `products` — слайс товаров. Результат — `error` |
| 21 | `for _, p := range products {` | тот же цикл, что в `printReport`: `p` — очередной товар (`_` — индекс, он не нужен) |
| 22 | `_, err := fmt.Fprintf(w, …)` | тот же шаблон, что у `Printf`, но первый аргумент — куда писать. `Fprintf` тоже возвращает два результата: число байт не нужно, отбрасываем его через `_`; `err` сохраняем |
| 23–25 | `if err != nil { return err }` | если запись вернула ошибку (например, диск заполнен), возвращаем её вызывающему коду |
| 27 | `return nil` | всё записано — ошибки нет |
| 31–35 | `products := []Product{ … }` | три товара в `main`: `olma`, `non` и `oʻrik` (цена в тийинах, `1_200_000` — GB-1.03) |
| 37 | `err := writeReport(os.Stdout, products)` | вместо `w` передаём `os.Stdout`: место записи выбирает вызывающий код |
| 38–41 | `if err != nil { … }` | при ошибке пишем её в stderr и выходим с кодом 1, как в GB-1.07 |

Внутри `writeReport` не видно, куда именно идёт запись:

```text
main ──► writeReport(w, products) ──► Fprintf(w, …) ──► w.Write(байты) ──► терминал
                  w = os.Stdout
```

```console
$ ./_video/run.sh 01-stdout go run .
olma    12000 soʻm   40 dona
non      4000 soʻm  100 dona
oʻrik   35000 soʻm    5 dona
```

Три строки, колонки ровные (`%-6s`, `%6d`, `%4d`). Пока результат такой же, как у `Printf`.

## Та же функция пишет в файл

Меняем `main`: теперь не на экран, а в файл. Изменился только `main` (`products` те же; полный файл — `_video/02-fayl/main.go`):

```go
	f, err := os.Create("hisobot.txt")
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	err = writeReport(f, products)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	err = f.Close()
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
```

| Код | Что делает |
|---|---|
| `f, err := os.Create("hisobot.txt")` | создаёт файл `hisobot.txt` (если он есть, очищает его) и возвращает открытый файл `f` — тип `*os.File` — и `error` |
| `err = writeReport(f, products)` | теперь в `writeReport` передаём `f`. `err` второй раз — не через `:=`, а через обычное `=`: переменная уже есть |
| `err = f.Close()` | `Close` закрывает файл, то есть сообщает операционной системе, что работа закончена |
| три `if err != nil { … }` | проверяется ошибка каждого действия: создание, запись, закрытие |

`f` — это `*os.File`, у него есть `Write`, поэтому `writeReport(f, …)` компилируется. Что `go run .` выведет в терминал?

**A)** три строки отчёта · **B)** ничего · **C)** ошибка компиляции: `f` не `io.Writer`

<details>
<summary>Ответ</summary>

**B: терминал пуст.** Отчёт попал в файл. Если вы выбрали **A**, вы решили, что вывод идёт на экран, как у `Printf`: теперь `Fprintf` пишет в `f`, а экран
не затронут. Если выбрали **C**, вы решили, что `io.Writer` нужно объявлять: у `*os.File` есть `Write`, этого достаточно.

`cat hisobot.txt` выводит содержимое файла в терминал. Чтобы обе команды выполнились в одной папке, я передал `run.sh` команду `sh -c '…'`

В `writeReport` не изменилось ни одной буквы: место записи выбрал вызывающий код.

## Свой Writer: byteCounter

Теперь напишем `io.Writer` сами: `byteCounter` считает записанные байты (из `_video/03-counter/main.go`):

```go
// byteCounter oʻziga yozilgan baytlarni sanaydi.
type byteCounter struct {
	n int
}

// Write p'dagi baytlar sonini n'ga qoʻshadi.
func (c *byteCounter) Write(p []byte) (int, error) {
	c.n += len(p)
	return len(p), nil
}
```

| Код | Что делает |
|---|---|
| `type byteCounter struct { n int }` | структура с одним полем: `n` — сколько байт записано к этому моменту |
| `func (c *byteCounter) Write(p []byte) (int, error)` | метод `Write`. Receiver `c` — pointer receiver, потому что `n` меняется (GB-2.05). Сигнатура как у `io.Writer`: параметр `p` — слайс байт, результаты — `int` и `error` |
| `c.n += len(p)` | `len(p)` — сколько байт пришло (GB-2.01): прибавляем к `n` |
| `return len(p), nil` | возвращаем «всё записано»: `n == len(p)` и нет ошибки — контракт `io.Writer` |

Обратите внимание: в этом коде нет слова `io.Writer`. В `main`, после закрытия файла:

```go
	var c byteCounter
	err = writeReport(&c, products)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
	fmt.Println("hisobot:", c.n, "bayt")
```

`var c byteCounter` — пустой счётчик, `c.n` равно нулю (zero value, GB-1.02). В `writeReport` передаём `&c` (`&` — GB-2.04: адрес `c`),
потому что `Write` определён у `*byteCounter`. Потом выводим `n`. Скомпилируется ли?

**A)** да, выведется число байт · **B)** нет: `byteCounter` не объявил, что реализует `io.Writer` · **C)** да, но `0`: `Write` пишет в копию

<details>
<summary>Ответ</summary>

**A: выведется число байт.** Если вы выбрали **B**, вы решили, что объявление нужно: компилятор увидел `Write` у `*byteCounter`, этого достаточно. **C** —
`Write` с pointer receiver пишет в сам `c`, а не в копию (GB-2.05).

```console
$ ./_video/run.sh 03-counter sh -c 'go run . ; wc -c hisobot.txt ; wc -m hisobot.txt'
hisobot: 91 bayt
91 hisobot.txt
87 hisobot.txt
```

`wc -c` считает байты в файле: в `hisobot.txt` тоже 91 байт, как у счётчика. `wc -m` считает символы (в локали UTF-8): 87. Байт — не символ:
знак `ʻ` из `soʻm` занимает в UTF-8 два байта (`soʻm` в трёх строках и `oʻrik` в одной: 4 знака `ʻ`, 87 + 4 = 91). Это мы разберём в
[GB-2.10 · UTF-8: bayt, rune va oʻzbekcha matn](/lab/youtube/gb/gb-2-10/ru).

</details>

## Что лежит внутри значения интерфейса

`w io.Writer` в `writeReport` — **значение интерфейса** (*interface value*). Оно состоит из двух частей: **конкретного типа** внутри и **значения** этого типа.
`Fprintf` вызывает `w.Write(…)`, а Go запускает метод `Write` того типа, который лежит внутри `w`
([Go blog: The Laws of Reflection](https://go.dev/blog/laws-of-reflection) — переменная интерфейса хранит пару из значения и его типа).

| Вызов | Тип внутри `w` | Значение внутри `w` | Что делает `w.Write(p)` |
|---|---|---|---|
| `writeReport(os.Stdout, …)` | `*os.File` | `os.Stdout` | пишет байты в терминал |
| `writeReport(f, …)` | `*os.File` | `f` (`hisobot.txt`) | пишет байты в файл |
| `writeReport(&c, …)` | `*byteCounter` | `&c` (адрес `c`) | `c.n += len(p)` |

`writeReport` не обязана знать, какой тип пришёл: она опирается только на наличие `Write`.

## Pointer receiver и интерфейс: зачем нужен &c

Самая частая ошибка: забыли `&`, в `writeReport` передали сам `c` (`_video/04-xato/main.go`, строка 65):

```go
	var c byteCounter
	err = writeReport(c, products)
```

Если вызвать метод напрямую, `c.Write(…)`, Go подставил бы `&` сам (GB-2.05). А здесь?

```console
$ ./_video/run.sh 04-xato go run .
# github.com/abdurahmon27/bozor
./main.go:65:20: cannot use c (variable of struct type byteCounter) as io.Writer value in argument to writeReport: byteCounter does not implement io.Writer (method Write has pointer receiver)
```

Как читать ошибку:

| Часть | Смысл |
|---|---|
| `./main.go:65:20` | файл, строка, столбец: место, где написано `c` |
| `cannot use c (variable of struct type byteCounter)` | `c` — переменная типа-структуры `byteCounter` — использовать нельзя |
| `as io.Writer value in argument to writeReport` | как значение `io.Writer` в аргументе `writeReport` |
| `byteCounter does not implement io.Writer` | `byteCounter` не реализует `io.Writer` |
| `(method Write has pointer receiver)` | причина: у `Write` pointer receiver, то есть он принадлежит `*byteCounter`; у самого значения `byteCounter` метода `Write` нет |

При вызове метода Go подставляет `&` сам, а при передаче в интерфейс — нет. Исправление: `writeReport(&c, products)`.

Вопрос. Есть другой тип, `logWriter`, и его метод `Write` — с **value** receiver. Какой вызов скомпилируется: с `l` или с `&l`?

**A)** только `l` · **B)** только `&l` · **C)** оба

<details>
<summary>Ответ</summary>

**C: оба.** Метод с value receiver есть и у значения, и у указателя: Go берёт копию через указатель. Наоборот не работает: метод с pointer receiver есть
только у указателя. Если вы выбрали **A**, вы решили, что указатель передать нельзя; **B** — вы обобщили прошлую ошибку, а она касается только pointer
receiver. Полная программа (её нет в папке курса):

```go
package main

import (
	"fmt"
	"io"
)

// logWriter — Write metodi value receiver'li tur.
type logWriter struct{}

func (l logWriter) Write(p []byte) (int, error) {
	fmt.Println("yozildi:", len(p), "bayt")
	return len(p), nil
}

func hello(w io.Writer) {
	fmt.Fprintln(w, "salom")
}

func main() {
	var l logWriter
	hello(l)
	hello(&l)
}
```

```console
$ go run .
yozildi: 6 bayt
yozildi: 6 bayt
```

Оба вызова сработали (`salom\n` — 6 байт). Правило в таблице ([Go spec: Method sets](https://go.dev/ref/spec#Method_sets)):

| Receiver метода | Есть у значения `T` | Есть у `*T` |
|---|---|---|
| `(l T)` — value | да | да |
| `(l *T)` — pointer | нет | да |

Поэтому для `byteCounter` нужен был `&`.

</details>

## fmt.Stringer: маленький интерфейс

Кроме `writeReport`, есть ещё один маленький интерфейс. Добавим в конец `main` прямой вывод товаров: `fmt.Println(products)`. `fmt` выводит каждую структуру как
последовательность полей в фигурных скобках; цена в тийинах, читать неудобно:

```console
$ ./_video/run.sh 05-oldin go run .
hisobot: 91 bayt
[{1 olma 1200000 40} {2 non 400000 100} {3 oʻrik 3500000 5}]
```

В пакете `fmt` есть интерфейс из одного метода:

```console
$ go doc fmt.Stringer
package fmt // import "fmt"

type Stringer interface {
	String() string
}
    Stringer is implemented by any value that has a String method, which defines
    the “native” format for that value. The String method is used to print
    values passed as an operand to any format that accepts a string or to an
    unformatted printer such as Print.
```

Метод — `String`, без параметров, возвращает `string`. В GB-2.05 мы написали точно такой метод для `OrderStatus`, и `fmt` выводил состояние по имени:
`OrderStatus` реализовал `Stringer` без объявления. Теперь напишем `String` для `Product` (из `main.go`):

```go
// String mahsulotni «olma (12000 soʻm)» koʻrinishida qaytaradi.
func (p Product) String() string {
	return fmt.Sprintf("%s (%d soʻm)", p.Name, p.Price/tiyinPerSom)
}
```

Receiver — value receiver `(p Product)`: метод только читает, а `Product` небольшой. `Sprintf` — из GB-1.04: шаблон как у `Printf`, но результат не
выводится на экран, а возвращается как текст; здесь это название и цена в сумах в скобках. `main` не меняется: тот же `fmt.Println(products)`. Что выведется теперь?

**A)** не изменится: `String` не действует на элементы слайса · **B)** название и цена каждого товара · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B.** `fmt` обошёл слайс, на каждом элементе нашёл `String` и вызвал его. Если вы выбрали **A**, вы решили, что `fmt` смотрит только на внешнее значение; **C** —
`Product` не объявляет, что реализует `Stringer`, компилятору это не нужно.

```console
$ ./_video/run.sh final go run .
hisobot: 91 bayt
[olma (12000 soʻm) non (4000 soʻm) oʻrik (35000 soʻm)]
```

(`final` — это `main.go` из папки.)

</details>

## Как fmt находит String

Параметры `Println` имеют тип `any`. `any` — **интерфейс без методов**: список пуст, поэтому ему подходит любое значение. Внутри `fmt` задаёт каждому значению, здесь
`arg`, вопрос: «ты `fmt.Stringer`?». Этот вопрос — **type assertion**. Упрощённый вид (это не настоящий код):

```go
// arg — Println'ga berilgan qiymat, turi any
s, ok := arg.(fmt.Stringer)
if ok {
	// … s.String() natijasini yozadi
}
```

| Код | Что делает |
|---|---|
| `arg.(fmt.Stringer)` | type assertion `x.(T)`: реализует ли тип внутри `arg` интерфейс `fmt.Stringer`? |
| `s, ok := …` | форма comma-ok из GB-2.02: `ok` — `true` или `false`; если `true`, `s` — это значение как `fmt.Stringer` |
| `if ok { … }` | если `ok` равно `true`, вызывается `s.String()` и его результат записывается |

Настоящий `fmt` проверяет несколько интерфейсов (`error`, `Stringer`, …) в одном `switch`: в исходниках Go 1.27.4, в файле `src/fmt/print.go`, в функции
`handleMethods` после `case error` идёт `case Stringer`. Механизм тот же, что в коде на экране: спрашивается, реализует ли тип внутри значения метод.
Запустим его сами (программы нет в папке курса):

```go
package main

import "fmt"

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// String mahsulotni «olma (12000 soʻm)» koʻrinishida qaytaradi.
func (p Product) String() string {
	return fmt.Sprintf("%s (%d soʻm)", p.Name, p.Price/tiyinPerSom)
}

// describe arg fmt.Stringer'ni bajaradimi, shuni soʻraydi.
func describe(arg any) {
	s, ok := arg.(fmt.Stringer)
	if ok {
		fmt.Println("Stringer:", s.String())
	} else {
		fmt.Println("Stringer emas")
	}
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	describe(olma)
	describe(42)
	describe("non")
}
```

```console
$ go run .
Stringer: olma (12000 soʻm)
Stringer emas
Stringer emas
```

(`Stringer emas` — «не Stringer».) У `describe(olma)` в `Product` есть `String`, `ok` равно `true`. У `42` (`int`) и `"non"` (`string`) `String` нет, `ok` равно `false`. Этот же запрос работает и
внутри `fmt`.

## Маленький интерфейс и тест без файла

И у `io.Writer`, и у `fmt.Stringer` по одному методу. Чем меньше интерфейс, тем больше типов его реализует:

| Интерфейс | Типы, которые его реализуют |
|---|---|
| `io.Writer` | `*os.File` (открытый файл и `os.Stdout`), `*byteCounter`, `*strings.Builder` (текстовый буфер в памяти) |
| `fmt.Stringer` | `Product`, `OrderStatus` |

Тип, который пишет HTTP-ответ, тоже реализует `io.Writer`: это мы увидим в [GB-4.03 · Handler — oddiy funksiya: httptest bilan tekshiramiz](/lab/youtube/gb#gb-4-03).
Отсюда правило: **в параметре функции запрашивайте только те методы, которые ей нужны**. `writeReport` нужен не файл, а `Write` (пословица Go: «чем больше интерфейс, тем слабее
абстракция», [Go Proverbs](https://go-proverbs.github.io/)).

В работе польза этого правила видна в тесте. `TestHisobot` в `tekshiruv_test.go` из папки проверяет `writeReport` без файла (функция скопирована из файла как есть;
`testProducts` — вспомогательная функция того же файла, возвращает три товара):

```go
func TestHisobot(t *testing.T) {
	products := testProducts()
	want := "olma    12000 soʻm   40 dona\n" +
		"non      4000 soʻm  100 dona\n" +
		"oʻrik   35000 soʻm    5 dona\n"

	var sb strings.Builder
	err := writeReport(&sb, products)
	if err != nil {
		t.Fatalf("writeReport xato qaytardi: %v", err)
	}
	got := sb.String()
	if got != want {
		t.Errorf("hisobot:\n%s\nkutilgan:\n%s", got, want)
	}
	if got := fmt.Sprint(testProducts()[0]); got != "olma (12000 soʻm)" {
		t.Errorf("fmt.Sprint(olma) = %q; kutilgan %q", got, "olma (12000 soʻm)")
	}
}
```

| Код | Что делает |
|---|---|
| `want := "…" + "…" + "…"` | ожидаемый текст: три строки, соединённые через `+` |
| `var sb strings.Builder` | `sb` — пустой текстовый буфер; у типа `*strings.Builder` есть `Write` |
| `writeReport(&sb, products)` | отчёт записывается в этот буфер (`&sb`: у `Write` pointer receiver) |
| `got := sb.String()` | `String` возвращает накопленный текст |
| `if got != want { … }` | текст сравнивается с ожидаемым; при расхождении — `t.Errorf` (GB-1.08) |
| `fmt.Sprint(testProducts()[0])` | `Sprint` превращает значение в текст, как `Println`, но возвращает его; проверяет, что `Product.String` работает |

Ни файла, ни диска. Ключ `-run` выбирает тест по имени, ключ `-v` показывает каждый тест:

```console
$ go test -run TestHisobot -v
=== RUN   TestHisobot
--- PASS: TestHisobot (0.00s)
PASS
ok  	github.com/abdurahmon27/bozor	0.002s
```

(Время `0.002s` каждый раз разное.)

## Частые ошибки

**1. Тип с pointer receiver, без `&`.** Самая частая показана выше: `writeReport(c, products)` (раздел «Pointer receiver и интерфейс: зачем нужен &c»). Та же ошибка
возникает и с типами стандартной библиотеки. У `strings.Builder` метод `Write` тоже с pointer receiver (полная программа, её нет в папке курса):

```go
package main

import (
	"fmt"
	"io"
	"strings"
)

func hello(w io.Writer) {
	fmt.Fprintln(w, "salom")
}

func main() {
	var sb strings.Builder
	hello(sb)
	fmt.Print(sb.String())
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:15:8: cannot use sb (variable of struct type strings.Builder) as io.Writer value in argument to hello: strings.Builder does not implement io.Writer (method Write has pointer receiver)
```

Читается так же: `cannot use sb … as io.Writer`, причина в скобках — `method Write has pointer receiver`. Исправление: `hello(&sb)`.

**2. `String` с pointer receiver — `fmt` его не вызывает (тихая ошибка).** Если написать `String` как `func (p *Product) String() string`, код скомпилируется, ошибки нет, но `fmt` выведет
товар вместе с полями. Полная программа (её нет в папке курса; тело `String` как в уроке):

```go
package main

import "fmt"

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// String bu yerda pointer receiver'li: bu xato.
func (p *Product) String() string {
	return fmt.Sprintf("%s (%d soʻm)", p.Name, p.Price/tiyinPerSom)
}

func main() {
	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	fmt.Println(products)
	fmt.Println(products[0])
	fmt.Println(&products[0])
}
```

```console
$ go run .
[{1 olma 1200000 40} {2 non 400000 100}]
{1 olma 1200000 40}
olma (12000 soʻm)
```

Причина — method set: элементы слайса — значения `Product`, а у типа `Product` метода `String` нет (он есть только у `*Product`). `fmt` смотрит на тип внутри интерфейса:
`Product` — не `Stringer`, `*Product` — `Stringer`. Ни компилятор, ни `go vet` не сообщают об этом. Исправление: для небольшого неизменяемого типа пишите `String` с value
receiver (`func (p Product) String() string`): он есть и у `Product`, и у `*Product`.

**3. Тип параметра без нужды конкретный.** Если написать `writeReport(f *os.File, …)`, функция сможет писать только в файл. Полная программа (её нет в папке курса):

```go
package main

import (
	"fmt"
	"os"
	"strings"
)

// hello faqat *os.File qabul qiladi.
func hello(f *os.File) {
	fmt.Fprintln(f, "salom")
}

func main() {
	var sb strings.Builder
	hello(os.Stdout)
	hello(&sb)
	fmt.Print(sb.String())
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:17:8: cannot use &sb (value of type *strings.Builder) as *os.File value in argument to hello
```

`hello(os.Stdout)` работает, `hello(&sb)` — нет: `*strings.Builder` — не `*os.File`. Функции нужен был только `Write`: сделайте тип параметра `io.Writer`, и подойдут
и тест, и `byteCounter`, и файл.

**1.** Что должно быть у типа, чтобы он реализовал `io.Writer`? Где вы это объявляете?

У него должен быть метод ровно с такой сигнатурой: `Write(p []byte) (n int, err error)` (имена параметров и результатов не важны, типы должны совпадать).

<details>

`&c`. `Write` входит в method set `*byteCounter`, но не входит в method set `byteCounter`; если передать `c`, компилятор скажет

</details>

<summary>Разбор ответа (сначала попробуйте сами)</summary>

**Шаг 1.** `fmt.Printf(…)` всегда пишет на экран; чтобы писать в `w`, нужен `fmt.Fprintf(w, …)`. `Fprintf` возвращает два результата: число байт не нужно (`_`), ошибку
проверяем и возвращаем. `%v` в шаблоне выводит `Product` через его метод `String` (`Stringer` из этого урока):

```go
func writeLowStock(w io.Writer, products []Product, limit int) error {
	for _, p := range products {
		if p.Stock < limit {
			_, err := fmt.Fprintf(w, "%v — %d dona qoldi\n", p, p.Stock)
			if err != nil {
				return err
			}
		}
	}
	return nil
}
```

**Шаг 2.** `bytes.Count(p, []byte("\n"))` возвращает, сколько раз байт `'\n'` встречается в `p` (`[]byte("\n")` превращает текст в слайс байт; добавьте `"bytes"`
в `import`). `Write` меняет `lines`, поэтому receiver — указатель (GB-2.05); `n == len(p)` и `nil` — контракт `io.Writer`:

```go
// lineCounter oʻziga yozilgan qatorlarni sanaydi.
type lineCounter struct {
	lines int
}

// Write p'dagi qator oxirlarini ('\n') sanab, lines'ga qoʻshadi.
func (c *lineCounter) Write(p []byte) (int, error) {
	c.lines += bytes.Count(p, []byte("\n"))
	return len(p), nil
}
```
