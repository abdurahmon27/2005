## Что вы узнаете

В bozor началась акция: каждая третья штука чая бесплатно. Покупатель берёт семь штук, значит, платить он должен за пять. Код же
сейчас считает `price * int64(sold)`, то есть умножает цену на семь. Как посчитать цену по штукам и пропустить бесплатную?

**Одна идея:** начало в заголовке `for` выполняется один раз, условие проверяется *перед* каждой итерацией, шаг выполняется
*после* каждой итерации. `continue` отбрасывает остаток этой итерации и переходит к шагу. `break` выходит из всего цикла.

К концу урока вы:

- пишете `for` из трёх частей и считаете в таблице памяти, сколько раз проверяется условие;
- пишете `for i := range sold`, `for range sold`, цикл только с условием и бесконечный `for`; читаете ошибки `undefined: i` и `declared and not used: i`;
- пишете правило «каждая третья штука бесплатно» через `continue` и `break`;
- знаете, что завершает `break` внутри `switch` в цикле.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| `for` из трёх частей | `for начало; условие; шаг { тело }`: блок внутри `{ }` повторяется со счётчиком | three-clause `for` loop |
| формы `for` | `range sold` (от 0 до `sold-1`), `for условие { }` только с условием, бесконечный `for { }` | `range`, condition-only and infinite `for` |
| `continue` и `break` | `continue`: остаток этой итерации пропускается; `break`: выход из всего цикла | `continue`, `break` |

Два вспомогательных слова: **`i++`** (*increment*) увеличивает `i` на единицу, то есть `i = i + 1`; **`+=`** — короткая запись:
`x += y` — это `x = x + y`. Общие слова: **цикл** (*loop*) — многократное выполнение блока; **итерация** (*iteration*) — одно
выполнение цикла; **счётчик** (*counter*) — переменная, которая считает итерации, обычно `i`; **тело** (*body*) — строки внутри `{ }`.

## Правило акции: семь штук, оплата за пять

Правило: **каждая третья штука бесплатно**. Штуки считаем с 1, поэтому бесплатны 3-я, 6-я, 9-я… Заказ из семи штук: 3-я и
6-я бесплатны, остальные пять платные:

| Штука | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| статус | платная | платная | **бесплатная** | платная | платная | **бесплатная** | платная |

Цена одной штуки чая — 1 999 сумов. К оплате: 5 × 1 999 = **9 995 сумов**. Сейчас же код умножает всё одной строкой:

```go
subtotal := price * int64(sold)
```

Это даёт 7 × 1 999 = 13 993 сума. Нужно смотреть на каждую штуку отдельно: если она бесплатная, цену не прибавлять. Чтобы
выполнить одно действие много раз, нужен **цикл** (*loop*). Для повторения в Go есть одно ключевое слово: `for`. Других
ключевых слов для циклов нет ([Go spec: Keywords](https://go.dev/ref/spec#Keywords)); [A Tour of Go](https://go.dev/tour/flowcontrol/1)
говорит то же: «Go has only one looping construct, the for loop». У него несколько форм, сегодня разберём все.

## `for` из трёх частей

Сначала на 3 штуках, без акции. Это `_video/01-sikl/main.go`:

```go filename="_video/01-sikl/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 3

	var subtotal int64
	for i := 1; i <= sold; i++ {
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `var price int64 = 199_900 // tiyinda` | цена чая: 1 999 сумов = 199 900 тийинов (GB-1.03) |
| 7 | `sold := 3` | количество штук в заказе |
| 9 | `var subtotal int64` | сумма: zero value, то есть `0` (GB-1.02) |
| 10 | `for i := 1; i <= sold; i++ {` | заголовок цикла: `for` и три части, разделённые **точкой с запятой** `;`; `{` открывает тело |
| 10 | `i := 1` | **начало** (*init*): один раз, в самом начале; `i` — счётчик, ему присваивается 1 |
| 10 | `i <= sold` | **условие** (*condition*): проверяется *перед* каждой итерацией; `true` — тело выполняется, `false` — цикл заканчивается |
| 10 | `i++` | **шаг** (*post*): выполняется *после* каждой итерации, увеличивает `i` на единицу |
| 11 | `subtotal += price` | тело: короткая запись `subtotal = subtotal + price`, то есть прибавляет цену к сумме |
| 12 | `}` | тело закончилось: программа возвращается к шагу |
| 13 | `fmt.Println(subtotal)` | после цикла печатает сумму |

Порядок ещё раз одной фразой: начало — один раз; затем повторяется: условие → тело → шаг → условие → тело → шаг…; как только
условие даёт `false`, цикл заканчивается, и программа продолжается со строки после `}`
([Go spec: For clause](https://go.dev/ref/spec#For_clause)).

Прежде чем запускать, подумайте: `sold` равно 3. Сколько раз проверяется условие и сколько раз выполняется тело?

**A)** 3 раза и 3 раза · **B)** 3 раза и 4 раза · **C)** 4 раза и 3 раза

<details>
<summary>Ответ</summary>

**C: условие 4 раза, тело 3 раза.** Условие проверяется *перед* телом, поэтому последняя проверка — та, что даёт `false`, —
остаётся без тела: на 3 итерации приходится 4 проверки. Если вы выбрали **A**, вы не посчитали последнюю проверку. В **B** тело
выполняется чаще, чем проверяется условие, а это невозможно: тело работает только после `true`.

</details>

Проследим в памяти. `sold` = 3, `subtotal` = 0, `price` = 199 900:

| Шаг | Строка | `i` | `subtotal` | Условие |
|---|---|---|---|---|
| начало `i := 1` | 10 | 1 | 0 | `1 <= 3` → `true` (1-я проверка) |
| тело | 11 | 1 | 199 900 | |
| шаг `i++` | 10 | 2 | 199 900 | `2 <= 3` → `true` (2-я проверка) |
| тело | 11 | 2 | 399 800 | |
| шаг `i++` | 10 | 3 | 399 800 | `3 <= 3` → `true` (3-я проверка) |
| тело | 11 | 3 | 599 700 | |
| шаг `i++` | 10 | 4 | 599 700 | `4 <= 3` → `false` (4-я проверка): **цикл закончился** |
| `Println` | 13 | — | 599 700 | на экран выводится `599700` |

Проверьте результат сами:

```console
$ ./_video/run.sh 01-sikl
599700
```

Три итерации — четыре проверки: если итераций *n*, условие проверяется *n + 1* раз. 599 700 тийинов — это 3 × 199 900.

## `i` живёт только внутри `for`

Когда цикл закончился, `i` был равен 4. В прошлом уроке `left`, объявленную в коротком `if`, нельзя было использовать после блока.
Теперь после цикла выведем вместе с `subtotal` и `i` (`_video/09-scope/main.go`, строка 11):

```go filename="_video/09-scope/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := 3
	var subtotal int64
	for i := 1; i <= sold; i++ {
		subtotal += 199_900
	}
	fmt.Println(subtotal, i)
}
```

Подумайте: что сделает эта программа?

**A)** выведет `599700 4` · **B)** выведет `599700 0` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**C: ошибка компиляции.** `i`, объявленная в начале, видна только внутри `for`. Если вы выбрали **A**, вы решили, что `i = 4`
из рисунка памяти остаётся и после цикла. В **B** вы решили, что `i` осталась со значением zero value: но после цикла `i` вообще не существует.

</details>

```console
$ ./_video/run.sh 09-scope
# github.com/abdurahmon27/bozor
./main.go:11:24: undefined: i
```

Первая строка сообщает, в каком модуле ошибка (GB-1.04). Вторая: файл `main.go`, **строка 11, столбец 24**, сообщение
`undefined: i` — «имя `i` неизвестно». Столбец 24 — это последняя `i` в `fmt.Println(subtotal, i)`.

Правило одно: `if`, `for` и `switch` создают каждый свой блок, поэтому **область видимости** (*scope*) этого имени ограничена
этим блоком ([Go spec: Blocks](https://go.dev/ref/spec#Blocks),
[Declarations and scope](https://go.dev/ref/spec#Declarations_and_scope)). Когда цикл заканчивается, `i` исчезает. Если результат
нужен после цикла, храните его в переменной, объявленной *перед* циклом: `subtotal` потому и стоит перед `for`.

## `range`: счётчик можно не писать

Вторая форма: `for i := range sold`. Если число после `range` равно *n*, цикл выполняется *n* раз и на каждой итерации даёт `i`
очередное число: 0, 1, … *n − 1*. `range` по целому числу есть в Go начиная с 1.22
([Go 1.22 Release Notes](https://go.dev/doc/go1.22#language), [Go spec: For range](https://go.dev/ref/spec#For_range)).
`_video/02-range/main.go`:

```go filename="_video/02-range/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := 3
	for i := range sold {
		fmt.Println(i)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `sold := 3` | цикл выполнится 3 раза |
| 7 | `for i := range sold {` | `i` получает 0, потом 1, потом 2: те же числа, что у `for i := 0; i < sold; i++` из трёх частей |
| 8 | `fmt.Println(i)` | тело: на каждой итерации печатает `i` |

Если `sold` = 3, какие три числа появятся на экране?

**A)** `1 2 3` · **B)** `0 1 2` · **C)** `0 1 2 3`

<details>
<summary>Ответ</summary>

**B: `0 1 2`.** `range sold` начинает с нуля и останавливается на `sold - 1`: всего `sold` чисел. Если вы выбрали **A**, вы
считали с 1: `range` так не делает. В **C** четыре числа, так выглядел бы вариант из трёх частей `i <= 3`, начатый с 0, а `range`
выполняется ровно 3 раза.

</details>

```console
$ ./_video/run.sh 02-range
0
1
2
```

В правиле акции штуки удобно считать с 1 (`i%3 == 0` — 3-я, 6-я, 9-я), поэтому в bozor мы оставляем форму из трёх частей.

Теперь сложим цены через `range`. Тело только прибавляет цену к `subtotal`, а `i` нигде не используется. В первом уроке
неиспользуемый импорт остановил компиляцию. Подумайте: скомпилируется ли этот код? `_video/03-range-xato/main.go`:

```go filename="_video/03-range-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 3

	var subtotal int64
	for i := range sold {
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

**A)** да, выведет `599700` · **B)** нет, ошибка компиляции

<details>
<summary>Ответ</summary>

**B.** `i` объявлена, но не использована, а Go такую переменную отвергает.

</details>

```console
$ ./_video/run.sh 03-range-xato
# github.com/abdurahmon27/bozor
./main.go:10:6: declared and not used: i
```

Читаем сообщение: `main.go`, **строка 10, столбец 6** (в `for i := range sold {` буква `i` — шестой символ),
`declared and not used: i` — «`i` объявлена, но не использована». Go отвергает неиспользуемую переменную внутри функции так же,
как неиспользуемый импорт: это ошибка компиляции ([Go spec: Variable declarations](https://go.dev/ref/spec#Variable_declarations)).

Исправление: если счётчик не нужен, его имя не пишут — `for range sold`. Цикл всё равно выполнится `sold` раз
(`_video/04-range-tuzat/main.go`, строка 10):

```go
	for range sold {
		subtotal += price
	}
```

## `for` только с условием и бесконечный `for`

Третья форма состоит только из условия: ни начала, ни шага. Её пишут, когда число итераций **заранее неизвестно**. Бюджет
покупателя — 50 000 сумов. Цикл продолжается, пока следующая штука не превышает бюджет. `_video/05-shart/main.go`:

```go filename="_video/05-shart/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var price int64 = 199_900    // tiyinda
	var budget int64 = 5_000_000 // 50 000 soʻm, tiyinda

	var spent int64
	count := 0
	for spent+price <= budget {
		spent += price
		count++
	}
	fmt.Println(count, "dona")
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `var price int64 = 199_900    // tiyinda` | цена чая в тийинах |
| 7 | `var budget int64 = 5_000_000 // 50 000 soʻm, tiyinda` | бюджет покупателя в тийинах |
| 9 | `var spent int64` | потраченные деньги, начинаются с `0` |
| 10 | `count := 0` | количество взятых штук |
| 11 | `for spent+price <= budget {` | только условие: «не превысим ли мы бюджет, если возьмём ещё одну штуку?». Ни начала, ни шага, ни `;` |
| 12 | `spent += price` | берём штуку: расход растёт |
| 13 | `count++` | увеличивает `count` на единицу: считает штуку |
| 15 | `fmt.Println(count, "dona")` | сколько штук взято |

Здесь условие делает `false` само тело (растёт `spent`). Если условие никогда не станет `false`, цикл не остановится. Чай стоит
1 999 сумов. Посчитайте до запуска: сколько штук поместится в 50 000 сумов?

**A)** 24 · **B)** 25 · **C)** 26

<details>
<summary>Ответ</summary>

**B: 25.** 25 × 199 900 = 4 997 500 тийинов, это не больше 5 000 000. Для 26-й штуки `spent + price` = 4 997 500 + 199 900 =
5 197 400 > 5 000 000: условие `false`, цикл заканчивается. 50 000 / 1 999 ≈ 25,01, поэтому в **A** на одну штуку меньше, а в **C**
на одну больше.

</details>

```console
$ ./_video/run.sh 05-shart
25 dona
```

Четвёртая форма — условие не написано вообще: `for { … }`. Если условия нет, оно считается `true`, то есть цикл бесконечный
([Go spec: For statements](https://go.dev/ref/spec#For_statements)). Из него выходят через `break`. Короткий пример
(его нет в папке; `urinish` — «попытка», `tamom` — «готово»):

```go
package main

import "fmt"

func main() {
	attempt := 0
	for {
		attempt++
		fmt.Println("urinish", attempt)
		if attempt == 3 {
			break
		}
	}
```

## Формы `for` в одном списке

| Форма | Когда | Пример |
|---|---|---|
| из трёх частей | цикл со счётчиком; числами управляете вы | `for i := 1; i <= sold; i++ { … }` |
| `range` | ровно *n* раз, от 0 до *n − 1* | `for i := range sold { … }`, `for range sold { … }` |
| только условие | число итераций заранее неизвестно | `for spent+price <= budget { … }` |
| бесконечный | условия нет; выходят через `break` | `for { … }` |

На работе всё это встречается постоянно: постраничное чтение, повторные попытки, строки заказа.

## `continue`: пропустить одну итерацию

Теперь напишем правило акции. В тело ставим `if`: если остаток от деления `i` на 3 равен нулю, то есть на каждой третьей штуке,
срабатывает `continue`. **`continue`** пропускает остаток тела и сразу переводит цикл на **шаг** (`i++`). Цикл не заканчивается,
заканчивается только эта итерация ([Go spec: Continue statements](https://go.dev/ref/spec#Continue_statements)). `sold` на этот
раз равно 7. `_video/06-continue/main.go`:

```go filename="_video/06-continue/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 7

	var subtotal int64
	for i := 1; i <= sold; i++ {
		if i%3 == 0 {
			continue // har uchinchi dona bepul
		}
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 7 | `sold := 7` | семь штук |
| 10 | `for i := 1; i <= sold; i++ {` | `i` = 1, 2, … 7 (номер штуки) |
| 11 | `if i%3 == 0 {` | `%` — остаток от деления (GB-1.03): при `i` = 3 и 6 остаток 0, то есть номер штуки делится на 3 |
| 12 | `continue // har uchinchi dona bepul` | остаток тела (строка 14) пропускается, цикл переходит к `i++` |
| 14 | `subtotal += price` | только если `if` не сработал: платная штука |

Семь итераций:

| `i` | `i%3` | `i%3 == 0` | что происходит | `subtotal` |
|---|---|---|---|---|
| 1 | 1 | `false` | цена прибавляется | 199 900 |
| 2 | 2 | `false` | цена прибавляется | 399 800 |
| 3 | 0 | `true` | **`continue`**: не прибавляется | 399 800 |
| 4 | 1 | `false` | цена прибавляется | 599 700 |
| 5 | 2 | `false` | цена прибавляется | 799 600 |
| 6 | 0 | `true` | **`continue`**: не прибавляется | 799 600 |
| 7 | 1 | `false` | цена прибавляется | 999 500 |

Не глядя в таблицу: цена скольких штук прибавится к `subtotal`?

**A)** 2 штуки · **B)** 4 штуки · **C)** 5 штук

<details>
<summary>Ответ</summary>

**C: 5 штук.** При `i` = 3 и 6 `continue` пропустил прибавление, остальные 5 итераций прибавили цену: 5 × 199 900 = 999 500.
**A** — это количество бесплатных штук (2), а не платных. Если вы выбрали **B** (4 штуки), вы вычли из 7 число 3 и решили, что бесплатных
штук три: бесплатных две.

</details>

```console
$ ./_video/run.sh 06-continue
999500
```

## `break`: выход из всего цикла

Теперь на том же месте вместо `continue` напишем `break`. **`break`** завершает цикл целиком: программа переходит к строке
после `for` ([Go spec: Break statements](https://go.dev/ref/spec#Break_statements)). `_video/07-break/main.go` отличается
только строкой 12:

```go
	for i := 1; i <= sold; i++ {
		if i%3 == 0 {
			break
		}
		subtotal += price
	}
```

`sold` снова 7. Цена скольких штук окажется в `subtotal` на этот раз?

**A)** 2 штуки · **B)** 5 штук · **C)** 6 штук

<details>
<summary>Ответ</summary>

**A: 2 штуки.** При `i` = 1 и 2 цена прибавилась, при `i` = 3 `break` завершил цикл, 4-ю штуку не рассматривали вовсе: 2 × 199 900 =
399 800. **B** — ответ для `continue`. **C** (6 штук) — вы решили, что цикл отбрасывает только одну штуку (3-ю), 7 − 1: а `break`
отбрасывает всё после 3-й штуки.

</details>

```console
$ ./_video/run.sh 07-break
399800
```

| | `continue` | `break` |
|---|---|---|
| что отбрасывает | остаток этой итерации | весь цикл |
| что дальше | `i++` (шаг), проверка условия, цикл продолжается | строка после `for` |
| результат в bozor | цена 5 штук: 999 500 | цена 2 штук: 399 800 |

## Ловушка: `break` в `switch` внутри цикла

Одна ловушка связана с `switch` из прошлого урока. Внутри цикла стоит `switch`, а в его `case` — `break`. Правило: `break` завершает
**самый внутренний** из окружающих `for` или `switch` ([Go spec: Break statements](https://go.dev/ref/spec#Break_statements);
`select` разберём в следующих модулях). `sold` на этот раз равно 4. `_video/08-switch-break/main.go`:

```go filename="_video/08-switch-break/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := 4
	for i := 1; i <= sold; i++ {
		switch {
		case i%3 == 0:
			break
		}
		fmt.Println(i)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 7 | `for i := 1; i <= sold; i++ {` | `i` = 1, 2, 3, 4 |
| 8–9 | `switch {` / `case i%3 == 0:` | `switch` без выражения (GB-1.05): если `i` делится на 3, срабатывает этот `case` |
| 10 | `break` | самый внутренний из окружающих — `switch`, а не цикл |
| 12 | `fmt.Println(i)` | после `switch`: на каждой итерации печатает `i` |

Сколько чисел появится на экране?

**A)** 2: `1 2` · **B)** 3: `1 2 3` · **C)** 4: `1 2 3 4`

<details>
<summary>Ответ</summary>

**C: 4.** При `i` = 3 `break` завершил только `switch`, программа перешла к `fmt.Println(i)` после `switch`, а цикл продолжился.
Если вы выбрали **A**, вы решили, что `break` выходит из цикла — в `for` обычно так и бывает, но здесь самый внутренний — `switch`. В
**B** выводилось бы `3`, а цикл заканчивался бы после него: но `break` завершил не цикл, а `switch`, поэтому выводится и `4`.

</details>

```console
$ ./_video/run.sh 08-switch-break
1
2
3
4
```

`3` тоже на экране: `break` завершил только `switch`. Если нужно выйти из цикла, вместо `switch` пишите `if`. Вариант этого кода
с `if` (его нет в папке):

```go
package main

import "fmt"

func main() {
	sold := 4
	for i := 1; i <= sold; i++ {
		if i%3 == 0 {
			break
		}
		fmt.Println(i)
	}
}
```

```console
$ go run .

```

Теперь `break` завершил самый внутренний `for`: `3` не вывелось, и `4` тоже не видно.

## Собираем всё в bozor

Первые две строки и проверки остаются такими же, как в прошлом уроке. Вместо умножения теперь цикл. Новая переменная `free`
считает бесплатные штуки: на каждой третьей штуке она увеличивается на единицу, а `continue` пропускает прибавление цены.
Цена доставки и НДС теперь считаются от суммы со скидкой. В конце `if`: если есть бесплатные штуки, в чеке печатается строка акции.

```go filename="main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 7
	if name == "" {
		fmt.Println("xato: mahsulot nomi boʻsh")
		return
	}
	if !active {
		fmt.Printf("xato: %s sotuvda emas\n", name)
		return
	}
	if price <= 0 || price > 10_000_000*tiyinPerSom {
		fmt.Printf("xato: narx notoʻgʻri: %d tiyin\n", price)
		return
	}
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)

	var subtotal int64
	free := 0
	for i := 1; i <= sold; i++ {
		if i%3 == 0 {
			free++
			continue // aksiya: har uchinchi dona bepul
		}
		subtotal += price
	}
	vat := subtotal * vatPercent / 100

	var delivery int64 // tiyinda
	switch {
	case subtotal >= 500_000*tiyinPerSom:
		delivery = 0
	case subtotal >= 100_000*tiyinPerSom:
		delivery = 10_000 * tiyinPerSom
	default:
		delivery = deliverySom * tiyinPerSom
	}
	total := subtotal + vat + delivery

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", delivery/tiyinPerSom, delivery%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
	if free > 0 {
		fmt.Printf("aksiya: %d dona bepul\n", free)
	}
}
```

| 50 | `free := 0` | количество бесплатных штук (`int`) |

## Частые ошибки

**1. Ошибиться границей на одну штуку (ошибки нет).** `range sold` начинает с нуля (мы видели: `0 1 2`), а форму из трёх частей
вы пишете сами. Если начать её с 0 и написать `<=`, получится лишняя итерация. Пример, которого нет в папке:

```go
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 3

	var subtotal int64
	for i := 0; i <= sold; i++ {
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

```console
$ go run .
799600
```

Компилятор молчит, но вместо 3 штук оплачены 4: 4 × 199 900 = 799 600. Причина: для `i` = 0, 1, 2, 3 условие `i <= 3` — `true`,
то есть 4 итерации. Исправление: `i := 1` с `i <= sold` или `i := 0` с `i < sold` (это то же, что `range sold`). Каждый раз
проверяйте две вещи: с какого числа начинается счётчик и каким числом заканчивается условие.

**2. Использовать `i` после цикла.** `undefined: i`: `i` живёт только внутри `for`. Смотрите выше раздел
«`i` живёт только внутри `for`». Исправление: сохраните результат в переменной, объявленной перед циклом (`subtotal`).

**3. Неиспользуемая `i` в `range`.** `declared and not used: i`: если счётчик не нужен, пишите `for range sold` (раздел `range` выше).

**4. Думать, что `break` в `switch` выходит из цикла (ошибки нет).** Цикл продолжается, результат неверный. Завершается самый
внутренний `switch`, а не цикл: раздел-ловушка выше. Исправление: вместо `switch` пишите `if`.

**5. Забыть шаг.** Если убрать шаг из `for` из трёх частей, `i` не растёт, условие никогда не станет `false`, и цикл не
остановится (пример, которого нет в папке; он компилируется):

```go
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 3

	var subtotal int64
	for i := 1; i <= sold; {
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

Программа ничего не печатает и не заканчивается (я остановил её через `timeout`). В терминале остановите её через
<kbd>Ctrl</kbd>+<kbd>C</kbd> и верните `i++`.

**2.** В чём разница между `continue` и `break`?

<details>
<summary>Ответ</summary>

`continue` пропускает остаток этой итерации и переводит цикл к шагу (`i++`): цикл продолжается. `break` выходит из всего цикла:
программа продолжается со строки после `for`. `break` внутри `switch` в цикле завершает только `switch`.

</details>

**3.** Из GB-1.03: `price` — `int64`, `sold` — `int`. Что даст `price * sold` и как это исправить?

<details>
<summary>Ответ</summary>

Ошибку компиляции `mismatched types`: `int64` и `int` нельзя умножать друг на друга. Исправление: `price * int64(sold)`.

</details>

```go

```

```go

```

Теперь `continue` срабатывает, когда истинны оба условия: штука делится на 3 **и** бесплатных штук пока меньше 2. После двух
бесплатных `free < maxFree` становится `false`, и остальные штуки платные. Для `sold` = 12:

| `i` | `i%3 == 0` | `free < maxFree` | что происходит | `free` |
|---|---|---|---|---|
| 1, 2 | `false` | | цена прибавляется | 0 |
| 3 | `true` | `0 < 2` — `true` | бесплатно (`continue`) | 1 |
| 4, 5 | `false` | | цена прибавляется | 1 |
| 6 | `true` | `1 < 2` — `true` | бесплатно (`continue`) | 2 |
| 7, 8 | `false` | | цена прибавляется | 2 |
| 9 | `true` | `2 < 2` — `false` | цена прибавляется | 2 |
| 10, 11 | `false` | | цена прибавляется | 2 |
| 12 | `true` | `2 < 2` — `false` | цена прибавляется | 2 |
