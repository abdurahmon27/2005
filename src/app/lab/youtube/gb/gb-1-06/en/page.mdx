## What you will learn

A promo has started in bozor: every third item of tea is free. A customer takes seven items, so they should pay for five. But
the code now computes `price * int64(sold)`, which multiplies the price by seven. How do you count item by item and skip the free one?

**One idea:** the init in the `for` header runs once, the condition is checked *before* every iteration, and the post
statement runs *after* every iteration. `continue` drops the rest of this iteration and goes to the post statement. `break` leaves the whole loop.

By the end of the lesson you will:

- write a three-clause `for` and count in a memory table how many times the condition is checked;
- write `for i := range sold`, `for range sold`, a condition-only loop and an infinite `for`; read the errors `undefined: i` and `declared and not used: i`;
- write the rule “every third item is free” with `continue` and `break`;
- know what `break` ends inside a `switch` in a loop.

Three main new words of the lesson:

| Word | Plain meaning | English term |
|---|---|---|
| three-clause `for` | `for init; condition; post { body }`: the block inside `{ }` repeats with a counter | three-clause `for` loop |
| forms of `for` | `range sold` (0 to `sold-1`), condition-only `for condition { }`, infinite `for { }` | `range`, condition-only and infinite `for` |
| `continue` and `break` | `continue`: the rest of this iteration is skipped; `break`: leave the whole loop | `continue`, `break` |

Two helper words: **`i++`** (*increment*) increases `i` by one, that is `i = i + 1`; **`+=`** is a short form: `x += y` means
`x = x + y`. General words: **loop** — running a block many times; **iteration** — one run of the loop; **counter** — a variable
that counts iterations, usually `i`; **body** — the lines inside `{ }`.

## The promo rule: seven items, pay for five

The rule: **every third item is free**. We count items from 1, so the 3rd, 6th, 9th… are free. In an order of seven items the 3rd and
the 6th are free and the other five are paid:

| Item | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| status | paid | paid | **free** | paid | paid | **free** | paid |

One item of tea costs 1 999 som. To pay: 5 × 1 999 = **9 995 som**. The current code, however, multiplies everything in one line:

```go
subtotal := price * int64(sold)
```

This gives 7 × 1 999 = 13 993 som. What we need is to look at each item separately: if it is free, do not add the price. To do one
thing many times you need a **loop**. Go has one keyword for repetition: `for`. There is no other loop keyword
([Go spec: Keywords](https://go.dev/ref/spec#Keywords)); [A Tour of Go](https://go.dev/tour/flowcontrol/1) says the same:
“Go has only one looping construct, the for loop”. It has several forms, and we will see all of them today.

## The three-clause `for`

First with 3 items, without the promo. This is `_video/01-sikl/main.go`:

```go filename="_video/01-sikl/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 3

	var subtotal int64
	for i := 1; i <= sold; i++ {
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `var price int64 = 199_900 // tiyinda` | the price of tea: 1 999 som = 199 900 tiyin (GB-1.03) |
| 7 | `sold := 3` | the number of items in the order |
| 9 | `var subtotal int64` | the sum: zero value, that is `0` (GB-1.02) |
| 10 | `for i := 1; i <= sold; i++ {` | the loop header: `for` and three clauses separated by a **semicolon** `;`; `{` opens the body |
| 10 | `i := 1` | the **init** statement: once, at the very start; `i` is the counter and gets 1 |
| 10 | `i <= sold` | the **condition**: checked *before* every iteration; `true` — the body runs, `false` — the loop ends |
| 10 | `i++` | the **post** statement: runs *after* every iteration and increases `i` by one |
| 11 | `subtotal += price` | the body: a short form of `subtotal = subtotal + price`, it adds the price to the sum |
| 12 | `}` | the body ended: the program goes back to the post statement |
| 13 | `fmt.Println(subtotal)` | prints the sum after the loop |

The order once more in one sentence: init — once; then it repeats: condition → body → post → condition → body → post…; as soon
as the condition gives `false`, the loop ends and the program goes on from the line after `}`
([Go spec: For clause](https://go.dev/ref/spec#For_clause)).

Before you run it, think: `sold` equals 3. How many times is the condition checked and how many times does the body run?

**A)** 3 times and 3 times · **B)** 3 times and 4 times · **C)** 4 times and 3 times

<details>
<summary>Answer</summary>

**C: the condition 4 times, the body 3 times.** The condition is checked *before* the body, so the last check — the one that
gives `false` — has no body: 3 iterations need 4 checks. If you chose **A**, you did not count the last check. In **B** the body
would run more often than the condition is checked, which is impossible: the body runs only after `true`.

</details>

We follow it in memory. `sold` = 3, `subtotal` = 0, `price` = 199 900:

| Step | Line | `i` | `subtotal` | Condition |
|---|---|---|---|---|
| init `i := 1` | 10 | 1 | 0 | `1 <= 3` → `true` (1st check) |
| body | 11 | 1 | 199 900 | |
| post `i++` | 10 | 2 | 199 900 | `2 <= 3` → `true` (2nd check) |
| body | 11 | 2 | 399 800 | |
| post `i++` | 10 | 3 | 399 800 | `3 <= 3` → `true` (3rd check) |
| body | 11 | 3 | 599 700 | |
| post `i++` | 10 | 4 | 599 700 | `4 <= 3` → `false` (4th check): **the loop ended** |
| `Println` | 13 | — | 599 700 | `599700` goes to the screen |

Check the result yourself:

```console
$ ./_video/run.sh 01-sikl
599700
```

Three iterations, four checks: if there are *n* iterations, the condition is checked *n + 1* times. 599 700 tiyin is 3 × 199 900.

## `i` lives only inside `for`

When the loop ended, `i` was 4. In the last lesson, `left` declared in a short `if` could not be used after the block.
Now we print `i` together with `subtotal` after the loop (`_video/09-scope/main.go`, line 11):

```go filename="_video/09-scope/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := 3
	var subtotal int64
	for i := 1; i <= sold; i++ {
		subtotal += 199_900
	}
	fmt.Println(subtotal, i)
}
```

Think: what does this program do?

**A)** prints `599700 4` · **B)** prints `599700 0` · **C)** a compile error

<details>
<summary>Answer</summary>

**C: a compile error.** The `i` declared in the init is visible only inside the `for`. If you chose **A**, you thought the `i = 4`
from the memory picture stays after the loop. In **B** you thought `i` stays with its zero value: but after the loop `i` does not exist at all.

</details>

```console
$ ./_video/run.sh 09-scope
# github.com/abdurahmon27/bozor
./main.go:11:24: undefined: i
```

The first line tells which module has the error (GB-1.04). The second: file `main.go`, **line 11, column 24**, message
`undefined: i` — “the name `i` is not known”. Column 24 is the last `i` in `fmt.Println(subtotal, i)`.

The rule is one: `if`, `for` and `switch` each create their own block, so the **scope** of this name is limited to that block
([Go spec: Blocks](https://go.dev/ref/spec#Blocks), [Declarations and scope](https://go.dev/ref/spec#Declarations_and_scope)).
When the loop ends, `i` is gone. If you need the result after the loop, keep it in a variable declared *before* the loop:
that is why `subtotal` stands before `for`.

## `range`: you do not have to write the counter

The second form: `for i := range sold`. If the number after `range` is *n*, the loop runs *n* times and gives `i` the next
number each time: 0, 1, … *n − 1*. `range` over an integer exists in Go since 1.22
([Go 1.22 Release Notes](https://go.dev/doc/go1.22#language), [Go spec: For range](https://go.dev/ref/spec#For_range)).
`_video/02-range/main.go`:

```go filename="_video/02-range/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := 3
	for i := range sold {
		fmt.Println(i)
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `sold := 3` | the loop runs 3 times |
| 7 | `for i := range sold {` | `i` gets 0, then 1, then 2: the same numbers as the three-clause `for i := 0; i < sold; i++` |
| 8 | `fmt.Println(i)` | the body: prints `i` on every iteration |

If `sold` is 3, which three numbers appear on the screen?

**A)** `1 2 3` · **B)** `0 1 2` · **C)** `0 1 2 3`

<details>
<summary>Answer</summary>

**B: `0 1 2`.** `range sold` starts at zero and stops at `sold - 1`: `sold` numbers in total. If you chose **A**, you counted from 1:
`range` does not do that. **C** has four numbers: that would be the three-clause `i <= 3` started from 0, while `range` runs exactly 3 times.

</details>

```console
$ ./_video/run.sh 02-range
0
1
2
```

In the promo rule it is convenient to count items from 1 (`i%3 == 0` — the 3rd, 6th, 9th), so in bozor we keep the three-clause form.

Now we add the prices with `range`. The body only adds the price to `subtotal`, and `i` is not used anywhere. In the first lesson an
unused import stopped the compilation. Think: will this code compile? `_video/03-range-xato/main.go`:

```go filename="_video/03-range-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 3

	var subtotal int64
	for i := range sold {
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

**A)** yes, it prints `599700` · **B)** no, a compile error

<details>
<summary>Answer</summary>

**B.** `i` is declared but not used, and Go rejects such a variable.

</details>

```console
$ ./_video/run.sh 03-range-xato
# github.com/abdurahmon27/bozor
./main.go:10:6: declared and not used: i
```

We read the message: `main.go`, **line 10, column 6** (in `for i := range sold {` the `i` is the sixth character),
`declared and not used: i` — “`i` is declared but not used”. Go rejects an unused variable inside a function the same way as an
unused import: it is a compile error ([Go spec: Variable declarations](https://go.dev/ref/spec#Variable_declarations)).

The fix: if you do not need the counter, you do not write its name — `for range sold`. The loop still runs `sold` times
(`_video/04-range-tuzat/main.go`, line 10):

```go
	for range sold {
		subtotal += price
	}
```


## The condition-only `for` and the infinite `for`

The third form is only a condition: no init and no post statement. You write it when the number of iterations is **not known in
advance**. The customer's budget is 50 000 som. The loop goes on while the next item does not exceed the budget.
`_video/05-shart/main.go`:

```go filename="_video/05-shart/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var price int64 = 199_900    // tiyinda
	var budget int64 = 5_000_000 // 50 000 soʻm, tiyinda

	var spent int64
	count := 0
	for spent+price <= budget {
		spent += price
		count++
	}
	fmt.Println(count, "dona")
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `var price int64 = 199_900    // tiyinda` | the price of tea, in tiyin |
| 7 | `var budget int64 = 5_000_000 // 50 000 soʻm, tiyinda` | the customer's budget, in tiyin |
| 9 | `var spent int64` | the money spent, starts at `0` |
| 10 | `count := 0` | the number of items taken |
| 11 | `for spent+price <= budget {` | only a condition: “if we take one more item, will we still stay within the budget?”. No init, no post statement, no `;` |
| 12 | `spent += price` | we take an item: the spending grows |
| 13 | `count++` | increases `count` by one: counts the item |
| 15 | `fmt.Println(count, "dona")` | how many items were taken |

Here the body itself makes the condition `false` (`spent` grows). If the condition never becomes `false`, the loop does not stop.
Tea costs 1 999 som. Calculate before you run: how many items fit into 50 000 som?

**A)** 24 · **B)** 25 · **C)** 26

<details>
<summary>Answer</summary>

**B: 25.** 25 × 199 900 = 4 997 500 tiyin, which is not more than 5 000 000. For the 26th item `spent + price` = 4 997 500 + 199 900 =
5 197 400 > 5 000 000: the condition is `false` and the loop ends. 50 000 / 1 999 ≈ 25.01, so **A** is one item short and **C** is
one item too many.

</details>

```console
$ ./_video/run.sh 05-shart
25 dona
```

The fourth form has no condition at all: `for { … }`. If the condition is absent, it counts as `true`, that is, the loop is
infinite ([Go spec: For statements](https://go.dev/ref/spec#For_statements)). You leave it with `break`. A short example
(not in the folder; `urinish` means “attempt”, `tamom` means “done”):

```go
package main

import "fmt"

func main() {
	attempt := 0
	for {
		attempt++
		fmt.Println("urinish", attempt)
		if attempt == 3 {
			break
		}
	}
	fmt.Println("tamom")
}
```

```console
$ go run .
urinish 1
urinish 2
urinish 3
tamom
```

The loop ran until `attempt` reached 3, the `break` inside `if` stopped it, and the program went to the `tamom` line after `}`.
We look at `break` in more detail soon.

## The forms of `for` in one list

| Form | When | Example |
|---|---|---|
| three-clause | a loop with a counter; you control the numbers | `for i := 1; i <= sold; i++ { … }` |
| `range` | exactly *n* times, from 0 to *n − 1* | `for i := range sold { … }`, `for range sold { … }` |
| condition only | the number of iterations is not known in advance | `for spent+price <= budget { … }` |
| infinite | no condition; you leave with `break` | `for { … }` |

At work these are everywhere: reading pages one by one, retries, order lines.

## `continue`: skip one iteration

Now we write the promo rule. We put an `if` in the body: if the remainder of `i` divided by 3 is zero, that is, on every third item,
`continue` runs. **`continue`** skips the rest of the body and sends the loop straight to the **post statement** (`i++`). The loop does not end,
only this iteration ends ([Go spec: Continue statements](https://go.dev/ref/spec#Continue_statements)). This time `sold` is 7.
`_video/06-continue/main.go`:

```go filename="_video/06-continue/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 7

	var subtotal int64
	for i := 1; i <= sold; i++ {
		if i%3 == 0 {
			continue // har uchinchi dona bepul
		}
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

| Line | Code | What it does |
|---|---|---|
| 7 | `sold := 7` | seven items |
| 10 | `for i := 1; i <= sold; i++ {` | `i` = 1, 2, … 7 (the item number) |
| 11 | `if i%3 == 0 {` | `%` is the remainder of a division (GB-1.03): for `i` = 3 and 6 the remainder is 0, that is, the item number is divisible by 3 |
| 12 | `continue // har uchinchi dona bepul` | the rest of the body (line 14) is skipped, the loop goes to `i++` |
| 14 | `subtotal += price` | only when the `if` did not run: a paid item |

Seven iterations:

| `i` | `i%3` | `i%3 == 0` | what happens | `subtotal` |
|---|---|---|---|---|
| 1 | 1 | `false` | the price is added | 199 900 |
| 2 | 2 | `false` | the price is added | 399 800 |
| 3 | 0 | `true` | **`continue`**: nothing is added | 399 800 |
| 4 | 1 | `false` | the price is added | 599 700 |
| 5 | 2 | `false` | the price is added | 799 600 |
| 6 | 0 | `true` | **`continue`**: nothing is added | 799 600 |
| 7 | 1 | `false` | the price is added | 999 500 |

Without looking at the table: the price of how many items is added to `subtotal`?

**A)** 2 items · **B)** 4 items · **C)** 5 items

<details>
<summary>Answer</summary>

**C: 5 items.** For `i` = 3 and 6, `continue` skipped the addition, and the other 5 iterations added the price: 5 × 199 900 = 999 500.
**A** is the number of free items (2), not paid items. If you chose **B** (4 items), you subtracted 3 from 7 and thought three items
are free: two are free.

</details>

```console
$ ./_video/run.sh 06-continue
999500
```

## `break`: leave the whole loop

Now, in the same place, we write `break` instead of `continue`. **`break`** ends the loop completely: the program goes to the line
after `for` ([Go spec: Break statements](https://go.dev/ref/spec#Break_statements)). `_video/07-break/main.go` differs only in
line 12:

```go
	for i := 1; i <= sold; i++ {
		if i%3 == 0 {
			break
		}
		subtotal += price
	}
```

`sold` is 7 again. The price of how many items is in `subtotal` this time?

**A)** 2 items · **B)** 5 items · **C)** 6 items

<details>
<summary>Answer</summary>

**A: 2 items.** For `i` = 1 and 2 the price was added, for `i` = 3 `break` ended the loop, and the 4th item was not even looked at: 2 × 199 900 =
399 800. **B** is the answer for `continue`. **C** (6 items) — you thought the loop drops only one item (the 3rd), 7 − 1: but `break`
drops everything after the 3rd item.

</details>

```console
$ ./_video/run.sh 07-break
399800
```

| | `continue` | `break` |
|---|---|---|
| what it drops | the rest of this iteration | the whole loop |
| what next | `i++` (post), the condition is checked, the loop goes on | the line after `for` |
| result in bozor | the price of 5 items: 999 500 | the price of 2 items: 399 800 |

## The trap: `break` in a `switch` inside a loop

One trap is connected with the `switch` of the last lesson. Inside a loop there is a `switch`, and in its `case` there is a `break`. The rule: `break` ends the
**innermost** enclosing `for` or `switch` ([Go spec: Break statements](https://go.dev/ref/spec#Break_statements);
we will see `select` in later modules). This time `sold` is 4. `_video/08-switch-break/main.go`:

```go filename="_video/08-switch-break/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sold := 4
	for i := 1; i <= sold; i++ {
		switch {
		case i%3 == 0:
			break
		}
		fmt.Println(i)
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 7 | `for i := 1; i <= sold; i++ {` | `i` = 1, 2, 3, 4 |
| 8–9 | `switch {` / `case i%3 == 0:` | a `switch` without an expression (GB-1.05): if `i` is divisible by 3, this `case` runs |
| 10 | `break` | the innermost enclosing statement is the `switch`, not the loop |
| 12 | `fmt.Println(i)` | after the `switch`: prints `i` on every iteration |

How many numbers appear on the screen?

**A)** 2: `1 2` · **B)** 3: `1 2 3` · **C)** 4: `1 2 3 4`

<details>
<summary>Answer</summary>

**C: 4.** For `i` = 3 the `break` ended only the `switch`, the program went to `fmt.Println(i)` after the `switch`, and the loop went on.
If you chose **A**, you thought `break` leaves the loop — in a `for` it usually does, but here the innermost statement is the `switch`. In
**B** the `3` would be printed and the loop would end after it: but `break` ended the `switch`, not the loop, so `4` is printed too.

</details>

```console
$ ./_video/run.sh 08-switch-break
1
2
3
4
```

`3` is on the screen too: `break` ended only the `switch`. If you need to leave the loop, write `if` instead of `switch`. The
variant of this code with `if` (not in the folder):

```go
package main

import "fmt"

func main() {
	sold := 4
	for i := 1; i <= sold; i++ {
		if i%3 == 0 {
			break
		}
		fmt.Println(i)
	}
}
```

```console
$ go run .
```

## Putting it all into bozor

The first two lines and the checks stay as in the last lesson. Instead of multiplication there is now a loop. A new variable `free`
counts the free items: on every third item it grows by one, and `continue` skips adding the price.
The delivery price and the VAT are now computed from the discounted sum. At the end an `if`: if there are free items, the receipt gets a promo line.

```go filename="main.go" showLineNumbers
package main

import "fmt"

const tiyinPerSom = 100    // 1 soʻm = 100 tiyin
const vatPercent = 12      // QQS, foizda
const deliverySom = 15_000 // yetkazib berish, soʻmda (QQS qoʻshilmaydi)

func main() {
	fmt.Println("bozor ishga tushdi")
	fmt.Println("versiya: 0.1.0")

	var name string
	var price int64
	var active bool
	fmt.Println(name, price, active)

	name = "choy"
	price = 1_999 * tiyinPerSom // tiyinda
	active = true
	stock := 40
	weight := 1.5
	fmt.Println(name, price, active, stock, weight)

	sold := 7
	if name == "" {
		fmt.Println("xato: mahsulot nomi boʻsh")
		return
	}
	if !active {
		fmt.Printf("xato: %s sotuvda emas\n", name)
		return
	}
	if price <= 0 || price > 10_000_000*tiyinPerSom {
		fmt.Printf("xato: narx notoʻgʻri: %d tiyin\n", price)
		return
	}
	if sold <= 0 {
		fmt.Println("xato: miqdor kamida 1 dona boʻlishi kerak")
		return
	}
	if left := stock - sold; left < 0 {
		fmt.Printf("xato: omborda %d dona yetmaydi\n", -left)
		return
	}
	stock = stock - sold
	fmt.Println(name, stock)

	var subtotal int64
	free := 0
	for i := 1; i <= sold; i++ {
		if i%3 == 0 {
			free++
			continue // aksiya: har uchinchi dona bepul
		}
		subtotal += price
	}
	vat := subtotal * vatPercent / 100

	var delivery int64 // tiyinda
	switch {
	case subtotal >= 500_000*tiyinPerSom:
		delivery = 0
	case subtotal >= 100_000*tiyinPerSom:
		delivery = 10_000 * tiyinPerSom
	default:
		delivery = deliverySom * tiyinPerSom
	}
	total := subtotal + vat + delivery

	item := fmt.Sprintf("%s, %d dona", name, sold)
	fmt.Printf("%-14s %9d.%02d\n", item, subtotal/tiyinPerSom, subtotal%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "QQS", vat/tiyinPerSom, vat%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "yetkazish", delivery/tiyinPerSom, delivery%tiyinPerSom)
	fmt.Printf("%-14s %9d.%02d\n", "jami", total/tiyinPerSom, total%tiyinPerSom)
	if free > 0 {
		fmt.Printf("aksiya: %d dona bepul\n", free)
	}
}
```

## Common mistakes

**1. Being off by one item (no error).** `range sold` starts at zero (we saw `0 1 2`), while you write the three-clause form
yourself. If you start it at 0 and write `<=`, you get one extra iteration. An example that is not in the folder:

```go
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 3

	var subtotal int64
	for i := 0; i <= sold; i++ {
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

```console
$ go run .
799600
```

The compiler says nothing, but 4 items are paid instead of 3: 4 × 199 900 = 799 600. The reason: for `i` = 0, 1, 2, 3 the condition `i <= 3` is `true`,
that is, 4 iterations. The fix: `i := 1` with `i <= sold`, or `i := 0` with `i < sold` (this is the same as `range sold`). Each time
check two things: from which number the counter starts and with which number the condition ends.

**2. Using `i` after the loop.** `undefined: i`: `i` lives only inside `for`. See the section “`i` lives only inside `for`” above.
The fix: keep the result in a variable declared before the loop (`subtotal`).

**3. An unused `i` in `range`.** `declared and not used: i`: if you do not need the counter, write `for range sold` (the `range` section above).

**4. Thinking that `break` in a `switch` leaves the loop (no error).** The loop goes on and the result is wrong. The innermost
`switch` ends, not the loop: the trap section above. The fix: write `if` instead of `switch`.

**5. Forgetting the post statement.** If you leave out the post statement of a three-clause `for`, `i` does not grow, the condition never
becomes `false`, and the loop does not stop (an example that is not in the folder; it compiles):

```go
package main

import "fmt"

func main() {
	var price int64 = 199_900 // tiyinda
	sold := 3

	var subtotal int64
	for i := 1; i <= sold; {
		subtotal += price
	}
	fmt.Println(subtotal)
}
```

The program prints nothing and does not end (I stopped it with `timeout`). In the terminal stop it with
<kbd>Ctrl</kbd>+<kbd>C</kbd> and put `i++` back.

## Check yourself

**1.** In a three-clause loop where `i` counts from one to three (`for i := 1; i <= 3; i++`), how many times is the condition checked?

<details>
<summary>Answer</summary>

4 times: `true` for `i` = 1, 2, 3, `false` for `i` = 4, and the loop ends. The body runs 3 times.

</details>

**2.** What is the difference between `continue` and `break`?

<details>
<summary>Answer</summary>

`continue` skips the rest of this iteration and sends the loop to the post statement (`i++`): the loop goes on. `break` leaves the
whole loop: the program goes on from the line after `for`. `break` inside a `switch` in a loop ends only the `switch`.

</details>

**3.** From GB-1.03: `price` is `int64`, `sold` is `int`. What does `price * sold` give and how do you fix it?

<details>
<summary>Answer</summary>

A `mismatched types` compile error: `int64` and `int` cannot be multiplied together. The fix: `price * int64(sold)`.

</details>

**4.** What does this program print (it is not in the folder)?

```go
package main

import "fmt"

func main() {
	for i := 1; i <= 10; i += 3 {
		fmt.Println(i)
	}
}
```

**A)** `1 4 7` · **B)** `1 4 7 10` · **C)** `1 4 7 10 13`

<details>
<summary>Answer</summary>

**B: `1 4 7 10`.** The post statement `i += 3`: `i` grows by 3 each time — 1, 4, 7, 10. Then `i` = 13: `13 <= 10` is `false`, the loop
ends. **A** misses 10 (`10 <= 10` is `true`). **C** prints 13 too, but the condition for 13 is `false`.

```console
$ go run .
1
4
7
10
```

</details>

**5.** What does this program print (it is not in the folder)?

```go
package main

import "fmt"

func main() {
	for i := range 4 {
		if i == 2 {
			continue
		}
		fmt.Println(i)
	}
}
```

**A)** `0 1 3` · **B)** `1 3` · **C)** `0 1`

<details>
<summary>Answer</summary>

**A: `0 1 3`.** `range 4` is 0, 1, 2, 3. For `i` = 2, `continue` skips `Println`, and the loop goes on with `i` = 3.
**B** starts counting from 1. **C** would be printed if there were `break` instead of `continue`.

```console
$ go run .
0
1
3
```

</details>
