## Nimani oʻrganasiz

`orders.sql` bir marta jadvallarni yaratdi. Server yangilanganda uni yana ishlatsangiz nima boʻladi? Maʼlumotlarni oʻchirmasdan sxemani qanday yangilaysiz?

**Bitta gʻoya:** sxemaning har oʻzgarishi raqamlangan SQL faylda turadi. Baza qoʻllangan fayllarni `goose_db_version` jadvalida saqlaydi; goose yetishmaganlarini qoʻllaydi.
Odatda har fayl bitta transaction ichida bajariladi: xato boʻlsa, shu faylning oʻzgarishlari qaytadi.

Darsdan keyin siz:

- goose oʻrnatib, `status`, `up`, `down` buyruqlarini ishlatasiz;
- versiya jadvalidan baza holatini oʻqiysiz;
- maʼlumotli jadvalga ustun qoʻshish xatosini `DEFAULT` bilan tuzatasiz;
- toʻrtinchi migratsiyani yozib, testdan oʻtkazasiz.

| Soʻz | Sodda maʼnosi | Inglizcha |
|---|---|---|
| migratsiya fayli | sxemani oʻzgartiradigan raqamlangan SQL fayl | migration file |
| goose | fayllar va bazadagi qoʻllangan versiyalarni solishtiradigan asbob | goose |
| xato bergan migratsiya | bajarilmagan va odatiy transaction ichida qaytarilgan oʻzgarish | failed migration |

**ALTER TABLE** mavjud jadval tuzilmasini oʻzgartiradi. **`\dt`** — psql'da jadvallar roʻyxatini chiqaradigan buyruq.
Bu darsda sxema jadval tuzilmasini anglatadi; `public` esa jadvallar joylashgan nomli schema.

## Migratsiya fayllari va goose

Har oʻzgarish — alohida **migratsiya fayli**. Raqam tartibni bildiradi; goose fayllarni bazadagi versiyalar bilan solishtiradi.

| Oldingi holat | Amal | Keyingi holat |
|---|---|---|
| fayllar 1, 2; bazada boshlangʻich 0 | `goose up` | 1, 2 qoʻllangan; versiya 2 |
| fayllar 1, 2; bazada 1, 2 | `goose up` | oʻzgarish yoʻq |
| fayllar 1, 2, 3; bazada 1, 2 | `goose up` | faqat 3 bajariladi |

Goose'ni aniq versiyada oʻrnating. Modul yoʻlidagi `v3` katta versiya, `cmd/goose` buyruq paketi, `@v3.30.2` oʻrnatiladigan versiya.
`go install` bajariladigan faylni `GOBIN`ga, u belgilanmagan boʻlsa odatda `~/go/bin`ga yozadi. Shu papka `PATH`da boʻlsin.

```console
$ go install github.com/pressly/goose/v3/cmd/goose@v3.30.2
```

```console
$ goose -version
goose version: v3.30.2
```

Oʻrnatish bu qayta ishga tushirishda hech narsa chiqarmadi; birinchi safar yuklash xabarlari boʻlishi mumkin. `-version` oʻrnatilgan versiyani koʻrsatadi.
Goose'ga uchta qiymat kerak: `GOOSE_DRIVER` — baza turi; `GOOSE_DBSTRING` — ulanish manzili; `GOOSE_MIGRATION_DIR` — fayllar papkasi.
Bir `export` bir nechta qiymatni belgilashi mumkin.

```bash
export GOOSE_DRIVER=postgres GOOSE_MIGRATION_DIR=migrations
export GOOSE_DBSTRING=postgres://bozor:bozor-lab@localhost:5486/bozor
export DATABASE_URL=postgres://bozor:bozor-lab@localhost:5486/bozor
```

`DATABASE_URL`ni keyingi Go testlari oʻqiydi; goose oʻzining `GOOSE_DBSTRING` qiymatini ishlatadi.
URL qismlari: `bozor` foydalanuvchi, `bozor-lab` laboratoriya paroli, `localhost:5486` manzil va port, oxirgi `bozor` baza nomi.
`ls migrations` fayllarni sanaydi:

```console
$ ls migrations
00001_products.sql
00002_orders.sql
```

```sql filename="migrations/00001_products.sql" showLineNumbers
-- +goose Up
CREATE TABLE products (
    id     bigint
           GENERATED ALWAYS AS IDENTITY
           PRIMARY KEY,
    name   text    NOT NULL UNIQUE CHECK (name <> ''),
    price  bigint  NOT NULL CHECK (price > 0),
    stock  integer NOT NULL DEFAULT 0 CHECK (stock >= 0),
    active boolean NOT NULL DEFAULT true
);

-- +goose Down
DROP TABLE products;
```

| Qator | Nima qiladi |
|---|---|
| 1 | SQL'da `--` izoh; goose uchun `-- +goose Up` qoʻllash boʻlimini boshlaydi |
| 2 | `CREATE TABLE products (` jadval va uning ustunlarini ochadi |
| 3–5 | `id` katta butun son; baza raqam beradi; asosiy kalit uni yagona qiladi |
| 6 | `name` matn; NULL, takror va boʻsh matn rad etiladi |
| 7 | `price` katta butun son, tiyinda; NULL va musbat boʻlmagan qiymat rad etiladi |
| 8 | `stock` butun son; odatda 0; manfiy qiymat va NULL rad etiladi |
| 9 | `active` mantiqiy qiymat; odatda true; NULL rad etiladi |
| 10 | `);` jadval taʼrifini va SQL buyrugʻini tugatadi |
| 12–13 | `Down` qaytarish boʻlimi; `DROP TABLE` jadvalni oʻchiradi |

`<>` — teng emas; `''` — boʻsh matn. Ikkinchi fayl bogʻliq jadvallarni yaratadi:

```sql filename="migrations/00002_orders.sql" showLineNumbers
-- +goose Up
CREATE TABLE orders (
    id       bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer text   NOT NULL,
    note     text
);
CREATE TABLE order_items (
    id         bigint  GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    order_id   bigint  NOT NULL REFERENCES orders (id),
    product_id bigint  NOT NULL REFERENCES products (id),
    quantity   integer NOT NULL CHECK (quantity > 0),
    unit_price bigint  NOT NULL CHECK (unit_price > 0)
);

-- +goose Down
DROP TABLE order_items;
DROP TABLE orders;
```

2–6-qatorlar: `orders` buyurtmalar jadvali; `customer` mijoz nomi, `note` ixtiyoriy izoh.
7–13-qatorlar: `order_items` buyurtma qatorlari; `order_id` va `product_id` tashqi kalitlar.
`quantity` soni va `unit_price` dona narxi musbat boʻlishi kerak.
15–17-qatorlar: avval havola qiluvchi `order_items`, keyin `orders` oʻchadi. Birinchi migratsiya keyin qaytariladi.

## Holat, Up va versiya jadvali

`goose status` har faylning holatini koʻrsatadi. `Applied At` — qoʻllangan vaqt; `Migration` — fayl.
`Pending` — hali qoʻllanmagan. Pastdagi barcha console bloklar qayta ishga tushirildi; sana prefikslari ham aynan saqlandi.

```console
$ goose status
2026/11/27 20:34:28     Applied At                  Migration
2026/11/27 20:34:28     =======================================
2026/11/27 20:34:28     Pending                  -- 00001_products.sql
2026/11/27 20:34:28     Pending                  -- 00002_orders.sql
```

`goose up` qoʻllanmagan fayllarni raqam tartibida bajaradi. Bu boʻsh bazada qaysi fayllar bajariladi?
**A)** faqat 2 · **B)** avval 1, keyin 2 · **C)** hech biri.

<details>
<summary>Javob</summary>

**B.** Ikkalasi `Pending`. Oxirgi raqam eng yangi versiya, faqat shu faylni bajarish buyrugʻi emas.

</details>

```console
$ goose up
2026/11/27 20:34:28 OK   00001_products.sql (8.94ms)
2026/11/27 20:34:28 OK   00002_orders.sql (9.83ms)
2026/11/27 20:34:28 goose: successfully migrated database to version: 2
```

`OK` — fayl qoʻllandi; qavsda vaqt, `ms` — millisekund. Oxirgi qator bazaning joriy versiyasi `2` ekanini aytadi.
`psql -c` bitta buyruqni bajaradi. `\dt` jadvallarni sanaydi:

```console
$ docker compose exec db psql -c '\dt'
              List of tables
 Schema |       Name       | Type  | Owner 
--------+------------------+-------+-------
 public | goose_db_version | table | bozor
 public | order_items      | table | bozor
 public | orders           | table | bozor
 public | products         | table | bozor
(4 rows)
```

`Schema` — nomli guruh (`public`); `Name` — jadval nomi; `Type` — `table`; `Owner` — egasi.
Uchta loyiha jadvali va goose'ning `goose_db_version` jadvali bor. `(4 rows)` — toʻrtta natija qatori.
Versiya yozuvlarini `id` boʻyicha tartiblab oʻqing:

```console
$ docker compose exec db psql -c 'SELECT id, version_id, is_applied FROM goose_db_version ORDER BY id'
 id | version_id | is_applied 
----+------------+------------
  1 |          0 | t
  2 |          1 | t
  3 |          2 | t
(3 rows)
```

`id` — yozuv kaliti; `version_id` — migratsiya raqami; `is_applied`dagi `t` — true, qoʻllangan.
`0` goose'ning boshlangʻich yozuvi, migratsiya fayli emas. Shuning uchun ikki faylga uchta yozuv bor.

Xuddi shu `goose up`ni takrorlang. **A)** jadval bor xatosi · **B)** oʻzgarish yoʻq · **C)** jadvallar qayta yaratiladi.

<details>
<summary>Javob</summary>

**B.** Goose ikkala versiya qoʻllanganini koʻradi. A javob qoʻlda SQL faylini takrorlashga tegishli; C esa maʼlumotlarni yoʻqotar edi.

</details>

```console
$ goose up
2026/11/27 20:34:28 goose: no migrations to run. current version: 2
```

`no migrations to run` — bajariladigan yangi fayl yoʻq. Sxema boshqarilayotgan boʻlsa, har deploy'da `up`ni shu tarzda qaytarish mumkin.
Bu qoʻlda oʻzgartirilgan sxemani tuzatish yoki bir vaqtda bir nechta deploy'ni boshqarish kafolati emas.

## Maʼlumotli jadvalda NOT NULL xatosi

`seed.sql` toʻrtta mahsulot, uchta buyurtma va toʻrtta buyurtma qatorini qoʻshadi:

```console
$ docker compose exec db psql -f /lab/seed.sql
INSERT 0 4
INSERT 0 3
INSERT 0 4
```

Har `INSERT 0 N`dagi `N` — yozilgan qatorlar soni.
Buyurtmaga status kerak. `goose create` fayl shablonini yaratadi; `-s` ketma-ket raqamni tanlaydi, `orders_status` nomi, `sql` fayl turi.
`-s` boʻlmasa, nom vaqt belgisi bilan boshlanadi; loyihada bitta usulni tanlang.

```console
$ goose create -s orders_status sql
2026/11/27 20:34:28 Created new file: migrations/00003_orders_status.sql
```

```console
$ ls migrations
00001_products.sql
00002_orders.sql
00003_orders_status.sql
```

`Created new file` — yangi fayl yaratildi. Shablondagi oʻrnak `SELECT`larni almashtiring. Hozircha ataylab xato variant:

```sql
-- +goose Up
ALTER TABLE orders ADD COLUMN status text NOT NULL;

-- +goose Down
ALTER TABLE orders DROP COLUMN status;
```

1-qator — Up. 2-qator: `ALTER TABLE orders` mavjud jadvalni oʻzgartiradi; `ADD COLUMN` `status` nomli matn ustunini qoʻshadi.
`NOT NULL` NULL qiymatini taqiqlaydi. 4–5-qatorlar — Down; `DROP COLUMN` ustunni oʻchiradi.
Yangi ustunda mavjud qatorlarga `DEFAULT` berilmasa, NULL keladi. NULL boʻsh matn emas.

Uchta buyurtma bor. Nima boʻladi? **A)** status `''` boʻladi · **B)** baza rad etadi · **C)** NULL qabul qilinadi.

<details>
<summary>Javob</summary>

**B.** Uchta mavjud qatorga NULL kerak boʻladi, `NOT NULL` esa buni rad etadi. A uchun hech qanday boʻsh matn qiymati belgilanmagan; C qoidaga zid.

</details>

```console
$ goose up
2026/11/27 20:34:28 goose run: ERROR 00003_orders_status.sql: failed to run SQL migration: failed to execute SQL query "ALTER TABLE orders ADD COLUMN status text NOT NULL;": ERROR: column "status" of relation "orders" contains null values (SQLSTATE 23502)
```

Goose chiqish kodi `1`. `ERROR 00003_orders_status.sql` faylni koʻrsatadi; keyin bajarilmagan SQL bor.
`column "status" of relation "orders" contains null values` — orders jadvalidagi status NULL qiymatlarni oʻz ichiga oladi.
`SQLSTATE 23502` — Postgres'ning `not_null_violation`, yaʼni NOT NULL buzilishi kodi.

**Transaction** — buyruqlarni yo hammasi, yo hech biri saqlanadigan qilib bajarish. Batafsil [GB-5.07](/lab/youtube/gb/gb-5-07).
Goose odatda har faylni bitta transaction ichida bajaradi. Bu bir `up`dagi barcha fayllar uchun bitta transaction degani emas.

| Bosqich | Fayl 1–2 | Fayl 3 | orders.status |
|---|---|---|---|
| xatodan oldin | saqlangan | boshlanmagan | yoʻq |
| xato | saqlangan | qaytariladi | yoʻq |
| keyingi urinish | qayta bajarilmaydi | yana bajariladi | muvaffaqiyatga bogʻliq |

Oraliq savol: xatodan keyin `orders` qanday? **A)** NULL bilan status bor · **B)** status yoʻq · **C)** jadval yarim oʻzgargan.

<details>
<summary>Javob</summary>

**B.** Ushbu faylning oʻzgarishi saqlanmadi. Bu misolda `ALTER TABLE`ning oʻzi ham atomar; bir nechta buyruqli faylda transaction oldingi buyruqlarni ham qaytaradi.

</details>

```console
$ docker compose exec db psql -c 'SELECT * FROM orders LIMIT 1'
 id | customer | note 
----+----------+------
  1 | Dilnoza  | 
(1 row)
```

```console
$ goose status
2026/11/27 20:34:28     Applied At                  Migration
2026/11/27 20:34:28     =======================================
2026/11/27 20:34:28     Fri Nov 27 15:34:28 2026 -- 00001_products.sql
2026/11/27 20:34:28     Fri Nov 27 15:34:28 2026 -- 00002_orders.sql
2026/11/27 20:34:28     Pending                  -- 00003_orders_status.sql
```

Faqat `id`, `customer`, `note` bor. `00003` esa `Pending`.
`Applied At` sanasi baza vaqt mintaqasiga, har qator boshidagi vaqt CLI muhitiga bogʻliq; bu yozuvlarda ular farq qiladi.
`-- +goose NO TRANSACTION` yozilgan faylda odatiy kafolat ishlamaydi: xatodan oldingi buyruqlar saqlanib qolishi mumkin.
Bu darsdagi fayllarda shu belgi yoʻq.

## Qoʻllanmagan faylni tuzatish

Qoida: biror bazaga qoʻllangan migratsiya faylini oʻzgartirmang. Goose mazmun oʻzgarganini tekshirmaydi va uni oʻzicha qayta bajarmaydi.
Aks holda turli bazalar bir raqam ostida turli sxemaga ega boʻladi. Oʻzgarish uchun yangi raqamli fayl yozing.
Bu uchinchi fayl hali hech bir bazaga qoʻllanmagan, shuning uchun uni tuzatamiz:

```sql filename="migrations/00003_orders_status.sql" showLineNumbers
-- +goose Up
ALTER TABLE orders
    ADD COLUMN status text NOT NULL DEFAULT 'yangi' CHECK (status <> '');

-- +goose Down
ALTER TABLE orders DROP COLUMN status;
```

Yangi qism — 3-qator. `DEFAULT 'yangi'` mavjud buyurtmalarga ham qiymat beradi; yangi yozuvda status berilmasa ham shu qiymat ishlaydi.
`yangi` — status qiymati. `CHECK (status <> '')` boʻsh matnni rad etadi; bu `NOT NULL`dan alohida qoida.
Endi nechta fayl qoʻllanadi? **A)** uchalasi · **B)** faqat 3 · **C)** hech biri.

<details>
<summary>Javob</summary>

**B.** Birinchi ikki fayl saqlangan. Uchinchi xatodan keyin qoʻllanmagan boʻlib qolgan; uni tuzatib qayta urinamiz.

</details>


## Down: oxirgi migratsiyani qaytarish

`goose down` oxirgi qoʻllangan migratsiyaning `Down` boʻlimini bajaradi. Versiya 3 boʻlsa, nechta fayl qaytadi?

## Chuqurroq (ixtiyoriy): SQL binary ichida

Serverda alohida goose buyrugʻi boʻlmasligi mumkin. Go fayllarni kompilyatsiyada binary ichiga joylaydi.
`migrate.go` faylidan parcha; bu alohida dastur emas:

```go
//go:embed migrations/*.sql
var files embed.FS
```

1-qator — `//go:embed` direktivasi. `migrations/*.sql` shu papkadagi SQL fayllarni tanlaydi; `*` nomning oʻzgaruvchi qismi.
2-qator — `var` `files` oʻzgaruvchisini `embed.FS` turida eʼlon qiladi. Bu tur ichiga joylangan fayllarni oʻqiydi; toʻliq faylda `embed` import qilingan.

Raqamlangan SQL fayllar binary bilan birga yuradi. Fayl oʻzgarsa, binary qayta qurilishi kerak.
Papkadagi `NewProvider` goose'ni kutubxona sifatida ishlatadi va Postgres sessiya qulfi bilan bir nechta nusxani muvofiqlashtiradi.
Kutubxona API'si va deploy paytida chaqirish [GB-8.06](/lab/youtube/gb#gb-8-06)da; hozir tayyor `migrate.go`ni testlar orqali ishlatamiz.

## Koʻp uchraydigan xatolar

1. **Qoʻllangan faylni tahrirlash.** Goose versiyani koʻradi, mazmun farqini emas. Yuqoridagi ikkinchi `up` bunga yangi ish bermaydi. Tuzatish: yangi raqamli fayl.
2. **Maʼlumotli jadvalga DEFAULT'siz NOT NULL.** Yuqoridagi toʻliq xato `23502`; `00003`dagi `DEFAULT 'yangi'` mavjud qatorlarga qiymat beradi.
3. **NULL bilan boʻsh matnni tenglashtirish.** `NOT NULL` `''`ni taqiqlamaydi. `CHECK (status <> '')`ni ham yozing.
4. **Down maʼlumotni tiklaydi deb oʻylash.** `DROP COLUMN` eski statuslarni oʻchiradi. Qayta Up faqat DEFAULT'ni tiklaydi.
5. **Bir fayldagi xatoni barcha fayllarning qaytishi deb tushunish.** 3-fayl xatosidan keyin 1 va 2 qoʻllanganicha qoladi. Transaction chegarasi — bitta fayl.

## Oʻzingizni tekshiring

**1.** Goose qoʻllangan versiyalarni qayerda saqlaydi? Nega ikkita faylga uchta yozuv bor?

<details>
<summary>Javob</summary>

`goose_db_version` jadvalida. `0` boshlangʻich yozuv, `1` va `2` fayl versiyalari.

</details>

**2.** Nega xato bergan migratsiya jadvalni yarim oʻzgartirmaydi? Istisnosi nima?

<details>
<summary>Javob</summary>

Odatda bitta fayl bitta transaction ichida. Xatoda shu fayl qaytadi. `NO TRANSACTION` bu himoyani oʻchiradi.

</details>

**3.** Versiya 3. `goose down`, keyin `goose up`. **A)** 1–3 qayta ishlaydi · **B)** faqat 3 qaytib, yana qoʻllanadi · **C)** up xato beradi.

<details>
<summary>Javob</summary>

**B.** Down oxirgi faylni qaytaradi; Up yana qoʻllanmagan 3-faylni koʻradi. Eski status maʼlumotlari qaytmaydi.

</details>

**4.** GB-5.03: `CHECK (price > 0)` boʻlsa, narxi `0` qator saqlanadimi?

<details>

</details>

<summary>Javob</summary>

`00003`dagi shaklni yangi jadval va ustun nomiga qoʻllang. `boshqa` — standart kategoriya:

```sql filename="solution/migrations/00004_products_category.sql" showLineNumbers
-- +goose Up
ALTER TABLE products
    ADD COLUMN category text NOT NULL DEFAULT 'boshqa' CHECK (category <> '');

-- +goose Down
```
