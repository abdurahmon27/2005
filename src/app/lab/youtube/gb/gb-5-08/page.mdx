## Nimani oʻrganasiz

Oʻrikdan bitta qoldi. Ikki xaridor sotib olishni bosdi, ikkalasiga ham «olindi» dedik. Bazada qoldiq `0`, xato yoʻq. Ikkinchi kamaytirish qayerga ketdi?

**Bitta gʻoya:** transaction oʻzi alohida oʻqish, tekshirish va yozishni boshqa xaridordan himoyalamaydi. Qoldiq shartini `UPDATE`ga qoʻshing yoki qaror uchun oʻqishdan oldin qatorni qulflang.

Darsdan keyin siz:

- ikkita baza ulanishida **yoʻqolgan yangilanish**ni (lost update) qayta yaratasiz;
- qoldiq tekshiruvi va kamaytirishni bitta shartli `UPDATE`ga birlashtirasiz;
- `SELECT … FOR UPDATE`ni `tx` orqali ishlatib, kim kutishini tushuntirasiz;
- parallel xaridorlarni tekshirib, promo-kod vazifasini tuzatasiz.

| Soʻz | Sodda maʼnosi | Inglizcha atama |
|---|---|---|
| yoʻqolgan yangilanish | ikki xaridor bir xil eski qoldiqdan hisoblaydi; bitta kamaytirish yoʻqoladi | lost update |
| shartli UPDATE | qatorni tekshirish va oʻzgartirish bitta SQL buyrugʻida | conditional UPDATE |
| qator qulfi | zid yozuvlar va qulfli oʻqishlar transaction tugashini kutadi | row-level lock |

**Ortiqcha sotuv** (overselling) — bor qoldiqdan koʻproq xaridni qabul qilish. `CommandTag` — `Exec` qaytaradigan natija yozuvi; `RowsAffected()` undan qator sonini oladi.

## Nega BEGIN oʻqi–tekshir–yozni tuzatmaydi?

Postgres standarti — **READ COMMITTED**. Bu izolyatsiya darajasi transaction'lar orasida nimalar koʻrinishini belgilaydi. Oddiy `SELECT` boshqa transaction'larning soʻrov boshlanishidan oldin tasdiqlangan maʼlumotini koʻradi. Oʻz transaction'ining oldingi yozuvlarini ham koʻradi.

B A tasdiqlashidan oldin oʻqidi. Keyingi `UPDATE` yangi buyruq, lekin `SET stock = 0` B'ning eski Go oʻzgaruvchisidan hisoblangan qiymatni yozadi. Kamaytirish bazadagi qiymatdan qayta hisoblanmaydi. READ COMMITTED'da zid yangilash kutib, keyin qatorning yangiroq nusxasiga ishlashi mumkin. Keyingi boʻlim shu qoidaga tayanadi.

Bu bazadagi yoʻqolgan yangilanish; GB-4.07 dagi xotira xatosiga bogʻliq. Bu Go xotirasida data race borligini isbotlamaydi. Go race detector'i bu SQL biznes qoidasini tekshirmaydi.

Koʻrsatish uchun berilgan toʻliq `naive.go` quyida. U `Store` va xato qiymatlari joylashgan `store.go` bilan birga `bozor` paketiga kiradi. Bu alohida `main` dasturi emas.

```go filename="naive.go" showLineNumbers
package bozor

import (
	"context"
	"errors"

	"github.com/jackc/pgx/v5"
)

// buyNaive — videoning birinchi, XATO versiyasi: transaction bor, lekin oʻqish va yozish orasida qulf yoʻq.
// Ikki xaridor bir xil eski qoldiqni oʻqib, ikkalasi ham yozadi (lost update). Faqat koʻrsatish uchun (naive_test.go): ishlatmang.
func (s *Store) buyNaive(ctx context.Context, id int64, qty int) error {
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return err
	}
	defer tx.Rollback(ctx)

	var stock int
	err = tx.QueryRow(ctx,
		"SELECT stock FROM products WHERE id = $1", id).Scan(&stock)
	if errors.Is(err, pgx.ErrNoRows) {
		return ErrNotFound
	}
	if err != nil {
		return err
	}
	if stock < qty {
		return ErrNotEnoughStock
	}
	_, err = tx.Exec(ctx,
		"UPDATE products SET stock = $1 WHERE id = $2", stock-qty, id)
	if err != nil {
		return err
	}
	return tx.Commit(ctx)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1, 3–8 | `package`, `import` | `bozor` paketiga kiradi; context, xato tekshiruvi va pgx'ni import qiladi |
| 10–12 | izoh va `buyNaive` | koʻrsatish metodi; `s *Store` receiver, `id` mahsulot, `qty` dona soni |
| 13–17 | `Begin`, xato shoxi, kechiktirilgan rollback | `tx`ga bitta ulanish oladi; boshlash xatosini qaytaradi; har chiqish uchun rollback rejalaydi |
| 19–21 | `var stock int`; `QueryRow(...).Scan(&stock)` | bitta qoldiqni `&stock` manziliga oʻqiydi; `$1` — `id` |
| 22–27 | `errors.Is`; `if err != nil` | qator yoʻqligini `ErrNotFound`ga aylantiradi; boshqa oʻqish xatosini qaytaradi |
| 28–30 | `stock < qty` | eslab qolingan qoldiq yetmasa `ErrNotEnoughStock` qaytaradi |
| 31–32 | `_, err = tx.Exec(...)` | `_` bilan natija yozuvini tashlaydi; `stock-qty`ni `$1`, `id`ni `$2` qilib yozadi |
| 33–36 | xato shoxi; `tx.Commit(ctx)` | yozish xatosini qaytaradi yoki tasdiqlaydi; commit xatosi chaqiruvchiga yetadi |

Boʻsh qator va `//` izohlar bajarilishga taʼsir qilmaydi. `:=` oʻzgaruvchi yaratadi; `=` boriga qiymat beradi. Nuqta metodni tanlaydi; qavs chaqiradi, jingalak qavslar blok chegarasini belgilaydi, `return` metoddan chiqadi. Bu yozilishlar oldingi darslarda bor.

`buyNaive` ataylab faqat musbat xaridni koʻrsatadi; unda `qty <= 0` himoyasi yoʻq. Ikkala yakuniy metod notoʻgʻri miqdorni rad etadi. Transaction shu xaridor yozuvlarini birga tasdiqlaydi yoki bekor qiladi. U oldin oʻqilgan qoldiqni shu xaridorga band qilmaydi.

Test qoldiq 5 boʻlganda 20 xaridorni boshlaydi. Berilgan yordamchi funksiyadan qisqartirilgan markaziy sikl:

```go
errs := make([]error, 20)
var wg sync.WaitGroup
for i := range errs {
	wg.Go(func() {
		errs[i] = store.Buy(ctx, 4, 1)
	})
}
wg.Wait()
```

`make([]error, 20)` 20 natija joyini ajratadi. `i` — joy indeksi; `wg.Go` funksiyani goroutine'da boshlaydi. Har biri faqat `errs[i]`ga yozadi. Har aylanishning alohida `i`si bor. `wg.Wait()` hammani kutadi. Chaqiruvchi `nil`ni muvaffaqiyat deb sanaydi, rad etilgan xaridor uchun `ErrNotEnoughStock`ni qabul qiladi. `WaitGroup` toʻliq [GB-7.01](/lab/youtube/gb#gb-7-01)da oʻtiladi.

## 1-tuzatish: tekshiruv va kamaytirish bitta UPDATE'da

Qoida bitta SQL shartiga sigʻadi:

```sql
UPDATE products
SET stock = stock - 1
WHERE id = 4 AND stock >= 1;
```

`SET` qatorning hozirgi qoldigʻidan hisoblaydi. `AND` id mosligini ham, kamida bir dona borligini ham talab qiladi. `UPDATE` transaction tugaguncha zid yozuvchilarga qarshi qator qulfini ushlaydi. Mos kelmagan qator yangilanmaydi.

Qoldiqni bittaga tiklang. A boshlaydi va kamaytiradi, lekin transaction'ni ochiq qoldiradi. B shu shartli buyruqni yuborib kutadi. A tasdiqlagach B nima qaytaradi?

**A)** `UPDATE 1`, qoldiq `-1` · **B)** `UPDATE 0` · **C)** CHECK xatosi.

<details>
<summary>Javob</summary>

**B.** Kutishdan keyin Postgres `WHERE`ni yangilangan qatorga qayta tekshiradi. Qoldiq nol, `stock >= 1` yolgʻon. Hech narsa kamaymaydi. A shartni eʼtiborsiz qoldiradi; C kamaytirish qator tanlanishidan oldin boʻladi deb hisoblaydi.

</details>

`shartli` shu holatni tanlaydi. Yordamchi dastur A tasdiqlaguncha B ikki soniya javob bermasligini tekshiradi. `kutyapti = True` — kutmoqda; bu qatorni Postgres emas, yordamchi dastur chiqaradi.

```console

-------

(1 row)

[A] BEGIN;
BEGIN

[A] UPDATE products SET stock = stock - 1 WHERE id = 4 AND stock >= 1;

[B] UPDATE products SET stock = stock - 1 WHERE id = 4 AND stock >= 1;
(2 soniya javob yoʻq: kutyapti = True)

[A] COMMIT;
COMMIT

[B] (kutgan buyruqning javobi)

oxirgi: stock 
-------

(1 row)
```

| Payt | A | B | Tasdiqlangan ishlar boʻyicha qoldiq |
|---|---|---|---|
| A yangiladi | qator qulfi bor; tasdiqlanmagan `0` | | `1` |
| B yangilamoqda | hali ochiq | A'ni kutadi | `1` |
| A tasdiqladi | qulf ochildi | `0 >= 1`ni qayta tekshirdi; nol qator yangiladi | `0` |

`store.go`dagi Go metodi, parcha sifatida:

```go
func (s *Store) Buy(ctx context.Context, id int64, qty int) error {
	if qty <= 0 {
		return ErrInvalidQuantity
	}
	tag, err := s.pool.Exec(ctx,
		"UPDATE products SET stock = stock - $1 WHERE id = $2 AND stock >= $1", qty, id)
	if err != nil {
		return err
	}
	if tag.RowsAffected() == 0 {
		return ErrNotEnoughStock
	}
	return nil
}
```

`qty <= 0` SQL'dan oldin `ErrInvalidQuantity` qaytaradi. `Exec` `tag`, yaʼni `CommandTag`, hamda `err`ni qaytaradi. Avval SQL xatosini qaytaring, keyin `tag.RowsAffected()`ni tekshiring. Nol — hech qaysi qator yangilanmagan. Bu yerda mahsulot bor deb faraz qilib, `ErrNotEnoughStock` qaytaramiz; yoʻq id ham nol beradi.

`$1` ikki marta yozilgan, lekin bitta `qty` parametri. `$2` — `id`. `nil` muvaffaqiyatni bildiradi. Bu bitta buyruq oʻzining avtomatik transaction'ida bajariladi. Ajratilgan qoldiq kamaytirish uchun alohida `Begin` kerak emas. Bir nechta yozuvli toʻliq buyurtmaga GB-5.07 dagi transaction hali kerak.

Oldingi ishchi papkada `store.go`ni `_video/stages/02-store.go` bilan almashtiring. Testdagi oʻsha boʻsh qator qolsin. Bashorat: **A)** ortiqcha sotuv qoladi · **B)** roppa-rosa 5 muvaffaqiyat · **C)** hamma rad etiladi.

</details>

## 2-tuzatish: tx ichida SELECT FOR UPDATE

Qaror uchun qatorni avval Go'ga oʻqish kerak boʻlsa, oʻqishda qulflang:

```sql
SELECT stock FROM products WHERE id = 4 FOR UPDATE;
```

`FOR UPDATE` tanlangan qatorni qulflaydi. Boshqa transaction yozuvlari yoki zid qulfli oʻqishlari kutadi. **Oddiy SELECT mumkin**: u koʻrinadigan tasdiqlangan maʼlumotni oʻqiydi. Qulf hamma oʻquvchini kutdirmaydi.

| Qadam | A | B |
|---|---|---|
| 1 | `BEGIN`; qulfli oʻqish `1` berdi | `BEGIN` |
| 2 | qator qulfini ushlab turibdi | `SELECT … FOR UPDATE` kutadi |
| 3 | `0` yozdi; `COMMIT` | A tugashini kutadi |
| 4 | tugadi | yangilangan qatorni qulflab, `0` oʻqidi; xaridni rad etdi |

A tasdiqlagach B'ning qulfli oʻqishini bashorat qiling: **A)** eski `1` · **B)** hozirgi `0` · **C)** doim xato.

<details>
<summary>Javob</summary>

Bu READ COMMITTED tajribasida **B**. Oʻqish kutib, keyin yangilangan qatorni qaytaradi. Go tekshiruvi qoldiq yetmasligini koʻradi. Boshqa izolyatsiya darajalarida parallel oʻzgarish transaction'ni qayta urinishni talab qilishi mumkin.

</details>

```go filename="store.go" showLineNumbers
package bozor

import (
	"context"
	"errors"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

// ErrNotFound — jadvalda bunday mahsulot yoʻq (GB-2.08, GB-5.05).
var ErrNotFound = errors.New("mahsulot topilmadi")

// ErrNotEnoughStock — omborda yetarli qoldiq yoʻq (GB-5.07).
var ErrNotEnoughStock = errors.New("qoldiq yetarli emas")

// ErrInvalidQuantity — miqdor noldan katta boʻlishi kerak (GB-5.07: manfiy miqdor qoldiqni oshirib yuborar edi).
var ErrInvalidQuantity = errors.New("miqdor noldan katta boʻlishi kerak")

// Store — Postgres'dagi bozor jadvallariga Go'dan kirish (GB-5.05).
type Store struct {
	pool *pgxpool.Pool
}

// Buy id mahsulotdan qty dona sotadi. Tekshiruv va kamaytirish bitta UPDATE buyrugʻida:
// "WHERE stock >= $1" shart bajarilmasa qator oʻzgarmaydi va RowsAffected() nol boʻladi.
// Bu darsda id mavjud deb faraz qilinadi: nol qator "qoldiq yetmaydi" degani (mavjud boʻlmagan id ham nol qator beradi;
// ikkisini ajratish uchun alohida SELECT kerak, BuyLocked esa ErrNoRows orqali ErrNotFound beradi).
func (s *Store) Buy(ctx context.Context, id int64, qty int) error {
	if qty <= 0 {
		return ErrInvalidQuantity
	}
	tag, err := s.pool.Exec(ctx,
		"UPDATE products SET stock = stock - $1 WHERE id = $2 AND stock >= $1", qty, id)
	if err != nil {
		return err
	}
	if tag.RowsAffected() == 0 {
		return ErrNotEnoughStock
	}
	return nil
}

// BuyLocked ham sotadi, lekin boshqacha: avval qatorni FOR UPDATE bilan qulflaydi, qoldiqni Go'da tekshiradi,
// keyin yozadi. Qulf transaction tugaguncha turadi, shuning uchun boshqa xaridorning FOR UPDATE'i yoki UPDATE'i shu qatorni kutadi (oddiy SELECT kutmaydi).
func (s *Store) BuyLocked(ctx context.Context, id int64, qty int) error {
	if qty <= 0 {
		return ErrInvalidQuantity
	}
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return err
	}
	defer tx.Rollback(ctx)

	var stock int
	err = tx.QueryRow(ctx,
		"SELECT stock FROM products WHERE id = $1 FOR UPDATE", id).Scan(&stock)
	if errors.Is(err, pgx.ErrNoRows) {
		return ErrNotFound
	}
	if err != nil {
		return err
	}
	if stock < qty {
		return ErrNotEnoughStock
	}
	_, err = tx.Exec(ctx,
		"UPDATE products SET stock = $1 WHERE id = $2", stock-qty, id)
	if err != nil {
		return err
	}
	return tx.Commit(ctx)
}
```

1–23-qatorlardagi umumiy eʼlonlar paketlarni import qiladi, `errors.New` bilan uchta sentinel xato yaratadi va `pool *pgxpool.Pool`li `Store`ni belgilaydi. `ErrNotFound` — mahsulot yoʻq; `ErrNotEnoughStock` — qoldiq yetmaydi; `ErrInvalidQuantity` — musbat miqdor kerak. Har biri chaqiruvchi `errors.Is` bilan taniydigan bitta xato qiymati. 29–42-qatorlar yuqorida tushuntirilgan shartli metod.

Faqat `BuyLocked`ning yangi qismlari:

| Qator | Kod | Nima qiladi |
|---|---|---|
| 46–49 | metod va miqdor himoyasi | `Buy` bilan bir xil kirish va notoʻgʻri miqdor qoidasi |
| 50–54 | `Begin`; kechiktirilgan rollback | oʻqish va yozishni bitta transaction ulanishida saqlaydi |
| 56–58 | `tx.QueryRow(... FOR UPDATE).Scan(&stock)` | qulf oladi va qoldiqni oʻqiydi |
| 59–64 | qator yoʻqligi va boshqa xato shoxlari | `pgx.ErrNoRows`ni `ErrNotFound`ga aylantiradi; boshqasini saqlaydi |
| 65–67 | qoldiq tekshiruvi | qator qulfi hali ushlab turilganida xaridni rad etadi |
| 68–72 | `tx.Exec`; xato tekshiruvi | qulf ostida hisoblangan qoldiqni yozadi |
| 73 | `tx.Commit(ctx)` | yozuvni tasdiqlab, transaction'ni tugatadi |

`Begin`dan keyingi har erta chiqishda kechiktirilgan rollback bajariladi. Muvaffaqiyatli commit ham transaction'ni tugatadi. Keyingi kechiktirilgan rollback `ErrTxClosed` beradi; bu andoza uni eʼtiborsiz qoldiradi.

## Koʻp uchraydigan xatolar

**1. FOR UPDATE'ni pool orqali yuborish.** Bu klassik jim xato. `tx := … Begin`dan keyin `BuyLocked`dagi faqat oʻqishni shunga almashtiring:

```go
var stock int
err = s.pool.QueryRow(ctx,
	"SELECT stock FROM products WHERE id = $1 FOR UPDATE", id).Scan(&stock)
```

Bu `_video/stages/04-store-pool-mistake.go`dagi parcha. `pool.QueryRow` `tx` band qilgan ulanish oʻrniga alohida ulanish oladi. Uning avtomatik transaction'i shu buyruq bilan tugaydi. Keyingi `tx.Exec`dan oldin qator qulfi ochiladi. Demak, `FOR UPDATE` soʻzlari butun operatsiyani himoyalamaydi.

Testni bashorat qiling: **A)** FOR UPDATE borligi uchun PASS · **B)** FAIL, ortiqcha muvaffaqiyat · **C)** doim panic.

<details>
<summary>Javob</summary>

Tekshiruvimizda **B**. Buyruq toʻgʻri, shuning uchun SQL sintaksis xatosi yoki panic shart emas. Oʻqish qulfi boshqa transaction'dagi yozuvni qamramaydi.

</details>

**2. BEGIN'ni qoldiqni band qilish deb olish.** Naive misol bu jim xatoni koʻrsatdi. Oʻqishdan oldin qulflang yoki shart va kamaytirishni birlashtiring.

**3. Faqat CHECK eski qiymat yozilishini ushlaydi deb oʻylash.** Ikkala xaridor nol yozsa, `CHECK (stock >= 0)` oʻtadi. Himoyasiz *nisbiy* kamaytirish nol ostiga tushsa, xato beradi. Yordamchining `check` holati avval qoldiqni nol qiladi; toʻliq chiqishi:

`violates check constraint` — yangi qator nomlangan qoidani buzdi. `DETAIL` rad etilgan qatorni koʻrsatadi: 4-mahsulot, oʻrik, narx `3500000` tiyin, qoldiq `-1`, faol `t` — true. Xato buyruqdan keyin qoldiq nol qoladi. Constraint oxirgi himoya boʻlib qolsin. Kutiladigan «qoldiq yetmaydi» natijasi uchun shartli qoidani ishlating.

**4. Aloqasiz ish paytida qulf ushlash.** Transaction'ni tez tugating; qoldiq qatori qulflanganda tarmoq chaqiruvlarini qilmang. Bir nechta mahsulot qulflansa, doim bir xil tartibda oling. Bu transaction'lar bir-birini kutadigan deadlock xavfini kamaytiradi. Postgres ulardan bittasini toʻxtatadi; chaqiruvchi bu xatoni qayta ishlashi kerak.

```go filename="solution/coupon.go" showLineNumbers
package bozor

import (
	"context"
	"errors"

	"github.com/jackc/pgx/v5"
)

// ErrCouponUsedUp — promo-kodning ishlatish soni tugagan.
var ErrCouponUsedUp = errors.New("promo-kod tugagan")

// ErrCouponNotFound — bunday promo-kod yoʻq.
var ErrCouponNotFound = errors.New("promo-kod topilmadi")

// UseCoupon promo-kodni bir marta ishlatadi: coupons.uses_left bittaga kamayadi.
// Tekshiruv va kamaytirish bitta UPDATE buyrugʻida (WHERE uses_left > 0): parallel chaqiruvlarda ham roppa-rosa uses_left marta oʻtadi.
func (s *Store) UseCoupon(ctx context.Context, code string) error {
	tag, err := s.pool.Exec(ctx,
		"UPDATE coupons SET uses_left = uses_left - 1 WHERE code = $1 AND uses_left > 0", code)
	if err != nil {
		return err
	}
	if tag.RowsAffected() == 1 {
		return nil
	}
	// Nol qator: promo-kod yoʻq yoki tugagan. Qaysi biri ekanini alohida oʻqib bilamiz.
	var left int
	err = s.pool.QueryRow(ctx,
		"SELECT uses_left FROM coupons WHERE code = $1", code).Scan(&left)
	if errors.Is(err, pgx.ErrNoRows) {
		return ErrCouponNotFound
	}
	if err != nil {
		return err
	}
	return ErrCouponUsedUp
}

var errUseCouponLockedTODO = errors.New("UseCouponLocked hali yozilmagan")

// UseCouponLocked ham promo-kodni ishlatadi, lekin boshqacha: qatorni FOR UPDATE bilan qulflaydi, Go'da tekshiradi, keyin yozadi.
func (s *Store) UseCouponLocked(ctx context.Context, code string) error {
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return err
	}
	defer tx.Rollback(ctx)

	var left int
	err = tx.QueryRow(ctx,
		"SELECT uses_left FROM coupons WHERE code = $1 FOR UPDATE", code).Scan(&left)
	if errors.Is(err, pgx.ErrNoRows) {
		return ErrCouponNotFound
	}
	if err != nil {
		return err
	}
	if left == 0 {
		return ErrCouponUsedUp
	}
	_, err = tx.Exec(ctx,
		"UPDATE coupons SET uses_left = $1 WHERE code = $2", left-1, code)
	if err != nil {
		return err
	}
	return tx.Commit(ctx)
}
```

Yangi nomlar: `code` promo-kodni aniqlaydi, `left` qolgan ishlatishlarni saqlaydi. `ErrCouponUsedUp` — promo-kod tugagan; `ErrCouponNotFound` — promo-kod topilmadi. 19–26-qatorlar himoyalangan kamaytirish va muvaffaqiyatni bajaradi. 28–37-qatorlar nol qator sababini aniqlaydi. 44–67-qatorlar transaction andozasini takrorlab, `left == 0`ni qator qulfi ostida tekshiradi. 40-qator test uchun asl ixtiyoriy boʻsh metod xatosini saqlaydi. Yozilgan metod endi uni qaytarmaydi.

</details>
