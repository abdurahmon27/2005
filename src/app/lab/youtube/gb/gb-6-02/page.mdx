## Nimani oʻrganasiz

Mijoz mahsulot narxini matn qilib yubordi. Nega javobda ichki Go turi — `productInput.price of type int64` koʻrindi?

**Bitta gʻoya:** bitta xatoning ikki yoʻli bor. Server toʻliq matnni log'ga yozadi; `problemFor` status va mijozga mos matnni tanlaydi. Soʻrov ID'si ikkalasini bogʻlaydi.

Dars oxirida siz:

- eski xato shaklini RFC 9457 problem details bilan almashtirasiz;
- oʻralgan xatolarni `errors.Is` va `errors.As` bilan tanib, ichki matnni javobdan olib tashlaysiz;
- javobni log qatorlari bilan bogʻlaysiz va unutilgan `return`ni topasiz;
- yetishmagan 422 va 413 holatlarini qoʻshib, vazifa testlarini oʻtkazasiz.

## Standart javob: problem details

**Problem details** — RFC 9457 belgilagan JSON xato shakli. Hujjatni internet standartlari tashkiloti IETF chiqargan. `application/problem+json` JSON sintaksisini saqlab, aynan shu xato shaklini bildiradi.

| Aʼzo | Ushbu API'dagi maʼnosi |
|---|---|
| `type` | xato turining URI identifikatori; `about:blank` statusdan ortiq maʼno qoʻshmaydi |
| `title` | tur haqida qisqa taʼrif; `about:blank` uchun status nomi |
| `status` | haqiqiy HTTP statusining nusxasi |
| `detail` | mijoz muammoni tuzatishi uchun aynan shu holatning ochiq izohi |
| `errors` | bizning kengaytmamiz: maydon nomi → validatsiya xabari |
| `request_id` | bizning kengaytmamiz: `X-Request-Id`dagi qiymat |

URI turni aniqlaydi. U ochiladigan sahifa boʻlishi shart emas, lekin hujjat sahifasi tavsiya qilinadi. Absolute URI afzal; nisbiy URI toʻliq yoʻlni oʻz ichiga olsin: `/problems/insufficient-stock` kabi. Mijoz dasturi `detail`ni tahlil qilish oʻrniga kengaytmadan tuzilmali maʼlumot olsin. Qoldiq soni kerak boʻlsa, API `available` va `requested` kengaytmalarini belgilashi mumkin.

Quyidagilar `cmd/api/problem.go`dan boʻlaklar; toʻliq fayl pastda:

```go
type problem struct {
	Type      string            `json:"type"`
	Title     string            `json:"title"`
	Status    int               `json:"status"`
	Detail    string            `json:"detail,omitempty"`
	Errors    map[string]string `json:"errors,omitempty"`
	RequestID string            `json:"request_id,omitempty"`
}

// newProblem — maxsus turi yoʻq xato: type "about:blank", title esa statusning standart nomi
// (RFC 9457 §4.2.1: about:blank boʻlsa title — HTTP status nomi).
func newProblem(status int, detail string) problem {
	return problem{
		Type:   "about:blank",
		Title:  http.StatusText(status),
		Status: status,
		Detail: detail,
	}
}

// writeProblem — har xato javobi shu funksiyadan chiqadi: sarlavha → status → body (GB-4.03 tartibi),
// media turi application/problem+json. request_id — GB-6.01'dagi requestID qoʻygan X-Request-Id: mijoz uni
// aytsa, log'dagi qatorni topamiz. (Middleware'siz, testda, sarlavha boʻsh: omitempty uni tashlaydi.)
func writeProblem(w http.ResponseWriter, p problem) {
	p.RequestID = w.Header().Get("X-Request-Id")
	w.Header().Set("Content-Type", "application/problem+json")
	w.WriteHeader(p.Status)
	json.NewEncoder(w).Encode(p) // Encode xatosi: log'ga yozish GB-8.02'da (writeJSON kabi)
}
```

| Boʻlakdagi qator | Kod | Nima qiladi |
|---|---|---|
| 1–8 | `type problem struct` | JSON uchun ochiq maydonlar; tag'lar mijoz kalitlarini belgilaydi; `Status` — `int`, boshqa oddiy maydonlar matn |
| 5–7 | `omitempty` | boʻsh `Detail`, `Errors`, `RequestID`ni tashlaydi; `Errors` matndan matngacha map |
| 12–19 | `newProblem` | struct qiymatini qaytaradi; `http.StatusText(status)` nom beradi, masalan 404 uchun `Not Found` |
| 24 | `writeProblem(w, p)` | javob yozuvchisini va problem nusxasini oladi |
| 25 | `p.RequestID = …` | `requestID` qoʻygan javob sarlavhasini oʻqiydi |
| 26–28 | sarlavha → status → kodlash | media turini tanlaydi, statusni yozadi, keyin `p`ni JSON qilib yozuvchiga uzatadi |

Izohlar funksiyalarni tavsiflaydi; qavslar literal va funksiya tanasini yopadi. Tekshirilmagan `Encode` xatosi `writeJSON`dagidek [GB-8.02 · Log](/lab/youtube/gb#gb-8-02)ga qoldirilgan.

`{"error":{"code":…}}` oʻrniga bu obyektni berish eski kelishuvga tayangan mijozlarni buzadi. Oʻzgarishni eʼlon qiling yoki versiya bilan chiqaring.

## Bitta funksiya xatoni javobga aylantiradi

```go
func problemFor(err error) problem {
	var se *store.StockError
	var te *json.UnmarshalTypeError
	switch {
	case errors.Is(err, store.ErrNotFound):
		return newProblem(http.StatusNotFound, "bunday ID'li mahsulot yoʻq")
	case errors.As(err, &se):
		return problem{
			Type:   "/problems/insufficient-stock",
			Title:  "Omborda yetarli emas",
			Status: http.StatusConflict,
			Detail: fmt.Sprintf("%s: omborda %d dona, soʻralgan %d", se.Name, se.Stock, se.Want),
		}
	// VAZIFA (TASK.md): 1) fieldErrors → 422 + errors; 2) store.ErrBadProduct, store.ErrBadQuantity → 422 + productRules;
	// 3) *http.MaxBytesError → 413 — errBadJSON case'idan OLDIN.
	case errors.Is(err, errBadID):
		return newProblem(http.StatusBadRequest, "id butun son boʻlishi kerak")
	case errors.As(err, &te) && te.Field != "":
		return newProblem(http.StatusBadRequest, te.Field+": qiymat turi notoʻgʻri")
	case errors.Is(err, errBadJSON):
		return newProblem(http.StatusBadRequest, "body bitta JSON obyekt boʻlsin, faqat maʼlum kalitlar bilan")
	default:
		return newProblem(http.StatusInternalServerError, "")
	}
}
```

`var se *store.StockError` va `var te *json.UnmarshalTypeError` nishonlarni eʼlon qiladi. `errors.As(err, &se)` topilgan koʻrsatkichni `se`ga yozadi; `&` uning manzilini beradi. `errors.Is` sentinel xatoni oʻralgan holda ham taniydi. Shartsiz `switch` case'larni tartib bilan tekshiradi va birinchi rostini tanlaydi. Bu shaklda `As` ishlatiladi: uning mantiqiy natijasi case'ga mos, topilgan qiymat oldindan eʼlon qilingan nishonga yoziladi. `AsType` ikki qiymat qaytaradi.

| Case | Natija | Sabab |
|---|---|---|
| `ErrNotFound` | 404, biz yozgan matn | mahsulot yoʻq |
| `*StockError` | 409, biz tanlagan tur va nom | `detail`ni ruxsat etilgan `Name`, `Stock`, `Want` maydonlaridan yigʻadi |
| `errBadID` | 400 | yoʻldagi ID butun son emas |
| `Field` boʻsh boʻlmagan tur xatosi | 400, maydonga mos matn | `&&` ikkala shartni talab qiladi; `+` maydon yoʻliga bizning matnni qoʻshadi |
| `errBadJSON` | 400, body haqida umumiy koʻrsatma | qolgan oʻqish xatolarini ushlaydi |
| `default` | 500, boʻsh detail | tanilmagan xato ichki matnni ochmaydi |

`fmt.Sprintf` matn yasaydi: `%s` nomni, `%d` butun sonlarni joylaydi. `VAZIFA` izohlari yetishmagan case'larni belgilaydi; ularni bajarmaydi.

Bu yerda `Field` — `price`. Umumiy holda u xato qiymatgacha boʻlgan yoʻl; har doim bitta aynan JSON kaliti emas. Body yuqori darajada massiv boʻlsa, u boʻsh; soʻrovni umumiy body case'i oladi. `Struct`, `Type` yoki dekoder xatosining toʻliq matnini chiqarmang.

## JSON oʻqishda ikkala xatoni saqlang

`errBadJSON` — API'ning sentinel xatosi. U ham, asl dekoder xatosi ham saqlanishi kerak:

```go filename="cmd/api/json.go" showLineNumbers
package main

// JSON kirish va chiqish (GB-4.06): qat'iy oʻqish va limit. GB-6.02: xato javobi endi problem.go'da.

import (
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"net/http"
)

// writeJSON: sarlavha → status → body (GB-4.03 tartibi).
func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	json.NewEncoder(w).Encode(v) // Encode xatosi: log'ga yozish GB-8.02'da
}

// maxBody — body'ning eng katta hajmi, baytda (GB-4.06).
const maxBody = 1024

// decodeJSON body'ni dst'ga oʻqiydi: eng koʻpi maxBody bayt, nomaʼlum kalit yoʻq, bitta JSON qiymat.
// Xato boʻlsa javobni oʻzi yozadi va false qaytaradi: chaqiruvchi darhol return qiladi.
// GB-6.02: Decode xatosi errBadJSON bilan birga oʻraladi (ikkita %w): problemFor ikkalasini ham koʻradi,
// asl matn esa faqat log'ga boradi.
func decodeJSON(w http.ResponseWriter, r *http.Request, dst any) bool {
	r.Body = http.MaxBytesReader(w, r.Body, maxBody)
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	if err := dec.Decode(dst); err != nil {
		writeError(w, fmt.Errorf("%w: %w", errBadJSON, err))
		return false
	}
	// Decode faqat birinchi JSON qiymatni oʻqiydi: undan keyin hech narsa boʻlmasligi kerak.
	if err := dec.Decode(&struct{}{}); err != io.EOF {
		if err == nil {
			err = errors.New("body'da bitta JSON boʻlishi kerak")
		}
		writeError(w, fmt.Errorf("%w: %w", errBadJSON, err))
		return false
	}
	return true
}
```

| Fayldagi qator | Kod | Nima qiladi |
|---|---|---|
| 1–11 | paket, izoh, import'lar | `encoding/json` JSON bilan ishlaydi; `errors` xato yasaydi, `fmt` oʻraydi, `io` EOF beradi, `net/http` kirishni cheklaydi |
| 14–18 | `writeJSON` | oʻzgarmagan muvaffaqiyatli javob: sarlavha, status, body |
| 21 | `maxBody = 1024` | baytdagi limit |
| 27–30 | `decodeJSON`, reader, decoder | `dst any` — natija manzili; kirishni cheklaydi, nomaʼlum maydonlarni rad etadi |
| 31–34 | birinchi `Decode` | xatoda ikkalasini oʻraydi, javob yozadi va `false` qaytaradi |
| 36 | `dec.Decode(&struct{}{})` | ikkinchi oʻqish EOF'ni tekshiradi; `&struct{}{}` — boʻsh struct qiymatining koʻrsatkichi |
| 37–41 | ikkinchi oʻqish muvaffaqiyatsiz | yana JSON qiymati yoki buzuq davom boʻlsa, oʻsha xato yoʻliga oʻtadi; oʻqish muvaffaqiyatli boʻlsa, xato yasaydi |
| 43–44 | `return true` | faqat oxirigacha toʻgʻri oʻqilgan kirish shu yerga yetadi; yopuvchi qavs funksiyani tugatadi |

Bir nechta `%w` Go 1.20'dan beri ishlaydi. Bu oʻralgan qiymat uchun `errors.Is(err, errBadJSON)` ham, `errors.As(err, &te)` ham rost boʻlishi mumkin:

```text
fmt.Errorf("%w: %w", errBadJSON, decoderError)
  ├─ errBadJSON
  └─ *json.UnmarshalTypeError
```

Aniq tur xatosi umumiy sentinel case'idan oldin tursin. Starter'da oldingi 413 xaritasi ataylab yoʻq; body limiti ishlashda davom etadi. Vazifada uning statusini qaytarasiz. Nomaʼlum maydon xatolari umumiy koʻrsatma oladi; bu kod ularning matnidan kalit nomini ajratmaydi.

## Toʻliq xatoni log'ga, tanlangan javobni mijozga yozing

```go
func writeError(w http.ResponseWriter, err error) {
	p := problemFor(err)
	log.Printf("%s xato %d: %q", w.Header().Get("X-Request-Id"), p.Status, err.Error())
	writeProblem(w, p)
}
```

1-qator `err error` oladi; 2-qator mijozga mos problem'ni tanlaydi. 3-qator ID, status va toʻliq matnni log'ga yozadi. `%q` matnni qoʻshtirnoqqa oladi, yangi qatorni `\n` qilib yozadi. 4-qator problem'ni uzatadi; 5-qator funksiyani yopadi. `err.Error()` faqat log chaqiruvida boʻlsin.

Handler'lar `writeStoreError` oʻrniga shu funksiyani chaqiradi va darhol qaytadi:

```go
	p, err := a.st.Get(id)
	if err != nil {
		writeError(w, err)
		return
	}
```

`p, err :=` mahsulot va xatoni oladi; `if` tarmogʻi xatoni yozib, funksiyadan chiqadi. Statusi oldindan tanlangan middleware toʻgʻridan-toʻgʻri `writeProblem`ni chaqiradi. Masalan, javob boshlanmasdan oldingi recovery:

```go
writeProblem(w, newProblem(http.StatusInternalServerError, ""))
```

`requireJSON` 415 ishlatadi; `muxErrors` mux'ning 404 va 405 javoblarini almashtiradi, `Allow`ni saqlaydi. Javob yozish boshlanganidan keyingi panic'da yangi 500 yozib boʻlmaydi: oldingi recovery kodi javobni uzadi.

## Validatsiya uchun hali case kerak

`validate` endi shu nomli map turini qaytaradi:

```go
type fieldErrors map[string]string

func (f fieldErrors) Error() string {
	return fmt.Sprintf("validatsiya: %d ta maydon notoʻgʻri", len(f))
}
```

1-qator maydon nomidan xabargacha map belgilaydi. 3–5-qatorlar qiymat receiver'i `f`ga `Error() string` metodini qoʻshadi; u `error` talabini bajaradi. `len(f)` notoʻgʻri maydonlarni sanaydi; `%d` sonni formatlaydi. Handler aniq map turining uzunligini tekshirishda davom etadi:

```go
	if f := validate(in); len(f) > 0 {
		writeError(w, f)
		return
	}
```

Qisqa `if` eʼloni `f`ni yaratadi; `len(f) > 0` xatolar borligini bildiradi. `writeError` map'ni `error` sifatida oladi, `return` handler'ni tugatadi. Shu map saqlangan `error` interface'ni nil bilan tekshirmang: ichida nil map boʻlsa ham interface nil emas.

Yangi case qoʻshmasdan oldin, boʻsh nom va nol narx natijasini bashorat qiling.

**A)** 400 · **B)** 422 · **C)** 500

<details>
<summary>Javob</summary>

**C.** `fieldErrors` uchun case yoʻq va u `default`ga tushadi. B — vazifadan keyingi kerakli natija; A toʻgʻri JSON bilan notoʻgʻri qiymatni aralashtiradi.

</details>

```console
$ curl -s localhost:8765/products -H "Content-Type: application/json" -d '{"name":"","price":0}'
```

```console
2026/11/27 22:10:11 LHNSLMJKV5WMB466KDY4XY6RGH POST "/products" 500 84.684µs
```

`detail` yoki ichki matn chiqmaydi, lekin status notoʻgʻri. Toʻliq sabab log'da qoladi. `problemFor` bu xatolarni 422 qiladi degan izohlar starter holatini emas, vazifadan keyingi maqsadni tasvirlaydi.

<summary>Toʻliq cmd/api/problem.go</summary>

```go filename="cmd/api/problem.go" showLineNumbers
package main

// Bir xil API xatolari (GB-6.02): har xato javobi RFC 9457 "problem details" shaklida.
// Qoida: err.Error() — dasturchi uchun matn, u faqat log'ga boradi. Mijoz faqat biz tanlab
// yozgan matnni oladi (detail, errors) va log'dagi qatorni topish uchun request_id'ni.

import (
	"encoding/json"
	"errors"
	"fmt"
	"log"
	"net/http"

	"github.com/abdurahmon27/bozor/internal/store"
)

// problem — RFC 9457 obyekti. type, title, status, detail — standart aʼzolar;
// errors va request_id — bozor'ning kengaytmalari (RFC 9457 §3.2).
type problem struct {
	Type      string            `json:"type"`
	Title     string            `json:"title"`
	Status    int               `json:"status"`
	Detail    string            `json:"detail,omitempty"`
	Errors    map[string]string `json:"errors,omitempty"`
	RequestID string            `json:"request_id,omitempty"`
}

// newProblem — maxsus turi yoʻq xato: type "about:blank", title esa statusning standart nomi
// (RFC 9457 §4.2.1: about:blank boʻlsa title — HTTP status nomi).
func newProblem(status int, detail string) problem {
	return problem{
		Type:   "about:blank",
		Title:  http.StatusText(status),
		Status: status,
		Detail: detail,
	}
}

// writeProblem — har xato javobi shu funksiyadan chiqadi: sarlavha → status → body (GB-4.03 tartibi),
// media turi application/problem+json. request_id — GB-6.01'dagi requestID qoʻygan X-Request-Id: mijoz uni
// aytsa, log'dagi qatorni topamiz. (Middleware'siz, testda, sarlavha boʻsh: omitempty uni tashlaydi.)
func writeProblem(w http.ResponseWriter, p problem) {
	p.RequestID = w.Header().Get("X-Request-Id")
	w.Header().Set("Content-Type", "application/problem+json")
	w.WriteHeader(p.Status)
	json.NewEncoder(w).Encode(p) // Encode xatosi: log'ga yozish GB-8.02'da (writeJSON kabi)
}

// API qatlamining oʻz sentinel xatolari (GB-2.08): decodeJSON va pathID asl xatoni shular bilan oʻraydi.
var errBadJSON = errors.New("body JSON sifatida oʻqilmadi")

var errBadID = errors.New("id butun son emas")

// fieldErrors — validate natijasi: maydon nomi → nima notoʻgʻri. Error() metodi bor, demak u error:
// handler uni boshqa xatolar kabi writeError'ga beradi, problemFor esa 422 qiladi.
type fieldErrors map[string]string

func (f fieldErrors) Error() string {
	return fmt.Sprintf("validatsiya: %d ta maydon notoʻgʻri", len(f))
}

// productRules — 422'da mijozga koʻrsatiladigan katalog qoidalari. Store xatosining matni emas:
// u ichki qatlam matni, ertaga unga boshqa tafsilot qoʻshilishi mumkin.
const productRules = "nom 1–20 belgi, narx 1 tiyindan 10 mln soʻmgacha, qoldiq 0–1 000 000"

// problemFor xatoni mijozga ketadigan problem'ga aylantiradi: status errors.Is/As bilan tanlanadi.
// Hech bir case err.Error()ni ishlatmaydi: detail faqat biz tanlagan maydonlardan yigʻiladi.
// switch birinchi mos case'ni oladi: aniqroq case (413) umumiyroq case'dan (errBadJSON) oldin turadi.
func problemFor(err error) problem {
	var se *store.StockError
	var te *json.UnmarshalTypeError
	switch {
	case errors.Is(err, store.ErrNotFound):
		return newProblem(http.StatusNotFound, "bunday ID'li mahsulot yoʻq")
	case errors.As(err, &se):
		return problem{
			Type:   "/problems/insufficient-stock",
			Title:  "Omborda yetarli emas",
			Status: http.StatusConflict,
			Detail: fmt.Sprintf("%s: omborda %d dona, soʻralgan %d", se.Name, se.Stock, se.Want),
		}
	// VAZIFA (TASK.md): 1) fieldErrors → 422 + errors; 2) store.ErrBadProduct, store.ErrBadQuantity → 422 + productRules;
	// 3) *http.MaxBytesError → 413 — errBadJSON case'idan OLDIN.
	case errors.Is(err, errBadID):
		return newProblem(http.StatusBadRequest, "id butun son boʻlishi kerak")
	case errors.As(err, &te) && te.Field != "":
		return newProblem(http.StatusBadRequest, te.Field+": qiymat turi notoʻgʻri")
	case errors.Is(err, errBadJSON):
		return newProblem(http.StatusBadRequest, "body bitta JSON obyekt boʻlsin, faqat maʼlum kalitlar bilan")
	default:
		return newProblem(http.StatusInternalServerError, "")
	}
}

// writeError — handler'dagi har Go xatosi shu yerdan chiqadi: log'ga toʻliq xato (err.Error()),
// mijozga problemFor tanlagan xavfsiz problem. Ikkalasida bir xil request ID.
// Metod, yoʻl va status logRequests qatorida (GB-6.01); bu qator — xatoning oʻzi. %q: xato matnida
// mijoz yuborgan narsa (yoʻl, kalit) boʻlishi mumkin, yangi qator log'da \n boʻlib qoladi (GB-6.01).
func writeError(w http.ResponseWriter, err error) {
	p := problemFor(err)
	log.Printf("%s xato %d: %q", w.Header().Get("X-Request-Id"), p.Status, err.Error())
	writeProblem(w, p)
}
```

1–18-qatorlar dastur paketini tanlaydi, qoidani izohlaydi va beshta standart paket bilan `store`ni import qiladi. 19–47-qatorlar problem'ni belgilaydi va yozadi. 50 va 52-qatorlar JSON hamda ID sentinel xatolarini yasaydi. 56–60-qatorlar `fieldErrors`ni amalga oshiradi; 64-qator vazifada ishlatiladigan ochiq katalog qoidalari — `productRules`ni belgilaydi. 69–93-qatorlar xatoni javobga aylantiradi; 99–103-qatorlar log va javobni yozadi. Qolganlari izohlar, boʻsh ajratgichlar yoki yopuvchi qavslardir.

</details>

## Koʻp uchraydigan xatolar

Asosiy xato — `detail`ga `err.Error()` yozish. Bu 4xx yoki oʻzbekcha store xatosida ham xato. Oldingi maʼlumot chiqishi sababini koʻrsatdi. Tuzatish: `problemFor`da mijoz matnini tanlang; ichki matnni faqat log'da saqlang.

Ikkinchi xato: `writeError`dan keyin `return`ni unutish. Xatoli nusxadagi metod toʻliq:

```go
func (a *api) getProduct(w http.ResponseWriter, r *http.Request) {
	id, ok := pathID(w, r)
	if !ok {
		return
	}
	p, err := a.st.Get(id)
	if err != nil {
		writeError(w, err)
	}
	writeJSON(w, http.StatusOK, p)
}
```

`pathID` avval notoʻgʻri ID'larni qaytaradi. Keyin `Get(99)` xato va nol qiymatli mahsulot qaytaradi. Xato yozilgach, bajarilish `writeJSON`ga yetadi.

Bashorat: **A)** faqat bitta 404 problem · **B)** 404 problem, keyin nol qiymatli mahsulot · **C)** 500.

<details>
<summary>Javob</summary>

**B.** Xato yozish handler'ni tugatmaydi. Birinchi yakuniy status 404 qoladi, lekin ikkala kodlash ham body'ga qoʻshiladi. A uchun `return` kerak; C avtomatik panic boʻladi deb taxmin qiladi.

</details>

## Uy vazifasi

[Dars papkasidagi TASK.md](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/gb-6-02-api-xatolar) bilan ishlang. Unda uchta majburiy qadamli bitta vazifa bor; murakkablik belgilari ushbu sahifa uchun qoʻyilgan:

1. 🟢 `fieldErrors`ni 422, `/problems/validation` turi, `Qiymatlar notoʻgʻri` nomi va `Errors: fe`ga aylantiring.
2. 🟢 `store.ErrBadProduct` hamda `store.ErrBadQuantity`ni oʻsha 422 turi/nomiga, `Detail: productRules` bilan aylantiring.
3. 🟡 `*http.MaxBytesError`ni 413'ga aylantiring, `errBadJSON`dan oldin. Mijoz matniga `tooBig.Limit`ni kiriting.

`productRules` mazmuni: nom 1–20 belgi, narx 1 tiyindan 10 million soʻmgacha, qoldiq 0–1 000 000. Bir soʻm — 100 tiyin. `var fe fieldErrors` qiymat nishonini va `var tooBig *http.MaxBytesError` koʻrsatkich nishonini eʼlon qiling. `As`ga ularning manzilini bering. `tekshiruv_test.go`ni oʻzgartirmang.

```go
	case errors.As(err, &fe): // vazifa, 1-qadam
		return problem{
			Type:   "/problems/validation",
			Title:  "Qiymatlar notoʻgʻri",
			Status: http.StatusUnprocessableEntity,
			Errors: fe,
		}
	case errors.Is(err, store.ErrBadProduct), errors.Is(err, store.ErrBadQuantity): // vazifa, 2-qadam
		return problem{
			Type:   "/problems/validation",
			Title:  "Qiymatlar notoʻgʻri",
			Status: http.StatusUnprocessableEntity,
			Detail: productRules,
		}
	case errors.As(err, &tooBig): // vazifa, 3-qadam: errBadJSON'dan oldin
		return newProblem(http.StatusRequestEntityTooLarge, fmt.Sprintf("body %d baytdan oshmasin", tooBig.Limit))
```

`fieldErrors` `error`ni qiymat sifatida bajaradi, shuning uchun `*fieldErrors` nishoni bu yerda yaratilgan qiymatlarga mos kelmaydi. Ikkinchi `case`dagi vergul ikkala sentinel'dan biriga ruxsat beradi. Oxirgi case xato matnini ochmasdan, maʼlum limitni oʻqiydi.

`errors` — shu API'ning map kengaytmasi, RFC majbur qilgan shakl emas. Ikkala 422 bir xil problem turini ishlatadi; birida maydon xatolari, boshqasida ochiq qoida izohi bor.
