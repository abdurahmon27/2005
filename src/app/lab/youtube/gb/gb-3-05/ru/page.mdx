## Что вы узнаете

`Store` в bozor прячет товары в слайсе `products` с маленькой буквы, поэтому внешний код до него не дотянется. А `List()` при каждом вызове отдаёт полную копию каталога через `slices.Clone`. Если в каталоге 10 000 товаров и нужный стоит вторым, каждый поиск всё равно копирует весь каталог. Можно ли обойти каталог, не открывая слайс наружу и не копируя его?

**Одна идея:** **итератор** — обычная функция, которая принимает функцию `yield` и отдаёт значения по одному через `yield(v)`. Когда вы пишете `for p := range st.All()`, компилятор превращает тело цикла в функцию и передаёт её итератору как `yield`. Итератор и тело работают **по очереди** в одной цепочке вызовов, промежуточного слайса нет. При `break` функция `yield` возвращает `false`, а остановка — дело итератора.

К концу урока вы:

- напишете для `Store` метод `All() iter.Seq[Product]` и обойдёте каталог через `for p := range st.All()` без доступа к внутреннему слайсу и без копирования;
- увидите в выводе, как итератор и тело цикла работают по очереди, и объясните, как `break` останавливает итератор;
- узнаете, что будет, если не проверять результат `yield` (паника `range function continued iteration …`), и исправите это;
- прочитаете `go doc iter.Seq` и отсортируете ключи map одной строкой `slices.Sorted(maps.Keys(m))`.

Три основных новых слова:

| Слово | Простой смысл | По-английски |
|---|---|---|
| итератор | функция, которая принимает функцию `yield` и отдаёт значения по одному в неё | iterator |
| функция yield | функция, в которую итератор передаёт значение; в цикле `range` её роль выполняет тело цикла | yield function |
| `iter.Seq[V]` | стандартное имя этого типа функции: `func(yield func(V) bool)` | iter.Seq |

Вспомогательные слова объясняются одной фразой там, где встречаются: `slices.Collect`, пакет `iter`, живое представление (live view).

## Проблема: List копирует при каждом вызове

Первый шаг — состояние из GB-2.06 (`_video/00-list`). `main` добавляет в каталог четыре товара и ищет первый, которого мало осталось (остаток меньше 5).

```go filename="_video/00-list/cmd/bozor/main.go" showLineNumbers

	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"

	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 3)

			break
		}
	}

```

| Строка | Код | Что делает |
|---|---|---|
| 10–14 | `var st store.Store` и четыре `st.Add(…)` | пустой каталог и четыре товара: `olma` (остаток 40), `non` (3), `choy` (8), `oʻrik` (2). `1_200_000` — цена в тийинах |

| 17–20 | `if p.Stock < 5 { … break }` | если остаток меньше 5, печатает название и выходит из цикла |

`List` написан так:

```go
func (s *Store) List() []Product {
	return slices.Clone(s.products)
}
```

`slices.Clone` создаёт новую копию всего слайса. Это нужно: даже если внешний код изменит результат `List()`, каталог не пострадает.

```console

```

Результат верный: `non`. Проблема в цене. Поиск закончился на втором товаре, но `List()` сначала скопировал **всё**. При 10 000 товаров каждый поиск копирует 10 000 `Product`. Измерим это чуть позже.

Нужно: отдавать каталог по одному, без копии и не открывая `products`, и чтобы вызывающий мог остановиться там, где захочет.

## Итератор: функция, принимающая yield

Добавим `Store` метод `All` (`_video/01-range`). Он возвращает не слайс, а **функцию**:

```go
func (s *Store) All() func(yield func(Product) bool) {
	return func(yield func(Product) bool) {
		for _, p := range s.products {
			if !yield(p) {
				return
			}
		}
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `func (s *Store) All() func(yield func(Product) bool)` | `All` — метод `*Store` (GB-2.05). Результат — функция. У неё один параметр `yield`, и сам `yield` тоже функция: принимает `Product`, возвращает `bool` (как `keep` из GB-3.04). `yield` — имя параметра, а не ключевое слово: так его называет документация Go |
| 2 | `return func(yield func(Product) bool) {` | эту функцию мы возвращаем как анонимную функцию |
| 3 | `for _, p := range s.products {` | анонимная функция видит внешний `s` (GB-2.09) и обходит `s.products` |
| 4–6 | `if !yield(p) { return }` | каждый `p` отдаётся в `yield`. Если `yield` вернул `false`, делаем `return`: итератор на этом заканчивается |
| 7–9 | `}` `}` `}` | закрываются `if`, `for` и анонимная функция (строка 9 — метод `All`) |

Имя `All` принятое: так называют итератор по всей коллекции (`go doc iter`, «Naming Conventions»). Слайс наружу не выходит. В `yield` попадает **копия** каждого товара: `for _, p := range` делает то же самое (GB-2.01). Копируется один `Product`, а не весь каталог.

**Итератор** — это и есть такая функция: она принимает функцию `yield` и отдаёт значения по одному в неё. Теперь в `main` обойдём результат `All()` через `range`:

```go filename="_video/01-range/cmd/bozor/main.go" showLineNumbers
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 3)
	st.Add("choy", 2_500_000, 8)
	st.Add("oʻrik", 3_500_000, 2)

	for p := range st.All() {
		fmt.Println(p.Name, p.Stock)
	}
}
```

`for p := range st.All()` — с Go 1.23 `range` работает и по такой функции. Компилятор превращает тело цикла (`fmt.Println(p.Name, p.Stock)`) в функцию и передаёт её итератору как `yield`. Если тело дошло до конца, эта функция возвращает `true`: итератор продолжает.

```console
$ ./_video/run.sh 01-range go run ./cmd/bozor
olma 40
non 3
choy 8
oʻrik 2
```

Четыре товара в порядке каталога. Результат такой же, как у `List`, но ни один слайс не копировался.

Что значит «компилятор превращает тело в функцию»? Это можно записать вручную. Этого примера нет в папке курса: скопируйте папку `_video/03-break` и замените только `cmd/bozor/main.go` (`All` там печатает текст на каждом шаге, поэтому вывод можно сравнить с выводом из следующего раздела):

```go
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 3)
	st.Add("choy", 2_500_000, 8)
	st.Add("oʻrik", 3_500_000, 2)

	// for p := range st.All() { … } oʻrniga: iteratorni oddiy funksiya kabi chaqiramiz
	// va sikl tanasini oʻzimiz yield funksiyasi qilib beramiz.
	st.All()(func(p store.Product) bool {
		fmt.Println("sikl:", p.Name)
		if p.Stock < 5 {
			return false // break
		}
		return true // tana oxiriga yetdi
	})
	fmt.Println("sikldan keyin")
}
```

Здесь результат `st.All()` вызывается как обычная функция: `st.All()(…)`. Мы сами передаём ей функцию — тело цикла — в роли `yield`. `return true` — «тело дошло до конца», `return false` — `break`.

```console
$ go run ./cmd/bozor
iterator: olma beraman
sikl: olma
iterator: non beraman
sikl: non
iterator: yield false → toʻxtayman
sikldan keyin
```

Этот вывод совпадает с выводом программы из шага `03-break`, написанной через `for … range` и `break` (увидите в следующем разделе). Значит, `range` — удобная запись этого вызова. Источники: Go wiki «Rangefunc Experiment» и файл компилятора `rewrite.go`: там `break` → `return false`, `continue` → `return true`.

## Итератор и тело цикла работают по очереди

Чтобы увидеть каждый шаг, временно добавим в `All` два `Println`, а тело цикла в `main` печатает «sikl:» («цикл:») и название (`_video/02-iz`):

```go
func (s *Store) All() func(yield func(Product) bool) {
	return func(yield func(Product) bool) {
		for _, p := range s.products {
			fmt.Println("iterator:", p.Name, "beraman")
			if !yield(p) {
				fmt.Println("iterator: yield false → toʻxtayman")
				return
			}
		}
	}
}
```

```go filename="_video/02-iz/cmd/bozor/main.go" showLineNumbers
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 3)
	st.Add("choy", 2_500_000, 8)
	st.Add("oʻrik", 3_500_000, 2)

	for p := range st.All() {
		fmt.Println("sikl:", p.Name)
	}
}
```

Первый `Println` — итератор перед `yield` говорит «beraman» («отдаю»). Второй печатается, только если `yield` вернул `false`: «toʻxtayman» («останавливаюсь»); сейчас `false` не будет. Тело цикла печатает «sikl:» и название товара.

В каком порядке выведутся строки для четырёх товаров?

**A)** сначала четыре строки итератора, потом четыре строки цикла · **B)** итератор, цикл, итератор, цикл, … · **C)** сначала четыре строки цикла, потом итератора

<details>
<summary>Ответ</summary>

**B: по очереди.** Итератор отдаёт `olma` и вызывает `yield`; тело сразу печатает «sikl: olma»; когда `yield` вернулся, итератор переходит к `non`, и так далее. Если вы выбрали **A**, вы решили, что итератор сначала собирает все товары, а потом отдаёт их циклу: нет, ничего не накапливается. В варианте **C** тело работало бы раньше итератора, но значение телу даёт сам итератор.

</details>

```console
$ ./_video/run.sh 02-iz go run ./cmd/bozor
iterator: olma beraman
sikl: olma
iterator: non beraman
sikl: non
iterator: choy beraman
sikl: choy
iterator: oʻrik beraman
sikl: oʻrik
```

На машине это обычные вызовы функций. `main` вызывает итератор; итератор для каждого `p` вызывает `yield`; `yield` — тело цикла, которое сделал компилятор. Если тело дошло до конца, `yield` возвращает `true`, и итератор переходит к следующему `p`.

| Шаг | Кто работает | На экран |
|---|---|---|
| 1 | `main` начинает `range st.All()`: вызывает итератор | — |
| 2 | итератор: `p = olma`, текст перед `yield` | `iterator: olma beraman` |
| 3 | итератор вызывает `yield(p)` — работает тело цикла | `sikl: olma` |
| 4 | тело дошло до конца, `yield` возвращает `true` | — |
| 5 | итератор переходит к `p = non`, шаг 2 повторяется | `iterator: non beraman` … |

Цепочка вызовов в момент, когда работает тело (`p = non`):

```text
main
 └─ итератор (функция внутри All)        p = non
     └─ yield(p)  = тело цикла           «sikl: non»
```

Всё в одной цепочке вызовов: ни очереди, ни промежуточного слайса.

## break: кто останавливает

Теперь ищем первый товар, которого мало осталось: если остаток меньше 5, `break` (`_video/03-break`). Второй товар в каталоге — `non`, остаток 3. После цикла печатаем одну строку.

```go filename="_video/03-break/cmd/bozor/main.go" showLineNumbers
package main

import (
	"fmt"

	"github.com/abdurahmon27/bozor/internal/store"
)

func main() {
	var st store.Store
	st.Add("olma", 1_200_000, 40)
	st.Add("non", 400_000, 3)
	st.Add("choy", 2_500_000, 8)
	st.Add("oʻrik", 3_500_000, 2)

	for p := range st.All() {
		fmt.Println("sikl:", p.Name)
		if p.Stock < 5 {
			break
		}
	}
	fmt.Println("sikldan keyin")
}
```

`All` прежний (с двумя `Println`). Что будет на экране после «sikl: non»?

**A)** `iterator: choy beraman` · **B)** `iterator: yield false → toʻxtayman` · **C)** только `sikldan keyin`

<details>
<summary>Ответ</summary>

**B.** `break` досрочно прерывает тело, и `yield` возвращает `false`. Итератор видит это в `if !yield(p)`, говорит «toʻxtayman» и делает `return`. Только после возврата итератора в `main` выполняется строка после цикла. Если вы выбрали **A**, вы решили, что `break` итератору не сообщается: сообщается, через `false`. **C** значило бы, что итератор молча убирается; но строку «toʻxtayman» печатает сам итератор.

</details>

```console
$ ./_video/run.sh 03-break go run ./cmd/bozor
iterator: olma beraman
sikl: olma
iterator: non beraman
sikl: non
iterator: yield false → toʻxtayman
sikldan keyin
```

`choy` и `oʻrik` не были прочитаны вообще. Последовательность:

```text
break                    в теле цикла
 └─ yield → false        тело возвращается
     └─ if !yield(p)     итератор: return
         └─ range закончился   строка после цикла
```

Значит, `break` сам итератор не останавливает: он только **просит** через `false`. Остановка — дело итератора. Что будет, если итератор этого не сделает, вы увидите в разделе «Частые ошибки».

## Измерение: List и All

Измерим исходную ситуацию: каталог из 10 000 товаров, первый товар с малым остатком стоит вторым; ищем его через `List` и через `All` (`_video/09-olchov`). Бенчмарки разбираются в GB-11.01; сейчас важно только, что измеряется.

## iter.Seq: имя типа функции

Наш тип функции в стандартной библиотеке имеет имя:

```console
$ go doc iter.Seq
package iter // import "iter"

type Seq[V any] func(yield func(V) bool)
    Seq is an iterator over sequences of individual values. When called as
    seq(yield), seq calls yield(v) for each value v in the sequence, stopping
    early if yield returns false. See the iter package documentation for more
    details.
```

Документация: `Seq` — итератор по последовательности значений; при вызове `seq(yield)` он вызывает `yield(v)` для каждого `v` и досрочно останавливается, если `yield` вернул `false`. (Строка `package iter …` и последняя фраза «See the iter package documentation» тоже входят в вывод `go doc`.)

Читаем первую строку:

```go
type Seq[V any] func(yield func(V) bool)
```

- `type Seq` — имя нового типа. `[V any]` в квадратных скобках — **параметр типа** `V`: `Seq` — тип с параметром типа. В GB-3.04 скобки стояли у функции, здесь — у типа.
- Основа — `func(yield func(V) bool)`, точно как у нашей функции. Это похоже на `type OrderStatus int` из GB-2.03: именованный тип, основа — другой тип.
- `Seq[Product]` — `V` заменён на `Product`: именно тот тип, который вернул `All`.

Теперь сделаем результатом `All` тип `iter.Seq[Product]` (`_video/05-seq`; `iter` тоже импортируется):

```go
import (
	"iter"
	"slices"
)
```

```go
func (s *Store) All() iter.Seq[Product] {
	return func(yield func(Product) bool) {
		for _, p := range s.products {
			if !yield(p) {
				return
			}
		}
	}
}
```

Тело не меняется. `iter.Seq[Product]` — именованный тип с основой `func`. Тип анонимной функции безымянный, основа та же: по спецификации Go она напрямую присваивается именованному типу (assignability). Сигнатура сообщает читателю, что это итератор. Результат тот же, что в `01-range`:

```console
$ ./_video/run.sh 05-seq go run ./cmd/bozor
olma 40
non 3
choy 8
oʻrik 2
```

В стандартной библиотеке лежит именно это тело: `slices.Values(s)` делает из слайса итератор (`src/slices/iter.go`, из GOROOT go1.27.4):

```go
func Values[Slice ~[]E, E any](s Slice) iter.Seq[E] {
	return func(yield func(E) bool) {
		for _, v := range s {
			if !yield(v) {
				return
			}
		}
	}
}
```

Поэтому `All` можно записать одной строкой. Этого варианта нет в папке курса, но он запущен (в копии `_video/05-seq` заменён только `All`; `go vet` молчит):

```go
func (s *Store) All() iter.Seq[Product] {
	return slices.Values(s.products)
}
```

```console
non 3
choy 8
oʻrik 2
```

## Ключи map: maps.Keys и slices.Sorted

`range` по map не гарантирует порядок (GB-2.02), поэтому ключи собирали в слайс и вызывали `slices.Sort`. В заказе есть map `count`: название товара и количество штук (`_video/06-eski`).

- `maps.Keys(count)` — функция пакета `maps`: возвращает итератор по ключам map, то есть `iter.Seq[string]`.
- `slices.Sorted(seq)` — собирает значения из `iter.Seq` по сортируемым значениям (числам или `string`) в **новый слайс** и сортирует его.

`go doc` показывает сигнатуры обеих:

```console

func Sorted[E cmp.Ordered](seq iter.Seq[E]) []E
    Sorted collects values from seq into a new slice, sorts the slice, and

```

Части в квадратных скобках — параметры типа (GB-3.04); сейчас важен тип результата: `iter.Seq[K]`. Смысл `~map[K]V` и `cmp.Ordered`: `maps.Keys` принимает любой тип map, а `Sorted` — значения, которые можно сравнивать через `<`. Документация тоже говорит: порядок у `Keys` «not specified» («не определён»), поэтому нужен `Sorted`.

## Частые ошибки

**Ошибка: не проверять результат `yield`.** Самая частая ошибка. В `All` нет `if`, `for` всегда отдаёт все товары (`_video/04-buzuq`; `main` — цикл с `break` из предыдущего раздела):

```go
func (s *Store) All() func(yield func(Product) bool) {
	return func(yield func(Product) bool) {
		for _, p := range s.products {
			fmt.Println("iterator:", p.Name, "beraman")
			yield(p)
		}
	}
}
```

Код собирается. Что произойдёт после `break` на `non`?

**A)** `break` проигнорируется, `choy` и `oʻrik` тоже пройдут через тело · **B)** итератор молча доработает · **C)** программа упадёт (паника)

<details>
<summary>Ответ</summary>

**C.** После `break` `yield` вернул `false`, а итератор не обратил внимания и вызвал `yield` ещё раз для `choy`. Это нарушает правило, и runtime вызывает панику. **A** — думать, что `break` не зависит от итератора; **B** — молчаливого завершения не бывает: Go сообщает об этом паникой.

</details>

Сначала `go vet`:

```console
$ ./_video/run.sh 04-buzuq go vet ./...
```

Тихо: ни `go vet`, ни `go build` ошибку не видят. Запускаем (путь к папке каждый раз разный, поэтому я сократил его до `/tmp/…/`):

Порядок чтения:

1. `iterator: choy beraman` — на `non` был `break`, но итератор перешёл к `choy` и вызвал `yield` снова (`sikl: choy` не напечатано).
2. `panic: runtime error: range function continued iteration after function for loop body returned false` — «после того как тело цикла вернуло `false`, функция `range` продолжила итерацию». Сделанный компилятором `yield` помнит, что вернул `false`, и при повторном вызове паникует.
3. Стек: `main.main-range1` — функция, которую компилятор сделал из тела первого цикла `range` в `main`; `store.go:39` — строка с вызовом `yield(p)`; `main.go:16` — строка `for p := range st.All()`.
4. `exit status 2` — как у паники в GB-2.09.

**Исправление:** после каждого `yield` проверяйте результат и при `false` сразу делайте `return` — так написан наш `All` (выше) и тело `slices.Values`. Правило спецификации Go: если тело цикла завершилось досрочно (например, `break`), `yield` возвращает `false`, и его нельзя вызывать снова. Редактор не поможет: в `gopls` есть такой анализатор (`yield may be called again after returning false`), но он проверяет только пакет, который импортирует `iter`, а `gopls` v0.22.0 здесь модуль `go 1.27` не анализировал, `gopls check` промолчал. Поэтому опирайтесь не на редактор, а на правило `if !yield(p) { return }`.

**После `return` срабатывает `defer`.** Если итератор открыл файл и закрывает его через `defer`, файл закроется и при `break` в цикле: `yield` вернёт `false`, итератор сделает `return`, сработает его `defer`, и только потом закончится `range` (`_video/10-defer`; `katalog.txt` лежит в этой же папке; в демо ошибка открытия файла опущена):

```go filename="_video/10-defer/cmd/bozor/main.go" showLineNumbers
// Iterator ichidagi defer: sikl break qilsa ham, iterator return qilganda fayl yopiladi.
// (Demo: ochish xatosi tashlab yuborilgan; ishda xatoni ham qaytaring.)
package main

import (
	"bufio"
	"fmt"
	"iter"
	"os"
)

// lines faylni qatorma-qator beradi (GB-3.01'dagi bufio.Scanner).
func lines(name string) iter.Seq[string] {
	return func(yield func(string) bool) {
		f, err := os.Open(name)
		if err != nil {
			return
		}
		defer func() {
			f.Close()
			fmt.Println("iterator: fayl yopildi")
		}()
		sc := bufio.NewScanner(f)
		for sc.Scan() {
			if !yield(sc.Text()) {
				return
			}
		}
	}
}

func main() {
	for line := range lines("katalog.txt") {
		fmt.Println("sikl:", line)
		break
	}
	fmt.Println("sikldan keyin")
}
```

<summary>Ответ и объяснение</summary>

`LowStock` устроен так же, как `All`. Товар с достаточным остатком пропускаем через `continue` (GB-1.06), остальные отдаём в `yield` и после каждого `yield` проверяем результат:

```go
func (s *Store) LowStock(limit int) iter.Seq[Product] {
	return func(yield func(Product) bool) {
		for _, p := range s.products {
			if p.Stock >= limit {
				continue
			}
			if !yield(p) {
				return
			}
		}
	}
}
```

`SortedNames` — одна строка поверх готового `Names()`:

```go
func (s *Store) SortedNames() []string {
	return slices.Sorted(s.Names())
}
```

`slices.Sorted` создаёт новый слайс, поэтому запись в него не меняет каталог. Замечание (`TASK.md`): `slices.Sorted(st.All())` не компилируется — `Product` нельзя сравнить через `<`; а `Names()` — это `iter.Seq[string]`. Проверка с ответом:
