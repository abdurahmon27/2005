## Nimani oʻrganasiz

Buyurtma yozildi, olma qoldigʻi kamaydi, lekin non yetmadi. Funksiya xato qaytardi. Bazada yarim buyurtma qoladimi?

**Bitta gʻoya:** bir nechta jadvaldagi oʻzgarishni bitta **transaction** birlashtiradi: hammasi saqlanadi yoki jadval oʻzgarishlari bekor qilinadi. Go'da hamma buyruq bitta `tx` orqali ketadi.

Darsdan keyin siz:

- transaction'siz qoladigan yarim buyurtmani SQL bilan topasiz;
- `BEGIN`, `COMMIT`, `ROLLBACK` va buzilgan transaction holatini ajratasiz;
- `pool.Begin`, `defer tx.Rollback(ctx)` va `tx.Commit(ctx)` bilan `PlaceOrder` yozasiz;
- `tx` oʻrniga pool ishlatilgan xatoni topib, vazifani haqiqiy Postgres'da tekshirasiz.

| Soʻz | Sodda maʼnosi | English term |
|---|---|---|
| transaction | bir butun saqlanadigan yoki bekor qilinadigan buyruqlar guruhi | transaction |
| buzilgan transaction | SQL xatosidan keyin odatdagi buyruqlar rad etiladigan holat | aborted transaction |
| pgx transaction | pool'dan olingan bitta ulanishdagi transaction'ni boshqaradigan `tx` | pgx transaction |

Yordamchi tushunchalar: `UPDATE … SET` mavjud qator qiymatini yangilaydi. **SQLSTATE** — Postgres xato turining besh belgili kodi.

## Transaction'siz: xato yarim buyurtmani oʻchirmaydi

`bozor.sql` oldingi darslarning uchta jadvalini qayta yaratadi. `DROP TABLE` mavjud qatorlarni ham oʻchiradi: buni shu laboratoriyada bajaring. Nusxamizdagi jadvallar avvaldan mavjud edi:

```console
$ docker compose exec db psql -f /lab/bozor.sql

INSERT 0 4
CREATE TABLE

INSERT 0 3

```

Yangi bazada oldin uchta `NOTICE … does not exist, skipping` ogohlantirishi ham chiqadi. `CREATE TABLE` jadval yaratadi, `INSERT 0 n` esa `n` qator qoʻshadi. Videoda `DROP TABLE`, ogohlantirishlar va ayrim qator sonlari yashirilgan; bu yerda qayta bajarilgan natijalar berilgan.

| Jadval | Boshlangʻich holat | Buyurtmadagi vazifasi |
|---|---|---|
| `products` | olma: `id=1`, qoldiq `40`; non: `id=2`, qoldiq `3`; yana choy va oʻrik | qoldiqni kamaytirish |
| `orders` | 3 buyurtma | mijoz uchun buyurtma qatori |
| `order_items` | 4 qator | mahsulot, miqdor va buyurtma paytidagi narx |

`price`/`unit_price` tiyinda: olma `1200000`, non `400000`. `products.stock` uchun `CHECK (stock >= 0)` bor.

`store.go`dagi yangi kirish turi:

```go
type OrderItem struct {
	ProductID int64
	Quantity  int
}
```

`ProductID` mahsulotni, `Quantity` miqdorni bildiradi. `[]OrderItem` — shu struct qiymatlarining slice'i. `Store` ichida oldingi darsdagi ulanishlar pool'i bor.

Avval xato usulning toʻliq fayli:

```go filename="notx.go" showLineNumbers
package main

import "context"

// PlaceOrderNoTx — videodagi XATO versiya: shu PlaceOrder, lekin transaction'siz.
// Har buyruq pool orqali alohida yuboriladi, shuning uchun xatodan keyin yarim yozilgan buyurtma qoladi.
// Faqat koʻrsatish uchun: ishlatmang.
func (s *Store) PlaceOrderNoTx(ctx context.Context, customer string, items []OrderItem) (int64, error) {
	var orderID int64
	err := s.pool.QueryRow(ctx,
		"INSERT INTO orders (customer) VALUES ($1) RETURNING id", customer).Scan(&orderID)
	if err != nil {
		return 0, err
	}
	for _, it := range items {
		var price int64
		err = s.pool.QueryRow(ctx,
			"UPDATE products SET stock = stock - $1 WHERE id = $2 RETURNING price",
			it.Quantity, it.ProductID).Scan(&price)
		if err != nil {
			return 0, err
		}
		_, err = s.pool.Exec(ctx,
			"INSERT INTO order_items (order_id, product_id, quantity, unit_price) VALUES ($1, $2, $3, $4)",
			orderID, it.ProductID, it.Quantity, price)
		if err != nil {
			return 0, err
		}
	}
	return orderID, nil
}
```

## SQL: BEGIN va ROLLBACK

**Transaction** shu yozuvlarni bir guruhga oladi. `BEGIN` boshlaydi; shu ulanish oʻzining yangi qiymatlarini koʻradi. Boshqa ulanishlar saqlanmagan jadval oʻzgarishlarini koʻrmaydi. `COMMIT` saqlaydi, `ROLLBACK` bekor qiladi.

| Bosqich | Shu ulanish | Boshqa ulanish |
|---|---|---|
| `BEGIN`dan oldin | olma `38` | olma `38` |
| `UPDATE … - 2`dan keyin | olma `36` | saqlangan olma `38` |
| `ROLLBACK`dan keyin | olma `38` | olma `38` |
| oʻrniga muvaffaqiyatli `COMMIT` boʻlsa | olma `36` | keyingi oʻqish `36`ni koʻra oladi |

Bu jadval oddiy alohida soʻrovlar uchun; boshqa transaction'ning uzoq yashaydigan oʻqish holati bu dars mavzusi emas.

```sql filename="bekor.sql" showLineNumbers
BEGIN;
UPDATE products SET stock = stock - 2 WHERE id = 1;
SELECT stock FROM products WHERE id = 1;
ROLLBACK;
SELECT stock FROM products WHERE id = 1;
```

1-qator boshlaydi, 2-qator kamaytiradi, 3-qator ichki qiymatni oʻqiydi. 4-qator bekor qiladi, 5-qator qayta oʻqiydi. `;` SQL buyrugʻini tugatadi.

Oxirgi `SELECT` nimani chiqaradi? **A)** `38` · **B)** `36` · **C)** `40`.

<details>
<summary>Javob</summary>

**A: `38`.** `ROLLBACK` faqat shu transaction'dagi kamayishni qaytaradi. **B** bekor qilishni eʼtiborsiz qoldiradi. **C** oldingi transaction'siz buyurtmani ham bekor boʻladi deb hisoblaydi.

</details>

```console
$ docker compose exec db psql -t -f /lab/bekor.sql
BEGIN
UPDATE 1
    36

ROLLBACK
    38
```

`-t` sarlavha va `(N rows)`ni yashiradi, lekin `BEGIN`, `UPDATE 1`, `ROLLBACK` qoladi. `UPDATE 1` — bitta qator yangilandi. Ichkarida `36`, bekor qilingach `38`.

Dastur COMMIT'ga yetmay toʻxtasa-chi? **A)** UPDATE qoladi · **B)** ulanish uzilganda bekor boʻladi · **C)** baza abadiy kutadi.

<details>
<summary>Javob</summary>

**B.** Postgres ulanish yopilganini aniqlaganda tugallanmagan transaction'ni bekor qiladi. **A** UPDATE'ni COMMIT bilan tenglashtiradi. **C** uzilish aniqlanganidan keyingi holatga mos emas. Jarayon toʻxtashi bilan tarmoq uzilishi aniqlanishi orasida vaqt oʻtishi mumkin.

</details>

## SQL xatosi: buzilgan transaction

`xato.sql` non qoldigʻini `3`dan `-2`ga tushirishga urinadi. `SELECT 1` oddiy soʻrov: muvaffaqiyatda `1` qaytaradi.

```sql filename="xato.sql" showLineNumbers
BEGIN;
UPDATE products SET stock = stock - 5 WHERE id = 2;
SELECT 1;
COMMIT;
```

Non qoldigʻi oxirida nechta? **A)** `3` · **B)** `-2` · **C)** `0`.

<details>
<summary>Javob</summary>

**A.** `CHECK` manfiy qoldiqni rad etadi; shu transaction'dagi jadval oʻzgarishlari saqlanmaydi. **B** qoidani, **C** esa buyruqda nolga tushirish yoʻqligini hisobga olmaydi.

</details>

```console
$ docker compose exec db psql -f /lab/xato.sql
BEGIN
psql:/lab/xato.sql:2: ERROR:  new row for relation "products" violates check constraint "products_stock_check"
DETAIL:  Failing row contains (2, non, 400000, -2, t).
psql:/lab/xato.sql:3: ERROR:  current transaction is aborted, commands ignored until end of transaction block
ROLLBACK
```

- `/lab/xato.sql:2` — SQL faylining ikkinchi qatori. `DETAIL`dagi `Failing row` saqlangan qator emas, rad etilgan qiymatlar.
- `current transaction is aborted` — transaction buzilgan; oddiy soʻrovlar blok tugaguncha rad etiladi. Shuning uchun `SELECT 1` ham bajarilmaydi.
- Oxirgi `COMMIT` bu holatda `ROLLBACK` javobini berdi. Transaction bloki tugadi; oʻzgarishlar saqlanmadi.

Bu laboratoriyada savepoint yoʻq. Savepoint — transaction ichidagi qaytish nuqtasi; unga qaytish alohida mavzu. Oddiy Go xatosi esa Postgres transaction'ni oʻz-oʻzidan buzmaydi. Masalan, `pgx.ErrNoRows` SQL xatosi emas; undan keyin bekor qilishni Go kodi bajarishi kerak.

## Go: bitta tx, hamma buyruqlar

`pool.Begin(ctx)` pool'dan bitta ulanish olib, `BEGIN` yuboradi. Qaytgan `tx` ulanishning oʻzi emas, shu ulanishdagi transaction'ni boshqaruvchi qiymat. Barcha `QueryRow`/`Exec` shu `tx` orqali ketadi.

| Go yoʻli | Postgres | Pool |
|---|---|---|
| `pool.Begin` | transaction boshlanadi | bitta ulanish band |
| `tx.QueryRow` / `tx.Exec` | oʻsha transaction'dagi yozuvlar | ulanish band qoladi |
| erta `return` → deferred `Rollback` | jadval oʻzgarishlari bekor | sogʻlom ulanish qaytadi |
| muvaffaqiyatli `Commit` | yozuvlar saqlanadi | ulanish qaytadi |
| keyingi deferred `Rollback` | yangi ROLLBACK yuborilmaydi | transaction allaqachon yopilgan |

Toʻliq `store.go` quyida; 1–96-qatorlar GB-5.05'dan qolgan kod. Yangi qismlar 98-qatordan boshlanadi.

<details>
<summary>Toʻliq store.go</summary>

```go filename="store.go" showLineNumbers
package main

import (
	"context"
	"errors"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

// Product — products jadvalidagi bitta qator (narx tiyinda, GB-1.03).
type Product struct {
	ID    int64
	Name  string
	Price int64
	Stock int
}

// ErrNotFound — jadvalda bunday mahsulot yoʻq (GB-2.08: chaqiruvchi errors.Is bilan tekshiradi).
var ErrNotFound = errors.New("mahsulot topilmadi")

// Store — products jadvaliga Go'dan kirish. pool bir vaqtda koʻp goroutine'dan ishlatilishi mumkin.
type Store struct {
	pool *pgxpool.Pool
}

// Get id boʻyicha bitta mahsulotni oʻqiydi; yoʻq boʻlsa ErrNotFound.
func (s *Store) Get(ctx context.Context, id int64) (Product, error) {
	var p Product
	err := s.pool.QueryRow(ctx,
		"SELECT id, name, price, stock FROM products WHERE id = $1", id).
		Scan(&p.ID, &p.Name, &p.Price, &p.Stock)
	if errors.Is(err, pgx.ErrNoRows) {
		return Product{}, ErrNotFound
	}
	return p, err
}

// ListActive faol mahsulotlarni id tartibida oʻqiydi.
func (s *Store) ListActive(ctx context.Context) ([]Product, error) {
	rows, err := s.pool.Query(ctx,
		"SELECT id, name, price, stock FROM products WHERE active ORDER BY id")
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	out := []Product{}
	for rows.Next() {
		var p Product
		if err := rows.Scan(&p.ID, &p.Name, &p.Price, &p.Stock); err != nil {
			return nil, err
		}
		out = append(out, p)
	}
	return out, rows.Err()
}

// OrderTotal bitta buyurtmaning jami summasini (tiyinda) hisoblaydi. Buyurtma yoʻq boʻlsa SUM NULL beradi: COALESCE uni nolga aylantiradi.
func (s *Store) OrderTotal(ctx context.Context, orderID int64) (int64, error) {
	var total int64
	err := s.pool.QueryRow(ctx,
		"SELECT COALESCE(SUM(quantity*unit_price), 0) FROM order_items WHERE order_id = $1", orderID).
		Scan(&total)
	return total, err
}

// ByName nom boʻyicha bitta mahsulotni oʻqiydi; yoʻq boʻlsa ErrNotFound.
func (s *Store) ByName(ctx context.Context, name string) (Product, error) {
	var p Product
	err := s.pool.QueryRow(ctx,
		"SELECT id, name, price, stock FROM products WHERE name = $1", name).
		Scan(&p.ID, &p.Name, &p.Price, &p.Stock)
	if errors.Is(err, pgx.ErrNoRows) {
		return Product{}, ErrNotFound
	}
	return p, err
}

// Cheapest eng arzon n ta faol mahsulotni narx boʻyicha oʻsish tartibida oʻqiydi.
func (s *Store) Cheapest(ctx context.Context, n int) ([]Product, error) {
	rows, err := s.pool.Query(ctx,
		"SELECT id, name, price, stock FROM products WHERE active ORDER BY price, id LIMIT $1", n)
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	out := []Product{}
	for rows.Next() {
		var p Product
		if err := rows.Scan(&p.ID, &p.Name, &p.Price, &p.Stock); err != nil {
			return nil, err
		}
		out = append(out, p)
	}
	return out, rows.Err()
}

// ErrNotEnoughStock — omborda yetarli qoldiq yoʻq. VAZIFA (TASK.md, 1-qadam): PlaceOrder shu xatoni qaytarsin.
var ErrNotEnoughStock = errors.New("qoldiq yetarli emas")

// ErrInvalidQuantity — miqdor noldan katta boʻlishi kerak. VAZIFA (TASK.md, 3-qadam).
var ErrInvalidQuantity = errors.New("miqdor noldan katta boʻlishi kerak")

// OrderItem — buyurtmadagi bitta qator: qaysi mahsulot va nechta.
type OrderItem struct {
	ProductID int64
	Quantity  int
}

// PlaceOrder buyurtmani bitta transaction'da yozadi: orders qatori, har mahsulot uchun products.stock kamayishi
// va order_items qatori. Biror qadam xato bersa, hech narsa yozilmaydi.
func (s *Store) PlaceOrder(ctx context.Context, customer string, items []OrderItem) (int64, error) {
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return 0, err
	}
	defer tx.Rollback(ctx)

	var orderID int64
	err = tx.QueryRow(ctx,
		"INSERT INTO orders (customer) VALUES ($1) RETURNING id", customer).Scan(&orderID)
	if err != nil {
		return 0, err
	}
	for _, it := range items {
		var price int64
		err = tx.QueryRow(ctx,
			"UPDATE products SET stock = stock - $1 WHERE id = $2 RETURNING price",
			it.Quantity, it.ProductID).Scan(&price)
		if errors.Is(err, pgx.ErrNoRows) {
			return 0, ErrNotFound
		}
		if err != nil {
			return 0, err
		}
		_, err = tx.Exec(ctx,
			"INSERT INTO order_items (order_id, product_id, quantity, unit_price) VALUES ($1, $2, $3, $4)",
			orderID, it.ProductID, it.Quantity, price)
		if err != nil {
			return 0, err
		}
	}
	if err := tx.Commit(ctx); err != nil {
		return 0, err
	}
	return orderID, nil
}

// Restock tovar qabul qilishni yozadi: har mahsulotning qoldigʻi Quantity ga oshadi.
// Hammasi bitta transaction'da: bitta mahsulot topilmasa, hech birining qoldigʻi oʻzgarmaydi. VAZIFA (TASK.md, 2-qadam).
func (s *Store) Restock(ctx context.Context, items []OrderItem) error {
	return errors.New("Restock hali yozilmagan")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 98–108 | xatolar va `OrderItem` | vazifa uchun ikki sentinel xato; mahsulot id'si va miqdor struct'i |
| 110–116 | `PlaceOrder`, `pool.Begin` | oldingi imzo; boshlash xatosida `0, err` |
| 117 | `defer tx.Rollback(ctx)` | funksiya qaytganda transaction hali ochiq boʻlsa bekor qilishga urinadi |
| 119–124 | `tx.QueryRow` | buyurtmani shu transaction'da yaratadi; `err` borligi uchun `=` |
| 125–129 | sikl, `UPDATE` | oldingi SQL, endi `tx` orqali; narx buyurtma qatoriga kerak |
| 130–135 | `errors.Is(err, pgx.ErrNoRows)` | UPDATE hech qator topmasa `Scan` shu xatoni beradi; `ErrNotFound`ga aylantirib chiqadi; qolgan xatolar oʻzgarmaydi |
| 136–142 | `tx.Exec`, xato tekshiruvi | buyurtma qatorini oʻsha transaction'ga yozadi |
| 143–147 | `tx.Commit(ctx)` | xatosini tekshiradi; faqat muvaffaqiyatda `orderID, nil` qaytaradi |
| 149–153 | `Restock` | vazifa uchun stub: hozir «hali yozilmagan» xatosi |

Commit'dan keyingi Rollback `pgx.ErrTxClosed` (`tx is closed`) qaytaradi va saqlangan yozuvni oʻzgartirmaydi. Deferred chaqiruvning natijasi tashlanadi. Shu sabab bu shakl muvaffaqiyat yoʻlida ham xavfsiz.

`defer` jarayonning majburiy toʻxtashida yoki `os.Exit`da ishlamaydi. Ulanish uzilsa, tugallanmagan transaction'ni Postgres bekor qiladi. `Begin` context'i bekor boʻlishi pgx'da avtomatik rollback bermaydi: `Commit` yoki `Rollback` baribir kerak. Rollback boshqa sababdan bajarilmasa, pgx ulanishni yopadi; sogʻlom ulanishgina pool'ga qaytadi.

## Chuqurroq (ixtiyoriy): Postgres xatosini kodidan tanish

Vazifada `23514`ni `ErrNotEnoughStock`ga aylantirish kerak. `*pgconn.PgError` — pgx qaytargan Postgres xatosi turi. `errors.As` uni ochadi; `&pgErr` oʻzgaruvchining manzili. `Code` — SQLSTATE, `ConstraintName` — buzilgan qoida nomi.

Quyidagi toʻliq bosqich fayli `errors` va `pgconn` importlarini ham koʻrsatadi:

```go filename="_video/stages/05-main-pgerr.go" showLineNumbers
package main

import (
	"context"
	"errors"
	"fmt"
	"os"
	"time"

	"github.com/jackc/pgx/v5/pgconn"
	"github.com/jackc/pgx/v5/pgxpool"
)

func main() {
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
	if err != nil {
		fmt.Fprintln(os.Stderr, "pool:", err)
		os.Exit(1)
	}
	defer pool.Close()

	store := &Store{pool: pool}
	qctx, cancel := context.WithTimeout(ctx, 5*time.Second)
	defer cancel()

	_, err = store.PlaceOrder(qctx, "Aziza", []OrderItem{{ProductID: 2, Quantity: 5}})
	var pgErr *pgconn.PgError
	if errors.As(err, &pgErr) {
		fmt.Println(pgErr.Code, pgErr.ConstraintName)
	}
}
```

Oldingi `main`dan yangi qatorlar: 5 va 10 — importlar; 27 — 5 non buyurtmasi; 28–31 — xatoni ochib, ikki maydonni chiqarish. `pgErr` — pointer; `errors.As` muvaffaqiyatli boʻlgandagina uning maydonlarini oʻqiymiz.

Agar SQL xatosidan keyin baribir `tx.Commit` chaqirilsa, pgx `pgx.ErrTxCommitRollback` beradi: `commit unexpectedly resulted in rollback`. Bu misoldagi `PlaceOrder` esa oldinroq xato bilan chiqadi. Shuning uchun u asl `23514` xatosini qaytaradi.

## Oʻzingizni tekshiring

1. Shu darsdagi savepoint'siz transaction ichida CHECK buzilsa, oldingi UPDATE saqlanadimi?

<details>
<summary>Javob</summary>

Yoʻq. Transaction buziladi; oddiy buyruqlar rad etiladi. ROLLBACK blokni tugatadi; COMMIT ham bu holatda rollback boʻladi. Jadvaldagi oldingi oʻzgarishlar saqlanmaydi.

</details>

2. Commit'dan keyingi deferred Rollback nega saqlangan buyurtmani oʻchirmaydi?

<details>
<summary>Javob</summary>

`tx` yopilgan. pgx `ErrTxClosed` qaytaradi va bazaga yangi ROLLBACK yubormaydi.

</details>

3. Avvaldan olma `40`. `BEGIN; UPDATE products SET stock = stock - 2 WHERE id = 1; ROLLBACK;`dan keyingi oʻqish: **A)** `38` · **B)** `40` · **C)** xato?

<details>
<summary>Javob</summary>

**B: `40`.** Faqat shu transaction'dagi oʻzgarish bekor qilingan. `38` boʻlishi uchun muvaffaqiyatli COMMIT kerak edi.

</details>

4. GB-5.04: `WHERE note = NULL` nega hech qator qaytarmaydi?

<details>

`NULL` bilan oddiy taqqoslash nomaʼlum beradi; WHERE faqat rostni saqlaydi. `WHERE note IS NULL` kerak.
