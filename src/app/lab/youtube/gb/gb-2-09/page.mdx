## Nimani oʻrganasiz

bozor'ning `saveReport` funksiyasi hisobotni faylga yozadi. `main` uni 2000 marta chaqiradi va har yangi xatoni urinish raqami bilan chiqaradi.
Dastlab xato bitta: yozish xatosi. Lekin 1020-urinishda xatoning matni oʻzgaradi: `too many open files`, yaʼni «ochiq fayllar juda koʻp».
Har chaqiruv bitta fayl ochadi va qaytadi. Fayllar nega yigʻilib qoldi va uni bitta qator qanday tuzatadi?

**Bitta gʻoya:** har bir funksiyaning oʻz **defer roʻyxati** bor. `defer` qatori chaqiruvni (argumentlarini shu zahoti hisoblab) roʻyxat oxiriga
yozadi. Funksiya qanday tugasa ham, `return` bilan yoki panic bilan, roʻyxat oxiridan boshiga qarab bajariladi. Panic chaqiruvlar boʻylab
yuqoriga chiqib, har bir funksiyaning roʻyxatini bajaradi. `recover` panic'ni faqat shu roʻyxatdagi funksiyaning oʻzida chaqirilsa toʻxtatadi.
`os.Exit` esa roʻyxatlarni bajarmaydi.

Dars oxirida siz:

- `saveReport`dagi fayl sizib chiqishini (`too many open files`) `defer f.Close()` bilan tuzatasiz;
- bir nechta `defer` qaysi tartibda bajarilishini va `defer` argumentlari qachon hisoblanishini dasturni ishga tushirmasdan aytasiz;
- panic qachon oʻrinli va qachon `error` qaytarish kerakligini bilasiz, panic'ni `recover` va nomlangan natija bilan oddiy `error`'ga aylantirasiz;
- `os.Exit` nega `defer`'larni oʻtkazib yuborishini va `run() error` bilan buni qanday tuzatishni bilasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| `defer` | chaqiruvni darhol bajarmaydi, funksiya tugaguncha kechiktiradi | defer |
| `panic` | funksiyaning oddiy ishini toʻxtatadi; defer'lar ishlagach dastur 2 kod bilan tugaydi | panic |
| `recover` | defer'dagi funksiya ichida panic'ni toʻxtatadi va uning qiymatini qaytaradi | recover |

Ikkita yordamchi: nomlangan natija (`(err error)` — natijaga nom berish) va `os.Exit` (dasturni darhol tugatadi).

## Muammo: yopilmay qolgan fayl

Boshlangʻich dastur `_video/01-leak/main.go`. Uning katta qismi oldingi darslardan tanish, yangisi — `saveReport` va `main`:

```go filename="_video/01-leak/main.go" showLineNumbers
package main

import (
	"fmt"
	"io"
	"os"
)

const tiyinPerSom = 100 // 1 soʻm = 100 tiyin

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

// writeReport katalog hisobotini w'ga yozadi (GB-2.07).
func writeReport(w io.Writer, products []Product) error {
	for _, p := range products {
		_, err := fmt.Fprintf(w, "%-6s %6d soʻm %4d dona\n", p.Name, p.Price/tiyinPerSom, p.Stock)
		if err != nil {
			return err
		}
	}
	return nil
}

// saveReport katalog hisobotini path fayliga yozadi.
func saveReport(path string, products []Product) error {
	f, err := os.Create(path)
	if err != nil {
		return err
	}
	err = writeReport(f, products)
	if err != nil {
		return err // f ochiq qoldi
	}
	return f.Close()
}

func main() {
	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
		{ID: 3, Name: "oʻrik", Price: 3_500_000, Stock: 5},
	}
	var last string
	for i := 1; i <= 2000; i++ {
		err := saveReport("/dev/full", products)
		if err != nil && err.Error() != last {
			fmt.Printf("%d: %v\n", i, err)
			last = err.Error()
		}
	}
}
```

|---|---|---|
| 11–17 | `type Product struct { … }` | katalogdagi mahsulot: `ID`, `Name`, `Price` (tiyinda), `Stock` (GB-2.03) |
| 20–28 | `writeReport` | har mahsulot uchun bitta qator yozadi; yozish xato bersa, xatoni qaytaradi (GB-2.07) |
| 31 | `func saveReport(path string, products []Product) error` | `path` — fayl yoʻli; funksiya `writeReport`ning bosqichlarini yigʻadi (GB-2.07) |
| 32–35 | `f, err := os.Create(path)` va tekshiruv | `os.Create` faylni ochadi (bor boʻlsa, ichini boʻshatadi); xato boʻlsa, funksiya darhol qaytadi |
| 36–39 | `err = writeReport(f, products)` va tekshiruv | ochiq `f`ga yozadi; yozish xato bersa, funksiya xatoni darhol qaytaradi va 40-qatordagi `f.Close()`'gacha **yetmaydi** |
| 40 | `return f.Close()` | faylni yopadi: operatsion tizimga ish tugaganini aytadi |
| 44–48 | `products := []Product{ … }` | katalog: olma, non va oʻrik |
| 49 | `var last string` | oldingi xatoning matni |
| 50–56 | `for i := 1; i <= 2000; i++ { … }` | `saveReport`ni 2000 marta chaqiradi; xato **yangi** boʻlsagina (`err.Error() != last`) uni urinish raqami bilan chiqaradi, shuning uchun ekranda koʻpi bilan ikki qator |
| 51 | `saveReport("/dev/full", products)` | hisobot `/dev/full` fayliga yoziladi |

`/dev/full` — Linux'dagi maxsus fayl (qurilma): unga yozish **doim** `no space left on device`, yaʼni disk toʻla xatosini beradi. Biz yozish xatosini
shu bilan majburan chiqaramiz. Endi javob: `ulimit -n 1024` bu terminaldagi jarayon bir vaqtda ocha oladigan fayllar sonini 1024 ga tushiradi;
xato tez chiqishi uchun. `bash -c '…'` esa bash'ga berilgan buyruq qatorini bajartiradi, shunda `ulimit` va `go run` bitta jarayonda boʻladi:

```console
$ ./_video/run.sh 01-leak bash -c 'ulimit -n 1024; go run .'
1: write /dev/full: no space left on device
1020: open /dev/full: too many open files
```

Birinchi qator kutilgan: 1-urinishda yozish xato berdi (`/dev/full`). 2–1019-urinishlarda xato oʻsha-oʻsha, shuning uchun chiqmadi. 1020-urinishda
xato **oʻzgardi**: yozishgacha yetmadi, `os.Create`ning oʻzi (`open`) xato berdi. Sababi:

- har ochiq fayl operatsion tizimda bitta joy band qiladi (**fayl deskriptori**, file descriptor): jarayondagi ochiq fayl yoki ulanishning kichik raqami;
  `ulimit` shu joylar sonini cheklaydi;
- yozish xatosida funksiya 38-qatordan qaytadi, 40-qatordagi `f.Close()` bajarilmaydi, fayl ochiq qoladi va uning joyi band boʻlib turadi;
- 1019 ta sizib chiqqan fayldan keyin joy tugadi.

| Chaqiruv | `os.Create` | Yozish | `f.Close()` | Ochiq fayllar |
|---|---|---|---|---|
| 1 | ochildi | xato | **yetmadi** | 1 |
| 2 | ochildi | xato | **yetmadi** | 2 |
| … | … | … | … | … |
| 1019 | ochildi | xato | **yetmadi** | 1019 |
| 1020 | **xato**: `too many open files` | — | — | 1019 |

Nega 1020 va 1024 emas? Limit 1024 ta joyni beradi, lekin beshtasini dastur oʻzi band qiladi: stdin, stdout, stderr (0, 1, 2-deskriptor) va Go runtime'ning
ikkita ichki fayli (birinchi `os.Create` paytida ochiladi). Qoldi 1019 ta. Bu sonni kitobdan emas, shu mashinada oʻlchab oldik: uch marta ishga tushirishda ham 1020.

> **Limit haqida.** `ulimit -n` bash'da yumshoq (soft) va **qattiq** (hard) limitni birga qoʻyadi. Go 1.19'dan beri `os`'ni import qilgan dastur
> ishga tushganda yumshoq limitni qattiqqacha oʻzi koʻtaradi ([Go 1.19 release notes](https://go.dev/doc/go1.19#os/exec)); qattiq limitdan oshira olmaydi.
> Shuning uchun tajriba bash'da ishlaydi. zsh'da `ulimit -n` faqat yumshoq limitni qoʻyadi: u yerda `ulimit -Hn 1024` yozing (kurs README'si shunday deydi).
> Bu qismi sahifada qayta ishga tushirilmadi, README'dan olingan.

## defer: chaqiruvni roʻyxatga yozib qoʻyish

Tuzatish bitta qator: `defer f.Close()`. Quyida `saveReport`ning yangi koʻrinishi (`_video/02-defer/main.go`; qolgan hamma narsa oldingidek, farq faqat shu funksiyada):

```go
func saveReport(path string, products []Product) error {
	f, err := os.Create(path)
	if err != nil {
		return err
	}
	defer f.Close()
	err = writeReport(f, products)
	if err != nil {
		return err
	}
	return f.Close()
}
```

`defer` kalit soʻzi chaqiruvni **darhol bajarmaydi**: uni shu funksiyaning **defer roʻyxatiga** yozib qoʻyadi. Roʻyxat funksiya tugaganda bajariladi, va
tugash uch xil boʻlishi mumkin:

1. istalgan `return` qatorida;
2. funksiyaning oxirgi `}` qavsida;
3. panic'da (quyida).

Shuning uchun `defer`dan keyingi ikkala `return` ham faylni yopadi. `os.Create`dan keyingi birinchi `return` yopmaydi: u `defer`dan oldin, yopadigan fayl hali yoʻq.

**`defer` nega `err` tekshiruvidan keyin turadi.** `os.Create` xato bersa, `f` ishlaydigan fayl emas: yopadigan narsa yoʻq, `nil` ustida metod chaqirish esa
koʻp turlarda panic beradi (GB-2.04). Shuning uchun avval tekshiruv, keyin `defer`: resurs olinganiga ishonch hosil qilgandan soʻng.

**Nega `return f.Close()` qoldi.** Yozilgan faylni yopishda ham xato boʻlishi mumkin, uni chaqiruvchiga qaytarish kerak. Undan keyin `defer`dagi `Close` yana
chaqiriladi; `*os.File` uchun ikkinchi `Close` xato qaytaradi, `defer` bu xatoni tashlab yuboradi. `*os.File` uchun bu xavfsiz, hujjatida yozilgan:

```console
$ go doc os.File.Close
package os // import "os"

func (f *File) Close() error
    Close closes the File, rendering it unusable for I/O. On files that support
    File.SetDeadline, any pending I/O operations will be canceled and return
    immediately with an ErrClosed error. Close will return an error if it has
    already been called.
```

(Ixtiyoriy `io.Closer` uchun ikkinchi `Close` kafolatlanmagan; bu qoida faqat `*os.File`ga tegishli.) Xuddi shu limit bilan yana ishga tushiramiz. Ikkinchi qator
chiqadimi?

<summary>Javob</summary>

Yoʻq: 2000 ta chaqiruvdan faqat disk toʻla xatosi qoldi. Har chaqiruv oʻz faylini yopib chiqdi, shuning uchun joy hech qachon tugamadi.

## Bir nechta defer: oxirgisi birinchi

Bitta funksiyada bir nechta `defer` boʻlsa-chi? Quyidagi dastur (`_video/03-tartib/main.go`) ikkita oddiy `Println` va ikkita `defer`'li `Println`dan iborat:

```go filename="_video/03-tartib/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println("hisobot boshlandi")
	defer fmt.Println("defer 1: fayl yopildi")
	defer fmt.Println("defer 2: buyurtma yopildi")
	fmt.Println("hisobot tugadi")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `fmt.Println("hisobot boshlandi")` | oddiy chaqiruv: darhol bajariladi |
| 7 | `defer fmt.Println("defer 1: …")` | chaqiruvni `main`ning defer roʻyxatiga yozadi, hozir chiqarmaydi |
| 8 | `defer fmt.Println("defer 2: …")` | ikkinchi chaqiruvni roʻyxat oxiriga yozadi |
| 9 | `fmt.Println("hisobot tugadi")` | oddiy chaqiruv: darhol bajariladi |
| 10 | `}` | `main` tugadi: roʻyxat bajariladi |

Ekranda qanday tartibda chiqadi?

**A)** defer'lar yozilgan joyida · **B)** defer'lar oxirida, yozilgan tartibda (1, 2) · **C)** defer'lar oxirida, teskari tartibda (2, 1)

<details>
<summary>Javob</summary>

**C.** Oddiy qatorlar oʻz joyida chiqadi, `defer`'lar esa `main` tugaganda va **teskari** tartibda: oxirgi yozilgani birinchi bajariladi (**LIFO**, last in — first out).
**A** ni tanlagan boʻlsangiz, `defer`ni oddiy chaqiruv deb oʻylagansiz; **B** — navbat tartibi, lekin roʻyxat oxiridan boshiga qarab ishlaydi.

```console
$ ./_video/run.sh 03-tartib go run .
hisobot boshlandi
hisobot tugadi
defer 2: buyurtma yopildi
defer 1: fayl yopildi
```

</details>

Roʻyxatning holati qatorma-qator:

| Bajarilgan qator | `main`ning defer roʻyxati | Ekran |
|---|---|---|
| 6 | boʻsh | `hisobot boshlandi` |
| 7 | `[defer 1]` | — |
| 8 | `[defer 1, defer 2]` | — |
| 9 | `[defer 1, defer 2]` | `hisobot tugadi` |
| 10 (`}`) | oxiridan boshiga: avval `defer 2`, keyin `defer 1` | `defer 2: …`, `defer 1: …` |

Teskari tartibning foydasi: keyin olingan resurs koʻpincha oldingisidan foydalanadi, shuning uchun u birinchi yopilishi kerak. Spetsifikatsiya faqat tartibni
beradi; bu sabab mulohaza (keyingi darslarda konkret juftlik chiqadi, masalan GB-3.01).

## defer argumentlari shu zahoti hisoblanadi

Endi argumentlar (`_video/04-arg/main.go`). `stock` 40, `defer`da uni chiqaramiz; keyin 3 dona sotamiz va hozirgi qoldiqni chiqaramiz:

```go filename="_video/04-arg/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := 40
	defer fmt.Println("defer: qoldiq", stock)
	stock -= 3
	fmt.Println("hozir: qoldiq", stock)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `stock := 40` | `stock` oʻzgaruvchisi, qiymati 40 |
| 7 | `defer fmt.Println("defer: qoldiq", stock)` | `Println` chaqiruvini defer roʻyxatiga yozadi |
| 8 | `stock -= 3` | `stock = stock - 3`: `stock` 37 boʻladi (GB-2.04'da `p.Stock -= quantity` shu) |
| 9 | `fmt.Println("hozir: qoldiq", stock)` | darhol chiqaradi |

`defer` qatori nechani chiqaradi?

**A)** `40` · **B)** `37` · **C)** kompilyatsiya xatosi

<details>
<summary>Javob</summary>

**A: 40.** `defer` qatori bajarilganda `Println` hali chaqirilmaydi, lekin uning **argumentlari shu zahoti hisoblanadi**: `stock`ning oʻsha paytdagi qiymati (40)
nusxa boʻlib roʻyxatga yoziladi. Keyin `stock` 37 boʻladi, nusxa esa oʻzgarmaydi. **B** ni tanlagan boʻlsangiz, argument roʻyxat bajarilganda oʻqiladi deb
oʻylagansiz.

```console
$ ./_video/run.sh 04-arg go run .
hozir: qoldiq 37
defer: qoldiq 40
```

</details>

| Qator | `stock` | Roʻyxatdagi chaqiruv | Ekran |
|---|---|---|---|
| 6 | 40 | — | — |
| 7 | 40 | `Println("defer: qoldiq", 40)` — **40 nusxa** | — |
| 8 | 37 | `Println("defer: qoldiq", 40)` | — |
| 9 | 37 | `Println("defer: qoldiq", 40)` | `hozir: qoldiq 37` |
| 10 (`}`) | 37 | roʻyxat bajariladi | `defer: qoldiq 40` |

Oxirgi qiymat kerak boʻlsa, `defer`ga **nomsiz funksiya** beramiz (GB-1.08'da uni `t.Run`'ga bergan edik). `_video/05-closure/main.go`:

```go filename="_video/05-closure/main.go" showLineNumbers
package main

import "fmt"

func main() {
	stock := 40
	defer func() {
		fmt.Println("defer: qoldiq", stock)
	}()
	stock -= 3
	fmt.Println("hozir: qoldiq", stock)
}
```

- 7–9-qatorlar: `func() { … }` — nomsiz funksiya; oxiridagi boʻsh qavslar `()` uni shu yerda **chaqiradi**, `defer` esa shu chaqiruvni roʻyxatga yozadi.
- Chaqiruvda **argument yoʻq**, nusxalanadigan narsa ham yoʻq.
- Funksiya ichidagi `stock` tashqaridagi oʻzgaruvchining **oʻzi**, nusxasi emas (**closure**): u `main` tugaganda, yaʼni 37 boʻlganda oʻqiladi.

Endi nechani chiqaradi? U `main` tugaganda oʻqiladi: 37.

```console
$ ./_video/run.sh 05-closure go run .
hozir: qoldiq 37
defer: qoldiq 37
```

Qoida: `defer fmt.Println(…, stock)` — qiymat **hozir**; `defer func() { … stock … }()` — qiymat funksiya **tugaganda**.

## panic: davom etib boʻlmaganda

GB-2.04'da nil pointer orqali yozish panic bergan edi. Endi panic'ni defer bilan birga koʻramiz. Quyida `_video/06-panic/main.go`: `Product` va `findProduct` GB-2.04'dagidek,
yangisi — `sell` va `main` (butun fayl papkada):

```go
// sell p mahsulotdan quantity dona sotadi.
func sell(p *Product, quantity int) {
	defer fmt.Println("defer: sell tugadi")
	p.Stock -= quantity
	fmt.Println("sotildi")
}

func main() {
	defer fmt.Println("defer: main tugadi")
	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
		{ID: 3, Name: "oʻrik", Price: 3_500_000, Stock: 5},
	}
	p := findProduct(products, 9) // topilmadi: nil
	sell(p, 1)
	fmt.Println("main oxiri")
}
```

- `sell`: avval `defer`, keyin `p.Stock -= quantity` — nil pointer orqali qoldiqni kamaytirish, yaʼni GB-2.04'dagi panic.
- `main`da ham `defer` bor. `findProduct` ID 9 ni topmaydi va `nil` qaytaradi; `main` `sell`ni shu `nil` bilan chaqiradi.

`sell(nil, 1)` chaqirilganda ekranda nima chiqadi?

**A)** faqat `sell`ning defer qatori, keyin panic · **B)** ikkala defer qatori, keyin panic · **C)** avval panic xabari, keyin ikkala defer qatori

<details>
<summary>Javob</summary>

**B.** Panic `sell`ning oddiy ishini shu qatorda toʻxtatdi: `sotildi` ham, `main oxiri` ham chiqmadi. Keyin Go chaqiruvlar boʻylab yuqoriga chiqib, har bir funksiyaning
defer roʻyxatini bajaradi: avval `sell`niki, keyin `main`niki. Shundan keyingina xabar chiqadi va dastur 2 chiqish kodi bilan tugaydi. **C** ni tanlagan boʻlsangiz,
xabar darhol chiqadi deb oʻylagansiz; **A** — `main`ning roʻyxati ham bajarilishini unutgansiz.

Quyida mening ishga tushirishim; `[signal …]` qatoridagi manzillar, stack trace'dagi vaqtinchalik papka yoʻli va `+0x…` siljishlar har gal boshqacha

Bu GB-1.07'dagi «panic dasturni darhol toʻxtatadi»ning aniqrogʻi: avval defer roʻyxatlari bajariladi, keyin dastur tugaydi. Rasmiy hujjat ham shuni aytadi:

```console
$ go doc builtin.panic
package builtin // import "builtin"

func panic(v any)
    The panic built-in function stops normal execution of the current goroutine.
    When a function F calls panic, normal execution of F stops immediately.
    Any functions whose execution was deferred by F are run in the usual way,
    and then F returns to its caller. To the caller G, the invocation of F then
    behaves like a call to panic, terminating G's execution and running any
    deferred functions. This continues until all functions in the executing
    goroutine have stopped, in reverse order. At that point, the program is
    terminated with a non-zero exit code. This termination sequence is called
    panicking and can be controlled by the built-in function recover.

    Starting in Go 1.21, calling panic with a nil interface value or an untyped
    nil causes a run-time error (a different panic). The GODEBUG setting
    panicnil=1 disables the run-time error.
```

**Qachon panic oʻrinli?**

- **Kutilgan xato uchun panic emas, `error` qaytaring:** chaqiruvchi hal qiladi (fayl yoʻq, qoldiq yetmaydi, notoʻgʻri kiritish).
- Panic **dasturchi xatosi** uchun: nil pointer yoki index xatosida runtime'ning oʻzi panic qiladi.
- Oʻrnatilgan `panic(v)` funksiyasini istalgan qiymat bilan oʻzingiz ham chaqira olasiz (`v` — `any`, istalgan tur).
- Standart kutubxonada nomi `Must` bilan boshlanadigan funksiyalar shunday: masalan `regexp` (regular expression, matn namunasi paketi) paketidagi `MustCompile` notoʻgʻri
  namunada panic qiladi va dastur boshida ishlatiladi:

```console
$ go doc regexp.MustCompile
package regexp // import "regexp"

func MustCompile(str string) *Regexp
    MustCompile is like Compile but panics if the expression cannot be parsed.
    It simplifies safe initialization of global variables holding compiled
    regular expressions.
```

- **Paketdan tashqariga `error` chiqadi:** hatto paket ichida panic ishlatsa ham, tashqi API xatoni qiymat sifatida qaytaradi (Go blog, Effective Go).

## recover va nomlangan natija: panic'ni xatoga aylantirish

Panic butun dasturni yiqitmasligi uchun **chegarada** — bitta buyruq yoki serverga kelgan soʻrov ishini boshlaydigan joyda — uni `recover` toʻxtatadi.
Quyida `safely` (`_video/07-recover/main.go`) va uni chaqiradigan `main`:

```go
// safely fn'ni chaqiradi; fn panic qilsa, panic'ni error qilib qaytaradi.
func safely(fn func()) (err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("panic: %v", r)
		}
	}()
	fn()
	return nil
}

func main() {
	products := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
		{ID: 3, Name: "oʻrik", Price: 3_500_000, Stock: 5},
	}
	p := findProduct(products, 9) // topilmadi: nil
	err := safely(func() {
		sell(p, 1)
	})
	fmt.Println("xato:", err)
	fmt.Println("main oxiri")
}
```

Qator raqamlari parcha ichidagi (1 — izoh qatori):

| Qator | Kod | Nima qiladi |
|---|---|---|
| 2 | `func safely(fn func()) (err error)` | `fn` — parametr, turi `func()`: parametrsiz va natijasiz funksiya (funksiya qiymati). `(err error)` — natijaga **nom** berdik |
| 3 | `defer func() { … }()` | nomsiz funksiyani defer roʻyxatiga yozadi |
| 4 | `if r := recover(); r != nil {` | oʻrnatilgan `recover` panic ketayotgan boʻlsa, uni **toʻxtatadi** va panic qiymatini qaytaradi; aks holda `nil`. `r` — `any` turida |
| 5 | `err = fmt.Errorf("panic: %v", r)` | qiymatdan `error` yasaydi va natija `err`ga yozadi; `r`ning turi `any`, shuning uchun `%v` |
| 8 | `fn()` | tanada `fn` chaqiriladi |
| 9 | `return nil` | panic boʻlmasa, `nil` qaytadi |

**Qoida:** `recover` faqat defer'dagi funksiyaning **oʻzida** chaqirilganda ishlaydi. Rasmiy hujjat:

```console
$ go doc builtin.recover
package builtin // import "builtin"

func recover() any
    The recover built-in function allows a program to manage behavior of
    a panicking goroutine. Executing a call to recover inside a deferred
    function (but not any function called by it) stops the panicking sequence
    by restoring normal execution and retrieves the error value passed to the
    call of panic. If recover is called outside the deferred function it will
    not stop a panicking sequence. In this case, or when the goroutine is not
    panicking, recover returns nil.

    Prior to Go 1.21, recover would also return nil if panic is called with a
    nil argument. See [panic] for details.
```

**Nomlangan natija.** GB-2.07'da natija nomlarini «hujjat uchun» degandik. Aslida `(err error)` — funksiya boshida zero value (`nil`) bilan yaratiladigan
oddiy oʻzgaruvchi. `return x` avval shu oʻzgaruvchiga `x`ni yozadi, **keyin** defer'lar ishlaydi, va defer'dagi funksiya uni oʻzgartira oladi; chaqiruvchi
aynan oʻzgargan qiymatni oladi. Kurs papkasida yoʻq kichik dastur (`natija/main.go`, toʻliq kodi shu yerda):

```go
package main

import "fmt"

func ikki() (n int) {
	defer func() {
		n *= 2
	}()
	return 21
}

func main() {
	fmt.Println(ikki())
}
```

`return 21` avval `n`ga 21 yozadi, keyin `defer` `n`ni ikki barobar qiladi: 42.

```console
$ go run main.go
42
```

`safely`da ham xuddi shunday: panic boʻlsa, defer'dagi funksiya `err`ga xato yozadi va `safely`ni chaqirgan kod aynan shu `err`ni oladi; panic boʻlmasa, `return nil`
avval `err`ga `nil` yozadi, defer'lar undan keyin ishlaydi. `main`da endi `defer`siz, `sell`ni nomsiz funksiya ichida `safely`ga beramiz. Nima chiqadi?

<details>
<summary>Javob</summary>

```console
$ ./_video/run.sh 07-recover go run .
defer: sell tugadi
xato: panic: runtime error: invalid memory address or nil pointer dereference
main oxiri
```

Avval `sell`ning defer'i ishladi, keyin `safely`niki: `recover` panic'ni toʻxtatdi va u oddiy xato boʻlib qaytdi, `main` davom etdi (`main oxiri`).
Server ham har bir soʻrovni (kelgan murojaatni) shunday oʻraydi: bitta soʻrovdagi panic serverni yiqitmaydi. Lekin bu xatoda panic **qayerda** boʻlgani, yaʼni
stack trace yoʻq: uni GB-6.01'da log'ga yozamiz.

</details>

## recover qayerda ishlamaydi

Kimdir `recover`ni `toError` degan alohida funksiyaga chiqardi, boshqa joylarda ham ishlatish uchun. Defer'dagi funksiya endi faqat `toError`ni chaqiradi va
natijasini `err`ga yozadi. `main` oʻsha (`_video/08-quiz/main.go`):

```go
// safely fn'ni chaqiradi; fn panic qilsa, panic'ni error qilib qaytaradi.
func safely(fn func()) (err error) {
	defer func() {
		err = toError() // recover endi shu yerda
	}()
	fn()
	return nil
}

// toError — recover defer'dagi funksiya chaqirgan boshqa funksiyada: panic'ni toʻxtatmaydi.
func toError() error {
	if r := recover(); r != nil {
		return fmt.Errorf("panic: %v", r)
	}
	return nil
}
```

Nima boʻladi?

**A)** xato qaytadi va `main` davom etadi (`xato: panic: …`, `main oxiri`) · **B)** dastur panic bilan yiqiladi · **C)** kompilyatsiya xatosi

<details>
<summary>Javob</summary>

**B.** `recover` faqat defer'dagi funksiyaning **oʻzida** ishlaydi. `toError` undan chaqirilgan **boshqa** funksiya: u yerda `recover` `nil` qaytardi va panic davom etdi.
**A** ni tanlagan boʻlsangiz, `recover` chaqiruvi defer'ga «tegishli» deb oʻylagansiz; Go esa faqat bevosita chaqiruvni sanaydi. Quyida mening ishga tushirishim
(trace qatorlari `…` bilan qisqartirildi):

```console

panic: runtime error: invalid memory address or nil pointer dereference
…
exit status 2
```

`recover` defer'siz, `fn`dan oldin chaqirilganda ham panic toʻxtamaydi: bunda defer'ning oʻzi yoʻq, panic paytida esa faqat defer'lar ishlaydi (`_video/12-defersiz/main.go`,
videoda faqat aytiladi):

```console
$ ./_video/run.sh 12-defersiz go run .
defer: sell tugadi

…
exit status 2
```

`recover` boshqa goroutine'dagi panic'ni ham ushlamaydi: goroutine — Go'da bir vaqtda ishlaydigan alohida funksiya, uni GB-7.01'da ochamiz.

</details>

## Koʻp uchraydigan xatolar

**1. `os.Exit` defer'larni bajarmaydi.** Eng koʻp uchraydigan xato: `main`da `defer` bor, xato boʻlsa `os.Exit(1)` bilan chiqiladi. `main`ning `defer`i tozalash ishining
oʻrnida turibdi (masalan vaqtinchalik faylni oʻchirish). `_video/09-exit/main.go`; `products` qisqalik uchun paket darajasiga chiqarilgan, `saveReport` oldingidek:

```go
func main() {
	defer fmt.Println("defer: main tugadi")
	err := saveReport("/dev/full", products)
	if err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}
```

Saqlash xato beradi. Ekranda nima chiqadi?

**A)** xato, keyin defer qatori · **B)** faqat xato qatori · **C)** avval defer qatori, keyin xato

<details>
<summary>Javob</summary>

**B: defer qatori yoʻq.** `os.Exit` dasturni shu zahoti tugatadi, defer roʻyxatlari bajarilmaydi:

func Exit(code int)
    Exit causes the current program to exit with the given status code.
    Conventionally, code zero indicates success, non-zero an error. The program

**Tuzatish.** Asosiy ishni `error` qaytaradigan `run` funksiyasiga chiqaramiz, `defer`'lar oʻsha yerda. `main` faqat `run`ni chaqiradi va xato boʻlsa `os.Exit` bilan chiqadi

## Oʻzingizni tekshiring

**1.** `defer f.Close()` nega `err` tekshiruvidan keyin yoziladi?

<details>
<summary>Javob</summary>

`os.Create` xato bersa, `f` ishlaydigan fayl emas va yopadigan narsa yoʻq; `nil` ustida metod chaqirish esa koʻp turlarda panic beradi. Avval tekshiruv, keyin `defer`.

</details>

**2.** `recover` nega defer'dagi funksiyaning oʻzida chaqiriladi?

<details>
<summary>Javob</summary>

Panic paytida faqat defer roʻyxatidagi funksiyalar ishlaydi, `recover`ni ularning oʻzi chaqirishi kerak. Defer'dagi funksiya chaqirgan boshqa funksiyada (`toError`) `recover` `nil` qaytaradi va panic davom etadi.

</details>

**3.** GB-2.06'dan: `main` `store` paketidagi kichik harfli `products` maydonini oʻqiy oladimi?

<details>
<summary>Javob</summary>

Yoʻq. Kichik harf bilan boshlangan nom faqat oʻz paketida koʻrinadi: `main` uni oʻqisa, kompilyator `unexported` deb rad etadi.

</details>

Nega har defer oʻzining `i`sini koʻrdi: Go 1.22'dan beri `for` sikli har qadamda **yangi** `i` yaratadi ([Go 1.22 release notes](https://go.dev/doc/go1.22#language)).
Oldingi versiyalarda `i` butun sikl uchun bitta umumiy oʻzgaruvchi edi va hamma defer oxirgi qiymatni (3) oʻqirdi, yaʼni **B** chiqardi; bu qismini men qayta ishga tushirmadim,

</details>

<details>
<summary>Javoblar: 1-qadam (handle) va 2-qadam (reserve)</summary>

**1-qadam** — `handle` bu darsdagi `safely`ning oʻzi, ikki farq bilan: `fn` endi `error` qaytaradi (`return fn()`), xato matni esa `%w` bilan `ErrPanic`ni oʻrab saqlaydi (GB-2.08):

```go
func handle(name string, fn func() error) (err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("%s: %w: %v", name, ErrPanic, r)
		}
	}()
	return fn()
}
```

`return fn()` avval `err`ga `fn`ning xatosini yozadi; panic boʻlmasa, defer'dagi funksiya unga tegmaydi. `%w` `ErrPanic`ni ichida saqlaydi (`errors.Is(err, ErrPanic)` — `true`), `%v` panic qiymatini matnga qoʻshadi.

**2-qadam** — `reserve`: boshida qoldiqlar nusxasini `append` bilan yigʻamiz (GB-2.01), `ok := false` yozamiz va `defer` ichida `!ok` boʻlsa qoldiqlarni qaytaramiz. `return nil`dan oldin `ok = true`:

```go
func reserve(products []Product, items []OrderItem) (err error) {
	var saved []int // boshidagi qoldiqlar
	for _, p := range products {
		saved = append(saved, p.Stock)
	}
	ok := false
	defer func() {
		if !ok { // xato bilan qaytdik yoki panic boʻldi: qoldiqni tiklaymiz
			for i := range saved {
				products[i].Stock = saved[i]
			}
		}
	}()
	// … oldingi sikl: har qatorni tekshirish va p.Stock -= it.Quantity (oʻzgarmagan) …
	ok = true
	return nil
}
```

Nomsiz funksiya `ok`ni funksiya **tugaganda** oʻqiydi (`05-closure`dagi `stock` kabi), shuning uchun har `return fmt.Errorf(…)`ga tegmaymiz. Oʻrtada panic boʻlsa ham qoldiq tiklanadi: panic'da ham defer'lar ishlaydi.
Boshidagi qoldiqlar nusxasi bitta mahsulot ikki qatorda kelganda ham toʻgʻri tiklaydi. Bu «hammasi yoki hech biri» shakli keyinroq `defer tx.Rollback()`da (GB-5.07) qayta uchraydi.

Butun `reserve` va `handle` — `solution/main.go`da. Javob bilan tekshirish (shu papkada; `solution/`da `main.go` bilan birga xuddi shu test fayli bor; mening ishga tushirishim):
