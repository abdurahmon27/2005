## Что вы узнаете

bozor получает прайс-листы от трёх поставщиков. Если каждый отвечает за секунду, зачем ждать три секунды?
Как запустить все три операции сразу и узнать, что они завершены?

**Одна идея:** запуск работы в новой горутине ещё не означает ожидание. Код, который запустил работу, должен управлять и её завершением.
В лаборатории `sync.WaitGroup` ждёт завершения; `time.Sleep` лишь угадывает время.

После урока вы сможете:

- запускать функцию через `go` и объяснять, что происходит при возврате `main`;
- запускать три операции через `wg.Go` и ждать их через `wg.Wait`;
- находить ошибку общего `append` и записывать результаты по отдельным индексам;
- проверять владельца работы в обработчике и выполнять задание `fetchAll`.

| Слово | Простое значение | Английский термин |
|---|---|---|
| горутина | выполнение функции одновременно с другим кодом под управлением Go runtime | goroutine |
| WaitGroup | тип пакета `sync`, который считает запущенные задачи и ждёт их завершения | WaitGroup |
| владелец горутины | код, ответственный за запуск работы и ожидание её завершения | goroutine owner |

## Сначала последовательное выполнение

Вместо сети здесь `time.Sleep(time.Second)`: поставщик как будто отвечает через секунду.
`fetch` означает чтение списка, `name` — имя поставщика. Пока `fetch` ничего не возвращает.

```go filename="_video/01-ketma/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func fetch(name string) {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
}

func main() {
	start := time.Now()
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		fetch(name)
	}
	fmt.Println("jami:", time.Since(start))
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `package main` | пакет исполняемой программы |
| 3–6 | `import` | `fmt` выводит текст, `time` работает со временем |
| 8 | `func fetch(name string)` | функция с текстовым параметром; `{}` ограничивают тело |
| 9 | `fmt.Println` | выводит `boshlandi:` («началось») и имя |
| 10 | `time.Sleep(time.Second)` | приостанавливает текущую горутину минимум на секунду |
| 11–12 | `fmt.Println`, `}` | выводит `tayyor:` («готово») и завершает функцию |
| 14 | `func main()` | входная функция программы |
| 15 | `start := time.Now()` | сохраняет время начала в переменной `start` |
| 16 | `for _, name := range []string{…}` | проходит слайс из трёх имён; `_` отбрасывает индекс |
| 17–18 | `fetch(name)` | завершает один вызов перед следующим |
| 19–20 | `time.Since(start)` | выводит прошедшее время с `jami:` («всего»), `main` возвращается |

Точка выбирает член пакета; `()` вызывает, кавычки ограничивают текст. Пустые строки не выполняются.

## `go`: запускает, не ждёт

Добавим одно слово: `go fetch(name)`. **Горутина** — отдельное выполнение функции под управлением Go runtime.
Runtime — вспомогательный код Go, работающий вместе с программой. `main` тоже выполняется в горутине.
`go` вычисляет функцию и аргументы в вызывающей горутине, затем запускает новую.
Завершения вызова он не ждёт; возвращённые результаты отбрасываются. [Официальное правило](https://go.dev/ref/spec#Go_statements).

```go filename="_video/02-go/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func fetch(name string) {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
}

func main() {
	start := time.Now()
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		go fetch(name)
	}
	fmt.Println("jami:", time.Since(start))
}
```

Изменилась строка 17: перед `fetch(name)` стоит `go`. `main` запускает три задачи и переходит к `jami`.

**Прогноз:** что увидим? **A)** всегда три `tayyor` · **B)** `jami`, возможно и `boshlandi` · **C)** ошибку о незавершённой работе

<details>
<summary>Ответ</summary>

**B.** При возврате `main` программа завершается, не ожидая остальные горутины. A предполагает скрытое ожидание, C — обязательную ошибку; их нет.

</details>

```console
$ ./_video/run.sh 02-go go run .
boshlandi: chorsu
jami: 4.094µs
(chiqish kodi: 0)
```

`µs` — микросекунды. Маленькое `jami` не означает выполненную работу: программа завершилась до результата.
[Официальное правило](https://go.dev/ref/spec#Program_execution) говорит, что возврат `main` не ждёт остальные горутины.
Это не их упорядоченное завершение; рассчитывать на выполнение их `defer` тоже нельзя.

| Событие | `main` | Три задачи |
|---|---|---|
| `go fetch` | переходит к следующей строке | готовы выполняться или уже работают |
| возврат `main` | программа завершается | незавершённая работа не продолжается |

`olchov.sh go` один раз собирает программу и запускает её 200 раз. Вывод группируется по числу строк `boshlandi` и `tayyor`.

```console
$ ./_video/olchov.sh go
    110 boshlandi=0 tayyor=0
     35 boshlandi=1 tayyor=0
     28 boshlandi=2 tayyor=0
     27 boshlandi=3 tayyor=0
```

Записанное в видео распределение: `110 / 32 / 37 / 21`; это цитата, а не новый запуск.
Сегодня получилось `110 / 35 / 28 / 27`, как показано выше. В обоих случаях `tayyor` — ноль.
Проценты не задают правило: причина в отсутствии ожидания завершения.

## `Sleep`: прошедшее время не доказывает завершение

Добавим в `main` вызов `time.Sleep(500 * time.Millisecond)`. `*` умножает длительность на 500: получается полсекунды.

```go filename="_video/03-sleep/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func fetch(name string) {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
}

func main() {
	start := time.Now()
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		go fetch(name)
	}
	time.Sleep(500 * time.Millisecond)
	fmt.Println("jami:", time.Since(start))
}
```

**Прогноз:** `main` ждёт 0,5 с, `fetch` — 1 с. **A)** три `tayyor` · **B)** обычно три `boshlandi`, без `tayyor` · **C)** всегда только `jami`

<details>
<summary>Ответ</summary>

**B — обычный результат.** Полсекунды хватило для запуска, но не завершения. A забывает секундное ожидание; C исключает запуск горутин. Порядок выполнения не гарантирован.

</details>

```console
$ ./_video/run.sh 03-sleep go run .
boshlandi: siyob
boshlandi: chorsu
boshlandi: oloy
jami: 500.059456ms
(chiqish kodi: 0)
```

`Sleep` ждёт минимум указанное время, не ровно столько. Увеличение до двух секунд в этом примере создаёт лишнее ожидание.
Если поставщик ответит через три секунды, двух уже мало. Эти числа иллюстрируют догадку, это не отдельные измерения.

| Ожидание `main` | Состояние работы | Вывод |
|---|---|---|
| 0,5 с | секундная работа не завершена | результат теряется |
| 2 с | секундная работа обычно завершена | лишнее ожидание |
| 2 с | трёхсекундная работа ещё не завершена | результат снова теряется |

## `WaitGroup`: ждать работу, а не время

Нужно узнать, завершились ли запущенные задачи. **WaitGroup** ведёт их счётчик.
`var wg sync.WaitGroup` готов к работе с нулевым значением. `wg` — имя переменной; в импорт добавлен `"sync"`.
`wg.Go(func() { fetch(name) })` запускает анонимную функцию в новой горутине и учитывает задачу.
При возврате функции задача снимается со счётчика. `wg.Wait()` блокирует вызывающую горутину, пока счётчик не станет нулём.
`wg.Go` появился в Go 1.25.

```go filename="_video/04-wg/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

func fetch(name string) {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
}

func main() {
	start := time.Now()
	var wg sync.WaitGroup
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		wg.Go(func() { fetch(name) })
	}
	wg.Wait()
	fmt.Println("jami:", time.Since(start))
}
```

Новые строки: 5 — `sync`, 17 — `wg`, 19 — запуск задачи, 21 — ожидание всех задач.
`func() { … }` — функция без параметров и результата; внутри выполняется `fetch(name)`.

**Прогноз:** **A)** ~1 с и три `tayyor` · **B)** ~3 с и три `tayyor` · **C)** ~0 с, без `tayyor`

<details>
<summary>Ответ</summary>

**A.** Три ожидания перекрываются. B предполагает последовательную работу; C игнорирует `Wait`.

</details>

```console
$ ./_video/run.sh 04-wg go run .
boshlandi: chorsu
boshlandi: siyob
boshlandi: oloy
tayyor: oloy
tayyor: siyob
tayyor: chorsu
jami: 1.000144574s
(chiqish kodi: 0)
```

| Событие | Счётчик | `main` |
|---|---|---|
| регистрация задач | +1 за задачу | в цикле |
| возврат задачи | −1 за задачу | может ждать в `Wait` |
| все задачи вернулись | 0 | переходит за `Wait` |

Задачи могут завершаться уже при регистрации следующих; счётчик не обязан сначала достичь трёх.
Вызовы `wg.Go` при нулевом счётчике должны предшествовать `Wait`. Здесь они в цикле, а `Wait` — после цикла.

| Вариант | Записано в видео, не новый запуск | Сегодняшний запуск |
|---|---|---|
| последовательно | 3.002459679 s | 3.001382105 s |
| `wg.Go` + `Wait` | 1.003058399 s | 1.000144574 s |

Важнее отношение примерно три к одному: ожидания перекрываются. Это не бенчмарк скорости вычислений CPU.
Порядок начала и завершения не гарантирован.

[Документация sync](https://pkg.go.dev/sync#WaitGroup.Go) упорядочивает записи задач до завершения относительно чтения после ожидания.
Гарантия относится к задачам именно этой WaitGroup. Она не делает безопасными конфликтующие записи горутин в общий адрес.

## Прежняя форма: `Add`, `go`, `Done`

В рабочем коде встречается и эта форма. Для нового кода документация рекомендует `wg.Go`.

```go filename="_video/08-adddone/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

func fetch(name string) {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
}

func main() {
	start := time.Now()
	var wg sync.WaitGroup
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		wg.Add(1)
		go func() {
			defer wg.Done()
			fetch(name)
		}()
	}
	wg.Wait()
	fmt.Println("jami:", time.Since(start))
}
```

Строка 19: `wg.Add(1)` учитывает задачу **до go**. Строки 20–23: `go func() { … }()` запускает анонимную функцию.
Последние `()` означают вызов; `defer wg.Done()` уменьшает счётчик при возврате функции или раскрутке её стека из-за panic.
Строка 25 ждёт всех. Если перенести `Add` внутрь горутины, `Wait` может увидеть ноль и вернуться раньше времени.
Ошибка бывает незаметной; компилятор её не исправляет.

**Прогноз:** **A)** ~1 с · **B)** ~3 с · **C)** счётчик никогда не уменьшается

<details>
<summary>Ответ</summary>

**A.** Задачи в отдельных горутинах, каждая вызывает `Done`. B предполагает последовательность, C — невыполнение `defer`.

</details>

```console
$ ./_video/run.sh 08-adddone go run .
boshlandi: oloy
boshlandi: siyob
boshlandi: chorsu
tayyor: chorsu
tayyor: siyob
tayyor: oloy
jami: 1.000167093s
(chiqish kodi: 0)
```

При panic эта форма не полностью эквивалентна `wg.Go`; разница разобрана в необязательной части.

## Результаты: гонка данных в общем `append`

Теперь map `offers` связывает поставщика с числом товаров: `40`, `120`, `5`.
`fetch(name string) int` возвращает число через `return offers[name]`. Map только читается, не изменяется.
`counts` хранит количества товаров. `var counts []int` — пустой слайс; каждая задача записывает результат `append` в эту переменную.

```go filename="_video/05-append/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

var offers = map[string]int{"chorsu": 40, "oloy": 120, "siyob": 5}

func fetch(name string) int {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
	return offers[name]
}

func main() {
	start := time.Now()
	var wg sync.WaitGroup
	var counts []int
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		wg.Go(func() { counts = append(counts, fetch(name)) })
	}
	wg.Wait()
	fmt.Println("mahsulotlar:", counts)
	fmt.Println("jami:", time.Since(start))
}
```

Новые строки: 9 — `offers`; 11 и 15 — результат `int` и `return`; 21 — `counts`; 23 — общие чтение и запись;
26 — вывод результата. `mahsulotlar` означает «товары», здесь — список количеств.

**Прогноз:** **A)** всегда `[40 120 5]` · **B)** число может потеряться · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B.** Несколько горутин читают и изменяют общий `counts` без синхронизации: это **гонка данных**.
`Wait` ждёт в конце, но не разделяет записи между собой. A предполагает порядок и безопасность; C путает ошибку выполнения с ошибкой компиляции.

</details>

Следующая команда **повторно выполнена в Docker**. `-race` проверяет конфликтующие обращения к памяти в выполненном коде.
`-trimpath` заменяет файловые пути путями модуля. `2>&1` включает поток ошибок; `| sed -n` выводит только выбранные строки.

## Исправление: каждая задача пишет свой элемент

Длина результата известна заранее. `make([]int, len(suppliers))` выделяет нужное число элементов.
Заголовок слайса не меняется; каждая горутина записывает только свой `counts[i]`.

```go filename="_video/06-index/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

var offers = map[string]int{"chorsu": 40, "oloy": 120, "siyob": 5}

func fetch(name string) int {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
	return offers[name]
}

func main() {
	start := time.Now()
	var wg sync.WaitGroup
	suppliers := []string{"chorsu", "oloy", "siyob"}
	counts := make([]int, len(suppliers))
	for i, name := range suppliers {
		wg.Go(func() { counts[i] = fetch(name) })
	}
	wg.Wait()
	fmt.Println("mahsulotlar:", counts)
	fmt.Println("jami:", time.Since(start))
}
```

Строка 21: `suppliers` — слайс имён. Строка 22: длина `counts` тоже три.
Строка 23 даёт индекс `i` и имя `name`. Строка 24 записывает свой элемент; строка 26 ждёт перед чтением.
`:=` в `for i, name := range` создаёт отдельные переменные на каждой итерации, если версия `go` модуля не ниже 1.22.
Здесь `go 1.27`. Присваивание через `=` заранее объявленным переменным под это правило не попадает.

По [официальному правилу](https://go.dev/ref/spec#Variables) каждый элемент слайса считается отдельной переменной.
[Гарантия sync](https://pkg.go.dev/sync#WaitGroup.Go) позволяет читать записи этих задач после `Wait`.
Если другая горутина читает или меняет те же элементы во время работы, нужна отдельная синхронизация.

| Элемент | Кто пишет | После `Wait` |
|---|---|---|
| `counts[0]` | задача chorsu | 40 |
| `counts[1]` | задача oloy | 120 |
| `counts[2]` | задача siyob | 5 |

**Прогноз:** **A)** `[40 120 5]`, без предупреждений · **B)** числа в порядке завершения · **C)** гонка общего `append`

<details>
<summary>Ответ</summary>

**A.** Место выбирается индексом, а не порядком завершения. Общий заголовок не изменяется; B и C относятся к старому коду.

</details>

```console
boshlandi: chorsu
tayyor: chorsu
tayyor: oloy
tayyor: siyob
mahsulotlar: [40 120 5]
jami: 1.000461175s
(chiqish kodi: 0)
```

В этом запуске предупреждений о гонке нет. Один чистый запуск не доказывает отсутствие гонок на всех путях;
главный аргумент здесь — отдельные элементы и `Wait` перед чтением.

## Владелец каждой горутины

В backend-коде может встретиться такой фрагмент. Это не самостоятельная программа, а решение внутри обработчика.
`sendReceipt(o)` отправляет чек для нового заказа `o`. `writeJSON` записывает ответ.

```go
go sendReceipt(o)
writeJSON(w, http.StatusCreated, o)
```

`w` записывает ответ, `http.StatusCreated` — `201`. Вызовы находятся внутри `createOrder` из GB-5.10 и GB-6.08.
Обработчик записывает ответ и возвращается, даже если отправка чека ещё продолжается.

**Вопрос:** кто ждёт эту горутину? **A)** сервер автоматически · **B)** никто · **C)** `main` автоматически

<details>
<summary>Ответ</summary>

**B.** Ожидание здесь не написано. Возврат обработчика сам по себе не останавливает отдельную горутину.
Но завершение программы может оборвать доставку чека. Учёта количества задач тоже нет.
A и C предполагают скрытое ожидание в сервере или `main`.

</details>

**Владелец** — код, отвечающий за запуск и ожидание завершения. Это правило проектирования, а не требование языка Go.
Владелец может передать работу другому явно указанному управляющему коду; ответственность должна оставаться понятной.
В задании `fetchAll` ждёт все запущенные им задачи и только затем возвращается.

| Код | Запускает | Ждёт завершения | При возврате |
|---|---|---|---|
| обработчик с `go sendReceipt(o)` | да | нет | чек ещё может отправляться |
| исправленный `fetchAll` | да | `wg.Wait` | его вызовы `fetch` завершены |

Сигнал остановки через `context` будет в GB-7.03, упорядоченная остановка сервера — в GB-8.03,
работа, переживающая перезапуск процесса, — в GB-9.01.

## Глубже (необязательно): `recover` не защищает другую горутину

В `main` есть `defer` и `recover`, но `panic` возникает в горутине, запущенной через `wg.Go`.

```go filename="_video/07-panic/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
)

func main() {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("ushlandi:", r)
		}
	}()
	var wg sync.WaitGroup
	wg.Go(func() { panic("chorsu: javob buzuq") })
	wg.Wait()
	fmt.Println("tugadi")
}
```

Строки 9–13: отложенная функция `main` сохраняет результат `recover()` в `r` и печатает его, если он не `nil`.
Строка 15 вызывает panic в другой горутине. Строка 17 должна была вывести `tugadi` («завершено»), но до неё выполнение не доходит.

**Прогноз:** **A)** появится `ushlandi` · **B)** программа завершится с panic · **C)** panic будет проигнорирован

<details>
<summary>Ответ</summary>

**B.** `recover` перехватывает panic только в своей горутине, при правильном вызове из отложенной функции.
A распространяет защиту на другую горутину; C предполагает автоматическое исчезновение panic.

</details>

```console
$ ./_video/run.sh 07-panic go run -trimpath .

goroutine 19 [running]:
sync.(*WaitGroup).Go.func1.1()
	sync/waitgroup.go:251 +0x45
panic({0x5593a0?, 0x4a4a60?})
	runtime/panic.go:859 +0x125
main.main.func2()
	github.com/abdurahmon27/bozor/main.go:15 +0x25
sync.(*WaitGroup).Go.func1()
	sync/waitgroup.go:258 +0x4a
created by sync.(*WaitGroup).Go in goroutine 1
	sync/waitgroup.go:238 +0x7d

(chiqish kodi: 1)
```

`ushlandi` — сообщение «перехвачено» — не появилось. `goroutine 19 [running]` указывает горутину с panic.
`main.main.func2` — вторая анонимная функция внутри `main`; `main.go:15` — строка panic.
Строки `sync` и `runtime` — стек вызовов: по нему panic поднят повторно.
`exit status 2` — код программы при panic; `1` в строке скрипта снова относится к `go run`.

`[recovered, repanicked]` означает, что реализация `wg.Go` в Go 1.27.4 перехватила panic и вызвала его снова.
Она не вызывает `Done`: иначе `Wait` мог бы разблокироваться и программа завершилась бы до окончания сообщения panic.
Обычный `defer wg.Done()` уменьшает счётчик и при раскрутке стека. Поэтому формы не полностью эквивалентны при panic.
**Контракт:** функция `f`, переданная в `wg.Go`, не должна паниковать. Возврат и сбор ошибок — тема `errgroup` в GB-7.04.

`recoverPanic` из GB-6.01 тоже защищает только горутину, выполняющую обработчик.
Неперехваченный panic в отдельной горутине `sendReceipt` завершит серверный процесс.

## Частые ошибки

1. **Считать, что `go` гарантирует завершение.** В `02-go` ошибка прошла без сообщения. Исправление: учитывать задачи и вызывать `Wait` до возврата.
2. **Принимать `Sleep` за гарантию ожидания.** Полсекунды в `03-sleep` не дождались результата. Исправление: ждать завершения работы, а не времени.
3. **Считать, что `WaitGroup` защищает общий `append`.** В `05-append` показан настоящий отчёт о гонке. Исправление: заранее `make`, каждой задаче свой `counts[i]`.
4. **Вызывать `Add(1)` внутри горутины.** `Wait` может вернуться до регистрации. Перенесите `Add` перед `go` или используйте `wg.Go`.
5. **Полагаться на `recover` из другой горутины.** В `07-panic` программа завершилась с `exit status 2`. Соблюдайте контракт `f`; внешний `recover` не защищает её.

Первые две ошибки не дают сообщения компилятора. Файлы, строки и исправления для гонки и panic разобраны выше.

```go filename="solution/main.go" showLineNumbers
// bir vaqtda oʻqish. Tarmoq oʻrniga time.Sleep: har yetkazuvchi bir soniyada javob beradi.

	"fmt"
	"sync"
	"time"
)

var offers = map[string]int{"chorsu": 40, "oloy": 120, "siyob": 5}

func fetch(name string) int {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)

// fetchAll har yetkazuvchi uchun fetch'ni chaqiradi va natijalarni xuddi suppliers tartibida qaytaradi:
// counts[i] = fetch(suppliers[i]).
//
// Javob (TASK.md, 1-qadam): har fetch alohida goroutine'da (wg.Go), har goroutine oʻz counts[i]'iga yozadi
// (har element alohida xotira joyi: data race yoʻq), fetchAll qaytishdan oldin hammasini kutadi (wg.Wait).
// fetchAll — bu goroutine'larning egasi: u qaytganda ulardan birortasi ham ishlamayapti.
func fetchAll(suppliers []string, fetch func(string) int) []int {
	counts := make([]int, len(suppliers))
	var wg sync.WaitGroup
	for i, name := range suppliers {
		wg.Go(func() { counts[i] = fetch(name) })
	}
	wg.Wait()
	return counts
}

// fetchAllAddDone — 🟡 javob (TASK.md, 2-qadam): xuddi fetchAll, eski shaklda. wg.Add(1) go'dan OLDIN
// (goroutine ichida emas: aks holda Wait hisob hali nol paytda qaytib ketishi mumkin), Done esa defer bilan.
// wg.Go shu ikki qatorni oʻzi bajaradi, bitta farq bilan: f panic qilsa, wg.Go Done'ni chaqirmaydi va panic'ni
// qayta tashlaydi, Wait ochilib, dastur panic tugashidan oldin chiqib ketmasin deb (src/sync/waitgroup.go).
// Hujjat yangi kodda wg.Go'ni tavsiya qiladi (go doc sync.WaitGroup.Add).
func fetchAllAddDone(suppliers []string, fetch func(string) int) []int {
	counts := make([]int, len(suppliers))
	var wg sync.WaitGroup
	for i, name := range suppliers {
		wg.Add(1)
		go func() {
			defer wg.Done()
			counts[i] = fetch(name)
		}()
	}
	wg.Wait()
	return counts
}

func main() {
	start := time.Now()
	counts := fetchAll([]string{"chorsu", "oloy", "siyob"}, fetch)
	fmt.Println("mahsulotlar:", counts)
	fmt.Println("jami:", time.Since(start))
}
```
