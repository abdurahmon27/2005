## Avval ketma-ket bajarilish

Bu tajribada tarmoq oʻrnida `time.Sleep(time.Second)` bor: yetkazuvchi bir soniya kutib javob bergandek boʻladi.
`fetch` roʻyxatni oʻqishni bildiradi, `name` — yetkazuvchi nomi. Hozir `fetch` natija qaytarmaydi.

```go filename="_video/01-ketma/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func fetch(name string) {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
}

func main() {
	start := time.Now()
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		fetch(name)
	}
	fmt.Println("jami:", time.Since(start))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `package main` | bajariladigan dastur paketi |
| 3–6 | `import` | `fmt` ekranga yozadi, `time` vaqt bilan ishlaydi |
| 8 | `func fetch(name string)` | matn parametrli funksiya; `{}` tana chegarasi |
| 9 | `fmt.Println` | `boshlandi:` va nomni chiqaradi |
| 10 | `time.Sleep(time.Second)` | shu goroutine'ni kamida bir soniya toʻxtatadi |

## `go`: boshlaydi, kutmaydi

Bitta soʻz qoʻshamiz: `go fetch(name)`. **Goroutine** — Go runtime boshqaradigan alohida funksiya bajarilishi.
Runtime — dastur bilan birga ishlaydigan Go yordamchi kodi. `main` ham goroutine'da ishlaydi.
`go` funksiya va argument qiymatlarini chaqiruvchi goroutine'da hisoblaydi, keyin yangi goroutine'ni boshlaydi.
Chaqiruv tugashini kutmaydi; qaytgan natijalar tashlanadi. [Rasmiy qoida](https://go.dev/ref/spec#Go_statements).

```go filename="_video/02-go/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func fetch(name string) {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
}

func main() {
	start := time.Now()
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		go fetch(name)
	}
	fmt.Println("jami:", time.Since(start))
}
```

17-qator oʻzgardi: `fetch(name)` oldida `go`. `main` uchta ishni boshlaydi va `jami`ga oʻtadi.

**Bashorat:** nima chiqadi? **A)** doim uchta `tayyor` · **B)** `jami`, balki `boshlandi` ham · **C)** tugamagan ish haqida xato

## `WaitGroup`: vaqtni emas, ishni kutish

Bizga boshlangan ishlar tugaganini bilish kerak. **WaitGroup** shu ishlar hisobini yuritadi.
`var wg sync.WaitGroup` nol qiymat bilan tayyor. `wg` — oʻzgaruvchi nomi; import'ga `"sync"` qoʻshildi.
`wg.Go(func() { fetch(name) })` nomsiz funksiyani yangi goroutine'da boshlaydi va uni hisobga oladi.
Funksiya qaytsa, ish hisobdan chiqadi. `wg.Wait()` hisob nol boʻlguncha chaqiruvchi goroutine'ni kutdiradi.
`wg.Go` Go 1.25'da qoʻshilgan.

```go filename="_video/04-wg/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

func fetch(name string) {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
}

func main() {
	start := time.Now()
	var wg sync.WaitGroup
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		wg.Go(func() { fetch(name) })
	}
	wg.Wait()
	fmt.Println("jami:", time.Since(start))
}
```

Yangi qatorlar: 5 — `sync`, 17 — `wg`, 19 — ishni boshlash, 21 — hammasini kutish.
`func() { … }` parametrsiz va natijasiz funksiya; uning ichida `fetch(name)` bajariladi.

**Bashorat:** **A)** ~1 s va uchta `tayyor` · **B)** ~3 s va uchta `tayyor` · **C)** ~0 s, `tayyor` yoʻq

<details>
<summary>Javob</summary>

**A.** Uch kutish ustma-ust tushadi. B ishlar hali ham ketma-ket deb oʻylaydi; C `Wait`ni hisobga olmaydi.

</details>

| Hodisa | Hisob | `main` |
|---|---|---|
| ishlar roʻyxatga olinadi | har ishga +1 | siklda |
| ish qaytadi | har ishga −1 | `Wait`da kutishi mumkin |
| barcha ishlar qaytgan | 0 | `Wait`dan keyingi qatorga oʻtadi |

Ishlar roʻyxatga olinayotganda ham tugashi mumkin; hisob doim avval uchga chiqishi shart emas.
Hisob nol paytda boshlanadigan `wg.Go` chaqiruvlari `Wait`dan oldin boʻlsin. Bu kodda ular siklda, `Wait` esa sikldan keyin.

| Variant | Videoda qayd etilgan, qayta bajarilmagan | Bugungi bajarilish |
|---|---|---|
| ketma-ket | 3.002459679 s | 3.001382105 s |
| `wg.Go` + `Wait` | 1.003058399 s | 1.000144574 s |

Muhimi — taxminan uch baravar nisbat: kutishlar ustma-ust tushdi. Bu CPU hisoblash tezligi haqidagi benchmark emas.
Boshlanish va tugash tartibi kafolatlanmaydi.

[Sync hujjati](https://pkg.go.dev/sync#WaitGroup.Go) kutishdan oldingi ish yozuvlarini kutishdan keyingi oʻqish bilan tartiblaydi.
Bu kafolat aynan shu WaitGroup hisoblagan ishlar uchun. U goroutine'larning oʻzaro umumiy manzilga yozishini xavfsiz qilmaydi.

## Eski shakl: `Add`, `go`, `Done`

Ishdagi kodda shu koʻrinish ham uchraydi. Yangi kod uchun hujjat `wg.Go`ni tavsiya qiladi.

```go filename="_video/08-adddone/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

func fetch(name string) {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
}

func main() {
	start := time.Now()
	var wg sync.WaitGroup
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		wg.Add(1)
		go func() {
			defer wg.Done()
			fetch(name)
		}()
	}
	wg.Wait()
	fmt.Println("jami:", time.Since(start))
}
```

19-qator: `wg.Add(1)` ishni **go'dan oldin** hisobga oladi. 20–23: `go func() { … }()` nomsiz funksiyani boshlaydi.
Oxirgi `()` — chaqiruv; `defer wg.Done()` shu funksiya qaytganda yoki panic bilan ochilganda hisobni kamaytiradi.
25-qator hammasini kutadi. `Add`ni goroutine ichiga qoʻysangiz, `Wait` nol hisobni koʻrib erta qaytishi mumkin.
Bu xato baʼzan jimgina kechadi; kompilyator uni tuzatmaydi.

**Bashorat:** **A)** ~1 s · **B)** ~3 s · **C)** hisob hech qachon kamaymaydi

</details>

## Natija: umumiy `append`dagi data race

Endi `offers` map'i yetkazuvchi nomini mahsulotlar soniga bogʻlaydi: `40`, `120`, `5`.
`fetch(name string) int` shu sonni `return offers[name]` bilan qaytaradi. Map faqat oʻqiladi, oʻzgarmaydi.
`counts` — mahsulot sonlari. `var counts []int` boʻsh slice; har ish `append` natijasini shu oʻzgaruvchiga yozadi.

```go filename="_video/05-append/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

var offers = map[string]int{"chorsu": 40, "oloy": 120, "siyob": 5}

func fetch(name string) int {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
	return offers[name]
}

func main() {
	start := time.Now()
	var wg sync.WaitGroup
	var counts []int
	for _, name := range []string{"chorsu", "oloy", "siyob"} {
		wg.Go(func() { counts = append(counts, fetch(name)) })
	}
	wg.Wait()
	fmt.Println("mahsulotlar:", counts)
	fmt.Println("jami:", time.Since(start))
}
```

Yangi qatorlar: 9 — `offers`; 11 va 15 — `int` natija va `return`; 21 — `counts`; 23 — umumiy oʻqish va yozish;
26 — natijani chiqarish. `mahsulotlar` mahsulot sonlari roʻyxatini bildiradi.

**Bashorat:** **A)** doim `[40 120 5]` · **B)** son yoʻqolishi mumkin · **C)** kompilyatsiya xatosi

<details>
<summary>Javob</summary>

**B.** Bir nechta goroutine bitta `counts`ni sinxronlashsiz oʻqib, yozadi: bu **data race**.
`Wait` oxirida kutadi, lekin yozuvchilarni bir-biridan ajratmaydi. A tartib va xavfsizlikni ortiqcha taxmin qiladi; C bu bajarilishdagi xato ekanini oʻtkazib yuboradi.

</details>

Quyidagi buyruq **Docker'da qayta bajarildi**. `-race` bajarilgan yoʻllardagi nizoli xotira murojaatlarini tekshiradi.
`-trimpath` fayl yoʻllarini modul yoʻli bilan chiqaradi. `2>&1` xatolar oqimini ham oladi; `| sed -n` faqat tanlangan qatorlarni chiqaradi.
Birinchi 18 qator va yakuniy natija tanlangan; oʻrtadagi stek qatorlari chiqarilmagan.

```console
$ ./_video/race.sh 05-append go run -trimpath -race . 2>&1 | sed -n '1,18p;/^mahsulotlar:/p;/^jami:/p;/^Found /p;/^exit status/p;/^(chiqish/p'
boshlandi: oloy
boshlandi: chorsu
boshlandi: siyob
tayyor: siyob
tayyor: chorsu
tayyor: oloy
==================
WARNING: DATA RACE
Read at 0x00c000124030 by goroutine 8:
  main.main.func1()
      github.com/abdurahmon27/bozor/main.go:23 +0x54

Previous write at 0x00c000124030 by goroutine 10:
  main.main.func1()
      github.com/abdurahmon27/bozor/main.go:23 +0xc9

Goroutine 8 (running) created at:
  sync.(*WaitGroup).Go()
mahsulotlar: [5 40]
jami: 1.001180388s

(chiqish kodi: 1)
```

`WARNING: DATA RACE` — nizoli murojaatlar topildi. `Read at` — manzildan oʻqish, `Previous write` — oldingi yozish.
Goroutine `8` va `10` — bajarilish identifikatorlari. `main.main.func1` — `main` ichidagi birinchi nomsiz funksiya.
`main.go:23` — xato qator; `+0x54` va `+0xc9` — funksiyadagi mashina kodi siljishlari.
`Found 2 data race(s)` — ikkita hisobot. Bu bajarilishda `120` yoʻqoldi: `[5 40]` qoldi.
Videodagi `[40 5]` ham `120`ni yoʻqotgan; u qayd etilgan eski natija.

`exit status 66` — tekshirilgan dasturning sukutdagi race kodi. Skriptdagi `chiqish kodi: 1` — `go run` buyrugʻining kodi.
Ularni bitta kod deb oʻqimang.

`append` slice sarlavhasini oʻqiydi, kerak boʻlsa massiv ajratadi va yangilangan sarlavhani qaytaradi.
`counts = …` uni umumiy oʻzgaruvchiga yozadi. Quyidagi jadval yoʻqotishning mumkin boʻlgan tartibini koʻrsatadi:

| Qadam | A | B | Oxirgi `counts` |
|---|---|---|---|
| oʻqish | `[40]`ni oldi | `[40]`ni oldi | `[40]` |
| A yozadi | `[40 120]` | eski qiymat hali unda | `[40 120]` |
| B yozadi | tugadi | `[40 5]` | `[40 5]`: `120` yoʻq |

Bu ruxsat etilgan dastur natijalari roʻyxati emas: race bor kodga tayanmang.
Yoʻqotish har bajarilishda koʻrinmaydi. Quyidagi oʻlchov `-race`siz, har ishga bir soniyalik kutish bilan bajarildi.

```console
$ ./_video/olchov.sh append

      8 sonlar=2
    189 sonlar=3
```

`sonlar=1/2/3` — natijada qolgan sonlar miqdori; chapdagi son — nechta bajarilish.
Videodagi eski oʻlchovlarda 200 martadan 7 va 20 tasida son yoʻqolgan. Bugungi taqsimot yuqorida.
Sonlar oʻzgarsa ham xato oʻzgarmaydi: umumiy slice sarlavhasiga bir nechta yozuvchi bor.
Tartib ham yetkazuvchilar tartibiga bogʻlanmagan. Hatto qulf qoʻshishning oʻzi kerakli indeks tartibini bermaydi.

## Tuzatish: har ish oʻz elementiga yozadi

Natija uzunligi oldindan maʼlum. `make([]int, len(suppliers))` shuncha element ajratadi.
Slice sarlavhasi oʻzgarmaydi, har goroutine faqat bitta `counts[i]`ga yozadi.

```go filename="_video/06-index/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
	"time"
)

var offers = map[string]int{"chorsu": 40, "oloy": 120, "siyob": 5}

func fetch(name string) int {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
	return offers[name]
}

func main() {
	start := time.Now()
	var wg sync.WaitGroup
	suppliers := []string{"chorsu", "oloy", "siyob"}
	counts := make([]int, len(suppliers))
	for i, name := range suppliers {
		wg.Go(func() { counts[i] = fetch(name) })
	}
	wg.Wait()
	fmt.Println("mahsulotlar:", counts)
	fmt.Println("jami:", time.Since(start))
}
```

21-qator: `suppliers` nomlar slice'i. 22-qator: `counts` uzunligi ham uch.
23-qator indeksni `i`ga, nomni `name`ga beradi. 24-qator faqat oʻz elementini yozadi; 26-qator oʻqishdan oldin kutadi.
`for i, name := range`dagi `:=` har aylanish uchun alohida oʻzgaruvchi yaratadi: modulning `go` versiyasi kamida 1.22 boʻlganda.
Bu modulda `go 1.27`. Oldindan eʼlon qilingan oʻzgaruvchilarga `=` bilan yozish bu qoida emas.

[Rasmiy qoidada](https://go.dev/ref/spec#Variables) har bir slice elementi alohida oʻzgaruvchi sifatida qaraladi.
[Sync kafolati](https://pkg.go.dev/sync#WaitGroup.Go) shu ishlarning yozuvlarini `Wait`dan keyin oʻqishga imkon beradi.
Boshqa goroutine shu elementlarni ish paytida oʻqisa yoki yozsa, alohida sinxronlash kerak.

| Element | Yozuvchi | `Wait`dan keyin |
|---|---|---|
| `counts[0]` | chorsu ishi | 40 |
| `counts[1]` | oloy ishi | 120 |
| `counts[2]` | siyob ishi | 5 |

**Bashorat:** **A)** `[40 120 5]`, ogohlantirishsiz · **B)** tugash tartibidagi sonlar · **C)** umumiy `append`dagi race

<details>
<summary>Javob</summary>

**A.** Joy indeks bilan tanlanadi, tugash tartibi bilan emas. Bu yerda umumiy sarlavhaga yozish yoʻq; B va C eski kodga mos.

</details>

## Har goroutine'ning egasi

Backend'da quyidagi qisqa parcha uchrashi mumkin. Bu bajariladigan toʻliq dastur emas, handler qarorini koʻrsatadi.
`sendReceipt(o)` yangi `o` buyurtmasi uchun chek yuboradi. `writeJSON` javob yozadi.

```go
go sendReceipt(o)
writeJSON(w, http.StatusCreated, o)
```

`w` — javob yozuvchi, `http.StatusCreated` — `201`. Chaqiruvlar GB-5.10 va GB-6.08'dagi `createOrder` handler'ining ichida.
Chek yuborish uzoq davom etsa ham handler javob yozib qaytadi.

**Savol:** bu goroutine'ni kim kutadi? **A)** server avtomatik · **B)** hech kim · **C)** `main` avtomatik

<details>
<summary>Javob</summary>

**B.** Bu parchada kutish yozilmagan. Handler qaytishi alohida goroutine'ni oʻzidan-oʻzi toʻxtatmaydi.
Ammo dastur tugasa, yarim yoʻldagi chek yoʻqolishi mumkin. Nechta ish borligini hisoblaydigan kod ham yoʻq.
A va C server yoki `main`da yashirin kutish bor deb oʻylaydi.

</details>

**Egasi** — ishni boshlash va tugashini kutish uchun masʼul kod. Bu Go majburlaydigan til qoidasi emas, loyihalash qoidasi.
Egasi ishni boshqa aniq boshqaruvchiga topshirishi ham mumkin; masʼuliyat ochiq boʻlsin.
Vazifadagi `fetchAll` boshlagan barcha ishlarini kutib, keyin qaytadi.

| Kod | Boshlaydi | Tugashni kutadi | Qaytganda |
|---|---|---|---|
| `go sendReceipt(o)`li handler | ha | yoʻq | chek hali yuborilayotgan boʻlishi mumkin |
| tuzatilgan `fetchAll` | ha | `wg.Wait` | oʻzi boshlagan `fetch`lar tugagan |

Toʻxtatish signali GB-7.03'dagi `context`da, serverni tartibli toʻxtatish GB-8.03'da,
jarayon qayta ishga tushsa ham yoʻqolmaydigan ishlar GB-9.01'da oʻtiladi.

## Chuqurroq (ixtiyoriy): `recover` boshqa goroutine'ni himoya qilmaydi

`main`da `defer` va `recover` bor, ammo `panic` `wg.Go` boshlagan goroutine'da yuz beradi.

```go filename="_video/07-panic/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
)

func main() {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("ushlandi:", r)
		}
	}()
	var wg sync.WaitGroup
	wg.Go(func() { panic("chorsu: javob buzuq") })
	wg.Wait()
	fmt.Println("tugadi")
}
```

9–13-qatorlar: `main`ning kechiktirilgan funksiyasi `recover()` natijasini `r`ga oladi va `nil` boʻlmasa chiqaradi.
15-qator boshqa goroutine'da panic qiladi. 17-qator `tugadi` chiqarishi kerak edi, lekin unga yetilmaydi.

**Bashorat:** **A)** `ushlandi` chiqadi · **B)** dastur panic bilan tugaydi · **C)** panic eʼtiborsiz qoladi

<details>
<summary>Javob</summary>

**B.** `recover` faqat shu goroutine'da, kechiktirilgan funksiyadan toʻgʻri chaqirilganda panic'ni ushlaydi.
A himoyani boshqa goroutine'ga yoyadi; C panic avtomatik yoʻqoladi deb oʻylaydi.

</details>

## Koʻp uchraydigan xatolar

1. **`go` yozilsa, ish albatta tugaydi deb oʻylash.** `02-go`da bu jimgina buzildi. Tuzatish: ishlarni roʻyxatga olib, qaytishdan oldin `Wait`.
2. **`Sleep`ni kutish kafolati deb olish.** `03-sleep`dagi yarim soniya natijani kutmadi. Tuzatish: vaqtni emas, ish tugashini kutish.
3. **`WaitGroup` umumiy `append`ni himoyalaydi deb oʻylash.** `05-append`da haqiqiy race hisoboti bor. Tuzatish: oldindan `make`, har ishga alohida `counts[i]`.
4. **`Add(1)`ni goroutine ichiga qoʻyish.** `Wait` roʻyxatga olishdan oldin qaytishi mumkin. `Add`ni `go`dan oldinga chiqaring yoki `wg.Go` ishlating.

```go filename="solution/main.go" showLineNumbers
// bozor import'ining birinchi qadami (GB-7.01): bir nechta yetkazib beruvchidan narx roʻyxatini
// bir vaqtda oʻqish. Tarmoq oʻrniga time.Sleep: har yetkazuvchi bir soniyada javob beradi.
// Toʻliq importer (cmd/import, bekor qilish, chegaralangan worker'lar) GB-7.07'da.
package main

import (
	"fmt"
	"sync"
	"time"
)

// offers — har yetkazib beruvchining narx roʻyxatida nechta mahsulot bor (laboratoriya maʼlumoti).
var offers = map[string]int{"chorsu": 40, "oloy": 120, "siyob": 5}

// fetch — bitta yetkazuvchining roʻyxatini "oʻqiydi" va undagi mahsulotlar sonini qaytaradi.
func fetch(name string) int {
	fmt.Println("boshlandi:", name)
	time.Sleep(time.Second)
	fmt.Println("tayyor:", name)
	return offers[name]
}

// fetchAll har yetkazuvchi uchun fetch'ni chaqiradi va natijalarni xuddi suppliers tartibida qaytaradi:
// counts[i] = fetch(suppliers[i]).
//
// Javob (TASK.md, 1-qadam): har fetch alohida goroutine'da (wg.Go), har goroutine oʻz counts[i]'iga yozadi
// (har element alohida xotira joyi: data race yoʻq), fetchAll qaytishdan oldin hammasini kutadi (wg.Wait).
// fetchAll — bu goroutine'larning egasi: u qaytganda ulardan birortasi ham ishlamayapti.
func fetchAll(suppliers []string, fetch func(string) int) []int {
	counts := make([]int, len(suppliers))
	var wg sync.WaitGroup
	for i, name := range suppliers {
		wg.Go(func() { counts[i] = fetch(name) })
	}
	wg.Wait()
	return counts
}

// fetchAllAddDone — 🟡 javob (TASK.md, 2-qadam): xuddi fetchAll, eski shaklda. wg.Add(1) go'dan OLDIN
// (goroutine ichida emas: aks holda Wait hisob hali nol paytda qaytib ketishi mumkin), Done esa defer bilan.
// wg.Go shu ikki qatorni oʻzi bajaradi, bitta farq bilan: f panic qilsa, wg.Go Done'ni chaqirmaydi va panic'ni
// qayta tashlaydi, Wait ochilib, dastur panic tugashidan oldin chiqib ketmasin deb (src/sync/waitgroup.go).
// Hujjat yangi kodda wg.Go'ni tavsiya qiladi (go doc sync.WaitGroup.Add).
func fetchAllAddDone(suppliers []string, fetch func(string) int) []int {
	counts := make([]int, len(suppliers))
	var wg sync.WaitGroup
	for i, name := range suppliers {
		wg.Add(1)
		go func() {
			defer wg.Done()
			counts[i] = fetch(name)
		}()
	}
	wg.Wait()
	return counts
}

func main() {
	start := time.Now()
	counts := fetchAll([]string{"chorsu", "oloy", "siyob"}, fetch)
	fmt.Println("mahsulotlar:", counts)
	fmt.Println("jami:", time.Since(start))
}
```

`fetchAll`dagi yangi `wg` mahalliy; har chaqiruv oʻz guruhiga ega. `return counts` faqat kutishdan keyin bajariladi.
Bu laboratoriyadagi `fetch` xato qaytarmaydi. Haqiqiy tarmoq xatosini yigʻish va bekor qilish GB-7.03–7.04'da qoʻshiladi.
