## Что вы узнаете

В первом модуле товар в bozor был тремя отдельными переменными:

```go
name := "olma"
price := int64(1_200_000) // tiyin
stock := 40
```

Добавляем второй товар, и появляются ещё три:

```go
name2 := "non"
price2 := int64(400_000)
stock2 := 100
```

Что `name2` и `price2` относятся к одному товару, говорит только цифра `2` в имени. Компилятор этой связи не знает. Как собрать один
товар в одно значение?

**Одна идея:** **struct** — тип, поля которого лежат рядом внутри одного значения. Поле, не указанное в литерале, получает нулевое
значение (zero value) своего типа, а `q := p` копирует все поля: `q` — отдельное значение.

К концу урока вы:

- объявите тип struct через `type Product struct { … }`, прочитаете поле как `p.Name` и запишете как `p.Stock = 40`;
- заполните значение struct по именам полей (литерал структуры, struct literal) и выведете его с именами полей через `%+v`;
- заранее скажете, чем станет неуказанное поле и почему после `q := p` изменение `q` не затрагивает `p`;
- запишете статус заказа через `type OrderStatus int` и `iota`.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| struct (структура) | тип, который собирает несколько именованных полей в одно значение: `type Product struct { … }` | struct |
| литерал структуры | запись значения struct в коде по именам полей: `Product{Name: "non"}`; неуказанное поле получает zero value | struct literal |
| iota | номер строки внутри блока `const ( … )`: начинается с 0, в каждой строке растёт на 1 | iota |

Два вспомогательных понятия: `%+v` (выводит struct с именами полей) и `type OrderStatus int` (новый тип на основе `int`).

В этом уроке появляются новые типы: `Product`, `OrderItem`, `Order` и `OrderStatus`. Это **доменные типы** bozor, то есть понятия
магазина. Следующие уроки строятся на них.

## Проблема: три переменные — это ещё не товар

Шесть переменных выше никак не связаны друг с другом. Если товаров десять, вы сами следите за тридцатью переменными, тридцатью
именами и цифрами в конце имён. Чтобы передать товар в функцию, придётся написать три параметра для трёх значений. Нужно другое:
собрать название, цену и остаток в **одно** значение.

Сегодня мы делаем три вещи:

1. **struct** — тип, который собирает несколько именованных полей в одно значение;
2. **литерал структуры и zero value** — заполнение значения по именам полей;
3. **iota** — последовательно пронумерованные константы для статусов заказа.

## Struct: именованные поля, одно значение

Для объявления нового типа есть ключевое слово `type`. Запись `type Product struct { … }` читается так: «новый тип `Product`, его
вид — список полей». **Поле** (field) — это имя и его тип. Первая программа (`_video/01-product/main.go`):

```go filename="_video/01-product/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	p := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	fmt.Println(p.Name, p.Price)
	fmt.Printf("%+v\n", p)
}
```

Строки 1–3 знакомы по GB-1.01 (`package main`, `import "fmt"`), строка 13 — `func main()`. Новые строки:

| Строка | Код | Что делает |
|---|---|---|
| 5 | `// Product — katalogdagi bitta mahsulot.` | комментарий (GB-1.03): говорит, что это за тип («`Product` — один товар каталога») |
| 6 | `type Product struct {` | `type` объявляет новый тип с именем `Product`. `struct` — вид типа: внутри фигурных скобок список полей. Заканчивается `}` в строке 11 |
| 7 | `ID    int64` | поле: сначала **имя** (`ID`, номер товара), затем **тип** (`int64`, GB-1.03) |
| 8 | `Name  string` | `Name` — название товара, текст |
| 9 | `Price int64 // tiyin` | `Price` — цена, как в GB-1.03, в тиынах |
| 10 | `Stock int` | `Stock` — остаток на складе |
| 14 | `p := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}` | **литерал структуры**: `Product`, затем в фигурных скобках пары `Поле: значение` через запятую. Результат попадает в переменную `p` (`:=`, GB-1.02) |
| 15 | `fmt.Println(p.Name, p.Price)` | `p.Name` читает поле `Name` значения `p`: точка выбирает поле. `tc.name` в GB-1.08 работал так же. `Println` печатает два значения через пробел |
| 16 | `fmt.Printf("%+v\n", p)` | `%+v` печатает struct целиком; знак `+` добавляет перед каждым значением имя поля |

Два замечания. Первое: колонки (`ID    int64`, `Name  string`) выровнены `go fmt` (GB-1.01), для Go выравнивание смысла не имеет.
Второе: имена типа и полей начинаются с заглавной буквы. Причину объяснит
[GB-2.06 · Paketlar: katta harf, internal/ va loyiha tuzilishi](/lab/youtube/gb/gb-2-06/ru), пока просто пишите так.

Что напечатают две последние строки? Предположите оба результата сами.

```console
$ ./_video/run.sh 01-product go run .
olma 1200000
{ID:1 Name:olma Price:1200000 Stock:40}
```

В первой строке два поля, `Println` разделил их пробелом. Во второй строке в фигурных скобках имя, двоеточие и значение каждого
поля, в порядке объявления. Текст напечатан без кавычек: так пишет `%v`.

Проверим, зачем нужен `+`. Следующей программы **нет** в папке курса; мы запустили её в отдельной папке с тем же `go.mod`. Во всех
трёх строках один и тот же `p`:

```go
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	p := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	fmt.Printf("%v\n", p)
	fmt.Printf("%+v\n", p)
	fmt.Println(p)
}
```

```console
$ go run .
{1 olma 1200000 40}
{ID:1 Name:olma Price:1200000 Stock:40}
{1 olma 1200000 40}
```

`%v` и `Println` дают только значения, без имён. `%+v` добавляет имена, поэтому при проверке полей удобен именно он.

## Неуказанное поле: zero value

Теперь в переменной `n` мы не пишем два поля: хлеб, цена 400 000 тиын. `ID` и `Stock` отсутствуют
(`_video/02-nol/main.go`, две строки внутри `main`):

```go
n := Product{Name: "non", Price: 400_000}
fmt.Printf("%+v\n", n)
```

Скомпилируется ли эта строка? Если да, что будет напечатано?

**A)** `{ID:0 Name:non Price:400000 Stock:0}` · **B)** `{Name:non Price:400000}` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**A.** Код компилируется, и печатаются все четыре поля. Поле, не указанное в литерале, получает **zero value** своего типа:
`0` для `int64`, `""` для `string`, `0` для `int`. Если вы выбрали **B**, вы решили, что struct состоит только из указанных полей:
поля struct заданы в объявлении типа, а литерал лишь даёт им значения. Если вы выбрали **C**, вы решили, что писать нужно все поля:
в литерале с именами полей это не обязательно, порядок тоже свободный
([Go spec: Composite literals](https://go.dev/ref/spec#Composite_literals)).

</details>

```console
$ ./_video/run.sh 02-nol go run .
{ID:0 Name:non Price:400000 Stock:0}
```

`ID:0` и `Stock:0` — неуказанные поля. Остаток нового товара равен нулю: это осмысленное начало, `Stock` вы запишете позже.

## В памяти: struct — одно значение, `q := p` — копия

Проследим код в памяти (`_video/03-nusxa/main.go`, тело `main`):

```go
p := Product{ID: 1, Name: "olma", Price: 1_200_000}
p.Stock = 40
q := p
q.Stock = 0
fmt.Println(p.Stock, q.Stock)
```

Когда литерал выполнился, ярлык `p` прикреплён к **одному** значению с четырьмя полями. Поля лежат рядом внутри этого значения, а
не как отдельные переменные. `Stock` не указан, поэтому он `0`.

```text
p ──▶ ┌───────────────────┐
      │ ID     1          │
      │ Name   "olma"     │
      │ Price  1200000    │
      │ Stock  0          │
      └───────────────────┘   ← одно значение, четыре поля
```

Вторая строка **записывает** одно поле через точку: `p.Stock = 40`, остальные три поля не меняются. Затем `q := p`: `:=` объявляет
новую переменную (GB-1.02). После этого `Stock` у `q` становится `0`. Какие два числа попадут на экран?

**A)** `0 0` · **B)** `40 0` · **C)** `40 40`

<details>
<summary>Ответ</summary>

**B: `40 0`.** `q := p` **копирует struct целиком**: `q` получает своё отдельное значение с четырьмя полями. `q.Stock = 0`
меняет только `q`, а в `p` остаётся `40`. Если вы выбрали **A**, вы решили, что `q` и `p` — два имени одного значения: нет, после
копирования значений два. Если вы выбрали **C**, вы решили, что запись `q.Stock = 0` вообще не сработала: она сработала в `q`.

</details>

Память после каждой строки:

| Строка | Код | `p` | `q` | Экран |
|---|---|---|---|---|
| 1 | `p := Product{ID: 1, Name: "olma", Price: 1_200_000}` | `{ID:1 Name:olma Price:1200000 Stock:0}` | — | |
| 2 | `p.Stock = 40` | `{ID:1 Name:olma Price:1200000 Stock:40}` | — | |
| 3 | `q := p` | `{… Stock:40}` | `{ID:1 Name:olma Price:1200000 Stock:40}` — **новое** значение, копия четырёх полей | |
| 4 | `q.Stock = 0` | `{… Stock:40}` | `{… Stock:0}` | |
| 5 | `fmt.Println(p.Stock, q.Stock)` | | | `40 0` |

```console
$ ./_video/run.sh 03-nusxa go run .
40 0
```

Когда struct передают в функцию как аргумент, копируется так же: функция работает со своей копией
([Go spec: Calls](https://go.dev/ref/spec#Calls), [Go FAQ: pass by value](https://go.dev/doc/faq#pass_by_value)). Если один
товар нужно менять из нескольких мест, нужен указатель (pointer): его объясняет
[GB-2.04 · Pointer: nusxa yoki umumiy qiymat](/lab/youtube/gb/gb-2-04/ru).

**Одна оговорка.** Если поле — слайс, `=` копирует только **заголовок** слайса (длину, ёмкость и ссылку на массив); элементы остаются
в общем массиве, как в GB-2.01. Проверим: следующей программы **нет** в папке курса, мы запустили её в отдельной папке (`Order` здесь
сокращён, полностью он описан в следующем разделе):

```go
package main

import "fmt"

// OrderItem — buyurtmadagi bitta qator.
type OrderItem struct {
	ProductID int64
	Price     int64 // tiyin, buyurtma paytidagi narx
	Quantity  int
}

// Order — bitta buyurtma.
type Order struct {
	ID    int64
	Items []OrderItem
}

func main() {
	a := Order{ID: 1, Items: []OrderItem{{ProductID: 1, Price: 1_200_000, Quantity: 3}}}
	b := a
	b.ID = 2
	b.Items[0].Quantity = 99
	fmt.Println(a.ID, b.ID)
	fmt.Println(a.Items[0].Quantity, b.Items[0].Quantity)
}
```

```console
$ go run .
1 2
99 99
```

Поле `ID` скопировалось: `1 2`. Но `b.Items[0].Quantity = 99` изменило и `a`, потому что `a.Items` и `b.Items` смотрят на один массив:
`99 99`. Правило: struct копируется, а элементы слайса внутри него — нет.

## Типы заказа: `OrderItem` и `Order`

Каждая строка заказа — `OrderItem`: какой товар, сколько штук и по какой цене.

```go
// OrderItem — buyurtmadagi bitta qator.
type OrderItem struct {
	ProductID int64
	Price     int64 // tiyin, buyurtma paytidagi narx
	Quantity  int
}
```

- `ProductID` — **ID** товара, а не сам товар. В строке нет значения `Product`, только число, которое на него указывает.
- `Price` — цена **этой строки**. Это решение bozor: цена копируется из товара в момент заказа. Если потом цена товара изменится,
  сумма старого заказа не изменится.
- `Quantity` — количество штук в этой строке.

В `Order` три поля:

```go
// Order — bitta buyurtma.
type Order struct {
	ID     int64
	Items  []OrderItem
	Status OrderStatus
}
```

- `ID` — номер заказа;
- `Items` имеет тип `[]OrderItem`: слайс из `OrderItem` (GB-2.01). Тип поля может быть и слайсом, и другим struct;
- `Status` имеет тип `OrderStatus`: его мы напишем прямо сейчас.

`Order` стоит **раньше** `OrderStatus`, но код компилируется: порядок объявлений на уровне файла для Go не важен
([Go spec: Declarations and scope](https://go.dev/ref/spec#Declarations_and_scope)). В `main.go` из папки порядок именно такой.

## Статус: `type OrderStatus int` и `iota`

У заказа четыре статуса: новый, оплаченный, отправленный и отменённый. Хранить их мы будем числами, а в коде писать именами:

```go
// OrderStatus — buyurtma holati.
type OrderStatus int

const (
	StatusNew OrderStatus = iota
	StatusPaid
	StatusShipped
	StatusCancelled
)
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `// OrderStatus — buyurtma holati.` | комментарий («`OrderStatus` — статус заказа») |
| 2 | `type OrderStatus int` | **новый тип** на основе `int`: внутри обычное число, а имя говорит, что это число — статус |
| 4 | `const (` | `const` со скобками (GB-1.03) объявляет несколько констант в одном блоке |
| 5 | `StatusNew OrderStatus = iota` | `iota` — номер строки внутри этого блока, отсчёт **с нуля**. Тип `StatusNew` — `OrderStatus`, значение `0` |
| 6–8 | `StatusPaid` и следующие | в строке без выражения **повторяются** и тип, и `= iota`, только `iota` растёт на 1 |

Результат:

| Константа | `iota` | Значение |
|---|---|---|
| `StatusNew` | 0 | `0` |
| `StatusPaid` | 1 | `1` |
| `StatusShipped` | 2 | `2` |
| `StatusCancelled` | 3 | `3` |

Это правило Go: [Go spec: Iota](https://go.dev/ref/spec#Iota) и [Constant declarations](https://go.dev/ref/spec#Constant_declarations)
(строка без выражения повторяет предыдущую).

**`OrderStatus` — отдельный тип.** **Переменную** типа `int` на место `OrderStatus` подставить нельзя. Мы проверили: следующей
программы **нет** в папке курса, мы запустили её в отдельной папке.

```go
package main

import "fmt"

// OrderStatus — buyurtma holati.
type OrderStatus int

const (
	StatusNew OrderStatus = iota
	StatusPaid
	StatusShipped
	StatusCancelled
)

func main() {
	n := 1
	var s OrderStatus = n
	fmt.Println(s)
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:17:22: cannot use n (variable of type int) as OrderStatus value in variable declaration
```

Ошибка: строка 17, столбец 22, `n` (переменную типа `int`) нельзя использовать как значение `OrderStatus`. Но **константу**
компилятор принимает, даже `99`, которого нет в списке. Замените функцию `main` в программе выше на следующую (мы запускали именно так):

```go
func main() {
	var s OrderStatus = 99
	fmt.Println(s, s == StatusCancelled)
}
```

```console
$ go run .
99 false
```

Значит, этот тип не отвергает недопустимый статус: тип — это имя и проверенная переменная, а не список значений
([Go spec: Assignability](https://go.dev/ref/spec#Assignability)). Проверку значения мы напишем сами в следующих уроках.

## Собираем всё вместе: строим заказ

Теперь в `main` мы собираем заказ в три шага. Это `main.go` из папки: его строки 1–49 совпадают с `_video/04-order/main.go`. Две функции


Новые строки внутри `main`:

| Строка | Код | Что делает |
|---|---|---|
| 38 | `p := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}` | **первый шаг**: то же яблоко в переменной `p` |
| 39–44 | `o := Order{ … }` | **второй шаг** (первый — строка 38): литерал `Order`. `ID: 1` и `Items:` — литерал слайса из `OrderItem` (строки 41–43). Запятые в конце строк — как в GB-1.08 |

предскажите сами.

**A)** `true 0` · **B)** `false 0` · **C)** `panic` (потому что `Items` равен nil)

<details>
<summary>Ответ</summary>

**A: `true 0`.** `Order` с zero value — это новый заказ, потому что `StatusNew` равен нулю. `Items` — nil-слайс: длина `0`, panic нет
([Go spec: The zero value](https://go.dev/ref/spec#The_zero_value), [Length and capacity](https://go.dev/ref/spec#Length_and_capacity)).
Если вы выбрали **B**, вы решили, что `Status` — «не выбранный» статус: в Go это `0`, то есть первая константа списка.
**C** — длина nil-слайса panic не вызывает; panic был бы при чтении по индексу (`Items[0]`).

</details>

```console
$ go run .

true 0
```

В первой строке `Items` — единственный элемент слайса в квадратных скобках, со своими фигурными скобками. `Status:0`: `%+v` пишет
число статуса; вывод имени (метод `String()`) появится в [GB-2.05 · Metodlar: value receiver yoki pointer receiver](/lab/youtube/gb/gb-2-05/ru).
Вторая строка — `true 0`. Список упорядочен намеренно: zero value — осмысленный статус, то есть новый заказ.

Память: `empty` — значение `Order`, его поля:

| Поле | Значение в `empty` | Почему |
|---|---|---|
| `ID` | `0` | zero value типа `int64` |
| `Items` | `nil`, `len` 0 | zero value слайса |
| `Status` | `0` = `StatusNew` | основа `OrderStatus` — `int`, zero value `0` |

## Глубже (необязательно): вставка значения в середину списка `iota`

Статусы хранятся как числа: их записывают в файл или в базу (это мы сделаем в 3-м и 5-м модулях). Представьте, что кто-то добавил после
`StatusNew` новый статус `StatusReserved` — «зарезервирован» (`_video/06-iota/main.go`):

```go
const (
	StatusNew OrderStatus = iota
	StatusReserved
	StatusPaid
	StatusShipped
	StatusCancelled
)

func main() {
	fmt.Println(StatusPaid, StatusShipped)
}
```

Чему теперь равны `StatusPaid` и `StatusShipped`?

**A)** `1 2`, как раньше · **B)** `2 3` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `2 3`.** `iota` — номер строки, поэтому `StatusReserved` получил 1, а все константы после него сдвинулись на единицу.
Если вы выбрали **A**, вы решили, что константа хранит своё число вместе с именем: число считается от места в списке.
**C** — код корректен, компилятор не считает такое изменение ошибкой.

</details>

```console
$ ./_video/run.sh 06-iota go run .
2 3
```

Следствие: «оплаченный» заказ, сохранённый в базе как `1`, теперь читается как «зарезервированный». Компилятор и `go vet` молчат.
Правило: **в сохраняемый список `iota` новое значение добавляют только в конец.** Другие пути: записать число у каждой константы явно
(`StatusPaid OrderStatus = 1`) или хранить в базе название статуса. В `tekshiruv_test.go` из папки курса `TestHolatRaqamlari`
поэтому закрепляет числа `0, 1, 2, 3`: если вставить значение в середину списка, тест упадёт.

## Частые ошибки

**1. Литерал без имён полей.** Литерал можно написать и без имён: значения попадают в поля в порядке объявления. Здесь три
значения, а `Stock` пропущен (`_video/05-xato/main.go`, строка 14):

```go
p := Product{1, "olma", 1_200_000}
```

```console
$ ./_video/run.sh 05-xato go run .
# github.com/abdurahmon27/bozor
./main.go:14:35: too few values in struct literal of type Product
```

Как читать: `./main.go:14:35` — файл, строка, столбец. Строка 14, столбец 35 — закрывающая `}` литерала. Сообщение: `too few values in
struct literal of type Product`, то есть «в литерале структуры типа `Product` слишком мало значений». В литерале без имён
**все** поля должны быть записаны по порядку ([Go spec: Composite literals](https://go.dev/ref/spec#Composite_literals)).

Если написать четыре значения, код скомпилируется: замените строку 14 в `_video/05-xato/main.go` на следующую (мы запускали именно так):

```go
p := Product{1, "olma", 1_200_000, 40}
```

```console
$ go run .
{ID:1 Name:olma Price:1200000 Stock:40}
```

Но в тот день, когда в `Product` добавят пятое поле (`Category string`), сломается каждая такая строка. Литерал с именами полей не
меняется: новое поле получает zero value. Следующая программа показывает оба варианта рядом (её нет в папке курса):

```go
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID       int64
	Name     string
	Price    int64 // tiyin
	Stock    int
	Category string
}

func main() {
	p := Product{1, "olma", 1_200_000, 40}
	fmt.Printf("%+v\n", p)
	q := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	fmt.Printf("%+v\n", q)
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:15:39: too few values in struct literal of type Product
```

Строка 15 (`p := …`) сломалась, а строка 17 (`q := …`) в порядке. Поэтому пишите имена полей.

**2. `q := p` — это два значения, а не два имени.** Самое частое неверное представление: после `q := p` изменение `q` меняет и `p`. Нет:
посмотрите таблицу в разделе «В памяти: struct — одно значение, `q := p` — копия», там `40 0`. Здесь программа не падает, результат просто
отличается от ожидаемого. Если одно значение нужно менять из двух мест, нужен указатель ([GB-2.04](/lab/youtube/gb/gb-2-04/ru)). Помните и о том, что
элементы слайса при копировании не копируются (`99 99`).

**3. Zero value читают как «значение не задано».** У zero value `Stock` — это `0`, а не «неизвестно». Товар с записанным `Stock: 0` и товар
с незаписанным `Stock` struct не различает: у обоих `0`. Для нового товара это осмысленно, но не для каждого поля: сами проверяйте, что
zero value поля осмысленно в вашем домене. Поэтому в `OrderStatus` `StatusNew` поставлен на `0`.

<summary>Подсказка и разбор ответа</summary>

Подсказки (из TASK.md):

- `o.Items` — слайс: `for _, it := range o.Items { … }` передаёт каждую строку в `it` (как `for _, tc := range tests` в GB-1.08).

```go
func orderTotal(o Order) int64 {
	var total int64
	for _, it := range o.Items {
		total += it.Price * int64(it.Quantity)
	}
	return total
}

func canCancel(o Order) bool {
	return o.Status == StatusNew || o.Status == StatusPaid
}
```

типы не смешивает, поэтому `int64(it.Quantity)`. В заказе без строк цикл не выполняется, и `total` остаётся в zero value, то есть `0`.
`canCancel` сравнивает `Status` с двумя константами через `==`; `||` — «или». У заказа с zero value `Status` равен `StatusNew`, поэтому
результат `true`. Проверить ответ можно прямо из папки:
