## Nimani oʻrganasiz

Handler javob yozishdan oldin panic qiladi. Mijoz uzilgan ulanishni oladi, server logidan esa soʻrovni topish qiyin. Har soʻrovga ID, status va log qatorini qanday beramiz?

**Bitta gʻoya:** middleware `http.Handler` oladi va boshqa `http.Handler` qaytaradi. Qaytgan funksiya `next`ni eslab qoladi; `next.ServeHTTP`dan oldingi va keyingi kod oʻralgan handler atrofida ishlaydi. `next`dan keyingi kod faqat chaqiruv oddiy qaytganda bajariladi.

Dars oxirida siz:

- handler'ni oʻrab, metod, yoʻl, status va vaqtni logga yozasiz;
- javob boshlanmagan boʻlsa, handler'dagi panic oʻrniga 500 JSON qaytarasiz;
- soʻrovga ID berib, log qatorini saqlaydigan tartibda zanjir qurasiz.

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| middleware | boshqa handler'dan oldin va keyin ish qoʻshadigan funksiya | middleware |
| panic recovery | joriy soʻrovdagi panic'ni toʻxtatib, nazoratli javob tayyorlash | panic recovery |
| zanjir tartibi | qaysi oʻrovchi oldin ishlashi va oddiy bajarilish qayerga qaytishi | middleware chain |

Ikki yordamchi atamani kerakli joyida ochamiz. **Embedding** — alohida nomsiz, faqat turi bilan eʼlon qilingan maydon. **Request ID** javob va server logidagi bitta soʻrovni belgilaydi.

## Javobdan oldingi panic

Faqat namoyish uchun `cmd/api/handlers.go`dagi `getProduct`ga, `pathID` muvaffaqiyatli tekshirilgach, shu qatorlarni qoʻshamiz. `id == 13` sinov soʻrovini tanlaydi; `panic` oddiy bajarilishni uzadi. Skript buni nusxada qiladi.

```go
	if id == 13 { // vaqtincha: bug oʻrnida
		panic("sinov: 13-mahsulotda bug")

```

Oʻz recovery qatlamimiz boʻlmasa, `net/http` `ServeHTTP`dagi panic'ni oʻzi ushlaydi. U faol funksiya chaqiruvlarini koʻrsatuvchi **stack trace**ni logga yozadi va HTTP/1 ulanishini yopadi. HTTP/2 da oqim uziladi. Bu butun server jarayoni toʻxtadi degani emas. [Handler shartnomasi](https://pkg.go.dev/net/http#Handler) shu xatti-harakatni belgilaydi.

## Middleware shakli va closure

Har bir route atrofida bir xil soʻrov logi kerak. Quyida birinchi variantning toʻliq `_video/v1-log/middleware.go` fayli bor. Qoʻlda tekshirish uchun uni kurs papkasining nusxasidagi `cmd/api/middleware.go` oʻrniga qoʻying. Skript bu nusxani oʻzi tayyorlaydi.

```go filename="_video/v1-log/middleware.go" showLineNumbers
package main

// _video/v1-log: birinchi logRequests — status hali yoʻq (video: shakl-kod).

import (
	"log"
	"net/http"
	"time"

	"github.com/abdurahmon27/bozor/internal/store"
)

func newHandler(st *store.Store) http.Handler {
	return logRequests(newMux(st))
}

func logRequests(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		next.ServeHTTP(w, r)
		log.Printf("%s %q %s", r.Method, r.URL.Path, time.Since(start))
	})
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1, 3 | `package main`, `// …` | bajariladigan dastur paketiga kiradi; izoh namoyish bosqichini bildiradi |
| 5–11 | `import (…)` | log, HTTP, vaqt va mavjud ichki store paketini oladi |
| 13–15 | `newHandler(st *store.Store)` | store koʻrsatkichini oladi, mux quradi va oʻralgan handler qaytaradi |
| 17 | `func logRequests(next http.Handler) http.Handler` | oʻraladigan handler'ni `next` nomi bilan oladi; handler qaytaradi |
| 18 | `return http.HandlerFunc(func(…) {` | nomsiz funksiyani `HandlerFunc`ga oʻgiradi; uning `ServeHTTP` metodi `http.Handler`ga mos. `w` javob yozadi, `r` soʻrovga koʻrsatadi |
| 19 | `start := time.Now()` | shu soʻrovning boshlanish vaqtini saqlovchi mahalliy oʻzgaruvchi yaratadi |
| 20 | `next.ServeHTTP(w, r)` | oʻralgan handler'ni shu writer va soʻrov bilan sinxron bajaradi |
| 21 | `log.Printf(…)` | metod (`%s`), qoʻshtirnoqli yoʻl (`%q`) va vaqtni (`%s`) yozadi; `time.Since(start)` oʻtgan vaqtni oʻlchaydi |
| 22–23 | `})`, `}` | nomsiz funksiya, turga oʻgirish chaqiruvi va tashqi funksiyani yopadi |

Nomsiz funksiya — **closure**: `logRequests` qaytgandan keyin ham `next`ga murojaat qila oladi. Oʻrovchini qurish va soʻrovni bajarish boshqa-boshqa vaqtda boʻladi.

| Payt | Holat | Amal |
|---|---|---|
| server qurilishi | `next = mux` | `logRequests(mux)` bir marta handler qaytaradi |
| birinchi soʻrov | yangi mahalliy `start` | qaytgan handler `start → next → log`ni bajaradi |
| keyingi soʻrov | boshqa mahalliy `start`, oʻsha `next` | qaytgan handler yana ishlaydi |

`cmd/api/main.go`dagi `newServer` `Handler: newHandler(st)`ni oʻrnatadi. Middleware'ni eʼlon qilishning oʻzi uni serverga ulamaydi.

404 qaytaradigan `/products/99` logida nima chiqadi? **A)** metod, yoʻl, vaqt · **B)** ular va 404 · **C)** xato boʻlgani uchun yozuv yoʻq.

<details>
<summary>Javob</summary>

**A.** Format matnida faqat uch maydon bor. `ResponseWriter` yuborilgan statusni soʻrash metodiga ega emas. **B** uchun uni oʻzimiz saqlashimiz kerak. **C** notoʻgʻri: 404 yozadigan handler oddiy qaytadi.

</details>

## Statusni saqlash va nol tuzogʻi

Video writer'ning shu soddaroq oʻrovchisidan boshlaydi:

```go
type statusRecorder struct {
	http.ResponseWriter
	status int
}

func (rec *statusRecorder) WriteHeader(code int) {
	rec.status = code
	rec.ResponseWriter.WriteHeader(code)
}
```

`http.ResponseWriter` — embedding maydon. Maydon nomi `ResponseWriter`; uning `Header` va `Write` kabi metodlari tashqi turga koʻtariladi. Oʻzimiz yozgan `WriteHeader` ustun keladi. `rec *statusRecorder` pointer receiver'i oʻsha struct'ni oʻzgartiradi, shuning uchun `&statusRecorder{…}` uzatamiz. Natijadagi `*statusRecorder` `http.ResponseWriter`ga mos keladi.

`rec.status = code` statusni eslaydi. `rec.ResponseWriter.WriteHeader(code)` ichki writer metodini chaqirib, statusni keyinga uzatadi. U yerda `rec.WriteHeader(code)` yozsak, oʻsha metod oʻzini yana chaqiradi.

Birinchi urinishda `status` nol qiymatda qoladi:

```go
rec := &statusRecorder{ResponseWriter: w}
next.ServeHTTP(rec, r)
log.Printf("%s %q %d %s", r.Method, r.URL.Path, rec.status, time.Since(start))
```

`/health` handler'i faqat `Fprintln` qiladi. Logdagi status qanday boʻladi? **A)** 200 · **B)** 0 · **C)** 404.

<details>
<summary>Javob</summary>

**B: shu tarixiy oʻrovchida 0.** Koʻtarilgan `Write` ichki writer'ni chaqiradi. Ichki writer yashirin 200 yuboradi; tashqi `WriteHeader`imizga kirmaydi. **A** — mijoz olgan status, ammo saqlangan maydon emas. **C** route topilmaganini bildirardi.

</details>

```console
$ curl -sS -s localhost:8765/health
ok
```

`_video/v3-nol`dan yangi loglar:

```text
2026/11/27 22:04:42 GET "/health" 0 14.466µs
2026/11/27 22:04:42 GET "/products/99" 404 155.427µs
```

| Sodda oʻrovchidagi qadam | `rec.status` | Mijoz javobi |
|---|---|---|
| `rec` yaratildi | 0 | boshlanmadi |
| `/health` koʻtarilgan `Write`ni chaqirdi | hali 0 | ichki writer 200 tanladi |
| `/products/99` bizning `WriteHeader(404)`ni chaqirdi | 404 | ichki writer 404 yubordi |

Videodagi tuzatish kutiladigan boshlangʻich qiymatni ochiq beradi:

```go
rec := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
```

`_video/v2-status`ning yangi logi `/health` uchun 200 koʻrsatdi. Yoʻq mahsulot ham, nomaʼlum route ham 404 berdi:

```text
2026/11/27 22:04:42 GET "/products/99" 404 115.584µs
2026/11/27 22:04:42 GET "/health" 200 5.34µs
2026/11/27 22:04:42 GET "/narsalar" 404 20.211µs
```

Quyida koʻrsatilgan papka versiyasi javob boshlanganini, jumladan `Write`ning yashirin 200 ini ham eslaydi. Videodagi sodda recorder har `WriteHeader`da maydonini almashtiradi. Haqiqiy HTTP tekshiruvida `WriteHeader(201); WriteHeader(500)` mijozga 201 yubordi, ammo logda 500 chiqdi. `Write("ok\n"); WriteHeader(500)` esa mijozga 200 yubordi, logda yana 500 chiqdi. Papka endi birinchi statusni saqlab, mos ravishda 201 va 200 yozadi. Takror chaqiruv ichki writer'ga ham uzatiladi: `net/http` odatdagi ogohlantirishini chiqarishi mumkin. Videoning tarixiy variantlarida sodda kod saqlangan.

## Panic recovery va notoʻgʻri tartib

Bu — papkadagi qoʻshimcha himoyalarsiz, `_video/v4-tartib`dagi recovery funksiyasi:

```go
func recoverPanic(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if v := recover(); v != nil {
				log.Printf("panic: %v\n%s", v, debug.Stack())
				writeError(w, http.StatusInternalServerError, apiError{Code: "internal", Message: "ichki xato"})
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

1-qator middleware shaklini saqlaydi. 2-qator soʻrov handler'ini qaytaradi. 3-qator kechiktirilgan nomsiz funksiyani roʻyxatga oladi. 4-qator `recover`ni bevosita uning ichida chaqirib, panic qiymatini `v`ga beradi; panic boʻlmasa `v` — `nil`. 5–6-qator qiymatni logga yozib, umumiy 500 JSON xatosini yuboradi. `%v` panic qiymatini formatlaydi, `\n` yangi qator qoʻshadi. `runtime/debug` paketidagi `debug.Stack()` shu goroutine'ning stack trace'ini qaytaradi. `ichki xato` — mijozga beriladigan umumiy xabar. Oxirgi `}()` kechiktirilgan funksiyani chiqishda chaqiradi; `next.ServeHTTP` ichki handler'ni bajaradi.

Panic matni server logida qoladi. Mijoz stack oʻrniga mavjud `apiError` shaklini oladi. Recovery joriy goroutine'da ishlaydi: handler ochgan boshqa goroutine'dagi panic'ni ushlay olmaydi.

Avval notoʻgʻri tartibni sinaymiz:

```go
return recoverPanic(logRequests(newMux(st)))
```

`recoverPanic` `logRequests`dan tashqarida. Logger soʻrov qatorini `next` oddiy qaytgach yozadi. `/products/13` uchun nima chiqadi? **A)** panic trace va soʻrov qatori · **B)** faqat panic trace · **C)** faqat soʻrov qatori.

<details>
<summary>Javob</summary>

**B.** Tashqi recovery ushlaguncha panic logger'dan oʻtib ketadi. Bajarilish tugab ketgan logger ichidagi `next`dan keyingi qatorga qaytmaydi. **A** uchun recovery logger ichida turishi kerak. **C** esa aniq yozilgan panic logini hisobga olmaydi.

</details>

```console
$ curl -sS -i localhost:8765/products/13
HTTP/1.1 500 Internal Server Error
Content-Type: application/json
Date: Fri, 27 Nov 2026 17:04:43 GMT
Content-Length: 53

{"error":{"code":"internal","message":"ichki xato"}}
```

Yangi qisqartirilgan log: soʻrov qatori yoʻq.

```text
2026/11/27 22:04:43 panic: sinov: 13-mahsulotda bug
goroutine 21 [running]:
…
main.logRequests.func1(…)
…
main.recoverPanic.func1(…)
…
```

| Tartib | Panic yoʻli | Logger'ning `next`idan keyingi kod |
|---|---|---|
| `recoverPanic(logRequests(mux))` | handler → mux → logger → recovery | bajarilmaydi |
| `logRequests(recoverPanic(mux))` | handler → mux → recovery; recovery logger'ga qaytadi | ishlaydi, 500 yozadi |

`main.logRequests.func1` — `logRequests` ichida yaratilgan nomsiz funksiya. Stack trace faol chaqiruvlarni koʻrsatadi; kim kimni chaqirganini ichki qatordan tashqi qatorga qarab oʻqing.

## Javob va loglarda bitta request ID

Bitta xatoli soʻrovning ikkala yozuvini topish uchun boshqa middleware'lardan oldin ID qoʻshamiz:

```go
func requestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("X-Request-Id", rand.Text())
		next.ServeHTTP(w, r)
	})
}
```

3-qator `crypto/rand.Text()` bilan yangi qiymat yaratib, javob sarlavhasini oʻrnatadi. 4-qator `next`ni chaqiradi. Go 1.27.4 da natija 26 ta base32 belgidan iborat. API kamida 128 bit tasodifiylikni kafolatlaydi; kelajak versiyada matn uzunroq boʻlishi mumkin. `Text` Go 1.24 da qoʻshilgan. Bu soʻrovni bogʻlash uchun ID; autentifikatsiya maʼlumoti emas. [rand.Text hujjati](https://pkg.go.dev/crypto/rand#Text).

Server mijoz yuborgan qiymatga ishonish oʻrniga ID'ni oʻzi yaratadi. Ikkala log funksiyasi `w.Header().Get("X-Request-Id")`ni oʻqiydi. Oʻrovchining koʻtarilgan `Header()` metodi ichki writer bilan bir xil sarlavhalar map'iga murojaat qiladi.

| Bosqich | Sarlavhalar map'i | Ishlatilishi |
|---|---|---|
| `requestID` | `X-Request-Id`ni oʻrnatadi | soʻrov ID'sini yaratadi |
| `recoverPanic` | oʻsha map'ni oʻqiydi | panic yozuvi oldiga qoʻshadi |
| `logRequests` | oʻsha map'ni oʻqiydi | soʻrov yozuvi oldiga qoʻshadi |
| javob | shu sarlavhani yuboradi | mijoz oʻsha ID'ni ayta oladi |

Ichki handler'larda bu sarlavhani oʻzgartirmang. ID'ni handler loglariga `context` orqali uzatish [GB-8.02 · tuzilgan loglar va request ID](/lab/youtube/gb#gb-8-02)da oʻrgatiladi.


Qurishda Go tashqi funksiyalarni chaqirishdan oldin ichki chaqiruvlarni hisoblaydi. Qurishda va soʻrovda qaysi biri birinchi ishlaydi? **A)** `requestID` / uning handler'i · **B)** `newMux` / `requestID` qaytargan handler · **C)** `newMux` / mux.

<details>
<summary>Javob</summary>

**B.** Qurish: `newMux → recoverPanic → logRequests → requestID`. Soʻrov tashqaridan kiradi: `requestID → logRequests → recoverPanic → mux → route handler'i`. **A** qurishni soʻrov bajarilishi bilan aralashtiradi. **C** oʻrovchilarni tashlab ketadi.

</details>

Quyida joriy `cmd/api/middleware.go` toʻliq berilgan. Papkadagi himoyalar va vazifa uchun boʻsh joylar ham bor. Kursning boshqa fayllari kerak; `main.go` `newHandler`ni allaqachon ulagan.

```go filename="cmd/api/middleware.go" showLineNumbers
package main

// Middleware (GB-6.01). Har biri bitta shaklda: http.Handler oladi (next) va uni oʻragan yangi
// http.Handler qaytaradi. Qaytgan handler oʻz ishini qiladi va next.ServeHTTP'ni chaqiradi:
// chaqiruvdan oldingi kod soʻrov handler'ga yetguncha, keyingi kod javob yozilgandan keyin ishlaydi.

import (
	"crypto/rand"
	"log"
	"net/http"
	"runtime/debug"
	"time"

	"github.com/abdurahmon27/bozor/internal/store"
)

// newHandler — server'ga beriladigan butun zanjir. Tashqaridan ichkariga:
// requestID → logRequests → recoverPanic → mux → handler.
// Tartib muhim: recoverPanic logRequests'ning ichida boʻlsin, aks holda panic boʻlgan soʻrov
// log'ga tushmaydi (panic logRequests'ning log qatoridan oʻtib ketadi).
func newHandler(st *store.Store) http.Handler {
	// VAZIFA (TASK.md, 1-qadam): requireJSON'ni shu zanjirga qoʻshing.
	return requestID(logRequests(recoverPanic(newMux(st))))
}

// requestID har soʻrovga tasodifiy ID beradi va uni javobning X-Request-Id sarlavhasiga yozadi.
// Mijoz xato haqida shu ID bilan xabar beradi, biz log'dan aynan shu soʻrovni topamiz.
// Mijoz yuborgan X-Request-Id'ga ishonmaymiz: ID'ni har doim server oʻzi yasaydi.
func requestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("X-Request-Id", rand.Text())
		next.ServeHTTP(w, r)
	})
}

// statusRecorder — ResponseWriter'ni oʻrab, handler yozgan status kodni eslab qoladi.
// http.ResponseWriter maydon nomisiz (embedding): Header ichkaridagi writer'niki.
// Birinchi yakuniy status esda qoladi: WriteHeader orqali yoki Write'dagi yashirin 200.
type statusRecorder struct {
	http.ResponseWriter
	status      int
	wroteHeader bool
}

func (rec *statusRecorder) WriteHeader(code int) {
	if rec.wroteHeader {
		// net/http ortiqcha WriteHeader haqida oʻzi ogohlantiradi; status oʻzgarmaydi.
		rec.ResponseWriter.WriteHeader(code)
		return
	}
	rec.ResponseWriter.WriteHeader(code)
	if code >= 100 && code < 200 && code != http.StatusSwitchingProtocols {
		return // 1xx vaqtinchalik javob; yakuniy status hali keladi.
	}
	rec.status = code
	rec.wroteHeader = true
}

func (rec *statusRecorder) Write(b []byte) (int, error) {
	if !rec.wroteHeader {
		rec.status = http.StatusOK
		rec.wroteHeader = true
	}
	return rec.ResponseWriter.Write(b) // ichki Write 200 va Content-Type'ni oʻzi tanlaydi.
}

// Unwrap ichkaridagi asl writer'ni qaytaradi: http.ResponseController (Flush va boshqalar)
// oʻralgan writer orqali ham ishlashi uchun (go doc net/http.NewResponseController).
func (rec *statusRecorder) Unwrap() http.ResponseWriter {
	return rec.ResponseWriter
}

// logRequests har soʻrovdan keyin bitta qator yozadi: ID, metod, yoʻl, status, vaqt.
// status 200'dan boshlanadi: handler WriteHeader'ni chaqirmay Write qilsa, javob 200 boʻladi (GB-4.03),
// Write birinchi yashirin 200'ni ham eslab qoladi (videodagi soddaroq variantdan farqi).
// Yoʻl %q bilan: mijoz yoʻlga yangi qator (%0A) yashirib, log'ga soxta qator qoʻsha olmaydi.
func logRequests(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		rec := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
		next.ServeHTTP(rec, r)
		log.Printf("%s %s %q %d %s", w.Header().Get("X-Request-Id"),
			r.Method, r.URL.Path, rec.status, time.Since(start))
	})
}

// recoverPanic — GB-2.09'dagi safely, har soʻrov uchun: handler'dagi panic'ni toʻxtatadi,
// stack'ni log'ga yozadi va mijozga 500 + bizning JSON xato shaklini qaytaradi.
// Videodagidan ikki farq (README, «recoverPanic: videodan tashqari ikki himoya»):
//   - http.ErrAbortHandler — "javobni ataylab uz" degan panic (go doc net/http.ErrAbortHandler):
//     uni toʻxtatmaymiz, net/http'ning oʻziga qaytaramiz;
//   - handler javobni yozishni boshlagan boʻlsa (status yoki body ketgan), 500'ni yuborib boʻlmaydi:
//     yarim javob oxiriga JSON qoʻshilib qoladi. Shunda panic'ni log'ga yozib, javobni ErrAbortHandler
//     bilan uzamiz: mijoz buzuq 200 emas, uzilgan javob oladi. Bu holda logRequests qatori yozilmaydi,
//     panic qatori esa ID bilan logda bor.
//
// Eslatma: handler oʻzi ishga tushirgan goroutine'dagi panic'ni bu middleware ushlamaydi (u boshqa
// goroutine'ning stack'ida; recover faqat panic qilgan goroutine'da ishlaydi) — bunday panic butun serverni yiqitadi.
func recoverPanic(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		sw := &startWriter{ResponseWriter: w}
		defer func() {
			if v := recover(); v != nil {
				if v == http.ErrAbortHandler {
					panic(v)
				}
				log.Printf("%s panic: %v\n%s", w.Header().Get("X-Request-Id"), v, debug.Stack())
				if sw.started {
					panic(http.ErrAbortHandler)
				}
				writeError(w, http.StatusInternalServerError, apiError{Code: "internal", Message: "ichki xato"})
			}
		}()
		next.ServeHTTP(sw, r)
	})
}

// startWriter javob boshlanganini (WriteHeader yoki Write chaqirilganini) eslab qoladi: recoverPanic uchun.
type startWriter struct {
	http.ResponseWriter
	started bool
}

func (sw *startWriter) WriteHeader(code int) {
	sw.started = true
	sw.ResponseWriter.WriteHeader(code)
}

func (sw *startWriter) Write(b []byte) (int, error) {
	sw.started = true
	return sw.ResponseWriter.Write(b)
}

func (sw *startWriter) Unwrap() http.ResponseWriter {
	return sw.ResponseWriter
}

// requireJSON — VAZIFA (TASK.md, 1-qadam): POST soʻrovida Content-Type application/json
// boʻlmasa — 415 va bizning xato shaklimiz. Hozircha hech narsa tekshirmaydi.
func requireJSON(next http.Handler) http.Handler {
	return next
}

// muxErrors — 🟡 ixtiyoriy (TASK.md, 2-qadam): mux'ning oʻz 404/405 javoblarini JSON qilish.
// Hozircha mux'ni oʻzgarishsiz qaytaradi.
func muxErrors(mux *http.ServeMux) http.Handler {
	return mux
}
```

Oldingi misollarga qoʻshilgan qismlarni tushuntiramiz:

| Qatorlar | Oʻzgarish |
|---|---|
| 8, 11 | ID va stack trace uchun `crypto/rand` hamda `runtime/debug` olinadi |
| 21–34 | butun zanjir ulanadi; ID `next`dan oldin oʻrnatiladi |
| 39–64 | `wroteHeader` — birinchi yakuniy statusni eslovchi boolean. `WriteHeader` uzatadi, lekin saqlangan statusni almashtirmaydi. `Write` yashirin 200 ni saqlab, bevosita ichki writer'ga beradi; kontentni aniqlash saqlanadi |
| 52–54 | 100–199 axborot javoblari: yakuniy statusni yopmaydi; 101 protokolni almashtiradi va boshlangan javob deb olinadi |
| 69–70 | `Unwrap` ichki writer'ni `http.NewResponseController`ga ochadi |
| 79–83 | har soʻrovga yangi recorder yaratiladi, `next`ga uzatiladi; ID, metod, qoʻshtirnoqli yoʻl, status va vaqt yoziladi |
| 101–114 | `sw` — `startWriter`; `defer` panic'ni ushlaydi, `ErrAbortHandler`ni qayta beradi, panic'ni yozadi, javob boshlanganini tekshiradi va mumkin boʻlsagina 500 yozadi |
| 119–135 | `started` avval `false`; `WriteHeader` va `Write` uni `true` qilib, chaqiruvni uzatadi. `[]byte`, `(int, error)` va qaytgan juftlik writer shartnomasidan |
| 140–147 | `requireJSON` va `muxErrors` hozir kirgan qiymatni oʻzgartirmay qaytaradi; ularni yozish va ulash — vazifa |

`http.ErrAbortHandler` — `net/http`ga yana stack yozmasdan javobni uzishni bildiradigan maxsus panic qiymati. Javob boshlangan boʻlsa, yangi 500 uning statusi yoki body'sini almashtira olmaydi. Papka panic'ni logga yozib, yarim javobga xato JSON qoʻshish oʻrniga javobni uzadi. Shu yoʻlda va ataylab uzishda soʻrov logi yozilmaydi. Yuqoridagi 500 va soʻrov logi natijasi javob boshlanmasidan oldingi panic uchun.

`Unwrap` `ResponseController`ning flush kabi amallarini qoʻllaydi. `ResponseWriter` interface'ini embedding qilish `http.Flusher` kabi qoʻshimcha interface'larni avtomatik saqlamaydi.

## Chuqurroq (ixtiyoriy): bitta yoʻl, bitta log qatori

URL yoʻlini mijoz tanlaydi. `%0A` `r.URL.Path`da yangi qatorga ochiladi; `%20` — boʻsh joy. `%s` ishlatadigan logger nima qiladi? **A)** ikkinchi haqiqiy log qatori · **B)** `\n` yozuvi · **C)** server loggacha URL'ni rad etadi.

<details>
<summary>Javob</summary>

**A.** `%s` ochilgan matnni bevosita yozadi. **B** — `%q`ning ishi. **C** route topilmaganini soʻrov logger'gacha yetmagan deb qabul qiladi.

</details>

Mux 404 qaytaradi. Yakuniy logger'da faqat `%q`ni `%s`ga almashtirsak (`_video/v7-s`), yangi logda ikkinchi soxta qator chiqadi:

```text
2026/11/27 21:00:00 soxta-qator 404 20.629µs
```

Papka kodidagi `%q` esa yangi qatorni qoʻshtirnoq ichida `\n` koʻrinishida saqlaydi:

U ishonchsiz log matnidagi qator ajratish belgilarini kodlash yoki tozalashni tavsiya qiladi. `%q` shu yoʻl maydonini himoyalaydi; boshqa maydonlarga himoya avtomatik oʻtmaydi. ## Koʻp uchraydigan xatolar

**Writer'dagi status maydoni tarmoqni oʻzi kuzatadi deb oʻylash.** Yuqoridagi nol status — jim log xatosi: HTTP 200 bilan ishlaydi, saqlangan maydon esa 0. Toʻliq papka kodidagidek boshlangʻich qiymat bering va birinchi aniq yoki yashirin statusni saqlang. Takroriy `WriteHeader` yuborilgan birinchi statusni oʻzgartirmaydi.

**Recovery'ni logger'dan tashqariga qoʻyish.** Yuqoridagi notoʻgʻri tartib 500 qaytaradi, lekin soʻrov qatorini yoʻqotadi. `recoverPanic` `logRequests`ning ichida tursin; shunda oddiy bajarilish logger'ga qaytadi.

**Soʻrovning sarlavha maydonini metod kabi chaqirish.** Bu toʻliq qoʻshimcha dastur kurs papkasida yoʻq. Alohida sinov papkasida `header-error.go` deb saqlang:

```go
package main

import "net/http"

func main() {
	r, _ := http.NewRequest("GET", "http://localhost/health", nil)
	_ = r.Header().Get("Content-Type")
}
```

```console
$ go run header-error.go
# command-line-arguments
./header-error.go:7:6: invalid operation: cannot call r.Header (variable of map type http.Header): http.Header is not a function
```

`./header-error.go:7:6` fayl, qator va ustunni koʻrsatadi. “Cannot call” — chaqirib boʻlmaydi: `r.Header` funksiya emas, map maydoni. `# command-line-arguments` nomlangan fayldan qurilgan vaqtinchalik paketni bildiradi. 7-qatorni `_ = r.Header.Get("Content-Type")`ga tuzating. `w.Header()` javob writer'ining metodi; `r.Header` soʻrov maydoni. `_` qiymatni tashlaydi; bu yerdagi muvaffaqiyatli soʻrov yaratishida qaytgan xato qiymatini ishlatish shart emas.

**Xato yozib, bajarishni davom ettirish.** `requireJSON` 415 yozgach qaytsin. Aks holda ichki handler ham javob yozadi; birinchi status qoladi. `net/http` `superfluous response.WriteHeader call` — ortiqcha chaqiruv haqida xabar berishi mumkin. Boshlangan javobga ikkinchi JSON obyekt qoʻshib, uni tuzatishga urinmang.

## Oʻzingizni tekshiring

1. Middleware imzosi qanday, `next` nima?

<details>
<summary>Javob</summary>

`func(next http.Handler) http.Handler`. `next` — qaytgan closure eslab qoladigan oʻralgan handler.

</details>

2. Recovery nega logger ichida?

<details>
<summary>Javob</summary>

Panic logger'dan oʻtib ketishidan oldin toʻxtaydi. Recovery handler'i oddiy qaytadi, shuning uchun logger'dagi `next`dan keyingi kod ishlaydi. Bu 500 javobini hali yozish mumkin boʻlgan holat uchun.

</details>

3. Papkadagi recorder uchun bashorat qiling: `WriteHeader(201)`, keyin `WriteHeader(500)`. Mijoz va soʻrov logi qaysi statusni oladi?

<details>
<summary>Javob</summary>

Ikkalasida 201. Videodagi dastlabki recorder keyingi 500 ni saqlardi; papkadagi regressiya testi haqiqiy HTTP javobini va logni birga tekshiradi.

</details>
