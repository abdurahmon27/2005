## What you will learn

bozor verifies passwords. How does it identify the sender of the next `GET /me`? How does logout invalidate an old cookie copy?

**The one idea:** a session is a server record saying “this token belongs to this user until this time.” The cookie carries the token; the database stores only its hash. Every protected request checks the record.

By the end you will:

- create a random token and store only its SHA-256 hash;
- pass the user through request context in middleware;
- verify expiry, restarts and logout against Postgres;
- implement logout everywhere until its tests pass.

| Word | Plain meaning | English term |
|---|---|---|
| session | record linking a user, token and expiry | session |
| session token | random secret proving identity | session token |
| session revocation | deleting the record so the next check rejects the token | session revocation |

Two helpers: a **cookie** is a value issued through `Set-Cookie` and returned through `Cookie`. A **request context** carries request-specific values between handlers.

## Random token, only its hash in the database

```go
func newToken() string {
	b := make([]byte, 32)
	rand.Read(b) // Go 1.24+: xato qaytarmaydi
	return base64.RawURLEncoding.EncodeToString(b)
}

// hashToken — bazaga yoziladigan va bazadan qidiriladigan qiymat: tokenning SHA-256 hash'i.
func hashToken(token string) []byte {
	sum := sha256.Sum256([]byte(token))
	return sum[:]
}
```

This is an excerpt from `cmd/api/auth.go`; the complete file is below. Do not run the excerpt alone.

| Line | What it does |
|---|---|
| 1 | `newToken` returns a string |
| 2 | `make([]byte, 32)` creates a 32-byte slice |
| 3 | `crypto/rand.Read` fills it with cryptographic randomness |
| 4 | `RawURLEncoding` encodes bytes as URL-safe text without `=` padding |
| 5 | ends the function |
| 7–8 | comment and `hashToken`: accepts text, returns bytes |
| 9 | `Sum256([]byte(token))` hashes the token string itself: `[32]byte` |
| 10–11 | `sum[:]` returns the whole array as a slice; ends the function |

32 random bytes provide 256 bits; base64url occupies 43 characters. Its alphabet uses letters, digits, `-` and `_`. Encoding is not encryption. SHA-256 produces 32 bytes, or 64 hex characters. Since Go 1.24, `rand.Read` fills the slice completely and never returns an error; failed randomness terminates the program without returning.

Human passwords need argon2id. A random 256-bit token can use fast SHA-256. A read-only database leak does not provide a usable cookie. This does not protect stolen cookies or database write access. [OWASP storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#server-side-session-token-storage) specifies at least 128 random bits and prefers 160 or more.

`00004_users.sql` creates users. `users_email_lower_idx` prevents duplicates by `lower(email)`; login searches using that expression too. The session table is:

```sql filename="migrations/00005_sessions.sql"
-- +goose Up
CREATE TABLE sessions (
    token_hash bytea       PRIMARY KEY,
    user_id    bigint      NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    expires_at timestamptz NOT NULL
);
-- "Hamma qurilmadan chiqish" (DELETE … WHERE user_id = $1) jadvalni oxirigacha oʻqimasin.
CREATE INDEX sessions_user_id_idx ON sessions (user_id);

-- +goose Down
DROP TABLE sessions;
```

`Up` creates; `Down` drops. `bytea` stores bytes; the primary key automatically creates a unique index. `user_id` is a foreign key; `ON DELETE CASCADE` removes sessions with their user. `timestamptz` stores a UTC instant, not the original time zone. `sessions_user_id_idx` supports deletion by user.

## Login: password verification and a cookie

```go
type loginInput struct {
	Email    string `json:"email"`
	Password string `json:"password"`
}

// login — POST /login: parol toʻgʻri boʻlsa yangi session ochadi va tokenni cookie'da qaytaradi.
// Har login yangi token oladi, so'rovda eski session cookie'si bo'lsa, uning qatori o'chiriladi: OWASP
// "Renew the Session ID After Any Privilege Level Change" — yangi ID, eskisi yo'q qilinsin (session fixation).
func (a *api) login(w http.ResponseWriter, r *http.Request) {
	var in loginInput
	if !decodeJSON(w, r, &in) {
		return
	}
	u, err := a.checkPassword(r.Context(), in.Email, in.Password)
	if err != nil {
		writeError(w, err)
		return
	}
	if err := a.endCurrentSession(r); err != nil {
		writeError(w, err)
		return
	}
	token := newToken()
	expires := time.Now().Add(sessionTTL)
	err = a.st.CreateSession(r.Context(), hashToken(token), u.ID, expires)
	if err != nil {
		writeError(w, err)
		return
	}
	setSessionCookie(w, token, expires)
	writeJSON(w, http.StatusOK, u)
}
```

The tags in `loginInput` map `Email` and `Password` to JSON body fields. `a *api` provides store access. `in` holds input; `&in` is its address. `!decodeJSON` means decoding failed: a response was already written, so return.

`u, err :=` receives a user and error. `checkPassword` is a new method using GB-6.03’s `password.Verify`. Each `err != nil` branch ends with `writeError` and `return`.

`endCurrentSession` deletes the presented old cookie’s record. Then generate a token. `time.Now().Add(sessionTTL)` adds `24 * time.Hour` to now. `err =` assigns to an existing variable. `CreateSession` inserts the hash, user ID and expiry. Only after storage succeeds are the cookie and `200` JSON sent. The `json:"-"` tag on `User.PasswordHash` excludes the hash from responses.

**Predict:** the address is absent. **A)** `404` · **B)** `401`, “address missing” · **C)** the same generic `401` as a wrong password.

<details>
<summary>Answer</summary>

</details>

```go
func setSessionCookie(w http.ResponseWriter, token string, expires time.Time) {
	http.SetCookie(w, &http.Cookie{
		Name:     sessionCookie,
		Value:    token,
		Path:     "/",
		Expires:  expires,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
	w.Header().Set("Cache-Control", "no-store")
}
```

`http.SetCookie` creates a header from `&http.Cookie{...}`. `Name` is `session`; `Value` is the token; `Path: "/"` covers this host’s paths; `Expires` is client retention. `HttpOnly` prevents page scripts from reading it. `Secure` requires HTTPS; curl treats `http://localhost` as an exception. `SameSite=Lax` excludes cookies on cross-site POST. Full limits are in [GB-6.07 · cookies and CSRF](/lab/youtube/gb/gb-6-07/en). `no-store` forbids caching the response.

## Every request: cookie → database → context

```go
type userKey struct{}

// requireUser — himoyalangan route'lar uchun middleware (GB-6.01 shakli): cookie'dagi token hash'i
// boʻyicha session egasini topadi va uni soʻrov context'iga qoʻyadi. Topilmasa — 401, handler ishlamaydi.
func (a *api) requireUser(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		c, err := r.Cookie(sessionCookie)
		if err != nil {
			writeError(w, err) // http.ErrNoCookie → 401
			return
		}
		u, err := a.st.UserBySession(r.Context(), hashToken(c.Value))
		if err != nil {
			writeError(w, err) // store.ErrNoSession → 401
			return
		}
		w.Header().Set("Cache-Control", "no-store") // shaxsiy javob: keshda qolmasin (OWASP)
		ctx := context.WithValue(r.Context(), userKey{}, u)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}
```

`userKey struct{}` defines a custom key type with no fields. Keys must be comparable. Go documentation recommends custom types instead of built-in `string` to avoid package collisions.

`requireUser` takes a handler and returns a closure converted to `http.HandlerFunc`. `r.Cookie` reads by name; if absent: `http.ErrNoCookie` → `401` → `return`.

`UserBySession` searches using `hashToken(c.Value)`. Missing or expired session: `ErrNoSession` → `401`. Database failure gives `500`. Success sets `no-store`. `WithValue` derives a new `ctx` from the old context: `userKey{}` → `u`. `r.WithContext(ctx)` returns a shallow request copy with that context. `next.ServeHTTP` calls the handler. The store:

```go
func (s *Store) UserBySession(ctx context.Context, tokenHash []byte) (User, error) {
	var u User
	err := s.pool.QueryRow(ctx, `
		SELECT u.id, u.email
		FROM sessions s JOIN users u ON u.id = s.user_id
		WHERE s.token_hash = $1 AND s.expires_at > now()`,
		tokenHash).Scan(&u.ID, &u.Email)
	if errors.Is(err, pgx.ErrNoRows) {
		return User{}, ErrNoSession
	}
	if err != nil {
		return User{}, fmt.Errorf("session oʻqilmadi: %w", err)
	}
	return u, nil
}
```

`var u User` receives the result. `QueryRow` expects one row; backticks delimit SQL. `s` and `u` are table aliases; `JOIN` attaches the user. `$1` is the hash parameter. `Scan(&u.ID, &u.Email)` fills fields. `pgx.ErrNoRows` becomes a missing session; other errors are wrapped with `%w`. `return u, nil` means success.

`now()` is the **current transaction start time**. For this standalone query it is close to the check. It does not advance with each SELECT in a long transaction.

```go
func currentUser(r *http.Request) store.User {
	u, ok := r.Context().Value(userKey{}).(store.User)
	if !ok {
		panic("currentUser: route requireUser bilan oʻralmagan")
	}
	return u
}
```

The `any` from `Value` is checked with the `.(store.User)` type assertion. `u, ok :=` detects a missing value or wrong type. `!ok` means a programming error: the route lacks its wrapper. An explicit `panic` becomes `500` through `recoverPanic`. Normally, `return u`. The complete routes file:

## Logout: the cookie and row are separate

```go
func (a *api) endCurrentSession(r *http.Request) error {
	c, err := r.Cookie(sessionCookie)
	if err != nil {
		return nil // cookie yoʻq: oʻchiradigan session ham yoʻq
	}
	return a.st.DeleteSession(r.Context(), hashToken(c.Value))
}

// logout — POST /logout: cookie'dagi session qatorini o'chiradi va brauzerga cookie'ni o'chirishni aytadi.
// requireUser'siz: session allaqachon eskirgan yoki o'chirilgan bo'lsa ham javob 204 va cookie tozalanadi.
func (a *api) logout(w http.ResponseWriter, r *http.Request) {
	if err := a.endCurrentSession(r); err != nil {
		writeError(w, err)
		return
	}
	clearSessionCookie(w)
```

`if err := ...; err != nil` declares and checks an error. Failed deletion calls `writeError` and returns. Otherwise clear the cookie and send `204 No Content`, without a body.

Clearing sends an empty value with the same name and `Path`. Go’s `MaxAge: -1` becomes `Max-Age=0`. Other attributes match login. DELETE revokes the session.

**A.** The copy retains the token, but the row is gone. Client retention does not replace server validation.

## Going deeper (optional): timing and security limits

`checkPassword` runs argon2id against `dummyHash` for unknown addresses too. Otherwise early return could reveal account existence through timing. `dummyHash` is computed once at startup. A malformed hash gives `500`. Success clears `u.PasswordHash = ""`: later code does not need it.

The comparison inside `password.Verify` is constant-time. `WHERE token_hash = $1` **has no such guarantee**. Recovering a high-entropy token from its hash is impractical. This does not prove all timing channels safe. A split-token design separates a public identifier and secret; the secret’s hash is compared separately in constant time.

The 24-hour TTL is a lab choice. It is the maximum lifetime: absolute timeout. An inactivity limit, idle timeout, is not implemented yet. Sliding expiry and the absolute limit need separate storage. The application writes using `time.Now()` while Postgres checks: keep clocks aligned.

Each login generates a fresh token and deletes the presented old session. This limits session fixation: retaining a previously known token through login. `SameSite` alone does not replace CSRF protection. Login throttling comes in GB-6.07; real deployment requires HTTPS.

RFC 9110 requires `WWW-Authenticate` on `401`. The lab sends `Cookie realm="bozor"`. It is a custom challenge, not a standard cookie auth-scheme providing automatic login.

<summary>Complete auth.go</summary>

```go filename="cmd/api/auth.go" showLineNumbers
package main

// Login va bekor qilinadigan session'lar (GB-6.04).
//
//	POST /login        parol toʻgʻri → yangi session: tokenning hash'i bazaga, tokenning oʻzi cookie'ga
//	requireUser        cookie → hash → sessions qatori → foydalanuvchi context'ga; yoʻq yoki eski → 401
//	POST /logout       cookie'dagi session qatorini oʻchiradi: shu token bilan keyingi soʻrov 401
//	POST /logout-all   foydalanuvchining hamma session'larini oʻchiradi (VAZIFA, TASK.md)

import (
	"context"
	"crypto/rand"
	"crypto/sha256"
	"encoding/base64"
	"errors"
	"fmt"
	"net/http"
	"time"

	"github.com/abdurahmon27/bozor/internal/password"
	"github.com/abdurahmon27/bozor/internal/store"
)

// sessionCookie — cookie nomi. sessionTTL — session'ning eng uzun umri: login'dan 24 soat keyin u
// baribir tugaydi (absolute timeout). 24 soat — bizning tanlov; OWASP Session Management Cheat Sheet'ning
// misoli ish kuni ilovasi uchun 4–8 soat, harakatsizlik (idle) muddati esa alohida (README).
const (
	sessionCookie = "session"
	sessionTTL    = 24 * time.Hour
)

// newToken — session tokeni: 32 tasodifiy bayt (256 bit), cookie'ga sigʻadigan matn qilib (43 belgi).
func newToken() string {
	b := make([]byte, 32)
	rand.Read(b) // Go 1.24+: xato qaytarmaydi
	return base64.RawURLEncoding.EncodeToString(b)
}

// hashToken — bazaga yoziladigan va bazadan qidiriladigan qiymat: tokenning SHA-256 hash'i.
func hashToken(token string) []byte {
	sum := sha256.Sum256([]byte(token))
	return sum[:]
}

// loginInput — POST /login body'si.
type loginInput struct {
	Email    string `json:"email"`
	Password string `json:"password"`
}

// login — POST /login: parol toʻgʻri boʻlsa yangi session ochadi va tokenni cookie'da qaytaradi.
// Har login yangi token oladi, so'rovda eski session cookie'si bo'lsa, uning qatori o'chiriladi: OWASP
// "Renew the Session ID After Any Privilege Level Change" — yangi ID, eskisi yo'q qilinsin (session fixation).
func (a *api) login(w http.ResponseWriter, r *http.Request) {
	var in loginInput
	if !decodeJSON(w, r, &in) {
		return
	}
	u, err := a.checkPassword(r.Context(), in.Email, in.Password)
	if err != nil {
		writeError(w, err)
		return
	}
	if err := a.endCurrentSession(r); err != nil {
		writeError(w, err)
		return
	}
	token := newToken()
	expires := time.Now().Add(sessionTTL)
	err = a.st.CreateSession(r.Context(), hashToken(token), u.ID, expires)
	if err != nil {
		writeError(w, err)
		return
	}
	setSessionCookie(w, token, expires)
	writeJSON(w, http.StatusOK, u)
}

// setSessionCookie — tokenni cookie qilib yuboradi. Atributlar GB-6.07'da batafsil:
// HttpOnly — sahifadagi skript cookie'ni oʻqiy olmaydi; Secure — brauzer uni faqat HTTPS orqali
// yuboradi (brauzerlar va curl http://localhost'ni istisno qiladi, MDN: Set-Cookie); SameSite=Lax — boshqa
// saytdan kelgan POST'ga qoʻshilmaydi. Cache-Control: no-store — session ID bor javob keshda qolmasin (OWASP).
func setSessionCookie(w http.ResponseWriter, token string, expires time.Time) {
	http.SetCookie(w, &http.Cookie{
		Name:     sessionCookie,
		Value:    token,
		Path:     "/",
		Expires:  expires,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
	w.Header().Set("Cache-Control", "no-store")
}

// clearSessionCookie — brauzerga cookie'ni oʻchirishni aytadi (MaxAge: -1 → "Max-Age=0").
// Bu faqat mijoz tomoni: session'ni bekor qiladigan narsa — bazadagi qatorni oʻchirish.
func clearSessionCookie(w http.ResponseWriter) {
	http.SetCookie(w, &http.Cookie{
		Name:     sessionCookie,
		Value:    "",
		Path:     "/",
		MaxAge:   -1,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
}

// errBadLogin — email yoki parol notoʻgʻri (problemFor → 401, ikkalasiga bir xil matn).
var errBadLogin = errors.New("email yoki parol notoʻgʻri")

// dummyHash — yoʻq email uchun ham argon2id bir marta ishlaydi: javob vaqti email bazada bor-yoʻqligini
// bildirmasin (OWASP Authentication Cheat Sheet, "Authentication Responses").
var dummyHash = password.Hash("bozor: email topilmadi")

// checkPassword — Verify (GB-6.03) ustidagi login tekshiruvi: email boʻyicha foydalanuvchi, keyin argon2id Verify.
func (a *api) checkPassword(ctx context.Context, email, pw string) (store.User, error) {
	u, err := a.st.UserByEmail(ctx, email)
	if errors.Is(err, store.ErrUserNotFound) {
		password.Verify(pw, dummyHash)
		return store.User{}, fmt.Errorf("%w: %w", errBadLogin, err)
	}
	if err != nil {
		return store.User{}, err
	}
	ok, err := password.Verify(pw, u.PasswordHash)
	if err != nil {
		return store.User{}, fmt.Errorf("foydalanuvchi %d: %w", u.ID, err)
	}
	if !ok {
		return store.User{}, fmt.Errorf("%w: foydalanuvchi %d", errBadLogin, u.ID)
	}
	u.PasswordHash = "" // hash bundan keyin kerak emas: javobga yoki log'ga tasodifan chiqmasin
	return u, nil
}

// userKey — context'dagi kalit turi. Oʻz turimiz: boshqa paketning kaliti bilan toʻqnashmaydi
// (go doc context.WithValue: kalit string yoki boshqa ichki tur boʻlmasin).
type userKey struct{}

// requireUser — himoyalangan route'lar uchun middleware (GB-6.01 shakli): cookie'dagi token hash'i
// boʻyicha session egasini topadi va uni soʻrov context'iga qoʻyadi. Topilmasa — 401, handler ishlamaydi.
func (a *api) requireUser(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		c, err := r.Cookie(sessionCookie)
		if err != nil {
			writeError(w, err) // http.ErrNoCookie → 401
			return
		}
		u, err := a.st.UserBySession(r.Context(), hashToken(c.Value))
		if err != nil {
			writeError(w, err) // store.ErrNoSession → 401
			return
		}
		w.Header().Set("Cache-Control", "no-store") // shaxsiy javob: keshda qolmasin (OWASP)
		ctx := context.WithValue(r.Context(), userKey{}, u)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// currentUser — requireUser context'ga qoʻygan foydalanuvchi. Route requireUser bilan oʻralmagan
// boʻlsa — bu dasturchi xatosi: panic, recoverPanic uni 500 qiladi (jim User{} qaytarishdan xavfsizroq).
func currentUser(r *http.Request) store.User {
	u, ok := r.Context().Value(userKey{}).(store.User)
	if !ok {
		panic("currentUser: route requireUser bilan oʻralmagan")
	}
	return u
}

// endCurrentSession — so'rovdagi session cookie'sining qatorini o'chiradi; cookie yo'q bo'lsa hech narsa
// qilmaydi. logout va login (eski session'ni yo'q qilish) ishlatadi.
func (a *api) endCurrentSession(r *http.Request) error {
	c, err := r.Cookie(sessionCookie)
	if err != nil {
		return nil // cookie yoʻq: oʻchiradigan session ham yoʻq
	}
	return a.st.DeleteSession(r.Context(), hashToken(c.Value))
}

// logout — POST /logout: cookie'dagi session qatorini o'chiradi va brauzerga cookie'ni o'chirishni aytadi.
// requireUser'siz: session allaqachon eskirgan yoki o'chirilgan bo'lsa ham javob 204 va cookie tozalanadi.
func (a *api) logout(w http.ResponseWriter, r *http.Request) {
	if err := a.endCurrentSession(r); err != nil {
		writeError(w, err)
		return
	}
	clearSessionCookie(w)
	w.WriteHeader(http.StatusNoContent)
}
```

## Common mistakes

1. **Checking only the hash.** In “Removing the expiry condition,” an expired row returned `200`. Restoring `AND s.expires_at > now()` and restarting changed it to `401`.
2. **Deleting only the cookie.** An old copy works while the record exists. Finish logout after `DeleteSession` succeeds.
3. **Calling `currentUser` on an open route.** `panic("currentUser: route requireUser bilan oʻralmagan")` means the route was not wrapped: a programming error. `recoverPanic` returns `500`. Fix: `a.requireUser(http.HandlerFunc(a.me))`.
4. **Wrapping ordinary logout in `requireUser`.** Expired sessions never reach cookie clearing. Ordinary logout is open; logout-all is protected to obtain the current user.
5. **Treating `Expires` as server expiry.** Client retention differs from server acceptance. Cleanup also cannot replace the expiry check.
