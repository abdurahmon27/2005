## Что вы узнаете

bozor проверяет пароль. Как определить отправителя следующего `GET /me`? Как выход делает старую копию cookie бесполезной?

**Главная идея:** сессия — серверная запись «этот токен принадлежит этому пользователю до этого момента». Cookie переносит токен; база хранит только хеш. Каждый защищённый запрос проверяет запись.

После урока вы сможете:

- создавать случайный токен и хранить только SHA-256;
- передавать пользователя через контекст запроса в middleware;
- проверять срок, перезапуск и выход с Postgres;
- реализовать выход со всех устройств и пройти тесты.

| Слово | Простое значение | Английский термин |
|---|---|---|
| сессия | запись, связывающая пользователя, токен и срок | session |
| токен сессии | случайный секрет, подтверждающий личность | session token |
| отзыв сессии | удаление записи, чтобы следующая проверка отвергла токен | session revocation |

Два вспомогательных понятия: **cookie** — значение из `Set-Cookie`, которое клиент возвращает через `Cookie`. **Контекст запроса** переносит относящиеся к запросу значения между обработчиками.

## Сессия и состояние на двух сторонах

Пароль в каждом запросе снова проходит по сети и требует argon2id. Вход проверяет его один раз, затем используется случайный токен.

`401 Unauthorized` означает, что личность не подтверждена. Что даст `/me` без cookie? **A)** `200` · **B)** `401` · **C)** `404`.

<details>
<summary>Ответ</summary>

**B.** Маршрут есть, но нет подтверждения личности. `404` означает отсутствие маршрута; для `200` нужна сессия.

</details>

|---|---|---|

## Случайный токен, в базе только хеш

```go
func newToken() string {
	b := make([]byte, 32)
	rand.Read(b) // Go 1.24+: xato qaytarmaydi
	return base64.RawURLEncoding.EncodeToString(b)
}

// hashToken — bazaga yoziladigan va bazadan qidiriladigan qiymat: tokenning SHA-256 hash'i.
func hashToken(token string) []byte {
	sum := sha256.Sum256([]byte(token))
	return sum[:]
}
```

Это фрагмент `cmd/api/auth.go`; полный файл ниже. Не запускайте фрагмент отдельно.

| Строка | Что делает |
|---|---|
| 1 | `newToken` возвращает строку |
| 2 | `make([]byte, 32)` создаёт слайс из 32 байтов |
| 3 | `crypto/rand.Read` заполняет криптографической случайностью |
| 4 | `RawURLEncoding` кодирует байты текстом для URL без дополнения `=` |
| 5 | конец функции |
| 7–8 | комментарий и `hashToken`: принимает строку, возвращает байты |
| 9 | `Sum256([]byte(token))` хеширует именно строку токена: `[32]byte` |
| 10–11 | `sum[:]` возвращает весь массив как слайс; конец функции |

32 случайных байта — 256 бит; base64url занимает 43 символа. Алфавит: буквы, цифры, `-`, `_`. Кодирование не является шифрованием. SHA-256 даёт 32 байта, или 64 hex-символа. С Go 1.24 `rand.Read` заполняет слайс полностью и не возвращает ошибку; отказ случайности завершает программу без возврата.

Для человеческого пароля нужен argon2id. Для случайного 256-битного токена достаточно быстрого SHA-256. Утечка базы только на чтение не даёт готовую cookie. Это не защищает от кражи cookie или записи в базу. [Рекомендация OWASP по хранению](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#server-side-session-token-storage) задаёт минимум 128 бит случайности и предпочитает 160 и более.

Пользователей создаёт `00004_users.sql`. Индекс `users_email_lower_idx` запрещает повторы по `lower(email)`; вход ищет по тому же выражению. Таблица сессий:

```sql filename="migrations/00005_sessions.sql"
-- +goose Up
CREATE TABLE sessions (
    token_hash bytea       PRIMARY KEY,
    user_id    bigint      NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    expires_at timestamptz NOT NULL
);
-- "Hamma qurilmadan chiqish" (DELETE … WHERE user_id = $1) jadvalni oxirigacha oʻqimasin.
CREATE INDEX sessions_user_id_idx ON sessions (user_id);

-- +goose Down
DROP TABLE sessions;
```

`Up` создаёт, `Down` удаляет. `bytea` хранит байты; первичный ключ автоматически создаёт уникальный индекс. `user_id` — внешний ключ; `ON DELETE CASCADE` удаляет сессии вместе с пользователем. `timestamptz` хранит момент UTC, не исходный часовой пояс. `sessions_user_id_idx` помогает удалять записи пользователя.

## Вход: проверка пароля и cookie

```go
type loginInput struct {
	Email    string `json:"email"`
	Password string `json:"password"`
}

// login — POST /login: parol toʻgʻri boʻlsa yangi session ochadi va tokenni cookie'da qaytaradi.
// Har login yangi token oladi, so'rovda eski session cookie'si bo'lsa, uning qatori o'chiriladi: OWASP
// "Renew the Session ID After Any Privilege Level Change" — yangi ID, eskisi yo'q qilinsin (session fixation).
func (a *api) login(w http.ResponseWriter, r *http.Request) {
	var in loginInput
	if !decodeJSON(w, r, &in) {
		return
	}
	u, err := a.checkPassword(r.Context(), in.Email, in.Password)
	if err != nil {
		writeError(w, err)
		return
	}
	if err := a.endCurrentSession(r); err != nil {
		writeError(w, err)
		return
	}
	token := newToken()
	expires := time.Now().Add(sessionTTL)
	err = a.st.CreateSession(r.Context(), hashToken(token), u.ID, expires)
	if err != nil {
		writeError(w, err)
		return
	}
	setSessionCookie(w, token, expires)
	writeJSON(w, http.StatusOK, u)
}
```

Теги `loginInput` связывают `Email` и `Password` с JSON-телом. `a *api` даёт доступ к store. `in` — входное значение; `&in` — его адрес. `!decodeJSON` означает неудачное чтение: ответ уже записан, нужен `return`.

`u, err :=` получает пользователя и ошибку. `checkPassword` — новый метод с `password.Verify` из GB-6.03. Каждая ветка `err != nil` заканчивается `writeError` и `return`.

`endCurrentSession` удаляет запись старой cookie из запроса. Затем создаётся токен. `time.Now().Add(sessionTTL)` добавляет `24 * time.Hour` к текущему времени. `err =` присваивает существующей переменной значение. `CreateSession` вставляет хеш, ID и срок. Только после записи отправляются cookie и JSON с `200`. Тег `json:"-"` у `User.PasswordHash` исключает хеш из ответа.

**Предскажите:** адреса нет в базе. **A)** `404` · **B)** `401`, «адреса нет» · **C)** общий `401`, как при неверном пароле.

<details>
<summary>Ответ</summary>

**C.** A и B позволяют проверять существование записи. Внутренняя причина остаётся в журнале.

</details>

```go
func setSessionCookie(w http.ResponseWriter, token string, expires time.Time) {
	http.SetCookie(w, &http.Cookie{
		Name:     sessionCookie,
		Value:    token,
		Path:     "/",
		Expires:  expires,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
	w.Header().Set("Cache-Control", "no-store")
}
```

`http.SetCookie` создаёт заголовок из `&http.Cookie{...}`. `Name` — `session`; `Value` — токен; `Path: "/"` охватывает пути хоста; `Expires` — клиентский срок хранения. `HttpOnly` запрещает чтение скрипту страницы. `Secure` требует HTTPS; curl делает исключение для `http://localhost`. `SameSite=Lax` исключает cookie из cross-site POST. Подробные границы — в [GB-6.07 · cookie и CSRF](/lab/youtube/gb#gb-6-07). `no-store` запрещает кеширование ответа.

## Каждый запрос: cookie → база → контекст

```go
type userKey struct{}

// requireUser — himoyalangan route'lar uchun middleware (GB-6.01 shakli): cookie'dagi token hash'i
// boʻyicha session egasini topadi va uni soʻrov context'iga qoʻyadi. Topilmasa — 401, handler ishlamaydi.
func (a *api) requireUser(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		c, err := r.Cookie(sessionCookie)
		if err != nil {
			writeError(w, err) // http.ErrNoCookie → 401
			return
		}
		u, err := a.st.UserBySession(r.Context(), hashToken(c.Value))
		if err != nil {
			writeError(w, err) // store.ErrNoSession → 401
			return
		}
		w.Header().Set("Cache-Control", "no-store") // shaxsiy javob: keshda qolmasin (OWASP)
		ctx := context.WithValue(r.Context(), userKey{}, u)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}
```

`userKey struct{}` — собственный тип ключа без полей. Ключ должен быть сравнимым. Документация Go советует собственный тип вместо встроенного `string`, чтобы пакеты не конфликтовали.

`requireUser` принимает обработчик и возвращает замыкание, преобразованное в `http.HandlerFunc`. `r.Cookie` читает по имени; если cookie нет: `http.ErrNoCookie` → `401` → `return`.

`UserBySession` ищет по `hashToken(c.Value)`. Нет сессии или срок истёк: `ErrNoSession` → `401`. Отказ базы даёт `500`. При успехе ставится `no-store`. `WithValue` создаёт новый `ctx` из старого контекста: `userKey{}` → `u`. `r.WithContext(ctx)` даёт поверхностную копию запроса с этим контекстом. `next.ServeHTTP` запускает обработчик. Store:

```go
func (s *Store) UserBySession(ctx context.Context, tokenHash []byte) (User, error) {
	var u User
	err := s.pool.QueryRow(ctx, `
		SELECT u.id, u.email
		FROM sessions s JOIN users u ON u.id = s.user_id
		WHERE s.token_hash = $1 AND s.expires_at > now()`,
		tokenHash).Scan(&u.ID, &u.Email)
	if errors.Is(err, pgx.ErrNoRows) {
		return User{}, ErrNoSession
	}
	if err != nil {
		return User{}, fmt.Errorf("session oʻqilmadi: %w", err)
	}
	return u, nil
}
```

`var u User` принимает результат. `QueryRow` ожидает одну запись; обратные кавычки ограничивают SQL. `s`, `u` — псевдонимы таблиц; `JOIN` присоединяет пользователя. `$1` — параметр хеша. `Scan(&u.ID, &u.Email)` заполняет поля. `pgx.ErrNoRows` превращается в отсутствие сессии, другие ошибки оборачиваются через `%w`. `return u, nil` — успех.

`now()` — **время начала текущей транзакции**. Для этого отдельного запроса оно близко к проверке. В долгой транзакции не обновляется с каждым SELECT.

```go
func currentUser(r *http.Request) store.User {
	u, ok := r.Context().Value(userKey{}).(store.User)
	if !ok {
		panic("currentUser: route requireUser bilan oʻralmagan")
	}
	return u
}
```

К `any` от `Value` применяется type assertion (утверждение типа) `.(store.User)`. `u, ok :=` обнаруживает отсутствие или неверный тип. `!ok` — ошибка программиста: маршрут не обёрнут. Явный `panic` превращается в `500` через `recoverPanic`. В норме — `return u`. Полный файл маршрутов:

## Выход: cookie и запись — отдельно

```go
func (a *api) endCurrentSession(r *http.Request) error {
	c, err := r.Cookie(sessionCookie)
	if err != nil {
		return nil // cookie yoʻq: oʻchiradigan session ham yoʻq
	}
	return a.st.DeleteSession(r.Context(), hashToken(c.Value))
}

// logout — POST /logout: cookie'dagi session qatorini o'chiradi va brauzerga cookie'ni o'chirishni aytadi.
// requireUser'siz: session allaqachon eskirgan yoki o'chirilgan bo'lsa ham javob 204 va cookie tozalanadi.
func (a *api) logout(w http.ResponseWriter, r *http.Request) {
	if err := a.endCurrentSession(r); err != nil {
		writeError(w, err)
		return
	}
	clearSessionCookie(w)
	w.WriteHeader(http.StatusNoContent)
}
```

```go
func clearSessionCookie(w http.ResponseWriter) {
	http.SetCookie(w, &http.Cookie{
		Name:     sessionCookie,
		Value:    "",
		Path:     "/",
		MaxAge:   -1,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
}
```

Без cookie в `endCurrentSession` нечего удалять: `nil`. Иначе `DeleteSession` выполняет `DELETE FROM sessions WHERE token_hash = $1` по хешу. Отсутствующая запись тоже считается успехом.

`if err := ...; err != nil` объявляет и проверяет ошибку. Неудачное удаление: `writeError` и `return`. Иначе — `clearSessionCookie`, `204 No Content`, без тела.

Очистка выдаёт пустое значение с тем же именем и `Path`. В Go `MaxAge: -1` превращается в `Max-Age=0`. Остальные атрибуты совпадают с входом. Сессию отзывает DELETE.

## Глубже (необязательно): время и границы защиты

`checkPassword` выполняет argon2id с `dummyHash` и для неизвестного адреса. Иначе ранний возврат может выдать существование записи по времени. `dummyHash` вычисляется один раз при запуске. Повреждённый хеш даёт `500`. При успехе `u.PasswordHash = ""`: дальше он не нужен.

Сравнение внутри `password.Verify` выполняется за постоянное время. У `WHERE token_hash = $1` **нет такой гарантии**. Высокоэнтропийный токен практически не восстановить из хеша. Это не доказывает безопасность всех временных каналов. Split-token разделяет открытый идентификатор и секрет; хеш секрета сравнивается отдельно за постоянное время.

Измерим каждый случай пять раз. `time_total` — секунды; `for` повторяет, `-w` выводит время:

```console
$ for i in 1 2 3 4 5; do curl -sS -o /dev/null -w '%{time_total}\n' localhost:8765/login -H 'Content-Type: application/json' --data-binary @wrong.json; done
0.048716
0.044513
0.055996
0.046747
0.041252
$ for i in 1 2 3 4 5; do curl -sS -o /dev/null -w '%{time_total}\n' localhost:8765/login -H 'Content-Type: application/json' --data-binary @missing.json; done
0.041623
0.034553
0.047727
0.053169
0.048297
```

| Случай | Видео, цитата | Повторный запуск |
|---|---|---|
| Неверный пароль | 24.8–26.2 ms | 41.3–56.0 ms |
| Неизвестный адрес | 25.1–31.0 ms | 34.6–53.2 ms |

Числа видео процитированы из `_video/chiqishlar.txt`. Новые медианы: 46.747 и 47.727 ms; отношение около 1.02. Нагрузка меняет абсолютное время. Главное: неизвестный адрес не обходит argon2id. Пять измерений не доказывают одинаковое время или невозможность определить существование записи.

TTL в 24 часа — выбор лаборатории. Это максимальная жизнь: absolute timeout. Срок бездействия, idle timeout, пока не реализован. Продлеваемый срок и абсолютная граница должны храниться отдельно. Приложение пишет по `time.Now()`, проверяет Postgres: часы должны быть согласованы.

Каждый вход выдаёт новый токен и удаляет предъявленную старую сессию. Это ограничивает session fixation — сохранение известного заранее токена после входа. `SameSite` не заменяет защиту CSRF. Ограничение попыток — в GB-6.07; реальное размещение требует HTTPS.

RFC 9110 требует `WWW-Authenticate` при `401`. Лаборатория отправляет `Cookie realm="bozor"`. Это собственный challenge, не стандартная cookie auth-scheme с автоматическим входом.

Полный файл ниже запускается вместе с остальной папкой через `go run ./cmd/api`:

<summary>Полный auth.go</summary>

```go filename="cmd/api/auth.go" showLineNumbers
package main

// Login va bekor qilinadigan session'lar (GB-6.04).
//
//	POST /login        parol toʻgʻri → yangi session: tokenning hash'i bazaga, tokenning oʻzi cookie'ga
//	requireUser        cookie → hash → sessions qatori → foydalanuvchi context'ga; yoʻq yoki eski → 401
//	POST /logout       cookie'dagi session qatorini oʻchiradi: shu token bilan keyingi soʻrov 401
//	POST /logout-all   foydalanuvchining hamma session'larini oʻchiradi (VAZIFA, TASK.md)

import (
	"context"
	"crypto/rand"
	"crypto/sha256"
	"encoding/base64"
	"errors"
	"fmt"
	"net/http"
	"time"

	"github.com/abdurahmon27/bozor/internal/password"
	"github.com/abdurahmon27/bozor/internal/store"
)

// sessionCookie — cookie nomi. sessionTTL — session'ning eng uzun umri: login'dan 24 soat keyin u
// baribir tugaydi (absolute timeout). 24 soat — bizning tanlov; OWASP Session Management Cheat Sheet'ning
// misoli ish kuni ilovasi uchun 4–8 soat, harakatsizlik (idle) muddati esa alohida (README).
const (
	sessionCookie = "session"
	sessionTTL    = 24 * time.Hour
)

// newToken — session tokeni: 32 tasodifiy bayt (256 bit), cookie'ga sigʻadigan matn qilib (43 belgi).
func newToken() string {
	b := make([]byte, 32)
	rand.Read(b) // Go 1.24+: xato qaytarmaydi
	return base64.RawURLEncoding.EncodeToString(b)
}

// hashToken — bazaga yoziladigan va bazadan qidiriladigan qiymat: tokenning SHA-256 hash'i.
func hashToken(token string) []byte {
	sum := sha256.Sum256([]byte(token))
	return sum[:]
}

// loginInput — POST /login body'si.
type loginInput struct {
	Email    string `json:"email"`
	Password string `json:"password"`
}

// login — POST /login: parol toʻgʻri boʻlsa yangi session ochadi va tokenni cookie'da qaytaradi.
// Har login yangi token oladi, so'rovda eski session cookie'si bo'lsa, uning qatori o'chiriladi: OWASP
// "Renew the Session ID After Any Privilege Level Change" — yangi ID, eskisi yo'q qilinsin (session fixation).
func (a *api) login(w http.ResponseWriter, r *http.Request) {
	var in loginInput
	if !decodeJSON(w, r, &in) {
		return
	}
	u, err := a.checkPassword(r.Context(), in.Email, in.Password)
	if err != nil {
		writeError(w, err)
		return
	}
	if err := a.endCurrentSession(r); err != nil {
		writeError(w, err)
		return
	}
	token := newToken()
	expires := time.Now().Add(sessionTTL)
	err = a.st.CreateSession(r.Context(), hashToken(token), u.ID, expires)
	if err != nil {
		writeError(w, err)
		return
	}
	setSessionCookie(w, token, expires)
	writeJSON(w, http.StatusOK, u)
}

// setSessionCookie — tokenni cookie qilib yuboradi. Atributlar GB-6.07'da batafsil:
// HttpOnly — sahifadagi skript cookie'ni oʻqiy olmaydi; Secure — brauzer uni faqat HTTPS orqali
// yuboradi (brauzerlar va curl http://localhost'ni istisno qiladi, MDN: Set-Cookie); SameSite=Lax — boshqa
// saytdan kelgan POST'ga qoʻshilmaydi. Cache-Control: no-store — session ID bor javob keshda qolmasin (OWASP).
func setSessionCookie(w http.ResponseWriter, token string, expires time.Time) {
	http.SetCookie(w, &http.Cookie{
		Name:     sessionCookie,
		Value:    token,
		Path:     "/",
		Expires:  expires,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
	w.Header().Set("Cache-Control", "no-store")
}

// clearSessionCookie — brauzerga cookie'ni oʻchirishni aytadi (MaxAge: -1 → "Max-Age=0").
// Bu faqat mijoz tomoni: session'ni bekor qiladigan narsa — bazadagi qatorni oʻchirish.
func clearSessionCookie(w http.ResponseWriter) {
	http.SetCookie(w, &http.Cookie{
		Name:     sessionCookie,
		Value:    "",
		Path:     "/",
		MaxAge:   -1,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
}

// errBadLogin — email yoki parol notoʻgʻri (problemFor → 401, ikkalasiga bir xil matn).
var errBadLogin = errors.New("email yoki parol notoʻgʻri")

// dummyHash — yoʻq email uchun ham argon2id bir marta ishlaydi: javob vaqti email bazada bor-yoʻqligini
// bildirmasin (OWASP Authentication Cheat Sheet, "Authentication Responses").
var dummyHash = password.Hash("bozor: email topilmadi")

// checkPassword — Verify (GB-6.03) ustidagi login tekshiruvi: email boʻyicha foydalanuvchi, keyin argon2id Verify.
func (a *api) checkPassword(ctx context.Context, email, pw string) (store.User, error) {
	u, err := a.st.UserByEmail(ctx, email)
	if errors.Is(err, store.ErrUserNotFound) {
		password.Verify(pw, dummyHash)
		return store.User{}, fmt.Errorf("%w: %w", errBadLogin, err)
	}
	if err != nil {
		return store.User{}, err
	}
	ok, err := password.Verify(pw, u.PasswordHash)
	if err != nil {
		return store.User{}, fmt.Errorf("foydalanuvchi %d: %w", u.ID, err)
	}
	if !ok {
		return store.User{}, fmt.Errorf("%w: foydalanuvchi %d", errBadLogin, u.ID)
	}
	u.PasswordHash = "" // hash bundan keyin kerak emas: javobga yoki log'ga tasodifan chiqmasin
	return u, nil
}

// userKey — context'dagi kalit turi. Oʻz turimiz: boshqa paketning kaliti bilan toʻqnashmaydi
// (go doc context.WithValue: kalit string yoki boshqa ichki tur boʻlmasin).
type userKey struct{}

// requireUser — himoyalangan route'lar uchun middleware (GB-6.01 shakli): cookie'dagi token hash'i
// boʻyicha session egasini topadi va uni soʻrov context'iga qoʻyadi. Topilmasa — 401, handler ishlamaydi.
func (a *api) requireUser(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		c, err := r.Cookie(sessionCookie)
		if err != nil {
			writeError(w, err) // http.ErrNoCookie → 401
			return
		}
		u, err := a.st.UserBySession(r.Context(), hashToken(c.Value))
		if err != nil {
			writeError(w, err) // store.ErrNoSession → 401
			return
		}
		w.Header().Set("Cache-Control", "no-store") // shaxsiy javob: keshda qolmasin (OWASP)
		ctx := context.WithValue(r.Context(), userKey{}, u)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// currentUser — requireUser context'ga qoʻygan foydalanuvchi. Route requireUser bilan oʻralmagan
// boʻlsa — bu dasturchi xatosi: panic, recoverPanic uni 500 qiladi (jim User{} qaytarishdan xavfsizroq).
func currentUser(r *http.Request) store.User {
	u, ok := r.Context().Value(userKey{}).(store.User)
	if !ok {
		panic("currentUser: route requireUser bilan oʻralmagan")
	}
	return u
}

// endCurrentSession — so'rovdagi session cookie'sining qatorini o'chiradi; cookie yo'q bo'lsa hech narsa
// qilmaydi. logout va login (eski session'ni yo'q qilish) ishlatadi.
func (a *api) endCurrentSession(r *http.Request) error {
	c, err := r.Cookie(sessionCookie)
	if err != nil {
		return nil // cookie yoʻq: oʻchiradigan session ham yoʻq
	}
	return a.st.DeleteSession(r.Context(), hashToken(c.Value))
}

// logout — POST /logout: cookie'dagi session qatorini o'chiradi va brauzerga cookie'ni o'chirishni aytadi.
// requireUser'siz: session allaqachon eskirgan yoki o'chirilgan bo'lsa ham javob 204 va cookie tozalanadi.
func (a *api) logout(w http.ResponseWriter, r *http.Request) {
	if err := a.endCurrentSession(r); err != nil {
		writeError(w, err)
		return
	}
	clearSessionCookie(w)
	w.WriteHeader(http.StatusNoContent)
}

Комментарии и пустые строки не выполняются. `errBadLogin` — общая ошибка; два `%w` сохраняют исходные причины. `ok` в `checkPassword` означает совпадение пароля, `err` — ошибку вычисления.

## Частые ошибки

1. **Проверять только хеш.** В разделе «Если убрать проверку срока» истёкшая запись дала `200`. Возврат `AND s.expires_at > now()` и перезапуск изменили результат на `401`.
2. **Удалять только cookie.** Старая копия работает, пока есть запись. Завершайте выход после успешного `DeleteSession`.
3. **Вызывать `currentUser` на открытом маршруте.** `panic("currentUser: route requireUser bilan oʻralmagan")` — ошибка программиста: маршрут не обёрнут. `recoverPanic` превращает её в `500`. Исправление: `a.requireUser(http.HandlerFunc(a.me))`.
4. **Оборачивать обычный выход в `requireUser`.** Истёкшая сессия не дойдёт до очистки cookie. Обычный выход открыт; logout-all защищён ради текущего пользователя.
5. **Считать `Expires` серверным сроком.** Клиентское хранение и серверное принятие различаются. Очистка тоже не заменяет проверку срока.

## Проверьте себя

1. Почему в базе хеш, а не сам токен?

<details>
<summary>Ответ</summary>

Чтобы копия базы на чтение не давала готовые токены входа. SHA-256 достаточно для высокоэнтропийного токена; кражу cookie это не устраняет.

</details>

<details>
<summary>Ответ</summary>

`401`: токен есть, записи на сервере нет.

</details>

3. GB-6.01: middleware не вызывает `next.ServeHTTP`. Что произойдёт?

<details>
<summary>Ответ</summary>

Внутренний обработчик не запускается. Так `requireUser` останавливается после `401`.

</details>

4. Нужна ли проверка срока в запросе при наличии `DeleteExpiredSessions`?

<details>
<summary>Ответ</summary>

Да. Очистка может запаздывать; проверка всё равно должна отвергать истёкшие записи.

</details>

```go
func (s *Store) DeleteUserSessions(ctx context.Context, userID int64) (int64, error) {
	tag, err := s.pool.Exec(ctx, "DELETE FROM sessions WHERE user_id = $1", userID)
	if err != nil {
		return 0, fmt.Errorf("foydalanuvchi %d session'lari oʻchirilmadi: %w", userID, err)
	}
	return tag.RowsAffected(), nil
}
```

```go
func (a *api) logoutAll(w http.ResponseWriter, r *http.Request) {
	_, err := a.st.DeleteUserSessions(r.Context(), currentUser(r).ID)
	if err != nil {
		writeError(w, err)
		return
	}
	clearSessionCookie(w)
	w.WriteHeader(http.StatusNoContent)
}
```

```go
mux.Handle("POST /logout-all", a.requireUser(http.HandlerFunc(a.logoutAll)))
```

Первый фрагмент — в store, второй — в auth.go, последний — в `newMux`. `RowsAffected()` даёт число удалённых записей. Обработчик отбрасывает число через `_`. `WHERE user_id` сохраняет другого пользователя; без него тест упадёт. Необязательная очистка использует тот же `Exec` с `WHERE expires_at <= now()`.

</details>
