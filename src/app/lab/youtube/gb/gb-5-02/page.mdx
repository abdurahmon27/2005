## Serverni kim ishga tushiradi?

Postgres alohida jarayon boʻlib, `5432` tarmoq portida ulanish kutadi. Mijoz bugun `psql`, keyin bozorning Go dasturi boʻladi.
Baza fayllarini server boshqaradi; mijozlar unga buyruq yuboradi. Bu mijozlarning bir faylni mustaqil almashtirishini toʻxtatadi.
Bir nechta SQL qadamining birgalikdagi toʻgʻriligini keyin [GB-5.07 · Tranzaksiya](/lab/youtube/gb/gb-5-07)da koʻramiz.

| Qadam | Kim bajaradi | Maʼlumot qayerda |
|---|---|---|
| ulanish | `psql` → port `5432` → Postgres | server hali fayllarni boshqaradi |
| buyruq | Postgres oʻqiydi yoki yozadi | nomlangan volume'dagi baza fayllari |
| javob | Postgres → `psql` | mijoz ekranda natijani koʻradi |

**Docker** dasturni container'da ishga tushiradi. **Image** — dastur va kerakli fayllarning tayyor paketi.
**Container (konteyner)** — shu image'dan ishga tushgan alohida jarayon muhiti.
**Docker Compose** esa container'larni bitta fayldagi tavsifdan boshqaradi. Postgres rasmiy image'ini PostgreSQL Docker hamjamiyati yuritadi.

## compose.yaml: har qatorning vazifasi

Serverni takror ishga tushirish uchun uning sozlamalarini faylga yozamiz. **YAML** nom va qiymatlarni ichkariga surilgan qatorlar bilan guruhlaydi.
Quyidagi fayl kurs papkasidagi `compose.yaml`ning toʻliq nusxasi:

```yaml filename="compose.yaml" showLineNumbers
services:
  db:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: bozor
      POSTGRES_PASSWORD: bozor
      POSTGRES_DB: bozor
    ports:
      - "127.0.0.1:5482:5432"
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `services:` | ishga tushadigan servislar roʻyxati; servis — bitta dastur tavsifi |
| 2 | `db:` | tanlangan servis nomi; ikki boʻshliq uning `services`ga tegishliligini koʻrsatadi |
| 3 | `image: postgres:18-alpine` | Postgres 18, Alpine Linux asosidagi image; `:`dan keyin versiya varianti |
| 4 | `environment:` | container'ga beriladigan muhit oʻzgaruvchilari |
| 5 | `POSTGRES_USER: bozor` | birinchi ishga tushishda yaratiladigan foydalanuvchi |
| 6 | `POSTGRES_PASSWORD: bozor` | shu foydalanuvchining oʻquv paroli |
| 7 | `POSTGRES_DB: bozor` | birinchi ishga tushishda yaratiladigan baza nomi |
| 8–9 | `ports:` va `- "127.0.0.1:5482:5432"` | `-` roʻyxat elementi, qoʻshtirnoq ichidagisi ulanish tavsifi |
| 10–11 | `volumes:` va `- pgdata:/var/lib/postgresql` | nomlangan `pgdata`ni container ichidagi papkaga ulaydi |
| 12 | boʻsh qator | oʻqishni qulay qiladi |
| 13–14 | `volumes:` va `pgdata:` | eng tashqi darajada volume'ni eʼlon qiladi; boʻsh qiymat standart sozlamalarni tanlaydi |

`POSTGRES_*` sozlamalari faqat maʼlumot papkasi boʻsh boʻlganda bazani tayyorlaydi.
`bozor` paroli faqat lokal oʻquv bazasi uchun; haqiqiy parollar [GB-8.01](/lab/youtube/gb#gb-8-01)da.

Port yozuvi uch qismdan iborat:

| Qism | Qiymat | Maʼno |
|---|---|---|
| host manzili | `127.0.0.1` | faqat shu kompyuterdan ulanish |
| chap port | `5482` | kompyuterda siz ulanadigan port |
| oʻng port | `5432` | container ichida Postgres kutadigan port |

Nomlangan **volume** — Docker boshqaradigan alohida saqlash joyi. Container oʻchirilganda uning oʻz fayllari ketadi, volume'dagi maʼlumot qoladi.
Yangi container `pgdata`ni yana ulaydi. Ikki `volumes:` har xil vazifada: biri ulaydi, tashqi biri eʼlon qiladi.

## Ishga tushirish va tayyorlik

`docker compose up -d` fayldagi servislarni ishga tushiradi. `-d` terminalni band qilmasdan fonda ishlatadi.
Quyidagi qayta ishga tushirishlar videodagi kabi yangi `bozor` nomli papkada bajarildi; kurs papkasida nomlar uzunroq prefiks oladi.
Image oldindan yuklangan edi; birinchi marta yuklash qatorlari ham chiqishi mumkin.

```console
$ docker compose up -d
[+] up 3/3
 ✔ Network bozor_default Created                                            0.1s
 ✔ Volume bozor_pgdata   Created                                            0.0s
 ✔ Container bozor-db-1  Started                                            0.3s
```

`[+] up 3/3` — uchta obyekt tayyorlandi; `✔` bajarilganini bildiradi.
`Network` — Docker tarmogʻi, `Volume` — saqlash joyi, `Container` — ishlaydigan jarayon muhiti.
`Created` — yaratildi, `Started` — ishga tushdi. Nomlardagi `bozor` loyiha papkasidan, `db` va `pgdata` fayldan olingan; `1` container tartib raqami.

Videoda container `0.3s`da ishga tushgan; qayta oʻlchovda ham `0.3s`. Tarmoq va volume vaqtlari hamda qator tartibi oʻzgaradi.
Bu sonlar soʻrov tezligini oʻlchamaydi; `Started` ham bazaning ulanishga tayyorligini kafolatlamaydi.
Muhim natija: server javob berishi va volume maʼlumotni saqlashi.

`docker compose logs db` servis jurnalini chiqaradi. `|` uni `tail -n 1`ga uzatadi; bu oxirgi qatorni koʻrsatadi.
Tayyorlik xabarini kuting, keyin davom eting:

```console
$ docker compose logs db | tail -n 1
db-1  | 2026-11-27 12:49:23.991 UTC [1] LOG:  database system is ready to accept connections
```

`db-1` — servis container'i; sana, vaqt va `[1]` — jarayon raqami. `LOG` jurnal yozuvi turini bildiradi.
`database system is ready to accept connections` — baza ulanishlarni qabul qilishga tayyor.
Vaqt qayta ishga tushirishda oʻzgardi; bu sahifadagi console chiqishlari qayta olindi, videodan koʻchirilmagan.

## psql: jadvallar va qatorlarni koʻrish

Serverga buyruq yuborish uchun **psql** mijozidan foydalanamiz. Buyruq qismlari:

| Qism | Vazifasi |
|---|---|
| `docker compose exec` | ishlab turgan container ichida buyruq bajaradi |
| `db` | qaysi servis ichida |
| `psql` | Postgres mijoz dasturi |
| `-U bozor` | foydalanuvchi nomi; katta `U` |
| `-d bozor` | baza nomi; bu `up -d`dagi flag'dan boshqa dasturga tegishli |
| `-c` | keyingi bitta buyruqni bajarib chiqadi |
| `'\dt'` | psql'ning jadvallar roʻyxati buyrugʻi; bitta tirnoq matnni bitta argument qilib beradi |

Baza yangidan yaratildi. `\dt` nima chiqaradi?
**A)** `products` bor · **B)** jadval topilmadi · **C)** baza topilmadi

<details>
<summary>Javob</summary>

**B.** `POSTGRES_DB` bazani yaratdi, lekin hech qanday jadval yaratmadik. A jadval avtomatik keladi deb taxmin qiladi; C baza bilan jadvalni aralashtiradi.

</details>

```console
$ docker compose exec db psql -U bozor -d bozor -c '\dt'
Did not find any tables.
```

`Did not find any tables.` — hech qanday jadval topilmadi.

Endi kursdagi `bozor.sql`ni yuklaymiz. SQL — bazaga buyruq yozish tili. `CREATE TABLE` jadval yaratadi, `INSERT` uchta mahsulot qoʻshadi.
Toʻliq fayl quyida; SQL yozilishini [GB-5.03](/lab/youtube/gb/gb-5-03)da mashq qilamiz.

```sql filename="bozor.sql" showLineNumbers
-- bozor: products jadvali va uchta mahsulot (SQL'ni GB-5.03'da oʻzimiz yozamiz)
CREATE TABLE products (
    id    bigint PRIMARY KEY,
    name  text    NOT NULL,
    price bigint  NOT NULL,
    stock integer NOT NULL
);

INSERT INTO products (id, name, price, stock) VALUES
    (1, 'olma', 1200000, 40),
    (2, 'non', 400000, 25),
    (3, 'oʻrik', 3500000, 5);
```

1. `--` bilan boshlangan birinchi qator — izoh.
2. 2–7-qatorlar `products` jadvalini tavsiflaydi. Qavslar ustunlarni guruhlaydi; vergullar ajratadi; `;` buyruqni tugatadi.
3. `id` — mahsulot raqami, `PRIMARY KEY` uni yagona va majburiy qiladi; `bigint` katta butun sonni saqlaydi.
4. `name` — nom, `text` matn turi. `price` — tiyindagi narx, `stock` — qoldiq, `integer` butun son turi.
5. `NOT NULL` qiymat yoʻqligini taqiqlaydi; bu boʻsh matnni taqiqlash degani emas.
6. `INSERT INTO` qaysi jadvalga yozishni, `VALUES` qiymatlarni belgilaydi. 9–12-qatorlar uchta qator qoʻshadi; bitta tirnoq mahsulot nomlarining boshi va oxiriga yozilgan.

`olma`, `non`, `oʻrik` — mahsulot nomlari. `1200000` tiyin = `12000` soʻm.
`< bozor.sql` faylni standart kirish sifatida beradi; `-T` terminal ulashni oʻchiradi, chunki kirish fayldan keladi.

Bashorat: yuklash javobidagi `INSERT 0 3`ning `3` soni nimani bildiradi?
**A)** uchta ustun · **B)** uchta qoʻshilgan qator · **C)** uchinchi baza

<details>
<summary>Javob</summary>

**B.** `INSERT` qator qoʻshadi. Birinchi `0` eski maydon: hozir doim nol; ustun yoki baza raqami emas.

</details>

```console
$ docker compose exec -T db psql -U bozor -d bozor < bozor.sql
CREATE TABLE
INSERT 0 3
$ docker compose exec db psql -U bozor -d bozor -c '\dt'
          List of tables
 Schema |   Name   | Type  | Owner 
--------+----------+-------+-------
 public | products | table | bozor
(1 row)
```

`CREATE TABLE` — jadval yaratildi. Keyingi javobdagi `List of tables` — jadvallar roʻyxati.
**Schema** — jadvallar joylashadigan nomli guruh; `public` standart schema nomi.
`Name` — nom, `Type: table` — obyekt jadval, `Owner: bozor` — egasi. `(1 row)` — roʻyxatda bitta qator.

`\d products` bitta jadval tuzilishini koʻrsatadi:

```console
$ docker compose exec db psql -U bozor -d bozor -c '\d products'
              Table "public.products"
 Column |  Type   | Collation | Nullable | Default 
--------+---------+-----------+----------+---------
 id     | bigint  |           | not null | 
 name   | text    |           | not null | 
 price  | bigint  |           | not null | 
 stock  | integer |           | not null | 
Indexes:
    "products_pkey" PRIMARY KEY, btree (id)
```

`Table "public.products"` — schema va jadvalning toʻliq nomi. `Column` — ustun, `Type` — turi, `Nullable` — qiymat yoʻq boʻlishi mumkinmi.
`not null` — mumkin emas. `Collation` va `Default` ustunlari [GB-5.03](/lab/youtube/gb/gb-5-03)da ochiladi.
Video pastdagi qatorlarni yashirgan; bu yerda toʻliq chiqish turibdi.
`Indexes` ostidagi `products_pkey` — `id` primary key uchun yaratilgan indeks, `btree` uning turi.
Indeks — `id` orqali qatorni qidirish uchun yordamchi tuzilma; `btree` — shu tuzilmaning daraxt turi.

`SELECT name FROM products` — `products`dan `name` ustunini oling.
Bashorat: **A)** toʻrtta ustun · **B)** uchta mahsulot nomi · **C)** faqat bitta nom

<details>
<summary>Javob</summary>

**B.** Soʻrov faqat `name`ni tanlaydi, uchta qator bor. Barcha ustunlar soʻralmagan, qatorlar ham bittaga cheklanmagan.

</details>

```console
$ docker compose exec db psql -U bozor -d bozor -c 'SELECT name FROM products'
 name  
-------
 olma
 non
 oʻrik
(3 rows)
```

`name` — natija ustuni; `(3 rows)` — uchta qator. Chiziqlar psql chizgan jadval chegaralari, maʼlumot emas.
SQL yozilishi keyingi darsda batafsil oʻrganiladi.

**Qisqa savol:** fayldan yuklashda `-T`ni olib tashlasak nima boʻladi?
**A)** bir xil ishlaydi · **B)** Docker xato beradi · **C)** jadval ikki marta yaratiladi

<details>
<summary>Javob</summary>

**B.** `exec` odatda terminal ulaydi, ammo standart kirish fayl. `-T` terminal ulashni oʻchiradi. Xato SQL serveriga yetib bormasdan chiqadi.

</details>

```console
$ docker compose exec db psql -U bozor -d bozor < bozor.sql
cannot attach stdin to a TTY-enabled container because stdin is not a terminal
```

`stdin` — standart kirish, `TTY` — terminal. Xabar: terminal yoqilgan container'ga terminal boʻlmagan kirishni ulab boʻlmaydi.
Tuzatish — yuklash buyrugʻiga `exec -T`ni qaytaring. Bu xato `bozor.sql` ichidagi SQL xatosi emas.

## Container ketganda maʼlumot qayerda qoladi?

`docker compose down` container va tarmoqni toʻxtatib oʻchiradi. Keyin `up -d` bilan yana boshlaymiz.
Bashorat: uchta mahsulot qoladimi?
**A)** ha, volume saqlaydi · **B)** jadval ham oʻchadi · **C)** jadval qoladi, qatorlar oʻchadi

<details>
<summary>Javob</summary>

**A.** Container yangi boʻladi, lekin u oldingi `pgdata`ni ulaydi. B va C jadval bilan qatorlarning bir volume'da saqlanishini hisobga olmaydi.

</details>

```console
$ docker compose down
[+] down 2/2
 ✔ Container bozor-db-1  Removed                                            0.3s
 ✔ Network bozor_default Removed                                            0.1s
$ docker compose up -d
[+] up 2/2
 ✔ Network bozor_default Created                                            0.0s
 ✔ Container bozor-db-1  Started                                            0.3s
$ docker compose exec db psql -U bozor -d bozor -c 'SELECT name FROM products'
 name  
-------
 olma
 non
 oʻrik
(3 rows)
```

`Removed` — oʻchirildi. Ikkinchi `up` volume yaratmadi: u allaqachon bor edi.
Qayta ulanishdan oldin server tayyorligini yana jurnal orqali tekshiring.

Endi `docker compose down -v`: `-v` nomlangan volume'ni ham oʻchiradi. Yana `up -d` qilsak, `\dt` nima chiqaradi?
**A)** `products` bor · **B)** jadval yoʻq, baza bor · **C)** bazaning oʻzi ham yoʻq

<details>
<summary>Javob</summary>

**B.** Yangi boʻsh volume'da `POSTGRES_DB: bozor` bazani yana yaratadi. `bozor.sql` avtomatik yuklanmaydi; eski jadval va qatorlar oʻchgan.

</details>

```console
$ docker compose down -v
[+] down 3/3
 ✔ Container bozor-db-1  Removed                                            0.2s
 ✔ Volume bozor_pgdata   Removed                                            0.0s
 ✔ Network bozor_default Removed                                            0.1s
$ docker compose up -d
[+] up 3/3
 ✔ Network bozor_default Created                                            0.0s
 ✔ Volume bozor_pgdata   Created                                            0.0s
 ✔ Container bozor-db-1  Started                                            0.3s
$ docker compose exec db psql -U bozor -d bozor -c '\dt'
Did not find any tables.
```

| Holat | Container | `pgdata` | `products` |
|---|---|---|---|
| yuklangandan keyin | ishlayapti | bor | 3 qator |
| `down`dan keyin | oʻchirildi | saqlandi | fayllari saqlandi |
| yana `up -d` | yangi | oldingi | 3 qator |
| `down -v`dan keyin | oʻchirildi | oʻchirildi | yoʻq |
| yana `up -d` | yangi | yangi | yoʻq; `bozor` bazasi boʻsh |

`down -v`ni faqat shu oʻquv maʼlumotlarini oʻchirishga tayyor boʻlganda bajaring.

## Ulanish URL'i

Keyingi Go dasturi ham host, port, foydalanuvchi, parol va baza nomi bilan ulanadi. Ularni **ulanish URL'i**da yozish mumkin:

`postgres://bozor:bozor@127.0.0.1:5482/bozor`

| Qism | Maʼno |
|---|---|
| `postgres://` | Postgres ulanish sxemasi |
| birinchi `bozor` | foydalanuvchi |
| `:`dan keyingi `bozor` | oʻquv paroli |
| `@127.0.0.1` | serverning kompyuterdagi manzili |
| `:5482` | kompyuter porti |
| `/bozor` | baza nomi |

Kompyuterga `psql` oʻrnatilgan boʻlsa, URL'ni tekshiring. `\conninfo` joriy ulanish maʼlumotlarini chiqaradi.
Yangi server tayyor boʻlgandan keyingi haqiqiy natija:

```console
$ psql postgres://bozor:bozor@127.0.0.1:5482/bozor -c '\conninfo'
You are connected to database "bozor" as user "bozor" on host "127.0.0.1" at port "5482".
```

Javob `bozor` bazasi, `bozor` foydalanuvchisi, `127.0.0.1` hosti va `5482` portini tasdiqlaydi.
Go'dan ulanishni [GB-5.05](/lab/youtube/gb/gb-5-05)da qilamiz.

## Chuqurroq (ixtiyoriy): dastlabki sozlash va volume yoʻli

`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` mavjud bazani qayta sozlamaydi.
Fayldagi parolni almashtirib, `up` qilsangiz, eski volume'dagi baza eski parolda qoladi.
Shu oʻquv bazasini yangidan boshlash uchun `down -v`, keyin `up -d` ishlatiladi: barcha oldingi maʼlumot ketadi.

Postgres 18 image'ida volume `/var/lib/postgresql`ga ulanadi; haqiqiy maʼlumot ichkaridagi `/var/lib/postgresql/18/docker`da.
17 va oldingi image'lar `/var/lib/postgresql/data` yoʻlini ishlatadi. Image versiyasini almashtirsangiz, ulash yoʻlini ham rasmiy hujjatdan tekshiring.

## Koʻp uchraydigan xatolar

**1. Band host portini tanlash.** Kompyuterda `5432`ni boshqa Postgres ishlatyapti. Toʻgʻri fayldagi port qatorini shunga almashtirsak:

```yaml
ports:
  - "127.0.0.1:5432:5432"
```

Sinov oldidan oʻquv container'ini `docker compose down -v` bilan tozaladik; boshqa Postgres'ga tegmadik.
Bashorat: **A)** Docker boshqa port tanlaydi · **B)** ishga tushirish xato beradi · **C)** ikkalasi bir portda ishlaydi

<details>
<summary>Javob</summary>

**B.** Bir manzil va portni ikkala dastur birga band qila olmaydi. Docker faylda soʻralgan portni oʻzi almashtirmaydi.

</details>

```console
$ docker compose up -d
[+] up 2/3
 ✔ Network bozor_default Created                                            0.0s
 ✔ Volume bozor_pgdata   Created                                            0.0s
 ⠸ Container bozor-db-1  Starting                                           0.3s
Error response from daemon: failed to set up container networking: driver failed programming external connectivity on endpoint bozor-db-1 (d5f82e1d23b64670c093ff3a29d3df035adf9fae65ddd66435cd7e2a561d7b90): failed to bind host port 127.0.0.1:5432/tcp: address already in use
```

Bu Docker daemon'ining xato xabari; daemon — Docker'ning fondagi dasturi.
`up 2/3` va aylanuvchi belgi jarayon yakunlanmaganini koʻrsatadi. Uzun qavsli raqam tarmoq ulanishining identifikatori.
Oxiridan oʻqing: `failed to bind host port` — kompyuter portini ulab boʻlmadi; `address already in use` — manzil band.
`127.0.0.1:5432/tcp` aynan qaysi manzil, port va protokol ekanini koʻrsatadi.

Tuzatish: avval muvaffaqiyatsiz oʻquv loyihasini `docker compose down -v` bilan tozalang.
Port qatorini `"127.0.0.1:5482:5432"`ga qaytaring, keyin `docker compose up -d` qiling.
Faqat chap raqam oʻzgardi; Postgres container ichida hanuz `5432`da.

**2. `down` maʼlumotni oʻchiradi deb oʻylash.** “Container ketganda maʼlumot qayerda qoladi?” boʻlimida uchta qator qaytganini koʻrdik.
Maʼlumotni ataylab tozalash uchun `down -v` kerak.

**3. Fayldan kirishda `-T`ni unutish.** psql boʻlimidagi haqiqiy xato SQL'dan oldin chiqadi. Tuzatish: `exec -T`.

**4. YAML'dagi parol mavjud bazani almashtiradi deb oʻylash.** “Chuqurroq” boʻlimidagi qoida: environment faqat boʻsh maʼlumot papkasini tayyorlaydi.

## Oʻzingizni tekshiring

**1.** `127.0.0.1:5482:5432`dagi qaysi port container'niki?

<details>
<summary>Javob</summary>

Oʻngdagi `5432`. Kompyuterdagi mijoz `5482`ga ulanadi; Docker uni container ichidagi `5432`ga yetkazadi.

</details>

**2.** `down` va `down -v` farqi nima?

<details>
<summary>Javob</summary>

Ikkalasi container va tarmoqni oʻchiradi. `down` nomlangan volume'ni saqlaydi, `down -v` uni maʼlumotlari bilan oʻchiradi.

</details>

**3.** Uchta mahsulot yuklangach `down -v`, keyin `up -d` qilindi. `\dt` nima chiqaradi?
**A)** uchta mahsulot · **B)** jadval topilmadi · **C)** baza topilmadi

<details>
<summary>Javob</summary>

**B: `Did not find any tables.`** `bozor` qayta yaratildi, lekin `bozor.sql` qayta yuklanmadi. `\dt` qatorlarni emas, jadvallarni sanaydi.

</details>

**4.** [GB-4.07](/lab/youtube/gb/gb-4-07)dan: `go test`da qaysi flag data race'ni topadi?

<details>
<summary>Javob</summary>

`-race`. Race detector ishlayotgan koddagi poygani tekshiradi. Unga cgo va C kompilyatori kerak; shu sabab `CGO_ENABLED=0` bilan bu flag ishlatilmaydi.

</details>

## Uy vazifasi

🟢 **Asosiy vazifa:** [TASK.md](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/gb-5-02-postgres-compose/TASK.md)dagi ikkinchi servisni qoʻshing.
Boshlangʻich fayllar [kurs papkasida](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/gb-5-02-postgres-compose), javob [solution/](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/gb-5-02-postgres-compose/solution)da.

1. `services:` ichida `db` bilan bir darajada `db-test` qoʻshing.
2. `POSTGRES_DB` — `bozor_test`; foydalanuvchi va oʻquv paroli — `bozor`.
3. Host porti `5483`, container porti `5432`: `"127.0.0.1:5483:5432"`.
4. Alohida `pgtest:/var/lib/postgresql` volume'ni ulang, tashqi `volumes:`da `pgtest:`ni ham eʼlon qiling.
5. Servislarni koʻtaring, asosiy bazaga `bozor.sql`ni yuklang, `go test ./...` oʻtguncha ishlang.

`tekshiruv_test.go`ni oʻzgartirmang. U `docker compose config`dan sozlamalarni oʻqib, ikkala serverga `psql` bilan soʻrov yuboradi.
`config` faylni tekshiradi va yakuniy shaklini chiqaradi. Test ulanishni 30 soniyagacha kutadi.
Yuklashdan oldin esa server tayyorligini oʻzingiz jurnal orqali tekshiring. `bozor.sql`ni bir yangi bazaga faqat bir marta yuklang.

```bash
docker compose config
docker compose up -d
docker compose logs db | tail -n 1
docker compose exec -T db psql -U bozor -d bozor < bozor.sql
CGO_ENABLED=0 go test ./...
```

Boshlangʻich faylda `db-test` yoʻqligi uchun test muvaffaqiyatsiz tugaydi. Javobni tekshirishdan oldin asosiy loyihani tozalang:
`docker compose down -v`. `solution/` ham shu host portlarini ishlatadi.

<details>
<summary>Javob</summary>

`db-test`ning porti va volume'i alohida boʻlishi shart. Bir xil volume ikki serverga bir xil baza fayllarini beradi.
Javobning toʻliq `solution/compose.yaml` fayli quyida. Yangi `name: gb502-solution` loyiha nomini aniq belgilaydi; bu boshqa `solution` papkalari bilan toʻqnashmaydi.

```yaml filename="solution/compose.yaml" showLineNumbers
name: gb502-solution # papka nomi "solution" boshqa darslarning solution/ papkalari bilan toʻqnashmasligi uchun
services:
  db:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: bozor
      POSTGRES_PASSWORD: bozor
      POSTGRES_DB: bozor
    ports:
      - "127.0.0.1:5482:5432"
    volumes:
      - pgdata:/var/lib/postgresql

  db-test:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: bozor
      POSTGRES_PASSWORD: bozor
      POSTGRES_DB: bozor_test
    ports:
      - "127.0.0.1:5483:5432"
    volumes:
      - pgtest:/var/lib/postgresql

volumes:
  pgdata:
  pgtest:
```

`db-test`ning yangi bloki `db` qoidalarini takrorlaydi; faqat servis nomi, baza, host porti va volume nomi oʻzgardi.
Pastdagi `pgtest:` ikkinchi volume'ni eʼlon qiladi. `solution/`da oʻz `go.mod` fayli ham bor.
Tekshirish uchun `cd solution` qiling, keyin yuqoridagi beshta buyruqni shu papkada bajaring.
Yechimning qayta ishlatilgan testi:

```console
$ CGO_ENABLED=0 go test ./...
ok  	github.com/abdurahmon27/bozor	0.305s
```

`ok` — test oʻtdi; keyingi yoʻl modul nomi, oxirgi son bajarilish vaqti.
Videoning tekshiruvida `1.159s` edi; bu safargi vaqtni yuqorida koʻrasiz. Bu yuklama sinovi emas, nisbatini unumdorlik yutugʻi deb talqin qilmang.

</details>

Ish tugagach, hozirgi loyiha container'lari va volume'larini tozalang. Javob papkasida boʻlsangiz, buyruqni oʻsha yerda bajaring:

```bash
docker compose down -v
```
