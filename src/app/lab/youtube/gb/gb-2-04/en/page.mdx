## What you will learn

The function `sell` lowered the stock of apples (`olma`) from 40 to 37 and printed "37" inside. After it returned to `main`, the stock
was 40 again. The compiler said nothing:

```console
$ ./_video/run.sh 01-nusxa go run .
sell ichida: 37
main'da: 40
```

The program is written correctly, but the result is wrong. What did `sell` change, and what must change so that the stock really goes down?

**One idea:** a pointer is the address of a value in memory. `&olma` takes the address, the variable `p` of type `*Product` stores it, and
`p.Stock` writes into the original value along that address. Go always copies: when you pass a pointer, the thing that is copied is the
address, and there is still only one value. A `nil` pointer points to nothing, and reading through it is a panic.

By the end of the lesson you will:

- see in a memory picture what is copied when a struct is passed to a function;
- take an address with `&olma` and, in `sell(p *Product, quantity int)`, lower the stock in the caller's value;
- return the address of an element from a catalog (`&products[i]`);
- read the panic from a nil pointer and prevent it with `if p == nil`.

Today's three core new words:

| Word | Plain meaning | English term |
|---|---|---|
| pointer | a variable that stores the memory address of a value. `&olma` is the address of `olma`, `*Product` is the type of such an address | pointer |
| passing a pointer to a function | the function gets a copy of the address, not a copy of the value, and can change the caller's value | passing a pointer |
| nil pointer | a pointer that points to nothing, the zero value of a `*T` type. Reading a value through it causes a panic | nil pointer |

Two helper ideas: the `-=` operation (`x -= n` means `x = x - n`) and the difference between `&products[i]` and `&p` (the last one is in the "Going deeper" section).

## The problem: sell reduced a copy

The program from the start of the lesson (`_video/01-nusxa/main.go`):

```go filename="_video/01-nusxa/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p Product, quantity int) {
	p.Stock -= quantity
	fmt.Println("sell ichida:", p.Stock)
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	sell(olma, 3)
	fmt.Println("main'da:", olma.Stock)
}
```

Lines 1–11 are the `Product` type from GB-2.03; it has not changed. The new and important lines:

| Line | Code | What it does |
|---|---|---|
| 13 | `func sell(p Product, quantity int) {` | `sell` takes two parameters: `p` (type `Product`, the product being sold) and `quantity` (how many units were sold) |
| 14 | `p.Stock -= quantity` | `-=` ("minus equals") is the opposite of `+=`: it subtracts `quantity` from `p.Stock` and writes the result into the same field. The same as `p.Stock = p.Stock - quantity` |
| 15 | `fmt.Println("sell ichida:", p.Stock)` | prints the stock inside `sell` ("sell ichida" means "inside sell") |
| 19 | `olma := Product{ID: 1, …, Stock: 40}` | `olma` is a product with stock 40 |
| 20 | `sell(olma, 3)` | calls `sell` with `olma` and 3: 3 units were sold |
| 21 | `fmt.Println("main'da:", olma.Stock)` | `main` prints the stock of its own `olma` ("main'da" means "in main") |

When a function is called, Go **copies** the argument's value into the parameter. In the words of the Go FAQ, *"everything in Go is
passed by value"* ([Go FAQ](https://go.dev/doc/faq#pass_by_value), [Go spec: Calls](https://go.dev/ref/spec#Calls)). A struct is one
whole value, so the copy is whole too: all four fields. In memory it looks like this (`olma.Stock` is the value in `main`, `p.Stock` is
the copy in `sell`):

| What happened | `olma.Stock` | `p.Stock` | On screen |
|---|---|---|---|
| `olma := Product{…Stock: 40}` (before line 20) | 40 | `p` does not exist yet | |
| `sell(olma, 3)` called: `p` is a full copy of `olma`, `quantity` is 3 | 40 | 40 | |
| `p.Stock -= quantity` (line 14) | 40 | **37** | |
| `fmt.Println("sell ichida:", …)` (line 15) | 40 | 37 | `sell ichida: 37` |
| `sell` finished: `p` disappeared with its copy | 40 | gone | |
| `fmt.Println("main'da:", …)` (line 21) | 40 | gone | `main'da: 40` |

The compiler is silent because there is no error: `sell` correctly reduced its own copy. What was lost is the change reaching `olma` in `main`.
For that, `sell` needs not a copy of `olma` but its **address**.

## Pointer: the address of a value

The label `olma` is attached to one value in memory (a cell). That cell has its own place in memory, that is, an **address**.
A variable that stores the address of a value is called a **pointer**. Two new symbols:

- `&olma` means "the address of `olma`" (ampersand);
- `*Product` is the type of a pointer: "a pointer to `Product`". A variable of this type stores not the `Product` itself but its address.

A small program (`_video/02-pointer/main.go`):

```go filename="_video/02-pointer/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	olma := Product{Name: "olma", Stock: 40}
	p := &olma
	p.Stock = 37
	q := p
	q.Stock = 35
	fmt.Println(olma.Stock, p.Stock)
}
```

| Line | Code | What it does |
|---|---|---|
| 14 | `olma := Product{Name: "olma", Stock: 40}` | creates the value `olma`. To keep the picture simple, `ID` and `Price` are not set: they are zero values, that is, 0 |
| 15 | `p := &olma` | `p` is a new variable of type `*Product`. Its cell holds not a `Product` but the address of `olma` |
| 16 | `p.Stock = 37` | Go follows the address in `p` to `olma` itself and writes 37 into its `Stock` field |
| 17 | `q := p` | `q` is also a `*Product`. What lies in the cell of `p` is copied, that is, the address |
| 18 | `q.Stock = 35` | follows the address in `q` and writes 35 into `Stock` |
| 19 | `fmt.Println(olma.Stock, p.Stock)` | prints the stock of `olma` and the stock through `p` |

The picture after line 16:

```text
olma → [ ID 0 | Name "olma" | Price 0 | Stock 37 ] ◄──┐
                                                       │
p    → [ address ] ────────────────────────────────────┘
```

The cell of `p` holds no new `Product`, only an arrow to `olma`. Now lines 17–18: `q := p` and `q.Stock = 35`. What does the last line print?

**A)** `37 35` · **B)** `35 35` · **C)** `37 37`

<details>
<summary>Answer</summary>

**B: `35 35`.** `q := p` copies the pointer, that is, the address: now two arrows lead to the same `olma`. Writing through `q` changes that same `olma`,
so both `olma.Stock` and `p.Stock` are 35. If you chose **A**, you thought `q := p` creates a new `Product` (that is the struct rule from
GB-2.03, not the pointer rule). **C**: you did not take `q.Stock = 35` into account.

```text
olma → [ ID 0 | Name "olma" | Price 0 | Stock 35 ] ◄──┬────┐
                                                       │    │
p    → [ address ] ────────────────────────────────────┘    │
q    → [ address ] ─────────────────────────────────────────┘
```

</details>

```console
$ ./_video/run.sh 02-pointer go run .
35 35
```

The state line by line (`olma.Stock` and `p.Stock` are two names for one cell):

| Line | `olma.Stock` | `p` | `q` | On screen |
|---|---|---|---|---|
| 14 | 40 | none | none | |
| 15 | 40 | → `olma` | none | |
| 16 | 37 | → `olma` | none | |
| 17 | 37 | → `olma` | → `olma` (address copied) | |
| 18 | 35 | → `olma` | → `olma` | |
| 19 | 35 | → `olma` | → `olma` | `35 35` |

The copy rule did not change: Go still copies, only now the thing copied is an address. With a struct, the copy was the whole value.

### `*` in an expression and the `p.Stock` notation

The symbol `*` appears in two places. In a type (`*Product`) it means "pointer type". In an expression (`*p`) it means "the value that `p` points
to itself": going along the address to the value, which is called **dereferencing** (dereference). So `p.Stock` is really
`(*p).Stock`, that is, "the `Stock` field of the `Product` that `p` points to". Go adds the parentheses and the star itself, so you write `p.Stock`
([Go spec: Selectors](https://go.dev/ref/spec#Selectors), [A Tour of Go: Pointers to structs](https://go.dev/tour/moretypes/4)).

A program that checks this (it is not in the course folder, I ran it):

```go
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	olma := Product{Name: "olma", Stock: 40}
	p := &olma
	q := p
	fmt.Println(p == q, p == &olma)
	fmt.Println((*p).Stock, p.Stock)
	fmt.Println(*p)
	var z *Product
	fmt.Println(z == nil)
}
```

```console
$ go run .
true true
40 40
{0 olma 0 40}
true
```

- `p == q` and `p == &olma` are `true`: two pointers are equal if they store the same address
  ([Go spec: Comparison operators](https://go.dev/ref/spec#Comparison_operators)).
- `(*p).Stock` and `p.Stock` are the same: `40 40`.
- `fmt.Println(*p)` prints the whole `Product`: in curly braces, the fields in order (`ID`, `Name`, `Price`, `Stock`)
  ([pkg.go.dev/fmt](https://pkg.go.dev/fmt)).
- `var z *Product` is a pointer declared without a value: its zero value is `nil`, so `z == nil` is `true`. More on this in the
  nil pointer section.

## Passing a pointer to a function

Now let us fix `sell`: the parameter type becomes `*Product`. `sell` gets not a copy of the product but its address. The body does not change:
`p.Stock` follows the address. We removed the `Println` from `sell`. The call in `main` stayed as it was (`_video/03-xato/main.go`):

```go filename="_video/03-xato/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	sell(olma, 3)
	fmt.Println("main'da:", olma.Stock)
}
```

`p *Product` on line 13 means "`p` is a pointer to `Product`". `sell(olma, 3)` on line 19 still passes `olma`, that is, a `Product` value.
Will this code compile, and if so, what does it print?

**A)** `main'da: 37` · **B)** `main'da: 40` · **C)** compile error

<details>
<summary>Answer</summary>

**C: compile error.** `sell` now expects a `*Product`, and `olma` is a `Product`: two different types, and Go does not turn a value into an address
by itself ([Go spec: Assignability](https://go.dev/ref/spec#Assignability)). If you chose **A**, you thought Go takes the address of `olma` itself.
If you chose **B**, you thought the old copy rule still applies: in fact the program does not run at all.

</details>

```console
$ ./_video/run.sh 03-xato go run .
# github.com/abdurahmon27/bozor
./main.go:19:7: cannot use olma (variable of struct type Product) as *Product value in argument to sell
```

How to read it:

- `# github.com/abdurahmon27/bozor`: which module is being compiled (GB-1.01);
- `./main.go:19:7`: file, line and column: line 19, column 7 (the tab at the start of the line is one column, then `sell(`, so `olma` is at column 7);
- `cannot use olma (variable of struct type Product) as *Product value in argument to sell`: "`olma` (a variable of struct type `Product`)
  cannot be used as a `*Product` value in the argument to `sell`".

The fix is to add `&` to the call (`_video/04-sell/main.go`; only line 19 changed):

```go filename="_video/04-sell/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	sell(&olma, 3)
	fmt.Println("main'da:", olma.Stock)
}
```

```console
$ ./_video/run.sh 04-sell go run .
main'da: 37
```

Now `main` shows 37. In memory:

| What happened | `olma.Stock` | `p` | `quantity` |
|---|---|---|---|
| `olma := Product{…Stock: 40}` | 40 | none | none |
| `sell(&olma, 3)` called: `p` is a copy of the address of `olma` | 40 | → `olma` | 3 |
| `p.Stock -= quantity`: writes into `olma` itself along the address | **37** | → `olma` | 3 |
| `sell` finished: `p` disappeared | 37 | none | none |

The argument was copied again, but what is copied is the address. The words of the Go FAQ: *"passing a pointer value makes a copy of the pointer,
but not the data it points to"* ([Go FAQ](https://go.dev/doc/faq#pass_by_value)). Even when `p` is gone, the change stays in `olma`.

**The rule.** If a function must change the caller's value, pass a pointer: this is visible in the function's signature (`p *Product`).
If the function only reads, pass a small struct like `Product` by value: the copy is cheap and the function cannot damage the original
value. Go Code Review Comments: *"Don't pass pointers as function arguments just to save a few bytes"*
([Pass Values](https://go.dev/wiki/CodeReviewComments#pass-values)).

**`*testing.T` is the same thing.** In GB-1.08 the test function was `func TestXxx(t *testing.T)` and we postponed the `*`:

```go
func TestVazifaSellByID(t *testing.T) {
```

`go test` gives the test function the address of a `testing.T` value. Through that address `t.Errorf` marks the test as failed
([pkg.go.dev/testing](https://pkg.go.dev/testing)). It is the same mechanism as `sell(p *Product, …)`.

## Finding in the catalog: &products[i]

In a real bozor a product is found in the catalog by ID. `findProduct` takes a slice of products and an ID, and returns a `*Product`.
`_video/05-find/main.go`:

```go filename="_video/05-find/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

// findProduct katalogdan ID boʻyicha mahsulotni topadi: topilsa elementning manzili, topilmasa nil.
func findProduct(products []Product, id int64) *Product {
	for i := range products {
		if products[i].ID == id {
			return &products[i]
		}
	}
	return nil
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	p := findProduct(catalog, 2)
	sell(p, 1)
	fmt.Println(catalog[1].Stock)
}
```

| Line | Code | What it does |
|---|---|---|
| 18 | `func findProduct(products []Product, id int64) *Product {` | parameters: a slice of products (GB-2.01) and `id`; the result type is `*Product` |
| 19 | `for i := range products {` | walks over the indexes, as in GB-2.01 |
| 20 | `if products[i].ID == id {` | is the `ID` of element number `i` equal to the wanted `id` |
| 21 | `return &products[i]` | on a match, returns the **address** of `products[i]`: the element itself inside the slice, not a copy of it |
| 24 | `return nil` | if nothing matched, returns `nil`: a pointer that points to nothing |
| 28–31 | `catalog := []Product{ … }` | the catalog: `olma` and `non` ("bread"; stock 100), `Product` is not written in the literal (GB-2.03) |
| 32 | `p := findProduct(catalog, 2)` | finds the product with ID 2, that is, `non` |
| 33 | `sell(p, 1)` | sells one `non`. There is no `&` here: `p` is already a `*Product` |
| 34 | `fmt.Println(catalog[1].Stock)` | the stock of the second element of the catalog; indexes start at 0, so `[1]` is `non` |

(The `p` in `main` and the `p` in `sell` are two different variables; the name is the same by chance.) What does the last line print?

**A)** `100` · **B)** `99` · **C)** compile error

<details>
<summary>Answer</summary>

**B: `99`.** `&products[i]` is the address of the element itself inside the slice. `findProduct` receives a copy of the slice header, but it points to the
same array (GB-2.01), so the address points into the array of `catalog`, and `sell` lowers exactly that element. A slice element can have its
address taken ([Go spec: Address operators](https://go.dev/ref/spec#Address_operators)). If you chose **A**, you thought `findProduct`
returns a copy. **C**: the code is correct.

```text
catalog → [ {ID 1, "olma", … Stock 40} | {ID 2, "non", … Stock 100 → 99} ]
                                                  ▲
p ────────────────────────────────────────────────┘   (&products[1])
```

</details>

```console
$ ./_video/run.sh 05-find go run .
99
```

## nil pointer: an address that points nowhere

If `findProduct` finds nothing, it returns `nil`. `nil` is the zero value of a pointer: the cell of `p` has no arrow. Let us ask for ID 9, which is not
in the catalog (`_video/06-nil/main.go`):

```go filename="_video/06-nil/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

// findProduct katalogdan ID boʻyicha mahsulotni topadi: topilsa elementning manzili, topilmasa nil.
func findProduct(products []Product, id int64) *Product {
	for i := range products {
		if products[i].ID == id {
			return &products[i]
		}
	}
	return nil
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	p := findProduct(catalog, 9)
	fmt.Println(p == nil)
	fmt.Println(p.Stock)
}
```

Line 33 checks `p == nil`: is `p` equal to `nil`? It prints `true`. Line 34 tries to read `Stock` through a nil pointer, but at the end of the arrow
there is no `Product`. What happens?

**A)** `0`, because it is a zero value · **B)** panic · **C)** compile error

<details>
<summary>Answer</summary>

**B: panic.** The compiler does not catch this: that `p` is `nil` is known only while the program runs. If you chose **A**,
you thought a zero value exists everywhere: `int` has `0`, but behind `nil` there is no `Product` at all, so there is nowhere to read `Stock` from.
**C**: the code compiles.

</details>

```console
$ ./_video/run.sh 06-nil go run .
```

(I shortened the temporary folder in the panic to `/tmp/…`; the rest is printed as it came out. The video shows only the first two lines.) How to read it:

- `true`: line 33 ran, `p == nil`;
- `panic: runtime error: invalid memory address or nil pointer dereference`: an error at run time (runtime): the memory address is invalid,
  because we **dereferenced** a nil pointer, that is, we tried to go to the value it points to. The spec says it like this:
  *"If x is nil, an attempt to evaluate `*x` will cause a run-time panic"* ([Go spec: Address operators](https://go.dev/ref/spec#Address_operators));
- `[signal SIGSEGV …]`: the operating system's signal for a memory access that is not allowed: for now this is all you need to know;
- `goroutine 1 [running]:` and `main.main()`: the chain of calls at the moment of the panic, `main.go:34` is the line with `p.Stock`;
- `exit status 2`: the exit code after a panic is 2 (GB-1.07).

`0` did not appear because a zero value exists where there is a value, and behind `nil` there is no `Product`.

**The fix:** after a function that returns a pointer, check for `nil`. If `p == nil`, print a message and leave `main` with `return`
(as in GB-1.05). In the lines after it, `p` is certainly not `nil` (`_video/07-guard/main.go`):

```go filename="_video/07-guard/main.go" showLineNumbers

	p.Stock -= quantity
}

// findProduct katalogdan ID boʻyicha mahsulotni topadi: topilsa elementning manzili, topilmasa nil.

	for i := range products {
		if products[i].ID == id {

		}
	}
```

## Going deeper (optional): the address of the range variable

If you write `findProduct` with the second value of `range`, the code also compiles (`_video/08-range/main.go`):

```go filename="_video/08-range/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

// findProduct — XATO variant: range bergan p elementning nusxasi.
func findProduct(products []Product, id int64) *Product {
	for _, p := range products {
		if p.ID == id {
			return &p
		}
	}
	return nil
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	p := findProduct(catalog, 2)
	sell(p, 1)
	fmt.Println(p.Stock, catalog[1].Stock)
}
```

On line 19 `p` is the variable that `range` gives. By the spec, `range` assigns each element to the variable like an ordinary assignment
([Go spec: For statements with range clause](https://go.dev/ref/spec#For_range)): `p` is a **copy** of the element, just like `q := p` for a struct. And `&p` is the address of that
copy, not of the catalog element. Since Go 1.22 `p` is a new variable on each iteration, but it is still a copy. `main`, as before, finds `non`,
sells it and prints the stock through `p`, then the stock in the catalog. Which two numbers are printed?

**A)** `99 99` · **B)** `99 100` · **C)** `100 100`

<details>
<summary>Answer</summary>

**B: `99 100`.** `sell` reduced the copy (100 → 99), and `non` in the catalog is still 100. If you chose **A**, you thought `&p` points to the
catalog element. **C**: you thought `sell` did not touch even the copy.

</details>

```console
$ ./_video/run.sh 08-range go run .
99 100
```

If you need the address of an element, go by index: `&products[i]`. The test in the task catches exactly this mistake.

One more precaution (it is not in the video, it comes from the README of the course folder): the pointer that `findProduct` returned points into the
array of the catalog slice. If `append` later makes a new array (GB-2.01), the old pointer changes the old array, and the catalog does not change.
This program is not in the course folder, I ran it myself:

```go
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
	}
	p := &catalog[0]
	catalog = append(catalog, Product{ID: 2, Name: "non", Price: 400_000, Stock: 100})
	p.Stock = 0
	fmt.Println(p.Stock, catalog[0].Stock)
}
```

```console
$ go run .
0 40
```

The capacity of `catalog` was 1, `append` made a new array, and `p` stayed on the old one: `p.Stock = 0` was written into the old element.
The rule: do not keep the pointer, and after changing the catalog, find the product again.

## Common mistakes

**1. "The function changed the argument, so it changes in `main` too".** The most common mistake: `sell(p Product, …)` changes its own copy,
the value in `main` does not change, and the compiler is silent. This is exactly what the start of the lesson showed: `sell ichida: 37` / `main'da: 40` (the
"The problem" section). The fix: make the parameter type `*Product` and call `sell(&olma, 3)`.

**2. Mixing up `Product` and `*Product`.** `sell(olma, 3)` is a `Product` where a `*Product` is expected:
`cannot use olma (variable of struct type Product) as *Product value in argument to sell` (the "Passing a pointer to a function" section).
The fix: `&olma`.

**3. A pointer not checked for `nil`.** If you read `p.Stock` right after `findProduct` and the ID is not found:
`panic: runtime error: invalid memory address or nil pointer dereference` (the nil pointer section). The fix: `if p == nil { … return }`.

**4. `for _, p := range` and `&p`.** `p` is a copy of the element, `&p` is the address of the copy: `sell` does not change the catalog and gives no error
(`99 100`, the "Going deeper" section). The fix: `&products[i]`.

**5. Comparing `nil` with `0`.** Beginners check the "emptiness" of a pointer with `0`. This program is not in the course folder, I ran it:

```go
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	var p *Product
	if p == 0 {
		fmt.Println("topilmadi")
	}
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:15:10: invalid operation: p == 0 (mismatched types *Product and untyped int)
```

`./main.go:15:10`: line 15, column 10 (the digit `0`). The message: "the operation `p == 0` is invalid: the types do not match: `*Product` and an integer
without a fixed type (`untyped int`)". `nil` is not `0`: compare a pointer only with `nil`, `if p == nil`.

## Check yourself

**1.** What is `p` equal to if it is declared as `var p *Product` and given no value?

<details>
<summary>Answer</summary>

`nil`: the zero value of a pointer, it points to nothing. In the `manzil` program above, `var z *Product` and `z == nil` showed this (`true`).

</details>

**2.** The function `f` has a parameter `p Product` and sets `p.Stock` to 0. Does the caller's `olma` change?

<details>
<summary>Answer</summary>

No: the parameter gets a copy of `olma` and disappears together with it. To change it, the parameter type must be `*Product` and the call must be `f(&olma)`.

</details>

**3.** (GB-2.01) After `t := s`, `t[0] = 9` was executed. Does `s[0]` change?

<details>
<summary>Answer</summary>

Yes. `t := s` copies the slice header, but the pointer inside the header leads to the same array: both slices see one array. This is the same
rule as with a pointer: there is a copy, but what is copied is an address.

</details>

**4.** What does this program print? (It is not in the course folder, I ran it.)

```go filename="solution/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

// findProduct katalogdan ID boʻyicha mahsulotni topadi: topilsa elementning manzili, topilmasa nil.
func findProduct(products []Product, id int64) *Product {
	for i := range products {
		if products[i].ID == id {
			return &products[i]
		}
	}
	return nil
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	p := findProduct(catalog, 9)
	if p == nil {
		fmt.Println("mahsulot topilmadi: 9")
		return
	}
	sell(p, 1)
	fmt.Println(p.Stock)
}

// sellByID katalogdagi id raqamli mahsulotdan quantity dona sotadi va xatoni qaytaradi.
func sellByID(products []Product, id int64, quantity int) error {
	p := findProduct(products, id)
	if p == nil {
		return fmt.Errorf("mahsulot topilmadi: %d", id)
	}
	if quantity <= 0 {
		return fmt.Errorf("miqdor musbat boʻlishi kerak, keldi %d", quantity)
	}
	if quantity > p.Stock {
		return fmt.Errorf("%s: qoldiq %d, soʻralgan %d", p.Name, p.Stock, quantity)
	}
	sell(p, quantity)
	return nil
}

// cheapest katalogdagi eng arzon mahsulotning manzilini qaytaradi; katalog boʻsh boʻlsa nil.
func cheapest(products []Product) *Product {
	var best *Product
	for i := range products {
		if best == nil || products[i].Price < best.Price {
			best = &products[i]
		}
	}
	return best
}
```

- `sellByID`: first `p := findProduct(products, id)`, the address of a catalog element. If `p == nil`, it returns an error instead of a panic.
  Then two conditions: `quantity <= 0` and `quantity > p.Stock`. `sell(p, quantity)` is called only **after** all the checks, so on an error
  the stock does not change.
- `cheapest`: `var best *Product` has the zero value `nil`. The loop goes by index (`for i := range products`). In the condition `best == nil || products[i].Price < best.Price` the `||` means "or": if the left side is true, the right side is not evaluated
  ([Go spec: Logical operators](https://go.dev/ref/spec#Logical_operators)), so while `best` is still `nil`, `best.Price` does not cause a
  panic. On a match, `best = &products[i]`: the address of the catalog element, not of the copy from `range`.
