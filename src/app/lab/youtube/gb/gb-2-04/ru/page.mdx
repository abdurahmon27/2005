## Что вы узнаете

Функция `sell` уменьшила остаток яблок (`olma`) с 40 до 37 и напечатала внутри «37». Но после возврата в `main` остаток снова 40.
Компилятор ничего не сказал:

```console
$ ./_video/run.sh 01-nusxa go run .
sell ichida: 37
main'da: 40
```

Программа написана правильно, а вывод неверный. Что изменила `sell` и что нужно поменять, чтобы остаток действительно уменьшился?

**Главная идея:** указатель — это адрес значения в памяти. `&olma` берёт адрес, переменная `p` типа `*Product` его хранит, а `p.Stock`
по этому адресу записывает в исходное значение. Go всегда копирует: если передан указатель, копируется адрес, а значение остаётся одно.
`nil`-указатель никуда не указывает, и чтение через него — это panic.

К концу урока вы:

- увидите на схеме памяти, что копируется при передаче структуры в функцию;
- возьмёте адрес через `&olma` и в функции `sell(p *Product, quantity int)` уменьшите остаток в значении вызывающего кода;
- вернёте из каталога адрес элемента (`&products[i]`);
- прочитаете panic из-за nil-указателя и предотвратите его проверкой `if p == nil`.

Три основных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| указатель | переменная, которая хранит адрес значения в памяти. `&olma` — адрес `olma`, `*Product` — тип такого адреса | pointer |
| передача указателя в функцию | функция получает не копию значения, а копию адреса и может изменить значение вызывающего кода | passing a pointer |
| nil-указатель | указатель, который никуда не указывает, нулевое значение (zero value) типа `*T`. Чтение значения через него вызывает panic | nil pointer |

Два вспомогательных понятия: операция `-=` (`x -= n` — это `x = x - n`) и разница между `&products[i]` и `&p` (последнее — в разделе «Глубже»).

## Проблема: sell уменьшила копию

Программа из начала урока (`_video/01-nusxa/main.go`):

```go filename="_video/01-nusxa/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p Product, quantity int) {
	p.Stock -= quantity
	fmt.Println("sell ichida:", p.Stock)
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	sell(olma, 3)
	fmt.Println("main'da:", olma.Stock)
}
```

Строки 1–11 — тип `Product` из GB-2.03, он не изменился. Новые и важные строки:

| Строка | Код | Что делает |
|---|---|---|
| 13 | `func sell(p Product, quantity int) {` | `sell` принимает два параметра: `p` (тип `Product`, продаваемый товар) и `quantity` (сколько штук продано) |
| 14 | `p.Stock -= quantity` | `-=` («минус равно») — противоположность `+=`: вычитает `quantity` из `p.Stock` и записывает результат в это же поле. То же, что `p.Stock = p.Stock - quantity` |
| 15 | `fmt.Println("sell ichida:", p.Stock)` | печатает остаток внутри `sell` («sell ichida» — «внутри sell») |
| 19 | `olma := Product{ID: 1, …, Stock: 40}` | `olma` — товар с остатком 40 |
| 20 | `sell(olma, 3)` | вызывает `sell` с `olma` и числом 3: продано 3 штуки |
| 21 | `fmt.Println("main'da:", olma.Stock)` | `main` печатает остаток своего `olma` («main'da» — «в main») |

При вызове функции Go **копирует** значение аргумента в параметр. По словам Go FAQ, *«everything in Go is passed by value»*
([Go FAQ](https://go.dev/doc/faq#pass_by_value), [Go spec: Calls](https://go.dev/ref/spec#Calls)). Структура — это цельное
значение, поэтому копия тоже цельная: все четыре поля. В памяти это выглядит так (`olma.Stock` — значение в `main`, `p.Stock` —
копия в `sell`):

| Что произошло | `olma.Stock` | `p.Stock` | На экране |
|---|---|---|---|
| `olma := Product{…Stock: 40}` (до строки 20) | 40 | `p` ещё нет | |
| вызвана `sell(olma, 3)`: `p` — полная копия `olma`, `quantity` — 3 | 40 | 40 | |
| `p.Stock -= quantity` (строка 14) | 40 | **37** | |
| `fmt.Println("sell ichida:", …)` (строка 15) | 40 | 37 | `sell ichida: 37` |
| `sell` завершилась: `p` исчезла вместе с копией | 40 | нет | |
| `fmt.Println("main'da:", …)` (строка 21) | 40 | нет | `main'da: 40` |

Компилятор молчит, потому что ошибки нет: `sell` верно уменьшила свою копию. Пропало другое: изменение не дошло до `olma` в `main`.
Для этого `sell` нужна не копия `olma`, а её **адрес**.

## Указатель: адрес значения

Ярлык `olma` приклеен к одному значению в памяти (к ячейке). У этой ячейки есть своё место в памяти, то есть **адрес** (address).
Переменная, которая хранит адрес значения, называется **указателем** (pointer). Два новых знака:

- `&olma` — «адрес `olma`» (амперсанд);
- `*Product` — тип указателя: «указатель на `Product`». Переменная такого типа хранит не сам `Product`, а его адрес.

Маленькая программа (`_video/02-pointer/main.go`):

```go filename="_video/02-pointer/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	olma := Product{Name: "olma", Stock: 40}
	p := &olma
	p.Stock = 37
	q := p
	q.Stock = 35
	fmt.Println(olma.Stock, p.Stock)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 14 | `olma := Product{Name: "olma", Stock: 40}` | создаёт значение `olma`. Чтобы схема была проще, `ID` и `Price` не заданы: это нулевое значение, то есть 0 |
| 15 | `p := &olma` | `p` — новая переменная типа `*Product`. В её ячейке лежит не `Product`, а адрес `olma` |
| 16 | `p.Stock = 37` | Go идёт по адресу из `p` к самому `olma` и записывает 37 в его поле `Stock` |
| 17 | `q := p` | `q` — тоже `*Product`. Копируется то, что лежит в ячейке `p`, то есть адрес |
| 18 | `q.Stock = 35` | идёт по адресу из `q` и записывает 35 в `Stock` |
| 19 | `fmt.Println(olma.Stock, p.Stock)` | печатает остаток `olma` и остаток через `p` |

Схема после строки 16:

```text
olma → [ ID 0 | Name "olma" | Price 0 | Stock 37 ] ◄──┐
                                                       │
p    → [ адрес ] ──────────────────────────────────────┘
```

В ячейке `p` нет нового `Product`, только стрелка к `olma`. Теперь строки 17–18: `q := p` и `q.Stock = 35`. Что напечатает последняя строка?

**A)** `37 35` · **B)** `35 35` · **C)** `37 37`

<details>
<summary>Ответ</summary>

**B: `35 35`.** `q := p` копирует указатель, то есть адрес: теперь две стрелки ведут к одному `olma`. Запись через `q` тоже меняет этот `olma`,
поэтому и `olma.Stock`, и `p.Stock` равны 35. Если вы выбрали **A**, вы решили, что `q := p` создаёт новый `Product` (это правило для
структур из GB-2.03, а не для указателей). **C** — вы не учли `q.Stock = 35`.

```text
olma → [ ID 0 | Name "olma" | Price 0 | Stock 35 ] ◄──┬────┐
                                                       │    │
p    → [ адрес ] ──────────────────────────────────────┘    │
q    → [ адрес ] ───────────────────────────────────────────┘
```

</details>

```console
$ ./_video/run.sh 02-pointer go run .
35 35
```

Состояние по строкам (`olma.Stock` и `p.Stock` — две записи одной ячейки):

| Строка | `olma.Stock` | `p` | `q` | На экране |
|---|---|---|---|---|
| 14 | 40 | нет | нет | |
| 15 | 40 | → `olma` | нет | |
| 16 | 37 | → `olma` | нет | |
| 17 | 37 | → `olma` | → `olma` (адрес скопирован) | |
| 18 | 35 | → `olma` | → `olma` | |
| 19 | 35 | → `olma` | → `olma` | `35 35` |

Правило копирования не изменилось: Go по-прежнему копирует, просто теперь копируется адрес. У структуры копия была цельным значением.

### `*` в выражении и запись `p.Stock`

Знак `*` встречается в двух местах. В типе (`*Product`) он означает «тип указателя». В выражении (`*p`) он означает «само значение, на которое
указывает `p`»: переход по адресу к значению, это называется **разыменованием** (dereference). Значит, `p.Stock` — это на самом деле
`(*p).Stock`, то есть «поле `Stock` у `Product`, на который указывает `p`». Скобки и звёздочку Go ставит сам, поэтому вы пишете `p.Stock`
([Go spec: Selectors](https://go.dev/ref/spec#Selectors), [A Tour of Go: Pointers to structs](https://go.dev/tour/moretypes/4)).

Программа, которая это проверяет (в папке курса её нет, я её запускал):

```go
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	olma := Product{Name: "olma", Stock: 40}
	p := &olma
	q := p
	fmt.Println(p == q, p == &olma)
	fmt.Println((*p).Stock, p.Stock)
	fmt.Println(*p)
	var z *Product
	fmt.Println(z == nil)
}
```

```console
$ go run .
true true
40 40
{0 olma 0 40}
true
```

- `p == q` и `p == &olma` — `true`: два указателя равны, если хранят один адрес
  ([Go spec: Comparison operators](https://go.dev/ref/spec#Comparison_operators)).
- `(*p).Stock` и `p.Stock` одинаковы: `40 40`.
- `fmt.Println(*p)` печатает весь `Product`: в фигурных скобках поля по порядку (`ID`, `Name`, `Price`, `Stock`)
  ([pkg.go.dev/fmt](https://pkg.go.dev/fmt)).
- `var z *Product` — указатель, объявленный без значения: его нулевое значение — `nil`, поэтому `z == nil` — `true`. Подробнее — в разделе
  про nil-указатель.

## Передача указателя в функцию

Теперь исправим `sell`: тип параметра становится `*Product`. `sell` получает не копию товара, а его адрес. Тело не меняется: `p.Stock`
идёт по адресу. `Println` из `sell` мы убрали. А вызов в `main` остался прежним (`_video/03-xato/main.go`):

```go filename="_video/03-xato/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	sell(olma, 3)
	fmt.Println("main'da:", olma.Stock)
}
```

`p *Product` в строке 13 — «`p` — указатель на `Product`». `sell(olma, 3)` в строке 19 по-прежнему передаёт `olma`, то есть значение `Product`.
Скомпилируется ли этот код, и если да, что он напечатает?

**A)** `main'da: 37` · **B)** `main'da: 40` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**C: ошибка компиляции.** `sell` теперь ждёт `*Product`, а `olma` — это `Product`: два разных типа, и Go не превращает значение в адрес
сам ([Go spec: Assignability](https://go.dev/ref/spec#Assignability)). Если вы выбрали **A**, вы решили, что Go сам возьмёт адрес `olma`.
Если **B** — что старое правило копирования всё ещё работает: на самом деле программа вообще не запустится.

</details>

```console
$ ./_video/run.sh 03-xato go run .
# github.com/abdurahmon27/bozor
./main.go:19:7: cannot use olma (variable of struct type Product) as *Product value in argument to sell
```

Как читать:

- `# github.com/abdurahmon27/bozor` — какой модуль компилируется (GB-1.01);
- `./main.go:19:7` — файл, строка и столбец: строка 19, столбец 7 (табуляция в начале строки — один столбец, затем `sell(`, поэтому `olma` в столбце 7);
- `cannot use olma (variable of struct type Product) as *Product value in argument to sell` — «нельзя использовать `olma` (переменную
  типа структуры `Product`) как значение `*Product` в аргументе `sell`».

Исправление — добавить `&` в вызов (`_video/04-sell/main.go`; изменилась только строка 19):

```go filename="_video/04-sell/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

func main() {
	olma := Product{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40}
	sell(&olma, 3)
	fmt.Println("main'da:", olma.Stock)
}
```

```console
$ ./_video/run.sh 04-sell go run .
main'da: 37
```

Теперь в `main` 37. В памяти:

| Что произошло | `olma.Stock` | `p` | `quantity` |
|---|---|---|---|
| `olma := Product{…Stock: 40}` | 40 | нет | нет |
| вызвана `sell(&olma, 3)`: `p` — копия адреса `olma` | 40 | → `olma` | 3 |
| `p.Stock -= quantity`: по адресу записывается в сам `olma` | **37** | → `olma` | 3 |
| `sell` завершилась: `p` исчезла | 37 | нет | нет |

Аргумент снова скопирован, но копируется адрес. Слова Go FAQ: *«passing a pointer value makes a copy of the pointer, but not the data it points to»*
([Go FAQ](https://go.dev/doc/faq#pass_by_value)). Даже когда `p` исчезла, изменение осталось в `olma`.

**Правило.** Если функция должна изменить значение вызывающего кода, передавайте указатель: это видно в сигнатуре функции (`p *Product`).
Если функция только читает, небольшую структуру вроде `Product` передавайте по значению: копия дешёвая, а функция не может испортить
исходное значение. Go Code Review Comments: *«Don't pass pointers as function arguments just to save a few bytes»*
([Pass Values](https://go.dev/wiki/CodeReviewComments#pass-values)).

**`*testing.T` — то же самое.** В GB-1.08 тестовая функция выглядела как `func TestXxx(t *testing.T)`, а `*` мы отложили:

```go
func TestVazifaSellByID(t *testing.T) {
```

`go test` передаёт тестовой функции адрес значения `testing.T`. Через этот адрес `t.Errorf` помечает тест как упавший
([pkg.go.dev/testing](https://pkg.go.dev/testing)). Это тот же механизм, что у `sell(p *Product, …)`.

## Поиск в каталоге: &products[i]

В настоящем bozor товар находят в каталоге по ID. `findProduct` принимает слайс товаров и ID, а возвращает `*Product`.
`_video/05-find/main.go`:

```go filename="_video/05-find/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

// findProduct katalogdan ID boʻyicha mahsulotni topadi: topilsa elementning manzili, topilmasa nil.
func findProduct(products []Product, id int64) *Product {
	for i := range products {
		if products[i].ID == id {
			return &products[i]
		}
	}
	return nil
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	p := findProduct(catalog, 2)
	sell(p, 1)
	fmt.Println(catalog[1].Stock)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 18 | `func findProduct(products []Product, id int64) *Product {` | параметры: слайс товаров (GB-2.01) и `id`; тип результата — `*Product` |
| 19 | `for i := range products {` | идёт по индексам, как в GB-2.01 |
| 20 | `if products[i].ID == id {` | равен ли `ID` элемента с номером `i` искомому `id` |
| 21 | `return &products[i]` | при совпадении возвращает **адрес** `products[i]`: сам элемент внутри слайса, а не его копию |
| 24 | `return nil` | если ничего не совпало, возвращается `nil`: указатель, который никуда не указывает |
| 28–31 | `catalog := []Product{ … }` | каталог: `olma` и `non` («хлеб»; остаток 100), в литерале `Product` не пишется (GB-2.03) |
| 32 | `p := findProduct(catalog, 2)` | находит товар с ID 2, то есть `non` |
| 33 | `sell(p, 1)` | продаёт один `non`. Здесь нет `&`: `p` уже `*Product` |
| 34 | `fmt.Println(catalog[1].Stock)` | остаток второго элемента каталога; индексы начинаются с 0, поэтому `[1]` — это `non` |

(`p` в `main` и `p` в `sell` — две разные переменные, имя совпало случайно.) Что напечатает последняя строка?

**A)** `100` · **B)** `99` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `99`.** `&products[i]` — адрес самого элемента внутри слайса. В `findProduct` приходит копия заголовка слайса, но она указывает на тот
же массив (GB-2.01), поэтому адрес указывает на массив `catalog`, и `sell` уменьшает именно этот элемент. Элемент слайса можно брать
по адресу ([Go spec: Address operators](https://go.dev/ref/spec#Address_operators)). Если вы выбрали **A**, вы решили, что `findProduct`
возвращает копию. **C** — код верный.

```text
catalog → [ {ID 1, "olma", … Stock 40} | {ID 2, "non", … Stock 100 → 99} ]
                                                  ▲
p ────────────────────────────────────────────────┘   (&products[1])
```

</details>

## nil-указатель: адрес, который никуда не указывает

Если `findProduct` ничего не нашла, она возвращает `nil`. `nil` — нулевое значение указателя: в ячейке `p` нет стрелки. Запросим ID 9, которого нет
в каталоге (`_video/06-nil/main.go`):

```go filename="_video/06-nil/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

// findProduct katalogdan ID boʻyicha mahsulotni topadi: topilsa elementning manzili, topilmasa nil.
func findProduct(products []Product, id int64) *Product {
	for i := range products {
		if products[i].ID == id {
			return &products[i]
		}
	}
	return nil
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	p := findProduct(catalog, 9)
	fmt.Println(p == nil)
	fmt.Println(p.Stock)
}
```

Строка 33 проверяет `p == nil`: равен ли `p` значению `nil`? Она напечатает `true`. Строка 34 пытается прочитать `Stock` через nil-указатель, но в конце стрелки
нет `Product`. Что будет?

**A)** `0`, ведь это нулевое значение · **B)** panic · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: panic.** Компилятор этого не ловит: что `p` равно `nil`, становится известно только во время работы программы. Если вы выбрали **A**,
вы решили, что нулевое значение есть везде: у `int` есть `0`, но за `nil` нет вообще никакого `Product`, и читать `Stock` неоткуда.
**C** — код компилируется.

</details>

```console
$ ./_video/run.sh 06-nil go run .

panic: runtime error: invalid memory address or nil pointer dereference
[signal SIGSEGV: segmentation violation code=0x1 addr=0x20 pc=0x499f50]

goroutine 1 [running]:
main.main()
	/tmp/…/bozor/main.go:34 +0x110
```

(Временную папку в panic я сократил до `/tmp/…`; остальное выведено как есть. В видео показаны только первые две строки.) Как читать:

- `true` — выполнилась строка 33: `p == nil`;
- `panic: runtime error: invalid memory address or nil pointer dereference` — ошибка времени выполнения (runtime): неверный адрес в памяти,
  потому что мы **разыменовали** nil-указатель, то есть попытались перейти к значению, на которое он указывает. Спецификация говорит так:
  *«If x is nil, an attempt to evaluate `*x` will cause a run-time panic»* ([Go spec: Address operators](https://go.dev/ref/spec#Address_operators));
- `[signal SIGSEGV …]` — сигнал операционной системы об обращении к памяти без разрешения: пока достаточно знать только это;
- `goroutine 1 [running]:` и `main.main()` — цепочка вызовов в момент panic, `main.go:34` — строка с `p.Stock`;
- `exit status 2` — код выхода после panic равен 2 (GB-1.07).

`0` не появился, потому что нулевое значение существует там, где есть значение, а за `nil` никакого `Product` нет.

**Исправление:** после функции, которая возвращает указатель, проверяйте `nil`. Если `p == nil`, напечатайте сообщение и выйдите из `main`
через `return` (как в GB-1.05). В следующих строках `p` точно не `nil` (`_video/07-guard/main.go`):


## Глубже (необязательно): адрес переменной, которую даёт range

Если написать `findProduct` со вторым значением `range`, код тоже скомпилируется (`_video/08-range/main.go`):

```go filename="_video/08-range/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

// findProduct — XATO variant: range bergan p elementning nusxasi.
func findProduct(products []Product, id int64) *Product {
	for _, p := range products {
		if p.ID == id {
			return &p
		}
	}
	return nil
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	p := findProduct(catalog, 2)
	sell(p, 1)
	fmt.Println(p.Stock, catalog[1].Stock)
}
```

В строке 19 `p` — переменная, которую даёт `range`. По спецификации `range` присваивает каждый элемент переменной как обычное присваивание
([Go spec: For statements with range clause](https://go.dev/ref/spec#For_range)): `p` — **копия** элемента, как `q := p` для структуры. А `&p` — адрес этой
копии, а не элемента каталога. С Go 1.22 на каждой итерации `p` — новая переменная, но всё равно копия. `main`, как и раньше, находит `non`,
продаёт его и печатает остаток через `p`, а затем остаток в каталоге. Какие два числа выведутся?

**A)** `99 99` · **B)** `99 100` · **C)** `100 100`

<details>
<summary>Ответ</summary>

**B: `99 100`.** `sell` уменьшила копию (100 → 99), а `non` в каталоге по-прежнему 100. Если вы выбрали **A**, вы решили, что `&p` указывает на
элемент каталога. **C** — вы решили, что `sell` не тронула и копию.

</details>

```console
$ ./_video/run.sh 08-range go run .
99 100
```

Если нужен адрес элемента, идите по индексу: `&products[i]`. Тест в задании ловит именно эту ошибку.

Ещё одна предосторожность (её нет в видео, она из README папки курса): указатель, который вернула `findProduct`, указывает на
массив слайса каталога. Если потом `append` создаст новый массив (GB-2.01), старый указатель изменит старый массив, а каталог не изменится.
Программы нет в папке курса, я запускал её сам:

```go
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
	}
	p := &catalog[0]
	catalog = append(catalog, Product{ID: 2, Name: "non", Price: 400_000, Stock: 100})
	p.Stock = 0
	fmt.Println(p.Stock, catalog[0].Stock)
}
```

```console
$ go run .

```

Ёмкость `catalog` была 1, `append` создал новый массив, а `p` остался на старом: `p.Stock = 0` записалось в старый элемент.
Правило: не храните указатель, а после изменения каталога находите товар заново.

## Частые ошибки

**1. «Функция изменила аргумент, значит, в `main` он тоже изменится».** Самая распространённая ошибка: `sell(p Product, …)` меняет свою копию,
значение в `main` не меняется, а компилятор молчит. Это ровно то, что показано в начале урока: `sell ichida: 37` / `main'da: 40` (раздел
«Проблема»). Исправление: сделайте тип параметра `*Product` и вызывайте `sell(&olma, 3)`.

**2. Путаница между `Product` и `*Product`.** `sell(olma, 3)` — `Product` там, где ждут `*Product`:
`cannot use olma (variable of struct type Product) as *Product value in argument to sell` (раздел «Передача указателя в функцию»).
Исправление: `&olma`.

**3. Указатель без проверки на `nil`.** Если сразу после `findProduct` прочитать `p.Stock`, а ID не найден:
`panic: runtime error: invalid memory address or nil pointer dereference` (раздел про nil-указатель). Исправление: `if p == nil { … return }`.

**4. `for _, p := range` и `&p`.** `p` — копия элемента, `&p` — адрес копии: `sell` не меняет каталог и не выдаёт ошибку
(`99 100`, раздел «Глубже»). Исправление: `&products[i]`.

**5. Сравнение `nil` с `0`.** Начинающие проверяют «пустоту» указателя через `0`. Программы нет в папке курса, я её запускал:

```go
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	var p *Product
	if p == 0 {
		fmt.Println("topilmadi")
	}
}
```

```console
$ go run .
# github.com/abdurahmon27/bozor
./main.go:15:10: invalid operation: p == 0 (mismatched types *Product and untyped int)
```

`./main.go:15:10` — строка 15, столбец 10 (цифра `0`). Сообщение: «операция `p == 0` недопустима: типы не совпадают — `*Product` и целое число без
определённого типа (`untyped int`)». `nil` — это не `0`: указатель сравнивайте только с `nil`, `if p == nil`.

## Проверьте себя

**1.** Чему равна переменная `p`, объявленная как `var p *Product` без значения?

<details>
<summary>Ответ</summary>

`nil`: нулевое значение указателя, он никуда не указывает. В программе `manzil` выше `var z *Product` и `z == nil` это показали (`true`).

</details>

**2.** У функции `f` параметр `p Product`, и она присваивает `p.Stock` значение 0. Изменится ли `olma` у вызывающего кода?

<details>
<summary>Ответ</summary>

Нет: параметр получает копию `olma` и исчезает вместе с ней. Чтобы изменить, тип параметра должен быть `*Product`, а вызов — `f(&olma)`.

</details>

**3.** (GB-2.01) После `t := s` выполнено `t[0] = 9`. Изменится ли `s[0]`?

<details>
<summary>Ответ</summary>

Да. `t := s` копирует заголовок слайса, но указатель внутри заголовка ведёт на тот же массив: оба слайса видят один массив. Это то же
правило, что и с указателем: копия есть, но копируется адрес.

</details>

**4.** Что напечатает эта программа? (Её нет в папке курса, я её запускал.)

```go
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func main() {
	a := Product{Name: "olma", Stock: 10}
	b := &a
	c := *b
	c.Stock = 5
	fmt.Println(a.Stock, b.Stock, c.Stock)
}
```

**A)** `5 5 5` · **B)** `10 10 5` · **C)** `10 5 5`

<details>
<summary>Ответ</summary>

**B: `10 10 5`.** `b := &a` — `b` указывает на `a`. `c := *b` копирует значение, на которое указывает `b`: `c` — отдельный `Product`.
`c.Stock = 5` затрагивает только `c`. Если вы выбрали **A**, вы решили, что `c := *b` тоже берёт адрес: звёздочка ведёт к значению, а `:=`
его копирует. **C** — вы решили, что `b.Stock` — значение копии.

```console
$ go run .

```

</details>

```go filename="solution/main.go" showLineNumbers
package main

import "fmt"

// Product — katalogdagi bitta mahsulot.
type Product struct {
	ID    int64
	Name  string
	Price int64 // tiyin
	Stock int
}

func sell(p *Product, quantity int) {
	p.Stock -= quantity
}

// findProduct katalogdan ID boʻyicha mahsulotni topadi: topilsa elementning manzili, topilmasa nil.
func findProduct(products []Product, id int64) *Product {
	for i := range products {
		if products[i].ID == id {
			return &products[i]
		}
	}
	return nil
}

func main() {
	catalog := []Product{
		{ID: 1, Name: "olma", Price: 1_200_000, Stock: 40},
		{ID: 2, Name: "non", Price: 400_000, Stock: 100},
	}
	p := findProduct(catalog, 9)
	if p == nil {
		fmt.Println("mahsulot topilmadi: 9")
		return
	}
	sell(p, 1)
	fmt.Println(p.Stock)
}

// sellByID katalogdagi id raqamli mahsulotdan quantity dona sotadi va xatoni qaytaradi.
func sellByID(products []Product, id int64, quantity int) error {
	p := findProduct(products, id)
	if p == nil {
		return fmt.Errorf("mahsulot topilmadi: %d", id)
	}
	if quantity <= 0 {
		return fmt.Errorf("miqdor musbat boʻlishi kerak, keldi %d", quantity)
	}
	if quantity > p.Stock {
		return fmt.Errorf("%s: qoldiq %d, soʻralgan %d", p.Name, p.Stock, quantity)
	}
	sell(p, quantity)
	return nil
}

// cheapest katalogdagi eng arzon mahsulotning manzilini qaytaradi; katalog boʻsh boʻlsa nil.
func cheapest(products []Product) *Product {
	var best *Product
	for i := range products {
		if best == nil || products[i].Price < best.Price {
			best = &products[i]
		}
	}
	return best
}
```

- `sellByID`: сначала `p := findProduct(products, id)` — адрес элемента каталога. Если `p == nil`, вместо panic возвращается ошибка.
  Затем два условия: `quantity <= 0` и `quantity > p.Stock`. `sell(p, quantity)` вызывается только **после** всех проверок, поэтому
  при ошибке остаток не меняется.
- `cheapest`: `var best *Product` — нулевое значение `nil`. Цикл идёт по индексу (`for i := range products`). В условии `best == nil || products[i].Price < best.Price` знак `||` — «или»: если левая часть истинна, правая не вычисляется
  ([Go spec: Logical operators](https://go.dev/ref/spec#Logical_operators)), поэтому, пока `best` ещё `nil`, `best.Price` не вызывает
  panic. При совпадении `best = &products[i]`: адрес элемента каталога, а не копии из `range`.
