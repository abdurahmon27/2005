`docker compose exec -T db` buyruqni `db` konteynerida bajaradi; `-T` terminal ajratmaydi.

Yangi volume'da hali jadval yoʻq:

```console
$ docker compose exec -T db psql -c '\dt'

```

`Did not find any tables` — «jadval topilmadi».
Dastlab faqat turlar berilgan video faylini ishlatamiz; asosiy `products.sql` esa dars oxiridagi qoidali jadvaldir.

```sql filename="_video/01-oddiy/products.sql" showLineNumbers
CREATE TABLE products (
    id     bigint
           GENERATED ALWAYS AS IDENTITY
           PRIMARY KEY,
    name   text,
    price  bigint,
    stock  integer,
    active boolean
);
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `CREATE TABLE products (` | `products` jadvalini yaratadi; qavs ichida vergul bilan ajratilgan ustunlar |
| 2 | `id bigint` | `id` — 8 baytli butun son |
| 3 | `GENERATED ALWAYS AS IDENTITY` | yangi qatorning `id` qiymatini baza oʻzi beradi |
| 4 | `PRIMARY KEY,` | asosiy kalit: qatorni yagona aniqlaydi, takrorlanmaydi va `NULL` boʻlmaydi |
| 5 | `name text,` | mahsulot nomi, matn |
| 6 | `price bigint,` | narx tiyinda; 8 bayt, Go'dagi `int64` oʻlchamida |
| 7 | `stock integer,` | qoldiq, 4 baytli butun son |
| 8 | `active boolean` | faol holati: `true` yoki `false` qiymati |
| 9 | `);` | ustunlar roʻyxatini va SQL buyrugʻini tugatadi |

`NULL` qiymat yoʻqligini bildiradi; batafsil [GB-5.04](/lab/youtube/gb#gb-5-04) da.

## INSERT: toʻrt mahsulot yozish

Bir mahsulotning qiymatlarini ustunlarga moslab yozamiz. **`INSERT INTO`** qaysi jadvalga va qaysi ustunlarga yozishni belgilaydi.
`id`ni bermaymiz: uni baza hisoblaydi. Kursdagi `seed.sql` toʻliq:

```sql filename="seed.sql" showLineNumbers
INSERT INTO products (name, price, stock, active)
VALUES ('olma', 1200000, 40, true),
       ('non', 400000, 3, true),
       ('choy', 2500000, 8, true),
       ('oʻrik', 3500000, 2, true);
```

1-qator ustunlar tartibini beradi. 2-qator `VALUES` bilan boshlanadi; har qavs — shu tartibdagi bitta qator.
3–5-qatorlar qolgan mahsulotlar; vergul qatorlarni ajratadi, oxirgi `;` buyruqni tugatadi.
`'olma'` bitta tirnoqdagi matn, sonlar tiyinda, `true` — faol mahsulot.

Fayl bajarilgach nechta qator yoziladi?

**A)** `1` · **B)** `4` · **C)** `5`, chunki beshta ustun bor

<details>
<summary>Javob</summary>

**B.** `VALUES`dan keyin toʻrtta qavs guruhi bor. Bitta buyruq bir nechta qator yozadi; ustunlar soni qatorlar soni emas.

</details>

```console
$ docker compose exec -T db psql -f /lab/seed.sql
INSERT 0 4
```

`INSERT 0 4` ichidagi `4` — qoʻshilgan qatorlar soni. Birinchi `0` tarixiy maydon, hozir doim nol.
**`SELECT`** qatorlarni oʻqiydi; `*` — barcha ustunlar, `FROM products` — manba jadval.
Qaysi `id`lar beriladi: **A)** hammasi `0` · **B)** `1, 2, 3, 4` · **C)** `id` boʻlmaydi?

<details>
<summary>Javob</summary>

**B.** Yangi jadvalning identity hisoblagichi har qatorga navbatdagi raqamni berdi. `id`ni `INSERT`da tashlab ketish ustunni yoʻqotmaydi.

</details>

```console
$ docker compose exec -T db psql -c 'SELECT * FROM products'
 id | name  |  price  | stock | active 
----+-------+---------+-------+--------
  1 | olma  | 1200000 |    40 | t
  2 | non   |  400000 |     3 | t
  3 | choy  | 2500000 |     8 | t
  4 | oʻrik | 3500000 |     2 | t
(4 rows)
```

Birinchi satr — ustun nomlari, chiziqlar — jadval chegarasi; `(4 rows)` — toʻrtta qator.
`active`dagi `t` — `true`. Holat: nol qator → toʻrtta mahsulot.
Bu chiqishdagi tartibni hozircha kafolat deb qabul qilmang: uni keyingi boʻlimda ochiq belgilaymiz.

## SELECT: filtrlash, saralash va cheklash

Butun jadval oʻrniga nom va narx kerak. `SELECT name, price` faqat shu ikki ustunni qaytaradi.
`WHERE stock < 5` faqat qoldigʻi beshtadan kam qatorlarni qoldiradi; `<` — qatʼiy kichik.

**A)** olma, choy · **B)** non, oʻrik · **C)** barcha mahsulotlar?

<details>
<summary>Javob</summary>

**B.** non qoldigʻi `3`, oʻrikniki `2`; olma `40`, choy `8` bilan shartdan oʻtmaydi.

</details>

```console
$ docker compose exec -T db psql -c 'SELECT name, price FROM products WHERE stock < 5'
 name  |  price  
-------+---------
 non   |  400000
 oʻrik | 3500000
(2 rows)
```

`AND` ikkala shart ham rost boʻlishini talab qiladi. Endi `price > 1000000`ni qoʻshsak nima qoladi?
`>` — qatʼiy katta.

**A)** non · **B)** oʻrik · **C)** non va oʻrik

<details>
<summary>Javob</summary>

**B.** non narxi `400000`, shuning uchun yangi shartdan oʻtmaydi. oʻrik narxi `3500000`; ikkala shart ham rost.

</details>

```console
$ docker compose exec -T db psql -c 'SELECT name, price FROM products WHERE stock < 5 AND price > 1000000'
 name  |  price  
-------+---------
 oʻrik | 3500000
(1 row)
```

`ORDER BY price DESC` narx kamayish tartibini belgilaydi; `DESC`siz oʻsish tartibi ishlatiladi.
`ORDER BY` boʻlmasa, Postgres qatorlar tartibini kafolatlamaydi.

```sql
SELECT name, price
FROM products
WHERE stock < 5
ORDER BY price DESC;
```

Qaysi qatorlar, qaysi tartibda keladi?

**A)** non, oʻrik · **B)** oʻrik, non · **C)** olma, choy

<details>
<summary>Javob</summary>

**B.** Filtr oʻzgarmadi: oʻrik va non qoldi. `DESC` avval `3500000`, keyin `400000`ni beradi.
A oʻsish tartibi; C filtrni eʼtiborsiz qoldirgan.

</details>

```console
$ docker compose exec -T db psql -c 'SELECT name, price FROM products WHERE stock < 5 ORDER BY price DESC'
 name  |  price  
-------+---------
 oʻrik | 3500000
 non   |  400000
(2 rows)
```

`LIMIT 2` natijada eng koʻpi ikki qator boʻlishini bildiradi.
Bu safar `WHERE` yoʻq: barcha mahsulotlar ichidan eng qimmat ikkitasi qaysi?

**A)** oʻrik, choy · **B)** olma, non · **C)** oʻrik, non

<details>
<summary>Javob</summary>

**A.** Narxlar kamayish tartibida: `3500000`, `2500000`, `1200000`, `400000`.
`LIMIT` saralangan natijaning boshidagi ikki qatorni oladi; C eski filtrni saqlab qolgan.

</details>

```console
$ docker compose exec -T db psql -c 'SELECT name, price FROM products ORDER BY price DESC LIMIT 2'
 name  |  price  
-------+---------
 oʻrik | 3500000
 choy  | 2500000
(2 rows)
```

| Bosqich | Qatorlar yoki natija |
|---|---|
| `FROM products` | toʻrtta mahsulot |
| `WHERE stock < 5` | non va oʻrik |
| `ORDER BY price DESC` | oʻrik, non |
| `SELECT name, price` | har qatorda faqat nom va narx |

Bu jadval natijani tushuntiradi; SQL matnida `SELECT` birinchi yoziladi.
Narxlar teng boʻlsa, barqaror tartib uchun ikkinchi kalit qoʻshing: `ORDER BY price, id`.

## Tirnoq: matn yoki ustun nomi

SQL matni bitta tirnoqda yoziladi: `'olma'`. Qoʻsh tirnoq esa nom uchun: `"olma"` — ustun nomi.
Tashqi shell tirnoqlari SQL matnini bitta argument sifatida uzatadi; ular SQL tirnoqlaridan alohida.

```sql
SELECT name FROM products WHERE name = "olma";
```

Bu xato soʻrov nima qiladi? `=` SQL'da tenglikni tekshiradi.

**A)** olmani topadi · **B)** `olma` ustunini qidirib, xato beradi · **C)** barcha qatorlarni qaytaradi

<details>
<summary>Javob</summary>

**B.** Jadvalda `name` ustuni bor, `olma` ustuni yoʻq. A javobi matn bilan ustun nomini aralashtirgan.

</details>

```console
$ docker compose exec -T db psql -c 'SELECT name FROM products WHERE name = "olma"'
ERROR:  column "olma" does not exist
LINE 1: SELECT name FROM products WHERE name = "olma"
                                               ^
```

`column … does not exist` — «bunday ustun yoʻq». `LINE 1` soʻrov qatorini, `^` xato joyini koʻrsatadi.
Tuzatish: SQL ichida `'olma'`; shell tashqarisida esa qoʻsh tirnoq.
Endi bitta olma qatori qaytadi:

```console
$ docker compose exec -T db psql -c "SELECT name FROM products WHERE name = 'olma'"
 name 
------
 olma
(1 row)
```

## RETURNING: yangi id va yetishmayotgan qoida

Yangi mahsulotga baza qaysi `id`ni berganini darhol bilish kerak.
**`RETURNING id`** qoʻshilgan qatordan `id`ni qaytaradi. Buni Go'dan ishlatish GB-5.05 da keladi.
`sut` qoʻshsak qanday `id` chiqadi: **A)** `4` · **B)** `5` · **C)** hech narsa?

<details>
<summary>Javob</summary>

**B.** Oldingi toʻrtta qator `1`–`4`ni olgan. `RETURNING` yozishni bekor qilmaydi: pastdagi `INSERT 0 1` ham qoʻshilgan qatorni bildiradi.

</details>

```console
$ docker compose exec -T db psql -c "INSERT INTO products (name, price) VALUES ('sut', 900000) RETURNING id"
 id 
----
  5
(1 row)

INSERT 0 1
```

Ammo tur biznes qoidasini tekshirmaydi. `''` — uzunligi nol boʻlgan matn; `-5` ham `bigint` qiymati.
`RETURNING *` yangi qatorning barcha ustunlarini qaytaradi. Natija nima boʻladi?

**A)** baza rad etadi · **B)** qator yoziladi · **C)** manfiy narx `0`ga almashtiriladi

<details>
<summary>Javob</summary>

**B.** Hozir `name` va `price` uchun faqat turlar bor. Ular boʻsh matnni yoki manfiy sonni taqiqlamaydi; avtomatik tuzatish ham yoʻq.

</details>

```console
$ docker compose exec -T db psql -c "INSERT INTO products (name, price) VALUES ('', -5) RETURNING *"
 id | name | price | stock | active 
----+------+-------+-------+--------
  6 |      |    -5 |       | 
(1 row)

INSERT 0 1
```

`stock` va `active` kataklaridagi boʻsh joy bu yerda `NULL`: qiymat berilmagan va `DEFAULT` ham yoʻq.
`name` esa `NULL` emas, `''`. Oddiy `psql` chiqishi ikkalasini ham boʻsh koʻrsatishi mumkin.
Holat: beshta toʻgʻri qator → oltita qator, bittasi biznes qoidasiga zid.

## Constraint: bazaning oʻzi rad etadi

Qaysi dastur yozishidan qatʼi nazar, narx musbat boʻlishi kerak.
**Constraint** shu talabni jadvalda saqlaydi. Endi asosiy `products.sql`ni ishlatamiz:

```sql filename="products.sql" showLineNumbers
DROP TABLE IF EXISTS products;
CREATE TABLE products (
    id     bigint
           GENERATED ALWAYS AS IDENTITY
           PRIMARY KEY,
    name   text    NOT NULL UNIQUE,
    price  bigint  NOT NULL CHECK (price > 0),
    stock  integer NOT NULL DEFAULT 0 CHECK (stock >= 0),
    active boolean NOT NULL DEFAULT true
);
```

| Qator | Yangi qoida | Natija |
|---|---|---|
| 1 | `DROP TABLE IF EXISTS products` | jadval bor boʻlsa, barcha qatorlari bilan oʻchiradi |
| 2–5 | `CREATE TABLE`, identity, `PRIMARY KEY` | avvalgidek yangi jadval va asosiy kalit |
| 6 | `NOT NULL UNIQUE` | nom `NULL` boʻlmaydi va takrorlanmaydi |
| 7 | `NOT NULL CHECK (price > 0)` | narx berilishi va noldan katta boʻlishi kerak |
| 8 | `NOT NULL DEFAULT 0 CHECK (stock >= 0)` | qoldiq yozilmasa `0`; manfiy qiymat rad etiladi |
| 9 | `NOT NULL DEFAULT true` | faol holati yozilmasa `true`; ochiq `NULL` rad etiladi |
| 10 | `);` | jadval taʼrifini tugatadi |

`>=` — katta yoki teng. `DEFAULT` ustun tashlab ketilganda qoʻyiladigan qiymat; u ochiq yozilgan `NULL`ni almashtirmaydi.
`CHECK (shart)` shart yolgʻon boʻlsa qatorni rad etadi; natija `NULL` boʻlsa oʻtkazadi.
Shuning uchun qiymat majburiy boʻlsa, `NOT NULL` ham kerak. `id`ga bu talabni `PRIMARY KEY` beradi.

| Yozish yoʻli | Nima tekshiriladi | Qoida buzilsa |
|---|---|---|
| qiymat turi | `bigint`, `text`, `integer`, `boolean`ga moslik | xato |
| `NOT NULL` | qiymat yoʻqligi | xato |
| `CHECK` | shart yolgʻon chiqishi | xato |
| `UNIQUE` | oldingi qator bilan takrorlanish | xato |
| saqlash | barcha talablar oʻtdi | yangi qator |

Bu PostgreSQL 18.7 dagi kuzatilgan yoʻl; tekshiruvlar tartibi dastur tayanadigan kafolat emas.
Xato boʻlsa, yaroqsiz qatorning yarmi saqlanmaydi; birinchi xabardan barcha muammolar roʻyxatini kutmang.

Jadvalni qayta yaratish eski olti qatorni oʻchiradi. Keyin toʻrt mahsulotni qayta yuklaymiz:

```console
$ docker compose exec -T db psql -f /lab/products.sql
DROP TABLE
CREATE TABLE
```

```console
$ docker compose exec -T db psql -f /lab/seed.sql
INSERT 0 4
```

Jadvalni oʻchirmasdan oʻzgartirish [GB-5.06](/lab/youtube/gb#gb-5-06) da keladi.
Endi `('', -5)` qatori nima beradi?

**A)** boʻsh nom uchun `NOT NULL` xatosi · **B)** narx uchun `CHECK` xatosi · **C)** ikkala xato

<details>
<summary>Javob</summary>

**B.** `''` qiymat borligini bildiradi, shuning uchun `NOT NULL`dan oʻtadi. Narx `-5` esa `price > 0`ga zid.
C javobi bitta xato xabari barcha buzilgan qoidalarni sanaydi deb oʻylagan.

</details>

```console
$ docker compose exec -T db psql -c "INSERT INTO products (name, price) VALUES ('', -5)"
ERROR:  new row for relation "products" violates check constraint "products_price_check"
DETAIL:  Failing row contains (5, , -5, 0, t).
```

`new row for relation … violates check constraint` — «jadvalning yangi qatori CHECK qoidasini buzdi».
`relation` bu yerda jadval; `products_price_check` — qoida nomi.
`DETAIL` rad etilgan qatorni koʻrsatadi: `id=5`, nom boʻsh matn, narx `-5`, qoldiq `0`, faol holati `t`.
Oxirgi ikki qiymatni `DEFAULT` berdi. Jadvalda hali ham toʻrtta qator bor.

Boʻsh matnni ham toʻsish uchun 6-qatorga quyidagini qoʻshish kerak; buni uy vazifasida bajarasiz:

```sql
name   text    NOT NULL UNIQUE CHECK (name <> ''),
```

`<>` — teng emas. `''` yonma-yon ikkita bitta tirnoq: boʻsh matn.
Bu qoida boʻsh joylardan iborat nomni tekshirmaydi; bugungi vazifa aynan boʻsh matn haqida.

Oraliq savol: jadvalda `choy` bor. Boshqa narxli ikkinchi `choy` yozilsa nima boʻladi?

**A)** ikkinchi qator qoʻshiladi · **B)** eski narx yangilanadi · **C)** `UNIQUE` xatosi

<details>
<summary>Javob</summary>

**C.** Qoida nomga qoʻyilgan, narxga emas. `INSERT` yangi qator qoʻshishga urinadi, mavjud qator narxini yangilamaydi.

</details>

```console
$ docker compose exec -T db psql -c "INSERT INTO products (name, price) VALUES ('choy', 2600000)"
ERROR:  duplicate key value violates unique constraint "products_name_key"
DETAIL:  Key (name)=(choy) already exists.
```

`duplicate key value` — «kalit qiymati takrorlandi»; `already exists` — «allaqachon bor».
`products_name_key` nom uchun yagonalik qoidasidir. Qator qoʻshilmadi.

Ochiq `NULL` nom qanday tekshiriladi?

**A)** `NOT NULL` rad etadi · **B)** `DEFAULT` nom yaratadi · **C)** boʻsh matn bilan bir xil

<details>
<summary>Javob</summary>

**A.** `NULL` qiymat yoʻqligi; `''` esa mavjud matn. `name` uchun `DEFAULT` ham yozilmagan.
`CHECK` yolgʻiz oʻzi `NULL`ni rad etishga yetmaydi.

</details>

```console
$ docker compose exec -T db psql -c "INSERT INTO products (name, price) VALUES (NULL, 900000)"
ERROR:  null value in column "name" of relation "products" violates not-null constraint
DETAIL:  Failing row contains (7, null, 900000, 0, t).
```

`null value in column "name" … violates not-null constraint` — «name ustunidagi NULL NOT NULL qoidasini buzdi».
`DETAIL`dagi qator ham saqlanmadi. Jadvalda toʻrtta mahsulot qoldi.

## Chuqurroq (ixtiyoriy): id'lar orasidagi boʻshliq

Identity raqami qator tekshirilishidan oldin olinadi. Qator rad etilsa, olingan raqam qaytarilmaydi.
Uchta `INSERT` rad etildi. Endi `sut` yozilib, `id` soʻralsa nima chiqadi?

**A)** `5` · **B)** `8` · **C)** `4`

<details>
<summary>Javob</summary>

**B.** Bu urinishlar tekshiruvdan oldin identity hisoblagichidan `5`, `6`, `7`ni olgan.
Qator rad etilishi hisoblagichni orqaga qaytarmaydi. A javobi qatorlar sonini keyingi `id` bilan tenglashtirgan.

</details>

```console
$ docker compose exec -T db psql -c "INSERT INTO products (name, price) VALUES ('sut', 900000) RETURNING id"
 id 
----
  8
(1 row)

INSERT 0 1
```

| Amal | Olingan id | Jadvaldagi qatorlar |
|---|---|---|
| boshlangʻich mahsulotlar | `1`–`4` | `4` |
| notoʻgʻri narx | `5` | `4` |
| takror nom | `6` | `4` |
| `NULL` nom | `7` | `4` |
| sut | `8` | `5` |

`id` qatorni aniqlaydi; u mahsulotlar soni yoki uzluksiz tartib raqami emas.
Ketma-ket raqamlarga tayanmang. Bu xulq identity ishlatadigan sequence hisoblagichidan keladi.

## Koʻp uchraydigan xatolar

1. **«NOT NULL boʻsh nomni ham rad etadi».** `VALUES ('', -5)` tajribasida narxni `CHECK` rad etdi; nom `NOT NULL`dan oʻtdi.
   Tuzatish: `name`ga `CHECK (name <> '')` qoʻshing; `NULL` uchun `NOT NULL`ni ham qoldiring.
2. **Matnni qoʻsh tirnoqqa olish.** `WHERE name = "olma"` xatosi «Tirnoq» boʻlimida koʻrsatilgan.
   `column "olma" does not exist` baza ustun izlaganini bildiradi. Tuzatish: `WHERE name = 'olma'`.
3. **INSERT eski qatorni yangilaydi deb oʻylash.** Takror `choy` uchun `UNIQUE` xatosi chiqdi; oldingi narx oʻzgarmadi.
   `INSERT`ni faqat yangi qator qoʻshish uchun ishlating.
4. **Koʻringan tartibga tayanish.** `ORDER BY` yozilmasa, tartib kafolatsiz. Kerakli ustunni, tenglik boʻlsa `id`ni ham yozing.
5. **Qayta yaratishni maʼlumot saqlanadi deb bajarish.** `DROP TABLE` qatorlarni ham oʻchiradi.
   Bu laboratoriyada `seed.sql` qayta yozildi; mavjud maʼlumotli tizimni oʻzgartirish GB-5.06 mavzusi.

```sql
name   text    NOT NULL UNIQUE CHECK (name <> ''),
```

```sql filename="solution/arzon.sql" showLineNumbers
SELECT name, price
FROM products
WHERE active AND price < 3000000
ORDER BY price, id
LIMIT 2;
```
