## Что вы узнаете

Каталог bozor до сих пор был записан прямо в `main.go`: изменилась цена — программу надо пересобирать. Теперь каталог приходит из файла.
В каждой строке — ID, название, цена в сумах и остаток, через точку с запятой:

```console
$ cat katalog.txt
1;olma;12000;40
2;oʻrik;35000;5
3;non;4000;100
4;choy;25000;8
```

Как программа читает этот файл? И почему одна функция `loadCatalog` должна одинаково читать каталог и из файла, и из текста, набранного в терминале,
и из текста в тесте?

**Главная идея:** `io.Reader` — интерфейс с одним методом. Вызывающий код передаёт `Read` байтовый слайс `p`, который служит буфером; Reader записывает в него
не больше `len(p)` байт и возвращает в `n`, сколько записал; когда данные кончились — `io.EOF`. Открытый файл отдаёт байты **порциями (chunk)**
и не знает ни про строки, ни про границы символов. А `bufio.Scanner` поверх любого `io.Reader` копит байты в своём буфере, собирает из них
строки и через `Err()` сообщает, почему остановился. Поэтому одна функция, которая принимает `io.Reader`, а не имя файла,
работает и с файлом, и со стандартным вводом, и с текстом из теста.

К концу урока вы:

- откроете каталог через `os.Open` и `defer f.Close()` и прочитаете контракт `Read` в `go doc io.Reader`;
- сами вызовете `f.Read`, увидите, какими порциями файл отдаёт байты, и прочитаете файл построчно через `bufio.Scanner`;
- запустите одну функцию `loadCatalog(r io.Reader)` с файлом, через `cat katalog.txt | go run .` и через `strings.NewReader`;
- своими глазами увидите, как данные **молча** пропадают, если не проверить `sc.Err()`, и исправите это; в задании научите `loadCatalog`
  пропускать комментарии и называть строку с ошибкой — пока не пройдёт `go test`.

Три основных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| `io.Reader` | интерфейс с одним методом: `Read(p)` заполняет ваш буфер байтами, в конце возвращает `io.EOF` | io.Reader |
| `bufio.Scanner` | читалка, которая собирает строки из байтов, пришедших порциями из Reader | bufio.Scanner |
| приём Reader | функция получает `io.Reader`, а не имя файла: один код для файла, stdin и теста | accept an io.Reader |

Вспомогательные понятия объясняются одной фразой при первой встрече: **стандартный ввод** (stdin) и **вертикальная черта** (pipe), `strings.Split`,
**смещение** (offset) и **буфер**.

## `os.Open`: открываем файл

Чтобы добраться до байтов файла на диске, программа сначала должна его **открыть**. Исходный код — форма `run() error` и `main` из [GB-2.09](/lab/youtube/gb/gb-2-09/ru),
внутри только открытие файла (`_video/01-open/main.go`):

```go filename="_video/01-open/main.go" showLineNumbers
// Video, 01-open: katalog.txt'ni oʻqish uchun ochadi (hali hech narsa oʻqimaydi).
package main

import (
	"fmt"
	"os"
)

func run() error {
	f, err := os.Open("katalog.txt")
	if err != nil {
		return err
	}
	defer f.Close()
	// … f'dan oʻqiymiz
	return nil
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `// Video, 01-open: …` | комментарий: Go его не читает |
| 2 | `package main` | этот файл — исполняемая программа (GB-1.01) |
| 4–7 | `import ( "fmt"  "os" )` | `fmt` — вывод, `os` — работа с операционной системой: в этом пакете есть `Open` |
| 9 | `func run() error {` | `run` — функция, которая делает работу; результат — `error` (GB-2.09) |
| 10 | `f, err := os.Open("katalog.txt")` | открывает `katalog.txt` **только для чтения**; возвращает два значения: `f` (тип `*os.File`, открытый файл) и `err` |
| 11–13 | `if err != nil { return err }` | если файл не открылся, возвращаем ошибку тому, кто вызвал `run` (GB-1.07) |
| 14 | `defer f.Close()` | закроет файл, когда `run` завершится; пишется сразу после проверки (GB-2.09) |
| 15 | `// … f'dan oʻqiymiz` | заглушка («читаем из `f`»): в следующих разделах сюда добавим код |
| 16 | `return nil` | ошибки нет |
| 19–24 | `func main() { … }` | если `run` вернул ошибку, `main` пишет её в stderr и завершает программу через `os.Exit(1)` (GB-2.09) |

Два замечания.

- `os.Open` открывает файл **только для чтения**. Отличие от `os.Create` ([GB-2.07](/lab/youtube/gb/gb-2-07/ru)): он не создаёт файл и не очищает его.
  Если файла нет, возвращает ошибку (посмотрим в разделе об ошибках).
- В записанном файле ошибка `Close` могла потерять данные, поэтому в GB-2.09 мы писали `return f.Close()`. У прочитанного файла терять нечего,
  так что простого `defer f.Close()` достаточно ([close(2)](https://man7.org/linux/man-pages/man2/close.2.html):
  отложенные ошибки относятся к записанным данным).

Пока программа только открывает и закрывает файл:

```console
$ ./_video/run.sh 01-open go run .
```

Ничего не вывелось: ошибки нет, вывода тоже.

## `io.Reader`: один метод

Чтобы прочитать файл, нужен метод `f`. Какой это метод и что он гарантирует? Это показывает `go doc` ([GB-2.07](/lab/youtube/gb/gb-2-07/ru)). Посмотрим начало документации
(вся она длинная, `head -n 5` берёт только первые пять строк):

```console
$ go doc io.Reader | head -n 5
package io // import "io"

type Reader interface {
	Read(p []byte) (n int, err error)
}
```

Это интерфейс с одним методом, как `Writer` в [GB-2.07](/lab/youtube/gb/gb-2-07/ru). Его части:

| Часть | Что это |
|---|---|
| `Read` | имя метода |
| `p []byte` | **буфер**, который передаёт вызывающий код: место для байтов (`[]byte` — слайс байтов) |
| `n int` | сколько байтов записал `Read` |
| `err error` | ошибка или признак, что данные кончились |

Правило из документации: `Read` записывает в `p` **не больше `len(p)` байт** и возвращает в `n`, сколько именно. Всегда `0 <= n <= len(p)`.

Открытый файл выполняет этот интерфейс без объявления ([GB-2.07](/lab/youtube/gb/gb-2-07/ru)). `Read` у `*os.File`:

```console
$ go doc os.File.Read
package os // import "os"

func (f *File) Read(b []byte) (n int, err error)
    Read reads up to len(b) bytes from the File and stores them in b. It
    returns the number of bytes read and any error encountered. At end of file,
    Read returns 0, io.EOF.
```

Сигнатура та же: `Read(b []byte) (n int, err error)` (имя параметра `b` — неважно). Из документации: «читает до `len(b)` байт, возвращает их число и ошибку. **В конце файла**
возвращает `0, io.EOF`». **EOF** — *end of file*, то есть конец файла. `io.EOF` — **sentinel-ошибка** (как `ErrNotFound` из
[GB-2.08](/lab/youtube/gb/gb-2-08/ru)): создана в пакете один раз, и вызывающий код сравнивает с ней. Её собственная документация:

```console
$ go doc io.EOF
package io // import "io"

var EOF = errors.New("EOF")
    EOF is the error returned by Read when no more input is available. (Read
    must return EOF itself, not an error wrapping EOF, because callers will test
    for EOF using ==.) Functions should return EOF only to signal a graceful
    end of input. If the EOF occurs unexpectedly in a structured data stream,
    the appropriate error is either ErrUnexpectedEOF or some other error giving
    more detail.
```

Обратите внимание: «Read обязан возвращать EOF **без обёртки**, потому что вызывающий код проверяет его через `==`». Поэтому в коде дальше будет
`==`, а не `errors.Is`.

## Вызываем `Read` сами

Проверим контракт: буфер нарочно маленький — 20 байт. Программа (`_video/02-read/main.go`):

```go filename="_video/02-read/main.go" showLineNumbers
// Video, 02-read: f.Read'ni oʻzimiz chaqiramiz — 20 baytlik buferga boʻlak-boʻlak.
package main

import (
	"fmt"
	"io"
	"os"
)

func run() error {
	f, err := os.Open("katalog.txt")
	if err != nil {
		return err
	}
	defer f.Close()
	buf := make([]byte, 20)
	for {
		n, err := f.Read(buf)
		fmt.Printf("%d %q\n", n, buf[:n])
		if err == io.EOF {
			break // fayl tugadi
		}
		if err != nil {
			return err
		}
	}
	return nil
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}
```

Новые строки:

| Строка | Код | Что делает |
|---|---|---|
| 6 | `"io"` | пакет `io` — ради `io.EOF` |
| 16 | `buf := make([]byte, 20)` | буфер на 20 байт: создан через `make`, заполнен нулями (GB-2.01) |
| 17 | `for {` | цикл без условия: крутится, пока не будет `break` или `return` (GB-1.06) |
| 18 | `n, err := f.Read(buf)` | заполняет `buf` байтами файла; `n` — сколько байтов, `err` — ошибка или `io.EOF` |
| 19 | `fmt.Printf("%d %q\n", n, buf[:n])` | печатает `n` и **только записанные** байты: `buf[:n]` — первые `n` элементов `buf` (GB-2.01). `%q` — в кавычках, а `\n` и подобные символы записываются escape-ами (GB-1.04) |
| 20–22 | `if err == io.EOF { break }` | если файл кончился, выходим из цикла. `==`, потому что `Read` не оборачивает `io.EOF` |
| 23–25 | `if err != nil { return err }` | любую другую ошибку возвращаем |

Строка 19 стоит **раньше** строки 20: правило документации — *сначала n байтов, потом err*. `Read` может вернуть байты вместе с ошибкой,
и эти байты нельзя терять.

Файл — 63 байта, буфер — 20 байт. Что вернёт `Read`?

**A)** каждый `Read` — одна строка · **B)** `20, 20, 20, 3`, а `EOF` приходит вместе с последним `Read` · **C)** `20, 20, 20, 3`, потом отдельный `0` байт и `EOF`

<details>
<summary>Ответ</summary>

**C.** В файле 63 байта: 20 + 20 + 20 + 3. Четвёртый `Read` возвращает последние 3 байта без ошибки, а пятый вызов — `0` и `io.EOF`.
Если вы выбрали **A**, вы решили, что `Read` знает про строки: он знает только байты. **B** — так могут вести себя другие Reader-ы
(документация это разрешает), но `*os.File` отдаёт последние байты без ошибки, а `EOF` — при следующем вызове.

</details>

```console
$ ./_video/run.sh 02-read go run .
20 "1;olma;12000;40\n2;o\xca"
20 "\xbbrik;35000;5\n3;non;4"
20 "000;100\n4;choy;25000"
3 ";8\n"
0 ""
```

Разберём вывод по шагам. Открытый файл помнит, где остановилось чтение: это **смещение** (offset), то есть сколько байтов от начала файла уже пройдено. Каждый `Read`
просит у операционной системы до `len(buf)` байт начиная с этого места и сдвигает смещение вперёд ([read(2)](https://man7.org/linux/man-pages/man2/read.2.html)):

| `Read` | Байты файла (смещение) | `n` | `err` | Напечатанная строка |
|---|---|---|---|---|
| 1 | 0–19 | 20 | `nil` | `20 "1;olma;12000;40\n2;o\xca"` |
| 2 | 20–39 | 20 | `nil` | `20 "\xbbrik;35000;5\n3;non;4"` |
| 3 | 40–59 | 20 | `nil` | `20 "000;100\n4;choy;25000"` |
| 4 | 60–62 | 3 | `nil` | `3 ";8\n"` |
| 5 | — (смещение 63: файл закончился) | 0 | `io.EOF` | `0 ""` |

Два вывода:

- **`Read` не знает про строки.** Первая порция закончилась посреди второй строки (`2;o`), остальное — в следующей порции.
- **`Read` не знает и про символы.** `ʻ` в `oʻrik` — два байта (`ca bb`, [GB-2.10](/lab/youtube/gb/gb-2-10/ru)). Первая порция закончилась на его первом байте (`\xca`),
  а второй байт (`\xbb`) стоит в начале следующей порции: `%q` показывает недопустимый байт как `\x..`.

Собирать строки и символы из порций должен другой код.

## `bufio.Scanner`: строки из порций

Это делает пакет `bufio` из стандартной библиотеки (*buffered I/O*, то есть ввод-вывод с буфером). `bufio.NewScanner` принимает любой `io.Reader`,
копит байты в своём буфере через `Read` и собирает из них строки. Программа (`_video/03-scan/main.go`):

```go filename="_video/03-scan/main.go" showLineNumbers
// Video, 03-scan: bufio.Scanner fayldan qatorlarni beradi.
package main

import (
	"bufio"
	"fmt"
	"os"
)

func run() error {
	f, err := os.Open("katalog.txt")
	if err != nil {
		return err
	}
	defer f.Close()
	sc := bufio.NewScanner(f)
	for sc.Scan() {
		fmt.Printf("%q\n", sc.Text())
	}
	if err := sc.Err(); err != nil {
		return err
	}
	return nil
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `"bufio"` | пакет `bufio` |
| 16 | `sc := bufio.NewScanner(f)` | создаёт Scanner, который читает из `f`; `f` — это `io.Reader`. `f.Read` Scanner вызывает сам |
| 17 | `for sc.Scan() {` | `Scan` возвращает `true`, если нашёл следующую строку, и `false`, если данные кончились или произошла ошибка. Это условие `for` ([GB-1.06](/lab/youtube/gb/gb-1-06/ru)) |
| 18 | `fmt.Printf("%q\n", sc.Text())` | `sc.Text()` отдаёт найденную строку как `string` |
| 20–22 | `if err := sc.Err(); err != nil { return err }` | после цикла: почему `Scan` остановился? Если `sc.Err()` вернул ошибку — возвращаем её. Короткий `if` — форма из [GB-1.05](/lab/youtube/gb/gb-1-05/ru) |

Теперь, глядя на прошлый вывод, подумайте: как вторая строка файла, `oʻrik`, выглядит в `sc.Text()`?

**A)** `"2;o\xca"` — разорванная, как в порции `Read` · **B)** `"2;oʻrik;35000;5"` — целая · **C)** ошибка: UTF-8 нарушен

<details>
<summary>Ответ</summary>

**B.** Scanner копит байты в своём буфере и ждёт конца строки, а потом отдаёт строку целиком. Границы порций `Read` ему не видны.
Если вы выбрали **A**, вы решили, что Scanner отдаёт порцию `Read`; **C** — разорванный символ никогда не доходит до `Text`,
потому что оба байта `ʻ` лежат в строке рядом.

</details>

```console
$ ./_video/run.sh 03-scan go run .
"1;olma;12000;40"
"2;oʻrik;35000;5"
"3;non;4000;100"
"4;choy;25000;8"
```

Четыре строки, `oʻrik` целиком. Конечный `\n` отброшен (как и `\r\n` в файлах Windows). Даже если файл не заканчивается на `\n`, последняя строка
всё равно возвращается. После цикла `sc.Err()` равен `nil`: **конец файла — не ошибка**, поэтому `io.EOF` не появился.

Вот что происходит внутри Scanner (каждая строка — один `Scan`):

| `Scan` | Что делает Scanner | Результат | `sc.Text()` |
|---|---|---|---|
| 1 | буфер пуст: вызывает `f.Read` (приходит 63 байта), ищет первый `\n` | `true` | `"1;olma;12000;40"` |
| 2 | до следующего `\n` в том, что осталось в буфере | `true` | `"2;oʻrik;35000;5"` |
| 3 | так же | `true` | `"3;non;4000;100"` |
| 4 | так же | `true` | `"4;choy;25000;8"` |
| 5 | буфер пуст: `f.Read` — `0` байт и `io.EOF`; EOF не ошибка | `false` | — (`sc.Err()` = `nil`) |

У одной строки есть предел: буфер Scanner при необходимости растёт, но одна строка не должна превышать примерно **64 KiB** (65 536 байт; 1 KiB = 1024 байта).
В документации это `bufio.MaxScanTokenSize = 64 * 1024` ([pkg.go.dev](https://pkg.go.dev/bufio#pkg-constants)). С этим пределом мы встретимся в разделе об ошибках.

## `parseLine`: из строки в `Product`

Строка пока остаётся обычной `string`. В `Product` её превращает `parseLine`. В видео её тело показано кратко, полный код — в `main.go`:

```go
func parseLine(line string) (Product, error) {
	parts := strings.Split(line, ";")
	if len(parts) != 4 {
		return Product{}, fmt.Errorf("4 ta maydon kerak, bor %d", len(parts))
	}
	id, err := strconv.ParseInt(parts[0], 10, 64)
	if err != nil {
		return Product{}, fmt.Errorf("ID: %w", err)
	}
	name := parts[1]
	if name == "" {
		return Product{}, errors.New("nom boʻsh")
	}
	if !utf8.ValidString(name) {
		return Product{}, errors.New("nom UTF-8 emas") // GB-2.10
	}
	price, err := parsePrice(parts[2])
	if err != nil {
		return Product{}, fmt.Errorf("narx: %w", err)
	}
	stock, err := strconv.Atoi(parts[3])
	if err != nil {
		return Product{}, fmt.Errorf("qoldiq: %w", err)
	}
	if stock < 0 {
		return Product{}, fmt.Errorf("qoldiq manfiy boʻlmasin, keldi %d", stock)
	}
	return Product{ID: id, Name: name, Price: price, Stock: stock}, nil
}
```

| Строка | Что делает |
|---|---|
| `parts := strings.Split(line, ";")` | `strings.Split` режет строку по `;` и возвращает `[]string`: `"1;olma;12000;40"` → `["1" "olma" "12000" "40"]` |
| `if len(parts) != 4 {…}` | если полей не четыре — ошибка вроде `4 ta maydon kerak, bor 1` («нужно 4 поля, есть 1») |
| `id, err := strconv.ParseInt(parts[0], 10, 64)` | переводит текст ID в число `int64` (`10` — десятичная система, `64` — 64 бита); при ошибке возвращает её с приставкой `ID: …` (`%w`, GB-2.08) |
| `name := parts[1]` и две проверки | название не пустое и это корректный UTF-8 (`utf8.ValidString`, GB-2.10) |
| `price, err := parsePrice(parts[2])` | цена из сумов в тийины: `12000` → `1200000` ([GB-1.07](/lab/youtube/gb/gb-1-07/ru)) |
| `stock, err := strconv.Atoi(parts[3])` | остаток как `int`; отрицательным быть не может |
| `return Product{ID: id, …}, nil` | готовый `Product` (GB-2.03) |

Посмотрим настоящий результат `strings.Split` (этой программы нет в папке курса; сохраните её и запустите `go run main.go`):

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	parts := strings.Split("1;olma;12000;40", ";")
	fmt.Printf("%q %d\n", parts, len(parts))
}
```

```console
$ go run main.go
["1" "olma" "12000" "40"] 4
```

`%q` показал каждое поле в кавычках: пока всё это текст. Строка `1;olma;12000;40` станет `Product{ID: 1, Name: "olma", Price: 1200000, Stock: 40}`
(именно это ожидает и `videoCatalog` в `tekshiruv_test.go`).

## `loadCatalog(r io.Reader)`: одна функция

Переносим цикл со Scanner в функцию:

```go
func loadCatalog(r io.Reader) ([]Product, error) {
	var products []Product
	sc := bufio.NewScanner(r)
	for sc.Scan() {
		p, err := parseLine(sc.Text())
		if err != nil {
			return nil, err
		}
		products = append(products, p)
	}
	return products, sc.Err()
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `func loadCatalog(r io.Reader) ([]Product, error) {` | тип параметра не `*os.File`, а **`io.Reader`**: Scanner нужен только `Read`. Правило [GB-2.07](/lab/youtube/gb/gb-2-07/ru): в параметре просите только нужный метод |
| 2 | `var products []Product` | пустой слайс |
| 3 | `sc := bufio.NewScanner(r)` | Scanner теперь читает из `r`: вызывается только `r.Read` |
| 4 | `for sc.Scan() {` | один оборот на каждую строку |
| 5–8 | `p, err := parseLine(sc.Text())` и `if err != nil { return nil, err }` | превращаем строку в `Product`; при ошибке возвращаем `nil` и ошибку |
| 9 | `products = append(products, p)` | добавляем результат в слайс (GB-2.01) |
| 11 | `return products, sc.Err()` | в конце — товары и ошибка Scanner (в конце файла она `nil`) |

В `run` отдаём `f` в `loadCatalog`, а результат печатаем через `writeReport` из [GB-2.07](/lab/youtube/gb/gb-2-07/ru) в `os.Stdout` (`_video/04-load/main.go`, имя файла здесь внутри кода):

```go
func run() error {
	f, err := os.Open("katalog.txt")
	if err != nil {
		return err
	}
	defer f.Close()
	products, err := loadCatalog(f)
	if err != nil {
		return err
	}
	return writeReport(os.Stdout, products)
}
```

```console
$ ./_video/run.sh 04-load go run .

oʻrik   35000 soʻm    5 dona
non      4000 soʻm  100 dona
choy    25000 soʻm    8 dona
```

Четыре товара, цена в сумах. `writeReport` не менялся: он получает `Price` в тийинах и делит на `tiyinPerSom`, чтобы напечатать суммы.

## Стандартный ввод: файл, `os.Stdin` и вертикальная черта

Теперь имя файла берётся не из кода, а из командной строки; если аргумента нет, программа читает **стандартный ввод**. `run` из `main.go`:

```go
func run() error {
	var r io.Reader = os.Stdin
	if len(os.Args) > 1 {
		f, err := os.Open(os.Args[1])
		if err != nil {
			return err
		}
		defer f.Close()
		r = f
	}
	products, err := loadCatalog(r)
	if err != nil {
		return err
	}
	return writeReport(os.Stdout, products)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 2 | `var r io.Reader = os.Stdin` | `r` — переменная типа `io.Reader`, сначала в ней `os.Stdin`. **Стандартный ввод** (stdin) — входной поток программы; `os.Stdin` тоже `*os.File`, как и `os.Stdout` ([GB-2.07](/lab/youtube/gb/gb-2-07/ru)) |
| 3 | `if len(os.Args) > 1 {` | есть ли в командной строке аргумент? ([GB-1.07](/lab/youtube/gb/gb-1-07/ru)) |
| 4 | `f, err := os.Open(os.Args[1])` | открываем файл с именем из первого аргумента |
| 8 | `defer f.Close()` | даже написанный внутри `if`, сработает, когда завершится `run` ([GB-2.09](/lab/youtube/gb/gb-2-09/ru)), а не при завершении блока `if` |
| 9 | `r = f` | записываем в `r` файл: значение интерфейса ([GB-2.07](/lab/youtube/gb/gb-2-07/ru)) теперь хранит `*os.File` |
| 11 | `products, err := loadCatalog(r)` | `loadCatalog` не изменился: он не знает, что лежит в `r` |

Что лежит в `r`:

| Ситуация | В `r` |
|---|---|
| аргумент есть (`go run . katalog.txt`) | открытый файл `*os.File` |
| аргумента нет (`go run .`) | `os.Stdin` |

Что сделает `go run .` без аргумента?

**A)** выведет пустой отчёт и сразу завершится · **B)** будет ждать: ввод — это терминал · **C)** ошибка: нет имени файла

<details>
<summary>Ответ</summary>

**B.** Стандартный ввод — сам терминал: `Read` ждёт строки, которые вы наберёте, а `Ctrl+D` в начале строки сообщает, что ввод закончился
([termios(3)](https://man7.org/linux/man-pages/man3/termios.3.html)). Этот ответ я заново не запускал: программа интерактивная, проверьте сами.
Если вы выбрали **A**, вы решили, что stdin пуст; **C** — аргумент необязателен: есть он — открывается файл, нет — остаётся stdin.

</details>

Каталог в stdin передаём через **вертикальную черту** (pipe): `|` соединяет вывод левой команды со стандартным вводом правой
([Bash manual: Pipelines](https://www.gnu.org/software/bash/manual/html_node/Pipelines.html)). С именем файла результат тот же:

```console
$ cat katalog.txt | go run .
olma    12000 soʻm   40 dona
oʻrik   35000 soʻm    5 dona
non      4000 soʻm  100 dona
choy    25000 soʻm    8 dona
```

```console
$ go run . katalog.txt
olma    12000 soʻm   40 dona
oʻrik   35000 soʻm    5 dona
non      4000 soʻm  100 dona
choy    25000 soʻm    8 dona
```

В обоих случаях одни и те же четыре строки: `loadCatalog` не знает, откуда пришли байты.

## Принимайте `Reader`, а не имя файла

Какой вызов не скомпилируется?

**A)** `loadCatalog(os.Stdin)` · **B)** `loadCatalog(f)` · **C)** `loadCatalog("katalog.txt")`

<details>
<summary>Ответ</summary>

**C.** `os.Stdin` и `f` — `*os.File`, у них есть `Read`. А `"katalog.txt"` — `string`, и метода `Read` у неё нет. Настоящая ошибка (в `_video/08-string/main.go` внутри `run`
вместо `loadCatalog(f)` написано `loadCatalog("katalog.txt")`):

```console
$ ./_video/run.sh 08-string go run .
(chiqish kodi: 1)
# github.com/abdurahmon27/bozor
./main.go:112:31: cannot use "katalog.txt" (constant of type string) as io.Reader value in argument to loadCatalog: string does not implement io.Reader (missing method Read)
```

Как читать: `./main.go:112:31` — файл, строка, столбец (GB-1.01). `cannot use "katalog.txt" (constant of type string) as io.Reader value in argument to loadCatalog` —
«строковую константу в кавычках нельзя использовать как `io.Reader` в аргументе `loadCatalog`». Причина: `string does not implement io.Reader (missing method Read)` —
«`string` не реализует `io.Reader`: нет метода `Read`». Первая строка `# github.com/abdurahmon27/bozor` — имя модуля (в видео её сократили).
Если вы выбрали **A** или **B**, оба вызова были верными.

</details>

Имя файла и Reader — разные вещи. Если функция принимает `Reader`, то **откуда** брать байты, решает вызывающий код: файл, stdin или текст. Поэтому `loadCatalog`
ничего не знает о том, есть ли файл, терминал или сеть.

В тесте файл вообще не нужен. Фрагмент из `tekshiruv_test.go` (сокращённый):

```go
	r := strings.NewReader("1;olma;12000;40\n2;oʻrik;35000;5\n")
	got, err := loadCatalog(r)
```

`strings.NewReader` создаёт `r`, который читает из текста. Его тип — `*strings.Reader`, у него есть `Read`, значит, это тоже `io.Reader`. `got` — товары, которые вернул `loadCatalog`.
Такой тест не трогает диск: он быстрый и каждый раз даёт один и тот же результат. В работе тело HTTP-запроса — тоже `io.Reader`: об этом в [GB-4.06](/lab/youtube/gb/gb-4-06/ru). Запустим
`TestVideo` из папки (`-run` выбирает тест по имени, `-v` показывает имя каждого теста):

```console
$ go test -run TestVideo -v
=== RUN   TestVideo
--- PASS: TestVideo (0.00s)
PASS
ok  	github.com/abdurahmon27/bozor	0.002s
```

## Глубже (необязательно): сколько раз Scanner вызывает `Read`

В видео этого нет, но в README папки курса есть (`07-count`). `logReader` — наш собственный Reader, который оборачивает другой Reader и печатает каждый `Read`.
У него есть метод `Read`, значит, он тоже `io.Reader`:

```go
// logReader boshqa Reader'ni oʻrab, har bir Read chaqiruvini chiqaradi.
type logReader struct {
	r io.Reader
}

func (l logReader) Read(p []byte) (int, error) {
	n, err := l.r.Read(p)
	fmt.Printf("Read: len(p)=%d n=%d err=%v\n", len(p), n, err)
	return n, err
}
```

В `run` изменилась одна строка: `loadCatalog(logReader{r: f})`. Scanner передаёт `Read` свой буфер на 4096 байт, поэтому для файла в 63 байта хватает двух вызовов
(в нашем цикле с буфером в 20 байт их было пять):

```console
$ ./_video/run.sh 07-count go run . katalog.txt
Read: len(p)=4096 n=63 err=<nil>
Read: len(p)=4033 n=0 err=EOF
4 ta mahsulot
```

Первый вызов принёс весь файл (`n=63`), второй вернул `EOF`: 4096 − 63 = 4033. Таблица `Scan` выше построена на этом измерении.

## Частые ошибки

### 1. `sc.Err()` не проверяется: данные пропадают молча

Это самая опасная ошибка, потому что она ничего не сообщает. Вариант, который встречается на code review: после цикла вместо `sc.Err()` возвращают `nil`. Обычно работает, потому что в конце файла
`Err` всё равно `nil`. `katta.txt` — тоже каталог из четырёх строк, но экспорт, который его записал, сломан: в третью строку вместо названия попало длинное описание. Поля:

```console
$ cut -c1-40 katta.txt
1;olma;12000;40
2;oʻrik;35000;5
3;non yangi uzilgan issiq non, yangi uzi
4;choy;25000;8
```

(`cut -c1-40` берёт первые 40 символов каждой строки.) Самая длинная строка — по `wc -L`:

```console
$ wc -L katta.txt
70014 katta.txt
```

70 014 — больше предела Scanner (64 KiB = 65 536). Ошибочный вариант (`_video/06-errsiz/main.go`):

```go
func loadCatalog(r io.Reader) ([]Product, error) {
	var products []Product
	sc := bufio.NewScanner(r)
	for sc.Scan() {
		p, err := parseLine(sc.Text())
		if err != nil {
			return nil, err
		}
		products = append(products, p)
	}
	return products, nil // XATO: sc.Err() tekshirilmadi
}
```

Посмотрите на последнюю строку: `return products, nil` — `sc.Err()` отброшен. Что выведет `go run . katta.txt`?

**A)** три товара: длинная строка пропускается · **B)** два товара, ошибки нет · **C)** ошибка: строка слишком длинная

<details>
<summary>Ответ</summary>

**B.** Третья строка длиннее предела Scanner: `Scan` вернул `false`, и цикл молча закончился. Наш код не заглянул в `sc.Err()`, поэтому ошибка пропала:

```console
$ ./_video/run.sh 06-errsiz go run . katta.txt
olma    12000 soʻm   40 dona
oʻrik   35000 soʻm    5 dona
```

Половина каталога потеряна, а программа завершилась успешно (код выхода 0: его печатает скрипт, я убрал эту строку из блока). Такую ошибку никто не заметит.
Если вы выбрали **A**, вы решили, что Scanner пропускает длинную строку: он останавливается. **C** — ошибка **есть**, но мы её не прочитали.

</details>

Исправление: в конце верните `return products, sc.Err()`. В `main.go` из папки так и сделано, и ошибка видна:

```console
$ go run . katta.txt
xato: bufio.Scanner: token too long
exit status 1
```

`xato:` — приставка `main`, `exit status 1` — сообщение `go run`: программа завершилась с кодом 1. `bufio.Scanner: token too long` — «строка слишком длинная для Scanner» (в документации Scanner одна строка называется **токеном**, token). Её
sentinel-ошибка — `bufio.ErrTooLong` (`go doc bufio.ErrTooLong`), её проверяют как в [GB-2.08](/lab/youtube/gb/gb-2-08/ru): `errors.Is(err, bufio.ErrTooLong)`. Если строка
действительно может быть длинной, `sc.Buffer` поднимает предел ([pkg.go.dev](https://pkg.go.dev/bufio#Scanner.Buffer)); на этой странице я его не запускал.

### 2. Относительный путь: файла «нет»

`os.Open("katalog.txt")` — **относительный путь**: файл ищется не рядом с файлом программы, а в **текущей папке** процесса
([path_resolution(7)](https://man7.org/linux/man-pages/man7/path_resolution.7.html)). В видео этого нет, это опыт из README: `go build` собирает бинарник, потом запускаем его на папку выше
(`bozor/` — временная папка, которую создал `run.sh`; `cd ..` — на папку выше):

```console
$ ./_video/run.sh 01-open sh -c 'go build && cd .. && ./bozor/bozor'
(chiqish kodi: 1)
```

## Проверьте себя

1. `f.Read(buf)` вернул `n` и `err`. Что использовать сначала?

<details>
<summary>Ответ</summary>

Сначала `n` байтов (`buf[:n]`), потом `err`. Reader может вернуть данные вместе с ошибкой (документация: «Callers should always process the n > 0 bytes returned
before considering the error»), и байты нельзя терять.

</details>

2. Цикл `for sc.Scan() { … }` закончился. Что вы проверяете и почему?

<details>
<summary>Ответ</summary>

`sc.Err()`. `Scan` возвращает `false` и при ошибке, и в конце файла; различает их только `Err` (в конце файла он `nil`). Без проверки в ситуации вроде `katta.txt` данные пропадают молча.

</details>

3. Из [GB-2.08](/lab/youtube/gb/gb-2-08/ru): как узнать, что внутри ошибки, обёрнутой через `%w`, есть `ErrNotFound`?

<details>
<summary>Ответ</summary>

`errors.Is(err, ErrNotFound)`. Он просматривает всю цепочку обёрнутых ошибок от начала до конца, а `err == ErrNotFound` сравнивает только самый внешний слой
([errors.Is](https://pkg.go.dev/errors#Is)).

</details>

4. Что выведет эта программа? (Её нет в папке курса: сохраните как `main.go` в пустой папке.)

```go
package main

import (
	"bufio"
	"fmt"
	"strings"
)

func main() {
	sc := bufio.NewScanner(strings.NewReader("a\nb\r\n\nc"))
	for sc.Scan() {
		fmt.Printf("%q\n", sc.Text())
	}
	fmt.Println(sc.Err())
}
```

**A)** `"a"`, `"b"`, `"c"` и `<nil>` · **B)** `"a"`, `"b"`, `""`, `"c"` и `<nil>` · **C)** `"a"`, `"b\r"`, `""`, `"c"` и `<nil>`

<details>
<summary>Ответ</summary>

**B.** `"a\nb\r\n\nc"` — четыре строки: `a`, `b` (`\r\n` тоже отбрасывается), пустая строка и последняя `c` без `\n`. **A** — Scanner пустые строки не пропускает (это вы сделаете
в задании сами). **C** — `\r` тоже отбрасывается. `Err()` — `nil`, `fmt.Println` печатает его как `<nil>`:

```console
$ go run main.go
"a"
"b"
""
"c"
<nil>
```

</details>

5. Из [GB-2.09](/lab/youtube/gb/gb-2-09/ru): `defer f.Close()` написан внутри блока `if len(os.Args) > 1 { … }`. Когда сработает `Close`?

<details>
<summary>Ответ</summary>

Когда завершится функция `run`, а не блок `if`: `defer` принадлежит функции ([Go spec: Defer statements](https://go.dev/ref/spec#Defer_statements)). Поэтому после `r = f`
`loadCatalog` читает из ещё открытого файла.

</details>

Подсказка: `n := 0` перед циклом, `n++` в начале цикла; комментарий пропускайте через `continue` **после** `n++`, иначе номера следующих строк сдвинутся. Понадобятся `strings.TrimSpace`
и `strings.HasPrefix`.

<details>
<summary>Разбор ответа (сначала попробуйте сами)</summary>

`loadCatalog` из `solution/main.go`:

```go
func loadCatalog(r io.Reader) ([]Product, error) {
	var products []Product
	sc := bufio.NewScanner(r)
	n := 0 // oʻqilgan qatorlar soni, izoh va boʻsh qatorlar ham
	for sc.Scan() {
		n++
		line := strings.TrimSpace(sc.Text())
		if line == "" || strings.HasPrefix(line, "#") {
			continue
		}
		p, err := parseLine(line)
		if err != nil {
			return nil, fmt.Errorf("%d-qator: %w", n, err)
		}
		products = append(products, p)
	}
	if err := sc.Err(); err != nil {
		// Scanner n-qatordan keyingisini oʻqiy olmadi.
		return nil, fmt.Errorf("%d-qator: %w", n+1, err)
	}
	return products, nil
}
```

- `n++` на каждой строке, **до** `continue`: комментарии и пустые строки тоже считаются, поэтому номер строки в ошибке совпадает с номером в файле.
- `strings.TrimSpace` убирает пробелы в начале и в конце; `line == ""` — пустая строка, `strings.HasPrefix(line, "#")` — комментарий. В обоих случаях `continue`.
- `fmt.Errorf("%d-qator: %w", n, err)`: `%w` сохраняет исходную ошибку внутри, `errors.As` и `errors.Is` её найдут. С `%v` текст был бы тот же, но цепочка оборвалась бы: тест это проверяет.
- `sc.Err()` теперь проверяется отдельно и оборачивается с `n+1`: Scanner не смог прочитать строку **после** последней прочитанной. В `katta.txt` прочитано две строки, третья слишком длинная: `3-qator`.

</details>
