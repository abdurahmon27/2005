## What you will learn

The GB-4.08 catalog lived in memory: stopping the server lost its orders. After moving to Postgres, how do you check for partial orders and negative stock?

**The one idea:** order integrity and stock rules run inside the database; test them against real Postgres. A separate schema for each test prevents parallel packages from damaging each other's tables.

By the end of the lesson you will:

- start the API with migrations and seed data;
- read the transaction and conditional UPDATE in `PlaceOrder`;
- test rollback, concurrent purchases and HTTP responses against a real database;
- add `GET /orders/{id}` using those tests.

| Term | Meaning | English term |
|---|---|---|
| integration test | tests the real handler, store and database together | integration test |
| test isolation | each test has its own tables and starting data | test isolation |
| package test parallelism | test programs for different packages may run at the same time | package test parallelism |

## Specification and files

`POST /orders` accepts `customer` and `items` in its body. Each item has `product_id` and `quantity`.
Money uses `int64` tiyin: `1200000` means 12,000 soʻm. `unit_price` is the unit price at sale time.
People's names in examples are fictional test data from `seed.sql`; `olma`, `non`, `choy`, `oʻrik` mean apples, bread, tea and apricots.

| Request or condition | Result |
|---|---|
| `GET /health` | `200`, `ok` |
| `GET /products`, `GET /products/{id}` | list or single product; invalid ID gives `400`, missing product gives `404` |
| `POST /products` | `201`; duplicate name gives `409`, invalid value gives `422` |
| `DELETE /products/{id}` | `204`; missing gives `404`, referenced by an order gives `409` |
| `POST /orders` | success `201`; missing product `404`, insufficient stock `409`, invalid value `422`, malformed JSON `400` |
| `GET /orders/{id}` | currently missing; homework |

Validation limits customer names to 1–100 characters, carts to 1–20 items, and quantities to 1–100 units. Repeating a product in two items also gives `422`.
`items[0].quantity` names the first item's quantity field. The error shape is unchanged: `error.code`, `error.message`, and `error.fields` when needed.

## From server to store

The complete entry file, including its comments:

```go filename="cmd/api/main.go" showLineNumbers
// api — bozor buyurtmalar API'si (GB-5.10, 5-modul nazorat nuqtasi): GB-4.08'dagi katalog API,
// endi maʼlumot Postgres'da. Server toʻxtasa ham mahsulotlar va buyurtmalar saqlanib qoladi.
//
//	docker compose up -d --wait
//	goose up                     (GOOSE_DRIVER, GOOSE_DBSTRING, GOOSE_MIGRATION_DIR: GB-5.06)
//	docker compose exec db psql -f /lab/seed.sql
//	export DATABASE_URL=postgres://bozor:bozor-lab@localhost:5510/bozor
//	go run ./cmd/api             → bozor API: http://localhost:8765
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"os"
	"time"

	"github.com/abdurahmon27/bozor/internal/store"
	"github.com/jackc/pgx/v5/pgxpool"
)

// newServer — bozor API serveri (GB-4.04): route'lar newMux'da, sarlavhalar uchun vaqt chegarasi.
func newServer(addr string, st *store.Store) *http.Server {
	return &http.Server{
		Addr:              addr,
		Handler:           newMux(st),
		ReadHeaderTimeout: 5 * time.Second,
	}
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}

func run() error {
	url := os.Getenv("DATABASE_URL")
	if url == "" {
		return errors.New("DATABASE_URL yoʻq: export DATABASE_URL=postgres://bozor:bozor-lab@localhost:5510/bozor")
	}
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	pool, err := pgxpool.New(ctx, url)
	if err != nil {
		return err
	}
	defer pool.Close()
	if err := pool.Ping(ctx); err != nil { // baza ishlamasa server ishga tushmaydi
		return err
	}
	srv := newServer(":8765", store.New(pool))
	fmt.Println("bozor API: http://localhost:8765")
	return srv.ListenAndServe()
}
```

| Line | What it does |
|---|---|
| 1–8 | commented startup notes; the URL uses the original port 5510 |
| 9, 11–21 | `package main`; context, errors, output, HTTP, environment, time, store and pgxpool packages |
| 23–30 | `newServer`: address, `newMux(st)` handler, five seconds for headers |
| 32–37 | `main` calls `run`; on error it writes to stderr and exits with code 1 |
| 39–43 | `run() error`: returns a clear error if the URL is missing |
| 44–45 | five-second context for checking the connection; `cancel` on return |
| 46–50 | create the pool, check its error, `Close` on return |
| 51–53 | `Ping` checks a real connection; the HTTP server does not start without the database |
| 54–57 | pool → store → server; print the address and wait for requests |

Blank lines separate the parts; `{}` bounds a block or struct, and `&http.Server` takes its address.
Successful return from `pgxpool.New` does not guarantee connectivity. That is why `Ping` is needed.
Ordinary return from `run` executes its deferred calls; `os.Exit` itself does not run deferred calls.

`Store` holds only `pool *pgxpool.Pool`. There is no mutable catalog in memory, so the previous `sync.Mutex` is unnecessary.
The handler passes `r.Context()` to the database: client disconnection cancels the context. By default, pgx stops waiting and closes the connection.
The following is a complete function excerpt from `cmd/api/handlers.go`; its other definitions are in the same project.

```go
func (a *api) createOrder(w http.ResponseWriter, r *http.Request) {
	var in orderInput
	if !decodeJSON(w, r, &in) {
		return
	}
	if f := validateOrder(in); len(f) > 0 {
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: "qiymatlar notoʻgʻri", Fields: f})
		return
	}
	items := make([]store.OrderItem, len(in.Items))
	for i, it := range in.Items {
		items[i] = store.OrderItem{ProductID: it.ProductID, Quantity: it.Quantity}
	}
	o, err := a.st.PlaceOrder(r.Context(), in.Customer, items)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	w.Header().Set("Location", fmt.Sprintf("/orders/%d", o.ID))
	writeJSON(w, http.StatusCreated, o)
}
```

`in` has type `orderInput`. `decodeJSON` checks structure; `validateOrder` returns field errors.
`make` allocates a slice of store items; the loop copies input IDs and quantities. `PlaceOrder` performs the actual writes.
Errors go to `writeStoreError`; success writes `Location` and `201`.

## One transaction: conditional UPDATE and price

The complete method from `internal/store/store.go`:

```go
func (s *Store) PlaceOrder(ctx context.Context, customer string, items []OrderItem) (Order, error) {
	if len(items) == 0 {
		return Order{}, fmt.Errorf("%w: savat boʻsh", ErrBadQuantity)
	}
	for _, it := range items {
		if it.Quantity <= 0 {
			return Order{}, fmt.Errorf("%w, hozir %d", ErrBadQuantity, it.Quantity)
		}
	}
	// Qatorlar doim bir xil tartibda (ID boʻyicha) qulflanadi: ikki savat bir-birini kutib qotmaydi
	// (deadlock, GB-5.08 Chuqurroq). Chaqiruvchining slice'i oʻzgarmasin: nusxa saralanadi.
	items = slices.Clone(items)
	slices.SortFunc(items, func(a, b OrderItem) int { return cmp.Compare(a.ProductID, b.ProductID) })

	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return Order{}, err
	}
	defer tx.Rollback(ctx)

	o := Order{Customer: customer}
	err = tx.QueryRow(ctx,
		"INSERT INTO orders (customer) VALUES ($1) RETURNING id, status", customer).
		Scan(&o.ID, &o.Status)
	if err != nil {
		return Order{}, err
	}
	for _, it := range items {
		err = tx.QueryRow(ctx,
			"UPDATE products SET stock = stock - $1 WHERE id = $2 AND stock >= $1 RETURNING price",
			it.Quantity, it.ProductID).Scan(&it.UnitPrice)
		if errors.Is(err, pgx.ErrNoRows) {
			return Order{}, whyNoRow(ctx, tx, it)
		}
		if err != nil {
			return Order{}, err
		}
		_, err = tx.Exec(ctx,
			"INSERT INTO order_items (order_id, product_id, quantity, unit_price) VALUES ($1, $2, $3, $4)",
			o.ID, it.ProductID, it.Quantity, it.UnitPrice)
		if err != nil {
			return Order{}, err
		}
		o.Items = append(o.Items, it)
		o.Total += it.UnitPrice * int64(it.Quantity)
	}
	if err := tx.Commit(ctx); err != nil {
		return Order{}, err
	}
	return o, nil
}
```

| Part | Reason |
|---|---|
| empty cart and `Quantity <= 0` | calls outside HTTP must reject invalid purchases too |
| `slices.Clone`, `slices.SortFunc`, `cmp.Compare` | consistent lock order by ID without changing the caller's slice |
| `Begin`, `defer Rollback` | transaction on one connection; rollback on every early return |
| `INSERT … RETURNING id, status` | write the new ID and default status into `o` |
| `$1` and `$2` | quantity and product ID respectively; values are passed separately from SQL |
| `stock >= $1` | check and decrement stock in one command |
| `RETURNING price`, `Scan(&it.UnitPrice)` | save the sale price in the item |
| `tx.Exec` | insert the order item through this same transaction |
| `append`, `Total += …` | response items and tiyin total; `int64` converts quantity to the price type |
| `Commit` | commit every step; its error is checked too |

`UPDATE` holds its row lock until the transaction ends. Opposite carts `[olma, choy]` and `[choy, olma]` can wait for each other: a **deadlock**.
ID order prevents this conflict. That is why `TestOppositeCarts` exists.
Under READ COMMITTED, a waiting `UPDATE` rechecks its condition against the updated row; 20 customers cannot all purchase the same remaining unit.

## Zero rows: 404 or 409?

When there is no updated row, `QueryRow(...).Scan(...)` returns `pgx.ErrNoRows`. This is not an SQL error: the transaction remains usable for another query.
Do not confuse it with the aborted transaction after an SQL error in GB-5.07.

```go
func whyNoRow(ctx context.Context, tx pgx.Tx, it OrderItem) error {
	var p Product
	err := tx.QueryRow(ctx,
		"SELECT name, stock FROM products WHERE id = $1", it.ProductID).Scan(&p.Name, &p.Stock)
	if errors.Is(err, pgx.ErrNoRows) {
		return fmt.Errorf("mahsulot %d: %w", it.ProductID, ErrNotFound)
	}
	if err != nil {
		return err
	}
	return &StockError{Name: p.Name, Stock: p.Stock, Want: it.Quantity}
}
```

`tx pgx.Tx` receives the same transaction. `whyNoRow` reads the product name and stock.
A missing product wraps `ErrNotFound` with `%w`. An existing product returns `&StockError{Name, Stock, Want}`.
`Name` is the name, `Stock` the available quantity, and `Want` the requested quantity. Returning from `PlaceOrder` then runs `Rollback`.

Seed orders reference apples. What does `DELETE /products/1` return? **A)** `204` · **B)** `500` · **C)** `409`.

<details>
<summary>Answer</summary>

**C.** `order_items.product_id REFERENCES products(id)` prevents deleting the product. The store maps `23503` to `ErrInUse`; the handler returns `409`.
A would damage order history; B treats an expected business condition as an internal error.

</details>

```console
$ curl -sS -i -X DELETE localhost:8765/products/1
HTTP/1.1 409 Conflict
Content-Type: application/json
Date: Fri, 27 Nov 2026 16:42:32 GMT
Content-Length: 81

{"error":{"code":"conflict","message":"mahsulot 1: mahsulot buyurtmalarda bor"}}
```

`writeStoreError` maps errors to statuses in one place:

| Store result | HTTP and code |
|---|---|
| `ErrNotFound` | `404 not_found` |
| `*StockError`, `errors.As` | `409 insufficient_stock` |
| `ErrDuplicate` (`23505`, `UNIQUE`) | `409 conflict` |
| `ErrInUse` (`23503`, foreign key) | `409 conflict` |
| `ErrBadQuantity`, `ErrBadProduct` | `422 validation_failed` |
| unexpected error | `500 internal`; details in the server log |

## Real Postgres: one schema per test

A mock is code that substitutes for the database. It does not check the conditional UPDATE, CHECK, foreign key and rollback inside Postgres.
An **integration test** exercises the real parts together: `httptest → newMux → Store → Postgres`. No separate HTTP server port is needed.
**Test isolation** ensures one test cannot change another test's data.

```go filename="internal/pgtest/pgtest.go" showLineNumbers
// Package pgtest — testlar uchun haqiqiy Postgres (mock emas). Har test oʻz boʻsh sxemasini oladi:
// migratsiyalar (goose) va seed.sql shu sxemaga qoʻllanadi, test tugagach sxema oʻchiriladi.
// Shuning uchun testlar bir-biriga xalaqit bermaydi, `go test ./...` paketlarni parallel
// ishga tushirganda ham (GB-5.10 videosidagi xato), va sizning public sxemangizga tegmaydi.
package pgtest

import (
	"context"
	"fmt"
	"os"
	"testing"
	"time"

	"github.com/abdurahmon27/bozor"
	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
	"github.com/jackc/pgx/v5/stdlib"
)

// LabURL — shu papkadagi compose.yaml koʻtaradigan Postgres. Boshqa manzil uchun DATABASE_URL qoʻying.
const LabURL = "postgres://bozor:bozor-lab@localhost:5510/bozor"

// New bu test uchun yangi sxema yaratadi, unga migratsiyalar va seed.sql'ni qoʻllaydi va shu sxemaga
// ulangan pool qaytaradi. Postgres ishlamasa test aniq xabar bilan yiqiladi (oʻtkazib yuborilmaydi).
func New(t *testing.T) *pgxpool.Pool {
	t.Helper()
	url := os.Getenv("DATABASE_URL")
	if url == "" {
		url = LabURL
	}
	cfg, err := pgxpool.ParseConfig(url)
	if err != nil {
		t.Fatalf("DATABASE_URL notoʻgʻri: %v", err)
	}
	cfg.MaxConns = max(cfg.MaxConns, 4) // URL'da pool_max_conns=1 qolgan boʻlsa ham parallel test toʻxtab qolmasin (GB-5.07)
	ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()

	admin, err := pgxpool.NewWithConfig(ctx, cfg)
	if err == nil {
		err = admin.Ping(ctx)
	}
	if err != nil {
		t.Fatalf("Postgres'ga ulanib boʻlmadi (%s:%d): avval shu papkada `docker compose up -d --wait` ishga tushiring.\n%v",
			cfg.ConnConfig.Host, cfg.ConnConfig.Port, err)
	}
	schema := fmt.Sprintf("test_%d", time.Now().UnixNano())
	if _, err := admin.Exec(ctx, "CREATE SCHEMA "+schema); err != nil {
		t.Fatalf("sxema yaratilmadi: %v", err)
	}
	t.Cleanup(func() {
		if _, err := admin.Exec(context.Background(), "DROP SCHEMA "+schema+" CASCADE"); err != nil {
			t.Logf("sxema %s oʻchirilmadi (qoʻlda: DROP SCHEMA %s CASCADE): %v", schema, schema, err)
		}
		admin.Close()
	})

	poolCfg := cfg.Copy()                                    // nusxa: admin pool'ning sozlamasi oʻzgarmasin (u ham shu cfg'dan yasalgan)
	poolCfg.ConnConfig.RuntimeParams["search_path"] = schema // har ulanish jadvallarni shu sxemadan qidiradi
	pool, err := pgxpool.NewWithConfig(ctx, poolCfg)
	if err != nil {
		t.Fatalf("pool: %v", err)
	}
	t.Cleanup(pool.Close)

	db := stdlib.OpenDBFromPool(pool) // goose database/sql bilan ishlaydi: pool ustidan *sql.DB
	defer db.Close()
	provider, err := bozor.NewProvider(db)
	if err != nil {
		t.Fatalf("goose: %v", err)
	}
	if _, err := provider.Up(ctx); err != nil {
		t.Fatalf("migratsiya qoʻllanmadi: %v", err)
	}
	// Oddiy protokol: bitta matnda bir nechta SQL buyrugʻi boʻlishi mumkin (GB-5.07 testlari).
	if _, err := pool.Exec(ctx, bozor.SeedSQL, pgx.QueryExecModeSimpleProtocol); err != nil {
		t.Fatalf("seed.sql bajarilmadi: %v", err)
	}
	return pool
}
```

|---|---|

| 39–46 | admin pool and `Ping`; a missing database produces a clear failure rather than skipping the test |

A schema is a named group of tables in a database. `search_path` determines which group supplies the name `products`.
`RuntimeParams` configures every new connection; we do not depend on an incidental `SET` on a single connection.
You cannot pass a schema name as an SQL identifier with `$1`. Here the name comes from an internal time value, never client text.

`t.Cleanup` runs when the test finishes; `defer` would run when `New` returned. Cleanup calls run in reverse order: close the test pool, then drop the schema.
`db.Close` closes the wrapper without closing the pgx pool. `go:embed` in `migrate.go` embedded migrations and seed data into the binary.

| Test A | Test B |
|---|---|
| `search_path = test_A` | `search_path = test_B` |
| `test_A.products`, `test_A.orders` | `test_B.products`, `test_B.orders` |
| only `test_A` is dropped at the end | `test_B` continues running |

## Going deeper (optional): protection and measurement limits

- `CHECK (stock >= 0)` adds database protection against application mistakes. A guard returning zero rows leaves the transaction usable; a CHECK error aborts it.
- Rollback does not rewind the identity sequence. A cancelled order can leave an ID gap; IDs are not guaranteed to be gapless.
- `go test` can cache success. Database state is not part of the cache key; use `-count=1` or `-count=5` for an actual integration run.
- This lesson's `NewProvider` uses no shared advisory lock: schema migrations are independent. Concurrent deployment migrations in one shared schema are a different problem, covered in GB-8.06.
- The README reports API tests with/without the lock at 6.1/1.1 s: about 5.55 times. This is a **quoted** video-preparation measurement, not rerun for this page.
- The `go test -race` result is also quoted from preparation: it passed in Docker with gcc. This page was checked with `CGO_ENABLED=0`; the race check was not rerun.
- `active` is absent from this lab's sale condition; seed products are active. Returning `404` for a missing product even inside the body is this course's specification; another API may choose `422`.
- testcontainers-go can start Postgres from a test. This course uses its existing Compose setup, later following the same approach in CI.

```go
func (s *Store) Order(ctx context.Context, id int64) (Order, error) {
	o := Order{ID: id, Items: []OrderItem{}}
	err := s.pool.QueryRow(ctx,
		"SELECT customer, status FROM orders WHERE id = $1", id).Scan(&o.Customer, &o.Status)
	if errors.Is(err, pgx.ErrNoRows) {
		return Order{}, fmt.Errorf("buyurtma %d: %w", id, ErrOrderNotFound)
	}
	if err != nil {
		return Order{}, err
	}
	rows, err := s.pool.Query(ctx,
		"SELECT product_id, quantity, unit_price FROM order_items WHERE order_id = $1 ORDER BY id", id)
	if err != nil {
		return Order{}, err
	}
	defer rows.Close()
	for rows.Next() {
		var it OrderItem
		if err := rows.Scan(&it.ProductID, &it.Quantity, &it.UnitPrice); err != nil {
			return Order{}, err
		}
		o.Items = append(o.Items, it)
		o.Total += it.UnitPrice * int64(it.Quantity)
	}
	if err := rows.Err(); err != nil {
		return Order{}, err
	}
	return o, nil
}
```
