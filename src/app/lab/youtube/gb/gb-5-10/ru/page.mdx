## Что вы узнаете

В GB-4.08 каталог хранился в памяти: после остановки сервера заказы исчезали. Как после перехода на Postgres проверить отсутствие частичных заказов и отрицательных остатков?

**Одна идея:** целостность заказа и правило остатка обеспечиваются базой; проверяйте их на настоящем Postgres. Отдельная схема для каждого теста защищает таблицы от параллельных тестов других пакетов.

К концу урока вы:

- запустите API с миграциями и начальными данными;
- разберёте транзакцию и условный UPDATE в `PlaceOrder`;
- проверите rollback, параллельные покупки и HTTP-ответы на настоящей базе;
- добавите `GET /orders/{id}`, опираясь на эти тесты.

| Термин | Смысл | Английский термин |
|---|---|---|
| интеграционный тест | настоящий обработчик, хранилище и база проверяются вместе | integration test |

## Спецификация и файлы

`POST /orders` принимает `customer` и `items` в теле. В каждой позиции есть `product_id` и `quantity`.
Деньги хранятся в тийинах, `int64`: `1200000` — 12 000 сумов. `unit_price` — цена единицы в момент продажи.
Имена людей в примерах — вымышленные тестовые данные из `seed.sql`; `olma`, `non`, `choy`, `oʻrik` означают яблоки, хлеб, чай, абрикосы.

| Запрос или ситуация | Результат |
|---|---|
| `GET /health` | `200`, `ok` |
| `GET /products`, `GET /products/{id}` | список или один товар; неверный ID — `400`, отсутствующий товар — `404` |
| `POST /products` | `201`; повтор имени — `409`, неверное значение — `422` |
| `DELETE /products/{id}` | `204`; не найден — `404`, используется в заказе — `409` |
| `POST /orders` | успех — `201`; отсутствующий товар — `404`, недостаточный остаток — `409`, неверное значение — `422`, повреждённый JSON — `400` |
| `GET /orders/{id}` | пока отсутствует; домашнее задание |

Валидация ограничивает имя клиента 1–100 символами, корзину — 1–20 позициями, количество — 1–100 единицами. Один товар в двух позициях тоже даёт `422`.
`items[0].quantity` — поле количества первой позиции. Формат ошибки прежний: `error.code`, `error.message`, при необходимости `error.fields`.

## От сервера до хранилища

Полный входной файл с комментариями:

```go filename="cmd/api/main.go" showLineNumbers
// api — bozor buyurtmalar API'si (GB-5.10, 5-modul nazorat nuqtasi): GB-4.08'dagi katalog API,
// endi maʼlumot Postgres'da. Server toʻxtasa ham mahsulotlar va buyurtmalar saqlanib qoladi.
//
//	docker compose up -d --wait
//	goose up                     (GOOSE_DRIVER, GOOSE_DBSTRING, GOOSE_MIGRATION_DIR: GB-5.06)
//	docker compose exec db psql -f /lab/seed.sql
//	export DATABASE_URL=postgres://bozor:bozor-lab@localhost:5510/bozor
//	go run ./cmd/api             → bozor API: http://localhost:8765
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"os"
	"time"

	"github.com/abdurahmon27/bozor/internal/store"
	"github.com/jackc/pgx/v5/pgxpool"
)

// newServer — bozor API serveri (GB-4.04): route'lar newMux'da, sarlavhalar uchun vaqt chegarasi.
func newServer(addr string, st *store.Store) *http.Server {
	return &http.Server{
		Addr:              addr,
		Handler:           newMux(st),
		ReadHeaderTimeout: 5 * time.Second,
	}
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "xato:", err)
		os.Exit(1)
	}
}

func run() error {
	url := os.Getenv("DATABASE_URL")
	if url == "" {
		return errors.New("DATABASE_URL yoʻq: export DATABASE_URL=postgres://bozor:bozor-lab@localhost:5510/bozor")
	}
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	pool, err := pgxpool.New(ctx, url)
	if err != nil {
		return err
	}
	defer pool.Close()
	if err := pool.Ping(ctx); err != nil { // baza ishlamasa server ishga tushmaydi
		return err
	}
	srv := newServer(":8765", store.New(pool))
	fmt.Println("bozor API: http://localhost:8765")
	return srv.ListenAndServe()
}
```

| Строка | Что делает |
|---|---|
| 1–8 | заметки о запуске в комментариях; URL записан для исходного порта 5510 |
| 9, 11–21 | `package main`; пакеты context, ошибок, вывода, HTTP, окружения, времени, store и pgxpool |
| 23–30 | `newServer`: адрес, обработчик `newMux(st)`, 5 секунд на заголовки |
| 32–37 | `main` вызывает `run`; при ошибке пишет в stderr и завершает процесс с кодом 1 |
| 39–43 | `run() error`: возвращает понятную ошибку, если URL отсутствует |
| 44–45 | context на 5 секунд для проверки подключения; `cancel` при возврате |
| 46–50 | создание пула, проверка ошибки, `Close` при возврате |
| 51–53 | `Ping` проверяет настоящее подключение; без базы HTTP-сервер не запускается |
| 54–57 | пул → хранилище → сервер; вывод адреса и ожидание запросов |

Пустые строки разделяют части; `{}` ограничивает блок или структуру, `&http.Server` означает её адрес.
Успешный возврат `pgxpool.New` не гарантирует подключения. Для этого нужен `Ping`.
При обычном возврате из `run` выполняются его `defer`; сам `os.Exit` их не выполняет.

`Store` хранит только `pool *pgxpool.Pool`. Изменяемого каталога в памяти больше нет, поэтому прежний `sync.Mutex` не нужен.
Обработчик передаёт базе `r.Context()`: при отключении клиента context отменяется. При стандартной настройке pgx прекращает ожидание и закрывает соединение.
Следующая функция — полный фрагмент из `cmd/api/handlers.go`; остальные определения находятся в том же проекте.

```go
func (a *api) createOrder(w http.ResponseWriter, r *http.Request) {
	var in orderInput
	if !decodeJSON(w, r, &in) {
		return
	}
	if f := validateOrder(in); len(f) > 0 {
		writeError(w, http.StatusUnprocessableEntity, apiError{Code: "validation_failed", Message: "qiymatlar notoʻgʻri", Fields: f})
		return
	}
	items := make([]store.OrderItem, len(in.Items))
	for i, it := range in.Items {
		items[i] = store.OrderItem{ProductID: it.ProductID, Quantity: it.Quantity}
	}
	o, err := a.st.PlaceOrder(r.Context(), in.Customer, items)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	w.Header().Set("Location", fmt.Sprintf("/orders/%d", o.ID))
	writeJSON(w, http.StatusCreated, o)
}
```

`in` имеет тип `orderInput`. `decodeJSON` проверяет форму; `validateOrder` возвращает ошибки полей.
`make` выделяет слайс позиций хранилища; цикл копирует входные ID и количество. `PlaceOrder` выполняет запись.
Ошибка передаётся в `writeStoreError`; при успехе записываются `Location` и `201`.

## Одна транзакция: условный UPDATE и цена

Полный метод из `internal/store/store.go`:

```go
func (s *Store) PlaceOrder(ctx context.Context, customer string, items []OrderItem) (Order, error) {
	if len(items) == 0 {
		return Order{}, fmt.Errorf("%w: savat boʻsh", ErrBadQuantity)
	}
	for _, it := range items {
		if it.Quantity <= 0 {
			return Order{}, fmt.Errorf("%w, hozir %d", ErrBadQuantity, it.Quantity)
		}
	}
	// Qatorlar doim bir xil tartibda (ID boʻyicha) qulflanadi: ikki savat bir-birini kutib qotmaydi
	// (deadlock, GB-5.08 Chuqurroq). Chaqiruvchining slice'i oʻzgarmasin: nusxa saralanadi.
	items = slices.Clone(items)
	slices.SortFunc(items, func(a, b OrderItem) int { return cmp.Compare(a.ProductID, b.ProductID) })

	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return Order{}, err
	}
	defer tx.Rollback(ctx)

	o := Order{Customer: customer}
	err = tx.QueryRow(ctx,
		"INSERT INTO orders (customer) VALUES ($1) RETURNING id, status", customer).
		Scan(&o.ID, &o.Status)
	if err != nil {
		return Order{}, err
	}
	for _, it := range items {
		err = tx.QueryRow(ctx,
			"UPDATE products SET stock = stock - $1 WHERE id = $2 AND stock >= $1 RETURNING price",
			it.Quantity, it.ProductID).Scan(&it.UnitPrice)
		if errors.Is(err, pgx.ErrNoRows) {
			return Order{}, whyNoRow(ctx, tx, it)
		}
		if err != nil {
			return Order{}, err
		}
		_, err = tx.Exec(ctx,
			"INSERT INTO order_items (order_id, product_id, quantity, unit_price) VALUES ($1, $2, $3, $4)",
			o.ID, it.ProductID, it.Quantity, it.UnitPrice)
		if err != nil {
			return Order{}, err
		}
		o.Items = append(o.Items, it)
		o.Total += it.UnitPrice * int64(it.Quantity)
	}
	if err := tx.Commit(ctx); err != nil {
		return Order{}, err
	}
	return o, nil
}
```

| Часть | Причина |
|---|---|
| пустая корзина и `Quantity <= 0` | вызов вне HTTP тоже должен отклонять недопустимую покупку |
| `slices.Clone`, `slices.SortFunc`, `cmp.Compare` | одинаковый порядок блокировок по ID без изменения слайса вызывающего |
| `Begin`, `defer Rollback` | транзакция на одном соединении; откат при каждом раннем возврате |
| `INSERT … RETURNING id, status` | запись нового ID и стандартного статуса в `o` |
| `$1` и `$2` | количество и ID товара соответственно; значения передаются отдельно от SQL |
| `stock >= $1` | проверка и уменьшение остатка одной командой |
| `RETURNING price`, `Scan(&it.UnitPrice)` | сохранение цены продажи в позиции |
| `tx.Exec` | запись позиции через ту же транзакцию |
| `append`, `Total += …` | позиции ответа и сумма в тийинах; `int64` приводит количество к типу цены |
| `Commit` | подтверждение всех шагов; его ошибка тоже проверяется |

`UPDATE` удерживает блокировку строки до конца транзакции. Противоположные корзины `[olma, choy]` и `[choy, olma]` могут ждать друг друга: **deadlock**.
Порядок по ID предотвращает этот конфликт. Для этого есть `TestOppositeCarts`.
При READ COMMITTED ожидавший `UPDATE` проверяет условие заново на обновлённой строке; 20 покупателей не смогут купить одну оставшуюся единицу одновременно.

## Ноль строк: 404 или 409?

Если обновлённая строка не найдена, `QueryRow(...).Scan(...)` возвращает `pgx.ErrNoRows`. Это не ошибка SQL: транзакция не прервана, в ней можно сделать следующий запрос.
Не путайте это с прерванной транзакцией после ошибки SQL из GB-5.07.

```go
func whyNoRow(ctx context.Context, tx pgx.Tx, it OrderItem) error {
	var p Product
	err := tx.QueryRow(ctx,
		"SELECT name, stock FROM products WHERE id = $1", it.ProductID).Scan(&p.Name, &p.Stock)
	if errors.Is(err, pgx.ErrNoRows) {
		return fmt.Errorf("mahsulot %d: %w", it.ProductID, ErrNotFound)
	}
	if err != nil {
		return err
	}
	return &StockError{Name: p.Name, Stock: p.Stock, Want: it.Quantity}
}
```

`tx pgx.Tx` принимает ту же транзакцию. `whyNoRow` читает название и остаток.
Если товара нет, `ErrNotFound` оборачивается через `%w`. Если есть — возвращается `&StockError{Name, Stock, Want}`.
`Name` — название, `Stock` — доступное количество, `Want` — запрошенное. Затем возврат из `PlaceOrder` запускает `Rollback`.

В начальных данных яблоки входят в заказы. Ответ на `DELETE /products/1`? **A)** `204` · **B)** `500` · **C)** `409`.

<details>
<summary>Ответ</summary>

**C.** `order_items.product_id REFERENCES products(id)` не позволяет удалить товар. Хранилище преобразует `23503` в `ErrInUse`, обработчик возвращает `409`.
A нарушил бы историю заказов; B считает ожидаемую бизнес-ситуацию внутренней ошибкой.

</details>

## Настоящий Postgres: своя схема у каждого теста

Mock — код, подменяющий базу. Он не проверяет условный UPDATE, CHECK, внешний ключ и rollback внутри Postgres.
**Интеграционный тест** запускает настоящие части вместе: `httptest → newMux → Store → Postgres`. Отдельный порт HTTP-сервера не нужен.
**Изоляция тестов** обеспечивает независимость данных одного теста от изменений другого.

```go filename="internal/pgtest/pgtest.go" showLineNumbers
// Package pgtest — testlar uchun haqiqiy Postgres (mock emas). Har test oʻz boʻsh sxemasini oladi:
// migratsiyalar (goose) va seed.sql shu sxemaga qoʻllanadi, test tugagach sxema oʻchiriladi.
// Shuning uchun testlar bir-biriga xalaqit bermaydi, `go test ./...` paketlarni parallel
// ishga tushirganda ham (GB-5.10 videosidagi xato), va sizning public sxemangizga tegmaydi.
package pgtest

import (
	"context"
	"fmt"
	"os"
	"testing"
	"time"

	"github.com/abdurahmon27/bozor"
	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
	"github.com/jackc/pgx/v5/stdlib"
)

// LabURL — shu papkadagi compose.yaml koʻtaradigan Postgres. Boshqa manzil uchun DATABASE_URL qoʻying.
const LabURL = "postgres://bozor:bozor-lab@localhost:5510/bozor"

// New bu test uchun yangi sxema yaratadi, unga migratsiyalar va seed.sql'ni qoʻllaydi va shu sxemaga
// ulangan pool qaytaradi. Postgres ishlamasa test aniq xabar bilan yiqiladi (oʻtkazib yuborilmaydi).
func New(t *testing.T) *pgxpool.Pool {
	t.Helper()
	url := os.Getenv("DATABASE_URL")
	if url == "" {
		url = LabURL
	}
	cfg, err := pgxpool.ParseConfig(url)
	if err != nil {
		t.Fatalf("DATABASE_URL notoʻgʻri: %v", err)
	}
	cfg.MaxConns = max(cfg.MaxConns, 4) // URL'da pool_max_conns=1 qolgan boʻlsa ham parallel test toʻxtab qolmasin (GB-5.07)
	ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()

	admin, err := pgxpool.NewWithConfig(ctx, cfg)
	if err == nil {
		err = admin.Ping(ctx)
	}
	if err != nil {
		t.Fatalf("Postgres'ga ulanib boʻlmadi (%s:%d): avval shu papkada `docker compose up -d --wait` ishga tushiring.\n%v",
			cfg.ConnConfig.Host, cfg.ConnConfig.Port, err)
	}
	schema := fmt.Sprintf("test_%d", time.Now().UnixNano())
	if _, err := admin.Exec(ctx, "CREATE SCHEMA "+schema); err != nil {
		t.Fatalf("sxema yaratilmadi: %v", err)
	}
	t.Cleanup(func() {
		if _, err := admin.Exec(context.Background(), "DROP SCHEMA "+schema+" CASCADE"); err != nil {
			t.Logf("sxema %s oʻchirilmadi (qoʻlda: DROP SCHEMA %s CASCADE): %v", schema, schema, err)
		}
		admin.Close()
	})

	poolCfg := cfg.Copy()                                    // nusxa: admin pool'ning sozlamasi oʻzgarmasin (u ham shu cfg'dan yasalgan)
	poolCfg.ConnConfig.RuntimeParams["search_path"] = schema // har ulanish jadvallarni shu sxemadan qidiradi
	pool, err := pgxpool.NewWithConfig(ctx, poolCfg)
	if err != nil {
		t.Fatalf("pool: %v", err)
	}
	t.Cleanup(pool.Close)

	db := stdlib.OpenDBFromPool(pool) // goose database/sql bilan ishlaydi: pool ustidan *sql.DB
	defer db.Close()
	provider, err := bozor.NewProvider(db)
	if err != nil {
		t.Fatalf("goose: %v", err)
	}
	if _, err := provider.Up(ctx); err != nil {
		t.Fatalf("migratsiya qoʻllanmadi: %v", err)
	}
	// Oddiy protokol: bitta matnda bir nechta SQL buyrugʻi boʻlishi mumkin (GB-5.07 testlari).
	if _, err := pool.Exec(ctx, bozor.SeedSQL, pgx.QueryExecModeSimpleProtocol); err != nil {
		t.Fatalf("seed.sql bajarilmadi: %v", err)
	}
	return pool
}
```

| Строка | Что делает |
|---|---|
| 1–24 | пакет и импорты; `LabURL` — стандартный адрес, `DATABASE_URL` заменяет его |
| 25–34 | `t.Helper` связывает ошибку с вызывающим тестом; URL разбирается в настройки |
| 35–37 | минимум 4 соединения; 30 секунд на подготовку, очистка context при возврате |
| 39–46 | административный пул и `Ping`; без базы тест завершается понятной ошибкой, а не пропускается |
| 47–50 | имя из значения времени `UnixNano`; `CREATE SCHEMA` создаёт отдельную группу таблиц |
| 51–56 | после теста `DROP SCHEMA … CASCADE`, затем закрытие административного пула; ошибка записывается в журнал |
| 58–64 | `cfg.Copy`, `search_path` для каждого соединения, пул теста и его Cleanup |
| 66–71 | `*sql.DB` поверх пула pgx; `bozor.NewProvider` из корневого пакета передаёт встроенные миграции goose |
| 72–79 | `Up` применяет миграции, simple protocol выполняет много команд из `SeedSQL`; возвращается пул |

Схема — именованная группа таблиц в базе. `search_path` определяет, в какой группе искать имя `products`.
`RuntimeParams` задаёт настройку каждому новому соединению; мы не полагаемся на случайный `SET` в одном соединении.
Имя схемы нельзя передать как SQL-идентификатор через `$1`. Здесь имя получается из внутреннего значения времени, а не из текста клиента.

`t.Cleanup` работает после теста; `defer` сработал бы при возврате из `New`. Cleanup выполняются в обратном порядке: сначала закрывается пул теста, затем удаляется схема.
`db.Close` закрывает обёртку, но не пул pgx. `go:embed` в `migrate.go` включил миграции и seed в бинарник.

| Тест A | Тест B |
|---|---|
| `search_path = test_A` | `search_path = test_B` |
| `test_A.products`, `test_A.orders` | `test_B.products`, `test_B.orders` |
| в конце удаляется только `test_A` | `test_B` продолжает работать |

Имена на схеме сокращены; в коде это `test_<UnixNano>`.

## Глубже (необязательно): защита и границы измерений

- `CHECK (stock >= 0)` — дополнительная защита базы от ошибки приложения. Ноль строк после guard не прерывает транзакцию; ошибка CHECK прерывает.
- Rollback не возвращает identity sequence назад. После отменённого заказа может остаться пропуск ID; непрерывность ID не гарантируется.
- `go test` может кэшировать успех. Состояние базы не входит в ключ кэша; для настоящей интеграционной проверки используйте `-count=1` или `-count=5`.
- `NewProvider` этого урока не использует общий advisory lock: миграции схем независимы. Параллельные миграции развёртывания в одной общей схеме — другая задача, GB-8.06.
- В README API-тесты с блокировкой/без неё занимали 6.1/1.1 s: примерно 5.55 раза. Это **цитируемое** измерение подготовки к видео; для этой страницы оно не повторялось.
- Результат `go test -race` тоже взят из журнала подготовки: проверка прошла в Docker с gcc. Эта страница проверена с `CGO_ENABLED=0`; race-проверка не повторялась.
- `active` не включён в условие продажи этой лаборатории; товары seed активны. `404` для отсутствующего товара даже внутри тела — спецификация курса; другое API может выбрать `422`.
- testcontainers-go может запускать Postgres из теста. Курс использует существующую настройку Compose; затем тот же подход будет в CI.

**3.** Почему нельзя заменить `t.Cleanup` на `defer pool.Close()` внутри `pgtest.New`?

<details>
<summary>Ответ</summary>

`defer` закроет пул при возврате из `New`. Тест ещё не начал работу. `Cleanup` выполняется после теста.

</details>

**4.** GB-5.07: изменяет ли базу `Rollback` после успешного `Commit`?

<details>
<summary>Ответ</summary>

Нет. Транзакция завершена; pgx возвращает `ErrTxClosed`. Поэтому заранее установленный защитный `defer tx.Rollback(ctx)` безопасен.

</details>

```go
func (s *Store) Order(ctx context.Context, id int64) (Order, error) {
	o := Order{ID: id, Items: []OrderItem{}}
	err := s.pool.QueryRow(ctx,
		"SELECT customer, status FROM orders WHERE id = $1", id).Scan(&o.Customer, &o.Status)
	if errors.Is(err, pgx.ErrNoRows) {
		return Order{}, fmt.Errorf("buyurtma %d: %w", id, ErrOrderNotFound)
	}
	if err != nil {
		return Order{}, err
	}
	rows, err := s.pool.Query(ctx,
		"SELECT product_id, quantity, unit_price FROM order_items WHERE order_id = $1 ORDER BY id", id)
	if err != nil {
		return Order{}, err
	}
	defer rows.Close()
	for rows.Next() {
		var it OrderItem
		if err := rows.Scan(&it.ProductID, &it.Quantity, &it.UnitPrice); err != nil {
			return Order{}, err
		}
		o.Items = append(o.Items, it)
		o.Total += it.UnitPrice * int64(it.Quantity)
	}
	if err := rows.Err(); err != nil {
		return Order{}, err
	}
	return o, nil
}
```

Первый запрос оборачивает `ErrOrderNotFound` через `%w`. Второй читает позиции и считает сумму по цене продажи.

```go
func (a *api) getOrder(w http.ResponseWriter, r *http.Request) {

	o, err := a.st.Order(r.Context(), id)
	if err != nil {
		writeStoreError(w, err)
		return
	}
	writeJSON(w, http.StatusOK, o)
}
```
