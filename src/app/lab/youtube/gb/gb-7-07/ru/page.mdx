## Что вы узнаете

Каждую ночь bozor импортирует каталог из 200 000 строк в Postgres. Сколько строк останется, если нажать Ctrl+C посередине, и как это проверить?

**Одна идея:** Ctrl+C отменяет один контекст; читатель, воркеры и SQL реагируют на этот сигнал. Каждая партия — одна транзакция: счётчик растёт после успешного Commit.

После урока вы сможете:

- записать большой файл с N воркерами через `cmd/import`;
- проследить распространение Ctrl+C и первой ошибки по конвейеру;
- проверить отчёт в базе и повторить импорт;
- проверить остановку тестами и добавить срок обработки партии.

| Термин | Простой смысл | Английский термин |
|---|---|---|
| `signal.NotifyContext` | превращает сигнал процесса в отмену контекста | signal.NotifyContext |
| конвейер с отменой | каждый этап проверяет отмену, владелец ждёт завершения всех этапов | cancellable pipeline |
| граница партии | 500 строк в одной транзакции; счётчик меняется после результата | batch boundary |

## Спецификация и партия

Команда: `go run ./cmd/import [-workers 4] katta.txt`. Квадратные скобки обозначают необязательный аргумент; вводить их не нужно.

| Часть | Правило |
|---|---|
| Вход | `nom;narx;qoldiq`; цена в сумах, `Price int64` в тийинах |
| Ключ | `products.name` UNIQUE; ID назначает база |
| Партия | `BatchSize = 500`; последняя может быть меньше |
| Конкурентная работа | один читатель и N постоянных воркеров |
| Ctrl+C | воркер, заметивший отмену, не начинает новую партию |
| Повреждённая строка | первая ошибка отменяет остальную работу; предыдущие commit сохраняются |
| Счётчик | `Rows`: добавленные **и обновлённые** строки успешных партий |

В `Product` поле `Name` — название, `Price` — цена, `Stock` — остаток. `olma;12000;40` → `Name: "olma", Price: 1200000, Stock: 40`. Пустые строки и строки с `#` пропускаются. `product.go` проверяет: три поля, непустое имя UTF-8, цену 1…10 000 000 сумов, неотрицательный остаток.

Весь файл не объединён одной транзакцией. Для `Rows = count(*)` таблица должна изначально быть пустой, а имена в файле — уникальными. Других писателей быть не должно; результаты Commit должны быть известны.

## Как Ctrl+C превращается в контекст

При Ctrl+C терминал отправляет SIGINT группе процессов переднего плана. В Unix `os.Interrupt` обозначает этот сигнал. `signal.NotifyContext` превращает его в **отмену контекста** вместо обычного завершения ([документация](https://pkg.go.dev/os/signal#NotifyContext)). Полная функция `main` из `cmd/import/main.go`:

```go
func main() {
	workers := flag.Int("workers", 4, "bir vaqtda nechta partiya yoziladi")
	flag.Parse()
	if err := run(flag.Arg(0), *workers); err != nil {
		fmt.Fprintln(os.Stderr, "import:", err)
		os.Exit(1)
	}
}
```

`workers` — указатель `*int`, возвращённый `flag.Int`: задаются имя, значение по умолчанию 4 и справка. `Parse` читает `os.Args`; `Arg(0)` — имя файла после флагов, `*workers` — значение по указателю. Если `run` вернул ошибку, `Fprintln` пишет её с `import:` в `os.Stderr`; `os.Exit(1)` завершает процесс с кодом ошибки. Полностью `flag` разбирается в [GB-8.01](/lab/youtube/gb/gb-8-01/ru).

Три строки в начале `run`:

```go
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
	defer stop()
	context.AfterFunc(ctx, stop) // birinchi Ctrl+C'dan keyin ushlash oʻchadi: ikkinchisi dasturni darhol toʻxtatadi
```

Первая строка возвращает `ctx` и функцию `stop`, снимающую перехват сигнала. `defer stop()` освобождает ресурсы при выходе. `context.AfterFunc(ctx, stop)` вызывает `stop` в отдельной горутине после отмены. После её выполнения следующий Ctrl+C снова завершает процесс обычным способом.

| Событие | Состояние |
|---|---|
| Импорт начался | `ctx.Done()` открыт |
| Пришёл SIGINT | `ctx.Done()` закрыт, `ctx.Err()` — `context.Canceled` |
| Этапы отреагировали | читатель и воркеры вернулись |
| `g.Wait()` завершился | печатается окончательный отчёт |

`run` открывает файл через `os.Open`, создаёт пул через `pgxpool.New` и закрывает оба через `defer`. `importer.NewPG(pool)` возвращает настоящее хранилище. Фрагмент с отчётом:

```go
	start := time.Now()
	st, err := importer.Run(ctx, f, importer.NewPG(pool), importer.Config{Workers: workers})
	fmt.Printf("%v · vaqt: %v\n", st, time.Since(start).Round(time.Millisecond))
	if errors.Is(err, context.Canceled) { // birinchi xato bekor qilish boʻlsa, uni Ctrl+C qilgan
		return errors.New("toʻxtatildi (Ctrl+C)")
	}
	return err
```

`start` хранит начальное время; `Since` даёт прошедшее время, `Round` округляет до миллисекунд. `%v` вызывает `Stats.String()`. Отчёт печатается и при ошибке. Если `errors.Is` находит отмену, возвращается `toʻxtatildi (Ctrl+C)` — «остановлено». Для кода выхода 1 `go run` печатает `exit status 1`.

## Один читатель, N воркеров и один владелец

**Конвейер с отменой**: `read` читает и проверяет, `work` записывает; `Run` владеет ими.

```text
katta.txt -> read -> batches (500) -> work x N -> Saver
              |                         |
              +------- gctx ------------+
                         |
                      g.Wait()
```

`Saver` — интерфейс с методом `SaveBatch(ctx, rows)`. В тесте используется подделка, при запуске — `PG`. `Batch.N` — номер партии, `Batch.Rows` — слайс товаров. Полный `internal/importer/importer.go`:

```go filename="internal/importer/importer.go" showLineNumbers
// Package importer — katta katalog faylini bazaga yozadigan bosqichlar (GB-7.07, 7-modul nazorat nuqtasi).
//
//	fayl → read (1 goroutine) → batches channel → work (Workers ta goroutine) → Saver (Postgres)
//
// read qatorlarni oʻqiydi, tekshiradi va BatchSize'lik partiyalarga yigʻadi. Har work goroutine partiyani oladi
// va Saver'ga beradi: Postgres'da bitta partiya = bitta transaction (pg.go), yoki toʻliq yoziladi, yoki umuman.
// Hammasi bitta errgroup'da (GB-7.04): birinchi xato (buzuq qator, baza xatosi) yoki tashqi ctx'ning bekor
// boʻlishi (Ctrl+C) qolgan hamma goroutine'ni toʻxtatadi, Run esa ular tugagandan keyingina qaytadi.
package importer

import (
	"bufio"
	"context"
	"errors"
	"fmt"
	"io"
	"strings"
	"sync/atomic"
	"time"

	"golang.org/x/sync/errgroup"
)

// BatchSize — bitta partiyadagi qatorlar soni (bitta transaction).
const BatchSize = 500

// Batch — fayldagi ketma-ket BatchSize ta qator. N — partiya raqami, 1 dan.
type Batch struct {
	N    int
	Rows []Product
}

// Saver partiyani bazaga yozadi: yoki hammasini, yoki hech birini (xato qaytaradi).
// Haqiqiysi — PG (pg.go); testlarda soxtasi (vaqt va xatoni test boshqaradi).
type Saver interface {
	SaveBatch(ctx context.Context, rows []Product) error
}

// Config — import sozlamalari.
type Config struct {
	Workers int // bir vaqtda nechta partiya yoziladi (kamida 1)

	// BatchTimeout — bitta partiyaga beriladigan eng koʻp vaqt; 0 — cheklovsiz.
	// VAZIFA (TASK.md): hozir ishlatilmaydi.
	BatchTimeout time.Duration
}

// Stats — import hisobi. Uni Workers ta goroutine bir vaqtda oshiradi, shuning uchun atomic (GB-7.05).
// Rows — commit boʻlgan partiyalardagi qatorlar (qoʻshilgan yoki upsert bilan yangilangan); faylda nomlar
// takrorlanmasa va jadval boʻsh boʻlsa, import tugagach Rows = SELECT count(*). Rolled* — SaveBatch xato qaytargan
// partiyalar (Begin'ning xatosi ham shu yerda: unda hech narsa yozilmagan). Commit javobi tarmoqda yoʻqolsa,
// partiya bazada boʻlsa ham Rolled'ga tushadi: bu holatni upsert qayta ishga tushirish bilan tuzatadi.
type Stats struct {
	Rows, Batches             atomic.Int64 // commit boʻlgan qatorlar va partiyalar
	RolledRows, RolledBatches atomic.Int64 // xato bilan tugagan (rollback) qatorlar va partiyalar
}

func (s *Stats) String() string {
	return fmt.Sprintf("yozildi: %d qator (%d partiya) · rollback: %d qator (%d partiya)",
		s.Rows.Load(), s.Batches.Load(), s.RolledRows.Load(), s.RolledBatches.Load())
}

// ErrBadWorkers — Workers 1 dan kichik: hech kim partiya olmasdi, read esa abadiy kutardi.
var ErrBadWorkers = errors.New("workers kamida 1 boʻlishi kerak")

// Run r'dagi katalogni s'ga cfg.Workers ta goroutine bilan yozadi. Birinchi xatoni qaytaradi; ctx bekor
// qilinsa (Ctrl+C), ctx xatosini. Qaytganda hech bir goroutine ishlamayotgan boʻladi, Stats esa yakuniy.
func Run(ctx context.Context, r io.Reader, s Saver, cfg Config) (*Stats, error) {
	st := &Stats{}
	if cfg.Workers < 1 {
		return st, ErrBadWorkers
	}
	batches := make(chan Batch)
	g, gctx := errgroup.WithContext(ctx)
	g.Go(func() error {
		defer close(batches)
		return read(gctx, r, batches)
	})
	for range cfg.Workers {
		g.Go(func() error {
			return work(gctx, s, batches, st, cfg.BatchTimeout)
		})
	}
	return st, g.Wait()
}

// read qatorlarni oʻqiydi va partiyalarni out'ga yuboradi. Buzuq qatorda raqami bilan xato qaytaradi.
// Boʻsh qatorlar va # bilan boshlangan izohlar tashlab oʻtiladi (GB-3.01).
func read(ctx context.Context, r io.Reader, out chan<- Batch) error {
	sc := bufio.NewScanner(r)
	b := Batch{N: 1}
	line := 0
	for sc.Scan() {
		line++
		text := strings.TrimSpace(sc.Text())
		if text == "" || strings.HasPrefix(text, "#") {
			continue
		}
		p, err := parseLine(text)
		if err != nil {
			return fmt.Errorf("%d-qator: %w", line, err)
		}
		b.Rows = append(b.Rows, p)
		if len(b.Rows) == BatchSize {
			if err := send(ctx, out, b); err != nil {
				return err
			}
			b = Batch{N: b.N + 1}
		}
	}
	if err := sc.Err(); err != nil {
		return fmt.Errorf("%d-qator: %w", line+1, err)
	}
	if len(b.Rows) > 0 {
		return send(ctx, out, b)
	}
	return nil
}

// send partiyani yuboradi yoki ctx bekor boʻlsa, kutmasdan qaytadi (GB-7.03).
func send(ctx context.Context, out chan<- Batch, b Batch) error {
	select {
	case out <- b:
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}

// work partiyalarni in channel'i yopilguncha oladi va s'ga yozadi.
// VAZIFA (TASK.md): timeout > 0 boʻlsa, har partiya shu vaqtdan koʻp davom etmasin.
func work(ctx context.Context, s Saver, in <-chan Batch, st *Stats, timeout time.Duration) error {
	for b := range in {
		if ctx.Err() != nil {
			return ctx.Err() // bekor qilingan: yangi partiya boshlanmaydi
		}
		if err := s.SaveBatch(ctx, b.Rows); err != nil {
			st.RolledRows.Add(int64(len(b.Rows)))
			st.RolledBatches.Add(1)
			return fmt.Errorf("partiya %d: %w", b.N, err)
		}
		st.Rows.Add(int64(len(b.Rows)))
		st.Batches.Add(1)
	}
	return nil
}
```

| Строки | Что происходит |
|---|---|
| 1–22 | Комментарии, пакет и импорты: Scanner, context, ошибки, форматирование, Reader, строки, atomic, время, errgroup. |
| 24–39 | Предел 500, `Batch` с номером и слайсом, интерфейс `Saver`. |
| 41–48 | `Workers` задаёт число воркеров; `BatchTimeout` пока оставлен для задания. |
| 50–65 | Четыре `atomic.Int64`; `Add` изменяет, `Load` читает; `String` формирует отчёт. |
| 67–75 | `ErrBadWorkers`; `st := &Stats{}` создаёт нулевые счётчики; N &lt; 1 сразу даёт ошибку. |
| 76–87 | Небуферизированный канал, `WithContext`, один читатель, N воркеров, затем `g.Wait()`. |
| 89–110 | Scanner проверяет строки; `line` — физический номер; после 500 строк отправляет партию и начинает новый слайс. |
| 111–118 | Оборачивается ошибка Scanner; отправляется неполная партия; при успехе возвращается `nil`. |
| 120–128 | `select`: воркер принимает партию либо отмена прекращает ожидание. |
| 130–146 | Работа до закрытия канала; проверка ctx; счётчик изменяется после результата сохранения. |

`chan<- Batch` только отправляет, `<-chan Batch` только принимает. `for range cfg.Workers` запускает N горутин. `defer close(batches)` находится только у читателя-отправителя: закрытие завершает `range` воркеров.

`b = Batch{N: b.N + 1}` начинает новый слайс. Отправленный слайс не перезаписывается следующей партией. `%w` сохраняет исходную ошибку, `%d` выводит номер.

Если обе ветки `select` готовы, выбирается одна: у отмены нет приоритета. Поэтому воркер ещё раз проверяет `ctx.Err()`. Все горутины не замирают одновременно.

`WithContext` отменяет `gctx` при первой ошибке. `g.Wait()` ждёт **всех** и возвращает первую зарегистрированную ошибку ([errgroup](https://pkg.go.dev/golang.org/x/sync/errgroup#WithContext)). `SetLimit` не нужен: число активных воркеров уже ограничено N. Воркеры безопасно изменяют общие счётчики через `atomic`.

## Партия = транзакция, счётчик после результата

Если независимо записывать 500 строк, Ctrl+C оставит половину партии. **Граница партии** объединяет их одной транзакцией. Полный `internal/importer/pg.go`:

```go filename="internal/importer/pg.go" showLineNumbers
package importer

import (
	"context"
	"time"

	"github.com/jackc/pgx/v5/pgxpool"
)

// PG — Saver: partiyani Postgres'ga bitta transaction'da yozadi (GB-5.07).
type PG struct {
	pool *pgxpool.Pool
}

// NewPG pool ustidagi Saver qaytaradi. Pool bir vaqtda koʻp goroutine uchun xavfsiz (GB-5.05).
func NewPG(pool *pgxpool.Pool) *PG {
	return &PG{pool: pool}
}

// upsert: shu nomli mahsulot yoʻq boʻlsa qoʻshadi, bor boʻlsa narxi va qoldigʻini yangilaydi.
// excluded — qoʻshilmoqchi boʻlgan (UNIQUE'ga urilgan) qator. Shuning uchun importni qayta ishga tushirish xavfsiz.
// Eslatma: qator yangilansa ham identity ketma-ketligi bitta qiymatni sarflaydi (ID'larda boʻshliq boʻladi).
const upsert = `
INSERT INTO products (name, price, stock) VALUES ($1, $2, $3)
ON CONFLICT (name) DO UPDATE SET price = excluded.price, stock = excluded.stock`

// endTimeout — Commit yoki Rollback javobini kutishning yuqori chegarasi (baza yoki tarmoq javob bermay qolsa).
const endTimeout = 5 * time.Second

// SaveBatch rows'ni bitta transaction'da yozadi. ctx bekor boʻlsa (Ctrl+C yoki BatchTimeout), Exec toʻxtaydi va
// transaction rollback boʻladi. Commit va Rollback esa alohida end ctx bilan: context.WithoutCancel ctx'ning bekor
// qilinishini (va muddatini) olib tashlaydi, WithTimeout oʻz chegarasini qoʻyadi. Natija: Exec'lari tugagan
// partiyaning Commit'i Ctrl+C'dan yarmida uzilmaydi, lekin abadiy ham kutmaydi; partiya yo toʻliq, yo yoʻq.
func (s *PG) SaveBatch(ctx context.Context, rows []Product) error {
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return err
	}
	end, cancel := context.WithTimeout(context.WithoutCancel(ctx), endTimeout)
	defer cancel()
	defer tx.Rollback(end) // Commit'dan keyin hech narsa qilmaydi
	for _, p := range rows {
		if _, err := tx.Exec(ctx, upsert, p.Name, p.Price, p.Stock); err != nil {
			return err
		}
	}
	return tx.Commit(end)
}
```

| Строки | Что происходит |
|---|---|
| 1–8 | Пакет `importer`; импорты context, времени и pgxpool. |
| 10–18 | `PG` хранит указатель на пул; `NewPG` возвращает `&PG{pool: pool}`. |
| 20–25 | SQL `upsert`; `$1`, `$2`, `$3` — аргументы имени, цены и остатка. |
| 27–28 | `endTimeout` — 5 секунд. |
| 30–38 | `SaveBatch` начинает транзакцию; ошибка Begin сразу возвращается. |
| 39–41 | `end` и `cancel`; при выходе сначала Rollback, затем cancel. |
| 42–46 | `_` отбрасывает индекс; для каждого `p` вызывается `Exec(ctx, …)`; ошибка запускает возврат и Rollback. |
| 47–48 | Возвращается результат `Commit(end)`. |

Rollback после успешного Commit не отменяет запись: он возвращает `ErrTxClosed`, который здесь игнорируется ([pgx Tx](https://pkg.go.dev/github.com/jackc/pgx/v5#Tx)).

`ctx` останавливает работу; `end` завершает транзакцию. **`context.WithoutCancel`** убирает отмену и срок родителя; `WithTimeout` задаёт новую границу ([документация](https://pkg.go.dev/context#WithoutCancel)).

Таймер запускается **после Begin, до Exec**. Commit и Rollback разделяют оставшееся время. При начале Commit новые пять секунд не выдаются.

| Когда пришёл Ctrl+C | Результат |
|---|---|
| Во время `Exec(ctx, …)` | обычно ошибка и rollback; счётчик успеха не растёт |
| После всех Exec, перед Commit | Ctrl+C не отменяет `end`; попытка Commit продолжается |
| После успешного Commit | увеличиваются `Rows` и `Batches` |

**Предскажите:** последний Exec завершился; перед Commit пришёл Ctrl+C. База исправна, времени `end` достаточно. **A)** полный commit · **B)** обязательный rollback · **C)** половина партии.

<details>
<summary>Ответ</summary>

**A.** Ctrl+C не отменяет контекст Commit. B путает `ctx` и `end`; C забывает целостность транзакции. Это не гарантия успеха при сбое сети или базы.

</details>

Вспомогательный термин — **upsert**: INSERT, если имени ещё нет; UPDATE при `ON CONFLICT (name)`. `excluded` — предлагаемая новая строка ([PostgreSQL](https://www.postgresql.org/docs/18/sql-insert.html#SQL-ON-CONFLICT)). Повторный импорт обновляет цену и остаток существующего товара.

## Проверяем остановку тестом

Пузырь `synctest.Test` управляет временем. `slowSaver` — поддельное хранилище, ожидающее `delay`; `catalog(t, 10_000)` создаёт 10 000 строк в памяти. Два фрагмента `importer_test.go`:

```go
type slowSaver struct {
	delay time.Duration
}

func (s slowSaver) SaveBatch(ctx context.Context, rows []Product) error {
	select {
	case <-time.After(s.delay):
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}
```

```go
func TestCancel(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		ctx, cancel := context.WithCancel(context.Background())
		go func() {
			time.Sleep(25 * time.Millisecond)
			cancel() // Ctrl+C
		}()
		st, err := Run(ctx, catalog(t, 10_000), slowSaver{10 * time.Millisecond}, Config{Workers: 4})
		if !errors.Is(err, context.Canceled) {
			t.Fatalf("err = %v, kutilgan context.Canceled", err)
		}
		if st.Batches.Load() != 8 || st.RolledBatches.Load() != 4 {
			t.Errorf("%v; kutilgan: 8 partiya yozilgan, 4 tasi rollback", st)
		}
	})
}
```

`delay` — время партии. Готов `time.After` — успех; готов `ctx.Done()` — ошибка контекста. Тест создаёт ctx через `WithCancel`. Отдельная горутина ждёт 25 ms по искусственным часам и вызывает cancel. `Run` ждёт всех; `errors.Is` проверяет причину, `.Load()` — оба счётчика.

|---|---|---|
| 10 ms | 4 | 0 |
| 20 ms | 8 | 0 |
| 25 ms, cancel | 8 | 4 |

Числа 8 и 4 описывают условия подделки, а не скорость настоящего Postgres. Если в пузыре остаётся заблокированная незавершённая горутина, synctest проваливает тест.

## Глубже (необязательно): границы счётчиков и отмены

- `Rolled*` фактически считает партии, для которых `SaveBatch` вернул ошибку. При ошибке Begin транзакция могла ещё не начаться.
- Если сервер выполнил Commit, но ответ потерялся в сети, клиент не знает результата точно. Код добавит партию в `Rolled*`; равенство с базой не гарантировано. Повторный импорт с upsert восстанавливает итоговое состояние товаров.
- `Scanner.Scan()` для обычного файла не принимает контекст. Отмена замечается в следующем `send` или при проверке воркером. Для произвольного бесконечно блокирующего `io.Reader` этого кода недостаточно.
- Срок `end` для Commit/Rollback отделён от рабочего ctx. `BatchTimeout` не равен строгому общему сроку настоящего вызова Postgres: завершение может продолжаться отдельно.

Целостность транзакции и знание результата клиентом — разные вопросы. Первая исключает половинные партии; на второе влияет сбой сети.

## Частые ошибки

**1. «Если воркеры вернулись, читатель остановится сам».** Вместо `send` в `read` записана обычная отправка. Фрагмент `_video/stages/importer-xato.go`:

```go
		b.Rows = append(b.Rows, p)
		if len(b.Rows) == BatchSize {
			out <- b // XATO VERSIYA: ctx bekor boʻlsa ham kutadi (select yoʻq)
			b = Batch{N: b.N + 1}
		}
```

После возврата воркеров некому принять `out <- b`. Читатель ждёт отправки, а `g.Wait()` ждёт читателя.

**Предскажите:** что произойдёт с `TestCancel`? **A)** 8/4 и PASS · **B)** synctest ждёт бесконечно · **C)** FAIL с deadlock.

<details>
<summary>Ответ</summary>

**C.** В пузыре нечему пробудить оставшуюся работу. A предполагает отправку с обработкой отмены; B путает зависание обычного CLI с проверкой synctest.

</details>

Ошибочную копию проверили во временной папке: `go test -run 'TestCancel$' ./internal/importer`. `$` обозначает конец имени теста. Ниже **точные фрагменты собственного повторного запуска**, а не полный стек:

```text
--- FAIL: TestCancel (0.00s)
panic: deadlock: all goroutines in bubble are blocked [recovered, repanicked]
goroutine 8 [sync.WaitGroup.Wait (durable), synctest bubble 1]:
goroutine 10 [chan send (durable), synctest bubble 1]:
```

`all goroutines in bubble are blocked` — «все горутины в пузыре заблокированы». `sync.WaitGroup.Wait` — ожидание errgroup; `chan send` — отправка читателя. Полный стек указал `importer.go:107` ошибочного файла. Номера горутин отличаются от видео. В настоящем CLI эта ошибка не даёт программе напечатать отчёт и завершиться после Ctrl+C.

Исправление: верните `send(ctx, out, b)`. В полном файле он через `select` ждёт также `ctx.Done()`. В исправленной копии:

```console
$ go test -run 'TestCancel$' ./internal/importer
ok  	github.com/abdurahmon27/bozor/internal/importer	0.007s
```

**2. «Каждый rollback в отчёте подтверждён».** `Rolled*` считает партии с ошибкой. Потерю ответа Commit разобрали в разделе «Глубже». Читайте отчёт с этим ограничением; при необходимости проверяйте базу и повторяйте импорт с upsert.

**3. Откладывать cancel до завершения воркера.** `defer cancel()` внутри `for` выполнится при возврате всего `work`. Вызывайте cancel после партии либо вынесите работу в `save`. `WithTimeout(ctx, 0)` означает уже истёкший срок, а не отсутствие ограничения.

## Проверьте себя

**1.** Как Ctrl+C доходит до каждой горутины?

<details>
<summary>Ответ</summary>

NotifyContext отменяет ctx; отменяется и `gctx`; send, воркеры и Exec проверяют его. Cancel сам не ждёт их: ждёт `g.Wait()`.

</details>

**2.** Почему в проверке новой таблицы «записано» совпадает с числом строк базы?

<details>
<summary>Ответ</summary>

Партия — транзакция; счётчик растёт после успешного Commit. Таблица пуста, имена уникальны, нет других писателей и неопределённых Commit. При повторе Rows считает и обновления.

</details>

**3.** Из GB-7.04: что нужно, чтобы первая ошибка остановила остальных?

<details>
<summary>Ответ</summary>

`errgroup.WithContext`, передача `gctx` в работу и реакция работы на отмену. Обычного `errgroup.Group` или неиспользуемого контекста недостаточно.

</details>

**4.** В пустую таблицу дважды полностью импортировали 2000 уникальных имён. Чему равны вторые `Rows` и `count(*)`? **A)** 2000/2000 · **B)** 4000/4000 · **C)** 0/2000.

<details>
<summary>Ответ</summary>

**A.** Второй импорт обновил 2000 строк. B забывает upsert, C — учёт обновлений.

</details>

<summary>Ответ</summary>

Замените `s.SaveBatch(ctx, b.Rows)` в `work` на `save(ctx, s, b.Rows, timeout)`. Помощник из `solution/internal/importer/importer.go`:

```go
func save(ctx context.Context, s Saver, rows []Product, timeout time.Duration) error {
	if timeout > 0 {
		var cancel context.CancelFunc
		ctx, cancel = context.WithTimeout(ctx, timeout)
		defer cancel()
	}
	return s.SaveBatch(ctx, rows)
}
```

Дочерний контекст создаётся только при `timeout > 0`. `ctx, cancel =` заменяет существующий ctx. `defer cancel()` выполняется при выходе из помощника, не дожидаясь завершения воркера. При нуле нового контекста нет. Оборачивание ошибки и счётчики остаются в `work`.

pgx может обернуть ошибку как `partiya 3: timeout: context deadline exceeded`. Не сравнивайте всю строку: проверяйте `errors.Is`. Помощник не может сам остановить Saver, игнорирующий контекст.
