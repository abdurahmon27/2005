## Nimani oʻrganasiz

bozor har kecha 200 000 qatorli katalogni Postgres'ga import qiladi. Yarmida Ctrl+C bosilsa, bazada nechta qator qoladi va buni qanday tekshirasiz?

**Bitta gʻoya:** Ctrl+C bitta contextni bekor qiladi; oʻquvchi, worker va SQL shu signalga javob beradi. Har partiya bitta transaction: hisob muvaffaqiyatli Commit'dan keyin oshadi.

Darsdan keyin siz:

- `cmd/import` orqali katta faylni N worker bilan yozasiz;
- Ctrl+C va birinchi xatoning butun pipeline boʻylab tarqalishini kuzatasiz;
- hisobotni bazada tekshirasiz va qayta import qilasiz;
- toʻxtashni testlab, partiya muddatini qoʻshasiz.

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| `signal.NotifyContext` | jarayon signalini context bekor qilinishiga aylantiradi | signal.NotifyContext |
| bekor qilinadigan pipeline | har bosqich toʻxtash signalini tekshiradi, egasi hammasini kutadi | cancellable pipeline |

## Spetsifikatsiya va partiya

Buyruq: `go run ./cmd/import [-workers 4] katta.txt`. Kvadrat qavslar ixtiyoriy argumentni bildiradi, terminalga yozilmaydi.

| Qism | Qoida |
|---|---|
| Kirish | `nom;narx;qoldiq`; narx soʻmda, `Price int64` tiyinda |
| Kalit | `products.name` UNIQUE; ID'ni baza beradi |
| Partiya | `BatchSize = 500`; oxirgi partiya kichikroq boʻlishi mumkin |
| Parallel ish | bitta oʻquvchi va N doimiy worker |
| Ctrl+C | bekor qilishni koʻrgan worker yangi partiyani boshlamaydi |
| Buzuq qator | birinchi xato qolgan ishni bekor qiladi; avvalgi commit'lar qoladi |
| Hisob | `Rows`: muvaffaqiyatli partiyalardagi qoʻshilgan **va yangilangan** qatorlar |

`Product`da `Name` — nom, `Price` — narx, `Stock` — qoldiq. `olma;12000;40` → `Name: "olma", Price: 1200000, Stock: 40`. Boʻsh va `#` bilan boshlangan qatorlar tashlab oʻtiladi. `product.go` tekshiradi: uch maydon, boʻsh boʻlmagan UTF-8 nom, 1…10 000 000 soʻm narx, manfiy boʻlmagan qoldiq.

Bu butun fayl uchun bitta transaction emas. `Rows = count(*)` uchun jadval avval boʻsh, fayldagi nomlar takrorsiz boʻlishi kerak. Boshqa yozuvchilar boʻlmasin va Commit natijalari maʼlum boʻlsin.

## Ctrl+C qanday qilib contextga aylanadi

Terminal Ctrl+C'da oldingi plandagi jarayonlar guruhiga SIGINT yuboradi. Unix'da `os.Interrupt` shu signal. `signal.NotifyContext` uni odatiy chiqish oʻrniga **context bekor qilinishi**ga aylantiradi ([rasmiy hujjat](https://pkg.go.dev/os/signal#NotifyContext)). `cmd/import/main.go`dagi `main` toʻliq:

```go
func main() {
	workers := flag.Int("workers", 4, "bir vaqtda nechta partiya yoziladi")
	flag.Parse()
	if err := run(flag.Arg(0), *workers); err != nil {
		fmt.Fprintln(os.Stderr, "import:", err)
		os.Exit(1)
	}
}
```

`workers` — `flag.Int` qaytargan `*int`: nom, standart 4 va yordam matni beriladi. `Parse` `os.Args`ni oʻqiydi; `Arg(0)` bayroqlardan keyingi fayl nomi, `*workers` pointerdagi qiymat. `run` xato qaytarsa, `Fprintln` uni `os.Stderr`ga `import:` bilan yozadi; `os.Exit(1)` xato kodi bilan chiqadi. `flag`ning toʻliq mavzusi [GB-8.01](/lab/youtube/gb/gb-8-01).

`run` boshidagi uch qator:

```go
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
	defer stop()
	context.AfterFunc(ctx, stop) // birinchi Ctrl+C'dan keyin ushlash oʻchadi: ikkinchisi dasturni darhol toʻxtatadi
```

Birinchi qator `ctx` va signalni ushlashni oʻchiradigan `stop`ni qaytaradi. `defer stop()` chiqishda resurslarni boʻshatadi. `context.AfterFunc(ctx, stop)` bekor qilishdan keyin `stop`ni alohida goroutine'da chaqiradi. U bajarilgach keyingi Ctrl+C odatiy chiqishni tiklaydi.

| Hodisa | Holat |
|---|---|
| Import boshlandi | `ctx.Done()` ochiq |
| SIGINT keldi | `ctx.Done()` yopildi, `ctx.Err()` — `context.Canceled` |
| Bosqichlar javob berdi | read va worker'lar qaytdi |
| `g.Wait()` tugadi | yakuniy hisob chop etiladi |

`run` faylni `os.Open` bilan ochadi, `pgxpool.New` bilan pool yaratadi, ikkalasini `defer` bilan yopadi. `importer.NewPG(pool)` haqiqiy saqlovchini beradi. Hisobot parchasi:

```go
	start := time.Now()
	st, err := importer.Run(ctx, f, importer.NewPG(pool), importer.Config{Workers: workers})
	fmt.Printf("%v · vaqt: %v\n", st, time.Since(start).Round(time.Millisecond))
	if errors.Is(err, context.Canceled) { // birinchi xato bekor qilish boʻlsa, uni Ctrl+C qilgan
		return errors.New("toʻxtatildi (Ctrl+C)")
	}
	return err
```

`start` eslab qolingan vaqt; `Since` oʻtgan vaqtni beradi, `Round` millisekundgacha yaxlitlaydi. `%v` `Stats.String()`ni chaqiradi. Xato boʻlsa ham hisob chiqadi. `errors.Is` bekor qilishni topsa, `toʻxtatildi (Ctrl+C)` qaytadi. `go run` xato kodi 1 uchun `exit status 1` chiqaradi.

## Bitta oʻquvchi, N worker va bitta egasi

**Bekor qilinadigan pipeline**: `read` oʻqish va tekshirishga, `work` yozishga masʼul; `Run` ularning egasi.

```text
katta.txt -> read -> batches (500) -> work x N -> Saver
              |                         |
              +------- gctx ------------+
                         |
                      g.Wait()
```

`Saver` — bitta `SaveBatch(ctx, rows)` metodli interface. Testda soxtasi, ishga tushirishda `PG` ishlaydi. `Batch.N` partiya raqami, `Batch.Rows` mahsulotlar slice'i. `internal/importer/importer.go` toʻliq:

```go filename="internal/importer/importer.go" showLineNumbers
// Package importer — katta katalog faylini bazaga yozadigan bosqichlar (GB-7.07, 7-modul nazorat nuqtasi).
//
//	fayl → read (1 goroutine) → batches channel → work (Workers ta goroutine) → Saver (Postgres)
//
// read qatorlarni oʻqiydi, tekshiradi va BatchSize'lik partiyalarga yigʻadi. Har work goroutine partiyani oladi
// va Saver'ga beradi: Postgres'da bitta partiya = bitta transaction (pg.go), yoki toʻliq yoziladi, yoki umuman.
// Hammasi bitta errgroup'da (GB-7.04): birinchi xato (buzuq qator, baza xatosi) yoki tashqi ctx'ning bekor
// boʻlishi (Ctrl+C) qolgan hamma goroutine'ni toʻxtatadi, Run esa ular tugagandan keyingina qaytadi.
package importer

import (
	"bufio"
	"context"
	"errors"
	"fmt"
	"io"
	"strings"
	"sync/atomic"
	"time"

	"golang.org/x/sync/errgroup"
)

// BatchSize — bitta partiyadagi qatorlar soni (bitta transaction).
const BatchSize = 500

// Batch — fayldagi ketma-ket BatchSize ta qator. N — partiya raqami, 1 dan.
type Batch struct {
	N    int
	Rows []Product
}

// Saver partiyani bazaga yozadi: yoki hammasini, yoki hech birini (xato qaytaradi).
// Haqiqiysi — PG (pg.go); testlarda soxtasi (vaqt va xatoni test boshqaradi).
type Saver interface {
	SaveBatch(ctx context.Context, rows []Product) error
}

// Config — import sozlamalari.
type Config struct {
	Workers int // bir vaqtda nechta partiya yoziladi (kamida 1)

	// BatchTimeout — bitta partiyaga beriladigan eng koʻp vaqt; 0 — cheklovsiz.
	// VAZIFA (TASK.md): hozir ishlatilmaydi.
	BatchTimeout time.Duration
}

// Stats — import hisobi. Uni Workers ta goroutine bir vaqtda oshiradi, shuning uchun atomic (GB-7.05).
// Rows — commit boʻlgan partiyalardagi qatorlar (qoʻshilgan yoki upsert bilan yangilangan); faylda nomlar
// takrorlanmasa va jadval boʻsh boʻlsa, import tugagach Rows = SELECT count(*). Rolled* — SaveBatch xato qaytargan
// partiyalar (Begin'ning xatosi ham shu yerda: unda hech narsa yozilmagan). Commit javobi tarmoqda yoʻqolsa,
// partiya bazada boʻlsa ham Rolled'ga tushadi: bu holatni upsert qayta ishga tushirish bilan tuzatadi.
type Stats struct {
	Rows, Batches             atomic.Int64 // commit boʻlgan qatorlar va partiyalar
	RolledRows, RolledBatches atomic.Int64 // xato bilan tugagan (rollback) qatorlar va partiyalar
}

func (s *Stats) String() string {
	return fmt.Sprintf("yozildi: %d qator (%d partiya) · rollback: %d qator (%d partiya)",
		s.Rows.Load(), s.Batches.Load(), s.RolledRows.Load(), s.RolledBatches.Load())
}

// ErrBadWorkers — Workers 1 dan kichik: hech kim partiya olmasdi, read esa abadiy kutardi.
var ErrBadWorkers = errors.New("workers kamida 1 boʻlishi kerak")

// Run r'dagi katalogni s'ga cfg.Workers ta goroutine bilan yozadi. Birinchi xatoni qaytaradi; ctx bekor
// qilinsa (Ctrl+C), ctx xatosini. Qaytganda hech bir goroutine ishlamayotgan boʻladi, Stats esa yakuniy.
func Run(ctx context.Context, r io.Reader, s Saver, cfg Config) (*Stats, error) {
	st := &Stats{}
	if cfg.Workers < 1 {
		return st, ErrBadWorkers
	}
	batches := make(chan Batch)
	g, gctx := errgroup.WithContext(ctx)
	g.Go(func() error {
		defer close(batches)
		return read(gctx, r, batches)
	})
	for range cfg.Workers {
		g.Go(func() error {
			return work(gctx, s, batches, st, cfg.BatchTimeout)
		})
	}
	return st, g.Wait()
}

// read qatorlarni oʻqiydi va partiyalarni out'ga yuboradi. Buzuq qatorda raqami bilan xato qaytaradi.
// Boʻsh qatorlar va # bilan boshlangan izohlar tashlab oʻtiladi (GB-3.01).
func read(ctx context.Context, r io.Reader, out chan<- Batch) error {
	sc := bufio.NewScanner(r)
	b := Batch{N: 1}
	line := 0
	for sc.Scan() {
		line++
		text := strings.TrimSpace(sc.Text())
		if text == "" || strings.HasPrefix(text, "#") {
			continue
		}
		p, err := parseLine(text)
		if err != nil {
			return fmt.Errorf("%d-qator: %w", line, err)
		}
		b.Rows = append(b.Rows, p)
		if len(b.Rows) == BatchSize {
			if err := send(ctx, out, b); err != nil {
				return err
			}
			b = Batch{N: b.N + 1}
		}
	}
	if err := sc.Err(); err != nil {
		return fmt.Errorf("%d-qator: %w", line+1, err)
	}
	if len(b.Rows) > 0 {
		return send(ctx, out, b)
	}
	return nil
}

// send partiyani yuboradi yoki ctx bekor boʻlsa, kutmasdan qaytadi (GB-7.03).
func send(ctx context.Context, out chan<- Batch, b Batch) error {
	select {
	case out <- b:
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}

// work partiyalarni in channel'i yopilguncha oladi va s'ga yozadi.
// VAZIFA (TASK.md): timeout > 0 boʻlsa, har partiya shu vaqtdan koʻp davom etmasin.
func work(ctx context.Context, s Saver, in <-chan Batch, st *Stats, timeout time.Duration) error {
	for b := range in {
		if ctx.Err() != nil {
			return ctx.Err() // bekor qilingan: yangi partiya boshlanmaydi
		}
		if err := s.SaveBatch(ctx, b.Rows); err != nil {
			st.RolledRows.Add(int64(len(b.Rows)))
			st.RolledBatches.Add(1)
			return fmt.Errorf("partiya %d: %w", b.N, err)
		}
		st.Rows.Add(int64(len(b.Rows)))
		st.Batches.Add(1)
	}
	return nil
}
```

| Qator | Nima qiladi |
|---|---|
| 1–22 | Izoh, paket va importlar: Scanner, context, error, format, Reader, matn, atomic, vaqt va errgroup. |
| 24–39 | 500 chegarasi, raqam va slice'li `Batch`, `Saver` interface'i. |
| 41–48 | `Workers` faol worker soni; `BatchTimeout` hozir vazifa. |
| 50–65 | Toʻrtta `atomic.Int64`; `Add` yozadi, `Load` oʻqiydi; `String` hisobotni yasaydi. |
| 67–75 | `ErrBadWorkers`; `st := &Stats{}` nol hisob yaratadi; N &lt; 1 darhol xato. |
| 76–87 | Buffersiz kanal, `WithContext`, bitta oʻquvchi, N worker, soʻng `g.Wait()`. |
| 89–110 | Scanner tekshiradi; `line` haqiqiy qator raqami; 500 boʻlganda yuboradi va yangi slice boshlaydi. |
| 111–118 | Scanner xatosini oʻraydi; qolgan kichik partiyani yuboradi; muvaffaqiyatda `nil`. |
| 120–128 | `select`: worker qabul qiladi yoki bekor qilish kutishni tugatadi. |
| 130–146 | Kanal yopilguncha ishlaydi; ctx'ni tekshiradi; natijadan keyin tegishli hisobni oshiradi. |

`chan<- Batch` faqat yuboradi, `<-chan Batch` faqat qabul qiladi. `for range cfg.Workers` N goroutine ochadi. `defer close(batches)` faqat yuboruvchi oʻquvchida: worker'larning `range`i oxirida tugaydi.

`b = Batch{N: b.N + 1}` yangi slice boshlaydi. Yuborilgan slice keyingi partiya uchun qayta yozilmaydi. `%w` asl xatoni saqlaydi, `%d` raqamni chiqaradi.

`select`da ikkala yoʻl tayyor boʻlsa, bittasi tanlanadi: bekor qilishga ustuvorlik yoʻq. Worker shu sabab `ctx.Err()`ni yana tekshiradi. Barcha goroutine bir onda muzlamaydi.

`WithContext` birinchi xatoda `gctx`ni bekor qiladi. `g.Wait()` **hammasini** kutadi va birinchi qayd etilgan xatoni qaytaradi ([errgroup](https://pkg.go.dev/golang.org/x/sync/errgroup#WithContext)). `SetLimit` shart emas: faol worker soni allaqachon N. Worker'lar umumiy hisobni `atomic` bilan xavfsiz oshiradi.

## Partiya = transaction, hisob natijadan keyin

500 qatorni mustaqil yozsak, Ctrl+C yarim partiya qoldiradi. **Partiya chegarasi** ularni bitta transactionga birlashtiradi. `internal/importer/pg.go` toʻliq:

```go filename="internal/importer/pg.go" showLineNumbers
package importer

import (
	"context"
	"time"

	"github.com/jackc/pgx/v5/pgxpool"
)

// PG — Saver: partiyani Postgres'ga bitta transaction'da yozadi (GB-5.07).
type PG struct {
	pool *pgxpool.Pool
}

// NewPG pool ustidagi Saver qaytaradi. Pool bir vaqtda koʻp goroutine uchun xavfsiz (GB-5.05).
func NewPG(pool *pgxpool.Pool) *PG {
	return &PG{pool: pool}
}

// upsert: shu nomli mahsulot yoʻq boʻlsa qoʻshadi, bor boʻlsa narxi va qoldigʻini yangilaydi.
// excluded — qoʻshilmoqchi boʻlgan (UNIQUE'ga urilgan) qator. Shuning uchun importni qayta ishga tushirish xavfsiz.
// Eslatma: qator yangilansa ham identity ketma-ketligi bitta qiymatni sarflaydi (ID'larda boʻshliq boʻladi).
const upsert = `
INSERT INTO products (name, price, stock) VALUES ($1, $2, $3)
ON CONFLICT (name) DO UPDATE SET price = excluded.price, stock = excluded.stock`

// endTimeout — Commit yoki Rollback javobini kutishning yuqori chegarasi (baza yoki tarmoq javob bermay qolsa).
const endTimeout = 5 * time.Second

// SaveBatch rows'ni bitta transaction'da yozadi. ctx bekor boʻlsa (Ctrl+C yoki BatchTimeout), Exec toʻxtaydi va
// transaction rollback boʻladi. Commit va Rollback esa alohida end ctx bilan: context.WithoutCancel ctx'ning bekor
// qilinishini (va muddatini) olib tashlaydi, WithTimeout oʻz chegarasini qoʻyadi. Natija: Exec'lari tugagan
// partiyaning Commit'i Ctrl+C'dan yarmida uzilmaydi, lekin abadiy ham kutmaydi; partiya yo toʻliq, yo yoʻq.
func (s *PG) SaveBatch(ctx context.Context, rows []Product) error {
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return err
	}
	end, cancel := context.WithTimeout(context.WithoutCancel(ctx), endTimeout)
	defer cancel()
	defer tx.Rollback(end) // Commit'dan keyin hech narsa qilmaydi
	for _, p := range rows {
		if _, err := tx.Exec(ctx, upsert, p.Name, p.Price, p.Stock); err != nil {
			return err
		}
	}
	return tx.Commit(end)
}
```

| Qator | Nima qiladi |
|---|---|
| 1–8 | `importer` paketi; context, vaqt va pgxpool importlari. |
| 10–18 | `PG` pool pointerini saqlaydi; `NewPG` `&PG{pool: pool}` qaytaradi. |
| 20–25 | `upsert` SQL matni; `$1`, `$2`, `$3` — nom, narx, qoldiq argumentlari. |
| 27–28 | `endTimeout` — 5 soniya. |
| 30–38 | `SaveBatch` transaction boshlaydi; Begin xatosi darhol qaytadi. |
| 39–41 | `end` va `cancel`; chiqishda avval Rollback, keyin cancel bajariladi. |
| 42–46 | `_` indeksni tashlaydi; har `p` uchun `Exec(ctx, …)`; xatoda qaytib, Rollback'ni ishga tushiradi. |
| 47–48 | `Commit(end)` natijasini qaytaradi. |

Muvaffaqiyatli Commit'dan keyingi Rollback yozuvni qaytarmaydi: `ErrTxClosed` beradi, bu yerda eʼtiborsiz qoldirilgan ([pgx Tx](https://pkg.go.dev/github.com/jackc/pgx/v5#Tx)).

`ctx` ishni toʻxtatadi; `end` transactionni yakunlaydi. **`context.WithoutCancel`** ota bekor qilinishi va muddatini olib tashlaydi; `WithTimeout` yangi chegara beradi ([hujjat](https://pkg.go.dev/context#WithoutCancel)).

Taymer **Begin'dan keyin, Exec'lardan oldin** boshlanadi. Commit va Rollback shu bitta qolgan vaqtni boʻlishadi. Commit boshlanishida yangi 5 soniya berilmaydi.

| Ctrl+C kelgan payt | Natija |
|---|---|
| `Exec(ctx, …)` davomida | odatda xato va rollback; muvaffaqiyatli hisob oshmaydi |
| Exec'lar tugagach, Commit oldida | Ctrl+C `end`ni bekor qilmaydi; Commit urinishi davom etadi |
| Commit muvaffaqiyatli qaytgach | `Rows` va `Batches` oshadi |

**Bashorat:** oxirgi Exec tugadi; Commit oldida Ctrl+C keldi. Baza sogʻlom, `end` muddati yetarli. **A)** toʻliq commit · **B)** majburiy rollback · **C)** yarim partiya.

<details>
<summary>Javob</summary>

**A.** Ctrl+C Commit contextini bekor qilmaydi. B `ctx` bilan `end`ni aralashtiradi; C transaction yaxlitligini unutadi. Bu tarmoq yoki baza xatosida Commit albatta muvaffaqiyatli degani emas.

</details>

Yordamchi tushuncha — **upsert**: nom yoʻq boʻlsa INSERT, `ON CONFLICT (name)` boʻlsa UPDATE. `excluded` qoʻshilmoqchi boʻlgan qator ([PostgreSQL](https://www.postgresql.org/docs/18/sql-insert.html#SQL-ON-CONFLICT)). Qayta import avvalgi mahsulot narxi va qoldigʻini yangilaydi.

## Toʻxtashni testda isbotlash

`synctest.Test` pufagi vaqtni boshqaradi. `slowSaver` — `delay` davomida kutadigan soxta saqlovchi; `catalog(t, 10_000)` xotirada 10 000 qator yasaydi. `importer_test.go`dan ikki parcha:

```go
type slowSaver struct {
	delay time.Duration
}

func (s slowSaver) SaveBatch(ctx context.Context, rows []Product) error {
	select {
	case <-time.After(s.delay):
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}
```

```go
func TestCancel(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		ctx, cancel := context.WithCancel(context.Background())
		go func() {
			time.Sleep(25 * time.Millisecond)
			cancel() // Ctrl+C
		}()
		st, err := Run(ctx, catalog(t, 10_000), slowSaver{10 * time.Millisecond}, Config{Workers: 4})
		if !errors.Is(err, context.Canceled) {
			t.Fatalf("err = %v, kutilgan context.Canceled", err)
		}
		if st.Batches.Load() != 8 || st.RolledBatches.Load() != 4 {
			t.Errorf("%v; kutilgan: 8 partiya yozilgan, 4 tasi rollback", st)
		}
	})
}
```

`delay` — partiya vaqti. `time.After` tayyor boʻlsa muvaffaqiyat, `ctx.Done()` boʻlsa context xatosi. Test `WithCancel` bilan ctx yaratadi. Alohida goroutine soxta soatda 25 ms kutib, cancel qiladi. `Run` hammasini kutadi; `errors.Is` sababni, `.Load()` ikkala hisobni tekshiradi.

| Soxta vaqt | Jami commit | Jami rollback |
|---|---|---|
| 10 ms | 4 | 0 |
| 20 ms | 8 | 0 |
| 25 ms, cancel | 8 | 4 |

Bu 8 va 4 haqiqiy Postgres tezligi emas: soxta saqlovchi shartlari. Pufakda tugamagan bloklangan goroutine qolsa, synctest testni yiqitadi.

`TestBadLine` yomon qator va keyingi partiya boshlanmasligini tekshiradi. `TestPostgresImport` bazaga 2000 qatorni ikki marta yozadi: son 2000 boʻlib qoladi. `TestPostgresCancel` hisobotni haqiqiy `count(*)` bilan solishtiradi. `pgtest.New(t)` har testga alohida schema yaratib, tugagach oʻchiradi.

**Bashorat:** tanlangan toʻrtta testda **A)** hammasi PASS · **B)** upsert testi UNIQUE bilan yiqiladi · **C)** cancellation testi yarim partiyalarni koʻradi.

## Chuqurroq (ixtiyoriy): hisob va bekor qilish chegaralari

- `Rolled*` aslida `SaveBatch` xato qaytargan partiyalarni sanaydi. Begin xatosida transaction hali boshlanmagan boʻlishi mumkin.
- Server Commit'ni bajarsa-yu, javob tarmoqda yoʻqolsa, mijoz natijani aniq bilmaydi. Bu kod partiyani `Rolled*`ga qoʻshadi; baza bilan tenglik kafolati yoʻq. Upsert bilan qayta import yakuniy mahsulot holatini tiklaydi.
- Oddiy fayldagi `Scanner.Scan()` context olmaydi. Bekor qilish keyingi `send` yoki worker tekshiruvida koʻriladi. Ixtiyoriy, abadiy bloklanadigan `io.Reader` uchun bu kodning oʻzi yetmaydi.
- Commit/Rollback'ning `end` muddati ish ctx'idan ajratilgan. `BatchTimeout` haqiqiy Postgres chaqiruvining qatʼiy umumiy muddatiga teng emas: yakunlash alohida davom etishi mumkin.

Transaction yaxlitligi bilan mijozning natijani bilishi ikki alohida masala. Birinchisi partiyani yarim qoldirmaydi; ikkinchisiga tarmoq xatosi taʼsir qiladi.
