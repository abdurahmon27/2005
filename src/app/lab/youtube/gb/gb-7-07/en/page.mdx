## What you will learn

Every night, bozor imports a catalog of 200,000 lines into Postgres. How many rows remain if you press Ctrl+C halfway through, and how can you check?

**One idea:** Ctrl+C cancels one context; the reader, workers, and SQL respond to that signal. Each batch is one transaction: the counter increases after a successful Commit.

After this lesson, you can:

- write a large file with N workers through `cmd/import`;
- trace Ctrl+C and the first error through the pipeline;
- check the report against the database and repeat the import;
- test shutdown and add a batch deadline.

| Term | Plain meaning | English term |
|---|---|---|
| `signal.NotifyContext` | turns a process signal into context cancellation | signal.NotifyContext |
| cancellable pipeline | every stage checks cancellation; the owner waits for all stages | cancellable pipeline |
| batch boundary | 500 rows in one transaction; counters change after the result | batch boundary |

## Specification and batches

Command: `go run ./cmd/import [-workers 4] katta.txt`. Square brackets mark an optional argument; do not type them.

| Part | Rule |
|---|---|
| Input | `nom;narx;qoldiq`; price in som, `Price int64` in tiyin |
| Key | `products.name` is UNIQUE; the database assigns IDs |
| Batch | `BatchSize = 500`; the final batch may be smaller |
| Concurrency | one reader and N persistent workers |
| Ctrl+C | a worker that observes cancellation does not start another batch |
| Bad line | the first error cancels remaining work; earlier commits remain |
| Counter | `Rows`: inserted **and updated** rows in successful batches |

In `Product`, `Name` is the name, `Price` is the price, and `Stock` is the stock. `olma;12000;40` → `Name: "olma", Price: 1200000, Stock: 40`. Empty lines and lines starting with `#` are skipped. `product.go` checks three fields, a nonempty UTF-8 name, a price of 1…10,000,000 som, and nonnegative stock.

The entire file is not one transaction. For `Rows = count(*)`, the table must start empty and names in the file must be unique. There must be no other writers, and Commit outcomes must be known.

## How Ctrl+C becomes a context

On Ctrl+C, the terminal sends SIGINT to its foreground process group. On Unix, `os.Interrupt` is that signal. `signal.NotifyContext` turns it into **context cancellation** instead of the usual exit ([documentation](https://pkg.go.dev/os/signal#NotifyContext)). Complete `main` function from `cmd/import/main.go`:

```go
func main() {
	workers := flag.Int("workers", 4, "bir vaqtda nechta partiya yoziladi")
	flag.Parse()
	if err := run(flag.Arg(0), *workers); err != nil {
		fmt.Fprintln(os.Stderr, "import:", err)
		os.Exit(1)
	}
}
```

`workers` is the `*int` returned by `flag.Int`: supply the name, default 4, and help text. `Parse` reads `os.Args`; `Arg(0)` is the filename after flags, and `*workers` dereferences the pointer. If `run` returns an error, `Fprintln` writes it with `import:` to `os.Stderr`; `os.Exit(1)` exits with an error code. The full `flag` topic is in [GB-8.01](/lab/youtube/gb/gb-8-01/en).

Three lines at the start of `run`:

```go
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
	defer stop()
	context.AfterFunc(ctx, stop) // birinchi Ctrl+C'dan keyin ushlash oʻchadi: ikkinchisi dasturni darhol toʻxtatadi
```

The first line returns `ctx` and `stop`, which unregisters signal handling. `defer stop()` releases resources on return. `context.AfterFunc(ctx, stop)` calls `stop` in a separate goroutine after cancellation. Once it runs, a subsequent Ctrl+C restores normal exit behavior.

| Event | State |
|---|---|
| Import starts | `ctx.Done()` is open |
| SIGINT arrives | `ctx.Done()` closes; `ctx.Err()` is `context.Canceled` |
| Stages respond | the reader and workers return |
| `g.Wait()` finishes | the final report is printed |

`run` opens the file with `os.Open`, creates a pool with `pgxpool.New`, and closes both through `defer`. `importer.NewPG(pool)` provides the real saver. Reporting excerpt:

```go
	start := time.Now()
	st, err := importer.Run(ctx, f, importer.NewPG(pool), importer.Config{Workers: workers})
	fmt.Printf("%v · vaqt: %v\n", st, time.Since(start).Round(time.Millisecond))
	if errors.Is(err, context.Canceled) { // birinchi xato bekor qilish boʻlsa, uni Ctrl+C qilgan
		return errors.New("toʻxtatildi (Ctrl+C)")
	}
	return err
```

`start` stores the start time; `Since` gives elapsed time, and `Round` rounds to milliseconds. `%v` calls `Stats.String()`. The report appears even on error. If `errors.Is` finds cancellation, it returns `toʻxtatildi (Ctrl+C)`, meaning “stopped.” For exit code 1, `go run` prints `exit status 1`.

## One reader, N workers, and one owner

The **cancellable pipeline**: `read` reads and validates, `work` saves, and `Run` owns them.

```text
katta.txt -> read -> batches (500) -> work x N -> Saver
              |                         |
              +------- gctx ------------+
                         |
                      g.Wait()
```

`Saver` is an interface with one method, `SaveBatch(ctx, rows)`. Tests use a fake; the actual run uses `PG`. `Batch.N` is the batch number; `Batch.Rows` is a product slice. Complete `internal/importer/importer.go`:

```go filename="internal/importer/importer.go" showLineNumbers
// Package importer — katta katalog faylini bazaga yozadigan bosqichlar (GB-7.07, 7-modul nazorat nuqtasi).
//
//	fayl → read (1 goroutine) → batches channel → work (Workers ta goroutine) → Saver (Postgres)
//
// read qatorlarni oʻqiydi, tekshiradi va BatchSize'lik partiyalarga yigʻadi. Har work goroutine partiyani oladi
// va Saver'ga beradi: Postgres'da bitta partiya = bitta transaction (pg.go), yoki toʻliq yoziladi, yoki umuman.
// Hammasi bitta errgroup'da (GB-7.04): birinchi xato (buzuq qator, baza xatosi) yoki tashqi ctx'ning bekor
// boʻlishi (Ctrl+C) qolgan hamma goroutine'ni toʻxtatadi, Run esa ular tugagandan keyingina qaytadi.
package importer

import (
	"bufio"
	"context"
	"errors"
	"fmt"
	"io"
	"strings"
	"sync/atomic"
	"time"

	"golang.org/x/sync/errgroup"
)

// BatchSize — bitta partiyadagi qatorlar soni (bitta transaction).
const BatchSize = 500

// Batch — fayldagi ketma-ket BatchSize ta qator. N — partiya raqami, 1 dan.
type Batch struct {
	N    int
	Rows []Product
}

// Saver partiyani bazaga yozadi: yoki hammasini, yoki hech birini (xato qaytaradi).
// Haqiqiysi — PG (pg.go); testlarda soxtasi (vaqt va xatoni test boshqaradi).
type Saver interface {
	SaveBatch(ctx context.Context, rows []Product) error
}

// Config — import sozlamalari.
type Config struct {
	Workers int // bir vaqtda nechta partiya yoziladi (kamida 1)

	// BatchTimeout — bitta partiyaga beriladigan eng koʻp vaqt; 0 — cheklovsiz.
	// VAZIFA (TASK.md): hozir ishlatilmaydi.
	BatchTimeout time.Duration
}

// Stats — import hisobi. Uni Workers ta goroutine bir vaqtda oshiradi, shuning uchun atomic (GB-7.05).
// Rows — commit boʻlgan partiyalardagi qatorlar (qoʻshilgan yoki upsert bilan yangilangan); faylda nomlar
// takrorlanmasa va jadval boʻsh boʻlsa, import tugagach Rows = SELECT count(*). Rolled* — SaveBatch xato qaytargan
// partiyalar (Begin'ning xatosi ham shu yerda: unda hech narsa yozilmagan). Commit javobi tarmoqda yoʻqolsa,
// partiya bazada boʻlsa ham Rolled'ga tushadi: bu holatni upsert qayta ishga tushirish bilan tuzatadi.
type Stats struct {
	Rows, Batches             atomic.Int64 // commit boʻlgan qatorlar va partiyalar
	RolledRows, RolledBatches atomic.Int64 // xato bilan tugagan (rollback) qatorlar va partiyalar
}

func (s *Stats) String() string {
	return fmt.Sprintf("yozildi: %d qator (%d partiya) · rollback: %d qator (%d partiya)",
		s.Rows.Load(), s.Batches.Load(), s.RolledRows.Load(), s.RolledBatches.Load())
}

// ErrBadWorkers — Workers 1 dan kichik: hech kim partiya olmasdi, read esa abadiy kutardi.
var ErrBadWorkers = errors.New("workers kamida 1 boʻlishi kerak")

// Run r'dagi katalogni s'ga cfg.Workers ta goroutine bilan yozadi. Birinchi xatoni qaytaradi; ctx bekor
// qilinsa (Ctrl+C), ctx xatosini. Qaytganda hech bir goroutine ishlamayotgan boʻladi, Stats esa yakuniy.
func Run(ctx context.Context, r io.Reader, s Saver, cfg Config) (*Stats, error) {
	st := &Stats{}
	if cfg.Workers < 1 {
		return st, ErrBadWorkers
	}
	batches := make(chan Batch)
	g, gctx := errgroup.WithContext(ctx)
	g.Go(func() error {
		defer close(batches)
		return read(gctx, r, batches)
	})
	for range cfg.Workers {
		g.Go(func() error {
			return work(gctx, s, batches, st, cfg.BatchTimeout)
		})
	}
	return st, g.Wait()
}

// read qatorlarni oʻqiydi va partiyalarni out'ga yuboradi. Buzuq qatorda raqami bilan xato qaytaradi.
// Boʻsh qatorlar va # bilan boshlangan izohlar tashlab oʻtiladi (GB-3.01).
func read(ctx context.Context, r io.Reader, out chan<- Batch) error {
	sc := bufio.NewScanner(r)
	b := Batch{N: 1}
	line := 0
	for sc.Scan() {
		line++
		text := strings.TrimSpace(sc.Text())
		if text == "" || strings.HasPrefix(text, "#") {
			continue
		}
		p, err := parseLine(text)
		if err != nil {
			return fmt.Errorf("%d-qator: %w", line, err)
		}
		b.Rows = append(b.Rows, p)
		if len(b.Rows) == BatchSize {
			if err := send(ctx, out, b); err != nil {
				return err
			}
			b = Batch{N: b.N + 1}
		}
	}
	if err := sc.Err(); err != nil {
		return fmt.Errorf("%d-qator: %w", line+1, err)
	}
	if len(b.Rows) > 0 {
		return send(ctx, out, b)
	}
	return nil
}

// send partiyani yuboradi yoki ctx bekor boʻlsa, kutmasdan qaytadi (GB-7.03).
func send(ctx context.Context, out chan<- Batch, b Batch) error {
	select {
	case out <- b:
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}

// work partiyalarni in channel'i yopilguncha oladi va s'ga yozadi.
// VAZIFA (TASK.md): timeout > 0 boʻlsa, har partiya shu vaqtdan koʻp davom etmasin.
func work(ctx context.Context, s Saver, in <-chan Batch, st *Stats, timeout time.Duration) error {
	for b := range in {
		if ctx.Err() != nil {
			return ctx.Err() // bekor qilingan: yangi partiya boshlanmaydi
		}
		if err := s.SaveBatch(ctx, b.Rows); err != nil {
			st.RolledRows.Add(int64(len(b.Rows)))
			st.RolledBatches.Add(1)
			return fmt.Errorf("partiya %d: %w", b.N, err)
		}
		st.Rows.Add(int64(len(b.Rows)))
		st.Batches.Add(1)
	}
	return nil
}
```

| Lines | What happens |
|---|---|
| 1–22 | Comments, package, and imports: Scanner, context, errors, formatting, Reader, strings, atomic, time, and errgroup. |
| 24–39 | The limit 500, `Batch` with a number and slice, and the `Saver` interface. |
| 41–48 | `Workers` sets the worker count; `BatchTimeout` is still the exercise. |
| 50–65 | Four `atomic.Int64` values; `Add` updates, `Load` reads, and `String` formats the report. |
| 67–75 | `ErrBadWorkers`; `st := &Stats{}` creates zero counters; N &lt; 1 returns an error immediately. |
| 76–87 | An unbuffered channel, `WithContext`, one reader, N workers, then `g.Wait()`. |
| 89–110 | Scanner validates lines; `line` counts physical lines; after 500 rows it sends and starts a new slice. |
| 111–118 | Wrap the Scanner error, send a partial final batch, return `nil` on success. |
| 120–128 | `select`: a worker receives the batch, or cancellation ends the wait. |
| 130–146 | Work until the channel closes, check ctx, update counters after the save result. |

`chan<- Batch` only sends; `<-chan Batch` only receives. `for range cfg.Workers` starts N goroutines. Only the sending reader calls `defer close(batches)`: closure ends the workers’ `range` loops.

`b = Batch{N: b.N + 1}` starts a new slice. The next batch does not overwrite the slice already sent. `%w` preserves the original error; `%d` prints the number.

If both `select` cases are ready, one is chosen: cancellation has no priority. That is why the worker checks `ctx.Err()` again. All goroutines do not freeze simultaneously.

`WithContext` cancels `gctx` on the first error. `g.Wait()` waits for **all** functions and returns the first recorded error ([errgroup](https://pkg.go.dev/golang.org/x/sync/errgroup#WithContext)). `SetLimit` is unnecessary: active workers are already bounded by N. Workers safely update shared counters using `atomic`.

## Batch = transaction, counters follow the result

If we write 500 rows independently, Ctrl+C leaves a partial batch. The **batch boundary** puts them into one transaction. Complete `internal/importer/pg.go`:

```go filename="internal/importer/pg.go" showLineNumbers
package importer

import (
	"context"
	"time"

	"github.com/jackc/pgx/v5/pgxpool"
)

// PG — Saver: partiyani Postgres'ga bitta transaction'da yozadi (GB-5.07).
type PG struct {
	pool *pgxpool.Pool
}

// NewPG pool ustidagi Saver qaytaradi. Pool bir vaqtda koʻp goroutine uchun xavfsiz (GB-5.05).
func NewPG(pool *pgxpool.Pool) *PG {
	return &PG{pool: pool}
}

// upsert: shu nomli mahsulot yoʻq boʻlsa qoʻshadi, bor boʻlsa narxi va qoldigʻini yangilaydi.
// excluded — qoʻshilmoqchi boʻlgan (UNIQUE'ga urilgan) qator. Shuning uchun importni qayta ishga tushirish xavfsiz.
// Eslatma: qator yangilansa ham identity ketma-ketligi bitta qiymatni sarflaydi (ID'larda boʻshliq boʻladi).
const upsert = `
INSERT INTO products (name, price, stock) VALUES ($1, $2, $3)
ON CONFLICT (name) DO UPDATE SET price = excluded.price, stock = excluded.stock`

// endTimeout — Commit yoki Rollback javobini kutishning yuqori chegarasi (baza yoki tarmoq javob bermay qolsa).
const endTimeout = 5 * time.Second

// SaveBatch rows'ni bitta transaction'da yozadi. ctx bekor boʻlsa (Ctrl+C yoki BatchTimeout), Exec toʻxtaydi va
// transaction rollback boʻladi. Commit va Rollback esa alohida end ctx bilan: context.WithoutCancel ctx'ning bekor
// qilinishini (va muddatini) olib tashlaydi, WithTimeout oʻz chegarasini qoʻyadi. Natija: Exec'lari tugagan
// partiyaning Commit'i Ctrl+C'dan yarmida uzilmaydi, lekin abadiy ham kutmaydi; partiya yo toʻliq, yo yoʻq.
func (s *PG) SaveBatch(ctx context.Context, rows []Product) error {
	tx, err := s.pool.Begin(ctx)
	if err != nil {
		return err
	}
	end, cancel := context.WithTimeout(context.WithoutCancel(ctx), endTimeout)
	defer cancel()
	defer tx.Rollback(end) // Commit'dan keyin hech narsa qilmaydi
	for _, p := range rows {
		if _, err := tx.Exec(ctx, upsert, p.Name, p.Price, p.Stock); err != nil {
			return err
		}
	}
	return tx.Commit(end)
}
```

| Lines | What happens |
|---|---|
| 1–8 | Package `importer`; imports for context, time, and pgxpool. |
| 10–18 | `PG` stores a pool pointer; `NewPG` returns `&PG{pool: pool}`. |
| 20–25 | The `upsert` SQL string; `$1`, `$2`, `$3` are name, price, and stock arguments. |
| 27–28 | `endTimeout` is 5 seconds. |
| 30–38 | `SaveBatch` begins a transaction; a Begin error returns immediately. |
| 39–41 | `end` and `cancel`; on return, Rollback runs before cancel. |
| 42–46 | `_` discards the index; each `p` gets `Exec(ctx, …)`; an error returns and triggers Rollback. |
| 47–48 | Return the result of `Commit(end)`. |

Rollback after a successful Commit does not undo the write: it returns `ErrTxClosed`, ignored here ([pgx Tx](https://pkg.go.dev/github.com/jackc/pgx/v5#Tx)).

`ctx` stops work; `end` finishes the transaction. **`context.WithoutCancel`** removes the parent’s cancellation and deadline; `WithTimeout` adds a new bound ([documentation](https://pkg.go.dev/context#WithoutCancel)).

The timer starts **after Begin, before the Exec loop**. Commit and Rollback share its remaining time. Commit does not get a fresh five seconds.

| When Ctrl+C arrives | Result |
|---|---|
| During `Exec(ctx, …)` | usually an error and rollback; the success counter does not grow |
| After all Exec calls, before Commit | Ctrl+C does not cancel `end`; the Commit attempt continues |
| After a successful Commit | `Rows` and `Batches` increase |

**Predict:** the last Exec finished; Ctrl+C arrives before Commit. The database is healthy and `end` has enough time left. **A)** a complete commit · **B)** mandatory rollback · **C)** half a batch.

<details>
<summary>Answer</summary>

**A.** Ctrl+C does not cancel the Commit context. B confuses `ctx` with `end`; C ignores transaction atomicity. This does not guarantee success during a network or database failure.

</details>

The helper concept is **upsert**: INSERT if the name is absent, UPDATE on `ON CONFLICT (name)`. `excluded` is the proposed row ([PostgreSQL](https://www.postgresql.org/docs/18/sql-insert.html#SQL-ON-CONFLICT)). A repeated import updates an existing product’s price and stock.

## Prove shutdown in a test

The `synctest.Test` bubble controls time. `slowSaver` is a fake saver that waits for `delay`; `catalog(t, 10_000)` creates 10,000 lines in memory. Two excerpts from `importer_test.go`:

```go
type slowSaver struct {
	delay time.Duration
}

func (s slowSaver) SaveBatch(ctx context.Context, rows []Product) error {
	select {
	case <-time.After(s.delay):
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}
```

```go
func TestCancel(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		ctx, cancel := context.WithCancel(context.Background())
		go func() {
			time.Sleep(25 * time.Millisecond)
			cancel() // Ctrl+C
		}()
		st, err := Run(ctx, catalog(t, 10_000), slowSaver{10 * time.Millisecond}, Config{Workers: 4})
		if !errors.Is(err, context.Canceled) {
			t.Fatalf("err = %v, kutilgan context.Canceled", err)
		}
		if st.Batches.Load() != 8 || st.RolledBatches.Load() != 4 {
			t.Errorf("%v; kutilgan: 8 partiya yozilgan, 4 tasi rollback", st)
		}
	})
}
```

`delay` is the batch duration. A ready `time.After` means success; a ready `ctx.Done()` means a context error. The test creates ctx with `WithCancel`. Another goroutine waits 25 ms on the fake clock, then cancels. `Run` waits for everyone; `errors.Is` checks the cause, and `.Load()` checks both counters.

| Fake time | Total commits | Total rollbacks |
|---|---|---|
| 10 ms | 4 | 0 |
| 20 ms | 8 | 0 |
| 25 ms, cancel | 8 | 4 |

These counts of 8 and 4 describe the fake saver’s conditions, not actual Postgres speed. If a blocked, unfinished goroutine remains in the bubble, synctest fails the test.

`TestBadLine` checks the bad line and prevents later batches from starting. `TestPostgresImport` writes 2,000 rows twice into the database: the count remains 2,000. `TestPostgresCancel` compares the report with an actual `count(*)`. `pgtest.New(t)` creates a separate schema for each test and removes it afterward.

## Going deeper (optional): limits of counters and cancellation

- `Rolled*` actually counts batches for which `SaveBatch` returned an error. With a Begin error, a transaction may never have started.
- If the server commits but its response is lost in transit, the client cannot know the outcome with certainty. This code adds the batch to `Rolled*`; equality with the database is not guaranteed. Repeating the import with upsert restores the final product state.
- `Scanner.Scan()` on the ordinary file does not accept a context. Cancellation is observed at the next `send` or worker check. This code alone cannot handle an arbitrary `io.Reader` that blocks forever.
- The Commit/Rollback `end` deadline is separate from the work ctx. `BatchTimeout` is not a strict total deadline for the real Postgres call: finalization may continue separately.

Transaction atomicity and the client’s knowledge of the result are separate concerns. The former prevents partial batches; a network failure affects the latter.

## Common mistakes

**1. “When the workers return, the reader stops by itself.”** A plain send replaces `send` inside `read`. Excerpt from `_video/stages/importer-xato.go`:

```go
		b.Rows = append(b.Rows, p)
		if len(b.Rows) == BatchSize {
			out <- b // XATO VERSIYA: ctx bekor boʻlsa ham kutadi (select yoʻq)
			b = Batch{N: b.N + 1}
		}
```

After the workers return, nobody receives `out <- b`. The reader waits to send, and `g.Wait()` waits for the reader.

**Predict:** what happens to `TestCancel`? **A)** 8/4 and PASS · **B)** synctest waits forever · **C)** FAIL with deadlock.

<details>
<summary>Answer</summary>

**C.** Nothing inside the bubble can wake the remaining work. A assumes a cancellation-aware send; B confuses an ordinary CLI hang with synctest’s check.

</details>

We tested the broken copy in a temporary folder with `go test -run 'TestCancel$' ./internal/importer`. `$` anchors the end of the test name. These are **exact excerpts from our own rerun**, not the full stack:

```text
--- FAIL: TestCancel (0.00s)
panic: deadlock: all goroutines in bubble are blocked [recovered, repanicked]
goroutine 8 [sync.WaitGroup.Wait (durable), synctest bubble 1]:
goroutine 10 [chan send (durable), synctest bubble 1]:
```

`all goroutines in bubble are blocked` describes the deadlock. `sync.WaitGroup.Wait` is errgroup waiting; `chan send` is the reader sending. The full stack pointed to `importer.go:107` in the broken file. Goroutine numbers differ from the video. In the actual CLI, this bug prevents the program from reporting and exiting after Ctrl+C.

Fix: restore `send(ctx, out, b)`. In the complete file, it also waits on `ctx.Done()` through `select`. In the fixed copy:

```console
$ go test -run 'TestCancel$' ./internal/importer
ok  	github.com/abdurahmon27/bozor/internal/importer	0.007s
```

**2. “Every reported rollback is confirmed.”** `Rolled*` counts batches that returned errors. The lost Commit response is covered in “Going deeper.” Read the report with that limitation; check the database and rerun with upsert if needed.

**3. Delaying cancel until the worker finishes.** `defer cancel()` inside `for` runs when the entire `work` function returns. Cancel after each batch or use a separate `save` function. `WithTimeout(ctx, 0)` is an already expired context, not an unlimited one.

## Check yourself

**1.** How does Ctrl+C reach every goroutine?

<details>
<summary>Answer</summary>

NotifyContext cancels ctx and therefore `gctx`; send, workers, and Exec observe it. Cancel does not wait for them; `g.Wait()` does.

</details>

**2.** Why does “written” match the database count in the new-table test?

<details>
<summary>Answer</summary>

Each batch is a transaction; counters increase after successful Commit. The table is empty, names are unique, and there are no other writers or ambiguous commits. On rerun, Rows also counts updates.

</details>

<details>

```go
func save(ctx context.Context, s Saver, rows []Product, timeout time.Duration) error {
	if timeout > 0 {
		var cancel context.CancelFunc
		ctx, cancel = context.WithTimeout(ctx, timeout)
		defer cancel()
	}
	return s.SaveBatch(ctx, rows)
}
```
