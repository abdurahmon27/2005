## Nimani oʻrganasiz

bozor importeri ikki yetkazib beruvchining narx roʻyxatini ikki goroutine'da oʻqiydi. Mahsulotni umumiy slice'ga bir vaqtda qoʻshmasdan, `main`ga qanday uzatamiz?

**Bitta gʻoya:** **kanal** (channel) qiymat uzatish bilan kutishni birlashtiradi. Bufersiz kanalda yuboruvchi va qabul qiluvchi bir-birini kutadi; `close` esa boshqa qiymat kelmasligini bildiradi.

Dars oxirida siz:

- goroutine natijasini kanal orqali olasiz va `[chan send]` / `[chan receive]` xabarlarini oʻqiysiz;
- `close` va `range` bilan oqimning oxirini bildirasiz;
- bufer kutishni qachongacha kechiktirishini aniqlaysiz;
- `parse → inStock` pipeline'ini ikki yuboruvchi bilan xavfsiz yopasiz.

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| kanal | goroutine'lar orasida qiymat uzatish va kutish vositasi | channel |
| `close` va kanal ustida `range` | boshqa qiymat yoʻqligini bildirish va oqim tugaguncha oʻqish | close and range |
| buffered channel | ichida cheklangan sondagi qiymatlar uchun bufer bor kanal | buffered channel |

Yordamchi tushuncha: **yoʻnalishli channel turi** funksiyaga faqat yuborish yoki faqat qabul qilish imkonini beradi. Bosqichlar kanallar bilan ulangan tuzilma **pipeline** deyiladi.

## Kanal: yuborish va qabul qilish

```go filename="_video/01-uzatish/main.go" showLineNumbers
package main

import "fmt"

func main() {
	counts := make(chan int)
	go func() {
		counts <- 40
	}()
	n := <-counts
	fmt.Println(n)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `package main` | bajariladigan dastur paketi |
| 3 | `import "fmt"` | chiqarish paketini ulaydi |
| 5, 12 | `func main() { … }` | asosiy funksiya va uning chegaralari |
| 6 | `counts := make(chan int)` | faqat `int` tashiydigan yangi bufersiz kanal; `counts` shu kanal qiymatini saqlaydi |
| 7, 9 | `go func() { … }()` | nomsiz funksiyani yangi goroutine'da chaqiradi; oxirgi `()` chaqiruv |
| 8 | `counts <- 40` | kanalga `40` yuboradi; `<-` yuborish operatori |
| 10 | `n := <-counts` | `<-counts` qiymatni qabul qiladi; natija `n`ga yoziladi |
| 11 | `fmt.Println(n)` | olingan sonni chiqaradi |

Boʻsh qatorlar faqat oʻqish uchun. `counts` bu yerda oldingi darsdagi slice emas, `chan int`.

| Voqea | Yuboruvchi | `main` |
|---|---|---|
| `main` oldin yetdi | hali yubormadi | `<-counts`da kutadi |
| yuboruvchi oldin yetdi | `counts <- 40`da kutadi | hali qabul qilmadi |
| ikkalasi tayyor | qiymat uzatiladi | `n == 40` |
| uzatishdan keyin | davom eta oladi | davom eta oladi |

`main` birinchi kelsa, nima chiqadi? **A)** `0` · **B)** kutib, `40` · **C)** darhol panic.

<details>
<summary>Javob</summary>

**B.** Ochiq va boʻsh kanaldan qabul qilish kutadi. A nol qiymatni avtomatik olish deb oʻylaydi; C uchun panic sababi yoʻq.

</details>

```console
$ ./_video/run.sh 01-uzatish go run .
40
(chiqish kodi: 0)
```

`time.Sleep` kerak boʻlmadi. [Go xotira modeli](https://go.dev/ref/mem#chan) yuboruvchi goroutine'da yuborishdan oldin bajarilgan yozuvlar mos qabul qilish tugaganidan keyin koʻrinishini kafolatlaydi. Shu qiymat uzatish uchun alohida mutex kerak emas. Keyingi umumiy xotira yozuvlari avtomatik himoyalanmaydi.

## Deadlock: qaysi goroutine kutyapti?

```go filename="_video/02-deadlock/main.go" showLineNumbers
package main

import "fmt"

func main() {
	counts := make(chan int)
	counts <- 40
	n := <-counts
	fmt.Println(n)
}
```

Oldingi koddan `go func` olib tashlandi. Endi 7-qator yuboradi, 8-qator qabul qiladi. Bitta goroutine ikkala qatorni ketma-ket bajarmoqchi.

Natija? **A)** `40` · **B)** abadiy xabarsiz kutish · **C)** deadlock xabari.

<details>
<summary>Javob</summary>

**C.** 7-qator qabul qiluvchini kutadi, 8-qatorga yetib bormaydi. A kutishni hisobga olmaydi. Bu kichik dasturda runtime deadlock'ni topadi, shuning uchun B emas.

</details>

```console
$ ./_video/run.sh 02-deadlock go run .
fatal error: all goroutines are asleep - deadlock!

goroutine 1 [chan send]:
main.main()
	/tmp/tmp.2dqN2Sd4ye/bozor/main.go:7 +0x36
exit status 2
(chiqish kodi: 1)
```

`all goroutines are asleep` — bajarilishni davom ettira oladigan goroutine qolmadi. Runtime — dastur ichida ishlaydigan Go kodi.

| Chiqish | Qanday oʻqiymiz |
|---|---|
| `goroutine 1 [chan send]` | `main` yuborishda turibdi |
| `main.main()` | kutayotgan funksiya |
| `main.go:7` | yuborish qatori; `/tmp/…` — nusxa yoʻli |
| `+0x36` | mashina kodi siljishi; sababni topishga kerak emas |
| `exit status 2` | dastur xato bilan tugadi |

Tuzatish: yuboruvchi va qabul qiluvchi alohida goroutine'da ishlasin, birinchi misoldagidek.

Bu xabar har osilib qolishni topmaydi. Taymer yoki tashqi hodisani kutayotgan goroutine bor dasturda global deadlock eʼlon qilinmasligi mumkin. Natijada tugamaydigan goroutine qolishi **goroutine leak** deyiladi; batafsil [GB-7.06](/lab/youtube/gb/gb-7-06).

## Qatorlar oqimi: range oxirni qayerdan biladi?

```go filename="data.go" showLineNumbers
package main

// Ikki yetkazib beruvchining narx roʻyxati, GB-3.01'dagi katalog.txt formatida: «ID;nom;narx;qoldiq», narx soʻmda.
// Haqiqiy importer ularni fayldan yoki HTTP'dan oʻqiydi (GB-7.07); bu darsda ular xotirada.
var chorsu = []string{
	"1;olma;12000;40",
	"2;oʻrik;35000;0",
	"3;non;4000;100",
	"4;choy;25000;8",
}

var oloy = []string{
	"3;non;4200;60",
	"5;anor;18000;25",
}
```

`chorsu` — toʻrt, `oloy` — ikki qatorli slice. Har qator `ID;nom;narx;qoldiq`; narx soʻmda. `parseLine` narxni tiyinga oʻtkazadi. `Product`da `ID`, `Name`, `Price`, `Stock` bor. ID `3` ikkala roʻyxatda uchraydi.

Avval faqat `chorsu`ni oʻqiymiz:

```go filename="_video/03-range/main.go" showLineNumbers
package main

import "fmt"

func parse(lines []string, out chan<- Product) {
	for _, line := range lines {
		p, err := parseLine(line)
		if err != nil {
			continue // xatoni qaytarish: GB-7.04
		}
		out <- p
	}
}

func main() {
	products := make(chan Product)
	go parse(chorsu, products)
	for p := range products {
		fmt.Println(p.Name, p.Stock)
	}
	fmt.Println("import tugadi")
}
```

| Qator | Yangi yoki oʻzgargan qism |
|---|---|
| 5 | `parse(lines []string, out chan<- Product)` qatorlar slice'i va faqat yuboriladigan kanal oladi |
| 6 | `for _, line := range lines` har qatorni oladi; `_` indeksni tashlaydi |
| 7 | `p, err := parseLine(line)` qatorni mahsulotga aylantiradi |
| 8–10 | `err != nil` boʻlsa `continue` shu qatorni tashlaydi; xatoni qaytarish GB-7.04'ga qoldirilgan |
| 11–13 | `out <- p` mahsulotni yuboradi; qavslar sikl va funksiyani tugatadi |
| 16 | `products := make(chan Product)` mahsulotlar kanali |
| 17 | `go parse(chorsu, products)` parser'ni alohida boshlaydi |
| 18–20 | `for p := range products` har qabul qilingan mahsulotning nomi va qoldigʻini chiqaradi |
| 21–22 | sikldan keyin `import tugadi` yozishi va `main` tugashi kerak |

`chan<- Product` kanalni yuborish bilan cheklaydi. Funksiyaga oʻsha kanal qiymati beriladi, boshqa kanal yaratilmaydi.

Toʻrt mahsulotdan keyin nima boʻladi? **A)** sikl tugaydi · **B)** boʻsh `Product` cheksiz chiqadi · **C)** deadlock.

<details>
<summary>Javob</summary>

**C.** `parse` qaytdi, lekin kanal ochiq. `range` keyingi qiymatni kutadi. A funksiya qaytishini kanal yopilishi deb oʻylaydi; B faqat yopiq va boʻsh kanaldan oddiy qabul qilish bilan bogʻliq.

</details>

## Bufer: ikki joy, uchta yuborish

```go filename="_video/05-buffer/main.go" showLineNumbers
package main

import "fmt"

func main() {
	counts := make(chan int, 2)
	counts <- 40
	counts <- 120
	fmt.Println(len(counts), cap(counts))

```

6-qatorning ikkinchi argumenti `2`: **bufer** ikki qiymatni saqlaydi. 7–8-qatorlar joy borligida kutmaydi. 9-qatorda `len` — buferdagi qiymatlar soni, `cap` — sigʻim. 10-qatordagi uchinchi yuborish-chi?

**A)** `2 2`, keyin deadlock · **B)** `3 2` · **C)** `40` oʻchib, `5` joylashadi.

<details>
<summary>Javob</summary>

**A.** Bufer oʻsmaydi va qiymatni tashlamaydi. Qabul qiluvchi joy boʻshatmaguncha uchinchi yuborish kutadi; bu dasturda qabul qiluvchi yoʻq.

</details>

func main() {

<summary>Javob</summary>

**B.** `close` buferdagi `40`ni oʻchirmaydi. Keyingi qabul qilish `int`ning nol qiymati va `false` qaytaradi. A yuborishni oʻqish bilan adashtiradi; C yopiq kanal qoidasi hisobga olinmagan.

</details>

|---|---|---|

## Pipeline: parse → inStock

```go filename="_video/07-pipeline/main.go" showLineNumbers
package main

import "fmt"

func parse(lines []string, out chan<- Product) {
	defer close(out)
	for _, line := range lines {
		p, err := parseLine(line)
		if err != nil {
			continue // xatoni qaytarish: GB-7.04
		}
		out <- p
	}
}

func inStock(in <-chan Product, out chan<- Product) {
	defer close(out)
	for p := range in {
		if p.Stock > 0 {
			out <- p
		}
	}
}

func main() {
	raw := make(chan Product)
	ready := make(chan Product)
	go parse(chorsu, raw)
	go inStock(raw, ready)
	for p := range ready {
		fmt.Println(p.Name, p.Stock)
	}
}
```

Yangi 16–23-qatorlar — `inStock`, faqat qoldigʻi musbat mahsulotlarni oʻtkazadigan bosqich. `in <-chan Product` faqat qabul qiladi; `out chan<- Product` faqat yuboradi. 17-qator `out`ni yopishni kechiktiradi. 18-qator kirishni oxirigacha oʻqiydi, 19-qator `p.Stock > 0`ni tekshiradi, 20-qator mahsulotni uzatadi. Qolgan qavslar `if`, sikl va funksiyani yopadi.

26–27-qatorlarda `raw` — xom mahsulotlar, `ready` — tayyor mahsulotlar kanali. 28-qator `parse`ni, 29-qator `inStock`ni boshlaydi. 30–32-qatorlarda `main` tayyor mahsulotlarni oladi va chiqaradi.

| Bosqich | Yopilishdan oldin | Yopilishdan keyin |
|---|---|---|
| `parse` | `raw`ga yozadi | `raw`ni yopadi |
| `inStock` | `raw`dan oʻqib, `ready`ga yozadi | kirish sikli tugab, `ready`ni yopadi |
| `main` | `ready`dan oʻqiydi | sikl tugaydi |

Nechta mahsulot chiqadi? **A)** 4 · **B)** 3 · **C)** 2.

<details>
<summary>Javob</summary>

**B.** `oʻrik` qoldigʻi `0`, shuning uchun oʻtmaydi. A filtrni unutadi; C uchun yana bitta mahsulotni tashlash sababi yoʻq.

</details>

```console
$ ./_video/run.sh 07-pipeline go run .

```

Bu [pipeline](https://go.dev/blog/pipelines): bosqichlar alohida goroutine'larda bir vaqtda ishlaydi, qiymatlar kanallar orqali oʻtadi. Har bosqich kirishni oxirigacha oʻqiydi; chiqishini xavfsiz vaqtda yopadi.

	"fmt"
	"sync"
)

func parse(lines []string, out chan<- Product) {

		p, err := parseLine(line)
		if err != nil {
			continue // xatoni qaytarish: GB-7.04

	}

		}
	}

## Chuqurroq (ixtiyoriy): nil va yopiq kanal

```go filename="_video/10-jadval/main.go" showLineNumbers
package main

// Chuqurroq: channel jadvali. Har holatni alohida ishga tushiring:
//   ./_video/run.sh 10-jadval go run . nil-send | nil-recv | nil-close | closed-close | closed-send | closed-recv
import (
	"fmt"
	"os"
)

func main() {
	var nilCh chan int64 // nol qiymati: nil channel
	closed := make(chan int64)
	close(closed)
	switch os.Args[1] {
	case "nil-send":
		nilCh <- 1
	case "nil-recv":
		<-nilCh
	case "nil-close":
		close(nilCh)
	case "closed-close":
		close(closed)
	case "closed-send":
		closed <- 1
	case "closed-recv":
		v, ok := <-closed
		fmt.Println(v, ok)
	}
}
```

11-qatordagi `var nilCh chan int64` kanal yaratmaydi: nol qiymat `nil`. 12–13-qatorlar boshqa kanalni yaratib yopadi. 14-qatordagi `switch os.Args[1]` buyruq argumentini tanlaydi; har `case` bitta holat. 16–27-qatorlar yuborish, qabul qilish yoki yopishni bajaradi.

Har qatorni `./_video/run.sh 10-jadval go run . HOLAT` bilan qayta tekshirdim. Quyida haqiqiy chiqishdan muhim qatorlar keltirilgan; stack trace'lar jadvalda qisqartirilgan.

| HOLAT | Amal | Haqiqiy natija |
|---|---|---|
| `nil-send` | `nilCh <- 1` | `fatal error: all goroutines are asleep - deadlock!`; `[chan send (nil chan)]` |
| `nil-recv` | `<-nilCh` | `fatal error: all goroutines are asleep - deadlock!`; `[chan receive (nil chan)]` |
| `nil-close` | `close(nilCh)` | `panic: close of nil channel` |
| `closed-close` | `close(closed)` | `panic: close of closed channel` |
| `closed-send` | `closed <- 1` | `panic: send on closed channel` |
| `closed-recv` | `v, ok := <-closed` | `0 false` |

`nil`ga yuborish va undan qabul qilish bloklanadi. Bu tajribada boshqa goroutine yoʻq: runtime deadlock xabarini beradi. Tuzatish: uzatishdan oldin `make`, mos qabul qiluvchi va yuboruvchi, yagona yopuvchi kerak. Yopiq kanalni yana yopmang, unga yubormang.

Serverdagi jim osilishni ham koʻrish mumkin:

```go filename="_video/12-osilish/main.go" showLineNumbers

// Boshqa goroutine tirik boʻlsa (masalan, server), runtime deadlock'ni aniqlamaydi: dastur abadiy osilib qoladi.
//   timeout 3 ./_video/run.sh 12-osilish go run .
import (
	"fmt"
	"time"
)

func main() {
	go func() {
		for {
			time.Sleep(time.Second) // tirik goroutine: masalan, ulanishlarni kutayotgan server
		}
	}()
	prices := make(chan int64)
	prices <- 12_000 // hech kim qabul qilmaydi

}
```

11–15-qatorlardagi goroutine `time.Sleep(time.Second)` bilan takror uxlaydi: taymerlar hali bor. 16-qator `prices` kanalini yaratadi. 17-qatorning qabul qiluvchisi yoʻq; 18-qatorga yetmaydi. Endi deadlock xabari boʻladimi? **A)** ha · **B)** jim osiladi · **C)** narx chiqadi.

<details>
<summary>Javob</summary>

**B.** Taymerli goroutine sabab runtime global deadlock demaydi. Bu qabul qiluvchi yaratmaydi; `main` yuborishda qoladi. A aniqlashni ortiqcha umumlashtiradi; C yetib boʻlmaydigan qatorni kutadi.

</details>

```go filename="solution/main.go" showLineNumbers
// bozor importeri: ikki yetkazib beruvchining narx roʻyxatini channel'lar orqali bosqichma-bosqich oʻtkazadi (GB-7.02).
//
//	parse (chorsu) ─┐
//	                ├─ raw ─ inStock ─ stocked ─ unique ─ ready ─ importAll
//	parse (oloy)  ──┘
//
// Javob (TASK.md): unique bosqichi yozilgan va importAll'ga qoʻyilgan.
package main

import (
	"fmt"
	"sync"
)

// parse qatorlarni Product'ga aylantirib out'ga yuboradi. out'ni yopmaydi: unga bir nechta parse yozadi,
// yopishni hammasini kutgan bitta goroutine qiladi (importAll).
func parse(lines []string, out chan<- Product) {
	for _, line := range lines {
		p, err := parseLine(line)
		if err != nil {
			continue // xatoni qaytarish: GB-7.04
		}
		out <- p
	}
}

// inStock faqat qoldigʻi bor mahsulotlarni oʻtkazadi; in yopilgach, out'ni yopadi.
func inStock(in <-chan Product, out chan<- Product) {
	defer close(out)
	for p := range in {
		if p.Stock > 0 {
			out <- p
		}
	}
}

// unique har ID'ni faqat birinchi marta oʻtkazadi; in yopilgach, out'ni yopadi.
func unique(in <-chan Product, out chan<- Product) {
	defer close(out)
	seen := make(map[int64]bool)
	for p := range in {
		if seen[p.ID] {
			continue
		}
		seen[p.ID] = true
		out <- p
	}
}

// importAll ikki roʻyxatni bir vaqtda oʻqiydi va qoldigʻi bor mahsulotlarni qaytaradi.
func importAll(a, b []string) []Product {
	raw := make(chan Product)
	ready := make(chan Product)
	var wg sync.WaitGroup
	wg.Go(func() { parse(a, raw) })
	wg.Go(func() { parse(b, raw) })
	go func() {
		wg.Wait()
		close(raw)
	}()
	stocked := make(chan Product)
	go inStock(raw, stocked)
	go unique(stocked, ready)

	var products []Product
	for p := range ready {
		products = append(products, p)
	}
	return products
}

func main() {
	for _, p := range importAll(chorsu, oloy) {
		fmt.Println(p.Name, p.Stock)
	}
}
```

`unique` boshida `defer close(out)` bor. `seen := make(map[int64]bool)` faqat shu goroutine'ga tegishli map yaratadi. `seen[p.ID]` yoʻq boʻlsa `false`; bor boʻlsa `continue`. Birinchi qiymatda `seen[p.ID] = true`, keyin `out <- p`.

`importAll`da `stocked := make(chan Product)` yangi bogʻlanish. `go inStock(raw, stocked)` unga yozadi; `go unique(stocked, ready)` undan oʻqiydi. Natija sikli avvalgidek `ready`ni oʻqiydi.
