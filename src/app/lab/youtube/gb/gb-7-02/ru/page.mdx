## Что вы узнаете

Импортёр bozor читает прайс-листы двух поставщиков в двух горутинах. Как передать товары в `main`, не добавляя их одновременно в общий слайс?

**Одна идея:** **канал** (channel) объединяет передачу значения и ожидание. В канале без буфера отправитель и получатель ждут друг друга; `close` сообщает, что новых значений не будет.

К концу урока вы:

- получите результат горутины через канал и прочитаете сообщения `[chan send]` / `[chan receive]`;
- обозначите конец потока через `close` и `range`;
- определите, насколько буфер откладывает ожидание;
- построите конвейер `parse → inStock` и правильно закроете канал с двумя отправителями.

| Слово | Простой смысл | Английский термин |
|---|---|---|
| канал | средство передачи значений и ожидания между горутинами | channel |
| `close` и `range` по каналу | сообщение об окончании потока и чтение до его конца | close and range |
| буферизованный канал | канал с буфером для ограниченного числа значений | buffered channel |

Вспомогательное понятие: **направленный канал** разрешает функции только отправку или только получение. Последовательность этапов, соединённых каналами, называется **конвейером** (pipeline).

## Канал: отправка и получение

```go filename="_video/01-uzatish/main.go" showLineNumbers
package main

import "fmt"

func main() {
	counts := make(chan int)
	go func() {
		counts <- 40
	}()
	n := <-counts
	fmt.Println(n)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `package main` | пакет исполняемой программы |
| 3 | `import "fmt"` | подключает пакет вывода |
| 5, 12 | `func main() { … }` | основная функция и её границы |
| 6 | `counts := make(chan int)` | создаёт канал без буфера для значений `int`; `counts` хранит значение канала |
| 7, 9 | `go func() { … }()` | вызывает анонимную функцию в новой горутине; последние `()` означают вызов |
| 8 | `counts <- 40` | отправляет `40` в канал; `<-` здесь означает отправку |
| 10 | `n := <-counts` | `<-counts` получает значение; результат записывается в `n` |
| 11 | `fmt.Println(n)` | выводит полученное число |

Пустые строки нужны только для читаемости. Здесь `counts` — `chan int`, а не слайс из предыдущего урока.

| Событие | Отправитель | `main` |
|---|---|---|
| `main` пришёл первым | ещё не отправил | ждёт на `<-counts` |
| отправитель пришёл первым | ждёт на `counts <- 40` | ещё не получает |
| оба готовы | значение передаётся | `n == 40` |
| после передачи | может продолжить | может продолжить |

Что будет, если `main` придёт первым? **A)** `0` · **B)** ожидание, затем `40` · **C)** немедленный panic.

<details>
<summary>Ответ</summary>

**B.** Получение из открытого пустого канала ждёт. A предполагает автоматическую выдачу нуля; для C нет причины panic.

</details>

```console
$ ./_video/run.sh 01-uzatish go run .
40
(chiqish kodi: 0)
```

`time.Sleep` не понадобился. [Модель памяти Go](https://go.dev/ref/mem#chan) гарантирует видимость записей, сделанных отправляющей горутиной до отправки, после завершения соответствующего получения. Для этой передачи отдельный мьютекс не нужен. Последующие записи в общую память автоматически не защищаются.

## Deadlock: какая горутина ждёт?

```go filename="_video/02-deadlock/main.go" showLineNumbers
package main

import "fmt"

func main() {
	counts := make(chan int)
	counts <- 40
	n := <-counts
	fmt.Println(n)
}
```

Из предыдущего кода убрали `go func`. Теперь строка 7 отправляет, строка 8 получает. Одна горутина пытается выполнить обе строки последовательно.

Результат? **A)** `40` · **B)** бесконечное ожидание без сообщения · **C)** сообщение deadlock.

<details>
<summary>Ответ</summary>

**C.** Строка 7 ждёт получателя и не доходит до строки 8. A игнорирует ожидание. В этой маленькой программе runtime обнаруживает deadlock, поэтому B неверно.

</details>

```console
$ ./_video/run.sh 02-deadlock go run .
fatal error: all goroutines are asleep - deadlock!

goroutine 1 [chan send]:
main.main()
	/tmp/tmp.2dqN2Sd4ye/bozor/main.go:7 +0x36
exit status 2
(chiqish kodi: 1)
```

`all goroutines are asleep` означает, что не осталось горутин, способных продолжить работу. Runtime — код Go, работающий внутри программы.

| Вывод | Как читать |
|---|---|
| `goroutine 1 [chan send]` | `main` ждёт на отправке |
| `main.main()` | ожидающая функция |
| `main.go:7` | строка отправки; `/tmp/…` — путь копии |
| `+0x36` | смещение в машинном коде; для поиска причины не нужно |
| `exit status 2` | программа завершилась с ошибкой |

Исправление: отправитель и получатель должны работать в отдельных горутинах, как в первом примере.

Это сообщение обнаруживает не каждое зависание. При наличии горутины, ожидающей таймер или внешнее событие, глобальный deadlock может не объявляться. Оставшаяся горутина, которая уже не завершится, — **goroutine leak**, утечка горутины; подробнее в [GB-7.06](/lab/youtube/gb/gb-7-06/ru).

## Поток строк: откуда range узнаёт о конце?

```go filename="data.go" showLineNumbers
package main

// Ikki yetkazib beruvchining narx roʻyxati, GB-3.01'dagi katalog.txt formatida: «ID;nom;narx;qoldiq», narx soʻmda.
// Haqiqiy importer ularni fayldan yoki HTTP'dan oʻqiydi (GB-7.07); bu darsda ular xotirada.
var chorsu = []string{
	"1;olma;12000;40",
	"2;oʻrik;35000;0",
	"3;non;4000;100",
	"4;choy;25000;8",
}

var oloy = []string{
	"3;non;4200;60",
	"5;anor;18000;25",
}
```

`chorsu` — слайс из четырёх строк, `oloy` — из двух. Формат строки: `ID;имя;цена;остаток`; цена в сумах. `parseLine` переводит её в тийины. У `Product` есть поля `ID`, `Name`, `Price`, `Stock`. ID `3` встречается в обоих списках. Названия: `olma` — яблоко, `oʻrik` — абрикос, `non` — хлеб, `choy` — чай, `anor` — гранат.

Сначала читаем только `chorsu`:

```go filename="_video/03-range/main.go" showLineNumbers
package main

import "fmt"

func parse(lines []string, out chan<- Product) {
	for _, line := range lines {
		p, err := parseLine(line)
		if err != nil {
			continue // xatoni qaytarish: GB-7.04
		}
		out <- p
	}
}

func main() {
	products := make(chan Product)
	go parse(chorsu, products)
	for p := range products {
		fmt.Println(p.Name, p.Stock)
	}
	fmt.Println("import tugadi")
}
```

| Строка | Новый или изменённый фрагмент |
|---|---|
| 5 | `parse(lines []string, out chan<- Product)` принимает слайс строк и канал только для отправки |
| 6 | `for _, line := range lines` перебирает строки; `_` отбрасывает индекс |
| 7 | `p, err := parseLine(line)` превращает строку в товар |
| 8–10 | при `err != nil` оператор `continue` пропускает строку; возврат ошибок отложен до GB-7.04 |
| 11–13 | `out <- p` отправляет товар; скобки завершают цикл и функцию |
| 16 | `products := make(chan Product)` создаёт канал товаров |
| 17 | `go parse(chorsu, products)` отдельно запускает парсер |
| 18–20 | `for p := range products` выводит имя и остаток каждого полученного товара |
| 21–22 | после цикла должны появиться `import tugadi` («импорт завершён») и завершиться `main` |

`chan<- Product` разрешает только отправку. Функция получает значение того же канала; новый канал не создаётся.

Что произойдёт после четырёх товаров? **A)** цикл закончится · **B)** бесконечно выводится пустой `Product` · **C)** deadlock.

<details>
<summary>Ответ</summary>

**C.** `parse` вернулся, но канал открыт. `range` ждёт следующее значение. A путает возврат функции с закрытием канала; B относится к обычному получению из закрытого пустого канала.

</details>

```console
$ ./_video/run.sh 03-range go run .
olma 40
oʻrik 0
non 100
choy 8
fatal error: all goroutines are asleep - deadlock!

goroutine 1 [chan receive]:
main.main()
	/tmp/tmp.g1IqkDO0WX/bozor/main.go:18 +0x199
exit status 2
(chiqish kodi: 1)
```

`[chan receive]` — теперь `main` ждёт получения на строке 18. `import tugadi` не появилось.

Исправление: единственный отправитель закрывает канал по завершении:

```go filename="_video/04-close/main.go" showLineNumbers
package main

import "fmt"

func parse(lines []string, out chan<- Product) {
	defer close(out)
	for _, line := range lines {
		p, err := parseLine(line)
		if err != nil {
			continue // xatoni qaytarish: GB-7.04
		}
		out <- p
	}
}

func main() {
	products := make(chan Product)
	go parse(chorsu, products)
	for p := range products {
		fmt.Println(p.Name, p.Stock)
	}
	fmt.Println("import tugadi")
}
```

Новая строка 6: `defer close(out)`. `defer` выполняет вызов при возврате из `parse` или при panic. Закрытие канала сообщает `range` о конце.

Появится ли теперь `import tugadi`? **A)** да · **B)** снова deadlock · **C)** `close` удалит последний товар.

<details>
<summary>Ответ</summary>

**A.** Отправленные значения не теряются. После закрытия и получения оставшихся значений `range` заканчивается; B и C противоречат этому правилу.

</details>

```console
$ ./_video/run.sh 04-close go run .
olma 40
oʻrik 0
non 100
choy 8
import tugadi
(chiqish kodi: 0)
```

| Состояние | Что делает `range`? |
|---|---|
| канал открыт, значения нет | ждёт |
| канал закрыт, в буфере есть значения | получает оставшиеся |
| канал закрыт и пуст | заканчивает цикл |

Закрывать каждый канал не обязательно. Закрытие сообщает получателю о конце потока. Им управляет сторона отправителя; самовольное закрытие получателем может вызвать panic при отправке.

## Буфер: два места, три отправки

```go filename="_video/05-buffer/main.go" showLineNumbers
package main

import "fmt"

func main() {
	counts := make(chan int, 2)
	counts <- 40
	counts <- 120
	fmt.Println(len(counts), cap(counts))
	counts <- 5
}
```

Второй аргумент `2` в строке 6: **буфер** хранит два значения. Строки 7–8 не ждут, пока есть место. В строке 9 `len` — число значений в буфере, `cap` — его ёмкость. Что произойдёт с третьей отправкой в строке 10?

**A)** `2 2`, затем deadlock · **B)** `3 2` · **C)** `40` удалится, освободив место для `5`.

<details>
<summary>Ответ</summary>

**A.** Буфер не растёт и не отбрасывает значения. Третья отправка ждёт освобождения места получателем; здесь получателя нет.

</details>

```console
$ ./_video/run.sh 05-buffer go run .
2 2
fatal error: all goroutines are asleep - deadlock!

goroutine 1 [chan send]:
main.main()
	/tmp/tmp.F9Embx1zFE/bozor/main.go:10 +0xe6
exit status 2
(chiqish kodi: 1)
```

| Действие | Буфер | Результат |
|---|---|---|
| создание | `[]`, ёмкость 2 | пуст |
| `counts <- 40` | `[40]` | продолжение |
| `counts <- 120` | `[40, 120]` | продолжение |
| `counts <- 5` | `[40, 120]` | ожидание |

В открытом буферизованном канале отправка блокируется при полном буфере, получение — при пустом. Буфер позволяет отправителю уйти вперёд на N значений; получателя он не создаёт.

Теперь отправим в буфер `40` и закроем канал:

```go filename="_video/06-quiz/main.go" showLineNumbers
package main

import "fmt"

func main() {
	counts := make(chan int, 2)
	counts <- 40
	close(counts)
	fmt.Println(<-counts)
	n, ok := <-counts
	fmt.Println(n, ok)
}
```

Строка 9 получает первое значение. `n, ok := <-counts` в строке 10 получает второе и сообщает, пришло ли оно от настоящей отправки. `ok == false` означает закрытый пустой канал.

Что выведут два вызова? **A)** panic · **B)** `40`, затем `0 false` · **C)** `40`, затем deadlock.

<details>
<summary>Ответ</summary>

**B.** `close` не удаляет `40` из буфера. Следующее получение возвращает нулевое значение `int` и `false`. A путает отправку с получением; C игнорирует правило закрытого канала.

</details>

```console
$ ./_video/run.sh 06-quiz go run .
40
0 false
(chiqish kodi: 0)
```

| Момент | Буфер | Получение |
|---|---|---|
| после `close` | `[40]` | отправленное значение ещё есть |
| первое чтение | `[]` | `40`, в форме с двумя результатами `ok == true` |
| второе чтение | `[]` | `0 false`, без ожидания |

Сам `0` не означает конец: отправитель может отправить настоящий `0`. Различайте конец через `ok` или `range`.

## Конвейер: parse → inStock

```go filename="_video/07-pipeline/main.go" showLineNumbers
package main

import "fmt"

func parse(lines []string, out chan<- Product) {
	defer close(out)
	for _, line := range lines {
		p, err := parseLine(line)
		if err != nil {
			continue // xatoni qaytarish: GB-7.04
		}
		out <- p
	}
}

func inStock(in <-chan Product, out chan<- Product) {
	defer close(out)
	for p := range in {
		if p.Stock > 0 {
			out <- p
		}
	}
}

func main() {
	raw := make(chan Product)
	ready := make(chan Product)
	go parse(chorsu, raw)
	go inStock(raw, ready)
	for p := range ready {
		fmt.Println(p.Name, p.Stock)
	}
}
```

Новые строки 16–23 — `inStock`, этап, пропускающий товары с положительным остатком. `in <-chan Product` разрешает только получение; `out chan<- Product` — только отправку. Строка 17 откладывает закрытие `out`. Строка 18 читает вход до конца, строка 19 проверяет `p.Stock > 0`, строка 20 передаёт товар. Остальные скобки закрывают `if`, цикл и функцию.

В строках 26–27 `raw` — канал исходных товаров, `ready` — готовых. Строка 28 запускает `parse`, строка 29 — `inStock`. В строках 30–32 `main` получает и выводит готовые товары.

| Этап | До закрытия | После закрытия |
|---|---|---|
| `parse` | пишет в `raw` | закрывает `raw` |
| `inStock` | читает `raw`, пишет в `ready` | заканчивает входной цикл, закрывает `ready` |
| `main` | читает `ready` | заканчивает цикл |

Сколько товаров появится? **A)** 4 · **B)** 3 · **C)** 2.

<details>

## Два отправителя: закрывает одно место


```go filename="_video/09-wg/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
)

func parse(lines []string, out chan<- Product) {
	for _, line := range lines {
		p, err := parseLine(line)
		if err != nil {
			continue // xatoni qaytarish: GB-7.04
		}
		out <- p
	}
}

func inStock(in <-chan Product, out chan<- Product) {
	defer close(out)
	for p := range in {
		if p.Stock > 0 {
			out <- p
		}
	}
}

func main() {
	raw := make(chan Product)
	ready := make(chan Product)
	var wg sync.WaitGroup
	wg.Go(func() { parse(chorsu, raw) })
	wg.Go(func() { parse(oloy, raw) })
	go func() {
		wg.Wait()
		close(raw)
	}()
	go inStock(raw, ready)
	for p := range ready {
		fmt.Println(p.Name, p.Stock)
	}
}
```

| Строка | Изменение |
|---|---|
| 3–6 | в `import` добавлен `sync` |
| 8–16 | в `parse` больше нет `defer close(out)` |
| 30 | `var wg sync.WaitGroup` учитывает завершение отправителей |
| 31–32 | `wg.Go` запускает каждый `parse` в отдельной горутине |
| 33–36 | другая горутина ждёт обоих через `wg.Wait()`, затем один раз вызывает `close(raw)` |
| 37–40 | работает `inStock`, `main` читает результаты |

Если поставить здесь `wg.Wait()` прямо в `main`, он не начнёт читать `ready`. `inStock` застрянет на отправке, затем остановятся и `parse`. Поэтому ожидание вынесено в отдельную горутину.

## Глубже (необязательно): nil и закрытый канал

```go filename="_video/10-jadval/main.go" showLineNumbers
package main

// Chuqurroq: channel jadvali. Har holatni alohida ishga tushiring:
//   ./_video/run.sh 10-jadval go run . nil-send | nil-recv | nil-close | closed-close | closed-send | closed-recv
import (
	"fmt"
	"os"
)

func main() {
	var nilCh chan int64 // nol qiymati: nil channel
	closed := make(chan int64)
	close(closed)
	switch os.Args[1] {
	case "nil-send":
		nilCh <- 1
	case "nil-recv":
		<-nilCh
	case "nil-close":
		close(nilCh)
	case "closed-close":
		close(closed)
	case "closed-send":
		closed <- 1
	case "closed-recv":
		v, ok := <-closed
		fmt.Println(v, ok)
	}
}
```

`var nilCh chan int64` в строке 11 не создаёт канал: нулевое значение — `nil`. Строки 12–13 создают и закрывают другой канал. `switch os.Args[1]` в строке 14 выбирает аргумент команды; каждый `case` — отдельное состояние. Строки 16–27 выполняют отправку, получение или закрытие.

Я проверил каждую строку командой `./_video/run.sh 10-jadval go run . СОСТОЯНИЕ`. Ниже приведены значимые строки настоящего вывода; stack trace в таблице сокращены.

| СОСТОЯНИЕ | Действие | Настоящий результат |
|---|---|---|
| `nil-send` | `nilCh <- 1` | `fatal error: all goroutines are asleep - deadlock!`; `[chan send (nil chan)]` |
| `nil-recv` | `<-nilCh` | `fatal error: all goroutines are asleep - deadlock!`; `[chan receive (nil chan)]` |
| `nil-close` | `close(nilCh)` | `panic: close of nil channel` |
| `closed-close` | `close(closed)` | `panic: close of closed channel` |
| `closed-send` | `closed <- 1` | `panic: send on closed channel` |
| `closed-recv` | `v, ok := <-closed` | `0 false` |

Отправка и получение через `nil` блокируются. Других горутин в опыте нет: runtime сообщает deadlock. Исправление: перед обменом нужны `make`, согласованные получатель и отправитель, одно место закрытия. Не закрывайте закрытый канал повторно и не отправляйте в него.

Можно увидеть и зависание без сообщения, как в сервере:

```go filename="_video/12-osilish/main.go" showLineNumbers

// Boshqa goroutine tirik boʻlsa (masalan, server), runtime deadlock'ni aniqlamaydi: dastur abadiy osilib qoladi.
//   timeout 3 ./_video/run.sh 12-osilish go run .
import (
	"fmt"
	"time"
)

func main() {
	go func() {
		for {
			time.Sleep(time.Second) // tirik goroutine: masalan, ulanishlarni kutayotgan server
		}
	}()
	prices := make(chan int64)
	prices <- 12_000 // hech kim qabul qilmaydi
	fmt.Println("bu qator hech qachon chiqmaydi")
}
```

Горутина в строках 11–15 повторяет `time.Sleep(time.Second)`: таймеры ещё есть. Строка 16 создаёт канал `prices`. Для строки 17 получателя нет; строка 18 недостижима. Появится ли сообщение deadlock? **A)** да · **B)** тихое зависание · **C)** вывод цены.

<details>
<summary>Ответ</summary>

**B.** Из-за горутины с таймером runtime не объявляет глобальный deadlock. Получатель от этого не появляется; `main` остаётся на отправке. A чрезмерно обобщает обнаружение; C ожидает недостижимую строку.

</details>

## Частые ошибки

**1. Каждый из двух отправителей закрывает канал.** Настоящий panic показан выше в примере с двумя отправителями. Исправление: `parse` не закрывает канал; одно место закрывает его после `wg.Wait()`.

```go filename="solution/main.go" showLineNumbers
//
//	parse (chorsu) ─┐
//	                ├─ raw ─ inStock ─ stocked ─ unique ─ ready ─ importAll
//	parse (oloy)  ──┘
//
// Javob (TASK.md): unique bosqichi yozilgan va importAll'ga qoʻyilgan.
package main

import (
	"fmt"
	"sync"
)

// parse qatorlarni Product'ga aylantirib out'ga yuboradi. out'ni yopmaydi: unga bir nechta parse yozadi,
// yopishni hammasini kutgan bitta goroutine qiladi (importAll).
func parse(lines []string, out chan<- Product) {
	for _, line := range lines {
		p, err := parseLine(line)
		if err != nil {
			continue // xatoni qaytarish: GB-7.04
		}
		out <- p
	}
}

// inStock faqat qoldigʻi bor mahsulotlarni oʻtkazadi; in yopilgach, out'ni yopadi.
func inStock(in <-chan Product, out chan<- Product) {
	defer close(out)
	for p := range in {
		if p.Stock > 0 {
			out <- p
		}
	}
}

// unique har ID'ni faqat birinchi marta oʻtkazadi; in yopilgach, out'ni yopadi.
func unique(in <-chan Product, out chan<- Product) {
	defer close(out)
	seen := make(map[int64]bool)
	for p := range in {
		if seen[p.ID] {
			continue
		}
		seen[p.ID] = true
		out <- p
	}
}

// importAll ikki roʻyxatni bir vaqtda oʻqiydi va qoldigʻi bor mahsulotlarni qaytaradi.
func importAll(a, b []string) []Product {
	raw := make(chan Product)
	ready := make(chan Product)
	var wg sync.WaitGroup
	wg.Go(func() { parse(a, raw) })
	wg.Go(func() { parse(b, raw) })
	go func() {
		wg.Wait()
		close(raw)
	}()
	stocked := make(chan Product)
	go inStock(raw, stocked)
	go unique(stocked, ready)

	var products []Product
	for p := range ready {
		products = append(products, p)
	}
	return products
}

func main() {
	for _, p := range importAll(chorsu, oloy) {
		fmt.Println(p.Name, p.Stock)
	}
}
```

В начале `unique` стоит `defer close(out)`. `seen := make(map[int64]bool)` создаёт map, принадлежащую только этой горутине. Если `seen[p.ID]` отсутствует, получается `false`; если уже есть, выполняется `continue`. Для первого значения выполняются `seen[p.ID] = true`, затем `out <- p`.

В `importAll` новый `stocked := make(chan Product)` соединяет этапы. `go inStock(raw, stocked)` пишет в него; `go unique(stocked, ready)` читает из него. Собирающий цикл по-прежнему читает `ready`.

Сохраняется первый **пришедший** ID. Цена какого поставщика останется для одинакового ID, не гарантирована. Это задание не выбирает самую низкую цену.
