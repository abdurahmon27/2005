## What you will learn

Dilnoza logged in to bozor. Then, on a foreign page on another port, she clicked the button «Sovgʻani olish» ("Get the gift"). That click cancelled order 41 in bozor, although the session cookie was `SameSite=Lax`. Why did the protection not work?

**One idea:** the browser adds the cookie to the request **by itself**, no matter which page started the request. Cookie attributes only control "when to add it", and `SameSite` looks at the *site*: a port or a subdomain does not change the site. So for a request that changes state, the server itself checks **where** the request came from. CORS only controls whether a page can **read** the response: the request still runs. And login is limited by the number of attempts.

By the end of the lesson you will:

- see in a real Chrome what each `Set-Cookie` attribute does (`__Host-`, `Max-Age`, `HttpOnly`, `Secure`, `SameSite`);
- recreate the cancellation of Dilnoza's order by a plain HTML form on another page, and turn it into a `403` with `http.CrossOriginProtection`;
- set up CORS with an allow-list and `Vary: Origin`, and see with your own eyes the mistake of returning `Origin` without checking it;
- put a token bucket limit per IP on `POST /login` (`429` and `Retry-After`), and write the second one, per email, yourself in the homework.

| Word | Plain meaning | English term |
|---|---|---|
| `SameSite` | an attribute: whether to add the cookie to a request started from **another site** | SameSite |
| CSRF | a page on a foreign site sends a request through the user's browser, with the user's cookie | cross-site request forgery |
| token bucket | a limited stock of tokens for each key (IP, email): every attempt takes one | token bucket |

Two helpers: the `Sec-Fetch-Site` and `Origin` headers (who started the request) and **CORS** (the browser's read rule). Other words are explained where they first appear.

## Cookie attributes: rules for the browser

The browser decides how to store a cookie and which request to add it to. The server gives it rules only through the **attributes** in the `Set-Cookie` header. Let us look at the whole login response (`-i` also prints the response headers, `-c jar.txt` saves the cookie to a file). Start the server from the `final` folder and run curl in the same folder:

```console
$ curl -s -i -c jar.txt localhost:8765/login -H "Content-Type: application/json" --data-binary @login.json | mask
HTTP/1.1 200 OK
Cache-Control: no-store
Content-Type: application/json
Set-Cookie: __Host-session=[redacted]; Path=/; Max-Age=86400; HttpOnly; Secure; SameSite=Lax
Vary: Origin
X-Request-Id: GLYOPBEPBDRKAICL3Q3V6FD3N7
Date: Sat, 28 Nov 2026 09:24:10 GMT
Content-Length: 38

{"id":1,"email":"[email]"}
```

The request ID, the date and the token are different on every run. The token is replaced by `[redacted]`: `mask` did that. `Cache-Control: no-store` is familiar from GB-6.04; `Content-Type`, `Content-Length` and `Date` are ordinary HTTP headers (GB-4.01). `Vary: Origin` was added in this lesson, and I explain it in the CORS section. Look at the `Set-Cookie` line. Compared with GB-6.04, two things changed: the `__Host-` prefix was added before the name, and `Max-Age` replaced `Expires`. The other attributes are the same.

| Part | What the browser does |
|---|---|
| `__Host-session` | the browser accepts a cookie whose name starts with `__Host-` only if three conditions hold (see below) |
| `Path=/` | the cookie is added to all paths of the site |
| `Max-Age=86400` | the browser keeps the cookie for 86400 seconds, that is, 24 hours |
| `HttpOnly` | a script on the page cannot read the cookie through `document.cookie` |
| `Secure` | the cookie is sent only over HTTPS; `http://localhost` is an exception |
| `SameSite=Lax` | limits adding the cookie to requests started from another site (next sections) |

Here is how these attributes are written in `setSessionCookie`:

```go
func setSessionCookie(w http.ResponseWriter, token string) {
	http.SetCookie(w, &http.Cookie{
		Name:     sessionCookie,
		Value:    token,
		Path:     "/",
		MaxAge:   int(sessionTTL.Seconds()),
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
	w.Header().Set("Cache-Control", "no-store")
}
```

| Code | What it does |
|---|---|
| `Name: sessionCookie` | the cookie name; this constant's value is `"__Host-session"` |
| `MaxAge: int(sessionTTL.Seconds())` | `sessionTTL` is `24 * time.Hour`; `Seconds()` converts it to seconds (`86400`), `int` makes a whole number |
| `HttpOnly: true`, `Secure: true` | write the matching attributes |
| `SameSite: http.SameSiteLaxMode` | writes `SameSite=Lax`; in GB-6.04 it was only named |
| `w.Header().Set("Cache-Control", "no-store")` | the response must not stay in a cache (GB-6.04) |

**`Max-Age`** is a *relative* lifetime in seconds: the browser adds it to its own current time. `Expires` is an exact date that the browser compares with its own clock, so a wrong clock shifts the lifetime. If both are given, `Max-Age` wins (RFC 6265bis §4.1.2.2). A browser may also shorten the lifetime, so the session lifetime on the server (`sessionTTL`, GB-6.04) stays the main one.

**The `__Host-` prefix** sets a condition for the browser: the cookie must be `Secure`, must have `Path=/`, and must not have a `Domain` attribute. A cookie without `Domain` is *host-only*: it returns only to the host that issued it, not to subdomains. The result: `blog.bozor.uz` cannot overwrite bozor's `__Host-session` cookie. The restriction is about the host, not the port: RFC 6265bis says that ports are the only part of the origin model that `__Host-` cookies still ignore.

How did curl store this cookie? The last line of `jar.txt`:

```console
$ tail -1 jar.txt | mask
#HttpOnly_localhost	FALSE	/	TRUE	1795944250	__Host-session	[redacted]
```

The line has seven tab-separated columns: the domain (the `#HttpOnly_` mark means the cookie is `HttpOnly`), whether subdomains accept it too (`FALSE` means no, there was no `Domain`), the path, `Secure` (`TRUE`), the expiry time (in epoch seconds: curl turned `Max-Age` into an absolute time), the name, the value. Curl stores and returns a `Secure` cookie for `http://localhost`: localhost is an exception (MDN, Set-Cookie).

### HttpOnly: in a real browser

You cannot show `HttpOnly` with curl: curl has no page script. That is why a real Chrome is needed. It runs without a window (**headless**), and a Go program in `_video/brauzer` drives it through the **chromedp** library. The program itself is not the topic of the lesson: it drives the browser and prints the result. The `httponly` command logs in to bozor as Dilnoza on a bozor page (the browser stores the cookie by itself), then does two things with a page script. The server runs from `final`, the command runs in the browser folder:

```console
$ go run . httponly | mask
login: 200 {"id":1,"email":"[email]"}
document.cookie: ""
fetch /me: 200 {"id":1,"email":"[email]"}
```

1. `login: 200 …`: the login worked, the browser has the cookie.
2. `document.cookie: ""`: the script reads cookies through `document.cookie` and gets an empty string. That is what `HttpOnly` does.
3. `fetch /me: 200 …`: `fetch` is the browser's function for requests. It sends a request to `/me`, and the browser adds the cookie by itself: the response is `200`.

Conclusion: a malicious script on the page **cannot steal** the token, but while the page is open it can send requests on Dilnoza's behalf. `HttpOnly` protects against the first, not the second.

## Origin and site: when a cookie counts as "coming from elsewhere"

To understand `SameSite` you must know exactly what "elsewhere" means. There are two notions.

**Origin** is the scheme, host and port together: `http://localhost:8765`. If any one differs, the origin is different.

**Site** is the scheme and the *registrable domain*: an entry from the Public Suffix List plus one part before it, for example `bozor.uz`. **The port is not counted.** Hosts such as `localhost` and IP addresses have no registrable domain: the whole host must be equal (HTML Standard, "same site"). The scheme is also checked: in cookie rules `http://` and `https://` are different sites (MDN, Site).

| One page | Another page | Origin | Site |
|---|---|---|---|
| `http://localhost:8765` | `http://localhost:8765/me` | same | same |
| `http://localhost:8765` | `http://localhost:9090` | **different** (port) | **same** (the port is not counted) |
| `https://app.bozor.uz` | `https://blog.bozor.uz` | different (host) | **same** (`bozor.uz`) |
| `http://localhost:8765` | `http://127.0.0.1:9090` | different | **different** (different host) |
| `http://localhost` | `https://localhost` | different | different (different scheme) |

In the lab the foreign site opens from one server under two names: `http://localhost:9090` (the **same site** as bozor, but a different origin) and `http://127.0.0.1:9090` (a **different site**). The first models a neighbouring service inside the network (a neighbour port or a subdomain), the second a plain foreign site.

## SameSite: when the cookie is added

`SameSite` decides whether to add the cookie to a request **started from another site**. There are three values. Inside one site the cookie is sent in all three cases, whatever the request type.

| Request started from another site | `Strict` | `Lax` | `None` (needs `Secure`) |
|---|---|---|---|
| a page opened by a link (top-level navigation, `GET`) | not sent | **sent** | sent |
| `POST` by a form | not sent | not sent | sent |
| `iframe` (a page inside a page) or `fetch` | not sent | not sent | sent |

`Lax` is the value of this lesson's cookie. Its rule: from another site it is sent only on a top-level navigation with a safe method (`GET`) (RFC 6265bis §4.1.2.7). Use this table to predict: if the foreign page is on another site, what does a `POST` form get?

## CSRF: a form on a foreign page

The attack page is in the `formaPage` constant in `cmd/begona`: a plain HTML form, no script.

```html
<form method="post" action="http://localhost:8765/orders/41/cancel">
  <button>Sovgʻani olish</button>
</form>
```

| Line | What it does |
|---|---|
| `<form method="post" action="…">` | when the form is submitted, the browser sends a `POST` request; `action` is where: bozor's cancel path |
| `<button>Sovgʻani olish</button>` | a button; when pressed, the browser submits the form |
| `</form>` | the form ends |

When the browser submits the form, it adds bozor's cookies **by itself**, if `SameSite` allows. This route has no body, so there is no `requireJSON` either (GB-6.01): a plain form can reach it too. This is the `cancelOrder` route:

```go
	mux.Handle("POST /orders/{id}/cancel", a.requireUser(http.HandlerFunc(a.cancelOrder)))
```

| Step | Who | What |
|---|---|---|
| 1 | Dilnoza | logs in to bozor; the browser stores the cookie |
| 2 | Dilnoza | opens the foreign page |
| 3 | Dilnoza | clicks «Sovgʻani olish» |
| 4 | browser | submits the form as `POST /orders/41/cancel` and, if allowed, adds the cookie by itself |
| 5 | bozor | the cookie is valid, the owner is valid: the order is cancelled |

### Two new fields in the server log

To see who started a request, two fields were added to `logRequests`:

```go
		_, err := r.Cookie(sessionCookie)
		log.Printf("%s %s %q %d %s site=%q cookie=%t", w.Header().Get("X-Request-Id"),
			r.Method, r.URL.Path, rec.status, time.Since(start), r.Header.Get("Sec-Fetch-Site"), err == nil)
```

`site=` is the `Sec-Fetch-Site` header: the browser adds it by itself to every request to HTTPS or localhost addresses, and it records which page started the request. Its values are `same-origin`, `same-site`, `cross-site`, `none` (typed into the address bar or opened from a bookmark). `cookie=` tells whether the session cookie arrived (`true`/`false`). `r.Header.Get` reads the header, and `err == nil` means the cookie is present (GB-6.04).

</details>

## Protection on the server: http.CrossOriginProtection

The server itself checks **where** a state-changing request came from. Since Go 1.25 the standard library has `http.CrossOriginProtection` for this; the OWASP CSRF Prevention Cheat Sheet names it. It relies on two headers that the browser sends: `Sec-Fetch-Site` (seen above) and `Origin` (the origin of the page that started the request; the browser adds it to `POST`).

```go
var allowedOrigins = []string{"http://localhost:3000"}

// errCrossOrigin — soʻrov boshqa origin'dagi sahifadan kelgan (problemFor → 403).
var errCrossOrigin = errors.New("boshqa saytdan kelgan soʻrov")

// protectCSRF — Go 1.25'dan beri standart kutubxonadagi http.CrossOriginProtection bilan:
//   - GET, HEAD, OPTIONS — har doim oʻtadi (ular holatni oʻzgartirmasligi kerak);
//   - Sec-Fetch-Site: same-origin yoki none (manzil qatoriga yozilgan) — oʻtadi; boshqa qiymat — rad;
//   - Sec-Fetch-Site yoʻq, Origin bor — Origin'ning host'i Host sarlavhasiga teng boʻlsa oʻtadi;
//   - ikkalasi ham yoʻq — Go buni brauzer emas deb hisoblaydi (curl, mobil ilova, boshqa server): oʻtadi (fail-open);
//   - AddTrustedOrigin'dagi origin'lar — oʻtadi.
//
// Origin ↔ Host solishtiruvida sxema (http/https) koʻrilmaydi: production'da HTTPS + HSTS (GB-8.06).
//
// Brauzer bo'lmagan mijozda begona cookie yoʻq: CSRF — aynan brauzer cookie'ni oʻzi qoʻshgani uchun xavf.
// Rad sababi (Check'ning xatosi) log'ga, mijozga — bizning matn (GB-6.02).
func protectCSRF(next http.Handler) http.Handler {
	cop := http.NewCrossOriginProtection()
	for _, o := range allowedOrigins {
		if err := cop.AddTrustedOrigin(o); err != nil {
			panic(err) // roʻyxat kodimizda: notoʻgʻri yozilgan boʻlsa server ishga tushmasin
		}
	}
```

| Code | What it does |
|---|---|
| `var allowedOrigins = []string{…}` | the list of allowed origins: bozor's own web app, `http://localhost:3000` |
| `func protectCSRF(next http.Handler) http.Handler` | middleware (the shape from GB-6.01) |
| `cop := http.NewCrossOriginProtection()` | creates the checker object |
| `for _, o := range allowedOrigins` | for each origin in the list |
| `cop.AddTrustedOrigin(o)` | adds it to the **trusted** origins; returns an error if the entry is malformed (no scheme, has a path) |
| `panic(err)` | the list is in our code: if it is wrong, the server must not start (GB-2.09) |

The main part is the returned handler:

```go
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if err := cop.Check(r); err != nil {
			writeError(w, fmt.Errorf("%w: %w", errCrossOrigin, err))
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

| Code | What it does |
|---|---|
| `cop.Check(r)` | checks the request; returns an error if it is rejected |
| `fmt.Errorf("%w: %w", errCrossOrigin, err)` | combines two errors: our text and the reason from `Check` (GB-6.02) |
| `writeError(w, …)` | writes a `403` problem response: our text to the client, the reason to the log |
| `next.ServeHTTP(w, r)` | the check passed, the handler runs |

The rules of `Check` (Go 1.27.4 source, `net/http/csrf.go`):

1. `GET`, `HEAD`, `OPTIONS` **always pass**: these methods must not change state. So never change state in a GET.
2. `Sec-Fetch-Site: same-origin` or `none` passes. Any other value (`same-site`, `cross-site`) is **rejected**, unless `Origin` is in the trusted list or the path is excepted with `AddInsecureBypassPattern`.
3. `Sec-Fetch-Site` is absent, `Origin` is present: it passes if the host in `Origin` (with port) equals the `Host` header, otherwise it is rejected. The scheme is not compared.
4. Neither is present: the request is assumed to be not from a browser or from the same origin, and it **passes**.

Its place in the chain: `requestID → logRequests → recoverPanic → cors → protectCSRF → muxErrors → mux` (`cmd/api/middleware.go`, `newHandler`).

## CORS: the rule for reading a response

**CORS** (cross-origin resource sharing) is the browser's **read** rule. A page from another origin can send a request to the server, but to read the response the server must name exactly that origin in the `Access-Control-Allow-Origin` header. If it does not, the browser does not give the response to the page. For a request with a cookie, `Access-Control-Allow-Credentials: true` is also needed. This rule does **not** protect the server: the request still runs. The experiment below shows it.

`oqishPage` in `cmd/begona` is a page with a script:

```html

<script>
fetch("http://localhost:8765/me", {credentials: "include"})
  .then(r => r.text())
  .then(t => { natija.textContent = "oʻqildi: " + t })
  .catch(e => { natija.textContent = "oʻqib boʻlmadi: " + e })
</script>
```

| Line | What it does |
|---|---|
| `<pre id="natija">kutilmoqda…</pre>` | the place where the result is written ("kutilmoqda" means "waiting") |
| `fetch("http://localhost:8765/me", {credentials: "include"})` | requests bozor's `/me`; `credentials: "include"` sends the cookie too |
| `.then(r => r.text())` | when the response arrives, takes its text |
| `.then(t => { natija.textContent = "oʻqildi: " + t })` | writes the text on the page ("oʻqildi" means "read") |
| `.catch(e => { … "oʻqib boʻlmadi: " + e })` | if reading is refused, writes the error ("oʻqib boʻlmadi" means "could not read") |

### A common mistake: returning Origin as it is

Developers want to allow everything, and instead of a list they return the request's own `Origin`, together with `Allow-Credentials: true`. This is the code from the `aks` copy:

```go
func cors(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// XATO (video): roʻyxat oʻrniga soʻrovdagi Origin'ni oʻzini qaytarish — har qanday sahifa javobni oʻqiydi.
		w.Header().Set("Access-Control-Allow-Origin", r.Header.Get("Origin"))
		w.Header().Set("Access-Control-Allow-Credentials", "true")
		next.ServeHTTP(w, r)
	})
}
```

`r.Header.Get("Origin")` reads the request's `Origin`, `Set` writes it into the response: it tells every page "you are allowed". And `Allow-Credentials: true` allows reading responses with a cookie too. `Origin` is checked against nothing.

### The right way: an allow-list

The list of allowed origins (the **allow-list**) is the same `allowedOrigins` that `protectCSRF` uses. This is the `cors` middleware (the final code):

```go
func cors(next http.Handler) http.Handler {
	allowed := map[string]bool{}
	for _, o := range allowedOrigins {
		allowed[o] = true
	}
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Add("Vary", "Origin")
		origin := r.Header.Get("Origin")
		if !allowed[origin] {
			next.ServeHTTP(w, r)
			return
		}
		w.Header().Set("Access-Control-Allow-Origin", origin)
		w.Header().Set("Access-Control-Allow-Credentials", "true")
		// Preflight: brauzer haqiqiy soʻrovdan oldin OPTIONS bilan ruxsat soʻraydi (JSON body, PATCH, DELETE…).
		if r.Method == http.MethodOptions && r.Header.Get("Access-Control-Request-Method") != "" {
			w.Header().Set("Access-Control-Allow-Methods", "POST, PATCH, DELETE")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
			w.Header().Set("Access-Control-Max-Age", "600") // brauzer javobni 10 daqiqa eslab qoladi
			w.WriteHeader(http.StatusNoContent)
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

| Code | What it does |
|---|---|
| `allowed := map[string]bool{}` and `for … allowed[o] = true` | turns the list into a `map` for fast checking |
| `w.Header().Add("Vary", "Origin")` | tells the cache: "the response depends on `Origin`" (`Add` **adds** a value to a header, `Set` replaces it) |
| `if !allowed[origin] { next.ServeHTTP(w, r); return }` | if the origin is not in the list, no CORS headers are **added**; the request runs as usual |
| `Access-Control-Allow-Origin` = `origin` | if the origin is in the list, returns exactly that one |
| `Access-Control-Allow-Credentials: true` | allows reading a response with a cookie |
| `if r.Method == http.MethodOptions && …` | the preflight branch (below) |

### Preflight

Before an unusual request (a JSON body, `PATCH`, `DELETE`, a custom header) the browser first sends an `OPTIONS` request and asks for permission: in `Access-Control-Request-Method` and `Access-Control-Request-Headers` it writes what it needs. ## Rate limit on login: token bucket

Every login attempt computes argon2id: in GB-6.03 we saw that one attempt takes 46 MiB of memory and noticeable CPU time. In my run one `POST "/login"` log line showed `82.523656ms`. Without a limit, `POST /login` is open for password guessing and is a cheap way to load the server. Bozor before the lesson (`himoyasiz`): eight wrong logins in a row from one IP. The bash loop `for i in $(seq 8)` repeats the command eight times; in curl `-o /dev/null` discards the body, `-w "%{http_code} "` prints only the status code, and `echo` ends the line:

```console
$ for i in $(seq 8); do curl -s -o /dev/null -w "%{http_code} " localhost:8765/login -H "Content-Type: application/json" --data-binary @wrong.json; done; echo
401 401 401 401 401 401 401 401
```

Eight `401`s: guessing is unlimited. The solution is a **token bucket**. For each key (now it is the IP) there is a bucket: it holds at most 5 tokens and starts full. Every attempt takes one token. One token returns to the bucket every 12 seconds. If there are no tokens, the answer is `429 Too Many Requests` and `Retry-After`: after how many seconds you may try again.

| Attempt | In the bucket before | Result | In the bucket after |
|---|---|---|---|
| 1 | 5 | `401` (wrong password, but the attempt is allowed) | 4 |
| 2 | 4 | `401` | 3 |
| 3 | 3 | `401` | 2 |
| 4 | 2 | `401` | 1 |
| 5 | 1 | `401` | 0 |
| 6, 7, 8 | 0 | `429`, `Retry-After` | 0 (no token is taken) |
| after 12 seconds | 0 → 1 | the next attempt gives `401` | 0 |

The code is in the `golang.org/x/time/rate` package: the Go team's token bucket (added with `go get golang.org/x/time/rate`, GB-2.06; `v0.16.0` in `go.mod`). The full `cmd/api/ratelimit.go`:

```go filename="cmd/api/ratelimit.go" showLineNumbers
package main

// Login'ga rate limit (GB-6.07). Har login urinishi argon2id hisoblaydi (GB-6.03: 46 MiB xotira):
// cheklovsiz POST /login — parol taxmin qilish uchun ochiq eshik va serverni band qilishning arzon yoʻli.
//
// golang.org/x/time/rate — Go jamoasining token bucket'i: chelakda eng koʻpi `burst` ta token,
// har `every` vaqtda bittadan toʻladi; har soʻrov bitta token oladi; token yoʻq — 429 Too Many Requests
// (RFC 6585 §4) va Retry-After: necha soniyadan keyin qayta urinish mumkin (RFC 9110 §10.2.3).

import (
	"math"
	"net"
	"net/http"
	"strconv"
	"sync"
	"time"

	"golang.org/x/time/rate"
)

// limiters — har kalit (IP yoki email) uchun alohida chelak. Map bir vaqtda koʻp soʻrovdan
// ishlatiladi, shuning uchun mutex (GB-4.07). Kalitlar oʻchirilmaydi: uzoq ishlaydigan serverda
// map oʻsib boradi — tozalash 🟡 ixtiyoriy vazifada (TASK.md, sweep).
type limiters struct {
	mu    sync.Mutex
	m     map[string]*rate.Limiter
	every rate.Limit
	burst int
}

// newLimiters — har kalitga: boshida burst ta urinish, keyin har every'da bittadan.
func newLimiters(every time.Duration, burst int) *limiters {
	return &limiters{m: map[string]*rate.Limiter{}, every: rate.Every(every), burst: burst}
}

// get — kalitning chelagi; birinchi murojaatda yangisi (toʻla) yaratiladi.
func (l *limiters) get(key string) *rate.Limiter {
	l.mu.Lock()
	defer l.mu.Unlock()
	lim, ok := l.m[key]
	if !ok {
		lim = rate.NewLimiter(l.every, l.burst)
		l.m[key] = lim
	}
	return lim
}

// wait — 0: urinish mumkin (token olindi). Aks holda — keyingi token qancha vaqtdan keyin.
// Reserve navbat oladi, Delay — shu navbatgacha kutish; biz kutmaymiz: Cancel tokenni qaytaradi.
func (l *limiters) wait(key string) time.Duration {
	res := l.get(key).Reserve()
	d := res.Delay()
	if d > 0 {
		res.Cancel()
	}
	return d
}

// limitByIP — middleware (GB-6.01 shakli): kalit — mijozning IP manzili. r.RemoteAddr — TCP ulanishning
// manzili («IP:port»), uni mijoz soxtalashtira olmaydi. X-Forwarded-For sarlavhasiga ishonmaymiz: uni
// har kim yozadi. Server proksi (Caddy, GB-8.06) ortida boʻlsa, RemoteAddr — proksining manzili: hamma mijoz bitta
// chelakka tushadi. U holda IP'ni faqat ishonchli proksi yozgan sarlavhadan olish kerak (GB-8.06).
// net/http serveri RemoteAddr'ni doim «IP:port» qiladi, shuning uchun SplitHostPort xatosi bu yerda kutilmaydi.
// Eslatma: IPv6'da bitta foydalanuvchida odatda butun /64 tarmoq boʻladi — production'da kalitni /64 boʻyicha olish mumkin.
func (l *limiters) limitByIP(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		ip, _, _ := net.SplitHostPort(r.RemoteAddr)
		if d := l.wait(ip); d > 0 {
			tooManyRequests(w, d)
			return
		}
		next.ServeHTTP(w, r)
	})
}

// tooManyRequests — 429 problem va Retry-After butun soniyalarda, yuqoriga yaxlitlangan.
func tooManyRequests(w http.ResponseWriter, d time.Duration) {
	w.Header().Set("Retry-After", strconv.Itoa(int(math.Ceil(d.Seconds()))))
	writeProblem(w, newProblem(http.StatusTooManyRequests, "urinishlar koʻp: keyinroq qayta urinib koʻring"))
}
```

| Lines | What it does |
|---|---|
| 10–19 | the `import`s; `rate` is `golang.org/x/time/rate` |
| 24–29 | `limiters`: `m` is key (IP or email) → one bucket (`*rate.Limiter`); `mu` is a mutex, because many requests use the `map` at the same time (GB-4.07); `every` is the interval between tokens (type `rate.Limit`), `burst` is the bucket size |
| 32–34 | `newLimiters`: `rate.Every(every)` creates the rate "one token every `every`" |
| 37–46 | `get`: the key's bucket; for a new key `rate.NewLimiter` creates a full bucket |
| 50–57 | `wait`: `Reserve` takes a place in the queue (a token is taken), `Delay` is the wait time until that place (`time.Duration`). We will not wait: if `d > 0`, `Cancel` returns the token. The function returns `0` (allowed) or the wait time |
| 65–74 | `limitByIP`: middleware (the shape from GB-6.01). `r.RemoteAddr` is the TCP connection's address, `"IP:port"`; `net.SplitHostPort` extracts the IP, the port and the error are thrown into `_`. If `wait(ip) > 0`: `429`, `return` |
| 77–80 | `tooManyRequests`: writes `Retry-After` in whole seconds: `math.Ceil` rounds up (`11.9` → `12`), `strconv.Itoa` turns a whole number into text. The response is the problem JSON from GB-6.02 |

Why is `Cancel` needed? `Reserve` takes a place in the queue even when tokens are short (it borrows a future token). So that a rejected attempt does not drain the bucket further, `Cancel` reverses its effect (the package documentation says "as much as possible"). Otherwise every rejected attempt would push the next permission later.

`limitByIP` wraps `requireJSON` in the route, so it runs **before** argon2id:

```go

```

And `api.loginIP` is created in `newMux`: `newLimiters(12*time.Second, 5)` means five attempts, then one every 12 seconds (`handlers.go`, `loginIP: newLimiters(12*time.Second, 5)`).

## Going deeper (optional): the limits

- **A request without headers passes (fail-open).** Because of rule 4 in `Check`, a request with neither `Sec-Fetch-Site` nor `Origin` passes, so that curl and mobile apps work. For sensitive endpoints OWASP recommends the opposite (fail-safe: no header means reject). Modern browsers have sent `Sec-Fetch-Site` since 2023 (OWASP), so for a browser this decision is not dangerous.
- **The scheme is not compared when `Origin` and `Host` are compared.** Rule 3 cannot tell a cross-origin request from HTTP to HTTPS. The comment in the Go source names the answer: HTTPS and HSTS (GB-8.06).
- **Fetch Metadata is sent only to trustworthy addresses:** `https`, `wss`, `file`, `localhost` and `127.0.0.0/8` (OWASP). In production HTTPS is required; on plain HTTP only the `Origin` check remains.
- **A cookie without `SameSite`.** RFC 6265bis: if the attribute is missing or unknown, the default mode equals `Lax`. A browser (`MAY`) may also apply the `Lax-allowing-unsafe` mode to a recently created cookie: it sends it on a top-level `POST` from another site; the RFC suggests a cookie age of 2 minutes or less. So always write the attribute explicitly.
- **A CSRF token** (synchronizer or signed double-submit) is the classic way. OWASP calls `Sec-Fetch-Site` the primary signal of a Fetch Metadata policy, and when the header is missing it advises an `Origin` check and, if needed, a token.
- **XSS defeats every CSRF protection** (OWASP): a script that gets onto the page sends requests from the same origin. `HttpOnly` only stops stealing the token.
- **The limits are in memory** and belong to one process. With several server instances you need a shared counter (for example Redis). Keys come from the client (IP, email), and a `map` that is never cleaned keeps growing: the homework's `sweep` cleans it.
- **Limits of an IP key.** Many users behind one NAT share one bucket. In IPv6 one client usually has a whole `/64` network (in production the key can be taken by `/64`).
- **DoS through lockout.** An email limit also lets an attacker lock Dilnoza out (OWASP, "Account Lockout"). That is why the email limit is softer than the IP limit: 10 attempts, then one per minute.

## Common mistakes

**1. "I set `SameSite=Lax`, so CSRF is closed."** We saw above: `Lax` stops a `POST` from **another site**, but not a neighbour port or a subdomain inside the same site. And with `None` the cookie goes from everywhere. The result: `200`, the order is cancelled (the table, three rows). The right way: keep `Lax` **and** use `protectCSRF` (`CrossOriginProtection`) on the server.

**2. Treating CORS as server protection.** The real output: the foreign page got `TypeError: Failed to fetch`, but the log had `GET "/me" 200 … cookie=true`: the request ran. The error is visible in the browser, but the server worked. The right way: `protectCSRF` stops the state-changing request, and reading data is protected by authentication (`requireUser`) and the ownership check (GB-6.06).

**3. Returning `Origin` without checking it.** The real output: the page read Dilnoza's data (`oʻqildi: {"id":1,…}`). The cause: `Allow-Origin` was taken from the request's `Origin` and `Allow-Credentials: true` was added. The right way: the `allowedOrigins` list, the `if !allowed[origin]` check in the `cors` code, `Vary: Origin` in every response. `Allow-Origin: *` cannot be used together with `Allow-Credentials`: the browser rejects such a response (OWASP).

**4. `X-Forwarded-For` as the IP key.** This is not in the folder, it is my extra experiment: three lines were added to `limitByIP` (in the scratch copy; the code in the folder is unchanged).

```go

			ip = xff // XATO: sarlavhani mijoz yozadi
		}

			return

}
```

## Check yourself

**1.** Why did the page at `localhost:9090` get the `Lax` cookie, even though the cookie is `Lax`?

<details>
<summary>Answer</summary>

A port does not change the site: `localhost:9090` and bozor (`localhost:8765`) are **one site**. `SameSite` limits only requests started from another site; inside one site the cookie goes with every request. That is why the server must check `Sec-Fetch-Site` and `Origin`: `Sec-Fetch-Site: same-site` is rejected in `CrossOriginProtection`.

</details>

**2.** Why is CORS not server protection?

<details>
<summary>Answer</summary>

CORS controls only **reading** the response. The request reaches the server and runs: the log had `GET "/me" 200 … cookie=true`, and the page still got `Failed to fetch`. The state-changing request is stopped by `protectCSRF`.

</details>

**3. GB-6.04.** Why does an old copy of the cookie get `401` after logout?

<details>
<summary>Answer</summary>

Logout deleted the session record on the server. On every request the server looks up the record by the hash of the token from the cookie and does not find it: `requireUser` returns `401`. The cookie itself (in the browser or in `jar.txt`) proves nothing.

</details>

**4. Predict.** On the `final` server Dilnoza logs in with the **right** password from one IP six times in a row. What are the statuses?

<details>
<summary>Answer</summary>

`200 200 200 200 200 429`. The limit counts attempts, not whether the password is right: in the route `limitByIP` stands before `login`. For the sixth attempt there is no token. The output "The limit counts all attempts" above shows it.

</details>

**5. Predict.** `curl -X POST -b jar.txt -H 'Origin: http://localhost:9090' localhost:8765/orders/41/cancel` (without `Sec-Fetch-Site`): the result?

<details>
<summary>Answer</summary>

`403`. `Sec-Fetch-Site` is missing, so rule 3 applies: the host in `Origin` (`localhost:9090`) differs from the `Host` header (`localhost:8765`), rejected. The reason in the log: `cross-origin request detected, and/or browser is out of date: Sec-Fetch-Site is missing, and Origin does not match Host`.

</details>

`sweep` (🟡):

```go
func (l *limiters) sweep(now time.Time) int {
	l.mu.Lock()
	defer l.mu.Unlock()
	n := 0
	for key, lim := range l.m {
		if lim.TokensAt(now) >= float64(l.burst) {
			delete(l.m, key) // range ichida delete mumkin (Go spec: For statements with range clause)
			n++
		}
	}
	return n
}
```

`sweep` takes `mu` (other requests use the map at the same time), and if `TokensAt(now)` shows a key's bucket is full, it removes the key with `delete` (`delete` inside `range` is allowed). Removing a full bucket is safe: a new bucket is created full anyway. On a server it must be called periodically (a goroutine with a `time.Ticker`, GB-7.01).
