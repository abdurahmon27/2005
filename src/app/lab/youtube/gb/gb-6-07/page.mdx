## Nimani oʻrganasiz

Dilnoza bozor'ga login qildi. Keyin boshqa portdagi begona sahifada «Sovgʻani olish» tugmasini bosdi. Shu bosish bozor'dagi 41-buyurtmani bekor qildi, holbuki session cookie'si `SameSite=Lax` edi. Himoya nega ishlamadi?

**Bitta gʻoya:** brauzer cookie'ni soʻrovga **oʻzi** qoʻshadi, soʻrovni qaysi sahifa boshlaganidan qatʼi nazar. Cookie atributlari faqat «qachon qoʻshilsin»ni boshqaradi, `SameSite` esa *site*'ga qaraydi: port va subdomen site'ni oʻzgartirmaydi. Shuning uchun holatni oʻzgartiradigan soʻrovda server soʻrov **qayerdan** kelganini oʻzi tekshiradi. CORS faqat javobni **oʻqish**ni boshqaradi: soʻrov baribir bajariladi. Login esa urinishlar soni bilan cheklanadi.

Dars oxirida siz:

- `Set-Cookie`ning har atributi (`__Host-`, `Max-Age`, `HttpOnly`, `Secure`, `SameSite`) brauzerda nima qilishini haqiqiy Chrome'da koʻrasiz;
- boshqa sahifadagi oddiy HTML forma Dilnozaning buyurtmasini bekor qilishini qayta yaratib, `http.CrossOriginProtection` bilan `403`ga aylantirasiz;
- CORS'ni allow-list va `Vary: Origin` bilan sozlaysiz, `Origin`ni tekshirmay qaytarish xatosini oʻz koʻzingiz bilan koʻrasiz;
- `POST /login`ga IP boʻyicha token bucket limit qoʻyasiz (`429` va `Retry-After`), email boʻyicha ikkinchisini esa uy vazifasida oʻzingiz yozasiz.

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| `SameSite` | cookie'ni boshqa **site**'dan boshlangan soʻrovga qoʻshish-qoʻshmaslikni aytuvchi atribut | SameSite |
| CSRF | boshqa saytdagi sahifa foydalanuvchining brauzeri orqali, uning cookie'si bilan soʻrov yuboradi | cross-site request forgery |
| token bucket | har kalit (IP, email) uchun cheklangan token zaxirasi: har urinish bittasini oladi | token bucket |

Ikki yordamchi: `Sec-Fetch-Site` va `Origin` sarlavhalari (soʻrovni kim boshlagani) hamda **CORS** (brauzerning oʻqish qoidasi). Qolgan soʻzlar birinchi uchragan joyda izohlanadi.

## Cookie atributlari: brauzer uchun qoidalar

Cookie'ni saqlash va uni qaysi soʻrovga qoʻshishni brauzer hal qiladi. Server faqat `Set-Cookie` sarlavhasidagi **atributlar** bilan unga qoida beradi. Login javobini toʻliq koʻramiz (`-i` javob sarlavhalarini ham chiqaradi, `-c jar.txt` cookie'ni faylga saqlaydi). Serverni `final` papkasidan ishga tushiring, curl'ni shu papkada yurgizing:

```console
$ curl -s -i -c jar.txt localhost:8765/login -H "Content-Type: application/json" --data-binary @login.json | mask
HTTP/1.1 200 OK
Cache-Control: no-store
Content-Type: application/json
Set-Cookie: __Host-session=[redacted]; Path=/; Max-Age=86400; HttpOnly; Secure; SameSite=Lax
Vary: Origin
X-Request-Id: GLYOPBEPBDRKAICL3Q3V6FD3N7
Date: Sat, 28 Nov 2026 09:24:10 GMT
Content-Length: 38

{"id":1,"email":"[email]"}
```

Soʻrov ID'si, sana va token har yurishda boshqa. Token oʻrniga `[redacted]` turibdi: uni `mask` almashtirdi. `Cache-Control: no-store` GB-6.04'dan tanish; `Content-Type`, `Content-Length`, `Date` — oddiy HTTP sarlavhalari (GB-4.01). `Vary: Origin` shu darsda qoʻshildi, CORS boʻlimida tushuntiraman. Diqqat `Set-Cookie` qatorida. GB-6.04'dagi bilan solishtirsangiz, ikki joy oʻzgargan: nom oldiga `__Host-` prefiksi qoʻshildi va `Expires` oʻrniga `Max-Age` keldi. Qolgan atributlar oʻsha.

| Qism | Brauzer nima qiladi |
|---|---|
| `__Host-session` | `__Host-` bilan boshlangan nomli cookie'ni brauzer faqat uchta shart bajarilsa qabul qiladi (pastga qarang) |
| `Path=/` | cookie saytning hamma yoʻllariga qoʻshiladi |
| `Max-Age=86400` | brauzer cookie'ni 86400 soniya, ya'ni 24 soat saqlaydi |
| `HttpOnly` | sahifadagi skript cookie'ni `document.cookie` orqali oʻqiy olmaydi |
| `Secure` | cookie faqat HTTPS orqali yuboriladi; `http://localhost` — istisno |
| `SameSite=Lax` | boshqa site'dan boshlangan soʻrovga cookie qoʻshilishi cheklanadi (keyingi boʻlimlarda) |

Bu atributlar `setSessionCookie`da qanday yoziladi:

```go
func setSessionCookie(w http.ResponseWriter, token string) {
	http.SetCookie(w, &http.Cookie{
		Name:     sessionCookie,
		Value:    token,
		Path:     "/",
		MaxAge:   int(sessionTTL.Seconds()),
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
	w.Header().Set("Cache-Control", "no-store")
}
```

| Kod | Nima qiladi |
|---|---|
| `Name: sessionCookie` | cookie nomi; bu konstantaning qiymati `"__Host-session"` |
| `MaxAge: int(sessionTTL.Seconds())` | `sessionTTL` — `24 * time.Hour`; `Seconds()` uni soniyaga (`86400`) aylantiradi, `int` butun son qiladi |
| `HttpOnly: true`, `Secure: true` | mos atributlarni yozadi |
| `SameSite: http.SameSiteLaxMode` | `SameSite=Lax` yozadi; GB-6.04'da u faqat nomlangan edi |
| `w.Header().Set("Cache-Control", "no-store")` | javob keshda qolmasin (GB-6.04) |

**`Max-Age`** — soniyalarda *nisbiy* muddat: brauzer uni oʻzining hozirgi vaqtiga qoʻshib hisoblaydi. `Expires` esa aniq sana, uni brauzer oʻz soati bilan solishtiradi, soat xato boʻlsa muddat ham siljiydi. Ikkalasi berilsa, `Max-Age` ustun (RFC 6265bis §4.1.2.2). Brauzer muddatni qisqartirishi ham mumkin, shuning uchun serverdagi session muddati (`sessionTTL`, GB-6.04) asosiy qoladi.

**`__Host-` prefiksi** brauzerga shart qoʻyadi: cookie `Secure` boʻlsin, `Path=/` boʻlsin va `Domain` atributi boʻlmasin. `Domain`siz cookie *host-only* boʻladi: u faqat oʻzi berilgan host'ga qaytadi, subdomenlarga emas. Natija: `blog.bozor.uz` bozor'ning `__Host-session` cookie'sini ustidan yozib qoʻya olmaydi. Cheklov host'ga tegishli, portga emas: RFC 6265bis aytadi, portlar `__Host-` cookie'lar eʼtiborsiz qoldiradigan yagona qism.

Curl bu cookie'ni qanday saqladi? `jar.txt`ning oxirgi qatori:

```console
$ tail -1 jar.txt | mask
#HttpOnly_localhost	FALSE	/	TRUE	1795944250	__Host-session	[redacted]
```

Qator tab bilan ajratilgan yetti ustun: domen (`#HttpOnly_` belgisi — cookie `HttpOnly`), subdomenlar ham qabul qiladimi (`FALSE` — yoʻq, `Domain` yoʻq edi), yoʻl, `Secure` (`TRUE`), tugash vaqti (epoch soniyalarda: curl `Max-Age`ni mutlaq vaqtga aylantirdi), nom, qiymat. Curl `http://localhost` uchun `Secure` cookie'ni ham saqlaydi va qaytaradi: localhost istisno (MDN, Set-Cookie).

### HttpOnly: haqiqiy brauzerda

`HttpOnly`ni curl bilan koʻrsatib boʻlmaydi: curl'da sahifa skripti yoʻq. Shuning uchun haqiqiy Chrome kerak. U oynasiz (**headless**) ishlaydi va uni `_video/brauzer`dagi Go dasturi **chromedp** kutubxonasi orqali boshqaradi. Bu dastur darsning mavzusi emas: u brauzerni boshqaradi va natijani chop etadi. `httponly` buyrugʻi bozor sahifasida Dilnoza sifatida login qiladi (brauzer cookie'ni oʻzi saqlaydi), keyin sahifa skripti bilan ikki narsa qiladi. Serverni `final`dan ishga tushirib, brauzer papkasida:

```console
$ go run . httponly | mask
login: 200 {"id":1,"email":"[email]"}
document.cookie: ""
fetch /me: 200 {"id":1,"email":"[email]"}
```

1. `login: 200 …` — login ishladi, brauzerda cookie bor.
2. `document.cookie: ""` — skript cookie'larni `document.cookie` bilan oʻqiydi va boʻsh qatorni oladi: `HttpOnly` shuni qiladi.
3. `fetch /me: 200 …` — `fetch` brauzerning soʻrov funksiyasi. U `/me`ga soʻrov yuboradi va brauzer cookie'ni oʻzi qoʻshadi: javob `200`.

Xulosa: sahifaga tushgan zararli skript tokenni **oʻgʻirlay olmaydi**, lekin sahifa ochiq turganda Dilnoza nomidan soʻrov yubora oladi. `HttpOnly` birinchisidan himoya qiladi, ikkinchisidan emas.

## Origin va site: cookie qachon «boshqa joydan» deb hisoblanadi

`SameSite` ishlashi uchun «boshqa joydan» nima ekanini aniq bilish kerak. Ikkita tushuncha bor.

**Origin** — sxema, host va port birgalikda: `http://localhost:8765`. Bittasi farq qilsa, origin boshqa.

**Site** — sxema va *roʻyxatdan oʻtgan domen* (registrable domain): Public Suffix List'dagi yozuv va undan oldingi bitta qism, masalan `bozor.uz`. **Port hisobga olinmaydi.** `localhost` va IP manzil kabi hostlarda roʻyxatdan oʻtgan domen yoʻq: ularda butun host teng boʻlishi kerak (HTML Standard, «same site»). Sxema ham qaraladi: cookie qoidalarida `http://` va `https://` turli site (MDN, Site).

| Bir sahifa | Boshqa sahifa | Origin | Site |
|---|---|---|---|
| `http://localhost:8765` | `http://localhost:8765/me` | bir xil | bir xil |
| `http://localhost:8765` | `http://localhost:9090` | **boshqa** (port) | **bir xil** (port hisobga olinmaydi) |
| `https://app.bozor.uz` | `https://blog.bozor.uz` | boshqa (host) | **bir xil** (`bozor.uz`) |
| `http://localhost:8765` | `http://127.0.0.1:9090` | boshqa | **boshqa** (host boshqa) |
| `http://localhost` | `https://localhost` | boshqa | boshqa (sxema boshqa) |

Laboratoriyadagi begona sayt bitta serverdan ikki nom bilan ochiladi: `http://localhost:9090` (bozor bilan **bir site**, boshqa origin) va `http://127.0.0.1:9090` (**boshqa site**). Birinchisi tarmoq ichidagi qoʻshni xizmatni modellaydi (qoʻshni port yoki subdomen), ikkinchisi — oddiy begona saytni.

## SameSite: cookie qachon qoʻshiladi

`SameSite` cookie'ni **boshqa site'dan boshlangan** soʻrovga qoʻshish-qoʻshmaslikni aytadi. Uch qiymat bor. Bir site ichida soʻrovning turidan qatʼi nazar cookie uchalasida ham ketadi.

| Boshqa site'dan boshlangan soʻrov | `Strict` | `Lax` | `None` (`Secure` shart) |
|---|---|---|---|
| havola bosilib ochilgan sahifa (yuqori darajadagi navigatsiya, `GET`) | ketmaydi | **ketadi** | ketadi |
| forma bilan `POST` | ketmaydi | ketmaydi | ketadi |
| `iframe` (sahifa ichidagi sahifa) yoki `fetch` | ketmaydi | ketmaydi | ketadi |

`Lax` — shu dars cookie'sining qiymati. Uning qoidasi: boshqa site'dan faqat yuqori darajadagi navigatsiyada xavfsiz metod (`GET`) bilan ketadi (RFC 6265bis §4.1.2.7). Shu jadvalga qarab bashorat qiling: begona sahifa boshqa site'da boʻlsa, `POST` forma nima oladi?

## CSRF: begona sahifadagi forma

Hujum sahifasi `cmd/begona`dagi `formaPage` konstantasida: oddiy HTML forma, skript yoʻq.

```html
<form method="post" action="http://localhost:8765/orders/41/cancel">
  <button>Sovgʻani olish</button>
</form>
```

| Qator | Nima qiladi |
|---|---|
| `<form method="post" action="…">` | forma yuborilganda brauzer `POST` soʻrov yuboradi; `action` — qayerga: bozor'ning bekor qilish yoʻli |
| `<button>Sovgʻani olish</button>` | tugma; bosilsa brauzer formani yuboradi |
| `</form>` | forma tugadi |

Brauzer formani yuborganda bozor'ning cookie'larini, `SameSite` ruxsat bersa, **oʻzi** qoʻshadi. Bu route'da body yoʻq, shuning uchun `requireJSON` ham yoʻq (GB-6.01): oddiy forma ham unga yetib keladi. Bu — `cancelOrder` route'i:

```go
	mux.Handle("POST /orders/{id}/cancel", a.requireUser(http.HandlerFunc(a.cancelOrder)))
```

| Qadam | Kim | Nima |
|---|---|---|
| 1 | Dilnoza | bozor'ga login qiladi; brauzer cookie'ni saqlaydi |
| 2 | Dilnoza | begona sahifani ochadi |
| 3 | Dilnoza | «Sovgʻani olish»ni bosadi |
| 4 | brauzer | formani `POST /orders/41/cancel` qilib yuboradi, cookie'ni (ruxsat boʻlsa) oʻzi qoʻshadi |
| 5 | bozor | cookie toʻgʻri, egalik toʻgʻri: buyurtma bekor |

### Server logiga ikki yangi maydon

Soʻrovni kim boshlaganini koʻrish uchun `logRequests`ga ikki maydon qoʻshildi:

```go
		_, err := r.Cookie(sessionCookie)
		log.Printf("%s %s %q %d %s site=%q cookie=%t", w.Header().Get("X-Request-Id"),
			r.Method, r.URL.Path, rec.status, time.Since(start), r.Header.Get("Sec-Fetch-Site"), err == nil)
```

`site=` — `Sec-Fetch-Site` sarlavhasi: brauzer uni HTTPS yoki localhost manzillariga har soʻrovda oʻzi qoʻshadi va unda soʻrovni qaysi sahifa boshlagani yoziladi. Qiymatlari: `same-origin`, `same-site`, `cross-site`, `none` (manzil qatoriga yozilgan yoki xatchoʻpdan ochilgan). `cookie=` — session cookie keldimi (`true`/`false`). `r.Header.Get` sarlavhani oʻqiydi, `err == nil` cookie borligini bildiradi (GB-6.04).

### Bashorat: boshqa site'dan forma

Begona sahifani endi `127.0.0.1` orqali, ya'ni **boshqa site**'da ochamiz. Cookie `SameSite=Lax`. «Sovgʻani olish» bosilsa, nima boʻladi? **A)** `200`, buyurtma bekor boʻldi · **B)** `401`, cookie kelmadi · **C)** `403`, ruxsat yoʻq.

<details>
<summary>Javob</summary>

**B.** `Lax` boshqa site'dan kelgan forma `POST`ida cookie'ni qoʻshmaydi (jadvalning ikkinchi qatori). Cookie yoʻq: `requireUser` `401` beradi (GB-6.04). A — buyurtma bekor boʻlishi uchun cookie kerak edi. C — `403` GB-6.06'da rolga ruxsat boʻlmaganda chiqadi, bu yerda esa server Dilnozani umuman tanimadi.

</details>

Bu dastur darsdan oldingi bozor (`himoyasiz` nusxasi): CSRF tekshiruvi hali yoʻq. Server `himoyasiz`dan, begona sayt `go run ./cmd/begona` bilan ishlasin. Brauzer dasturining `csrf` buyrugʻi sahifani ochadi, tugmani bosadi va javobni chop etadi:

```console
$ go run . csrf http://127.0.0.1:9090 | mask
login: 200 {"id":1,"email":"[email]"}
sahifa: http://127.0.0.1:9090 → «Sovgʻani olish» bosildi
javob: {"type":"about:blank","title":"Unauthorized","status":401,"detail":"avval login qiling","request_id":"ACVH6PKV4N4FAPNLU3FZIDAK5C"}
GET /orders/41: {"id":41,"user_id":1,"status":"yangi","note":"Chilonzor 9-kvartal, 12-uy"}
```

Javob `401`, buyurtma 41 hamon `yangi`. Server logi (`grep` login, health va favicon shovqinini olib tashlaydi):


## Server himoyasi: http.CrossOriginProtection

Server holatni oʻzgartiradigan soʻrovning **qayerdan** kelganini oʻzi tekshiradi. Go 1.25'dan beri buning uchun standart kutubxonada `http.CrossOriginProtection` bor; OWASP CSRF Prevention Cheat Sheet uni nomlab koʻrsatadi. U brauzer yuboradigan ikki sarlavhaga tayanadi: `Sec-Fetch-Site` (yuqorida koʻrdik) va `Origin` (soʻrovni boshlagan sahifaning origin'i; brauzer uni `POST`da qoʻshadi).

```go
var allowedOrigins = []string{"http://localhost:3000"}

// errCrossOrigin — soʻrov boshqa origin'dagi sahifadan kelgan (problemFor → 403).
var errCrossOrigin = errors.New("boshqa saytdan kelgan soʻrov")

// protectCSRF — Go 1.25'dan beri standart kutubxonadagi http.CrossOriginProtection bilan:
//   - GET, HEAD, OPTIONS — har doim oʻtadi (ular holatni oʻzgartirmasligi kerak);
//   - Sec-Fetch-Site: same-origin yoki none (manzil qatoriga yozilgan) — oʻtadi; boshqa qiymat — rad;
//   - Sec-Fetch-Site yoʻq, Origin bor — Origin'ning host'i Host sarlavhasiga teng boʻlsa oʻtadi;
//   - ikkalasi ham yoʻq — Go buni brauzer emas deb hisoblaydi (curl, mobil ilova, boshqa server): oʻtadi (fail-open);
//   - AddTrustedOrigin'dagi origin'lar — oʻtadi.
//
// Origin ↔ Host solishtiruvida sxema (http/https) koʻrilmaydi: production'da HTTPS + HSTS (GB-8.06).
//
// Brauzer bo'lmagan mijozda begona cookie yoʻq: CSRF — aynan brauzer cookie'ni oʻzi qoʻshgani uchun xavf.
// Rad sababi (Check'ning xatosi) log'ga, mijozga — bizning matn (GB-6.02).
func protectCSRF(next http.Handler) http.Handler {
	cop := http.NewCrossOriginProtection()
	for _, o := range allowedOrigins {
		if err := cop.AddTrustedOrigin(o); err != nil {
			panic(err) // roʻyxat kodimizda: notoʻgʻri yozilgan boʻlsa server ishga tushmasin
		}
	}
```

| Kod | Nima qiladi |
|---|---|
| `var allowedOrigins = []string{…}` | ruxsat berilgan origin'lar roʻyxati: bozor'ning oʻz veb ilovasi, `http://localhost:3000` |
| `func protectCSRF(next http.Handler) http.Handler` | middleware (GB-6.01 shakli) |
| `cop := http.NewCrossOriginProtection()` | tekshiradigan obyekt yasaydi |
| `for _, o := range allowedOrigins` | roʻyxatdagi har origin uchun |
| `cop.AddTrustedOrigin(o)` | uni **ishonchli** origin'larga qoʻshadi; yozilishi notoʻgʻri boʻlsa (sxema yoʻq, yoʻl bor) xato qaytaradi |
| `panic(err)` | roʻyxat bizning kodimizda: xato boʻlsa server ishga tushmasin (GB-2.09) |

Asosiy qism — qaytarilgan handler:

```go
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if err := cop.Check(r); err != nil {
			writeError(w, fmt.Errorf("%w: %w", errCrossOrigin, err))
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

| Kod | Nima qiladi |
|---|---|
| `cop.Check(r)` | soʻrovni tekshiradi; rad etilsa xato qaytaradi |
| `fmt.Errorf("%w: %w", errCrossOrigin, err)` | ikki xatoni birlashtiradi: bizning matn va `Check`ning sababi (GB-6.02) |
| `writeError(w, …)` | `403` problem javobi yozadi: mijozga bizning matn, sabab esa logga |
| `next.ServeHTTP(w, r)` | tekshiruv oʻtdi, handler ishlaydi |

`Check` qoidalari (Go 1.27.4 manbasi, `net/http/csrf.go`):

1. `GET`, `HEAD`, `OPTIONS` — **doim oʻtadi**: bu metodlar holatni oʻzgartirmasligi kerak. Shuning uchun GET'da holat oʻzgartirmang.
2. `Sec-Fetch-Site: same-origin` yoki `none` — oʻtadi. Boshqa qiymat (`same-site`, `cross-site`) — **rad**, agar `Origin` ishonchli roʻyxatda boʻlmasa yoki yoʻl `AddInsecureBypassPattern` bilan istisno qilinmagan boʻlsa.
3. `Sec-Fetch-Site` yoʻq, `Origin` bor — `Origin`ning host'i (port bilan) `Host` sarlavhasiga teng boʻlsa oʻtadi, aks holda rad. Sxema solishtirilmaydi.
4. Ikkalasi ham yoʻq — soʻrov brauzerdan emas yoki bir origin'dan deb hisoblanadi va **oʻtadi**.

Zanjirdagi oʻrni: `requestID → logRequests → recoverPanic → cors → protectCSRF → muxErrors → mux` (`cmd/api/middleware.go`, `newHandler`).

## CORS: javobni oʻqish qoidasi

Aytmasa, brauzer javobni sahifaga bermaydi. Cookie bilan soʻrovda yana `Access-Control-Allow-Credentials: true` kerak. Bu qoida serverni himoya **qilmaydi**: soʻrov baribir bajariladi. ### Tez-tez uchraydigan xato: Origin'ni qaytarish

Dasturchilar ruxsat bermoqchi boʻladi va roʻyxat oʻrniga soʻrovdagi `Origin`ning oʻzini qaytaradi, `Allow-Credentials: true` bilan. Bu `aks` nusxasidagi kod:

```go
func cors(next http.Handler) http.Handler {
```

### Toʻgʻrisi: allow-list

Ruxsat etilgan origin'lar roʻyxati (**allow-list**) — `protectCSRF` ishlatadigan oʻsha `allowedOrigins`. Bu `cors` middleware (yakuniy kod):

```go
func cors(next http.Handler) http.Handler {
	allowed := map[string]bool{}
	for _, o := range allowedOrigins {
		allowed[o] = true
	}
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Add("Vary", "Origin")
		origin := r.Header.Get("Origin")
		if !allowed[origin] {
			next.ServeHTTP(w, r)
			return
		}
		w.Header().Set("Access-Control-Allow-Origin", origin)
		w.Header().Set("Access-Control-Allow-Credentials", "true")
		// Preflight: brauzer haqiqiy soʻrovdan oldin OPTIONS bilan ruxsat soʻraydi (JSON body, PATCH, DELETE…).
		if r.Method == http.MethodOptions && r.Header.Get("Access-Control-Request-Method") != "" {
			w.Header().Set("Access-Control-Allow-Methods", "POST, PATCH, DELETE")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
			w.Header().Set("Access-Control-Max-Age", "600") // brauzer javobni 10 daqiqa eslab qoladi
			w.WriteHeader(http.StatusNoContent)
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

## Login'ga rate limit: token bucket

Har login urinishi argon2id hisoblaydi: GB-6.03'da koʻrdik, har urinish 46 MiB xotira va sezilarli CPU vaqti. Mening yurishimda logdagi bitta `POST "/login"` qatori `82.523656ms` koʻrsatdi. Cheklov boʻlmasa, `POST /login` parol taxmin qilish uchun ochiq va serverni band qilishning arzon yoʻli. Darsdan oldingi bozor (`himoyasiz`): bitta IP'dan ketma-ket sakkizta notoʻgʻri login. `for i in $(seq 8)` bash sikli buyruqni sakkiz marta takrorlaydi; curl'da `-o /dev/null` body'ni tashlaydi, `-w "%{http_code} "` faqat status kodini chiqaradi, `echo` qatorni yakunlaydi:

```console
$ for i in $(seq 8); do curl -s -o /dev/null -w "%{http_code} " localhost:8765/login -H "Content-Type: application/json" --data-binary @wrong.json; done; echo
401 401 401 401 401 401 401 401
```

Sakkizta `401`: taxminlar cheksiz. Yechim — **token bucket** («tokenli chelak»). Har kalit uchun (hozir IP) chelak bor: ichida eng koʻpi 5 token, bosh holatda toʻla. Har urinish bitta token oladi. Chelakka har 12 soniyada bitta token qaytadi. Token qolmasa — `429 Too Many Requests` va `Retry-After`: necha soniyadan keyin yana urinish mumkin.

| Urinish | Chelakda oldin | Natija | Chelakda keyin |
|---|---|---|---|
| 1 | 5 | `401` (parol xato, lekin urinish ruxsat) | 4 |
| 2 | 4 | `401` | 3 |
| 3 | 3 | `401` | 2 |
| 4 | 2 | `401` | 1 |
| 5 | 1 | `401` | 0 |
| 6, 7, 8 | 0 | `429`, `Retry-After` | 0 (token olinmaydi) |
| 12 soniyadan keyin | 0 → 1 | keyingi urinish `401` | 0 |

Kod `golang.org/x/time/rate` paketida: Go jamoasining token bucket'i (`go get golang.org/x/time/rate` bilan qoʻshilgan, GB-2.06; `go.mod`da `v0.16.0`). Toʻliq `cmd/api/ratelimit.go`:

```go filename="cmd/api/ratelimit.go" showLineNumbers
package main

// Login'ga rate limit (GB-6.07). Har login urinishi argon2id hisoblaydi (GB-6.03: 46 MiB xotira):
// cheklovsiz POST /login — parol taxmin qilish uchun ochiq eshik va serverni band qilishning arzon yoʻli.
//
// golang.org/x/time/rate — Go jamoasining token bucket'i: chelakda eng koʻpi `burst` ta token,
// har `every` vaqtda bittadan toʻladi; har soʻrov bitta token oladi; token yoʻq — 429 Too Many Requests
// (RFC 6585 §4) va Retry-After: necha soniyadan keyin qayta urinish mumkin (RFC 9110 §10.2.3).

import (
	"math"
	"net"
	"net/http"
	"strconv"
	"sync"
	"time"

	"golang.org/x/time/rate"
)

// limiters — har kalit (IP yoki email) uchun alohida chelak. Map bir vaqtda koʻp soʻrovdan
// ishlatiladi, shuning uchun mutex (GB-4.07). Kalitlar oʻchirilmaydi: uzoq ishlaydigan serverda
// map oʻsib boradi — tozalash 🟡 ixtiyoriy vazifada (TASK.md, sweep).
type limiters struct {
	mu    sync.Mutex
	m     map[string]*rate.Limiter
	every rate.Limit
	burst int
}

// newLimiters — har kalitga: boshida burst ta urinish, keyin har every'da bittadan.
func newLimiters(every time.Duration, burst int) *limiters {
	return &limiters{m: map[string]*rate.Limiter{}, every: rate.Every(every), burst: burst}
}

// get — kalitning chelagi; birinchi murojaatda yangisi (toʻla) yaratiladi.
func (l *limiters) get(key string) *rate.Limiter {
	l.mu.Lock()
	defer l.mu.Unlock()
	lim, ok := l.m[key]
	if !ok {
		lim = rate.NewLimiter(l.every, l.burst)
		l.m[key] = lim
	}
	return lim
}

// wait — 0: urinish mumkin (token olindi). Aks holda — keyingi token qancha vaqtdan keyin.
// Reserve navbat oladi, Delay — shu navbatgacha kutish; biz kutmaymiz: Cancel tokenni qaytaradi.
func (l *limiters) wait(key string) time.Duration {
	res := l.get(key).Reserve()
	d := res.Delay()
	if d > 0 {
		res.Cancel()
	}
	return d
}

// limitByIP — middleware (GB-6.01 shakli): kalit — mijozning IP manzili. r.RemoteAddr — TCP ulanishning
// manzili («IP:port»), uni mijoz soxtalashtira olmaydi. X-Forwarded-For sarlavhasiga ishonmaymiz: uni
// har kim yozadi. Server proksi (Caddy, GB-8.06) ortida boʻlsa, RemoteAddr — proksining manzili: hamma mijoz bitta
// chelakka tushadi. U holda IP'ni faqat ishonchli proksi yozgan sarlavhadan olish kerak (GB-8.06).
// net/http serveri RemoteAddr'ni doim «IP:port» qiladi, shuning uchun SplitHostPort xatosi bu yerda kutilmaydi.
// Eslatma: IPv6'da bitta foydalanuvchida odatda butun /64 tarmoq boʻladi — production'da kalitni /64 boʻyicha olish mumkin.
func (l *limiters) limitByIP(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		ip, _, _ := net.SplitHostPort(r.RemoteAddr)
		if d := l.wait(ip); d > 0 {
			tooManyRequests(w, d)
			return
		}
		next.ServeHTTP(w, r)
	})
}

// tooManyRequests — 429 problem va Retry-After butun soniyalarda, yuqoriga yaxlitlangan.
func tooManyRequests(w http.ResponseWriter, d time.Duration) {
	w.Header().Set("Retry-After", strconv.Itoa(int(math.Ceil(d.Seconds()))))
	writeProblem(w, newProblem(http.StatusTooManyRequests, "urinishlar koʻp: keyinroq qayta urinib koʻring"))
}
```

|---|---|
| 10–19 | `import`lar; `rate` — `golang.org/x/time/rate` |
| 24–29 | `limiters`: `m` — kalit (IP yoki email) → bitta chelak (`*rate.Limiter`); `mu` — mutex, chunki `map`ni koʻp soʻrov bir vaqtda ishlatadi (GB-4.07); `every` — token oraligʻi (`rate.Limit` turi), `burst` — chelak hajmi |
| 32–34 | `newLimiters`: `rate.Every(every)` «har `every`da bitta token» tezligini yasaydi |
| 37–46 | `get`: kalitning chelagi; yangi kalitga `rate.NewLimiter` toʻla chelak yasaydi |
| 50–57 | `wait`: `Reserve` navbat oladi (token olinadi), `Delay` — shu navbatgacha kutish vaqti (`time.Duration`). Kutmaymiz: `d > 0` boʻlsa `Cancel` tokenni qaytaradi. Funksiya `0` (mumkin) yoki kutish vaqtini qaytaradi |

## Chuqurroq (ixtiyoriy): chegaralar

- **Sarlavhasiz soʻrov oʻtadi (fail-open).** `Check` 4-qoidasi tufayli `Sec-Fetch-Site` ham, `Origin` ham yoʻq soʻrov oʻtadi: curl va mobil ilovalar ishlashi uchun. OWASP sezgir endpoint'larda teskarisini (fail-safe: sarlavha yoʻq — rad) tavsiya qiladi. Zamonaviy brauzerlar `Sec-Fetch-Site`ni 2023-yildan beri yuboradi (OWASP), shuning uchun bu qaror brauzer uchun xavfli emas.
- **`Origin` va `Host` solishtirilganda sxema koʻrilmaydi.** HTTP'dan HTTPS'ga boʻlgan origin'lararo soʻrovni 3-qoida ajrata olmaydi. Go manbasidagi izoh yechimni aytadi: HTTPS va HSTS (GB-8.06).
- **Fetch Metadata faqat ishonchli manzillarga** yuboriladi: `https`, `wss`, `file`, `localhost` va `127.0.0.0/8` (OWASP). Production'da HTTPS shart; oddiy HTTP'da faqat `Origin` tekshiruvi qoladi.
- **`SameSite`siz cookie.** RFC 6265bis: atribut yoʻq yoki notanish boʻlsa, odatiy rejim `Lax`ga teng. Brauzer (`MAY`) yaqinda yaratilgan cookie uchun `Lax-allowing-unsafe` rejimini ham qoʻllashi mumkin: boshqa site'dan yuqori darajadagi `POST`ga yuboradi; RFC cookie yoshi 2 daqiqa yoki kamroq boʻlishini tavsiya etadi. Shuning uchun atributni har doim aniq yozing.
- **CSRF token** (synchronizer yoki signed double-submit) — klassik yoʻl. OWASP `Sec-Fetch-Site`ni Fetch Metadata siyosatining asosiy signali deydi, sarlavha topilmasa esa `Origin` tekshiruvi va kerak boʻlsa token bilan tekshirishni aytadi.
- **XSS hamma CSRF himoyasini yengadi** (OWASP): sahifaga tushgan skript soʻrovni bir origin'dan yuboradi. `HttpOnly` faqat tokenni oʻgʻirlashni toʻxtatadi.
- **Limitlar xotirada** va bitta jarayonga tegishli. Bir nechta server nusxasi boʻlsa, umumiy hisob kerak (masalan Redis). Kalitlar mijozdan keladi (IP, email), `map` oʻchirilmasa oʻsib boradi: uy vazifasidagi `sweep` shuni tozalaydi.
- **IP kaliti chegaralari.** Bitta NAT ortidagi koʻp foydalanuvchi bitta chelakni boʻlishadi. IPv6'da bitta mijozda odatda butun `/64` tarmoq boʻladi (production'da kalitni `/64` boʻyicha olish mumkin).
- **Lockout orqali DoS.** Email limiti hujumchiga Dilnozani bloklash imkonini ham beradi (OWASP, «Account Lockout»). Shuning uchun email limiti IP limitidan yumshoqroq: 10 urinish, keyin daqiqada bitta.

## Koʻp uchraydigan xatolar

**1. «`SameSite=Lax` qoʻydim, CSRF yopildi».** Yuqorida koʻrdik: `Lax` boshqa **site**'dan kelgan `POST`ni toʻxtatadi, lekin bir site ichidagi qoʻshni port yoki subdomenni emas. `None`da esa cookie hamma joydan ketadi. Natija: `200`, buyurtma bekor (jadval, uch qator). Toʻgʻrisi: `Lax`ni qoldiring **va** serverda `protectCSRF` (`CrossOriginProtection`) ishlating.

**2. CORS'ni server himoyasi deb bilish.** Real chiqish: begona sahifa `TypeError: Failed to fetch` oldi, lekin logda `GET "/me" 200 … cookie=true` bor edi: soʻrov bajarilgan. Xato koʻrinishi brauzerda, server esa ishlagan. Toʻgʻrisi: holat oʻzgartiradigan soʻrovni `protectCSRF` toʻxtatadi, ma'lumot oʻqishni esa autentifikatsiya (`requireUser`) va egalik tekshiruvi (GB-6.06).

**3. `Origin`ni tekshirmay qaytarish.** Real chiqish: sahifa Dilnozaning maʼlumotini oʻqidi (`oʻqildi: {"id":1,…}`). Sababi: `Allow-Origin` soʻrovdagi `Origin`dan olingan va `Allow-Credentials: true` qoʻshilgan. Toʻgʻrisi: `allowedOrigins` roʻyxati, `cors` kodidagi `if !allowed[origin]`, har javobda `Vary: Origin`. `Allow-Origin: *` bilan `Allow-Credentials` ishlatib boʻlmaydi: brauzer bunday javobni rad etadi (OWASP).

**4. IP kaliti sifatida `X-Forwarded-For`.** Bu papkada yoʻq, mening qoʻshimcha tajribam: `limitByIP`ga quyidagi uch qator qoʻshildi (vaqtinchalik nusxada; papkadagi kod oʻzgarmagan).

```go
func (l *limiters) limitByIP(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		ip, _, _ := net.SplitHostPort(r.RemoteAddr)
		if xff := r.Header.Get("X-Forwarded-For"); xff != "" {
			ip = xff // XATO: sarlavhani mijoz yozadi
		}
		if d := l.wait(ip); d > 0 {
			tooManyRequests(w, d)
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

<details>
<summary>Javob</summary>

CORS faqat javobni **oʻqish**ni boshqaradi. Soʻrov serverga yetib boradi va bajariladi: logda `GET "/me" 200 … cookie=true` bor edi, sahifa esa baribir `Failed to fetch` oldi. Holat oʻzgartiradigan soʻrovni `protectCSRF` toʻxtatadi.

</details>

**3. GB-6.04.** Logout'dan keyin cookie'ning eski nusxasi nega `401` oladi?

<details>
<summary>Javob</summary>

Logout serverdagi session yozuvini oʻchirgan. Server har soʻrovda cookie'dagi token hash'i boʻyicha yozuvni qidiradi va topmaydi: `requireUser` `401` beradi. Cookie'ning oʻzi (brauzerda yoki `jar.txt`da) hech narsa isbotlamaydi.

</details>

**4. Bashorat.** `final` serverda Dilnoza **toʻgʻri** parol bilan bitta IP'dan ketma-ket 6 marta login qiladi. Statuslar qanday?

<details>
<summary>Javob</summary>

`200 200 200 200 200 429`. Limit urinishni sanaydi, parol toʻgʻriligini emas: `limitByIP` route'da `login`dan oldin turadi. Oltinchi urinishga token yetmaydi. Yuqoridagi «Limit hamma urinishni sanaydi» chiqishi shuni koʻrsatadi.

</details>

**5. Bashorat.** `curl -X POST -b jar.txt -H 'Origin: http://localhost:9090' localhost:8765/orders/41/cancel` (`Sec-Fetch-Site`siz): natija?

<details>
<summary>Javob</summary>

`403`. `Sec-Fetch-Site` yoʻq, shuning uchun 3-qoida: `Origin`ning host'i (`localhost:9090`) `Host` sarlavhasidan (`localhost:8765`) farq qiladi, rad. Logdagi sabab: `cross-origin request detected, and/or browser is out of date: Sec-Fetch-Site is missing, and Origin does not match Host`.

</details>

## Uy vazifasi

🟢 **Email boʻyicha ikkinchi limit.** Videodagi IP limiti bitta IP'ni cheklaydi. Hujumchi IP'ni almashtirsa (proksilar, botnet, IPv6), har yangi IP'ning chelagi toʻla: Dilnozaning paroliga taxminlar cheksiz davom etadi. OWASP Authentication Cheat Sheet: urinishlar hisoblagichi **hisobning oʻziga** bogʻlansin, manba IP'ga emas.

Spetsifikatsiya (papkadagi [TASK.md](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/gb-6-07-cookie-csrf-cors/TASK.md)dan):

- bitta email'ga: 10 urinish, keyin har daqiqada bittadan (`newLimiters(time.Minute, 10)`);
- email harf kattaligisiz: `Dilnoza@…` va `DILNOZA@…` bitta chelak;
- 11-urinish (har safar boshqa IP'dan) → `429` va `Retry-After`; boshqa email'ga oddiy `401`;
- tekshiruv argon2id'dan **oldin**: limitdan oshgan urinish serverni band qilmasin.

Nima qilish kerak: `cmd/api/handlers.go`dagi `api` struct'iga `loginEmail *limiters` maydoni va `newMux`da `newLimiters(time.Minute, 10)`; `cmd/api/auth.go`dagi `login`da `decodeJSON`dan keyin, `checkPassword`dan oldin email'ni `strings.ToLower` bilan kichik harfga oʻtkazing, `a.loginEmail.wait(…)`ni chaqiring, natija `0`dan katta boʻlsa `tooManyRequests(w, d)` va `return`. `handlers.go`da maydon va yaratilishi:

```go
type api struct {
	st         *store.Store
	loginIP    *limiters // GB-6.07: bitta IP'dan login urinishlari
	loginEmail *limiters // vazifa: bitta email'ga login urinishlari (IP'lar almashsa ham)
}

// newMux — hamma route'lar shu yerda: main ham, testlar ham bir xil mux'ni ishlatadi.
func newMux(st *store.Store) *http.ServeMux {
	a := &api{
		st:         st,
		loginIP:    newLimiters(12*time.Second, 5), // 5 ta urinish, keyin har 12 soniyada bittadan
		loginEmail: newLimiters(time.Minute, 10),   // 10 ta urinish, keyin har daqiqada bittadan
	}
```

`auth.go`dagi `login`da `decodeJSON`dan keyin, `checkPassword`dan oldin (importga `"strings"` qoʻshiladi):

```go
	// Vazifa: email boʻyicha limit — argon2id'dan oldin, harf kattaligisiz (users_email_lower_idx, GB-6.04).
	// OWASP Authentication Cheat Sheet: hujumchi IP'larni almashtirsa ham, bitta hisobga urinishlar cheklansin.
	if d := a.loginEmail.wait(strings.ToLower(in.Email)); d > 0 {
		tooManyRequests(w, d)
		return
	}
```

Kalit — kichik harfga oʻtkazilgan email: `Dilnoza@…` va `DILNOZA@…` bitta chelakka tushadi. Tekshiruv `checkPassword`dan oldin: argon2id hisoblanmaydi. IP limiti route'da email limitidan oldin turadi: avval IP, keyin email.

`sweep` (🟡):

```go
func (l *limiters) sweep(now time.Time) int {
	l.mu.Lock()
	defer l.mu.Unlock()
	n := 0
	for key, lim := range l.m {
		if lim.TokensAt(now) >= float64(l.burst) {
			delete(l.m, key) // range ichida delete mumkin (Go spec: For statements with range clause)
			n++
		}
	}
	return n
}
```

`sweep` `mu`ni ushlaydi (map'ni boshqa soʻrovlar bir vaqtda ishlatadi), har kalitning chelagida `TokensAt(now)` toʻla chelakni koʻrsatsa — kalitni `delete` bilan oʻchiradi (`range` ichida `delete` mumkin). Toʻla chelakni oʻchirish xavfsiz: yangi chelak baribir toʻla yaratiladi. Serverda uni vaqti-vaqti bilan chaqirish kerak (`time.Ticker` bilan goroutine'da, GB-7.01).
