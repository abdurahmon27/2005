## Что вы узнаете

`Store` (GB-2.06) держит каталог только в памяти: программа завершилась, и товары пропали. Работа с `bozor.json` (GB-3.02) осталась в отдельной программе. Как собрать эти части в одну программу командной строки, в **CLI** (command-line interface)? И как сделать её надёжной: чтобы файл не оставался недописанным даже при отключении питания, а молча испорченный остаток ловил тест?

**Одна идея:** bozor CLI выполняет одну команду в одном процессе. `main` только передаёт `os.Args` в `run(path, args, w)` и превращает ошибку в код выхода: 1 — ошибка, 2 — неверный вызов. `run` загружает каталог из `bozor.json`, выбирает команду через `switch`, вызывает правила из `internal/store` и сохраняет изменённый каталог **атомарно**: новый JSON сначала пишется во временный файл, затем `os.Rename` одним шагом ставит его на место `bozor.json`. Путь и `io.Writer` — параметры, поэтому тест вызывает весь CLI в своей папке и проверяет не вывод, а состояние каталога.

К концу урока вы:

- прочитаете CLI со структурой `cmd/bozor` + `internal/store` и объясните, почему `run(path, args, w)` делает весь CLI доступным для теста;
- различите код выхода 1 (ошибка) и 2 (неверный вызов);
- увидите, почему `os.WriteFile` может оставить недописанный файл, и прочитаете атомарное сохранение через `os.CreateTemp` + `Sync` + `os.Rename`;
- увидите, как табличный тест ловит настоящий баг, который `go vet` и `staticcheck` пропустили, а команду `bozor restock ID DONA` напишете сами, вместе с тестом.

Три основных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| структура CLI | `main` только передаёт аргументы и превращает ошибку в код выхода; вся работа в функции `run(path, args, w) error` | CLI structure (thin `main` + `run`) |
| атомарное сохранение | новый файл сначала пишется отдельно, затем имя меняется одним шагом: читатель видит либо старый, либо новый файл | atomic save |
| тест, проверяющий состояние | тест проверяет не значение, которое вернула функция, а состояние каталога (или файла) | state-checking test |

Вспомогательные слова объясняются одной фразой там, где встречаются: `t.TempDir()`, ширина в `fmt`, которая считается в рунах, временный файл.

Один вопрос по прошлому уроку. Итератор `All()` не проверяет результат `yield(p)`. Что будет с итератором на следующем товаре после `break` в цикле?

**A)** цикл продолжится · **B)** итератор тихо завершится · **C)** panic: программа упадёт

<details>
<summary>Ответ</summary>

**C.** При `break` `yield` возвращает `false`. Если итератор не проверит это и вызовет `yield` снова, функция, сгенерированная компилятором, вызовет панику. Если вы выбрали **A** или **B**, вы считали `yield` «необязательным»: нет, вызывать его после `false` запрещено. Поэтому `All` написан так: `if !yield(p) { return }`. Сегодняшний `list` тоже обходит каталог этим же итератором `All`.

</details>

## Структура: путь одной команды

Сначала форма готовой папки. `ls` выводит файлы двух папок (в терминале колонками; при выводе в файл каждый идёт отдельной строкой):

```console
$ ls cmd/bozor internal/store
cmd/bozor:
main.go  main_test.go

internal/store:
file.go  store.go  store_test.go
```

Структура такая же, как в GB-2.06:

| Файл | Зачем |
|---|---|
| `cmd/bozor/main.go` | `main`, `run`, команды (`add`, `list`, `order`) и тексты ошибок: часть, которая общается с пользователем |
| `cmd/bozor/main_test.go` | тесты CLI: вызывают `run` |
| `internal/store/store.go` | правила товара: `Product`, `validate`, `Add`, `All`, `find`, `Sell`, ошибки |
| `internal/store/file.go` | работа с `bozor.json`: `Load` и `Save` |
| `internal/store/store_test.go` | тесты store: табличные тесты и тесты `Save` |

Пакет из папки `internal/` может импортировать только этот модуль (GB-2.06). Путь одной команды, например `./bozor order 1 3`:

| Шаг | Кто | Что делает |
|---|---|---|
| 1 | `main` | передаёт `os.Args[1:]` (`order`, `1`, `3`) в `run` |
| 2 | `run` | загружает `bozor.json` (`store.Load`), выбирает `order` через `switch` |
| 3 | `st.Sell(1, 3)` | `internal/store`: проверяет правила и уменьшает остаток |
| 4 | `st.Save(path)` | записывает изменённый каталог в `bozor.json` |
| 5 | `main` | если `run` вернул ошибку, пишет её текст в stderr и ставит код выхода |

`main` нарочно тонкий: правил в нём нет. Весь CLI — функция `run`. Пользу этого вы увидите в разделе «Тесты».

## Запускаем: add, list, order

`go build ./cmd/bozor` собирает пакет `cmd/bozor`. Результат — один бинарник (GB-1.01), имя берётся из папки: `bozor`. Первая команда — `list`. Файла `bozor.json` ещё нет, `Load` считает это не ошибкой, а пустым каталогом.

```console
$ go build ./cmd/bozor
$ ./bozor list
katalog boʻsh: bozor add NOM NARX QOLDIQ
```

`go build` ничего не вывел: успех. `add` принимает название, цену в сумах и остаток. Программа сама выдаёт новый ID (наибольший ID + 1) и записывает каталог в `bozor.json`:

```console
$ ./bozor add olma 12000 40
qoʻshildi: 1. olma, 12000 soʻm, 40 dona
$ ./bozor add non 4000 3
qoʻshildi: 2. non, 4000 soʻm, 3 dona
$ ./bozor add choy 25000 8
qoʻshildi: 3. choy, 25000 soʻm, 8 dona
$ ./bozor add oʻrik 35000 2
qoʻshildi: 4. oʻrik, 35000 soʻm, 2 dona
```

ID у `oʻrik` — четыре: это четвёртый `add`. Теперь код `list`. Он обходит каталог итератором `All` из GB-3.05 и пишет каждый товар в `w`:

```go showLineNumbers
func list(st *store.Store, w io.Writer) error {
	n := 0
	for p := range st.All() {
		n++
		_, err := fmt.Fprintf(w, "%2d. %-20s %8d soʻm %4d dona\n",
			p.ID, p.Name, p.Price/tiyinPerSom, p.Stock)
		if err != nil {
			return err
		}
	}
	if n == 0 {
		_, err := fmt.Fprintln(w, "katalog boʻsh: bozor add NOM NARX QOLDIQ")
		return err
	}
	return nil
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `func list(st *store.Store, w io.Writer) error` | каталог и место вывода (`w`, GB-2.07) — параметры; возвращает только `error` |
| 2, 4 | `n := 0`, `n++` | число выведенных строк; `++` — GB-1.06 |
| 3 | `for p := range st.All()` | обходит каталог по одному товару (GB-3.05) |
| 5–6 | `fmt.Fprintf(w, "…", p.ID, p.Name, …)` | пишет одну строку в `w`; `_` — число записанных байт не нужно |
| 6 | `p.Price/tiyinPerSom` | цена хранится в тийинах, при выводе переводится в сумы (GB-1.03) |
| 7–9 | `if err != nil { return err }` | если записать не удалось, возвращает ошибку |
| 11–14 | `if n == 0 { … }` | если ни одной строки не выведено: «каталог пуст» |

Шаблон `"%2d. %-20s %8d soʻm %4d dona\n"` задаёт для четырёх значений четыре ширины (GB-1.04):

| Шаблон | Значение | Ширина |
|---|---|---|
| `%2d` | `p.ID` | 2 символа, справа |
| `%-20s` | `p.Name` | колонка в 20 символов, слева (минус — выравнивание влево) |
| `%8d` | цена в сумах | 8 символов, справа |
| `%4d` | `p.Stock` | 4 символа, справа |

В `oʻrik` 5 символов, но 6 байт (GB-2.10). Где в строке `oʻrik` окажется колонка цены относительно строки `olma`?

**A)** на одной линии · **B)** на один символ левее · **C)** на один символ правее

<details>
<summary>Ответ</summary>

**A.** `fmt` считает ширину не в байтах, а в рунах: в pkg.go.dev/fmt сказано «Width and precision are measured in units of Unicode code points, that is, runes». В `oʻrik` 5 рун, поэтому добавляется 15 пробелов, и колонка не сдвигается. Если вы выбрали **B**, вы решили, что считаются байты: тогда `oʻrik` занял бы 6 мест, а остаток строки сдвинулся бы на один символ вправо. В варианте **C** строка, наоборот, сдвинулась бы влево. А то, что название не длиннее 20 символов, проверяет store (`validate`, ниже).

</details>

```console
$ ./bozor list
 1. olma                    12000 soʻm   40 dona
 2. non                      4000 soʻm    3 dona
 3. choy                    25000 soʻm    8 dona
 4. oʻrik                   35000 soʻm    2 dona
```

Начало `bozor.json`. Ключи берутся из тегов в `Product` (GB-3.02), цена в тийинах: `1200000` тийинов — 12 000 сумов. `head -6` выводит первые шесть строк файла:

```console

$ ./bozor list
```

## Ошибка и код выхода: 1 или 2

Теперь ошибки. Просим пять штук `oʻrik`, на складе две. Сообщение уходит в stderr (GB-1.07). `echo $?` показывает код выхода последней команды:

```console
$ ./bozor order 4 5
xato: oʻrik: faqat 2 dona qoldi
$ echo $?
1
```

Код выхода 1: ошибка. Теперь неизвестная команда, например `sell`. Это не ошибка внутри программы, а неверный вызов. Что покажет `echo $?` после `./bozor sell 1 1`?

**A)** 0 · **B)** 1 · **C)** 2

<details>
<summary>Ответ</summary>

**C.** В GB-1.07 любая ошибка давала 1. Теперь CLI отделяет неверный вызов (неизвестная команда, неверное число аргументов) отдельным кодом: 2. Если вы выбрали **A**, вы решили, что раз сообщение вывелось, то это успех: 0 получает только программа, завершившаяся без ошибки. Если выбрали **B**, вы вспомнили правило из GB-1.07: теперь оно относится только к ошибкам внутри программы.

</details>

```console
$ ./bozor sell 1 1
foydalanish: bozor add NOM NARX QOLDIQ | list | order ID DONA
$ echo $?
2
```

Это не прихоть, а правило: команда `go` тоже возвращает 2 при неверном вызове. Для этого вопроса мы запустили её сами (в папке курса такого нет):

```console
$ go foo
go foo: unknown command
Run 'go help' for usage.
$ echo $?
2
```

Пакет `flag` (флаги командной строки) делает то же самое: документация его `ExitOnError` (pkg.go.dev/flag) говорит «Call os.Exit(2) or for -h/-help Exit(0)». Это мы не запускали: цитата из документации. Польза такого разделения: скрипт или другая программа по коду выхода отличит «вызов нужно исправить» (2) от «операция не выполнена» (1).

Остальные сообщения тоже выходят из функции `message` (GB-2.08). Если передать `order` несуществующий ID, неверное количество или ID не числом:

```console
$ ./bozor order 9 1
xato: bunday mahsulot yoʻq
$ ./bozor order 1 0
xato: dona soni notoʻgʻri
$ ./bozor order bir 1
xato: ID: strconv.ParseInt: parsing "bir": invalid syntax
```

## Код: main, run, order и Sell

Теперь код, который даёт такое поведение. Сначала `main`:

```go showLineNumbers
func main() {
	err := run(dataFile, os.Args[1:], os.Stdout)
	if err == nil {
		return
	}
	fmt.Fprintln(os.Stderr, message(err))
	if errors.Is(err, errUsage) {
		os.Exit(2)
	}
	os.Exit(1)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 2 | `err := run(dataFile, os.Args[1:], os.Stdout)` | `dataFile` — константа `"bozor.json"`; `os.Args[1:]` — аргументы без имени программы (GB-2.02); `os.Stdout` — `io.Writer` (GB-2.07) |
| 3–5 | `if err == nil { return }` | ошибки нет: `main` завершается обычно, код выхода 0 |
| 6 | `fmt.Fprintln(os.Stderr, message(err))` | `message` превращает ошибку в текст, который пишется в stderr (GB-2.08) |
| 7–9 | `if errors.Is(err, errUsage) { os.Exit(2) }` | `errUsage` — `errors.New("foydalanish: …")` («использование: …»): если это ошибка использования, код выхода 2 |
| 10 | `os.Exit(1)` | любая другая ошибка — 1 |

`run` — весь CLI:

```go showLineNumbers
func run(path string, args []string, w io.Writer) error {
	if len(args) == 0 {
		return errUsage
	}
	st, err := store.Load(path)
	if err != nil {
		return err
	}
	var msg string // oʻzgartiruvchi buyruqning natija qatori
	switch args[0] {
	case "list":
		return list(st, w)
	case "add":
		msg, err = add(st, args[1:])
	case "order":
		msg, err = order(st, args[1:])
	default:
		return errUsage
	}
	if err != nil {
		return err
	}
	if err := st.Save(path); err != nil {
		return err
	}
	_, err = fmt.Fprintln(w, msg)
	return err
}
```

|---|---|---|
| 1 | `func run(path string, args []string, w io.Writer) error` | путь к файлу, аргументы и `w`, куда пишется результат, — параметры; в `main` `w` — `os.Stdout`, в тесте — `strings.Builder` |
| 2–4 | `if len(args) == 0 { return errUsage }` | команда не задана: ошибка использования (поэтому дальше `args[0]` безопасен) |
| 5–8 | `st, err := store.Load(path)` | загружает каталог, при порче файла выходит с ошибкой |
| 9 | `var msg string` | строка-результат изменяющей команды |
| 10–12 | `switch args[0] { case "list": return list(st, w) }` | `list` только читает: возвращается сразу, без сохранения (GB-1.05) |

| 26–27 | `fmt.Fprintln(w, msg)` | строку-результат печатаем **после** успешного сохранения |

В строке 23 `if err := st.Save(path); err != nil` затеняет внешний `err` новым `err` (shadowing): он живёт только внутри этого `if`. Порядок важен: несохранённый заказ не должен выводить «buyurtma: …» («заказ: …»). Это проверяет `TestNoOutputWithoutSave`. А поскольку путь и `w` — параметры, тест может вызвать `run` в своей папке.

## Сохранение: чем опасен os.WriteFile

Теперь сохранение. `saveProducts` из GB-3.02 (в этой папке её нет, она взята из урока GB-3.02):

```go showLineNumbers
func saveProducts(path string, products []Product) error {
	data, err := json.MarshalIndent(products, "", "  ")
	if err != nil {
		return err
	}
	return os.WriteFile(path, data, 0o644)
}
```

По документации `os.WriteFile` перед записью очищает файл: «otherwise WriteFile truncates it before writing». Документация ещё предупреждает: «Since WriteFile requires multiple system calls to complete, a failure mid-operation can leave the file in a partially written state». То есть шагов два:

| Момент | `bozor.json` |
|---|---|
| в начале | весь каталог (320 байт) |
| 1) очищен | 0 байт |
| 2) идёт запись | часть каталога |
| 2 завершён | новый целый каталог |

Если процесс убьют или отключат питание между 1 и 2, файл останется недописанным. Воспроизведём это вручную: `truncate -s 60` обрезает файл до 60 байт, как будто запись прервалась посередине:

```console
$ truncate -s 60 bozor.json
```

Что теперь сделает `list`?

**A)** выведет, что каталог пуст · **B)** ошибка, код выхода 1 · **C)** panic

<details>
<summary>Ответ</summary>

**B.** Файл есть, но JSON не дочитан до конца: `Unmarshal` возвращает ошибку `unexpected end of JSON input` («неожиданный конец JSON-ввода»), `Load` оборачивает её именем файла (`"%s: %w"`), `run` возвращает ошибку, `main` ставит код выхода 1. Чтобы получить **A**, файла не должно быть совсем (`os.ErrNotExist`). **C** неверно: ошибка обычная, `error`, а не panic.

</details>

```console
$ ./bozor list
xato: bozor.json: unexpected end of JSON input
$ echo $?
1
$ ./bozor add anor 3000 1
xato: bozor.json: unexpected end of JSON input
```

`add` тоже не работает: он тоже сначала делает `Load`. С недописанным файлом программа останавливается, и каталог нужно восстанавливать вручную. Это как раз то поведение, которое нам нужно: поверх испорченного каталога новая запись не пишется. Лучше, чтобы такой файл вообще не появлялся. Но сначала вторая задача `Load`.

### Load проверяет и прочитанный товар

```go showLineNumbers
func Load(path string) (*Store, error) {
	data, err := os.ReadFile(path)
	if errors.Is(err, os.ErrNotExist) {
		return &Store{}, nil
	}
	if err != nil {
		return nil, err
	}
	var products []Product
	if err := json.Unmarshal(data, &products); err != nil {
		return nil, fmt.Errorf("%s: %w", path, err)
	}
	seen := make(map[int64]bool)
	for i, p := range products {
		if err := validate(p); err != nil {
			return nil, fmt.Errorf("%s: %d-mahsulot: %w", path, i+1, err)
		}
		if seen[p.ID] {
			return nil, fmt.Errorf("%s: %d-mahsulot: %w: ID %d takrorlangan", path, i+1, ErrBadProduct, p.ID)
		}
		seen[p.ID] = true
	}
	return &Store{products: products}, nil
}
```

| Строка | Код | Что делает |
|---|---|---|
| 2–5 | `os.ReadFile`, `os.ErrNotExist` | файла нет: первый запуск, пустой каталог; другая ошибка чтения — ошибка |
| 9–12 | `json.Unmarshal(data, &products)` | ошибка JSON оборачивается именем файла (GB-3.02) |
| 13 | `seen := make(map[int64]bool)` | map уже встреченных ID (GB-2.02) |
| 14–17 | `validate(p)` | каждый товар проходит правила; ошибка `"%s: %d-mahsulot: %w"`: имя файла и номер товара |
| 18–21 | `seen[p.ID]` | повторяющийся ID — тоже ошибка |

`validate` собирает в одном месте правила `parseLine` из GB-3.01 и правила названия из GB-2.10:

```go showLineNumbers
func validate(p Product) error {
	switch {
	case p.ID <= 0:
		return fmt.Errorf("%w: ID musbat boʻlishi kerak, keldi %d", ErrBadProduct, p.ID)
	case p.Name == "":
		return fmt.Errorf("%w: nom boʻsh", ErrBadProduct)
	case !utf8.ValidString(p.Name):
		return fmt.Errorf("%w: nom UTF-8 emas", ErrBadProduct)
	case utf8.RuneCountInString(p.Name) > maxNameRunes:
		return fmt.Errorf("%w: nom %d belgi, eng koʻpi %d", ErrBadProduct, utf8.RuneCountInString(p.Name), maxNameRunes)
	case p.Price <= 0:
		return fmt.Errorf("%w: narx musbat boʻlishi kerak, keldi %d", ErrBadProduct, p.Price)
	case p.Stock < 0:
		return fmt.Errorf("%w: qoldiq manfiy boʻlmasin, keldi %d", ErrBadProduct, p.Stock)
	}
	return nil
}
```

Через эту функцию проходят и `Add`, и `Load`. Каждая ошибка оборачивает `ErrBadProduct` через `%w`. Если файл испортить вручную, например поставить остаток `oʻrik` равным `-5`, bozor не будет торговать по испорченному каталогу, а остановится с ошибкой:

```console
$ sed -i 's/"stock": 2$/"stock": -5/' bozor.json
$ ./bozor list
xato: bozor.json: 4-mahsulot: mahsulot notoʻgʻri: qoldiq manfiy boʻlmasin, keldi -5
```

## Атомарное сохранение: временный файл и os.Rename

Решение: сначала пишем в **другой** файл, а когда он готов, меняем имя. Вот полный код `Save`:

```go showLineNumbers
func (s *Store) Save(path string) (err error) {
	products := s.products
	if products == nil {
		products = []Product{} // nil slice JSON'da null boʻladi, boʻsh slice esa []
	}
	data, err := json.MarshalIndent(products, "", "  ")
	if err != nil {
		return err
	}
	data = append(data, '\n')

	f, err := os.CreateTemp(filepath.Dir(path), ".bozor-*.json")
	if err != nil {
		return err
	}
	defer func() {
		if err != nil {
			f.Close()
			os.Remove(f.Name()) // xato boʻlsa vaqtinchalik fayl qolmasin
		}
	}()
	if err = f.Chmod(0o644); err != nil { // CreateTemp 0600 bilan ochadi; bozor.json GB-3.02'dagidek 0644
		return err
	}
	if _, err = f.Write(data); err != nil {
		return err
	}
	if err = f.Sync(); err != nil {
		return err
	}
	if err = f.Close(); err != nil {
		return err
	}
	return os.Rename(f.Name(), path)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `func (s *Store) Save(path string) (err error)` | `(err error)` — именованный результат (GB-2.09): `defer` его видит |
| 2–5 | `if products == nil { products = []Product{} }` | пустой каталог записывается как `[]`, а не `null` (ниже) |
| 6–10 | `json.MarshalIndent(…)`, `append(data, '\n')` | текст JSON и перевод строки в конце. В `data, err :=` `data` новая, а `err` — именованный результат этой функции: он в той же области видимости, поэтому новая переменная не создаётся |
| 12–15 | `os.CreateTemp(filepath.Dir(path), ".bozor-*.json")` | открывает новый файл в папке `path`; `*` в имени заменяет случайным числом (`.bozor-2476821519.json`). `filepath.Dir("bozor.json")` — `"."`, текущая папка |
| 16–21 | `defer func() { if err != nil { … } }()` | при ошибке закрывает файл и удаляет его через `os.Remove`: временный файл не остаётся. `f.Name()` — путь этого файла |
| 22–24 | `f.Chmod(0o644)` | `CreateTemp` открывает файл с правами `0600`; `bozor.json` должен остаться `0644`, как в GB-3.02 |
| 25–27 | `f.Write(data)` | отдаёт байты операционной системе |
| 28–30 | `f.Sync()` | ждёт, пока байты попадут на диск (pkg.go.dev/os: «Sync commits the current contents of the file to stable storage») |
| 31–33 | `f.Close()` | закрывает файл и проверяет ошибку |
| 34 | `os.Rename(f.Name(), path)` | переносит временный файл на имя `bozor.json` |

Файл, имя которого начинается с точки, скрытый: обычный `ls` его не показывает. После успешного `Save` временного файла не остаётся: `Rename` переименовал его в `bozor.json`. `ls -A1` показывает и скрытые файлы, каждый в отдельной строке:

```console
$ ./bozor add olma 12000 40
qoʻshildi: 1. olma, 12000 soʻm, 40 dona
$ ls -A1
bozor
bozor.json
cmd
go.mod
internal
```

Во время записи до `bozor.json` никто не дотрагивается:

| Шаг | `bozor.json` | `.bozor-*.json` |
|---|---|---|
| в начале | старый каталог | нет |
| `CreateTemp`, `Write`, `Sync`, `Close` | старый каталог, не тронут | новый каталог пишется и попадает на диск |
| `os.Rename` | новый каталог (имя перешло одним шагом) | нет (теперь это `bozor.json`) |

`os.Rename` — одна операция ядра Linux (системный вызов `rename(2)`): имя переходит на новый файл **атомарно**, то есть одним шагом. Атомарно значит: читатель видит либо старый, либо новый каталог, но никогда половину. Страница man: «newpath will be atomically replaced». Порядок важен: `Sync` идёт до rename. Если после rename без `Sync` отключится питание, новое имя может указывать на файл, не записанный на диск (`fsync(2)` и документация `os.File.Sync`).

Промежуточный вопрос. `Save` выполнил `Sync`, но до `Rename` отключилось питание. Что лежит в `bozor.json` после включения компьютера?

**A)** недописанный каталог · **B)** старый каталог, целый · **C)** новый каталог

<details>
<summary>Ответ</summary>

**B.** `Rename` не выполнялся, поэтому `bozor.json` не тронут: старый каталог цел. Может остаться только временный файл с точкой (`.bozor-*.json`): его можно удалить вручную. Если вы выбрали **A**, вы решили, что запись идёт в сам `bozor.json`: нет, она идёт в другой файл. Если выбрали **C**, вы решили, что `Sync` ставит новый каталог на место: `Sync` лишь сбрасывает временный файл на диск, а имя меняет `Rename`. В production состояние и конфигурационные файлы пишут так же: `github.com/google/renameio` упаковал именно этот приём в пакет.

</details>

### Где гарантия заканчивается

- **Одна файловая система.** Rename выполняется одним шагом только внутри одной файловой системы; в другую он возвращает ошибку `EXDEV` («invalid cross-device link»). Поэтому временный файл открывается **рядом** с `bozor.json` (`filepath.Dir(path)`). Саму ошибку вы увидите в разделе «Частые ошибки».
- **Linux и macOS.** `go doc os.Rename`: «Even within the same directory, on non-Unix platforms Rename is not an atomic operation». Гарантия — для Unix-систем.
- **Запись папки.** Для полной гарантии «даже при отключении питания» после rename нужно сделать `Sync` ещё и самой папки. CLI v0 этого не делает: в худшем случае остаётся старый каталог, но не недописанный файл (README курса).
- **Один процесс.** Если два `bozor` работают одновременно, побеждает последний `rename`: файловой блокировки нет. По README это сознательно оставлено до мьютекса в модуле 4 и транзакции Postgres в модуле 5.

```go showLineNumbers

	tests := []struct {
		name      string
		id        int64
		quantity  int
		wantStock int   // shu ID'li mahsulotning katalogdagi qoldigʻi Sell'dan keyin

		{"manfiy_dona", 1, -2, 40, ErrBadQuantity},

```

|---|---|---|
| 2–8 | `tests := []struct{ … }` | в каждой строке: название, ID, количество, **ожидаемый остаток в каталоге**, ожидаемая ошибка |

## Баг: vet молчит, тест ловит

Теперь настоящий баг. Ваш коллега «упростил» `Sell`: вместо `find` один цикл `range` (`_video/01-nusxa`). Код собирается:

</details>

Причина: `range` на каждом шаге записывает в `p` **копию** элемента (спецификация Go, For statements with range clause), как `p := olma`. `p.Stock -= quantity` меняет копию, `olma` в каталоге по-прежнему 40. 	Stock int

**Ошибка 3: открывать временный файл в другой папке.** `CreateTemp("", …)` создаёт файл в общей временной папке системы; она может оказаться на другой файловой системе, чем `bozor.json`. Другую файловую систему мы явно взяли в `/dev/shm` (в папке курса этого нет, полный код):

```go showLineNumbers

import (
	"fmt"
	"os"
)

func main() {
	// vaqtinchalik fayl bozor.json'dan boshqa fayl tizimida: /dev/shm (Linux'da odatda tmpfs)
	f, err := os.CreateTemp("/dev/shm", ".bozor-*.json")
	if err != nil {
		fmt.Println(err)
		return
	}
	defer os.Remove(f.Name())
	f.WriteString("[]\n")
	f.Close()

	err = os.Rename(f.Name(), "bozor.json")
	fmt.Println(err)
}
```

Как читать: операция `rename`, старый путь (каждый раз другое число), новый путь, причина: `invalid cross-device link` — это `EXDEV`. Исправление: `CreateTemp(filepath.Dir(path), …)`, то есть рядом с целью.

**Ошибка 4: тихие ошибки.** Две из них эта страница уже показала, и ни в одной нет текста ошибки. Первая — копия из `range`: смотрите раздел «Баг», исправление — взять адрес через `find`. ## Проверьте себя

**1.** Почему `Save` открывает временный файл именно рядом с `bozor.json`?

<details>
<summary>Ответ</summary>

`os.Rename` выполняется одним шагом только внутри одной файловой системы. Если временный файл на другой файловой системе, `rename` вернёт ошибку `invalid cross-device link` (`EXDEV`), и атомарность пропадёт. `filepath.Dir(path)` берёт папку у самого `bozor.json`.

</details>

**2.** Почему `run` принимает путь к файлу и `io.Writer` параметрами?

<details>
<summary>Ответ</summary>

Тест может вызвать `run` с файлом в своей временной папке (`t.TempDir()`) и читать вывод из памяти (`strings.Builder`). А `main` передаёт `dataFile` и `os.Stdout`. Весь CLI проверяется, не касаясь настоящего `bozor.json` и не печатая на экран.

</details>

**3.** (GB-3.03) Запускает ли `go test` все проверки `go vet`?

<details>
<summary>Ответ</summary>

Нет. `go test` запускает лишь небольшую часть проверок vet: 11 из 35 (GB-3.03). Для полной проверки `go vet ./...` запускают отдельно. А сегодняшний баг с копией из `range` не нашли ни `go vet`, ни `staticcheck`: его поймал тест.

</details>

**4.** После `./bozor order 1 3` запущено `./bozor order 1 38` (остаток `olma` — 37). Что выведется и какой будет код выхода?

<details>
<summary>Ответ</summary>

Запрошено 38 штук, на складе 37: `Sell` возвращает `*StockError`, `message` превращает его в «xato: olma: faqat 37 dona qoldi» («ошибка: olma: осталось только 37 штук»), `main` ставит код выхода 1 (это не ошибка использования). Каталог не меняется: при ошибке `run` не вызывает `Save`.

```console
$ ./bozor order 1 3
buyurtma: olma × 3 = 36000 soʻm, qoldiq 37
$ ./bozor order 1 38; echo $?
xato: olma: faqat 37 dona qoldi
1
```

</details>

**5.** (GB-2.09) Зачем в `Save` нужен именованный результат `(err error)`?

<details>
<summary>Ответ</summary>

Анонимная функция внутри `defer` видит `err` в момент завершения функции: что бы ни вернул `return os.Rename(…)` или другой `return err`, `err` получит это значение. Если `err != nil`, `defer` закрывает временный файл и удаляет его через `os.Remove`. Без именованного результата `defer` не увидел бы возвращаемую ошибку.

</details>

<summary>Ответ и объяснение</summary>

`Restock` — обратный `Sell`: сначала проверяем `quantity`, затем `find`, затем `p.Stock += quantity` и `return *p, nil`. Для границы удобна константа:

```go showLineNumbers
// maxRestock — bitta Restock'da qoʻshiladigan eng koʻp dona (xato yozilgan sondan himoya).
const maxRestock = 10_000

// Restock id'li mahsulotning qoldigʻiga quantity dona qoʻshadi va yangilangan mahsulotni qaytaradi.
// Xato boʻlsa katalog oʻzgarmaydi: ErrBadQuantity (quantity 1..maxRestock emas), ErrNotFound.
func (s *Store) Restock(id int64, quantity int) (Product, error) {
	if quantity <= 0 {
		return Product{}, fmt.Errorf("%w, hozir %d", ErrBadQuantity, quantity)
	}
	if quantity > maxRestock {
		return Product{}, fmt.Errorf("%w: bir martada koʻpi bilan %d, hozir %d", ErrBadQuantity, maxRestock, quantity)
	}
	p := s.find(id)
	if p == nil {
		return Product{}, fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
	}
	p.Stock += quantity
	return *p, nil
}
```
