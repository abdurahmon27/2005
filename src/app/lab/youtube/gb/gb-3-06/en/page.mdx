## What you will learn

`Store` (GB-2.06) keeps the catalog only in memory: when the program ends, the products are gone. Working with `bozor.json` (GB-3.02) was left in a separate program. How do we combine these pieces into one command-line program, a **CLI** (command-line interface)? And how do we make it reliable: a file that is never left half-written, even if the power goes off, and a silently wrong stock number that a test catches?

**One idea:** the bozor CLI runs one command in one process. `main` only passes `os.Args` to `run(path, args, w)` and turns the error into an exit code: 1 means error, 2 means wrong invocation. `run` loads the catalog from `bozor.json`, picks the command with `switch`, calls the rules in `internal/store` and saves the changed catalog **atomically**: the new JSON is first written to a temporary file, then `os.Rename` puts it in place of `bozor.json` in one step. The path and the `io.Writer` are parameters, so a test calls the whole CLI in its own folder and checks the state of the catalog, not the output.

By the end of the lesson you will:

- read a CLI laid out as `cmd/bozor` + `internal/store` and explain why `run(path, args, w)` makes the whole CLI testable;
- tell exit code 1 (error) from exit code 2 (wrong invocation);
- see why `os.WriteFile` can leave a half-written file, and read atomic saving with `os.CreateTemp` + `Sync` + `os.Rename`;
- see a table test catch a real bug that `go vet` and `staticcheck` missed, and write the `bozor restock ID DONA` command yourself, with its test.

Today's three core new words:

| Word | Plain meaning | English |
|---|---|---|
| CLI structure | `main` only passes the arguments and turns the error into an exit code; all the work is in `run(path, args, w) error` | CLI structure (thin `main` + `run`) |
| atomic save | the new file is written separately, then the name is switched in one step: a reader sees either the old or the new file | atomic save |
| state-checking test | the test checks the state of the catalog (or the file), not the value the function returned | state-checking test |

Helper words are explained in one sentence where they appear: `t.TempDir()`, `fmt` width counted in runes, temporary file.

One question about the previous lesson. The `All()` iterator does not check the result of `yield(p)`. After the loop does `break`, what happens to the iterator at the next product?

**A)** the loop goes on · **B)** the iterator quietly ends · **C)** panic: the program crashes

<details>
<summary>Answer</summary>

**C.** On `break`, `yield` returns `false`. If the iterator does not check this and calls `yield` again, the function generated by the compiler panics. If you chose **A** or **B**, you treated `yield` as "optional": it is not, calling it after `false` is forbidden. That is why `All` is written like this: `if !yield(p) { return }`. Today's `list` also walks the catalog with this same `All` iterator.

</details>

## Structure: the path of one command

First, the shape of the finished folder. `ls` lists the files of two folders (in columns on a terminal; one per line when the output goes to a file):

```console
$ ls cmd/bozor internal/store
cmd/bozor:
main.go  main_test.go

internal/store:
file.go  store.go  store_test.go
```

The layout is the same as in GB-2.06:

| File | What for |
|---|---|
| `cmd/bozor/main.go` | `main`, `run`, the commands (`add`, `list`, `order`) and the error texts: the part that talks to the user |
| `cmd/bozor/main_test.go` | CLI tests: they call `run` |
| `internal/store/store.go` | product rules: `Product`, `validate`, `Add`, `All`, `find`, `Sell`, errors |
| `internal/store/file.go` | working with `bozor.json`: `Load` and `Save` |
| `internal/store/store_test.go` | store tests: table tests and `Save` tests |

A package in `internal/` can be imported only by this module (GB-2.06). The path of one command, for example `./bozor order 1 3`:

| Step | Who | What it does |
|---|---|---|
| 1 | `main` | passes `os.Args[1:]` (`order`, `1`, `3`) to `run` |
| 2 | `run` | loads `bozor.json` (`store.Load`) and picks `order` with `switch` |
| 3 | `st.Sell(1, 3)` | `internal/store`: checks the rules and decreases the stock |
| 4 | `st.Save(path)` | writes the changed catalog to `bozor.json` |
| 5 | `main` | if `run` returned an error, writes its text to stderr and sets the exit code |

`main` is thin on purpose: it has no rules. The whole CLI is the `run` function. You will see the payoff in the "Tests" section.

## Running it: add, list, order

`go build ./cmd/bozor` builds the `cmd/bozor` package. The result is one binary (GB-1.01), named after the folder: `bozor`. The first command is `list`. There is no `bozor.json` yet, and `Load` treats this as an empty catalog, not an error.

```console
$ go build ./cmd/bozor
$ ./bozor list
katalog boʻsh: bozor add NOM NARX QOLDIQ
```

`go build` printed nothing: success. `add` takes a name, a price in som and a stock number. The program gives the new ID itself (the largest ID + 1) and writes the catalog to `bozor.json`:

```console
$ ./bozor add olma 12000 40
qoʻshildi: 1. olma, 12000 soʻm, 40 dona
$ ./bozor add non 4000 3
qoʻshildi: 2. non, 4000 soʻm, 3 dona
$ ./bozor add choy 25000 8
qoʻshildi: 3. choy, 25000 soʻm, 8 dona
$ ./bozor add oʻrik 35000 2
qoʻshildi: 4. oʻrik, 35000 soʻm, 2 dona
```

The ID of `oʻrik` is four: it is the fourth `add`. Now the code of `list`. It walks the catalog with the `All` iterator from GB-3.05 and writes each product to `w`:

```go showLineNumbers
func list(st *store.Store, w io.Writer) error {
	n := 0
	for p := range st.All() {
		n++
		_, err := fmt.Fprintf(w, "%2d. %-20s %8d soʻm %4d dona\n",
			p.ID, p.Name, p.Price/tiyinPerSom, p.Stock)
		if err != nil {
			return err
		}
	}
	if n == 0 {
		_, err := fmt.Fprintln(w, "katalog boʻsh: bozor add NOM NARX QOLDIQ")
		return err
	}
	return nil
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `func list(st *store.Store, w io.Writer) error` | the catalog and the output place (`w`, GB-2.07) are parameters; returns only `error` |
| 2, 4 | `n := 0`, `n++` | the number of printed lines; `++` is GB-1.06 |
| 3 | `for p := range st.All()` | walks the catalog one product at a time (GB-3.05) |
| 5–6 | `fmt.Fprintf(w, "…", p.ID, p.Name, …)` | writes one line to `w`; `_` means the number of written bytes is not needed |
| 6 | `p.Price/tiyinPerSom` | the price is stored in tiyin and converted to som when printed (GB-1.03) |
| 7–9 | `if err != nil { return err }` | if writing fails, returns the error |
| 11–14 | `if n == 0 { … }` | if no line was printed: "catalog is empty" |

The template `"%2d. %-20s %8d soʻm %4d dona\n"` gives four widths for four values (GB-1.04):

| Template | Value | Width |
|---|---|---|
| `%2d` | `p.ID` | 2 characters, right-aligned |
| `%-20s` | `p.Name` | a 20-character column, left-aligned (the minus means left) |
| `%8d` | price in som | 8 characters, right-aligned |
| `%4d` | `p.Stock` | 4 characters, right-aligned |

`oʻrik` has 5 characters but 6 bytes (GB-2.10). Where does the price column of the `oʻrik` line stand compared with the `olma` line?

**A)** on the same line · **B)** one character to the left · **C)** one character to the right

<details>
<summary>Answer</summary>

**A.** `fmt` counts width in runes, not bytes: pkg.go.dev/fmt says "Width and precision are measured in units of Unicode code points, that is, runes". `oʻrik` is 5 runes, so 15 spaces are added and the column does not move. If you chose **B**, you thought bytes are counted: then `oʻrik` would take 6 places and the rest of the line would shift one character to the right. With **C**, the line would move left instead. That a name is at most 20 characters is checked by the store (`validate`, below).

</details>

```console
$ ./bozor list

 2. non                      4000 soʻm    3 dona
 3. choy                    25000 soʻm    8 dona
 4. oʻrik                   35000 soʻm    2 dona
```

The beginning of `bozor.json`. The keys come from the tags in `Product` (GB-3.02), and the price is in tiyin: `1200000` tiyin is 12 000 som. `head -6` prints the first six lines of the file:

## Error and exit code: 1 or 2

Now errors. We ask for five `oʻrik`, and the stock has two. The message goes to stderr (GB-1.07). `echo $?` shows the exit code of the last command:

```console
$ ./bozor order 4 5
xato: oʻrik: faqat 2 dona qoldi
$ echo $?
1
```

Exit code 1: an error. Now an unknown command, for example `sell`. This is not an error inside the program, the invocation is wrong. What does `echo $?` show after `./bozor sell 1 1`?

**A)** 0 · **B)** 1 · **C)** 2

<details>
<summary>Answer</summary>

**C.** In GB-1.07 every error gave 1. Now the CLI separates a wrong invocation (an unknown command, a wrong number of arguments) with its own code: 2. If you chose **A**, you thought a printed message means success: 0 goes only to a program that finished without an error. If you chose **B**, you remembered the rule from GB-1.07: now it applies only to errors inside the program.

</details>

```console
$ ./bozor sell 1 1
foydalanish: bozor add NOM NARX QOLDIQ | list | order ID DONA
$ echo $?
2
```

This is not a whim but a convention: the `go` command also returns 2 for a wrong invocation. We ran it ourselves for this question (it is not in the course folder):

```console
$ go foo
go foo: unknown command
Run 'go help' for usage.
$ echo $?
2
```

The `flag` package does the same: the documentation of its `ExitOnError` (pkg.go.dev/flag) says "Call os.Exit(2) or for -h/-help Exit(0)". We did not run this one: it is a quote from the documentation. The use of the separation: a script or another program can tell "fix the invocation" (2) from "the operation did not happen" (1) by the exit code.

The other messages also come out of the `message` function (GB-2.08). If we pass `order` an unknown ID, a bad quantity or an ID that is not a number:

```console
$ ./bozor order 9 1

$ ./bozor order 1 0
xato: dona soni notoʻgʻri
$ ./bozor order bir 1
```

## Code: main, run, order and Sell

Now the code that gives this behavior. First `main`:

```go showLineNumbers
func main() {
	err := run(dataFile, os.Args[1:], os.Stdout)
	if err == nil {
		return
	}
	fmt.Fprintln(os.Stderr, message(err))
	if errors.Is(err, errUsage) {
		os.Exit(2)
	}
	os.Exit(1)
}
```

| Line | Code | What it does |
|---|---|---|
| 2 | `err := run(dataFile, os.Args[1:], os.Stdout)` | `dataFile` is the constant `"bozor.json"`; `os.Args[1:]` is the arguments without the program name (GB-2.02); `os.Stdout` is an `io.Writer` (GB-2.07) |
| 3–5 | `if err == nil { return }` | no error: `main` ends normally, exit code 0 |
| 6 | `fmt.Fprintln(os.Stderr, message(err))` | `message` turns the error into text, which is written to stderr (GB-2.08) |
| 7–9 | `if errors.Is(err, errUsage) { os.Exit(2) }` | `errUsage` is `errors.New("foydalanish: …")` ("usage: …"): if it is a usage error, exit code 2 |
| 10 | `os.Exit(1)` | any other error: 1 |

`run` is the whole CLI:

```go showLineNumbers
func run(path string, args []string, w io.Writer) error {
	if len(args) == 0 {
		return errUsage
	}
	st, err := store.Load(path)
	if err != nil {
		return err
	}
	var msg string // oʻzgartiruvchi buyruqning natija qatori
	switch args[0] {
	case "list":
		return list(st, w)
	case "add":
		msg, err = add(st, args[1:])
	case "order":
		msg, err = order(st, args[1:])
	default:
		return errUsage
	}
	if err != nil {
		return err
	}
	if err := st.Save(path); err != nil {
		return err
	}
	_, err = fmt.Fprintln(w, msg)
	return err
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `func run(path string, args []string, w io.Writer) error` | the file path, the arguments and the `w` to write the result to are parameters; in `main`, `w` is `os.Stdout`, in a test it is a `strings.Builder` |
| 2–4 | `if len(args) == 0 { return errUsage }` | no command given: a usage error (so `args[0]` is safe below) |
| 5–8 | `st, err := store.Load(path)` | loads the catalog, stops with an error if the file is broken |
| 9 | `var msg string` | the result line of a changing command |
| 10–12 | `switch args[0] { case "list": return list(st, w) }` | `list` only reads: it returns at once, without saving (GB-1.05) |
| 13–16 | `case "add"`, `case "order"` | the command returns the result line (`msg`) and an error; `args[1:]` is the arguments after the command name |
| 17–18 | `default: return errUsage` | an unknown command (`sell`) ends up here: exit code 2 |
| 20–22 | `if err != nil { return err }` | if the command failed, we neither save nor print |
| 23–25 | `st.Save(path)` | we save **first** |
| 26–27 | `fmt.Fprintln(w, msg)` | we print the result line **after** a successful save |

On line 23, `if err := st.Save(path); err != nil` shadows the outer `err` with a new `err` (shadowing): it lives only inside that `if`. The order matters: an unsaved order must not print "buyurtma: …" ("order: …"). `TestNoOutputWithoutSave` checks this. And since the path and `w` are parameters, a test can call `run` in its own folder.

`order` is the pattern for `add` and for the future `restock`:

```go showLineNumbers
func order(st *store.Store, args []string) (string, error) {
	if len(args) != 2 {
		return "", errUsage
	}
	id, err := strconv.ParseInt(args[0], 10, 64)
	if err != nil {
		return "", fmt.Errorf("ID: %w", err)
	}
	quantity, err := strconv.Atoi(args[1])
	if err != nil {
		return "", fmt.Errorf("dona: %w", err)
	}
	p, err := st.Sell(id, quantity)
	if err != nil {
		return "", err
	}
	total := p.Price * int64(quantity)
	return fmt.Sprintf("buyurtma: %s × %d = %d soʻm, qoldiq %d", p.Name, quantity, total/tiyinPerSom, p.Stock), nil
}
```

| Line | Code | What it does |
|---|---|---|
| 2–4 | `if len(args) != 2 { return "", errUsage }` | if there are not two arguments: a usage error; the first result is `""`, because no line is needed on error |
| 5–8 | `strconv.ParseInt(args[0], 10, 64)` | the ID from text to number: 10 is base ten, 64 is `int64` (GB-3.01); the error is wrapped as `"ID: %w"` |
| 9–12 | `strconv.Atoi(args[1])` | the quantity to `int`; the error with `"dona: %w"` |
| 13–16 | `st.Sell(id, quantity)` | the store rules; returns the error unchanged |
| 17 | `total := p.Price * int64(quantity)` | the total in tiyin: `Price` is `int64`, so `quantity` is converted (GB-1.03) |
| 18 | `return fmt.Sprintf(…), nil` | the result line; `run` prints it after `Save` |

`message` turns an error into text the user can read:

```go showLineNumbers
func message(err error) string {
	var se *store.StockError
	switch {
	case errors.Is(err, errUsage):
		return err.Error()
	case errors.Is(err, store.ErrNotFound):
		return "xato: bunday mahsulot yoʻq"
	case errors.Is(err, store.ErrBadQuantity):
		return "xato: dona soni notoʻgʻri"
	case errors.As(err, &se):
		return fmt.Sprintf("xato: %s: faqat %d dona qoldi", se.Name, se.Stock)
	}
	return "xato: " + err.Error()
}
```

Every message starts with `xato:` ("error:"), and a usage error is printed with its own text. `errors.Is` and `errors.As` are GB-2.08. Now the store side: `Sell` and the `find` it uses.

```go showLineNumbers
func (s *Store) find(id int64) *Product {
	for i := range s.products {
		if s.products[i].ID == id {
			return &s.products[i]
		}
	}
	return nil
}
```

```go showLineNumbers
func (s *Store) Sell(id int64, quantity int) (Product, error) {
	if quantity <= 0 {
		return Product{}, fmt.Errorf("%w, hozir %d", ErrBadQuantity, quantity)
	}
	p := s.find(id)
	if p == nil {
		return Product{}, fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
	}
	if p.Stock < quantity {
		return Product{}, &StockError{Name: p.Name, Stock: p.Stock, Want: quantity}
	}
	p.Stock -= quantity
	return *p, nil
}
```

| Line | Code | What it does |
|---|---|---|
| `find` 1 | `func (s *Store) find(id int64) *Product` | gives the **address** of the product in the catalog, or `nil` if not found (GB-2.04) |
| `find` 2–4 | `for i := range s.products`, `return &s.products[i]` | loops by index and returns the address of the element itself inside the slice |
| `Sell` 1 | `(Product, error)` | now it also returns the product after the sale: `order` prints the price and the stock |
| `Sell` 2–4 | `quantity <= 0` | `ErrBadQuantity`, with `%w` (GB-2.08) |
| `Sell` 5–8 | `p := s.find(id)`, `if p == nil` | unknown ID: `ErrNotFound` |
| `Sell` 9–11 | `p.Stock < quantity` | not enough stock: `&StockError{…}` |
| `Sell` 12 | `p.Stock -= quantity` | writing through the pointer changes the catalog **itself** |
| `Sell` 13 | `return *p, nil` | `*p` is a copy: the caller cannot touch the inner state of the catalog |

`find` gives an address, `*p` a copy: this difference decides things in the "Bug" section.

## Saving: why os.WriteFile is risky

Now saving. The `saveProducts` from GB-3.02 (it is not in this folder; it is taken from the GB-3.02 lesson):

```go showLineNumbers
func saveProducts(path string, products []Product) error {
	data, err := json.MarshalIndent(products, "", "  ")
	if err != nil {
		return err
	}
	return os.WriteFile(path, data, 0o644)
}
```

According to its documentation, `os.WriteFile` empties the file before writing: "otherwise WriteFile truncates it before writing". The documentation also warns: "Since WriteFile requires multiple system calls to complete, a failure mid-operation can leave the file in a partially written state". So there are two steps:

| Moment | `bozor.json` |
|---|---|
| at the start | the whole catalog (320 bytes) |
| 1) emptied | 0 bytes |
| 2) being written | part of the catalog |
| 2 finished | the new whole catalog |

If the process is killed or the power goes off between 1 and 2, the file stays half-written. Let us make that by hand: `truncate -s 60` cuts the file to 60 bytes, as if the write stopped in the middle:

```console
$ truncate -s 60 bozor.json
```

What does `list` do now?

**A)** prints that the catalog is empty · **B)** an error, exit code 1 · **C)** panic

<details>
<summary>Answer</summary>

**B.** The file exists, but the JSON does not reach its end: `Unmarshal` returns the error `unexpected end of JSON input`, `Load` wraps it with the file name (`"%s: %w"`), `run` returns the error, and `main` sets exit code 1. To get **A**, the file would have to be missing completely (`os.ErrNotExist`). **C** is wrong: the error is an ordinary `error`, not a panic.

</details>

```console
$ ./bozor list
xato: bozor.json: unexpected end of JSON input
$ echo $?
1
$ ./bozor add anor 3000 1
xato: bozor.json: unexpected end of JSON input
```

`add` does not work either: it also calls `Load` first. With a half-written file the program stops, and the catalog must be restored by hand. This is exactly the behavior we want: a new write never goes over a broken catalog. It is better still if such a file never appears. But first, the second job of `Load`.

### Load checks the product it read

```go showLineNumbers
func Load(path string) (*Store, error) {
	data, err := os.ReadFile(path)
	if errors.Is(err, os.ErrNotExist) {
		return &Store{}, nil
	}
	if err != nil {
		return nil, err
	}
	var products []Product
	if err := json.Unmarshal(data, &products); err != nil {
		return nil, fmt.Errorf("%s: %w", path, err)
	}
	seen := make(map[int64]bool)
	for i, p := range products {
		if err := validate(p); err != nil {
			return nil, fmt.Errorf("%s: %d-mahsulot: %w", path, i+1, err)
		}
		if seen[p.ID] {
			return nil, fmt.Errorf("%s: %d-mahsulot: %w: ID %d takrorlangan", path, i+1, ErrBadProduct, p.ID)
		}
		seen[p.ID] = true
	}
	return &Store{products: products}, nil
}
```

| Line | Code | What it does |
|---|---|---|
| 2–5 | `os.ReadFile`, `os.ErrNotExist` | no file: the first run, an empty catalog; any other read error is an error |
| 9–12 | `json.Unmarshal(data, &products)` | a JSON error is wrapped with the file name (GB-3.02) |
| 13 | `seen := make(map[int64]bool)` | a map of the IDs already seen (GB-2.02) |
| 14–17 | `validate(p)` | each product goes through the rules; the error is `"%s: %d-mahsulot: %w"`: the file name and the product number |
| 18–21 | `seen[p.ID]` | a repeated ID is also an error |

`validate` collects in one place the `parseLine` rules from GB-3.01 and the name rules from GB-2.10:

```go showLineNumbers
func validate(p Product) error {
	switch {
	case p.ID <= 0:
		return fmt.Errorf("%w: ID musbat boʻlishi kerak, keldi %d", ErrBadProduct, p.ID)
	case p.Name == "":
		return fmt.Errorf("%w: nom boʻsh", ErrBadProduct)
	case !utf8.ValidString(p.Name):
		return fmt.Errorf("%w: nom UTF-8 emas", ErrBadProduct)
	case utf8.RuneCountInString(p.Name) > maxNameRunes:
		return fmt.Errorf("%w: nom %d belgi, eng koʻpi %d", ErrBadProduct, utf8.RuneCountInString(p.Name), maxNameRunes)
	case p.Price <= 0:
		return fmt.Errorf("%w: narx musbat boʻlishi kerak, keldi %d", ErrBadProduct, p.Price)
	case p.Stock < 0:
		return fmt.Errorf("%w: qoldiq manfiy boʻlmasin, keldi %d", ErrBadProduct, p.Stock)
	}
	return nil
}
```

Both `Add` and `Load` go through this function. Every error wraps `ErrBadProduct` with `%w`. If the file is broken by hand, for example if we set the stock of `oʻrik` to `-5`, bozor does not sell from a broken catalog, it stops with an error:

```console

$ ./bozor list
xato: bozor.json: 4-mahsulot: mahsulot notoʻgʻri: qoldiq manfiy boʻlmasin, keldi -5
```

## Atomic save: a temporary file and os.Rename

The solution: write to a **different** file first, and switch the name when it is ready. Here is the full code of `Save`:

```go showLineNumbers
func (s *Store) Save(path string) (err error) {
	products := s.products
	if products == nil {
		products = []Product{} // nil slice JSON'da null boʻladi, boʻsh slice esa []
	}
	data, err := json.MarshalIndent(products, "", "  ")
	if err != nil {
		return err
	}
	data = append(data, '\n')

	f, err := os.CreateTemp(filepath.Dir(path), ".bozor-*.json")
	if err != nil {
		return err
	}
	defer func() {
		if err != nil {
			f.Close()
			os.Remove(f.Name()) // xato boʻlsa vaqtinchalik fayl qolmasin
		}
	}()
	if err = f.Chmod(0o644); err != nil { // CreateTemp 0600 bilan ochadi; bozor.json GB-3.02'dagidek 0644
		return err
	}
	if _, err = f.Write(data); err != nil {
		return err
	}
	if err = f.Sync(); err != nil {
		return err
	}
	if err = f.Close(); err != nil {
		return err
	}
	return os.Rename(f.Name(), path)
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `func (s *Store) Save(path string) (err error)` | `(err error)` is a named result (GB-2.09): `defer` can see it |
| 2–5 | `if products == nil { products = []Product{} }` | an empty catalog is written as `[]`, not `null` (below) |
| 6–10 | `json.MarshalIndent(…)`, `append(data, '\n')` | the JSON text and a newline at the end. In `data, err :=`, `data` is new and `err` is the named result of this function: it is in the same scope, so no new variable is made |
| 12–15 | `os.CreateTemp(filepath.Dir(path), ".bozor-*.json")` | opens a new file in the folder of `path`; replaces the `*` in the name with a random number (`.bozor-2476821519.json`). `filepath.Dir("bozor.json")` is `"."`, the current folder |
| 16–21 | `defer func() { if err != nil { … } }()` | on error, closes the file and deletes it with `os.Remove`: no temporary file is left. `f.Name()` is the path of this file |
| 22–24 | `f.Chmod(0o644)` | `CreateTemp` opens the file with mode `0600`; `bozor.json` should stay `0644`, as in GB-3.02 |
| 25–27 | `f.Write(data)` | hands the bytes to the operating system |
| 28–30 | `f.Sync()` | waits until the bytes reach the disk (pkg.go.dev/os: "Sync commits the current contents of the file to stable storage") |
| 31–33 | `f.Close()` | closes the file and checks the error |
| 34 | `os.Rename(f.Name(), path)` | moves the temporary file to the name `bozor.json` |

A file whose name starts with a dot is hidden: a plain `ls` does not show it. After a successful `Save`, no temporary file is left: `Rename` renamed it to `bozor.json`. `ls -A1` shows hidden files too, one per line:

```console
$ ./bozor add olma 12000 40
qoʻshildi: 1. olma, 12000 soʻm, 40 dona
$ ls -A1
bozor
bozor.json
cmd
go.mod
internal
```

While the write is going on, nobody touches `bozor.json`:

| Step | `bozor.json` | `.bozor-*.json` |
|---|---|---|
| at the start | the old catalog | none |
| `CreateTemp`, `Write`, `Sync`, `Close` | the old catalog, untouched | the new catalog is written and reaches the disk |
| `os.Rename` | the new catalog (the name moved in one step) | none (it is now `bozor.json`) |

`os.Rename` is a single operation of the Linux kernel (the `rename(2)` system call): the name moves to the new file **atomically**, that is, in one step. Atomic means: a reader sees either the old or the new catalog, never half of one. The man page says: "newpath will be atomically replaced". The order matters: `Sync` comes before rename. If the power goes off after a rename without `Sync`, the new name may point to a file that was never written to disk (`fsync(2)` and the `os.File.Sync` documentation).

An intermediate question. `Save` did `Sync`, but the power went off before `Rename`. What is in `bozor.json` after the computer starts again?

**A)** a half-written catalog · **B)** the old catalog, whole · **C)** the new catalog

<details>
<summary>Answer</summary>

**B.** `Rename` never happened, so `bozor.json` was not touched: the old catalog is whole. Only the dotted temporary file (`.bozor-*.json`) may be left: you can delete it by hand. If you chose **A**, you thought the write goes into `bozor.json` itself: it does not, it goes into another file. If you chose **C**, you thought `Sync` puts the new catalog in place: `Sync` only flushes the temporary file to disk, and the one that switches the name is `Rename`. In production, state and configuration files are written the same way: `github.com/google/renameio` packages exactly this technique.

</details>

### Where the guarantee ends

- **One file system.** Rename is one step only inside a single file system; to another one it returns the error `EXDEV` ("invalid cross-device link"). That is why the temporary file is opened **next to** `bozor.json` (`filepath.Dir(path)`). You will see the error itself in "Common mistakes".
- **Linux and macOS.** `go doc os.Rename`: "Even within the same directory, on non-Unix platforms Rename is not an atomic operation". The guarantee is for Unix systems.
- **The folder entry.** For a full "even if the power goes off" guarantee, the folder itself must also be synced after the rename. CLI v0 does not do this: in the worst case the old catalog stays, not a half-written file (the course README).
- **One process.** If two `bozor` processes run at the same time, the last `rename` wins: there is no file lock. According to the README this is deliberately left until the mutex in module 4 and the Postgres transaction in module 5.

## Bug: vet is silent, the test catches it

Now a real bug. Your teammate "simplified" `Sell`: one `range` loop instead of `find` (`_video/01-nusxa`). The code builds:

```go showLineNumbers
func (s *Store) Sell(id int64, quantity int) (Product, error) {
	if quantity <= 0 {
		return Product{}, fmt.Errorf("%w, hozir %d", ErrBadQuantity, quantity)
	}
	for _, p := range s.products {
		if p.ID == id {
			if p.Stock < quantity {
				return Product{}, &StockError{Name: p.Name, Stock: p.Stock, Want: quantity}
			}
			p.Stock -= quantity
			return p, nil
		}
	}
	return Product{}, fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
}
```

## Common mistakes

**Mistake 1: testing only the return value.** This is the most common misconception: "the function returned the right value, so it works". Let us add such a test to the folder with the bug, `_video/01-nusxa` (it is not in the course folder, full code):


## Check yourself

**1.** Why does `Save` open the temporary file right next to `bozor.json`?

<details>
<summary>Answer</summary>

`os.Rename` is a single step only inside one file system. If the temporary file is on another file system, `rename` returns the error `invalid cross-device link` (`EXDEV`) and the atomicity is lost. `filepath.Dir(path)` takes the folder from `bozor.json` itself.

</details>

**2.** Why does `run` take the file path and an `io.Writer` as parameters?

<details>
<summary>Answer</summary>

A test can call `run` with a file in its own temporary folder (`t.TempDir()`) and read the output from memory (`strings.Builder`). And `main` passes `dataFile` and `os.Stdout`. The whole CLI is checked without touching the real `bozor.json` and without printing to the screen.

</details>

**3.** (GB-3.03) Does `go test` run all the checks of `go vet`?

<details>
<summary>Answer</summary>

No. `go test` runs only a small part of the vet checks: 11 out of 35 (GB-3.03). For the full check, `go vet ./...` is run separately. And today's `range`-copy bug was found neither by `go vet` nor by `staticcheck`: a test caught it.

</details>

**4.** After `./bozor order 1 3`, `./bozor order 1 38` was run (the stock of `olma` is 37). What is printed, and what is the exit code?

<details>
<summary>Answer</summary>

38 were requested, the stock has 37: `Sell` returns a `*StockError`, `message` turns it into "xato: olma: faqat 37 dona qoldi" ("error: olma: only 37 left"), and `main` sets exit code 1 (it is not a usage error). The catalog does not change: on error, `run` does not call `Save`.

```console
$ ./bozor order 1 3
buyurtma: olma × 3 = 36000 soʻm, qoldiq 37
$ ./bozor order 1 38; echo $?
xato: olma: faqat 37 dona qoldi
1
```

</details>

**5.** (GB-2.09) Why does `Save` need the named result `(err error)`?

<details>
<summary>Answer</summary>

The anonymous function inside `defer` sees `err` at the moment the function ends: whatever `return os.Rename(…)` or another `return err` returned, `err` gets that value. If `err != nil`, `defer` closes the temporary file and deletes it with `os.Remove`. Without a named result, `defer` could not see the returned error.

</details>

`Restock` is the reverse of `Sell`: first check `quantity`, then `find`, then `p.Stock += quantity` and `return *p, nil`. A constant is handy for the limit:

```go showLineNumbers
// maxRestock — bitta Restock'da qoʻshiladigan eng koʻp dona (xato yozilgan sondan himoya).
const maxRestock = 10_000

// Restock id'li mahsulotning qoldigʻiga quantity dona qoʻshadi va yangilangan mahsulotni qaytaradi.
// Xato boʻlsa katalog oʻzgarmaydi: ErrBadQuantity (quantity 1..maxRestock emas), ErrNotFound.
func (s *Store) Restock(id int64, quantity int) (Product, error) {
	if quantity <= 0 {
		return Product{}, fmt.Errorf("%w, hozir %d", ErrBadQuantity, quantity)
	}
	if quantity > maxRestock {
		return Product{}, fmt.Errorf("%w: bir martada koʻpi bilan %d, hozir %d", ErrBadQuantity, maxRestock, quantity)
	}
	p := s.find(id)
	if p == nil {
		return Product{}, fmt.Errorf("mahsulot %d: %w", id, ErrNotFound)
	}
	p.Stock += quantity
	return *p, nil
}
```
