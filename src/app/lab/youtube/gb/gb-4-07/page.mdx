## Nimani oʻrganasiz

bozorning har bir testi oʻtadi. Lekin ming soʻrov bir vaqtda kelganda dastur qulaydi yoki oʻrikning qoldigʻi notoʻgʻri chiqadi.
Savol: bitta soʻrovda toʻgʻri ishlaydigan kod ming soʻrovda nega buziladi va buni qanday topib, qanday tuzatasiz?

**Bitta gʻoya:** server bir vaqtda kelgan soʻrovlarni alohida **goroutine**'larda ishlatadi (har yangi ulanish uchun bittadan), shuning uchun hamma handler xotiradagi bitta katalogga (`map`) bir vaqtda murojaat qiladi.
Kamida bittasi yozayotgan, sinxronlashsiz murojaat — **data race**: oʻqish–oʻzgartirish–yozish qadamlari aralashib, yangilanish yoʻqoladi (yoki runtime dasturni `fatal error: concurrent map …` bilan toʻxtatadi).
`go test -race` har bunday juftlikni topadi; **`sync.Mutex`** (`Lock` + `defer Unlock`) oʻsha qadamni boʻlinmas qiladi.
Qoida: umumiy maʼlumotga **har** murojaat, oʻqish ham, bir xil qulf ostida.

Dars oxirida siz:

- `curl` bilan serverning soʻrovlarni bir vaqtda ishlatishini koʻrasiz;
- ming parallel soʻrov bilan `go test` nega qulashini bilasiz va `go test -race` hisobotini (`Read at` / `Previous write`, fayl:qator) oʻqiysiz;
- `Sell` metodini `sync.Mutex` bilan tuzatasiz va qulf qoidasini aytib berasiz;
- mutex'ni nusxalash xatosini `go vet` bilan topasiz;
- vazifada `Restock`ni himoyalab, `Total`ni yozasiz va `go test .` ni oʻtkazasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| goroutine | boshqa chaqiruvlar bilan bir vaqtda ishlaydigan funksiya; server har yangi ulanishni bittasiga beradi | goroutine |
| data race | bitta xotira joyiga kamida bittasi yozadigan, sinxronlashsiz murojaat | data race |
| mutex (qulf) | bir vaqtda faqat bitta goroutine ushlab tura oladigan qulf; qolganlari kutadi | `sync.Mutex` |

Yordamchi: `wg.Go` va `wg.Wait` (faqat "boshlaydi" va "kutadi"; `sync.WaitGroup`ning oʻzi [GB-7.01](/lab/youtube/gb#gb-7-01)da), yoʻqolgan yangilanish (oʻqish–oʻzgartirish–yozish qadamlari aralashishi) va `409 Conflict`.
Boshqa yangi nomlarning hammasiga yoʻlda bitta jumla beraman.

## Soʻrovlar bir vaqtda ishlaydi

Avval isbot kerak: server bir vaqtda kelgan soʻrovlarni haqiqatan birga ishlatadimi? Buning uchun oʻzimiz sekin handler yozamiz. `slowHandler` ogʻir ishni taqlid qiladi:
u boshlanganini yozadi, bir soniya uxlaydi va tugaganini yozadi. `time.Sleep` bazani yoki tashqi servisni kutishning oʻrnini bosadi.

```go filename="_video/01-slow/main.go" showLineNumbers
package main

import (
	"fmt"
	"log"
	"net/http"
	"time"
)

func slowHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Println("boshladi")
	time.Sleep(time.Second)
	fmt.Println("tugadi")
}

func main() {
	http.HandleFunc("/slow", slowHandler)
	log.Fatal(http.ListenAndServe("localhost:8085", nil))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10 | `func slowHandler(w http.ResponseWriter, r *http.Request) {` | handler: [GB-4.03](/lab/youtube/gb/gb-4-03)dagi imzo. `slowHandler` nomini biz tanladik |
| 11 | `fmt.Println("boshladi")` | serverning oʻz terminaliga "boshladi" yozadi (javob body'siga emas) |
| 12 | `time.Sleep(time.Second)` | goroutine'ni bir soniya uxlatadi; `time.Second` — [GB-4.02](/lab/youtube/gb/gb-4-02)dagi bir soniya |
| 13 | `fmt.Println("tugadi")` | uxlagandan keyin "tugadi" yozadi |
| 17 | `http.HandleFunc("/slow", slowHandler)` | `/slow` yoʻlini shu handler'ga ulaydi ([GB-4.04](/lab/youtube/gb/gb-4-04)) |
| 18 | `log.Fatal(http.ListenAndServe("localhost:8085", nil))` | 8085-portni tinglaydi; port band boʻlsa, xatoni yozib dasturni tugatadi |

Handler javob body'siga hech narsa yozmaydi, shuning uchun `curl` hech narsa chiqarmaydi. Koʻrinadigan chiqish — serverning yozuvlari (logi).

Serverni ishga tushiramiz. Videoda bitta terminal ishlatildi, shuning uchun buyruq oxirida `&` turadi: shell buyruqni fonda ishga tushiradi va terminal boʻsh qoladi (shell faqat `[1] 12345` kabi fon-ish qatorini yozadi: bu dasturning chiqishi emas).
Sizga qulayroq variant: ikkita terminal — birinchisida `./_video/run.sh 01-slow go run .`, ikkinchisida `curl`; serverni birinchisida `Ctrl+C` bilan toʻxtatasiz.

```console
$ go run . &
```

Bu buyruq hech narsa chiqarmaydi: server fonda ishlay boshlaydi.

Ikkinchi buyruq: bitta `curl`, uchta bir xil manzil.

```bash
$ curl -s --parallel --parallel-immediate localhost:8085/slow localhost:8085/slow localhost:8085/slow
```

|---|---|
| `-s` | ortiqcha chiqishni (yuklash chizigʻini) yashiradi |
| `--parallel` | manzillarni ketma-ket emas, bir vaqtda soʻraydi |
| `--parallel-immediate` | uchala ulanishni darhol ochadi; usiz `curl` ulanishni qayta ishlatish mumkinligini kutib, ikkinchi va uchinchi soʻrovni kechiktiradi |

Bashorat qiling. Uchta manzil bir vaqtda ketdi. Serverning yozuvlari qanday tartibda chiqadi?

**A)** `boshladi`, `tugadi` — uch marta ketma-ket · **B)** uchta `boshladi`, keyin uchta `tugadi` · **C)** faqat bitta soʻrov javob oladi

<details>
<summary>Javob</summary>

**B.** Uchala soʻrov birga ishladi: har biri `boshladi` yozdi va uxlashga ketdi, bir soniyadan keyin hammasi `tugadi` yozdi.
**A** ni tanlagan boʻlsangiz, server soʻrovlarni navbat bilan ishlaydi deb oʻyladingiz: unda har bir `boshladi` oʻz `tugadi`sidan keyin kelardi va hammasi uch soniya olardi. **C** da ikkinchi va uchinchi soʻrov rad etiladi deb oʻyladingiz; server rad etmaydi.

</details>

|---|---|---|

Oʻlchovlar mashina yuklamasiga qarab biroz oʻzgaradi; muhimi — nisbat. Uchta soʻrov bir soniyaga sigʻdi: ular ustma-ust ishladi. Ketma-ket ishlasa uch soniya ketardi.
`--parallel-immediate`siz `curl` uchinchi soʻrovlarni kechiktirdi (2 soniya), shuning uchun bu bayroq bu yerda kerak.

**Nima uchun serverda shunday boʻladi?** `net/http`ning `Server.Serve` metodi ulanishlarni qabul qiladi va **har yangi ulanish uchun** yangi xizmat goroutine'i yaratadi; goroutine soʻrovni oʻqib, handler'ni chaqiradi ([hujjat](https://pkg.go.dev/net/http#Server.Serve)).
**Goroutine** — boshqa chaqiruvlar bilan bir vaqtda ishlaydigan funksiya; toʻliq tushuntirish [GB-7.01](/lab/youtube/gb#gb-7-01)da. Bugun bizga bitta narsa muhim: ular bir vaqtda ishlaydi.
Uchta `curl` uchta ulanish ochdi, shuning uchun `slowHandler` uch marta birga ishladi. Bitta ulanishdagi soʻrovlar esa ketma-ket oʻqiladi: bir vaqtlilik *turli* ulanishlardan keladi.

| Qadam | Nima boʻladi |
|---|---|
| 1 | uchta ulanish bir vaqtda keladi |
| 2 | server har biri uchun alohida goroutine ochadi |
| 3 | handler uch marta birga ishlaydi |
| 4 | handler'lar bir xil maʼlumotga (masalan katalogga) murojaat qilishi mumkin: xavf shu yerda |

## Katalog va `Sell`: bitta soʻrovda hammasi toʻgʻri

Endi "bir xil maʼlumot". bozor katalogi xotirada turadi: `Store` struct'i va ichida `products` map'i. Kalit — mahsulot ID'si, qiymat — `Product`.
ID boʻyicha topish uchun slice emas, map. Bu darsda katalog qisqartirilgan va oʻz papkasida turadi; [GB-4.08](/lab/youtube/gb#gb-4-08)da bozorning qolgan qismi bilan birlashtiramiz.

Mana mutex'siz variant, `_video/02-race/main.go`. Hamma qatorni tushuntiraman, chunki bugungi xato aynan shu yerda yashiringan:

```go filename="_video/02-race/main.go" showLineNumbers
package main

import (
	"errors"
	"fmt"
	"net/http"
)

// Product — katalogdagi bitta mahsulot (GB-3.02).
type Product struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Price int64  `json:"price"` // tiyin
	Stock int    `json:"stock"`
}

// ErrStock — mahsulot yoʻq yoki omborda soʻralgancha dona yoʻq.
var ErrStock = errors.New("qoldiq yetmaydi")

// Store — xotiradagi katalog: ID → mahsulot.
type Store struct {
	products map[int64]Product
}

// Sell id'li mahsulotdan quantity dona sotadi (quantity musbat deb olinadi: bu laboratoriya soddalashtirilgan).
func (s *Store) Sell(id int64, quantity int) error {
	p, ok := s.products[id]
	if !ok || p.Stock < quantity {
		return ErrStock
	}
	p.Stock -= quantity
	s.products[id] = p
	return nil
}

// buy — POST /buy: oʻrikdan (ID 3) bitta dona sotadi. Soddalik uchun har xato 409 Conflict (haqiqiy API'da yoʻq
// mahsulot 404 boʻlardi).
func (s *Store) buy(w http.ResponseWriter, r *http.Request) {
	if err := s.Sell(3, 1); err != nil {
		w.WriteHeader(http.StatusConflict)
		return
	}
	fmt.Fprintln(w, "sotildi")
}

func main() {
	st := &Store{products: map[int64]Product{
		3: {ID: 3, Name: "oʻrik", Price: 3_500_000, Stock: 5},
	}}
	http.HandleFunc("POST /buy", st.buy)
	http.ListenAndServe("localhost:8080", nil)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10–15 | `type Product struct {…}` | mahsulot ([GB-3.02](/lab/youtube/gb/gb-3-02)); narx `int64`, tiyinda |
| 18 | `var ErrStock = errors.New("qoldiq yetmaydi")` | xato qiymati ([GB-2.08](/lab/youtube/gb/gb-2-08)): sotib boʻlmasa shu qaytadi |
| 21–23 | `type Store struct { products map[int64]Product }` | katalog: `map[int64]Product` — kalit ID (`int64`), qiymat `Product` |
| 26 | `func (s *Store) Sell(id int64, quantity int) error {` | `id` boʻyicha `quantity` dona sotadi, `quantity` — dona soni; pointer receiver ([GB-2.05](/lab/youtube/gb/gb-2-05)) |
| 27 | `p, ok := s.products[id]` | map'dan mahsulotning **nusxasini** `p` ga va bor-yoʻqligini `ok` ga oladi ([GB-2.02](/lab/youtube/gb/gb-2-02)) |
| 28–30 | `if !ok \|\| p.Stock < quantity { return ErrStock }` | mahsulot yoʻq yoki qoldiq yetmasa — `ErrStock` |
| 31 | `p.Stock -= quantity` | nusxadagi qoldiqni kamaytiradi |
| 32 | `s.products[id] = p` | nusxani map'ga qaytarib **yozadi** |
| 33 | `return nil` | xato yoʻq |
| 38 | `func (s *Store) buy(w http.ResponseWriter, r *http.Request) {` | `POST /buy` handler'i |
| 39–42 | `if err := s.Sell(3, 1); err != nil { w.WriteHeader(http.StatusConflict); return }` | oʻrikdan (ID 3) bitta dona sotadi; xato boʻlsa status `409` va `return` |
| 43 | `fmt.Fprintln(w, "sotildi")` | muvaffaqiyatda javob: `sotildi` |
| 46–52 | `func main() {…}` | katalogda bitta mahsulot (oʻrik, qoldiq 5), `POST /buy` ulangan, server 8080-portda |

`409 Conflict` — "soʻrov resursning hozirgi holatiga zid" ([RFC 9110 §15.5.10](https://www.rfc-editor.org/rfc/rfc9110#name-409-conflict)): qoldiq yetmasa, soʻrov katalogning hozirgi holatiga zid.
Laboratoriya soddalashtirishi: `buy` har xatoga `409` beradi; haqiqiy API'da yoʻq mahsulot uchun `404` boʻlardi.

Eng muhimi — `Sell`ning ichi uch qadam: 27-qatorda **oʻqiymiz**, 31-qatorda **oʻzgartiramiz**, 32-qatorda **yozamiz**. Bitta soʻrovda bu uch qadam ketma-ket va toʻgʻri.

## Yoʻqolgan yangilanish: ikki soʻrov, bitta qoldiq

Endi ikkita soʻrov, A va B, bir vaqtda `Sell`ga kirdi. Oʻrikning qoldigʻi 5. Har biri bitta dona sotmoqchi, demak oxirida qoldiq 3 boʻlishi kerak.
Qadamlar aralashib ketgan holat:

| Vaqt | A | B | Katalogdagi `Stock` |
|---|---|---|---|
| 1 | `p, ok := s.products[id]` → `p.Stock` = 5 | | 5 |
| 2 | | `p, ok := s.products[id]` → `p.Stock` = 5 | 5 |
| 3 | `p.Stock -= 1` → nusxada 4; `s.products[id] = p` | | 4 |

Ikkinchi soʻrov ham oʻz nusxasini 4 deb yozadi. Oxirida qoldiq nechta?

**A)** 3 · **B)** 4 · **C)** 5

<details>
<summary>Javob</summary>

**B — 4.** B 2-vaqtda qoldiqni 5 deb oʻqigan edi va A yozganini koʻrmadi; u oʻz nusxasini 4 ga tushirib yozdi. Ikki dona sotildi, lekin qoldiq faqat bittaga kamaydi: bitta yangilanish **yoʻqoldi**.
**A** (3) — soʻrovlar ketma-ket ishlagandagi toʻgʻri natija, lekin bu yerda ular aralashgan. **C** (5) boʻlishi uchun ikkalasi ham yozmagan boʻlishi kerak edi.

</details>

| Vaqt | A | B | `Stock` |
|---|---|---|---|
| 4 | | `p.Stock -= 1` → nusxada 4; `s.products[id] = p` | 4 (kutilgan: 3) |

Bu — **data race**: ikki goroutine **bitta xotira joyiga**, kamida biri **yozish** bilan, **sinxronlashsiz** (orada kutish yoʻq) murojaat qildi. Uchala shart birga boʻlsa — data race.
Map'ga bir vaqtda yozish Go'da ruxsat etilmagan: **runtime** — dastur bilan birga ishlaydigan Go'ning oʻz kodi — buni sezsa, dasturni toʻxtatadi (`fatal error`). Sezmasa, yuqoridagidek jimgina notoʻgʻri qoldiq chiqadi.

## Ming soʻrov bilan test

Buni testda qayta yaratamiz. `buy_test.go` ichida yordamchi funksiya `orderParallel` n ta `POST /buy` soʻrovini bir vaqtda yuboradi:

```go filename="buy_test.go" showLineNumbers
package main

import (
	"net/http"
	"net/http/httptest"
	"sync"
	"testing"
)

// orderParallel n ta "POST /buy" soʻrovini bir vaqtda yuboradi.
func orderParallel(st *Store, n int) {
	var wg sync.WaitGroup
	for range n {
		wg.Go(func() {
			st.buy(httptest.NewRecorder(), httptest.NewRequest(http.MethodPost, "/buy", nil))
		})
	}
	wg.Wait()
}

func TestBuyParallel(t *testing.T) {
```

Lekin u faqat **ishga tushgan** kodda topadi, shuning uchun test kodni parallel chaqirishi kerak (bizning `orderParallel` shuni qiladi). `go test -race` har loyihada, CI'da ishlaydi; CI'ni [GB-8.05](/lab/youtube/gb#gb-8-05)da koʻramiz.

## `sync.Mutex`: `Lock` va `defer Unlock`

Tuzatish: `Store`ga `mu` maydonini qoʻshamiz, turi `sync.Mutex` — **qulf**. Uni bir vaqtda faqat bitta goroutine ushlab tura oladi, qolganlari kutadi.
Nol qiymati tayyor: ochiq qulf, alohida yaratish shart emas. `mu` nomini biz tanladik.

```go
type Store struct {
	mu       sync.Mutex
	products map[int64]Product
}
```

`Sell`ning boshiga ikki qator:

```go
func (s *Store) Sell(id int64, quantity int) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	p, ok := s.products[id]
	if !ok || p.Stock < quantity {
		return ErrStock
	}
	p.Stock -= quantity
	s.products[id] = p
	return nil
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 2 | `s.mu.Lock()` | qulfni oladi; band boʻlsa, boʻshaguncha kutadi |
| 3 | `defer s.mu.Unlock()` | `defer` ([GB-2.09](/lab/youtube/gb/gb-2-09)): `Sell` qanday tugasa ham — `return ErrStock` bilan ham, `return nil` bilan ham — qulf qoʻyib yuboriladi |
| 4–9 | oʻqish, tekshirish, yozish | oldingi kod oʻzgarmadi, lekin endi bitta **boʻlinmas** qadam: ikkinchi soʻrov kutadi |

Endi A va B shunday ishlaydi:

| Qadam | A | B | Qulf |
|---|---|---|---|
| 1 | `Lock` — oldi | | A'da |
| 2 | oʻqiydi, yozadi (qoldiq 4) | `Lock` da kutadi | A'da |
| 3 | `Unlock` — qoʻyib yubordi | | boʻsh |
| 4 | | `Lock` — oldi | B'da |
| 5 | | oʻqiydi (4), yozadi (3) | B'da |

Poyga yoʻq: B qoldiqni A yozgandan **keyin** oʻqiydi. Xuddi shu test, xuddi shu `-race`:

```console
$ go test -race
ok  	github.com/abdurahmon27/bozor	1.018s
```

Ming soʻrov, race yoʻq, qoldiq 0. Bu yerdagi taxminan bir soniyaning asosiy sababi — race runtime chiqishdan oldin kutishi: `GORACE` sozlamasi `atexit_sleep_ms` sukut boʻyicha `1000` millisoniya ([Data Race Detector](https://go.dev/doc/articles/race_detector#Options)). Bu vaqtni oddiy `go test`dagi `0.005s`ga boʻlib, kod 200 barobar sekinlashdi deb boʻlmaydi.

Tekshirish uchun kutishni oʻchiramiz; `-count=1` test natijasi keshdan olinmasligini taʼminlaydi:

```console
$ GORACE=atexit_sleep_ms=0 go test -race -count=1 .
ok  	github.com/abdurahmon27/bozor	0.082s
```

`_video/race.sh 03-mutex` Docker muhitida (go1.27.4 linux/amd64) qayta oʻlchadim: uch ishga tushirishda `ok` qatoridagi vaqt odatiy `-race` bilan 1,045–1,062 s, kutishsiz 0,067–0,082 s boʻldi. Oldindan yigʻilgan test dasturlarida alohida oʻlchov: kutishsiz race wall vaqtining uchta oʻlchov boʻyicha oʻrtachasi 0,102 s, oddiy rejimda 0,036 s (taxminan 2,8 barobar; jarayon boshlanishi ham kiradi). Bu qisqa test ishlash tezligi uchun benchmark emas. Race tekshiruvining oʻzi ham qoʻshimcha vaqt va xotira sarflaydi: hujjatdagi odatiy oraliq 2–20 barobar vaqt va 5–10 barobar xotira ([Data Race Detector](https://go.dev/doc/articles/race_detector#Runtime_Overhead)). `-race`ni parallel testlar va CI'da ishlatamiz.

`Store`ga `Stock` metodini qoʻshamiz: `id` boʻyicha qoldiqni qaytaradi, **faqat oʻqiydi**:


Savol: hamma yozuvchi (`Sell`) qulf ostida. `Stock` faqat oʻqiydi. Unga qulf kerakmi?

**A)** yoʻq: oʻqish zarar qilmaydi · **B)** ha: oʻqish ham qulf ostida · **C)** faqat bitta yozuvchi boʻlsa

<details>
<summary>Javob</summary>

**B.** Yuqoridagi hisobotda oʻqish ham bor edi: `Read at` va `Previous write`. Yozuvchi qulf ostida, oʻquvchi qulfsiz boʻlsa, ular baribir toʻqnashadi: oʻquvchi map'ni yozuvchi oʻzgartirayotgan paytda oʻqiydi.
Buni isbotlash uchun kichik misol tuzdim; u kurs papkasida **yoʻq**, men uni ishga tushirdim, shuning uchun toʻliq kodini keltiraman. `Sell` qulf ostida, `Stock` esa qulfsiz; ikkita goroutine: biri 500 marta `Sell`, ikkinchisi 500 marta `Stock`:

```go
package main

import (
	"fmt"
	"sync"
)

type Store struct {
	mu    sync.Mutex
	stock map[int64]int
}

func (s *Store) Sell(id int64, quantity int) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.stock[id] -= quantity
}

// Stock qulfsiz oʻqiydi: yozuvchi (Sell) qulf ostida, oʻquvchi qulfsiz.
func (s *Store) Stock(id int64) int {
	return s.stock[id]
}

func main() {
	st := &Store{stock: map[int64]int{3: 1000}}
	var wg sync.WaitGroup
	wg.Go(func() {
		for range 500 {
			st.Sell(3, 1)
		}
	})
	wg.Go(func() {
		for range 500 {
			st.Stock(3)
		}
	})
	wg.Wait()
	fmt.Println("qoldiq:", st.Stock(3))
}
```

## Mutex'ni nusxalamang

Klassik xato: `Sell`ni yulduzchasiz yozish.

```go
func (s Store) Sell(id int64, quantity int) error {
	s.mu.Lock()
	defer s.mu.Unlock()
```

Qabul qiluvchi (`s`) `Store` **qiymat** boʻlib keladi ([GB-2.05](/lab/youtube/gb/gb-2-05)): har chaqiruv `Store`ning **nusxasini** oladi, qulf ham nusxalanadi.
Har soʻrov oʻz nusxasidagi qulfni ushlaydi, hech kim hech kimni kutmaydi — himoya yoʻq, `go test` yana qulaydi (men `_video/04-nusxa`da tekshirdim: 6 ta ishga tushirishda 6 marta `fatal error`).
Sababini `go vet` topadi:

```console
$ go vet ./...
main.go:28:9: Sell passes lock by value: github.com/abdurahmon27/bozor.Store contains sync.Mutex
```

Oʻqish: `main.go:28:9` — fayl, 28-qator, 9-ustun (`Store` turi yozilgan joy). `Sell passes lock by value` — "`Sell` qulfni qiymat bilan uzatyapti"; `Store contains sync.Mutex` — `Store` ichida `sync.Mutex` bor ([`go vet`, copylocks](https://pkg.go.dev/cmd/vet)).
Tuzatish — yulduzcha: `func (s *Store) Sell(…)`. Qulf nusxalanmaydi, hamma chaqiruv bitta qulfni ushlaydi va `go vet` jim boʻladi.

## Chuqurroq (ixtiyoriy): iterator ichida qulf — deadlock

[GB-3.05](/lab/youtube/gb/gb-3-05)dagi `All` iteratorini qulf bilan oʻraymiz, sodda variant: `Lock` va `defer Unlock`, `yield`ni ham shu qulf ostida chaqiramiz.

```go
func (s *Store) All() iter.Seq[Product] {
	return func(yield func(Product) bool) {
		s.mu.Lock()
		defer s.mu.Unlock()
		for _, p := range s.products {
			if !yield(p) {
				return
			}
		}
	}
}
```

Endi sikl tanasida `Sell`ni chaqiramiz. Sikl tanasi `yield` boʻlib ishlaydi, yaʼni `All` qulfni ushlab turgan paytda:

```go
for p := range st.All() {
	st.Sell(p.ID, 1)
}
```

Pastdan yuqoriga oʻqing: `main.main` → `All.func1` (`All` ichidagi birinchi nomsiz funksiya; sikl tanasini shu chaqiradi) → `main.main-range1` (sikl tanasi) → `Sell` → `Lock`.

## Koʻp uchraydigan xatolar

**1. "Test oʻtdi, demak xavfsiz."** Eng keng tarqalgan xato. Bitta soʻrovli test `ok` beradi, mutex'siz kod ham bir goroutine'da toʻgʻri ishlaydi: bu darsning boshidagi `Sell` shunday.
Data race faqat kod parallel chaqirilganda ochiladi. Davosi: parallel test (`orderParallel`) va `go test -race` — baʼzan `ok` ham beradigan oddiy `go test`ga ishonmang.

**2. `-race` ishlamaydi.** Linux'da C kompilyator yoʻq boʻlsa:

```console
$ go test -race
go: -race requires cgo; enable cgo by setting CGO_ENABLED=1
```

Bu shu mashinada, `go env CGO_ENABLED` `0` boʻlganda chiqadi: kompilyator topilmagani uchun Go `cgo`ni oʻzi oʻchirib qoʻygan. `CGO_ENABLED=1` bilan majburlasangiz ham, kompilyatorsiz xato shu:

```console
$ CGO_ENABLED=1 go test -race
# runtime/cgo
cgo: C compiler "gcc" not found: exec: "gcc": executable file not found in $PATH
FAIL	github.com/abdurahmon27/bozor [build failed]
```

Linux'da tuzatish: C kompilyator oʻrnating (masalan, `apt install gcc`) va `cgo` yoqilganini tekshiring (`go env CGO_ENABLED`: `1`). macOS'da Go 1.20'dan beri race detector uchun Xcode/cgo kerak emas ([Go 1.20 eslatmalari](https://go.dev/doc/go1.20#cgo)). Men Linux'da Docker'dan foydalandim (`_video/race.sh`).

**3. Faqat yozuvchini qulflash.** `Sell` qulf ostida, `Stock` qulfsiz: oʻqish ham poyga ("Oʻqish ham qulf ostida" boʻlimidagi hisobot). Qoida: `products`ga har murojaat bir xil qulf ostida.

**4. Qulfni nusxalash.** `func (s Store) Sell`: `go vet` aytadi ("Mutex'ni nusxalamang" boʻlimi). Tuzatish — pointer receiver.

**5. Qulf ichida yana `Lock`.** `Total` ichida `s.Stock(…)` chaqirilsa, `Stock` ham `Lock` chaqiradi, qulf esa allaqachon `Total`da: deadlock, yuqoridagi "Chuqurroq" boʻlimidagi sabab bilan bir xil. Davosi — qulfni bir marta olish va ichida `s.products`ga toʻgʻridan-toʻgʻri murojaat qilish (vazifa).

## Oʻzingizni tekshiring

**1.** Server bir vaqtda kelgan soʻrovlarni nimada ishlatadi va bu nega xavfli?

<details>
<summary>Javob</summary>

**Goroutine'larda**: server har yangi ulanishni alohida goroutine'ga beradi, handler'lar bir vaqtda ishlaydi va umumiy maʼlumotga (katalog `map`) bir vaqtda murojaat qiladi. Kamida bittasi yozsa va sinxronlash boʻlmasa, yangilanish yoʻqoladi yoki runtime dasturni toʻxtatadi.

</details>

**2.** Data race nima va qaysi bayroq uni topadi?

<details>
<summary>Javob</summary>

Data race — **bitta xotira joyiga**, **kamida bitta yozish bilan**, **sinxronlashsiz** murojaat. Uni `go test -race` topadi (C kompilyator kerak va faqat ishga tushgan kodda).

</details>

**3.** `Sell` ichidagi `defer s.mu.Unlock()` qachon bajariladi: faqat `return nil`da, yoki `return ErrStock`da ham?

<details>
<summary>Javob</summary>

**Ikkala holatda ham.** `defer` funksiya qanday tugashidan qatʼi nazar, tugashi bilan ishlaydi; `return ErrStock` ham, `return nil` ham `Sell`ni tugatadi. Shuning uchun xato yoʻli qulfni ochiq qoldirmaydi ([GB-2.09](/lab/youtube/gb/gb-2-09)).

</details>

**4.** Bashorat qiling: vazifadagi `Total` boshida `s.mu.Lock()` turibdi, ichida esa `s.Stock(1)` chaqirilsa, nima boʻladi?

**A)** hammasi ishlaydi · **B)** `Stock` qulf kutib qoladi: deadlock · **C)** kompilyatsiya xatosi

<details>
<summary>Javob</summary>

**B.** `Total` qulfni ushlab turibdi, `Stock` esa `Lock` chaqiradi va oʻsha qulfni kutadi. Bir goroutine `sync.Mutex`ni ikki marta ola olmaydi: "Chuqurroq" boʻlimidagi `All` + `Sell` bilan bir xil sabab.
Bu kodni bu yerda alohida ishga tushirmadim; xulosa shu boʻlimdagi real `deadlock` chiqishiga asoslangan. **A** — qulf oʻzini oʻzi kutmaydi deb oʻylagan boʻlsangiz; **C** — kompilyator qulflarni tekshirmaydi.

</details>

**5.** Oldingi darsdan ([GB-4.04](/lab/youtube/gb/gb-4-04)): `http.ListenAndServe` qachon qaytadi?

<details>
<summary>Javob</summary>

**Faqat xato bilan**, masalan port band boʻlsa. Shuning uchun uning natijasini tekshiramiz ([GB-4.04](/lab/youtube/gb/gb-4-04), [pkg.go.dev](https://pkg.go.dev/net/http#Server.ListenAndServe): "ListenAndServe always returns a non-nil error").

</details>

`main.go`da `Restock` yozilgan, lekin **qulfsiz** — videodagi `Sell`ning oldingi holati; `Total` esa hali yozilmagan (har doim `0` qaytaradi). `Restock` qoldiqqa dona qoʻshadi, mahsulot yoʻq boʻlsa `ErrNotFound` qaytaradi.
`Sell`, `Restock` va `Total` bir vaqtda chaqirilishi mumkin, shuning uchun `products`ga har murojaat bir xil qulf ostida boʻlishi kerak.

- 🟢 **1-qadam, `Restock`.** Metod boshiga `s.mu.Lock()` va keyingi qatorga `defer s.mu.Unlock()` qoʻying. Mantiq oʻzgarmaydi.

```go
func (s *Store) Restock(id int64, quantity int) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	p, ok := s.products[id]
	if !ok {
		return ErrNotFound
	}
	p.Stock += quantity
	s.products[id] = p
	return nil
}

func (s *Store) Total() int {
	s.mu.Lock()
	defer s.mu.Unlock()
	total := 0
	for _, p := range s.products {
		total += p.Stock
	}
	return total
}
```

`Restock`da qulf `Sell`dagidek: ikki qator, mantiq oʻzgarmaydi; `p.Stock += quantity` — `-=`ning teskarisi. `Total`: qulf bir marta, ichida `s.products`ga toʻgʻridan-toʻgʻri murojaat, `Stock(…)` chaqirilmaydi.
Tekshiruv natijalari (men ishga tushirdim):

```console
$ go test ./solution/
ok  	github.com/abdurahmon27/bozor/solution	0.013s
```

Javob `-race` bilan ham toza: Docker'da (`./_video/race.sh solution go test -race -count=1 .`) `ok  	github.com/abdurahmon27/bozor	4.061s` chiqdi (javob fayllari papka ildiziga koʻchiriladi, shuning uchun paket yoʻli `…/bozor`).

</details>
