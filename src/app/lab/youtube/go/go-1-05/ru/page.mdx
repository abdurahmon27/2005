## Что вы узнаете

Одна и та же программа, буква в букву. В одной папке она печатает `a.uz b.uz c.uz`, в другой — `c.uz c.uz c.uz`.
Разница не в тексте программы, а в одной строке файла настроек рядом с ней. Из-за точно такой же ошибки в 2020 году
Let's Encrypt выдал больше 3 миллионов сертификатов (документов безопасности для сайтов) без нужной
повторной проверки. Как такое возможно? В конце урока
разберём это полностью.

**Главная идея:** в Go любое повторение записывается одним `for`. На каждом шаге цикл записывает в свою переменную
копию значения, а начиная с Go 1.22 у каждого шага своя, новая переменная.

К концу урока вы сможете:

- читать и писать четыре формы `for` (из трёх частей, только с условием, бесконечный, `range`);
- понимать, что `range` даёт не сам элемент, а его копию, и менять список через индекс;
- читать `switch` и `fallthrough`, а изнутри `switch` выходить из всего цикла с помощью метки;
- объяснить, как одна строка в `go.mod` меняет поведение цикла.

Три главных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| переменная цикла | ярлык, который создал сам `for`: на каждом шаге в неё записывается новое значение | loop variable |
| `switch` (выбор) | по одному значению выбирает один путь из многих | switch statement |
| метка | имя, данное циклу: говорит, из какого именно цикла выходит `break` | label |

По дороге встретятся ещё два вспомогательных слова: **слайс** (список значений одного типа) и **адрес** (где
переменная лежит в памяти). Оба объясним там, где они понадобятся.

## Один for, четыре формы

Когда программе нужно сделать одно и то же много раз, мы пишем **цикл**: как стрелка часов, он идёт по кругу и
повторяет одни и те же шаги. Во многих языках для этого есть несколько слов: `for`, `while`, `do … while`.

А в Go **25 ключевых слов**. Ключевое слово — это слово, которое Go забрал себе (`for`, `if`, `func`…); его нельзя
использовать как имя. `while` среди них **нет**. В Go любой цикл записывается одним `for`.

Два правила:

- скобки `( )` вокруг условия **не нужны** (программа форматирования Go, `gofmt`, их убирает);
- фигурные скобки `{ }` **обязательны**, даже если внутри одна строка.

Все четыре формы — в одной программе. Это файл `shakllar/main.go` («формы») из папки курса:

```go filename="shakllar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	for i := 0; i < 3; i++ { // 1. uch qismli
		fmt.Print(i, " ")
	}
	n := 1
	for n < 100 { // 2. faqat shart (while)
		n *= 2
	}
	fmt.Println("|", n)
	for { // 3. cheksiz
		n -= 50
		if n < 0 {
			break
		}
	}
	fmt.Println(n)
	for i := range 3 { // 4. son ustida (Go 1.22+)
		fmt.Print(i, " ")
	}
	fmt.Println()
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1–5 | `package main` … `func main() {` | знакомый шаблон: программа начинается с `main` |
| 6 | `for i := 0; i < 3; i++ {` | **1-я форма, из трёх частей:** начало `i := 0`; условие `i < 3`; шаг `i++` (увеличивает `i` на 1). Всё после `//` — комментарий, Go его не читает |
| 7 | `fmt.Print(i, " ")` | выводит `i` и один пробел. `Print` **не** переходит на новую строку (этим он и отличается от `Println`) |
| 9 | `n := 1` | новый ярлык `n`, значение 1 |
| 10 | `for n < 100 {` | **2-я форма, только условие:** повторяет, пока условие `true`. Это `while` из других языков |
| 11 | `n *= 2` | короткая запись `n = n * 2`: пусть `n` станет вдвое больше |
| 13 | `fmt.Println("\|", n)` | выводит знак `\|` и `n`, потом переходит на новую строку |
| 14 | `for {` | **3-я форма, бесконечная:** условия нет, сам цикл не остановится |
| 15 | `n -= 50` | короткая запись `n = n - 50` |
| 16–18 | `if n < 0 { break }` | если `n` отрицательное, `break` выходит из цикла |
| 20 | `fmt.Println(n)` | выводит `n` после цикла |
| 21 | `for i := range 3 {` | **4-я форма, `range`:** по очереди даёт `i` значения 0, 1, 2 (само 3 не входит) |
| 24 | `fmt.Println()` | ничего не пишет, только переходит на новую строку |

`i` в 6-й строке и `i` в 21-й строке создал сам `for` (`:=` стоит прямо в строке `for`). Это тот же счётчик из
[GO-0.05](/lab/youtube/go#go-0-05): на каждом круге ярлык остаётся на месте, меняется значение под ним. Такой ярлык,
созданный самим циклом, называется **переменной цикла** (по-английски **loop variable**): на каждом шаге (итерации)
в неё записывается новое значение. А `n` из 9-й строки — не переменная цикла: она создана заранее, отдельно.

`range` есть в Go с самого начала. Начиная с **Go 1.22** он умеет ходить и по целому числу: `range 3` даёт 0, 1, 2.

Прежде чем запускать, подумайте: что будет во второй строке вывода? **A)** `100` · **B)** `128` · **C)** `-22`

<details>
<summary>Ответ</summary>

**C: `-22`** (а первая строка заканчивается на `| 128`). 2-я форма удваивает `n`, пока оно не превысит 100: 1, 2, 4, 8, 16, 32,
64, 128. 128 &lt; 100 — неправда, поэтому цикл останавливается. Потом бесконечный цикл каждый раз вычитает 50: 78, 28,
−22. −22 отрицательное, срабатывает `break`. Если вы выбрали «100»: `n` никогда не равно ровно 100, оно удваивается
и перепрыгивает через 100. А «128» стоит в конце первой строки.

</details>

```console
$ go run ./shakllar
0 1 2 | 128
-22
0 1 2 
```

Первая строка собрана из двух циклов: `Print` не переходит на новую строку, поэтому `| 128` встало сразу после
`0 1 2 `. Как менялось `n` в памяти:

| Где | Значения `n` | На экран |
|---|---|---|
| строка 9 | 1 | |
| 2-я форма (10–12) | 2 → 4 → 8 → 16 → 32 → 64 → 128 (условие `false`) | `\| 128` |
| 3-я форма (14–19) | 78 → 28 → −22 (`break`) | `-22` |

## По чему ходит range

Чтобы ходить с `range`, сначала нужно хранить несколько значений под одним именем. Например, три цены. Представьте
полку с пронумерованными ячейками: в каждой ячейке одна цена, а ячейки пронумерованы **с 0**.

```text
narxlar:   [ 100 ][ 200 ][ 300 ]
индекс:       0      1      2
```

Такой список в Go называется **слайс** (slice): `[]int{100, 200, 300}` — «список из `int`, внутри 100, 200, 300».
Каждое значение в списке — **элемент**, а его номер — **индекс**. `narxlar[0]` — элемент на месте 0, то есть 100.
Слайсы подробно изучим в [GO-1.08](/lab/youtube/go#go-1-08).

`range` ходит не только по числам. На каждом шаге он даёт одно или два значения:

| По чему | 1-е значение | 2-е значение | Где подробно |
|---|---|---|---|
| слайс | индекс | элемент (его копия!) | этот урок, [GO-1.08](/lab/youtube/go#go-1-08) |
| строка (`string`) | номер байта, с которого начинается руна | руна | [GO-1.04](/lab/youtube/go#go-1-04) |
| map (словарь «ключ → значение») | ключ | значение; порядок не гарантирован | [GO-1.09](/lab/youtube/go#go-1-09) |
| целое число `n` (Go 1.22+) | 0, 1, …, n−1 | — | этот урок |
| channel (труба между goroutine) | значения | — | [GO-1.21](/lab/youtube/go#go-1-21) |
| функция (Go 1.23+) | итератор | | [GO-1.18](/lab/youtube/go#go-1-18) |

Вместо ненужного значения пишут `_` (подчёркивание): `for _, n := range narxlar` — «индекс не нужен, только
элемент». Если нужно только первое значение, второе просто не пишут: `for i := range narxlar`.

## Ловушка: range даёт копию

Есть список цен `narxlar` («цены»), и мы хотим удвоить каждую цену. Вот первая часть `nusxa/main.go` («копия»;
остальное откроем после ответа):

```go
	narxlar := []int{100, 200, 300}
	for _, n := range narxlar {
		n *= 2
	}
	fmt.Println(narxlar)
```

- **Строка 6:** слайс `narxlar`, внутри 100, 200, 300.
- **Строка 7:** на каждом шаге `range` записывает очередной элемент в `n`; индекс выброшен через `_`.
- **Строка 8:** пусть `n` станет вдвое больше.
- **Строка 10:** выводит весь слайс. `Println` печатает слайс в квадратных скобках: `[1 2 3]`.

Что выведет `Println`? **A)** `[100 200 300]` · **B)** `[200 400 600]` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**A: `[100 200 300]`, слайс не изменился.** На каждом шаге `range` записывает в `n` **копию** элемента (так же,
как `rekord := ochko` в [GO-0.02](/lab/youtube/go/go-0-02/ru)). Мы удвоили копию, а исходного значения в слайсе никто не
касался. Если вы выбрали «B», вы думали, что `n` — это сам элемент. Не «C»: код написан правильно, он просто
делает не то, чего мы ждали.

</details>

Каждый шаг в памяти:

| Шаг | `n` (копия) | после `n *= 2` | `narxlar` |
|---|---|---|---|
| 1 | 100 | 200 | `[100 200 300]` |
| 2 | 200 | 400 | `[100 200 300]` |
| 3 | 300 | 600 | `[100 200 300]` |

Теперь запустим весь файл (в нём есть и вторая строка вывода, её разберём ниже):

```console
$ go run ./nusxa
[100 200 300]
[200 400 600]
```

Есть программы-проверяльщики, которые читают код, не запуская его, и находят подозрительные места; их называют
анализаторами кода. `go vet` поставляется вместе с Go. `staticcheck` устанавливается отдельно
(`go install honnef.co/go/tools/cmd/staticcheck@2026.2.1`) и попадает в папку `$(go env GOPATH)/bin/`; команда ниже
запускает его из этой папки.

```console
$ go vet ./nusxa
```

```console
$ $(go env GOPATH)/bin/staticcheck ./nusxa
nusxa/main.go:8:3: this value of n is never used (SA4006)
```

`go vet` молчит: он ничего не нашёл. А `staticcheck` указывает на строку 8, символ 3: *this value of n is never
used* — «это значение `n` никогда не используется». То есть удвоенная копия никуда не попадает.

Откуда же правильный результат во второй строке? Вот весь файл:

```go filename="nusxa/main.go" showLineNumbers
package main

import "fmt"

func main() {
	narxlar := []int{100, 200, 300}
	for _, n := range narxlar {
		n *= 2
	}
	fmt.Println(narxlar)

	for i := range narxlar {
		narxlar[i] *= 2
	}
	fmt.Println(narxlar)
}
```

- **Строка 12:** `for i := range narxlar` — берём только индекс: 0, 1, 2.
- **Строка 13:** `narxlar[i] *= 2` — удваивает не копию, а сам элемент в ячейке `i` слайса.
- **Строка 15:** теперь `[200 400 600]`.

Правило: если хотите изменить элемент слайса, пишите **через индекс**: `narxlar[i]`.

## switch: один путь из многих

Вспомните телефонное меню: «чтобы узнать баланс, нажмите 1; тариф — 2». По одной цифре выбирается один путь из
многих. Это можно записать цепочкой `if … else if … else if`, но в Go для этого есть отдельная команда **выбора**:
по-английски **switch**. Каждый путь называется **case** («случай»).

Это `tanlov/main.go` («выбор»). Функция `kun` («день») получает номер дня недели и возвращает его название:

```go filename="tanlov/main.go" showLineNumbers
package main

import "fmt"

func kun(d int) string {
	s := ""
	switch d {
	case 6, 7: // bir nechta qiymat
		s = "dam olish"
	case 1:
		s = "hafta boshi, "
		fallthrough // keyingi case ham bajariladi
	case 2, 3, 4, 5:
		s += "ish kuni"
	default:
		s = "bunday kun yoʻq"
	}
	return s
}

func main() {
	for _, d := range []int{1, 3, 7, 9} {
		fmt.Println(d, kun(d))
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `func kun(d int) string {` | наша функция: получает `d` типа `int`, возвращает `string` (функции: [GO-1.06](/lab/youtube/go#go-1-06)) |
| 6 | `s := ""` | новый ярлык `s` с пустой строкой |
| 7 | `switch d {` | по значению `d` выбирается один `case` |
| 8–9 | `case 6, 7:` | несколько значений в одном `case`: если 6 **или** 7, `s` = «dam olish» («выходной») |
| 10–11 | `case 1:` | если 1, `s` = «hafta boshi, » («начало недели, ») |
| 12 | `fallthrough` | «провалиться вниз»: выполнить и тело следующего `case` |
| 13–14 | `case 2, 3, 4, 5:` | рабочие дни; `s += "ish kuni"` — в конец `s` добавляется «ish kuni» («рабочий день») |
| 15–16 | `default:` | срабатывает, если не подошёл ни один `case` («bunday kun yoʻq» — «такого дня нет») |
| 18 | `return s` | возвращает `s` туда, откуда вызвали функцию |
| 22 | `for _, d := range []int{1, 3, 7, 9} {` | проходит по четырём числам |
| 23 | `fmt.Println(d, kun(d))` | выводит число и слово, которое вернула `kun` |

Важное отличие: в C и в классическом `switch` Java после каждого `case` нужно писать `break`, иначе программа
проваливается в следующий `case`. В Go **каждый `case` заканчивается сам**, писать `break` не нужно. Если хотите
провалиться вниз, пишете это явно: `fallthrough`.

Угадайте: что выведется для `1`? **A)** `1 hafta boshi, ` · **B)** `1 hafta boshi, ish kuni` · **C)** `1 ish kuni`

<details>
<summary>Ответ</summary>

**B: `1 hafta boshi, ish kuni`.** `case 1` записал «hafta boshi, », потом `fallthrough` провалился в тело
следующего `case` и добавил «ish kuni». Внимание: числа 1 нет в списке `2, 3, 4, 5`, но `fallthrough` **не
проверяет** условие следующего `case`, а просто переходит внутрь. Если вы выбрали «A», вы забыли про
`fallthrough`; если «C» — забыли, что сработал и `case 1`.

</details>

```console
$ go run ./tanlov
1 hafta boshi, ish kuni
3 ish kuni
7 dam olish
9 bunday kun yoʻq
```

| `d` | Какой `case` | `s` |
|---|---|---|
| 1 | `case 1` → `fallthrough` → `case 2, 3, 4, 5` | «hafta boshi, » + «ish kuni» |
| 3 | `case 2, 3, 4, 5` | «ish kuni» |
| 7 | `case 6, 7` | «dam olish» |
| 9 | ни один → `default` | «bunday kun yoʻq» |

На практике `fallthrough` используют редко.

## break внутри switch не выходит из цикла

Теперь положим `switch` внутрь `for`. Мы хотим найти среди чисел первое отрицательное и остановиться. Это
`break/main.go`:

```go filename="break/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sonlar := []int{4, 7, -1, 8, -5}
	for _, s := range sonlar {
		switch {
		case s < 0:
			fmt.Println("manfiy:", s, "→ toʻxtaymiz")
			break // faqat switch'dan chiqadi
		case s%2 == 0:
			fmt.Println("juft:", s)
		}
	}
	fmt.Println("tugadi")
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `sonlar := []int{4, 7, -1, 8, -5}` | слайс `sonlar` («числа») из пяти чисел |
| 7 | `for _, s := range sonlar {` | на каждом шаге очередное число записывается в `s` |
| 8 | `switch {` | **`switch` без выражения**: после `switch` ничего нет. Тогда срабатывает **первый `case`, который `true`** |
| 9–11 | `case s < 0:` | если `s` отрицательное, выводит сообщение («manfiy» — «отрицательное», «toʻxtaymiz» — «останавливаемся»), и здесь написан `break` |
| 12–13 | `case s%2 == 0:` | `%` — остаток от деления: если `s % 2` равно 0, число чётное («juft») |
| 16 | `fmt.Println("tugadi")` | после цикла («tugadi» — «закончилось») |

Число 7 не отрицательное и не чётное: ни один `case` не подходит, `default` тоже нет, поэтому для 7 ничего не
выводится.

Когда нашлось отрицательное число, мы написали `break`. Остановится ли цикл? **A)** да: `juft: 4`,
`manfiy: -1 → toʻxtaymiz`, `tugadi` · **B)** нет: после −1 выведутся ещё 8 и −5 · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: цикл не останавливается.** Официальное правило Go: *"A "break" statement terminates execution of the
innermost "for", "switch", or "select" statement within the same function"* — «`break` завершает самый внутренний
`for`, `switch` или `select`». Здесь ближайшая к `break`, самая внутренняя коробка — `switch`. `break` вышел только
из `switch`, а `for` перешёл к следующему числу. Если вы выбрали «A», вы думали, что `break` всегда относится к
циклу.

</details>

```console
$ go run ./break
juft: 4
manfiy: -1 → toʻxtaymiz
juft: 8
manfiy: -5 → toʻxtaymiz
tugadi
```

Картинка с коробками: `break` выходит только из самой внутренней коробки, в которой стоит.

```text
┌ for ─────────────────────────────┐
│  ┌ switch ───────────────────┐   │
│  │  case s < 0:              │   │
│  │      break ──► выходит    │   │
│  │               из switch   │   │
│  └───────────────────────────┘   │
│  for продолжается: следующее s   │
└──────────────────────────────────┘
```

Что скажут анализаторы?

```console
$ go vet ./break
```

```console
$ $(go env GOPATH)/bin/staticcheck ./break
break/main.go:11:4: ineffective break statement. Did you mean to break out of the outer loop? (SA4011)
break/main.go:11:4: redundant break statement (S1023)
```

`go vet` опять молчит. А `staticcheck` находит именно эту ошибку, строка 11: *ineffective break statement. Did you
mean to break out of the outer loop?* — «бесполезный `break`. Вы хотели выйти из внешнего цикла?» Вторая строка,
*redundant break statement* — «лишний `break`»: в Go `case` заканчивается сам, этот `break` ничего не делает.

Та же ловушка есть и с `select` внутри `for`; к `select` и этой ловушке вернёмся в уроках про goroutine
([GO-1.21](/lab/youtube/go#go-1-21)).

Ловушка не новая. 15 января 1990 года телефонная сеть AT&T почти девять часов работала со сбоями. Согласно письму,
разошедшемуся в RISKS Digest (это не официальное заявление AT&T), причиной был `break` в коде на C: его написали для
`if`, а он вышел из `switch`. И там, и у нас урок один: `break` не относится ни к `if`, ни к `case`.

## Решение: метка

Чтобы выйти из цикла, дадим `for` имя. Если в доме несколько дверей, мы говорим не «выйди», а «выйди **через
входную дверь**». Имя, данное циклу, называется **меткой** (по-английски **label**). Это `label/main.go`, от
`break/main.go` он отличается только двумя строками:

```go filename="label/main.go" showLineNumbers
package main

import "fmt"

func main() {
	sonlar := []int{4, 7, -1, 8, -5}
qidiruv:
	for _, s := range sonlar {
		switch {
		case s < 0:
			fmt.Println("manfiy:", s, "→ toʻxtaymiz")
			break qidiruv // for'dan chiqadi
		case s%2 == 0:
			fmt.Println("juft:", s)
		}
	}
	fmt.Println("tugadi")
}
```

- **Строка 7:** `qidiruv:` («поиск») — имя и двоеточие перед `for`. Теперь этот цикл называется `qidiruv`.
- **Строка 12:** `break qidiruv` — «выйди из цикла с именем `qidiruv`». Теперь `break` завершает именно этот `for`.

Угадайте: **A)** `juft: 4`, `manfiy: -1 → toʻxtaymiz`, `tugadi` · **B)** то же, что в прошлый раз ·
**C)** `juft: 4`, `tugadi`

<details>
<summary>Ответ</summary>

**A.** Сначала выводится 4 (оно чётное), для 7 ничего не выводится. Потом находится −1, выводится сообщение, и
`break qidiruv` выходит из всего цикла: до 8 и −5 очередь не доходит. Если вы выбрали «C»: сообщение выводится
**до** `break`.

</details>

```console
$ go run ./label
juft: 4
manfiy: -1 → toʻxtaymiz
tugadi
```

Ещё три вещи о метках:

- `continue` тоже работает с меткой. Во вложенных циклах `continue qidiruv` бросает внутренний цикл и переходит к
  следующему шагу внешнего.
- Неиспользованная метка — ошибка компиляции (увидим ниже, в «Частых ошибках»).
- Ещё один путь: вынести цикл в отдельную функцию и сделать `return`. `return` сразу завершает функцию.

Правило: если изнутри `switch` нужно выйти из цикла, используйте **метку**.

## Один код, два результата: Go 1.22 и переменная цикла

Теперь вернёмся к ошибке из начала урока. Домен — это имя сайта, например `a.uz`. Поставим список доменов в очередь,
чтобы проверить их позже. В очередь запишем не сам домен, а **адрес** переменной цикла `d`.

Что такое адрес? Каждая переменная лежит где-то в памяти, как дом стоит на какой-то улице. Можно записать на
бумажку не сам дом, а его адрес. Потом прийти по адресу и посмотреть, кто там живёт сейчас. В Go `&d` — «адрес
`d`», а `*p` — «значение по адресу `p`». Значение, которое хранит адрес, называется **указателем** (pointer);
подробно разберём их в [GO-1.11](/lab/youtube/go#go-1-11).

Это `manzil/main.go` («адрес»):

```go filename="manzil/main.go" showLineNumbers
package main

import "fmt"

func main() {
	domenlar := []string{"a.uz", "b.uz", "c.uz"}
	var navbat []*string
	for _, d := range domenlar {
		navbat = append(navbat, &d) // d'ning manzili
	}
	for _, p := range navbat {
		fmt.Print(*p, " ")
	}
	fmt.Println()
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `domenlar := []string{…}` | слайс `domenlar` («домены») из трёх имён доменов |
| 7 | `var navbat []*string` | `var` объявляет переменную, не присваивая значения; `navbat` («очередь») — «список адресов строк» (`*string` = адрес строки), пока пустой |
| 8 | `for _, d := range domenlar {` | `d` — переменная цикла: на каждом шаге в неё записывается очередной домен |
| 9 | `navbat = append(navbat, &d)` | `append` добавляет адрес `d` в конец списка; результат снова записывается в `navbat` |
| 11 | `for _, p := range navbat {` | проходит по сохранённым адресам |
| 12 | `fmt.Print(*p, " ")` | выводит значение, которое **сейчас** лежит по адресу `p` |

Что выведет эта программа? **A)** `a.uz b.uz c.uz` · **B)** номера адресов, начинающиеся с `0x…` · **C)** ошибку

<details>
<summary>Ответ</summary>

**A: `a.uz b.uz c.uz`** (в нашем модуле). `*p` даёт не сам адрес, а **значение** по этому адресу, поэтому
выводятся домены, а не числа. Номера адресов вывел бы `fmt.Print(p)`.

</details>

```console
$ go run ./manzil
a.uz b.uz c.uz 
```

Теперь папка `eski/` («старый»). В ней `main.go` — буква в букву тот же код, но у папки есть свой файл `go.mod`.
`go.mod` — файл настроек папки. Папка с таким файлом называется **модулем**. Строка `go` в нём говорит, по правилам
какой версии языка Go написан модуль. Команда `grep '^go ' файл` находит в файле строку, которая начинается с
`go `, и выводит её:

```console
$ grep '^go ' ../../go.mod
go 1.26
```

```console
$ grep '^go ' eski/go.mod
go 1.21
```

В модуле курса `go 1.26`, в `eski/` — `go 1.21`. Теперь зайдём в `eski/` (`cd eski`) и запустим программу:

```console
$ cd eski && go run .
c.uz c.uz c.uz 
```

Почему по всем трём адресам `c.uz`? **A)** старый Go проходит `range` задом наперёд · **B)** все три адреса
указывают на одну переменную · **C)** `append` трижды добавил последний элемент

<details>
<summary>Ответ</summary>

**B.** Если строка `go` ниже 1.22, на весь цикл есть **одна** `d`. Каждый шаг перезаписывает эту одну `d`: сначала
`a.uz`, потом `b.uz`, потом `c.uz`. А `&d` каждый раз один и тот же адрес. Все три адреса указывают на одну
переменную, а в ней осталось последнее значение. Не «A»: `range` всегда начинает с элемента 0. Не «C»: `append`
каждый раз добавлял `&d`, просто `&d` каждый раз был одинаковым.

</details>

Картинка памяти (`go 1.21`, одна `d`):

| Шаг | `d` (одна ячейка) | `navbat` |
|---|---|---|
| 1 | `a.uz` | `[&d]` |
| 2 | `b.uz` (a.uz пропал) | `[&d &d]` |
| 3 | `c.uz` (b.uz пропал) | `[&d &d &d]` |
| вывод | `c.uz` | на экране: `c.uz c.uz c.uz` |

Начиная с Go 1.22 (`go 1.22` и выше) у каждого шага своя `d`:

| Шаг | Новая `d` | `navbat` |
|---|---|---|
| 1 | `d₁ = a.uz` | `[&d₁]` |
| 2 | `d₂ = b.uz` | `[&d₁ &d₂]` |
| 3 | `d₃ = c.uz` | `[&d₁ &d₂ &d₃]` |
| вывод | | на экране: `a.uz b.uz c.uz` |

```text
go 1.21:   navbat[0] ─┐
           navbat[1] ─┼──►  d [ c.uz ]        одна ячейка, каждый шаг её перезаписывал
           navbat[2] ─┘

go 1.22+:  navbat[0] ──►  d₁ [ a.uz ]
           navbat[1] ──►  d₂ [ b.uz ]         на каждом шаге новая ячейка
           navbat[2] ──►  d₃ [ c.uz ]
```

Находят ли эту ошибку анализаторы?

```console
$ cd eski && go vet . && $(go env GOPATH)/bin/staticcheck .
```

Нет: и `go vet`, и `staticcheck` молчат. (`&&` — «если предыдущая команда прошла успешно, выполни следующую».)

## Let's Encrypt, 2020, и решение команды Go

Let's Encrypt бесплатно выдаёт сайтам сертификаты для HTTPS (безопасного, зашифрованного соединения с сайтом).
Сертификат — это электронный документ за значком замка в браузере: он подтверждает «это действительно тот самый
сайт». DNS — «телефонная книга» интернета, в ней лежат записи о каждом домене. CAA — одна из таких записей: в ней
владелец домена пишет, какие организации могут выдавать ему сертификаты.

Перед выдачей сертификата сервер Let's Encrypt (он называется Boulder) должен был заново проверить CAA-запись
каждого домена. Код сохранял адрес переменной цикла, совсем как наша программа `manzil`. В итоге в запросе с
несколькими доменами один домен проверялся несколько раз, а остальные заново не проверялись. Самое интересное:
для `k` в коде сделана копия с комментарием, а про `v` забыли. Упрощённая картинка:

```text
for k, v := range m {
    // Make a copy of k because it will be reassigned with each loop.
    kCopy := k          ← для k копия есть ✓
    ... &v ...          ← для v копии нет ✗
}
```

| Дата (UTC) | Что произошло |
|---|---|
| 24 апреля 2019 | добавлен код с ошибкой (пока за выключенной настройкой) |
| 23 августа 2019 | настройку включили на рабочих серверах (production) |
| 29 февраля 2020, 03:08 | ошибка подтверждена |
| 29 февраля 2020, 05:22 | исправление запущено: чуть больше чем за два часа |

Ошибка работала в production больше полугода. Она затронула 3 048 289 сертификатов, и Let's Encrypt отозвал из них
1 711 396. Первая фраза отчёта об инциденте: *"The proximate cause of the bug was a common mistake in Go: taking a
reference to a loop iterator variable"* — «непосредственная причина ошибки — частая ошибка в Go: взять ссылку
(адрес) на переменную цикла».

Прежде чем менять правило, команда Go проверила его внутри Google. Примерно из 100 000 тестов не прошли 58. Только в
2 из них код действительно полагался на старое поведение, почти все остальные оказались скрытыми ошибками. А вторая
по частоте причина — ровно то, что мы видели: добавление адреса переменной цикла в слайс.

После этого, **начиная с Go 1.22**:

- переменная, которую объявил сам цикл, на каждой итерации новая;
- ручная копия вроде `d := d` больше не нужна;
- но только в модулях, где строка `go` в `go.mod` — **1.22 или выше**. Код, перенесённый в модуль со старой
  строкой, возвращает ошибку (как в `eski/`).

Как эта строка управляет поведением программы, увидим в [GO-1.16](/lab/youtube/go#go-1-16).

## Частые ошибки

**1. Думать, что `break` внутри `switch` останавливает цикл.** Это главная ловушка урока, мы видели её выше в
`break/main.go`: программа не выдаёт ошибку, но продолжает работать и после −1. `break` выходит из самого
внутреннего `for`, `switch` или `select`. **Исправление:** дайте циклу метку и напишите `break qidiruv`, или вынесите
цикл в функцию и сделайте `return`.

**2. Менять значение из `range` и думать, что изменился слайс.** `for _, n := range narxlar { n *= 2 }` не трогает
слайс: `n` — копия. `staticcheck` показывает это как `SA4006`. **Исправление:** `narxlar[i] *= 2`.

**3. Писать `while`.** Так часто пишут те, кто пришёл из другого языка (этого примера нет в папке курса, он запущен
отдельно):

```go
package main

import "fmt"

func main() {
	n := 1
	while n < 100 {
		n *= 2
	}
	fmt.Println(n)
}
```

```console
$ go run while/main.go
# command-line-arguments
while/main.go:7:8: syntax error: unexpected name n at end of statement
while/main.go:10:2: syntax error: non-declaration statement outside function body
```

`while/main.go`, строка 7, символ 8: *syntax error: unexpected name n at end of statement* — «синтаксическая ошибка:
неожиданное имя `n` в конце инструкции». Go не знает `while` как ключевое слово, читает его как обычное имя и не
понимает, что после него делает `n`. Вторая строка — следствие первой ошибки: Go сбился и решил, что остальной код
находится вне функции. Исправите первую ошибку — исчезнет и вторая. **Исправление:** вместо `while` пишите `for`:
`for n < 100 {`.

**4. Брать цикл из трёх частей в скобки.** (Этого примера тоже нет в папке курса.)

```go
package main

import "fmt"

func main() {
	for (i := 0; i < 3; i++) {
		fmt.Println(i)
	}
}
```

```console
$ go run qavs/main.go
# command-line-arguments
qavs/main.go:6:9: syntax error: unexpected :=, expected )
```

Строка 6, символ 9: *unexpected :=, expected )* — «неожиданное `:=`, ожидалась `)`». Внутри скобок Go ждал простое
условие, а не `:=`. **Исправление:** уберите скобки: `for i := 0; i < 3; i++ {`. Только в цикле с одним условием
скобки не ошибка: `for (n < 100) {` работает, но `gofmt` всё равно превратит его в `for n < 100 {`.

**5. Неиспользованная метка.** (Нет в папке курса.) Здесь `break` написан без метки, а `qidiruv` нигде не
используется:

```go
package main

import "fmt"

func main() {
	sonlar := []int{4, 7, -1}
qidiruv:
	for _, s := range sonlar {
		if s < 0 {
			break
		}
		fmt.Println(s)
	}
}
```

```console
$ go run ortiqcha/main.go
# command-line-arguments
ortiqcha/main.go:7:1: label qidiruv defined and not used
```

*label qidiruv defined and not used* — «метка `qidiruv` объявлена, но не используется». Как и неиспользованную
переменную, Go считает это ошибкой. **Исправление:** удалите метку (здесь `break` не внутри `switch`, поэтому метка
не нужна) или используйте её: `break qidiruv`.

**6. Писать `range 3` в старом модуле.** (Нет в папке курса; отдельный модуль с `go 1.21` в `go.mod`.)

```go
package main

import "fmt"

func main() {
	for i := range 3 {
		fmt.Print(i, " ")
	}
	fmt.Println()
}
```

```console
$ cd eskirange && go run .
# eskirange
./main.go:6:17: cannot range over 3 (untyped int constant): requires go1.22 or later (-lang was set to go1.21; check go.mod)
```

*cannot range over 3 … requires go1.22 or later (-lang was set to go1.21; check go.mod)* — «по 3 нельзя пройти
`range` … нужен Go 1.22 или выше (версия языка установлена в go1.21; проверьте `go.mod`)». Сообщение даже говорит,
куда смотреть. **Исправление:** поднимите строку `go` в `go.mod` до 1.22 или выше либо напишите цикл из трёх частей.

**7. Думать, что переменная, созданная до цикла, на каждом шаге новая.** Правило Go 1.22 касается только
переменной, **которую объявил сам цикл**. Здесь `j` создана до цикла через `var j int`, а `for` только присваивает
ей значение через `=` (этого примера нет в папке курса, он запущен в модуле с `go 1.26`):

```go
package main

import "fmt"

func main() {
	var navbat []*int
	var j int
	for j = 0; j < 3; j++ {
		navbat = append(navbat, &j)
	}
	for _, p := range navbat {
		fmt.Print(*p, " ")
	}
	fmt.Println()
}
```

```console
$ go run tashqi/main.go
3 3 3 
```

Одна `j`, все три адреса указывают на неё. Цикл остановился, когда `j` стала 3, поэтому `3 3 3`. **Исправление:**
создайте `j` прямо в `for`: `for j := 0; j < 3; j++`. Тогда она станет переменной цикла, и результат будет `0 1 2`.

fmt.Println()

<details>
<summary>Ответ</summary>

`0 1 2 3`. `range 4` начинает с 0 и не включает само 4.

```console
$ go run savol1/main.go
0 1 2 3 
```

</details>

**3.** Что выведет этот код? **A)** `0` · **B)** `0 1 2` · **C)** `0 2`

```go
for i := 0; i < 3; i++ {
	switch i {
	case 1:
		break
	}
	fmt.Print(i, " ")
}
fmt.Println()
```

<details>
<summary>Ответ</summary>

**B: `0 1 2`.** `break` выходит только из `switch`, а `fmt.Print` стоит после `switch` и выполняется на каждом шаге.
Цикл тоже не останавливается.

```console
$ go run savol2/main.go
0 1 2 
```

</details>

**4.** Проверяет ли `fallthrough` условие следующего `case`?

<details>
<summary>Ответ</summary>

Нет. Он переходит в тело следующего `case`, не проверяя условие. Поэтому в `tanlov` к 1 добавилось «ish kuni»,
хотя 1 нет в списке `2, 3, 4, 5`.

</details>

**5.** Один и тот же код в одном модуле вывел `a.uz b.uz c.uz`, а в другом `c.uz c.uz c.uz`. Куда смотреть?

<details>
<summary>Ответ</summary>

На строку `go` в `go.mod`. Если она ниже 1.22, на цикл есть одна переменная, и все сохранённые адреса указывают на
неё. Если 1.22 или выше, переменная, которую объявил сам цикл, на каждом шаге новая.

</details>

**6.** Из [GO-1.02](/lab/youtube/go#go-1-02): `var x int8 = 127`, потом `x++`. Что выведет `fmt.Println(x)`?

<details>
<summary>Ответ</summary>

`-128`. `int8` не вмещает число больше 127, и переменная без всякой ошибки «перекатывается» к самому маленькому
значению (переполнение, overflow).

```console
$ go run overflow/main.go
-128
```

</details>

<details>
<summary>Ответ</summary>

`homework/orta/main.go`. `strconv.Itoa` превращает число в строку, `range` проходит по её рунам, а `switch`

<details>
<summary>Ответ</summary>

`homework/qiyin/main.go`. Внешний цикл идёт по строкам таблицы, внутренний — по числам в строке. Обычный `break`

🔴 **Гуру:** исправьте ошибку в `eski/`, не трогая `go.mod`. Есть три способа.

<details>
<summary>Ответ</summary>

`homework/guru/` — отдельный модуль, в `go.mod` стоит `go 1.21` (старое правило).

1. `d := d`: внутри цикла создаётся новая переменная, каждый адрес указывает на свою копию. Так писали до Go 1.22;
   в модуле `go 1.22+` эта строка лишняя, и `go fix` (команда Go, которая обновляет старый код) её удаляет.
2. `&domenlar[i]`: адрес не переменной цикла, а самого элемента слайса. Копии здесь нет вообще.
3. Строка `//go:build go1.22` в начале файла поднимает версию языка **для этого файла**: даже если модуль остаётся
   на `go 1.21`, в этом файле на каждом шаге будет новая `d`. Подробно: [GO-1.16](/lab/youtube/go#go-1-16).

```console
$ cd homework/guru && go run .
a.uz b.uz c.uz ← d := d
a.uz b.uz c.uz ← &domenlar[i]
```

```console
$ cd homework/guru && go run ./buildtag
a.uz b.uz c.uz ← //go:build go1.22
```

</details>
