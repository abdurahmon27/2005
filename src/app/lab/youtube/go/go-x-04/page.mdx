## Nimani oʻrganasiz

Balansni 50 ga oshiradigan endpoint yozdingiz. `POST` javobida balans 150, hammasi joyida. Lekin keyingi `GET` yana
100 deydi: xato ham, log ham yoʻq. Node'dagi xuddi shu `for…of` sikli esa 150 ni saqlaydi. Qisqa javob: Go'dagi
`range` elementning nusxasini beradi. Nega shunday, va qanday tuzatiladi?

**Bitta gʻoya:** Go'da `=` va funksiyaga uzatish qiymatni nusxalaydi (struct'ni ham, massivni ham), JS/Python'dagidek
oʻsha obyektga havola bermaydi. Asl qiymatni oʻzgartirish uchun uni pointer (`&user`, `*User`) yoki indeks orqali
yozasiz.

Dars oxirida siz:

- `for _, user := range users` ichidagi oʻzgarish nega yoʻqolishini tushuntirib, uni `users[i]` yoki `&users[i]`
  bilan tuzata olasiz;
- funksiya chaqiruvchining struct'ini oʻzgartirishi kerak boʻlsa, `*User` parametri va `&user` yozasiz, kerak
  boʻlmasa qiymat bilan uzatasiz;
- `cannot assign to struct field … in map` xatosini oʻqib, uni ikki usulda tuzata olasiz;
- massiv (`[3]int`) va slice (`[]int`) nusxasi qanday farq qilishini bilasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| qiymat nusxasi | `=` va funksiyaga uzatish butun qiymatni (struct'ning hamma maydonlarini) yangi joyga koʻchiradi | value semantics |
| pointer | qiymatning xotiradagi manzili: `&user` manzilni oladi, `*User` — «User'ga pointer» turi | pointer |
| massiv va slice | `[3]int` — massiv, butunlay nusxalanadi; `[]int` — slice, uning nusxasi oʻsha elementlarni koʻradi | array, slice |

Ikkita yordamchi soʻz ham bor: **addressable** (Go faqat manzili bor narsaning maydoniga yozadi; map elementi
bunday emas) va **slice sarlavhasi** (slice header: elementlarga pointer, uzunlik va sigʻim).

## Balans qayerga ketdi: handler Go'da va Node'da

Mana hook'dagi xizmat. Bu GO-X.01 dagi xizmat, faqat foydalanuvchilar maʼlumotlar bazasi oʻrniga xotiradagi
`users` slice'ida turadi. `hook/main.go`:

```go filename="hook/main.go" showLineNumbers
// Hook (GO-X.04): GO-X.01 xizmati + xotiradagi users ro'yxati. POST /users/{id}/topup balansni 50 ga oshirishi
// kerak. Javob 150 deydi, keyingi GET esa 100: range bergan user — elementning NUSXASI.
// Ishga tushirish: go run ./hook   (boshqa terminalda: curl -X POST localhost:3000/users/42/topup; curl localhost:3000/users/42)
package main

import (
	"encoding/json"
	"log"
	"net/http"
)

type User struct {
	ID      string `json:"id"`
	Balance int    `json:"balance"`
}

var users = []User{{ID: "42", Balance: 100}}

func main() {
	http.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
		for _, user := range users {
			if user.ID == r.PathValue("id") {
				json.NewEncoder(w).Encode(user)
				return
			}
		}
		http.NotFound(w, r)
	})
	http.HandleFunc("POST /users/{id}/topup", func(w http.ResponseWriter, r *http.Request) {
		for _, user := range users {
			if user.ID == r.PathValue("id") {
				user.Balance += 50
				json.NewEncoder(w).Encode(user)
				return
			}
		}
		http.NotFound(w, r)
	})
	log.Println("listening on :3000")
	log.Fatal(http.ListenAndServe(":3000", nil))
}
```

|---|---|---|
| 1–3 | `// …` | izohlar: vazifa va ishga tushirish buyruqlari |
| 4–10 | `package main`, `import ( … )` | bajariladigan dastur; paketlar: `encoding/json` (JSON), `log` (log yozish), `net/http` (HTTP server) |
| 12–15 | `type User struct { … }` | `User` turi: `ID` va `Balance` («balans») maydonlari, JSON teglari bilan (GO-X.02) |
| 17 | `var users = []User{{ID: "42", Balance: 100}}` | `users` — `User`'lar slice'i, maʼlumotlar bazasi oʻrnida. Jingalak qavsdagi `{ID: "42", Balance: 100}` — **struct literal**, JavaScript'dagi obyekt literali kabi |
| 20–28 | `GET /users/{id}` | handler `w` (javob) va `r` (soʻrov) oladi (GO-X.01; `*http.Request` dagi `*` — pastda «Pointer» boʻlimida). id mos `user` ni JSON qilib qaytaradi, topilmasa `http.NotFound` — `404` |
| 29 | `POST /users/{id}/topup` | balansni oshiradigan endpoint |
| 30 | `for _, user := range users {` | JavaScript'dagi `for (const user of users)` kabi koʻrinadi |
| 31 | `if user.ID == r.PathValue("id") {` | URL'dagi id bilan solishtiradi |
| 32 | `user.Balance += 50` | topilgan `user` ga 50 qoʻshadi |

| 39–40 | `log.Println(…)`, `http.ListenAndServe(":3000", nil)` | xizmatni `:3000` da ishga tushiradi (GO-X.01) |

Endi Node'dagi xuddi shu xizmat. `js/server.js` kutubxonasiz yozilgan:

```js filename="js/server.js"
// Hook'ning Node tomoni (GO-X.04): xuddi shu xizmat, kutubxonasiz. for…of bergan user — massivdagi O'SHA obyekt.
// Ishga tushirish: node js/server.js
const http = require("node:http");

const users = [{ id: "42", balance: 100 }];

http
  .createServer((req, res) => {
    const m = req.url.match(/^\/users\/(\w+)(\/topup)?$/);
    if (!m) return res.writeHead(404).end();
    for (const user of users) {
      if (user.id === m[1]) {
        if (req.method === "POST" && m[2]) user.balance += 50;
        return res.end(JSON.stringify(user) + "\n");
      }
    }
    res.writeHead(404).end();
  })
  .listen(3000, () => console.log("listening on :3000"));
```

Go serverini <kbd>Ctrl</kbd>+<kbd>C</kbd> bilan toʻxtating (port bitta), keyin:

```console

```

```console
$ curl -X POST localhost:3000/users/42/topup

$ curl localhost:3000/users/42
{"id":"42","balance":150}
```

Node'da ikkalasi ham 150. Sikllar bir xil koʻrinadi, natija har xil. Sababi keyingi boʻlimlarda.

## Python va PHP'da xuddi shu sikl

Python ham JavaScript kabi ishlaydi. `anchor/topup.py`:

```python filename="anchor/topup.py"
# Python tomoni (GO-X.04): for bergan user — ro'yxatdagi O'SHA dict (nom obyektga bog'lanadi).
users = [{"id": "42", "name": "Dilnoza", "balance": 100}]
for user in users:
    if user["id"] == "42":
        user["balance"] += 50
print(users[0]["balance"])  # 150
```

```console
$ python3 anchor/topup.py
150
```

`for` bergan `user` — roʻyxatdagi oʻsha dict. Python'da nom obyektga bogʻlanadi, nusxa yaratilmaydi.

PHP'da esa farq bor. `anchor/topup.php` avval massivlar ustidan, keyin obyektlar ustidan yuradi:

```php filename="anchor/topup.php"
<?php
// PHP tomoni (GO-X.04): massiv qiymat bilan nusxalanadi (Go struct kabi), obyekt esa handle bilan (Go pointer kabi).
$users = [["id" => "42", "name" => "Dilnoza", "balance" => 100]];
foreach ($users as $u) {
    if ($u["id"] === "42") {
        $u["balance"] += 50; // $u — nusxa
    }
}
echo $users[0]["balance"], "\n"; // 100

$objs = [(object) ["id" => "42", "name" => "Dilnoza", "balance" => 100]];
foreach ($objs as $o) {
    if ($o->id === "42") {
        $o->balance += 50; // $o — o'sha obyektning handle'i
    }
}
echo $objs[0]->balance, "\n"; // 150
```

```console
$ php anchor/topup.php
100
150
```

PHP qoʻllanmasida yozilgan: massivni qiymat sifatida berish doim nusxalashni anglatadi. Shuning uchun `foreach` dagi
oʻzgarish yoʻqoladi va 100 qoladi. Obyektni esa PHP **handle**, yaʼni obyektga ishora orqali oʻzgartiradi: 150.
PHP'da havolani ochiq yozish mumkin: `foreach ($users as &$u)` (`anchor/topup-ref.php`):

```console
$ php anchor/topup-ref.php
150
```

| Til | Sikl | Element | Natija |
|---|---|---|---|
| JavaScript | `for (const user of users)` | oʻsha obyekt | 150 |
| Python | `for user in users` | oʻsha dict | 150 |
| PHP, massiv | `foreach ($users as $u)` | nusxa | 100 |
| PHP, obyekt | `foreach ($objs as $o)` | oʻsha obyektning handle'i | 150 |
| Go | `for _, user := range users` | ? | `POST` 150, `GET` 100 |

PHP'dagi massiv Go'dagi struct'ga eng yaqin. Buni keyingi boʻlimda koʻramiz.

## Qiymat nusxasi: `c := user`

Go'da struct — qiymat, JavaScript'dagi obyekt kabi havola emas. `nusxa/main.go`:

```go filename="nusxa/main.go" showLineNumbers
// Qiymat nusxasi (GO-X.04): c := user butun struct'ni (hamma maydonlarini) yangi joyga nusxalaydi.
// JS'da const c = user — o'sha obyektga ikkinchi havola bo'lardi.
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func main() {
	user := User{ID: "42", Balance: 100}
	c := user
	c.Balance += 50
	fmt.Println(user.Balance, c.Balance) // 100 150
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7–10 | `type User struct { … }` | hook'dagi `User`, teglarsiz |
| 13 | `user := User{ID: "42", Balance: 100}` | struct literal'dan yangi `user` |
| 14 | `c := user` | havola emas: `user` ning hamma maydonlari yangi joyga nusxalanadi |
| 15 | `c.Balance += 50` | faqat `c` ning maydoni oʻzgaradi |
| 16 | `fmt.Println(user.Balance, c.Balance)` | ikkala balansni chiqaradi |

Xotirada qator-baqator:

| Qatordan keyin | `user.ID` | `user.Balance` | `c.ID` | `c.Balance` | Ekranda |
|---|---|---|---|---|---|
| 13 | `"42"` | 100 | | | |
| 14 | `"42"` | 100 | `"42"` (nusxa) | 100 (nusxa) | |
| 15 | `"42"` | 100 | `"42"` | **150** | |
| 16 | `"42"` | 100 | `"42"` | 150 | `100 150` |

```console
$ go run ./nusxa
100 150
```

Bu **qiymat semantikasi** (value semantics): `=` qiymatning oʻzini nusxalaydi. JavaScript'da `const c = user`
oʻsha obyektga ikkinchi havola boʻlardi va `user.balance` ham 150 boʻlardi. Go spec'dagi qiymat berish
(assignment) qoidasi ham shu: qiymat oʻzgaruvchiga yoziladi.

## Funksiya parametri ham nusxa

Ishda balansni odatda alohida funksiya oshiradi. JavaScript'da obyektni funksiyaga bersangiz, funksiya aynan oʻsha
obyektni oʻzgartiradi. Go'da ham `User` ni `topUp` («toʻldirish») ga beramiz. `param/main.go`:

```go filename="param/main.go" showLineNumbers
// Bashorat 1 (GO-X.04): funksiya parametri ham qiymat berish — topUp user'ning nusxasini oladi.
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func topUp(user User, amount int) {
	user.Balance += amount
}

func main() {
	user := User{ID: "42", Balance: 100}
	topUp(user, 50)           // JS: topUp(user) → 150
	fmt.Println(user.Balance) // 100
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 11 | `func topUp(user User, amount int) {` | `user` parametri `User` turida, `amount` («miqdor») — `int` |
| 12 | `user.Balance += amount` | parametrning balansini oshiradi |
| 17 | `topUp(user, 50)` | `main` dagi `user` ni beradi |

`topUp` dan keyin `Println` nima chiqaradi? (Fayldagi `// 100` izohini koʻrmaslikka harakat qiling.)

**A)** `150` · **B)** `100` · **C)** build xatosi

<summary>Javob</summary>

nusxa yoʻqoladi. Go FAQ'da qoida shunday yozilgan: C oilasidagi hamma tillardagi kabi, Go'da hamma narsa qiymat
bilan uzatiladi. Funksiya doim uzatilgan narsaning nusxasini oladi, xuddi parametrga qiymat berilgandek. «`150`»
ni tanlagan boʻlsangiz, JavaScript odatini koʻchirgansiz: u yerda obyekt havola boʻlib uzatiladi. «Build xatosi» ni
tanlagan boʻlsangiz, Go buni xato deb biladi deb oʻylagansiz: bu xato emas, qoida.

</details>

**Nega Go shunday tanlagan?** JavaScript'da istalgan funksiya obyektingizni jim oʻzgartira oladi, va buni imzodan
bilib boʻlmaydi. Go'da struct'ingizni oʻzgartirmoqchi boʻlgan funksiya buni imzosida yozadi: pointer bilan, uni

| | Kim oʻzgartira oladi? |
|---|---|
| JavaScript: `f(user)` | istalgan funksiya; imzoda koʻrinmaydi |
| Go: `topUp(user User, …)` | hech kim: funksiya nusxa oladi, sizning `user` ga tegmaydi |
| Go: oʻzgartiradigan funksiya | imzosida pointer bor (keyingi boʻlim) |

## Pointer: `&user` va `*User`

Endi `topUp` asl `user` ni oʻzgartirsin. `pointer/main.go` `param/main.go` dan ikki qator bilan farq qiladi:

```go filename="pointer/main.go" showLineNumbers
// Pointer (GO-X.04): &user — user'ning manzili, *User — "User'ga pointer". topUp nusxa emas, manzil oladi.
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func topUp(user *User, amount int) {
	user.Balance += amount // Go o'zi (*user).Balance deb o'qiydi
}

func main() {
	user := User{ID: "42", Balance: 100}
	topUp(&user, 50)          // JS'da havola yashirin, Go'da &
	fmt.Println(user.Balance) // 150
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 17 | `topUp(&user, 50)` | `&user` — `user` ning xotiradagi **manzili**. JavaScript'da havola yashirin, Go'da `&` bilan ochiq yoziladi |
| 11 | `func topUp(user *User, amount int) {` | `*User` — tur nomi: «`User` ga **pointer**», yaʼni `User` turidagi qiymatning manzili |
| 12 | `user.Balance += amount` | maydonga oddiy nuqta bilan yozamiz: Go manzil boʻyicha oʻzi boradi, `(*user).Balance` deb oʻqiydi. C'dagi `->` kabi alohida belgi kerak emas |

```console
$ go run ./pointer
150
```

Xotirada nima boʻladi? Qisqa fragment (kurs papkasida bunday fayl yoʻq, `pointer/` dagi bilan bir xil gʻoya):

```go
user := User{Balance: 100}
p := &user
p.Balance += 50
fmt.Println(user.Balance)
```

`p := &user` yangi `User` yaratmaydi. `p` faqat `user` qayerda turganini saqlaydi. `p` orqali yozsak, `user` ning
oʻz qiymati oʻzgaradi:

| Qatordan keyin | `user.Balance` | `p` (`*User`) | Ekranda |
|---|---|---|---|
| 1 | 100 | — | |
| 2 | 100 | `user` ning manzili (yangi `User` yoʻq) | |
| 3 | **150** (`p` orqali, `user` ning oʻzi) | `user` ning manzili | |
| 4 | 150 | | `150` |

```text
p := &user

  user (User)                       p (*User)
  ┌──────────┬──────────────┐       ┌────────────────────┐
  │ ID "42"  │ Balance 150  │ ◄──── │ user'ning manzili  │
  └──────────┴──────────────┘       └────────────────────┘

topUp(&user, 50): manzil nusxalanadi

  main'dagi &user ───────┐
                         ├──► bitta user
  topUp'dagi user ───────┘   (ikkala nusxa bitta joyni koʻrsatadi)
```

Diqqat: `topUp` ga `&user` berganda ham nusxa olinadi, faqat bu safar **manzilning** nusxasi. Ikkala nusxa bitta
joyni koʻrsatadi. Shuning uchun qoida oʻzgarmaydi: Go'da hamma narsa qiymat bilan uzatiladi. Go FAQ: pointer
qiymatini uzatish pointer'ning nusxasini yaratadi, u koʻrsatgan maʼlumotning emas.

Pointer'ning zero value'si — `nil`: u hech narsani koʻrsatmaydi. Boshidagi GO-X.03 savolidagi panic shu edi: `resp` `nil` edi,
`resp.Body` esa `nil` orqali oʻqish.

### Qachon pointer kerak?

| Holat | Parametr turi |
|---|---|
| chaqiruvchining qiymatini oʻzgartirish kerak | `*User` |
| struct katta | `*User` |
| kichik struct, faqat oʻqiladi | `User` (odatiy) |

Go jamoasining tavsiyasi (Code Review Comments): bir necha bayt tejash uchun pointer uzatmang. Bu maslahat katta
struct'larga, hatto oʻsishi mumkin boʻlgan kichik struct'larga ham taalluqli emas.

Oldingi darslardagi ikki vaʼda ham shu:

- GO-X.02 dagi `json.Unmarshal([]byte(body), &item)`: `Unmarshal` `item` ni toʻldirishi kerak, shuning uchun `&item`
  oladi. Hujjatda yozilgan: argument pointer boʻlmasa, `Unmarshal` `InvalidUnmarshalError` qaytaradi.
- GO-X.01 dagi handler soʻrovni `r *http.Request`, yaʼni pointer bilan oladi.

## `range` nusxasi: hook'ning javobi

Endi boshidagi handler'ga qaytamiz. Undagi sikl — A variant. Yana ikki variantni koʻring. Har biridan oldin `users`
`fresh()` («yangi») bilan qaytadan 100 ga tiklanadi. B variantda indeks, C variantda pointer bor. `range/main.go`:

```go filename="range/main.go" showLineNumbers
// Bashorat 2 (GO-X.04): uchta sikl — qaysi biri users'ni o'zgartiradi?
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func fresh() []User { return []User{{ID: "42", Balance: 100}} }

func main() {
	users := fresh()
	for _, user := range users { // A: user — elementning nusxasi
		user.Balance += 50
	}
	fmt.Println("A:", users[0].Balance)

	users = fresh()
	for i := range users { // B: users[i] — elementning o'zi
		users[i].Balance += 50
	}
	fmt.Println("B:", users[0].Balance)

	users = fresh()
	for _, user := range users { // C: &user — NUSXAning manzili
		p := &user
		p.Balance += 50
	}
	fmt.Println("C:", users[0].Balance)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 11 | `func fresh() []User { … }` | har chaqiruvda bitta foydalanuvchili yangi slice qaytaradi |
| 15–17 | A: `for _, user := range users { user.Balance += 50 }` | hook'dagi sikl |
| 21–23 | B: `for i := range users { users[i].Balance += 50 }` | `i` — indeks (GO-X.02); `users[i]` — indeks orqali olingan element |
| 27–30 | C: `p := &user; p.Balance += 50` | `range` bergan `user` ning manzili orqali yozadi |
| 18, 24, 31 | `fmt.Println("A:", users[0].Balance)` | slice'dagi birinchi elementning balansi |

Izohlardagi javoblarni yopib turing. Qaysi variant `users` dagi balansni 150 qiladi?

**A)** faqat B · **B)** B va C · **C)** uchalasi ham

<details>
<summary>Javob</summary>

**A: faqat B.** `range` bergan `user` — elementning nusxasi, xuddi `c := user` kabi. C'dagi pointer esa shu
**nusxaning** manzili. B'da indeks orqali olingan `users[i]` — slice ichidagi elementning oʻzi. «B va C» ni tanlagan
boʻlsangiz, pointer har doim asl qiymatni koʻrsatadi deb oʻylagansiz: u siz bergan narsaning manzilini koʻrsatadi,
bu yerda nusxaning. «Uchalasi ham» ni tanlagan boʻlsangiz, `range` ni JavaScript'dagi `for…of` deb oʻqigansiz.

</details>

```console
$ go run ./range
A: 100
B: 150
C: 100
```

| Variant | Nimaga yozildi | `users[0].Balance` |
|---|---|---|
| A | `user` — elementning nusxasi | 100 |
| B | `users[i]` — elementning oʻzi | **150** |
| C | `p` → `user` nusxasining manzili | 100 |

Spec'dagi `for range` qoidasi: har qadamda iteratsiya qiymatlari sikl oʻzgaruvchilariga **qiymat sifatida beriladi**,
keyin blok bajariladi. «100 Go Mistakes» kitobidagi 30-xato aynan shu: `range` dagi qiymat elementi — nusxa.

### Oʻrtadagi savol: `&users[i]`

Bu safar indeks bilan yuramiz, lekin indeks orqali olingan elementning manzilini `&` bilan olamiz. Keyin `p` orqali
yozamiz. `manzil/main.go`:

```go filename="manzil/main.go" showLineNumbers
// O'rtadagi sinov (GO-X.04): &users[i] — slice elementining o'z manzili (C variantdagi &user esa nusxaning manzili).
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func main() {
	users := []User{{ID: "42", Balance: 100}}
	for i := range users {
		p := &users[i]
		p.Balance += 50
	}
	fmt.Println(users[0].Balance) // 150
}
```

14-qatorda `&users[i]`, C variantda esa `&user` edi. Ekranda nima chiqadi?

**A)** `100` — `p` yana nusxa · **B)** `150` · **C)** build xatosi

<details>
<summary>Javob</summary>

**B: `150`.** Indeks orqali olingan `users[i]` — slice'dagi asl element, `&` esa uning oʻz manzilini beradi. C'da
manzil nusxaniki edi. «`100`» ni tanlagan boʻlsangiz, har qanday `p := &…` nusxa beradi deb oʻylagansiz: `&` hech
narsani nusxalamaydi, faqat manzil oladi. «Build xatosi» ni tanlagan boʻlsangiz, slice elementining manzilini olib
boʻlmaydi deb oʻylagansiz: Go spec boʻyicha slice elementi addressable, yaʼni manzili bor.

</details>

```console
$ go run ./manzil
150
```

Bu shakl struct katta boʻlsa yoki elementni boshqa funksiyaga berish kerak boʻlsa qulay.

### Handler'ni tuzatamiz

Indeks bilan yuramiz va elementga indeks orqali yozamiz, javobga ham shu elementni beramiz. `tuzat/main.go`
(`hook/main.go` bilan farqi izohlardan, yaʼni 1–3-qatorlardan tashqari faqat 30–33-qatorlarda):

```go filename="tuzat/main.go" showLineNumbers
// Tuzatilgan hook (GO-X.04): range indeks bilan, element users[i] orqali o'zgartiriladi.
// ⚠️ Demo: users global, so'rovlar esa parallel goroutine'larda — haqiqiy xizmatda sync.Mutex kerak (GO-1.09).
// Ishga tushirish: go run ./tuzat   (boshqa terminalda: curl -X POST localhost:3000/users/42/topup; curl localhost:3000/users/42)
package main

import (
	"encoding/json"
	"log"
	"net/http"
)

type User struct {
	ID      string `json:"id"`
	Balance int    `json:"balance"`
}

var users = []User{{ID: "42", Balance: 100}}

func main() {
	http.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
		for _, user := range users {
			if user.ID == r.PathValue("id") {
				json.NewEncoder(w).Encode(user)
				return
			}
		}
		http.NotFound(w, r)
	})
	http.HandleFunc("POST /users/{id}/topup", func(w http.ResponseWriter, r *http.Request) {
		for i := range users {
			if users[i].ID == r.PathValue("id") {
				users[i].Balance += 50
				json.NewEncoder(w).Encode(users[i])
				return
			}
		}
		http.NotFound(w, r)
	})
	log.Println("listening on :3000")
	log.Fatal(http.ListenAndServe(":3000", nil))
}
```

| Qator | Kod | Nima oʻzgardi |
|---|---|---|
| 30 | `for i := range users {` | element emas, indeks |
| 31 | `if users[i].ID == r.PathValue("id") {` | elementning oʻzini oʻqiymiz |
| 32 | `users[i].Balance += 50` | slice'dagi elementning oʻziga yozamiz |
| 33 | `json.NewEncoder(w).Encode(users[i])` | javobga ham shu element |

`GET` handler'idagi `range` nusxasi zararsiz: u faqat oʻqiydi.

```console

```

```console

```

ishlatilgan («Koʻp uchraydigan xatolar» boʻlimida golangci-lint natijasi bor).

Bu demo. `net/http` har bir soʻrovni alohida goroutine'da, yaʼni parallel ishlaydigan alohida ishda bajaradi.

## Map'dagi struct: manzili yoʻq element

Koʻp xizmat foydalanuvchilarni slice'da emas, id boʻyicha map'da saqlaydi. Map — JavaScript'dagi `Map` kabi kalit →
qiymat jadvali. Avval bitta qoida.

Go faqat manzili bor narsaning maydoniga yozadi. Bunday qiymat **addressable** deyiladi. Go spec'dagi roʻyxat:

| Nima | Addressable? | Misol |
|---|---|---|
| oʻzgaruvchi | ha | `user.Balance = 0` ✓ |
| slice elementi | ha | `users[i].Balance = 0` ✓ |
| pointer orqali | ha | `p.Balance = 0` ✓ |
| map elementi | **yoʻq** | `users["42"].Balance = 0` ✗ |
| butun map elementini almashtirish | (alohida qoida) | `users["42"] = user` ✓ |

Nega map elementi emas? Map oʻsganda elementlarni yangi xotiraga koʻchiradi (go1.26.8 manbasida
`runtime/maps` paketidagi `grow` funksiyasi shuni qiladi). Element manzili eskirib qolardi. Go tilining
mualliflaridan Robert Griesemer 2012-yilda shunday yozgan: biz map elementiga omon qolgan pointer boʻlishini
istamaymiz.

JavaScript'da `Map` dan elementni olib, balansini oshirish ishlaydi. Go'da xuddi shuni yozamiz. `mapxato/main.go`:

```go filename="mapxato/main.go" showLineNumbers
// O'rtadagi sinov (GO-X.04): map'dagi struct maydoniga to'g'ridan-to'g'ri yozib bo'lmaydi. Ataylab build bo'lmaydi.
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func main() {
	users := map[string]User{"42": {ID: "42", Balance: 100}}
	// JS: users.get("42").balance += 50 — ishlaydi
	users["42"].Balance += 50
	fmt.Println(users["42"].Balance)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 12 | `users := map[string]User{"42": {…}}` | `map[string]User` — kaliti `string`, qiymati `User` boʻlgan map; `"42"` kalitida bitta `User` |
| 14 | `users["42"].Balance += 50` | `"42"` kalitidagi `User` ning maydoniga yozmoqchi |
| 15 | `fmt.Println(users["42"].Balance)` | balansni chiqaradi |

Bu dastur nima qiladi?

**A)** `150` chiqaradi · **B)** `100` chiqaradi (nusxa) · **C)** build xatosi

<details>
<summary>Javob</summary>

**C: build xatosi.** Map elementi addressable emas, uning maydoniga yozib boʻlmaydi. Go jim nusxani oʻzgartirish
oʻrniga buni build paytida toʻxtatadi. «`100` (nusxa)» ni tanlagan boʻlsangiz, «hamma narsa nusxalanadi» qoidasini
qoʻllagansiz: bu yerda Go jim qolmaydi. «`150`» ni tanlagan boʻlsangiz, JavaScript'dagi `Map` ni koʻchirgansiz.

</details>

```console
$ go run ./mapxato

mapxato/main.go:14:2: cannot assign to struct field users["42"].Balance in map
```

Birinchi qator — xato qaysi paketda. Buyruqda papka (`./mapxato`) berildi, shuning uchun Go paketning toʻliq
nomini yozadi: modul yoʻli + papka. (GO-X.02 da buyruqqa `.go` fayl berilgani uchun `# command-line-arguments`
edi.) `mapxato/main.go:14:2` — 14-qator, 2-ustun. *cannot assign to struct field users["42"].Balance in map* —
«map'dagi `users["42"].Balance` struct maydoniga qiymat berib boʻlmaydi».

### Ikki tuzatish

`maptuzat/main.go`:


| 15 | `users["42"] = user` | butun elementni map'ga qaytarib yozamiz |
| 18 | `ptrs := map[string]*User{"42": &User{…}}` | **2-usul:** map'da pointer saqlaymiz. `&User{…}` — yangi `User` ning manzili |

## Slice va massiv

Oxirgi tushuncha. Kvadrat qavs ichida uzunlik boʻlsa (`[3]int`), bu **massiv** (array), va uzunlik turning bir
qismi: `[3]int` va `[4]int` — ikki xil tur. Boʻsh qavs (`[]int`) esa **slice**, oldingi darslarda koʻrgan
roʻyxatimiz. Amalda massiv kam uchraydi, deyarli hamma joyda slice. Lekin farq nusxa qoidasini yaxshi koʻrsatadi.
`slice/main.go`:

```go filename="slice/main.go" showLineNumbers
// Bashorat 3 (GO-X.04): massiv qiymat — butunlay nusxalanadi; slice esa elementlarni bo'lishadi.
package main

import "fmt"

func main() {
	a := [3]int{1, 2, 3} // massiv: uzunligi turning bir qismi
	b := a
	b[0] = 9

	s := []int{1, 2, 3} // slice
	t := s
	t[0] = 9

	fmt.Println(a[0], s[0]) // 1 9
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7 | `a := [3]int{1, 2, 3}` | uchta `int` li massiv |
| 8–9 | `b := a`, `b[0] = 9` | `a` ni `b` ga beramiz, `b` ning birinchi elementini oʻzgartiramiz |
| 11 | `s := []int{1, 2, 3}` | xuddi shunday slice |
| 12–13 | `t := s`, `t[0] = 9` | `s` ni `t` ga beramiz, `t[0]` ni oʻzgartiramiz |
| 15 | `fmt.Println(a[0], s[0])` | asl `a` va `s` ning birinchi elementi |

Fayl boshidagi izohlarni yopib turing. `Println` nima chiqaradi?

**A)** `1 1` · **B)** `9 9` · **C)** `1 9`

<details>
<summary>Javob</summary>

**C: `1 9`.** Massiv — qiymat: `b := a` hamma elementlarni nusxalaydi, xuddi struct kabi. Slice esa JavaScript
massivi kabi elementlarni boʻlishadi, chunki uning ichida elementlarga pointer bor. «`9 9`» ni tanlagan boʻlsangiz,
JavaScript odatini koʻchirgansiz: u yerda `b = a` oʻsha massiv. «`1 1`» ni tanlagan boʻlsangiz, yangi oʻrgangan
nusxa qoidasini slice'ga ham qoʻllagansiz: slice'da faqat kichik sarlavha nusxalanadi (pastda).

</details>

```console
$ go run ./slice
1 9
```

JavaScript'da massivni nusxalash uchun uch nuqtali spread yozardingiz (`[...a]`). Oddiy `t = s` esa oʻsha massiv:

```console
$ node -e 'const s=[1,2,3]; const t=s; t[0]=9; console.log(s[0])'
9
```

PHP'da esa massiv nusxalanadi, xuddi Go'dagi `[3]int` kabi:

```console
$ php -r '$a=[1,2,3]; $b=$a; $b[0]=9; echo $a[0];'
1
```

(Bu ikki buyruq kurs papkasida fayl sifatida yoʻq: kod buyruqning oʻzida.)

### Slice sarlavhasi

Slice — bu kichik **sarlavha** (slice header). Ichida uchta narsa bor: elementlarga pointer, uzunlik va sigʻim
(capacity). `t := s` faqat sarlavhani nusxalaydi, elementlar bitta qoladi:

```text
a := [3]int{1, 2, 3};  b := a            s := []int{1, 2, 3};  t := s

  a  [1 2 3]                               s  ┌─────────┬───────┬───────┐
  b  [9 2 3]   ← alohida nusxa                │ pointer │ len 3 │ cap 3 │
                                              └────┬────┴───────┴───────┘
                                                   ▼
                                                [9 2 3]   ← elementlar bitta, umumiy
                                                   ▲
                                              t  ┌─┴───────┬───────┬───────┐
                                                 │ pointer │ len 3 │ cap 3 │  ← sarlavha nusxasi
                                                 └─────────┴───────┴───────┘
```

Go FAQ'da shunday yozilgan: map va slice qiymatlari pointer kabi ishlaydi, ularni nusxalash ular koʻrsatgan
maʼlumotni nusxalamaydi. Shuning uchun slice'ni funksiyaga bersangiz, funksiya uning elementlarini oʻzgartira oladi:
imzoda pointer boʻlmasa ham.

Diqqat: struct'da slice maydoni boʻlsa, struct nusxasi ham faqat sarlavhani oladi. Bu sayoz nusxa: elementlar
umumiy qoladi (misol «Koʻp uchraydigan xatolar» boʻlimida). `append`, `len` va `cap` bilan bogʻliq tuzoqlar —
[GO-1.08](/lab/youtube/go/go-1-08) da.

| | Nusxada nima koʻchadi | Elementlar |
|---|---|---|
| struct `c := user` | hamma maydonlar | — |
| massiv `b := a` | hamma elementlar | alohida |
| slice `t := s` | faqat sarlavha (pointer, uzunlik, sigʻim) | umumiy |
| pointer `q := p` | faqat manzil | bitta qiymat |

## Chuqurroq (ixtiyoriy): JS massivi va Go `[]User` xotirada

JavaScript'dagi obyektlar massivi aslida havolalar roʻyxati: har bir element obyektga ishora qiladi (MDN: obyektlar
havola turi). Go'dagi `[]User` esa `User` larning oʻzini ketma-ket saqlaydi. `range` nusxani aynan shu joydan oladi.

```text
JS:  users = [ ref ─┐ ]                 Go:  users []User
                    ▼                        ┌───────────────────────┬─────┐
              { id: "42", balance: 100 }     │ User{ID "42", 100}    │ ... │
                                             └───────────────────────┴─────┘
  for (const user of users)                   for _, user := range users
  → user = oʻsha havola                       → user = elementdan nusxa
```

Pointer funksiyadan tashqariga chiqib ketsa, qiymat **heap** ga, yaʼni garbage collector (GC) boshqaradigan
xotiraga oʻtishi mumkin. Go FAQ: kompilyator oʻzgaruvchi funksiya qaytgandan keyin ishlatilmasligini isbotlay
olmasa, uni heap'ga qoʻyadi. Bu **escape analysis**, u [GO-1.11](/lab/youtube/go/go-1-11) da.

Go'da pointer arifmetikasi yoʻq (`unsafe` paketisiz). Go FAQ'dagi sabab bitta soʻz: «Safety», yaʼni xavfsizlik.
Pointer arifmetikasisiz til hech qachon notoʻgʻri manzilni hosil qila olmaydi.

## Koʻp uchraydigan xatolar

**1. `range` bergan elementni oʻzgartirish.** Bu mavzuning eng klassik xatosi:
`for _, user := range users { user.Balance += 50 }` slice'ga tegmaydi. Hook'da `POST` 150, `GET` 100 edi («`range` nusxasi» boʻlimi). Eng yomoni:
standart linter buni koʻrmaydi, chunki nusxa `Encode(user)` da oʻqilgan:

```console
$ golangci-lint run ./hook
hook/main.go:23:30: Error return value of `(*encoding/json.Encoder).Encode` is not checked (errcheck)
				json.NewEncoder(w).Encode(user)
				                         ^
hook/main.go:33:30: Error return value of `(*encoding/json.Encoder).Encode` is not checked (errcheck)
				json.NewEncoder(w).Encode(user)
				                         ^
2 issues:
* errcheck: 2
```

Ikkala ogohlantirish ham faqat `Encode` qaytargan xato tekshirilmagani haqida: *Error return value … is not checked*
— «qaytgan xato tekshirilmagan». Nusxa haqida hech narsa yoʻq (golangci-lint 2.12.2, sukut boʻyicha linterlar).
**Tuzatish:** `for i := range users { users[i].Balance += 50 }` yoki `p := &users[i]`.

**2. Nusxaning manzilini olish.** `for _, user := range users { p := &user; … }` ham slice'ga tegmaydi: `p` —
nusxaning manzili (C variant, `C: 100`). **Tuzatish:** `p := &users[i]`.

**3. Oʻzgartiradigan funksiyaga struct'ni qiymat bilan berish.** `func topUp(user User, …)` chaqiruvchining
`user` iga tegmaydi, build ham, `go vet` ham jim («Funksiya parametri ham nusxa» boʻlimi). **Tuzatish:**
`func topUp(user *User, …)` va `topUp(&user, 50)`.

**4. Map'dagi struct maydoniga yozish.** `users["42"].Balance += 50` → *cannot assign to struct field
users["42"].Balance in map* (build xatosi, «Map'dagi struct» boʻlimi). **Tuzatish:** oʻqing → oʻzgartiring →
`users["42"] = user`, yoki `map[string]*User`.

**5. `map[string]*User` da yoʻq kalit.** Yoʻq kalit `*User` ning zero value'sini, yaʼni `nil` ni beradi. Bu misol
kurs papkasida yoʻq, u dars uchun alohida ishga tushirilgan (sinash uchun dars papkasida `nilptr/main.go`
yarating):

```go
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func main() {
	ptrs := map[string]*User{"42": &User{ID: "42", Balance: 100}}
	fmt.Println(ptrs["x"] == nil)
	ptrs["x"].Balance += 50
}
```

```console
$ go run ./nilptr
true
panic: runtime error: invalid memory address or nil pointer dereference
[signal SIGSEGV: segmentation violation code=0x1 addr=0x10 pc=0x49e2bd]

goroutine 1 [running]:
main.main()
	…/nilptr/main.go:13 +0x17d
exit status 2
```

12-qator `true` chiqardi: `ptrs["x"]` — `nil`. 13-qatorda `nil` orqali yozish boshidagi GO-X.03 savolidagi panic'ni berdi:
*invalid memory address or nil pointer dereference* — «notoʻgʻri manzil yoki nil pointer orqali murojaat».
`main.go:13` — yiqilgan qator. **Tuzatish:** avval kalit borligini tekshiring: `p, ok := ptrs[id]` va `!ok` boʻlsa
`404` qaytaring (🟡 uy vazifasidagi `GET` handler shunday qiladi; batafsil [GO-1.09](/lab/youtube/go/go-1-09) da).

**6. Struct nusxasini «chuqur» deb oʻylash.** Struct'da slice maydoni boʻlsa, `c := user` faqat slice sarlavhasini
nusxalaydi. Bu misol ham kurs papkasida yoʻq, dars uchun alohida ishga tushirilgan (`sayoz/main.go`, «sayoz» —
shallow):

```go
package main

import "fmt"

type User struct {
	ID   string
	Tags []string
}

func main() {
	user := User{ID: "42", Tags: []string{"new"}}
	c := user
	c.ID = "7"
	c.Tags[0] = "vip"
	fmt.Println(user.ID, user.Tags[0])
}
```

```console
$ go run ./sayoz
42 vip
```

`c.ID` ning oʻzgarishi `user` ga tegmadi (`42`), `c.Tags[0]` esa `user.Tags[0]` ni ham oʻzgartirdi (`vip`): ikkala
sarlavha bitta elementlarni koʻrsatadi. **Tuzatish:** alohida elementlar kerak boʻlsa, slice'ni ochiq nusxalang:
`c.Tags = slices.Clone(user.Tags)` ([GO-1.08](/lab/youtube/go/go-1-08) mavzusi).

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** `range` bergan `user` ni oʻzgartirgan sikl nega `users` ga tegmaydi, va ikki tuzatish qanday?

<details>
<summary>Javob</summary>

`user` — elementning nusxasi. Tuzatish: indeks orqali yozish (`users[i].Balance += 50`) yoki indeks orqali olingan
elementning manzilini olish (`p := &users[i]`).

</details>

**2.** `topUp` ga `&user` berilganda nima nusxalanadi va nega `user` oʻzgaradi?

<details>
<summary>Javob</summary>

Manzil nusxalanadi. Nusxa ham oʻsha `user` ni koʻrsatadi, shuning uchun `topUp` ichidagi `user.Balance += amount`
asl `user` ga yozadi. Qoida oʻzgarmaydi: hamma narsa qiymat bilan uzatiladi, bu yerda qiymat — manzil.

</details>

**3.** Bu dastur nima chiqaradi? (Kurs papkasida yoʻq, dars uchun alohida ishga tushirilgan.)

```go
package main

import "fmt"

func reset(a [3]int, s []int) {
	a[0] = 0
	s[0] = 0
}

func main() {
	a := [3]int{1, 2, 3}
	s := []int{1, 2, 3}
	reset(a, s)
	fmt.Println(a[0], s[0])
}
```

**A)** `0 0` · **B)** `1 0` · **C)** `1 1`

<details>
<summary>Javob</summary>

**B: `1 0`.** `reset` («nolga qaytarish») massivning toʻliq nusxasini oladi, shuning uchun `a[0]` 1 boʻlib qoladi.
Slice'ning esa faqat sarlavhasi nusxalanadi, elementlar umumiy: `s[0]` 0 boʻladi. Imzoda pointer yoʻq, lekin
funksiya slice elementlarini oʻzgartirdi. «`0 0`» ni tanlagan boʻlsangiz, massivni JavaScript massivi kabi havola
deb oʻylagansiz. «`1 1`» ni tanlagan boʻlsangiz, slice'ni ham toʻliq nusxalanadi deb oʻylagansiz.

```console
$ go run ./reset
1 0
```

</details>

**4.** `m := map[string]User{…}` boʻlsa, `m["42"].Balance = 0` nega build boʻlmaydi, `m["42"] = user` esa boʻladi?

<details>
<summary>Javob</summary>

Map elementi addressable emas: map oʻsganda elementlarni yangi xotiraga koʻchiradi, shuning uchun Go uning maydoniga
yozishga ruxsat bermaydi. Butun elementni almashtirish esa alohida ruxsat etilgan: map indeksi qiymat berishning
chap tomonida turishi mumkin.

</details>

**5.** GO-X.01 dan: `go build` qilingan binary'ni serverga koʻchirsangiz, u yerda Go kerakmi?

<details>
<summary>Javob</summary>

Kerak emas. Binary ichida runtime ham bor. Faqat u bitta OS va bitta protsessor uchun yigʻiladi (`GOOS`/`GOARCH`).

</details>

Bu bilan GO-X kursi tugadi: bitta binary, runtime'dagi turlar, error qiymat va endi nusxa bilan pointer. Keyingi
qadam — Go asoslari kursi: [GO-1.01 · Go nega bor? go build ichida nima bor](/lab/youtube/go/go-1-01).

## Uy vazifasi

Boshlangʻich fayllar GitHub'dagi dars papkasida:
[lessons/0x-04-values-pointers](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/0x-04-values-pointers)
(`uyga/` papkasi). Buyruqlar dars papkasidan ishlaydi.

🟢 **Oson** (`uyga/oson/main.go`): `deactivate` va `rename` foydalanuvchini oʻzgartirishi kerak, lekin hech narsa
oʻzgarmaydi. Birini indeks bilan, ikkinchisini pointer bilan tuzating (`main` dagi chaqiruv ham oʻzgaradi). Avval
natijani taxmin qiling.

```go filename="uyga/oson/main.go" showLineNumbers
// Uy vazifasi 🟢 (GO-X.04): ikkala funksiya users'ni o'zgartirishi kerak, lekin hech narsa o'zgarmaydi.
//
//  1. Avval taxmin qiling, keyin dars papkasidan ishga tushiring: go run ./uyga/oson
//  2. deactivate'ni indeks bilan, rename'ni pointer bilan tuzating (main'dagi chaqiruv ham o'zgaradi).
//  3. Kutilgan natija:
//     true
//     [{42 Dilnoza false} {7 Bekzod true}]
//
// Ishora: golangci-lint'da govet'ning unusedwrite tekshiruvini yoqsangiz, ikkala joyni ham ko'rsatadi
// (README'dagi .golangci.yml namunasi).
// Javob: uyga/javob/oson/main.go
package main

import "fmt"

type User struct {
	ID     string
	Name   string
	Active bool
}

var users = []User{
	{ID: "42", Name: "Dilnoza", Active: true},
	{ID: "7", Name: "Jasur", Active: true},
}

// deactivate id'si mos foydalanuvchini o'chiradi (Active = false).
func deactivate(id string) bool {
	for _, u := range users {
		if u.ID == id {
			u.Active = false
			return true
		}
	}
	return false
}

// rename foydalanuvchining nomini o'zgartiradi.
func rename(u User, name string) {
	u.Name = name
}

func main() {
	fmt.Println(deactivate("42"))
	rename(users[1], "Bekzod")
	fmt.Println(users)
}
```

```console
$ go run ./uyga/oson
true
[{42 Dilnoza true} {7 Jasur true}]
```

`Println` slice'ni `[{…} {…}]` koʻrinishida, har bir struct'ni maydon qiymatlari bilan chiqaradi. Kutilgan natija:
`true` va `[{42 Dilnoza false} {7 Bekzod true}]`. Fayldagi ishora README'dagi golangci-lint sozlamasiga ishora
qiladi: govet'ning `unusedwrite` tekshiruvi hech qachon oʻqilmaydigan yozuvni topadi.

🟡 **Oʻrta** (`uyga/orta/main.go`): `PATCH /users/{id}` map'dagi foydalanuvchi nomini oʻzgartirishi kerak, lekin
fayl build boʻlmaydi:

```console
$ go run ./uyga/orta
# github.com/abdurahmon27/go-backend-uz/lessons/0x-04-values-pointers/uyga/orta
uyga/orta/main.go:53:3: cannot assign to struct field users[id].Name in map
```

Ikki usulda tuzating: a) oʻqing → oʻzgartiring → map'ga qaytarib yozing; b) `map[string]*User`. Fayldagi
`u, ok := users[…]` — map'dan oʻqishning ikkinchi shakli: `ok` kalit bor-yoʻqligini aytadi (batafsil
[GO-1.09](/lab/youtube/go/go-1-09) da). `var body struct { … }` — faqat shu handler uchun nomsiz struct. Ishga tushiring
(gcc boʻlmasa, `CGO_ENABLED=0` bilan) va boshqa terminalda tekshiring:

```bash
go run ./uyga/orta
curl -X PATCH -d '{"name":"Dilnoza A."}' localhost:3000/users/42   # {"id":"42","name":"Dilnoza A.","balance":100}
curl localhost:3000/users/42                                        # oʻsha
curl -X PATCH -d '{"name":"X"}' localhost:3000/users/1              # 404 page not found
```

⚠️ `net/http` har soʻrovni alohida goroutine'da bajaradi, shuning uchun haqiqiy xizmatda map'ga yozish
`sync.Mutex` bilan himoyalanadi ([GO-1.09](/lab/youtube/go/go-1-09)). Bu vazifada bitta `curl` bilan tekshiramiz.

Javoblar: [uyga/javob/](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/0x-04-values-pointers/uyga/javob)
papkasi. Avval oʻzingiz urinib koʻring.

<details>
<summary>Javob</summary>

🟢 `deactivate` da `u` — elementning nusxasi (`range`), `rename` da `u` — chaqiruvchining nusxasi (qiymat
parametri). `deactivate` ni indeks bilan, `rename` ni pointer bilan tuzatamiz:

```go filename="uyga/javob/oson/main.go" showLineNumbers
// Javob 🟢 (GO-X.04): deactivate — indeks orqali elementning o'zi; rename — pointer (&users[1]).
package main

import "fmt"

type User struct {
	ID     string
	Name   string
	Active bool
}

var users = []User{
	{ID: "42", Name: "Dilnoza", Active: true},
	{ID: "7", Name: "Jasur", Active: true},
}

func deactivate(id string) bool {
	for i := range users {
		if users[i].ID == id {
			users[i].Active = false // nusxa emas, slice'dagi element
			return true
		}
	}
	return false
}

func rename(u *User, name string) {
	u.Name = name // u — pointer: chaqiruvchining qiymatiga yozadi
}

func main() {
	fmt.Println(deactivate("42"))
	rename(&users[1], "Bekzod") // slice elementining manzili
	fmt.Println(users)
}
```

```console
$ go run ./uyga/javob/oson
true
[{42 Dilnoza false} {7 Bekzod true}]
```

`rename(&users[1], …)` — `manzil/` dagi `&users[i]` bilan bir xil gʻoya: slice elementining oʻz manzili.

🟡 a) usulda `PATCH` handler'ining oxiri shunday boʻladi (`uyga/javob/orta/main.go`):

```go
u, ok := users[id] // u — map'dagi qiymatning nusxasi
if !ok {
	http.NotFound(w, r)
	return
}
u.Name = body.Name
users[id] = u // nusxani qaytarib yozamiz
json.NewEncoder(w).Encode(u)
```

b) usulda `var users = map[string]*User{…}`: `u` pointer boʻlgani uchun `u.Name = body.Name` dan keyin qaytarib
yozish shart emas. `sync.Mutex` esa ikkala usulda ham kerak. Dars tayyorlanayotganda javob `CGO_ENABLED=0` bilan
ishga tushirildi: `PATCH` va keyingi `GET` → `{"id":"42","name":"Dilnoza A.","balance":100}`, `/users/1` →
`404 page not found`.

</details>
