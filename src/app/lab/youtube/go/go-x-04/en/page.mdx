## What you will learn

You wrote an endpoint that adds 50 to a balance. The `POST` response says the balance is 150, all good. But the next
`GET` says 100 again: no error, nothing in the log. The same `for…of` loop in Node keeps 150. The short answer:
Go's `range` gives you a copy of the element. Why is that, and how do you fix it?

**One idea:** in Go, `=` and passing to a function copy the value (a struct too, an array too); they do not give you
a reference to the same object as JS/Python do. To change the original value, you write to it through a pointer
(`&user`, `*User`) or through an index.

By the end of the lesson you will:

- explain why a change inside `for _, user := range users` is lost, and fix it with `users[i]` or `&users[i]`;
- write a `*User` parameter and `&user` when a function must change the caller's struct, and pass by value
  otherwise;
- read the error `cannot assign to struct field … in map` and fix it in two ways;
- know how copying an array (`[3]int`) differs from copying a slice (`[]int`).

The three core new words of this lesson:

| Word | Plain meaning | English term |
|---|---|---|
| value copy | `=` and passing to a function move the whole value (all fields of a struct) to a new place | value semantics |
| pointer | the address of a value in memory: `&user` takes the address, `*User` is the type "pointer to User" | pointer |
| array and slice | `[3]int` is an array and is copied whole; `[]int` is a slice, and its copy sees the same elements | array, slice |

There are also two helper words: **addressable** (Go writes only to fields of something that has an address; a map
element does not) and **slice header** (a pointer to the elements, the length and the capacity).

First, one question from GO-X.03. `defer resp.Body.Close()` is written **before** the error check, and `http.Get`
returned an error:


<details>
<summary>Answer</summary>

**B: panic.** When `http.Get` returns an error, `resp` is `nil`. The `defer` line evaluates `resp.Body` right away,

## Where did the balance go: the handler in Go and in Node

Here is the service from the hook. It is the GO-X.01 service, but the users live in an in-memory `users` slice
instead of a database. `hook/main.go`:

```go filename="hook/main.go" showLineNumbers
// Hook (GO-X.04): GO-X.01 xizmati + xotiradagi users ro'yxati. POST /users/{id}/topup balansni 50 ga oshirishi
// kerak. Javob 150 deydi, keyingi GET esa 100: range bergan user — elementning NUSXASI.
// Ishga tushirish: go run ./hook   (boshqa terminalda: curl -X POST localhost:3000/users/42/topup; curl localhost:3000/users/42)
package main

import (
	"encoding/json"
	"log"
	"net/http"
)

type User struct {
	ID      string `json:"id"`
	Balance int    `json:"balance"`
}

var users = []User{{ID: "42", Balance: 100}}

func main() {
	http.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
		for _, user := range users {
			if user.ID == r.PathValue("id") {
				json.NewEncoder(w).Encode(user)
				return
			}
		}
		http.NotFound(w, r)
	})
	http.HandleFunc("POST /users/{id}/topup", func(w http.ResponseWriter, r *http.Request) {
		for _, user := range users {
			if user.ID == r.PathValue("id") {
				user.Balance += 50
				json.NewEncoder(w).Encode(user)
				return
			}
		}
		http.NotFound(w, r)
	})
	log.Println("listening on :3000")
	log.Fatal(http.ListenAndServe(":3000", nil))
}
```

| Line | Code | What it does |
|---|---|---|
| 1–3 | `// …` | comments: the task and how to run it |
| 4–10 | `package main`, `import ( … )` | an executable program; packages: `encoding/json` (JSON), `log` (logging), `net/http` (HTTP server) |
| 12–15 | `type User struct { … }` | the `User` type: fields `ID` and `Balance` with JSON tags (GO-X.02) |
| 17 | `var users = []User{{ID: "42", Balance: 100}}` | `users` is a slice of `User` values, standing in for a database. `{ID: "42", Balance: 100}` in curly braces is a **struct literal**, like an object literal in JavaScript |
| 20–28 | `GET /users/{id}` | the handler gets `w` (the response) and `r` (the request) (GO-X.01; the `*` in `*http.Request` is explained below in "Pointer"). It returns the `user` with the matching id as JSON, otherwise `http.NotFound` — `404` |
| 29 | `POST /users/{id}/topup` | the endpoint that adds to the balance |
| 30 | `for _, user := range users {` | looks like `for (const user of users)` in JavaScript |
| 31 | `if user.ID == r.PathValue("id") {` | compares with the id from the URL |
| 32 | `user.Balance += 50` | adds 50 to the `user` it found |
| 33 | `json.NewEncoder(w).Encode(user)` | writes `user` to the response as JSON |
| 34 | `return` | leaves the handler |
| 39–40 | `log.Println(…)`, `http.ListenAndServe(":3000", nil)` | starts the service on `:3000` (GO-X.01) |

```js filename="js/server.js"
// Hook'ning Node tomoni (GO-X.04): xuddi shu xizmat, kutubxonasiz. for…of bergan user — massivdagi O'SHA obyekt.
// Ishga tushirish: node js/server.js
const http = require("node:http");

const users = [{ id: "42", balance: 100 }];

http
  .createServer((req, res) => {
    const m = req.url.match(/^\/users\/(\w+)(\/topup)?$/);
    if (!m) return res.writeHead(404).end();
    for (const user of users) {
      if (user.id === m[1]) {
        if (req.method === "POST" && m[2]) user.balance += 50;
        return res.end(JSON.stringify(user) + "\n");
      }
    }
    res.writeHead(404).end();
  })
  .listen(3000, () => console.log("listening on :3000"));
```

## The same loop in Python and PHP

Python behaves like JavaScript. `anchor/topup.py`:

```python filename="anchor/topup.py"
# Python tomoni (GO-X.04): for bergan user — ro'yxatdagi O'SHA dict (nom obyektga bog'lanadi).
users = [{"id": "42", "name": "Dilnoza", "balance": 100}]
for user in users:
    if user["id"] == "42":
        user["balance"] += 50
print(users[0]["balance"])  # 150
```

```console
$ python3 anchor/topup.py
150
```

The `user` from `for` is the same dict that is in the list. In Python a name is bound to an object; no copy is
made.

PHP is different. `anchor/topup.php` loops over arrays first, then over objects:

```php filename="anchor/topup.php"
<?php
// PHP tomoni (GO-X.04): massiv qiymat bilan nusxalanadi (Go struct kabi), obyekt esa handle bilan (Go pointer kabi).
$users = [["id" => "42", "name" => "Dilnoza", "balance" => 100]];
foreach ($users as $u) {
    if ($u["id"] === "42") {
        $u["balance"] += 50; // $u — nusxa
    }
}
echo $users[0]["balance"], "\n"; // 100

$objs = [(object) ["id" => "42", "name" => "Dilnoza", "balance" => 100]];
foreach ($objs as $o) {
    if ($o->id === "42") {
        $o->balance += 50; // $o — o'sha obyektning handle'i
    }
}
echo $objs[0]->balance, "\n"; // 150
```

```console
$ php anchor/topup.php
100
150
```

The PHP manual says that array assignment always involves value copying. So the change in `foreach` is lost and 100
stays. An object, however, PHP changes through a **handle**, that is, an identifier of the object: 150. In PHP you
can write the reference explicitly: `foreach ($users as &$u)` (`anchor/topup-ref.php`):

```console
$ php anchor/topup-ref.php
150
```

| Language | Loop | Element | Result |
|---|---|---|---|
| JavaScript | `for (const user of users)` | the same object | 150 |
| Python | `for user in users` | the same dict | 150 |
| PHP, array | `foreach ($users as $u)` | a copy | 100 |
| PHP, object | `foreach ($objs as $o)` | a handle to the same object | 150 |
| Go | `for _, user := range users` | ? | `POST` 150, `GET` 100 |

The PHP array is the closest thing to a Go struct. The next section shows why.

## Value copy: `c := user`

In Go a struct is a value, not a reference like an object in JavaScript. `nusxa/main.go` ("copy"):

```go filename="nusxa/main.go" showLineNumbers
// Qiymat nusxasi (GO-X.04): c := user butun struct'ni (hamma maydonlarini) yangi joyga nusxalaydi.
// JS'da const c = user — o'sha obyektga ikkinchi havola bo'lardi.
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func main() {
	user := User{ID: "42", Balance: 100}
	c := user
	c.Balance += 50
	fmt.Println(user.Balance, c.Balance) // 100 150
}
```

| Line | Code | What it does |
|---|---|---|
| 7–10 | `type User struct { … }` | the `User` from the hook, without tags |
| 13 | `user := User{ID: "42", Balance: 100}` | a new `user` from a struct literal |
| 14 | `c := user` | not a reference: all fields of `user` are copied to a new place |
| 15 | `c.Balance += 50` | only the field of `c` changes |
| 16 | `fmt.Println(user.Balance, c.Balance)` | prints both balances |

In memory, line by line:

| After line | `user.ID` | `user.Balance` | `c.ID` | `c.Balance` | On screen |
|---|---|---|---|---|---|
| 13 | `"42"` | 100 | | | |
| 14 | `"42"` | 100 | `"42"` (copy) | 100 (copy) | |
| 15 | `"42"` | 100 | `"42"` | **150** | |
| 16 | `"42"` | 100 | `"42"` | 150 | `100 150` |

```console
$ go run ./nusxa
100 150
```

This is **value semantics**: `=` copies the value itself. In JavaScript `const c = user` would be a second reference
to the same object, and `user.balance` would be 150 too. The assignment rule in the Go spec says the same: the value
is assigned to the variable.

## A function parameter is a copy too

At work a separate function usually adds to the balance. In JavaScript, if you pass an object to a function, the
function changes that very object. In Go we also pass the `User` to `topUp`. `param/main.go`:

```go filename="param/main.go" showLineNumbers
// Bashorat 1 (GO-X.04): funksiya parametri ham qiymat berish — topUp user'ning nusxasini oladi.
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func topUp(user User, amount int) {
	user.Balance += amount
}

func main() {
	user := User{ID: "42", Balance: 100}
	topUp(user, 50)           // JS: topUp(user) → 150
	fmt.Println(user.Balance) // 100
}
```

| Line | Code | What it does |
|---|---|---|
| 11 | `func topUp(user User, amount int) {` | the parameter `user` is of type `User`, `amount` is an `int` number |
| 12 | `user.Balance += amount` | adds to the parameter's balance |
| 17 | `topUp(user, 50)` | passes the `user` from `main` |

What does `Println` print after `topUp`? (Try not to look at the `// 100` comment in the file.)

**A)** `150` · **B)** `100` · **C)** a build error

<details>
<summary>Answer</summary>

**B: `100`.** Passing to a function is also an assignment: the parameter is a copy of the caller's `user`. When the
function returns, the copy is gone. The Go FAQ puts the rule like this: as in all languages in the C family,
everything in Go is passed by value. A function always gets a copy of the thing passed, as if the value were
assigned to the parameter. If you chose "`150`", you carried over a JavaScript habit: there an object is passed as
a reference. If you chose "a build error", you thought Go treats this as an error: it is not an error, it is the
rule.

</details>

```console
$ go run ./param
100
```

| Step | `user.Balance` in `main` | `user.Balance` in `topUp` (copy) |
|---|---|---|
| after line 16 | 100 | — |
| entering `topUp` | 100 | 100 |
| after line 12 | 100 | 150 |
| `topUp` returned | 100 | — (the copy is gone) |

The build and `go vet` are both silent:

```console
$ go vet ./param
```

`go vet` printed nothing. It is not a bug; it is a language rule.

**Why did Go choose this?** In JavaScript any function can silently change your object, and you cannot tell from
its signature. In Go a function that wants to change your struct says so in its signature: with a pointer, which we
see next. Slices and maps are a separate case: they come at the end.

| | Who can change it? |
|---|---|
| JavaScript: `f(user)` | any function; not visible in the signature |
| Go: `topUp(user User, …)` | nobody: the function gets a copy and does not touch your `user` |
| Go: a function that changes it | has a pointer in its signature (next section) |

## Pointer: `&user` and `*User`

Now let `topUp` change the original `user`. `pointer/main.go` differs from `param/main.go` in two lines:

```go filename="pointer/main.go" showLineNumbers
// Pointer (GO-X.04): &user — user'ning manzili, *User — "User'ga pointer". topUp nusxa emas, manzil oladi.
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func topUp(user *User, amount int) {
	user.Balance += amount // Go o'zi (*user).Balance deb o'qiydi
}

func main() {
	user := User{ID: "42", Balance: 100}
	topUp(&user, 50)          // JS'da havola yashirin, Go'da &
	fmt.Println(user.Balance) // 150
}
```

| Line | Code | What it does |
|---|---|---|
| 17 | `topUp(&user, 50)` | `&user` is the **address** of `user` in memory. In JavaScript the reference is hidden; in Go you write it explicitly with `&` |
| 11 | `func topUp(user *User, amount int) {` | `*User` is a type name: "**pointer** to `User`", that is, the address of a value of type `User` |
| 12 | `user.Balance += amount` | we write to the field with a plain dot: Go follows the address itself and reads it as `(*user).Balance`. No separate operator like C's `->` is needed |

```console
$ go run ./pointer
150
```

What happens in memory? A short fragment (there is no such file in the course folder; it is the same idea as in
`pointer/`):

```go
user := User{Balance: 100}
p := &user
p.Balance += 50
fmt.Println(user.Balance)
```

`p := &user` does not create a new `User`. `p` only stores where `user` is. If we write through `p`, the value of
`user` itself changes:

| After line | `user.Balance` | `p` (`*User`) | On screen |
|---|---|---|---|
| 1 | 100 | — | |
| 2 | 100 | the address of `user` (no new `User`) | |
| 3 | **150** (through `p`, `user` itself) | the address of `user` | |
| 4 | 150 | | `150` |

```text
p := &user

  user (User)                       p (*User)
  ┌──────────┬──────────────┐       ┌────────────────────┐
  │ ID "42"  │ Balance 150  │ ◄──── │ address of user    │
  └──────────┴──────────────┘       └────────────────────┘

topUp(&user, 50): the address is copied

  &user in main ─────────┐
                         ├──► the same single user
  user in topUp ─────────┘   (both copies point to one place)
```

Note: when you pass `&user` to `topUp`, a copy is still made, only this time it is a copy of the **address**. Both
copies point to one place. So the rule does not change: everything in Go is passed by value. Go FAQ: passing a
pointer value makes a copy of the pointer, but not of the data it points to.

The zero value of a pointer is `nil`: it points to nothing. The panic in the GO-X.03 question at the start was
exactly this: `resp` was `nil`, and `resp.Body` is a read through `nil`.

### When do you need a pointer?

| Situation | Parameter type |
|---|---|
| the caller's value must change | `*User` |
| the struct is large | `*User` |
| a small struct that is only read | `User` (the usual case) |

The Go team's advice (Code Review Comments): don't pass pointers as function arguments just to save a few bytes. The
advice does not apply to large structs, or even to small structs that might grow.

Two promises from earlier lessons are about this too:

- `json.Unmarshal([]byte(body), &item)` from GO-X.02: `Unmarshal` must fill `item`, so it takes `&item`. The
  documentation says: if the argument is not a pointer, `Unmarshal` returns an `InvalidUnmarshalError`.
- The handler from GO-X.01 receives the request as `r *http.Request`, that is, through a pointer.

## The `range` copy: the answer to the hook

Back to the handler from the start. Its loop is variant A. Look at two more variants. Before each one, `fresh()`
resets `users` to 100. Variant B has an index, variant C has a pointer. `range/main.go`:

```go filename="range/main.go" showLineNumbers
// Bashorat 2 (GO-X.04): uchta sikl — qaysi biri users'ni o'zgartiradi?
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func fresh() []User { return []User{{ID: "42", Balance: 100}} }

func main() {
	users := fresh()
	for _, user := range users { // A: user — elementning nusxasi
		user.Balance += 50
	}
	fmt.Println("A:", users[0].Balance)

	users = fresh()
	for i := range users { // B: users[i] — elementning o'zi
		users[i].Balance += 50
	}
	fmt.Println("B:", users[0].Balance)

	users = fresh()
	for _, user := range users { // C: &user — NUSXAning manzili
		p := &user
		p.Balance += 50
	}
	fmt.Println("C:", users[0].Balance)
}
```

| Line | Code | What it does |
|---|---|---|
| 11 | `func fresh() []User { … }` | returns a new slice with one user on every call |
| 15–17 | A: `for _, user := range users { user.Balance += 50 }` | the loop from the hook |
| 21–23 | B: `for i := range users { users[i].Balance += 50 }` | `i` is the index (GO-X.02); `users[i]` is the element taken by index |
| 27–30 | C: `p := &user; p.Balance += 50` | writes through the address of the `user` that `range` gave |
| 18, 24, 31 | `fmt.Println("A:", users[0].Balance)` | the balance of the first element in the slice |

Cover the answers in the comments. Which variant makes the balance in `users` 150?

**A)** only B · **B)** B and C · **C)** all three

<details>
<summary>Answer</summary>

**A: only B.** The `user` from `range` is a copy of the element, just like `c := user`. The pointer in C is the
address of that **copy**. In B, `users[i]`, taken by index, is the element inside the slice itself. If you chose "B
and C", you thought a pointer always points to the original: it points to whatever you took the address of, here
the copy. If you chose "all three", you read `range` as JavaScript's `for…of`.

</details>

```console
$ go run ./range
A: 100
B: 150
C: 100
```

| Variant | What was written to | `users[0].Balance` |
|---|---|---|
| A | `user`, a copy of the element | 100 |
| B | `users[i]`, the element itself | **150** |
| C | `p` → the address of the `user` copy | 100 |

The `for range` rule in the spec: on each step the iteration values are **assigned** to the loop variables, then the
block runs. Mistake #30 in the book "100 Go Mistakes" is exactly this: the value element in a `range` loop is a
copy.

### Mid-lesson question: `&users[i]`

This time we loop by index, but we take the address of the element taken by index, with `&`. Then we write through
`p`. `manzil/main.go` ("address"):

```go filename="manzil/main.go" showLineNumbers
// O'rtadagi sinov (GO-X.04): &users[i] — slice elementining o'z manzili (C variantdagi &user esa nusxaning manzili).
package main

import "fmt"

type User struct {
	ID      string
	Balance int
}

func main() {
	users := []User{{ID: "42", Balance: 100}}
	for i := range users {
		p := &users[i]
		p.Balance += 50
	}
	fmt.Println(users[0].Balance) // 150
}
```

Line 14 has `&users[i]`; variant C had `&user`. What is printed?

## A struct in a map: an element with no address

Many services keep users not in a slice but in a map by id. A map is a key → value table, like `Map` in
JavaScript. First, one rule.

Go writes only to fields of something that has an address. Such a value is called **addressable**. The list from
the Go spec:

| What | Addressable? | Example |
|---|---|---|
| a variable | yes | `user.Balance = 0` ✓ |
| a slice element | yes | `users[i].Balance = 0` ✓ |
| through a pointer | yes | `p.Balance = 0` ✓ |
| a map element | **no** | `users["42"].Balance = 0` ✗ |
| replacing a whole map element | (a separate rule) | `users["42"] = user` ✓ |

Why not a map element? When a map grows, it moves its elements to new memory (in the go1.26.8 source, the `grow`
function in the `runtime/maps` package does this). An element's address would go stale. Robert Griesemer, one of
Go's designers, wrote in 2012: we don't want a surviving pointer to a map element.

In JavaScript, taking an element from a `Map` and adding to its balance works. Let's write the same thing in Go.
`mapxato/main.go` ("map error"):

```go filename="mapxato/main.go" showLineNumbers

	ID      string
	Balance int
}

func main() {
	users := map[string]User{"42": {ID: "42", Balance: 100}}
	// JS: users.get("42").balance += 50 — ishlaydi
	users["42"].Balance += 50
	fmt.Println(users["42"].Balance)
}
```

| Line | Code | What it does |
|---|---|---|
| 12 | `users := map[string]User{"42": {…}}` | `map[string]User` is a map with `string` keys and `User` values; key `"42"` holds one `User` |
| 14 | `users["42"].Balance += 50` | tries to write to a field of the `User` under key `"42"` |
| 15 | `fmt.Println(users["42"].Balance)` | prints the balance |

## Slices and arrays

The last concept. If there is a length inside the square brackets (`[3]int`), it is an **array**, and the length is
part of the type: `[3]int` and `[4]int` are two different types. Empty brackets (`[]int`) mean a **slice**, the list
from earlier lessons. In practice arrays are rare; slices are almost everywhere. But the difference shows the copy
rule well. `slice/main.go`:

```go filename="slice/main.go" showLineNumbers

	a := [3]int{1, 2, 3} // massiv: uzunligi turning bir qismi
	b := a
	b[0] = 9

	s := []int{1, 2, 3} // slice
	t := s
	t[0] = 9

	fmt.Println(a[0], s[0]) // 1 9
}
```

| Line | Code | What it does |
|---|---|---|
| 7 | `a := [3]int{1, 2, 3}` | an array of three `int` numbers |
| 8–9 | `b := a`, `b[0] = 9` | assign `a` to `b`, change the first element of `b` |
| 11 | `s := []int{1, 2, 3}` | the same as a slice |
| 12–13 | `t := s`, `t[0] = 9` | assign `s` to `t`, change `t[0]` |
| 15 | `fmt.Println(a[0], s[0])` | the first elements of the original `a` and `s` |

### The slice header

A slice is a small **header** (slice header). It holds three things: a pointer to the elements, the length and the
capacity. `t := s` copies only the header; the elements stay the same:

```text
a := [3]int{1, 2, 3};  b := a            s := []int{1, 2, 3};  t := s

  a  [1 2 3]                               s  ┌─────────┬───────┬───────┐
  b  [9 2 3]   ← a separate copy              │ pointer │ len 3 │ cap 3 │
                                              └────┬────┴───────┴───────┘
                                                   ▼
                                                [9 2 3]   ← one set of elements, shared
                                                   ▲
                                              t  ┌─┴───────┬───────┬───────┐
                                                 │ pointer │ len 3 │ cap 3 │  ← a copy of the header
                                                 └─────────┴───────┴───────┘
```

The Go FAQ says: map and slice values behave like pointers, and copying a map or slice value doesn't copy the data
it points to. So if you pass a slice to a function, the function can change its elements, even without a pointer in
its signature.

Note: if a struct has a slice field, a copy of the struct also gets only the header. This is a shallow copy: the
elements stay shared (the example is in "Common mistakes"). The traps with `append`, `len` and `cap` are in
[GO-1.08](/lab/youtube/go/go-1-08/en).

| | What goes into the copy | Elements |
|---|---|---|
| struct `c := user` | all fields | — |
| array `b := a` | all elements | separate |
| slice `t := s` | only the header (pointer, length, capacity) | shared |
| pointer `q := p` | only the address | one value |

## Going deeper (optional): a JS array and a Go `[]User` in memory

An array of objects in JavaScript is really a list of references: each element points to an object (MDN: objects
are a reference type). A Go `[]User` stores the `User` values themselves, one after another. `range` takes its copy
from exactly there.

```text
JS:  users = [ ref ─┐ ]                 Go:  users []User
                    ▼                        ┌───────────────────────┬─────┐
              { id: "42", balance: 100 }     │ User{ID "42", 100}    │ ... │
                                             └───────────────────────┴─────┘
  for (const user of users)                   for _, user := range users
  → user = the same reference                 → user = a copy of the element
```

If a pointer leaves the function, the value may move to the **heap**, that is, the memory managed
by the garbage collector (GC). Go FAQ: if the compiler cannot prove that the variable is not referenced after the function returns,
it allocates the variable on the heap. This is **escape analysis**, covered in [GO-1.11](/lab/youtube/go/go-1-11/en).

Go has no pointer arithmetic (without the `unsafe` package). The reason in the Go FAQ is one word: "Safety". Without
pointer arithmetic, a language can never derive an illegal address.

## Common mistakes

**1. Changing the element that `range` gives you.** The most classic mistake of this topic:
`for _, user := range users { user.Balance += 50 }` does not touch the slice. In the hook, `POST` gave 150 and `GET`
gave 100 (the "`range` copy" section). Worst of all, the standard linter does not see it, because the copy is read
in `Encode(user)`:

```console
$ golangci-lint run ./hook
hook/main.go:23:30: Error return value of `(*encoding/json.Encoder).Encode` is not checked (errcheck)
				json.NewEncoder(w).Encode(user)
				                         ^
hook/main.go:33:30: Error return value of `(*encoding/json.Encoder).Encode` is not checked (errcheck)
				json.NewEncoder(w).Encode(user)
				                         ^
2 issues:
* errcheck: 2
```

Both warnings are only about the unchecked error returned by `Encode`: *Error return value … is not checked*. Nothing
about the copy (golangci-lint 2.12.2, default linters). **Fix:** `for i := range users { users[i].Balance += 50 }` or
`p := &users[i]`.

**2. Taking the address of the copy.** `for _, user := range users { p := &user; … }` does not touch the slice
either: `p` is the address of the copy (variant C, `C: 100`). **Fix:** `p := &users[i]`.

**3. Passing a struct by value to a function that should change it.** `func topUp(user User, …)` does not touch the
caller's `user`, and both the build and `go vet` are silent (the "A function parameter is a copy too" section).
**Fix:** `func topUp(user *User, …)` and `topUp(&user, 50)`.

**4. Writing to a struct field inside a map.** `users["42"].Balance += 50` → *cannot assign to struct field
users["42"].Balance in map* (a build error, the "A struct in a map" section). **Fix:** read → change →
`users["42"] = user`, or `map[string]*User`.

**5. A missing key in `map[string]*User`.** A missing key gives the zero value of `*User`, that is, `nil`. This
example is not in the course folder; it was run separately for the lesson (to try it, create `nilptr/main.go` in the
lesson folder):

```go

	ptrs["x"].Balance += 50
}
```

Line 12 printed `true`: `ptrs["x"]` is `nil`. On line 13, writing through `nil` gave the same panic as in the GO-X.03

**6. Thinking a struct copy is "deep".** If a struct has a slice field, `c := user` copies only the slice header.
This example is not in the course folder either; it was run separately for the lesson (`sayoz/main.go`, "sayoz"
means "shallow"):

```go
	Tags []string
```

to the same elements. **Fix:** if you need separate elements, copy the slice explicitly:
`c.Tags = slices.Clone(user.Tags)` (a [GO-1.08](/lab/youtube/go/go-1-08/en) topic).

```go filename="uyga/javob/oson/main.go" showLineNumbers
			users[i].Active = false // nusxa emas, slice'dagi element
			return true
		}
	}
	return false
}

func rename(u *User, name string) {
	u.Name = name // u — pointer: chaqiruvchining qiymatiga yozadi
}

func main() {
	fmt.Println(deactivate("42"))
	rename(&users[1], "Bekzod") // slice elementining manzili
	fmt.Println(users)
}
```

```console
$ go run ./uyga/javob/oson
true
[{42 Dilnoza false} {7 Bekzod true}]
```

`rename(&users[1], …)` is the same idea as `&users[i]` in `manzil/`: the slice element's own address.

🟡 With fix a), the end of the `PATCH` handler looks like this (`uyga/javob/orta/main.go`):

```go
u, ok := users[id] // u — map'dagi qiymatning nusxasi
if !ok {
	http.NotFound(w, r)
	return
}
u.Name = body.Name
users[id] = u // nusxani qaytarib yozamiz
json.NewEncoder(w).Encode(u)
```

With fix b), `var users = map[string]*User{…}`: `u` is a pointer, so after `u.Name = body.Name` there is no need to
write it back. `sync.Mutex` is needed with both fixes. While preparing the lesson, the answer was run with
`CGO_ENABLED=0`: `PATCH` and the following `GET` → `{"id":"42","name":"Dilnoza A.","balance":100}`, `/users/1` →
`404 page not found`.
