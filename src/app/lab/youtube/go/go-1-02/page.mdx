## Nimani oʻrganasiz

Katta identifikatorga, `9223372036854775807` ga bir qoʻshamiz, uchta tilda. Python aniq javob beradi:
`9223372036854775808`. JavaScript oxirgi raqamlarni yaxlitlab, `9223372036854776000` chiqaradi. Go'da shu son
`int64` oʻzgaruvchida turadi, va `id++` xatosiz **manfiy son** beradi: `-9223372036854775808`. Bu manfiy son
qayerdan keladi, va Go qachon uni umuman kompilyatsiya qilmaydi?

**Bitta gʻoya:** Go'da butun sonning chegarasini siz tanlagan tur belgilaydi (`int8` = −128 … 127). Oʻzgaruvchidagi
qiymat chegaradan oʻtsa, two's complement boʻyicha jim aylanadi (Python'da chegara yoʻq, JS'da aniqlik yoʻqoladi).
Konstanta ifoda esa aniq hisoblanadi: yakuniy qiymat turga sigʻmasa, Go uni kompilyatsiya paytida rad etadi.

Dars oxirida siz:

- `int8`, `int16`, `int32`, `int64` va `int` ning chegarasini nomidan aytib, ularni Python `int` va JS `number`
  bilan solishtira olasiz;
- `int8` da `127 + 1` nega aynan `−128` ekanini bitlarda koʻrsata olasiz;
- qaysi qator kompilyatsiya xatosi berishini, qaysi biri jim aylanishini kodni ishga tushirmasdan ayta olasiz;
- `int8` layk hisoblagichidagi bug'ni topib tuzata olasiz va katta `int64` ID'ni frontend'ga `json:"id,string"`
  bilan buzmasdan yubora olasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| `int8` … `int64`, `int` | oʻlchami belgilangan butun son turlari: nomidagi raqam — bitlar soni | sized integer types |
| overflow | qiymat tur chegarasidan oʻtib, boshqa uchidan qaytishi: `int8` da 127 + 1 → −128 | overflow |
| konstanta | qiymati kompilyatsiya paytida maʼlum ifoda (`128`, `math.MaxInt64 + 1`): aniq hisoblanadi, turga qoʻyilganda tekshiriladi | constant |

Ikkita yordamchi soʻz ham uchraydi: **two's complement** (manfiy sonni bitlarda yozish usuli) va
**`math.MaxInt64`** (`int64` oʻzgaruvchiga sigʻadigan eng katta son). Ikkalasini kerakli joyda tushuntiramiz.

## Bir xil +1, uch xil javob

Darsning boshidagi uchta buyruq. Python va Node uchun kodning oʻzi buyruq ichida, Go uchun `hook/main.go`:

```go filename="hook/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	var id int64 = math.MaxInt64 // 9223372036854775807
	id++
	fmt.Println(id)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 3–6 | `import ( "fmt" "math" )` | `fmt` (chiqarish) va `math` paketlarini ulaydi |
| 9 | `var id int64 = math.MaxInt64` | `id` — `int64` turidagi oʻzgaruvchi. `math.MaxInt64` — `math` paketidagi konstanta: `int64` ga sigʻadigan eng katta son |
| 10 | `id++` | `id` ga bir qoʻshadi, JS'dagi `id++` kabi |
| 11 | `fmt.Println(id)` | natijani chiqaradi |

```console
$ python3 -c 'print(9223372036854775807 + 1)'
9223372036854775808
$ node -p '9223372036854775807 + 1'
9223372036854776000
$ go run hook/main.go
-9223372036854775808
```

Uchta til, uchta javob. Ulardan faqat Go'niki manfiy, va Go hech qanday xato yoki ogohlantirish bermadi.

## Butun sonning chegarasi har tilda boshqa joyda

Nega javoblar har xil? Chunki «butun son» har tilda boshqacha saqlanadi:

| Til | Butun son | Chegara | `9223372036854775807 + 1` |
|---|---|---|---|
| Python | `int` | yoʻq: «Integers have unlimited precision» | `9223372036854775808`, aniq |
| JavaScript | `number` = float64 (kasrli son formati) | 2⁵³ dan keyin aniqlik yoʻqoladi; aniq butun son uchun `BigInt` | `9223372036854776000`, yaxlitlangan |
| Go | `int8`, `int16`, `int32`, `int64`, `int` | siz tanlagan tur | `int64` da `-9223372036854775808` |

JavaScript'dagi chegarani oʻzingiz koʻring. Bu buyruqlar kurs papkasida fayl sifatida yoʻq, kodning oʻzi buyruq
ichida:

```console
$ node -p 'Number.MAX_SAFE_INTEGER'
9007199254740991
$ node -p '2**53 + 1'
9007199254740992
$ node -p '9223372036854775807n + 1n'
9223372036854775808n
```

`Number.MAX_SAFE_INTEGER` = 2⁵³ − 1. Undan keyin float64 har bir butun sonni yoza olmaydi: `2**53 + 1` ning oʻrniga
qoʻshni `2**53` chiqdi. `n` qoʻshimchasi bilan yozilgan `BigInt` esa Python kabi aniq hisoblaydi.

Go'da esa chegarani tur belgilaydi. Keyingi boʻlimda turlarni koʻramiz.

## Tur nomidagi raqam — bitlar soni: `int8` … `int64`

Go'da butun son turining nomidagi raqam bitlar soni: `int8` — 8 bit, yaʼni 1 bayt, `int64` — 64 bit, 8 bayt.
Oʻlcham va chegaralarni `sizes/main.go` chiqaradi:

```go filename="sizes/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
	"unsafe"
)

func main() {
	fmt.Println("int8 ", unsafe.Sizeof(int8(0)), "bayt:", math.MinInt8, "...", math.MaxInt8)
	fmt.Println("int16", unsafe.Sizeof(int16(0)), "bayt:", math.MinInt16, "...", math.MaxInt16)
	fmt.Println("int32", unsafe.Sizeof(int32(0)), "bayt:", math.MinInt32, "...", math.MaxInt32)
	fmt.Println("int64", unsafe.Sizeof(int64(0)), "bayt:", math.MinInt64, "...", math.MaxInt64)
	fmt.Println("uint8", unsafe.Sizeof(uint8(0)), "bayt:", 0, "...", math.MaxUint8)
	fmt.Println("int  ", unsafe.Sizeof(int(0)), "bayt (bu kompyuterda)")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 3–7 | `import (…)` | `fmt`, `math` va `unsafe` paketlarini ulaydi |
| 10–15 | `unsafe.Sizeof(int8(0))` | `int8(0)` — `int8` turidagi nol; `unsafe.Sizeof` shu turdagi qiymat xotirada necha bayt olishini aytadi. `unsafe` paketi Go'ning tur himoyasini chetlab oʻtadigan asboblar; bu yerda faqat oʻlchash uchun |
| 10–13 | `math.MinInt8`, `math.MaxInt8`, … | `math` paketidagi konstantalar: har bir turning eng kichik va eng katta qiymati |
| 14 | `uint8` | `u` — unsigned (ishorasiz): manfiy son yoʻq, 0 … 255. Bugun ishlatmaymiz, `byte` aynan shu tur |
| 15 | `int(0)` | oddiy `int` ning oʻlchami |

```console
$ go run sizes/main.go
int8  1 bayt: -128 ... 127
int16 2 bayt: -32768 ... 32767
int32 4 bayt: -2147483648 ... 2147483647
int64 8 bayt: -9223372036854775808 ... 9223372036854775807
uint8 1 bayt: 0 ... 255
int   8 bayt (bu kompyuterda)
```

Asosiy qoida: `int8` turiga faqat **−128 dan 127 gacha** sigʻadi, jami 256 ta son. Oddiy `int` bu kompyuterda
`int64` bilan bir xil oʻlchamda. Go'ning rasmiy qoidasi (Go spec) boʻyicha `int` 32 yoki 64 bit boʻladi. (Videoda
`uint8` qatori qisqartirilgan, bu yerda toʻliq chiqish.)

`:=` butun son uchun doim `int` tanlaydi (GO-X.02). Shuning uchun `int8` kerak boʻlsa, turini `var` bilan
yozamiz: `var x int8 = 127`.

## Nega aynan −128: bitlar va two's complement

Sakkiz bitda 127 bu `0111 1111`: nol va yettita bir. Bir qoʻshsak, oʻngdagi birlar nolga aylanadi va bir chapga
koʻchadi: `1000 0000`. Endi savol — bu sakkiz bit qaysi son?

Go manfiy sonni **two's complement** usulida saqlaydi: eng chap bitning vazni manfiy, `int8` da **−128**. Qolgan
bitlar odatdagidek musbat:

```text
bit vazni:    −128   64   32   16    8    4    2    1
  127  =         0    1    1    1    1    1    1    1    = 64+32+16+8+4+2+1
  + 1
 −128  =         1    0    0    0    0    0    0    0    = −128
   −1  =         1    1    1    1    1    1    1    1    = −128 + 127

sonlar doirasi:   … 126 → 127 → −128 → −127 …
```

Go'ning rasmiy qoidasi butun sonlarni aynan shunday saqlashni talab qiladi: «represented using two's complement
arithmetic». Deyarli barcha protsessorlar ham manfiy sonni shunday saqlaydi. Bitlarni `binary/main.go` chiqaradi:

```go filename="binary/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var x int8 = 127
	fmt.Printf("%4d = %08b\n", x, uint8(x))
	x++
	fmt.Printf("%4d = %08b\n", x, uint8(x))
	x = -1
	fmt.Printf("%4d = %08b\n", x, uint8(x))
}
```

- **7-qator:** `Printf` qolip boʻyicha chiqaradi: `%4d` — son, 4 belgilik joyda; `%08b` — ikkilik yozuv, 8 ta
  raqamgacha nollar bilan toʻldirilgan; `\n` — yangi qator. `uint8(x)` — oʻsha bitlarni ishorasiz son deb oʻqish:
  `%b` manfiy songa minus qoʻyib chiqarardi, bizga esa bitlarning oʻzi kerak. Konversiya «Chuqurroq» boʻlimida.
- **8–9-qatorlar:** bir qoʻshib, yana chiqaradi.
- **10–11-qatorlar:** `x = -1` va uning bitlari.

```console
$ go run binary/main.go
 127 = 01111111
-128 = 10000000
  -1 = 11111111
```

Jadvaldagi uchta qator, endi Go'ning oʻzidan.

## Overflow: xato emas, lekin tekshiruv ham yoʻq

Turning chegarasidan oʻtib aylanish **overflow** deyiladi. Go'ning rasmiy qoidasi boʻyicha bu xato emas:

> For signed integers, the operations `+`, `-`, `*`, `/`, and `<<` may legally overflow and the resulting value exists and is
> deterministically defined by the signed integer representation, the operation, and its operands. Overflow does not
> cause a run-time panic.

Yaʼni ishorali butun sonlarda `+`, `-`, `*`, `/` va `<<` qonuniy ravishda overflow boʻlishi mumkin. Natija aniq
belgilangan, dastur toʻxtamaydi (panic yoʻq).

| Qator | `x` (`int8`) | Nima boʻldi |
|---|---|---|
| `var x int8 = 127` | 127 | |
| `x++` | −128 | 127 + 1 → −128 |
| keyingi qator | −128 | xato yoʻq, dastur davom etadi |

Lekin Go overflow'ni siz uchun tekshirmaydi ham. Chegaraga yetish mumkin boʻlgan joyda tekshiruvni oʻzingiz
yozasiz: buni 🟡 uy vazifasida `safeAdd` bilan qilasiz.

GO-X.02 da Go tur xatolarini qachon ushlaganini eslang. Bu dastur nima qiladi?
**A)** `-128` chiqaradi · **B)** `128` chiqaradi · **C)** kompilyatsiya xatosi

<details>
<summary>Javob</summary>

**C: kompilyatsiya xatosi.** `128` — **konstanta**: uning qiymati kompilyatsiya paytida maʼlum. Uni `int8`
oʻzgaruvchiga qoʻyganda Go sigʻishini tekshiradi va rad etadi. «`-128`» ni tanlagan boʻlsangiz, `x++` dagi aylanishni
bu yerga koʻchirgansiz. «`128`» ni tanlagan boʻlsangiz, `int8` chegarasini unutgansiz.

</details>

```console
$ go run sigmaydi/main.go

sigmaydi/main.go:6:15: cannot use 128 (untyped int constant) as int8 value in variable declaration (overflows)
```

Xabarni oʻqiymiz. `# command-line-arguments` — `go run` fayl nomi bilan yigʻgan paketning nomi. Keyin
`sigmaydi/main.go:6:15`: fayl, 6-qator, 15-ustun, yaʼni `128` turgan joy. Keyin sabab: *cannot use 128 (untyped int
constant) as int8 value in variable declaration (overflows)* — «oʻzgaruvchi eʼlonida 128 ni (turi yoʻq butun son
konstantasini) `int8` qiymat sifatida ishlatib boʻlmaydi (sigʻmaydi)». Dastur ishga tushmadi ham.

Xabardagi *untyped constant* (turi yoʻq konstanta) nima ekanini keyingi darsda,
[GO-1.03](/lab/youtube/go/go-1-03) da ochamiz. U yerda kutish funksiyasi `time.Sleep(2)` nega atigi
2 nanosekund kutishini ham koʻramiz.

## Qoida: konstanta ifoda aniq hisoblanadi

Qoida aniqrogʻi shunday. **Konstanta ifodalar aniq, chegarasiz hisoblanadi.** Go spec: «Constant expressions are
always evaluated exactly; intermediate values and the constants themselves may require precision significantly
larger than supported by any predeclared type». Xato faqat natija `int8` yoki `int64` kabi turga qoʻyilganda va
sigʻmaganda chiqadi.

Shuning uchun boshidagi misolni konstanta bilan yozsak, u ham rad etiladi. `const64/main.go`:

```go filename="const64/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

// Ataylab kompilyatsiya bo'lmaydi: konstanta int64 ga sig'maydi.
func main() {
	var id int64 = math.MaxInt64 + 1
	fmt.Println(id)
}
```

```console
$ go run const64/main.go
# command-line-arguments
const64/main.go:10:17: cannot use math.MaxInt64 + 1 (untyped int constant 9223372036854775808) as int64 value in variable declaration (overflows)
```

10-qator, 17-ustun: `math.MaxInt64 + 1`. Xabarga qarang: Go yigʻindini aniq hisobladi, `9223372036854775808`, hech
narsa aylanmadi. Keyin bu son `int64` ga sigʻmasligini koʻrib, rad etdi. `hook/main.go` da esa xuddi shu `+ 1`
oʻzgaruvchida, ishlash paytida boʻldi va jim aylandi.

TypeScript bunday qatorni umuman tekshirmaydi. `tsc 5.9.3` `strict: true` bilan quyidagi faylni xatosiz
kompilyatsiya qildi (bu fayl kurs papkasida yoʻq, alohida tekshirdik). Qiymat esa ishlash paytida yaxlitlanadi, Node
misolidagidek:

```ts
declare const console: { log(...a: unknown[]): void }
const id: number = 9223372036854775807 + 1
console.log(id)
```

Hammasi bitta jadvalda:

| Kod | Nima | Natija |
|---|---|---|
| `var x int8 = 128` | konstanta, `int8` ga sigʻmaydi | kompilyatsiya xatosi 🛑 |
| `var id int64 = math.MaxInt64 + 1` | konstanta ifoda, `int64` ga sigʻmaydi | kompilyatsiya xatosi 🛑 |
| `x++` (`x` = 127, `int8`) | oʻzgaruvchi, ishlash paytida | −128, jim 🔄 |
| TS: `const id: number = 2⁶³ − 1 + 1` | `tsc --strict` | xato yoʻq, yaxlitlanadi |

## Amaliy xato: `int8` layk hisoblagichi

Postdagi layklar hisoblagichi uchun joyni tejab, `int8` tanlaymiz. Sikl uni noldan boshlab 200 marta oshiradi.
`layk/main.go`:

```go filename="layk/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var layk int8
	for i := 1; i <= 200; i++ {
		layk++
	}
	fmt.Println(layk)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `var layk int8` | `layk` («layk») — `int8` hisoblagich, zero value 0 |
| 7 | `for i := 1; i <= 200; i++ {` | JS'dagi `for (let i = 1; i <= 200; i++)` bilan bir xil, faqat qavssiz: 200 marta |
| 8 | `layk++` | har safar bitta layk |
| 10 | `fmt.Println(layk)` | sikldan keyin natija |

Postga 200 layk bosildi. Nima chiqadi?
**A)** `127` da toʻxtaydi · **B)** `-128` da toʻxtaydi · **C)** `-56`

<details>
<summary>Javob</summary>

**C: `-56`.** 127-laykdan keyin `layk` = 127. 128-laykda u −128 ga aylandi. Qolgan 72 layk uni −56 gacha olib
keldi: −128 + 72 = −56. «`127` da toʻxtaydi» ni tanlagan boʻlsangiz, Go sonni chegarada ushlab qoladi
(saturation) deb oʻylagansiz: ushlab qolmaydi. «`-128` da toʻxtaydi» ni tanlagan boʻlsangiz, aylanishdan keyin
qoʻshish toʻxtaydi deb oʻylagansiz: −128 dan keyin −127, −126 va hokazo.

</details>

```console
$ go run layk/main.go
-56
```

| `i` | `layk` dan keyin |
|---|---|
| 1 | 1 |
| 127 | 127 |
| 128 | −128 |
| 129 | −127 |
| 200 | −56 |

Xato ham, log ham yoʻq. Shuning uchun bunday bug'ni testsiz sezish qiyin.

**Tuzatish:** `int8` oʻrniga `int`. `layk-int/main.go` da faqat 6-qator oʻzgargan:

```go filename="layk-int/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var layk int
	for i := 1; i <= 200; i++ {
		layk++
	}
	fmt.Println(layk)
}
```

```console
$ go run layk-int/main.go
200
```

Go Tour qoidasi ham shu: «you should use `int` unless you have a specific reason to use a sized or unsigned integer
type», yaʼni alohida sabab boʻlmasa, `int` ishlating. Bir necha bayt tejash uchun kichik tur tanlash odatda
arzimaydi.

## Frontend'ga katta ID: `json:"id,string"`

Frontend uchun ikkinchi chegara ham bor. Backend `int64` ID'ni JSON'da son qilib yuborsa, JavaScript uni float64 ga
oʻqiydi va yaxlitlaydi: boshqa ID chiqadi. `hook/id.js` shuni koʻrsatadi:

```js filename="hook/id.js"
// Backend JSON'da 64 bitlik ID yubordi, frontend uni JSON.parse bilan son qilib o'qidi.
const body = '{"id":1234567890123456789}'
console.log(body)
console.log(JSON.parse(body).id)
```

```console
$ node hook/id.js
{"id":1234567890123456789}
1234567890123456800
```

Oxirgi raqamlar `789` emas, `800`. Bu ID bazadagi boshqa postga tegishli boʻlishi yoki umuman boʻlmasligi mumkin.
Shuning uchun X API (sobiq Twitter) ID'larni string qilib beradi. Uning hujjatida: «In JavaScript, integers are
limited to 53 bits. This causes precision loss with large IDs» va «Always use string IDs in your code». Twitter
`id_str` maydonini 2010-yilda shu sababdan qoʻshgan.

Go'da bu struct maydonidagi bitta teg. `jsonid/main.go`:

```go filename="jsonid/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
)

// ",string" teg int64 ni JSON'da string qilib yozadi: JS uni yaxlitlamaydi.
type Post struct {
	ID int64 `json:"id,string"`
}

func main() {
	b, _ := json.Marshal(Post{ID: 1234567890123456789})
	fmt.Println(string(b))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 4 | `"encoding/json"` | Go bilan birga keladigan JSON paketi |
| 9–11 | `type Post struct { … }` | `Post` — maydonlar toʻplami (struct), TS'dagi `type Post = { id: … }` ga oʻxshash. Structlarni [GO-1.10](/lab/youtube/go/go-1-10) da batafsil koʻramiz |
| 10 | `` ID int64 `json:"id,string"` `` | `ID` maydoni, turi `int64`. Teskari tirnoq ichidagi matn — **teg**: `encoding/json` uni oʻqiydi. `id` — JSON'dagi kalit nomi, `,string` — «bu sonni JSON'da string qilib yoz» |
| 14 | `b, _ := json.Marshal(…)` | struct'ni JSON baytlariga aylantiradi. `json.Marshal` baytlar va `error` qaytaradi, `_` xatoni tashlab yuboradi (haqiqiy kodda uni tekshiring, GO-X.03) |
| 15 | `fmt.Println(string(b))` | baytlarni matn qilib chiqaradi |

```console
$ go run jsonid/main.go
{"id":"1234567890123456789"}
```

Endi ID qoʻshtirnoq ichida: `JSON.parse` uni string qilib oʻqiydi va hech bir raqam oʻzgarmaydi. Frontend uni
string qilib saqlaydi, hisob kerak boʻlsa `BigInt(post.id)` qiladi.

## Hayotda: Boeing 787

Bu faqat oʻquv misoli emas. 2015-yilda AQSh aviatsiya boshqarmasi (FAA) Boeing 787 uchun majburiy koʻrsatma chiqardi
(AD 2015-09-07). Generatorlarni boshqaradigan toʻrtta blok (GCU) bir vaqtda yoqilib, **248 kun** uzluksiz ishlasa,
ulardagi dasturiy hisoblagich toʻlib qolardi. Shunda samolyot generator quvvatini butunlay yoʻqotib, «loss of control of
the airplane» — boshqaruvdan chiqishi mumkin edi.

Dastur tuzatilguncha samolyotni muntazam oʻchirib-yoqish buyurildi: «at intervals not to exceed 120 days», yaʼni
**120 kundan** oshmasin. Keyinroq AD 2018-20-15 yangi GCU dasturini talab qildi. FAA hisoblagichning turini va
qanchalik tez oshishini aytmagan.

| Raqam | Nima |
|---|---|
| 248 kun | uzluksiz ishlashdan keyin hisoblagich toʻladi |
| 120 kun | oʻchirib-yoqish oraligʻi bundan oshmasin |

## Chuqurroq (ixtiyoriy): konversiya `int8(big)`

Yana bir jim joy: **konversiya**, yaʼni bir butun son turini boshqasiga aylantirish. `convert/main.go`:

```go filename="convert/main.go" showLineNumbers
package main

import "fmt"

func main() {
	big := 300
	small := int8(big)
	fmt.Println(small)

	other := 200
	fmt.Println(int8(other))
}
```

- **6-qator:** `big` («katta») — `:=` tufayli `int`, qiymati 300.
- **7-qator:** `int8(big)` — `big` ni `int8` ga aylantiradi. 300 `int8` ga sigʻmaydi.
- **10–11-qatorlar:** xuddi shu, 200 bilan.

```console
$ go run convert/main.go
44
-56
```

Go pastki 8 bitni oladi, qolganini tashlaydi va xatosiz natija beradi:

| Son | Bitlari | Pastki 8 bit | `int8` sifatida |
|---|---|---|---|
| 300 | `1 0010 1100` | `0010 1100` | 32 + 8 + 4 = **44** |
| 200 | `1100 1000` | `1100 1000` | −128 + 64 + 8 = **−56** |

Go spec (Conversions): son «truncated to fit in the result type's size», yaʼni tur oʻlchamiga qirqiladi, va «there
is no indication of overflow» — overflow haqida hech qanday belgi yoʻq. JavaScript'dagi `Int8Array` ham 300 ni 44 ga
aylantiradi:

```console
$ node -p 'new Int8Array([300])[0]'
44
```

Bazadan `int64` oʻqib, `int32` ga aylantiradigan kodda xuddi shu bug boʻlishi mumkin. (Kasrli sonni butun songa
aylantirishda son sigʻmasa, natija Go implementatsiyasiga bogʻliq.)

## Koʻp uchraydigan xatolar

**1. «Overflow boʻlsa, Go xato beradi» deb oʻylash.** Bu mavzudagi eng klassik xato tushuncha. Oʻzgaruvchidagi
overflow xato ham, panic ham, log ham bermaydi: `int8` layk hisoblagichi 200 layk oʻrniga `-56` chiqardi. Toʻliq
misol «Amaliy xato: `int8` layk hisoblagichi» boʻlimida. **Tuzatish:** alohida sabab boʻlmasa, `int` ishlating.
Chegaraga yetishi mumkin boʻlgan hisobda (pul, hisoblagich) tekshiruvni oʻzingiz yozing, 🟡 uy vazifasidagi
`safeAdd` kabi.

**2. Konstantani kichik turga qoʻyish.** `var x int8 = 128` va `var id int64 = math.MaxInt64 + 1` kompilyatsiya
boʻlmaydi: «Go qachon rad etadi» va «Qoida» boʻlimlariga qarang. Xuddi shu xato turi bor konstantada ham chiqadi,
lekin xabar boshqacha. Bu `constover/main.go` (darsning birinchi versiyasidan, kurs papkasida):

```go filename="constover/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println(int8(127) + 1)
}
```

```console
$ go run constover/main.go
# command-line-arguments
constover/main.go:6:14: int8(127) + 1 (constant 128 of type int8) overflows int8
```

6-qator, 14-ustun: `int8(127) + 1`. *(constant 128 of type int8) overflows int8* — «`int8` turidagi 128 konstantasi
`int8` dan oshib ketadi». `int8(127)` — turi bor konstanta, shuning uchun Go yigʻindini ham `int8` deb tekshiradi.
Nega bu holda tekshiruv qattiqroq — [GO-1.03](/lab/youtube/go/go-1-03) da. **Tuzatish:** qiymatni sigʻadigan turga qoʻying
(`int`), yoki konstantani `int8` chegarasida qoldiring.

**3. Katta `int64` ID'ni JSON'da son qilib yuborish.** Xato xabari yoʻq: frontend `1234567890123456789` oʻrniga
`1234567890123456800` ni oladi. Misol «Frontend'ga katta ID» boʻlimida. **Tuzatish:** maydonga `json:"…,string"`
teg qoʻying, frontend'da ID'ni string yoki `BigInt` qilib saqlang.

**4. Sigʻmaydigan sonni konversiya qilish.** `int8(300)` xatosiz `44` beradi. Misol «Chuqurroq» boʻlimida.
**Tuzatish:** aylantirishdan oldin chegarani tekshiring: `if big < math.MinInt8 || big > math.MaxInt8 { … }`.

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** `int8` oʻzgaruvchida `x = 127; x++` dan keyin nima chiqadi?

<details>
<summary>Javob</summary>

`-128`. Bu overflow: qiymat chegaradan oʻtib, boshqa uchidan qaytdi, jim. Bitlarda: `0111 1111` + 1 =
`1000 0000`, eng chap bitning vazni −128.

</details>

**2.** Nega `var x int8 = 128` rad etiladi, `var a int8 = 100 + 50 - 60` esa yoʻq?

<details>
<summary>Javob</summary>

Konstanta ifoda aniq hisoblanadi, Go faqat yakuniy qiymat turga sigʻishini tekshiradi: 128 sigʻmaydi ❌, 90
sigʻadi ✅. Oraliqdagi 150 hech qayerga saqlanmaydi.

</details>

**3.** Katta `int64` ID'ni frontend'ga qanday yuborasiz?

<details>
<summary>Javob</summary>

String qilib, `json:"id,string"` teg bilan. Sabab: JavaScript'da son float64, 2⁵³ dan katta butun son yaxlitlanadi.
Frontend ID'ni string yoki `BigInt` qilib saqlaydi.

</details>

**4.** `sinov/main.go` nima chiqaradi? **A)** `150` · **B)** kompilyatsiya xatosi · **C)** `-106`

```go filename="sinov/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var a int8 = 100
	a = a + 50
	fmt.Println(a)
}
```

<details>
<summary>Javob</summary>

**C: `-106`.** Bu safar `a + 50` da oʻzgaruvchi bor, demak hisob ishlash paytida boʻladi va jim aylanadi:
150 − 256 = −106. `100 + 50 - 60` dan farqi shu: u yerda hammasi konstanta edi.

```console
$ go run sinov/main.go
-106
```

</details>

**5.** [GO-1.01](/lab/youtube/go/go-1-01) dan: yetti qatorlik Go dasturining binary'si nega qariyb 2 MB?

<details>
<summary>Javob</summary>

Go linker'i sukut boʻyicha static binary yasaydi: har bir binary ichida Go runtime (garbage collector, scheduler va
boshqalar) bor. Dasturning oʻz kodi juda kichik, baytlarning asosiy qismi runtime.

</details>

➕ **Qoʻshimcha** (`uyga/int16/main.go`): `int16` (−32768 … 32767) qaysi qadamda manfiy boʻladi? Sikl ichida
`if son < 0` bilan `i` va `son` ni chiqaring va `break` bilan chiqing. (`son` — hisoblagich.)

🟡 **Oʻrta** (`uyga/orta/main.go`): `safeAdd(a, b int64) (int64, error)` yozing: yigʻindi `int64` ga sigʻmasa, natija
oʻrniga `ErrOverflow` qaytarsin. `main` dagi toʻrtta chaqiruv `kutilgan:` izohidagidek chiqishi kerak.

```go filename="uyga/orta/main.go" showLineNumbers
package main

import (
	"errors"
	"fmt"
	"math"
)

var ErrOverflow = errors.New("int64 overflow")

// Vazifa: a+b int64 ga sig'masa, natija o'rniga ErrOverflow qaytaring.
// Ishora: overflow faqat ishorasi bir xil ikki son qo'shilganda bo'ladi
// (musbat + musbat yoki manfiy + manfiy), va yig'indining ishorasi o'zgaradi.
func safeAdd(a, b int64) (int64, error) {
	return a + b, nil // hozir jim aylanadi
}

func main() {
	fmt.Println(safeAdd(2, 3))                         // kutilgan: 5 <nil>
	fmt.Println(safeAdd(math.MaxInt64, 1))             // kutilgan: 0 int64 overflow
	fmt.Println(safeAdd(math.MinInt64, -1))            // kutilgan: 0 int64 overflow
	fmt.Println(safeAdd(math.MaxInt64, math.MinInt64)) // kutilgan: -1 <nil>
}
```

Hozir u jim aylanadi:

-1 <nil>

🟡 Overflow faqat ishorasi bir xil ikki son qoʻshilganda boʻladi: musbat + musbat manfiy chiqsa, yoki manfiy + manfiy
musbat (yoki 0) chiqsa. Go'da `a + b` panic bermaydi, shuning uchun avval qoʻshib, keyin ishorani tekshirish xavfsiz:

```go filename="uyga/javob/orta/main.go" showLineNumbers
package main

import (
	"errors"
	"fmt"
	"math"
)

var ErrOverflow = errors.New("int64 overflow")

// safeAdd a+b ni qaytaradi; int64 ga sig'masa ErrOverflow.
// Go'da a+b panic bermaydi, jim aylanadi. Shuning uchun natijani hisoblab,
// keyin ishorasini tekshiramiz: musbat+musbat manfiy chiqsa yoki
// manfiy+manfiy musbat (yoki 0) chiqsa, overflow bo'lgan.
func safeAdd(a, b int64) (int64, error) {
	sum := a + b
	if (a > 0 && b > 0 && sum < 0) || (a < 0 && b < 0 && sum >= 0) {
		return 0, ErrOverflow
	}
	return sum, nil
}

func main() {
	fmt.Println(safeAdd(2, 3))                         // 5 <nil>
	fmt.Println(safeAdd(math.MaxInt64, 1))             // 0 int64 overflow
	fmt.Println(safeAdd(math.MinInt64, -1))            // 0 int64 overflow
	fmt.Println(safeAdd(math.MaxInt64, math.MinInt64)) // -1 <nil>
}
```

```console
$ go run ./uyga/javob/orta
5 <nil>
0 int64 overflow
0 int64 overflow
-1 <nil>
```

17-qatordagi `&&` — «va», `||` — «yoki», JS'dagidek. `MaxInt64 + MinInt64` ishorasi har xil ikki son, shuning uchun
overflow yoʻq: `-1`.

Qiyinroq vazifalar (`homework/README.md` da batafsil):

- 🟢 `int16` da `32767 + 1` → `-32768`: `0111 1111 1111 1111` + 1 = `1000 0000 0000 0000`, `int8` dagi qoida, faqat
  16 bitda.
- 🟡 `int32` ning eng katta qiymati 2 147 483 647 sekund — **2038-yil 19-yanvar, 03:14:07 UTC**. Bir sekunddan keyin
  son manfiy boʻladi va 1901-yil 13-dekabrga aylanadi («2038-yil muammosi»). MySQL'dagi `TIMESTAMP` oraligʻi ham aynan
  shu yerda tugaydi.
- 🟠 Gʻoya 🟡 dagi bilan bir xil: ishorasi bir xil sonlar qoʻshilganda natijaning ishorasi oʻzgarsa, overflow.
- 🔴 `abs8(math.MinInt8)` → `-128`: +128 `int8` ga sigʻmaydi, `-(-128)` yana −128 ga aylanadi. Yechim: natijani
  kattaroq turda qaytarish (`int16`) yoki `math.MinInt8` ni alohida tekshirish.

</details>
