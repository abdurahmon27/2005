## Что вы узнаете

На одометре машины, счётчике километров, все цифры — девятки: **999 999**. Машина проезжает ещё один километр. Что
покажет счётчик? Все колёсики разом провернутся, и появятся **000 000**, без всякого предупреждения. Некоторые числа
в Go ведут себя так же, только они уходят в минус. В этом уроке разберёмся, почему.

**Одна идея:** тип числа говорит ещё и о размере ячейки: в ячейку `int8` помещаются только числа от −128 до 127.
Если неподходящее число получается во время работы программы, оно, как одометр, молча проворачивается и возвращается
к самому маленькому числу. А если оно записано без переменных, одними числами, Go отклоняет его ещё при переводе
программы.

К концу урока вы сможете:

- прочитать строку `var x int8 = 127` простыми словами и знать, какие числа помещаются в ячейку `int8`;
- заранее сказать, когда вычисление в `int8` молча пойдёт по кругу, а когда Go вообще не переведёт программу;
- знать, что лежит в переменной, которой не дали значения;
- найти скрытую ошибку в счётчике лайков и исправить её с помощью `int`.

Сегодня три новых слова:

| Слово | Простой смысл | По-английски |
|---|---|---|
| `int8` | тип числа с маленькой ячейкой: только −128 … 127 | int8 |
| переполнение | число, которое не помещается в ячейку, проворачивается и переходит на другую сторону круга | overflow |
| нулевое значение | начальное значение в ячейке, которой не дали значения: `0`, `false`, пустая строка | zero value |

Встретятся и два вспомогательных слова: **ячейка** (место, где лежит значение) и **`var`** (ярлык, тип ячейки
которого мы пишем сами).

## Ячейка и её размер: `int8`

На картинках памяти в Go 0 под ярлыком всегда был нарисован прямоугольник: именно в нём лежит значение. Отныне
будем называть этот прямоугольник **ячейкой**. Ячейка — место, где лежит значение. А ярлык — имя, приклеенное к
ячейке.

| Ярлык | Ячейка (значение) |
|---|---|
| `ochko` | `127` |

Теперь упростим одометр. Допустим, в нём всего три колёсика. Он может досчитать до 999, а для 1000 места нет.
Поэтому после последнего числа он возвращается к самому маленькому:

```text
 [9][9][8]   →   [9][9][9]    →   [0][0][0]
                самое большое     вернулся к самому маленькому
```

В памяти компьютера ячейка тоже не бесконечна. Тип числа говорит не только «это целое число», **он говорит ещё и о
размере ячейки**. Чтобы экономить место, в Go есть маленькие числовые типы. Самый маленький называется **`int8`**:

| Тип | Ячейка | Самое маленькое число | Самое большое число |
|---|---|---|---|
| `int8` | маленькая | −128 | 127 |
| `int` | очень большая | −9 223 372 036 854 775 808 | 9 223 372 036 854 775 807 |

В ячейку `int8` помещается ровно 256 чисел: половина отрицательные (от −128 до −1), половина — ноль и положительные
(от 0 до 127). Эти границы записаны в официальных правилах Go (спецификация Go): *"int8 the set of all signed 8-bit
integers (-128 to 127)"*, то есть «все 8-битные целые числа со знаком, от −128 до 127». Что такое бит,
разберём в разделе «Глубже». А обычный `int` — очень большая ячейка. Границы в таблице — для этого компьютера: на
некоторых компьютерах `int` меньше, но всё равно намного больше `int8`.

## `var`: тип ячейки пишем сами

Чтобы создать ячейку `int8`, нужно новое слово. `:=` выбирает тип сам и для целого числа всегда берёт обычный `int`.
Поэтому пишем слово **`var`**:

```go
var x int8 = 127
```

Читайте эту строку так: **«`var`, `x`, `int8`, значение 127»**.

| Часть | Что делает |
|---|---|
| `var` | создаёт новый ярлык (как `:=`) |
| `x` | имя ярлыка |
| `int8` | тип ячейки: мы написали его сами |
| `= 127` | начальное значение, которое кладётся в ячейку |

Здесь `=` написан вместе с новым ярлыком. Читайте его как «значение», так же как в GO-0.02 мы читали `ochko := 3`
как «значение три».

| После строки | Ярлык | Тип | В ячейке |
|---|---|---|---|
| `var x int8 = 127` | `x` | `int8` | `127` |

## Что будет, если прибавить к 127 единицу?

Теперь увеличим `x` на один и выведем на экран. Это файл `aylanish/main.go` («вращение») из папки курса:

```go filename="aylanish/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var x int8 = 127
	x++
	fmt.Println(x)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1–5 | `package main` … `func main() {` | знакомый шаблон из первого урока |
| 6 | `var x int8 = 127` | новый ярлык `x`, тип `int8`, значение 127: самое большое число в ячейке |
| 7 | `x++` | увеличивает `x` на один: `x = x + 1` |
| 8 | `fmt.Println(x)` | выводит на экран значение под `x` |
| 9 | `}` | `main` и программа закончились |

То есть мы хотим прибавить единицу к самому большому числу в ячейке и посмотреть на результат. Но для 128 в ячейке
`int8` места нет. Вспомните, что одометр после последнего числа возвращается к самому маленькому. Что появится на
экране? **A)** `128` · **B)** ошибка · **C)** `-128`

<details>
<summary>Ответ</summary>

**C: `-128`.** 127 — самое большое число в `int8`. После него, как на одометре, идёт самое маленькое, то есть −128.
Если вы выбрали «`128`», вы думали, что ячейка `int8` такая же большая, как `int`: 128 в неё не помещается. Если вы
выбрали «ошибку», вы ждали, что Go остановит программу. Но во время работы программы Go ничего не говорит.

</details>

`go run` переводит программу и сразу её запускает:

```console
$ go run aylanish/main.go
-128
```

`go run` не выдал ни ошибки, ни предупреждения. Программа просто вывела другое число.

## Круг чисел: переполнение (overflow)

В `int8` помещаются только числа от −128 до 127. Представьте эти числа по кругу, как циферблат часов. После 127
круг замыкается, и идёт самое маленькое число:

```text
  … → 125 → 126 → 127 ──┐
                        │ +1: для 128 нет места
  ┌─────────────────────┘
  └─► -128 → -127 → -126 → … → -1 → 0 → 1 → … → 126 → 127 ─┐
                                                            └─► снова -128 …
```

Поэтому если прибавить к 127 единицу, получится −128. Когда число не помещается в ячейку и так проворачивается, это
называется **переполнением**, по-английски **overflow**.

Что произошло в памяти:

| Строка | `x` (`int8`) | На экране |
|---|---|---|
| 6 `var x int8 = 127` | `127` | |
| 7 `x++` | `-128` (127 + 1 → по кругу: −128) | |
| 8 `fmt.Println(x)` | `-128` | `-128` |

По официальным правилам Go это **не ошибка**. В спецификации написано: результат такого вычисления *"exists and is
deterministically defined"* (точно определён) и *"Overflow does not cause a run-time panic"* (программа не
останавливается). Коротко: число молча идёт по кругу, а заметить это — задача программиста.

## Когда Go отказывается

Теперь напишем число напрямую, без переменных. Это `sigmaydi/main.go` («не помещается»):

```go filename="sigmaydi/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var x int8 = 128
	fmt.Println(x)
}
```

В 6-й строке: `var`, `x`, `int8`, значение 128. Это число стоит прямо в коде, и Go видит его ещё до запуска
программы. Вспомните [GO-0.03](/lab/youtube/go/go-0-03/ru): когда типы не совпадали, Go показывал ошибку во время перевода.
Запустится ли эта программа? **A)** выведет `128` · **B)** выведет `-128` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**C: ошибка компиляции**, программа не запустилась. 128 не помещается в `int8`, и Go увидел это заранее. Если вы
выбрали «`-128`», вы применили сюда правило про круг. Но там, где число молча шло по кругу, в вычислении была
переменная (`x++`). А здесь никакого вычисления нет: только записанное число.

</details>

```console
$ go run sigmaydi/main.go
# command-line-arguments
sigmaydi/main.go:6:15: cannot use 128 (untyped int constant) as int8 value in variable declaration (overflows)
```

Первая строка — заголовок, который пишет `go run`, он нам не нужен. Вторую строку читаем, как в прошлых уроках:

- `sigmaydi/main.go:6:15` — файл, **6-я строка**, 15-й символ (табуляция в начале строки тоже считается): здесь
  стоит `128`.
- `cannot use 128` — «нельзя использовать 128».
- `(untyped int constant)` — «целое число, тип которого ещё не задан». Об этих словах — в [GO-1.03](/lab/youtube/go/go-1-03/ru).
- `as int8 value in variable declaration` — «как значение `int8` при объявлении переменной».
- `(overflows)` — «переполняется».

В официальных правилах Go так и сказано: если число не помещается в тип, это ошибка (*"It is an error if the
constant value cannot be represented as a value of the respective type"*). **Исправление:** напишите число, которое
помещается в `int8` (127 или меньше), или выберите тип побольше, например `int`.

Итог: одно и то же неподходящее число даёт два разных результата.

| Откуда взялось неподходящее число | Пример | Что будет |
|---|---|---|
| без переменных, одними числами | `var x int8 = 128` | Go **отклоняет его при компиляции** 🛑 |
| в вычислении участвует переменная | `x++` (под `x` лежит 127) | результат получается **во время работы программы**, и число **молча идёт по кругу** 🔄 |

## Маленькая проверка: `a = a + 50`

Проверьте себя. Это `sinov/main.go` («проверка»):

```go filename="sinov/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var a int8 = 100
	a = a + 50
	fmt.Println(a)
}
```

- **Строка 6:** `var`, `a`, `int8`, значение 100.
- **Строка 7:** пусть `a` будет `a + 50`.

Что появится на экране? **A)** `150` · **B)** ошибка компиляции · **C)** отрицательное число

<details>
<summary>Ответ</summary>

**C: отрицательное число, а точнее −106.** В вычислении участвовала переменная `a`, поэтому Go не выдал ошибку. А
150 в `int8` не помещается. Если вы выбрали «`150`», вы забыли о размере ячейки. Если выбрали «ошибку компиляции»:
50 тоже записано в коде, но в вычислении есть переменная `a`. Такой результат получается только во время работы
программы.

Считаем по кругу. От 100 до 127 — 27 шагов. Из 50 остаётся ещё 23 шага: −128, −127, …, −106.

| Шаг | Число |
|---|---|
| в начале | `100` |
| 27-й шаг | `127` (самое большое) |
| 28-й шаг | `-128` (круг замкнулся) |
| 50-й шаг | `-106` |

</details>

```console
$ go run sinov/main.go
-106
```

## Нулевое значение (zero value): ячейка не бывает пустой

Одометр новой машины выходит с завода с нулями: **000 000**. Теперь скажем в Go `var`, `y`, `int8` и **не дадим
значения**:

```go
var y int8
```

Что лежит в ячейке? Для подсказки вспомните новую машину. **A)** `0` · **B)** случайное число · **C)** ошибка
компиляции

<details>
<summary>Ответ</summary>

**A: в ячейке лежит `0`.** Go никогда не оставляет ячейку без значения пустой или со случайным числом. Если вы
выбрали «случайное число»: в Go так не бывает, это записано в официальных правилах Go. Если выбрали «ошибку
компиляции»: с `var` можно создать ярлык без значения, нужно только написать тип.

</details>

Теперь не дадим значения трём ярлыкам. Это `nol/main.go` («ноль»):

```go filename="nol/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var y int8
	var tayyor bool
	var ism string
	fmt.Println(y, tayyor, "["+ism+"]")
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `var y int8` | новый ярлык `y`, тип `int8`, значение не задано |
| 7 | `var tayyor bool` | новый ярлык `tayyor` («готов»), тип `bool` (`true` или `false`), значение не задано |
| 8 | `var ism string` | новый ярлык `ism` («имя»), тип `string` (строка), значение не задано |
| 9 | `fmt.Println(y, tayyor, "["+ism+"]")` | выводит три значения через запятую в одну строку |

Обратите внимание на `"["+ism+"]"` в 9-й строке. Пустую строку на экране не видно. Чтобы её увидеть, мы приклеили
`ism` плюсом между двумя квадратными скобками (склеивание строк из [GO-0.03](/lab/youtube/go/go-0-03/ru)). `"["` и `"]"` — обычный
текст в кавычках.

```console
$ go run nol/main.go
0 false []
```

| Ярлык | Тип | В ячейке | На экране |
|---|---|---|---|
| `y` | `int8` | `0` | `0` |
| `tayyor` | `bool` | `false` | `false` |
| `ism` | `string` | `""` (пустая строка) | `[]` (между скобками ничего нет) |

Такое значение в ячейке, которой не дали значения, называется **нулевым значением**, по-английски **zero value**.
Для числа это `0`, для `bool` — `false`, для строки — пустая строка. Официальное правило Go: переменная без
значения *"is given a default value"*, то есть получает нулевое значение своего типа.

## Скрытая ошибка в счётчике лайков

Теперь частая ошибка. Программист считает лайки под фотографией и ради «экономии места» выбирает `int8`. Это
`layk/main.go` («лайк»):

```go filename="layk/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var layk int8
	for i := 1; i <= 200; i++ {
		layk++
	}
	fmt.Println(layk)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `var layk int8` | новый ярлык `layk`, тип `int8`, значения нет, значит нулевое значение: `0` |
| 7 | `for i := 1; i <= 200; i++ {` | цикл из [GO-0.05](/lab/youtube/go/go-0-05/ru): `i` от 1 до 200, то есть 200 кругов |
| 8 | `layk++` | на каждом круге добавляется один лайк |
| 9 | `}` | конец группы цикла |
| 10 | `fmt.Println(layk)` | после цикла один раз выводит `layk` |

Под фотографией нажали лайк 200 раз. Что появится на экране? **A)** `200` · **B)** ошибка компиляции ·
**C)** отрицательное число

<details>
<summary>Ответ</summary>

**C: отрицательное число, а точнее −56.** 200 не помещается в `int8`, а в вычислении есть переменная `layk`. Значит,
Go не выдаёт ошибку, и число молча идёт по кругу. Если вы выбрали «`200`», вы забыли о размере ячейки. Если выбрали
«ошибку компиляции»: в коде не написано ни одного числа больше 200, к `layk` просто прибавляется по одному.

</details>

```console
$ go run layk/main.go
-56
```

Что произошло в памяти:

| Круг (`i`) | `layk` (`int8`) |
|---|---|
| до цикла | `0` |
| 1 | `1` |
| … | … |
| 127 | `127` (самое большое) |
| 128 | `-128` (круг замкнулся) |
| … | … |
| 200 | `-56` |

На 128-м лайке число перешло на отрицательную сторону. Остальные 72 лайка довели его от −128 до −56. Ошибки не было.
Поэтому такой баг, то есть скрытую ошибку, легко не заметить: программа работает, только показывает неверное число.

**Исправить просто:** вместо `int8` пишем обычный `int`. Это `layk-int/main.go`, изменилась только 6-я строка:

```go filename="layk-int/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var layk int
	for i := 1; i <= 200; i++ {
		layk++
	}
	fmt.Println(layk)
}
```

Что теперь появится на экране? 200, потому что в ячейке `int` места хватает:

```console
$ go run layk-int/main.go
200
```

Официальное руководство Go (*A Tour of Go*) советует то же самое: *"use int unless you have a specific reason to use
a sized or unsigned integer type"*, то есть если нет особой причины, используйте `int`.

## В жизни: Boeing 787

Это не только учебный пример. В 2015 году Федеральное управление гражданской авиации США (FAA) выпустило обязательную
директиву для самолётов Boeing 787 (AD 2015-09-07). В ней сказано:

- счётчик в программе блоков, которые управляют генераторами, переполняется, если они **248 дней** подряд под
  напряжением;
- тогда самолёт мог полностью потерять питание от генераторов и *"loss of control of the airplane"*, то есть
  потерять управление;
- пока не нашли решение, было предписано регулярно выключать и снова включать самолёт: с промежутком **не больше
  120 дней**.

Позже, в 2018 году, FAA новой директивой потребовало установить в блоки новую программу (AD 2018-20-15). Тип
счётчика в директиве не назван, поэтому мы его и не угадываем.

## Глубже (необязательно): биты и two's complement

Если вы только начинаете, прочитайте этот раздел позже. Остальная часть урока от него не зависит.

**Почему именно −128?** Компьютер хранит число в лампочках: горит — 1, не горит — 0. Одна лампочка называется
**бит**. В `int8` восемь битов (это и есть 8 в названии). У каждого бита свой вес (значение). Веса горящих битов
складываются:

| Вес бита | −128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 | Число |
|---|---|---|---|---|---|---|---|---|---|
| 127 | 0 | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 64 + 32 + 16 + 8 + 4 + 2 + 1 = **127** |
| 127 + 1 | 1 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | **−128** |
| −1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 | −128 + 127 = **−1** |

127 — это один 0 и семь единиц. Прибавим единицу: единицы справа превращаются в нули, и 1 переносится влево (как
«пишем ноль, один в уме» при обычном сложении): 1 и семь нулей. Самый левый бит Go считает не плюсом, а **минус
128**. Поэтому `1000 0000` = −128. Такой способ, где самый левый бит имеет отрицательный вес, называется **two's
complement** (дополнительный код). В официальных правилах Go записано, что целые числа хранятся именно так.

Если хотите увидеть это сами, в папке есть `binary/main.go`:

```go filename="binary/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var x int8 = 127
	fmt.Printf("%4d = %08b\n", x, uint8(x))
	x++
	fmt.Printf("%4d = %08b\n", x, uint8(x))
	x = -1
	fmt.Printf("%4d = %08b\n", x, uint8(x))
}
```

Здесь три новых обозначения, они нужны только для вывода. `fmt.Printf` выводит по шаблону: `%4d` пишет число в 4
позиции, `%08b` — в виде 8 битов, `\n` заканчивает строку. `uint8(x)` — чтобы показать биты без знака минус; такая
запись (преобразование) будет в следующих уроках.

```console
$ go run binary/main.go
 127 = 01111111
-128 = 10000000
  -1 = 11111111
```

**Только числа: `int8(127) + 1`.** Ещё один пример, `constover/main.go`:

```go filename="constover/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println(int8(127) + 1)
}
```

`int8(127)` — «127, тип `int8`». Здесь тоже нет переменных, только числа. Поэтому Go отклоняет это при компиляции:

```console
$ go run constover/main.go
# command-line-arguments
constover/main.go:6:14: int8(127) + 1 (constant 128 of type int8) overflows int8
```

`overflows int8` — «переполняет `int8`». Такие числа, записанные в коде без переменных, называются **константами**
(*constant 128 of type int8* — «константа 128 типа `int8`»). Почему Go проверяет их так строго, разберём в следующем
уроке: [GO-1.03 · Константы и iota](/lab/youtube/go/go-1-03/ru).

## Частые ошибки

**1. Думать, что «Go остановит переполнение как ошибку».** Самое классическое заблуждение по этой теме. Во время
работы программы Go ничего не говорит: прибавьте единицу к 127 в `int8`, и молча получится −128. Полный пример — в
разделе «Скрытая ошибка в счётчике лайков» выше: 200 лайков превратились в `-56`. Признак: сообщения об ошибке нет,
но число неверное (часто неожиданно отрицательное). **Исправление:** если нет особой причины, используйте `int`.

**2. Выбирать маленький тип «ради экономии места».** `int8` слишком мал для счётчика: он идёт по кругу уже на 128-м
шаге. Это тот же пример с лайками. **Исправление:** обычный `int`. Маленький тип нужен, только когда границы значения
точно известны.

**3. Писать напрямую число, которое не помещается.** `var x int8 = 128`:

```console
$ go run sigmaydi/main.go
# command-line-arguments
sigmaydi/main.go:6:15: cannot use 128 (untyped int constant) as int8 value in variable declaration (overflows)
```

Читаем сообщение: файл `sigmaydi/main.go`, **6-я строка**, 15-й символ; `cannot use 128` — «нельзя использовать
128»; `(overflows)` — «переполняется». Подробный разбор — в разделе «Когда Go отказывается». **Исправление:** приведите
число к границам `int8` (−128 … 127) или выберите `int`.

## Проверьте себя

Сначала ответьте сами, потом откройте ответ.

**1.** Что получится, если к 127 в `int8` прибавить единицу (`x++`)?

<details>
<summary>Ответ</summary>

`-128`. Число молча идёт по кругу: это overflow (переполнение). Go не выдаёт ни ошибки, ни предупреждения.

</details>

**2.** Почему `var x int8 = 128` не запускается?

<details>
<summary>Ответ</summary>

Здесь есть только число, вычисления с переменной нет. Go заранее видит 128 и, раз оно не помещается в `int8`,
отклоняет программу при компиляции (`cannot use 128 … (overflows)`).

</details>

**3.** Что лежит в ярлыке `bool` без значения (`var tayyor bool`)?

<details>
<summary>Ответ</summary>

`false`: это нулевое значение (zero value) типа `bool`. В `int8` лежит `0`, в строке — пустая строка.

</details>

**4.** Что выведет этот код? **A)** `130` · **B)** ошибка компиляции · **C)** `-126`

```go
var c int8 = 120
c = c + 10
fmt.Println(c)
```

<details>
<summary>Ответ</summary>

**C: `-126`.** В вычислении есть переменная `c`, поэтому ошибки нет, и число молча идёт по кругу. От 120 до 127 —
7 шагов, оставшиеся 3 шага: −128, −127, −126. Этого примера нет в папке курса, мы запустили его отдельно:

```go
package main

import "fmt"

func main() {
	var c int8 = 120
	c = c + 10
	fmt.Println(c)
}
```

```console
$ go run takror/main.go
-126
```

</details>

**5.** Из [GO-0.05](/lab/youtube/go/go-0-05/ru): сколько кругов сделает цикл `for i := 1; i <= 200; i++ { … }`?

<details>
<summary>Ответ</summary>

200. `i` начинается с 1; когда `i` равно 200, `200 <= 200` → `true`, а при 201 — `false`. Поэтому в программе с
лайками `layk++` выполнился ровно 200 раз.

</details>
