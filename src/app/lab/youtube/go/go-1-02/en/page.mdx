## What you will learn

A car's odometer, the counter of kilometres, shows all nines: **999 999**. The car drives one more kilometre. What
does the odometer show? All the little wheels turn at once and it shows **000 000**, with no warning at all. Some
numbers in Go behave the same way, only they go back to a minus number. In this lesson you will see why.

**The one idea:** a number type also tells the size of its cell: an `int8` cell holds only numbers from −128 to 127.
If a number that doesn't fit is computed while the program runs, it silently wraps around like an odometer and goes
back to the smallest number. If it is written with no variable, only with numbers, Go rejects it while translating
the program.

By the end of the lesson you will be able to:

- read the line `var x int8 = 127` in plain words and know which numbers fit in an `int8` cell;
- say in advance when a calculation in `int8` silently wraps around, and when Go refuses to translate the program
  at all;
- know what is in a variable that was given no value;
- find the hidden mistake in a like counter and fix it with `int`.

There are three new words today:

| Word | Plain meaning | Term |
|---|---|---|
| `int8` | a number type with a small cell: only −128 … 127 | int8 |
| overflow | a number that doesn't fit in the cell wraps around to the other side of the circle | overflow |
| zero value | the starting value in a cell that was given no value: `0`, `false`, empty text | zero value |

You will also meet two helper words: **cell** (the place where a value is kept) and **`var`** (a label whose cell
type we write ourselves).

## The cell and its size: `int8`

In the memory pictures of Go 0 there was always a box drawn under the label: the value is kept in it. From now on we
call this box a **cell**. A cell is the place where a value is kept. A label is the name stuck to the cell.

| Label | Cell (value) |
|---|---|
| `ochko` | `127` |

Now let's make the odometer simpler. Say it has only three little wheels. It can count up to 999, but there is no
room for 1000. So after the last number it goes back to the smallest one:

```text
 [9][9][8]   →   [9][9][9]    →   [0][0][0]
                  the largest      back to the smallest
```

In a computer's memory a cell is not endless either. A number type does not only say "this is a whole number", **it
also tells the size of the cell**. To save space, Go has small number types. The smallest one is called **`int8`**:

| Type | Cell | Smallest number | Largest number |
|---|---|---|---|
| `int8` | small | −128 | 127 |
| `int` | very big | −9 223 372 036 854 775 808 | 9 223 372 036 854 775 807 |

An `int8` cell holds exactly 256 numbers: half are negative (from −128 to −1), half are zero and positive (from 0 to
127). These limits are written in Go's official rules (the Go spec): *"int8 the set of all signed 8-bit integers
(-128 to 127)"*. What a bit is, we will see in the section "Going deeper". The
ordinary `int` is a very big cell. The limits in the table are for this computer: on some
computers `int` is smaller, but it is still far bigger than `int8`.

## `var`: we write the cell type ourselves

To create an `int8` cell, we need a new word. `:=` chooses the type itself, and for a whole number it always takes
the ordinary `int`. So we write the word **`var`**:

```go
var x int8 = 127
```

Read this line like this: **"`var`, `x`, `int8`, value 127"**.

| Part | What it does |
|---|---|
| `var` | creates a new label (like `:=`) |
| `x` | the name of the label |
| `int8` | the type of the cell: we wrote it ourselves |
| `= 127` | the starting value put into the cell |

Here `=` is written together with a new label. Read it as "value", just as in GO-0.02 we read `ochko := 3` as "value
three".

| After the line | Label | Type | In the cell |
|---|---|---|---|
| `var x int8 = 127` | `x` | `int8` | `127` |

## What happens if we add one to 127?

Now we add one to `x` and print it. This is `aylanish/main.go` ("wrapping") from the course folder:

```go filename="aylanish/main.go" showLineNumbers
package main

import "fmt"

func main() {

	x++
	fmt.Println(x)
}
```

| Line | Code | What it does |
|---|---|---|
| 1–5 | `package main` … `func main() {` | the familiar template from the first lesson |
| 6 | `var x int8 = 127` | new label `x`, type `int8`, value 127: the largest number in the cell |
| 7 | `x++` | adds one to `x`: `x = x + 1` |
| 8 | `fmt.Println(x)` | prints the value under `x` |
| 9 | `}` | `main` and the program end |

So we want to add one to the largest number in the cell and look at the result. But there is no room for 128 in an
`int8` cell. Remember that the odometer goes back to the smallest number after the last one. What appears on the
screen? **A)** `128` · **B)** an error · **C)** `-128`

<details>
<summary>Answer</summary>

**C: `-128`.** 127 is the largest number in `int8`. After it, as on the odometer, comes the smallest one, that is
−128. If you chose "`128`", you thought the `int8` cell is as big as `int`: 128 does not fit in it. If you chose "an
error", you expected Go to stop the program. But while the program runs, Go says nothing.

</details>

`go run` translates the program and runs it right away:

```console
$ go run aylanish/main.go

```

`go run` gave no error and no warning. The program simply printed a different number.

## The circle of numbers: overflow

`int8` holds only numbers from −128 to 127. Picture these numbers on a circle, like a clock face. After 127 the circle
closes and the smallest number comes:

```text
  … → 125 → 126 → 127 ──┐
                        │ +1: no room for 128
  ┌─────────────────────┘
  └─► -128 → -127 → -126 → … → -1 → 0 → 1 → … → 126 → 127 ─┐
                                                            └─► -128 again …
```

So if we add one to 127, we get −128. When a number doesn't fit in its cell and wraps around like this, it is called
**overflow** (in Uzbek, *toʻlib ketish*, "spilling over").

What happened in memory:

| Line | `x` (`int8`) | On screen |
|---|---|---|
| 6 `var x int8 = 127` | `127` | |
| 7 `x++` | `-128` (127 + 1 → round the circle: −128) | |
| 8 `fmt.Println(x)` | `-128` | `-128` |

By Go's official rules this is **not an error**. The spec says the result of such a calculation *"exists and is
deterministically defined"* and *"Overflow does not cause a run-time panic"* (the program does not stop). In short:
the number silently wraps around, and noticing it is the programmer's job.

## When Go refuses

Now let's write the number directly, with no variable. This is `sigmaydi/main.go` ("doesn't fit"):

```go filename="sigmaydi/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var x int8 = 128
	fmt.Println(x)
}
```

Line 6 says: `var`, `x`, `int8`, value 128. This number sits right in the code, so Go can see it before the program
runs. Remember [GO-0.03](/lab/youtube/go/go-0-03/en): when types did not match, Go showed the error while translating. Will this
program run? **A)** it prints `128` · **B)** it prints `-128` · **C)** a compile error

<details>
<summary>Answer</summary>

**C: a compile error**, the program did not run. 128 does not fit in `int8`, and Go saw that in advance. If you chose
"`-128`", you applied the wrapping rule here too. But where the number silently wrapped, the calculation had a
variable in it (`x++`). Here there is no calculation at all: only a written number.

</details>

```console
$ go run sigmaydi/main.go
# command-line-arguments
sigmaydi/main.go:6:15: cannot use 128 (untyped int constant) as int8 value in variable declaration (overflows)
```

The first line is a heading that `go run` writes; we don't need it. We read the second line as in the earlier
lessons:

- `sigmaydi/main.go:6:15` — the file, **line 6**, character 15 (the Tab at the start of the line counts too): this is
  where `128` is.
- `cannot use 128` — "128 cannot be used".
- `(untyped int constant)` — "a whole number whose type is not set yet". More on these words in
  [GO-1.03](/lab/youtube/go/go-1-03/en).
- `as int8 value in variable declaration` — "as an `int8` value where a variable is declared".
- `(overflows)` — "it overflows".

Go's official rules say the same: if a number does not fit in the type, it is an error (*"It is an error if the
constant value cannot be represented as a value of the respective type"*). **Fix:** write a number that fits in
`int8` (127 or less) or pick a bigger type, for example `int`.

Summary: the same number that doesn't fit gives two different results.

| Where the number that doesn't fit came from | Example | What happens |
|---|---|---|
| no variable, only numbers | `var x int8 = 128` | Go **rejects it at compile time** 🛑 |
| a variable takes part in the calculation | `x++` (127 under `x`) | the result appears **while the program runs** and the number **silently wraps around** 🔄 |

## A small quiz: `a = a + 50`

Check yourself. This is `sinov/main.go` ("test"):

```go filename="sinov/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var a int8 = 100
	a = a + 50

```

- **Line 6:** `var`, `a`, `int8`, value 100.
- **Line 7:** let `a` now be `a + 50`.

What appears on the screen? **A)** `150` · **B)** a compile error · **C)** a negative number

<details>
<summary>Answer</summary>

**C: a negative number, to be exact −106.** The variable `a` took part in the calculation, so Go gave no error. And
150 does not fit in `int8`. If you chose "`150`", you forgot the size of the cell. If you chose "a compile error": 50
is also written in the code, but the calculation has the variable `a` in it. Such a result appears only while the

Let's count round the circle. From 100 to 127 is 27 steps. Of the 50, 23 steps are left: −128, −127, …, −106.

| Step | Number |
|---|---|
| at the start | `100` |
| step 27 | `127` (the largest) |
| step 28 | `-128` (the circle closed) |
| step 50 | `-106` |

</details>

## Zero value: a cell is never empty

A new car's odometer leaves the factory with zeros: **000 000**. Now in Go we say `var`, `y`, `int8` and **give no
value**:

```go
var y int8
```

What is in the cell? As a hint, remember the new car. **A)** `0` · **B)** a random number · **C)** a compile error

<details>
<summary>Answer</summary>

**A: the cell holds `0`.** Go never leaves a cell without a value empty or with a random number. If you chose "a
random number": that does not happen in Go, it is written in Go's official rules. If you chose "a compile error":
with `var` you can create a label without a value, you only have to write the type.

</details>

Now we give no value to three labels. This is `nol/main.go` ("zero"):

```go filename="nol/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var y int8
	var tayyor bool
	var ism string
	fmt.Println(y, tayyor, "["+ism+"]")
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `var y int8` | new label `y`, type `int8`, no value given |
| 7 | `var tayyor bool` | new label `tayyor` ("ready"), type `bool` (`true` or `false`), no value given |
| 8 | `var ism string` | new label `ism` ("name"), type `string` (text), no value given |
| 9 | `fmt.Println(y, tayyor, "["+ism+"]")` | prints three values, separated by commas, on one line |

Look at `"["+ism+"]"` on line 9. Empty text is invisible on the screen. To see it, we joined `ism` between two square
brackets with plus (joining strings from [GO-0.03](/lab/youtube/go/go-0-03/en)). `"["` and `"]"` are plain text in quotes.

```console
$ go run nol/main.go
0 false []
```

| Label | Type | In the cell | On screen |
|---|---|---|---|
| `y` | `int8` | `0` | `0` |
| `tayyor` | `bool` | `false` | `false` |
| `ism` | `string` | `""` (empty text) | `[]` (nothing between the brackets) |

Such a value in a cell that was given no value is called the **zero value** (in Uzbek, *nol qiymat*). For a number
it is `0`, for `bool` it is `false`, for text it is empty text. Go's official rule: a variable without a value *"is
given a default value"*, that is, the zero value of its type.

## The hidden mistake in a like counter

Now a common mistake. A programmer counts the likes on a photo and picks `int8` to "save space". This is
`layk/main.go` ("like"):

```go filename="layk/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var layk int8
	for i := 1; i <= 200; i++ {
		layk++
	}
	fmt.Println(layk)
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `var layk int8` | new label `layk`, type `int8`, no value, so the zero value: `0` |
| 7 | `for i := 1; i <= 200; i++ {` | the loop from [GO-0.05](/lab/youtube/go/go-0-05/en): `i` from 1 to 200, that is 200 laps |
| 8 | `layk++` | one like is added on every lap |
| 9 | `}` | the end of the loop's group |
| 10 | `fmt.Println(layk)` | after the loop, prints `layk` once |

The photo got 200 likes. What appears on the screen? **A)** `200` · **B)** a compile error · **C)** a negative number

<details>
<summary>Answer</summary>

**C: a negative number, to be exact −56.** 200 does not fit in `int8`, and the calculation has the variable `layk`
in it. So Go gives no error and the number silently wraps around. If you chose "`200`", you forgot the size of the
cell. If you chose "a compile error": no number bigger than 200 is written in the code, `layk` just gets one added at
a time.

</details>

```console
$ go run layk/main.go
-56
```

What happened in memory:

| Lap (`i`) | `layk` (`int8`) |
|---|---|
| before the loop | `0` |
| 1 | `1` |
| … | … |
| 127 | `127` (the largest) |
| 128 | `-128` (the circle closed) |
| … | … |
| 200 | `-56` |

On the 128th like the number crossed to the negative side. The other 72 likes took it from −128 to −56. No error
appeared. That is why such a bug, a hidden mistake, is easy to miss: the program works, it just shows a wrong number.

**The fix is easy:** write the ordinary `int` instead of `int8`. This is `layk-int/main.go`; only line 6 changed:

```go filename="layk-int/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var layk int
	for i := 1; i <= 200; i++ {
		layk++
	}
	fmt.Println(layk)
}
```

What appears on the screen now? 200, because an `int` cell has enough room:

```console
$ go run layk-int/main.go
200
```

Go's official guide (*A Tour of Go*) gives the same advice: *"use int unless you have a specific reason to use a
sized or unsigned integer type"*.

## In real life: the Boeing 787

This is not just a classroom example. In 2015 the US Federal Aviation Administration (FAA) issued a mandatory
directive for Boeing 787 airplanes (AD 2015-09-07). It says:

- a counter in the software of the units that control the generators overflows if they stay powered for **248 days**
  without a break;
- then the airplane could lose all generator power and this could lead to *"loss of control of the airplane"*;
- until a solution was found, the airplane had to be switched off and on again regularly: at intervals of **no more
  than 120 days**.

Later, in 2018, a new FAA directive required new software in these units (AD 2018-20-15). The directive does not name
the counter's type, so we do not guess it either.

## Going deeper (optional): bits and two's complement

If you are just starting, read this section later. The rest of the lesson does not depend on it.

**Why exactly −128?** A computer keeps a number in little lamps: a lamp that is on is 1, a lamp that is off is 0. One
lamp is called a **bit**. `int8` has eight bits (that is the 8 in its name). Each bit has its own weight (value). The
weights of the bits that are on are added up:

| Bit weight | −128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 | Number |
|---|---|---|---|---|---|---|---|---|---|
| 127 | 0 | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 64 + 32 + 16 + 8 + 4 + 2 + 1 = **127** |
| 127 + 1 | 1 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | **−128** |
| −1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 | −128 + 127 = **−1** |

127 is one 0 and seven 1s. Add one: the 1s on the right turn into 0s, and a 1 carries to the left (like "carry the
one" in ordinary addition): a 1 and seven 0s. Go counts the leftmost bit not as plus but as **minus 128**. So
`1000 0000` = −128. This method, where the leftmost bit has a negative weight, is called **two's complement**. Go's
official rules say that whole numbers are stored exactly this way.

If you want to see it yourself, the folder has `binary/main.go`:

```go filename="binary/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var x int8 = 127
	fmt.Printf("%4d = %08b\n", x, uint8(x))
	x++
	fmt.Printf("%4d = %08b\n", x, uint8(x))
	x = -1
	fmt.Printf("%4d = %08b\n", x, uint8(x))
}
```

There are three new notations here, needed only for printing. `fmt.Printf` prints by a template: `%4d` writes the
number in 4 places, `%08b` writes it as 8 bits, `\n` ends the line. `uint8(x)` shows the bits without a minus sign;
this kind of notation (conversion) comes in later lessons.

```console
$ go run binary/main.go
 127 = 01111111
-128 = 10000000
  -1 = 11111111
```

**Only numbers: `int8(127) + 1`.** One more example, `constover/main.go`:

```go filename="constover/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println(int8(127) + 1)
}
```

`int8(127)` means "127, of type `int8`". Here too there is no variable, only numbers. So Go rejects it at compile
time:

```console
$ go run constover/main.go
# command-line-arguments
constover/main.go:6:14: int8(127) + 1 (constant 128 of type int8) overflows int8
```

`overflows int8` — "it overflows `int8`". Such numbers, written in the code with no variable, are called
**constants** (*constant 128 of type int8* — "the constant 128 of type `int8`"). Why Go checks them so strictly is
the topic of the next lesson: [GO-1.03 · Constants and iota](/lab/youtube/go/go-1-03/en).

## Common mistakes

**1. Thinking "Go will stop an overflow as an error".** The most classic misconception on this topic. While the
program runs, Go says nothing: add one to 127 in `int8` and you silently get −128. The full example is in the section
"The hidden mistake in a like counter" above: 200 likes came out as `-56`. The sign: there is no error message, but
the number is wrong (often unexpectedly negative). **Fix:** unless you have a specific reason, use `int`.

**2. Picking a small type "to save space".** `int8` is too small for a counter: it wraps around already at step 128.
This is the same like example. **Fix:** the ordinary `int`. A small type is needed only when the limits of the value
are known for sure.

**3. Writing a number that doesn't fit directly.** `var x int8 = 128`:

```console
$ go run sigmaydi/main.go
# command-line-arguments
sigmaydi/main.go:6:15: cannot use 128 (untyped int constant) as int8 value in variable declaration (overflows)
```

Reading the message: the file `sigmaydi/main.go`, **line 6**, character 15; `cannot use 128` — "128 cannot be used";
`(overflows)` — "it overflows". The full reading is in the section "When Go refuses". **Fix:** bring the number into
the `int8` limits (−128 … 127) or pick `int`.

<summary>Answer</summary>

🟢 With `i <= 127` it prints `127`: the number still fits. With `i <= 128` it prints `-128`: on the 128th like the
number crosses to the negative side of the circle. The second case is in `uyga/javob/oson/main.go`:

```console
$ go run uyga/javob/oson/main.go
-128
```

🟡 `uyga/javob/orta/main.go`:

```go filename="uyga/javob/orta/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var son int16
	for i := 1; i <= 100000; i++ {
		son++
		if son < 0 {
			fmt.Println(i, son)
			break
		}
	}
}
```

```console
$ go run uyga/javob/orta/main.go
32768 -32768
```

At step 32768, `int16` wraps from 32767 to −32768. The rule is the same as in `int8`, only the circle is bigger.

The harder tasks:

```console
$ go run homework/medium/main.go
2038-01-19 03:14:07 +0000 UTC
1901-12-13 20:45:52 +0000 UTC
```

🟡 The largest `int32` value is 2 147 483 647 seconds, which is 19 January 2038, 03:14:07 (UTC). One second later the
number becomes negative and the date "jumps" to 1901. This is called the "year 2038 problem".

```console
$ go run homework/hard/main.go
false
true
true
false
```

🟠 Overflow happens only when two numbers with the same sign are added, and then the sign of the result changes. If
the sum of two positive numbers comes out negative (or the other way round), there was an overflow.

```console
$ go run homework/guru/main.go
5 -128
5 128
```

🔴 The `int8` circle is not symmetric: −128 exists, +128 does not. So `-(-128)` overflows too, and you get `-128`
again. Solution: return the result in a bigger type (`int16`).
