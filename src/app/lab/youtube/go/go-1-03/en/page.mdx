## What you will learn

In a class register, grades are written by list number, not by name: "student no. 3 got a 5". If a new student is
added in the middle of the list, whose 5 is it now?

```text
Yesterday:  1 Ali    2 Bobur   3 Dilnoza    ← no. 3 ⭐ 5
Today:      1 Ali    2 Bobur   3 Botir      4 Dilnoza
                               ⭐ 5 — whose is it now?
```

Go programs have exactly the same silent bug. In this lesson we find it and fix it.

**One idea:** a constant does not change, but its meaning depends on where it stands. It takes its type from the cell
it lands in, and `iota` takes its value from the position of its line in the list.

By the end of the lesson you will be able to:

- write a number that never changes with `const`, and know what happens if you give it a new value;
- explain why `time.Sleep(2)` asks for two nanoseconds, not two seconds, and fix it with `2 * time.Second`;
- write a list of states with `iota`;
- avoid breaking saved numbers by adding a line in the middle of the list.

Today's three main new words:

| Word | Plain meaning | Go term |
|---|---|---|
| constant (`const`) | a ready number written in the code that never changes: words carved in stone | constant |
| untyped constant | a constant with no type written: like water, it takes the type of the cell it lands in | untyped constant |
| `iota` | the line number inside the `const ( … )` brackets, starting at 0 | iota |

Two helper words also come up on the way: **`time.Sleep`** (the command that makes a program wait) and
**nanosecond** (one billionth of a second). We explain each one where it is needed.

## Constant: a number carved in stone (`const`)

In [GO-0.02](/lab/youtube/go/go-0-02/en) we compared a variable to a stadium scoreboard: the number on it keeps changing. But some
numbers never change. For example, a minute always has 60 seconds. Picture such a number as words carved in stone: you
cannot erase them and write something else.

```text
variable = scoreboard        constant = stone 🪨
PAXTAKOR  3 → 4              ┌──────────────┐
the number changes           │ soniyalar 60 │  never changes
                             └──────────────┘
```

A ready number written in the code that never changes is called a **constant**. To give a constant a name, Go uses
the word **`const`**:

```go
const soniyalar = 60
soniyalar = 61
fmt.Println(soniyalar)
```

Read the first line like this: "constant `soniyalar`, value 60". `soniyalar` means "seconds": the number of seconds in
a minute. In the second line we want to give it a new value: "let `soniyalar` now be 61".

Remember Go's habit: if there is a mistake in the code, it does not let it pass silently. What is printed?
**A)** `61` · **B)** `60` · **C)** compile error

<details>
<summary>Answer</summary>

**C: compile error.** You cannot give a constant a new value, and Go sees this before the program runs. If you chose
**A**, you took `soniyalar` for an ordinary variable. If you chose **B**, you thought Go would quietly ignore the 61.
But Go does not let mistakes pass silently: it stops and tells you.

</details>

The full program, the file `ozgarmas/main.go` in the course folder:

```go filename="ozgarmas/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const soniyalar = 60 // bir daqiqadagi soniyalar soni (vaqt emas, oddiy son)
	soniyalar = 61       // ataylab xato: konstantani oʻzgartirib boʻlmaydi
	fmt.Println(soniyalar)
}
```

| Line | Code | What it does |
|---|---|---|
| 1–5 | `package main` … `func main() {` | the familiar template: a program that runs, we connect `fmt`, the program starts in `main` |
| 6 | `const soniyalar = 60` | **constant** `soniyalar`, value 60. The text after `//` is a comment; Go does not read it |
| 7 | `soniyalar = 61` | tries to give the constant a new value: a mistake made on purpose |
| 8 | `fmt.Println(soniyalar)` | was supposed to print `soniyalar` |
| 9 | `}` | end of `main` |

```console
$ go run ozgarmas/main.go
# command-line-arguments
ozgarmas/main.go:7:2: cannot assign to soniyalar (neither addressable nor a map index expression)
```

As always, we read the message starting from the file and the line: file `ozgarmas/main.go`, **line 7**, character 2.
In the 3-line fragment above this was the second line; in the full file it is line 7, because the familiar template
stands on top. Next comes `cannot assign to soniyalar`, that is, "a value cannot be given to `soniyalar`". The other
words in brackets mean "this name is not a place where a value can be put". `go run` did not run the program.

| Line | `soniyalar` | On screen |
|---|---|---|
| 6 `const soniyalar = 60` | `60` 🪨 | |
| 7 `soniyalar = 61` | compile error: the program does not run | |

In short: like words in stone, a constant does not change.

## Untyped constant: water takes the shape of the jar

In [GO-0.03](/lab/youtube/go/go-0-03/en) we saw that `int` and `float64` variables cannot be mixed: the types do not match. As a
reminder, here is `suv-xato/main.go` (a mistake on purpose):

```go filename="suv-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	n := 100          // oʻzgaruvchi: turi int
	var b float64 = n // ataylab xato: int oʻzgaruvchi float64 katakka tushmaydi
	fmt.Println(b)
}
```

Line 6, `n := 100`, creates a variable of type `int`. Line 7, `var b float64`, creates a new label as in
[GO-1.02](/lab/youtube/go#go-1-02), only we write the cell's type ourselves: `float64`. We want to put `n` into it.

```console
$ go run suv-xato/main.go
# command-line-arguments
suv-xato/main.go:7:18: cannot use n (variable of type int) as float64 value in variable declaration
```

Line 7, character 18 (that is `n`): "`n` (a variable of type `int`) cannot be used as a `float64` value".

A constant is different. When a constant has no type written, its type is decided when it lands in a cell. Picture
the constant as water: whatever jar you pour it into, it takes that jar's shape. Such a constant is called an
**untyped constant**. This does not mean the constant never has a type: the cell it lands in gives it one.

```go filename="suv/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const yuz = 100       // turi yoʻq (untyped) konstanta
	var a int8 = yuz      // int8 katakka tushdi
	var b float64 = yuz   // float64 katakka tushdi
	fmt.Println(a/8, b/8) // int8: kasr tashlanadi, float64: qoladi
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `const yuz = 100` | the untyped constant `yuz` ("hundred" = 100) |
| 7 | `var a int8 = yuz` | an `int8` cell `a`; `yuz` landed in it: now this 100 is an `int8` |
| 8 | `var b float64 = yuz` | a `float64` cell `b`; `yuz` landed in it too: now this 100 is a `float64` |
| 9 | `fmt.Println(a/8, b/8)` | divides both by 8 and prints them, to show the difference between the types |

One constant, two different cells:

| Name | Type | Value |
|---|---|---|
| `yuz` | no type 💧 | `100` |
| `a` | `int8` | `100` |
| `b` | `float64` | `100` |

Predict: what is printed? **A)** `12 12` · **B)** `12 12.5` · **C)** compile error

<details>
<summary>Answer</summary>

**B: `12 12.5`.** `yuz` landed in both cells without an error, because it had no type. `a` is a whole number, and
dividing whole numbers drops the fraction: `100 / 8` → `12`. `b` is a floating-point number, so the fraction stays:
`12.5`. If you chose **C**, you thought `yuz` was an `int`, like `n` in `suv-xato`. If you chose **A**, you thought both
cells got the same type.

</details>

```console
$ go run suv/main.go
12 12.5
```

## `time.Sleep(2)`: not two seconds

This rule matters a lot when you work with time. **`time`** is one of Go's ready toolboxes (a package), like `fmt`. It
has a command that makes the program wait a little: **`time.Sleep`**. It puts the number in its brackets into a time
cell. The name of this cell's type is **`time.Duration`**. This cell counts time in **nanoseconds**, and a nanosecond
is one billionth of a second:

| | |
|---|---|
| 1 second | 1 000 000 000 nanoseconds |
| 1 nanosecond | 0.000 000 001 seconds |

Now a question. With `var` we create the label `kutish`, cell type `time.Duration`, value 2:

```go
var kutish time.Duration = 2
fmt.Println(kutish)
```

What is on the screen? **A)** `2s` · two seconds · **B)** `2ns` · two nanoseconds · **C)** compile error

<details>
<summary>Answer</summary>

**B: two nanoseconds.** Go gave no error, because 2 was a number with no type. It landed silently in the time cell,
and a 2 in that cell is read as nanoseconds. `Println` writes a time with its unit: `ns` = nanosecond. If you chose
**A**, you thought like a person: "time is usually in seconds". But Go counts in nanoseconds. If you chose **C**, you
remembered `suv-xato`, but there it was a variable; here it is an untyped constant.

</details>

```text
    2             →   time.Duration cell     →   2 nanoseconds
no type 💧            counts nanoseconds          no error, silent
```

So if you write `time.Sleep(2)`, the program asks to wait not two seconds but only two nanoseconds. In other words, it
hardly waits at all, and there is no error either. (`Sleep` waits at least the time asked for: when we measured it 1000
times for this course, it took from 0.4 to 27 microseconds. Still far, far less than a second.)

For two seconds, Go has a ready constant: **`time.Second`**, which equals one second. The star `*` multiplies, so
`2 * time.Second` = two seconds. Everything in one program, `kutish/main.go`:

```go filename="kutish/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	var kutish time.Duration = 2 // vaqt turi: nanosekundlarni sanaydi
	fmt.Println(kutish)          // Println birlik qoʻshadi: ns = nanosekund
	time.Sleep(kutish)           // = time.Sleep(2): deyarli kutmaydi
	kutish = 2 * time.Second     // time.Second = 1 soniya = 1 000 000 000 nanosekund
	fmt.Println(kutish)          // s = soniya
	time.Sleep(kutish)           // 2 soniya kutadi
}
```

| Line | Code | What it does |
|---|---|---|
| 3–6 | `import ( "fmt" "time" )` | connects two packages at once: inside brackets, each on its own line |
| 9 | `var kutish time.Duration = 2` | the label `kutish` ("wait"), cell type `time.Duration`; 2 landed in it: 2 nanoseconds |
| 10 | `fmt.Println(kutish)` | prints `2ns` |
| 11 | `time.Sleep(kutish)` | the same as `time.Sleep(2)`: asks for 2 nanoseconds, hardly waits |
| 12 | `kutish = 2 * time.Second` | let `kutish` now be 2 seconds: the cell holds 2 000 000 000 nanoseconds |
| 13 | `fmt.Println(kutish)` | prints the new value |
| 14 | `time.Sleep(kutish)` | now really waits 2 seconds |

What does line 13 print? **A)** `2000000000` · **B)** `2s` · **C)** `2ns`

<details>
<summary>Answer</summary>

**B: `2s`.** The cell holds 2 000 000 000 nanoseconds, but `Println` writes a time in a handy unit: `s` = second. If
you chose **A**, you saw the number in the cell, but `Println` writes it as a time, with a unit. **C** is the old
value; it was gone after line 12.

</details>

```console
$ go run kutish/main.go
2ns
2s
```

After printing `2s`, the program waits 2 seconds and only then ends.

| Line | In the `kutish` cell | On screen |
|---|---|---|
| 9 | `2` (nanoseconds) | |
| 10 | `2` | `2ns` |
| 11 | `2` | hardly waits |
| 12 | `2000000000` (nanoseconds) | |
| 13 | `2000000000` | `2s` |
| 14 | `2000000000` | waits 2 seconds ✅ |

## Quick check: `const narx = 300`

Now test yourself. We put the constant `narx` ("price") into an `int` cell and into an `int8` cell:

```go
const narx = 300
var a int = narx
var b int8 = narx
fmt.Println(a, b)
```

What is printed? **A)** `300 300` · **B)** `300 44` · **C)** compile error

<details>
<summary>Answer</summary>

**C: compile error.** 300 fit into the `int` cell, but not into the `int8` cell (it holds at most 127). If you chose
**A**, you thought water fits into any jar. **B** is the silent wrap-around: 300 − 256 = 44. That happens like `x++` in
[GO-1.02](/lab/youtube/go#go-1-02), while the program runs and computes with a variable. A constant, however, Go checks in
advance.

</details>

```go filename="sinov/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const narx = 300
	var a int = narx
	var b int8 = narx // ataylab xato: 300 int8 ga sigʻmaydi
	fmt.Println(a, b)
}
```

```console
$ go run sinov/main.go
# command-line-arguments
sinov/main.go:8:15: cannot use narx (untyped int constant 300) as int8 value in variable declaration (overflows)
```

`go run` pointed at the `int8` line: **line 8**, character 15 (that is `narx`). The message: "`narx` (the untyped whole
number constant 300) cannot be used as an `int8` value … (it overflows)". The word **untyped** is in the message too:
this is our "no type". Line 7 has no error: 300 fits easily into an `int` cell.

In short: an untyped constant takes the type of the cell it lands in. If the jar is too small, Go does not spill the
water; it gives a compile error.

## `iota`: the list number, like in a register

Now the states of an order in a shop: unknown, new, paid. Programs often store them like a register does, by list
number: 0, 1, 2. To write several constants together there are the `const ( … )` brackets. So that we do not write the
numbers by hand, we write **`iota`** inside the brackets:

```go
const (
	Nomalum = iota
	Yangi
	Tolangan
)
fmt.Println(Yangi, Tolangan)
```

The rules:

- **`iota`** is the line number inside the `const ( … )` brackets; it starts **at 0** and grows by one on each line.
- On a line with only a name, Go repeats the previous entry, that is, `= iota`.

The names: `Nomalum` ("unknown"), `Yangi` ("new"), `Tolangan` ("paid"). In the code they are written without the
apostrophe (in Uzbek they are spelled *nomaʼlum*, *toʻlangan*).

In the last line `Println` prints `Yangi` and `Tolangan`. Which two numbers are on the screen?
**A)** `0 1` · **B)** `1 2` · **C)** `2 3`

<details>
<summary>Answer</summary>

**B: `1 2`**, because counting started from zero: `Nomalum` 0, `Yangi` 1, `Tolangan` 2. If you chose **C**, you
started counting at 1. If you chose **A**, you counted `Yangi` as the first line, but the first line is `Nomalum`.

</details>

```go filename="holat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const (
		Nomalum  = iota // 0: qiymat berilmagan (nol qiymat) holat
		Yangi           // 1
		Tolangan        // 2
	)
	fmt.Println(Yangi, Tolangan)
}
```

| Line | Code | `iota` | Value of the constant |
|---|---|---|---|
| 6 | `const (` | | several constants start together |
| 7 | `Nomalum = iota` | `0` | `Nomalum` = 0 |
| 8 | `Yangi` | `1` | only a name → `= iota` is repeated → `Yangi` = 1 |
| 9 | `Tolangan` | `2` | `Tolangan` = 2 |
| 10 | `)` | | the group ends |
| 11 | `fmt.Println(Yangi, Tolangan)` | | on screen: `1 2` |

```console
$ go run holat/main.go
1 2
```

Why is 0 "unknown"? Remember the zero value from [GO-1.02](/lab/youtube/go#go-1-02): a cell that was given no value holds 0.
So even if an order was given no state, its cell holds 0. If 0 is `Nomalum`, such an order shows up as "unknown", not
as "new". That is right: we never gave it any state.

## A silent bug: a line added in the middle of the list

Now back to the register question from the start. Yesterday the shop saved a paid order to a file, like writing it in
a register, as the number **2** (back then `Tolangan` = 2). Today a programmer added a new state: `Bekor`
("cancelled"). They wrote it after `Yangi`. Then the program compares the saved 2 with `Tolangan` and with `Bekor`:

```go filename="xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const (
		Nomalum = iota
		Yangi
		Bekor // yangi holat oʻrtaga qoʻshildi
		Tolangan
	)
	saqlangan := 2 // kecha faylga yozilgan: oʻshanda 2 = Tolangan edi
	fmt.Println(saqlangan == Tolangan, saqlangan == Bekor)
}
```

| Line | Code | What it does |
|---|---|---|
| 9 | `Bekor` | the new state, added in the middle of the list |
| 12 | `saqlangan := 2` | the number saved to the file yesterday (`saqlangan` = "saved") |
| 13 | `saqlangan == Tolangan, saqlangan == Bekor` | `==` compares two numbers: the answer is `true` or `false`. `Println` prints both answers |

What is printed? **A)** `true false` · **B)** `false true` · **C)** compile error. Count the lines yourself.

<details>
<summary>Answer</summary>

**B: `false true`.** Let us count the lines: `Nomalum` 0, `Yangi` 1, `Bekor` 2, `Tolangan` 3. Now 2 means `Bekor`, and
`Tolangan` became 3. If you chose **A**, you thought `Tolangan` was still 2: but `iota` takes the number from the
position of the line. If you chose **C**, you thought Go treats this as a mistake: for Go this is a correct program.

</details>

```console
$ go run xato/main.go
false true
```

`go run` ran without an error. How the numbers moved:

| State | Yesterday (no `Bekor`) | Today (`Bekor` in the middle) |
|---|---|---|
| `Nomalum` | 0 | 0 |
| `Yangi` | 1 | 1 |
| `Bekor` | — | **2** |
| `Tolangan` | **2** | 3 |

But in the file, yesterday's 2 stayed where it was. Yesterday's paid orders now look cancelled. Just like the register:
the number stayed in place, its meaning changed.

### The fix

The lesson: the meaning of a number saved to a file must never change. So for states that are saved, write the numbers
by hand:

```go filename="tuzatish/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const ( // faylga saqlanadigan raqamlar qoʻlda yoziladi va hech qachon oʻzgarmaydi
		Nomalum  = 0
		Yangi    = 1
		Tolangan = 2
		Bekor    = 3 // yangi holat roʻyxat oxiriga
	)
	saqlangan := 2
	fmt.Println(saqlangan == Tolangan, saqlangan == Bekor)
}
```

What changed: on lines 7–10 the numbers are written by hand (no `iota`), and the new `Bekor` is at the end and got 3.
`Tolangan` is 2 again. What is printed now? **A)** `true false` · **B)** `false true`

<details>
<summary>Answer</summary>

**A: `true false`.** The saved 2 is `Tolangan` again. The number is written by hand, so no new line can move it.

</details>

```console
$ go run tuzatish/main.go
true false
```

You can keep `iota` too, but with two conditions: add a new state **only at the end of the list**, and **never delete
one** (if you delete one, the ones after it move by one again). The first homework task is exactly this. Large systems
do the same: for example, the Protocol Buffers guide (Google's format for exchanging data between programs) strongly
recommends never reusing deleted numbers.

## Going deeper (optional): `1 << 100` and `0.1 + 0.2`

If you are just starting, read this section later: the rest of the lesson makes sense without it.

**A very large constant.** By Go's rules, a whole-number constant is kept with very high precision: at least 256 bits. A **bit** is a single 0 or 1, like a lamp that is on or off
(more in the "Going deeper" part of [GO-1.02](/lab/youtube/go#go-1-02)). `big/main.go`:

```go filename="big/main.go" showLineNumbers
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(big >> 98)
}
```

| Line | Code | What it does |
|---|---|---|
| 5 | `const big = 1 << 100` | a constant can also be written outside `main`. `<<` is a left shift: it multiplies 1 by 2 a hundred times, that is, 2¹⁰⁰ |
| 8 | `fmt.Println(big >> 98)` | `>>` is a right shift: it divides `big` by 2⁹⁸ |

2¹⁰⁰ = 1 267 650 600 228 229 401 496 703 205 376, a 101-bit number. The largest whole-number cell in Go is 64 bits, so
this number fits into no whole-number cell. As a constant, though, it lives happily. Does the program run?
**A)** it runs · **B)** compile error

<details>
<summary>Answer</summary>

**A: it runs and prints `4`.** 2¹⁰⁰ / 2⁹⁸ = 2² = 4. The big number was only a constant and was computed at compile
time. Only the result, 4, went into a cell, and it fits easily into an `int`. This example is also in Go's official
rules.

</details>

```console
$ go run big/main.go
4
```

**Constants are computed exactly.** Is the sum of 0.1 and 0.2 equal to 0.3? `float/main.go`:

```go filename="float/main.go" showLineNumbers
package main

import "fmt"

const a, b = 0.1, 0.2

func main() {
	fmt.Println(a+b == 0.3)

	x, y := 0.1, 0.2
	fmt.Println(x+y == 0.3)
	fmt.Println(x + y)
}
```

| Line | Code | What it does |
|---|---|---|
| 5 | `const a, b = 0.1, 0.2` | two constants in one line: `a` = 0.1, `b` = 0.2 |
| 8 | `fmt.Println(a+b == 0.3)` | compares the sum of the constants with 0.3 |
| 10 | `x, y := 0.1, 0.2` | two `float64` variables in one line |
| 11 | `fmt.Println(x+y == 0.3)` | compares the sum of the variables with 0.3 |
| 12 | `fmt.Println(x + y)` | prints the sum itself |

Predict: **A)** `true` and `true` · **B)** `true` and `false` · **C)** `false` and `false`

<details>
<summary>Answer</summary>

**B.** With constants, `true`: Go computes them exactly. With `float64` variables, `false`, because a `float64` cell
cannot hold 0.1 and 0.2 exactly; it stores them rounded. The sum comes out slightly larger: `0.30000000000000004`.

</details>

```console
$ go run float/main.go
true
false
0.30000000000000004
```

## Common mistakes

**1. Adding a new state in the middle of an `iota` list.** The most classic mistake, because it is easy to think "I only
added one line". Go gives no error, but the numbers saved in a file silently change meaning: yesterday's paid order
shows up as cancelled. The full example is above, in the section "A silent bug: a line added in the middle of the list"
(`xato/main.go` → `false true`). **Fix:** write the numbers by hand for states that are saved (`tuzatish/main.go` →
`true false`), or add new states only at the end and never delete one.

**2. Thinking `time.Sleep(2)` is two seconds.** This is a silent bug too: the program runs without an error, but does
not wait. The untyped 2 lands in a `time.Duration` cell and becomes 2 nanoseconds. Details: the section
"`time.Sleep(2)`: not two seconds" above. **Fix:** `time.Sleep(2 * time.Second)`. Neither Go itself nor `go vet` says
anything about it; the separate code checker [staticcheck](https://staticcheck.dev/docs/checks/#SA1004) (SA1004)
catches it.

**3. Seconds in a variable: `n * time.Second`.** `2 * time.Second` works, because 2 is a number with no type. What if
the number is in a variable? This example is not in the video; it is in the course folder (`duration/main.go`):

```go filename="duration/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	fmt.Println(2 * time.Second)

	n := 2
	fmt.Println(n * time.Second)
}
```

```console
$ go run duration/main.go
# command-line-arguments
duration/main.go:12:14: invalid operation: n * time.Second (mismatched types int and time.Duration)
```

Line 12, character 14: "invalid operation: `n * time.Second` (the types do not match: `int` and `time.Duration`)". `n`
is not an untyped constant; it is an `int` variable. And Go does not mix types on its own, exactly as in `suv-xato`.
**Fix:** convert `n` to the time type, like `float64(olma)` in [GO-0.03](/lab/youtube/go/go-0-03/en) (`durfix/main.go`):

```go filename="durfix/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	n := 2
	fmt.Println(time.Duration(n) * time.Second)
}
```

```console
$ go run durfix/main.go
2s
```

**4. Giving a constant a new value.** `const soniyalar = 60`, then `soniyalar = 61` → `cannot assign to soniyalar`
(the section "Constant: a number carved in stone" above). **Fix:** if the value has to change, create a variable, not
a constant: `soniyalar := 60`.

**5. The constant does not fit into the cell.** `const narx = 300`, then `var b int8 = narx` → `(overflows)` (the
section "Quick check" above). **Fix:** choose a bigger cell, for example `int`.

## Check yourself

Answer first, then open the answer.

**1.** What happens if, after `const soniyalar = 60`, we write `soniyalar = 61`?

<details>
<summary>Answer</summary>

A compile error (`cannot assign to soniyalar`), because a constant does not change. The program does not run at all.

</details>

**2.** If the brackets of `time.Sleep` hold `2`, how long does the program ask to wait?

<details>
<summary>Answer</summary>

Two nanoseconds, so it hardly waits at all. The untyped 2 lands in a `time.Duration` cell, and that cell counts
nanoseconds. For two seconds, write `2 * time.Second`.

</details>

**3.** If we add a new state in the middle of an `iota` list, what happens to the numbers saved in a file?

<details>
<summary>Answer</summary>

The numbers after it move by one, and the meaning of the saved numbers changes silently, with no error. For states that
are saved, write the numbers by hand or add new states only at the end.

</details>

**4.** What does this code print?

```go
const (
	Qizil = iota
	Sariq
	Yashil
)
fmt.Println(Qizil, Yashil)
```

<details>
<summary>Answer</summary>

`0 2`. `Qizil` ("red") is the first line: `iota` = 0. `Sariq` ("yellow") is 1, `Yashil` ("green") is 2.

</details>

**5.** From the previous lesson: `var x int8 = 127`, then `x++` and `fmt.Println(x)`. What is printed? Why is there no
compile error this time?

<details>
<summary>Answer</summary>

`-128`. Here 128 is not written in the code as a ready number: it is computed with a variable while the program runs,
so the `int8` cell silently wraps around (overflow). A constant, on the other hand, stands ready in the code, and Go
checks it in advance.

</details>
