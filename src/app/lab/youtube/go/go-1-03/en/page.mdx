## What you will learn

Multiply 100 twos together and you get a 31-digit number: 1 267 650 600 228 229 401 496 703 205 376.
The largest whole-number type in Go holds numbers of only up to 20 digits. If we write such a number in a Go
program, does the program compile? Today we will see the answer and four practical traps that follow from it.

**The one idea:** a constant written in the code without a type (an untyped constant) lives in the compiler as an
exact mathematical number. Whether it fits a type is checked only when it gets a type.

By the end of the lesson you will be able to:

- write a constant with `const` and explain the difference between an untyped and a typed constant;
- explain why `fmt.Println(big)`, `0.1 + 0.2 == 0.3`, `n * time.Second` and `time.Sleep(2)` give unexpected
  results, and fix them;
- write a list of statuses with `iota`;
- explain why numbers that are stored in a database must not be left to `iota`.

Three core new words today:

| Word | Plain meaning | Term |
|---|---|---|
| constant | a value fixed when the program is written, which never changes after that: `const` | constant |
| untyped constant | a constant with no type yet: like a mathematical number on paper, not yet put into a memory cell | untyped constant |
| `iota` | the position number inside a `const` group: it counts 0, 1, 2, … for you | iota |

Two helper words appear along the way: **bit shift** (`<<`, `>>`) and **default type** (the type Go picks by
itself). We explain both where they are needed.

## Bit shift: how much is `1 << 100`?

In [GO-1.02](/lab/youtube/go#go-1-02) we saw that a computer stores a number in bits. A bit is a lamp that is on or off,
1 or 0. An `int64` has 64 bits.

In decimal, adding a 0 to the end of a number makes it 10 times bigger: 7 → 70. In binary, adding a 0 to the end
makes the number **2 times** bigger. In Go the `<<` sign does this: `1 << 3` means "move the bits of 1 three steps
to the left and add 0s on the right". This operation is called a **bit shift**.

| Expression | In binary | In decimal |
|---|---|---|
| `1` | `1` | 1 |
| `1 << 1` | `10` | 2 |
| `1 << 2` | `100` | 4 |
| `1 << 3` | `1000` | 8 |
| `1 << 10` | `1` and ten `0`s | 1 024 |
| `1 << 100` | `1` and a hundred `0`s (101 bits) | 1 267 650 600 228 229 401 496 703 205 376 |

`>>` is the opposite, a shift to the right: the bits on the right are dropped, and each step divides the number
by 2. For example, `8 >> 1` = 4, `8 >> 3` = 1.

`1 << 100` needs 101 bits. The largest whole-number type in Go has 64 bits (`int64`, `uint64`).

## A constant: `const`

Some values in a program never change: 60 seconds in a minute, the number π. If we make them variables (labels),
someone may write a different value into them with `=` by accident. That is why Go has the **constant**: its value
is fixed when the program is written and never changes after that. It is written with the `const` keyword:
`const daqiqa = 60` (`daqiqa` means "minute").

Here is `big/main.go` from the course folder. This example is in Go's official rules (the Go spec), and the Go
Tour has a similar one:

```go filename="big/main.go" showLineNumbers
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(big >> 98)
}
```

| Line | Code | What it does |
|---|---|---|
| 1–3 | `package main`, `import "fmt"` | the familiar template |
| 5 | `const big = 1 << 100` | a constant named `big`; its value is 1 shifted left 100 times. It is written outside `main`, so the whole file can see it. A constant uses `=`, not `:=` |
| 7 | `func main() {` | the program starts here |
| 8 | `fmt.Println(big >> 98)` | shifts `big` right 98 times and prints the result |

Pause and think: does this program compile? If it does, what does it print?
**A)** a compile error: 101 bits do not fit into 64 · **B)** `4` · **C)** a different, wrong number because of
overflow

<details>
<summary>Answer</summary>

**B: `4`.** The program compiles and runs. `big` equals 2¹⁰⁰, and shifting right 98 times is the same as
dividing by 2⁹⁸: 2¹⁰⁰ / 2⁹⁸ = 2² = 4. If you chose "A", you thought a constant must also fit into an `int64`
cell. If you chose "C", you expected a silent wrap like `x++` in GO-1.02. A constant does not wrap.

</details>

```console
$ go run ./big
4
```

The big number never reached the program's memory. You can see this in the machine code the compiler produces.
The command below is long, so let's read it in parts:

- `go build -gcflags=-S` compiles the program and prints the machine code the compiler made (called
  **assembly**);
- `-o /dev/null` does not save the finished program file; we only want the listing;
- `2>&1 | grep -A1 'stmp_0 SRODATA'` keeps only the line with `stmp_0 SRODATA` and the one line after it from the
  long listing (`2>&1` sends the compiler's listing to `grep` too).

```console
$ go build -gcflags=-S -o /dev/null ./big 2>&1 | grep -A1 'stmp_0 SRODATA'
main..stmp_0 SRODATA static size=8
	0x0000 04 00 00 00 00 00 00 00                          ........
```

There is only one ready-made value for the `main` function: `size=8`, that is 8 bytes. The bytes on the second
line, `04 00 00 00 00 00 00 00`, are the number 4. The 101-bit number is nowhere. The compiler did the sum itself
and put only the result, `4`, into the program.

## An untyped constant: a number without a type

Why was there no error, even though `big` does not fit into 64 bits? Imagine a mathematician: on paper they can
write a number as long as they like. A memory cell has limited room: an `int64` has 64 bits, no more.

```text
on paper (the compiler):   big = 1 267 650 600 228 229 401 496 703 205 376   ← exact number, no type
in a memory cell (int64):  [ 64 bits ]   ← the largest is 9 223 372 036 854 775 807
```

`big` is still on paper: it has **no type**. Such a constant is called an **untyped constant**. Go's official
rules (the spec) say:

- numeric constants have **exact values** and do not overflow;
- every Go compiler must store integer constants with **at least 256 bits**;
- whether an untyped constant fits a type is checked only **when it gets a type**.

A constant gets a type in three ways, and we will see all three today: when it is written into a variable with a
type (`var f float64 = math.Pi`), when it is computed together with a value that has a type (`2 * time.Second`),
and when it is passed to a function (`fmt.Println(big)`).

In `big >> 98`, `big` never got a type: the compiler did the whole sum on paper and got `4`. Only `4` got a type,
when it was passed to `Println`, and `4` fits any type.

A constant that has a type is called a **typed constant**: `const x int8 = 127` or `int8(127)`. A typed constant
must fit its type **after every operation**. Now the error from the previous lesson makes sense:

| Expression | Type | When it is checked | Result |
|---|---|---|---|
| `1 << 100 >> 98` | untyped | when it gets a type, i.e. at the end | `4`, no error |
| `int8(127) + 1` | typed (`int8`) | after every operation: right after `+ 1` | 128 does not fit `int8` → compile error |
| `x++` (`x` is a variable) | an `int8` variable | the compiler does not check | wraps silently while the program runs → −128 |

## Where is the limit: 512 bits

The spec says "at least 256 bits". In practice, Go's own compiler stores integer constants with **up to 512
bits**. The number is written in the compiler's type-checker code: `const prec = 512`. Let's test it with two
programs. In `huge/main.go` we shift 1 left 511 times:

```go filename="huge/main.go" showLineNumbers
package main

import "fmt"

const huge = 1 << 511

func main() {
	fmt.Println(huge >> 510)
}
```

`edge/main.go` differs only in two numbers: `1 << 512` on line 5 and `huge >> 511` on line 8:

```go filename="edge/main.go" showLineNumbers
package main

import "fmt"

const huge = 1 << 512

func main() {
	fmt.Println(huge >> 511)
}
```

Guess: **A)** both print `2` · **B)** `huge` prints `2`, `edge` does not compile · **C)** neither compiles

<details>
<summary>Answer</summary>

**B.** `1 << 511` is a 512-bit number: it fits the limit, and 2⁵¹¹ / 2⁵¹⁰ = 2. `1 << 512` has 513 bits: the
compiler cannot store it. If you chose "A", you thought a constant can be infinitely large: both the rules and the
compiler have a limit.

</details>

```console
$ go run ./huge
2
```

```console
$ go run ./edge
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/edge
edge/main.go:5:16: constant shift overflow
```

Let's read the error. The first line (`# …/edge`) says which package was being compiled. The second line: the file
`edge/main.go`, line 5, column 16, which is exactly the `<<` sign. *constant shift overflow* means the shift made
the constant too big. This limit applies only to **whole-number** (integer) constants.

## math.Pi: 63 digits, but float64 keeps 16

The standard library (the packages that come with Go) uses this feature. In the `const.go` file of the `math`
package, π is written like this (shortened):

```go
// Mathematical constants.
const (
	E   = 2.71828182845904523536028747135266249775724709369995957496696763
	Pi  = 3.14159265358979323846264338327950288419716939937510582097494459
	Phi = 1.61803398874989484820458683436563811772030917980576286213544862
)
```

`Pi` is written with 63 digits. A `float64` (the floating-point type from [GO-0.03](/lab/youtube/go/go-0-03/en)) can keep
about 16 digits. There is one more floating-point type: `float32`, a 32-bit, less precise one. Because `Pi` is
untyped, whatever type you put it into, the exact value is rounded to the nearest number of that type.

This is `pi/main.go`:

```go filename="pi/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	var f32 float32 = math.Pi
	var f64 float64 = math.Pi
	fmt.Printf("float32: %.20f\n", f32)
	fmt.Printf("float64: %.20f\n", f64)
	fmt.Println("haqiqiy: 3.14159265358979323846...")
}
```

| Line | Code | What it does |
|---|---|---|
| 3–6 | `import ( "fmt" "math" )` | imports two packages; several packages go inside parentheses, one per line |
| 9 | `var f32 float32 = math.Pi` | a variable `f32` of type `float32`: this is where `Pi` gets its type |
| 10 | `var f64 float64 = math.Pi` | the same for `float64` |
| 11 | `fmt.Printf("float32: %.20f\n", f32)` | `Printf` prints text by a template: `f32` goes in place of `%.20f` with 20 digits after the point; `\n` starts a new line |
| 12 | `fmt.Printf("float64: %.20f\n", f64)` | the same for `f64` |
| 13 | `fmt.Println("haqiqiy: …")` | the real start of π for comparison, plain text (`haqiqiy` means "real") |

Guess: which line gets more digits of the real π right? **A)** both the same · **B)** the `float64` one ·
**C)** both get all 20 digits right

<details>
<summary>Answer</summary>

**B.** `float64` has 64 bits, `float32` has 32: fewer bits hold fewer digits. Not "C": `%.20f` *prints* 20
digits, but where the type could not keep the digits, you see what is left after rounding.

</details>

```console
$ go run ./pi
float32: 3.14159274101257324219
float64: 3.14159265358979311600
haqiqiy: 3.14159265358979323846...
```

| | Value | Correct digits |
|---|---|---|
| real π | 3.14159265358979323846… | — |
| `float32` | 3.141592**74**101257324219 | 7 (`3.141592`) |
| `float64` | 3.141592653589793**11**600 | 16 (`3.141592653589793`) |

The error is not in the constant: `math.Pi` is exact. Precision is lost only at the last step, when the value is
put into a type.

## Trap 1: the default type

Now the traps. The first one: what happens if we print `big` directly? This is `limit/main.go`:

```go filename="limit/main.go" showLineNumbers
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(big)
}
```

`fmt.Println` accepts a value of any type, but the value must have some type. If a constant has no type, Go picks
one itself. This is called the **default type**: `int` for an untyped whole-number constant, `float64` for an
untyped floating-point constant. On this computer `int` is 64 bits.

```console
$ go run ./limit
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/limit
limit/main.go:8:14: cannot use big (untyped int constant 1267650600228229401496703205376) as int value in argument to fmt.Println (overflows)
```

Line 8, column 14 (`big`): *cannot use big (untyped int constant …) as int value in argument to fmt.Println
(overflows)*: `big` (an untyped integer constant, with this value) cannot be passed to `fmt.Println` as an `int`
value, because it does not fit. The compiler even shows the number.

The same error happens with `math.MaxUint64`. This is the largest value of `uint64`, 2⁶⁴ − 1. In the `math`
package it is an untyped constant: `MaxUint64 = 1<<64 - 1`. This is `maxuint/main.go`:

```go filename="maxuint/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	fmt.Println(math.MaxUint64)
}
```

```console
$ go run ./maxuint
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/maxuint
maxuint/main.go:9:14: cannot use math.MaxUint64 (untyped int constant 18446744073709551615) as int value in argument to fmt.Println (overflows)
```

The default type is `int`, and `int` holds at most 2⁶³ − 1. The fix: state the type yourself (a conversion).
`maxfix/main.go`:

```go filename="maxfix/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	fmt.Println(uint64(math.MaxUint64))
}
```

```console
$ go run ./maxfix
18446744073709551615
```

`uint64(math.MaxUint64)`: now the constant got the type `uint64`, and the number fits.

`big`, however, fits no whole-number type. You can make it `float64(big)` (a `float64` keeps only about 16
digits; we will see it below in "Common mistakes"). If you need an exact big number while the program runs, Go has
the `math/big` package for that.

## Trap 2: 0.1 + 0.2 == 0.3

We add 0.2 to 0.1. Is the result equal to 0.3? This is `float/main.go`:

```go filename="float/main.go" showLineNumbers
package main

import "fmt"

const a, b = 0.1, 0.2

func main() {
	fmt.Println(a+b == 0.3)

	x, y := 0.1, 0.2
	fmt.Println(x+y == 0.3)
	fmt.Println(x + y)
}
```

| Line | Code | What it does |
|---|---|---|
| 5 | `const a, b = 0.1, 0.2` | two constants in one line: `a` = 0.1, `b` = 0.2 (untyped) |
| 8 | `fmt.Println(a+b == 0.3)` | is the sum of the constants equal to 0.3? `==` answers `true` or `false` |
| 10 | `x, y := 0.1, 0.2` | two variables in one line; by the default type both are `float64` |
| 11 | `fmt.Println(x+y == 0.3)` | the same question, with variables |
| 12 | `fmt.Println(x + y)` | prints the sum itself |

Guess what the first two lines print: **A)** `true`, `true` · **B)** `true`, `false` · **C)** `false`, `false`

<details>
<summary>Answer</summary>

**B: `true`, then `false`.** The compiler computes constants exactly: 0.1 + 0.2 is exactly 0.3. In `float64`
variables, 0.1 and 0.2 cannot be written exactly in binary, just as 1/3 = 0.333… goes on forever in decimal.
`float64` rounds after about 16 digits, and small errors add up. If you chose "A", you thought the computer stores
fractions exactly. If you chose "C", you thought constants are also computed in `float64`.

</details>

```console
$ go run ./float
true
false
0.30000000000000004
```

In one and the same program the answer is both `true` and `false`. The third line shows why: the sum in `float64`
is slightly bigger than 0.3.

## Trap 3: `n * time.Second`

The third trap is about time. Go has the `time` package for working with time. It has a separate type for a span
of time: `Duration`. Here it is from the file `time/time.go` (shortened):

```go
type Duration int64

const (
	Nanosecond  Duration = 1
	Microsecond          = 1000 * Nanosecond
	Millisecond          = 1000 * Microsecond
	Second               = 1000 * Millisecond
	Minute               = 60 * Second
	Hour                 = 60 * Minute
)
```

`type Duration int64` creates a new type: inside it is an `int64`, but it is **not** `int64`, it is a separate
type. Its unit is the nanosecond (a billionth of a second). `time.Second` is a constant of type `Duration`,
1 000 000 000 nanoseconds. `Println` prints a `Duration` with its unit: `2s` (2 seconds), `2ns` (2 nanoseconds).

A puzzle. This is `duration/main.go`, and it has one error:

```go filename="duration/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	fmt.Println(2 * time.Second)

	n := 2
	fmt.Println(n * time.Second)
}
```

| Line | Code | What it does |
|---|---|---|
| 9 | `fmt.Println(2 * time.Second)` | multiplies 2 by `time.Second` |
| 11 | `n := 2` | the variable `n`, value 2 |
| 12 | `fmt.Println(n * time.Second)` | multiplies `n` by `time.Second` |

Which line does not compile, and why? Pause and think. **A)** line 9 · **B)** line 12 · **C)** both work

<details>
<summary>Answer</summary>

**B: line 12.** The `2` on line 9 is an untyped constant: it silently takes the type `Duration`, and
`2 * time.Second` = `2s`. But `n` got the default type `int` on the line `n := 2`: it is now a variable of type
`int`. Go does not mix different types ([GO-0.03](/lab/youtube/go/go-0-03/en), [GO-1.02](/lab/youtube/go#go-1-02)), and `int` and
`Duration` are different types. If you chose "A", you thought `2` was an `int`. If you chose "C", you thought `n`
adapts like `2` does: but a variable's type is always fixed.

</details>

```console
$ go run ./duration
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/duration
duration/main.go:12:14: invalid operation: n * time.Second (mismatched types int and time.Duration)
```

Line 12, column 14 (`n`): *invalid operation: n * time.Second (mismatched types int and time.Duration)*: the types
do not match, `int` and `time.Duration`. Making `n` an `int64` does not help either: `Duration` is not `int64`, it
is a separate type.

The fix: convert `n` to `time.Duration`. The documentation of the `time` package has exactly this example.
`durfix/main.go`:

```go filename="durfix/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	n := 2
	fmt.Println(time.Duration(n) * time.Second)
}
```

- **Line 10:** `time.Duration(n)` makes a new value of type `Duration` from `n`; now both sides have the same type.

```console
$ go run ./durfix
2s
```

## Trap 4: `time.Sleep(2)`

The fourth trap is the other side of the same rule, and it is more dangerous. `time.Sleep(d)` pauses the program
for at least `d`. `d` is a `Duration`. This is `sleep2/main.go`:

```go filename="sleep2/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	start := time.Now()
	time.Sleep(2) // 2 sekund kutadi deb o'ylaysizmi?
	fmt.Println(time.Since(start) < time.Second)

	var d time.Duration = 2
	fmt.Println(d)
}
```

| Line | Code | What it does |
|---|---|---|
| 9 | `start := time.Now()` | stores the current time in `start` |
| 10 | `time.Sleep(2)` | pauses the program for "2". The comment asks: do you think it waits 2 seconds? |
| 11 | `fmt.Println(time.Since(start) < time.Second)` | `time.Since(start)` is how much time has passed since `start`; is it less than 1 second? |
| 13 | `var d time.Duration = 2` | the same value `Sleep` received: the untyped `2` takes the type `Duration` |
| 14 | `fmt.Println(d)` | prints `d` with its unit |

Guess: **A)** `false` and `2s` · **B)** `true` and `2ns` · **C)** a compile error

<details>
<summary>Answer</summary>

**B.** The untyped `2` silently becomes a `Duration`, and the unit of `Duration` is the nanosecond. The program
asks not for 2 seconds but for only 2 nanoseconds, so it hardly waits at all. That is why the time passed is less
than 1 second: `true`. If you chose "A", you thought `2` means seconds. Not "C": `2` is a constant, it fits
`Duration`, there is no error.

</details>

```console
$ go run ./sleep2
true
2ns
```

The compiler is silent. What about the programs that check code without running it? `go vet` comes with Go:

```console
$ go vet ./sleep2
```

`go vet` printed nothing: it found no problem. `staticcheck` is a code checker you install separately
(`go install honnef.co/go/tools/cmd/staticcheck@2026.2.1`; it goes into the `$(go env GOPATH)/bin/` folder):

```console
$ $(go env GOPATH)/bin/staticcheck ./sleep2
sleep2/main.go:10:13: sleeping for 2 nanoseconds is probably a bug; be explicit if it isn't (SA1004)
```

Line 10: *sleeping for 2 nanoseconds is probably a bug; be explicit if it isn't*. The fix: write the unit,
`time.Sleep(2 * time.Second)`.

## iota: a list of statuses

In an online shop an order has a status: unknown, new, paid, shipped. The program gives each status a number:
a number is easy to store and compare. You could write 0, 1, 2, 3 by hand. But Go can count for you: like the
ticket machine in a bank queue, it hands out each next number itself. This position number is called **`iota`**:
it says which declaration it is inside a `const ( … )` group, and it starts at **0** in every group.

This is `status/main.go`:

```go filename="status/main.go" showLineNumbers
package main

import "fmt"

type Status int

const (
	Unknown Status = iota
	New
	Paid
	Shipped
)

func main() {
	fmt.Println(Unknown, New, Paid, Shipped)

	var s Status
	fmt.Println(s == Unknown)
}
```

| Line | Code | What it does |
|---|---|---|
| 5 | `type Status int` | a new type: `Status`, with an `int` inside (just as `Duration` has an `int64` inside) |
| 7 | `const (` | declares several constants together, as a group in parentheses |
| 8 | `Unknown Status = iota` | declaration 0 of the group: `iota` = 0, `Unknown` = 0, type `Status` |
| 9–11 | `New`, `Paid`, `Shipped` | no expression written: Go repeats the previous expression **and type**, `Status = iota`, and `iota` grows by one on each line |
| 15 | `fmt.Println(Unknown, New, Paid, Shipped)` | prints all four values |
| 17 | `var s Status` | a `Status` variable with no value given: the zero value |
| 18 | `fmt.Println(s == Unknown)` | is `s` equal to `Unknown`? |

What Go actually sees:

| Line | Written | What Go sees | `iota` | Value |
|---|---|---|---|---|
| 8 | `Unknown Status = iota` | `Unknown Status = iota` | 0 | 0 |
| 9 | `New` | `New Status = iota` | 1 | 1 |
| 10 | `Paid` | `Paid Status = iota` | 2 | 2 |
| 11 | `Shipped` | `Shipped Status = iota` | 3 | 3 |

Why is 0 `Unknown`? Remember the zero value from [GO-1.02](/lab/youtube/go#go-1-02): a `Status` with no value given equals 0.
If 0 were `New`, every status someone forgot to set would look like a "new order". So 0 must not be a meaningful
status.

Guess: **A)** `0 1 2 3` and `true` · **B)** `1 2 3 4` and `false` · **C)** `Unknown New Paid Shipped` and `true`

<details>
<summary>Answer</summary>

**A.** `iota` starts at 0, and the zero value of `s` is 0, that is `Unknown`. If you chose "B", you thought
counting starts at 1. Not "C": `Status` is a plain number, `Println` does not know its name and prints only the
number.

</details>

```console
$ go run ./status
0 1 2 3
true
```

Remember one thing: Go has no separate **enum** type (a type that accepts only the listed values). `Status` is just
a type based on `int`, so a `Status` of 42 is legal too (we will see it below in "Common mistakes").

You can also combine `iota` with a bit shift. The example from the "Effective Go" guide: kilobyte, megabyte,
gigabyte and terabyte come from one formula. This is `sizes/main.go`:

```go filename="sizes/main.go" showLineNumbers
package main

import "fmt"

const (
	_  = iota
	KB = 1 << (10 * iota)
	MB
	GB
	TB
)

func main() {
	fmt.Println(KB, MB, GB, TB)
}
```

| Line | Code | `iota` | Value |
|---|---|---|---|
| 6 | `_ = iota` | 0 | thrown away: `_` means "this value is not needed" |
| 7 | `KB = 1 << (10 * iota)` | 1 | `1 << 10` = 1 024 |
| 8 | `MB` (the same expression is repeated) | 2 | `1 << 20` = 1 048 576 |
| 9 | `GB` | 3 | `1 << 30` = 1 073 741 824 |
| 10 | `TB` | 4 | `1 << 40` = 1 099 511 627 776 |

```console
$ go run ./sizes
1024 1048576 1073741824 1099511627776
```

To be exact, these are KiB, MiB, GiB, TiB (powers of 1024, not of 1000).

## Bonus: iota and the database, a silent bug

And a bonus: the danger of `iota` on live servers (production). Imagine `Status` is written to a database as a
number. A database is where a program keeps data for a long time (a table on disk). In the first version (v1),
`Paid` = 2, and thousands of orders are stored in the database with `2`.

One day someone adds a `Cancelled` status after `New`. This is `bug/main.go`:

```go filename="bug/main.go" showLineNumbers
package main

import "fmt"

type Status int

// v2
const (
	Unknown Status = iota
	New
	Cancelled
	Paid
	Shipped
)

func main() {
	saved := Status(2) // bazada saqlangan: v1'da bu Paid edi
	fmt.Println("to'langanmi?", saved == Paid)
	fmt.Println("bekor qilinganmi?", saved == Cancelled)
}
```

- **Lines 7–14:** the second version (v2): `Cancelled` was added between `New` and `Paid`.
- **Line 17:** `saved := Status(2)` is the number read from the database, converted to the type `Status`. In v1 it
  was `Paid`. (The comment says: "stored in the database: in v1 this was Paid".)
- **Lines 18–19:** is this order paid (`to'langanmi?`)? Is it cancelled (`bekor qilinganmi?`)?

Guess: **A)** `true`, `false` · **B)** `false`, `true` · **C)** a compile error

<details>
<summary>Answer</summary>

**B.** After `Cancelled` is added, every value after it moves by one:

| Status | v1 | v2 |
|---|---|---|
| `Unknown` | 0 | 0 |
| `New` | 1 | 1 |
| `Cancelled` | — | **2** |
| `Paid` | **2** | 3 |
| `Shipped` | 3 | 4 |

The `2` in the database is now `Cancelled`. Not "C": the code is correct, there is no error, and that is exactly
why this bug is dangerous.

</details>

```console
$ go run ./bug
to'langanmi? false
bekor qilinganmi? true
```

The paid orders in the database (`2`) now look cancelled, and the shipped ones (`3`) look as if they are still only
paid. And no error appears.

The rule: a number that has gone out to a database or over the network **never changes and is never reused**. So
for such values write the numbers by hand, or store the status name in the database instead of a number. This is
`fix/main.go`:

```go filename="fix/main.go" showLineNumbers
package main

import "fmt"

type Status int

// bazada saqlanadigan qiymatlar: har biri qo'lda yoziladi va hech qachon o'zgarmaydi
const (
	Unknown   Status = 0
	New       Status = 1
	Paid      Status = 2
	Shipped   Status = 3
	Cancelled Status = 4 // yangi qiymat oxiriga
)

func main() {
	saved := Status(2)
	fmt.Println("to'langanmi?", saved == Paid)
}
```

- **Lines 9–13:** every value is written by hand; the new `Cancelled` = 4 is added at the end, and the old ones
  stay where they were. (The comment says: "values stored in the database: each one is written by hand and never
  changes".)

```console
$ go run ./fix
to'langanmi? true
```

If you delete a value, never give its number to another one: in an `iota` list, leave a `_` in its place. In
Protocol Buffers (Google's format for sending data between programs), every enum value also gets its number by
hand, and the guide strongly recommends never reusing deleted numbers. Its style guide also recommends making the
first value, 0, `_UNSPECIFIED`, just like our `Unknown`.

## Common mistakes

**1. Adding a new value in the middle of an `iota` list.** This is the most dangerous mistake of the lesson; we saw
it in "Bonus: iota and the database": no error appears, but every old number in the database changes its meaning.
**Fix:** write the numbers of stored values by hand (`fix/main.go`) or store the status name.

**2. Passing a big untyped constant straight to `Println`.** `fmt.Println(big)` and `fmt.Println(math.MaxUint64)`:
we saw this in "Trap 1: the default type": the default type is `int`, and the number does not fit. **Fix:** state
the type: `uint64(math.MaxUint64)`.

**3. Converting `big` to `uint64`.** (This example is not in the course folder; it was run separately.)

```go
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(uint64(big))
}
```

```console
$ go run uint64big/main.go
# command-line-arguments
uint64big/main.go:8:21: constant 1267650600228229401496703205376 overflows uint64
```

Line 8, column 21: *constant … overflows uint64*: the constant does not fit `uint64`. A 101-bit number fits no
whole-number type. **Fix:** `float64(big)` (only about 16 digits are kept exactly), or the `math/big` package if
you need the exact number. (This example is not in the course folder either.)

```go
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(float64(big))
}
```

```console
$ go run katta/main.go
1.2676506002282294e+30
```

`1.2676506002282294e+30` means "1.2676506002282294 × 10³⁰". `Println` printed the number in a short form: 17 digits
instead of 31. A `float64` keeps about 16 digits, so the last digits of big whole numbers can be lost.

**4. Thinking `time.Sleep(2)` means 2 seconds.** We saw it in "Trap 4": the untyped `2` becomes a `Duration`, that
is 2 nanoseconds. Both the compiler and `go vet` are silent. **Fix:** always write the unit:
`time.Sleep(2 * time.Second)`.

**5. Multiplying an `int64` variable by `time.Second`.** You may think it works because `Duration` has an `int64`
inside. (Not in the course folder.)

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	var n int64 = 2
	fmt.Println(n * time.Second)
}
```

```console
$ go run int64dur/main.go
# command-line-arguments
int64dur/main.go:10:14: invalid operation: n * time.Second (mismatched types int64 and time.Duration)
```

"Mismatched types, `int64` and `time.Duration`". `type Duration int64` creates a new, separate type.
**Fix:** `time.Duration(n) * time.Second`.

**6. Comparing `float64` values with `==`.** We saw it in "Trap 2": `x+y == 0.3` is `false`. **Fix:** don't check
for equality; check whether the difference is very small. `math.Abs` gives a number without its sign, and `1e-9`
is 0.000000001. (Not in the course folder.)

```go
package main

import (
	"fmt"
	"math"
)

func main() {
	x, y := 0.1, 0.2
	fmt.Println(math.Abs(x+y-0.3) < 1e-9)
}
```

```console
$ go run floatcmp/main.go
true
```

**7. Thinking that `iota` gives you a real enum in Go.** You may think `Status` accepts only the four values in the
list. (Not in the course folder.)

```go
package main

import "fmt"

type Status int

const (
	Unknown Status = iota
	New
	Paid
	Shipped
)

func main() {
	var s Status = 42
	fmt.Println(s, s == Unknown)
}
```

```console
$ go run status42/main.go
42 false
```

No error: `Status` is a plain type based on `int`, and `42` fits it. **Fix:** check yourself that a value coming
from a database or the network is between `Unknown` and `Shipped`.

**8. Trying to change a constant.** (Not in the course folder.)

```go
package main

import "fmt"

const daqiqa = 60

func main() {
	daqiqa = 61
	fmt.Println(daqiqa)
}
```

```console
$ go run ozgarmas/main.go
# command-line-arguments
ozgarmas/main.go:8:2: cannot assign to daqiqa (neither addressable nor a map index expression)
```

Line 8, column 2: *cannot assign to daqiqa*: you cannot give `daqiqa` a new value. The text in parentheses
("neither addressable nor a map index expression": it has no address and is not a map element) is the
compiler's technical note: a constant is not a cell in
memory, so nothing can be written into it. **Fix:** if the value must change, use a variable, not a constant:
`daqiqa := 60`.

## Check yourself

Answer first, then open the answer.

**1.** What does this program print? **A)** `8` · **B)** `128` · **C)** a compile error

```go
package main

import "fmt"

const c = 1 << 10

func main() {
	fmt.Println(c >> 7)
}
```

<details>
<summary>Answer</summary>

**A: `8`.** `1 << 10` = 1024 = 2¹⁰. Shifting right 7 times divides by 2⁷: 2¹⁰ / 2⁷ = 2³ = 8.

```console
$ go run savol1/main.go
8
```

</details>

**2.** What does this program print? **A)** `1 2 3` · **B)** `1 2 4` · **C)** `0 1 2`

```go
package main

import "fmt"

const (
	_ = iota
	A
	B
	_
	C
)

func main() {
	fmt.Println(A, B, C)
}
```

<details>
<summary>Answer</summary>

**B: `1 2 4`.** `iota` grows with every declaration, including the ones thrown away with `_`: `_` = 0, `A` = 1,
`B` = 2, `_` = 3, `C` = 4.

```console
$ go run savol2/main.go
1 2 4
```

</details>

**3.** Why does `const big = 1 << 100` compile without errors, but `fmt.Println(big)` does not?

<details>
<summary>Answer</summary>

`big` is an untyped constant: the compiler keeps it as an exact number of at least 256 bits, and whether it fits a
type is checked only when it gets a type. When passed to `Println`, `big` gets the default type `int`, and a
101-bit number does not fit `int`.

</details>

**4.** How long does `time.Sleep(5)` pause the program?

<details>
<summary>Answer</summary>

At least 5 **nanoseconds**, so it hardly pauses at all. The untyped `5` becomes a `Duration`, and the unit of
`Duration` is the nanosecond. For 5 seconds: `time.Sleep(5 * time.Second)`.

</details>

**5.** From [GO-1.02](/lab/youtube/go#go-1-02): `big := 300`, then `fmt.Println(int8(big))`. What is printed?

<details>
<summary>Answer</summary>

`44`. A conversion between whole-number types keeps only the lowest 8 bits: 300 = 256 + 44. This is
`convert/main.go` in the GO-1.02 folder; its second line converts `int8(200)` through a variable:

```console
$ go run ./convert
44
-56
```

Note: here `big` is a **variable**. If you write `fmt.Println(int8(300))` with a constant directly, the compiler
gives the error `constant 300 overflows int8`: a constant must fit its type when it gets one.

</details>

<details>

`homework/medium/main.go`. `Read Perm = 1 << iota`, then `Write`, `Exec`: the values are `001`, `010`, `100`. Each
flag is a separate bit, so they combine with `|` (`Read | Write` = `011`) and are checked with `&` (bitwise AND):

🟠 **Hard:** why does `1.5 * time.Second` not compile, while `1500 * time.Millisecond` works?

<details>
<summary>Answer</summary>

`time.Second` is a `Duration` with an `int64` inside. The untyped `1.5` must first become a `Duration`, that is a
whole number, but 1.5 cannot become a whole number exactly, and a constant is never rounded: the compiler refuses.
This line is commented out in `homework/hard/main.go`; we ran it separately:


"1.5 (an untyped floating-point constant) would be cut off when converted to `int64`". The right ways:
`1500 * time.Millisecond` or `time.Second * 3 / 2` (first 3 s, then whole-number division by 2).

```console

1.5s
```

</details>

🔴 **Guru:** find where `iota` is used in the `time` package and explain why `Month` starts at 1.

<details>
<summary>Answer</summary>

In `time/time.go`: `January Month = 1 + iota`, so months go from 1 to 12, the way people write them, and
`Sunday Weekday = iota`, so weekdays start at 0. `homework/guru/main.go`:

```console
$ go run ./homework/guru
January 1
Sunday 0
%!Month(0)
```

`time.Month` and `time.Weekday` know how to print their names, which is why `January` and `Sunday` were printed. A
`time.Month` with no value given equals 0, but there is no month 0: Go shows it as `%!Month(0)`. So here the Go
team chose "the number should equal the number people use" over "the zero value should be meaningful". Both are
deliberate choices; what matters is to make the choice knowingly.

</details>
