## Nimani oʻrganasiz

100 ta ikkini bir-biriga koʻpaytirsak, 31 xonali son chiqadi: 1 267 650 600 228 229 401 496 703 205 376.
Go'dagi eng katta butun son turi esa atigi 20 xonali songacha sigʻdiradi. Bunday sonni Go dasturiga yozsak,
dastur kompilyatsiya boʻladimi? Bugun javobni va undan kelib chiqadigan toʻrtta amaliy tuzoqni koʻramiz.

**Bitta gʻoya:** kodga yozilgan turi belgilanmagan konstanta (untyped konstanta) kompilyatorda aniq matematik son
boʻlib yashaydi. U turga sigʻadimi yoki yoʻqmi, bu faqat u tur olganda tekshiriladi.

Dars oxirida siz:

- `const` bilan konstanta yoza olasiz va untyped hamda typed konstanta farqini tushuntira olasiz;
- `fmt.Println(big)`, `0.1 + 0.2 == 0.3`, `n * time.Second` va `time.Sleep(2)` nega kutilmagan natija berishini
  bilasiz va ularni tuzata olasiz;
- `iota` bilan holatlar roʻyxatini yoza olasiz;
- bazaga yoziladigan raqamlarni nega `iota` ga ishonib qoʻymaslik kerakligini bilasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| konstanta | dastur yozilganda belgilanadigan va keyin oʻzgarmaydigan qiymat: `const` | constant |
| untyped konstanta | turi belgilanmagan konstanta: qogʻozdagi matematik son kabi, xotira katagiga hali joylanmagan | untyped constant |
| `iota` | `const` guruhidagi navbat raqami: 0, 1, 2, … ni oʻzi sanaydi | iota |

Yoʻl-yoʻlakay ikkita yordamchi soʻz ham uchraydi: **bit siljitish** (`<<`, `>>`) va **default tur** (Go oʻzi
tanlaydigan tur). Ikkalasini kerak boʻlgan joyda tushuntiramiz.

## Bit siljitish: `1 << 100` qancha?

[GO-1.02](/lab/youtube/go#go-1-02) da koʻrdik: kompyuter sonni bitlarda saqlaydi. Bit — yoqilgan yoki oʻchgan chiroq,
1 yoki 0. `int64` da 64 ta bit bor.

Oʻnlik sanoqda sonning oxiriga 0 qoʻshsak, son 10 barobar oshadi: 7 → 70. Ikkilik sanoqda oxiriga 0 qoʻshsak,
son **2 barobar** oshadi. Go'da buni `<<` belgisi qiladi: `1 << 3` — «1 ning bitlarini 3 qadam chapga sur,
oʻng tomondan 0 lar qoʻsh». Bu amal **bit siljitish** (inglizcha **bit shift**) deyiladi.

| Ifoda | Ikkilikda | Oʻnlikda |
|---|---|---|
| `1` | `1` | 1 |
| `1 << 1` | `10` | 2 |
| `1 << 2` | `100` | 4 |
| `1 << 3` | `1000` | 8 |
| `1 << 10` | `1` va 10 ta `0` | 1 024 |
| `1 << 100` | `1` va 100 ta `0` (101 bit) | 1 267 650 600 228 229 401 496 703 205 376 |

`>>` esa teskarisi, oʻngga siljitish: oʻngdagi bitlar tashlab yuboriladi, har qadam sonni 2 ga boʻladi.
Masalan, `8 >> 1` = 4, `8 >> 3` = 1.

`1 << 100` uchun 101 ta bit kerak. Go'dagi eng katta butun tur esa 64 bit (`int64`, `uint64`).

## Konstanta: `const`

Dasturdagi baʼzi qiymatlar hech qachon oʻzgarmaydi: bir daqiqadagi 60 sekund, π soni. Ularni oʻzgaruvchi
(yorliq) qilib qoʻysak, kimdir tasodifan `=` bilan boshqa qiymat yozib qoʻyishi mumkin. Shuning uchun Go'da
**konstanta** (inglizcha **constant**) bor: qiymati dastur yozilganda belgilanadi va keyin oʻzgarmaydi. U
`const` kalit soʻzi bilan yoziladi: `const daqiqa = 60`.

Mana kurs papkasidagi `big/main.go`. Bu misol Go'ning rasmiy qoidalarida (Go spec) bor, Go Tour'da esa
oʻxshashi:

```go filename="big/main.go" showLineNumbers
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(big >> 98)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1–3 | `package main`, `import "fmt"` | tanish qolip |
| 5 | `const big = 1 << 100` | `big` nomli konstanta, qiymati 1 ni 100 marta chapga siljitilgani. `main` dan tashqarida yozilgan, shuning uchun butun faylda koʻrinadi. Konstantada `:=` emas, `=` yoziladi |
| 7 | `func main() {` | dastur shu yerdan boshlanadi |
| 8 | `fmt.Println(big >> 98)` | `big` ni 98 marta oʻngga siljitib, natijani chiqaradi |

Pauza qilib oʻylab koʻring: bu dastur kompilyatsiya boʻladimi? Boʻlsa, nima chiqaradi?
**A)** kompilyatsiya xatosi: 101 bit 64 bitga sigʻmaydi · **B)** `4` · **C)** overflow sababli boshqa, notoʻgʻri son

<details>
<summary>Javob</summary>

**B: `4`.** Dastur kompilyatsiya boʻladi va ishlaydi. `big` 2¹⁰⁰ ga teng, 98 marta oʻngga siljitish 2⁹⁸ ga
boʻlish bilan barobar: 2¹⁰⁰ / 2⁹⁸ = 2² = 4. «A» ni tanlagan boʻlsangiz, konstanta ham `int64` katagiga
joylashishi kerak deb oʻylagansiz. «C» ni tanlagan boʻlsangiz, GO-1.02 dagi `x++` kabi jim aylanish boʻladi
deb oʻylagansiz. Konstantada esa aylanish yoʻq.

</details>

```console
$ go run ./big
4
```

Katta son dastur xotirasiga hech qachon tushmadi. Buni kompilyator yasagan mashina kodida koʻrish mumkin.
Quyidagi buyruq uzun, uni qismlab oʻqiymiz:

- `go build -gcflags=-S` — dasturni kompilyatsiya qiladi va kompilyator yasagan mashina kodini (inglizcha
  **assembly**) chiqaradi;
- `-o /dev/null` — tayyor dastur faylini saqlamaydi, bizga faqat roʻyxat kerak;
- `2>&1 | grep -A1 'stmp_0 SRODATA'` — uzun roʻyxatdan faqat `stmp_0 SRODATA` boʻlgan qatorni va undan
  keyingi bitta qatorni qoldiradi (`2>&1` kompilyatorning bu roʻyxatini ham `grep` ga yuboradi).

```console
$ go build -gcflags=-S -o /dev/null ./big 2>&1 | grep -A1 'stmp_0 SRODATA'
main..stmp_0 SRODATA static size=8
	0x0000 04 00 00 00 00 00 00 00                          ........
```

`main` funksiyasi uchun faqat bitta tayyor qiymat bor: `size=8`, yaʼni 8 bayt. Ikkinchi qatordagi baytlar
`04 00 00 00 00 00 00 00` — bu 4 soni. 101 bitlik son hech qayerda yoʻq. Kompilyator hisobni oʻzi qildi va
dasturga faqat natijani, `4` ni qoʻydi.

## Untyped konstanta: turi yoʻq son

Nega `big` 64 bitga sigʻmasa ham xato chiqmadi? Tasavvur qiling: matematik qogʻozga istalgancha uzun son yoza
oladi. Xotira katagida esa joy cheklangan: `int64` da 64 ta bit, undan koʻp emas.

```text
qogʻozda (kompilyator):   big = 1 267 650 600 228 229 401 496 703 205 376   ← aniq son, tur yoʻq
xotira katagida (int64):  [ 64 ta bit ]   ← eng kattasi 9 223 372 036 854 775 807
```

`big` hali qogʻozda turibdi: uning **turi yoʻq**. Bunday konstanta **untyped konstanta** (turi belgilanmagan
konstanta) deyiladi. Go'ning rasmiy qoidalari (spec) shunday deydi:

- raqamli konstantalar **aniq qiymatga** ega va overflow boʻlmaydi;
- har bir Go kompilyatori butun konstantalarni **kamida 256 bit** bilan saqlashi shart;
- untyped konstanta turga sigʻadimi, bu faqat u **tur olganda** tekshiriladi.

Tur olish uch xil yoʻl bilan boʻladi, uchalasini bugun koʻramiz: turi aniq oʻzgaruvchiga yozilganda
(`var f float64 = math.Pi`), turi bor qiymat bilan birga hisoblanganda (`2 * time.Second`) va funksiyaga
berilganda (`fmt.Println(big)`).

`big >> 98` da `big` hech qachon tur olmadi: kompilyator butun hisobni qogʻozda qilib, `4` ni oldi. Faqat `4`
`Println` ga berilganda tur oldi, va `4` istalgan turga sigʻadi.

Turi bor konstanta esa **typed konstanta** deyiladi: `const x int8 = 127` yoki `int8(127)`. Typed konstanta
**har bir amaldan keyin** oʻz turiga sigʻishi kerak. Endi oldingi darsdagi xato tushunarli:

| Ifoda | Turi | Qachon tekshiriladi | Natija |
|---|---|---|---|
| `1 << 100 >> 98` | untyped | tur olganda, yaʼni oxirida | `4`, xato yoʻq |
| `int8(127) + 1` | typed (`int8`) | har amaldan keyin: `+ 1` dan keyin darhol | 128 `int8` ga sigʻmaydi → kompilyatsiya xatosi |
| `x++` (`x` oʻzgaruvchi) | `int8` oʻzgaruvchi | kompilyator tekshirmaydi | dastur ishlayotganda jim aylanadi → −128 |

## Chegara qayerda: 512 bit

Spec «kamida 256 bit» deydi. Amalda Go'ning oʻz kompilyatori butun konstantalarni **512 bitgacha** saqlaydi. Bu
raqam kompilyatorning tur tekshiruvchi kodida yozilgan: `const prec = 512`. Ikki dastur bilan tekshiramiz.
`huge/main.go` da 1 ni 511 marta chapga siljitamiz:

```go filename="huge/main.go" showLineNumbers
package main

import "fmt"

const huge = 1 << 511

func main() {
	fmt.Println(huge >> 510)
}
```

`edge/main.go` dan faqat ikki son farq qiladi: 5-qatorda `1 << 512`, 8-qatorda `huge >> 511`:

```go filename="edge/main.go" showLineNumbers
package main

import "fmt"

const huge = 1 << 512

func main() {
	fmt.Println(huge >> 511)
}
```

Taxmin qiling: **A)** ikkalasi ham `2` chiqaradi · **B)** `huge` `2` chiqaradi, `edge` kompilyatsiya boʻlmaydi ·
**C)** ikkalasi ham kompilyatsiya boʻlmaydi

<details>
<summary>Javob</summary>

**B.** `1 << 511` 512 bitlik son: u chegaraga sigʻadi, va 2⁵¹¹ / 2⁵¹⁰ = 2. `1 << 512` esa 513 bit: kompilyator
uni saqlay olmaydi. «A» ni tanlagan boʻlsangiz, konstanta cheksiz katta boʻla oladi deb oʻylagansiz: qoidada
ham, kompilyatorda ham chegara bor.

</details>

```console
$ go run ./huge
2
```

```console
$ go run ./edge
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/edge
edge/main.go:5:16: constant shift overflow
```

Xatoni oʻqiymiz. Birinchi qator (`# …/edge`) qaysi paket kompilyatsiya qilinganini aytadi. Ikkinchi qator:
`edge/main.go` fayli, 5-qator, 16-belgi — aynan `<<` belgisi. *constant shift overflow* — «konstantani
siljitishda toʻlib ketish». Bu chegara faqat **butun** konstantalarga tegishli.

## math.Pi: 63 ta raqam, float64 esa 16 ta

Standart kutubxona (Go bilan birga keladigan paketlar) bu imkoniyatdan foydalanadi. `math` paketining
`const.go` faylida π shunday yozilgan (qisqartirilgan):

```go
// Mathematical constants.
const (
	E   = 2.71828182845904523536028747135266249775724709369995957496696763
	Pi  = 3.14159265358979323846264338327950288419716939937510582097494459
	Phi = 1.61803398874989484820458683436563811772030917980576286213544862
)
```

`Pi` 63 ta raqam bilan yozilgan. `float64` esa ([GO-0.03](/lab/youtube/go/go-0-03) dagi kasrli son turi) taxminan
16 ta raqamni saqlay oladi. Yana bir kasrli tur bor: `float32` — 32 bitlik, kamroq aniq kasrli son. `Pi`
untyped boʻlgani uchun, uni qaysi turga yozsangiz, aniq qiymat oʻsha turga eng yaqin songa yaxlitlanadi.

Bu `pi/main.go`:

```go filename="pi/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	var f32 float32 = math.Pi
	var f64 float64 = math.Pi
	fmt.Printf("float32: %.20f\n", f32)
	fmt.Printf("float64: %.20f\n", f64)
	fmt.Println("haqiqiy: 3.14159265358979323846...")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 3–6 | `import ( "fmt" "math" )` | ikki paketni ulaydi; bir nechta paket qavs ichida, har biri alohida qatorda yoziladi |
| 9 | `var f32 float32 = math.Pi` | `float32` turidagi `f32` oʻzgaruvchisi: `Pi` shu yerda tur oladi |
| 10 | `var f64 float64 = math.Pi` | xuddi shu, `float64` uchun |
| 11 | `fmt.Printf("float32: %.20f\n", f32)` | `Printf` matnni qolip boʻyicha chiqaradi: `%.20f` oʻrniga `f32` nuqtadan keyin 20 ta raqam bilan qoʻyiladi; `\n` — yangi qatorga oʻtish |
| 12 | `fmt.Printf("float64: %.20f\n", f64)` | xuddi shu, `f64` uchun |
| 13 | `fmt.Println("haqiqiy: …")` | solishtirish uchun π ning haqiqiy boshlanishi, oddiy matn |

Taxmin qiling: qaysi qatorda haqiqiy π dan koʻproq raqam toʻgʻri chiqadi? **A)** ikkalasida bir xil ·
**B)** `float64` da · **C)** ikkalasida ham 20 ta raqam toʻgʻri

<details>
<summary>Javob</summary>

**B.** `float64` ga 64 bit, `float32` ga 32 bit ajratilgan: kamroq bitda kamroq raqam sigʻadi. «C» emas:
`%.20f` 20 ta raqam *chiqaradi*, lekin tur saqlay olmagan raqamlar oʻrnida yaxlitlash «qoldigʻi» turadi.

</details>

```console
$ go run ./pi
float32: 3.14159274101257324219
float64: 3.14159265358979311600
haqiqiy: 3.14159265358979323846...
```

| | Qiymat | Toʻgʻri raqamlar |
|---|---|---|
| haqiqiy π | 3.14159265358979323846… | — |
| `float32` | 3.141592**74**101257324219 | 7 ta (`3.141592`) |
| `float64` | 3.141592653589793**11**600 | 16 ta (`3.141592653589793`) |

Xato konstantada emas: `math.Pi` aniq. Aniqlik faqat oxirgi qadamda, qiymat turga yozilganda yoʻqoladi.

## 1-tuzoq: default tur

Endi tuzoqlar. Birinchisi: `big` ni toʻgʻridan-toʻgʻri ekranga chiqarsak nima boʻladi? Bu `limit/main.go`:

```go filename="limit/main.go" showLineNumbers
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(big)
}
```

`fmt.Println` istalgan turdagi qiymatni qabul qiladi, lekin qiymatning qandaydir turi boʻlishi shart. Konstanta
turi yoʻq boʻlsa, Go oʻzi tur tanlaydi. Bu **default tur** (inglizcha **default type**) deyiladi: untyped butun
konstanta uchun `int`, untyped kasrli konstanta uchun `float64`. Bu kompyuterda `int` 64 bit.

```console
$ go run ./limit
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/limit
limit/main.go:8:14: cannot use big (untyped int constant 1267650600228229401496703205376) as int value in argument to fmt.Println (overflows)
```

8-qator, 14-belgi (`big`): *cannot use big (untyped int constant …) as int value in argument to fmt.Println
(overflows)* — «`big` ni (turi belgilanmagan butun konstanta, qiymati …) `fmt.Println` ga `int` qiymat sifatida
berib boʻlmaydi (sigʻmaydi)». Kompilyator sonning oʻzini ham koʻrsatdi.

Xuddi shu xato `math.MaxUint64` bilan ham boʻladi. Bu `uint64` ning eng katta qiymati, 2⁶⁴ − 1. `math`
paketida u untyped konstanta: `MaxUint64 = 1<<64 - 1`. Bu `maxuint/main.go`:

```go filename="maxuint/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	fmt.Println(math.MaxUint64)
}
```

```console
$ go run ./maxuint
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/maxuint
maxuint/main.go:9:14: cannot use math.MaxUint64 (untyped int constant 18446744073709551615) as int value in argument to fmt.Println (overflows)
```

Default tur `int`, `int` esa eng koʻpi bilan 2⁶³ − 1 ni sigʻdiradi. Yechim: turni oʻzingiz aniq aytish
(konversiya). `maxfix/main.go`:

```go filename="maxfix/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	fmt.Println(uint64(math.MaxUint64))
}
```

```console
$ go run ./maxfix
18446744073709551615
```

`uint64(math.MaxUint64)` — konstanta endi `uint64` turini oldi, va son unga sigʻadi.

`big` esa hech bir butun turga sigʻmaydi. Uni `float64(big)` qilish mumkin (`float64` faqat taxminan 16 raqamni saqlaydi; pastda
«Koʻp uchraydigan xatolar» da koʻramiz). Dastur ishlayotganda aniq katta son kerak boʻlsa, Go'da buning uchun
`math/big` paketi bor.

## 2-tuzoq: 0.1 + 0.2 == 0.3

0.1 ga 0.2 ni qoʻshamiz. Natija 0.3 ga tengmi? Bu `float/main.go`:

```go filename="float/main.go" showLineNumbers
package main

import "fmt"

const a, b = 0.1, 0.2

func main() {
	fmt.Println(a+b == 0.3)

	x, y := 0.1, 0.2
	fmt.Println(x+y == 0.3)
	fmt.Println(x + y)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 5 | `const a, b = 0.1, 0.2` | bitta qatorda ikki konstanta: `a` = 0.1, `b` = 0.2 (untyped) |
| 8 | `fmt.Println(a+b == 0.3)` | konstantalar yigʻindisi 0.3 ga tengmi? `==` javobi `true` yoki `false` |
| 10 | `x, y := 0.1, 0.2` | bitta qatorda ikki oʻzgaruvchi; default tur boʻyicha ikkalasi `float64` |
| 11 | `fmt.Println(x+y == 0.3)` | xuddi shu savol, oʻzgaruvchilar bilan |
| 12 | `fmt.Println(x + y)` | yigʻindining oʻzini chiqaradi |

Taxmin qiling, birinchi ikki qatorda nima chiqadi? **A)** `true`, `true` · **B)** `true`, `false` ·
**C)** `false`, `false`

<details>
<summary>Javob</summary>

**B: `true`, keyin `false`.** Konstantalarni kompilyator aniq hisoblaydi: 0.1 + 0.2 aynan 0.3. `float64`
oʻzgaruvchilarda esa 0.1 va 0.2 ikkilik sanoqda aniq yozilmaydi. Xuddi oʻnlik sanoqda 1/3 = 0.333… cheksiz
davom etgani kabi. `float64` taxminan 16 raqamdan keyin yaxlitlaydi, va kichik xatolar yigʻiladi. «A» ni
tanlagan boʻlsangiz, kompyuter kasrlarni aniq saqlaydi deb oʻylagansiz. «C» ni tanlagan boʻlsangiz,
konstantalar ham `float64` da hisoblanadi deb oʻylagansiz.

</details>

```console
$ go run ./float
true
false
0.30000000000000004
```

Bitta dasturning oʻzida javob ham `true`, ham `false`. Uchinchi qator sababini koʻrsatadi: `float64` dagi yigʻindi
0.3 dan biroz katta.

## 3-tuzoq: `n * time.Second`

Uchinchi tuzoq vaqt bilan bogʻliq. Go'da vaqt bilan ishlash uchun `time` paketi bor. Unda vaqt oraligʻi uchun
alohida tur bor — `Duration` («davomiylik»). Mana `time/time.go` fayldan (qisqartirilgan):

```go
type Duration int64

const (
	Nanosecond  Duration = 1
	Microsecond          = 1000 * Nanosecond
	Millisecond          = 1000 * Microsecond
	Second               = 1000 * Millisecond
	Minute               = 60 * Second
	Hour                 = 60 * Minute
)
```

`type Duration int64` — yangi tur yaratadi: uning ichi `int64`, lekin u `int64` **emas**, alohida tur. Hisob
birligi — nanosekund (sekundning milliarddan biri). `time.Second` — `Duration` turidagi konstanta,
1 000 000 000 nanosekund. `Println` `Duration` ni birligi bilan chiqaradi: `2s` (2 sekund), `2ns`
(2 nanosekund).

Topishmoq. Bu `duration/main.go`, unda bitta xato bor:

```go filename="duration/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	fmt.Println(2 * time.Second)

	n := 2
	fmt.Println(n * time.Second)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 9 | `fmt.Println(2 * time.Second)` | 2 ni `time.Second` ga koʻpaytiradi |
| 11 | `n := 2` | `n` oʻzgaruvchisi, qiymati 2 |
| 12 | `fmt.Println(n * time.Second)` | `n` ni `time.Second` ga koʻpaytiradi |

Qaysi qator kompilyatsiya boʻlmaydi va nega? Pauza qilib oʻylab koʻring. **A)** 9-qator · **B)** 12-qator ·
**C)** ikkalasi ham ishlaydi

<details>
<summary>Javob</summary>

**B: 12-qator.** 9-qatordagi `2` untyped konstanta: u jimgina `Duration` turini oladi va `2 * time.Second` =
`2s`. `n` esa `n := 2` qatorida default tur `int` ni oldi: u endi `int` turidagi oʻzgaruvchi. Go turli
turlarni aralashtirmaydi ([GO-0.03](/lab/youtube/go/go-0-03), [GO-1.02](/lab/youtube/go#go-1-02)), `int` bilan `Duration` esa
turli turlar. «A» ni tanlagan boʻlsangiz, `2` ni `int` deb oʻylagansiz. «C» ni tanlagan boʻlsangiz, `n` ham
`2` kabi moslashadi deb oʻylagansiz: oʻzgaruvchining turi esa doim aniq.

</details>

```console
$ go run ./duration
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/duration
duration/main.go:12:14: invalid operation: n * time.Second (mismatched types int and time.Duration)
```

12-qator, 14-belgi (`n`): *invalid operation: n * time.Second (mismatched types int and time.Duration)* —
«notoʻgʻri amal: turlar mos emas, `int` va `time.Duration`». `n` ni `int64` qilsangiz ham ishlamaydi:
`Duration` `int64` emas, alohida tur.

Yechim: `n` ni `time.Duration` ga konversiya qilish. `time` paketining hujjatida ham aynan shu misol bor.
`durfix/main.go`:

```go filename="durfix/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	n := 2
	fmt.Println(time.Duration(n) * time.Second)
}
```

- **10-qator:** `time.Duration(n)` — `n` dan `Duration` turidagi yangi qiymat yasaydi, endi ikki tomon bir xil
  turda.

```console
$ go run ./durfix
2s
```

## 4-tuzoq: `time.Sleep(2)`

Toʻrtinchi tuzoq shu qoidaning teskari tomoni, va u xavfliroq. `time.Sleep(d)` dasturni kamida `d` vaqt
toʻxtatib turadi. `d` — `Duration`. Bu `sleep2/main.go`:

```go filename="sleep2/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	start := time.Now()
	time.Sleep(2) // 2 sekund kutadi deb o'ylaysizmi?
	fmt.Println(time.Since(start) < time.Second)

	var d time.Duration = 2
	fmt.Println(d)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 9 | `start := time.Now()` | hozirgi vaqtni `start` ga yozadi |
| 10 | `time.Sleep(2)` | dasturni «2» vaqt toʻxtatadi. Izohdagi savol: 2 sekundmi? |
| 11 | `fmt.Println(time.Since(start) < time.Second)` | `time.Since(start)` — `start` dan beri qancha vaqt oʻtdi; u 1 sekunddan kichikmi? |
| 13 | `var d time.Duration = 2` | xuddi `Sleep` olgan qiymat: untyped `2` `Duration` turini oladi |
| 14 | `fmt.Println(d)` | `d` ni birligi bilan chiqaradi |

Taxmin qiling: **A)** `false` va `2s` · **B)** `true` va `2ns` · **C)** kompilyatsiya xatosi

<details>
<summary>Javob</summary>

**B.** Untyped `2` jimgina `Duration` ga aylanadi, `Duration` ning birligi esa nanosekund. Dastur 2 sekund emas,
atigi 2 nanosekund soʻraydi, yaʼni deyarli umuman kutmaydi. Shuning uchun oʻtgan vaqt 1 sekunddan kichik:
`true`. «A» ni tanlagan boʻlsangiz, `2` ni sekund deb oʻylagansiz. «C» emas: `2` konstanta, u `Duration` ga
sigʻadi, xato yoʻq.

</details>

```console
$ go run ./sleep2
true
2ns
```

Kompilyator jim. Kodni ishga tushirmasdan tekshiradigan dasturlar-chi? `go vet` Go bilan birga keladi:

```console
$ go vet ./sleep2
```

`go vet` hech narsa chiqarmadi: u xato topmadi. `staticcheck` — alohida oʻrnatiladigan tekshiruvchi dastur
(`go install honnef.co/go/tools/cmd/staticcheck@2026.2.1`, `$(go env GOPATH)/bin/` papkasiga tushadi):

```console

```

10-qator: *sleeping for 2 nanoseconds is probably a bug; be explicit if it isn't* — «2 nanosekund uxlash,
ehtimol, xato; ataylab boʻlsa, buni aniq yozing». Tuzatish: birlikni yozing — `time.Sleep(2 * time.Second)`.

## iota: holatlar roʻyxati

Internet doʻkonda buyurtmaning holati bor: nomaʼlum, yangi, toʻlangan, joʻnatilgan. Dastur har bir holatga
bitta son beradi: sonni saqlash va solishtirish oson. 0, 1, 2, 3 ni qoʻlda yozish mumkin. Lekin Go buni oʻzi
sanay oladi: bankdagi navbat apparati kabi, u har keyingi raqamni oʻzi beradi. Bu navbat raqami **`iota`**
deyiladi: u `const ( … )` guruhida nechanchi eʼlon ekanini bildiradi, har bir guruhda **0 dan** boshlanadi.

Bu `status/main.go`:

```go filename="status/main.go" showLineNumbers
package main

import "fmt"

type Status int

const (
	Unknown Status = iota
	New
	Paid
	Shipped
)

func main() {
	fmt.Println(Unknown, New, Paid, Shipped)

	var s Status
	fmt.Println(s == Unknown)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 5 | `type Status int` | yangi tur: `Status`, ichi `int` (xuddi `Duration` ichi `int64` boʻlgani kabi) |
| 7 | `const (` | bir nechta konstantani qavs ichida, guruh qilib eʼlon qiladi |
| 8 | `Unknown Status = iota` | guruhning 0-eʼloni: `iota` = 0, `Unknown` = 0, turi `Status` |
| 9–11 | `New`, `Paid`, `Shipped` | ifoda yozilmagan: Go oldingi ifodani **va turni** takrorlaydi, `Status = iota`, `iota` esa har qatorda bittaga oshadi |
| 15 | `fmt.Println(Unknown, New, Paid, Shipped)` | toʻrtala qiymatni chiqaradi |
| 17 | `var s Status` | qiymat berilmagan `Status` oʻzgaruvchisi: zero value |
| 18 | `fmt.Println(s == Unknown)` | `s` `Unknown` ga tengmi? |

Go aslida nimani koʻradi:

| Qator | Yozilgan | Go koʻradigan | `iota` | Qiymat |
|---|---|---|---|---|
| 8 | `Unknown Status = iota` | `Unknown Status = iota` | 0 | 0 |
| 9 | `New` | `New Status = iota` | 1 | 1 |
| 10 | `Paid` | `Paid Status = iota` | 2 | 2 |
| 11 | `Shipped` | `Shipped Status = iota` | 3 | 3 |

Nega 0 — `Unknown`? [GO-1.02](/lab/youtube/go#go-1-02) dagi zero value'ni eslang: qiymat berilmagan `Status` 0 ga teng.
Agar 0 `New` boʻlsa, unutib qoldirilgan har bir holat «yangi buyurtma» boʻlib koʻrinardi. Shuning uchun 0
maʼnoli holat boʻlmasligi kerak.

Taxmin qiling: **A)** `0 1 2 3` va `true` · **B)** `1 2 3 4` va `false` · **C)** `Unknown New Paid Shipped`
va `true`

<details>
<summary>Javob</summary>

**A.** `iota` 0 dan boshlanadi, va `s` ning zero value'si 0, yaʼni `Unknown`. «B» ni tanlagan boʻlsangiz,
sanash 1 dan boshlanadi deb oʻylagansiz. «C» emas: `Status` — oddiy son, `Println` uning nomini bilmaydi, faqat
sonni chiqaradi.

</details>

```console
$ go run ./status
0 1 2 3
true
```

Bir narsani unutmang: Go'da alohida **enum** turi (faqat sanab oʻtilgan qiymatlarni qabul qiladigan tur) yoʻq.
`Status` bor-yoʻgʻi `int` asosidagi tur, shuning uchun `Status` 42 ham qonuniy (pastda, «Koʻp uchraydigan
xatolar» da koʻramiz).

`iota` ni bit siljitish bilan ham birlashtirsa boʻladi. «Effective Go» qoʻllanmasidagi misol: kilobayt,
megabayt, gigabayt va terabayt bitta formuladan chiqadi. Bu `sizes/main.go`:

```go filename="sizes/main.go" showLineNumbers
package main

import "fmt"

const (
	_  = iota
	KB = 1 << (10 * iota)
	MB
	GB
	TB
)

func main() {
	fmt.Println(KB, MB, GB, TB)
}
```

| Qator | Kod | `iota` | Qiymat |
|---|---|---|---|
| 6 | `_ = iota` | 0 | tashlab yuboriladi: `_` — «bu qiymat kerak emas» |
| 7 | `KB = 1 << (10 * iota)` | 1 | `1 << 10` = 1 024 |
| 8 | `MB` (shu ifoda takrorlanadi) | 2 | `1 << 20` = 1 048 576 |
| 9 | `GB` | 3 | `1 << 30` = 1 073 741 824 |
| 10 | `TB` | 4 | `1 << 40` = 1 099 511 627 776 |

```console
$ go run ./sizes
1024 1048576 1073741824 1099511627776
```

Aniqroq aytsak, bular KiB, MiB, GiB, TiB (1000 emas, 1024 ning darajalari).

## Bonus: iota va baza — jim xato

Va bonus, `iota` ning ishchi serverlardagi (production) xavfi. Faraz qiling, `Status` bazaga son sifatida
yoziladi. Baza — dastur maʼlumotni uzoq saqlaydigan joy (diskdagi jadval). Birinchi versiyada (v1)
`Paid` = 2, va bazada minglab buyurtma `2` bilan saqlangan.

Bir kuni kimdir `Cancelled` («bekor qilingan») holatini `New` dan keyin qoʻshadi. Bu `bug/main.go`:

```go filename="bug/main.go" showLineNumbers
package main

import "fmt"

type Status int

// v2
const (
	Unknown Status = iota
	New
	Cancelled
	Paid
	Shipped
)

func main() {
	saved := Status(2) // bazada saqlangan: v1'da bu Paid edi
	fmt.Println("to'langanmi?", saved == Paid)
	fmt.Println("bekor qilinganmi?", saved == Cancelled)
}
```

- **7–14-qatorlar:** ikkinchi versiya (v2): `Cancelled` `New` va `Paid` orasiga qoʻshildi.
- **17-qator:** `saved := Status(2)` — bazadan oʻqilgan son, `Status` turiga aylantirildi. v1 da bu `Paid` edi.
- **18–19-qatorlar:** bu buyurtma toʻlanganmi? Bekor qilinganmi?

Taxmin qiling: **A)** `true`, `false` · **B)** `false`, `true` · **C)** kompilyatsiya xatosi

<details>
<summary>Javob</summary>

**B.** `Cancelled` qoʻshilgandan keyin undan keyingi hamma qiymat bittaga suriladi:

| Holat | v1 | v2 |
|---|---|---|
| `Unknown` | 0 | 0 |
| `New` | 1 | 1 |
| `Cancelled` | — | **2** |
| `Paid` | **2** | 3 |
| `Shipped` | 3 | 4 |

Bazadagi `2` endi `Cancelled`. «C» emas: kod toʻgʻri yozilgan, xato chiqmaydi — shuning uchun bu xato xavfli.

</details>

```console
$ go run ./bug
to'langanmi? false
bekor qilinganmi? true
```

Bazadagi toʻlangan buyurtmalar (`2`) bekor qilingan boʻlib koʻrinadi, joʻnatilganlari (`3`) esa hali
toʻlangan holatda turadi. Va hech qanday xato chiqmaydi.

Qoida: bazaga yoki tarmoqqa chiqqan raqam **hech qachon oʻzgarmaydi va qayta ishlatilmaydi**. Shuning uchun
bunday qiymatlarga raqamni qoʻlda yozing, yoki bazaga son emas, holat nomini yozing. Bu `fix/main.go`:

```go filename="fix/main.go" showLineNumbers
package main

import "fmt"

type Status int

// bazada saqlanadigan qiymatlar: har biri qo'lda yoziladi va hech qachon o'zgarmaydi
const (
	Unknown   Status = 0
	New       Status = 1
	Paid      Status = 2
	Shipped   Status = 3
	Cancelled Status = 4 // yangi qiymat oxiriga
)

func main() {
	saved := Status(2)
	fmt.Println("to'langanmi?", saved == Paid)
}
```

- **9–13-qatorlar:** har bir qiymat qoʻlda yozilgan; yangi `Cancelled` = 4 oxiriga qoʻshildi, eskilari oʻz
  joyida.

```console
$ go run ./fix
to'langanmi? true
```

Biror qiymatni oʻchirsangiz, uning raqamini boshqasiga bermang: `iota` roʻyxatida oʻrniga `_` qoldiring.
Protocol Buffers'da ham (Google'ning dasturlar orasida maʼlumot yuborish formati) har bir enum qiymatiga raqam
qoʻlda yoziladi, va qoʻllanma oʻchirilgan raqamlarni qayta ishlatmaslikni qatʼiy tavsiya qiladi. Uning uslub
qoʻllanmasi birinchi, 0-qiymatni ham `_UNSPECIFIED` («belgilanmagan») qilishni tavsiya qiladi — xuddi bizning
`Unknown` kabi.

## Koʻp uchraydigan xatolar

**1. `iota` roʻyxatining oʻrtasiga yangi qiymat qoʻshish.** Bu darsning eng xavfli xatosi, «Bonus: iota va

<details>
<summary>Javob</summary>

Kamida 5 **nanosekund**, yaʼni deyarli umuman toʻxtatmaydi. Untyped `5` `Duration` ga aylanadi, `Duration` ning
birligi esa nanosekund. 5 sekund uchun: `time.Sleep(5 * time.Second)`.

</details>

**5.** [GO-1.02](/lab/youtube/go#go-1-02) dan: `big := 300`, keyin `fmt.Println(int8(big))`. Nima chiqadi?

<details>
<summary>Javob</summary>

`44`. Butun sonlar orasidagi konversiya faqat pastki 8 bitni oladi: 300 = 256 + 44. Bu GO-1.02 papkasidagi
`convert/main.go`; uning ikkinchi qatori `int8(200)` ni oʻzgaruvchi orqali aylantiradi:

```console
$ go run ./convert
44
-56
```

Diqqat: bu yerda `big` — **oʻzgaruvchi**. `fmt.Println(int8(300))` ni esa toʻgʻridan-toʻgʻri konstanta bilan
yozsangiz, kompilyator `constant 300 overflows int8` xatosini beradi: konstanta tur olganda unga sigʻishi shart.

</details>

🟢 **Oson:** hafta kunlari uchun `iota` bilan konstantalar yozing.

<details>
<summary>Javob</summary>

`homework/easy/main.go`. `Monday Weekday = iota + 1` bilan dushanba 1 dan boshlanadi, 0 esa «kun tanlanmagan»
boʻlib qoladi. Shunda qiymat berilmagan `Weekday` (zero value) tasodifan dushanba boʻlib qolmaydi. Standart
`time.Weekday` boshqacha: u yerda `Sunday Weekday = iota`, yaʼni yakshanba 0.

```console
$ go run ./homework/easy

0
```

</details>

🟡 **Oʻrta:** `iota` bilan bir nechta bit flag (har biri alohida bit boʻlgan belgi) yozib, ularni bitli YOKI
(`|`) bilan birlashtiring.

<details>
<summary>Javob</summary>

`homework/medium/main.go`. `Read Perm = 1 << iota` keyin `Write`, `Exec`: qiymatlar `001`, `010`, `100`. Har bir
flag alohida bit, shuning uchun ular `|` bilan birlashadi (`Read | Write` = `011`) va `&` (bitli VA) bilan
tekshiriladi: `p&Write != 0` — «`Write` biti yoqilganmi?». `&^` bitni oʻchiradi. `%03b` — sonni ikkilikda,
3 ta raqam bilan chiqaradi. `io/fs.FileMode` ham xuddi shunday qurilgan.

```console
$ go run ./homework/medium
011
true
false
001
```

</details>

🟠 **Qiyin:** nega `1.5 * time.Second` kompilyatsiya boʻlmaydi, `1500 * time.Millisecond` esa ishlaydi?

<details>
<summary>Javob</summary>

`time.Second` — `Duration`, ichi `int64`. Untyped `1.5` avval `Duration` ga, yaʼni butun songa aylanishi kerak,
lekin 1.5 butun songa aniq aylanmaydi, konstanta esa yaxlitlanmaydi: kompilyator rad etadi. Bu qator
`homework/hard/main.go` da izohga olingan; biz uni alohida ishga tushirdik:

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	fmt.Println(1.5 * time.Second)
}
```

```console
$ go run yarim/main.go
# command-line-arguments
yarim/main.go:9:14: 1.5 (untyped float constant) truncated to int64
```

«1.5 (turi belgilanmagan kasrli konstanta) `int64` ga aylantirilganda kesilib qoladi». Toʻgʻri yoʻllar:
`1500 * time.Millisecond` yoki `time.Second * 3 / 2` (avval 3 s, keyin 2 ga butun boʻlish).

```console
$ go run ./homework/hard
1.5s
1.5s
```

</details>

🔴 **Guru:** `time` paketida `iota` qayerlarda ishlatilganini toping va nega `Month` 1 dan boshlanishini
tushuntiring.

<details>
<summary>Javob</summary>

`time/time.go` da: `January Month = 1 + iota` — oylar 1 dan 12 gacha, odamlar yozganidek, va `Sunday Weekday =
iota` — hafta kunlari 0 dan. `homework/guru/main.go`:

```console
$ go run ./homework/guru
January 1
Sunday 0
%!Month(0)
```

`time.Month` va `time.Weekday` oʻz nomini chiqarishni biladi, shuning uchun `January`, `Sunday` chiqdi. Qiymat
berilmagan `time.Month` 0 ga teng, lekin 0-oy yoʻq: Go buni `%!Month(0)` deb koʻrsatadi. Yaʼni Go jamoasi bu
yerda «zero value maʼnoli boʻlsin» qoidasidan koʻra «raqam odamlar ishlatadigan raqamga teng boʻlsin» ni tanlagan.
Ikkalasi ham ongli tanlov; muhimi — tanlovni bilib qilish.

</details>
