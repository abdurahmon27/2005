## Что вы узнаете

Оплаченные заказы хранятся в базе со `status = 2`. Кто-то добавил в середину списка статусов в коде на Go один новый
статус. Компилятор молчит. Как на следующий день будут выглядеть эти заказы? Ответ — во второй половине урока, и он
следует из одного правила констант в Go.

**Одна идея:** `const` в Go — значение, известное во время компиляции, а константа без указанного типа
(**нетипизированная константа**, untyped constant) берёт тип из места, где её используют: поэтому `time.Sleep(2)`
просит две наносекунды. А `iota` берёт значение из позиции объявления в блоке `const`, поэтому статус, добавленный в
середину списка, тихо меняет смысл чисел в базе.

К концу урока вы сможете:

- отличать `const` в Go от `const` в JavaScript: какое выражение может быть константой, а какое даёт `is not
  constant`;
- объяснить, почему `time.Sleep(2)` — это не 2 секунды и не 2 мс, а 2 наносекунды, и правильно записывать время через
  `2 * time.Second` и `time.Duration(n) * time.Second`;
- писать список статусов с `iota` и добавлять новый статус, не ломая числа в базе.

Три главных новых слова сегодня:

| Слово | Простой смысл | Английский термин |
|---|---|---|
| `const` | имя, значение которого известно во время компиляции: только число, строка или bool | constant |
| нетипизированная константа | константа без указанного типа: берёт тип из места использования | untyped constant |
| `iota` | порядковый номер объявления в блоке `const`, с 0 | iota |

Встретятся и два вспомогательных слова: **`time.Duration`** (промежуток времени, число наносекунд) и **новый тип**
(`type Duration int64`: в основе `int64`, но это отдельный тип). Кроме того, есть два выражения — **тип по умолчанию**
(default type) и **типизированная константа** (typed constant); их объясняем в разделе о нетипизированных константах.

Сначала один вопрос из прошлого урока:

```go
var x int8 = 127
x += 3
fmt.Println(x)
```

Что выведется? **A)** `130` · **B)** `127` · **C)** `-126` · **D)** программа остановится

<details>
<summary>Ответ</summary>

**C: `-126`.** `x` — переменная, её значение вычисляется во время работы программы. После 127 `int8` переходит
границу и тихо переполняется: 127 → −128 → −127 → −126. Если вы выбрали «`130`», вы думали, что число безгранично,
как в Python. Если «`127`» — что Go удерживает число на границе. Если «программа остановится» — что переполнение
вызывает panic: не вызывает.

```go filename="eslash/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var x int8 = 127
	x += 3 // 127 → −128 → −127 → −126: jim aylanadi (02-dars)
	fmt.Println(x)
}
```

```console
$ go run eslash/main.go
-126
```

</details>

Переменная переполняется тихо. А константу Go проверяет во время компиляции: `var x int8 = 128` вообще не
компилировался. В том сообщении об ошибке было слово *untyped int constant*. Сегодня разбираем именно его.

## `const`: не тот `const`, что в JavaScript

Сегодня три понятия Go, и каждое рядом с тем, что вы уже знаете: `const` ↔ `const` в JS, нетипизированная
константа ↔ `time.Sleep(2)`, `iota` ↔ `enum` в TypeScript. Начнём с первого.

В JavaScript `const` замораживает только **имя**: его нельзя заново привязать к другому значению. Само значение
вычисляется во время работы программы, например из `Date.now()`. И содержимое объекта по-прежнему меняется:

```js filename="anchors/const.js"
// JS const faqat nomni qayta bogʻlashni taqiqlaydi
const cfg = { port: 80 };
cfg.port = 81;            // ✅ obyekt ichi oʻzgaradi
console.log(cfg.port);    // 81
const start = Date.now(); // ✅ qiymat ishlash paytida olinadi
console.log(typeof start); // number
```

```console
$ node anchors/const.js
81
number
```

В Python констант нет вообще. Имя заглавными буквами — просто соглашение (PEP 8), и перезапись тоже работает:

```python filename="anchors/const.py"
# Python'da konstanta faqat kelishuv (katta harfli nom)
MAX_RETRIES = 3
MAX_RETRIES = 4  # ✅ ishlaydi
print(MAX_RETRIES)  # 4
```

```console
$ python3 anchors/const.py
4
```

В Go `const` — другое. Его значение обязано быть известно **во время компиляции**, и это может быть только число
(включая rune), строка или bool. В константном выражении участвуют только константы и операторы, но не обычный
вызов функции. (Некоторые встроенные функции, например `len("abc")`, `min` и `max`, с константами — исключение.)

Польза: ошибки вроде `var x int8 = 128` из прошлого урока ловятся до запуска программы.

| Язык | Что замораживает `const` | Когда известно значение | Кто проверяет |
|---|---|---|---|
| JavaScript | имя (нельзя привязать заново) | во время работы (`Date.now()`) | runtime |
| Python | ничего: имя заглавными — соглашение | во время работы | никто |
| PHP | имя и значение | во время компиляции | PHP, до запуска файла |
| Go | имя и значение | во время компиляции | компилятор |

Теперь три строки. Десять мегабайт в байтах, квадратный корень из двух и текущее время (как `Date.now()` в JS):

```go
const maxSize = 10 * 1024 * 1024
const root2 = math.Sqrt(2)
const start = time.Now()
```

Какие из них скомпилируются? **A)** все три · **B)** `maxSize` и `root2` · **C)** только `maxSize` ·
**D)** ни одна

<details>
<summary>Ответ</summary>

**C: только `maxSize`.** В `10 * 1024 * 1024` только константы и оператор `*`, компилятор вычисляет это сам.
Результат `math.Sqrt(2)` никогда не меняется, но это вызов функции: Go вычисляет его во время работы. А `time.Now()`
каждый раз возвращает другое значение. Если вы выбрали «все три», вы думали, что `const` в Go такой же, как в JS.
Если «`maxSize` и `root2`» — что «результат не меняется, значит константа»: Go смотрит не на результат, а на само
выражение.

</details>

Полная программа, `notconst/main.go`:

```go filename="notconst/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
	"time"
)

func main() {
	const maxSize = 10 * 1024 * 1024 // faqat konstantalar va operatorlar: kompilyator hisoblaydi
	const root2 = math.Sqrt(2)       // ataylab xato: funksiya chaqiruvi — natija ishlash paytida
	const start = time.Now()         // ataylab xato: time.Now() faqat ishlash paytida maʼlum
	fmt.Println(maxSize, root2, start)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–7 | `import ( "fmt" "math" "time" )` | подключает пакеты `fmt` (вывод), `math` (математические функции) и `time` (время) |
| 10 | `const maxSize = 10 * 1024 * 1024` | константное выражение: 10 485 760, вычисляет компилятор ✅ |
| 11 | `const root2 = math.Sqrt(2)` | вызов функции: результат во время работы ❌ |
| 12 | `const start = time.Now()` | текущее время: известно только во время работы ❌ |
| 13 | `fmt.Println(maxSize, root2, start)` | должна была вывести все три |

```console
$ go run notconst/main.go
# command-line-arguments
notconst/main.go:11:16: math.Sqrt(2) (value of type float64) is not constant
notconst/main.go:12:16: time.Now() (value of struct type time.Time) is not constant
```

Две строки, в обеих *is not constant* — «не константа». `notconst/main.go:11:16` — строка 11, столбец 16, то есть
место, где стоит `math.Sqrt(2)`. В скобках Go называет его тип: *value of type float64* — «значение типа `float64`».
А `time.Now()` возвращает структуру (struct) `time.Time`. В строке 10 ошибки нет.

`const` в PHP устроен так же: если написать функцию `time()`, файл вообще не запустится.

```php filename="anchors/const.php"

```

```console

```

(Полный путь в выводе сокращён до `…`: он зависит от папки на вашем компьютере.) `echo` в строке 4 тоже не

используют обычную переменную: в Go `start := time.Now()`.

## Нетипизированная константа: тип из места использования

Из урока о типах вы знаете: переменную `int` нельзя положить в `float64`, неявного преобразования в Go нет.
`untyped-xato/main.go`:

```go filename="untyped-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	n := 100          // oʻzgaruvchi: turi int
	var b float64 = n // ataylab xato: int oʻzgaruvchini float64 ga yashirin konversiya yoʻq
	fmt.Println(b)
}
```

```console
$ go run untyped-xato/main.go
# command-line-arguments
untyped-xato/main.go:7:18: cannot use n (variable of type int) as float64 value in variable declaration
```

*cannot use n (variable of type int) as float64 value* — «нельзя использовать переменную `n` типа `int` как значение
`float64`». `:=` в строке 6 дал `n` тип `int`, и он не меняется.

А у константы без указанного типа **типа пока нет**. Это называется **нетипизированной константой** (untyped
constant). Она берёт тип из места, где её используют: в одной строке `int8`, в другой `float64`. `untyped/main.go`:

```go filename="untyped/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const yuz = 100       // untyped constant: turi hali yoʻq
	var a int8 = yuz      // bu yerda int8 boʻldi
	var b float64 = yuz   // bu yerda float64 boʻldi
	m := yuz              // tur aytilmagan joy → default type: int (butun son konstantasi uchun)
	fmt.Println(a/8, b/8) // int8: kasr tashlanadi, float64: qoladi
	fmt.Printf("%T\n", m) // int
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `const yuz = 100` | `yuz` («сто», 100) — нетипизированная константа: тип не указан |
| 7 | `var a int8 = yuz` | здесь `yuz` становится `int8` |
| 8 | `var b float64 = yuz` | здесь — `float64`: ошибки из `untyped-xato` нет |
| 9 | `m := yuz` | `:=` тип не называет: целочисленная константа получает **тип по умолчанию** (default type), то есть `int` |
| 10 | `fmt.Println(a/8, b/8)` | при делении `int8` дробная часть отбрасывается (12), в `float64` остаётся (12.5) |
| 11 | `fmt.Printf("%T\n", m)` | `%T` выводит тип значения; `\n` — новая строка |

```console
$ go run untyped/main.go
12 12.5
int
```

Одна `yuz`, три разных типа:

| Где использована | Тип `yuz` в этом месте | Почему |
|---|---|---|
| `var a int8 = yuz` | `int8` | тип переменной указан |
| `var b float64 = yuz` | `float64` | тип переменной указан |
| `m := yuz` | `int` | тип не назван → тип по умолчанию |

**Тип по умолчанию** (default type) — тип, который Go выбирает там, где тип не назван (`:=`, `fmt.Println`): для
целого числа `int`, для дробного `float64`, для `'a'` — `rune`. Противоположность нетипизированной константы —
**типизированная константа** (typed constant): константа с указанным типом (`const b int = 3`). Она строга, как
переменная; это увидим в разделе «Проверка».

В TypeScript есть похожая вещь. Тип `const a = 3` — не `number`, а `3` (literal type, литеральный тип). Если
передать его в `let`, тип расширится до `number`:

```ts filename="anchors/literal.ts"
// TS: const a = 3 → literal type 3; let b = a → number ga kengayadi ("widening")
const a = 3
let b = a
const ok: 3 = a
const bad: 3 = b // TS2322: Type 'number' is not assignable to type '3'.
```

```console
$ tsc --strict anchors/literal.ts
anchors/literal.ts(5,7): error TS2322: Type 'number' is not assignable to type '3'.
```

Строка 4 прошла: тип `a` всё ещё `3`. В строке 5 `b` уже `number`. Нетипизированная константа и тип по умолчанию в
Go — та же идея. Разница: типы TypeScript стираются после компиляции, а в Go выбранный тип сохраняется и во время
работы программы.

## `time.Sleep(2)`: секунды, миллисекунды или наносекунды?

Сильнее всего это правило чувствуется при работе со временем. В Python `time.sleep(2)` ждёт две **секунды**:

```python filename="anchors/sleep.py"
import time

t = time.monotonic()
time.sleep(2)  # soniya
print(round(time.monotonic() - t, 1))  # 2.0
```

```console
$ python3 anchors/sleep.py
2.0
```

А в `setTimeout` в Node `2` — это две **миллисекунды**:

```js filename="anchors/sleep.js"
const t = Date.now();
setTimeout(() => console.log(Date.now() - t), 2); // millisekund → 2
```

```console
$ node anchors/sleep.js
2
```

В Go параметр `time.Sleep` — `time.Duration`: `func Sleep(d Duration)`. **`time.Duration`** считает промежуток
времени в **наносекундах** (миллиардных долях секунды).

### `type Duration int64`: новый тип, а не псевдоним

В пакете `time` он объявлен как `type Duration int64`. `type Ms = number` в TypeScript — всего лишь псевдоним
(alias): в него проходит любой `number`.

```ts filename="anchors/alias.ts"
// TS: type Ms = number — faqat taxallus (alias): istalgan number oʻtadi
type Ms = number
function sleep(ms: Ms) {}
const n: number = 2
sleep(n) // ✅ xato yoʻq. Go'da type Duration int64 esa alohida tur: int oʻtmaydi
```

```console
$ tsc --strict anchors/alias.ts
```

`tsc` ничего не вывел: ошибки нет. А `type` в Go создаёт **новый тип**. В основе `Duration` лежит `int64`, но
переменную `int` в `Duration` положить нельзя. `duration-type/main.go`:

```go filename="duration-type/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	// time paketida: type Duration int64 — asosi int64, lekin alohida tur
	var n int = 2
	var d time.Duration = n // ataylab xato: int → time.Duration yashirin oʻtmaydi
	fmt.Println(d)
}
```

```console
$ go run duration-type/main.go
# command-line-arguments
duration-type/main.go:11:24: cannot use n (variable of type int) as time.Duration value in variable declaration
```

Строка 11, столбец 24: `n`. Сообщение такое же, как в `untyped-xato`, только вместо `float64` — `time.Duration`.

| | TypeScript `type Ms = number` | Go `type Duration int64` |
|---|---|---|
| Что это | псевдоним (alias) | новый тип |
| Передать обычное число | `sleep(n)` ✅ | `var d time.Duration = n` ❌ |
| Во время работы | типа нет | тип есть |

### Предскажите

Теперь в Go в скобках `time.Sleep` стоит `2`:

```go
time.Sleep(2) // func Sleep(d Duration)
```

Сколько времени программа просит подождать? **A)** 2 секунды · **B)** 2 миллисекунды · **C)** 2 наносекунды ·
**D)** тип не подходит, ошибка компиляции

<details>
<summary>Ответ</summary>

**C: 2 наносекунды, без ошибки.** `2` — нетипизированная константа. Она берёт тип параметра `Sleep`, то есть
`time.Duration`, а `Duration` считает наносекунды. Если вы выбрали «2 секунды», вы перенесли правило Python.
«2 миллисекунды» — правило `setTimeout`. Если «ошибка компиляции» — вы вспомнили ошибку из `duration-type`: там `n`
был переменной с типом, здесь `2` — константа без типа.

</details>

`sleep2/main.go`:

```go filename="sleep2/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	start := time.Now()
	time.Sleep(2) // 2 soniya? 2 millisekund?
	fmt.Println(time.Duration(2), time.Since(start) < time.Millisecond)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 9 | `start := time.Now()` | запоминает время начала |
| 10 | `time.Sleep(2)` | `2` → `time.Duration`: просит 2 наносекунды |
| 11 | `time.Duration(2)` | выводит `2` как `Duration`: `Println` пишет его с единицей |
| 11 | `time.Since(start) < time.Millisecond` | прошло меньше 1 миллисекунды? `true` или `false` |

```console
$ go run sleep2/main.go
2ns true
```

`2ns` — запрошенное время. `true` — `Sleep` вернулся быстрее, чем за миллисекунду. `Sleep` ждёт не меньше `d`, точное
время зависит от ОС: при подготовке урока 1000 вызовов `time.Sleep(2)` возвращались за 0,3–14 микросекунды.
Молчат и компилятор, и `go vet`. А [staticcheck SA1004](https://staticcheck.dev/docs/checks/#SA1004) ловит такую
маленькую константу в `time.Sleep`.

### Исправление: `2 * time.Second`

Для двух секунд пишите `2 * time.Second`. `kutish/main.go`:

```go filename="kutish/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	time.Sleep(2) // untyped 2 → time.Duration: 2 nanosekund soʻraydi
	var d time.Duration = 2
	fmt.Println(d)      // Duration birligi bilan chiqadi: 2ns
	d = 2 * time.Second // time.Second: typed constant, turi Duration (1 000 000 000 ns)
	fmt.Println(d)      // 2s
	time.Sleep(d)       // 2 soniya kutadi
}
```

| После строки | `d` (`time.Duration`) | На экране | Комментарий |
|---|---|---|---|
| 9 | — | | нетипизированная `2` → `Duration`: просит 2 нс |
| 10 | 2 | | `d` = 2 наносекунды |
| 11 | 2 | `2ns` | `Println` выводит `Duration` с единицей |
| 12 | 2 000 000 000 | | `time.Second` = 1 000 000 000 нс |
| 13 | 2 000 000 000 | `2s` | |
| 14 | 2 000 000 000 | | ждёт 2 секунды ✅ |

```console
$ go run kutish/main.go
2ns
2s
```

(После `2s` программа ждёт ещё 2 секунды и только потом завершается.) **`time.Second`** — **типизированная
константа**: тип `Duration`, значение миллиард наносекунд. В пакете `time` это записано так:
`Nanosecond Duration = 1`, `Microsecond = 1000 * Nanosecond`, …, `Second = 1000 * Millisecond`. В `2 * time.Second`
`2` нетипизированная, она подстраивается под `Duration`, и результат тоже `Duration`.

## Секунды из config: `n * time.Second`

Теперь рабочая ситуация: число секунд ожидания приходит из config или env. Только что `2 * time.Second` сработало.

```go
n := 2
time.Sleep(n * time.Second)
```

Что будет на этот раз? **A)** подождёт 2 секунды · **B)** подождёт 2 наносекунды · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**C: ошибка компиляции.** `:=` дал `n` тип по умолчанию, то есть `int`. Теперь `n` — переменная типа `int`, а Go не
превращает `int` в `Duration` молча. Литерал `2` же был нетипизированным и подстроился под `Duration`. Если вы
выбрали «2 секунды», вы думали, что `n` подстроится так же, как `2`. Если «2 наносекунды» — вы перенесли сюда
ловушку `time.Sleep(2)`.

</details>

```go filename="config/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	n := 2                      // masalan, config yoki env'dan oʻqilgan soniyalar soni: tur = int
	time.Sleep(n * time.Second) // ataylab xato: int × time.Duration
	fmt.Println("tayyor")
}
```

```console
$ go run config/main.go
# command-line-arguments
config/main.go:10:13: invalid operation: n * time.Second (mismatched types int and time.Duration)
```

Строка 10, столбец 13. *invalid operation: n * time.Second (mismatched types int and time.Duration)* — «недопустимая
операция: типы не совпадают, `int` и `time.Duration`».

**Исправление:** `time.Duration(n)` — явное преобразование `n` в `Duration` (**конверсия**, как `int8(big)` в
[GO-1.02](/lab/youtube/go/go-1-02/ru)), затем `* time.Second`. Именно такая форма есть и в документации самого пакета `time`.
`config-fix/main.go`:

```go filename="config-fix/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	n := 2
	d := time.Duration(n) * time.Second // konversiya: int → time.Duration
	fmt.Println(d)
	time.Sleep(d) // 2 soniya kutadi
}
```

```console
$ go run config-fix/main.go
2s
```

(Эта программа тоже ждёт 2 секунды после `2s`.) Осторожно: если написать только преобразование и забыть умножение,
снова получатся 2 наносекунды. `wrongfix/main.go`:

```go filename="wrongfix/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	n := 2
	fmt.Println(time.Duration(n) * time.Second) // 2s — toʻgʻri
	fmt.Println(time.Duration(n))               // 2ns — notoʻgʻri tuzatish: birlik yoʻq
}
```

```console
$ go run wrongfix/main.go
2s
2ns
```

| Код | `n` = 2 | Результат |
|---|---|---|
| `n * time.Second` | `int` × `Duration` | ошибка компиляции |
| `time.Duration(n)` | 2 нс | без ошибки, но неверно ❌ |
| `time.Duration(n) * time.Second` | 2 × 1 000 000 000 нс | `2s` ✅ |

staticcheck SA1004 не ловит `time.Sleep(time.Duration(n))`: он смотрит только на константу. Если в config текст
вроде `"2s"`, используйте `time.ParseDuration("2s")` (похоже на `ms('2s')` из npm).

Почему Go так строг? Неявное числовое преобразование в Go не добавили намеренно (Go FAQ). А нетипизированные
константы оставляют числовые литералы удобными даже при такой строгости: для `2 * time.Second` или
`var b float64 = 100` преобразование писать не нужно (Rob Pike, *Constants*).

## Проверка: нетипизированная `a` и типизированная `b`

Две константы: у `a` тип не указали, у `b` указали `int`. Затем умножаем обе на `time.Second`:

```go
const a = 3
const b int = 3
x := a * time.Second
y := b * time.Second
```

Какая строка не скомпилируется? **A)** ни одна · **B)** `x` · **C)** `y` · **D)** обе

<details>
<summary>Ответ</summary>

**C: строка `y`.** Типизированная константа строга, как переменная: `b` теперь `int`, а `int` нельзя умножить на
`Duration`. Нетипизированная `a` подстроилась под `Duration`. Если вы выбрали «ни одна», вы думали, что
подстраивается любая константа. Если «`x`» или «обе» — что константа тоже становится `int`, как `n`:
нетипизированная константа получает тип по умолчанию только там, где тип не назван.

</details>

```go filename="sinov/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	const a = 3     // untyped
	const b int = 3 // typed: turi int
	x := a * time.Second
	y := b * time.Second // ataylab xato: int × time.Duration
	fmt.Println(x, y)
}
```

```console
$ go run sinov/main.go
# command-line-arguments
sinov/main.go:12:7: invalid operation: b * time.Second (mismatched types int and time.Duration)
```

Только строка 12. Правило одно: **нетипизированная константа берёт тип из места использования**, а типизированная
везде несёт свой тип. Поэтому и `int8(127) + 1` из [GO-1.02](/lab/youtube/go/go-1-02/ru) был отвергнут: `int8(127)` —
типизированная константа, а по Go spec значение типизированной константы всегда обязано помещаться в её тип.
А 128 в `int8` не помещается.

## `enum` в TypeScript и `iota` в Go

Теперь вернёмся к вопросу из начала. В TypeScript `enum` сам расставляет числа: `Unknown` 0, `New` 1, `Paid` 2.

```ts filename="anchors/enum1.ts"
enum Status { Unknown, New, Paid }
console.log(Status.New, Status.Paid) // 1 2
```

```console
$ tsc anchors/enum1.ts && node anchors/enum1.js
1 2
```

Ключевого слова `enum` в Go нет. Вместо него используют свой тип и **`iota`** в блоке `const`. `holat/main.go`
(«holat» — статус):

```go filename="holat/main.go" showLineNumbers
package main

import "fmt"

type Holat int // time.Duration kabi: asosi int boʻlgan alohida tur

const (
	Nomalum  Holat = iota // 0: zero value — holat berilmagan
	Yangi                 // 1: faqat nom → oldingi ifoda "Holat = iota" takrorlanadi
	Tolangan              // 2
)

func main() {
	var h Holat // zero value
	fmt.Println(Yangi, Tolangan, h == Nomalum)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `type Holat int` | свой тип, как `time.Duration`: в основе `int`, но это отдельный тип |
| 7 | `const (` | блок `const`: несколько констант в одних скобках |
| 8 | `Nomalum Holat = iota` | `Nomalum` («неизвестен», unknown). `iota` — порядковый номер объявления в блоке, с 0. `Nomalum` = 0 |
| 9 | `Yangi` | («новый», new) только имя: Go повторяет предыдущее выражение `Holat = iota`, `iota` = 1 |
| 10 | `Tolangan` | («оплачен», paid) снова повтор, `iota` = 2 |
| 14 | `var h Holat` | значение не задано: нулевое значение, 0 |
| 15 | `fmt.Println(Yangi, Tolangan, h == Nomalum)` | два числа и сравнение |

```console
$ go run holat/main.go
1 2 true
```

Результат такой же, как в TypeScript: `1 2`. Компилятор читает блок так:

| Строка | Написано | Что видит Go | `iota` | Значение |
|---|---|---|---|---|
| 8 | `Nomalum Holat = iota` | `Nomalum Holat = iota` | 0 | 0 |
| 9 | `Yangi` | `Yangi Holat = iota` | 1 | 1 |
| 10 | `Tolangan` | `Tolangan Holat = iota` | 2 | 2 |

Комментарии и пустые строки не считаются: `iota` считает только объявления. В каждом новом блоке `const` он снова
начинается с 0.

Этот тип не закрыт: `Holat(42)` тоже компилируется. Go проверяет только тип, а не то, есть ли значение в списке
(что все статусы обработаны, проверяет линтер `exhaustive`).

**Почему 0 — именно `Nomalum`?** В переменной без заданного статуса лежит нулевое значение, то есть 0 (строка 14).
Если бы 0 был `Yangi`, заказ с забытым статусом выглядел бы новым. Поэтому 0 оставляем для `Nomalum`. Руководство
Protobuf (формат схем gRPC) требует того же: первое значение — `…_UNSPECIFIED = 0`.

## Статус, добавленный в середину списка

Теперь напишем изменение из начала. Вчера оплаченный заказ записали в базу с числом `2`. Сегодня кто-то добавил
новый статус `Bekor` («отменён», cancelled) и вписал его после `Yangi`. Сравним сохранённую `2` с `Tolangan` и
`Bekor`. `xato/main.go`:

```go filename="xato/main.go" showLineNumbers
package main

import "fmt"

type Holat int

const (
	Nomalum Holat = iota
	Yangi
	Bekor // yangi holat oʻrtaga qoʻshildi
	Tolangan
)

func main() {
	var saqlangan Holat = 2 // kecha bazaga yozilgan: oʻshanda 2 = Tolangan edi
	fmt.Println(saqlangan == Tolangan, saqlangan == Bekor)
}
```

В строке 10 новый статус. В строке 15 вчерашняя `2`, в строке 16 два сравнения.

Что выведется на экран? **A)** `true false` · **B)** `false true` · **C)** ошибка компиляции. Посчитайте объявления
сами.

<details>
<summary>Ответ</summary>

**B: `false true`.** `Bekor` стоит на 2-й позиции, поэтому теперь `Bekor` = 2, а `Tolangan` = 3. Если вы выбрали
«`true false`», вы считали число `Tolangan` неизменным: `iota` берёт число из позиции. Если «ошибка компиляции» — вы
думали, что Go заметит смену чисел: о базе он ничего не знает.

</details>

```console
$ go run xato/main.go

```

И компиляция, и работа без ошибок. Но теперь `2` — это `Bekor`:

| Имя | Вчера | Сегодня |
|---|---|---|
| `Nomalum` | 0 | 0 |
| `Yangi` | 1 | 1 |
| `Bekor` | — | **2** |
| `Tolangan` | **2** | 3 |
| `status = 2` в базе | оплачен ✅ | отменён 💥 |

Вчерашние оплаченные заказы выглядят отменёнными. В `enum` TypeScript результат точно такой же:

```ts filename="anchors/enum2.ts"
enum Status { Unknown, New, Cancelled, Paid } // Cancelled oʻrtaga qoʻshildi
const saved: number = 2 // kecha bazaga yozilgan: oʻshanda 2 = Paid
console.log(saved === Status.Paid, saved === Status.Cancelled) // false true
```

```console
$ tsc anchors/enum2.ts && node anchors/enum2.js
false true
```

### Исправление

Правило: смысл числа, которое уходит в базу или JSON, не должен меняться никогда. Есть три пути:

1. **Пишите числа вручную.** Каждый статус сам называет своё число, новый — в конец.
2. **Если оставляете `iota`, добавляйте новый статус только в конец** и ничего не удаляйте (на месте удалённого
   статуса можно оставить `_`, вопрос 3 в «Проверьте себя»).
3. **Храните не число, а имя:** пишите в базу `"paid"`, как строковый `enum` в TypeScript. Это вы сделаете в
   домашнем задании 🟡.

Первый путь, `tuzatish/main.go`:

```go filename="tuzatish/main.go" showLineNumbers
package main

import "fmt"

type Holat int

const ( // bazaga saqlanadigan raqamlar qoʻlda yoziladi va hech qachon oʻzgarmaydi
	Nomalum  Holat = 0
	Yangi    Holat = 1
	Tolangan Holat = 2
	Bekor    Holat = 3 // yangi holat roʻyxat oxiriga
)

func main() {
	var saqlangan Holat = 2
	fmt.Println(saqlangan == Tolangan, saqlangan == Bekor)
}
```

```console
$ go run tuzatish/main.go
true false
```

С числами, записанными вручную, сохранённая `2` снова `Tolangan`. Protobuf тоже заставляет писать число каждого
значения вручную, а удалённое число объявлять `reserved` и запрещает использовать его повторно.

## Глубже (необязательно): `0.1 + 0.2 == 0.3`

Знаменитый вопрос из JavaScript:

```console
$ node -p '0.1 + 0.2 === 0.3'
false
```

(Этой команды нет в папке курса в виде файла, код прямо в команде.) А что выйдет в Go с константами без указанного
типа?

```go
const a, b = 0.1, 0.2
fmt.Println(a+b == 0.3)
```

**A)** `true` · **B)** `false`

<details>
<summary>Ответ</summary>

**A: `true`.** Нетипизированные константные выражения вычисляются точно (Go spec: «evaluated exactly»): сумма ровно
0.3, ничего не округляется. Если вы выбрали «`false`», вы перенесли правило JS: оно верно для `float64`.

</details>

```go filename="float/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const a, b = 0.1, 0.2 // untyped: aniq hisoblanadi
	fmt.Println(a+b == 0.3)

	const c, d float64 = 0.1, 0.2 // typed: float64 ga yaxlitlangan
	fmt.Println(c+d == 0.3)

	x, y := 0.1, 0.2 // float64 oʻzgaruvchilar
	fmt.Println(x+y == 0.3, x+y)
}
```

```console
$ go run float/main.go
true
false
false 0.30000000000000004
```

| Строки | Что | Результат |
|---|---|---|
| 6–7 | нетипизированные константы: точный расчёт | `true` |
| 9–10 | указан тип `float64`: каждая округляется до `float64` | `false` |
| 12–13 | переменные `float64`: как в JavaScript | `false 0.30000000000000004` |

## Частые ошибки

**1. Добавить статус в середину списка `iota`.** Самая классическая ошибка этой темы. Ни ошибки, ни предупреждения:
все числа после него сдвигаются на один, и `2` в базе теперь означает другой статус. Полный пример — в разделе
«Статус, добавленный в середину списка». **Исправление:** числа, которые уходят в базу или JSON, пишите вручную, или
добавляйте новый статус только в конец, или храните имя.

**2. Считать, что `time.Sleep(2)` — это две секунды.** Компилятор молчит: `2` нетипизированная, она становится
`Duration` и просит 2 наносекунды. Пример — в разделе «`time.Sleep(2)`». **Исправление:** всегда пишите единицу:
`2 * time.Second`, `500 * time.Millisecond`. staticcheck SA1004 это ловит.

**3. Умножать переменную `int` на `time.Second`.** `n * time.Second` →
`mismatched types int and time.Duration` (`config/main.go`). **Исправление:** `time.Duration(n) * time.Second`.
Не просто `time.Duration(n)`: это 2 наносекунды (`wrongfix/main.go`).

**4. Делать `const` из значения времени работы.** `const start = time.Now()` →
`time.Now() (value of struct type time.Time) is not constant` (`notconst/main.go`). **Исправление:** обычная
переменная: `start := time.Now()`. `const` — только для чисел, строк и bool, известных во время компиляции.

**5. Брать адрес константы.** Этой ошибки нет в видео, но она есть в папке курса, `addr/main.go`:

```go filename="addr/main.go" showLineNumbers
package main

import "fmt"

const Port = 8080

func main() {
	fmt.Println(&Port) // ataylab xato: konstantaning xotirada manzili yoʻq
}
```

```console
$ go run addr/main.go
# command-line-arguments
addr/main.go:8:15: invalid operation: cannot take address of Port (untyped int constant 8080)
```

`cannot take address of Port` — «нельзя взять адрес `Port`» (`Port` — порт сервера, 8080). `&` — адрес значения в памяти (указатели — в следующих
уроках). По правилам Go `&` ставится только к значению, у которого есть место в памяти, как у переменной
(addressable), а константа не такая. **Исправление:** сначала положите её в переменную (`p := Port`, затем `&p`).
С Go 1.26 работает и `new(Port)`: он создаёт новую переменную с копией значения.

## Проверьте себя

Сначала ответьте сами, потом откройте.

**1.** В чём главное отличие `const` в JavaScript от `const` в Go?

<details>
<summary>Ответ</summary>

Значение `const` в Go должно быть известно во время компиляции (только число, строка или bool; не вызов функции).
`const` в JavaScript замораживает только имя, а значение вычисляется во время работы.

</details>

**2.** Если `n := 2`, сколько времени просит `time.Sleep(time.Duration(n))`?

<details>
<summary>Ответ</summary>

2 наносекунды. `time.Duration(n)` меняет только тип, единицу он не добавляет. Для двух секунд нужно
`time.Duration(n) * time.Second`.

</details>

**3.** Если из списка `iota` `Nomalum, Yangi, Tolangan, Bekor` удалить `Yangi`, что будет означать `2` в базе?
Что выведет `ochirish/main.go`?

```go filename="ochirish/main.go" showLineNumbers
package main

import "fmt"

type Holat int

const (
	Nomalum Holat = iota
	// Yangi oʻchirildi → keyingilarning raqami bittaga kamaydi
	Tolangan // endi 1
	Bekor    // endi 2
)

const (
	Nomalum2  Holat = iota
	_               // Yangi oʻchirildi, lekin raqami band qoldi
	Tolangan2       // 2
	Bekor2          // 3
)

func main() {
	var saqlangan Holat = 2 // kecha: 2 = Tolangan
	fmt.Println(saqlangan == Tolangan, saqlangan == Bekor)
	fmt.Println(saqlangan == Tolangan2, saqlangan == Bekor2)
}
```

<details>
<summary>Ответ</summary>

В первом блоке `2` теперь `Bekor`, потому что следующие числа сдвигаются на один: `Tolangan` = 1, `Bekor` = 2. Во
втором блоке на месте удалённого `Yangi` стоит `_` (пустое имя): оно занимает число, поэтому `Tolangan2` снова 2.

```console
$ go run ochirish/main.go
false true
true false
```

</details>

**4.** Из [GO-1.02](/lab/youtube/go/go-1-02/ru): в сообщении об ошибке для `var x int8 = 128` было слово *(untyped int constant)*.
А `x++` с 127 тихо переполнился до −128. Объясните разницу сегодняшними словами.

<details>
<summary>Ответ</summary>

`128` — нетипизированная константа: тип `int8` она берёт из места использования, то есть из объявления переменной.
Go делает это во время компиляции и видит, что 128 в `int8` не помещается. А `x++` — операция над переменной, она
происходит во время работы и тихо переполняется.

</details>

🟡 `HolatNomi` даёт каждому статусу имя, `HolatNomdan` перебирает все статусы и возвращает тот, чьё имя совпало:

```go filename="uyga/javob/orta/main.go" showLineNumbers
// 🟡 Javob: nom ↔ Holat. Bazada "paid" saqlansa, const blokidagi tartib oʻzgarsa ham maʼno buzilmaydi.
package main

import "fmt"

type Holat int

const (
	Nomalum Holat = iota
	Yangi
	Tolangan
	Bekor
)

func HolatNomi(h Holat) string {
	if h == Yangi {
		return "new"
	}
	if h == Tolangan {
		return "paid"
	}
	if h == Bekor {
		return "cancelled"
	}
	return "unknown"
}

func HolatNomdan(s string) (Holat, error) {
	for _, h := range []Holat{Nomalum, Yangi, Tolangan, Bekor} {
		if HolatNomi(h) == s {
			return h, nil
		}
	}
	return Nomalum, fmt.Errorf("nomaʼlum holat: %q", s)
}

func main() {
	h, err := HolatNomdan(HolatNomi(Tolangan))
	fmt.Println(HolatNomi(h), h, err)

	h, err = HolatNomdan("refund")
	fmt.Println(h, err)
}
```

```console
$ go run uyga/javob/orta/main.go
paid 2 <nil>
0 nomaʼlum holat: "refund"
```

`for _, h := range []Holat{…}` — цикл по каждому статусу в списке (как `for (const h of [...])` в JS; подробнее о
`range` — в следующих уроках). `fmt.Errorf` создаёт `error` с текстом, `%q` пишет значение в кавычках. Если в базе
хранится `"paid"`, смысл не сломается, даже если порядок в блоке `const` изменится.

Задания посложнее (подробно — в `homework/README.md`):

- 🟢 С `Monday Weekday = iota + 1` понедельник начинается с 1, а `0` остаётся «день не выбран»:
  `homework/easy` → `1 5 7` и `0`. А в стандартном `time.Weekday` — `Sunday Weekday = iota`, воскресенье 0.
- 🟡 `Read Perm = 1 << iota` → `001`, `010`, `100`: каждый флаг — отдельный бит, объединяются через `|`,
  проверяются через `&`. `io/fs.FileMode` устроен так же.
- 🟠 `1.5 * time.Second` → `1.5 (untyped float constant) truncated to int64`: нетипизированное `1.5` не превращается
  точно в `Duration`, то есть в целое число, а константа не округляется. Правильные пути: `1500 * time.Millisecond`
  или `time.Second * 3 / 2`, оба дают `1.5s`.
- 🔴 `January Month = 1 + iota`: месяцы от 1 до 12, как их пишут люди. Незаданный `time.Month` равен 0, но 0-го
  месяца нет: `fmt` выводит его как `%!Month(0)`. Команда Go здесь выбрала «число совпадает с тем, которым
  пользуются люди».

</details>
