## Что вы узнаете

В классном журнале оценки записаны не по имени, а по порядковому номеру: «ученику № 3 — пятёрка». Если в середину
списка добавить нового ученика, чья теперь эта пятёрка?

```text
Вчера:    1 Али    2 Бобур   3 Дильноза    ← номеру 3 ⭐ 5
Сегодня:  1 Али    2 Бобур   3 Ботир       4 Дильноза
                             ⭐ 5 теперь чья?
```

В программах на Go бывает точно такая же тихая ошибка. В этом уроке мы её найдём и исправим.

**Одна идея:** константа не меняется, но её смысл зависит от того, где она стоит. Тип она берёт от ячейки, в которую
попала, а `iota` берёт значение от места строки в списке.

К концу урока вы:

- сможете записать неизменяемое число через `const` и будете знать, что случится, если присвоить ему новое значение;
- сможете объяснить, почему `time.Sleep(2)` просит не две секунды, а две наносекунды, и исправить это на
  `2 * time.Second`;
- сможете записать список состояний с помощью `iota`;
- будете знать, как не испортить сохраняемые числа, вставив строку в середину списка.

Три главных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| константа (`const`) | готовое число, записанное в коде, которое не меняется: надпись, высеченная в камне | constant |
| нетипизированная константа | константа без записанного типа: как вода, принимает тип той ячейки, в которую попала | untyped constant |
| `iota` | номер строки внутри скобок `const ( … )`, начинается с 0 | iota |

По дороге встретятся ещё два вспомогательных слова: **`time.Sleep`** (команда, которая заставляет программу ждать)
и **наносекунда** (миллиардная доля секунды). Оба объясним там, где они понадобятся.

```go
var x int8 = 128
```

<details>
<summary>Ответ</summary>

</details>

## Константа: число, высеченное в камне (`const`)

В [GO-0.02](/lab/youtube/go/go-0-02/ru) мы сравнили переменную с табло на стадионе: число на нём меняется. Но некоторые числа
не меняются никогда. Например, в минуте всегда 60 секунд. Представьте такое число как надпись, высеченную в камне:
её нельзя стереть и написать другую.

```text
переменная = табло           константа = камень 🪨
PAXTAKOR  3 → 4              ┌──────────────┐
число меняется               │ soniyalar 60 │  не меняется
                             └──────────────┘
```

Готовое неизменяемое число, записанное в коде, называется **константой**, по-английски **constant**. Чтобы дать
константе имя, в Go пишут слово **`const`**:

```go
const soniyalar = 60
soniyalar = 61
fmt.Println(soniyalar)
```

Первую строку читайте так: «константа `soniyalar`, значение 60». `soniyalar` — «секунды», количество секунд в минуте.
Во второй строке стоит присваивание, мы хотим дать ей новое значение: «пусть `soniyalar` теперь будет 61».

Вспомните привычку Go: если в коде ошибка, он не пропускает её молча. Что выведется на экран?
**A)** `61` · **B)** `60` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**C: ошибка компиляции.** Константе нельзя присвоить новое значение, и Go видит это ещё до запуска программы.
Если вы выбрали **A**, вы приняли `soniyalar` за обычную переменную. Если **B** — решили, что Go молча проигнорирует
61. Но Go не пропускает ошибки молча: он останавливается и сообщает о них.

</details>

Полная программа, файл `ozgarmas/main.go` из папки курса:

```go filename="ozgarmas/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const soniyalar = 60 // bir daqiqadagi soniyalar soni (vaqt emas, oddiy son)
	soniyalar = 61       // ataylab xato: konstantani oʻzgartirib boʻlmaydi
	fmt.Println(soniyalar)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1–5 | `package main` … `func main() {` | знакомый шаблон: запускаемая программа, подключаем `fmt`, программа начинается с `main` |
| 6 | `const soniyalar = 60` | **константа** `soniyalar`, значение 60. Текст после `//` — комментарий, Go его не читает |
| 7 | `soniyalar = 61` | попытка присвоить константе новое значение: ошибка, сделанная нарочно |
| 8 | `fmt.Println(soniyalar)` | должна была вывести `soniyalar` на экран |
| 9 | `}` | конец `main` |

```console
$ go run ozgarmas/main.go
# command-line-arguments
ozgarmas/main.go:7:2: cannot assign to soniyalar (neither addressable nor a map index expression)
```

Как всегда, читаем сообщение с файла и строки: файл `ozgarmas/main.go`, **строка 7**, символ 2. В отрывке из 3 строк
выше это была вторая строка, а в полном файле — седьмая, потому что сверху стоит знакомый шаблон. Дальше
`cannot assign to soniyalar` — «нельзя присвоить значение `soniyalar`». Остальные слова в скобках означают «это имя —
не место, куда можно положить значение». `go run` не запустил программу.

| Строка | `soniyalar` | На экране |
|---|---|---|
| 6 `const soniyalar = 60` | `60` 🪨 | |
| 7 `soniyalar = 61` | ошибка компиляции: программа не запускается | |

Коротко: как надпись на камне, константа не меняется.

## Нетипизированная константа: вода принимает форму сосуда

В [GO-0.03](/lab/youtube/go/go-0-03/ru) мы видели, что переменные `int` и `float64` нельзя смешивать: типы не совпадают.
Чтобы вспомнить, вот `suv-xato/main.go` (ошибка нарочно):

```go filename="suv-xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	n := 100          // oʻzgaruvchi: turi int
	var b float64 = n // ataylab xato: int oʻzgaruvchi float64 katakka tushmaydi
	fmt.Println(b)
}
```

Строка 6, `n := 100`, создаёт переменную типа `int`. Строка 7, `var b float64`, как в [GO-1.02](/lab/youtube/go#go-1-02),
создаёт новый ярлык, только тип ячейки мы пишем сами: `float64`. В неё мы хотим положить `n`.

```console
$ go run suv-xato/main.go
# command-line-arguments
suv-xato/main.go:7:18: cannot use n (variable of type int) as float64 value in variable declaration
```

Строка 7, символ 18 (это `n`): «нельзя использовать `n` (переменную типа `int`) как значение `float64`».

С константой всё иначе. Тип константы, у которой тип не записан, определяется, когда она попадает в ячейку.
Представьте константу как воду: в какой сосуд её нальют, такую форму она и примет. Такая константа называется
**нетипизированной константой**, по-английски **untyped constant**. Это не значит, что у константы вообще не бывает
типа: тип ей даёт ячейка, в которую она попала.

```go filename="suv/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const yuz = 100       // turi yoʻq (untyped) konstanta
	var a int8 = yuz      // int8 katakka tushdi
	var b float64 = yuz   // float64 katakka tushdi
	fmt.Println(a/8, b/8) // int8: kasr tashlanadi, float64: qoladi
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `const yuz = 100` | нетипизированная константа `yuz` («сто» = 100) |
| 7 | `var a int8 = yuz` | ячейка `int8` по имени `a`, в неё попала `yuz`: теперь это 100 типа `int8` |
| 8 | `var b float64 = yuz` | ячейка `float64` по имени `b`, в неё тоже попала `yuz`: теперь это 100 типа `float64` |
| 9 | `fmt.Println(a/8, b/8)` | делит оба значения на 8 и выводит: чтобы увидеть разницу типов |

Одна константа, две разные ячейки:

| Имя | Тип | Значение |
|---|---|---|
| `yuz` | без типа 💧 | `100` |
| `a` | `int8` | `100` |
| `b` | `float64` | `100` |

Угадайте: что выведется на экран? **A)** `12 12` · **B)** `12 12.5` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `12 12.5`.** `yuz` без ошибки попала в обе ячейки, потому что у неё не было типа. `a` — целое число, а при делении
целых дробная часть отбрасывается: `100 / 8` → `12`. `b` — дробное число, в нём дробная часть остаётся: `12.5`.
Если вы выбрали **C**, вы решили, что `yuz` — это `int`, как `n` в `suv-xato`. Если **A** — что обе ячейки получили
один и тот же тип.

</details>

```console
$ go run suv/main.go
12 12.5
```

Полного варианта этой программы в видео нет: там показаны только строки 6–8.

## `time.Sleep(2)`: не две секунды

Это правило очень важно при работе со временем. **`time`** — такой же готовый ящик с инструментами (пакет) Go, как
`fmt`. В нём есть команда, которая заставляет программу немного подождать: **`time.Sleep`**. Она кладёт число из
своих скобок в ячейку для времени. Тип этой ячейки называется **`time.Duration`**. Эта ячейка считает время в
**наносекундах**, а наносекунда — это миллиардная доля секунды:

| | |
|---|---|
| 1 секунда | 1 000 000 000 наносекунд |
| 1 наносекунда | 0,000 000 001 секунды |

Теперь вопрос. Создаём через `var` ярлык `kutish`, тип ячейки `time.Duration`, значение 2:

```go
var kutish time.Duration = 2
fmt.Println(kutish)
```

Что будет на экране? **A)** `2s` · две секунды · **B)** `2ns` · две наносекунды · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: две наносекунды.** Go не выдал ошибку, потому что 2 было числом без типа. Оно молча попало в ячейку для времени,
а 2 в этой ячейке читается как наносекунды. `Println` пишет время с единицей: `ns` = наносекунда. Если вы выбрали
**A**, вы подумали как человек: «время обычно в секундах». А Go считает в наносекундах. Если **C** — вы вспомнили
`suv-xato`, но там была переменная, а здесь нетипизированная константа.

</details>

```text
     2               →   ячейка time.Duration    →   2 наносекунды
без типа 💧              считает наносекунды          ошибки нет, тихо
```

Значит, если написать `time.Sleep(2)`, программа просит подождать не две секунды, а всего две наносекунды. То есть
почти совсем не ждёт, и ошибки тоже нет. (`Sleep` ждёт не меньше запрошенного: в замерах для этого курса, 1000 раз,
вышло от 0,4 до 27 микросекунд. Всё равно намного-намного меньше секунды.)

Для двух секунд в Go есть готовая константа: **`time.Second`**, она равна одной секунде. Звёздочка `*` умножает,
поэтому `2 * time.Second` = две секунды. Всё вместе в одной программе, `kutish/main.go`:

```go filename="kutish/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	var kutish time.Duration = 2 // vaqt turi: nanosekundlarni sanaydi
	fmt.Println(kutish)          // Println birlik qoʻshadi: ns = nanosekund
	time.Sleep(kutish)           // = time.Sleep(2): deyarli kutmaydi
	kutish = 2 * time.Second     // time.Second = 1 soniya = 1 000 000 000 nanosekund
	fmt.Println(kutish)          // s = soniya
	time.Sleep(kutish)           // 2 soniya kutadi
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–6 | `import ( "fmt" "time" )` | подключает два пакета сразу: в скобках, каждый на своей строке |
| 9 | `var kutish time.Duration = 2` | ярлык `kutish` («ожидание»), тип ячейки `time.Duration`, в неё попало 2: 2 наносекунды |
| 10 | `fmt.Println(kutish)` | выводит `2ns` |
| 11 | `time.Sleep(kutish)` | то же, что `time.Sleep(2)`: просит 2 наносекунды, почти не ждёт |
| 12 | `kutish = 2 * time.Second` | пусть `kutish` теперь будет 2 секунды: в ячейке 2 000 000 000 наносекунд |
| 13 | `fmt.Println(kutish)` | выводит новое значение |
| 14 | `time.Sleep(kutish)` | теперь действительно ждёт 2 секунды |

Что выведет строка 13? **A)** `2000000000` · **B)** `2s` · **C)** `2ns`

<details>
<summary>Ответ</summary>

**B: `2s`.** В ячейке лежит 2 000 000 000 наносекунд, но `Println` пишет время в удобной единице: `s` = секунда.
Если вы выбрали **A**, вы увидели число в ячейке, но `Println` пишет его как время, с единицей. **C** — старое
значение; после строки 12 его больше нет.

</details>

```console
$ go run kutish/main.go
2ns
2s
```

После вывода `2s` программа ждёт 2 секунды и только потом завершается.

| Строка | В ячейке `kutish` | На экране |
|---|---|---|
| 9 | `2` (наносекунды) | |
| 10 | `2` | `2ns` |
| 11 | `2` | почти не ждёт |
| 12 | `2000000000` (наносекунды) | |
| 13 | `2000000000` | `2s` |
| 14 | `2000000000` | ждёт 2 секунды ✅ |

## Маленькая проверка: `const narx = 300`

Теперь проверьте себя. Кладём константу `narx` («цена») и в ячейку `int`, и в ячейку `int8`:

```go
const narx = 300
var a int = narx
var b int8 = narx
fmt.Println(a, b)
```

Что выведется на экран? **A)** `300 300` · **B)** `300 44` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**C: ошибка компиляции.** В ячейку `int` 300 поместилось, а в ячейку `int8` — нет (в неё помещается максимум 127).
Если вы выбрали **A**, вы решили, что вода поместится в любой сосуд. **B** — это тихий переход через край:
300 − 256 = 44. Так бывает, как с `x++` в [GO-1.02](/lab/youtube/go#go-1-02), когда программа работает и считает с
переменной. А константу Go проверяет заранее.

</details>

```go filename="sinov/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const narx = 300
	var a int = narx
	var b int8 = narx // ataylab xato: 300 int8 ga sigʻmaydi
	fmt.Println(a, b)
}
```

```console
$ go run sinov/main.go
# command-line-arguments
sinov/main.go:8:15: cannot use narx (untyped int constant 300) as int8 value in variable declaration (overflows)
```

`go run` указал на строку с `int8`: **строка 8**, символ 15 (это `narx`). Сообщение: «нельзя использовать `narx`
(нетипизированную целую константу 300) как значение `int8` … (переполнение)». В сообщении есть и слово **untyped**:
это наше «без типа». В строке 7 ошибки нет: в ячейку `int` 300 помещается спокойно.

Коротко: нетипизированная константа принимает тип той ячейки, в которую попала. Если сосуд мал, Go не разливает воду,
а выдаёт ошибку компиляции.

## `iota`: порядковый номер, как в журнале

Теперь состояния заказа в магазине: неизвестно, новый, оплачен. Программы часто хранят их, как в журнале, по
порядковому номеру: 0, 1, 2. Чтобы записать несколько констант вместе, есть скобки `const ( … )`. Чтобы не писать
номера вручную, внутри скобок пишем **`iota`**:

```go
const (
	Nomalum = iota
	Yangi
	Tolangan
)
fmt.Println(Yangi, Tolangan)
```

Правила:

- **`iota`** — номер строки внутри скобок `const ( … )`; он начинается **с 0** и на каждой строке растёт на один.
- В строке, где написано только имя, Go повторяет предыдущую запись, то есть `= iota`.

Имена: `Nomalum` («неизвестно»), `Yangi` («новый»), `Tolangan` («оплачен»). В коде они записаны без апострофа
(по-узбекски *nomaʼlum*, *toʻlangan*).

В последней строке `Println` выводит `Yangi` и `Tolangan`. Какие два числа будут на экране?
**A)** `0 1` · **B)** `1 2` · **C)** `2 3`

<details>
<summary>Ответ</summary>

**B: `1 2`**, потому что счёт начался с нуля: `Nomalum` 0, `Yangi` 1, `Tolangan` 2. Если вы выбрали **C**, вы начали
счёт с 1. Если **A** — посчитали `Yangi` первой строкой, но первая строка — `Nomalum`.

</details>

```go filename="holat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const (
		Nomalum  = iota // 0: qiymat berilmagan (nol qiymat) holat
		Yangi           // 1
		Tolangan        // 2
	)
	fmt.Println(Yangi, Tolangan)
}
```

| Строка | Код | `iota` | Значение константы |
|---|---|---|---|
| 6 | `const (` | | начинаются несколько констант вместе |
| 7 | `Nomalum = iota` | `0` | `Nomalum` = 0 |
| 8 | `Yangi` | `1` | только имя → повторяется `= iota` → `Yangi` = 1 |
| 9 | `Tolangan` | `2` | `Tolangan` = 2 |
| 10 | `)` | | группа закончилась |
| 11 | `fmt.Println(Yangi, Tolangan)` | | на экране: `1 2` |

```console
$ go run holat/main.go
1 2
```

Почему 0 — «неизвестно»? Вспомните нулевое значение из [GO-1.02](/lab/youtube/go#go-1-02): в ячейке, которой не дали значение,
лежит 0. Значит, если заказу не задали состояние, в ячейке всё равно будет 0. Если 0 — это `Nomalum`, такой заказ
выглядит не «новым», а «неизвестным». Так и правильно: мы ведь не дали ему никакого состояния.

## Тихая ошибка: строка, вставленная в середину списка

Теперь вопрос про журнал из начала. Вчера магазин записал оплаченный заказ в файл, как в журнал, под числом **2**
(тогда `Tolangan` = 2). Сегодня программист добавил новое состояние: `Bekor` («отменён»). Он вписал его после `Yangi`.
Потом сохранённое 2 сравнивается с `Tolangan` и с `Bekor`:

```go filename="xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const (
		Nomalum = iota
		Yangi
		Bekor // yangi holat oʻrtaga qoʻshildi
		Tolangan
	)
	saqlangan := 2 // kecha faylga yozilgan: oʻshanda 2 = Tolangan edi
	fmt.Println(saqlangan == Tolangan, saqlangan == Bekor)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 9 | `Bekor` | новое состояние, вставлено в середину списка |
| 12 | `saqlangan := 2` | число, вчера записанное в файл («сохранённое») |
| 13 | `saqlangan == Tolangan, saqlangan == Bekor` | `==` сравнивает два числа: ответ `true` или `false`. `Println` выводит оба ответа |

Что выведется на экран? **A)** `true false` · **B)** `false true` · **C)** ошибка компиляции. Посчитайте строки
сами.

<details>
<summary>Ответ</summary>

**B: `false true`.** Считаем строки: `Nomalum` 0, `Yangi` 1, `Bekor` 2, `Tolangan` 3. Теперь 2 означает `Bekor`,
а `Tolangan` стал 3. Если вы выбрали **A**, вы думали, что `Tolangan` всё ещё 2: но `iota` берёт число от места
строки. Если **C** — вы думали, что Go считает это ошибкой: для Go это правильная программа.

</details>

```console
$ go run xato/main.go
false true
```

`go run` отработал без ошибок. Как сдвинулись номера:

| Состояние | Вчера (без `Bekor`) | Сегодня (`Bekor` в середине) |
|---|---|---|
| `Nomalum` | 0 | 0 |
| `Yangi` | 1 | 1 |
| `Bekor` | — | **2** |
| `Tolangan` | **2** | 3 |

А в файле вчерашнее 2 осталось на месте. Вчерашние оплаченные заказы теперь выглядят отменёнными. Как в журнале:
номер остался на месте, а смысл изменился.

### Исправление

Вывод: смысл числа, записанного в файл, никогда не должен меняться. Поэтому для сохраняемых состояний пишите номера
вручную:

```go filename="tuzatish/main.go" showLineNumbers
package main

import "fmt"

func main() {
	const ( // faylga saqlanadigan raqamlar qoʻlda yoziladi va hech qachon oʻzgarmaydi
		Nomalum  = 0
		Yangi    = 1
		Tolangan = 2
		Bekor    = 3 // yangi holat roʻyxat oxiriga
	)
	saqlangan := 2
	fmt.Println(saqlangan == Tolangan, saqlangan == Bekor)
}
```

Что изменилось: в строках 7–10 номера записаны вручную (без `iota`), а новое `Bekor` стоит в конце и получило 3.
`Tolangan` снова 2. Что выведется теперь? **A)** `true false` · **B)** `false true`

<details>
<summary>Ответ</summary>

**A: `true false`.** Сохранённое 2 снова `Tolangan`. Номер записан вручную, поэтому никакая новая строка не может его
сдвинуть.

</details>

```console
$ go run tuzatish/main.go
true false
```

Можно оставить и `iota`, но с двумя условиями: добавляйте новое состояние **только в конец списка** и **ничего не
удаляйте** (при удалении следующие номера снова сдвинутся на один). Первое задание домашки как раз об этом. Большие
системы поступают так же: например, руководство по Protocol Buffers (формат Google для обмена данными между
программами) настоятельно рекомендует не использовать удалённые номера повторно.

## Глубже (необязательно): `1 << 100` и `0.1 + 0.2`

Если вы только начинаете, прочитайте этот раздел позже: остальной урок понятен и без него.

**Очень большая константа.** По правилам Go целая константа хранится с очень большой точностью: не меньше 256 бит. **Бит** — это один 0 или 1, как включённая или выключенная лампочка
(подробно в разделе «Глубже» урока [GO-1.02](/lab/youtube/go#go-1-02)). `big/main.go`:

```go filename="big/main.go" showLineNumbers
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(big >> 98)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `const big = 1 << 100` | константу можно писать и вне `main`. `<<` — сдвиг влево: умножает 1 на 2 сто раз, то есть 2¹⁰⁰ |
| 8 | `fmt.Println(big >> 98)` | `>>` — сдвиг вправо: делит `big` на 2⁹⁸ |

2¹⁰⁰ = 1 267 650 600 228 229 401 496 703 205 376, это 101-битное число. Самая большая ячейка для целых чисел в Go —
64 бита, поэтому такое число не помещается ни в одну целочисленную ячейку. А как константа оно живёт спокойно.
Программа заработает? **A)** заработает · **B)** ошибка компиляции

<details>
<summary>Ответ</summary>

**A: заработает и выведет `4`.** 2¹⁰⁰ / 2⁹⁸ = 2² = 4. Большое число было только константой и вычислилось во время
компиляции. В ячейку попал только результат, 4, а он спокойно помещается в `int`. Этот пример есть и в официальных
правилах Go.

</details>

```console
$ go run big/main.go
4
```

**Константы вычисляются точно.** Равна ли сумма 0,1 и 0,2 числу 0,3? `float/main.go`:

```go filename="float/main.go" showLineNumbers
package main

import "fmt"

const a, b = 0.1, 0.2

func main() {
	fmt.Println(a+b == 0.3)

	x, y := 0.1, 0.2
	fmt.Println(x+y == 0.3)
	fmt.Println(x + y)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `const a, b = 0.1, 0.2` | две константы в одной строке: `a` = 0.1, `b` = 0.2 |
| 8 | `fmt.Println(a+b == 0.3)` | сравнивает сумму констант с 0.3 |
| 10 | `x, y := 0.1, 0.2` | две переменные `float64` в одной строке |
| 11 | `fmt.Println(x+y == 0.3)` | сравнивает сумму переменных с 0.3 |
| 12 | `fmt.Println(x + y)` | выводит саму сумму |

Угадайте: **A)** `true` и `true` · **B)** `true` и `false` · **C)** `false` и `false`

<details>
<summary>Ответ</summary>

**B.** С константами `true`: Go вычисляет их точно. С переменными `float64` — `false`, потому что ячейка `float64`
не может хранить 0.1 и 0.2 точно и хранит их округлёнными. Сумма получается чуть больше: `0.30000000000000004`.

</details>

```console
$ go run float/main.go
true
false
0.30000000000000004
```

## Частые ошибки

**1. Вставить новое состояние в середину списка `iota`.** Самая классическая ошибка: легко подумать «я же добавил
всего одну строку». Go не выдаёт ошибку, а сохранённые в файле числа молча меняют смысл: вчерашний оплаченный заказ
выглядит отменённым. Полный пример — выше, в разделе «Тихая ошибка: строка, вставленная в середину списка»
(`xato/main.go` → `false true`). **Исправление:** для сохраняемых состояний пишите номера вручную
(`tuzatish/main.go` → `true false`) или добавляйте новое состояние только в конец и ничего не удаляйте.

**2. Думать, что `time.Sleep(2)` — это две секунды.** Это тоже тихая ошибка: программа работает без ошибок, но не
ждёт. Нетипизированное 2 попадает в ячейку `time.Duration` и становится 2 наносекундами. Подробно — выше, в разделе
«`time.Sleep(2)`: не две секунды». **Исправление:** `time.Sleep(2 * time.Second)`. Ни сам Go, ни `go vet` об этом не
предупреждают; отдельный анализатор кода [staticcheck](https://staticcheck.dev/docs/checks/#SA1004) (SA1004) это
ловит.

**3. Секунды в переменной: `n * time.Second`.** `2 * time.Second` работает, потому что 2 — число без типа. А если
число лежит в переменной? Этого примера нет в видео, он есть в папке курса (`duration/main.go`):

```go filename="duration/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	fmt.Println(2 * time.Second)

	n := 2
	fmt.Println(n * time.Second)
}
```

```console
$ go run duration/main.go
# command-line-arguments
duration/main.go:12:14: invalid operation: n * time.Second (mismatched types int and time.Duration)
```

Строка 12, символ 14: «недопустимая операция: `n * time.Second` (типы не совпадают: `int` и `time.Duration`)». `n` —
не нетипизированная константа, а переменная `int`. А Go сам молча типы не смешивает, точно как в `suv-xato`.
**Исправление:** преобразуйте `n` в тип времени, как `float64(olma)` в [GO-0.03](/lab/youtube/go/go-0-03/ru) (`durfix/main.go`):

```go filename="durfix/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	n := 2
	fmt.Println(time.Duration(n) * time.Second)
}
```

```console
$ go run durfix/main.go
2s
```

**4. Присвоить константе новое значение.** `const soniyalar = 60`, потом `soniyalar = 61` → `cannot assign to
soniyalar` (раздел «Константа: число, высеченное в камне» выше). **Исправление:** если значение должно меняться,
создайте не константу, а переменную: `soniyalar := 60`.

**5. Константа не помещается в ячейку.** `const narx = 300`, потом `var b int8 = narx` → `(overflows)` (раздел
«Маленькая проверка» выше). **Исправление:** выберите ячейку побольше, например `int`.

Номера после него сдвинутся на один, и смысл сохранённых чисел тихо изменится, без всякой ошибки. Для сохраняемых


<details>
<summary>Ответ</summary>

`0 2`. `Qizil` («красный») — первая строка: `iota` = 0. `Sariq` («жёлтый») — 1, `Yashil` («зелёный») — 2.

</details>

**5.** Из прошлого урока: `var x int8 = 127`, потом `x++` и `fmt.Println(x)`. Что выведется на экран? Почему на этот

<details>
<summary>Ответ</summary>

`-128`. Здесь 128 не записано в коде готовым числом: оно вычисляется с переменной, пока программа работает, поэтому
ячейка `int8` тихо переходит через край (overflow). А константа записана в коде готовой, и Go проверяет её заранее.

</details>
