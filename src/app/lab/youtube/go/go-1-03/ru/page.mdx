## Что вы узнаете

Перемножим 100 двоек и получим 31-значное число: 1 267 650 600 228 229 401 496 703 205 376. А самый большой
целочисленный тип в Go вмещает числа не длиннее 20 цифр. Если записать такое число в программу на Go, она
скомпилируется? Сегодня узнаем ответ и разберём четыре практические ловушки, которые из него следуют.

**Главная идея:** константа без типа, записанная в коде (нетипизированная константа), живёт в компиляторе как
точное математическое число. Помещается ли она в тип, проверяется только тогда, когда она получает тип.

В конце урока вы сможете:

- записать константу через `const` и объяснить разницу между нетипизированной и типизированной константой;
- объяснить, почему `fmt.Println(big)`, `0.1 + 0.2 == 0.3`, `n * time.Second` и `time.Sleep(2)` дают неожиданный
  результат, и исправить их;
- написать список состояний с `iota`;
- объяснить, почему номера, которые сохраняются в базе данных, нельзя доверять `iota`.

Три главных новых слова сегодня:

| Слово | Простой смысл | Термин |
|---|---|---|
| константа | значение, которое задаётся при написании программы и потом не меняется: `const` | constant |
| нетипизированная константа | константа, у которой ещё нет типа: как математическое число на бумаге, ещё не положенное в ячейку памяти | untyped constant |
| `iota` | порядковый номер внутри группы `const`: сам считает 0, 1, 2, … | iota |

По пути встретятся два вспомогательных слова: **битовый сдвиг** (`<<`, `>>`) и **тип по умолчанию** (тип, который
Go выбирает сам). Объясним оба там, где они понадобятся.

## Битовый сдвиг: сколько это — `1 << 100`?

В [GO-1.02](/lab/youtube/go#go-1-02) мы видели: компьютер хранит число в битах. Бит — лампочка, которая горит или не
горит, 1 или 0. В `int64` 64 бита.

В десятичной системе, если дописать к числу 0 в конце, оно станет в 10 раз больше: 7 → 70. В двоичной системе
ноль в конце делает число **в 2 раза** больше. В Go это делает знак `<<`: `1 << 3` значит «сдвинь биты единицы на
3 шага влево и допиши справа нули». Эта операция называется **битовый сдвиг** (по-английски **bit shift**).

| Выражение | В двоичной | В десятичной |
|---|---|---|
| `1` | `1` | 1 |
| `1 << 1` | `10` | 2 |
| `1 << 2` | `100` | 4 |
| `1 << 3` | `1000` | 8 |
| `1 << 10` | `1` и десять `0` | 1 024 |
| `1 << 100` | `1` и сто `0` (101 бит) | 1 267 650 600 228 229 401 496 703 205 376 |

`>>` — наоборот, сдвиг вправо: биты справа отбрасываются, каждый шаг делит число на 2. Например, `8 >> 1` = 4,
`8 >> 3` = 1.

Для `1 << 100` нужен 101 бит. А самый большой целочисленный тип в Go — 64 бита (`int64`, `uint64`).

## Константа: `const`

Некоторые значения в программе никогда не меняются: 60 секунд в минуте, число π. Если сделать их переменными
(ярлыками), кто-нибудь может случайно записать в них другое значение через `=`. Поэтому в Go есть **константа**
(по-английски **constant**): её значение задаётся при написании программы и потом не меняется. Она пишется с
ключевым словом `const`: `const daqiqa = 60` (`daqiqa` — «минута»).

Вот `big/main.go` из папки курса. Этот пример есть в официальных правилах Go (Go spec), а в Go Tour — похожий:

```go filename="big/main.go" showLineNumbers
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(big >> 98)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1–3 | `package main`, `import "fmt"` | знакомый шаблон |
| 5 | `const big = 1 << 100` | константа `big`, её значение — единица, сдвинутая влево 100 раз. Записана вне `main`, поэтому видна во всём файле. У константы пишется `=`, а не `:=` |
| 7 | `func main() {` | программа начинается здесь |
| 8 | `fmt.Println(big >> 98)` | сдвигает `big` вправо 98 раз и выводит результат |

Остановитесь и подумайте: эта программа скомпилируется? Если да, что она выведет?
**A)** ошибка компиляции: 101 бит не помещается в 64 · **B)** `4` · **C)** другое, неверное число из-за
переполнения

<details>
<summary>Ответ</summary>

**B: `4`.** Программа компилируется и работает. `big` равно 2¹⁰⁰, а сдвиг вправо на 98 — то же, что деление на
2⁹⁸: 2¹⁰⁰ / 2⁹⁸ = 2² = 4. Если вы выбрали «A», вы думали, что константа тоже должна поместиться в ячейку `int64`.
Если «C» — вы ждали тихой прокрутки, как у `x++` в GO-1.02. Константа не прокручивается.

</details>

```console
$ go run ./big
4
```

Большое число так и не попало в память программы. Это видно в машинном коде, который делает компилятор. Команда
ниже длинная, разберём её по частям:

- `go build -gcflags=-S` компилирует программу и выводит машинный код, созданный компилятором (по-английски
  **assembly**, ассемблер);
- `-o /dev/null` не сохраняет готовый файл программы, нам нужен только листинг;
- `2>&1 | grep -A1 'stmp_0 SRODATA'` оставляет из длинного листинга только строку с `stmp_0 SRODATA` и одну строку
  после неё (`2>&1` отправляет листинг компилятора тоже в `grep`).

```console
$ go build -gcflags=-S -o /dev/null ./big 2>&1 | grep -A1 'stmp_0 SRODATA'
main..stmp_0 SRODATA static size=8
	0x0000 04 00 00 00 00 00 00 00                          ........
```

Для функции `main` есть только одно готовое значение: `size=8`, то есть 8 байт. Байты во второй строке
`04 00 00 00 00 00 00 00` — это число 4. 101-битного числа нигде нет. Компилятор сам выполнил вычисление и
положил в программу только результат, `4`.

## Нетипизированная константа: число без типа

Почему не было ошибки, хотя `big` не помещается в 64 бита? Представьте математика: на бумаге он может написать
число любой длины. А в ячейке памяти место ограничено: в `int64` 64 бита, не больше.

```text
на бумаге (компилятор):   big = 1 267 650 600 228 229 401 496 703 205 376   ← точное число, без типа
в ячейке памяти (int64):  [ 64 бита ]   ← максимум 9 223 372 036 854 775 807
```

`big` пока на бумаге: у неё **нет типа**. Такая константа называется **нетипизированной константой** (по-английски
**untyped constant**). Официальные правила Go (спецификация) говорят:

- числовые константы имеют **точные значения** и не переполняются;
- каждый компилятор Go обязан хранить целые константы **минимум в 256 битах**;
- помещается ли нетипизированная константа в тип, проверяется только **когда она получает тип**.

Тип появляется тремя способами, и все три мы сегодня увидим: когда константу записывают в переменную с типом
(`var f float64 = math.Pi`), когда её вычисляют вместе со значением, у которого есть тип (`2 * time.Second`), и
когда её передают в функцию (`fmt.Println(big)`).

В `big >> 98` константа `big` так и не получила тип: компилятор сделал всё вычисление на бумаге и получил `4`.
Тип получило только `4`, когда его передали в `Println`, а `4` помещается в любой тип.

Константа с типом называется **типизированной константой** (**typed constant**): `const x int8 = 127` или
`int8(127)`. Типизированная константа должна помещаться в свой тип **после каждой операции**. Теперь ошибка из
прошлого урока понятна:

| Выражение | Тип | Когда проверяется | Результат |
|---|---|---|---|
| `1 << 100 >> 98` | нетипизированная | когда получает тип, то есть в конце | `4`, ошибки нет |
| `int8(127) + 1` | типизированная (`int8`) | после каждой операции: сразу после `+ 1` | 128 не помещается в `int8` → ошибка компиляции |
| `x++` (`x` — переменная) | переменная `int8` | компилятор не проверяет | молча прокручивается во время работы → −128 |

## Где предел: 512 бит

Спецификация говорит «минимум 256 бит». На практике собственный компилятор Go хранит целые константы **до 512 бит**.
Это число записано в коде проверки типов компилятора: `const prec = 512`. Проверим двумя программами. В
`huge/main.go` сдвигаем единицу влево 511 раз:

```go filename="huge/main.go" showLineNumbers
package main

import "fmt"

const huge = 1 << 511

func main() {
	fmt.Println(huge >> 510)
}
```

`edge/main.go` отличается только двумя числами: `1 << 512` в строке 5 и `huge >> 511` в строке 8:

```go filename="edge/main.go" showLineNumbers
package main

import "fmt"

const huge = 1 << 512

func main() {
	fmt.Println(huge >> 511)
}
```

Угадайте: **A)** обе выведут `2` · **B)** `huge` выведет `2`, `edge` не скомпилируется · **C)** обе не
скомпилируются

<details>
<summary>Ответ</summary>

**B.** `1 << 511` — 512-битное число: оно укладывается в предел, и 2⁵¹¹ / 2⁵¹⁰ = 2. А в `1 << 512` уже 513 бит:
компилятор не может его хранить. Если вы выбрали «A», вы думали, что константа может быть бесконечно большой: предел
есть и в правилах, и в компиляторе.

</details>

```console
$ go run ./huge
2
```

```console
$ go run ./edge
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/edge
edge/main.go:5:16: constant shift overflow
```

Читаем ошибку. Первая строка (`# …/edge`) говорит, какой пакет компилировался. Вторая строка: файл
`edge/main.go`, строка 5, символ 16 — это как раз знак `<<`. *constant shift overflow* — «переполнение константы
при сдвиге». Этот предел касается только **целых** констант.

## math.Pi: 63 цифры, а float64 хранит 16

Стандартная библиотека (пакеты, которые идут вместе с Go) пользуется этой возможностью. В файле `const.go` пакета
`math` число π записано так (сокращённо):

```go
// Mathematical constants.
const (
	E   = 2.71828182845904523536028747135266249775724709369995957496696763
	Pi  = 3.14159265358979323846264338327950288419716939937510582097494459
	Phi = 1.61803398874989484820458683436563811772030917980576286213544862
)
```

`Pi` записано 63 цифрами. А `float64` (тип дробных чисел из [GO-0.03](/lab/youtube/go/go-0-03/ru)) хранит примерно 16 цифр.
Есть ещё один дробный тип: `float32` — 32-битное, менее точное дробное число. Так как `Pi` нетипизированная, в
какой тип её ни запиши, точное значение округлится до ближайшего числа этого типа.

Это `pi/main.go`:

```go filename="pi/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	var f32 float32 = math.Pi
	var f64 float64 = math.Pi
	fmt.Printf("float32: %.20f\n", f32)
	fmt.Printf("float64: %.20f\n", f64)
	fmt.Println("haqiqiy: 3.14159265358979323846...")
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–6 | `import ( "fmt" "math" )` | подключает два пакета; несколько пакетов пишутся в скобках, каждый на своей строке |
| 9 | `var f32 float32 = math.Pi` | переменная `f32` типа `float32`: здесь `Pi` получает тип |
| 10 | `var f64 float64 = math.Pi` | то же самое для `float64` |
| 11 | `fmt.Printf("float32: %.20f\n", f32)` | `Printf` выводит текст по шаблону: вместо `%.20f` подставляется `f32` с 20 цифрами после точки; `\n` — переход на новую строку |
| 12 | `fmt.Printf("float64: %.20f\n", f64)` | то же для `f64` |
| 13 | `fmt.Println("haqiqiy: …")` | настоящее начало π для сравнения, обычный текст (`haqiqiy` — «настоящее») |

Угадайте: в какой строке больше верных цифр настоящего π? **A)** в обеих одинаково · **B)** в `float64` ·
**C)** в обеих верны все 20 цифр

<details>
<summary>Ответ</summary>

**B.** У `float64` 64 бита, у `float32` — 32: в меньшее число бит помещается меньше цифр. Не «C»: `%.20f`
*выводит* 20 цифр, но там, где тип не смог сохранить цифры, стоит «остаток» округления.

</details>

```console
$ go run ./pi
float32: 3.14159274101257324219
float64: 3.14159265358979311600
haqiqiy: 3.14159265358979323846...
```

| | Значение | Верные цифры |
|---|---|---|
| настоящее π | 3.14159265358979323846… | — |
| `float32` | 3.141592**74**101257324219 | 7 (`3.141592`) |
| `float64` | 3.141592653589793**11**600 | 16 (`3.141592653589793`) |

Ошибка не в константе: `math.Pi` точна. Точность теряется только на последнем шаге, когда значение записывают в
тип.

## Ловушка 1: тип по умолчанию

Теперь ловушки. Первая: что будет, если вывести `big` напрямую? Это `limit/main.go`:

```go filename="limit/main.go" showLineNumbers
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(big)
}
```

`fmt.Println` принимает значение любого типа, но какой-то тип у значения быть обязан. Если у константы нет типа,
Go выбирает его сам. Это называется **тип по умолчанию** (по-английски **default type**): `int` для
нетипизированной целой константы, `float64` для нетипизированной дробной. На этом компьютере `int` — 64 бита.

```console
$ go run ./limit
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/limit
limit/main.go:8:14: cannot use big (untyped int constant 1267650600228229401496703205376) as int value in argument to fmt.Println (overflows)
```

Строка 8, символ 14 (`big`): *cannot use big (untyped int constant …) as int value in argument to fmt.Println
(overflows)* — «нельзя использовать `big` (нетипизированная целая константа с таким значением) как значение `int`
в аргументе `fmt.Println` (переполнение)». Компилятор даже показал само число.

Та же ошибка бывает и с `math.MaxUint64`. Это наибольшее значение `uint64`, 2⁶⁴ − 1. В пакете `math` это
нетипизированная константа: `MaxUint64 = 1<<64 - 1`. Это `maxuint/main.go`:

```go filename="maxuint/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	fmt.Println(math.MaxUint64)
}
```

```console
$ go run ./maxuint
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/maxuint
maxuint/main.go:9:14: cannot use math.MaxUint64 (untyped int constant 18446744073709551615) as int value in argument to fmt.Println (overflows)
```

Тип по умолчанию — `int`, а `int` вмещает максимум 2⁶³ − 1. Решение: указать тип самому (преобразование).
`maxfix/main.go`:

```go filename="maxfix/main.go" showLineNumbers
package main

import (
	"fmt"
	"math"
)

func main() {
	fmt.Println(uint64(math.MaxUint64))
}
```

```console
$ go run ./maxfix
18446744073709551615
```

`uint64(math.MaxUint64)` — константа получила тип `uint64`, и число в него помещается.

А `big` не помещается ни в один целочисленный тип. Её можно сделать `float64(big)` (`float64` хранит только около
16 цифр; увидим ниже, в «Частых ошибках»). Если во время работы программы нужно точное большое число, в Go для
этого есть пакет `math/big`.

## Ловушка 2: 0.1 + 0.2 == 0.3

Сложим 0.1 и 0.2. Равен ли результат 0.3? Это `float/main.go`:

```go filename="float/main.go" showLineNumbers
package main

import "fmt"

const a, b = 0.1, 0.2

func main() {
	fmt.Println(a+b == 0.3)

	x, y := 0.1, 0.2
	fmt.Println(x+y == 0.3)
	fmt.Println(x + y)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `const a, b = 0.1, 0.2` | две константы в одной строке: `a` = 0.1, `b` = 0.2 (нетипизированные) |
| 8 | `fmt.Println(a+b == 0.3)` | равна ли сумма констант 0.3? Ответ `==` — `true` или `false` |
| 10 | `x, y := 0.1, 0.2` | две переменные в одной строке; по типу по умолчанию обе `float64` |
| 11 | `fmt.Println(x+y == 0.3)` | тот же вопрос, но с переменными |
| 12 | `fmt.Println(x + y)` | выводит саму сумму |

Угадайте, что выведут первые две строки: **A)** `true`, `true` · **B)** `true`, `false` · **C)** `false`, `false`

<details>
<summary>Ответ</summary>

**B: `true`, потом `false`.** Константы компилятор считает точно: 0.1 + 0.2 — ровно 0.3. А в переменных `float64`
числа 0.1 и 0.2 нельзя точно записать в двоичной системе — так же, как в десятичной 1/3 = 0.333… тянется
бесконечно. `float64` округляет примерно после 16 цифр, и мелкие ошибки накапливаются. Если вы выбрали «A», вы
думали, что компьютер хранит дроби точно. Если «C» — что константы тоже считаются во `float64`.

</details>

```console
$ go run ./float
true
false
0.30000000000000004
```

В одной и той же программе ответ и `true`, и `false`. Третья строка показывает причину: сумма во `float64` чуть
больше 0.3.

## Ловушка 3: `n * time.Second`

Третья ловушка связана со временем. Для работы со временем в Go есть пакет `time`. В нём есть отдельный тип для
промежутка времени — `Duration` («длительность»). Вот он из файла `time/time.go` (сокращённо):

```go
type Duration int64

const (
	Nanosecond  Duration = 1
	Microsecond          = 1000 * Nanosecond
	Millisecond          = 1000 * Microsecond
	Second               = 1000 * Millisecond
	Minute               = 60 * Second
	Hour                 = 60 * Minute
)
```

`type Duration int64` создаёт новый тип: внутри у него `int64`, но это **не** `int64`, а отдельный тип. Единица
счёта — наносекунда (миллиардная доля секунды). `time.Second` — константа типа `Duration`, 1 000 000 000
наносекунд. `Println` выводит `Duration` с единицей: `2s` (2 секунды), `2ns` (2 наносекунды).

Загадка. Это `duration/main.go`, в нём одна ошибка:

```go filename="duration/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	fmt.Println(2 * time.Second)

	n := 2
	fmt.Println(n * time.Second)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 9 | `fmt.Println(2 * time.Second)` | умножает 2 на `time.Second` |
| 11 | `n := 2` | переменная `n`, значение 2 |
| 12 | `fmt.Println(n * time.Second)` | умножает `n` на `time.Second` |

Какая строка не скомпилируется и почему? Остановитесь и подумайте. **A)** строка 9 · **B)** строка 12 ·
**C)** обе работают

<details>
<summary>Ответ</summary>

**B: строка 12.** `2` в строке 9 — нетипизированная константа: она молча принимает тип `Duration`, и
`2 * time.Second` = `2s`. А `n` в строке `n := 2` получила тип по умолчанию `int`: теперь это переменная типа
`int`. Go не смешивает разные типы ([GO-0.03](/lab/youtube/go/go-0-03/ru), [GO-1.02](/lab/youtube/go#go-1-02)), а `int` и `Duration` —
разные типы. Если вы выбрали «A», вы думали, что `2` — это `int`. Если «C» — что `n` подстраивается, как `2`: но тип
переменной всегда определён.

</details>

```console
$ go run ./duration
# github.com/abdurahmon27/go-backend-uz/lessons/003-const-iota/duration
duration/main.go:12:14: invalid operation: n * time.Second (mismatched types int and time.Duration)
```

Строка 12, символ 14 (`n`): *invalid operation: n * time.Second (mismatched types int and time.Duration)* —
«недопустимая операция: типы не совпадают, `int` и `time.Duration`». Если сделать `n` типа `int64`, тоже не
сработает: `Duration` — не `int64`, а отдельный тип.

Решение: преобразовать `n` в `time.Duration`. В документации пакета `time` есть ровно такой пример.
`durfix/main.go`:

```go filename="durfix/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	n := 2
	fmt.Println(time.Duration(n) * time.Second)
}
```

- **Строка 10:** `time.Duration(n)` делает из `n` новое значение типа `Duration`; теперь обе стороны одного типа.

```console
$ go run ./durfix
2s
```

## Ловушка 4: `time.Sleep(2)`

Четвёртая ловушка — обратная сторона того же правила, и она опаснее. `time.Sleep(d)` приостанавливает программу
как минимум на `d`. `d` — это `Duration`. Это `sleep2/main.go`:

```go filename="sleep2/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	start := time.Now()
	time.Sleep(2) // 2 sekund kutadi deb o'ylaysizmi?
	fmt.Println(time.Since(start) < time.Second)

	var d time.Duration = 2
	fmt.Println(d)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 9 | `start := time.Now()` | записывает текущее время в `start` |
| 10 | `time.Sleep(2)` | приостанавливает программу на «2». Вопрос в комментарии: думаете, ждёт 2 секунды? |
| 11 | `fmt.Println(time.Since(start) < time.Second)` | `time.Since(start)` — сколько времени прошло с `start`; меньше ли это 1 секунды? |
| 13 | `var d time.Duration = 2` | то же значение, что получил `Sleep`: нетипизированное `2` принимает тип `Duration` |
| 14 | `fmt.Println(d)` | выводит `d` с единицей |

Угадайте: **A)** `false` и `2s` · **B)** `true` и `2ns` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B.** Нетипизированное `2` молча становится `Duration`, а единица `Duration` — наносекунда. Программа просит не
2 секунды, а всего 2 наносекунды, то есть почти не ждёт. Поэтому прошло меньше 1 секунды: `true`. Если вы выбрали
«A», вы думали, что `2` — это секунды. Не «C»: `2` — константа, она помещается в `Duration`, ошибки нет.

</details>

```console
$ go run ./sleep2
true
2ns
```

Компилятор молчит. А программы, которые проверяют код без запуска? `go vet` идёт вместе с Go:

```console
$ go vet ./sleep2
```

`go vet` ничего не вывел: проблем он не нашёл. `staticcheck` — анализатор кода, который устанавливается отдельно
(`go install honnef.co/go/tools/cmd/staticcheck@2026.2.1`, попадает в папку `$(go env GOPATH)/bin/`):

```console
$ $(go env GOPATH)/bin/staticcheck ./sleep2
sleep2/main.go:10:13: sleeping for 2 nanoseconds is probably a bug; be explicit if it isn't (SA1004)
```

Строка 10: *sleeping for 2 nanoseconds is probably a bug; be explicit if it isn't* — «сон на 2 наносекунды,
вероятно, ошибка; если это намеренно, напишите явно». Исправление: укажите единицу —
`time.Sleep(2 * time.Second)`.

## iota: список состояний

В интернет-магазине у заказа есть состояние: неизвестно, новый, оплачен, отправлен. Программа даёт каждому
состоянию число: число легко хранить и сравнивать. Можно написать 0, 1, 2, 3 вручную. Но Go умеет считать сам: как
аппарат электронной очереди в банке, он сам выдаёт каждый следующий номер. Этот порядковый номер называется
**`iota`**: он показывает, какое по счёту это объявление в группе `const ( … )`, и в каждой группе начинается
с **0**.

Это `status/main.go`:

```go filename="status/main.go" showLineNumbers
package main

import "fmt"

type Status int

const (
	Unknown Status = iota
	New
	Paid
	Shipped
)

func main() {
	fmt.Println(Unknown, New, Paid, Shipped)

	var s Status
	fmt.Println(s == Unknown)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `type Status int` | новый тип `Status`, внутри `int` (так же, как у `Duration` внутри `int64`) |
| 7 | `const (` | объявляет несколько констант вместе, группой в скобках |
| 8 | `Unknown Status = iota` | объявление номер 0 в группе: `iota` = 0, `Unknown` = 0, тип `Status` |
| 9–11 | `New`, `Paid`, `Shipped` | выражение не написано: Go повторяет предыдущее выражение **и тип**, `Status = iota`, а `iota` на каждой строке растёт на один |
| 15 | `fmt.Println(Unknown, New, Paid, Shipped)` | выводит все четыре значения |
| 17 | `var s Status` | переменная `Status` без значения: нулевое значение |
| 18 | `fmt.Println(s == Unknown)` | равно ли `s` значению `Unknown`? |

Что на самом деле видит Go:

| Строка | Написано | Что видит Go | `iota` | Значение |
|---|---|---|---|---|
| 8 | `Unknown Status = iota` | `Unknown Status = iota` | 0 | 0 |
| 9 | `New` | `New Status = iota` | 1 | 1 |
| 10 | `Paid` | `Paid Status = iota` | 2 | 2 |
| 11 | `Shipped` | `Shipped Status = iota` | 3 | 3 |

Почему 0 — это `Unknown`? Вспомните нулевое значение из [GO-1.02](/lab/youtube/go#go-1-02): `Status` без значения равен 0.
Если бы 0 был `New`, каждое забытое состояние выглядело бы как «новый заказ». Поэтому 0 не должен быть осмысленным
состоянием.

Угадайте: **A)** `0 1 2 3` и `true` · **B)** `1 2 3 4` и `false` · **C)** `Unknown New Paid Shipped` и `true`

<details>
<summary>Ответ</summary>

**A.** `iota` начинается с 0, а нулевое значение `s` — 0, то есть `Unknown`. Если вы выбрали «B», вы думали, что
счёт начинается с 1. Не «C»: `Status` — обычное число, `Println` не знает его имени и выводит только число.

</details>

```console
$ go run ./status
0 1 2 3
true
```

Не забывайте: в Go нет отдельного типа **перечисления** (enum — тип, который принимает только перечисленные
значения). `Status` — всего лишь тип на основе `int`, поэтому `Status` со значением 42 тоже допустим (увидим ниже,
в «Частых ошибках»).

`iota` можно сочетать и с битовым сдвигом. Пример из руководства «Effective Go»: килобайт, мегабайт, гигабайт и
терабайт получаются из одной формулы. Это `sizes/main.go`:

```go filename="sizes/main.go" showLineNumbers
package main

import "fmt"

const (
	_  = iota
	KB = 1 << (10 * iota)
	MB
	GB
	TB
)

func main() {
	fmt.Println(KB, MB, GB, TB)
}
```

| Строка | Код | `iota` | Значение |
|---|---|---|---|
| 6 | `_ = iota` | 0 | отбрасывается: `_` значит «это значение не нужно» |
| 7 | `KB = 1 << (10 * iota)` | 1 | `1 << 10` = 1 024 |
| 8 | `MB` (повторяется то же выражение) | 2 | `1 << 20` = 1 048 576 |
| 9 | `GB` | 3 | `1 << 30` = 1 073 741 824 |
| 10 | `TB` | 4 | `1 << 40` = 1 099 511 627 776 |

```console
$ go run ./sizes
1024 1048576 1073741824 1099511627776
```

Точнее говоря, это KiB, MiB, GiB, TiB (степени 1024, а не 1000).

## Бонус: iota и база данных — тихая ошибка

И бонус: опасность `iota` на рабочих серверах (production). Представьте, что `Status` записывается в базу данных
числом. База данных — место, где программа долго хранит данные (таблица на диске). В первой версии (v1)
`Paid` = 2, и в базе тысячи заказов сохранены с `2`.

Однажды кто-то добавляет состояние `Cancelled` («отменён») после `New`. Это `bug/main.go`:

```go filename="bug/main.go" showLineNumbers
package main

import "fmt"

type Status int

// v2
const (
	Unknown Status = iota
	New
	Cancelled
	Paid
	Shipped
)

func main() {
	saved := Status(2) // bazada saqlangan: v1'da bu Paid edi
	fmt.Println("to'langanmi?", saved == Paid)
	fmt.Println("bekor qilinganmi?", saved == Cancelled)
}
```

- **Строки 7–14:** вторая версия (v2): `Cancelled` добавлен между `New` и `Paid`.
- **Строка 17:** `saved := Status(2)` — число, прочитанное из базы и преобразованное в тип `Status`. В v1 это был
  `Paid`. (Комментарий: «сохранено в базе: в v1 это был Paid».)
- **Строки 18–19:** этот заказ оплачен (`to'langanmi?`)? Отменён (`bekor qilinganmi?`)?

Угадайте: **A)** `true`, `false` · **B)** `false`, `true` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B.** После добавления `Cancelled` все значения после него сдвигаются на один:

| Состояние | v1 | v2 |
|---|---|---|
| `Unknown` | 0 | 0 |
| `New` | 1 | 1 |
| `Cancelled` | — | **2** |
| `Paid` | **2** | 3 |
| `Shipped` | 3 | 4 |

`2` в базе теперь означает `Cancelled`. Не «C»: код написан правильно, ошибки нет — поэтому эта ошибка и опасна.

</details>

```console
$ go run ./bug
to'langanmi? false
bekor qilinganmi? true
```

Оплаченные заказы в базе (`2`) выглядят отменёнными, а отправленные (`3`) — будто они ещё только оплачены. И никакой
ошибки не появляется.

Правило: номер, который ушёл в базу данных или в сеть, **никогда не меняется и не используется повторно**. Поэтому
для таких значений пишите номера вручную или храните в базе не число, а имя состояния. Это `fix/main.go`:

```go filename="fix/main.go" showLineNumbers
package main

import "fmt"

type Status int

// bazada saqlanadigan qiymatlar: har biri qo'lda yoziladi va hech qachon o'zgarmaydi
const (
	Unknown   Status = 0
	New       Status = 1
	Paid      Status = 2
	Shipped   Status = 3
	Cancelled Status = 4 // yangi qiymat oxiriga
)

func main() {
	saved := Status(2)
	fmt.Println("to'langanmi?", saved == Paid)
}
```

- **Строки 9–13:** каждое значение записано вручную; новый `Cancelled` = 4 добавлен в конец, старые остались на
  своих местах. (Комментарий: «значения, которые хранятся в базе: каждое пишется вручную и никогда не меняется».)

```console
$ go run ./fix
to'langanmi? true
```

Если удаляете значение, не отдавайте его номер другому: в списке с `iota` оставьте на его месте `_`. В Protocol
Buffers (формат Google для передачи данных между программами) номер каждого значения перечисления тоже пишется
вручную, и руководство настоятельно рекомендует не использовать удалённые номера повторно. Его руководство по стилю
рекомендует и первое значение, 0, делать `_UNSPECIFIED` («не задано») — как наш `Unknown`.

## Частые ошибки

**1. Добавить новое значение в середину списка с `iota`.** Самая опасная ошибка урока, мы видели её в разделе
«Бонус: iota и база данных»: ошибки нет, но все старые номера в базе меняют смысл. **Исправление:** для
сохраняемых значений пишите номера вручную (`fix/main.go`) или храните имя состояния.

**2. Передать большую нетипизированную константу прямо в `Println`.** `fmt.Println(big)` и
`fmt.Println(math.MaxUint64)` — мы видели это в разделе «Ловушка 1: тип по умолчанию»: тип по умолчанию `int`, и
число в него не помещается. **Исправление:** укажите тип явно: `uint64(math.MaxUint64)`.

**3. Преобразовать `big` в `uint64`.** (Этого примера нет в папке курса, он запущен отдельно.)

```go
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(uint64(big))
}
```

```console
$ go run uint64big/main.go
# command-line-arguments
uint64big/main.go:8:21: constant 1267650600228229401496703205376 overflows uint64
```

Строка 8, символ 21: *constant … overflows uint64* — «константа не помещается в `uint64`». 101-битное число не
помещается ни в один целочисленный тип. **Исправление:** `float64(big)` (точно сохраняется около 16 цифр) или пакет
`math/big`, если нужно точное число. (Этого примера тоже нет в папке курса.)

```go
package main

import "fmt"

const big = 1 << 100

func main() {
	fmt.Println(float64(big))

```


`1.2676506002282294e+30` — это «1.2676506002282294 × 10³⁰». `Println` вывел число в коротком виде: 17 цифр вместо
31. `float64` хранит около 16 цифр, поэтому последние цифры больших целых чисел могут теряться.

**4. Думать, что `time.Sleep(2)` — это 2 секунды.** Мы видели это в разделе «Ловушка 4»: нетипизированное `2`
становится `Duration`, то есть 2 наносекундами. И компилятор, и `go vet` молчат. **Исправление:** всегда пишите
единицу: `time.Sleep(2 * time.Second)`.

**5. Умножить переменную `int64` на `time.Second`.** Можно подумать, что сработает, ведь внутри `Duration` —
`int64`. (Нет в папке курса.)

```go
package main

import (
	"fmt"
	"time"

```

```console
$ go run int64dur/main.go
```

«Типы не совпадают, `int64` и `time.Duration`». `type Duration int64` создаёт новый, отдельный тип.
**Исправление:** `time.Duration(n) * time.Second`.

**6. Сравнивать `float64` через `==`.** Мы видели это в разделе «Ловушка 2»: `x+y == 0.3` — `false`.
**Исправление:** проверяйте не равенство, а то, что разница очень мала. `math.Abs` — модуль числа (число без
знака), `1e-9` — это 0.000000001. (Нет в папке курса.)

```go
	"fmt"
	"math"

func main() {

}
```

```console
$ go run floatcmp/main.go
true
```

**7. Думать, что `iota` даёт в Go настоящее перечисление.** Можно подумать, что `Status` принимает только четыре
значения из списка. (Нет в папке курса.)

```go
package main

import "fmt"

type Status int

const (
	Unknown Status = iota
	New
	Paid
	Shipped
)

func main() {
	var s Status = 42
	fmt.Println(s, s == Unknown)
}
```

```console
$ go run status42/main.go
42 false
```

Ошибки нет: `Status` — обычный тип на основе `int`, и `42` в него помещается. **Исправление:** сами проверяйте, что
значение из базы или из сети лежит между `Unknown` и `Shipped`.

**8. Попытаться изменить константу.** (Нет в папке курса.)

```go
package main

import "fmt"

const daqiqa = 60

func main() {
	daqiqa = 61
	fmt.Println(daqiqa)
}
```

```console
$ go run ozgarmas/main.go

ozgarmas/main.go:8:2: cannot assign to daqiqa (neither addressable nor a map index expression)
```

Строка 8, символ 2: *cannot assign to daqiqa* — «нельзя присвоить значение `daqiqa`». Текст в скобках («ни

записать. **Исправление:** если значение должно меняться, используйте переменную, а не константу: `daqiqa := 60`.

## Проверьте себя

Сначала ответьте сами, потом откройте ответ.

**1.** Что выведет эта программа? **A)** `8` · **B)** `128` · **C)** ошибка компиляции

```go
package main

import "fmt"

const c = 1 << 10

func main() {
	fmt.Println(c >> 7)
}
```

<details>
<summary>Ответ</summary>

**A: `8`.** `1 << 10` = 1024 = 2¹⁰. Сдвиг вправо на 7 — деление на 2⁷: 2¹⁰ / 2⁷ = 2³ = 8.

```console
$ go run savol1/main.go
8
```

</details>

**2.** Что выведет эта программа? **A)** `1 2 3` · **B)** `1 2 4` · **C)** `0 1 2`

```go
package main

import "fmt"

const (
	_ = iota
	A
	B
	_
	C
)

func main() {
	fmt.Println(A, B, C)
}
```

<details>
<summary>Ответ</summary>

**B: `1 2 4`.** `iota` растёт с каждым объявлением, в том числе с теми, что отброшены через `_`: `_` = 0, `A` = 1,
`B` = 2, `_` = 3, `C` = 4.

```console
$ go run savol2/main.go
1 2 4
```

</details>

**3.** Почему `const big = 1 << 100` компилируется без ошибок, а `fmt.Println(big)` — нет?

<details>
<summary>Ответ</summary>

`big` — нетипизированная константа: компилятор хранит её как точное число минимум в 256 бит, а помещается ли она в
тип, проверяется только когда она получает тип. При передаче в `Println` константа `big` получает тип по умолчанию
`int`, а 101-битное число в `int` не помещается.

</details>

**4.** На сколько `time.Sleep(5)` приостановит программу?

<details>
<summary>Ответ</summary>

Минимум на 5 **наносекунд**, то есть почти не приостановит. Нетипизированное `5` становится `Duration`, а единица
`Duration` — наносекунда. Для 5 секунд: `time.Sleep(5 * time.Second)`.

</details>

**5.** Из [GO-1.02](/lab/youtube/go#go-1-02): `big := 300`, потом `fmt.Println(int8(big))`. Что выведется?

<details>
<summary>Ответ</summary>

`44`. Преобразование между целыми типами берёт только младшие 8 бит: 300 = 256 + 44. Это `convert/main.go` из папки
GO-1.02; его вторая строка преобразует `int8(200)` через переменную:

```console
$ go run ./convert
44
-56
```

Внимание: здесь `big` — **переменная**. Если же написать `fmt.Println(int8(300))` прямо с константой, компилятор
выдаст ошибку `constant 300 overflows int8`: константа обязана поместиться в тип, когда получает его.

</details>

🟠 **Сложно:** почему `1.5 * time.Second` не компилируется, а `1500 * time.Millisecond` работает?

<details>
<summary>Ответ</summary>

`time.Second` — это `Duration`, внутри `int64`. Нетипизированное `1.5` сначала должно стать `Duration`, то есть
целым числом, но 1.5 точно в целое не превращается, а константа никогда не округляется: компилятор отказывает.
В `homework/hard/main.go` эта строка закомментирована; мы запустили её отдельно:

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	fmt.Println(1.5 * time.Second)
}
```

```console
$ go run yarim/main.go
# command-line-arguments
yarim/main.go:9:14: 1.5 (untyped float constant) truncated to int64
```

«1.5 (нетипизированная дробная константа) обрезается при преобразовании в `int64`». Правильные способы:
`1500 * time.Millisecond` или `time.Second * 3 / 2` (сначала 3 с, потом целочисленное деление на 2).

```console
$ go run ./homework/hard
1.5s
1.5s
```

</details>

🔴 **Гуру:** найдите, где в пакете `time` используется `iota`, и объясните, почему `Month` начинается с 1.

<details>
<summary>Ответ</summary>

В `time/time.go`: `January Month = 1 + iota` — месяцы от 1 до 12, как их пишут люди, и `Sunday Weekday = iota` —
дни недели с 0. `homework/guru/main.go`:

```console
$ go run ./homework/guru
January 1
Sunday 0
%!Month(0)
```

`time.Month` и `time.Weekday` умеют выводить своё имя, поэтому напечатались `January` и `Sunday`. `time.Month` без
значения равен 0, но месяца 0 нет: Go показывает его как `%!Month(0)`. То есть здесь команда Go предпочла правило
«номер равен номеру, которым пользуются люди» правилу «нулевое значение должно быть осмысленным». Оба варианта —
сознательный выбор; главное — делать этот выбор осознанно.

</details>
