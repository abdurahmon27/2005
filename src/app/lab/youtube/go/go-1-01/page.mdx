## Nimani oʻrganasiz

GO-X.01 dagi yigirma qatorlik HTTP API'ning binary'si 8 659 683 bayt, yaʼni 8.66 MB. Frontend'da 8 MB'lik bundle
koʻrsangiz, darhol bundle analyzer ochasiz. Go binary'sida bu megabaytlar nima, va ulardan qanchasi bizning kodimiz?
Bugun shuni oʻlchaymiz.

**Bitta gʻoya:** Go binary'sining katta qismi bizning kod emas. Har bir dasturda runtime bor. Import qilingan
paketlardan linker faqat chaqiriladigan funksiyalarni va har bir paketning `init` kodini qoldiradi. Tizimdagi
maʼlumot (vaqt zonalari bazasi) esa binary'ga umuman kirmaydi: uni `import _` bilan ataylab qoʻshasiz.

Dars oxirida siz:

- har qanday Go binary'sini `go tool nm` va 10 qatorlik `paketlar.sh` skripti bilan paketlar boʻyicha oʻlchay olasiz;
- ichi boʻsh Go dasturi nega 1.8 MB ekanini va bu narxdan qaysi qismini olib tashlash mumkinligini tushuntira olasiz;
- bitta funksiya uchun import qilingan paket binary'ni nega ikki barobar kattalashtirishini `init` orqali ayta olasiz;
- `FROM scratch` image'dagi `unknown time zone` xatosini `import _ "time/tzdata"` yoki distroless bilan tuzata olasiz.

Bugungi uchta asosiy yangi tushuncha:

| Tushuncha | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| runtime'ning doimiy narxi | GC, scheduler va ularning jadvallari har bir Go binary'si ichida: ichi boʻsh dastur ham 1.8 MB | runtime (fixed cost) |
| linker tree-shaking va `init` | linker chaqirilmagan funksiyalarni tashlaydi, lekin paketlarning `init` kodi va global oʻzgaruvchilari qoladi | dead-code elimination, package initialization |
| `import _ "…"` | paketni nomsiz, faqat `init`i (yon taʼsiri) uchun ulash, `import 'dotenv/config'` kabi | blank import |

Ikkita yordamchi asbob ham bor: **`go tool nm`** (binary'dagi har bir funksiyaning hajmini beradi) va
**`-ldflags="-s -w"`** (linker'ga flag: debug maʼlumotini olib tashlaydi, faqat «Chuqurroq» boʻlimida).

## Go binary uchun bundle analyzer

Avval taxmin qiling. GO-X.01 API'si 8 659 683 bayt. Bizning yigirma qatorimiz (`main` paketining mashina kodi)
shundan qancha?

**A)** ~1 MB · **B)** ~100 KB · **C)** 2 KB'dan kam

<details>
<summary>Javob</summary>

**C: 1 595 bayt**, faylning 0.02 %. A yoki B ni tanlagan boʻlsangiz, binary'ni bundle kabi «asosan bizning kod» deb
oʻylagansiz. Go binary'sida bizning kod eng kichik qism. Qolgani nima ekanini quyida oʻlchaymiz.

</details>

Go'da tayyor bundle analyzer yoʻq. Lekin `go tool nm -size` binary'dagi har bir simvolni (funksiya yoki global
oʻzgaruvchi) hajmi bilan chiqaradi. Dars papkasidagi `paketlar.sh` shu roʻyxatdan faqat funksiyalarni olib,
ularni paketlar boʻyicha qoʻshadi:

```bash filename="paketlar.sh" showLineNumbers
#!/bin/sh
# Go binary uchun "bundle analyzer": mashina kodi (funksiyalar) baytlarini paketlar bo'yicha qo'shadi.
# Ishlatish: ./paketlar.sh <binary> [qator soni, standart 6]
# Eslatma: -ldflags="-s" bilan build qilingan faylda simvollar jadvali yo'q, natija bo'sh bo'ladi.
go tool nm -size "$1" | awk '
  $3 == "T" || $3 == "t" {
    size = $2
    name = $0; sub(/^ *[0-9a-f]+ +[0-9]+ +[A-Za-z] +/, "", name)   # nomda bo`sh joy bo`lishi mumkin
    sub(/^go:/, "", name); sub(/^type:\.(eq|hash)\./, "", name)     # kompilyator yasagan eq/hash funksiyalari
    sub(/\[.*/, "", name)                                            # generic: Foo[...] -> Foo
    slash = 0; for (i = 1; i <= length(name); i++) if (substr(name, i, 1) == "/") slash = i
    rest = substr(name, slash + 1); dot = index(rest, ".")
    pkg = (dot > 0) ? substr(name, 1, slash + dot - 1) : "runtime(asm)"   # paketsiz nom = runtime assembler kodi
    sum[pkg] += size; total += size
  }
  END { for (p in sum) printf "%8d %5.1f%% %s\n", sum[p], 100 * sum[p] / total, p; printf "%8d 100.0%% JAMI\n", total }
' | sort -rn | head -n "${2:-6}"
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 5 | `go tool nm -size "$1"` | har bir simvol uchun: manzil, hajm (bayt), tur harfi, nom. `T`/`t` — mashina kodi (funksiya) |
| 6 | `$3 == "T" \|\| $3 == "t"` | faqat funksiyalarni oladi; global oʻzgaruvchilar hisobga kirmaydi |
| 8–10 | `sub(…)` | nomni tozalaydi: kompilyator yasagan `type:.eq.`/`type:.hash.` va generic `[...]` qismi olib tashlanadi |
| 11–13 | `slash`, `dot`, `pkg` | paket nomini ajratadi: `net/http.StatusText` → `net/http`. Paketsiz nom (assembler kodi) → `runtime(asm)` |
| 14 | `sum[pkg] += size` | paket boʻyicha baytlarni qoʻshadi |
| 16–17 | `END …`, `sort -rn \| head` | foiz bilan chiqaradi, kattasidan boshlab; ikkinchi argument — nechta qator |

## Runtime: har bir Go dasturining doimiy narxi

Runtime'ning narxini eng kichik dasturda oʻlchaymiz. Yetti qatorlik «Salom, dunyo»:

```go filename="salom/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println("Salom, dunyo!")
}
```

```console
$ cd ../001-why-go/salom && go build main.go && ls -l
total 2360
-rwxr-xr-x 1 haywan users 2409990 Nov 26 17:49 main
-rw-r--r-- 1 haywan users      74 Nov 26 12:25 main.go
```

`main.go` 74 bayt, `go build` yasagan `main` esa 2 409 990 bayt. Ichini ochamiz:

```console
$ ../paketlar.sh main 4
  612609 100.0% JAMI
  437293  71.4% runtime
   29557   4.8% fmt
   25634   4.2% reflect
$ go tool nm -size main | grep ' main.main$'
  49e140         83 T main.main
```

Mashina kodining 71.4 % i `runtime` paketiniki. Bizning `main.main` funksiyamiz 83 bayt. Runtime GO-X.01 dan
tanish: garbage collector va scheduler. Yangisi shu: u API'da ham, «Salom, dunyo»da ham bor. Bu har bir Go
dasturining **doimiy narxi** (Go FAQ: runtime «is part of every Go program»).

Node bilan farqi: V8 va event loop bitta `node` faylida, u serverga bir marta oʻrnatiladi. Go'da esa har bir xizmat
oʻz runtime'ini oʻz binary'si ichida olib yuradi.

Endi bu narxni sof holda oʻlchaymiz: `fmt`ni ham olib tashlaymiz. Import yoʻq, `func main` boʻsh, dastur hech narsa
qilmaydi:

```go filename="bosh/main.go" showLineNumbers
package main

func main() {
}
```

Uning binary'si «Salom, dunyo»ning (2 409 990 bayt) qancha qismi boʻladi? Yuqorida `fmt` mashina kodining 4.8 % i edi.

**A)** ~5 %: hajmning koʻpi `fmt` edi · **B)** ~75 %: `fmt` va u tortgan paketlar chorakka yaqin ·
**C)** ~100 %: `fmt` arzimas

<details>
<summary>Javob</summary>

**B: 1 829 988 bayt, 75.9 %.** Hech narsa qilmaydigan dastur ham 1.8 MB. Bu runtime, uning jadvallari va debug
maʼlumoti. A ni tanlagan boʻlsangiz, hajmni bizning kod va `fmt` beradi deb oʻylagansiz: runtime ularsiz ham bor.
C ni tanlagan boʻlsangiz, `fmt`ning oʻzini koʻrgansiz: u kichik, lekin `reflect` kabi paketlarni tortadi. «Salom,
dunyo» bilan farq 580 002 bayt.

</details>

## Tree-shaking: linker chaqirilmagan kodni tashlaydi

Frontend'dagi tree-shaking savoli. Vite yoki Rollup `lodash-es`dan faqat chaqirilgan funksiyalarni bundle'ga qoʻyadi.
Go'da bu ishni **linker** qiladi: kompilyator har bir paketni alohida mashina kodiga aylantiradi, linker esa ularni
bitta binary'ga yigʻadi. Yigʻishda u `main.main`dan yetib boriladigan funksiyalarni qoldiradi, qolganini tashlaydi
(**dead-code elimination**).

Sinab koʻramiz. `net/http`ni import qilamiz, lekin undan bitta kichik funksiya, `http.StatusText`ni chaqiramiz. U
HTTP status kodining matnini qaytaradi: 404 uchun `Not Found`.

```go filename="statustext/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
)

func main() {
	fmt.Println(http.StatusText(404))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 3–6 | `import ( "fmt" "net/http" )` | ikkita paket: `fmt` va GO-X.01 dagi HTTP server paketi `net/http` |
| 9 | `http.StatusText(404)` | `net/http`dagi yagona chaqiruv: 404 → `"Not Found"`. Server ham, soʻrov ham yoʻq |

```console
$ cd ../statustext && CGO_ENABLED=0 go run main.go
Not Found
```

Binary qancha boʻladi? Taqqoslash uchun: «Salom, dunyo» 2.4 MB, GO-X.01 API'si 8.7 MB.

**A)** ~2.4 MB: linker ishlatilmaganini tashlaydi · **B)** ~5 MB: bir qismi qoladi · **C)** ~8.7 MB: paket butunlay
kiradi

<details>
<summary>Javob</summary>

**B: 5 143 595 bayt**, «Salom, dunyo»dan ikki barobar katta. A ni tanlagan boʻlsangiz, tree-shaking hamma
ishlatilmagan kodni tashlaydi deb oʻylagansiz: keyingi boʻlimda nega tashlay olmasligini koʻramiz. C ni tanlagan
boʻlsangiz, Go paketni butunlay qoʻshadi deb oʻylagansiz: `net/http`ning oʻz kodi haqiqatan tashlandi.

</details>

```console
$ CGO_ENABLED=0 go build -o st main.go && ls -l st
-rwxr-xr-x 1 haywan users 5143595 Nov 26 17:49 st
$ ../paketlar.sh st 400 | grep ' net/http$'
    5262   0.4% net/http
```

`net/http`ning oʻz kodi 5 262 bayt. GO-X.01 API'sida u 231 802 bayt edi, yaʼni 44 barobar kichik. Linker chaqirilmagan
funksiyalarni haqiqatan tashladi. Unda «Salom, dunyo»dan ortiq 2.7 MB qayerdan keldi?

## `init`: main'dan oldin ishlaydigan kod qoladi

JavaScript'da modulning yuqori darajadagi kodi import paytida ishlaydi: `import './polyfill'` faylidagi kod
hech narsa chaqirmasangiz ham bajariladi. Shuning uchun bundler bunday modulni tashlay olmaydi. `package.json`dagi
`"sideEffects": false` bilan siz bundler'ga «bu modullarda yon taʼsir yoʻq, tashlayver» deysiz.

Go'da bunga **paket initsializatsiyasi** toʻgʻri keladi. Har bir import qilingan paketda ikki narsa `main`dan oldin,
albatta bajariladi (Go spec, «Package initialization»):

- global oʻzgaruvchilarni boshlash: masalan, `net/http`dagi `var DefaultTransport = &Transport{…}`;
- paketning `func init()` funksiyalari.

Linker'ning boshlangʻich nuqtalari ikkita: `main.main` va barcha paketlarning init vazifalari
(`cmd/link/internal/ld/deadcode.go`). Init kodi va u chaqiradigan hamma narsa binary'da qoladi. Go'da
`"sideEffects": false` kabi bayroq yoʻq.

`statustext` binary'sidagi eng katta paketlar:

```console
$ ../paketlar.sh st 6
 1428465 100.0% JAMI
  454858  31.8% runtime
  121834   8.5% net
   59328   4.2% math/big
   51441   3.6% crypto/internal/fips140/nistec
   48111   3.4% time
$ go tool nm -size -sort size st | grep -E ' (net/http|net|crypto/x509)\.init$'
  506ac0       3754 T crypto/x509.init
  521a60       3092 T net/http.init
  4df440       2867 T net.init
$ ../paketlar.sh st 400 | grep -E ' crypto(/|$)' | wc -l
47
```

Biz `net`ni ham, `crypto`ni ham chaqirmadik. Ular init zanjiri orqali kirdi:

| Qadam | Nima | Natija |
|---|---|---|
| 1 | `main`dan oldin har bir import qilingan paketning init vazifasi (`main.inittasks`) | linker ularni tashlamaydi |
| 2 | `net/http.init`: global oʻzgaruvchilar, masalan `DefaultTransport` | `Transport` va uning dialer'i qoladi |
| 3 | `DefaultTransport` → `net.(*Dialer).DialContext` | `net` paketi: 121 834 bayt |
| 4 | TLS va sertifikatlar (`crypto/x509.init` va boshqalar) | `math/big` va 47 ta `crypto` paketi (`crypto` va `crypto/…`) |
| 5 | hammasi | binary 5 143 595 bayt, `StatusText` chaqirilmasa ham |

Kurs README'sida yana bir qoida bor: interfeysga saqlangan turning metodlari ham, shu nomli interfeys metodi biror
joyda chaqirilsa, qoladi (`math/big` qisman shu yoʻl bilan kiradi).

Ishdagi xulosa: Go'da import bepul emas. Bitta yordamchi funksiya uchun katta paketni import qilishdan oldin uning
narxini `paketlar.sh` bilan oʻlchang.

## Production holati: `FROM scratch` va vaqt zonasi

Endi binary'ga **kirmaydigan** narsa. Servis Toshkent soatini koʻrsatadi:

```go filename="vaqt/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	loc, err := time.LoadLocation("Asia/Tashkent")
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	fmt.Println("Toshkent soati:", time.Now().In(loc).Hour())
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 9 | `loc, err := time.LoadLocation("Asia/Tashkent")` | vaqt zonasini nomi boʻyicha yuklaydi: `loc` — zona, `err` — xato (GO-X.03 dagi kabi ikki qiymat) |
| 10–13 | `if err != nil { … return }` | zona topilmasa, xatoni chiqarib, toʻxtaydi |
| 14 | `time.Now().In(loc).Hour()` | hozirgi vaqtni shu zonaga oʻtkazib, soatni oladi |

Laptop'da soat toʻgʻri:

```console
$ cd ../vaqt && go build -o vaqt main.go && ./vaqt
Toshkent soati: 17
```

Uni GO-X.01 dagi `FROM scratch` image'ga qoʻyamiz. `vaqt/Dockerfile`:

```dockerfile filename="vaqt/Dockerfile"

COPY vaqt /vaqt
ENTRYPOINT ["/vaqt"]
```

```bash
docker build -t vaqt .
```

`docker run` nima chiqaradi? Laptop'da `Toshkent soati: 17` edi (Toshkent UTC+5).

**A)** `Toshkent soati: 17` · **B)** UTC soati: `12` · **C)** xato

<details>
<summary>Javob</summary>

**C: `xato: unknown time zone Asia/Tashkent`.** Vaqt zonalari bazasi binary ichida emas. `time.LoadLocation` uni
tizimdan oʻqiydi, `scratch`da esa hech qanday fayl yoʻq. A ni tanlagan boʻlsangiz, binary hamma narsani oʻzi bilan
olib yuradi deb oʻylagansiz: kod — ha, tizim maʼlumoti — yoʻq. B boshqa holatda chiqadi: pastda koʻramiz.

</details>

```console
$ docker run --rm vaqt

```

`go doc time.LoadLocation` boʻyicha bazani qidirish tartibi:

| # | Qayerdan | Laptop | `scratch` |
|---|---|---|---|
| 1 | `$ZONEINFO` muhit oʻzgaruvchisi koʻrsatgan fayl | — | — |
| 2 | Unix tizim joylari: `/usr/share/zoneinfo/` … `/etc/zoneinfo` | ✅ topadi | ❌ yoʻq |
| 3 | `$GOROOT/lib/time/zoneinfo.zip` (Go oʻrnatilgan joy) | ✅ | ❌ Go yoʻq |
| 4 | `time/tzdata` paketi, agar import qilingan boʻlsa | — | ❌ import yoʻq |

Bu xato hech boʻlmasa koʻrinadi. Yashirinrogʻi — B varianti. Zona koʻrsatilmagan `time.Now()` mahalliy zonani
(`time.Local`) ishlatadi, `scratch`da esa u jimgina UTC boʻladi. `vaqt-local/main.go`:

```go filename="vaqt-local/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	// zona ko'rsatilmagan: time.Local (scratch'da jimgina UTC)
	fmt.Println(time.Now().Format("15:04 MST"))
}
```

10-qator: `Format("15:04 MST")` — soat:daqiqa va zona nomi. Go'da format namunasi aniq sana bilan yoziladi:
`15` — soat, `04` — daqiqa, `MST` — zona.

```console
$ cd ../vaqt-local && go build -o vaqt main.go && ./vaqt
17:49 +05
```

```bash
docker build -t vaqt-local .
```

```console
$ docker run --rm vaqt-local
12:49 UTC
```

## Tuzatish: `import _ "time/tzdata"`

`time/tzdata` paketida vaqt zonalari bazasining nusxasi bor. Bizga undan hech qanday funksiya kerak emas, faqat
uning `init`i: u bazani `time` paketiga roʻyxatdan oʻtkazadi. JS'dagi `import 'dotenv/config'` kabi: modul hech
narsa eksport qilmasa ham, import qilish yetarli.

Avval oddiy import bilan urinib koʻramiz. Bu fayl kurs papkasida yoʻq, uni `vaqt-tz/main.go`dan `_` belgisini olib
tashlab, alohida papkada tekshirdik:

```go
package main

import (
	"fmt"
	"time"
	"time/tzdata"
)

func main() {
	loc, err := time.LoadLocation("Asia/Tashkent")
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	fmt.Println("Toshkent soati:", time.Now().In(loc).Hour())
}
```

```console
$ go build -o vaqt main.go
# command-line-arguments
./main.go:6:2: "time/tzdata" imported and not used
```

Xabarni oʻqiymiz: `./main.go:6:2` — fayl, 6-qator, 2-ustun. *"time/tzdata" imported and not used* — «import
qilingan, lekin ishlatilmagan». Go ishlatilmagan importni ogohlantirish emas, kompilyatsiya xatosi deydi. JS'da
bunday qoida yoʻq, shuning uchun u yerda `_` kerak emas.

Yechim — **blank import**: paket nomi oʻrniga `_`. Bu «paketni ulayman, lekin nomini ishlatmayman, faqat init uchun»
degani (Go spec, «Import declarations»). `vaqt-tz/main.go`da faqat 6-qator qoʻshilgan:

```go filename="vaqt-tz/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
	_ "time/tzdata"
)

func main() {
	loc, err := time.LoadLocation("Asia/Tashkent")
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	fmt.Println("Toshkent soati:", time.Now().In(loc).Hour())
}
```

Qayta build qilib, `scratch`da ishga tushiramiz. `vaqt-tz/Dockerfile` `vaqt/Dockerfile` bilan bir xil:

```console
$ cd ../vaqt-tz && go build -o vaqt main.go
```

`go build` hech narsa chiqarmadi: build muvaffaqiyatli.

```bash
docker build -t vaqt .
```

```console
$ docker run --rm vaqt
Toshkent soati: 17
$ ls -l vaqt ../vaqt/vaqt
-rwxr-xr-x 1 haywan users 2885090 Nov 26 17:49 vaqt
-rwxr-xr-x 1 haywan users 2474690 Nov 26 17:49 ../vaqt/vaqt
```

Narxi 410 400 bayt (hujjatda «about 450 KB»). Endi qidirish tartibining 4-qadami ishlaydi:

| | `vaqt` | `vaqt-tz` |
|---|---|---|
| import | `"time"` | `"time"` + `_ "time/tzdata"` |
| `main`dan oldin | — | `tzdata` init: bazani `time`ga roʻyxatdan oʻtkazadi |
| `scratch`da | `unknown time zone` | `Toshkent soati: 17` |
| hajm, bayt | 2 474 690 | 2 885 090 (+410 400) |

Ikkinchi yoʻl: `scratch` oʻrniga distroless static image. Unda vaqt zonalari bazasi bor, shuning uchun tuzatilmagan
`vaqt` ham ishlaydi. Bu buyruq kurs papkasida yoʻq, biz uni alohida tekshirdik (`-v` — faylni image'ga ulash):

```console
$ cd ../vaqt && docker run --rm -v $PWD/vaqt:/vaqt:ro --entrypoint /vaqt gcr.io/distroless/static-debian13
Toshkent soati: 17
```

**`-ldflags="-s -w"`.** `-ldflags` linker'ga flag beradi. `-w` DWARF debug maʼlumotini olib tashlaydi. `-s` esa
`go tool nm` oʻqiydigan simvollar jadvalini ham olib tashlaydi va Go 1.22 dan beri `-w`ni ham anglatadi:

2 409 990 → 1 601 698 bayt, −33.5 %. Bu source map'larsiz production build'ga oʻxshaydi. Farqi bor: runtime
ishlatadigan `.gopclntab` qoladi, shuning uchun panic stack trace'dagi funksiya nomlari va qator raqamlari
oʻzgarmaydi (🔍 uy vazifasi). Narxi: debugger (masalan, Delve) va `go tool nm` endi bu fayl bilan ishlay olmaydi.

**Go'ning import modeli va 2007-yil.** Rob Pike 2012-yilgi «Go at Google» maqolasida Google'dagi C++ binary'sini
eslaydi. `#include`lar ochilgach, kompilyatorga «a blow-up of 2000 bytes for every C++ source byte» borgan: manbaning
har bir baytiga 2000 bayt. Build esa «took 45 minutes using a precursor distributed build system». Go kompilyatori
import qilingan paketning manbasini emas, tayyor obyekt faylini oʻqiydi: «the compiler reads the object file for B,
not its source code». Pike Go gʻoyasi shunday 45 daqiqalik kutishda tugʻilganini «the origin myth for Go» deydi.

## Koʻp uchraydigan xatolar

**1. «Linker tree-shaking qiladi, demak import bepul» deb oʻylash.** Bu mavzudagi eng klassik xato tushuncha. Xato
xabari yoʻq: binary jim kattalashadi. `http.StatusText` uchun `net/http` import qilindi va binary 2.4 MB'dan 5.1 MB'ga
oʻsdi. Sabab — paketlarning init kodi va global oʻzgaruvchilari («`init`: main'dan oldin ishlaydigan kod qoladi»
boʻlimi). **Tuzatish:** importdan oldin va keyin `paketlar.sh` bilan oʻlchang. Bitta kichik funksiya uchun katta paket
kerak boʻlmasligi mumkin.

**2. `FROM scratch`da `time.LoadLocation`.** Laptop'da ishlaydi, image'da `xato: unknown time zone Asia/Tashkent`.
Toʻliq misol «Production holati» boʻlimida. **Tuzatish:** `main` paketida `import _ "time/tzdata"`, yoki
`go build -tags timetzdata`, yoki distroless image.

**3. Zonasiz `time.Now()` `scratch`da jimgina UTC.** Xato yoʻq, faqat soat 5 soat farq qiladi (`vaqt-local`,
«Production holati» boʻlimi). **Tuzatish:** zonani `time.LoadLocation` bilan aniq yuklang (va bazani 2-xatodagidek
qoʻshing). Vaqtni laptop'da emas, production bilan bir xil image'da tekshiring.

**4. `time/tzdata`ni `_`siz import qilish.** `./main.go:6:2: "time/tzdata" imported and not used`. Misol «Tuzatish»
boʻlimida. **Tuzatish:** paket nomi oʻrniga `_` yozing.

**5. gcc'siz mashinada `net`ni tortadigan dasturni oddiy `go build` qilish.** Bu laptop'da shunday chiqadi:

```console
$ cd ../statustext && go build -o st main.go
# runtime/cgo
cgo: C compiler "gcc" not found: exec: "gcc": executable file not found in $PATH
```

Oʻqiymiz: `# runtime/cgo` — xato `runtime/cgo` paketini build qilishda chiqdi. *C compiler "gcc" not found* — «C
kompilyatori gcc topilmadi». Go'da cgo sukut boʻyicha yoqiq (`go env CGO_ENABLED` → `1`), `net` paketi esa cgo
orqali tizim kutubxonasini ishlatmoqchi. **Tuzatish:** `CGO_ENABLED=0 go build …`. Bu binary'ni `scratch`ga ham mos
qiladi (GO-X.01).

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** Hech narsa qilmaydigan Go dasturi nega 1.8 MB?

<details>
<summary>Javob</summary>

Har bir Go binary'si oʻz runtime'ini (garbage collector, scheduler va boshqalar), uning jadvallarini (`.gopclntab`)
va debug maʼlumotini (DWARF) olib yuradi. Bu doimiy narx. `-ldflags="-s -w"` bilan debug maʼlumoti ketadi, runtime va
jadvallar qoladi.

</details>

**2.** Bitta `http.StatusText` uchun `net/http` import qilsak, binary nega ikki barobar oshadi?

<details>
<summary>Javob</summary>

Linker chaqirilmagan funksiyalarni tashlaydi (`net/http`ning oʻz kodi 5 262 bayt qoldi). Lekin har bir import
qilingan paketning `init` kodi va global oʻzgaruvchilari `main`dan oldin albatta bajariladi, shuning uchun ular va
ular chaqiradigan hamma narsa qoladi: `DefaultTransport` → `net`, TLS, 47 ta `crypto` paketi. Go'da
`"sideEffects": false` yoʻq.

</details>

**3.** `scratch` image'da `unknown time zone` chiqdi. Nima qilasiz?

<details>
<summary>Javob</summary>

Vaqt zonalari bazasi tizimdan oʻqiladi, `scratch`da u yoʻq. `main` paketiga `import _ "time/tzdata"` qoʻshing
(+410 KB), yoki `go build -tags timetzdata`, yoki distroless image oling. Zonasiz `time.Now()` esa xato bermaydi,
jimgina UTC koʻrsatadi: buni ham tekshiring.

</details>

**4.** `salom/` papkasida `main-sw` `-ldflags="-s -w"` bilan build qilingan. `../paketlar.sh main-sw` nima chiqaradi?
**A)** `main`dagi bilan bir xil jadval · **B)** kichikroq sonlar · **C)** boʻsh natija

<details>
<summary>Javob</summary>

**C.** `-s` simvollar jadvalini olib tashlaydi, `go tool nm` esa aynan shu jadvalni oʻqiydi. Funksiyalar binary'da bor,
faqat ularning nomlari va hajmlari yozilgan jadval yoʻq. B ni tanlagan boʻlsangiz, `-s -w` kodni kichraytiradi deb
oʻylagansiz: mashina kodi oʻzgarmaydi.

```console
$ ../paketlar.sh main-sw
reading main-sw: no symbol section
reading main-sw: no symbols
       0 100.0% JAMI
```

</details>

**5.** Dars boshidan: `scratch`da `exec /api: no such file or directory` chiqsa, birinchi nimani tekshirasiz?

<details>
<summary>Javob</summary>

Binary cgo bilan build qilinganmi: u holda u tizimdan libc va uning yuklovchisini qidiradi, `scratch`da esa ular yoʻq.
`CGO_ENABLED=0` bilan qayta build qiling. Bu ham «binary'ga nima kirmaydi» savoli, vaqt zonasi bazasi kabi.

</details>
