## Что вы узнаете

Вы отдали переводчику рецепт на одном листе, а он вернул вам толстую книгу. Удивительно, правда? Именно так
происходит, когда Go переводит нашу программу из семи строк: готовый файл почти в **32 000 раз** больше исходного
текста. В этом уроке мы найдём причину.

**Одна идея:** `go build` переводит наш код и сохраняет перевод в отдельный готовый файл. Go каждый раз кладёт в
этот файл и своего помощника (runtime). Поэтому даже самая маленькая программа весит почти два миллиона байт и
работает на компьютере, где Go не установлен. Если вы изменили код, файл нужно собрать заново.

К концу урока вы сможете:

- объяснить простыми словами разницу между `go run` и `go build`;
- собрать готовый файл командой `go build`, посмотреть его размер и запустить его;
- объяснить, почему даже самая маленькая программа на Go больше миллиона байт;
- найти и исправить причину, если после правки кода на экран выводится старый текст.

Сегодня всего три новых слова:

| Слово | Простой смысл | По-английски |
|---|---|---|
| `go build` | команда, которая сохраняет перевод в файл | go build (*build* — «собирать») |
| готовый файл | файл с командами, которые выполняет компьютер | binary |
| внутренний помощник | вспомогательная часть, которую Go добавляет в каждый готовый файл | runtime |

Встретятся и два вспомогательных слова: **байт** (единица размера: место для одной простой буквы) и **компоновщик**
(linker; только в разделе «Глубже»).

**A)** только запуск · **B)** перевод, потом запуск · **C)** код отправляется в интернет

<details>
<summary>Ответ</summary>

**B.** `go run` сначала переводит `main.go` компилятором на язык компьютера, а потом сразу запускает перевод. Так
написано и в документации Go: *"Run compiles and runs the named main Go package"* («Run компилирует и запускает
указанный пакет main»). **A** невозможно: компьютер не понимает текст на Go, перевод обязателен. **C** тоже нет:
всё происходит на вашем компьютере.

Сегодня мы разделим эти два действия: перевод сохраним отдельно, а запускать будем потом сами.

</details>

## `go build`: сохранить перевод в файл

`go run` сам использует перевод и вам его не отдаёт. Но иногда перевод нужно сохранить: чтобы запустить позже или
отдать на другой компьютер.

Представьте: переводчик не читает вам перевод рецепта вслух. Он печатает перевод книгой и отдаёт её вам в руки.
Книгу можно открыть когда угодно и даже подарить другу.

```text
go run:    main.go ──► перевод ──► сразу запускается    (перевод вам не отдают)

go build:  main.go ──► перевод ──► 📕 новый файл         (не запускает)
                                      │
                                      └──► потом: запустить, отдать на другой компьютер
```

В Go команда, которая сохраняет перевод в файл, называется **`go build`** (*build* по-английски «собирать»,
«строить»).

| | `go run main.go` | `go build main.go` |
|---|---|---|
| переводит? | да | да |
| запускает? | да, сразу | нет |
| отдаёт перевод вам? | нет | да, в виде нового файла |

## Готовый файл: binary

Напечатанная книга — это новый файл. В `main.go` буквы, которые читает человек. А в новом файле команды, которые
выполняет компьютер, на языке компьютера. Такой файл по-русски называют **готовым файлом**, по-английски
**binary** («бинарник»).

| | `main.go` | `main` |
|---|---|---|
| что внутри | текст на Go: буквы | команды компьютера |
| кто читает | человек (и компилятор) | компьютер |
| откуда взялся | мы написали | его собрал `go build` |

Если написать `go build main.go`, готовый файл будет называться `main`: Go берёт имя первого файла без `.go`. В
Windows он будет называться `main.exe` (`.exe` — признак файла, который запускается в Windows).

Программа из видео — `salom/main.go`, знакомая по Go 0 «Salom, dunyo» («Привет, мир»):

```go filename="salom/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println("Salom, dunyo!")
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `package main` | это программа, которую можно запустить |
| 3 | `import "fmt"` | подключает ящик с инструментами (пакет) `fmt` |
| 5 | `func main() {` | отсюда программа начинается |
| 6 | `fmt.Println("Salom, dunyo!")` | выводит на экран `Salom, dunyo!` |
| 7 | `}` | `main` закончилась, программа закончилась |

Напишите в терминале `cd salom`: команда `cd` переводит терминал в указанную папку. Затем пишем `go build main.go`.
Что появится на экране? **A)** `Salom, dunyo!` · **B)** ничего · **C)** сообщение об ошибке

<details>
<summary>Ответ</summary>

**B: ничего.** `go build` только переводит и не запускает. Поэтому `Salom, dunyo!` не появится (не **A**). В коде
нет ошибки, поэтому нет и сообщения об ошибке (не **C**). Если всё прошло хорошо, `go build` молчит.

</details>

```console
$ cd salom
$ go build main.go
```

Обе команды ничего не вывели на экран. Но в папке появился новый файл.

## Размер: 74 байта и 2 409 990 байт

Посмотрим на новый файл. Мы работаем в Linux: это, как Windows и Mac, основная система компьютера. В Linux команда
`ls -l` показывает файлы папки вместе с размером. В Windows вместо неё пишут `dir`.

```console
$ ls -l
total 2360
-rwxr-xr-x 1 haywan users 2409990 Nov 26 15:08 main
-rw-r--r-- 1 haywan users      74 Nov 26 12:25 main.go
```

Первая строка (`total`) нам не нужна. Каждая следующая строка — один файл. Прочитаем строку `main`:

| Часть | В строке `main` | Что значит |
|---|---|---|
| символы в начале | `-rwxr-xr-x 1 haywan users` | права и владелец файла: пока не обращайте внимания |
| число перед датой | `2409990` | **размер** |
| дата и время | `Nov 26 15:08` | когда файл собран (26 ноября) |
| последнее слово | `main` | имя файла |

Размер измеряется в **байтах**. Байт — маленькое место из восьми нулей или единиц, например `01010011`. В него
помещается одна простая буква: `01010011` — это буква `S` на языке компьютера.

| Файл | Размер | Что это |
|---|---|---|
| `main.go` | 74 байта | наши 7 строк: 74 буквы, пробелы, Tab и концы строк |
| `main` | 2 409 990 байт (почти два миллиона четыреста тысяч) | готовый файл, который собрал `go build` |

Если разделить 2 409 990 на 74, получится примерно 32 567. Значит, готовый файл почти в 32 000 раз больше исходного
текста.

На вашем компьютере имя, дата и размер могут немного отличаться. В другой папке размер отличается на несколько
байт, потому что пути к файлам тоже хранятся внутри готового файла.

## Запуск готового файла: `./main`

Теперь запустим готовый файл. `./main` — «файл `main` в этой папке» (`./` вы знаете из GO-0.01). В окне `cmd` в
Windows пишут просто `main`, а в PowerShell (ещё один терминал Windows) — `.\main`.

```console
$ ./main
Salom, dunyo!
```

Обратите внимание: в этой команде нет слова `go`. Перевод уже готов, файл выполняет сам компьютер.

Коротко: `go build` сохраняет перевод в файл, а компьютер выполняет этот готовый файл.

```text
main.go (74 байта) ──go build──► main (2 409 990 байт) ──./main──► Salom, dunyo!
   рецепт                          напечатанная книга                 результат
```

## Runtime: помощник, которого добавляют в каждый готовый файл

Зачем для одной строки работы больше двух миллионов байт?

Вспомните кухню. В рецепте написано, что готовить. Но на кухне есть и вспомогательная работа: мыть посуду. С
программой то же самое. Значения лежат в памяти (GO-0.02), и значения, которые больше не нужны, надо из памяти
убирать.

Команды для такой вспомогательной работы Go сам добавляет в каждый готовый файл. Вместе они называются **runtime**
(«рантайм»), по-нашему **внутренний помощник**. К нашей книге каждый раз допечатывают толстый раздел «помощник на
кухне».

| На кухне | В программе на Go |
|---|---|
| рецепт: что готовить | наш код: вывести `Salom, dunyo!` |
| мытьё посуды | убрать из памяти значения, которые больше не нужны |
| помощник, который это делает | runtime |
| дополнительный раздел в книге | runtime внутри каждого готового файла |

В официальных вопросах и ответах Go (Go FAQ) написано: runtime *"is part of every Go program"* — «часть каждой
программы на Go». Он убирает память (по-английски *garbage collection*, сборка мусора) и делает другую важную
работу. Остальное увидим в следующих уроках.

Значит, команды компьютера в файле `main` приходят из трёх мест:

| Откуда | Команды внутри `main` |
|---|---|
| перевод наших 7 строк | всего 83 байта |
| пакет `fmt` | отсюда берётся `Println` |
| runtime | самая большая часть: почти три четверти команд (71 %) |

Эти числа измерены командой `go tool nm -size main`. Она показывает размер каждой группы команд внутри готового
файла. Знать эту команду сейчас не обязательно.

Команды — только часть файла. Что составляет остальное, увидим в разделе «Глубже».

## Даже пустая программа больше миллиона байт

Правда ли runtime есть в каждом файле? Проверим. Вот `bosh/main.go`, пустая программа:

```go filename="bosh/main.go" showLineNumbers
package main

func main() {
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `package main` | знакомо: это программа, которую можно запустить |
| 3 | `func main() {` | отсюда программа начинается |
| 4 | `}` | сразу заканчивается: между фигурными скобками нет ни одной команды |

Здесь нет ни `import`, ни `Println`. Программа ничего не делает.

Если собрать её командой `go build`, какого размера будет готовый файл? **A)** почти 0 байт · **B)** около 70 байт ·
**C)** больше 1 000 000 байт

<details>
<summary>Ответ</summary>

**C: больше миллиона байт**, почти 1 830 000 байт. Даже в программу, которая ничего не делает, Go добавляет runtime.
Если вы выбрали **A** или **B**, вы думали, что в готовом файле только наш код. Но без runtime программа на Go
вообще не работает.

</details>

Переходим в терминале в папку `bosh`. `..` — «на одну папку выше», поэтому `cd ../bosh` значит «поднимись выше,
потом зайди в `bosh`»:

```console
$ cd ../bosh
$ go build main.go
$ ls -l main
-rwxr-xr-x 1 haywan users 1829988 Nov 26 15:08 main
```

`ls -l main` показывает только файл `main`. Сравним два результата:

| Программа | Готовый файл |
|---|---|
| пустая (`bosh/`) | 1 829 988 байт |
| «Salom, dunyo» (`salom/`) | 2 409 990 байт |
| разница: `fmt` и `Println` | 580 002 байта (почти пятьсот восемьдесят тысяч) |

Коротко: runtime есть внутри любой программы на Go, даже той, что ничего не делает.

## Работает ли файл там, где Go не установлен?

Быстрый вопрос. Копируем готовый файл `main` на компьютер друга. Там тоже Linux, но Go не установлен. Заработает?
**A)** да, заработает · **B)** нет: сначала нужен Go · **C)** только вместе с `main.go`

<details>
<summary>Ответ</summary>

**A: заработает.** Всё нужное — наш код, `fmt` и runtime — внутри одного файла `main`. Сам Go не нужен.

- Если вы выбрали **B**: Go нужен был только для перевода. Чтобы читать напечатанную книгу, переводчик не нужен.
- Если вы выбрали **C**: `main.go` — это рецепт. Готовый файл существует отдельно от него, `main.go` ему не нужен.

Только компьютер должен быть таким же: например, файл, собранный для Linux, не заработает в Windows. Точнее,
одинаковыми должны быть и система, и процессор (часть компьютера, которая считает).

</details>

```text
main  =  наш код + fmt + runtime
  │
  ├──► 📤 компьютер друга (Linux, Go нет)  ──► Salom, dunyo!   ✅
  │
  └──► 📤 компьютер с Windows              ──► не работает     ❌ файл собран для Linux
```

Go FAQ говорит то же: *"All Go binaries therefore include the Go runtime"* («поэтому каждый готовый файл Go
содержит runtime Go»). Вы проверите это сами: об этом задание 🔍 в домашней работе.

## Зачем создали Go?

В 2007 году одна сборка (build) большой программы в Google длилась 45 минут. Об этом писал Роб Пайк, один из
авторов Go, в статье 2012 года. По легенде, идея Go родилась во время одного из таких ожиданий (сам Пайк называет
это «мифом о происхождении» Go).

Цель записана в Go FAQ: писать должно быть легко, а программа должна работать быстро и надёжно. И даже большая
программа должна собираться на одном компьютере за несколько секунд.

## Изменили код — соберите файл заново

Теперь самая частая ошибка. Вернитесь в терминале в папку `salom` командой `cd ../salom`. Откройте `main.go`,
замените в 6-й строке слово `dunyo` на `Aziza` (имя) и сохраните файл. Теперь файл такой:

```go
package main

import "fmt"

func main() {
	fmt.Println("Salom, Aziza!")
}
```

Но `go build` заново не пишем и сразу запускаем `./main`. Что появится на экране?
**A)** `Salom, Aziza!` · **B)** `Salom, dunyo!` · **C)** сообщение об ошибке

Вспомните книгу: мы изменили рецепт уже после того, как книгу напечатали.

<details>
<summary>Ответ</summary>

**B: старое `Salom, dunyo!`.** Готовый файл собран из кода, каким он был в момент перевода. Если изменить
`main.go`, напечатанная книга не меняется: это два отдельных файла.

- Если вы выбрали **A**, вы думали, что `./main` каждый раз читает `main.go`. Так делает команда `go run`.
- Если вы выбрали **C**: ничего не сломано. Старый готовый файл на месте и делает свою работу.

</details>

```console
$ ./main
Salom, dunyo!
```

Исправить легко: сначала `go build`, потом `./main`.

```console
$ go build main.go
$ ./main
Salom, Aziza!
```

Что происходило шаг за шагом:

| Шаг | В `main.go` | В `main` (готовый файл) | На экране |
|---|---|---|---|
| `go build main.go` (раньше) | `dunyo` | `dunyo` | |
| изменили и сохранили `main.go` | `Aziza` | `dunyo` (не изменился) | |
| `./main` | `Aziza` | `dunyo` | `Salom, dunyo!` |
| `go build main.go` | `Aziza` | `Aziza` (собран заново) | |
| `./main` | `Aziza` | `Aziza` | `Salom, Aziza!` |

**Правило:** изменили код — соберите файл заново. `go run` делает это сам каждый раз, поэтому в уроках Go 0 такой
ошибки не было.

Когда проверите, верните в `main.go` текст `Salom, dunyo!`: следующие примеры ждут именно его.

## Глубже (необязательно): что внутри go build

Если вы только начинаете, этот раздел можно прочитать позже. Главная идея урока закончилась до него.

**1. Компилятор переводит части по отдельности.** `go build` сначала по отдельности переводит `main.go`, пакет
`fmt` и runtime. Готовые части он запоминает, чтобы в следующий раз не переводить их заново. Это место
по-английски называется *build cache* (кэш сборки). По данным README курса, наша программа из 7 строк в первый раз
собралась примерно за 2,8 секунды, а в следующий раз — примерно за 0,1 секунды. `go run` с Go 1.24 тоже
пользуется этим местом, но если код изменился, переводит заново.

**2. Компоновщик сшивает всё в один файл.** Когда разделы книги напечатаны отдельно, переплётчик сшивает их в одну
книгу. В Go эту работу делает **компоновщик**, по-английски **linker**. Он собирает переведённые части в один файл
`main` и выбрасывает группы команд, которые никто не вызывает.

```text
main.go  ──► компилятор ──┐
fmt      ──► компилятор ──┼──► linker (компоновщик) ──► main (готовый файл)
runtime  ──► компилятор ──┘
             (запоминает готовые части)
```

**3. Что внутри файла.** Команда Linux `size -A main` измеряет части готового файла:

| Часть | Байт | Доля | Зачем нужна |
|---|---|---|---|
| команды компьютера | 643 537 | почти четверть (27 %) | сама программа: наш код, `fmt`, runtime |
| имена групп команд и номера строк | 677 386 | почти четверть (28 %) | если программа остановится с ошибкой, отсюда она узнаёт, на какой строке; runtime тоже этим пользуется |
| данные для поиска ошибок | 676 118 | почти четверть (28 %) | нужны программисту, когда он ищет ошибку; программа работает и без них |
| остальное | 412 949 | 17 % | тексты, сведения о типах и прочее |

«Группа команд» — это функция из GO-0.01 (как `func main`). По Go FAQ данные для поиска ошибок можно убрать
флагом `-ldflags=-w`, программа всё равно будет работать.

## Частые ошибки

**1. Изменить код и не выполнить `go build` заново.** Самая частая ошибка, и она тихая: сообщения об ошибке нет,
на экран просто выводится старый текст. Мы разобрали её выше, в разделе «Изменили код — соберите файл заново».
**Исправление:** после каждой правки сначала `go build main.go`, потом `./main`.

**2. Терминал открыт не в той папке.** Терминал стоит в самой папке урока (`lessons/001-why-go`), а не внутри
`salom`. Там нет `main.go`:

```console
$ go build main.go
no required module provides package main.go; to add it:
	go get main.go
```

Сообщение: «ни один модуль не предоставляет пакет `main.go`; чтобы добавить его: `go get main.go`». Go не нашёл в
этой папке файл `main.go`. Поэтому он решил, что `main.go` — имя пакета, который надо скачать из интернета (модуль —
папка проекта на Go, мы разберём её в следующих уроках). Не пишите здесь `go get`: он не нужен.
**Исправление:** `cd salom`, потом снова `go build main.go`. Проверьте командой `ls` (в Windows `dir`), что
`main.go` есть в папке.

**3. Написать `main` без `./`.** Терминал Linux и Mac ищет команды только в известных ему системных папках, а не в
текущей папке:

```console
$ main
bash: main: command not found
```

«команда `main` не найдена». Терминал на Mac пишет то же сообщение так: `zsh: command not found: main`.
**Исправление:** `./main`, то есть «`main` в этой папке». (А в окне `cmd` в Windows `main` работает.)

Если не работает и `./main`, готового файла в папке ещё нет: вы не сделали `go build` или находитесь в другой
папке.

```console
$ ./main
bash: ./main: No such file or directory
```

«нет такого файла или папки». **Исправление:** в нужной папке сначала `go build main.go`, потом `./main`.

## Проверьте себя

Сначала ответьте сами, потом откройте ответ.

**1.** Чем `go run` отличается от `go build`?

<details>
<summary>Ответ</summary>

`go run` переводит и сразу запускает; перевод вам не отдаёт. `go build` сохраняет перевод в готовый файл (`main`)
и не запускает его.

</details>

**2.** Почему пустая программа больше миллиона байт?

<details>
<summary>Ответ</summary>

Внутри каждого готового файла есть runtime: Go добавляет его в каждую программу, даже в ту, что ничего не делает.
`bosh/main` — 1 829 988 байт.

</details>

**3.** Вы изменили код. Что теперь делать?

<details>
<summary>Ответ</summary>

Заново выполнить `go build main.go`, потом `./main`. Иначе старый готовый файл выведет старый текст.

</details>

**4.** Вы сделали `go build main.go` для `salom/main.go`. Потом заменили `dunyo` на `Go` и сохранили файл. Теперь
пишете подряд две команды: сначала `go run main.go`, потом `./main`. Что выведет каждая?
**A)** `Salom, Go!` и `Salom, Go!` · **B)** `Salom, Go!` и `Salom, dunyo!` · **C)** `Salom, dunyo!` и
`Salom, dunyo!`

<details>
<summary>Ответ</summary>

**B.** `go run` каждый раз переводит новый `main.go`, поэтому выводит `Salom, Go!`. Но файл `main` команда `go run`
не меняет: перевод она вам не отдаёт. Поэтому `./main` по-прежнему выводит старое `Salom, dunyo!`. Мы проверили это
запуском: результат именно такой.

</details>

**5.** Из GO-0.01: что значит `./` в сообщении об ошибке `./main.go:6:6`? Где он встретился сегодня?

<details>
<summary>Ответ</summary>

`./` — «в этой папке». Сегодня он встретился в команде `./main`: «запусти файл `main` из этой папки».

</details>

```go filename="uyga/orta/main.go" showLineNumbers
package main

import "fmt"

func main() {
	for i := 1; i <= 3; i++ {
		fmt.Println("Salom!")
	}
}
```

Строка 6: счётчик `i` начинается с 1, цикл идёт, пока `i <= 3`, а после каждого круга `i++` увеличивает его на
один. Строка 7 на каждом круге выводит `Salom!`. **До** сборки угадайте: на сколько готовый файл будет больше
`salom/main` (2 409 990 байт)? На несколько байт, на тысячи байт, на миллион байт?

неважно, что рядом нет `main.go`?

➕ **Дополнительно** (нет в видео, есть в `uyga/README.md`): Go умеет на одном компьютере собирать файл и для другой
системы. `GOOS` — целевая система. Например, в Linux или Mac `GOOS=windows go build main.go` собирает `main.exe`
для Windows.

Ответы: [uyga/README.md](https://github.com/abdurahmon27/go-backend-uz/blob/main/lessons/001-why-go/uyga/README.md).

<details>
<summary>Ответ</summary>

```console
-rwxr-xr-x 1 haywan users 2410174 Nov 26 15:08 main
```

2 410 174 − 2 409 990 = 184.
