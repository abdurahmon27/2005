## Что вы узнаете

Бинарник двадцатистрочного HTTP API из GO-X.01 весит 8 659 683 байта, то есть 8,66 МБ. Увидев бандл на 8 МБ во
фронтенде, вы сразу открываете bundle analyzer. Что это за мегабайты в Go-бинарнике и сколько из них — наш код?
Сегодня это измерим.

**Одна идея:** бо́льшая часть Go-бинарника — не наш код. В каждой программе есть runtime. Из импортированных пакетов
linker оставляет только функции, которые могут быть вызваны, и init-код каждого пакета. А данные системы (база
часовых поясов) в бинарник не попадают вовсе: их добавляют осознанно, через `import _`.

К концу урока вы сможете:

- измерить любой Go-бинарник по пакетам с помощью `go tool nm` и 10-строчного скрипта `paketlar.sh`;
- объяснить, почему пустая Go-программа весит 1,8 МБ и какую часть этой цены можно убрать;
- через `init` объяснить, почему пакет, импортированный ради одной функции, удваивает бинарник;
- исправить ошибку `unknown time zone` в образе `FROM scratch` с помощью `import _ "time/tzdata"` или distroless.

Три главных новых понятия:

| Понятие | Простыми словами | По-английски |
|---|---|---|
| постоянная цена runtime | GC, планировщик и их таблицы есть в каждом Go-бинарнике: даже пустая программа весит 1,8 МБ | runtime (fixed cost) |
| tree-shaking в linker и `init` | linker выбрасывает функции, которые никто не вызывает, но init-код пакетов и их глобальные переменные остаются | dead-code elimination, package initialization |
| `import _ "…"` | подключить пакет без имени, только ради его `init` (побочного эффекта), как `import 'dotenv/config'` | blank import |

Есть ещё два вспомогательных инструмента: **`go tool nm`** (показывает размер каждой функции в бинарнике) и
**`-ldflags="-s -w"`** (флаг для linker, убирает отладочную информацию; только в разделе «Глубже»).

## Bundle analyzer для Go-бинарника

Сначала угадайте. API из GO-X.01 весит 8 659 683 байта. Сколько из них — наши двадцать строк (машинный код пакета
`main`)?

**A)** ~1 МБ · **B)** ~100 КБ · **C)** меньше 2 КБ

<details>
<summary>Ответ</summary>

**C: 1 595 байт**, 0,02 % файла. Если вы выбрали A или B, вы представили бинарник как бандл, который «в основном наш
код». В Go-бинарнике наш код — самая маленькая часть. Из чего остальное, измерим ниже.

</details>

Готового bundle analyzer в Go нет. Но `go tool nm -size` выводит каждый символ бинарника (функцию или глобальную
переменную) с его размером. Скрипт `paketlar.sh` («пакеты») из папки урока берёт из этого списка только функции и
суммирует их по пакетам:

```bash filename="paketlar.sh" showLineNumbers
#!/bin/sh
# Go binary uchun "bundle analyzer": mashina kodi (funksiyalar) baytlarini paketlar bo'yicha qo'shadi.
# Ishlatish: ./paketlar.sh <binary> [qator soni, standart 6]
# Eslatma: -ldflags="-s" bilan build qilingan faylda simvollar jadvali yo'q, natija bo'sh bo'ladi.
go tool nm -size "$1" | awk '
  $3 == "T" || $3 == "t" {
    size = $2
    name = $0; sub(/^ *[0-9a-f]+ +[0-9]+ +[A-Za-z] +/, "", name)   # nomda bo`sh joy bo`lishi mumkin
    sub(/^go:/, "", name); sub(/^type:\.(eq|hash)\./, "", name)     # kompilyator yasagan eq/hash funksiyalari
    sub(/\[.*/, "", name)                                            # generic: Foo[...] -> Foo
    slash = 0; for (i = 1; i <= length(name); i++) if (substr(name, i, 1) == "/") slash = i
    rest = substr(name, slash + 1); dot = index(rest, ".")
    pkg = (dot > 0) ? substr(name, 1, slash + dot - 1) : "runtime(asm)"   # paketsiz nom = runtime assembler kodi
    sum[pkg] += size; total += size
  }
  END { for (p in sum) printf "%8d %5.1f%% %s\n", sum[p], 100 * sum[p] / total, p; printf "%8d 100.0%% JAMI\n", total }
' | sort -rn | head -n "${2:-6}"
```

| Строка | Код | Что делает |
|---|---|---|
| 5 | `go tool nm -size "$1"` | для каждого символа: адрес, размер (байты), буква типа, имя. `T`/`t` — машинный код (функция) |
| 6 | `$3 == "T" \|\| $3 == "t"` | берёт только функции; глобальные переменные не считаются |
| 8–10 | `sub(…)` | чистит имя: убирает сгенерированные компилятором `type:.eq.`/`type:.hash.` (функции сравнения и хеш-функции) и generic-часть `[...]` |
| 11–13 | `slash`, `dot`, `pkg` | выделяет имя пакета: `net/http.StatusText` → `net/http`. Имя без пакета (ассемблерный код) → `runtime(asm)` |
| 14 | `sum[pkg] += size` | суммирует байты по пакетам |
| 16–17 | `END …`, `sort -rn \| head` | выводит с процентами, от большего к меньшему (`JAMI` — «итого»); второй аргумент — сколько строк |

Теперь соберём API из GO-X.01 и откроем его этим скриптом (`cd` — перейти в другую папку):

```console
$ cd ../0x-01-http-api && CGO_ENABLED=0 go build -o api . && ls -l api

$ ../001-why-go/paketlar.sh api 6
```

Самый большой — `runtime`, за ним `crypto/tls` и `net/http`. А наш пакет `main` — 1 595 байт: мы нашли его через
`grep` в списке из 400 строк.

Обратите внимание: `JAMI` — это только машинный код, 2 614 648 байт. Это 30 % файла в 8,66 МБ. Остальное — таблица имён
функций и отладочная информация, их откроем в разделе «Глубже».

## Runtime: постоянная цена каждой Go-программы

Цену runtime измерим на самой маленькой программе. Семистрочная «Salom, dunyo» («Привет, мир»):

```go filename="salom/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println("Salom, dunyo!")
}
```

```console
$ cd ../001-why-go/salom && go build main.go && ls -l
total 2360
-rwxr-xr-x 1 haywan users 2409990 Nov 26 17:49 main
-rw-r--r-- 1 haywan users      74 Nov 26 12:25 main.go
```

`main.go` — 74 байта, а собранный `go build` файл `main` — 2 409 990 байт. Откроем его:

```console
$ ../paketlar.sh main 4
  612609 100.0% JAMI
  437293  71.4% runtime
   29557   4.8% fmt
   25634   4.2% reflect
$ go tool nm -size main | grep ' main.main$'
  49e140         83 T main.main
```

71,4 % машинного кода принадлежит пакету `runtime`. Наша функция `main.main` — 83 байта. Runtime вы знаете по
GO-X.01: garbage collector и планировщик (scheduler). Новое здесь вот что: он есть и в API, и в «Salom, dunyo». Это
**постоянная цена** каждой Go-программы (Go FAQ: runtime «is part of every Go program»).

Отличие от Node: V8 и event loop живут в одном файле `node`, который ставится на сервер один раз. В Go каждый сервис
носит свой runtime внутри своего бинарника.

Теперь измерим эту цену в чистом виде: уберём и `fmt`. Импортов нет, `func main` пустая, программа ничего не делает
(`bosh` — «пустой»):

```go filename="bosh/main.go" showLineNumbers
package main

func main() {
}
```

Какую долю от «Salom, dunyo» (2 409 990 байт) составит её бинарник? Выше `fmt` занимал 4,8 % машинного кода.

**A)** ~5 %: бо́льшая часть размера была `fmt` · **B)** ~75 %: `fmt` и подтянутые им пакеты — около четверти ·
**C)** ~100 %: `fmt` ничтожен

<details>
<summary>Ответ</summary>

**B: 1 829 988 байт, 75,9 %.** Даже программа, которая ничего не делает, весит 1,8 МБ. Это runtime, его таблицы и
отладочная информация. Если вы выбрали A, вы думали, что размер дают наш код и `fmt`: runtime есть и без них. Если
выбрали C, вы смотрели только на сам `fmt`: он маленький, но тянет пакеты вроде `reflect`. Разница с «Salom, dunyo» —
580 002 байта.

</details>

```console
$ cd ../bosh && go build main.go && ls -l main
-rwxr-xr-x 1 haywan users 1829988 Nov 26 17:49 main
```

| Бинарник | Размер, байты | Внутри |
|---|---|---|
| `bosh/main` (пустая `func main`) | 1 829 988 | runtime + таблицы + отладочная информация |
| `salom/main` | 2 409 990 | + `fmt`, `reflect` и другие (+580 002) |
| `api` из GO-X.01 | 8 659 683 | + `net/http`, `crypto/tls`, `net`, `encoding/json` … |

Часть этих 1,8 МБ можно убрать (отладочную информацию), остальное нужно для работы runtime. Какую именно — в разделе
«Глубже».

## Tree-shaking: linker выбрасывает код, который никто не вызывает

Вопрос из фронтенда про tree-shaking. Vite или Rollup кладут в бандл только те функции из `lodash-es`, которые вы
вызываете. В Go это работа **linker** (компоновщика): компилятор превращает каждый пакет в машинный код отдельно, а
linker собирает их в один бинарник. При сборке он оставляет функции, достижимые из `main.main`, а остальное
выбрасывает (**dead-code elimination**).

Проверим. Импортируем `net/http`, но вызовем из него одну маленькую функцию — `http.StatusText`. Она возвращает текст
HTTP-кода статуса: для 404 — `Not Found`.

```go filename="statustext/main.go" showLineNumbers
package main

import (
	"fmt"
	"net/http"
)

func main() {
	fmt.Println(http.StatusText(404))
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–6 | `import ( "fmt" "net/http" )` | два пакета: `fmt` и `net/http` — пакет HTTP-сервера из GO-X.01 |
| 9 | `http.StatusText(404)` | единственный вызов из `net/http`: 404 → `"Not Found"`. Ни сервера, ни запроса |

```console
$ cd ../statustext && CGO_ENABLED=0 go run main.go
Not Found
```

Какого размера будет бинарник? Для сравнения: «Salom, dunyo» — 2,4 МБ, API из GO-X.01 — 8,7 МБ.

**A)** ~2,4 МБ: linker выбрасывает неиспользуемое · **B)** ~5 МБ: часть остаётся · **C)** ~8,7 МБ: пакет входит
целиком

<details>
<summary>Ответ</summary>

**B: 5 143 595 байт**, вдвое больше «Salom, dunyo». Если вы выбрали A, вы думали, что tree-shaking выбрасывает весь
неиспользуемый код: в следующем разделе увидим, почему он не может. Если выбрали C, вы думали, что Go добавляет пакет
целиком: собственный код `net/http` действительно выброшен.

</details>

```console
$ CGO_ENABLED=0 go build -o st main.go && ls -l st
-rwxr-xr-x 1 haywan users 5143595 Nov 26 17:49 st
$ ../paketlar.sh st 400 | grep ' net/http$'
    5262   0.4% net/http
```

Собственный код `net/http` — 5 262 байта. В API из GO-X.01 было 231 802 байта, то есть в 44 раза меньше. Linker
действительно выбросил функции, которые никто не вызывает. Тогда откуда лишние 2,7 МБ сверх «Salom, dunyo»?

## `init`: код, который выполняется до main, остаётся

В JavaScript код верхнего уровня модуля выполняется при импорте: код из `import './polyfill'` выполнится, даже если вы
ничего из него не вызываете. Поэтому бандлер не может выбросить такой модуль. Через `"sideEffects": false` в
`package.json` вы говорите бандлеру: «в этих модулях нет побочных эффектов, выбрасывай смело».

В Go этому соответствует **инициализация пакета**. В каждом импортированном пакете две вещи выполняются до `main`,
всегда (Go spec, «Package initialization»):

- инициализация глобальных переменных: например, `var DefaultTransport = &Transport{…}` в `net/http`;
- функции `func init()` пакета.

У linker две стартовые точки: `main.main` и init-задачи всех пакетов (`cmd/link/internal/ld/deadcode.go`). Init-код и
всё, что он вызывает, остаются в бинарнике. Флага вроде `"sideEffects": false` в Go нет.

Самые большие пакеты в бинарнике `statustext`:

```console
$ ../paketlar.sh st 6
 1428465 100.0% JAMI
  454858  31.8% runtime
  121834   8.5% net
   59328   4.2% math/big
   51441   3.6% crypto/internal/fips140/nistec
   48111   3.4% time
$ go tool nm -size -sort size st | grep -E ' (net/http|net|crypto/x509)\.init$'
  506ac0       3754 T crypto/x509.init
  521a60       3092 T net/http.init
  4df440       2867 T net.init
$ ../paketlar.sh st 400 | grep -E ' crypto(/|$)' | wc -l
47
```

Мы не вызывали ни `net`, ни `crypto`. Они вошли по цепочке init:

| Шаг | Что | Результат |
|---|---|---|
| 1 | до `main` — init-задача каждого импортированного пакета (`main.inittasks`) | linker их не выбрасывает |
| 2 | `net/http.init`: глобальные переменные, например `DefaultTransport` | остаются `Transport` и его dialer |
| 3 | `DefaultTransport` → `net.(*Dialer).DialContext` | пакет `net`: 121 834 байта |
| 4 | TLS и сертификаты (`crypto/x509.init` и другие) | `math/big` и 47 пакетов `crypto` (`crypto` и `crypto/…`) |
| 5 | всё вместе | бинарник 5 143 595 байт, хотя вызван только `StatusText` |

В README курса есть ещё одно правило: методы типа, сохранённого в интерфейс, тоже остаются, если где-то вызывается
метод интерфейса с тем же именем (`math/big` частично попадает так).

Вывод для работы: импорт в Go не бесплатен. Прежде чем импортировать большой пакет ради одной вспомогательной
функции, измерьте его цену через `paketlar.sh`.

## Случай из продакшена: `FROM scratch` и часовой пояс

Теперь то, что в бинарник **не** попадает. Сервис показывает время в Ташкенте (`vaqt` — «время»):

```go filename="vaqt/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
)

func main() {
	loc, err := time.LoadLocation("Asia/Tashkent")
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	fmt.Println("Toshkent soati:", time.Now().In(loc).Hour())
}
```

| Строка | Код | Что делает |
|---|---|---|
| 9 | `loc, err := time.LoadLocation("Asia/Tashkent")` | загружает часовой пояс по имени: `loc` — пояс, `err` — ошибка (два значения, как в GO-X.03) |
| 10–13 | `if err != nil { … return }` | если пояс не найден, выводит ошибку (`xato` — «ошибка») и выходит |
| 14 | `time.Now().In(loc).Hour()` | переводит текущее время в этот пояс и берёт час (`Toshkent soati` — «час в Ташкенте») |

На ноутбуке час правильный:

```console
$ cd ../vaqt && go build -o vaqt main.go && ./vaqt
Toshkent soati: 17
```

Кладём его в образ `FROM scratch` из GO-X.01. `vaqt/Dockerfile`:

```dockerfile filename="vaqt/Dockerfile"
FROM scratch
COPY vaqt /vaqt
ENTRYPOINT ["/vaqt"]
```

```bash
docker build -t vaqt .
```

Что выведет `docker run`? На ноутбуке было `Toshkent soati: 17` (Ташкент — UTC+5).

**A)** `Toshkent soati: 17` · **B)** час по UTC: `12` · **C)** ошибку

<details>
<summary>Ответ</summary>

**C: `xato: unknown time zone Asia/Tashkent`.** Базы часовых поясов нет внутри бинарника. `time.LoadLocation` читает её
из системы, а в `scratch` вообще нет файлов. Если вы выбрали A, вы думали, что бинарник несёт с собой всё: код — да,
данные системы — нет. B получается в другом случае: увидим ниже.

</details>

```console
$ docker run --rm vaqt

```

Порядок поиска базы по `go doc time.LoadLocation`:

| # | Откуда | Ноутбук | `scratch` |
|---|---|---|---|
| 1 | файл из переменной окружения `$ZONEINFO` | — | — |
| 2 | системные пути Unix: `/usr/share/zoneinfo/` … `/etc/zoneinfo` | ✅ находит | ❌ нет |
| 3 | `$GOROOT/lib/time/zoneinfo.zip` (где установлен Go) | ✅ | ❌ нет Go |
| 4 | пакет `time/tzdata`, если он импортирован | — | ❌ не импортирован |

Эта ошибка хотя бы видна. Вариант B тише. `time.Now()` без пояса использует локальный пояс (`time.Local`), а в

дату: `15` — час, `04` — минуты, `MST` — пояс. (Комментарий в строке 9: «пояс не указан: time.Local, в scratch молча

## Исправление: `import _ "time/tzdata"`

В пакете `time/tzdata` лежит копия базы часовых поясов. Никакие функции из него нам не нужны, только его `init`: он
регистрирует базу в пакете `time`. Как `import 'dotenv/config'` в JS: модуль ничего нужного не экспортирует, достаточно
его импортировать.

Сначала попробуем обычный импорт. Этого файла нет в папке курса: мы убрали `_` из `vaqt-tz/main.go` и проверили в
отдельной папке:

```go
package main

import (
	"fmt"
	"time"
	"time/tzdata"
)

func main() {
	loc, err := time.LoadLocation("Asia/Tashkent")
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	fmt.Println("Toshkent soati:", time.Now().In(loc).Hour())
}
```

```console
$ go build -o vaqt main.go
# command-line-arguments
./main.go:6:2: "time/tzdata" imported and not used
```

Читаем сообщение: `./main.go:6:2` — файл, строка 6, столбец 2. *"time/tzdata" imported and not used* — «импортирован, но
не используется». Неиспользуемый импорт в Go — не предупреждение, а ошибка компиляции. В JS такого правила нет, поэтому
там `_` не нужен.

Решение — **blank import** (пустой импорт): `_` вместо имени пакета. Это значит «подключаю пакет, но его имя не
использую, только ради init» (Go spec, «Import declarations»). В `vaqt-tz/main.go` добавлена только строка 6:

```go filename="vaqt-tz/main.go" showLineNumbers
package main

import (
	"fmt"
	"time"
	_ "time/tzdata"
)

func main() {
	loc, err := time.LoadLocation("Asia/Tashkent")
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	fmt.Println("Toshkent soati:", time.Now().In(loc).Hour())
}
```

Пересобираем и запускаем в `scratch`. `vaqt-tz/Dockerfile` такой же, как `vaqt/Dockerfile`:

```console
$ cd ../vaqt-tz && go build -o vaqt main.go
```

`go build` ничего не вывел: сборка прошла успешно.

```bash
docker build -t vaqt .
```

```console
$ docker run --rm vaqt
Toshkent soati: 17
$ ls -l vaqt ../vaqt/vaqt
-rwxr-xr-x 1 haywan users 2885090 Nov 26 17:49 vaqt
-rwxr-xr-x 1 haywan users 2474690 Nov 26 17:49 ../vaqt/vaqt
```

Цена — 410 400 байт (в документации «about 450 KB»). Теперь работает шаг 4 порядка поиска:

| | `vaqt` | `vaqt-tz` |
|---|---|---|
| импорт | `"time"` | `"time"` + `_ "time/tzdata"` |
| до `main` | — | init `tzdata`: регистрирует базу в `time` |
| в `scratch` | `unknown time zone` | `Toshkent soati: 17` |

Второй путь: образ distroless static вместо `scratch`. В нём есть база часовых поясов, поэтому работает даже

`.bss` и `.noptrbss` места в файле не занимают: память под них выделяется при запуске программы.

**`-ldflags="-s -w"`.** `-ldflags` передаёт флаги linker. `-w` убирает отладочную информацию DWARF. `-s` убирает ещё и
таблицу символов, которую читает `go tool nm`, а начиная с Go 1.22 подразумевает и `-w`:

```console
$ go build -ldflags="-s -w" -o main-sw main.go && ls -l main-sw
-rwxr-xr-x 1 haywan users 1601698 Nov 26 17:49 main-sw
```

2 409 990 → 1 601 698 байт, −33,5 %. Похоже на продакшен-сборку без source map'ов. Но с отличием: `.gopclntab`, которую
использует runtime, остаётся, поэтому имена функций и номера строк в stack trace паники (panic) не меняются (🔍
домашнее задание). Цена: отладчик (например, Delve) и `go tool nm` больше не могут работать с этим файлом.

**Модель импорта Go и 2007 год.** В статье 2012 года «Go at Google» Роб Пайк вспоминает C++-бинарник в Google. После
раскрытия `#include` компилятор получал «a blow-up of 2000 bytes for every C++ source byte»: 2000 байт на каждый байт
исходника. А сборка «took 45 minutes using a precursor distributed build system». Компилятор Go читает не исходник
импортированного пакета, а готовый объектный файл: «the compiler reads the object file for B, not its source code».
Историю о том, что идея Go родилась во время такого 45-минутного ожидания, Пайк называет «the origin myth for Go».

## Частые ошибки

**1. Думать «linker делает tree-shaking, значит импорт бесплатный».** Это классическое заблуждение по этой теме.
Сообщения об ошибке нет: бинарник молча растёт. `net/http` импортировали ради `http.StatusText`, и бинарник вырос с
2,4 МБ до 5,1 МБ. Причина — init-код и глобальные переменные пакетов (раздел «`init`: код, который выполняется до main,
остаётся»). **Исправление:** измеряйте через `paketlar.sh` до и после импорта. Ради одной маленькой функции большой
пакет может быть не нужен.

**2. `time.LoadLocation` во `FROM scratch`.** На ноутбуке работает, в образе — `xato: unknown time zone Asia/Tashkent`.
Полный пример — в разделе «Случай из продакшена». **Исправление:** `import _ "time/tzdata"` в пакете `main`, или
`go build -tags timetzdata`, или образ distroless.

**3. `time.Now()` без пояса молча становится UTC в `scratch`.** Ошибки нет, просто час сдвинут на 5 часов
(`vaqt-local`, раздел «Случай из продакшена»). **Исправление:** загружайте пояс явно через `time.LoadLocation` (и
добавьте базу, как в ошибке 2). Проверяйте время в том же образе, что и в продакшене, а не на ноутбуке.

**4. Импорт `time/tzdata` без `_`.** `./main.go:6:2: "time/tzdata" imported and not used`. Пример — в разделе
«Исправление». **Исправление:** напишите `_` вместо имени пакета.

**5. Обычный `go build` программы, которая тянет `net`, на машине без gcc.** На этом ноутбуке выходит так:

```console
$ cd ../statustext && go build -o st main.go
# runtime/cgo
cgo: C compiler "gcc" not found: exec: "gcc": executable file not found in $PATH
```

Читаем: `# runtime/cgo` — ошибка возникла при сборке пакета `runtime/cgo`. *C compiler "gcc" not found* — «компилятор C
gcc не найден». В Go cgo по умолчанию включён (`go env CGO_ENABLED` → `1`), а пакет `net` хочет использовать системную
библиотеку через cgo. **Исправление:** `CGO_ENABLED=0 go build …`. Так бинарник заодно подходит и для `scratch`
(GO-X.01).

## Проверьте себя

Сначала ответьте сами, потом откройте.

**1.** Почему Go-программа, которая ничего не делает, весит 1,8 МБ?

<details>
<summary>Ответ</summary>

Каждый Go-бинарник несёт свой runtime (garbage collector, планировщик и другое), его таблицы (`.gopclntab`) и
отладочную информацию (DWARF). Это постоянная цена. С `-ldflags="-s -w"` уходит отладочная информация, runtime и
таблицы остаются.

</details>

**2.** Если импортировать `net/http` ради одного `http.StatusText`, почему бинарник удваивается?

<details>
<summary>Ответ</summary>

Linker выбрасывает функции, которые никто не вызывает (собственный код `net/http` сократился до 5 262 байт). Но init-код
и глобальные переменные каждого импортированного пакета всегда выполняются до `main`, поэтому они остаются вместе со
всем, что вызывают: `DefaultTransport` → `net`, TLS, 47 пакетов `crypto`. В Go нет `"sideEffects": false`.

</details>

**3.** Образ `scratch` выводит `unknown time zone`. Что делать?

<details>
<summary>Ответ</summary>

База часовых поясов читается из системы, а в `scratch` её нет. Добавьте в пакет `main` `import _ "time/tzdata"`
(+410 КБ), или используйте `go build -tags timetzdata`, или возьмите образ distroless. А `time.Now()` без пояса ошибки
не даёт и молча показывает UTC: проверьте и это.

</details>

**4.** В папке `salom/` файл `main-sw` собран с `-ldflags="-s -w"`. Что выведет `../paketlar.sh main-sw`?
**A)** ту же таблицу, что и для `main` · **B)** числа поменьше · **C)** пустой результат

<details>
<summary>Ответ</summary>

**C.** `-s` убирает таблицу символов, а `go tool nm` читает именно её. Функции в бинарнике есть, нет только таблицы с их
именами и размерами. Если вы выбрали B, вы думали, что `-s -w` уменьшает код: машинный код не меняется.

```console
$ ../paketlar.sh main-sw
reading main-sw: no symbol section
reading main-sw: no symbols
       0 100.0% JAMI
```

</details>

**5.** Из начала урока: `scratch` выводит `exec /api: no such file or directory`. Что проверите первым?

<details>
<summary>Ответ</summary>

Собран ли бинарник с cgo: тогда он ищет в системе libc и её загрузчик, а в `scratch` их нет. Пересоберите с
`CGO_ENABLED=0`. Это тот же вопрос «что не попадает в бинарник», что и с базой часовых поясов.

</details>
