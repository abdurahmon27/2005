## What you will learn

You gave a translator a recipe on one sheet of paper, and they gave you back a thick book. Surprising, right? This
is exactly what happens when Go translates our seven-line program: the ready file is about **32,000 times** bigger
than the original text. In this lesson we find out why.

**The one idea:** `go build` translates our code and saves the translation in a separate ready file. Every time, Go
also puts its own helper (the runtime) inside this file. That is why even the smallest program is about two million
bytes, and why it runs on a computer where Go is not installed. If you change the code, you must build the file
again.

By the end of the lesson you will be able to:

- explain in plain words the difference between `go run` and `go build`;
- build a ready file with `go build`, see its size and run it;
- explain why even the smallest Go program is bigger than a million bytes;
- find and fix the cause when the screen shows old text after you changed the code.

There are only three new words today:

| Word | Plain meaning | Term |
|---|---|---|
| `go build` | the command that saves the translation in a file | go build (*build* = "make") |
| ready file | a file with commands that the computer runs | binary |
| inner helper | the helper part that Go adds to every ready file | runtime |

Two helper words also appear: **byte** (a unit of size: room for one simple letter) and **linker** (only in the
"Going deeper" part).

## `go build`: saving the translation in a file

`go run` uses the translation itself and does not give it to you. But sometimes you need to keep the translation:
to run it later, or to give it to another computer.

Imagine this: the translator does not read the translated recipe aloud to you. They print the translation as a
book and put it in your hands. You can open the book whenever you like, and you can give it to a friend.

```text
go run:    main.go ──► translation ──► runs right away    (you don't get the translation)

go build:  main.go ──► translation ──► 📕 new file         (doesn't run it)
                                          │
                                          └──► later: run it, give it to another computer
```

In Go, the command that saves the translation in a file is called **`go build`** (*build* means "make",
"construct").

| | `go run main.go` | `go build main.go` |
|---|---|---|
| translates? | yes | yes |
| runs? | yes, right away | no |
| gives you the translation? | no | yes, as a new file |

## The ready file: binary

The printed book is a new file. `main.go` holds letters that a person reads. The new file holds commands that the
computer runs, in the computer's language. Such a file is called a **ready file**, or a **binary**.

| | `main.go` | `main` |
|---|---|---|
| what is inside | Go text: letters | computer commands |
| who reads it | a person (and the compiler) | the computer |
| where it came from | we wrote it | `go build` made it |

If you type `go build main.go`, the ready file is named `main`: Go takes the name of the first file without `.go`.
On Windows it is named `main.exe` (`.exe` marks a file that Windows can run).

The program from the video is `salom/main.go`, the "Salom, dunyo" ("Hello, world" in Uzbek) you know from Go 0:

```go filename="salom/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println("Salom, dunyo!")
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `package main` | this is a program you can run |
| 3 | `import "fmt"` | brings in the `fmt` toolbox (package) |
| 5 | `func main() {` | the program starts here |
| 6 | `fmt.Println("Salom, dunyo!")` | prints `Salom, dunyo!` on the screen |
| 7 | `}` | `main` ends, the program ends |

Type `cd salom` in the terminal: the `cd` command moves the terminal into the folder you name. Then we type
`go build main.go`. What appears on the screen? **A)** `Salom, dunyo!` · **B)** nothing · **C)** an error message

<details>
<summary>Answer</summary>

**B: nothing.** `go build` only translates; it does not run the program. So `Salom, dunyo!` does not appear (not
**A**). There is no mistake in the code, so there is no error message either (not **C**). When all goes well,
`go build` stays silent.

</details>

```console
$ cd salom
$ go build main.go
```

Neither command printed anything. But a new file has appeared in the folder.

## Size: 74 bytes and 2,409,990 bytes

Let's look at the new file. We are working on Linux: like Windows and Mac, it is a computer's main system. On Linux,
the `ls -l` command lists the files in a folder with their sizes. On Windows you type `dir` instead.

```console
$ ls -l
total 2360
-rwxr-xr-x 1 haywan users 2409990 Nov 26 15:08 main
-rw-r--r-- 1 haywan users      74 Nov 26 12:25 main.go
```

We don't need the first line (`total`). Every other line is one file. Let's read the `main` line:

| Part | In the `main` line | Meaning |
|---|---|---|
| the characters at the start | `-rwxr-xr-x 1 haywan users` | permissions and the file's owner: ignore them for now |
| the number before the date | `2409990` | the **size** |
| date and time | `Nov 26 15:08` | when the file was built (26 November) |
| the last word | `main` | the file name |

Size is measured in **bytes**. A byte is a small place made of eight zeros or ones, for example `01010011`. One
simple letter fits in it: `01010011` is the letter `S` in the computer's language.

| File | Size | What it is |
|---|---|---|
| `main.go` | 74 bytes | our 7 lines: 74 letters, spaces, a Tab and line ends |
| `main` | 2,409,990 bytes (about two million four hundred thousand) | the ready file that `go build` made |

If you divide 2,409,990 by 74, you get about 32,567. So the ready file is about 32,000 times bigger than the
original text.

On your computer the name, the date and the size may be a little different. In another folder the size differs by a
few bytes, because file paths are also stored inside the ready file.

## Running the ready file: `./main`

Now let's run the ready file. `./main` means "the `main` file in this folder" (you know `./` from GO-0.01). In the
Windows `cmd` window you just type `main`, and in PowerShell (another Windows terminal) you type `.\main`.

```console
$ ./main
Salom, dunyo!
```

Notice: there is no `go` in this command. The translation is already done; the computer itself runs the file.

In short: `go build` saves the translation in a file, and the computer runs that ready file.

```text
main.go (74 bytes) ──go build──► main (2,409,990 bytes) ──./main──► Salom, dunyo!
   recipe                           printed book                       result
```

## The runtime: a helper added to every ready file

Why does one line of work need more than two million bytes?

Think of a kitchen. The recipe says what to cook. But a kitchen also has helper work: washing the dishes. A program
is the same. Values live in memory (GO-0.02), and values that are no longer needed must be cleaned out of memory.

Go itself adds the commands for this kind of helper work to every ready file. Together they are called the
**runtime**, the **inner helper**. Every time, our book is printed with an extra thick "kitchen helper" section.

| In the kitchen | In a Go program |
|---|---|
| recipe: what to cook | our code: print `Salom, dunyo!` |
| washing the dishes | cleaning values that are no longer needed out of memory |
| the helper who does this work | the runtime |
| the extra section in the book | the runtime inside every ready file |

Go's official questions and answers (the Go FAQ) say that the runtime *"is part of every Go program"*. It cleans up
memory (this is called *garbage collection*) and does other important work. We will see the rest in later lessons.

So the computer commands in the `main` file come from three places:

| From where | Commands inside `main` |
|---|---|
| the translation of our 7 lines | only 83 bytes |
| the `fmt` package | `Println` comes from here |
| the runtime | the biggest part: about three quarters of the commands (71 %) |

These numbers were measured with the `go tool nm -size main` command. It shows the size of each group of commands
inside the ready file. You don't need to know this command now.

The commands are only one part of the file. We will see what the rest is in the "Going deeper" section.

## Even an empty program is bigger than a million bytes

Is the runtime really in every file? Let's check. This is `bosh/main.go`, an empty program:

```go filename="bosh/main.go" showLineNumbers
package main

func main() {
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `package main` | familiar: this is a program you can run |
| 3 | `func main() {` | the program starts here |
| 4 | `}` | it ends right away: there is not a single command between the curly braces |

There is no `import` and no `Println` here. The program does nothing.

If we `go build` it, how big will the ready file be? **A)** almost 0 bytes · **B)** about 70 bytes · **C)** more than
1,000,000 bytes

<details>
<summary>Answer</summary>

**C: more than a million bytes**, about 1,830,000 bytes. Go adds the runtime even to a program that does nothing.
If you chose **A** or **B**, you thought the ready file holds only our code. But a Go program cannot run at all
without the runtime.

</details>

In the terminal, we move to the `bosh` folder. `..` means "one folder up", so `cd ../bosh` means "go up, then go into
`bosh`":

```console
$ cd ../bosh
$ go build main.go
$ ls -l main
-rwxr-xr-x 1 haywan users 1829988 Nov 26 15:08 main
```

`ls -l main` shows only the `main` file. Let's compare the two results:

| Program | Ready file |
|---|---|
| empty (`bosh/`) | 1,829,988 bytes |
| "Salom, dunyo" (`salom/`) | 2,409,990 bytes |
| difference: `fmt` and `Println` | 580,002 bytes (about five hundred eighty thousand) |

In short: the runtime is inside every Go program, even one that does nothing.

## Does it run where Go is not installed?

Quick question. We copy the ready `main` file to a friend's computer. It also runs Linux, but Go is not installed.
Does it run? **A)** yes, it runs · **B)** no: you need Go first · **C)** only together with `main.go`

<details>
<summary>Answer</summary>

**A: it runs.** Everything it needs (our code, `fmt` and the runtime) is inside the single `main` file. Go itself
is not needed.

- If you chose **B**: Go was needed only for translating. Once the book is printed, you don't need the translator to
  read it.
- If you chose **C**: `main.go` is the recipe. The ready file is separate from it and does not need `main.go`.

The computer just has to be the same kind: for example, a file built for Linux does not run on Windows. More
precisely, both the system and the processor (the part of the computer that calculates) must be the same.

</details>

```text
main  =  our code + fmt + runtime
  │
  ├──► 📤 friend's computer (Linux, no Go)  ──► Salom, dunyo!   ✅
  │
  └──► 📤 a Windows computer                ──► doesn't run     ❌ the file was built for Linux
```

The Go FAQ says the same: *"All Go binaries therefore include the Go runtime"*. You will check this yourself: the 🔍
homework task is about it.

## Why was Go created?

In 2007, one build of a large program at Google took 45 minutes. Rob Pike, one of Go's authors, wrote about this in a
2012 article. According to the story, the idea of Go was born during one of those waits (Pike himself calls it Go's
"origin myth").

The goal is written in the Go FAQ: writing code should be easy, and the program should run fast and safely. Even a
large program should build in a few seconds on one computer.

## You changed the code: build the file again

Now the most common mistake. In the terminal, go back to the `salom` folder with `cd ../salom`. Open `main.go`,
replace the word `dunyo` with `Aziza` (a name) on line 6, and save the file. Now the file looks like this:

```go
package main

import "fmt"

func main() {
	fmt.Println("Salom, Aziza!")
}
```

But we don't type `go build` again; we run `./main` right away. What appears on the screen?
**A)** `Salom, Aziza!` · **B)** `Salom, dunyo!` · **C)** an error message

Remember the book: we changed the recipe after the book was printed.

<details>
<summary>Answer</summary>

**B: the old `Salom, dunyo!`.** The ready file was made from the code as it was at the moment of translation. When
you change `main.go`, the printed book does not change: they are two separate files.

- If you chose **A**, you thought `./main` reads `main.go` every time. The command that does that is `go run`.
- If you chose **C**: nothing is broken. The old ready file is still there and does its job.

</details>

```console
$ ./main
Salom, dunyo!
```

The fix is easy: first `go build`, then `./main`.

```console
$ go build main.go
$ ./main
Salom, Aziza!
```

What happened, step by step:

| Step | In `main.go` | In `main` (ready file) | On screen |
|---|---|---|---|
| `go build main.go` (earlier) | `dunyo` | `dunyo` | |
| we edited and saved `main.go` | `Aziza` | `dunyo` (unchanged) | |
| `./main` | `Aziza` | `dunyo` | `Salom, dunyo!` |
| `go build main.go` | `Aziza` | `Aziza` (built again) | |
| `./main` | `Aziza` | `Aziza` | `Salom, Aziza!` |

**Rule:** changed the code? Build the file again. `go run` does this by itself every time, which is why this
mistake never happened in the Go 0 lessons.

When you are done checking, change `main.go` back to `Salom, dunyo!`: the next examples expect that text.

## Going deeper (optional): what is inside go build

If you are just starting, you can read this part later. The main idea of the lesson ended before it.

**1. The compiler translates the parts separately.** `go build` first translates `main.go`, the `fmt` package and
the runtime, each one separately. It remembers the finished parts, so that it doesn't translate them again next
time. This storage place is called the *build cache*. According to the course README, our 7-line program built in
about 2.8 seconds the first time and in about 0.1 seconds the next time. Since Go 1.24, `go run` also uses this
place, but it translates again when the code has changed.

**2. The linker stitches everything into one file.** When the sections of a book are printed separately, a
bookbinder stitches them into one book. In Go this job is done by the **linker**. It joins the translated parts into
one `main` file and throws away the groups of commands that nobody calls.

```text
main.go  ──► compiler ──┐
fmt      ──► compiler ──┼──► linker ──► main (ready file)
runtime  ──► compiler ──┘
             (remembers finished parts)
```

**3. What is inside the file.** The Linux command `size -A main` measures the parts of the ready file:

| Part | Bytes | Share | What it is for |
|---|---|---|---|
| computer commands | 643,537 | about a quarter (27 %) | the program itself: our code, `fmt`, the runtime |
| names of the command groups and line numbers | 677,386 | about a quarter (28 %) | if the program stops with an error while running, this tells which line it stopped on; the runtime uses it too |
| information for finding bugs | 676,118 | about a quarter (28 %) | a programmer needs it when looking for a bug; the program runs without it |
| the rest | 412,949 | 17 % | texts, information about types and more |

A "group of commands" is a function from GO-0.01 (like `func main`). According to the Go FAQ, you can remove the
bug-finding information with `-ldflags=-w`, and the program still runs.

## Common mistakes

**1. Changing the code and not running `go build` again.** The most common mistake, and a silent one: there is no
error message, the screen just shows the old text. We saw it above, in the section "You changed the code: build the
file again". **Fix:** after every edit, first `go build main.go`, then `./main`.

**2. The terminal is open in the wrong folder.** The terminal is in the lesson folder itself (`lessons/001-why-go`),
not inside `salom`. There is no `main.go` there:

```console
$ go build main.go
no required module provides package main.go; to add it:
	go get main.go
```

The message says: "no module provides a package called `main.go`; to add it: `go get main.go`". Go did not find a
`main.go` file in this folder. So it thought `main.go` was the name of a package to download from the internet (a
module is the folder of a Go project; we will see it in later lessons). Don't type `go get` here: you don't need it.
**Fix:** `cd salom`, then `go build main.go` again. Check with `ls` (on Windows `dir`) that `main.go` is in the
folder.

**3. Typing `main` without `./`.** The Linux and Mac terminal looks for commands only in the system folders it knows,
not in the current folder:

```console
$ main
bash: main: command not found
```

"there is no command called `main`". The Mac terminal writes the same message as `zsh: command not found: main`.
**Fix:** `./main`, that is, "the `main` in this folder". (In the Windows `cmd` window, `main` does work.)

If `./main` does not work either, there is no ready file in the folder yet: you have not run `go build`, or you are
in another folder.

```console
$ ./main
bash: ./main: No such file or directory
```

"there is no such file or folder". **Fix:** in the right folder, first `go build main.go`, then `./main`.
