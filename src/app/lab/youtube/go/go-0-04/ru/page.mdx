## Что вы узнаете

Если ваша покупка в магазине дошла до 100 000 сумов, касса сама даёт скидку. Кассир ничего не считает. Кто принял
решение? Программа. В этом уроке вы напишете свою первую программу, которая так же сама принимает решение.

**Одна идея:** программа сравнивает два числа и задаёт вопрос. Ответ бывает только «да» (`true`) или «нет» (`false`),
а `if` по этому ответу выбирает только одну из двух дорог.

К концу урока вы:

- прочитаете вопрос вроде `xarid >= 100000` простыми словами и скажете его ответ (`true` или `false`);
- напишете программу скидки на `if` / `else` и программу оценки на `else if`;
- сможете сказать, что программа выведет на экран, ещё до её запуска;
- узнаете две самые частые ошибки: один `=` внутри `if` и неправильный порядок вопросов в `else if`.

Сегодня три новых слова:

| Знак или слово | Простой смысл | По-английски |
|---|---|---|
| сравнение (`>`, `<`, `>=`, `<=`, `==`, `!=`) | сравнить два числа и задать вопрос | comparison |
| `true` / `false` | ответ на вопрос: да (истина) / нет (ложь) | true / false |
| `if` / `else` | «если …» / «иначе» | if / else |

Встретятся и два вспомогательных слова: `bool` (тип «да-нет») и `else if` («иначе, если»).

## Вопрос кассы: сравнение

Касса задаёт каждой покупке один вопрос: **«покупка больше или равна 100 000 сумов?»** Ответ бывает только двух видов:
если да, даётся скидка, если нет, берётся полная цена.

```text
         покупка ≥ 100 000 ?
            /           \
          да            нет
           |              |
   скидка даётся     полная цена
```

В таком вопросе сравниваются два числа. По-русски это **сравнение**, по-английски **comparison**. В Go используются
школьные знаки «больше» и «меньше». На клавиатуре нет знаков `≥` и `≤`, поэтому их пишут двумя символами: сначала
«больше» (или «меньше»), потом «равно».

| Знак | Как читается | Пример | Ответ |
|---|---|---|---|
| `>` | больше | `5 > 3` | да |
| `<` | меньше | `3 < 5` | да |
| `>=` | больше или равно (≥) | `5 >= 5` | да: даже если равны |
| `<=` | меньше или равно (≤) | `4 <= 5` | да |

`>=` и `<=` — это один знак: между `>` и `=` пробел не ставится. Есть ещё два знака (`==` и `!=`), их мы разберём
перед ошибками.

## Ответ — тоже значение: `true` и `false`

Ответ сравнения — тоже **значение**, как число или текст. Но Go называет его английским словом:

| Ответ кассы | В Go | По-русски |
|---|---|---|
| да | `true` | истина |
| нет | `false` | ложь |

Каждое сравнение даёт одно из двух, третьего не бывает.

Раз ответ — значение, его можно приклеить к ярлыку. Посмотрите на эти три строки (внутренняя часть программы):

```go
xarid := 120000
katta := xarid >= 100000
fmt.Println(katta)
```

- **Строка 1:** новый ярлык `xarid` («покупка»), значение 120 000.
- **Строка 2:** справа стоит вопрос. Как в прошлом уроке, Go **сначала вычисляет правую часть**: `120000 >= 100000`?
  Да, ответ `true`. Потом новый ярлык `katta` («больше») приклеивается к этому ответу.
- **Строка 3:** выводит на экран значение под `katta`: `true`.

Картина памяти:

| После строки | `xarid` | `katta` | На экране |
|---|---|---|---|
| 1 `xarid := 120000` | `120000` (int) | — (ещё нет) | |
| 2 `katta := xarid >= 100000` | `120000` (int) | `true` (bool) | |
| 3 `fmt.Println(katta)` | `120000` | `true` | `true` |

У значения под `katta` тоже есть тип. Это **bool**, то есть тип «да-нет»: в нём всего два значения, `true` и `false`.
К `int` (число) и `string` (текст) из прошлого урока добавился третий тип.

Теперь изменим первую строку: покупка 50 000. Это файл `taqqos/main.go` из папки курса:

```go filename="taqqos/main.go" showLineNumbers
package main

import "fmt"

func main() {
	xarid := 50000
	katta := xarid >= 100000
	fmt.Println(katta)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1–5 | `package main` … `func main() {` | знакомый шаблон из первого урока |
| 6 | `xarid := 50000` | новый ярлык `xarid`, значение 50 000 |
| 7 | `katta := xarid >= 100000` | вопрос: `50000 >= 100000`? Ответ попадает под новый ярлык `katta` |
| 8 | `fmt.Println(katta)` | выводит ответ под `katta` на экран |
| 9 | `}` | конец `main` и программы |

Перед запуском угадайте: что будет на экране? **A)** `false` · **B)** `true` · **C)** `50000`

<details>
<summary>Ответ</summary>

**A: `false`.** 50 000 меньше 100 000, значит, на вопрос «больше или равно?» ответ — нет, то есть `false`.
Если вы выбрали `true`, вы вспомнили старые 120 000: теперь в строке 6 стоит 50 000. Если выбрали `50000`: ярлык
`katta` приклеен не к самой покупке, а к ответу на вопрос.

</details>

`go run` переводит программу и сразу её запускает:

```console
$ go run taqqos/main.go
false
```

Коротко: сравнение задаёт вопрос, а его ответ — `true` или `false`.

## `if` и `else`: одна дорога из двух

Знать ответ мало, программа должна по нему действовать. Запишем правило кассы предложением:
**если** покупка больше или равна 100 000, дай скидку, **иначе** возьми полную цену.

В Go слово **`if`** значит «если», а **`else`** — «иначе».

Сначала часть с `if`. Покупка ровно 100 000:

```go
xarid := 100000
if xarid >= 100000 {
	fmt.Println("chegirma bor")
}
```

- **Строка 1:** новый ярлык `xarid`, значение 100 000.
- **Строка 2:** `if`, потом вопрос (`xarid >= 100000`), потом фигурная скобка `{`. Как в первом уроке, `{` — начало
  группы.
- **Строка 3:** строка внутри группы. Она выводит `chegirma bor` («скидка есть»), но выполняется **только если ответ
  на вопрос `true`**. Отступ (табуляция) в начале строки показывает, что она внутри группы.
- **Строка 4:** `}` — конец группы.

Теперь добавим вторую группу. После `}`, закрывающей первую группу, **на той же строке** идут `else` и новая группа:

```go
xarid := 100000
if xarid >= 100000 {
	fmt.Println("chegirma bor")
} else {
	fmt.Println("chegirma yoʻq")
}
```

- **Строка 4:** `} else {` — первая группа закончилась, началась группа «иначе».
- **Строка 5:** выводит `chegirma yoʻq` («скидки нет»), но выполняется **только если ответ `false`**.
- **Строка 6:** `}` — конец второй группы.

Полная программа — файл `chegirma/main.go` из папки курса:

```go filename="chegirma/main.go" showLineNumbers
package main

import "fmt"

func main() {
	xarid := 100000
	if xarid >= 100000 {
		fmt.Println("chegirma bor")
	} else {
		fmt.Println("chegirma yoʻq")
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `xarid := 100000` | новый ярлык `xarid`, значение 100 000 |
| 7 | `if xarid >= 100000 {` | задаёт вопрос; если ответ `true`, заходит в строку 8 |
| 8 | `fmt.Println("chegirma bor")` | выполняется только при ответе `true` |
| 9 | `} else {` | если ответ `false`, программа отсюда заходит в строку 10 |
| 10 | `fmt.Println("chegirma yoʻq")` | выполняется только при ответе `false` |
| 11 | `}` | конец группы `else` |
| 12 | `}` | конец `main` |

Покупка ровно 100 000. Что будет на экране? **A)** `chegirma bor` · **B)** `chegirma yoʻq` · **C)** обе строки

<details>
<summary>Ответ</summary>

**A: `chegirma bor`.** 100 000 равно 100 000, а знак `>=` даёт `true` и при равенстве. Поэтому выполнилась группа `if`.
Если вы выбрали «нет», вы прочитали `>=` как простое «больше». Если выбрали «обе»: из двух групп всегда
выполняется только одна.

</details>

```console
$ go run chegirma/main.go
chegirma bor
```

Как шла программа:

| Строка | Что произошло | На экране |
|---|---|---|
| 6 `xarid := 100000` | под `xarid` лежит `100000` | |
| 7 `if xarid >= 100000 {` | `100000 >= 100000` → `true` | |
| 8 `fmt.Println("chegirma bor")` | выполнилась | `chegirma bor` |
| 9–11 `} else { … }` | **пропущены** | |

```text
              xarid >= 100000 ?   →  true
               /              \
        группа if ✔        группа else ✘
     "chegirma bor"          (пропущен)
```

Коротко: из двух групп всегда выполняется только одна. Ответ `true` — группа `if`, ответ `false` — группа `else`.

## Маленькая проверка: `>` и `>=`

Теперь в строке 7 вместо `>=` поставим только `>` (больше). Покупка снова 100 000. Это `sinov/main.go`:

```go filename="sinov/main.go" showLineNumbers
package main

import "fmt"

func main() {
	xarid := 100000
	if xarid > 100000 {
		fmt.Println("chegirma bor")
	} else {
		fmt.Println("chegirma yoʻq")
	}
}
```

Отличие от `chegirma/main.go` только в строке 7: не `xarid >= 100000`, а `xarid > 100000`.

Что теперь будет на экране? **A)** `chegirma bor` · **B)** `chegirma yoʻq` · **C)** ошибка

<details>
<summary>Ответ</summary>

**B: `chegirma yoʻq`.** 100 000 **не больше** 100 000, оно ему равно. Ответ `false`, поэтому выполнилась группа `else`.
Если вы выбрали «ошибка»: `>` — тоже правильный знак сравнения, программа спокойно работает.

</details>

```console
$ go run sinov/main.go
chegirma yoʻq
```

| Вопрос | Ответ | Какая группа |
|---|---|---|
| `100000 >= 100000` | `true` | `if`: скидка есть |
| `100000 > 100000` | `false` | `else`: скидки нет |

Один знак решает судьбу покупки на границе. Говорит ли правило «**дошла** до 100 000» или «**больше** 100 000» —
от этого зависит, выбрать `>=` или `>`.

## `else if`: вопросы друг за другом

Иногда ответов не два, а три. Например, балл за тест (это наш пример, а не официальная шкала):

- 90 и выше — `aʼlo` («отлично»);
- 70 и выше — `yaxshi` («хорошо»);
- в остальных случаях — `qayta topshiring` («пересдайте»).

Ставим вопросы друг за другом: **`else if`**, то есть «иначе, если». Последний `else` выполняется, если ни один ответ
не был `true`. Это `baho/main.go`:

```go filename="baho/main.go" showLineNumbers
package main

import "fmt"

func main() {
	ball := 75
	if ball >= 90 {
		fmt.Println("aʼlo")
	} else if ball >= 70 {
		fmt.Println("yaxshi")
	} else {
		fmt.Println("qayta topshiring")
	}
}
```

Новые строки:

| Строка | Код | Что делает |
|---|---|---|
| 6 | `ball := 75` | новый ярлык `ball` («балл»), значение 75 |
| 7–8 | `if ball >= 90 {` … `"aʼlo"` | вопрос 1: при ответе `true` выводит `aʼlo` |
| 9–10 | `} else if ball >= 70 {` … `"yaxshi"` | вопрос 2: задаётся, только если ответ 1 — `false` |
| 11–12 | `} else {` … `"qayta topshiring"` | выполняется, если оба ответа `false` |
| 13 | `}` | конец последней группы |

Если балл 75, что будет на экране? **A)** `yaxshi` · **B)** `aʼlo` · **C)** `qayta topshiring`

<details>
<summary>Ответ</summary>

**A: `yaxshi`.** 75 меньше 90, но больше 70. Если вы выбрали `aʼlo`, проверьте вопрос 1 ещё раз: `75 >= 90` —
`false`. `qayta topshiring` выводится, только когда на оба вопроса ответ `false`.

</details>

```console
$ go run baho/main.go
yaxshi
```

Go проверяет вопросы **сверху вниз, по одному**:

| Шаг | Строка | Вопрос | Ответ | Что происходит |
|---|---|---|---|---|
| 1 | 7 | `75 >= 90` | `false` | переходит к следующему вопросу |
| 2 | 9 | `75 >= 70` | `true` | строка 10: на экране `yaxshi` |
| 3 | 11 | `else` | — | **не проверяется** |

Коротко: как только найден первый `true`, остальное вообще не проверяется.

## Равно ли? `==` и `!=`

В прошлом уроке один `=` значил «пусть будет»: он кладёт значение под ярлык и **ничего не спрашивает**. Чтобы
спросить, равны ли два числа, в Go пишут **два знака равенства**: `==`. Есть и обратный вопрос: восклицательный знак
и равно, `!=`, то есть «не равно ли?».

| Запись | Как читается | Что делает |
|---|---|---|
| `a = 4` | пусть `a` будет 4 | присваивание: кладёт 4 под `a` |
| `a == 4` | `a` равно 4? | вопрос: ответ `true` или `false` |
| `a != 4` | `a` не равно 4? | вопрос: ответ `true` или `false` |

Этой маленькой программы нет в папке курса, мы запустили её отдельно для этой страницы:

```go
package main

import "fmt"

func main() {
	a := 4
	fmt.Println(a == 4, a != 4)
	a = 5
	fmt.Println(a == 4, a != 4)
}
```

- **Строка 6:** новый ярлык `a`, значение 4.
- **Строка 7:** два вопроса: `a == 4`? и `a != 4`? `Println` выводит оба ответа в одну строку через пробел.
- **Строка 8:** один `=`: пусть `a` теперь будет 5.
- **Строка 9:** те же два вопроса, но теперь под `a` лежит 5.

Угадайте: **A)** `true false`, потом `false true` · **B)** `true true`, потом `false false` ·
**C)** `true false`, потом `true false`

<details>
<summary>Ответ</summary>

**A.** Сначала под `a` лежит 4: «равно 4?» — `true`, «не равно?» — `false`. После строки 8 под `a` лежит 5:
теперь «равно?» — `false`, «не равно?» — `true`. `==` и `!=` всегда отвечают противоположно. «B» не бывает: два
вопроса не могут одновременно дать `true`. Если вы выбрали «C», вы забыли про `a = 5` в строке 8.

</details>

```console
$ go run teng/main.go
true false
false true
```

## Глубже (необязательно): ещё четыре факта об `if`

Этой части нет в видео, она взята из README папки курса.

- **Круглые скобки вокруг вопроса не нужны, а фигурные обязательны:** `if xarid >= 100000 {`
  ([A Tour of Go](https://go.dev/tour/flowcontrol/5)).
- **`else` не обязателен.** В `tuzat/main.go` из следующего раздела есть только `if`: если ответ `false`, программа
  ничего не выводит.
- **В `else if ball >= 70` не нужно добавлять вопрос «`ball` меньше 90».** До этого вопроса доходит очередь, только
  если предыдущий ответ `ball >= 90` был `false`. Гарвардский CS50 задаёт тот же вопрос: *"not all these lines of code
  are required"*.
- **Вопрос после `if` программисты называют ещё условием (condition).** В этом уроке мы держались одного слова —
  «вопрос».

## Частые ошибки

**1. Один `=` внутри `if` (самая частая ошибка).** В этой программе ответ ученика — 4. Если ответ 4, на экран
должно выйти `toʻgʻri` («правильно»). Помните: после `if` стоит вопрос. Но в строке 7 по ошибке написан один `=`, а
это не вопрос. Это `xato/main.go`, ошибка сделана нарочно:

```go filename="xato/main.go" showLineNumbers
package main

import "fmt"

func main() {
	javob := 4
	if javob = 4 {
		fmt.Println("toʻgʻri")
	}
}
```

Что сделает эта программа? **A)** выведет `toʻgʻri` · **B)** промолчит · **C)** выдаст ошибку

<details>
<summary>Ответ</summary>

**C: ошибка.** Компилятор не переводит программу, и она вообще не запускается. После `if` нужен вопрос, а один `=`
не вопрос, он кладёт значение. Если вы выбрали `toʻgʻri`, вы прочитали `=` как математическое «равно».

</details>

```console
$ go run xato/main.go
# command-line-arguments
xato/main.go:7:11: syntax error: cannot use assignment javob = 4 as value
```

Читаем сообщение по частям, как в первом уроке:

| Часть | Смысл |
|---|---|
| `xato/main.go` | файл |
| `7` | **строка 7** |
| `11` | **11-й символ** в строке: ровно один `=` (табуляция — 1, `if` — 2–3, пробел — 4, `javob` — 5–9, пробел — 10, `=` — 11) |
| `syntax error` | синтаксическая ошибка: компилятор не смог прочитать код |
| `cannot use assignment javob = 4 as value` | «присваивание `javob = 4` нельзя использовать как значение (ответ)» |

Эта ошибка встречается так часто, что в компиляторе Go для неё есть отдельное сообщение. В коде компилятора есть такой
комментарий: *"A common syntax error is to write '=' instead of '=='"* («частая ошибка — написать `=` вместо `==`»).

**Исправление:** пишем два знака равенства. Это `tuzat/main.go`:

```go filename="tuzat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	javob := 4
	if javob == 4 {
		fmt.Println("toʻgʻri")
	}
}
```

Изменилась только строка 7: `javob == 4` — «ответ равен 4?». В этой программе нет `else`: при ответе `false` она
ничего бы не вывела.

```console
$ go run tuzat/main.go
toʻgʻri
```

**2. Неправильный порядок вопросов в `else if`.** Здесь компилятор молчит, а программа даёт неверный ответ. Это та же
программа оценки, только два вопроса поменялись местами: сначала спрашивается 70, потом 90. А балл — 95.
Это `tartib/main.go`:

```go filename="tartib/main.go" showLineNumbers
package main

import "fmt"

func main() {
	ball := 95
	if ball >= 70 {
		fmt.Println("yaxshi")
	} else if ball >= 90 {
		fmt.Println("aʼlo")
	} else {
		fmt.Println("qayta topshiring")
	}
}
```

Что будет на экране для 95 баллов? **A)** `aʼlo` · **B)** `yaxshi` · **C)** обе строки

<details>
<summary>Ответ</summary>

**B: `yaxshi`.** Go проверяет вопросы сверху вниз и останавливается на первом `true`. `95 >= 70` — `true`, поэтому
на экран выходит `yaxshi`, а до вопроса про `aʼlo` очередь не доходит. Если вы выбрали `aʼlo`, вы думали, что Go
смотрит все вопросы и выбирает самый подходящий. «Обе» не бывает: после этих вопросов выполняется только одна группа.

</details>

```console
$ go run tartib/main.go
yaxshi
```

| Шаг | Строка | Вопрос | Ответ | Что происходит |
|---|---|---|---|---|
| 1 | 7 | `95 >= 70` | `true` | строка 8: на экране `yaxshi` |
| 2 | 9 | `95 >= 90` | — | **не проверяется** (а был бы `true`) |
| 3 | 11 | `else` | — | не проверяется |

**Исправление:** самый строгий вопрос, то есть `>= 90`, ставьте первым. Это ровно порядок из `baho/main.go`
(раздел «`else if`: вопросы друг за другом» выше).

**3. Путаница `>` и `>=` на границе.** Это тоже тихая ошибка: правило говорит «дошла до 100 000», а в коде написано
`>`. В итоге покупка ровно на 100 000 остаётся без скидки. Подробно: раздел «Маленькая проверка» выше.
**Исправление:** для правила «дошла до», «и выше» пишите `>=`.

**4. `else` на новой строке.** Этой программы нет в папке курса, мы запустили её отдельно для этой страницы:

```go
package main

import "fmt"

func main() {
	xarid := 100000
	if xarid >= 100000 {
		fmt.Println("chegirma bor")
	}
	else {
		fmt.Println("chegirma yoʻq")
	}
}
```

```console
$ go run elsequr/main.go
# command-line-arguments
elsequr/main.go:10:2: syntax error: unexpected keyword else, expected }
```

Строка 10, символ 2: ровно слово `else`. `unexpected keyword else` — «неожиданное слово: `else`», `expected }` —
«здесь ожидалась `}`». Go считает, что после `}` в конце строки команда закончилась, поэтому `else` на следующей
строке остаётся «сиротой». **Исправление:** пишите `else` на одной строке с предыдущей `}`: `} else {`.

**5. Сравнение текста с числом.** Этой программы тоже нет в папке курса, она запущена отдельно:

```go
package main

import "fmt"

func main() {
	yosh := "15"
	fmt.Println(yosh == 15)
}
```

```console
$ go run matn/main.go
# command-line-arguments
matn/main.go:7:22: invalid operation: yosh == 15 (mismatched types string and untyped int)
```

Это родственница ошибки из прошлого урока: `invalid operation` — «недопустимая операция», в скобках причина: «типы не
совпадают, один `string`, другой — число». Под `yosh` («возраст») лежит `"15"` в кавычках, то есть текст, а `15` —
число. Сравнение, как и плюс, работает только со значениями одного типа. **Исправление:** пишите число без кавычек:
`yosh := 15`.

## Проверьте себя

Сначала ответьте сами, потом откройте.

**1.** Каков ответ `5 < 3`?

<summary>Ответ</summary>

`false`, потому что 5 не меньше 3.

**2.** Чем отличаются один `=` и два `==`?

<details>
<summary>Ответ</summary>

Один `=` кладёт значение под ярлык (присваивание). Два `==` задают вопрос «равно ли?», ответ — `true` или `false`.

</details>

**3.** Когда выполняется группа `else`?

<details>
<summary>Ответ</summary>

Только когда ответ на вопрос — `false`. А если вопросы идут друг за другом через `else if` — когда на все вопросы
выше ответ `false`.

</details>

**4.** Что выведет этот код?

**5.** Из первого урока: что значит первое число (`7`) в сообщении `xato/main.go:7:11`?
