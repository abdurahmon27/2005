## Что вы узнаете

В TypeScript вы объявили поле `price` как `number`. А бэкенд прислал цену в JSON строкой: `{"price": "2"}`.
`tsc --strict` молчит, а JavaScript превращает `"2" + 2` в `22`. В Go такое же сложение не собирается. Почему так
и что это меняет для бэкенда?

**Одна идея:** Go строго проверяет типы при сборке и доносит информацию о типах до рантайма, а TypeScript её
стирает. Поэтому `"2" + 2` не собирается, `"2"` из JSON не попадает в поле `int`, а переменная без значения — не
`undefined`, а zero value своего типа.

К концу урока вы:

- прочитаете ошибку `mismatched types` и исправите смешанные типы явным преобразованием (`float64(a)`);
- будете знать, что `json.Unmarshal` возвращает ошибку для поля не того типа, а отсутствующее поле молча делает `0`;
- отличите `:=` от `=` и найдёте затенение внутри `if` на код-ревью;
- будете правильно писать `for _, p := range` и использовать `strconv.Itoa(id)` вместо `string(id)`.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| статический тип | тип каждой переменной задаётся при сборке и не меняется; смешанные типы — только через явное `T(x)` | static type, conversion |
| zero value | начальное значение переменной без значения: `0`, `""`, `false`, `nil` | zero value |
| `:=` и `=` | `:=` объявляет новую переменную, `=` присваивает значение существующей; `:=` во внутреннем блоке затеняет внешнюю | short variable declaration, assignment, shadowing |

Есть и два вспомогательных слова: **`strconv.Itoa`** (превращает число в строку десятичных цифр) и **`go vet`**
(статический анализатор, который идёт вместе с Go). В конце — ещё и запись `for`/`range`.

## `"2" + 2`: типы TypeScript стираются после сборки

Сначала доказательство. TypeScript-файл из начала урока:

```ts filename="js/narx.ts"
type Item = { price: number };

const item: Item = JSON.parse('{"price": "2"}');
console.log(item.price + 2);
```

`JSON.parse` возвращает `any` (так записано в файле `lib.es5.d.ts` самого TypeScript), а `any` можно присвоить
любому типу. Поэтому `tsc` молчит даже в режиме `--strict`:

```console
$ npx -p typescript@5.9.3 tsc --strict js/narx.ts && node js/narx.js
22
```

`tsc` ничего не вывел, то есть ошибок нет, и записал `js/narx.js`. `node` запустил его и вывел `22`. Посмотрите
на JavaScript, который сгенерировал `tsc`:

```console
$ cat js/narx.js
"use strict";
var item = JSON.parse('{"price": "2"}');
console.log(item.price + 2);
```

В файле нет ни `Item`, ни `number`, рантайм их не видит. Документация TypeScript пишет об этом прямо: аннотации
типов никогда не меняют поведение программы в рантайме, они полностью стираются (type erasure). Рантайм видит
только строку `"2"`. А оператор `+` в JavaScript, если одна сторона — строка, превращает в строку и вторую и
склеивает их (MDN). Node 24 умеет запускать `.ts`-файл и напрямую (`node js/narx.ts` тоже даёт `22`): он просто
вырезает типы, не проверяя их.

Тот же код на Python:

```python filename="js/narx.py"
import json

item = json.loads('{"price": "2"}')
print(item["price"] + 2)
```

```console
$ python3 js/narx.py
Traceback (most recent call last):
  File "…/js/narx.py", line 4, in <module>
    print(item["price"] + 2)
          ~~~~~~~~~~~~~~^~~
TypeError: can only concatenate str (not "int") to str
```

(Полный путь в выводе сокращён до `…`: он зависит от папки на вашем компьютере.) *can only concatenate str (not
"int") to str* — «к str можно приклеить только str, не int». Python выдаёт `TypeError`, но только когда
выполняется эта строка, то есть, возможно, уже в продакшене.

## Статический тип: в Go `"2" + 2` не собирается

То же сложение на Go, `hook/main.go`:

```go filename="hook/main.go" showLineNumbers
package main

import "fmt"

func main() {
	price := "2"
	count := 2
	fmt.Println(price + count)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `package main` | пакет исполняемой программы (GO-X.01) |
| 3 | `import "fmt"` | `fmt` — пакет для вывода на экран |
| 5 | `func main() {` | программа начинается с этой функции |
| 6 | `price := "2"` | `price` («цена») — новая переменная; `:=` берёт тип из правой части: `string` |
| 7 | `count := 2` | `count` («количество») — тип `int` |
| 8 | `fmt.Println(price + count)` | `string` + `int`: Go это не принимает |

```console
$ go run hook/main.go
# command-line-arguments
hook/main.go:8:14: invalid operation: price + count (mismatched types string and int)
```

`hook/main.go:8:14` — строка 8, столбец 14 (табуляция считается за один столбец), то есть место, где начинается
`price`. *invalid operation: price + count (mismatched types string and int)* — «недопустимая операция: типы не
совпадают, `string` и `int`». `# command-line-arguments` в первой строке — пакет, где ошибка: если в команде
указаны имена `.go`-файлов, Go собирает из них безымянный пакет и называет его так (`go help packages`).

В Go тип каждой переменной задаётся при сборке и не меняется. Это **статический тип** (static type). `:=` берёт
тип из значения справа, как `let` в TypeScript. Компилятор видит `hook/main.go` так:

| Переменная | Значение | Тип | Откуда |
|---|---|---|---|
| `price` | `"2"` | `string` | строка 6, `:=` взял из правой части |
| `count` | `2` | `int` | строка 7, `:=` взял из правой части |
| `price + count` | — | ⛔ | `string` и `int`: ошибка компиляции, бинарника нет |

По спецификации Go у бинарного оператора обе стороны должны быть одного типа (кроме сдвигов и нетипизированных
констант). Go сам не преобразует переменные разных типов. Поэтому ошибка возникла при сборке, и бинарник не был
создан.

| | JavaScript / TypeScript | Python | Go |
|---|---|---|---|
| `"2" + 2` | `"22"` | `TypeError`, только когда строка выполняется | ошибка компиляции |
| когда проверяется тип | при `tsc`, потом стирается | в рантайме | при сборке; информация о типе есть и в рантайме |

А в PHP, по [документации PHP](https://www.php.net/manual/en/language.operators.arithmetic.php), `"2" + 2` → `4`:
числовая строка превращается в число, а для склейки есть отдельный оператор `.` (PHP для этого урока не
запускали).

## `int` и `float64`: явное преобразование

Теперь обе стороны — числа. `a` — 2, `b` — 1.5:

```go
a := 2
b := 1.5
fmt.Println(a + b)
```

Что выведется? **A)** `3.5` · **B)** `3` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**C: ошибка компиляции.** `number` в JavaScript — на самом деле `float64` (IEEE 754 double), отдельного типа для
целых нет. А в Go `:=` выбирает для `2` тип `int`, для `1.5` — `float64`, и это два разных типа. Если вы выбрали
«`3.5`», вы перенесли правило JS/Python: и `node -p '2 + 1.5'`, и Python дают `3.5`. Если вы выбрали «`3`», вы
думали, что Go отбросит дробную часть и сделает `int`: он вообще не складывает.

</details>

```go filename="aralash/main.go" showLineNumbers
package main

import "fmt"

func main() {
	a := 2
	b := 1.5
	fmt.Println(a + b)
}
```

```console
$ go run aralash/main.go
# command-line-arguments
aralash/main.go:8:14: invalid operation: a + b (mismatched types int and float64)
```

Строка 8, столбец 14: `a`. *mismatched types int and float64* — «типы не совпадают: `int` и `float64`».

**Исправление:** преобразуйте тип явно: `float64(a)`. Форма `T(x)` — **преобразование** (conversion): даёт
значение `x` в типе `T`. `aylantir/main.go` («преобразовать»):

```go filename="aylantir/main.go" showLineNumbers
package main

import "fmt"

func main() {
	a := 2
	b := 1.5
	fmt.Printf("%T %T\n", a, b) // int float64
	fmt.Println(float64(a) + b) // 3.5
}
```

| Строка | Код | Что делает |
|---|---|---|
| 8 | `fmt.Printf("%T %T\n", a, b)` | `Printf` — форматированный вывод; `%T` выводит тип значения; `\n` — перевод строки |
| 9 | `fmt.Println(float64(a) + b)` | `float64(a)` — `2` теперь `float64`; обе стороны одного типа |

```console
$ go run aylantir/main.go
int float64
3.5
```

`%T` похож на `typeof` в JavaScript, но точнее: `typeof 2` и `typeof 1.5` оба дают `number`, а Go говорит `int` и
`float64`. Почему Go не преобразует сам? Причина написана в Go FAQ: удобство автоматического преобразования между
числовыми типами в C не стоит путаницы, которую оно создаёт. Коротко: смешанные типы складываются только через
явное преобразование.

## В рантайме: `"2"` из JSON и поле `int`

Теперь JSON из начала урока, на Go. `json/main.go`:

```go filename="json/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
)

type Item struct {
	Price int `json:"price"`
}

func main() {
	body := `{"price": "2"}`
	var item Item
	err := json.Unmarshal([]byte(body), &item)
	fmt.Println(item.Price, err)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–6 | `import ( … )` | два пакета в скобках: `encoding/json` (JSON) и `fmt` |
| 8–10 | `type Item struct { … }` | `Item` — тип, как `type Item = { price: number }` в TypeScript. В Go такой тип называется **структура** (struct), подробно в [GO-1.10](/lab/youtube/go/go-1-10/ru) |
| 9 | `Price int` + текст в обратных кавычках | поле `Price` типа `int`. **Тег** (tag) в обратных кавычках говорит, что ключ `price` из JSON попадает в это поле. Заглавная буква — поле экспортировано (export, GO-X.01): `encoding/json` заполняет только такие поля |
| 13 | `body := …` | строка в обратных кавычках: `"` внутри не нужно экранировать |
| 14 | `var item Item` | переменная типа `Item` без значения (об этом в следующем разделе) |
| 15 | `err := json.Unmarshal([]byte(body), &item)` | `Unmarshal` записывает байты JSON в `item`. `[]byte(body)` — преобразование строки в байты. `&item` — адрес `item`, чтобы `Unmarshal` мог его изменить (указатели — в [GO-X.04](/lab/youtube/go/go-x-04/ru)). `err` — значение ошибки (тема [GO-X.03](/lab/youtube/go/go-x-03/ru)) |
| 16 | `fmt.Println(item.Price, err)` | выводит поле и ошибку |

Тип `Item` в TypeScript в рантайме молчал. Что сделает `Unmarshal` в Go?

**A)** сделает `2`, без ошибки · **B)** вернёт ошибку · **C)** программа упадёт

<details>
<summary>Ответ</summary>

**B: вернёт ошибку.** `Unmarshal` в рантайме знает, что тип поля — `int`, и не принимает строку. Если вы выбрали
«сделает `2`», вы вспомнили `as Item` в TypeScript или библиотеки, которые молча превращают строку в число. Если
вы выбрали «упадёт», вы думали, что Go бросает ошибку как исключение: здесь ошибка возвращается как обычное
значение.

</details>

```console
$ go run json/main.go
0 json: cannot unmarshal string into Go struct field Item.price of type int
```

*json: cannot unmarshal string into Go struct field Item.price of type int* — «строку из JSON нельзя записать в
поле `Item.price` типа `int`». Вместо имени поля стоит ключ JSON (`price`). По документации, `Unmarshal`
пропускает неподходящее поле, заполняет остальное как может и возвращает первую такую ошибку как
`UnmarshalTypeError`.

| | TypeScript (`JSON.parse` + `: Item`) | Go (`json.Unmarshal` → `Item`) |
|---|---|---|
| `{"price": "2"}` | молча: `item.price` = `"2"`, потом `22` | `err` — ошибка, `item.Price` = `0` |
| кто проверяет | никто (если не добавить библиотеку вроде zod) | `encoding/json`, в рантайме |

В TypeScript после сборки этой информации нет, поэтому нужна библиотека валидации вроде zod. В Go информация о
типах остаётся в бинарнике, и `encoding/json` её читает (как — в разделе «Глубже»).

Осторожно: `Unmarshal` проверяет только **тип**, а не валидирует данные. В README курса измерено на go1.26.8:
`{"PRICE": 5}` → `5` (ключ совпадает без учёта регистра), `{"price": null}` → `0` без ошибки,
`{"price": 2.0}` → ошибка, а незнакомые ключи молча отбрасываются.

Откуда взялся `0` в выводе? Об этом следующий раздел.

## Zero value вместо `undefined`

Переменная без значения в JavaScript — это `undefined` (после `+ 1` получается `NaN`), а в Python — `NameError`:

```console
$ node -e 'let total; console.log(total + 1)'
NaN
```

```console
$ python3 -c 'print(total + 1)'
Traceback (most recent call last):
  File "<string>", line 1, in <module>
    print(total + 1)
          ^^^^^
NameError: name 'total' is not defined
```

(Этих двух команд нет в папке курса в виде файлов: код записан прямо в команде.)

В Go нет `undefined`. `var total int` — как `let total: number` в TypeScript, только сначала имя, потом тип.
Если значение не задано, переменная получает нулевое значение своего типа. Это называется **нулевое значение
(zero value)**; дальше, как в документации Go, будем говорить «zero value». `nol/main.go` («ноль»):

```go filename="nol/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var total int
	var name string
	var paid bool
	fmt.Printf("%v %q %v\n", total, name, paid)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `var total int` | `int` → `0` |
| 7 | `var name string` | `string` → `""` (пустая строка) |
| 8 | `var paid bool` | `bool` → `false` |
| 9 | `fmt.Printf("%v %q %v\n", total, name, paid)` | `%v` — значение в обычном виде; `%q` — строка в кавычках, чтобы была видна и пустая строка |

```console
$ go run nol/main.go
0 "" false
```

| После строки | `total` (`int`) | `name` (`string`) | `paid` (`bool`) |
|---|---|---|---|
| 6 | `0` | | |
| 7 | `0` | `""` | |
| 8 | `0` | `""` | `false` |

С полями структур так же: если написать `var item Item`, то `item.Price` будет `0`. `0` из `json/main.go` — отсюда:
`Unmarshal` ничего не записал в `Price`, и оно осталось в zero value.

А у указателя, map и слайса из следующих уроков zero value — **`nil`**, то есть «ничего» (близко к `null` в JS).
Запись в `nil`-map роняет программу (**panic**). Map — в [GO-1.09](/lab/youtube/go/go-1-09/ru), короткий пример — в разделе
«Частые ошибки».

### Если поля в JSON нет совсем

Схема zod `z.object({price: z.number()})` отклоняет `{}` с сообщением `Required` («обязательно»; измерено на zod
3.25.76). `yoq/main.go` («нет») — такой же, как `json/main.go`, только в строке 13 `body` — пустой JSON-объект
`{}`. Что сделает Go?

**A)** `0`, без ошибки · **B)** вернёт ошибку · **C)** программа упадёт

<details>
<summary>Ответ</summary>

**A: `0`, без ошибки.** `Unmarshal` записывает только пришедшие ключи. `price` не пришёл, поэтому `Price` остался
в zero value, которое дал `var item Item`. Zero value у `err` тоже `nil`, то есть «ошибки нет». Если вы выбрали
«вернёт ошибку», вы перенесли привычку zod. Если вы выбрали «упадёт», вы думали, что отсутствующее поле приводит к
ошибке, как обращение к `undefined`: в Go `undefined` нет.

</details>

```go filename="yoq/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
)

type Item struct {
	Price int `json:"price"`
}

func main() {
	body := `{}`
	var item Item
	err := json.Unmarshal([]byte(body), &item)
	fmt.Println(item.Price, err)
}
```

```console
$ go run yoq/main.go
0 <nil>
```

`Println` выводит `nil`-ошибку как `<nil>`. Значит, бесплатный товар (`"price": 0`) и забытое поле выглядят
одинаково. В платёжном API это серьёзный баг. Пока проверяйте важное поле отдельно, полное решение — после урока
про указатели. Коротко: неверный тип даёт ошибку, а отсутствующее поле молча становится zero value.

| JSON | `item.Price` | `err` |
|---|---|---|
| `{"price": "2"}` | `0` | `json: cannot unmarshal string …` |
| `{}` | `0` | `<nil>` |

## `:=` и `=`

`:=` объявляет новую переменную, как `let` в TypeScript (**short variable declaration**, краткое объявление).
Обычное `=` даёт существующей переменной новое значение (**присваивание**, assignment). Есть одна тонкость: если
слева несколько имён, хотя бы одно должно быть новым, остальные только получают значение. Это важно для `err` в
следующем уроке. `:=` работает только внутри функции, на уровне пакета пишут `var`.

В `deklar/main.go` («объявление») две ошибки компиляции. Найдите их до запуска:

```go filename="deklar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	status := "new" // let status = "new"
	status = "paid" // status = "paid"
	status := "sent"
	count := 0
	fmt.Println(status)
}
```

<details>
<summary>Ответ</summary>

Строка 8: `status` уже есть, слева от `:=` нет нового имени. Строка 9: `count` объявлена, но нигде не используется.
`=` в строке 7 правильный: новое значение для существующей переменной.

</details>

```console
$ go run deklar/main.go
# command-line-arguments
deklar/main.go:8:9: no new variables on left side of :=
deklar/main.go:9:2: declared and not used: count
```

`deklar/main.go:8:9` — столбец, где стоит `:=`. *no new variables on left side of :=* — «слева от `:=` нет новых
переменных». `deklar/main.go:9:2` — *declared and not used: count* — «объявлена, но не используется: `count`».
Вторая ошибка — особенность Go. В TypeScript неиспользуемая переменная — предупреждение линтера или
`noUnusedLocals` (по умолчанию выключен), а в Go — ошибка компиляции. По Go FAQ, неиспользуемая переменная часто
признак бага.

| Строка | Код | Что говорит Go |
|---|---|---|
| 6 | `status := "new"` | новая `status` ✅ |
| 7 | `status = "paid"` | новое значение существующей ✅ |
| 8 | `status := "sent"` | слева нет нового имени ❌ |
| 9 | `count := 0` | объявлена, не используется ❌ |

## Затенение: `:=` внутри `if`

Теперь классическая ловушка с `:=`. `soya/main.go` («тень», shadow): `total` 150, `discount` («скидка») 0. Внутри
`if` даём `discount` значение 10, но через `:=`:

```go filename="soya/main.go" showLineNumbers
package main

import "fmt"

func main() {
	total := 150
	discount := 0
	if total > 100 {
		discount := 10
		fmt.Println("chegirma:", discount)
	}
	fmt.Println(total - discount)
}
```

Условие `if` в строке 8: если `total` больше 100, выполняется содержимое `{ }`. Что выведет последний `Println`?

**A)** `140` · **B)** `150` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `150`.** `:=` внутри `if` создал новую `discount`, и она затенила внешнюю. Это называется **затенение**
(shadowing). Внутренняя `discount` исчезает на `}`, внешняя по-прежнему `0`. Если вы выбрали «`140`», вы прочитали
`:=` как обычное присваивание. Если вы выбрали «ошибка компиляции», вы вспомнили *no new variables* из `deklar`. Но
во внутреннем блоке можно объявить новую переменную с тем же именем (спецификация Go: Declarations and scope), и
она используется в строке 10.

</details>

```console
$ go run soya/main.go
chegirma: 10
150
```

(`chegirma` — «скидка».)

| После строки | `total` | `discount` (внешняя) | `discount` (внутри `if`) | На экране |
|---|---|---|---|---|
| 7 | 150 | 0 | — | |
| 9 | 150 | 0 | 10 | |
| 10 | 150 | 0 | 10 | `chegirma: 10` |
| 11 | 150 | 0 | — (блок закончился) | |
| 12 | 150 | 0 | — | `150` |

В TypeScript новую переменную видно по слову `let`, а в Go разница — в одном двоеточии. **Исправление:** внутри
пишите обычное `=`. `soya-tuzat/main.go` («исправление»):

```go filename="soya-tuzat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	total := 150
	discount := 0
	if total > 100 {
		discount = 10
		fmt.Println("chegirma:", discount)
	}
	fmt.Println(total - discount)
}
```

```console
$ go run soya-tuzat/main.go
chegirma: 10
140
```

В строке 9 вместо `:=` стоит `=`: теперь `discount` одна. `go vet` по умолчанию затенение не ловит, поэтому
проверяйте его на код-ревью.

## `for` и `range`: одна переменная — это индекс

В Go нет `while`: если после `for` написать только условие (`for n < 10 { … }`), это и будет `while`. Для обхода
списка есть `range`. На каждом шаге он даёт два значения: **индекс** и **элемент**. `[]int{2, 3, 5}` — **слайс**,
список `int` (подробно в [GO-X.04](/lab/youtube/go/go-x-04/ru)). `range/main.go` хочет сложить цены:

```go filename="range/main.go" showLineNumbers
package main

import "fmt"

func main() {
	prices := []int{2, 3, 5}
	total := 0
	for p := range prices {
		total += p
	}
	fmt.Println(total)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `prices := []int{2, 3, 5}` | `prices` («цены») — три `int` |
| 8 | `for p := range prices {` | цикл по `prices`; переменная одна: `p` |
| 9 | `total += p` | `total = total + p` |

Здесь переменная одна — `p`. Что выведет `Println`?

**A)** `10` · **B)** `3` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `3`.** Если написать одну переменную, это индекс: 0, 1, 2. 0 + 1 + 2 = 3. Если вы выбрали «`10`», вы
перенесли `for (const p of prices)` из TypeScript: он даёт значения. Если вы выбрали «ошибка компиляции», вы
думали, что Go требует писать оба значения: `range` с одной переменной — правильный код на Go.

</details>

```console
$ go run range/main.go
3
```

| Шаг | `p` (индекс) | `prices[p]` (элемент) | `total` после шага |
|---|---|---|---|
| 1 | 0 | 2 | 0 |
| 2 | 1 | 3 | 1 |
| 3 | 2 | 5 | 3 |

**Исправление:** вместо индекса — подчёркивание `_`, то есть **blank identifier** (пустой идентификатор): он
отбрасывает значение. Он нужен, потому что неиспользуемый индекс был бы ошибкой компиляции *declared and not used*.
`range-tuzat/main.go`:

```go filename="range-tuzat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	prices := []int{2, 3, 5}
	total := 0
	for _, p := range prices { // TS: for (const p of prices)
		total += p
	}
	fmt.Println(total) // 10
}
```

```console
$ go run range-tuzat/main.go
10
```

| Что нужно | TypeScript | Go |
|---|---|---|
| элемент | `for (const p of prices)` | `for _, p := range prices` |
| индекс | — | `for i := range prices` |
| оба | — | `for i, p := range prices` |

`for…in` в JavaScript тоже даёт ключи, но строками: `"0"`, `"1"`, `"2"`. Если прибавить их к `0`, получится
`"0012"` (измерено в README курса).

## `string(65)`: ключ Redis превратился в `user:A`

Последняя — ошибка, ради которой команда Go добавила отдельную проверку. Собираем ключ Redis: `user:` и id.
Напоминание: номер Unicode буквы `A` — 65. `id/main.go`:

```go filename="id/main.go" showLineNumbers
package main

import "fmt"

func main() {
	id := 65
	key := "user:" + string(id)
	fmt.Println(key)
}
```

В строке 7 `string(id)` — преобразование `T(x)`, как `float64(a)` в `aylantir/`. Чем станет `key` («ключ»)?

**A)** `user:65` · **B)** `user:A` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `user:A`.** `string(число)` в Go работает не как `String(65)` в JavaScript, а как `String.fromCharCode(65)`:
даёт символ с номером Unicode 65. В спецификации Go написано, что эта возможность осталась «по историческим
причинам». Если вы выбрали «`user:65`», вы перенесли правило `String(65)` из JS или `str(65)` из Python. Если вы
выбрали «ошибка компиляции», вы думали, что Go вообще не превращает число в строку: превращает, только в другом
смысле.

</details>

```console
$ go run id/main.go
user:A
```

```console
$ node -p 'String(65) + " " + String.fromCharCode(65)'
65 A
```

(Второй команды нет в папке курса в виде файла.) Компилятор молчит. Но **`go vet`**, статический анализатор,
который идёт вместе с Go, это ловит:

```console
$ go vet id/main.go
id/main.go:7:19: conversion from int to string yields a string of one rune, not a string of digits
```

`id/main.go:7:19` — строка 7, столбец 19: `string`. *conversion from int to string yields a string of one rune, not
a string of digits* — «преобразование `int` в `string` даёт строку из одной руны, а не строку цифр». **Руна** —
один символ Unicode (подробно в [GO-1.04](/lab/youtube/go/go-1-04/ru)). Эту проверку добавили в Go 1.15. Причина написана в
release notes: опыт показал, что во многих таких преобразованиях ошибочно считают, что `string(x)` даёт число в
виде текста. `go test` при запуске тестов тоже сам выполняет эту проверку (`stringintconv`).

Кроме того, любой id больше 1 114 111 становится `"�"`. Значит, со `string(id)` все такие id попадают в один ключ
Redis (измерено в README курса).

**Исправление:** **`strconv.Itoa`** из пакета `strconv`: превращает число в строку десятичных цифр.
`id-tuzat/main.go`:

```go filename="id-tuzat/main.go" showLineNumbers
package main

import (
	"fmt"
	"strconv"
)

func main() {
	id := 65
	key := "user:" + strconv.Itoa(id)
	fmt.Println(key)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–6 | `import ( … )` | второй пакет: `strconv` (строка ↔ число) |
| 10 | `strconv.Itoa(id)` | `65` → `"65"` (`go doc strconv.Itoa`: то же, что `FormatInt(int64(i), 10)`) |

```console
$ go run id-tuzat/main.go
user:65
```

Обратная функция — `strconv.Atoi` (строка → число). Она возвращает число и ошибку, её шаблон есть в файле 🟡
домашнего задания.

## Глубже (необязательно): как информация о типе живёт в рантайме

`fmt.Println` принимает любой тип: его параметр — `any`. Внутри значения `any` две вещи: само значение и
информация о его типе. В статье *The Laws of Reflection* из блога Go сказано: переменная интерфейсного типа хранит
пару — значение и дескриптор его типа. `%T` читает эту информацию о типе. А `encoding/json` с помощью пакета
`reflect` видит поля структуры и их типы в рантайме.

```text
a := 2;  fmt.Printf("%T", a)

   значение any
   ┌─────────────┬──────────────┐
   │ тип: int    │ значение: 2  │
   └─────────────┴──────────────┘
          ▲
          └── %T читает это → "int"

json.Unmarshal([]byte(body), &item)
   reflect → Item.Price: int, тег "price"
   в JSON "2" (string) ≠ int → UnmarshalTypeError
```

В TypeScript части `Item` этой пары после сборки нет. Но основная проверка и в Go всё равно происходит при сборке:
информация о типе в рантайме используется только через интерфейсы (`any`) и рефлексию.

Ещё один момент: `2 + 1.5` без переменных работает. `chuqur/main.go` («глубоко»):

```go filename="chuqur/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println(2 + 1.5) // konstantalar: tur hali tanlanmagan
}
```

```console
$ go run chuqur/main.go
3.5
```

Это константы: их тип ещё не выбран, поэтому Go может их сложить. А в `aralash/main.go` `a` и `b` — переменные, их
типы уже зафиксированы как `int` и `float64`. Константам посвящён отдельный урок:
[GO-1.03 · Константы и iota](/lab/youtube/go/go-1-03/ru).

## Частые ошибки

**1. Думать, что Go сам преобразует типы, как JavaScript.** Самая классическая ошибка этой темы. `price + count`
(`string` + `int`) и `a + b` (`int` + `float64`) не собираются: *mismatched types string and int*, *mismatched
types int and float64*. Полные примеры — в разделах «Статический тип» и «`int` и `float64`». **Исправление:**
явное преобразование (`float64(a) + b`); для числа → текста — `strconv.Itoa`.

**2. Ждать ошибку на отсутствующее поле JSON.** `{}` → `0 <nil>`: ошибки нет, поле молча в zero value. От
бесплатного товара не отличить. Этого примера нет в папке курса, его запускали отдельно для урока:

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Item struct {
	Price int `json:"price"`
}

func main() {
	for _, body := range []string{`{"price": 0}`, `{}`, `{"price": null}`} {
		var item Item
		err := json.Unmarshal([]byte(body), &item)
		fmt.Println(body, item.Price, err)
	}
}
```

```console
$ go run zero/main.go
{"price": 0} 0 <nil>
{} 0 <nil>
{"price": null} 0 <nil>
```

Три разных JSON, один результат. **Исправление:** проверяйте важное поле отдельно; полное решение (поле-указатель)
— после урока про указатели.

**3. `:=` внутри `if`.** Внешняя переменная не меняется, вместо `140` получается `150` (затенение). Пример — в
разделе «Затенение». **Исправление:** присваивайте существующей переменной через `=`.

**4. `range` с одной переменной.** В `for p := range prices` `p` — индекс, а не элемент: вместо `10` получается
`3`. **Исправление:** `for _, p := range prices`.

**5. Число → текст через `string(id)`.** `user:A`, компилятор молчит. **Исправление:** `strconv.Itoa(id)`; `go vet`
(и `go test`) это ловят.

**6. Повторное объявление через `:=` и неиспользуемая переменная.** *no new variables on left side of :=* и
*declared and not used* — обе ошибки компиляции (`deklar/main.go`). **Исправление:** `=` для существующей
переменной; лишнюю переменную удалите или замените на `_`.

**7. Запись в `nil`-map.** В видео это только упоминается, в папке курса этого нет. Этот пример тоже запускали
отдельно для урока:

```go
package main

import "fmt"

func main() {
	var hits map[string]int // zero value: nil
	fmt.Println(hits["/users"], len(hits))
	hits["/users"]++
}
```

```console
$ go run nilmap/main.go
0 0
panic: assignment to entry in nil map

goroutine 1 [running]:
main.main()
	…/nilmap/main.go:8 +0xa8
exit status 2
```

`hits` («обращения») — `map[string]int` без значения, значит `nil`. Строка 7 сработала: чтение из `nil`-map даёт
`0`, `len` тоже `0`. А запись в строке 8 — не ошибка компиляции, а **panic** во время работы: *assignment to entry
in nil map* — «присваивание элементу в `nil`-map». `main.go:8` — строка, где программа упала. `exit status 2` —
программа завершилась с кодом 2. **Исправление:** создайте map: `hits := map[string]int{}` (подробно в
[GO-1.09](/lab/youtube/go/go-1-09/ru)).

<summary>Ответ</summary>

🟢 Ошибок было три: `total := 0` — `int`, к нему нельзя прибавить `float64` (`total := 0.0`); `p*qty` — `float64`
× `int` (`float64(qty)`); `i` не используется (`_`). Результат: 12.5 × 2 + 7.5 × 2 = 40.

```go filename="uyga/javob/oson/main.go" showLineNumbers
// Javob 🟢. Uchta xato edi:
//  1. total := 0 → int; float64 qo'shib bo'lmaydi → total := 0.0 (yoki var total float64)
//  2. p*qty: float64 * int → float64(qty)
//  3. i ishlatilmagan (declared and not used) → _
//
// Natija: jami: 40
package main

import "fmt"

func main() {
	prices := []float64{12.5, 7.5}
	qty := 2
	total := 0.0
	for _, p := range prices {
		total = total + p*float64(qty)
	}
	fmt.Println("jami:", total)
}
```

```console
$ go run uyga/javob/oson/main.go
jami: 40
```

(`jami` — «итого».) 🟡 `strconv.Atoi` возвращает число и ошибку. При ошибке `http.Error` отвечает статусом 400, а `return` выходит из
обработчика. Благодаря `map[string]int` в JSON `id` и `next` выходят числами (`42`, а не `"42"`).

```go filename="uyga/javob/orta/main.go" showLineNumbers
// Javob 🟡. map[string]int: JSON'da id va next son bo'lib chiqadi ("42" emas, 42).
package main

import (
	"encoding/json"
	"log"
	"net/http"
	"strconv"
)

func main() {
	http.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
		id, err := strconv.Atoi(r.PathValue("id"))
		if err != nil {
			http.Error(w, "id son emas", http.StatusBadRequest)
			return
		}
		w.Header().Set("Content-Type", "application/json")
		json.NewEncoder(w).Encode(map[string]int{"id": id, "next": id + 1})
	})
	log.Println("listening on :3000")
	log.Fatal(http.ListenAndServe(":3000", nil))
}
```

При подготовке урока запускали с `CGO_ENABLED=0`: `/users/42` → `200 OK` и `{"id":42,"next":43}`, `/users/abc` →
`400 Bad Request` и `id son emas` («id — не число»).
