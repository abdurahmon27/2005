## Nimani oʻrganasiz

TypeScript'da `price` maydonini `number` deb yozdingiz. Backend esa narxni JSON'da string qilib yubordi:
`{"price": "2"}`. `tsc --strict` jim, JavaScript esa `"2" + 2` ni `22` qiladi. Go'da xuddi shu qoʻshish build
boʻlmaydi. Nega shunday, va bu backend uchun nimani oʻzgartiradi?

**Bitta gʻoya:** Go turni build paytida qatʼiy tekshiradi va tur maʼlumotini runtime'gacha olib boradi, TypeScript esa
uni oʻchiradi. Shuning uchun `"2" + 2` build boʻlmaydi, JSON'dagi `"2"` `int` maydonga tushmaydi, qiymat berilmagan
oʻzgaruvchi esa `undefined` emas, oʻz turining zero value'si.

Dars oxirida siz:

- `mismatched types` xatosini oʻqib, aralash turlarni ochiq conversion (`float64(a)`) bilan tuzata olasiz;
- `json.Unmarshal` notoʻgʻri turdagi maydonga xato qaytarishini, yoʻq maydonni esa jim `0` qilishini bilasiz;
- `:=` va `=` ni farqlab, `if` ichidagi shadowing'ni kod review'da topa olasiz;
- `for _, p := range` ni toʻgʻri yozasiz va `string(id)` oʻrniga `strconv.Itoa(id)` ishlatasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| statik tur | har bir oʻzgaruvchining turi build paytida belgilanadi va oʻzgarmaydi; aralash turlar faqat ochiq `T(x)` bilan | static type, conversion |
| zero value | qiymat berilmagan oʻzgaruvchining boshlangʻich qiymati: `0`, `""`, `false`, `nil` | zero value |
| `:=` va `=` | `:=` yangi oʻzgaruvchi eʼlon qiladi, `=` mavjudiga qiymat beradi; ichki blokdagi `:=` tashqisini yashiradi | short variable declaration, assignment, shadowing |

Ikkita yordamchi soʻz ham bor: **`strconv.Itoa`** (sonni oʻnlik raqamlar stringiga aylantiradi) va **`go vet`** (Go
bilan keladigan statik tekshiruvchi). Oxirida `for`/`range` ning yozilishi ham bor.

## `"2" + 2`: TypeScript turlari build'dan keyin oʻchadi

Avval dalil. Hook'dagi TypeScript fayl:

```ts filename="js/narx.ts"
type Item = { price: number };

const item: Item = JSON.parse('{"price": "2"}');
console.log(item.price + 2);
```

`JSON.parse` `any` qaytaradi (TypeScript'ning `lib.es5.d.ts` faylida shunday yozilgan), `any` esa istalgan turga
beriladi. Shuning uchun `tsc` `--strict` rejimida ham jim:

```console
$ npx -p typescript@5.9.3 tsc --strict js/narx.ts && node js/narx.js
22
```

`tsc` hech narsa chiqarmadi, yaʼni xato yoʻq, va `js/narx.js` ni yozdi. `node` uni ishga tushirib, `22` chiqardi.
`tsc` yasagan JavaScript faylga qarang:

```console
$ cat js/narx.js
"use strict";
var item = JSON.parse('{"price": "2"}');
console.log(item.price + 2);
```

Faylda `Item` ham, `number` ham yoʻq, runtime ularni koʻrmaydi. TypeScript qoʻllanmasi buni ochiq yozadi: tur
izohlari dasturning runtime'dagi xatti-harakatini hech qachon oʻzgartirmaydi, ular butunlay oʻchiriladi (type
erasure). Runtime faqat `"2"` stringini koʻradi. JavaScript'ning `+` operatori esa bir tomoni string boʻlsa,
ikkinchisini ham stringga aylantirib, ularni ulaydi (MDN). Node 24 `.ts` faylni toʻgʻridan-toʻgʻri ham ishga
tushiradi (`node js/narx.ts` ham `22`): u turlarni shunchaki oʻchiradi, tekshirmaydi.

Python'da shu kod:

```python filename="js/narx.py"
import json

item = json.loads('{"price": "2"}')
print(item["price"] + 2)
```

```console
$ python3 js/narx.py
Traceback (most recent call last):
  File "…/js/narx.py", line 4, in <module>
    print(item["price"] + 2)
          ~~~~~~~~~~~~~~^~~
TypeError: can only concatenate str (not "int") to str
```

(Chiqishdagi toʻliq yoʻl `…` bilan qisqartirildi: u sizning kompyuteringizdagi papkaga bogʻliq.) *can only
concatenate str (not "int") to str* — «str'ga faqat str'ni ulash mumkin, int'ni emas». Python `TypeError` beradi,
lekin faqat shu qator ishlaganda, yaʼni balki production'da.

## Statik tur: Go'da `"2" + 2` build boʻlmaydi

Go'dagi xuddi shu qoʻshish, `hook/main.go`:

```go filename="hook/main.go" showLineNumbers
package main

import "fmt"

func main() {
	price := "2"
	count := 2
	fmt.Println(price + count)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1 | `package main` | bajariladigan dastur paketi (GO-X.01) |
| 3 | `import "fmt"` | `fmt` — ekranga chiqarish paketi |
| 5 | `func main() {` | dastur shu funksiyadan boshlanadi |
| 6 | `price := "2"` | `price` («narx») — yangi oʻzgaruvchi; `:=` turni oʻng tomondan oladi: `string` |
| 7 | `count := 2` | `count` («soni») — turi `int` |
| 8 | `fmt.Println(price + count)` | `string` + `int`: Go buni qabul qilmaydi |

```console
$ go run hook/main.go
# command-line-arguments
hook/main.go:8:14: invalid operation: price + count (mismatched types string and int)
```

`hook/main.go:8:14` — 8-qator, 14-ustun (tab bitta ustun sanaladi), yaʼni `price` boshlangan joy. *invalid
operation: price + count (mismatched types string and int)* — «notoʻgʻri amal: turlar mos emas, `string` va `int`».
Birinchi qatordagi `# command-line-arguments` — xato qaysi paketda: buyruqda `.go` fayl nomi berilsa, Go shu
fayllardan nomsiz paket yasaydi va uni shunday ataydi (`go help packages`).

Go'da har bir oʻzgaruvchining turi build paytida belgilanadi va oʻzgarmaydi. Bu **statik tur** (static type).
`:=` turni oʻng tomondagi qiymatdan oladi, xuddi TypeScript'dagi `let` kabi. Kompilyator `hook/main.go` ni shunday
koʻradi:

| Oʻzgaruvchi | Qiymat | Turi | Qayerdan |
|---|---|---|---|
| `price` | `"2"` | `string` | 6-qator, `:=` oʻng tomondan oldi |
| `count` | `2` | `int` | 7-qator, `:=` oʻng tomondan oldi |
| `price + count` | — | ⛔ | `string` va `int`: build xatosi, binary yoʻq |

Go spec boʻyicha binar operatorning ikki tomoni bir xil turda boʻlishi shart (siljitish va untyped konstantalar
bundan mustasno). Go turli turdagi oʻzgaruvchilarni oʻzi aylantirmaydi. Shuning uchun xato build paytida chiqdi va
binary yaratilmadi.

| | JavaScript / TypeScript | Python | Go |
|---|---|---|---|
| `"2" + 2` | `"22"` | `TypeError`, faqat qator ishlaganda | build xatosi |
| tur qachon tekshiriladi | `tsc` paytida, keyin oʻchiriladi | runtime'da | build paytida; tur maʼlumoti runtime'da ham bor |

PHP'da esa, [PHP qoʻllanmasi](https://www.php.net/manual/en/language.operators.arithmetic.php) boʻyicha, `"2" + 2`
→ `4`: raqamli string songa aylanadi, ulash uchun alohida `.` operatori bor (PHP bu dars uchun ishga
tushirilmadi).

## `int` va `float64`: ochiq conversion

Endi ikkala tomon ham son. `a` — 2, `b` — 1.5:

```go
a := 2
b := 1.5
fmt.Println(a + b)
```

Nima chiqadi? **A)** `3.5` · **B)** `3` · **C)** build xatosi

<details>
<summary>Javob</summary>

**C: build xatosi.** JavaScript'dagi `number` aslida `float64` (IEEE 754 double), butun son uchun alohida tur yoʻq.
Go'da esa `:=` `2` uchun `int`, `1.5` uchun `float64` tanlaydi, va bular ikki xil tur. «`3.5`» ni tanlagan
boʻlsangiz, JS/Python qoidasini koʻchirgansiz: `node -p '2 + 1.5'` ham, Python ham `3.5` beradi. «`3`» ni tanlagan
boʻlsangiz, Go kasrni tashlab `int` qiladi deb oʻylagansiz: u umuman qoʻshmaydi.

</details>

```go filename="aralash/main.go" showLineNumbers
package main

import "fmt"

func main() {
	a := 2
	b := 1.5
	fmt.Println(a + b)
}
```

```console
$ go run aralash/main.go
# command-line-arguments
aralash/main.go:8:14: invalid operation: a + b (mismatched types int and float64)
```

8-qator, 14-ustun: `a`. *mismatched types int and float64* — «turlar mos emas: `int` va `float64`».

**Tuzatish:** turni ochiq aylantiring: `float64(a)`. `T(x)` shakli — **conversion** (aylantirish): `x` ning
qiymatini `T` turida beradi. `aylantir/main.go`:

```go filename="aylantir/main.go" showLineNumbers
package main

import "fmt"

func main() {
	a := 2
	b := 1.5
	fmt.Printf("%T %T\n", a, b) // int float64
	fmt.Println(float64(a) + b) // 3.5
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 8 | `fmt.Printf("%T %T\n", a, b)` | `Printf` — formatli chiqarish; `%T` qiymatning turini chiqaradi; `\n` — yangi qator |
| 9 | `fmt.Println(float64(a) + b)` | `float64(a)` — `2` endi `float64`; ikkala tomon bir xil turda |

```console
$ go run aylantir/main.go
int float64
3.5
```

`%T` JavaScript'dagi `typeof` ga oʻxshaydi, lekin aniqroq: `typeof 2` va `typeof 1.5` ikkalasi ham `number`, Go esa
`int` va `float64` deydi. Nega Go oʻzi aylantirmaydi? Go FAQ'da sababi yozilgan: C'dagi sonli turlar orasidagi
avtomatik aylantirishning qulayligi u keltiradigan chalkashlikka arzimaydi. Qisqasi: aralash turlar faqat ochiq
conversion bilan qoʻshiladi.

## Runtime'da: JSON'dagi `"2"` va `int` maydon

Endi hook'dagi JSON, Go'da. `json/main.go`:

```go filename="json/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
)

type Item struct {
	Price int `json:"price"`
}

func main() {
	body := `{"price": "2"}`
	var item Item
	err := json.Unmarshal([]byte(body), &item)
	fmt.Println(item.Price, err)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 3–6 | `import ( … )` | qavs ichida ikki paket: `encoding/json` (JSON) va `fmt` |
| 8–10 | `type Item struct { … }` | `Item` — TypeScript'dagi `type Item = { price: number }` kabi tur. Go'da bunday tur **struct** deyiladi (batafsil [GO-1.10](/lab/youtube/go/go-1-10) da) |
| 9 | `Price int` + backtick'dagi matn | `Price` maydoni, turi `int`. Backtick ichidagi **teg** (tag) JSON'dagi `price` kaliti shu maydonga tushishini aytadi. Katta harf — maydon export qilingan (GO-X.01): `encoding/json` faqat shunday maydonlarni toʻldiradi |
| 13 | `body := …` | backtick ichidagi string: ichidagi `"` ni ekranlash shart emas |
| 14 | `var item Item` | `Item` turidagi oʻzgaruvchi, qiymat berilmagan (bu haqda keyingi boʻlimda) |
| 15 | `err := json.Unmarshal([]byte(body), &item)` | `Unmarshal` JSON baytlarini `item` ichiga yozadi. `[]byte(body)` — stringni baytlarga conversion. `&item` — `item` ning manzili, shunda `Unmarshal` uni oʻzgartira oladi (pointer'lar [GO-X.04](/lab/youtube/go/go-x-04) da). `err` — xato qiymati ([GO-X.03](/lab/youtube/go/go-x-03) mavzusi) |
| 16 | `fmt.Println(item.Price, err)` | maydon va xatoni chiqaradi |

TypeScript'dagi `Item` turi runtime'da jim edi. Go'dagi `Unmarshal` nima qiladi?

**A)** `2` qiladi, xatosiz · **B)** xato qaytaradi · **C)** dastur yiqiladi

<details>
<summary>Javob</summary>

**B: xato qaytaradi.** `Unmarshal` maydon turi `int` ekanini runtime'da biladi va stringni qabul qilmaydi. «`2`
qiladi» ni tanlagan boʻlsangiz, TypeScript'dagi `as Item` yoki stringni songa jim aylantiradigan kutubxonalarni
eslagansiz. «Yiqiladi» ni tanlagan boʻlsangiz, Go xatoni exception kabi otadi deb oʻylagansiz: bu yerda xato
oddiy qiymat boʻlib qaytadi.

</details>

```console
$ go run json/main.go
0 json: cannot unmarshal string into Go struct field Item.price of type int
```

*json: cannot unmarshal string into Go struct field Item.price of type int* — «JSON'dagi stringni `int` turidagi
`Item.price` maydoniga yozib boʻlmaydi». Maydon nomi oʻrnida JSON kaliti (`price`) turibdi. Hujjatga koʻra,
`Unmarshal` mos kelmagan maydonni tashlab ketadi, qolganini iloji boricha toʻldiradi va birinchi shunday xatoni
`UnmarshalTypeError` sifatida qaytaradi.

| | TypeScript (`JSON.parse` + `: Item`) | Go (`json.Unmarshal` → `Item`) |
|---|---|---|
| `{"price": "2"}` | jim: `item.price` = `"2"`, keyin `22` | `err` — xato, `item.Price` = `0` |
| kim tekshiradi | hech kim (zod kabi kutubxona qoʻshmasangiz) | `encoding/json`, runtime'da |

TypeScript'da bu maʼlumot build'dan keyin yoʻq, shuning uchun zod kabi validatsiya kutubxonasi kerak. Go'da tur
maʼlumoti binary'da qoladi va `encoding/json` uni oʻqiydi (qanday — «Chuqurroq» boʻlimida).

Ehtiyot boʻling: `Unmarshal` faqat **turni** tekshiradi, validatsiya qilmaydi. Kurs README'sida go1.26.8 da
oʻlchangan: `{"PRICE": 5}` → `5` (kalit katta-kichik harfga qaramay mos keladi), `{"price": null}` → `0` xatosiz,
`{"price": 2.0}` → xato, notanish kalitlar esa jim tashlanadi.

Natijadagi `0` qayerdan keldi? Keyingi boʻlim shu haqda.

## Zero value: `undefined` oʻrniga

Qiymat berilmagan oʻzgaruvchi JavaScript'da `undefined` (`+ 1` dan keyin `NaN`), Python'da esa `NameError`:

```console
$ node -e 'let total; console.log(total + 1)'
NaN
```

```console
$ python3 -c 'print(total + 1)'
Traceback (most recent call last):
  File "<string>", line 1, in <module>
    print(total + 1)
          ^^^^^
NameError: name 'total' is not defined
```

(Bu ikki buyruq kurs papkasida fayl sifatida yoʻq: kod buyruqning oʻzida.)

Go'da `undefined` yoʻq. `var total int` — TypeScript'dagi `let total: number` kabi, faqat avval nom, keyin tur.
Qiymat berilmasa, oʻzgaruvchi oʻz turining nol qiymatini oladi. Bu **nol qiymat (zero value)** deyiladi, Go
hujjatlaridagi kabi bundan keyin «zero value» deymiz. `nol/main.go`:

```go filename="nol/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var total int
	var name string
	var paid bool
	fmt.Printf("%v %q %v\n", total, name, paid)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `var total int` | `int` → `0` |
| 7 | `var name string` | `string` → `""` (boʻsh string) |
| 8 | `var paid bool` | `bool` → `false` |
| 9 | `fmt.Printf("%v %q %v\n", total, name, paid)` | `%v` — qiymat oddiy koʻrinishda; `%q` — string qoʻshtirnoq bilan, boʻsh string ham koʻrinsin deb |

```console
$ go run nol/main.go
0 "" false
```

| Qatordan keyin | `total` (`int`) | `name` (`string`) | `paid` (`bool`) |
|---|---|---|---|
| 6 | `0` | | |
| 7 | `0` | `""` | |
| 8 | `0` | `""` | `false` |

Struct maydonlari ham shunday: `var item Item` yozsangiz, `item.Price` `0` boʻladi. `json/main.go` dagi `0` shu
yerdan: `Unmarshal` `Price` ga hech narsa yozmadi, u zero value'da qoldi.

Keyingi darslardagi pointer, map va slice'ning zero value'si esa **`nil`**, yaʼni «hech narsa» (JS'dagi `null` ga
yaqin). `nil` map'ga yozish dasturni yiqitadi (**panic**). Map'lar [GO-1.09](/lab/youtube/go/go-1-09) da, qisqa misol
«Koʻp uchraydigan xatolar» boʻlimida.

### JSON'da maydon umuman boʻlmasa

zod `z.object({price: z.number()})` sxemasi `{}` ni `Required` («majburiy») deb rad etadi (zod 3.25.76 da
oʻlchangan). `yoq/main.go` («yoʻq») — `json/main.go` bilan bir xil, faqat 13-qatorda `body` — boʻsh JSON obyekt
`{}`. Go nima qiladi?

**A)** `0`, xatosiz · **B)** xato qaytaradi · **C)** dastur yiqiladi

<details>
<summary>Javob</summary>

**A: `0`, xatosiz.** `Unmarshal` faqat kelgan kalitlarni yozadi. `price` kelmadi, shuning uchun `Price`
`var item Item` bergan zero value'da qoldi. `err` ning zero value'si ham `nil`, yaʼni «xato yoʻq». «Xato qaytaradi»
ni tanlagan boʻlsangiz, zod odatini koʻchirgansiz. «Yiqiladi» ni tanlagan boʻlsangiz, yoʻq maydon `undefined` kabi
xatoga olib keladi deb oʻylagansiz: Go'da `undefined` yoʻq.

</details>

```go filename="yoq/main.go" showLineNumbers
package main

import (
	"encoding/json"
	"fmt"
)

type Item struct {

func main() {

```

darsidan keyin. Qisqasi: notoʻgʻri tur xato beradi, yoʻq maydon esa jim zero value boʻladi.

| JSON | `item.Price` | `err` |
|---|---|---|
| `{"price": "2"}` | `0` | `json: cannot unmarshal string …` |
| `{}` | `0` | `<nil>` |

## `:=` va `=`

`:=` TypeScript'dagi `let` kabi yangi oʻzgaruvchi eʼlon qiladi (**short variable declaration**). Oddiy `=` mavjud
oʻzgaruvchiga yangi qiymat beradi (**qiymat berish**, assignment). Bir farqi bor: chap tomonda bir nechta nom
boʻlsa, kamida bittasi yangi boʻlishi kerak, qolganlari faqat qiymat oladi. Bu keyingi darsdagi `err` uchun muhim.
`:=` faqat funksiya ichida ishlaydi, paket darajasida `var` yoziladi.

`deklar/main.go` da ikkita build xatosi bor. Ishga tushirishdan oldin toping:

```go filename="deklar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	status := "new" // let status = "new"
	status = "paid" // status = "paid"
	status := "sent"
	count := 0
	fmt.Println(status)
}
```

<details>
<summary>Javob</summary>

8-qator: `status` allaqachon bor, `:=` ning chap tomonida yangi nom yoʻq. 9-qator: `count` eʼlon qilingan, lekin
hech qayerda ishlatilmagan. 7-qatordagi `=` toʻgʻri: mavjud oʻzgaruvchiga yangi qiymat.

</details>

```console
$ go run deklar/main.go
# command-line-arguments
deklar/main.go:8:9: no new variables on left side of :=
deklar/main.go:9:2: declared and not used: count
```

`deklar/main.go:8:9` — `:=` turgan ustun. *no new variables on left side of :=* — «`:=` ning chap tomonida yangi
oʻzgaruvchi yoʻq». `deklar/main.go:9:2` — *declared and not used: count* — «eʼlon qilingan, lekin ishlatilmagan:
`count`». Ikkinchisi Go'ga xos. TypeScript'da ishlatilmagan oʻzgaruvchi linter yoki `noUnusedLocals` (sukut
boʻyicha oʻchiq) ogohlantirishi, Go'da esa build xatosi. Go FAQ'ga koʻra, ishlatilmagan oʻzgaruvchi koʻpincha bug
belgisi.

| Qator | Kod | Go nima deydi |
|---|---|---|
| 6 | `status := "new"` | yangi `status` ✅ |
| 7 | `status = "paid"` | mavjudiga yangi qiymat ✅ |
| 8 | `status := "sent"` | chap tomonda yangi nom yoʻq ❌ |
| 9 | `count := 0` | eʼlon qilingan, ishlatilmagan ❌ |

## Shadowing: `if` ichidagi `:=`

Endi `:=` bilan bogʻliq klassik tuzoq. `soya/main.go` («soya» — shadow): `total` 150, `discount` («chegirma») 0.
`if` ichida `discount` ga 10 beramiz, lekin `:=` bilan:

```go filename="soya/main.go" showLineNumbers
package main

import "fmt"

func main() {
	total := 150
	discount := 0
	if total > 100 {
		discount := 10
		fmt.Println("chegirma:", discount)
	}
	fmt.Println(total - discount)
}
```

8-qatordagi `if` sharti: `total` 100 dan katta boʻlsa, `{ }` ichi ishlaydi. Oxirgi `Println` nima chiqaradi?

**A)** `140` · **B)** `150` · **C)** build xatosi

<details>
<summary>Javob</summary>

**B: `150`.** `if` ichidagi `:=` yangi `discount` yaratdi va u tashqaridagisini yashirdi. Bu **shadowing**
deyiladi. Ichkaridagi `discount` `}` da yoʻqoladi, tashqaridagisi hamon `0`. «`140`» ni tanlagan boʻlsangiz, `:=`
ni oddiy qiymat berish deb oʻqigansiz. «Build xatosi» ni tanlagan boʻlsangiz, `deklar` dagi *no new variables* ni
eslagansiz. Ichki blokda esa bir xil nom bilan yangi oʻzgaruvchi eʼlon qilish mumkin (Go spec: Declarations and
scope), va u 10-qatorda ishlatilgan.

</details>

```console
$ go run soya/main.go
chegirma: 10
150
```

| Qatordan keyin | `total` | `discount` (tashqi) | `discount` (`if` ichida) | Ekranda |
|---|---|---|---|---|
| 7 | 150 | 0 | — | |
| 9 | 150 | 0 | 10 | |
| 10 | 150 | 0 | 10 | `chegirma: 10` |
| 11 | 150 | 0 | — (blok tugadi) | |
| 12 | 150 | 0 | — | `150` |

TypeScript'da yangi oʻzgaruvchini `let` soʻzidan koʻrasiz, Go'da esa farq bitta ikki nuqtada. **Tuzatish:**
ichkarida oddiy `=` yozing. `soya-tuzat/main.go`:

```go filename="soya-tuzat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	total := 150
	discount := 0
	if total > 100 {
		discount = 10
		fmt.Println("chegirma:", discount)
	}
	fmt.Println(total - discount)
}
```

```console
$ go run soya-tuzat/main.go
chegirma: 10
140
```

9-qatorda `:=` oʻrniga `=`: endi `discount` bitta. `go vet` shadowing'ni sukut boʻyicha ushlamaydi, shuning uchun
uni kod review'da koʻzdan oʻtkazing.

## `for` va `range`: bitta oʻzgaruvchi — indeks

Go'da `while` yoʻq: `for` dan keyin faqat shart yozsangiz (`for n < 10 { … }`), u `while` boʻladi. Roʻyxat ustidan
yurish uchun `range`. U har qadamda ikki qiymat beradi: **indeks** va **element**. `[]int{2, 3, 5}` — **slice**,
`int`'lar roʻyxati (batafsil [GO-X.04](/lab/youtube/go/go-x-04) da). `range/main.go` narxlarni qoʻshmoqchi:

```go filename="range/main.go" showLineNumbers
package main

import "fmt"

func main() {
	prices := []int{2, 3, 5}
	total := 0
	for p := range prices {
		total += p
	}
	fmt.Println(total)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `prices := []int{2, 3, 5}` | `prices` («narxlar») — uchta `int` |
| 8 | `for p := range prices {` | `prices` ustidan sikl; oʻzgaruvchi bitta: `p` |
| 9 | `total += p` | `total = total + p` |

Bu yerda oʻzgaruvchi bitta, `p`. `Println` nima chiqaradi?

**A)** `10` · **B)** `3` · **C)** build xatosi

<details>
<summary>Javob</summary>

**B: `3`.** Bitta oʻzgaruvchi yozsangiz, u indeks boʻladi: 0, 1, 2. 0 + 1 + 2 = 3. «`10`» ni tanlagan boʻlsangiz,
TypeScript'dagi `for (const p of prices)` ni koʻchirgansiz: u qiymat beradi. «Build xatosi» ni tanlagan
boʻlsangiz, Go ikkala qiymatni ham yozishni talab qiladi deb oʻylagansiz: bitta oʻzgaruvchili `range` — toʻgʻri Go
kodi.

</details>

```console
$ go run range/main.go
3
```

| Qadam | `p` (indeks) | `prices[p]` (element) | `total` qadamdan keyin |
|---|---|---|---|
| 1 | 0 | 2 | 0 |
| 2 | 1 | 3 | 1 |
| 3 | 2 | 5 | 3 |

**Tuzatish:** indeks oʻrniga pastki chiziq `_`, yaʼni **blank identifier**: u qiymatni tashlab yuboradi. U kerak,
chunki ishlatilmagan indeks *declared and not used* build xatosi boʻlardi. `range-tuzat/main.go`:

```go filename="range-tuzat/main.go" showLineNumbers
package main

import "fmt"

func main() {
	prices := []int{2, 3, 5}
	total := 0
	for _, p := range prices { // TS: for (const p of prices)
		total += p
	}
	fmt.Println(total) // 10
}
```

```console
$ go run range-tuzat/main.go
10
```

| Nima kerak | TypeScript | Go |
|---|---|---|
| element | `for (const p of prices)` | `for _, p := range prices` |
| indeks | — | `for i := range prices` |
| ikkalasi | — | `for i, p := range prices` |

JavaScript'dagi `for…in` ham kalit beradi, lekin string: `"0"`, `"1"`, `"2"`. Ularni `0` ga qoʻshsangiz, `"0012"`
chiqadi (kurs README'sida oʻlchangan).

## `string(65)`: Redis kaliti `user:A` boʻlib qoldi

Oxirgisi — Go jamoasi alohida tekshiruv qoʻshgan xato. Redis kaliti yasaymiz: `user:` va id. Eslatma: Unicode'da
`A` harfining raqami 65. `id/main.go`:

```go filename="id/main.go" showLineNumbers
package main

import "fmt"

func main() {
	id := 65
	key := "user:" + string(id)
	fmt.Println(key)
}
```

7-qatorda `string(id)` — conversion `T(x)`, `aylantir/` dagi `float64(a)` kabi. `key` («kalit») nima boʻladi?

**A)** `user:65` · **B)** `user:A` · **C)** build xatosi

<details>
<summary>Javob</summary>

**B: `user:A`.** Go'dagi `string(son)` JavaScript'dagi `String(65)` emas, `String.fromCharCode(65)` kabi ishlaydi:
Unicode raqami 65 boʻlgan belgini beradi. Go spec'da yozilgan: bu imkoniyat «tarixiy sabablar bilan» qolgan.
«`user:65`» ni tanlagan boʻlsangiz, JS `String(65)` yoki Python `str(65)` qoidasini koʻchirgansiz. «Build xatosi»
ni tanlagan boʻlsangiz, Go sonni stringga umuman aylantirmaydi deb oʻylagansiz: aylantiradi, faqat boshqa maʼnoda.

</details>

```console
$ go run id/main.go
user:A
```

```console
$ node -p 'String(65) + " " + String.fromCharCode(65)'
65 A
```

(Ikkinchi buyruq kurs papkasida fayl sifatida yoʻq.) Kompilyator jim. Lekin **`go vet`**, yaʼni Go bilan keladigan
statik tekshiruvchi, buni ushlaydi:

```console
$ go vet id/main.go
id/main.go:7:19: conversion from int to string yields a string of one rune, not a string of digits
```

`id/main.go:7:19` — 7-qator, 19-ustun: `string`. *conversion from int to string yields a string of one rune, not a
string of digits* — «`int` dan `string` ga conversion raqamlar stringini emas, bitta rune'li stringni beradi».
**Rune** — bitta Unicode belgi (batafsil [GO-1.04](/lab/youtube/go/go-1-04) da). Bu tekshiruv Go 1.15 da qoʻshilgan. Release
notes'da sababi yozilgan: tajribaga koʻra, bunday conversion'larning koʻpida `string(x)` sonning matnli koʻrinishini
beradi deb xato oʻylangan. `go test` ham bu tekshiruvni (`stringintconv`) oʻzi ishga tushiradi.

Bundan tashqari, 1 114 111 dan katta har qanday id `"�"` boʻladi. Demak `string(id)` bilan bunday id'larning
hammasi bitta Redis kalitiga tushadi (kurs README'sida oʻlchangan).

**Tuzatish:** `strconv` paketidagi **`strconv.Itoa`**: u sonni oʻnlik raqamlar stringiga aylantiradi.
`id-tuzat/main.go`:

```go filename="id-tuzat/main.go" showLineNumbers
package main

import (
	"fmt"
	"strconv"
)

func main() {
	id := 65
	key := "user:" + strconv.Itoa(id)
	fmt.Println(key)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 3–6 | `import ( … )` | ikkinchi paket: `strconv` (string ↔ son) |
| 10 | `strconv.Itoa(id)` | `65` → `"65"` (`go doc strconv.Itoa`: `FormatInt(int64(i), 10)` bilan bir xil) |

```console
$ go run id-tuzat/main.go
user:65
```

Teskarisi — `strconv.Atoi` (string → son). U son va xato qaytaradi, uning qolipi 🟡 uy vazifasi faylida bor.

## Chuqurroq (ixtiyoriy): tur maʼlumoti runtime'da qanday yashaydi

`fmt.Println` istalgan turni qabul qiladi: uning parametri `any`. `any` qiymati ichida ikki narsa bor: qiymatning
oʻzi va uning tur maʼlumoti. Go blog'idagi *The Laws of Reflection* maqolasi shunday deydi: interface turidagi
oʻzgaruvchi juftlik saqlaydi — qiymat va uning tur tavsifi. `%T` shu tur maʼlumotini oʻqiydi. `encoding/json` esa
`reflect` paketi bilan struct maydonlari va ularning turlarini runtime'da koʻradi.

```text
a := 2;  fmt.Printf("%T", a)

   any qiymati
   ┌─────────────┬─────────────┐
   │ tur: int    │ qiymat: 2   │
   └─────────────┴─────────────┘
          ▲
          └── %T shuni oʻqiydi → "int"

json.Unmarshal([]byte(body), &item)
   reflect → Item.Price: int, teg "price"
   JSON'da "2" (string) ≠ int → UnmarshalTypeError
```

TypeScript'da bu juftlikning `Item` qismi build'dan keyin yoʻq. Lekin tekshiruvlarning asosiysi Go'da ham baribir
build paytida: runtime'dagi tur maʼlumoti faqat interface (`any`) va reflection orqali ishlatiladi.

Yana bir nuqta: `2 + 1.5` oʻzgaruvchisiz yozilsa, ishlaydi. `chuqur/main.go`:

```go filename="chuqur/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println(2 + 1.5) // konstantalar: tur hali tanlanmagan
}
```

```console
$ go run chuqur/main.go
3.5
```

Bular konstantalar: ularning turi hali tanlanmagan, shuning uchun Go ularni qoʻsha oladi. `aralash/main.go` da esa
`a` va `b` oʻzgaruvchilar, ularning turi `int` va `float64` boʻlib qotgan. Konstantalar haqida alohida dars bor:
[GO-1.03 · Konstanta va iota](/lab/youtube/go/go-1-03).

## Koʻp uchraydigan xatolar

**1. Go turlarni JavaScript kabi oʻzi aylantiradi deb oʻylash.** Bu mavzuning eng klassik xatosi. `price + count`
(`string` + `int`) va `a + b` (`int` + `float64`) build boʻlmaydi: *mismatched types string and int*, *mismatched
types int and float64*. Toʻliq misollar «Statik tur» va «`int` va `float64`» boʻlimlarida. **Tuzatish:** ochiq
conversion (`float64(a) + b`); son → matn uchun `strconv.Itoa`.

**2. Yoʻq JSON maydonini xato deb kutish.** `{}` → `0 <nil>`: xato yoʻq, maydon jim zero value. Bepul mahsulot
bilan farqi yoʻq. Bu misol kurs papkasida yoʻq, u dars uchun alohida ishga tushirilgan:

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Item struct {
	Price int `json:"price"`
}

func main() {
	for _, body := range []string{`{"price": 0}`, `{}`, `{"price": null}`} {
		var item Item
		err := json.Unmarshal([]byte(body), &item)
		fmt.Println(body, item.Price, err)
	}
}
```

```console
$ go run zero/main.go
{"price": 0} 0 <nil>
{} 0 <nil>
{"price": null} 0 <nil>
```

Uchta har xil JSON, bitta natija. **Tuzatish:** muhim maydonni alohida tekshiring; toʻliq yechim (pointer maydon)
pointer darsidan keyin.

**3. `if` ichida `:=`.** Tashqaridagi oʻzgaruvchi oʻzgarmaydi, `140` oʻrniga `150` (shadowing). Misol
«Shadowing» boʻlimida. **Tuzatish:** mavjud oʻzgaruvchiga `=` bilan qiymat bering.

**4. Bitta oʻzgaruvchili `range`.** `for p := range prices` da `p` — indeks, element emas: `10` oʻrniga `3`.
**Tuzatish:** `for _, p := range prices`.

**5. `string(id)` bilan son → matn.** `user:A`, kompilyator jim. **Tuzatish:** `strconv.Itoa(id)`; `go vet` (va
`go test`) buni ushlaydi.

**6. `:=` bilan qayta eʼlon qilish va ishlatilmagan oʻzgaruvchi.** *no new variables on left side of :=* va
*declared and not used* — ikkalasi ham build xatosi (`deklar/main.go`). **Tuzatish:** mavjud oʻzgaruvchiga `=`,
keraksiz oʻzgaruvchini oʻchiring yoki `_` yozing.

**7. `nil` map'ga yozish.** Videoda faqat aytiladi, kurs papkasida yoʻq. Bu misol ham dars uchun alohida ishga tushirilgan:

```go
package main

import "fmt"

func main() {
	var hits map[string]int // zero value: nil
	fmt.Println(hits["/users"], len(hits))
	hits["/users"]++
}
```

```console
$ go run nilmap/main.go
0 0
panic: assignment to entry in nil map

goroutine 1 [running]:
main.main()
	…/nilmap/main.go:8 +0xa8
exit status 2
```

`hits` («murojaatlar») — `map[string]int`, qiymat berilmagan, demak `nil`. 7-qator ishladi: `nil` map'dan oʻqish
`0` beradi, `len` ham `0`. 8-qatorda yozish esa build xatosi emas, ishlash paytidagi **panic**: *assignment to entry
in nil map* — «`nil` map'dagi yozuvga qiymat berish». `main.go:8` — yiqilgan qator. `exit status 2` — dastur 2 kodi
bilan tugadi. **Tuzatish:** map'ni yarating: `hits := map[string]int{}` (batafsil [GO-1.09](/lab/youtube/go/go-1-09) da).

<details>
<summary>Javob</summary>

🟢 Uchta xato edi: `total := 0` — `int`, unga `float64` qoʻshib boʻlmaydi (`total := 0.0`); `p*qty` — `float64` ×

```go filename="uyga/javob/oson/main.go" showLineNumbers
// Javob 🟢. Uchta xato edi:
//  1. total := 0 → int; float64 qo'shib bo'lmaydi → total := 0.0 (yoki var total float64)
//  2. p*qty: float64 * int → float64(qty)
//  3. i ishlatilmagan (declared and not used) → _
//
// Natija: jami: 40
package main

import "fmt"

func main() {
	prices := []float64{12.5, 7.5}
	qty := 2
	total := 0.0
	for _, p := range prices {
		total = total + p*float64(qty)
	}
	fmt.Println("jami:", total)
}
```


🟡 `strconv.Atoi` son va xato qaytaradi. Xato boʻlsa, `http.Error` 400 status bilan javob beradi va `return`
handler'dan chiqadi. `map[string]int` tufayli JSON'da `id` va `next` son boʻlib chiqadi (`"42"` emas, `42`).

```go filename="uyga/javob/orta/main.go" showLineNumbers
// Javob 🟡. map[string]int: JSON'da id va next son bo'lib chiqadi ("42" emas, 42).
package main

import (
	"encoding/json"
	"log"
	"net/http"
	"strconv"
)

func main() {
	http.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
		id, err := strconv.Atoi(r.PathValue("id"))
		if err != nil {
			http.Error(w, "id son emas", http.StatusBadRequest)
			return
		}
		w.Header().Set("Content-Type", "application/json")
		json.NewEncoder(w).Encode(map[string]int{"id": id, "next": id + 1})
	})
	log.Println("listening on :3000")
	log.Fatal(http.ListenAndServe(":3000", nil))
}
```

Dars tayyorlanayotganda `CGO_ENABLED=0` bilan ishga tushirildi: `/users/42` → `200 OK` va `{"id":42,"next":43}`,
`/users/abc` → `400 Bad Request` va `id son emas`.
