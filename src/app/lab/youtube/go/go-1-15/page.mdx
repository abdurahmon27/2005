## Nimani oʻrganasiz

Funksiya 2000 ta log faylni birma-bir ochadi va har birini `defer f.Close()` bilan yopadi. Ochiq fayllar
limiti 1024 boʻlganda u 1019 ta fayldan keyin `too many open files` bilan toʻxtaydi. Demak, «yopilgan» fayllar
hali ham ochiq. `defer` aslida qachon ishlaydi? Dars oxirida esa `recover` ham qutqara olmaydigan xatolarni
ishga tushiramiz.

**Bitta gʻoya:** `defer` blokka emas, **funksiyaga** bogʻlangan: chaqiruv funksiya tugaganda (`return` bilan
ham, panic bilan ham) teskari tartibda ishlaydi, argumentlari esa `defer` qatorining oʻzida hisoblanadi.
`recover` faqat shu `defer` ichida va faqat oʻz goroutine'sidagi panic'ni ushlaydi. Fatal error va `os.Exit`
da `defer` umuman ishlamaydi.

Dars oxirida siz:

- `defer` lar qaysi tartibda ishlashini va argumentlari qachon hisoblanishini oldindan ayta olasiz;
- sikl ichidagi `defer` tuzogʻini taniysiz va uni alohida funksiya bilan tuzata olasiz;
- panic'ni `recover` va nomlangan natija orqali oddiy `error` ga aylantira olasiz, va bu qayerda oʻrinli
  ekanini bilasiz;
- `recover` nimani ushlamasligini bilasiz: boshqa goroutine'dagi panic, fatal error (deadlock, stack overflow,
  out of memory), `os.Exit` va `log.Fatal`.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| defer | chaqiruvni oʻrab turgan funksiya tugaguncha kechiktiradi; JS/PHP'dagi `finally` ning funksiya darajasidagi shakli | defer |
| panic | runtime yoki kod chaqiradigan favqulodda toʻxtash: oddiy ish toʻxtaydi, `defer` lar ishlaydi, keyin dastur yiqiladi | panic |
| recover | `defer` qilingan funksiya ichida panic'ni toʻxtatadi va uning qiymatini qaytaradi; `catch` ga eng yaqin narsa | recover |

Yoʻl-yoʻlakay ikkita yordamchi soʻz ham uchraydi: **LIFO** (*Last In, First Out* — oxirgi qoʻyilgan birinchi
chiqadi) va **nomlangan natija** (*named result*: `func f() (n int, err error)` dagi `n` va `err`). Ikkalasini
kerak boʻlgan joyda tushuntiramiz.

## 2000 ta fayl, 1019 tasi ochildi

Kurs papkasidagi `sikl/main.go`. `sana` («sanash») funksiyasi fayllarni ochadi va har biri uchun yopishni
`defer` ga topshiradi:

```go filename="sikl/main.go" showLineNumbers
// Ataylab xato: sikl ichidagi defer fayllarni funksiya tugaguncha yopmaydi.
package main

import (
	"fmt"
	"os"
)

func sana(nomlar []string) (int, error) {
	ochildi := 0
	for _, nom := range nomlar {
		f, err := os.Open(nom)
		if err != nil {
			return ochildi, err
		}
		defer f.Close() // XATO: sikl oxirida emas, sana tugaganda yopiladi
		ochildi++
	}
	return ochildi, nil
}

func main() {
	dir, nomlar := loglar(2000)
	defer os.RemoveAll(dir)

	n, err := sana(nomlar)
	fmt.Println("ochildi:", n, "ta fayl")
	if err != nil {
		fmt.Println("xato:", err)
	}
}

// loglar vaqtinchalik papkada n ta bo'sh fayl yaratadi va o'sha papkaga o'tadi.
func loglar(n int) (string, []string) {
	dir, err := os.MkdirTemp("", "loglar")
	if err != nil {
		panic(err)
	}
	if err := os.Chdir(dir); err != nil {
		panic(err)
	}
	nomlar := make([]string, n)
	for i := range nomlar {
		nomlar[i] = fmt.Sprintf("log-%04d.txt", i+1)
		if err := os.WriteFile(nomlar[i], nil, 0o644); err != nil {
			panic(err)
		}
	}
	return dir, nomlar
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 9 | `func sana(nomlar []string) (int, error)` | fayl nomlari (`nomlar`) slice'ini oladi, nechta fayl ochilganini (`ochildi`) va xatoni qaytaradi |
| 12 | `f, err := os.Open(nom)` | faylni oʻqish uchun ochadi; `f` — `*os.File` |
| 13–15 | `if err != nil { return ochildi, err }` | ochilmasa, shu paytgacha sanalganini va xatoni qaytaradi |
| 16 | `defer f.Close()` | `f.Close()` chaqiruvini **kechiktiradi**; qachongacha — shu darsning savoli |
| 17 | `ochildi++` | hisoblagichni bittaga oshiradi |
| 23 | `dir, nomlar := loglar(2000)` | vaqtinchalik papkada 2000 ta boʻsh fayl yaratadi |
| 24 | `defer os.RemoveAll(dir)` | `main` tugaganda papkani oʻchiradi |
| 26–30 | `n, err := sana(nomlar)` … | natijani va xatoni chiqaradi |
| 34–50 | `func loglar(n int) …` | yordamchi: `os.MkdirTemp` bilan papka yaratadi, `os.Chdir` bilan unga oʻtadi, `log-0001.txt` … `log-2000.txt` nomli boʻsh fayllar yozadi (`%04d` — 4 xonali, oldi nol bilan; `0o644` — fayl ruxsatlari, sakkizlik sanoqda). Xato boʻlsa `panic(err)`: bugun koʻradigan favqulodda toʻxtash; demo uchun yetarli |

Ochiq fayllar soni har bir jarayon (process) uchun cheklangan. `ulimit -n 1024` bu limitni 1024 ga tushiradi.
Linux'da har bir ochiq fayl jarayonda bitta **fayl deskriptori** (*file descriptor*) — kichik raqam — egallaydi.
`bash -c '…'` buyruqni bash ichida ishga tushiradi (zsh'da `ulimit -n` boshqacha ishlaydi):

```console
$ bash -c 'ulimit -n 1024; go run ./sikl'
ochildi: 1019 ta fayl
xato: open log-1020.txt: too many open files
```

*too many open files* — «ochiq fayllar juda koʻp». 1020-fayl ochilmadi: limit 1024, 5 ta deskriptor esa
dastur boshidan band. 3 tasi — stdin, stdout, stderr; 2 tasi — Go runtime'ning tarmoq/fayl kutish mexanizmi
(`eventpoll` va `eventfd`). 1024 − 5 = 1019. Demak, 1019 ta fayl **hali ham ochiq**, garchi har biri uchun
`defer f.Close()` yozilgan boʻlsa ham. Sababini keyingi ikki boʻlimda ochamiz.

## defer: funksiya tugaganda, teskari tartibda

Fayl, baza ulanishi, mutex lock — olingan resursni qaytarish kerak. JS va PHP'da buning uchun
`try … finally`, Python'da `with` bor. Go'da **`defer`** bor: u chaqiruvni oʻrab turgan funksiya tugaguncha
kechiktiradi. Resursni olgan zahoti `defer` bilan uni qaytarishni yozasiz, va qaytarish yoʻldan qolmaydi. Kurs
papkasidagi `tartib/main.go` resurslar olinishini shunchaki ekranga yozadi:

```go filename="tartib/main.go" showLineNumbers
// defer tartibi: oxirgi qo'yilgan defer birinchi ishlaydi (LIFO).
package main

import "fmt"

func main() {
	fmt.Println("baza ochildi")
	defer fmt.Println("baza yopildi")

	fmt.Println("fayl ochildi")
	defer fmt.Println("fayl yopildi")

	fmt.Println("lock olindi")
	defer fmt.Println("lock qaytarildi")

	fmt.Println("ish bajarildi")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7, 10, 13 | `fmt.Println("… ochildi")` | resurs olinganini darhol yozadi |
| 8, 11, 14 | `defer fmt.Println("… yopildi")` | yopish chaqiruvini `main` tugaguncha kechiktiradi |
| 16 | `fmt.Println("ish bajarildi")` | asosiy ish |

Ishga tushirishdan oldin oʻylab koʻring: «yopildi» qatorlari qaysi tartibda chiqadi?

**A)** har biri oʻz «ochildi» qatoridan keyin darhol · **B)** oxirida, ochilish tartibida: baza, fayl, lock ·
**C)** oxirida, teskari tartibda: lock, fayl, baza

<details>
<summary>Javob</summary>

**C.** `defer` chaqiruvni bajarmaydi, uni roʻyxatga qoʻyadi. Roʻyxat `main` tugaganda oxiridan boshlab
bajariladi: oxirgi qoʻyilgan birinchi ishlaydi. «A» ni tanlagan boʻlsangiz, `defer` keyingi qatordan keyin
ishlaydi deb oʻylagansiz. «B» ni tanlagan boʻlsangiz, roʻyxat navbat (queue) kabi ishlaydi deb oʻylagansiz: u
stek kabi ishlaydi.

</details>

```console
$ go run ./tartib
baza ochildi
fayl ochildi
lock olindi
ish bajarildi
lock qaytarildi
fayl yopildi
baza yopildi
```

Bu tartib **LIFO** (*Last In, First Out* — oxirgi qoʻyilgan birinchi chiqadi) deyiladi. Mantiqi oddiy: lock
faylni ochgandan keyin olingan, fayl esa bazadan keyin. Oxirgi olingan resurs birinchi qaytariladi, chunki u
oldingilariga tayanishi mumkin. Har bir qatordan keyin `defer` roʻyxati:

| Qator | Ekranga | `defer` roʻyxati (yuqorisi — birinchi ishlaydigani) |
|---|---|---|
| 7–8 | `baza ochildi` | `baza yopildi` |
| 10–11 | `fayl ochildi` | `fayl yopildi`, `baza yopildi` |
| 13–14 | `lock olindi` | `lock qaytarildi`, `fayl yopildi`, `baza yopildi` |
| 16 | `ish bajarildi` | oʻzgarmadi |
| 17 (`}`) | `lock qaytarildi`, `fayl yopildi`, `baza yopildi` | boʻsh |

Go spec'i buni shunday yozadi: *"deferred functions are invoked immediately before the surrounding function
returns, in the reverse order they were deferred"* — «kechiktirilgan funksiyalar oʻrab turgan funksiya
qaytishidan oldin, qoʻyilgan tartibiga teskari tartibda chaqiriladi». Funksiya `return` bilan tugasa ham, oxirgi
`}` ga yetsa ham, panic bilan tugasa ham — `defer` lar ishlaydi.

Xuddi shu dastur JS, Python va PHP'da (bu fayllar kurs papkasida yoʻq, alohida ishga tushirildi: Node.js 24,
Python 3.13, PHP 8.4):

```js
console.log("baza ochildi");
try {
  console.log("fayl ochildi");
  try {
    console.log("ish bajarildi");
  } finally {
    console.log("fayl yopildi");
  }
} finally {
  console.log("baza yopildi");
}
```

```python
from contextlib import contextmanager

@contextmanager
def resurs(nom):
    print(nom, "ochildi")
    yield
    print(nom, "yopildi")

with resurs("baza"), resurs("fayl"):
    print("ish bajarildi")
```

```php
<?php
echo "baza ochildi\n";
try {
    echo "fayl ochildi\n";
    try {
        echo "ish bajarildi\n";
    } finally {
        echo "fayl yopildi\n";
    }
} finally {
    echo "baza yopildi\n";
}
```

```console
$ node tartib.js
baza ochildi
fayl ochildi
ish bajarildi
fayl yopildi
baza yopildi
$ python3 tartib.py
baza ochildi
fayl ochildi
ish bajarildi
fayl yopildi
baza yopildi
$ php tartib.php
baza ochildi
fayl ochildi
ish bajarildi
fayl yopildi
baza yopildi
```

Tartib bir xil: teskari. Farq — shaklda va chegarada:

| | JS / PHP `try … finally` | Python `with` | Go `defer` |
|---|---|---|---|
| Har bir resurs | yangi ichma-ich blok | `with` dagi yana bitta element yoki ichma-ich blok | bitta tekis qator, olishning yonida |
| Qachon ishlaydi | **blok** tugaganda | **blok** tugaganda | **funksiya** tugaganda |
| Teskari tartib | ichma-ich joylashuvdan kelib chiqadi | xuddi shunday | `defer` roʻyxati: LIFO |

Go nega shunday tanlagan: olish va qaytarish yonma-yon turadi, ichma-ich bloklar oʻsmaydi. Narxi — oxirgi
qatordagi «funksiya» soʻzi. Boshidagi xato aynan shundan.

## Argument defer qatorida hisoblanadi

`defer` ning ikkinchi qoidasi. Kurs papkasidagi `vaqt/main.go` funksiya qancha ishlaganini `defer` bilan ikki xil
oʻlchaydi:

```go filename="vaqt/main.go" showLineNumbers
// defer argumentlari defer qatorida hisoblanadi, closure ichidagisi esa oxirida.
package main

import (
	"fmt"
	"time"
)

func ish() {
	start := time.Now()
	defer fmt.Println("argument:", time.Since(start).Round(time.Millisecond))
	defer func() {
		fmt.Println("closure: ", time.Since(start).Round(time.Millisecond))
	}()

	time.Sleep(100 * time.Millisecond) // og'ir ish
}

func main() {
	ish()
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10 | `start := time.Now()` | boshlanish vaqti |
| 11 | `defer fmt.Println("argument:", time.Since(start)…)` | `time.Since(start)` — `start` dan beri oʻtgan vaqt; `.Round(time.Millisecond)` — millisekundgacha yaxlitlaydi. Bu yerda u `Println` ning **argumenti** |
| 12–14 | `defer func() { … }()` | nomsiz funksiya (closure, [GO-1.06](/lab/youtube/go/go-1-06)); oxiridagi `()` uni chaqiradi, `defer` esa shu chaqiruvni kechiktiradi. `time.Since` closure'ning **ichida** |
| 16 | `time.Sleep(100 * time.Millisecond)` | 100 ms kutadi: «ogʻir ish» oʻrnida |

Oʻylab koʻring: dastur qaysi ikki qatorni, qaysi tartibda chiqaradi?

**A)** `argument: 100ms`, keyin `closure:  100ms` · **B)** `closure:  100ms`, keyin `argument: 0s` ·
**C)** `argument: 0s`, keyin `closure:  100ms`

<details>
<summary>Javob</summary>

**B.** Ikki qoida birga ishlaydi. Birinchisi — tartib: 12-qatordagi `defer` oxirgi qoʻyilgan, u birinchi
ishlaydi (LIFO). Ikkinchisi — argument vaqti: 11-qatordagi `time.Since(start)` `defer` qatorining **oʻzida**
hisoblandi, oʻshanda hali 0 oʻtgan edi; `Println` keyin shu saqlangan `0s` ni chiqaradi. Closure ichidagi kod esa
funksiya tugaganda ishlaydi va 100 ms ni koʻradi. «A» ni tanlagan boʻlsangiz, `defer` butun qatorni kechiktiradi
deb oʻylagansiz. «C» ni tanlagan boʻlsangiz, argument qoidasini topgansiz, lekin LIFO'ni unutgansiz.

</details>

```console
$ go run ./vaqt
closure:  100ms
argument: 0s
```

Spec: *"Each time a "defer" statement executes, the function value and parameters to the call are evaluated as
usual and saved anew but the actual function is not invoked."* — «`defer` har safar bajarilganda funksiya qiymati
va chaqiruv parametrlari odatdagidek hisoblanadi va saqlab qoʻyiladi, lekin funksiyaning oʻzi chaqirilmaydi».
Vaqt chizigʻi:

| Vaqt | Nima boʻladi | Saqlangan narsa |
|---|---|---|
| 0 ms, 11-qator | `time.Since(start)` hisoblanadi → `0s` | `Println("argument:", 0s)` |
| 0 ms, 12-qator | closure yaratiladi, ichidagi kod hali ishlamaydi | `func(){…}` (u `start` ni ushlab turadi) |
| 0 → 100 ms | `time.Sleep` | — |
| 100 ms, `}` | closure ishlaydi: `time.Since(start)` endi hisoblanadi → `100ms` | — |
| 100 ms | `Println("argument:", 0s)` saqlangan `0s` ni chiqaradi | — |

Bu xatoni `go vet` taniydi:

```console
$ go vet ./vaqt
vaqt/main.go:11:33: call to time.Since is not deferred
```

11-qator, 33-ustun: *call to time.Since is not deferred* — «`time.Since` chaqiruvi kechiktirilmagan». Bu
`go vet` ning `defers` tekshiruvi; u aynan `time.Since` ni defer argumentida topadi. Boshqa funksiyalar uchun
(`defer log.Println(len(buf))`) u jim, qoida esa bir xil. Shu qoida method value uchun ham ishlaydi:
[GO-1.12](/lab/youtube/go/go-1-12) uy vazifasidagi `defer b.Chiqar()` da value receiver'li `b` `defer` qatorida
nusxalanadi.

**Tuzatish:** kechikib hisoblanishi kerak boʻlgan narsani closure ichiga oling (12–14-qatorlar).

## Sikldagi defer tuzogʻi

Endi boshidagi `sikl/main.go` ga qaytamiz. `defer` **sikl qadami** tugaganda emas, **butun funksiya** (`sana`)
tugaganda ishlaydi. Har bir qadam roʻyxatga yana bitta `f.Close()` qoʻshadi, fayl esa ochiq qoladi:

| Qadam (`nom`) | Ochiq fayllar | `defer` roʻyxati |
|---|---|---|
| 1 (`log-0001.txt`) | 1 | `f1.Close()` |
| 2 (`log-0002.txt`) | 2 | `f2.Close()`, `f1.Close()` |
| … | … | … |
| 1019 (`log-1019.txt`) | 1019 (+5 band = 1024) | 1019 ta `Close` |
| 1020 (`log-1020.txt`) | `os.Open` → `too many open files` | `return` → 1019 ta `Close` endi ishlaydi |

Limit boʻlmasa, 2000 qadamdan keyin 2000 ta fayl ochiq turardi. Fayllar faqat `sana` tugaganda yopiladi.
Haqiqiy serverda limit kattaroq, lekin uzoq yoki cheksiz siklda (masalan, navbatdan oʻqiyotgan worker) ochiq
fayllar baribir toʻplanadi.

Kompilyator ham, `go vet` ham bu yerda jim:

```console
$ go vet ./sikl
```

Buyruq hech narsa chiqarmadi: `go vet` uchun bu toʻgʻri kod. staticcheck'ning SA9001 tekshiruvi shu mavzuda:
*"Deferred calls run when the surrounding function returns, not at the end of each loop iteration."* — «defer
chaqiruvlari sikl qadami oxirida emas, oʻrab turgan funksiya qaytganda ishlaydi». Lekin u asosan kanal ustidagi
`range` siklini tekshiradi; bizning fayl siklimizni topishiga tayanmang.

Python'da xuddi shu sikl `with` bilan yoziladi va muammo yoʻq, chunki `with` **blok** tugaganda yopadi (fayl kurs
papkasida yoʻq, alohida ishga tushirildi):

```python
import os
import tempfile

os.chdir(tempfile.mkdtemp())
ochildi = 0
for i in range(1, 2001):
    nom = f"log-{i:04d}.txt"
    open(nom, "w").close()
    with open(nom) as f:  # with bloki tugashi bilan yopiladi
        ochildi += 1
print("ochildi:", ochildi, "ta fayl")
```

```console
$ bash -c 'ulimit -n 1024; python3 sikl.py'
ochildi: 2000 ta fayl
```

JS yoki PHP'dagi `try … finally` ham sikl ichida har qadamda ishlaydi: u ham blokka bogʻlangan. Go'ning `defer` i
esa funksiyaga bogʻlangan. JS/Python/PHP'dan kelgan dasturchining qoʻli aynan shu yerda adashadi.

Yana bitta narx bor. Go 1.14 reliz yozuvlariga koʻra, oddiy `defer` *"almost zero overhead"* — «deyarli bepul»
boʻldi. Lekin bu tezlashtirish (open-coded defer) sikl ichidagi `defer` ga qoʻllanmaydi: kompilyator butun
funksiyada uni oʻchiradi (manba «Chuqurroq» boʻlimida).

## Tuzatish: sikl tanasi alohida funksiyada

Tuzatish oddiy: sikl tanasini alohida funksiyaga chiqaramiz. Endi `defer` oʻsha kichik funksiya tugashi bilan
ishlaydi. Kurs papkasidagi `sikltuzat/main.go`:

```go filename="sikltuzat/main.go" showLineNumbers
// Tuzatish: har bir fayl alohida funksiyada ochiladi, defer o'sha funksiya tugaganda ishlaydi.
package main

import (
	"fmt"
	"os"
)

func bittasi(nom string) error {
	f, err := os.Open(nom)
	if err != nil {
		return err
	}
	defer f.Close() // bittasi tugashi bilan yopiladi
	return nil
}

func sana(nomlar []string) (int, error) {
	ochildi := 0
	for _, nom := range nomlar {
		if err := bittasi(nom); err != nil {
			return ochildi, err
		}
		ochildi++
	}
	return ochildi, nil
}

func main() {
	dir, nomlar := loglar(2000)
	defer os.RemoveAll(dir)

	n, err := sana(nomlar)
	fmt.Println("ochildi:", n, "ta fayl")
	if err != nil {
		fmt.Println("xato:", err)
	}
}

// loglar vaqtinchalik papkada n ta bo'sh fayl yaratadi va o'sha papkaga o'tadi.
func loglar(n int) (string, []string) {
	dir, err := os.MkdirTemp("", "loglar")
	if err != nil {
		panic(err)
	}
	if err := os.Chdir(dir); err != nil {
		panic(err)
	}
	nomlar := make([]string, n)
	for i := range nomlar {
		nomlar[i] = fmt.Sprintf("log-%04d.txt", i+1)
		if err := os.WriteFile(nomlar[i], nil, 0o644); err != nil {
			panic(err)
		}
	}
	return dir, nomlar
}
```

Oʻzgargan qatorlar:

| Qator | Kod | Nima qiladi |
|---|---|---|
| 9–16 | `func bittasi(nom string) error` | bitta faylni ochadi va yopadi («bittasi» — bitta fayl uchun) |
| 14 | `defer f.Close()` | endi `bittasi` tugashi bilan, yaʼni har bir fayl uchun alohida ishlaydi |
| 21 | `if err := bittasi(nom); err != nil {` | sikl tanasi endi bitta chaqiruv |

`main` va `loglar` oʻzgarmagan. Xuddi shu limit bilan:

```console
$ bash -c 'ulimit -n 1024; go run ./sikltuzat'
ochildi: 2000 ta fayl
```

2000 ta faylning hammasi ochildi va yopildi: bir vaqtda ochiq fayl eng koʻpi bilan bitta. Ish vaqtida koʻp
uchraydigan boshqa yoʻl — `defer` siz, `f.Close()` ni qoʻlda chaqirish. Lekin unda har bir `return` va panic
yoʻlida `Close` ni unutmaslik kerak; alohida funksiya bu ishni `defer` ga qaytaradi.

## panic: oddiy ish toʻxtaydi, defer'lar ishlaydi

`defer` panic bilan tugagan funksiyada ham ishlaydi, dedik. Tekshiramiz. Indeks slice chegarasidan tashqarida
boʻlsa, Go runtime **panic** beradi ([GO-1.08](/lab/youtube/go/go-1-08) da koʻrgan edik). Kurs papkasidagi `panik/main.go`:


## recover: panic'ni oddiy xatoga aylantirish

`catch` ga eng yaqin narsa — **`recover`**. U panic'ni toʻxtatadi va panic qiymatini qaytaradi. Lekin bitta shart
bor: u faqat **`defer` qilingan funksiyaning oʻzida** chaqirilganda ishlaydi. Boshqa joyda `nil` qaytaradi va
hech narsa qilmaydi. Kurs papkasidagi `qutqar/main.go`:

```go filename="qutqar/main.go" showLineNumbers
// recover: panic'ni ushlab, oddiy xatoga aylantirish (nomlangan natija orqali).
package main

import "fmt"

func narx(narxlar []int, i int) (n int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("narx(%d): %v", i, r)
		}
	}()
	return narxlar[i], nil
}

func main() {
	narxlar := []int{1200, 3400, 560}
	for _, i := range []int{1, 5, 2} {
		n, err := narx(narxlar, i)
		fmt.Println(n, err)
	}
	fmt.Println("dastur davom etdi")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `func narx(…) (n int, err error)` | ikkala natijaga nom berilgan: `n` va `err`. Bu **nomlangan natija** (*named result*): funksiya ichida oddiy oʻzgaruvchi, boshida zero value (`0`, `nil`) |
| 7–11 | `defer func() { … }()` | panic boʻlsa ham ishlaydigan closure |
| 8 | `if r := recover(); r != nil {` | `recover()` — panic boʻlmasa `nil`, boʻlsa panic qiymati (`r`) |
| 9 | `err = fmt.Errorf("narx(%d): %v", i, r)` | panic'ni `err` natijasiga oddiy xato qilib yozadi |
| 12 | `return narxlar[i], nil` | `i` chegarada boʻlsa — narx va `nil`; boʻlmasa shu yerda panic |
| 17 | `for _, i := range []int{1, 5, 2}` | uchta indeksni sinaydi: 5 — chegaradan tashqarida |

Closure tashqi funksiyaning nomlangan natijasini oʻzgartira oladimi? Spec: *"if the deferred function is a
function literal and the surrounding function has named result parameters that are in scope within the literal,
the deferred function may access and modify the result parameters before they are returned"* — «defer qilingan
funksiya nomsiz funksiya boʻlsa va tashqi funksiyaning nomlangan natijalari uning ichida koʻrinsa, u natijalarni
qaytarilishidan oldin oʻqiy va oʻzgartira oladi». Nomsiz natijada (`(int, error)`) closure'ning `err` ga
yetadigan nomi boʻlmasdi.

Oʻylab koʻring: `narx(narxlar, 5)` qatori nima chiqaradi?

**A)** dastur `panik` dagi kabi yiqiladi · **B)** `0 narx(5): runtime error: index out of range [5] with length 3`,
keyin dastur davom etadi · **C)** `0 <nil>`: panic jim yutiladi

<details>
<summary>Javob</summary>

**B.** 12-qatorda panic boʻldi, oddiy ish toʻxtadi, `defer` dagi closure ishladi. `recover` panic'ni toʻxtatdi va
uning qiymatini (`runtime error: …`) qaytardi, closure uni `err` ga yozdi. `narx` oddiy funksiya kabi qaytdi:
`n` hali `0` (unga hech narsa yozilmagan edi), `err` esa yangi xato. `main` uchun bu oddiy `(qiymat, error)`.
«A» ni tanlagan boʻlsangiz, `recover` ni unutgansiz. «C» ni tanlagan boʻlsangiz, `recover` xatoni oʻzi qaytaradi deb
oʻylagansiz: `err` ga uni closure yozadi (9-qator).

</details>

```console
$ go run ./qutqar
3400 <nil>
0 narx(5): runtime error: index out of range [5] with length 3
560 <nil>
dastur davom etdi
```

| `i` | 12-qator | `defer` closure | `narx` qaytaradi |
|---|---|---|---|
| 1 | `return 3400, nil` | `recover()` → `nil`, hech narsa qilmaydi | `3400, nil` |
| 5 | panic: `index out of range [5]` | `recover()` → panic qiymati; `err = narx(5): …` | `0, narx(5): …` |
| 2 | `return 560, nil` | `recover()` → `nil` | `560, nil` |

JS/Python'dagi `try { … } catch (e) { … }` dan farqi: `catch` blokning istalgan joyida turadi va dastur
`catch` dan keyingi qatordan davom etadi. `recover` esa faqat `defer` ichida ishlaydi, va funksiya panic boʻlgan
joydan emas, **funksiyaning oʻzidan** qaytadi. Natijani oʻzgartirishning yagona yoʻli — nomlangan natija.

Lekin bu kundalik yoʻl emas. Kutilgan xato (yoʻq narx, notoʻgʻri summa) uchun `error` qaytaring: buni oʻtgan
darsda koʻrdik. Effective Go: *"recover is only useful inside deferred functions"* va uni ishlatish joyi sifatida
serverni koʻrsatadi: *"shut down a failing goroutine inside a server without killing the other executing
goroutines"* — «server ichidagi yiqilayotgan goroutine'ni boshqa ishlayotgan goroutine'larni oʻldirmasdan
toʻxtatish». `recover` **chegarada** kerak: HTTP handler, fon goroutine'ning boshi, kutubxonaning tashqi API'si.
`fmt` ham shunday qiladi: `Error()` yoki `String()` metodidagi panic'ni ushlab, `%!v(PANIC=…)` deb yozadi
([GO-1.14](/lab/youtube/go/go-1-14) uy vazifasi «Guru»).

## Pauza: main'dagi recover boshqa goroutine'ni qutqaradimi?

Bitta yangi kalit soʻz kerak: `go f()` funksiyani yangi **goroutine** da — `main` bilan parallel ishlaydigan
alohida bajarilish oqimida — ishga tushiradi. Goroutine'larni [GO-1.21](/lab/youtube/go#go-1-21) da batafsil koʻramiz.
Kurs papkasidagi `goroutine/main.go`:

```go filename="goroutine/main.go" showLineNumbers
// main'dagi recover boshqa goroutine'dagi panic'ni ushlay olmaydi.
package main

import (
	"fmt"
	"time"
)

func main() {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("qutqarildi:", r)
		}
	}()

	go func() {
		var narxlar map[string]int
		narxlar["olma"] = 1200 // nil map'ga yozish: panic
	}()

	time.Sleep(100 * time.Millisecond)
	fmt.Println("main tugadi")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10–14 | `defer func() { if r := recover(); … }()` | `main` da `qutqar` dagi kabi himoya |
| 16–19 | `go func() { … }()` | nomsiz funksiyani yangi goroutine'da ishga tushiradi |
| 17–18 | `var narxlar map[string]int`, `narxlar["olma"] = 1200` | nil map'ga yozish → panic ([GO-1.09](/lab/youtube/go/go-1-09)) |
| 21 | `time.Sleep(100 * time.Millisecond)` | `main` goroutine'ni 100 ms kuttiradi, toki ikkinchisi ishlab ulgursin |

Ishga tushirishdan oldin oʻylab koʻring: `main` dagi `recover` dasturni qutqaradimi?

**A)** ha: `qutqarildi: assignment to entry in nil map`, keyin `main tugadi` · **B)** yoʻq: dastur yiqiladi,
`main` dan hech narsa chiqmaydi · **C)** panic faqat oʻsha goroutine'ni toʻxtatadi, `main tugadi` chiqadi

<details>
<summary>Javob</summary>

**B.** Panic faqat **oʻz goroutine'sining** chaqiruvlari boʻylab yuqoriga chiqadi, boshqa goroutine'ga
oʻtmaydi. `main` ning `defer` i boshqa goroutine'ning stekida yoʻq, shuning uchun uning `recover` iga navbat
kelmaydi. Panic oʻsha goroutine'ning boshiga yetganda, spec boʻyicha **butun dastur** toʻxtaydi: *"the program is
terminated and the error condition is reported"* — «dastur toʻxtatiladi va xato haqida xabar beriladi». «A» ni
tanlagan boʻlsangiz, `recover` ni butun dasturni oʻrab turgan `try/catch` deb oʻylagansiz. «C» ni tanlagan
boʻlsangiz, Python thread'lari kabi deb oʻylagansiz (pastda solishtiramiz).

</details>

## net/http: handler'dagi panic va fondagi panic

Backend'da bu farq juda muhim. `net/http` server har bir ulanishga alohida goroutine ochadi va handler'dagi
panic'ni oʻzi ushlaydi. Hujjatida shunday yozilgan: *"If ServeHTTP panics, the server (the caller of ServeHTTP)
assumes that the effect of the panic was isolated to the active request. It recovers the panic, logs a stack
trace to the server error log, and either closes the network connection or sends an HTTP/2 RST_STREAM"* —
«ServeHTTP panic qilsa, server panic taʼsiri faqat shu soʻrovga tegishli deb hisoblaydi: panic'ni `recover`
bilan toʻxtatadi, stack trace'ni server xato logiga yozadi va ulanishni yopadi yoki HTTP/2 RST_STREAM yuboradi».
Handler oʻzi ochgan goroutine esa bu himoyadan tashqarida. Kurs papkasidagi `server/main.go` — server va unga
soʻrov yuboradigan mijoz bitta dasturda:

```go filename="server/main.go" showLineNumbers
// net/http handler'dagi panic'ni ushlaydi, handler ochgan goroutine'dagisini esa yo'q.
package main

import (
	"fmt"
	"log"
	"net/http"
	"os"
	"time"
)

func main() {
	http.HandleFunc("/narx", func(w http.ResponseWriter, r *http.Request) {
		narxlar := []int{1200, 3400, 560}
		fmt.Fprintln(w, narxlar[5]) // panic: server uni ushlaydi
	})
	http.HandleFunc("/salom", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "server tirik")
	})
	http.HandleFunc("/fon", func(w http.ResponseWriter, r *http.Request) {
		go func() {
			time.Sleep(50 * time.Millisecond) // fondagi ish
			var hisob map[string]int
			hisob["fon"]++ // panic boshqa goroutine'da: hech kim ushlamaydi
		}()
		fmt.Fprintln(w, "fonda ishlayapti")
	})

	srv := &http.Server{Addr: "127.0.0.1:8015", ErrorLog: log.New(os.Stdout, "", 0)}
	go srv.ListenAndServe()
	time.Sleep(100 * time.Millisecond)

	for _, yol := range []string{"/narx", "/salom", "/fon", "/salom"} {
		so(yol)
		time.Sleep(100 * time.Millisecond)
	}
}

func so(yol string) {
	res, err := http.Get("http://127.0.0.1:8015" + yol)
	if err != nil {
		fmt.Println("javob", yol+":", "xato,", err)
		return
	}
	defer res.Body.Close()
	fmt.Println("javob", yol+":", res.Status)
}
```

## Fatal error: recover ojiz qoladigan xatolar

Endi `recover` umuman ushlay olmaydigan xatolar. Kurs papkasidagi uchta dasturning `main` funksiyasida `recover`
bor, va u har doim `qutqarildi:` deb yozishi kerak edi:

```go filename="fatal/deadlock/main.go" showLineNumbers

import "fmt"

func main() {

		fmt.Println("qutqarildi:", r)

}
```

```go filename="fatal/stack/main.go" showLineNumbers
func main() {
```

|---|---|---|
| hammasi | `defer func() { r := recover(); fmt.Println("qutqarildi:", r) }()` | `defer` ishlasa, `qutqarildi:` qatori **har doim** chiqadi (hatto `r` `nil` boʻlsa ham) |

## Nega recover ojiz: throw va fatal panic emas

Chunki bular panic emas. Runtime bu holatlarda `panic` ni emas, `throw` yoki `fatal` funksiyasini chaqiradi.
Ularning izohlari (`runtime/panic.go`, go1.26.8, qisqartirilgan: funksiya tanalari va qoʻshimcha izohlar
olib tashlangan):

```go
// throw triggers a fatal error that dumps a stack trace and exits.
//
// throw should be used for runtime-internal fatal errors where Go itself,
// rather than user code, may be at fault for the failure.
func throw(s string)

// fatal is equivalent to throw, but is used when user code is expected to be
// at fault for the failure, such as racing map writes.
func fatal(s string)

// fatalthrow implements an unrecoverable runtime throw. It freezes the
// system, prints stack traces starting from its caller, and terminates the
// process.
func fatalthrow(t throwType)
```

| Funksiya | Izohning tarjimasi | Qayerda ishlatiladi |
|---|---|---|
| `throw` | «fatal error chiqaradi, stack trace'ni yozadi va chiqadi»; xatoda foydalanuvchi kodi emas, Go'ning oʻzi aybdor boʻlishi mumkin | stack overflow (`throw("stack overflow")`), out of memory (`throw("out of memory")`) |
| `fatal` | `throw` bilan bir xil, lekin xatoda foydalanuvchi kodi aybdor deb hisoblanganda, masalan map'ga bir vaqtda yozish | deadlock (`fatal("all goroutines are asleep - deadlock!")`), `concurrent map writes` |
| `fatalthrow` | «ushlab boʻlmaydigan throw: tizimni muzlatadi, stack trace'larni chiqaradi va jarayonni toʻxtatadi» | ikkalasi ham shu yerga keladi → `exit(2)` |

[GO-1.09](/lab/youtube/go/go-1-09) dagi `concurrent map writes` ham shu `fatal` dan chiqqan edi. Ikkalasi ham xabarni
chiqaradi va jarayonni darhol toʻxtatadi. Panic'dagi kabi stek boʻylab yuqoriga chiqish yoʻq: `defer` lar
ishlamaydi, `recover` ga navbat ham kelmaydi.

| | panic | fatal error (`throw` / `fatal`) |
|---|---|---|
| Misollar | indeks chegaradan tashqarida, nil map'ga yozish, nil pointer, `panic(x)` | deadlock, stack overflow, out of memory, concurrent map writes |
| `defer` ishlaydimi | ha, stek boʻylab | yoʻq |
| `recover` | oʻsha goroutine'da ushlaydi | ushlay olmaydi |
| Natija | ushlanmasa — `panic: …`, exit status 2 | har doim `fatal error: …`, exit status 2 |

## os.Exit va log.Fatal: defer'ni oʻzingiz oʻtkazib yuborasiz

`defer` ni oʻtkazib yuboradigan yana bir yoʻl bor, va u sizning qoʻlingizda. `os.Exit` dasturni darhol
toʻxtatadi. Hujjatda ochiq yozilgan: *"The program terminates immediately; deferred functions are not run."* —
«dastur darhol toʻxtaydi; defer qilingan funksiyalar ishlamaydi». `log.Fatal` ham ichida `os.Exit` chaqiradi:
*"Fatal is equivalent to Print followed by a call to os.Exit(1)."* — «Fatal — `Print`, keyin `os.Exit(1)`».
Kurs papkasidagi `exit/main.go`:

```go filename="exit/main.go" showLineNumbers

	"fmt"
	"log"
)

func main() {
	defer fmt.Println("defer: buferdagi loglar yozildi")

	if err := sozla(); err != nil {

	}

func sozla() error {
```

## Xulosa: defer, panic, recover qoidalari

- Resursni olgan zahoti uni `defer` bilan qaytaring; `defer` lar funksiya tugaganda teskari tartibda (LIFO)
  ishlaydi — `return` da ham, panic'da ham.
- `defer` qatoridagi argument darhol hisoblanadi; closure ichidagi kod esa oxirida ishlaydi.
- Sikl ichida `defer` kerak boʻlsa, sikl tanasini alohida funksiyaga chiqaring.
- `recover` faqat `defer` qilingan funksiyaning oʻzida va faqat oʻz goroutine'sidagi panic'ni ushlaydi; u
  chegarada (handler, goroutine boshi) kerak, kutilgan xatolar uchun `error` qaytaring.
- Fatal error (deadlock, stack overflow, out of memory, concurrent map writes) va `os.Exit` / `log.Fatal` da
  `defer` ham ishlamaydi, `recover` ham yordam bermaydi.

## Chuqurroq (ixtiyoriy): nega aynan 1019 va defer narxi

**Nega 1019, va nega `bash -c`.** Dastur ishga tushganda 0, 1, 2 deskriptorlari (stdin, stdout, stderr) band.
Go runtime yana ikkitasini ochadi: `eventpoll` (epoll) va `eventfd` — tarmoq va fayllarni kutish mexanizmi uchun.
Bu tadqiqot paytida `ls -l /proc/<pid>/fd` bilan tekshirilgan. Limitning ikki qismi bor: yumshoq (*soft*) va
qattiq (*hard*). Go dastur ishga tushganda yumshoq limitni qattiq limitdan bittaga kamgacha koʻtaradi
(`syscall/rlimit.go`: `nlim.Cur = nlim.Max - 1`). bash'dagi `ulimit -n 1024` ikkalasini ham 1024 qiladi, shuning
uchun Go uni koʻtara olmaydi. zsh'dagi `ulimit -n` esa faqat yumshoq limitni oʻzgartiradi: Go uni qayta
koʻtaradi va 2000 ta faylning hammasi ochiladi. Demo shuning uchun `bash -c` bilan yozilgan.

**Open-coded defer.** Go 1.14 dan kompilyator oddiy `defer` larni funksiya oxiriga toʻgʻridan-toʻgʻri chaqiruv
sifatida joylashtiradi (*open-coded defer*, [taklif hujjati](https://github.com/golang/proposal/blob/master/design/34481-opencoded-defers.md)): reliz
yozuvlari boʻyicha bu *"almost zero overhead compared to calling the deferred function directly"* — «toʻgʻridan-
toʻgʻri chaqiruvga nisbatan deyarli nol qoʻshimcha xarajat». Sikl ichidagi `defer` lar soni esa oldindan
nomaʼlum. Kompilyator kodi (`cmd/compile/internal/walk/stmt.go`, go1.26.8):

```console
$ sed -n 116,120p $(go env GOROOT)/src/cmd/compile/internal/walk/stmt.go

			// If n.Esc is not EscNever, then this defer occurs in a loop,
			// so open-coded defers cannot be used in this function.
			ir.CurFunc.SetOpenCodedDeferDisallowed(true)
		}
```

*«n.Esc EscNever boʻlmasa, bu defer siklda turibdi, shuning uchun bu funksiyada open-coded defer ishlatib
boʻlmaydi»*. Eʼtibor bering: butun **funksiya** sekin yoʻlga oʻtadi, faqat sikldagi `defer` emas. Ichki tuzilishi
(`_defer` va `_panic` yozuvlari) [GO-4.15](/lab/youtube/go#go-4-15) da.

**`panic(nil)`.** Go 1.21 dan beri (modulning `go` qatori 1.21 yoki yangiroq boʻlsa) `panic(nil)` ham
ushlanadigan qiymat beradi: `recover()` `nil` emas, `*runtime.PanicNilError` qaytaradi. Shuning uchun `if r := recover(); r != nil` tekshiruvi hech qachon panic'ni
oʻtkazib yubormaydi (dastur kurs papkasida yoʻq, alohida ishga tushirildi):


(`%T` — qiymatning turi.)

**Deadlock har doim ham topilmaydi.** Runtime deadlock'ni faqat **hamma** goroutine qotganda aniqlaydi. Serverda
bitta goroutine abadiy kutib qolsa, boshqalari (masalan, `ListenAndServe`) ishlayotgan boʻladi va runtime hech
narsa demaydi: bu jim goroutine leak.

oʻylash. Xato xabari yoʻq, kompilyator ham, `go vet` ham jim; yuk ostida fayllar yoki ulanishlar tugaydi va
`too many open files` chiqadi. «2000 ta fayl, 1019 tasi ochildi» va «Sikldagi defer tuzogʻi» boʻlimlarida
koʻrdik. **Tuzatish:** sikl tanasini alohida funksiyaga chiqaring (`sikltuzat/`).

**2. Kechikishi kerak boʻlgan qiymatni argumentga qoʻyish.** `defer fmt.Println(time.Since(start))` har doim
`0s` chiqaradi («Argument defer qatorida hisoblanadi» boʻlimi). `go vet` buni faqat `time.Since` uchun topadi:
`call to time.Since is not deferred`. **Tuzatish:** `defer func() { fmt.Println(time.Since(start)) }()`.

**3. `defer f.Close` — qavslarsiz.** `defer` ga chaqiruv kerak, funksiyaning oʻzi emas (bu misol kurs papkasida
yoʻq, alohida ishga tushirildi):

```go
package main

import "os"

func main() {
	f, err := os.Open("go.mod")
	if err != nil {
		return
	}
	defer f.Close
}
```

```console
$ go run -trimpath qavssiz/main.go
# command-line-arguments
qavssiz/main.go:10:8: expression in defer must be function call
```

10-qator, 8-ustun: *expression in defer must be function call* — «defer'dagi ifoda funksiya chaqiruvi boʻlishi
kerak». **Tuzatish:** `defer f.Close()`.

**4. `recover` ni `defer` siz chaqirish.** `recover` ni funksiya boshida oddiy chaqirsangiz, u `nil` qaytaradi:
oʻsha paytda hali panic yoʻq. Kompilyator ham, `go vet` ham jim (bu misol kurs papkasida yoʻq, alohida ishga
tushirildi):

```go
package main

import "fmt"

func narx(narxlar []int, i int) (n int, err error) {
	if r := recover(); r != nil { // XATO: defer'siz
		err = fmt.Errorf("narx(%d): %v", i, r)
	}
	return narxlar[i], nil
}

func main() {
	fmt.Println(narx([]int{1200, 3400, 560}, 5))
	fmt.Println("dastur davom etdi")
}
```

```console
$ go run -trimpath togridan/main.go
panic: runtime error: index out of range [5] with length 3

goroutine 1 [running]:
main.narx({0x17c1e0acee8, 0x3, 0x17c1e07a6f8?}, 0x5)
	./main.go:9 +0xe8
main.main()
	./main.go:13 +0x49
exit status 2
```

`main.narx(…)` dagi raqamlar — argumentlarning xotiradagi koʻrinishi (slice manzili, uzunligi 3, …, `i = 5`),
manzil har safar boshqa. 9-qatorda panic, `recover` esa 6-qatorda allaqachon `nil` qaytargan edi. Xuddi shunday,
`defer recover()` va `defer` dagi funksiya ichidagi **boshqa** funksiyadan chaqirilgan `recover` ham ishlamaydi
(uy vazifasi «Guru»). **Tuzatish:** `recover` ni toʻgʻridan-toʻgʻri `defer` qilingan funksiyaning ichida
chaqiring, `qutqar/main.go` dagi kabi.

**5. `main` dagi `recover` hammasini ushlaydi, deb oʻylash.** Fon goroutine'dagi panic butun jarayonni yiqitadi
(«Pauza» va «net/http» boʻlimlari). **Tuzatish:** har bir `go func()` ning birinchi `defer` ida `recover`
(uy vazifasi «Qiyin»).

**6. `defer` li funksiyada `log.Fatal` yoki `os.Exit`.** Jim muammo: `defer` lar ishlamaydi, bufer diskka
yozilmaydi («os.Exit va log.Fatal» boʻlimi). **Tuzatish:** `main` dan tashqarida `log.Fatal` ishlatmang; ishni
`run() error` ga chiqaring va `os.Exit` ni faqat `main` da, `run` qaytgandan keyin chaqiring.

**7. Yozilgan faylda `defer f.Close()` xatosini tashlab yuborish.** Oʻqish uchun ochilgan faylda bu zararsiz.
Yozishda esa disk toʻlganda xato aynan `Close` da chiqishi mumkin, oddiy `defer f.Close()` uni yoʻqotadi.
**Tuzatish:** nomlangan natija + `defer func() { err = errors.Join(err, f.Close()) }()` (uy vazifasi «Oʻrta»).

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** `defer fmt.Println(x)` va `defer func() { fmt.Println(x) }()` farqi nima?

<details>
<summary>Javob</summary>

Birinchisida `x` `defer` qatorining oʻzida hisoblanadi va saqlanadi: keyingi oʻzgarishlar koʻrinmaydi. Ikkinchisida
`defer` closure'ni saqlaydi, `x` esa closure ichida funksiya tugaganda oʻqiladi va oxirgi qiymatni koʻradi.
Ikkalasi ham funksiya tugaganda, LIFO tartibida ishlaydi.

</details>

**2.** Bu dastur nima chiqaradi? **A)** `3` · **B)** `6` · **C)** `0`

```go
func ikki() (n int) {
	defer func() { n *= 2 }()
	return 3
}

func main() {
	fmt.Println(ikki())
}
```

<details>
<summary>Javob</summary>

**B: `6`.** `return 3` avval nomlangan natijaga yozadi (`n = 3`), keyin `defer` lar ishlaydi, keyin funksiya
qaytadi. Closure `n` ni ikkiga koʻpaytiradi: `6`. «A» ni tanlagan boʻlsangiz, `return` qiymatni darhol olib
ketadi deb oʻylagansiz. «C» ni tanlagan boʻlsangiz, `defer` `n` ning boshidagi `0` ni koʻradi deb oʻylagansiz.
Toʻliq dastur (kurs papkasida yoʻq, alohida ishga tushirildi):

```go
package main

import "fmt"

func ikki() (n int) {
	defer func() { n *= 2 }()
	return 3
}

func main() {
	fmt.Println(ikki())
}
```

```console
$ go run -trimpath natija/main.go
6
```

</details>

**3.** `main` da `recover` bor, panic esa `go func() { … }()` ichida. Dastur qutqariladimi? `recover` qayerda
turishi kerak edi?

<details>
<summary>Javob</summary>

Yoʻq. Panic faqat oʻz goroutine'sining chaqiruvlari boʻylab yuqoriga chiqadi; goroutine boshiga yetganda butun
dastur `exit status 2` bilan toʻxtaydi. `recover` oʻsha goroutine'ning **ichida**, uning birinchi `defer` ida
turishi kerak (uy vazifasidagi `xavfsizGo`).

</details>

**4.** Quyidagilardan qaysi birida `defer` lar ishlaydi: `return`, panic, `os.Exit(1)`, `log.Fatal(err)`,
`fatal error: all goroutines are asleep - deadlock!`?

<details>
<summary>Javob</summary>

Faqat `return` va panic'da. `os.Exit` va `log.Fatal` (`Print` + `os.Exit(1)`) jarayonni darhol toʻxtatadi.
Fatal error esa panic emas: runtime `fatal` / `throw` → `fatalthrow` → `exit(2)`, stek boʻylab yuqoriga chiqish
yoʻq.

</details>

**5.** [GO-1.09](/lab/youtube/go/go-1-09) dan: nil map'ga yozish va ikki goroutine'ning bitta map'ga bir vaqtda yozishi.
Qaysi birini `recover` ushlaydi va nega?

<details>
<summary>Javob</summary>

Nil map'ga yozishni ushlaydi: bu oddiy panic (`assignment to entry in nil map`). Bir vaqtda yozish esa
`fatal("concurrent map writes")`: runtime buni foydalanuvchi kodidagi xato deb hisoblaydi va `defer` larni
ishlatmasdan jarayonni toʻxtatadi, shuning uchun `recover` ga navbat kelmaydi.

</details>

🟡 **Oʻrta:** faylga yozadigan `Saqla(nom, data)` funksiyasini yozing: `f.Close()` qaytargan xato yoʻqolmasin.

<summary>Javob</summary>

`homework/orta/saqla.go`:

```go filename="homework/orta/saqla.go" showLineNumbers
// O'rta: Close xatosini yo'qotmaydigan saqla.
package orta

import (
	"errors"
	"os"
)

// saqlaXato: defer f.Close() Close qaytargan xatoni tashlab yuboradi.
func saqlaXato(nom string, data []byte) error {
	f, err := os.Create(nom)
	if err != nil {
		return err
	}
	defer f.Close()
	_, err = f.Write(data)
	return err
}

// Saqla: nomlangan natija + defer closure, Close xatosi ham qaytadi.
func Saqla(nom string, data []byte) (err error) {
	f, err := os.Create(nom)
	if err != nil {
		return err
	}
	defer func() {
		err = errors.Join(err, f.Close())
	}()
	_, err = f.Write(data)
	return err
}
```

`saqlaXato` dagi oddiy `defer f.Close()` `Close` xatosini tashlab yuboradi. `Saqla` da nomlangan natija `err` va
`defer` dagi closure bor: `errors.Join(err, f.Close())` yozish xatosini ham, `Close` xatosini ham saqlaydi,
ikkalasi `nil` boʻlsa — `nil` («Oldin bilish kerak» dagi savol). Test `/dev/full` ga yozadi: Linux'dagi bu

🟠 **Qiyin:** `xavfsizGo(nom, f)` yozing: `f` ni yangi goroutine'da ishga tushirsin, uning panic'i serverni
yiqitmasin.

<details>
<summary>Javob</summary>

`homework/qiyin/main.go`:

```go filename="homework/qiyin/main.go" showLineNumbers
// Qiyin: fondagi goroutine'dagi panic butun serverni yiqitmasin.
package main

import (
	"fmt"
	"log"
	"os"
	"time"
)

var logger = log.New(os.Stdout, "", 0)

// xavfsizGo f'ni yangi goroutine'da ishga tushiradi va uning panic'ini o'sha goroutine ichida ushlaydi.
func xavfsizGo(nom string, f func()) {
	go func() {
		defer func() {
			if r := recover(); r != nil {
				logger.Printf("%s: panic ushlandi: %v", nom, r)
			}
		}()
		f()
	}()
}

func main() {
	xavfsizGo("fon", func() {
		var hisob map[string]int
		hisob["fon"]++
	})
	time.Sleep(100 * time.Millisecond)
	fmt.Println("server tirik")
}
```

`recover` yangi goroutine'ning **ichida**, uning birinchi `defer` ida turibdi (16–20-qatorlar). `f` shu
goroutine'da ishlaydi (21-qator), shuning uchun uning panic'i shu `defer` gacha koʻtariladi.

```console
$ go run ./homework/qiyin

server tirik
```

</details>

🔴 **Guru:** `homework/guru/main.go` dagi toʻrtta variantdan (`a`, `b`, `c`, `d`) qaysilari panic'ni ushlaydi?
Nega?

```go filename="homework/guru/main.go" showLineNumbers
// Guru: to'rtta variantdan qaysi birida recover panic'ni ushlaydi?
package main

import "fmt"

func qutqar() {
	if r := recover(); r != nil {
		fmt.Println("  ushlandi:", r)
	}
}

func a() {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("  ushlandi:", r)
		}
	}()
	panic("a")
}

func b() {
	defer qutqar()
	panic("b")
}

func c() {
	defer func() { qutqar() }()
	panic("c")
}

func d() {
	defer recover()
	panic("d")
}

func sina(nom string, f func()) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("  ushlanmadi, tashqariga chiqdi:", r)
		}
	}()
	fmt.Println(nom + ":")
	f()
}

func main() {
	sina("a", a)
	sina("b", b)
	sina("c", c)
	sina("d", d)
}
```

(`sina` — «sinash»: har variantni oʻz `recover` i bilan ishga tushiradi, variant ushlamagan panic shu yerga
chiqadi.)

<details>
<summary>Javob</summary>

```console
$ go run ./homework/guru
a:
  ushlandi: a
b:
  ushlandi: b
c:
  ushlanmadi, tashqariga chiqdi: c
d:
  ushlanmadi, tashqariga chiqdi: d
```

Faqat `a` va `b`. `a` da `recover` ni `defer` qilingan nomsiz funksiya toʻgʻridan-toʻgʻri chaqiradi. `b` da
`qutqar` ning oʻzi `defer` qilingan, `recover` ni u toʻgʻridan-toʻgʻri chaqiradi. `c` da `recover` `defer`
qilingan funksiyaning ichidagi **boshqa** funksiyadan (`qutqar`) chaqirilgan → `nil`. `d` da (`defer recover()`)
`recover` ning oʻzi `defer` qilingan, uni `defer` qilingan funksiya chaqirmagan → `nil`. Spec: *"The return value
of recover is nil when the goroutine is not panicking or recover was not called directly by a deferred
function."* — «goroutine panic holatida boʻlmasa yoki `recover` ni defer qilingan funksiya toʻgʻridan-toʻgʻri
chaqirmagan boʻlsa, `recover` `nil` qaytaradi».

</details>
