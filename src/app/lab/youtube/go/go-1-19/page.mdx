## Nimani oʻrganasiz

Buyurtmalar eksporti — 1 GiB CSV fayl, ichida 61 003 111 qator. Ikki Go dasturi qatorlarni sanaydi va bir xil javob
beradi. Biri eng koʻp 1028 MiB xotira oladi, ikkinchisi 2.5 MiB. Ikkinchisi hech narsa qilmaydigan boʻsh Go
dasturidan deyarli farq qilmaydi. Fayl 10 GiB boʻlsa-chi? Konteynerga 512 MiB xotira chegarasi qoʻyilgan boʻlsa-chi?
Node'da bu `fs.readFile` va `fs.createReadStream` orasidagi tanlov. Go'da bu tanlov qanday koʻrinadi?

**Bitta gʻoya:** katta maʼlumotni bir yoʻla emas, kichik boʻlaklab oʻqing va yozing. Go'da buni bitta metodli ikkita
interface bajaradi: `io.Reader` va `io.Writer`. `io.Copy` ularni ulaydi, shuning uchun xotira fayl hajmiga bogʻliq
boʻlmaydi.

Dars oxirida siz:

- `f.Read(buf)` sikli bilan istalgan hajmdagi faylni oʻzgarmas xotirada oʻqiysiz va `n` hamda `io.EOF` ni toʻgʻri
  tartibda tekshirasiz;
- oʻz `io.Writer` ingizni yozasiz va uning shartnoma qoidalarini bilasiz (`n < len(p)` → xato, `p` ni saqlamaslik);
- `io.Copy(dst, src)` bilan Reader va Writer'ni ulaysiz, argumentlar tartibida adashmaysiz;
- Writer ichiga Writer qoʻyib (gzip), 1 GiB faylni bir necha MiB xotirada siqasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| oqim | maʼlumotni bir yoʻla emas, boʻlakma-boʻlak oʻqish va yozish | stream |
| `io.Reader` / `io.Writer` | bitta metodli ikki interface: `Read(p)` sizning buferingizni toʻldiradi, `Write(p)` toʻla buferni oladi | Reader, Writer |
| `io.Copy` | Reader'dan oʻqib, Writer'ga yozadigan tayyor sikl, oʻrtada bitta bufer | io.Copy |

Ikkita yordamchi soʻz ham bor: **bufer** (buffer) — boʻlak uchun bir marta ajratilgan `[]byte`. Kurs kodidagi
izohlarda u «chelak» deb atalgan. **Peak RSS** esa jarayon ishlagan vaqtda egallagan eng koʻp operativ xotira.
Kod chiqaradigan «eng koʻp xotira» shu. `io.EOF` yangi soʻz emas: bu GO-1.14 dagi sentinel xato.

## Ikki dastur, bitta javob

Avval faylning hajmi. `du -h --apparent-size` faylning haqiqiy uzunligini odam oʻqiydigan birlikda chiqaradi:

```console

```

Aniqrogʻi, 1 073 741 824 bayt, yaʼni roppa-rosa 1 GiB (2³⁰). Bu sahifada MiB = 2²⁰ bayt, KiB = 1024 bayt.

Birinchi dastur faylni bir yoʻla xotiraga yuklaydi. Node'dagi `fs.readFileSync(path)` yoki Python'dagi
`open(path, "rb").read()` shu ishni qiladi.

```go filename="hammasi/main.go" showLineNumbers

import (
	"bytes"
	"fmt"
	"os"

	"github.com/abdurahmon27/go-backend-uz/lessons/019-io-reader-writer/ozim"
)

func main() {
	data, err := os.ReadFile(os.Args[1]) // butun fayl — bitta katta slice
	if err != nil {
		fmt.Println(err)
		os.Exit(1)

	buyurtma := bytes.Count(data, []byte{'\n'}) // har buyurtma — bitta qator
```

### «Xotira» deganda nima oʻlchanyapti

`ozim.RSS()` jarayonning **peak RSS** ini qaytaradi: dastur ishlagan vaqt ichida operativ xotirada eng koʻp nechta
sahifasi turgan. Linux buni `/proc/self/status` dagi `VmHWM` qatorida beradi (proc_pid_status(5)).

```go filename="ozim/rss.go" showLineNumbers
package ozim

import (
	"bytes"
	"os"
	"strconv"
)

// RSS — shu jarayon (dasturning oʻzi) egallagan eng katta operativ xotira (peak RSS), MiB. Faqat Linux:
// /proc/self/status dagi VmHWM. getrusage'ning Maxrss'i bu yerga yaramaydi: `go run` va shell
// dasturni fork/vfork + exec bilan ishga tushiradi, Maxrss esa ota jarayonning xotirasini ham "meros" oladi.
func RSS() float64 {
	b, err := os.ReadFile("/proc/self/status")
	if err != nil {
		return -1
	}
	_, s, _ := bytes.Cut(b, []byte("VmHWM:"))
	s, _, _ = bytes.Cut(s, []byte("kB"))
	kb, err := strconv.ParseInt(string(bytes.TrimSpace(s)), 10, 64)
	if err != nil {
		return -1
	}
	return float64(kb) / 1024
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 13 | `os.ReadFile("/proc/self/status")` | jarayonning holat faylini oʻqiydi (u kichik, shuning uchun butun oʻqish mayli) |
| 17–18 | `bytes.Cut(…)` | `VmHWM:` dan keyingi va `kB` dan oldingi qismni ajratadi |
| 19 | `strconv.ParseInt(…)` | `"2560"` kabi matnni songa aylantiradi |
| 23 | `float64(kb) / 1024` | kB → MiB |

Ikki nozik joy. Birinchisi: Linux'ning fayl keshi (page cache) bu songa kirmaydi. Yadro faylni ikkala dastur uchun
ham xotirada ushlab turishi mumkin, lekin u jarayonniki emas. Ikkinchisi: `getrusage` ning `Maxrss` i bu yerda
notoʻgʻri natija beradi. Sababi «Chuqurroq» boʻlimida.

## Shartnoma: `io.Reader`

Ikkinchi dastur faylni boʻlaklab oʻqiydi. Boshqa tillarda buning uchun alohida API bor: Node'da `stream`, Python'da
`f.read(n)`. Go'da esa standart kutubxonaning `io` paketidagi bitta kichik interface bor. `io/io.go` (go1.26.8):

```go
type Reader interface {
	Read(p []byte) (n int, err error)
}
```

`Read` metodiga **siz** bufer berasiz: `p` — boʻsh `[]byte`. `Read` unga koʻpi bilan `len(p)` bayt yozadi va ikki
narsani qaytaradi:

| Nima | Maʼnosi |
|---|---|
| `p` | chaqiruvchining buferi: `Read` baytlarni shu yerga yozadi |
| `n` | nechta bayt yozildi: `0 <= n <= len(p)`. Faqat `p[:n]` yangi maʼlumot |
| `err` | xato yoki `io.EOF` — «maʼlumot tugadi» belgisi |

Bu shakl nega muhim? Buferni Reader emas, chaqiruvchi beradi. Shuning uchun bitta buferni million marta qayta
ishlatish mumkin, har chaqiruvda yangi xotira ajratilmaydi. Node'ning `'data'` hodisasi esa har boʻlakni yangi
`Buffer` sifatida beradi. Python'dagi `f.read(n)` ham har safar yangi `bytes` qaytaradi. Python'da Go'ga eng yaqin
narsa — `f.readinto(buf)`: u ham oldindan ajratilgan buferni toʻldiradi.

Hujjatdagi yana bir qoida: `Read` buferni oxirigacha toʻldirishi shart emas. Hujjatda shunday yozilgan: maʼlumot bor,
lekin `len(p)` bayt emas — `Read` odatda borini qaytaradi, koʻproq kutmaydi. Diskdagi fayl odatda toʻla bufer beradi,
tarmoq ulanishi esa kamroq berishi mumkin. Shuning uchun doim `n` ga qarang. Aniq `N` bayt kerak boʻlsa, `io.ReadFull`
bor.

Bu interface'ni kim bajaradi? `*os.File`, `os.Stdin`, `net.Conn`, HTTP soʻrovining tanasi (`r.Body`),
`strings.Reader`, `bytes.Buffer`, `gzip.Reader`. Hammasi bitta metod bilan. GO-1.13 dagi kabi, hech biri
`implements io.Reader` deb yozmaydi.

## Shartnoma: `io.Writer`

Ikkinchi interface buning teskarisi: unga baytlar bilan **toʻla** bufer berasiz.

```go
type Writer interface {
	Write(p []byte) (n int, err error)
}
```

`n` — `p` dan nechta bayt yozilgani. Hujjatdagi qoidalar qisqa, lekin qatʼiy:

| Qoida (io.go) | Maʼnosi |
|---|---|
| *Write must return a non-nil error if it returns n &lt; len(p)* | hammasini yoza olmasangiz, xato qaytaring |
| *Write must not modify the slice data, even temporarily* | `p` ichini oʻzgartirmang |
| *Implementations must not retain p* | `p` ni oʻzingizda saqlab qolmang: chaqiruvchi uni keyingi boʻlak uchun qayta ishlatadi |

Writer'lar: `*os.File`, `os.Stdout`, `http.ResponseWriter`, `bytes.Buffer`, `gzip.Writer`, `net.Conn`. SHA-256 kabi
hash ham Writer (`hash.Hash` ichida `io.Writer` bor). Diskdagi fayl (`*os.File`) ikkala interface'ni ham bajaradi:
undan oʻqish ham, unga yozish ham mumkin.

Ikkala interface ham faqat baytlarni biladi. Fayl nima, tarmoq nima, gzip nima — ularga farqi yoʻq. Rob Pike'ning
«The bigger the interface, the weaker the abstraction» degan maqolini GO-1.13 da koʻrgansiz. `io.Reader` va
`io.Writer` — uning eng yaxshi misoli.

## Bufer sikli: `oqim/main.go`

Endi ikkinchi dasturning toʻliq kodi:

```go filename="oqim/main.go" showLineNumbers
// oqim: xuddi shu sanoq, lekin fayl 32 KiB'lik "chelak" bilan boʻlakma-boʻlak oʻqiladi.
package main

import (
	"bytes"
	"fmt"
	"io"
	"log"
	"os"

	"github.com/abdurahmon27/go-backend-uz/lessons/019-io-reader-writer/ozim"
)

func main() {
	f, err := os.Open(os.Args[1]) // f — ochilgan fayl
	if err != nil {
		log.Fatal(err)
	}
	defer f.Close()

	buyurtma, chaqiruv := 0, 0
	buf := make([]byte, 32*1024) // 32 KiB'lik boʻsh chelak
	for {
		n, err := f.Read(buf) // fayl chelakni toʻldiradi
		chaqiruv++
		buyurtma += bytes.Count(buf[:n], []byte{'\n'}) // chelakning toʻlgan qismida qator oxirlarini sanaymiz

		if err == io.EOF { // fayl tugadi
			break // takrorlashni toʻxtatamiz
		}
		if err != nil { // boshqa xato: toʻxtaymiz
			log.Fatal(err)
		}
	}
	fmt.Printf("buyurtmalar: %d · eng koʻp xotira: %.1fMiB\n", buyurtma, ozim.RSS())
	fmt.Printf("Read chaqiruvi: %d\n", chaqiruv)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 15 | `f, err := os.Open(os.Args[1])` | faylni oʻqish uchun ochadi: `f` — `*os.File`, ham Reader, ham Writer |
| 16–18 | `log.Fatal(err)` | xatoni vaqt bilan chiqarib, 1 kodi bilan chiqadi |
| 19 | `defer f.Close()` | `main` tugaganda faylni yopadi (GO-1.15) |
| 21 | `buyurtma, chaqiruv := 0, 0` | ikki hisoblagich: qatorlar va `Read` chaqiruvlari |
| 22 | `buf := make([]byte, 32*1024)` | 32 768 baytli bufer, **bir marta** ajratiladi |
| 23 | `for {` | shartsiz `for` — boshqa tillardagi `while (true)` (GO-1.05) |
| 24 | `n, err := f.Read(buf)` | fayl buferni toʻldiradi. `:=` sikl ichida yangi `n` va `err` yaratadi: 15-qatordagi `err` ni yashiradi (shadowing, GO-1.06), bu yerda zararsiz |
| 25 | `chaqiruv++` | chaqiruvlarni sanaydi |
| 26 | `bytes.Count(buf[:n], …)` | faqat buferning **toʻlgan** qismidagi `'\n'` larni sanaydi |
| 28–30 | `if err == io.EOF { break }` | fayl tugadi: sikldan chiqamiz |
| 31–33 | `if err != nil { log.Fatal(err) }` | boshqa xato: dasturni toʻxtatamiz |
| 35–36 | `fmt.Printf(…)` | natija, xotira va `Read` chaqiruvlari soni |

28-qatorda `io.EOF` bilan `==` orqali solishtiramiz. GO-1.14 da `errors.Is` ni oʻrgangan edik. Lekin `io.EOF` ning
hujjati aniq: `Read` `EOF` ning oʻzini qaytarishi shart, uni oʻrab (wrap qilib) emas, chunki chaqiruvchilar uni `==`
bilan tekshiradi.

Tartibga qarang: avval 26-qatorda baytlar sanaladi, keyin 28-qatorda `err` tekshiriladi. Hujjatdagi qoida: *Callers
should always process the n > 0 bytes returned before considering the error err*. Baʼzi Reader'lar oxirgi baytlarni
`io.EOF` bilan **bitta** chaqiruvda qaytaradi. `err` ni avval tekshirsangiz, oʻsha baytlar yoʻqoladi (bu xatoning
ishga tushgan misoli «Koʻp uchraydigan xatolar» boʻlimida).

Bitta chaqiruvda xotirada nima bor:

```text
        disk                               jarayon xotirasi
 ┌──────────────────────────┐        ┌──────────────────────────────────┐
 │ buyurtma.csv  1 GiB       │  Read  │ buf  [32 768 bayt]  ← bitta,      │
 │ ██████████████████████████│ ─────► │                       qayta-qayta │
 └──────────────────────────┘        │ buyurtma, chaqiruv  (ikki son)    │
                                     │ Go runtime          (~2.4 MiB)    │
                                     └──────────────────────────────────┘

 hammasi/:   data [1 073 741 824 bayt]  ← butun fayl birdaniga
```

Endi savol. Fayl 1 GiB, bufer 32 KiB, va bu yerda kilo 1024 degani (1 GiB = 1024 × 1024 KiB). Fayl tugaguncha
`Read` necha marta chaqiriladi?

**A)** `32768` · **B)** `32769` · **C)** `31250`

<details>
<summary>Javob</summary>

**B: `32769`.** 1 073 741 824 ÷ 32 768 = 32 768 ta toʻla bufer. Undan keyin yana bitta chaqiruv kerak: u `n = 0` va
`io.EOF` qaytaradi, shu bilan sikl tugaydi. «`32768`» ni tanlagan boʻlsangiz, oxirgi boʻsh chaqiruvni unutgansiz:
fayl roppa-rosa tugagan boʻlsa ham, `Read` buni faqat keyingi chaqiruvda aytadi. «`31250`» ni tanlagan boʻlsangiz,
1 GB ÷ 32 KB ni oʻnli birliklarda (1 000 000 000 ÷ 32 000) hisoblagansiz.

| Chaqiruv | `n` | `err` | Nima boʻladi |
|---|---|---|---|
| 1 | 32 768 | `nil` | 0…32 767-baytlar `buf` da, qatorlar sanaladi |
| 2 | 32 768 | `nil` | oʻsha `buf` ustiga keyingi 32 768 bayt yoziladi |
| … | 32 768 | `nil` | … |
| 32 768 | 32 768 | `nil` | faylning oxirgi baytlari |
| 32 769 | 0 | `io.EOF` | `buf[:0]` boʻsh, 0 qoʻshiladi; `break` |

</details>

```go filename="bosh/main.go" showLineNumbers
// bosh: hech narsa qilmaydigan Go dasturi — taqqoslash uchun: Go runtime'ning oʻzi qancha xotira oladi?
package main
```

### Python'da xuddi shu sikl

Python'da `f.read(n)` fayl oxirida xato emas, boʻsh `bytes` qaytaradi. Kod kurs papkasida yoʻq:

```python
# Python: faylni 32 KiB'lik boʻlaklarda oʻqib, qator oxirlarini sanaydi.
import re
import sys

buyurtma = chaqiruv = 0
with open(sys.argv[1], "rb") as f:
    while True:
        chunk = f.read(32 * 1024)
        chaqiruv += 1
        if not chunk:  # fayl oxiri: boʻsh bytes
            break
        buyurtma += chunk.count(b"\n")

hwm = int(re.search(r"VmHWM:\s+(\d+)", open("/proc/self/status").read()).group(1))
print(f"buyurtmalar: {buyurtma} · read chaqiruvi: {chaqiruv} · eng koʻp xotira: {hwm / 1024:.1f}MiB")
```

```console
$ python3 oqim.py /tmp/io19/buyurtma.csv

```

Chaqiruvlar soni ham bir xil: 32 768 ta toʻla boʻlak va bitta boʻsh. Farqlar:

| | Python `f.read(n)` | Go `f.Read(buf)` |
|---|---|---|
| bufer | har chaqiruvda yangi `bytes` | chaqiruvchining bitta buferi |
| fayl oxiri | boʻsh `b""` | `n = 0`, `err == io.EOF` |
| oxirgi baytlar va oxir belgisi | hech qachon birga kelmaydi | bitta chaqiruvda kelishi mumkin: avval `n` |
| xato | istisno (exception) | `err` qiymati |

## Oʻz Writer'imiz: `Hisoblagich`

Endi interface'ni oʻzimiz bajaramiz. `Hisoblagich` («hisoblagich», counter) baytlarni saqlamaydi, faqat sanaydi:

```go filename="ozim/hisoblagich.go" showLineNumbers
package ozim

import "bytes"

// Hisoblagich — oʻz io.Writer'imiz: kelgan baytlar va qatorlarni sanaydi, chelakni saqlamaydi.
type Hisoblagich struct{ Bayt, Qator int64 } // ikkita sanoq

func (h *Hisoblagich) Write(p []byte) (int, error) {
	h.Bayt += int64(len(p))                        // kelgan baytlar soni
	h.Qator += int64(bytes.Count(p, []byte{'\n'})) // qator oxirlari
	return len(p), nil                             // hammasini oldim, muammo yoʻq
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `type Hisoblagich struct{ Bayt, Qator int64 }` | ikki maydon, ikkalasi `int64`: baytlar va qatorlar soni |
| 8 | `func (h *Hisoblagich) Write(p []byte) (int, error)` | `io.Writer` ning metodi bilan bir xil imzo. Pointer receiver: metod `h` ning maydonlarini oʻzgartiradi (GO-1.12) |
| 9 | `h.Bayt += int64(len(p))` | kelgan baytlar soni; `len` `int` qaytaradi, shuning uchun `int64(…)` ga aylantiramiz |
| 10 | `h.Qator += int64(bytes.Count(p, []byte{'\n'}))` | kelgan boʻlakdagi qator oxirlari |
| 11 | `return len(p), nil` | shartnomaga javob: «hamma baytni oldim, xato yoʻq» |

`implements io.Writer` hech qayerda yozilmagan: imzo mos, shuning uchun `*Hisoblagich` `io.Writer` ni oʻzi bajaradi
(GO-1.13). Pointer receiver boʻlgani uchun interface'ni `*Hisoblagich` bajaradi, `Hisoblagich` qiymati emas. Bu
keyingi boʻlimdagi `&h` ning sababi.

Hisoblagich `p` ni hech qayerga saqlamaydi, faqat undan sanaydi. Bu «must not retain p» qoidasi. `io.Copy` bitta
buferni qayta-qayta beradi. `p` ni slice'ga qoʻshib saqlasangiz, saqlangan hamma «boʻlaklar» bitta 32 KiB xotiraga
qaraydi va har yangi boʻlak ularni ustidan yozadi.

## `io.Copy`: Reader'ni Writer'ga ulash

Endi Reader (fayl) va Writer'ni (Hisoblagich) ulaymiz. `oqim/` dagi qoʻlda yozilgan sikl kerak emas: standart
kutubxonada tayyor sikl bor.

```go
func Copy(dst Writer, src Reader) (written int64, err error)
```

Diqqat: **avval qayerga, keyin qayerdan.** Node'dagi `pipeline(source, destination)` va Python'dagi
`shutil.copyfileobj(fsrc, fdst)` da manba birinchi. Go'da esa manzil birinchi, xuddi `copy(dst, src)` funksiyasidagi
kabi.

```go filename="sanash/main.go" showLineNumbers
// sanash: oqim/ dagi siklni io.Copy bajaradi: manba — fayl (Reader), manzil — Hisoblagich (Writer).
package main

import (
	"fmt"
	"io"
	"os"

	"github.com/abdurahmon27/go-backend-uz/lessons/019-io-reader-writer/ozim"
)

func main() {
	f, err := os.Open(os.Args[1])
	if err != nil {
		fmt.Println(err)
		os.Exit(1)
	}
	defer f.Close()

	var h ozim.Hisoblagich
	_, err = io.Copy(&h, f) // qayerga ← qayerdan: Hisoblagich (&h — nusxasi emas, oʻzi) ← fayl
	if err != nil {
		fmt.Println(err)
		os.Exit(1)
	}
	fmt.Printf("buyurtmalar: %d · bayt: %d · eng koʻp xotira: %.1fMiB\n", h.Qator, h.Bayt, ozim.RSS())
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 13–18 | `os.Open`, `defer f.Close()` | `oqim/` dagi kabi |
| 20 | `var h ozim.Hisoblagich` | zero value: `Bayt` va `Qator` — 0 |
| 21 | `_, err = io.Copy(&h, f)` | manzil — `&h` (Hisoblagich'ning manzili), manba — `f`. Birinchi natija (yozilgan baytlar soni) `_` ga tashlanadi: u `h.Bayt` da bor |
| 22–25 | `if err != nil { … }` | `io.Copy` muvaffaqiyatda `nil` qaytaradi, `io.EOF` emas |
| 26 | `fmt.Printf(…, h.Qator, h.Bayt, …)` | Hisoblagich sanagan sonlar |

Nega `&h`? Ikki sabab bor. Birinchisi: `Write` pointer receiver'li, shuning uchun `io.Writer` ni faqat `*Hisoblagich`
bajaradi. Ikkinchisi: `h` ni qiymat bilan bersangiz, `io.Copy` uning nusxasini oladi va sanoq nusxada qolardi.
`&h` bilan `io.Copy` aynan bizning `h` ga yozadi. (`&` siz yozilsa nima boʻlishi «Koʻp uchraydigan xatolar»
boʻlimida.)

`io.Copy` hujjatda shunday yozilgan: muvaffaqiyatli `Copy` `err == nil` qaytaradi, `err == EOF` emas. U manbani
`EOF` gacha oʻqishi kerak, shuning uchun `EOF` ni xato deb hisoblamaydi.

```console
$ go run ./sanash /tmp/io19/buyurtma.csv
buyurtmalar: 61003111 · bayt: 1073741824 · eng koʻp xotira: 2.5MiB
```

Qatorlar soni avvalgidek, baytlar — roppa-rosa 1 GiB, xotira yana 2.5 MiB. Bu yerda `io.Copy` oʻrtada bitta 32 KiB
bufer bilan `oqim/` dagi siklni bajardi. Fayl ham, Hisoblagich ham bir-birini tanimaydi: ular faqat bitta
metodli shartnomani biladi. Shuning uchun istalgan Reader'ni istalgan Writer'ga ulash mumkin.

```text
  f (*os.File)                io.Copy                     &h (*Hisoblagich)
 ┌────────────┐  Read(buf)  ┌──────────────┐  Write(buf[:n]) ┌──────────────┐
 │ 1 GiB fayl │ ──────────► │ buf 32 KiB   │ ──────────────► │ Bayt, Qator  │
 └────────────┘             └──────────────┘                 └──────────────┘
                 32 769 marta takrorlanadi, bufer bitta
```

«Oʻrtada doim 32 KiB» — har doim emasmi? Yoʻq: `io.Copy` avval qisqa yoʻllarni qidiradi. Bu «Chuqurroq» boʻlimida.

## Writer ichida Writer: gzip

Endi ulashning eng kuchli tomoni. `gzip.Writer` ham Writer: unga berilgan baytlarni siqadi va **ichidagi boshqa
Writer'ga** yozadi. Videoda buni matryoshka deyishgan: Writer ichida Writer.

```go filename="siqish/main.go" showLineNumbers
// siqish: Writer ichida Writer — gzip baytlarni siqadi va ichidagi faylga yozadi.
package main

import (
	"compress/gzip"
	"fmt"
	"io"
	"os"

	"github.com/abdurahmon27/go-backend-uz/lessons/019-io-reader-writer/ozim"
)

func main() {
	f, err := os.Open(os.Args[1])
	tek(err)
	defer f.Close()
	out, err := os.Create(os.Args[2])
	tek(err)

	gz, _ := gzip.NewWriterLevel(out, gzip.BestSpeed) // gz — arxivlovchi: yangi faylni (out) oʻrab oladi, eng tez rejimda
	n, err := io.Copy(gz, f)                          // nasos: fayl → arxivlovchi → yangi fayl
	tek(err)
	tek(gz.Close()) // qolgan siqilgan baytlarni yozib tugatadi
	tek(out.Close())

	st, err := os.Stat(os.Args[2])
	tek(err)
	mib := func(b int64) float64 { return float64(b) / (1 << 20) }
	fmt.Printf("oʻqildi: %.1fMiB · yozildi: %.1fMiB · eng koʻp xotira: %.1fMiB\n", mib(n), mib(st.Size()), ozim.RSS())
}

func tek(err error) {
	if err != nil {
		fmt.Println(err)
		os.Exit(1)
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 17 | `out, err := os.Create(os.Args[2])` | yangi fayl (`*os.File`, Writer) |
| 20 | `gz, _ := gzip.NewWriterLevel(out, gzip.BestSpeed)` | `gz` — `out` ni oʻragan gzip Writer, eng tez siqish darajasida. Xato faqat notoʻgʻri daraja konstantasida boʻladi, shuning uchun `_` |
| 21 | `n, err := io.Copy(gz, f)` | fayl → `gz` → `out`. `n` — oʻqilgan (siqilmagan) baytlar |
| 23 | `tek(gz.Close())` | gzip ichida qolgan baytlarni va fayl oxiridagi nazorat qismini (trailer) yozadi. Busiz `.gz` fayl chala qoladi |
| 24 | `tek(out.Close())` | yangi faylni yopadi |
| 26–29 | `os.Stat`, `mib(…)` | yozilgan fayl hajmi; `mib` — baytni MiB ga aylantiradigan kichik funksiya (closure, GO-1.06) |
| 32–37 | `func tek(err error)` | xato boʻlsa chiqarib, 1 kodi bilan chiqadi |

```text
 f (*os.File) ──Read──► io.Copy [32 KiB] ──Write──► gz (gzip.Writer) ──Write──► out (*os.File)
 buyurtma.csv                                        siqadi                     buyurtma.csv.gz
```

```console
$ go run ./siqish /tmp/io19/buyurtma.csv /tmp/io19/buyurtma.csv.gz
oʻqildi: 1024.0MiB · yozildi: 384.6MiB · eng koʻp xotira: 3.1MiB
```

1 GiB oʻqildi, 384.6 MiB yozildi (37.6 %), xotira 3.1 MiB. Bu ish ~17 soniya oladi. Siqilgan fayl toʻgʻrimi?
`zcat` uni ochib, natijani chiqaradi. `cmp -` shu natijani asl fayl bilan bayt-baytlab solishtiradi va farq boʻlmasa
jim qoladi. `&& echo` faqat oldingi buyruq muvaffaqiyatli boʻlsa ishlaydi:

```console
$ zcat /tmp/io19/buyurtma.csv.gz | cmp - /tmp/io19/buyurtma.csv && echo 'bir xil'
bir xil
```

Butun fayl xotiraga hech qachon chiqmadi: baytlar fayldan gzip'ga, gzip'dan yangi faylga oqib oʻtdi. Boshqa tillarda
xuddi shu zanjir:

| Til | Zanjir |
|---|---|
| Node | `pipeline(fs.createReadStream(a), zlib.createGzip(), fs.createWriteStream(b))` |
| Python | `with open(a, "rb") as f, gzip.open(b, "wb") as g: shutil.copyfileobj(f, g)` |
| Go | `gz := gzip.NewWriter(out)` va `io.Copy(gz, f)` |

Node'da zanjir alohida stream turlari (Readable, Transform, Writable) ustida qurilgan. Go'da esa hammasi oʻsha ikki
metodli interface.

## Xulosa: butun dars bitta jadvalda

| Narsa | Qoida |
|---|---|
| `io.Reader` | `Read(p)`: buferni siz berasiz, u `p[:n]` ni toʻldiradi |
| `io.Writer` | `Write(p)`: toʻla buferni oladi; `n < len(p)` boʻlsa xato; `p` ni saqlamaydi |
| `io.EOF` | «maʼlumot tugadi», nosozlik emas; avval `n` bayt, keyin `err` |
| `io.Copy(dst, src)` | tayyor sikl; avval manzil; muvaffaqiyatda `nil` |
| natija | 1 GiB fayl ~2.5 MiB xotirada: bufer bitta, fayl xotiraga chiqmaydi |

## Chuqurroq (ixtiyoriy): bufer harfni kesadi, io.Copy'ning qisqa yoʻllari

### Bufer baytlarni beradi, harflarni emas

`utf8/main.go` 4 baytlik bufer bilan `"7000 soʻm"` ni oʻqiydi. `ʻ` 2 bayt (`ca bb`, GO-1.04):

```go filename="utf8/main.go" showLineNumbers
// utf8: chelak baytlarni beradi, harflarni emas — boʻlak chegarasi "ʻ" ni (2 bayt) kesib oʻtadi.
package main

import (
	"fmt"
	"io"
	"strings"
	"unicode/utf8"
)

func main() {
	r := strings.NewReader("7000 soʻm")
	buf := make([]byte, 4) // 4 baytlik chelak
	for {
		n, err := r.Read(buf)
		if n > 0 {
			fmt.Printf("%q  toʻgʻri UTF-8: %v\n", buf[:n], utf8.Valid(buf[:n]))
		}
		if err == io.EOF {
			break
		}
	}
}
```

```console
$ go run ./utf8

" so\xca"  toʻgʻri UTF-8: false
"\xbbm"  toʻgʻri UTF-8: false
```

Boʻlak chegarasi `ʻ` ning oʻrtasidan oʻtdi: ikkala boʻlak ham notoʻgʻri UTF-8. Bizning qator sanoqimizga bu
taʼsir qilmaydi. `'\n'` — `0x0A`, koʻp baytli UTF-8 belgilarning esa hamma baytlari `0x80` dan katta (RFC 3629 §3).
Shuning uchun `'\n'` hech qachon boshqa belgining bir qismi boʻlmaydi. Matnni belgilab yoki qatorlab oʻqish uchun
`bufio` bor ([GO-1.20](/lab/youtube/go#go-1-20)). 🔴 uy vazifasi aynan shu kesilishni hal qiladi.

### Oʻz Reader'imiz: `Generator`

Test faylini yasagan `yarat/` manba sifatida kursning oʻz Reader'ini ishlatadi. U buyurtmalarni oldindan
saqlamaydi: `Read(p)` chaqirilganda `p` ga sigʻadigan qatorlarni yasaydi:

```go filename="ozim/generator.go" showLineNumbers
// Package ozim — bu darsda oʻzimiz yozgan io.Reader va io.Writer.
package ozim

import (
	"io"
	"strconv"
)

// Generator — oʻz io.Reader'imiz. Buyurtma qatorlarini oldindan saqlamaydi:
// Read chaqirilganda p ga sigʻadigan qatorlarni yasaydi va beradi.
type Generator struct {
	qoldi  int64  // yana nechta bayt yasash kerak
	id     int64  // oxirgi buyurtma raqami
	navbat []byte // yasalgan, lekin hali berilmagan baytlar
}

// NewGenerator kamida hajm bayt beradi (oxirgi qator butun qoladi, shuning uchun bir necha bayt ortiq boʻlishi mumkin).
func NewGenerator(hajm int64) *Generator { return &Generator{qoldi: hajm} }

func (g *Generator) Read(p []byte) (int, error) {
	if len(p) == 0 { // boʻsh chelak: hech narsa bermaymiz, lekin EOF ham emas
		return 0, nil
	}
	for len(g.navbat) < len(p) && g.qoldi > 0 {
		oldin := len(g.navbat)
		g.id++
		g.navbat = Yoz(g.navbat, g.id)
		g.qoldi -= int64(len(g.navbat) - oldin)
	}
	if len(g.navbat) == 0 {
		return 0, io.EOF
	}
	n := copy(p, g.navbat)
	g.navbat = g.navbat[:copy(g.navbat, g.navbat[n:])]
	return n, nil
}

// Yoz bitta "id,summa,tolandi" qatorini b ga qoʻshadi.
func Yoz(b []byte, id int64) []byte {
	b = strconv.AppendInt(b, id, 10)
	b = append(b, ',')
	b = strconv.AppendInt(b, 1000+id*7919%499000, 10)
	if id%4 == 0 {
		return append(b, ",0\n"...)
	}
	return append(b, ",1\n"...)
}
```

21–23-qatorlar: `len(p) == 0` boʻlsa `0, nil` (hujjat: boʻsh `p` da `Read` doim `n == 0` qaytarishi kerak).
24–29: `navbat` («navbat», queue) `p` ni toʻldirishga yetguncha yangi qatorlar yasaladi. 30–32: berishga hech narsa
qolmasa, `0, io.EOF`. 33–34: `copy` bilan `p` ni toʻldiradi, sigʻmagan qismini `navbat` boshiga suradi. Kursdagi
`ozim/ozim_test.go` uni standart `iotest.TestReader` bilan tekshiradi: u `Read` shartnomasini turli bufer
oʻlchamlarida sinaydi.

### `io.Copy` ichida: ikki qisqa yoʻl

`io.Copy` buferli siklni boshlashdan oldin ikki narsani tekshiradi (go1.26.8, `io/io.go`, `copyBuffer`):

```go
if wt, ok := src.(WriterTo); ok {
	return wt.WriteTo(dst)
}
if rf, ok := dst.(ReaderFrom); ok {
	return rf.ReadFrom(src)
}
```

Bu GO-1.13 dagi type assertion: manbaning `WriteTo` metodi bormi, manzilning `ReadFrom` metodi bormi? Bor boʻlsa,
ishni ularga beradi. Faqat ikkalasi ham boʻlmasa 32 KiB bufer ochiladi.

Shundan bitta muhim xulosa: «oʻzgarmas xotira» — `io.Copy` ning emas, manba va manzilning xususiyati.
`io.Copy(&bytes.Buffer{}, f)` `bytes.Buffer.ReadFrom` orqali butun faylni xotiraga yigʻadi: `bytes.Buffer` baytlarni
saqlaydigan Writer.

Fayldan faylga nusxa (`nusxa/`) eng qiziq holat. Manzil `*os.File`, unda `ReadFrom` bor. Linux'da u
`copy_file_range` tizim chaqiruvini ishlatadi: baytlar dasturga umuman kirmaydi, yadro ichida koʻchiriladi.
`strace` dastur qilgan tizim chaqiruvlarini koʻrsatadi (`-e trace=copy_file_range` — faqat shu chaqiruvni):

```console
$ strace -f -qq -e signal=none -e trace=copy_file_range /tmp/io19/nusxa /tmp/io19/buyurtma.csv /tmp/io19/nusxa.csv
[pid 1101867] copy_file_range(3, NULL, 6, NULL, 2147479552, 0) = 1073741824
[pid 1101867] copy_file_range(3, NULL, 6, NULL, 2147479552, 0) = 0
nusxa: 1073741824 bayt · eng koʻp xotira: 2.5MiB
```

(`/tmp/io19/nusxa` — `go build -o /tmp/io19/nusxa ./nusxa` bilan yigʻilgan binary; `pid` raqami har safar boshqa.)
Bitta chaqiruv 1 073 741 824 baytni koʻchirdi, keyingisi 0 qaytardi: fayl tugadi. Manzil pipe yoki `/dev/null`
boʻlsa, oddiy `read`/`write` siklga qaytadi.

### Qachon butun faylni oʻqish mayli

Kichik, hajmi oldindan maʼlum fayl (sozlamalar, `/proc/self/status`) — `os.ReadFile` mayli. Hajmi nomaʼlum kirish
(yuklangan fayl, HTTP soʻrov tanasi) — faqat boʻlaklab. `io.ReadAll` bundan ham qimmatroq: kurs README'siga koʻra,
go1.26 da u oʻsib boruvchi boʻlaklar yigʻadi va oxirida bitta slice'ga koʻchiradi, 1 GiB faylda 2096 MiB oʻlchangan.
HTTP serverda tanani `http.MaxBytesReader` bilan cheklang: chegaradan oshsa, u xato qaytaradi. `io.LimitReader` esa
chegarada jim `EOF` beradi. U bilan `n+1` bayt oʻqing va `n` dan uzunini rad eting.

### Nega `getrusage` yaramadi

Birinchi versiyada xotira `syscall.Getrusage(RUSAGE_SELF).Maxrss` bilan oʻlchangan. `go run` ostida oqim dasturi
19–20 MiB koʻrsatgan, binary sifatida esa 2 MiB. Sababi: `go run` dasturni vfork + exec bilan ishga tushiradi.
Linux `exec` da `Maxrss` eski xotira maydonining eng yuqori qiymatini ham saqlab qoladi, yaʼni `go` buyrugʻining
~20 MiB ini «meros» oladi. `VmHWM` esa faqat jarayonning hozirgi xotira maydoniga tegishli. Shuning uchun u
`go run` da ham, binary'da ham bir xil ~2.5 MiB koʻrsatadi (dars tadqiqotidagi oʻlchov).

## Koʻp uchraydigan xatolar

**1. `err` ni `n` dan oldin tekshirish.** Bu mavzuning eng klassik xatosi. `iotest.DataErrReader` oxirgi baytlarni
`io.EOF` bilan bitta chaqiruvda qaytaradi. Bu ruxsat etilgan xulq, `*os.File` buni qilmagani uchun xato faylda
koʻrinmay qoladi. Kurs papkasida yoʻq, dars uchun alohida ishga tushirilgan (boʻsh papkada `tartib.go` yarating):

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"strings"
	"testing/iotest"
)

func sana(r io.Reader, avvalErr bool) int {
	buf := make([]byte, 32*1024)
	qator := 0
	for {
		n, err := r.Read(buf)
		if avvalErr && err == io.EOF {
			break // ❌ oxirgi n baytni sanamay chiqib ketadi
		}
		qator += bytes.Count(buf[:n], []byte{'\n'})
		if err == io.EOF {
			break
		}
	}
	return qator
}

func main() {
	matn := "1,8919,1\n2,16838,1\n3,24757,1\n"
	fmt.Println("avval err:", sana(iotest.DataErrReader(strings.NewReader(matn)), true))
	fmt.Println("avval n:  ", sana(iotest.DataErrReader(strings.NewReader(matn)), false))
}
```

```console
$ go run tartib.go
avval err: 0
avval n:   3
```

Xato ham, ogohlantirish ham yoʻq: shunchaki 3 qator oʻrniga 0. **Tuzatish:** avval `buf[:n]` ni ishlating, keyin
`err` ga qarang (`oqim/main.go` dagi 26 → 28-qatorlar tartibi).

**2. `buf[:n]` oʻrniga butun `buf`.** Oxirgi boʻlak odatda buferdan qisqa, uning orqasida oldingi boʻlakning eski
baytlari qoladi. Bu misol ham kurs papkasida yoʻq (`butunbuf.go`):

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"strings"
)

func main() {
	r := strings.NewReader("1\n2\n3\n") // 3 ta qator, 6 bayt
	buf := make([]byte, 4)              // 4 baytlik chelak
	xato, togri := 0, 0
	for {
		n, err := r.Read(buf)
		xato += bytes.Count(buf, []byte{'\n'})      // ❌ butun chelak
		togri += bytes.Count(buf[:n], []byte{'\n'}) // ✅ faqat toʻlgan qismi
		if err == io.EOF {
			break
		}
	}
	fmt.Println("buf:", xato, "· buf[:n]:", togri)
}
```

```console
$ go run butunbuf.go
buf: 6 · buf[:n]: 3
```

Ikkinchi chaqiruv 2 bayt (`"3\n"`) beradi, buferning qolgan ikki bayti esa birinchi chaqiruvdan qolgan `"2\n"`.
Uchinchi chaqiruv `n = 0` beradi, lekin bufer oʻzgarmaydi. **Tuzatish:** faqat `buf[:n]`.

**3. `io.Copy` ga `&` siz Writer berish.** `Write` pointer receiver'li boʻlsa (`manzilsiz.go`, kurs papkasida yoʻq):

```go
package main

import (
	"fmt"
	"io"
	"strings"
)

type Hisoblagich struct{ Bayt int64 }

func (h *Hisoblagich) Write(p []byte) (int, error) {
	h.Bayt += int64(len(p))
	return len(p), nil
}

func main() {
	var h Hisoblagich
	io.Copy(h, strings.NewReader("salom\n"))
	fmt.Println(h.Bayt)
}
```

```console
$ go run manzilsiz.go
# command-line-arguments
./manzilsiz.go:18:10: cannot use h (variable of struct type Hisoblagich) as io.Writer value in argument to io.Copy: Hisoblagich does not implement io.Writer (method Write has pointer receiver)
```

Qanday oʻqiladi: `manzilsiz.go:18:10` — 18-qator, 10-ustun. *cannot use h … as io.Writer value* — «`h` ni io.Writer
qiymati sifatida ishlatib boʻlmaydi». *Hisoblagich does not implement io.Writer (method Write has pointer receiver)* —
«Hisoblagich io.Writer'ni bajarmaydi: Write metodi pointer receiver'li». Bu GO-1.12 dagi method set qoidasi.
**Tuzatish:** `io.Copy(&h, …)`.

**4. Writer `n < len(p)` va `nil` qaytaradi.** Hammasini yozmagan, lekin xato ham aytmagan Writer shartnomani
buzadi (`qisqa.go`, kurs papkasida yoʻq):

```go
package main

import (
	"fmt"
	"io"
	"strings"
)

type Yarim struct{}

// ❌ yarmini "yozadi", lekin xato qaytarmaydi
func (Yarim) Write(p []byte) (int, error) { return len(p) / 2, nil }

func main() {
	n, err := io.Copy(Yarim{}, strings.NewReader("salom dunyo"))
	fmt.Println(n, err)
}
```

```console
$ go run qisqa.go
5 short write
```

`io.Copy` buni oʻzi topdi: 11 baytdan 5 tasi yozildi va xato `io.ErrShortWrite` — *short write*, «qisqa yozuv».
Lekin hamma chaqiruvchi bunchalik ehtiyotkor emas. **Tuzatish:** sigʻmagan boʻlsa, aniq xato qaytaring (🟠 uy
vazifasidagi `ErrToldi` kabi).

**5. Hajmi nomaʼlum kirishni butunlay oʻqish.** `os.ReadFile` yoki `io.ReadAll` xatosiz ishlaydi, lekin xotira fayl
bilan birga oʻsadi («Ikki dastur, bitta javob» va «Oʻlchov» boʻlimlari: 1 GiB → 1028 MiB). **Tuzatish:** `io.Copy`
yoki bufer sikli; HTTP'da `http.MaxBytesReader`.

**6. Writer'da `p` ni saqlab qolish.** `Write` ichida `saqlangan = append(saqlangan, p)` xatosiz ishlaydi, lekin
saqlangan hamma boʻlak bitta buferga qaraydi va keyingi `Write` ularni ustidan yozadi («Oʻz Writer'imiz» boʻlimi).
**Tuzatish:** saqlash shart boʻlsa, nusxa oling: `append([]byte(nil), p...)`.

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** `io.Reader` va `io.Writer` da buferni kim beradi va `n` nimani bildiradi?

<details>
<summary>Javob</summary>

Ikkalasida ham buferni chaqiruvchi beradi. `Read` da `n` — buferga nechta bayt yozilgani (faqat `p[:n]` yangi),
`Write` da — buferdan nechta bayt yozilgani (`n < len(p)` boʻlsa, xato ham boʻlishi shart). Bufer chaqiruvchiniki
boʻlgani uchun bitta buferni qayta-qayta ishlatish mumkin.

</details>

**2.** Nega bufer siklida avval `buf[:n]` ishlatiladi, keyin `err == io.EOF` tekshiriladi?

<details>
<summary>Javob</summary>

`Read` oxirgi baytlarni `io.EOF` bilan bitta chaqiruvda qaytarishi mumkin. `err` ni avval tekshirsangiz, oʻsha
baytlar yoʻqoladi (`tartib.go`: 3 oʻrniga 0). Hujjat ham shuni aytadi: avval `n > 0` baytni qayta ishlang.

</details>

**3.** Node'dagi `pipeline(src, dst)` odati bilan argumentlarni almashtirib yozdik. Bu dastur nima qiladi?
(Kurs papkasida yoʻq, dars uchun alohida ishga tushirilgan.)

```go
package main

import (
	"fmt"
	"io"
	"os"
)

type Hisoblagich struct{ Bayt int64 }

func (h *Hisoblagich) Write(p []byte) (int, error) {
	h.Bayt += int64(len(p))
	return len(p), nil
}

func main() {
	f, _ := os.Open("teskari.go")
	var h Hisoblagich
	io.Copy(f, &h) // Node'dagi pipeline(src, dst) tartibida
	fmt.Println(h.Bayt)
}
```

**A)** faylning baytlarini sanab chiqaradi · **B)** `0` chiqaradi · **C)** build xatosi

<details>
<summary>Javob</summary>

**C: build xatosi.** `io.Copy` ning ikkinchi argumenti `io.Reader` boʻlishi kerak, `*Hisoblagich` da esa `Read`
metodi yoʻq. Go buni ishga tushirishdan oldin toʻxtatadi:

```console
$ go run teskari.go
# command-line-arguments
./teskari.go:19:13: cannot use &h (value of type *Hisoblagich) as io.Reader value in argument to io.Copy: *Hisoblagich does not implement io.Reader (missing method Read)
```

*missing method Read* — «Read metodi yoʻq». «`0`» ni tanlagan boʻlsangiz, Go buni runtime'da topadi deb oʻylagansiz.
Birinchi argument `f` esa xatosiz: `*os.File` da `Write` bor. Tartibni eslab qoling: `io.Copy(dst, src)`.

</details>

**4.** `io.Copy(&h, f)` 1 GiB faylda ~2.5 MiB oldi. `io.Copy(&buf, f)` (`buf` — `bytes.Buffer`) qancha oladi va nega?

<details>
<summary>Javob</summary>

Kamida fayl hajmicha. `bytes.Buffer` baytlarni saqlaydigan Writer, ustiga unda `ReadFrom` bor, va `io.Copy` ishni
unga beradi. Oʻzgarmas xotira — `io.Copy` ning emas, manba va manzilning xususiyati («Chuqurroq» boʻlimi).

</details>

**5.** GO-1.13 dan: `Hisoblagich` `io.Writer` ni bajarishini kompilyatsiya vaqtida qanday tekshirasiz, `implements`
yozmasdan?

<details>
<summary>Javob</summary>

Paket darajasida `var _ io.Writer = (*Hisoblagich)(nil)` yozing. Imzo mos kelmasa (yoki receiver notoʻgʻri boʻlsa),
build shu qatorda toʻxtaydi. `(*Hisoblagich)(nil)` — `*Hisoblagich` turidagi `nil`: xotira ajratilmaydi, faqat tur
tekshiriladi.

</details>

```go filename="homework/orta/orta.go" showLineNumbers
// Package orta — Oʻrta: boshqa Reader'ni oʻrab, Windows qator oxiridagi '\r' baytlarini olib tashlaydigan Reader.
package orta

import "io"

type CRsiz struct{ R io.Reader }

func (c CRsiz) Read(p []byte) (int, error) {
	for {
		n, err := c.R.Read(p) // avval ichki Reader'dan oʻqiymiz
		k := 0
		for _, b := range p[:n] { // '\r' dan boshqa baytlarni chelak boshiga suramiz
			if b != '\r' {
				p[k] = b
				k++
			}
		}
		// Chelakda faqat '\r' boʻlgan boʻlsa, (0, nil) qaytarmaymiz — hujjat buni tavsiya qilmaydi, qayta oʻqiymiz.
		if k > 0 || err != nil || n == 0 {
			return k, err
		}
	}
}
```

Test `iotest.OneByteReader` (har safar bitta bayt) va `iotest.TestReader` bilan tekshiradi.

🟠 Sigʻganini yozing va `ErrToldi` qaytaring. `io.Copy` xatoni koʻrib toʻxtaydi: testda `n=5`, bufer `"salom"`.

```go filename="homework/qiyin/qiyin.go" showLineNumbers
// Package qiyin — Qiyin: N baytdan keyin yozishni rad etadigan Writer.
// Shartnoma: n < len(p) boʻlsa, xato nil boʻlmasligi shart.
package qiyin

import (
	"errors"
	"io"
)

var ErrToldi = errors.New("chegara toʻldi")

type Chekli struct {
	W     io.Writer
	Qoldi int64
}

func (c *Chekli) Write(p []byte) (int, error) {
	if int64(len(p)) <= c.Qoldi {
		n, err := c.W.Write(p)
		c.Qoldi -= int64(n)
		return n, err
	}
	n, err := c.W.Write(p[:c.Qoldi]) // sigʻganini yozamiz
	c.Qoldi -= int64(n)
	if err == nil {
		err = ErrToldi
	}
	return n, err
}
```

🔴 Boʻlak oxirida tugallanmagan rune boʻlsa (`utf8.FullRune` false), uning 1–3 baytini `dum` da keyingi `Write`
gacha saqlang. Bu «`p` ni saqlamang» qoidasini buzmaydi: `append([]byte(nil), b...)` nusxa oladi. Oqim tugaganda
qolgan baytlarni `Close` sanaydi.

```go filename="homework/guru/guru.go" showLineNumbers
// Package guru — Guru: rune'larni sanaydigan Writer. Boʻlak chegarasi rune'ni kesib oʻtsa ham
// toʻgʻri sanaydi: tugallanmagan 1–3 baytni keyingi Write'gacha saqlab turadi.
// Oqim tugaganda dum'da qolgan baytlarni Close sanaydi (buzuq oxir — har bayt bitta RuneError, utf8.RuneCount kabi).
package guru

import "unicode/utf8"

type RuneSanagich struct {
	Rune int64
	dum  []byte // oldingi boʻlakdan qolgan, hali tugallanmagan rune baytlari (≤ 3)
}

func (s *RuneSanagich) Write(p []byte) (int, error) {
	b := p
	if len(s.dum) > 0 {
		b = append(s.dum, p...) // faqat dum boʻlganda nusxa (koʻpi bilan 3 + len(p))
		s.dum = nil
	}
	for len(b) > 0 {
		if !utf8.FullRune(b) { // rune keyingi boʻlakda davom etadi
			s.dum = append([]byte(nil), b...)
			break
		}
		_, size := utf8.DecodeRune(b)
		s.Rune++
		b = b[size:]
	}
	return len(p), nil
}

// Close oqim oxirida qolgan tugallanmagan baytlarni ham sanaydi.
func (s *RuneSanagich) Close() error {
	s.Rune += int64(utf8.RuneCount(s.dum))
	s.dum = nil
	return nil
}
```

Test `iotest.OneByteReader` bilan har bir koʻp baytli rune'ni (`ʻ`, `😀`) albatta kesadi va natijani
`utf8.RuneCountInString` bilan solishtiradi.

</details>
