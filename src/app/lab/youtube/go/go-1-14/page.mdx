## Nimani oʻrganasiz

Bitta dastur Go 1.24.13 da `xato: buyurtma topilmadi` deb yozadi va jim tugaydi. Xuddi shu dastur Go 1.26.8 da
`panic` bilan yiqiladi. Kodda bitta belgi ham oʻzgarmagan. Qaysi versiya toʻgʻri ishlayapti: eskisimi yoki
yangisi? Javobni dars oxirida ochamiz. Avval Go'da xato qanday qiymat ekanini koʻramiz.

**Bitta gʻoya:** Go'da xato — `throw` qilinadigan exception emas, funksiya qaytaradigan oddiy qiymat. Shuning
uchun uni `%w` bilan oʻrab kontekst qoʻshish, `errors.Is` va `errors.AsType` bilan zanjir ichidan topish va
`errors.Join` bilan yigʻish mumkin. Faqat bitta shart bor: xatoni natijani ishlatishdan oldin tekshirish kerak.

Dars oxirida siz:

- `%w` va `%v` farqini bilasiz: xatoga kontekst qoʻsha olasiz va qachon oʻramaslik kerakligini ayta olasiz;
- oʻralgan xatoni `==` bilan emas, `errors.Is` bilan, xato turini esa `errors.AsType` (Go 1.26) bilan tekshira
  olasiz;
- bir nechta xatoni `errors.Join` bilan bitta qiymatga yigʻa olasiz;
- Go 1.25 da birdan paydo boʻlgan nil pointer panic'ini tushuntirib, tuzata olasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| sentinel xato | paket darajasida bir marta yaratilgan, chaqiruvchi solishtiradigan tayyor xato qiymati: `io.EOF`, `sql.ErrNoRows` | sentinel error |
| oʻrash | xatoga kontekst qoʻshib, asl xatoni ichida saqlash: `fmt.Errorf("…: %w", err)` | wrapping |
| xatolar zanjiri | oʻralgan xato → uning ichidagi xato → … ; `Unwrap` bilan qavatma-qavat ochiladi | error chain |

Yoʻl-yoʻlakay ikkita yordamchi soʻz ham uchraydi: **`GOTOOLCHAIN`** (go buyrugʻiga Go'ning qaysi versiyasini
ishlatishni aytadigan oʻzgaruvchi) va kvadrat qavsdagi **type argument** (`errors.AsType[*SummaXato]`). Ikkalasini
kerak boʻlgan joyda tushuntiramiz.

## Xato — oddiy qiymat

Funksiya muvaffaqiyatsiz boʻlishi mumkin: buyurtma topilmadi, summa notoʻgʻri. JS'da bunda `throw`, Python'da
`raise`, PHP'da `throw` qilasiz. Xato funksiyadan alohida yoʻl bilan chiqadi va stek boʻylab yuqoriga, birinchi
mos `catch` / `except` gacha koʻtariladi. Go'da exception yoʻq. Xato — funksiya **qaytaradigan** oddiy qiymat,
odatda oxirgi qaytgan qiymat. Go'ning rasmiy savol-javoblari (Go FAQ) sababini shunday aytadi: exception'ni
try-catch-finally kabi boshqaruv tuzilmasiga bogʻlash *"results in convoluted code"* — «chalkash kodga olib
keladi».

`error` turi Go'ning oʻzida shunday eʼlon qilingan:

```console
$ sed -n 315,319p $(go env GOROOT)/src/builtin/builtin.go
// The error built-in interface type is the conventional interface for
// representing an error condition, with the nil value representing no error.
type error interface {
	Error() string
}
```

`error` — bitta `Error() string` metodli interface ([GO-1.13](/lab/youtube/go/go-1-13)). Shu metodi bor har qanday tur
xato boʻla oladi. `nil` esa «xato yoʻq» degani. Xato odatda oxirgi qaytgan qiymat boʻladi: staticcheck'ning
ST1008 tekshiruvi buni talab qiladi (*"A function's error value should be its last return value"*).

Eng oddiy xatoni `errors.New` yaratadi: u faqat matn saqlaydi. Biz uni paket darajasidagi oʻzgaruvchida
saqlaymiz (`wrap/main.go`, 10–17-qatorlar):

```console
$ sed -n 10,17p wrap/main.go
var ErrTopilmadi = errors.New("buyurtma topilmadi")

func top(id int) error {
	if id != 7 {
		return ErrTopilmadi
	}
	return nil
}
```

`ErrTopilmadi` («buyurtma topilmadi») — paket ishga tushganda bir marta yaratiladigan bitta qiymat. Chaqiruvchi
xatoni aynan shu qiymat bilan solishtiradi. Bunday xato **sentinel xato** (*sentinel error*) deyiladi: standart
kutubxonada `io.EOF` («fayl tugadi») va `sql.ErrNoRows` («qator topilmadi») shunday. Python'dagi
`except TopilmadiError` dan farqi: bu yerda xato sinfi emas, bitta aniq qiymat tekshiriladi.

Xato oddiy qiymat boʻlgani uchun u bilan oddiy kod yozish mumkin: saqlash, solishtirish, oʻrash, yigʻish. Rob
Pike'ning 2015 yilgi maqolasi aynan shu haqida: *"Errors are values. Values can be programmed, and since errors
are values, errors can be programmed."* — «Xatolar — qiymat. Qiymat bilan dasturlash mumkin, demak xatolar bilan
ham».

## %v yoki %w: matn bir xil, ichi har xil

Xato yuqoriga koʻtarilganda unga kontekst kerak boʻladi: qaysi buyurtmada xato boʻldi? Buning uchun
`fmt.Errorf` bor: u `fmt.Sprintf` kabi matn yasaydi, lekin natijani `error` qilib qaytaradi. Asl xatoni matnga
ikki xil qoʻyish mumkin: `%v` yoki `%w`. Kurs papkasidagi `wrap/main.go`:

```go filename="wrap/main.go" showLineNumbers
// wrap: %v xatoni matnga aylantiradi, %w esa asl xatoni ichida saqlaydi.
// go run ./wrap
package main

import (
	"errors"
	"fmt"
)

var ErrTopilmadi = errors.New("buyurtma topilmadi")

func top(id int) error {
	if id != 7 {
		return ErrTopilmadi
	}
	return nil
}

func olishV(id int) error {
	if err := top(id); err != nil {
		return fmt.Errorf("buyurtma %d: %v", id, err) // faqat matn qoladi
	}
	return nil
}

func olishW(id int) error {
	if err := top(id); err != nil {
		return fmt.Errorf("buyurtma %d: %w", id, err) // asl xato ichida
	}
	return nil
}

func main() {
	for _, x := range []struct {
		nom string
		err error
	}{{"oddiy", top(42)}, {"%v", olishV(42)}, {"%w", olishW(42)}} {
		fmt.Printf("%-5s  %-34q ==: %-5v  errors.Is: %v\n",
			x.nom, x.err.Error(), x.err == ErrTopilmadi, errors.Is(x.err, ErrTopilmadi))
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10 | `var ErrTopilmadi = errors.New(…)` | sentinel xato |
| 12–17 | `func top(id int) error` | faqat 7-buyurtma bor; boshqa `id` uchun `ErrTopilmadi` ning oʻzini qaytaradi |
| 19–24 | `func olishV(…)` | xatoga `buyurtma 42: ` kontekstini qoʻshadi, asl xatoni `%v` bilan qoʻyadi |
| 20 | `if err := top(id); err != nil {` | `if` ning qisqa shakli: `err` faqat shu `if` ichida koʻrinadi |
| 21 | `fmt.Errorf("buyurtma %d: %v", id, err)` | `%d` — butun son, `%v` — qiymatning standart koʻrinishi; xato uchun bu `err.Error()` matni |
| 26–31 | `func olishW(…)` | xuddi shunday, faqat `%w` bilan (28-qator) |
| 34–37 | `for _, x := range []struct{…}{…}` | uchta holatdan jadval: nomsiz struct'lar slice'i (`nom` — «nom», `err` — xato), [GO-1.07](/lab/youtube/go/go-1-07) dagi table test kabi |
| 38 | `fmt.Printf("%-5s  %-34q …")` | `%-5s` — chapga tekislangan 5 belgilik joy; `%q` — matnni qoʻshtirnoq ichida chiqaradi |
| 39 | `x.err == ErrTopilmadi`, `errors.Is(x.err, ErrTopilmadi)` | ikki xil tekshiruv: oddiy tenglik va `errors.Is` |

`errors.Is(err, target)` — «`err` ichida qayerdadir `target` bormi?» degan savol. Qanday qidirishini keyingi
boʻlimda ochamiz.

Ishga tushirishdan oldin oʻylab koʻring: `%v` va `%w` qatorlarida `==` va `errors.Is` nima beradi?

**A)** ikkalasida ham `==: true`, chunki ichida oʻsha `ErrTopilmadi` · **B)** ikkalasida `==: false`;
`errors.Is` faqat `%w` da `true` · **C)** ikkalasida `==: false`, `errors.Is` ham ikkalasida `true`, chunki
matnda «buyurtma topilmadi» bor

<details>
<summary>Javob</summary>

**B.** `fmt.Errorf` har doim **yangi** xato qiymatini yaratadi, shuning uchun u `ErrTopilmadi` ga `==` emas.
`%v` asl xatodan faqat matnni oladi, `%w` esa asl xatoning oʻzini ichida saqlaydi. `errors.Is` matnga qaramaydi:
u ichidagi qiymatlarni qidiradi va faqat `%w` da topadi. «A» ni tanlagan boʻlsangiz, `fmt.Errorf` asl xatoni
qaytaradi deb oʻylagansiz. «C» ni tanlagan boʻlsangiz, `errors.Is` matnni solishtiradi deb oʻylagansiz.

</details>

```console
$ go run ./wrap
oddiy  "buyurtma topilmadi"               ==: true   errors.Is: true
%v     "buyurtma 42: buyurtma topilmadi"  ==: false  errors.Is: false
%w     "buyurtma 42: buyurtma topilmadi"  ==: false  errors.Is: true
```

Matn ikkala holatda bir xil: `"buyurtma 42: buyurtma topilmadi"`. Farq ichida. Go blogi buni shunday aytadi:
`fmt.Errorf` bilan yangi xato yaratish *"discards everything from the original error except the text"* — «asl
xatodan matndan boshqa hamma narsani tashlab yuboradi». `%w` (Go 1.13 dan) aynan shuning uchun qoʻshilgan.

Har bir `x.err` interface ichida nima turibdi? Turlarni `%T` bilan chiqaramiz (bu dastur kurs papkasida yoʻq,
alohida ishga tushirildi):

```go
package main

import (
	"errors"
	"fmt"
)

var ErrTopilmadi = errors.New("buyurtma topilmadi")

func main() {
	v := fmt.Errorf("buyurtma 42: %v", ErrTopilmadi)
	w := fmt.Errorf("buyurtma 42: %w", ErrTopilmadi)
	fmt.Printf("oddiy  %T\n", ErrTopilmadi)
	fmt.Printf("%%v     %T\n", v)
	fmt.Printf("%%w     %T\n", w)
}
```

```console
$ go run turlar/main.go
oddiy  *errors.errorString
%v     *errors.errorString
%w     *fmt.wrapError
```

(`%%` — `Printf` da oddiy `%` belgisini chiqaradi.) Endi rasm:

| Satr | interface ichida: tur | interface ichida: qiymat | `== ErrTopilmadi` | `errors.Is` |
|---|---|---|---|---|
| oddiy | `*errors.errorString` | `ErrTopilmadi` ning oʻzi (oʻsha pointer) | `true` | `true` |
| `%v` | `*errors.errorString` | **yangi** pointer, matni `buyurtma 42: …` | `false`: tur bir xil, pointer boshqa | `false`: ichida asl xato yoʻq |
| `%w` | `*fmt.wrapError` | matn + asl xatoga havola | `false`: tur boshqa | `true`: `Unwrap()` asl xatoni beradi |

[GO-1.13](/lab/youtube/go/go-1-13) dagi qoida: ikki interface faqat turi ham, qiymati ham bir xil boʻlsa teng. `%v` da tur
bir xil, lekin qiymat (pointer) yangi. `%w` da tur ham boshqa. Demak **oʻralgan xatoni `==` bilan tekshirib
boʻlmaydi**. Kontekst qoʻshib, asl xatoni ichida saqlash **oʻrash** (*wrapping*) deyiladi: `%w` oʻraydi, `%v`
oʻramaydi.

## Zanjir: errors.Unwrap va errors.Is ichida

Haqiqiy dasturda xato bir necha qavat oʻraladi: ombor → buyurtma → toʻlov. `zanjir/main.go`:

```go filename="zanjir/main.go" showLineNumbers
// zanjir: %w bilan oʻralgan xatolar zanjiri. errors.Unwrap har safar bitta qavatni ochadi.
// go run ./zanjir
package main

import (
	"errors"
	"fmt"
)

var ErrTopilmadi = errors.New("buyurtma topilmadi")

func top(id int) error { return ErrTopilmadi }

func olish(id int) error {
	if err := top(id); err != nil {
		return fmt.Errorf("buyurtma %d: %w", id, err)
	}
	return nil
}

func tolov(id int) error {
	if err := olish(id); err != nil {
		return fmt.Errorf("toʻlov: %w", err)
	}
	return nil
}

func main() {
	err := tolov(42)
	for i, e := 0, err; e != nil; i, e = i+1, errors.Unwrap(e) {
		fmt.Printf("%d  %-20T  %s\n", i, e, e)
	}
	fmt.Println("errors.Is(err, ErrTopilmadi):", errors.Is(err, ErrTopilmadi))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 12 | `func top(id int) error { return ErrTopilmadi }` | har doim sentinel xatoni qaytaradi |
| 14–19 | `func olish(…)` | 1-qavat: `buyurtma 42: ` qoʻshadi, `%w` bilan |
| 21–26 | `func tolov(…)` | 2-qavat: `toʻlov: ` qoʻshadi, yana `%w` bilan |
| 30 | `for i, e := 0, err; e != nil; i, e = i+1, errors.Unwrap(e) {` | ikki oʻzgaruvchili `for`: `e` dan boshlab, har aylanada `errors.Unwrap(e)` bilan bitta qavat pastga tushadi; `e` nil boʻlganda toʻxtaydi |
| 31 | `fmt.Printf("%d  %-20T  %s\n", i, e, e)` | qavat raqami, turi (`%T`) va matni (`%s`) |
| 33 | `errors.Is(err, ErrTopilmadi)` | eng tashqi xatodan qidiradi |

`errors.Unwrap(e)` — agar `e` da `Unwrap() error` metodi boʻlsa, uni chaqiradi va ichidagi xatoni qaytaradi;
boʻlmasa `nil` qaytaradi. `%w` bilan yozilgan har bir `fmt.Errorf` shunday metodli yangi xato yaratadi.

Oʻylab koʻring: sikl necha qator chiqaradi? **A)** 1 · **B)** 2 · **C)** 3

<details>
<summary>Javob</summary>

**C: 3.** Ikki `fmt.Errorf` — ikki oʻram, ularning ichida `ErrTopilmadi` ning oʻzi. Uchinchi qavatda (`ErrTopilmadi`)
`Unwrap` metodi yoʻq, shuning uchun `errors.Unwrap` `nil` qaytaradi va sikl tugaydi. «B» ni tanlagan
boʻlsangiz, eng ichki xatoni sanamagansiz.

</details>

```console
$ go run ./zanjir
0  *fmt.wrapError        toʻlov: buyurtma 42: buyurtma topilmadi
1  *fmt.wrapError        buyurtma 42: buyurtma topilmadi
2  *errors.errorString   buyurtma topilmadi
errors.Is(err, ErrTopilmadi): true
```

Bu — **xatolar zanjiri** (*error chain*):

```text
err ─► 0: *fmt.wrapError      "toʻlov: buyurtma 42: buyurtma topilmadi"
            │ Unwrap()
            ▼
       1: *fmt.wrapError      "buyurtma 42: buyurtma topilmadi"
            │ Unwrap()
            ▼
       2: *errors.errorString "buyurtma topilmadi"   ◄── ErrTopilmadi bilan bir xil qiymat
            │ Unwrap metodi yoʻq
            ▼
          zanjir tugadi (errors.Unwrap → nil)
```

`errors.Is` ham shu zanjir boʻylab yuradi. Uning ichi (`errors/wrap.go`, go1.26.8):

```console
$ sed -n 54,75p $(go env GOROOT)/src/errors/wrap.go
func is(err, target error, targetComparable bool) bool {
	for {
		if targetComparable && err == target {
			return true
		}
		if x, ok := err.(interface{ Is(error) bool }); ok && x.Is(target) {
			return true
		}
		switch x := err.(type) {
		case interface{ Unwrap() error }:
			err = x.Unwrap()
			if err == nil {
				return false
			}
		case interface{ Unwrap() []error }:
			for _, err := range x.Unwrap() {
				if is(err, target, targetComparable) {
					return true
				}
			}
			return false
		default:
```

Har bir qavatda uch qadam:

1. `err == target` — xatoning oʻzini solishtiradi (`targetComparable` — `target` turini `==` bilan solishtirish
   mumkinmi; masalan, ichida slice bor struct'ni mumkin emas).
2. Xatoda oʻzining `Is(error) bool` metodi boʻlsa, uni chaqiradi: tur «men shu xatoga tengman» deb oʻzi hal
   qilishi mumkin.
3. Type switch ([GO-1.13](/lab/youtube/go/go-1-13)): `Unwrap() error` boʻlsa — bitta qavat pastga tushib, siklni
   takrorlaydi; `Unwrap() []error` boʻlsa — har bir tarmoqni alohida tekshiradi (bu `errors.Join` uchun, pastda
   koʻramiz); ikkalasi ham boʻlmasa (`default`) — `false`.

## JS, Python va PHP bilan solishtiramiz

Boshqa tillarda ham xatoni oʻrash bor. Uchta bir xil dastur: ichki funksiya «topilmadi» xatosini tashlaydi,
tashqi kod uni kontekst bilan oʻraydi va qayta tashlaydi. Bu fayllar kurs papkasida yoʻq, alohida ishga
tushirildi (Node.js 24, Python 3.13, PHP 8.4).

```js
class TopilmadiError extends Error {}

function top(id) {
  throw new TopilmadiError("buyurtma topilmadi");
}

try {
  try {
    top(42);
  } catch (e) {
    throw new Error(`buyurtma 42: ${e.message}`, { cause: e });
  }
} catch (e) {
  console.log(e.message);
  console.log("instanceof:      ", e instanceof TopilmadiError);
  console.log("cause instanceof:", e.cause instanceof TopilmadiError);
}
```

```python
class TopilmadiError(Exception):
    pass

def top(id):
    raise TopilmadiError("buyurtma topilmadi")

try:
    try:
        top(42)
    except TopilmadiError as e:
        raise RuntimeError(f"buyurtma 42: {e}") from e
except TopilmadiError:
    print("except TopilmadiError ishladi")
except RuntimeError as e:
    print("except RuntimeError:", e)
    print("__cause__:", type(e.__cause__).__name__)
```

```php
<?php
class TopilmadiException extends Exception {}

function top($id) {
    throw new TopilmadiException("buyurtma topilmadi");
}

try {
    try {
        top(42);
    } catch (TopilmadiException $e) {
        throw new RuntimeException("buyurtma 42: " . $e->getMessage(), 0, $e);
    }
} catch (TopilmadiException $e) {
    echo "catch TopilmadiException ishladi\n";
} catch (RuntimeException $e) {
    echo "catch RuntimeException: ", $e->getMessage(), "\n";
    echo "getPrevious: ", get_class($e->getPrevious()), "\n";
}
```

```console
$ node wrap.js
buyurtma 42: buyurtma topilmadi
instanceof:       false
cause instanceof: true
$ python3 wrap.py
except RuntimeError: buyurtma 42: buyurtma topilmadi
__cause__: TopilmadiError
$ php wrap.php
catch RuntimeException: buyurtma 42: buyurtma topilmadi
getPrevious: TopilmadiException
```

Uchala tilda asl xato saqlanadi (`cause`, `__cause__`, `getPrevious()`), lekin `instanceof`, `except` va
`catch` faqat **eng tashqi** xatoga qaraydi. Oʻragandan keyin «topilmadi» ni ushlamoqchi boʻlsangiz, zanjirni
qoʻlda yurishingiz kerak.

| | Oʻrash | Bitta qavat ichiga | Zanjirdan qidirish |
|---|---|---|---|
| JS / TS | `new Error(msg, { cause: e })` (ES2022) | `e.cause` | qoʻlda: `instanceof` faqat tashqi xatoni tekshiradi |
| Python | `raise … from e` | `e.__cause__` | qoʻlda: `except` faqat tashqi xatoni ushlaydi |
| PHP | `new RuntimeException($msg, 0, $e)` | `$e->getPrevious()` | qoʻlda: `catch` faqat tashqi xatoni ushlaydi |
| Go | `fmt.Errorf("…: %w", err)` | `errors.Unwrap(err)` | `errors.Is`, `errors.AsType` butun zanjirni yuradi |

Go'da farq ikki joyda. Birinchidan, xato stek boʻylab oʻzi «uchib» ketmaydi: u qaytgan qiymat, va har bir
chaqiruvchi `if err != nil` bilan uni ochiq koʻradi. Ikkinchidan, tekshiruv (`errors.Is`) zanjirni oʻzi yuradi,
shuning uchun oʻrta qavatda kontekst qoʻshish chaqiruvchining tekshiruvini buzmaydi.

## Qachon oʻramaslik kerak

Har bir xatoni `%w` bilan oʻrash shart emas. Go blogining «Working with Errors in Go 1.13» maqolasi ogohlantiradi:
*"wrapping an error makes that error part of your API"* — «xatoni oʻrasangiz, u paketingiz API'sining bir qismiga
aylanadi».

Misol: `BuyurtmaTop` funksiyangiz PostgreSQL'dan oʻqiydi va `database/sql` ning `sql.ErrNoRows` xatosini `%w`
bilan oʻraydi. Chaqiruvchi kod endi `errors.Is(err, sql.ErrNoRows)` deb yozadi va sizning SQL ishlatishingizga
bogʻlanib qoladi. Ertaga omborni boshqa tizimga almashtirsangiz, `sql.ErrNoRows` endi qaytmaydi, va ularning kodi
jim buziladi.

Ichki tafsilotni yashirmoqchi boʻlsangiz, `%v` ishlating. Maqola aytganidek, *"whether you wrap or not, the error
text will be the same"* — «oʻrasangiz ham, oʻramasangiz ham, xato matni bir xil». Uber'ning Go style guide'i ham
shunday tavsiya qiladi: chaqiruvchi asl xatoga muhtoj boʻlsa `%w`, yashirish kerak boʻlsa `%v`.

| Holat | Nima yozish kerak |
|---|---|
| chaqiruvchi asl xatoni tekshirishi kerak (sizning `ErrTopilmadi` ingiz) | `fmt.Errorf("buyurtma %d: %w", id, err)` |
| asl xato — ichki tafsilot (`sql.ErrNoRows`, uchinchi tomon kutubxonasi xatosi) | `fmt.Errorf("buyurtma %d: %v", id, err)` |

## errors.As va errors.AsType: xato ichidan oʻz turingizni olish

Sentinel xato «nima boʻldi» degan savolga javob beradi. Lekin baʼzan xato ichidagi **maʼlumot** kerak: summa
qancha edi? Buning uchun oʻz xato turimizni yozamiz: `SummaXato`, ichida `Summa` maydoni bor.
Python'da bu `except SummaError as e: print(e.summa)`, JS'da
`if (e instanceof SummaError) console.log(e.summa)` boʻlardi. Go'da bunga ikki funksiya bor. `astype/main.go`:

```go filename="astype/main.go" showLineNumbers
// astype: oʻralgan xatodan oʻz turimizni olish. errors.As (Go 1.13) va errors.AsType (Go 1.26).
// go run ./astype
package main

import (
	"errors"
	"fmt"
)

type Buyurtma struct {
	ID    int
	Summa int64
}

type SummaXato struct{ Summa int64 }

func (e *SummaXato) Error() string { return fmt.Sprintf("summa notoʻgʻri: %d", e.Summa) }

func saqla(b Buyurtma) error {
	if b.Summa <= 0 {
		return fmt.Errorf("buyurtma %d: %w", b.ID, &SummaXato{Summa: b.Summa})
	}
	return nil
}

func main() {
	err := saqla(Buyurtma{ID: 9, Summa: -5})
	fmt.Println("err:", err)

	// eski usul (Go 1.13): avval oʻzgaruvchi, keyin uning manzili
	var sx *SummaXato
	if errors.As(err, &sx) {
		fmt.Println("As:     summa =", sx.Summa)
	}

	// yangi usul (Go 1.26): tur qavs ichida, natija qaytadi
	if sx, ok := errors.AsType[*SummaXato](err); ok {
		fmt.Println("AsType: summa =", sx.Summa)
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 15 | `type SummaXato struct{ Summa int64 }` | oʻz xato turimiz, bitta maydon |
| 17 | `func (e *SummaXato) Error() string` | **pointer receiver** bilan yozilgan: `error` ni faqat `*SummaXato` bajaradi ([GO-1.12](/lab/youtube/go/go-1-12)) |
| 19–24 | `func saqla(…)` | summa ≤ 0 boʻlsa, `&SummaXato{…}` ni `%w` bilan oʻrab qaytaradi |
| 31 | `var sx *SummaXato` | `errors.As` uchun boʻsh (nil) pointer oʻzgaruvchi |
| 32 | `errors.As(err, &sx)` | zanjirni yuradi; `*SummaXato` topsa, uni `sx` ga yozadi va `true` qaytaradi. Shuning uchun `sx` ning **manzili** (`&sx`) beriladi |
| 37 | `sx, ok := errors.AsType[*SummaXato](err)` | `[*SummaXato]` — qidirilayotgan tur. Natija va `ok` qaytadi; `sx` faqat shu `if` ichida |

`errors.As` Go 1.13 dan beri bor. `errors.AsType` esa Go 1.26 da qoʻshildi. Kvadrat qavs ichidagi tur — **type
argument**: funksiyaga qiymat emas, tur beriladi (bu generics, uni [GO-1.17](/lab/youtube/go/go-1-17) da ochamiz).
`AsType` eʼloni `func AsType[E error](err error) (E, bool)`: `E` istalgan tur boʻlishi mumkin, faqat u `error` ni
bajarishi shart. `sx, ok := …` shakli [GO-1.13](/lab/youtube/go/go-1-13) dagi type assertion `err.(*SummaXato)` ga
oʻxshaydi. Farqi: type assertion faqat eng tashqi qiymatga qaraydi, `AsType` esa butun zanjirni yuradi.

```console
$ go run ./astype
err: buyurtma 9: summa notoʻgʻri: -5
As:     summa = -5
AsType: summa = -5
```

Ikkalasi bir xil natija berdi: `SummaXato` `buyurtma 9: ` oʻrami ichida boʻlsa ham topildi. Unda yangi funksiya
nimaga kerak? Go 1.26 reliz yozuvlari: *"The new AsType function is a generic version of As. It is type-safe,
faster, and, in most cases, easier to use."* — «tur jihatdan xavfsiz, tezroq va koʻp hollarda qulayroq».
Keyingi ikki boʻlimda «type-safe» va «faster» ni tekshiramiz.

## Type-safe: adashsangiz kim ushlaydi?

Farq dasturchi adashganda koʻrinadi. `asxato/` da `errors.As` ga `&` unutilgan:

```console
$ sed -n 18p asxato/main.go
	if errors.As(err, sx) { // & yoʻq
```

Qolgani `astype/` bilan bir xil: `err` — oʻralgan `*SummaXato`, `sx` — `var sx *SummaXato`. Nima boʻladi?

**A)** kompilyatsiya xatosi · **B)** kompilyatsiya boʻladi, ishlaganda panic · **C)** ishlaydi, `errors.As`
shunchaki `false` qaytaradi

<details>
<summary>Javob</summary>

**B.** `errors.As` ning eʼloni `func As(err error, target any) bool`: ikkinchi parametr `any`, yaʼni istalgan
qiymat. Kompilyator hech narsani rad etmaydi. `As` dastur ishlaganda tekshiradi: `target` nil boʻlmagan pointer
boʻlishi kerak, `sx` esa nil — panic. «A» ni tanlagan boʻlsangiz, kompilyator `any` ichiga nima kirishini
tekshiradi deb oʻylagansiz. «C» ni tanlagan boʻlsangiz, notoʻgʻri argument jim `false` beradi deb oʻylagansiz.

</details>

`2>&1 | head -1` panic xabarining faqat birinchi qatorini koʻrsatadi:

```console
$ go run ./asxato 2>&1 | head -1

```

*target must be a non-nil pointer* — «target nil boʻlmagan pointer boʻlishi kerak». Buni kompilyator emas,
`go vet` ushlaydi (uning `errorsas` tekshiruvi):


«`errors.As` ning ikkinchi argumenti nil boʻlmagan pointer boʻlishi kerak: yoki `error` ni bajaradigan turga, yoki
istalgan interface turiga». `go test` ham bu tekshiruvni avtomatik ishga tushiradi: `go help test` ga koʻra, test
oldidan `go vet` ning ishonchli qismi ishlaydi (*"atomic, bool, buildtags, directive, errorsas, …"*). Lekin `go run`
va `go build` uni ishga tushirmaydi.

Endi `errors.AsType` da adashamiz. `astypexato/` da tur yulduzchasiz yozilgan:

```console

```

`-o /dev/null` tayyor faylni saqlamaydi: bizga faqat kompilyatsiya natijasi kerak.


*SummaXato does not satisfy error (method Error has pointer receiver)* — «`SummaXato` `error` ni bajarmaydi
(`Error` metodi pointer receiver bilan yozilgan)». Bu [GO-1.12](/lab/youtube/go/go-1-12) dagi method set qoidasi:
`SummaXato` qiymatining method set'ida `Error` yoʻq. `AsType[E error]` cheklovi buni kompilyatsiya paytida
tekshiradi, dastur ishga tushmaydi ham.

| Adashish | `errors.As` | `errors.AsType` |
|---|---|---|
| pointer oʻrniga boshqa narsa | kompilyatsiya boʻladi → ishlaganda panic; `go vet` / `go test` topadi | bunday argument yoʻq: natija qaytadi |
| `error` ni bajarmaydigan tur | kompilyatsiya boʻladi → panic; `go vet` topadi | kompilyatsiya xatosi |

Cheklovning ikki chegarasi bor (README'dan; misol kurs papkasida yoʻq, alohida ishga tushirildi). `error` ni
bajaradigan, lekin zanjirda yoʻq tur (`*os.PathError`) kompilyatsiya boʻladi va shunchaki `ok == false` beradi.
`error` dan tashqari metod talab qiladigan interface'ni esa `interface{ error; … }` deb yozish kerak:

```go
package main

import (
	"errors"
	"fmt"
	"os"
)

type SummaXato struct{ Summa int64 }

func (e *SummaXato) Error() string { return fmt.Sprintf("summa notoʻgʻri: %d", e.Summa) }

func main() {
	err := fmt.Errorf("buyurtma 9: %w", &SummaXato{Summa: -5})

	// error'ni bajaradi, lekin zanjirda yoʻq: kompilyatsiya boʻladi, ok = false
	_, ok := errors.AsType[*os.PathError](err)
	fmt.Println("*os.PathError:", ok)

	// error'ga qoʻshimcha metod talab qiladigan interface
	_, ok = errors.AsType[interface {
		error
		Timeout() bool
	}](err)
	fmt.Println("Timeout():", ok)
}
```

```console
$ go run chegara/main.go
*os.PathError: false
Timeout(): false
```

`error` siz interface esa rad etiladi (`errors.As` uni qabul qilardi):

```go
package main

import (
	"errors"
	"fmt"
)

func main() {
	err := fmt.Errorf("ulanish: %w", errors.New("vaqt tugadi"))
	_, ok := errors.AsType[interface{ Timeout() bool }](err)
	fmt.Println(ok)
}
```

```console
$ go run chegara2/main.go
# command-line-arguments
chegara2/main.go:10:25: interface{Timeout() bool} does not satisfy error (missing method Error)
```

*missing method Error* — «`Error` metodi yoʻq». Tuzatish: `AsType[interface{ error; Timeout() bool }]`.

## errors.Join: bir nechta xato bitta qiymatda

Baʼzan xato bitta emas. Buyurtmani tekshirsak, summa ham notoʻgʻri, manzil ham boʻsh. Birinchi xatoda toʻxtasak,
foydalanuvchi ikkinchisini faqat keyingi urinishda biladi. Go 1.20 dan beri `errors.Join` bir nechta xatoni bitta
`error` ga yigʻadi. `join/main.go`:

```go filename="join/main.go" showLineNumbers
// join: bir nechta xatoni bitta error'ga yigʻish (Go 1.20).
// go run ./join
package main

import (
	"errors"
	"fmt"
)

type Buyurtma struct {
	Summa  int64
	Manzil string
}

type SummaXato struct{ Summa int64 }

func (e *SummaXato) Error() string { return fmt.Sprintf("summa notoʻgʻri: %d", e.Summa) }

var ErrManzilYoq = errors.New("manzil boʻsh")

func tekshir(b Buyurtma) error {
	var summaXato, manzilXato error // turi error: typed nil boʻlmaydi
	if b.Summa <= 0 {
		summaXato = &SummaXato{Summa: b.Summa}
	}
	if b.Manzil == "" {
		manzilXato = ErrManzilYoq
	}
	return errors.Join(summaXato, manzilXato)
}

func main() {
	err := tekshir(Buyurtma{Summa: -5})
	fmt.Println(err)
	fmt.Println("manzil xatosi bormi:", errors.Is(err, ErrManzilYoq))
	if sx, ok := errors.AsType[*SummaXato](err); ok {
		fmt.Println("summa xatosi:", sx.Summa)
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 19 | `var ErrManzilYoq = errors.New("manzil boʻsh")` | yana bir sentinel xato («manzil yoʻq») |
| 22 | `var summaXato, manzilXato error` | ikkala oʻzgaruvchi **`error` turida**, boshida `nil`. Nega bu muhim — pauzadagi savolda |
| 23–28 | ikki `if` | har bir muammo uchun oʻz xatosi |
| 29 | `errors.Join(summaXato, manzilXato)` | `Join(errs ...error) error`: variadic, nil boʻlmaganlarini bitta xatoga yigʻadi |
| 33 | `tekshir(Buyurtma{Summa: -5})` | summa −5, manzil boʻsh: ikkala xato |
| 35–38 | `errors.Is`, `errors.AsType` | yigʻilgan xato ichidan har birini qidiradi |

`Join` ning matni — xatolar matnlari, har biri alohida qatorda. Ichida esa `Unwrap() []error` metodli xato bor:

```text
err ─► *errors.joinError
          │ Unwrap() []error
          ├──► *SummaXato      "summa notoʻgʻri: -5"   ◄── errors.AsType[*SummaXato] topadi
          └──► ErrManzilYoq    "manzil boʻsh"          ◄── errors.Is(err, ErrManzilYoq) topadi
```

Zanjir endi chiziq emas, daraxt. `errors.Is` ichida koʻrgan `case interface{ Unwrap() []error }` shu holat uchun:
har bir tarmoq alohida tekshiriladi. `errors.AsType` ham shunday. Shu versiyadan (Go 1.20) beri `fmt.Errorf` ham
bir nechta `%w` qabul qiladi: `fmt.Errorf("saqlash: %w; %w", ErrDisk, ErrLog)` (uy vazifasidagi oʻrta masala).

Python 3.11 da bunga yaqin narsa bor: `ExceptionGroup` va `except*` (JS'da `AggregateError`). Taqqoslash uchun
(kurs papkasida yoʻq, alohida ishga tushirildi):

```python
class SummaError(Exception):
    pass

class ManzilError(Exception):
    pass

try:
    raise ExceptionGroup("buyurtma", [SummaError("summa: -5"), ManzilError("manzil boʻsh")])
except* ManzilError as g:
    print("manzil:", g.exceptions)
except* SummaError as g:
    print("summa:", g.exceptions)
```

```console
$ python3 join.py
manzil: (ManzilError('manzil boʻsh'),)
summa: (SummaError('summa: -5'),)
```

Python'da guruh tashlanadi va har bir `except*` oʻz turini guruh ichidan ajratib oladi. Go'da guruh oddiy qaytgan
qiymat, `errors.Is` va `errors.AsType` uning ichiga qaraydi.

## Pauza: errors.Join(nil, nil) nil'ga tengmi?

```go

fmt.Println("err == nil:", err == nil)
```

Ishora: `Join` nil'larni qanday aniqlaydi? **A)** `true` · **B)** `false`: `Join` boʻsh `joinError` qaytaradi ·
**C)** panic

<details>
<summary>Javob</summary>

**A: `true`.** `Join` avval nil boʻlmagan xatolarni sanaydi. Hech biri boʻlmasa, toʻgʻridan-toʻgʻri `nil`

boʻlsangiz, bu aynan typed nil tuzogʻi boʻlardi: Go jamoasi uni `Join` ichida chetlab oʻtgan.

</details>

`savol/main.go`:

Lekin `Join` faqat `err != nil` ni tekshiradi. Typed nil esa ([GO-1.13](/lab/youtube/go/go-1-13)) `nil` ga teng **emas**:
`error` ichidagi nil `*SummaXato` `Join` uchun haqiqiy xato boʻlib koʻrinadi. Shuning uchun `join/main.go` ning

## Jumboqqa qaytamiz: Go 1.25 va nil tekshiruvi

Endi boshidagi dastur. Toʻliq `tartib/main.go`:

```go filename="tartib/main.go" showLineNumbers
// tartib: natija err tekshirilmasdan OLDIN ishlatiladi. ATAYLAB XATO.
// Go 1.21.5–1.24 kompilyatori nil tekshiruvini kechiktirib yuborardi (golang/go#72860;
// bug CL 537775 bilan 1.21.5 ga backport qilingan, #63743),
// shuning uchun bu dastur u versiyalarda jim ishlaydi. Go 1.21.4 gacha va 1.25+ da panic.
// ./versiyalar.sh
package main

import (
	"errors"
	"fmt"
)

type Buyurtma struct {
	ID    int
	Summa int64
}

var ErrTopilmadi = errors.New("buyurtma topilmadi")

func top(id int) (*Buyurtma, error) {
	if id != 7 {
		return nil, ErrTopilmadi
	}
	return &Buyurtma{ID: 7, Summa: 150000}, nil
}

func main() {
	b, err := top(42)
	summa := b.Summa // XATO: err hali tekshirilmagan, b esa nil
	if err != nil {
		fmt.Println("xato:", err)
		return
	}
	fmt.Println("summa:", summa)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 20–25 | `func top(id int) (*Buyurtma, error)` | 7-buyurtma boʻlsa — pointer va `nil`; boshqa `id` uchun — `nil, ErrTopilmadi` |
| 28 | `b, err := top(42)` | `b` — nil, `err` — `ErrTopilmadi` |
| 29 | `summa := b.Summa` | nil pointer orqali maydonni oʻqish. Go spec (Selectors): *"If x is of pointer type and has the value nil and x.f denotes a struct field, assigning to or evaluating x.f causes a run-time panic."* — panic boʻlishi **shart** |
| 30–33 | `if err != nil { … return }` | xato tekshiruvi — kech: 29-qatordan keyin |

Modulning `go.mod` i alohida, `go 1.20` qatori bilan: shunda eski Go versiyalari ham bu papkani ishga tushira
oladi:

```text
module tartib

go 1.20
```

`tartib/versiyalar.sh` bitta dasturni olti Go versiyasida ishga tushiradi:

```bash
#!/usr/bin/env bash
# Bitta dasturni olti xil Go versiyasida ishga tushiradi.
# GOTOOLCHAIN kerakli versiyani proxy.golang.org dan yuklab oladi (birinchi marta).
cd "$(dirname "$0")"
for v in go1.20.14 go1.21.4 go1.21.5 go1.24.13 go1.25.0 local; do
  out=$(GOTOOLCHAIN=$v go run -trimpath . 2>&1 | grep -v '^go: downloading' | head -1)
  [ "$v" = local ] && v=$(go env GOVERSION)
  printf '%-10s %s\n' "$v" "$out"
done
```

Har bir versiya uchun `go run` natijasining birinchi qatori olinadi (`go: downloading` qatorlari tashlanadi).
`GOTOOLCHAIN=local` — kompyuterdagi Go'ning oʻzi; uning versiyasini `go env GOVERSION` beradi.

```console
$ ./tartib/versiyalar.sh

go1.21.4   panic: runtime error: invalid memory address or nil pointer dereference
go1.21.5   xato: buyurtma topilmadi
go1.24.13  xato: buyurtma topilmadi
go1.25.0   panic: runtime error: invalid memory address or nil pointer dereference
go1.26.8   panic: runtime error: invalid memory address or nil pointer dereference
```

Go 1.21.4 gacha — panic. Go 1.21.5 dan Go 1.24 gacha — panic'siz. Go 1.25 dan — yana panic. Demak jumboqning
javobi: **Go 1.26 toʻgʻri ishlayapti**, Go 1.24 esa notoʻgʻri ishlagan.

Nima boʻlgan? `b.Summa` ni oʻqishdan oldin kompilyator yashirin **nil tekshiruvi** qoʻyadi: «`b` nil boʻlsa —
panic». Bu sizning `if` ingiz emas, kompilyator oʻzi qoʻshadigan mashina tekshiruvi. Go 1.21.5–1.24 dagi bug shu
tekshiruvni `if err != nil` dan **keyinga** surib yuborgan. `err` nil boʻlmagani uchun dastur `return` bilan
chiqib ketadi va kechiktirilgan tekshiruvgacha yetmaydi.

| Qadam | Spec boʻyicha (≤ 1.21.4, ≥ 1.25) | Bug bilan (1.21.5 … 1.24) |
|---|---|---|
| 1 | `b, err := top(42)` → `b = nil` | `b, err := top(42)` → `b = nil` |
| 2 | nil tekshiruvi: `b == nil` → **panic**, 29-qator | `if err != nil` → `true` |
| 3 | — | `xato: buyurtma topilmadi`, `return` |
| 4 | — | nil tekshiruvi bu yerda turardi, lekin unga hech qachon yetilmaydi |

Go 1.25 reliz yozuvlari: kompilyator *"incorrectly delayed the nil check until after the error check"* —
«nil tekshiruvini xato tekshiruvidan keyinga notoʻgʻri kechiktirgan». Tuzatish — CL 657715 (CL — Go'dagi bitta kod oʻzgarishi, pull request kabi; *"cmd/compile: don't
move nilCheck operations during tighten"*).

Bir aniqlik: reliz yozuvlari bug *"introduced in Go 1.21"* deydi. Oʻlchovda go1.21.0, 1.21.1,
1.21.3 va 1.21.4 hali panic beradi (reliz yozuvlaridagi `os.Open` misoli ham). Bug go1.21.5 dan boshlanadi.
Sababi: bug'ni keltirib chiqargan CL 537775 (Ian Lance Taylor #72860 da koʻrsatgan) 1.21 ga keyinroq backport
qilingan (eski versiya tarmogʻiga koʻchirilgan): #63743, milestone Go1.21.5.

Qoida oddiy: **xatoni darhol, natijani ishlatishdan oldin tekshiring.**

## Go 1.25 eski kodni sindirdimi?

Bir qarashda — ha: Go 1.24 da ishlagan dastur Go 1.25 da yiqiladi. Lekin reliz yozuvlari (ulardagi misol — `os.Open` va `f.Name()`, xuddi shu shakl) aniq aytadi: *"This
program is incorrect because it uses the result of os.Open before checking the error"* — dastur oldin ham

want a point release to break anyone's (even incorrect) code without a very compelling reason."* — «Shu bug'li
xulqqa tayanadigan kod topdik. Tuzatish versiyasi hech kimning (hatto notoʻgʻri) kodini jiddiy sababsiz

## Xulosa: xato qoidalari

| Vazifa | Yozuv | Nega |
|---|---|---|
| kontekst qoʻshib oʻrash | `fmt.Errorf("buyurtma %d: %w", id, err)` | matn + asl xato ichida qoladi |
| tafsilotni yashirish | `fmt.Errorf("buyurtma %d: %v", id, err)` | matn bir xil, chaqiruvchi ichki xatoga bogʻlanmaydi |
| sentinel'ni tekshirish | `errors.Is(err, ErrTopilmadi)`, `==` emas | `==` oʻralgan xatoda doim `false` |
| xato turini olish | `sx, ok := errors.AsType[*SummaXato](err)` | kompilyator tekshiradi, ~8× tez, ajratish yoʻq |
| bir nechta xato | `errors.Join(a, b)` | nil'larni tashlaydi; `Is`/`AsType` har birini koʻradi |
| natijani ishlatish | `v, err := f(); if err != nil { … }` — keyin `v` | Go 1.25 dan bu yoʻl bilan yozilmagan kod panic beradi |

## Koʻp uchraydigan xatolar

**1. Oʻralgan xatoni `==` bilan tekshirish.** Bu mavzuning eng keng tarqalgan xatosi. Kod oldin
`if err == ErrTopilmadi` bilan ishlagan, keyin kimdir oʻrta qavatda `fmt.Errorf("…: %w", err)` qoʻshgan, va
tekshiruv jim `false` bera boshlagan. Xato xabari yoʻq: shunchaki notoʻgʻri yoʻlga oʻtiladi. «%v yoki %w»
boʻlimidagi jadvalda koʻrdik: `==: false`, `errors.Is: true`. **Tuzatish:** sentinel xatoni doim
`errors.Is(err, ErrTopilmadi)` bilan tekshiring, xato turini esa type assertion bilan emas, `errors.AsType`
bilan oling.

**2. Natijani xatodan oldin ishlatish.** «Jumboqqa qaytamiz» boʻlimidagi `tartib/main.go`: `summa := b.Summa`
`if err != nil` dan oldin. Go 1.21.5–1.24 da jim ishlaydi, Go 1.25 dan panic beradi:
`panic: runtime error: invalid memory address or nil pointer dereference` — «notoʻgʻri xotira manzili yoki nil
pointer boʻyicha qiymatga borish», `tartib/main.go:29`. **Tuzatish:** `if err != nil` ni chaqiruvdan keyingi
birinchi qator qiling, natijani faqat undan keyin oʻqing.

**3. `errors.As` ga `&` ni unutish.** «Type-safe» boʻlimida koʻrdik: kompilyatsiya boʻladi, ishlaganda
`panic: errors: target must be a non-nil pointer`. **Tuzatish:** `errors.As(err, &sx)`, yoki yaxshisi
`errors.AsType[*SummaXato](err)` — u bunday xatoga yoʻl qoʻymaydi.

**4. `%w` ga xatoning oʻrniga matn berish.** `err.Error()` ni `%w` ga berish oson adashish. (Bu misol kurs
papkasida yoʻq, alohida ishga tushirildi.)

```go
package main

import (
	"errors"
	"fmt"
)

var ErrTopilmadi = errors.New("buyurtma topilmadi")

func main() {
	err := fmt.Errorf("buyurtma 42: %w", ErrTopilmadi.Error())
	fmt.Println(err)
	fmt.Println(errors.Is(err, ErrTopilmadi))
}
```

```console
$ go run wxato/main.go
buyurtma 42: %!w(string=buyurtma topilmadi)
false
```

Kompilyator jim: `fmt.Errorf` ning argumentlari `...any`. Ishlaganda `fmt` notoʻgʻri argumentni
`%!w(string=…)` deb yozadi, `errors.Is` esa `false`. `go vet` buni topadi (va `go test` uni avtomatik ishga
tushiradi, chunki `printf` tekshiruvi ham oʻsha ishonchli qismda):

```console
$ go vet wxato/main.go
wxato/main.go:11:34: fmt.Errorf format %w has arg ErrTopilmadi.Error() of wrong type string
```

11-qator, 34-ustun: *format %w has arg … of wrong type string* — «`%w` formatiga `string` turidagi notoʻgʻri
argument berilgan». **Tuzatish:** `%w` ga xatoning oʻzini bering: `fmt.Errorf("buyurtma 42: %w", ErrTopilmadi)`.

**5. Ichki tafsilotni `%w` bilan tashqariga chiqarish.** Jim muammo: kod ishlaydi, lekin chaqiruvchilar
sizning `sql.ErrNoRows` ingizga bogʻlanib qoladi («Qachon oʻramaslik kerak» boʻlimi). **Tuzatish:** API
chegarasida `%v` ishlating yoki oʻz sentinel xatongizni qaytaring.

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** `%w` va `%v` farqi nima? Qachon qaysi birini ishlatasiz?

<details>
<summary>Javob</summary>

Ikkalasi bir xil matn beradi. `%v` asl xatodan faqat matnni oladi, `%w` esa asl xatoning oʻzini ichida saqlaydi
(`Unwrap` metodli `*fmt.wrapError`). Chaqiruvchi asl xatoni tekshirishi kerak boʻlsa — `%w`; ichki tafsilotni
yashirish kerak boʻlsa — `%v`, chunki oʻralgan xato API'ning bir qismiga aylanadi.

</details>

**2.** Nega oʻralgan xatoda `err == ErrTopilmadi` `false`, `errors.Is` esa `true`?

<details>
<summary>Javob</summary>

`fmt.Errorf` yangi xato qiymatini yaratadi: interface ichida endi boshqa tur (`*fmt.wrapError`) turibdi, ikki
interface esa faqat turi ham, qiymati ham bir xil boʻlsa teng. `errors.Is` esa zanjir boʻylab `Unwrap` bilan
pastga tushadi va har qavatni `target` bilan solishtiradi.

</details>

**3.** Bu kod nima chiqaradi? **A)** `true true true` · **B)** `true false true` · **C)** `true false false`

```go
a := fmt.Errorf("buyurtma 42: %w", ErrTopilmadi)
b := fmt.Errorf("toʻlov: %v", a)
c := fmt.Errorf("toʻlov: %w", a)
fmt.Println(errors.Is(a, ErrTopilmadi), errors.Is(b, ErrTopilmadi), errors.Is(c, ErrTopilmadi))
```

<details>
<summary>Javob</summary>

**B: `true false true`.** `a` — oddiy oʻram. `b` da `%v` zanjirni uzdi: ichida faqat matn qoldi, garchi `a` ning
oʻzi oʻralgan boʻlsa ham. `c` da ikki qavat `%w`, `errors.Is` ikkalasini ham ochadi. «A» ni tanlagan boʻlsangiz,
bir marta `%w` bilan oʻralgan xato keyin ham «oʻralgan» boʻlib qoladi deb oʻylagansiz: zanjirdagi bitta `%v`
hammasini uzadi.

Toʻliq dastur (kurs papkasida yoʻq, alohida ishga tushirildi):

```go
package main

import (
	"errors"
	"fmt"
)

var ErrTopilmadi = errors.New("buyurtma topilmadi")

func main() {
	a := fmt.Errorf("buyurtma 42: %w", ErrTopilmadi)
	b := fmt.Errorf("toʻlov: %v", a)
	c := fmt.Errorf("toʻlov: %w", a)
	fmt.Println(errors.Is(a, ErrTopilmadi), errors.Is(b, ErrTopilmadi), errors.Is(c, ErrTopilmadi))
}
```

```console
$ go run savol2/main.go
true false true
```

</details>

**4.** `errors.As(err, sx)` (`&` yoʻq) va `errors.AsType[SummaXato](err)` (`*` yoʻq): qaysi xato qachon
ushlanadi?

<details>
<summary>Javob</summary>

`errors.As` ning ikkinchi parametri `any`, shuning uchun birinchisi kompilyatsiya boʻladi va faqat ishlaganda
panic beradi; uni `go vet` (va `go test`) topadi. Ikkinchisini kompilyator darhol rad etadi:
`SummaXato does not satisfy error (method Error has pointer receiver)`.

</details>

**5.** `errors.Join(nil, nil) == nil` nima beradi? `errors.Join` ga nil `*SummaXato` saqlagan `error` berilsa-chi?

<details>
<summary>Javob</summary>

Birinchisi `true`: `Join` nil boʻlmaganlarni sanaydi va hech biri boʻlmasa aniq `nil` qaytaradi. Ikkinchisida
typed nil `err != nil` tekshiruvidan oʻtadi, `Join` uni haqiqiy xato deb saqlaydi va natija `nil` emas.

</details>

**6.** [GO-1.12](/lab/youtube/go/go-1-12) dan: nega `SummaXato` (yulduzchasiz) `error` ni bajarmaydi, `*SummaXato` esa
bajaradi?

<details>
<summary>Javob</summary>

`Error` metodi pointer receiver bilan yozilgan: `func (e *SummaXato) Error()`. Pointer receiver'li metodlar faqat
`*SummaXato` ning method set'iga kiradi. `SummaXato` qiymatining method set'ida `Error` yoʻq, demak u `error`
interface'ini bajarmaydi.

</details>
