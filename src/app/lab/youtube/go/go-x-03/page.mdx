## Nimani oʻrganasiz

`config.json` da bitta ortiqcha vergul qoldi. Node'dagi xizmat ishga tushmaydi va `SyntaxError` bilan yiqiladi.
Go'dagi xuddi shu xizmat esa `listening on :0` deb yozadi va ishlayveradi, lekin 8080-portda uni hech kim
tinglamaydi. Xato qayerga yoʻqoldi?

**Bitta gʻoya:** Go'da xato qaytariladigan oddiy qiymat. Uni har chaqiruvdan keyin oʻzingiz tekshirasiz (tozalashni
ham oʻzingiz qoʻygan `defer` bilan yozasiz), aks holda dastur notoʻgʻri qiymat bilan jim davom etadi.

Dars oxirida siz:

- `func ReadFile(name string) ([]byte, error)` kabi imzoni oʻqib, xato qayerdan qaytishini koʻra olasiz;
- `if err != nil` bilan xatoni tekshirib, uni yuqoriga qaytarasiz yoki `log.Fatal` bilan toʻxtaysiz;
- natijasi olinmagan chaqiruvdagi jim yoʻqolgan xatoni koʻzda va golangci-lint'ning errcheck'i bilan topasiz;
- `defer` ni `finally` oʻrnida toʻgʻri joyga qoʻyasiz: `resp.Body.Close()` xato tekshiruvidan keyin.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| xato qiymati | funksiya oxirgi natija qilib qaytaradigan `error` turidagi qiymat; `nil` — xato yoʻq | error value |
| `if err != nil` | xatoni tekshirish: xato boʻlsa, uni hal qilasiz yoki yuqoriga qaytarasiz; `try…catch` oʻrnida | `if err != nil` |
| `defer` | chaqiruvni funksiya tugaguncha kechiktiradi, qaysi `return` bilan chiqmasin; `finally` oʻrnida | defer statement |

Ikkita yordamchi soʻz ham bor: **`errors.New`** (matndan yangi xato yasaydi) va **errcheck** (golangci-lint
linterlar toʻplamidagi tekshiruv: tekshirilmagan xatolarni topadi).

Avval GO-X.02 dan bitta savol. Birinchi qatorda `a` va `err` `:=` bilan eʼlon qilindi. Ikkinchi qatorda `b` va
`err` yana `:=` bilan:

```go
a, err := strconv.Atoi("42")
b, err := strconv.Atoi("x")
```

`strconv.Atoi` GO-X.02 ning uy vazifasidan: u stringni songa aylantiradi va son bilan xatoni qaytaradi. Bu kod
build boʻladimi?

**A)** build xatosi: `err` ikki marta eʼlon qilingan · **B)** build boʻladi: `b` yangi, `err` esa yangi qiymat
oladi · **C)** ikkinchi `err` — yangi oʻzgaruvchi

<details>
<summary>Javob</summary>

**B.** `:=` ning chap tomonida kamida bitta yangi nom boʻlsa yetarli. `b` yangi, `err` esa yangi oʻzgaruvchi emas,
faqat yangi qiymat oladi. «Build xatosi» ni tanlagan boʻlsangiz, JavaScript'dagi `let err` ni ikki marta yozish
qoidasini koʻchirgansiz. «Yangi oʻzgaruvchi» ni tanlagan boʻlsangiz, shadowing'ni eslagansiz: u faqat ichki blokda
boʻladi, bu yerda blok bitta.

</details>

```go filename="eslash/main.go" showLineNumbers
// Takrorlash (GO-X.02): := chap tomonida kamida bitta yangi nom bo'lsa yetarli, qolganlari qiymat oladi.
package main

import (
	"fmt"
	"strconv"
)

func main() {
	a, err := strconv.Atoi("42")
	b, err := strconv.Atoi("x") // b yangi, err esa qayta yoziladi
	fmt.Println(a, b, err)
}
```

```console
$ go run ./eslash

```

`a` — 42. `"x"` son emas, shuning uchun `b` zero value'da (`0`), `err` esa xato matnini olib keldi: *parsing "x":
invalid syntax* — «`"x"` ni oʻqib boʻlmadi: yozilishi notoʻgʻri». Go kodida `err` aynan shunday qayta-qayta
ishlatiladi. Bugungi dars shu `err` haqida.

## Xato qiymati: `error` — oddiy qaytgan qiymat

Go'da xato throw qilinmaydi. Xato beradigan funksiya uni oddiy qiymat qilib qaytaradi, odatda oxirgi natija
sifatida. Bu **xato qiymati** (error value). `os.ReadFile` faylni oʻqiydi va ikki natija qaytaradi: baytlar
slice'i (`[]byte`) va xato. `oqish/main.go` («oʻqish») yoʻq faylni oʻqiydi:

```go filename="oqish/main.go" showLineNumbers
// error qiymat: fayl yo'q bo'lsa, data bo'sh, err esa xato matnini olib keladi.
package main

import (
	"fmt"
	"os"
)

func main() {
	data, err := os.ReadFile("yoq.json")
	fmt.Println(len(data), err)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 4–7 | `import ( … )` | `fmt` va `os` (fayllar va operatsion tizim bilan ishlash) paketlari |
| 10 | `data, err := os.ReadFile("yoq.json")` | `data` — fayl baytlari (`[]byte`), `err` — xato; ikkalasi ham yangi |
| 11 | `fmt.Println(len(data), err)` | `len(data)` — baytlar soni; keyin xato |

`error` — Go'ning oʻrnatilgan turi. Unda bitta metod bor: `Error()`, u xato matnini qaytaradi. `Println` xatoni
shu matn bilan chiqaradi. Muvaffaqiyatda `err` — `nil`, yaʼni «xato yoʻq» (GO-X.02). Xotirada shunday:

| Qatordan keyin | `data` (`[]byte`) | `err` (`error`) | Ekranda |
|---|---|---|---|
| 10, fayl yoʻq | `nil` (0 bayt) | `open yoq.json: no such file or directory` | |
| 10, fayl bor | fayl baytlari | `nil` | |
| 11 (fayl yoʻq) | `nil` | xato | `0 open yoq.json: no such file or directory` |

```console
$ go run ./oqish
0 open yoq.json: no such file or directory
```

*open yoq.json: no such file or directory* — «`yoq.json` ni ochib boʻlmadi: bunday fayl yoki papka yoʻq». Muhimi:
11-qator baribir ishladi. JavaScript'da `fs.readFileSync("yoq.json")` throw qilardi va boshqaruv eng yaqin `catch`
ga sakrardi. Go'da hech narsa sakramaydi: xato `err` ichida yotadi, keyingi qator ishlaydi. Xato boʻlsa, boshqa
natijalarga ishonmang: `data` boʻsh.

### Natijalardan bittasini olsa boʻladimi?

Endi bitta natija olamiz: `data := os.ReadFile("config.json")`, `err` siz. JavaScript'da massivdan birinchi
elementni olish mumkin, Python esa tuple qaytaradi. Go nima qiladi?

**A)** `data` — birinchi natija, `err` tashlanadi · **B)** build xatosi · **C)** `data` — `(baytlar, err)` juftligi

<details>
<summary>Javob</summary>

**B: build xatosi.** Natijani oʻzgaruvchiga olsangiz, Go hamma natijani olishni talab qiladi. «Birinchi natija» ni
tanlagan boʻlsangiz, `const [data] = …` destructuring'ini koʻchirgansiz. «Juftlik» ni tanlagan boʻlsangiz, Python'ning
tuple'ini eslagansiz: Go'da bir nechta natija bitta qiymatga yigʻilmaydi.

</details>

```go filename="ikki/main.go" showLineNumbers
// Bashorat: os.ReadFile ikki qiymat qaytaradi, biz bittasini oldik. Ataylab build bo'lmaydi.
package main

import (
	"fmt"
	"os"
)

func main() {
	data := os.ReadFile("config.json")
	fmt.Println(len(data))
}
```

```console
$ go run ikki/main.go
# command-line-arguments
ikki/main.go:10:10: assignment mismatch: 1 variable but os.ReadFile returns 2 values
```

`ikki/main.go:10:10` — 10-qator, 10-ustun: `os.ReadFile`. *assignment mismatch: 1 variable but os.ReadFile returns 2
values* — «qiymat berishda nomuvofiqlik: oʻzgaruvchi bitta, `os.ReadFile` esa 2 ta qiymat qaytaradi». Xatoni
ataylab tashlash uchun pastki chiziq bor: `data, _ := os.ReadFile(…)`. Lekin Go jamoasining code review
qoʻllanmasi buni qilmang deydi: *Do not discard errors using `_` variables* — «xatolarni `_` bilan tashlab
yubormang».

### Xato imzoda koʻrinadi

`go doc` terminalda paket hujjatini koʻrsatadi. `grep func` undan faqat imzo qatorini oladi:

```console
$ go doc os.ReadFile | grep func
func ReadFile(name string) ([]byte, error)
```

Imzoda ikki natija bor, `error` doim oxirida. JavaScript'da funksiya throw qilishini imzodan bilib boʻlmaydi,
TypeScript'da ham `throws` yoʻq (TypeScript'da shunday taklif «rejalashtirilmagan» deb yopilgan). Go'da xato
qaytadimi yoʻqmi, imzoning oʻzidan koʻrinadi.

Nega Go exception'ni tanlamadi? Go FAQ sababini aytadi: exception'larni `try-catch-finally` kabi boshqaruv
tuzilmasiga bogʻlash chalkash kodga olib keladi. U dasturchilarni fayl ochilmasligi kabi oddiy xatolarni ham
favqulodda deb belgilashga undaydi. Go'ning bir nechta natija qaytarishi esa xatoni asosiy qiymat bilan yonma-yon
qaytarishni osonlashtiradi.

## `if err != nil`: tekshirish va yuqoriga qaytarish

Endi config'ni yuklaydigan funksiya. `config/main.go`:

```go filename="config/main.go" showLineNumbers
// if err != nil: xatoni yuqoriga qaytarish (loadConfig) va ishga tushishda to'xtatish (main).
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"os"
)

type Config struct {
	Port int `json:"port"`
}

func loadConfig(path string) (Config, error) {
	var cfg Config
	data, err := os.ReadFile(path)
	if err != nil {
		return cfg, err
	}
	err = json.Unmarshal(data, &cfg)
	return cfg, err
}

func main() {
	cfg, err := loadConfig("config.json")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("port:", cfg.Port)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 11–13 | `type Config struct { … }` | config tuzilmasi: `Port` maydoni JSON'dagi `port` kalitidan (GO-X.02) |
| 15 | `func loadConfig(path string) (Config, error) {` | parametrda ham avval nom, keyin tur; qavsdagi `(Config, error)` — ikki natija |
| 16 | `var cfg Config` | qaytariladigan config, hozircha zero value |
| 17 | `data, err := os.ReadFile(path)` | faylni oʻqish: baytlar va xato |
| 18 | `if err != nil {` | xato bormi? Shart atrofida qavs yoʻq, `{ }` esa majburiy |
| 19 | `return cfg, err` | xatoni chaqiruvchiga qaytaradi: `catch` yozilmagan `throw` kabi, faqat koʻrinib turadi |
| 21 | `err = json.Unmarshal(data, &cfg)` | `Unmarshal` faqat `error` qaytaradi; `err` allaqachon bor, shuning uchun oddiy `=` |
| 22 | `return cfg, err` | xato boʻlsa ham, boʻlmasa ham chaqiruvchi `err` ni oʻzi tekshiradi |
| 26 | `cfg, err := loadConfig("config.json")` | `main` natijani oladi |
| 27–29 | `if err != nil { log.Fatal(err) }` | ishga tushishda xato: matnni yozib, dasturni 1 kodi bilan toʻxtatadi (GO-X.01) |
| 30 | `fmt.Println("port:", cfg.Port)` | xato boʻlmasa, port |

Bu **`if err != nil`** qolipi: Go'da `try…catch` oʻrnida. Videoda 18-qator yonida `// JS: catch'siz throw` izohi
bor (kurs faylida yoʻq). JavaScript'da `catch` yozmasangiz, xato oʻzi yuqoriga
koʻtariladi. Go'da yuqoriga qaytarishni `return cfg, err` bilan qoʻlda yozasiz, va u kodda koʻrinib turadi.

Buzuq `config.json` bilan:

```console
$ go run ./config
2026/11/26 18:38:10 invalid character '}' looking for beginning of object key string
exit status 1
```

*invalid character '\}' looking for beginning of object key string* — «notoʻgʻri belgi `}`: obyekt kaliti boshlanishi
kutilgan edi». Vergul «yana kalit bor» degani, keyin esa `}` keldi. `exit status 1` — `go run` dastur 1 chiqish
kodi bilan tugaganini aytadi: buni `log.Fatal` qildi.

### Xatoni qayerda hal qilasiz

Code review qoʻllanmasining qoidasi: xatoni hal qiling yoki yuqoriga qaytaring.

```text
loadConfig            return cfg, err       → yuqoriga qaytaradi
   │
   ▼
main (ishga tushish)  log.Fatal(err)        → sababini yozib, toʻxtaydi
HTTP handler          http.Error(w, …, 400/500); return
                                            → mijozga javob, handler'dan chiqish

asosiy yoʻl chap chetda, xato yoʻli if ichida
```

| Qayerda | Nima qilasiz | Misol |
|---|---|---|
| yordamchi funksiya | yuqoriga qaytarasiz | `return cfg, err` |
| ishga tushish (`main`) | sababini yozib, toʻxtaysiz | `log.Fatal(err)` |
| HTTP handler | mijozga 400 yoki 500 qaytarasiz | `http.Error(w, …, http.StatusBadRequest)` va `return` |

Qoʻllanmaning yana bir qoidasi (*Indent Error Flow*): asosiy yoʻl chap chetda qoladi, xato yoʻli `if` ichida.
`else` yozilmaydi: `if` ichida `return` bor, asosiy kod undan keyin davom etadi.

## Yoʻqolgan xato: natijasiz chaqiruv

Endi boshidagi xizmatga qaytamiz. `hook/main.go`:

```go filename="hook/main.go" showLineNumbers
// GO-X.03 hook: GO-X.01 xizmati config.json'ni o'qiydi. Unmarshal'ning xatosi tekshirilmagan.
// Ishga tushirish (dars papkasidan): go run ./hook   (config.json'da ortiqcha vergul bor)
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"net/http"
	"os"
)

type Config struct {
	Port int `json:"port"`
}

func main() {
	data, err := os.ReadFile("config.json")
	if err != nil {
		log.Fatal(err)
	}
	var cfg Config
	json.Unmarshal(data, &cfg)

	addr := fmt.Sprintf(":%d", cfg.Port)
	http.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})
	log.Println("listening on", addr)
	log.Fatal(http.ListenAndServe(addr, nil))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 18–21 | `data, err := os.ReadFile(…)` + `if err != nil` | `ReadFile` tekshirilgan |
| 22 | `var cfg Config` | `cfg.Port` hozircha `0` (zero value) |
| 23 | `json.Unmarshal(data, &cfg)` | natijasi olinmagan oddiy chaqiruv |
| 25 | `addr := fmt.Sprintf(":%d", cfg.Port)` | `Sprintf` matnni formatlab qaytaradi; `%d` — butun son: port `8080` → `":8080"` |
| 26–28 | `http.HandleFunc("GET /health", …)` | health check uchun handler: `200 OK` qaytaradi (GO-X.01) |
| 29–30 | `log.Println(…)`, `log.Fatal(http.ListenAndServe(addr, nil))` | xizmatni `addr` da ishga tushiradi (GO-X.01) |

Bir ishora: `fmt.Println` ham ikki natija qaytaradi, `n` va `err`

## `defer`: `finally` oʻrnida

Endi tozalash. JavaScript'da faylni yopish uchun `try…finally`, Python'da `with`. `js/finally.mjs`:

```js filename="js/finally.mjs"
// defer'ning JS'dagi tanish tomoni: try…finally. Ishga tushirish: node js/finally.mjs
import { open } from "node:fs/promises";

async function loadUsers(path) {
  const fh = await open(path);
  try {
    return JSON.parse(await fh.readFile("utf8"));
  } finally {
    await fh.close();
  }
}

console.log(await loadUsers("js/users.json"));
```

```console
$ node js/finally.mjs
[ { id: 42, name: 'Dilnoza' } ]
```

MDN boʻyicha `finally` bloki boshqaruv `try…catch…finally` dan chiqishidan oldin har doim ishlaydi. Go'da
`finally` yoʻq. Uning oʻrnida **`defer`**: bitta qator, u chaqiruvni oʻzi turgan funksiya tugaguncha
kechiktiradi.

### Bashorat: `defer` erta `return` dan keyin

Fayl oʻrniga ekranga yozamiz. `defer/main.go` dagi `load` funksiyasi:

```go
func load(fail bool) error {
	fmt.Println("ochildi")
	if fail {
		return errors.New("buzuq JSON")
	}
	defer fmt.Println("yopildi")
	fmt.Println("o'qildi")
	return nil
}
```

`ochildi` — «ochildi», `yopildi` — «yopildi», `o'qildi` — «oʻqildi». **`errors.New`** matndan yangi xato yasaydi.
Funksiya faqat `error` qaytaradi: `nil` — muvaffaqiyat. Diqqat: `defer` qatori erta `return` dan **keyin** turibdi.
`main` avval `load(false)`, keyin `load(true)` ni chaqiradi va xato boʻlsa `xato: …` deb chiqaradi.

`finally` har doim ishlardi. `load(true)` chaqirilganda ekranda nima chiqadi?

**A)** `ochildi` · `yopildi` · `xato: buzuq JSON` · **B)** `ochildi` · `xato: buzuq JSON` · **C)** `yopildi` ·
`ochildi` · `xato: buzuq JSON`

<details>
<summary>Javob</summary>

**B: `ochildi` va xato, `yopildi` yoʻq.** `defer` faqat oʻsha qator bajarilganda roʻyxatga yoziladi. `fail` true
boʻlganda `return` 13-qatorda boʻldi, 15-qatordagi `defer` gacha yetib kelinmadi. «A» ni tanlagan boʻlsangiz,
`finally` modelini koʻchirgansiz: `finally` blokka bogʻlangan, `defer` esa bajarilgan qatorga. «C» ni tanlagan
boʻlsangiz, `defer` funksiya boshida ishlaydi deb oʻylagansiz: u funksiya oxirida ishlaydi.

</details>

```go filename="defer/main.go" showLineNumbers
// defer: chaqiruv funksiya tugaguncha kechiktiriladi. Lekin u faqat defer qatori bajarilganda ro'yxatga yoziladi:
// undan oldingi return'da hech narsa yopilmaydi (finally'dan farqi).
package main

import (
	"errors"
	"fmt"
)

func load(fail bool) error {
	fmt.Println("ochildi")
	if fail {
		return errors.New("buzuq JSON")
	}
	defer fmt.Println("yopildi")
	fmt.Println("o'qildi")
	return nil
}

func main() {
	if err := load(false); err != nil {
		fmt.Println("xato:", err)
	}
	if err := load(true); err != nil {
		fmt.Println("xato:", err)
	}
}
```

`main` dagi 21 va 24-qatorlar bugungi qisqa shakl: `if err := …; err != nil`.

```console
$ go run ./defer
ochildi
o'qildi
yopildi
ochildi
xato: buzuq JSON
```

| Chaqiruv | Qator | Nima boʻldi | Ekranda |
|---|---|---|---|
| `load(false)` | 11 | | `ochildi` |
| | 15 | `defer` roʻyxatga yozildi: `fmt.Println("yopildi")` | |
| | 16 | | `o'qildi` |
| | 17 | `return nil` → avval roʻyxat bajariladi | `yopildi` |
| `load(true)` | 11 | | `ochildi` |
| | 13 | `return errors.New(…)`: roʻyxat boʻsh | |
| `main` | 25 | | `xato: buzuq JSON` |

`fail` false boʻlganda `yopildi` funksiya oxirida, `o'qildi` dan keyin chiqdi. `finally` dan farqi shu: u blokni
emas, oʻzidan keyingi yoʻlni qamraydi. Qisqasi: `defer` funksiya oxirida ishlaydi, lekin faqat oʻzi bajarilgan
boʻlsa.

## `defer` amalda: `resp.Body.Close()`

Xizmatimiz foydalanuvchini boshqa xizmatdan (users API) HTTP orqali oladi. `http/main.go`:

```go filename="http/main.go" showLineNumbers
// defer amalda: xizmat boshqa xizmatdan (users API) foydalanuvchini HTTP orqali oladi.
// resp.Body — tarmoq ulanishidan oqim; uni yopish shart. Demo uchun users API'ni httptest bilan shu dasturda ko'taramiz.
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
)

type User struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}

func fetchUser(baseURL, id string) (User, error) {
	var u User
	resp, err := http.Get(baseURL + "/users/" + id)
	if err != nil {
		return u, err
	}
	defer resp.Body.Close()
	err = json.NewDecoder(resp.Body).Decode(&u)
	return u, err
}

func main() {
	api := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		fmt.Fprint(w, `{"id": 42, "name": "Dilnoza"}`)
	}))
	defer api.Close()

	u, err := fetchUser(api.URL, "42")
	fmt.Println(u, err)

	_, err = fetchUser("http://localhost:9", "42") // 9-port: hech kim tinglamaydi
	fmt.Println(err)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 17 | `func fetchUser(baseURL, id string) (User, error) {` | ikkala parametr ham `string` (tur bir marta yoziladi); natija — foydalanuvchi va xato |
| 19 | `resp, err := http.Get(…)` | GET soʻrov; `resp` — javob (`*http.Response`, `*` pointer — [GO-X.04](/lab/youtube/go/go-x-04) da) |
| 20–22 | `if err != nil { return u, err }` | tarmoq xatosi: yuqoriga qaytaradi |
| 23 | `defer resp.Body.Close()` | `resp.Body` — tarmoq ulanishidagi oqim; funksiya tugaganda yopiladi |
| 24 | `err = json.NewDecoder(resp.Body).Decode(&u)` | JSON'ni toʻgʻridan-toʻgʻri oqimdan `u` ga oʻqiydi (JS'dagi `await res.json()` kabi) |
| 29–32 | `httptest.NewServer(…)` | demo uchun users API: shu dasturning oʻzida, tasodifiy portda haqiqiy HTTP server; `api.URL` — uning manzili |
| 33 | `defer api.Close()` | `main` tugaganda serverni toʻxtatadi |
| 38 | `fetchUser("http://localhost:9", "42")` | 9-portda hech kim tinglamaydi: tarmoq xatosi; `_` — foydalanuvchi kerak emas |

```console
$ go run ./http
{42 Dilnoza} <nil>
Get "http://localhost:9/users/42": dial tcp [::1]:9: connect: connection refused
```

Birinchi qator: foydalanuvchi va `<nil>` (xato yoʻq). Ikkinchisi: *connect: connection refused* — «ulanish rad
etildi». `net/http` hujjatida yozilgan: `Body` ni yopish chaqiruvchining vazifasi. Body oxirigacha oʻqilib
yopilmasa, HTTP/1.x keep-alive ulanish qayta ishlatilmasligi mumkin.

`defer` xato tekshiruvidan **keyin** turadi. Xato boʻlsa, `resp` — `nil`. `defer` qatori esa `resp.Body` ni
darhol oʻqiydi va dastur yiqiladi. Bu tartibni `go vet` tekshiradi (misol «Koʻp uchraydigan xatolar» boʻlimida).

### `defer` qanday ishlaydi

`defer` qatori bajarilganda chaqiruv funksiyaning roʻyxatiga yoziladi. Funksiya qaysi `return` bilan chiqmasin,
avval roʻyxat bajariladi:

```text
fetchUser(…)
  19  resp, err := http.Get(…)
  20  if err != nil → return u, err      roʻyxat boʻsh: yopadigan narsa yoʻq
  23  defer resp.Body.Close()           roʻyxat: [ resp.Body.Close() ]
  24  err = json.NewDecoder(…).Decode(&u)
  25  return u, err                     → avval resp.Body.Close(), keyin chiqish
```

Effective Go'dagi sabab: keyin funksiyaga yangi `return` qoʻshsangiz ham, yopish unutilmaydi. Yopish ochishning
yonida turadi. Maʼlumotlar bazasida ham shu qolip: `tx, err := db.BeginTx(…)` dan keyin `defer tx.Rollback()`,
yaʼni tranzaksiyani bekor qilish. `Commit` dan keyin u zararsiz: `sql.ErrTxDone` qaytaradi va hech narsa qilmaydi.

| | JavaScript | Python | Go |
|---|---|---|---|
| tozalash | `try { … } finally { fh.close() }` | `with open(…) as f:` | `defer f.Close()` |
| nimaga bogʻlangan | blokka | blokka | funksiyaga; faqat `defer` qatori bajarilgan boʻlsa |

## Chuqurroq (ixtiyoriy): nega `if err != nil` qoladi va stack trace yoʻq

`if err != nil` juda koʻp takrorlanadi. Go blog'idagi 2025-yil 3-iyun maqolasiga koʻra (R. Griesemer), xato
qayta ishlash haqidagi shikoyatlar yillar davomida Go'ning yillik soʻrovnomalarida birinchi oʻrinda turadi. Go
jamoasi bir necha taklifni koʻrib chiqdi:

| Yil | Taklif |
|---|---|
| 2018 | `check` / `handle` |
| 2019 | `try` |
| 2024 | `?` operatori (Ian Lance Taylor) |
| 2025 | qaror: yaqin kelajakda xato sintaksisi oʻzgarmaydi |

Yetti yil oʻtib, 2025-yilda Go jamoasi xato uchun yangi sintaksis izlashni toʻxtatdi. Demak `if err != nil` qoladi.

Yana bir farq: standart `error` da stack trace yoʻq, u faqat qiymat va matn. go1.26.8 manbasida `errors.New`
yasaydigan tur shunday: `type errorString struct { s string }` — bitta string maydon. `tuzat/` da `log.Fatal`
*invalid character* dedi, lekin qaysi fayl ekanini aytmadi. Node esa fayl va qatorni (`server.js:5:18`)
koʻrsatgandi.

| | JavaScript `Error` | Go `error` |
|---|---|---|
| ichida nima bor | matn + stack (fayl:qator) | faqat qiymat va matn |
| kontekst | stack'dan | oʻzingiz qoʻshasiz |

Xatoga kontekst qoʻshish (`%w`, `errors.Is`) — [GO-1.14](/lab/youtube/go/go-1-14) da, `panic` va `defer` tartibi —
[GO-1.15](/lab/youtube/go/go-1-15) da.

## Koʻp uchraydigan xatolar

**1. Natijasiz chaqiruv: xato jim yoʻqoladi.** Bu mavzuning eng klassik xatosi: `json.Unmarshal(data, &cfg)`
build boʻladi, `go vet` ham jim, `cfg` esa zero value'da qoladi (`listening on :0`). Toʻliq misol «Yoʻqolgan xato»
boʻlimida. **Tuzatish:** `if err := json.Unmarshal(data, &cfg); err != nil { … }`, CI'da golangci-lint (errcheck).

**2. Bir nechta natijadan bittasini olish.** `data := os.ReadFile(…)` → *assignment mismatch: 1 variable but
os.ReadFile returns 2 values* (`ikki/main.go`, «Xato qiymati» boʻlimida). **Tuzatish:** `data, err := …` va
`if err != nil`. `data, _ :=` build boʻladi, lekin xatoni tashlaydi: buni qilmang.

**3. `defer` xato tekshiruvidan oldin.** Videoda faqat aytiladi, kurs papkasida misoli bor:

```go filename="defer-oldin/main.go" showLineNumbers
// Xato: defer xato tekshiruvidan OLDIN. http.Get xato qaytarsa resp nil bo'ladi, defer qatori esa resp.Body'ni
// darhol o'qiydi — dastur nil pointer bilan yiqiladi (panic va defer tafsilotlari: GO-1.15).
package main

import (
	"fmt"
	"net/http"
)

func main() {
	resp, err := http.Get("http://localhost:9/users/42") // 9-port: hech kim tinglamaydi
	defer resp.Body.Close()
	if err != nil {
		fmt.Println(err)
		return
	}
}
```

```console
$ go run ./defer-oldin

[signal SIGSEGV: segmentation violation code=0x1 addr=0x40 pc=0x62bbd7]

goroutine 1 [running]:
main.main()
	…/defer-oldin/main.go:12 +0x37
exit status 2
```

*invalid memory address or nil pointer dereference* — «notoʻgʻri xotira manzili: `nil` pointer orqali murojaat».
`main.go:12` — `defer` qatori. `http.Get` xato qaytardi, `resp` — `nil`, `defer` esa `resp.Body` ni shu qatorda
oʻqidi. Bu ishlash paytidagi **panic**: dastur 2 kodi bilan yiqildi (batafsil [GO-1.15](/lab/youtube/go/go-1-15) da).
`go vet` buni oldindan ushlaydi:

```console

```

*using resp before checking for errors* — «`resp` xatolar tekshirilishidan oldin ishlatilmoqda». **Tuzatish:**
avval `if err != nil { return … }`, keyin `defer resp.Body.Close()`, `http/main.go` dagi kabi.

**4. `defer` ni `finally` deb oʻylash.** Erta `return` dan keyin qoʻyilgan `defer` u yoʻlda ishlamaydi: `load(true)`
da `yopildi` chiqmadi («Bashorat: `defer` erta `return` dan keyin» boʻlimi). **Tuzatish:** `defer` ni resurs
olingan zahoti, uning xato tekshiruvidan keyin darhol yozing.

**5. `if` sarlavhasida kerakli natijani eʼlon qilish.** `if cfg, err := loadConfig(…); err != nil` dan keyin `cfg`
yoʻq: *undefined: cfg* («Oʻrtadagi savol» boʻlimi). **Tuzatish:** natijani `if` dan oldin alohida qatorda oling.
Qisqa shakl faqat keyin kerak boʻlmaydigan natija uchun.

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** `json.Unmarshal(data, &cfg)` natijasiz yozildi. Build boʻladimi va xato qayerga ketadi?

<details>
<summary>Javob</summary>

Build ham, `go vet` ham jim. Xato tashlanadi, hech kim uni koʻrmaydi, `cfg` esa zero value'da qoladi. Buni
golangci-lint'ning errcheck'i topadi.

</details>

**2.** `defer resp.Body.Close()` qachon ishlaydi va nega xato tekshiruvidan keyin turadi?

<details>
<summary>Javob</summary>

`fetchUser` tugaganda, qaysi `return` boʻlmasin. Xato boʻlsa `resp` — `nil`, `defer` qatori esa `resp.Body` ni
darhol oʻqiydi va dastur panic bilan yiqiladi. `go vet` buni *using resp before checking for errors* deb ushlaydi.

</details>

**3.** GO-X.01 dan: nega `http.ListenAndServe(…)` `log.Fatal(…)` ichida yoziladi?

<details>
<summary>Javob</summary>

Hujjatga koʻra `ListenAndServe` doim `nil` boʻlmagan xato qaytaradi: u faqat xato bilan qaytadi, masalan port band
boʻlsa. `log.Fatal` shu xatoni yozadi va dasturni 1 kodi bilan toʻxtatadi. Bugungi tilda: bu xatoni ishga tushishda
hal qilish.

</details>

**4.** Bu dastur nima chiqaradi? (Kurs papkasida yoʻq, dars uchun alohida ishga tushirilgan: `defer` bu safar
`return` dan **oldin**.)

```go
package main

import (
	"errors"
	"fmt"
)

func load(fail bool) error {
	defer fmt.Println("yopildi")
	fmt.Println("ochildi")
	if fail {
		return errors.New("buzuq JSON")
	}
	return nil
}

func main() {
	err := load(true)
	fmt.Println("xato:", err)
}
```

**A)** `ochildi` · `xato: buzuq JSON` · **B)** `ochildi` · `yopildi` · `xato: buzuq JSON` · **C)** `yopildi` ·
`ochildi` · `xato: buzuq JSON`

<details>
<summary>Javob</summary>

**B.** `defer` qatori birinchi bajarildi, shuning uchun `return errors.New(…)` da ham u ishladi: funksiya
chiqishidan oldin `yopildi`. Keyin `main` xatoni chiqardi. «A» ni tanlagan boʻlsangiz, `defer/main.go` dagi natijani
koʻchirgansiz: u yerda `defer` `return` dan keyin edi. «C» ni tanlagan boʻlsangiz, `defer` darhol ishlaydi deb
oʻylagansiz: u faqat roʻyxatga yoziladi.

```console
$ go run oldin/main.go
ochildi
yopildi
xato: buzuq JSON
```

</details>

## Uy vazifasi

Boshlangʻich fayllar GitHub'dagi dars papkasida:
[lessons/0x-03-errors](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/0x-03-errors) (`uyga/`
papkasi). Buyruqlar dars papkasidan ishlaydi.

🟢 **Oson** (`uyga/oson/main.go`): config yuklovchi xatoni uch joyda tashlab yuboradi. Avval natijani taxmin
qiling, keyin hammasini `if err != nil` bilan tuzating: `loadConfig` xatoni qaytarsin, `main` esa `log.Fatal`
bilan toʻxtasin. `os.Getenv("CONFIG")` — `CONFIG` muhit oʻzgaruvchisi (`CONFIG=… go run …` qilib beriladi).

```go filename="uyga/oson/main.go" showLineNumbers
// Uy vazifasi 🟢 (GO-X.03): bu config yuklovchi xatolarni uch joyda tashlab yuboradi.
//
//  1. Avval taxmin qiling, keyin dars papkasidan ishga tushiring:
//     go run ./uyga/oson                                  # buzuq config.json (ortiqcha vergul)
//     CONFIG=uyga/oson/config.json go run ./uyga/oson     # to'g'ri config
//  2. Uchala joyni ham if err != nil bilan tuzating:
//     loadConfig xatoni chaqiruvchiga qaytarsin, main esa log.Fatal bilan sababini yozib to'xtasin.
//  3. Tekshiring: buzuq config → "invalid character '}' …", CONFIG=yoq.json → "open yoq.json: no such file
//     or directory", to'g'ri config → "port: 8080".
//     Qiziq: golangci-lint run ./uyga/oson hozir faqat Unmarshal'ni ko'rsatadi — _ bilan tashlangan xatolarni
//     errcheck sukut bo'yicha sanamaydi (check-blank: false). Ko'z bilan topasiz.
//
// Javob: uyga/javob/oson/main.go
package main

import (
	"encoding/json"
	"fmt"
	"os"
)

type Config struct {
	Port int `json:"port"`
}

func loadConfig(path string) (Config, error) {
	var cfg Config
	data, _ := os.ReadFile(path)
	json.Unmarshal(data, &cfg)
	return cfg, nil
}

func main() {
	path := os.Getenv("CONFIG")
	if path == "" {
		path = "config.json"
	}
	cfg, _ := loadConfig(path)
	fmt.Println("port:", cfg.Port)
}
```

```console
$ go run ./uyga/oson
port: 0
```

Buzuq config bilan ham, yoʻq fayl bilan ham `port: 0`. Toʻgʻri yechimda: buzuq config → `invalid character '}' …`,
`CONFIG=yoq.json` → `open yoq.json: no such file or directory`, `CONFIG=uyga/oson/config.json` → `port: 8080`.

🟡 **Oʻrta** (`uyga/orta/main.go`): users API nomaʼlum id uchun `404` qaytaradi, `fetchUser` esa xatosiz boʻsh
foydalanuvchi beradi. Go'da ham, `fetch` dagi kabi, `404` xato emas: `net/http` hujjatida *A non-2xx response
doesn't cause an error* — «2xx boʻlmagan javob xato hisoblanmaydi». `defer` dan keyin `resp.StatusCode` ni
tekshiring va `200` boʻlmasa `fmt.Errorf("users API: %s", resp.Status)` qaytaring. `fmt.Errorf` — `Sprintf` kabi
formatlab, xato yasaydi.

Boshlangʻich faylda `fetchUser` — `http/main.go` dagi bilan bir xil, faqat `defer resp.Body.Close()` dan keyin
vazifa izohi turibdi. `usersAPI()` — demo uchun soxta users API (`httptest`): faqat 42-foydalanuvchi bor, qolgan
id'larga `404` va `{"error": "not found"}` qaytaradi. `main` `fetchUser` ni `"42"` va `"7"` bilan chaqiradi.
Faylning toʻliq matni va vazifa izohi GitHub'dagi `uyga/orta/` papkasida.

```console
$ go run ./uyga/orta
{42 Dilnoza} <nil>
{0 } <nil>
```

`{0 }` — boʻsh `User`: `ID` `0`, `Name` boʻsh string. Toʻgʻri yechimda ikkinchi qator
`{0 } users API: 404 Not Found` boʻladi.

⭐ **Qoʻshimcha:** GO-X.01 dagi `GET /users/{id}` handler'ini `fetchUser` bilan yozing. Xato boʻlsa,
`http.Error(w, err.Error(), http.StatusBadGateway)` va `return`.

Javoblar: [uyga/javob/](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/0x-03-errors/uyga/javob)
papkasi. Avval oʻzingiz urinib koʻring.

<details>
<summary>Javob</summary>

🟢 Uchta joy edi: `data, _ :=` (`ReadFile` xatosi `_` bilan tashlangan), natijasiz `json.Unmarshal` va
`main` dagi `cfg, _ :=`. `return cfg, nil` ham yolgʻon edi: xato boʻlsa ham «xato yoʻq» deyardi. errcheck faqat
`Unmarshal` ni koʻrsatadi, qolgan ikkitasini koʻz bilan topasiz.

```go filename="uyga/javob/oson/main.go" showLineNumbers
// Javob 🟢 (GO-X.03): uchala xato tekshiriladi.
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"os"
)

type Config struct {
	Port int `json:"port"`
}

func loadConfig(path string) (Config, error) {
	var cfg Config
	data, err := os.ReadFile(path)
	if err != nil {
		return cfg, err
	}
	if err := json.Unmarshal(data, &cfg); err != nil {
		return cfg, err
	}
	return cfg, nil
}

func main() {
	path := os.Getenv("CONFIG")
	if path == "" {
		path = "config.json"
	}
	cfg, err := loadConfig(path)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("port:", cfg.Port)
}
```

```console
exit status 1
```

🟡 `defer` dan keyin status tekshiriladi. `200` boʻlmasa, body JSON sifatida oʻqilmaydi, xato qaytadi.
`resp.Status` — `"404 Not Found"` kabi matn.

```go filename="uyga/javob/orta/main.go" showLineNumbers
// Javob 🟡 (GO-X.03): 200 bo'lmagan javob xato sifatida qaytariladi.
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
)

type User struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}

func fetchUser(baseURL, id string) (User, error) {
	var u User
	resp, err := http.Get(baseURL + "/users/" + id)
	if err != nil {
		return u, err
	}
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK {
		return u, fmt.Errorf("users API: %s", resp.Status)
	}
	err = json.NewDecoder(resp.Body).Decode(&u)
	return u, err
}

// usersAPI — demo uchun soxta users API: faqat 42-foydalanuvchi bor.
func usersAPI() *httptest.Server {
	return httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		if r.URL.Path != "/users/42" {
			w.WriteHeader(http.StatusNotFound)
			fmt.Fprint(w, `{"error": "not found"}`)
			return
		}
		fmt.Fprint(w, `{"id": 42, "name": "Dilnoza"}`)
	}))
}

func main() {
	api := usersAPI()
	defer api.Close()

	fmt.Println(fetchUser(api.URL, "42"))
	fmt.Println(fetchUser(api.URL, "7"))
}
```

```console
$ go run ./uyga/javob/orta
{42 Dilnoza} <nil>
{0 } users API: 404 Not Found
```

⭐ uchun javob fayli yoʻq: handler'da `u, err := fetchUser(…)`, xato boʻlsa
`http.Error(w, err.Error(), http.StatusBadGateway)` va `return`, aks holda `u` ni JSON qilib yozasiz (GO-X.01).

</details>
