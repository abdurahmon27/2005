## Nimani oʻrganasiz

`Tola` («toʻla») metodi buyurtmani toʻlangan deb belgilaydi, uning receiver'i pointer. Shu metodni slice elementida
chaqirsak, dastur kompilyatsiya boʻladi. Map elementida chaqirsak, kompilyator rad etadi: `cannot call pointer method`.
Python'da `orders[0].pay()` ham, `orders["a1"].pay()` ham bir xil ishlaydi. Go'da nega farq bor?

**Bitta gʻoya:** receiver — metodning oddiy argumenti: value receiver qiymatning nusxasini, pointer receiver esa
manzilini oladi. Qaysi chaqiruv kompilyatsiya boʻlishini ikki qoida hal qiladi: **method set** va
**addressability**. Method set esa qaysi interface (metodlar roʻyxatidan iborat tur) qanoatlanishini ham hal qiladi.

Dars oxirida siz:

- metod eʼlon qilib, value receiver va pointer receiver farqini (nusxa yoki manzil) Python'dagi `self` va JS'dagi
  `this` bilan solishtirib tushuntira olasiz;
- `cannot call pointer method` xatosini oʻqib, qiymat nega addressable emasligini (map elementi, funksiya natijasi)
  aytib, tuzata olasiz;
- `String()` metodi nega baʼzan chaqirilmasligini, `has pointer receiver` xatosi nimani bildirishini bilasiz;
- turingiz uchun receiver'ni Go FAQ va kod review qoidalari asosida tanlay olasiz (mutex bor struct'da nega faqat
  pointer).

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| receiver | metod chaqirilgan qiymat; Python'dagi `self`, JS va PHP'dagi `this` / `$this` oʻrnida, lekin Go'da u oddiy argument kabi nusxalanadi | receiver |
| method set | turga tegishli metodlar toʻplami: `T` da faqat value receiver'li metodlar, `*T` da hammasi | method set |
| addressable | manzilini (`&`) olish mumkin boʻlgan qiymat: oʻzgaruvchi, slice elementi va boshqalar; map elementi emas | addressable |

Yoʻl-yoʻlakay ikkita yordamchi soʻz ham uchraydi: **method value** (`f := b.Jami` — metod receiver'i bilan birga
oʻzgaruvchiga olinadi) va **method expression** (`Buyurtma.Jami` — metod oddiy funksiya sifatida ishlatiladi). Ikkalasini
kerak boʻlgan joyda tushuntiramiz.

## Jumboq: slice'da kompilyatsiya boʻladi, map'da yoʻq

Kurs papkasidagi `hook/main.go`. Bitta tur, bitta metod, ikki chaqiruv:

```go filename="hook/main.go" showLineNumbers
// dastur kompilyatsiya ham boʻlmaydi. Bu papka ATAYLAB kompilyatsiya boʻlmaydi: go build ./hook
package main

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func (b *Buyurtma) Tola() { b.Tolandi = true }

func main() {

	m := map[string]Buyurtma{"a1": {Summa: 50_000}}

```

## Metod va receiver: receiver — oddiy argument

**Metod** — receiver'i bor funksiya (Go spetsifikatsiyasi, *Method declarations*). **Receiver** `func` soʻzi bilan
metod nomi orasida, qavs ichida yoziladi: `func (b Buyurtma) Jami()`. Bu yerda `b` — receiver nomi, `Buyurtma` —
uning turi. Metod ichida `b` oddiy parametr kabi ishlatiladi.

Python'dan kelgan boʻlsangiz, bu tanish: `self` ham metodning birinchi parametri. Python'da metodni klass orqali,
`self` ni qoʻlda berib chaqirish mumkin. JS'da shu ishni `call` qiladi, PHP'da `$this` yashirin. Bu misollar kurs
papkasida yoʻq, alohida ishga tushirildi:

```python
class Order:
    def __init__(self, summa):
        self.summa = summa
        self.paid = False

    def total(self):
        return self.summa + self.summa // 100

    def pay(self):
        self.paid = True

o = Order(50_000)
print(o.total(), Order.total(o))
o.pay()
print(o.paid)
```

```js
class Order {
  constructor(summa) {
    this.summa = summa;
    this.paid = false;
  }
  total() {
    return this.summa + Math.floor(this.summa / 100);
  }
  pay() {
    this.paid = true;
  }
}

const o = new Order(50000);
console.log(o.total(), Order.prototype.total.call(o));
o.pay();
console.log(o.paid);
```

```php
<?php
class Order {
    public bool $paid = false;
    public function __construct(public int $summa) {}
    public function pay(): void { $this->paid = true; }
}

$o = new Order(50000);
$o->pay();
var_dump($o->paid);
```

```console
$ python3 receiver.py
50500 50500
True
$ node receiver.js
50500 50500
true
$ php receiver.php
bool(true)
```

Uchala tilda ham `pay()` asl obyektni oʻzgartirdi. Sababi: `self`, `this` va `$this` doim obyektga **havola**
(reference). Endi Go'dagi xuddi shu buyurtma, `metod/main.go`:

```go filename="metod/main.go" showLineNumbers
// metod: metod — receiver'li funksiya. Value receiver nusxa oladi, pointer receiver manzil oladi.
package main

import "fmt"

type Buyurtma struct {
	Summa   int64 // tiyinda
	Tolandi bool
}

// Jami: value receiver. b — buyurtmaning nusxasi.
func (b Buyurtma) Jami() int64 { return b.Summa + b.Summa/100 } // +1% xizmat haqi

// Tola: value receiver. Nusxani oʻzgartiradi, asl buyurtma oʻzgarmaydi.
func (b Buyurtma) Tola() { b.Tolandi = true }

// TolaP: pointer receiver. Asl buyurtmani oʻzgartiradi.
func (b *Buyurtma) TolaP() { b.Tolandi = true }

func main() {
	b := Buyurtma{Summa: 50_000}
	fmt.Println("Jami:          ", b.Jami())
	fmt.Println("Buyurtma.Jami: ", Buyurtma.Jami(b)) // receiver — birinchi argument

	b.Tola()
	fmt.Println("Tola:  ", b.Tolandi)

	b.TolaP() // (&b).TolaP() ning qisqa yozuvi
	fmt.Println("TolaP: ", b.Tolandi)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7 | `Summa int64 // tiyinda` | summa tiyinda saqlanadi: `50_000` tiyin = 500 soʻm |
| 12 | `func (b Buyurtma) Jami() int64` | `Jami` («jami») metodi. Receiver'i `Buyurtma` turidagi qiymat, pointer emas: bu **value receiver**. Summaga 1% xizmat haqini qoʻshib qaytaradi |
| 15 | `func (b Buyurtma) Tola()` | `Tola` ham value receiver: nusxadagi `Tolandi` ni `true` qiladi |
| 18 | `func (b *Buyurtma) TolaP()` | `TolaP` da tur nomi oldida `*` bor: bu **pointer receiver**. `b` — buyurtmaning manzili. `b.Tolandi` — `(*b).Tolandi` ning qisqa yozuvi (GO-1.11) |
| 22 | `b.Jami()` | metodni odatdagidek chaqiradi |
| 23 | `Buyurtma.Jami(b)` | **method expression**: `Buyurtma.Jami` — oddiy funksiya, uning birinchi argumenti receiver. Python'dagi `Order.total(o)` ning oʻzi |
| 25 | `b.Tola()` | value receiver'li metod: `b` ning nusxasi beriladi |
| 28 | `b.TolaP()` | pointer receiver'li metod. Biz `&` yozmadik, Go uni oʻzi qoʻshdi (keyingi boʻlim) |

Go FAQ aytadi: receiver *"behaves exactly as if it were an argument to the method"* — «metodning argumentidek
ishlaydi». 23-qator buni koʻrsatadi: `b.Jami()` va `Buyurtma.Jami(b)` — bitta chaqiruvning ikki yozuvi. GO-1.06
qoidasi esa: argument har doim nusxalanadi. Demak value receiver ham nusxa.

Ishga tushirishdan oldin oʻylab koʻring: `Tola:` va `TolaP:` qatorlarida nima chiqadi? **A)** `true`, `true` ·
**B)** `false`, `true` · **C)** `false`, `false`

<details>
<summary>Javob</summary>

**B: `false`, keyin `true`.** `Tola` ning receiver'i `b` ning nusxasi: metod nusxani oʻzgartirdi, nusxa metod
tugashi bilan yoʻqoldi. `TolaP` esa `b` ning manzilini oldi va `main` dagi `b` ning oʻzini oʻzgartirdi. «A» ni
tanlagan boʻlsangiz, receiver'ni Python'dagi `self` yoki JS'dagi `this` kabi doim havola deb oʻylagansiz. «C» ni
tanlagan boʻlsangiz, pointer ham nusxalanadi, demak u ham yordam bermaydi deb oʻylagansiz: nusxalanadi, lekin
nusxa oʻsha manzilni saqlaydi (GO-1.11).

</details>

|---|---|---|

| Go, pointer receiver `(b *T)` | `b` — manzil | ha |

## Go `&` va `*` ni oʻzi qoʻshadi

`metod` da `b.TolaP()` yozdik, `(&b).TolaP()` emas. Spetsifikatsiya (*Calls*): *"If x is addressable and &x's method
set contains m, x.m() is shorthand for (&x).m()"* — «`x` addressable boʻlsa va `&x` ning method set'ida `m` boʻlsa,
`x.m()` — `(&x).m()` ning qisqa yozuvi».

Teskari yoʻnalish ham ishlaydi. Pointer orqali value receiver'li metodni chaqirsangiz, Go `*` qoʻyadi: `p.Jami()` —
`(*p).Jami()` (spetsifikatsiya, *Method values*). `p` `nil` boʻlsa, bu `*p` panic beradi. Pointer receiver'li metod
esa `nil` receiver bilan ham chaqiriladi va uni oʻzi tekshira oladi. `nilp/main.go`:

```go filename="nilp/main.go" showLineNumbers
// nilp: nil pointer orqali metod. Pointer receiver nil'ni oʻzi tekshira oladi,
// value receiver esa chaqiruvdan oldin *p ni oʻqiydi va panic beradi (ATAYLAB).
package main

import "fmt"

type Buyurtma struct{ Summa int64 }

func (b Buyurtma) Jami() int64 { return b.Summa }

func (b *Buyurtma) JamiP() int64 {
	if b == nil {
		return 0
	}
	return b.Summa
}

func main() {
	var p *Buyurtma
	fmt.Println("JamiP:", p.JamiP()) // 0: receiver nil, metod buni tekshirdi
	fmt.Println("Jami: ", p.Jami())  // (*p).Jami() → panic
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 9 | `func (b Buyurtma) Jami()` | value receiver |
| 11–16 | `func (b *Buyurtma) JamiP()` | pointer receiver: `b` `nil` boʻlsa 0 qaytaradi |
| 19 | `var p *Buyurtma` | qiymat berilmagan pointer: `nil` |
| 20 | `p.JamiP()` | receiver — `nil` pointer'ning oʻzi; metod ichida tekshiriladi |
| 21 | `p.Jami()` | Go buni `(*p).Jami()` qiladi: `nil` boʻyicha qiymatga borish |

`JamiP: 0` chiqdi, keyin 21-qatorda panic. JS'da `null.total()` yoki Python'da `None.total()` har doim xato beradi.
Go'da esa `nil` receiver bilan pointer metodni chaqirish mumkin, chunki receiver shunchaki argument.

Spetsifikatsiya bu «oʻzi qoʻshadi» qoidalarini **method set** bilan ifodalaydi. Method set — turga tegishli
metodlar toʻplami (*Method sets*):

| Tur | Method set'ida | `metod` misolida |
|---|---|---|
| `Buyurtma` (`T`) | faqat receiver'i `T` boʻlgan metodlar | `Jami`, `Tola` |
| `*Buyurtma` (`*T`) | receiver'i `T` **va** `*T` boʻlgan metodlar | `Jami`, `Tola`, `TolaP` |

`b.TolaP()` da `TolaP` `Buyurtma` ning method set'ida yoʻq. Shuning uchun Go `&b` ni olib, `*Buyurtma` ning metodini
chaqiradi. Lekin `&b` ni olish uchun bitta shart bor: `b` **addressable** boʻlishi kerak, yaʼni uning manzilini olish
mumkin boʻlishi kerak.

## Qaysi qiymatlar addressable?

Spetsifikatsiya (*Address operators*) aniq roʻyxat beradi: oʻzgaruvchi, pointer orqali qiymat (`*p`), slice
elementi, addressable struct'ning maydoni va addressable massivning elementi. Kompilyatorda tekshiramiz,
`manzilsiz/main.go`:

```go filename="manzilsiz/main.go" showLineNumbers
// manzilsiz: pointer metodni qaysi qiymatda chaqirsa boʻladi? Faqat addressable qiymatda.
// Bu papka ATAYLAB kompilyatsiya boʻlmaydi: go build -o /dev/null ./manzilsiz
package main

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func (b *Buyurtma) Tola() { b.Tolandi = true }

type Savat struct{ B Buyurtma }

func yarat() Buyurtma { return Buyurtma{Summa: 50_000} }

func main() {
	var b Buyurtma
	b.Tola() // ✅ oʻzgaruvchi
	s := []Buyurtma{{}}
	s[0].Tola() // ✅ slice elementi
	var a [2]Buyurtma
	a[1].Tola() // ✅ addressable massiv elementi
	var sv Savat
	sv.B.Tola() // ✅ addressable struct'ning maydoni
	p := &b
	(*p).Tola() // ✅ pointer orqali qiymat (pointer indirection)

	(&Buyurtma{}).Tola() // ✅ lekin bu yerda receiver allaqachon pointer: &T{} — & uchun istisno

	m := map[string]Buyurtma{}
	m["a1"].Tola()    // ❌ map elementi
	yarat().Tola()    // ❌ funksiya natijasi
	Buyurtma{}.Tola() // ❌ composite literal'ning oʻzi
}
```

| Qator | Kod | Addressable? |
|---|---|---|
| 18 | `b.Tola()` | ha: `b` — oʻzgaruvchi |
| 20 | `s[0].Tola()` | ha: slice elementi ichki massivda turadi (GO-1.08) |
| 22 | `a[1].Tola()` | ha: `a` — oʻzgaruvchidagi massiv (`[2]Buyurtma`), uning elementi ham addressable |
| 24 | `sv.B.Tola()` | ha: `sv` addressable, demak uning `B` maydoni ham. `Savat` («savat») bitta `Buyurtma` maydonli struct |
| 26 | `(*p).Tola()` | ha: pointer orqali qiymat (*pointer indirection*) |
| 28 | `(&Buyurtma{}).Tola()` | receiver allaqachon pointer, addressability kerak emas. Composite literal addressable emas, lekin unga `&` yozish mumkin: bu faqat `&` uchun istisno |
| 31 | `m["a1"].Tola()` | yoʻq: map elementi |
| 32 | `yarat().Tola()` | yoʻq: funksiya natijasi. `yarat` («yarat») yangi buyurtma qaytaradi |
| 33 | `Buyurtma{}.Tola()` | yoʻq: `&` siz composite literal |

## Nega map elementining manzilini olib boʻlmaydi?

Bir sababi — map'ning oʻsishi. [GO-1.09](/lab/youtube/go/go-1-09) da koʻrdik: Go 1.24 dan beri map **Swiss table** ustida
ishlaydi. Elementlar koʻpaysa, runtime jadvalni kattarogʻiga almashtiradi va elementlarni unga koʻchiradi. Go'ning
manba kodida shunday yozilgan:

```console
$ sed -n 100,102p $(go env GOROOT)/src/internal/runtime/maps/map.go
// A map starts with a single table. Up to [maxTableCapacity], growth simply
// replaces this table with a replacement with double capacity. Beyond this
// limit, growth splits the table into two.
```

«Map bitta jadvaldan boshlanadi. Maʼlum chegaragacha oʻsish jadvalni ikki barobar sigʻimli jadvalga almashtiradi.
Undan keyin jadval ikkiga boʻlinadi.» Agar `&m["a1"]` mumkin boʻlganda, oʻsishdan keyin bu manzil eski jadvaldagi
eskirgan nusxaga qarab qolardi.

Bu [GO-1.11](/lab/youtube/go/go-1-11) dagi `&s[0]` + `append` tuzogʻining aynan oʻzi. Slice'da bu xato runtime'da jim yuz
beradi. Map'da esa til uni kompilyatsiya paytida taqiqlaydi. (Donovan va Kernighan ham §4.3 da shu sababni
keltiradi.)

Python'da bu muammo yoʻq: dict obyektlarga havola saqlaydi. Bu misol ham kurs papkasida yoʻq:

```python
class Order:
    def __init__(self, summa):
        self.summa = summa
        self.paid = False

    def pay(self):
        self.paid = True

m = {"a1": Order(50_000)}
m["a1"].pay()
print(m["a1"].paid)
```

```console
$ python3 mapref.py
True
```

Go'da bunga eng yaqini — map'da pointer saqlash. Yechim ikki xil, `mapfix/main.go`:

```go filename="mapfix/main.go" showLineNumbers
// mapfix: map elementida pointer metodni chaqirishning ikki yoʻli.
package main

import "fmt"

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func (b *Buyurtma) Tola() { b.Tolandi = true }

func main() {
	// 1-yoʻl: nusxa ol, oʻzgartir, qaytarib yoz.
	m := map[string]Buyurtma{"a1": {Summa: 50_000}}
	b := m["a1"]
	b.Tola()
	m["a1"] = b
	fmt.Println("1-yoʻl:", m["a1"].Tolandi)

	// 2-yoʻl: map'da pointer saqla. m2["a1"] — pointer, uning ortidagi buyurtma addressable.
	m2 := map[string]*Buyurtma{"a1": {Summa: 50_000}}
	m2["a1"].Tola()
	fmt.Println("2-yoʻl:", m2["a1"].Tolandi)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 16 | `b := m["a1"]` | map elementining nusxasini oʻzgaruvchiga oladi: endi u addressable |
| 17 | `b.Tola()` | `(&b).Tola()`: nusxani oʻzgartiradi |
| 18 | `m["a1"] = b` | oʻzgargan nusxani map'ga qaytarib yozadi |
| 22 | `map[string]*Buyurtma{"a1": {Summa: 50_000}}` | map'da pointer saqlanadi. `{Summa: 50_000}` bu yerda `&Buyurtma{…}` ning qisqa yozuvi |
| 23 | `m2["a1"].Tola()` | `m2["a1"]` — pointer, receiver ham pointer: `&` kerak emas |

```console
$ go run ./mapfix
1-yoʻl: true
2-yoʻl: true
```

Go wiki (*MethodSets*) aytadi: struct elementli map'lar deyarli har doim pointer bilan yaratiladi. Lekin 1-yoʻl ham
toʻgʻri, ayniqsa struct kichik boʻlsa.

## Method set va `fmt.Stringer`: `String()` nega chaqirilmadi?

Python'da `__str__`, JS'da `toString()`, PHP'da `__toString()`. Go'da esa `String() string` metodi: `fmt` paketi uni
topsa, qiymatni chop etishda shu metodni chaqiradi. Bunday metodli tur **`fmt.Stringer`** deyiladi. Python'da
`print` `__str__` ni har doim topadi (bu misol ham kurs papkasida yoʻq):

```python
class Order:
    def __init__(self, summa):
        self.summa = summa

    def __str__(self):
        return f"buyurtma: {self.summa // 100} soʻm"

print(Order(50_000))
```

```console
$ python3 stringer.py
buyurtma: 500 soʻm
```

Go'da `String()` ni pointer receiver bilan yozamiz, `stringer/main.go`:

```go filename="stringer/main.go" showLineNumbers
// stringer: String metodi pointer receiver'da. fmt.Println(b) uni chaqirmaydi, fmt.Println(&b) chaqiradi.
package main

import "fmt"

type Buyurtma struct {
	Summa   int64 // tiyinda
	Tolandi bool
}

// String: *Buyurtma ning metodi. Buyurtma (pointer emas) ning method set'ida yoʻq.
func (b *Buyurtma) String() string {
	return fmt.Sprintf("buyurtma: %d soʻm, toʻlandi: %t", b.Summa/100, b.Tolandi)
}

func main() {
	b := Buyurtma{Summa: 50_000}
	fmt.Println(b)  // Buyurtma fmt.Stringer emas: maydonlar chiqadi
	fmt.Println(&b) // *Buyurtma fmt.Stringer: String() chaqiriladi
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 12 | `func (b *Buyurtma) String() string` | `String` pointer receiver'da |
| 13 | `fmt.Sprintf(…)` | `Printf` kabi formatlaydi, lekin chop etmaydi, matnni qaytaradi. `%d` — butun son, `%t` — `bool`. `b.Summa/100` — tiyindan soʻmga |
| 18 | `fmt.Println(b)` | buyurtmaning oʻzini beradi |
| 19 | `fmt.Println(&b)` | buyurtmaning manzilini beradi |

Ishga tushirishdan oldin: 18-qator nima chiqaradi? **A)** `buyurtma: 500 soʻm, toʻlandi: false` ·
**B)** `{50000 false}` · **C)** kompilyatsiya xatosi

<details>
<summary>Javob</summary>

**B: `{50000 false}`.** `b` ning turi `Buyurtma`, uning method set'ida `String` yoʻq: `String` faqat `*Buyurtma`
da. `fmt` `String` ni topmaydi va maydonlarni xom chop etadi. «A» ni tanlagan boʻlsangiz, Go `b.TolaP()` dagi kabi
`&` ni bu yerda ham qoʻshadi deb oʻylagansiz. Lekin `Println` metodni chaqirmaydi, u faqat qiymatni oladi. «C» emas:
`Println` istalgan qiymatni oladi, quyida koʻramiz.

</details>

```console
$ go run ./stringer
{50000 false}
buyurtma: 500 soʻm, toʻlandi: false
```

Nega shunday? `Println` ning parametri `...any`: unga har qanday qiymat sigʻadi. `String` bor-yoʻqligini esa `fmt`
dastur ishlayotganda tekshiradi (`fmt/print.go` dagi `handleMethods` ichida `case Stringer:`). Bu tekshiruv qiymat
turining method set'iga qaraydi: `Buyurtma` da `String` yoʻq, `*Buyurtma` da bor.

Bu xato ham jim. `Println` bilan `go vet` ham indamaydi:

```console
$ go vet ./stringer && echo vet: jim
vet: jim
```

`&&` — «chap tomondagi buyruq muvaffaqiyatli tugasa, oʻngdagisini ishga tushir». `go vet` xato topmadi, shuning
uchun `echo` ishladi.

Endi qiymatni `fmt.Stringer` turidagi oʻzgaruvchiga beramiz. **Interface** — metodlar roʻyxatidan iborat tur:
`fmt.Stringer` «`String() string` metodi bor har qanday tur» degani. Batafsil keyingi darsda:
[GO-1.13 · Interface'lar: `nil` nega `nil`ga teng emas?](/lab/youtube/go/go-1-13).
`stringerxato/main.go`:

```go filename="stringerxato/main.go" showLineNumbers
// stringerxato: kompilyator method set'ni tekshiradi. Bu papka ATAYLAB kompilyatsiya boʻlmaydi:
// go build -o /dev/null ./stringerxato
package main

import "fmt"

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func (b *Buyurtma) String() string { return fmt.Sprint(b.Summa) }

func main() {
	b := Buyurtma{Summa: 50_000}
	var s fmt.Stringer = b // ❌ String pointer receiver'da
	fmt.Println(s)
}
```

12-qatordagi `fmt.Sprint` qiymatni matnga aylantiradi. 16-qatorda `b` `fmt.Stringer` turidagi `s` ga beriladi. Bu safar tekshiruvni kompilyator qiladi:

```console
$ go build -o /dev/null ./stringerxato
# github.com/abdurahmon27/go-backend-uz/lessons/012-methods-receivers/stringerxato
stringerxato/main.go:16:23: cannot use b (variable of struct type Buyurtma) as fmt.Stringer value in variable declaration: Buyurtma does not implement fmt.Stringer (method String has pointer receiver)
```

Xabarni oʻqiymiz: *cannot use b … as fmt.Stringer value* — «`b` ni `fmt.Stringer` qiymati sifatida ishlatib
boʻlmaydi». *Buyurtma does not implement fmt.Stringer (method String has pointer receiver)* — «`Buyurtma`
`fmt.Stringer` ni amalga oshirmaydi: `String` metodi pointer receiver'da». **Tuzatish:** `var s fmt.Stringer = &b`
yoki `String` ni value receiver'da yozish.

Nega Go `&b` ni bu yerda oʻzi qoʻshmaydi? Go FAQ (*Why do T and \*T have different method sets?*) javob beradi:
interface ichidagi qiymatning manzilini xavfsiz olib boʻlmaydi. Olinsa ham, metod interface ichidagi nusxani
oʻzgartirar va oʻzgarish chaqiruvchiga yetmay yoʻqolardi.

## Embedding: metodlar ham koʻtariladi

[GO-1.10](/lab/youtube/go/go-1-10) da koʻrdik: embedding'da ichki struct'ning maydonlari tashqi struct'ga koʻtariladi
(*promoted*). Metodlar ham xuddi shunday koʻtariladi. `embed/main.go`:

```go filename="embed/main.go" showLineNumbers
// embed: embedding'da metodlar ham koʻtariladi (GO-1.10 vaʼdasi). Receiver baribir ichki struct.
package main

import "fmt"

type Manzil struct {
	Shahar string
	Kocha  string
}

func (m Manzil) Toliq() string         { return m.Shahar + ", " + m.Kocha }
func (m *Manzil) Kochir(shahar string) { m.Shahar = shahar }

type Mijoz struct {
	Ism    string
	Manzil // embedding
}

func main() {
	a := Mijoz{Ism: "Aziza", Manzil: Manzil{Shahar: "Toshkent", Kocha: "Navoiy"}}
	a.Kochir("Samarqand")  // (&a.Manzil).Kochir("Samarqand")
	fmt.Println(a.Toliq()) // a.Manzil.Toliq()
	fmt.Println(a.Ism, "—", a.Manzil.Shahar)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 11 | `func (m Manzil) Toliq() string` | `Toliq` («toʻliq») — value receiver: shahar va koʻchani qaytaradi |
| 12 | `func (m *Manzil) Kochir(shahar string)` | `Kochir` («koʻchir») — pointer receiver: shaharni oʻzgartiradi |
| 14–17 | `type Mijoz struct {…}` | `Mijoz` («mijoz») ichida `Manzil` embedding bilan |
| 21 | `a.Kochir("Samarqand")` | koʻtarilgan metod: aslida `(&a.Manzil).Kochir(…)`. Ishlaydi, chunki `a` — oʻzgaruvchi, `a.Manzil` esa addressable struct'ning maydoni |
| 22 | `a.Toliq()` | aslida `a.Manzil.Toliq()` |
| 23 | `a.Manzil.Shahar` | ichki `Manzil` ning shahrini toʻgʻridan-toʻgʻri oʻqiydi |

Python'da shunga oʻxshash kod meros (inheritance) bilan yoziladi. Bu misol ham kurs papkasida yoʻq:

```python
class Address:
    def __init__(self, city):
        self.city = city

    def move(self, city):
        print(type(self).__name__)
        self.city = city

class Customer(Address):
    pass

c = Customer("Toshkent")
c.move("Samarqand")
print(c.city)
```

```console
$ python3 inherit.py
Customer
Samarqand
```

Python'da merosdan kelgan metod ichida `self` — `Customer` ning oʻzi. Go'da esa:

```console
$ go run ./embed
Samarqand, Navoiy
Aziza — Samarqand
```

Aziza Samarqandga koʻchdi, lekin oʻzgarish ichki `Manzil` ga yozildi: `Kochir` ning receiver'i aynan shu ichki
struct. Effective Go (*Embedding*): metod chaqirilganda uning receiver'i ichki tur, tashqisi emas. Bu meros emas,
oddiy delegatsiya: `Kochir` `Mijoz` haqida hech narsa bilmaydi.

Method set'ga taʼsiri (spetsifikatsiya, *Struct types*): `S` ichida `T` embed qilinsa, `S` va `*S` ning method
set'iga receiver'i `T` boʻlgan metodlar kiradi. Receiver'i `*T` boʻlganlari esa faqat `*S` ga kiradi. Bu qoidani uy
vazifasining «guru» darajasida sinaymiz.

## Pauza: method value receiver'ni qachon oladi?

Metodni chaqirmasdan, oʻzgaruvchiga olish mumkin: `f := b.Jami`. Bu **method value** deyiladi: `f` — funksiya,
uni keyin `f()` deb chaqirasiz. Savol:

```go
type Buyurtma struct {
	Summa int64
}

func (b Buyurtma) Jami() int64   { return b.Summa }
func (b *Buyurtma) JamiP() int64 { return b.Summa }

b := Buyurtma{Summa: 100}
f := b.Jami
g := b.JamiP
b.Summa = 200
fmt.Println("f():", f())
fmt.Println("g():", g())
```

`f()` va `g()` nima qaytaradi? **A)** `200`, `200` · **B)** `100`, `200` · **C)** `100`, `100`

Ishora: receiver qachon olinadi — `f := …` qatorida yoki `f()` chaqirilganda?

<details>
<summary>Javob</summary>

**B: `f()` — 100, `g()` — 200.** Spetsifikatsiya (*Method values*): method value yaratilgan paytda receiver
*"evaluated and saved"* — «hisoblanib, saqlab qoʻyiladi». `f` value receiver: `b` ning nusxasi (`Summa: 100`) shu
paytda saqlandi. `g` pointer receiver: `&b` saqlandi, `Summa` esa chaqiruv paytida oʻqildi — 200. «A» ni tanlagan
boʻlsangiz, receiver chaqiruv paytida olinadi deb oʻylagansiz (Python'dagi bound method shunday ishlaydi, pastda).
«C» ni tanlagan boʻlsangiz, `g` ham nusxa saqlaydi deb oʻylagansiz.

</details>

Toʻliq dastur, `savol/main.go`:

```go filename="savol/main.go" showLineNumbers
// savol: method value receiver'ni qachon oladi? Pauzadagi savol.
package main

import "fmt"

type Buyurtma struct {
	Summa int64
}

func (b Buyurtma) Jami() int64   { return b.Summa }
func (b *Buyurtma) JamiP() int64 { return b.Summa }

func main() {
	b := Buyurtma{Summa: 100}
	f := b.Jami  // value receiver: b ning nusxasi shu yerda olinadi
	g := b.JamiP // pointer receiver: &b shu yerda olinadi
	b.Summa = 200
	fmt.Println("f():", f())
	fmt.Println("g():", g())
}
```

```console
$ go run ./savol
f(): 100
g(): 200
```

| Qator | `b.Summa` | `f` saqlagan receiver | `g` saqlagan receiver |
|---|---|---|---|
| 14 | 100 | — | — |
| 15 | 100 | `Buyurtma{100}` nusxasi | — |
| 16 | 100 | `Buyurtma{100}` nusxasi | `&b` |
| 17 | 200 | `Buyurtma{100}` nusxasi (oʻzgarmadi) | `&b` → endi 200 |

JS va Python bilan solishtiramiz (kurs papkasida yoʻq). JS'da `o.total` ni oʻzgaruvchiga olsangiz, `this` yoʻqoladi;
uni `bind` bilan bogʻlash kerak:

```js
class Order {
  constructor(summa) { this.summa = summa; }
  total() { return this.summa; }
}

const o = new Order(100);
const f = o.total;
const g = o.total.bind(o);
o.summa = 200;
try {
  console.log("f():", f());
} catch (e) {
  console.log("f():", e.constructor.name + ":", e.message);
}
console.log("g():", g());
```

```console
$ node methodvalue.js
f(): TypeError: Cannot read properties of undefined (reading 'summa')
g(): 200
```

Python'da `o.total` — *bound method*: u obyektga havolani saqlaydi.

```python
class Order:
    def __init__(self, summa):
        self.summa = summa

    def total(self):
        return self.summa

o = Order(100)
f = o.total
o.summa = 200
print("f():", f())
```

```console
$ python3 methodvalue.py
f(): 200
```

| Til | `f := b.Jami` nimani saqlaydi | `b.Summa = 200` dan keyin `f()` |
|---|---|---|
| JS, `bind` siz | hech narsa: `this` yoʻqoladi | `TypeError` |
| JS, `bind(o)` bilan / Python bound method | obyektga havola | 200 |
| Go, pointer receiver | `&b` | 200 |
| Go, value receiver | `b` ning nusxasi | **100** |

`defer b.Chiqar()` ham receiver'ni xuddi shunday `defer` qatorida oladi. Bu uy vazifasining «qiyin» darajasi.

## Mutex va aralash receiver'lar: deadlock

Receiver'larni aralashtirishning eng xavfli holati. `sync.Mutex` — qulf: `Lock()` qulfni oladi, qulf band boʻlsa
boʻshaguncha kutadi, `Unlock()` qulfni boʻshatadi. Batafsil [GO-1.22](/lab/youtube/go#go-1-22) da. `myuteks/main.go`:

```go filename="myuteks/main.go" showLineNumbers
// myuteks: sync.Mutex bor struct'da value receiver — ATAYLAB xato. go vet ./myuteks buni ushlaydi.
// Qosh (pointer receiver) lock'ni ushlab turib Balansi (value receiver) ni chaqiradi:
// Balansi mutex'ning nusxasini oladi — nusxa ham qulflangan, Lock abadiy kutadi.
package main

import (
	"fmt"
	"sync"
)

type Hisob struct {
	mu     sync.Mutex
	balans int64
}

func (h *Hisob) Qosh(n int64) {
	h.mu.Lock()
	defer h.mu.Unlock()
	h.balans += n
	fmt.Println("yangi balans:", h.Balansi())
}

// Balansi: value receiver — mutex ham nusxalanadi.
func (h Hisob) Balansi() int64 {
	h.mu.Lock()
	defer h.mu.Unlock()
	return h.balans
}

func main() {
	var h Hisob
	h.Qosh(100)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 11–14 | `type Hisob struct {…}` | `Hisob` («hisob») — mutex va balans |
| 16 | `func (h *Hisob) Qosh(n int64)` | `Qosh` («qoʻsh») — pointer receiver |
| 17–18 | `h.mu.Lock()`, `defer h.mu.Unlock()` | qulfni oladi; `defer` (GO-1.09) uni funksiya oxirida boʻshatadi |
| 20 | `h.Balansi()` | qulf hali `Qosh` qoʻlida, `Balansi` chaqiriladi |
| 24 | `func (h Hisob) Balansi() int64` | `Balansi` («balansi») — **value receiver**: butun `Hisob` nusxalanadi, `mu` ham |
| 25 | `h.mu.Lock()` | nusxadagi mutex'ni qulflashga urinadi |

Nusxa olingan paytda asl mutex qulflangan edi. Mutex — oddiy maydonlardan iborat struct, shuning uchun nusxa ham
«qulflangan» holatda. Uni hech kim boʻshatmaydi, `Lock` abadiy kutadi. `2>&1 | head -1` xato oqimini ham olib,
faqat birinchi qatorni koʻrsatadi:

```console
$ go run ./myuteks 2>&1 | head -1
fatal error: all goroutines are asleep - deadlock!
```

*all goroutines are asleep - deadlock!* — «hamma goroutine'lar uxlab qoldi: **deadlock**». Goroutine — Go'ning
yengil oqimi; bu dasturda bittasi bor (`main`), u esa oʻzini oʻzi kutib qoldi. Runtime buni koʻrib, dasturni
`fatal error` bilan toʻxtatdi (GO-1.09). `yangi balans:` hech qachon chiqmadi.

Bu xatoni `go vet` ushlaydi (uning `copylocks` tekshiruvi):

```console
$ go vet ./myuteks
myuteks/main.go:24:9: Balansi passes lock by value: github.com/abdurahmon27/go-backend-uz/lessons/012-methods-receivers/myuteks.Hisob contains sync.Mutex
```

24-qator: *Balansi passes lock by value: … Hisob contains sync.Mutex* — «`Balansi` qulfni qiymat sifatida
(nusxalab) uzatadi: `Hisob` ichida `sync.Mutex` bor». Mutex hujjatida ham yozilgan:

```console
$ go doc sync.Mutex | grep copied
    A Mutex must not be copied after first use.
```

«Mutex birinchi ishlatilgandan keyin nusxalanmasligi kerak.» **Tuzatish:** `func (h *Hisob) Balansi()`. Agar
`Hisob` ning hamma metodi value receiver boʻlganda, deadlock boʻlmasdi. Lekin `Qosh` ham `Tola` kabi nusxaga
yozardi va mutex hech narsani himoya qilmasdi.

## Qaysi receiver'ni tanlash kerak?

Go FAQ (*Should I define methods on values or pointers?*) va Go wiki CodeReviewComments (*Receiver Type*) shunday
maslahat beradi:

| Holat | Receiver | Nega |
|---|---|---|
| metod receiver'ni oʻzgartiradi | `*T` | value receiver nusxani oʻzgartiradi (`Tola`) |
| struct'da `sync.Mutex` bor | `*T` | mutex nusxalanmasligi kerak (`myuteks`) |
| struct katta | `*T` | har chaqiruvda butun struct nusxalanmasin |
| kichik, oʻzgarmas qiymat (`time.Time` kabi), oddiy tur | `T` | arzon va tushunarli; FAQ: oddiy turlar, slice va kichik struct uchun value receiver *"very cheap"* |
| tur map, funksiya yoki channel ([GO-1.21](/lab/youtube/go#go-1-21)) | `T` | ular ichida allaqachon havola bor, pointer kerak emas |
| butun tur uchun | bittasi | receiver'ni har bir metod uchun emas, tur uchun tanlang, aralashtirmang |
| ikkilansangiz | `*T` | wiki: *"when in doubt, use a pointer receiver"* |

Standart kutubxonada ikkala yondashuv ham bor. `time.Time` — kichik qiymat (24 bayt). Uning value receiver'li
metodlarini sanaymiz (`grep -c` — mos qatorlar sonini chiqaradi):

```console
$ go doc -all time | grep -cE '^func \(t Time\)'
43
$ go doc -all time | grep -E '^func \(t \*Time\)'
func (t *Time) GobDecode(data []byte) error
func (t *Time) UnmarshalBinary(data []byte) error
func (t *Time) UnmarshalJSON(data []byte) error
func (t *Time) UnmarshalText(data []byte) error
```

43 ta value receiver, faqat 4 ta pointer receiver. Bu toʻrttasi maʼlumotni (JSON, matn, baytlar) oʻqib, vaqtning
oʻzini oʻzgartiradi. Demak «aralashtirmang» qoidasining ham asosli istisnosi bor. `go doc time.Time` ham aytadi:
vaqtni odatda pointer emas, qiymat sifatida saqlang va uzating.

`strings.Builder` da esa hamma metod pointer receiver:

```console
$ go doc strings.Builder
package strings // import "strings"

type Builder struct {
	// Has unexported fields.
}
    A Builder is used to efficiently build a string using Builder.Write methods.
    It minimizes memory copying. The zero value is ready to use. Do not copy a
    non-zero Builder.

func (b *Builder) Cap() int
func (b *Builder) Grow(n int)
func (b *Builder) Len() int
func (b *Builder) Reset()
func (b *Builder) String() string
func (b *Builder) Write(p []byte) (int, error)
func (b *Builder) WriteByte(c byte) error
func (b *Builder) WriteRune(r rune) (int, error)
func (b *Builder) WriteString(s string) (int, error)
```

*Do not copy a non-zero Builder* — «ichiga yozilgan Builder'ni nusxalamang», xuddi mutex kabi. Yozuv metodlari
nusxani tekshiradi (`strings/builder.go` dagi `copyCheck`). Faqat oʻqiydigan `Len` buni tekshirmaydi, lekin u ham
pointer receiver: tur boʻyicha izchillik.

## Koʻp uchraydigan xatolar

**1. Value receiver'li metod receiver'ni oʻzgartiradi deb kutish.** Bu mavzuning eng keng tarqalgan notoʻgʻri
tasavvuri, ayniqsa Python, JS yoki PHP'dan kelganlarda: `self` / `this` doim havola, Go'dagi `(b T)` esa nusxa.
«Metod va receiver» boʻlimida koʻrdik: `Tola` chaqirildi, `Tolandi` `false` boʻlib qoldi, kompilyator ham, `go vet`
ham jim. **Tuzatish:** `func (b *Buyurtma) Tola()`. Bunday xatoni staticcheck `SA4005` bilan ushlaydi, uni CI'ga
qoʻshing.

**2. Map elementida pointer metodni chaqirish.** `m["a1"].Tola()` → `cannot call pointer method Tola on Buyurtma`
(«Jumboq» boʻlimi). Xabarni oʻqish: *pointer method* — receiver'i `*T`, *on Buyurtma* — sizda esa `T` qiymat bor va
uning manzilini olib boʻlmaydi. Funksiya natijasi (`yarat().Tola()`) ham xuddi shu xatoni beradi. **Tuzatish:**
qiymatni oʻzgaruvchiga oling, oʻzgartiring va qaytarib yozing, yoki map'da pointer saqlang
(`map[string]*Buyurtma`).

**3. `String()` ni pointer receiver'da yozib, qiymatni chop etish.** `fmt.Println(b)` `{50000 false}` chiqaradi va
`go vet` jim («Method set va `fmt.Stringer`» boʻlimi). `Printf` bilan esa `go vet` ushlaydi. Bu misol kurs papkasida
yoʻq, alohida ishga tushirildi:

```go
package main

import "fmt"

type Buyurtma struct{ Summa int64 }

func (b *Buyurtma) String() string { return fmt.Sprint(b.Summa) }

func main() {
	b := Buyurtma{Summa: 50_000}
	fmt.Printf("%s\n", b)
}
```

```console
$ go run printfvet/main.go
{%!s(int64=50000)}
$ go vet printfvet/main.go
printfvet/main.go:11:14: fmt.Printf format %s has arg b of wrong type command-line-arguments.Buyurtma
```

`{%!s(int64=50000)}` — `fmt` ning «`%s` bu qiymatga mos emas» degan belgisi. Vet xabari: *format %s has arg b of
wrong type* — «`%s` formatiga notoʻgʻri turdagi `b` argumenti berilgan». **Tuzatish:** `String` ni value receiver'da
yozing (u receiver'ni oʻzgartirmaydi) yoki manzilni bering: `fmt.Println(&b)`.

**4. Mutex bor struct'da value receiver.** Deadlock yoki himoyasiz yozuv («Mutex va aralash receiver'lar» boʻlimi).
**Tuzatish:** hamma metod pointer receiver; `go vet` ni har doim ishga tushiring, u `passes lock by value` ni
ushlaydi.

**5. `nil` pointer orqali value receiver'li metodni chaqirish.** `p.Jami()` — `(*p).Jami()`, `p` `nil` boʻlsa panic
(«Go `&` va `*` ni oʻzi qoʻshadi» boʻlimi). **Tuzatish:** pointer'ni tekshiring yoki metodni pointer receiver'da
yozib, `nil` ni metod ichida tekshiring (`JamiP` kabi).

**6. Embedding'ni meros deb oʻylash.** Koʻtarilgan metodning receiver'i ichki struct («Embedding» boʻlimi). `Kochir`
`Mijoz` ni koʻrmaydi va uning metodlarini «override» qilib boʻlmaydi. **Tuzatish:** embedding'ni delegatsiya deb
oʻqing: `a.Kochir(…)` = `a.Manzil.Kochir(…)`.

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** Nega `s[0].Tola()` kompilyatsiya boʻladi, `m["a1"].Tola()` esa yoʻq (`Tola` pointer receiver'da)?

<details>
<summary>Javob</summary>

`Tola` `*Buyurtma` ning method set'ida. `x.Tola()` ni Go `(&x).Tola()` ga aylantiradi, lekin faqat `x` addressable
boʻlsa. Slice elementi addressable, map elementi esa yoʻq: map oʻsganda runtime elementlarni yangi jadvalga koʻchiradi,
eski manzil eskirgan nusxaga qarab qolardi.

</details>

**2.** `T` va `*T` ning method set'ida qaysi metodlar bor? `String()` `*Buyurtma` da eʼlon qilingan boʻlsa,
`var s fmt.Stringer = &b` kompilyatsiya boʻladimi?

<details>
<summary>Javob</summary>

`T` da — receiver'i `T` boʻlgan metodlar; `*T` da — receiver'i `T` va `*T` boʻlganlar. `&b` ning turi `*Buyurtma`,
uning method set'ida `String` bor, demak **ha**, kompilyatsiya boʻladi. `= b` esa `method String has pointer
receiver` xatosini beradi.

</details>

**3.** Bu kod nima chiqaradi? **A)** `200 200` · **B)** `100 200` · **C)** `100 100`

```go
type Buyurtma struct{ Summa int64 }

func (b Buyurtma) Jami() int64 { return b.Summa }

b := Buyurtma{Summa: 100}
p := &b
f := p.Jami // Jami: value receiver
b.Summa = 200
fmt.Println(f(), p.Jami())
```

<details>
<summary>Javob</summary>

**B: `100 200`.** `p.Jami` — `(*p).Jami` (spetsifikatsiya, *Method values*). Method value yaratilganda receiver
hisoblanib saqlanadi: `*p`, yaʼni `b` ning shu paytdagi nusxasi (100). `p.Jami()` esa chaqiruv paytida `*p` ni
oʻqiydi: 200. «A» ni tanlagan boʻlsangiz, `f` pointer'ni saqlaydi deb oʻylagansiz: pointer orqali olingan boʻlsa
ham, value receiver nusxa saqlaydi.

Toʻliq dastur (kurs papkasida yoʻq, alohida ishga tushirildi):

```go
package main

import "fmt"

type Buyurtma struct{ Summa int64 }

func (b Buyurtma) Jami() int64 { return b.Summa }

func main() {
	b := Buyurtma{Summa: 100}
	p := &b
	f := p.Jami // Jami: value receiver
	b.Summa = 200
	fmt.Println(f(), p.Jami())
}
```

```console
$ go run ptrval/main.go
100 200
```

</details>

**4.** Struct'da `sync.Mutex` bor. Faqat oʻqiydigan `Balansi` metodi uchun qaysi receiver kerak va nega?

<details>
<summary>Javob</summary>

**Pointer receiver.** Value receiver butun struct'ni, mutex'ni ham nusxalaydi. Qulf band paytda olingan nusxa ham
qulflangan boʻladi: `myuteks` da bu deadlock berdi. `go vet` buni `passes lock by value` deb ushlaydi. Bundan
tashqari, turda receiver'larni aralashtirmaslik kerak.

</details>

**5.** [GO-1.11](/lab/youtube/go/go-1-11) dan: `p := &s[0]`, keyin sigʻim yetmagan `append`. `p.Tolandi = true` dan keyin
`s[0].Tolandi` nima boʻladi va bu bugungi map qoidasiga qanday bogʻliq?

<details>
<summary>Javob</summary>

`false`. `append` yangi massiv ajratdi, `p` esa eski massivga qarab qoldi. Map'da xuddi shu xavf bor (oʻsish
elementlarni koʻchiradi), shuning uchun Go map elementining manzilini olishni kompilyatsiya paytida taqiqlaydi.
Slice'da esa bu xato runtime'da jim yuz beradi.

</details>

🟢 **Oson:** nega `3` emas, `0` chiqadi? Toping va tuzating.

```go
type Hisoblagich struct{ n int }
func (h Hisoblagich) Oshir()     { h.n++ }
func (h Hisoblagich) Qiymat() int { return h.n }
// var h Hisoblagich; h.Oshir(); h.Oshir(); h.Oshir(); fmt.Println(h.Qiymat())
```

<details>
<summary>Javob</summary>

`Oshir` («oshir») value receiver: har chaqiruvda nusxa oshiriladi, `h` esa 0 da qoladi. Tuzatish — pointer
receiver. Izchillik uchun `Qiymat` («qiymat») ham pointer receiver. staticcheck xato variantni `SA4005` bilan
ushlaydi.

```go filename="homework/oson/main.go" showLineNumbers
// oson (javob): Hisoblagich nega 0 da qoladi? Value receiver nusxani oshiradi.
// Tuzatish: pointer receiver. staticcheck xato variantni SA4005 bilan ushlaydi.
package main

import "fmt"

type Hisoblagich struct{ n int }

// Xato edi: func (h Hisoblagich) Oshir() { h.n++ }
func (h *Hisoblagich) Oshir() { h.n++ }

func (h *Hisoblagich) Qiymat() int { return h.n } // izchillik: hamma metod pointer receiver

func main() {
	var h Hisoblagich
	h.Oshir()
	h.Oshir()
	h.Oshir()
	fmt.Println(h.Qiymat()) // 3
}
```

🟡 **Oʻrta:** `homework/orta/main.go` dagi 1–8 raqamli qatorlardan qaysilari kompilyatsiya boʻladi? Avval oʻzingiz

```go filename="homework/orta/main.go" showLineNumbers
// orta: qaysi qatorlar kompilyatsiya boʻladi? Avval oʻzingiz javob bering, keyin tekshiring:
//
//	go build -o /dev/null ./homework/orta
//
// Bu papka ATAYLAB kompilyatsiya boʻlmaydi. Javob — README'da.
package main

type Nuqta struct{ X, Y int }

func (n Nuqta) Uzunlik() int { return n.X*n.X + n.Y*n.Y }
func (n *Nuqta) Sur(d int)   { n.X += d }

func yangi() Nuqta   { return Nuqta{1, 2} }
func ikki() [2]Nuqta { return [2]Nuqta{} }

func main() {
	nuqtalar := []Nuqta{{1, 2}}

	mp := map[string]*Nuqta{"a": {}}

	_ = m["a"].Uzunlik()  // 4

	f := m["a"].Sur       // 6
	ikki()[0].Sur(1)      // 7
	mp["a"].X = 5         // 8
	_ = f

```

- **7** (27-qator): funksiya qaytargan massiv addressable emas, demak uning elementi ham.

🟠 **Qiyin:** `b := Buyurtma{Summa: 100}; defer b.Chiqar(); defer func() { b.Chiqar() }(); b.Summa = 200`
(`Chiqar` — value receiver). Nima chiqadi va qaysi tartibda?

<details>
<summary>Javob</summary>

**`200`, keyin `100`.** `defer` lar teskari tartibda (LIFO) ishlaydi: avval closure, keyin method value.
`defer b.Chiqar()` receiver'ni (nusxa, 100) `defer` qatorida oladi, «Pauza» boʻlimidagi `f := b.Jami` kabi.
Closure esa `b` ni funksiya oxirida, chaqiruv paytida oʻqiydi (200).

```go filename="homework/qiyin/main.go" showLineNumbers
// qiyin (javob): defer receiver'ni qachon oladi?
// defer b.Chiqar()            — method value: receiver (b ning nusxasi) defer qatorida olinadi → 100
// defer func() { b.Chiqar() }() — closure: b funksiya oxirida, chaqiruv paytida oʻqiladi → 200
// Tartib: defer LIFO, shuning uchun avval closure (200), keyin method value (100).
package main

import "fmt"

type Buyurtma struct{ Summa int64 }

func (b Buyurtma) Chiqar() { fmt.Println(b.Summa) }

func main() {
	b := Buyurtma{Summa: 100}
	defer b.Chiqar()
	defer func() { b.Chiqar() }()
	b.Summa = 200
}
```

```console
$ go run ./homework/qiyin
200
100
```

</details>

🔴 **Guru:** `type A struct{ Manzil }` va `type B struct{ *Manzil }`. `Kochir` pointer receiver'da. `A{}`, `&A{}`,
`B{}`, `&B{}` dan qaysilari `interface{ Kochir(string) }` ni qanoatlantiradi? Kompilyator bilan isbotlang.

<details>
<summary>Javob</summary>

**`&A{}`, `B{}`, `&B{}` — ha; `A{}` — yoʻq.** `A` ichida `Manzil` (qiymat): `*Manzil` receiver'li `Kochir` faqat
`*A` ning method set'iga koʻtariladi. `B` ichida `*Manzil`: hamma metod `B` ga ham, `*B` ga ham koʻtariladi.
`var _ Kochiruvchi = A{}` qatori izohdan chiqarilsa, kompilyator fayl boshidagi izohda yozilgan xatoni beradi:
`A does not implement Kochiruvchi (method Kochir has pointer receiver)`. `B{}` ichidagi `*Manzil` `nil` boʻlsa,
`Kochir` chaqiruvi panic beradi.

```go filename="homework/guru/main.go" showLineNumbers
// guru (javob): embedding va method set. Kochiruvchi interface'ini kim qanoatlantiradi?
//
//	type A struct{ Manzil }   — A ning method set'ida Toliq bor, Kochir yoʻq; *A da ikkalasi bor.
//	type B struct{ *Manzil }  — B va *B ning method set'ida ikkalasi ham bor.
//
// var _ Kochiruvchi = A{} kompilyatsiya boʻlmaydi:
//
//	cannot use A{} (value of struct type A) as Kochiruvchi value in variable declaration:
//	A does not implement Kochiruvchi (method Kochir has pointer receiver)
package main

import "fmt"

type Manzil struct{ Shahar string }

func (m Manzil) Toliq() string         { return m.Shahar }
func (m *Manzil) Kochir(shahar string) { m.Shahar = shahar }

type Kochiruvchi interface{ Kochir(string) }

type A struct{ Manzil }
type B struct{ *Manzil }

var (
	_ Kochiruvchi = &A{} // ✅
	_ Kochiruvchi = B{}  // ✅ (lekin B{}.Manzil == nil: Kochir chaqirilsa panic)
	_ Kochiruvchi = &B{} // ✅
	// _ Kochiruvchi = A{} // ❌ yuqoridagi xato
)

func main() {
	b := B{Manzil: &Manzil{Shahar: "Toshkent"}}
	var k Kochiruvchi = b // B nusxalanadi, lekin ichidagi pointer bitta Manzil'ga qaraydi
	k.Kochir("Buxoro")
	fmt.Println(b.Toliq()) // Buxoro
}
```

`Kochiruvchi` («koʻchiruvchi») — `Kochir` metodi bor har qanday tur. `var _ Kochiruvchi = …` — qiymatni hech qayerda
ishlatmay, faqat kompilyatorga tekshirtirish usuli.

```console
$ go run ./homework/guru
Buxoro
```

`b` `k` ga nusxalandi, lekin nusxadagi `*Manzil` oʻsha manzilga qaraydi. Shuning uchun `k.Kochir` `b` ning shahrini
ham oʻzgartirdi.

</details>
