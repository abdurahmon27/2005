## What you will learn

How many letters are in the Uzbek word «oʻzbek» ("Uzbek")? Five: oʻ, z, b, e and k. But if you ask Go for the
length of this word, it says **seven**. Python's `len` and JavaScript's `.length` say 6 for the same word. In this
lesson we find out where the seven comes from. Then we see how this affects Uzbek text: for example, why a site's
search cannot find the word «Oʻzbekiston» ("Uzbekistan").

**One idea:** a computer stores every character as a number in bytes. An ordinary keyboard character takes one byte,
but the turned comma (ʻ) in oʻ takes two. `len` counts bytes, not letters. So words that look the same can contain
different bytes, and Go can say they are not equal.

At the end of the lesson you will:

- be able to explain why «oʻzbek» has 5 letters, 6 runes and 7 bytes;
- say which numbers `len` and `utf8.RuneCountInString` print, without running the program;
- know how Go's `len` differs from Python's `len` and JavaScript's `.length`;
- tell four kinds of apostrophe apart and know which one is correct for oʻ and gʻ;
- explain why Go says two words that look the same are not equal, and fix it with `strings.ReplaceAll`.

Today there are three new words:

| Word | Plain meaning | Go term |
|---|---|---|
| `len` (length) | the number of **bytes** in a string, not the number of letters | len (length) |
| rune | the Unicode number of a character: `ʻ` → 699 | rune |
| UTF-8 | the rule that writes a character's number as bytes (1 to 4) | UTF-8 |

Two helper words also appear: **Unicode** (the numbered list of all the world's characters) and
**`strings.ReplaceAll`** (a tool that replaces one character with another everywhere in a string).

On this page three words always mean the same thing:

| Word | What it means | How many in «oʻzbek» |
|---|---|---|
| letter | a letter of the alphabet: oʻ is one letter | 5: oʻ, z, b, e, k |
| character | one sign you see on the screen: oʻ is two characters on screen | 6: o, ʻ, z, b, e, k |
| byte | a small place in memory | 7 |

```text

 8 zeros or ones          int8 is 1 byte too          every letter has a number
```

The `01111010` above is exactly 122, that is, the letter `z`.

</details>

## Every character has a number: Unicode

There are very many characters in the world: Latin and Cyrillic letters, Chinese characters, emoji. For a computer to
store each of them as a number, each character must get a number. All characters are numbered in one big list. This
list is called **Unicode**.

| Character | Unicode number | Fits in one byte? |
|---|---|---|
| `z` | 122 | yes: 122 &lt; 256 |
| `ʻ` (the turned comma in oʻ) | 699 | no: 699 > 255 |
| all characters in Unicode | 172 808 | no |

The sign in the letter oʻ looks like a comma turned upside down, so we call it the **turned comma**. Unicode version
18.0 has 172 808 characters. One byte holds only 256 different numbers: 0 to 255. So a character with a big number
does not fit in one byte.

## Bigger number, more bytes: UTF-8

That is why a character with a big number is written **in several bytes**. Characters of an ordinary English keyboard
take one byte each, but the turned comma in oʻ takes two. The rule that writes a character as bytes is called
**UTF-8**. The rule looks at the character's number:

| Unicode number of the character | Bytes | Example |
|---|---|---|
| 0 – 127 | 1 | all characters of an English keyboard: `z` (122), `'` (39) |
| 128 – 2 047 | 2 | `ʻ` turned comma (699) |
| 2 048 – 65 535 | 3 | `‘` and `’` (8216 and 8217): we will see them below |
| more than 65 536 | 4 | many emoji, for example 😀 |

This table is in the official description of UTF-8 (RFC 3629). Go code is written in UTF-8 too. So `"oʻzbek"` in
quotes is stored in memory as bytes written by exactly this rule.

## «oʻzbek» in memory: 7 bytes and `len`

How does the word «oʻzbek» sit in memory? `o` is one byte, the turned comma is two bytes, `z`, `b`, `e` and `k` are
one each:

| Byte | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| Which character | `o` | `ʻ` (start) | `ʻ` (continuation) | `z` | `b` | `e` | `k` |

That is **seven bytes** in total. To get the length of a string in Go, we write **`len` (length)**. It is short for
the English word *length*. `len` counts not letters but exactly these **bytes**. That is why Go says "seven" for a
five-letter word.

Go's official rules (the Go spec) say the same: *"The number of bytes is called the length of the string"*.

## Characters on the screen: rune

Now let's look at the characters on the screen: `o`, `ʻ`, `z`, `b`, `e` and `k`. In the alphabet oʻ is one letter,
but on the screen it is two characters. Every character has a Unicode number. In Go this number of a character is
called a **rune**.

| Character | From which letter | Rune (Unicode number) | Bytes |
|---|---|---|---|
| `o` | oʻ | 111 | 1 |
| `ʻ` | oʻ | 699 | 2 |
| `z` | z | 122 | 1 |
| `b` | b | 98 | 1 |
| `e` | e | 101 | 1 |
| `k` | k | 107 | 1 |
| **total** | **5 letters** | **6 runes** | **7 bytes** |

So «oʻzbek» has five letters, and one rune per character: six. Note two things:

- a rune is not a letter: oʻ is one letter but two runes;
- a rune is not a byte either: `ʻ` is one rune but two bytes.

## Checking it in Go: `len` and `utf8.RuneCountInString`

Now let's check this in Go. Here is `uzunlik/main.go` from the course folder:

```go filename="uzunlik/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "oʻzbek"
	fmt.Println(len(s))                    // baytlar soni
	fmt.Println(utf8.RuneCountInString(s)) // rune'lar (belgilar) soni
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `package main` | the program template, as in the first lesson |
| 3–6 | `import (` `"fmt"` `"unicode/utf8"` `)` | connects two ready-made toolboxes (packages): `fmt` and `unicode/utf8`. With two of them, they are written one under the other in parentheses |
| 8 | `func main() {` | the program starts here |
| 9 | `s := "oʻzbek"` | a new label `s`; its value is the string «oʻzbek» |
| 10 | `fmt.Println(len(s))` | prints the number of bytes in `s` |
| 11 | `fmt.Println(utf8.RuneCountInString(s))` | prints the number of runes in `s` |
| 12 | `}` | the end of `main` and of the program |

`RuneCountInString` means "count the runes in a string". It lives in the ready-made toolbox `utf8`, so at the top of
the file we connected it with `import`, like `fmt`. In the code the toolbox name is written short: `utf8`. After `//`
come comments ("number of bytes", "number of runes (characters)").

In memory:

| Label | Type | Value | Bytes | Runes |
|---|---|---|---|---|
| `s` | `string` | `"oʻzbek"` | 7 | 6 |

If we run the program with `go run`, which numbers do the two lines print? Remember the byte table.
**A)** `5` and `5` · **B)** `7` and `6` · **C)** `6` and `7`

<details>
<summary>Answer</summary>

**B: `7` and `6`.** The first line is `len`, the number of bytes: 7. The second is the number of runes: 6. If you
chose "`5` and `5`", you thought both count letters. If you chose "`6` and `7`", you swapped the numbers: `ʻ` is one
rune but two bytes, so there are more bytes.

</details>

```console
$ go run uzunlik/main.go
7
6
```

In short: `len` counts bytes, not letters.

## Comparing with Python and JavaScript

If you come from another language, here is a trap: "length" counts something different in each language. We checked
the same two strings in Python and Node.js (these commands are not in the course folder):

```console
$ python3 -c 'print(len("oʻzbek"), len("😀"))'
6 1
$ node -e 'console.log("oʻzbek".length, "😀".length)'
6 2
```

| Language and expression | What it counts | `"oʻzbek"` | `"😀"` |
|---|---|---|---|
| Go: `len(s)` | UTF-8 bytes | 7 | 4 |
| Go: `utf8.RuneCountInString(s)` | runes (Unicode numbers) | 6 | 1 |
| Python: `len(s)` | Unicode numbers | 6 | 1 |
| JavaScript / TypeScript: `s.length` | UTF-16 units | 6 | 2 |

So Python's `len` matches Go's `utf8.RuneCountInString`, not Go's `len`. JavaScript counts UTF-16 units: a character
with a number above 65 535 (😀) takes two units there. The Go values for `"😀"` in the table come from this program
(it is not in the course folder either):

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	fmt.Println(len("😀"), utf8.RuneCountInString("😀"))
}
```

```console
$ go run emoji/main.go
4 1
```

4 bytes is the last row of the UTF-8 table: the number of 😀 is 128 512.

## One word, four spellings

The turned comma is hard to find on an ordinary keyboard. So people write the Uzbek word in four ways:

| Sign | Name | Unicode number |
|---|---|---|
| `'` | keyboard apostrophe (the ordinary key) | 39 |
| `ʻ` | turned comma ✅ | 699 |
| `’` | right curly apostrophe | 8217 |
| `‘` | left curly apostrophe | 8216 |

To the eye they are almost the same. But the curly apostrophes have an even bigger Unicode number than the turned
comma, so they take more space. Which one is correct? Unicode's data about languages (CLDR, the file `uz.xml`) gives
the **turned comma** `ʻ` for oʻ and gʻ.

`tort/main.go` ("four") prints `len` and the rune count of all four spellings:

```go filename="tort/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

// Bitta soʻz, toʻrt xil apostrof. Koʻzga deyarli bir xil, baytlari har xil.
func main() {
	sozlar := []string{
		"o'zbek", // U+0027 APOSTROPHE (klaviaturadagi)
		"oʻzbek", // U+02BB MODIFIER LETTER TURNED COMMA (teskari vergul, toʻgʻrisi)
		"o’zbek", // U+2019 RIGHT SINGLE QUOTATION MARK (oʻng jingalak)
		"o‘zbek", // U+2018 LEFT SINGLE QUOTATION MARK (chap jingalak)
	}
	for _, s := range sozlar {
		fmt.Printf("%s  len=%d  rune=%d\n", s, len(s), utf8.RuneCountInString(s))
	}
}
```

New lines:

| Line | Code | What it does |
|---|---|---|
| 10–15 | `sozlar := []string{` … `}` | `sozlar` ("words") is a list of four strings, like an array in JS or a list in Python. In Go it is called a slice, more in [GO-1.08](/lab/youtube/go/go-1-08/en) |
| 11–14 | comments | the English Unicode name of each apostrophe. The comments call the curly apostrophe «jingalak» ("curly"); it is the same thing |
| 16 | `for _, s := range sozlar {` | puts each word into `s` in turn: like `for (const s of sozlar)` in JS or `for s in sozlar` in Python. `range` gives an index and a value; `_` throws the index away. This form of `for` is in [GO-1.05](/lab/youtube/go/go-1-05/en) |
| 17 | `fmt.Printf(…)` | prints by a template, like `printf` in C: `%s` — a string, `%d` — a number, `\n` — a new line |

What is `len` on the four lines? Remember the UTF-8 table.
**A)** `6 · 7 · 8 · 8` · **B)** `7 · 7 · 7 · 7` · **C)** `6 · 6 · 6 · 6`

<details>
<summary>Answer</summary>

**A: `6 · 7 · 8 · 8`.** The keyboard apostrophe is one byte (number 39), the turned comma is two bytes (699), and the
curly apostrophes take three each, because their number is big (8217 and 8216). The other five characters are one
byte each in all of them. If you chose "`7 · 7 · 7 · 7`", you thought any apostrophe is two bytes. If you chose
"`6 · 6 · 6 · 6`", you thought `len` counts the characters on the screen.

</details>

```console
$ go run tort/main.go
o'zbek  len=6  rune=6
oʻzbek  len=7  rune=6
o’zbek  len=8  rune=6
o‘zbek  len=8  rune=6
```

The rune count is the same in all four: 6. Each apostrophe is one character, so one rune. Only the number of bytes it
takes is different.

## Looks the same, different for Go

Now a common mistake. In a list on a site, «Oʻzbekiston» is stored with the turned comma. A user typed it into the
search box with the keyboard apostrophe. Here is `teng/main.go` ("equal"):

```go filename="teng/main.go" showLineNumbers
package main

import "fmt"

func main() {
	saytda := "Oʻzbekiston"  // saytdagi roʻyxatda: ʻ (U+02BB)
	qidiruv := "O'zbekiston" // foydalanuvchi klaviaturadan yozdi: ' (U+0027)
	fmt.Println(saytda == qidiruv)
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `saytda := "Oʻzbekiston"` | the label `saytda` ("on the site") points to the word on the site: with the turned comma |
| 7 | `qidiruv := "O'zbekiston"` | the label `qidiruv` ("search") points to the word the user typed: with the keyboard apostrophe |
| 8 | `fmt.Println(saytda == qidiruv)` | asks with two equals signs: are they equal? The answer is `true` or `false` |

In memory:

| Label | Value | Apostrophe | Bytes |
|---|---|---|---|
| `saytda` | `"Oʻzbekiston"` | `ʻ` (699, 2 bytes) | 12 |
| `qidiruv` | `"O'zbekiston"` | `'` (39, 1 byte) | 11 |

If we run the program in the `teng` folder with `go run`, what does Go say? Hint: Go compares strings by their bytes.
**A)** `true` · **B)** `false` · **C)** compile error

<details>
<summary>Answer</summary>

**B: `false`.** Go compares strings by bytes, not by how they look. The turned comma and the keyboard apostrophe are
different characters: both their numbers and their bytes are different. Even the byte counts differ: 12 and 11. If
you chose "`true`", you trusted how the words look on the screen. If you chose "compile error": there is no error in
the code, and two strings can be compared with `==`. The result is simply `false`.

</details>

```console
$ go run teng/main.go
false
```

Go's official rules also compare strings byte by byte. The site's search compares the same way. As a result, the user
cannot find something that is on the site.

## The fix: `strings.ReplaceAll`

The solution: before comparing, bring the apostrophes to one kind. Go comes with another ready-made toolbox,
`strings`. It has `ReplaceAll`: "replace all". Here is `tuzat/main.go` ("fix"):

```go filename="tuzat/main.go" showLineNumbers
package main

import (
	"fmt"
	"strings"
)

func main() {
	saytda := "Oʻzbekiston"
	qidiruv := "O'zbekiston"
	qidiruv = strings.ReplaceAll(qidiruv, "'", "ʻ") // har bir ' (U+0027) ni ʻ (U+02BB) ga almashtir
	fmt.Println(saytda == qidiruv)
	fmt.Println(strings.ReplaceAll("ma'no", "'", "ʻ")) // cheklov: toʻgʻrisi maʼno (ʼ U+02BC, tutuq belgisi)
}
```

| Line | Code | What it does |
|---|---|---|
| 3–6 | `import (` `"fmt"` `"strings"` `)` | connects the toolboxes `fmt` and `strings` |
| 9–10 | `saytda := …`, `qidiruv := …` | the same two labels as in `teng/main.go` |
| 11 | `qidiruv = strings.ReplaceAll(qidiruv, "'", "ʻ")` | replaces every keyboard apostrophe in `qidiruv` with the turned comma. Inside the parentheses are three things: the string, in the first quotes the character to replace, in the second the new character. The result goes under `qidiruv` again (`=` — "let it be") |
| 12 | `fmt.Println(saytda == qidiruv)` | asks again: are they equal now? |
| 13 | `fmt.Println(strings.ReplaceAll("ma'no", "'", "ʻ"))` | does the same replacement in the word «maʼno» ("meaning") and prints the result |

The code comments say: on line 11 "replace every ' with ʻ", on line 13 "limit: the correct form is maʼno (ʼ U+02BC,
tutuq belgisi)".

In memory:

| After line | `saytda` | `qidiruv` |
|---|---|---|
| 10 | `"Oʻzbekiston"` (12 bytes) | `"O'zbekiston"` (11 bytes) |
| 11 | `"Oʻzbekiston"` (12 bytes) | `"Oʻzbekiston"` (12 bytes) |

Now let's run the program in the `tuzat` folder. What do lines 12 and 13 print?
**A)** `true` · «maʼno» changes too · **B)** `true` · «maʼno» does not change · **C)** `false` · «maʼno» does not change

<details>
<summary>Answer</summary>

**A: `true`, and «maʼno» changes too.** After line 11 the bytes of the two words are the same, so `true`. But
`ReplaceAll` does not know what a word means: it turns every keyboard apostrophe into the turned comma, including the
one in `ma'no`. If you chose "B", you thought `ReplaceAll` only touches the apostrophe in oʻ and gʻ. If you chose "C",
you did not count the replacement on line 11.

</details>

```console
$ go run tuzat/main.go
true
maʻno
```

Look at the second line: the apostrophe in the word «maʼno» also became a turned comma. But a different sign is needed
there: the **tutuq belgisi** (the glottal-stop sign) `ʼ` (Unicode number 700). It is a separate sign of Uzbek writing,
not the turned comma of oʻ and gʻ. To the eye they are almost the same, but their numbers differ.

So do this work in one place: before saving and before searching, with the same rule. A fuller clean-up program is in
the course folder:
[tozala/](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/004-strings-utf8/tozala) ("clean"). It turns
an apostrophe after `o`/`g` into `ʻ`, and one between two other letters into `ʼ`. It has its limits too:
`Go'da` → `Goʻda` (an apostrophe before an Uzbek suffix). It is written with a function and `[]rune`; we cover these
parts of Go in later lessons.

## Going deeper (optional): the bits of `ʻ` and slicing by bytes

If you are just starting, read this section later. The rest of the lesson does not depend on it.

**How `ʻ` is written in two bytes.** The number of the turned comma is 699. In binary that is `1010111011`, that is,
10 bits (we saw bits in the "Going deeper" part of [GO-1.02](/lab/youtube/go/go-1-02/en)). The two-byte template of UTF-8 is: the
first byte starts with `110`, the second with `10`. The bits of the number go into the remaining places (`x`):

```text
template:     110xxxxx   10xxxxxx      (11 free places)
699:            01010      111011      (a 0 added in front: 10 bits → 11)
result:       11001010   10111011
hex:             ca         bb
```

**Hexadecimal** notation writes a byte with two signs: the digits 0–9 and the letters a–f (a = 10, …, f = 15). For
example, `ca` = 12 × 16 + 10 = 202. `bitlar/main.go` ("bits") shows this:

```go filename="bitlar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	r := 'ʻ'
	fmt.Printf("%U = %d = %b (%d bit)\n", r, r, r, len(fmt.Sprintf("%b", r)))
	b := []byte(string(r))
	// 2 baytli qolip: 110xxxxx 10xxxxxx, 11 ta x ga raqamning bitlari
	fmt.Printf("110|%05b  10|%06b  = % x\n", r>>6, r&0x3f, b)
}
```

- **Line 6:** single quotes hold exactly one character. Under `r` there is not a string but the rune of this
  character, that is, 699.
- **Line 7:** `%U` prints the number in Unicode notation (`U+02BB`), `%d` as an ordinary number, `%b` in binary.
  `len(fmt.Sprintf("%b", r))` counts the binary digits: 10.
- **Line 8:** `b` is the bytes of this character.
- **Line 10:** `r>>6` is a shift of the number 6 bits to the right: it drops the last 6 bits and keeps the first 5.
  `r&0x3f` keeps only the last 6 bits. `% x` prints the bytes in hexadecimal, separated by spaces. (The comment on
  line 9: "2-byte template: 110xxxxx 10xxxxxx, the number's bits go into the 11 x places".)

```console
$ go run bitlar/main.go
U+02BB = 699 = 1010111011 (10 bit)
110|01010  10|111011  = ca bb
```

Thanks to these prefixes a program can look at any byte and know at once whether it is the start of a character or a
continuation: `110…` is the start of a two-byte character, `10…` is a continuation (RFC 3629, section 3).

**Slicing by bytes is dangerous.** `s[:2]` (square bracket, colon, two) takes the first two bytes of a string. Taking
a part like this is called **slicing**; more about it in [GO-1.08](/lab/youtube/go/go-1-08/en). In «oʻzbek» two bytes are `o` and
half of the turned comma. Here is `kesish/main.go` ("cutting"):

```go filename="kesish/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "oʻzbek"
	fmt.Printf("%q\n", s[:2])                 // 2 bayt: belgining yarmi
	fmt.Println(utf8.ValidString(s[:2]))      // bu UTF-8 emas
	fmt.Printf("%q\n", string([]rune(s)[:2])) // 2 rune: butun "oʻ"
	fmt.Printf("%q\n", string([]rune(s)[:1])) // 1 rune: faqat "o"
}
```

- **Line 10:** `%q` prints a string in quotes. A byte that is not valid UTF-8 is shown as a code such as `\xca`.
- **Line 11:** `utf8.ValidString` asks: "is this valid UTF-8?"
- **Line 12:** `[]rune(s)` converts the string into a list of runes. `[:2]` is the first two runes, and `string(…)`
  turns them back into a string.
- **Line 13:** the same, but one rune.

```console
$ go run kesish/main.go
"o\xca"
false
"oʻ"
"o"
```

The first line is `o` and the first byte of the turned comma (`ca`): half a character. `ValidString` says `false`. To
take a whole character, first convert the string into a list of runes: the result is `"oʻ"`. But look at the last
line: one rune is just `"o"`, because the letter oʻ is two runes. A rune is not a letter either.

## Common mistakes

**1. Thinking "if it looks the same, it is the same for Go".** This is the most classic misconception of this topic.
`"Oʻzbekiston" == "O'zbekiston"` runs without an error but prints `false`: the bytes of the apostrophes differ. The
full example is in the section "Looks the same, different for Go" above. The sign: no error message, but the search
does not find something that exists. **Fix:** before comparing, bring the apostrophes to one kind
(`strings.ReplaceAll`), and do it in one place: before saving and before searching.

**2. Counting letters with `len`.** `len("oʻzbek")` prints 7, not 5: `len` counts bytes. There is no error message,
just a wrong number. The example is in the section "Checking it in Go". **Fix:** to count the characters on the
screen, use `utf8.RuneCountInString`. Remember that it counts runes, not letters, too: oʻ is two runes.

**3. Forgetting to `import` `unicode/utf8`.** This program is not in the course folder; we ran it separately:

```go
package main

import "fmt"

func main() {
	s := "oʻzbek"
	fmt.Println(len(s))
	fmt.Println(utf8.RuneCountInString(s))
}
```

```console
$ go run importsiz/main.go
# command-line-arguments
importsiz/main.go:8:14: undefined: utf8
```

Reading the message: the file `importsiz/main.go` ("without import"), **line 8**, column 14 (the Tab at the start of
the line counts too): this is where `utf8` stands. `undefined: utf8` means Go does not know this name, because the
toolbox is not connected. **Fix:** add `"unicode/utf8"` to the `import`, as in `uzunlik/main.go`. At the top of the
file you write the full path of the toolbox (`unicode/utf8`), and in the code its last part (`utf8`).

**4. Writing a string in single quotes.** In JavaScript and Python `'oʻzbek'` is a string too. In Go it is not. This
program is not in the course folder either; we ran it separately:

```go
package main

import "fmt"

func main() {
	s := 'oʻzbek'
	fmt.Println(len(s))
}
```

```console
$ go run tirnoq/main.go
# command-line-arguments
tirnoq/main.go:6:7: more than one character in rune literal
```

`tirnoq/main.go:6:7` ("quote mark") — line 6, column 7: this is where the single quote stands. `more than one character
in rune literal` means there is more than one character inside a rune literal. In Go single quotes hold exactly one
character (its rune, like `'ʻ'` in "Going deeper"). A value written directly in the code is called a **literal**.
**Fix:** always write strings in double quotes: `"oʻzbek"`.

**5. Applying `ReplaceAll` to every apostrophe.** `strings.ReplaceAll("ma'no", "'", "ʻ")` gives `maʻno`: a turned
comma instead of the tutuq belgisi. There is no error message. The example is in the section "The fix:
`strings.ReplaceAll`". **Fix:** you need a rule that turns an apostrophe into `ʻ` only after `o`/`g`. Such a rule is
in the program [tozala/](https://github.com/abdurahmon27/go-backend-uz/tree/main/lessons/004-strings-utf8/tozala).

## Check yourself

Answer first, then open the answer.

**1.** Why is `len("oʻzbek")` 7?

<details>
<summary>Answer</summary>

`len` counts bytes, not letters. `o`, `z`, `b`, `e`, `k` are one byte each, and the turned comma `ʻ` is two bytes:
5 + 2 = 7.

</details>

**2.** Which tool counts runes?

<details>
<summary>Answer</summary>

`utf8.RuneCountInString` from the toolbox `unicode/utf8`. For «oʻzbek» it prints 6.

</details>

**3.** From [GO-1.01](/lab/youtube/go/go-1-01/en): what does `go build` make?

<details>
<summary>Answer</summary>

It translates the code and saves it into a ready file (a *binary*). The difference from `go run`: it does not run it
right away.

</details>

**4.** What does this program print? The word «togʻ» ("mountain") has `t`, `o`, `g` and the turned comma.
**A)** `4` and `4` · **B)** `5` and `4` · **C)** `4` and `5`

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "togʻ"
	fmt.Println(len(s))
	fmt.Println(utf8.RuneCountInString(s))
}
```

<details>
<summary>Answer</summary>

**B: `5` and `4`.** Bytes: 1 + 1 + 1 + 2 = 5. Runes: four characters, four runes. This program is not in the course
folder; we ran it separately:

```console
$ go run tog/main.go
5
4
```

</details>

**5.** `saytda` holds `"Oʻzbekiston"` (turned comma), and `qidiruv` holds `"O‘zbekiston"` (left curly apostrophe).
What does `saytda == qidiruv` give?

<details>
<summary>Answer</summary>

`false`. The left curly apostrophe is a different character: its number is 8216, and it takes three bytes. The turned
comma's number is 699, and it takes two bytes. The bytes differ, so for Go the two strings are not equal.

</details>
