## What you will learn

How many letters are in the Uzbek word «oʻzbek» ("Uzbek")? Five: oʻ, z, b, e and k. But if you ask Go with
`len`, it says **seven**. Swap the apostrophe for another one, and the answer becomes six or eight. Why? In this
lesson we find out, and we learn to work with Uzbek text without breaking it.

**One idea:** in Go a string (`string`) is a sequence of bytes. `len` counts bytes, and `range` gives runes. An
Uzbek letter can differ from both: «oʻzbek» has 5 letters, 6 runes and 7 bytes.

At the end of the lesson you will:

- be able to explain why `len` and `utf8.RuneCountInString` give different numbers;
- read a string rune by rune with `range`, and know why slicing it by bytes is dangerous;
- tell four kinds of apostrophe apart and know which one is correct for oʻ and gʻ;
- be able to read a function that brings text to one form before a search.

Today's three main new words:

| Word | Plain meaning | Go term |
|---|---|---|
| byte | the smallest piece of memory, 8 bits: one number from 0 to 255 | byte |
| rune | one character from the Unicode list, more exactly its number | rune |
| UTF-8 | the rule that packs a character's number into 1–4 bytes | UTF-8 |

Two helper words also appear on the way: **Unicode number** (a character's number in the world list, for
example `U+02BB`; officially a *code point*) and **hexadecimal notation** (a way to write a byte with two signs,
for example `ca`). We explain both where they are needed.

## One word, four kinds of apostrophe

There are no letters in a computer's memory, only numbers. So every character needs a number. For this, the whole
world agreed on one big list: **Unicode**. Think of a library catalogue: every character — Latin `z`, Cyrillic
`ж`, a Chinese character, an emoji — gets its own number. This number is called the **Unicode number** and is
written with `U+`: `z` = `U+007A`, `ʻ` = `U+02BB`. (The digits after `U+` are in hexadecimal notation; we explain
it below.)

In Go, one character from the Unicode list, more exactly its number, is called a **rune**. A rune is not the same
as a letter: the Uzbek letter `oʻ` is made of two runes — `o` and the turned comma `ʻ`.

Now an experiment. We write the word «oʻzbek» with four different apostrophes. On screen they look almost the same
at first glance, but for the computer they are four different characters. The eye cannot tell them apart, so a
comment next to each one gives its Unicode name. This is `uch/main.go` from the course folder (`uch` means
"three"):

```go filename="uch/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	sozlar := []string{
		"o'zbek", // U+0027 APOSTROPHE (klaviaturadagi)
		"oʻzbek", // U+02BB MODIFIER LETTER TURNED COMMA
		"o’zbek", // U+2019 RIGHT SINGLE QUOTATION MARK
		"o‘zbek", // U+2018 LEFT SINGLE QUOTATION MARK
	}
	for _, s := range sozlar {
		fmt.Printf("%s  len=%d  rune=%d  % x\n", s, len(s), utf8.RuneCountInString(s), s)
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 1 | `package main` | the familiar template: a program you can run |
| 3–6 | `import ( "fmt" "unicode/utf8" )` | we import two packages. Inside the parentheses you can list several packages. `unicode/utf8` is a package for working with UTF-8 text |
| 8 | `func main() {` | the program starts here |
| 9 | `sozlar := []string{` | a new variable `sozlar` ("words"): a list of strings. `[]string{…}` means "a list of `string` values, containing …". Such a list is called a **slice**; we study it in [GO-1.08](/lab/youtube/go#go-1-08) |
| 10–13 | `"o'zbek", // U+0027 …` | four strings that differ only in the apostrophe. After `//` comes a comment: the character's Unicode number and name |
| 15 | `for _, s := range sozlar {` | puts each string of the list into `s`, one by one. `_` means "I don't need the position number". We look at `range` in detail in [GO-1.05](/lab/youtube/go/go-1-05/en) |
| 16 | `fmt.Printf(…)` | prints using a template (explained below) |

`Printf` means "print formatted". The first value is the template text. Each `%` place in it is filled, in order,
with the next values:

| In the template | Which value | What is printed |
|---|---|---|
| `%s` | `s` | the string itself |
| `len=%d` | `len(s)` | the number that `len` returns (`%d` is a decimal number) |
| `rune=%d` | `utf8.RuneCountInString(s)` | the number of runes in the string |
| `% x` | `s` | every byte of the string in hexadecimal, separated by spaces |
| `\n` | — | go to a new line (`Printf` does not do it by itself) |

Before you run it, think: is `len` the same in all four lines? **A)** yes, 5 everywhere (the number of letters) ·
**B)** yes, 6 everywhere · **C)** no, they differ

<details>
<summary>Answer</summary>

**C: they differ.** The four strings look almost the same on screen, but the apostrophes are different characters.
Each one takes a different amount of memory. And `len` counts neither letters nor runes, but **bytes**. If you
chose "A", you thought `len` counts letters: this is the main trap of the lesson. If you chose "B", you thought it
counts runes: there really are 6 runes, but `len` counts something else.

</details>

```console
$ go run ./uch
o'zbek  len=6  rune=6  6f 27 7a 62 65 6b
oʻzbek  len=7  rune=6  6f ca bb 7a 62 65 6b
o’zbek  len=8  rune=6  6f e2 80 99 7a 62 65 6b
o‘zbek  len=8  rune=6  6f e2 80 98 7a 62 65 6b
```

There are 6 runes in every line. But `len` gives 6, 7, 8 and 8: three different lengths. So `len` counts bytes.

The right column shows the bytes themselves. They are written in **hexadecimal** notation (hex for short). It has
16 digits: `0`–`9`, then `a` = 10, `b` = 11, `c` = 12, `d` = 13, `e` = 14, `f` = 15. Every byte (0–255) is written
with exactly two such digits: `6f` = 6 × 16 + 15 = 111, `ca` = 12 × 16 + 10 = 202.

Let's compare the apostrophes:

| Character | Unicode number | Unicode name | Bytes | Number of bytes |
|---|---|---|---|---|
| `'` | U+0027 | APOSTROPHE (keyboard apostrophe) | `27` | 1 |
| `ʻ` | U+02BB | MODIFIER LETTER TURNED COMMA (turned comma) | `ca bb` | 2 |
| `’` | U+2019 | RIGHT SINGLE QUOTATION MARK (right curly) | `e2 80 99` | 3 |
| `‘` | U+2018 | LEFT SINGLE QUOTATION MARK (left curly) | `e2 80 98` | 3 |

The keyboard apostrophe is one byte, the turned comma in the letter oʻ is two bytes, and the curly apostrophes are
three bytes each. This is how a correctly written «oʻzbek» sits in memory:

```text
byte position:  0    1    2    3    4    5    6      len = 7 bytes
byte:           6f   ca   bb   7a   62   65   6b
rune:           o    ʻ ─────   z    b    e    k      6 runes
letter:         oʻ ────────    z    b    e    k      5 letters
```

One word, three different numbers: 5 letters, 6 runes, 7 bytes.

## Why: a string is a sequence of bytes, and UTF-8

Go's official rules (the specification) say it clearly: a `string` is a **sequence of bytes**, and its length is
the number of bytes. A `string` can hold any bytes. But Go source code itself is written in UTF-8, so the text
between double quotes becomes UTF-8 bytes.

**UTF-8** is the rule that packs a character's Unicode number into bytes. One byte holds only 0–255, and Unicode
numbers are much bigger. So UTF-8 splits the number over several bytes. A small number fits in one byte, a bigger
one takes two, three or four. Think of a train: each character is a train of 1 to 4 cars, and the front car says
how many cars follow it.

The rule depends on how many bits the number fits in (a bit is one 0 or 1, the "light bulb" from
[GO-1.02](/lab/youtube/go#go-1-02)):

| Number fits in | Unicode range | Bytes | Example |
|---|---|---|---|
| 7 bits | U+0000 – U+007F | 1 | old ASCII: Latin letters, digits, `'` U+0027 |
| 11 bits | U+0080 – U+07FF | 2 | `ʻ` U+02BB, `ʼ` U+02BC |
| 16 bits | U+0800 – U+FFFF | 3 | `’` U+2019, `‘` U+2018 |
| 21 bits | U+10000 – U+10FFFF | 4 | many emoji, for example 😀 U+1F600 |

**ASCII** is an old list of 128 characters: Latin letters, digits and punctuation. UTF-8 did not change them, so
English text is one byte per character in UTF-8 too. We say "many emoji" because not all: for example, ✅ (U+2705)
is three bytes.

The number of `ʻ` is U+02BB, 699 in decimal. It fits in 11 bits, so it takes two bytes. The curly apostrophes
U+2018 and U+2019 fit in 16 bits: three bytes. That is where our 6, 7, 8 come from.

UTF-8 was designed in 1992 by Ken Thompson together with Rob Pike. As Pike remembers it, this happened in a diner
in New Jersey, on a paper placemat. Later both became two of Go's three authors (the third is Robert Griesemer).

## How two bytes are put together

Now let's build one character at the bit level: how `ʻ` becomes `ca bb`.

In UTF-8 every byte says "who I am" with the bits at its start:

| Byte starts with | Meaning |
|---|---|
| `0xxxxxxx` | a one-byte character (ASCII) |
| `110xxxxx` | the start of a two-byte character |
| `1110xxxx` | the start of a three-byte character |
| `11110xxx` | the start of a four-byte character |
| `10xxxxxx` | continuation: the next byte of the previous character |

`x` marks the free places. The bits of the number are written into them. The two-byte template
`110xxxxx 10xxxxxx` has 5 + 6 = 11 free places.

This is `bitlar/main.go` from the course folder (`bitlar` means "bits"):

```go filename="bitlar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	r := 'ʻ'
	fmt.Printf("%U = %d = %b (%d bit)\n", r, r, r, len(fmt.Sprintf("%b", r)))
	b := []byte(string(r))
	// 2 baytli qolip: 110xxxxx 10xxxxxx, 11 ta x ga raqamning bitlari
	fmt.Printf("110|%05b  10|%06b  = % x\n", r>>6, r&0x3f, b)
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `r := 'ʻ'` | **single** quotes (`' '`) make one rune. Its value is the character's number, 699. Double quotes (`" "`) would make a string |
| 7 | `fmt.Printf("%U = %d = %b (%d bit)\n", …)` | `%U` prints the `U+02BB` form, `%d` decimal, `%b` binary (only 0 and 1). The last `%d` gets the length of the binary form, that is the number of bits: `fmt.Sprintf` does not print, it builds and returns a string, and `len` counts it |
| 8 | `b := []byte(string(r))` | turns the rune into a string (UTF-8 bytes), then into a list of bytes |
| 9 | `// 2 baytli qolip: …` | a comment ("two-byte template") |
| 10 | `fmt.Printf("110\|%05b  10\|%06b  = % x\n", r>>6, r&0x3f, b)` | `r>>6` shifts the number 6 bits to the right: the last 6 bits fall off and the first part stays. `r&0x3f` does the opposite and keeps only the last 6 bits (`0x3f` = `111111`). `%05b` is a 5-digit binary number (padded with zeros in front), `%06b` a 6-digit one |

You don't need to memorise `>>` and `&` from line 10: they are only there to split the number into two parts.

Think: how many bits does 699 fit in? **A)** 8 · **B)** 10 · **C)** 11

<details>
<summary>Answer</summary>

**B: 10 bits.** 10 bits hold the numbers from 0 to 1023 (2¹⁰ = 1024), 9 bits only up to 511. 699 is between them.
If you chose "A": 8 bits only go up to 255. "C": the template has 11 places, but the number itself needs only 10
bits. The one free place left gets a zero.

</details>

```console
$ go run ./bitlar
U+02BB = 699 = 1010111011 (10 bit)
110|01010  10|111011  = ca bb
```

How the bits were placed:

```text
699 = 1010111011                 10 bits
into 11 places: 0 1010111011     one 0 in front
           = 01010 | 111011      5 bits + 6 bits

byte 1: 110 + 01010  = 11001010 = ca
byte 2:  10 + 111011 = 10111011 = bb
```

Thanks to these starts, a program can look at any byte and know at once whether it starts a character or
continues one. Starts with `10` — a continuation; starts with `110` — the start of a new character. Even a program
that begins reading in the middle of a text can find where the next character starts.

## range: reading a string rune by rune

Now we walk over a string with `range`. `for … range` reads a string not by bytes but **by runes**. This is
`aylanish/main.go` (`aylanish` means "going round"):

```go filename="aylanish/main.go" showLineNumbers
package main

import "fmt"

func main() {
	s := "oʻzbek"
	for i, r := range s {
		fmt.Printf("%d  %c  %U  %d\n", i, r, r, r)
	}
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `s := "oʻzbek"` | the word written with the correct character (7 bytes) |
| 7 | `for i, r := range s {` | two values at each step: `i` is the position of the byte where the rune starts, `r` is the rune itself |
| 8 | `fmt.Printf("%d  %c  %U  %d\n", i, r, r, r)` | prints the position, the character (`%c`), the Unicode number (`%U`) and the same number in decimal (`%d`) |

In Go, a `rune` is a number of type `int32` that holds one Unicode number. A `byte` is a `uint8`. Both are just
other names for whole-number types from [GO-1.02](/lab/youtube/go#go-1-02).

Guess: which positions appear in the first column? **A)** `0 1 2 3 4 5` · **B)** `0 1 3 4 5 6` ·
**C)** `0 2 3 4 5 6`

<details>
<summary>Answer</summary>

**B: `0 1 3 4 5 6`.** `i` is the position of the **byte** where the rune starts. `o` starts at byte 0, `ʻ` starts
at byte 1 and takes two bytes (1 and 2). So the next rune, `z`, is at byte 3. If you chose "A", you took `i` for
the rune's sequence number. If you chose "C", you thought `o` takes two bytes: `o` is plain ASCII, one byte.

</details>

```console
$ go run ./aylanish
0  o  U+006F  111
1  ʻ  U+02BB  699
3  z  U+007A  122
4  b  U+0062  98
5  e  U+0065  101
6  k  U+006B  107
```

The indexes are 0, 1, then suddenly 3. There is no 2, because the turned comma took two bytes. On the right is
each rune's number: the turned comma is 699, a plain `z` is 122.

| Step | `i` (byte position) | `r` | Bytes taken by the rune |
|---|---|---|---|
| 1 | 0 | `o` (111) | 0 |
| 2 | 1 | `ʻ` (699) | 1, 2 |
| 3 | 3 | `z` (122) | 3 |
| 4 | 4 | `b` (98) | 4 |
| 5 | 5 | `e` (101) | 5 |
| 6 | 6 | `k` (107) | 6 |

## Byte by byte: s[i] is one byte

Now we walk byte by byte with an ordinary three-part `for` (as in [GO-0.05](/lab/youtube/go/go-0-05/en)). This is
`bayt/main.go` (`bayt` means "byte"):

```go filename="bayt/main.go" showLineNumbers
package main

import "fmt"

func main() {
	s := "oʻzbek"
	for i := 0; i < len(s); i++ {
		fmt.Printf("%c", s[i])
	}
	fmt.Println()
}
```

| Line | Code | What it does |
|---|---|---|
| 7 | `for i := 0; i < len(s); i++ {` | `i` from 0 to 6: `len(s)` = 7 bytes |
| 8 | `fmt.Printf("%c", s[i])` | `s[i]` — `i` in square brackets: **one byte** of the string at position `i`. `%c` prints the character whose Unicode number equals that number |
| 10 | `fmt.Println()` | goes to a new line at the end |

Question: what appears on the screen? Take your time, stop and think. **A)** `oʻzbek` ·
**B)** `o`, then two strange characters, then `zbek` · **C)** a compile error

<details>
<summary>Answer</summary>

**B: `oÊ»zbek`.** The two bytes of the turned comma became two separate characters. The first byte is `ca`, 202
in decimal. `%c` takes it as Unicode number 202, and U+00CA is a capital `Ê` with a circumflex ("hat"). The second
is `bb` = 187, U+00BB, the angle quotation mark `»`. If you chose "A", you took `s[i]` for a letter or a rune: it
is one byte. Not "C": the code is correct, it just doesn't do what we expected.

</details>

```console
$ go run ./bayt
oÊ»zbek
```

| `i` | `s[i]` (hex) | decimal | what `%c` printed |
|---|---|---|---|
| 0 | `6f` | 111 | `o` |
| 1 | `ca` | 202 | `Ê` (U+00CA) |
| 2 | `bb` | 187 | `»` (U+00BB) |
| 3–6 | `7a 62 65 6b` | 122 98 101 107 | `z b e k` |

When a website mixes up the encoding (the rule used to read text from bytes), you get exactly this: UTF-8 bytes
read with the old Latin-1 rule look like `oÊ»zbek`. With the Cyrillic encoding (Windows-1251) you see a Cyrillic
`К` instead of `Ê`: `oК»zbek`. You may have seen such "strange letters" on broken websites.

## Slicing: half a character

The same problem appears when slicing. Taking a piece of a string is called **slicing**: `s[:2]` means "from the
start up to byte 2 (byte 2 itself not included)", that is bytes 0 and 1. This is `kesish/main.go` (`kesish` means
"cutting"):

```go filename="kesish/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "oʻzbek"
	fmt.Printf("%q\n", s[:2])                 // 2 bayt: belgining yarmi
	fmt.Println(utf8.ValidString(s[:2]))      // bu UTF-8 emas
	fmt.Printf("%q\n", string([]rune(s)[:2])) // 2 rune: butun "oʻ"
	fmt.Printf("%q\n", string([]rune(s)[:1])) // 1 rune: faqat "o"
}
```

| Line | Code | What it does |
|---|---|---|
| 10 | `fmt.Printf("%q\n", s[:2])` | takes the first 2 bytes. `%q` prints the string in double quotes and shows a bad byte as `\x` plus two hex digits |
| 11 | `utf8.ValidString(s[:2])` | are these bytes valid UTF-8? `true` or `false` |
| 12 | `string([]rune(s)[:2])` | `[]rune(s)` turns the string into a list of runes (6 of them). `[:2]` takes the first 2 runes. `string(…)` turns them back into a string |
| 13 | `string([]rune(s)[:1])` | only the first rune |

Guess: which of the four lines gives the whole letter `oʻ`? **A)** line 1 (`s[:2]`) · **B)** line 3 (2 runes) ·
**C)** line 4 (1 rune)

<details>
<summary>Answer</summary>

**B: line 3.** `s[:2]` takes two **bytes**: `o` and only the first byte of the turned comma, `ca`. That is no
longer valid UTF-8. Two **runes** are `o` and the whole `ʻ`, that is `oʻ`. Line 4 has one rune — only `o`: the
letter `oʻ` is two runes.

</details>

```console
$ go run ./kesish
"o\xca"
false
"oʻ"
"o"
```

Cut the first two bytes, and half of the turned comma is left: `"o\xca"`, and `ValidString` says `false`. Cut by
runes, and UTF-8 does not break. But the letter can break: take the first rune, and only `o` is left.

```text
characters:      o    ʻ         z    b    e    k
bytes:           6f   ca   bb   7a   62   65   6b

s[:2]            6f   ca             → "o\xca"   ✗ half a character
[]rune(s)[:2]    o    ʻ              → "oʻ"      ✓ the whole letter
[]rune(s)[:1]    o                   → "o"       ✓ valid UTF-8, ✗ half a letter
```

Two more notes. `[]rune(s)` creates a new list: for a big text that is expensive. And it silently turns bad bytes
into U+FFFD (the `�` character).

## Which apostrophe is correct?

So which character is correct for oʻ and gʻ? **CLDR** is Unicode's database about languages: alphabets, sort
order, how dates are written. CLDR uses the turned comma (U+02BB) for oʻ and gʻ. Its name is *modifier letter
turned comma*, "a turned comma that attaches to a letter". Unicode treats it not as punctuation but as a
**letter**.

The tutuq belgisi (the Uzbek sign that separates sounds) in the word *maʼno* ("meaning") is a different letter:
U+02BC, *modifier letter apostrophe*. It is a letter in Unicode too. In English, the right curly mark (U+2019) is
recommended for the apostrophe. But in Uzbek the turned comma is part of the letter, and the curly `‘ ’` work as
inner quotation marks in Uzbek Latin writing.

| Character | Unicode | What it is in Unicode | Where it is correct |
|---|---|---|---|
| `ʻ` | U+02BB | letter | oʻ, gʻ (CLDR) |
| `ʼ` | U+02BC | letter | tutuq belgisi: maʼno |
| `’` | U+2019 | punctuation (quotation mark) | English apostrophe |
| `‘` | U+2018 | punctuation (quotation mark) | quotation mark |
| `'` | U+0027 | punctuation | keyboard apostrophe |

In practice, everything is mixed. We downloaded the lex.uz page of the new alphabet law on 25 November 2026 and
counted the characters after the letters o and g (JavaScript code on the page not counted; the `lexuz` program in
the course folder does this):

| Character | How many times |
|---|---|
| `ʻ` U+02BB | 60 |
| `‘` U+2018 | 16 |
| `’` U+2019 | 2 |
| `'` U+0027 (keyboard) | 1 |

The text of the law itself uses the correct character. But the whole page (with menus and headings) has four
different characters, even two different ones in a single line: `Oʻzbekiston Respublikasining Qonuni, 21.10.2026 yildagi O‘RQ-1184-son`
(`ʻ` in the first word, `‘` in the last). The left curly mark looks like the turned comma, so it is often used in
its place. And Word usually replaces the keyboard apostrophe with the right curly one (`’`) automatically. If the
site changes, these numbers may change too.

## A real-life example: search, splitting, sorting

The database stores `Oʻzbekiston` ("Uzbekistan") with the correct character, but the user typed `O'zbekiston` into
the search box from the keyboard. This is `qidiruv/main.go` (`qidiruv` means "search"):

```go filename="qidiruv/main.go" showLineNumbers
package main

import (
	"fmt"
	"slices"
	"strings"
	"unicode"
)

func main() {
	baza := "Oʻzbekiston poytaxti Toshkent" // bazada: U+02BB
	soz := "O'zbekiston"                    // klaviaturadan: U+0027
	fmt.Println(strings.Contains(baza, soz))

	harfEmas := func(r rune) bool { return !unicode.IsLetter(r) }
	fmt.Println(strings.FieldsFunc("oʻzbek o'zbek o’zbek", harfEmas))

	sozlar := []string{"olma", "pomidor", "oʻrik", "zarang", "gilos", "gʻoz"}
	slices.Sort(sozlar)
	fmt.Println(sozlar)
}
```

| Line | Code | What it does |
|---|---|---|
| 11 | `baza := "Oʻzbekiston poytaxti Toshkent"` | `baza` ("database"): the stored text ("the capital of Uzbekistan is Tashkent"), with U+02BB |
| 12 | `soz := "O'zbekiston"` | `soz` ("word"): what the user typed, with the keyboard apostrophe U+0027 |
| 13 | `strings.Contains(baza, soz)` | is `soz` inside `baza`? `true` or `false` |
| 15 | `harfEmas := func(r rune) bool { … }` | a small function without a name, stored in the variable `harfEmas` ("not a letter"). It takes a rune and returns a `bool`: `unicode.IsLetter(r)` asks "is `r` a letter?", `!` means "not". Functions: [GO-1.06](/lab/youtube/go/go-1-06/en) |
| 16 | `strings.FieldsFunc("…", harfEmas)` | splits the string at every place where `harfEmas` says `true`, and returns the list of words. The string holds «oʻzbek» written three ways |
| 18 | `sozlar := []string{…}` | six names (olma — apple, pomidor — tomato, oʻrik — apricot, zarang — maple, gilos — cherry, gʻoz — goose) |
| 19 | `slices.Sort(sozlar)` | sorts the list in place |
| 20 | `fmt.Println(sozlar)` | `Println` prints a list in square brackets: `[a b c]` |

Two guesses. What is printed on the first line? **A)** `true` · **B)** `false` · **C)** a compile error.
Where does `oʻrik` land on the third line? **D)** at the end, after `zarang` · **E)** between `olma` and `pomidor` ·
**F)** at the very start

<details>
<summary>Answer</summary>

**B and E.** The search gives `false`: `strings.Contains` compares bytes. The byte `27` in `soz` does not match
`ca bb` in `baza`. When sorting, Go also compares strings byte by byte: the second byte of `oʻrik` is `ca`, that of
`olma` is `l` (`6c`), so `oʻrik` comes after `olma`. Its first byte is `o` (`6f`), that of `pomidor` is `p`
(`70`), so it comes before `pomidor`. "D" would be correct in the Uzbek alphabet, but Go doesn't know the alphabet.

</details>

```console
$ go run ./qidiruv
false
[oʻzbek o zbek o zbek]
[gilos gʻoz olma oʻrik pomidor zarang]
```

Result: the search is `false`, not found. On the second line, the word with the correct character stayed whole,
and the other two broke into the pieces `o` and `zbek`: U+02BB is a letter, while `'` and `’` are punctuation.

Sorting is by bytes. In the current Uzbek alphabet, though, the letters oʻ, gʻ, sh and ch come after `z` (CLDR):

| | Order |
|---|---|
| `slices.Sort` (bytes) | gilos, gʻoz, olma, oʻrik, pomidor, zarang |
| Uzbek alphabet | gilos, olma, pomidor, zarang, oʻrik, gʻoz |

The correct order is the 🔴 Guru level of the homework. The package `golang.org/x/text/collate` (v0.42.0) does not
give this order with `language.Uzbek` either: the course author checked.

## The fix: tozala

The fix: bring the text to **one form** both before writing it to the database and before searching. This is
`tozala/main.go` (`tozala` means "clean"):

```go filename="tozala/main.go" showLineNumbers
package main

import (
	"fmt"
	"strings"
	"unicode"
)

// tozala apostrof turlarini bir xil qiladi:
// o/g dan keyin -> ʻ (U+02BB), boshqa harfdan keyin -> ʼ (U+02BC, tutuq belgisi).
// Faqat harfdan keyin turganlarini oʻzgartiradi: soʻz boshidagi ‘ qoʻshtirnoqqa tegmaydi.
func tozala(s string) string {
	r := []rune(s)
	for i := 1; i < len(r); i++ {
		if !strings.ContainsRune("'`´‘’ʻʼ", r[i]) || !unicode.IsLetter(r[i-1]) {
			continue
		}
		ogdan := strings.ContainsRune("oOgG", r[i-1])
		keyingiHarf := i+1 < len(r) && unicode.IsLetter(r[i+1])
		soz2 := i >= 2 && unicode.IsLetter(r[i-2]) // o/g soʻz boshida emas
		switch {
		case ogdan && (keyingiHarf || soz2): // oʻzbek, togʻ
			r[i] = 'ʻ'
		case keyingiHarf: // maʼno
			r[i] = 'ʼ'
		}
	}
	return string(r)
}

func main() {
	fmt.Println(tozala("O'zbekiston, tog’, ma'no, O`zbek"))
	fmt.Println(tozala("U ‘Salom’ dedi"))
	baza := tozala("Bu togʻ baland")
	fmt.Println(strings.Contains(baza, tozala("tog'")))
}
```

The function looks for the apostrophe kinds we know and changes only the ones that stand **after a letter**:

| Line | Code | What it does |
|---|---|---|
| 9–11 | `// tozala …` | comment: what the function does |
| 12 | `func tozala(s string) string {` | the function `tozala`: takes a string, returns a string |
| 13 | `r := []rune(s)` | turns the string into a list of runes: a `string` cannot be changed in place, but a list can |
| 14 | `for i := 1; i < len(r); i++ {` | starting from rune 1 (there is no letter before rune 0) |
| 15–17 | `if !… \|\| !… { continue }` | if `r[i]` is **not** one of the apostrophes, or the rune before it is **not** a letter, `continue`: skip this step and go to the next one. `\|\|` means "or" |
| 18 | `ogdan := …` | `ogdan` ("after o/g"): is the previous letter `o`, `O`, `g` or `G`? |
| 19 | `keyingiHarf := …` | `keyingiHarf` ("next letter"): is there a next rune, and is it a letter? `&&` means "and" |
| 20 | `soz2 := …` | is the o/g also not at the start of a word (is there another letter before it)? |
| 21 | `switch {` | the first `case` that is `true` runs (`switch`: [GO-1.05](/lab/youtube/go/go-1-05/en)) |
| 22–23 | `case ogdan && (…): r[i] = 'ʻ'` | after o/g, if a letter follows or it is the end of a word: the turned comma |
| 24–25 | `case keyingiHarf: r[i] = 'ʼ'` | between two other letters: the tutuq belgisi |
| 28 | `return string(r)` | turns the list back into a string and returns it |
| 32–33 | `tozala(…)` | two test strings |
| 34–35 | `baza := tozala("Bu togʻ baland")` | we clean before writing to the database ("This mountain is high") and before searching: `tozala("tog'")` (`tog'` is "mountain") |

The rule on a few words:

| In the text | Previous letter | Next rune | Result |
|---|---|---|---|
| `O'zbekiston` | `O` (o/g) | `z`, a letter | `ʻ` → `Oʻzbekiston` |
| `tog’` | `g` (o/g), with `o` before it | `,`, not a letter | `ʻ` → `togʻ` (also at the end of a word) |
| `ma'no` | `a` | `n`, a letter | `ʼ` → `maʼno` |
| `‘` in `‘Salom’` | a space, not a letter | — | left alone |
| `’` in `‘Salom’` | `m` | a space | no `case` matches: left alone |

Guess: what happens to the second line, `U ‘Salom’ dedi` ("He said ‘Hello’")? **A)** it does not change ·
**B)** both quotation marks become `ʻ` · **C)** only `’` becomes the tutuq belgisi

<details>
<summary>Answer</summary>

**A: it does not change.** Before `‘` there is a space: not a letter, so line 15 skips it. Before `’` there is the
letter `m`, but `m` is not o/g, and after `’` comes a space: both `case`s are `false`. If you chose "C": for the
tutuq belgisi, the next rune must be a letter too.

</details>

```console
$ go run ./tozala
Oʻzbekiston, togʻ, maʼno, Oʻzbek
U ‘Salom’ dedi
true
```

The words now use the correct characters, the quoted phrase did not change, and the search now returns `true`.

But this rule is not perfect either. The apostrophe in the word `Go'da` ("in Go") separates a suffix, and `tozala`
turns it into `ʻ` (`Goʻda`; in the same way `Rio’ga` → `Rioʻga`). A closing quotation mark after a word that ends
in o or g also turns into a letter: `‘Bingo’ oʻyini` → `‘Bingoʻ oʻyini`. So do the cleaning **in one place** and
protect it with a test. We learn to write tests in [GO-1.07](/lab/youtube/go#go-1-07).

## 2027: the new alphabet and a Cyrillic letter

The new alphabet law (OʻRQ-1184, signed on 21 October 2026) comes into force on 22 April 2027. It has letters
without apostrophes instead of oʻ and gʻ (`Ö`, `Ğ`, and also `Ş`, `Ç`); the alphabet is 28 letters plus the tutuq
belgisi `ʼ`. Documents in the old form stay valid, and a government programme sets the transition dates. The
tutuq belgisi stays.

The problem does not go away, it changes shape. The new `ö` can be written in two ways: as one character, or as a
plain `o` with a separate two dots above it. This is `yangi/main.go` (`yangi` means "new"):

```go filename="yangi/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	nfc := "\u00f6zbek"  // ö bitta belgi (U+00F6)
	nfd := "o\u0308zbek" // o + ustidagi ikki nuqta (U+0308)
	for _, s := range []string{nfc, nfd} {
		fmt.Printf("%s  len=%d  rune=%d\n", s, len(s), utf8.RuneCountInString(s))
	}
	fmt.Println(nfc == nfd)
}
```

| Line | Code | What it does |
|---|---|---|
| 9 | `nfc := "özbek"` | `\u` plus 4 hex digits is a character inside a string written by its Unicode number. U+00F6 is the single character `ö` |
| 10 | `nfd := "özbek"` | a plain `o` and U+0308: two dots placed over the previous letter |
| 11–13 | `for _, s := range …` | prints `len` and the rune count of both strings |
| 14 | `fmt.Println(nfc == nfd)` | are they equal? |

Guess: what is printed on the last line? **A)** `true`, they look the same on screen · **B)** `false`

<details>
<summary>Answer</summary>

**B: `false`.** `==` compares strings byte by byte. U+00F6 is two bytes, `o` + U+0308 is three: the bytes differ.
Looking the same on screen means nothing to Go.

</details>

```console
$ go run ./yangi
özbek  len=6  rune=5
özbek  len=7  rune=6
false
```

**Normalization** fixes this (bringing text that looks the same to one standard form). In Go it is not in the
standard library but in the separate package `golang.org/x/text/unicode/norm` (in the `x/text` module).

But in the alphabet table on that same lex.uz page, `A` and one more letter are typed with Cyrillic letters. This
is `kirill/main.go`:

```go filename="kirill/main.go" showLineNumbers
package main

import "fmt"

func main() {
	lotin := "A"
	kirill := "\u0410" // lex.uz alifbo jadvalidagi birinchi "A"
	for _, s := range []string{lotin, kirill} {
		fmt.Printf("%s  %U  len=%d\n", s, []rune(s)[0], len(s))
	}
	fmt.Println(lotin == kirill)
}
```

| Line | Code | What it does |
|---|---|---|
| 6 | `lotin := "A"` | `lotin` ("Latin"): the Latin `A`, U+0041 |
| 7 | `kirill := "А"` | `kirill` ("Cyrillic"): the Cyrillic `А`, U+0410, the first letter in the lex.uz table |
| 9 | `fmt.Printf("%s  %U  len=%d\n", s, []rune(s)[0], len(s))` | prints the letter, the Unicode number of its first rune and the number of bytes |
| 11 | `fmt.Println(lotin == kirill)` | are they equal? |

```console
$ go run ./kirill
A  U+0041  len=1
А  U+0410  len=2
false
```

They look the same, but the Cyrillic `А` is two bytes, and `==` gives `false`. Normalization does not merge such
look-alike letters: in Unicode they really are different letters. Unicode calls such pairs *confusables*. So trust
the bytes, not your eyes.

## Common mistakes

**1. Thinking that `len` counts letters.** The main trap of this lesson: the program gives no error, only a wrong
number. We saw it in "One word, four kinds of apostrophe": `len("oʻzbek")` = 7, but there are 5 letters. **Fix:**
for runes, use `utf8.RuneCountInString(s)`. For Uzbek letters, count oʻ, gʻ, sh, ch yourself (the 🟡 Medium level of
the homework).

**2. Taking `s[i]` for a letter.** `s[i]` is one byte. In "Byte by byte", printing with `%c` gave `oÊ»zbek`.
**Fix:** if you need characters, walk with `for i, r := range s`.

**3. Slicing a string by bytes.** `s[:2]` cuts a character in half and leaves invalid UTF-8 (see "Slicing").
**Fix:** slice with `[]rune(s)`, or take the cut position from the `i` that `range` gives; and remember that a
letter can be two runes.

**4. Double quotes for a rune.** This example is not in the course folder; it was run separately:

```go
package main

import "fmt"

func main() {
	var r rune = "ʻ"
	fmt.Println(r)
}
```

```console
$ go run qoshtirnoq/main.go
# command-line-arguments
qoshtirnoq/main.go:6:15: cannot use "ʻ" (untyped string constant) as rune value in variable declaration
```

Line 6, character 15: *cannot use "ʻ" (untyped string constant) as rune value in variable declaration* — the
string constant `"ʻ"` cannot be used as a rune value. Double quotes make a string, but a rune is a number.
**Fix:** single quotes: `var r rune = 'ʻ'`.

**5. Thinking that `oʻ` is one rune.** (Not in the course folder.)

```go
package main

import "fmt"

func main() {
	r := 'oʻ'
	fmt.Println(r)
}
```

```console
$ go run ikkibelgi/main.go
# command-line-arguments
ikkibelgi/main.go:6:7: more than one character in rune literal
```

*more than one character in rune literal* — more than one character inside single quotes. Single quotes hold only
one rune, and `oʻ` is two: `o` and `ʻ`. **Fix:** write `"oʻ"` (a string).

**6. Changing a byte of a string in place.** (Not in the course folder.) We want a capital first letter:

```go
package main

import "fmt"

func main() {
	s := "oʻzbek"
	s[0] = 'O'
	fmt.Println(s)
}
```

```console
$ go run ozgartir/main.go
# command-line-arguments
ozgartir/main.go:7:2: cannot assign to s[0] (neither addressable nor a map index expression)
```

Line 7: *cannot assign to s[0] (neither addressable nor a map index expression)* — you cannot assign a value to
`s[0]`. In Go a `string` does not change after it is created. **Fix:** build a new string. For example, as in
`tozala`: `r := []rune(s)`, `r[0] = 'O'`, then `s = string(r)`.

**7. Comparing a byte with a rune.** (Not in the course folder.)

```go
package main

import "fmt"

func main() {
	s := "oʻzbek"
	if s[1] == 'ʻ' {
		fmt.Println("topildi")
	}
}
```

```console
$ go run taqqos/main.go
# command-line-arguments
taqqos/main.go:7:13: 'ʻ' (untyped rune constant 699) overflows byte
```

*'ʻ' (untyped rune constant 699) overflows byte* — the rune constant `'ʻ'` (699) does not fit in a `byte`. `s[1]`
is a `byte`, which cannot hold numbers above 255 ([GO-1.02](/lab/youtube/go#go-1-02)), and 699 is bigger. **Fix:** compare
runes (`for _, r := range s { if r == 'ʻ' … }`) or use `strings.ContainsRune(s, 'ʻ')`.

**8. Searching with different apostrophes.** The program gives no error, it just finds nothing (see "A real-life
example"). **Fix:** pass the text through one `tozala` function both before saving and before searching.
