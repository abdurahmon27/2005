## Что вы узнаете

В форме регистрации имя должно быть не длиннее 5 символов. `<input maxLength={5}>` в React пропускает имя «Gʻani»:
`"Gʻani".length` — 5. А проверка `len(ism) <= 5` на Go-бэкенде отклоняет то же имя, потому что для Go его длина 6.
С одним словом то же самое: Node говорит, что `"oʻzbek".length` равно 6, а `len` в Go — 7. Что считает Go?

**Одна идея:** строка в Go состоит из байтов: длина, индекс и сравнение работают побайтово, а перевёрнутая запятая
в `oʻ` занимает два байта.

К концу урока вы сможете:

- объяснить, что считают и сравнивают `len`, `s[i]` и `==` в Go, сравнивая с JS, Python и PHP;
- использовать `utf8.RuneCountInString`, когда нужно число символов, и `[]rune(s)`, когда нужен сам символ;
- по code point любого символа сказать, сколько байтов он занимает в UTF-8;
- привести узбекские апострофы в базе и в поиске к одному виду, не ломая знак тутук в *maʼno*.

Три главных новых слова урока:

| Слово | Простое значение | По-английски |
|---|---|---|
| `string` = байты | строка в Go — последовательность байтов: `len`, индекс `s[i]` и `==` работают с байтами | string (a sequence of bytes) |
| `rune` | один code point, то есть номер Unicode символа; другое имя `int32` | rune |
| UTF-8 | правило записи code point в 1–4 байта; так хранится текст в коде на Go | UTF-8 |

Есть и вспомогательные слова: **code point** (в разделе про UTF-8), слайс рун `[]rune(s)` (в разделе про индекс) и
`strings.NewReplacer` (в разделе про исправление).

## Одно слово, четыре языка

Сначала сам Go, `hook/main.go`:

```go filename="hook/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println(len("oʻzbek")) // JS: "oʻzbek".length → 6
}
```

В 6-й строке `len("oʻzbek")` — длина строки, в комментарии результат JS. Запустим оба языка рядом:

```console
$ node -p '"oʻzbek".length'
6
$ go run hook/main.go
7
```

Ещё два языка, Python и PHP:

```console
$ python3 -c 'print(len("oʻzbek"))'
6
$ php -r 'echo strlen("oʻzbek");'
7
$ php -r 'echo mb_strlen("oʻzbek");'
6
```

`tillar/tekshir.sh` вызывает все четыре одной командой:

```console
$ ./tillar/tekshir.sh
js     .length  6
python len      6
php    strlen   7
go     len      7
```

Для одного слова получилось два разных числа, потому что языки считают три разные единицы:

| Язык | Выражение | `"oʻzbek"` | Что считает |
|---|---|---|---|
| JavaScript / TS | `s.length` | 6 | единицы UTF-16 |
| Python | `len(s)` | 6 | code point (в Go: руны) |
| PHP | `strlen($s)` | 7 | байты |
| PHP | `mb_strlen($s)` | 6 | символы (code point) |
| Go | `len(s)` | 7 | байты |

В Go `string` — **последовательность байтов**, а `len` считает эти байты, как `strlen` в PHP. Спецификация Go
говорит ровно это: «The number of bytes is called the length of the string». Единица, которую считает Python, в Go
называется **руна** (rune). У JavaScript третий вариант: **единицы UTF-16** (ECMAScript: длина строки — число
16-битных элементов). Для этого слова JS и Python дали одинаковые 6, но совпадают они не всегда: это вы увидите в
промежуточном вопросе.

## UTF-8: code point → 1–4 байта

Почему именно 7 байтов? `codePointAt` в JavaScript возвращает номер символа:

```console
$ node -p '"oʻzbek".codePointAt(1)'
699
```

(Этой команды нет в папке курса как файла, код прямо в команде.) Это число называется **code point**: номер Unicode
символа. Обычно его пишут в шестнадцатеричной записи (hex) в виде `U+02BB`: `0x2BB` = 699.

**UTF-8** — правило записи code point в байты. Маленький code point записывается в один байт, побольше — в два, три
или четыре байта (RFC 3629):

| Code point | Байтов | Пример |
|---|---|---|
| 0 … 127 | 1 | `o` = 111, `z` = 122 |
| 128 … 2 047 | 2 | `ʻ` = 699 |
| 2 048 … 65 535 | 3 | |
| 65 536 … 1 114 111 | 4 | |

Первая строка — диапазон ASCII: латинские буквы, цифры и символы клавиатуры занимают по одному байту. Перевёрнутая
запятая в `oʻ` — это 699, значит, два байта. Вот как `"oʻzbek"` лежит в строке Go:

| Символ | `o` | `ʻ` | `z` | `b` | `e` | `k` |
|---|---|---|---|---|---|---|
| Code point | U+006F | U+02BB | U+007A | U+0062 | U+0065 | U+006B |
| Байты UTF-8 (hex) | `6f` | `ca bb` | `7a` | `62` | `65` | `6b` |
| Число байтов | 1 | 2 | 1 | 1 | 1 | 1 |

Всего 7 байтов, и `len` в Go считает именно их. В шестнадцатеричной записи `ca` = 12 × 16 + 10 = 202, `bb` = 187.

`string` в Go может хранить любые байты. Но сам код на Go пишется в UTF-8 (spec: «Source code is Unicode text
encoded in UTF-8»), поэтому `"oʻzbek"` в кавычках превращается ровно в эти 7 байтов.

## Руна: единица, которую считает Python

Шесть вещей, которые насчитал Python, — это code point: o, ʻ, z, b, e и k. В Go тип одного code point — **`rune`**
(руна). Это другое имя `int32` (spec: «rune alias for int32»). А `byte` — другое имя `uint8`.

Но и руна — не буква. В алфавите `oʻ` — одна буква, а рун две: `o` и `ʻ`.

| Что считаем | Сколько | Что именно |
|---|---|---|
| буквы (алфавит) | 5 | oʻ, z, b, e, k |
| руны (code point) | 6 | o, ʻ, z, b, e, k |
| байты (UTF-8) | 7 | 6f, ca, bb, 7a, 62, 65, 6b |

В Go можно посчитать и то и другое, `uzunlik/main.go` (`uzunlik` — «длина»):

```go filename="uzunlik/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "oʻzbek"
	fmt.Println(len(s))                    // baytlar soni
	fmt.Println(utf8.RuneCountInString(s)) // rune'lar (belgilar) soni
}
```

| Строка | Код | Что делает |
|---|---|---|
| 3–6 | `import ( "fmt" "unicode/utf8" )` | `unicode/utf8` — стандартный пакет для работы с UTF-8 |
| 9 | `s := "oʻzbek"` | строка из 7 байтов |
| 10 | `len(s)` | число байтов |
| 11 | `utf8.RuneCountInString(s)` | число рун: читает байты по правилу UTF-8 и считает code point |

```console
$ go run uzunlik/main.go
7
6
```

Семь и шесть. В JavaScript code point считает spread: `[...s]` раскладывает строку в массив code point.

```console
$ node -p '[..."oʻzbek"].length'
6
```

(Этой команды тоже нет в папке.)

## Индекс: `s[1]` — не символ, а байт

В JavaScript и Python `s[1]` даёт второй символ:

```console
$ node -p '"oʻzbek"[1]'
ʻ
$ python3 -c 'print("oʻzbek"[1])'
ʻ
```

Что выведет то же выражение в Go?

```go
s := "oʻzbek"
fmt.Println(s[1])
```

**A)** `ʻ` · **B)** `202` · **C)** `o`

<details>
<summary>Ответ</summary>

**B: `202`.** Индекс строки в Go даёт один **байт** типа `byte` (spec: «a[x] is the non-constant byte value at
index x and the type of a[x] is byte»). Байт с индексом 1 — первый байт перевёрнутой запятой, `ca`, в десятичной
записи 202. `fmt.Println` выводит `byte` как число. Если вы выбрали «`ʻ`», вы перенесли привычку из JS и Python.
Если выбрали «`o`», вы решили, что индекс начинается с 1: в Go он тоже начинается с 0.

</details>

Полная программа, `indeks/main.go`:

```go filename="indeks/main.go" showLineNumbers
package main

import "fmt"

func main() {
	s := "oʻzbek"
	fmt.Println(s[1])                 // JS va Python'da s[1] → "ʻ"; Go'da: 1-oʻrindagi bayt (byte, son)
	fmt.Printf("%x\n", s[1])          // oʻsha bayt oʻn oltilikda: ca (ʻ ning birinchi bayti)
	fmt.Println(string([]rune(s)[1])) // rune'lar boʻyicha: 1-element — ʻ
}
```

| Строка | Код | Что делает |
|---|---|---|
| 7 | `s[1]` | байт с индексом 1; тип `byte` (`uint8`), `Println` выводит его как число |
| 8 | `fmt.Printf("%x\n", s[1])` | тот же байт в шестнадцатеричной записи: `%x` — hex, `\n` — новая строка |
| 9 | `[]rune(s)` | преобразует строку в слайс рун (преобразование `T(x)`): список, похожий на массив JS, каждый элемент — один code point |
| 9 | `[]rune(s)[1]` | элемент этого списка с индексом 1: `ʻ` (699) |
| 9 | `string(…)` | превращает руну обратно в строку, чтобы `Println` вывел символ, а не число |

```console
$ go run indeks/main.go
202
ca
ʻ
```

Разница вот в чём: индекс строки идёт по байтам, а индекс слайса рун — по code point.

| Индекс | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| `s[i]` (байт, hex) | `6f` | `ca` | `bb` | `7a` | `62` | `65` | `6b` |
| `[]rune(s)[i]` (руна) | `o` | `ʻ` | `z` | `b` | `e` | `k` | — |

В JavaScript байты даёт `TextEncoder`. Его элемент с индексом 1 тоже 202:

```console
$ node -p 'new TextEncoder().encode("oʻzbek")[1]'
202
```

(В папке нет.) Обратите внимание: `[]rune(s)` создаёт новый слайс и копирует весь текст. Для короткого имени или
заголовка это не проблема, а для большого текста дорого.

## Промежуточный вопрос: эмодзи

В JavaScript длина этого эмодзи 2:

```console
$ node -p '"😀".length'
2
```

😀 = U+1F600 = 128 512. Сравните code point с таблицей UTF-8. Сколько будет `len("😀")` в Go?

**A)** 1 · **B)** 2 · **C)** 4

<details>
<summary>Ответ</summary>

**C: 4.** 128 512 > 65 535, значит, последняя строка таблицы: UTF-8 записывает его в четыре байта. А руна одна.
Если вы выбрали «2», вы перенесли результат JS. Причина двойки в JS другая: UTF-16 делит символ больше 65 535 на две
16-битные единицы (**surrogate pair**, суррогатная пара). «1» — это число рун, а не `len`.

</details>

`emoji/main.go`:

```go filename="emoji/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "😀"                               // U+1F600 = 128512 > 65535
	fmt.Println(len(s))                    // baytlar
	fmt.Println(utf8.RuneCountInString(s)) // rune'lar
}
```

```console
$ go run emoji/main.go
4
1
```

Теперь полная таблица (результаты Python и PHP получены на этом же компьютере):

| Язык | Выражение | `"oʻzbek"` | `"😀"` | Что считает |
|---|---|---|---|---|
| JavaScript / TS | `s.length` | 6 | 2 | единицы UTF-16 |
| JavaScript | `[...s].length` | 6 | 1 | code point |
| Python | `len(s)` | 6 | 1 | code point |
| PHP | `strlen($s)` · `mb_strlen($s)` | 7 · 6 | 4 · 1 | байты · символы |
| Go | `len(s)` | 7 | 4 | байты |
| Go | `utf8.RuneCountInString(s)` | 6 | 1 | руны (code point) |

В узбекских именах `.length` в JS и число рун в Go совпадают. В эмодзи — нет: в JS code point считает
`[...s].length`.

## Одно слово, четыре апострофа

Теперь проблема, характерная для узбекского текста. Перевёрнутой запятой `ʻ` нет на обычной клавиатуре, поэтому одно
слово пишут четырьмя способами:

| Знак | Название | Code point |
|---|---|---|
| `'` | апостроф с клавиатуры | U+0027 = 39 |
| `ʻ` | перевёрнутая запятая | U+02BB = 699 |
| `’` | правый изогнутый апостроф | U+2019 = 8217 |
| `‘` | левый изогнутый апостроф | U+2018 = 8216 |

Языковые данные Unicode (CLDR, `uz.xml`) в списке узбекского алфавита дают `oʻ` и `gʻ` с перевёрнутой запятой.

`tort/main.go` (`tort` — «четыре») выводит `len` всех четырёх вариантов. Сравните code point с таблицей UTF-8: какая
строка верна?

**A)** 6 · 7 · 8 · 8 · **B)** 7 · 7 · 7 · 7 · **C)** 6 · 7 · 7 · 7

<details>
<summary>Ответ</summary>

**A: 6 · 7 · 8 · 8.** Апостроф с клавиатуры (39) — 1 байт, перевёрнутая запятая (699) — 2 байта. У изогнутых
апострофов code point больше 2 047, поэтому они занимают по три байта. А рун во всех четырёх по 6: разница только в
байтах. Если вы выбрали «B», вы решили: выглядит одинаково — значит, и байты одинаковые. Если выбрали «C», вы решили,
что любой апостроф занимает 2 байта, как перевёрнутая запятая.

</details>

```go filename="tort/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

// Bitta soʻz, toʻrt xil apostrof. Koʻzga deyarli bir xil, baytlari har xil.
func main() {
	sozlar := []string{
		"o'zbek", // U+0027 APOSTROPHE (klaviaturadagi)
		"oʻzbek", // U+02BB MODIFIER LETTER TURNED COMMA (teskari vergul, toʻgʻrisi)
		"o’zbek", // U+2019 RIGHT SINGLE QUOTATION MARK (oʻng jingalak)
		"o‘zbek", // U+2018 LEFT SINGLE QUOTATION MARK (chap jingalak)
	}
	for _, s := range sozlar {
		fmt.Printf("%s  len=%d  rune=%d\n", s, len(s), utf8.RuneCountInString(s))
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 10–15 | `sozlar := []string{…}` | слайс из четырёх строк (`sozlar` — «слова»); в комментариях code point каждого апострофа |
| 16 | `for _, s := range sozlar` | цикл по каждому элементу; `_` — индекс не нужен |
| 17 | `fmt.Printf("%s  len=%d  rune=%d\n", …)` | `%s` — строка, `%d` — целое число |

```console
$ go run tort/main.go
o'zbek  len=6  rune=6
oʻzbek  len=7  rune=6
o’zbek  len=8  rune=6
o‘zbek  len=8  rune=6
```

На экране все четыре почти одинаковы. Для Go же это четыре разные последовательности байтов.

апостроф — на кнопке выбора языка (`O’zb`). Последняя строка — кириллическая `е` (U+0435) внутри латинского слова,
это за рамками сегодняшней темы (`kirill/` в приложении README). Если сайт изменится, числа тоже могут измениться:
результат на 2026-11-26.

## Последствие на бэкенде: `==` даёт false

В базе `Oʻzbekiston` сохранён с перевёрнутой запятой. Пользователь ввёл в поиск `O'zbekiston` с апострофом с
клавиатуры. `teng/main.go` (`teng` — «равно»; `saytda` — из списка на сайте, `qidiruv` — из поля поиска):

```go filename="teng/main.go" showLineNumbers
package main

import "fmt"

func main() {
	saytda := "Oʻzbekiston"  // saytdagi roʻyxatda: ʻ (U+02BB)
	qidiruv := "O'zbekiston" // foydalanuvchi klaviaturadan yozdi: ' (U+0027)
	fmt.Println(saytda == qidiruv)
}
```

```console
$ go run teng/main.go
false
```

Go сравнивает строки побайтово (spec: Comparison operators). `Oʻzbekiston` — 12 байтов, `O'zbekiston` — 11 байтов:
байты разные, значит, `false`. Строгое равенство `===` в JavaScript тоже даёт `false`. Нормализация Unicode
(`normalize("NFC")` или `"NFKC"`) тоже не помогает: это разные символы, а не две записи одного символа.

```console
$ node -p '"Oʻzbekiston" === "O\x27zbekiston"'
false
$ node -p '["NFC", "NFKC"].map(f => "Oʻzbekiston".normalize(f) === "O\x27zbekiston".normalize(f))'
[ false, false ]
```

(Обеих команд нет в папке. `\x27` — апостроф с клавиатуры: так он записан, чтобы не путаться с кавычками shell.)

## Исправление: только апостроф после `o` и `g`

Первая мысль — заменить каждый `'` на `ʻ`. `tuzat/main.go` (`tuzat` — «исправь»):

```go filename="tuzat/main.go" showLineNumbers
package main

import (
	"fmt"
	"strings"
)

func main() {
	saytda := "Oʻzbekiston"
	qidiruv := "O'zbekiston"
	qidiruv = strings.ReplaceAll(qidiruv, "'", "ʻ") // har bir ' (U+0027) ni ʻ (U+02BB) ga almashtir
	fmt.Println(saytda == qidiruv)
	fmt.Println(strings.ReplaceAll("ma'no", "'", "ʻ")) // cheklov: toʻgʻrisi maʼno (ʼ U+02BC, tutuq belgisi)
}
```

В 11-й строке `strings.ReplaceAll(qidiruv, "'", "ʻ")` заменяет каждый `'` в тексте на `ʻ`. В 13-й строке та же
замена в слове *maʼno*.

```console
$ go run tuzat/main.go
true
maʻno
```

Поиск заработал, но *maʼno* сломалось. Знак в этом слове — не перевёрнутая запятая, а **знак тутук** `ʼ` (U+02BC,
tutuq belgisi): CLDR указывает его отдельно. Поэтому заменяем на перевёрнутую запятую только апострофы после `o` и
`g`, изогнутые тоже. `normal/main.go`:

```go filename="normal/main.go" showLineNumbers
package main

import (
	"fmt"
	"strings"
)

func main() {
	saytda := "Oʻzbekiston"
	qidiruv := "O'zbekiston"
	// Faqat o/g dan keyingi apostrof (klaviatura ' va egri ’ ‘) → ʻ (U+02BB). Boshqa joydagi ' tegilmaydi:
	// maʼno dagi tutuq belgisi (ʼ U+02BC) teskari vergul emas. Toʻliqroq qoida va chegaralar: ../tozala/
	r := strings.NewReplacer(
		"o'", "oʻ", "g'", "gʻ", "O'", "Oʻ", "G'", "Gʻ",
		"o’", "oʻ", "g’", "gʻ", "O’", "Oʻ", "G’", "Gʻ",
		"o‘", "oʻ", "g‘", "gʻ", "O‘", "Oʻ", "G‘", "Gʻ",
	)
	fmt.Println(r.Replace(qidiruv) == saytda)
	fmt.Println(r.Replace("ma'no"))
	// egri apostroflar ham: true true
	fmt.Println(r.Replace("O’zbekiston") == saytda, r.Replace("O‘zbekiston") == saytda)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 13 | `strings.NewReplacer(…)` | заменитель из пакета `strings`: аргументы — пары «старое, новое» |
| 14 | `"o'", "oʻ", …` | апостроф с клавиатуры: после `o`, `g`, `O`, `G` становится `ʻ` |
| 15–16 | `"o’", "oʻ", …` · `"o‘", "oʻ", …` | то же для правого и левого изогнутых апострофов |
| 18 | `r.Replace(qidiruv) == saytda` | `Replace` заменяет все пары за один проход по тексту, потом сравниваем |
| 19 | `r.Replace("ma'no")` | апострофа после `a` в парах нет: он остаётся на месте |
| 21 | два `==` | варианты с изогнутыми апострофами тоже становятся равны `saytda` |

```console
$ go run normal/main.go
true
ma'no
true true
```

`true`, а *maʼno* не тронуто. `strings.NewReplacer` выполняет замены в том порядке, в каком они встречаются в тексте,
без перекрытий (pkg.go.dev).

Правило: соберите эту замену в одну функцию и вызывайте её **и перед сохранением, и перед поиском**. Тогда текст в
базе и в поиске состоит из одних и тех же байтов. Более полное правило — в `tozala/` в папке курса: после `o`/`g` —
`ʻ`, между другими буквами — `ʼ`. У него тоже есть предел: `Go'da` → `Goʻda` (приложение README).

## Глубже (необязательно): устройство UTF-8 и побайтовая нарезка

### Как `ʻ` становится `ca bb`

В многобайтовом символе каждый байт начинается с префикса. У первого байта и у байтов продолжения префиксы разные.
`bitlar/main.go` (`bitlar` — «биты»):

```go filename="bitlar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	r := 'ʻ'
	fmt.Printf("%U = %d = %b (%d bit)\n", r, r, r, len(fmt.Sprintf("%b", r)))
	b := []byte(string(r))
	// 2 baytli qolip: 110xxxxx 10xxxxxx, 11 ta x ga raqamning bitlari
	fmt.Printf("110|%05b  10|%06b  = % x\n", r>>6, r&0x3f, b)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `r := 'ʻ'` | литерал руны (в одинарных кавычках): тип `rune`, значение 699 |
| 7 | `%U`, `%d`, `%b` | вид `U+02BB`, десятичная и двоичная запись; `len(fmt.Sprintf("%b", r))` — число битов в двоичной записи |
| 8 | `[]byte(string(r))` | руна → строка → слайс байтов: байты UTF-8 символа |
| 10 | `r>>6`, `r&0x3f` | `>>6` отбрасывает последние 6 битов (остаются старшие), `&0x3f` берёт только последние 6 битов (`0x3f` = `111111`) |
| 10 | `%05b`, `%06b`, `% x` | двоичная запись в 5 и 6 разрядов; байты в hex через пробел |

```console
$ go run bitlar/main.go
U+02BB = 699 = 1010111011 (10 bit)
110|01010  10|111011  = ca bb
```

699 в двоичной записи — 10 битов. В двухбайтовом шаблоне 11 свободных мест (`x`), поэтому впереди добавляется один 0:
`01010111011`.

| | 1-й байт | 2-й байт |
|---|---|---|
| Шаблон | `110xxxxx` | `10xxxxxx` |
| Биты числа 699 | `01010` | `111011` |
| Результат | `11001010` = `ca` | `10111011` = `bb` |

По тому, с каких битов начинается байт, понятна его роль:

| Начало байта | Значение |
|---|---|
| `0xxxxxxx` | однобайтовый символ (ASCII) |
| `110xxxxx` | начало двухбайтового символа |
| `1110xxxx` | начало трёхбайтового символа |
| `11110xxx` | начало четырёхбайтового символа |
| `10xxxxxx` | байт продолжения |

Благодаря этим префиксам программа находит начало символа с любого байта UTF-8: она пропускает назад байты,
начинающиеся с `10` (RFC 3629 §3).

### Побайтовая нарезка

В JavaScript `slice(0, 2)` берёт две единицы UTF-16, то есть `oʻ`:

```console
$ node -p '"oʻzbek".slice(0, 2)'
oʻ
```

(В папке нет.) В Go `s[:2]` — **байты** с 0 до 2 (2 не входит): `o` и половина перевёрнутой запятой. Это называется
**срез** (slicing). `kesish/main.go` (`kesish` — «резать»):

```go filename="kesish/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "oʻzbek"
	fmt.Printf("%q\n", s[:2])                 // 2 bayt: belgining yarmi
	fmt.Println(utf8.ValidString(s[:2]))      // bu UTF-8 emas
	fmt.Printf("%q\n", string([]rune(s)[:2])) // 2 rune: butun "oʻ"
	fmt.Printf("%q\n", string([]rune(s)[:1])) // 1 rune: faqat "o"
}
```

| Строка | Код | Что делает |
|---|---|---|
| 10 | `s[:2]` | первые 2 байта; `%q` выводит значение в кавычках и показывает сломанный байт как `\xca` |
| 11 | `utf8.ValidString(s[:2])` | корректный ли это UTF-8? |
| 12 | `string([]rune(s)[:2])` | первые 2 руны: целое `oʻ` |
| 13 | `string([]rune(s)[:1])` | первая 1 руна: только `o` |

```console
$ go run kesish/main.go
"o\xca"
false
"oʻ"
"o"
```

`s[:2]` разрезал символ пополам: остался `ca`, а `bb` нет, и эти байты уже не корректный UTF-8. В приложении такой
байт обычно показывается как `�`. Срез через слайс рун сохраняет символ целиком. Но букву он всё равно может
сломать: в последней строке от `oʻ` осталась только `o`, потому что `oʻ` — две руны.

## Частые ошибки

**1. Считать, что `len` — число символов.** Самая классическая ошибка этой темы. Если лимит имени, заголовка или SMS
проверяется через `len(s) <= n`, каждая `ʻ` считается дважды: «Gʻani», пропущенное фронтендом, на бэкенде имеет длину
6. Сообщения об ошибке нет, результат молча неверный. Пример — в разделах «Одно слово, четыре языка» и «Руна».
**Исправление:** для лимита символов — `utf8.RuneCountInString(s)`.

**2. Считать `s[i]` символом.** Если по привычке из JS записать индекс в переменную типа `rune`, Go откажет. Этой
программы нет в папке курса, сохраните её в `xato/main.go` и запустите:

```go
package main

import "fmt"

func main() {
	s := "oʻzbek"
	var c rune = s[1] // JS kabi belgi kutyapmiz
	fmt.Println(string(c))
}
```

```console
$ go run xato/main.go
# command-line-arguments
xato/main.go:7:15: cannot use s[1] (value of type byte) as rune value in variable declaration
```

`xato/main.go:7:15` — 7-я строка, 15-й столбец, то есть `s[1]`. *cannot use s[1] (value of type byte) as rune value in
variable declaration* — «нельзя использовать `s[1]` типа `byte` как значение `rune` в объявлении переменной». Go не
делает неявных преобразований. Если написать `rune(s[1])`, код скомпилируется, но это всё равно байт 202:
`string(rune(s[1]))` → `Ê`. **Исправление:** `[]rune(s)[1]`, а если символ нужен строкой — `string([]rune(s)[1])`.
Подробнее — в разделе «Индекс».

**3. Побайтовая нарезка.** `s[:n]` берёт `n` **байтов** и может разрезать узбекскую букву пополам: `"o\xca"`. В тексте
уведомления или превью это выглядит как `�`. Пример — в разделе «Глубже». **Исправление:** `string([]rune(s)[:n])`.

**4. Сравнивать внешне одинаковый текст через `==`.** `Oʻzbekiston` и `O'zbekiston` не равны, и нормализация не
помогает. Пример — в разделе «Последствие на бэкенде». **Исправление:** заменяйте апострофы после `o`/`g` через
`strings.NewReplacer` и перед сохранением, и перед поиском. Не заменяйте каждый `'`: `strings.ReplaceAll` превращает
*maʼno* в `maʻno`.

```go filename="uyga/javob/oson/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

// Javob: len baytlarni sanaydi: "Gʻani" = 6 bayt (ʻ ikki bayt), lekin 5 rune.
// Frontend'dagi .length UTF-16 birliklarini sanaydi; bu ismlarda u rune soniga teng, shuning uchun backend
// rune'larni sanashi kerak: utf8.RuneCountInString.
// (Emoji kabi U+FFFF dan katta belgilarda JS .length 2 beradi, rune esa 1 — bu yerda ular uchramaydi.)
func ismTekshir(ism string) string {
	if utf8.RuneCountInString(ism) <= 5 {
		return "qabul"
	}
	return "juda uzun"
}

func main() {
	for _, ism := range []string{"Anvar", "Gʻani", "Oʻktam"} {
		fmt.Println(ism, ismTekshir(ism))
	}
}
```

```console
$ go run uyga/javob/oson/main.go
Anvar qabul
Gʻani qabul
Oʻktam juda uzun
```

Для символов больше U+FFFF, например эмодзи, `.length` в JS даёт 2, а число рун — 1. Для таких имён на фронтенде
используйте `[...s].length`.

🟡 `s[:n]` берёт `n` байтов: 3-й байт в «Toʻlov» — первый байт перевёрнутой запятой (`ca`). `[]rune(s)` разбивает
текст на руны, и нарезка идёт уже по целым символам:

```go filename="uyga/javob/orta/main.go" showLineNumbers
package main

import "fmt"

// Javob: s[:n] n ta BAYT oladi: "Toʻlov" ning 3-bayti ʻ ning birinchi bayti (ca), shuning uchun "To\xca…".
// []rune(s) matnni rune'larga ajratadi: kesish endi butun belgilar boʻyicha.
// Eslatma: rune ham har doim "harf" emas (oʻ = o + ʻ ikki rune), lekin UTF-8 endi buzilmaydi.
func qisqa(s string, n int) string {
	r := []rune(s)
	if len(r) <= n {
		return s
	}
	return string(r[:n]) + "…"
}

func main() {
	fmt.Printf("%q\n", qisqa("Toʻlov qabul qilindi", 3))
	fmt.Printf("%q\n", qisqa("Gʻalaba", 7))
	fmt.Printf("%q\n", qisqa("Payme orqali toʻlov", 5))
}
```

```console
$ go run uyga/javob/orta/main.go
"Toʻ…"
"Gʻalaba"
"Payme…"
```

Дополнительные упражнения (подробно в `homework/README.md`):

- 🟢 `len` считает байты, `utf8.RuneCountInString` — руны: «Gʻayrat» — 8 байтов и 7 рун.
- 🟡 Идём по рунам и считаем пару `oʻ gʻ sh ch` одной буквой: `shahar` — 6 рун, 5 букв.
- 🟠 `oʻzbek` наоборот — `kebzʻo`: перевёрнутая запятая теперь прилипла к `z`, потому что `oʻ` — одна буква, но две
  руны.
- 🔴 Go сортирует строки побайтово, поэтому `oʻrik` попадает между `olma` и `pomidor`. Порядок алфавита приходится
  писать вручную: `golang.org/x/text/collate` v0.42.0 это правило не применяет.
