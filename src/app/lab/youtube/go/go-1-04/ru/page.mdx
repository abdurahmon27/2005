## Что вы узнаете

Сколько букв в узбекском слове «oʻzbek» («узбек»)? Пять: oʻ, z, b, e и k. А если спросить Go через `len`, он
ответит **семь**. Замените апостроф на другой, и ответ станет шесть или восемь. Почему? В этом уроке разберёмся
и научимся работать с узбекским текстом, не ломая его.

**Одна идея:** в Go строка (`string`) — это последовательность байтов. `len` считает байты, а `range` выдаёт руны.
Узбекская буква может не совпадать ни с тем, ни с другим: в «oʻzbek» 5 букв, 6 рун и 7 байтов.

В конце урока вы:

- сможете объяснить, почему `len` и `utf8.RuneCountInString` дают разные числа;
- будете читать строку по рунам через `range` и поймёте, почему резать её по байтам опасно;
- отличите четыре вида апострофа и узнаете, какой из них правильный для oʻ и gʻ;
- сможете прочитать функцию, которая перед поиском приводит текст к одному виду.

Три главных новых слова сегодня:

| Слово | Простой смысл | По-английски |
|---|---|---|
| байт | самая маленькая порция памяти из 8 битов: одно число от 0 до 255 | byte |
| руна | один символ из списка Unicode, точнее его номер | rune |
| UTF-8 | правило, по которому номер символа раскладывается на 1–4 байта | UTF-8 |

По пути встретятся ещё два вспомогательных слова: **номер Unicode** (номер символа в мировом списке, например
`U+02BB`) и **шестнадцатеричная запись** (способ записывать байт двумя знаками, например `ca`). Оба объясним
там, где они понадобятся.

## Одно слово, четыре вида апострофа

В памяти компьютера нет букв, есть только числа. Значит, каждому символу нужно дать число. Для этого есть большой
список, о котором договорился весь мир: **Unicode**. Представьте каталог библиотеки: каждый символ — латинская
`z`, кириллическая `ж`, китайский иероглиф, эмодзи — получает свой номер. Этот номер называется **номером
Unicode** и записывается с `U+`: `z` = `U+007A`, `ʻ` = `U+02BB`. (Цифры после `U+` записаны в шестнадцатеричной
системе; это объясним ниже.)

В Go один символ из списка Unicode, точнее его номер, называется **руной** (rune). Руна — не то же самое, что
буква: узбекская буква `oʻ` состоит из двух рун — `o` и перевёрнутой запятой `ʻ`.

Теперь опыт. Запишем слово «oʻzbek» с четырьмя разными апострофами. На экране они на первый взгляд почти
одинаковы, но для компьютера это четыре разных символа. Глаз их не различает, поэтому рядом с каждым в
комментарии записано имя символа в Unicode. Это файл `uch/main.go` из папки курса (`uch` — «три»):

```go filename="uch/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	sozlar := []string{
		"o'zbek", // U+0027 APOSTROPHE (klaviaturadagi)
		"oʻzbek", // U+02BB MODIFIER LETTER TURNED COMMA
		"o’zbek", // U+2019 RIGHT SINGLE QUOTATION MARK
		"o‘zbek", // U+2018 LEFT SINGLE QUOTATION MARK
	}
	for _, s := range sozlar {
		fmt.Printf("%s  len=%d  rune=%d  % x\n", s, len(s), utf8.RuneCountInString(s), s)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 1 | `package main` | знакомый шаблон: запускаемая программа |
| 3–6 | `import ( "fmt" "unicode/utf8" )` | подключаем два пакета. В скобках можно перечислить несколько пакетов. `unicode/utf8` — пакет для работы с текстом в UTF-8 |
| 8 | `func main() {` | программа начинается здесь |
| 9 | `sozlar := []string{` | новая переменная `sozlar` («слова»): список строк. `[]string{…}` — «список из `string`, внутри …». Такой список называется **слайсом** (slice), его изучим в [GO-1.08](/lab/youtube/go/go-1-08/ru) |
| 10–13 | `"o'zbek", // U+0027 …` | четыре строки, отличаются только апострофом. После `//` — комментарий: номер символа в Unicode и его имя |
| 15 | `for _, s := range sozlar {` | по очереди кладёт каждую строку списка в `s`. `_` — «номер позиции не нужен». `range` подробно разберём в [GO-1.05](/lab/youtube/go/go-1-05/ru) |
| 16 | `fmt.Printf(…)` | выводит по шаблону (объясним ниже) |

`Printf` — «вывести по шаблону». Первое значение — текст шаблона. На место каждого `%` в нём по очереди
подставляются следующие значения:

| В шаблоне | Какое значение | Что выводится |
|---|---|---|
| `%s` | `s` | сама строка |
| `len=%d` | `len(s)` | число, которое вернул `len` (`%d` — десятичное число) |
| `rune=%d` | `utf8.RuneCountInString(s)` | количество рун в строке |
| `% x` | `s` | каждый байт строки в шестнадцатеричной записи, через пробел |
| `\n` | — | переход на новую строку (`Printf` сам не переходит) |

Прежде чем запускать, подумайте: будет ли `len` одинаковым во всех четырёх строках? **A)** да, везде 5 (число
букв) · **B)** да, везде 6 · **C)** нет, разным

<details>
<summary>Ответ</summary>

**C: разным.** Хотя четыре строки на экране выглядят почти одинаково, апострофы — разные символы. Каждый занимает
в памяти разное место. А `len` считает не буквы и не руны, а **байты**. Если вы выбрали «A», вы думали, что `len`
считает буквы: это главная ловушка урока. Если «B» — что он считает руны: рун действительно 6, но `len` считает
другое.

</details>

```console
$ go run ./uch
o'zbek  len=6  rune=6  6f 27 7a 62 65 6b
oʻzbek  len=7  rune=6  6f ca bb 7a 62 65 6b
o’zbek  len=8  rune=6  6f e2 80 99 7a 62 65 6b
o‘zbek  len=8  rune=6  6f e2 80 98 7a 62 65 6b
```

Рун везде 6. А `len` — 6, 7, 8 и 8: три разные длины. Значит, `len` считает байты.

В правом столбце — сами байты. Они записаны в **шестнадцатеричной системе** (по-английски **hexadecimal**,
коротко hex). В ней 16 цифр: `0`–`9`, затем `a` = 10, `b` = 11, `c` = 12, `d` = 13, `e` = 14, `f` = 15. Каждый
байт (0–255) записывается ровно двумя такими цифрами: `6f` = 6 × 16 + 15 = 111, `ca` = 12 × 16 + 10 = 202.

Сравним апострофы:

| Символ | Номер Unicode | Имя в Unicode | Байты | Сколько байтов |
|---|---|---|---|---|
| `'` | U+0027 | APOSTROPHE (апостроф с клавиатуры) | `27` | 1 |
| `ʻ` | U+02BB | MODIFIER LETTER TURNED COMMA (перевёрнутая запятая) | `ca bb` | 2 |
| `’` | U+2019 | RIGHT SINGLE QUOTATION MARK (правая фигурная) | `e2 80 99` | 3 |
| `‘` | U+2018 | LEFT SINGLE QUOTATION MARK (левая фигурная) | `e2 80 98` | 3 |

Апостроф с клавиатуры — один байт, перевёрнутая запятая в букве oʻ — два байта, а фигурные апострофы — по три.
Вот как правильно записанное «oʻzbek» лежит в памяти:

```text
позиция байта:  0    1    2    3    4    5    6      len = 7 байтов
байт:           6f   ca   bb   7a   62   65   6b
руна:           o    ʻ ─────   z    b    e    k      6 рун
буква:          oʻ ────────    z    b    e    k      5 букв
```

В одном слове три разных числа: 5 букв, 6 рун, 7 байтов.

## Почему так: строка — последовательность байтов, и UTF-8

Официальные правила Go (спецификация) говорят прямо: `string` — это **последовательность байтов**, а её длина —
количество байтов. `string` может хранить любые байты. Но сам код на Go пишется в UTF-8, поэтому текст в кавычках
превращается в байты UTF-8.

**UTF-8** — правило, по которому номер символа в Unicode раскладывается на байты. Один байт вмещает только 0–255,
а номера Unicode гораздо больше. Поэтому UTF-8 записывает номер в несколько байтов. Маленький номер помещается в
один байт, больший занимает два, три или четыре. Представьте поезд: каждый символ — поезд из 1–4 вагонов, а
головной вагон говорит, сколько вагонов идёт за ним.

Правило зависит от того, во сколько битов помещается номер (бит — один 0 или 1, «лампочка» из
[GO-1.02](/lab/youtube/go/go-1-02/ru)):

| Номер помещается в | Диапазон Unicode | Байтов | Пример |
|---|---|---|---|
| 7 бит | U+0000 – U+007F | 1 | старый ASCII: латинские буквы, цифры, `'` U+0027 |
| 11 бит | U+0080 – U+07FF | 2 | `ʻ` U+02BB, `ʼ` U+02BC |
| 16 бит | U+0800 – U+FFFF | 3 | `’` U+2019, `‘` U+2018 |
| 21 бит | U+10000 – U+10FFFF | 4 | многие эмодзи, например 😀 U+1F600 |

**ASCII** — старый список из 128 символов: латинские буквы, цифры и знаки препинания. UTF-8 их не изменил,
поэтому английский текст и в UTF-8 занимает один байт на символ. Мы говорим «многие эмодзи», потому что не все:
например, ✅ (U+2705) — три байта.

Номер `ʻ` — U+02BB, в десятичной записи 699. Он помещается в 11 бит, поэтому занимает два байта. Фигурные
апострофы U+2018 и U+2019 помещаются в 16 бит: три байта. Отсюда наши 6, 7, 8.

UTF-8 придумал в 1992 году Кен Томпсон вместе с Робом Пайком. По воспоминаниям Пайка, это было в кафе в
Нью-Джерси, на бумажной салфетке-подстилке. Позже оба стали двумя из трёх авторов Go (третий — Роберт Гриземер).

## Как собираются два байта

Теперь соберём один символ на уровне битов: как `ʻ` превращается в `ca bb`.

В UTF-8 каждый байт битами в своём начале сообщает, «кто он»:

| Начало байта | Смысл |
|---|---|
| `0xxxxxxx` | однобайтовый символ (ASCII) |
| `110xxxxx` | начало двухбайтового символа |
| `1110xxxx` | начало трёхбайтового символа |
| `11110xxx` | начало четырёхбайтового символа |
| `10xxxxxx` | продолжение: следующий байт предыдущего символа |

`x` — свободные места. В них записываются биты номера. В двухбайтовом шаблоне `110xxxxx 10xxxxxx`
5 + 6 = 11 свободных мест.

Это `bitlar/main.go` из папки курса (`bitlar` — «биты»):

```go filename="bitlar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	r := 'ʻ'
	fmt.Printf("%U = %d = %b (%d bit)\n", r, r, r, len(fmt.Sprintf("%b", r)))
	b := []byte(string(r))
	// 2 baytli qolip: 110xxxxx 10xxxxxx, 11 ta x ga raqamning bitlari
	fmt.Printf("110|%05b  10|%06b  = % x\n", r>>6, r&0x3f, b)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `r := 'ʻ'` | **одинарные** кавычки (`' '`) — одна руна. Её значение — номер символа, 699. Двойные кавычки (`" "`) дали бы строку |
| 7 | `fmt.Printf("%U = %d = %b (%d bit)\n", …)` | `%U` — в виде `U+02BB`, `%d` — в десятичной записи, `%b` — в двоичной (только 0 и 1). В последний `%d` попадает длина двоичной записи, то есть число битов: `fmt.Sprintf` ничего не выводит, а собирает и возвращает строку, `len` её считает |
| 8 | `b := []byte(string(r))` | превращает руну в строку (байты UTF-8), затем в список байтов |
| 9 | `// 2 baytli qolip: …` | комментарий («двухбайтовый шаблон») |
| 10 | `fmt.Printf("110\|%05b  10\|%06b  = % x\n", r>>6, r&0x3f, b)` | `r>>6` сдвигает номер на 6 бит вправо: последние 6 бит отпадают, остаётся первая часть. `r&0x3f`, наоборот, оставляет только последние 6 бит (`0x3f` = `111111`). `%05b` — двоичное число из 5 знаков (с нулями впереди), `%06b` — из 6 |

`>>` и `&` из строки 10 запоминать не обязательно: они нужны, чтобы разделить номер на две части.

Подумайте: во сколько битов помещается 699? **A)** 8 · **B)** 10 · **C)** 11

<details>
<summary>Ответ</summary>

**B: 10 бит.** В 10 битов помещаются числа от 0 до 1023 (2¹⁰ = 1024), а в 9 — только до 511. 699 — между ними.
Если вы выбрали «A»: 8 бит — только до 255. «C»: в шаблоне 11 мест, но самому номеру хватает 10 бит. В
оставшееся место пишется ноль.

</details>

```console
$ go run ./bitlar
U+02BB = 699 = 1010111011 (10 bit)
110|01010  10|111011  = ca bb
```

Как легли биты:

```text
699 = 1010111011                 10 бит
в 11 мест:   0 1010111011        впереди один 0
           = 01010 | 111011      5 бит + 6 бит

1-й байт: 110 + 01010  = 11001010 = ca
2-й байт:  10 + 111011 = 10111011 = bb
```

Благодаря этим началам программа, взглянув на любой байт, сразу понимает: начало это символа или продолжение.
Начинается с `10` — продолжение, с `110` — начало нового символа. Даже программа, начавшая читать с середины
текста, найдёт, где начинается следующий символ.

## range: чтение строки по рунам

Теперь пройдём по строке с помощью `range`. `for … range` читает строку не по байтам, а **по рунам**. Это
`aylanish/main.go` (`aylanish` — «обход»):

```go filename="aylanish/main.go" showLineNumbers
package main

import "fmt"

func main() {
	s := "oʻzbek"
	for i, r := range s {
		fmt.Printf("%d  %c  %U  %d\n", i, r, r, r)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `s := "oʻzbek"` | слово с правильным символом (7 байтов) |
| 7 | `for i, r := range s {` | на каждом шаге два значения: `i` — позиция байта, где начинается руна, `r` — сама руна |
| 8 | `fmt.Printf("%d  %c  %U  %d\n", i, r, r, r)` | выводит позицию, символ (`%c`), номер Unicode (`%U`) и этот же номер в десятичной записи (`%d`) |

В Go `rune` — число типа `int32`, в нём хранится один номер Unicode. А `byte` — это `uint8`. Оба — просто другие
имена целочисленных типов из [GO-1.02](/lab/youtube/go/go-1-02/ru).

Угадайте: какие позиции будут в первом столбце? **A)** `0 1 2 3 4 5` · **B)** `0 1 3 4 5 6` ·
**C)** `0 2 3 4 5 6`

<details>
<summary>Ответ</summary>

**B: `0 1 3 4 5 6`.** `i` — позиция **байта**, где начинается руна. `o` начинается в байте 0, `ʻ` — в байте 1 и
занимает два байта (1 и 2). Поэтому следующая руна `z` — в байте 3. Если вы выбрали «A», вы приняли `i` за
порядковый номер руны. Если «C» — решили, что `o` занимает два байта: `o` — обычный ASCII, один байт.

</details>

```console
$ go run ./aylanish
0  o  U+006F  111
1  ʻ  U+02BB  699
3  z  U+007A  122
4  b  U+0062  98
5  e  U+0065  101
6  k  U+006B  107
```

Индексы 0, 1, а потом вдруг 3. Двойки нет, потому что перевёрнутая запятая заняла два байта. Справа — номер
каждой руны: перевёрнутая запятая — 699, обычная `z` — 122.

| Шаг | `i` (позиция байта) | `r` | Байты, занятые руной |
|---|---|---|---|
| 1 | 0 | `o` (111) | 0 |
| 2 | 1 | `ʻ` (699) | 1, 2 |
| 3 | 3 | `z` (122) | 3 |
| 4 | 4 | `b` (98) | 4 |
| 5 | 5 | `e` (101) | 5 |
| 6 | 6 | `k` (107) | 6 |

## Побайтово: s[i] — один байт

Теперь пройдём побайтово обычным `for` из трёх частей (как в [GO-0.05](/lab/youtube/go/go-0-05/ru)). Это `bayt/main.go`
(`bayt` — «байт»):

```go filename="bayt/main.go" showLineNumbers
package main

import "fmt"

func main() {
	s := "oʻzbek"
	for i := 0; i < len(s); i++ {
		fmt.Printf("%c", s[i])
	}
	fmt.Println()
}
```

| Строка | Код | Что делает |
|---|---|---|
| 7 | `for i := 0; i < len(s); i++ {` | `i` от 0 до 6: `len(s)` = 7 байтов |
| 8 | `fmt.Printf("%c", s[i])` | `s[i]` — `i` в квадратных скобках: **один байт** строки на позиции `i`. А `%c` выводит символ, номер Unicode которого равен этому числу |
| 10 | `fmt.Println()` | в конце переходит на новую строку |

Вопрос: что появится на экране? Не спешите, остановитесь и подумайте. **A)** `oʻzbek` ·
**B)** `o`, затем два странных символа, затем `zbek` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B: `oÊ»zbek`.** Два байта перевёрнутой запятой стали двумя отдельными символами. Первый байт — `ca`, в
десятичной записи 202. `%c` принимает его за номер Unicode 202, а U+00CA — это заглавная `Ê` с «шапочкой».
Второй — `bb` = 187, U+00BB — угловая кавычка `»`. Если вы выбрали «A», вы приняли `s[i]` за букву или руну: это
один байт. Не «C»: код правильный, он просто делает не то, чего мы ждали.

</details>

```console
$ go run ./bayt
oÊ»zbek
```

| `i` | `s[i]` (hex) | десятичное | что вывел `%c` |
|---|---|---|---|
| 0 | `6f` | 111 | `o` |
| 1 | `ca` | 202 | `Ê` (U+00CA) |
| 2 | `bb` | 187 | `»` (U+00BB) |
| 3–6 | `7a 62 65 6b` | 122 98 101 107 | `z b e k` |

Если сайт путает кодировку (правило, по которому текст читается из байтов), выходит ровно это: байты UTF-8,
прочитанные по старому правилу Latin-1, выглядят как `oÊ»zbek`. А в кириллической кодировке (Windows-1251) вместо
`Ê` будет кириллическая `К`: `oК»zbek`. Такие «странные буквы» вы, наверное, видели на сломанных сайтах.

## Срез: половина символа

Та же проблема и при срезе. Взять кусок строки называется **срезом**: `s[:2]` — «с начала до байта 2 (сам байт 2
не входит)», то есть байты 0 и 1. Это `kesish/main.go` (`kesish` — «резать»):

```go filename="kesish/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "oʻzbek"
	fmt.Printf("%q\n", s[:2])                 // 2 bayt: belgining yarmi
	fmt.Println(utf8.ValidString(s[:2]))      // bu UTF-8 emas
	fmt.Printf("%q\n", string([]rune(s)[:2])) // 2 rune: butun "oʻ"
	fmt.Printf("%q\n", string([]rune(s)[:1])) // 1 rune: faqat "o"
}
```

| Строка | Код | Что делает |
|---|---|---|
| 10 | `fmt.Printf("%q\n", s[:2])` | берёт первые 2 байта. `%q` выводит строку в кавычках, а неправильный байт показывает как `\x` и две hex-цифры |
| 11 | `utf8.ValidString(s[:2])` | правильный ли это UTF-8? `true` или `false` |
| 12 | `string([]rune(s)[:2])` | `[]rune(s)` превращает строку в список рун (6 штук). `[:2]` — первые 2 руны. `string(…)` — снова в строку |
| 13 | `string([]rune(s)[:1])` | только первая руна |

Угадайте: какая из четырёх строк даст целую букву `oʻ`? **A)** строка 1 (`s[:2]`) · **B)** строка 3
(2 руны) · **C)** строка 4 (1 руна)

<details>
<summary>Ответ</summary>

**B: строка 3.** `s[:2]` берёт два **байта**: `o` и только первый байт перевёрнутой запятой, `ca`. Это уже не
правильный UTF-8. А две **руны** — это `o` и целая `ʻ`, то есть `oʻ`. В строке 4 одна руна — только `o`: буква
`oʻ` — это две руны.

</details>

```console
$ go run ./kesish
"o\xca"
false
"oʻ"
"o"
```

Отрежете первые два байта — останется половина перевёрнутой запятой: `"o\xca"`, и `ValidString` скажет `false`.
Режете по рунам — UTF-8 не ломается. Но может сломаться буква: возьмёте первую руну — останется только `o`.

```text
символы:         o    ʻ         z    b    e    k
байты:           6f   ca   bb   7a   62   65   6b

s[:2]            6f   ca             → "o\xca"   ✗ половина символа
[]rune(s)[:2]    o    ʻ              → "oʻ"      ✓ целая буква
[]rune(s)[:1]    o                   → "o"       ✓ правильный UTF-8, ✗ половина буквы
```

Ещё два замечания. `[]rune(s)` создаёт новый список: для большого текста это дорого. А неправильные байты он
молча превращает в U+FFFD (символ `�`).

## Какой апостроф правильный?

Итак, какой символ правильный для oʻ и gʻ? **CLDR** — база данных Unicode о языках: алфавиты, порядок сортировки,
запись дат. CLDR использует для oʻ и gʻ перевёрнутую запятую (U+02BB). Её имя — *modifier letter turned comma*,
«перевёрнутая запятая, которая присоединяется к букве». Unicode считает её не знаком препинания, а **буквой**.

Знак тутук (узбекский знак, отделяющий звуки) в слове *maʼno* («смысл») — другая буква: U+02BC, *modifier letter
apostrophe*. В Unicode она тоже буква. В английском для апострофа рекомендуется правая фигурная кавычка (U+2019).
Но в узбекском перевёрнутая запятая — часть буквы, а фигурные `‘ ’` в узбекской латинице служат внутренними
кавычками.

| Символ | Unicode | Что это в Unicode | Где правильно |
|---|---|---|---|
| `ʻ` | U+02BB | буква | oʻ, gʻ (CLDR) |
| `ʼ` | U+02BC | буква | знак тутук: maʼno |
| `’` | U+2019 | знак препинания (кавычка) | английский апостроф |
| `‘` | U+2018 | знак препинания (кавычка) | кавычка |
| `'` | U+0027 | знак препинания | апостроф с клавиатуры |

На практике же всё перемешано. Мы скачали страницу закона о новом алфавите на lex.uz 25 ноября 2026 года и
посчитали символы после букв o и g (код JavaScript на странице не учитывался; это делает программа `lexuz` из
папки курса):

| Символ | Сколько раз |
|---|---|
| `ʻ` U+02BB | 60 |
| `‘` U+2018 | 16 |
| `’` U+2019 | 2 |
| `'` U+0027 (клавиатура) | 1 |

В самом тексте закона использован правильный символ. Но на всей странице (с меню и заголовками) встречаются четыре
разных символа, даже в одной строке два разных: `Oʻzbekiston Respublikasining Qonuni, 21.10.2026 yildagi O‘RQ-1184-son`
(в первом слове `ʻ`, в последнем `‘`). Левая фигурная кавычка похожа на перевёрнутую запятую, поэтому часто стоит
вместо неё. А Word обычно сам заменяет апостроф с клавиатуры на правую фигурную (`’`). Если сайт изменится, эти
числа тоже могут измениться.

## Пример из жизни: поиск, разбиение, сортировка

В базе `Oʻzbekiston` («Узбекистан») сохранён с правильным символом, а пользователь набрал в поиске с клавиатуры
`O'zbekiston`. Это `qidiruv/main.go` (`qidiruv` — «поиск»):

```go filename="qidiruv/main.go" showLineNumbers
package main

import (
	"fmt"
	"slices"
	"strings"
	"unicode"
)

func main() {
	baza := "Oʻzbekiston poytaxti Toshkent" // bazada: U+02BB
	soz := "O'zbekiston"                    // klaviaturadan: U+0027
	fmt.Println(strings.Contains(baza, soz))

	harfEmas := func(r rune) bool { return !unicode.IsLetter(r) }
	fmt.Println(strings.FieldsFunc("oʻzbek o'zbek o’zbek", harfEmas))

	sozlar := []string{"olma", "pomidor", "oʻrik", "zarang", "gilos", "gʻoz"}
	slices.Sort(sozlar)
	fmt.Println(sozlar)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 11 | `baza := "Oʻzbekiston poytaxti Toshkent"` | `baza` («база»): сохранённый текст («столица Узбекистана — Ташкент»), с U+02BB |
| 12 | `soz := "O'zbekiston"` | `soz` («слово»): то, что набрал пользователь, с апострофом клавиатуры U+0027 |
| 13 | `strings.Contains(baza, soz)` | есть ли `soz` внутри `baza`? `true` или `false` |
| 15 | `harfEmas := func(r rune) bool { … }` | маленькая безымянная функция в переменной `harfEmas` («не буква»). Принимает руну, возвращает `bool`: `unicode.IsLetter(r)` — «`r` буква?», `!` — «не». Функции: [GO-1.06](/lab/youtube/go/go-1-06/ru) |
| 16 | `strings.FieldsFunc("…", harfEmas)` | режет строку в каждом месте, где `harfEmas` говорит `true`, и возвращает список слов. В строке три по-разному записанных «oʻzbek» |
| 18 | `sozlar := []string{…}` | шесть названий (olma — яблоко, pomidor — помидор, oʻrik — абрикос, zarang — клён, gilos — черешня, gʻoz — гусь) |
| 19 | `slices.Sort(sozlar)` | сортирует список на месте |
| 20 | `fmt.Println(sozlar)` | `Println` выводит список в квадратных скобках: `[a b c]` |

Два предсказания. Что будет в первой строке? **A)** `true` · **B)** `false` · **C)** ошибка компиляции.
Куда попадёт `oʻrik` в третьей строке? **D)** в конец, после `zarang` · **E)** между `olma` и `pomidor` ·
**F)** в самое начало

<details>
<summary>Ответ</summary>

**B и E.** Поиск даёт `false`: `strings.Contains` сравнивает байты. Байт `27` из `soz` не совпадает с `ca bb` из
`baza`. При сортировке Go тоже сравнивает строки побайтово: второй байт `oʻrik` — `ca`, у `olma` — `l` (`6c`),
поэтому `oʻrik` идёт после `olma`. Первый байт — `o` (`6f`), у `pomidor` — `p` (`70`), поэтому раньше `pomidor`.
«D» было бы правильно по узбекскому алфавиту, но Go не знает алфавита.

</details>


Итог: поиск — `false`, не найдено. Во второй строке слово с правильным символом осталось целым, а два других

Сортировка идёт по байтам. А в нынешнем узбекском алфавите буквы oʻ, gʻ, sh и ch идут после `z` (CLDR):

|---|---|

## Решение: tozala

Решение: приводите текст к **одному виду** и перед записью в базу, и перед поиском. Это `tozala/main.go`
(`tozala` — «очистить»):

```go filename="tozala/main.go" showLineNumbers
package main

import (
	"fmt"
	"strings"
	"unicode"
)

// tozala apostrof turlarini bir xil qiladi:
// o/g dan keyin -> ʻ (U+02BB), boshqa harfdan keyin -> ʼ (U+02BC, tutuq belgisi).
// Faqat harfdan keyin turganlarini oʻzgartiradi: soʻz boshidagi ‘ qoʻshtirnoqqa tegmaydi.
func tozala(s string) string {
	r := []rune(s)
	for i := 1; i < len(r); i++ {
		if !strings.ContainsRune("'`´‘’ʻʼ", r[i]) || !unicode.IsLetter(r[i-1]) {
			continue
		}
		ogdan := strings.ContainsRune("oOgG", r[i-1])
		keyingiHarf := i+1 < len(r) && unicode.IsLetter(r[i+1])
		soz2 := i >= 2 && unicode.IsLetter(r[i-2]) // o/g soʻz boshida emas
		switch {
		case ogdan && (keyingiHarf || soz2): // oʻzbek, togʻ
			r[i] = 'ʻ'
		case keyingiHarf: // maʼno
			r[i] = 'ʼ'
		}
	}
	return string(r)
}

func main() {
	fmt.Println(tozala("O'zbekiston, tog’, ma'no, O`zbek"))
	fmt.Println(tozala("U ‘Salom’ dedi"))
	baza := tozala("Bu togʻ baland")
	fmt.Println(strings.Contains(baza, tozala("tog'")))
}
```

Функция ищет известные нам виды апострофов и меняет только те, что стоят **после буквы**:

| Строка | Код | Что делает |
|---|---|---|
| 9–11 | `// tozala …` | комментарий: что делает функция |
| 12 | `func tozala(s string) string {` | функция `tozala`: принимает строку, возвращает строку |
| 13 | `r := []rune(s)` | превращает строку в список рун: `string` нельзя изменить на месте, а список можно |
| 14 | `for i := 1; i < len(r); i++ {` | начиная с руны 1 (перед руной 0 буквы нет) |
| 15–17 | `if !… \|\| !… { continue }` | если `r[i]` **не** один из апострофов или руна перед ним **не** буква — `continue`: пропустить этот шаг и перейти к следующему. `\|\|` — «или» |
| 18 | `ogdan := …` | `ogdan` («после o/g»): предыдущая буква — `o`, `O`, `g` или `G`? |
| 19 | `keyingiHarf := …` | `keyingiHarf` («следующая буква»): есть ли следующая руна и буква ли она? `&&` — «и» |
| 20 | `soz2 := …` | o/g тоже не в начале слова (перед ней есть ещё буква)? |
| 21 | `switch {` | срабатывает первый `case`, равный `true` (`switch`: [GO-1.05](/lab/youtube/go/go-1-05/ru)) |
| 22–23 | `case ogdan && (…): r[i] = 'ʻ'` | после o/g, если дальше буква или это конец слова: перевёрнутая запятая |
| 24–25 | `case keyingiHarf: r[i] = 'ʼ'` | между двумя другими буквами: знак тутук |
| 28 | `return string(r)` | превращает список снова в строку и возвращает её |
| 32–33 | `tozala(…)` | две проверочные строки |
| 34–35 | `baza := tozala("Bu togʻ baland")` | очищаем перед записью в базу («Эта гора высокая») и перед поиском: `tozala("tog'")` (`tog'` — «гора») |

Правило на нескольких словах:

| В тексте | Предыдущая буква | Следующая руна | Результат |
|---|---|---|---|
| `O'zbekiston` | `O` (o/g) | `z` буква | `ʻ` → `Oʻzbekiston` |
| `tog’` | `g` (o/g), перед ней `o` | `,` не буква | `ʻ` → `togʻ` (и в конце слова) |
| `ma'no` | `a` | `n` буква | `ʼ` → `maʼno` |
| `‘` в `‘Salom’` | пробел, не буква | — | не трогается |
| `’` в `‘Salom’` | `m` | пробел | ни один `case` не подходит: не трогается |

Угадайте: что станет со второй строкой, `U ‘Salom’ dedi` («Он сказал ‘Привет’»)? **A)** не изменится ·
**B)** обе кавычки станут `ʻ` · **C)** только `’` станет знаком тутук

<details>
<summary>Ответ</summary>

**A: не изменится.** Перед `‘` стоит пробел: это не буква, строка 15 её пропускает. Перед `’` стоит буква `m`, но
`m` — не o/g, а после `’` пробел: оба `case` дают `false`. Если вы выбрали «C»: для знака тутук следующая руна тоже
должна быть буквой.

</details>

```console
$ go run ./tozala
Oʻzbekiston, togʻ, maʼno, Oʻzbek
U ‘Salom’ dedi
true
```

Слова перешли на правильные символы, фраза в кавычках не изменилась, а поиск теперь возвращает `true`.

Но и это правило не идеально. Апостроф в слове `Go'da` («в Go») отделяет окончание, а `tozala` превращает его в
`ʻ` (`Goʻda`, так же `Rio’ga` → `Rioʻga`). Закрывающая кавычка после слова на o или g тоже становится буквой:
`‘Bingo’ oʻyini` → `‘Bingoʻ oʻyini`. Поэтому делайте очистку **в одном месте** и защитите её тестом. Писать
тесты научимся в [GO-1.07](/lab/youtube/go/go-1-07/ru).

## 2027 год: новый алфавит и кириллическая буква

Закон о новом алфавите (OʻRQ-1184, подписан 21 октября 2026 года) вступает в силу 22 апреля 2027 года. В нём
вместо oʻ и gʻ — буквы без апострофа (`Ö`, `Ğ`, а также `Ş`, `Ç`), алфавит состоит из 28 букв и знака тутук `ʼ`.
Документы старого образца остаются в силе, а сроки перехода определит правительственная программа. Знак тутук
остаётся.

Проблема не исчезает, она меняет форму. Новую `ö` можно записать двумя способами: одним символом или обычной `o`
с отдельными двумя точками над ней. Это `yangi/main.go` (`yangi` — «новый»):

```go filename="yangi/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	nfc := "\u00f6zbek"  // ö bitta belgi (U+00F6)
	nfd := "o\u0308zbek" // o + ustidagi ikki nuqta (U+0308)
	for _, s := range []string{nfc, nfd} {
		fmt.Printf("%s  len=%d  rune=%d\n", s, len(s), utf8.RuneCountInString(s))
	}
	fmt.Println(nfc == nfd)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 9 | `nfc := "özbek"` | `\u` и 4 hex-цифры — символ внутри строки, записанный номером Unicode. U+00F6 — один символ `ö` |
| 10 | `nfd := "özbek"` | обычная `o` и U+0308: две точки, которые ставятся над предыдущей буквой |
| 11–13 | `for _, s := range …` | выводит `len` и число рун обеих строк |
| 14 | `fmt.Println(nfc == nfd)` | равны ли они? |

Угадайте: что будет в последней строке? **A)** `true`, на экране ведь одинаково · **B)** `false`

<details>
<summary>Ответ</summary>

**B: `false`.** `==` сравнивает строки побайтово. U+00F6 — два байта, а `o` + U+0308 — три: байты разные. То, что
на экране они выглядят одинаково, для Go ничего не значит.

</details>

```console
$ go run ./yangi
özbek  len=6  rune=5
özbek  len=7  rune=6
false
```

Это исправляет **нормализация** (normalization: приведение одинаково выглядящего текста к одной стандартной
записи). В Go её нет в стандартной библиотеке, она в отдельном пакете `golang.org/x/text/unicode/norm` (в модуле
`x/text`).

Но в таблице алфавита на той же странице lex.uz `A` и ещё одна буква набраны кириллицей. Это `kirill/main.go`:

```go filename="kirill/main.go" showLineNumbers
package main

import "fmt"

func main() {
	lotin := "A"
	kirill := "\u0410" // lex.uz alifbo jadvalidagi birinchi "A"
	for _, s := range []string{lotin, kirill} {
		fmt.Printf("%s  %U  len=%d\n", s, []rune(s)[0], len(s))
	}
	fmt.Println(lotin == kirill)
}
```

| Строка | Код | Что делает |
|---|---|---|
| 6 | `lotin := "A"` | `lotin` («латиница»): латинская `A`, U+0041 |
| 7 | `kirill := "А"` | `kirill` («кириллица»): кириллическая `А`, U+0410, первая буква таблицы на lex.uz |
| 9 | `fmt.Printf("%s  %U  len=%d\n", s, []rune(s)[0], len(s))` | выводит букву, номер Unicode первой руны и число байтов |
| 11 | `fmt.Println(lotin == kirill)` | равны ли? |

```console
$ go run ./kirill
A  U+0041  len=1
А  U+0410  len=2
false
```

На глаз одинаковы, но кириллическая `А` — два байта, а `==` даёт `false`. Нормализация такие похожие буквы не
объединяет: в Unicode это действительно разные буквы. Unicode называет такие пары *confusables* («путаемые»).
Поэтому верьте не глазам, а байтам.

## Частые ошибки

**1. Думать, что `len` считает буквы.** Главная ловушка урока: программа не выдаёт ошибку, просто число неверное.
Мы видели это в разделе «Одно слово, четыре вида апострофа»: `len("oʻzbek")` = 7, а букв 5. **Исправление:** нужны
руны — `utf8.RuneCountInString(s)`. Нужны узбекские буквы — считайте oʻ, gʻ, sh, ch сами (уровень 🟡 Средний
домашнего задания).

**2. Считать `s[i]` буквой.** `s[i]` — один байт. В разделе «Побайтово» вывод через `%c` дал `oÊ»zbek`.
**Исправление:** если нужны символы, идите по строке через `for i, r := range s`.

**3. Резать строку по байтам.** `s[:2]` режет символ пополам и оставляет неправильный UTF-8 (раздел «Срез»).
**Исправление:** режьте через `[]rune(s)` или берите место среза из `i`, который выдаёт `range`; и помните, что
буква может состоять из двух рун.

**4. Двойные кавычки для руны.** Этого примера нет в папке курса, он запущен отдельно:

```go
package main

import "fmt"

func main() {
	var r rune = "ʻ"
	fmt.Println(r)
}
```

```console
$ go run qoshtirnoq/main.go
# command-line-arguments
qoshtirnoq/main.go:6:15: cannot use "ʻ" (untyped string constant) as rune value in variable declaration
```

Строка 6, символ 15: *cannot use "ʻ" (untyped string constant) as rune value in variable declaration* — «нельзя
использовать `"ʻ"` (строковую константу без типа) как значение руны в объявлении переменной». Двойные кавычки —
строка, а руна — число. **Исправление:** одинарные кавычки: `var r rune = 'ʻ'`.

**5. Считать `oʻ` одной руной.** (Нет в папке курса.)

```go
package main

import "fmt"

func main() {
	r := 'oʻ'
	fmt.Println(r)
}
```

```console
$ go run ikkibelgi/main.go
# command-line-arguments
ikkibelgi/main.go:6:7: more than one character in rune literal
```

*more than one character in rune literal* — «больше одного символа в одинарных кавычках». В одинарные кавычки
помещается только одна руна, а `oʻ` — это две: `o` и `ʻ`. **Исправление:** пишите `"oʻ"` (строку).

**6. Менять байт строки на месте.** (Нет в папке курса.) Хотим сделать первую букву заглавной:

```go
package main

import "fmt"

func main() {
	s := "oʻzbek"
	s[0] = 'O'
	fmt.Println(s)
}
```

```console
$ go run ozgartir/main.go
# command-line-arguments
ozgartir/main.go:7:2: cannot assign to s[0] (neither addressable nor a map index expression)
```

Строка 7: *cannot assign to s[0] (neither addressable nor a map index expression)* — «нельзя присвоить значение
`s[0]`». В Go `string` после создания не меняется. **Исправление:** соберите новую строку. Например, как в
`tozala`: `r := []rune(s)`, `r[0] = 'O'`, затем `s = string(r)`.

**7. Сравнивать байт с руной.** (Нет в папке курса.)

```go
package main

import "fmt"

func main() {
	s := "oʻzbek"
	if s[1] == 'ʻ' {
		fmt.Println("topildi")
	}
}
```

```console
$ go run taqqos/main.go
# command-line-arguments
taqqos/main.go:7:13: 'ʻ' (untyped rune constant 699) overflows byte
```

*'ʻ' (untyped rune constant 699) overflows byte* — «`'ʻ'` (рунная константа без типа, 699) не помещается в
`byte`». `s[1]` — это `byte`, он не вмещает числа больше 255 ([GO-1.02](/lab/youtube/go/go-1-02/ru)), а 699 больше.
**Исправление:** сравнивайте руны (`for _, r := range s { if r == 'ʻ' … }`) или используйте
`strings.ContainsRune(s, 'ʻ')`.

**8. Искать с разными апострофами.** Программа не выдаёт ошибку, просто ничего не находит (раздел «Пример из
жизни»). **Исправление:** пропускайте текст через одну функцию `tozala` и перед сохранением, и перед поиском.

## Проверьте себя

Сначала ответьте сами, потом откройте.

**1.** Почему `len("oʻzbek")` равно 7, а букв 5?

<details>
<summary>Ответ</summary>

`len` считает байты. Буква `oʻ` — две руны: `o` (1 байт) и `ʻ` U+02BB (2 байта). Остальные 4 буквы — по одному
байту: 1 + 2 + 4 = 7. Рун 6, а букв 5, потому что `oʻ` — одна буква.

</details>

**2.** Что выведет эта программа? **A)** `6 6` · **B)** `7 6` · **C)** `7 7`

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "gʻisht"
	fmt.Println(len(s), utf8.RuneCountInString(s))
}
```

<details>
<summary>Ответ</summary>

**B: `7 6`.** `gʻisht` («кирпич»): `g` — 1 байт, `ʻ` — 2 байта, `i s h t` — 4 байта, всего 7. Рун 6. (А узбекских
букв 4: gʻ, i, sh, t.)

```console
$ go run savol1/main.go
7 6
```

</details>

**3.** Что выведет эта программа?

```go
package main

import "fmt"

func main() {
	for i, r := range "gʻoz" {
		fmt.Print(i, " ", string(r), "  ")
	}
	fmt.Println()
}
```

<details>
<summary>Ответ</summary>

Позиции `0 1 3 4`: `ʻ` начинается в байте 1 и занимает два байта, поэтому `o` — в байте 3. `string(r)`
превращает руну в строку.

```console
$ go run savol2/main.go
0 g  1 ʻ  3 o  4 z  
```

</details>

**4.** Какой символ правильный для `oʻ` и `gʻ`? А для знака тутук в *maʼno*?

<details>
<summary>Ответ</summary>

Для oʻ, gʻ — U+02BB (перевёрнутая запятая, *modifier letter turned comma*), для знака тутук — U+02BC (*modifier
letter apostrophe*). Оба в Unicode — буквы. Именно их использует CLDR.

</details>

**5.** В базе `Oʻzbekiston` (U+02BB), пользователь искал `O'zbekiston`. Почему `strings.Contains` возвращает
`false` и что делать?

<details>
<summary>Ответ</summary>

`strings.Contains` сравнивает байты: `ca bb` и `27` разные. Решение: и перед сохранением, и перед поиском
приводить текст к одному виду одной функцией (`tozala` из урока).

</details>

**6.** Из [GO-1.02](/lab/youtube/go/go-1-02/ru): что выведет эта программа?

```go
package main

import "fmt"

func main() {
	var b byte = 255
	b++
	fmt.Println(b)
}
```

<details>
<summary>Ответ</summary>

`0`. `byte` — это `uint8`, он не вмещает числа больше 255. Если к 255 прибавить 1, значение без ошибки
«перекатывается» в 0 (переполнение, overflow).

```console
$ go run overflow/main.go
0
```

</details>

(Программ из вопросов 2, 3 и 6 нет в папке курса: они запущены отдельно.)

В `shahar` («город») 6 рун, но 5 букв: `sh` — одна буква. А в `Isʼhoq` (имя Исхак) знак тутук разделяет `s` и `h`,
