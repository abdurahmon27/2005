## Nimani oʻrganasiz

Roʻyxatdan oʻtish formasida ism 5 belgidan oshmasligi kerak. React'dagi `<input maxLength={5}>` «Gʻani» ismini
oʻtkazadi: `"Gʻani".length` — 5. Go backend'dagi `len(ism) <= 5` tekshiruvi esa xuddi shu ismni rad etadi, chunki
Go uchun uning uzunligi 6. Bitta soʻzda ham shunday: Node `"oʻzbek".length` ni 6 deydi, Go'ning `len` i esa 7.
Go nimani sanayapti?

**Bitta gʻoya:** Go'da matn baytlardan iborat: uzunlik, indeks va solishtirish baytlar boʻyicha ishlaydi, `oʻ` dagi
teskari vergul esa ikki bayt oladi.

Dars oxirida siz:

- Go'dagi `len`, `s[i]` va `==` nimani sanashi va solishtirishini JS, Python va PHP bilan solishtirib tushuntira
  olasiz;
- belgilar soni kerak boʻlsa `utf8.RuneCountInString`, belgining oʻzi kerak boʻlsa `[]rune(s)` ishlata olasiz;
- istalgan belgining UTF-8 da necha bayt olishini uning code point'idan aytib bera olasiz;
- bazadagi va qidiruvdagi oʻzbekcha apostroflarni bir xil koʻrinishga keltira olasiz, *maʼno* dagi tutuq belgisini
  buzmasdan.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| `string` = baytlar | Go'da matn baytlar ketma-ketligi: `len`, indeks `s[i]` va `==` baytlar bilan ishlaydi | string (a sequence of bytes) |
| `rune` | bitta code point, yaʼni belgining Unicode raqami; `int32` ning boshqa nomi | rune |
| UTF-8 | code point'ni 1–4 baytga yozish qoidasi; Go kodidagi matn shunday saqlanadi | UTF-8 |

Yordamchi soʻzlar ham bor: **code point** (UTF-8 boʻlimida), rune slice `[]rune(s)` (indeks boʻlimida) va
`strings.NewReplacer` (tuzatish boʻlimida).

## Bitta soʻz, toʻrt til

Avval Go'ning oʻzi, `hook/main.go`:

```go filename="hook/main.go" showLineNumbers
package main

import "fmt"

func main() {
	fmt.Println(len("oʻzbek")) // JS: "oʻzbek".length → 6
}
```

6-qatorda `len("oʻzbek")` — string uzunligi, izohda JS natijasi. Ikki tilni yonma-yon ishga tushiramiz:

```console
$ node -p '"oʻzbek".length'
6
$ go run hook/main.go
7
```

Yana ikki til, Python va PHP:

```console
$ python3 -c 'print(len("oʻzbek"))'
6
$ php -r 'echo strlen("oʻzbek");'
7
$ php -r 'echo mb_strlen("oʻzbek");'
6
```

`tillar/tekshir.sh` toʻrttasini bitta buyruqda chaqiradi:

```console
$ ./tillar/tekshir.sh
js     .length  6
python len      6
php    strlen   7
go     len      7
```

Bitta soʻzga ikki xil son chiqdi, chunki tillar uch xil birlikni sanaydi:

| Til | Ifoda | `"oʻzbek"` | Nimani sanaydi |
|---|---|---|---|
| JavaScript / TS | `s.length` | 6 | UTF-16 birliklari |
| Python | `len(s)` | 6 | code point'lar (Go'da: rune) |
| PHP | `strlen($s)` | 7 | baytlar |
| PHP | `mb_strlen($s)` | 6 | belgilar (code point'lar) |
| Go | `len(s)` | 7 | baytlar |

Go'da `string` — **baytlar ketma-ketligi**, `len` esa shu baytlarni sanaydi, PHP'dagi `strlen` kabi. Go
spetsifikatsiyasi aynan shunday deydi: «The number of bytes is called the length of the string». Python sanagan
birlik Go'da **rune** deyiladi. JavaScript'niki uchinchi xil: **UTF-16 birliklari** (ECMAScript: string uzunligi —
16 bitli elementlar soni). Bu soʻzda JS va Python bir xil 6 berdi, lekin ular har doim teng emas: buni oraliq
savolda koʻrasiz.

## UTF-8: code point → 1–4 bayt

Nega aynan 7 bayt? JavaScript'dagi `codePointAt` belgining raqamini beradi:

```console
$ node -p '"oʻzbek".codePointAt(1)'
699
```

(Bu buyruq kurs papkasida fayl sifatida yoʻq, kod buyruqning oʻzida.) Bu son **code point** deyiladi: belgining
Unicode raqami. U odatda oʻn oltilik sanoqda (hex) `U+02BB` koʻrinishida yoziladi: `0x2BB` = 699.

**UTF-8** — code point'ni baytlarga yozish qoidasi. Kichik code point bitta baytga, kattasi ikki, uch yoki toʻrt
baytga yoziladi (RFC 3629):

| Code point | Bayt | Misol |
|---|---|---|
| 0 … 127 | 1 | `o` = 111, `z` = 122 |
| 128 … 2 047 | 2 | `ʻ` = 699 |
| 2 048 … 65 535 | 3 | |
| 65 536 … 1 114 111 | 4 | |

Birinchi qator — ASCII oraligʻi: lotin harflari, raqamlar va klaviatura belgilari bir baytdan. `oʻ` dagi teskari
vergul 699, demak ikki bayt. `"oʻzbek"` Go string'ida shunday turadi:

| Belgi | `o` | `ʻ` | `z` | `b` | `e` | `k` |
|---|---|---|---|---|---|---|
| Code point | U+006F | U+02BB | U+007A | U+0062 | U+0065 | U+006B |
| UTF-8 baytlari (hex) | `6f` | `ca bb` | `7a` | `62` | `65` | `6b` |
| Bayt soni | 1 | 2 | 1 | 1 | 1 | 1 |

Jami 7 bayt, Go'ning `len` i aynan shularni sanaydi. Oʻn oltilikda `ca` = 12 × 16 + 10 = 202, `bb` = 187.

Go `string` istalgan baytlarni saqlay oladi. Lekin Go kodining oʻzi UTF-8 da yoziladi (spec: «Source code is Unicode
text encoded in UTF-8»), shuning uchun qoʻshtirnoq ichidagi `"oʻzbek"` aynan shu 7 baytga aylanadi.

## rune: Python sanagan birlik

Python sanagan oltita narsa — shu code point'lar: o, ʻ, z, b, e va k. Go'da bitta code point'ning turi **`rune`**.
U `int32` ning boshqa nomi (spec: «rune alias for int32»). `byte` esa `uint8` ning boshqa nomi.

Lekin rune ham harf emas. Alifboda `oʻ` bitta harf, rune esa ikkita: `o` va `ʻ`.

| Nima sanaladi | Soni | Nimalar |
|---|---|---|
| harf (alifbo) | 5 | oʻ, z, b, e, k |
| rune (code point) | 6 | o, ʻ, z, b, e, k |
| bayt (UTF-8) | 7 | 6f, ca, bb, 7a, 62, 65, 6b |

Go'da ikkalasini ham sanash mumkin, `uzunlik/main.go`:

```go filename="uzunlik/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "oʻzbek"
	fmt.Println(len(s))                    // baytlar soni
	fmt.Println(utf8.RuneCountInString(s)) // rune'lar (belgilar) soni
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 3–6 | `import ( "fmt" "unicode/utf8" )` | `unicode/utf8` — UTF-8 bilan ishlaydigan standart paket |
| 9 | `s := "oʻzbek"` | 7 baytli string |
| 10 | `len(s)` | baytlar soni |
| 11 | `utf8.RuneCountInString(s)` | rune'lar soni: baytlarni UTF-8 qoidasi bilan oʻqib, code point'larni sanaydi |

```console
$ go run uzunlik/main.go
7
6
```

Yetti va olti. JavaScript'da code point'larni spread sanaydi: `[...s]` string'ni code point'lar massiviga yoyadi.

```console
$ node -p '[..."oʻzbek"].length'
6
```

(Bu buyruq ham papkada yoʻq.)

## Indeks: `s[1]` belgi emas, bayt

JavaScript va Python'da `s[1]` ikkinchi belgini beradi:

```console
$ node -p '"oʻzbek"[1]'
ʻ
$ python3 -c 'print("oʻzbek"[1])'
ʻ
```

Go'da shu ifoda nima chiqaradi?

```go
s := "oʻzbek"
fmt.Println(s[1])
```

**A)** `ʻ` · **B)** `202` · **C)** `o`

<details>
<summary>Javob</summary>

**B: `202`.** Go'da string indeksi bitta **baytni** beradi, uning turi `byte` (spec: «a[x] is the non-constant byte
value at index x and the type of a[x] is byte»). 1-indeksdagi bayt — teskari vergulning birinchi bayti `ca`,
oʻnlikda 202. `fmt.Println` `byte` ni son qilib chiqaradi. «`ʻ`» ni tanlagan boʻlsangiz, JS va Python odatini
koʻchirgansiz. «`o`» ni tanlagan boʻlsangiz, indeks 1 dan boshlanadi deb oʻylagansiz: Go'da ham 0 dan.

</details>

Toʻliq dastur, `indeks/main.go`:

```go filename="indeks/main.go" showLineNumbers
package main

import "fmt"

func main() {
	s := "oʻzbek"
	fmt.Println(s[1])                 // JS va Python'da s[1] → "ʻ"; Go'da: 1-oʻrindagi bayt (byte, son)
	fmt.Printf("%x\n", s[1])          // oʻsha bayt oʻn oltilikda: ca (ʻ ning birinchi bayti)
	fmt.Println(string([]rune(s)[1])) // rune'lar boʻyicha: 1-element — ʻ
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7 | `s[1]` | 1-indeksdagi bayt; turi `byte` (`uint8`), `Println` uni son qilib chiqaradi |
| 8 | `fmt.Printf("%x\n", s[1])` | oʻsha bayt oʻn oltilikda: `%x` — hex, `\n` — yangi qator |
| 9 | `[]rune(s)` | string'ni rune slice'iga aylantiradi (konversiya `T(x)`): JS massiviga oʻxshash roʻyxat, har elementi bitta code point |
| 9 | `[]rune(s)[1]` | shu roʻyxatning indeksi 1 boʻlgan elementi: `ʻ` (699) |
| 9 | `string(…)` | rune'ni yana string'ga aylantiradi, shunda `Println` sonni emas, belgini chiqaradi |

```console
$ go run indeks/main.go
202
ca
ʻ
```

Farq shunda: string indeksi baytlar ustida yuradi, rune slice indeksi esa code point'lar ustida.

| Indeks | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| `s[i]` (bayt, hex) | `6f` | `ca` | `bb` | `7a` | `62` | `65` | `6b` |
| `[]rune(s)[i]` (rune) | `o` | `ʻ` | `z` | `b` | `e` | `k` | — |

JavaScript'da baytlarni `TextEncoder` beradi. Uning ham indeksi 1 boʻlgan elementi 202:

```console
$ node -p 'new TextEncoder().encode("oʻzbek")[1]'
202
```

(Papkada yoʻq.) Eʼtibor bering: `[]rune(s)` yangi slice yaratadi va butun matnni nusxalaydi. Qisqa ism yoki sarlavha
uchun bu muammo emas, katta matnda esa qimmat.

## Oraliq savol: emoji

JavaScript'da bu emoji'ning uzunligi 2:

```console
$ node -p '"😀".length'
2
```

😀 = U+1F600 = 128 512. Code point'ni UTF-8 jadvali bilan solishtiring. Go'da `len("😀")` nechta?

**A)** 1 · **B)** 2 · **C)** 4

<details>
<summary>Javob</summary>

**C: 4.** 128 512 > 65 535, demak jadvalning oxirgi qatori: UTF-8 uni toʻrt baytga yozadi. Rune esa bitta.
«2» ni tanlagan boʻlsangiz, JS natijasini koʻchirgansiz. JS'dagi 2 ning sababi boshqa: UTF-16 65 535 dan katta
belgini ikki 16 bitli birlikka boʻladi (**surrogate pair**). «1» — bu rune soni, `len` emas.

</details>

`emoji/main.go`:

```go filename="emoji/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "😀"                               // U+1F600 = 128512 > 65535
	fmt.Println(len(s))                    // baytlar
	fmt.Println(utf8.RuneCountInString(s)) // rune'lar
}
```

```console
$ go run emoji/main.go
4
1
```

Endi toʻliq jadval (Python va PHP natijalari ham shu kompyuterda olingan):

| Til | Ifoda | `"oʻzbek"` | `"😀"` | Nimani sanaydi |
|---|---|---|---|---|
| JavaScript / TS | `s.length` | 6 | 2 | UTF-16 birliklari |
| JavaScript | `[...s].length` | 6 | 1 | code point'lar |
| Python | `len(s)` | 6 | 1 | code point'lar |
| PHP | `strlen($s)` · `mb_strlen($s)` | 7 · 6 | 4 · 1 | baytlar · belgilar |
| Go | `len(s)` | 7 | 4 | baytlar |
| Go | `utf8.RuneCountInString(s)` | 6 | 1 | rune'lar (code point'lar) |

Oʻzbekcha ismlarda JS `.length` va Go'dagi rune soni teng. Emoji'da esa farq qiladi: JS'da code point'larni
`[...s].length` sanaydi.

## Bitta soʻz, toʻrt xil apostrof

Endi oʻzbek matniga xos muammo. Teskari vergul `ʻ` oddiy klaviaturada yoʻq, shuning uchun bitta soʻz toʻrt xil
yoziladi:

| Belgi | Nomi | Code point |
|---|---|---|
| `'` | klaviatura apostrofi | U+0027 = 39 |
| `ʻ` | teskari vergul | U+02BB = 699 |
| `’` | oʻng egri apostrof | U+2019 = 8217 |
| `‘` | chap egri apostrof | U+2018 = 8216 |

Unicode'ning tillar haqidagi maʼlumotlari (CLDR, `uz.xml`) oʻzbek alifbosi roʻyxatida `oʻ` va `gʻ` ni teskari
vergul bilan beradi.

`tort/main.go` toʻrttala yozuvning `len` ini chiqaradi. Code point'larni UTF-8 jadvali bilan solishtiring: qaysi
qator toʻgʻri?

**A)** 6 · 7 · 8 · 8 · **B)** 7 · 7 · 7 · 7 · **C)** 6 · 7 · 7 · 7

<details>
<summary>Javob</summary>

**A: 6 · 7 · 8 · 8.** Klaviatura apostrofi (39) — 1 bayt, teskari vergul (699) — 2 bayt. Egri apostroflarning
code point'i 2 047 dan katta, shuning uchun ular uch baytdan oladi. Rune soni esa toʻrttasida ham 6: farq faqat
baytlarda. «B» ni tanlagan boʻlsangiz, koʻzga bir xil boʻlsa, baytlari ham bir xil deb oʻylagansiz. «C» ni tanlagan
boʻlsangiz, hamma apostrof teskari vergul kabi 2 bayt deb oʻylagansiz.

</details>

```go filename="tort/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

// Bitta soʻz, toʻrt xil apostrof. Koʻzga deyarli bir xil, baytlari har xil.
func main() {
	sozlar := []string{
		"o'zbek", // U+0027 APOSTROPHE (klaviaturadagi)
		"oʻzbek", // U+02BB MODIFIER LETTER TURNED COMMA (teskari vergul, toʻgʻrisi)
		"o’zbek", // U+2019 RIGHT SINGLE QUOTATION MARK (oʻng jingalak)
		"o‘zbek", // U+2018 LEFT SINGLE QUOTATION MARK (chap jingalak)
	}
	for _, s := range sozlar {
		fmt.Printf("%s  len=%d  rune=%d\n", s, len(s), utf8.RuneCountInString(s))
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10–15 | `sozlar := []string{…}` | toʻrtta string'dan slice (`sozlar` — «soʻzlar»); izohlarda har bir apostrofning code point'i |
| 16 | `for _, s := range sozlar` | har bir element ustida sikl; `_` — indeks kerak emas |
| 17 | `fmt.Printf("%s  len=%d  rune=%d\n", …)` | `%s` — string, `%d` — butun son |

```console
$ go run tort/main.go
o'zbek  len=6  rune=6
oʻzbek  len=7  rune=6
o’zbek  len=8  rune=6
o‘zbek  len=8  rune=6
```

Ekranda toʻrttasi deyarli bir xil. Go uchun esa bular toʻrt xil bayt ketma-ketligi.

## Backend'dagi oqibat: `==` false beradi

Bazada `Oʻzbekiston` teskari vergul bilan saqlangan. Foydalanuvchi qidiruvga klaviatura apostrofi bilan
`O'zbekiston` yozdi. `teng/main.go` («teng» — equal; `saytda` — saytdagi roʻyxatdan, `qidiruv` — qidiruv maydonidan):

```go filename="teng/main.go" showLineNumbers
package main

import "fmt"

func main() {
	saytda := "Oʻzbekiston"  // saytdagi roʻyxatda: ʻ (U+02BB)
	qidiruv := "O'zbekiston" // foydalanuvchi klaviaturadan yozdi: ' (U+0027)
	fmt.Println(saytda == qidiruv)
}
```

```console
$ go run teng/main.go
false
```

Go string'larni bayt boʻyicha solishtiradi (spec: Comparison operators). `Oʻzbekiston` — 12 bayt, `O'zbekiston` —
11 bayt: baytlar har xil, demak `false`. JavaScript'dagi qatʼiy tenglik `===` ham `false` beradi. Unicode
normalizatsiyasi (`normalize("NFC")` yoki `"NFKC"`) ham yordam bermaydi: bular boshqa-boshqa belgilar, bitta
belgining ikki yozuvi emas.

```console
$ node -p '"Oʻzbekiston" === "O\x27zbekiston"'
false
$ node -p '["NFC", "NFKC"].map(f => "Oʻzbekiston".normalize(f) === "O\x27zbekiston".normalize(f))'
[ false, false ]
```

(Ikkala buyruq ham papkada yoʻq. `\x27` — klaviatura apostrofi: shell qoʻshtirnoqlari bilan adashmasligi uchun shunday
yozildi.)

## Tuzatish: faqat `o` va `g` dan keyingi apostrof

Birinchi fikr: har bir `'` ni `ʻ` ga almashtirish. `tuzat/main.go`:

```go filename="tuzat/main.go" showLineNumbers
package main

import (
	"fmt"
	"strings"
)

func main() {
	saytda := "Oʻzbekiston"
	qidiruv := "O'zbekiston"
	qidiruv = strings.ReplaceAll(qidiruv, "'", "ʻ") // har bir ' (U+0027) ni ʻ (U+02BB) ga almashtir
	fmt.Println(saytda == qidiruv)
	fmt.Println(strings.ReplaceAll("ma'no", "'", "ʻ")) // cheklov: toʻgʻrisi maʼno (ʼ U+02BC, tutuq belgisi)
}
```

11-qatorda `strings.ReplaceAll(qidiruv, "'", "ʻ")` matndagi har bir `'` ni `ʻ` ga almashtiradi. 13-qatorda xuddi
shu almashtirish *maʼno* soʻzida.

```console
$ go run tuzat/main.go
true
maʻno
```

Qidiruv ishladi, lekin *maʼno* buzildi. Undagi belgi teskari vergul emas, **tutuq belgisi** `ʼ` (U+02BC): CLDR uni
alohida beradi. Shuning uchun faqat `o` va `g` dan keyingi apostroflarni, egrilarini ham, teskari vergulga
almashtiramiz. `normal/main.go`:

```go filename="normal/main.go" showLineNumbers
package main

import (
	"fmt"
	"strings"
)

func main() {
	saytda := "Oʻzbekiston"
	qidiruv := "O'zbekiston"
	// Faqat o/g dan keyingi apostrof (klaviatura ' va egri ’ ‘) → ʻ (U+02BB). Boshqa joydagi ' tegilmaydi:
	// maʼno dagi tutuq belgisi (ʼ U+02BC) teskari vergul emas. Toʻliqroq qoida va chegaralar: ../tozala/
	r := strings.NewReplacer(
		"o'", "oʻ", "g'", "gʻ", "O'", "Oʻ", "G'", "Gʻ",
		"o’", "oʻ", "g’", "gʻ", "O’", "Oʻ", "G’", "Gʻ",
		"o‘", "oʻ", "g‘", "gʻ", "O‘", "Oʻ", "G‘", "Gʻ",
	)
	fmt.Println(r.Replace(qidiruv) == saytda)
	fmt.Println(r.Replace("ma'no"))
	// egri apostroflar ham: true true
	fmt.Println(r.Replace("O’zbekiston") == saytda, r.Replace("O‘zbekiston") == saytda)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 13 | `strings.NewReplacer(…)` | `strings` paketidagi almashtiruvchi: argumentlari «eski, yangi» juftliklari |
| 14 | `"o'", "oʻ", …` | klaviatura apostrofi: `o`, `g`, `O`, `G` dan keyin `ʻ` boʻladi |
| 15–16 | `"o’", "oʻ", …` · `"o‘", "oʻ", …` | oʻng va chap egri apostroflar uchun xuddi shunday |
| 18 | `r.Replace(qidiruv) == saytda` | `Replace` hamma juftlikni matnda bir oʻtishda almashtiradi, keyin solishtiramiz |
| 19 | `r.Replace("ma'no")` | `a` dan keyingi apostrof juftliklarda yoʻq: u joyida qoladi |
| 21 | ikkita `==` | egri apostrofli yozuvlar ham `saytda` ga teng boʻladi |

```console
$ go run normal/main.go
true
ma'no
true true
```

`true`, *maʼno* esa tegilmagan. `strings.NewReplacer` almashtirishlarni matnda uchragan tartibda, ustma-ust
tushirmasdan bajaradi (pkg.go.dev).

Qoida: bu almashtirishni bitta funksiyaga yigʻing va uni **saqlashdan oldin ham, qidirishdan oldin ham** chaqiring.
Shunda bazadagi va qidiruvdagi matn bir xil baytlardan iborat boʻladi. Toʻliqroq qoida kurs papkasidagi `tozala/` da:
`o`/`g` dan keyin `ʻ`, boshqa harflar orasida `ʼ`. Uning ham chegarasi bor: `Go'da` → `Goʻda` (README ilovasi).

## Chuqurroq (ixtiyoriy): UTF-8 ichi va baytlab kesish

### `ʻ` qanday qilib `ca bb` boʻladi

Koʻp baytli belgida har bir bayt prefiks bilan boshlanadi. Birinchi bayt va davom baytlarining prefikslari har xil.
`bitlar/main.go`:

```go filename="bitlar/main.go" showLineNumbers
package main

import "fmt"

func main() {
	r := 'ʻ'
	fmt.Printf("%U = %d = %b (%d bit)\n", r, r, r, len(fmt.Sprintf("%b", r)))
	b := []byte(string(r))
	// 2 baytli qolip: 110xxxxx 10xxxxxx, 11 ta x ga raqamning bitlari
	fmt.Printf("110|%05b  10|%06b  = % x\n", r>>6, r&0x3f, b)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `r := 'ʻ'` | rune literal (bitta tirnoq ichida): turi `rune`, qiymati 699 |
| 7 | `%U`, `%d`, `%b` | `U+02BB` koʻrinishi, oʻnlik va ikkilik yozuv; `len(fmt.Sprintf("%b", r))` — ikkilik yozuvdagi bitlar soni |
| 8 | `[]byte(string(r))` | rune → string → bayt slice: belgining UTF-8 baytlari |
| 10 | `r>>6`, `r&0x3f` | `>>6` oxirgi 6 bitni tashlaydi (yuqori bitlar qoladi), `&0x3f` faqat oxirgi 6 bitni oladi (`0x3f` = `111111`) |
| 10 | `%05b`, `%06b`, `% x` | 5 va 6 xonali ikkilik; baytlarni boʻsh joy bilan hex |

```console
$ go run bitlar/main.go
U+02BB = 699 = 1010111011 (10 bit)
110|01010  10|111011  = ca bb
```

699 ikkilikda 10 bit. Ikki baytli qolipda 11 ta boʻsh joy (`x`) bor, shuning uchun oldiga bitta 0 qoʻshiladi:
`01010111011`.

| | 1-bayt | 2-bayt |
|---|---|---|
| Qolip | `110xxxxx` | `10xxxxxx` |
| 699 ning bitlari | `01010` | `111011` |
| Natija | `11001010` = `ca` | `10111011` = `bb` |

Bayt qaysi bitlar bilan boshlanishiga qarab, uning vazifasi maʼlum:

| Bayt boshi | Maʼnosi |
|---|---|
| `0xxxxxxx` | 1 baytli belgi (ASCII) |
| `110xxxxx` | 2 baytli belgining boshi |
| `1110xxxx` | 3 baytli belgining boshi |
| `11110xxx` | 4 baytli belgining boshi |
| `10xxxxxx` | davom bayti |

Shu prefikslar tufayli dastur istalgan UTF-8 baytdan belgining boshini topadi: `10` bilan boshlangan baytlarni
orqaga qarab oʻtkazib yuboradi (RFC 3629 §3).

### Baytlab kesish

JavaScript'da `slice(0, 2)` ikki UTF-16 birligini oladi, yaʼni `oʻ`:

```console
$ node -p '"oʻzbek".slice(0, 2)'
oʻ
```

(Papkada yoʻq.) Go'da `s[:2]` — 0 dan 2 gacha (2 kirmaydi) **baytlar**: `o` va teskari vergulning yarmi. Bu
**kesish** (slicing) deyiladi. `kesish/main.go`:

```go filename="kesish/main.go" showLineNumbers
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "oʻzbek"
	fmt.Printf("%q\n", s[:2])                 // 2 bayt: belgining yarmi
	fmt.Println(utf8.ValidString(s[:2]))      // bu UTF-8 emas
	fmt.Printf("%q\n", string([]rune(s)[:2])) // 2 rune: butun "oʻ"
	fmt.Printf("%q\n", string([]rune(s)[:1])) // 1 rune: faqat "o"
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10 | `s[:2]` | birinchi 2 bayt; `%q` qiymatni qoʻshtirnoq ichida chiqaradi, buzilgan baytni `\xca` deb koʻrsatadi |
| 11 | `utf8.ValidString(s[:2])` | bu baytlar toʻgʻri UTF-8 mi? |
| 12 | `string([]rune(s)[:2])` | birinchi 2 rune: butun `oʻ` |
| 13 | `string([]rune(s)[:1])` | birinchi 1 rune: faqat `o` |

```console
$ go run kesish/main.go
"o\xca"
false
"oʻ"
"o"
```

`s[:2]` belgini yarmidan kesdi: `ca` qoldi, `bb` yoʻq, bu baytlar endi toʻgʻri UTF-8 emas. Ilovada bunday bayt
odatda `�` boʻlib koʻrinadi. Rune slice orqali kesish butun belgini saqlaydi. Lekin harfni baribir buzishi mumkin:
oxirgi qatorda `oʻ` dan faqat `o` qoldi, chunki `oʻ` ikki rune.

## Koʻp uchraydigan xatolar

**1. `len` ni belgilar soni deb oʻylash.** Bu mavzudagi eng klassik xato. Ism, sarlavha yoki SMS limiti
`len(s) <= n` bilan tekshirilsa, har bir `ʻ` ikki marta sanaladi: frontend oʻtkazgan «Gʻani» backend'da 6.
Xato xabari yoʻq, natija jim notoʻgʻri. Misol «Bitta soʻz, toʻrt til» va «rune» boʻlimlarida. **Tuzatish:** belgilar
limiti uchun `utf8.RuneCountInString(s)`.

**2. `s[i]` ni belgi deb oʻylash.** JS odati bilan indeksni `rune` oʻzgaruvchiga yozsak, Go rad etadi. Bu dastur
kurs papkasida yoʻq, uni `xato/main.go` ga saqlab ishga tushiring:

```go
package main

import "fmt"

func main() {
	s := "oʻzbek"
	var c rune = s[1] // JS kabi belgi kutyapmiz
	fmt.Println(string(c))
}
```

```console
$ go run xato/main.go
# command-line-arguments
xato/main.go:7:15: cannot use s[1] (value of type byte) as rune value in variable declaration
```

`xato/main.go:7:15` — 7-qator, 15-ustun, yaʼni `s[1]`. *cannot use s[1] (value of type byte) as rune value in
variable declaration* — «`byte` turidagi `s[1]` ni oʻzgaruvchi eʼlonida `rune` qiymat sifatida ishlatib boʻlmaydi».
Go yashirin konversiya qilmaydi. `rune(s[1])` deb yozsangiz, kompilyatsiya boʻladi, lekin bu baribir 202-bayt:
`string(rune(s[1]))` → `Ê`. **Tuzatish:** `[]rune(s)[1]`, belgi string sifatida kerak boʻlsa `string([]rune(s)[1])`.
Batafsil «Indeks» boʻlimida.

**3. Baytlab kesish.** `s[:n]` `n` ta **bayt** oladi va oʻzbekcha harfni yarmidan kesishi mumkin: `"o\xca"`.
Bildirishnoma yoki preview matnida bu `�` boʻlib chiqadi. Misol «Chuqurroq» boʻlimida. **Tuzatish:**
`string([]rune(s)[:n])`.

**4. Koʻzga bir xil matnni `==` bilan solishtirish.** `Oʻzbekiston` va `O'zbekiston` teng emas, normalizatsiya
ham yordam bermaydi. Misol «Backend'dagi oqibat» boʻlimida. **Tuzatish:** `o`/`g` dan keyingi apostroflarni
`strings.NewReplacer` bilan saqlashdan oldin ham, qidirishdan oldin ham almashtiring. Har bir `'` ni almashtirmang:
`strings.ReplaceAll` *maʼno* ni `maʻno` qiladi.
