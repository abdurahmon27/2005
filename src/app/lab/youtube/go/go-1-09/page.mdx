## Nimani oʻrganasiz

Beshta soʻzni (non, sut, tuxum, choy, olma) 120 xil tartibda terish mumkin: 5 × 4 × 3 × 2 × 1 = 120. Biz Go'ga
shu besh soʻzni 100 000 marta sanab chiqishni buyurdik va har safar qaysi tartib chiqqanini yozib bordik. Go faqat
**5 xil** tartib berdi. Ulardan bittasi esa qariyb **yarim** safar chiqdi. Demak, tartib tasodifiy, lekin oʻyin
kartalaridek aralashtirilmagan. Nega? Bugun javobni Go'ning oʻz manba kodidan topamiz. Dars oxirida esa
xavfsizlik toʻri (`recover`) ham qutqara olmaydigan xatoni koʻramiz.

**Bitta gʻoya:** map kalitni qiymatga bogʻlaydi: yoʻq kalit xato bermaydi, nol qiymat qaytaradi, aylanish
tartibiga esa tayanib boʻlmaydi. Map'ga ikki goroutine bir vaqtda yozsa, bu panic emas, `recover` ushlay
olmaydigan fatal error.

Dars oxirida siz:

- map yaratasiz, unga qiymat qoʻshasiz, oʻzgartirasiz, oʻchirasiz va `len` bilan kalitlarni sanaysiz;
- comma ok bilan «narxi 0» va «bunday mahsulot yoʻq» ni ajrata olasiz;
- `range` tartibi nega tasodifiy, lekin teng taqsimlanmaganini tushuntira olasiz va kerak boʻlsa kalitlarni
  saralaysiz;
- nil map'ga yozish (panic, `recover` ushlaydi) va map'ga bir vaqtda yozish (fatal error, ushlamaydi) farqini
  bilasiz va map'ni `sync.Mutex` bilan himoyalaysiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| map | narxlar taxtasi: har bir **kalit**ga (mahsulot nomiga) bitta **qiymat** (narx) bogʻlangan | map (key → value) |
| comma ok | ikkinchi oʻzgaruvchi: «bunday kalit bormi?» degan savolning javobi, `true` yoki `false` | comma ok idiom |
| fatal error | runtime dasturni darhol toʻxtatadigan xato: `defer` ishlamaydi, `recover` ushlamaydi | fatal error |

Yoʻl-yoʻlakay ikkita yordamchi soʻz ham uchraydi: **panic** (dasturning favqulodda yiqilishi; `recover` uni
ushlay oladi) va **goroutine** (dasturda boshqa ishlar bilan bir vaqtda bajariladigan alohida ish). Ikkalasini
kerak boʻlgan joyda tushuntiramiz, batafsil esa [GO-1.15](/lab/youtube/go#go-1-15) va [GO-1.21](/lab/youtube/go#go-1-21) da.

## Map: kalit → qiymat

Doʻkon narxlarini saqlamoqchimiz: non 5000 soʻm, sut 12000 soʻm. Slice'da qiymatlar 0, 1, 2 raqamli kataklarda
turadi. Bizga esa raqam emas, **nom** boʻyicha qidirish kerak: «non qancha turadi?».

Doʻkondagi narxlar taxtasini tasavvur qiling. Chap ustunda mahsulot nomi, oʻng ustunda uning narxi. Nomni topasiz,
yonidagi narxni oʻqiysiz. Taxtada bitta nom ikki marta yozilmaydi.

| Kalit (nom) | Qiymat (narx) |
|---|---|
| `"non"` | 5000 |
| `"sut"` | 12000 |

Bunday taxta Go'da **map** deyiladi. Chap ustundagi nom — **kalit** (inglizcha **key**), oʻng ustundagi narx —
**qiymat** (**value**). Map har bir kalitga bitta qiymat bogʻlaydi. Turi `map[string]int` deb yoziladi: «kalitlari
`string`, qiymatlari `int` boʻlgan map».

Bu kurs papkasidagi `asos/main.go`:

```go filename="asos/main.go" showLineNumbers
package main

import "fmt"

func main() {
	narx := map[string]int{"non": 5000, "sut": 12000}
	narx["choy"] = 25000

	fmt.Println(narx["olma"]) // bunday kalit yoʻq

	n, bor := narx["olma"]
	fmt.Println(n, bor)

	delete(narx, "sut")
	fmt.Println(len(narx))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 1–5 | `package main` … `func main() {` | tanish qolip: dastur `main` dan boshlanadi |
| 6 | `narx := map[string]int{"non": 5000, "sut": 12000}` | `narx` («narx») nomli yangi map. Jingalak qavs ichida boshlangʻich juftliklar: `kalit: qiymat`, vergul bilan ajratilgan |
| 7 | `narx["choy"] = 25000` | kvadrat qavsda kalit: «`choy` ning narxi 25000 boʻlsin». Kalit yoʻq boʻlsa, qoʻshiladi; bor boʻlsa, eski qiymat almashadi |
| 9 | `fmt.Println(narx["olma"])` | map'da yoʻq `olma` ning narxini soʻraydi |
| 11 | `n, bor := narx["olma"]` | xuddi shu soʻrov, lekin **ikkita** oʻzgaruvchi bilan: `n` — narx, `bor` — kalit bormi (`true`/`false`) |
| 12 | `fmt.Println(n, bor)` | ikkalasini chiqaradi |
| 14 | `delete(narx, "sut")` | `delete` — Go'ning tayyor funksiyasi: `sut` kalitini (qiymati bilan birga) oʻchiradi |
| 15 | `fmt.Println(len(narx))` | `len` map'da nechta kalit borligini aytadi |

Ishga tushirishdan oldin oʻylab koʻring: 9-qator nima chiqaradi? **A)** dastur xato bilan yiqiladi · **B)** `0` ·
**C)** boʻsh qator

<details>
<summary>Javob</summary>

**B: `0`.** Map'da yoʻq kalit xato emas. Map qiymat turining **zero value** sini qaytaradi: qiymat turi `int`,
shuning uchun 0. «A» ni tanlagan boʻlsangiz, boshqa baʼzi tillardagi xulqni kutgansiz: ularda yoʻq kalit
xato beradi, Go'da esa bermaydi. «C» qiymat turi `string` boʻlganda toʻgʻri boʻlardi: `string` ning zero value si
boʻsh matn `""`.

</details>


## Comma ok: «0 soʻm» yoki «umuman yoʻq»?

Endi muammo. `narx["olma"]` 0 qaytardi. Bu nimani anglatadi: olma bepulmi (narxi 0 soʻm) yoki doʻkonda olma umuman
yoʻqmi? Birinchi qiymatning oʻzidan buni bilib boʻlmaydi.

Shuning uchun 11-qatorda ikkinchi oʻzgaruvchi `bor` turibdi. U savolga javob beradi: «bunday kalit map'da bormi?».
`0 false` — narx 0, lekin `false`, yaʼni **bunday kalit yoʻq**. Bepul mahsulot boʻlganda `0 true` chiqardi.

Bu yozuv Go'da **comma ok** deb ataladi: vergul (inglizcha *comma*) va ikkinchi oʻzgaruvchi, uni koʻpincha `ok` deb
nomlashadi (`n, ok := narx["olma"]`). Biz uni `bor` deb atadik. Go'da bu usul juda koʻp uchraydi. U koʻpincha
`if` bilan birga yoziladi:

```go
	if n, bor := narx["olma"]; bor {
		fmt.Println("olma:", n)
	} else {
		fmt.Println("olma yoʻq")
	}
```

`if` qatorida avval `n` va `bor` yaratiladi, nuqtali verguldan (`;`) keyin esa `bor` tekshiriladi. Bu ikki
oʻzgaruvchi faqat shu `if` ichida yashaydi.

`delete` dan keyin `len(narx)` 2 ni berdi: `non` va `choy` qoldi.

## nil map: oʻqish mumkin, yozish — panic

Map'ni `:=` bilan emas, `var` bilan, qiymat bermasdan eʼlon qilsa nima boʻladi?

```go
	var narx map[string]int
```

Har bir turning zero value si bor. Map turining zero value si **`nil`**, yaʼni «hali map yoʻq». Buni hali osilmagan
narxlar taxtasi deb tasavvur qiling. Unga qarasangiz, hech narsa koʻrmaysiz. Lekin unga narx yozib boʻlmaydi: taxtaning
oʻzi yoʻq.

Ishlatishga tayyor, boʻsh map'ni ikki xil yaratish mumkin:

```go
	narx := map[string]int{}       // boʻsh map literal
	narx2 := make(map[string]int)  // make bilan
```

`make` — Go'ning tayyor funksiyasi: u yangi, boʻsh, lekin tayyor map yaratadi. «make qilinmagan» map, yaʼni `var`
bilan eʼlon qilingan map — `nil`.

Bu `nilmap/main.go`. Unda **ataylab** xato bor:

```go filename="nilmap/main.go" showLineNumbers
package main

import "fmt"

func main() {
	var narx map[string]int // nil map: make qilinmagan
	fmt.Println(narx["non"], len(narx))
	yoz(narx)
	fmt.Println("dastur davom etdi")
}

func yoz(m map[string]int) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("qutqarildi:", r)
		}
	}()
	m["non"] = 5000 // ataylab xato: nil map'ga yozib boʻlmaydi
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `var narx map[string]int` | qiymatsiz map: `narx` — `nil` |
| 7 | `fmt.Println(narx["non"], len(narx))` | nil map'dan oʻqiydi va kalitlarni sanaydi |
| 8 | `yoz(narx)` | `yoz` funksiyasini chaqiradi va unga map'ni beradi |
| 9 | `fmt.Println("dastur davom etdi")` | `yoz` dan keyin dastur shu yerga yetib keladimi? |
| 12 | `func yoz(m map[string]int) {` | map oladigan oʻz funksiyamiz |
| 13–17 | `defer func() { … }()` | **himoya**: `defer` funksiya tugayotganda ishlaydigan ishni belgilaydi. Bu yerda u nomsiz funksiya; oxiridagi `()` uni chaqiradi, `defer` esa bu chaqiruvni funksiya oxiriga qoldiradi |
| 14 | `if r := recover(); r != nil {` | `recover` yiqilishni toʻxtatadi va uning sababini qaytaradi. Yiqilish boʻlmagan boʻlsa, `nil` qaytaradi. `!=` — «teng emasmi» |
| 15 | `fmt.Println("qutqarildi:", r)` | yiqilish sababini chiqaradi |
| 18 | `m["non"] = 5000` | nil map'ga yozish: shu yerda xato |

Bu yerda yangi yordamchi soʻz bor. Dastur davom eta olmaydigan holatga tushsa, Go **panic** qiladi: funksiya
toʻxtaydi va dastur yiqila boshlaydi. `recover` — xavfsizlik toʻri: u `defer` qilingan funksiya ichida chaqirilsa,
yiqilishni toʻxtatadi va dastur davom etadi. `defer`, `panic` va `recover` ni
[GO-1.15](/lab/youtube/go#go-1-15) da batafsil oʻrganamiz. Bugun bizga shu ikki gap yetarli.

Taxmin qiling: dastur nima chiqaradi? **A)** `0 0`, keyin `qutqarildi: …` va `dastur davom etdi` · **B)** `0 0`,
keyin dastur yiqiladi · **C)** birinchi qatordayoq yiqiladi, chunki nil map'dan oʻqib boʻlmaydi

<details>
<summary>Javob</summary>

**A.** Nil map'dan oʻqish mumkin: u boʻsh map kabi zero value (0) qaytaradi, `len` esa 0. Shuning uchun «C» emas.
Yozish esa panic beradi. Lekin `yoz` ichida `defer` + `recover` himoyasi bor: u yiqilishni toʻxtatadi, `yoz`
tugaydi va `main` 9-qatorga oʻtadi. «B» himoya boʻlmaganda toʻgʻri boʻlardi (buni «Koʻp uchraydigan xatolar» da
koʻramiz).

</details>

```console
$ go run ./nilmap
0 0
qutqarildi: assignment to entry in nil map
dastur davom etdi
```

Panic sababi: *assignment to entry in nil map* — «nil map'dagi yozuvga qiymat berish». Go'ning rasmiy qoidasi
ham shunday deydi: nil map boʻsh map bilan bir xil, faqat unga element qoʻshib boʻlmaydi.

| Qadam | Nima boʻldi | Ekranga |
|---|---|---|
| 7-qator | nil map'dan oʻqish: 0, `len` 0 | `0 0` |
| 18-qator | nil map'ga yozish → panic | |
| 13–17-qator | `defer` ishladi, `recover` panic'ni ushladi | `qutqarildi: assignment to entry in nil map` |
| 9-qator | `main` davom etdi | `dastur davom etdi` |

Yana bir narsa: 8-qatorda map'ni `yoz` ga berdik. Map ham slice kabi: uning nusxasi **oʻsha** jadvalga qaraydi.
Shuning uchun funksiya ichida `m` ga yozilgan narsa tashqaridagi map'da ham koʻrinadi (bu yerda map `nil` edi,
shuning uchun yozib boʻlmadi). Bu gap dars oxirida, ikki goroutine bitta map'ga yozganda muhim boʻladi.

Bu dasturni eslab qoling. Dars oxirida aynan shu himoya ishlamaydigan holatni koʻramiz.

## Tartib: Go'ning rasmiy qoidasi nima deydi

Endi tartibga oʻtamiz. Go'ning rasmiy qoidalarida (Go spetsifikatsiyasida) ochiq yozilgan:

> *"The iteration order over maps is not specified and is not guaranteed to be the same from one iteration to the
> next."* — «Map ustida aylanish tartibi belgilanmagan va bir aylanishdan keyingisigacha bir xil boʻlishi
> kafolatlanmaydi».

Bu qoidaning tarixi:

| Versiya | Nima boʻldi |
|---|---|
| Go 1 | tartib ataylab «oldindan aytib boʻlmaydigan» deb eʼlon qilindi: dasturchilar map tartibiga tayanmasin |
| Go 1.1 | map'ning yangi ichki tuzilishi kichik map'larda (8 tagacha kalit) tartibni tasodifiy qilishni unutib qoʻydi |
| Go 1.3 | xato tuzatildi: kichik map'larda ham tartib yana tasodifiy |
| Go 1.24 | map xotirada yangi usulda saqlanadigan boʻldi (**Swiss table**), lekin tartib qoidalari oʻzgarmadi |

Go 1 ning hujjatida maqsad aniq yozilgan: *"Code should not assume that the elements are visited in any particular
order"* — «Kod elementlar biror aniq tartibda keladi deb hisoblamasligi kerak».

## Qanday ishlaydi: 8 oʻrinli guruh va tasodifiy boshlanish

Unda nega 120 emas, aynan 5 xil tartib? Javob Go'ning manba kodida (go1.26.8,
`internal/runtime/maps/table.go`). Avval oddiy soʻzlar bilan.

**1. Guruh.** Sakkiztagacha kalitli map'da hamma kalitlar bitta **guruh** da turadi. Guruh — 8 ta oʻrinli qator,
xuddi 8 kishilik dumaloq stol kabi. Oʻchirish boʻlmasa, kalitlar qoʻshilgan tartibda birinchi boʻsh oʻringa
oʻtiradi. Bizning 5 kalit 0–4 oʻrinlarni egallaydi, 5, 6, 7 oʻrinlar boʻsh:

| Oʻrin | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| Kalit | non | sut | tuxum | choy | olma | — | — | — |

**2. Tasodifiy boshlanish.** Har bir `range` boshida runtime tasodifiy son oladi va undan boshlanish oʻrnini
tanlaydi: 0 dan 7 gacha, har biri teng ehtimol bilan.

**3. Aylana.** Sikl shu oʻrindan boshlanib, stol atrofida aylana boʻylab yuradi: 7-oʻrindan keyin yana 0-oʻrin.
Boʻsh oʻrinlarni oʻtkazib yuboradi.

Endi sakkizta boshlanishning hammasini yozib chiqamiz:

| Boshlanish oʻrni | Chiqadigan tartib |
|---|---|
| 0 | non sut tuxum choy olma |
| 1 | sut tuxum choy olma non |
| 2 | tuxum choy olma non sut |
| 3 | choy olma non sut tuxum |
| 4 | olma non sut tuxum choy |
| 5 (boʻsh) | → 6, 7 boʻsh → 0: non sut tuxum choy olma |
| 6 (boʻsh) | → 7 boʻsh → 0: non sut tuxum choy olma |
| 7 (boʻsh) | → 0: non sut tuxum choy olma |

Sakkizta boshlanishdan toʻrttasi (0, 5, 6, 7) bir xil tartibni beradi: `non sut tuxum choy olma`. 4/8 = 50 %.
Qolgan toʻrt tartibning har biri 1/8 = 12,5 %. Boshidagi oʻlchov aynan shuni koʻrsatdi. Kalitlar har doim bir xil
aylanma ketma-ketlikda keladi, faqat boshlanish nuqtasi oʻzgaradi. Shuning uchun 120 emas, 5 ta tartib.

Mana manba kodning oʻsha joyi (`// ...` — biz tashlab ketgan qatorlar). Bu Go'ning ichki kodi:
`func (it *Iter) Init(…)` — `Iter` turiga tegishli funksiya (metod, [GO-1.12](/lab/youtube/go#go-1-12)), `*` esa pointer
([GO-1.11](/lab/youtube/go#go-1-11)). Hammasini tushunish shart emas, bizga jadvaldagi qatorlar yetarli.

```go
func (it *Iter) Init(typ *abi.MapType, m *Map) {
	// ...
	it.entryOffset = rand()
	// ...
}

func (it *Iter) Next() {
	// ...
	if it.dirIdx < 0 {
		// Map was small at Init.
		for ; it.entryIdx < abi.MapGroupSlots; it.entryIdx++ {
			k := uintptr(it.entryIdx+it.entryOffset) % abi.MapGroupSlots
			if (it.group.ctrls().get(k) & ctrlEmpty) == ctrlEmpty {
				// Empty or deleted.
				continue
			}
```

| Qator | Nima qiladi |
|---|---|
| 1–5 | `Init` — `range` boshlanganda bir marta ishlaydi. `it.entryOffset = rand()`: tasodifiy son, boshlanish oʻrni shundan olinadi |
| 7 | `Next` — har qadamda navbatdagi kalitni topadi |
| 9–10 | `if it.dirIdx < 0` — izoh: *Map was small at Init*, «`Init` paytida map kichik edi» (bitta guruh) |
| 11 | sikl guruhning `abi.MapGroupSlots` = 8 ta oʻrni boʻylab yuradi |
| 12 | `k := … % abi.MapGroupSlots`: qadam raqamiga tasodifiy son qoʻshiladi va 8 ga boʻlinganda qoldiq olinadi (`%`, [GO-1.05](/lab/youtube/go/go-1-05) dan). Qoldiq doim 0–7: 7 dan keyin yana 0. Aylana shu. (`uintptr(…)` — son turini aylantirish, bu yerda ahamiyatsiz) |
| 13–16 | oʻrin boʻsh yoki oʻchirilgan boʻlsa (*Empty or deleted*), `continue` uni oʻtkazib, keyingi oʻringa oʻtadi. (`&` bu yerda bitlar ustidagi amal: oʻrin belgisidan «boʻsh» bitini ajratib oladi) |

Xulosa: tartib **tasodifiy**, lekin **aralashtirilmagan**. Mumkin boʻlgan 120 tartibdan 5 tasi chiqadi va ular teng
ehtimolli emas. Demak, `range` ni tasodifiy element tanlash uchun ishlatmang: natija teng taqsimlanmagan. Bu oʻlchovga
ham tayanmang: bu Go'ning ichki tuzilishi, keyingi versiyada oʻzgarishi mumkin. Qoida bitta: tartib kafolatlanmagan.

## Bir vaqtda yozish: fatal error

Endi eng xavfli tuzoq. Buning uchun bitta yangi yordamchi soʻz kerak.

Hozirgacha dasturlarimiz bitta ishni qadamma-qadam bajardi. Lekin dastur bir vaqtda bir nechta ishni bajarishi ham
mumkin. Masalan, doʻkonda ikki kassir bir vaqtda ishlaydi. Go'da bir vaqtda bajariladigan har bir alohida ish
**goroutine** deyiladi. `main` ning oʻzi ham goroutine. Goroutine'larni [GO-1.21](/lab/youtube/go#go-1-21) da batafsil
oʻrganamiz.

Bu `poyga/main.go` («poyga» — musobaqa). Unda **ataylab** xato bor:

```go filename="poyga/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
)

func main() {
	m := map[int]int{}
	var wg sync.WaitGroup
	for g := range 2 {
		wg.Go(func() { yoz(m, g) }) // ataylab xato: ikki goroutine bitta map'ga yozadi
	}
	wg.Wait()
	fmt.Println("dastur davom etdi:", len(m))
}

func yoz(m map[int]int, g int) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("qutqarildi:", r)
		}
	}()
	for i := range 1_000_000 {
		m[i] = g
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 5 | `"sync"` | bir vaqtda ishlaydigan goroutine'lar uchun asboblar paketi |
| 9 | `m := map[int]int{}` | boʻsh map: kalit ham, qiymat ham `int` |
| 10 | `var wg sync.WaitGroup` | **WaitGroup** — goroutine'larni ishga tushiradi va hammasi tugashini kutadi ([GO-1.22](/lab/youtube/go#go-1-22) da batafsil) |
| 11 | `for g := range 2 {` | ikki marta: `g` = 0, keyin 1 |
| 12 | `wg.Go(func() { yoz(m, g) })` | nomsiz funksiyani **yangi goroutine** da ishga tushiradi. U `yoz(m, g)` ni chaqiradi. `main` kutmasdan keyingi qadamga oʻtadi. `wg.Go` Go 1.25 da qoʻshilgan |
| 14 | `wg.Wait()` | ikkala goroutine tugaguncha shu yerda kutadi |
| 15 | `fmt.Println("dastur davom etdi:", len(m))` | dastur shu yerga yetib kelsa, kalitlar sonini chiqaradi |
| 18 | `func yoz(m map[int]int, g int) {` | map'ga yozadigan funksiya; `g` — goroutine raqami |
| 19–23 | `defer func() { … recover … }()` | xuddi `nilmap` dagi himoya |
| 24–26 | `for i := range 1_000_000 { m[i] = g }` | map'ga million marta yozadi: kalit `i`, qiymat `g` |

Ikkala goroutine `m` ning nusxasini oldi, lekin map ham slice kabi: ikkala nusxa **bitta** jadvalga qaraydi. Demak,
ikki goroutine bitta map'ga bir vaqtda yozadi. Har birining ichida `recover` turibdi.

```text
main ─┬─ wg.Go ──► goroutine 0:  m[0]=0  m[1]=0  m[2]=0  …
      │                              ╲
      │                               ►  bitta map  m  ◄──  bir vaqtda ikki yozuvchi
      │                              ╱
      ├─ wg.Go ──► goroutine 1:  m[0]=1  m[1]=1  m[2]=1  …
      └─ wg.Wait()  …ikkalasi tugashini kutadi
```

Taxmin qiling: nima boʻladi? **A)** `qutqarildi: …` chiqadi, dastur davom etadi · **B)** dastur yiqiladi,
`qutqarildi` yozuvi chiqmaydi · **C)** xato yoʻq: `dastur davom etdi: 1000000`

<details>
<summary>Javob</summary>

**B.** Dastur yiqiladi va `recover` hech narsa ushlamaydi. Bu oddiy panic emas, **fatal error**. Uni pastda
koʻramiz. «A» ni tanlagan boʻlsangiz, `nilmap` dagi kabi panic boʻladi deb oʻylagansiz. «C» ni tanlagan
boʻlsangiz, map'ga bir vaqtda yozish xavfsiz deb oʻylagansiz. Koʻp dasturchilar ham shunday oʻylaydi (darsning
oxirida Uber misoli).

</details>

Videoda va bu yerda dasturni yordamchi skript bilan ishga tushiramiz. Sababi: Go bu xatoni «best effort» bilan
aniqlaydi (pastda tushuntiramiz). Juda kamdan-kam holda dastur boshqa xabar bilan yiqiladi yoki yiqilmay tugaydi.
`poyga/demo.sh` dasturni bir marta kompilyatsiya qiladi va uni `fatal error: concurrent map writes` xabari va
chiqish kodi 2 olinguncha qayta ishga tushiradi (koʻpi bilan 20 urinish). Keyin haqiqiy ishga tushirishdan olingan
xabar qatorini va chiqish kodini chiqaradi. `bash` — skriptni bajaradigan dastur.

```console
$ bash ./poyga/demo.sh

```

*fatal error: concurrent map writes* — «halokatli xato: map'ga bir vaqtda yozish». *exit status 2* — dastur 2
chiqish kodi bilan toʻxtadi (0 — muvaffaqiyat, boshqa son — xato). `qutqarildi` yozuvi yoʻq, `dastur davom etdi`
ham yoʻq.

Oddiy `go run ./poyga` ham xuddi shu birinchi qatorni chiqaradi. Uning ostida esa goroutine'lar roʻyxati (stack
trace) keladi. Bizning ishga tushirishda unda `main.yoz` va `poyga/main.go:25` bor edi: 25-qator, `m[i] = g`.
Videoda bu uzun roʻyxat qisqartirilgan.

## Nega recover ojiz: panic va fatal

`m[i] = g` qatori aslida runtime'dagi bitta funksiyani chaqiradi. Mana uning qisqartirilgan koʻrinishi (go1.26.8):

```go
// internal/runtime/maps/runtime_fast64.go
func runtime_mapassign_fast64(...) unsafe.Pointer {
	if m == nil {
		panic(errNilAssign)
	}
	// ...
	if m.writing != 0 {
		fatal("concurrent map writes")
	}
	// ...
	m.writing ^= 1 // toggle, see comment on writing
	// ...
}

// runtime/panic.go
// fatal is equivalent to throw, but is used when user code is expected to be
// at fault for the failure, such as racing map writes.
```

| Qator | Nima qiladi |
|---|---|
| 2 | map'ga `int` kalit bilan yozadigan runtime funksiyasi: bizning `m[i] = g` shuni chaqiradi. `(...)` — biz qisqartirgan parametrlar; `unsafe.Pointer` — qaytadigan qiymat turi, bu yerda ahamiyatsiz |
| 3–5 | map `nil` boʻlsa — oddiy `panic`. `nilmap` dagi xato shu edi, uni `recover` ushladi |
| 7–9 | `m.writing` — bayroq: «hozir kimdir bu map'ga yozayaptimi?». Yozayotgan boʻlsa — `panic` emas, `fatal` |
| 11 | yozishni boshlaganda bayroqni almashtiradi (`^= 1`: 0 boʻlsa 1, 1 boʻlsa 0) |
| 15–16 | `fatal` ning izohi: *«`fatal` — `throw` bilan bir xil, lekin xatoda foydalanuvchi kodi aybdor deb hisoblanganda ishlatiladi, masalan, map'ga musobaqalashib yozish»* |

Runtime buni dasturchi xatosi deb hisoblaydi. `fatal` xabarni chiqaradi va `defer` larni ishga tushirmasdan
dasturni 2 kodi bilan toʻxtatadi. `defer` ishlamasa, uning ichidagi `recover` ham ishlamaydi. Mantiqan (bu bizning
izohimiz, manbaning gapi emas): buzilgan boʻlishi mumkin boʻlgan map bilan davom etish xavfli.

| | `nilmap` | `poyga` |
|---|---|---|
| Xato | nil map'ga yozish | ikki goroutine bir vaqtda yozadi |
| Runtime nima qiladi | `panic(errNilAssign)` | `fatal("concurrent map writes")` |
| `defer` ishlaydimi | ha | yoʻq |
| `recover` | ushlaydi: `qutqarildi: …` | ushlay olmaydi |
| Dastur | davom etadi | `exit status 2` |

## Ikki muhim gap: «best effort» va faqat oʻqish

**1. Bu tekshiruv kafolat emas.** Go 1.6 dan beri runtime map'dan notoʻgʻri foydalanishni aniqlaydi. Uning hujjati
buni *"best-effort detection"* deydi: «imkon qadar aniqlash». Yaʼni baʼzan xato ushlanmasdan oʻtib ketishi mumkin.

Ancha yaxshiroq vosita — **race detector** (data race'larni topadigan Go asbobi). Testlarni `-race` bayrogʻi bilan
ishga tushiring: `go test -race`. Lekin u ham faqat ishga tushgan kodni tekshiradi: hech qachon bajarilmagan yoʻldagi
xatoni topmaydi. Linux'da race detector C kompilyatorini (gcc) talab qiladi. Kurs kompyuterida gcc yoʻq edi, shuning
uchun bu yerda uning natijasini koʻrsatmaymiz. Uni [GO-1.22](/lab/youtube/go#go-1-22) da koʻramiz.

**2. Faqat oʻqish xavfsiz.** Map'ni bir nechta goroutine faqat **oʻqisa**, bu xavfsiz. Go FAQ: *"Map access is
unsafe only when updates are occurring"* — «map'ga murojaat faqat uni oʻzgartirish boʻlayotganda xavfli». Muammo
kimdir yozganda boshlanadi.

| Kim nima qiladi | Xavfsizmi |
|---|---|
| bir nechta goroutine faqat oʻqiydi | ha |
| bitta goroutine yozadi, boshqasi oʻqiydi yoki yozadi | yoʻq: himoya kerak |

## Tuzatish: sync.Mutex

Tuzatish: map'ga har bir yozishni **mutex** bilan oʻraymiz. Bitta kishilik kiyim almashtirish xonasini tasavvur
qiling. Kirgan odam eshikni ichidan qulflaydi, qolganlar navbatda kutadi. Chiqqanda qulfni ochadi va navbatdagi
kiradi. `sync.Mutex` shu qulf: `Lock` bir vaqtda faqat bitta goroutine'ni ichkariga kiritadi. Ish tugagach,
`Unlock` yoʻlni boshqasiga ochadi.

Bu `mutex/main.go`:

```go filename="mutex/main.go" showLineNumbers
package main

import (
	"fmt"
	"sync"
)

func main() {
	m := map[int]int{}
	var mu sync.Mutex
	var wg sync.WaitGroup
	for g := range 2 {
		wg.Go(func() {
			for i := range 1_000_000 {
				mu.Lock()
				m[i] = g
				mu.Unlock()
			}
		})
	}
	wg.Wait()
	fmt.Println("tugadi:", len(m))
}
```

| 13–19 | `wg.Go(func() { … })` | `yoz` funksiyasi va `recover` yoʻq: sikl toʻgʻridan-toʻgʻri nomsiz funksiya ichida |
| 15 | `mu.Lock()` | qulflaydi. Qulf band boʻlsa, ikkinchi goroutine shu yerda kutadi |
| 16 | `m[i] = g` | map'ga yozish: endi bir vaqtda faqat bitta goroutine yozadi |
| 17 | `mu.Unlock()` | qulfni ochadi, navbatdagi goroutine kirishi mumkin |
| 22 | `fmt.Println("tugadi:", len(m))` | map'dagi kalitlar soni |

## Haqiqiy dunyo: Uber, 2022

Bu nazariy muammo emas. Uber muhandislari 2022-yilda oʻz Go kodlaridagi **data race** larni oʻrganib chiqishdi.
Data race — ikki goroutine bitta xotiraga bir vaqtda murojaat qilib, ulardan kamida bittasi yozganda boʻladigan xato.

| Raqam | Nima |
|---|---|
| qariyb 2000 | topilgan data race |
| qariyb 1100 | tuzatilgan va tahlil qilingan (210 dasturchi, olti oy) |

Map'ga bir vaqtda murojaat ular tez-tez uchratgan sabablardan biri boʻlgan. Dasturchilar har xil kalitga murojaat
qilish xavfsiz deb oʻylagan. Chunki `table[key]` dagi kvadrat qavs xuddi alohida elementga murojaat qilayotgandek
koʻrinadi. Aslida esa hamma kalitlar bitta map'da, bitta umumiy tuzilma ichida.

## Chuqurroq (ixtiyoriy): tekshiruv nega «best effort»

Runtime'dagi bayroqni yana bir bor koʻring: `m.writing ^= 1`. Bu oddiy, **atomik boʻlmagan** almashtirish. Atomik
amalni boshqa goroutine yarim yoʻlda koʻra olmaydi; bu amal esa shunday emas. Ikki yozuvchi bayroqni bir vaqtda
almashtirsa, tekshiruv buni sezmasligi mumkin.

Dars tayyorlanayotganda tanqidchi (darsni alohida koʻrib chiqqan sharhlovchi) `poyga` ni koʻp marta ishga tushirib oʻlchagan:

| Sharoit | Natija |
|---|---|
| 300 ta oddiy ishga tushirish | 297 ta `fatal error: concurrent map writes`, 2 ta `small map with no empty slot (concurrent map writes?)`, 1 ta `unexpected fault address` (xotiradagi notoʻgʻri manzilga murojaat) |
| `GOMAXPROCS=1` bilan 100 ta | 98 tasi yiqildi, 2 tasi yiqilmay tugadi |

`GOMAXPROCS=1` — Go kodini bir vaqtda faqat bitta protsessor yadrosida bajarish sozlamasi. Shunda ham dastur
deyarli har safar yiqildi. Demak, muammo ikki ishning aynan bir soniyada bajarilishida emas: bitta yozuv tugamasdan
ikkinchisi boshlanishining oʻzi yetarli. Shuning uchun biz «parallel» emas, «bir vaqtda» deymiz. Bitta
`unexpected fault address` esa buzilgan map haqiqatan xavfli ekanini koʻrsatadi.

Yana bir oʻlchov: ikki marta ishga tushirganda `tartib` ning bir xil tartib berish ehtimoli qariyb 31 %
(0,5² + 4 · 0,125²). Shuning uchun «ikki marta ishga tushirdim, tartib bir xil chiqdi» hech narsani isbotlamaydi.

## Koʻp uchraydigan xatolar

**1. Map tartibiga tayanish.** Bu darsning asosiy tuzogʻi. Dastur xato bermaydi, lekin `range` tartibi har safar
boshqacha boʻlishi mumkin (yuqorida, «Qanday ishlaydi» boʻlimida). `fmt.Println(map)` saralab chiqarib, buni
yashiradi («Pauza» boʻlimi). `range` ni tasodifiy element tanlash uchun ishlatish ham xato: bizning map'da bitta
tartib 50 % chiqdi. **Tuzatish:** tartib kerak boʻlsa, `slices.Sorted(maps.Keys(m))` bilan saralang; tasodifiy
element kerak boʻlsa, uni tasodifiy son bilan tanlang.

**2. Nolni «yoʻq» deb oʻylash.** `if narx["suv"] == 0 { … "yoʻq" … }` bepul mahsulotni ham «yoʻq» deb hisoblaydi.
Yoʻq kalit ham, 0 qiymatli kalit ham 0 qaytaradi («Comma ok» boʻlimi). **Tuzatish:** `n, bor := narx["suv"]` va
`bor` ni tekshiring.

**3. nil map'ga himoyasiz yozish.** Bu misol kurs papkasida yoʻq, alohida ishga tushirildi:

```go
package main

import "fmt"

func main() {
	var narx map[string]int
	narx["non"] = 5000
	fmt.Println(narx)
}
```

```console
$ go run -trimpath nilyoz/main.go
panic: assignment to entry in nil map

goroutine 1 [running]:
main.main()
	./main.go:7 +0x28
exit status 2
```

`-trimpath` faqat xabardagi fayl yoʻlini qisqa qiladi; usiz kompyuteringizdagi toʻliq papka yoʻli chiqadi. Xabarni
oʻqiymiz: *panic: assignment to entry in nil map* — «panic: nil map'dagi yozuvga qiymat berish». *goroutine 1
[running]* — xato 1-goroutine'da, yaʼni `main` da boʻldi. `main.main()` va `main.go:7` — `main` funksiyasi, 7-qator:
`narx["non"] = 5000`. `recover` yoʻq, shuning uchun dastur 2 kodi bilan yiqildi. **Tuzatish:** map'ni yarating:
`narx := map[string]int{}` yoki `narx := make(map[string]int)`.

**4. `recover` bir vaqtda yozishni ham ushlaydi deb oʻylash.** `poyga` da koʻrdik: `recover` turibdi, lekin dastur
baribir yiqiladi, chunki bu panic emas, fatal error («Nega recover ojiz» boʻlimi). **Tuzatish:** map'ga yozishni
`sync.Mutex` bilan himoyalang («Tuzatish: sync.Mutex» boʻlimi), testlarni esa `go test -race` bilan ishga tushiring.

**5. `maps.Keys` slice qaytaradi deb oʻylash.** (Kurs papkasida yoʻq, alohida ishga tushirildi.)

```go
package main

import (
	"fmt"
	"maps"
)

func main() {
	narx := map[string]int{"non": 5000, "sut": 12000}
	kalitlar := maps.Keys(narx)
	fmt.Println(len(kalitlar))
}
```

```console
$ go run kalitlar/main.go
# command-line-arguments
kalitlar/main.go:11:18: invalid argument: kalitlar (variable of func type iter.Seq[string]) for built-in len
```

11-qator, 18-belgi: *invalid argument: kalitlar (variable of func type iter.Seq[string]) for built-in len* —
«`len` uchun notoʻgʻri argument: `kalitlar` — `iter.Seq[string]` turidagi funksiya oʻzgaruvchisi». Yaʼni `maps.Keys`
slice emas, iterator qaytardi, `len` esa iteratorni sanay olmaydi. **Tuzatish:** avval slice'ga yigʻing:
`kalitlar := slices.Sorted(maps.Keys(narx))` (saralangan) yoki `slices.Collect(maps.Keys(narx))` (saralanmagan).
Keyin `len(kalitlar)` ishlaydi.

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** Map'da yoʻq kalitni oʻqisak nima boʻladi? «Narxi 0» va «bunday kalit yoʻq» ni qanday ajratamiz?

<details>
<summary>Javob</summary>

Xato boʻlmaydi: map qiymat turining zero value sini qaytaradi (`int` uchun 0). Ajratish uchun comma ok:
`n, bor := narx["olma"]`. `bor` `false` boʻlsa, kalit yoʻq; `true` boʻlsa, kalit bor va narxi `n`.

</details>

**2.** Map kalitlarini har safar bir xil tartibda chiqarish kerak. Nima qilasiz?

<details>
<summary>Javob</summary>

`range` tartibiga tayanmaysiz. Kalitlarni saralab olasiz va shu tartibda yurasiz:
`for _, k := range slices.Sorted(maps.Keys(m)) { … m[k] … }`.

</details>

**3.** Ikki goroutine bitta map'ga bir vaqtda yozsa, har birining ichidagi `recover` dasturni qutqaradimi?

<details>
<summary>Javob</summary>

Yoʻq. Runtime `panic` emas, `fatal` chaqiradi: `fatal error: concurrent map writes`. U `defer` larni ishga
tushirmasdan dasturni 2 kodi bilan toʻxtatadi, shuning uchun `recover` ga navbat kelmaydi. Tuzatish: `sync.Mutex`.

</details>

**4.** Bu dastur nima chiqaradi? **A)** `2 0 false 2` · **B)** `2 0 false 1` · **C)** `1 0 true 1`

```go
package main

import "fmt"

func main() {
	sanoq := map[string]int{}
	sanoq["a"]++
	sanoq["a"]++
	n, bor := sanoq["b"]
	fmt.Println(sanoq["a"], n, bor, len(sanoq))
}
```

<details>
<summary>Javob</summary>

**B: `2 0 false 1`.** `sanoq["a"]++` birinchi marta 0 dan 1 ga, ikkinchi marta 2 ga oshiradi. `"b"` kaliti yoʻq:
`n` = 0, `bor` = `false`. Yoʻq kalitni oʻqish map'ga hech narsa qoʻshmaydi, shuning uchun `len` 1. «A» ni tanlagan
boʻlsangiz, oʻqish ham kalit qoʻshadi deb oʻylagansiz. (Bu dastur kurs papkasida yoʻq, alohida ishga tushirildi.)

```console
$ go run savol/main.go
2 0 false 1
```

</details>

**5.** Bir nechta goroutine map'ni faqat oʻqisa (hech kim yozmasa), himoya kerakmi?

<details>
<summary>Javob</summary>

Kerak emas: faqat oʻqish xavfsiz. Muammo kimdir yozganda boshlanadi.

</details>

**6.** [GO-1.06](/lab/youtube/go/go-1-06) dan: closure tashqaridagi oʻzgaruvchining nusxasini ushlaydimi yoki oʻzini?

<details>
<summary>Javob</summary>

Oʻzini. Closure yaratilgandan keyin oʻzgaruvchi oʻzgarsa, closure yangi qiymatni koʻradi. Bugungi `poyga` va
`mutex` dagi nomsiz funksiyalar ham tashqaridagi `m`, `g` va `mu` ni shunday ushlaydi.

</details>
