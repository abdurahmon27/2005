## Nimani oʻrganasiz

`Tolanganlar(bb)` funksiyasi slice qaytarmaydi, lekin `for range` uning ustida aylanadi. Sikl kichik summada
`break` qiladi va hammasi joyida. Endi iterator ichidan bitta `if` ni olib tashlaymiz. `go vet` jim, kompilyator ham
jim, dastur esa ishga tushganda `panic` bilan yiqiladi. Nega? Bu darsda shu qoidani va iterator ichida aslida nima
boʻlishini ochamiz.

**Bitta gʻoya:** Go'da iterator — `yield` funksiyasini har bir element bilan chaqiradigan oddiy funksiya. `for range`
sikl tanasini shu `yield` ga aylantiradi. `yield` `false` qaytarsa, iterator darhol `return` qilishi shart.

Dars oxirida siz:

- `iter.Seq` va `iter.Seq2` qaytaradigan oʻz iterator'ingizni yoza olasiz, rekursiv tuzilma uchun ham;
- `break`, `continue` va `return` iterator ichida nimaga aylanishini va qoidabuzarlik qanday `panic` berishini
  tushuntira olasiz;
- iterator qachon oddiy sikl kabi tez, qachon sekin ekanini `-gcflags=-m` va benchmark bilan tekshira olasiz;
- `slices.Sorted(maps.Keys(m))`, `cmp.Compare` va `cmp.Or` ni toʻgʻri ishlata olasiz va bir martalik iterator
  tuzogʻini taniysiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| iterator | ketma-ketlik elementlarini birma-bir boshqa funksiyaga berib turadigan funksiya | iterator |
| yield funksiyasi | iterator har bir element bilan chaqiradigan funksiya; `range` da bu sikl tanasi: `true` — davom et, `false` — toʻxta | yield function |
| taqqoslash funksiyasi | ikki elementni solishtirib manfiy son, `0` yoki musbat son qaytaradigan funksiya; `slices.SortFunc` shunga qarab saralaydi | comparison function |

Yoʻl-yoʻlakay ikkita yordamchi soʻz ham uchraydi: **bir martalik iterator** (*single-use iterator*, ikkinchi marta
boshidan boshlamaydi) va **inline** ([GO-1.07](/lab/youtube/go/go-1-07) dan tanish: kompilyator funksiya tanasini chaqiruv
joyiga koʻchiradi).

## Funksiya ustida for range

Mavzu tanish: buyurtmalar (`Buyurtma`), summalar soʻmda. Bizga faqat toʻlangan buyurtmalar kerak. Slice yigʻib
qaytarish oʻrniga, `Tolanganlar` ularni birma-bir **beradigan** funksiya qaytaradi.

```go filename="hook/main.go" showLineNumbers
// Hook: Tolanganlar slice qaytarmaydi, u funksiya qaytaradi.
// for range esa shu funksiya ustida aylanadi (Go 1.23+).
package main

import (
	"fmt"
	"iter"
)

type Buyurtma struct {
	ID      int
	Summa   int64
	Tolandi bool
}

// iter paketida: type Seq[V any] func(yield func(V) bool)
//
// Tolanganlar faqat toʻlangan buyurtmalarni beradi.
func Tolanganlar(bb []Buyurtma) iter.Seq[Buyurtma] {
	return func(yield func(Buyurtma) bool) {
		for _, b := range bb {
			if !b.Tolandi {
				continue
			}
			if !yield(b) {
				return
			}
		}
	}
}

func main() {
	bb := []Buyurtma{
		{1, 150000, true},
		{2, 99000, false},
		{3, 42000, true},
		{4, 310000, true},
	}
	for b := range Tolanganlar(bb) {
		fmt.Println("buyurtma", b.ID, b.Summa)
		if b.Summa < 50000 {
			fmt.Println("kichik summa, toʻxtaymiz")
			break
		}
	}
}
```

JS yoki Python'dan kelgan boʻlsangiz, bu sizga **generator** ni eslatadi. Xuddi shu iterator JavaScript'da:

```js
function* tolanganlar(bb) {
  for (const b of bb) {
    if (!b.tolandi) continue;
    yield b;            // generator shu yerda pauza qiladi
  }
}

for (const b of tolanganlar(bb)) {
  console.log("buyurtma", b.id, b.summa);
  if (b.summa < 50000) break;   // for...of generator'ni oʻzi yopadi
}
```

Python'da ham `def tolanganlar(bb): … yield b`, PHP'da ham `function tolanganlar(array $bb) { … yield $b; }`. Tashqi
koʻrinish bir xil, ichi esa boshqacha:

| | JS / Python / PHP generator | Go iterator |
|---|---|---|
| `yield` nima | tilning kalit soʻzi: funksiya shu joyda pauza qiladi | oddiy parametr nomi (odat boʻyicha `yield`, iter hujjati: *"conventionally named yield"*) |
| kim kimni chaqiradi | sikl generator'dan keyingi qiymatni soʻraydi (`next()`, *pull*) | iterator sikl tanasini chaqiradi va qiymatni oʻzi beradi (*push*) |
| `break` boʻlsa | til generator'ni oʻzi yopadi (JS'da `return()` chaqiriladi) | `yield` `false` qaytaradi; toʻxtash — iterator'ning vazifasi |

Oxirgi qator — darsning asosiy tuzogʻi. JS'da `break` qilsangiz, `for...of` generator'ning `return()` metodini oʻzi
chaqiradi ([MDN: for...of](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/for...of)).
Go'da esa `yield(b)` — oddiy funksiya chaqiruvi, u `bool` qaytaradi. Iterator uni tekshirmasa, kimdir majburan
toʻxtatmaydi. Nima boʻlishini «Panic» boʻlimida koʻramiz.

## Nega kerak edi: Go 1.23 gacha har paketda oʻz usul

Go 1.23 gacha `range` faqat slice, massiv, satr, map, channel va (Go 1.22 dan) butun son ustida ishlardi. Oʻz
tuzilmangizni aylanish uchun har paket oʻz usulini oʻylab topardi:

| Paket | Qanday aylanadi |
|---|---|
| `sync.Map` | `m.Range(func(k, v any) bool { … })` — funksiya berasiz, `false` qaytarsangiz toʻxtaydi |
| `path/filepath` | `filepath.Walk(root, func(path string, info fs.FileInfo, err error) error { … })` — funksiya berasiz, xato qaytarsangiz toʻxtaydi |
| `bufio.Scanner` | `for sc.Scan() { sc.Text() }` — sikl ichida `Scan` ni oʻzingiz chaqirasiz |

Go blogida I. L. Taylor shunday yozgan: *"when you start using a new Go container package you may have to learn a new
looping mechanism"* — «Go'da yangi konteyner paketini ishlata boshlasangiz, yangi sikl usulini ham oʻrganishingiz
kerak boʻlishi mumkin» ([Range Over Function Types](https://go.dev/blog/range-functions), 2024). Range over func
shuni bitta shaklga keltiradi: paket iterator qaytaradi, siz esa oddiy `for range` yozasiz.

Imkoniyat ikki bosqichda kelgan. [Go 1.22](https://go.dev/doc/go1.22) da u tajriba edi va faqat
`GOEXPERIMENT=rangefunc` bilan yoqilardi. [Go 1.23](https://go.dev/doc/go1.23#language) da tilning bir qismi boʻldi.
`eski/` papkasida `hook/main.go` ning aynan nusxasi bor, lekin u alohida modul:

```console
$ cat eski/go.mod
// Alohida modul: til versiyasi go 1.22. Range over func Go 1.23 dan boshlab bor.
module eski

go 1.22
```

[GO-1.16](/lab/youtube/go/go-1-16) dan bilasiz: `go` qatori shu modulning til versiyasi. Kompyuterdagi Go 1.26.8, lekin u
modulni Go 1.22 tili bilan kompilyatsiya qiladi:

```console
$ cd eski && go build -o /dev/null .
# eski
./main.go:38:17: cannot range over Tolanganlar(bb) (value of func type iter.Seq[Buyurtma]): requires go1.23 or later (-lang was set to go1.22; check go.mod)
```

Xatoni oʻqiymiz: `./main.go:38:17` — fayl, 38-qator, 17-ustun (`Tolanganlar(bb)`). *cannot range over
Tolanganlar(bb) (value of func type iter.Seq[Buyurtma])* — «`Tolanganlar(bb)` ustida range qilib boʻlmaydi (bu
`iter.Seq[Buyurtma]` funksiya turidagi qiymat)». *requires go1.23 or later* — «go1.23 yoki undan yangisi kerak».
Qavs ichida sabab: `-lang` go1.22 qilib berilgan, go.mod'ni tekshiring.

Haqiqiy Go 1.22 esa tajriba bayrogʻi bilan bu kodni ishga tushiradi. `GOTOOLCHAIN=go1.22.12` birinchi marta Go
1.22.12 ni yuklab oladi:

```console

go version go1.22.12 linux/amd64
buyurtma 1 150000
buyurtma 3 42000
kichik summa, toʻxtaymiz
```

Bayroqsiz Go 1.22.12 build'ni boshlamaydi ham: `imports iter: build constraints exclude all Go files` — `iter`
paketining fayllari faqat shu tajriba yoqilganda kompilyatsiya qilinadi. Tuzatish oddiy: `go.mod` da `go 1.23` yoki
undan yuqori boʻlsin.

## iter.Seq va yield: iterator nima

`iter` paketidagi taʼrif bitta qator:

```go
type Seq[V any] func(yield func(V) bool)
```

Uni oʻngdan chapga oʻqiymiz:

| Qism | Maʼnosi |
|---|---|
| `func(V) bool` | `V` turidagi qiymat olib, `bool` qaytaradigan funksiya. Bu — **yield funksiyasi** (*yield function*) |
| `func(yield func(V) bool)` | shunday funksiyani parametr sifatida oladigan, hech narsa qaytarmaydigan funksiya. Bu — **iterator** |
| `Seq[V any]` | generic tur, `V` — type parameter ([GO-1.17](/lab/youtube/go#go-1-17)). `iter.Seq[Buyurtma]` da `V = Buyurtma` |

Ism *seek* deb oʻqiladi: *sequence* soʻzining birinchi boʻgʻini (iter hujjati). Hujjatning taʼrifi: *"An iterator is a
function that passes successive elements of a sequence to a callback function, conventionally named yield."* —
«Iterator — ketma-ketlik elementlarini birma-bir callback funksiyaga beradigan funksiya; odatda u `yield` deb
ataladi». *"The function stops either when the sequence is finished or when yield returns false"* — «ketma-ketlik
tugaganda yoki `yield` `false` qaytarganda toʻxtaydi».

Endi `hook/main.go` dagi `Tolanganlar` ni shu koʻz bilan qayta oʻqiymiz:

| Qator | Nima boʻlyapti |
|---|---|
| 19 | `Tolanganlar` iteratorning oʻzi emas: u iterator **yasaydi** va qaytaradi |
| 20 | qaytgan nomsiz funksiya — iterator. Uning `yield` parametri bor |
| 21 | iterator `bb` ni ushlab qolgan: `Tolanganlar` qaytgandan keyin ham `bb` unga koʻrinadi (closure) |
| 25 | har bir toʻlangan buyurtma `yield(b)` bilan beriladi |
| 25–27 | `yield` `false` qaytarsa — darhol `return` |
| 39 | `for b := range …` — shu iterator ustida aylanadi. `yield` ga nima berilsa, `b` shu boʻladi |

`slices.Values` ham xuddi shunday yozilgan: `for _, v := range s { if !yield(v) { return } }`
([slices/iter.go](https://github.com/golang/go/blob/go1.26.8/src/slices/iter.go#L37-L45)). Standart kutubxonadagi
iterator'larda sehr yoʻq: siz yozgan kod bilan bir xil.

## Kim qachon ishlaydi: iz qoldiramiz

Iterator va sikl tanasi qaysi tartibda ishlaydi? `iz/` da ikkalasiga ham `Println` qoʻshilgan:

```go filename="iz/main.go" showLineNumbers
// Iz: kim qachon ishlaydi? Iterator va sikl tanasi navbatma-navbat gapiradi.
package main

import (
	"fmt"
	"iter"
)

func Summalar(ss []int64) iter.Seq[int64] {
	return func(yield func(int64) bool) {
		for _, s := range ss {
			fmt.Println("iterator:", s, "ni beraman")
			davom := yield(s)
			fmt.Println("iterator: yield", davom, "qaytardi")
			if !davom {
				return
			}
		}
		fmt.Println("iterator: hammasi berildi")
	}
}

func main() {
	for s := range Summalar([]int64{150000, 42000, 310000}) {
		fmt.Println("  sikl:", s)
		if s < 50000 {
			break
		}
	}
	fmt.Println("sikldan keyin")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 9 | `func Summalar(ss []int64) iter.Seq[int64] {` | `int64` summalarni beradigan iterator yasaydi |
| 12 | `fmt.Println("iterator:", s, "ni beraman")` | iterator `yield` dan oldin gapiradi |
| 13 | `davom := yield(s)` | `yield` ning javobini oʻzgaruvchiga oladi |
| 14 | `fmt.Println("iterator: yield", davom, "qaytardi")` | javobni chiqaradi |
| 15–17 | `if !davom { return }` | `false` boʻlsa toʻxtaydi |
| 19 | `fmt.Println("iterator: hammasi berildi")` | sikl oxirigacha yetsa chiqadi |
| 24 | `for s := range Summalar([]int64{150000, 42000, 310000}) {` | uchta summa ustida aylanadi |
| 25 | `fmt.Println("  sikl:", s)` | sikl tanasi gapiradi (ikki boʻsh joy bilan) |
| 26–28 | `if s < 50000 { break }` | `42000` da chiqadi |
| 30 | `fmt.Println("sikldan keyin")` | sikldan keyingi qator |

**A)** ikkalasi ham chiqadi · **B)** `310000` chiqmaydi, `hammasi berildi` chiqadi · **C)** ikkalasi ham chiqmaydi

19-qatorga ham, uchinchi summaga ham navbat kelmaydi. «A» yoki «B» ni tanlagan boʻlsangiz, iterator oldin hamma
qiymatni tayyorlab qoʻyadi deb oʻylagansiz. Iterator qiymatni faqat soʻralganda hisoblaydi.

</details>

one stack"* — «hammasi bitta stekda» ([Rangefunc Experiment](https://go.dev/wiki/RangefuncExperiment)). Channel ham,
qoʻshimcha goroutine ham yoʻq. (Bu `range` uchun toʻgʻri. Keyinroq koʻradigan `iter.Pull` esa ichida alohida coroutine
yaratadi.)

## Kompilyator sikl tanasini funksiyaga aylantiradi

`yield` ga kim qiymat qaytaryapti? Uni kompilyator yasaydi. U sikl tanasini yangi nomsiz funksiyaga joylaydi va
iteratorga `yield` sifatida beradi. Bu Go kompilyatorining `rangefunc` paketida yozilgan
([rewrite.go, *Theory of Operation*](https://github.com/golang/go/blob/go1.26.8/src/cmd/compile/internal/rangefunc/rewrite.go)).
`hook` dagi sikl taxminan shunday boʻladi:

```text
// siz yozgan:
for b := range Tolanganlar(bb) {
    fmt.Println("buyurtma", b.ID, b.Summa)
    if b.Summa < 50000 {
        fmt.Println("kichik summa, toʻxtaymiz")
        break
    }
}

// kompilyator yasagani (soddalashtirilgan):
Tolanganlar(bb)(func(b Buyurtma) bool {
    fmt.Println("buyurtma", b.ID, b.Summa)
    if b.Summa < 50000 {
        fmt.Println("kichik summa, toʻxtaymiz")
        return false    // break edi
    }
    return true         // tana oxiri: keyingisini ber
})
```

Tanadagi har bir kalit soʻz shunday almashtiriladi:

| Sikl tanasida | `yield` funksiyasida | Maʼnosi iterator uchun |
|---|---|---|
| tana oxiri | `return true` | keyingi elementni ber |
| `continue` | `return true` | keyingi elementni ber |
| `break` | `return false` | toʻxta |
| `return` | `#next = -1; return false` | toʻxta; iterator qaytgach, tashqi funksiya ham `return` qiladi |

`return` eng qiziq holat. Tana ichidagi `return` tashqi funksiyadan chiqishi kerak, lekin u endi boshqa funksiya
ichida. Shuning uchun kompilyator avval `false` qaytaradi va yashirin `#next` oʻzgaruvchisiga belgi qoʻyadi. Iterator
`return` qilgach, kompilyator qoʻshgan kod `if #next == -1 { return }` ni tekshiradi va tashqi funksiyadan chiqadi.
`#` bilan boshlangan nomlarni siz yoza olmaysiz: bular kompilyatorning ichki oʻzgaruvchilari.

Bundan tashqari, kompilyator har bir sikl uchun holat oʻzgaruvchisini (`#stateK`) yaratadi. Yasalgan `yield` har
chaqiruvda shu holatni tekshiradi. Bu keyingi boʻlim uchun muhim.

## Panic: yield false qaytargandan keyin

Endi darsning boshidagi `panic` ga qaytamiz. `buzuq/` papkasidagi kod `hook/` bilan bir xil, faqat bitta joyda farq
qiladi:

```console
$ diff hook/main.go buzuq/main.go | tail -5
< 			if !yield(b) {
< 				return
< 			}
---
> 			yield(b)
```

`<` — `hook/main.go` dagi qatorlar, `>` — `buzuq/main.go` dagisi. `buzuq` da `yield(b)` ning javobi tashlab
yuboriladi. `go vet` bu xatoni topmaydi:

```console
$ go vet ./buzuq && echo 'vet: jim'
vet: jim
```

`vet: jim` — `go vet` hech narsa topmadi va `echo` ishladi. Oʻylab koʻring: `go run ./buzuq` nima qiladi?

**A)** `hook` bilan bir xil uchta qator · **B)** `buyurtma 4 310000` ham chiqadi: iterator toʻxtamadi ·
**C)** uchta qator, keyin `panic`

<details>
<summary>Javob</summary>

**C.** `break` dan keyin `yield` `false` qaytardi, lekin `buzuq` iterator buni tekshirmadi va 4-buyurtma bilan `yield`
ni yana chaqirdi. Kompilyator yasagan `yield` holatni tekshiradi va dasturni toʻxtatadi. «B» ni tanlagan boʻlsangiz,
`yield` ni oddiy callback deb oʻylagansiz: tana `break` dan keyin qayta ishlamaydi. «A» ni tanlagan boʻlsangiz, Go buni
jim oʻtkazib yuboradi deb oʻylagansiz.

</details>


`22:4-12` — 22-qator, 4–12 ustunlar: `yield(b)`. `hook/main.go` uchun `gopls check` hech narsa chiqarmaydi.
Tuzatish: `yield` ning javobini doim tekshiring, `if !yield(b) { return }`.

## Daraxt: rekursiv iterator

Iterator'ning katta foydasi murakkab tuzilmalarda koʻrinadi. `daraxt/` da generic **ikkilik qidiruv daraxti** (*binary
search tree*) bor: har bir tugunning chap shoxida undan kichik qiymatlar, oʻng shoxida esa katta yoki teng qiymatlar.

```go filename="daraxt/main.go" showLineNumbers
// Daraxt: rekursiv tuzilmani iterator bilan aylanish.
// Slice yaratilmaydi, channel ham, goroutine ham kerak emas.
package main

import (
	"cmp"
	"fmt"
	"iter"
)

type Daraxt[T cmp.Ordered] struct {
	chap, ong *Daraxt[T]
	qiymat    T
}

func (d *Daraxt[T]) Qosh(v T) *Daraxt[T] {
	if d == nil {
		return &Daraxt[T]{qiymat: v}
	}
	if v < d.qiymat {
		d.chap = d.chap.Qosh(v)
	} else {
		d.ong = d.ong.Qosh(v)
	}
	return d
}

// All qiymatlarni oʻsish tartibida beradi.
func (d *Daraxt[T]) All() iter.Seq[T] {
	return func(yield func(T) bool) {
		d.aylan(yield)
	}
}

func (d *Daraxt[T]) aylan(yield func(T) bool) bool {
	if d == nil {
		return true
	}
	return d.chap.aylan(yield) && yield(d.qiymat) && d.ong.aylan(yield)
}

func main() {
	var d *Daraxt[int64]
	for _, s := range []int64{150000, 42000, 310000, 99000, 7000} {
		d = d.Qosh(s)
	}
	for s := range d.All() {
		fmt.Println(s)
		if s >= 100000 {
			break
		}
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 11 | `type Daraxt[T cmp.Ordered] struct {` | generic tur; `T` — `<` bilan solishtirsa boʻladigan tur ([GO-1.17](/lab/youtube/go#go-1-17)) |
| 12 | `chap, ong *Daraxt[T]` | chap va oʻng shoxga pointer; shox yoʻq boʻlsa `nil` |
| 13 | `qiymat T` | tugundagi qiymat |
| 16 | `func (d *Daraxt[T]) Qosh(v T) *Daraxt[T] {` | qiymat qoʻshadi va daraxtning ildizini qaytaradi |
| 17–19 | `if d == nil { return &Daraxt[T]{qiymat: v} }` | boʻsh joyga yangi tugun. Pointer receiver'li metodni `nil` ustida ham chaqirsa boʻladi |
| 20–24 | `if v < d.qiymat { … } else { … }` | kichigi chapga, qolgani oʻngga |
| 29 | `func (d *Daraxt[T]) All() iter.Seq[T] {` | iterator qaytaradi. iter hujjati: kolleksiyaning hamma elementlarini beradigan metod odatda `All` deb ataladi |
| 31 | `d.aylan(yield)` | ishni rekursiv `aylan` ga beradi |
| 35 | `func (d *Daraxt[T]) aylan(yield func(T) bool) bool {` | `bool` qaytaradi: `true` — davom, `false` — toʻxtadik |
| 36–38 | `if d == nil { return true }` | boʻsh shox: aylanadigan narsa yoʻq, davom etaveramiz |
| 39 | `return d.chap.aylan(yield) && yield(d.qiymat) && d.ong.aylan(yield)` | avval chap shox, keyin tugun, keyin oʻng shox |
| 44–46 | `for _, s := range []int64{…} { d = d.Qosh(s) }` | beshta summani daraxtga qoʻshadi |
| 47–52 | `for s := range d.All() { …; if s >= 100000 { break } }` | oʻsish tartibida chiqaradi, `100000` dan oshganda toʻxtaydi |

Butun ish 39-qatorda. `&&` — qisqa tutashuv (*short-circuit*): chap tomoni `false` boʻlsa, oʻng tomoni umuman
hisoblanmaydi. Demak, biror `yield` `false` qaytarsa, qolgan qadamlar chaqirilmaydi va `false` rekursiya boʻylab
yuqoriga qaytadi. Iterator qoidani shu bitta qatorda bajaradi. Go spetsifikatsiyasidagi `Tree.walk` misoli ham shu
gʻoyada.

Daraxt shunday koʻrinadi (qoʻshilish tartibi: `150000, 42000, 310000, 99000, 7000`):

```text
              150000
             /      \
         42000      310000
        /     \
     7000    99000

aylanish tartibi: chap → tugun → oʻng
7000 → 42000 → 99000 → 150000 → (break) → 310000 ga navbat kelmaydi
```

```console
$ go run ./daraxt
7000
42000
99000
150000
```

Natija oʻsish tartibida chiqdi, `150000` dan keyin esa sikl toʻxtadi. Buning uchun na slice, na channel, na
qoʻshimcha goroutine kerak boʻldi. Iterator'siz bu ishni ikki yoʻl bilan qilardingiz: hamma qiymatni slice'ga yigʻish
(xotira) yoki `filepath.Walk` kabi callback qabul qilish (har paketda oʻz usul).

## Tezlik: oʻlchab koʻramiz

Har bir element uchun funksiya chaqiruvi — sekin emasmi? Taxmin qilmaymiz, oʻlchaymiz ([GO-1.07](/lab/youtube/go/go-1-07)).
`tezlik/` da bir xil yigʻindi toʻrt usulda:

```go filename="tezlik/tezlik.go" showLineNumbers
// Tezlik: bir xil yigʻindi toʻrt usulda.
package tezlik

import (
	"iter"
	"slices"
)

// 1. Oddiy range slice ustida.
func JamiOddiy(ss []int64) int64 {
	var j int64
	for _, s := range ss {
		j += s
	}
	return j
}

// 2. Standart iterator: slices.Values.
func JamiValues(ss []int64) int64 {
	var j int64
	for s := range slices.Values(ss) {
		j += s
	}
	return j
}

// Barchasi — oʻzimiz yozgan iterator.
func Barchasi(ss []int64) iter.Seq[int64] {
	return func(yield func(int64) bool) {
		for _, s := range ss {
			if !yield(s) {
				return
			}
		}
	}
}

// 3. Oʻz iteratorimiz.
func JamiOz(ss []int64) int64 {
	var j int64
	for s := range Barchasi(ss) {
		j += s
	}
	return j
}

// 4. Iterator qiymat sifatida keladi, funksiya inline qilinmaydi:
// endi har bir element uchun yield haqiqiy chaqiruv boʻladi.
//
//go:noinline
func JamiSeq(seq iter.Seq[int64]) int64 {
	var j int64
	for s := range seq {
		j += s
	}
	return j
}
```

## iter.Seq2: har qadamda ikki qiymat

`range` uch xil funksiyani qabul qiladi ([Go 1.23 release notes](https://go.dev/doc/go1.23#language)):

| Funksiya turi | `iter` dagi nomi | `for` shakli |
|---|---|---|
| `func(func() bool)` | — | `for range f` |
| `func(func(V) bool)` | `iter.Seq[V]` | `for v := range f` |
| `func(func(K, V) bool)` | `iter.Seq2[K, V]` | `for k, v := range f` |

`Seq2` odatda kalit–qiymat yoki indeks–qiymat juftligini beradi. `slices.All` — indeks va qiymat, `maps.All` — kalit
va qiymat.

```go filename="seq2/main.go" showLineNumbers
// Seq2: har qadamda ikki qiymat (indeks va qiymat, kalit va qiymat).
package main

import (
	"fmt"
	"iter"
	"slices"
	"sync"
)

func main() {
	summalar := []int64{150000, 42000}
	for i, s := range slices.All(summalar) { // iter.Seq2[int, int64]
		fmt.Println(i, s)
	}

	// sync.Map'ning Range metodi Go 1.9 dan beri bor va aynan Seq2 shaklida.
	var m sync.Map
	m.Store("Aziz", 150000)
	var _ iter.Seq2[any, any] = m.Range
	for k, v := range m.Range {
		fmt.Println(k, v)
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 13 | `for i, s := range slices.All(summalar) {` | `slices.All` — `iter.Seq2[int, int64]`: indeks va qiymat |
| 18 | `var m sync.Map` | goroutine'lar uchun xavfsiz map (goroutine'lar keyingi darslarda) |
| 19 | `m.Store("Aziz", 150000)` | kalit va qiymat yozadi; ikkalasi ham `any` boʻlib saqlanadi |
| 20 | `var _ iter.Seq2[any, any] = m.Range` | tekshiruv: `m.Range` metodi `iter.Seq2[any, any]` turiga mos keladimi? Mos kelmasa, kompilyatsiya xatosi. `_` — qiymatni tashlab yuboradi |
| 21 | `for k, v := range m.Range {` | eski metodning oʻzi ustida `range` |

```console
$ go run ./seq2
0 150000
1 42000
Aziz 150000
```

Qiziq tomoni: `sync.Map.Range` Go 1.9 dan beri bor, iterator'lardan ancha oldin. Lekin uning imzosi
`Range(f func(key, value any) bool)` aynan `Seq2` shaklida. Shuning uchun uni hech qanday oʻzgarishsiz `range` qilish
mumkin.

Ikki iterator'ni yonma-yon yurgizish kerak boʻlsa-chi (masalan, ismlar va summalarni juftlab)? `range` bunga
yetmaydi: u bitta iteratorni boshqaradi. Buning uchun `iter.Pull` bor: u iteratorni *pull* shakliga (`next`, `stop`
funksiyalari) aylantiradi. Uni uy vazifasining Guru darajasida yozasiz.

Iterator'da xato qayerga ketadi? `iter.Seq[T]` da xato uchun joy yoʻq. Ikki odatiy yoʻl bor: `iter.Seq2[T, error]`
(har qiymat bilan birga xato) yoki `bufio.Scanner` kabi alohida `Err()` metodi.

## Bir martalik iterator

Endi bitta yashirin tuzoq. Go 1.24 da `strings.SplitSeq` qoʻshilgan: `strings.Split` kabi satrni qismlarga boʻladi,
lekin slice yasamaydi, iterator qaytaradi.

```go filename="birmarta/main.go" showLineNumbers
// Bir martalik iterator: strings.SplitSeq ikkinchi marta boshidan boshlamaydi.
package main

import (
	"fmt"
	"strings"

func main() {
	qismlar := strings.SplitSeq("Aziz,Bobur,Dilnoz", ",")
	for q := range qismlar {
		fmt.Println("1-marta:", q)
	}
	for q := range qismlar {
		fmt.Println("2-marta:", q)
	}
}
```

### Taqqoslash funksiyasi: ayirma emas

Mahsulotlarni reyting boʻyicha, kattasi oldin saralaymiz. JS'dagi odatiy usul: `mm.sort((a, b) => b.reyting -
a.reyting)`. Go'da `slices.SortFunc` ga **taqqoslash funksiyasi** (*comparison function*) beriladi. Hujjatiga koʻra u
`a < b` boʻlsa manfiy son, `a > b` boʻlsa musbat son, teng boʻlsa `0` qaytarishi kerak. Natija turi esa `int`.

```go filename="saralash/main.go" showLineNumbers
// Saralash: reyting boʻyicha kamayish tartibida. Ikki xato va bitta toʻgʻri usul.
package main

import (
	"cmp"
	"fmt"
	"slices"
)

type Mahsulot struct {
	Nom     string
	Reyting float64
}

func main() {
	mm := []Mahsulot{{"choynak", 4.2}, {"dazmol", 4.8}, {"fen", 3.9}, {"blender", 4.5}}

	// Xato: ayirma int'ga aylanganda 0.6 → 0 boʻladi, ya'ni "teng".
	slices.SortFunc(mm, func(a, b Mahsulot) int {
		return int(b.Reyting - a.Reyting)
	})
	fmt.Println("int(ayirma):  ", mm)

	// Toʻgʻri: cmp.Compare manfiy, nol yoki musbat qaytaradi.
	slices.SortFunc(mm, func(a, b Mahsulot) int {
		return cmp.Compare(b.Reyting, a.Reyting)
	})
	fmt.Println("cmp.Compare:  ", mm)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10–13 | `type Mahsulot struct { Nom string; Reyting float64 }` | mahsulot nomi va reytingi (kasrli son) |
| 16 | `mm := []Mahsulot{…}` | toʻrtta mahsulot: `choynak` 4.2, `dazmol` 4.8, `fen` 3.9, `blender` 4.5 |
| 19–21 | `slices.SortFunc(mm, func(a, b Mahsulot) int { return int(b.Reyting - a.Reyting) })` | JS'dagi `b - a`, lekin natija `int` ga aylantiriladi |
| 22 | `fmt.Println("int(ayirma):  ", mm)` | birinchi natija |
| 25–27 | `… return cmp.Compare(b.Reyting, a.Reyting) …` | toʻgʻri usul |
| 28 | `fmt.Println("cmp.Compare:  ", mm)` | ikkinchi natija |

**C)** teskari: `fen, choynak, blender, dazmol`

<details>
<summary>Javob</summary>

**B.** `4.8 − 4.2 = 0.6`. Kasrli sonni `int` ga aylantirganda Go kasr qismini tashlaydi (nolga qarab), `0.6` → `0`,
ya'ni «teng». Bu yerda eng katta ayirma `4.8 − 3.9 = 0.9`, hamma ayirma birdan kichik. `slices.SortFunc` hammasini
teng deb biladi va hech narsani surmaydi. «A» ni tanlagan boʻlsangiz, JS'dagi kabi ishlaydi deb oʻylagansiz: JS'da
`sort` kasrli natijani ham qabul qiladi va faqat ishorasiga qaraydi. «C» ni tanlagan boʻlsangiz, `b, a` tartibini
teskari oʻqigansiz.

</details>

Tuzatish — [`cmp.Compare`](https://pkg.go.dev/cmp#Compare) (Go 1.21). U `x < y` da `-1`, teng boʻlsa `0`, `x > y`

(*overflow*) mumkin.

### NaN va cmp.Or

Yana bir tuzoq. Sharhi yoʻq yangi mahsulotning reytingi `0/0` boʻlsa-chi? Kasrli sonlarda `0/0` — **NaN** (*Not a
Number*, «son emas»), IEEE 754 qoidasi. JS'da ham `0/0` → `NaN`.

```go filename="nan/main.go" showLineNumbers
// NaN: sharhi yoʻq mahsulotning reytingi 0/0 = NaN. Qoʻlda yozilgan taqqoslash buziladi.
package main

import (
	"cmp"
	"fmt"
	"slices"
	"strings"
)

type Mahsulot struct {
	Nom     string
	Reyting float64
}

func main() {
	var nol float64
	yangi := Mahsulot{"yangi", nol / nol} // 0/0 = NaN
	asl := []Mahsulot{
		{"dazmol", 4.8}, {"fen", 3.9}, yangi,
		{"choynak", 4.2}, {"mikser", 4.5}, {"blender", 4.5},
	}

	// Xato: NaN hech narsadan katta ham, kichik ham emas — "hammaga teng".
	mm := slices.Clone(asl)
	slices.SortFunc(mm, func(a, b Mahsulot) int {
		if a.Reyting > b.Reyting {
			return -1
		}
		if a.Reyting < b.Reyting {
			return 1
		}
		return 0
	})
	fmt.Println("qoʻlda:", nomlar(mm))

	// Toʻgʻri: cmp.Compare NaN'ni eng kichik deb hisoblaydi.
	// cmp.Or: reyting teng boʻlsa, nom boʻyicha.
	mm = slices.Clone(asl)
	slices.SortFunc(mm, func(a, b Mahsulot) int {
		return cmp.Or(
			cmp.Compare(b.Reyting, a.Reyting),
			strings.Compare(a.Nom, b.Nom),
		)
	})
	fmt.Println("cmp.Or:", nomlar(mm))
}

func nomlar(mm []Mahsulot) []string {
	var s []string
	for _, m := range mm {
		s = append(s, fmt.Sprintf("%s=%.1f", m.Nom, m.Reyting))
	}
	return s
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 17–18 | `var nol float64`; `yangi := Mahsulot{"yangi", nol / nol}` | `0/0 = NaN`. Konstanta `0.0/0.0` ni kompilyator rad etadi (*division by zero*), shuning uchun oʻzgaruvchi orqali |
| 19–22 | `asl := []Mahsulot{…}` | oltita mahsulot, `mikser` va `blender` ning reytingi bir xil (4.5) |
| 25 | `mm := slices.Clone(asl)` | nusxa: asl tartib ikkinchi saralash uchun saqlanadi |
| 26–34 | `if a.Reyting > b.Reyting { return -1 }`… | qoʻlda yozilgan taqqoslash: kattasi oldin |
| 35 | `fmt.Println("qoʻlda:", nomlar(mm))` | birinchi natija |
| 40–45 | `cmp.Or(cmp.Compare(b.Reyting, a.Reyting), strings.Compare(a.Nom, b.Nom))` | reyting boʻyicha, teng boʻlsa nom boʻyicha |
| 49–55 | `func nomlar(mm []Mahsulot) []string` | `nom=reyting` koʻrinishidagi qatorlar (`%.1f` — bitta kasr xonasi) |

Oʻylab koʻring: qoʻlda yozilgan funksiya bilan `yangi=NaN` qayerga tushadi?

**A)** oxiriga · **B)** boshiga · **C)** oʻrtaga va boshqalarni ham buzadi

<details>
<summary>Javob</summary>

**C.** NaN bilan har qanday `<` yoki `>` taqqoslash `false` beradi. Demak, qoʻlda yozilgan funksiya NaN uchun doim
`0` qaytaradi: NaN `4.8` ga ham, `3.9` ga ham «teng». Lekin `4.8` va `3.9` bir-biriga teng emas. Saralash esa «teng»
munosabati tranzitiv boʻlishini talab qiladi (*strict weak ordering*). Bu qoida buzilgani uchun `fen=3.9` ikkinchi
oʻringa chiqib qoldi. «A» yoki «B» ni tanlagan boʻlsangiz, NaN oddiy kichik yoki katta son kabi ishlaydi deb oʻylagansiz.

</details>

```console

cmp.Or: [dazmol=4.8 blender=4.5 mikser=4.5 choynak=4.2 fen=3.9 yangi=NaN]
```

Birinchi qatorda `fen=3.9` `mikser=4.5` dan oldin turibdi: saralash buzildi. Ikkinchi qator toʻgʻri, ikki sababga koʻra:

1. `cmp.Compare` NaN'ni eng kichik deb hisoblaydi. Hujjati: *"a NaN is considered less than any non-NaN, a NaN is
   considered equal to a NaN"*. `b, a` tartibida esa eng kichigi oxirida.
2. [`cmp.Or`](https://pkg.go.dev/cmp#Or) (Go 1.22) argumentlaridan birinchi nol boʻlmaganini qaytaradi. Reytinglar
   farq qilsa, `cmp.Compare` natijasi olinadi. Teng boʻlsa (`0`), `strings.Compare(a.Nom, b.Nom)` olinadi: `blender`
   `mikser` dan oldin. SQL'dagi `ORDER BY reyting DESC, nom` ning aynan oʻzi.

`slices.SortFunc` barqaror emas: teng elementlarning tartibi saqlanishi kafolatlanmagan. Shuning uchun ikkinchi
kalit (`cmp.Or`) natijani har safar bir xil qiladi. Asl tartibni saqlash kerak boʻlsa, `slices.SortStableFunc` bor.

## Savol: defer va break

Iterator ichida resurs ochilsa-chi? Masalan, fayl. `savol/` da shunday iterator bor:

```go
func Qatorlar() iter.Seq[string] {
	return func(yield func(string) bool) {
		fmt.Println("fayl ochildi")
		defer fmt.Println("fayl yopildi")
		for _, q := range []string{"birinchi", "ikkinchi", "uchinchi"} {
			if !yield(q) {
				return
			}
		}
	}
}
```

Iterator «fayl ochadi» va uni `defer` bilan «yopadi» (haqiqiy fayl oʻrniga `Println`). Sikl esa birinchi qatordayoq
`break` qiladi, keyin `sikldan keyin` ni chiqaradi.

Oʻylab koʻring: `fayl yopildi` chiqadimi? Chiqsa, `sikldan keyin` dan oldinmi yoki keyinmi?

**A)** chiqmaydi: `break` iteratorni oʻrtada tashlab ketadi · **B)** chiqadi, `sikldan keyin` dan keyin ·
**C)** chiqadi, `sikldan keyin` dan oldin

<details>
<summary>Javob</summary>

**C.** `break` dan keyin `yield` `false` qaytaradi, iterator `return` qiladi va uning `defer` i ishlaydi. `range`
faqat shundan keyin tugaydi. Iterator — oddiy funksiya, `defer` esa funksiya tugaganda ishlaydi
([GO-1.15](/lab/youtube/go/go-1-15)). Go wiki: *"If an iterator function defers a call, the call runs when the iterator function
returns."* «A» ni tanlagan boʻlsangiz, JS/Python generator kabi pauzada qoladi deb oʻylagansiz. «B» ni tanlagan
boʻlsangiz, `defer` `main` ga tegishli deb oʻylagansiz.

</details>

```go filename="savol/main.go" showLineNumbers
// Savol: sikl birinchi qatordayoq break qiladi. "fayl yopildi" chiqadimi? Qachon?
package main

import (
	"fmt"
	"iter"
)

func Qatorlar() iter.Seq[string] {
	return func(yield func(string) bool) {
		fmt.Println("fayl ochildi")
		defer fmt.Println("fayl yopildi")
		for _, q := range []string{"birinchi", "ikkinchi", "uchinchi"} {
			if !yield(q) {
				return
			}
		}
	}
}

func main() {
	for q := range Qatorlar() {
		fmt.Println(q)
		break
	}
	fmt.Println("sikldan keyin")
}
```

```console
$ go run ./savol
fayl ochildi
birinchi
fayl yopildi
sikldan keyin
```

Demak, `range` bilan ishlatilgan iterator oʻz faylini ishonchli yopadi. Lekin bu kafolat faqat `range` uchun.
`iter.Pull` da `stop` chaqirilmasa, iterator oʻrtada qotib qoladi va bu `defer` ishlamaydi. iter hujjati: *"If clients
do not consume the sequence to completion, they must call stop"* — «ketma-ketlikni oxirigacha olmasangiz, `stop` ni
chaqirishingiz shart». Uy vazifasidagi `TestStop` aynan shuni tekshiradi.

## Xulosa: iterator qoidalari

| Qoida | Nega |
|---|---|
| iterator = `yield` ni chaqiradigan oddiy funksiya | `iter.Seq[V]` — `func(yield func(V) bool)`, sehr yoʻq |
| `yield` `false` qaytarsa — darhol `return` | aks holda `panic`; `go vet` jim, gopls koʻrsatadi |
| tezlik haqida taxmin qilmang, oʻlchang | oddiy holatlar inline boʻladi, noaniq iterator 7–9 baravar sekin (kichik tanada) |
| bir martalik iterator'larga ehtiyot boʻling | `strings.SplitSeq` ikkinchi marta boshidan boshlamaydi: hujjatni oʻqing |
| saralashda ayirma emas, `cmp.Compare` va `cmp.Or` | `int(0.6) = 0`, NaN tartibni buzadi |

## Koʻp uchraydigan xatolar

**1. `yield` ning javobini tekshirmaslik.** Eng koʻp uchraydigani. Iterator `break` dan keyin `yield` ni yana
chaqiradi va dastur `range function continued iteration after function for loop body returned false` bilan yiqiladi.
Toʻliq misol, xato va stack trace «Panic» boʻlimida. Xatoni oʻqish: `main.main-range1` — sikl tanasi, uning ostidagi
qator (`buzuq/main.go:22`) esa `yield` ni noqonuniy chaqirgan joy. Tuzatish: har bir `yield` ni
`if !yield(v) { return }` shaklida yozing. Bir nechta `yield` boʻlsa (masalan, `Filtr` adapterida), har birini.
Muharrirda gopls'ni yoqing: u `yield may be called again after returning false` deb ogohlantiradi.

**2. Iterator qaytaradigan funksiyani eski `go` qatorli modulda ishlatish.** `go 1.22` (yoki undan past) modulda
`requires go1.23 or later (-lang was set to go1.22; check go.mod)` («Nega kerak edi» boʻlimi). Kompyuterdagi Go yangi
boʻlsa ham, `go.mod` dagi qator hal qiladi. Tuzatish: `go` qatorini `1.23` yoki undan yuqori qiling.

**3. Bir martalik iterator'ni ikki marta aylanish.** Xato ham, `panic` ham yoʻq: ikkinchi sikl shunchaki kamroq (yoki
hech narsa) beradi («Bir martalik iterator» boʻlimi, `2-marta: Dilnoz`). Tuzatish: hujjatda *single-use* soʻzini
qidiring. Qiymatlar ikki marta kerak boʻlsa, `slices.Collect` bilan slice'ga yigʻing.

**4. Taqqoslash funksiyasida ayirma.** `int(b.Reyting - a.Reyting)` kasr qismini tashlaydi va `0.6` ni «teng» qiladi.
Saralash jim, natija esa oʻzgarmagan («Taqqoslash funksiyasi» boʻlimi). Butun sonlarda ayirma toʻlib ketishi mumkin.
Tuzatish: `cmp.Compare(b.Reyting, a.Reyting)`.

**5. Kasrli sonlarni `<` va `>` bilan qoʻlda taqqoslash.** NaN boʻlsa, saralash buziladi va bu ham jim boʻladi
(«NaN va cmp.Or» boʻlimi). Tuzatish: `cmp.Compare`, u NaN'ni eng kichik deb hisoblaydi.

**6. `iter.Pull` dan keyin `stop` ni chaqirmaslik.** Iterator oʻrtada qoladi, uning `defer` i (fayl yopish) ishlamaydi.
Xato chiqmaydi. Tuzatish: `next, stop := iter.Pull(seq)` dan keyin darhol `defer stop()`.

## Oʻzingizni tekshiring

**1.** Iterator ichida nega `yield(v)` emas, `if !yield(v) { return }` yozish kerak?

<details>
<summary>Javob</summary>

`yield` `false` qaytarsa, sikl tanasi tugagan (`break`, `return` yoki `goto`). Spetsifikatsiyaga koʻra `yield` ni
endi chaqirish mumkin emas. Kompilyator yasagan `yield` buni tekshiradi va qoidabuzarlikda `panic` qiladi. JS/Python
generator'idan farqli, iteratorni hech kim majburan toʻxtatmaydi: toʻxtash uning oʻz vazifasi.

</details>

**2.** Kompilyator sikl tanasidagi `continue`, `break` va `return` ni nimaga aylantiradi?

<details>
<summary>Javob</summary>

`continue` → `return true` (keyingisini ber). `break` → `return false` (toʻxta). `return` → avval `#next = -1;
return false`, iterator qaytgach esa tashqi funksiya ham `return` qiladi. Tana oxiri → `return true`.

</details>

**3.** `daraxt/main.go` da 49-qatorni `if s > 40000 {` ga oʻzgartirdik (kurs papkasida yoʻq, alohida ishga

<details>
<summary>Javob</summary>

`7000` va `42000`. Oʻsish tartibida `7000` (`40000` dan kichik, davom), keyin `42000` (`40000` dan katta, `break`).
`yield` `false` qaytaradi, `&&` qolgan qadamlarni chaqirmaydi va rekursiya toʻxtaydi.

```console
$ go run .

42000
```

</details>

**4.** `fmt.Printf("%T\n", maps.Keys(m))` nima chiqaradi (`m` — `map[string]int64`)? Nega `slices.Sorted` uni qabul
qiladi?

<details>
<summary>Javob</summary>

`iter.Seq[string]`. `maps.Keys` slice emas, iterator qaytaradi. `slices.Sorted` istalgan `iter.Seq` ni oladi, hamma
qiymatni slice'ga yigʻadi va saralangan holda qaytaradi.

</details>

**5.** `cmp.Or(cmp.Compare(jami[b], jami[a]), strings.Compare(a, b))` qanday tartib beradi?

<details>
<summary>Javob</summary>

Jami summa boʻyicha kamayish tartibida (`b, a` — kattasi oldin). Summalar teng boʻlsa, birinchi natija `0`, va `cmp.Or`
ikkinchisini oladi: ism boʻyicha alifbo tartibida. Bu uy vazifasidagi Qiyin masalaning javobi.

</details>

**6.** [GO-1.11](/lab/youtube/go/go-1-11) dan: `JamiSeq` da nega `j` heap'ga koʻchdi, `JamiOz` da esa yoʻq?

<details>
<summary>Javob</summary>

`JamiSeq` da sikl tanasi closure boʻlib qoladi va `j` ni ushlaydi ([GO-1.06](/lab/youtube/go/go-1-06): closure oʻzgaruvchining
oʻzini ushlaydi). Bu closure kompilyator ichini bilmaydigan `seq` ga beriladi. Kompilyator `j` funksiyadan keyin
kerak emasligini isbotlay olmaydi va uni heap'ga qoʻyadi (`moved to heap: j`). `JamiOz` da hammasi inline qilinadi,
closure qolmaydi va `j` stekda qoladi.

</details>

<details>

```go filename="homework/oson/oson.go" showLineNumbers
// Oson: Oraliq(a, b) a dan b gacha (b ham kiradi) sonlarni beradi.
package oson

import "iter"

func Oraliq(a, b int) iter.Seq[int] {
	return func(yield func(int) bool) {
		for i := a; i <= b; i++ {

				return
			}
		}
	}
}
```

🟡 **Oʻrta:** [GO-1.17](/lab/youtube/go#go-1-17) dagi `Filtr` va `Aylantir` ni endi iterator ustida generic funksiya qilib
yozing: `Filtr[V any](seq iter.Seq[V], f func(V) bool) iter.Seq[V]` va
`Aylantir[V, W any](seq iter.Seq[V], f func(V) W) iter.Seq[W]`. `slices.Values` bilan zanjir qiling.

<details>
<summary>Javob</summary>

```go filename="homework/orta/orta.go" showLineNumbers
// Oʻrta: iterator'ni oladigan va iterator qaytaradigan generic adapterlar (GO-1.17).
package orta

import "iter"

// Filtr faqat f true qaytargan qiymatlarni beradi.
func Filtr[V any](seq iter.Seq[V], f func(V) bool) iter.Seq[V] {
	return func(yield func(V) bool) {
		for v := range seq {
			if f(v) && !yield(v) {
				return
			}
		}
	}
}

// Aylantir har bir qiymatni f orqali boshqa turga aylantiradi.
func Aylantir[V, W any](seq iter.Seq[V], f func(V) W) iter.Seq[W] {
	return func(yield func(W) bool) {
		for v := range seq {
			if !yield(f(v)) {
				return
			}
		}
	}
}
```

Ichkarida oddiy `for v := range seq`. Tashqi `yield` `false` qaytarsa, `return` qilamiz. Shunda ichki sikl ham tugaydi:
uning `yield` i (bizning sikl tanamiz) `false` qaytaradi va ichki iterator oʻzi toʻxtaydi. `Filtr` da
`f(v) && !yield(v)`: `f` `false` bersa, `&&` tufayli `yield` umuman chaqirilmaydi. `TestZanjir`:
`Aylantir(Filtr(slices.Values(summalar), …), …)` → `["150000 soʻm" "310000 soʻm" "99000 soʻm"]`.

</details>

🟠 **Qiyin:** buyurtmalardan mijozlar boʻyicha jami summani hisoblang va mijozlarni jami summa kamayishi boʻyicha,
teng boʻlsa ism boʻyicha qaytaring (`maps.Keys`, `slices.SortedFunc`, `cmp.Or`). Natija har safar bir xil boʻlsinmi?

<details>
<summary>Javob</summary>

```go filename="homework/qiyin/qiyin.go" showLineNumbers
// Qiyin: mijozlar boʻyicha jami summa; jami kamayish tartibida, teng boʻlsa ism boʻyicha.
package qiyin

import (
	"cmp"
	"maps"
	"slices"
	"strings"
)

type Buyurtma struct {
	Mijoz string
	Summa int64
}

func Reyting(bb []Buyurtma) []string {
	jami := map[string]int64{}
	for _, b := range bb {
		jami[b.Mijoz] += b.Summa
	}
	return slices.SortedFunc(maps.Keys(jami), func(a, b string) int {
		return cmp.Or(
			cmp.Compare(jami[b], jami[a]), // summa: kattasi oldin

	})
}
```

beradi: ikki xil ism hech qachon «teng» chiqmaydi. Testda Aziz, Bobur va Kamola'ning jamisi bir xil (150000), shuning

</details>

🔴 **Guru:** `Zip[A, B any](a iter.Seq[A], b iter.Seq[B]) iter.Seq2[A, B]` — ikki iterator'ni yonma-yon yurgizing,
qisqasi tugaganda toʻxtasin. Nega `range` bunga yetmaydi va nega `stop` ni `defer` qilish kerak?

<details>
<summary>Javob</summary>

```go filename="homework/guru/guru.go" showLineNumbers
// Guru: ikki iterator'ni yonma-yon yurgizish. range bunga yetmaydi — iter.Pull kerak.
package guru

import "iter"

// Zip a va b dan navbatma-navbat bittadan qiymat oladi; qisqasi tugaganda toʻxtaydi.
func Zip[A, B any](a iter.Seq[A], b iter.Seq[B]) iter.Seq2[A, B] {
	return func(yield func(A, B) bool) {
		nextA, stopA := iter.Pull(a)
		defer stopA()
		nextB, stopB := iter.Pull(b)
		defer stopB()
		for {
			va, ok1 := nextA()
			vb, ok2 := nextB()
			if !ok1 || !ok2 || !yield(va, vb) {
				return
			}
		}
	}
}
```

`range` bitta iteratorni boshqaradi: iterator qiymatni oʻzi itaradi (*push*), siz faqat qabul qilasiz. Ikkitasidan
navbatma-navbat bittadan olish uchun **tortish** (*pull*) kerak. `iter.Pull(a)` iteratorni ikki funksiyaga aylantiradi:
`next()` keyingi qiymatni va `ok` ni qaytaradi, `stop()` iteratorni toʻxtatadi. Bu JS/Python generator'ining
`next()` iga oʻxshaydi. Ichkarida Go buning uchun coroutine yaratadi.

`defer stop()` nega kerak: `Zip` qisqasi tugaganda yoki tashqi sikl `break` qilganda, ikkinchi iterator oʻrtada
qoladi. iter hujjati: *"If clients do not consume the sequence to completion, they must call stop, which allows the
iterator function to finish and return."* — «ketma-ketlikni oxirigacha olmasangiz, `stop` ni chaqirishingiz shart, shunda
iterator funksiyasi tugab, qaytadi». `TestStop` buni koʻrsatadi: `stop` siz chaqirilgan `iter.Pull` da iteratorning
`defer` i ishlamaydi.

</details>
