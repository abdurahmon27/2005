## Nimani oʻrganasiz

Ikkita buyurtma yozuvi bor. Ikkalasida ham bir xil uchta maʼlumot turibdi: toʻlandimi (ha/yoʻq), summa va
yetkazildimi (ha/yoʻq). Farq faqat tartibda. Birinchisi xotirada **24 bayt** joy oladi, ikkinchisi **16 bayt**.
Maʼlumotlarning oʻzi esa jami 10 bayt. Ortiqcha baytlar qayerdan keldi? Bunday bir necha bayt GitLab'ning bir
xizmatini ham yiqitgan. Bugun yozuvning ichiga kirib, har bir baytni sanaymiz.

**Bitta gʻoya:** struct maydonlari xotirada ketma-ket turadi, lekin har bir maydon oʻz turiga mos manzildan
boshlanishi kerak. Shuning uchun maydonlar orasida boʻsh baytlar (padding) qolishi mumkin: maydonlar tartibi struct
oʻlchamini oʻzgartiradi. Alignment'i katta maydonlarni boshiga qoʻysangiz, struct koʻpincha kichrayadi, lekin buni
oʻlchab qiling.

Dars oxirida siz:

- oʻz struct turingizni eʼlon qilasiz va uni composite literal bilan yaratasiz, embedding'ni oʻqiy olasiz;
- `unsafe.Sizeof`, `unsafe.Alignof` va `unsafe.Offsetof` bilan struct'ning har bir baytini qogʻozda chizib,
  natijani tekshira olasiz;
- maydonlarni qayta tartiblab struct'ni kichraytira olasiz va bu qachon foyda berishini, qachon bermasligini
  bilasiz;
- 32 bitli tizimda `int64` hisoblagich nega panic berishini va `atomic.Int64` uni qanday tuzatishini
  tushuntira olasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| struct (maydon) | maydonlari oldindan eʼlon qilingan tur: TS'dagi obyekt turi yoki Python'dagi `dataclass` ga yaqin | struct (field) |
| padding (boʻsh baytlar) | maydonlar orasida yoki oxirida qoladigan, hech narsa saqlamaydigan baytlar | padding |
| tekislash (alignment) | qiymat manzili nechaga karrali boʻlishi kerakligi: 8 baytli son 8 ga karrali manzilda | alignment |

Yoʻl-yoʻlakay ikkita yordamchi soʻz ham uchraydi: **composite literal** (struct qiymatini kodning oʻzida
jingalak qavs bilan yozish) va **embedding** (bir struct'ni boshqasining ichiga nomsiz joylash). Ikkalasini
kerak boʻlgan joyda tushuntiramiz.

## Struct: bir nechta maydon, bitta tur

Doʻkon mijozni eslab qolishi kerak: ismi, hisobidagi puli va manzili. Uchta alohida oʻzgaruvchi noqulay: ular
doim birga yurishi kerak. JS/TS'da buning uchun obyekt (`{ name, balance }`) va uning turi, Python'da `class` yoki
`dataclass` yozardingiz.

Go'da `class` yoʻq. Uning oʻrnida **struct**: maydonlari oldindan eʼlon qilingan tur. Har bir nomli qiymat
**maydon** (inglizcha **field**) deyiladi. JS obyektidan farqi: struct'ga ishga tushganda yangi maydon qoʻshib
boʻlmaydi, maydonlar va ularning turlari kompilyatsiyada aniq. Struct'ni [GO-1.07](/lab/youtube/go/go-1-07) dagi jadval
testida `[]struct{ … }` koʻrinishida koʻrgan edik. Bugun unga oʻz nomini beramiz.

Bu kurs papkasidagi `literal/main.go`:

```go filename="literal/main.go" showLineNumbers
// literal: struct e'lon qilish, composite literal, zero value va embedding.
package main

import "fmt"

type Manzil struct {
	Shahar string
	Kocha  string
}

type Mijoz struct {
	Ism    string
	Balans int64 // tiyinda
	Manzil       // embedding: tur nomi (Manzil) maydon nomi ham boʻladi
}

func main() {
	// kalitli literal: maydon nomi bilan, tartib muhim emas; Manzil yozilmadi -> zero value
	a := Mijoz{Ism: "Aziza", Balans: 50_000}
	fmt.Printf("%+v\n", a)

	// var: hamma maydon zero value oladi
	var b Mijoz
	fmt.Printf("%+v\n", b)

	// embedding: Manzil'ning maydonlari Mijoz'ga "koʻtariladi"
	a.Shahar = "Samarqand"
	fmt.Println(a.Shahar, a.Manzil.Shahar)
}
```

Diqqat: bu darsda «manzil» soʻzi ikki maʼnoda keladi. `Manzil` turi — mijozning pochta manzili (shahar, koʻcha).
Pastdagi «xotira manzili» esa qiymat xotirada qayerda turgani ([GO-1.05](/lab/youtube/go/go-1-05) dagi `&x`).

19-qatordagi yozuv `Mijoz{ … }` **composite literal** deyiladi: struct qiymatini kodning oʻzida, jingalak qavs
ichida yozish. Koʻrinishi JS'dagi obyekt literaliga oʻxshaydi, lekin oldida tur nomi turadi. Qavs ichida
`maydon: qiymat` juftlari turadi. Bunday maydon nomi bilan yozilgan literal **kalitli**
literal deyiladi, unda maydonlar tartibi muhim emas: `Mijoz{Balans: 50_000, Ism: "Aziza"}` ham aynan shu qiymat.
Bu yerda `Manzil` umuman yozilmadi. Go'ning rasmiy qoidasiga koʻra, yozilmagan maydon zero value oladi.

Ishga tushirishdan oldin oʻylab koʻring: ikkinchi qatorda (`var b Mijoz`) nima chiqadi?
**A)** `{Ism: Balans:0 Manzil:{Shahar: Kocha:}}` · **B)** `<nil>` · **C)** kompilyatsiya xatosi: `b` ga qiymat
berilmagan

<details>
<summary>Javob</summary>

**A.** `var` bilan eʼlon qilingan struct'da **hamma** maydon zero value oladi: matnlar boʻsh (`Ism:` dan keyin
hech narsa yoʻq), son `0`. Ichki `Manzil` struct'ining maydonlari ham boʻsh matn. JS'dagi `undefined` ga oʻxshash
holat yoʻq. «B» ni tanlagan boʻlsangiz: struct qiymati `null` boʻlmaydi, u doim maydonlari bilan turadi. «C» emas: [GO-1.02](/lab/youtube/go/go-1-02) da
koʻrganimizdek, Go qiymat berilmagan oʻzgaruvchini zero value bilan toʻldiradi, xato bermaydi.

</details>

```console
$ go run ./literal
{Ism:Aziza Balans:50000 Manzil:{Shahar: Kocha:}}
{Ism: Balans:0 Manzil:{Shahar: Kocha:}}
Samarqand Samarqand
```

Birinchi qatorda Azizaning ismi va balansi bor, manzili esa boʻsh. Ikkinchi qatorda hamma maydon zero value.
Xotirada ikkala qiymat shunday:

| Maydon | `a` (literal bilan) | `b` (`var` bilan) |
|---|---|---|
| `Ism` | `"Aziza"` | `""` |
| `Balans` | `50000` | `0` |
| `Manzil.Shahar` | `""` | `""` |
| `Manzil.Kocha` | `""` | `""` |

## Embedding: ichki struct maydonlari tashqariga koʻtariladi

`Mijoz` ning 14-qatorida maydon nomi alohida yozilmagan, faqat `Manzil` turi turibdi. Bunday maydon **embedded
field** («joylashtirilgan maydon») deyiladi, usulning oʻzi esa **embedding**. Maydon nomi baribir bor: tur nomining
oʻzi maydon nomi boʻladi. Shuning uchun 28-qatordagi `a.Manzil.Shahar` ishlaydi.

Uchinchi qatorni oldindan taxmin qilsak boʻladi. 27-qatorda `a.Shahar` ga yozdik, lekin `Mijoz` da `Shahar`
degan maydon yoʻq-ku. 28-qator nima chiqaradi? **A)** `Samarqand` va boʻsh joy · **B)** `Samarqand Samarqand` ·
**C)** kompilyatsiya xatosi: `Mijoz` da `Shahar` yoʻq

<details>
<summary>Javob</summary>

**B: `Samarqand Samarqand`** (natija yuqorida, uchinchi qator). Ichki struct'ning maydonlari tashqi struct'ga
«koʻtariladi» (Go'ning rasmiy qoidasida *promoted*): `a.Shahar` aslida `a.Manzil.Shahar` ning qisqa yozuvi.
Ikkalasi bitta katak, shuning uchun ikki marta `Samarqand`. «A» ni tanlagan boʻlsangiz, ularni ikki xil maydon
deb oʻylagansiz. «C» emas: koʻtarilgan maydon tashqi struct'ning oʻz maydonidek ishlatiladi.

</details>

```text
a (Mijoz)
├─ Ism      "Aziza"
├─ Balans   50000
└─ Manzil   (Manzil turi)
   ├─ Shahar   "Samarqand"   ← a.Shahar ham, a.Manzil.Shahar ham shu katak
   └─ Kocha    ""
```

Bu meros emas: JS/TS'dagi `class Mijoz extends Manzil` yoki Python'dagi `class Mijoz(Manzil)` ga teng emas.
`Mijoz` `Manzil` turiga aylanmaydi, unga faqat `Manzil` ning maydonlari koʻtariladi. Go'ning
rasmiy qoʻllanmasi (Effective Go) ham shuni yozadi: embedding boshqa tillardagi meros olishdan (subclassing)
muhim jihatdan farq qiladi. Buni «Koʻp uchraydigan xatolar» da xato xabari bilan koʻramiz. Turga biriktirilgan
funksiyalar (metodlar) ham xuddi shunday koʻtariladi. Buni [GO-1.12](/lab/youtube/go/go-1-12) da koʻramiz.

## Boshidagi jumboq: bir xil maydonlar, 24 va 16 bayt

Endi struct'ning xotirada qanday turishiga qaraymiz. Bu `olcham/main.go`:

```go filename="olcham/main.go" showLineNumbers
// olcham: maydonlari bir xil ikki struct, lekin oʻlchami har xil.
package main

import (
	"fmt"
	"unsafe"
)

// Buyurtma: maydonlar "mantiqiy" tartibda yozilgan.
type Buyurtma struct {
	Tolandi    bool  // toʻlandimi?
	Summa      int64 // tiyinda
	Yetkazildi bool  // yetkazildimi?
}

// Ixcham: xuddi shu uchta maydon, faqat tartibi boshqa.
type Ixcham struct {
	Summa      int64
	Tolandi    bool
	Yetkazildi bool
}

func main() {
	fmt.Println("Buyurtma:", unsafe.Sizeof(Buyurtma{}), "bayt")
	fmt.Println("Ixcham:  ", unsafe.Sizeof(Ixcham{}), "bayt")
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 4–7 | `import ( "fmt" "unsafe" )` | ikkita paket. `unsafe` — Go bilan birga keladigan past darajadagi paket, biz undan faqat oʻlchash uchun foydalanamiz ([GO-1.08](/lab/youtube/go/go-1-08) da ham shunday qilgan edik) |
| 10–14 | `type Buyurtma struct { … }` | `Buyurtma` («buyurtma»): `Tolandi` («toʻlandi», `bool`), `Summa` («summa», `int64`, tiyinda), `Yetkazildi` («yetkazildi», `bool`) |
| 17–21 | `type Ixcham struct { … }` | `Ixcham` («ixcham»): xuddi shu uchta maydon, faqat `Summa` birinchi turibdi |
| 24 | `unsafe.Sizeof(Buyurtma{})` | `Buyurtma{}` — hamma maydoni zero value boʻlgan literal. `unsafe.Sizeof` uning oʻlchamini baytda qaytaradi |
| 25 | `unsafe.Sizeof(Ixcham{})` | xuddi shu, `Ixcham` uchun. `"Ixcham:  "` dagi boʻsh joylar ikki qatorni tekislash uchun |

Ishga tushirishdan oldin hisoblang. `bool` 1 bayt, `int64` 8 bayt. Uchta maydon jami necha bayt?

<details>
<summary>Javob</summary>

1 + 8 + 1 = **10 bayt**. Maydonlarning oʻzi shuncha joy oladi. Endi Go nima deyishini koʻramiz.

</details>

```console
$ go run ./olcham
Buyurtma: 24 bayt
Ixcham:   16 bayt
```

10 emas! `Buyurtma` 24 bayt, `Ixcham` 16 bayt. Maydonlar bir xil, faqat tartibi boshqa. Demak, ortiqcha 14 va 6
bayt maydonlarning oʻzidan emas, ularning **joylashuvidan** keladi. Qaysi bayt qayerda turganini koʻrish uchun
oʻlchov asboblari kerak.

## Struct ichini oʻlchaymiz: Sizeof, Alignof, Offsetof

`unsafe` paketidan uchta funksiya olamiz:

```go
var x Buyurtma

unsafe.Sizeof(x)         // 24: jami, padding bilan
unsafe.Alignof(x)        // 8: manzil 8 ga karrali
unsafe.Offsetof(x.Summa) // 8: boshidan 8 bayt narida
```

- **`unsafe.Sizeof`** turning necha bayt ekanini aytadi, boʻsh baytlar bilan birga. Uning hujjatida: *"For a
  struct, the size includes any padding introduced by field alignment"* — «struct uchun oʻlchamga tekislash
  sababli qoʻshilgan padding ham kiradi».
- **`unsafe.Alignof`** qiymatning xotira manzili nechaga karrali boʻlishi kerakligini aytadi. «8 ga karrali» —
  8 ga qoldiqsiz boʻlinadi: 0, 8, 16, 24…
- **`unsafe.Offsetof`** maydon struct boshidan necha bayt narida turganini aytadi. Bu son inglizcha **offset**
  deyiladi. Birinchi maydonning offset'i doim 0.

Bu sonlardan har bir baytning xaritasini chizish mumkin. Buni `xarita/main.go` qiladi:

```go filename="xarita/main.go" showLineNumbers
// xarita: har bir maydon struct ichida qayerda turadi (Offsetof) va
// orada nechta boʻsh bayt (padding) bor.
package main

import (
	"fmt"
	"strings"
	"unsafe"
)

type Buyurtma struct {
	Tolandi    bool
	Summa      int64
	Yetkazildi bool
}

type Ixcham struct {
	Summa      int64
	Tolandi    bool
	Yetkazildi bool
}

type maydon struct {
	harf           string
	offset, olcham uintptr
}

// chiz: har bir bayt uchun bitta belgi; maydon harfi yoki "·" (padding).
func chiz(nom string, jami, align uintptr, mm ...maydon) {
	b := []string{}
	for range jami {
		b = append(b, "·")
	}
	for _, m := range mm {
		for i := m.offset; i < m.offset+m.olcham; i++ {
			b[i] = m.harf
		}
	}
	fmt.Printf("%-9s %2d bayt, align %d  [%s]\n", nom, jami, align, strings.Join(b, ""))
}

func main() {
	var x Buyurtma
	chiz("Buyurtma", unsafe.Sizeof(x), unsafe.Alignof(x),
		maydon{"T", unsafe.Offsetof(x.Tolandi), unsafe.Sizeof(x.Tolandi)},
		maydon{"S", unsafe.Offsetof(x.Summa), unsafe.Sizeof(x.Summa)},
		maydon{"Y", unsafe.Offsetof(x.Yetkazildi), unsafe.Sizeof(x.Yetkazildi)})

	var y Ixcham
	chiz("Ixcham", unsafe.Sizeof(y), unsafe.Alignof(y),
		maydon{"S", unsafe.Offsetof(y.Summa), unsafe.Sizeof(y.Summa)},
		maydon{"T", unsafe.Offsetof(y.Tolandi), unsafe.Sizeof(y.Tolandi)},
		maydon{"Y", unsafe.Offsetof(y.Yetkazildi), unsafe.Sizeof(y.Yetkazildi)})
}
```

Bir xil uchta maydon, lekin oʻlcham har xil. Nuqtalar — boʻsh baytlar. Ular hech narsa saqlamaydi, faqat keyingi
maydonni toʻgʻri joyga surish uchun turadi. Bunday baytlar oʻzbekcha **boʻsh baytlar**, inglizcha **padding**
deyiladi.

| Baytlar | Nima turadi | Nega |
|---|---|---|
| 0 | `T` (`Tolandi`, `bool`) | birinchi maydon, offset 0 |
| 1–7 | padding, 7 bayt | `Summa` 8 ga karrali manzildan boshlanishi kerak |
| 8–15 | `S` (`Summa`, `int64`) | offset 8 |

6 bayt.

## Nega boʻsh joy kerak: tekislash qoidasi

Protsessor xotirani bittalab bayt bilan emas, **boʻlaklab** oʻqiydi: 4 yoki 8 baytli soʻzlar bilan (keshga esa
undan ham katta boʻlaklar bilan). 8 baytli son 8 ga karrali manzilda tursa, u bitta boʻlakka toʻliq sigʻadi va
bitta oʻqish yetadi. 5-baytdan boshlansa, u ikki boʻlakka boʻlinadi: protsessor ikkita boʻlakni oʻqib, sonni
yigʻishi kerak boʻladi yoki baʼzi protsessorlarda umuman oʻqiy olmaydi.

Karnegi Mellon universiteti (CMU) kursida qoida shunday yozilgan:

- K baytli oddiy qiymat K ga karrali manzilda turishi kerak: 8 baytli qiymat — 8 ga karrali manzilda;
- 4 baytli qiymat — 4 ga karrali manzilda.

Shunda bitta qiymat ikki boʻlak chegarasini kesib oʻtmaydi. Qiymatni shunday joylash oʻzbekcha **tekislash**,
inglizcha **alignment** deyiladi. Slaydda: *"Required on some machines; advised on IA32"* — «baʼzi mashinalarda
majburiy; IA32 da (32 bitli Intel protsessorlarida) tavsiya etiladi». Intel protsessorlari tekislanmagan qiymatni ham
oʻqiy oladi. Lekin Intel'ning oʻzi unumdorlik uchun tekislashni tavsiya qiladi (CS:APP darsligi, §3.9.3).

Go'ning rasmiy qoidasi (spec) struct uchun kafolat beradi: struct'ning alignment'i **maydonlar alignment'larining
eng kattasiga** teng. `Buyurtma` da bu `max(1, 8, 1) = 8`. Kompilyator esa struct oʻlchamini shu songa karrali
qilib yaxlitlaydi. Shuning uchun `Buyurtma` ning oxirida yana 7 bayt bor.

Nega oxiridagi baytlar kerak? Struct'lar massivini ([GO-1.08](/lab/youtube/go/go-1-08)) eslang: elementlar ketma-ket
turadi. Agar `Buyurtma` 24 emas, 17 bayt boʻlganida edi:

| Element | Boshlanishi (24 bayt) | `Summa` (24 bayt) | Boshlanishi (17 boʻlsa) | `Summa` (17 boʻlsa) |
|---|---|---|---|---|
| `[0]` | 0 | 8 ✓ | 0 | 8 ✓ |
| `[1]` | 24 | 32 ✓ | 17 | 25 ✗ |
| `[2]` | 48 | 56 ✓ | 34 | 42 ✗ |

17 baytli variantda keyingi elementning `int64` i 8 ga karrali boʻlmagan manzilga tushardi. Oxiridagi padding
massivdagi har bir elementni toʻgʻri joyda ushlab turadi.

Bir tuzoq: «eng katta maydonning alignment'i» emas, «maydonlar alignment'larining eng kattasi». 16 baytli
maydon ham alignment'i 1 boʻlishi mumkin. Buni «Koʻp uchraydigan xatolar» da tekshiramiz.

## Pauza: bool, int32, bool

Endi bitta misolni oʻzingiz hisoblang. `int32` — 4 baytli butun son, uning alignment'i 4.

```go
type Savol struct {
	A bool
	B int32
	C bool
}
```

Bu struct necha bayt boʻladi? Uni qanday qilib kichraytirish mumkin? Baytlarni qogʻozga chizib koʻring.

<details>
<summary>Javob</summary>

**12 bayt.** `A` 0-baytda. `B` (`int32`) 4 ga karrali manzildan boshlanadi, shuning uchun `A` dan keyin 3 bayt
boʻsh qoladi: `B` 4–7-baytlarda. `C` 8-baytda. Jami 9, lekin struct'ning alignment'i 4, oʻlcham 4 ga karrali
boʻlishi kerak: oxiriga yana 3 bayt qoʻshiladi, **12**.

`int32` ni boshiga qoʻysak: 4 + 1 + 1 = 6, 4 ga karralisi **8**. Struct 8 baytga tushadi.

Agar 6 deb hisoblagan boʻlsangiz, padding'ni unutgansiz. 9 deb hisoblagan boʻlsangiz, oxiridagi yaxlitlashni
unutgansiz.

</details>

Javobni `savol/main.go` tekshiradi. U `xarita/main.go` bilan deyarli bir xil:

```go filename="savol/main.go" showLineNumbers
// savol: pauzadagi savolning javobi. bool, int32, bool: necha bayt?
package main

import (
	"fmt"
	"strings"
	"unsafe"
)

type Savol struct {
	A bool
	B int32
	C bool
}

type Javob struct {
	B int32
	A bool
	C bool
}

type maydon struct {
	harf           string
	offset, olcham uintptr
}

func chiz(nom string, jami, align uintptr, mm ...maydon) {
	b := []string{}
	for range jami {
		b = append(b, "·")
	}
	for _, m := range mm {
		for i := m.offset; i < m.offset+m.olcham; i++ {
			b[i] = m.harf
		}
	}
	fmt.Printf("%-6s %2d bayt, align %d  [%s]\n", nom, jami, align, strings.Join(b, ""))
}

func main() {
	var x Savol
	chiz("Savol", unsafe.Sizeof(x), unsafe.Alignof(x),
		maydon{"A", unsafe.Offsetof(x.A), unsafe.Sizeof(x.A)},
		maydon{"B", unsafe.Offsetof(x.B), unsafe.Sizeof(x.B)},
		maydon{"C", unsafe.Offsetof(x.C), unsafe.Sizeof(x.C)})
	var y Javob
	chiz("Javob", unsafe.Sizeof(y), unsafe.Alignof(y),
		maydon{"B", unsafe.Offsetof(y.B), unsafe.Sizeof(y.B)},
		maydon{"A", unsafe.Offsetof(y.A), unsafe.Sizeof(y.A)},
		maydon{"C", unsafe.Offsetof(y.C), unsafe.Sizeof(y.C)})
}
```

Faqat turlar boshqa: `Savol` (`A`, `B`, `C`) va qayta tartiblangan `Javob` («javob»: `B`, `A`, `C`). 37-qatorda
nomlar qisqa, shuning uchun `%-6s`. `chiz` funksiyasi `xarita/` dagining oʻzi.

```console
$ go run ./savol

Javob   8 bayt, align 4  [BBBBAC··]
```

	"fmt"
	"runtime"

	Tolandi    bool

	Yetkazildi bool

func ajratildi(f func()) uint64 {

	runtime.ReadMemStats(&a)
	f()

}

	s1 []Buyurtma
	s2 []Ixcham

// faqat xotiradan oʻqiladigan baytlar soni har xil.
// Ikkala variant navbatma-navbat 100 marta oʻlchanadi va eng yaxshi
// natija olinadi: kompyuterda boshqa ish ketayotgan boʻlsa ham shovqin kam.
package main

import (
	"fmt"
	"os"
	"strconv"
	"time"
)

type Buyurtma struct {
	Tolandi    bool
	Summa      int64
	Yetkazildi bool
}

type Ixcham struct {
	Summa      int64
	Tolandi    bool
	Yetkazildi bool
}

var natija int64 // kompilyator hisobni oʻchirib tashlamasin

func jami1(s []Buyurtma) (j int64) {
	for i := range s {
		if s[i].Tolandi {
			j += s[i].Summa
		}
	}
	return j
}

func jami2(s []Ixcham) (j int64) {
	for i := range s {
		if s[i].Tolandi {
			j += s[i].Summa
		}
	}
	return j
}

// vaqt: f ni bir marta ishlatib, ketgan vaqtni qaytaradi.
func vaqt(f func()) time.Duration {
	t := time.Now()
	f()
	return time.Since(t)
}

func main() {
	n := 1_000_000 // go run ./tezlik 100000 — boshqa oʻlcham
	if len(os.Args) > 1 {
		n, _ = strconv.Atoi(os.Args[1])

	s2 := make([]Ixcham, n)
	for i := range n {
		s1[i] = Buyurtma{Tolandi: i%2 == 0, Summa: int64(i)}
		s2[i] = Ixcham{Tolandi: i%2 == 0, Summa: int64(i)}
	}
	eng1, eng2 := time.Hour, time.Hour
	for range 100 {
		eng1 = min(eng1, vaqt(func() { natija += jami1(s1) }))
		eng2 = min(eng2, vaqt(func() { natija += jami2(s2) }))
	}
	fmt.Printf("n = %d\n", n)
	fmt.Printf("Buyurtma: %.1f µs\n", eng1.Seconds()*1e6)
	fmt.Printf("Ixcham:   %.1f µs\n", eng2.Seconds()*1e6)
	fmt.Printf("Ixcham / Buyurtma: %.2f\n", eng2.Seconds()/eng1.Seconds())
}

## 32 bitli tizimda: GOARCH=386

Yana bir nozik joy bor: bu sonlar arxitekturaga (protsessor turiga) va kompilyator qoidalariga bogʻliq. Hozirgacha

tushirish yoqilgan boʻlsa).

## Tekislash dasturni yiqitganda: atomik amal

Bu farq dasturni yiqitishi ham mumkin. Avval yangi tushuncha. **Atomik amal** — bir nechta goroutine bir vaqtda
xavfsiz bajara oladigan amal: uni hech kim yarmida boʻlib qoʻya olmaydi. Goroutine'larni va atomik amallarni
keyingi darslarda ([GO-1.21](/lab/youtube/go#go-1-21)) koʻramiz. Hozir bitta qoida yetarli: Go'da 64 bitli sonni atomik
oshirish uchun `sync/atomic` paketi bor.

Bu `atom/main.go`:

```go filename="atom/main.go" showLineNumbers
// atom: 32-bitli tizimda int64 maydon 8 ga karrali manzilda turmasligi mumkin.
// GOARCH=386 go run ./atom — ataylab xato (panic).
package main

import (
	"fmt"
	"sync/atomic"
	"unsafe"
)

type Hisoblagich struct {
	Yoniq bool
	Soni  int64 // bir nechta goroutine atomik oshiradi
}

func main() {
	h := &Hisoblagich{}
	fmt.Println("Soni offset:", unsafe.Offsetof(h.Soni))
	atomic.AddInt64(&h.Soni, 1)
	fmt.Println("Soni:", h.Soni)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 11–14 | `type Hisoblagich struct { Yoniq bool; Soni int64 }` | `Hisoblagich` («hisoblagich»): avval `Yoniq` («yoqilgan», `bool`), keyin `Soni` («soni», `int64`) |
| 17 | `h := &Hisoblagich{}` | struct'ni yaratib, uning manzilini `h` ga yozadi (`&`). Manzil orqali ham `h.Soni` deb yozish mumkin; buni [GO-1.11](/lab/youtube/go/go-1-11) da ochamiz |
| 18 | `unsafe.Offsetof(h.Soni)` | `Soni` struct boshidan necha bayt narida |
| 19 | `atomic.AddInt64(&h.Soni, 1)` | `Soni` ning manziliga borib, unga atomik ravishda 1 qoʻshadi |
| 20 | `fmt.Println("Soni:", h.Soni)` | natijani chiqaradi |

64 bitli kompyuterda bu dastur `Soni offset: 8` va `Soni: 1` chiqaradi. 32 bitlida-chi? Buyruqdagi `2>&1` xato
chiqishini oddiy chiqish bilan birlashtiradi, `| head -2` esa faqat birinchi ikki qatorni koʻrsatadi (qolgani uzun
texnik maʼlumot).

```console
$ GOARCH=386 go run ./atom 2>&1 | head -2
Soni offset: 4
panic: unaligned 64-bit atomic operation
```

32 bitli dasturda `Soni` struct boshidan 4 bayt narida turibdi. *unaligned 64-bit atomic operation* — «tekislanmagan
64 bitli atomik amal». Bu protsessor xatosi emas: Go runtime'i manzilni oʻzi tekshiradi va 8 ga karrali boʻlmasa,
panic beradi. `sync/atomic` hujjatining «Bugs» boʻlimida yozilgan: *"On ARM, 386, and 32-bit MIPS, it is the
caller's responsibility to arrange for 64-bit alignment of 64-bit words accessed atomically"* — «ARM, 386 va 32 bitli
MIPS da atomik ishlatiladigan 64 bitli sonlarni 64 bitga tekislash chaqiruvchining (yaʼni dasturchining)
vazifasi».

Go 1.19 da yangi turlar qoʻshildi. Ulardan biri `atomic.Int64`: u har qanday tizimda 8 baytga tekislanadi. Bu
`atomfix/main.go`:

```go filename="atomfix/main.go" showLineNumbers
// atomfix: atomic.Int64 (Go 1.19+) har qanday tizimda 8 baytga tekislanadi.
package main

import (
	"fmt"
	"sync/atomic"
	"unsafe"
)

type Hisoblagich struct {
	Yoniq bool
	Soni  atomic.Int64
}

func main() {
	h := &Hisoblagich{}
	fmt.Println("Soni offset:", unsafe.Offsetof(h.Soni))
	h.Soni.Add(1)
	fmt.Println("Soni:", h.Soni.Load())
}
```

- **12-qator:** `Soni atomic.Int64` — oddiy `int64` emas, `sync/atomic` paketining maxsus turi.
- **18-qator:** `h.Soni.Add(1)` — atomik ravishda 1 qoʻshadi. `Add` — shu turga biriktirilgan funksiya (metod).
- **19-qator:** `h.Soni.Load()` — qiymatni atomik oʻqiydi.

Taxmin qiling: `GOARCH=386` da `Soni offset` nechchi boʻladi? **A)** 4 · **B)** 8 · **C)** 1

<details>
<summary>Javob</summary>

**B: 8.** Go 1.19 release notes: *"Int64 and Uint64 are automatically aligned to 64-bit boundaries in structs and
allocated data, even on 32-bit systems"* — «`Int64` va `Uint64` struct'larda va ajratilgan maʼlumotlarda, hatto 32
bitli tizimlarda ham, avtomatik 64 bitga tekislanadi». Kompilyator `Yoniq` dan keyin 7 bayt padding qoʻydi. «A» —
oddiy `int64` ning 32 bitdagi offset'i.

</details>

```console
$ GOARCH=386 go run ./atomfix
Soni offset: 8
Soni: 1
```

## Baytlarni qoʻlda sanamang: fieldalignment

Baytlarni har safar qoʻlda sanash shart emas. Go jamoasining `fieldalignment` degan analizatori (kodni ishga
tushirmasdan tekshiradigan statik tahlil vositasi, linter kabi) bor. Avval uni oʻrnatamiz:

```console
$ go install golang.org/x/tools/go/analysis/passes/fieldalignment/cmd/fieldalignment@v0.53.0
```

`go install` hech narsa chiqarmadi: oʻrnatish muvaffaqiyatli. Dastur `$(go env GOPATH)/bin/` papkasiga tushadi
([GO-1.05](/lab/youtube/go/go-1-05) dagi `staticcheck` kabi). Biz `v0.53.0` versiyasini yozdik; kurs README'sida
`@latest` turibdi, 2026-11-25 kuni u ham `v0.53.0` edi.

Endi uni birinchi dasturimizda ishga tushiramiz. Buyruq oxiridagi `2>&1 | sed "s|$PWD/||"` faqat xabardagi uzun
papka yoʻlini qisqartiradi.

```console
$ $(go env GOPATH)/bin/fieldalignment ./olcham 2>&1 | sed "s|$PWD/||"
olcham/main.go:10:15: Buyurtma has size 24 but the optimal size is 16 leading to a waste of 8 bytes (33%)
```

`olcham/main.go`, 10-qator, 15-belgi (`struct` soʻzi): *Buyurtma has size 24 but the optimal size is 16 leading
to a waste of 8 bytes (33%)* — «`Buyurtma` ning oʻlchami 24, lekin eng yaxshi oʻlcham 16: 8 bayt (33 %) behuda».
`Ixcham` haqida u hech narsa demadi: u allaqachon eng ixcham.

Lekin hujjatida ogohlantirish ham bor: *"the diagnostics produced by fieldanalyzer very rarely indicate a
significant problem, so the analyzer is not included in typical suites such as vet or gopls"* — «bu analizator
xabarlari jiddiy muammoni juda kam koʻrsatadi, shuning uchun u `go vet` yoki `gopls` kabi odatiy toʻplamlarga
kiritilmagan».

`-fix` bayrogʻi maydonlarni oʻzi tartiblaydi. Biz uni `olcham/main.go` ning nusxasida sinadik (bu sinov kurs
papkasida yoʻq: faylni alohida papkaga, `go 1.26` qatorli oʻz `go.mod` fayli bilan koʻchirdik):

```console
$ $(go env GOPATH)/bin/fieldalignment -fix .
```

U hech narsa chiqarmadi. `sed -n 10,14p main.go` faylning 10–14-qatorlarini chiqaradi:

```console
$ sed -n 10,14p main.go
type Buyurtma struct {
	Summa      int64
	Tolandi    bool
	Yetkazildi bool
}
```

Tartib toʻgʻri, lekin maydonlar yonidagi izohlar (`// toʻlandimi?`, `// tiyinda`, `// yetkazildimi?`) yoʻqoldi.
`-fix` ni ishlatsangiz, keyin faylni albatta koʻzdan kechiring.

## Qachon tartiblash kerak

Xoʻsh, har bir struct'ni qayta tartiblash kerakmi? Koʻp hollarda kerak emas.

| Holat | Nima qilish kerak |
|---|---|
| bitta struct, 8 bayt farq | ahamiyatsiz: oʻqish oson tartibni qoldiring |
| millionlab nusxasi xotirada turadigan struct (katta slice'lar, kesh yozuvlari) | oʻlchang, kerak boʻlsa tartiblang |
| avval | oʻqish oson boʻlgan tartibda yozing |
| keyin | oʻlchang va kerak boʻlsagina tartibni oʻzgartiring |

Dave Cheney 2015-yilgi «Padding is hard» maqolasida xuddi shunday yozgan: *"Do Go programmers need to care about
this minutiae ? Probably not."* — «Go dasturchilariga bu mayda-chuydalar kerakmi? Ehtimol, yoʻq».

Yana bir istisno bor. Protsessor kesh bilan baytlab emas, **cache line** (kesh qatori) deb ataladigan 64 baytli
boʻlaklar bilan ishlaydi (bu kompyuterda 64). Ixcham tartib baʼzan ikki goroutine'ning oʻzgaruvchilarini bitta
cache line'ga joylaydi. Bir goroutine oʻz oʻzgaruvchisiga yozsa, ikkinchi yadrodagi shu qatorning nusxasi
eskiradi. Bu **false sharing** («soxta boʻlishish») deyiladi va ikkalasini ham sekinlashtiradi. `fieldalignment`
hujjati ham shuni ogohlantiradi: *"the most compact order is not always the most efficient"* — «eng ixcham tartib
doim eng samarali emas». Buni Guru uy vazifasida oʻlchaysiz.

## Chuqurroq (ixtiyoriy): spec nimani vaʼda qiladi

Bu boʻlim videoda yoʻq, u kurs README'sidan.

- Go'ning rasmiy qoidasi faqat minimal kafolat beradi: sonli turlarning oʻlchami va struct alignment'i
  (maydonlar alignment'larining eng kattasi). Maydonlarni manbadagi tartibda joylash — `gc` kompilyatorining
  amaldagi xatti-harakati.
- Spec maydonlar tartibini vaʼda qilmaydi. Go jamoasidan Robert Griesemer
  [golang/go#10014](https://github.com/golang/go/issues/10014) da: *"Currently, the spec does not specify how
  struct fields are laid out in memory"* — «hozircha spec struct maydonlari xotirada qanday joylashishini
  belgilamaydi». Lekin mavjud struct'lardagi maydonlarni kompilyator oʻzi qayta tartiblashi rad etilgan.
- C tili bilan bir xil joylashuv kerak boʻlsa, Go 1.23 dan beri [`structs.HostLayout`](https://pkg.go.dev/structs#HostLayout)
  belgisi bor.
- 32 bitli Linux'da C ham 8 baytli `double` (kasr son) uchun 4 baytlik tekislashni ishlatgan (CMU slaydi, IA32).
  Go ham `GOARCH=386` da `int64` ni shunday joylaydi.

Papkada `go test` bilan oʻlchaydigan benchmark ham bor. Bu `million/bench_test.go`:

```go filename="million/bench_test.go" showLineNumbers

```

## Koʻp uchraydigan xatolar

**1. Struct oʻlchami = maydonlar oʻlchamlari yigʻindisi deb oʻylash.** Bu darsning asosiy tuzogʻi, «Boshidagi
jumboq» boʻlimida koʻrdik: `bool + int64 + bool` 10 emas, 24 bayt. Xato xabari yoʻq, faqat xotira ortiqcha
sarflanadi. **Tuzatish:** oʻlchamni `unsafe.Sizeof` bilan tekshiring yoki `fieldalignment` ni ishga tushiring.
Millionlab nusxa boʻlsa, alignment'i katta maydonlarni boshiga qoʻying.

**2. «Struct alignment'i = eng katta maydonning alignment'i» deb oʻylash.** Bu misol kurs papkasida yoʻq, u alohida
ishga tushirildi:

```go
package main

import (
	"fmt"
	"unsafe"
)

type Katta struct {
	A [16]byte
	B int32
}

func main() {
	var k Katta
	fmt.Println("Sizeof:", unsafe.Sizeof(k), "Alignof:", unsafe.Alignof(k))
}
```

`[16]byte` — 16 baytli massiv, bu struct'dagi eng katta maydon.

```console
$ go run engkatta/main.go
Sizeof: 20 Alignof: 4
```

Eng katta maydon 16 bayt, lekin alignment 4. `[16]byte` ning alignment'i 1 (u baytlardan iborat), `int32` niki 4.
Qoida: maydonlar alignment'larining **eng kattasi**, `max(1, 4) = 4`. **Tuzatish:** har bir maydonning
alignment'iga qarang, oʻlchamiga emas.

**3. Kalitsiz literalda maydonni tashlab ketish.** Maydon nomisiz literalda hamma maydon tartib bilan yozilishi
kerak (kurs papkasida yoʻq):

```go
package main

import "fmt"

type Mijoz struct {
	Ism    string
	Balans int64
	Shahar string
}

func main() {
	a := Mijoz{"Aziza", 50_000}
	fmt.Println(a)
}
```

```console
$ go run kalitsiz/main.go
# command-line-arguments
kalitsiz/main.go:12:28: too few values in struct literal of type Mijoz
```

12-qator, 28-belgi: *too few values in struct literal of type Mijoz* — «`Mijoz` turidagi struct literalida qiymatlar
juda kam». Struct'da uchta maydon, biz ikkitasini yozdik. Kalitsiz literal struct'ga yangi maydon qoʻshilsa ham
shunday buziladi. **Tuzatish:** kalitli literal yozing: `Mijoz{Ism: "Aziza", Balans: 50_000}`. Yozilmagan
`Shahar` zero value oladi.

**4. Struct'da yoʻq maydonni yozish.** (Kurs papkasida yoʻq.)

```go
package main

import "fmt"

type Mijoz struct {
	Ism    string
	Balans int64
}

func main() {
	a := Mijoz{Ism: "Aziza", Yosh: 20}
	fmt.Println(a)
}
```

```console
$ go run nomalum/main.go
# command-line-arguments
nomalum/main.go:11:27: unknown field Yosh in struct literal of type Mijoz
```

*unknown field Yosh in struct literal of type Mijoz* — «`Mijoz` turidagi struct literalida nomaʼlum `Yosh` maydoni».
`Mijoz` da `Yosh` («yosh») maydoni eʼlon qilinmagan. **Tuzatish:** maydonni struct turiga qoʻshing yoki nomini
toʻgʻrilang.

**5. Embedding'ni meros deb oʻylash.** `Mijoz` ichida `Manzil` bor, lekin `Mijoz` `Manzil` emas (kurs papkasida yoʻq):

```go
package main

import "fmt"

type Manzil struct {
	Shahar string
}

type Mijoz struct {
	Ism string
	Manzil
}

func chop(m Manzil) {
	fmt.Println(m.Shahar)
}

func main() {
	a := Mijoz{Ism: "Aziza", Manzil: Manzil{Shahar: "Buxoro"}}
	chop(a)
}
```

```console
$ go run meros/main.go
# command-line-arguments
meros/main.go:20:7: cannot use a (variable of struct type Mijoz) as Manzil value in argument to chop
```

20-qator, 7-belgi: *cannot use a (variable of struct type Mijoz) as Manzil value in argument to chop* — «`a` ni
(`Mijoz` turidagi oʻzgaruvchini) `chop` ga argument sifatida `Manzil` qiymati oʻrnida ishlatib boʻlmaydi».
Maydonlar koʻtariladi, tur esa oʻzgarmaydi. **Tuzatish:** ichki struct'ni oʻzini bering: `chop(a.Manzil)`.

**6. 32 bitli tizimda oddiy `int64` ni atomik oshirish.** «Tekislash dasturni yiqitganda» boʻlimida koʻrdik:
`bool` dan keyingi `int64` ga `atomic.AddInt64` `GOARCH=386` da panic beradi. 64 bitli kompyuterda xato
koʻrinmaydi, shuning uchun u yashirin qoladi. **Tuzatish:** `atomic.Int64` turini ishlating (Go 1.19+).

**7. `fieldalignment -fix` dan keyin faylni tekshirmaslik.** Bizning sinovda u maydon izohlarini oʻchirib yubordi
(«Baytlarni qoʻlda sanamang» boʻlimi). **Tuzatish:** `-fix` dan keyin oʻzgarishlarni koʻzdan kechiring yoki
maydonlarni qoʻlda tartiblang.

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** Maydonlari bir xil boʻlsa ham, nega `Buyurtma` 24 bayt, `Ixcham` esa 16 bayt?

<details>
<summary>Javob</summary>

`int64` 8 ga karrali manzildan boshlanishi kerak. `Buyurtma` da u `bool` dan keyin turadi: orada 7 bayt padding,
oxirida yana 7 bayt (oʻlcham 8 ga karrali boʻlishi uchun). `Ixcham` da `int64` boshida, ikkala `bool` uning
ortidan keladi, boʻsh joy faqat oxirida: 6 bayt.

</details>

**2.** Bu dastur 64 bitli kompyuterda nima chiqaradi? **A)** `13` · **B)** `16` · **C)** `24`

```go
package main

import (
	"fmt"
	"unsafe"
)

type T struct {
	A int32
	B bool
	C int64
}

func main() {
	fmt.Println(unsafe.Sizeof(T{}))
}
```

<details>
<summary>Javob</summary>

**B: `16`.** `A` 0–3-baytlarda, `B` 4-baytda, keyin 3 bayt padding, `C` (`int64`) 8–15-baytlarda. 16 ning oʻzi 8
ga karrali, oxirida padding kerak emas. «A» — padding'siz yigʻindi. «C» ni tanlagan boʻlsangiz, har bir maydon 8
bayt oladi deb oʻylagansiz. (Bu dastur kurs papkasida yoʻq, alohida ishga tushirildi.)

```console
$ go run savol1/main.go
16
```

</details>

**3.** Kalitli composite literalda baʼzi maydonlarni yozmasangiz nima boʻladi?

<details>
<summary>Javob</summary>

Ular zero value oladi: son `0`, matn `""`, `bool` `false`. Kalitli literalda maydonlar tartibi ham muhim emas.

</details>

**4.** Struct'ni ixcham qilish har doim dasturni tezlashtiradimi?

<details>
<summary>Javob</summary>

Yoʻq. Bir million buyurtmada (keshga sigʻmaydi) ixcham variant taxminan beshdan bir qism tez chiqdi. Yuz mingtada
(keshga sigʻadi) farq ancha kichik, baʼzan ixcham hatto sekinroq. Avval oʻlchang.

</details>

**5.** 32 bitli tizimda bir nechta goroutine oshiradigan 64 bitli hisoblagich uchun qaysi turni tanlaysiz va nega?

<details>
<summary>Javob</summary>

`atomic.Int64`. U har qanday tizimda 8 baytga tekislanadi (Go 1.19+). Oddiy `int64` ni `386` da faqat 4 ga
karrali manzilga qoʻyish mumkin, `atomic.AddInt64` esa bunday manzilda panic beradi.

</details>

**6.** [GO-1.07](/lab/youtube/go/go-1-07) dan: benchmark funksiyasi qanday nomlanadi va uning ichidagi sikl qanday yoziladi?

<details>
<summary>Javob</summary>

`Benchmark` bilan boshlanadi va `b *testing.B` oladi: `func BenchmarkIxcham(b *testing.B)`. Oʻlchanadigan ish
`for b.Loop() { … }` ichida turadi. Fayl nomi `_test.go` bilan tugaydi, ishga tushirish: `go test -bench .`.
Bugungi `million/bench_test.go` aynan shunday.

</details>

`homework/oson/main.go`. `A` 0-baytda, 7 bayt padding, `B` 8–15, `C` 16–19, `D` 20. Jami 21, 8 ga karralisi
**24**. Ixcham tartib `B, C, A, D`: 8 + 4 + 1 + 1 = 14 → **16**.

```console
$ go run ./homework/oson
Oson:       24
OsonIxcham: 16
```

</details>

🟡 **Oʻrta:** `struct { Faol bool; Ism string; Admin bool; Yosh int32 }` uchun oʻlchamni va eng ixcham tartibni
toping.

<details>
<summary>Javob</summary>

`homework/orta/main.go`. `string` ichida ikkita narsa bor: matn baytlarining manzili (8 bayt) va uzunligi (8 bayt).
Jami 16 bayt, alignment 8. `Faol` 0, 7 bayt padding, `Ism` 8–23, `Admin` 24, 3 bayt padding, `Yosh` 28–31 →
**32**. Ixcham: `Ism, Yosh, Faol, Admin` = 16 + 4 + 1 + 1 = 22 → **24**. `fieldalignment` ham shuni aytadi.

```console
$ go run ./homework/orta
string: 16 bayt, align 8
Foydalanuvchi:       32
FoydalanuvchiIxcham: 24
```

</details>

🟠 **Qiyin:** boʻsh struct `struct{}` 0 bayt. Nega `struct { A int64; B struct{} }` 16 bayt, `struct \{ B struct\{\};
A int64 \}` esa 8?

<details>
<summary>Javob</summary>

`homework/qiyin/main.go`. Oxirgi 0 baytli maydonning manzili (`&x.B`) struct'dan keyingi baytga, yaʼni boshqa
obyektga ishora qilmasligi kerak. Aks holda garbage collector (keraksiz xotirani tozalovchi) u obyektni ham
«tirik» deb oʻylashi mumkin edi. Shuning uchun kompilyator oxiridagi 0 baytli maydonga 1 bayt qoʻshadi, keyin
8 ga yaxlitlaydi: 9 → **16** (`cmd/compile/internal/types/size.go`, issue 9401). Boshida boʻlsa, qoʻshimcha bayt
kerak emas: **8**.

```console
$ go run ./homework/qiyin
struct{}: 0
Oxirida:  16
Boshida:  8
```

</details>

🔴 **Guru** (goroutine'larni oʻrgangandan keyin): ikki goroutine har biri oʻz `atomic.Int64` hisoblagichini
oshiradi. Hisoblagichlar yonma-yon turgan va orasida 64 bayt boʻlgan holat uchun benchmark yozing va solishtiring.

<details>
<summary>Javob</summary>
