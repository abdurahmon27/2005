## Nimani oʻrganasiz

Go'ning rasmiy FAQ sahifasida bugun ham shunday jumla turibdi: *"We do not anticipate that Go will ever add generic
methods"* — «Go'ga generic metodlar qoʻshilishini kutmaymiz». Lekin Go 1.27 ularni qoʻshdi. Bitta fayl Go 1.26 da
sintaksis xatosi, Go 1.27 da esa ishlaydi. Faqat bitta shart bor, va oʻsha FAQ bu shartni hali ham «qabul qilib
boʻlmaydi» deb ataydi. Qanday shart, va nega Go jamoasi aynan uni tanladi?

**Bitta gʻoya:** type parameter bir xil kodni turli turlar uchun bir marta yozish uchun, interface esa xulq uchun.
Go 1.27 da metodlar ham generic boʻldi, lekin generic metod hech qanday interface'ni bajarmaydi.

Dars oxirida siz:

- type parameter va constraint yoza olasiz, `~` nima uchun kerakligini va `cmp.Ordered` qanday tuzilganini bilasiz;
- Go 1.27 generic metodini yoza olasiz va u qachon kompilyatsiya boʻlmasligini (`go.mod`, interface) oldindan
  ayta olasiz;
- generic kod qachon ortiqcha ekanini uchta hid boʻyicha taniysiz va uni interface yoki oddiy funksiyaga
  aylantira olasiz;
- «generic interface'dan tezroq» degan fikrni benchmark, `-gcflags=-m` va `go tool nm` bilan tekshira olasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| type parameter | funksiya yoki tur eʼlonida kvadrat qavs ichidagi tur nomi (`T`); qaysi tur boʻlishini chaqiruv hal qiladi | type parameter |
| constraint | type parameter qaysi turlar boʻla olishini cheklaydigan interface (`cmp.Ordered`) | constraint |
| generic metod | oʻz type parametrini eʼlon qiladigan metod: `func (r Royxat[T]) Aylantir[U any](…)` (Go 1.27+) | generic method |

Yoʻl-yoʻlakay ikkita yordamchi soʻz ham uchraydi: **type inference** (kompilyator turni argumentlardan oʻzi topadi)
va **instantiation** (`T` oʻrniga aniq tur qoʻyiladi). Ikkalasini birinchi dasturda koʻramiz.

## Jumboq: FAQ «hech qachon» deydi, Go 1.27 ishga tushiradi

`hook/` papkasidagi dastur. Hozircha har bir qatorni toʻliq tushunish shart emas: `[T any]` va `[U any]` ni keyingi
boʻlimlarda ochamiz.

```go filename="hook/main.go" showLineNumbers
// hook: Go 1.27 dagi generic metod. Xuddi shu fayl ../eski da (go 1.26) kompilyatsiya boʻlmaydi.
// go run ./hook
package main

import "fmt"

type Royxat[T any] []T

// Aylantir har bir elementga f ni qoʻllaydi.
// U — metodning oʻz type parametri: Go 1.27 dan beri mumkin.
func (r Royxat[T]) Aylantir[U any](f func(T) U) Royxat[U] {
	natija := make(Royxat[U], len(r))
	for i, x := range r {
		natija[i] = f(x)
	}
	return natija
}

func main() {
	summalar := Royxat[int64]{150000, 99000, 42000}
	matn := summalar.Aylantir(func(s int64) string {
		return fmt.Sprintf("%d soʻm", s)
	})
	fmt.Println(matn)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7 | `type Royxat[T any] []T` | `Royxat` (roʻyxat) — elementlari `T` turida boʻlgan slice turi; `T` — type parameter, `any` — istalgan tur |
| 11 | `func (r Royxat[T]) Aylantir[U any](f func(T) U) Royxat[U]` | metod nomidan keyin oʻz kvadrat qavsi: `U` — metodning **oʻz** type parametri. `f` har bir `T` ni `U` ga aylantiradi, natija — `Royxat[U]` |
| 12 | `natija := make(Royxat[U], len(r))` | `r` bilan bir xil uzunlikdagi yangi slice, elementlari `U` |
| 13–15 | `for i, x := range r { natija[i] = f(x) }` | har bir elementga `f` ni qoʻllaydi |
| 20 | `Royxat[int64]{150000, 99000, 42000}` | `T` oʻrniga `int64`: buyurtma summalari soʻmda |
| 21–23 | `summalar.Aylantir(func(s int64) string {…})` | `U` = `string`: har bir summa matnga aylanadi |
| 24 | `fmt.Println(matn)` | slice'ni `[a b c]` koʻrinishida chiqaradi |

TypeScript'da bu oddiy narsa: `Array<T>` ning `map<U>(f: (x: T) => U): U[]` metodi aynan shunday generic metod.
Go'da esa 1.27 gacha bunday metod yozib boʻlmasdi.

## Type parameter: bir xil kod, turli tur

`katta/` dagi dasturda ikkita funksiya bor. Biri ikkita butun sonning kattasini qaytaradi, ikkinchisi ikkita
satrning. Kod bir xil, faqat tur boshqa.

```go filename="katta/main.go" showLineNumbers
// katta: bir xil kod ikki marta, faqat tur boshqa → bitta generic funksiya.
// go run ./katta
package main

import (
	"cmp"
	"fmt"
)

func KattaInt(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func KattaString(a, b string) string {
	if a > b {
		return a
	}
	return b
}

// T — type parameter, cmp.Ordered — uning constraint'i.
func Katta[T cmp.Ordered](a, b T) T {
	if a > b {
		return a
	}
	return b
}

func main() {
	fmt.Println(Katta(3, 7), Katta(1.5, 0.5), Katta("olma", "nok"))
	fmt.Println(Katta[int64](150000, 99000))
	fmt.Println(KattaInt(3, 7), KattaString("olma", "nok"))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 6 | `"cmp"` | standart kutubxonadagi `cmp` paketi (Go 1.21+): `cmp.Ordered` shu yerda |
| 10–15 | `func KattaInt(a, b int) int` | `int` uchun: `a > b` boʻlsa `a`, aks holda `b` |
| 17–22 | `func KattaString(a, b string) string` | aynan shu kod, faqat `string` uchun (satrlar alifbo tartibida solishtiriladi) |
| 25 | `func Katta[T cmp.Ordered](a, b T) T` | kvadrat qavsda `T` — **type parameter**; `cmp.Ordered` — **constraint**: `T` faqat `<` va `>` bilan solishtiriladigan tur boʻla oladi |
| 26–29 | `if a > b { return a }; return b` | tana oldingi ikkitasi bilan bir xil |
| 33 | `Katta(3, 7), Katta(1.5, 0.5), Katta("olma", "nok")` | uch chaqiruv, uch xil tur, turni yozmadik |
| 34 | `Katta[int64](150000, 99000)` | turni kvadrat qavsda oʻzimiz berdik |
| 35 | `KattaInt(3, 7), KattaString("olma", "nok")` | eski ikki funksiya, solishtirish uchun |

Boshqa tillarda xuddi shu funksiya (ikkalasi ham ishga tushirildi: TypeScript 5.9.3, Python 3.13):

```text
TypeScript:  function katta<T extends number | string>(a: T, b: T): T { return a > b ? a : b; }
Python 3.12+: def katta[T: (int, str)](a: T, b: T) -> T: return a if a > b else b
Go:          func Katta[T cmp.Ordered](a, b T) T { if a > b { return a }; return b }
```

TS'dagi `<T extends …>` — Go'dagi `[T constraint]`. Farq ishlashda: TS va Python turlarni faqat tekshirish uchun
ishlatadi. Ishga tushganda bitta JS yoki Python funksiyasi qoladi va istalgan qiymat oʻtadi. Go kompilyatori esa
turni oʻzi tekshiradi va mashina kodini yasaydi: `Katta(3, "nok")` umuman kompilyatsiya boʻlmaydi. PHP'da
tilning oʻzida generics yoʻq: PHPStan va Psalm `@template` izohlarini tekshiradi.

Qachon type parameter yozish kerak? Ian Lance Taylor, *When To Use Generics* (Go blog, 2022): *"avoid type
parameters until you notice that you are about to write the exact same code multiple times"* — «bir xil kodni bir
necha marta yozayotganingizni sezmaguningizcha, type parameter ishlatmang». Bizda aynan shu holat: `KattaInt` va
`KattaString`.

Oʻylab koʻring: `go run ./katta` ning birinchi qatori nima?

**A)** `7 1.5 olma` · **B)** `7 1.5 nok` · **C)** kompilyatsiya xatosi: `Katta` ga tur berilmagan

<details>
<summary>Javob</summary>

**A.** `"olma"` `"nok"` dan katta, chunki satrlar bayt boʻyicha solishtiriladi va `o` (111) `n` (110) dan keyin
keladi. «B» ni tanlagan boʻlsangiz, satr uzunligi solishtiriladi deb oʻylagansiz. «C» ni tanlagan boʻlsangiz:
turni yozish shart emas, kompilyator uni argumentlardan topadi.

</details>

```console
$ go run ./katta
7 1.5 olma
150000
7 olma
```

`Katta` butun son, kasr son va satr bilan ishladi, turni esa biz yozmadik. Kompilyator `T` ni argumentlardan oʻzi
topdi: `3` va `7` dan `int`, `1.5` dan `float64`. Bu **type inference** (turni chiqarib olish) deyiladi. Ikkinchi
qatorda turni `Katta[int64]` deb oʻzimiz berdik. Har ikki holatda kompilyator `T` oʻrniga aniq turni qoʻyadi: bu
**instantiation** deyiladi. Go spetsifikatsiyasi: *"A generic function, method, or type is instantiated by
substituting type arguments for the type parameters"*.

| Chaqiruv | `T` qayerdan | `T` | Natija |
|---|---|---|---|
| `Katta(3, 7)` | type inference | `int` | `7` |
| `Katta(1.5, 0.5)` | type inference | `float64` | `1.5` |
| `Katta("olma", "nok")` | type inference | `string` | `olma` |
| `Katta[int64](150000, 99000)` | oʻzimiz berdik | `int64` | `150000` |

Bir eslatma: Go 1.21 dan beri tilning oʻzida `max` funksiyasi bor. Uning imzosi aynan shunday:

```console
$ go doc builtin.max | sed -n 3p
func max[T cmp.Ordered](x T, y ...T) T
```

`Katta` — faqat misol. Generic yozishdan oldin tayyorini qidiring: `max`, `min`, `slices`, `maps` paketlari.

## Constraint — bu interface

Constraint aslida oddiy interface. Faqat unda metodlardan tashqari turlar roʻyxati ham boʻlishi mumkin. Bunday
roʻyxat interface'ning **type set**'ini, yaʼni u ruxsat beradigan turlar toʻplamini belgilaydi.

```go filename="cheklov/main.go" showLineNumbers
// cheklov: oʻz constraint'imiz. ~int64 — "asosiy turi int64 boʻlgan har qanday tur".
// go run ./cheklov
package main

import "fmt"

type Son interface {
	~int64 | ~float64
}

type Ball int64 // asosiy (underlying) turi int64

func Jami[T Son](xs []T) T {
	var s T
	for _, x := range xs {
		s += x
	}
	return s
}

func main() {
	fmt.Println(Jami([]Ball{90, 85, 70}))
	fmt.Println(Jami([]float64{1.5, 2.25}))
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7–9 | `type Son interface { ~int64 \| ~float64 }` | `Son` (son) — constraint: ikki tur, `\|` — «yoki». Metodi yoʻq, faqat turlar |
| 8 | `~` (tilde) | «**asosiy turi** shu boʻlgan hamma turlar» (pastda) |
| 11 | `type Ball int64` | `Ball` (ball, baho) — yangi nomli tur, asosiy turi (*underlying type*) `int64` |
| 13 | `func Jami[T Son](xs []T) T` | `T` faqat `Son` dagi turlardan biri |
| 14 | `var s T` | `T` ning zero value'si: `0` |
| 16 | `s += x` | ruxsat, chunki `Son` dagi har bir tur `+` ni biladi |
| 22 | `Jami([]Ball{90, 85, 70})` | `T` = `Ball` |
| 23 | `Jami([]float64{1.5, 2.25})` | `T` = `float64` |

TS'dagi `T extends number | string` ga oʻxshaydi. Lekin Go'da `type Ball int64` — `int64` ning taxallusi emas,
alohida tur ([GO-1.03](/lab/youtube/go/go-1-03) dagi `type Status int` kabi). Shuning uchun `~` kerak. Go spetsifikatsiyasi:
*"The type set of a term of the form ~T is the set of all types whose underlying type is T"* — «`~T` termining type
set'i — asosiy turi `T` boʻlgan hamma turlar toʻplami».

```console
$ go run ./cheklov
245
3.75
```

90 + 85 + 70 = 245, 1.5 + 2.25 = 3.75. Endi `~` belgisini olib tashlaymiz. `tildesiz/main.go` boshqa hamma joyda
bir xil, faqat 7–9-qatorlar:

```go
type Son interface {
	int64 | float64
}
```

```console
$ go build -o /dev/null ./tildesiz
# generics/tildesiz
tildesiz/main.go:22:18: Ball does not satisfy Son (possibly missing ~ for int64 in Son)
```

Xatoni oʻqiymiz: 22-qator, `Jami([]Ball{…})`. *Ball does not satisfy Son* — «`Ball` `Son` ni qanoatlantirmaydi».
Qavs ichida kompilyator hatto maslahat beradi: *possibly missing ~ for int64 in Son* — «`Son` dagi `int64` oldida
`~` tushib qolgan boʻlishi mumkin». `~` siz `Son` ning type set'i faqat ikkita tur: `int64` va `float64`. `Ball`
ular orasida yoʻq.

| `Son` | `int64` | `Ball` (asosiy turi `int64`) | `float64` |
|---|---|---|---|
| `~int64 \| ~float64` | ha | ha | ha |
| `int64 \| float64` | ha | **yoʻq** | ha |

Standart kutubxonadagi `cmp.Ordered` ham shunday yozilgan:

```console
$ sed -n 18,23p $(go env GOROOT)/src/cmp/cmp.go
type Ordered interface {
	~int | ~int8 | ~int16 | ~int32 | ~int64 |
		~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~uintptr |
		~float32 | ~float64 |
		~string
}
```

Har bir tur oldida `~` bor, shuning uchun `cmp.Ordered` siz yaratgan turlar bilan ham ishlaydi: `Katta(Ball(90),
Ball(85))` kompilyatsiya boʻladi.

## Generic metodlar (Go 1.27)

`Royxat` turi generic, uning elementlari `T` turida. Go 1.18 dan beri generic turning metodlari bor, lekin ular
faqat receiver'dagi `T` dan foydalana oladi. Yangi tur kerak boʻlsa-chi? `royxat/` — Go 1.18–1.26 usuli:

```go filename="royxat/main.go" showLineNumbers
// royxat: Go 1.18–1.26 usuli. Metod faqat receiver'dagi T ni ishlata oladi,
// yangi tur (U) kerak boʻlsa — paket darajasidagi funksiya.
// go run ./royxat
package main

import "fmt"

type Royxat[T any] []T

// Filtr: faqat T kerak — metod boʻla oladi (Go 1.18 dan beri).
func (r Royxat[T]) Filtr(ok func(T) bool) Royxat[T] {
	var natija Royxat[T]
	for _, x := range r {
		if ok(x) {
			natija = append(natija, x)
		}
	}
	return natija
}

// Aylantir: yangi U kerak — 1.27 gacha faqat funksiya.
func Aylantir[T, U any](r Royxat[T], f func(T) U) Royxat[U] {
	natija := make(Royxat[U], len(r))
	for i, x := range r {
		natija[i] = f(x)
	}
	return natija
}

func main() {
	r := Royxat[int64]{150000, 99000, 42000}
	fmt.Println(Aylantir(r.Filtr(katta), somda))
}

func katta(s int64) bool   { return s > 50000 }
func somda(s int64) string { return fmt.Sprintf("%d soʻm", s) }
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 8 | `type Royxat[T any] []T` | generic tur: elementlari `T` |
| 11 | `func (r Royxat[T]) Filtr(ok func(T) bool) Royxat[T]` | `Filtr` (filtr) — yangi tur kerak emas, faqat receiver'dagi `T`: shuning uchun metod |
| 12–18 | `var natija …; if ok(x) { natija = append(natija, x) }` | `ok` true qaytargan elementlarni yigʻadi |
| 22 | `func Aylantir[T, U any](r Royxat[T], f func(T) U) Royxat[U]` | `Aylantir` (aylantir) yangi `U` turini qaytaradi: 1.27 gacha faqat paket darajasidagi funksiya boʻla olardi |
| 31 | `r := Royxat[int64]{…}` | uchta summa |

```go filename="zanjir/main.go" showLineNumbers
// zanjir: Go 1.27 usuli. Aylantir endi metod — chaqiruvlar chapdan oʻngga oʻqiladi.
// go run ./zanjir
package main

import "fmt"

type Royxat[T any] []T

func (r Royxat[T]) Filtr(ok func(T) bool) Royxat[T] {
	var natija Royxat[T]
	for _, x := range r {
		if ok(x) {
			natija = append(natija, x)
		}
	}
	return natija
}

// U — metodning oʻz type parametri (Go 1.27).
func (r Royxat[T]) Aylantir[U any](f func(T) U) Royxat[U] {
	natija := make(Royxat[U], len(r))
	for i, x := range r {
		natija[i] = f(x)
	}
	return natija
}

func main() {
	r := Royxat[int64]{150000, 99000, 42000}
	fmt.Println(r.Filtr(katta).Aylantir(somda))
}

func katta(s int64) bool   { return s > 50000 }
func somda(s int64) string { return fmt.Sprintf("%d soʻm", s) }
```

## Cheklov: generic metod interface'ni bajarmaydi

Endi boshidagi shartga oʻtamiz. U ikki qismdan iborat. Go 1.27 release notes: *"methods of interfaces may not declare
type parameters nor can interface methods be implemented by generic methods"*.

**Birinchi qism:** interface metodi oʻz type parametrini eʼlon qila olmaydi.

```go filename="imetod/main.go" showLineNumbers
// imetod: ATAYLAB kompilyatsiya boʻlmaydi. Interface metodi type parameter e'lon qila olmaydi.
// go build -o /dev/null ./imetod   (plain "go build ./imetod" collides with the folder name)
package main

	Aylantir[U any](f func(int64) U) []U
}

func main() {}
```

```console
$ go build -o /dev/null ./imetod
# generics/imetod
imetod/main.go:6:10: interface method must have no type parameters
imetod/main.go:6:32: undefined: U
```

*interface method must have no type parameters* — «interface metodining type parametrlari boʻlmasligi kerak».
Ikkinchi xato birinchisining natijasi: `[U any]` rad etilgani uchun `U` eʼlon qilinmagan (*undefined*). Interface'ning
**oʻz** type parametrlaridan foydalanish esa mumkin (spetsifikatsiya: *"they may use type parameters from the
interface declaration"*):

```go

```

**Ikkinchi qism:** generic metod hech qanday interface'ni bajarmaydi. `ibajar/`:

```go filename="ibajar/main.go" showLineNumbers

import "fmt"

func (Bosh) Nop[T any](x T) T { return x }

	Nop(string) string

	fmt.Println(b.Nop("salom"), b.Nop(42)) // toʻgʻridan-toʻgʻri: ishlaydi
```

## Nega aynan shunday tanlandi?

[GO-1.13](/lab/youtube/go/go-1-13) da koʻrdik: interface ichida (tur, qiymat) juftligi turadi, `x.(T)` esa turni dastur
ishlayotganda tekshiradi. Demak interface'ni bajarish dastur ishlayotganda ham tekshiriladi. Generic metodning esa
cheksiz koʻp varianti bor: `Nop[string]`, `Nop[int]`, `Nop[Ball]`, … Kompilyator binary'ga faqat kodda ishlatilgan
variantlarni yozadi. Dastur ishlayotganda `any` ichidagi `Bosh` dan `Nop(float32) float32` soʻralsa, bu variant
binary'da boʻlmasligi mumkin.

Go FAQ (*Why does Go not support methods with type parameters?*) toʻrtta yoʻlni sanaydi:

| # | Yoʻl | Izoh |
|---|---|---|
| 1 | link'dan keyin kerakli variantlarni qayta kompilyatsiya qilish | build sekinlashadi |
| 2 | JIT | runtime'da kompilyatsiya |
| 3 | sekin zaxira kod | tezlikni oldindan bilib boʻlmaydi |
| 4 | generic metod interface'ni umuman bajarmaydi | FAQ: *"unacceptable from a design point of view"* → Go 1.27 tanlovi |

Toʻrtinchisi u yerda qabul qilib boʻlmaydi deb atalgan, lekin Go 1.27 aynan uni tanladi. Griesemer taklifda
(golang/go#77273, *"A change of view"*) sababini yozgan: metod faqat interface uchun emas, kodni tartiblash uchun
ham kerak. Uning soʻzlari: *"concrete methods are a language feature that is useful in itself, irrespective of
interfaces"*. TypeScript'da bu muammo yoʻq: turlar ishga tushishdan oldin oʻchiriladi va bitta JS funksiyasi hamma
turga xizmat qiladi.

FAQ'dagi misolni Go 1.27 da ishga tushiramiz. `Bosh` qiymatini boʻsh interface'ga solib, undan `Nop` metodini
soʻraymiz:

```go filename="faq/main.go" showLineNumbers
// faq: Go FAQ'dagi misol (generic_methods), Go 1.27 da ishga tushirilgan.
// Bosh qiymati any ichida: dastur ishlayotganda uning generic metodi koʻrinmaydi.
// go run ./faq
package main

import (
	"fmt"
	"reflect"
)

type Bosh struct{}

func (Bosh) Nop[T any](x T) T { return x }
func (Bosh) Oddiy()           {}

func main() {
	var x any = Bosh{}
	_, ok := x.(interface{ Nop(string) string })
	fmt.Println("Nop(string) string bormi?", ok)
	_, ok = x.(interface{ Nop(int) int })
	fmt.Println("Nop(int) int bormi?", ok)
	_, ok = x.(interface{ Oddiy() })
	fmt.Println("Oddiy() bormi?", ok)
	fmt.Println("reflect koʻrgan metodlar:", reflect.TypeOf(x).NumMethod())
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 13 | `func (Bosh) Nop[T any](x T) T` | generic metod |
| 14 | `func (Bosh) Oddiy()` | oddiy metod, solishtirish uchun |
| 17 | `var x any = Bosh{}` | `Bosh` boʻsh interface ichida |
| 18, 20, 22 | `_, ok := x.(interface{ … })` | type assertion: «`x` ichidagi tur shu interface'ni bajaradimi?» Mos kelmasa `ok` = `false`, panic yoʻq ([GO-1.13](/lab/youtube/go/go-1-13)) |
| 24 | `reflect.TypeOf(x).NumMethod()` | `reflect` — dastur ishlayotganda turlarni oʻrganadigan standart paket; `NumMethod` turning metodlarini sanaydi |

## Generic qachon kerak emas: uchta hid

Endi eng muhim savol: generic qachon kerak emas? `hid/` da uchta generic funksiya bor. Hammasi kompilyatsiya
boʻladi va ishlaydi, lekin bu yerda type parameter hech narsa bermaydi.

```go filename="hid/main.go" showLineNumbers
// hid: uchta ortiqcha generic. Hammasi kompilyatsiya boʻladi va ishlaydi,
// lekin type parameter hech narsa bermaydi. Tozalangani: ../toza
// go run ./hid
package main

import (
	"fmt"
	"strconv"
)

type Buyurtma struct{ Summa int64 }

func (b Buyurtma) String() string { return fmt.Sprintf("buyurtma: %d soʻm", b.Summa) }

// 1-hid: T bilan faqat metod chaqiriladi.
func Chiqar[T fmt.Stringer](x T) { fmt.Println(x.String()) }

// 2-hid: T hech narsa bermaydi, Println baribir any oladi.
func Yoz[T any](x T) { fmt.Println("log:", x) }

// 3-hid: har bir tur uchun boshqa kod (type switch).
func Matn[T int64 | string](x T) string {
	switch v := any(x).(type) {
	case int64:
		return strconv.FormatInt(v, 10)
	case string:
		return v
	}
	return ""
}

func main() {
	Chiqar(Buyurtma{150000})
	Yoz(42)
	fmt.Println(Matn(int64(99000)), Matn("nok"))
}
```

| Qator | Kod | Nima qiladi va nega ortiqcha |
|---|---|---|
| 11–13 | `Buyurtma`, `String()` | `fmt.Stringer` ni bajaradigan tur ([GO-1.13](/lab/youtube/go/go-1-13)) |
| 16 | `func Chiqar[T fmt.Stringer](x T)` | `Chiqar` (chiqar) `T` bilan faqat `String()` metodini chaqiradi. Taylor: *"If all you need to do with a value of some type is call a method on that value, use an interface type"* |
| 19 | `func Yoz[T any](x T)` | `Yoz` (yoz): `fmt.Println` baribir istalgan qiymatni (`any`) oladi, `T` hech narsa qoʻshmaydi |
| 22–30 | `func Matn[T int64 \| string](x T) string` | ichida type switch: `any(x)` — `T` ni boʻsh interface'ga oʻgirish, keyin har bir tur uchun boshqa kod. Taylor: *"if the implementation is different for each type, then use an interface type … don't use a type parameter"* |
| 25 | `strconv.FormatInt(v, 10)` | `int64` ni oʻnlik sanoqdagi matnga aylantiradi |

`toza/` — xuddi shu uchta funksiya type parameter'siz:

```go filename="toza/main.go" showLineNumbers
// toza: ../hid dagi uchta funksiya type parameter'siz. Natija bir xil.
// go run ./toza
package main

import (
	"fmt"
	"strconv"
)

type Buyurtma struct{ Summa int64 }

func (b Buyurtma) String() string { return fmt.Sprintf("buyurtma: %d soʻm", b.Summa) }

// 1: faqat metod kerak — interface.
func Chiqar(x fmt.Stringer) { fmt.Println(x.String()) }

// 2: any yetarli.
func Yoz(x any) { fmt.Println("log:", x) }

// 3: har bir tur uchun oʻz kodi — alohida funksiyalar.
func MatnSon(x int64) string   { return strconv.FormatInt(x, 10) }
func MatnSatr(x string) string { return x }

func main() {
	Chiqar(Buyurtma{150000})
	Yoz(42)
	fmt.Println(MatnSon(99000), MatnSatr("nok"))
}
```

| Hid (`hid/`) | Tozasi (`toza/`) |
|---|---|
| `Chiqar[T fmt.Stringer](x T)` | `Chiqar(x fmt.Stringer)`: interface |
| `Yoz[T any](x T)` | `Yoz(x any)`: istalgan qiymat |
| `Matn[T int64 \| string]` + type switch | `MatnSon(int64)` va `MatnSatr(string)`: ikkita alohida funksiya |

Ikkala dasturning natijasini solishtiramiz. `diff <(…) <(…)` ikki buyruqning chiqishini qatorma-qator
solishtiradi va bir xil boʻlsa hech narsa chiqarmaydi; `&&` keyingi buyruqni faqat muvaffaqiyatda bajaradi:

```console
$ go run ./hid
buyurtma: 150000 soʻm
log: 42
99000 nok
```

```console
$ diff <(go run ./hid) <(go run ./toza) && echo natija bir xil
natija bir xil
```

Natija bir xil, kod esa soddaroq. Bizning amaliy tekshiruvimiz shunday: type parameter'ni olib tashlaganda hech
narsa yoʻqolmasa, u ortiqcha edi. Bu Taylor'ning maslahatlariga asoslangan, lekin qatʼiy qoida emas: u
*"consider"* («oʻylab koʻring») deydi.

## Generic interface'dan tezmi? Oʻlchaymiz

Generic kod interface'dan tezroqmi? Keling, oʻlchab koʻramiz. `tezlik/` da bir xil yigʻindi uch usulda hisoblanadi:

```go filename="tezlik/tezlik.go" showLineNumbers
// Package tezlik: bir xil yigʻindi uch usulda — interface, generic, oddiy tur.
// go test -bench . ./tezlik
package tezlik

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func (b *Buyurtma) Jami() int64 { return b.Summa }

type Summali interface{ Jami() int64 }

//go:noinline
func JamiInterface(xs []Summali) (s int64) {
	for _, x := range xs {
		s += x.Jami()
	}
	return s
}

//go:noinline
func JamiGeneric[T Summali](xs []T) (s int64) {
	for _, x := range xs {
		s += x.Jami()
	}
	return s
}

//go:noinline
func JamiOddiy(xs []*Buyurtma) (s int64) {
	for _, x := range xs {
		s += x.Jami()
	}
	return s
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 10 | `func (b *Buyurtma) Jami() int64` | pointer receiver'li metod: summani qaytaradi |
| 12 | `type Summali interface{ Jami() int64 }` | `Summali` (summasi bor) — `Jami` metodi bor turlar |
| 14, 22, 30 | `//go:noinline` | kompilyatorga: bu funksiyaning oʻzini chaqiruv joyiga koʻchirma. Benchmark funksiyani oʻlchashi uchun |
| 15 | `JamiInterface(xs []Summali)` | interface slice'i |
| 23 | `JamiGeneric[T Summali](xs []T)` | generic: `T` = `*Buyurtma` |
| 31 | `JamiOddiy(xs []*Buyurtma)` | oddiy aniq tur |
| 15, 23, 31 | `(s int64)` | nomlangan natija (named result): `s` 0 dan boshlanadi, `return s` uni qaytaradi |

Benchmark'lar ([GO-1.07](/lab/youtube/go/go-1-07)) 1000 ta buyurtma bilan:

```go filename="tezlik/tezlik_test.go" showLineNumbers
package tezlik

import "testing"

const n = 1000

func buyurtmalar() []*Buyurtma {
	xs := make([]*Buyurtma, n)
	for i := range xs {
		xs[i] = &Buyurtma{Summa: int64(i)}
	}
	return xs
}

func TestBirXil(t *testing.T) {
	xs := buyurtmalar()
	is := make([]Summali, n)
	for i, x := range xs {
		is[i] = x
	}
	a, b, c := JamiInterface(is), JamiGeneric(xs), JamiOddiy(xs)
	if a != b || b != c {
		t.Fatalf("%d %d %d", a, b, c)
	}
}

func BenchmarkInterface(b *testing.B) {
	xs := buyurtmalar()
	is := make([]Summali, n)
	for i, x := range xs {
		is[i] = x
	}
	for b.Loop() {
		JamiInterface(is)
	}
}

func BenchmarkGeneric(b *testing.B) {
	xs := buyurtmalar()
	for b.Loop() {
		JamiGeneric(xs)
	}
}

func BenchmarkOddiy(b *testing.B) {
	xs := buyurtmalar()
	for b.Loop() {
		JamiOddiy(xs)
	}
}
```

`TestBirXil` uchala funksiya bir xil yigʻindi berishini tekshiradi. Uchta benchmark bir xil 1000 ta buyurtmani
oʻlchaydi; interface versiyasi uchun ular avval `[]Summali` ga koʻchiriladi (17–20-qatorlar).

Bitta oʻlchov shovqinli boʻladi, shuning uchun `olch.sh` har bir benchmark'ni 7 marta ishga tushirib, medianani

</details>

interface va generic bir-biriga juda yaqin (goh biri, goh ikkinchisi oldinda), oddiy tur esa ikkalasidan ham bir
necha baravar tez (bu yerda ≈ 4,4×, yengil yuklamada 5–6×). Uchala variant ham `0 allocs/op`: xotira ajratish yoʻq.

Sababi kompilyatorda. Birinchisi: oddiy versiyada `Jami` metodi **inline** boʻladi, yaʼni chaqiruv yoʻqoladi.
`-gcflags=-m` ([GO-1.11](/lab/youtube/go/go-1-11)) kompilyatorning qarorlarini chiqaradi:

`2>&1` kompilyator xabarlarini (`stderr`) `grep` ga yuboradi. 33-qator — `JamiOddiy` ichidagi `x.Jami()`. 17- va
25-qatorlarda (interface va generic) inline yoʻq: u yerda har safar haqiqiy chaqiruv bor.

Ikkinchisi: standart Go kompilyatori generic funksiyani har bir tur uchun alohida yasamaydi. Hamma pointer turlar
uchun bitta umumiy tana yasaydi. Bunday tana guruhi **shape** (shakl) deyiladi, barcha pointer turlar bitta
`go.shape.*uint8` shaklida. Tana qaysi aniq tur bilan ishlayotganini yashirin argument — **lugʻat** (*dictionary*)
orqali biladi. Metod ham shu lugʻat orqali, xuddi interface kabi chaqiriladi. `go tool nm` binary'dagi nomlarni
koʻrsatadi:

```console
$ go test -c -o /tmp/tezlik.test ./tezlik && go tool nm /tmp/tezlik.test | grep JamiGeneric
  5656e0 R generics/tezlik..dict.JamiGeneric[*generics/tezlik.Buyurtma]
  544560 T generics/tezlik.JamiGeneric[go.shape.*uint8]
```

`go test -c` testni ishga tushirmaydi, faqat binary yasaydi. `T` — kod (funksiya tanasi):
`JamiGeneric[go.shape.*uint8]`, hamma pointer turlar uchun bitta. `R` — faqat oʻqiladigan maʼlumot: `*Buyurtma`
uchun lugʻat. Uy vazifasidagi guru masalasida toʻrt tur bilan nechta tana chiqishini oʻzingiz sanaysiz.

| | Interface | Generic (`T` = `*Buyurtma`) | Oddiy |
|---|---|---|---|
| `Jami` qanday chaqiriladi | interface jadvali orqali | lugʻat orqali | toʻgʻridan-toʻgʻri, inline |
| chaqiruv bormi | ha, har elementda | ha, har elementda | yoʻq |
| tezlik | sekin | sekin | bir necha baravar tez |

Bular standart (gc) kompilyatorning tafsilotlari. Go FAQ: *"Different compilers will make different choices"* —
«turli kompilyatorlar turlicha tanlaydi». Taylor buni ham yozgan: *"don't change from interface types to type
parameters just for speed, because it probably won't run any faster"* — «faqat tezlik uchun interface'ni type
parameter'ga almashtirmang, ehtimol tezroq ishlamaydi».

## Xulosa: generic kerakmi?

| Holat | Nima ishlatamiz |
|---|---|
| faqat tezlik uchun | yoʻq, avval oʻlchang |
| bir xil kod, turli tur (slice, map, konteyner: `Katta`, `Royxat[T]`) | type parameter `[T]` |
| qiymatdan faqat metod kerak yoki har bir tur uchun kod boshqa | interface (yoki alohida funksiyalar) |
| metod yangi tur qaytaradi (`Aylantir[U]`) | generic metod (Go 1.27+): qulay, lekin interface orqali chaqirilmaydi |

## Koʻp uchraydigan xatolar

**1. Generic metod interface'ni bajaradi deb kutish.** TypeScript'dan kelgan odam `nop<T>` ni `nop(string)` li
interface'ga bemalol soladi. Go 1.27 da `var _ MatnNop = b` → `Bosh does not implement MatnNop (wrong type for
method Nop)`, *have* `Nop[T any](T) T`, *want* `Nop(string) string` («Cheklov» boʻlimi). Runtime'da ham:
`x.(interface{ Nop(string) string })` → `false` («Nega aynan shunday tanlandi?» boʻlimi). Tuzatish: interface
kerak boʻlsa, oddiy metod yozing (`func (Bosh) NopMatn(x string) string`) yoki turning oʻzini generic qiling
(`type Bosh[T any] struct{}` va `func (Bosh[T]) Nop(x T) T`): bunda `Bosh[string]` `MatnNop` ni bajaradi.

**2. `~` ni unutish.** `Son interface{ int64 | float64 }` va `type Ball int64` → `Ball does not satisfy Son
(possibly missing ~ for int64 in Son)` («Constraint — bu interface» boʻlimi). Tuzatish: `~int64 | ~float64`.
Oʻz turlaringiz bilan ishlashi kerak boʻlgan constraint'da doim `~` qoʻying, `cmp.Ordered` kabi.

**3. Generic metodni instantiation'siz qiymat sifatida olish.** [GO-1.12](/lab/youtube/go/go-1-12) dagi method value
(`f := b.Jami`) generic metod bilan ishlamaydi. Bu dastur kurs papkasida yoʻq, alohida modulda (`go 1.27`) ishga
tushirildi:

```go
package main

import "fmt"

type Quti[T any] struct{ v T }

func (q Quti[T]) Juft[U any](u U) (T, U) { return q.v, u }

func main() {
	q := Quti[int]{7}
	f := q.Juft
	fmt.Println(f("yetti"))
}
```

```console
$ go run ./juft
# scratch/juft
juft/main.go:11:7: cannot use generic function q.Juft without instantiation
```

*cannot use generic function q.Juft without instantiation* — «`q.Juft` generic funksiyasini instantiation'siz
ishlatib boʻlmaydi». `f` qaysi turda boʻlishini kompilyator bilmaydi: `U` hali nomaʼlum. Tuzatish: turni bering,
`f := q.Juft[string]`, yoki `f` ning turini yozing: `var f func(string) (int, string) = q.Juft`.

**4. Interface metodiga type parameter yozish.** `Aylantir[U any](…)` interface ichida → `interface method must have
no type parameters` («Cheklov» boʻlimi, birinchi qism). Tuzatish: type parameter'ni interface'ning oʻziga qoʻying
(`type Aylantiruvchi[U any] interface{ Aylantir(f func(int64) U) []U }`) yoki paket darajasidagi generic funksiya
yozing.

**5. Yangi Go, eski `go` qatori.** Go 1.27.4 oʻrnatilgan, `go.mod` da esa `go 1.26` → `generic method requires
go1.27 or later (-lang was set to go1.26; check go.mod)` («go.mod sharti» boʻlimi). Tuzatish: `go` qatorini
`go 1.27` qiling (`go get go@1.27`), lekin kutubxona boʻlsa, bu uning foydalanuvchilarini ham Go 1.27 ga majburlaydi.

**6. `go build ./papka` va papka nomidagi binary.** Kurs fayllaridagi izohda `go build ./tildesiz` deb yozilgan.
Uni aynan shunday ishga tushirsangiz, kompilyator xatosi oʻrniga boshqa xabar chiqadi:

```console
$ go build ./tildesiz
go: build output "tildesiz" already exists and is a directory
```

*build output "tildesiz" already exists and is a directory* — «build natijasi `tildesiz` allaqachon bor va u papka».
`go build` bitta `main` paketidan binary yasaydi va uni paket nomi bilan joriy papkaga yozmoqchi boʻladi. Bu yerda
esa shu nomli papka bor, shuning uchun `go` kompilyatsiyaga ham yetib bormaydi. Tuzatish: `go build -o /dev/null
./tildesiz` (binary kerak emas) yoki `go vet ./tildesiz`.

**7. Ortiqcha generic va «generic tezroq» degan ishonch.** Xato chiqmaydi, kod ishlaydi, lekin keraksiz murakkab
(«Generic qachon kerak emas» boʻlimi). Tezlik ham deyarli oʻzgarmaydi («Generic interface'dan tezmi?» boʻlimi).
Tuzatish: type parameter'ni olib tashlab koʻring; hech narsa yoʻqolmasa, u ortiqcha edi.

## Oʻzingizni tekshiring

**1.** `func Katta[T cmp.Ordered](a, b T) T` da type parameter qaysi, constraint qaysi? `Katta[int64](1, 2)` da
`int64` nima deyiladi?

<details>
<summary>Javob</summary>

`T` — type parameter, `cmp.Ordered` — constraint. `int64` — type argument: kompilyator `T` oʻrniga uni qoʻyadi, bu
instantiation. `Katta(1, 2)` da esa turni type inference topadi (`int`).

</details>

**2.** Bu dastur nima chiqaradi? (`Katta` — darsdagi funksiya; kurs papkasida yoʻq, alohida ishga tushirildi.)

```go
fmt.Println(Katta("10", "9"), Katta(10, 9))
```

<details>
<summary>Javob</summary>

```console
$ go run ./satr
9 10
```

Satrlar son sifatida emas, bayt boʻyicha solishtiriladi: `"9"` ning birinchi bayti `'9'` `"10"` ning birinchi bayti
`'1'` dan katta. `Katta(10, 9)` da `T` = `int`, natija `10`.

</details>

**3.** Qaysi biri generic boʻlishi kerak, qaysi biri yoʻq?
(a) `func Oxirgi[T any](s []T) T { return s[len(s)-1] }`
(b) `func Yop[T io.Closer](c T) error { return c.Close() }`

<details>
<summary>Javob</summary>

(a) — generic boʻlsin: bir xil kod istalgan element turi uchun, va natija aynan `T` (interface bilan natija `any`
boʻlib qolardi). (b) — keraksiz: `T` bilan faqat metod chaqiriladi, `func Yop(c io.Closer) error` yetarli
(birinchi hid).

</details>

**4.** Go 1.27 da `type Bosh struct{}` ning `func (Bosh) Nop[T any](x T) T` metodi bor. Nega `Bosh`
`interface{ Nop(string) string }` ni bajarmaydi, va Go jamoasi buni nega shunday qoldirdi?

<details>
<summary>Javob</summary>

Go 1.27 qoidasi: generic metod interface metodini bajarmaydi. Interface'ni bajarish dastur ishlayotganda ham
tekshiriladi, generic metodning esa cheksiz koʻp varianti bor va binary'da faqat ishlatilganlari turadi. FAQ'dagi
toʻrt yoʻldan qolgan uchtasi (link'dan keyin qayta kompilyatsiya, JIT, sekin zaxira kod) build'ni yoki tezlikni
yomonlashtiradi. Go 1.27 toʻrtinchisini tanladi, chunki metodlar interface'siz ham foydali (Griesemer, #77273).

</details>

**5.** [GO-1.13](/lab/youtube/go/go-1-13) dan: `var x any = Bosh{}` dan keyin `v, ok := x.(MatnNop)` mos kelmasa, nima
boʻladi? `ok` siz `v := x.(MatnNop)` boʻlsa-chi?

<details>
<summary>Javob</summary>

`ok` bilan: `ok` = `false`, `v` — `MatnNop` ning zero value'si (`nil`), panic yoʻq. `ok` siz: mos kelmasa, dastur
panic bilan toʻxtaydi. Bugungi `faq/` dasturi shuning uchun `ok` shaklini ishlatadi.

</details>

🟢 **Oson:** `Indeks[T comparable](s []T, x T) int` yozing: `x` birinchi uchragan oʻrin, topilmasa `-1`. Uni

```go filename="homework/oson/main.go" showLineNumbers
// oson: Indeks — x birinchi uchragan oʻrin yoki -1. Bitta generic funksiya.
// go run ./homework/oson
package main

import (
	"fmt"
	"slices"
)

func Indeks[T comparable](s []T, x T) int {
	for i, v := range s {
		if v == x {
			return i
		}
	}
	return -1
}

func main() {
	fmt.Println(Indeks([]int64{150000, 99000}, 99000))
	fmt.Println(Indeks([]string{"olma", "nok"}, "uzum"))
	// Standart kutubxonada tayyori bor (Go 1.21+):
	fmt.Println(slices.Index([]int64{150000, 99000}, 99000))
}
```

```console
$ go run ./homework/oson

```

`comparable` — `==` va `!=` bilan solishtiriladigan turlar uchun tilning oʻzidagi constraint. 12-qatorda `v == x`

🟡 **Oʻrta:** `type Quti[T any] struct{ v T }`. Qaysi qatorlar Go 1.27 da kompilyatsiya boʻladi?

1. `func (q Quti[T]) Ol() T { return q.v }`
2. `func (q Quti[T]) Juft[U any](u U) (T, U) { return q.v, u }`
3. `type I interface{ M[T any](T) }`
4. `f := q.Juft`
5. `var o Oluvchi[int] = q` (bunda `type Oluvchi[T any] interface{ Ol() T }`)
6. `f := q.Juft[string]`

<details>
<summary>Javob</summary>

**1, 2, 5, 6** kompilyatsiya boʻladi. 3 — `interface method must have no type parameters` («Cheklov» boʻlimi).
4 — `cannot use generic function q.Juft without instantiation` («Koʻp uchraydigan xatolar», 3). 5 — generic
*interface* boshqa narsa: uning metodi `Ol()` oddiy, faqat interface'ning `T` sini ishlatadi, shuning uchun
`Quti[int]` uni bajaradi. Kompilyatsiya boʻladiganlari:

```go filename="homework/orta/main.go" showLineNumbers
// 1: generic turdagi metod, receiver'dagi T bilan (Go 1.18+)
func (q Quti[T]) Ol() T { return q.v }

// 2: generic turdagi metod, oʻz type parametri bilan (Go 1.27+)

func main() {
```

🟠 **Qiyin:** `Royxat[T]` ga `Guruhla[K comparable](kalit func(T) K) map[K]Royxat[T]` generic metodini yozing va

<details>
<summary>Javob</summary>

```go filename="homework/qiyin/qiyin.go" showLineNumbers
// Package qiyin: Guruhla — Go 1.27 generic metodi. K — metodning oʻz type parametri.
package qiyin

type Royxat[T any] []T

// Guruhla elementlarni kalit(x) boʻyicha guruhlaydi; har guruhda tartib saqlanadi.
func (r Royxat[T]) Guruhla[K comparable](kalit func(T) K) map[K]Royxat[T] {
	natija := make(map[K]Royxat[T])
	for _, x := range r {
		k := kalit(x)
		natija[k] = append(natija[k], x)
	}
	return natija
}
```

`K` — metodning oʻz type parametri, `comparable`, chunki u map kaliti. `natija[k]` yoʻq kalit uchun `nil` slice
qaytaradi va `append` unga ham ishlaydi ([GO-1.08](/lab/youtube/go/go-1-08), [GO-1.09](/lab/youtube/go/go-1-09)). Test
(`homework/qiyin/qiyin_test.go`) bir marta `Tolandi` (`bool`) boʻyicha, bir marta `"katta"`/`"kichik"` (`string`)
boʻyicha guruhlaydi:

`-count=1` testni keshdan olmasdan qayta ishga tushiradi. Vaqt sizda boshqacha boʻladi.

🔴 **Guru:** `JamiGeneric[T Summali]` ni `*Buyurtma`, `*Mijoz`, `Narx` (`int64` asosli) va `Chegirma` (`int64`
asosli) bilan chaqiring. Kompilyator nechta tana va nechta lugʻat yasaydi? `go tool nm` bilan tekshiring.

<summary>Javob</summary>
