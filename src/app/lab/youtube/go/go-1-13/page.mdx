## Nimani oʻrganasiz

Funksiya xato boʻlmasa `nil` qaytaradi. Uni toʻgʻri buyurtma bilan chaqiramiz va natijani chiqaramiz. Ekranda
`err: <nil>` yozildi. Lekin keyingi qatordagi `if err != nil` baribir ishladi va «xato bor!» deb yozdi. Ishda bu
toʻgʻri soʻrovni ham xato deb qaytaradigan handler boʻladi. Bu holat Go'ning rasmiy savol-javoblarida (Go FAQ)
alohida savol sifatida turadi. Qaytgan qiymat ekranda `nil`, lekin `nil` ga teng emas. Nega?

**Bitta gʻoya:** interface qiymati — (tur, qiymat) juftligi. U faqat ikkalasi ham boʻsh boʻlganda `nil` ga teng.

Dars oxirida siz:

- tur interface'ni `implements` siz qachon bajarishini va kompilyator buni qachon rad etishini tushuntira olasiz;
- interface qiymati ichidagi tur va qiymatni `%T` bilan koʻra olasiz, uning xotiradagi tuzilishini bilasiz;
- type assertion (`v, ok := x.(T)`) va type switch bilan ichidagi qiymatni panic'siz qaytarib ola olasiz;
- typed nil xatosini taniysiz, tuzatasiz va staticcheck bilan topasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| interface | metodlar roʻyxati; shu metodlarga ega har qanday tur uni oʻzi bajaradi, `implements` yozilmaydi | interface |
| type assertion | interface ichidagi qiymatni aniq turi bilan qaytarib olish: `x.(T)`; tur runtime'da tekshiriladi | type assertion |
| typed nil | ichida tur yozilgan, qiymati esa `nil` boʻlgan interface; u `nil` ga teng emas | typed nil |

Yoʻl-yoʻlakay ikkita yordamchi soʻz ham uchraydi: **type switch** (bir nechta turni bitta `switch` da tekshirish) va
**`any`** (boʻsh interface: metodi yoʻq, shuning uchun har qanday tur uni bajaradi). Ikkalasini kerak boʻlgan joyda
tushuntiramiz.

## Jumboq: nil, lekin nil emas

Bu kurs papkasidagi `hook/main.go`. U **ataylab xato** yozilgan:

```go filename="hook/main.go" showLineNumbers
// hook: funksiya nil qaytaradi, ekranga <nil> chiqadi, lekin err != nil.
// ATAYLAB XATO (typed nil). Tuzatilgani: ../fix
// go run ./hook
package main

import "fmt"

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

type SummaXato struct{ Summa int64 }

func (e *SummaXato) Error() string { return fmt.Sprintf("summa notoʻgʻri: %d", e.Summa) }

func tekshir(b Buyurtma) error {
	var xato *SummaXato
	if b.Summa <= 0 {
		xato = &SummaXato{Summa: b.Summa}
	}
	return xato
}

func main() {
	err := tekshir(Buyurtma{Summa: 150000})
	fmt.Println("err:", err)
	if err != nil {
		fmt.Println("xato bor!")
	}
	fmt.Printf("ichida: %T, %v\n", err, err)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 8–11 | `type Buyurtma struct {…}` | oldingi darslardagi buyurtma: summa va «toʻlandimi?» |
| 13 | `type SummaXato struct{ Summa int64 }` | oʻz xato turimiz (`SummaXato` — «summa xatosi»): notoʻgʻri summani saqlaydi |
| 15 | `func (e *SummaXato) Error() string {…}` | pointer receiver'li `Error` metodi. `Error() string` metodi bor tur `error` sifatida qaytarila oladi; nega — keyingi boʻlimda |
| 17 | `func tekshir(b Buyurtma) error {` | `tekshir` («tekshir») buyurtmani tekshiradi va `error` qaytaradi |
| 18 | `var xato *SummaXato` | `*SummaXato` turidagi pointer; uning zero value'si `nil` |
| 19–21 | `if b.Summa <= 0 {…}` | summa notoʻgʻri boʻlsa, pointer'ga yangi xatoning manzilini yozadi |
| 22 | `return xato` | pointer'ni `error` sifatida qaytaradi; summa toʻgʻri boʻlsa, u `nil` |
| 26 | `err := tekshir(Buyurtma{Summa: 150000})` | toʻgʻri summa: xato boʻlmasligi kerak |
| 27 | `fmt.Println("err:", err)` | `err` ni chiqaradi |
| 28–30 | `if err != nil {…}` | xato bor boʻlsa, «xato bor!» deb yozadi |
| 31 | `fmt.Printf("ichida: %T, %v\n", err, err)` | `%T` — tur, `%v` — qiymat. Bu qatorni keyinroq ochamiz |

Avval faqat birinchi ikki qatorni koʻramiz (`| head -2` — chiqishning boshidagi ikki qator). Ishga tushirishdan
oldin oʻylab koʻring: nima chiqadi? **A)** faqat `err: <nil>` · **B)** `err: <nil>` va `xato bor!` ·
**C)** `err: summa notoʻgʻri: 150000` va `xato bor!`

<details>
<summary>Javob</summary>

**B.** Ekranda `nil`, lekin `if err != nil` ishladi. «A» ni tanlagan boʻlsangiz, `nil` pointer'ni qaytarish `nil`
xatoni qaytarish bilan bir xil deb oʻylagansiz: JS'dagi `null` yoki Python'dagi `None` shunday ishlaydi. Go'da
bunday emas, va bu darsning hammasi shu haqda. «C» ni tanlagan boʻlsangiz, `Error()` metodi oddiy ishlaydi deb
oʻylagansiz. U chaqirildi ham, lekin uning matni ekranga chiqmadi. Nega — «Nega ekran ham aldadi» boʻlimida.

</details>

```console
$ go run ./hook | head -2
err: <nil>
xato bor!
```

JavaScript'da `null === null` doim `true`, Python'da `None is None` ham. Go'da esa `nil` bilan `nil` ni
solishtirish `false` berishi mumkin. Sababini topish uchun interface'ning ichiga kiramiz. Reja: avval Go'da
interface qanday bajariladi, keyin interface qiymatining ichida nima bor, keyin type assertion va type switch,
oxirida shu jumboq.

## Interface: metodlar roʻyxati, implements'siz

`fmt.Println` bizning `Buyurtma` ni chiroyli chiqarishi kerak. Lekin `fmt` paketi `Buyurtma` dan ancha oldin
yozilgan va u haqida hech narsa bilmaydi. `fmt` faqat bitta narsani soʻraydi: «qiymatingda `String() string`
metodi bormi?». Bu talab `fmt.Stringer` degan **interface** sifatida yozilgan:

```go
type Stringer interface {
	String() string
}
```

Interface — metodlar roʻyxati. Bu roʻyxatdagi hamma metodlarga ega tur interface'ni **bajaradi** (inglizcha
*implements*). Go'da bir-ikki metodli kichik interface'lar odatiy hol (Effective Go: *"Interfaces with only one or
two methods are common in Go code"*). [GO-1.06](/lab/youtube/go/go-1-06) dan beri qaytarib kelayotgan `error` ham shunday
interface (Go spec, «Errors»):

```go
type error interface {
	Error() string
}
```

Endi `stringer/main.go`:

```go filename="stringer/main.go" showLineNumbers
// stringer: Buyurtma hech qayerda "fmt.Stringer'ni bajaraman" demaydi.
// go run ./stringer
package main

import "fmt"

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func (b Buyurtma) String() string {
	return fmt.Sprintf("buyurtma: %d soʻm, toʻlandi: %v", b.Summa, b.Tolandi)
}

type Mijoz struct{ Ism string }

func (m Mijoz) String() string { return "mijoz: " + m.Ism }

func main() {
	royxat := []fmt.Stringer{
		Buyurtma{Summa: 150000},
		Mijoz{Ism: "Aziza"},
	}
	for _, s := range royxat {
		fmt.Println(s)
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7–10 | `type Buyurtma struct {…}` | oddiy struct. Hech qayerda «`fmt.Stringer` ni bajaraman» deb yozilmagan |
| 12–14 | `func (b Buyurtma) String() string {…}` | value receiver'li `String` metodi. `fmt.Sprintf` matnni ekranga chiqarmaydi, qaytaradi |
| 16 | `type Mijoz struct{ Ism string }` | butunlay boshqa tur: mijoz, `Ism` («ism») maydoni bilan |
| 18 | `func (m Mijoz) String() string {…}` | unda ham `String` metodi bor |
| 21 | `royxat := []fmt.Stringer{` | `fmt.Stringer` slice'i (`royxat` — «roʻyxat»): unga `String() string` metodi bor har qanday qiymat sigʻadi |
| 22–23 | `Buyurtma{Summa: 150000},` `Mijoz{Ism: "Aziza"},` | ikki xil tur bitta slice'da |
| 25–27 | `for _, s := range royxat {…}` | har birini `fmt.Println` bilan chiqaradi |

```console
$ go run ./stringer
buyurtma: 150000 soʻm, toʻlandi: false
mijoz: Aziza
```

`fmt.Println` ikkala qiymatni ham ularning `String` metodi orqali chiqardi. `Buyurtma` ham, `Mijoz` ham
`fmt.Stringer` ni bajaradi, chunki ularda kerakli metod bor. Shu bilan tamom: `implements` kalit soʻzi Go'da yoʻq.

**TypeScript, Python va PHP bilan solishtiramiz.** Uchala tilda ham bir xil gʻoyani yozib, ishga tushirdik.

TypeScript ham shakl boʻyicha (inglizcha *structural*) tekshiradi: `implements` yozmasangiz ham, `Buyurtma` kerakli
metodga ega boʻlgani uchun `Stringer` oʻrniga oʻtadi. Lekin TS interface'i faqat kompilyatsiya vaqtida yashaydi:
JS'ga oʻtkazilganda u oʻchiriladi (TS Handbook: *erased types*). Node 24 `.ts` faylni turlarni olib tashlab ishga
tushiradi, shuning uchun buni bevosita koʻrish mumkin (`stringer.ts`):

```ts
interface Stringer {
  string(): string;
}

class Buyurtma {
  // "implements Stringer" yozilmagan
  string() { return "buyurtma: 150000 soʻm"; }
}

const s: Stringer = new Buyurtma(); // TS shaklni solishtiradi va qabul qiladi
console.log(s.string());

const x: unknown = s;
console.log(x instanceof Stringer); // runtime'da Stringer degan narsa yoʻq
```

```console
$ node --input-type=module-typescript < stringer.ts 2>&1 | head -6
buyurtma: 150000 soʻm
[eval]:14
console.log(x instanceof Stringer); // runtime'da Stringer degan narsa yoʻq
                         ^

ReferenceError: Stringer is not defined
```

Birinchi qator ishladi. Oxirgi qatorda esa `Stringer is not defined`: dastur ishlayotganda `Stringer` degan narsa
umuman yoʻq.

Python'da hech narsa eʼlon qilinmaydi (*duck typing*): metod chaqiruv paytida qidiriladi. Xato faqat oʻsha qator
ishlaganda chiqadi (`duck.py`):

```python
class Buyurtma:
    def string(self):
        return "buyurtma: 150000 soʻm"

class Mijoz:  # string() metodi yoʻq
    pass

def chop(x):
    print(x.string())  # tekshiruv faqat shu qatorda, chaqiruv paytida

chop(Buyurtma())
chop(Mijoz())
```

```console
$ python3 - < duck.py
buyurtma: 150000 soʻm
Traceback (most recent call last):
  File "<stdin>", line 15, in <module>
  File "<stdin>", line 11, in chop
AttributeError: 'Mijoz' object has no attribute 'string'
```

Python'da Go'ga yaqinroq yoʻl ham bor: `typing.Protocol` ([PEP 544](https://peps.python.org/pep-0544/), *"static
duck typing"*). Lekin uni mypy kabi tekshiruvchi dastur tekshiradi, Python'ning oʻzi emas.

PHP'da esa aksincha: sinf interface'ni faqat `implements` bilan bajaradi. Metodlari bir xil boʻlsa ham, `implements`
yozilmasa, PHP uni qabul qilmaydi (`narxli.php`):

```php
<?php
interface Narxli {
    public function narx(): int;
}

class Buyurtma { // "implements Narxli" yozilmagan
    public function narx(): int { return 150000; }
}

function korsat(Narxli $x): void { echo $x->narx(), "\n"; }

var_dump(new Buyurtma() instanceof Narxli);
korsat(new Buyurtma());
```

```console
$ php < narxli.php
bool(false)

Fatal error: Uncaught TypeError: korsat(): Argument #1 ($x) must be of type Narxli, Buyurtma given, called in Standard input code on line 13 and defined in Standard input code:10
Stack trace:
#0 Standard input code(13): korsat(Object(Buyurtma))
#1 {main}
  thrown in Standard input code on line 10
```

| Til | `implements` kerakmi? | Qachon tekshiriladi | Dastur ishlayotganda interface bormi? |
|---|---|---|---|
| TypeScript | yoʻq, shakl boʻyicha | kompilyatsiyada | yoʻq, oʻchiriladi |
| Python | yoʻq, duck typing | metod chaqirilganda | yoʻq (`Protocol` — tekshiruvchi dastur uchun) |
| PHP | ha | funksiya chaqirilganda (`TypeError`) | ha |
| Go | yoʻq, metodlar boʻyicha | kompilyatsiyada | ha: tur va metodlar interface qiymati ichida |

Go ikkala dunyoning yaxshi tomonini oladi. TS va Python kabi `implements` yozilmaydi. PHP va Java kabi tekshiruv
qatʼiy: notoʻgʻri tur kompilyatsiya boʻlmaydi (pastda koʻramiz). TS'dan farqli, interface dastur ishlayotganda ham
bor, va `fmt` aynan shundan foydalanadi. Java'da esa sinf interface'ni faqat `implements` bilan bajaradi (Java
tilining spetsifikatsiyasi, §8.1.5).

Go nega `implements` ni olib tashlagan? Go FAQ: *"A Go type implements an interface by implementing the methods of
that interface, nothing more. This property allows interfaces to be defined and used without needing to modify
existing code."* — «Go turi interface'ni uning metodlarini yozish orqali bajaradi, boshqa hech narsa kerak emas. Bu
interface'ni mavjud kodni oʻzgartirmasdan eʼlon qilish va ishlatish imkonini beradi». Yaʼni interface'ni keyinroq,
oʻz paketingizda yozib, eski turlarga ham qoʻllaysiz.

## Pointer receiver: method set yana hal qiladi

[GO-1.12](/lab/youtube/go/go-1-12) da `String` metodini pointer receiver bilan yozganimizda, `fmt` uni qiymat uchun
chaqirmaganini koʻrdik. Endi sababi aniq. `ptrrecv/main.go`:

```go filename="ptrrecv/main.go" showLineNumbers
// ptrrecv: String pointer receiver bilan. Buyurtma qiymatining method set'ida
// String yoʻq (GO-1.12), shuning uchun fmt uni koʻrmaydi.
// go run ./ptrrecv
package main

import "fmt"

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func (b *Buyurtma) String() string {
	return fmt.Sprintf("buyurtma: %d soʻm, toʻlandi: %v", b.Summa, b.Tolandi)
}

func main() {
	b := Buyurtma{Summa: 150000}
	fmt.Println(b)  // qiymat: String ishlamaydi
	fmt.Println(&b) // pointer: String ishlaydi
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 13 | `func (b *Buyurtma) String() string {` | `String` endi **pointer** receiver bilan |
| 19 | `fmt.Println(b)` | `Buyurtma` qiymatini beradi |
| 20 | `fmt.Println(&b)` | `*Buyurtma`, yaʼni manzilni beradi |

Oʻylab koʻring: ikki qator bir xil chiqadimi?

<details>
<summary>Javob</summary>

**Yoʻq.** `Buyurtma` qiymatining method set'ida `String` yoʻq, demak u `fmt.Stringer` ni bajarmaydi. `fmt` uni oddiy
struct sifatida chiqaradi: `{150000 false}`. `*Buyurtma` ning method set'ida esa `String` bor, shuning uchun
ikkinchi qator formatlangan.

</details>

```console
$ go run ./ptrrecv
{150000 false}
buyurtma: 150000 soʻm, toʻlandi: false
```

```console
$ go vet ./ptrrecv && echo vet: jim
vet: jim
```

`fmt.Println` istalgan qiymatni `any` sifatida oladi, `String` ni esa dastur ishlayotganda qidiradi. Shuning uchun
kompilyator ham, `go vet` ham jim. `vet: jim` faqat `go vet` hech narsa topmagani uchun chiqdi (`&&` — oldingi
buyruq muvaffaqiyatli boʻlsa, keyingisini bajar).

Qiymatni toʻgʻridan-toʻgʻri `fmt.Stringer` turidagi oʻzgaruvchiga yozsak, kompilyator buni ochiq aytadi va rad
etadi. `xato/main.go` **ataylab kompilyatsiya boʻlmaydi**:

```go filename="xato/main.go" showLineNumbers
// xato: ATAYLAB kompilyatsiya boʻlmaydi.
// Buyurtma emas, faqat *Buyurtma fmt.Stringer'ni bajaradi.
// go build ./xato
package main

import "fmt"

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func (b *Buyurtma) String() string { return fmt.Sprint("buyurtma: ", b.Summa) }

func main() {
	b := Buyurtma{Summa: 150000}
	var s fmt.Stringer = b
	fmt.Println(s)
}
```

```console
$ go build -o /dev/null ./xato
# github.com/abdurahmon27/go-backend-uz/lessons/013-interfaces-nil/xato
xato/main.go:17:23: cannot use b (variable of struct type Buyurtma) as fmt.Stringer value in variable declaration: Buyurtma does not implement fmt.Stringer (method String has pointer receiver)
```

`-o /dev/null` — tayyor dasturni saqlamasdan tashlab yuborish: bizga faqat kompilyatsiya natijasi kerak. Xabarni
oʻqiymiz: `xato/main.go:17:23` — 17-qator, 23-ustun, yaʼni `var s fmt.Stringer = b` dagi `b`. *cannot use b
(variable of struct type Buyurtma) as fmt.Stringer value in variable declaration* — «`b` ni (`Buyurtma` struct
turidagi oʻzgaruvchini) oʻzgaruvchi eʼlonida `fmt.Stringer` qiymati sifatida ishlatib boʻlmaydi». Sababi oxirida:
*Buyurtma does not implement fmt.Stringer (method String has pointer receiver)* — «`Buyurtma` `fmt.Stringer` ni
bajarmaydi (`String` metodining receiver'i pointer)». **Tuzatish:** `var s fmt.Stringer = &b`, yoki `String` ni value
receiver bilan yozing.

Nega Go bu yerda `&b` ni oʻzi olmaydi? Go FAQ: interface ichida `T` qiymati saqlansa, metod chaqiruvi uchun undan
pointer olishning xavfsiz yoʻli yoʻq. Olinganda ham, metod interface ichidagi nusxani oʻzgartirgan boʻlardi.

## Interface ichida nima bor: (tur, qiymat)

Interface qiymati xotirada qanday turadi? U ikkita mashina soʻzidan (64-bitli tizimda 8 baytdan) iborat:

1. **tur** — ichidagi qiymat qaysi turdan ekani. Metodli interface'da (`fmt.Stringer`, `error`) bu soʻz metodlar
   jadvaliga ham olib boradi: `fmt` `String` ni aynan shu jadvaldan topadi.
2. **qiymat** — qiymatning oʻzi yoki unga pointer.

Go runtime'ining manba kodida bu ikki struct:

```console
$ sed -n 184,192p $(go env GOROOT)/src/runtime/runtime2.go
type iface struct {
	tab  *itab
	data unsafe.Pointer
}

type eface struct {
	_type *_type
	data  unsafe.Pointer
}
```

`iface` — metodli interface: `tab` tur va metodlar jadvaliga (`itab`) ishora qiladi. `eface` — boʻsh interface
(`any`): metod yoʻq, shuning uchun faqat tur (`_type`). Ikkalasida ham `data` — qiymatga pointer
(`unsafe.Pointer` — istalgan turdagi manzil). `$(go env GOROOT)` — Go oʻrnatilgan papka, `sed -n 184,192p` esa
faylning 184–192-qatorlarini chiqaradi.

**`any`** — metodsiz interface, `interface{}` ning qisqa nomi (Go spec). Metod talab qilinmagani uchun har qanday tur
uni bajaradi. U TS'dagi `unknown` ga yaqin, lekin bitta farq bilan: `any` ichida turning oʻzi saqlanadi.

Bu JS va Python'dan kelganlar uchun yangi narsa. Python'da har bir obyekt oʻz turini oʻzi bilan olib yuradi
(`type(x)` har doim ishlaydi). Go'da esa `int64` oʻzgaruvchisi shunchaki 8 bayt: uning turini faqat kompilyator
biladi. Tur qiymat yoniga faqat qiymat interface'ga solinganda yoziladi. Shuning uchun interface ikki soʻzdan iborat.

```text
var a any = 42                      var s fmt.Stringer = Buyurtma{Summa: 150000}
┌────────────┬────────────┐         ┌──────────────────────────┬────────────┐
│ tur: int   │ qiymat ─────► 42     │ tur: Buyurtma            │ qiymat ─────► {150000 false}
└────────────┴────────────┘         │ + metodlar: String       │            │
                                    └──────────────────────────┴────────────┘

nil interface:            ( tur: —,          qiymat: — )     → == nil  true
ichida nil pointer:       ( tur: *Buyurtma,  qiymat: nil )   → == nil  false
```

Go FAQ buni (T, V) juftligi deydi: *"An interface value is nil only if the V and T are both unset"* — «interface
qiymati faqat V (qiymat) ham, T (tur) ham boʻsh boʻlganda `nil`».

Buni koʻz bilan koʻramiz. `juftlik/main.go` («juftlik») har bir qiymatni boʻsh interface'ga solib, ichidagi tur va
qiymatni chiqaradi:

```go filename="juftlik/main.go" showLineNumbers

	"fmt"

	Summa   int64
```

## Type assertion: qiymatni qaytarib olish

`any` ichida `Buyurtma` turibdi. Uning `Summa` maydoniga qanday yetamiz? `a.Summa` kompilyatsiya boʻlmaydi: `any`
ning maydonlari ham, metodlari ham yoʻq. Buning uchun **type assertion** bor: nuqtadan keyin qavs ichida kutgan
turingizni yozasiz, `a.(Buyurtma)`. Go runtime interface'ning tur soʻzini tekshiradi.

Bu TS'dagi `x as Buyurtma` ga oʻxshab koʻrinadi, lekin TS'dagi `as` dastur ishlayotganda hech narsani tekshirmaydi
(`as.ts`):

```ts
const x: unknown = "150000";
const n = x as number; // TS: "menga ishon, bu number"
console.log(typeof n, n + 1);
```

```console
$ node --input-type=module-typescript < as.ts
string 1500001
```

TS «bu `number`» deganimizga ishondi, lekin ichida matn qoldi: `n + 1` `1500001` ni berdi. Go'dagi `x.(T)` esa har
safar haqiqiy turni tekshiradi. Python'da bunga eng yaqini — `isinstance(x, Buyurtma)`.

`assert/main.go`:

```go filename="assert/main.go" showLineNumbers
// assert: type assertion — interface ichidagi turni tekshirish.
// go run ./assert
package main

import "fmt"

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func main() {
	var a any = Buyurtma{Summa: 150000}

	b, ok := a.(Buyurtma) // comma-ok: panic yoʻq
	fmt.Println("Buyurtma?", ok, b.Summa)

	s, ok := a.(string)
	fmt.Printf("string?   %v %q\n", ok, s)

	n := a.(int) // ok'siz: tur mos kelmasa — panic
	fmt.Println(n)
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 13 | `var a any = Buyurtma{Summa: 150000}` | `any` ichida `Buyurtma` |
| 15 | `b, ok := a.(Buyurtma)` | type assertion, comma ok shakli: `ok` — tur mos keldimi |
| 16 | `fmt.Println("Buyurtma?", ok, b.Summa)` | `b` endi oddiy `Buyurtma`, `b.Summa` ishlaydi |
| 18 | `s, ok := a.(string)` | ichida `string` bormi? `:=` chapda kamida bitta yangi oʻzgaruvchi (`s`) boʻlsa ishlaydi, `ok` qayta ishlatiladi |
| 19 | `fmt.Printf("string?   %v %q\n", ok, s)` | `%q` — matnni qoʻshtirnoq ichida chiqaradi, boʻsh matn ham koʻrinadi |
| 21 | `n := a.(int)` | comma ok'siz assertion: tur mos kelmasa — panic |

<details>
<summary>Javob</summary>

**A.** Comma ok shaklida tur mos kelmasa, `ok` `false` boʻladi va siz oʻsha turning zero value'sini olasiz:
`string` uchun `""`. Panic yoʻq. «B» ni tanlagan boʻlsangiz, mos kelmasa `nil` qaytadi deb oʻylagansiz: `string`
`nil` boʻla olmaydi. «C» faqat 21-qatordagi ok'siz shaklda boʻladi.

</details>

Panic xabari stderr'ga yoziladi. `2>&1` uni ham `head` ga uzatadi, `head -3` esa birinchi uch qatorni qoldiradi:

Uchinchi qator: *interface conversion: interface \{\} is main.Buyurtma, not int* — «interface konversiyasi:
`interface {}` (yaʼni `any`) ichida `main.Buyurtma` bor, `int` emas». Toʻliq chiqishda bundan keyin panic
boʻlgan qator (`assert/main.go:21`) va `exit status 2` ham bor. Qoida: turga ishonchingiz komil boʻlmasa,
`v, ok := x.(T)` shaklini ishlating. Bu [GO-1.09](/lab/youtube/go/go-1-09) dagi map'ning comma ok shakli bilan bir xil gʻoya.

## Type switch: bir nechta tur

Turlar koʻp boʻlsa, ketma-ket assertion yozish oʻrniga **type switch** qulayroq. U qiymatlarni emas, turlarni
solishtiradi. `tswitch/main.go`:

```go filename="tswitch/main.go" showLineNumbers
// tswitch: type switch — bir nechta turni bitta switch'da tekshirish.
// go run ./tswitch
package main

import (
	"errors"
	"fmt"
)

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

func tavsifla(a any) string {
	switch v := a.(type) {
	case nil:
		return "hech narsa"
	case int, int64:
		return fmt.Sprintf("son: %v", v)
	case Buyurtma:
		return fmt.Sprintf("buyurtma, summa: %d", v.Summa)
	case error:
		return "xato: " + v.Error()
	default:
		return fmt.Sprintf("notanish tur: %T", v)
	}
}

func main() {
	for _, a := range []any{nil, 42, Buyurtma{Summa: 150000}, errors.New("disk toʻla"), 3.14} {
		fmt.Println(tavsifla(a))
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 15 | `func tavsifla(a any) string {` | `tavsifla` («tavsifla») qiymatni turiga qarab tasvirlaydi |
| 16 | `switch v := a.(type) {` | `.(type)` faqat `switch` ichida yoziladi. `v` — yangi oʻzgaruvchi, har bir case'da oʻz turini oladi |
| 17–18 | `case nil:` | interface boʻsh boʻlsa tanlanadi (tur ham, qiymat ham yoʻq) |
| 19–20 | `case int, int64:` | bir case'da ikki tur: `v` bu yerda `any` boʻlib qoladi, shuning uchun uni faqat chiqaramiz |
| 21–22 | `case Buyurtma:` | bitta tur: `v` — `Buyurtma`, `v.Summa` ishlaydi |
| 23–24 | `case error:` | interface ham case boʻla oladi: `Error()` metodi bor har qanday tur |
| 25–26 | `default:` | qolgan hamma turlar |
| 31 | `[]any{nil, 42, …, 3.14}` | beshta har xil qiymat; `errors.New` — [GO-1.06](/lab/youtube/go/go-1-06) dagi xato yasash |

Oʻylab koʻring: `3.14` uchun nima chiqadi? **A)** `son: 3.14` · **B)** `notanish tur: float64`

<details>
<summary>Javob</summary>

**B.** `3.14` turi yoʻq konstanta, `any` ga solinganda u default turini oladi: `float64`. `case int, int64:` unga
mos kelmaydi, shuning uchun `default` ishlaydi. «A» ni tanlagan boʻlsangiz, JS'dagi kabi «son — son» deb
oʻylagansiz: Go'da `int` va `float64` — ikki xil tur.

</details>

```console
$ go run ./tswitch
hech narsa
son: 42
buyurtma, summa: 150000
xato: disk toʻla
notanish tur: float64
```

Har bir qiymat oʻz case'iga tushdi. TS'da `typeof`/`instanceof` bilan turni toraytirish (narrowing) mumkin, lekin
interface bilan emas: yuqorida koʻrdik, TS interface'i dastur ishlayotganda yoʻq. Go'da esa `case error:` ishlaydi.

Endi `fmt` `Buyurtma` ning `String` metodini qanday topganini bilamiz. `fmt` paketining oʻzida xuddi shunday type
switch bor:

```console
$ sed -n 658,676p $(go env GOROOT)/src/fmt/print.go
		switch verb {
		case 'v', 's', 'x', 'X', 'q':
			// Is it an error or Stringer?
			// The duplication in the bodies is necessary:
			// setting handled and deferring catchPanic
			// must happen before calling the method.
			switch v := p.arg.(type) {
			case error:
				handled = true
				defer p.catchPanic(p.arg, verb, "Error")
				p.fmtString(v.Error(), verb)
				return

			case Stringer:
				handled = true
				defer p.catchPanic(p.arg, verb, "String")
				p.fmtString(v.String(), verb)
				return
			}
```

`Println` uchun `verb` — `'v'`. `fmt` qiymat `error` mi yoki `Stringer` mi, shuni tekshiradi, va `error` birinchi
turadi. Shu tekshiruv tufayli `fmt` sizning turingizni oldindan bilmasa ham, uning metodini chaqiradi. Bu switch'dan
oldin `fmt` yana `Formatter` ni ham tekshiradi (README'da). `defer p.catchPanic(…)` qatorini eslab qoling: u
jumboqning oxirgi boʻlagi.

## Pauza: 0 va 0 tengmi?

Ikkalasida ham nol:

```go
var a any = 0        // int
var b any = int64(0) // int64

```

`a == b` nima beradi? **A)** `true` · **B)** `false` · **C)** kompilyatsiya xatosi

<details>
<summary>Javob</summary>

**B: `false`.** Ikki interface teng boʻlishi uchun ichidagi turlar ham, qiymatlar ham bir xil boʻlishi kerak. Bu
yerda qiymatlar nol, lekin turlar har xil: `int` va `int64`. Go spec: *"Two interface values are equal if they have
identical dynamic types and equal dynamic values or if both have value nil."* — «ikki interface qiymati, agar
dinamik turlari (ichidagi turlari) bir xil va dinamik qiymatlari teng boʻlsa, yoki ikkalasi ham `nil` boʻlsa, teng».

«A» ni tanlagan boʻlsangiz, interface faqat qiymatni solishtiradi deb oʻylagansiz. «C» ni tanlagan boʻlsangiz, Go
`int` va `int64` ni solishtirishga ruxsat bermaydi deb oʻylagansiz. Ikki oddiy oʻzgaruvchi uchun bu toʻgʻri
(`mismatched types int and int64`). Lekin ikkalasi ham `any` turida, shuning uchun solishtirish kompilyatsiya
boʻladi va dastur ishlayotganda bajariladi.

</details>

## Typed nil: jumboqqa qaytamiz

Endi boshidagi jumboqni ochish uchun hamma narsa bor. `hook` ni toʻliq ishga tushiramiz. Uchinchi qator
interface'ning ichini koʻrsatadi:

```console
$ go run ./hook
err: <nil>
xato bor!
ichida: *main.SummaXato, <nil>
```

`tekshir` xatoni `*SummaXato` pointer'ida saqlaydi va uni `error` sifatida qaytaradi. Summa toʻgʻri boʻlsa, pointer
`nil` boʻlib qoladi. Lekin `error` — interface. `return xato` pointer'ni `error` ga aylantirganda, interface'ning tur
soʻziga `*SummaXato` yoziladi, qiymat soʻzi esa `nil` boʻladi:

| Qator | `xato` (`*SummaXato`) | `err` ichida: tur | `err` ichida: qiymat | `err != nil` |
|---|---|---|---|---|
| 18 `var xato *SummaXato` | `nil` | — | — | — |
| 22 `return xato` → 26 `err := …` | `nil` | `*SummaXato` | `nil` | `true` |
| toʻgʻrisi: `return nil` | — | — | — | `false` |

Interface faqat tur ham, qiymat ham boʻsh boʻlganda `nil` ga teng. Bu yerda tur bor, shuning uchun `err != nil`
sharti doim `true`. Bunday interface **typed nil** deyiladi: turi yozilgan `nil`. Go FAQ'dagi misol ham aynan shu:
*"(T=\*int, V=nil). Such an interface value will therefore be non-nil even when the pointer value V inside is nil."*
— «bunday interface qiymati, ichidagi V pointer `nil` boʻlsa ham, `nil` emas».

JS'da `null` — turi yoʻq bitta qiymat, Python'dagi `None` ham. Go'da esa interface ichidagi `nil` pointer oʻz turini
eslab qoladi.

## Nega ekran ham aldadi

Unda nega ekranga `err: <nil>` chiqdi? `Error` metodiga qaraymiz:

```console
$ sed -n 15p hook/main.go
func (e *SummaXato) Error() string { return fmt.Sprintf("summa notoʻgʻri: %d", e.Summa) }
```

`Println` `err` ni oldi, type switch'da `case error` ga tushdi va `Error()` ni chaqirdi. Metod `nil` pointer orqali
`e.Summa` ni oʻqimoqchi boʻldi va panic qildi ([GO-1.11](/lab/youtube/go/go-1-11) dagi *nil pointer dereference*). Lekin
`fmt` `Error()` ni chaqirishdan oldin `defer p.catchPanic(…)` qoʻygan edi:

```console
$ sed -n 588,596p $(go env GOROOT)/src/fmt/print.go
func (p *pp) catchPanic(arg any, verb rune, method string) {
	if err := recover(); err != nil {
		// If it's a nil pointer, just say "<nil>". The likeliest causes are a
		// Stringer that fails to guard against nil or a nil pointer for a
		// value receiver, and in either case, "<nil>" is a nice result.
		if v := reflect.ValueOf(arg); v.Kind() == reflect.Pointer && v.IsNil() {
			p.buf.writeString(nilAngleString)
			return
		}
```

`catchPanic` panic'ni `recover` bilan ushlaydi ([GO-1.09](/lab/youtube/go/go-1-09)). Argument `nil` pointer boʻlgani uchun u
shunchaki `<nil>` deb yozadi. Izohda: *"If it's a nil pointer, just say "&lt;nil>""* — «agar bu `nil` pointer boʻlsa,
shunchaki `<nil>` de». Yaʼni ekran ham bizni chalgʻitdi: `<nil>` panic'ning izi edi. Haqiqatni `%T` aytadi:
`*main.SummaXato`. Xatoni tekshirayotganda ekrandagi matnga emas, `%T` va `err == nil` ga qarang.

## Tuzatish: aniq return nil

Tuzatish oddiy. Xato boʻlmasa, pointer oʻzgaruvchini emas, toʻgʻridan-toʻgʻri `nil` qaytaring. `fix/main.go`:

```go filename="fix/main.go" showLineNumbers
// fix: xato yoʻq boʻlsa, oddiy nil qaytaramiz.
// go run ./fix
package main

import "fmt"

type Buyurtma struct {
	Summa   int64
	Tolandi bool
}

type SummaXato struct{ Summa int64 }

func (e *SummaXato) Error() string { return fmt.Sprintf("summa notoʻgʻri: %d", e.Summa) }

func tekshir(b Buyurtma) error {
	if b.Summa <= 0 {
		return &SummaXato{Summa: b.Summa}
	}
	return nil
}

func main() {
	for _, b := range []Buyurtma{{Summa: 150000}, {Summa: -5}} {
		err := tekshir(b)
		fmt.Printf("summa %d → err == nil: %v, err: %v\n", b.Summa, err == nil, err)
	}
}
```

| Qator | Kod | Nima oʻzgardi |
|---|---|---|
| 17–19 | `if b.Summa <= 0 { return &SummaXato{…} }` | xato boʻlsa, uning manzili darhol qaytadi; `*SummaXato` oʻzgaruvchisi yoʻq |
| 20 | `return nil` | xato boʻlmasa, aniq `nil`: interface'ning ikkala soʻzi ham boʻsh |
| 24 | `for _, b := range []Buyurtma{{Summa: 150000}, {Summa: -5}} {` | ikki buyurtma: toʻgʻri va notoʻgʻri. Slice literal ichida `Buyurtma` turini qayta yozish shart emas |
| 26 | `fmt.Printf("summa %d → err == nil: %v, err: %v\n", …)` | summani, `err == nil` ni va `err` ni chiqaradi |

```console
$ go run ./fix
summa 150000 → err == nil: true, err: <nil>
summa -5 → err == nil: false, err: summa notoʻgʻri: -5
```

Endi toʻgʻri summada `err == nil: true`, notoʻgʻri summada esa xato matni chiqdi: bu safar `Error()` haqiqiy
pointer bilan chaqirildi.

Go FAQ ikkita qoida beradi. Birinchisi: *"the function must return an explicit nil"* — «funksiya aniq `nil` qaytarishi
kerak». Ikkinchisi: xato qaytaradigan funksiya imzosida aniq tur (`*SummaXato`) emas, `error` yozilsin: *"It's a good idea for
functions that return errors always to use the error type in their signature … rather than a concrete type such as
\*MyError, to help guarantee the error is created correctly."*

solishtirish doim `true`». Keyingi qatorlar sababini aytadi: chap tomon — 26-qatordagi funksiya chaqiruvining
birinchi qaytgan qiymati, va *tekshir never returns a nil interface value* — «`tekshir` hech qachon `nil` interface
qiymatini qaytarmaydi». Buyruq bir xato topgani uchun 0 dan farqli kod bilan tugaydi, shuning uchun CI'da ishlatish
mumkin.

staticcheck Go bilan birga kelmaydi. Oʻrnatish: `go install honnef.co/go/tools/cmd/staticcheck@latest`, u
`~/go/bin` ga tushadi. Uni loyihangiz tekshiruvlariga qoʻshib qoʻying.

## Xulosa: interface qoidalari

1. **Interface yashirin bajariladi.** Tur kerakli interface'ni bajarishiga ishonch kerak boʻlsa, kompilyatsiya
   vaqtidagi tekshiruv qoʻshing (Effective Go, «Interface checks»):

```go
   var _ fmt.Stringer = Buyurtma{}
```

   `_` — nomsiz oʻzgaruvchi: qiymat tashlab yuboriladi, faqat kompilyatorning tekshiruvi qoladi. `String` ni
   oʻchirsangiz, dastur kompilyatsiya boʻlmaydi. Pointer receiver uchun: `var _ fmt.Stringer = (*Buyurtma)(nil)`
   (Go FAQ).
2. **Interface qiymati — (tur, qiymat) juftligi.** U faqat ikkalasi ham boʻsh boʻlganda `nil`.
3. **Turga ishonchingiz komil boʻlmasa, comma ok bilan tekshiring:** `v, ok := x.(T)`. Koʻp tur boʻlsa — type
   switch.
4. **Xato qaytaradigan funksiyada `error` turini va aniq `nil` ni qaytaring.** Typed nil'ni staticcheck SA4023
   topadi.
5. **Interface kichik boʻlsin.** Rob Pike (Go Proverbs, 2015): *"The bigger the interface, the weaker the
   abstraction"* — «interface qancha katta boʻlsa, abstraksiya shuncha zaif».

Keyingi darsda xatolarni chuqurroq oʻrganamiz: xatoni oʻrash (`%w`), `errors.Is` va `errors.AsType`.

## Chuqurroq (ixtiyoriy): `<nil>` — tasodif

`hook` da ekranga `<nil>` chiqqani tasodif: `Error()` maydonni oʻqigani uchun panic qildi, `fmt` esa uni yashirdi.
`Error()` receiver'ga tegmasa, typed nil uchun ham oʻz matnini chiqaradi. Buni tekshirish uchun alohida dastur
(kurs papkasida yoʻq, `matn/main.go` sifatida ishga tushirildi):

```go
package main

import "fmt"

type AXato struct{ Kod int }

// Error receiver'ga tegmaydi: nil pointer bilan ham ishlaydi.
func (e *AXato) Error() string { return "A xato" }

type BXato struct{ Kod int }

// Error e.Kod ni oʻqiydi: nil pointer bilan panic.
func (e *BXato) Error() string { return fmt.Sprint("B xato: ", e.Kod) }

func main() {
	var a *AXato
	var b *BXato
	var errA, errB error = a, b
	fmt.Println(errA, errB)
}
```

```console
$ go run -trimpath matn/main.go
A xato <nil>
```

Ikkalasi ham typed nil, ikkalasi ham `nil` ga teng emas. Lekin `AXato` `A xato` deb yozildi, `BXato` esa `<nil>`.
Shuning uchun ekrandagi matn interface `nil` mi yoki yoʻqmi, buni aytmaydi. `-trimpath` faqat xabarlardagi fayl
yoʻlini qisqa qiladi.

`fmt` ning toʻliq tartibi (`handleMethods`, README): avval `Formatter`, `%#v` uchun `GoStringer`, keyin `%v`, `%s`,
`%x`, `%X`, `%q` uchun avval `error`, keyin `Stringer`.

Bu tuzoqni oʻzgartirish takliflari boʻlgan (Dave Cheney, «Typed nils in Go 2», 2017; Go issue #22729). Hech biri
qabul qilinmagan: #22729 2026-11-25 holatida hali ochiq (`LanguageChangeReview`), muhokamadagi asosiy eʼtiroz —
orqaga moslik (eski kod buzilmasligi).

## Koʻp uchraydigan xatolar

**1. `nil` pointer'ni `error` sifatida qaytarish (typed nil).** Bu mavzuning klassik xatosi. Kompilyatsiya ham,
`go vet` ham jim, `if err != nil` esa doim `true` («Typed nil: jumboqqa qaytamiz» boʻlimi). **Tuzatish:** xato
boʻlmasa aniq `return nil`, funksiya imzosida `error`. staticcheck'ni CI'ga qoʻshing: SA4023 buni topadi.

**2. Ekrandagi `<nil>` ga ishonish.** `fmt.Println(err)` `<nil>` chiqarsa ham, `err` `nil` boʻlmasligi mumkin
(«Nega ekran ham aldadi»). **Tuzatish:** tekshirayotganda `fmt.Printf("%T %v\n", err, err)` yoki `err == nil` ni
chiqaring.

**3. Pointer receiver'li metod va qiymat.** `String` `*Buyurtma` da yozilgan boʻlsa, `var s fmt.Stringer = b`
kompilyatsiya boʻlmaydi (*method String has pointer receiver*), `fmt.Println(b)` esa jim xom struct chiqaradi
(«Pointer receiver» boʻlimi). **Tuzatish:** `&b` bering yoki metodni value receiver bilan yozing. Kompilyatsiya
vaqtidagi tekshiruv `var _ fmt.Stringer = Buyurtma{}` buni darhol koʻrsatadi.

**4. Comma ok'siz type assertion.** `n := a.(int)` ichida boshqa tur boʻlsa, dastur panic bilan toʻxtaydi
(«Type assertion» boʻlimi). **Tuzatish:** `n, ok := a.(int)` va `ok` ni tekshiring, yoki type switch.

**5. Ichida slice bor interface'larni `==` bilan solishtirish.** Kompilyator `any` larni solishtirishga ruxsat
beradi, lekin ichidagi turni solishtirib boʻlmasa, dastur ishlayotganda panic boʻladi. (Kurs papkasida yoʻq,
`slicecmp/main.go` sifatida ishga tushirildi.)

```go
package main

import "fmt"

func main() {
	var a, b any = []int{1}, []int{1}
	fmt.Println(a == b)
}
```

```console
$ go run -trimpath slicecmp/main.go
panic: runtime error: comparing uncomparable type []int

goroutine 1 [running]:
main.main()
	./main.go:7 +0x72
exit status 2
```

*runtime error: comparing uncomparable type []int* — «runtime xatosi: solishtirib boʻlmaydigan `[]int` turini
solishtirish». `./main.go:7` — 7-qator, `a == b`. Slice, map va funksiyani `==` bilan solishtirib boʻlmaydi. Ular
interface ichida boʻlsa, kompilyator buni koʻrmaydi. **Tuzatish:** ichidagi turni assertion bilan oling va
`slices.Equal` kabi funksiya bilan solishtiring. Panic'siz umumiy yechim — uy vazifasidagi «Qiyin» topshiriq.

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** Interface qiymati qachon `nil` ga teng?

<details>
<summary>Javob</summary>

Faqat ikkala soʻzi ham boʻsh boʻlganda: ichida tur ham, qiymat ham yoʻq. Ichida `nil` pointer boʻlsa, tur soʻzi
toʻla, shuning uchun interface `nil` emas.

</details>

**2.** Bu kod nima chiqaradi? **A)** `true true` · **B)** `true false` · **C)** `false false`

```go
var e *SummaXato
var err error = e
fmt.Println(e == nil, err == nil)
```

<details>
<summary>Javob</summary>

**B: `true false`.** `e` — oddiy pointer, u `nil`. `err` esa interface: ichida `(tur: *SummaXato, qiymat: nil)`,
shuning uchun `nil` emas. «A» ni tanlagan boʻlsangiz, `err` ga faqat qiymat koʻchadi deb oʻylagansiz.

Toʻliq dastur (kurs papkasida yoʻq, `tekshir2/main.go` sifatida ishga tushirildi):

```go
package main

import "fmt"

type SummaXato struct{ Summa int64 }

func (e *SummaXato) Error() string { return "summa notoʻgʻri" }

func main() {
	var e *SummaXato
	var err error = e
	fmt.Println(e == nil, err == nil)
}
```

```console
$ go run tekshir2/main.go
true false
```

</details>

**3.** `v, ok := x.(T)` da tur mos kelmasa, `v` va `ok` nima boʻladi? `ok` siz yozilsa-chi?

<details>
<summary>Javob</summary>

`ok` — `false`, `v` — `T` turining zero value'si, panic yoʻq. `ok` siz (`v := x.(T)`) tur mos kelmasa, dastur panic
bilan toʻxtaydi: `interface conversion: …`.

</details>

**4.** Type switch'dagi `case int, int64:` ichida `v` qaysi turda?

<details>
<summary>Javob</summary>

Switch'dagi ifodaning turida, yaʼni `any`. Bitta turli case'da (`case Buyurtma:`) `v` oʻsha turni oladi, bir nechta
turli case'da esa interface boʻlib qoladi.

</details>

**5.** TypeScript ham, Go ham interface'ni `implements` siz qabul qiladi. Unda nega Go'da `a.(fmt.Stringer)` ishlaydi,
TS'da esa `x instanceof Stringer` ishlamaydi?

<details>
<summary>Javob</summary>

TS interface'i faqat kompilyatsiya vaqtida bor va JS'ga oʻtkazilganda oʻchiriladi. Go'da interface qiymati tur
soʻzini dastur ishlayotganda ham saqlaydi, va runtime shu tur metodlarini tekshira oladi. `fmt` ham `String` ni
aynan shunday topadi.

</details>

**6.** [GO-1.11](/lab/youtube/go/go-1-11) dan: `var p *Buyurtma`, keyin `fmt.Println(p.Summa)`. Nima boʻladi? Bugun bunday
panic qayerda yashirinib qoldi?

<details>
<summary>Javob</summary>

Panic: *invalid memory address or nil pointer dereference*. Bugun xuddi shu panic `hook` dagi `Error()` ichida
boʻldi (`e.Summa`), lekin `fmt` uni `catchPanic` bilan ushlab, oʻrniga `<nil>` yozdi.

</details>

```go filename="homework/orta/main.go" showLineNumbers
// Uy vazifasi (oʻrta): tur ham Error, ham String metodiga ega. fmt.Println qaysi birini chaqiradi?
```

🟠 **Qiyin:** ikki `any` ni panic'siz solishtiradigan `teng(a, b any) bool` funksiyasini yozing. Ichida `[]int{1}`
boʻlsa, `a == b` panic beradi; `struct{ X any }` ichida boʻlsa ham.

<details>
<summary>Javob</summary>

```go filename="homework/qiyin/qiyin.go" showLineNumbers
// Uy vazifasi (qiyin): ikki interface'ni panic'siz solishtirish.
// a == b kompilyatsiya boʻladi, lekin ichidagi tur solishtirib boʻlmaydigan boʻlsa
// (slice, map, funksiya — yoki ularni ichida saqlagan struct) — runtime panic.
// go test -v ./homework/qiyin
package qiyin

// teng: a == b, lekin panic oʻrniga false.
// reflect.TypeOf(a).Comparable() yetarli emas: struct{ X any } "comparable" turi,
// ichidagi X esa slice boʻlishi mumkin. Shuning uchun panic'ni ushlaymiz.
func teng(a, b any) (natija bool) {
	defer func() {
		if recover() != nil {
			natija = false
		}
	}()
	return a == b
}
```

`defer` ichidagi `recover` panic'ni ushlaydi va natijani `false` qiladi ([GO-1.09](/lab/youtube/go/go-1-09); batafsil
GO-1.15 da). `(natija bool)` — nomli qaytgan qiymat: `defer` uni `return` dan keyin ham oʻzgartira oladi.
`reflect.TypeOf(a).Comparable()` yetarli emas: `struct{ X any }` turi «solishtirsa boʻladigan», lekin `X` ichida
slice boʻlsa, baribir panic. Testlar `homework/qiyin/qiyin_test.go` da. `TestPanic` panic'ni koʻrsatadi, `TestTeng`
jadval testi esa `struct ichida slice` holatini ham tekshiradi:

```console
$ go test -v ./homework/qiyin
=== RUN   TestPanic
    qiyin_test.go:14: panic: runtime error: comparing uncomparable type []int
--- PASS: TestPanic (0.00s)
=== RUN   TestTeng
--- PASS: TestTeng (0.00s)
PASS
ok  	github.com/abdurahmon27/go-backend-uz/lessons/013-interfaces-nil/homework/qiyin	0.002s
```

Oxirgi qatordagi vaqt har safar biroz oʻzgaradi. Testlar oʻzgarmagan boʻlsa, qayta ishga tushirganda vaqt oʻrnida `(cached)` chiqadi: Go oldingi natijani qayta ishlatdi.

</details>

🔴 **Guru:** `bosh(a any) bool` funksiyasini yozing: `a == nil` boʻlsa yoki ichida `nil` pointer, map, slice, chan
yoki func (typed nil) boʻlsa, `true`.

<details>
<summary>Javob</summary>

```go filename="homework/guru/guru.go" showLineNumbers
// Uy vazifasi (guru): interface ichida typed nil bormi? go test -v ./homework/guru
package guru

import "reflect"

// bosh: a == nil yoki ichida nil pointer/map/slice/chan/func (typed nil) boʻlsa true.
func bosh(a any) bool {
	if a == nil {
		return true
	}
	v := reflect.ValueOf(a)
	switch v.Kind() {
	case reflect.Pointer, reflect.Map, reflect.Slice, reflect.Chan, reflect.Func:
		return v.IsNil()
	}
	return false
}
```

`reflect` paketi interface ichidagi qiymatni dastur ishlayotganda oʻrganadi. `reflect.ValueOf(a)` ichidagi qiymatni
oladi, `Kind()` uning turkumini aytadi (pointer, map, slice…), `IsNil()` esa bu turkumdagi qiymat `nil` mi, shuni.
`reflect.ValueOf` hech qachon `Interface` turkumini qaytarmaydi, chunki u interface ichidagi qiymatni oladi. Bu
diagnostika uchun; oddiy kodda typed nil'ni umuman yaratmaslik (`return nil`) toʻgʻri yoʻl.

```console
$ go test -v ./homework/guru
=== RUN   TestBosh
--- PASS: TestBosh (0.00s)
PASS
ok  	github.com/abdurahmon27/go-backend-uz/lessons/013-interfaces-nil/homework/guru	0.002s
```

</details>
