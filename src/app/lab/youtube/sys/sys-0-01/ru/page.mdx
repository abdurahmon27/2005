## Что вы узнаете

У вашей команды есть заметки со стендапов за год: 12 текстовых файлов, 360 строк. Сделанная задача записана просто,
открытая начинается с `TODO`. Вопрос: сколько задач Азиз ещё не закрыл? Можно написать маленький скрипт на Python или
Node. А сегодня мы получим ответ без скрипта, соединив в терминале три маленькие команды.

**Одна идея:** если шаг за шагом соединить вертикальной чертой (pipe) маленькие команды, каждая из которых делает
одно дело, они ответят на большой вопрос без скрипта: `grep` фильтрует, `wc -l` считает — точно как
`filter().filter().length` в JavaScript.

К концу урока вы:

- найдёте нужные строки во всех файлах папки с помощью `grep -r` и прочитаете вывод в форме `путь к файлу:строка`;
- посчитаете строки с помощью `|` и `wc -l` и добавите в середину новый этап-фильтр;
- проверите промежуточный результат, убрав последний этап конвейера (pipeline);
- объясните, почему папка или `-r` у `grep` после вертикальной черты молча даёт неверное число.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| `grep` | фильтрует строки: строку с образцом пропускает целиком, остальные отбрасывает | grep |
| `wc -l` | считает пришедшие строки и печатает одно число | wc (word count), `-l` = lines |
| вертикальная черта `\|` | передаёт вывод команды слева на вход команды справа | pipe |

Есть и два вспомогательных слова: **стандартный ввод** (stdin) — откуда команда читает данные, если файл не указан;
**stderr** — отдельный выход для сообщений об ошибках (только в разделе «Глубже»). **Образец** (pattern) — текст,
который ищет `grep`; сегодня это просто слово: `TODO`, `Aziz`.

Перед началом один вопрос на знакомом вам языке. В массиве четыре строки:

```js
const qatorlar = [
  "Aziz: saytga logo qoʻydi",
  "TODO Aziz: menyuni tuzatish",
  "Malika: narxlarni yangiladi",
  "TODO Malika: rasmlarni kichraytirish",
];
qatorlar.filter((q) => q.includes("TODO")).filter((q) => q.includes("Aziz")).length;
```

(`qatorlar` — «строки»; заметки на узбекском: «поставил логотип на сайт», «исправить меню», «обновила цены»,
«уменьшить картинки».) Чему равно последнее выражение?

**A)** `1` · **B)** `2` · **C)** `4`

<details>
<summary>Ответ</summary>

**A: `1`.** Первый `filter` оставляет две строки с `TODO`, второй — те из них, где есть `Aziz`, а `length` считает
оставшееся. Если вы выбрали «`2`», вы забыли второй фильтр: `Aziz` есть в двух строках, но одна из них не `TODO`.
Сегодня мы соберём ровно эту цепочку в терминале.

</details>

## От цепочки в JavaScript к терминалу

В JavaScript вы написали бы этот вопрос так: отфильтровать массив строк по `TODO`, потом по `Aziz`, в конце взять
`length`. В терминале каждому шагу соответствует одна команда:

| JavaScript | Терминал | Что делает |
|---|---|---|
| `.filter(q => q.includes("TODO"))` | `grep TODO` | оставляет строки с образцом |
| `.filter(q => q.includes("Aziz"))` | `grep Aziz` | фильтрует ещё раз |
| `.length` | `wc -l` | считает строки |
| `.` (цепочка) | `\|` (вертикальная черта) | передаёт результат одного шага следующему |

Для сравнения — тот же вопрос для папки `eslatmalar/` на Node. Этого файла нет в папке курса: сохраните его в папке
урока под именем `zanjir.js` («цепочка») и запустите в Node 24.

```js
// zanjir.js: xuddi shu savol JavaScript'da (Node 24)
const fs = require("fs");

const qatorlar = fs.readdirSync("eslatmalar")
  .flatMap((f) => fs.readFileSync(`eslatmalar/${f}`, "utf8").trimEnd().split("\n"));

const javob = qatorlar
  .filter((q) => q.includes("TODO"))
  .filter((q) => q.includes("Aziz"))
  .length;

console.log(javob);
```

| Строка | Код | Что делает |
|---|---|---|
| 4–5 | `readdirSync` + `flatMap(…split("\n"))` | читает все файлы папки и собирает один массив строк |
| 7–10 | `.filter(…).filter(…).length` | строки с `TODO`, потом с `Aziz`, потом их количество (`javob` — «ответ») |
| 12 | `console.log(javob)` | печатает число |

```console
$ node zanjir.js
3
```

Это программа из 12 строк. В терминале тот же ответ даёт одна строка:
`grep -r TODO eslatmalar | grep Aziz | wc -l`. Теперь соберём её шаг за шагом.

## Производственная линия: pipe

Представьте pipe как производственную линию. Каждый этап делает одно дело и кладёт результат на следующую ленту.
Первый этап берёт со склада, то есть из папки. Следующие читают только с ленты перед собой.

В терминале **этап** — это команда, а **лента** — вертикальная черта `|`. По-английски её называют **pipe**. Вся
цепочка называется **pipeline** (конвейер).

```text
 склад (папка)            лента (|)            лента (|)
 ┌────────────┐      ┌──────────────┐     ┌────────────┐     ┌───────────┐
 │ eslatmalar/│ ───► │ grep -r TODO │ ──► │ grep Aziz  │ ──► │  wc -l    │ ──► экран
 └────────────┘      │  фильтрует   │     │ фильтрует  │     │  считает  │
                     └──────────────┘     └────────────┘     └───────────┘
                      этап 1:              этап 2:             этап 3:
                      читает папку         читает ленту        читает ленту
```

От цепочки над массивом есть отличие, и оно важно:

| | JavaScript `filter().length` | Конвейер в терминале |
|---|---|---|
| Что такое этап | вызов метода внутри одной программы | отдельная программа (отдельный процесс) |
| Когда работает | по очереди: сначала строится весь новый массив, потом следующий метод | все этапы работают одновременно |
| Что передаётся | массив (объекты, с типами) | поток текста: байты, разбитые на строки |

Shell запускает каждую команду конвейера в отдельном процессе, и они работают одновременно. Данные идут **потоком**
через небольшой буфер в ядре (POSIX §2.9.2, bash(1), pipe(7)). Третья строка — «только текст» — понадобится в этом
уроке дважды.

## Этап 1: `grep`

Первый этап — `grep`. Он фильтрует строки: строку с образцом пропускает целиком, остальные отбрасывает.

```console
$ grep -r TODO eslatmalar
eslatmalar/seshanba.txt:TODO Bobur: zaxira nusxa olish
eslatmalar/seshanba.txt:TODO Aziz: mijozga javob yozish
eslatmalar/chorshanba.txt:TODO Malika: biz haqimizda matni
eslatmalar/chorshanba.txt:TODO Aziz: telefon raqamini tekshirish
eslatmalar/dushanba.txt:TODO Aziz: menyuni tuzatish
eslatmalar/dushanba.txt:TODO Malika: rasmlarni kichraytirish
```

Пока не смотрите на вывод. Сначала разберём команду по частям:

| Часть | Что это |
|---|---|
| `grep` | имя команды (программы) |
| `-r` | **флаг**: читать папку рекурсивно, все файлы внутри (как `-g` в npm) |
| `TODO` | образец: искомый текст |
| `eslatmalar` | откуда читать: папка |

`grep` различает регистр: если написать образец как `todo`, ничего не найдётся (это мы увидим в «Частых ошибках»).

Теперь вопрос. Здесь `grep` читает три файла. Как выглядит каждая строка вывода?

**A)** только сама строка · **B)** путь к файлу, двоеточие, потом строка · **C)** только имена файлов

<details>
<summary>Ответ</summary>

**B.** Посмотрите на вывод выше: вышло шесть строк, две из понедельника. В начале каждой строки путь к файлу
(`eslatmalar/dushanba.txt`), после двоеточия — сама строка. Когда читается несколько файлов, `grep` так показывает,
из какого файла строка (руководство GNU grep, `-H`: «это поведение по умолчанию, если файлов больше одного»).

Если вы выбрали «A», вы думали о `grep` по одному файлу: `grep TODO eslatmalar/dushanba.txt` действительно печатает
только строки. «C» — это другой флаг, `grep -l`, он печатает только имена файлов.

</details>

Вывод попал на экран, потому что следующего этапа нет. Порядок файлов у вас может быть другим: `grep -r` читает
файлы в том порядке, который отдаёт файловая система (здесь вторник, среда, понедельник).

## Этап 2: `wc -l`

Второй этап — `wc -l`. `wc` — это *word count*, а с флагом `-l` — только число строк. Подключаем его вертикальной
чертой:

```text
grep -r TODO eslatmalar  |  wc -l
└─────── этап 1 ──────┘  │  └─ этап 2: файл не указан → читает с ленты
                       лента
```

Файл для `wc` не указываем. Если файла нет, он читает то, что пришло по вертикальной черте. Этот вход команды
называется **стандартный ввод** (*standard input*, коротко **stdin**). wc(1): «без FILE … читает стандартный ввод».

Что теперь появится на экране?

**A)** те же 6 строк · **B)** одно число: `6` · **C)** одно число: `13`

<details>
<summary>Ответ</summary>

**B: `6`.** Строки `grep` попали не на экран, а на ленту. `wc -l` посчитал их и напечатал только число.

Если вы выбрали «A», вы пропустили `|`: строки теперь идут в `wc`, а не на экран. «C», `13`, — число всех строк в
папке. Но `wc` не читал папку, он считает только то, что пришло по ленте.

</details>

```console
$ grep -r TODO eslatmalar | wc -l
6
```

Откуда могло бы взяться `13`? Если бы `wc` прочитал все файлы. `cat` выводит файлы один за другим, а `*.txt` — это
все `.txt`-файлы папки:

```console
$ cat eslatmalar/*.txt | wc -l
13
```

## Новый этап в середине: `grep Aziz`

Теперь главный вопрос: задачи Азиза. Как второй `filter` в JavaScript, ставим в середину ещё один `grep` с образцом
`Aziz`. Ему не даём ни `-r`, ни папку: строки он берёт с ленты. Три этапа, две вертикальные черты.

Какое число появится на экране? Вспомните шесть строк из прошлого шага.

**A)** `6` · **B)** `3` · **C)** `5`

<details>
<summary>Ответ</summary>

**B: `3`.** На ленте было шесть строк `TODO`, в трёх из них есть `Aziz`.

Если вы выбрали «A», вы думали, что второй `grep` ничего не отбрасывает. «C», `5`, — это **все** записи Азиза,
вместе со сделанными. Это число даёт другая команда, мы увидим её в «Частых ошибках».

</details>

Сначала уберём `wc -l` и посмотрим, что лежит на ленте:

```console
$ grep -r TODO eslatmalar | grep Aziz
eslatmalar/seshanba.txt:TODO Aziz: mijozga javob yozish
eslatmalar/chorshanba.txt:TODO Aziz: telefon raqamini tekshirish
eslatmalar/dushanba.txt:TODO Aziz: menyuni tuzatish
```

Три строки, все — строки `TODO` Азиза. Так удобно проверять конвейер: убрать последний этап и посмотреть на
промежуточный результат. Это похоже на `console.log` в середине цепочки JavaScript. Теперь возвращаем `wc -l`:

```console
$ grep -r TODO eslatmalar | grep Aziz | wc -l
3
```

Что лежит на каждой ленте:

| Место | Что там | Строк |
|---|---|---|
| склад: `eslatmalar/` | все строки трёх файлов | 13 |
| лента 1: после `grep -r TODO eslatmalar` | строки `TODO` (с путём к файлу) | 6 |
| лента 2: после `grep Aziz` | строки `TODO` Азиза | 3 |
| экран: после `wc -l` | одно число | `3` |

Скрипт на Node `zanjir.js` тоже сказал `3`.

## Порядок важен: `wc -l` в середине

А если поменять этапы местами: `wc -l` в середине, `grep Aziz` в конце?

```text
grep -r TODO eslatmalar | wc -l | grep Aziz
```

Что появится на экране?

**A)** `3` · **B)** `6` · **C)** ничего

<details>
<summary>Ответ</summary>

**C: ничего.** `wc -l` кладёт на ленту одну строку: `6`. Последний `grep` не находит в ней образец `Aziz` и ничего не
печатает.

Если вы выбрали «A», вы думали, что порядок этапов не важен. Если «B» — вы не учли последний `grep`: `6` на ленте
есть, но фильтр `grep Aziz` она не проходит.

</details>

```console
$ grep -r TODO eslatmalar | wc -l | grep Aziz
```

Команда ничего не напечатала: ни числа, ни ошибки. Уберём последний `grep`:

```console
$ grep -r TODO eslatmalar | wc -l
6
```

`wc` положил на ленту одну строку: `6`. `grep Aziz` в ней ничего не находит. (Когда `grep` ничего не нашёл, его код выхода
равен 1, но на экран он ничего не пишет.)

В JavaScript вызов `filter` после `length` даёт TypeError (в Node 24:
`TypeError: [1,2].length.filter is not a function`). А терминал молчит, потому что на ленте только текст, типов нет:
`6` — просто строка текста. Порядок важен: сначала фильтруем, потом считаем.

## Папка за год

Теперь вопрос из начала: папка за целый год. Что нужно изменить в конвейере? Подумайте, прежде чем читать дальше.

Только имя папки: `yil` вместо `eslatmalar`.

```console
$ grep -r TODO yil | grep Aziz | wc -l
22
```

У Азиза 22 открытые задачи. Мы просмотрели 12 файлов одной строкой. Для уверенности — размер папки (`ls` выводит
список файлов папки, каждый на своей строке, потому что вывод идёт в pipe):

```console
$ ls yil | wc -l
12
```

```console
$ cat yil/* | wc -l
360
```

```console
$ grep -r TODO yil | wc -l
93
```

12 файлов, 360 строк, 93 `TODO`. Папку `yil/` создаёт `yasash.py` из папки курса (результат всегда одинаковый). В ней
каждый `TODO` — отдельная задача, и она никогда не записана как «сделано». Поэтому `22` — действительно число
открытых задач.

## Глубже (необязательно): ошибки не попадают на ленту

Ещё одна тонкость. У каждой программы два выхода: основной вывод (*standard output*, **stdout**) и отдельный поток
для сообщений об ошибках — **stderr**. Это та же разница, что между `console.log` и `console.error` в Node:
`console.error` тоже пишет в stderr. Обычная вертикальная черта передаёт только основной вывод.

Если добавить несуществующую папку (`arxiv`, «архив»), что скажет `wc -l`? Сначала подумайте.

```console
$ grep -r TODO eslatmalar arxiv | wc -l
grep: arxiv: No such file or directory
6
```

Ошибка осталась на экране: «`arxiv`: нет такого файла или папки». А `wc` всё равно говорит `6`: строка ошибки не
попала на ленту и не посчиталась. Поэтому конвейер может показать ошибку и всё равно дать верное число. Как
отправить на ленту и ошибки (`2>&1 |` или `|&` в bash) — в части «Chuqurroq» README курса и в следующих уроках.

## Частые ошибки

### 1. Папка у `grep` после вертикальной черты

Это самая частая ошибка. Что, если по привычке написать второму `grep` тоже `-r` и имя папки?

```text
grep -r TODO eslatmalar | grep -r Aziz eslatmalar | wc -l
```

**A)** всё равно `3` · **B)** больше `3` · **C)** `0`

<details>
<summary>Ответ</summary>

**B: `5`.** `grep`, которому дали файл или папку, не смотрит на ленту — он возвращается на склад. Он читает папку с
начала и выводит все записи Азиза, сделанные тоже. А `wc` их считает.

</details>

```console
$ grep -r TODO eslatmalar | grep -r Aziz eslatmalar | wc -l
5
```

Сообщения об ошибке нет, число просто неверное. Что на самом деле вывел второй `grep`, можно увидеть без последнего
этапа. Он читает папку, а не ленту, поэтому его вывод совпадает с этим:

```console
$ grep -r Aziz eslatmalar
eslatmalar/seshanba.txt:Aziz: tugma rangini oʻzgartirdi
eslatmalar/seshanba.txt:TODO Aziz: mijozga javob yozish
eslatmalar/chorshanba.txt:TODO Aziz: telefon raqamini tekshirish
eslatmalar/dushanba.txt:Aziz: saytga logo qoʻydi
eslatmalar/dushanba.txt:TODO Aziz: menyuni tuzatish
```

Три `TODO` и две сделанные задачи: 5. Работа первого `grep` пропала зря. Правило написано в `grep --help`: «без FILE
читает `.`, если поиск рекурсивный, иначе `-`» (`-` — стандартный ввод).

**Правило:** этапу после вертикальной черты не давайте ни `-r`, ни папку. Правильно так:

```console
$ grep -r TODO eslatmalar | grep Aziz | wc -l
3
```

### 2. Только `-r`, без папки

Убрать папку, но оставить `-r` тоже нельзя: `grep -r` без файла читает **текущую папку** (`.`), а не ленту.

```console
$ grep -r TODO eslatmalar | grep -r Aziz | wc -l
112
```

`112` — строки с `Aziz` во всех файлах папки урока (и в `yil/`, и в README). Это число зависит от содержимого папки,
у вас оно может быть другим. Главное: это не `3`, и ошибки нет.

### 3. Только папка, без `-r`

Обратный случай: папка есть, `-r` нет. На этот раз `grep` выдаёт ошибку:

```console
$ grep -r TODO eslatmalar | grep Aziz eslatmalar | wc -l
grep: eslatmalar: Is a directory
0
```

Как читать: `grep:` — ошибку написал `grep`; `eslatmalar: Is a directory` — «`eslatmalar` — это папка»: без `-r`
`grep` папки не читает. На ленту ничего не попало, `wc` сказал `0`. Исправление то же: уберите и папку.

### 4. Образец строчными буквами

```console
$ grep -r todo eslatmalar | wc -l
0
```

Ошибки нет, просто `0`. `grep` различает регистр: в файлах написано `TODO`, а не `todo`. Пишите образец так, как в
файле. (Чтобы не различать регистр, есть `grep -i`.)

### 5. Терминал в другой папке

Если запустить команду вне папки урока (например, в домашней папке):

```console
$ grep -r TODO eslatmalar | wc -l
grep: eslatmalar: No such file or directory
0
```

«`eslatmalar`: нет такого файла или папки». Эта команда запущена вне папки урока. Исправление:
`cd go-backend-uz/lessons/sys-01-terminal` (или проверьте, где вы, с помощью `pwd`).

### 6. `wc -l` в середине

`… | wc -l | grep Aziz` ничего не печатает и не выдаёт ошибки: на ленте остаётся только `6`. Мы видели это в разделе
«Порядок важен». Исправление: сначала фильтровать, потом считать: `… | grep Aziz | wc -l`.

### 7. Терминал «завис»

Если написать `grep Aziz` отдельно (без вертикальной черты перед ним и без папки), `grep` ждёт стандартный ввод, то
есть клавиатуру. Кажется, что терминал не отвечает. Нажмите **Ctrl+C**: это останавливает работающую команду.

## Проверьте себя

1. Что делает вертикальная черта `|`?

<details>
<summary>Ответ</summary>

Передаёт вывод (stdout) команды слева на вход (stdin) команды справа. Вывод идёт не на экран, а следующему этапу.

</details>

2. Почему `grep` после вертикальной черты мы не даём папку (или `-r`)?

<details>
<summary>Ответ</summary>

Если дать папку или `-r`, `grep` не смотрит на ленту: он заново читает папку (или текущую папку). Фильтр
предыдущего этапа теряется, и число молча получается неверным (`5` или `112`, а не `3`).

</details>

3. Почему терминал не выдаёт ошибку, когда `wc -l` стоит в середине, а JavaScript выдаёт TypeError?

<details>
<summary>Ответ</summary>

На ленте только текст, типов нет. `wc -l` кладёт на ленту обычную текстовую строку `6`, следующий `grep` фильтрует её
как любую другую строку и ничего не находит. В JavaScript `length` возвращает число, а у числа нет метода `filter`.

</details>

4. Предскажите вывод:

```text
grep -r TODO eslatmalar | grep Bobur | wc -l
```

<details>
<summary>Ответ</summary>

`1`. Из шести строк `TODO` только одна — Бобура (`seshanba.txt`).

```console
$ grep -r TODO eslatmalar | grep Bobur
eslatmalar/seshanba.txt:TODO Bobur: zaxira nusxa olish
```

```console
$ grep -r TODO eslatmalar | grep Bobur | wc -l
1
```

</details>

5. Из начала урока: почему каждая строка вывода `grep -r TODO eslatmalar` начинается с пути вроде
   `eslatmalar/seshanba.txt:`?

<details>
<summary>Ответ</summary>

`grep` читает несколько файлов (`-r` читает все три файла папки). В этом случае он пишет перед каждой строкой, из
какого она файла: путь к файлу и двоеточие. Когда читается один файл, такого префикса нет.

</details>
