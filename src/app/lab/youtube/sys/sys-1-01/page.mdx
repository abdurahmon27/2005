## Nimani oʻrganasiz

Kompyuter bitta sonni oʻzining eng tez xotirasidan oladi. Keyin internetdagi saytdan javob kutadi. Bu ikki ish
orasida qancha farq bor? Agar birinchisi bir soniya davom etsa, ikkinchisi oʻn ikki yilga yaqin davom etadi. Bu
hisobni sahifa oxirida birga qilamiz.

**Bitta gʻoya:** kompyuter ichida har bir ish oʻz kutish vaqtiga ega, va bu vaqtlar million barobar farq qiladi.
Protsessorning eng tez xotirasidan bitta son ~1,5 ns, internetdagi saytdan javob ~0,55 s. Bugun bu vaqtlarni Go
dasturi bilan oʻzimiz oʻlchaymiz va dasturchilar yoddan biladigan mashhur jadval bilan solishtiramiz.

Dars oxirida siz:

- ns, µs va ms ni bir-biriga aylantirasiz va qaysi ish qaysi «qavat»da ekanini taxmin qila olasiz;
- `time.Now` / `time.Since` bilan sekin ishni koʻp marta oʻlchab, mediana va oraliqni oʻqiysiz;
- «faylga yozdim — demak diskda» xatosini tushunasiz va `f.Sync()` (fsync) narxini bilasiz;
- bitta HTTPS soʻrov nega yuzlab millisekund olishini bosqichlarga boʻlib tushuntirasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| kechikish | dastur biror narsani soʻragan paytdan javob kelguncha oʻtgan vaqt | latency |
| kesh | protsessor ichidagi kichik, juda tez xotira | cache |
| borib-kelish | kichik xabar boshqa kompyuterga borib, javobi qaytguncha oʻtgan vaqt | round trip |

Ikkita yordamchi soʻz ham bor. **SSD** — elektr oʻchganda ham maʼlumotni saqlaydigan disk: ichida aylanadigan qism
yoʻq, faqat chiplar. **fsync** — Linux'ga «maʼlumot diskka yetib borguncha kut» deydigan buyruq, Go'da `f.Sync()`.

## Vaqt birliklari: ms, µs, ns

Bugungi raqamlar uch xil birlikda chiqadi. Koʻz yumib ochish 100 dan 400 millisekundgacha davom etadi (BioNumbers
BNID 100706).

| Birlik | Yozilishi | Soniyaning qanchasi | Misol (bugungi oʻlchovlardan) |
|---|---|---|---|
| millisekund | ms | 1/1 000 | Wi-Fi orqali borib-kelish ~5 ms |
| mikrosekund | µs | 1/1 000 000 | SSD'dan 4 KiB oʻqish ~120–150 µs |
| nanosekund | ns | 1/1 000 000 000 | keshdan bitta son ~1,5 ns |

Har bir qadam — ming barobar: 1 ms = 1000 µs, 1 µs = 1000 ns. Go'da bu birliklar `time` paketida:
`time.Millisecond`, `time.Microsecond`, `time.Nanosecond`. Vaqt oraligʻi `time.Duration` turida turadi. Bu aslida
nanosekundlar soni (`int64`), lekin chop etilganda `1.29ms`, `146µs` kabi koʻrinadi.

## Kechikish (latency): soʻrovdan javobgacha

Dastur tarmoq orqali soʻrov yuborsa, javob kelguncha kutadi.
Bu kutish faqat tarmoqda emas: protsessor xotiradan son soʻraganda ham, dastur diskdan fayl oʻqiganda ham kutadi.

DSA-A.01 da xotirani choʻntak va omborga oʻxshatgan edik. Choʻntakdagi narsani darhol olasiz. Ombordagi narsaga borib
kelish kerak. Bugun bitta qavat qoʻshamiz: uzoqdagi arxiv, yaʼni disk. Undan ham uzoqrogʻi — boshqa kompyuter, tarmoq
orqali.

| Qavat | Oʻxshatish | Bugungi tartib |
|---|---|---|
| kesh (protsessor ichida) | choʻntak | nanosekundlar |
| operativ xotira (RAM) | ombor | ~100 ns |
| disk (SSD) | uzoqdagi arxiv | yuzlab mikrosekund |
| tarmoq, internet | qoʻshniga savol yuborib, javob kutish | millisekundlar, yuzlab ms |

Shu kutish vaqtini **kechikish** deymiz, inglizcha **latency**. Kechikish — bitta ish qancha *kutishini*
bildiradi. U soniyada nechta ish bajarilishini (inglizcha *throughput*) bildirmaydi. Bu ikkisi har xil narsa: uy
vazifasining «Guru» darajasida buni raqamlar bilan koʻramiz.

## Qanday oʻlchaymiz: `olcha` funksiyasi

Go'da vaqt ikki funksiya bilan oʻlchanadi:
`time.Now()` soatga qaraydi, `time.Since(boshi)` boshidan beri qancha vaqt oʻtganini aytadi. Videoda dasturning
yuragi qisqartirilgan holda koʻrsatilgan:

```go
for i := range n {
	boshi := time.Now()
	ish(i)
	vaqt := time.Since(boshi)
	natija = append(natija, vaqt)
}
```

1-qator ishni `n` marta takrorlaydi. 2-qator hozirgi vaqtni `boshi` («boshi» — boshlanish) degan yorliqqa
yopishtiradi (`:=` — yangi oʻzgaruvchi). 3-qator oʻlchanayotgan ishni (`ish`) bir marta bajaradi. 4-qator boshidan
beri oʻtgan vaqtni oladi. 5-qator uni `natija` («natija» — result) roʻyxatiga qoʻshadi.

Kurs papkasidagi haqiqiy funksiya (`olcha/main.go` dan, oʻzgarishsiz) bir oz ixchamroq: `vaqt` yorligʻi yoʻq.
`olcha` — «oʻlcha»:

```go
// olcha: ishni n marta bajarib, har birining vaqtini yozib boradi.
func olcha(nom string, n int, ish func(i int)) natija {
	r := natija{nom: nom}
	for i := range n {
		boshi := time.Now()
		ish(i)
		r.t = append(r.t, time.Since(boshi))
	}
	return r
}
```

| Kod | Nima qiladi |
|---|---|
| `func olcha(nom string, n int, ish func(i int)) natija` | uchta parametr: oʻlchov nomi (`nom`), necha marta (`n`) va oʻlchanadigan ish. `ish` — funksiya qiymati (GO-1.06). Natija — `natija` struct'i |
| `r := natija{nom: nom}` | boʻsh natija: nomi bor, vaqtlar roʻyxati hali boʻsh |
| `for i := range n` | `i` = 0, 1, …, n−1 (GO-1.05) |
| `boshi := time.Now()` | soatga qaraydi. Go'ning `time.Now()` ichida monoton soat ham bor: kompyuter soati toʻgʻrilansa ham `time.Since` toʻgʻri chiqadi |
| `ish(i)` | oʻlchanayotgan ishni chaqiradi: masalan, SSD'dan 4 KiB oʻqish |
| `r.t = append(r.t, time.Since(boshi))` | oʻtgan vaqtni (`time.Duration`) roʻyxat oxiriga qoʻshadi (GO-1.08) |
| `return r` | hamma vaqtlarni qaytaradi |

Nega koʻp marta? Har safar natija biroz boshqacha chiqadi: disk band boʻladi, tarmoqda paket kechikadi. Bitta
oʻlchovga ishonib boʻlmaydi (GO-1.07 qoidasi). Shuning uchun ish 30 dan 5000 martagacha takrorlanadi, keyin vaqtlar
tartiblanadi:

```go
// natija: bitta o'lchovning hamma vaqtlari.
type natija struct {
	nom string
	t   []time.Duration
	yoq int // tarmoq: javobsiz qolgan urinishlar
}

// p: tartiblangan vaqtlarning q-qismi, eng yaqin o'rin bo'yicha (0.5 = mediana; juft n da yuqori o'rtadagi).
func (n natija) p(q float64) time.Duration {
	s := slices.Clone(n.t)
	slices.Sort(s)
	return s[int(q*float64(len(s)-1)+0.5)]
}
```

`natija` struct'ida oʻlchov nomi va hamma vaqtlar (`t`) turadi. `yoq` («yoʻq») — tarmoqda 3 soniyada javob olmagan
urinishlar soni: ular vaqtga qoʻshilmaydi, alohida sanaladi. `p` metodi vaqtlarning nusxasini oladi (`slices.Clone`:
asl tartib buzilmasin), tartiblaydi va `q` ulushdagi elementni qaytaradi. Uchta ustun shundan chiqadi:

| Ustun | Maʼnosi | Qanday hisoblanadi |
|---|---|---|
| `marta` («marta» — times) | necha marta oʻlchandi | `len(n.t)` |
| `odatda` («odatda» — usually) | **mediana**: tartiblangan roʻyxatning oʻrtasi, natijalarning yarmi undan tez, yarmi sekin | `p(0.5)` |
| `oraliq` («oraliq» — range) | eng tez 10 % va eng sekin 10 % tashlab yuborilgandan keyin qolgani | `p(0.1) … p(0.9)` |

Nega oʻrtacha emas, mediana? Bitta 500 ms lik tarmoq urinishi 99 ta 5 ms lik urinishning oʻrtachasini ikki barobar
oshiradi (5 ms dan ~10 ms ga). Mediana esa 5 ms da qoladi. Grafana va APM vositalarida koʻradigan p50 / p90 / p99 xuddi shu
narsa.

Bitta muhim chegara: bu usul faqat **mikrosekund va undan sekin** ishlar uchun. `time.Now()` ning oʻzi bu noutbukda
~25 ns turadi («Chuqurroq» boʻlimida oʻlchaymiz). 1,5 ns lik ishni 25 ns lik soat bilan bittalab oʻlchab boʻlmaydi:
bunday ishlarga GO-1.07 dagi benchmark sikli kerak.

## Kesh va operativ xotira: choʻntak va ombor

**Kesh** — protsessor ichidagi kichik va juda tez xotira, bizning choʻntak. Kattaroq operativ xotira — ombor.
DSA-A.01 da ularni zanjir usuli bilan oʻlchagan edik. Bu darsda ular **qayta oʻlchanmadi**: raqamlar DSA-A.01 ning
`natija.txt` faylidan (10 oʻlchov mediani):

| Qayerdan | Hajm | Bitta oʻqish | Mashhur jadval |
|---|---|---|---|
| L1 kesh | 8 KiB | 1,52 ns | 0,5 ns |
| L2 kesh | 256 KiB | 4,23 ns | 7 ns |
| operativ xotira | 128 MiB | 105,8 ns | 100 ns |

```text
protsessor ──soʻraydi──▶ kesh (choʻntak)      ~1,5 ns
                            │ yoʻq boʻlsa
                            ▼
                    operativ xotira (ombor)    ~106 ns   ≈ 70 barobar uzoq
```

1,52 ns — har bir oʻqish oldingisini kutgan holdagi vaqt, yaʼni haqiqiy *kechikish*. Ketma-ket, bir-biriga bogʻliq
boʻlmagan oʻqishlar tezroq: DSA-A.01 da L1 dan 0,31 ns/element. Lekin bu kutish emas, oʻtkazish tezligi. Bugun bizni
kutish qiziqtiradi, shuning uchun hisob 1,52 ns dan.

## Disk: SSD va Linux'ning nusxasi

Disk — elektr oʻchganda ham maʼlumot saqlanib qoladigan joy, bizning uzoqdagi arxiv. Bu noutbukda disk SSD: ichida
aylanadigan qism yoʻq, faqat chiplar. Linux esa diskdan oʻqilgan faylning nusxasini operativ xotirada saqlab qoʻyadi.
Bu nusxa **page cache** deyiladi. Keyingi safar oʻsha joy soʻralsa, Linux diskka bormaydi, nusxadan beradi.

Dastur 4 KiB ni ikki xil oʻqiydi. Bir marta toʻgʻridan-toʻgʻri SSD'dan: buning uchun fayl `O_DIRECT` bayrogʻi bilan
ochiladi, u Linux'ning nusxasini chetlab oʻtadi (open(2)). Bir marta oddiy `os.Open` bilan, nusxadan. Kod
(`olcha/main.go`, oʻzgarishsiz):

```go
func disk() {
	tayyorla()
	r := rand.New(rand.NewPCG(3, 4))

	// 1) SSD'dan 4 KiB, tasodifiy joydan. O_DIRECT xotiradagi nusxani (page cache) chetlab o'tadi:
	// har bir o'qish haqiqatan SSD'ga boradi.
	f, buf, err := ochDirect(*faylYoli, kb4)
	tekshir(err)
	chiqar(olcha("SSD'dan 4 KiB", 5000, func(int) {
		_, err := f.ReadAt(buf, int64(r.IntN(hajm/kb4))*kb4)
		tekshir(err)
	}))
	f.Close()

	// 2) Xuddi shu 4 KiB, oddiy open bilan: avval 16 MiB ni bir marta o'qiymiz,
	// Linux uni operativ xotirada nusxa qilib saqlaydi, keyingi o'qishlar nusxadan.
	g, err := os.Open(*faylYoli)
	tekshir(err)
	defer g.Close()
	_, err = g.ReadAt(make([]byte, 16*mib), 0)
	tekshir(err)
	b := make([]byte, kb4)
	chiqar(olcha("nusxadan 4 KiB", 5000, func(int) {
		_, err := g.ReadAt(b, int64(r.IntN(16*mib/kb4))*kb4)
		tekshir(err)
	}))
}
```

| Kod | Nima qiladi |
|---|---|
| `kb4`, `mib`, `hajm` | konstantalar: 4 KiB, 1 MiB va sinov faylining hajmi («hajm» — size) 1 GiB |
| `tayyorla()` | («tayyorla» — prepare) 1 GiB lik `sinov.dat` ni tasodifiy baytlar bilan yaratadi, agar u hali yoʻq boʻlsa |
| `rand.New(rand.NewPCG(3, 4))` | tasodifiy sonlar generatori, har safar bir xil ketma-ketlik (`math/rand/v2`) |
| `ochDirect(*faylYoli, kb4)` | `*faylYoli` — `-fayl` flag'ining qiymati (standart `sinov.dat`; `*` pointer orqali qiymatni oʻqiydi). Funksiya faylni `O_DIRECT` bilan ochadi va 4 KiB bufer beradi. U `olcha/direct_linux.go` faylida: `O_DIRECT` bufer manzili 4096 ga karrali boʻlishini talab qiladi, shuning uchun bufer `syscall.Mmap` bilan olinadi |
| `f.ReadAt(buf, int64(r.IntN(hajm/kb4))*kb4)` | 1 GiB ichidagi tasodifiy 4 KiB lik joydan oʻqiydi. Tasodifiy joy — oldingi oʻqish keyingisiga yordam bermasin |
| `g.ReadAt(make([]byte, 16*mib), 0)` | faylning boshidagi 16 MiB ni bir marta oʻqiydi: Linux uni operativ xotirada nusxa qilib qoʻyadi |
| `g.ReadAt(b, …16*mib/kb4…)` | endi faqat shu 16 MiB ichidan oʻqiydi: hamma oʻqish nusxadan |
| `tekshir(err)` | («tekshir» — check) xato boʻlsa, xabar chiqarib, dasturni toʻxtatadi |

`O_DIRECT` haqiqatan diskka boradimi? Kurs README'si `/proc/diskstats` bilan tekshirgan: `olcha disk` paytida
qurilma +5066 ta oʻqish bajardi (5000 ta oʻlchov va 16 MiB). Demak, ha.

Endi taxmin qiling. Nusxa operativ xotirada turadi, operativ xotira esa ~100 ns edi. SSD — uzoqdagi arxiv. Nusxadan
oʻqish SSD'dan necha barobar tez?

**A)** 2 barobar · **B)** 20 barobar · **C)** 200 barobar

## Keng tarqalgan xato: «faylga yozdim — demak diskda»

Koʻp dasturchi shunday oʻylaydi: `write` qaytdi, demak maʼlumot diskda. Aslida Linux maʼlumotni avval omborga, yaʼni
operativ xotiradagi nusxaga qoʻyadi. Diskka esa keyinroq, oʻzi qulay paytda yozadi. Shu orada elektr oʻchsa, maʼlumot
yoʻqolishi mumkin. write(2) hujjati buni ochiq aytadi: «A successful return from write() does not make any guarantee
that data has been committed to disk» (muvaffaqiyatli `write` maʼlumot diskka yozilganini kafolatlamaydi).

```text
dastur: f.WriteAt(b, joy)
   │
   ▼
operativ xotira (ombor)  ◀── WriteAt shu yerda qaytadi. Elektr oʻchsa — yoʻqolishi mumkin
   │  keyinroq (Linux oʻzi tanlaydi)
   ▼
SSD (arxiv)              ◀── f.Sync() shu yergacha kutadi
```

Diskka yetib borguncha kutish uchun alohida buyruq bor: **fsync**. Go'da u `f.Sync()`: «faylning joriy tarkibini
doimiy xotiraga yozadi» (`os.File.Sync` hujjati). Linux'da uning ostida `fsync(2)` tizim chaqiruvi turadi.
Videodagi oʻxshatish: oddiy yozish — xatni pochta qutisiga tashlash, fsync esa — xatni manzilga
yetkazib, imzo olib qaytish.

Videoda kod ikki qatorga qisqartirilgan:

```go
f.WriteAt(b, joy)
f.Sync()
```

`WriteAt` `f` fayliga `b` baytlarni `joy` («joy» — place) degan oʻringa yozadi. `f.Sync()` disk «yozib boʻldim» deb
javob bermaguncha kutadi. Kurs papkasidagi toʻliq funksiya:

```go
func fsync() {
	f, err := os.Create("fsync.dat")
	tekshir(err)
	defer os.Remove("fsync.dat")
	defer f.Close()
	b := make([]byte, kb4)
	for i := range 256 { // 1 MiB joy: keyin shu joyga qayta-qayta yozamiz
		_, err := f.WriteAt(b, int64(i)*kb4)
		tekshir(err)
	}
	tekshir(f.Sync())

	chiqar(olcha("4 KiB yozish", 2000, func(i int) {
		_, err := f.WriteAt(b, int64(i%256)*kb4)
		tekshir(err)
	}))
	chiqar(olcha("4 KiB yozish + fsync", 300, func(i int) {
		_, err := f.WriteAt(b, int64(i%256)*kb4)
		tekshir(err)
		tekshir(f.Sync()) // Linux'da fsync(2): ma'lumot diskka yetib borguncha kutadi
	}))
}
```

| Kod | Nima qiladi |
|---|---|
| `os.Create("fsync.dat")` | yangi fayl. `defer os.Remove` va `defer f.Close` funksiya tugaganda uni yopib oʻchiradi |
| `for i := range 256 { f.WriteAt(b, …) }` | 256 × 4 KiB = 1 MiB joy tayyorlaydi; keyin aynan shu joyga qayta-qayta yozamiz |
| `tekshir(f.Sync())` | tayyorgarlikni diskka yetkazadi: oʻlchov boshlanishidan oldin hammasi diskda |
| `"4 KiB yozish", 2000` | oddiy yozish, 2000 marta |
| `"4 KiB yozish + fsync", 300` | yozish va har safar `f.Sync()`, 300 marta (sekinroq, shuning uchun kamroq) |
| `int64(i%256)*kb4` | `%` — boʻlinma qoldigʻi: joy 0, 1, …, 255, 0, 1, … boʻyicha aylanadi |

## Tarmoq: borib-kelish (round trip)

Tarmoq — kompyuterlarni sim yoki radio toʻlqin orqali bogʻlaydigan yoʻl. Bitta kompyuter kichik xabar yuboradi,
ikkinchisi javob qaytaradi. Xabar ketgandan javob kelguncha oʻtgan vaqt — **borib-kelish**, inglizcha **round trip**
(qisqasi RTT). `ping` buyrugʻi koʻrsatadigan `time=…ms` aynan shu.

Dastur borib-kelishni TCP ulanish bilan oʻlchaydi. Ulanish shunday boshlanadi: noutbuk SYN paketini yuboradi, qarshi
tomon SYN-ACK bilan javob beradi (RFC 9293 §3.5). Bu bitta toʻliq borib-kelish. Ertalab noutbuk Wi-Fi orqali
telefonga ulangan edi, internet telefondan kelardi. Dastur Wi-Fi tarmogʻining shlyuziga (default gateway, ertalab —
telefon) 53-port orqali ulanadi:

```go
func tarmoq() {
	// Wi-Fi orqali routergacha (bizda: telefon hotspot'i). TCP ulanish = SYN ketadi, SYN-ACK qaytadi:
	// bitta borib-kelish.
	addr := *lanAddr
	if addr == "" {
		gw, err := gateway()
		tekshir(err)
		addr = net.JoinHostPort(gw, "53")
	}
	ulan(addr) // isitish: hisobga kirmaydi
	chiqar(olchaTarmoq("Wi-Fi: borib-kelish", 100, func() bool { return ulan(addr) }))
}

// ulan: TCP ulanish o'rnatib, darhol yopadi (vaqtni olchaTarmoq o'lchaydi).
// Port yopiq bo'lsa, qurilma SYN'ga RST bilan javob beradi ("connection refused"):
// bu ham bitta to'liq borib-kelish. 3 soniyada javob kelmasa (paket yo'qoldi), false.
func ulan(addr string) bool {
	c, err := net.DialTimeout("tcp", addr, 3*time.Second)
	if errors.Is(err, syscall.ECONNREFUSED) {
		return true
	}
	var ne net.Error
	if errors.As(err, &ne) && ne.Timeout() {
		return false
	}
	tekshir(err)
	c.Close()
	return true
}
```

| Kod | Nima qiladi |
|---|---|
| `gateway()` | `/proc/net/route` dan shlyuz manzilini topadi (Linux) |
| `ulan(addr) // isitish` | birinchi urinish hisobga kirmaydi: Wi-Fi radiosi «uygʻonishi» oʻlchovni buzmasin |
| `olchaTarmoq(…, 100, …)` | `olcha` kabi, 100 marta, urinishlar orasida 100 ms pauza; javob kelmagan urinish vaqtga qoʻshilmaydi, sanaladi |
| `net.DialTimeout("tcp", addr, 3*time.Second)` | TCP ulanish: SYN ketadi, SYN-ACK qaytadi. 3 soniyada javob boʻlmasa — paket yoʻqolgan |
| `errors.Is(err, syscall.ECONNREFUSED)` | port yopiq boʻlsa, qurilma RST bilan javob beradi («connection refused»). Bu ham bitta toʻliq borib-kelish, shuning uchun `true` |
| `c.Close()` | ulanishni darhol yopadi: bizga faqat ulanish vaqti kerak |

## Internet: bitta soʻrov ichida nechta borib-kelish

Endi haqiqiy internet. `head -3` natijaning faqat birinchi uch qatorini koʻrsatadi (SYS-0.01):


Ikkinchi qator: go.dev javobini beradigan Google serverigacha bitta borib-kelish (TCP ulanish), 144 ms. Videoda 128 ms
edi. Shlyuzgacha ~5 ms edi: qolgani — undan keyingi yoʻl, provayder (ertalab — mobil operator) tarmogʻi va internet
orqali serverga.
Server qayerdaligini oʻlchamadik: javob sarlavhasida faqat `server: Google Frontend` bor.

Uchinchi qator: `https://go.dev/robots.txt` kichik faylini soʻraymiz, har safar yangi ulanish bilan. 529 ms (videoda
555 ms). Bu bitta borib-kelishdan 3,7 barobar uzoq. Nega? Bitta soʻrov aslida toʻrt bosqichdan iborat:

| Bosqich | Nima boʻladi | Borib-kelish |
|---|---|---|
| manzil topish (DNS) | `go.dev` nomi raqamli IP manzilga aylanadi | bitta, lekin yaqin serverga (ertalab javob telefondan kelgan) |
| ulanish (TCP) | SYN → SYN-ACK | bitta, serverga |
| shifrlash (TLS) | ikki tomon maʼlumotni begonalar oʻqiy olmaydigan qilib shifrlashga kelishadi | TLS 1.3 da bitta (RFC 8446 §2) + hisob-kitob |
| javob kutish | soʻrov ketadi, javobning birinchi bayti keladi | bitta + server ishi |

Brauzerda buni DevTools → Network → bitta soʻrov → **Timing** yorligʻida koʻrgansiz: «DNS Lookup», «Initial
connection», «SSL», «Waiting for server response». Go'da xuddi shu bosqichlarni `net/http/httptrace` paketi beradi.
Kod (`olcha/main.go` dagi `internet` funksiyasining bir qismi):

```go
		iz := &httptrace.ClientTrace{
			// DNS: go.dev nomidan IP manzilni topish
			DNSStart: func(httptrace.DNSStartInfo) { dns0 = time.Now() },
			DNSDone:  func(httptrace.DNSDoneInfo) { dD = time.Since(dns0) },
			// TCP: ulanish (bitta borib-kelish)
			ConnectStart: func(string, string) { tcp0 = time.Now() },
			ConnectDone:  func(string, string, error) { tD = time.Since(tcp0) },
			// TLS: shifrlangan kanal haqida kelishish
			TLSHandshakeStart: func() { tls0 = time.Now() },
			TLSHandshakeDone:  func(tls.ConnectionState, error) { sD = time.Since(tls0) },
			// so'rov yuborilgandan javobning birinchi baytigacha
			WroteRequest:         func(httptrace.WroteRequestInfo) { yubordi = time.Now() },
			GotFirstResponseByte: func() { jD = time.Since(yubordi) },
		}
```

`httptrace.ClientTrace` — `http.Client` har bir bosqichning boshida va oxirida chaqiradigan funksiyalar (hook'lar)
toʻplami. Har bir juftlik `time.Now()` va `time.Since()` bilan bitta bosqichni oʻlchaydi: `dD` — DNS, `tD` — TCP,
`sD` — TLS, `jD` — soʻrov yuborilgandan birinchi baytgacha (`iz` — «iz», trace; `yubordi` — «yubordi», sent).
Funksiyaning boshqa qismlari: `DisableKeepAlives: true` har bir soʻrovni yangi ulanish bilan qiladi, `"tcp4"` faqat
IPv4 ishlatadi, birinchi soʻrov esa isitish uchun tashlanadi (sertifikatlar yuklanadi).

## Chuqurroq (ixtiyoriy): nanosekundli ishlar, keep-alive va disk tarqoqligi

**Nanosekundli ishlarni qanday oʻlchaymiz.** `time.Now()` ning oʻzi qancha turadi? Uni bittalab oʻlchab boʻlmaydi,

```go filename="xotira/xotira_test.go" showLineNumbers
// Nanosekund darajasidagi amallar: ularni bittalab soat bilan o'lchab bo'lmaydi,
// shuning uchun GO-1.07 dagi kabi benchmark sikli ishlatiladi (b.Loop).
//
//	taskset -c 2 go test -run '^$' -bench . -count 10 ./xotira
//
// Kesh va operativ xotiradan bitta o'qish (L1, L2, RAM) bu yerda qayta o'lchanmaydi:
// ular DSA-A.01 darsida o'lchangan (../dsa-a01-cache, Zanjir benchmark'i).

import (
	"sync"
	"testing"
	"time"
)

// time.Now() ning o'zi qancha turadi? Shu sababli 1 ns lik amalni bittalab o'lchamaymiz.
func BenchmarkVaqt(b *testing.B) {
	var t time.Time
	for b.Loop() {
		t = time.Now()
	}
	_ = t
}

// Hech kim raqobat qilmayotgan mutex: Lock + Unlock juftligi.
func BenchmarkMutex(b *testing.B) {
	var mu sync.Mutex
	for b.Loop() {
		mu.Lock()
		mu.Unlock()
	}
}

const (
	mb    = 1 << 20    // 1 MiB
	katta = 512 << 20  // 512 MiB: L3 (12 MiB) dan ancha katta
	el    = mb / 8     // 1 MiB dagi int64 soni
	nKat  = katta / mb // nechta 1 MiB lik bo'lak
)

var yigindi int64

// 1 MiB ni ketma-ket o'qish (qo'shish), har safar keyingi bo'lakdan:
// 512 MiB aylanib chiqquncha bitta bo'lak keshda qolmaydi, demak o'qish operativ xotiradan.
func BenchmarkMegabayt(b *testing.B) {
	s := make([]int64, katta/8)
	for i := range s {
		s[i] = int64(i)
	}
	var y int64
	k := 0
	for b.Loop() {
		bolak := s[k*el : (k+1)*el]
		for _, v := range bolak {
			y += v
		}
		k = (k + 1) % nKat
	}
	yigindi = y
}
```

| 26–32 | `BenchmarkMutex` | hech kim raqobat qilmayotgan `sync.Mutex` ning `Lock` + `Unlock` juftligi (mutex — GO-1.22 da) |
| 34–39 | `const (…)` | 1 MiB, 512 MiB va ulardan chiqadigan sonlar. `<<` — chapga surish: `1 << 20` = 2²⁰ = 1 048 576 |
| 45–59 | `BenchmarkMegabayt` | 512 MiB lik slice'dan har safar keyingi 1 MiB boʻlakni ketma-ket qoʻshadi. 512 MiB keshga (L3 12 MiB) sigʻmaydi, demak oʻqish operativ xotiradan |
| 58 | `yigindi = y` | natijani paket oʻzgaruvchisiga yozadi: kompyuter sikl natijasi kerak emas deb uni tashlab yubormasin |

kutish». Dasturning oldingi versiyasida oʻlchangan (tadqiqot jurnali, biz qayta ishga tushirmadik): ochiq ulanish bilan
~0,28–0,34 s, yangi ulanish bilan ~0,7–0,8 s. Shuning uchun Go'da `http.Client` ni har soʻrovda yangidan yaratmang:
bitta klientni qayta ishlating.

**Disk tarqoqligi.** Yuqorida koʻrdik: yangi yaratilgan faylda SSD 73 µs, bir daqiqadan keyin 119 µs. Ertalabki
oʻlchovlarda ham shunday boʻlgan (68–81 µs → 116–145 µs). Sababi oʻrganilmagan (SSD ichidagi kesh boʻlishi mumkin, lekin
tekshirilmagan). Bunday holatda bitta raqamni emas, oraliqni va bir necha oʻlchovni koʻrsating.

## Koʻp uchraydigan xatolar

**1. «Faylga yozdim — demak diskda» (jim xato).** Hech qanday xato chiqmaydi. Elektr oʻchsa yoki server qulasa,
oxirgi yozuvlar yoʻqolishi mumkin («Keng tarqalgan xato» boʻlimi). **Tuzatish:** muhim maʼlumotdan keyin `f.Sync()`
qiling va uning xatosini tekshiring. Narxi ~1–2 ms, shuning uchun koʻp yozuvni yigʻib, bitta fsync qiling (uy
vazifasi, «Oʻrta»).

**2. `go run main.go` bitta faylni ishga tushiradi.** Papkadagi faylni nomi bilan bersangiz:

```console
$ go run olcha/main.go disk
# command-line-arguments
olcha/main.go:188:17: undefined: ochDirect
```

*undefined: ochDirect* — «`ochDirect` aniqlanmagan». `olcha/main.go:188:17` — fayl, qator, ustun. `ochDirect`
funksiyasi oʻsha papkadagi boshqa faylda, `direct_linux.go` da. Fayl nomini bersangiz, Go faqat shu faylni yigʻadi.
**Tuzatish:** paketni papka bilan bering: `go run ./olcha disk`.

**3. Qaysi oʻlchovni tanlashni unutish.** Argument bermasangiz:

```console
$ go run ./olcha
ishlatish: go run ./olcha disk|fsync|tarmoq|internet|hammasi
exit status 2
```

«ishlatish» — usage: dastur qaysi soʻzlarni kutishini aytadi va 2 kodi bilan chiqadi (`os.Exit(2)`). `exit status 2`
qatorini `go run` qoʻshadi. **Tuzatish:** `go run ./olcha disk` (yoki `fsync`, `tarmoq`, `internet`, `hammasi`).

**4. Nanosekundli ishni `time.Now()` bilan bittalab oʻlchash (jim xato).** Natija chiqadi, lekin u soatning narxi
(~25 ns), ishning emas. **Tuzatish:** benchmark sikli (`b.Loop()`, GO-1.07), «Chuqurroq» boʻlimi.

**5. Bitta oʻlchovga yoki oʻrtachaga ishonish (jim xato).** Tarmoq bir necha daqiqada 10 barobar oʻzgaradi (4–5 ms va
100 ms dan koʻp). Bitta sekin urinish oʻrtachani buzadi. **Tuzatish:** koʻp marta oʻlchang, mediana va p10 … p90 ni
koʻrsating, bir necha turda takrorlang (`olchov.sh` 5 tur qiladi).

**6. macOS yoki Windows'da «SSD» qatoriga ishonish (jim xato).** `O_DIRECT` faqat Linux'da. Boshqa tizimda
`olcha/direct_other.go` faylni oddiy ochadi va «SSD'dan» qatori aslida nusxani oʻlchashi mumkin: natija mikrosekund
emas, nanosekund chiqadi. **Tuzatish:** disk oʻlchovini Linux'da qiling.

**7. Wi-Fi ni data markaz bilan solishtirish.** «Biz mashhur jadvaldan 10 barobar sekinmiz» — notoʻgʻri xulosa:
jadvaldagi 500 µs bitta bino ichidagi tarmoq uchun. **Tuzatish:** solishtirishdan oldin har ikki raqam *nimani*
oʻlchaganini tekshiring.

## Oʻzingizni tekshiring

Avval oʻzingiz javob bering, keyin oching.

**1.** Bugun oʻlchaganlarimizdan eng tez joy qaysi va qancha?

<details>
<summary>Javob</summary>

Protsessorning keshi: bitta son ~1,5 ns (DSA-A.01, L1, zanjir usuli). Operativ xotira ~70 barobar uzoq (~106 ns).

</details>

**2.** «Faylga yozdim, demak diskda.» Toʻgʻrimi?

<details>
<summary>Javob</summary>

Yoʻq. `write` (Go'da `f.Write` / `f.WriteAt`) maʼlumotni operativ xotiradagi nusxaga qoʻyib qaytadi. Diskka yetib
borganini fsync kabi maxsus buyruq bildiradi (Go'da `f.Sync()`). Bizda u oddiy yozishdan 1762–2455 barobar sekin edi.

</details>

**3.** Internetdagi bitta HTTPS soʻrov nega bitta borib-kelishdan 3–4 barobar uzoq?

<details>
<summary>Javob</summary>

Chunki uning ichida bir necha borib-kelish bor: TCP ulanish (bitta), TLS kelishuvi (TLS 1.3 da bitta), soʻrov va
javob (bitta + server ishi), oldidan esa manzil topish (DNS). Ochiq ulanishni qayta ishlatish (keep-alive) birinchi
uchtasini olib tashlaydi.

</details>

**4.** Dastur 1000 ta yozuvni yozadi va har biridan keyin `f.Sync()` qiladi. Bu noutbukda taxminan qancha vaqt
ketadi?

**A)** ~1 ms · **B)** ~1–2 soniya · **C)** ~1 daqiqa

<details>
<summary>Javob</summary>

**B.** Bitta yozish + fsync bizda 1.29–1.62 ms: 1000 × ~1,5 ms ≈ 1,5 soniya. fsync'siz esa 1000 × ~0,7 µs ≈ 0,7 ms
(«A» — fsync'ni unutgan dastur). 10 ta yozuvga bitta fsync qilsangiz, uy vazifasidagi oʻlchov boʻyicha ~0,2 soniya.

</details>

**5.** GO-1.07 dan: nega `sync.Mutex` ning Lock + Unlock juftligini (~11 ns) `time.Now()` / `time.Since()` bilan
bittalab oʻlchamaymiz?

<details>
<summary>Javob</summary>

Chunki `time.Now()` ning oʻzi ~25 ns: soat oʻlchanayotgan ishdan qimmat. Benchmark sikli ishni millionlab marta
bajaradi va umumiy vaqtni soniga boʻladi (`ns/op`), shunda soatning narxi yoʻqoladi. Biz uni `xotira/` paketida
`b.Loop()` bilan oʻlchadik: 11.4 ns.

</details>

🟡 Kod (`uyvazifa/main.go` dan):

```go
// guruh: ma'lumotlar bazalaridagi "group commit" g'oyasi: bir nechta yozuv, bitta fsync.
func guruh() {
	f, err := os.Create("guruh.dat")
	tekshir(err)
	defer os.Remove("guruh.dat")
	defer f.Close()
	b := make([]byte, 4096)
	const n = 300
	for _, k := range []int{1, 10} { // k ta yozuvdan keyin bitta fsync
		t0 := time.Now()
		for i := range n {
			_, err := f.WriteAt(b, int64(i%256)*4096)
			tekshir(err)
			if (i+1)%k == 0 {
				tekshir(f.Sync())
			}
		}
		d := time.Since(t0)
		fmt.Printf("%2d ta yozuvga 1 fsync: bitta yozuvga %v\n", k, (d / n).Round(time.Microsecond))
	}
}
```

`k` — nechta yozuvdan keyin bitta fsync: avval 1, keyin 10. `(i+1)%k == 0` — har `k`-yozuvda. 300 ta yozuvning umumiy
vaqti 300 ga boʻlinadi. Natija: har yozuvga fsync — 1.77 ms/yozuv, 10 ta yozuvga bitta — 226 µs/yozuv, ~8 barobar tez
(README: uchta oʻlchovda 5–19 barobar). Bu maʼlumotlar bazalaridagi *group commit* gʻoyasi: narx asosan fsync'da,
yozuvlar sonida emas. Bahosi: bitta fsync oldidan 10 ta yozuv xavf ostida — elektr oʻchsa, ular birga yoʻqoladi.

🟠 TCP localhost: 6.6 µs, Unix domain socket: 2.8 µs — 2,3 barobar tez (README: uchta oʻlchovda 1,4–2,7 barobar).
Tarmoq kartasi ishlatilmaydi, lekin TCP qatlami (paket, tasdiq) baribir ishlaydi; Unix socket uni chetlab oʻtadi. Har
holda Wi-Fi'dagi ~5 ms dan ming barobar tez.

🔴 1 goroutine: bitta oʻqish 116 µs, soniyasiga 3472 ta. 32 goroutine: bitta oʻqish 223 µs (2 barobar sekin), lekin
soniyasiga 84 072 ta (24 barobar koʻp). NVMe SSD bir vaqtda koʻp soʻrovni parallel bajaradi. Kechikish (latency) va
soniyadagi ishlar soni (throughput) — har xil narsa: biri yomonlashganda ikkinchisi yaxshilanishi mumkin.

</details>
