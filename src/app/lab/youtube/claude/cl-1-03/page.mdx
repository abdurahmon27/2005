## Nimani oʻrganasiz

Claude Sonnet 5.5 ga bitta qator yozdik: «Go'da xato tekshirish ishlamayapti, nega?». Uch marta soʻradik, uch marta
340–374 soʻzli javob keldi. Har birida yettita taxmin, haqiqiy sabab esa 3- yoki 4-oʻrinda. Keyin xuddi shu modelga
xuddi shu xatoni boshqacha yozdik va 31 soʻzli, ishga tushirsa ishlaydigan tuzatish oldik. Model bir xil edi.
Nima oʻzgardi? Bugun buni yettita prompt, 21 ta saqlangan javob va ularni oʻlchaydigan Go dasturi bilan koʻramiz.

**Bitta gʻoya:** prompt — modelga yozilgan texnik topshiriq. Model faqat siz yozgan matnni koʻradi, shuning uchun
javobni eng koʻp kontekst (kod, versiya, kutilgan va haqiqiy natija) va natija formati oʻzgartiradi. Har qanday usulning
foydasini esa taxmin bilan emas, oʻlchab va ishga tushirib bilasiz.

Dars oxirida siz:

- bitta qatorli savolni bug report kabi toʻliq promptga aylantirasiz: kontekst, kod, haqiqiy natija, format va uning
  sababi;
- promptning qaysi qismi javobning nimasini oʻzgartirganini uch marta ishga tushirib va Go dasturi bilan oʻlchab
  koʻrsatasiz;
- few-shot misol va XML teglarni qachon qoʻshishni bilasiz: misol javobning shaklini oʻzgartiradi, toʻgʻriligini emas;
- eski qoʻllanmalardagi prefill va `temperature` hozirgi modellarda nega xato qaytarishini bilasiz.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| prompt | modelga yozgan topshirigʻingiz: savol, kontekst, kod, talablar, hammasi bitta matnda | prompt |
| few-shot misol | promptga qoʻyilgan namunaviy javob: «mana shunday yoz» | few-shot example |
| XML teg | promptning qismlarini ajratadigan `<kod>…</kod>` kabi belgilar | XML tag |

Yordamchi soʻzlar matnda birinchi uchraganda bitta gap bilan tushuntiriladi: **kontekst** (vazifa haqidagi maʼlumot),
**natija formati** (javob qanday koʻrinishda boʻlishi), **muvaffaqiyat mezoni** (javob qachon «yaxshi» hisoblanadi),
**system prompt** va **prefill**.

## Bitta qatorli savol: yettita taxmin

Birinchi prompt — bitta qator:

```console
$ cat promptlar/1-yomon.txt
Go'da xato tekshirish ishlamayapti, nega?
```

Uchala javob ham raqamlangan roʻyxat boʻldi. Birinchi javobning band nomlari:

```console
$ grep -E '^\*\*[0-9]' javoblar/1-yomon/1.txt
**1. Xato e'tiborsiz qoldirilgan**
**2. Shadowing (`:=` bilan o'zgaruvchini qayta e'lon qilish)**
**3. Nil interfeys tuzog'i**
**4. Xatolarni noto'g'ri solishtirish**
**5. Goroutine ichidagi xatolar**
**6. `defer` ichidagi xatolar**
**7. `panic`/`recover` bilan aralashtirish**
```

`grep -E '^\*\*[0-9]'` faqat `**` va raqam bilan boshlanadigan qatorlarni chiqaradi, yaʼni Markdown'dagi qalin
band nomlarini. Yettita taxmin, hammasi Go'da haqiqatan uchraydigan xatolar. Bizning xato — 4-band: oʻralgan xatoni
`==` bilan solishtirish. 2- va 3-javoblarda ham yettitadan taxmin, haqiqiy sabab 4- va 3-oʻrinda. Javob oxiri:

```console
$ tail -7 javoblar/1-yomon/1.txt

Aniq sababni topish uchun, iltimos, quyidagilarni yuboring:
- Muammoli kod bo'lagi
- Kutgan natija va aslida nima bo'layotgani
- Agar bor bo'lsa, xato xabari yoki chiqish (output)

Xohlasangiz, ish papkasidagi Go fayllarni o'zim ko'rib chiqaman, faqat qaysi fayl ekanini ayting.
```

Claude kodni, kutilgan va haqiqiy natijani soʻradi; 2- va 3-javoblar yana Go versiyasini (`go version`) ham soʻradi.
Bu yomon javob emas: kodsiz savolga boshqacha javob berib boʻlmaydi. Model taxmin qilmasdan javob bera olmaydi, chunki
kod uning koʻziga koʻrinmaydi. Oxirgi gap qiziq: tajribada Claude fayl oʻqiy olmasdi, buni keyingi boʻlimda koʻramiz.

## Tajriba qanday oʻtkazildi

Hamma javobni bitta skript oldi. U Claude Code'ning **print rejimini** (`claude -p`) ishlatadi: promptni beradi,
javobni chiqaradi va tugaydi, chat ochilmaydi.

```bash filename="takrorla.sh" showLineNumbers
#!/usr/bin/env bash
# takrorla.sh promptlar/2-kontekst.txt [N]
# Promptni Claude'ga N marta (standart 3) beradi, javoblarni javoblar/<prompt>/ ga yozadi:
#   <i>.txt   javob matni, oʻzgartirilmagan
#   <i>.json  sana, model, tokenlar, vaqt
# Javob har safar boshqacha boʻlishi mumkin: shuning uchun uchta javob saqlaymiz.
set -euo pipefail
prompt=$(realpath "$1"); n=${2:-3}; model=${MODEL:-claude-sonnet-5-5}
dir=$(realpath javoblar)/$(basename "$prompt" .txt); mkdir -p "$dir"
cd "$(mktemp -d)"   # boʻsh papka: CLAUDE.md va loyiha fayllari taʼsir qilmasin
for i in $(seq 1 "$n"); do
  # boʻsh system prompt, asboblarsiz: Claude faqat bizning promptni oladi
  claude -p --model "$model" --effort high --system-prompt "" --tools "" \
    --setting-sources "" --strict-mcp-config --disable-slash-commands \
    --no-session-persistence --output-format json < "$prompt" > raw.json
  jq -r .result raw.json > "$dir/$i.txt"
  jq --arg sana "$(date -u +%FT%TZ)" --arg model "$model" \
    --arg prompt "$(basename "$prompt")" \
    '{sana: $sana, model: $model, prompt: $prompt, effort: "high",
      stop_reason, duration_ms, output_tokens: .usage.output_tokens,
      input_tokens_jami: (.usage.input_tokens + .usage.cache_creation_input_tokens
                     + .usage.cache_read_input_tokens),
      models: (.modelUsage | keys)}' raw.json > "$dir/$i.json"
  echo "$dir/$i.txt: $(wc -w < "$dir/$i.txt") soʻz"
done
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 7 | `set -euo pipefail` | birorta buyruq yiqilsa, skript toʻxtaydi |
| 8 | `n=${2:-3}`, `model=${MODEL:-…}` | takrorlar soni (standart 3) va model (standart `claude-sonnet-5-5`) |
| 9 | `dir=…/javoblar/<prompt nomi>` | `promptlar/3-format.txt` → `javoblar/3-format/` |
| 10 | `cd "$(mktemp -d)"` | boʻsh vaqtinchalik papkaga oʻtadi: CLAUDE.md va loyiha fayllari javobga taʼsir qilmaydi |
| 13 | `--effort high --system-prompt "" --tools ""` | yuqori effort, boʻsh **system prompt**, asboblar yoʻq: Claude fayl oʻqiy olmaydi, buyruq ishlata olmaydi |
| 14–15 | `--setting-sources ""` … `--output-format json` | sozlamalar, MCP va slash-buyruqlar oʻchiq; sessiya saqlanmaydi; natija JSON |
| 16 | `jq -r .result` | javob matni `<i>.txt` ga oʻzgartirilmasdan yoziladi |
| 17–23 | `jq … > "$dir/$i.json"` | yoniga sana, model, effort, tokenlar soni va vaqt yoziladi |
| 24 | `wc -w` | ekranga javobning soʻzlar sonini chiqaradi |

**System prompt** — modelga sizning xabaringizdan oldin beriladigan doimiy koʻrsatma; CL-1.02 dagi Project koʻrsatmasi
shunga oʻxshaydi. Biz uni boʻsh qoldirdik, shunda javobga faqat promptning oʻzi taʼsir qiladi.

Ikkita halol eslatma (README'dan):

1. **CLI qoʻshimchasi.** `--system-prompt ""` boʻlsa ham CLI baribir qisqa tizim matnini qoʻshadi. Bir qatorli
   promptda `input_tokens_jami` 581, prompt oʻzi esa taxminan 12 token. Demak qoʻshimcha taxminan 570 token, uning
   mazmunini biz koʻrmaymiz. Yomon promptga kelgan «fayllarni oʻzim koʻrib chiqaman» gapi shundan boʻlsa kerak.
2. **Haiku yozuvi.** `.json` dagi `models` roʻyxatida `claude-haiku-5-5` ham bor. Bu CLI'ning oʻz kichik xizmat
   chaqiruvi, javobni Sonnet 5.5 yozgan.

Promptga toʻrt narsani navbat bilan qoʻshamiz: kontekst, natija formati, misol va XML teglar. Har qadamda javob
qanday oʻzgarishini Go dasturi bilan oʻlchaymiz. Yettita prompt bitta xato atrofida qurilgan, har biri oldingisiga
bitta narsa qoʻshadi:

| Prompt | Nima qoʻshildi | Savol |
|---|---|---|
| `1-yomon` | bitta qator | nega xato tekshirish ishlamayapti? |
| `2-kontekst` | kim, qaysi loyiha, Go versiyasi, kutilgan natija, butun kod, `go run` natijasi | xuddi shu |
| `3-format` | natija formati (aynan 3 qator) va nega shunday format | xuddi shu |
| `4-misol` | boshqa xato (nil map) uchun bitta namunaviy javob | xuddi shu |
| `5-xml` | 4 bilan bir xil mazmun, lekin XML teglarda | xuddi shu |
| `6-test` | kod + vazifa, XML teglarda | `holat` uchun jadval test yoz |
| `7-test-misol` | 6 + GO-1.07 dagi `kabisa` testi misol sifatida | xuddi shu |

7 prompt × 3 = 21 javob, uy vazifasida yana 2 × 3 = 6 javob. Hammasi GitHub'da, sanasi va modeli bilan.

## Kontekst: promptni bexabar hamkasbga koʻrsating

Anthropic'ning prompt yozish qoʻllanmasi (*Prompting best practices*) Claude'ni «aqlli, lekin ishga yangi kelgan
xodimga» oʻxshatadi: u sizning qoidalaringiz va ish jarayoningizni bilmaydi. Tekshirish usuli ham oʻsha yerda:
promptni vazifadan bexabar hamkasbga koʻrsating va undan shu boʻyicha ishlashni soʻrang.

Bizning bir qatorli savolni olgan hamkasb darhol soʻraydi: qaysi kod? qaysi Go versiyasi? nima kutilgan va nima
chiqdi? Bu savollarni har bir GitHub issue shabloni ham beradi: *steps to reproduce*, *expected*, *actual*, *version*.
Claude ham javob oxirida aynan shularni soʻradi. Prompt — shu maʼnoda texnik topshiriq (TZ): ijrochi faqat yozilganni
biladi.

Ikkinchi promptda hamkasb soʻragan hamma narsa bor. Boshi:

```console
$ head -3 promptlar/2-kontekst.txt
Men Go'ni o'rganyapman va bozor degan onlayn do'kon backend'ini yozyapman. Go 1.26.8.
Mavjud bo'lmagan buyurtma uchun 404 qaytishi kerak, lekin 500 qaytyapti.
Xatoni o'zim tuzatib, sababini tushunmoqchiman.
```

Uch qatorda: kim yozyapti va qaysi loyiha, Go versiyasi, kutilgan natija (404) va haqiqiy natija (500). Uchinchi
qatorni eslab qoling, u keyin muhim boʻladi. Bu **kontekst** — vazifa haqidagi maʼlumot. CL-1.01 dagi context
window'dan farqi: context window — model koʻradigan butun matn, kontekst esa siz unga qoʻshgan kerakli faktlar.

Ostida butun kod. Bu promptga qoʻyilgan fayl:

```go filename="bozor/main.go" showLineNumbers
package main

import (
	"errors"
	"fmt"
)

var ErrTopilmadi = errors.New("buyurtma topilmadi")

var buyurtmalar = map[string]string{"1": "olma, 2 kg"}

func topish(id string) (string, error) {
	b, ok := buyurtmalar[id]
	if !ok {
		return "", fmt.Errorf("topish %s: %w", id, ErrTopilmadi)
	}
	return b, nil
}

// holat: handler shu kodni HTTP javobga yozadi
func holat(err error) int {
	if err == nil {
		return 200
	}
	if err == ErrTopilmadi {
		return 404
	}
	return 500
}

func main() {
	for _, id := range []string{"1", "42"} {
		_, err := topish(id)
		fmt.Printf("GET /buyurtma/%s → %d %v\n", id, holat(err), err)
	}
}
```

| Qator | Kod | Nima qiladi |
|---|---|---|
| 8 | `var ErrTopilmadi = errors.New(…)` | paket darajasidagi bitta xato qiymati, **sentinel xato** (GO-1.14): `ErrTopilmadi` («topilmadi») |
| 10 | `var buyurtmalar = map[string]string{…}` | «baza» oʻrnida map: faqat `"1"` buyurtma bor (`buyurtmalar` — «buyurtmalar», *orders*) |
| 12–18 | `func topish(id string) (string, error)` | buyurtmani qidiradi (`topish` — «topish», *find*); topilmasa, `ErrTopilmadi` ni `%w` bilan oʻrab qaytaradi |
| 15 | `fmt.Errorf("topish %s: %w", id, ErrTopilmadi)` | yangi xato: matni `topish 42: buyurtma topilmadi`, ichida asl `ErrTopilmadi` |
| 21–29 | `func holat(err error) int` | xatoni HTTP holat kodiga aylantiradi (`holat` — «holat», *status*): `nil` → 200, topilmadi → 404, boshqasi → 500 |
| 25 | `if err == ErrTopilmadi {` | **xato shu yerda**: oʻralgan xato `ErrTopilmadi` ning oʻzi emas |
| 31–35 | `main` | ikki soʻrovni taqlid qiladi: `/buyurtma/1` va `/buyurtma/42` |
| 34 | `fmt.Printf("GET /buyurtma/%s → %d %v\n", …)` | `%s` — matn, `%d` — butun son, `%v` — xatoning matni (`nil` boʻlsa `<nil>`) |

Prompt kod ostiga uning haqiqiy natijasini ham qoʻyadi. Uni oʻzingiz oling:

```console
$ go run ./bozor
GET /buyurtma/1 → 200 <nil>
GET /buyurtma/42 → 500 topish 42: buyurtma topilmadi
```

42-buyurtma yoʻq, 404 kutilgan, lekin 500 qaytdi. Sababni GO-1.14 ni koʻrganlar biladi:

```text
topish("42") qaytargan err:
  *fmt.wrapError  "topish 42: buyurtma topilmadi"
        │ Unwrap()
        ▼
  ErrTopilmadi    "buyurtma topilmadi"

err == ErrTopilmadi            → false  (ikki xil qiymat)
errors.Is(err, ErrTopilmadi)   → true   (zanjir boʻylab ichkariga qaraydi)
```

`==` faqat tashqi qiymatni solishtiradi. `errors.Is` esa xatolar zanjiri boʻylab `Unwrap` qilib boradi va ichida
`ErrTopilmadi` ni topadi. Tuzatish — bitta qator:

```console
$ diff bozor/main.go tuzatildi/main.go
25c25
< 	if err == ErrTopilmadi {
---
> 	if errors.Is(err, ErrTopilmadi) {
```

`diff` ikki faylning farqini chiqaradi: `25c25` — «25-qator oʻzgardi», `<` — eski fayl, `>` — yangi fayl.

Doimiy kontekstni (kimsiz, qaysi loyiha, qaysi Go versiyasi) har safar qayta yozish shart emas: buning uchun CL-1.02 dagi
Project koʻrsatmasi bor. Bu tajribada esa uni ataylab promptning oʻziga yozdik, shunda oʻlchov toza boʻladi.

## Kontekst javobi: sabab topildi, tayyor qator yoʻq

Kontekst qoʻshildi. Javobda nima boʻladi deb oʻylaysiz?

**A)** sabab topiladi va ichida koʻchirib qoʻyiladigan `if errors.Is(err, ErrTopilmadi) {` boʻladi · **B)** sabab
topiladi, lekin tayyor qator boʻlmaydi · **C)** yana yettita taxmin, chunki savol oʻzgarmadi

<details>
<summary>Javob</summary>

**B.** Uchala javobni oʻqib chiqdik: uchalasi ham sababni toʻgʻri topdi (`%w` bilan oʻralgan xato `==` bilan
topilmaydi, `errors.Is` kerak). Javob 196, 208 va 234 soʻzga qisqardi. Lekin hech birida tayyor
`errors.Is(err, ErrTopilmadi)` qatori yoʻq. «A» ni tanlagan boʻlsangiz, prompt ichidagi bitta gapni eʼtiborsiz
qoldirdingiz. «C» ni tanlagan boʻlsangiz, savol emas, kontekst javobni oʻzgartirishini unutdingiz.

</details>

Bitta javob hatto hujjat linkini berdi va shartni oʻzingiz almashtiring dedi:

```console
$ grep -h "o'zingiz almashtiring" javoblar/2-kontekst/*.txt
`errors.Is(err, target)` imzosini [pkg.go.dev/errors#Is](https://pkg.go.dev/errors#Is) sahifasida ko'rib chiqing va `holat` ichidagi shartni o'zingiz almashtiring.
```

`grep -h` mos qatorni fayl nomisiz chiqaradi. Nega tayyor qator yoʻq? Sababi promptning oʻzida: «Xatoni oʻzim tuzatib,
sababini tushunmoqchiman» degan edik. Claude shu istakni bajardi: yoʻl koʻrsatdi, kodni yozmadi. Kontekst javobning
aniqligini ham, ohangini ham oʻzgartiradi. «Sabab toʻgʻri» degan baho dastur bilan emas, qoʻlda oʻqib berilgan: bu
yerda «tayyor qator yoʻq» qismini esa pastdagi oʻlchov dasturi ham tasdiqlaydi.

## Natija formati: uch qator va «nega»

Uchinchi promptga **natija formati**ni qoʻshamiz — javob qanday koʻrinishda boʻlishi kerakligi. Bu dars nomidagi
**cheklov**: aynan uch qator, boshqa hech narsa. Prompt oxiri:

```console
$ tail -4 promptlar/3-format.txt
Javobni terminalda o'qiyman, shuning uchun o'zbekcha, aynan uch qator yoz, boshqa hech narsa qo'shma:
Sabab: <bitta gap>
Tuzatish: <o'zgaradigan bitta Go qatori>
Tekshirish: <bitta buyruq>
```

Birinchi qatorda format bilan birga uning sababi ham bor: «javobni terminalda oʻqiyman». Anthropic hujjati (*Add context
to improve performance*) shunday deydi: qoida nega muhimligini tushuntirsangiz, Claude maqsadingizni yaxshiroq tushunadi,
«Claude can generalize from the explanation» («Claude tushuntirishdan umumlashtira oladi»). Bu hujjatning gapi: sabab
gapining alohida taʼsirini biz oʻlchamadik.

Format — bu API kontrakti kabi: javobni oʻqiydigan tomon (siz, terminal yoki skript) qaysi maydon qayerda ekanini

```go
// formatda: boʻsh boʻlmagan qatorlar aynan uchta va kerakli soʻzlar bilan boshlanadi
func formatda(javob string) bool {
	var q []string
	for _, l := range strings.Split(javob, "\n") {
		if strings.TrimSpace(l) != "" {
			q = append(q, strings.TrimSpace(l))
		}
	}
	return len(q) == 3 && strings.HasPrefix(q[0], "Sabab:") &&
		strings.HasPrefix(q[1], "Tuzatish:") && strings.HasPrefix(q[2], "Tekshirish:")
}
```

Javob qatorlarga boʻlinadi, boʻsh qatorlar tashlanadi. Keyin uchta shart: qatorlar aynan uchta, har biri kerakli soʻz
bilan boshlanadi. `strings.HasPrefix(s, p)` — `s` matni `p` bilan boshlanadimi.

`Tuzatish:` qatorini ajratib olish:

```go
// tuzatish: «Tuzatish:» qatoridagi Go kodi (` belgilarisiz)
func tuzatish(javob string) (string, bool) {
	for _, l := range strings.Split(javob, "\n") {
		l = strings.TrimSpace(l)
		if s, ok := strings.CutPrefix(l, "Tuzatish:"); ok {
			s = strings.TrimSpace(strings.Trim(strings.TrimSpace(s), "`"))
			return s, s != ""
		}
	}
	return "", false
}
```

`strings.CutPrefix` qator boshidagi `Tuzatish:` ni kesib, qolganini qaytaradi; `ok` — prefiks bor edi. `strings.Trim(…,
"`")` Markdown'dagi teskari tirnoqlarni olib tashlaydi: `` `if errors.Is(err, ErrTopilmadi) \{` `` →
`if errors.Is(err, ErrTopilmadi) {`.

`404` ustuni — eng muhimi, chunki u javobni ishga tushiradi:

```go
// ishlat: tuzatilgan kodni vaqtinchalik papkada ishga tushiradi, /buyurtma/42 holatini qaytaradi
func ishlat(kod, yangi string) string {
	if !strings.Contains(kod, eski) {
		return "eski qator topilmadi"
	}
	dir := vaqtinchalik(map[string]string{"main.go": strings.Replace(kod, eski, yangi, 1)})
	defer os.RemoveAll(dir)

	cmd.Dir = dir
	out, err := cmd.CombinedOutput()
	if err != nil {
		return "kompilyatsiya xatosi"
	}
	for _, l := range strings.Split(string(out), "\n") {
		if s, ok := strings.CutPrefix(l, "GET /buyurtma/42 → "); ok {
			return strings.Fields(s)[0]
		}
	}
	return "natija yoʻq"
}
```

```text
javob ──► «Tuzatish:» qatori ──► bozor/main.go dagi 25-qator oʻrniga
                                  (eski = "if err == ErrTopilmadi {")
      ──► vaqtinchalik papka: main.go + go.mod ──► go run .
      ──► «GET /buyurtma/42 → 404 …» ──► "404"
```

`eski` — faylning boshidagi konstanta: `"if err == ErrTopilmadi {"`. `strings.Replace(kod, eski, yangi, 1)` uni Claude
bergan qator bilan almashtiradi (1 — faqat birinchisini). `vaqtinchalik` yangi papka yaratib, `main.go` va `go.mod`
yozadi. `exec.Command("go", "run", ".")` shu papkada dasturni ishga tushiradi, `cmd.CombinedOutput()` uning
chiqishini oladi. Kod kompilyatsiya boʻlmasa — `kompilyatsiya xatosi`. Boʻlsa, 42-buyurtma qatoridagi birinchi soʻz

Shu sababli `404` ustuni «Claude toʻgʻri aytdi» degani emas, «Claude bergan qator ishladi» degani. Model javobini

## Misol: soʻz bilan aytish qiyin boʻlgan shakl

**Few-shot misol** — promptga qoʻyilgan namunaviy javob. U soʻz bilan tushuntirish qiyin boʻlgan narsani koʻrsatadi.

yozamiz» deb mavjud test faylini ochib berasiz.

## XML teglar va uzun promptlar

5-, 6- va 7-promptlarda **XML teglar** ishlatilgan: promptning har bir qismi oʻz tegi ichida. Markdown'dagi kod bloki
yoki multipart soʻrovdagi *boundary* kabi, teg qism qayerda boshlanib, qayerda tugashini aniq aytadi. 5-prompt tuzilmasi:

```console
$ grep -n '^<' promptlar/5-xml.txt
1:<kontekst>
5:</kontekst>
7:<kod fayl="bozor/main.go">
44:</kod>
46:<natija buyruq="go run ./bozor">
49:</natija>
51:<format>
56:</format>
58:<misol>
64:</misol>
66:<savol>Nega 404 emas?</savol>
```

`grep -n` qator raqamini ham chiqaradi. 5-prompt mazmuni 4-promptniki bilan bir xil, faqat teglarga boʻlingan.
7-promptda teglar ayniqsa kerak: unda ikki xil Go kodi bor.

```text
<kod fayl="bozor/main.go">      bizning kod: test shu uchun
   …
</kod>
<misol fayl="kabisa_test.go">   faqat namuna, boshqa paket (kabisa)
   …
</misol>
<vazifa>                        nima qilish kerak
   …
</vazifa>
```

Teglar qaysi kod bizniki, qaysi biri faqat namuna ekanini ajratadi. Anthropic hujjati (*Structure prompts with XML tags*) aytadi: teglar
murakkab promptni aniq ajratishga yordam beradi; nomlari tushunarli va hamma promptlarda bir xil boʻlsin; tabiiy
ierarxiya boʻlsa, teglarni ichma-ich qoʻying. Maxsus «toʻgʻri» teg nomlari yoʻq: biz oʻzbekcha nomlarni (`kod`,
`misol`, `vazifa`) ishlatdik va javoblar toʻgʻri chiqdi.

Lekin halol xulosa: XML'ning alohida taʼsirini bu tajribada koʻra olmadik. Oʻlchov jadvalida 4-misol va 5-xml bir
xil: 3/3, 3/3, 3/3.

Uzun promptlar uchun hujjatda yana bitta aniq maslahat bor (*Long context prompting*). Matn 20 000 tokendan oshsa,
uzun hujjatlarni promptning boshiga, savolni esa oxiriga qoʻying. Anthropic sinovlarida savolni oxiriga qoʻyish javob
sifatini 30 foizgacha oshirgan, ayniqsa koʻp hujjatli murakkab promptlarda. Bu raqam XML haqida emas, savolning
oʻrni haqida. Bizning kichik promptlarimiz 1 400 tokendan kam (`input_tokens_jami` 1327 va 1374, CLI qoʻshimchasi bilan), bunga misol emas: 4- va 5-variant bir xil natija berdi.

| Prompt hajmi | Maslahat | Bizning tajribada |
|---|---|---|
| kichik, bitta vazifa | aniq kontekst + format yetarli | 3-format'dan keyin hech narsa oʻzgarmadi |
| bir necha xil qism (kod + namuna) | XML teglar bilan ajrating | 7-prompt: teglar qaysi kod bizniki ekanini aytadi |
| 20 000+ token, koʻp hujjat | hujjatlar boshida, savol oxirida | sinalmagan (hujjat: 30 foizgacha yaxshi) |

## Eski qoʻllanmalardagi ikki usul: prefill va temperature

Internetdagi eski qoʻllanmalarda yana ikki usul uchraydi. Hozirgi modellarda ikkalasi ham ishlamaydi.

**Prefill** — Claude javobining boshini oʻzingiz yozib berish: soʻrovdagi xabarlar roʻyxati oxirida assistant
xabari turadi, model uni davom ettiradi. Anthropic'ning *Prompt Engineering Interactive Tutorial* kursi uni 5-bobda
(«Speaking for Claude») oʻrgatadi: `{"role": "assistant", "content": prefill}`. Bu yaxshi kurs, lekin eski Claude 3
Haiku modeli uchun yozilgan. Hozirgi toʻrtta modelning migration guide'lari esa aytadi:

| Model | Prefill | `temperature`, `top_p`, `top_k` |
|---|---|---|
| Sonnet 5.5 | «rejects a prefilled last assistant turn with a 400 error» | «Sampling parameters return an error» |
| Opus 5.5 | «Don't end `messages` with a prefilled assistant turn: it is rejected» | «Omit `temperature`, `top_p`, and `top_k`» |
| Haiku 5.5 | «rejects it with a 400 error, even with thinking turned off» | olib tashlang |
| Fable 5.2 | «Prefilling the assistant message returns a 400 error» | «Omit `temperature`, `top_p`, and `top_k`» |

400 — HTTP «notoʻgʻri soʻrov» kodi: API soʻrovni umuman bajarmaydi. Ikkinchi usul — `temperature`, `top_p` va
`top_k` ni sozlash (CL-1.01 dagi sampling parametrlari). Ularni yuborsangiz ham endi xato qaytadi. Biz bu sahifa uchun
API'ni chaqirmadik, shuning uchun xato matnini koʻrsatmaymiz: yuqoridagilar hujjatdan iqtibos.

Hujjat ikkala holatda bitta yoʻlni aytadi: xohishingizni promptning oʻzida aniq yozing. Bizning 3-format prompti
aynan shunday qiladi: javob qanday boshlanishini prefill bilan emas, format talabi bilan belgilaydi.

## Oʻziga zid prompt

Endi bitta savol. 3-promptda ham «Xatoni oʻzim tuzatib, sababini tushunmoqchiman» degan gap turibdi. Lekin Claude
tayyor qatorni berdi. Nega shunday boʻldi? Va oʻrganmoqchi boʻlsangiz, formatni qanday oʻzgartirardingiz? Ishora:
prompt oʻziga zid emasmi?

<details>
<summary>Javob</summary>

Bizning taxminimiz shunday: prompt oʻziga zid edi. Bir joyda «oʻzim tuzataman» dedik, boshqa joyda
`Tuzatish: <oʻzgaradigan bitta Go qatori>` deb tuzatish qatorini aniq soʻradik. Claude formatdagi aniq talabni
bajardi: umumiy istakdan koʻra aniq, tekshirsa boʻladigan talab kuchliroq chiqdi. Bu bizning tushuntirishimiz, oʻlchov
emas: model nima «oʻylaganini» bilmaymiz.

```text
«oʻzim tuzatmoqchiman»              umumiy istak
«Tuzatish: <Go qatori>»             aniq format talabi  → bajarildi (3/3 tayyor qator)
«Ishora: …; tayyor kod yozma»       aniq format talabi  → 3/3 sabab + yoʻnalish, kod yoʻq
```

Oʻrganmoqchi boʻlsangiz, `Tuzatish:` oʻrniga `Ishora:` qatorini soʻrang va «tayyor kod yozma» deng. Biz buni ham uch
marta sinadik: uchala javobda sabab va yoʻnalish bor, tayyor kod yoʻq. Prompt va javoblar uy vazifasining 2-topshirigʻida.
Diqqat: bu promptda «tayyor kod yozma» ham bor, shuning uchun natijani faqat `Ishora` soʻziga bogʻlab boʻlmaydi.

</details>

Keyingi darsda, [CL-1.04 · AI — ustoz, javob mashinasi emas: bilim illyuziyasisiz oʻrganish](/lab/youtube/claude/cl-1-04) da
Claude'ni aynan shunday ustoz sifatida ishlatamiz.

## Xulosa: prompt shabloni

Bugun koʻrdik: kontekst Claude'ga vazifani tushuntiradi, format javobni ishlatsa boʻladigan qiladi, misol esa uslubni
koʻrsatadi. Har bir javobni baribir ishga tushirib tekshirdik. Bugungi tajribadan qolgan shablon:

```text
<kontekst>
Kim yozyapti, qaysi loyiha, qaysi versiya (Go 1.26.8).
Kutilgan natija: …   Haqiqiy natija: …
Nima istayman: tayyor tuzatishmi yoki ishorami (bittasini tanlang).
</kontekst>

<kod fayl="…">
butun kerakli kod
</kod>

<natija buyruq="go run ./…">
dasturning haqiqiy chiqishi, oʻzgartirmasdan
</natija>

<format>
Javobni qayerda va qanday ishlataman (shuning uchun …):
Sabab: <bitta gap>
Tuzatish: <bitta Go qatori>     yoki     Ishora: <qayerga qarash; tayyor kod yozma>
Tekshirish: <bitta buyruq>
</format>

<misol>…</misol>     faqat shakl muhim boʻlsa (test uslubi); 3–5 ta, har xil
```

Va har doim: bir necha marta bering, javobni ishga tushiring, muvaffaqiyat mezonini oldindan yozing. Rol berish va
loyiha qoidalari (`CLAUDE.md`) kabi usullarni Claude Code darslarida koʻramiz.

## Koʻp uchraydigan xatolar

### 1. «Model mening kodimni koʻradi»

Bu mavzuning klassik notoʻgʻri tasavvuri. Model faqat promptdagi matnni koʻradi (CL-1.01). Kodsiz savolga u 340–374
soʻzli, yettita taxminli roʻyxat yozdi va oxirida kodni soʻradi («Bitta qatorli savol» boʻlimi). Tuzatish: promptga
bug report'dagi hamma narsani qoʻying — kod, versiya, kutilgan va haqiqiy natija.

### 2. Oʻziga zid prompt

Jim xato: hech qanday xabar chiqmaydi, faqat siz kutmagan javob keladi. «Oʻzim tuzatmoqchiman» deb yozib, formatda
`Tuzatish:` qatorini soʻrasangiz, tayyor kod olasiz («Oʻziga zid prompt» boʻlimi). Tuzatish: istak va formatni bir
tomonga qarating. Oʻrganmoqchi boʻlsangiz — `Ishora:` va «tayyor kod yozma».

### 3. «Misol va XML har doim yordam beradi»

Bizning kichik vazifada ular hech narsani oʻzgartirmadi (4-misol = 5-xml = 3-format). Misol shaklni oʻzgartirdi,
toʻgʻrilikni emas. Misol keraksiz andozani ham koʻchiradi: uy vazifasining 3-javobida Claude misol izohlaridagi `ʻ`
harfini ham oldi. Tuzatish: misolni faqat shakl muhim boʻlganda qoʻshing, bir nechta va har xil qiling, va natijani
oʻlchang.

### 4. Eski qoʻllanmadan prefill yoki `temperature`

Hozirgi modellarda bunday soʻrov 400 xato bilan qaytadi («Eski qoʻllanmalardagi ikki usul» boʻlimi). Biz API'ni
chaqirmadik, shuning uchun xato matnini koʻrsatmaymiz. Tuzatish: parametrni yoki oxirgi assistant xabarini olib
tashlang va xohishingizni promptda yozing.

### 5. «Bir marta ishladi — demak prompt yaxshi»

Bitta javob tasodif boʻlishi mumkin. Uch marta deyarli bir xil javob ham hali isbot emas (CL-1.01: bir xillik
toʻgʻrilik emas). Bizda «toʻgʻri» degan bahoni faqat `404` va `PASS`/`FAIL` ustunlari beradi, chunki ular kodni ishga
tushiradi. Tuzatish: har promptni bir necha marta bering va javobni ishga tushirib tekshiring.

### 6. Dastur xatolari: boshqa papka va `./` siz

`olchov` saqlangan fayllarni joriy papkadan oʻqiydi. Dars papkasidan tashqarida ishga tushirsangiz (`cd ..` — bir
papka yuqoriga):

```console
$ cd .. && go run ./cl-03-prompt/olchov
bu papkadan ishga tushiring: open bozor/main.go: no such file or directory
exit status 1
```

Birinchi qatorni dastur yozdi (41-qator): «bu papkadan ishga tushiring», keyin Go'ning xatosi «`bozor/main.go` ni
ochib boʻlmadi: bunday fayl yoki papka yoʻq». `exit status 1` ni `go run` qoʻshadi. Tuzatish: `cd cl-03-prompt` va
`go run ./olchov`.

`./` siz yozsangiz:

```console
$ go run olchov
package olchov is not in std (/nix/store/h3rc4y3szd0391wryw9hslrijdvni030-go-1.26.8/share/go/src/olchov)
```

«`olchov` paketi standart kutubxonada yoʻq». `./` boʻlmasa, Go `olchov` ni papka emas, `fmt` kabi standart paket nomi
deb qidiradi. Qavs ichidagi yoʻl — Go oʻrnatilgan joy, sizda boshqacha boʻladi. Tuzatish: `go run ./olchov`.

## Oʻzingizni tekshiring

1. Claude'ga bu javob keldi. `olchov` uni qanday baholaydi (`format`, `tayyor`, `404`)?

```text
Sabab: `topish` xatoni `%w` bilan oʻraydi, `==` uni topmaydi.
Tuzatish: `if errors.Is(err, ErrTopilmadi)`
Tekshirish: `go run ./bozor`
```

**A)** format ✓, tayyor ✓, 404 ✓ · **B)** format ✓, tayyor ✓, `kompilyatsiya xatosi` · **C)** format ✗, tayyor ✗, —

<details>
<summary>Javob</summary>

**B.** Uch qator va kerakli soʻzlar bor, demak `format` ✓. `errors.Is(err, ErrTopilmadi)` matni bor, demak `tayyor` ✓.
Lekin qatorda `{` yoʻq. `ishlat` 25-qatorni shu qator bilan almashtiradi, qolgan `return 404` va `}` joyida qoladi,
shuning uchun ochuvchi qavssiz `if` kompilyatsiya boʻlmaydi: `kompilyatsiya xatosi`. «A» ni tanlagan boʻlsangiz,
`404` ustuni matnni oʻqiydi deb oʻyladingiz: u kodni ishga tushiradi. Shuning uchun bu ustun eng muhimi.

Biz buni tekshirdik. Dars papkasining nusxasini oldik (`bozor/`, `tuzatildi/`, `olchov/` va yangi `go.mod`),
`javoblar/` ichiga faqat `9-sinov/1.txt` ni qoʻyib, unga aynan shu uch qatorni yozdik. Keyin `olchov` ni `-v` (har
javob boʻyicha tafsilot) bilan ishga tushirdik. Bu fayl kurs papkasida yoʻq:

```console
$ go run ./olchov -v
prompt        soʻz (3 marta)  format  tayyor      404
  javoblar/9-sinov/1.txt: 17 soʻz, format true, tayyor true, kompilyatsiya xatosi
9-sinov       17              1/1     1/1         0/1
```

</details>

2. Promptga navbat bilan qoʻshilgan toʻrt narsa qaysilar, va har biri bizning tajribada nimani oʻzgartirdi?

<details>
<summary>Javob</summary>

- **Kontekst** (kod, versiya, kutilgan va haqiqiy natija): sabab 3/3 topildi, javob ~200 soʻzga qisqardi, ohang
  «oʻzingiz tuzating» ga oʻzgardi.
- **Natija formati** (uch qator + nega): 31 soʻz, tayyor tuzatish, 9/9 ishga tushirilganda 404.
- **Few-shot misol**: kichik vazifada oʻzgarish yoʻq; testda shaklni oʻzgartirdi (1 funksiya, 31 qator, kurs nomlari).
- **XML teglar**: alohida taʼsir koʻrinmadi; 7-promptda bizning kod va namunani ajratdi.

</details>

3. Eski qoʻllanmada shunday maslahat bor: «javobni JSON boʻlishi uchun assistant xabarini `{` bilan boshlang va
`temperature: 0` qoʻying». Sonnet 5.5 da nima boʻladi va oʻrniga nima qilasiz?

<details>
<summary>Javob</summary>

Ikkalasi ham 400 xato qaytaradi: prefill (oxirgi assistant xabari) ham, sampling parametrlari ham. Oʻrniga formatni
promptning oʻzida aniq yozing va sababini ayting, 3-format kabi. JSON'ning qatʼiy shakli kerak boʻlsa, uni CL-3.04 da
koʻramiz.

</details>

4. Nega 7-promptda XML teglar ayniqsa foydali, 5-promptda esa sezilmadi?

<details>
<summary>Javob</summary>

7-promptda ikki xil Go kodi bor: `bozor/main.go` (biz test yozdiradigan kod) va `kabisa_test.go` (faqat namuna, boshqa
paket). Teglar qaysi biri qaysi ekanini aytadi. 5-promptning qismlari esa matnning oʻzidan ham ajralib turadi, va
format allaqachon 3/3 natija bergan edi: yaxshilanadigan joy yoʻq edi.

</details>

5. CL-1.01 dan: 3-format'ning uchala javobi deyarli soʻzma-soʻz bir xil chiqdi. Bu tuzatishning toʻgʻriligini
isbotlaydimi?

<details>
<summary>Javob</summary>

Yoʻq. CL-1.01 dagi model `t = 0` da besh marta bir xil va besh marta notoʻgʻri javob berdi: bir xillik faqat modelning
ishonchini koʻrsatadi. Tuzatishning toʻgʻriligini `404` ustuni isbotlaydi: `olchov` qatorni kodga qoʻyib, ishga tushirdi
va 42-buyurtma uchun haqiqatan 404 oldi.

</details>

## Uy vazifasi

yozadi; keyin asl javoblarni `git restore javoblar` bilan qaytarasiz. Claude Code ichidan ishga tushirsangiz:
`env -u CLAUDECODE ./takrorla.sh …`. Sizning javoblaringiz biznikidan farq qilishi mumkin.

1. 🟢 **Oson.** Oʻz Go savolingizni ikki xil bering: `1-yomon` kabi bitta qator va `3-format` kabi kontekst + format.
   Ikkalasini `takrorla.sh` bilan uch martadan ishga tushiring (yoki Claude.ai'da uchta yangi chatda) va soʻzlarni
   sanang (`wc -w javoblar/*/*.txt`).
2. 🟡 **Oʻrta.** `3-format` da `Tuzatish:` oʻrniga `Ishora:` soʻrang (tayyor kod yozmasin) va javoblarni solishtiring.

4. 🔴 **Guru.** `olchov` ga test javobida nechta `Test` funksiya va nechta jadval holati borligini sanaydigan ustun
   qoʻshing.

<details>
<summary>Javob</summary>

🟢 Natija sizniki boʻladi. Bizda bir qatorli savol 340–374 soʻz, kontekst + format esa 31 soʻz berdi. Claude Code
boʻlmasa: Claude.ai'da uchta yangi chat oching (har biri toza kontekst), promptni yopishtiring, soʻzlarni sanang va
tuzatishni Go kodingizga qoʻyib `go run` qiling. Har bir javobni ishga tushirib tekshiring (CL-1.05 shu haqda).

$ tail -4 homework/ishora.txt

Javoblar (2026-11-26, Sonnet 5.5, 46/52/50 soʻz):

Ishora: `holat` funksiyasidagi `==` solishtirishga qarang va standart kutubxonadagi `errors` paketida o'ralgan xatolar zanjirini tekshiradigan funksiyalarni o'qing.

`go doc errors.Is` ham «bitta buyruq», lekin tuzatishni emas, hujjatni koʻrsatadi. Prompt «tayyor kod yozma» deb ham

shu usul haqida.

(map, `t.Run` siz). Uchala javob ham struct jadval uslubini oldi:
