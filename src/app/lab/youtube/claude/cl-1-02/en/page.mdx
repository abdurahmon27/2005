## What you will learn

Your server threw an error, and you want to paste the log into Claude and ask "what happened?". But the log contains
your database password, your Claude API key and a customer's phone number. Where does text pasted into a chat go, and
how long does it stay there? According to Anthropic, one of the most frequent causes of API key leaks is accidental
exposure in public repositories or third-party tools. Today we write a small Go scanner that deals with this, and we
look at how to set up Claude.ai itself.

**One idea:** on Claude.ai, the right model and a Project make the work faster, but everything you send to a chat
leaves your computer and is stored on the server. So choose the model and the Project with care, and never let a
secret into the chat at all.

By the end of the lesson you will:

- choose Haiku, Sonnet, Opus or Fable and the effort level by task;
- open a Project for one topic, put course files and short instructions into it, and know what Claude sees and what
  it does not;
- say how long the data you send to Claude.ai is kept and what to do if a key leaks;
- check a log or a folder with the `main.go` scanner, replace secrets with `-yashir`, and know where the scanner gets
  it wrong.

Today's three core new words:

| Word | Plain meaning | English term |
|---|---|---|
| Project | a separate workspace on Claude.ai with its own chats, knowledge base (files) and instructions | project (knowledge, instructions) |
| effort | how much work (thinking and time) the model spends on one answer; in the menu from Low to Max | effort |
| entropy | a measure of how random the characters of a text are, in bits per character | entropy (Shannon) |

Helper words get one sentence where they first appear: **RAG** (looking up only the needed part of the knowledge
base), **incognito chat** (a chat that is not saved to history), **Luhn** (the check formula of a card number).

<details>
<summary>Answer</summary>

This is an eight-line log of the "bozor" server: "server started on port :8080", a database URL, a Claude key

Now the scanner. `go run .` runs the package in the current folder, `misol/xato.log` is the file to check. How many
findings do you think the scanner reports?

**A)** 8: the order number is a card, the commit hash is a key · **B)** 6 · **C)** 7: the commit hash is a key too

<details>
<summary>Answer</summary>

**B.** Three secrets (the database URL with a password, the Claude key, the payment key) and three pieces of
personal data (email, phone, card). The 16-digit order number is not a card, because it fails the Luhn check. The
commit hash is not a key, because it has no upper-case letters. We look at both in the sections "Inside the scanner"
and "Unknown keys". If you chose "A" or "C", you thought any long number or long random string is a secret: the
scanner checks more than that.

</details>

## Four models and the plans

Anthropic's official *Models overview* page (2026-11-25) lists four main models today:

| Model | Anthropic's description | In short |
|---|---|---|
| Claude Fable 5.2 | demanding reasoning and long-horizon agentic work | the hardest reasoning, long-running agent work |
| Claude Opus 5.5 | long-running agentic coding and knowledge work | long programming and knowledge work |
| Claude Sonnet 5.5 | the best combination of speed and intelligence | the best balance of speed and intelligence |
| Claude Haiku 5.5 | high-volume, latency-sensitive tasks such as classification, extraction, and routing | the fastest: many quick tasks, for example classification and data extraction |

Which models you can use depends on your plan (claude.com/pricing and the help center):

| Plan | Models | Projects |
|---|---|---|
| Free | Sonnet, Haiku | up to 5 |
| Pro | + Opus; Fable only with separately paid *usage credits* | yes |
| Max and Ultra | all; Fable up to 50 % of the weekly limit | yes |

One more important fact: besides message length and files, the chosen model and effort level also affect how fast you
hit your limits (*Usage and length limits*). Uzbekistan is on the list of countries where Anthropic's services
(Claude.ai and the API) are officially available (*Supported regions*, in effect from 2026-11-12).

## Which model to choose, and effort

For developers (in API applications), Anthropic describes two approaches (*Choosing the right model*). The same logic
works in a chat:

| Approach | How | When |
|---|---|---|
| efficiency-first | start with a fast, cheap model (Haiku), move to a stronger one only if it falls short | simple, repeated work |
| capability-first | start with the strongest model (Opus), then move down to a cheaper one; if Opus at `xhigh`/`max` effort still falls short, Fable | complex work |

The document also says that tuning effort is often a better lever than switching models. Here is the rule we use in
this course. It is our rule, not Anthropic's documentation:

| Task | Model |
|---|---|
| what does this error message mean? | Haiku |
| one function, one test | Sonnet |
| a change across many files, a hard bug | Opus |
| Opus could not do it even at high effort | Fable |

Where do you choose the model? A diagram based on the help center (*Change the model, effort, and thinking settings*):

```text
[ message box .............. ] [Sonnet 5.5 · High ▾] [↑]
                                  ├─ Haiku 5.5 / Sonnet 5.5 / Opus 5.5 / Fable 5.2
                                  ├─ More models
                                  └─ Effort: Low · Medium · High · Extra high · Max
```

- The model menu is next to the send button. You click the model name and pick the one you need; the ones not in the
  list are under **More models**.
- **Effort** is in the same menu. The help center: Low and Medium work well for routine tasks, High offers the best
  overall balance of quality and speed.
- On the four current models (Fable 5.2, Opus 5.5, Sonnet 5.5, Haiku 5.5), **thinking** (reasoning before the answer)
  is always on and cannot be turned off. To make Claude think less, lower the effort.
- A change applies starting with Claude's next response, even in the middle of a conversation.

## Project: a workspace with its own files and instructions

When you work on one topic for a long time (for example, one lesson of the course), each new chat means uploading the
same files and writing the same rules again. That is what a **Project** is for. The help center's definition: a
self-contained workspace with its own chat history and knowledge base. Projects are on the Free plan too, but only
up to five.

Creating a new Project (a diagram based on the help center):

```text
claude.ai/projects → + New Project → name + description (Claude does NOT see them)
                   → Set project instructions  (added to every chat)
                   → + → files                 (the Project knowledge base)
```

Here is the surprising part: a Project's name and description are only for you, Claude does not see them. The help
center says it plainly: "Claude will not have access to these details". So you write what matters under **Set project
instructions** (these are the **project instructions**). You upload files with the **+** button, and they go into the
Project's **knowledge base** (*project knowledge*).

Anthropic is rolling out a new version of Projects (beta) step by step, starting in Claude Code. So your screen may
look a little different from the diagram. The diagrams follow the current version described in the help center.

## Knowledge base, memory, RAG and caching

What sees what inside a Project:

| What | Visible in the Project's other chats? |
|---|---|
| files in the knowledge base | yes, in all chats |
| project instructions | yes, added to every chat |
| the conversation of one chat itself | no |
| Project memory (*memory*, if it is on) | as short summaries, Claude may use them |

The help center: "Context is not shared across chats within a project unless the information is added into the
project knowledge base". So a decision you agreed on in one chat does not move to another chat by itself. Memory is on
by default on Free, Pro, Max and Ultra, and each Project has its own memory. But it is a short summary, not the full
conversation. Put important decisions into the knowledge base as a file. To fully separate a Project from your account
memory, turn off "Use account memory" on the Project page.

Two facts about limits and the context window:

- **RAG** (*retrieval-augmented generation*). On paid plans, when the knowledge base approaches the context window
  limit, Claude turns on RAG mode by itself. It no longer loads every file into the window, it looks up only the part
  needed for the question. Capacity grows up to 10 times.
- **Caching.** Project files are cached: when reused, they count less against your limits.

## File limits

From the help center (*Upload files to Claude*):

| Where | Limit |
|---|---|
| chat | up to 20 files, each up to 500 MB |
| PDF, ≤ 100 pages | Claude sees the text and also images and charts |
| PDF, 101–1000 pages | text only |
| Project file | up to 30 MB, text extraction only (except multimodal PDFs) |

Types on the official list: PDF, DOCX, CSV, TXT, HTML, ODT, RTF, EPUB, JSON, XLSX and images. `.go` and `.md` are not
on the list. If the app does not accept `README.md` or a `.go` file, upload it as `.txt` (for example,
`main.go.txt`). We did not test uploading on a Claude.ai account, so we say only what the page says.

## What not to send to a chat

Anthropic's own advice (*sensitive data*): be mindful with financial information, health records, passwords and login
credentials, and confidential documents. For a developer the list is longer:

| Kind | Example |
|---|---|
| financial | card number, bank account |
| health, confidential documents | documents your employer has not allowed |
| password, login, API key, token | `.env`, `DB_URL=postgres://user:PAROL@…`, `sk-ant-…`, `ghp_…` |
| customers' personal data | phone, email, address |

Anthropic compares an API key to a credit card number: "if someone obtains and uses your API key, they incur charges
on your behalf". The lesson folder has `tekshiruv-royxati.md` ("checklist"): a 30-second check before you send
anything to a chat.

## How long data is kept

How long is what you send kept? Anthropic Privacy Center, for the Free, Pro and Max plans:

| Situation | How long |
|---|---|
| Settings → Privacy: model improvement allowed | de-identified, up to 5 years |
| you deleted the conversation | from history at once, from the servers within 30 days |
| you pressed 👍 or 👎 on an answer | the whole conversation, up to 5 years |
| incognito chat | not in history, not used for training, but kept for 30 days |

The model-improvement setting is in Settings → Privacy, under the "Help improve our AI models" toggle. An
**incognito chat** is a temporary chat that is not saved to your chat history. There is no incognito inside a
Project.

## I sent a key to an incognito chat: what now

The pause question from the video. An incognito chat is not saved to history and not used to train the model. So if
you send a key there once and then close the chat, is the key safe? Hint: are "not in the history" and "not on the
server" the same thing?

**A)** yes: incognito is not saved · **B)** yes, if I delete the chat at once · **C)** no: the key must be revoked

<details>
<summary>Answer</summary>

**C.** The key left your computer and went to the server the moment you sent it. According to the help center, an
incognito chat does not appear in history, but it is kept for 30 days. If you chose "A", you took "not in the history"
for "not on the server". "B" is wrong too: a deleted conversation leaves the servers within 30 days, and the key keeps
working all that time. Deleting a chat never revokes a key.

</details>

The only right move is to revoke the key at once:

```text
sent = on the server        incognito also keeps it for 30 days
        ↓
revoke at once              Claude Console → API keys → … → Delete API key
        ↓
new key                     only in an environment variable or a secret manager
```

There is one layer of protection: Anthropic partners with GitHub. GitHub scans public repositories, and Anthropic
automatically deactivates a Claude key found there. But the document names this protection only for public GitHub
repositories: not for a chat, a forum or a Telegram group. If the key got into git history, see
[GIT-1.02](/lab/youtube/git/git-1-02/en).

## Inside the scanner: known formats and Luhn

Now we look inside the scanner. It works in two ways. The first is known formats: a key has its own prefix or shape.
The second is entropy, for keys of an unknown format (next section). The whole program:

```go filename="main.go" showLineNumbers
// tekshir: matnni chatga (Claude.ai, Project fayllari) yuborishdan oldin unda kalit,
// parol yoki shaxsiy maʼlumotga oʻxshash narsa bor-yoʻqligini qidiradi.
//
//	go run . fayl.log           topilmalar roʻyxati (qiymatning faqat boshi va oxiri)
//	go run . papka/             papkadagi matn fayllari + .env fayllarining nomi
//	go run . -yashir fayl.log   matnning oʻzi, topilmalar [YASHIRIN:tur] bilan
//	cat fayl.log | go run .     stdin
//
//	go run . -qatiy papka/      topilma boʻlsa chiqish kodi 1 (skript va git hook uchun)
package main

import (
	"bufio"
	"bytes"
	"flag"
	"fmt"
	"io"
	"io/fs"
	"math"
	"os"
	"path/filepath"
	"regexp"
	"sort"
	"strings"
)

type qoida struct {
	tur string              // topilma turi
	sir bool                // true: kalit/parol, false: shaxsiy maʼlumot
	re  *regexp.Regexp      // qidiruv namunasi
	ok  func(s string) bool // qoʻshimcha tekshiruv (nil = shart yoʻq)
}

// Tartib muhim: bir joyga ikki qoida tushsa, roʻyxatda oldin turgani yutadi.
var qoidalar = []qoida{
	{"anthropic-kalit", true, regexp.MustCompile(`sk-ant-[A-Za-z0-9_-]{20,}`), nil},
	{"github-token", true, regexp.MustCompile(`\b(?:gh[pousr]_|github_pat_)[A-Za-z0-9_]{20,}`), nil},
	{"aws-kalit", true, regexp.MustCompile(`\b(?:AKIA|ASIA)[A-Z0-9]{16}\b`), nil},
	{"maxfiy-kalit", true, regexp.MustCompile(`-----BEGIN [A-Z ]*PRIVATE KEY-----`), nil},
	{"url-parol", true, regexp.MustCompile(`[a-z][a-z0-9+.-]*://[^/\s:@]+:[^/\s@]+@`), nil},
	{"parol", true, regexp.MustCompile(`(?i)\b[a-z_]*(?:password|passwd|pass|pwd|parol|secret|api_?key|token)["']?\s*[:=]\s*["']?[^\s"',}]{6,}`), nil},
	{"email", false, regexp.MustCompile(`\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b`), nil},
	{"telefon", false, regexp.MustCompile(`\+998[ -]?\(?\d{2}\)?[ -]?\d{3}[ -]?\d{2}[ -]?\d{2}\b`), nil},
	{"karta", false, regexp.MustCompile(`\b\d{4}[ -]?\d{4}[ -]?\d{4}[ -]?\d{4}\b`), luhn},
}

// Nomaʼlum formatdagi kalit: uzun, tasodifiy koʻrinadigan soʻz.
var soz = regexp.MustCompile(`[A-Za-z0-9]{24,}`)

type topilma struct {
	joy        string // fayl:qator
	bosh, oxir int    // qator ichidagi bayt oraligʻi
	tur        string
	sir        bool
	qiymat     string
}

// qatorTekshir bitta qatordagi topilmalarni qaytaradi (bir-birini qoplamaydi).
func qatorTekshir(joy, qator string) []topilma {
	var t []topilma
	band := func(b, o int) bool {
		for _, x := range t {
			if b < x.oxir && x.bosh < o {
				return true
			}
		}
		return false
	}
	for _, q := range qoidalar {
		for _, m := range q.re.FindAllStringIndex(qator, -1) {
			s := qator[m[0]:m[1]]
			if band(m[0], m[1]) || (q.ok != nil && !q.ok(s)) {
				continue
			}
			t = append(t, topilma{joy, m[0], m[1], q.tur, q.sir, s})
		}
	}
	for _, m := range soz.FindAllStringIndex(qator, -1) {
		s := qator[m[0]:m[1]]
		if !band(m[0], m[1]) && tasodifiy(s) {
			t = append(t, topilma{joy, m[0], m[1], "nomaʼlum-kalit", true, s})
		}
	}
	sort.Slice(t, func(i, j int) bool { return t[i].bosh < t[j].bosh })
	return t
}

// tasodifiy: kamida 24 belgi; katta harf, kichik harf va kamida 2 ta raqam aralash; Shannon
// entropiyasi 4 bit/belgidan koʻp (Go'dagi uzun nomlar, masalan http2ErrCodeEnhanceYourCalm, oʻtmaydi).
// Git hash (40 ta hex) bu sinovga kirmaydi: katta harfi yoʻq, 16 xil belgida esa maksimum 4 bit.
// Narxi: 24 belgili tasodifiy kalitlarning ~13 foizini oʻtkazib yuboradi (go test -run Olchov -v).
func tasodifiy(s string) bool {
	var katta, kichik bool
	raqam := 0
	soni := map[rune]int{}
	for _, r := range s {
		katta = katta || (r >= 'A' && r <= 'Z')
		kichik = kichik || (r >= 'a' && r <= 'z')
		if r >= '0' && r <= '9' {
			raqam++
		}
		soni[r]++
	}
	return katta && kichik && raqam >= 2 && entropiya(soni, len(s)) > 4.0
}

func entropiya(soni map[rune]int, n int) float64 {
	var c []int
	for _, x := range soni {
		c = append(c, x)
	}
	sort.Ints(c) // map tartibi tasodifiy: yigʻindi har safar bir xil boʻlsin
	h := 0.0
	for _, x := range c {
		p := float64(x) / float64(n)
		h -= p * math.Log2(p)
	}
	return h
}

// luhn: karta raqamining oxirgi raqami tekshiruv raqami (ISO/IEC 7812-1).
// 16 xonali har qanday son (buyurtma raqami, vaqt) karta emas. 0000 0000 … ham emas.
func luhn(s string) bool {
	raqamlar := strings.Map(func(r rune) rune {
		if r >= '0' && r <= '9' {
			return r
		}
		return -1
	}, s)
	if strings.Count(raqamlar, raqamlar[:1]) == len(raqamlar) {
		return false // hammasi bir xil raqam
	}
	sum, ikki := 0, false
	for i := len(s) - 1; i >= 0; i-- {
		c := s[i]
		if c < '0' || c > '9' {
			continue
		}
		d := int(c - '0')
		if ikki {
			if d *= 2; d > 9 {
				d -= 9
			}
		}
		sum += d
		ikki = !ikki
	}
	return sum%10 == 0
}

// yashir qiymatning boshi va oxirini qoldiradi: sk-a…Qx. Qisqa qiymat toʻliq yashirinadi.
func yashir(s string) string {
	r := []rune(s)
	if len(r) < 16 {
		return strings.Repeat("*", len(r))
	}
	return string(r[:4]) + "…" + string(r[len(r)-2:])
}

var xeshFayl = map[string]bool{"go.sum": true, "package-lock.json": true, "yarn.lock": true, "pnpm-lock.yaml": true}

// envFayl: .env, .env.local … (lekin namunasi .env.example emas)
func envFayl(nom string) bool {
	if nom == ".env.example" || nom == ".env.sample" {
		return false
	}
	return nom == ".env" || strings.HasPrefix(nom, ".env.")
}

func oqi(joy string, r io.Reader, yoz io.Writer) ([]topilma, error) {
	var hammasi []topilma
	sc := bufio.NewScanner(r)
	sc.Buffer(make([]byte, 1024*1024), 1024*1024)
	for n := 1; sc.Scan(); n++ {
		qator := sc.Text()
		t := qatorTekshir(fmt.Sprintf("%s:%d", joy, n), qator)
		hammasi = append(hammasi, t...)
		if yoz != nil { // -yashir: qatorni topilmalarsiz chiqaramiz
			for i := len(t) - 1; i >= 0; i-- {
				qator = qator[:t[i].bosh] + "[YASHIRIN:" + t[i].tur + "]" + qator[t[i].oxir:]
			}
			fmt.Fprintln(yoz, qator)
		}
	}
	return hammasi, sc.Err()
}

func papka(yol string) ([]topilma, error) {
	var hammasi []topilma
	err := filepath.WalkDir(yol, func(p string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if d.IsDir() {
			if d.Name() == ".git" || d.Name() == "node_modules" {
				return filepath.SkipDir
			}
			return nil
		}
		if xeshFayl[d.Name()] {
			return nil // xesh'lar roʻyxati: tasodifiy koʻrinadi, lekin sir emas
		}
		if envFayl(d.Name()) {
			hammasi = append(hammasi, topilma{joy: p, tur: "env-fayl", sir: true, qiymat: d.Name()})
		}
		if info, err := d.Info(); err != nil || info.Size() > 1<<20 {
			return nil // 1 MB dan katta fayl: oʻtkazib yuboramiz
		}
		b, err := os.ReadFile(p)
		if err != nil {
			fmt.Fprintln(os.Stderr, "oʻqib boʻlmadi:", err)
			return nil
		}
		if bytes.IndexByte(b[:min(len(b), 512)], 0) >= 0 {
			return nil // binar fayl
		}
		t, err := oqi(p, bytes.NewReader(b), nil)
		hammasi = append(hammasi, t...)
		return err
	})
	return hammasi, err
}
```

(`regexp.Compile` returns an error instead).

Now cards. Sixteen digits are not enough: the order number `id=2026112510140712` in the log has 16 digits too. The
last digit of a card number is a check digit, computed with the **Luhn** formula (ISO/IEC 7812-1). The formula:
starting from the right, double every second digit (if the result is over 9, subtract 9), and add up all the digits.
If the sum is divisible by 10, the number is valid:

|---|---|---|---|
| `4111 1111 1111 1111` (a well-known test card number) | 30 | yes | card |
| `2026112510140712` (the order number) | 45 | no | not a card |
| `4111 1111 1111 1112` | 31 | no | not a card |

The `luhn` function (121–149) does exactly this. `strings.Map` (124–129) removes spaces and dashes. Line 130 rejects a
number made of one repeated digit: `0000 0000 0000 0000` passes Luhn (sum 0), but it is not a card. The loop (134–147)
goes from right to left, and `ikki` ("second") flips on every step: every second digit is doubled.

## Unknown keys: entropy

The second way is for keys of an unknown format. The payment key `Xq7Lm2Pz…` in the log has no prefix at all. How do
we tell it apart? In a randomly generated key, the characters are varied and appear almost equally often. A name a
person wrote, or a hash, is not like that. **Entropy** measures this (Shannon, 1948):

```text
H = −Σ p · log₂ p        p — the share of each character in the word
```

The `tasodifiy` function (92–105) checks four conditions; if all hold, it looks like a key:

1. at least 24 letters or digits (the pattern on line 48);
2. there is an upper-case letter and a lower-case letter;
3. at least 2 digits;
4. entropy above 4 bits per character.

`entropiya` (107–119) takes the count of each character (the `soni` map, "count") and computes the formula. Why is
`sort.Ints` on line 112 needed? Map order is random (GO-1.09). If you add floating-point numbers in a different order,
their last digits may differ a little. A sorted order makes the result the same every time.

Three strings from the log:

| String | Length | Distinct characters | Digits | Entropy | Result |
|---|---|---|---|---|---|
| `Xq7Lm2Pz9Rt4Vb8Nc3Kd6Wf1Hs5Jy0Ge` (payment key) | 32 | 32 | 10 | 5.0 | key |
| `3f9a1c27e0b84d6a9e2c5b7f1d08a4c6e9b2f731` (git commit hash) | 40 | 16 | 25 | 3.95 | does not enter the test |
| `http2ErrCodeEnhanceYourCalm` (a Go name) | 27 | 17 | 1 | 3.99 | does not enter the test |

All 32 characters of the payment key are different, so each has a share of 1/32 and H = log₂ 32 = 5.0. The git hash
has no upper-case letters at all, so it drops out at condition 2. Even if it had them, with 16 distinct characters
(0–9, a–f) the entropy cannot exceed log₂ 16 = 4. The Go name has only one digit (condition 3).

The scanner does not print entropy values. We computed the numbers in the table with the scanner's own `entropiya`
function. This file is not in the lesson folder: save it as `entropiya.go` in a separate empty folder and run it:

```go filename="entropiya.go" showLineNumbers

	"fmt"
	"math"
	"sort"
)

// entropiya: main.go dagi funksiyaning oʻzi (107–119-qatorlar)
func entropiya(soni map[rune]int, n int) float64 {
	var c []int
	for _, x := range soni {
		c = append(c, x)
	}
	sort.Ints(c)
	h := 0.0
	for _, x := range c {
		p := float64(x) / float64(n)
		h -= p * math.Log2(p)
	}
	return h
}

		for _, r := range s {
			soni[r]++
		}
		fmt.Printf("%-42s %.2f\n", s, entropiya(soni, len(s)))
	}
}
```

The test key in `testcert.go` is interesting: Go writes it with a `TESTING KEY` header and replaces it with

signals (false positives): the scanner is cautious, because an extra warning is cheap and a leaked key is expensive.

It also works the other way: the scanner misses a real key (a false negative). `olchov_test.go` (`olchov`,
"measurement") generates 10 000 random keys each of 24, 32 and 40 characters and counts how many the scanner finds. The

("24 characters: 8732 / 10000 found".) Of the 24-character keys, 8732 were found, so about one in eight slipped
through. Why? A random key can have fewer than 2 digits, or repeated characters that push the entropy below 4 bits.
This is the price of tuning. The README measured four variants:

| Rule variant (digits ≥ N, H > X) | 24 chars | 32 chars | 40 chars | "unknown keys" in `net/http` |
|---|---|---|---|---|
| N = 3, X = 4.0 | 73 % | 91 % | 97 % | 128 |
| **N = 2, X = 4.0 (current)** | **87 %** | **97 %** | **99 %** | **144** |
| N = 1, X = 4.0 | 94 % | 99.6 % | 99.9 % | 196 |
| N = 1, X = 3.7 | 98 % | 99.7 % | 99.9 % | 488 |

The more keys you catch, the more false signals you get. So even when the scanner says "no findings", look at the
text once yourself. For a serious project, use a ready-made tool: Anthropic recommends
[gitleaks](https://github.com/gitleaks/gitleaks), and on GitHub turn on secret scanning and push protection
(GIT-1.02).

In short: the model is chosen by task, a Project gives every chat the same course files, and a secret must never reach
the chat at all. In the next lesson we write a prompt like a technical spec: with context, examples and constraints
([CL-1.03](/lab/youtube/claude/cl-1-03/en)).

## Common mistakes

### 1. "I sent it in an incognito chat and then deleted it, so the key is safe"

This is the classic misconception of this lesson. The key went to the server the moment you sent it. An incognito
chat is also kept for 30 days, a deleted conversation leaves the servers within 30 days, and the key keeps working all
that time (section "I sent a key to an incognito chat"). Fix: revoke the key at once (Console → API keys → … → Delete
API key) and keep the new one only in an environment variable.

### 2. "I wrote the rule in the Project description"

Claude does not see a Project's name and description. If the rule "answer in Uzbek" is in the description, Claude
does not know it. Fix: write the rules in the Set project instructions field, briefly: context, key guidelines, role
(`loyiha-korsatma.md`).

### 3. "We agreed on it in one chat, so the other chat knows too"

Inside a Project, chats do not see each other's conversations. Even with memory on, memory is only a short summary.
Fix: put an important decision (for example, "we wrap errors with `%w`") into the knowledge base as a file.

### 4. "I always pick the strongest model"

The model and the effort level affect how fast you hit your limits. You do not need Fable to understand an error
message. Fix: following the course rule, start with Haiku or Sonnet and move up only if it falls short. Often changing
the effort is enough before you switch models.

### 5. "The scanner said clean, so it is safe"

The scanner knows only its own rules. For example, it deliberately does not catch a phone number in the local form
(without `+998`): otherwise any 9-digit number would become a phone number. This command is not in the lesson folder;
run it yourself in one line (`echo` passes the text through a pipe to the scanner's standard input):

```console
$ echo 'tel=90 123 45 67' | go run .
topilma yoʻq (bu «xavfsiz» degani emas: faqat shu qoidalar tekshirildi)
```

The scanner says so itself: "no findings (this does not mean «safe»: only these rules were checked)". One in eight
random 24-character keys also slips through (section "The scanner gets it wrong too"). Fix: after the scanner, look
at the text once yourself.

### 6. "I could not upload a `.go` file to the Project"

`.go` and `.md` are not on the official list. If the app does not accept the file, change the extension to `.txt`
(`main.go.txt`). A Project file is limited to 30 MB, and only its text is extracted.

### 7. Program errors: no `misol/` and `-yashir` with a folder

If you run the scanner in a fresh clone without running `./misol.sh` first:

```console
$ go run . misol/xato.log
xato: lstat misol/xato.log: no such file or directory
exit status 2
```

"lstat misol/xato.log: no such file or directory". `lstat` is the system call that `filepath.WalkDir` uses to get
information about the path. The program itself prints `xato:` ("error:") and exits with code 2 (lines 250–253), and
`go run` adds `exit status 2`. Fix: run `./misol.sh` first.

`-yashir` works with one file only:

```console
$ go run . -yashir misol/bozor
xato: read misol/bozor: is a directory
exit status 2
```

"read misol/bozor: is a directory". `-yashir` opens the path with `os.Open` and reads it like a file (lines 234–239),
and a folder cannot be read like a file. Fix: pass each file separately.

## Check yourself

1. What does this command print?

```text
echo 'karta=4111 1111 1111 1112' | go run .
```

**A)** a `karta` finding · **B)** `topilma yoʻq` · **C)** `nomaʼlum-kalit`

<details>
<summary>Answer</summary>

**B.** The number has 16 digits, but its Luhn sum is 31, which is not divisible by 10. "C" cannot happen:
`nomaʼlum-kalit` also needs letters.

```console
$ echo 'karta=4111 1111 1111 1112' | go run .
topilma yoʻq (bu «xavfsiz» degani emas: faqat shu qoidalar tekshirildi)
```

</details>

2. Which rule reports a finding for this command, and with what value?

```text
echo 'DB_PASSWORD=Qovun2026' | go run .
```

<details>
<summary>Answer</summary>

The `parol` rule (line 41): `[a-z_]*` takes `DB_`, and `(?i)` matches `PASSWORD` against the lower-case `password`.
The match starts at the variable name, so the value is `DB_PASSWORD=Qovun2026` (21 characters), longer than 16: 4
characters at the start and 2 at the end remain.

```console
$ echo 'DB_PASSWORD=Qovun2026' | go run .
stdin:1                sir     parol           DB_P…26
jami 1: 1 ta sir, 0 ta shaxsiy maʼlumot. Chatga yuborishdan oldin olib tashlang.
```

</details>

3. Where in a Project do you write the rule "answer in Uzbek", and why not in the description?

<details>
<summary>Answer</summary>

In the Set project instructions field. The help center: Claude does not see a Project's name and description. The
instructions are added to every chat in the Project.

</details>

4. By the course rule, which model for: (a) "what does this error message mean?", (b) a refactoring that touches five
files, (c) Opus could not do it even at high effort?

<details>
<summary>Answer</summary>

(a) Haiku, (b) Opus, (c) Fable. This is our rule, not Anthropic's documentation. The documentation describes two
approaches (efficiency-first, capability-first) and says that tuning effort is often better than switching models.

</details>

5. If you delete a conversation, when does it leave the servers? If you press 👍 on an answer, how long is the
conversation kept?

<details>
<summary>Answer</summary>

A deleted conversation leaves the history at once and the servers within 30 days. If you press 👍 or 👎, the whole
conversation is kept for up to 5 years (Privacy Center, for Free, Pro and Max).

</details>

6. From CL-1.01: which problem does line 5 of the instructions ("say it is not in the files and say you are guessing")
fight?

<details>
<summary>Answer</summary>

The confident mistake (hallucination). The model has to pick the next token at every step and can write a fluent
answer even where it knows nothing. One of the methods Anthropic recommends is to allow it, explicitly, to say "I
don't know". Line 4 adds a second one: base the answer on the given documents (the Project files).

</details>

🟠 The format follows the example in Telegram's official docs: `123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11` (the bot
number, a colon, the key).

```go filename="homework/telegram.go" showLineNumbers
// Package homework: CL-1.02 uy vazifasining «Qiyin» javobi.
//
// Telegram bot tokeni: «bot raqami : kalit». Rasmiy Bot API hujjatidagi namuna:
// 123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11 (https://core.telegram.org/bots/api#authorizing-your-bot).
// Asosiy skanerga qoʻshish uchun main.go dagi qoidalar roʻyxatiga shu qatorni yozing:
//
//	{"telegram-token", true, TelegramToken, nil},
package homework

import "regexp"

// TelegramToken: 6–12 xonali bot raqami, ikki nuqta, keyin 30+ ta harf/raqam/_/-.
var TelegramToken = regexp.MustCompile(`\b\d{6,12}:[A-Za-z0-9_-]{30,}`)
```

The regex: a bot number of 6–12 digits, `:`, then at least 30 letters, digits, `_` or `-`. The test
(`homework/telegram_test.go`) must find the example from the docs and one fake token, and must not match the time
`10:14:02` or `id=…:ok`:

```console
$ go test -run Telegram -v ./homework | head -2
=== RUN   TestTelegramToken
--- PASS: TestTelegramToken (0.00s)
```

`head -2` keeps the first two lines: the time on the final `ok` line differs on every run. To plug it into the main
scanner, add the line `{"telegram-token", true, homework.TelegramToken, nil}` to the `qoidalar` list in `main.go` (or
copy the regex).

🔴 A git hook is a script that git itself runs before a commit:

```bash filename="homework/pre-commit"
#!/usr/bin/env bash
# CL-1.02 uy vazifasi, «Guru»: sir bor commit'ni toʻxtatadigan git hook.
# Commit'ga ketayotgan (staged) fayllarning index'dagi holatini skaner bilan tekshiradi.
#
# Oʻrnatish (go-backend-uz repo ildizida):
#   cp lessons/cl-02-claude-ai/homework/pre-commit .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
# Bir martaga chetlab oʻtish (faqat yolgʻon signal boʻlsa!): git commit --no-verify
set -euo pipefail
root=$(git rev-parse --show-toplevel)
tmp=$(mktemp -d); trap 'rm -rf "$tmp"' EXIT

git diff --cached --name-only --diff-filter=ACMR -z | while IFS= read -r -d '' f; do
	mkdir -p "$tmp/$(dirname "$f")"
	git show ":$f" > "$tmp/$f"
done

if ! (cd "$root" && go run ./lessons/cl-02-claude-ai -qatiy "$tmp" | sed "s|$tmp/||"); then
	echo "commit toʻxtatildi: yuqoridagi sirlarni olib tashlang (yoki -yashir bilan almashtiring)" >&2
	exit 1
fi
```

`git diff --cached --name-only` lists the files going into the commit (staged). `git show ":$f"` takes the file's
state in the *index*, not on disk: exactly what goes into this commit. The files are written to a temporary folder and
checked with `-qatiy`: if there is a finding, the exit code is 1 and git stops the commit. `trap … EXIT` deletes the
temporary folder at the end. Installing (in the repository root):

```bash
cp lessons/cl-02-claude-ai/homework/pre-commit .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```

We tried it in a temporary repository (a copy of `go.mod` and of this lesson folder, with the hook installed). A file
with a password:

```console
$ git add config.txt && git commit -m "config"
exit status 1
config.txt:1 sir     url-parol       post…6@
jami 1: 1 ta sir, 0 ta shaxsiy maʼlumot. Chatga yuborishdan oldin olib tashlang.
commit toʻxtatildi: yuqoridagi sirlarni olib tashlang (yoki -yashir bilan almashtiring)
```

("commit stopped: remove the secrets above (or replace them with -yashir)".) `config.txt` had one line:
`DB_URL=postgres://bozor:Qovun2026@localhost:5432/bozor`. No commit was created. With a clean file (`toza.txt`
containing `salom`), the hook printed `topilma yoʻq …` and the commit went through. Careful: the course folder itself
is full of fake keys, so the hook catches them too. Use `git commit --no-verify` once, only for a false signal.

</details>
