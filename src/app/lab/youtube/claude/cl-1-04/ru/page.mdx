## Что вы узнаете

В Турции почти тысячу школьников разделили на три группы. Одна группа решала задачи по математике с помощником,
похожим на ChatGPT, и на практике показала результат на 48 процентов лучше. Потом на экзамене AI убрали. Оценки этой
группы оказались на 17 процентов ниже, чем у тех, кто учился без AI, а сами ученики этого не заметили (Bastani и
соавт., PNAS 2025). Вы тоже каждый день получаете код от Claude. Он работает. Но учитесь ли вы?

**Одна идея:** если AI пишет ответ, а вы только копируете, потом вы можете не справиться сами. Поэтому сначала пишете
вы, даже с ошибками. А Claude становится наставником: показывает, где ошибка, и задаёт вопрос.

К концу урока вы:

- дадите Claude шесть строк правил наставника и увидите, как вместо готового кода он показывает строку с ошибкой и
  задаёт вопрос;
- сравните два пути на одной ошибке Go: «исправь» (машина ответов) и наставник; измерите 12 сохранённых ответов Claude
  программой на Go;
- будете судить о своём понимании не по ощущению «я понимаю», а по проверке: закрыть чат и написать по памяти или
  объяснить;
- попутно исправите классическую ошибку Go: почему `errors.Is(err, &MaydonXato{})` никогда не бывает `true`.

Три главных новых слова урока:

| Слово | Простой смысл | По-английски |
|---|---|---|
| иллюзия знания | ощущение «я понимаю» есть, а объяснить шаг за шагом не получается | illusion of explanatory depth |
| правила наставника | указания, которые Claude получает до разговора: не пиши готовый код, покажи ошибку, задай вопрос | system prompt (в Claude.ai — Project instructions) |
| припоминание | закрыть материал и записать то, что запомнили | retrieval practice |

Два вспомогательных названия: **машина ответов** — способ просить у Claude готовое исправление; **режим Learning** —
официальный режим наставника в Claude for Education от Anthropic (ниже).

## Иллюзия знания: ощущение «понимаю» — не понимание

Один вопрос: как работает молния (zipper) на куртке? Большинство скажет «знаю». А теперь попробуйте записать шаг за
шагом: как сцепляются зубцы, почему она не расходится?

Розенблит и Кейл (Cognitive Science, 2002, исследование 1) попросили 16 аспирантов Йельского университета оценить по
шкале от 1 до 7, насколько хорошо они понимают такие вещи — молнию, спидометр, клавишу пианино, замок. Потом каждый
шаг за шагом расписал, как это работает, и оценил себя заново. Авторы: *«Nearly all participants showed drops in
estimates of what they knew when confronted with having to provide a real explanation»* — «когда пришлось дать
настоящее объяснение, оценка почти у всех упала».

| Шаг | Что произошло |
|---|---|
| 1. «Знаю»: оценка от 1 до 7 | по ощущению, не задумываясь |
| 2. Объяснение шаг за шагом | видны пробелы |
| 3. Повторная оценка | почти у всех ниже |
| Вывод | ощущение ≠ понимание: не можете объяснить — значит, не поняли |

Авторы назвали это **иллюзией знания** (*illusion of explanatory depth*, «иллюзия глубины объяснения»). Разработчику
это знакомо: читаете объяснение Claude, всё кажется логичным, но закрыв чат, не можете написать этот код. Школьники в
турецком исследовании были именно в таком положении: экзамен написали хуже, но этого не заметили.

**Наставник — тоже не гарантия.** В турецком исследовании была и третья группа: **GPT Tutor**. Её помощник не
говорил ответ, а давал подсказку; учителя заранее записали для него решение каждой задачи и частые ошибки.

| Группа | На практике | На экзамене (без AI) | Как оценили себя |
|---|---|---|---|
| без AI | — | база | — |
| GPT Base (похож на ChatGPT) | +48 % | −17 % | не заметили ухудшения |
| GPT Tutor (подсказка, не ответ) | +127 % | вреда почти нет, пользы тоже нет | думали, что написали лучше |

Значит, наставник убирает вред, но не иллюзию. Поэтому и после наставника вы проверяете себя. Как это делать — в
последней части страницы.

Почему сначала пишете вы? Метаанализ Берча и соавторов (Memory & Cognition, 2007) объединил 86 исследований:
информацию, которую вы создали сами (*generate*), вы запоминаете лучше, чем просто прочитанную. Психологи называют
это *generation effect* («эффект генерации»). Средний эффект — 0,40 стандартного отклонения, то есть «почти
половина стандартного отклонения».

## Эксперимент: цена −5, ответ 500

Эксперимент — на коде небольшого интернет-магазина (`bozor`, «базар») из проекта курса. Handler проверяет заказ и по
ошибке возвращает HTTP-статус. Требование: если цена отрицательная — `400` (клиент прислал неверные данные), а не
`500`. Наш ученик **вымышленный**: его код и сообщения написали мы, ответы Claude — без изменений. Он только что
изучил `errors.Is` в [CL-1.03](/lab/youtube/claude/cl-1-03/ru) и написал его и для 400:

```go filename="bozor/main.go" showLineNumbers
package main

import (
	"errors"
	"fmt"
)

var ErrTopilmadi = errors.New("buyurtma topilmadi")

// MaydonXato: buyurtmaning bitta maydoni notoʻgʻri
type MaydonXato struct {
	Maydon string
	Sabab  string
}

func (e *MaydonXato) Error() string { return e.Maydon + ": " + e.Sabab }

func tekshir(narx int) error {
	if narx <= 0 {
		return fmt.Errorf("tekshir: %w", &MaydonXato{Maydon: "narx", Sabab: "musbat boʻlishi kerak"})
	}
	return nil
}

// holat: handler shu kodni HTTP javobga yozadi
func holat(err error) int {
	if err == nil {
		return 200
	}
	if errors.Is(err, ErrTopilmadi) {
		return 404
	}
	// mening urinishim: oʻtgan safar errors.Is yordam bergan edi
	if errors.Is(err, &MaydonXato{}) {
		return 400
	}
	return 500
}

func main() {
	for _, narx := range []int{12000, -5} {
		err := tekshir(narx)
		fmt.Printf("POST /buyurtma narx=%d → %d %v\n", narx, holat(err), err)
	}
}
```

| Строка | Код | Что делает |
|---|---|---|
| 8 | `var ErrTopilmadi = errors.New(…)` | **sentinel-ошибка** («заказ не найден»): одно готовое значение, сравнивается через `errors.Is` ([GO-1.14](/lab/youtube/go/go-1-14/ru)) |
| 11–14 | `type MaydonXato struct` | наш тип ошибки («ошибка поля»): какое поле (`Maydon`, «поле») и почему (`Sabab`, «причина») неверно |
| 16 | `func (e *MaydonXato) Error() string` | pointer receiver: `error` реализует только `*MaydonXato` |
| 18–23 | `func tekshir(narx int) error` | `tekshir` («проверить»): если цена (`narx`) ≤ 0, создаёт **новый** `&MaydonXato{…}` и оборачивает его через `%w` в `tekshir: ` |
| 26–38 | `func holat(err error) int` | `holat` («состояние»): превращает ошибку в HTTP-статус: `nil` → 200, `ErrTopilmadi` → 404, `MaydonXato` → 400, остальное → 500 |
| 33 | `// mening urinishim…` | комментарий ученика: «в прошлый раз помог `errors.Is`» |
| 34 | `errors.Is(err, &MaydonXato{})` | намерение ученика: «если ошибка — `MaydonXato`, то 400». Но строка спрашивает другое (ниже) |
| 41 | `for _, narx := range []int{12000, -5}` | два запроса: правильная цена и отрицательная |
| 43 | `fmt.Printf(…)` | запрос, статус и текст ошибки; `%v` выводит ошибку как текст, при отсутствии ошибки — `<nil>` |

Что выведется для `narx=-5`?

**A)** `400` · **B)** `500` · **C)** ошибка компиляции

<details>
<summary>Ответ</summary>

**B.** Код компилируется: `&MaydonXato{}` — `error` правильного типа. Но `errors.Is` в строке 34 никогда не вернёт
`true`, поэтому `holat` доходит до последнего `return 500`. Если вы выбрали «A», вы, как и ученик, прочитали
`errors.Is` как «есть ли ошибка такого типа?». Почему это не так — в следующем разделе.

</details>

```console
$ go run ./bozor
POST /buyurtma narx=12000 → 200 <nil>
POST /buyurtma narx=-5 → 500 tekshir: narx: musbat boʻlishi kerak
```

В первой строке цена правильная: `200`, а `<nil>` значит «ошибки нет». Во второй строке текст ошибки верный —
«narx: musbat boʻlishi kerak» («цена: должна быть положительной»), — но статус `500`. `go vet` тоже не помогает:

```console
$ go vet ./bozor
```

Он ничего не вывел: с точки зрения Go этот код корректен. Это тихая ошибка (silent bug): её не ловят ни компилятор, ни
`vet`.

## Где ошибка: `errors.Is` ищет конкретное значение

Ошибка, которую возвращает `tekshir`, — двухслойная **цепочка ошибок**: снаружи обёртка `fmt.Errorf("tekshir: %w", …)`,
внутри указатель `*MaydonXato`. Картинка из видео: паспорт лежит в сумке, сумка — в чемодане. И `errors.Is`, и
`errors.As` раскрывают чемодан слой за слоем. Разница — в том, что они ищут:

```text
err  =  "tekshir: …"  (обёртка %w)
          └── *MaydonXato  адрес 0xA1  {Maydon: "narx", Sabab: "musbat boʻlishi kerak"}

errors.Is(err, &MaydonXato{})       ищет: НОВОЕ пустое значение по адресу 0xB2
                                    0xA1 == 0xB2 ?  нет → false → 500

errors.AsType[*MaydonXato](err)     ищет: любую ошибку ТИПА *MaydonXato
                                    тип 0xA1 — *MaydonXato ?  да → true → 400
```

(Адреса условные, только чтобы показать разницу.) `errors.Is` сравнивает каждую ошибку в цепочке с переданным
значением через `==`. Для указателей `==` означает «оба указывают на **один и тот же** объект в памяти?».
`&MaydonXato{}` каждый раз создаёт новый объект, и он никогда не совпадёт с объектом, который создал `tekshir`. На
языке паспорта: `errors.Is` спрашивает «есть ли внутри **именно мой** паспорт?», а ученик сделал новый пустой паспорт
и спросил «есть ли вот этот?». Нужный вопрос другой: «есть ли внутри **вообще** паспорт?» Это `errors.As` и
`errors.AsType`.

Значит, сравнение значений и проверка типа — две разные операции:

| Вопрос | Go (по всей цепочке) |
|---|---|
| именно это значение? | `errors.Is(err, ErrTopilmadi)` |
| ошибка этого типа? | `errors.As(err, &me)` или `errors.AsType[*MaydonXato](err)` |

`errors.Is` — для sentinel-ошибок (`ErrTopilmadi`). Для поиска по типу нужен `errors.As` (с Go 1.13) или
`errors.AsType` (с Go 1.26) ([GO-1.14](/lab/youtube/go/go-1-14/ru)). Теперь дадим эту ошибку Claude двумя способами.

## Путь 1: машина ответов

Первая строка `promptlar/1-javob.txt`, за ней весь `bozor/main.go` и вывод `go run`:

```text
Bu Go kodni tuzatib ber. Narx manfiy bo'lsa 400 qaytishi kerak, lekin 500 qaytyapti. Go 1.26.8.
```

(«Исправь этот код на Go. Если цена отрицательная, должен возвращаться 400, а возвращается 500. Go 1.26.8.») Мы дали
его Claude Sonnet 5.5 без системного текста, три раза, каждый раз в новом разговоре (`takrorla.sh`, как в CL-1.03). Во
всех трёх ответах есть готовый код. Цитата из первого ответа (`javoblar/1-javob/1-1.txt`):

```text
Xato **turini** tekshirish uchun `errors.As` kerak. U zanjirdagi (`%w` orqali o'ralgan) xatolar ichidan shu turdagisini topib, o'zgaruvchiga yozadi.

`holat` funksiyasini shunday o'zgartiring:
```

(«Чтобы проверить **тип** ошибки, нужен `errors.As`. Он находит среди ошибок в цепочке (обёрнутых через `%w`) ошибку
этого типа и записывает её в переменную. Измените функцию `holat` так:») Дальше в ответе идёт готовая функция, ровно
такая:

```go
func holat(err error) int {
	if err == nil {
		return 200
	}
	if errors.Is(err, ErrTopilmadi) {
		return 404
	}
	var me *MaydonXato
	if errors.As(err, &me) {
		return 400
	}
	return 500
}
```

Это правильное исправление. Две изменённые строки:

| Код | Что делает |
|---|---|
| `var me *MaydonXato` | пустой «карман» для найденной ошибки: переменная-указатель со значением `nil` |
| `errors.As(err, &me)` | ищет в цепочке ошибку типа `*MaydonXato`; если находит, записывает её в `me` и возвращает `true`. Чтобы записать, ему передают **адрес** `me` (`&me`) |

Мы вставили код в `bozor/main.go` (это делает программа `olchov`, ниже): код всех трёх ответов заработал и вывел
`narx=-5 → 400`. В ответе есть и объяснение: `errors.Is` сравнивает через `==`, новый указатель никогда не будет
равен.

**Давайте подведём итог: что произошло?** Код работает, объяснение есть. Но мы ничего не написали и ничего не
вспомнили. Объяснение легко пробежать глазами — это и есть иллюзия знания. В турецком исследовании самым частым
сообщением учеников из группы GPT Base помощнику было то же самое: *«What is the answer?»* — «какой ответ?».

## Путь 2: правила наставника

Во втором пути мы **до** разговора даём Claude правила из шести строк. Это **правила наставника**: в API и Claude Code
CLI они становятся *system prompt* (системным промптом), а в Claude.ai записываются в инструкции Project
([CL-1.02](/lab/youtube/claude/cl-1-02/ru)). `promptlar/ustoz-tizim.txt` (`ustoz` — «наставник»):

```text
Sen Go o'rganayotgan dasturchining ustozisan. Maqsad: u kodni o'zi yozib, xatoning sababini o'zi tushunsin.
- Tayyor kod, tuzatilgan qator yoki to'g'ri funksiya nomini yozma, hatto so'rasa ham. Uning o'rniga yo'nalish ber.
- Avval o'quvchining urinishini o'qi: nima to'g'ri ekanini ayt, keyin xato qaysi qatorda ekanini ko'rsat.
- So'ng bitta savol ber, javobini u o'zi topsin. Savolga o'zing javob berma.
- O'quvchi tuzatishini yuborsa, uni tekshir: xato bo'lsa, qaysi qator va nega ekanini ayt, lekin to'g'ri kodni yozma.
- Javobing 150 so'zdan oshmasin, o'zbek tilida yoz.
```

| Строка | Что говорит | Зачем |
|---|---|---|
| 1 | ты наставник разработчика, который учит Go; пусть он сам напишет код и сам поймёт причину ошибки | задаёт цель: не ответ, а понимание |

**Сообщение 3.** Ученик не ответил на этот вопрос: он вспомнил другой путь из GO-1.14 — `errors.AsType`. Этой функции
не нужен карман, она сама возвращает найденную ошибку. Новый `holat` в `tuzatildi/main.go`:

```go
// holat: handler shu kod va matnni HTTP javobga yozadi
func holat(err error) (int, string) {
	if err == nil {
		return 200, "ok"
	}
	if errors.Is(err, ErrTopilmadi) {
		return 404, "topilmadi"
	}
	// zanjirdan *MaydonXato turidagi xatoni qidiradi va topilsa oʻzini qaytaradi (Go 1.26)
	if mx, ok := errors.AsType[*MaydonXato](err); ok {
		return 400, "notoʻgʻri maydon: " + mx.Maydon
	}
	return 500, "ichki xato"
}
```

| Код | Что делает |
|---|---|
| `(int, string)` | теперь `holat` возвращает два значения: статус и текст ответа (ученик хотел ещё и написать, какое поле неверно) |
| `errors.AsType[*MaydonXato](err)` | в квадратных скобках — искомый тип (type argument). Если в цепочке есть ошибка этого типа, возвращает её и `true` |
| `mx, ok := …; ok` | `mx` — найденный `*MaydonXato`, виден только внутри этого `if`; `ok` — найдена ли |
| `"notoʻgʻri maydon: " + mx.Maydon` | пишет в ответ, какое поле неверно («неверное поле: …») |

`main` тоже принимает два значения (`kod, matn := holat(err)`). Запускаем снова:

```console

POST /buyurtma narx=12000 → 200 ok
POST /buyurtma narx=-5 → 400 notoʻgʻri maydon: narx
```

## Припоминание: как проверить, что вы поняли

Мы сказали, что и после наставника вы проверяете себя. Один из лучше всего изученных способов — **припоминание**
(*retrieval practice*). Рёдигер и Карпик (Psychological Science, 2006, эксперимент 2): одна группа прочитала текст
четыре раза. Другая прочитала один раз, а потом три раза закрывала книгу и записывала то, что запомнила.

| Группа | Через 5 минут | Через 1 неделю |
|---|---|---|
| только чтение (4 раза) | 83 % | 40 % |
| одно чтение + 3 раза припоминание | 71 % | 61 % |

Через пять минут читавшие помнили лучше и больше в себе были уверены. А через неделю они помнили 40 %, а
припоминавшие — 61 %. Снова иллюзия знания: перечитывание даёт ощущение «знаю», но надолго в памяти не оставляет.

У разработчиков похожий результат. Исследователи Anthropic Шен и Тамкин (arXiv, 2026) дали 52 разработчикам задачу с
незнакомой Python-библиотекой (Trio), не больше 35 минут. Половине дали AI-помощника (это был GPT-4o). На следующем
тесте средний балл группы с AI был 50 %, без AI — 67 %; самый большой разрыв — в вопросах по debugging. Внутри группы
с AI высокий балл получили 7 человек, которые спрашивали только объяснения (*conceptual inquiry*). Авторы не
утверждают причинно-следственной связи для этих групп, а тест был сразу после задачи.

**Код работает. Как узнать, что вы его действительно поняли?** Подумайте, прежде чем открывать ответ (подсказка:
опыт с молнией).

<details>
<summary>Ответ</summary>

Закройте чат и попробуйте написать эту строку по памяти. Или объясните её коллеге (или игрушке на столе): что
сравнивает `errors.Is`, зачем `errors.As` нужен `&me`. Не получается написать или объяснить — это была иллюзия знания.
Тогда вернитесь к наставнику и спросите снова.

</details>

## Частые ошибки

### 1. «Код работает, объяснение я прочитал — значит, понял»

Главная ловушка урока. Код машины ответов сработал 3/3, объяснение тоже было, но мы ничего не написали. В опыте
Розенблит и Кейла ощущение «знаю» тоже падало при попытке объяснить. Исправление: закройте чат и напишите по памяти
или объясните (раздел «Припоминание»). Не получилось — вернитесь к наставнику.

### 2. «Правила наставника есть — значит, я учусь»

В группе GPT Tutor вред на экзамене почти исчез, но пользы не было, а ученики думали, что написали лучше. `olchov` тоже
измеряет не обучение, а следование правилам. Исправление: и после наставника проверяйте себя и просите у Claude
проверочный вопрос в конце (домашнее задание 🟠).

### 3. `errors.Is(err, &MaydonXato{})` — поиск типа ошибки через `Is`

Тихая ошибка: компилируется, `go vet` молчит, результат `500` (раздел «Эксперимент»). `errors.Is` сравнивает через
`==`, а новый `&MaydonXato{}` никогда не равен указателю в цепочке. Исправление: ищите по типу.

```go
	if mx, ok := errors.AsType[*MaydonXato](err); ok {
		return 400, "notoʻgʻri maydon: " + mx.Maydon
	}
```

### 4. `errors.As(err, mx)` — без `&`

`panic: errors: target must be a non-nil pointer`, а `go vet` предупреждает заранее («Разговор с наставником»,
сообщение 2). Исправление: `errors.As(err, &mx)` или `errors.AsType`, которому указатель вообще не нужен. Запускайте
`go vet` в CI — эту ошибку он ловит, а ошибку 3 нет.

### 5. Написать правила один раз и не проверять

Правило — это указание, а не гарантия: даже стиль Learning в Claude Code на нашей задаче сам написал код. Исправление:
проверяйте правила несколько раз, сохраняйте ответы и измеряйте (`takrorla.sh` + `olchov`), как в CL-1.03.

зная имени, он ищет ответ на вопрос («есть ли функция, которая ищет тип?») и сам находит её в документации — это
generation effect. В первом сообщении имени не было ни в одном из трёх разговоров (0/3).

</details>

5. Из CL-1.02: куда в Claude.ai положить правила наставника, чтобы не писать их заново в каждом разговоре?

```go filename="homework/sinov/main.go" showLineNumbers
// sinov: Claude ustoz rejimida bergan uchta tekshiruv savoliga javobni ishga tushirib koʻrsatadi.
// Avval savollarga oʻzingiz javob yozing (README → Uy vazifasi), keyin: go run ./homework/sinov
package main

import (
	"errors"
	"fmt"
)

type MaydonXato struct{ Maydon, Sabab string }

func (e *MaydonXato) Error() string { return e.Maydon + ": " + e.Sabab }

// QiymatXato: xuddi shunday, lekin Error() qiymat qabul qiluvchida va pointersiz qaytariladi
type QiymatXato struct{ Maydon, Sabab string }

func (e QiymatXato) Error() string { return e.Maydon + ": " + e.Sabab }

func main() {
	err := fmt.Errorf("tekshir: %w", &MaydonXato{Maydon: "narx", Sabab: "musbat boʻlishi kerak"})

	// 1-savol: errors.Is qiymatni (bu yerda pointer manzilini) solishtiradi, AsType esa turni qidiradi
	_, ok := errors.AsType[*MaydonXato](err)
	fmt.Println("1. errors.Is(err, &MaydonXato{}):", errors.Is(err, &MaydonXato{}), "· AsType[*MaydonXato]:", ok)

	// 2-savol: yana bir qavat %w bilan oʻrasak zanjir saqlanadi, %v bilan esa uziladi
	w := fmt.Errorf("handler: %w", err)
	v := fmt.Errorf("handler: %v", err)
	_, okW := errors.AsType[*MaydonXato](w)
	_, okV := errors.AsType[*MaydonXato](v)
	fmt.Println("2. %w bilan yana oʻralgan:", okW, "· %v bilan:", okV)

	// 3-savol: xato pointersiz qaytsa, *QiymatXato turi zanjirda yoʻq
	q := fmt.Errorf("tekshir: %w", QiymatXato{Maydon: "narx", Sabab: "musbat boʻlishi kerak"})
	_, okP := errors.AsType[*QiymatXato](q)
	_, okQ := errors.AsType[QiymatXato](q)
	fmt.Println("3. pointersiz xato: AsType[*QiymatXato]:", okP, "· AsType[QiymatXato]:", okQ)
}
```

```console
$ go run ./homework/sinov
1. errors.Is(err, &MaydonXato{}): false · AsType[*MaydonXato]: true
2. %w bilan yana oʻralgan: true · %v bilan: false
3. pointersiz xato: AsType[*QiymatXato]: false · AsType[QiymatXato]: true
```

- (1) `errors.Is` сравнивает каждую ошибку цепочки через `==`; для указателей это «именно этот адрес?», а новый
  `&MaydonXato{}` — другой адрес. `AsType` же ищет **тип**.
- (2) `%w` сохраняет цепочку — число слоёв не важно, `holat` вернёт 400. `%v` превращает ошибку в обычный текст,
  цепочка рвётся → 500.
- (3) В цепочке есть `QiymatXato` (значение), а `*QiymatXato` (указателя) нет, поэтому `false`; нужен
  `AsType[QiymatXato]` (при условии, что `Error()` объявлен на value receiver). Тип должен совпадать точно. Для этого
  вопроса в файле есть отдельный тип `QiymatXato` («ошибка-значение»), потому что `Error()` у `MaydonXato` — на pointer
  receiver.
