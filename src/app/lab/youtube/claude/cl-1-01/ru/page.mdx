## Что вы узнаете

«Язык Python создал Google». Это сказала языковая модель. Она училась всего на шести верных предложениях, и в одном
из них написано «Python создал Гвидо». Модель выбрала Google с вероятностью 50 процентов, но в предложении этого
сомнения не видно. Как из верных данных получается неверный, но гладкий ответ? Сегодня разберём это шаг за шагом в
программе на Go из 150 строк и по документации Anthropic проверим, что в Claude устроено иначе.

**Одна идея:** языковая модель (LLM) на каждом шаге считает вероятности следующего токена и выбирает один из них.
Поэтому гладкий ответ ещё не значит верный ответ: знать истину — не работа модели, проверять её — ваша работа.

К концу урока вы:

- запустите маленькую модель из `main.go` и прочитаете каждое её решение: какой контекст она видела, какие были
  кандидаты, что она выбрала;
- измерите на открытом токенизаторе, сколько токенов занимает один и тот же текст на английском и на узбекском;
- покажете на примере, что контекстное окно и temperature могут исправить, а что не могут;
- будете проверять ответ Claude способами, которые советует Anthropic: дать документ, попросить цитату, разрешить
  сказать «не знаю».

Три основных новых слова сегодня:

| Слово | Простой смысл | Английский термин |
|---|---|---|
| токен | кусок, которым модель измеряет текст: слово, часть слова, символ или байт | token |
| контекстное окно (context window) | весь текст, который модель видит, пока пишет ответ, включая сам ответ | context window |
| сэмплирование (sampling) | выбор следующего токена среди вероятностей; **температура** (temperature) меняет форму этих вероятностей | sampling, temperature |

Вспомогательные слова объясняются одной фразой там, где встречаются впервые: **n-gram** (модель-счётчик слов),
**BPE** (способ работы токенизатора), **backoff** (откат к более короткому контексту), **галлюцинация**
(hallucination: гладкая выдумка там, где знаний нет).

Сначала один вопрос из GO-1.09. Модель хранит счёт в двухуровневом map. Что сделает эта программа?

```go
package main

func main() {
	sanoq := map[string]map[string]int{}
	sanoq["tilini"]["google"]++
}
```

**A)** `sanoq["tilini"]["google"]` станет 1 · **B)** ошибка компиляции · **C)** panic во время выполнения

<details>
<summary>Ответ</summary>

**C.** `sanoq["tilini"]` («счёт») ещё нет, поэтому вместо внутреннего map приходит его нулевое значение: `nil` map.
Читать из `nil` map можно (вернёт 0), а запись в него вызывает panic: `panic: assignment to entry in nil map`
(«присваивание элементу nil map»). Компилятор этого не ловит, ведь типы верны. Если вы выбрали «A», вы думали, что
map в Go сам создаёт вложенный map, как `defaultdict` в Python. Поэтому в `main.go` внутренний map сначала создаётся
(строки 37–39, ниже).

</details>

## Шесть верных предложений, один неверный ответ

Даём модели начало фразы: `python tilini` («язык python»). Продолжение она пишет сама:

```console
$ go run . python tilini
[tilini]           → google    google 0.50  guido 0.25  dennis 0.25
[google]           → yaratgan  yaratgan 0.67  ochiq 0.33
[yaratgan]         → .         . 1.00
python tilini google yaratgan .
```

Последняя строка — ответ модели: `python tilini google yaratgan .` («язык python создал google»). Неверно: Python
создал Гвидо ван Россум. Три строки перед ней — журнал того, что модель делала на каждом шаге:

| Часть | Пример | Смысл |
|---|---|---|
| `[tilini]` | в квадратных скобках | **контекст**, на который смотрела модель: последнее слово текста |
| `→ google` | после стрелки | следующее слово, которое выбрала модель |
| `google 0.50  guido 0.25  dennis 0.25` | в конце | все кандидаты и их вероятности |

На первом шаге модель увидела трёх кандидатов и выбрала Google, потому что его вероятность наибольшая: 0.50. На
втором шаге после `[google]` идёт `yaratgan` («создал», 0.67) или `ochiq` («открытым», 0.33). На третьем после
`[yaratgan]` — только точка. Когда выходит точка, фраза заканчивается.

На чём училась модель? Всё её «знание» — в одном файле:

```console
$ cat korpus.txt
go tilini google yaratgan .
go tilini google ochiq kodli qilgan .
gmail xizmatini google yaratgan .
python tilini guido yaratgan .
c tilini dennis yaratgan .
linux yadrosini linus yaratgan .
```

Такой текст, на котором учится модель, называется **корпус**. Все шесть предложений верны: Go создали в Google и в
2009 году открыли его код, C написал Деннис Ритчи, ядро Linux — Линус Торвальдс (источники в конце). Посчитайте, что
идёт после слова `tilini`:

| Слово после `tilini` | Сколько раз | Вероятность |
|---|---|---|
| `google` | 2 (1-е и 2-е предложения) | 2 / 4 = 0.50 |
| `guido` | 1 (4-е предложение) | 1 / 4 = 0.25 |
| `dennis` | 1 (5-е предложение) | 1 / 4 = 0.25 |

Модель видит только последнее слово, `tilini`. Стоящее перед ним `python` ей не видно. В корпусе после `tilini` чаще
всего шёл `google`, его модель и выбрала. Она не лгала: она посчитала и взяла самое частое. Любопытная деталь: Гвидо
ван Россум работал в Google в 2005–2012 годах, поэтому эта ошибка звучит особенно правдоподобно.

Claude тоже обучен предсказывать следующее слово. В глоссарии Anthropic (*Pretraining*) сказано: авторегрессионные
языковые модели, как модель, лежащая в основе Claude, обучаются «предсказывать следующее слово по предыдущему тексту».
Конечно, Claude намного больше нашего счётчика. Но форма вывода та же, и корень ошибки тоже здесь.

## Наша модель и Claude: общее у них одно

В этом треке мы учимся работать с Claude как инженеры. ИИ пишет код, но ответственность за результат остаётся на
вас. В треке пять модулей, все на учебном проекте курса bozor:

| Модуль | Что |
|---|---|
| CL-1 | правильная работа с ИИ: чат, промпт, обучение с ИИ, проверка ответа |
| CL-2 | Claude Code: ИИ-коллега в терминале |
| CL-3 | вызов Claude API из Go |
| CL-4 | свой агент и eval |
| CL-5 | безопасность |

Каждый ответ ИИ мы проверяем тестом и измерением. Для этого сначала нужно знать, что модель делает на самом деле.

Сегодня три понятия: токен, контекстное окно и сэмплирование. Наша модель — простая **n-gram**, то есть счётчик
слов: для каждого слова корпуса она считает, какие 1–3 слова шли перед ним (учебник Джурафски и Мартина, глава 3).
Claude устроен иначе:

| | Наша модель (`main.go`) | Claude |
|---|---|---|
| Токен | одно слово, точка тоже | слово, часть слова, символ или байт |
| Знание | счёт 6 предложений из `korpus.txt` | заранее обучен на огромных текстах, модель «со многими параметрами» |
| На что смотрит | последние 1–3 слова (`-oyna`) | на весь контекст |
| Дообучение | нет | дообучен быть ассистентом (fine-tuning, RLHF) |
| На каждом шаге | вероятности следующего токена, потом один выбор | то же самое |

Глоссарий Anthropic говорит это прямо: «Claude — не голая языковая модель; он уже дообучен (fine-tuning) быть
полезным ассистентом». **RLHF** — дообучение на оценках, которые поставили люди. Мы говорим «модель», а не
«трансформер»: ни одна прочитанная нами страница Anthropic не называет архитектуру.

Обратите внимание на последнюю строку. Весь урок опирается на это общее свойство.

## main.go построчно: таблица счёта и следующее слово

Вся модель:

```go filename="main.go" showLineNumbers
// Kichik til modeli: korpusdagi soʻzlarni sanaydi va keyingi soʻzni bashorat qiladi.
// Claude ham har qadamda bitta keyingi tokenni tanlaydi; bu dastur oʻsha gʻoyaning eng
// kichik nusxasi: n-gram model. Token = soʻz, model = sanoq jadvali (korpusdan bir marta
// oʻrganiladi), kontekst oynasi = javob paytida model koʻradigan oxirgi -oyna ta token.
//
//	go run . -oyna 1 -t 0 python tilini
package main

import (
	"flag"
	"fmt"
	"math"
	"math/rand/v2"
	"os"
	"sort"
	"strings"
)

// maxOyna: model oʻrganadigan eng uzun kontekst. -oyna undan katta boʻlolmaydi.
const maxOyna = 3

// model: kontekst (oxirgi k ta token) → keyingi token → necha marta uchradi.
type model struct {
	sanoq  map[string]map[string]int
	tartib map[string]int // token korpusda birinchi marta qayerda uchragan (teng holatda shu hal qiladi)
}

// oqit korpusdagi har bir oʻrin uchun 1..oyna uzunlikdagi kontekstlarni sanaydi.
func oqit(tokenlar []string, oyna int) model {
	m := model{sanoq: map[string]map[string]int{}, tartib: map[string]int{}}
	for i, tok := range tokenlar {
		if _, bor := m.tartib[tok]; !bor {
			m.tartib[tok] = i
		}
		for k := 1; k <= oyna && k <= i; k++ {
			kon := strings.Join(tokenlar[i-k:i], " ")
			if m.sanoq[kon] == nil {
				m.sanoq[kon] = map[string]int{}
			}
			m.sanoq[kon][tok]++
		}
	}
	return m
}

type nomzod struct {
	token string
	soni  int
	p     float64
}

// taqsimot: eng uzun tanish kontekstni topadi va temperature bilan ehtimolliklarni hisoblaydi.
// p ~ soni^(1/t). t = 0 boʻlsa modelning oʻz ehtimolligi (t = 1) koʻrsatiladi,
// tanlov esa har doim eng ehtimolli token (greedy).
func (m model) taqsimot(matn []string, oyna int, t float64) (string, []nomzod) {
	for k := min(oyna, len(matn)); k >= 1; k-- {
		kon := strings.Join(matn[len(matn)-k:], " ")
		keyingi, bor := m.sanoq[kon]
		if !bor {
			continue // bunday kontekst korpusda yoʻq: qisqaroq kontekstga oʻtamiz
		}
		var ns []nomzod
		for tok, soni := range keyingi {
			ns = append(ns, nomzod{token: tok, soni: soni})
		}
		sort.Slice(ns, func(i, j int) bool {
			if ns[i].soni != ns[j].soni {
				return ns[i].soni > ns[j].soni
			}
			return m.tartib[ns[i].token] < m.tartib[ns[j].token]
		})
		daraja := 1.0
		if t > 0 {
			daraja = 1 / t
		}
		var jami float64
		for i := range ns {
			ns[i].p = math.Pow(float64(ns[i].soni), daraja)
			jami += ns[i].p
		}
		for i := range ns {
			ns[i].p /= jami
		}
		return kon, ns
	}
	return "", nil
}

// tanla: ehtimollik boʻyicha bitta tokenni tasodifiy tanlaydi (sampling).
func tanla(ns []nomzod, r *rand.Rand) string {
	x := r.Float64()
	for _, n := range ns {
		if x < n.p {
			return n.token
		}
		x -= n.p
	}
	return ns[len(ns)-1].token
}

func main() {
	oyna := flag.Int("oyna", 1, "kontekst oynasi: model oxirgi nechta tokenni koʻradi")
	t := flag.Float64("t", 0, "temperature: 0 = har doim eng ehtimolli token")
	seed := flag.Uint64("seed", 1, "tasodif urugʻi (bir xil seed = bir xil natija)")
	n := flag.Int("n", 1, "nechta javob yaratish (n > 1 boʻlsa faqat javoblar chiqadi)")
	korpus := flag.String("korpus", "korpus.txt", "model oʻrganadigan matn")
	flag.Parse()

	matn, err := os.ReadFile(*korpus)
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	if *oyna < 1 || *oyna > maxOyna {
		fmt.Fprintf(os.Stderr, "-oyna 1..%d boʻlishi kerak\n", maxOyna)
		os.Exit(2)
	}
	m := oqit(strings.Fields(strings.ToLower(string(matn))), maxOyna)
	boshi := strings.Fields(strings.ToLower(strings.Join(flag.Args(), " ")))
	if len(boshi) == 0 {
		fmt.Fprintln(os.Stderr, "boshlanish soʻzlarini bering, masalan: go run . python tilini")
		os.Exit(2)
	}
	r := rand.New(rand.NewPCG(*seed, 0))

	for j := 0; j < *n; j++ {
		jumla := append([]string(nil), boshi...)
		for len(jumla) < 20 && jumla[len(jumla)-1] != "." {
			kon, ns := m.taqsimot(jumla, *oyna, *t)
			if ns == nil {
				fmt.Printf("%-18s → ?         korpusda yoʻq\n", "["+jumla[len(jumla)-1]+"]")
				break
			}
			var tok string
			if *t == 0 {
				tok = ns[0].token
			} else {
				tok = tanla(ns, r)
			}
			if *n == 1 {
				var qator []string
				for _, x := range ns {
					qator = append(qator, fmt.Sprintf("%s %.2f", x.token, x.p))
				}
				fmt.Printf("%-18s → %-9s %s\n", "["+kon+"]", tok, strings.Join(qator, "  "))
			}
			jumla = append(jumla, tok)
		}
		fmt.Println(strings.Join(jumla, " "))
	}
}
```

Сначала часть со счётом:

| Строка | Код | Что делает |
|---|---|---|
| 1–6 | комментарий | говорит, что это за программа и как её запускать |
| 9–17 | `import (…)` | `flag` (флаги командной строки), `fmt` (вывод), `math` (степень), `math/rand/v2` (случайные числа, с Go 1.22), `os` (файл, код выхода), `sort`, `strings` |
| 20 | `const maxOyna = 3` | самый длинный контекст, который учит модель: 3 слова (`oyna` — «окно») |
| 23–26 | `type model struct` | модель — это два map: `sanoq` («счёт») и `tartib` («порядок») |
| 24 | `sanoq map[string]map[string]int` | контекст → следующее слово → сколько раз встретилось. Например `sanoq["tilini"]["google"] == 2` |
| 25 | `tartib map[string]int` | на какой позиции корпуса слово встретилось впервые; при равном счёте раньше встреченное идёт первым |
| 29 | `func oqit(tokenlar []string, oyna int) model` | обучение (`oqit` — «обучить»): строит таблицу счёта из списка слов |
| 30 | `m := model{sanoq: …, tartib: …}` | создаёт оба map пустыми |
| 31 | `for i, tok := range tokenlar` | каждое слово корпуса (`tok`) и его позиция (`i`) |
| 32–34 | `if _, bor := m.tartib[tok]; !bor` | если слово встретилось впервые, записывает позицию (`bor` — «есть ли ключ?», GO-1.09) |
| 35 | `for k := 1; k <= oyna && k <= i; k++` | контексты из 1, 2 и 3 слов перед `tok` (в начале корпуса меньше) |
| 36 | `kon := strings.Join(tokenlar[i-k:i], " ")` | склеивает `k` слов перед `tok` через пробел в одну строку: `"python tilini"` |
| 37–39 | `if m.sanoq[kon] == nil { … }` | если внутреннего map ещё нет, создаёт его (иначе panic из вопроса выше) |
| 40 | `m.sanoq[kon][tok]++` | увеличивает на единицу счёт «после `kon` пришло `tok`» |
| 46–50 | `type nomzod struct` | один кандидат (`nomzod`): слово, его счёт и вероятность `p` |

Обучение происходит один раз, в строке 118. `strings.ToLower` делает все буквы строчными, `strings.Fields` делит

сохраните его в папку урока как `bigram.py` и запустите сами):


## Токен: в чём модель измеряет текст

Модель читает текст не буквами и не словами, а **токенами**. В нашей модели один токен равен одному слову. По
глоссарию Anthropic, в Claude токен может быть словом, частью слова, символом или даже байтом. Сколько символов
приходится на один токен, зависит от модели и языка. Глоссарий добавляет: Claude 4.7 и более новые модели используют
новый **токенизатор** (tokenizer — программа, которая делит текст на токены). Для того же текста он даёт примерно на
30 процентов больше токенов, чем у прежних моделей. Руководство по миграции на Opus 5.5 точнее: от 1 до 1,35 раза.

Нынешний токенизатор Claude не опубликован. Поэтому посмотрим одно слово на **открытом** токенизаторе OpenAI
`o200k_base`. Это не число Claude, только тенденция. `uv run --quiet` тихо запускает скрипт с нужной библиотекой.

Английское `we are learning` (3 слова) и узбекское `oʻrganmoqdamiz` (1 слово, «мы учимся»). Где больше токенов?

**A)** в английском, ведь слов больше · **B)** поровну, смысл один · **C)** в узбекском, намного больше

<details>
<summary>Ответ</summary>

**C.** Английское — 3 токена, узбекское с перевёрнутой запятой `ʻ` — 8 токенов, с обычным апострофом с клавиатуры —
7. Если вы выбрали «A», вы думали, что токен = слово. Так только в нашей маленькой модели.

</details>

```console
$ uv run --quiet tokenlar/tokenlar.py soz
we are learning  3 token: we |  are |  learning
oʻrganmoqdamiz   8 token: o | ʻ | r | gan | mo | q | dam | iz
o'rganmoqdamiz   7 token: o | 'r | gan | mo | q | dam | iz
```

Знак `|` показывает границы токенов. `we`, ` are` и ` learning` — три целых слова (пробел перед словом тоже входит в
токен). А `oʻrganmoqdamiz` разбилось на восемь кусков: `o | ʻ | r | gan | mo | q | dam | iz`. Перевёрнутая запятая
`ʻ` (U+02BB) в UTF-8 занимает 2 байта (GO-1.04) и здесь стала отдельным токеном. С апострофом с клавиатуры `'r`
слилось в один токен, всего 7.

Такие токенизаторы строятся методом **BPE** (byte pair encoding). Он объединяет частые последовательности символов в
один токен (Сеннрих и др., 2016). Английское ` learning` встречается часто, поэтому стало одним токеном. Вероятно, в
текстах, на которых обучали этот токенизатор, узбекского было мало. Это наш вывод, а не измерение.

Одного слова мало. Теперь большой текст: Всеобщая декларация прав человека на английском и узбекском (параллельный
текст, смысл один). Первая строка от `tokenlar.py`, вторая от `eski_claude.mjs`; `&&` запускает вторую команду, только
если первая завершилась успешно:

```console
$ uv run --quiet tokenlar/tokenlar.py til && node tokenlar/eski_claude.mjs
Inson huquqlari deklaratsiyasi     inglizcha oʻzbekcha   farq
belgilar                               10638     12241  1.15x
tokenlar: o200k_base (OpenAI)           2011      3911  1.94x
tokenlar: Claude 3 gacha                2068      5249  2.54x
```

| Строка | Английский | Узбекский | Разница | Что это |
|---|---|---|---|---|
| `belgilar` | 10638 | 12241 | 1.15x | символов почти поровну: узбекский текст длиннее всего на 15 процентов |
| `o200k_base (OpenAI)` | 2011 | 3911 | 1.94x | а токенов почти вдвое больше |
| `Claude 3 gacha` | 2068 | 5249 | 2.54x | открытый токенизатор Anthropic для моделей до Claude 3 |

(`belgilar` — «символы», `tokenlar` — «токены», `gacha` — «до».) С третьей строкой осторожно. README пакета
`@anthropic-ai/tokenizer`: «начиная с моделей Claude 3 этот алгоритм больше не точен, только очень приблизителен».
Точное число для нынешнего Claude сообщает только API: в поле `usage` каждого ответа написано, сколько токенов
израсходовал запрос (`input_tokens`, `output_tokens`). Мы измерим его в [CL-3.01](/lab/youtube/claude#cl-3-01).

Почему это важно? И цена, и контекстное окно измеряются в токенах. Цены Anthropic указаны как «$ за миллион входных
токенов» и «$ за миллион выходных токенов». Значит, узбекский текст с тем же смыслом может занимать больше токенов: он
стоит дороже и меньше помещается в окно. Точную разницу для Claude мы не измеряли. На открытых токенизаторах она
1,94 и 2,54 раза.

Вид апострофа на всём тексте почти не влияет: `tokenlar.py apostrof` даёт 3911 токенов с перевёрнутой запятой, 3892 с
апострофом с клавиатуры и 3938 с `‘`. Как BPE режет узбекский текст — [ML-4.01](/lab/youtube/ml#ml-4-01).

## Контекстное окно: текст, видимый во время ответа

Второе понятие — **контекстное окно** (context window). Определение Anthropic: весь текст, который модель может
видеть, пока пишет ответ, включая сам ответ. Это «рабочая память» модели, а не огромные данные, на которых она
обучалась. В чате это ваши сообщения, ответы Claude и добавленные вами файлы.

Цифры (Anthropic, *Context windows* и *Models overview*):

| Факт | Значение |
|---|---|
| нынешние модели Claude через API | 1 000 000 токенов |
| это примерно | 555 000 слов (на новом токенизаторе) |
| с ростом числа токенов | точность и припоминание падают: **context rot** |
| в очень длинном диалоге в чате | чат-приложения (например, claude.ai) могут выталкивать старые сообщения из окна |

В нашей модели окно — флаг `-oyna`. Он не переобучает модель: модель всегда обучается с контекстом до 3 слов
(строка 118). Флаг лишь задаёт, на сколько последних слов текста модель смотрит во время ответа (строка 56).

```text
-oyna 1:   python [tilini]          модель видит только "tilini"
-oyna 2:   [python tilini]          модель видит пару "python tilini"
```

`-oyna 1` — значение по умолчанию. Поэтому вывод тот же, что в начале урока:

```console
$ go run . -oyna 1 python tilini
[tilini]           → google    google 0.50  guido 0.25  dennis 0.25
[google]           → yaratgan  yaratgan 0.67  ochiq 0.33
[yaratgan]         → .         . 1.00
python tilini google yaratgan .
```

`python` остался за пределами окна. Что будет, если увеличить окно до двух?

**A)** снова `google`: Google в корпусе всё равно чаще · **B)** `guido`, вероятность 1.00 · **C)** `→ ?`, такого контекста нет

<details>
<summary>Ответ</summary>

**B.** Теперь контекст — `python tilini`. В корпусе после этой пары шло только одно слово: `guido`. Если вы выбрали
«A», вы думали, что модель берёт самое частое слово всего корпуса: на деле она считает только слова после этого
контекста. «C» было бы, если бы `python tilini` не было в корпусе.

</details>

```console
$ go run . -oyna 2 python tilini
[python tilini]    → guido     guido 1.00
[tilini guido]     → yaratgan  yaratgan 1.00
[guido yaratgan]   → .         . 1.00
python tilini guido yaratgan .
```

Ответ верный. На втором шаге контекст `[tilini guido]`, на третьем `[guido yaratgan]`: окно — всегда два последних
слова.

Но не делайте отсюда вывод «Claude ошибается, потому что окно маленькое». Окно Claude — миллион токенов, такой
короткий вопрос из него не выпадет. Его ошибки приходят из другого места. Это мы увидим, начиная со следующего раздела.

## Там, где нет знаний: rust, backoff и галлюцинация

Теперь спросим о языке, которого в корпусе нет вовсе: Rust. Сначала одно слово:

```console
$ go run . rust
[rust]             → ?         korpusda yoʻq
rust
```

`→ ?  korpusda yoʻq` («нет в корпусе»): модель промолчала, потому что никогда не видела, что идёт после `rust`
(строки 130–133). Теперь скажем `rust tilini`, окно 2:

```console
$ go run . -oyna 2 rust tilini
[tilini]           → google    google 0.50  guido 0.25  dennis 0.25
[tilini google]    → yaratgan  yaratgan 0.50  ochiq 0.50
[google yaratgan]  → .         . 1.00
rust tilini google yaratgan .
```

`[rust tilini]` в корпусе нет. Модель не промолчала: она отбросила незнакомое `rust` и опёрлась на знакомое `[tilini]`
(строки 56–61, `continue`). Такой переход к более короткому контексту называется **backoff** (откат). Именно это
решение заставило модель гадать вместо того, чтобы молчать. На втором шаге после `[tilini google]` у `yaratgan` и
`ochiq` поровну (0.50), и модель взяла `yaratgan`, встреченное в корпусе раньше (строки 66–71).

Снова Google. На самом деле Rust начал Грейдон Хоар: в 2006 году как личный проект, с 2009 года при поддержке
Mozilla. Гладкий текст там, где знаний нет, называют **галлюцинацией** (hallucination). Здесь увеличение окна не
поможет: `rust` в окне есть, но знаний о нём у модели нет.

Различайте две ошибки:

| Случай | Причина | Что исправляет |
|---|---|---|
| `python tilini` → google | нужное слово за пределами окна | окно побольше (`-oyna 2`) |
| `rust tilini` → google | знаний нет вовсе, backoff угадал | не окно: знание или «не знаю» |

## Сэмплирование и temperature

Третье понятие — **сэмплирование** (sampling), то есть выбор следующего токена. На каждом шаге модель даёт каждому
кандидату вероятность. Потом нужно взять одного из них. **Температура** (temperature, `-t`) задаёт две вещи.

Первая — как выбирать. При `t = 0` всегда берётся самый вероятный. Это **жадный** (greedy) выбор:

```go
			var tok string
			if *t == 0 {
				tok = ns[0].token
			} else {
				tok = tanla(ns, r)
			}
```

`ns` отсортирован, поэтому `ns[0]` — самый вероятный кандидат (строки 134–139). При `t > 0` бросается жребий
пропорционально вероятностям: большая вероятность выигрывает чаще, но и маленькая иногда выпадает. Это делает `tanla`:

```go
func tanla(ns []nomzod, r *rand.Rand) string {
	x := r.Float64()
	for _, n := range ns {
		if x < n.p {
			return n.token
		}
		x -= n.p
	}
	return ns[len(ns)-1].token
}
```

`r.Float64()` даёт случайное число от 0 до 1 (1 не входит). Разложите кандидатов подряд на отрезке 0..1: в чей
кусок попадёт `x`, тот и выбран. В цикле: если `x < n.p`, берём этого кандидата; иначе вычитаем `n.p` из `x` и
переходим к следующему. Последний `return` — запас на случай ошибки округления. В JS с `Math.random()` пишется так же.

```text
t = 1,  [tilini]:
0                     0.50          0.75          1
|-------- google -------|--- guido ---|-- dennis --|
x = 0.62  →  0.62 ≥ 0.50, x = 0.12  →  0.12 < 0.25  →  guido
```

Вторая — форма вероятностей. Строки 72–83 возводят счёт в степень и делят на сумму: `p ~ soni^(1/t)` (`soni` —
«количество», `daraja` — «степень», `jami` — «сумма»).

```go
		daraja := 1.0
		if t > 0 {
			daraja = 1 / t
		}
		var jami float64
		for i := range ns {
			ns[i].p = math.Pow(float64(ns[i].soni), daraja)
			jami += ns[i].p
		}
		for i := range ns {
			ns[i].p /= jami
		}
```

Для `[tilini]` счёт 2, 1, 1. Посчитаем:

| `t` | `1/t` | google | guido | dennis | сумма | p(google) |
|---|---|---|---|---|---|---|
| 0.5 | 2 (квадрат) | 2² = 4 | 1 | 1 | 6 | 4 / 6 = 0.67 |
| 1 | 1 (как есть) | 2 | 1 | 1 | 4 | 2 / 4 = 0.50 |
| 2 | 0.5 (квадратный корень) | √2 ≈ 1.41 | 1 | 1 | 3.41 | 1.41 / 3.41 = 0.41 |

Маленькая температура усиливает фаворита, большая выравнивает распределение. При `t = 0` в журнале показывается
собственная вероятность модели (как при `t = 1`) (комментарий в строках 53–54). Для тех, кто знает математику:
нормированное `soni^(1/t)` — это softmax от `log(soni) / t`, стандартное определение температуры.

Теперь три температуры одной командой. `for t in 0.5 1 2; do … done` по очереди даёт `t` три значения и трижды
запускает одну и ту же команду. `$(…)` берёт вывод команды внутри, `head -1` оставляет только первую строку, а
`printf 't=%-4s %s\n'` печатает `t` в колонке шириной 4 символа:

```console
$ for t in 0.5 1 2; do printf 't=%-4s %s\n' $t "$(go run . -t $t python tilini | head -1)"; done
t=0.5  [tilini]           → google    google 0.67  guido 0.17  dennis 0.17
t=1    [tilini]           → google    google 0.50  guido 0.25  dennis 0.25
t=2    [tilini]           → google    google 0.41  guido 0.29  dennis 0.29
```

Совпадает с таблицей: 0.67, 0.50, 0.41.

Теперь создадим фразу `python tilini` 10 000 раз (`-n 10000`) и посчитаем, сколько раз вышел верный ответ, Гвидо.
`grep -c guido` — число строк, где есть `guido`:

```console
$ for t in 0 1 2; do echo "t=$t: $(go run . -t $t -n 10000 python tilini | grep -c guido) / 10000 guido"; done
t=0: 0 / 10000 guido
t=1: 2418 / 10000 guido
t=2: 2891 / 10000 guido
```

| `t` | Ожидалось | Вышло |
|---|---|---|
| 0 | 0 (всегда google) | 0 |
| 1 | 0.25 × 10 000 = 2500 | 2418 (примерно четверть) |
| 2 | 0.29 × 10 000 ≈ 2929 | 2891 (почти 29 процентов) |

Разница между ожидаемым и полученным — случайность. С другим seed (`-seed 2` … `-seed 5`) при `t = 1` выходит
2413–2513, при `t = 2` — 2854–2934. Вывод не меняется.

Значит, если поднять температуру, верных ответов станет больше? Ответьте на вопрос в следующем разделе.

## Температура не знает истины

Вопрос с паузой из видео. Проведём тот же опыт с `go tilini` («язык go»). Здесь верный ответ — Google. Как
изменится число верных ответов, если поднять температуру с 0 до 2? Подсказка: что видит модель при окне 1?

**A)** вырастет, как с `python tilini` · **B)** уменьшится · **C)** не изменится

<details>
<summary>Ответ</summary>

**B.** При окне 1 модель и для `go tilini` видит только `[tilini]`: контекст тот же, что у `python tilini`, и
кандидаты те же (google 2, guido 1, dennis 1). Только на этот раз верный ответ — фаворит. Температура выравнивает
распределение, значит, фаворит выпадает реже. Если вы выбрали «A», вы думали, что температура улучшает верный ответ.
С `python tilini` она «помогла» лишь потому, что фаворит был неверным.

</details>

```console
$ for t in 0 1 2; do echo "t=$t: $(go run . -t $t -n 10000 go tilini | grep -c google) / 10000 google"; done
t=0: 10000 / 10000 google
t=1: 5027 / 10000 google
t=2: 4105 / 10000 google
```

При `t = 0` верны все 10 000 ответов, при `t = 1` — половина (ожидалось 5000), при `t = 2` — 41 процент (ожидалось
4142). Тот же контекст, то же распределение, разная только истина:

| Вопрос | Контекст (окно 1) | Верный ответ | `t = 0` | `t = 1` | `t = 2` |
|---|---|---|---|---|---|
| `python tilini` | `[tilini]` | guido | 0 | 2418 | 2891 |
| `go tilini` | `[tilini]` | google | 10 000 | 5027 | 4105 |

Температура не знает истины. Она лишь меняет форму распределения: уменьшает неверного фаворита, но и верного тоже.

## Температура в Claude

Как это работает в Claude? Три факта:

1. Глоссарий Anthropic (*Temperature*): даже при температуре 0 результат не полностью детерминирован, и одинаковый
   вход может давать разные ответы в разных вызовах API.
2. Руководство по миграции на Opus 5.5: в Opus 5.5 `temperature`, `top_p` и `top_k` удалены, а в самой новой версии
   API их нет у всех моделей. Если отправить эти параметры, API вернёт ошибку.
3. То же руководство: поведением модели рекомендуется управлять через промпт.

Практический вывод: на один и тот же вопрос могут прийти разные ответы. Кнопки «заморозить всё», как `-seed` в нашей
модели, нет. Поэтому на этой странице нет ни одного ответа Claude: вы не смогли бы его точно повторить.

## Почему уверенно, но неверно?

Теперь главный вопрос: почему ответ звучит уверенно, но оказывается неверным? Три причины:

| # | Причина | В нашей модели | Источник |
|---|---|---|---|
| 1 | модель всегда должна угадать следующее слово, обучение к этому подталкивает | backoff отбросил `rust` и всё равно ответил | Anthropic, *Tracing the thoughts…* (2025) |
| 2 | вероятность в тексте не видна | google выбран с 0.50, а в фразе нет «возможно» | `go run . python tilini` |
| 3 | оценивание тоже поощряет угадывание | — | Калаи и др., *Why Language Models Hallucinate* (2025) |

Третью причину авторы статьи объясняют через экзамен. Если за неверный ответ баллы не снимают, студент, который
угадывает, получает больше баллов, чем тот, кто говорит «не знаю». Обучение и оценивание языковых моделей часто
устроены так же: угадывать выгоднее, чем признавать неуверенность.

В отличие от нашей модели, Claude обучен и говорить «не знаю». Anthropic называет это обучение «относительно успешным,
но не идеальным». Изучив внутреннее устройство **Claude 3.5 Haiku** (2025), они нашли следующее:

```text
обычное состояние:    схема «не знаю» ВКЛЮЧЕНА             → «не могу ответить»
знакомое имя:         Michael Jordan → признак «знакомо»    → схема ВЫКЛЮЧАЕТСЯ → верный ответ
незнакомое имя:       Michael Batkin → признака нет        → схема включена  → «не знаю»
имя знакомо, знаний нет: признак «знакомо» срабатывает по ошибке → схема ВЫКЛЮЧАЕТСЯ → правдоподобный, но неверный ответ
```

Последняя строка самая опасная. Если имя кажется знакомым, а знаний нет, схема может выключиться по ошибке. Тогда
модель сочиняет правдоподобный, но неверный ответ. Исследование проведено на Claude 3.5 Haiku. О других моделях Claude
оно ничего точно не говорит.

## Что делать против уверенной ошибки

Способы из документа Anthropic *Reduce hallucinations*:

1. **Явно разрешите сказать «не знаю».** Напишите в промпте: если данных не хватает, пусть ответит «не знаю».
2. **Дайте документ и просите отвечать только по нему.** Положите нужный документ (API spec, README, лог) в промпт и
   скажите «опирайся только на этот документ».
3. **К каждому утверждению просите дословную цитату из документа.** Если цитата не нашлась, утверждение убирается. Не
   просите «источник» по памяти: модель может выдумать и источник. Цитата должна быть из документа, который дали вы.
4. **Задайте один вопрос несколько раз и сравните.** Если ответы противоречат друг другу — это сигнал опасности. Но
   одинаковый ответ — не доказательство: наша модель при `t = 0` 10 000 раз повторила одну и ту же ошибку.
5. **Код всегда запускайте и тестируйте.** Подробно — в [CL-1.05](/lab/youtube/claude#cl-1-05).

Сам документ предупреждает: эти способы уменьшают ошибки, но не устраняют их полностью.

Первые три способа в одном промпте могут выглядеть так (структура промпта — [CL-1.03](/lab/youtube/claude#cl-1-03)):

```text
<документ>
… сюда текст README или документации API …
</документ>

Отвечай на вопрос, опираясь только на документ выше.
Если ответа в документе нет, напиши «не знаю».
К каждому утверждению приведи дословную цитату из документа.
Утверждение, для которого цитата не нашлась, убери из ответа.
```

Если применить эти способы к нашей модели: «не знаю» — уровень 🟠 домашнего задания, «дать документ» — уровень 🟢
(добавить нужное предложение в корпус).

Коротко: модель предсказывает следующий токен, её окно ограничено, а в выборе есть случайность. Поэтому гладкий ответ
ещё не значит верный ответ. На следующем уроке учимся правильно пользоваться Claude.ai: выбор модели, Projects и
файлы ([CL-1.02](/lab/youtube/claude#cl-1-02)).

## Частые ошибки

### 1. «Подниму температуру — верных ответов станет больше»

Классическое заблуждение этого урока. С `python tilini` `t = 2` подняло верные ответы с 0 до 2891, но только потому,
что фаворит был неверным. С `go tilini` та же температура уменьшила верные ответы с 10 000 до 4105 (раздел
«Температура не знает истины»). Температура выравнивает распределение и не знает истины. Исправление: повышайте
точность ответа не температурой, а контекстом (документом) и проверкой.

### 2. «Спросил пять раз, пять раз один и тот же ответ — значит, верно»

```console
$ go run . -t 0 -n 5 python tilini
python tilini google yaratgan .
python tilini google yaratgan .
python tilini google yaratgan .
python tilini google yaratgan .
python tilini google yaratgan .
```

Пять раз одинаково и пять раз неверно. Одинаковость показывает лишь уверенность модели в этом ответе, а не истину.
Противоречивые ответы — сигнал опасности; одинаковые — ещё не доказательство. Исправление: проверяйте утверждение
документом или запущенным кодом.

### 3. «Поставлю `temperature: 0`, и Claude всегда будет отвечать одинаково»

Неверно по двум причинам (раздел «Температура в Claude»). Во-первых, глоссарий Anthropic не гарантирует полной
детерминированности даже при 0. Во-вторых, в Opus 5.5 (а в самой новой версии API — у всех моделей) `temperature`
нет вовсе: если отправить оставшиеся от старого кода `temperature`, `top_p` или `top_k`, запрос вернётся с ошибкой.
Для этой страницы мы API не вызывали, поэтому текст ошибки не показываем. Исправление: уберите параметр и опишите
нужное поведение в промпте.

### 4. «1 токен ≈ 4 символа, и на узбекском так же»

Это правило говорят для английского текста и других токенизаторов. По глоссарию Anthropic, отношение символов к
токенам зависит от модели и языка. В декларации узбекский текст занял на `o200k_base` в 1,94 раза больше токенов, чем
английский, на старом токенизаторе Anthropic — в 2,54 раза, хотя символов всего в 1,15 раза больше (раздел «Токен»).
Исправление: считайте цену и окно не на глаз, а по полю `usage`.

### 5. «Контекстное окно побольше исправит ошибку»

`-oyna 2` исправил `python tilini`, но не `rust tilini`: `rust` в окне есть, знаний нет. Окно Claude — миллион
токенов, короткий вопрос из него не выпадет. А очень длинный контекст снижает точность (context rot). Исправление:
дайте нужный документ, не забивайте окно лишним текстом.

### 6. «Достаточно попросить у Claude источник»

«Источник», запрошенный по памяти, тоже может оказаться выдумкой: модель пишет его тоже как следующие токены.
Совет Anthropic другой: цитата должна быть из документа, который **дали** вы; если её нет, утверждение убирается.
Исправление: промпт из раздела «Что делать против уверенной ошибки».

### 7. Ошибки программы: `-oyna 4` и другая папка

Окно вне 1..3:

```console
$ go run . -oyna 4 python tilini
-oyna 1..3 boʻlishi kerak
exit status 2
```

Первую строку написала программа (строки 114–117): «-oyna должно быть 1..3». `exit status 2` добавляет `go run`:
программа завершилась с кодом выхода 2. Модель училась только на контексте до 3 слов (`maxOyna = 3`), поэтому окно
больше бессмысленно. Исправление: `-oyna 1`, `2` или `3`.

Если запустить программу вне папки урока:

```console
$ cd .. && go run ./cl-01-next-token python tilini
open korpus.txt: no such file or directory
exit status 1
```

`open korpus.txt: no such file or directory` — «не удалось открыть `korpus.txt`: нет такого файла или каталога».
Программа ищет корпус в текущей папке (строка 106, по умолчанию `-korpus korpus.txt`). Исправление: перейдите в папку
урока через `cd` или укажите путь: `-korpus cl-01-next-token/korpus.txt`.

Если запустить `tokenlar.py` без `uv`, как `python3 tokenlar/tokenlar.py soz`, и `tiktoken` не установлен, в последней
строке будет `ModuleNotFoundError: No module named 'tiktoken'` («нет модуля с именем `tiktoken`»). Исправление:
`uv run --quiet tokenlar/tokenlar.py soz`. В блоке `# /// script` в начале скрипта указаны нужная библиотека и её
версия, `uv` установит её сам.

4. После `[google]` счёт: `yaratgan` 2, `ochiq` 1. Какова вероятность `yaratgan` при `t = 0.5`?

**A)** 0.67 · **B)** 0.80 · **C)** 0.59

<details>
<summary>Ответ</summary>

**B.** `1/t = 2`: счёт возводится в квадрат, 2² = 4 и 1² = 1, сумма 5, значит 4 / 5 = 0.80. «A» — значение при

5. Из GO-1.04: что выведет эта программа и как это связано с токенами `oʻrganmoqdamiz`?

```go
package main

import "fmt"

func main() {
	fmt.Println(len("ʻ"), len("'"))
	fmt.Printf("% x\n", "oʻ")
}
```

<details>
<summary>Ответ</summary>

В Go `len` считает байты. Перевёрнутая запятая `ʻ` (U+02BB) в UTF-8 — 2 байта (`ca bb`), апостроф с клавиатуры —
1 байт. `"% x"` печатает каждый байт в шестнадцатеричном виде через пробел:

```console
$ go run main.go
2 1
6f ca bb
```

BPE-токенизаторы работают с байтами и объединяют частые последовательности. В `o200k_base` `ʻ` ни с чем не
объединился и стал отдельным токеном (`o | ʻ | r`), а ASCII `'` слился с `r` в один токен (`'r`). Отсюда 8 и 7
токенов.

</details>

```console
[guido yaratgan]   → .         . 1.00
python tilini guido yaratgan .
```

При окне 2 у `guido` 1.00, и модель отвечает. Но есть цена:

```console
$ go run ./homework -chegara 0.6 go tilini
[tilini]           → bilmayman eng yuqorisi google 0.50 < 0.60
go tilini (bilmayman)
```

Здесь самый вероятный ответ (`google`) был верным, а модель всё равно промолчала. Молчание уменьшает ошибки, но
теряет и верные ответы.

🔴 Флаг `-k` в `homework/main.go`: из отсортированных кандидатов остаются только первые `k` (`ns = ns[:topk]`).
`sort | uniq -c | sort -rn` считает одинаковые ответы и сортирует от частых к редким:

```console
$ go run ./homework -t 1 -k 2 -n 100 python tilini | sort | uniq -c | sort -rn
     40 python tilini google yaratgan .
     33 python tilini guido yaratgan .
     27 python tilini google ochiq kodli qilgan .
```

`dennis` нет вовсе: при `k = 2` остались только google и guido. Для сравнения `-k 1` = жадный выбор, `-k 0` = обычное
сэмплирование:

```console
$ go run ./homework -t 1 -k 1 -n 100 python tilini | sort | uniq -c | sort -rn
    100 python tilini google yaratgan .
```

```console
$ go run ./homework -t 1 -k 0 -n 100 python tilini | sort | uniq -c | sort -rn
     33 python tilini google yaratgan .
     24 python tilini dennis yaratgan .
     22 python tilini google ochiq kodli qilgan .
     21 python tilini guido yaratgan .
```

Температура меняет форму распределения (все кандидаты остаются), а top-k отрезает хвост (маловероятные кандидаты не
выпадают вовсе). 100 примеров — мало: числа меняются на несколько процентов в зависимости от seed.
