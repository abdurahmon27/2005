## Nimani oʻrganasiz

«Python tilini Google yaratgan.» Bu gapni til modeli aytdi. U faqat oltita toʻgʻri gapdan oʻrgangan, ularning
birida «Python'ni Guido yaratgan» deb yozilgan. Model Google'ni 50 foiz ehtimollik bilan tanladi, lekin gapda bu
ikkilanish koʻrinmaydi. Qanday qilib toʻgʻri maʼlumotdan notoʻgʻri, lekin ravon javob chiqadi? Bugun buni 150 qatorlik
Go dasturida qadamma-qadam koʻramiz va Claude'da nima farq qilishini Anthropic hujjatlari bilan tekshiramiz.

**Bitta gʻoya:** til modeli (LLM) har qadamda keyingi token uchun ehtimolliklarni hisoblaydi va ulardan bittasini
tanlaydi. Shuning uchun ravon javob hali toʻgʻri javob degani emas: haqiqatni bilish modelning ishi emas, uni
tekshirish sizning ishingiz.

Dars oxirida siz:

- `main.go` dagi kichik modelni ishga tushirib, uning har bir qarorini oʻqiysiz: qaysi kontekstni koʻrdi, qaysi
  nomzodlar bor edi, nimani tanladi;
- bir xil matn ingliz va oʻzbek tilida necha token boʻlishini ochiq tokenizer'da oʻlchaysiz;
- context window va temperature nimani tuzata olishini va nimani tuzata olmasligini misol bilan koʻrsatasiz;
- Claude javobini Anthropic tavsiya qilgan usullar bilan tekshirasiz: hujjat berish, iqtibos soʻrash, «bilmayman»
  deyishga ruxsat.

Bugungi uchta asosiy yangi soʻz:

| Soʻz | Oddiy maʼnosi | Inglizcha |
|---|---|---|
| token | model matnni oʻlchaydigan bir boʻlak: soʻz, soʻz boʻlagi, harf yoki bayt | token |
| context window (kontekst oynasi) | model javob yozayotganda koʻra oladigan butun matn, javobning oʻzi ham shunga kiradi | context window |
| sampling (tanlash) | keyingi tokenni ehtimolliklar orasidan tanlash; **temperature** bu ehtimolliklar shaklini oʻzgartiradi | sampling, temperature |

Yordamchi soʻzlar matnda birinchi uchraganda bitta gap bilan tushuntiriladi: **n-gram** (soʻz sanagich model),
**BPE** (tokenizer'ning ishlash usuli), **backoff** (qisqaroq kontekstga oʻtish), **hallucination** (bilmagan joyda
ravon toʻqish).

## Olti toʻgʻri gap, bitta notoʻgʻri javob

Modelga gapning boshini beramiz: `python tilini`. U davomini oʻzi yozadi:

```console
$ go run . python tilini
[tilini]           → google    google 0.50  guido 0.25  dennis 0.25
[google]           → yaratgan  yaratgan 0.67  ochiq 0.33
[yaratgan]         → .         . 1.00
python tilini google yaratgan .
```

Oxirgi qator — modelning javobi: `python tilini google yaratgan .`. Notoʻgʻri: Python'ni Guido van Rossum yaratgan.
Undan oldingi uch qator — model har qadamda nima qilganining jurnali:

| Qism | Misol | Maʼnosi |
|---|---|---|
| `[tilini]` | kvadrat qavs ichida | model qaragan **kontekst**: matnning oxirgi soʻzi |
| `→ google` | strelkadan keyin | model tanlagan keyingi soʻz |
| `google 0.50  guido 0.25  dennis 0.25` | oxirida | hamma nomzod va ularning ehtimolligi |

Birinchi qadamda model uchta nomzodni koʻrdi va Google'ni tanladi, chunki uning ehtimolligi eng katta: 0.50. Ikkinchi
qadamda `[google]` dan keyin `yaratgan` (0.67) yoki `ochiq` (0.33). Uchinchisida `[yaratgan]` dan keyin faqat nuqta.
Nuqta chiqqanda gap tugaydi.

Model nimadan oʻrgandi? Butun «bilimi» bitta faylda:

```console
$ cat korpus.txt
go tilini google yaratgan .
go tilini google ochiq kodli qilgan .
gmail xizmatini google yaratgan .
python tilini guido yaratgan .
c tilini dennis yaratgan .
linux yadrosini linus yaratgan .
```

Modelga beriladigan bunday matn **korpus** deyiladi. Oltita gapning hammasi toʻgʻri: Go'ni Google'da yaratishgan va
2009 yilda ochiq kodli qilishgan, C'ni Dennis Ritchie, Linux yadrosini Linus Torvalds yozgan (manbalar oxirida).
Endi `tilini` soʻzidan keyin nima kelganini sanang:

| `tilini` dan keyingi soʻz | Necha marta | Ehtimollik |
|---|---|---|
| `google` | 2 (1- va 2-gap) | 2 / 4 = 0.50 |
| `guido` | 1 (4-gap) | 1 / 4 = 0.25 |
| `dennis` | 1 (5-gap) | 1 / 4 = 0.25 |

Model faqat oxirgi soʻzni, `tilini` ni koʻradi. Undan oldingi `python` unga koʻrinmaydi. Korpusda `tilini` dan keyin
eng koʻp `google` kelgan, model shuni tanladi. U yolgʻon gapirmadi: u sanadi va eng koʻpini oldi. Qiziq tomoni:
Guido van Rossum 2005–2012 yillarda Google'da ishlagan, shuning uchun bu xato ayniqsa ishonarli eshitiladi.

Claude ham keyingi soʻzni bashorat qilishga oʻrgatilgan. Anthropic lugʻatida (*Pretraining*): Claude'ning asosidagi
model kabi autoregressive til modellari «oldingi matnga qarab keyingi soʻzni bashorat qilishga» oʻrgatiladi.
Albatta, Claude bizning sanagichdan ancha katta. Lekin chiqish shakli bir xil, va bu xatoning ildizi ham shu yerda.

## main.go qatorma-qator: sanoq jadvali va keyingi soʻz

Butun model:

```go filename="main.go" showLineNumbers
// Kichik til modeli: korpusdagi soʻzlarni sanaydi va keyingi soʻzni bashorat qiladi.
// Claude ham har qadamda bitta keyingi tokenni tanlaydi; bu dastur oʻsha gʻoyaning eng
// kichik nusxasi: n-gram model. Token = soʻz, model = sanoq jadvali (korpusdan bir marta
// oʻrganiladi), kontekst oynasi = javob paytida model koʻradigan oxirgi -oyna ta token.
//
//	go run . -oyna 1 -t 0 python tilini
package main

import (
	"flag"
	"fmt"
	"math"
	"math/rand/v2"
	"os"
	"sort"
	"strings"
)

// maxOyna: model oʻrganadigan eng uzun kontekst. -oyna undan katta boʻlolmaydi.
const maxOyna = 3

// model: kontekst (oxirgi k ta token) → keyingi token → necha marta uchradi.
type model struct {
	sanoq  map[string]map[string]int
	tartib map[string]int // token korpusda birinchi marta qayerda uchragan (teng holatda shu hal qiladi)
}

// oqit korpusdagi har bir oʻrin uchun 1..oyna uzunlikdagi kontekstlarni sanaydi.
func oqit(tokenlar []string, oyna int) model {
	m := model{sanoq: map[string]map[string]int{}, tartib: map[string]int{}}
	for i, tok := range tokenlar {
		if _, bor := m.tartib[tok]; !bor {
			m.tartib[tok] = i
		}
		for k := 1; k <= oyna && k <= i; k++ {
			kon := strings.Join(tokenlar[i-k:i], " ")
			if m.sanoq[kon] == nil {
				m.sanoq[kon] = map[string]int{}
			}
			m.sanoq[kon][tok]++
		}
	}
	return m
}

type nomzod struct {
	token string
	soni  int
	p     float64
}

// taqsimot: eng uzun tanish kontekstni topadi va temperature bilan ehtimolliklarni hisoblaydi.
// p ~ soni^(1/t). t = 0 boʻlsa modelning oʻz ehtimolligi (t = 1) koʻrsatiladi,
// tanlov esa har doim eng ehtimolli token (greedy).
func (m model) taqsimot(matn []string, oyna int, t float64) (string, []nomzod) {
	for k := min(oyna, len(matn)); k >= 1; k-- {
		kon := strings.Join(matn[len(matn)-k:], " ")
		keyingi, bor := m.sanoq[kon]
		if !bor {
			continue // bunday kontekst korpusda yoʻq: qisqaroq kontekstga oʻtamiz
		}
		var ns []nomzod
		for tok, soni := range keyingi {
			ns = append(ns, nomzod{token: tok, soni: soni})
		}
		sort.Slice(ns, func(i, j int) bool {
			if ns[i].soni != ns[j].soni {
				return ns[i].soni > ns[j].soni
			}
			return m.tartib[ns[i].token] < m.tartib[ns[j].token]
		})
		daraja := 1.0
		if t > 0 {
			daraja = 1 / t
		}
		var jami float64
		for i := range ns {
			ns[i].p = math.Pow(float64(ns[i].soni), daraja)
			jami += ns[i].p
		}
		for i := range ns {
			ns[i].p /= jami
		}
		return kon, ns
	}
	return "", nil
}

// tanla: ehtimollik boʻyicha bitta tokenni tasodifiy tanlaydi (sampling).
func tanla(ns []nomzod, r *rand.Rand) string {
	x := r.Float64()
	for _, n := range ns {
		if x < n.p {
			return n.token
		}
		x -= n.p
	}
	return ns[len(ns)-1].token
}

func main() {
	oyna := flag.Int("oyna", 1, "kontekst oynasi: model oxirgi nechta tokenni koʻradi")
	t := flag.Float64("t", 0, "temperature: 0 = har doim eng ehtimolli token")
	seed := flag.Uint64("seed", 1, "tasodif urugʻi (bir xil seed = bir xil natija)")
	n := flag.Int("n", 1, "nechta javob yaratish (n > 1 boʻlsa faqat javoblar chiqadi)")
	korpus := flag.String("korpus", "korpus.txt", "model oʻrganadigan matn")
	flag.Parse()

	matn, err := os.ReadFile(*korpus)
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	if *oyna < 1 || *oyna > maxOyna {
		fmt.Fprintf(os.Stderr, "-oyna 1..%d boʻlishi kerak\n", maxOyna)
		os.Exit(2)
	}
	m := oqit(strings.Fields(strings.ToLower(string(matn))), maxOyna)
	boshi := strings.Fields(strings.ToLower(strings.Join(flag.Args(), " ")))
	if len(boshi) == 0 {
		fmt.Fprintln(os.Stderr, "boshlanish soʻzlarini bering, masalan: go run . python tilini")
		os.Exit(2)
	}
	r := rand.New(rand.NewPCG(*seed, 0))

	for j := 0; j < *n; j++ {
		jumla := append([]string(nil), boshi...)
		for len(jumla) < 20 && jumla[len(jumla)-1] != "." {
			kon, ns := m.taqsimot(jumla, *oyna, *t)
			if ns == nil {
				fmt.Printf("%-18s → ?         korpusda yoʻq\n", "["+jumla[len(jumla)-1]+"]")
				break
			}
			var tok string
			if *t == 0 {
				tok = ns[0].token
			} else {
				tok = tanla(ns, r)
			}
			if *n == 1 {
				var qator []string
				for _, x := range ns {
					qator = append(qator, fmt.Sprintf("%s %.2f", x.token, x.p))
				}
				fmt.Printf("%-18s → %-9s %s\n", "["+kon+"]", tok, strings.Join(qator, "  "))
			}
			jumla = append(jumla, tok)
		}
		fmt.Println(strings.Join(jumla, " "))
	}
}
```

Oʻqitish faqat bir marta, 118-qatorda boʻladi. `strings.ToLower` hamma harfni kichik qiladi, `strings.Fields` matnni
boʻsh joy va qator oxirlari boʻyicha soʻzlarga ajratadi. Shuning uchun nuqta ham alohida soʻz (token) boʻladi, gaplar
esa bitta uzun roʻyxatga ulanadi. Python'da xuddi shu sanoqni bir necha qatorda yozish mumkin (bu fayl dars papkasida
yoʻq, uni `bigram.py` nomi bilan dars papkasiga saqlab, oʻzingiz ishga tushiring):

```python
from collections import Counter, defaultdict

tokenlar = open("korpus.txt", encoding="utf-8").read().lower().split()
sanoq = defaultdict(Counter)
for oldingi, keyingi in zip(tokenlar, tokenlar[1:]):
    sanoq[oldingi][keyingi] += 1
print(sanoq["tilini"])
```

```console
$ python3 bigram.py
Counter({'google': 2, 'guido': 1, 'dennis': 1})
```

Python versiyasi faqat bitta soʻzlik kontekstni sanaydi, `defaultdict` esa ichki `Counter` ni oʻzi yaratadi. Go'da
ichki map'ni qoʻlda yaratamiz (37–39-qatorlar). JS'da bu `Map` ichidagi `Map` boʻlardi. Jadvalning bir qismi:

| `sanoq` kaliti (kontekst) | Keyingi soʻzlar va sanoq |
|---|---|
| `"tilini"` | `google: 2`, `guido: 1`, `dennis: 1` |
| `"python tilini"` | `guido: 1` |
| `"go tilini"` | `google: 2` |
| `"google"` | `yaratgan: 2`, `ochiq: 1` |

## Token: model matnni nimada oʻlchaydi

Model matnni harf yoki soʻz bilan emas, **token** bilan oʻqiydi. Bizning modelda bitta token bitta soʻzga teng.
Anthropic lugʻatiga koʻra, Claude'da token soʻz, soʻzning bir boʻlagi, harf yoki hatto bayt boʻlishi mumkin. Bitta
token nechta harfga toʻgʻri kelishi model va tilga bogʻliq. Lugʻat yana aytadi: Claude 4.7 va keyingi modellar yangi
**tokenizer** ishlatadi (tokenizer — matnni tokenlarga boʻladigan dastur). U bir xil matnga oldingi modellardagidan
taxminan 30 foiz koʻproq token beradi. Opus 5.5 migratsiya qoʻllanmasi aniqroq: 1 dan 1,35 baravargacha.

Hozirgi Claude tokenizer'i ochiq eʼlon qilinmagan. Shuning uchun bitta soʻzni OpenAI'ning **ochiq** `o200k_base`
tokenizer'ida koʻramiz. Bu Claude'ning soni emas, faqat tendensiya. `uv run --quiet` skriptni kerakli kutubxona bilan
jim ishga tushiradi.

Inglizcha `we are learning` (3 soʻz) va uning oʻzbekchasi `oʻrganmoqdamiz` (1 soʻz). Qaysi biri koʻproq token?

**A)** inglizchasi, chunki soʻz koʻp · **B)** teng, maʼnosi bir xil · **C)** oʻzbekchasi, ancha koʻp

<details>
<summary>Javob</summary>

**C.** Inglizchasi 3 token, oʻzbekchasi teskari vergul `ʻ` bilan 8 token, oddiy klaviatura apostrofi bilan 7.
«A» ni tanlagan boʻlsangiz, token = soʻz deb oʻyladingiz. Bu faqat bizning kichik modelda shunday.

</details>

```console
$ uv run --quiet tokenlar/tokenlar.py soz
we are learning  3 token: we |  are |  learning
oʻrganmoqdamiz   8 token: o | ʻ | r | gan | mo | q | dam | iz
o'rganmoqdamiz   7 token: o | 'r | gan | mo | q | dam | iz
```

`|` belgisi tokenlar chegarasini koʻrsatadi. `we`, ` are` va ` learning` — uchta butun soʻz (oldidagi boʻsh joy ham
token ichida). `oʻrganmoqdamiz` esa sakkiz boʻlakka boʻlindi: `o | ʻ | r | gan | mo | q | dam | iz`. Teskari vergul
`ʻ` (U+02BB) UTF-8 da 2 bayt (GO-1.04) va bu yerda alohida token boʻldi. Klaviatura apostrofi bilan `'r` bitta
tokenga birlashdi, jami 7.

Bunday tokenizer'lar **BPE** (byte pair encoding) usulida quriladi. U koʻp uchraydigan harf ketma-ketliklarini
bitta tokenga birlashtiradi (Sennrich va boshq., 2016). Inglizcha ` learning` koʻp uchragani uchun bitta token
boʻlgan. Ehtimol, bu tokenizer oʻrgatilgan matnlarda oʻzbekcha kam boʻlgan. Bu bizning xulosamiz, oʻlchov emas.

Bitta soʻz kam. Endi katta matn: Inson huquqlari umumjahon deklaratsiyasi, inglizcha va oʻzbekcha (parallel matn,
maʼnosi bir xil). Birinchi qator `tokenlar.py` dan, ikkinchisi `eski_claude.mjs` dan; `&&` ikkinchi buyruqni birinchisi
muvaffaqiyatli tugasa ishga tushiradi:

```console
$ uv run --quiet tokenlar/tokenlar.py til && node tokenlar/eski_claude.mjs
Inson huquqlari deklaratsiyasi     inglizcha oʻzbekcha   farq
belgilar                               10638     12241  1.15x
tokenlar: o200k_base (OpenAI)           2011      3911  1.94x
tokenlar: Claude 3 gacha                2068      5249  2.54x
```

| Qator | Inglizcha | Oʻzbekcha | Farq | Nima |
|---|---|---|---|---|
| `belgilar` | 10638 | 12241 | 1.15x | harflar soni deyarli teng: oʻzbekchasi atigi 15 foiz uzunroq |
| `o200k_base (OpenAI)` | 2011 | 3911 | 1.94x | tokenlar esa qariyb ikki baravar koʻp |
| `Claude 3 gacha` | 2068 | 5249 | 2.54x | Anthropic'ning Claude 3 gacha boʻlgan modellar uchun chiqargan ochiq tokenizer'i |

Uchinchi qatorga ehtiyot boʻling. `@anthropic-ai/tokenizer` paketining README'si: «Claude 3 modellaridan boshlab bu
algoritm endi aniq emas, faqat juda taxminiy». Hozirgi Claude'dagi aniq sonni faqat API aytadi: har bir javobning
`usage` maydonida soʻrov qancha token ishlatgani yoziladi (`input_tokens`, `output_tokens`). Uni
[CL-3.01](/lab/youtube/claude#cl-3-01) da oʻlchaymiz.

Bu nega muhim? Narx ham, context window ham token bilan oʻlchanadi. Anthropic narxlari «$ / million input token» va
«$ / million output token» koʻrinishida. Demak, bir xil maʼnodagi oʻzbekcha matn koʻproq token egallashi mumkin: u
qimmatroq turadi va oynaga kamroq sigʻadi. Claude uchun aniq farqni biz oʻlchamadik. Ochiq tokenizer'larda u 1,94 va
2,54 baravar.

Apostrof turi butun matnda kam farq qiladi: `tokenlar.py apostrof` teskari vergul bilan 3911, klaviatura apostrofi
bilan 3892, `‘` bilan 3938 token beradi. Oʻzbek matnini BPE qanday kesishi — [ML-4.01](/lab/youtube/ml#ml-4-01).

## Bilim yoʻq joyda: rust, backoff va hallucination

Endi korpusda umuman yoʻq tilni soʻraymiz: Rust. Avval faqat bitta soʻz:

```console
$ go run . rust
[rust]             → ?         korpusda yoʻq
rust
```

`→ ?  korpusda yoʻq`: model jim qoldi, chunki `rust` dan keyin nima kelishini hech qachon koʻrmagan (130–133-qatorlar).
Endi `rust tilini` deymiz, oyna 2:

```console
$ go run . -oyna 2 rust tilini
[tilini]           → google    google 0.50  guido 0.25  dennis 0.25
[tilini google]    → yaratgan  yaratgan 0.50  ochiq 0.50
[google yaratgan]  → .         . 1.00
rust tilini google yaratgan .
```

`[rust tilini]` korpusda yoʻq. Model jim qolmadi: u notanish `rust` ni tashladi va tanish `[tilini]` ga tayandi
(56–61-qatorlar, `continue`). Bunday qisqaroq kontekstga oʻtish **backoff** deyiladi. Aynan shu qaror modelni jim
turish oʻrniga taxmin qilishga majbur qildi. Ikkinchi qadamda `[tilini google]` dan keyin `yaratgan` va `ochiq` teng
(0.50), model korpusda oldin uchragan `yaratgan` ni oldi (66–71-qatorlar).

Natija yana Google. Aslida Rust'ni Graydon Hoare boshlagan: 2006 yilda shaxsiy loyiha sifatida, 2009 yildan Mozilla
homiyligida. Bilmagan joyda ravon gap tuzish **hallucination** deyiladi. Bu yerda oynani kattalashtirish yordam
bermaydi: oynada `rust` bor, lekin modelda u haqida bilim yoʻq.

Ikki xil xatoni farqlang:

| Holat | Sabab | Nima tuzatadi |
|---|---|---|
| `python tilini` → google | kerakli soʻz oynadan tashqarida | kattaroq oyna (`-oyna 2`) |
| `rust tilini` → google | bilim umuman yoʻq, backoff taxmin qildi | oyna emas: bilim yoki «bilmayman» |

## Sampling va temperature

Uchinchi tushuncha — **sampling**, yaʼni keyingi tokenni tanlash. Model har qadamda har bir nomzodga ehtimollik
beradi. Keyin ulardan bittasini olish kerak. **Temperature** (`-t`) ikki narsani belgilaydi.

Birinchisi — qanday tanlash. `t = 0` boʻlsa, har doim eng ehtimollisi olinadi. Bu **greedy** tanlov:

```go
			var tok string
			if *t == 0 {
				tok = ns[0].token
			} else {
				tok = tanla(ns, r)
			}
```

`ns` saralangan, shuning uchun `ns[0]` eng ehtimolli nomzod (134–139-qatorlar). `t > 0` boʻlsa, ehtimollikka mos qurʼa
tashlanadi: katta ehtimollik koʻproq yutadi, kichigi ham baʼzan chiqadi. Buni `tanla` qiladi:

```go
func tanla(ns []nomzod, r *rand.Rand) string {
	x := r.Float64()
	for _, n := range ns {
		if x < n.p {
			return n.token
		}
		x -= n.p
	}
	return ns[len(ns)-1].token
}
```

`r.Float64()` 0 dan 1 gacha (1 kirmaydi) tasodifiy son beradi. Nomzodlarni 0..1 kesmasida ketma-ket qoʻyib chiqing:
`x` qaysi boʻlakka tushsa, oʻsha nomzod tanlanadi. Siklda `x < n.p` boʻlsa, shu nomzod; aks holda `x` dan `n.p` ni
ayirib, keyingisiga oʻtamiz. Oxirgi `return` — yaxlitlash xatosi uchun zaxira. JS'da `Math.random()` bilan xuddi
shunday yoziladi.

```text
t = 1,  [tilini]:
0                     0.50          0.75          1
|-------- google -------|--- guido ---|-- dennis --|
x = 0.62  →  0.62 ≥ 0.50, x = 0.12  →  0.12 < 0.25  →  guido
```

Ikkinchisi — ehtimolliklar shakli. 72–83-qatorlar sanoqni darajaga koʻtaradi va jamiga boʻladi: `p ~ soni^(1/t)`.

```go
		daraja := 1.0
		if t > 0 {
			daraja = 1 / t
		}
		var jami float64
		for i := range ns {
			ns[i].p = math.Pow(float64(ns[i].soni), daraja)
			jami += ns[i].p
		}
		for i := range ns {
			ns[i].p /= jami
		}
```

`[tilini]` uchun sanoqlar 2, 1, 1. Hisoblab koʻramiz:

| `t` | `1/t` | google | guido | dennis | jami | p(google) |
|---|---|---|---|---|---|---|
| 0.5 | 2 (kvadrat) | 2² = 4 | 1 | 1 | 6 | 4 / 6 = 0.67 |
| 1 | 1 (oʻzi) | 2 | 1 | 1 | 4 | 2 / 4 = 0.50 |
| 2 | 0.5 (kvadrat ildiz) | √2 ≈ 1.41 | 1 | 1 | 3.41 | 1.41 / 3.41 = 0.41 |

Kichik temperature favoritni kuchaytiradi, kattasi taqsimotni tekislaydi. `t = 0` boʻlsa, jurnalda modelning oʻz
ehtimolligi (`t = 1` dagi) koʻrsatiladi (53–54-qatorlardagi izoh). Matematikani bilganlar uchun: normallangan
`soni^(1/t)` — bu `log(soni) / t` ning softmax'i, temperature'ning standart taʼrifi.

Endi bir buyruqda uchta temperature. `for t in 0.5 1 2; do … done` — `t` ga navbat bilan uchta qiymat berib, bir xil
buyruqni uch marta ishga tushiradi. `$(…)` ichidagi buyruqning natijasini oladi, `head -1` faqat birinchi qatorni
qoldiradi, `printf 't=%-4s %s\n'` esa `t` ni 4 belgilik ustunga tekislab chiqaradi:

```console
$ for t in 0.5 1 2; do printf 't=%-4s %s\n' $t "$(go run . -t $t python tilini | head -1)"; done
t=0.5  [tilini]           → google    google 0.67  guido 0.17  dennis 0.17
t=1    [tilini]           → google    google 0.50  guido 0.25  dennis 0.25
t=2    [tilini]           → google    google 0.41  guido 0.29  dennis 0.29
```

Jadvaldagi sonlar bilan bir xil: 0.67, 0.50, 0.41.

Endi `python tilini` gapini 10 000 marta yaratamiz (`-n 10000`) va toʻgʻri javob, Guido, necha marta chiqqanini
sanaymiz. `grep -c guido` — `guido` bor qatorlar soni:

```console
$ for t in 0 1 2; do echo "t=$t: $(go run . -t $t -n 10000 python tilini | grep -c guido) / 10000 guido"; done
t=0: 0 / 10000 guido
t=1: 2418 / 10000 guido
t=2: 2891 / 10000 guido
```

| `t` | Kutilgan | Chiqdi |
|---|---|---|
| 0 | 0 (har doim google) | 0 |
| 1 | 0.25 × 10 000 = 2500 | 2418 (taxminan chorak) |
| 2 | 0.29 × 10 000 ≈ 2929 | 2891 (qariyb 29 foiz) |

Kutilgan va chiqqan sonlar orasidagi farq — tasodif. Boshqa seed'da (`-seed 2` … `-seed 5`) `t = 1` da 2413–2513,
`t = 2` da 2854–2934 chiqadi. Xulosa oʻzgarmaydi.

Demak, temperature'ni oshirsak, toʻgʻri javob koʻpayadimi? Keyingi boʻlimdagi savolga javob bering.

## Claude'da temperature

Claude'da bu qanday ishlaydi? Uchta fakt:

1. Anthropic lugʻati (*Temperature*): temperature 0 boʻlsa ham, natija toʻliq deterministik emas, bir xil kirish API
   chaqiruvlarida har xil javob berishi mumkin.
2. Opus 5.5 migratsiya qoʻllanmasi: Opus 5.5 da `temperature`, `top_p` va `top_k` olib tashlangan, API'ning eng yangi
   versiyasida esa ular barcha modellarda yoʻq. Bu parametrlarni yuborsangiz, API xato qaytaradi.
3. Oʻsha qoʻllanma: model xulqini prompt orqali boshqarish tavsiya qilinadi.

Amaliy xulosa: bir xil savolga har xil javob kelishi mumkin. Bizning modeldagi `-seed` kabi «hamma narsani qotirib
qoʻyish» tugmasi yoʻq. Shuning uchun bu sahifada birorta ham Claude javobini koʻrsatmadik: uni siz aynan takrorlay
olmaysiz.

## Nega ishonchli, lekin notoʻgʻri?

Endi asosiy savol: nega javob ishonchli eshitiladi, lekin notoʻgʻri boʻladi? Uchta sabab:

| # | Sabab | Bizning modelda | Manba |
|---|---|---|---|
| 1 | model har doim keyingi soʻzni taxmin qilishi kerak, oʻqitish shunga undaydi | backoff `rust` ni tashlab, baribir javob berdi | Anthropic, *Tracing the thoughts…* (2025) |
| 2 | ehtimollik matnda koʻrinmaydi | google 0.50 bilan tanlandi, gapda «balki» yoʻq | `go run . python tilini` |
| 3 | baholash ham taxminni ragʻbatlantiradi | — | Kalai va boshq., *Why Language Models Hallucinate* (2025) |

Uchinchisini maqola mualliflari imtihon bilan tushuntiradi. Xato javob uchun ball ayirilmasa, taxmin qilgan talaba
«bilmayman» degan talabadan koʻproq ball oladi. Til modellarini oʻqitish va baholash ham koʻpincha shunday: noaniqlikni
tan olishdan koʻra taxmin qilish foydaliroq chiqadi.

Claude bizning modeldan farqli oʻlaroq «bilmayman» deyishga ham oʻrgatilgan. Anthropic buni «nisbatan muvaffaqiyatli,
lekin mukammal emas» deydi. Ular **Claude 3.5 Haiku** ichini oʻrganib (2025), quyidagini topdi:

```text
odatiy holat:        «bilmayman» sxemasi YONIQ          → «javob bera olmayman»
tanish nom:          Michael Jordan → «tanish» belgisi   → sxema OʻCHADI → toʻgʻri javob
notanish nom:        Michael Batkin → belgi yoʻq         → sxema yoniq   → «bilmayman»
nom tanish, bilim yoʻq: «tanish» belgisi adashib yonadi → sxema OʻCHADI → ishonarli, lekin notoʻgʻri javob
```

Oxirgi qator — eng xavflisi. Nom tanish tuyulsa-yu, bilim boʻlmasa, sxema adashib oʻchishi mumkin. Shunda model
ishonarli, lekin notoʻgʻri javob toʻqiydi. Bu tadqiqot Claude 3.5 Haiku ustida qilingan. Boshqa Claude modellari
haqida u aniq hech narsa demaydi.

## Ishonchli xatoga qarshi nima qilamiz

Anthropic'ning *Reduce hallucinations* hujjatidagi usullar:

1. **«Bilmayman» deyishga ochiq ruxsat bering.** Promptda yozing: maʼlumot yetmasa, «bilmayman» deb javob bersin.
2. **Hujjatni bering va faqat undan javob soʻrang.** Kerakli hujjatni (API spec, README, log) promptga qoʻying va
   «faqat shu hujjatga tayan» deng.
3. **Har bir daʼvoga hujjatdan soʻzma-soʻz iqtibos soʻrang.** Iqtibos topilmasa, daʼvo olib tashlansin. Xotiradan
   «manba» soʻramang: model manbani ham toʻqib chiqarishi mumkin. Iqtibos siz bergan hujjatdan boʻlishi kerak.
4. **Bir savolni bir necha marta bering va solishtiring.** Javoblar bir-biriga zid boʻlsa, bu xavf belgisi. Lekin
   bir xil javob isbot emas: bizning model `t = 0` da 10 000 marta bir xil xato qildi.
5. **Kodni doim ishga tushiring va test qiling.** Buni [CL-1.05](/lab/youtube/claude#cl-1-05) da batafsil qilamiz.

Hujjatning oʻzi ogohlantiradi: bu usullar xatoni kamaytiradi, lekin butunlay yoʻqotmaydi.

Birinchi uchta usul bitta promptda bunday koʻrinishi mumkin (prompt tuzilishi — [CL-1.03](/lab/youtube/claude/cl-1-03)):

```text
<hujjat>
… bu yerga README yoki API hujjati matni …
</hujjat>

Savolga faqat yuqoridagi hujjatga tayanib javob bering.
Hujjatda javob boʻlmasa, «bilmayman» deb yozing.
Har bir daʼvo uchun hujjatdan soʻzma-soʻz iqtibos keltiring.
Iqtibos topa olmagan daʼvoni javobdan olib tashlang.
```

Bizning modelga bu usullarni qoʻllasak: «bilmayman» — uy vazifasining 🟠 darajasi, «hujjatni berish» — 🟢 darajasi
(korpusga kerakli gapni qoʻshish).

Qisqacha: model keyingi tokenni bashorat qiladi, uning oynasi chegaralangan, tanlovda esa tasodif bor. Shuning uchun
ravon javob hali toʻgʻri javob degani emas. Keyingi darsda Claude.ai'dan toʻgʻri foydalanishni oʻrganamiz: model
tanlash, Projects va fayllar ([CL-1.02](/lab/youtube/claude/cl-1-02)).

## Koʻp uchraydigan xatolar

### 1. «Temperature'ni oshirsam, toʻgʻri javob koʻpayadi»

Bu darsning klassik notoʻgʻri tasavvuri. `python tilini` da `t = 2` toʻgʻri javobni 0 dan 2891 ga koʻtardi, lekin
faqat favorit notoʻgʻri boʻlgani uchun. `go tilini` da xuddi shu temperature toʻgʻri javobni 10 000 dan 4105 ga
tushirdi («Temperature haqiqatni bilmaydi» boʻlimi). Temperature taqsimotni tekislaydi, haqiqatni bilmaydi. Tuzatish:
javobning toʻgʻriligini temperature bilan emas, kontekst (hujjat) va tekshiruv bilan oshiring.

### 2. «Besh marta soʻradim, besh marta bir xil javob — demak toʻgʻri»

```console
$ go run . -t 0 -n 5 python tilini
python tilini google yaratgan .
python tilini google yaratgan .
python tilini google yaratgan .
python tilini google yaratgan .
python tilini google yaratgan .
```

Besh marta bir xil va besh marta notoʻgʻri. Bir xillik faqat model shu javobga ishonchini koʻrsatadi, haqiqatni emas.
Zid javoblar — xavf belgisi; bir xil javoblar — hali isbot emas. Tuzatish: daʼvoni hujjat yoki ishga tushirilgan kod
bilan tekshiring.

### 3. «`temperature: 0` qoʻysam, Claude har doim bir xil javob beradi»

Ikki sababga koʻra notoʻgʻri («Claude'da temperature» boʻlimi). Birinchidan, Anthropic lugʻati 0 da ham toʻliq
determinizmni kafolatlamaydi. Ikkinchidan, Opus 5.5 da (va API'ning eng yangi versiyasida barcha modellarda)
`temperature` umuman yoʻq: eski koddan qolgan `temperature`, `top_p` yoki `top_k` ni yuborsangiz, soʻrov xato bilan
qaytadi. Biz bu sahifa uchun API'ni chaqirmadik, shuning uchun xato matnini koʻrsatmaymiz. Tuzatish: parametrni olib
tashlang va kerakli xulqni promptda yozing.

### 4. «1 token ≈ 4 harf, oʻzbekchada ham shunday»

Bu qoida inglizcha matn va boshqa tokenizer'lar uchun aytiladi. Anthropic lugʻatiga koʻra, harf/token nisbati model
va tilga bogʻliq. Deklaratsiyada oʻzbekcha matn `o200k_base` da inglizchadan 1,94 baravar, eski Anthropic
tokenizer'ida 2,54 baravar koʻp token oldi, holbuki harflar atigi 1,15 baravar koʻp («Token» boʻlimi). Tuzatish: narx
va oyna hisobini taxmin bilan emas, `usage` maydoni bilan qiling.

### 5. «Kattaroq context window xatoni tuzatadi»

`-oyna 2` `python tilini` ni tuzatdi, `rust tilini` ni tuzatmadi: oynada `rust` bor, bilim yoʻq. Claude'ning oynasi
1 million token, qisqa savol undan chiqib ketmaydi. Juda uzun kontekst esa aniqlikni pasaytiradi (context rot).
Tuzatish: kerakli hujjatni bering, keraksiz matnni oynaga toʻldirmang.

### 6. «Claude'dan manba soʻrasam, yetarli»

Xotiradan soʻralgan «manba» ham toʻqilgan boʻlishi mumkin: model uni ham keyingi token sifatida yozadi. Anthropic
tavsiyasi boshqacha: iqtibos siz **bergan** hujjatdan boʻlsin, topilmasa, daʼvo olib tashlansin. Tuzatish:
«Ishonchli xatoga qarshi nima qilamiz» boʻlimidagi prompt.

### 7. Dastur xatolari: `-oyna 4` va boshqa papka

Oyna 1..3 dan tashqarida:

```console
$ go run . -oyna 4 python tilini
-oyna 1..3 boʻlishi kerak
exit status 2
```

Birinchi qatorni dastur yozdi (114–117-qatorlar): «-oyna 1..3 boʻlishi kerak». `exit status 2` ni `go run` qoʻshadi:
dastur 2 chiqish kodi bilan tugadi. Model faqat 3 soʻzgacha kontekstni oʻrgangan (`maxOyna = 3`), shuning uchun
kattaroq oyna maʼnosiz. Tuzatish: `-oyna 1`, `2` yoki `3`.

Dasturni dars papkasidan tashqarida ishga tushirsangiz:

```console
$ cd .. && go run ./cl-01-next-token python tilini
open korpus.txt: no such file or directory
exit status 1
```

`open korpus.txt: no such file or directory` — «`korpus.txt` ni ochib boʻlmadi: bunday fayl yoki papka yoʻq». Dastur
korpusni joriy papkadan qidiradi (106-qator, standart `-korpus korpus.txt`). Tuzatish: dars papkasiga `cd` qiling
yoki yoʻlni bering: `-korpus cl-01-next-token/korpus.txt`.

`tokenlar.py` ni `uv` siz, `python3 tokenlar/tokenlar.py soz` deb ishga tushirsangiz, `tiktoken` oʻrnatilmagan
boʻlsa, oxirgi qatorda `ModuleNotFoundError: No module named 'tiktoken'` chiqadi («`tiktoken` degan modul yoʻq»).
Tuzatish: `uv run --quiet tokenlar/tokenlar.py soz`. Skript boshidagi `# /// script` blokida kerakli kutubxona va uning
versiyasi yozilgan, `uv` uni oʻzi oʻrnatadi.

## Oʻzingizni tekshiring

1. Bu buyruq nima chiqaradi? (Oyna 2, `t = 0`.)

```text
go run . -oyna 2 go tilini
```

**A)** `go tilini google yaratgan .` · **B)** `go tilini google ochiq kodli qilgan .` · **C)** `go tilini → ?`

<details>
<summary>Javob</summary>

**A.** `[go tilini]` dan keyin faqat `google` kelgan (1.00). Keyin `[tilini google]`: `yaratgan` va `ochiq` bir
martadan, 0.50 ga 0.50. Teng holatda korpusda oldin uchragan soʻz oldinda turadi (25-qator va saralash), `yaratgan`
1-gapda birinchi keladi. «B» ni tanlagan boʻlsangiz, teng holatda tasodifiy yoki oxirgisi tanlanadi deb oʻyladingiz:
`t = 0` da tasodif yoʻq.

```console
$ go run . -oyna 2 go tilini
[go tilini]        → google    google 1.00
[tilini google]    → yaratgan  yaratgan 0.50  ochiq 0.50
[google yaratgan]  → .         . 1.00
go tilini google yaratgan .
```

</details>

2. Context window'ga nima kiradi? Model oʻqitilgan maʼlumot ham kiradimi?

<details>
<summary>Javob</summary>

Model javob yozayotganda koʻra oladigan butun matn: sizning xabarlaringiz, oldingi javoblar, qoʻshilgan fayllar va
yozilayotgan javobning oʻzi. Oʻqitilgan maʼlumot kirmaydi: Anthropic oynani «ishchi xotira» deydi. Hozirgi Claude
modellarida API orqali 1 million token.

</details>

3. Nega `-oyna 2` `python tilini` ni tuzatdi, lekin `rust tilini` ni tuzatmadi?

<details>
<summary>Javob</summary>

`python tilini` da bilim bor edi, faqat `python` oynadan tashqarida qolgan edi: oyna 2 uni koʻrsatdi. `rust tilini`
korpusda umuman yoʻq. Backoff `rust` ni tashlab, `[tilini]` ga tayandi va Google'ni taxmin qildi. Oyna bilim
qoʻshmaydi.

</details>

4. `[google]` dan keyin sanoqlar: `yaratgan` 2, `ochiq` 1. `t = 0.5` da `yaratgan` ning ehtimolligi qancha?

**A)** 0.67 · **B)** 0.80 · **C)** 0.59

<details>
<summary>Javob</summary>

**B.** `1/t = 2`: sanoqlar kvadratga koʻtariladi, 2² = 4 va 1² = 1, jami 5, demak 4 / 5 = 0.80. «A» — `t = 1` dagi
qiymat (2 / 3). «C» — `t = 2` dagi qiymat: √2 / (√2 + 1) ≈ 0.59.

</details>

5. GO-1.04 dan: bu dastur nima chiqaradi va bu `oʻrganmoqdamiz` ning tokenlariga qanday bogʻliq?

```go
package main

import "fmt"

func main() {
	fmt.Println(len("ʻ"), len("'"))
	fmt.Printf("% x\n", "oʻ")
}
```

<details>
<summary>Javob</summary>

Go'da `len` baytlarni sanaydi. Teskari vergul `ʻ` (U+02BB) UTF-8 da 2 bayt (`ca bb`), klaviatura apostrofi 1 bayt.
`"% x"` har baytni boʻsh joy bilan 16 lik sonda chiqaradi:

```console
$ go run main.go
2 1
6f ca bb
```

BPE tokenizer'lar baytlar ustida ishlaydi va koʻp uchraydigan ketma-ketliklarni birlashtiradi. `o200k_base` da
`ʻ` hech narsa bilan birlashmay, alohida token boʻldi (`o | ʻ | r`), ASCII `'` esa `r` bilan bitta tokenga qoʻshildi
(`'r`). Shuning uchun 8 va 7 token.

</details>

6. Claude'ning ishonchli xatosiga qarshi Anthropic tavsiya qilgan uchta usulni ayting. Qaysi birining chegarasi bor?

<details>
<summary>Javob</summary>

«Bilmayman» deyishga ruxsat berish; hujjatni berib, faqat undan javob soʻrash; har bir daʼvoga shu hujjatdan
soʻzma-soʻz iqtibos soʻrash; bir savolni bir necha marta berib solishtirish. Oxirgisining chegarasi bor: zid javoblar
xavf belgisi, lekin bir xil javoblar isbot emas (`t = 0` da 10 000 marta bir xil xato). Va kodni har doim ishga
tushirib, test qilish kerak.

</details>
