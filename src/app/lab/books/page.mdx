This started as a blog post in January 2025, which was the wrong shape for it: a
post is finished the day you publish it, and a reading list never is. So it lives
here now, and I edit it instead of writing a new one.

## Reading now

### Site Reliability Engineering — the Google SRE book

**Status:** chapter 17 · **Why:** it came out of work at
[Numeo](https://numeo.ai), and stayed because everything in it keeps showing up
in the [backend I work on now](/lab/skills/golang).

The foundational text on SRE's philosophy and practices — eliminating toil, SLOs,
monitoring, incident response. The part that actually changed how I work isn't a
technique, it's the framing: reliability is a product feature with a budget, not
a vibe.

| Chapter | Topic |
|---|---|
| 15 | [Postmortem Culture: Learning from Failure](https://sre.google/sre-book/postmortem-culture/) |
| 16 | [Tracking Outages](https://sre.google/sre-book/tracking-outages/) |
| 17 | [Testing for Reliability](https://sre.google/sre-book/testing-reliability/) |
| 18 | [Software Engineering in SRE](https://sre.google/sre-book/software-engineering-in-sre/) |
| 19 | [Load Balancing at the Frontend](https://sre.google/sre-book/load-balancing-frontend/) |

Free online: [sre.google/sre-book](https://sre.google/sre-book/table-of-contents/).

### CyberYozh — cybersecurity guide

**Status:** reading, summarising as I go · **Why:** recommended by a friend
([shakhzod.me](https://shakhzod.me)).

A wide sweep of security, from the basics up. I'm keeping summaries rather than
highlights — if I can't write a topic down in my own words, I didn't read it.

Link: [book.cyberyozh.com](https://book.cyberyozh.com/en).

### Arch Wiki — Security

**Status:** reference, dipped into whenever I touch a server · **Why:** also a
friend's recommendation, and the Arch Wiki is still the best Linux documentation
anyone has written.

Hardening, encryption, access control. This one isn't read front to back — it's
what I open when I'm setting something up, and the tips get applied to
[the machine I actually run](/lab/ideas/shoshshi) and to my own
[NixOS config](/lab/skills/nixos).

Link: [wiki.archlinux.org/title/Security](https://wiki.archlinux.org/title/Security).

## Why these three

1. **Operational excellence** — how reliable systems are built and kept alive at
   scale.
2. **A security mindset** — learning to think like the attacker so the defence
   isn't guesswork.
3. **Practical skills** — things I can apply to a server the same week I read
   them.
